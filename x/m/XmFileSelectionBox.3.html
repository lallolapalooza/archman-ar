XmFileSelectionBox(3)

الحزمة: openmotif

التراخيص: LGPL-2.1-or-later

NAME

FileSelectionBox - A widget that allows users to select files.

SYNOPSIS

A FileSelectionBox widget consists of the following child widgets:

  • A directory list
  • A directory selection field
  • A file list
  • A filter field
  • An OK button
  • A Cancel button
  • An Apply button
  • A Help button

DESCRIPTION

The FileSelectionBox widget provides a standard dialog for selecting files. It displays a list of directories, a list of files in the current directory, and text fields for filtering the file list and specifying the desired file path. It also includes buttons for applying the selection, canceling the dialog, and getting help.

The FileSelectionBox widget supports the standard Motif drag and drop operations. It handles the TARGETS, FILE_NAME, and TEXT targets for both the directory list and the file list. When a data transfer is initiated from the directory list or the file list, and their respective search procedures (XmNdirSearchProc and XmNfileSearchProc) have their default values, these lists automatically support the FILE and FILE_NAME targets.

To facilitate this, FileSelectionBox adds an XmNconvertCallback procedure to the appropriate list. This procedure adds FILE and FILE_NAME to the TARGETS returned by the list. It treats requests for conversion of a selection to FILE and FILE_NAME exactly like requests for conversion to TEXT.

If an application modifies XmNdirSearchProc or XmNfileSearchProc and still wants to support the FILE and FILE_NAME targets on the corresponding list, it must provide its own conversion support by adding a procedure to the list's XmNconvertCallback list.

Classes

FileSelectionBox inherits behavior, resources, and traits from Core, Composite, Constraint, XmManager, XmBulletinBoard, and XmSelectionBox.

The class pointer is xmFileSelectionBoxWidgetClass.

The class name is XmFileSelectionBox.

XmNdirectory
يحدد الدليل الأساسي المستخدم بالاشتراك مع XmNpattern لتحديد الملفات والأدلة التي سيتم عرضها. القيمة الافتراضية يتم تحديدها بواسطة XmNqualifySearchDataProc وتعتمد على القيم الأولية لـ XmNdirMask و XmNdirectory و XmNpattern. إذا كانت القيمة الافتراضية NULL أو فارغة، فسيتم استخدام الدليل الحالي.
XmNdirectoryValid
يحدد سمة يتم تعيينها فقط بواسطة إجراء البحث في الدليل. يتم تعيين القيمة إلى True إذا كان الدليل الذي تم تمريره إلى إجراء البحث في الدليل يمكن البحث فيه فعليًا. إذا كانت هذه القيمة False، فلن يتم استدعاء إجراء البحث في الملف، ولن يتم تغيير XmNdirMask و XmNdirectory و XmNpattern.
XmNdirListItems
يحدد العناصر في قائمة الدليل. XtGetValues لهذا المورد يعيد عناصر القائمة نفسها، وليس نسخة من عناصر القائمة. يجب على التطبيق عدم تحرير العناصر المعادة.
XmNdirListItemCount
يحدد عدد العناصر في قائمة الدليل. يجب ألا تكون القيمة سالبة.
XmNdirListLabelString
يحدد سلسلة العنوان لقائمة الدليل. القيمة الافتراضية لهذا المورد تعتمد على اللغة. في لغة C الافتراضية هي Directories.
الآن بعد توفير بعض سلاسل العناوين الافتراضية المترجمة من خلال كتالوجات الرسائل للأطفال من عناصر الواجهة المركبة، لا يمكن تعيين موارد labelString على الطفل من خلال ملفات الموارد الافتراضية. بدلاً من ذلك، يجب استخدام المورد المتوفر على مستوى الوالد.
XmNdirMask
يحدد قناع الدليل المستخدم في تحديد الملفات والأدلة التي سيتم عرضها. يتم تحديد القيمة الافتراضية بواسطة XmNqualifySearchDataProc وتعتمد على القيم الأولية لـ XmNdirMask و XmNdirectory و XmNpattern.
XmNdirSearchProc
يحدد إجراء بحث في الدليل لاستبدال إجراء البحث في الدليل الافتراضي. يقوم إجراء البحث الافتراضي لـ FileSelectionBox بتلبية احتياجات معظم التطبيقات. نظرًا لعدم إمكانية تغطية متطلبات جميع التطبيقات، يمكنك استبدال إجراء البحث الافتراضي.
يتم استدعاء إجراء البحث في الدليل بوسيطين: عنصر الواجهة FileSelectionBox ومؤشر إلى بنية XmFileSelectionBoxCallbackStruct. يتم إنشاء بنية الاستدعاء بواسطة XmNqualifySearchDataProc وتحتوي على جميع المعلومات المطلوبة لإجراء بحث في الدليل، بما في ذلك قناع الدليل ودليل أساسي مؤهل ونمط بحث. بمجرد الاستدعاء، يعود الأمر إلى روتين البحث لتوليد قائمة جديدة بالأدلة وتحديث عنصر الواجهة FileSelectionBox باستخدام XtSetValues.
يجب أن يقوم روتين البحث
يقوم بتعيين XmNdirectoryValid و XmNlistUpdated. إذا قام بإنشاء قائمة جديدة من الدلائل، فيجب عليه أيضًا تعيين XmNdirListItems و XmNdirListItemCount.
إذا لم يتمكن إجراء البحث من البحث في الدليل المحدد، فيجب عليه تحذير المستخدم وتعيين XmNdirectoryValid و XmNlistUpdated إلى False، ما لم يقدم مطالبة ويحصل لاحقًا على دليل صالح. إذا كان الدليل صالحًا ولكنه هو نفسه XmNdirectory الحالي، فيجب على إجراء البحث تعيين XmNdirectoryValid إلى True، ولكنه قد يختار عدم إنشاء قائمة جديدة من الدلائل. في هذه الحالة، يجب عليه تعيين XmNlistUpdated إلى False.
إذا قام إجراء البحث بإنشاء قائمة جديدة من الدلائل، فيجب عليه تعيين XmNdirListItems إلى القائمة الجديدة من الدلائل و XmNdirListItemCount إلى عدد العناصر في القائمة. إذا لم تكن هناك دلائل، فإنه يعين XmNdirListItems إلى NULL و XmNdirListItemCount إلى 0 (صفر). في كلتا الحالتين، يجب عليه تعيين XmNdirectoryValid و XmNlistUpdated إلى True.
لا ينبغي لإجراء البحث عادةً تغيير هيكل الاستدعاء. ولكن إذا لم يكن الدليل الأصلي صالحًا، فقد يحصل إجراء البحث على دليل جديد من المستخدم. في هذه الحالة، يجب عليه تعيين عضو dir في هيكل الاستدعاء إلى الدليل الجديد، واستدعاء XmNqualifySearchDataProc مع هيكل الاستدعاء كوسيطة الإدخال، ونسخ البيانات المؤهلة التي تم إرجاعها بواسطة XmNqualifySearchDataProc إلى هيكل الاستدعاء.
XmNdirSpec
يحدد مواصفات المسار الكامل للملف. هذا هو مورد XmNtextString في SelectionBox، تم إعادة تسميته لـ FileSelectionBox. القيمة الافتراضية يتم تحديدها بواسطة FileSelectionBox بعد إجراء البحث الأولي عن الدليل والملف.
XmNdirTextLabelString
يستخدم XmString المحدد كتسمية فوق دليل TextField. يأخذ المورد تأثيره عندما تكون قيمة مورد XmNpathMode هي XmPATH_MODE_RELATIVE. يتم تجاهله عندما تكون قيمة مورد XmNpathMode هي XmPATH_MODE_FULL.
الآن بعد توفير بعض سلاسل التسمية الافتراضية المحلية من خلال كتالوجات الرسائل للأطفال من الويدجتات المركبة، لا يمكن تعيين موارد labelString على الطفل من خلال ملفات الموارد الافتراضية. بدلاً من ذلك، يجب استخدام المورد المقدم على مستوى الأصل.
XmNfileFilterStyle
يحدد ما إذا كانت الملفات "المخفية" (تلك التي تبدأ أسماؤها بـ . (نقطة) في أنظمة POSIX) سيتم سردها في قوائم التمرير للملفات والدلائل (حيث يتم استخدام إجراء البحث الافتراضي عن الدليل). القيم الممكنة هي:
XmFILTER_NONE
لا يقوم بتصفية الملفات المخفية.
XmFILTER_HIDDEN_FILES
يقيّد قائمة أسماء الملفات الممكنة، مثل تلك التي تبدأ بـ . (نقطة).
XmNfileListItems
يحدد العناصر في قائمة الملفات. هذا هو مورد XmNlistItems في SelectionBox، تم إعادة تسميته لـ FileSelectionBox. XtGetValues لهذا المورد يعيد العناصر نفسها، وليس نسخة من العناصر. يجب على التطبيق عدم تحرير العناصر المعاد توجيهها.
XmNfileListItemCount
يحدد عدد العناصر في قائمة الملفات. هذا هو مورد XmNlistItemCount في SelectionBox، تم إعادة تسميته لـ FileSelectionBox. يجب ألا تكون القيمة سالبة.
XmNfileListLabelString
يحدد سلسلة التسمية لقائمة الملفات. هذا هو مورد XmNlistLabelString في SelectionBox، تم إعادة تسميته لـ FileSelectionBox. يعتمد الافتراضي لهذا المورد على اللغة. في لغة C، الافتراضي هو Files.
الآن بعد توفير بعض سلاسل التسمية الافتراضية المحلية من خلال كتالوجات الرسائل للأطفال من الويدجتات المركبة، لا يمكن تعيين موارد labelString على الطفل من خلال ملفات الموارد الافتراضية. بدلاً من ذلك، يجب استخدام المورد المقدم على مستوى الأصل.
XmNfileSearchProc
يحدد إجراء بحث ملف لاستبدال إجراء البحث الافتراضي للملفات. إجراء البحث الافتراضي للملفات في FileSelectionBox يلبي احتياجات معظم التطبيقات. نظرًا لأنه من المستحيل تغطية متطلبات جميع التطبيقات، يمكنك استبدال إجراء البحث الافتراضي.
يتم استدعاء إجراء البحث للملفات مع وسيطتين: ويدجت FileSelectionBox ومؤشر لهيكل XmFileSelectionBoxCallbackStruct. هيكل الاستدعاء يتم إنشاؤه بواسطة XmNqualifySearchDataProc (ويمكن تعديله بواسطة XmNdirSearchProc). يحتوي على جميع المعلومات المطلوبة لإجراء بحث ملف، بما في ذلك قناع الدليل والدليل الأساسي المؤهل ونمط البحث. بمجرد استدعاء هذا الإجراء، يقع على عاتق روتين البحث إنشاء قائمة جديدة من الملفات وتحديث ويدجت FileSelectionBox باستخدام XtSetValues.
يجب على إجراء البحث تعيين XmNlistUpdated. إذا قام بإنشاء قائمة جديدة من الملفات، فيجب عليه أيضًا تعيين XmNfileListItems و XmNfileListItemCount.
يُوصى بأن يقوم إجراء البحث دائمًا بإنشاء قائمة جديدة من الملفات. إذا كان عضو mask في هيكل الاستدعاء هو نفسه عضو mask في هيكل الاستدعاء في الاستدعاء السابق لإجراء البحث، فقد يختار الإجراء عدم إنشاء قائمة جديدة من الملفات. في هذه الحالة، يجب عليه تعيين XmNlistUpdated إلى False.
إذا قام إجراء البحث بإنشاء قائمة جديدة من الملفات، فيجب عليه تعيين XmNfileListItems إلى قائمة الملفات الجديدة و XmNfileListItemCount إلى عدد العناصر في القائمة. إذا لم تكن هناك ملفات، فإنه يعين XmNfileListItems إلى NULL و XmNfileListItemCount إلى 0 (صفر). في كلتا الحالتين، يجب عليه تعيين XmNlistUpdated إلى True.
في بناء قائمة الملفات، يجب على إجراء البحث تضمين الملفات من الأنواع المحددة بواسطة XmNfileTypeMask للويدجت فقط.
تعيين XmNdirSpec اختياري، ولكنه موصى به. قم بتعيين هذا السمة إلى مواصفات الملف الكاملة للدليل الذي تم البحث فيه. يتم عرض مواصفات الدليل أسفل قوائم الدلائل والملفات.
XmNfileTypeMask
يحدد نوع الملفات المدرجة في قائمة الملفات. القيم الممكنة هي:
XmFILE_REGULAR
يقيّد قائمة الملفات لتضمين الملفات العادية فقط.
XmFILE_DIRECTORY
يقيّد قائمة الملفات لتضمين الدلائل فقط.
XmFILE_ANY_TYPE
يسمح للقائمة بتضمين جميع أنواع الملفات بما في ذلك الدلائل.
XmNfilterLabelString
يحدد سلسلة التسمية لحقل إدخال النص لقناع الدليل. يعتمد الافتراضي لهذا المورد على اللغة. في لغة C، الافتراضي هو Filter.
الآن بعد توفير بعض سلاسل التسمية الافتراضية المحلية من خلال كتالوجات الرسائل للأطفال من الويدجتات المركبة، لا يمكن تعيين موارد labelString على الطفل من خلال ملفات الموارد الافتراضية. بدلاً من ذلك، يجب استخدام المورد المقدم على مستوى الأصل.
XmNlistUpdated
يحدد سمة يتم تعيينها فقط بواسطة إجراءات البحث عن الدليل والملفات. يتم تعيين هذا المورد إلى True إذا قام إجراء البحث بتحديث قائمة الدلائل أو الملفات.
XmNnoMatchString
يحدد سلسلة لعرضها في قائمة الملفات إذا كانت قائمة الملفات فارغة.
XmNpattern
يحدد نمط البحث المستخدم بالاشتراك مع XmNdirectory في تحديد الملفات والدلائل التي سيتم عرضها. يتم تحديد القيمة الافتراضية بواسطة XmNqualifySearchDataProc وتعتمد على القيم الأولية لـ XmNdirMask و XmNdirectory و XmNpattern. إذا كانت القيمة الافتراضية NULL أو فارغة، يتم استخدام نمط يطابق جميع الملفات.
XmNpathMode
يحدد ما إذا كان سيتم استخدام حقل نص إضافي لعرض وتعديل المرشح. القيم الممكنة هي:
XmPATH_MODE_FULL
يحدد أنه لن يتم استخدام حقل نص إضافي لعرض المرشح. سيكون هناك حقل نص واحد فقط لعرض XmNdirMask.
XmPATH_MODE_RELATIVE
يحدد أنه سيكون هناك عرضين لحقل نص، أحدهما لعرض XmNdirectory والآخر لعرض XmNpattern. في هذه الحالة، ينطبق مورد XmNfilterLabelString على حقل النص الخاص بـ XmNpattern، وينطبق XmNdirTextLabelString على حقل النص الخاص بـ XmNdirectory.
XmNqualifySearchDataProc
يحدد إجراء تأهيل بيانات البحث لاستبدال إجراء تأهيل البيانات الافتراضي. إجراء تأهيل البيانات الافتراضي لـ FileSelectionBox يلبي احتياجات معظم التطبيقات. نظرًا لأنه من المستحيل تغطية متطلبات جميع التطبيقات، يمكنك استبدال الإجراء الافتراضي.
يتم استدعاء إجراء تأهيل البيانات لإنشاء قناع دليل مؤهل، ودليل أساسي، ونمط بحث لاستخدامهما بواسطة إجراءات البحث عن الدلائل والملفات. يتم استدعاؤه مع ثلاث وسيطات: ويدجت FileSelectionBox ومؤشرين لهيكلين XmFileSelectionBoxCallbackStruct. يحتوي هيكل الاستدعاء الأول على بيانات الإدخال. يحتوي هيكل الاستدعاء الثاني على
البيانات المخرجة، ليتم ملؤها بواسطة إجراء تأهيل البيانات.
إذا لم تكن عضويتا dir و pattern المدخلتان NULL، فيجب على الإجراء نسخهما إلى العضويتين المقابلتين لهما في هيكل رد الاتصال المخرج.
إذا كانت dir المدخلة NULL، فيقوم الإجراء بإنشاء dir المخرج على النحو التالي: إذا كانت mask المدخلة NULL، فيستخدم الإجراء XmNdirectory الخاص بالأداة كـ dir المخرج؛ وإلا، فإنه يستخرج dir المخرج من mask المدخلة. إذا كانت dir الناتجة فارغة، فيستخدم الإجراء الدليل الحالي بدلاً منها.
إذا كانت pattern المدخلة NULL، فيقوم الإجراء بإنشاء pattern المخرج على النحو التالي: إذا كانت mask المدخلة NULL، فيستخدم الإجراء XmNpattern الخاص بالأداة كـ pattern المخرج؛ وإلا، فإنه يستخرج pattern المخرج من mask المدخلة. إذا كان pattern الناتج فارغًا، فيستخدم الإجراء نمطًا يطابق جميع الملفات بدلاً من ذلك.
يقوم إجراء تأهيل البيانات بإنشاء mask المخرج من dir و pattern المخرجين. يجب على الإجراء التأكد من أن dir و pattern و mask المخرجة مؤهلة بالكامل.
إذا لم تكن value المدخلة NULL، فيجب على الإجراء نسخها إلى value المخرج؛ وإلا، فيجب على الإجراء نسخ XmNdirSpec الخاص بالأداة إلى value المخرج.
يجب على إجراء تأهيل البيانات حساب أطوال عضويات value و mask و dir و pattern المخرجة ويجب عليه ملء عضويات الطول المقابلة لهما في بنية رد الاتصال المخرجة.
يجب على إجراء تأهيل البيانات نسخ عضويتي reason و event المدخلتين إلى العضويتين المخرجتين المقابلتين.

قيم XmNdirSearchProc و XmNfileSearchProc هي مؤشرات إجراءات من النوع XmSearchProc، معرّفة على النحو التالي:

void (* XmSearchProc) (w, search_data)
        Widget w;
        XtPointer search_data;
w

search_data
مؤشر إلى XmFileSelectionBoxCallbackStruct يحتوي على معلومات لإجراء بحث

قيمة المورد XmNqualifySearchDataProc هي مؤشر إجراء من النوع XmQualifyProc، معرّفة على النحو التالي:

void (* XmQualifyProc) (w, input_data, output_data)
        Widget w;
        XtPointer input_data;
        XtPointer output_data;

input_data

output_data
مؤشر إلى XmFileSelectionBoxCallbackStruct يحتوي على بيانات مخرجة ليتم ملؤها بواسطة إجراء التأهيل

يتم تمرير مؤشر إلى الهيكل التالي إلى كل رد نداء:

typedef struct
{
        int reason;
        XEvent * event;
        XmString value;
        int length;
        XmString mask;
        int mask_length;
        XmString dir;
        int dir_length;
        XmString pattern;
        int pattern_length;
} XmFileSelectionBoxCallbackStruct;
reason
يشير إلى سبب استدعاء رد النداء
event
يشير إلى XEvent الذي أدى إلى تشغيل رد النداء
value
يحدد القيمة الحالية لـ XmNdirSpec
length
يحدد عدد البايتات في value هذا العضو قديم ويوجد للتوافق مع الإصدارات السابقة.
mask
يحدد القيمة الحالية لـ XmNdirMask
mask_length
يحدد عدد البايتات في mask هذا العضو قديم ويوجد للتوافق مع الإصدارات السابقة.
dir
يحدد الدليل الأساسي الحالي
dir_length
يحدد عدد البايتات في dir هذا العضو قديم ويوجد للتوافق مع الإصدارات السابقة.
pattern
يحدد نمط البحث الحالي
pattern_length
يحدد عدد البايتات في pattern هذا العضو قديم ويوجد للتوافق مع الإصدارات السابقة.

الترجمات

يرث XmFileSelectionBox الترجمات من XmSelectionBox.

المسرعات

تتم إضافة XmNtextAccelerators من XmSelectionBox إلى أحفاد النص الخاص بالاختيار وقناع الدليل (التصفية) لـ XmFileSelectionBox.

إجراءات الروتين

إجراءات روتين XmFileSelectionBox هي:

SelectionBoxUpOrDown(Previous|Next|First|Last):
إذا لم يكن نص الاختيار ولا نص قناع الدليل (التصفية) لديه التركيز، فإن هذا الإجراء لا يفعل شيئًا.
إذا كان نص الاختيار لديه التركيز، فإن المصطلح list في الوصف التالي يشير إلى قائمة الملفات، والمصطلح text يشير إلى نص الاختيار. إذا كان نص قناع الدليل لديه التركيز، فإن list يشير إلى قائمة الدليل، و text يشير إلى نص قناع الدليل.
عند استدعائه بحجة Previous، أو 0 (صفر) للتوافق، يقوم هذا الإجراء بتحديد العنصر السابق في القائمة واستبدال النص بهذا العنصر.
عند استدعائه بحجة Next، أو 1 للتوافق، يقوم هذا الإجراء بتحديد العنصر التالي في القائمة واستبدال النص بهذا العنصر.
عند استدعائه بحجة First، أو 2 للتوافق، يقوم هذا الإجراء بتحديد العنصر الأول في القائمة واستبدال النص بهذا العنصر.
عند استدعائه بحجة Last، أو 3 للتوافق، يقوم هذا الإجراء بتحديد العنصر الأخير في القائمة واستبدال النص بهذا العنصر.
SelectionBoxRestore():
إذا لم يكن نص الاختيار ولا نص قناع الدليل (التصفية) لديه التركيز، فإن هذا الإجراء لا يفعل شيئًا.
إذا كان نص الاختيار لديه التركيز، فإن هذا الإجراء يستبدل نص الاختيار بالعنصر المحدد في قائمة الملفات. إذا لم يتم تحديد أي عنصر في قائمة الملفات، فإنه يمسح نص الاختيار.
إذا كان نص قناع الدليل لديه التركيز، فإن هذا الإجراء يستبدل نص قناع الدليل بقناع دليل جديد تم إنشاؤه من موارد XmNdirectory و XmNpattern.

سلوك إضافي

يحتوي عنصر واجهة مستخدم FileSelectionBox على السلوك الإضافي التالي:

<Key><osfCancel>:
يستدعي ردود نداء التفعيل لزر الإلغاء إذا كان حساسًا. إذا لم يكن هناك زر إلغاء وكان الأصل لـ FileSelectionBox هو مدير، فإنه يمرر الحدث إلى الأصل.
<Key><osfActivate> في Selection Text:
يستدعي ردود نداء XmNactivateCallback لعنصر نص الاختيار. إذا كان XmNmustMatch صحيحًا ولم يتطابق نص الاختيار مع عنصر في قائمة الملفات، فإنه يستدعي ردود نداء XmNnoMatchCallback مع السبب XmCR_NO_MATCH. بخلاف ذلك، فإنه يستدعي ردود نداء XmNokCallback مع السبب XmCR_OK.
<Key><osfActivate> في Directory Mask Text:
يستدعي ردود نداء XmNactivateCallback لعنصر نص قناع الدليل، ويبدأ بحثًا عن الدليل والملفات، ويستدعي ردود نداء XmNapplyCallback مع السبب XmCR_APPLY.
<Btn1Down>(2+) or <Key><osfActivate> في Directory List:
يستدعي ردود نداء XmNdefaultActionCallback لعنصر قائمة الدليل، ويبدأ بحثًا عن الدليل والملفات، ويستدعي ردود نداء XmNapplyCallback مع السبب XmCR_APPLY.
<Btn1Down>(2+) or <Key><osfActivate> في File List:
يستدعي ردود نداء XmNdefaultActionCallback لعنصر قائمة الملفات ويستدعي ردود نداء XmNokCallback مع السبب XmCR_OK.
<Key><osfSelect> في Directory List:
ينشئ قناع دليل جديد، باستخدام العنصر المحدد في القائمة كدليل ونمط البحث المستخرج من نص قناع الدليل الحالي. إذا كان نمط البحث فارغًا، فإنه يستخدم نمطًا يطابق جميع الملفات في الدليل. يستبدل نص قناع الدليل بقناع الدليل الجديد.
<Key><osfSelect> في File List:
يستبدل نص الاختيار بالعنصر المحدد في القائمة.
<Btn2Down> في File List:
يسحب محتوى عنصر واحد أو أكثر من العناصر المحددة في القائمة باستخدام مرفق السحب والإفلات. إذا تم الضغط على <Btn2Down على عنصر غير محدد، فإنه يسحب هذا العنصر فقط، باستثناء أي عناصر أخرى محددة.
يقوم هذا الإجراء بتعيين XmNconvertProc لـ DragContext إلى دالة تستدعي إجراءات XmNconvertCallback لقائمة الملفات، ربما عدة مرات، للتحديد _MOTIF_DROP.
<Btn2Down> في Directory List:
يسحب محتوى عنصر واحد أو أكثر من العناصر المحددة في القائمة باستخدام مرفق السحب والإفلات. إذا تم الضغط على <Btn2Down على عنصر غير محدد، فإنه يسحب هذا العنصر فقط، باستثناء أي عناصر أخرى محددة.
يقوم هذا الإجراء بتعيين XmNconvertProc لـ DragContext إلى دالة تستدعي إجراءات XmNconvertCallback لقائمة الدليل، ربما عدة مرات، للتحديد _MOTIF_DROP.
<Apply Button Activated>:
يبدأ بحثًا عن الدليل والملفات. يستدعي ردود نداء XmNapplyCallback مع السبب XmCR_APPLY.
<OK Button Activated>:
إذا كان XmNmustMatch صحيحًا ولم يتطابق نص الاختيار مع عنصر في قائمة الملفات، فإنه يستدعي ردود نداء XmNnoMatchCallback مع السبب XmCR_NO_MATCH. بخلاف ذلك، فإنه يستدعي ردود نداء XmNokCallback مع السبب XmCR_OK.
<Cancel Button Activated>:
يستدعي ردود نداء XmNcancelCallback مع السبب XmCR_CANCEL.
<Help Button Activated>:
يستدعي ردود نداء XmNhelpCallback مع السبب XmCR_HELP.
<Key><osfActivate>:
إذا لم يكن لدى أي زر أو عنصر قائمة أو عنصر نص التركيز على لوحة المفاتيح، وإذا كان XmNmustMatch صحيحًا ولم يتطابق نص الاختيار مع عنصر في قائمة الملفات، فإنه يستدعي ردود نداء XmNnoMatchCallback مع السبب XmCR_NO_MATCH. بخلاف ذلك، فإنه يستدعي ردود نداء XmNokCallback callbacks مع السبب XmCR_OK.
