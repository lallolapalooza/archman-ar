XML__LibXML__Simple(3pm)

الحزمة: perl-xml-libxml-simple

التراخيص: PerlArtistic, GPL

XML::LibXML::Simple(3) وثائق Perl المساهمة من المستخدم XML::LibXML::Simple(3)

الاسم

XML::LibXML::Simple - نسخة طبق الأصل من XML::LibXML لـ XMLin() في XML::Simple

الوراثة

XML::LibXML::Simple
  هو Exporter

الملخص

my $xml  = ...;  # اسم الملف، أو مقبض الملف، أو السلسلة، أو عقدة XML::LibXML

الطريقة الإجرائية:

use XML::LibXML::Simple   qw(XMLin);
my $data = XMLin $xml, %options;

أو الطريقة الشيئية:

use XML::LibXML::Simple   ();
my $xs   = XML::LibXML::Simple->new(%options);
my $data = $xs->XMLin($xml, %options);

الوصف

هذه الوحدة هي إعادة كتابة صريحة لـ XML::Simple (بواسطة Grant McLean) لاستخدام محلل XML::LibXML لهياكل XML، بينما يستخدم الأصل محللات Perl العادية أو SAX.

كن حذرًا: هذه الوحدة تعتقد أنها ذكية. قد تصيب نفسك بسهولة بالتسبب في مشاكل مع هذه القدرة على "القيام بما تتوقعه". اقرأ صفحة الدليل بأكملها مرة واحدة على الأقل قبل البدء في استخدامها. إذا تم وصف XML الخاص بك في مخطط (schema) أو WSDL، فاستخدم XML::Compile للحصول على كود قابل للصيانة.

الأساليب

المنشئات

XML::LibXML::Simple->new(%options)
إنشاء كائن، يمكن استخدامه لاستدعاء XMLin() عليه. يمكنك توفير %options لهذا المنشئ (لإعادة استخدامها لكل استدعاء لـ XMLin) ومع كل استدعاء لـ XMLin (لاستخدامها مرة واحدة)

لأوصاف %options، راجع قسم "التفاصيل" في صفحة الدليل هذه.

المترجمات

$obj->XMLin($xmldata, %options)
بالنسبة لـ $xmldata وأوصاف %options، راجع قسم "التفاصيل" في صفحة الدليل هذه.

الوظائف

الوظائف "XMLin" (مُصدَّرة ضمنيًا) و "xml_in" (مُصدَّرة عند الطلب) تستدعي ببساطة "<XML::LibXML::Simple-"new->XMLin() >> مع المعلمات المقدمة.

التفاصيل

المعلمة $xmldata

كأول معلمة لـ XMLin()، يجب عليك توفير رسالة XML ليتم ترجمتها إلى بنية Perl. اختر أحد الخيارات التالية:

اسم ملف
إذا كان اسم الملف لا يحتوي على مكونات دليل، فسيقوم XMLin() بالبحث عن الملف في كل دليل في مسار البحث (انظر الخيارات أدناه) وفي الدليل الحالي. مثال: 
$data = XMLin('/etc/params.xml', %options);
شرطة (-)
التحليل من الإدخال القياسي (STDIN). 
$data = XMLin('-', %options);
undef
[مهمل] إذا لم يكن هناك محدد XML، فسيتحقق XMLin() من دليل البرنامج النصي وكل دليل في مسار البحث عن ملف يحمل نفس اسم البرنامج النصي ولكن بالامتداد '.xml'. ملاحظة: إذا كنت ترغب في تحديد خيارات، فيجب عليك تحديد القيمة 'undef'. مثال: 
$data = XMLin(undef, ForceArray => 1);

هذه الميزة متاحة للتوافق مع الإصدارات السابقة مع XML::Simple، ولكنها حساسة للغاية. يمكنك بسهولة الوصول إلى ملف XML الخاطئ كمدخل. يرجى عدم استخدامه: استخدم دائمًا اسم ملف صريح.

سلسلة من XML
سيتم تحليل سلسلة تحتوي على XML (يتم التعرف عليها بوجود علامتي '<' و '>') مباشرة. مثال: 
$data = XMLin('<opt username="bob" password="flurp" />', %options);
كائن IO::Handle
في هذه الحالة، ستقرأ XML::LibXML::Parser بيانات XML مباشرة من الملف المقدم. 
# $fh = IO::File->new('/etc/params.xml') or die;
open my $fh, '<:encoding(utf8)', '/etc/params.xml' or die;
$data = XMLin($fh, %options);
XML::LibXML::Document أو ::Element
[غير متوفر في XML::Simple] عندما يكون لديك عقدة XML::LibXML مُحللة مسبقًا، يمكنك تمريرها.

المعلمة %options

تدعم XML::LibXML::Simple معظم الخيارات التي تحددها XML::Simple، لذلك الواجهة متوافقة تمامًا. تنطبق تغييرات طفيفة. هذا الشرح مستخرج من صفحة دليل XML::Simple.

  • تحقق من "ForceArray" لأنك سترغب في تشغيلها بالتأكيد
  • تأكد من أنك تعرف ما تفعله خيار "KeyAttr" وما هي قيمته الافتراضية لأنه قد يفاجئك بخلاف ذلك.
  • أسماء الخيارات غير حساسة لحالة الأحرف، لذا يمكنك استخدام الإصدارات المختلطة الموضح هنا؛ يمكنك إضافة شرطات سفلية بين الكلمات (مثل: key_attr) إذا أردت.

بالترتيب الأبجدي:

ContentKey => 'keyname' # نادر الاستخدام
عندما يتم تحليل المحتوى النصي إلى قيمة تجزئة (hash)، يسمح لك هذا الخيار بتحديد اسم لمفتاح التجزئة لتجاوز الاسم الافتراضي 'content'. لذا على سبيل المثال: 
XMLin('<opt one="1">Two</opt>', ContentKey => 'text')

سيتم تحليله إلى:

{ one => 1, text => 'Two' }

بدلاً من:

{ one => 1, content => 'Two' }

يمكنك أيضًا إضافة بادئة لاسم المفتاح الذي اخترته بحرف '-' لجعل XMLin() تبذل جهدًا أكبر لإزالة مفاتيح 'content' غير الضرورية بعد دمج المصفوفة. على سبيل المثال:

XMLin(
  '<opt><item name="one">First</item><item name="two">Second</item></opt>', 
  KeyAttr => {item => 'name'}, 
  ForceArray => [ 'item' ],
  ContentKey => '-content'
)

سيتم تحليله إلى:

{
   item => {
    one =>  'First'
    two =>  'Second'
  }
}

بدلاً من هذا (بدون '-'):

{
  item => {
    one => { content => 'First' }
    two => { content => 'Second' }
  }
}
ForceArray => 1 # مهم
يجب تعيين هذا الخيار إلى '1' لفرض عناصر متداخلة ليتم تمثيلها كمصفوفات حتى عندما يكون هناك عنصر واحد فقط. على سبيل المثال، مع تمكين ForceArray، هذا الـ XML: 
<opt>
  <name>value</name>
</opt>

سيتم تحليله إلى هذا:

{ name => [ 'value' ] }

بدلاً من هذا (الافتراضي):

{ name => 'value' }

هذا الخيار مفيد بشكل خاص إذا كان من المحتمل أن يتم إعادة كتابة بنية البيانات كـ XML وكان السلوك الافتراضي لدمج العناصر الفردية المتداخلة في سمات غير مرغوب فيه.

إذا كنت تستخدم ميزة دمج المصفوفة، فيجب عليك بالتأكيد تمكين هذا الخيار. إذا لم تفعل، فلن يتم تحليل العناصر الفردية المتداخلة إلى مصفوفات وبالتالي لن تكون مرشحة للدمج في تجزئة (hash). (نظرًا لأن القيمة الافتراضية لـ 'KeyAttr' تمكن دمج المصفوفة، كان يجب تمكين القيمة الافتراضية لهذا الخيار أيضًا).

ForceArray => [ names ] # مهم
هذا الشكل البديل (والمفضل) لخيار 'ForceArray' يسمح لك بتحديد قائمة بأسماء العناصر التي يجب دائمًا إجبارها على تمثيل المصفوفة، بدلاً من نهج 'الكل أو لاشيء' المذكور أعلاه.

من الممكن أيضًا تضمين تعبيرات عادية (regular expressions) مُجمَّعة في القائمة - سيتم إجبار أي أسماء عناصر تطابق النمط على أن تكون مصفوفات. إذا كانت القائمة تحتوي على تعبير عادي واحد فقط، فلا يلزم إحاطته بـ arrayref. مثال:

ForceArray => qr/_list

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

$/
ForceContent => 1 # نادر الاستخدام
عندما تقوم XMLin() بتحليل العناصر التي تحتوي على محتوى نصي بالإضافة إلى سمات، يجب تمثيل المحتوى النصي كقيمة هاش بدلاً من قيمة قياسية بسيطة. يتيح لك هذا الخيار فرض تحليل المحتوى النصي دائمًا إلى قيمة هاش حتى عندما لا تكون هناك سمات. على سبيل المثال: 
XMLin('<opt><x>text1</x><y a="2">text2</y></opt>', ForceContent => 1)

سيتم تحليله إلى:

{
  x => {         content => 'text1' },
  y => { a => 2, content => 'text2' }
}

بدلاً من:

{
  x => 'text1',
  y => { 'a' => 2, 'content' => 'text2' }
}
GroupTags => { tag التجميع => tag مجمّع } # مفيد
يمكنك استخدام هذا الخيار لإزالة مستويات إضافية من التوجيه غير المباشر في هيكل بيانات Perl الخاص بك. على سبيل المثال، هذا XML: 
 <opt>
  <searchpath>
    <dir>/usr/bin</dir>
    <dir>/usr/local/bin</dir>
    <dir>/usr/X11/bin</dir>
  </searchpath>
</opt>

سيتم قراءته بشكل طبيعي في هيكل مثل هذا:

{
  searchpath => {
     dir => [ '/usr/bin', '/usr/local/bin', '/usr/X11/bin' ]
  }
}

ولكن عند قراءته مع القيمة المناسبة لـ 'GroupTags':

my $opt = XMLin($xml, GroupTags => { searchpath => 'dir' });

سيعود بهيكل أبسط:

{
  searchpath => [ '/usr/bin', '/usr/local/bin', '/usr/X11/bin' ]
}

يجب ألا يحتوي عنصر التجميع ("<searchpath>" في المثال) على أي سمات أو عناصر بخلاف العنصر المجمع.

يمكنك تحديد تعيينات متعددة من 'عنصر التجميع' إلى 'عنصر مجمع' في نفس الهاش. إذا تم دمج هذا الخيار مع "KeyAttr"، فسيحدث طي المصفوفة أولاً ثم سيتم إزالة أسماء العناصر المجمعة.

HookNodes => CODE
تحديد عقد المستند لتطبيق خدع خاصة. تم تقديمه في [0.96]، غير متوفر في XML::Simple.

عند توفير هذا الخيار، سيتم استدعاء CODE مرة واحدة عندما تكون شجرة DOM XML جاهزة للتحويل إلى Perl. يجب أن يعيد CODE إما "undef" (لا شيء للقيام به) أو HASH يربط قيم unique_key (راجع طريقة XML::LibXML::Node "unique_key") إلى مراجع CODE ليتم استدعاؤها.

بمجرد أن يصل المترجم من XML إلى Perl إلى عقدة محددة، سيستدعي روتينك الخاص بتلك العقدة. هذه العقدة المحفزة هي المعلمة الوحيدة. عندما تعيد "undef"، لن يتم العثور على العقدة في النتيجة النهائية. يمكنك إرجاع أي بيانات (حتى العقدة نفسها) التي سيتم تضمينها في النتيجة النهائية كما هي، تحت اسم العقدة الأصلية.

مثال:

my $out = XMLin $file, HookNodes => \&protect_html;
sub protect_html($$)
{   # $obj هو كائن XML::Compile::Simple المُنشأ
    # $xml هو XML::LibXML::Element ليتم تحويله
    my ($obj, $xml) = @_;
    my %hooks;    # يجمع جدول الخطافات
    # قم بإجراء بحث xpath عن HTML
    my $xpc   = XML::LibXML::XPathContext->new($xml);
    my @nodes = $xpc->findNodes(...); #XXX
    @nodes or return undef;
    my $as_text = sub { $_[0]->toString(0) };  # كنص
    #  $as_node = sub { $_[0] };               # كعقدة
    #  $skip    = sub { undef };               # على الإطلاق
    # نفس السلوك لجميع عقد xpath، في هذا المثال
    $hook{$_->unique_key} = $as_text
        for @nodes;

    \%hook;
}
KeepRoot => 1 # مفيد
في محاولته لإرجاع هيكل بيانات خالٍ من التفاصيل غير الضرورية ومستويات التوجيه غير الضرورية، تتجاهل XMLin() عادةً اسم العنصر الجذر. سيؤدي تعيين الخيار 'KeepRoot' إلى '1' إلى الاحتفاظ باسم العنصر الجذر. لذلك بعد تنفيذ هذا الكود: 
$config = XMLin('<config tempdir="/tmp" />', KeepRoot => 1)

ستتمكن من الإشارة إلى tempdir كـ "$config->{config}->{tempdir}" بدلاً من الافتراضي "$config->{tempdir}".

KeyAttr => [ قائمة ] # مهم
يتحكم هذا الخيار في ميزة 'طي المصفوفة' التي تحول العناصر المتداخلة من مصفوفة إلى هاش. كما أنه يتحكم في 'فك' الهاش إلى مصفوفات.

على سبيل المثال، هذا XML:

<opt>
  <user login="grep" fullname="Gary R Epstein" />
  <user login="stty" fullname="Simon T Tyson" />
</opt>

بشكل افتراضي، سيتم تحليله إلى هذا:

{
  user => [
     { login    => 'grep',
       fullname => 'Gary R Epstein'
     },
     { login    => 'stty',
       fullname => 'Simon T Tyson'
     }
  ]
}

إذا تم استخدام الخيار 'KeyAttr => "login"' لتحديد أن السمة 'login' هي مفتاح، فسيتم تحليل نفس XML إلى:

{
  user => {
     stty => { fullname => 'Simon T Tyson' },
     grep => { fullname => 'Gary R Epstein' }
  }
}

يجب توفير أسماء سمات المفتاح في مصفوفة إذا كان هناك أكثر من واحد. ستحاول XMLin() مطابقة أسماء السمات بالترتيب المقدم.

ملاحظة 1: القيمة الافتراضية لـ 'KeyAttr' هي "['name', 'key', 'id']". إذا كنت لا تريد الطي عند الإدخال أو الفك عند الإخراج، فيجب عليك تعيين هذا الخيار إلى قائمة فارغة لتعطيل الميزة.

ملاحظة 2: إذا كنت ترغب في استخدام هذا الخيار، فيجب عليك أيضًا تمكين "ForceArray". بدون 'ForceArray'، سيتم تحويل عنصر متداخل واحد إلى قيمة قياسية بدلاً من مصفوفة وبالتالي لن يتم طيه (لأن المصفوفات فقط يتم طيها).

KeyAttr => { قائمة } # مهم
تسمح هذه الطريقة البديلة (والمفضلة) لتحديد سمات المفتاح بتحكم أدق في العناصر التي يتم طيها وعلى أي سمات. على سبيل المثال، الخيار 'KeyAttr => { package => 'id' } سيؤدي إلى طي أي عناصر package على السمة 'id'. لن يتم طي أي عناصر أخرى تحتوي على السمة 'id' على الإطلاق.

يتم تمكين شكلين إضافيين من خلال إضافة البادئة '+' أو '-' إلى اسم السمة:

الخيار 'KeyAttr => { user => "+login" }' سيؤدي إلى هذا XML:

<opt>
  <user login="grep" fullname="Gary R Epstein" />
  <user login="stty" fullname="Simon T Tyson" />
</opt>

للتحليل إلى هيكل البيانات هذا:

{
  user => {
     stty => {
        fullname => 'Simon T Tyson',
        login    => 'stty'
     },
     grep => {
        fullname => 'Gary R Epstein',
        login    => 'grep'
     }
  }
}

تشير '+' إلى أنه يجب نسخ قيمة سمة المفتاح بدلاً من نقلها إلى مفتاح الهاش المطوي.

سيؤدي البادئة '-' إلى إنتاج هذه النتيجة:

{
  user => {
     stty => {
        fullname => 'Simon T Tyson',
        -login   => 'stty'
     },
     grep => {
        fullname => 'Gary R Epstein',
        -login    => 'grep'
     }
  }
}
NoAttr => 1 # مفيد
عند استخدامه مع XMLin()، سيتم تجاهل أي سمات في XML.
NormaliseSpace => 0 | 1 | 2 # مفيد
يتحكم هذا الخيار في كيفية التعامل مع المسافات البيضاء في المحتوى النصي. القيم المعترف بها للخيار هي:
"0"
(افتراضي) يتم تمرير المسافات البيضاء دون تغيير (باستثناء بالطبع تطبيع المسافات البيضاء في قيم السمات المفروضة بموجب توصية XML)
"1"
يتم تطبيع المسافات البيضاء في أي قيمة مستخدمة كمفتاح هاش (التطبيع يعني إزالة المسافات البادئة واللاحقة ودمج تسلسلات المسافات البيضاء إلى مسافة واحدة)
"2"
يتم تطبيع المسافات البيضاء في كل المحتوى النصي

ملاحظة: يمكنك تهجئة هذا الخيار بحرف 'z' إذا كان ذلك طبيعيًا لك.

Parser => OBJECT
يمكنك تمرير كائن XML::LibXML الخاص بك، بدلاً من إنشاء واحد لك. هذا مفيد عندما تحتاج إلى تكوين معين لهذا الكائن (انظر XML::LibXML::Parser) أو قمت بتطبيق امتداد خاص بك لهذا الكائن.

كائن المحلل المدمج تم تكوينه في وضع آمن. اقرأ دليل XML::LibXML::Parser حول قضايا الأمان مع إعدادات معينة للمعلمات. الافتراضي غير آمن!

ParserOpts => HASH|ARRAY
تمرير معلمات لإنشاء كائن محلل داخلي جديد. يمكنك تجاوز الخيارات التي ستنشئ محللًا آمنًا. قد يكون من الأسهل قراءة استخدام "Parser" المعلمة.
SearchPath => [ قائمة ] # مفيد
إذا قمت بتمرير اسم ملف إلى XMLin()، ولكن اسم الملف لا يتضمن مكون دليل، فيمكنك استخدام هذا الخيار لتحديد الأدلة التي يجب البحث فيها لتحديد موقع الملف. قد تستخدم هذا الخيار للبحث أولاً في الدليل الرئيسي للمستخدم، ثم في دليل عام مثل /etc.

إذا تم توفير اسم ملف لـ XMLin() ولكن SearchPath غير محدد، فمن المفترض أن يكون الملف في الدليل الحالي.

إذا كان المعلمة الأولى لـ XMLin() غير محددة، فسيتضمن SearchPath الافتراضي فقط الدليل الذي يوجد فيه البرنامج النصي نفسه. بخلاف ذلك، سيكون SearchPath الافتراضي فارغًا.

SuppressEmpty => 1 | '' | undef
[0.99] ماذا تفعل بالعناصر الفارغة (بدون سمات وبدون محتوى). السلوك الافتراضي هو تمثيلها كهاش فارغ. تعيين
- "هذا" option to a true value (eg: 1) will cause empty elements to be skipped altogether. Setting the option to 'undef' or the empty string will cause empty elements to be represented as the undefined value or the empty string respectively.
ValueAttr => [ names ] # handy
استخدم هذا الخيار للتعامل مع العناصر التي تحتوي دائمًا على سمة واحدة ولا يوجد بها محتوى. مثال: 
<opt>
  <colour value="red" />
  <size   value="XXL" />
</opt>

سيؤدي تعيين الخيار "ValueAttr => [ 'value' ]" إلى تحليل XML أعلاه إلى:

{
  colour => 'red',
  size   => 'XXL'
}

بدلاً من هذا (الافتراضي):

{
  colour => { value => 'red' },
  size   => { value => 'XXL' }
}
NsExpand => 0 advised
عند استخدام مساحات الأسماء، يكون السلوك الافتراضي هو تضمين البادئة في اسم المفتاح. ومع ذلك، هذا خطير جدًا: يمكن تغيير البادئات دون تغيير معنى رسالة XML. لذلك، يمكنك استخدام هذا الخيار "NsExpand" بشكل أفضل. الجانب السلبي، ومع ذلك، هو أن الملصقات تصبح طويلة جدًا.

بدون هذا الخيار:

<record xmlns:x="http://xyz">
  <x:field1>42</x:field1>
</record>
<record xmlns:y="http://xyz">
  <y:field1>42</y:field1>
</record>

يترجم إلى

{ 'x:field1' => 42 }
{ 'y:field1' => 42 }

ولكن كلا المكونين المصدر لهما نفس المعنى تمامًا. عند استخدام "NsExpand"، تكون النتيجة:

{ '{http://xyz}field1' => 42 }
{ '{http://xyz}field1' => 42 }

بالطبع، معالجة هذه الحقول تتطلب المزيد من العمل. يُنصح بتنفيذها على النحو التالي:

my $ns = 'http://xyz';
$data->{"{$ns}field1"};
NsStrip => 0 sloppy coding
[غير متوفر في XML::Simple] مساحات الأسماء مهمة جدًا لتجنب تعارض الأسماء، ولكنها قد تكون مزعجة بعض الشيء. للقيام بذلك بشكل صحيح، استخدم الخيار "NsExpand". للقيام بذلك بشكل غير دقيق، استخدم "NsStrip". مع تعيين هذا الخيار، سيعود المثال أعلاه بـ 
{ field1 => 42 }
{ field1 => 42 }

أمثلة

عندما تقرأ XMLin() قطعة XML بسيطة جدًا التالية:

<opt username="testuser" password="frodo"></opt>

فإنها تعيد هيكل البيانات التالي:

{
  username => 'testuser',
  password => 'frodo'
}

كان يمكن إنتاج نفس النتيجة باستخدام XML البديل التالي:

<opt username="testuser" password="frodo" />

أو هذا (على الرغم من انظر الخيار 'ForceArray' للاختلافات):

<opt>
  <username>testuser</username>
  <password>frodo</password>
</opt>

يتم تمثيل العناصر المتداخلة المتكررة كمصفوفات مجهولة:

<opt>
  <person firstname="Joe" lastname="Smith">
    <email>joe@smith.com</email>
    <email>jsmith@yahoo.com</email>
  </person>
  <person firstname="Bob" lastname="Smith">
    <email>bob@smith.com</email>
  </person>
</opt>
{
  person => [
    { email     => [ 'joe@smith.com', 'jsmith@yahoo.com' ],
      firstname => 'Joe',
      lastname  => 'Smith'
    },
    { email     => 'bob@smith.com',
      firstname => 'Bob',
      lastname  => 'Smith'
    }
  ]
}

يتم تحويل العناصر المتداخلة ذات سمة مفتاح معترف بها (طيها) من مصفوفة إلى جدول تجزئة مفهرس بقيمة تلك السمة (انظر خيار "KeyAttr"):

<opt>
  <person key="jsmith" firstname="Joe" lastname="Smith" />
  <person key="tsmith" firstname="Tom" lastname="Smith" />
  <person key="jbloggs" firstname="Joe" lastname="Bloggs" />
</opt>
{
  person => {
     jbloggs => {
        firstname => 'Joe',
        lastname  => 'Bloggs'
     },
     tsmith  => {
        firstname => 'Tom',
        lastname  => 'Smith'
     },
     jsmith => {
        firstname => 'Joe',
        lastname => 'Smith'
     }
  }
}

يمكن استخدام العلامة <anon> لإنشاء مصفوفات مجهولة:

<opt>
  <head><anon>Col 1</anon><anon>Col 2</anon><anon>Col 3</anon></head>
  <data><anon>R1C1</anon><anon>R1C2</anon><anon>R1C3</anon></data>
  <data><anon>R2C1</anon><anon>R2C2</anon><anon>R2C3</anon></data>
  <data><anon>R3C1</anon><anon>R3C2</anon><anon>R3C3</anon></data>
</opt>
{
  head => [ [ 'Col 1', 'Col 2', 'Col 3' ] ],
  data => [ [ 'R1C1', 'R1C2', 'R1C3' ],
            [ 'R2C1', 'R2C2', 'R2C3' ],
            [ 'R3C1', 'R3C2', 'R3C3' ]
          ]
}

يمكن تداخل المصفوفات المجهولة إلى مستويات اعتباطية وكحالة خاصة، إذا كانت العلامات المحيطة بوثيقة XML تحتوي فقط على مصفوفة مجهولة، فسيتم إرجاع مرجع المصفوفة مباشرة بدلاً من المرجع العادي للجدول:

<opt>
  <anon><anon>Col 1</anon><anon>Col 2</anon></anon>
  <anon><anon>R1C1</anon><anon>R1C2</anon></anon>
  <anon><anon>R2C1</anon><anon>R2C2</anon></anon>
</opt>
[
  [ 'Col 1', 'Col 2' ],
  [ 'R1C1', 'R1C2' ],
  [ 'R2C1', 'R2C2' ]
]

سيتم تمثيل العناصر التي تحتوي فقط على محتوى نصي ببساطة كقيمة أساسية. عندما يحتوي العنصر على سمات ومحتوى نصي، سيتم تمثيل العنصر كجدول تجزئة مع المحتوى النصي في المفتاح 'content' (انظر خيار "ContentKey"):

<opt>
  <one>first</one>
  <two attr="value">second</two>
</opt>
{
  one => 'first',
  two => { attr => 'value', content => 'second' }
}

المحتوى المختلط (العناصر التي تحتوي على محتوى نصي وعناصر متداخلة) لن يتم تمثيلها بطريقة مفيدة - سيتم فقدان ترتيب العناصر والمسافات البيضاء المهمة. إذا كنت بحاجة إلى العمل مع محتوى مختلط، فإن XML::Simple ليس الأداة المناسبة لمهمتك - تحقق من القسم التالي.

الاختلافات عن XML::Simple

بشكل عام، تكون المخرجات والخيارات مكافئة، على الرغم من أن هذه الوحدة لديها بعض الاختلافات مع XML::Simple التي يجب أن تكون على دراية بها.

فقط XMLin() مدعوم
إذا كنت ترغب في كتابة XML، فاستخدم مخططًا (على سبيل المثال مع XML::Compile). لا تحاول إنشاء XML يدويًا! إذا كنت لا تزال تعتقد أنك بحاجة إليها، فابحث عن XMLout() كما هو مطبق بواسطة XML::Simple أو أي من أنظمة القوالب المتعددة.
لا يوجد خيار "variables"
في رأيي، يجب عليك استخدام نظام قوالب إذا كنت تريد ملء المتغيرات في الإدخال: هذه ليست مهمة لهذه الوحدة.
خيارات ForceArray
هناك بعض الاختلافات الطفيفة في نتيجة خيار "forcearray"، لأن XML::Simple يبدو أنه يتصرف بشكل غير متسق.
hooks (خطافات)
XML::Simple لا يدعم الخطافات.

انظر أيضًا

XML::Compile لمعالجة XML عندما يكون المخطط متاحًا. عندما يكون لديك مخطط، يتم التحقق من صحة البيانات وهيكل رسالتك.

XML::Simple، التطبيق الأصلي الذي تم اتباع واجهته بأكبر قدر ممكن من الدقة.
