t object، ويعيد كائن XML::LibXML::Document جديد. تُستخدم إدخالات الـ hash الإضافية كـ معاملات. تأكد من الانتباه إلى التحذير المتعلق بعلامات التنصيص الموضح في قسم "المعاملات" أدناه.

transform_file(filename, %params)
my $results = $stylesheet->transform_file($filename, bar => "'baz'");

لاحظ التحذير المتعلق بمعاملات السلاسل النصية، والمفصل في قسم "المعاملات" أدناه.

output_as_bytes(result)
يعيد قيمة عددية تمثل عرض XSLT لكائن XML::LibXML::Document بالتنسيق الناتج المطلوب (المحدد في وسم xsl:output في ورقة الأنماط). لاحظ أنه يمكنك أيضًا استدعاء $result->toString، ولكن هذا *سيقوم دائمًا* بعرض المستند بتنسيق XML، وهو ما قد لا يكون ما طلبته في وسم xsl:output. القيمة العددية هي سلسلة بايت مشفرة بالترميز الناتج المحدد في ورقة الأنماط.
output_as_chars(result)
مثل output_as_bytes(result)، ولكنه يعيد الناتج دائمًا كسلسلة أحرف (مشفرة بـ UTF-8).
output_string(result)
تم إهمالها: هذه الدالة هي شيء بين output_as_bytes(result) و output_as_bytes(result): القيمة العددية التي تعيدها هذه الدالة تبدو لـ Perl كأحرف (مع تمكين علامة UTF8) إذا كان ترميز الإخراج المحدد في ورقة أنماط XSLT هو UTF-8، وكبايتات إذا لم يتم تحديد ترميز الإخراج أو إذا كان ترميز الإخراج غير UTF-8. نظرًا لأن سلوك هذه الدالة يعتمد على ورقة الأنماط المحددة، فقد تم إهمالها لصالح output_as_bytes(result) و output_as_chars(result).
output_fh(result, fh)
يقوم بإخراج النتيجة إلى مقبض الملف المعطى في $fh.
output_file(result, filename)
يقوم بإخراج النتيجة إلى الملف المسمى في $filename.
output_encoding()
يعيد ترميز الإخراج للنتائج. القيمة الافتراضية هي "UTF-8".
output_method()
يعيد قيمة السمة "method" من "xsl:output" (عادةً "xml"، "html"، أو "text"). إذا لم يتم تحديد هذه السمة، فإن القيمة الافتراضية هي مبدئيًا "xml". إذا تم استخدام طريقة التحويل لإنتاج مستند HTML، وفقًا لمواصفات XSLT http://www.w3.org/TR/xslt#output، ستتغير القيمة الافتراضية إلى "html". لتجاوز هذا السلوك بالكامل، قم بتوفير عنصر "xsl:output" في مستند مصدر ورقة الأنماط.
media_type()
يعيد قيمة السمة "media-type" من "xsl:output". إذا لم يتم تحديد هذه السمة، فإن نوع الوسائط الافتراضي هو مبدئيًا "text/xml". يتغير هذا الافتراضي إلى "text/html" تحت نفس الظروف التي تتغير فيها output_method.
input_callbacks($icb)
يمكّن استدعاءات الرد في $icb لهذه الورقة الأنماط فقط. يجب أن يكون $icb كائن "XML::LibXML::InputCallback". سيقوم هذا باستدعاء "init_callbacks" و "cleanup_callbacks" تلقائيًا أثناء التحويل.
transform_into_chars(doc, %params)
يجمع بين transform() و output_as_chars().

(تمت إضافته في الإصدار 2.0000).

المعاملات

تتوقع LibXSLT المعاملات بتنسيق XPath. أي، إذا كنت ترغب في تمرير سلسلة نصية إلى محرك XSLT، فيجب عليك تمريرها فعليًا كسلسلة محاطة بعلامات تنصيص:

$stylesheet->transform($doc, param => "'string'");

لاحظ علامات التنصيص داخل علامات التنصيص هناك!

من الواضح أن هذا ليس ممتعًا كثيرًا، لذا يمكنك تسهيل الأمر على نفسك:

$stylesheet->transform($doc, XML::LibXSLT::xpath_to_string(
      param => "string"
      ));

تقوم الدالة المساعدة بالشيء الصحيح فيما يتعلق بالسلاسل النصية في XPath، بما في ذلك عندما تكون لديك علامات تنصيص مضمنة بالفعل في سلسلتك النصية.

XML::LibXSLT::Security

يوفر واجهة لإطار عمل الأمان الخاص بـ libxslt عن طريق السماح بتعريف استدعاءات الرد التي يمكنها تقييد الوصول إلى موارد مختلفة (ملفات أو عناوين URL) أثناء التحويل.

يسمح إطار عمل الأمان الخاص بـ libxslt بتعريف استدعاءات الرد لإجراءات معينة قد تحاول ورقة الأنماط القيام بها أثناء التحويل. قد يكون من المرغوب فيه تقييد بعض هذه الإجراءات (على سبيل المثال، كتابة ملف جديد باستخدام exsl:document). الإجراءات التي يمكن تقييدها هي:

read_file
يتم استدعاؤه عندما تحاول ورقة الأنماط فتح ملف محلي (أي: عند استخدام الدالة document()).
write_file
يتم استدعاؤه عند محاولة كتابة ملف محلي (أي: عند استخدام العنصر exsl:document).
create_dir
يتم استدعاؤه عندما يلزم إنشاء دليل لكتابة ملف.

ملاحظة: افتراضيًا، لا يُسمح بـ create_dir. لتمكينه، يجب تسجيل استدعاء رد.

read_net
يتم استدعاؤه عندما تحاول ورقة الأنماط القراءة من الشبكة.
write_net
يتم استدعاؤه عندما تحاول ورقة الأنماط الكتابة إلى الشبكة.

استخدام XML::LibXSLT::Security

الواجهة لهذه الوحدة مشابهة لـ XML::LibXML::InputCallback. بعد إنشاء مثيل جديد، يمكنك تسجيل استدعاءات الرد لكل خيارات الأمان المذكورة أعلاه. ثم تقوم بتطبيق تفضيلات الأمان على كائن XML::LibXSLT أو XML::LibXSLT::Stylesheet باستخدام security_callbacks().

my $security = XML::LibXSLT::Security->new();
$security->register_callback( read_file  => $read_cb );
$security->register_callback( write_file => $write_cb );
$security->register_callback( create_dir => $create_cb );
$security->register_callback( read_net   => $read_net_cb );
$security->register_callback( write_net  => $write_net_cb );
$xslt->security_callbacks( $security );
 -OR-
$stylesheet->security_callbacks( $security );

يتم استدعاء دوال استدعاء الرد المسجلة عند طلب الوصول إلى مورد. إذا كان يجب السماح بالوصول، يجب أن تعيد الدالة 1، وإلا يجب أن تعيد 0. يجب أن تقبل دوال استدعاء الرد المعاملات التالية:

$tctxt
هذا هو سياق التحويل (XML::LibXSLT::TransformContext). يمكنك استخدام هذا للحصول على كائن XML::LibXSLT::Stylesheet الحالي عن طريق استدعاء stylesheet(). 
my $stylesheet = $tctxt->stylesheet();

يمكن بعد ذلك استخدام كائن ورقة الأنماط لمشاركة معلومات السياق بين استدعاءات مختلفة لاستدعاءات الرد الأمنية.

$value
هذا هو اسم المورد (ملف أو URI) الذي تم طلبه.

إذا لم يكن لدى خيار معين (باستثناء "create_dir") استدعاء رد مسجل، فإن ورقة الأنماط سيكون لديها وصول كامل لهذا الإجراء.

الواجهة

new()
ينشئ كائن XML::LibXSLT::Security جديد.
register_callback( $option, $callback )
يسجل دالة استدعاء رد للخيار الأمني المعطى (المدرج أعلاه).
unregister_callback( $option )
يزيل استدعاء الرد للخيار المعطى. هذا له تأثير السماح بكافة الوصول للخيار المعطى (باستثناء "create_dir").

BENCHMARK

مضمن في التوزيعة هو برنامج قياس أداء بسيط، والذي يحتوي على محركين - أحدهما لـ LibXSLT والآخر لـ Sablotron. يتطلب برنامج قياس الأداء ملفات حالات الاختبار من توزيعة XSLTMark التي يمكنك العثور عليها في http://www.datapower.com/XSLTMark/

ضع الدليل testcases في الدليل الذي تم إنشاؤه بواسطة هذا التوزيع، ثم قم بتشغيل:

perl benchmark.pl -h

للحصول على قائمة بالخيارات.

يتطلب برنامج قياس الأداء XML::XPath في الوقت الحالي، ولكن آمل في فصله عن المعادلة قريبًا. كما يتطلب Time::HiRes، والذي يمكن إقناعي بفصله واستبداله بـ Benchmark.pm، ولكني لم أفعل ذلك بعد.

أود بشدة الحصول على محركات لـ XML::XSLT و XML::Transformiix، إذا كنت ترغب في المساهمة بها. أيضًا، إذا نجحت في تشغيل هذا على Win32، فسأكون سعيدًا بالحصول على محرك لـ MSXSLT عبر OLE، لمعرفة ما يمكننا فعله ضد هؤلاء أولاد ردموند!

LIBRARY VERSIONS

XML::LibXSLT issues a warning if the runtime version of the library is less then the compile-time version.

XML::LibXSLT::LIBXSLT_VERSION()
Returns version number of libxslt library which was used to compile XML::LibXSLT as an integer. For example, for libxslt-1.1.18, it will return 10118.
XML::LibXSLT::LIBXSLT_DOTTED_VERSION()
Returns version number of libxslt library which was used to compile XML::LibXSLT as a string, e.g. "1.1.18".
XML::LibXSLT::LIBXSLT_RUNTIME_VERSION()
Returns version number of libxslt library to which XML::LibXSLT is linked at runtime (either dynamically or statically). For example, for example, for libxslt.so.1.1.18, it will return 10118.
XML::LibXSLT::HAVE_EXLT()
Returns 1 if the module was compiled with libexslt, 0 otherwise.
