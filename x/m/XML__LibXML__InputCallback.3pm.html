NAME

XML::LibXML::InputCallback - Callback interface for custom input methods

SYNOPSIS

use XML::LibXML::InputCallback;

my $input_callbacks = XML::LibXML::InputCallback->new();
$input_callbacks->register_callbacks([ \&match_uri, \&open_uri,
                                       \&read_uri, \&close_uri ] );
$parser->input_callbacks( $input_callbacks );

DESCRIPTION

The XML::LibXML::InputCallback module allows you to define custom input methods for the XML::LibXML parser. This is particularly useful for parsing XML from non-file sources, such as network sockets, databases, or in-memory strings. You can use it to implement custom URI schemes (e.g. myscheme://...).

The callback system operates with a stack. When you register a set of callbacks, they are pushed onto the stack. If you later register another set of callbacks, they will be pushed on top of the existing ones. The parser will iterate through the stack, calling the match_uri callback for each registered set, until one returns true. The corresponding open_uri, read_uri, and close_uri callbacks will then be used for that URI. If you clear the stack or if all callback groups are deleted from the stack, the parser will fall back to the default file-based input method.

INTERFACE DESCRIPTION

new()
Creates a new, empty XML::LibXML::InputCallback object.
register_callbacks( $callbacks )
Registers a callback group. $callbacks is an array reference containing four subroutine references in the following order:
match_uri
Takes the URI string as an argument and should return true if this callback group can handle the given URI, false otherwise.
open_uri
Takes the URI string as an argument and should return an object that implements a filehandle-like interface (e.g., it must have read and close methods). This object will be used to read the XML document.
read_uri
Takes the handle object (returned by open_uri) and an optional length as arguments. It should read data from the handle and return it as a string. An empty string indicates the end of the input stream.
close_uri
Takes the handle object as an argument and should perform any necessary cleanup, such as closing the handle.

All four callbacks must be provided. If a URI is matched by multiple callback groups, the parser will use the callbacks from the group that was registered most recently (i.e., the one highest on the stack).

input_callbacks( $parser )
Associates this callback object with a given XML::LibXML parser instance. This method should be called *before* calling any parsing methods (e.g., parse_file, parse_string) on the parser.
clear()
Clears all registered callback groups. If the stack is cleared, the parser will fall back to its default input method.
deregister_callbacks()
Removes the most recently registered callback group from the stack. If multiple callback groups were registered in different callback groups, ALL of them will be deleted from the stack.
init_callbacks( $parser )
Initializes the callback system for the provided parser before starting a parsing process.
cleanup_callbacks()
Resets global variables and the libxml2 callback stack.
lib_init_callbacks()
Used internally for callback registration at C-level.
lib_cleanup_callbacks()
Used internally for callback resetting at the C-level.

EXAMPLE CALLBACKS

The following example is a purely fictitious example that uses a MyScheme::Handler object that responds to methods similar to an IO::Handle.

# Define the four callback functions
sub match_uri {
    my $uri = shift;
    return $uri =~ /^myscheme:/; # trigger our callback group at a 'myscheme' URIs
}
sub open_uri {
    my $uri = shift;
    my $handler = MyScheme::Handler->new($uri);
    return $handler;
}
# The returned $buffer will be parsed by the libxml2 parser
sub read_uri {
    my $handler = shift;
    my $length = shift;
    my $buffer;
    read($handler, $buffer, $length);
    return $buffer; # $buffer will be an empty string '' if read() is done
}
# Close the handle associated with the resource.
sub close_uri {
    my $handler = shift;
    close($handler);
}
# Register them with a instance of XML::LibXML::InputCallback
my $input_callbacks = XML::LibXML::InputCallback->new();
$input_callbacks->register_callbacks([ \&match_uri, \&open_uri,
                                       \&read_uri, \&close_uri ] );
# Register the callback group at a parser instance
$parser->input_callbacks( $input_callbacks );
# $some_xml_file will be parsed using our callbacks
$parser->parse_file( $some_xml_file );
