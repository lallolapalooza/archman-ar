NAME

xinput – manipulate input device settings

SYNOPSIS

xinput [-A | --append] [-a | --all] [-c | --create] [-d | --delete] [-f | --force] [-h | --help] [-i | --idiot] [-l | --list] [-q | --query] [-r | --remove] [-s | --set] [-v | --verbose] [-w | --watch] [--setup] [device]

xinput [--set-prop device prop value...]

xinput [--set-key device keycode values...]

xinput [--set-axis-calibration device values...]

xinput [--set-int-prop device prop value...]

xinput [--set-float-prop device prop value...]

xinput [--set-button-map device map...]

xinput [--enable device]

xinput [--disable device]

xinput [--list-props device]

xinput [--watch-props device]

xinput [--short-list-props device]

xinput [--long-list-props device]

xinput [--list-buttons device]

xcast [-f | --force] [-h | --help] [-l | --list] [-s | --set] [device]

xset [-r | --remove] [-s | --set] [- | --] [device] [args...]

xprop [-set] [-id window] [-f fmt] [-len number] [-|atom...]

DESCRIPTION

The xinput utility is a tool to configure and test X Input devices.

It can be used to:

  • List available input devices.
  • View and change input device properties.
  • Enable and disable input devices.

The X Input Extension (XInput) is a protocol extension to the X Window System protocol that allows input devices like graphics tablets, joysticks, mice, and keyboards to be plugged into an X server and used by clients.

Configuration options are typically device-specific and depend on the properties exposed by the device driver.

COMMANDS

--list, -l
Lists all available input devices. Each device is listed with its name and its XInput device ID.
--list-props, --short-list-props, --long-list-props
Lists the properties of a specified device. --short-list-props shows only the property names, while --long-list-props shows the property names and their current values.
--set-prop, --set-int-prop, --set-float-prop
Sets the value of a device property. The type of property is specified by the subcommand (e.g., --set-int-prop for integer properties). Use --list-props to find the correct property name and type.
--set-button-map
Sets the button mapping for a mouse or other pointing device. The map is a space-separated list of integers representing the button numbers.
--enable, --disable
Enables or disables a device. Disabled devices will not generate input events.
--create, --delete, --destroy
Creates or destroys XInput devices. These commands are rarely needed and typically used by device drivers.
--watch-props
Prints property changes for the specified device in real time.
--list-buttons
Lists the current button mapping for a device.

CHANGING PROPERTIES

To change a property, you first need to know the device ID or name, and the property name. Use xinput --list to get the device ID/name and xinput --list-props to see the available properties for that device.

For example, to change the sensitivity of a mouse named "Logitech USB Optical Mouse":

$ xinput --list
...
⎜   ↳ Logitech USB Optical Mouse              id=12 [slave  pointer  (2)]
...
$ xinput --list-props 12
...
    Device Accel Profile (290):    0
    Device Accel Velocity (291):   0
...
$ xinput --set-int-prop 12 "Device Accel Velocity" 80 80 80

Note that the exact property names and their accepted values vary greatly between devices and drivers.

XWAYLAND

Xwayland is a compatibility layer for running X clients on a Wayland compositor. When Xwayland is running, it presents X Input Extension devices (e.g., "xwayland-pointer", "xwayland-keyboard") to X clients.

These Xwayland devices are abstractions that map to the underlying Wayland input devices. They do not directly represent physical hardware.

Modifying properties of these Xwayland devices using xinput will only affect X clients connected through Xwayland. These changes will not propagate to Wayland-native applications, which interact directly with the Wayland compositor's input handling.

Using xinput on Xwayland devices is generally discouraged. It often indicates a misconfiguration or a misunderstanding of how Xwayland interacts with Wayland. For Wayland-native input device configuration, use the tools and methods provided by your specific Wayland compositor (e.g., libinput configuration). If xinput issues a warning about using it with an Xwayland device, it is a strong indicator that you should be using native Wayland configuration methods instead.
