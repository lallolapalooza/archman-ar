XPROP(1) دليل الأوامر العامة XPROP(1)

الاسم

xprop - عارض خصائص X

الملخص

xprop [-help] [-grammar] [-id id] [-root] [-name name] [-frame] [-font font] [-display display] [-len n] [-notype] [-fs file] [-remove property-name] [-set property-name value] [-spy] [-version] [-f atom format [dformat]]* [format [dformat] atom]*

ملخص

أداة xprop هي لعرض خصائص النوافذ والخطوط في خادم X. يتم اختيار نافذة أو خط واحد باستخدام وسيطات سطر الأوامر أو ربما في حالة النافذة، عن طريق النقر على النافذة المطلوبة. ثم يتم تقديم قائمة بالخصائص، ربما مع معلومات التنسيق.

خيارات

-help
طباعة ملخص لخيارات سطر الأوامر.
-grammar
طباعة قواعد مفصلة لجميع وسيطات سطر الأوامر.
-id id
تسمح هذه الوسيطة للمستخدم بتحديد النافذة id في سطر الأوامر بدلاً من استخدام المؤشر لتحديد النافذة المستهدفة. هذا مفيد جدًا في تصحيح أخطاء تطبيقات X حيث لا يتم تعيين النافذة المستهدفة على الشاشة أو حيث قد يكون استخدام المؤشر مستحيلاً أو يؤثر على التطبيق.
-name name
تسمح هذه الوسيطة للمستخدم بتحديد أن النافذة المسماة name هي النافذة المستهدفة في سطر الأوامر بدلاً من استخدام المؤشر لتحديد النافذة المستهدفة.
-font font
تسمح هذه الوسيطة للمستخدم بتحديد أن خصائص الخط font يجب عرضها.
-root
تحدد هذه الوسيطة أن نافذة X الجذرية هي النافذة المستهدفة. هذا مفيد في المواقف التي تكون فيها النافذة الجذرية محجوبة بالكامل.
-display display
تسمح لك هذه الوسيطة بتحديد الخادم للاتصال به؛ انظر X(7).
-len n
تحدد أن الحد الأقصى لعدد البايتات n لأي خاصية يجب قراءتها أو عرضها.
-notype
تحدد أن نوع كل خاصية لا يجب عرضه.
-fs file
تحدد أن الملف file يجب استخدامه كمصدر لتنسيقات إضافية للخصائص.
-frame
تحدد أنه عند اختيار نافذة يدويًا (أي إذا لم يتم إعطاء -name أو -root أو -id)، انظر إلى إطار مدير النافذة (إن وجد) بدلاً من البحث عن نافذة العميل.
-remove property-name
تحدد اسم الخاصية المراد إزالتها من النافذة المشار إليها.
-set property-name value
تحدد اسم الخاصية وقيمة الخاصية، ليتم تعيينها على النافذة المشار إليها.
-spy
فحص خصائص النافذة إلى الأبد، والبحث عن أحداث تغيير الخاصية.
-version
طباعة معلومات إصدار البرنامج والخروج.
-f name format [dformat]
تحدد أن format لـ name يجب أن يكون format وأن dformat لـ name يجب أن يكون dformat. إذا كان dformat مفقودًا، يُفترض " = $0+\n".

الوصف

لكل من هذه الخصائص، تتم طباعة قيمتها على النافذة أو الخط المحدد باستخدام معلومات التنسيق المقدمة إن وجدت. إذا لم يتم توفير معلومات التنسيق، يتم استخدام الافتراضات الداخلية. إذا لم يتم تعريف خاصية على النافذة أو الخط المحدد، تتم طباعة "غير معرف" كقيمة لتلك الخاصية. إذا لم يتم تقديم قائمة خصائص، يتم طباعة جميع الخصائص التي تمتلكها النافذة أو الخط المحدد.

يمكن تحديد نافذة بإحدى الطرق الأربع. أولاً، إذا كانت النافذة المطلوبة هي النافذة الجذرية، يمكن استخدام الوسيطة -root. إذا لم تكن النافذة المطلوبة هي النافذة الجذرية، فيمكن تحديدها بطريقتين في سطر الأوامر، إما عن طريق رقم المعرف مثل الذي يمكن الحصول عليه من xwininfo، أو بالاسم إذا كانت النافذة تمتلك اسمًا. الوسيطة -id تحدد نافذة برقم المعرف في النظام العشري أو الست عشري (يجب أن يبدأ بـ 0x) بينما الوسيطة -name تحدد نافذة بالاسم.

الطريقة الأخيرة لتحديد نافذة لا تتضمن سطر الأوامر على الإطلاق. إذا لم يتم تحديد أي من -font، -id، -name، و -root، يتم عرض مؤشر متقاطع ويُسمح للمستخدم باختيار أي نافذة مرئية عن طريق الضغط على أي زر مؤشر في النافذة المطلوبة. إذا كان المطلوب هو عرض خصائص خط بدلاً من نافذة، فيجب استخدام الوسيطة -font.

بخلاف الوسيطات الأربع المذكورة أعلاه والوسيطة -help للحصول على المساعدة، والوسيطة -grammar لسرد القواعد الكاملة لسطر الأوامر، تُستخدم جميع وسيطات سطر الأوامر الأخرى في تحديد كل من تنسيق الخصائص المراد عرضها وكيفية عرضها. تحدد الوسيطة -len n أن الحد الأقصى لـ n بايت من أي خاصية معينة سيتم قراءتها وعرضها. هذا مفيد على سبيل المثال عند عرض مخزن القطع على النافذة الجذرية الذي يمكن أن يمتد لعدة صفحات إذا تم عرضه بالكامل.

عادةً ما يتم عرض اسم كل خاصية عن طريق طباعة اسم الخاصية أولاً ثم نوعها (إذا كان لها نوع) بين قوسين متبوعًا بقيمتها. تحدد الوسيطة -notype أنه لا يجب عرض أنواع الخصائص. تُستخدم الوسيطة -fs لتحديد ملف يحتوي على قائمة بالتنسيقات للخصائص بينما تُستخدم الوسيطة -f لتحديد تنسيق لخاصية واحدة.

تتكون معلومات التنسيق لخاصية ما فعليًا من جزأين، format و dformat. يحدد format التنسيق الفعلي للخاصية (أي، هل تتكون من كلمات، بايتات، أو أعداد كبيرة؟، إلخ) بينما يحدد dformat كيفية عرض الخاصية.

تصف الفقرات التالية كيفية بناء formats و dformats. ومع ذلك، بالنسبة لغالبية المستخدمين والاستخدامات، لا ينبغي أن يكون هذا ضروريًا لأن الافتراضات المضمنة تحتوي على formats و dformats اللازمة لعرض جميع الخصائص القياسية. يجب أن يكون من الضروري فقط تحديد formats و dformats إذا كان يتم التعامل مع خاصية جديدة أو إذا كان المستخدم لا يحب تنسيق العرض القياسي. يتم تشجيع المستخدمين الجدد بشكل خاص على تخطي هذا الجزء.

يتكون format من 0، 8، 16، أو 32 متبوعًا بتسلسل من حرف تنسيق واحد أو أكثر. يحدد الصفر، 8، 16، أو 32 عدد البتات لكل حقل في الخاصية. الصفر هو حالة خاصة تعني استخدام معلومات حجم الحقل المرتبطة بالخاصية نفسها. (هذا مطلوب فقط للحالات الخاصة مثل النوع INTEGER وهو في الواقع ثلاثة أنواع مختلفة اعتمادًا على حجم حقول الخاصية.)

القيمة 8 تعني أن الخاصية هي سلسلة من البايتات بينما القيمة 16 تعني أن الخاصية هي سلسلة من الكلمات. الفرق بين هذين يكمن في حقيقة أن سلسلة الكلمات سيتم تبديل ترتيب البايتات فيها بينما سلسلة البايتات لن يتم ذلك عند قراءتها بواسطة آلة بترتيب بايت معاكس للآلة التي كتبت الخاصية في الأصل. لمزيد من المعلومات حول كيفية تنسيق وتخزين الخصائص، استشر دليل Xlib.

بمجرد تحديد حجم الحقول، من الضروري تحديد نوع كل حقل (أي، هل هو رقم صحيح، سلسلة، ذرة، أو ما هو؟) يتم ذلك باستخدام حرف تنسيق واحد لكل حقل. إذا كان هناك حقول أكثر في الخاصية من أحرف التنسيق المقدمة، فسيتم تكرار الحرف الأخير حسب الضرورة للحقول الإضافية. أحرف التنسيق ومعناها هي كما يلي:

a
يحمل الحقل رقم ذرة. يجب أن يكون للحقل من هذا النوع حجم 32.
b
الحقل هو قيمة منطقية (boolean). تعني 0 خطأ بينما أي شيء آخر يعني صواب.
xprop(1) - X Window System

NAME

xprop

window information utility

SYNOPSIS

xprop [-options] [ atom ... ]

SUMMARY

xprop is a utility for the X Window System that allows you to select windows and display information about them. It can display window id, window name, window type, window geometry, and other properties associated with a window. It can also be used to modify window properties.

OPTIONS

The following options are available:

-display display
Specifies the X server to contact.
-id id
Specifies the resource id of the window to query.
-name name
Specifies the name of the window to query.
-root
Query the root window.
-len number
Limits the number of bytes displayed for each property.
-f format-name format dformat
Specifies a format for a property.
-fs filename
Specifies a file containing formats.
-font fontname
Specifies the font to use for displaying text.
-format atom format
Specifies the format of a property.
-set atom value
Sets a property to a given value.
-remove atom
Removes a property.
-help
Displays a help message and exits.

DESCRIPTION

The xprop utility is used to interactively display window properties. When invoked without any arguments, it selects the top-level window. When invoked with a window id or name, it queries that specific window.

xprop can display window properties in a human-readable format. It can also be used to set or modify window properties. This is useful for debugging applications or for customizing the behavior of the X server.

The following format characters are supported:

c
The field is an unsigned number, a cardinal.
i
The field is a signed integer.
m
The field is a set of bit flags, 1 meaning on.
o
The field is an array of icons, packed as a sequence of 32 bit numbers consisting of the width, height and ARGB pixel values, as defined for the _NET_WM_ICON property in the Extended Window Manager Hints specification. A field of this type must be of size 32.
s
This field and the next ones until either a 0 or the end of the property represent a sequence of bytes. This format character is only usable with a field size of 8 and is most often used to represent a string.
t
This field and the next ones until either a 0 or the end of the property represent an internationalized text string. This format character is only usable with a field size of 8. The string is assumed to be in an ICCCM compliant encoding and is converted to the current locale encoding before being output.
u
This field and the next ones until either a 0 or the end of the property represent an UTF-8 encoded unicode string. This format character is only usable with a field size of 8. If the string is found to be an invalid character, the type of encoding violation is printed instead, followed by the string formatted using 's'. When in an environment not capable of displaying UTF-8 encoded string, behaviour is identical to 's'.
x
The field is a hex number (like 'c' but displayed in hex - most useful for displaying window ids and the like)

An example format is 32ica which is the format for a property of three fields of 32 bits each, the first holding a signed integer, the second an unsigned integer, and the third an atom.

The format of a dformat unlike that of a format is not so rigid. The only limitations on a dformat is that one may not start with a letter or a dash. This is so that it can be distinguished from a property name or an argument. A dformat is a text string containing special characters instructing that various fields be printed at various points in a manner similar to the formatting string used by printf. For example, the dformat " is ( $0, $1 \)\n" would render the POINT 3, -4 which has a format of 32ii as " is ( 3, -4 )\n".

Any character other than a $, ?, \, or a ( in a dformat prints as itself. To print out one of $, ?, \, or ( precede it by a \. For example, to print out a $, use \$. Several special backslash sequences are provided as shortcuts. \n will cause a newline to be displayed while \t will cause a tab to be displayed. \o where o is an octal number will display character number o.

A $ followed by a number n causes field number n to be displayed. The format of the displayed field depends on the formatting character used to describe it in the corresponding format. I.e., if a cardinal is described by 'c' it will print in decimal while if it is described by a 'x' it is displayed in hex.

If the field is not present in the property (this is possible with some properties), <field not available> is displayed instead. $n+ will display field number n then a comma then field number n+1 then another comma then ... until the last field defined. If field n is not defined, nothing is displayed. This is useful for a property that is a list of values.

A ? is used to start a conditional expression, a kind of if-then statement. ?exp(text) will display text if and only if exp evaluates to non-zero. This is useful for two things. First, it allows fields to be displayed if and only if a flag is set. And second, it allows a value such as a state number to be displayed as a name rather than as just a number. The syntax of exp is as follows:

exp
::= term | term=exp | !exp
term
::= n | $n | mn

The ! operator is a logical ``not'', changing 0 to 1 and any non-zero value to 0. = is an equality operator. Note that internally all expressions are evaluated as 32 bit numbers so -1 is not equal to 65535. = returns 1 if the two values are equal and 0 if not. n represents the constant value n while $n represents the value of field number n. mn is 1 if flag number n in the first field having format character 'm' in the corresponding format is 1, 0 otherwise.

Examples: ?m3(count: $3\n) displays field 3 with a label of count if and only if flag number 3 (count starts at 0!) is on. ?$2=0(True)?!$2=0(False) displays the inverted value of field 2 as a boolean.

In order to display a property, xprop needs both a format and a dformat. Before xprop uses its default values of a format of 32x and a dformat of " = { $0+ }\n", it searches several places in an attempt to find more specific formats. First, a search is made using the name of the property. If this fails, a search is made using the type of the property. This allows type STRING to be defined with one set of formats while allowing property WM_NAME which is of type STRING to be defined with a different format. In this way, the display formats for a given type can be overridden for specific properties.

The locations searched are in order: the format if any specified with the property name (as in 8x WM_NAME), the formats defined by -f options in last to first order, the contents of the file specified by the -fs option if any, the contents of the file specified by the environmental variable XPROPFORMATS if any, and finally xprop's built in file of formats.

The format of the files referred to by the -fs argument and the XPROPFORMATS variable is one or more lines of the following form:

name format [dformat]

Where name is either the name of a property or the name of a type, format is the format to be used with name and dformat is the dformat to be used with name. If dformat is not present, " = $0+\n" is assumed.

EXAMPLES

To display the name of the root window: xprop -root WM_NAME

To display the window manager hints for the clock: xprop -name xclock WM_HINTS

To display the start of the cut buffer: xprop -root -len 100 CUT_BUFFER0

To display the point size of the fixed font: xprop -font fixed POINT_SIZE

To display all the properties of window # 0x200007: xprop -id 0x200007

To set a simple string property: xprop -root -format MY_ATOM_NAME 8s -set MY_ATOM_NAME "my_value"

ENVIRONMENT

DISPLAY
To get default display.
XPROPFORMATS
Specifies the name of a file from which additional formats are to be obtained.

SEE ALSO

X(7), xdpyinfo(1), xwininfo(1), xdriinfo(1), glxinfo(1), xvinfo(1)
