XtCloseDisplay(3)

الحزمة: libxt

التراخيص: MIT, HPND-sell-variant, SMLNJ, MIT-open-group, X11

XtDisplayInitialize(3) وظائف XT XtDisplayInitialize(3)

الاسم

XtDisplayInitialize, XtOpenDisplay, XtDatabase, XtScreenDatabase, XtCloseDisplay - تهيئة، فتح، أو إغلاق شاشة عرض

الصيغة

#include <X11/Intrinsic.h>

void XtDisplayInitialize(XtAppContext app_context, Display *display, const char *application_name, const char *application_class, XrmOptionDescRec *options, Cardinal num_options, int *argc, char **argv);

Display *XtOpenDisplay(XtAppContext app_context, const char *display_string, const char *application_name, const char *application_class, XrmOptionDescRec *options, Cardinal num_options, int *argc, char **argv);

void XtCloseDisplay(Display *display);

XrmDatabase XtDatabase(Display *display);

XrmDatabase XtScreenDatabase(Screen* screen);

الوسائط

argc
يحدد مؤشرًا إلى عدد معلمات سطر الأوامر.
argv
يحدد معلمات سطر الأوامر.
app_context
يحدد سياق التطبيق.
application_class
يحدد اسم فئة هذا التطبيق، والذي يكون عادةً الاسم العام لجميع مثيلات هذا التطبيق.
application_name
يحدد اسم مثيل التطبيق.
display
يحدد الشاشة. لاحظ أن الشاشة يمكن أن تكون في سياق تطبيق واحد فقط.
num_options
يحدد عدد الإدخالات في قائمة الخيارات.
options
يحدد كيفية تحليل سطر الأوامر لأي موارد خاصة بالتطبيق. يتم تمرير الوسيط options كمعلمة لـ XrmParseCommand. لمزيد من المعلومات، انظر Xlib - واجهة لغة C لـ X.
screen
يحدد الشاشة التي سيتم إرجاع قاعدة بيانات مواردها.

الوصف

تقوم الدالة XtDisplayInitialize بإنشاء قاعدة بيانات الموارد، وتستدعي الدالة XrmParseCommand الخاصة بـ Xlib لتحليل سطر الأوامر، وتقوم بتهيئة أخرى خاصة بالشاشة. بعد استدعاء XrmParseCommand، يحتوي argc و argv على المعلمات التي لم تكن في جدول الخيارات القياسي أو في الجدول المحدد بواسطة الوسيط options فقط. إذا كان argc المعدل لا يساوي صفرًا، فإن معظم التطبيقات تقوم ببساطة بطباعة argv المعدل مع رسالة تسرد الخيارات المسموح بها. في الأنظمة المستندة إلى UNIX، عادةً ما يكون اسم التطبيق هو المكون الأخير لـ argv[0]. إذا كان مورد المزامنة True للتطبيق المحدد، فإن XtDisplayInitialize تستدعي الدالة XSynchronize الخاصة بـ Xlib لوضع Xlib في وضع المزامنة لاتصال الشاشة هذا. إذا كان مورد reverseVideo True، فإن Intrinsics تقوم بتبديل XtDefaultForeground و XtDefaultBackground للأدوات التي تم إنشاؤها على هذه الشاشة. (انظر القسم 9.6.1).

تقوم الدالة XtOpenDisplay باستدعاء XOpenDisplay اسم الشاشة المحدد. إذا كان display_string هو NULL، فإن XtOpenDisplay تستخدم القيمة الحالية لـ -display option المحدد في argv، وإذا لم يتم تحديد شاشة في argv، فإنها تستخدم شاشة المستخدم الافتراضية (في الأنظمة المستندة إلى UNIX، هذه هي قيمة متغير البيئة DISPLAY).

إذا نجح هذا، فإنها تستدعي XtDisplayInitialize وتمرر لها الشاشة المفتوحة وقيمة -name option المحدد في argv كاسم للتطبيق. إذا لم يتم تحديد خيار الاسم، فإنها تستخدم اسم التطبيق الذي تم تمريره إلى XtOpenDisplay. إذا كان اسم التطبيق NULL، فإنها تستخدم المكون الأخير من argv[0]. تُرجع XtOpenDisplay الشاشة المفتوحة حديثًا أو NULL إذا فشلت.

تم توفير XtOpenDisplay كراحة لمبرمج التطبيق.

تقوم الدالة XtCloseDisplay بإغلاق الشاشة المحددة فورما يكون ذلك آمنًا. إذا تم استدعاؤها من داخل توزيع أحداث (على سبيل المثال، إجراء رد اتصال)، فإن XtCloseDisplay لا تغلق الشاشة حتى تكتمل عملية التوزيع. لاحظ أن التطبيقات تحتاج فقط إلى استدعاء XtCloseDisplay إذا كانت ستستمر في التنفيذ بعد إغلاق الشاشة؛ بخلاف ذلك، يجب عليها استدعاء XtDestroyApplicationContext أو الخروج ببساطة.

تُرجع الدالة XtDatabase قاعدة بيانات الموارد المدمجة بالكامل التي تم بناؤها بواسطة XtDisplayInitialize المرتبطة بالشاشة التي تم تمريرها. إذا لم يتم تهيئة هذه الشاشة بواسطة XtDisplayInitialize، فالنتائج غير محددة.

تُرجع الدالة XtScreenDatabase قاعدة بيانات الموارد المدمجة بالكامل المرتبطة بالشاشة المحددة. إذا كانت screen لا تنتمي إلى Display تم تهيئتها بواسطة XtDisplayInitialize، فالنتائج غير محددة.
