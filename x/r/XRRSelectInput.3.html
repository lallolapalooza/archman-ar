أنواع البيانات

الدورانات/الانعكاسات

يمكن أن يكون أيًا مما يلي:

#define RR_Rotate_0             1
#define RR_Rotate_90            2
#define RR_Rotate_180           4
#define RR_Rotate_270           8
/∗ جديد في بروتوكول 1.0، للسماح بانعكاس الشاشة */
/∗ يتم تطبيق الانعكاس بعد الدوران */
#define RR_Reflect_X            16
#define RR_Reflect_Y            32
typedef struct {
    int	width, height;
    int	mwidth, mheight;
} XRRScreenSize;
typedef struct {
    int type;				/∗ قاعدة الأحداث */
    unsigned long serial;	/∗ # آخر طلب تم معالجته بواسطة الخادم */
    Bool send_event;		/∗ صحيح إذا جاء هذا من طلب SendEvent */
    Display *display;		/∗ العرض الذي تمت قراءة الحدث منه */
    Window window;			/∗ النافذة التي اختارت لهذا الحدث */
    Window root;			/∗ النافذة الجذر للتغيير في الشاشة */
    Time timestamp;			/∗ وقت حدوث تغيير الشاشة */
    Time config_timestamp;	/∗ وقت آخر تغيير للتكوين */
    SizeID size_index;
    SubpixelOrder subpixel_order;
    Rotation rotation;
    int width;
    int height;
    int mwidth;
    int mheight;
} XRRScreenChangeNotifyEvent;
يحتوي هيكل XRRScreenSize على حجم جذر محتمل بالبكسل وبالمليمتر.

XRRScreenChangeNotifyEvent يتم إرساله إلى عميل طلب الإخطار كلما تغير تكوين الشاشة. يمكن للعميل إجراء هذا الطلب عن طريق استدعاء XRRSelectInput، وتمرير العرض، والنافذة الجذر، والقناع RRScreenChangeNotifyMask.

XRRScreenConfiguration هو نوع بيانات غير شفاف يحتوي على معلومات تكوين الشاشة.

الأوقات

يتم تضمين الطوابع الزمنية ويجب استخدامها لضمان أن العميل يلعب بورقة كاملة: قد تقوم الشاشة بتغيير خصائصها بشكل فوري وهذا يضمن أن معرفتها بالتكوين محدثة. هذا للمساعدة في القضايا عندما قد تصبح الشاشات قابلة للتوصيل والتشغيل في المستقبل.

الوصف

Xrandr هي مكتبة بسيطة مصممة للتفاعل مع امتداد X لتغيير الحجم والدوران. هذا يسمح للعملاء بتغيير حجم ودوران النافذة الجذر للشاشة، بالإضافة إلى القدرة على عكس الشاشة حول أي محور (إذا كان مدعومًا من قبل التنفيذ). قد يتم تنفيذ الدوران والانعكاس بواسطة البرنامج وقد يؤدي إلى أداء أبطأ إذا تم تنفيذ الدوران والانعكاس بهذه الطريقة (كما هو الحال في جميع التنفيذات اعتبارًا من أكتوبر 2002).

تقوم مكتبة Xrandr ببعض التخزين المؤقت البسيط لتجنب الرحلات ذهابًا وإيابًا لتوفير معلومات مستخدمة بشكل متكرر للعملاء. انظر "امتداد X لتغيير الحجم والدوران" لوصف مفصل؛ لاحظ أيضًا أن تبديل العمق، كما هو موضح في المستند، لم يتم تنفيذه، وقد (أو قد لا) يتم تنفيذه أبدًا، حيث أن ذاكرة العرض تنمو بسرعة، وبدأت أطر العمل بالفعل في دعم الترحيل، مما يخفف من الحاجة إلى تبديل العمق. إذا تم تنفيذه في المستقبل، نتوقع القيام بذلك عبر امتداد متوافق للأعلى للمكتبة/البروتوكول الحالي؛ يجب أن تستمر الوظائف الموضحة هنا في العمل.

الدوران والانعكاس وكيفية تفاعلهما يمكن أن يكون مربكًا. في Randr، يتم تدوير نظام الإحداثيات في اتجاه عكس عقارب الساعة بالنسبة للتوجيه العادي. الانعكاس يكون على طول نظام إحداثيات نظام النوافذ، وليس محور X و Y للشاشة المادية، لذلك لا يتفاعل الدوران والانعكاس. الطريقة الأخرى للنظر في الانعكاس هي معاملته كما هو محدد في الاتجاه "العادي"، قبل الدوران.

يتم إرسال الحدث XRRScreenChangeNotify إلى العملاء الذين يطلبون إبلاغهم كلما تغير تكوين النافذة الجذر. قد تشمل تغييرات التكوين الدقة، الحجم المادي، ترتيب البكسلات الفرعية (انظر XRender(3))، والدوران. لاحظ أن التغييرات على أي من هذه أو كلها قد تحدث بسبب أحداث خارجية (تحكم المستخدم في خادم X، توصيل/فصل شاشة/لوحة عرض مسطحة أخرى) ولا تنتج فقط عن طلب بروتوكول/مكتبة إلى خادم X.

بالإضافة إلى ذلك، للقضاء على شرط سباق محتمل، قد يتم إنشاء هذا الحدث فور اختيار الإخطار إذا تغيرت الشاشة منذ أن اتصل عميل Xrandr بخادم X، لتمكين تغيير دقة الشاشة بشكل موثوق عندما قد يقوم المستخدم بتسجيل الدخول وتغيير التكوين بينما يبدأ عميل واحد أو أكثر في التشغيل.

إخطار Xlib

يجب على العملاء الاستدعاء مرة أخرى إلى Xlib باستخدام XRRUpdateConfiguration عند إنشاء أحداث الإخطار بتغيير تكوين الشاشة (أو حدوث تغييرات في تكوين النافذة الجذر، لتحديث عرض Xlib للدقة، الحجم، الدوران، الانعكاس، أو ترتيب البكسلات الفرعية. بشكل عام، ستقوم أطر العمل بتنفيذ هذه العملية نيابة عن التطبيقات؛ لم نكن نرغب في تغيير بيانات هيكل العرض خلف ظهور أطر العمل، حيث قد تحدث شروط سباق مختلفة في العملاء متعددي الخيوط. يجب أن توفر أطر العمل للعملاء بعض الآلية للإخطار بتغيير الشاشة، بالطبع.

DESCRIPTION

The RandR extension provides the ability to dynamically change screen resolution, rotation, and reflection. This library provides a C interface to the RandR extension.

There are two classes of interfaces: those which can be safely called even if RandR is not implemented on a screen (to make common idioms not dependent on the server having support), and those which will return errors if the extension is not present.

XRRRotations returns both the possible set of rotations/reflections supported (as a bitmask) as the value of the function, along with the current rotation/reflection of the screen.

XRRSizes returns the size and a pointer to the current sizes supported by the specified screen. The first size specified is the default size of the server. If RandR is not supported, it returns 0 for the number of sizes.

XRRRates returns a pointer to the rates supported by the specified size. If RandR is not supported, it returns 0 for the number of rates.

XRRTimes returns the time last reported by the server along with the timestamp the last configuration changed. If the configuration has changed since the client last updated its view of the server time, requests to change the configuration will fail until the client has an up to date timestamp.

XRRRootToScreen returns the screen number given a root window (for example, from an XRRScreenChangeNotifyEvent).

The rest of the functions will fail if applied to screens not implementing the RandR extension. XRRSetScreenConfig sets the screen size and rotation and reflection to the desired values on the screen specified by draw, or returns a BadValue error. size_index specifies which size configuration is to be used, rotation specifies which rotation or reflection is to be used (or a BadValue error is returned). The timestamp is used by the server to make sure the client has up to date configuration information. Status is returned to indicate success or failure; a client must refresh its configuration information if it fails and try the call again (by calling XRRGetScreenInfo).

XRRSetScreenConfigAndRate is like XRRSetScreenConfig but also sets the refresh rate. If specified rate is not supported a BadValue error is returned.

XRRConfigRotations, XRRConfigSizes, XRRConfigCurrentConfiguration, XRRConfigTimes, XRRConfigRates, and XRRConfigCurrentRate are used to get specific configuration information out of a screen configuration.

XRRGetScreenInfo returns a screen configuration for later use; the information is private to the library. Call XRRFreeScreenConfigInfo to free this information when you are finished with it. It forces a round trip to the server.

Other functions include: XRRQueryExtension which returns the event and error base codes, XRRQueryVersion , which returns the current version of the extension (this information is cached by the library).
