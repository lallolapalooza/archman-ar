X11__Protocol__Ext__MIT_SHM(3pm)

الحزمة: perl-x11-protocol-other

التراخيص: GPL

X11::Protocol::Ext::MIT_SHM(3) توثيق Perl من مساهمات المستخدم X11::Protocol::Ext::MIT_SHM(3)

الاسم

X11::Protocol::Ext::MIT_SHM - صور في أجزاء الذاكرة المشتركة بنمط SysV

ملخص

use X11::Protocol;
my $X = X11::Protocol->new;
$X->init_extension('MIT-SHM')
  or print "ملحق MIT-SHM غير متوفر";
use IPC::SysV;
my $shmid = shmget (IPC::SysV::IPC_PRIVATE(),
                    100000,  # بايت
                    IPC::SysV::IPC_CREAT() | 0666);
my $shmseg = $X->new_rsrc;
$X->MitShmAttach ($shmseg, $shmid, 0);
my ($depth, $visual, $size) =  $X->MitShmGetImage
      ($window, 0,0, 16,16, ~0, 'ZPixmap', $shmseg, 0);
my $image_bytes;
shmread ($shmid, $image_bytes, 0, 16*16*$bpp) || die "$!";
# $image_bytes هي أعلى 16x16 بكسل من الشاشة

الوصف

يسمح ملحق MIT-SHM للعميل والخادم الذين يعملان على نفس الجهاز بنقل بيانات الصور عبر أجزاء الذاكرة المشتركة من نمط System-V.

يقوم العميل بإنشاء جزء ذاكرة باستخدام shmget() (راجع "shmget" في perlfunc و "SysV IPC" في perlipc) ويطلب من الخادم الارتباط به ثم القراءة أو الكتابة باستخدام ما يعادل GetImage و PutImage الأساسيين.

الهدف هو تجنب إرسال صور كبيرة عبر اتصال الإدخال/الإخراج عندما تكون على نفس الجهاز. الذاكرة أسرع، وقد تساعد في تجنب حدود حجم الطلب للصور الكبيرة جدًا.

ترتيب البايتات، الحشو، وما إلى ذلك، المطلوبة أو الناتجة في الصور يتم تحديدها بواسطة الخادم "$X->{'image_byte_order'}"، "$X->{'pixmap_formats'}"، إلخ، بنفس الطريقة التي تم بها تحديدها للـ GetImage() و PutImage() الأساسيين. الأمر متروك للعميل للتكيف مع تخطيط الخادم، والذي قد يكون عملاً شاقًا بعض الشيء.

Shm من Perl

يمكن إنشاء جزء ذاكرة مشترك من Perl باستخدام shmget()، ثم قراءة محتوياته أو الكتابة إليها باستخدام shmread() و shmwrite(). تقوم هذه الدوال بالربط وفصل الربط في كل مرة باستخدام استدعاءات نظام shmat() و shmdt()، وهو ما يكون جيدًا لالتقاط الكل ولكن سيكون بطيئًا بعض الشيء للعديد من عمليات الوصول الصغيرة.

"IPC::SysV" (الإصدار 2 وما فوق) يوفر shmat() للاحتفاظ بالجزء المرفق و memread() و memwrite() للوصول إليه (راجع IPC::SysV). راجع IPC::SharedMem للحصول على غلاف كائني التوجه حول هذا أيضًا.

بالمناسبة، إذا لم يكن shmget() متاحًا على النظام، فإن shmget() الخاص بـ Perl يقوم بالانهيار (croaks). من الممكن دائمًا أن يعيد "undef" أيضًا بسبب عدم كفاية الذاكرة وما إلى ذلك. مع ذلك، وعدم وجوده على نفس الجهاز، وعدم وجود أذونات قابلة للتعريف، وما إلى ذلك، هناك عدة حالات يجب فيها الرجوع إلى الإدخال/الإخراج العادي.

أذونات Shm

لجزء الذاكرة المشتركة SysV، توجد بتات أذونات للمالك/المجموعة/الآخرين مشابهة للملف. لن يقوم الخادم بالارتباط إلا بالأجزاء التي يملك العميل الذي يطلبها (UID/GID) إذن قراءتها أو كتابتها.

عادةً ما يستطيع الخادم تحديد معرف المستخدم (UID) ومعرف المجموعة (GID) الخاص بالعميل في اتصال محلي مثل مقبس Unix (X11::Protocol::Connection::UNIXSocket، و "SO_PEERCRED" في socket(7))، وربما في اتصال TCP المحلي. إذا لم يتم ذلك، يعامل الخادم العميل على أنه "آخر" ولن يرتبط إلا بالأجزاء القابلة للقراءة عالميًا (أو القابلة للقراءة والكتابة عالميًا).

يمكنك جعل جزء shm قابلاً للقراءة عالميًا لضمان قدرة الخادم على قراءته. إذا كانت البيانات الخاصة بـ PutImage وما إلى ذلك موجودة بالفعل من ملف قابل للقراءة عالميًا أو عامة، فلا ينبغي أن يهم كثيرًا من يقرأ الجزء. تذكر أن تطلب للقراءة فقط في MitShmAttach() حتى لا يطلب الخادم الكتابة أيضًا.

على الأرجح لا داعي للمخاطرة بتخفيف الأذونات لكتابة الجزء. الاحتمالات تشير إلى أنه إذا لم يكن بالإمكان تحديد معرف المستخدم/المجموعة الخاص بالعميل، فذلك لأن الاتصال ليس محليًا والخادم موجود على جهاز مختلف، لذا لا يمكن استخدام الذاكرة المشتركة على أي حال.

من المعتاد أن يعمل الخادم كـ root، وبالتالي يتحقق من أذوناته الخاصة، ولكن من الممكن أيضًا أن يكون الخادم مستخدمًا عاديًا. في هذه الحالة، ستكون أجزاء shm التي يمكنه الوصول إليها محدودة بالطريقة المعتادة للمستخدم الذي يعمل به.

الطلبات

الطلبات التالية متاحة بعد init_extension() لكل "EXTENSIONS" في X11::Protocol.

my $bool = $X->init_extension('MIT-SHM');

في ما يلي، $shmid هو معرف الذاكرة المشتركة (عدد صحيح) كما تم الحصول عليه من النواة باستخدام shmget(). $shmseg هو XID (يتم تخصيصه كالمعتاد بواسطة العميل "$X->new_rsrc()") على الخادم يمثل ارتباط الخادم بالجزء.

"($server_major, $server_minor, $uid, $gid, $shared_pixmaps, $pixmap_format) = $X->MitShmQueryVersion ()"
إرجاع معلومات حول ملحق MIT-SHM. على عكس الملحقات الأخرى، لا يوجد تفاوض على إصدار العميل / إصدار الخادم.

$server_major و $server_minor هما رقم إصدار الامتداد الذي ينفذه الخادم.

$uid و $gid (أعداد صحيحة) هما معرف المستخدم الفعلي للخادم ومعرف المجموعة ( geteuid() و getegid()). الصفر يعني root.

$shared_pixmaps هو غير صفري إذا كانت صور الـ pixmaps في الذاكرة المشتركة مدعومة (راجع MitShmCreatePixmap() أدناه). $pixmap_format (ImageFormat) هو "XYPixmap" أو "ZPixmap" للتخطيط المطلوب في مثل هذه الـ pixmap.

"$X->MitShmAttach ($shmseg, $shmid, $readonly)"
ربط الخادم بجزء ذاكرة مشترك معين. $shmseg هو XID جديد لتمثيل الذاكرة المرفقة. 
my $shmseg = $X->new_rsrc;
$X->MitShmAttach ($shmseg, $shmid, 0); # للقراءة/الكتابة

$shmid هو معرف الذاكرة المشتركة للربط، كما تم الحصول عليه من shmget() (راجع "shmget" في perlfunc).

$readonly هو 1 لربط الخادم للقراءة فقط، أو 0 للقراءة والكتابة. القراءة فقط تكفي لـ MitShmPutImage()، ولكن القراءة والكتابة مطلوبة لـ MitShmGetImage() و MitShmCreatePixmap().

"$X->MitShmDetach ($shmseg)"
فصل الخادم عن الذاكرة المشتركة $shmseg (XID) وتحرير هذا XID. 
$X->MitShmDetach ($shmseg);
"$X->MitShmPutImage ($drawable, $gc, $depth, $total_width, $total_height, $src_x, $src_y, $src_width, $src_height, $dst_x, $dst_y, $format, $send_event, $shmseg, $offset)"
وضع بيانات الصورة من $shmseg (XID) إلى $drawable. المعلمات مشابهة للـ PutImage() الأساسي.

$depth هو عمق الصورة. لـ $format "Bitmap"، يجب أن يكون 1 وسيتم رسم ألوان المقدمة والخلفية لـ $gc. لـ $format "XYPixmap" و "ZPixmap"، يجب أن يكون $depth هو عمق $drawable.

$total_width، $total_height هو الحجم الكامل للصورة في الذاكرة المشتركة. $src_x، $src_y و $src_width، $src_height هما الجزء الذي سيتم رسمه. $dst_x، $dst_y هو المكان الذي سيتم وضعها فيه في $drawable.

$format هو "Bitmap"، "XYPixmap" أو "ZPixmap" (ImageFormat).

$send_event هو 1 لإرسال "MitShmCompletionEvent" إلى العميل عند الانتهاء من الرسم (راجع "EVE

X11::Protocol::Ext::MIT_SHM(3pm)

This module implements the MIT Shared Memory Transfer extension for X11::Protocol. This allows for faster image transfer between the X server and clients.

NAME

X11::Protocol::Ext::MIT_SHM - MIT Shared Memory Transfer extension protocol

SYNOPSIS

    use X11::Protocol::Ext::MIT_SHM;
    my $x = X11::Protocol->new;

    my ($major_opcode, $event_base, $error_base) = $x->MitShmQueryVersion;

    my $shminfo = $x->MitShmAllocate(1024*1024); # allocate 1MB shared memory
    # ... use $shminfo->{shmseg}, $shminfo->{offset} ...
    $x->MitShmPutImage(...);
    $x->MitShmGetImage(...);
    $x->MitShmCreatePixmap(...);
    $x->MitShmAttach(...);
    $x->MitShmDetach(...);
    $x->MitShmPutImage(...); # Send image to server
    my $ev = $x->next_event; # Wait for MitShmCompletionEvent
    $x->MitShmFree(shminfo);

DESCRIPTION

This module implements the MIT Shared Memory Transfer extension for X11::Protocol. This extension allows for faster image transfer between the X server and clients by using shared memory segments. Instead of copying data over the network, the X server and client can access the same memory region directly.

The extension provides functions for allocating and freeing shared memory, putting images into shared memory, getting images from shared memory, and creating pixmaps in shared memory.

REQUESTS

"$major_opcode, $event_base, $error_base = $X->MitShmQueryVersion"
Checks if the MIT-SHM extension is supported and retrieves its base opcode, event code, and error code.
"$shminfo = $X->MitShmAllocate($size)"
Requests the X server to allocate a shared memory segment of $size bytes. Returns a hash containing information about the shared memory segment, including its XID (shmseg), the memory offset (offset), and the actual allocated size (size). The client must later MitShmAttach() to use it.
"$X->MitShmAttach ($shmseg)"
Attaches a shared memory segment specified by $shmseg (an XID) to the X server's address space, making it readable and writable by the server. This must be done before using the shared memory segment for image transfer.
"$X->MitShmDetach ($shmseg)"
Detaches a shared memory segment specified by $shmseg (an XID) from the X server's address space.
"$X->MitShmPutImage ($drawable, $x, $y, $width, $height, $planemask, $format, $sendevent, $shmseg, $offset)"
Copies an image from the shared memory segment specified by $shmseg (an XID) to the X server's drawable $drawable.

$x,$y, $width,$height specify the region of the drawable to be updated.

$planemask is a bit mask for which bit planes of the pixels are to be transferred.

$format can be "XYPixmap" or "ZPixmap", specifying the layout of the image data in shared memory.

$sendevent is a boolean flag. If true, the server will send a MitShmCompletionEvent when the operation is complete.

$shmseg is the XID of the shared memory segment containing the image data.

$offset is a byte offset into the shared memory where the image data begins.

"($depth, $visual, $size) = $X->MitShmCreatePixmap ($pixmap, $drawable, $depth, $width, $height, $shmseg, $offset)"
Creates a pixmap $pixmap (a new XID) with its contents stored in the shared memory segment $shmseg (an XID). Subsequent reads or writes to this shared memory by the client will directly affect the pixmap's contents. The parameters are similar to the core CreatePixmap() request.

$drawable determines the screen for the new pixmap.

$offset is a byte offset into the shared memory where the pixmap data starts.

The returned values are:

  • $depth: The depth of the created pixmap.
  • $visual: The visual ID of the pixmap, or "None" if it's a pixmap created from a pixmap.
  • $size: The actual size of the pixmap in bytes.

If the DAMAGE extension is active and monitoring this shared pixmap, client writes to the shared memory may not generate "DamageNotify" events by default. The client can use DamageAdd() requests (in Damage version 1.1) to inform the server of changes made to the shared memory, which the server will then broadcast to interested damage objects.

"$shminfo = $X->MitShmGetImage ($drawable, $x, $y, $width, $height, $planemask, $format, $shmseg, $offset)"
Copies an image from the specified drawable region $drawable,$x,$y,$width,$height to the shared memory segment $shmseg (an XID) at the specified $offset.

$planemask selects the bit planes to be copied.

$format specifies the layout in shared memory, either "XYPixmap" or "ZPixmap".

The returned $shminfo hash contains:

  • depth: The depth of the drawable.
  • visual: The visual ID of the drawable, or "None" for a pixmap.
  • size: The number of bytes written to shared memory.

$shmseg must have been attached using MitShmAttach() (read-write) before this request, otherwise an "Access" error will result.

"$X->MitShmFree ($shminfo)"
Frees a shared memory segment previously allocated with MitShmAllocate(). The argument is the hash returned by MitShmAllocate(). This detaches the segment from the server and frees the underlying system resources.

EVENTS

"MitShmCompletionEvent" is sent to the client when requested by a MitShmPutImage() call where $sendevent was true. It indicates that the server has finished processing the shared memory image.

The event has the following fields:

    name            "MitShmCompletionEvent"
    synthetic       boolean, true if from a SendEvent request
    code            integer, the MIT-SHM extension opcode
    sequence_number integer, the sequence number of the request that generated this event

And event-specific fields:

    drawable        XID, the drawable target of the MitShmPutImage request
    shmseg          XID, the shared memory segment used
    offset          integer, the byte offset within the shared memory segment
    major_opcode    integer, the MIT-SHM extension opcode
    minor_opcode    integer, 3 for MitShmPutImage

The major_opcode and minor_opcode fields identify the originating request. These fields are analogous to those in core X events like "GraphicsExposure" and "NoExposure", but in the MIT-SHM extension, only MitShmPutImage() can generate a completion event.

ERRORS

Error type "ShmSeg" is raised when an invalid shared memory segment XID ($shmseg) is provided in a request.
