X11__Protocol(3pm)

الحزمة: perl-x11-protocol

التراخيص: GPL, PerlArtistic

Protocol(3) توثيق Perl من مساهمي المستخدم Protocol(3)

الاسم

X11::Protocol - وحدة Perl لبروتوكول X Window System، الإصدار 11

الملخص

use X11::Protocol;
$x = X11::Protocol->new();
$win = $x->new_rsrc;
$x->CreateWindow($win, $x->root, 'InputOutput',
                 $x->root_depth, 'CopyFromParent',
                 ($x_coord, $y_coord), $width,
                 $height, $border_w);  
...

الوصف

X11::Protocol هي واجهة من جانب العميل لبروتوكول X11 (انظر X(1) للحصول على معلومات حول X11)، مما يسمح لبرامج perl بعرض النوافذ والرسومات على خوادم X11.

الوصف الكامل للبروتوكول يتجاوز نطاق هذا التوثيق؛ للحصول على معلومات كاملة، انظر بروتوكول X Window System، الإصدار 11، المتاح كـ Postscript أو مصدر *roff من "ftp://ftp.x.org"، أو المجلد 0: دليل مرجع بروتوكول X من سلسلة كتب O'Reilly & Associates حول X (ISBN 1-56592-083-X، "http://www.oreilly.com")، والتي تحتوي على معظم نفس المعلومات.

إخلاء المسؤولية

«يحتوي البروتوكول على العديد من آليات الإدارة التي لم يتم تصميمها للتطبيقات العادية. ليست كل الآليات مطلوبة لبناء واجهة مستخدم معينة. من المهم أن نأخذ في الاعتبار أن البروتوكول يهدف إلى توفير الآلية، وليس السياسة.» -- روبرت دبليو. شيفلر

الأساليب الأساسية

new

$x = X11::Protocol->new();
$x = X11::Protocol->new($display_name);
$x = X11::Protocol->new($connection);
$x = X11::Protocol->new($display_name, [$auth_type, $auth_data]);
$x = X11::Protocol->new($connection, [$auth_type, $auth_data]);

فتح اتصال بالخادم. يجب أن يكون $display_name اسم عرض X، بالشكل 'host:display_num.screen_num'؛ إذا لم يتم توفير أي وسائط، يتم استخدام محتويات متغير البيئة DISPLAY. بدلاً من ذلك، يمكن تقديم اتصال مفتوح مسبقًا، من إحدى فئات X11::Protocol::Connection (انظر X11::Protocol::Connection، X11::Protocol::Connection::FileHandle، X11::Protocol::Connection::Socket، X11::Protocol::Connection::UNIXFH، X11::Protocol::Connection::INETFH، X11::Protocol::Connection::UNIXSocket، X11::Protocol::Connection::INETSocket). يتم الحصول على بيانات المصادقة باستخدام X11::Auth أو الوسيط الثاني. إذا تم تحديد العرض بواسطة $display_name، بدلاً من $connection، يتم أيضًا إجراء choose_screen()، مع افتراض الشاشة 0 إذا لم يكن '.screen_num' لاسم العرض موجودًا. ترجع كائن البروتوكول الجديد.

new_rsrc

$x->new_rsrc;

ترجع معرف مورد جديد. مطلوب معرف مورد فريد لكل كائن ينشئه الخادم نيابة عن العميل: النوافذ، والخطوط، والمؤشرات، وما إلى ذلك (يختار العميل معرفات بدلاً من الخادم لتحقيق الكفاءة -- لا يحتاج العميل إلى انتظار الخادم للاعتراف بالإنشاء قبل البدء في استخدام الكائن).

لاحظ أن العدد الإجمالي لمعرفات الموارد المتاحة، على الرغم من أنه كبير، محدود. بدءًا من إنشاء اتصال، يتم تخصيص معرفات الموارد بشكل متسلسل من نطاق حجمه يعتمد على الخادم (عادة 2**21، حوالي 2 مليون). إذا تم الوصول إلى هذا الحد ولم يدعم الخادم امتداد XC_MISC، فإن الاستدعاءات اللاحقة لـ new_rsrc ستفشل. إذا كان الخادم يدعم هذا الامتداد، ستحاول الوحدة طلب نطاق جديد من المعرفات الحرة من الخادم. يجب أن يسمح هذا للبرنامج بالاستمرار، ولكنه حل غير مثالي، لأنه بمرور الوقت قد يتفتت مجموعة المعرفات المتاحة، مما يتطلب طلبات نطاق ذهابًا وإيابًا بشكل متزايد من الخادم. بالنسبة للبرامج طويلة الأمد، قد يكون النهج الأفضل هو تتبع المعرفات الحرة عندما يتم تدمير الموارد. في الإصدار الحالي، ومع ذلك، لا يتم تقديم أي دعم خاص لهذا.

handle_input

$x->handle_input;

الحصول على جزء واحد من المعلومات من الخادم، والقيام بشيء بها. إذا كان خطأ، فقم بمعالجته باستخدام معالج كائن البروتوكول ('error_handler' -- الافتراضي هو إنهاء البرنامج برسالة توضيحية). إذا كان حدثًا، فقم بتمريره إلى معالج الأحداث المختار، أو ضعه في قائمة انتظار إذا كان المعالج 'queue'. إذا كان ردًا على طلب، فقم بحفظه باستخدام تجزئة 'replies' للكائن لمزيد من المعالجة.

atom_name

$name = $x->atom_name($atom);

إرجاع السلسلة النصية المقابلة للذرة $atom. هذا مشابه لطلب GetAtomName، ولكنه يخزن النتيجة مؤقتًا لتحقيق الكفاءة.

atom

$atom = $x->atom($name);

العملية العكسية؛ إرجاع الذرة (الرقمية) المقابلة لـ $name. هذا مشابه لطلب InternAtom، ولكنه يخزن النتيجة مؤقتًا.

choose_screen

$x->choose_screen($screen_num);

الإشارة إلى تفضيل استخدام شاشة معينة من العرض. سيتم توفير معلومات لكل شاشة، مثل 'root'، 'width_in_pixels'، و 'white_pixel' كـ

$x->{'root'}

بدلاً من

$x->{'screens'}[$screen_num]{'root'}

الثوابت الرمزية

بشكل عام، يتم تمرير الثوابت الرمزية المستخدمة في البروتوكول، مثل 'CopyFromParent' أو 'PieSlice'، إلى الأساليب كسلاسل نصية، وتقوم الوحدة بتحويلها إلى أرقام. أسماؤها هي نفس أسماء مواصفات البروتوكول، بما في ذلك حالة الأحرف، ولكن مع تغيير الشرطات ('-') إلى شرطات سفلية ('_') لتبدو أقرب إلى أسلوب Perl. إذا كنت ترغب في إجراء التحويل بنفسك لسبب ما، فإن الأساليب التالية متاحة:

num

$num = $x->num($type, $str)

بالنظر إلى سلسلة تمثل ثابتًا وسلسلة تحدد نوع الثابت، قم بإرجاع الرقم المقابل. يجب أن يكون $type اسمًا مثل 'VisualClass' أو 'GCLineStyle'. إذا لم يتم التعرف على الاسم، يتم إرجاعه كما هو.

interp

$name = $x->interp($type, $num)

العملية العكسية؛ بالنظر إلى رقم وسلسلة تحدد نوعه، قم بإرجاع سلسلة تمثل الثابت.

يمكنك تعطيل interp() وتفسير الوحدة الداخلي للأرقام عن طريق تعيين $x->{'do_interp'} إلى الصفر. بالطبع، هذا ليس مفيدًا جدًا، إلا إذا كان لديك تعريفاتك الخاصة لجميع الثوابت.

$x->{'release_number'}

x->release_number

الطلبات

request

$x->request('CreateWindow', ...);
$x->req('CreateWindow', ...);
$x->CreateWindow(...);

إرسال طلب بروتوكول إلى الخادم، والحصول على الرد، إن وجد. لأسماء ومعلومات الطلبات الفردية، انظر أدناه و/أو دليل مرجع البروتوكول.

robust_req

$x->robust_req('CreateWindow', ...);

مثل request()، ولكن إذا أعاد الخادم خطأ، فقم بإرجاع معلومات الخطأ بدلاً من استدعاء معالج الخطأ (الذي ينهار افتراضيًا). إذا نجح الطلب، فإنه يعيد مرجع مصفوفة يحتوي على أي شيء قد يعيده request(). خلاف ذلك، فإنه يعيد نوع الخطأ، ورقمي الترميز الرئيسيين والثانويين للطلب الفاشل، ومعلومات الخطأ الإضافية، إن وجدت. لاحظ أنه حتى لو لم يكن للطلب رد في العادة، فإن هذه الطريقة لا تزال بحاجة إلى الانتظار لوقت رحلة ذهاب وعودة لمعرفة ما إذا كان هناك خطأ. إذا كنت تهتم بالأداء، فيجب عليك تصميم معالجة الأخطاء الخاصة بك لتكون غير متزامنة.

add_reply

$x->add_reply($sequence_num, \$var);

إضافة طابع للرد المتوقع إلى تجزئة 'replies' للكائن. عندما يأتي رد مرقم $sequence_num، سيتم تخزينه في $var.

delete_reply

$x->delete_reply($sequence_num);

حذف الإدخال في 'replies' للرد المحدد. (يجب القيام بذلك بعد استلام الرد).

send

$x->send('CreateWindow', ...);

إرسال طلب، ولكن لا تنتظر ردًا. يجب عليك التعامل مع الرد، إن وجد، بنفسك، باستخدام add_reply() و handle_input() و delete_reply() و unpack_reply()، بشكل عام بهذا الترتيب.

unpack_reply

$x->unpack_reply('GetWindowAttributes', $data);

تفسير بيانات الرد الخام $data، وفقًا لتنسيق الرد للطلب المسمى. يعيد بيانات بنفس التنسيق الذي تعيده "request($request_name, ...)".

يتضمن هذا القسم فقط ملخص استدعاء قصير لكل طلب؛ للأوصاف الكاملة، انظر معيار البروتوكول. ترتيب الوسيطات عادة ما يكون نفس الترتيب المدرج في المواصفات، ولكنك بشكل عام لا تحتاج إلى تمرير أطوال السلاسل أو المصفوفات، لأن perl يحتفظ بها. يتم تمرير الثوابت الرمزية بشكل عام كسلاسل. يتم إرجاع معظم الردود كقوائم، ولكن عندما تكون هناك قيم كثيرة، يتم استخدام تجزئة. تأتي القوائم عادة في النهاية؛ عندما يكون هناك أكثر من قائمة واحدة، يتم تمرير كل منها بالمرجع. في قوائم الهياكل متعددة الأجزاء، كل عنصر هو مرجع قائمة. يتم إدراج الأقواس في قوائم الوسيطات للتوضيح، ولكنها اختيارية. يتم سرد الطلبات بالترتيب حسب رقم الترميز الرئيسي، لذا غالبًا ما تكون الطلبات ذات الصلة قريبة من بعضها البعض. تتبع الردود '=>'.

X11::Protocol(3pm)

NAME

X11::Protocol - A Perl interface to the X Window System Protocol

SYNOPSIS

 use X11::Protocol;
 my $x = X11::Protocol->new;
 my $screen = $x->root->SCREEN;
 print "root window is $screen\n";

DESCRIPTION

This module provides a Perl interface to the X protocol. It is designed to be a fairly direct mapping of the protocol specification.

The main class is X11::Protocol. You can create an object representing a connection to an X server with X11::Protocol->new.

There are a number of other classes that are used internally by X11::Protocol, or which you might find useful in writing extensions.

DISCLAIMER

This module is not complete. It implements the core protocol, and most of the extensions that are commonly used. However, new extensions are always being added to X11, and it is possible that this module does not support all of them.

This module is also not particularly efficient. It is designed to be a direct mapping of the protocol, and as such, it does not take advantage of some of the optimizations that might be possible. For example, it does not use shared memory to communicate with the X server.

Create a new connection to the X server.
display
Return the display name.

Return the file descriptor for the connection to the X server.

Return the root window object.

Return the file descriptor for error messages.

Return the setup information from the X server.

Flush the output buffer.

Read the next event from the X server.
pending
Return the number of events pending in the input buffer.

SYMBOLIC CONSTANTS

The module exports a large number of symbolic constants, such as ConfigureNotify, ButtonPress, KeyRelease, etc. These are the names of the events that can be generated by the X server.

It also exports constants for the various request codes, such as CreateWindow, DestroyWindow, MapWindow, etc.

Finally, it exports constants for the various error codes, such as BadRequest, BadValue, BadWindow, etc.

SERVER INFORMATION

The setup method returns an object that contains information about the X server. This includes information about the server's vendor, protocol version, and screen configuration.

The screen information can be accessed via the screens method of the setup object, which returns a list of screen objects. Each screen object contains information about the screen's root window, width, height, and depth.

REQUESTS

The module allows you to send requests to the X server. For example, to create a new window, you would use the CreateWindow request:

 my $window = $x->CreateWindow(
     parent => $x->root,
     x => 0,
     y => 0,
     width => 100,
     height => 100,
     border_width => 5,
     class => 'InputOutput',
     visual => 'copy from parent',
     valuemask => [qw(background_pixel border_pixel event_mask)],
     background_pixel => 0xffffffff,
     border_pixel => 0x00000000,
     event_mask => [qw(ExposureKeyPress)],
 );

The arguments to the requests are specified as a hash. The keys of the hash are the names of the fields in the request structure. The values are the values to be sent to the server.

Some fields are optional, and are specified by a valuemask. If a field is specified in the valuemask, then it must be included in the hash. Otherwise, it is ignored.

EVENTS

The event method reads the next event from the X server. The event is returned as an object that contains the event information.

For example, to wait for a KeyPress event:

 my $event = $x->wait_for(qw(KeyPress));
 if ($event->isa('X11::Protocol::Event::KeyPress')) {
     my $keycode = $event->detail;
     print "Key pressed: $keycode\n";
 }

The wait_for method can be used to wait for one or more specific events. It returns the first event that matches the specified types.

EXTENSIONS

The module supports X11 extensions. Extensions are loaded dynamically when they are first used.

For example, to use the SHAPE extension:

 use X11::Protocol::Ext::SHAPE;
 my $shape = X11::Protocol::Ext::SHAPE->new($x);
 $shape->Set(window => $window, destinations => [ SHAPE_BOUNDING ]);

WRITING EXTENSIONS

This module is designed to make it easy to write X11 extensions. The module provides a number of helper functions that can be used to simplify the process.

For examples of code that does all of this, look at X11::Protocol::Ext::SHAPE.

X11::Protocol exports several functions that might be useful in extensions (note that these are not methods).

padding

$p = padding $x;

Given an integer, compute the number need to round it up to a multiple of 4. For instance, padding(5) is 3.

pad

$p = pad $str;

Given a string, return the number of extra bytes needed to make a multiple of 4. Equivalent to "padding(length($str))".

padded

$data = pack(padded($str), $str);

Return a format string, suitable for pack(), for a string padded to a multiple of 4 bytes. For instance, "pack(padded('Hello'), 'Hello')" gives "Hello\0\0\0".

hexi

$str = hexi $n;

Format a number in hexidecimal, and add a "0x" to the front.

make_num_hash

%hash = make_num_hash(['A', 'B', 'C']);

Given a reference to a list of strings, return a hash mapping the strings onto numbers representing their position in the list, as used by "$x->{'ext_const_num'}".

BUGS

This module is too big (~2500 lines), too slow (10 sec to load on a slow machine), too inefficient (request args are copied several times), and takes up too much memory (3000K for basicwin).

If you have more than 65535 replies outstanding at once, sequence numbers can collide.

The protocol is too complex.
