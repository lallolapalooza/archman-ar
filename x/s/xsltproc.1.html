الاسم

xsltproc - معالج XSLT سطر الأوامر

ملخص

xsltproc [[-V | --version] [-v | --verbose] [{-o | --output} {FILE | DIRECTORY}] | --timing | --repeat | --debug | --novalid | --noout | --maxdepth VALUE | --maxvars VALUE | --huge | --seed-rand VALUE | --html | --encoding ENCODING  | --param PARAMNAME PARAMVALUE  | --stringparam PARAMNAME PARAMVALUE  | --nonet | --path "PATH(S)" | --load-trace | --catalogs | --xinclude | --xincludestyle | [--profile | --norman] | --dumpextensions | --nowrite | --nomkdir | --writesubtree PATH | --nodtdattr] [STYLESHEET] {XML-FILE... | -}

الوصف

xsltproc هي أداة سطر أوامر لتطبيق أوراق أنماط XSLT على مستندات XML. هي جزء من libxslt(3)، وهي مكتبة XSLT مكتوبة بلغة C لمشروع GNOME. على الرغم من أنها طُورت كجزء من مشروع GNOME، إلا أنها يمكن أن تعمل بشكل مستقل عن بيئة سطح المكتب GNOME.

يتم استدعاء xsltproc من سطر الأوامر باسم ورقة الأنماط المراد استخدامها متبوعًا باسم الملف أو الملفات التي سيتم تطبيق ورقة الأنماط عليها. ستستخدم الإدخال القياسي إذا كان اسم الملف المقدم هو -.

إذا تم تضمين ورقة أنماط في مستند XML باستخدام تعليمات معالجة ورقة الأنماط (Stylesheet Processing Instruction)، فلا حاجة لتحديد ورقة أنماط في سطر الأوامر. سيكتشف xsltproc تلقائيًا ورقة الأنماط المضمنة وسيستخدمها.

بشكل افتراضي، يتم توجيه الإخراج إلى stdout. يمكنك تحديد ملف للإخراج باستخدام الخيار -o أو --output.

الخيارات

يقبل xsltproc الخيارات التالية (مرتبة أبجديًا):

--catalogs

استخدم كتالوج SGML المحدد في SGML_CATALOG_FILES لحل موقع الكيانات الخارجية. افتراضيًا، يبحث xsltproc عن الكتالوج المحدد في XML_CATALOG_FILES. إذا لم يتم تحديده، فإنه يستخدم /etc/xml/catalog.

--debug

إخراج شجرة XML للمستند المحول لأغراض التصحيح.

--dumpextensions

إخراج قائمة بجميع الامتدادات المسجلة إلى stdout.

--html

المستند المدخل هو ملف HTML.

--load-trace

عرض جميع المستندات التي تم تحميلها أثناء المعالجة إلى stderr.

--maxdepth VALUE

ضبط الحد الأقصى لعمق مكدس القالب قبل أن يقرر libxslt(3) أنه في حلقة لا نهائية. القيمة الافتراضية هي 3000.

--maxvars VALUE

الحد الأقصى لعدد المتغيرات. القيمة الافتراضية هي 15000.

--huge

تخفيف حدود محلل XML الثابتة عن طريق تعيين خيار المحلل XML_PARSE_HUGE.

--seed-rand VALUE

تهيئة مولد الأرقام العشوائية الزائفة ببذرة محددة.

--nodtdattr

لا تطبق سمات افتراضية من DTD المستند.

--nomkdir

يرفض إنشاء المجلدات.

--nonet

لا تستخدم الإنترنت لجلب DTDs أو الكيانات أو المستندات.

--noout

لا تخرج النتيجة.

--novalid

تجاوز تحميل DTD المستند.

--nowrite

يرفض الكتابة إلى أي ملف أو مورد.

-o أو --output FILE | DIRECTORY

توجيه الإخراج إلى الملف المحدد FILE. استخدام الخيار مع DIRECTORY يوجه ملفات الإخراج إلى الدليل المحدد. يمكن أن يكون هذا مفيدًا للمخرجات المتعددة (المعروفة أيضًا باسم "التجزئة") أو معالجة صفحات الدليل.

هام
يجب أن يكون الدليل المحدد DIRECTORY موجودًا بالفعل.

ملاحظة
تأكد من أن FILE و DIRECTORY يتبعان "حساب مرجع URI" كما هو موضح في RFC 2396 والإصدارات اللاحقة. هذا يعني، على سبيل المثال، أن -o directory قد لا تعمل، ولكن -o directory/ ستعمل.

--encoding ENCODING

السماح بتحديد ترميز الإدخال.

--param PARAMNAME PARAMVALUE

تمرير معامل بالاسم PARAMNAME والقيمة PARAMVALUE إلى ورقة الأنماط. يمكنك تمرير أزواج متعددة من الاسم/القيمة بحد أقصى 32. إذا كانت القيمة التي يتم تمريرها عبارة عن سلسلة نصية، يمكنك استخدام --stringparam بدلاً من ذلك، لتجنب أحرف الاقتباس الإضافية التي تظهر في تعبيرات السلاسل النصية. ملاحظة: يجب ترميز تعبير XPath بـ UTF-8.

--path "PATH(S)"

استخدم قائمة مسارات نظام الملفات (مفصولة بمسافات أو نقاط) المحددة بواسطة PATHS لتحميل DTDs أو الكيانات أو المستندات. قم بتضمين القوائم المفصولة بمسافات بين علامتي اقتباس.

--profile أو --norman

إخراج معلومات تعريفية تفصيلية للمدة الزمنية المستغرقة في كل جزء من ورقة الأنماط. هذا مفيد في تحسين أداء ورقة الأنماط.

--repeat

تشغيل التحويل 20 مرة. يستخدم لاختبارات التوقيت.

--stringparam PARAMNAME PARAMVALUE

تمرير معامل بالاسم PARAMNAME والقيمة PARAMVALUE حيث PARAMVALUE عبارة عن سلسلة نصية بدلاً من معرف عقدة. ملاحظة: يجب ترميز السلسلة النصية بـ UTF-8.

--timing

عرض الوقت المستغرق لتحليل ورقة الأنماط، وتحليل المستند، وتطبيق ورقة الأنماط وحفظ النتيجة. يتم عرضه بالمللي ثانية.

-v أو --verbose

إخراج كل خطوة يتخذها xsltproc في معالجة ورقة الأنماط والمستند.

-V أو --version

عرض إصدار libxml(3) و libxslt(3) المستخدم.

--writesubtree PATH

السماح بالكتابة إلى الملف فقط ضمن شجرة المسار PATH.

--xinclude

معالجة المستند المدخل باستخدام مواصفات XInclude. مزيد من التفاصيل حول هذا يمكن العثور عليها في مواصفات XInclude: http://www.w3.org/TR/xinclude/

--xincludestyle

معالجة ورقة الأنماط باستخدام XInclude.

البيئة

SGML_CATALOG_FILES

يمكن تغيير سلوك كتالوج SGML عن طريق إعادة توجيه الاستعلامات إلى مجموعة الكتالوجات الخاصة بالمستخدم. يمكن القيام بذلك عن طريق تعيين متغير البيئة SGML_CATALOG_FILES إلى قائمة بالكتالوجات. يجب أن يؤدي إفراغها إلى إلغاء تحميل كتالوج /etc/sgml/catalog الافتراضي.

XML_CATALOG_FILES

يمكن تغيير سلوك كتالوج XML عن طريق إعادة توجيه الاستعلامات إلى مجموعة الكتالوجات الخاصة بالمستخدم. يمكن القيام بذلك عن طريق تعيين متغير البيئة XML_CATALOG_FILES إلى قائمة بالكتالوجات. يجب أن يؤدي إفراغها إلى إلغاء تحميل كتالوج /etc/xml/catalog الافتراضي.

التشخيصات

توفر رموز الإرجاع لـ xsltproc معلومات يمكن استخدامها عند استدعائها من نصوص برمجية.

0

لا يوجد خطأ (تشغيل طبيعي)

1

لا يوجد وسيط

2

عدد كبير جدًا من المعاملات

3

خيار غير معروف

4

فشل في تحليل ورقة الأنماط

5

خطأ في ورقة الأنماط

6

خطأ في واحد

xsltproc(1) - xsltproc man page

NAME

xsltproc - command line XSLT processor

SYNOPSIS

xsltproc [options] [--stringparam name value]... [--param name value]... [--assign name value]... stylesheet file...

DESCRIPTION

xsltproc is a command line XSLT 1.0 processor. It can be used to transform XML documents using XSLT stylesheets.

It takes the stylesheet and the XML document as input and produces the result of the transformation.

The stylesheet can be specified either on the command line as the last argument before the file (or files) to be processed, or using the xml-stylesheet processing instruction in the XML document itself.

If multiple stylesheets are specified on the command line, they are applied sequentially. The output of one stylesheet is used as the input for the next.

If no XML input file is specified, xsltproc reads from standard input.

If no stylesheet is specified, xsltproc tries to find an xml-stylesheet processing instruction in the input document.

The stylesheet itself is an XML document following the XSLT namespace and syntax. The processor supports XSLT 1.0 and the EXSLT extensions.

OPTIONS

--output file, -o file

Write the result to the specified file instead of standard output.

--stringparam name value

Set a string parameter for the stylesheet. The name is interpreted as a QName.

--param name value

Set a parameter for the stylesheet. The value is interpreted as an XPath expression.

--assign name value

Set a variable for the stylesheet. The value is interpreted as an XPath expression.

--insert file

Insert the specified file into the current document.

--pipe

Use the stylesheet to transform the input XML document, and output the result to standard output. This is the default behavior.

--cd directory

Change directory to the specified directory before processing.

--novalid

Do not perform DTD validation of the input XML document.

--noout

Do not generate any output. Useful for checking the validity of an XSLT stylesheet.

--path path

Add a directory to the search path for the external entities and XSLT stylesheets.

--nonet

Disable network access for fetching external entities.

--catalogs

Use XML entity catalogs to resolve public identifiers.

--debug

Enable debugging output.

--version

Print the version of xsltproc and exit.

-

Read input from standard input.

-h, --help

Print a help message and exit.

ENVIRONMENT

No specific environment variables are used by xsltproc.

DIAGNOSTICS

The exit status is 0 on success, and non-zero on failure. Errors are reported to standard error.

Specific error codes:

0

Success

1

Internal error

2

Unrecoverable error, processing stopped

3

Usage error

4

Transfomation error

5

Stack overflow

6

Unknown error

7

Unsupported xsl:output method

8

String parameter contains both quote and double-quotes

9

Internal processing error

10

Processing was stopped by a terminating message

11

Could not write the result to the output file
