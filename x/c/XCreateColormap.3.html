XCreateColormap(3)

الحزمة: libx11

التراخيص: MIT AND X11

XCreateColormap(3) وظائف XLIB XCreateColormap(3)

الاسم

XCreateColormap, XCopyColormapAndFree, XFreeColormap, XColor - إنشاء، نسخ، أو تدمير خرائط الألوان وهياكل الألوان

الصيغة

Colormap XCreateColormap(Display *display, Window w, Visual *visual, int alloc);

Colormap XCopyColormapAndFree(Display *display, Colormap colormap);

int XFreeColormap(Display *display, Colormap colormap);

المعاملات

alloc
يحدد مدخلات خريطة الألوان التي سيتم تخصيصها. يمكنك تمرير AllocNone أو AllocAll.
colormap
يحدد خريطة الألوان التي تريد إنشائها، نسخها، تعيينها، أو تدميرها.
display
يحدد الاتصال بخادم X.
visual
يحدد نوع عرض مدعوم على الشاشة. إذا لم يكن نوع العرض مدعومًا من قبل الشاشة، فستنتج خطأ BadMatch.
w
يحدد النافذة التي تريد إنشاء خريطة ألوان لها على شاشتها.

الوصف

تقوم الدالة XCreateColormap بإنشاء خريطة ألوان من نوع العرض المحدد للشاشة التي توجد عليها النافذة المحددة وتعيد معرف خريطة الألوان المرتبط بها. لاحظ أن النافذة المحددة تستخدم فقط لتحديد الشاشة.

القيم الأولية لمدخلات خريطة الألوان غير محددة لفئات العرض GrayScale و PseudoColor و DirectColor. بالنسبة لـ StaticGray و StaticColor و TrueColor، تكون المدخلات ذات قيم محددة، ولكن هذه القيم خاصة بالعرض وليست محددة بواسطة X. بالنسبة لـ StaticGray و StaticColor و TrueColor، يجب أن يكون alloc هو AllocNone، أو سينتج خطأ BadMatch. بالنسبة لفئات العرض الأخرى، إذا كان alloc هو AllocNone، فإن خريطة الألوان لا تحتوي في البداية على أي مدخلات مخصصة، ويمكن للعملاء تخصيصها. للحصول على معلومات حول أنواع العرض، انظر القسم 3.1.

إذا كان alloc هو AllocAll، يتم تخصيص خريطة الألوان بأكملها للكتابة. القيم الأولية لجميع المدخلات المخصصة غير محددة. بالنسبة لـ GrayScale و PseudoColor، يكون التأثير كما لو أن استدعاء XAllocColorCells أعاد جميع قيم البكسل من صفر إلى N - 1، حيث N هي قيمة مدخلات خريطة الألوان في العرض المحدد. بالنسبة لـ DirectColor، يكون التأثير كما لو أن استدعاء XAllocColorPlanes أعاد قيمة بكسل صفر وقناع أحمر، وقناع أخضر، وقناع أزرق تحتوي على نفس بتات الأقنعة المقابلة في العرض المحدد. ومع ذلك، في جميع الحالات، لا يمكن تحرير أي من هذه المدخلات باستخدام XFreeColors.

يمكن لـ XCreateColormap إنشاء أخطاء BadAlloc و BadMatch و BadValue و BadWindow.

تقوم الدالة XCopyColormapAndFree بإنشاء خريطة ألوان بنفس نوع العرض ولنفس الشاشة مثل خريطة الألوان المحددة وتعيد معرف خريطة الألوان الجديد. كما أنها تنقل جميع التخصيصات الحالية للعميل من خريطة الألوان المحددة إلى خريطة الألوان الجديدة مع الاحتفاظ بقيم الألوان الخاصة بها وخصائص القراءة فقط أو الكتابة الخاصة بها، وتقوم بتحرير تلك المدخلات في خريطة الألوان المحددة. قيم الألوان في المدخلات الأخرى في خريطة الألوان الجديدة غير محددة. إذا تم إنشاء خريطة الألوان المحددة بواسطة العميل مع تعيين alloc إلى AllocAll، يتم إنشاء خريطة الألوان الجديدة أيضًا مع AllocAll، ويتم نسخ جميع قيم الألوان لجميع المدخلات من خريطة الألوان المحددة، ثم يتم تحرير جميع المدخلات في خريطة الألوان المحددة. إذا لم يتم إنشاء خريطة الألوان المحددة بواسطة العميل باستخدام AllocAll، فإن التخصيصات المراد نقلها هي جميع البكسلات والمستويات التي تم تخصيصها بواسطة العميل باستخدام XAllocColor و XAllocNamedColor و XAllocColorCells أو XAllocColorPlanes والتي لم يتم تحريرها منذ تخصيصها.

يمكن لـ XCopyColormapAndFree إنشاء أخطاء BadAlloc و BadColor.

تقوم الدالة XFreeColormap بحذف الارتباط بين معرف مورد خريطة الألوان وخريطة الألوان وتحرير مساحة تخزين خريطة الألوان. ومع ذلك، لا يكون لهذه الدالة أي تأثير على خريطة الألوان الافتراضية للشاشة. إذا كانت خريطة الألوان المحددة خريطة مثبتة لشاشة، فسيتم إلغاء تثبيتها (انظر XUninstallColormap). إذا تم تعريف خريطة الألوان المحددة على أنها خريطة الألوان لنافذة (بواسطة XCreateWindow أو XSetWindowColormap أو XChangeWindowAttributes)، فإن XFreeColormap تغير خريطة الألوان المرتبطة بالنافذة إلى None وتنشئ حدث ColormapNotify. لا تحدد X الألوان المعروضة لنافذة ذات خريطة ألوان None.

يمكن لـ XFreeColormap إنشاء خطأ BadColor.

الهياكل

يحتوي الهيكل XColor على:

typedef struct {
        unsigned long pixel;    /* قيمة البكسل */
        unsigned short red, green, blue;        /* قيم RGB */
        char flags;     /* DoRed, DoGreen, DoBlue */
        char pad;
} XColor;

تكون قيم red و green و blue دائمًا في النطاق من 0 إلى 65535 شاملة، بغض النظر عن عدد البتات المستخدمة فعليًا في عتاد العرض. يقوم الخادم بتغيير حجم هذه القيم إلى النطاق المستخدم بواسطة العتاد. يتم تمثيل الأسود بـ (0,0,0)، والأبيض بـ (65535,65535,65535). في بعض الوظائف، يتحكم العضو flags في أي من الأعضاء red أو green أو blue سيتم استخدامه ويمكن أن يكون OR شامل لأي من DoRed أو DoGreen أو DoBlue أو صفر منها.

التشخيص

BadAlloc
فشل الخادم في تخصيص المورد المطلوب أو ذاكرة الخادم.
BadColor
قيمة لمعامل Colormap لا تشير إلى خريطة ألوان محددة.
BadMatch
تم استخدام نافذة InputOnly كـ Drawable.
BadMatch
بعض المعاملات أو أزواج المعاملات لها النوع والنطاق الصحيحين ولكنها تفشل في المطابقة بطريقة أخرى تتطلبها الطلب.
BadValue
تقع قيمة رقمية ما خارج نطاق القيم التي يقبلها الطلب. ما لم يتم تحديد نطاق معين لمعامل، يتم قبول النطاق الكامل الذي يحدده نوع المعامل. يمكن لأي معامل تم تحديده كمجموعة من البدائل إنشاء هذا الخطأ.
BadWindow
قيمة لمعامل Window لا تشير إلى نافذة محددة.

XCreateColormap(3)

NAME

XCreateColormap - create a colormap

SYNOPSIS

Colormap XCreateColormap(Display *display, Drawable d, Visual *visual, int allocate);

DESCRIPTION

The XCreateColormap function creates a colormap. The colormap is associated with the specified screen of the specified display. The visual argument must match the visual type of the window or pixmap's drawable d. The allocate argument determines how the colormap cells are initially allocated.

AllocNone
No colormap entries are allocated. You must allocate entries explicitly using XAllocColor or XAllocNamedColor.
AllocAll
All colormap entries are allocated. The X server will allocate all entries in the colormap. You can then retrieve the actual RGB values of these entries using XQueryColor.

RETURN VALUE

Returns the created colormap ID.

DIAGNOSTICS

If the visual type of the drawable d does not match the visual argument, a BadMatch error is generated.
