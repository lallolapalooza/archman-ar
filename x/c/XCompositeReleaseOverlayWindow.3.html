XCompositeReleaseOverlayWindow(3)

الحزمة: libxcomposite

التراخيص: MIT, HPND-sell-variant

DESCRIPTION

The X Composite extension provides a mechanism for redirecting rendering operations of child windows. This allows applications such as compositing window managers to intercept drawing commands and perform additional processing, such as applying visual effects, before the drawing is displayed. The extension enables the creation of an off-screen buffer for a redirected window, allowing for manipulation of its contents before it is composed onto the screen. It also provides functionality for managing overlay windows, which can be used for special purposes like displaying notifications or cursors on top of the composited content.

Key features include:

  • Window redirection: Clients can request to redirect the drawing operations of specific child windows.
  • Off-screen pixmap creation: For redirected windows, an off-screen pixmap can be created to hold the window's contents.
  • Region clipping: The extension provides information about the clipped area of a window, considering its siblings and parent, which can be used to optimize rendering.
  • Overlay windows: Clients can obtain and manage special overlay windows that appear above the composited content, suitable for elements that need to be persistently visible.

The Composite extension is typically used by compositing window managers (e.g., Compiz, KWin, Mutter) to implement features like transparency, shadows, animations, and other visual effects.

FUNCTIONS

XCompositeRedirectWindow

XCompositeRedirectWindow requests the X server to redirect all rendering operations destined for window to a private off-screen pixmap. The update argument specifies how the update should be handled: if it is `CompositeUpdateRectangles`, the server will return a list of rectangles that have been updated within the window since the last call to this function. If `update` is `CompositeUpdateRegion`, the server will return a region that represents the clipped area of the window against siblings and the parent. This region can be used to restrict rendering to suitable areas while updating only a single window. The region is copied at the moment the request is executed; future changes to the window hierarchy will not be reflected in this region.

Generates a BadMatch error if window is not redirectable (e.g., it is a root window or it is already redirected).

The X server must support at least version 0.2 of the Composite Extension for XCompositeRedirectWindow.

XCompositeRedirectSubwindows

XCompositeRedirectSubwindows requests the X server to redirect all rendering operations destined for the children of window to private off-screen pixmaps. This is similar to XCompositeRedirectWindow but applies to all subwindows of the specified window. The update argument works the same way as for XCompositeRedirectWindow.

Generates a BadMatch error if window is not redirectable.

The X server must support at least version 0.2 of the Composite Extension for XCompositeRedirectSubwindows.

XCompositeUnredirectWindow

XCompositeUnredirectWindow undoes the effect of XCompositeRedirectWindow. Rendering operations for window will no longer be redirected. If update is `CompositeUpdateRegion`, the region is copied at the moment the request is executed; future changes to the window hierarchy will not be reflected in this region.

Generates a BadMatch error if window is not redirected.

The X server must support at least version 0.2 of the Composite Extension for XCompositeUnredirectWindow.

XCompositeUnredirectSubwindows

XCompositeUnredirectSubwindows undoes the effect of XCompositeRedirectSubwindows. Rendering operations for the children of window will no longer be redirected. If update is `CompositeUpdateRegion`, the region is copied at the moment the request is executed; future changes to the window hierarchy will not be reflected in this region.

Generates a BadMatch error if any of the subwindows of window are not redirected.

The X server must support at least version 0.2 of the Composite Extension for XCompositeUnredirectSubwindows.

XCompositeGetWindowAttributes

XCompositeGetWindowAttributes retrieves the attributes of a redirected window. It returns a pointer to a XCompositeWindowAttributes structure containing information such as whether the window is redirected and the format of its backing pixmap. The returned structure should be freed by the caller using XFree.

Generates a BadMatch error if window is not redirected.

The X server must support at least version 0.2 of the Composite Extension for XCompositeGetWindowAttributes.

XCompositeQueryExtension

XCompositeQueryExtension checks if the Composite extension is available on the server and returns its event and error base opcodes. It takes a display pointer and pointers to integers where the event and error bases will be stored. It returns `True` if the extension is present, `False` otherwise.

XCompositeQueryVersion

XCompositeQueryVersion queries the version of the Composite extension supported by the server. It takes the display pointer and pointers to integers for the major and minor version numbers to be returned. It returns `True` if the server supports the extension, `False` otherwise.

XCompositeGetPfx

XCompositeGetPfx returns a pixmap id that represents the off-screen storage for window. This pixmap will remain allocated until freed, even if the window is unmapped, reconfigured or destroyed. However, the window will get a new pixmap allocated each time it is mapped or resized, so this function will need to be reinvoked for the client to continue to refer to the storage holding the current window contents. Generates a BadMatch error if window is not redirected or is not visible.

The X server must support at least version 0.2 of the Composite Extension for XCompositeGetPfx.

XCompositeNameWindow

XCompositeNameWindow associates a pixmap with the given window. This pixmap can then be used as the off-screen storage for the window. The pixmap must be created with the correct attributes, matching the window's attributes. This function is useful for clients that want to manage their own off-screen buffers. Generates a BadMatch error if window is not redirected.

The X server must support at least version 0.2 of the Composite Extension for XCompositeNameWindow.

XCompositeGetClipBox

XCompositeGetClipBox returns the clip box for the specified window. This is the area of the window clipped against siblings and the parent. This region can be used to restrict rendering to suitable areas while updating only a single window. The region is copied at the moment the request is executed; future changes to the window hierarchy will not be reflected in this region.

XCompositeNameWindowPixmap

XCompositeNameWindowPixmap creates and returns a pixmap id that serves as a reference to the off-screen storage for window. This pixmap will remain allocated until freed, even if the window is unmapped, reconfigured or destroyed. However, the window will get a new pixmap allocated each time it is mapped or resized, so this function will need to be reinvoked for the client to continue to refer to the storage holding the current window contents. Generates a BadMatch error if window is not redirected or is not visible.

The X server must support at least version 0.2 of the Composite Extension for XCompositeNameWindowPixmap.

XCompositeGetOverlayWindow

XCompositeGetOverlayWindow returns the window ID of the Composite Overlay Window for the screen specified by the argument window. This function notifies the X server that the client wishes to use the Composite Overlay Window of this screen. If this Composite Overlay Window has not yet been mapped, it is mapped by this request.

The Composite Overlay Window for a particular screen will be unmapped when all clients who have called this function have either called XCompositeReleaseOverlayWindow for that screen, or terminated their connection to the X server.

The X server must support at least version 0.3 of the Composite Extension for XCompositeGetOverlayWindow.

XCompositeReleaseOverlayWindow

This request specifies that the client is no longer using the Composite Overlay Window on the screen specified by the argument window. A screen's Composite Overlay Window is unmapped when there are no longer any clients using it.

The X server must support at least version 0.3 of the Composite Extension for XCompositeReleaseOverlayWindow.
