الوصف

يوفر امتداد composite عدة آليات مترابطة:

تخزين لكل هرمية

يتم إعادة توجيه عرض هرمية كاملة من النوافذ إلى تخزين خارج الشاشة. تكون بكسلات تلك الهرمية متاحة كلما أمكن عرضها. يتم إعادة تخصيص التخزين تلقائيًا عند تغيير حجم النافذة العليا. لا يتم الاحتفاظ بالمحتويات التي تتجاوز هندسة النافذة العليا.

تحديث الظل تلقائيًا

عند عرض هرمية خارج الشاشة، يوفر خادم X آلية تلقائية لعرض تلك المحتويات داخل النافذة الأم. التطبيق حر في جعل هذا التحديث يتأخر عن عمليات العرض الفعلية بمقدار زمني غير محدد. يمكن تعطيل آلية التحديث التلقائي هذه بحيث يمكن تحديد محتويات النافذة الأم بالكامل بواسطة تطبيق خارجي.

نافذة التراكب المركب

يضيف الإصدار 0.3 من البروتوكول نافذة التراكب المركب، والتي توفر لمديري التراكيب سطحًا للرسم عليه دون تدخل. تكون هذه النافذة دائمًا فوق النوافذ العادية ودائمًا تحت نافذة شاشة التوقف. إنها نافذة InputOutput بعرض وارتفاع أبعاد الشاشة. صورتها هي صورة الجذر وعرض حدودها صفر. يتم تجاهل محاولات إعادة توجيهها باستخدام امتداد composite. لا تظهر هذه النافذة في رد طلب QueryTree. إنها أيضًا نافذة override redirect. تجعل هاتان الميزتان الأخيرتان غير مرئية لمديري النوافذ وعملاء X11 الآخرين. الطريقة الوحيدة للوصول إلى XID لهذه النافذة هي عبر طلب CompositeGetOverlayWindow. في البداية، تكون نافذة التراكب المركب غير مرئية.

قص النافذة الأم

يعدل الإصدار 0.4 من البروتوكول دلالات قص النافذة الأم في وجود نوافذ فرعية معاد توجيهها يدويًا. مع هذا الإصدار، تُترك المنطقة في النافذة الأم التي تغطيها النوافذ الفرعية المعاد توجيهها يدويًا في قائمة قص النافذة الأم بدلاً من إزالتها كما في الإصدارات القديمة.

يمكن إنشاء تخزين لكل هرمية لنوافذ فردية أو لجميع النوافذ الفرعية لنافذة. يمكن اختيار تحديث الظل يدويًا بواسطة عميل واحد فقط لكل نافذة؛ يمكن أيضًا اختيار التحديث اليدوي على أساس كل نافذة أو لكل نافذة فرعية لنافذة. يمكن اكتشاف وقت التحديث باستخدام امتداد Damage.

يشمل التخزين خارج الشاشة محتويات النافذة، وحدودها، ومحتويات جميع النوافذ الفرعية.

الوسائط

display

مؤشر إلى هيكل Display الذي تم إرجاعه من XOpenDisplay للاتصال بخادم X.

event_base_return

مؤشر إلى عدد صحيح سيتم تخزين القيمة الأساسية لأحداث امتداد Composite فيها.

error_base_return

مؤشر إلى عدد صحيح سيتم تخزين القيمة الأساسية لأخطاء امتداد Composite فيها.

major_version_return

مؤشر إلى عدد صحيح سيتم تخزين إصدار امتداد Composite الرئيسي المدعوم من قبل خادم X فيه.

minor_version_return

مؤشر إلى عدد صحيح سيتم تخزين إصدار امتداد Composite الثانوي المدعوم من قبل خادم X فيه.

window

يحدد معرف النافذة للعمل عليه.

update

يحدد وضع تحديث محتويات النافذة. يجب أن يكون إما CompositeRedirectAutomatic أو CompositeRedirectManual.

الوظائف

XCompositeQueryExtension

XCompositeQueryExtension تحدد ما إذا كان امتداد Composite متاحًا على الشاشة المحددة. تُرجع True إذا كان الامتداد مدعومًا، وإلا تُرجع False. إذا كان الامتداد موجودًا، يتم إرجاع القيم الأساسية للأحداث والأخطاء، ويمكن استخدامها لفك تشفير قيم الأحداث والأخطاء الواردة.

XCompositeQueryVersion

XCompositeQueryVersion تحدد ما إذا كان خادم X يدعم إصدارًا من امتداد X Composite متوافقًا مع مكتبة العميل. يتم إرجاع قيمة Status غير صفرية إذا كان إصدار متوافق من الامتداد مدعومًا، وإلا يتم إرجاع قيمة Status صفرية. إذا كان الامتداد مدعومًا، يتم إرجاع أرقام الإصدار الرئيسية والثانوية للإشارة إلى مستوى دعم امتداد Composite. لا يجوز استدعاء وظائف XComposite الأخرى (باستثناء XCompositeQueryExtension) قبل هذه الوظيفة. إذا انتهك عميل هذه القاعدة، فإن تأثير جميع استدعاءات XComposite اللاحقة التي يقوم بها يكون غير محدد.

XCompositeVersion

XCompositeVersion تُرجع إصدار مكتبة X Composite. يتم ترميز رقم الإصدار على النحو التالي: (major * 10000) + (minor * 100) + revision

على سبيل المثال، سيتم ترميز الإصدار 1.4.6 كرقم صحيح 10406.

XCompositeRedirectWindow

XCompositeRedirectWindow يطلب من خادم X توجيه الهرمية التي تبدأ عند window إلى تخزين خارج الشاشة. يحدد الوسيط update ما إذا كانت المحتويات تُنسخ إلى النافذة الأم تلقائيًا أم لا. يمكن لعميل واحد فقط في كل مرة تحديد نوع تحديث CompositeRedirectManual، وسيؤدي محاولة أخرى إلى خطأ BadAccess. عند انتهاء جميع العملاء الذين يقومون بتمكين إعادة التوجيه، سيتم تعطيل إعادة التوجيه تلقائيًا.

لا يمكن إعادة توجيه النافذة الجذر. يؤدي القيام بذلك إلى خطأ BadMatch. سيؤدي تحديد معرف نافذة غير صالح إلى خطأ BadWindow.

XCompositeRedirectSubwindows

XCompositeRedirectSubwindows يطلب من خادم X إعادة توجيه الهرميات التي تبدأ عند جميع النوافذ الفرعية الحالية والمستقبلية لـ window كما في XCompositeRedirectWindow. إذا كان update هو CompositeRedirectManual، فسيتم تثبيط رسم خلفية النافذة أثناء معالجة النافذة وطلبات ClearArea.

XCompositeUnredirectWindow

XCompositeUnredirectWindow يطلب من خادم X إنهاء إعادة توجيه window. إذا لم يتم تحديد النافذة المحددة لإعادة التوجيه بواسطة العميل الحالي، فستحدث خطأ BadValue.

XCompositeUnredirectSubwindows

XCompositeUnredirectWindow يطلب من خادم X إنهاء إعادة توجيه جميع النوافذ الفرعية لـ window. إذا لم يتم تحديد النافذة المحددة لإعادة التوجيه الفرعية بواسطة العميل الحالي، فستحدث خطأ BadValue.

XCompositeCreateRegionFromBorderClip

XCompositeCreateRegionFromBorderClip ينشئ منطقة تحتوي على الإطار "المعتاد".

NAME

XCompositeNameWindowPixmap, XCompositeGetOverlayWindow, XCompositeReleaseOverlayWindow - composite extension

SYNOPSIS

#include <X11/extensions/Xcomposite.h>

unsigned long XCompositeNameWindowPixmap (Display *dpy, Window win);

Window XCompositeGetOverlayWindow (Display *dpy, Window win);

void XCompositeReleaseOverlayWindow (Display *dpy, Window win);

DESCRIPTION

The Composite extension allows clients to redirect portions of their windows to off-screen pixmaps. This allows applications to draw directly to off-screen buffers and have those buffers composited onto the screen by a separate compositing manager.

The following functions are available:

  • XCompositeRedirectWindow
  • XCompositeRedirectSubwindow
  • XCompositeUnredirectWindow
  • XCompositeUnredirectSubwindow
  • XCompositeGetClientWindown
  • XCompositeGetOverlayWindow
  • XCompositeReleaseOverlayWindow
  • XCompositeNameWindowPixmap

When a window is redirected, the X server intercepts all drawing operations that would normally be performed on the window and instead directs them to an off-screen pixmap. A compositing manager can then take this pixmap and composite it onto the screen along with other windows.

The following functions are provided to manage the redirection of windows:

XCompositeRedirectWindow

XCompositeRedirectWindow requests that the X server redirect all subsequent rendering operations directed to win to an off-screen pixmap. The X server automatically creates this pixmap. The pixmap is accessible via XCompositeNameWindowPixmap. If win is already redirected, XCompositeRedirectWindow will generate a BadMatch error. If win is not visible, it will also generate a BadMatch error. The update argument specifies whether the redirection should include updates to the window's contents that are currently off-screen. Setting update to CompositeRedirectManual disables automatic updates, and the client must explicitly request updates by calling XCompositeUpdateWindow. Setting update to CompositeRedirectAutomatic enables automatic updates. The client should explicitly unredirect the window using XCompositeUnredirectWindow when it no longer needs to redirect the window.

The X server must support at least version 0.2 of the Composite Extension for XCompositeRedirectWindow.

XCompositeRedirectSubwindow

XCompositeRedirectSubwindow redirects the specified subwindow. This is useful for redirecting only specific subwindows of a larger window. The arguments are otherwise the same as for XCompositeRedirectWindow.

The X server must support at least version 0.3 of the Composite Extension for XCompositeRedirectSubwindow.

XCompositeUnredirectWindow

XCompositeUnredirectWindow informs the X server that the client no longer wishes to redirect win. The X server will stop redirecting the window and will resume normal drawing operations. The update argument should match the value used when the window was redirected. If win is not redirected, XCompositeUnredirectWindow will generate a BadMatch error.

The X server must support at least version 0.2 of the Composite Extension for XCompositeUnredirectWindow.

XCompositeUnredirectSubwindow

XCompositeUnredirectSubwindow unredirects the specified subwindow. The arguments are otherwise the same as for XCompositeUnredirectWindow.

The X server must support at least version 0.3 of the Composite Extension for XCompositeUnredirectSubwindow.

XCompositeGetClientWindown

XCompositeGetClientWindown retrieves the window that the client should use to render into when the target window win is redirected. This is the off-screen pixmap created by the X server when the window was redirected. If the window is not redirected, or if the Composite extension is not supported, this function will return 0.

The X server must support at least version 0.2 of the Composite Extension for XCompositeGetClientWindown.

XCompositeGetOverlayWindow

XCompositeGetOverlayWindow returns the window ID of the Composite Overlay Window for the screen specified by the argument window. This function notifies the X server that the client wishes to use the Composite Overlay Window of this screen. If this Composite Overlay Window has not yet been mapped, it is mapped by this request.

The Composite Overlay Window for a particular screen will be unmapped when all clients who have called this function have either called XCompositeReleaseOverlayWindow for that screen, or terminated their connection to the X server.

The X server must support at least version 0.3 of the Composite Extension for XCompositeGetOverlayWindow.

XCompositeReleaseOverlayWindow

This request specifies that the client is no longer using the Composite Overlay Window on the screen specified by the argument window. A screen's Composite Overlay Window is unmapped when there are no longer any clients using it.

The X server must support at least version 0.3 of the Composite Extension for XCompositeReleaseOverlayWindow.

XCompositeNameWindowPixmap

XCompositeNameWindowPixmap creates and returns a pixmap id that serves as a reference to the off-screen storage for window. This pixmap will remain allocated until freed, even if the window is unmapped, reconfigured or destroyed. However, the window will get a new pixmap allocated each time it is mapped or resized, so this function will need to be reinvoked for the client to continue to refer to the storage holding the current window contents. Generates a BadMatch error if window is not redirected or is not visible.

The X server must support at least version 0.2 of the Composite Extension for XCompositeNameWindowPixmap.

ARGUMENTS

Display *dpy
Specifies the connection to the X server.
Window win
Specifies the window or subwindow.
CompositeRedirect update
Specifies how updates should be handled.

FUNCTIONS

XCompositeRedirectWindow
Redirects drawing operations to an off-screen pixmap.
XCompositeRedirectSubwindow
Redirects drawing operations for a subwindow to an off-screen pixmap.
XCompositeUnredirectWindow
Stops redirecting drawing operations for a window.
XCompositeUnredirectSubwindow
Stops redirecting drawing operations for a subwindow.
XCompositeGetClientWindown
Retrieves the off-screen pixmap for a redirected window.
XCompositeGetOverlayWindow
Retrieves the overlay window for a screen.
XCompositeReleaseOverlayWindow
Releases the overlay window for a screen.
XCompositeNameWindowPixmap
Returns the pixmap ID of the off-screen storage for a redirected window.
