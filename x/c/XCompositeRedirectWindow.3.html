الوصف

يوفر امتداد composite عدة آليات ذات صلة:

تخزين لكل تسلسل هرمي

يتم إعادة توجيه عرض تسلسل هرمي كامل من النوافذ إلى تخزين خارج الشاشة. تكون وحدات البكسل لهذا التسلسل الهرمي متاحة كلما كان مرئيًا. يتم إعادة تخصيص التخزين تلقائيًا عند تغيير حجم النافذة العلوية. لا يتم الاحتفاظ بالمحتويات التي تتجاوز هندسة النافذة العلوية.

تحديث ظل تلقائي

عند عرض تسلسل هرمي خارج الشاشة، يوفر خادم X آلية تلقائية لعرض هذه المحتويات داخل النافذة الأم. تنفيذ حر لجعل هذا التحديث يتأخر عن عمليات العرض الفعلية بمقدار غير محدد من الوقت. يمكن تعطيل آلية التحديث التلقائي هذه بحيث يمكن تحديد محتويات النافذة الأم بالكامل بواسطة تطبيق خارجي.

نافذة التراكب المركب

يضيف الإصدار 0.3 من البروتوكول نافذة التراكب المركب، والتي توفر لمديري التركيب سطحًا للرسم عليه دون تدخل. تكون هذه النافذة دائمًا فوق النوافذ العادية ودائمًا تحت نافذة توفير الشاشة. إنها نافذة InputOutput بعرض وارتفاع يساويان أبعاد الشاشة. مرئيها هو المرئي الجذري وعرض حدودها صفر. يتم تجاهل محاولات إعادة توجيهها باستخدام امتداد التركيب. هذه النافذة لا تظهر في رد طلب QueryTree. وهي أيضًا نافذة تجاوز إعادة التوجيه. هذان الميزتان الأخيرتان تجعلانها غير مرئية لمديري النوافذ وعملاء X11 الآخرين. الطريقة الوحيدة للوصول إلى XID هذه النافذة هي عبر طلب CompositeGetOverlayWindow. في البداية، تكون نافذة التراكب المركب غير مرئية.

اقتصاص النافذة الأم

يعدل الإصدار 0.4 من البروتوكول دلالات اقتصاص النافذة الأم في وجود أطفال تم إعادة توجيههم يدويًا. مع هذا الإصدار، يتم ترك المنطقة في الأم التي تغطيها النوافذ الفرعية المعاد توجيهها يدويًا في قائمة قص الأم بدلاً من إزالتها كما في الإصدارات الأقدم.

يمكن إنشاء تخزين لكل تسلسل هرمي لنوافذ فردية أو لجميع النوافذ الفرعية للنافذة. يمكن اختيار التحديث اليدوي بواسطة عميل واحد فقط لكل نافذة؛ يمكن أيضًا اختيار التحديث اليدوي على أساس كل نافذة أو لكل نافذة فرعية للنافذة. يمكن اكتشاف وقت التحديث باستخدام امتداد الضرر.

يتضمن التخزين خارج الشاشة محتويات النافذة وحدودها ومحتويات جميع الأحفاد.

الوسائط

display

مؤشر إلى بنية Display تم إرجاعه من XOpenDisplay للاتصال بخادم X.

event_base_return

مؤشر إلى عدد صحيح حيث سيتم تخزين القيمة الأساسية لأحداث امتداد التركيب.

error_base_return

مؤشر إلى عدد صحيح حيث سيتم تخزين القيمة الأساسية لأخطاء امتداد التركيب.

major_version_return

مؤشر إلى عدد صحيح حيث سيتم تخزين الإصدار الرئيسي لامتداد التركيب الذي يدعمه خادم X.

minor_version_return

مؤشر إلى عدد صحيح حيث سيتم تخزين الإصدار الثانوي لامتداد التركيب الذي يدعمه خادم X.

window

يحدد معرف النافذة للعمل عليه.

update

يحدد وضع تحديث محتويات النافذة. يجب أن يكون إما CompositeRedirectAutomatic أو CompositeRedirectManual.

الوظائف

XCompositeQueryExtension

XCompositeQueryExtension يحدد ما إذا كان امتداد التركيب متاحًا على العرض المحدد. يقوم بإرجاع True إذا كان الامتداد مدعومًا، وإلا False. إذا كان الامتداد موجودًا، يتم إرجاع القيم الأساسية للأحداث والأخطاء، ويمكن استخدامها لفك تشفير قيم الأحداث والأخطاء الواردة.

XCompositeQueryVersion

XCompositeQueryVersion يحدد ما إذا كان خادم X يدعم إصدارًا من امتداد X Composite متوافقًا مع مكتبة العميل. يتم إرجاع قيمة Status غير صفرية إذا كان إصدار متوافق من الامتداد مدعومًا، وإلا يتم إرجاع قيمة Status صفرية. إذا كان الامتداد مدعومًا، يتم إرجاع أرقام الإصدار الرئيسي والثانوي للإشارة إلى مستوى دعم امتداد التركيب. لا يمكن استدعاء وظائف XComposite الأخرى (باستثناء XCompositeQueryExtension) قبل هذه الوظيفة. إذا انتهك العميل هذه القاعدة، فإن آثار جميع استدعاءات XComposite اللاحقة التي يقوم بها غير محددة.

XCompositeVersion

XCompositeVersion يقوم بإرجاع إصدار مكتبة X Composite. يتم ترميز رقم الإصدار على النحو التالي: (major * 10000) + (minor * 100) + revision

على سبيل المثال، سيتم ترميز الإصدار 1.4.6 كرقم صحيح 10406.

XCompositeRedirectWindow

XCompositeRedirectWindow يطلب من خادم X توجيه التسلسل الهرمي الذي يبدأ في window إلى تخزين خارج الشاشة. تحدد الوسيطة update ما إذا كانت المحتويات تعكس في النافذة الأم تلقائيًا أم لا. يمكن لعميل واحد فقط في كل مرة تحديد نوع تحديث CompositeRedirectManual، وستؤدي محاولة أخرى إلى خطأ BadAccess. عندما تنتهي صلاحية جميع العملاء الذين يمكّنون إعادة التوجيه، سيتم تعطيل إعادة التوجيه تلقائيًا.

لا يمكن إعادة توجيه النافذة الجذرية. القيام بذلك يؤدي إلى خطأ BadMatch. تحديد معرف نافذة غير صالح سيؤدي إلى خطأ BadWindow.

XCompositeRedirectSubwindows

XCompositeRedirectSubwindows يطلب من خادم X إعادة توجيه التسلسلات الهرمية التي تبدأ في جميع النوافذ الفرعية الحالية والمستقبلية لـ window كما في XCompositeRedirectWindow. إذا كانت update هي CompositeRedirectManual، فسيتم منع رسم خلفية النافذة أثناء معالجة النافذة وطلبات ClearArea.

XCompositeUnredirectWindow

XCompositeUnredirectWindow يطلب من خادم X إنهاء إعادة توجيه window. إذا لم يتم تحديد النافذة المحددة لإعادة التوجيه بواسطة العميل الحالي، فستكون النتيجة خطأ BadValue.

XCompositeUnredirectSubwindows

XCompositeUnredirectWindow يطلب من خادم X إنهاء إعادة توجيه جميع النوافذ الفرعية لـ window. إذا لم يتم تحديد النافذة المحددة لإعادة التوجيه الفرعي بواسطة العميل الحالي، فستكون النتيجة خطأ BadValue.

DESCRIPTION

\n

The Composite extension provides a mechanism for redirecting window contents to off-screen pixmaps, allowing for effects like transparency, shadows, and complex window decorations. It allows clients to intercept drawing operations on a window and composite them onto other windows or pixmaps.

\n

Redirection can be applied to individual windows using XCompositeRedirectWindow and XCompositeRedirectSubwindow, or to entire subtrees using the latter. When a window is redirected, all drawing operations to it are instead sent to an off-screen pixmap managed by the server. The client can then retrieve this pixmap, perform compositing operations, and draw the result back onto the screen or another window.

\n

XCompositeUnredirectWindow and XCompositeUnredirectSubwindow disable this redirection.

\n

XCompositeGetCapability retrieves the maximum supported version of the Composite extension. It returns a status indicating success or failure, and fills in major_version_return and minor_version_return with the version numbers.

\n

XCompositeQueryExtension checks if the Composite extension is available on the server. If it is, it returns the base event and error codes for the extension and fills in event_base_return and error_base_return.

\n

XCompositeGetWindowAttributes retrieves attributes of a redirected window. The ret_attributes structure will be filled with information such as the serial number of the redirection request, the mask of valid values, and input filter settings.

\n

XCompositeNameWindowPixmap creates a pixmap that serves as a reference to the off-screen storage for the specified window. This pixmap can be used to access the window's contents after redirection. The pixmap remains allocated until explicitly freed, but the window may get a new pixmap if remapped or resized, requiring the function to be called again.

\n

XCompositeGetOverlayWindow returns the window ID of the Composite Overlay Window for a given screen. This window is used for special compositing tasks. If it hasn't been mapped yet, this request maps it. It remains mapped as long as at least one client is using it.

\n

XCompositeReleaseOverlayWindow notifies the server that the client is no longer using the Composite Overlay Window for the specified screen. The overlay window will be unmapped when no clients are using it anymore.

FUNCTIONS

\n

XCompositeRedirectWindow, XCompositeRedirectSubwindow

\n
\n

These functions redirect drawing operations on the specified window. XCompositeRedirectSubwindow also redirects drawing on all subwindows of window. The update_kind argument specifies how the redirection should be handled. If the redirection is successful, the server will intercept drawing operations and send them to an off-screen pixmap. A return value of 0 indicates success, while a non-zero value indicates failure. A BadMatch error is generated if the window is not redirectable, if the extension is not supported, or if the specified update_kind is invalid.

\n
\n

XCompositeUnredirectWindow, XCompositeUnredirectSubwindow

\n
\n

These functions disable redirection previously set up by XCompositeRedirectWindow or XCompositeRedirectSubwindow, respectively. The return value is 0 on success and non-zero on failure. A BadMatch error is generated if the window is not currently redirected or if the extension is not supported.

\n
\n

XCompositeGetCapability

\n
\n

This function retrieves the maximum supported version of the Composite extension. It returns Success on success and 0 on failure. The major_version_return and minor_version_return arguments are filled with the major and minor version numbers, respectively.

\n

The X server must support at least version 0.2 of the Composite Extension for this function to succeed.

\n
\n

XCompositeQueryExtension

\n
\n

This function checks if the Composite extension is available on the server. If it is available, it returns Success and fills in event_base_return and error_base_return with the base event and error codes for the extension. If the extension is not available, it returns 0.

\n
\n

XCompositeGetWindowAttributes

\n
\n

This function retrieves attributes associated with a redirected window. The ret_attributes structure is filled with the following information:

\n
\n
serial_number
\n
The serial number of the redirection request.
\n
value_mask
\n
A mask indicating which fields in valid_values are valid.
\n
input_filter_mask
\n
Specifies which input events should be passed through to the redirected window. This value is only valid if the CompositeInputFilter bit is set in value_mask.
\n
valid_values
\n
Contains the actual values for the fields indicated by value_mask.
\n
unused
\n
Reserved for future use.
\n
\n

A return value of Success indicates that the attributes were retrieved successfully. A return value of 0 indicates failure. A BadMatch error is generated if the window is not redirected or if the extension is not supported.

\n

The input_filter_mask field can be used to specify which events should be delivered to the redirected window. By default, all events are delivered. This can be used to filter out events that are not relevant to the redirected window.

\n

The value_mask indicates which fields in the valid_values structure are valid. This is useful when only a subset of attributes needs to be specified.

\n

The region returned by XCompositeGetClipRectangles (not shown here, but related) defines the area of the window that is currently visible and needs to be rendered. This clipping region is known as the "clip value"; that is the area of the window clipped against siblings and the parent. This region can be used to restrict rendering to suitable areas while updating only a single window. The region is copied at the moment the request is executed; future changes to the window hierarchy will not be reflected in this region.

\n
\n

XCompositeNameWindowPixmap

\n
\n

XCompositeNameWindowPixmap creates and returns a pixmap id that serves as a reference to the off-screen storage for window. This pixmap will remain allocated until freed, even if the window is unmapped, reconfigured or destroyed. However, the window will get a new pixmap allocated each time it is mapped or resized, so this function will need to be reinvoked for the client to continue to refer to the storage holding the current window contents. Generates a BadMatch error if window is not redirected or is not visible.

\n

The X server must support at least version 0.2 of the Composite Extension for XCompositeNameWindowPixmap.

\n
\n

XCompositeGetOverlayWindow

\n
\n

XCompositeGetOverlayWindow returns the window ID of the Composite Overlay Window for the screen specified by the argument window. This function notifies the X server that the client wishes to use the Composite Overlay Window of this screen. If this Composite Overlay Window has not yet been mapped, it is mapped by this request.

\n

The Composite Overlay Window for a particular screen will be unmapped when all clients who have called this function have either called XCompositeReleaseOverlayWindow for that screen, or terminated their connection to the X server.

\n

The X server must support at least version 0.3 of the Composite Extension for XCompositeGetOverlayWindow.

\n
\n

XCompositeReleaseOverlayWindow

\n
This request specifies that the client is no longer using the Composite Overlay Window on the screen specified by the argument window. A screen's Composite Overlay Window is unmapped when there are no longer any clients using it.

The X server must support at least version 0.3 of the Composite Extension for XCompositeReleaseOverlayWindow.
