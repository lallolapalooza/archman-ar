XftDraw

هو كائن غير شفاف يحتفظ بالمعلومات المستخدمة للعرض على عنصر قابل للرسم X باستخدام البروتوكول الأساسي أو امتداد X Rendering.

يتم إنشاء كائنات XftDraw باستخدام أي من XftDrawCreate() (التي تربط XftDraw بعنصر قابل للرسم X موجود)، أو XftDrawCreateBitmap()، أو XftDrawCreateAlpha()، ويتم تدميرها باستخدام XftDrawDestroy(). يمكن تغيير عنصر الرسم X المرتبط بـ XftDraw باستخدام XftDrawChange(). يتم تخصيص كائنات XftDraw وتحريرها داخليًا بواسطة Xft؛ لا يحتاج المبرمج عادةً إلى تخصيص أو تحرير مساحة تخزين لها.

يمكن الاستعلام عن خصائص X Display، و Drawable، و Colormap، و Visual الخاصة بـ XftDraw باستخدام XftDrawDisplay()، و XftDrawDrawable()، و XftDrawColormap()، و XftDrawVisual()، على التوالي.

تستخدم العديد من الدوال كائنات XftDraw: XftDrawCharFontSpec()، و XftDrawCharSpec()، و XftDrawGlyphFontSpec()، و XftDrawGlyphSpec()، و XftDrawGlyphs()، و XftDrawRect()، و XftDrawSetClip()، و XftDrawSetClipRectangles()، و XftDrawSetSubwindowMode()، وعائلة XftDrawString*().

يتم إرجاع امتداد X Rendering Picture المرتبط بـ XftDraw بواسطة XftDrawPicture() و XftDrawSrcPicture(). يتم استخدامه بواسطة XftCharFontSpecRender()، و XftCharSpecRender()، و XftGlyphFontSpecRender()، و XftGlyphRender()، و XftGlyphSpecRender()، وعائلة XftTextRender*().

الوظائف

التهيئة

التطبيق النموذجي الذي يستخدم Xft لا يقوم بتهيئة المكتبة بشكل صريح. يتم ذلك عادةً كنتيجة ثانوية لفتح خط.

عندما تقوم Xft بالتهيئة، فإنها تجمع معلومات حول العرض، وتخزن بعض تلك المعلومات في نمط Fontconfig (وهو في الأساس مجموعة من الخصائص ذات القيم المكتوبة. يمكن للتطبيق المستدعي تعديل هذا النمط لتغيير سلوك المكتبة.

لا يتم تخزين كل المعلومات المجمعة في نمط. يتم تخزين الباقي في هياكل بيانات داخلية. تجعل Xft بعضًا من ذلك متاحًا للتطبيق عبر الدوال.

Bool XftDefaultHasRender (
	Display	*dpy);

الحصول على معلومات حول العرض dpy إذا لم يتم ذلك بالفعل، وإرجاع صحيح إذا وجدت Xft أن العرض يدعم امتداد X Render، وإذا تمكنت من العثور على XRenderPictFormat مناسب (نوع بيانات X Render الذي يشبه Visual الخاص بـ Xlib) على العرض.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

الحصول على معلومات حول العرض dpy إذا لم يتم ذلك بالفعل، وتعيين نمط Fontconfig الذي يحتوي على الخصائص الافتراضية التي ستستخدمها Xft لهذا العرض.

تستخدم Xft تلك الخصائص مبدئيًا للحصول على هذه الحدود:
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). هذا هو الحد الأقصى لذاكرة الحروف لجميع الخطوط التي تستخدمها Xft (الافتراضي: 4*1024*1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). هذا هو الحد الأقصى لعدد الخطوط غير المشار إليها (الافتراضي: 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). عند التفعيل، تتتبع Xft استخدام ذاكرة الحروف لتحسين الأداء عند اتخاذ قرار بشأن ما يجب إلغاؤه عند الوصول إلى الحد الأقصى لذاكرة الحروف (الافتراضي: false).
تستخدم Xft أيضًا هذه الخصائص الافتراضية في XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

تقوم Xft بملء الخصائص المفقودة في pattern المعطى باستخدام الخصائص الافتراضية للعرض dpy المحدد، مثل تلك التي تم تعيينها في XftDefaultSet().

تستخدم تطبيقات Xft النموذجية هذه الدالة للمساعدة في اختيار Fontconfig لخط مناسب. يتم استبدال هذه الخصائص قبل استدعاء FcDefaultSubstitute():
FC_ANTIALIAS
صحيح إذا كان يجب على FreeType استخدام التنعيم (الافتراضي: False). (الافتراضي: True).
FC_AUTOHINT
صحيح إذا كان يجب على FreeType استخدام التلميحات التلقائية (الافتراضي: False).
FC_DPI
نقاط/بوصة مستخدمة للدقة (الافتراضي: محسوبة من ارتفاع العرض).
FC_EMBOLDEN
صحيح إذا كان يجب استخدام FT_GlyphSlot_Embolden() لتكثيف الخط (الافتراضي: False).
FC_HINTING
صحيح إذا كان يجب استخدام التلميحات عند ملء الخصائص لفتح خط (الافتراضي: True).
FC_HINT_STYLE
أسلوب التلميح المستخدم عند ملء الخصائص لفتح خط (الافتراضي: FC_HINT_FULL).
FC_LCD_FILTER
المعلمة التي تم تمريرها إلى FT_Library_SetLcdFilter() عند تحميل الحروف (الافتراضي: FC_LCD_DEFAULT).
FC_MINSPACE
قيمة المسافة الدنيا المستخدمة عند ملء الخصائص لفتح خط (الافتراضي: False).
FC_RGBA
قيمة RGBA المستخدمة عند ملء الخصائص لفتح خط (الافتراضي: محسوبة عن طريق استدعاء XRenderQuerySubpixelOrder()).
FC_SCALE
المقياس المستخدم في Fontconfig (الافتراضي: 1.0).
XFT_MAX_GLYPH_MEMORY
الحد الأقصى للذاكرة لخط واحد (الافتراضي: 1024*1024).
XFT_RENDER
صحيح إذا كان العرض يدعم امتداد X Render (الافتراضي: نتيجة من XftDefaultHasRender()).

Xft provides several functions for determining the required
    height and width for displaying a text-string. After accounting for the
    offset, in cases where the string will be shifted up, down, left or
    right, these numbers are referred to as text extents.

Bool XftColorAllocName (

  

    
	Display	*dpy,
	_Xconst Visual	*visual,
	Colormap	 cmap,
	_Xconst char	*name,
	XftColor	*result);


    
Use XAllocNamedColor() to look up the named color
        name for the screen associated with the colormap cmap.

  






    
  
  • If XAllocNamedColor() returns nonzero, XftColorAllocName()
      fills in the resulting XftColor pixel field with the closest color
      supported by the screen, as well as the exact red, green and blue fields
      from the database, and returns True.
    • 
  
  • If XAllocNamedColor() returns zero, XftColorAllocName()
      returns False, and does not update the XftColor referenced by
      result.
    • 






  

  
The visual parameter is unused.





  
Bool XftColorAllocValue (

  

    
	Display	*dpy,
	Visual	*visual,
	Colormap	 cmap,
	_Xconst XRenderColor	*color,
	XftColor	*result);


    
Allocate a color value:

  






    
  
  • If the visual class is TrueColor, XftColorAllocValue() sets
      the pixel field in the XftColor referenced by result
      using the red, green and blue fields from the color parameter.
    • 
  
  • If the visual class is not TrueColor, XftColorAllocValue()
      calls XAllocColor() to allocate an entry in the colormap
      cmap. which returns the pixel value of the color closest to the
      specified RGB elements supported by the hardware.
    • 




  

  
If XAllocColor() succeeds XftColorAllocValue() stores that
      pixel value in the XRenderColor referenced by result and
      returns True.

  

  
If XAllocColor() fails, XftColorAllocValue() returns False
      and does not modify the result.
