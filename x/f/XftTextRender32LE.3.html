XftTextRender32LE(3)

الحزمة: libxft

التراخيص: HPND-sell-variant

DESCRIPTION

XftDraw

هو كائن مبهم يحتفظ بالمعلومات المستخدمة للعرض على رسم X باستخدام بروتوكول أساسي أو امتداد X Rendering.

يتم إنشاء كائنات XftDraw باستخدام أي من
XftDrawCreate() (التي تربط XftDraw برسم X موجود)، أو XftDrawCreateBitmap()، أو XftDrawCreateAlpha()، ويتم تدميرها باستخدام XftDrawDestroy(). يمكن تغيير رسم X المرتبط بـ XftDraw باستخدام XftDrawChange(). يتم تخصيص كائنات XftDraw وتحريرها داخليًا بواسطة Xft؛ ولا يحتاج المبرمج عادةً إلى تخصيص أو تحرير مساحة لها.

يمكن الاستعلام عن خصائص X Display و Drawable و Colormap و Visual الخاصة بـ XftDraw باستخدام
XftDrawDisplay() و XftDrawDrawable() و XftDrawColormap() و XftDrawVisual() على التوالي.

تستخدم العديد من الدوال كائنات XftDraw:
XftDrawCharFontSpec() و XftDrawCharSpec() و
XftDrawGlyphFontSpec() و XftDrawGlyphSpec() و
XftDrawGlyphs() و XftDrawRect() و XftDrawSetClip() و
XftDrawSetClipRectangles() و XftDrawSetSubwindowMode() وعائلة XftDrawString*().

صورة امتداد X Rendering (Picture) المرتبطة بـ XftDraw يتم إرجاعها بواسطة
XftDrawPicture() و XftDrawSrcPicture(). وهي تستخدم بواسطة
XftCharFontSpecRender() و XftCharSpecRender() و
XftGlyphFontSpecRender() و XftGlyphRender() و XftGlyphSpecRender() وعائلة XftTextRender*().

Functions

Initialization

عادةً لا يقوم التطبيق النموذجي الذي يستخدم Xft بتهيئة المكتبة بشكل صريح. يتم ذلك عادةً كتأثير جانبي لفتح خط.

عند تهيئة Xft، يقوم بجمع معلومات حول الشاشة، ويخزن بعض هذه المعلومات في نمط Fontconfig (وهو في الأساس مجموعة من الخصائص ذات القيم المسماة. يمكن للتطبيق المتصل تعديل هذا النمط لتغيير سلوك المكتبة.

لا يتم تخزين كل المعلومات التي تم جمعها في نمط. يتم تخزين الباقي في هياكل بيانات داخلية. يوفر Xft بعض هذه المعلومات للتطبيق عبر الدوال.

Bool XftDefaultHasRender (
	Display	*dpy);

احصل على معلومات حول الشاشة dpy إذا لم يتم ذلك بالفعل، وأرجع true إذا اكتشف Xft أن الشاشة تدعم امتداد X Render، وإذا كان قادرًا على العثور على XRenderPictFormat مناسب (نوع بيانات X Render الذي يشبه Visual في Xlib) على الشاشة.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

احصل على معلومات حول الشاشة dpy إذا لم يتم ذلك بالفعل، واضبط نمط Fontconfig الذي يحتوي على الخصائص الافتراضية التي ستستخدمها Xft لهذه الشاشة.

تستخدم Xft هذه الخصائص مبدئيًا للحصول على هذه الحدود:
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). هذا هو الحد الأقصى لذاكرة الرموز لجميع الخطوط التي تستخدمها Xft (افتراضي: 4 * 1024 * 1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). هذا هو الحد الأقصى لعدد الخطوط غير المشار إليها (افتراضي: 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). عند التعيين على true، يتتبع Xft استخدام ذاكرة الرموز لتحسين الأداء عند تحديد ما يجب إلغاء تحميله عند الوصول إلى الحد الأقصى لذاكرة الرموز (افتراضي: false).
تستخدم Xft أيضًا هذه الخصائص الافتراضية في XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

يقوم Xft بملء الخصائص المفقودة في pattern المحدد باستخدام الخصائص الافتراضية للشاشة المحددة dpy، على سبيل المثال، كما تم تعيينها في XftDefaultSet().

تستخدم تطبيقات Xft النموذجية هذه الدالة للمساعدة في اختيار Fontconfig لخط مناسب. يتم استبدال هذه الخصائص قبل استدعاء FcDefaultSubstitute():
FC_ANTIALIAS
True إذا كان FreeType يجب أن يستخدم تنعيم الحواف (افتراضي: False). (افتراضي: True).
FC_AUTOHINT
True إذا كان FreeType يجب أن يستخدم الإشارة التلقائية (افتراضي: False).
FC_DPI
النقاط/البوصة المستخدمة للدقة (افتراضي: محسوبة من ارتفاع الشاشة).
FC_EMBOLDEN
True إذا كان يجب استخدام FT_GlyphSlot_Embolden() لتغميق خط (افتراضي: False).
FC_HINTING
True إذا كان يجب استخدام الإشارة عند ملء الخصائص لفتح خط (افتراضي: True).
FC_HINT_STYLE
نمط الإشارة المستخدم عند ملء الخصائص لفتح خط (افتراضي: FC_HINT_FULL).
FC_LCD_FILTER
المعلمة التي تم تمريرها إلى FT_Library_SetLcdFilter() عند تحميل الرموز (افتراضي: FC_LCD_DEFAULT).
FC_MINSPACE
الحد الأدنى لمساحة المسافة المستخدمة عند ملء الخصائص لفتح خط (افتراضي: False).
FC_RGBA

FC_SCALE
المقياس المستخدم في Fontconfig (افتراضي: 1.0).
XFT_MAX_GLYPH_MEMORY
الحد الأقصى للذاكرة لخط واحد (افتراضي: 1024 * 1024).
XFT_RENDER
True إذا كانت الشاشة تدعم امتداد X Render (افتراضي: نتيجة من XftDefaultHasRender()).

Opening and Matching Fonts



  
XftFont *XftFontOpen (

  

    
	Display	*dpy,
	int	 screen,
	...);


    
تأخذ XftFontOpen قائمة من ثلاثيات عناصر النمط بالشكل field، type، value (تنتهي بـ NULL)، تطابق هذا النمط مع الخطوط المتاحة، وتفتح الخط المطابق، وتضبط حجمه بشكل صحيح للشاشة رقم screen على الشاشة dpy. ترجع الخط المطابق، أو NULL إذا لم يتم العثور على تطابق.

  




مثال:
  




    font = XftFontOpen (dpy, screen,
                        XFT_FAMILY, XftTypeString, "charter",
                        XFT_SIZE, XftTypeDouble, 12.0,
                        NULL);




  

  
يفتح هذا خط "charter" بحجم 12 نقطة. يتم تحويل حجم النقطة تلقائيًا إلى حجم البكسل الصحيح بناءً على دقة الشاشة.

إدارة XftColor



  
Bool XftColorAllocName (

  

    
	Display	*dpy,
	_Xconst Visual	*visual,
	Colormap	 cmap,
	_Xconst char	*name,
	XftColor	*result);


    
استخدم XAllocNamedColor() للبحث عن اللون المسمى
        name للشاشة المرتبطة بخريطة الألوان cmap.

  






    
  
  • إذا أعادت XAllocNamedColor() قيمة غير صفرية، فإن XftColorAllocName()
      تقوم بملء حقل البكسل الناتج لـ XftColor بأقرب لون تدعمه الشاشة،
      بالإضافة إلى حقول الأحمر والأخضر والأزرق الدقيقة من قاعدة البيانات، وتعيد True.
    • 
  
  • إذا أعادت XAllocNamedColor() صفرًا، فإن XftColorAllocName()
      تعيد False، ولا تقوم بتحديث XftColor المشار إليها بواسطة
      result.
    • 






  

  
المعلمة visual غير مستخدمة.





  
Bool XftColorAllocValue (

  

    
	Display	*dpy,
	Visual	*visual,
	Colormap	 cmap,
	_Xconst XRenderColor	*color,
	XftColor	*result);


    
تخصيص قيمة لون:

  






    
  
  • إذا كان فئة visual هي TrueColor، فإن XftColorAllocValue()
      تعين حقل pixel في XftColor المشار إليها بواسطة result
      باستخدام حقول الأحمر والأخضر والأزرق من المعلمة color.
    • 
  
  • إذا لم تكن فئة visual هي TrueColor، فإن XftColorAllocValue()
      تستدعي XAllocColor() لتخصيص إدخال في خريطة الألوان cmap.
      والتي تعيد قيمة البكسل لأقرب لون للعناصر RGB المحددة المدعومة بواسطة
      الأجهزة.
    • 




  

  
إذا نجحت XAllocColor()، فإن XftColorAllocValue() تخزن
      قيمة البكسل هذه في XRenderColor المشار إليها بواسطة result
      وتعيد True.

  

  
إذا فشلت XAllocColor()، فإن XftColorAllocValue() تعيد False
      ولا تعدل النتيجة.

void XftDrawGlyphFontSpec (
\n  
\n    
\tXftDraw	*draw,\n\t_Xconst XftColor	*color,\n\t_Xconst XftGlyphFontSpec	*glyphs,\n\tint	 len);\n
\n    
Draw a list of glyphs associated with fonts at specified\n        coordinates, passed as an array of len XftGlyphFontSpec\n        structures via the parameter glyphs. All of the glyphs are drawn\n        using the color specified in the color parameter.
\n  
\n
\n
\n  
\n  
For each entry in the glyphs array:
\n
\n
\n
    \n  
  • If the associated font uses the X Render extension, then Xft uses\n      XftGlyphFontSpecRender() to draw the glyph, using a Picture\n      obtained from calling XftDrawSrcPicture () with the draw and\n      color parameters.
    • \n  
  • Otherwise, Xft provides an analogous feature using Xlib.
    • \n
\n
\n
\n  
void XftGlyphFontSpecRender (
\n  
\n    
\tDisplay	*dpy,\n\tint	 op,\n\tPicture	 src,\n\tPicture	 dst,\n\tint	 srcx,\n\tint	 srcy,\n\t_Xconst XftGlyphFontSpec	*glyphs,\n\tint	 nglyphs);\n
\n    
This involves several steps:
\n  
\n
\n
\n
    \n  
  • First, Xft ensures that the glyphs array is complete using\n      XftFontCheckGlyph() and loading any missing glyphs with\n      XftFontLoadGlyphs().
    • \n  
  • Then Xft examines the glyphs to find the maximum Unicode value.\n      That determines the encoding size, i.e., the width.
    • \n  
  • Then, for each glyph, Xft checks if its Unicode value is handled by\n      the corresponding font. If not, the value is set to zero (0), to ignore\n      it. While doing this, Xft also remembers which was the first font\n      used, and computes the position at which each glyph will be drawn.
    • \n  
  • Xft then constructs an equivalent array of glyphs in the format\n      expected by the X Render library.
    • \n  
  • Finally, XftGlyphFontSpecRender() uses the X Render extension to\n      draw the glyphs, with the appropriate XRenderCompositeText*()\n      function according to the width, and discards temporary data.
    • \n
\n
\n  
\n  
The op, dst, src, srcx, and srcy\n      parameters are used as described in the documentation for the X Render\n      library.

\tXftDraw	*draw,\n\t_Xconst XftColor	*color,\n\t_Xconst XftGlyphFontSpec	*glyphs,\n\tint	 len);\n
\n    
Draw a list of glyphs associated with fonts at specified\n        coordinates, passed as an array of len XftGlyphFontSpec\n        structures via the parameter glyphs. All of the glyphs are drawn\n        using the color specified in the color parameter.
\n  
\n
\n
\n  
\n  
For each entry in the glyphs array:
\n
\n
\n
    \n  
  • If the associated font uses the X Render extension, then Xft uses\n      XftGlyphFontSpecRender() to draw the glyph, using a Picture\n      obtained from calling XftDrawSrcPicture () with the draw and\n      color parameters.
    • \n  
  • Otherwise, Xft provides an analogous feature using Xlib.
    • \n
\n
\n
\n  
void XftGlyphFontSpecRender (
\n  
\n    
\tDisplay	*dpy,\n\tint	 op,\n\tPicture	 src,\n\tPicture	 dst,\n\tint	 srcx,\n\tint	 srcy,\n\t_Xconst XftGlyphFontSpec	*glyphs,\n\tint	 nglyphs);\n
\n    
This involves several steps:
\n  
\n
\n
\n
    \n  
  • First, Xft ensures that the glyphs array is complete using\n      XftFontCheckGlyph() and loading any missing glyphs with\n      XftFontLoadGlyphs().
    • \n  
  • Then Xft examines the glyphs to find the maximum Unicode value.\n      That determines the encoding size, i.e., the width.
    • \n  
  • Then, for each glyph, Xft checks if its Unicode value is handled by\n      the corresponding font. If not, the value is set to zero (0), to ignore\n      it. While doing this, Xft also remembers which was the first font\n      used, and computes the position at which each glyph will be drawn.
    • \n  
  • Xft then constructs an equivalent array of glyphs in the format\n      expected by the X Render library.
    • \n  
  • Finally, XftGlyphFontSpecRender() uses the X Render extension to\n      draw the glyphs, with the appropriate XRenderCompositeText*()\n      function according to the width, and discards temporary data.
    • \n
\n
\n  
\n  
The op, dst, src, srcx, and srcy\n      parameters are used as described in the documentation for the X Render\n      library.
\n
\n
\n

التوافق


اعتبارًا من الإصدار 2 (مايو 2002)، أصبح Xft مستقرًا نسبيًا.
    من المتوقع أن يحتفظ بالتوافق في المصدر والثنائي في الإصدارات المستقبلية.


يوفر Xft واجهة توافق لإصداره الرئيسي السابق، Xft 1.x،
    الموصوف أدناه.




ملف رأس Xft 1.x


#include <X11/Xft/XftCompat.h>






أنواع بيانات Xft 1.x



  
XftPattern

  
يحتوي على مجموعة من الأسماء مع قوائم قيم مرتبطة؛ يشير كل اسم إلى خاصية
      لخط. تستخدم XftPattern كمدخلات لرمز المطابقة بالإضافة إلى الاحتفاظ
      بمعلومات حول خطوط محددة.

  
XftFontSet

  
يحتوي على قائمة XftPattern. داخليًا، يستخدم Xft هيكل البيانات
      هذا للاحتفاظ بمجموعات من الخطوط. خارجيًا، يعيد Xft نتائج سرد
      الخطوط بهذا التنسيق.

  
XftObjectSet

  
يحتوي على مجموعة من الأسماء ويستخدم لتحديد الحقول التي يتم وضعها من الخطوط
      في قائمة الأنماط المعادة عند سرد الخطوط.
