XftFontInfoEqual(3)

الحزمة: libxft

التراخيص: HPND-sell-variant

Xft(3) إصدار X 11 Xft(3)

الاسم

Xft - مكتبة واجهة X FreeType

الملخص

#include <X11/Xft/Xft.h>

الوصف

Xft هي مكتبة بسيطة تقوم برسم النصوص والرسومات:

  • باستخدام المعلومات المقدمة من مكتبة Fontconfig،
  • يقوم Xft بتحويل رموز الخطوط باستخدام مولد الخطوط FreeType، و
  • يعرض بيانات الخط المحولة باستخدام امتداد X للتقديم.

هذه الصفحة الدليلية لا تكاد تلامس سطح هذه المكتبة.

الثوابت

XFT_MAJOR
هو رقم الإصدار الرئيسي لـ Xft.
XFT_MINOR
هو رقم الإصدار الثانوي لـ Xft.
XFT_REVISION
هو رقم المراجعة لـ Xft.
XFT_VERSION
هو XFT_MAJOR مضروبًا في 10000 (عشرة آلاف)، زائد XFT_MINOR مضروبًا في 100، زائد XFT_REVISION.
XftVersion
هو اسم مستعار لـ XFT_VERSION.

يوضح المثال التالي كيف يمكن استخدام ثوابت إصدار Xft: 

    #if (XFT_VERSION >= 20107)
    (void) puts("الإصدار 2.1.7 أو أحدث من مكتبة Xft قيد الاستخدام.");
    #else
    (void) printf("إصدار غير كافٍ من Xft (%d.%d.%d) مثبت؛
                  " نحتاج إلى إصدار 2.1.7 على الأقل.\n", XFT_MAJOR,
                  XFT_MINOR,
                  XFT_REVISION);
    #endif

أنواع البيانات

تتبع أنواع بيانات Xft اتفاقية تسمية، حيث تسبق جميع الأسماء بـ "Xft"

من Xlib...

لا تتبع أنواع بيانات Xlib اتفاقية تسمية. تم توثيقها في Xlib - واجهة لغة C.

يستخدم Xft هذه الأسماء: Bool، Colormap، Display، Drawable، Pixmap، Region، Visual، و XRectangle.

بعض أنواع البيانات ذات صلة خاصة بـ Xft:

Drawable
معلن في <X11/X.h>، هذا هو معرف مورد X، على سبيل المثال، نافذة مرتبطة بالشاشة. يمكن استخدام كل من النوافذ والـ pixmaps كمصادر ووجهات في عمليات الرسومات. تُعرف هذه النوافذ والـ pixmaps بشكل جماعي باسم drawables. ومع ذلك، لا يمكن استخدام نافذة InputOnly كمصدر أو وجهة في عملية رسومات.
Region
معلن في <X11/Xutil.h> و <X11/Xregion.h>، Region هو مجموعة عشوائية من مواقع البكسل التي يمكن لـ Xlib معالجتها. داخليًا، يتم تمثيل Region باتحاد عدد عشوائي من المستطيلات. تحتفظ Xlib بمستطيل يحدد نطاق هذا الاتحاد.
Visual
معلن في <X11/Xutil.h>، يحتوي هذا الهيكل على معلومات حول تعيين الألوان المحتمل.

من XRender...

مكتبة امتداد X للتقديم مستوحاة من Xlib، ولكنها تفتقر إلى الوثائق المقابلة. راجع ملف الرأس للحصول على التفاصيل:

<X11/extensions/Xrender.h>

أو اقرأ الكود المصدري (الذي يوفر مخططًا لمكتبة libXrender).

يستخدم Xft هذه الأسماء: Picture، XGlyphInfo، XRenderColor.

من Fontconfig...

تتبع أنواع بيانات Fontconfig اتفاقية تسمية، حيث تسبق جميع الأسماء بـ "Fc" وهي موثقة في Fontconfig Developers Reference.

يستخدم Xft هذه الأسماء من Fontconfig: FcBool، FcChar8، FcChar16، FcChar32، FcCharSet، FcEndian، FcFontSet، FcPattern، و FcResult.

من FreeType 2...

تتبع أنواع بيانات FreeType 2 اتفاقية تسمية، حيث تسبق جميع الأسماء بـ "FT_" وهي موثقة في FreeType API Reference.

يستخدم Xft هذه الأسماء: FT_Face، FT_Library، و FT_UInt.

يستخدم FreeType 2 FT_UInt (عدد صحيح غير موقع) لتمثيل رموز الخطوط (glyphs).

XftFont


typedef struct _XftFont {
	int	 ascent;
	int	 descent;
	int	 height;
	int	 max_advance_width;
	FcCharSet	*charset;
	FcPattern	*pattern;
} XftFont;

XftFont هو هيكل البيانات الأساسي الذي يهم المبرمجين الذين يستخدمون Xft؛ فهو يحتوي على مقاييس الخط العامة ومؤشرات إلى مجموعة أحرف Fontconfig والنمط المرتبط بالخط.

يتم ملء XftFonts باستخدام أي من الدوال XftFontOpen()، XftFontOpenName()، XftFontOpenXlfd()، XftFontOpenInfo()، أو XftFontOpenPattern(). تُستخدم XftFontCopy() لنسخ XftFonts، وتُستخدم XftFontClose() لوضع علامة على XftFont بأنه غير مستخدم. يتم تخصيص XftFonts داخليًا، وإدارة عدد المراجع، وتحريرها بواسطة Xft؛ لا يحتاج المبرمج عادةً إلى تخصيص أو تحرير مساحة تخزين لها.

تستخدم الدوال XftDrawGlyphs()، عائلة الدوال XftDrawString*()، XftDrawCharSpec()، و XftDrawGlyphSpec() XftFonts لرسم النص إلى كائن XftDraw، والذي قد يتوافق مع كائن قابل للرسم أساسي في X أو كائن قابل للرسومات من امتداد X للتقديم.

تُستخدم XftGlyphExtents() وعائلة الدوال XftTextExtents*() لتحديد أبعاد (الحد الأقصى للأبعاد) لـ XftFont.

يمكن تحديد تغطية رموز الخطوط أو الأحرف الخاصة بـ XftFont باستخدام XftFontCheckGlyph() أو XftCharExists(). تُرجع XftCharIndex() فهرس الحرف الخاص بـ XftFont المقابل لنقطة رمز Unicode معينة.

تستخدم الدوال XftGlyphRender()، XftGlyphSpecRender()، XftCharSpecRender()، وعائلة الدوال XftTextRender*() XftFonts للرسم في هياكل Picture الخاصة بامتداد X للتقديم.

ملاحظة: توفر الدوال XftDrawGlyphs()، وعائلة الدوال XftDrawString*()، XftDrawCharSpec()، و XftDrawGlyphSpec() وسيلة لرسم الخطوط مستقلة عن توفر امتداد X للتقديم على خادم X.

XftFontInfo

هو كائن غير شفاف يخزن معلومات حول الخط. يتم إنشاء هياكل XftFontInfo باستخدام XftFontInfoCreate()، وتحريرها باستخدام XftFontInfoDestroy()، ومقارنتها باستخدام XftFontInfoEqual(). يتم تخصيص الكائنات XftFontInfo داخليًا وتحريرها بواسطة Xft؛ لا يحتاج المبرمج عادةً إلى تخصيص أو تحرير مساحة تخزين لها.

كل هيكل XftFontInfo قيد الاستخدام مرتبط بمعرف فريد، والذي يمكن استرجاعه باستخدام XftFontInfoHash(). يمكن فتح XftFont بناءً على بيانات XftFontInfo باستخدام XftFontOpenInfo().

XftColor


typedef struct _XftColor {
	unsigned long	 pixel;
	XRenderColor	 color;
} XftColor;

يسمح كائن XftColor برسم النصوص والعناصر الأخرى بلون معين (أو أقرب تقريب تقدمه رؤية X المستخدمة).

تقوم الدوال XftColorAllocName() و XftColorAllocValue() بطلب تخصيص لون من خادم X (إذا لزم الأمر) وتهيئة أعضاء XftColor. تطلب الدالة XftColorFree() من خادم X تحرير اللون المخصص حاليًا لـ XftColor.

بمجرد تهيئة XftColor، يمكن استخدام الدوال XftDrawSrcPicture()، XftDrawGlyphs()، عائلة الدوال XftDrawString*()، XftDrawCharSpec()، XftDrawCharFontSpec()، XftDrawGlyphSpec()، XftDrawGlyphFontSpec()، و XftDrawRect() لرسم كائنات مختلفة باستخدام

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

XftDraw

هو كائن غير شفاف يحتوي على معلومات تستخدم للرسم على كائن قابل للرسم في X باستخدام البروتوكول الأساسي أو امتداد X Rendering.

يتم إنشاء كائنات XftDraw باستخدام أي من الدوال التالية: XftDrawCreate() (التي تربط XftDraw بكائن قابل للرسم موجود في X)، XftDrawCreateBitmap()، أو XftDrawCreateAlpha()، ويتم تدميرها باستخدام XftDrawDestroy(). يمكن تغيير كائن X القابل للرسم المرتبط بـ XftDraw باستخدام XftDrawChange(). يتم تخصيص وتحرير كائنات XftDraw داخليًا بواسطة Xft؛ لا يحتاج المبرمج عادةً إلى تخصيص أو تحرير مساحة تخزين لها.

يمكن الاستعلام عن خصائص X Display، Drawable، Colormap، و Visual لكائن XftDraw باستخدام XftDrawDisplay()، XftDrawDrawable()، XftDrawColormap()، و XftDrawVisual() على التوالي.

تستخدم العديد من الدوال كائنات XftDraw: XftDrawCharFontSpec()، XftDrawCharSpec()، XftDrawGlyphFontSpec()، XftDrawGlyphSpec()، XftDrawGlyphs()، XftDrawRect()، XftDrawSetClip()، XftDrawSetClipRectangles()، XftDrawSetSubwindowMode()، وعائلة XftDrawString*().

يتم إرجاع امتداد X Rendering Picture المرتبط بـ XftDraw بواسطة XftDrawPicture() و XftDrawSrcPicture(). يتم استخدامه بواسطة XftCharFontSpecRender()، XftCharSpecRender()، XftGlyphFontSpecRender()، XftGlyphRender()، XftGlyphSpecRender()، وعائلة XftTextRender*().

الوظائف

التهيئة

التطبيق النموذجي الذي يستخدم Xft لا يقوم بتهيئة المكتبة بشكل صريح. يتم ذلك عادةً كنتيجة ثانوية لفتح خط.

عندما تقوم Xft بالتهيئة، فإنها تجمع معلومات حول العرض، وتخزن بعض تلك المعلومات في نمط Fontconfig (وهو في الأساس مجموعة من الخصائص ذات القيم المسماة). يمكن للتطبيق المتصل تعديل هذا النمط لتغيير سلوك المكتبة.

لا يتم تخزين كل المعلومات المجمعة في نمط. يتم تخزين الباقي في هياكل بيانات داخلية. تجعل Xft بعضًا منها متاحًا للتطبيق عبر وظائف.

Bool XftDefaultHasRender (
	Display	*dpy);

الحصول على معلومات حول العرض dpy إذا لم يتم ذلك بالفعل، وإرجاع صحيح إذا وجدت Xft أن العرض يدعم امتداد X Render، وإذا كان قادرًا على العثور على XRenderPictFormat مناسب (نوع بيانات X Render الذي يشبه Visual في Xlib) على العرض.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

الحصول على معلومات حول العرض dpy إذا لم يتم ذلك بالفعل، وتعيين نمط Fontconfig الذي يحتوي على الخصائص الافتراضية التي ستستخدمها Xft لهذا العرض.

تستخدم Xft هذه الخصائص مبدئيًا للحصول على هذه الحدود:
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). هذا هو الحد الأقصى لذاكرة الخطوط لجميع الخطوط التي تستخدمها Xft (الافتراضي: 4*1024*1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). هذا هو الحد الأقصى لعدد الخطوط غير المشار إليها (الافتراضي: 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). عند التشغيل (true)، تتتبع Xft استخدام ذاكرة الخطوط لتحسين الأداء عند اتخاذ قرار بشأن ما يجب إلغاء تحميله عند الوصول إلى الحد الأقصى لذاكرة الخطوط (الافتراضي: false).
تستخدم Xft أيضًا هذه الخصائص الافتراضية في XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

تقوم Xft بملء الخصائص المفقودة في pattern المحدد باستخدام الخصائص الافتراضية للعرض المحدد dpy، على سبيل المثال، كما تم تعيينه في XftDefaultSet().

DESCRIPTION


The XftDraw* functions provide a drawing interface to Xft.
    The basic idea is that one creates an XftDraw object, which abstracts
    an X drawable (an X window or a pixmap), and then uses the functions to draw
    strings or rectangles into it. The XftDraw object holds the X display,
    visual, and colormap for the drawable, along with an X Render Picture object
    if the X Render extension is available.

	Display	*dpy,
	Drawable	 drawable,
	Visual	*vis,
	Colormap	 cmap);


    
Creates an XftDraw object associated with the X
        drawable drawable on display dpy, using the visual vis
        and colormap cmap.

Bool XftDrawSetClip (

  

    
	XftDraw	*draw,
	Region	 r);


    
Set up clipping for the given XftDraw parameter
        draw starting with a Region:

  






    
  
  • If the Region parameter r is not null, Xft creates a
      new Region (to copy the parameter),
    • 
  
  • Xft destroys any existing clipping region.
    • 
  
  • Xft sets the clip_type for the draw parameter to
      XftClipTypeRegion if the r parameter was not null. Otherwise
      it sets the clip_type to XftClipTypeNone.
    • 
  
  • Finally, Xft updates clipping for existing objects, updates the
      clip_mask for its X Render Picture object and sets the
      clipping-mask in the graphic context (GC) associated with the
      XftDraw parameter.
    • 






  

  
XftDrawSetClip() returns True if no change was necessary, or
      if the operation succeeded. It returns False if it was unable to
      create the new Region().

void XftDrawSetSubwindowMode (

  

    
	XftDraw	*draw,
	int	 mode);


    
Sets the subwindow-mode for the given XftDraw parameter
        draw. The mode can be either ClipByChildren (the default),
        or IncludeInferiors:

  






    
  
  • For ClipByChildren, both source and destination windows are
      additionally clipped by all viewable InputOutput children.
    • 
  
  • For IncludeInferiors, neither source nor destination window is
      clipped by inferiors. This will result in including subwindow contents in
      the source and drawing through subwindow boundaries of the
    destination.
    • 






  

  
In addition to the subwindow-mode maintained by Xft, it updates the
      subwindow mode for any associated graphics context GC using
      XSetSubwindowMode() as well as for an X Render Picture using
      XRenderChangePicture().

void XftDrawGlyphFontSpec (

  

    
	XftDraw	*draw,
	_Xconst XftColor	*color,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 len);


    
Draw a list of glyphs associated with fonts at specified
        coordinates, passed as an array of len XftGlyphFontSpec
        structures via the parameter glyphs. All of the glyphs are drawn
        using the color specified in the color parameter.

  





  

  
For each entry in the glyphs array:






    
  
  • If the associated font uses the X Render extension, then Xft uses
      XftGlyphFontSpecRender() to draw the glyph, using a Picture
      obtained from calling XftDrawSrcPicture () with the draw and
      color parameters.
    • 
  
  • Otherwise, Xft provides an analogous feature using Xlib.
    • 






  
void XftGlyphFontSpecRender (

  

    
	Display	*dpy,
	int	 op,
	Picture	 src,
	Picture	 dst,
	int	 srcx,
	int	 srcy,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 nglyphs);


    
This involves several steps:

  






    
  
  • First, Xft ensures that the glyphs array is complete using
      XftFontCheckGlyph() and loading any missing glyphs with
      XftFontLoadGlyphs().
    • 
  
  • Then Xft examines the glyphs to find the maximum Unicode value.
      That determines the encoding size, i.e., the width.
    • 
  
  • Then, for each glyph, Xft checks if its Unicode value is handled by
      the corresponding font. If not, the value is set to zero (0), to ignore
      it. While doing this, Xft also remembers which was the first font
      used, and computes the position at which each glyph will be drawn.
    • 
  
  • Xft then constructs an equivalent array of glyphs in the format
      expected by the X Render library.
    • 
  
  • Finally, XftGlyphFontSpecRender() uses the X Render extension to
      draw the glyphs, with the appropriate XRenderCompositeText*()
      function according to the width, and discards temporary data.
    • 




  

  
The op, dst, src, srcx, and srcy
      parameters are used as described in the documentation for the X Render
      library.
