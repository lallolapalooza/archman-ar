XftDrawSetSubwindowMode(3)

الحزمة: libxft

التراخيص: HPND-sell-variant

Xft(3) إصدار X 11 Xft(3)

الاسم

Xft - مكتبة واجهة X FreeType

الملخص

#include <X11/Xft/Xft.h>

الوصف

Xft هي مكتبة بسيطة تقوم برسم النصوص والرسومات:

  • باستخدام المعلومات المقدمة من مكتبة Fontconfig،
  • Xft تحول حروف الخط باستخدام راسم الخطوط FreeType، و
  • تعرض بيانات الخط المحولة باستخدام امتداد X للرسم (X Rendering Extension).

صفحة الدليل هذه بالكاد تخدش سطح هذه المكتبة.

الثوابت

XFT_MAJOR
هو رقم الإصدار الرئيسي لـ Xft.
XFT_MINOR
هو رقم الإصدار الثانوي لـ Xft.
XFT_REVISION
هو رقم المراجعة لـ Xft.
XFT_VERSION
هو XFT_MAJOR مضروبًا في 10000 (عشرة آلاف)، زائد XFT_MINOR مضروبًا في 100، زائد XFT_REVISION.
XftVersion
هو اسم مستعار لـ XFT_VERSION.

يوضح المثال التالي كيف يمكن استخدام ثوابت إصدار Xft: 

    #if (XFT_VERSION >= 20107)
    (void) puts("الإصدار 2.1.7 أو أحدث من مكتبة Xft قيد الاستخدام.");
    #else
    (void) printf("إصدار غير كافٍ من Xft (%d.%d.%d) مثبت؛
                  " نحتاج إلى الإصدار 2.1.7 على الأقل.\n", XFT_MAJOR,
                  XFT_MINOR,
                  XFT_REVISION);
    #endif

أنواع البيانات

تتبع أنواع بيانات Xft اتفاقية تسمية، مسبوقة بـ "Xft"

من Xlib...

لا تتبع أنواع بيانات Xlib اتفاقية تسمية. يتم توثيقها في Xlib - واجهة لغة C.

تستخدم Xft هذه الأسماء: Bool، Colormap، Display، Drawable، Pixmap، Region، Visual، و XRectangle.

بعض أنواع البيانات ذات أهمية خاصة لـ Xft:

Drawable
معرّف في <X11/X.h>، وهو معرف مورد X، على سبيل المثال، نافذة مرتبطة بالعرض. يمكن استخدام كل من النوافذ والـ pixmaps كمصادر ووجهات في عمليات الرسومات. تُعرف هذه النوافذ والـ pixmaps بشكل جماعي باسم drawables. ومع ذلك، لا يمكن استخدام نافذة InputOnly كمصدر أو وجهة في عملية رسومات.
Region
معرّف في <X11/Xutil.h> و <X11/Xregion.h>، Region هو مجموعة عشوائية من مواقع البكسل التي يمكن لـ Xlib معالجتها. داخليًا، يتم تمثيل Region باتحاد عدد عشوائي من المستطيلات. تحتفظ Xlib بمستطيل يخبرنا بمدى هذا الاتحاد.
Visual
معرّف في <X11/Xutil.h>، يحتوي هذا الهيكل على معلومات حول تخطيط الألوان الممكن.

من XRender...

تستلهم أنواع بيانات مكتبة امتداد X للرسم (X Render Extension) من Xlib، ولكنها تفتقر إلى التوثيق المقابل. راجع ملف الرأس للحصول على التفاصيل:

<X11/extensions/Xrender.h>

أو اقرأ الكود المصدري (الذي يوفر مخططًا تفصيليًا لـ libXrender).

تستخدم Xft هذه الأسماء: Picture، XGlyphInfo، XRenderColor.

من Fontconfig...

تتبع أنواع بيانات Fontconfig اتفاقية تسمية، مسبوقة بـ "Fc" وهي موثقة في مرجع مطوري Fontconfig.

تستخدم Xft أسماء Fontconfig هذه: FcBool، FcChar8، FcChar16، FcChar32، FcCharSet، FcEndian، FcFontSet، FcPattern، و FcResult.

من FreeType 2...

تتبع أنواع بيانات FreeType 2 اتفاقية تسمية، مسبوقة بـ "FT_" وهي موثقة في مرجع واجهة برمجة تطبيقات FreeType.

تستخدم Xft هذه الأسماء: FT_Face، FT_Library، و FT_UInt.

يستخدم FreeType 2 FT_UInt (عدد صحيح غير موقّع) لتمثيل الحروف.

XftFont


typedef struct _XftFont {
	int	 ascent;
	int	 descent;
	int	 height;
	int	 max_advance_width;
	FcCharSet	*charset;
	FcPattern	*pattern;
} XftFont;

XftFont هو هيكل البيانات الأساسي الذي يهم المبرمجين الذين يستخدمون Xft؛ يحتوي على مقاييس خط عامة ومؤشرات إلى مجموعة أحرف Fontconfig والنمط المرتبطين بالخط.

يتم ملء XftFonts باستخدام أي من XftFontOpen()، XftFontOpenName()، XftFontOpenXlfd()، XftFontOpenInfo()، أو XftFontOpenPattern(). يتم استخدام XftFontCopy() لنسخ XftFonts، ويتم استخدام XftFontClose() لتمييز XftFont بأنه غير مستخدم. يتم تخصيص XftFonts داخليًا، وحساب مراجعها، وتحريرها بواسطة Xft؛ لا يحتاج المبرمج عادةً إلى تخصيص مساحة لها أو تحريرها.

تستخدم XftDrawGlyphs()، وعائلة XftDrawString*()، وXftDrawCharSpec()، وXftDrawGlyphSpec() XftFonts لرسم النصوص إلى كائن XftDraw، والذي قد يتوافق مع رسم X أساسي أو رسم امتداد X للرسم.

تُستخدم XftGlyphExtents() وعائلة XftTextExtents*() لتحديد امتدادات (أقصى أبعاد) XftFont.

يمكن تحديد تغطية الحروف أو الرموز لـ XftFont باستخدام XftFontCheckGlyph() أو XftCharExists(). تُرجع XftCharIndex() فهرس الحرف الخاص بـ XftFont المقابل لنقطة ترميز Unicode معينة.

تستخدم XftGlyphRender()، وXftGlyphSpecRender()، وXftCharSpecRender()، وعائلة XftTextRender*() XftFonts للرسم في هياكل Picture الخاصة بامتداد X للرسومات.

ملاحظة: توفر XftDrawGlyphs()، وعائلة XftDrawString*()، وXftDrawCharSpec()، وXftDrawGlyphSpec() وسيلة لرسم الخطوط مستقلة عن توفر امتداد X للرسومات على خادم X.

XftFontInfo

هو كائن غير شفاف يخزن معلومات حول خط. يتم إنشاء هياكل XftFontInfo باستخدام XftFontInfoCreate()، وتحريرها باستخدام XftFontInfoDestroy()، ومقارنتها باستخدام XftFontInfoEqual(). يتم تخصيص هياكل XftFontInfo داخليًا وتحريرها بواسطة Xft؛ لا يحتاج المبرمج عادةً إلى تخصيص مساحة لها أو تحريرها.

يرتبط كل هيكل XftFontInfo قيد الاستخدام بمعرف فريد، والذي يمكن استرداده باستخدام XftFontInfoHash(). يمكن فتح XftFont بناءً على بيانات XftFontInfo باستخدام XftFontOpenInfo().

XftColor


typedef struct _XftColor {
	unsigned long	 pixel;
	XRenderColor	 color;
} XftColor;

يسمح كائن XftColor برسم النصوص والعناصر الأخرى بلون معين (أو أقرب تقريب تقدمه نافذة X المستخدمة).

تقوم XftColorAllocName() و XftColorAllocValue() بطلب تخصيص لون من خادم X (إذا لزم الأمر) وتهيئة أعضاء XftColor. تطلب XftColorFree() من خادم X تحرير اللون المخصص حالياً لـ XftColor.

بمجرد تهيئة XftColor، يمكن استخدام XftDrawSrcPicture()، وXftDrawGlyphs()، وعائلة XftDrawString*()، وXftDrawCharSpec()، وXftDrawCharFontSpec()، وXftDrawGlyphSpec()، وXftDrawGlyphFontSpec()، وXftDrawRect() لرسم كائنات مختلفة

XFT_DRAWABLE_OBJECTS

XftDraw

هو كائن غير شفاف يحتوي على معلومات تُستخدم للعرض على رسم X باستخدام البروتوكول الأساسي أو امتداد X Rendering.

يتم إنشاء كائنات XftDraw باستخدام أي من الدالتين XftDrawCreate() (التي تربط XftDraw برسم X موجود) أو XftDrawCreateBitmap() أو XftDrawCreateAlpha()، ويتم تدميرها باستخدام XftDrawDestroy(). يمكن تغيير رسم X المرتبط بـ XftDraw باستخدام XftDrawChange(). يتم تخصيص كائنات XftDraw وتحريرها داخليًا بواسطة Xft؛ لا يحتاج المبرمج عادةً إلى تخصيص أو تحرير مساحة لها.

يمكن الاستعلام عن خصائص X Display و Drawable و Colormap و Visual لـ XftDraw باستخدام XftDrawDisplay() و XftDrawDrawable() و XftDrawColormap() و XftDrawVisual() على التوالي.

تستخدم العديد من الدوال كائنات XftDraw: XftDrawCharFontSpec() و XftDrawCharSpec() و XftDrawGlyphFontSpec() و XftDrawGlyphSpec() و XftDrawGlyphs() و XftDrawRect() و XftDrawSetClip() و XftDrawSetClipRectangles() و XftDrawSetSubwindowMode() وعائلة XftDrawString*().

يتم إرجاع امتداد X Rendering Picture المرتبط بـ XftDraw بواسطة XftDrawPicture() و XftDrawSrcPicture(). يتم استخدامه بواسطة XftCharFontSpecRender() و XftCharSpecRender() و XftGlyphFontSpecRender() و XftGlyphRender() و XftGlyphSpecRender() وعائلة XftTextRender*().

FUNCTIONS

Initialization

تطبيق نموذجي يستخدم Xft لا يقوم بتهيئة المكتبة بشكل صريح. يتم ذلك عادةً كأثر جانبي لفتح خط.

عندما تقوم Xft بالتهيئة، فإنها تجمع معلومات حول العرض، وتخزن بعضًا من تلك المعلومات في نمط Fontconfig (وهو في الأساس مجموعة من الخصائص ذات القيم المصنفة). يمكن للتطبيق المتصل تعديل هذا النمط لتغيير سلوك المكتبة.

لا يتم تخزين جميع المعلومات المجمعة في نمط. يتم تخزين الباقي في هياكل بيانات داخلية. توفر Xft بعضًا من ذلك للتطبيق عبر الدوال.

Bool XftDefaultHasRender (
	Display	*dpy);

احصل على معلومات حول العرض dpy إذا لم يتم ذلك بالفعل، وقم بإرجاع true إذا وجدت Xft أن العرض يدعم امتداد X Render، وإذا تمكن من العثور على XRenderPictFormat مناسب (نوع بيانات X Render الذي يماثل Visual في Xlib) على العرض.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

احصل على معلومات حول العرض dpy إذا لم يتم ذلك بالفعل، وقم بتعيين نمط Fontconfig الذي يحتوي على الخصائص الافتراضية التي ستستخدمها Xft لهذا العرض.

تستخدم Xft هذه الخصائص مبدئيًا للحصول على هذه الحدود:
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). هذا هو الحد الأقصى لذاكرة الرموز لجميع الخطوط المستخدمة بواسطة Xft (الافتراضي: 4 * 1024 * 1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). هذا هو الحد الأقصى لعدد الخطوط غير المشار إليها (الافتراضي: 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). عندما يكون صحيحًا، تقوم Xft بتتبع استخدام ذاكرة الرموز لتحسين الأداء عند تحديد الرموز التي يجب إلغاء تحميلها عندما يتم الوصول إلى الحد الأقصى لذاكرة الرموز (الافتراضي: false).
تستخدم Xft أيضًا هذه الخصائص الافتراضية في XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

تقوم Xft بملء الخصائص المفقودة في pattern المحدد باستخدام الخصائص الافتراضية للعرض المحدد dpy، على سبيل المثال، كما هو محدد في XftDefaultSet().

تستخدم تطبيقات Xft النموذجية هذه الدالة للمساعدة في اختيار Fontconfig لخط مناسب. يتم استبدال هذه الخصائص قبل استدعاء FcDefaultSubstitute():
FC_ANTIALIAS
صحيح إذا كان FreeType يجب أن يستخدم التنعيم (الافتراضي: False). (الافتراضي: True).
FC_AUTOHINT
صحيح إذا كان FreeType يجب أن يستخدم التلميح التلقائي (الافتراضي: False).
FC_DPI
نقاط/بوصة المستخدمة للدقة (الافتراضي: محسوبة من ارتفاع الشاشة).
FC_EMBOLDEN
صحيح إذا كان يجب استخدام FT_GlyphSlot_Embolden() لجعل الخط غامقًا (الافتراضي: False).
FC_HINTING
صحيح إذا كان يجب استخدام التلميح عند ملء الخصائص لفتح خط (الافتراضي: True).
FC_HINT_STYLE
أسلوب التلميح المستخدم عند ملء الخصائص لفتح خط (الافتراضي: FC_HINT_FULL).
FC_LCD_FILTER
معلمة تم تمريرها إلى FT_Library_SetLcdFilter() عند تحميل الرموز (الافتراضي: FC_LCD_DEFAULT).
FC_MINSPACE
الحد الأدنى لمساحة الحرف المستخدمة عند ملء الخصائص لفتح خط (الافتراضي: False).
FC_RGBA
قيمة RGBA المستخدمة عند ملء الخصائص لفتح خط (الافتراضي: محسوبة عن طريق استدعاء XRenderQuerySubpixelOrder()).
FC_SCALE
المقياس المستخدم في Fontconfig (الافتراضي: 1.0).
XFT_MAX_GLYPH_MEMORY
الحد الأقصى لذاكرة خط واحد (الافتراضي: 1024 * 1024).
XFT_RENDER
صحيح إذا كان العرض يدعم امتداد X Render (الافتراضي: نتيجة من XftDefaultHasRender()).

تأخذ XftFontOpen قائمة ثلاثيات عناصر النمط بالشكل field و type و value (تنتهي بـ NULL)، وتطابق هذا النمط مع الخطوط المتاحة، وتفتح الخط المطابق، وتضبط حجمه بشكل صحيح للشاشة رقم screen على العرض dpy. إرجاع الخط المطابق، أو NULL إذا لم يتم العثور على تطابق.

يفتح هذا خط “charter” بحجم 12 نقطة. يتم تحويل حجم النقطة تلقائيًا إلى حجم البكسل الصحيح بناءً على دقة الشاشة.

NAME


Xft - font rendering library







SYNOPSIS


#include <X11/Xft/Xft.h>








DESCRIPTION


Xft is a library for rendering fonts using the FreeType
    library. It provides a high-level API for opening, matching, and rendering
    fonts, and it integrates with the X Render extension for efficient drawing.


Xft is typically used in conjunction with Fontconfig, a
    font configuration library, to manage font discovery and matching.

        dpy. The result argument is set to the result of the
        operation (e.g., FcResultMatch, FcResultNoMatch,
        FcResultTypeMismatch).

Xft name parsing



  
FcBool XftNameParse (

  

    
	const char	*name,
	int	 len);


    
Xft uses Fontconfig to parse the name, passing the
        name to FcNameParse(), returning the result.

  

  
FcBool XftNameUnparse (

  

    
	FcPattern	*pat,
	char	*dest,
	int	 len);


    
Like XfgNameParse(), Xft uses Fontconfig. In
        this case, it uses FcNameUnparse(), which converts the pattern
        pat back into a string that can be parsed.
        XftNameUnparse() stores the result via the caller's pointer
        dest, but checks first if it will fit, using the len
        parameter. If it fits, Xft copies the string and returns
        FcTrue, otherwise it returns FcFalse.

  








Manipulating   Font data



  
void XftFontLoadGlyphs (

  

    
	Display	*dpy,
	XftFont	*pub,
	FcBool	 need_bitmaps,
	_Xconst FT_UInt	*glyphs,
	int	 nglyph);


    
Using FT_Load_Glyph(), load nglyphs for the
        glyph indices (Unicode values) listed in the array glyphs from
        the given font pub.

  





  

  
Loading a glyph entails more than just reading data into memory.
      Xft uses the Fontconfig pattern associated with the display
      dpy (e.g., via XftDefaultSet()) to determine whether to use
      a bounding box, clip the glyphs into those bounds, scale the glyphs,
      compute font metrics, and add it to the X Render extension using
      XRenderAddGlyphs().





  
void XftFontUnloadGlyphs (

  

    
	Display	*dpy,
	XftFont	*pub,
	_Xconst FT_UInt	*glyphs,
	int	 nglyph);


    
Discards data for up to nglyph glyphs whose glyph
        indices (Unicode values) are listed in the array glyphs for the
        given font pub. If the glyphs were added to the X Render
        extension, Xft removes those using XRenderFreeGlyphs().
        Xft keeps track of the amount of memory used for glyphs, and
        updates the usage associated with the display dpy.

  

  
FT_Face XftLockFace (

  

    
	XftFont	*pub);


    
If no FreeType 2 “face” (in-memory
        representation of a given typeface in a given style) has been created
        for the pub font, create one using FT_New_Face().
        Face-locks are a reference count used by Xft to ensure that only
        one face is created, and that it is retained until the font is no longer
        used.

  





  

  
Face-locking is used directly in XftCharIndex() and
      XftFontLoadGlyphs(), which in turn are used in many functions of
      Xft.

  

  
Face-locking was introduced in version 1 (October 2002). A few
      applications, such as Gdk/Gimp relied upon these functions. In version
      2.1.9 (June 2006), face-locking was retained as part of the public API
      when improved shared-library configurations provided for hiding private
      symbols.





  
void XftUnlockFace (

  

    
	XftFont	*pub);


    
Decrements the reference count for the FreeType 2
        “face” associated with the font.

  





  

  
FT_Face objects are deallocated using FT_Done_Face().
      Xft does this in XftFontInfoDestroy() and when cleaning up
      on failure in XftFontInfoCreate() and
    XftFontOpenPattern().










DEBUGGING


Xft reads the environment variable XFT_DEBUG and
    converts that to an integer. Each bit in the resulting value tells
    Xft to print debugging information to the standard output:



  
1

  
font-opening

  
2

  
additional font-matching and opening (verbose)

  
4

  
shows details about the XRenderPictFormat which will be used.

  
8

  
shows the string which XftDrawString8() will draw.

  
16

  
shows which font-ids are matched.

  
32

  
shows useful information about the glyphs which will be drawn

  
64

  
shows an ASCII-art representation of the glyphs.

  
128

  
shows details about the memory-cache management

  
256

  
shows details about managing glyph cached-memory

  
512

  
shows a report on memory-usage

  
1024

  
shows details on extended management of glyph cached-memory








COMPATIBILITY


As of version 2 (May 2002), Xft became relatively stable.
    It is expected to retain source and binary compatibility in future
  releases.


Xft provides a compatibility interface to its previous
    major version, Xft 1.x, described below.




Xft   1.x Header File


#include <X11/Xft/XftCompat.h>






Xft   1.x Data Types



  
XftPattern

  
holds a set of names with associated value lists; each name refers to a
      property of a font. XftPatterns are used as inputs to the matching
      code as well as holding information about specific fonts.

  
XftFontSet

  
contains a list of XftPatterns. Internally, Xft uses this
      data structure to hold sets of fonts. Externally, Xft returns the
      results of listing fonts in this format.

  
XftObjectSet

  
holds a set of names and is used to specify which fields from fonts are
      placed in the list of returned patterns when listing fonts.
