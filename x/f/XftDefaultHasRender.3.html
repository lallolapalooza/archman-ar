XftDraw

هو كائن غير شفاف يحتوي على معلومات تُستخدم للعرض على رسم X باستخدام البروتوكول الأساسي أو امتداد X Rendering.

يتم إنشاء كائنات XftDraw باستخدام أي من الدوال التالية: XftDrawCreate() (التي تربط XftDraw برسم X موجود)، XftDrawCreateBitmap()، أو XftDrawCreateAlpha()، ويتم تدميرها باستخدام XftDrawDestroy(). يمكن تغيير رسم X المرتبط بـ XftDraw باستخدام XftDrawChange(). يتم تخصيص كائنات XftDraw وتحريرها داخليًا بواسطة Xft؛ لا يحتاج المبرمج عادةً إلى تخصيص مساحة تخزين لها أو تحريرها.

يمكن الاستعلام عن خصائص X Display و Drawable و Colormap و Visual لكائن XftDraw باستخدام XftDrawDisplay() و XftDrawDrawable() و XftDrawColormap() و XftDrawVisual() على التوالي.

تستخدم العديد من الدوال كائنات XftDraw: XftDrawCharFontSpec()، XftDrawCharSpec()، XftDrawGlyphFontSpec()، XftDrawGlyphSpec()، XftDrawGlyphs()، XftDrawRect()، XftDrawSetClip()، XftDrawSetClipRectangles()، XftDrawSetSubwindowMode()، وعائلة الدوال XftDrawString*().

صورة X Rendering Extension Picture المرتبطة بـ XftDraw يتم إرجاعها بواسطة XftDrawPicture() و XftDrawSrcPicture(). يتم استخدامها بواسطة XftCharFontSpecRender() و XftCharSpecRender() و XftGlyphFontSpecRender() و XftGlyphRender() و XftGlyphSpecRender() وعائلة الدوال XftTextRender*().

الوظائف

التهيئة

عادةً لا يقوم التطبيق النموذجي الذي يستخدم Xft بتهيئة المكتبة بشكل صريح. يتم ذلك عادةً كأثر جانبي لفتح خط.

عند تهيئة Xft، تقوم بجمع معلومات حول العرض، وتخزين بعض تلك المعلومات في نمط Fontconfig (وهو في الأساس مجموعة من الخصائص ذات القيم المفيدة). يمكن للتطبيق المتصل تعديل هذا النمط لتغيير سلوك المكتبة.

لا يتم تخزين جميع المعلومات التي تم جمعها في نمط. يتم تخزين الباقي في هياكل بيانات داخلية. يجعل Xft بعض هذه البيانات متاحة للتطبيق من خلال الدوال.

Bool XftDefaultHasRender (
	Display	*dpy);

الحصول على معلومات حول العرض dpy إذا لم يتم ذلك بالفعل، وإرجاع صحيح إذا وجد Xft أن العرض يدعم امتداد X Render، وإذا كان قادرًا على العثور على XRenderPictFormat مناسب (نوع بيانات X Render الذي يشبه Visual الخاص بـ Xlib) على العرض.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

الحصول على معلومات حول العرض dpy إذا لم يتم ذلك بالفعل، وتعيين نمط Fontconfig الذي يحتوي على الخصائص الافتراضية التي سيستخدمها Xft لهذا العرض.

يستخدم Xft هذه الخصائص مبدئيًا للحصول على هذه الحدود:
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). هذا هو الحد الأقصى لذاكرة الحروف الرسومية لجميع الخطوط التي يستخدمها Xft (افتراضي: 4*1024*1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). هذا هو الحد الأقصى لعدد الخطوط غير المشار إليها (افتراضي: 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). عند صح، يتتبع Xft استخدام ذاكرة الحروف الرسومية لتحسين الأداء عند اتخاذ قرار بشأن ما يجب إلغاء تحميله عند الوصول إلى الحد الأقصى لذاكرة الحروف الرسومية (افتراضي: خطأ).
يستخدم Xft أيضًا هذه الخصائص الافتراضية في XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

يقوم Xft بملء الخصائص المفقودة في pattern المعطى باستخدام الخصائص الافتراضية للعرض المحدد dpy، على سبيل المثال، كما تم تعيينها في XftDefaultSet().

تستخدم تطبيقات Xft النموذجية هذه الدالة للمساعدة في اختيار Fontconfig لخط مناسب. يتم استبدال هذه الخصائص قبل استدعاء FcDefaultSubstitute():
FC_ANTIALIAS
صحيح إذا كان FreeType يجب أن يستخدم التنعيم (افتراضي: خطأ). (افتراضي: صحيح).
FC_AUTOHINT
صحيح إذا كان FreeType يجب أن يستخدم التلميحات التلقائية (افتراضي: خطأ).
FC_DPI
النقاط/بوصة المستخدمة للدقة (افتراضي: محسوب من ارتفاع الشاشة).
FC_EMBOLDEN
صحيح إذا كان يجب استخدام FT_GlyphSlot_Embolden() لجعل الخط غامقًا (افتراضي: خطأ).
FC_HINTING
صحيح إذا كان يجب استخدام التلميحات عند ملء الخصائص لفتح خط (افتراضي: صحيح).
FC_HINT_STYLE
نمط التلميح المستخدم عند ملء الخصائص لفتح خط (افتراضي: FC_HINT_FULL).
FC_LCD_FILTER
المعلمة التي يتم تمريرها إلى FT_Library_SetLcdFilter() عند تحميل الحروف الرسومية (افتراضي: FC_LCD_DEFAULT).
FC_MINSPACE
الحد الأدنى لقيمة المسافة المستخدمة عند ملء الخصائص لفتح خط (افتراضي: خطأ).
FC_RGBA

الحد الأقصى للذاكرة لخط واحد (افتراضي: 1024*1024).

NAME


XftDraw - drawing abstractions






DESCRIPTION


The Xft library provides drawing abstractions that simplify the use
    of X fonts. This man page describes the functions that create, destroy, and
    manipulate XftDraw objects, as well as functions for drawing glyphs
    and other objects.



  
XftDraw *XftDrawCreate (

  

    
	Display	*dpy,
	Drawable	 drawable,
	Visual	*visual,
	Colormap	 cmap);


    
XftDrawCreate() creates and returns a new XftDraw
        object associated with the given X drawable, visual, and
        colormap. The X server's default screen is used if drawable
        is 0. If the X server does not support the X Rendering Extension, a new
        XftDraw object is created, but subsequent drawing operations will
        use the core X library functions.

        except that it uses an X pixmap instead of an X drawable.

Bool XftDrawSetClip (

  

    
	XftDraw	*draw,
	Region	 r);


    
Set up clipping for the given XftDraw parameter
        draw starting with a Region:

  






    
  
  • If the Region parameter r is not null, Xft creates a
      new Region (to copy the parameter),
    • 
  
  • Xft destroys any existing clipping region.
    • 
  
  • Xft sets the clip_type for the draw parameter to
      XftClipTypeRegion if the r parameter was not null. Otherwise
      it sets the clip_type to XftClipTypeNone.
    • 
  
  • Finally, Xft updates clipping for existing objects, updates the
      clip_mask for its X Render Picture object and sets the
      clipping-mask in the graphic context (GC) associated with the
      XftDraw parameter.
    • 






  

  
XftDrawSetClip() returns True if no change was necessary, or
      if the operation succeeded. It returns False if it was unable to
      create the new Region().





  
Bool XftDrawSetClipRectangles (

  

    
	XftDraw	*draw,
	int	 xOrigin,
	int	 yOrigin,
	_Xconst XRectangle	*rects,
	int	 n);


    
Like XftDrawSetClip(),
        XftDrawSetClipRectangles() sets up clipping for the given
        XftDraw parameter draw but uses a set of n
        rectangles (the rects parameter) which could be used to construct
        a Region .

  





  

  
Xft sets the clip_type for draw to XftClipTypeRectangles and
      uses XSetClipRectangles() for core (X11) clipping and
      XRenderSetPictureClipRectangles() for X Render clipping.





  
void XftDrawSetSubwindowMode (

  

    
	XftDraw	*draw,
	int	 mode);


    
Sets the subwindow-mode for the given XftDraw parameter
        draw. The mode can be either ClipByChildren (the default),
        or IncludeInferiors:

  






    
  
  • For ClipByChildren, both source and destination windows are
      additionally clipped by all viewable InputOutput children.
    • 
  
  • For IncludeInferiors, neither source nor destination window is
      clipped by inferiors. This will result in including subwindow contents in
      the source and drawing through subwindow boundaries of the
    destination.
    • 






  

  
In addition to the subwindow-mode maintained by Xft, it updates the
      subwindow mode for any associated graphics context GC using
      XSetSubwindowMode() as well as for an X Render Picture using
      XRenderChangePicture().

void XftDrawGlyphFontSpec (

  

    
	XftDraw	*draw,
	_Xconst XftColor	*color,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 len);


    
Draw a list of glyphs associated with fonts at specified
        coordinates, passed as an array of len XftGlyphFontSpec
        structures via the parameter glyphs. All of the glyphs are drawn
        using the color specified in the color parameter.

  





  

  
For each entry in the glyphs array:






    
  
  • If the associated font uses the X Render extension, then Xft uses
      XftGlyphFontSpecRender() to draw the glyph, using a Picture
      obtained from calling XftDrawSrcPicture () with the draw and
      color parameters.
    • 
  
  • Otherwise, Xft provides an analogous feature using Xlib.
    • 






  
void XftGlyphFontSpecRender (

  

    
	Display	*dpy,
	int	 op,
	Picture	 src,
	Picture	 dst,
	int	 srcx,
	int	 srcy,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 nglyphs);


    
This involves several steps:

  






    
  
  • First, Xft ensures that the glyphs array is complete using
      XftFontCheckGlyph() and loading any missing glyphs with
      XftFontLoadGlyphs().
    • 
  
  • Then Xft examines the glyphs to find the maximum Unicode value.
      That determines the encoding size, i.e., the width.
    • 
  
  • Then, for each glyph, Xft checks if its Unicode value is handled by
      the corresponding font. If not, the value is set to zero (0), to ignore
      it. While doing this, Xft also remembers which was the first font
      used, and computes the position at which each glyph will be drawn.
    • 
  
  • Xft then constructs an equivalent array of glyphs in the format
      expected by the X Render library.
    • 
  
  • Finally, XftGlyphFontSpecRender() uses the X Render extension to
      draw the glyphs, with the appropriate XRenderCompositeText*()
      function according to the width, and discards temporary data.
    • 




  

  
The op, dst, src, srcx, and srcy
      parameters are used as described in the documentation for the X Render
      library.
