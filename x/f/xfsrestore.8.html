xfsrestore(8) دليل مدير النظام xfsrestore(8)

الاسم

xfsrestore - أداة استعادة الاستعادة التدريجية لنظام ملفات XFS

الملخص

xfsrestore -h
xfsrestore [ خيارات ] -f مصدر [ -f مصدر ... ] وجهة
xfsrestore [ خيارات ] - وجهة
xfsrestore -I [ خيارات_فرعية=قيمة ... ]

الوصف

تقوم xfsrestore باستعادة أنظمة الملفات من النسخ الاحتياطي التي تم إنتاجها بواسطة xfsdump(8). يتوفر وضعان للتشغيل: بسيط وتراكمي.

الوضع الافتراضي هو الوضع البسيط. تقوم xfsrestore بتعبئة دليل الوجهة المحدد، وجهة، بالملفات الموجودة في النسخة الاحتياطية.

الخيار -r يحدد الوضع التراكمي. يتم استخدام استدعاءات متتالية لـ xfsrestore لتطبيق تسلسل مرتب زمنيًا من النسخ الاحتياطية التكميلية على نسخة احتياطية أساسية (مستوى 0). يتم إعادة إنتاج محتويات نظام الملفات في الوقت الذي تم فيه إنتاج كل نسخة احتياطية. قد يشمل ذلك إضافة، حذف، إعادة تسمية، ربط، وفك ربط الملفات والأدلة.

يتم تعريف النسخة الاحتياطية التكميلية على أنها إما نسخة احتياطية تزايدية (الخيار xfsdump -l مع مستوى > 0) أو نسخة احتياطية مستأنفة (الخيار xfsdump -R). يجب تطبيق النسخ التكميلية بالترتيب الذي تم إنتاجها به. يجب أن تكون كل نسخة تكميلية تم تطبيقها قد تم إنتاجها باستخدام النسخة التكميلية السابقة كأساس لها.

تحتفظ xfsrestore بمعلومات الحالة في xfsrestorehousekeepingdir، لإعلام الاستدعاءات اللاحقة عند استخدامها في الوضع التراكمي، أو في حالة مقاطعة الاستعادة. لضمان إمكانية معالجة معلومات الحالة، يجب استخدام إصدار متوافق من xfsrestore لكل استدعاء لاحق. بالإضافة إلى ذلك، يجب أن يعمل كل استدعاء على نظام بنفس الحجم الأصغر (endianness) وحجم الصفحة.

خيارات xfsrestore هي:

-a housekeeping
يقوم كل استدعاء لـ xfsrestore بإنشاء دليل يسمى xfsrestorehousekeepingdir. يتم إنشاء هذا الدليل عادةً مباشرة تحت دليل وجهة. يسمح الخيار -a للمشغل بتحديد دليل بديل، housekeeping، يقوم xfsrestore بإنشاء دليل xfsrestorehousekeepingdir بداخله. عند إجراء استعادة تراكمية (الخيار -r) أو استئناف (الخيار -R) استعادة، يجب على كل استدعاء متعاقب تحديد نفس الدليل البديل.
-b حجم_الكتلة
يحدد حجم الكتلة، بالبايت، للاستخدام في الاستعادة. بالنسبة لمحركات الأقراص الأخرى مثل DAT أو 8 mm ، يجب تحديد نفس حجم الكتلة المستخدم لعملية xfsdump لاستعادة الشريط. حجم الكتلة الافتراضي هو 1 ميجابايت.
-c اسم_البرنامج
استخدم البرنامج المحدد لتنبيه المشغل عند الحاجة إلى تغيير الوسائط. برنامج التنبيه عادة ما يكون برنامج نصي لإرسال بريد إلكتروني أو عرض نافذة لجذب انتباه المشغل.
-e
يمنع xfsrestore من الكتابة فوق الملفات الموجودة في دليل وجهة.
-f مصدر [ -f مصدر ... ]
يحدد مصدر النسخة الاحتياطية المراد استعادتها. يمكن أن يكون هذا المسار إلى جهاز (مثل محرك أقراص شريط)، أو ملف عادي، أو محرك أقراص شريط عن بعد (انظر rmt(8)). يجب حذف هذا الخيار إذا تم تحديد خيار الإدخال القياسي (علامة - وحيدة تسبق تحديد وجهة).
-i
يختار التشغيل التفاعلي. بمجرد قراءة التسلسل الهرمي للأدلة على الوسائط، يتم بدء حوار تفاعلي. يستخدم المشغل مجموعة صغيرة من الأوامر لتصفح التسلسل الهرمي للأدلة، واختيار الملفات والأشجار الفرعية للاستخراج. الأوامر المتاحة معطاة أدناه. في البداية لا يتم تحديد شيء، باستثناء تلك الأشجار الفرعية المحددة بخيارات سطر الأوامر -s.
ls [arg]
قائمة الإدخالات في الدليل الحالي أو الدليل المحدد، أو إدخال ملف غير دليلي محدد. يتم عرض رقم inode الأصلي واسم كل إدخال. الإدخالات التي هي أدلة يتم إلحاق "/" بها. الإدخالات التي تم تحديدها للاستخراج يتم إضافة "*" قبلها عند عرضها بواسطة ls.
cd [arg]
تغيير دليل العمل الحالي إلى الوسيط المحدد، أو إلى دليل جذر نظام الملفات إذا لم يتم تحديد وسيط.
pwd
طباعة مسار الدليل الحالي، نسبة إلى جذر نظام الملفات.
add [arg]
يتم تحديد الدليل الحالي أو الملف أو الدليل المحدد داخل الدليل الحالي للاستخراج. إذا تم تحديد دليل، فسيتم تحديده هو وجميع ما يحتويه. الإدخالات التي يتم تحديدها للاستخراج يتم إضافة "*" قبلها عند عرضها بواسطة ls.
delete [arg]
يتم إلغاء تحديد الدليل الحالي أو الملف أو الدليل المحدد داخل الدليل الحالي للاستخراج. إذا تم تحديد دليل، فسيتم إلغاء تحديده هو وجميع ما يحتويه. الطريقة الأكثر فعالية لاستخراج معظم الملفات من دليل هي تحديد الدليل ثم إلغاء تحديد الملفات التي ليست مطلوبة.
extract
ينهي الحوار التفاعلي، ويتسبب في استعادة جميع الأشجار الفرعية المحددة.
quit
تنهي xfsrestore الحوار التفاعلي وتخرج على الفور، حتى لو كانت هناك ملفات أو أشجار فرعية محددة للاستخراج.
help
قائمة ملخص للأوامر المتاحة.
-m
استخدم بروتوكول الشريط الأدنى. لا يمكن استخدام هذا الخيار بدون تحديد حجم كتلة للاستخدام (انظر الخيار -b أعلاه).
-n ملف
يسمح لـ xfsrestore باستعادة الملفات الأحدث فقط من ملف. يتم مقارنة وقت تعديل ملف (أي، كما هو معروض باستخدام الأمر ls -l) بوقت تعديل inode لكل ملف على وسائط المصدر (أي، كما هو معروض باستخدام الأمر ls -lc). يتم استعادة ملف من الوسائط فقط إذا كان وقت تعديل inode الخاص به أكبر من أو يساوي وقت تعديل ملف.
-o
استعادة مالك/مجموعة الملف والدليل حتى لو لم يكن المستخدم هو الجذر (root). عند التشغيل بمعرف مستخدم فعال كجذر، تقوم xfsrestore باستعادة ملكية ومجموعة كل ملف ودليل. عند التشغيل بأي معرف مستخدم فعال آخر، لا تفعل ذلك، إلا إذا تم تحديد هذا الخيار.
-p فاصل_زمني
يتسبب في طباعة تقارير التقدم على فترات من فاصل_زمني ثانية. قيمة الفاصل الزمني تقريبية، ستؤخر xfsrestore تقارير التقدم لتجنب حمل معالجة لا داعي لها.
-q
محرك أقراص شريط المصدر هو شريط QIC. تستخدم أشرطة QIC حجم كتلة 512 بايت فقط، والتي يجب على xfsrestore إجراء تعديلات خاصة لها.
-r
يختار الوضع التراكمي للتشغيل. يجب أن تكون الخيارات -a و الوجهة هي نفسها لكل استدعاء.
-s شجرة_فرعية
يحدد شجرة فرعية للاستعادة. يمكن استخدام أي عدد من الخيارات -s. يتم تقييد الاستعادة إلى اتحاد جميع الأشجار الفرعية المحددة. يتم تحديد كل شجرة فرعية كمسار نسبي إلى وجهة الاستعادة. إذا تم تحديد دليل، فسيتم استعادة الدليل وجميع الملفات الموجودة تحته.
-t
يعرض محتويات النسخة الاحتياطية، ولكنه لا ينشئ أو يعدل أي ملفات أو أدلة. قد يكون من المرغوب فيه ضبط مستوى الإسهاب على صامت عند استخدام هذا الخيار.
-x
قد يكون هذا الخيار مفيدًا لإصلاح مشكلة حيث يتم استعادة الملفات إلى دليل مهمل بسبب مشكلة xfsdump (الإصدارات 3.1.7 - 3.1.9). لا يمكن استعادة نسخة احتياطية عادية باستخدام هذا الخيار. يعمل هذا الخيار فقط لنسخة احتياطية تالفة. إذا تم إنشاء نسخة احتياطية بواسطة xfsdump إشكالي (الإصدارات 3.1.7 - 3.1.9)، يجب عليك عرض محتويات النسخة الاحتياطية باستخدام الخيار -t ب

It is also possible to restore a dump from standard input into a regular file, or from a regular file to standard output. The dump session label (-L option) or dump session UUID (-S option) can be used to restore a specific dump session from a media object that contains multiple dump sessions. If neither is specified, xfsrestore will scan the media object, prompting for confirmation before restoring each session it finds. Media objects may contain more than one dump session. The operator can select the desired dump session by specifying the dump label (-L option), or by specifying the dump UUID (-S option). If neither is specified, xfsrestore scans the entire media object, prompting the operator as each dump session is encountered. The inventory display (-I option) is useful for identifying the media objects required. It is also useful for identifying a dump session. The session UUID can be copied from the inventory display to the -S option argument to unambiguously identify a dump session to be restored. Dumps placed in regular files or the standard output do not span multiple media objects, nor do they contain multiple dumps. diagnostics: | The exit code is 0 on normal completion, and non-zero if an error occurred or the restore was terminated by the operator. For all verbosity levels greater than 0 (silent) the final line of the output shows the exit status of the restore. It is of the form: # xfsdump: Restore Status: code Where code takes one of the following values: SUCCESS (normal completion), INTERRUPT (interrupted), QUIT (media no longer usable), INCOMPLETE (restore incomplete), FAULT (software error), and ERROR (resource error). Every attempt will be made to keep both the syntax and the semantics of this log message unchanged in future versions of xfsrestore. However, it may be necessary to refine or expand the set of exit codes, or their interpretation at some point in the future. examples: - To restore the root filesystem from a locally mounted tape: # xfsrestore -f /dev/tape / - To restore from a remote tape, specifying the dump session id: # xfsrestore -L session_1 -f otherhost:/dev/tape /new - To restore the contents a of a dump to another subdirectory: # xfsrestore -f /dev/tape /newdir - To copy the contents of a filesystem to another directory (see xfsdump(8)): # xfsdump -J - / | xfsrestore -J - /new files: - path: /var/lib/xfsdump/inventory description: dump inventory database inventory: description: | Each dump session updates an inventory database in /var/lib/xfsdump/inventory. This database can be displayed by invoking xfsrestore with the -I option. The display uses tabbed indentation to present the inventory hierarchically. The first level is filesystem. The second level is session. The third level is media stream (currently only one stream is supported). The fourth level lists the media files sequentially composing the stream. suboptions: - name: -I depth=n description: | (where n is 1, 2, or 3) limits the hierarchical depth of the display. When n is 1, only the filesystem information from the inventory is displayed. When n is 2, only filesystem and session information are displayed. However, at most four suboptions can be specified at once: one to constrain the display hierarchy depth, one to constrain the dump level, one to constrain the media object, and one to constrain the filesystem. Dump records may be removed (pruned) from the inventory using the xfsinvutil program. An additional media file is placed at the end of each dump stream. This media file contains the inventory information for the current dump session. If the online inventory files in /var/lib/xfsdump/inventory are missing information for the current dump session, then the inventory information in the media file is automatically added to the files in /var/lib/xfsdump/inventory. If you wish to incorporate the inventory information from the media file without restoring any data, you may do so using the -t option: # xfsrestore -t -f /dev/tape This is useful to rebuild the inventory database if it is ever lost or corrupted. The only caveat is that xfsrestore needs to read through the entire dump in order to reach the inventory media file. This could become time consuming for dump sessions with large media files. media_errors: description: | xfsdump is tolerant of media errors, but cannot do error correction. If a media error occurs in the body of a media file, the filesystem file represented at that point is lost. The bad portion of the media is skipped, and the restoration resumes at the next filesystem file after the bad portion of the media. If a media error occurs in the beginning of the media file, the entire media file is lost. For this reason, large dumps are broken into a number of reasonably sized media files. The restore resumes with the next media file. notes: | Removable media drives are not supported). Tape cartridges can contain multiple media files, which are typically separated by (in tape parlance) file marks. If a dump spans multiple media objects, the restore must begin with the media object containing the first media file dumped. The operator is prompted when the next media object is needed. Media objects can contain more than one dump. The operator can select the desired dump by specifying the dump label (-L option), or by specifying the dump UUID (-S option). If neither is specified, xfsrestore scans the entire media object, prompting the operator as each dump session is encountered. quotas: description: | When xfsdump dumps a filesystem with user quotas, it creates a file in the root of the dump called xfsdump_quotas. xfsrestore can restore this file like any other file included in the dump. This file can be processed by the restore command of xfs_quota(8) to reactivate the quotas. However, the xfsdump_quotas file contains information which may first require modification; specifically the filesystem name and the user ids. If you are restoring the quotas for the same users on the same filesystem from which the dump was taken, then no modification will be necessary. However, if you are restoring the dump to a different filesystem, you will need to: steps: - ensure the new filesystem is mounted with the quota option - modify the xfsdump_quotas file to contain the new filesystem name - ensure the uids in the xfsdump_quotas file are correct notes: | Once the quota information has been verified, the restore command of xfs_quota (8) can be used to apply the quota limits to the filesystem.
