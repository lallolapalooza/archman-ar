XftDraw

هو كائن غير شفاف يحتوي على معلومات تُستخدم للرسم على عنصر قابل للرسم في X باستخدام البروتوكول الأساسي أو امتداد X Rendering.

يتم إنشاء كائنات XftDraw باستخدام أي من الدالات التالية: XftDrawCreate() (التي تربط XftDraw بعنصر قابل للرسم موجود في X)، XftDrawCreateBitmap()، أو XftDrawCreateAlpha(). ويتم تدميرها باستخدام XftDrawDestroy(). يمكن تغيير عنصر X القابل للرسم المرتبط بـ XftDraw باستخدام XftDrawChange(). يتم تخصيص كائنات XftDraw وتحريرها داخليًا بواسطة Xft؛ لا يحتاج المبرمج عادةً إلى تخصيص أو تحرير مساحة تخزين لها.

يمكن الاستعلام عن خصائص X Display و Drawable و Colormap و Visual الخاصة بـ XftDraw باستخدام XftDrawDisplay() و XftDrawDrawable() و XftDrawColormap() و XftDrawVisual() على التوالي.

تستخدم العديد من الدوال كائنات XftDraw: XftDrawCharFontSpec() و XftDrawCharSpec() و XftDrawGlyphFontSpec() و XftDrawGlyphSpec() و XftDrawGlyphs() و XftDrawRect() و XftDrawSetClip() و XftDrawSetClipRectangles() و XftDrawSetSubwindowMode() وعائلة XftDrawString*().

يتم إرجاع امتداد X Rendering Picture المرتبط بـ XftDraw بواسطة XftDrawPicture() و XftDrawSrcPicture(). ويتم استخدامه بواسطة XftCharFontSpecRender() و XftCharSpecRender() و XftGlyphFontSpecRender() و XftGlyphRender() و XftGlyphSpecRender() وعائلة XftTextRender*().

الدالات

التهيئة

التطبيق النموذجي الذي يستخدم Xft لا يقوم بتهيئة المكتبة بشكل صريح. يتم ذلك عادةً كنتيجة جانبية لفتح خط.

عندما تقوم Xft بالتهيئة، تجمع معلومات حول الشاشة، وتخزن بعض تلك المعلومات في نمط Fontconfig (وهو أساسًا مجموعة من الخصائص ذات القيم المكتوبة. يمكن للتطبيق المستدعي تعديل هذا النمط لتغيير سلوك المكتبة.

لا يتم تخزين كل المعلومات المجمعة في نمط. يتم تخزين الباقي في هياكل بيانات داخلية. توفر Xft بعضًا من هذه المعلومات للتطبيق عبر دوال.

Bool XftDefaultHasRender (
	Display	*dpy);

تحصل على معلومات حول الشاشة dpy إذا لم يتم ذلك بالفعل، وتعيد صحيحًا إذا وجدت Xft أن الشاشة تدعم امتداد X Render، وإذا تمكنت من العثور على XRenderPictFormat مناسب (نوع بيانات X Render الذي يشبه Visual الخاص بـ Xlib) على الشاشة.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

تحصل على معلومات حول الشاشة dpy إذا لم يتم ذلك بالفعل، وتعيّن نمط Fontconfig الذي يحمل الخصائص الافتراضية التي ستستخدمها Xft لهذه الشاشة.

تستخدم Xft هذه الخصائص في البداية للحصول على هذه الحدود:
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). هذا هو الحد الأقصى لذاكرة الأشكال لجميع الخطوط المستخدمة بواسطة Xft (الافتراضي: 4*1024*1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). هذا هو الحد الأقصى لعدد الخطوط غير المشار إليها (الافتراضي: 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). عندما يكون صحيحًا، تتتبع Xft استخدام ذاكرة الأشكال لتحسين الأداء عند تحديد أي منها سيتم إلغاء تحميله عندما يتم الوصول إلى الحد الأقصى لذاكرة الأشكال (الافتراضي: false).
تستخدم Xft أيضًا هذه الخصائص الافتراضية في XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

تقوم Xft بملء الخصائص المفقودة في pattern المعطى باستخدام الخصائص الافتراضية للشاشة المحددة dpy، على سبيل المثال، كما تم تعيينها في XftDefaultSet().

تستخدم تطبيقات Xft النموذجية هذه الدالة للمساعدة في اختيار Fontconfig لخط مناسب. يتم استبدال هذه الخصائص قبل استدعاء FcDefaultSubstitute():
FC_ANTIALIAS
صحيح إذا كان FreeType يجب أن يستخدم التنعيم (الافتراضي: False). (الافتراضي: True).
FC_AUTOHINT
صحيح إذا كان FreeType يجب أن يستخدم التلميح التلقائي (الافتراضي: False).
FC_DPI
النقاط/البوصة المستخدمة للدقة (الافتراضي: محسوب من ارتفاع الشاشة).
FC_EMBOLDEN
صحيح إذا كان يجب استخدام FT_GlyphSlot_Embolden() لتغميق الخط (الافتراضي: False).
FC_HINTING
صحيح إذا كان يجب استخدام التلميح عند ملء الخصائص لفتح خط (الافتراضي: True).
FC_HINT_STYLE
أسلوب التلميح المستخدم عند ملء الخصائص لفتح خط (الافتراضي: FC_HINT_FULL).
FC_LCD_FILTER
المعلمة التي تم تمريرها إلى FT_Library_SetLcdFilter() عند تحميل الأشكال (الافتراضي: FC_LCD_DEFAULT).

FC_RGBA
قيمة RGBA المستخدمة عند ملء الخصائص لفتح خط (الافتراضي: محسوبة عن طريق استدعاء XRenderQuerySubpixelOrder()).
FC_SCALE
المقياس المستخدم في Fontconfig (الافتراضي: 1.0).
XFT_MAX_GLYPH_MEMORY
الحد الأقصى لذاكرة شكل واحد (الافتراضي: 1024*1024).
XFT_RENDER
صحيح إذا كانت الشاشة تدعم امتداد X Render (الافتراضي: النتيجة من XftDefaultHasRender()).

XftDrawChange(3)


الحزمة: libxft


التراخيص: HPND-sell-variant


        
        

            





NAME


XftDrawChange, XftDrawSetClip, XftDrawSetSubwindow — modify drawing
   attributes






SYNOPSIS


    void XftDrawChange(XftDraw *draw, XftPattern *pattern);
    void XftDrawSetClip(XftDraw *draw, XftRegion *clip);
    void XftDrawSetSubwindow(XftDraw *draw, Window subwindow);







DESCRIPTION


XftDrawChange() sets the font and color of the drawing
   context draw to match the properties in pattern. This is useful
   for changing the font or color in the middle of a sequence of drawing
   operations.


XftDrawSetClip() sets the clipping region for the
   drawing context draw to clip. All drawing operations will be
   clipped to this region. If clip is NULL, then no clipping is
   performed.


XftDrawSetSubwindow() sets the subwindow attribute for the
   drawing context draw to subwindow. If subwindow is None,
   then drawing is performed directly into the window associated with the
   drawing context. Otherwise, drawing is performed into the specified
   subwindow.






CONSTANTS



  
XftFont

  
holds information about a font, including its FreeType face, metrics,
      and the X Render font. It is returned by XftFontOpen() and
      XftFontOpenPattern().

  
XftPattern

  
holds a set of names with associated value lists; each name refers to a
      property of a font. XftPatterns are used as inputs to the matching
      code as well as holding information about specific fonts.

  
XftColor

  
holds an X Render color value. The spec field holds a string
      representation of the color (e.g., "red", "#ff0000"),
      and the pixel field holds the corresponding X Render color value.
      This structure is filled by XftColorAllocName() and
      XftColorAllocValue().

  
XftDraw

  
holds drawing state, including the display, the drawable, the current
      font, and color. It is returned by XftDrawCreate().

  
XftRegion

  
holds a region, which is a set of rectangles. Regions are used for
      clipping.








DATA TYPES


The following data types are used by the Xft library:



  
FcPattern

  
A Fontconfig pattern. This is the primary structure for describing and
      matching fonts.

  
FcFontSet

  
A Fontconfig font set, containing a list of FcPatterns.

FcBool XftNameUnparse (

  

    
	FcPattern	*pat,
	char	*dest,
	int	 len);


    
Like XfgNameParse(), Xft uses Fontconfig. In
        this case, it uses FcNameUnparse(), which converts the pattern
        pat back into a string that can be parsed.
        XftNameUnparse() stores the result via the caller's pointer
        dest, but checks first if it will fit, using the len
        parameter. If it fits, Xft copies the string and returns
        FcTrue, otherwise it returns FcFalse.

  





  
void XftFontLoadGlyphs (

  

    
	Display	*dpy,
	XftFont	*pub,
	FcBool	 need_bitmaps,
	_Xconst FT_UInt	*glyphs,
	int	 nglyph);


    
Using FT_Load_Glyph(), load nglyphs for the
        glyph indices (Unicode values) listed in the array glyphs from
        the given font pub.

  





  

  
Loading a glyph entails more than just reading data into memory.
      Xft uses the Fontconfig pattern associated with the display
      dpy (e.g., via XftDefaultSet()) to determine whether to use
      a bounding box, clip the glyphs into those bounds, scale the glyphs,
      compute font metrics, and add it to the X Render extension using
      XRenderAddGlyphs().





  
void XftFontUnloadGlyphs (

  

    
	Display	*dpy,
	XftFont	*pub,
	_Xconst FT_UInt	*glyphs,
	int	 nglyph);


    
Discards data for up to nglyph glyphs whose glyph
        indices (Unicode values) are listed in the array glyphs for the
        given font pub. If the glyphs were added to the X Render
        extension, Xft removes those using XRenderFreeGlyphs().
        Xft keeps track of the amount of memory used for glyphs, and
        updates the usage associated with the display dpy.

  

  
FT_Face XftLockFace (

  

    
	XftFont	*pub);


    
If no FreeType 2 “face” (in-memory
        representation of a given typeface in a given style) has been created
        for the pub font, create one using FT_New_Face().
        Face-locks are a reference count used by Xft to ensure that only
        one face is created, and that it is retained until the font is no longer
        used.

  





  

  
Face-locking is used directly in XftCharIndex() and
      XftFontLoadGlyphs(), which in turn are used in many functions of
      Xft.

  

  
Face-locking was introduced in version 1 (October 2002). A few
      applications, such as Gdk/Gimp relied upon these functions. In version
      2.1.9 (June 2006), face-locking was retained as part of the public API
      when improved shared-library configurations provided for hiding private
      symbols.





  
void XftUnlockFace (

  

    
	XftFont	*pub);


    
Decrements the reference count for the FreeType 2
        “face” associated with the font.

  





  

  
FT_Face objects are deallocated using FT_Done_Face().
      Xft does this in XftFontInfoDestroy() and when cleaning up
      on failure in XftFontInfoCreate() and
    XftFontOpenPattern().








DEBUGGING


Xft reads the environment variable XFT_DEBUG and
    converts that to an integer. Each bit in the resulting value tells
    Xft to print debugging information to the standard output:



  
1

  
font-opening

  
2

  
additional font-matching and opening (verbose)

  
4

  
shows details about the XRenderPictFormat which will be used.

  
8

  
shows the string which XftDrawString8() will draw.

  
16

  
shows which font-ids are matched.

  
32

  
shows useful information about the glyphs which will be drawn

  
64

  
shows an ASCII-art representation of the glyphs.

  
128

  
shows details about the memory-cache management

  
256

  
shows details about managing glyph cached-memory

  
512

  
shows a report on memory-usage

  
1024

  
shows details on extended management of glyph cached-memory








COMPATIBILITY


As of version 2 (May 2002), Xft became relatively stable.
    It is expected to retain source and binary compatibility in future
  releases.


Xft provides a compatibility interface to its previous
    major version, Xft 1.x, described below.




Xft   1.x Header File


#include <X11/Xft/XftCompat.h>






Xft   1.x Data Types



  
XftPattern

  
holds a set of names with associated value lists; each name refers to a
      property of a font. XftPatterns are used as inputs to the matching
      code as well as holding information about specific fonts.

  
XftFontSet

      placed in the list of returned patterns when listing fonts.
