الحزمة: libxft

التراخيص: HPND-sell-variant

Xft(3) إصدار X 11 Xft(3)

الاسم

Xft - مكتبة واجهة X FreeType

الملخص

#include <X11/Xft/Xft.h>

الوصف

Xft هي مكتبة بسيطة تقوم برسم النصوص والرسومات:

  • باستخدام المعلومات المقدمة من مكتبة Fontconfig،
  • تقوم Xft بتحويل رموز الخطوط باستخدام مُقدِّم الخطوط FreeType، و
  • تعرض بيانات الخط المحولة باستخدام امتداد X للتقديم (X Rendering Extension).

صفحة الدليل هذه لا تخدش سوى سطح هذه المكتبة.

الثوابت

XFT_MAJOR
هو رقم الإصدار الرئيسي لـ Xft.
XFT_MINOR
هو رقم الإصدار الفرعي لـ Xft.
XFT_REVISION
هو رقم المراجعة لـ Xft.
XFT_VERSION
هو XFT_MAJOR مضروبًا في 10000 (عشرة آلاف)، زائد XFT_MINOR مضروبًا في 100، زائد XFT_REVISION.
XftVersion
هو اسم مستعار لـ XFT_VERSION.

يوضح المثال التالي كيف يمكن استخدام ثوابت إصدار Xft: 

    #if (XFT_VERSION >= 20107)
    (void) puts("الإصدار 2.1.7 أو أحدث من مكتبة Xft قيد الاستخدام.");
    #else
    (void) printf("إصدار غير كافٍ من Xft (%d.%d.%d) مثبت؛
                  " نحتاج إلى إصدار 2.1.7 على الأقل.\n", XFT_MAJOR,
                  XFT_MINOR,
                  XFT_REVISION);
    #endif

أنواع البيانات

تتبع أنواع بيانات Xft اصطلاح تسمية، حيث تسبق جميع الأسماء بـ "Xft"

من Xlib...

لا تتبع أنواع بيانات Xlib اصطلاح تسمية. يتم توثيقها في Xlib - واجهة لغة C.

تستخدم Xft هذه الأسماء: Bool، Colormap، Display، Drawable، Pixmap، Region، Visual، و XRectangle.

بعض أنواع البيانات ذات أهمية خاصة لـ Xft:

Drawable
معرّف مورد X، مثل نافذة مرتبطة بشاشة عرض. يمكن استخدام كل من النوافذ والصور (pixmaps) كمصادر ووجهات في عمليات الرسومات. تُعرف هذه النوافذ والصور مجتمعة باسم "drawables". ومع ذلك، لا يمكن استخدام نافذة من نوع InputOnly كمصدر أو وجهة في عملية رسومات.
Region
مجموعة اعتباطية من مواقع البكسل التي يمكن لـ Xlib معالجتها. داخليًا، يتم تمثيل Region باتحاد عدد اعتباطي من المستطيلات. تحتفظ Xlib بمستطيل يخبره بمدى هذا الاتحاد.
Visual
يحتوي هذا الهيكل على معلومات حول تعيين الألوان الممكنة.

من XRender...

تستلهم أنواع بيانات امتداد X للتقديم (X Render Extension) من Xlib، ولكنها تفتقر إلى الوثائق المقابلة. راجع ملف الرأس للحصول على التفاصيل:

<X11/extensions/Xrender.h>

أو اقرأ الكود المصدري (الذي يوفر مخططًا عامًا لـ libXrender).

تستخدم Xft هذه الأسماء: Picture، XGlyphInfo، XRenderColor.

من Fontconfig...

تتبع أنواع بيانات Fontconfig اصطلاح تسمية، حيث تسبق جميع الأسماء بـ "Fc" وهي موثقة في مرجع مطوري Fontconfig.

تستخدم Xft هذه الأسماء من Fontconfig: FcBool، FcChar8، FcChar16، FcChar32، FcCharSet، FcEndian، FcFontSet، FcPattern، و FcResult.

من FreeType 2...

تتبع أنواع بيانات FreeType 2 اصطلاح تسمية، حيث تسبق جميع الأسماء بـ "FT_" وهي موثقة في مرجع واجهة برمجة تطبيقات FreeType.

تستخدم Xft هذه الأسماء: FT_Face، FT_Library، و FT_UInt.

يستخدم FreeType 2 FT_UInt (عدد صحيح غير موقع) لتمثيل الرموز.

XftFont


typedef struct _XftFont {
	int	 ascent;
	int	 descent;
	int	 height;
	int	 max_advance_width;
	FcCharSet	*charset;
	FcPattern	*pattern;
} XftFont;

XftFont هو هيكل البيانات الأساسي الذي يهم المبرمجين الذين يستخدمون Xft؛ فهو يحتوي على مقاييس الخط العامة ومؤشرات إلى مجموعة أحرف Fontconfig والنمط المرتبطين بالخط.

يتم ملء XftFonts باستخدام أي من الدوال التالية: XftFontOpen()، XftFontOpenName()، XftFontOpenXlfd()، XftFontOpenInfo()، أو XftFontOpenPattern(). تُستخدم XftFontCopy() لنسخ XftFonts، وتُستخدم XftFontClose() لتمييز XftFont على أنه غير مستخدم. يتم تخصيص XftFonts وتحريرها وإدارة عداد المراجع لها داخليًا بواسطة Xft؛ لا يحتاج المبرمج عادةً إلى تخصيص أو تحرير مساحة تخزين لها.

تستخدم XftDrawGlyphs()، وعائلة دوال XftDrawString*()، XftDrawCharSpec()، و XftDrawGlyphSpec() XftFonts لرسم النصوص إلى كائن XftDraw، والذي قد يتوافق مع رسم أساسي في X أو رسم باستخدام امتداد X للتقديم.

تُستخدم XftGlyphExtents() وعائلة دوال XftTextExtents*() لتحديد امتدادات (الأبعاد القصوى) لـ XftFont.

يمكن تحديد تغطية الرموز أو حروف XftFont باستخدام XftFontCheckGlyph() أو XftCharExists(). تُرجع XftCharIndex() فهرس الحرف الخاص بـ XftFont المقابل لنقطة رمز Unicode معينة.

تستخدم XftGlyphRender()، XftGlyphSpecRender()، XftCharSpecRender()، وعائلة دوال XftTextRender*() XftFonts للرسم في هياكل Picture الخاصة بامتداد X للتقديم.

ملاحظة: توفر XftDrawGlyphs()، وعائلة دوال XftDrawString*()، XftDrawCharSpec()، و XftDrawGlyphSpec() وسيلة لتقديم الخطوط مستقلة عن توفر امتداد X للتقديم على خادم X.

XftFontInfo

هو كائن غامض يخزن معلومات حول خط. يتم إنشاء هياكل XftFontInfo باستخدام XftFontInfoCreate()، وتحريرها باستخدام XftFontInfoDestroy()، ومقارنتها باستخدام XftFontInfoEqual(). يتم تخصيص كائنات XftFontInfo وتحريرها داخليًا بواسطة Xft؛ لا يحتاج المبرمج عادةً إلى تخصيص أو تحرير مساحة تخزين لها.

كل هيكل XftFontInfo قيد الاستخدام مرتبط بمعرف فريد، يمكن استرداده باستخدام XftFontInfoHash(). يمكن فتح XftFont بناءً على بيانات XftFontInfo باستخدام XftFontOpenInfo().

XftColor


typedef struct _XftColor {
	unsigned long	 pixel;
	XRenderColor	 color;
} XftColor;

يسمح كائن XftColor برسم النصوص والعناصر الأخرى بلون معين (أو أقرب تقريب يقدمه العرض المرئي في X المستخدم).

تطلب XftColorAllocName() و XftColorAllocValue() تخصيص لون من خادم X (إذا لزم الأمر) وتهيئة أعضاء XftColor. تُعلم XftColorFree() خادم X بتحرير اللون المخصص حاليًا لـ XftColor.

بمجرد تهيئة XftColor، يمكن استخدام XftDrawSrcPicture()، XftDrawGlyphs()، عائلة دوال XftDrawString*()، XftDrawCharSpec()، XftDrawCharFontSpec()، XftDrawGlyphSpec()، XftDrawGlyphFontSpec()، و XftDrawRect() لرسم عناصر مختلفة باستخدامها.

.

XftDraw

هو كائن غير شفاف يحتوي على معلومات تُستخدم للرسم على واجهة X قابلة للرسم باستخدام البروتوكول الأساسي أو امتداد X Rendering.

يتم إنشاء كائنات XftDraw باستخدام أي من الدالتين XftDrawCreate() (التي تربط XftDraw بواجهة X قابلة للرسم موجودة)، XftDrawCreateBitmap()، أو XftDrawCreateAlpha()، ويتم تدميرها باستخدام XftDrawDestroy(). يمكن تغيير واجهة X القابلة للرسم المرتبطة بـ XftDraw باستخدام XftDrawChange(). يتم تخصيص كائنات XftDraw وتحريرها داخليًا بواسطة Xft؛ لا يحتاج المبرمج عادةً إلى تخصيص أو تحرير مساحة تخزين لها.

يمكن الاستعلام عن خصائص X Display و Drawable و Colormap و Visual لكائن XftDraw باستخدام XftDrawDisplay() و XftDrawDrawable() و XftDrawColormap() و XftDrawVisual() على التوالي.

تستخدم العديد من الدوال كائنات XftDraw: XftDrawCharFontSpec() و XftDrawCharSpec() و XftDrawGlyphFontSpec() و XftDrawGlyphSpec() و XftDrawGlyphs() و XftDrawRect() و XftDrawSetClip() و XftDrawSetClipRectangles() و XftDrawSetSubwindowMode() وعائلة XftDrawString*().

يتم إرجاع امتداد X Rendering Picture المرتبط بـ XftDraw بواسطة XftDrawPicture() و XftDrawSrcPicture(). يتم استخدامه بواسطة XftCharFontSpecRender() و XftCharSpecRender() و XftGlyphFontSpecRender() و XftGlyphRender() و XftGlyphSpecRender() وعائلة XftTextRender*().

الوظائف

التهيئة

لا يقوم التطبيق النموذجي الذي يستخدم Xft بتهيئة المكتبة بشكل صريح. عادةً ما يتم ذلك كأثر جانبي لفتح خط.

عند تهيئة Xft، يقوم بجمع معلومات حول العرض، ويخزن بعض هذه المعلومات في نمط Fontconfig (وهو في الأساس مجموعة من الخصائص ذات القيم المصنفة). يمكن للتطبيق المتصل تعديل هذا النمط لتغيير سلوك المكتبة.

لا يتم تخزين كل المعلومات المجمعة في نمط. يتم تخزين الباقي في هياكل بيانات داخلية. تجعل Xft بعض هذه المعلومات متاحة للتطبيق عبر الوظائف.

Bool XftDefaultHasRender (
	Display	*dpy);

احصل على معلومات حول العرض dpy إذا لم يتم ذلك بالفعل، وأرجع true إذا وجدت Xft أن العرض يدعم امتداد X Render، وإذا كان بإمكانه العثور على XRenderPictFormat مناسب (نوع بيانات X Render الذي يعادل Visual الخاص بـ Xlib) على العرض.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

احصل على معلومات حول العرض dpy إذا لم يتم ذلك بالفعل، واضبط نمط Fontconfig الذي يحتوي على الخصائص الافتراضية التي ستستخدمها Xft لهذا العرض.

تستخدم Xft هذه الخصائص مبدئيًا للحصول على هذه الحدود:
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). هذه هي الحد الأقصى لذاكرة الرموز لجميع الخطوط التي تستخدمها Xft (الافتراضي: 4*1024*1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). هذا هو الحد الأقصى لعدد الخطوط غير المشار إليها (الافتراضي: 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). عندما تكون صحيحة، تتتبع Xft استخدام ذاكرة الرموز لتحسين الأداء عند اتخاذ قرار بشأن ما يجب إلغاء تحميله عندما يتم الوصول إلى الحد الأقصى لذاكرة الرموز (الافتراضي: false).
تستخدم Xft أيضًا هذه الخصائص الافتراضية في XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

تملأ Xft الخصائص المفقودة في pattern المحدد باستخدام الخصائص الافتراضية للعرض dpy المحدد، على سبيل المثال، كما تم تعيينها في XftDefaultSet().

تستخدم تطبيقات Xft النموذجية هذه الوظيفة للمساعدة في اختيار Fontconfig لخط مناسب. يتم استبدال هذه الخصائص قبل استدعاء FcDefaultSubstitute():
FC_ANTIALIAS
صحيح إذا كان FreeType يجب أن يستخدم التجانس (الافتراضي: False). (الافتراضي: True).
FC_AUTOHINT
صحيح إذا كان FreeType يجب أن يستخدم التلميح التلقائي (الافتراضي: False).
FC_DPI
النقاط/بوصة المستخدمة للدقة (الافتراضي: محسوبة من ارتفاع العرض).
FC_EMBOLDEN
صحيح إذا كان يجب استخدام FT_GlyphSlot_Embolden() لتجعيد الخط (الافتراضي: False).
FC_HINTING
صحيح إذا كان يجب استخدام التلميح عند ملء الخصائص لفتح خط (الافتراضي: True).
FC_HINT_STYLE
نمط التلميح المستخدم عند ملء الخصائص لفتح خط (الافتراضي: FC_HINT_FULL).
FC_LCD_FILTER
معلمة يتم تمريرها إلى FT_Library_SetLcdFilter() عند تحميل الرموز (الافتراضي: FC_LCD_DEFAULT).
FC_MINSPACE
الحد الأدنى لقيمة المسافة المستخدمة عند ملء الخصائص لفتح خط (الافتراضي: False).
FC_RGBA
قيمة RGBA المستخدمة عند ملء الخصائص لفتح خط (الافتراضي: محسوبة عن طريق استدعاء XRenderQuerySubpixelOrder()).
FC_SCALE
المقياس المستخدم في Fontconfig (الافتراضي: 1.0).
XFT_MAX_GLYPH_MEMORY
الحد الأقصى للذاكرة لخط واحد (الافتراضي: 1024*1024).
XFT_RENDER
صحيح إذا كان العرض يدعم امتداد X Render (الافتراضي: نتيجة من XftDefaultHasRender()).
FcBool XftInit (
	_Xconst char	*config);

تهيئة مكتبة Fontconfig (استدعاء FcInit()).

المعلمة config غير مستخدمة.
Xft لا تقوم بإلغاء تهيئة مكتبة Fontconfig عند الانتهاء.
FcBool XftInitFtLibrary (void);

    
تهيئة مكتبة FreeType (استدعاء
        FT_Init_FreeType() لإنشاء كائن مكتبة) إذا لم يتم تهيئتها بالفعل.
        هذا ضروري قبل استخدام مكتبة FreeType لقراءة بيانات الخط من ملف.

  





  

  
تقوم Xft باستدعاء XftInitFtLibrary() داخليًا عبر
      XftFontInfoCreate() و XftFontOpenPattern().

  

  
Xft لا تتجاهل كائن المكتبة (على سبيل المثال، باستخدام
      FT_Done_FreeType()) عند الانتهاء.





  
int XftGetVersion (void);

  

    

    
إرجاع XftVersion، مما يتيح للتطبيق تحديد الإصدار الفعلي لـ
        Xft قيد الاستخدام.

  








فتح ومطابقة الخطوط



  
XftFont *XftFontOpen (

  

    
	Display	*dpy,
	int	 screen,
	...);


    
تأخذ XftFontOpen قائمة من ثلاثيات عناصر النمط بالشكل
        field و type و value (تنتهي بـ NULL)، وتطابق هذا النمط
        مع الخطوط المتاحة، وتفتح الخط المطابق، وتضبط حجمه بشكل صحيح لرقم الشاشة
        screen على العرض dpy. إرجاع الخط المطابق، أو NULL إذا لم يتم
        العثور على تطابق.

  




مثال:
  




    font = XftFontOpen (dpy, screen,
                        XFT_FAMILY, XftTypeString, "charter",
                        XFT_SIZE, XftTypeDouble, 12.0,
                        NULL);




  

  
هذا يفتح خط “charter” بحجم 12 نقطة. يتم تحويل حجم النقطة
      تلقائيًا إلى حجم البكسل الصحيح بناءً على دقة الشاشة.





  
XftFont *XftFontOpenName (

  

    
	Display	*dpy,
	int	 screen,
	_Xconst char	*name);


    
XftFontOpenName تعمل كما لو كانت XftFontOpen،
        باستثناء أنها تأخذ سلسلة نمط Fontconfig (والتي يتم تمريرها إلى
        مكتبة Fontconfig FcNameParse()).

  

  
XftFont *XftFontOpenXlfd (

  

    
	Display	*dpy,
	int	 screen,
	_Xconst char	*xlfd)


    
XftFontOpenXlfd يعمل كما يفعل XftFontOpen،
        باستثناء أنه يأخذ سلسلة تحتوي على وصف خط X المنطقي (XLFD)، ويستخدم
        الدالة XftXlfdParse().

  

  
FcPattern *XftFontMatch (

  

    
	Display	*dpy,
	int	 screen,
	_Xconst FcPattern	*pattern,
	FcResult	*result);


    
تُستخدم أيضًا داخليًا بواسطة الدوال XftFontOpen*،
        يمكن أيضًا استخدام XftFontMatch مباشرة لتحديد نمط خط
        Xft الناتج عن طلب فتح خط Xft.

  

  
FcPattern *XftXlfdParse (

  

    
	_Xconst char	*xlfd_orig,
	Bool	ignore_scalable,
	Bool	complete);


    
تقوم XftXlfdParse بتحليل المعامل xlfd_orig
        وفقًا لوثيقة X Logical Font Description Conventions،
        ولكنها تتجاهل بعض الحقول: setwidth_name،
        add_style_name، spacing، و average_width.

  





  

  
تقوم XftXlfdParse بإنشاء نمط Fontconfig، وتعيين الخاصية
      XFT_XLFD إلى قيمة xlfd_orig، وتربط المعلومات التي تم
      جمعها بخصائص Fontconfig. يتم تجاهل الحقول الفارغة أو "*":







  
FC_FOUNDRY

  
من foundry.

  
FC_FAMILY

  
من family.

  
FC_WEIGHT

  
weight_name، الافتراضي هو FC_WEIGHT_MEDIUM.

  
FC_SLANT

  
من slant، الافتراضي هو FC_SLANT_ROMAN.

  
FC_SIZE

  
من point_size.

  
FC_PIXEL_SIZE

  
من pixel_size. إذا تم تعيين point_size، بالإضافة إلى
      resolution_x و resolution_y، فإن القيمة يتم قياسها
      لتحويل ارتفاع الخط إلى نقاط.

void XftDrawGlyphFontSpec (

  

    
	XftDraw	*draw,
	_Xconst XftColor	*color,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 len);


    
Draw a list of glyphs associated with fonts at specified
        coordinates, passed as an array of len XftGlyphFontSpec
        structures via the parameter glyphs. All of the glyphs are drawn
        using the color specified in the color parameter.

  





  

  
For each entry in the glyphs array:






    
  
  • If the associated font uses the X Render extension, then Xft uses
      XftGlyphFontSpecRender() to draw the glyph, using a Picture
      obtained from calling XftDrawSrcPicture () with the draw and
      color parameters.
    • 
  
  • Otherwise, Xft provides an analogous feature using Xlib.
    • 






  
void XftGlyphFontSpecRender (

  

    
	Display	*dpy,
	int	 op,
	Picture	 src,
	Picture	 dst,
	int	 srcx,
	int	 srcy,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 nglyphs);


    
This involves several steps:

  






    
  
  • First, Xft ensures that the glyphs array is complete using
      XftFontCheckGlyph() and loading any missing glyphs with
      XftFontLoadGlyphs().
    • 
  
  • Then Xft examines the glyphs to find the maximum Unicode value.
      That determines the encoding size, i.e., the width.
    • 
  
  • Then, for each glyph, Xft checks if its Unicode value is handled by
      the corresponding font. If not, the value is set to zero (0), to ignore
      it. While doing this, Xft also remembers which was the first font
      used, and computes the position at which each glyph will be drawn.
    • 
  
  • Xft then constructs an equivalent array of glyphs in the format
      expected by the X Render library.
    • 
  
  • Finally, XftGlyphFontSpecRender() uses the X Render extension to
      draw the glyphs, with the appropriate XRenderCompositeText*()
      function according to the width, and discards temporary data.
    • 




  

  
The op, dst, src, srcx, and srcy
      parameters are used as described in the documentation for the X Render
      library.

DESCRIPTION


The XftDrawString functions draw a string of characters onto
    the specified drawable. The characters are taken from the given font, and
    rendered using the specified color. The string is drawn starting at the
    coordinate (x, y).


The string parameter points to an array of characters. The
    length of the string in characters is given by len.


XftDrawString8 takes a string of 8-bit characters.
    XftDrawString16 takes a string of 16-bit characters.
    XftDrawString32 takes a string of 32-bit characters.


The character encoding is determined by the font. For 8-bit
    strings, the encoding is typically ISO-8859-1. For 16-bit and 32-bit strings,
    the encoding is UCS-2 and UCS-4, respectively. The library will convert the
    character encoding to the font's internal format as needed.


The color parameter specifies the foreground color for the
    text. If it is NULL, the current foreground color of the drawable is
    used.


The font parameter specifies the font to use for rendering
    the text. The font must have been previously opened using
    XftFontOpen() or XftFontOpenName().


The draw parameter specifies the drawable onto which the
    text will be drawn.


If len is negative, the string is null-terminated and its
    length is determined by the standard string functions.


These functions use the X Render extension if available. Otherwise,
    they use the X core protocol.
