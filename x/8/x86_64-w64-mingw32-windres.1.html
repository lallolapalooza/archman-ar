WINDRES(1) أدوات تطوير GNU WINDRES(1)

الاسم

windres - معالجة موارد Windows

ملخص

windres [خيارات] [ملف الإدخال] [ملف الإخراج]

الوصف

يقرأ windres الموارد من ملف إدخال وينسخها إلى ملف إخراج. يمكن لأي من الملفين أن يكون بأحد التنسيقات الثلاثة:

"rc"
تنسيق نصي يقرأه مترجم الموارد (Resource Compiler).
"res"
تنسيق ثنائي تم إنشاؤه بواسطة مترجم الموارد.
"coff"
كائن COFF أو ملف تنفيذي.

الوصف الدقيق لهذه التنسيقات المختلفة متاح في الوثائق الخاصة بمايكروسوفت.

عندما يحول windres من تنسيق "rc" إلى تنسيق "res"، فإنه يتصرف مثل مترجم الموارد لنظام Windows. عندما يحول windres من تنسيق "res" إلى تنسيق "coff"، فإنه يتصرف مثل برنامج "CVTRES" الخاص بنظام Windows.

عندما ينشئ windres ملف "rc"، يكون الإخراج مشابهًا للتنسيق المتوقع للإدخال ولكنه ليس مطابقًا تمامًا. عندما يشير ملف إدخال "rc" إلى اسم ملف خارجي، فإن ملف "rc" الإخراج سيحتوي بدلاً من ذلك على محتويات الملف.

إذا لم يتم تحديد تنسيق الإدخال أو الإخراج، سيقوم windres بالتخمين بناءً على اسم الملف، أو، بالنسبة لملف الإدخال، محتويات الملف. سيتم التعامل مع ملف بامتداد .rc كملف "rc"، وسيتم التعامل مع ملف بامتداد .res كملف "res"، وسيتم التعامل مع ملف بامتداد .o أو .exe كملف "coff".

إذا لم يتم تحديد ملف إخراج، سيقوم windres بطباعة الموارد بتنسيق "rc" إلى المخرج القياسي.

الاستخدام العادي هو أن تكتب ملف "rc"، وتستخدم windres لتحويله إلى ملف كائن COFF، ثم تربط ملف COFF بتطبيقك. سيؤدي هذا إلى جعل الموارد الموصوفة في ملف "rc" متاحة لنظام Windows.

الخيارات

-i اسم الملف
--input اسم الملف
اسم ملف الإدخال. إذا لم يتم استخدام هذا الخيار، فسيستخدم windres أول وسيط غير خيار كاسم لملف الإدخال. إذا لم تكن هناك وسائط غير خيارات، فسيقرأ windres من الإدخال القياسي. لا يمكن لـ windres قراءة ملف COFF من الإدخال القياسي.
-o اسم الملف
--output اسم الملف
اسم ملف الإخراج. إذا لم يتم استخدام هذا الخيار، فسيستخدم windres أول وسيط غير خيار، بعد أي وسيط مستخدم لاسم ملف الإدخال، كاسم لملف الإخراج. إذا لم يكن هناك وسيط غير خيار، فسيكتب windres إلى المخرج القياسي. لا يمكن لـ windres كتابة ملف COFF إلى المخرج القياسي. ملاحظة، للتوافق مع rc، يتم قبول الخيار -fo أيضًا، ولكن لا يُنصح باستخدامه.
-J التنسيق
--input-format التنسيق
تنسيق الإدخال للقراءة. يمكن أن يكون التنسيق res أو rc أو coff. إذا لم يتم تحديد تنسيق الإدخال، فسيقوم windres بالتخمين، كما هو موضح أعلاه.
-O التنسيق
--output-format التنسيق
تنسيق الإخراج الذي سيتم إنشاؤه. يمكن أن يكون التنسيق res أو rc أو coff. إذا لم يتم تحديد تنسيق الإخراج، فسيقوم windres بالتخمين، كما هو موضح أعلاه.
-F الهدف
--target الهدف
تحديد تنسيق BFD لاستخدامه كملف COFF للإدخال أو الإخراج. هذا اسم هدف BFD؛ يمكنك استخدام خيار --help لرؤية قائمة بالأهداف المدعومة. عادةً ما يستخدم windres التنسيق الافتراضي، وهو الأول المدرج بواسطة خيار --help.
--preprocessor البرنامج
عندما يقرأ windres ملف "rc"، فإنه يقوم بتشغيله من خلال معالج C المسبق أولاً. يمكن استخدام هذا الخيار لتحديد المعالج المسبق المراد استخدامه. المعالج المسبق الافتراضي هو "gcc".
--preprocessor-arg الخيار
عندما يقرأ windres ملف "rc"، فإنه يقوم بتشغيله من خلال معالج C المسبق أولاً. يمكن استخدام هذا الخيار لتحديد نص إضافي يتم تمريره إلى المعالج المسبق على سطر أوامره. يمكن استخدام هذا الخيار عدة مرات لإضافة خيارات متعددة إلى سطر أوامر المعالج المسبق. إذا لم يتم تحديد خيار --preprocessor، فسيتم استخدام مجموعة افتراضية من وسائط المعالج المسبق، مع وضع أي خيارات --preprocessor-arg بعدها في سطر الأوامر. هذه الوسائط الافتراضية هي "-E"، "-xc-header" و "-DRC_INVOKED".
-I الدليل
--include-dir الدليل
تحديد دليل تضمين لاستخدامه عند قراءة ملف "rc". سيمرر windres هذا إلى المعالج المسبق كخيار -I. سيبحث windres أيضًا في هذا الدليل عند البحث عن الملفات المسماة في ملف "rc". إذا تطابق الوسيط الممرر لهذا الأمر مع أي من التنسيقات المدعومة (كما هو موضح في خيار -J)، فسيصدر تحذيرًا بالتقادم، ويتصرف تمامًا مثل خيار -J. لا ينبغي للبرامج الجديدة استخدام هذا السلوك. إذا تطابق دليل ما مع تنسيق، فقم ببساطة بإضافة بادئة ./ إليه لتعطيل التوافق الخلفي.
-D الهدف
--define الرمز[=القيمة]
تحديد خيار -D لتمريره إلى المعالج المسبق عند قراءة ملف "rc".
-U الهدف
--undefine الرمز
تحديد خيار -U لتمريره إلى المعالج المسبق عند قراءة ملف "rc".
-r
تم تجاهله للتوافق مع rc.
-v
تمكين وضع الإسهاب. هذا يخبرك ما هو المعالج المسبق إذا لم تحدد واحدًا.
-c القيمة
--codepage القيمة
تحديد صفحة الترميز الافتراضية لاستخدامها عند قراءة ملف "rc". يجب أن تكون القيمة بادئة برمز سداسي عشري مسبوق بـ 0x أو رمز صفحة ترميز عشري. النطاق الصالح من صفر حتى 0xffff، ولكن صلاحية صفحة الترميز تعتمد على المضيف والتكوين.
-l القيمة
--language القيمة
تحديد اللغة الافتراضية لاستخدامها عند قراءة ملف "rc". يجب أن تكون القيمة رمز لغة سداسي عشري. الأثمان الثمانية المنخفضة هي اللغة، والأثمان الثمانية العليا هي اللغة الفرعية.
--use-temp-file
استخدام ملف مؤقت بدلاً من استخدام popen لقراءة مخرجات المعالج المسبق. استخدم هذا الخيار إذا كان تنفيذ popen به خلل في المضيف (على سبيل المثال، بعض إصدارات اللغة غير الإنجليزية من Windows 95 و Windows 98
windres(1) - Arch Linux

NAME

windres-1.0.0

SYNOPSIS

windres [-o output-file] [--target=bfdname] [-i input-file] [-i input-file] ...

DESCRIPTION

The windres program is a resource compiler for Microsoft Windows. It takes Windows resource files (— files containing definitions of icons, bitmaps, dialogs, strings, etc. —) and compiles them into a binary format that can be linked into Windows executables.

OPTIONS

-o output-file
Write output to output-file instead of stdout.
--target=bfdname
This is used to specify the target type. For example, "--target=pe-i386". The default is "pe-i386".
-i input-file
Process the resource script file input-file. This option can be repeated to process multiple resource script files. If no -i option is given, then windres will read from standard input.
--no-use-temp-file
Use popen, not a temporary file, to read the output of the preprocessor. This is the default behaviour. Some old versions of popen are known to have buggy popen where the output will instead go the console).
-h
--help
Prints a usage summary.
-V
--version
Prints the version number for windres.
--yydebug
If windres is compiled with "YYDEBUG" defined as 1, this will turn on parser debugging.
@file
Read command-line options from file. The options read are inserted in place of the original @file option. If file does not exist, or cannot be read, then the option will be treated literally, and not removed.

Options in file are separated by whitespace. A whitespace character may be included in an option by surrounding the entire option in either single or double quotes. Any character (including a backslash) may be included by prefixing the character to be included with a backslash. The file may itself contain additional @file options; any such options will be processed recursively.
