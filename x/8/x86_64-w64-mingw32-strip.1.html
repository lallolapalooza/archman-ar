الاسم

strip - تجاهل الرموز والبيانات الأخرى من الملفات الكائنية

الملخص

strip [-F اسم_bfd |--target=اسم_bfd]
[-I اسم_bfd |--input-target=اسم_bfd]
[-O اسم_bfd |--output-target=اسم_bfd]
[-s|--strip-all]
[-S|-g|-d|--strip-debug]
[--strip-dwo]
[-K اسم_الرمز|--keep-symbol=اسم_الرمز]
[-M|--merge-notes][--no-merge-notes]
[-N اسم_الرمز |--strip-symbol=اسم_الرمز]
[-w|--wildcard]
[-x|--discard-all] [-X |--discard-locals]
[-R اسم_المقطع |--remove-section=اسم_المقطع]
[--keep-section=نمط_المقطع]
[--remove-relocations=نمط_المقطع]
[--strip-section-headers]
[-o ملف] [-p|--preserve-dates]
[-D|--enable-deterministic-archives]
[-U|--disable-deterministic-archives]
[--keep-section-symbols]
[--keep-file-symbols]
[--only-keep-debug]
[--plugin الاسم]
[-v |--verbose] [-V|--version]
[--help] [--info]
ملف_كائني...

الوصف

تقوم أداة strip الخاصة بـ GNU بتجاهل جميع الرموز من الملفات الكائنية ملف_كائني. قد تشمل قائمة الملفات الكائنية الأرشيفات. يجب تقديم ملف كائني واحد على الأقل.

تقوم strip بتعديل الملفات المسماة في معاملاتها، بدلاً من كتابة نسخ معدلة بأسماء مختلفة.

الخيارات

-F اسم_bfd
--target=اسم_bfd
عامل الملف الأصلي ملف_كائني كملف بتنسيق الشفرة الكائنية اسم_bfd، وأعد كتابته بنفس التنسيق.
--help
عرض ملخص للخيارات المتاحة لـ strip والخروج.
--info
عرض قائمة توضح جميع البنى المعمارية وتنسيقات الكائنات المتاحة.
-I اسم_bfd
--input-target=اسم_bfd
عامل الملف الأصلي ملف_كائني كملف بتنسيق الشفرة الكائنية اسم_bfd.
-O اسم_bfd
--output-target=اسم_bfd
استبدل ملف_كائني بملف بتنسيق الإخراج اسم_bfd.
-R اسم_المقطع
--remove-section=اسم_المقطع
إزالة أي قسم مسمى اسم_المقطع من ملف الإخراج، بالإضافة إلى أي أقسام أخرى قد تتم إزالتها بخلاف ذلك. يمكن تقديم هذا الخيار أكثر من مرة. لاحظ أن استخدام هذا الخيار بشكل غير مناسب قد يجعل ملف الإخراج غير قابل للاستخدام. يمكن تقديم حرف البدل * في نهاية اسم_المقطع. إذا كان الأمر كذلك، فسيتم إزالة أي قسم يبدأ بـ اسم_المقطع.

إذا كان الحرف الأول من نمط_المقطع هو علامة التعجب (!)، فلن تتم إزالة الأقسام المطابقة حتى لو أدت استخدامات سابقة لـ --remove-section في نفس سطر الأوامر إلى إزالتها.

--remove-section=.text.* --remove-section=!.text.foo

سيؤدي هذا إلى إزالة جميع الأقسام التي تطابق النمط '.text.*'، ولكنه لن يزيل القسم '.text.foo'.

--keep-section=نمط_المقطع
عند إزالة الأقسام من ملف الإخراج، احتفظ بالأقسام التي تطابق نمط_المقطع.
--remove-relocations=نمط_المقطع
إزالة عمليات إعادة التوطين من ملف الإخراج لأي قسم مطابق لـ نمط_المقطع. يمكن تقديم هذا الخيار أكثر من مرة. لاحظ أن استخدام هذا الخيار بشكل غير مناسب قد يجعل ملف الإخراج غير قابل للاستخدام. تقبل أحرف البدل في نمط_المقطع. على سبيل المثال: 
--remove-relocations=.text.*

سيؤدي هذا إلى إزالة عمليات إعادة التوطين لجميع الأقسام المطابقة للنمط '.text.*'.

إذا كان الحرف الأول من نمط_المقطع هو علامة التعجب (!)، فلن تتم إزالة عمليات إعادة التوطين للأقسام المطابقة حتى لو أدت استخدامات سابقة لـ --remove-relocations في نفس سطر الأوامر إلى إزالة عمليات إعادة التوطين.

--remove-relocations=.text.* --remove-relocations=!.text.foo

سيؤدي هذا إلى إزالة جميع عمليات إعادة التوطين للأقسام التي تطابق النمط '.text.*'، ولكنه لن يزيل عمليات إعادة التوطين للقسم '.text.foo'.

--strip-section-headers
إزالة رؤوس الأقسام. هذا الخيار خاص بملفات ELF. يعني ضمنياً --strip-all و --merge-notes.
-s
--strip-all
إزالة جميع الرموز.
-g
-S
-d
--strip-debug
إزالة رموز التصحيح فقط.
--strip-dwo
إزالة محتويات جميع أقسام DWARF .dwo، مع ترك أقسام التصحيح المتبقية وجميع الرموز سليمة. راجع وصف هذا الخيار في قسم objcopy لمزيد من المعلومات.
--strip-unneeded
إزالة جميع الرموز غير الضرورية لمعالجة إعادة التوطين بالإضافة إلى رموز التصحيح والأقسام التي تم تجريدها بواسطة --strip-debug.
-K اسم_الرمز
--keep-symbol=اسم_الرمز
عند تجريد الرموز، احتفظ بالرمز اسم_الرمز حتى لو كان سيتم تجريده عادةً. يمكن تقديم هذا الخيار أكثر من مرة.
-M
--merge-notes
--no-merge-notes
بالنسبة لملفات ELF، حاول (أو لا تحاول) تقليل حجم أقسام النوع SHT_NOTE عن طريق إزالة الملاحظات المكررة. الافتراضي هو محاولة هذا التقليل ما لم يتم تجريد معلومات التصحيح أو DWO.
-N اسم_الرمز
--strip-symbol=اسم_الرمز
إزالة الرمز اسم_الرمز من الملف المصدر. يمكن تقديم هذا الخيار أكثر من مرة، ويمكن دمجه مع خيارات التجريد بخلاف -K.
-o ملف
ضع الإخراج المجرد في ملف، بدلاً من استبدال الملف الحالي. عند استخدام هذه الوسيطة، يمكن تحديد وسيطة ملف_كائني واحدة فقط.
-p
--preserve-dates
احتفظ بتواريخ الوصول والتعديل للملف.
-D
--enable-deterministic-archives
العمل في وضع الحتمية. عند نسخ أعضاء الأرشيف وكتابة فهرس الأرشيف، استخدم الصفر لمعرفات المستخدم (UIDs) ومعرفات المجموعة (GIDs) والطوابع الزمنية، واستخدم أوضاع ملفات متسقة لجميع الملفات.

إذا تم تكوين binutils باستخدام --enable-deterministic-archives، فإن هذا الوضع يكون ممكّنًا بشكل افتراضي. يمكن تعطيله باستخدام الخيار -U، أدناه.

-U
--disable-deterministic-archives
لا تعمل في وضع الحتمية.

هذا هو الوضع الافتراضي، ما لم يتم تكوين binutils مع --enable-deterministic-archives.

--keep-section-symbols
احتفظ بالرموز الخاصة بالأقسام. يتم تجريدها افتراضياً.
--keep-file-symbols
احتفظ بالرموز الخاصة بالملفات. يتم تجريدها افتراضياً.
--only-keep-debug
تجريد جميع الرموز والبيانات باستثناء تلك الموجودة في أقسام التصحيح. تُستخدم هذه الميزة عادةً لإنشاء ملف منفصل يحتوي على معلومات التصحيح فقط.
--plugin الاسم
تحميل البرنامج المساعد الاسم. سيوفر هذا البرنامج المساعد وظائف إضافية يمكن استخدامها مع strip.
-V
--version
عرض معلومات الإصدار لـ strip والخروج.
-v
--verbose
تمكين وضع الإسهاب. سيؤدي ذلك إلى إظهار المزيد من المعلومات حول عملية التجريد.
-w
--wildcard
تفسير الرموز أو الأقسام التي تحتوي على أحرف بدل (مثل `*` و `؟`) كأنماط تطابق الأسماء.
-x
--discard-all
إزالة جميع الرموز غير الضرورية.
-X
--discard-locals
إزالة جميع الرموز المحلية.

strip(1) — mingw-w64-binutils documentation

NAME

strip - remove symbols from object files

SYNOPSIS

strip [OPTION...] [FILE...

DESCRIPTION

The strip utility deletes symbol table entries from object files. It can also be used to strip other information from object files, such as debugging information.

This version of strip operates on object files and archives. It is part of the GNU binary utilities.

Object files are processed in the order they are specified on the command line. If no files are specified, or if a file is -, then the standard input is read.

OPTIONS

-a
--discard-all
Remove all symbol-processing sections. This is equivalent to strip --discard-all.
-A
--discard-all
Remove all symbol-processing sections.
-c
--discard-none
Do not remove any symbol-processing sections.
-d
--discard-locals
Remove compiler-generated local symbols. (These usually start with L or ..)
--strip-debug
Remove debugging symbols from the object file. This is equivalent to strip --discard-type=debuginfostrip.
-g
--strip-debug
Remove debugging symbols from the object file.
-h
--help
Show the help message and exit.
-i
--info-strip
Remove debugging symbols, as with -s, but also remove the .comment section. This is equivalent to strip --discard-type=infostrip.
-k
--keep-symbol=symbolname
Do not discard the symbol symbolname. This option can be specified multiple times.
-K
--keep-global=symbolname
Do not discard the global symbol symbolname. This option can be specified multiple times.
-n
--strip-unneeded
Remove all symbols, except for those that are used in the relocation entries. This is equivalent to strip --discard-type=unneededstrip.
-N
--strip-symbol=symbolname
Discard the symbol symbolname. This option can be specified multiple times.
-G
--strip-global=symbolname
Discard the global symbol symbolname. This option can be specified multiple times.
-p
--no-debuginfod
Do not write debug symbol information to the separate file when using strip with the --extract-symbol option.
-P
--strip-specific-symbol=symbolname
Discard the symbol symbolname only if it is a specific symbol type (e.g. a local symbol). This option can be specified multiple times.
-s
--strip-symbols
Remove debugging symbols from the object file. This is equivalent to strip --discard-type=debuginfostrip.
-t
--strip-symbol-table
Remove the entire symbol table. This is equivalent to strip --discard-type=stripall.
--extract-symbol=symbolname
Keep only the specified symbol symbolname. This option can be specified multiple times.
-u
--discard-unneeded
Remove all symbols, except for those that are used in the relocation entries.
-v
--verbose
Verbose output: list all object files modified. In the case of archives, strip -v lists all members of the archive.
-w
--wildcard
Permit regular expressions in symbolnames used in other command line options. The question mark (?), asterisk (*), backslash (\) and square brackets ([]) operators can be used anywhere in the symbol name. If the first character of the symbol name is the exclamation point (!) then the sense of the switch is reversed for that symbol. For example: 
-w -K !foo -K fo*
would cause strip to only keep symbols that start with the letters "fo", but to discard the symbol "foo".
-x
--discard-all
Remove non-global symbols.
-X
--discard-locals
Remove compiler-generated local symbols. (These usually start with L or ..)
--keep-section-symbols
When stripping a file, perhaps with --strip-debug or --strip-unneeded, retain any symbols specifying section names, which would otherwise get stripped.
--keep-file-symbols
When stripping a file, perhaps with --strip-debug or --strip-unneeded, retain any symbols specifying source file names, which would otherwise get stripped.
--only-keep-debug
Strip a file, emptying the contents of any sections that would not be stripped by --strip-debug and leaving the debugging sections intact. In ELF files, this preserves all the note sections in the output as well.

Note - the section headers of the stripped sections are preserved, including their sizes, but the contents of the section are discarded. The section headers are preserved so that other tools can match up the debuginfo file with the real executable, even if that executable has been relocated to a different address space.

The intention is that this option will be used in conjunction with --add-gnu-debuglink to create a two part executable. One a stripped binary which will occupy less space in RAM and in a distribution and the second a debugging information file which is only needed if debugging abilities are required. The suggested procedure to create these files is as follows:

1.<Link the executable as normal. Assuming that it is called>
"foo" then...
1.<Run "objcopy --only-keep-debug foo foo.dbg" to>
create a file containing the debugging info.
1.<Run "objcopy --strip-debug foo" to create a>
stripped executable.
1.<Run "objcopy --add-gnu-debuglink=foo.dbg foo">
to add a link to the debugging info into the stripped executable.

Note---the choice of ".dbg" as an extension for the debug info file is arbitrary. Also the "--only-keep-debug" step is optional. You could instead do this:

1.<Link the executable as normal.>
1.<Copy "foo" to "foo.full">
1.<Run "strip --strip-debug foo">
1.<Run "objcopy --add-gnu-debuglink=foo.full foo">

i.e., the file pointed to by the --add-gnu-debuglink can be the full executable. It does not have to be a file created by the --only-keep-debug switch.

Note---this switch is only intended for use on fully linked files. It does not make sense to use it on object files where the debugging information may be incomplete. Besides the gnu_debuglink feature currently only supports the presence of one filename containing debugging information, not multiple filenames on a one-per-object-file basis.

--plugin name
Load the plugin called name to add support for extra target types. This option is only available if the toolchain has been built with plugin support enabled.

If --plugin is not provided, but plugin support has been enabled then strip iterates over the files in ${libdir}/bfd-plugins in alphabetic order and the first plugin that claims the object in question is used.

Please note that this plugin search directory is not the one used by ld's -plugin option. In order to make strip use the linker plugin it must be copied into the ${libdir}/bfd-plugins directory. For GCC based compilations the linker plugin is called liblto_plugin.so.0.0.0. For Clang based compilations it is called LLVMgold.so. The GCC plugin is always backwards compatible with earlier versions, so it is sufficient to just copy the newest one.

-V
--version
Show the version number for strip.
-v
--verbose
Verbose output: list all object files modified. In the case of archives, strip -v lists all members of the archive.
@file
Read command-line options from file. The options read are inserted in place of the original @file option. If file does not exist, or cannot be read, then the option will be treated literally, and not removed.

Options in file are separated by whitespace. A whitespace character may be included in an option by surrounding the entire option in either single or double quotes. Any character (including a backslash) may be included by prefixing the character to be included with a backslash. The file may itself contain additional @file options; any such options will be processed recursively.
