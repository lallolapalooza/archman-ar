NAME

ar - create, modify, and extract from archives

SYNOPSIS

ar [-X32_64] [-]p[mod] [--plugin name] [--target bfdname] [--output dirname] [--record-libdeps libdeps] [--thin] [relpos] [count] archive [member...]

DESCRIPTION

The GNU ar program creates, modifies, and extracts from archives. An archive is a single file holding a collection of other files in a structure that makes it possible to retrieve the original individual files (called members of the archive).

The original files' contents, mode (permissions), timestamp, owner, and group are preserved in the archive, and can be restored on extraction.

GNU ar can maintain archives whose members have names of any length; however, depending on how ar is configured on your system, a limit on member-name length may be imposed for compatibility with archive formats maintained with other tools. If it exists, the limit is often 15 characters (typical of formats related to a.out) or 16 characters (typical of formats related to coff).

ar is considered a binary utility because archives of this sort are most often used as libraries holding commonly needed subroutines. Since libraries often will depend on other libraries, ar can also record the dependencies of a library when the --record-libdeps option is specified.

ar creates an index to the symbols defined in relocatable object modules in the archive when you specify the modifier s. Once created, this index is updated in the archive whenever ar makes a change to its contents (save for the q update operation). An archive with such an index speeds up linking to the library, and allows routines in the library to call each other without regard to their placement in the archive.

You may use nm -s or nm --print-armap to list this index table. If an archive lacks the table, another form of ar called ranlib can be used to add just the table.

GNU ar can optionally create a thin archive, which contains a symbol index and references to the original copies of the member files of the archive. This is useful for building libraries for use within a local build tree, where the relocatable objects are expected to remain available, and copying the contents of each object would only waste time and space.

An archive can either be thin or it can be normal. It cannot be both at the same time. Once an archive is created its format cannot be changed without first deleting it and then creating a new archive in its place.

Thin archives are also flattened, so that adding one thin archive to another thin archive does not nest it, as would happen with a normal archive. Instead the elements of the first archive are added individually to the second archive.

The paths to the elements of the archive are stored relative to the archive itself.

GNU ar is designed to be compatible with two different facilities. You can control its activity using command-line options, like the different varieties of ar on Unix systems; or, if you specify the single command-line option -M, you can control it with a script supplied via standard input, like the MRI "librarian" program.

OPTIONS

GNU ar allows you to mix the operation code p and modifier flags mod in any order, within the first command-line argument.

If you wish, you may begin the first command-line argument with a dash.

The p keyletter specifies what operation to execute; it may be any of the following, but you must specify only one of them:

d
Delete modules from the archive. Specify the names of modules to be deleted as member...; the archive is untouched if you specify no files to delete.

If you specify the v modifier, ar lists each module as it is deleted.

m
Use this operation to move members in an archive.

The ordering of members in an archive can make a difference in how programs are linked using the library, if a symbol is defined in more than one member.

If no modifiers are used with "m", any members you name in the member arguments are moved to the end of the archive; you can use the a, b, or i modifiers to move them to a specified place instead.

p
Print the specified members of the archive, to the standard output file. If the v modifier is specified, show the member name before copying its contents to standard output.

If you specify no member arguments, all the files in the archive are printed.

q
Quick append; Historically, add the files member... to the end of archive, without checking for replacement.

The modifiers a, b, and i do not affect this operation; new members are always placed at the end of the archive.

The modifier v makes ar list each file as it is appended.

Since the point of this operation is speed, implementations of ar have the option of not updating the archive's symbol table if one exists. Too many different systems however assume that symbol tables are always up-to-date, so GNU ar will rebuild the table even with a quick append.

Note - GNU ar treats the command qs as a synonym for r - replacing already existing files in the archive and appending new ones at the end.

r
Insert the files member... into archive (with replacement). This operation differs from q in that any previously existing members are deleted if their names match those being added.

If one of the files named in member... does not exist, ar displays an error message, and leaves undisturbed any existing members of the archive matching that name.

By default, new members are added at the end of the file; but you may use one of the modifiers a, b, or i to request placement relative to some existing member.

The modifier v used with this operation elicits a line of output for each file inserted, along with one of the letters a or r to indicate whether the file was appended (no old member deleted) or replaced.

s
Add an index to the archive, or update it if it already exists. Note this command is an exception to the rule that there can only be one command letter, as it is possible to use it as either a command or a modifier. In either case it does the same thing.
t
Display a table listing the contents of archive, or those of the files listed in member... that are present in the archive. Normally only the member name is shown, but if the modifier O is specified, then the corresponding offset of the member is also displayed. Finally, in order to see the modes (permissions), timestamp, owner, group, and size the v modifier should be included.

If you do not specify a member, all files in the archive are listed.

If there is more than one file with the same name (say, fie) in an archive (say b.a), ar t b.a fie lists only the first instance; to see them all, you must ask for a complete listing---in our example, ar t b.a.

x
Extract members (named member) from the archive. You can use the v modifier with this operation, to request that ar list each name as it extracts it.

If you do not specify a member, all files in the archive are extracted.

مطلق، ولا يجوز أن يحتوي على ".."، ويجب أن تكون الدلائل الفرعية في المسارات موجودة. إذا كان المراد تجنب هذه القيود، فاستخدم الخيار --output لتحديد دليل إخراج.

يمكن أن يتبع حرف المفتاح p مباشرة عدد من المعدلات (mod) لتحديد تنويعات على سلوك العملية:

a
أضف ملفات جديدة بعد عضو موجود في الأرشيف. إذا استخدمت المعدل a، يجب أن يكون اسم عضو أرشيف موجود موجودًا كوسيط relpos، قبل تحديد archive.
b
أضف ملفات جديدة قبل عضو موجود في الأرشيف. إذا استخدمت المعدل b، يجب أن يكون اسم عضو أرشيف موجود موجودًا كوسيط relpos، قبل تحديد archive. (نفس i).
c
أنشئ الأرشيف. يتم دائمًا إنشاء archive المحدد إذا لم يكن موجودًا، عندما تطلب تحديثًا. ولكن يتم إصدار تحذير ما لم تحدد مسبقًا أنك تتوقع إنشاؤه، باستخدام هذا المعدل.
D
العمل في وضع الحتمية. عند إضافة ملفات وفهرس الأرشيف، استخدم صفرًا لمعرفات المستخدم (UIDs) ومعرفات المجموعة (GIDs) والطوابع الزمنية، واستخدم أوضاع ملفات متسقة لجميع الملفات. عند استخدام هذا الخيار، إذا تم استخدام ar بنفس الخيارات وملفات الإدخال المتطابقة، فإن عمليات التشغيل المتعددة ستنشئ ملفات إخراج متطابقة بغض النظر عن مالكي ملفات الإدخال، أو مجموعاتها، أو أوضاع الملفات، أو أوقات التعديل.

إذا تم تكوين binutils باستخدام --enable-deterministic-archives، فإن هذا الوضع يكون نشطًا افتراضيًا. يمكن تعطيله باستخدام المعدل U، أدناه.

f
اقتطع الأسماء في الأرشيف. يسمح ar الخاص بـ GNU عادةً بأسماء ملفات بأي طول. سيؤدي هذا إلى إنشاء أرشيفات غير متوافقة مع برنامج ar الأصلي على بعض الأنظمة. إذا كان هذا يمثل مشكلة، فيمكن استخدام المعدل f لاقتطاع أسماء الملفات عند وضعها في الأرشيف.
i
أدخل ملفات جديدة قبل عضو موجود في الأرشيف. إذا استخدمت المعدل i، يجب أن يكون اسم عضو أرشيف موجود موجودًا كوسيط relpos، قبل تحديد archive. (نفس b).
l
حدد تبعيات هذه المكتبة. يجب أن تتبع التبعيات مباشرة حرف الخيار هذا، ويجب أن تستخدم نفس صيغة سطر أوامر الرابط، ويجب تحديدها ضمن وسيط واحد. أي، إذا كانت هناك حاجة إلى عناصر متعددة، فيجب اقتباسها لتشكيل وسيط سطر أوامر واحد. على سبيل المثال l "-L/usr/local/lib -lmydep1 -lmydep2"
N
يستخدم الوسيط count. يتم استخدامه إذا كان هناك إدخالات متعددة في الأرشيف بنفس الاسم. استخراج أو حذف المثيل count للاسم المعطى من الأرشيف.
o
احتفظ بالتواريخ الأصلية للأعضاء عند استخراجها. إذا لم تحدد هذا المعدل، فسيتم ختم الملفات المستخرجة من الأرشيف بوقت الاستخراج.
O
اعرض إزاحات الأعضاء داخل الأرشيف. استخدم مع خيار t.
P
استخدم اسم المسار الكامل عند مطابقة أو تخزين الأسماء في الأرشيف. الأرشيفات المنشأة بأسماء مسارات كاملة ليست متوافقة مع POSIX، وبالتالي قد لا تعمل مع أدوات أخرى غير الأدوات الحديثة لـ GNU. سيؤدي تعديل مثل هذه الأرشيفات باستخدام ar الخاص بـ GNU دون استخدام P إلى إزالة أسماء المسارات الكاملة ما لم يكن الأرشيف أرشيفًا رفيعًا (thin archive). لاحظ أن P قد يكون مفيدًا عند إضافة ملفات إلى أرشيف رفيع لأن r بدون P يتجاهل المسار عند اختيار العنصر الذي سيتم استبداله. وبالتالي 
ar rcST archive.a subdir/file1 subdir/file2 file1

سيؤدي إلى استبدال subdir/file1 الأولى بـ file1 من الدليل الحالي. سيمنع إضافة P هذا الاستبدال.

s
اكتب فهرس ملف الكائن في الأرشيف، أو قم بتحديث الفهرس الموجود، حتى لو لم يتم إجراء أي تغيير آخر على الأرشيف. يمكنك استخدام علامة المعدل هذه إما مع أي عملية، أو بمفردها. تشغيل ar s على أرشيف يعادل تشغيل ranlib عليه.
S
لا تقم بإنشاء جدول رموز الأرشيف. يمكن أن يؤدي هذا إلى تسريع بناء مكتبة كبيرة على عدة خطوات. لا يمكن استخدام الأرشيف الناتج مع الرابط. لبناء جدول رموز، يجب عليك حذف المعدل S في آخر تنفيذ لـ ar، أو يجب عليك تشغيل ranlib على الأرشيف.
T
اسم مستعار مهمل لـ --thin. لا يُنصح باستخدام T لأنه في العديد من تطبيقات ar، يكون لـ T معنى مختلف، كما هو محدد بواسطة واجهة نظام X/Open.
u
عادةً، تقوم ar r... بإدراج جميع الملفات المدرجة في الأرشيف. إذا كنت ترغب في إدراج الملفات التي تسردها فقط والتي تكون أحدث من الأعضاء الموجودين بنفس الأسماء، فاستخدم هذا المعدل. يُسمح بالمعدل u فقط لعملية r (استبدال). على وجه الخصوص، لا يُسمح بالجمع qu، حيث أن التحقق من الطوابع الزمنية سيفقد أي ميزة سرعة من العملية q.

ملاحظة - إذا تم إنشاء أرشيف بطريقة حتمية، على سبيل المثال عبر استخدام المعدل D، فسيحدث الاستبدال دائمًا ولن يكون للمعدل u أي تأثير.

U
لا تعمل في وضع الحتمية. هذا هو عكس المعدل D، أعلاه: ستتلقى الملفات المضافة وفهرس الأرشيف قيم معرف المستخدم (UID) ومعرف المجموعة (GID) والطابع الزمني ووضع الملف الفعلية.

هذا هو الوضع الافتراضي ما لم يتم تكوين binutils باستخدام --enable-deterministic-archives.

v
يطلب هذا المعدل الإصدار المسهب لعملية ما. تعرض العديد من العمليات معلومات إضافية، مثل أسماء الملفات التي تتم معالجتها، عند إضافة المعدل v.
V
يعرض هذا المعدل رقم إصدار ar.

يدعم برنامج ar أيضًا بعض خيارات سطر الأوامر التي ليست معدلات ولا إجراءات، ولكنها تغير سلوكه بطرق محددة:

--help
يعرض قائمة خيارات سطر الأوامر التي يدعمها ar ثم يخرج.
--version
يعرض معلومات إصدار ar ثم يخرج.
-X32_64
يتجاهل ar خيارًا أوليًا مسمى -X32_64، للتوافق مع AIX. السلوك الناتج عن هذا الخيار هو الوضع الافتراضي لـ GNU ar. لا يدعم ar أي من خيارات -X الأخرى؛ على وجه الخصوص، لا يدعم -X32 وهو الوضع الافتراضي لـ AIX ar.
--plugin name
التبديل الاختياري لسطر الأوامر --plugin name يتسبب في تحميل ar للمكون الإضافي المسمى name الذي يضيف دعمًا لمزيد من تنسيقات الملفات، بما في ذلك ملفات الكائنات التي تحتوي على معلومات تحسين وقت الربط.

هذا الخيار متاح فقط إذا تم بناء مجموعة الأدوات مع تمكين دعم المكونات الإضافية.

إذا لم يتم توفير --plugin، ولكن تم تمكين دعم المكونات الإضافية، فإن ar يتكرر عبر الملفات في ${libdir}/bfd-plugins بالترتيب الأبجدي ويتم استخدام المكون الإضافي الأول الذي يدعي الكائن المعني.

يرجى ملاحظة أن دليل البحث عن المكونات الإضافية هذا ليس الدليل الذي تستخدمه ld مع الخيار -plugin. لجعل ar يستخدم مكون الربط الإضافي، يجب نسخه إلى الدليل ${libdir}/bfd-plugins. لتجميعات GCC، يسمى مكون الربط الإضافي liblto_plugin.so.0.0.0. لتجميعات Clang، يسمى LLVMgold.so. مكون GCC متوافق دائمًا مع الإصدارات السابقة، لذلك يكفي نسخ الأحدث.

--target target
يحدد التبديل الاختياري لسطر الأوامر --target bfdname أن أعضاء الأرشيف موجودون بتنسيق شفرة كائن مختلف عن التنسيق الافتراضي لنظامك. انظر
--output dirname
يمكن استخدام الخيار --output لتحديد مسار إلى دليل يجب استخراج أعضاء الأرشيف إليه. إذا لم يتم تحديد هذا الخيار، فسيتم استخدام الدليل الحالي.

ملاحظة - على الرغم من أن وجود هذا الخيار يعني عملية استخراج x، يجب تضمين هذا الخيار في سطر الأوامر.

--record-libdeps libdeps
الخيار --record-libdeps مطابق للمعدل l، فقط تم التعامل معه بالشكل الطويل.
--thin
اجعل archive المحدد أرشيفًا رفيعًا. إذا كان موجودًا بالفعل وكان أرشيفًا عاديًا، فيجب أن تكون الأعضاء الموجودة في نفس دليل archive.
@file
اقرأ خيارات سطر الأوامر من file. يتم إدراج الخيارات المقروءة في مكان خيار @file الأصلي. إذا لم يكن file موجودًا، أو لا يمكن قراءته، فسيتم التعامل مع الخيار حرفيًا، ولن يتم إزالته.

يتم فصل الخيارات في file بمسافات بيضاء. يمكن تضمين حرف مسافة بيضاء في خيار عن طريق إحاطة الخيار بأكمله بعلامات اقتباس فردية أو مزدوجة. يمكن تضمين أي حرف (بما في ذلك الشرطة المائلة للخلف) عن طريق وضع الشرطة المائلة للخلف قبل الحرف المراد تضمينه. قد يحتوي file نفسه على خيارات @file إضافية؛ سيتم معالجة أي خيارات من هذا القبيل بشكل تكراري.
