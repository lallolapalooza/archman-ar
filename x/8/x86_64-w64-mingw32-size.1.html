x86_64-w64-mingw32-size(1)

الحزمة: mingw-w64-binutils

التراخيص: GPL-2.0-or-later, GPL-3.0-or-later, LGPL-2.0-or-later, LGPL-3.0-or-later, GFDL-1.3-only, FSFAP

SIZE(1) أدوات تطوير GNU SIZE(1)

الاسم

size - يسرد أحجام المقاطع وإجمالي حجم ملفات الثنائيات

الملخص

size [-A|-B|-G|--format=compatibility]
[--help]
[-d|-o|-x|--radix=number]
[--common]
[-t|--totals]
[--target=bfdname] [-V|--version]
[-f]
[objfile...]

الوصف

يقوم أداة size من GNU بسرد أحجام المقاطع وإجمالي الحجم لكل من ملفات الثنائيات objfile في قائمة وسيطاتها. افتراضيًا، يتم إنشاء سطر إخراج واحد لكل ملف أو لكل وحدة إذا كان الملف أرشيفًا.

objfile... هي الملفات المراد فحصها. إذا لم يتم تحديد أي ملفات، فسيتم استخدام الملف "a.out" بدلاً من ذلك.

خيارات

خيارات سطر الأوامر لها المعاني التالية:

-A
-B
-G
--format=compatibility
باستخدام أحد هذه الخيارات، يمكنك اختيار ما إذا كان إخراج size من GNU يشبه إخراج size من System V (باستخدام -A، أو --format=sysv)، أو size من Berkeley (باستخدام -B، أو --format=berkeley). الافتراضي هو تنسيق السطر الواحد المشابه لتنسيق Berkeley. بدلاً من ذلك، يمكنك اختيار تنسيق إخراج GNU (باستخدام -G، أو --format=gnu)، وهذا مشابه لتنسيق إخراج Berkeley، ولكن يتم حساب الأحجام بشكل مختلف.

إليك مثال على تنسيق Berkeley (الافتراضي) لإخراج size:

$ size --format=Berkeley ranlib size
   text    data     bss     dec     hex filename
 294880   81920   11592  388392   5ed28 ranlib
 294880   81920   11888  388688   5ee50 size

يحسب إخراج نمط Berkeley البيانات للقراءة فقط في عمود "text"، وليس في عمود "data"، ويعرض كل من عمودي "dec" و "hex" مجموع أعمدة "text" و "data" و "bss" بالعشري والسداسي عشري على التوالي.

يحسب تنسيق GNU البيانات للقراءة فقط في عمود "data"، وليس عمود "text"، ويعرض فقط مجموع أعمدة "text" و "data" و "bss" مرة واحدة، في عمود "total". يمكن استخدام الخيار --radix لتغيير قاعدة الأرقام لجميع الأعمدة. إليك نفس البيانات المعروضة باتفاقيات GNU:

$ size --format=GNU ranlib size
      text       data        bss      total filename
    279880      96920      11592     388392 ranlib
    279880      96920      11888     388688 size

هذه هي نفس البيانات، ولكنها معروضة بشكل أقرب إلى اتفاقيات System V:

$ size --format=SysV ranlib size
ranlib  :
section         size         addr
.text         294880         8192
.data          81920       303104
.bss           11592       385024
Total         388392


size  :
section         size         addr
.text         294880         8192
.data          81920       303104
.bss           11888       385024
Total         388688
--help
-h
-H
-?
يعرض ملخصًا للوسائط والخيارات المقبولة.
-d
-o
-x
--radix=number
باستخدام أحد هذه الخيارات، يمكنك التحكم فيما إذا كان حجم كل مقطع معطى بالعشري (-d، أو --radix=10)؛ ثماني (-o، أو --radix=8)؛ أو سداسي عشري (-x، أو --radix=16). في --radix=number، فقط القيم الثلاث (8، 10، 16) مدعومة. يتم دائمًا إعطاء الحجم الإجمالي بجذرين؛ عشري وسداسي عشري لإخراج -d أو -x، أو ثماني وسداسي عشري إذا كنت تستخدم -o.
--common
يطبع الحجم الإجمالي للرموز المشتركة في كل ملف. عند استخدام تنسيق Berkeley أو GNU، يتم تضمين هذه الرموز في حجم bss.
-t
--totals
يعرض الإجماليات لجميع الكائنات المدرجة (وضع تنسيق Berkeley أو GNU فقط).
--target=bfdname
تحديد أن تنسيق رمز الكائن objfile هو bfdname. قد لا يكون هذا الخيار ضروريًا؛ يمكن لـ size التعرف تلقائيًا على العديد من التنسيقات.
-v
-V
--version
يعرض رقم إصدار size.
-f
تم تجاهله. يتم استخدام هذا الخيار بواسطة إصدارات أخرى من برنامج size، ولكنه غير مدعوم من قبل إصدار Binutils من GNU.
@file
يقرأ خيارات سطر الأوامر من file. يتم إدراج الخيارات المقروءة في مكان خيار @file الأصلي. إذا كان file غير موجود، أو لا يمكن قراءته، فسيتم التعامل مع الخيار حرفيًا، ولن يتم إزالته.

يتم فصل الخيارات في file بواسطة مسافات بيضاء. يمكن تضمين حرف مسافة بيضاء في خيار عن طريق إحاطة الخيار بأكمله بعلامات اقتباس مفردة أو مزدوجة. يمكن تضمين أي حرف (بما في ذلك الشرطة المائلة للخلف) عن طريق وضع الشرطة المائلة للخلف قبل الحرف المراد تضمينه. يمكن أن يحتوي file نفسه على خيارات @file إضافية؛ سيتم معالجة أي خيارات من هذا القبيل بشكل متكرر.

انظر أيضًا

ar(1)، objdump(1)، readelf(1)، وإدخالات Info لـ binutils.
