XkbDeviceBellEvent(3)

الحزمة: libx11

التراخيص: MIT AND X11

XkbDeviceBellEvent(3) XKB FUNCTIONS XkbDeviceBellEvent(3)

الاسم

XkbDeviceBellEvent - يقوم بإنشاء حدث جرس لجهاز امتداد إدخال X أو للوحة المفاتيح، دون إصدار الجرس المقابل

الملخص

Bool XkbDeviceBellEvent (Display *display, Window window, unsigned int device_spec, unsigned int bell_class, unsigned int bell_id, int percent, Atom name);

المعاملات

display
الاتصال بخادم X
window
نافذة الحدث، أو None
device_spec
معرف الجهاز، أو XkbUseCoreKbd
bell_class
فئة جرس امتداد الإدخال للحدث
bell_id
معرف جرس امتداد الإدخال للحدث
percent
مستوى الصوت للجرس، والذي يمكن أن يتراوح من -100 إلى 100 شاملة
name
اسم جرس، أو NULL

الوصف

يسمح بروتوكول X الأساسي فقط للتطبيقات بإصدار صوت جرس النظام صراحةً بمدة ودرجة وصوت محددين. يوسع Xkb هذه القدرة عن طريق السماح للعملاء بإرفاق أسماء رمزية للأجراس، وتعطيل الأجراس المسموعة، وتلقي حدث كلما تم تشغيل جرس لوحة المفاتيح. لأغراض هذا المستند، يُعرّف الجرس المسموع بأنه جرس النظام، أو جرس لوحة المفاتيح الافتراضي، على عكس أي صوت مسموع آخر يتم إنشاؤه في مكان آخر في النظام. يمكنك طلب تلقي أحداث XkbBellNotify عندما يقوم أي عميل بتشغيل أي من الأنواع التالية:

  • الجرس الافتراضي
  • أي جرس على جهاز إدخال يمكن تحديده بواسطة زوج bell_class و bell_id
  • أي جرس محدد فقط باسم تعسفي. (هذا، من وجهة نظر الخادم، مجرد اسم، وليس مرتبطًا بأي جهاز مادي يولد الصوت. يجب على بعض تطبيقات العملاء إنشاء الصوت، أو ردود الفعل المرئية، إن وجدت، المرتبطة بالاسم.)

    يمكنك أيضًا طلب تلقي أحداث XkbBellNotify عندما يقوم الخادم بتشغيل الجرس الافتراضي أو إذا طلب أي عميل أحداثًا فقط (بدون إصدار صوت الجرس) لأي من أنواع الأجراس المذكورة سابقًا.

    يمكنك تعطيل الأجراس المسموعة على أساس شامل. على سبيل المثال، قد يرغب عميل يستبدل جرس لوحة المفاتيح بإشارة صوتية أخرى في إيقاف تشغيل التحكم AudibleBell لمنع الخادم من إصدار صوت أيضًا وتجنب الفوضى. إذا قمت بتعطيل الأجراس المسموعة وطلبت تلقي أحداث XkbBellNotify، يمكنك إنشاء ردود فعل مختلفة عن الجرس الافتراضي.

    ومع ذلك، يمكنك تجاوز التحكم AudibleBell عن طريق استدعاء إحدى الوظائف التي تجبر على إصدار جرس على الرغم من إعداد التحكم AudibleBell - XkbForceDeviceBell أو XkbForceBell. في هذه الحالة، لا يقوم الخادم بإنشاء حدث جرس.

    تمامًا كما يمكن لبعض لوحات المفاتيح إنتاج نقرات مفاتيح للإشارة إلى وقت الضغط على مفتاح أو تكراره، يمكن لـ Xkb توفير ردود فعل للضوابط عن طريق استخدام رموز تنبيه خاصة. يستخدم التحكم AccessXFeedback لتكوين الأنواع المحددة من العمليات التي تولد ردود فعل.

    أسماء الأجراس

    يمكنك ربط اسم بعملية إصدار جرس عن طريق تحويل الاسم إلى Atom ثم استخدام هذا الاسم عند استدعاء الوظائف المذكورة في هذا الفصل. إذا تم إنشاء حدث كنتيجة، يتم تمرير الاسم بعد ذلك إلى جميع العملاء الآخرين المهتمين بتلقي أحداث XkbBellNotify. لاحظ أن هذه أسماء تعسفية ولا يوجد ارتباط بأي أصوات. يجب على أي أصوات أو تأثيرات أخرى (مثل الأجراس المرئية على الشاشة) أن يتم إنشاؤها بواسطة تطبيق عميل عند تلقي حدث الجرس الذي يحتوي على الاسم. لا يوجد اسم افتراضي لجرس لوحة المفاتيح الافتراضي. يقوم الخادم بإنشاء بعض الأجراس المعرفة مسبقًا لضوابط AccessX. تظهر هذه الأجراس المسماة في الجدول 1 أدناه؛ يتم تضمين الاسم في أي حدث جرس يتم إرساله إلى العملاء الذين طلبوا تلقي أحداث XkbBellNotify.

    الأجراس المسموعة

    باستخدام Xkb، يمكنك إنشاء أحداث جرس لا تصدر بالضرورة جرس النظام. هذا مفيد إذا كنت بحاجة إلى استخدام خادم صوت بدلاً من صوت النظام. على سبيل المثال، عند بدء تشغيل عميل صوت، يمكنه تعطيل الجرس المسموع (جرس النظام)، ثم الاستماع إلى أحداث XkbBellNotify. عند تلقي حدث XkbBellNotify، يمكن لعميل الصوت بعد ذلك إرسال طلب إلى خادم الصوت لتشغيل صوت.

    يمكنك التحكم في ميزة الأجراس المسموعة عن طريق تمرير XkbAudibleBellMask إلى XkbChangeEnabledControls. إذا قمت بتعيين XkbAudibleBellMask على تشغيل، يقوم الخادم بإصدار صوت جرس النظام عند حدوث حدث جرس. هذا هو الافتراضي. إذا قمت بتعيين XkbAudibleBellMask على إيقاف، وعند حدوث حدث جرس، لا يقوم الخادم بإصدار صوت جرس النظام ما لم تستدعي XkbForceDeviceBell أو XkbForceBell.

    الأجراس المسموعة هي أيضًا جزء من ضوابط إعادة الضبط التلقائي لكل عميل.

    وظائف الجرس

    استخدم الوظائف الموضحة في هذا القسم لإصدار الأجراس وإنشاء أحداث الجرس.

    يحتوي امتداد الإدخال على نوعين من ردود الفعل التي يمكن أن تولد الأجراس - ردود فعل الجرس وردود فعل لوحة المفاتيح. بعض الوظائف في هذا القسم تحتوي على معاملات bell_class و bell_id؛ قم بتعيينها على النحو التالي: قم بتعيين bell_class إلى BellFeedbackClass أو KbdFeedbackClass. يمكن لجهاز أن يحتوي على أكثر من رد فعل واحد من كل نوع؛ قم بتعيين bell_id إلى جرس معين من نوع bell_class.

    يوضح الجدول 2 الظروف التي تتسبب في إصدار جرس أو في توليد حدث XkbBellNotify عند استدعاء وظيفة جرس.

    XkbDeviceBellEvent(3) — libX11 — X Version 11

    NAME

    XkbDeviceBellEvent, XkbBellEvent, XkbDeviceForceBell, XkbForceBell — generate keyboard device bell events

    SYNOPSIS

        #include <X11/extensions/XKBbells.h>

    Bool XkbDeviceBellEvent(
        Display *		display,
        unsigned int	 device_spec,
        int			 percent,
        int			norel
    );
    Bool XkbBellEvent(
        Display *		display,
        unsigned int	 device_spec,
        int			 percent,
        int			norel
    );
    Bool XkbDeviceForceBell(
        Display *		display,
        unsigned int	 device_spec,
        int			 percent,
        int			norel
    );
    Bool XkbForceBell(
        Display *		display,
        unsigned int	 device_spec,
        int			 percent,
        int			norel
    );

    ARGUMENTS

    display
    Specifies the connection to the X server.
    device_spec
    Specifies the device for which the bell is generated. Can be a device ID or XkbUseCoreKbd.
    percent
    Specifies the volume for the bell, as a percentage of the maximum volume.
    norel
    If non-zero, the server uses the value of percent directly; otherwise, it is interpreted as a relative change to the current volume.

    DESCRIPTION

    The XkbDeviceBellEvent function causes a bell to be generated on the specified device. The percent argument specifies the volume, and norel specifies whether the volume is relative to the current volume or an absolute value. If percent is 0, the bell volume is set to the default volume.

    The Xkb extension must be present on the X server for this function to work. If the extension is not present, XkbDeviceBellEvent returns False.

    If the extension is present, XkbDeviceBellEvent sends an XkbBellNotify event to all interested clients and returns True. The event details are specified by the percent and norel arguments.

    The other functions listed in the SYNOPSIS are similar:

    • XkbBellEvent is equivalent to XkbDeviceBellEvent with device_spec set to XkbUseCoreKbd.

    • XkbDeviceForceBell causes a bell to be generated on the specified device, overriding any device-specific bell settings. This function does not send an XkbBellNotify event.

    • XkbForceBell is equivalent to XkbDeviceForceBell with device_spec set to XkbUseCoreKbd.

    The following table summarizes the behavior of these functions:

    If a compatible keyboard extension isn't present in the X server, XkbDeviceBellEvent immediately returns False. Otherwise, XkbDeviceBellEvent causes an XkbBellNotify event to be sent to all interested clients and returns True. Set percent to be the volume relative to the base volume for the keyboard as described for XBell.

    In addition, XkbDeviceBellEvent may generate Atom protocol errors as well as XkbBellNotify events. You can call XkbBell without first initializing the keyboard extension.

RETURN VALUES

True
The XkbDeviceBellEvent sends an XkbBellNotify event to to all interested clients and returns True.
False
If a compatible keyboard extension isn't present in the X server, XkbDeviceBellEvent immediately returns False

STRUCTURES

Xkb generates XkbBellNotify events for all bells except for those resulting from
calls to XkbForceDeviceBell and XkbForceBell. To receive XkbBellNotify events under all possible conditions, pass XkbBellNotifyMask in both the bits_to_change and values_for_bits parameters to XkbSelectEvents.

The XkbBellNotify event has no event details. It is either selected or it is not. However, you can call XkbSelectEventDetails using XkbBellNotify as the event_type and specifying XkbAllBellEventsMask in bits_to_change and values_for_bits. This has the same effect as a call to XkbSelectEvents.

The structure for the XkbBellNotify event type contains:

   typedef struct _XkbBellNotify {
       int            type;        /* Xkb extension base event code */
       unsigned long  serial;      /* X server serial number for event */
       Bool           send_event;  /* True => synthetically generated */
       Display *      display;     /* server connection where event generated */
       Time           time;        /* server time when event generated */
       int            xkb_type;    /* XkbBellNotify */
       unsigned int   device;      /* Xkb device ID, will not be XkbUseCoreKbd */
       int            percent;     /* requested volume as % of max */
       int            pitch;       /* requested pitch in Hz */
       int            duration;    /* requested duration in microseconds */
       unsigned int   bell_class;  /* X input extension feedback class */
       unsigned int   bell_id;     /* X input extension feedback ID */
       Atom           name;        /* "name" of requested bell */
       Window         window;      /* window associated with event */
       Bool           event_only;  /* False -> the server did not produce a beep */
   } XkbBellNotifyEvent;
If your application needs to generate visual bell feedback on the screen when it receives a bell event, use the window ID in the XkbBellNotifyEvent, if present.
