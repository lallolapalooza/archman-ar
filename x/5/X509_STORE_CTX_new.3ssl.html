DESCRIPTION

The certificate verification process in OpenSSL is managed by an X509_STORE_CTX structure. This structure holds all the necessary information for the verification, including the certificate chain, the trusted certificates, and any specific verification parameters.

X509_STORE_CTX_new() creates and returns a new, empty X509_STORE_CTX structure.

X509_STORE_CTX_free() frees the supplied X509_STORE_CTX structure and all associated memory.

X509_STORE_CTX_cleanup() cleans up the contents of the X509_STORE_CTX structure, freeing any dynamically allocated memory, but does not free the structure itself.

X509_STORE_CTX_init() initializes an existing X509_STORE_CTX structure ctx. The store parameter is an X509_STORE object containing trusted certificates and CRLs. The x509 parameter is the certificate to be verified. The chain parameter is a stack of intermediate certificates that may be used to build a path from x509 to a trusted certificate.

X509_STORE_CTX_get_ex_data() and X509_STORE_CTX_set_ex_data() are used to get and set arbitrary data associated with the X509_STORE_CTX structure. The idx parameter is an index obtained from X509_STORE_CTX_get_ex_new_index(). This allows applications to associate private data with a context.

X509_STORE_CTX_get_ex_new_index() obtains a new index for use with the X509_STORE_CTX_get_ex_data() and X509_STORE_CTX_set_ex_data() functions. The new_func, free_func, and dup_func parameters are optional callback functions that are called when the context is created, freed, or duplicated, respectively.

X509_STORE_CTX_seq_cert() and related functions X509_STORE_CTX_seq_get0_current(), X509_STORE_CTX_seq_get0_only_end(), and X509_STORE_CTX_seq_range() are used to iterate through the certificate chain during verification. X509_STORE_CTX_seq_cert() starts the iteration. X509_STORE_CTX_seq_get0_current() returns the current certificate being processed. X509_STORE_CTX_seq_get0_only_end() returns the last certificate in the chain (the end-entity certificate). X509_STORE_CTX_seq_range() returns the start and stop indices of the current sequence of certificates being processed.

X509_STORE_CTX_get_chain() returns the stack of certificates used in the verification process. This typically includes the end-entity certificate and any intermediate certificates.

X509_STORE_CTX_set_cert() sets the certificate to be verified. This is typically done during initialization.

X509_STORE_CTX_set0_trusted_chain() sets the trusted chain for the context. Note that this function takes ownership of the supplied chain.

X509_STORE_CTX_set_verify_callback() and X509_STORE_CTX_get_verify_callback() allow an application to set and retrieve a custom callback function that is invoked during the verification process. This callback can be used to implement custom verification logic or to control the verification flow.

X509_STORE_CTX_get_error() and X509_STORE_CTX_set_error() retrieve and set the error code associated with the verification process. If verification fails, this function returns the reason for the failure.

X509_STORE_CTX_get_error_depth() and X509_STORE_CTX_set_error_depth() retrieve and set the depth of the current error in the certificate chain. The depth is the number of intermediate certificates between the current certificate and the trusted root.

X509_STORE_CTX_get_flags() and X509_STORE_CTX_set_flags() retrieve and set flags that control the behavior of the verification process. See the X509_V_FLAG_* constants in openssl/x509_vfy.h for available flags.

X509_STORE_CTX_get_current_cert() and X509_STORE_CTX_set_current_cert() retrieve and set the certificate currently being processed during verification.

X509_STORE_CTX_get_peer() and X509_STORE_CTX_set_peer() retrieve and set the peer certificate. This is the certificate presented by the remote party in a TLS connection.

X509_STORE_CTX_get_untrusted() and X509_STORE_CTX_set0_untrusted() retrieve and set the stack of untrusted certificates. These are certificates that are not part of the main chain but may be needed for verification (e.g., intermediate certificates).

X509_STORE_CTX_get_store() and X509_STORE_CTX_set_store() retrieve and set the X509_STORE object associated with the context.

X509_STORE_CTX_get_purpose() and X509_STORE_CTX_set_purpose() retrieve and set the intended purpose of the certificate (e.g., server authentication, client authentication).

X509_STORE_CTX_get_check_issued() and X509_STORE_CTX_set_check_issued() allow setting and retrieving a callback function that checks if a certificate was issued by its purported issuer. This is typically used to enforce specific policies on certificate issuance.

X509_STORE_CTX_get_check_policy() and X509_STORE_CTX_set_check_policy() allow setting and retrieving a callback function for checking certificate policies.

X509_STORE_CTX_get_get_input() and X509_STORE_CTX_set_get_input() allow setting and retrieving a callback function that is called to obtain input data for verification.

X509_STORE_CTX_get_verify_result() and X509_STORE_CTX_set_verify_result() retrieve and set the final verification result.

X509_STORE_CTX_set_client_CA_list() and X509_STORE_CTX_get_client_CA_list() manage the list of trusted Certificate Authorities (CAs) that are sent to the client during the TLS handshake.

The functions starting with X509_STORE_CTX_get_hs_hbx and X509_STORE_CTX_set_hs_hbx (and their list variants, count, and add variants) are related to a specific internal feature (possibly "hash boxes" or similar) within the OpenSSL verification process. Their exact purpose and usage might depend on the OpenSSL version and specific internal implementations and are less commonly used in standard application-level certificate verification.

NOTES

The X509_STORE_CTX structure is central to the certificate verification process. Applications typically interact with it indirectly through functions like X509_verify_cert(), but direct manipulation of the context is sometimes necessary for advanced use cases.

When using X509_STORE_CTX_init(), the caller is responsible for managing the lifetime of the X509_STORE, X509, and STACK_OF(X509) objects passed to it. The context does not take ownership unless explicitly stated (e.g., in X509_STORE_CTX_set0_trusted_chain()).

The callback functions set via X509_STORE_CTX_set_verify_callback(), X509_STORE_CTX_set_check_issued(), etc., are called by the OpenSSL verification engine. The callback function should return 1 on success and 0 on failure.

The extended data functions (_get_ex_data, _set_ex_data, _get_ex_new_index) provide a mechanism for associating application-specific data with the verification context without modifying the core X509_STORE_CTX structure. This is useful for passing state information or custom data to callbacks.

BUGS

The specific behavior and availability of the hs_hbx related functions might vary between OpenSSL versions, as they appear to be related to internal implementation details. Consult the specific OpenSSL version documentation if these functions are critical.

RETURN VALUES

X509_STORE_CTX_new() returns a pointer to a newly allocated X509_STORE_CTX structure, or NULL on failure.

X509_STORE_CTX_init(), X509_STORE_CTX_set_cert(), X509_STORE_CTX_set0_trusted_chain(), X509_STORE_CTX_set_verify_callback(), X509_STORE_CTX_set_error(), X509_STORE_CTX_set_error_depth(), X509_STORE_CTX_set_flags(), X509_STORE_CTX_set_current_cert(), X509_STORE_CTX_set_peer(), X509_STORE_CTX_set0_untrusted(), X509_STORE_CTX_set_store(), X509_STORE_CTX_set_purpose(), X509_STORE_CTX_set_check_issued(), X509_STORE_CTX_set_check_policy(), X509_STORE_CTX_set_get_input(), X509_STORE_CTX_set_verify_result(), X509_STORE_CTX_set_client_CA_list(), and the hs_hbx setting functions return 1 on success and 0 or an error code on failure.

X509_STORE_CTX_get_ex_data() returns a pointer to the data associated with the index, or NULL if the index is invalid or no data is set.

X509_STORE_CTX_set_ex_data() and X509_STORE_CTX_get_ex_new_index() return 1 on success and 0 on failure.

X509_STORE_CTX_seq_cert() returns 1 if the iteration is successful, 0 otherwise.

X509_STORE_CTX_seq_get0_current(), X509_STORE_CTX_seq_get0_only_end(), X509_STORE_CTX_get_chain(), X509_STORE_CTX_get_untrusted(), X509_STORE_CTX_get_store(), X509_STORE_CTX_get_purpose(), X509_STORE_CTX_get_check_issued(), X509_STORE_CTX_get_check_policy(), X509_STORE_CTX_get_get_input(), X509_STORE_CTX_get_verify_result(), X509_STORE_CTX_get_client_CA_list(), and the hs_hbx getting functions return pointers to the relevant data structures or values. They may return NULL or specific error indicators on failure or if no data is available.

X509_STORE_CTX_get_verify_callback() returns a pointer to the callback function, or NULL if no callback is set.

X509_STORE_CTX_get_error() returns the error code.

X509_STORE_CTX_get_error_depth() returns the error depth.

X509_STORE_CTX_get_flags() returns the verification flags.

X509_STORE_CTX_get_current_cert() returns the current certificate.

X509_STORE_CTX_get_peer() returns the peer certificate.

X509_STORE_CTX_seq_range() returns 1 on success, setting *start and *stop. It returns 0 on failure.

The hs_hbx related functions return 1 on success and 0 or an error code on failure. The "get" functions return the value or NULL/0 on failure.

HISTORY

The X509_STORE_CTX_new(), X509_STORE_CTX_free(), X509_STORE_CTX_init(), X509_STORE_CTX_cleanup(), and X509_STORE_CTX_verify() functions were added in OpenSSL 0.9.7.

The extended data functions X509_STORE_CTX_get_ex_data(), X509_STORE_CTX_set_ex_data(), and X509_STORE_CTX_get_ex_new_index() were added in OpenSSL 0.9.8.

The X509_STORE_CTX_set0_trusted_chain() function was added in OpenSSL 1.0.0.
