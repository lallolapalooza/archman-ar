XGetWindowProperty(3) وظائف XLIB XGetWindowProperty(3)

الاسم

XGetWindowProperty، XListProperties، XChangeProperty، XRotateWindowProperties، XDeleteProperty - الحصول على خصائص النافذة وتغييرها

الصيغة

int XGetWindowProperty(Display *display، Window w، Atom property، long long_offset، long long_length، Bool delete، Atom req_type، Atom *actual_type_return، int *actual_format_return، unsigned long *nitems_return، unsigned long *bytes_after_return، unsigned char **prop_return);

Atom *XListProperties(Display *display، Window w، int *num_prop_return);

int XChangeProperty(Display *display، Window w، Atom property، Atom type، int format، int mode، _Xconst unsigned char *data، int nelements);

int XRotateWindowProperties(Display *display، Window w، Atom properties[]; int num_prop، int npositions);

int XDeleteProperty(Display *display، Window w، Atom property);

المعاملات

actual_format_return
تُرجع التنسيق الفعلي للخاصية.
actual_type_return
تُرجع معرف الذرة الذي يحدد النوع الفعلي للخاصية.
bytes_after_return
تُرجع عدد البايتات المتبقية للقراءة في الخاصية إذا تم إجراء قراءة جزئية.
data
تحدد بيانات الخاصية.
delete
تحدد قيمة منطقية تحدد ما إذا كانت الخاصية سيتم حذفها.
display
تحدد الاتصال بخادم X.
format
تحدد ما إذا كان يجب النظر إلى البيانات كقائمة من الكميات 8-بت، 16-بت، أو 32-بت. القيم الممكنة هي 8، 16، و 32. تسمح هذه المعلومات لخادم X بإجراء عمليات تبديل البايتات بشكل صحيح حسب الحاجة. إذا كان التنسيق 16-بت أو 32-بت، فيجب عليك صب مؤشر البيانات الخاص بك بشكل صريح إلى (unsigned char *) في استدعاء XChangeProperty.
long_length
تحدد الطول بمضاعفات 32-بت للبيانات المراد استردادها.
long_offset
تحدد الإزاحة في الخاصية المحددة (بكميات 32-بت) حيث سيتم استرداد البيانات.
mode
تحدد وضع العملية. يمكنك تمرير PropModeReplace، PropModePrepend، أو PropModeAppend.
nelements
تحدد عدد العناصر بالتنسيق المحدد للبيانات.
nitems_return
تُرجع العدد الفعلي للعناصر 8-بت، 16-بت، أو 32-بت المخزنة في بيانات prop_return.
num_prop
تحدد طول مصفوفة الخصائص.
num_prop_return
تُرجع طول مصفوفة الخصائص.
npositions
تحدد مقدار الدوران.
prop_return
تُرجع البيانات بالتنسيق المحدد. إذا كان التنسيق المرجع 8، يتم تمثيل البيانات المرجعة كمصفوفة char. إذا كان التنسيق المرجع 16، يتم تمثيل البيانات المرجعة كمصفوفة من نوع short int ويجب تحويلها إلى هذا النوع للحصول على العناصر. إذا كان التنسيق المرجع 32، سيتم تخزين بيانات الخاصية كمصفوفة من long (والتي في تطبيق 64-بت ستكون قيم 64-بت يتم حشوها في البايتات الأربعة العلوية).
property
تحدد اسم الخاصية.
properties
تحدد مصفوفة الخصائص التي سيتم تدويرها.
req_type
تحدد معرف الذرة المرتبط بنوع الخاصية أو AnyPropertyType.
type
تحدد نوع الخاصية. خادم X لا يفسر النوع ولكنه ببساطة يعيده إلى تطبيق يتصل لاحقًا بـ XGetWindowProperty.
w
تحدد النافذة التي تريد الحصول على خاصيتها أو تغييرها أو تدويرها أو حذفها.

الوصف

تُرجع الدالة XGetWindowProperty النوع الفعلي للخاصية؛ التنسيق الفعلي للخاصية؛ عدد العناصر 8-بت، 16-بت، أو 32-بت المنقولة؛ عدد البايتات المتبقية للقراءة في الخاصية؛ ومؤشر إلى البيانات التي تم إرجاعها فعليًا. تقوم XGetWindowProperty بتعيين معاملات الإرجاع على النحو التالي:

  • إذا لم تكن الخاصية المحددة موجودة للنافذة المحددة، تُرجع XGetWindowProperty None إلى actual_type_return والقيمة صفر إلى actual_format_return و bytes_after_return. الوسيط nitems_return يكون فارغًا. في هذه الحالة، يتم تجاهل الوسيط delete.
  • إذا كانت الخاصية المحددة موجودة ولكن نوعها لا يتطابق مع النوع المحدد، تُرجع XGetWindowProperty النوع الفعلي للخاصية إلى actual_type_return، والتنسيق الفعلي للخاصية (لا يكون صفرًا أبدًا) إلى actual_format_return، وطول الخاصية بالبايتات (حتى لو كان actual_format_return 16 أو 32) إلى bytes_after_return. كما أنها تتجاهل الوسيط delete. الوسيط nitems_return يكون فارغًا.
  • إذا كانت الخاصية المحددة موجودة وإما أن تقوم بتعيين AnyPropertyType إلى الوسيط req_type أو أن يتطابق النوع المحدد مع نوع الخاصية الفعلي، تُرجع XGetWindowProperty النوع الفعلي للخاصية إلى actual_type_return والتنسيق الفعلي للخاصية (لا يكون صفرًا أبدًا) إلى actual_format_return. كما أنها تُرجع قيمة إلى bytes_after_return و nitems_return، من خلال تحديد القيم التالية:
N = الطول الفعلي للخاصية المخزنة بالبايتات
     (حتى لو كان التنسيق 16 أو 32)
I = 4 * long_offset
T = N - I
L = MINIMUM(T, 4 * long_length)
A = N - (I + L)
تبدأ القيمة المرجعة عند فهرس البايت I في الخاصية (الفهرسة من صفر)، وطولها بالبايتات هو L. إذا تسبب قيمة long_offset في أن تكون L سالبة، ينتج خطأ BadValue. قيمة bytes_after_return هي A، مما يعطي عدد البايتات غير المقروءة اللاحقة في الخاصية المخزنة.

إذا كان التنسيق المرجع 8، يتم تمثيل البيانات المرجعة كمصفوفة char. إذا كان التنسيق المرجع 16، يتم تمثيل البيانات المرجعة كمصفوفة short ويجب تحويلها إلى هذا النوع للحصول على العناصر. إذا كان التنسيق المرجع 32، يتم تمثيل البيانات المرجعة كمصفوفة long ويجب تحويلها إلى هذا النوع للحصول على العناصر.

تقوم XGetWindowProperty دائمًا بتخصيص بايت إضافي في prop_return (حتى لو كانت الخاصية بطول صفر) وتعيينه إلى صفر حتى لا تضطر الخصائص البسيطة المكونة من أحرف إلى النسخ إلى سلسلة أخرى قبل الاستخدام.

إذا كان delete هو True وكان bytes_after_return يساوي صفرًا، تقوم XGetWindowProperty بحذف الخاصية من النافذة وتوليد حدث PropertyNotify على النافذة.

تُرجع الدالة Success إذا تم تنفيذها بنجاح. لتحرير البيانات الناتجة، استخدم XFree.

يمكن أن تولد XGetWindowProperty أخطاء BadAtom، و BadValue، و BadWindow.

تُرجع الدالة XListProperties مؤشرًا إلى مصفوفة من خصائص الذرة المعرفة للنافذة المحددة أو تُرجع NULL إذا لم يتم العثور على خصائص. لتحرير الذاكرة التي تم تخصيصها بواسطة هذه الدالة، استخدم XFree.

يمكن أن تولد XListProperties خطأ BadWindow.

تقوم الدالة XChangeProperty بتعديل الخاصية للنافذة المحددة وتتسبب في قيام خادم X بتوليد حدث PropertyNotify.

XChangeProperty(3) — libX11 — X Version 11

NAME

XChangeProperty, XDeleteProperty, XGetWindowProperty, XListProperties, XRotateWindowProperties — change window properties

SYNTAX

Change or replace a property:
int XChangeProperty(Display *display, Window w, Atom property, Atom type, int format, int mode, const unsigned char *data, int nelements);
Change or replace a property:
int XChangeProperty(Display *display, Window w, Atom property, Atom type, int format, int mode, const unsigned char *data, int nelements);
Delete a property:
int XDeleteProperty(Display *display, Window w, Atom property);
Get a property:
int XGetWindowProperty(Display *display, Window w, Atom property, long offset, long length, Bool delete, Atom req_type, Atom *actual_type_return, int *actual_format_return, unsigned long *nitems_return, unsigned long *bytes_after_return, unsigned char **data_return);
List properties:
Atom *XListProperties(Display *display, Window w, int *num_properties_return);
Rotate properties:
int XRotateWindowProperties(Display *display, Window w, XPropertyEvent *properties, int num_properties, int npositions);

ARGUMENTS

data
Specifies a pointer to the data to be stored with the property.
delete
Specifies whether to delete the property after getting it.
display
Specifies the connection to the X server.
format
Specifies the format for the data. Must be 8, 16, or 32.
length
Specifies the length of the data in 32-bit quantities.
mode
Specifies the mode for replacing or adding data. Must be PropModeReplace, PropModePrepend, or PropModeAppend.
nelements
Specifies the number of elements in the data array.
npositions
Specifies the number of positions to rotate the properties.
num_properties
Specifies the number of properties to rotate.
offset
Specifies the offset in 32-bit quantities into the property where the data should be read or written.
properties
Specifies the array of properties to rotate.
property
Specifies the atom associated with the property.
req_type
Specifies the desired atom type for the property.
type
Specifies the atom associated with the property type.
w
Specifies the window.

DESCRIPTION

The X Window System uses properties to associate arbitrary data with a window. Properties are named by atoms, and the data is stored as a sequence of 8-bit, 16-bit, or 32-bit quantities. The type of the property is also specified by an atom. For example, the window manager might store the window's name in a property named `_NET_WM_NAME` (a special atom) with type `UTF8_STRING` (another special atom).

The XChangeProperty function changes the value of a specified property on the specified window. It can also be used to add data to a property or to delete a property. The XChangeProperty function can generate a BadAtom, BadMatch, BadValue, or BadWindow error.

If mode is PropModeReplace, XChangeProperty discards the previous property value and stores the new data.

If mode is PropModePrepend or PropModeAppend, XChangeProperty inserts the specified data before the beginning of the existing data or onto the end of the existing data, respectively. The type and format must match the existing property value, or a BadMatch error results. If the property is undefined, it is treated as defined with the correct type and format with zero-length data.

If the specified format is 8, the property data must be a char array. If the specified format is 16, the property data must be a short array. If the specified format is 32, the property data must be a long array.

The lifetime of a property is not tied to the storing client. Properties remain until explicitly deleted, until the window is destroyed, or until the server resets. For a discussion of what happens when the connection to the X server is closed, see section 2.6. The maximum size of a property is server dependent and can vary dynamically depending on the amount of memory the server has available. (If there is insufficient space, a BadAlloc error results.)

XChangeProperty can generate BadAlloc, BadAtom, BadMatch, BadValue, and BadWindow errors.

The XRotateWindowProperties function allows you to rotate properties on a window and causes the X server to generate PropertyNotify events. If the property names in the properties array are viewed as being numbered starting from zero and if there are num_prop property names in the list, then the value associated with property name I becomes the value associated with property name (I + npositions) mod N for all I from zero to N - 1. The effect is to rotate the states by npositions places around the virtual ring of property names (right for positive npositions, left for negative npositions). If npositions mod N is nonzero, the X server generates a PropertyNotify event for each property in the order that they are listed in the array. If an atom occurs more than once in the list or no property with that name is defined for the window, a BadMatch error results. If a BadAtom or BadMatch error results, no properties are changed.

XRotateWindowProperties can generate BadAtom, BadMatch, and BadWindow errors.

The XDeleteProperty function deletes the specified property only if the property was defined on the specified window and causes the X server to generate a PropertyNotify event on the window unless the property does not exist.

XDeleteProperty can generate BadAtom and BadWindow errors.

DIAGNOSTICS

BadAlloc
The server failed to allocate the requested resource or server memory.
BadAtom
A value for an Atom argument does not name a defined Atom.
BadValue
Some numeric value falls outside the range of values accepted by the request. Unless a specific range is specified for an argument, the full range defined by the argument's type is accepted. Any argument defined as a set of alternatives can generate this error.
BadWindow
A value for a Window argument does not name a defined Window.
