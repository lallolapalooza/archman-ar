الاسم

xdp-filter - مرشح حزم بسيط يعمل بتقنية XDP

الملخص

xdp-filter هي أداة لترشيح الحزم تعمل بتقنية XDP. إنها بسيطة عن قصد، ولذلك لا تتمتع بنفس قدرات المطابقة الموجودة في، على سبيل المثال، netfilter. بدلاً من ذلك، بفضل XDP، يمكنها تحقيق معدلات إسقاط عالية جدًا: عشرات الملايين من الحزم في الثانية على نواة معالج واحدة.

تشغيل xdp-filter

صيغة تشغيل xdp-filter هي:

xdp-filter COMMAND [options]
حيث يمكن أن يكون COMMAND أحد ما يلي:
       load        - تحميل xdp-filter على واجهة
       unload      - إلغاء تحميل xdp-filter من واجهة
       port        - إضافة منفذ إلى قائمة المرشحات
       ip          - إضافة عنوان IP إلى قائمة المرشحات
       ether       - إضافة عنوان Ethernet MAC إلى قائمة المرشحات
       status      - عرض الحالة الحالية لـ xdp-filter
       poll        - استطلاع إخراج الإحصائيات
       help        - عرض قائمة الأوامر المتاحة

يتم شرح كل أمر وخياراته أدناه. أو استخدم xdp-filter COMMAND --help لعرض الخيارات لكل أمر.

الأمر LOAD

لاستخدام xdp-filter، يجب تحميله أولاً على واجهة. يتم ذلك باستخدام الأمر load، والذي يأخذ اسم الواجهة كمعامل، ويسمح اختياريًا بتحديد الميزات التي يجب تضمينها. بشكل افتراضي، يتم تحميل جميع الميزات، ولكن إلغاء تحديد بعض الميزات يمكن أن يسرع مطابقة الحزم، ويزيد الأداء بشكل كبير.

صيغة الأمر load هي:

xdp-filter load [options] <ifname>

حيث <ifname> هو اسم الواجهة التي سيتم تحميل xdp-filter عليها، ويجب تحديده. الخيارات المدعومة هي:

-m, --mode <mode>

يحدد الوضع الذي سيتم تحميل برنامج XDP به. القيم الصالحة هي 'native'، وهو الوضع الافتراضي لـ XDP داخل المشغل (in-driver)، و 'skb'، والذي يسبب استخدام ما يسمى وضع skb (المعروف أيضًا باسم XDP عام)، أو 'hw'، والذي يسبب تفريغ البرنامج إلى الأجهزة.

-p, --policy <policy>

يحدد هذا النهج الذي يطبقه xdp-filter على الحزم التي لا تتطابق مع أي من قواعد الترشيح. الافتراضي هو السماح، حيث يُسمح للحزم التي لا تتطابق مع أي قواعد بالمرور. الخيار الآخر هو الرفض، حيث يتم إسقاط **جميع** الحزم **باستثناء** تلك التي تتطابق مع خيارات الترشيح.

لا يمكن تحميل xdp-filter في وقت واحد في وضعي النهج الرفض و السماح على النظام. لاحظ أن تحميل xdp-filter في وضع الرفض سيؤدي إلى إسقاط جميع حركة المرور على الواجهة حتى يتم تثبيت قواعد سماح مناسبة، لذا يلزم بعض الحذر لتجنب حظر الوصول إلى نظام بعيد.

-f, --features <feats>

استخدم هذا الخيار لتحديد الميزات التي سيتم تضمينها عند تحميل xdp-filter. الافتراضي هو تحميل جميع الميزات المتاحة. لذا، لتحديد ميزات فردية، قم بتحديد واحدة أو أكثر من هذه:

  • tcp: دعم الترشيح على رقم منفذ TCP
  • udp: دعم الترشيح على رقم منفذ UDP
  • ipv6: دعم الترشيح على عناوين IPv6
  • ipv4: دعم الترشيح على عناوين IPv4
  • ethernet: دعم الترشيح على عناوين Ethernet MAC

حدد ميزات متعددة بفصلها بفاصلة. مثال: tcp,udp,ipv6.

-v, --verbose

تمكين تسجيل التصحيح. حدد مرتين لمزيد من التفاصيل.

-h, --help

عرض ملخص للخيارات المتاحة

الأمر UNLOAD

يقوم الأمر unload بإلغاء تحميل xdp-filter من واجهة واحدة (أو جميع الواجهات)، وتنظيف حالة البرنامج.

صيغة الأمر load هي:

xdp-filter unload [options] <ifname>

حيث <ifname> هو اسم الواجهة التي سيتم إلغاء تحميل xdp-filter منها، ويجب تحديده ما لم يتم استخدام الخيار --all. الخيارات المدعومة هي:

-a, --all

حدد هذا الخيار لإزالة xdp-filter من جميع الواجهات التي تم تحميله عليها. إذا تم تحديد هذا الخيار، فلن تكون هناك حاجة إلى <ifname>.

يمكن أيضًا استخدام هذا الخيار لتنظيف جميع حالات xdp-filter إذا تم إلغاء تحميل برامج XDP بوسائل أخرى.

-k, --keep-maps

حدد هذا الخيار لمنع xdp-filter من مسح حالة الخرائط الخاصة به. بشكل افتراضي، تتم إزالة جميع خرائط BPF التي لم تعد هناك حاجة إليها بواسطة أي برنامج تم تحميله. ومع ذلك، سيؤدي هذا أيضًا إلى إزالة محتويات الخرائط (قواعد الترشيح)، لذا يمكن استخدام هذا الخيار للاحتفاظ بالخرائط حتى تظل القواعد موجودة حتى يتم تحميل xdp-filter مرة أخرى.

-v, --verbose

تمكين تسجيل التصحيح. حدد مرتين لمزيد من التفاصيل.

-h, --help

عرض ملخص للخيارات المتاحة

الأمر PORT

استخدم الأمر port لإضافة منفذ TCP أو UDP إلى قائمة مطابقة xdp-filter. لكي يعمل هذا، يجب تحميل xdp-filter بميزة udp أو tcp (أو كليهما) على واجهة واحدة على الأقل.

صيغة الأمر port هي:

xdp-filter port [options] <port>

حيث <port> هو رقم المنفذ المراد إضافته (أو إزالته إذا تم تحديد --remove). الخيارات المدعومة هي:

-r, --remove

إزالة المنفذ بدلاً من إضافته.

-m, --mode <mode>

حدد وضع الترشيح. الخيارات الصالحة هي src و dst، وكلاهما يمكن تحديده كـ src,dst. إذا تم تحديد src، فسيتم إضافة رقم المنفذ كمطابقة منفذ مصدر، بينما إذا تم تحديد dst، فسيتم إضافة رقم المنفذ كمطابقة منفذ وجهة. إذا تم تحديد كليهما، فسيتم مطابقة الحزمة إذا كان أي من منفذ مصدرها أو منفذ وجهتها هو المنفذ المحدد.

-p, --proto <proto>

حدد واحدًا (أو كلاهما) من udp و/أو tcp لمطابقة منافذ UDP أو TCP، على التوالي.

-s, --status

إذا تم تحديد هذا الخيار، فسيتم طباعة القائمة الحالية للمنافذ المتطابقة بعد إدراج رقم المنفذ. بخلاف ذلك، لن يتم طباعة أي شيء.

-v, --verbose

تمكين تسجيل التصحيح. حدد مرتين لمزيد من التفاصيل.

-h, --help

عرض ملخص للخيارات المتاحة

NAME

xdp-filter

simple XDP packet filter configuration tool

SYNOPSIS

xdp-filter

load [options] <iface> | unload [<iface>] | port [options] <port> | ip [options] <addr> | ether [options] <addr> | status [options] | poll [options]

The LOAD command

Load an XDP program onto the specified interface. The program will filter packets based on the rules configured by the other commands.

The syntax for the load command is:

xdp-filter load [options] <iface>

Where <iface> is the network interface to load the XDP program onto. The supported options are:

-f, --feature <features>

Enable specified features. This affects which packet headers are parsed and made available for matching. Valid options are: srcmac, dstmac, srcip, dstip, srcipv6, dstipv6, tcp, udp, icmp, arp, all. Features can be comma-separated, e.g. -f tcp,udp.

-p, --policy <policy>

Set the default policy for packets that are not matched by any rule. Valid options are accept (default) and drop.

-s, --status

If this option is specified, the current list of matched ips will be printed after loading the XDP program. Otherwise, nothing will be printed.

-v, --verbose

Enable debug logging. Specify twice for even more verbosity.

-h, --help

Display a summary of the available options

The UNLOAD command

Unload the XDP program from the specified interface.

The syntax for the unload command is:

xdp-filter unload [<iface>]

If no interface is specified, the XDP program will be unloaded from all interfaces it is currently loaded on.

The PORT command

Add a TCP or UDP port to the xdp-filter match list. For this to work, xdp-filter must be loaded with either the tcp or udp feature on at least one interface.

The syntax for the port command is:

xdp-filter port [options] <port>

Where <port> is the TCP or UDP port number to add (or remove if the --remove is specified). The supported options are:

-r, --remove

Remove the port number instead of adding it.

-m, --mode <mode>

Select filtering mode. Valid options are src and dst, both of which may be specified as src,dst. If src is specified, the port number will be added as a source port match, while if dst is specified, the port number will be added as a destination port match. If both are specified, a packet will be matched if either its source or destination port is the specified port number.

-s, --status

If this option is specified, the current list of matched ports will be printed after inserting the port number. Otherwise, nothing will be printed.

-v, --verbose

Enable debug logging. Specify twice for even more verbosity.

-h, --help

Display a summary of the available options

The IP command

Add an IP address to the xdp-filter match list. For this to work, xdp-filter must be loaded with either the srcip, dstip, srcipv6 or dstipv6 feature on at least one interface.

The syntax for the ip command is:

xdp-filter ip [options] <addr>

Where <addr> is the IP address to add (or remove if the --remove is specified). The supported options are:

-r, --remove

Remove the IP address instead of adding it.

-m, --mode <mode>

Select filtering mode. Valid options are src and dst, both of which may be specified as src,dst. If src is specified, the IP address will added as a source IP match, while if dst is specified, the IP address will be added as a destination IP match. If both are specified, a packet will be matched if either its source or destination IP is the specified IP address.

-s, --status

If this option is specified, the current list of matched ips will be printed after inserting the IP address. Otherwise, nothing will be printed.

-v, --verbose

Enable debug logging. Specify twice for even more verbosity.

-h, --help

Display a summary of the available options

The ETHER command

Use the ether command to add an Ethernet MAC address to the xdp-filter match list. For this to work, xdp-filter must be loaded with either the ethernet feature on at least one interface.

The syntax for the ether command is:

xdp-filter ether [options] <addr>

Where <addr> is the MAC address to add (or remove if the --remove is specified). The supported options are:

-r, --remove

Remove the MAC address instead of adding it.

-m, --mode <mode>

Select filtering mode. Valid options are src and dst, both of which may be specified as src,dst. If src is specified, the MAC address will added as a source MAC match, while if dst is specified, the MAC address will be added as a destination MAC match. If both are specified, a packet will be matched if either its source or destination MAC is the specified MAC address.

-s, --status

If this option is specified, the current list of matched ips will be printed after inserting the MAC address. Otherwise, nothing will be printed.

-v, --verbose

Enable debug logging. Specify twice for even more verbosity.

-h, --help

Display a summary of the available options

The STATUS command

The status command prints the current status of xdp-filter: Which interfaces it is loaded on, the current list of rules, and some statistics for how many packets have been processed in total, and how many times each rule has been hit.

The syntax for the status command is:

xdp-filter status [options]

Where the supported options are:

-v, --verbose

Enable debug logging. Specify twice for even more verbosity.

-h, --help

Display a summary of the available options

The POLL command

The poll command periodically polls the xdp-filter statistics map and prints out the total number of packets and bytes processed by xdp-filter, as well as the number in the last polling interval, converted to packets (and bytes) per second. This can be used to inspect the performance of xdp-filter, and to compare the performance of the different feature sets selectable by the load parameter.

The syntax for the poll command is:

xdp-filter poll [options]

Where the supported options are:

-i, --interval <interval>

The polling interval, in milliseconds. Defaults to 1000 (1 second).

-v, --verbose

Enable debug logging. Specify twice for even more verbosity.

-h, --help

Display a summary of the available options

Examples

To filter all packets arriving on port 80 on eth0, issue the following commands:

# xdp-filter load eth0 -f tcp,udp
# xdp-filter port 80

To filter all packets except those from IP address fc00:dead:cafe::1 issue the following commands (careful, this can lock you out of remote access!):

# xdp-filter load eth0 -f ipv6 -p deny
# xdp-filter ip fc00:dead:cafe::1 -m src

To allow packets from either IP fc00:dead:cafe::1 or arriving on port 22, issue the following (careful, this can lock you out of remote access!):

# xdp-filter load eth0 -f ipv6,tcp -p deny
# xdp-filter port 22
# xdp-filter ip fc00:dead:cafe::1 -m src
