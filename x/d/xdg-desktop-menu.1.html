xdg-desktop-menu(1)

الحزمة: xdg-utils

التراخيص: MIT

NAME

xdg-desktop-menu - A tool to install and uninstall application menus.

SYNOPSIS

xdg-desktop-menu [--verbose] [--quiet] [--noupdate] [--force] [install FILE...] xdg-desktop-menu [--verbose] [--quiet] [--noupdate] [--force] install DIR xdg-desktop-menu [--verbose] [--quiet] [--noupdate] [--force] uninstall FILE... xdg-desktop-menu [--verbose] [--quiet] [--noupdate] [--force] uninstall DIR xdg-desktop-menu [--verbose] [--quiet] [--force] forceupdate

DESCRIPTION

The xdg-desktop-menu tool is used to install and uninstall menu entries in the user's menu tree. It is designed to be used by install scripts of packages providing desktop integrations.

The menu entries are described by files that follow the Desktop entry specification (Desktop entry specification[1]) and the menu entries are grouped into submenus described by files that follow the Desktop menu specification (Desktop menu specification[2]).

COMMANDS

install
Installs one or more files into the menu tree. If a directory is given as argument, xdg-desktop-menu will scan the directory recursively for menu files and install them.

The installation is done by copying the specified files to the appropriate directory within the user's menu tree (usually ~/.local/share/applications). The menu tree is updated to reflect the changes.

If the argument is a directory, the directory itself is not copied. Instead, xdg-desktop-menu will scan the directory recursively for files ending in .desktop and .directory and install them.

uninstall
Uninstalls one or more files from the menu tree. If a directory is given as argument, xdg-desktop-menu will scan the directory recursively for menu files and uninstall them.

The uninstallation is done by removing the specified files from the user's menu tree. The menu tree is updated to reflect the changes.

If the argument is a directory, the directory itself is not removed. Instead, xdg-desktop-menu will scan the directory recursively for files ending in .desktop and .directory and uninstall them.

forceupdate
Forces an update of the menu tree, even if no changes have been detected. This is useful if external tools have modified the menu tree and the xdg-desktop-menu tool is not aware of the changes.

OPTIONS

--verbose
Makes xdg-desktop-menu more verbose. This option can be specified multiple times to increase verbosity.
--quiet
Makes xdg-desktop-menu less verbose. This option can be specified multiple times to decrease verbosity.
--noupdate
Suppresses the automatic update of the menu tree after installation or uninstallation. This can be useful if multiple operations are performed and a single update at the end is desired.
--force
Forces the operation to proceed even if errors are encountered. This should be used with caution.

DESKTOP FILES

Desktop files are used to describe application entries in the menu. They are INI-style files with a [Desktop Entry] header followed by several Key=Value lines.

The following keys are relevant for menu entries:

Type=Application

This is a mandatory field that indicates that the .desktop file describes an application.

Name=Application Name

The name of the application as it should appear in the menu.

Comment=Comment

Optional field to specify a tooltip for the application.

Icon=Icon File

The icon to use for the application. This can either be an absolute path to an image file or an icon-name. If an icon-name is provided an image lookup by name is done in the user's current icon theme. The xdg-icon-resource command can be used to install image files into icon themes. The advantage of using an icon-name instead of an absolute path is that with an icon-name the application icon can be provided in several different sizes as well as in several differently themed styles.

Exec=Command

The command to execute when the application is launched from the menu.

Categories=Category List

A list of semicolon-separated categories to which the application belongs. This determines where the application will appear in the menu.

Only the keys Type, Name, Exec, and Categories are mandatory for an application to be listed in the menu.

DIRECTORY FILES

Directory files are used to describe submenus in the application menu. They are INI-style files with a [Desktop Entry] header followed by several Key=Value lines.

A *.directory file can provide a title (name) for the submenu in several different languages. This is done by adding a language code as used by LC_MESSAGES in square brackets behind the Key. This way one can specify different values for the same Key depending on the currently selected language.

The following keys are relevant for submenus:

Type=Directory

This is a mandatory field that indicates that the *.directory file describes a submenu.

Name=Menu Name

The title of submenu. For example Mozilla

Comment=Comment

Optional field to specify a tooltip for the submenu.

Icon=Icon File

The icon to use for the submenu. This can either be an absolute path to an image file or an icon-name. If an icon-name is provided an image lookup by name is done in the user's current icon theme. The xdg-icon-resource command can be used to install image files into icon themes. The advantage of using an icon-name instead of an absolute path is that with an icon-name the submenu icon can be provided in several different sizes as well as in several differently themed styles.

ENVIRONMENT VARIABLES

xdg-desktop-menu honours the following environment variables:

XDG_UTILS_DEBUG_LEVEL

Setting this environment variable to a non-zero numerical value makes xdg-desktop-menu do more verbose reporting on stderr. Setting a higher value increases the verbosity.

XDG_UTILS_INSTALL_MODE

This environment variable can be used by the user or administrator to override the installation mode. Valid values are user and system.

EXIT CODES

An exit code of 0 indicates success while a non-zero exit code indicates failure. The following failure codes can be returned:

1

Error in command line syntax.

2

One of the files passed on the command line did not exist.

3

A required tool could not be found.

4

The action failed.

5

No permission to read one of the files passed on the command line.

EXAMPLES

The company ShinyThings Inc. has developed an application named "WebMirror" and would like to add it to the application menu. The company will use "shinythings" as its vendor id. In order to add the application to the menu there needs to be a .desktop file with a suitable Categories entry:

shinythings-webmirror.desktop:
  [Desktop Entry]
  Encoding=UTF-8
  Type=Application
  Exec=webmirror
  Icon=webmirror
  Name=WebMirror
  Name[nl]=WebSpiegel
  Categories=Network;WebDevelopment;

Now the xdg-desktop-menu tool can be used to add the shinythings-webmirror.desktop file to the desktop application menu:

xdg-desktop-menu install ./shinythings-webmirror.desktop

Note that for the purpose of this example the menu items are available in two languages, English and Dutch. The language code for Dutch is nl.

In the next example the company ShinyThings Inc. will add its own submenu to the desktop application menu consisting of a "WebMirror" menu item and a "WebMirror Admin Tool" menu item.

First the company needs to create two .desktop files that describe the two menu items. Since the items are to be added to a new submenu it is not necessary to include a Categories= line:

shinythings-webmirror.desktop:
  [Desktop Entry]
  Encoding=UTF-8
  Type=Application
  Exec=webmirror
  Icon=shinythings-webmirror
  Name=WebMirror
  Name[nl]=WebSpiegel
shinythings-webmirror-admin.desktop:
  [Desktop Entry]
  Encoding=UTF-8
  Type=Application
  Exec=webmirror-admintool
  Icon=shinythings-webmirror-admintool
  Name=WebMirror Admin Tool
  Name[nl]=WebSpiegel Administratie Tool

In addition a .directory file needs to be created to provide a title and icon for the sub-menu itself:

shinythings-webmirror.directory:
  [Desktop Entry]
  Encoding=UTF-8
  Icon=shinythings-webmirror-menu
  Name=WebMirror
  Name[nl]=WebSpiegel

These file can now be installed with:

xdg-desktop-menu install ./shinythings-webmirror.directory \
      ./shinythings-webmirror.desktop ./shinythings-webmirror-admin.desktop

The menu entries could also be installed one by one:

xdg-desktop-menu install --noupdate ./shinythings-webmirror.directory \
      ./shinythings-webmirror.desktop
xdg-desktop-menu install --noupdate ./shinythings-webmirror.directory \
      ./shinythings-webmirror-admin.desktop
xdg-desktop-menu forceupdate

Although the result is the same it is slightly more efficient to install all files at the same time.

The *.desktop and *.directory files reference icons with the names webmirror, webmirror-admin and webmirror-menu which should also be installed. In this example the icons are installed in two different sizes, once with a size of 22x22 pixels and once with a size of 64x64 pixels:

xdg-icon-resource install --size 22 ./wmicon-22.png shinythings-webmirror
xdg-icon-resource install --size 22 ./wmicon-menu-22.png shinythings-webmirror-menu
xdg-icon-resource install --size 22 ./wmicon-admin-22.png shinythings-webmirror-admin
xdg-icon-resource install --size 64 ./wmicon-64.png shinythings-webmirror
xdg-icon-resource install --size 64 ./wmicon-menu-64.png shinythings-webmirror-menu
xdg-icon-resource install --size 64 ./wmicon-admin-64.png shinythings-webmirror-admin
