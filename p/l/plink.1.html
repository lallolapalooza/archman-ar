plink(1) مجموعة أدوات PuTTY plink(1)

الاسم

plink - PuTTY link, أداة اتصال شبكة سطر الأوامر

الملخص

plink  [خيارات]  [مستخدم@]مضيف  [أمر]

الوصف

plink هي أداة اتصال شبكة تدعم بروتوكولات متعددة.

الخيارات

خيارات سطر الأوامر التي يدعمها plink هي:

-V
عرض معلومات الإصدار والخروج.
-pgpfp
عرض بصمات مفاتيح PuTTY PGP الرئيسية والخروج، للمساعدة في التحقق من الملفات الجديدة التي صدرت عن فريق PuTTY.
-v
عرض رسائل تفصيلية.
-load جلسة
تحميل الإعدادات من جلسة محفوظة.
-ssh
فرض استخدام بروتوكول SSH (افتراضي).
-telnet
فرض استخدام بروتوكول Telnet.
-rlogin
فرض استخدام بروتوكول rlogin.
-raw
فرض الوضع الخام.
-serial
فرض الوضع التسلسلي.
-ssh-connection
فرض استخدام بروتوكول `ssh-connection' العاري. من المحتمل أن يكون هذا مفيدًا فقط عند الاتصال بخادم psusan(1)، وغالبًا ما يكون بمسار مطلق لمقبس مجال Unix بدلاً من المضيف.
-proxycmd أمر
بدلاً من إجراء اتصال TCP، استخدم الأمر كخادم وكيل؛ سيتم إعادة توجيه حركة مرور الشبكة إلى الإدخال والإخراج القياسي لـ الأمر. يجب أن يكون الأمر كلمة واحدة، لذا من المحتمل أن تحتاج إلى اقتباس من قبل shell.

سيتم استبدال السلاسل الخاصة %host و %port في الأمر باسم المضيف ورقم المنفذ الذي تريد الاتصال به؛ للحصول على علامة % حرفية، أدخل %%.

تُدعم أيضًا تسلسلات الهروب بشرطة مائلة للخلف، مثل تسلسل \n الذي يتم استبداله بسطر جديد حرفي؛ للحصول على شرطة مائلة للخلف حرفية، أدخل \\. (قد تكون هناك حاجة إلى المزيد من الهروب من قبل shell.)

(راجع دليل PuTTY الرئيسي للحصول على التفاصيل الكاملة للرموز المدعومة التي تبدأ بـ % والتي تبدأ بشرطة مائلة للخلف، على الرغم من أن معظمها قد لا يكون مفيدًا جدًا في هذا السياق.)

-P منفذ
الاتصال بالمنفذ المنفذ.
-l مستخدم
تعيين اسم المستخدم البعيد إلى مستخدم.
-m مسار
قراءة الأوامر البعيدة من الملف المحلي المسار.
-batch
تعطيل المطالبات التفاعلية.
-sanitise-stderr
-sanitise-stdout
-no-sanitise-stderr
-no-sanitise-stdout
بشكل افتراضي، يمكن لـ Plink اختيار تصفية أحرف التحكم إذا بدا ذلك مناسبًا، لمنع العمليات البعيدة من إرسال تسلسلات هروب مربكة. تتجاوز هذه الخيارات السلوك الافتراضي لـ Plink لتمكين أو تعطيل مثل هذه التصفية على قنوات الخطأ القياسي والإخراج القياسي.
-pwfile اسم_الملف
افتح الملف المحدد، واستخدم السطر الأول من النص المقروء منه ككلمة مرور بعيدة.
-pw كلمة_المرور
تعيين كلمة المرور البعيدة إلى كلمة_المرور. تحذير: سيؤدي هذا على الأرجح إلى جعل كلمة المرور مرئية للمستخدمين الآخرين على الجهاز المحلي (عبر أوامر مثل `ps' أو `w'). استخدم -pwfile بدلاً من ذلك.
-L [عنوان_المصدر:]منفذ_المصدر:المضيف_الوجهة:منفذ_الوجهة
إعداد إعادة توجيه منفذ محلي: استمع على منفذ_المصدر (أو عنوان_المصدر:منفذ_المصدر إذا تم تحديده)، وقم بإعادة توجيه أي اتصالات عبر اتصال SSH إلى عنوان الوجهة المضيف_الوجهة:منفذ_الوجهة. يعمل فقط في SSH.
-R [عنوان_المصدر:]منفذ_المصدر:المضيف_الوجهة:منفذ_الوجهة
إعداد إعادة توجيه منفذ بعيد: اطلب من خادم SSH الاستماع على منفذ_المصدر (أو عنوان_المصدر:منفذ_المصدر إذا تم تحديده)، وإعادة توجيه أي اتصالات مرة أخرى عبر اتصال SSH حيث سيقوم العميل بتمريرها إلى عنوان الوجهة المضيف_الوجهة:منفذ_الوجهة. يعمل فقط في SSH.
-D [عنوان_المصدر:]منفذ_المصدر
إعداد إعادة توجيه منفذ ديناميكي. يستمع العميل على منفذ_المصدر (أو عنوان_المصدر:منفذ_المصدر إذا تم تحديده)، وينفذ خادم SOCKS. لذلك يمكنك توجيه التطبيقات التي تدعم SOCKS إلى هذا المنفذ وستستخدم تلقائيًا اتصال SSH لتوجيه جميع اتصالاتها. يعمل فقط في SSH.
-X
تمكين إعادة توجيه X11.
-x
تعطيل إعادة توجيه X11 (افتراضي).
-A
تمكين إعادة توجيه الوكيل.
-a
تعطيل إعادة توجيه الوكيل (افتراضي).
-t
تمكين تخصيص pty (افتراضي إذا لم يتم تحديد أمر).
-T
تعطيل تخصيص pty (افتراضي إذا تم تحديد أمر).
-1
فرض استخدام بروتوكول SSH الإصدار 1.
-2
فرض استخدام بروتوكول SSH الإصدار 2.
-4, -6
فرض استخدام IPv4 أو IPv6 لاتصالات الشبكة.
-C
تمكين ضغط SSH.
-i ملف_المفتاح
ملف المفتاح الخاص للمصادقة على المستخدم. بالنسبة لمفاتيح SSH-2، يجب أن يكون ملف المفتاح هذا بتنسيق PPK الخاص بـ PuTTY، وليس بتنسيق OpenSSH أو أي تنسيق آخر.

إذا كنت تستخدم وكيل مصادقة، يمكنك أيضًا تحديد مفتاح عام هنا (بتنسيق RFC 4716 أو OpenSSH)، لتحديد أي من مفاتيح الوكيل سيتم استخدامه.

-noagent
لا تحاول استخدام وكيل مصادقة للمصادقة المحلية. (هذا لا يؤثر على إعادة توجيه الوكيل.)
-agent
السماح باستخدام وكيل مصادقة. (هذا الخيار ضروري فقط لتجاوز إعداد في جلسة محفوظة.)
-no-trivial-auth
قطع الاتصال بأي خادم SSH يقبل المصادقة دون أن يطلب أي نوع من كلمات المرور أو التوقيعات أو الرموز. (قد ترغب في تمكين هذا لخادم تتوقع دائمًا أن يتحدىك، على سبيل المثال للتأكد من أنك لا تدخل عرضًا كلمة المرور لملف المفتاح الخاص بك إلى خادم تم اختراقه ينتحل هوية مطالبة كلمة المرور الخاصة بـ Plink.)
-noshare
لا تختبر ولا تحاول مشاركة اتصال موجود، قم دائمًا بإنشاء اتصال جديد.
-share
اختبر وحاول مشاركة اتصال موجود.
-hostkey مفتاح
حدد مفتاح عام للمضيف مقبول. يمكن تحديد هذا الخيار عدة مرات؛ يمكن أن يكون كل مفتاح إما بصمة (SHA256:AbCdE...، 99:aa:bb:...، إلخ) أو كتلة مشفرة بـ base64 بتنسيق سطر واحد الخاص بـ OpenSSH.

تجاوز تحديد هذا الخيار إدارة مفتاح المضيف الآلية؛ سيتم قبول المفاتيح المحددة فقط على سطر الأوامر (ما لم تقم جلسة محفوظة أيضًا بتجاوز مفاتيح المضيف، وفي هذه الحالة سيتم إضافة تلك المفاتيح.

plink(1) - plink - PuTTY link

NAME

plink – PuTTY link

SYNOPSIS

plink [options] [user@] host [-P port] [-pw password]

plink [options] -load saved-session [-pw password]

DESCRIPTION

plink is a command-line tool for connecting to remote systems using the SSH, Telnet or Rlogin protocols. It is often used for automating tasks that would normally require an interactive login.

plink is part of the PuTTY suite of tools, and it shares a lot of its configuration options with the graphical PuTTY client.

OPTIONS

All the command-line options are optional. If no options are specified, then plink will attempt to log in to the remote host using your local username, and will attempt to negotiate an interactive session.

-pw password
Specifies the password to use for authentication. You should only use this option if you are absolutely sure that no one will be able to observe your command line. It is far more secure to use SSH keys for authentication, which plink supports via the -keyfile option.
-keyfile filename
Specifies the name of the private key file to use for authentication (SSH-2 only).
-load session-name
Loads the specified saved session from PuTTY's configuration.
-v
Requests verbose output. This will cause plink to print a lot of diagnostic information about the progress of the connection and authentication.
-loadhostkey keyfile
Load the remote host's public key from the specified file, instead of prompting the user if the key is unknown or changed.
-hostkey keytype signature
Specify the expected public key for the remote host. The key is given in one of the formats supported by PuTTYgen, and the signature is the base64 encoded signature of the key's fingerprint.
-nc host:port
Make a remote network connection from the server instead of starting a shell or command.
-sercfg configuration-string
Specify the configuration parameters for the serial port, in -serial mode. configuration-string should be a comma-separated list of configuration parameters as follows:
•
Any single digit from 5 to 9 sets the number of data bits.
•
`1', `1.5' or `2' sets the number of stop bits.
•
Any other numeric string is interpreted as a baud rate.
•
A single lower-case letter specifies the parity: `n' for none, `o' for odd, `e' for even, `m' for mark and `s' for space.
•
A single upper-case letter specifies the flow control: `N' for none, `X' for XON/XOFF, `R' for RTS/CTS and `D' for DSR/DTR.
-sshlog logfile
-sshrawlog logfile
For SSH connections, these options make plink log protocol details to a file. (Some of these may be sensitive, although by default an effort is made to suppress obvious passwords.)

-sshlog logs decoded SSH packets and other events (those that -v would print). -sshrawlog additionally logs the raw encrypted packet data.

-logoverwrite
If Plink is configured to write to a log file that already exists, discard the existing file.
-logappend
If Plink is configured to write to a log file that already exists, append new log data to the existing file.
-shareexists
Instead of making a new connection, test for the presence of an existing connection that can be shared. The desired session can be specified in any of the usual ways.

Returns immediately with a zero exit status if a suitable `upstream' exists, nonzero otherwise.
