place(n)

الحزمة: tk

التراخيص: TCL

place(n) أوامر Tk المضمنة place(n)

الاسم

place - مدير هندسة للتثبيت الثابت أو المطاطي

ملخص

place option arg ?arg ...?

الوصف

الـ placer هو مدير هندسة لـ Tk. يوفر تثبيتًا بسيطًا وثابتًا للنوافذ، حيث تحدد الحجم والموقع الدقيق لنافذة واحدة، تسمى المحتوى، داخل نافذة أخرى، تسمى الحاوية. يوفر الـ placer أيضًا تثبيتًا مطاطيًا، حيث تحدد حجم وموقع المحتوى بالنسبة لأبعاد الحاوية، بحيث يتغير حجم المحتوى وموقعه استجابةً للتغييرات في حجم الحاوية. أخيرًا، يسمح لك الـ placer بدمج هذه الأساليب من التثبيت بحيث، على سبيل المثال، يكون للمحتوى عرض وارتفاع ثابتين ولكنه يتوسط داخل الحاوية.

place window option value ?option value ...?
ترتيب الـ placer لإدارة هندسة المحتوى الذي اسمه window. تتكون الوسيطات المتبقية من زوج أو أكثر من option-value التي تحدد الطريقة التي تتم بها إدارة هندسة window. قد يحتوي option على أي من القيم التي يقبلها أمر place configure.
place configure window ?option? ?value option value ...?
استعلام أو تعديل خيارات هندسة المحتوى المحدد بواسطة window. إذا لم يتم تحديد option، فإن هذا الأمر يعيد قائمة تصف الخيارات المتاحة (انظر Tk_ConfigureInfo للحصول على معلومات حول تنسيق هذه القائمة). إذا تم تحديد option بدون value، فإن الأمر يعيد قائمة تصف الخيار المسمى الواحد (ستكون هذه القائمة مطابقة للقائمة الفرعية المقابلة للقيمة التي تم إرجاعها إذا لم يتم تحديد option). إذا تم تحديد زوج أو أكثر من option-value، فإن الأمر يعدل الخيار (الخيارات) المعطى (المعطاة) ليأخذ القيمة (القيم) المعطاة؛ في هذه الحالة، يعيد الأمر سلسلة نصية فارغة.

تدعم أزواج option-value التالية:

-anchor where
Where تحدد أي نقطة من window سيتم وضعها في الموقع (x,y) المحدد بواسطة خيارات -x، -y، -relx، و -rely. نقطة الربط تكون من حيث المساحة الخارجية لـ window بما في ذلك حدها، إن وجد. لذلك، إذا كان where هو se، فستظهر الزاوية السفلية اليمنى لحد window في الموقع (x,y) المحدد في الحاوية. نقطة الربط الافتراضية هي nw.
-bordermode mode
Mode تحدد الدرجة التي يتم بها استخدام الحدود داخل الحاوية لتحديد وضع المحتوى. القيمة الافتراضية والأكثر شيوعًا هي inside. في هذه الحالة، يعتبر الـ placer مساحة الحاوية هي المساحة الداخلية للحاوية، داخل أي حد: الخيار -x 0 يتوافق مع إحداثي x مباشرة داخل الحد، والخييار -relwidth 1.0 يعني أن window ستملأ المساحة داخل حد الحاوية.

إذا كان mode هو outside، فإن الـ placer يعتبر مساحة الحاوية لتشمل حدها؛ هذا الوضع يستخدم عادة عند وضع window خارج حاويتها، كما هو الحال مع خيارات -x 0 -y 0 -anchor ne. أخيرًا، يمكن تحديد mode كـ ignore، وفي هذه الحالة يتم تجاهل الحدود: تعتبر مساحة الحاوية مساحتها X الرسمية، والتي تشمل أي حد داخلي ولكن لا يوجد حد خارجي. وضع bordermode بقيمة ignore ربما لا يكون مفيدًا جدًا.

-height size
Size تحدد الارتفاع لـ window بوحدات الشاشة (أي أي شكل من الأشكال التي تقبلها Tk_GetPixels). الارتفاع سيكون البعد الخارجي لـ window بما في ذلك حدها، إن وجد. إذا كان size سلسلة نصية فارغة، أو إذا لم يتم تحديد خيار -height أو -relheight، فسيتم استخدام الارتفاع المطلوب داخليًا بواسطة النافذة.
-in container
Container تحدد اسم المسار للنافذة التي سيتم وضع window بالنسبة لها. يجب أن تكون Container إما الوالد لـ window أو سليل للوالد لـ window. بالإضافة إلى ذلك، يجب أن تكون كل من container و window سليلين لنفس النافذة العليا. هذه القيود ضرورية لضمان أن window تكون مرئية كلما كانت container مرئية. إذا لم يتم تحديد هذا الخيار، فإن النافذة الأخرى تكون افتراضيًا هي الوالد لـ window.
-relheight size
Size تحدد الارتفاع لـ window. في هذه الحالة، يتم تحديد الارتفاع كرقم عشري نسبي لارتفاع الحاوية: 0.5 يعني أن window ستكون نصف ارتفاع الحاوية، 1.0 يعني أن window سيكون لها نفس ارتفاع الحاوية، وهكذا. إذا تم تحديد كل من -height و -relheight للمحتوى، يتم جمع قيمهما. على سبيل المثال، -relheight 1.0 -height -2 يجعل المحتوى أقصر بـ 2 بكسل من الحاوية.
-relwidth size
Size تحدد العرض لـ window. في هذه الحالة، يتم تحديد العرض كرقم عشري نسبي لعرض الحاوية: 0.5 يعني أن window ستكون نصف عرض الحاوية، 1.0 يعني أن window سيكون لها نفس عرض الحاوية، وهكذا. إذا تم تحديد كل من -width و -relwidth للمحتوى، يتم جمع قيمهما. على سبيل المثال، -relwidth 1.0 -width 5 يجعل المحتوى أعرض بـ 5 بكسلات من الحاوية.
-relx location
Location تحدد الإحداثي x داخل نافذة الحاوية لنقطة الربط لـ window. في هذه الحالة، يتم تحديد الموقع بطريقة نسبية كرقم عشري: 0.0 يتوافق مع الحافة اليسرى للحاوية و 1.0 يتوافق مع الحافة اليمنى للحاوية. لا يلزم أن يكون Location في النطاق 0.0-1.0. إذا تم تحديد كل من -x و -relx للمحتوى، يتم جمع قيمهما. على سبيل المثال، -relx 0.5 -x -2 يضع الحافة اليسرى للمحتوى بـ 2 بكسل إلى يسار مركز حاويته.
-rely location
Location تحدد الإحداثي y داخل نافذة الحاوية لنقطة الربط لـ window. في هذه الحالة، يتم تحديد القيمة بطريقة نسبية كرقم عشري: 0.0 يتوافق مع الحافة العلوية للحاوية و 1.0 يتوافق مع الحافة السفلية للحاوية. لا يلزم أن يكون Location في النطاق 0.0-1.0. إذا تم تحديد كل من -y و -rely للمحتوى، يتم جمع قيمهما. على سبيل المثال، -rely 0.5 -x 3 يضع الحافة العلوية للمحتوى بـ 3 بكسلات أسفل مركز حاويته.
-width size
Size تحدد العرض لـ window بوحدات الشاشة (أي أي شكل من الأشكال التي تقبلها Tk_GetPixels). سيكون العرض هو العرض الخارجي لـ window بما في ذلك حدها، إن وجد. إذا كان size سلسلة نصية فارغة، أو إذا لم يتم تحديد خيار -width أو -relwidth، فسيتم استخدام العرض المطلوب داخليًا بواسطة النافذة.
-x location
Location تحدد الإحداثي x داخل نافذة الحاوية لنقطة الربط لـ window. يتم تحديد الموقع بوحدات الشاشة (أي أي شكل من الأشكال التي تقبلها Tk_GetPixels) ولا يلزم أن يكون ضمن حدود نافذة الحاوية.
-y location
Location تحدد الإحداثي y داخل نافذة الحاوية لنقطة الربط لـ window. يتم تحديد الموقع بوحدات الشاشة (أي أي شكل من الأشكال التي تقبلها Tk_GetPixels) ولا يلزم أن يكون ضمن حدود نافذة الحاوية.

إذا تم تحديد نفس القيمة بشكل منفصل بخيارين مختلفين، مثل -x و -relx، فإن الخيار الأخير هو الذي يتم استخدامه ويتم تجاهل الخيار الأقدم.

PLACE

place ...?

DESCRIPTION

The place command provides geometry management for Tk windows. It is intended to provide a more flexible and powerful alternative to the pack and grid commands. The place command manipulates the geometry of its child windows in response to requests from those child windows, or in response to explicit configuration commands from the application.

The place command operates on a container window, and manages the geometry of one or more content windows within that container. The container window is specified as the first argument to the place command. The content windows are specified as arguments to the subcommands.

The following is a list of the available subcommands:

place configure window ?arg ...?
Configures the geometry of window. The arguments are a list of name-value pairs. The following options are available:
  • -anchor anchor: Specifies how to anchor the window within its container. Valid values are the standard Tk anchors: n, ne, e, se, s, sw, w, nw, and center. The default is nw.
  • -bordermode mode: Specifies whether window geometry calculations should include the container window's border. Valid values are inside (default) and outside.
  • -height height: Specifies the height of the window. If the value is a number, it is interpreted as screen units. If it ends with a percent sign (e.g., 50%), it is interpreted as a percentage of the container's height.
  • -in master: Specifies the container window for window. If this option is not specified, the container is assumed to be the parent of window.
  • -relheight relheight: Specifies the height of the window as a percentage of the container's height.
  • -relwidth relwidth: Specifies the width of the window as a percentage of the container's width.
  • -relx relx: Specifies the x-coordinate of the anchor point of the window as a percentage of the container's width.
  • -rely rely: Specifies the y-coordinate of the anchor point of the window as a percentage of the container's height.
  • -width width: Specifies the width of the window. If the value is a number, it is interpreted as screen units. If it ends with a percent sign (e.g., 50%), it is interpreted as a percentage of the container's width.
  • -x x: Specifies the x-coordinate of the anchor point of the window. If the value is a number, it is interpreted as screen units. If it ends with a percent sign (e.g., 50%), it is interpreted as a percentage of the container's width.
  • -y y: Specifies the y-coordinate of the anchor point of the window. If the value is a number, it is interpreted as screen units. If it ends with a percent sign (e.g., 50%), it is interpreted as a percentage of the container's height.

The place configure command returns an empty string.

When a window is configured using place, it is automatically mapped if it is not already visible. If the window is unmapped, the configuration is still stored, but it has no visible effect until the window is mapped again.

place forget window
Causes the placer to stop managing the geometry of window. As a side effect of this command window will be unmapped so that it does not appear on the screen. If window is not currently managed by the placer then the command has no effect. This command returns an empty string.
place info window
Returns a list giving the current configuration of window. The list consists of option-value pairs in exactly the same form as might be specified to the place configure command.
place slaves window
Returns a list of all the content windows for which window is the container. If there is no content for window then an empty string is returned.
place content window
Synonym for place slaves window.

If the configuration of a window has been retrieved with place info, that configuration can be restored later by first using place forget to erase any existing information for the window and then invoking place configure with the saved information.

FINE POINTS

It is not necessary for the container window to be the parent of the content window. This feature is useful in at least two situations. First, for complex window layouts it means you can create a hierarchy of subwindows whose only purpose is to assist in the layout of the parent. The “real children” of the parent (i.e. the windows that are significant for the application's user interface) can be children of the parent yet be placed inside the windows of the geometry-management hierarchy. This means that the path names of the “real children” do not reflect the geometry-management hierarchy and users can specify options for the real children without being aware of the structure of the geometry-management hierarchy.

A second reason for having a container different than the content's parent is to tie two siblings together. For example, the placer can be used to force a window always to be positioned centered just below one of its siblings by specifying the configuration

-in sibling -relx 0.5 -rely 1.0 -anchor n -bordermode outside
Whenever the sibling is repositioned in the future, the content will be repositioned as well.

Unlike many other geometry managers (such as the packer) the placer does not make any attempt to manipulate the geometry of the container windows or the parents of content windows (i.e. it does not set their requested sizes). To control the sizes of these windows, make them windows like frames and canvases that provide configuration options for this purpose.

EXAMPLE

Make the label occupy the middle bit of the toplevel, no matter how it is resized:

label .l -text "In the\nMiddle!" -bg black -fg white
place .l -relwidth .3 -relx .35 -relheight .3 -rely .35
