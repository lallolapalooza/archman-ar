ping(8)

الحزمة: iputils

التراخيص: BSD-3-Clause, GPL-2.0-or-later

PING(8) iputils PING(8)

الاسم

ping - إرسال طلبات ICMP ECHO_REQUEST إلى المضيفين الشبكيين

الاستخدام

ping [-aAbBdCDfhHLnOqrRUvV346] [-c العدد] [-e المعرف] [-F تسمية التدفق] [-i الفاصل] [-I الواجهة] [-l التحميل المسبق] [-m العلامة] [-M خيار pmtudisc] [-N خيار nodeinfo] [-w المهلة] [-W المهلة] [-p النمط] [-Q tos] [-s حجم الحزمة] [-S حجم المخزن المؤقت للإرسال] [-t ttl] [-T خيار الطابع الزمني] [hop...] {الوجهة}

الوصف

يستخدم ping حزمة ICMP ECHO_REQUEST الإلزامية لاستدعاء ICMP ECHO_RESPONSE من مضيف أو بوابة. تحتوي حزم ECHO_REQUEST (“pings”) على رأس IP ورأس ICMP، يتبعهما struct timeval ثم عدد عشوائي من بايتات “pad” المستخدمة لملء الحزمة.

يعمل ping مع كل من IPv4 و IPv6. يمكن فرض استخدام واحد منهما فقط عن طريق تحديد -4 أو -6.

يمكن لـ ping أيضًا إرسال استعلامات معلومات العقدة لـ IPv6 (RFC4620). قد لا يتم السماح بالبوابات الوسيطة، لأن التوجيه المصدر لـ IPv6 تم إهماله (RFC5095).

خيارات

-3

دقة RTT (لا تقرب وقت النتيجة).

-4

استخدام IPv4 فقط.

-6

استخدام IPv6 فقط.

-a

صوت ping.

-A

Ping تكيفي. تتكيف فترة الاستجابة مع وقت الاستجابة، بحيث لا يوجد فعليًا أكثر من مسبار واحد (أو أكثر، إذا تم تعيين التحميل المسبق) بدون رد في الشبكة. الفترة الافتراضية هي 2 مللي ثانية، لمزيد من المعلومات انظر الخيار -i. في الشبكات ذات RTT المنخفض، يكون هذا الوضع مكافئًا بشكل أساسي لوضع الفيضان.

-b

السماح بإرسال ping إلى عنوان البث.

-B

لا تسمح لـ ping بتغيير عنوان مصدر الاستعلامات. يتم ربط العنوان بواحد تم اختياره عند بدء ping.

-c العدد

توقف بعد إرسال العدد من حزم ECHO_REQUEST. مع خيار المهلة، ينتظر ping عدد العدد من حزم ECHO_REPLY، حتى تنتهي المهلة.

-C

استدعاء استدعاءات النظام connect() عند إنشاء المقبس.

-d

تعيين خيار SO_DEBUG على المقبس المستخدم. بشكل أساسي، لا يستخدم نواة Linux هذا الخيار للمقبس.

-D

طباعة الطابع الزمني (وقت يونكس + ميكروثواني كما في gettimeofday) قبل كل سطر.

-e المعرف

تعيين حقل التعريف لـ ECHO_REQUEST. القيمة 0 تعني استخدام مقبس خام (غير مدعوم على مقبس بيانات ICMP). قد يتم طباعة قيمة الحقل مع الخيار -v.

-f

Ping الفيضان. لكل ECHO_REQUEST تم إرساله، تتم طباعة فترة “.”، بينما لكل ECHO_REPLY تم استلامه، تتم طباعة حرف مسافة للخلف. يوفر هذا عرضًا سريعًا لعدد الحزم المفقودة. إذا لم يتم توفير الفاصل، فإنه يضبط الفاصل على صفر ويخرج الحزم بأسرع ما يمكن عند عودتها أو مائة مرة في الثانية، أيهما أكبر. يمكن فقط للمستخدم الخارق استخدام هذا الخيار بفاصل صفري.

-F تسمية التدفق

IPv6 فقط. تخصيص وتعيين تسمية تدفق 20 بت (بالنظام السداسي عشري) على حزم طلب الصدى. إذا كانت القيمة صفرًا، تقوم النواة بتخصيص تسمية تدفق عشوائية.

-h

عرض المساعدة.

-H

فرض تحليل أسماء DNS للإخراج. مفيد للوجهات الرقمية، أو الخيار -f، الذي لا يقوم بإجرائه افتراضيًا. يمكن أن يساعد أيضًا في تجاوز مشاكل تحليل DNS. يتجاوز الخيار -n المحدد سابقًا. انظر أيضًا متغير البيئة IPUTILS_PING_PTR_LOOKUP.

-i الفاصل

انتظر الفاصل ثانية بين إرسال كل حزمة. يمكن استخدام الأعداد الحقيقية مع نقطة كفاصل عشري (بغض النظر عن إعداد المحلية). الافتراضي هو الانتظار لمدة ثانية واحدة بين كل حزمة بشكل طبيعي، أو عدم الانتظار في وضع الفيضان. لا يمكن للمستخدم الخارق سوى تعيين فاصل أقل من 2 مللي ثانية. لدى ping البث والمتعدد قيود أعلى للمستخدم العادي: الحد الأدنى هو ثانية واحدة.

-I الواجهة

الواجهة هي إما عنوان، أو اسم واجهة، أو اسم VRF. إذا كانت الواجهة عنوانًا، فإنها تعين عنوان المصدر إلى عنوان الواجهة المحدد. إذا كانت الواجهة اسم واجهة، فإنها تعين واجهة المصدر إلى الواجهة المحددة. إذا كانت الواجهة اسم VRF، يتم توجيه كل حزمة باستخدام جدول التوجيه المقابل؛ في هذه الحالة، يمكن تكرار الخيار -I لتحديد عنوان مصدر. ملاحظة: بالنسبة لـ IPv6، عند إجراء ping إلى عنوان نطاق محلي للرابط، يمكن استخدام تحديد الرابط (بواسطة ترميز '%'- notation في الوجهة، أو بواسطة هذا الخيار) ولكن لم يعد مطلوبًا.

-l التحميل المسبق

إذا تم تحديد التحميل المسبق، يرسل ping عددًا كبيرًا من الحزم دون انتظار الرد. لا يمكن للمستخدم الخارق سوى اختيار تحميل مسبق أكثر من 3.

-L

منع إعادة توجيه حزم البث المتعدد. ينطبق هذا العلامة فقط إذا كانت وجهة ping هي عنوان بث متعدد.

-m العلامة

استخدم العلامة لوضع علامة على الحزم الصادرة. هذا مفيد لمجموعة متنوعة من الأسباب داخل النواة مثل استخدام توجيه السياسات لاختيار معالجة صادرة محددة. يتطلب قدرة CAP_NET_ADMIN أو CAP_NET_RAW (منذ Linux 5.17)، انظر socket(7).

-M خيار pmtudisc

اختر استراتيجية اكتشاف MTU للمسار (Path MTU Discovery). قد يكون خيار pmtudisc إما do (تعيين علم DF ولكن يخضع لفحوصات PMTU بواسطة النواة، سيتم رفض الحزم الكبيرة جدًا)، want (قم بإجراء اكتشاف PMTU، قم بالتجزئة محليًا عندما يكون حجم الحزمة كبيرًا)، probe (تعيين علم DF وتجاوز فحوصات PMTU، مفيد للاستجواب)، أو dont (لا تقم بتعيين علم DF).

-N خيار nodeinfo

IPv6 فقط. إرسال استعلامات معلومات العقدة لـ IPv6 (RFC4620)، بدلاً من Echo Request. يتطلب قدرة CAP_NET_RAW.

DUPLICATE AND DAMAGED PACKETS

Sometimes we receive the same ICMP echo reply twice. This can happen if we send two ICMP echo requests too close together. If the data part of the packet is also corrupted, the packet is marked as "duplicate, downstream". If the data is okay, it is marked as "duplicate, upstream". If the packet is damaged, it is marked as "received, while still processing".

These messages are not errors, but they might indicate a problem with the network. The primary use of this feature is to check for bugs in the implementation of the interface.

ID COLLISIONS

On systems that can only send one packet (datagram) at a time, ping can be used to find these collisions. When pinging from two hosts at the same time, if they use the same ID field for their requests, they may receive bad data. It is recommended to use the -i option to try and space out the pings.

TRYING DIFFERENT DATA PATTERNS

It is possible to specify different patterns for the data part of the ICMP packet. You can use the -p option of ping to fill the data with a specified pattern. This is useful for testing how the network handles different kinds of data. For example, you might want to send a file with a specific pattern of bytes to another host and see how the network handles it. You can then examine this file for repeated patterns that you can test using the -p option of ping.

TTL DETAILS

The TTL value of an IP packet represents the maximum number of IP routers that the packet can go through before being thrown away. In current practice you can expect each router in the Internet to decrement the TTL field by exactly one.

The TTL field for TCP packets may take various values. The maximum possible value of this field is 255, a recommended initial value is 64. For more information, see the TCP/Lower-Level Interface section of RFC9293.

In normal operation ping prints the TTL value from the packet it receives. When a remote system receives a ping packet, it can do one of three things with the TTL field in its response:

• Not change it; this is what Berkeley Unix systems did before the 4.3BSD Tahoe release. In this case the TTL value in the received packet will be 255 minus the number of routers in the round-trip path.
• Set it to 255; this is what current Berkeley Unix systems do. In this case the TTL value in the received packet will be 255 minus the number of routers in the path from the remote system to the pinging host.
• Set it to some other value. Some machines use the same value for ICMP packets that they use for TCP packets, for example either 30 or 60. Others may use completely wild values.

BUGS

• Many Hosts and Gateways ignore the RECORD_ROUTE option.
• The maximum IP header length is too small for options like RECORD_ROUTE to be completely useful. There's not much that can be done about this, however.
• Flood pinging is not recommended in general, and flood pinging the broadcast address should only be done under very controlled conditions.

HISTORY

The ping command appeared in 4.3BSD.

The version described here is its descendant specific to Linux.

As of version s20150815, the ping6 binary doesn't exist anymore. It has been merged into ping. Creating a symlink named ping6 pointing to ping will result in the same functionality as before.

SECURITY

ping requires CAP_NET_RAW capability to be executed 1) if the program is used for non-echo queries (see -N option) or when the identification field set to 0 for ECHO_REQUEST (see -e), or 2) if kernel does not support ICMP datagram sockets, or 3) if the user is not allowed to create an ICMP echo socket. The program may be used as set-uid root.
