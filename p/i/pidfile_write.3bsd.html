pidfile_write(3bsd)

الحزمة: libbsd

التراخيص: custom

NAME

pidfile_fileno, pidfile_open, pidfile_write, pidfile_close, pidfile_remove — manage PID files

LIBRARY

libbsd

Based on the flopen(3bsd) library function.

SYNOPSIS

#include <bsd/stdio.h>

FILE *
pidfile_open(const char *path, int flags, mode_t mode);

int
pidfile_write(FILE *fp);

int
pidfile_close(FILE *fp);

int
pidfile_remove(const char *path);

int
pidfile_fileno(FILE *fp);

DESCRIPTION

The functions described here provide a simple interface for writing and managing daemon process ID (PID) files.

pidfile_open() creates or opens a PID file specified by path. The PID file is opened with the specified flags and mode, in a manner similar to the open(2) system call. If the PID file already exists, pidfile_open() will truncate it and overwrite it with the current process ID. If the PID file does not exist, it will be created with the specified mode. The current process ID will be written to the file, and the function returns a FILE pointer to the opened PID file. The returned file pointer is unbuffered.

pidfile_write() writes the current process ID to the PID file pointed to by fp. This function should be called after pidfile_open() if the caller wants to ensure the PID file contains the correct PID, for example, after forking a child process.

pidfile_close() closes the PID file pointed to by fp. If the PID file was created by pidfile_open() (i.e., it did not exist before), it will be removed after closing. Otherwise, it will be left as is. This function should be called when the daemon exits normally.

pidfile_remove() removes the PID file specified by path. This function should be used to manually remove a PID file, for example, if the daemon exits abnormally.

pidfile_fileno() returns the file descriptor associated with the FILE pointer fp. This can be useful if you need to perform operations on the PID file using low-level file descriptor functions, such as flock(2) or unlink(2) system calls and the flopen(3bsd) library function.

RETURN VALUES

pidfile_open() returns a pointer to an open FILE on success, or NULL on failure.

pidfile_write(), pidfile_close(), and pidfile_remove() return 0 on success, or -1 on failure.

pidfile_fileno() returns the file descriptor associated with fp on success, or -1 on failure.

EXAMPLES

To create a PID file named "/var/run/mydaemon.pid":

...

FILE *fp;

fp = pidfile_open("/var/run/mydaemon.pid", 0, 0644);
if (fp == NULL) {
        err(1, "Failed to open PID file %s", "/var/run/mydaemon.pid");
}
if (pidfile_write(fp) == -1) {
        err(1, "Failed to write PID to PID file %s", "/var/run/mydaemon.pid");
}
...
/* Fork, exec, etc. */
...
if (pidfile_close(fp) == -1) {
        err(1, "Failed to close PID file %s", "/var/run/mydaemon.pid");
}

If the daemon exits abnormally:

...

if (pidfile_remove("/var/run/mydaemon.pid") == -1) {
        err(1, "Failed to remove PID file %s", "/var/run/mydaemon.pid");
}

ERRORS

The functions may fail if:

[EACCES]
The PID file could not be created or opened due to permissions.
[EEXIST]
The PID file already exists and another process holds an exclusive lock on it.
[EINVAL]
Improper function use. Probably called not from the process which used pidfile_open().
[ENOENT]
A directory component of the path prefix does not exist, or the path string specifies an empty string.
[ENOMEM]
Not enough memory available.
[ENOSPC]
The directory containing the file has no room for the file.

The underlying system calls like open(2), write(2), close(2), and unlink(2) system calls and the flopen(3bsd) library function.

pidfile_fileno() will fail if:

[EINVAL]
Improper function use. Probably called not from the process which used pidfile_open().

SEE ALSO

open(2), daemon(3), flopen(3bsd)

HISTORY

The functions pidfile_open(), pidfile_write(), pidfile_close() and pidfile_remove() first appeared in FreeBSD 5.5.

The function pidfile_fileno() first appeared in FreeBSD 10.0.
