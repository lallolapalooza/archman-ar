NAME

\n

pip-wheel - description of pip wheel command

\n
\n
\n

DESCRIPTION

\n

Build Wheel archives for your requirements and dependencies.

\n

Wheel is a built-package format, and offers the advantage of not\n recompiling your software during every install. For more details, see the\n wheel docs: https://wheel.readthedocs.io/en/latest/

\n

'pip wheel' uses the build system interface as described here:\n https://pip.pypa.io/en/stable/reference/build-system/

\n
\n
\n

USAGE

\n
\n
\n
python -m pip wheel [options] <requirement specifier> ...\npython -m pip wheel [options] -r <requirements file> ...\npython -m pip wheel [options] [-e] <vcs project url> ...\npython -m pip wheel [options] [-e] <local project path> ...\npython -m pip wheel [options] <archive url/path> ...
\n
\n
\n
\n
\n

OPTIONS

\n
\n
\n
-w, --wheel-dir\n <dir>
\n
Build wheels into <dir>, where the default is the current working\n directory.\n

(environment variable: PIP_WHEEL_DIR)

\n
\n
\n
\n
\n
\n
--no-binary\n <format_control>
\n
Do not use binary packages. Can be supplied multiple times, and each time\n adds to the existing value. Accepts either ":all:" to disable\n all binary packages, ":none:" to empty the set (notice the\n colons), or one or more package names with commas between them (no\n colons). Note that some packages are tricky to compile and may fail to\n install when this option is used on them.\n

(environment variable: PIP_NO_BINARY)

\n
\n
\n
\n
\n
\n
--only-binary\n <format_control>
\n
Do not use source packages. Can be supplied multiple times, and each time\n adds to the existing value. Accepts either ":all:" to disable\n all source packages, ":none:" to empty the set, or one or more\n package names with commas between them. Packages without binary\n distributions will fail to install when this option is used on them.\n

(environment variable: PIP_ONLY_BINARY)

\n
\n
\n
\n
\n
\n
--prefer-binary
\n
Prefer binary packages over source packages, even if the source packages\n are newer.\n

(environment variable: PIP_PREFER_BINARY)

\n
\n
\n
\n
\n
\n
--no-build-isolation
\n
Disable isolation when building a modern source distribution. Build\n dependencies specified by PEP 518 must be already installed if this option\n is used.\n

(environment variable: PIP_NO_BUILD_ISOLATION)

\n
\n
\n
\n
\n
\n
--check-build-dependencies
\n
Check the build dependencies.\n

(environment variable:\n PIP_CHECK_BUILD_DEPENDENCIES)

\n
\n
\n
\n
\n
\n
-c, --constraint\n <file>
\n
Constrain versions using the given constraints file. This option can be\n used multiple times.\n

(environment variable: PIP_CONSTRAINT)

\n
\n
\n
\n
\n
\n
--build-constraint\n <file>
\n
Constrain build dependencies using the given constraints file. This option\n can be used multiple times.\n

(environment variable: PIP_BUILD_CONSTRAINT)

\n
\n
\n
\n
\n
\n
-e, --editable\n <path/url>
\n
Install a project in editable mode (i.e. setuptools "develop\n mode") from a local project path or a VCS url.\n

(environment variable: PIP_EDITABLE)

\n
\n
\n
\n
\n
\n
-r, --requirement\n <file>
\n
Install from the given requirements file. This option can be used multiple\n times.\n

(environment variable: PIP_REQUIREMENT)

\n
\n
\n
\n
\n
\n
--src\n <dir>
\n
Directory to check out editable projects into. The default in a virtualenv\n is "<venv path>/src". The default for global installs is\n "<current dir>/src".\n

(environment variable: PIP_SRC, PIP_SOURCE,\n PIP_SOURCE_DIR, PIP_SOURCE_DIRECTORY)

\n
\n
\n
\n
\n
\n
--ignore-requires-python
\n
Ignore the Requires-Python information.\n

(environment variable: PIP_IGNORE_REQUIRES_PYTHON)

\n
\n
\n
\n
\n
\n
--no-deps
\n
Don't install package dependencies.\n

(environment variable: PIP_NO_DEPS,\n PIP_NO_DEPENDENCIES)

\n
\n
\n
\n
\n
\n
--progress-bar\n <progress_bar>
\n
Specify whether the progress bar should be used. In 'auto' mode, --quiet\n will suppress all progress bars. [auto, on, off, raw] (default: auto)\n

(environment variable: PIP_PROGRESS_BAR)

\n

\n
\n
--no-verify
\n
Don't verify if built wheel is valid.\n

(environment variable: PIP_NO_VERIFY)

\n
\n
\n
\n
\n
\n
-C, --config-settings\n <settings>
\n
Configuration settings to be passed to the build backend. Settings take\n the form KEY=VALUE. Use multiple --config-settings options to pass\n multiple keys to the backend.\n

(environment variable: PIP_CONFIG_SETTINGS)

\n
\n
\n
\n
\n
\n
--pre
\n
Include pre-release and development versions. By default, pip only finds\n stable versions.\n

(environment variable: PIP_PRE)

\n

\n
\n
\n
--require-hashes
\n
Require a hash to check each requirement against, for repeatable installs.\n This option is implied when any package in a requirements file has a\n --hash option.\n

(environment variable: PIP_REQUIRE_HASHES)

\n

\n
--group\n <[path:]group>
\n
Install a named dependency-group from a "pyproject.toml" file.\n If a path is given, the name of the file must be\n "pyproject.toml". Defaults to using "pyproject.toml"\n in the current directory.\n

(environment variable: PIP_GROUP)

\n

\n

\n
\n
--no-clean

Don't clean up build directories.\n

(environment variable: PIP_NO_CLEAN)

الاسم

\n

pip-wheel - وصف أمر pip wheel

\n
\n
\n

الوصف

\n

إنشاء أرشيفات Wheel لمتطلباتك وتبعياتك.

\n

Wheel هو تنسيق حزمة مبنية، ويوفر ميزة عدم إعادة تجميع برنامجك في كل مرة تثبيت. لمزيد من التفاصيل، راجع وثائق wheel: https://wheel.readthedocs.io/en/latest/

\n

يستخدم 'pip wheel' واجهة نظام البناء كما هو موضح هنا: https://pip.pypa.io/en/stable/reference/build-system/

\n
\n
\n

الاستخدام

\n
\n
\n
python -m pip wheel [options] <requirement specifier> ...\npython -m pip wheel [options] -r <requirements file> ...\npython -m pip wheel [options] [-e] <vcs project url> ...\npython -m pip wheel [options] [-e] <local project path> ...\npython -m pip wheel [options] <archive url/path> ...
\n
\n
\n
\n
\n

خيارات

\n
\n
\n
-w, --wheel-dir\n <dir>
\n
بناء عجلات في <dir>، حيث يكون الافتراضي هو الدليل الحالي.\n

(متغير البيئة: PIP_WHEEL_DIR)

\n
\n
\n
\n
\n
\n
--no-binary\n <format_control>
\n
لا تستخدم حزم ثنائية. يمكن تقديمها عدة مرات، وفي كل مرة تضاف إلى القيمة الموجودة. تقبل إما ":all:" لتعطيل جميع الحزم الثنائية، أو ":none:" لإفراغ المجموعة (لاحظ النقطتين)، أو اسم حزمة واحدة أو أكثر مع فواصل بينها (بدون نقطتين). لاحظ أن بعض الحزم صعبة التجميع وقد تفشل في التثبيت عند استخدام هذا الخيار عليها.\n

(متغير البيئة: PIP_NO_BINARY)

\n
\n
\n
\n
\n
\n
--only-binary\n <format_control>
\n
لا تستخدم حزم المصدر. يمكن تقديمها عدة مرات، وفي كل مرة تضاف إلى القيمة الموجودة. تقبل إما ":all:" لتعطيل جميع حزم المصدر، أو ":none:" لإفراغ المجموعة، أو اسم حزمة واحدة أو أكثر مع فواصل بينها. ستفشل الحزم التي لا تحتوي على توزيعات ثنائية في التثبيت عند استخدام هذا الخيار عليها.\n

(متغير البيئة: PIP_ONLY_BINARY)

\n
\n
\n
\n
\n
\n
--prefer-binary
\n
تفضيل الحزم الثنائية على حزم المصدر، حتى لو كانت حزم المصدر أحدث.\n

(متغير البيئة: PIP_PREFER_BINARY)

\n
\n
\n
\n
\n
\n
--no-build-isolation
\n
تعطيل العزل عند بناء توزيع مصدر حديث. يجب أن تكون تبعيات البناء المحددة بواسطة PEP 518 مثبتة بالفعل إذا تم استخدام هذا الخيار.\n

(متغير البيئة: PIP_NO_BUILD_ISOLATION)

\n
\n
\n
\n
\n
\n
--check-build-dependencies
\n
التحقق من تبعيات البناء.\n

(متغير البيئة:\n PIP_CHECK_BUILD_DEPENDENCIES)

\n
\n
\n
\n
\n
\n
-c, --constraint\n <file>
\n
تقييد الإصدارات باستخدام ملف القيود المحدد. يمكن استخدام هذا الخيار عدة مرات.\n

(متغير البيئة: PIP_CONSTRAINT)

\n
\n
\n
\n
\n
\n
--build-constraint\n <file>
\n
تقييد تبعيات البناء باستخدام ملف القيود المحدد. يمكن استخدام هذا الخيار عدة مرات.\n

(متغير البيئة: PIP_BUILD_CONSTRAINT)

\n
\n
\n
\n
\n
\n
-e, --editable\n <path/url>
\n
تثبيت مشروع في وضع قابل للتعديل (أي وضع تطوير setuptools) من مسار مشروع محلي أو عنوان URL لنظام التحكم في الإصدار.\n

(متغير البيئة: PIP_EDITABLE)

\n
\n
\n
\n
\n
\n
-r, --requirement\n <file>
\n
التثبيت من ملف المتطلبات المحدد. يمكن استخدام هذا الخيار عدة مرات.\n

(متغير البيئة: PIP_REQUIREMENT)

\n
\n
\n
\n
\n
\n
--src\n <dir>
\n
الدليل الذي سيتم فيه سحب المشاريع القابلة للتعديل. الافتراضي في بيئة افتراضية هو "<venv path>/src". الافتراضي للتثبيتات العامة هو "<current dir>/src".\n

(متغير البيئة: PIP_SRC, PIP_SOURCE,\n PIP_SOURCE_DIR, PIP_SOURCE_DIRECTORY)

\n
\n
\n
\n
\n
\n
--ignore-requires-python
\n
تجاهل معلومات Requires-Python.\n

(متغير البيئة: PIP_IGNORE_REQUIRES_PYTHON)

\n
\n
\n
\n
\n
\n
--no-deps
\n
لا تقم بتثبيت تبعيات الحزمة.\n

(متغير البيئة: PIP_NO_DEPS,\n PIP_NO_DEPENDENCIES)

\n
\n
\n
\n
\n
\n
--progress-bar\n <progress_bar>
\n
تحديد ما إذا كان سيتم استخدام شريط التقدم. في وضع 'auto'، سيقوم --quiet بقمع جميع أشرطة التقدم. [auto, on, off, raw] (الافتراضي: auto)\n

(متغير البيئة: PIP_PROGRESS_BAR)

\n
\n
\n
\n
\n
\n
--no-verify
\n
لا تتحقق مما إذا كانت العجلة المبنية صالحة.\n

(متغير البيئة: PIP_NO_VERIFY)

\n
\n
\n
\n
\n
\n
-C, --config-settings\n <settings>
\n
إعدادات التكوين التي سيتم تمريرها إلى الواجهة الخلفية للبناء. تأخذ الإعدادات شكل KEY=VALUE. استخدم خيارات --config-settings متعددة لتمرير مفاتيح متعددة إلى الواجهة الخلفية.\n

(متغير البيئة: PIP_CONFIG_SETTINGS)

\n
\n
\n
\n
\n
\n
--pre
\n
تضمين الإصدارات ما قبل الإصدار والتطوير. افتراضيًا، يجد pip الإصدارات المستقرة فقط.\n

(متغير البيئة: PIP_PRE)

\n
\n
\n
\n
\n
\n
--require-hashes
\n
طلب تجزئة للتحقق من كل متطلب، لتثبيتات قابلة للتكرار. يتم ضمنيًا هذا الخيار عند وجود أي حزمة في ملف المتطلبات تحمل خيار --hash.\n

(متغير البيئة: PIP_REQUIRE_HASHES)

\n
\n
\n
\n
\n
\n
--group\n <[path:]group>
\n
تثبيت مجموعة تبعيات مسماة من ملف "pyproject.toml". إذا تم إعطاء مسار، يجب أن يكون اسم الملف "pyproject.toml". افتراضيًا استخدام "pyproject.toml" في الدليل الحالي.\n

(متغير البيئة: PIP_GROUP)

\n
\n
\n
\n
\n
\n
--no-clean
\n
لا تنظيف أدلة البناء.\n

(متغير البيئة: PIP_NO_CLEAN)
