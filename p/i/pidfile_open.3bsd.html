pidfile_open(3bsd)

الحزمة: libbsd

التراخيص: custom

pidfile(3bsd) 3bsd pidfile(3bsd)

الاسم

pidfile_open، pidfile_write، pidfile_close، pidfile_remove، pidfile_fileno — مكتبة للتعامل مع ملفات PID

المكتبة

المكتبة "libbsd"

الملخص

#include <libutil.h> (انظر libbsd(7) لاستخدام تضمين.)
struct pidfh *
pidfile_open(const char *path, mode_t mode, pid_t *pidptr);

int
pidfile_write(struct pidfh *pfh);

int
pidfile_close(struct pidfh *pfh);

int
pidfile_remove(struct pidfh *pfh);

int
pidfile_fileno(struct pidfh *pfh);

الوصف

تسمح عائلة دوال pidfile للخوادم (daemons) بالتعامل مع ملفات PID. تستخدم flopen(3bsd) لقفل ملف PID والكشف عن الخوادم قيد التشغيل بالفعل.

تقوم الدالة pidfile_open() بفتح (أو إنشاء) ملف محدد بواسطة الوسيط path وقفلته. إذا كان الوسيط pidptr ليس NULL ولم يمكن قفل الملف، فستستخدم الدالة هذا الوسيط لتخزين معرف العملية (PID) لخادم قيد التشغيل بالفعل أو -1 في حالة عدم كتابة الخادم لمعرفه بعد. لا تقوم الدالة بكتابة معرف العملية الحالي إلى الملف هنا، لذلك يمكن استخدامها قبل fork() والخروج برسالة خطأ مناسبة عند الحاجة. إذا كان الوسيط path هو NULL، فسيتم استخدام الملف /var/run/⟨اسم_البرنامج⟩.pid. تقوم الدالة pidfile_open() بتعيين علامة الإغلاق عند التنفيذ O_CLOEXEC عند فتح ملف PID.

تقوم الدالة pidfile_write() بكتابة معرف العملية (PID) إلى ملف تم فتحه مسبقًا. يتم اقتطاع الملف قبل الكتابة، لذا فإن استدعاء الدالة pidfile_write() عدة مرات مدعوم.

تقوم الدالة pidfile_close() بإغلاق ملف PID. يجب استخدامها بعد أن يقوم الخادم fork() لإنشاء عملية ابن.

تقوم الدالة pidfile_remove() بإغلاق وإزالة ملف PID.

تقوم الدالة pidfile_fileno() بإرجاع واصف الملف لملف PID المفتوح.

قيم الإرجاع

ترجع الدالة pidfile_open() مؤشرًا صالحًا إلى بنية pidfh عند النجاح، أو NULL في حالة حدوث خطأ. في حالة حدوث خطأ، سيتم تعيين errno.


ترجع الدوال pidfile_write() و pidfile_close() و pidfile_remove() القيمة 0 عند النجاح؛ وإلا، يتم إرجاع القيمة -1 ويتم تعيين المتغير العام errno لتحديد الخطأ.

ترجع الدالة pidfile_fileno() واصف الملف منخفض المستوى. ترجع -1 وتعين errno إذا تم تحديد pidfh على أنه NULL، أو إذا لم يعد ملف PID مفتوحًا.

أمثلة

يوضح المثال التالي الترتيب الذي يجب أن تستخدم به هذه الدوال. لاحظ أنه من الآمن تمرير NULL إلى الدوال pidfile_write() و pidfile_remove() و pidfile_close() و pidfile_fileno().

struct pidfh *pfh;
pid_t otherpid, childpid;

pfh = pidfile_open("/var/run/daemon.pid", 0600, &otherpid);
if (pfh == NULL) {
	if (errno == EEXIST) {
		errx(EXIT_FAILURE, "الخادم يعمل بالفعل، معرف العملية: %jd.",
		    (intmax_t)otherpid);
	}
	/* إذا لم نتمكن من إنشاء ملف PID لأسباب أخرى، فقط نحذر. */
	warn("لا يمكن فتح أو إنشاء ملف PID");
	/*
	 * على الرغم من أن pfh هو NULL، يمكننا المتابعة، حيث يمكن لدالات pidfile_* الأخرى
	 * التعامل مع هذا الموقف عن طريق عدم فعل شيء باستثناء تعيين
	 * errno إلى EINVAL.
	 */
}

if (daemon(0, 0) == -1) {
	warn("لا يمكن تشغيل الخادم");
	pidfile_remove(pfh);
	exit(EXIT_FAILURE);
}

pidfile_write(pfh);

for (;;) {
	/* قم بالعمل. */
	childpid = fork();
	switch (childpid) {
	case -1:
		syslog(LOG_ERR, "لا يمكن fork(): %s.", strerror(errno));
		break;
	case 0:
		pidfile_close(pfh);
		/* قم بعمل الابن. */
		break;
	default:
		syslog(LOG_INFO, "تم بدء الابن %jd.", (intmax_t)childpid);
		break;
	}
}

pidfile_remove(pfh);
exit(EXIT_SUCCESS);

الأخطاء

ستفشل الدالة pidfile_open() إذا:

[EEXIST]
تحتفظ عملية ما بالفعل بقفل على ملف PID المحدد، مما يعني أن خادمًا يعمل بالفعل. إذا كان الوسيط pidptr ليس NULL، فستستخدم الدالة هذا لتخزين معرف العملية (PID) لخادم يعمل بالفعل أو -1 في حالة عدم كتابة الخادم لمعرفه بعد.
[ENAMETOOLONG]
اسم ملف PID المحدد طويل جدًا.
[EINVAL]
تحتفظ عملية ما بالفعل بقفل على ملف PID المحدد، ولكن معرف العملية (PID) المقروء منه غير صالح.

قد تفشل الدالة pidfile_open() أيضًا وتعين errno لأي أخطاء محددة لاستدعاءات fstat(2) و open(2) و read(2).

ستفشل الدالة pidfile_write() إذا:

[EINVAL]
استخدام غير صحيح للدالة. ربما تم استدعاؤها قبل pidfile_open().

قد تفشل الدالة pidfile_write() أيضًا وتعين errno لأي أخطاء محددة لاستدعاءات fstat(2) و ftruncate(2) و write(2).

قد تفشل الدالة pidfile_close() وتعين errno لأي أخطاء محددة لاستدعاءات close(2) و fstat(2).

ستفشل الدالة pidfile_remove() إذا:

[EINVAL]
استخدام غير صحيح للدالة. ربما تم استدعاؤها ليس من قبل العملية التي قامت بـ pidfile_write().

قد تفشل الدالة pidfile_remove() أيضًا وتعين errno لأي أخطاء محددة لاستدعاءات close(2) و fstat(2) و write(2) و unlink(2).

pidfile_open(3bsd) — archlinux man pages

NAME

pidfile_open, pidfile_write, pidfile_close, pidfile_remove, pidfile_fileno ― create and manage PID files

LIBRARY

Support library functions (libbsd, -lbsd)

SYNOPSIS

#include <bsd/stdio.h>

#include <bsd/stdlib.h>

pidfile_t *pidfile_open(const char *path, mode_t mode, char *const argv[])

int pidfile_write(pidfile_t *pidf)

int pidfile_close(pidfile_t *pidf)

int pidfile_remove(pidfile_t *pidf)

int pidfile_fileno(pidfile_t *pidf)

DESCRIPTION

The functions pidfile_open(), pidfile_write(), pidfile_close() and pidfile_remove() provide a convenient way to create and manage PID files. A PID file is a file which stores the process ID (PID) of a running daemon. It is typically used to prevent multiple instances of the same daemon from running simultaneously.

The pidfile_open() function creates or opens the PID file specified by path. The mode argument specifies the file permissions for the PID file. The argv argument is an array of strings which are used to construct the default content of the PID file, typically the command line arguments used to invoke the daemon.

The pidfile_write() function writes the PID of the calling process into the PID file. This function should be called after the daemon has successfully started.

The pidfile_close() function closes the PID file. If the PID file was created by pidfile_open(), it will be removed from the filesystem. Otherwise, it will simply be closed.

The pidfile_remove() function explicitly removes the PID file from the filesystem. This is useful if the daemon needs to be stopped gracefully.

The pidfile_fileno() function returns the file descriptor associated with the PID file. This can be used to perform additional operations on the PID file, such as writing additional information or checking its status.

The PID file management functions are based on the open(2) and unlink(2) system calls and the flopen(3bsd) library function.

RETURN VALUES

Upon success, pidfile_open() returns a pointer to a pidfile_t structure. Otherwise, it returns NULL and sets errno appropriately.

The functions pidfile_write(), pidfile_close(), pidfile_remove() and pidfile_fileno() return 0 on success, and -1 on error, setting errno appropriately.

EXAMPLES

The following example demonstrates the basic usage of the PID file management functions:

pidfile_t *pidf;
pidf = pidfile_open("/var/run/mydaemon.pid", 0644, argv);
if (pidf == NULL) {
    /* handle error */
}
if (pidfile_write(pidf) == -1) {
    /* handle error */
    pidfile_close(pidf);
    return (1);
}
/* Daemon is now running, continue with initialization */
...
/* Daemon is shutting down */
if (pidfile_remove(pidf) == -1) {
    /* handle error */
}

ERRORS

The functions pidfile_open(), pidfile_write(), pidfile_close() and pidfile_remove() may fail for various reasons, including insufficient permissions, invalid file paths, or disk full errors. The specific error codes are set in the errno variable.

The pidfile_fileno() function will fail if:

[EINVAL]
Improper function use. Probably called not from the process which used pidfile_open().

SEE ALSO

open(2), daemon(3), flopen(3bsd)

HISTORY

The functions pidfile_open(), pidfile_write(), pidfile_close() and pidfile_remove() first appeared in FreeBSD 5.5.

The function pidfile_fileno() first appeared in FreeBSD 10.0.
