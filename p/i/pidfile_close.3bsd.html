pidfile_close(3bsd)

الحزمة: libbsd

التراخيص: custom

NAME

pidfile_open, pidfile_write, pidfile_close, pidfile_remove, pidfile_fileno — library for handling pidfiles

LIBRARY

libbsd (libbsd.a, libbsd.so)

SYNOPSIS

#include <bsd/bsd.h>

pidfile_t *
pidfile_open(const char *path, mode_t mode, int flags);

int
pidfile_write(pidfile_t *pidf);

int
pidfile_close(pidfile_t *pidf);

int
pidfile_remove(pidfile_t *pidf);

int
pidfile_fileno(pidfile_t *pidf);

DESCRIPTION

The pidfile functions provide a simple interface to create and manage pidfiles. A pidfile is a file which contains the process ID (PID) of a running daemon. Typically, daemons create a pidfile when they start and remove it when they terminate. This allows other processes to check if a daemon is already running by trying to create the pidfile. If the creation succeeds, the daemon is not running. If it fails with EEXIST, the daemon is already running. If the existing pidfile contains the PID of a process that is no longer running, the new process may replace the stale pidfile.

The pidfile_open() function creates a new pidfile or opens an existing one. The path argument is the path to the pidfile. The mode argument is the mode to be used for creating the file if it does not exist. The flags argument can be a bitwise OR of zero or more of the following flags:

PIDFILE_NO_CREATE
Do not create the pidfile if it does not exist. In this case, pidfile_open() will fail with ENOENT.
PIDFILE_LOCK
Acquire an exclusive lock on the pidfile. This is the default behavior if no flags are specified.
PIDFILE_NOLOCK
Do not acquire a lock on the pidfile. This flag implies PIDFILE_NO_CREATE.

If the pidfile already exists and is locked by another process, pidfile_open() will try to obtain the lock for a short period of time (1 second). If it fails to obtain the lock, it will check if the PID in the file corresponds to a running process. If it does, pidfile_open() will fail with EWOULDBLOCK. If the PID does not correspond to a running process, the existing pidfile will be truncated and the lock will be acquired.

If pidfile_open() succeeds, it returns a pointer to an opaque pidfile_t structure, which is used by the other functions. The returned structure contains a file descriptor to the opened pidfile, which is locked (unless PIDFILE_NOLOCK was specified).

The pidfile_write() function writes the current process ID into the pidfile. It should be called after pidfile_open() succeeds.

The pidfile_close() function closes the pidfile and releases the lock. It does not remove the file.

The pidfile_remove() function removes the pidfile. It should be called after pidfile_close() or instead of it if the pidfile is no longer needed.

The pidfile_fileno() function returns the file descriptor associated with the pidfile.

RETURN VALUES

The pidfile_open() function returns a pointer to a pidfile_t structure on success, or NULL on failure. The specific failure condition can be determined by checking the value of errno.

The pidfile_write(), pidfile_close(), and pidfile_remove() functions return 0 on success, and -1 on failure. If -1 is returned, errno is set to indicate the error.

The pidfile_fileno() function returns the file descriptor on success, or -1 on failure.

EXAMPLES

Create a pidfile for a daemon:

pidfile_t *pidf;
pidf = pidfile_open("/var/run/mydaemon.pid", 0644, 0);
if (pidf == NULL) {
if (errno == EWOULDBLOCK)
errx(1, "mydaemon is already running");
err(1, "pidfile_open");
}
pidfile_write(pidf);

/* ... daemon code ... */

pidfile_remove(pidf);

ERRORS

The pidfile_open() function may fail and set errno to the following values:

[EACCES]
The directory containing the pidfile cannot be written to, or the pidfile already exists and is not writable.
[EEXIST]
The pidfile already exists and is locked by another process, and the PID in the file does not correspond to a running process.
[EINTR]
The operation was interrupted by a signal.
[EINVAL]
Invalid flags were specified.
[EISDIR]
The specified path is a directory.
[EMFILE]
Too many file descriptors are open.
[ENAMETOOLONG]
The path argument is too long.
[ENOENT]
The pidfile does not exist and PIDFILE_NO_CREATE was specified.
[ENOMEM]
Not enough memory.
[ENOSPC]
The device containing the pidfile has no room for the file.
[ENOTDIR]
A component of the path prefix does not exist or is not a directory.
[EPERM]
The process does not have permission to create the pidfile.
[EROFS]
The pidfile resides on a read-only file system.
[ETXTBSY]
The pidfile is currently in use by another process, and cannot be opened. This usually happens when a text segment is being executed.
[EWOULDBLOCK]
The pidfile is locked by another process, and the PID in the file does not correspond to a running process.

The pidfile_write() function may fail and set errno to:

[EBADF]
The file descriptor is invalid.
[EIO]
An I/O error occurred.
[EINVAL]
Improper function use. Probably called not from the process which used pidfile_open().

The pidfile_close() and pidfile_remove() functions may fail and set errno to:

[EBADF]
The file descriptor is invalid.
[EIO]
An I/O error occurred.
[EINVAL]
Improper function use. Probably called not from the process which used pidfile_open().
[ENOTDIR]
A component of the path prefix does not exist or is not a directory.
[EPERM]
The process does not have permission to remove the pidfile.
[EROFS]
The pidfile resides on a read-only file system.

The pidfile_fileno() function may fail and set errno to:

[EINVAL]
Improper function use. Probably called not from the process which used pidfile_open().

HISTORY

The functions pidfile_open(), pidfile_write(), pidfile_close() and pidfile_remove() first appeared in FreeBSD 5.5.

The function pidfile_fileno() first appeared in FreeBSD 10.0.

AUTHORS

The code and manual page was written by Pawel Jakub Dawidek <pjd@FreeBSD.org>.

BUGS

Improper function use. Probably called not from the process which used pidfile_open().

الوصف

توفر دوال pidfile واجهة بسيطة لإنشاء وإدارة ملفات PID. ملف PID هو ملف يحتوي على معرف العملية (PID) لخادم يعمل. عادةً، تقوم الخوادم بإنشاء ملف PID عند بدئها وإزالته عند انتهائها. يسمح هذا للعمليات الأخرى بالتحقق مما إذا كان خادم يعمل بالفعل عن طريق محاولة إنشاء ملف PID. إذا نجح الإنشاء، فإن الخادم لا يعمل. إذا فشل مع EEXIST، فإن الخادم يعمل بالفعل. إذا كان ملف PID الموجود يحتوي على PID لعملية لم تعد قيد التشغيل، فقد تستبدل العملية الجديدة ملف PID القديم.

تقوم الدالة pidfile_open() بإنشاء ملف PID جديد أو فتح ملف موجود. الوسيط path هو المسار إلى ملف PID. الوسيط mode هو الوضع الذي سيتم استخدامه لإنشاء الملف إذا لم يكن موجودًا. الوسيط flags يمكن أن يكون OR بت (bitwise OR) لعلامة واحدة أو أكثر مما يلي:

PIDFILE_NO_CREATE
لا تنشئ ملف PID إذا لم يكن موجودًا. في هذه الحالة، ستفشل pidfile_open() مع ENOENT.
PIDFILE_LOCK
احصل على قفل حصري على ملف PID. هذا هو السلوك الافتراضي إذا لم يتم تحديد أي علامات.
PIDFILE_NOLOCK
لا تحصل على قفل على ملف PID. هذه العلامة تعني PIDFILE_NO_CREATE.

إذا كان ملف PID موجودًا بالفعل ومقفلًا بواسطة عملية أخرى، ستحاول pidfile_open() الحصول على القفل لفترة قصيرة (1 ثانية). إذا فشلت في الحصول على القفل، فستتحقق مما إذا كان معرف العملية (PID) في الملف يتوافق مع عملية قيد التشغيل. إذا كان الأمر كذلك، ستفشل pidfile_open() مع EWOULDBLOCK. إذا كان معرف العملية (PID) لا يتوافق مع عملية قيد التشغيل، فسيتم اقتطاع ملف PID الموجود وسيتم الحصول على القفل.

إذا نجحت pidfile_open()، فإنها تُرجع مؤشرًا إلى هيكل pidfile_t غامض، والذي تستخدمه الدوال الأخرى. يحتوي الهيكل المُرجع على واصف ملف لملف PID المفتوح، والذي يكون مقفولًا (إلا إذا تم تحديد PIDFILE_NOLOCK).

تقوم الدالة pidfile_write() بكتابة معرف العملية الحالي إلى ملف PID. يجب استدعاؤها بعد نجاح pidfile_open().

تقوم الدالة pidfile_close() بإغلاق ملف PID وتحرير القفل. لا تزيل الملف.

تقوم الدالة pidfile_remove() بإزالة ملف PID. يجب استدعاؤها بعد pidfile_close() أو بدلاً منها إذا لم يعد ملف PID مطلوبًا.

تقوم الدالة pidfile_fileno() بإرجاع واصف الملف المرتبط بملف PID.

قيم الإرجاع

تُرجع الدالة pidfile_open() مؤشرًا إلى هيكل pidfile_t عند النجاح، أو NULL عند الفشل. يمكن تحديد حالة الفشل المحددة عن طريق التحقق من قيمة errno.

تُرجع الدوال pidfile_write() و pidfile_close() و pidfile_remove() القيمة 0 عند النجاح، و -1 عند الفشل. إذا تم إرجاع -1، فسيتم تعيين errno للإشارة إلى الخطأ.

تُرجع الدالة pidfile_fileno() واصف الملف عند النجاح، أو -1 عند الفشل.

أمثلة

إنشاء ملف PID لخادم:

pidfile_t *pidf;
pidf = pidfile_open("/var/run/mydaemon.pid", 0644, 0);
if (pidf == NULL) {
if (errno == EWOULDBLOCK)
errx(1, "mydaemon is already running");
err(1, "pidfile_open");
}
pidfile_write(pidf);

/* ... daemon code ... */

pidfile_remove(pidf);

الأخطاء

قد تفشل الدالة pidfile_open() وتعيّن errno إلى القيم التالية:

[EACCES]
لا يمكن كتابة الدليل الذي يحتوي على ملف PID، أو أن ملف PID موجود بالفعل وغير قابل للكتابة.
[EEXIST]
ملف PID موجود بالفعل ومقفل بواسطة عملية أخرى، و PID الموجود في الملف لا يتوافق مع عملية قيد التشغيل.
[EINTR]
تم مقاطعة العملية بواسطة إشارة.
[EINVAL]
تم تحديد علامات غير صالحة.
[EISDIR]
المسار المحدد هو دليل.
[EMFILE]
عدد واصفات الملفات المفتوحة كبير جدًا.
[ENAMETOOLONG]
المسار طويل جدًا.
[ENOENT]
ملف PID غير موجود وتم تحديد PIDFILE_NO_CREATE.
[ENOMEM]
لا توجد ذاكرة كافية.
[ENOSPC]
الجهاز الذي يحتوي على ملف PID ليس لديه مساحة كافية للملف.
[ENOTDIR]
أحد مكونات بادئة المسار غير موجود أو ليس دليلاً.
[EPERM]
ليس لدى العملية إذن لإنشاء ملف PID.
[EROFS]
ملف PID موجود على نظام ملفات للقراءة فقط.
[ETXTBSY]
ملف PID قيد الاستخدام حاليًا بواسطة عملية أخرى، ولا يمكن فتحه. يحدث هذا عادةً عند تنفيذ مقطع نصي.
[EWOULDBLOCK]
ملف PID مقفل بواسطة عملية أخرى، و PID الموجود في الملف لا يتوافق مع عملية قيد التشغيل.

قد تفشل الدالة pidfile_write() وتعيّن errno إلى:

[EBADF]
واصف الملف غير صالح.
[EIO]
حدث خطأ إدخال/إخراج.
[EINVAL]
استخدام غير صحيح للدالة. ربما تم استدعاؤها ليس من العملية التي استخدمت pidfile_open().

قد تفشل الدوال pidfile_close() و pidfile_remove() وتعيّن errno إلى:

[EBADF]
واصف الملف غير صالح.
[EIO]
حدث خطأ إدخال/إخراج.
[EINVAL]
استخدام غير صحيح للدالة. ربما تم استدعاؤها ليس من العملية التي استخدمت pidfile_open().
[ENOTDIR]
أحد مكونات بادئة المسار غير موجود أو ليس دليلاً.
[EPERM]
ليس لدى العملية إذن لإزالة ملف PID.
[EROFS]
ملف PID موجود على نظام ملفات للقراءة فقط.

قد تفشل الدالة pidfile_fileno() وتعيّن errno إلى:

[EINVAL]
استخدام غير صحيح للدالة. ربما تم استدعاؤها ليس من العملية التي استخدمت pidfile_open().
