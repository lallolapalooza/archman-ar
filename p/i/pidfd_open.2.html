pidfd_open(2) دليل استدعاءات النظام pidfd_open(2)

الاسم

pidfd_open - الحصول على واصف ملف يشير إلى مهمة

المكتبة

مكتبة C القياسية (libc، -lc)

الملخص

#include <sys/syscall.h>      /* تعريف ثوابت SYS_* */
#include <unistd.h>
int syscall(SYS_pidfd_open, pid_t pid, unsigned int flags);

ملاحظة: لا توفر glibc غلافًا لـ pidfd_open()، مما يستلزم استخدام syscall(2).

الوصف

ينشئ استدعاء النظام pidfd_open() واصف ملف يشير إلى المهمة التي يشير إليها pid. يتم إرجاع واصف الملف كنتيجة للدالة؛ يتم تعيين علامة الإغلاق عند التنفيذ على واصف الملف.

يحتوي الوسيط flags إما على القيمة 0، أو يحتوي على العلامات التالية:

PIDFD_NONBLOCK (منذ لينكس 5.10)
إرجاع واصف ملف غير مانع. إذا لم تنتهِ المهمة التي يشير إليها واصف الملف بعد، فإن محاولة الانتظار على واصف الملف باستخدام waitid(2) ستعيد على الفور الخطأ EAGAIN بدلاً من الانتظار.
PIDFD_THREAD (منذ لينكس 6.9)
إنشاء واصف ملف يشير إلى خيط معين، بدلاً من عملية (قائد مجموعة الخيوط). إذا لم يتم تعيين هذه العلامة، فيجب أن يشير pid إلى عملية.

قيمة الإرجاع

عند النجاح، يعيد pidfd_open() واصف ملف (عدد صحيح غير سالب). عند حدوث خطأ، يتم إرجاع -1 ويتم تعيين errno للإشارة إلى الخطأ.

الأخطاء

EINVAL
flags غير صالحة.
EINVAL
pid غير صالحة.
EMFILE
تم الوصول إلى حد العمليات لكل عملية لعدد واصفات الملفات المفتوحة (انظر وصف RLIMIT_NOFILE في getrlimit(2)).
ENFILE
تم الوصول إلى الحد العام للنظام لإجمالي عدد الملفات المفتوحة.
ENODEV
نظام ملفات inode المجهول غير متوفر في هذا النواة.
ENOMEM
كانت ذاكرة النواة غير كافية.
ESRCH
العملية المحددة بواسطة pid غير موجودة.

المعايير

لينكس.

التاريخ

لينكس 5.3.

ملاحظات

يمكن استخدام التسلسل التالي من التعليمات البرمجية للحصول على واصف ملف للطفل الناتج عن fork(2):


pid = fork();
if (pid > 0) {     /* إذا كان الوالد */
    pidfd = pidfd_open(pid, 0);
    ...
}

حتى لو كان الطفل قد انتهى بالفعل بحلول وقت استدعاء pidfd_open()، فلن تتم إعادة تدوير معرف العملية الخاص به وسيشير واصف الملف الذي تم إرجاعه إلى عملية الزومبي الناتجة. لاحظ، مع ذلك، أن هذا مضمون فقط إذا كانت الشروط التالية صحيحة:

•
لم يتم تعيين تصرف SIGCHLD بشكل صريح إلى SIG_IGN (انظر sigaction(2))؛
•
لم يتم تحديد علامة SA_NOCLDWAIT أثناء إنشاء معالج لـ SIGCHLD أو أثناء تعيين تصرف هذه الإشارة إلى SIG_DFL (انظر sigaction(2))؛ و
•
لم يتم حصاد عملية الزومبي في مكان آخر في البرنامج (على سبيل المثال، إما بواسطة معالج إشارة منفذ بشكل غير متزامن أو بواسطة wait(2) أو ما شابه في خيط آخر).

إذا لم يكن أي من هذه الشروط صحيحًا، فيجب بدلاً من ذلك إنشاء العملية الفرعية (مع واصف ملف PID يشير إليها) باستخدام clone(2) مع علامة CLONE_PIDFD.

حالات الاستخدام لواصفات ملفات PID

يمكن استخدام واصف ملف PID الذي تم إرجاعه بواسطة pidfd_open() (أو بواسطة clone(2) مع علامة CLONE_PID) للأغراض التالية:

•
يمكن استخدام استدعاء النظام pidfd_send_signal(2) لإرسال إشارة إلى العملية التي يشير إليها واصف ملف PID.
•
يمكن مراقبة واصف ملف PID باستخدام poll(2)، select(2)، و epoll(7).
عندما تنتهي المهمة التي يشير إليها وتصبح زومبي، تشير هذه الواجهات إلى واصف الملف على أنه قابل للقراءة (EPOLLIN). عندما يتم حصاد المهمة، تنتج هذه الواجهات حدث انقطاع (EPOLLHUP).
لاحظ، مع ذلك، أنه في التنفيذ الحالي، لا يمكن قراءة أي شيء من واصف الملف (read(2) على واصف الملف يفشل مع الخطأ EINVAL). يعتمد سلوك الاستطلاع على ما إذا كانت علامة PIDFD_THREAD قد تم استخدامها عند الحصول على واصف الملف:
•
مع PIDFD_THREAD، يصبح واصف الملف قابلاً للقراءة عندما تنتهي المهمة وتصبح زومبي، حتى لو كانت مجموعة الخيوط غير فارغة.
•
بدون PIDFD_THREAD، يصبح واصف الملف قابلاً للقراءة فقط عندما تنتهي آخر خيط في مجموعة الخيوط.
•
إذا كان واصف ملف PID يشير إلى طفل للعملية المستدعية، فيمكن الانتظار عليه باستخدام waitid(2).
•
يمكن استخدام استدعاء النظام pidfd_getfd(2) للحصول على نسخة مكررة من واصف ملف لعملية أخرى يشير إليها واصف ملف PID.
•
يمكن استخدام واصف ملف PID كوسيط لـ setns(2) للانتقال إلى واحد أو أكثر من نفس مساحات الأسماء مثل العملية التي يشير إليها واصف الملف.
•
يمكن استخدام واصف ملف PID كوسيط لـ process_madvise(2) لتقديم نصائح حول أنماط استخدام الذاكرة للعملية التي يشير إليها واصف الملف.

استدعاء النظام pidfd_open() هو الطريقة المفضلة للحصول على واصف ملف PID لعملية موجودة بالفعل. البديل هو الحصول على واصف ملف عن طريق فتح دليل /proc/pid. ومع ذلك، فإن هذا الأسلوب ممكن فقط إذا كان نظام ملفات proc(5) مثبتًا؛ علاوة على ذلك، فإن واصف الملف الذي تم الحصول عليه بهذه الطريقة *غير* قابل للاستطلاع ولا يمكن الانتظار عليه باستخدام waitid(2).

أمثلة

البرنامج أدناه يفتح واصف ملف PID للعملية التي تم تحديد PID الخاص بها كوسيط لسطر الأوامر الخاص بها. ثم يستخدم poll(2) لمراقبة واصف الملف لخروج العملية، كما هو مشار إليه بواسطة حدث EPOLLIN.

NAME

pidfd_open - obtain a file descriptor referring to a process

\n
\n

LIBRARY

librt

\n
\n
\n

SYNOPSIS

#include <sys/pidfd.h>
pid_t pidfd_open(pid_t pid, unsigned int flags);
\n
\n
\n

DESCRIPTION

The pidfd_open() system call creates a new file descriptor that refers to the process specified by pid. This new file descriptor is a pidfd.

A pidfd provides a robust way to refer to a process. Unlike a process ID (PID), a pidfd is not recycled: once a process terminates and its PID is freed, the pidfd referring to it remains valid (referring to the terminated process) until it is closed. This prevents race conditions where a new process might be created with the PID of a recently terminated process.

The pid argument specifies the process to which the pidfd should refer. If pid is 0, the calling process itself is used.

The flags argument is reserved for future use and must be specified as 0.

A pidfd can be used with several system calls. Most notably:

  • pidfd_send_signal(2): send a signal to the process referred to by the pidfd.
  • pidfd_getfd(2): get a file descriptor referring to a particular file that is open in the target process.
  • poll(2) and epoll(7): monitor the pidfd for events. The only event that can be monitored is the termination of the process.
  • process_madvise(2): perform madvise operations on the target process's address space.
  • setns(2): join a namespace of the target process.
  • waitid(2): wait for the process to change state.

The pidfd returned by pidfd_open() is a regular file descriptor and can be closed using close(2).

\n
\n
\n

RETURN VALUE

On success, pidfd_open() returns the new pidfd. On failure, -1 is returned, and errno is set to indicate the error.

\n
\n
\n

ERRORS

The following errors can occur:

  • EACCES
    The calling process does not have permission to access the specified process.
  • EINVAL
    Invalid value for flags (must be 0).
  • ENOMEM
    Could not allocate memory to create the pidfd.
  • ENOSPC
    The system limit on the total number of pidfds has been reached.
  • ESRCH
    The process specified by pid does not exist.

\n

STANDARDS

This system call is specific to Linux and was introduced in kernel version 5.1.

\n
\n

HISTORY

The pidfd_open() system call was added in Linux kernel 5.1.

\n
\n
\n

NOTES

The primary use case for pidfds is to provide a reliable way to interact with processes, especially in scenarios where PIDs might be reused.

"" : "not ");\n\n    close(pidfd);\n    exit(EXIT_SUCCESS);\n}\n
