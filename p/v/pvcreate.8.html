الاسم

pvcreate — تهيئة وحدات التخزين المادية (Physical Volumes) لاستخدامها بواسطة LVM

الملخص

pvcreate محددات_موضعية
محددات_خيارات

الوصف

يقوم pvcreate بتهيئة وحدة تخزين مادية (PV) على جهاز بحيث يتم التعرف على الجهاز كجزء من LVM. هذا يسمح باستخدام PV في مجموعة وحدات تخزين (VG). يتم كتابة تسمية قرص LVM على الجهاز، ويتم تهيئة مناطق بيانات LVM الوصفية. يمكن وضع PV على جهاز كامل أو قسم.

استخدم vgcreate(8) لإنشاء VG جديد على PV، أو vgextend(8) لإضافة PV إلى VG موجود. استخدم pvremove(8) لإزالة تسمية قرص LVM من الجهاز.

سيؤدي خيار القوة (force) إلى إنشاء PV بدون تأكيد. تكرار خيار القوة (-ff) سيؤدي إلى إنشاء PV بالقوة، متجاوزًا الفحوصات التي تمنعه عادةً، على سبيل المثال إذا كان PV موجودًا بالفعل في VG.

موقع وحجم ومحاذاة البيانات الوصفية

تبدأ تسمية قرص LVM قبل 512 بايت من بداية الجهاز، وحجمها 512 بايت.

تبدأ منطقة البيانات الوصفية لـ LVM عند إزاحة (من بداية الجهاز) تساوي حجم صفحة الجهاز الذي يقوم بإنشاء PV (غالبًا 4 كيلوبايت). تحتوي منطقة البيانات الوصفية على رأس بحجم 512 بايت ومخزن دائري بحجم متعدد الكيلوبايت يحتفظ بنسخ نصية من البيانات الوصفية الخاصة بـ VG.

باستخدام الإعدادات الافتراضية، فإن أول امتداد مادي (PE)، الذي يحتوي على بيانات LV، يكون على بعد 1 ميغابايت من بداية الجهاز. يتم التحكم في هذا الموقع بواسطة default_data_alignment في lvm.conf، والذي يتم تعيينه إلى 1 (ميغابايت) افتراضيًا. ستكون pe_start مضاعفًا لهذا العدد من الميغابايت. يمكن التحقق من هذا الموقع باستخدام:
pvs -o pe_start PV

حجم منطقة البيانات الوصفية لـ LVM هو المساحة بين بداية منطقة البيانات الوصفية وأول PE. عندما تبدأ البيانات الوصفية عند 4 كيلوبايت ويكون أول PE عند 1024 كيلوبايت، يكون حجم منطقة البيانات الوصفية 1020 كيلوبايت. يمكن التحقق من هذا باستخدام:
pvs -o mda_size PV

لا يمكن زيادة mda_size بعد pvcreate، لذلك إذا كانت هناك حاجة إلى بيانات وصفية أكبر، فيجب تعيينها أثناء pvcreate. يجب دائمًا أن تتسع نسختان من البيانات الوصفية لـ VG داخل منطقة البيانات الوصفية، لذا فإن الحد الأقصى لحجم البيانات الوصفية لـ VG هو حوالي نصف mda_size. يمكن التحقق من هذا باستخدام:
vgs -o mda_free VG

يمكن تعيين منطقة بيانات وصفية أكبر باستخدام --metadatasize. قد يكون حجم mda_size الناتج أكبر من المحدد بسبب default_data_alignment الذي يضع pe_start على حدود ميغابايت، وحقيقة أن منطقة البيانات الوصفية تمتد إلى أول PE. مع بدء البيانات الوصفية عند 4 كيلوبايت و default_data_alignment 1 (ميغابايت)، فإن تعيين --metadatasize 2048k يؤدي إلى pe_start 3 ميغابايت و mda_size 3068 كيلوبايت. بدلاً من ذلك، --metadatasize 2044k يؤدي إلى pe_start عند 2 ميغابايت و mda_size 2044 كيلوبايت.

قد يتم تجاوز محاذاة pe_start المذكورة أعلاه تلقائيًا بناءً على خصائص جهاز md أو خصائص إدخال/إخراج الجهاز التي تم الإبلاغ عنها في sysfs. يمكن تمكين/تعطيل هذه التعديلات التلقائية باستخدام إعدادات lvm.conf md_chunk_alignment و data_alignment_offset_detection.

لاستخدام محاذاة pe_start مختلفة، استخدم خيار --dataalignment. عادةً ما يتم استخدام خيار --metadatasize أيضًا في هذه الحالة لأن حجم منطقة البيانات الوصفية يحدد أيضًا موقع pe_start. عند استخدام هذين الخيارين معًا، يتم حساب pe_start كالتالي: بداية منطقة البيانات الوصفية (حجم الصفحة)، بالإضافة إلى --metadatasize المحدد، مقربًا لأعلى إلى أقرب مضاعف لـ --dataalignment. مع بدء البيانات الوصفية عند 4 كيلوبايت، --metadatasize 2048k، و --dataalignment 128k، يكون pe_start 2176 كيلوبايت و mda_size 2172 كيلوبايت. pe_start البالغ 2176 كيلوبايت هو أقرب مضاعف زوجي لـ 128 كيلوبايت يوفر مساحة بيانات وصفية لا تقل عن 2048 كيلوبايت. تحقق دائمًا من المحاذاة وحجم البيانات الوصفية الناتجة عند استخدام هذه الخيارات.

لتحويل قيمة pe_start المحاذاة، استخدم خيار --dataalignmentoffset. يتم حساب محاذاة pe_start كما هو موضح أعلاه، ثم يتم إضافة القيمة المحددة بواسطة --dataalignmentoffset لإنتاج قيمة pe_start النهائية.

المتغيرات

PV
اسم حجم فعلي (Physical Volume)، وهو مسار جهاز تحت /dev. بالنسبة للأوامر التي تدير الأحجام الفعلية (physical extents)، عادةً ما يقبل وسيط موضعي PV لاحقة تشير إلى نطاق (أو نطاقات متعددة) من الأحجام الفعلية (PEs). عند حذف أول PE، فإنه يفسد بداية الجهاز، وعند حذف آخر PE، فإنه يفسد نهاية الجهاز.
نطاق البدء والانتهاء (شامل): PV[:PE-PE] ...
نطاق البدء والطول (العد من 0): PV[:PE+PE] ...
String
انظر وصف الخيار للحصول على معلومات حول محتوى السلسلة.
Size[UNIT]
الحجم هو رقم إدخال يقبل وحدة اختيارية. وحدات الإدخال تعامل دائمًا كقيم أساس اثنان، بغض النظر عن حالة الأحرف، على سبيل المثال 'k' و 'K' يشيران كلاهما إلى 1024. وحدة الإدخال الافتراضية محددة بحرف، متبوعًا بـ |UNIT. UNIT تمثل وحدات الإدخال الممكنة الأخرى: b|B هي البايت، s|S هي القطاعات بحجم 512 بايت، k|K هي KiB، m|M هي MiB، g|G هي GiB، t|T هي TiB، p|P هي PiB، e|E هي EiB. (يجب عدم الخلط بين هذا وبين التحكم في الإخراج --units، حيث تشير الأحرف الكبيرة إلى مضاعفات 1000.)

متغيرات البيئة

انظر lvm(8) للحصول على معلومات حول متغيرات البيئة المستخدمة بواسطة lvm. على سبيل المثال، يمكن استبدال LVM_VG_NAME بوسيط VG مطلوب بشكل عام.

أمثلة

تهيئة قسم وجهاز كامل.
pvcreate /dev/sdc4 /dev/sde

إذا كان الجهاز عبارة عن قرص قطاعات 4 KiB يعوض تقسيم ويندوز (القطاع 7 هو أدنى كتلة منطقية محاذية، وتبدأ قطاعات 4 KiB عند LBA -1، وبالتالي فإن القطاع 63 محاذٍ على حدود 4 KiB)، قم بحساب ذلك يدويًا عند التهيئة للاستخدام بواسطة LVM.
pvcreate --dataalignmentoffset 7s /dev/sdb

pvcreate — Create a physical volume for use by LVM

SYNOPSIS

pvcreate [-A|--autoboot {y|n}] [-B|--restorefile filename] [-c|--clustered] [-d|--debug] [-h|--help] [-k|--keepactive] [-M|--metadatatype storage-format] [-m|--metadatasize MEGABYTES] [-p|--metacopy count] [-P|--probes] [-t|--test] [-u|--uuid uuid] [-v|--verbose] [-y|--yes] [--addnode node] [--allocating-device allocation_device] [--bootloader bootloader_path] [--bootloaderargs bootloader_args] [--data-alignment offset] [--data-center offset] [--datappb offset] [--device device] [--devices device [device...]] [--devicesfile filename] [--driverloaded {y|n}] [--ignoremonitoring] [--] PhysicalVolume[ PhysicalVolume...]

See also lvm(8) for common options and differences between logical volume managers.

DESCRIPTION

Creates a new physical volume for use by LVM from one or more whole devices, partitions, or other block devices. The tool initializes the specified block device(s) to be used by LVM. For more details on the concepts of Physical Volumes, Volume Groups, and Logical Volumes, see lvmintro(8).

The block device is marked with an LVM2 identifier, and metadata structures are created. If the device is already in use as a physical volume, pvcreate will refuse to overwrite it unless the --force option is given.

The metadata is stored on the physical volume itself. The default metadata area size is 1016 KiB, but this can be changed using the --metadatasize option.

--metacopy is an option that can be used to store multiple copies of the metadata on the physical volume. If metadata is corrupted, the copies can be used to restore the metadata.

USAGE

pvcreate creates a physical volume. The device name of the physical volume is given as an argument. This can be a whole device (e.g. /dev/sda) or a partition (e.g. /dev/sda1).

For RAID devices (e.g. mdadm arrays or device-mapper devices), specify the RAID device name (e.g. /dev/md0).

When creating a physical volume on a device that is already in use, pvcreate will ask for confirmation. To skip this confirmation, use the -y or --yes option.

When creating a physical volume from multiple devices, the devices are treated as independent physical volumes. They can be added to the same or different volume groups.

The --dataalignment, --data-center and --datappb options can be used to specify the alignment of data within the physical volume. This is important for performance, especially with certain hardware RAID controllers or solid state drives.

OPTIONS

See lvm(8) for common options.

Basic options

-f, --force
Force the creation of PV even if the device is already in use. This will overwrite existing data and LVM metadata. Use with caution!
-y, --yes
Assume "yes" to all questions. pvcreate will not ask for confirmation when overwriting existing data or metadata.

Metadata options

-A, --autoboot { y | n }
If set to 'y' (default), LVM will attempt to write a boot loader for your system, if applicable. If set to 'n', it will not.
-B, --restorefile filename
Restores LVM metadata from a file named filename instead of creating new metadata. The file should contain the metadata that was previously saved using vgcfgbackup(8) or vgcfgrestore(8).
-c, --clustered
Create a clustered physical volume. This is for use with LVM clusters.
-k, --keepactive
If the PV is part of an active VG, its metadata will be preserved.
-M, --metadatatype storage-format
Specifies the metadata storage format. Defaults to lvm2.
-m, --metadatasize MEGABYTES
Sets the size of the metadata area in megabytes. Defaults to 80 MiB (since LVM2 version 2.02.67).
-p, --metacopy count
Number of metadata copies to place on the PV. Defaults to 1. Maximum is 2.
-P, --probes
Probe all devices in /dev for metadata. This can be slow.
-u, --uuid uuid
Use the specified UUID for the new physical volume instead of generating one.

Device and Alignment options

--addnode node
For clustered PVs, adds the specified node to the list of nodes that can access the PV.
--allocating-device allocation_device
Specifies the device on which to allocate the PV metadata. This is useful when the physical volume is composed of multiple devices.
--bootloader bootloader_path
Specifies the path to the boot loader. This is relevant when using the --autoboot option.
--bootloaderargs bootloader_args
Specifies arguments to be passed to the boot loader. This is relevant when using the --autoboot option.
--data-alignment offset
Sets the data alignment offset for the PV. This should be a multiple of the physical sector size and a power of 2.
--data-center offset
Sets the data center offset for the PV. This should be a multiple of the physical sector size and a power of 2.
--datappb offset
Sets the data physical-to-physical offset for the PV. This should be a multiple of the physical sector size and a power of 2.
--device device
Specifies the device to use for creating the PV. This option can be used multiple times.
--devices device [device...]
Specifies a list of devices to use for creating the PV.
--devicesfile filename
Specifies a file that contains a list of devices to use for creating the PV.
--driverloaded { y | n }
Indicates whether the LVM driver is already loaded. Defaults to 'y'.
--ignoremonitoring
Ignores monitoring when creating the PV. This is useful in environments where monitoring daemons might interfere with PV creation.

Other options

-d, --debug
Enable debugging output.
-h, --help
Print a usage summary.
-t, --test
Perform a trial run with no changes made.
-v, --verbose
Enable verbose output, showing LVM commands as they are executed.

VARIABLES

None.

ENVIRONMENT VARIABLES

See lvm(8) for information about environment variables.

EXAMPLES

Create a physical volume on /dev/sda1:

pvcreate /dev/sda1

Create a physical volume on /dev/sdb, overwriting any existing data without prompting:

pvcreate --yes /dev/sdb

Create a physical volume on two devices, /dev/sdc and /dev/sdd, and make two copies of the metadata on each:

pvcreate --metacopy 2 /dev/sdc /dev/sdd

Create a physical volume on /dev/sdX with a metadata area of 128MB:

pvcreate --metadatasize 128 /dev/sdX
