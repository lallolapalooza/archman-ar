pp(3pm)

الحزمة: perl-par-packer

التراخيص: GPL

pp(3pm) توثيق مساهم من مستخدمي Perl pp(3pm)

الاسم

pp - مُجمِّع PAR

المُلَخَّص

pp [ -ABCEFILMPTSVXacdefghilmnoprsuvxz ] [ parfile | scriptfile ]...

أمثلة

ملاحظة: عند التشغيل على نظام Microsoft Windows، سيتم استبدال a.out بـ a.exe بدلاً من ذلك.

% pp hello.pl               # حزم 'hello.pl' في ملف قابل للتنفيذ 'a.out'
% pp -o hello hello.pl      # حزم 'hello.pl' في ملف قابل للتنفيذ 'hello'
                            # (أو 'hello.exe' على Win32)
% pp -o foo foo.pl bar.pl   # حزم 'foo.pl' و 'bar.pl' في 'foo'
% ./foo                     # تشغيل 'foo.pl' داخل 'foo'
% mv foo bar; ./bar         # تشغيل 'bar.pl' داخل 'foo'
% mv bar baz; ./baz         # خطأ: لا يمكن فتح نص Perl "baz"
% pp -p file                # إنشاء ملف PAR، 'a.par'
% pp -o hello a.par         # حزم 'a.par' إلى ملف قابل للتنفيذ 'hello'
% pp -S -o hello file       # دمج الخطوتين أعلاه
% pp -p -o out.par file     # إنشاء 'out.par' من 'file'
% pp -B -p -o out.par file  # نفس ما سبق، لكن مع تجميع الوحدات الأساسية
                            # وإزالة أي مسارات محلية من @INC
% pp -P -o out.pl file      # إنشاء 'out.pl' من 'file'
% pp -B -p -o out.pl file   # نفس ما سبق، لكن مع تجميع الوحدات الأساسية
                            # وإزالة أي مسارات محلية من @INC
                            # (-B مفترض عند إنشاء ملفات قابلة للتنفيذ)
% pp -e "print 123"         # حزم سطر واحد في 'a.out'
% pp -p -e "print 123"      # إنشاء ملف PAR 'a.par'
% pp -P -e "print 123"      # إنشاء نص Perl 'a.pl'
% pp -c hello               # التحقق من التبعيات من "perl -c hello"
% pp -x hello               # التحقق من التبعيات من "perl hello"
% pp -n -x hello            # نفس ما سبق، لكن يتخطى المسح الثابت
% pp -I /foo hello          # مسارات تضمين إضافية
% pp -M Foo::Bar hello      # وحدات إضافية في مسار التضمين
% pp -M abbrev.pl hello     # مكتبات إضافية في مسار التضمين
% pp -X Foo::Bar hello      # استبعاد الوحدات
% pp -a data.txt hello      # ملفات بيانات إضافية
% pp -r hello               # حزم 'hello' في 'a.out'، وتشغيل 'a.out'
% pp -r hello a b c         # حزم 'hello' في 'a.out'، وتشغيل 'a.out'
                            # مع الوسائط 'a b c'
% pp hello --log=c          # حزم 'hello' في 'a.out'، وتسجيل
                            # الرسائل في 'c'
# حزم 'hello' في 'out.exe' خالٍ من الوحدة الطرفية (Win32 فقط)
% pp --gui -o out.exe hello
% pp @file hello.pl         # حزم 'hello.pl' ولكن قراءة خيارات _إضافية_
                            # من الملف 'file'

الوصف

يقوم pp بإنشاء ملفات تنفيذية مستقلة من برامج Perl، باستخدام مُجمِّع مضغوط توفره PAR، واستدلالات اكتشاف التبعية التي تقدمها Module::ScanDeps. يتم ضغط ملفات المصدر حرفياً دون تجميع.

يمكنك التفكير في pp على أنه "perlcc الذي يعمل دون متاعب". :-)

واجهة مستخدم رسومية متاحة أيضًا كأمر tkpp.

إنه لا يوفر تسريع خطوة التجميع الذي يوفره perlcc (ومع ذلك، انظر -f أدناه للحصول على تقنيات التجميع بالبايت، وإخفاء المصدر)، ولكنه يعوض ذلك بموثوقية أفضل، وحجم تنفيذي أصغر، واستعادة كاملة لرمز المصدر الأصلي.

عندما يتم تحديد برنامج إدخال واحد، فإن الملف التنفيذي الناتج سيعمل بشكل متطابق مع هذا البرنامج. ومع ذلك، عند تجميع برامج متعددة، فإن الملف التنفيذي المنتج سيشغل البرنامج الذي له نفس الاسم الأساسي مثل $0 (أي اسم الملف المستخدم لاستدعائه). إذا لم يتطابق أي شيء، فسيموت بخطأ "Can't open perl script "$0"".

الخيارات

الخيارات متاحة في شكل قصير و طويل. على سبيل المثال، الأسطر الثلاثة أدناه متكافئة جميعًا:

% pp -o output.exe input.pl
% pp --output output.exe input.pl
% pp --output=output.exe input.pl

نظرًا لأن سطور الأوامر يمكن أن تصبح طويلة بما يكفي للوصول إلى الحدود التي تفرضها بعض الواجهات، فمن الممكن جعل pp يقرأ بعض خياراته من ملف نصي واحد أو أكثر. الاستخدام الأساسي هو مجرد تضمين وسيطة تبدأ برمز "at" (@). سيتم تفسير هذه الوسيطة كملف لقراءة الخيارات منه. يمكن خلط الخيارات العادية وخيارات @file. تم تنفيذ ذلك باستخدام الوحدة النمطية Getopt::ArgvFile، لذا اقرأ توثيقها للاستخدام المتقدم. لاحظ أن Getopt::ArgvFile تستخدم هنا مع المعلمة "resolveEnvVars=1"، أي أن السلاسل الفرعية للشكل ${FOO"}" في محتويات @file يتم استبدالها بقيمة متغير البيئة FOO.

-a, --addfile=FILE|DIR
إضافة ملف إضافي إلى الحزمة. إذا كان الملف عبارة عن دليل، فقم بإضافة جميع الملفات بداخله بشكل متكرر، مع تحويل الروابط إلى ملفات فعلية.

بشكل افتراضي، يتم وضع الملفات تحت "/" داخل الحزمة بأسمائها الأصلية. يمكنك تجاوز ذلك بإلحاق اسم الملف الهدف بعد ";"، على النحو التالي:

% pp -a "old_filename.txt;new_filename.txt"
% pp -a "old_dirname;new_dirname"

يمكنك تحديد "-a" عدة مرات.

-A, --addlist=FILE
قراءة قائمة بأسماء الملفات/الأدلة من FILE، وإضافتها إلى الحزمة. يتم أخذ كل سطر في FILE كوسيطة لـ -a أعلاه.

يمكنك تحديد "-A" عدة مرات.

-B, --bundle
تجميع الوحدات الأساسية في الحزمة الناتجة. يتم تمكين هذا الخيار افتراضيًا، باستثناء عندما يتم تحديد "-p" أو "-P".

منذ إصدار PAR 0.953، يقوم هذا أيضًا بإزالة أي مسارات محلية من قائمة مسارات بحث الوحدة @INC قبل تشغيل النص البرمجي المحتوي.

-C, --clean
تنظيف الملفات المؤقتة المستخرجة من التطبيق وقت التشغيل. بشكل افتراضي، يتم تخزين هذه الملفات مؤقتًا في الدليل المؤقت؛ وهذا يسمح للبرنامج بالبدء بشكل أسرع في المرة القادمة.
-c, --compile
تشغيل "perl -c inputfile" لتحديد تبعيات إضافية لوقت التشغيل.
-cd, --cachedeps=FILE
استخدام FILE لتخزين التبعيات المكتشفة مؤقتًا. ينشئ FILE إذا لم يكن موجودًا. سيؤدي ذلك إلى تسريع عملية المسح في التشغيلات اللاحقة.
-d, --dependent
تقليل حجم الملف التنفيذي بعدم تضمين نسخة من مترجم Perl. الملفات التنفيذية المبنية بهذه الطريقة ستحتاج إلى perl5x.dll أو libperl.so منفصلة لتعمل بشكل صحيح. هذا الخيار متاح فقط إذا تم بناء Perl كمكتبة مشتركة.
-e, --eval=STRING
حزم سطرًا واحدًا، بنفس طريقة "perl -e '...'"
-E, --evalfeature=STRING
يعمل تمامًا مثل "-e"، باستثناء أنه يمكن بشكل ضمني تفعيل جميع الميزات الاختيارية (في وحدة التجميع الرئيسية) مع Perl 5.10 والإصدارات الأحدث. انظر feature.
-x, --execute
تشغيل "perl inputfile" لتحديد تبعيات إضافية لوقت التشغيل.

باستخدام هذا الخيار، قد يتمكن pp من اكتشاف استخدام الوحدات التي لا يمكن تحديدها عن طريق التحليل الثابت لـ "inputfile". الأمثلة هي الأشياء التي يتم تحميلها بواسطة مُحمِّلات وقت التشغيل مثل Module::Runtime أو مُحمِّلات "الإضافات" مثل Module::Loader. لاحظ أن الوحدات التي يتم اكتشافها تعتمد على أجزاء برنامجك التي يتم ممارستها عند تشغيل "inputfile". على سبيل المثال، إذا كان برنامجك ينتهي فورًا عند تشغيله كـ "perl inputfile" لأنه يفتقر إلى الوسائط الإلزامية، فلن يكون لهذا الخيار أي تأثير على الأرجح. يمكنك استخدام --xargs لتوفير الوسائط في هذه الحالة.

--xargs=STRING
استخدام STRING كوسائط عند تشغيل "perl inputfile" باستخدام -x.

على سبيل المثال، قد تحتاج إلى تشغيل "pp -x --xargs --"-a b c" hello.pl" إذا كان hello.pl يتطلب وسائط لتشغيل جزء كافٍ منه لاكتشاف التبعيات.

يتم تحليل STRING بواسطة Perl’s split() باستخدام /(\s+)/ كفاصل افتراضي، لذلك يمكن استخدامه لتوفير وسائط متعددة.

-n, --noexecute
تجنب تشغيل البرنامج المحدد باستخدام -x.
-f, --bytecode
إنشاء ملفات تجميع بالبايت (.bytecode) بدلاً من ملفات المصدر العادية. هذا يخفي رمز المصدر الأصلي إلى حد ما، لكنه ليس آمنًا للغاية.
-F, --no-compress
لا تقم بضغط الملفات المصدر. هذا ينتج عنه ملفات PAR و executables أكبر حجمًا.
-g, --gui
استخدام واجهة مستخدم رسومية (Tk).
-h, --help
عرض رسالة مساعدة.
-i, --include=PATH
تضمين دليل في مسار البحث عن الوحدات @INC. يمكن استخدام هذا الخيار عدة مرات.
-I, --inc=PATH
نفس -i.
-l, --lib=FILE|DIR
إضافة ملف أو دليل مكتبة إلى الحزمة. يعادل استخدام -a، لكنه يضع الملفات في الدليل lib/ داخل الحزمة.
-L, --liblist=FILE
قراءة قائمة بملفات أو أدلة المكتبات من FILE، وإضافتها إلى الحزمة. يعادل استخدام -A، ولكنه يضع الملفات في الدليل lib/ داخل الحزمة.
-m, --module=MOD
تضمين الوحدة النمطية MOD ووحداتها النمطية التابعة، بغض النظر عما إذا كانت مستخدمة في الكود أم لا. يمكن استخدام هذا الخيار عدة مرات.
-M, --moduledeps=MOD
نفس -m.
-o, --output=FILE
تحديد اسم الملف التنفيذي الناتج. إذا لم يتم تحديده، فإن الافتراضي هو "a.out" (أو "a.exe" على Win32).
-p, --par
إنشاء ملف PAR بدلاً من ملف تنفيذي. اسم الملف الافتراضي هو "a.par".
-P, --perlscript
إنشاء نص Perl قابل للتنفيذ بدلاً من ملف PAR. اسم الملف الافتراضي هو "a.pl".
-q, --quiet
كتم معظم رسائل الإخراج.
-r, --run
بعد إنشاء الملف التنفيذي، قم بتشغيله. أي وسائط متبقية بعد اسم الملف (أو بعد "--") يتم تمريرها إلى الملف التنفيذي.
-s, --script
تأكد من أن الملف التنفيذي الناتج يمكن تشغيله كبرنامج نصي عادي (أي، مُلحق تلقائيًا بـ "use scriptname; scriptname-").
-S, --script=FILE
قم بإنشاء ملف تنفيذي من FILE، مع افتراض أن FILE هو برنامج Perl. يعادل "pp -o $(basename $FILE) $FILE".
-t, --target=ARCH
إنشاء حزمة تستهدف بنية ARCH (على سبيل المثال، "MSWin32-x86-multi-thread").
-T, --tar
إنشاء أرشيف TAR بدلاً من ملف PAR.
-u, --unpack
استخراج محتويات ملف PAR (أو ملف تنفيذي) إلى دليل.
-v, --version
عرض معلومات الإصدار.
-V, --verbose
طباعة المزيد من معلومات الإخراج.
--
توقف عن تحليل الخيارات. كل شيء بعد ذلك هو وسائط.
-X, --exclude=MOD
استبعاد الوحدة النمطية MOD ووحداتها النمطية التابعة. يمكن استخدام هذا الخيار عدة مرات.
-z, --strip
إزالة رموز التصحيح من الملف التنفيذي الناتج.

pp(1) - ArchWiki

DESCRIPTION

The pp program, or PAR Packer, is a self-extracting archive generator for Perl scripts. It bundles your script and all of its dependencies into a single executable file that can be run directly without requiring the end-user to have Perl installed, or it can create a compressed archive that requires Perl.

It is useful for distributing Perl applications to users who may not have Perl installed or who may not have the correct versions of dependencies installed. It can also be used to create self-contained installers or to obfuscate Perl code.

SYNOPSIS

pp [options] SCRIPT [args...]

OPTIONS

-o OUTFILE
Specify the output file name. If not given, the output file will be named after the script with a -packed suffix.
-x
Create a script that extracts itself to a temporary directory and then runs. This is the default behavior.
-X
Do not create a temporary directory. The script will be executed directly from the archive.
-c
Compress the archive using gzip. This is the default.
-z
Do not compress the archive. This will result in a larger file size but faster extraction.
-Z
Compress the archive using bzip2. This provides better compression than gzip but is slower.
--level NUMBER
Set zip compression level; NUMBER is an integer from 0 to 9, 0 = no compression, 9 = max compression. Defaults to 6 if -z is not used.

ENVIRONMENT

PP_OPTS
Command-line options (switches). Switches in this variable are taken as if they were on every pp command line.

NOTES

Here are some recipes showing how to utilize pp to bundle source.pl with all its dependencies, on target machines with different expected settings:

Stone-alone setup:
To make a stand-alone executable, suitable for running on a machine that doesn't have perl installed: 
% pp -o packed.exe source.pl        # makes packed.exe
# Now, deploy 'packed.exe' to target machine...
% packed.exe                        # run it
Perl interpreter only, without core modules:
To make a packed .pl file including core modules, suitable for running on a machine that has a perl interpreter, but where you want to be sure of the versions of the core modules that your program uses: 
% pp -B -P -o packed.pl source.pl   # makes packed.pl
# Now, deploy 'packed.pl' to target machine...
% perl packed.pl                    # run it
Perl with core modules installed:
To make a packed .pl file without core modules, relying on the target machine's perl interpreter and its core libraries. This produces a significantly smaller file than the previous version: 
% pp -P -o packed.pl source.pl      # makes packed.pl
# Now, deploy 'packed.pl' to target machine...
% perl packed.pl                    # run it
Perl with PAR.pm and its dependencies installed:
Make a separate archive and executable that uses the archive. This relies upon the perl interpreter and libraries on the target machine. 
% pp -p source.pl                   # makes source.par
% echo "use PAR 'source.par';" > packed.pl;
% cat source.pl >> packed.pl;       # makes packed.pl
# Now, deploy 'source.par' and 'packed.pl' to target machine...
% perl packed.pl                    # run it, perl + core modules required

Note that even if your perl was built with a shared library, the 'Stand-alone executable' above will not need a separate perl5x.dll or libperl.so to function correctly. But even in this case, the underlying system libraries such as libc must be compatible between the host and target machines. Use "--dependent" if you are willing to ship the shared library with the application, which can significantly reduce the executable size.
