NAME

objdump - display information from object files

SYNOPSIS

DESCRIPTION

objdump displays information about one or more object files. The options control what particular information to display. This information is mostly useful to programmers who are working on the compilation tools, as opposed to programmers who just want their program to compile and work.

objfile... are the object files to be examined. When you specify archives, objdump shows information on each of the member object files.

OPTIONS

The long and short forms of options, shown here as alternatives, are equivalent. At least one option from the list -a,-d,-D,-e,-f,-g,-G,-h,-H,-p,-P,-r,-R,-s,-S,-t,-T,-V,-x must be given.

-a
--archive-header
If any of the objfile files are archives, display the archive header information (in a format similar to ls -l). Besides the information you could list with ar tv, objdump -a shows the object file format of each archive member.
--adjust-vma=offset
When dumping information, first add offset to all the section addresses. This is useful if the section addresses do not correspond to the symbol table, which can happen when putting sections at particular addresses when using a format which can not represent section addresses, such as a.out.
-b bfdname
--target=bfdname
Specify that the object-code format for the object files is bfdname. This option may not be necessary; objdump can automatically recognize many formats.

For example,

objdump -b oasys -m vax -h fu.o

displays summary information from the section headers (-h) of fu.o, which is explicitly identified (-m) as a VAX object file in the format produced by Oasys compilers. You can list the formats available with the -i option.

-C
--demangle[=style]
Decode (demangle) low-level symbol names into user-level names. Besides removing any initial underscore prepended by the system, this makes C++ function names readable. Different compilers have different mangling styles. The optional demangling style argument can be used to choose an appropriate demangling style for your compiler.
--recurse-limit
--no-recurse-limit
--recursion-limit
--no-recursion-limit
Enables or disables a limit on the amount of recursion performed whilst demangling strings. Since the name mangling formats allow for an infinite level of recursion it is possible to create strings whose decoding will exhaust the amount of stack space available on the host machine, triggering a memory fault. The limit tries to prevent this from happening by restricting recursion to 2048 levels of nesting.

The default is for this limit to be enabled, but disabling it may be necessary in order to demangle truly complicated names. Note however that if the recursion limit is disabled then stack exhaustion is possible and any bug reports about such an event will be rejected.

-g
--debugging
Display debugging information. This attempts to parse STABS debugging format information stored in the file and print it out using a C like syntax. If no STABS debugging was found this option falls back on the -W option to print any DWARF information in the file.
-e
--debugging-tags
Like -g, but the information is generated in a format compatible with ctags tool.
-d
--disassemble
--disassemble=symbol
Display the assembler mnemonics for the machine instructions from the input file. This option only disassembles those sections which are expected to contain instructions. If the optional symbol argument is given, then display the assembler mnemonics starting at symbol. If symbol is a function name then disassembly will stop at the end of the function, otherwise it will stop when the next symbol is encountered. If there are no matches for symbol then nothing will be displayed.

Note if the --dwarf=follow-links option is enabled then any symbol tables in linked debug info files will be read in and used when disassembling.

-D
--disassemble-all
Like -d, but disassembles all sections that contain code, not just the .text section. If the optional symbol argument is given, then disassembly starts at symbol and continues through all sections that contain code.
-EB
-EL
--endian={big|little}
Specify that the object code is big endian or little endian. This option may be used to override the BFD default if it cannot determine the endianness of the object file, or if you want to examine an object file which uses a different endianness than the host.
-f
--file-headers
Display the linker script header for each input file. This shows information such as the file's type, architecture, and machine architecture.
-F
--file-offsets
Display the values of file offset pointers for all sections in the input file. These are the offsets of the start of the section within the file. This is only useful for formats which have section offsets.
--file-start-context
When displaying DWARF information, display the context for the file start address. This can be useful for debugging issues with the C compilation toolchain.
-G
--stabs
Dump the STABS debugging information in the object file. This is intended to be a debugging tool for the gdb debugger. The output is sometimes hard to understand. It is recommended to use -g instead.
-h
--section-headers
--headers
Display the summary information from the section headers of the input file. This includes the name, type, address, size, flags and offsets of each section.
-H
--help
Display the usage message for objdump and exit.
-i
--info
List the target formats known to this version of objdump and exit.
--insn-width=width
When disassembling, print instructions of at most width bytes wide. This is useful to help format output.
-j section
--section=section
Displays information from the specified section only. Multiple -j options can be given to display information from several sections.
-L
--process-links
Display information from any linked debug info files. This option is useful when debugging C++ code.
-l
--line-numbers
Adds line number and file name information to the output of the -d and -S options. This option is only useful when the input file contains debugging information.
-m machine
--architecture=machine
Specify that the input files are for the given instruction set architecture. The default is to let the BFD library attempt to automatically detect the architecture. This option can be used to override the automatic detection.
-M options
--disassembler-options=options
Pass comma separated options to the disassembler. The available options depend on the target architecture. For x86, valid options include intel, att, and dynamic-reloc. For MIPS, valid options include full-mem.
-p
--private-headers
Display any extra information that is specific to a file format. For example, for COFF files, this will dump the COFF header. For DWARF files, it dumps the DWARF header. For ELF files, it dumps the ELF header. Note that this option is the default when no other information is requested.
-P options
--private=options
Display specific private headers, where options is a comma separated list of header types. For example, -P arm-linker.
--prefix=prefix
When processing DWARF information, only print sections prefixed with prefix. This can be useful when dealing with multiple linked debug files.
--prefix-addresses
When disassembling, prefix each instruction with its address. This is the default behavior.
--prefix-strip=level
When processing DWARF information, strip level components from the prefix of any section names. This can be useful when dealing with multiple linked debug files.
-r
--reloc
Display the relocation entries in the full contents of the input file. This option is only useful for files which contain relocation entries.
-R
--dynamic-reloc
Display the dynamic relocation entries in the full contents of the input file. This option is only useful for files which contain dynamic relocation entries.
-s
--full-contents
Display the full contents of all read sections, in hexadecimal and ASCII. If you specify a section using -j, then only that section will be displayed.
-S
--source
Display the source code corresponding to the disassembled memory. This option is only useful when the input file contains debugging information.
--source-comment[=text]
Add a comment line before printing source code. If no text is supplied, a default comment is printed. This option is useful when debugging assembly code.
--special-syms
Display all special symbols in the input file. These are symbols which are not usually seen, like the start and end symbols for sections.
--start-address=address
Start displaying information from the given address. The default is the lowest address in the file.
--stop-address=address
Stop displaying information at the given address. The default is the highest address in the file.
-t
--syms
Display the symbol table entries in the full contents of the input file.
-T
--dynamic-syms
Display the dynamic symbol table entries in the full contents of the input file.
-U method
--unicode=method
Specify the method for handling unicode characters when displaying output. Valid methods are always, locale, and never. The default is locale.
-V
--version
Display the version number of objdump and exit.
--visualize-jumps[=color|=extended-color|=off]
Enable or disable visualization of jumps in disassembled code. This can be useful for understanding control flow. The optional argument can be used to specify coloring options. The default is to disable this feature.
-W[options]
--dwarf=options
Dump DWARF debugging information in the object file. The options argument is a comma-separated list of DWARF sections to dump. Available sections are:

rawline: Dump raw line number information.
decodedline: Decode line number information.
info: Dump information entries.
abbrev: Dump abbreviation entries.
pubnames: Dump public name entries.
aranges: Dump address range entries.
macro: Dump macro entries.
frames: Dump frame entries.
frames-interp: Dump interpreted frame entries.
str: Dump string entries.
str-offsets: Dump string offset entries.
loc: Dump location entries.
Ranges: Dump range entries.
pubtypes: Dump public type entries.
trace_info: Dump trace info entries.
trace_abbrev: Dump trace abbrev entries.
trace_aranges: Dump trace aranges entries.
gdb_index: Dump GDB index entries.
addr: Dump address sections.
cu_index: Dump compilation unit index entries.
links: Dump link information.

If no options are specified, then all DWARF sections are dumped.

--dwarf-depth=n
Limit the depth of recursion when processing DWARF information to n levels. This can be useful to prevent stack overflows when dealing with deeply nested or malformed DWARF data.
--dwarf-start=n
Start processing DWARF information at compilation unit n. This can be useful to limit the amount of output when dealing with large numbers of compilation units.
-wD
--dwarf=use-debuginfod
Use the debuginfod service to fetch DWARF information if it is not found in the object file. This requires that the debuginfod client is installed and configured correctly.
-wE
--dwarf=do-not-use-debuginfod
Do not use the debuginfod service to fetch DWARF information, even if it is available.
-WK
--dwarf=follow-links
Follow symbolic links when processing DWARF information. This can be useful when debugging code that is built using symlinks.
-WN
--dwarf=no-follow-links
Do not follow symbolic links when processing DWARF information.
-w
--wide
Display output in wide 132 columns instead of the default 80 columns. This is useful for displaying long lines of disassembly.
-x
--all-headers
Display all available header information. This is equivalent to specifying all of -a, -f, -h, -p, -r, and -R.
-z
--disassemble-zeroes
Disassemble zero sections. This can be useful for finding hidden code or data in an object file.

يضيف الوسيط on الألوان باستخدام ألوان طرفية بسيطة.

يقوم الوسيط terminal بنفس الشيء، ولكن فقط إذا كان جهاز الإخراج طرفية.

الوسيط extended-color مشابه للوسيط on، ولكنه يستخدم ألوان 8 بت. قد لا تعمل هذه الألوان على جميع الطرفيات.

يقوم الوسيط off بتعطيل التفكيك الملون.

ملاحظة - إذا تم تمكين دعم بروتوكول debuginfod عند بناء binutils، فسيتضمن هذا الخيار أيضًا محاولة الاتصال بأي خوادم debuginfod مذكورة في متغير البيئة DEBUGINFOD_URLS. قد يستغرق هذا وقتًا طويلاً. يمكن تعطيل هذا السلوك عبر خيار التصحيح =do-not-use-debuginfod.

--dwarf-depth=n
يحد من تفريغ قسم ".debug_info" إلى n من الأبناء. هذا مفيد فقط مع --debug-dump=info. الافتراضي هو طباعة جميع وحدات معلومات التصحيح (DIEs)؛ القيمة الخاصة 0 لـ n سيكون لها هذا التأثير أيضًا.

مع قيمة غير صفرية لـ n، لن تتم طباعة وحدات معلومات التصحيح (DIEs) على مستوى n أو أعمق منه. النطاق لـ n يبدأ من الصفر.

--dwarf-start=n
يطبع فقط وحدات معلومات التصحيح (DIEs) بدءًا من الوحدة رقم n. هذا مفيد فقط مع --debug-dump=info.

إذا تم تحديد هذا الخيار، فسيقوم بقمع طباعة أي معلومات رأس وجميع وحدات معلومات التصحيح (DIEs) قبل الوحدة رقم n. سيتم طباعة الأشقاء والأبناء فقط للوحدة المحددة.

يمكن استخدام هذا بالاقتران مع --dwarf-depth.

--dwarf-check
يمكّن فحوصات إضافية لاتساق معلومات Dwarf.
--ctf[=section]
يعرض محتويات قسم CTF المحدد. تحتوي أقسام CTF نفسها على العديد من الأقسام الفرعية، ويتم عرضها جميعًا بالترتيب.

بشكل افتراضي، يعرض اسم القسم المسمى .ctf، وهو الاسم الذي ينشره ld.

--ctf-parent=member
إذا كان قسم CTF يحتوي على أنواع محددة بشكل غامض، فسيتكون من أرشيف للعديد من قواميس CTF، وجميعها ترث من قاموس واحد يحتوي على أنواع غير غامضة. يتم تسمية هذا العضو افتراضيًا .ctf، مثل القسم الذي يحتويه، ولكن يمكن تغيير هذا الاسم باستخدام الدالة "ctf_link_set_memb_name_changer" في وقت الربط. عند النظر إلى أرشيفات CTF التي تم إنشاؤها بواسطة رابط يستخدم مغير الاسم لإعادة تسمية عضو الأرشيف الرئيسي، يمكن استخدام --ctf-parent لتحديد الاسم المستخدم للرئيس.
--sframe[=section]
يعرض محتويات قسم SFrame المحدد.

بشكل افتراضي، يعرض اسم القسم المسمى .sframe، وهو الاسم الذي ينشره ld.

-G
--stabs
يعرض المحتويات الكاملة لأي أقسام مطلوبة. يعرض محتويات أقسام .stab و .stab.index و .stab.excl من ملف ELF. هذا مفيد فقط في الأنظمة (مثل Solaris 2.0) التي يتم فيها حمل إدخالات جدول رموز التصحيح ".stab" في قسم ELF. في معظم تنسيقات الملفات الأخرى، يتم دمج إدخالات جدول رموز التصحيح مع رموز الربط، وتكون مرئية في إخراج --syms.
--start-address=address
يبدأ عرض البيانات من العنوان المحدد. يؤثر هذا على إخراج الخيارات -d و -r و -s.
--stop-address=address
يتوقف عن عرض البيانات عند العنوان المحدد. يؤثر هذا على إخراج الخيارات -d و -r و -s.
-t
--syms
يطبع إدخالات جدول الرموز للملف. هذا مشابه للمعلومات التي يوفرها برنامج nm، على الرغم من أن تنسيق العرض مختلف. يعتمد تنسيق الإخراج على تنسيق الملف الذي يتم تفريغه، ولكن هناك نوعان رئيسيان. أحدهما يبدو كالتالي: 
[  4](sec  3)(fl 0x00)(ty   0)(scl   3) (nx 1) 0x00000000 .bss
[  6](sec  1)(fl 0x00)(ty   0)(scl   2) (nx 0) 0x00000000 fred
