PPI__Document(3pm)

الحزمة: perl-ppi

التراخيص: PerlArtistic

PPI::Document(3) وثائق Perl المساهمة من قبل المستخدم PPI::Document(3)

الاسم

PPI::Document - تمثيل كائني لوثيقة Perl

الوراثة

PPI::Document
isa PPI::Node
    isa PPI::Element

الملخص

use PPI;

# تحميل وثيقة من ملف
my $Document = PPI::Document->new('My/Module.pm');

# إزالة التعليقات
$Document->prune('PPI::Token::Comment');

# البحث عن جميع الدوال المسماة
my $sub_nodes = $Document->find( 
      sub { $_[1]->isa('PPI::Statement::Sub') and $_[1]->name }
);
my @sub_names = map { $_->name } @$sub_nodes;

# حفظ الملف
$Document->save('My/Module.pm.stripped');

الوصف

يمثل الكلاس "PPI::Document" وثيقة Perl واحدة. يعمل كائن "PPI::Document" كجذر PPI::Node، مع بعض الطرق الإضافية للتحميل والحفظ، والعمل مع مواقع الأسطر/الأعمدة للعناصر داخل الملف.

الاستثناء لسلوكه الشبيه بـ PPI::Node هو أن كائن "PPI::Document" لا يمكن أن يكون له أب مطلقًا، وهو دائمًا العقدة الجذرية في الشجرة.

دعم Storable

ينفذ "PPI::Document" الخطافات الضرورية "STORABLE_freeze" و "STORABLE_thaw" لتوفير دعم أصلي لـ Storable، إذا كان مثبتًا لديك.

ومع ذلك، إذا كنت ترغب في استنساخ وثيقة، فمن المستحسن بشدة استخدام الطريقة "$Document->clone" بدلاً من دالة "dclone" الخاصة بـ Storable (على الرغم من أن "dclone" يجب أن تعمل أيضًا).

الطرق

معظم الأشياء التي قد ترغب في القيام بها مع وثيقة من المرجح أن تنطوي على الطرق من الكلاس PPI::Node، الذي ينتمي هذا إليه.

الطرق المدرجة هنا هي القلائل المتبقية من الطرق الخاصة بالوثيقة حقًا.

جديد

# بناء بسيط
$doc = PPI::Document->new( $filename );
$doc = PPI::Document->new( \$source  );

# مع تعيين السمة readonly
$doc = PPI::Document->new( $filename,
        readonly => 1,
);

يأخذ المُنشئ "new" كوسيط مجموعة متنوعة من مصادر كود Perl المختلفة، وينشئ وثيقة Perl "PPI::Document" متماسكة واحدة لها.

إذا تم تمرير اسم ملف كسلسلة نصية عادية، فسوف يحاول تحميل الوثيقة من الملف.

إذا تم تمرير مرجع إلى "SCALAR"، فيعتبر هذا كود مصدر ويتم تحليله مباشرة لإنشاء الوثيقة.

إذا تم تمرير صفر وسيط، سيتم إنشاء وثيقة "فارغة" لا تحتوي على أي محتوى على الإطلاق.

في جميع الحالات، تعتبر الوثيقة "مجهولة" وليست مرتبطة بمكان إنشائها. على وجه التحديد، إذا قمت بإنشاء PPI::Document من اسم ملف، فإن الوثيقة لن تتذكر من أين تم إنشاؤها.

يعيد كائن "PPI::Document"، أو "undef" إذا فشل التحليل. يمكن أيضًا إلقاء كائنات PPI::Exception إذا كانت هناك مشاكل في التحليل.

يأخذ المُنشئ أيضًا أعلام السمات.

readonly

سيسمح تعيين "readonly" إلى true للأنظمة المختلفة بتوفير تحسينات وتخزين مؤقت إضافي. لاحظ أنه نظرًا لأن "readonly" هو علامة تحسين، فهو معطل افتراضيًا وستحتاج إلى تمكينه بشكل صريح.

feature_mods

يتيح تعيين feature_mods مع hashref تحديد ميزات تحليل perl لتفعيلها للوثيقة بأكملها. (على سبيل المثال، عندما يُفترض تشغيل الكود كسطر واحد)

custom_feature_includes

custom_feature_includes =>
  { strEct => { signatures => "Syntax::Keyword::Try" } }

يتيح تعيين custom_feature_includes مع hashref تحديد أسماء تضمين تعمل كـ pragmas التي تمكن ميزات التحليل ضمن نطاقها.

هذا مفيد جدًا عندما يكون لدى مشروع عملك وحدة نمطية أساسية خاصة به.

يمكن أيضًا تقديمه بتنسيق JSON أو YAML في متغير البيئة PPI_CUSTOM_FEATURE_INCLUDES، كالتالي:

PPI_CUSTOM_FEATURE_INCLUDES='strEct: {signatures: perl}' \
  perlcritic lib/OurModule.pm
PPI_CUSTOM_FEATURE_INCLUDES='{"strEct":{"signatures":"perl"}}' \
  perlcritic lib/OurModule.pm

custom_feature_include_cb

custom_feature_include_cb => sub {
  my ($statement) = @_;
  return $statement->module eq "strEct" ? { signatures => "perl" } : ();
},

يتسبب تعيين custom_feature_include_cb مع مرجع كود في أن تقوم جميع عمليات الفحص على التضمينات باستدعاء تلك الدالة الفرعية قبل القيام بأي عمليات فحص أخرى. يمكن للدالة الفرعية أن تقرر إما إرجاع hashref من الميزات التي سيتم تمكينها أو تعطيلها، والتي سيتم استخدامها للنطاق الذي تم استدعاء التضمين فيه، أو undef للمتابعة مع عمليات الفحص الافتراضية. الوسيط للدالة الفرعية سيكون كائن PPI::Statement::Include.

يمكن أن يكون هذا مفيدًا عندما يكون لدى مشروع عملك وحدة نمطية أساسية معقدة.

set_cache $cache

اعتبارًا من PPI 1.100، يدعم "PPI::Document" التخزين المؤقت للمحلل.

يوفر فئة التخزين المؤقت الافتراضية PPI::Cache تخزينًا مؤقتًا قائمًا على Storable أو الوثيقة المحللة بناءً على تجزئة MD5 للوثيقة كسلسلة نصية.

تُستخدم الطريقة الثابتة "set_cache" لتعيين كائن التخزين المؤقت الذي سيستخدمه "PPI::Document" عند تحميل الوثائق. تأخذ كوسيط كائن PPI::Cache (أو شيئًا يطابق "isa" نفس الشيء).

إذا تم تمرير "undef"، فستتوقف هذه الطريقة عن استخدام ذاكرة التخزين المؤقت الحالية، إن وجدت.

لمزيد من المعلومات حول التخزين المؤقت، راجع PPI::Cache.

يعيد true عند النجاح، أو "undef" إذا لم يتم تمرير معلمة صالحة.

get_cache

إذا تم تعيين ذاكرة تخزين مؤقت للوثيقة حاليًا، فستقوم طريقة "get_cache" بإعادتها.

يعيد كائن PPI::Cache، أو "undef" إذا لم تكن هناك ذاكرة تخزين مؤقت حاليًا لـ "PPI::Document".

filename

تقوم أداة الوصول "filename" بإعادة اسم الملف الذي تم تخزين الوثيقة فيه.

readonly

تشير السمة "readonly" إلى ما إذا كانت الوثيقة مخصصة للقراءة فقط، ولن يتم تعديلها أبدًا. هذه علامة استشارية، قد يستخدمها أو لا يستخدمها كتاب أنظمة PPI ذات الصلة للتمكين التحسينات وذاكرات التخزين المؤقت لوثيقتك.

يعيد true إذا كانت الوثيقة للقراءة فقط أو false إذا لم تكن كذلك.

tab_width [ $width ]

لتمكين دعم "location" بشكل صحيح، تحتاج "Documents" إلى فهم مفهوم علامات الجدولة وعرض علامة الجدولة. تُستخدم طريقة "tab_width" للحصول على عرض علامة الجدولة وتعيينه.

في الوقت الحالي، يدعم PPI فقط علامات الجدولة "الساذجة" (العرض 1)، ولكننا نخطط لدعم عروض علامات الجدولة العشوائية والافتراضية وتحديد الأنماط تلقائيًا لاحقًا.

يعيد عرض علامة الجدولة كرقم صحيح، أو "die"s إذا حاولت تعيين عرض علامة الجدولة.

PPI::Document(3pm) - Arch Linux Man Pages

NAME

PPI::Document - A document object

INHERITANCE

PPI::Document is a subclass of PPI::Node.

PPI::Document is a subclass of PPI::Node::Package.

PPI::Document is a subclass of PPI::Node::Root.

SYNOPSIS

  my $document = PPI::Document->new( \$string );
  my $document = PPI::Document->new( $file );
  my $document = PPI::Document->new;

  # Get the package name
  my $package = $document->package;

  # Get all of the POD sections
  my @pod = $document->pod;

  # Get all of the elements of a given type
  my @statements = $document->find( 'PPI::Statement' );

  # Save the document to a file
  $document->save( 'new_file.pl' );

  # Get the document as a string
  my $string = $document->serialize;

  # Get a unique ID for the document
  my $id = $document->hex_id;

  # Check if the document is complete
  if ( $document->complete ) {
      # ...
  }

DESCRIPTION

This is the main object for representing a Perl document. It is the root node of the document's internal tree structure.

METHODS

custom_feature_includes { module_name => { feature_name => $provider } }

A method to generate a Perl Document object from a number of separate files that contain Perl code. It will return a Perl Document that has been populated with the content of those files.

It returns a PPI::Document object on success and undef on failure.

custom_feature_include_cb sub { ... }

save

$document->save( $file )

The "save" method serializes the "PPI::Document" object and saves the resulting Perl document to a file. Returns "undef" on failure to open or write to the file.

serialize

Unlike the "content" method, which shows only the immediate content within an element, Document objects also have to be able to be written out to a file again.

When doing this we need to take into account some additional factors.

Primarily, we need to handle here-docs correctly, so that are written to the file in the expected place.

The "serialize" method generates the actual file content for a given Document object. The resulting string can be written straight to a file.

Returns the serialized document as a string.

hex_id

The "hex_id" method generates an unique identifier for the Perl document.

This identifier is basically just the serialized document, with Unix-specific newlines, passed through MD5 to produce a hexadecimal string.

This identifier is used by a variety of systems (such as PPI::Cache and Perl::Metrics) as a unique key against which to store or cache information about a document (or indeed, to cache the document itself).

Returns a 32 character hexadecimal string.

index_locations

Within a document, all PPI::Element objects can be considered to have a "location", a line/column position within the document when considered as a file. This position is primarily useful for debugging type activities.

The method for finding the position of a single Element is a bit laborious, and very slow if you need to do it a lot. So the "index_locations" method will index and save the locations of every Element within the Document in advance, making future calls to <PPI::Element::location> virtually free.

Please note that this index should always be cleared using "flush_locations" once you are finished with the locations. If content is added to or removed from the file, these indexed locations will be wrong.

flush_locations

When no longer needed, the "flush_locations" method clears all location data from the tokens.

normalized

The "normalized" method is used to generate a "Layer 1" PPI::Document::Normalized object for the current Document.

A "normalized" Perl Document is an arbitrary structure that removes any irrelevant parts of the document and refactors out variations in style, to attempt to approach something that is closer to the "true meaning" of the Document.

See PPI::Normal for more information on document normalization and the tasks for which it is useful.

Returns a PPI::Document::Normalized object, or "undef" on error.

complete

The "complete" method is used to determine if a document is cleanly structured, all braces are closed, the final statement is fully terminated and all heredocs are fully entered.

Returns true if the document is complete or false if not.

errstr

For error that occur when loading and saving documents, you can use "errstr", as either a static or object method, to access the error message.

If a Document loads or saves without error, "errstr" will return false.
