ppc64le-elf-c++filt(1)

الحزمة: ppc64le-elf-binutils

التراخيص: GPL

C++FILT(1) أدوات تطوير GNU C++FILT(1)

الاسم

c++filt - فك تشفير رموز C++ و Java

الملخص

c++filt [-_|--strip-underscore]
[-n|--no-strip-underscore]
[-p|--no-params]
[-t|--types]
[-i|--no-verbose]
[-r|--no-recurse-limit]
[-R|--recurse-limit]
[-s format|--format=format]
[--help] [--version] [symbol...]

الوصف

توفر لغات C++ و Java التحميل الزائد للدوال، مما يعني أنه يمكنك كتابة العديد من الدوال بنفس الاسم، بشرط أن تأخذ كل دالة معلمات بأنواع مختلفة. لكي تتمكن من التمييز بين هذه الدوال ذات الأسماء المتشابهة، تقوم C++ و Java بتشفيرها إلى اسم تجميع منخفض المستوى يحدد بشكل فريد كل إصدار مختلف. تُعرف هذه العملية باسم التشفير (mangling). يقوم برنامج c++filt [1] بالعكس: يقوم بفك تشفير (demangles) الأسماء منخفضة المستوى إلى أسماء على مستوى المستخدم حتى يمكن قراءتها.

كل كلمة أبجدية رقمية (تتكون من أحرف، أرقام، شرطات سفلية، علامات الدولار، أو نقاط) تُرى في المدخلات هي اسم مشفر محتمل. إذا قام الاسم بفك تشفير إلى اسم C++، يتم استبدال اسم C++ بالاسم منخفض المستوى في المخرجات، وإلا يتم إخراج الكلمة الأصلية. بهذه الطريقة يمكنك تمرير ملف تجميع كامل، يحتوي على أسماء مشفرة، عبر c++filt ورؤية نفس الملف المصدر الذي يحتوي على أسماء مفككة الشفرة.

يمكنك أيضًا استخدام c++filt لفك تشفير رموز فردية عن طريق تمريرها في سطر الأوامر:

c++filt <symbol>

إذا لم يتم تقديم أي وسيطات symbol، يقرأ c++filt أسماء الرموز من المدخلات القياسية بدلاً من ذلك. تتم طباعة جميع النتائج على المخرجات القياسية. الفرق بين قراءة الأسماء من سطر الأوامر مقابل قراءة الأسماء من المدخلات القياسية هو أن الوسيطات في سطر الأوامر يُتوقع أن تكون مجرد أسماء مشفرة ولا يتم إجراء أي فحص لفصلها عن النص المحيط. وبالتالي، على سبيل المثال:

c++filt -n _Z1fv

سيعمل وسيقوم بفك تشفير الاسم إلى "f()" بينما:

c++filt -n _Z1fv,

لن يعمل. (لاحظ الفاصلة الإضافية في نهاية الاسم المشفر مما يجعلها غير صالحة). ومع ذلك، فإن هذا الأمر سيعمل:

echo _Z1fv, | c++filt -n

وسيعرض "f(),"، أي الاسم المفكك للشفرة متبوعًا بفاصلة لاحقة. هذا السلوك موجود لأن الأسماء عند قراءتها من المدخلات القياسية يُتوقع أن تكون جزءًا من ملف تجميع قد يحتوي على أحرف إضافية، غير ضرورية، تتبع اسمًا مشفرًا. على سبيل المثال:

.type   _Z1fv, @function

الخيارات

-_
--strip-underscore
على بعض الأنظمة، تضع كل من مترجمات C و C++ شرطة سفلية قبل كل اسم. على سبيل المثال، اسم C "foo" يحصل على الاسم منخفض المستوى "_foo". هذا الخيار يزيل الشرطة السفلية الأولية. يعتمد ما إذا كان c++filt يزيل الشرطة السفلية افتراضيًا على الهدف.
-n
--no-strip-underscore
لا تقم بإزالة الشرطة السفلية الأولية.
-p
--no-params
عند فك تشفير اسم دالة، لا تعرض أنواع معلمات الدالة.
-t
--types
حاول فك تشفير الأنواع بالإضافة إلى أسماء الدوال. هذا معطل افتراضيًا نظرًا لأن الأنواع المشفرة تستخدم عادة داخليًا في المترجم، ويمكن الخلط بينها وبين الأسماء غير المشفرة. على سبيل المثال، سيتم فك تشفير دالة تسمى "a" تُعامل كاسم نوع مشفر إلى "signed char".
-i
--no-verbose
لا تتضمن تفاصيل التنفيذ (إن وجدت) في المخرجات المفككة للشفرة.
-r
-R
--recurse-limit
--no-recurse-limit
--recursion-limit
--no-recursion-limit
تمكين أو تعطيل حد على مقدار العودية (recursion) التي يتم إجراؤها أثناء فك تشفير السلاسل النصية. نظرًا لأن تنسيقات تشفير الأسماء تسمح بمستوى لانهائي من العودية، فمن الممكن إنشاء سلاسل نصية قد يؤدي فك تشفيرها إلى استنفاد مساحة المكدس المتاحة على الجهاز المضيف، مما يؤدي إلى خطأ في الذاكرة. يحاول الحد منع حدوث ذلك عن طريق تقييد العودية إلى 2048 مستوى تداخل.

الافتراضي هو تمكين هذا الحد، ولكن قد يكون تعطيله ضروريًا لفك تشفير الأسماء المعقدة حقًا. لاحظ مع ذلك أنه إذا تم تعطيل حد العودية، فإن استنفاد المكدس ممكن وسيتم رفض أي تقارير عن أخطاء بخصوص هذا الحدث.

الخيار -r هو مرادف للخيار --no-recurse-limit. الخيار -R هو مرادف للخيار --recurse-limit.

-s format
--format=format
يمكن لـ c++filt فك تشفير طرق مختلفة للتشفير، تستخدمها مترجمات مختلفة. يحدد الوسيط لهذا الخيار الطريقة التي يستخدمها:
"auto"
الاختيار التلقائي بناءً على الملف التنفيذي (الطريقة الافتراضية)
"gnu"
الطريقة التي يستخدمها مترجم C++ GNU (g++)
"lucid"
الطريقة التي يستخدمها مترجم Lucid (lcc)
"arm"
الطريقة المحددة في مرجع C++ الملحق (C++ Annotated Reference Manual)
"hp"
الطريقة التي يستخدمها مترجم HP (aCC)
"edg"
الطريقة التي يستخدمها مترجم EDG
"gnu-v3"
الطريقة التي يستخدمها مترجم C++ GNU (g++) مع ABI V3.
"java"
الطريقة التي يستخدمها مترجم Java GNU (gcj)
"gnat"
الطريقة التي يستخدمها مترجم Ada GNU (GNAT).
--help
طباعة ملخص للخيارات المتاحة لـ c++filt والخروج.
--version
طباعة رقم إصدار c++filt والخروج.
@file
قراءة خيارات سطر الأوامر من file. يتم إدراج الخيارات المقروءة بدلاً من خيار @file الأصلي. إذا لم يكن file موجودًا، أو تعذر قراءته، فسيتم التعامل مع الخيار حرفيًا، ولن يتم إزالته.

يتم فصل الخيارات في file بالمسافات البيضاء. يمكن تضمين حرف مسافة بيضاء في خيار عن طريق إحاطة الخيار بأكمله إما بعلامات اقتباس فردية أو مزدوجة. يمكن تضمين أي حرف (بما في ذلك الشرطة المائلة العكسية) عن طريق وضع الشرطة المائلة العكسية قبل الحرف المراد تضمينه. قد يحتوي file نفسه على خيارات @file إضافية؛ سيتم معالجة أي خيارات من هذا القبيل بشكل تكراري.

NAME

c++filt — Demangle C++ mangled symbol names

SYNOPSIS

c++filt [options] [names...]

DESCRIPTION

This manual page documents the c++filt command. This utility is part of the GNU Binary Utilities (binutils).

c++filt demangles C++ mangled symbol names. C++ compilers mangle symbol names to embed type information into them. This can make them difficult to read. c++filt reverses this process.

If no names are given on the command line, c++filt reads them from the standard input.

OPTIONS

This utility accepts the following options:

-h, --help
Display a help message and exit.
-v, --version
Display version information and exit.
