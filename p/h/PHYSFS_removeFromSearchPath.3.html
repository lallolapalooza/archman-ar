DESCRIPTION

The PhysicsFS library provides an abstract layer of read/write access to data. This is a very common need in games, where data is often stored in archives.

This library is designed to be cross-platform. It is intended to be used with C or C++ code. It should be compatible with any system that has a C compiler and a POSIX-like environment.

File Access

The core of PhysicsFS is file access. The functions PHYSFS_open(), PHYSFS_close(), PHYSFS_read(), PHYSFS_write(), PHYSFS_eof(), PHYSFS_tell(), and PHYSFS_seek() provide basic file I/O operations. You can use these functions to read and write files from the underlying operating system, or from any archives that have been mounted.

The _real versions of these functions bypass PhysicsFS's file abstraction layer and perform operations directly on the underlying operating system's file system.

PHYSFS_tell64() and PHYSFS_seek64() provide 64-bit file offset support.

There are also functions for reading and writing data in various endian formats:

  • PHYSFS_readLE16(), PHYSFS_writeLE16() read/write 16-bit little-endian values.
  • PHYSFS_readBE16(), PHYSFS_writeBE16() read/write 16-bit big-endian values.
  • PHYSFS_readLE32(), PHYSFS_writeLE32() read/write 32-bit little-endian values.
  • PHYSFS_readBE32(), PHYSFS_writeBE32() read/write 32-bit big-endian values.
  • PHYSFS_readLE64(), PHYSFS_writeLE64() read/write 64-bit little-endian values.
  • PHYSFS_readBE64(), PHYSFS_writeBE64() read/write 64-bit big-endian values.

The _real versions of these functions are provided for completeness, but they are not intended for general use.

Swap functions are provided to convert values between little-endian and the platform's native byte order:

  • PHYSFS_swapSLE16() swaps a signed 16-bit little-endian value.
  • PHYSFS_swapULE16() swaps an unsigned 16-bit little-endian value.
  • PHYSFS_swapSBE16() swaps a signed 16-bit big-endian value.

Initialization and Configuration

Before using any PhysicsFS functions, you must initialize the library using PHYSFS_init(). When you are done, you should call PHYSFS_deinit().

You can check if PhysicsFS is initialized using PHYSFS_isInit().

PHYSFS_symbolicLinksPermitted() tells you whether symbolic links are allowed to be followed.

You can replace PhysicsFS's default memory allocation routines with your own by calling PHYSFS_setAllocator(). The current allocator can be queried with PHYSFS_getAllocator().

PHYSFS_registerArchiver() and PHYSFS_deregisterArchiver() allow you to add or remove support for new archive formats.

PHYSFS_setRoot() allows you to treat a subdirectory of an archive as its root directory.

Mounting Archives

PhysicsFS uses a search path to find files. You can add directories and archives to this search path using PHYSFS_mount().

You can also mount archives directly from I/O structures (PHYSFS_mountIo()), memory buffers (PHYSFS_mountMemory()), or file handles (PHYSFS_mountHandle()).

You can find out which mount point a given directory belongs to using PHYSFS_getMountPoint().

To iterate over the search path, use PHYSFS_getSearchPathCallback(). To iterate over files in a directory, use PHYSFS_enumerateFilesCallback() or PHYSFS_enumerate().

To remove a directory or archive from the search path, use PHYSFS_unmount().

Directory Handling

PHYSFS_getCdRomDirsCallback() enumerates the directories on CD-ROMs.

PHYSFS_getPrefDir() returns the path to a user-and-app-specific directory where preference files can be stored.

PHYSFS_stat() retrieves information about a file or directory.

String Conversion

PhysicsFS provides functions for converting strings between various Unicode formats and UTF-8:

  • PHYSFS_utf8FromUcs4(), PHYSFS_utf8ToUcs4() convert between UTF-8 and UCS-4.
  • PHYSFS_utf8FromUcs2(), PHYSFS_utf8ToUcs2() convert between UTF-8 and UCS-2.
  • PHYSFS_utf8FromLatin1() converts from Latin-1 to UTF-8.
  • PHYSFS_utf8FromUtf16(), PHYSFS_utf8ToUtf16() convert between UTF-8 and UTF-16.

The _real versions of these functions are provided for completeness, but they are not intended for general use.

Case-insensitive string comparisons are provided for UTF-8, UTF-16, and UCS-4 strings:

  • PHYSFS_utf8stricmp()
  • PHYSFS_utf16stricmp()
  • PHYSFS_ucs4stricmp()

PHYSFS_caseFold() converts a Unicode codepoint to its lowercase equivalent.

Error Handling

You can get the last error code using PHYSFS_getLastErrorCode(). A human-readable string describing the error can be obtained using PHYSFS_getErrorByCode(). You can also set the current thread's error code using PHYSFS_setErrorCode().

int PHYSFS_enumerate (const char * dir, PHYSFS_EnumerateCallback c, void * d)

Get a file listing of a search path's directory, using an application-defined callback, with errors reported. Internally, PHYSFS_enumerateFiles() just calls this function and then builds a list before returning to the application, so functionality is identical except for how the information is represented to the application.

Unlike PHYSFS_enumerateFiles(), this function does not return an array. Rather, it calls a function specified by the application once per element of the search path:

static PHYSFS_EnumerateCallbackResult printDir(void *data, const char *origdir, const char *fname)
{
    printf(" * We've got [%s] in [%s].\n", fname, origdir);
    return PHYSFS_ENUM_OK;  // give me more data, please.
}
// ...
PHYSFS_enumerate("/some/path", printDir, NULL);

Items sent to the callback are not guaranteed to be in any order whatsoever. There is no sorting done at this level, and if you need that, you should probably use PHYSFS_enumerateFiles() instead, which guarantees alphabetical sorting. This form reports whatever is discovered in each archive before moving on to the next. Even within one archive, we can't guarantee what order it will discover data. Any sorting you find in these callbacks is just pure luck. Do not rely on it. As this walks the entire list of archives, you may receive duplicate filenames.

This API and the callbacks themselves are capable of reporting errors. Prior to this API, callbacks had to accept every enumerated item, even if they were only looking for a specific thing and wanted to stop after that, or had a serious error and couldn't alert anyone. Furthermore, if PhysicsFS itself had a problem (disk error or whatnot), it couldn't report it to the calling app, it would just have to skip items or stop enumerating outright, and the caller wouldn't know it had lost some data along the way.

Now the caller can be sure it got a complete data set, and its callback has control if it wants enumeration to stop early. See the documentation for PHYSFS_EnumerateCallback for details on how your callback should behave.

dir Directory, in platform-independent notation, to enumerate.
c Callback function to notify about search path elements.
d Application-defined data passed to callback. Can be NULL.

Returns

non-zero on success, zero on failure. Use PHYSFS_getLastErrorCode() to obtain the specific error. If the callback returns PHYSFS_ENUM_STOP to stop early, this will be considered success. Callbacks returning PHYSFS_ENUM_ERROR will make this function return zero and set the error code to PHYSFS_ERR_APP_CALLBACK.

char ** PHYSFS_enumerateFiles (const char * dir)

Get a file listing of a search path's directory.

Warning

In PhysicsFS versions prior to 2.1, this function would return as many items as it could in the face of a failure condition (out of memory, disk i/o error, etc). Since this meant apps couldn't distinguish between complete success and partial failure, and since the function could always return NULL to report catastrophic failures anyway, in PhysicsFS 2.1 this function's policy changed: it will either return a list of complete results or it will return NULL for any failure of any kind, so we can guarantee that the enumeration ran to completion and has no gaps in its results.

Matching directories are interpolated. That is, if "C:\mydir" is in the search path and contains a directory "savegames" that contains "x.sav", "y.sav", and "z.sav", and there is also a "C:\userdir" in the search path that has a "savegames" subdirectory with "w.sav", then the following code:

char **rc = PHYSFS_enumerateFiles("savegames");
char **i;
for (i = rc; *i != NULL; i++)
    printf(" * We've got [%s].\n", *i);
PHYSFS_freeList(rc);
* We've got [x.sav].
* We've got [y.sav].
* We've got [z.sav].
* We've got [w.sav]..fi
Feel free to sort the list however you like. However, the returned data will always contain no duplicates, and will be always sorted in alphabetic (rather: case-sensitive Unicode) order for you.
Don't forget to call PHYSFS_freeList() with the return value from this function when you are done with it.

void PHYSFS_utf8ToUtf16 (const char * src, PHYSFS_uint16 * dst, PHYSFS_uint64 len)

تحويل سلسلة UTF-8 إلى سلسلة UTF-16.

تحذير

لن تقوم هذه الدالة بالإبلاغ عن خطأ إذا كانت هناك تسلسلات غير صالحة في سلسلة الإدخال. ستقوم باستبدالها بحرف '؟' والمتابعة.

سلاسل UTF-16 لديها 16 بت لكل حرف (باستثناء بعض الأحرف، التي تكون 32 بت): TCHAR في Windows، عند تجميعها مع دعم Unicode. تستخدم إصدارات Windows الحديثة UTF-16. استخدمت إصدارات Windows القديمة قبل عام 2000 TCHAR، لكنها تعاملت فقط مع UCS-2. UTF-16 *هو* UCS-2، باستثناء الأحرف التي تكون 4 بايت، والتي لا يمكن تمثيلها في UCS-2 على الإطلاق. إذا لم تكن متأكدًا، يجب عليك استخدام UTF-16 في هذا الوقت في Windows.

لضمان أن يكون المخزن المؤقت الوجهة كبيرًا بما يكفي للتحويل، يرجى تخصيص مخزن مؤقت بحجم مضاعف لحجم المخزن المؤقت للإدخال. يستخدم UTF-8 من 1 إلى 4 بايت لكل حرف، لكن UTF-16 يستخدم دائمًا من 2 إلى 4 بايت، لذلك ستتضاعف حجم السلسلة النصية ASCII بالكامل. الأحرف UTF-16 التي تتطلب 4 بايت تستخدم أيضًا 4 بايت في UTF-8، لذلك لا تحتاج إلى تخصيص 4 أضعاف المساحة، فقط الضعف.

سيتم اقتطاع السلاسل التي لا تناسب المخزن المؤقت الوجهة، ولكنها ستنتهي دائمًا بحرف فارغ ولن يكون لديها زوج بديل غير مكتمل في النهاية. إذا كان طول المخزن المؤقت 0، فلن تقوم هذه الدالة بأي شيء.
