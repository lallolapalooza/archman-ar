typedef void(* PHYSFS_EnumFilesCallback) (void *data, const char *origdir, const char *fname)

Function signature for callbacks that enumerate files.

Warning

As of PhysicsFS 2.1, Use PHYSFS_EnumerateCallback with PHYSFS_enumerate() instead; it gives you more control over the process.

These are used to report a list of directory entries to an original caller, one file/dir/symlink per callback. All strings are UTF-8 encoded. Functions should not try to modify or free any string's memory.

These callbacks are used, starting in PhysicsFS 1.1, as an alternative to functions that would return lists that need to be cleaned up with PHYSFS_freeList(). The callback means that the library doesn't need to allocate an entire list and all the strings up front.

Be aware that promised data ordering in the list versions are not necessarily so in the callback versions. Check the documentation on specific APIs, but strings may not be sorted as you expect and you might get duplicate strings.

Parameters

data User-defined data pointer, passed through from the API that eventually called the callback.
origdir A string containing the full path, in platform-independent notation, of the directory containing this file. In most cases, this is the directory on which you requested enumeration, passed in the callback for your convenience.
fname The filename that is being enumerated. It may not be in alphabetical order compared to other callbacks that have fired, and it will not contain the full path. You can recreate the fullpath with $origdir/$fname ... The file can be a subdirectory, a file, a symlink, etc.

enum PHYSFS_ErrorCode

Values that represent specific causes of failure. Most of the time, you should only concern yourself with whether a given operation failed or not, but there may be occasions where you plan to handle a specific failure case gracefully, so we provide specific error codes.

Most of these errors are a little vague, and most aren't things you can fix...if there's a permission error, for example, all you can really do is pass that information on to the user and let them figure out how to handle it. int PHYSFS_enumerate (const char * dir, PHYSFS_EnumerateCallback c, void * d)

الحصول على قائمة بالملفات من مجلد في مسار البحث، باستخدام رد اتصال محدد بواسطة المستخدم، مع الإبلاغ عن الأخطاء. داخليًا، PHYSFS_enumerateFiles() يستدعي هذه الوظيفة فقط ثم يبني قائمة قبل العودة إلى التطبيق، لذلك الوظيفة متطابقة باستثناء كيفية تقديم المعلومات إلى التطبيق.

على عكس PHYSFS_enumerateFiles()، لا تعيد هذه الوظيفة مصفوفة. بدلاً من ذلك، تستدعي وظيفة محددة بواسطة مقدم الطلب مرة واحدة لكل عنصر في مسار البحث:

static physFS_EnumerateCallbackResult printDir(void *data, const char *origdir, const char *fname)
{
    printf(" * We've got [%s] in [%s].\n", fname, origdir);
    return PHYSFS_ENUM_OK;  // أعطني المزيد من البيانات، من فضلك.
}
// ...
PHYSFS_enumerate("/some/path", printDir, NULL);

العناصر المرسلة إلى رد الاتصال غير مضمونة لتكون بأي ترتيب. لا يتم إجراء أي فرز على هذا المستوى، وإذا كنت بحاجة إليه، يجب عليك استخدام PHYSFS_enumerateFiles()، التي تضمن الترتيب الأبجدي. هذا الشكل يبلغ عن ما هو موجود في كل ملف مؤرشف قبل الانتقال إلى التالي. حتى داخل أرشيف واحد، لا يمكننا ضمان ترتيب اكتشاف البيانات. أي ترتيب تجده في ردود الاتصال هذه هو مجرد حظ. لا تعتمد عليه. نظرًا لأن هذه الوظيفة تمر عبر كل قائمة مؤرشفة، فقد تتلقى أسماء ملفات مكررة.

هذه الواجهة وبرامج رد الاتصال نفسها قادرة على الإبلاغ عن الأخطاء. قبل هذه الواجهة، كان على برامج رد الاتصال قبول كل عنصر تم تعداده، حتى لو كانوا يبحثون فقط عن عنصر معين ويرغبون في التوقف بعد ذلك، أو لديهم خطأ فادح ولم يتمكنوا من تنبيه أي شخص. بالإضافة إلى ذلك، إذا كان لدى PhysicsFS نفسه مشكلة (خطأ في القرص أو أي شيء آخر)، لم يتمكن من إبلاغ التطبيق المتصل، فسوف يتجاهل ببساطة العناصر أو يوقف التعداد، ولن يعرف المتصل أنه فقد بعض البيانات على طول الطريق.

الآن يمكن للمتصل أن يكون متأكدًا من أنه حصل على مجموعة كاملة من البيانات، وإذا رغب في ذلك، فإن برنامج رد الاتصال الخاص به يتحكم فيما إذا كان سيوقف التعداد مبكرًا. راجع الوثائق الخاصة بـ PHYSFS_EnumerateCallback للحصول على تفاصيل حول كيفية سلوك برنامج رد الاتصال الخاص بك.

المعلمات

dir المجلد المراد تعداده، بتنسيق مستقل عن النظام.
c وظيفة رد اتصال لإعلام العناصر المسار.
d بيانات محددة بواسطة مقدم الطلب يتم تمريرها إلى رد الاتصال. يمكن أن تكون NULL.

العودة

غير صفر عند النجاح، صفر عند الخطأ. استخدم PHYSFS_getLastErrorCode() للحصول على الخطأ المحدد. إذا أعاد رد الاتصال PHYSFS_ENUM_OK، فسيتم اعتبار هذا نجاحًا. إذا أعاد رد الاتصال PHYSFS_ENUM_STOP، فسيتم اعتبار هذا نجاحًا. برامج رد الاتصال التي تعيد PHYSFS_ENUM_ERROR ستجعل هذه الوظيفة تعود بصفر وتعيين رمز الخطأ إلى PHYSFS_ERR_APP_CALLBACK.

تحذير

في الإصدارات السابقة من PhysicsFS (قبل 2.1)، كانت هذه الوظيفة تعيد أكبر عدد ممكن من العناصر في حالة الفشل (خطأ في الذاكرة، قراءة/كتابة على القرص، إلخ). نظرًا لأن هذا يعني أن مقدمي الطلبات لم يتمكنوا من التمييز بين النجاح الكامل والفشل الجزئي، وبما أن الوظيفة يمكنها دائمًا إرجاع NULL للإبلاغ عن فشل كارثي، فقد تغيرت هذه السياسة في PhysicsFS 2.1: ستعيد قائمة كاملة من النتائج أو NULL في حالة أي فشل، حتى نتمكن من ضمان اكتمال التعداد وعدم وجود فجوات في نتائجك.

يتم استيفاء المجلدات المطابقة. أي، إذا كان "C:\mydir" موجودًا في مسار البحث ويحتوي على مجلد "savegames" يحتوي على "x.sav"، "y.sav" و "z.sav"، وهناك أيضًا مجلد "C:\userdir" في مسار البحث مع مجلد فرعي "savegames" يحتوي على "w.sav"، فإن الكود التالي:

char **rc = PHYSFS_enumerateFiles("savegames");
char **i;
for (i = rc; *i != NULL; i++)
    printf(" * We've got [%s].\n", *i);
PHYSFS_freeList(rc);
* We've got [x.sav].
* We've got [y.sav].
* We've got [z.sav].
* We've got [w.sav].
لا تتردد في فرز القائمة كما تشاء. ومع ذلك، فإن البيانات المعادة ستحتوي دائمًا على عدم وجود تكرارات، وسيتم فرزها دائمًا بترتيب أبجدي (أو بالأحرى: حساسية حالة أحرف يونيكود) لك.

لا تنس استدعاء PHYSFS_freeList() بالقيمة المعادة من هذه الوظيفة عندما تنتهي منها.

العودة

مصفوفة سلاسل نصية منتهية بـ NULL وسلاسل نصية منتهية بـ NULL، أو NULL في حالة الفشل.

يتم فحص الروابط الرمزية بشكل صريح فقط عند التعامل مع أسماء الملفات بتدوين مستقل عن النظام الأساسي. أي، عند إعداد مسارات البحث والكتابة الخاصة بك، وما إلى ذلك، لا يتم فحص الروابط الرمزية مطلقًا.

يرجى ملاحظة أن PHYSFS_stat() ستقوم دائمًا بفحص المسار المحدد؛ إذا كان هذا المسار رابطًا رمزيًا، فلن يتم اتباعه في أي حال. إذا لم يتم السماح بالروابط الرمزية من خلال هذه الدالة، فإن PHYSFS_stat() تتجاهلها، وستعامل الاستعلام كما لو كان المسار غير موجود على الإطلاق.

يمكن تمكين أو تعطيل إذن الروابط الرمزية في أي وقت بعد استدعاء PHYSFS_init()، وهي معطلة افتراضيًا.

المعاملات

int PHYSFS_strcasecmp (const char * str1, const char * str2)

Case-insensitive compare of two null-terminated strings. This is a strcasecmp/stricmp replacement. This function expects strings in your system's native character encoding.

It will report which string is "greater than" the other, but be aware that this doesn't necessarily mean anything: 'a' may be "less than" 'b', but a Japanese kuten has no meaningful alphabetically relationship to a Greek lambda, but being able to assign a reliable "value" makes sorting algorithms possible, if not entirely sane. void PHYSFS_utf8FromLatin1 (const char * src, char * dst, PHYSFS_uint64 len)

Convert a Latin1 string to a UTF-8 string. Latin1 strings are 8-bits per character: a popular "high ASCII" encoding.

To ensure that the destination buffer is large enough for the conversion, please allocate a buffer that is double the size of the source buffer. UTF-8 expands latin1 codepoints over 127 from 1 to 2 bytes, so the string may grow in some cases.

Strings that don't fit in the destination buffer will be truncated, but will always be null-terminated and never have an incomplete UTF-8 sequence at the end. If the buffer length is 0, this function does nothing.

Please note that we do not supply a UTF-8 to Latin1 converter, since Latin1 can't express most Unicode codepoints. It's a legacy encoding; you should be converting away from it at all times.

Parameters

src Null-terminated source string in Latin1 format.
dst Buffer to store converted UTF-8 string.
len Size, in bytes, of destination buffer.
