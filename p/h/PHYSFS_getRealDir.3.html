هذا هو نفس الشيء مثل PHYSFS_EnumFilesCallback من PhysicsFS 2.0، باستثناء أنه يمكن أن يرجع نتيجة من المكالمة: وهو: إذا كنت تبحث عن شيء معين، بمجرد العثور عليه، يمكنك إخبار PhysicsFS بالتوقف عن السرد الإضافي. يستخدم هذا مع PHYSFS_enumerate()، والذي نأمل أن نكون قد حصلنا عليه بشكل صحيح هذه المرة. :)

المعلمات

data مؤشر بيانات معرف من قبل المستخدم، يتم تمريره من الواجهة التي استدعت المكالمة في النهاية.
origdir سلسلة نصية تحتوي على المسار الكامل، بتدوين مستقل عن النظام الأساسي، للدليل الذي يحتوي على هذا الملف. في معظم الحالات، هذا هو الدليل الذي طلبت السرد منه، يتم تمريره في المكالمة لراحتك.
fname اسم الملف الذي يتم سرده. قد لا يكون بترتيب أبجدي مقارنة بالمكالمات الأخرى التي تم تشغيلها، ولن يحتوي على المسار الكامل. يمكنك إعادة إنشاء المسار الكامل باستخدام $origdir/$fname ... يمكن أن يكون الملف دليلًا فرعيًا، أو ملفًا، أو رابطًا رمزيًا، وما إلى ذلك.

قيمة من PHYSFS_EnumerateCallbackResult. جميع القيم الأخرى غير محددة (حاليًا)؛ لا تستخدمها.

تحذير

اعتبارًا من PhysicsFS 2.1، استخدم PHYSFS_EnumerateCallback مع PHYSFS_enumerate() بدلاً من ذلك؛ فهو يمنحك المزيد من التحكم في العملية.

تستخدم هذه لسرد قائمة مدخلات الدليل إلى المتصل الأصلي، ملف/دليل/رابط رمزي واحد لكل مكالمة. جميع السلاسل النصية مشفرة بتنسيق UTF-8. يجب ألا تحاول الدوال تعديل أو تحرير ذاكرة أي سلسلة نصية.

تستخدم هذه المكالمات، بدءًا من PhysicsFS 1.1، كبديل للدوال التي ترجع قوائم تحتاج إلى تنظيف باستخدام PHYSFS_freeList(). المكالمة تعني أن المكتبة لا تحتاج إلى تخصيص قائمة كاملة وجميع السلاسل النصية مسبقًا.

Get the currently used allocator. This can be useful for apps that want to access PhysicsFS's internal, default allocation routines, as well as for external code that wants to share the same allocator, even if the application specified their own.

As of PhysicsFS 2.1, this function has been nerfed. Before PhysicsFS 2.1, this function was the only way to get error details beyond a given function's basic return value. This was meant to be a human-readable string in one of several languages, and was not useful for application parsing. This was a problem, because the developer and not the user chose the language at compile time, and the PhysicsFS maintainers had to (poorly) maintain a significant amount of localization work. The app couldn't parse the strings, even if they counted on a specific language, since some were dynamically generated. In 2.1 and later, this always returns a static string in English; you may use it as a key string for your own localizations if you like, as we'll promise not to change existing error strings. Also, if your application wants to look at specific errors, we now offer a better option: use PHYSFS_getLastErrorCode() instead.

Get the last PhysicsFS error message as a human-readable, null-terminated string. This will return NULL if there's been no error since the last call to this function. The pointer returned by this call points to an internal buffer. Each thread has a unique error state associated with it, but each time a new error message is set, it will overwrite the previous one associated with that thread. It is safe to call this function at anytime, even before PHYSFS_init().

PHYSFS_getLastError() and PHYSFS_getLastErrorCode() both reset the same thread-specific error state. Calling one will wipe out the other's data. If you need both, call PHYSFS_getLastErrorCode(), then pass that value to PHYSFS_getErrorByCode().

As of PhysicsFS 2.1, this function only presents text in the English language, but the strings are static, so you can use them as keys into your own localization dictionary. These strings are meant to be passed on directly to the user.

Generally, applications should only concern themselves with whether a given function failed; however, if your code require more specifics, you should use PHYSFS_getLastErrorCode() instead of this function.

تمكين أو تعطيل اتباع الروابط الرمزية. تحتوي بعض أنظمة الملفات المادية والأرشيفات على ملفات هي مجرد مؤشرات لملفات أخرى. في نظام الملفات المادي، سيؤدي فتح مثل هذا الرابط إلى فتح (بشفافية) الملف الذي يشير إليه.

بشكل افتراضي، سيتحقق PhysicsFS مما إذا كان الملف رابطًا رمزيًا بالفعل أثناء استدعاءات الفتح ويفشل إذا كان كذلك. خلاف ذلك، يمكن للرابط أن يخرجك من مسارات الكتابة والبحث، ويقوض الأمان.

إذا كنت ترغب في تحمل هذا الخطر، استدع هذه الوظيفة بمعامل غير صفري. لاحظ أن هذا يتعلق بشكل أكبر بتأمين لغة برمجة البرنامج النصي، في حالة محاولة البرامج النصية غير الموثوق بها تقويض النظام. بشكل عام، يمكن للمستخدم أن يكون لديه سبب مشروع لإعداد رابط رمزي، لذلك ما لم تشعر أن هناك خطرًا محددًا في السماح بها، يجب عليك السماح بها.

يتم فحص الروابط الرمزية بشكل صريح فقط عند التعامل مع أسماء الملفات بالترميز المستقل عن النظام الأساسي. وهذا يعني، عند إعداد مسارات البحث والكتابة الخاصة بك، وما إلى ذلك، لا يتم فحص الروابط الرمزية مطلقًا.

يرجى ملاحظة أن PHYSFS_stat() سيتحقق دائمًا من المسار المحدد؛ إذا كان هذا المسار رابطًا رمزيًا، فلن يتم اتباعه في أي حال. إذا لم تسمح الروابط الرمزية من خلال هذه الوظيفة، فإن PHYSFS_stat() يتجاهلها، وسيعامل الاستعلام كما لو كان المسار غير موجود على الإطلاق.

يمكن تمكين أو تعطيل إذن الروابط الرمزية في أي وقت بعد استدعاء PHYSFS_init()، وهو معطل بشكل افتراضي.

int PHYSFS_setRoot (const char * archive, const char * subdir)

Establece un subdirectorio de un archivo como su directorio raíz. Esto te permite restringir los archivos accesibles dentro de un archivo específico. Por ejemplo, si tienes x.zip con un archivo en y/z.txt, montado en /a, si llamas a PHYSFS_setRoot("x.zip", "/y"), entonces la llamada a PHYSFS_openRead("/a/z.txt") tendrá éxito.

Puedes cambiar el directorio raíz de un archivo en cualquier momento, alterando el árbol de archivos interpolado (dependiendo de dónde se desplacen las rutas, un archivo diferente podría proporcionar archivos diferentes). Si estableces el directorio raíz a NULL o "/", el archivo se tratará como si no se hubiera especificado ningún directorio raíz especial (como si el archivo se hubiera montado normalmente).

Cambiar el directorio raíz solo afecta a las operaciones futuras en las rutas de archivos; un archivo que se abrió desde una ruta que cambió debido a un setRoot no se verá afectado.

Establecer un nuevo directorio raíz no se limita a los archivos en la ruta de búsqueda; puedes establecerlo en el directorio de escritura, lo que podría ser útil si tienes archivos abiertos en escritura y no puedes cambiar el directorio de escritura en este momento.

Es inofensivo establecer un subdirectorio que no exista como directorio raíz de un archivo; sin embargo, en ese caso, no se verán archivos. Si los directorios faltantes terminan siendo creados (una mkdir en el sistema de archivos físico, etc.), esto se reflejará en el árbol de archivos interpolado.

archive El directorio/archivo en el cual se cambia el directorio raíz.
subdir El nuevo directorio a ser el directorio raíz de este archivo.

Retorna

Distinto de cero en caso de éxito, cero en caso de error. Usa PHYSFS_getLastErrorCode() para obtener el error específico.

  • La carpeta base (PHYSFS_getBaseDir())

تحذير

لن تقوم هذه الوظيفة بالإبلاغ عن خطأ إذا كانت هناك تسلسلات UTF-8 غير صالحة في سلسلة المصدر. ستقوم باستبدالها بحرف '؟' وتستمر.

سلاسل UTF-16 هي 16 بت لكل حرف (باستثناء بعض الأحرف، التي هي 32 بت): TCHAR على Windows، عند البناء بدعم Unicode. الإصدارات الحديثة من Windows تستخدم UTF-16. الإصدارات القديمة من Windows قبل عام 2000 استخدمت TCHAR، ولكنها دعمت فقط UCS-2. UTF-16 * هو * UCS-2، باستثناء الأحرف التي تتكون من 4 بايت، والتي لا يمكن تمثيلها في UCS-2 على الإطلاق. إذا لم تكن متأكدًا، فيجب عليك استخدام UTF-16 في هذه المرحلة على Windows.

للتأكد من أن المخزن المؤقت الوجهة كبير بما يكفي للتحويل، يرجى تخصيص مخزن مؤقت بحجم ضعف حجم المخزن المؤقت المصدر. يستخدم UTF-8 من بايت واحد إلى أربعة بايتات لكل حرف، ولكن UTF-16 يستخدم دائمًا من اثنين إلى أربعة، لذا ستتضاعف سلسلة ASCII المنخفضة بالكامل في الحجم! أحرف UTF-16 التي تتطلب أربعة بايتات تأخذ أيضًا أربعة بايتات في UTF-8، لذلك لا تحتاج إلى تخصيص 4 أضعاف المساحة كاحتياط: مضاعفة المساحة كافية.

سيتم اقتطاع السلاسل التي لا تتناسب مع المخزن المؤقت الوجهة، ولكنها ستكون دائمًا منتهية بـ null ولن تحتوي أبدًا على زوج بديل UTF-16 غير مكتمل في النهاية. إذا كان طول المخزن المؤقت 0، فلن تقوم هذه الوظيفة بأي شيء.

NAME

PHYSFS_writeUBE16, PHYSFS_writeUBE32, PHYSFS_writeUBE64, PHYSFS_writeULE16, PHYSFS_writeULE32, PHYSFS_writeULE64 - convert and write an unsigned big-endian or little-endian value.

LIBRARY

PhysicsFS API library (libphysfs).

SYNOPSIS

#include <physfs.h>

int PHYSFS_writeUBE32(PHYSFS_File * file, PHYSFS_uint32 val);

int PHYSFS_writeULE32(PHYSFS_File * file, PHYSFS_uint32 val);

DESCRIPTION

These functions convert a value from the platform's native byte order to the specified endianness (big-endian or little-endian) and write it to the given file.

These are convenience functions. They are equivalent to calling PHYSFS_write*BE16, PHYSFS_write*BE32, or PHYSFS_write*BE64, respectively.

The functions are:

  • PHYSFS_writeUBE16, PHYSFS_writeUBE32, PHYSFS_writeUBE64: Write an unsigned 16-bit, 32-bit, or 64-bit big-endian value.
  • PHYSFS_writeULE16, PHYSFS_writeULE32, PHYSFS_writeULE64: Write an unsigned 16-bit, 32-bit, or 64-bit little-endian value.
