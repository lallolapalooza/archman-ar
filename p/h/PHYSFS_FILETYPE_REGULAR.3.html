DESCRIPTION

The PhysicsFS library provides an abstraction layer over a data storage system. It allows you to treat archives (like ZIP files, RAR files, etc.) and directories as if they were a single, unified file system. This can be very useful for games and other applications that need to load resources from various locations.

The library provides functions for initializing and shutting down the system, mounting and unmounting archives and directories, enumerating files, reading and writing data, and handling byte order conversions.

Here's a breakdown of the function categories:

Byte Order Conversion:

These functions are used to convert byte orders between little-endian and big-endian formats, and the platform's native byte order. This is crucial when dealing with data files that may have been created on systems with different endianness.

PHYSFS_swapSLE16, PHYSFS_swapULE16, PHYSFS_swapSLE32, PHYSFS_swapULE32, PHYSFS_swapSLE64, PHYSFS_swapULE64:
Swap little-endian signed and unsigned 16, 32, and 64-bit integers to the platform's native byte order.
PHYSFS_swapSBE16, PHYSFS_swapUBE16, PHYSFS_swapSBE32, PHYSFS_swapUBE32, PHYSFS_swapSBE64, PHYSFS_swapUBE64:
Swap big-endian signed and unsigned 16, 32, and 64-bit integers to the platform's native byte order.
File Reading and Writing:

These functions provide a way to read and write data from/to PhysicsFS file handles, automatically handling byte order conversions if necessary.

PHYSFS_readSLE16, PHYSFS_readULE16, PHYSFS_readSBE16, PHYSFS_readUBE16, PHYSFS_readSLE32, PHYSFS_readULE32, PHYSFS_readSBE32, PHYSFS_readUBE32, PHYSFS_readSLE64, PHYSFS_readULE64, PHYSFS_readSBE64, PHYSFS_readUBE64:
Read and convert signed/unsigned 16, 32, or 64-bit little-endian or big-endian values from a file.
PHYSFS_writeSLE16, PHYSFS_writeULE16, PHYSFS_writeSBE16, PHYSFS_writeUBE16, PHYSFS_writeSLE32, PHYSFS_writeULE32, PHYSFS_writeSBE32, PHYSFS_writeUBE32, PHYSFS_writeSLE64, PHYSFS_writeULE64, PHYSFS_writeSBE64, PHYSFS_writeUBE64:
Convert and write signed/unsigned 16, 32, or 64-bit little-endian or big-endian values to a file.
PHYSFS_readBytes, PHYSFS_writeBytes:
Read and write raw bytes from/to a PhysicsFS file handle.
Initialization and Shutdown:

These functions manage the lifecycle of the PhysicsFS library.

PHYSFS_init:
Initializes the PhysicsFS library. This function must be called before any other PhysicsFS function. It takes the program name as an argument, which may be used for determining platform-specific configuration paths.
PHYSFS_deinit:
Shuts down the PhysicsFS library and frees any allocated resources. This should be called before your program exits.
PHYSFS_isInit:
Determines if the PhysicsFS library has been initialized.
Mounting and Search Path:

These functions allow you to add and remove archives and directories to the PhysicsFS search path, effectively defining the locations where PhysicsFS will look for files.

PHYSFS_mount:
Adds a directory or archive file to the search path. The `appendToPath` parameter determines whether it's added to the beginning or end of the path.
PHYSFS_mountIo:
Adds an archive built on a `PHYSFS_Io` interface to the search path. This allows for custom archive formats or data loaded from non-standard sources.
PHYSFS_mountMemory:
Adds an archive contained in a memory buffer to the search path. This is useful for archives that are loaded entirely into memory.
PHYSFS_mountHandle:
Adds an archive contained in a `PHYSFS_File` handle to the search path. This allows mounting archives that are already opened by PhysicsFS.
PHYSFS_unmount:
Removes a directory or archive from the search path.
PHYSFS_getMountPoint:
Retrieves the mount point for a given directory or archive in the search path.
PHYSFS_getCdRomDirsCallback:
Enumerates directories that are typically found on CD-ROMs, using a callback function. This is often used for game data.
PHYSFS_getSearchPathCallback:
Enumerates all directories and archives currently in the PhysicsFS search path, using a callback function.
File Enumeration and Information:

These functions allow you to list the contents of directories within the PhysicsFS search path and retrieve information about files.

PHYSFS_enumerateFilesCallback:
Gets a file listing of a directory within the search path, using a callback function to process each file found.
PHYSFS_enumerate:
Similar to `PHYSFS_enumerateFilesCallback`, but also reports errors during enumeration.
PHYSFS_stat:
Retrieves information about a file or directory, such as its size, modification time, and type (regular file, directory, etc.).
String Conversion and Comparison:

These functions handle conversions between different character encodings (UTF-8, UCS-2, UCS-4, Latin1) and provide case-insensitive string comparison functions.

PHYSFS_utf8FromUcs4, PHYSFS_utf8ToUcs4:
Convert between UCS-4 and UTF-8 encoded strings.
PHYSFS_utf8FromUcs2, PHYSFS_utf8ToUcs2:
Convert between UCS-2 and UTF-8 encoded strings.
PHYSFS_utf8FromLatin1:
Convert from Latin1 to UTF-8 encoded strings.
PHYSFS_utf8FromUtf16, PHYSFS_utf8ToUtf16:
Convert between UTF-16 and UTF-8 encoded strings.
PHYSFS_caseFold:
Performs a case-folding operation on a Unicode codepoint, converting it to its lowercase equivalent.
PHYSFS_utf8stricmp, PHYSFS_utf16stricmp, PHYSFS_ucs4stricmp:
Case-insensitive comparison of strings in UTF-8, UTF-16, and UCS-4 encodings, respectively.
Allocator and Error Handling:

These functions allow customization of memory allocation and provide access to error information.

PHYSFS_setAllocator:
Allows you to hook your own memory allocation routines (malloc, free, etc.) into PhysicsFS.
PHYSFS_getAllocator:
Retrieves the currently active memory allocator used by PhysicsFS.
PHYSFS_getLastErrorCode:
Returns the last error code that occurred in the current thread.
PHYSFS_getErrorByCode:
Returns a human-readable string description for a given error code.
PHYSFS_setErrorCode:
Sets the current thread's error code.
Preference Directory:

PHYSFS_getPrefDir:

Retrieves the user-and-application-specific path where files can be written. This is typically used for saving configuration files or user data.
Archiver Registration:

PHYSFS_registerArchiver, PHYSFS_deregisterArchiver:

These functions allow you to add support for new archive formats to PhysicsFS or remove existing ones.
Root Directory:

PHYSFS_setRoot:

Allows you to designate a subdirectory within an archive as the root directory for subsequent operations. This can be useful when an archive contains multiple sub-projects or data sets.

char ** PHYSFS_getCdRomDirs(void)

Get an array of paths to available CD-ROM drives. The dirs returned are platform-dependent ("D:\" on Win32, "/cdrom" or whatnot on Unix). Dirs are only returned if there is a disc ready and accessible in the drive. So if you've got two drives (D: and E:), and only E: has a disc in it, then that's all you get. If the user inserts a disc in D: and you call this function again, you get both drives. If, on a Unix box, the user unmounts a disc and remounts it elsewhere, the next call to this function will reflect that change.This function refers to "CD-ROM" media, but it really means "inserted disc media," such as DVD-ROM, HD-DVD, CDRW, and Blu-Ray discs. It looks for filesystems, and as such won't report an audio CD, unless there's a mounted filesystem track on it.The returned value is an array of strings, with a NULL entry to signify the end of the list: 

char **cds = PHYSFS_getCdRomDirs();
char **i;
for (i = cds; *i != NULL; i++)
    printf("cdrom dir [s] is available.\n", *i);

PHYSFS_freeList(cds);

This call may block while drives spin up. Be forewarned.

تحذير

هذا أمر متقدم وصعب. لا تحتاج إليه إلا إذا كنت تعرف حقًا ما تفعله. معظم التطبيقات لن تحتاج إليه.

إذا كنت تريد توفير مستودع أرشيف خاص بك (على سبيل المثال، تنسيق ملف أرشيف مخصص، أو شيء افتراضي تريد أن يبدو كنظام ملفات يمكنك الوصول إليه من خلال واجهات برمجة تطبيقات PhysicsFS العادية)، فهذه هي نقطة البداية. بمجرد تسجيل مستودع الأرشيف بنجاح، يمكنك بعد ذلك استخدام PHYSFS_mount() لإضافة الأرشيفات التي يدعمها مستودع الأرشيف الخاص بك إلى مسار البحث، أو ربما استخدامه كدليل للكتابة. داخليًا، يستخدم PhysicsFS هذه الوظيفة لتسجيل مستودعات الأرشيف المدمجة الخاصة به، مثل دعم .zip، إلخ.

لا يمكنك الحصول على مستودعي أرشيف يتعاملان مع نفس الامتداد. إذا كان هناك تعارض، يمكنك إلغاء تسجيل مستودع الأرشيف الآخر (بما في ذلك المستودعات المدمجة) باستخدام PHYSFS_deregisterArchiver().

void PHYSFS_utf8ToUcs4 (const char * src, PHYSFS_uint32 * dst, PHYSFS_uint64 len)

Convert a UTF-8 string to a UCS-4 string.

Warning

This function will not report an error if there are invalid UTF-8 sequences in the source string. It will replace them with a '?' character and continue on.

UTF-32 strings are 32-bits per character. They are the simplest encoding to work with for general text manipulation, but they can be prohibitively large for storage or transmission.

To ensure that the destination buffer is large enough for the conversion, please allocate a buffer that is three times the size of the source buffer. UTF-8 uses from one to four bytes per character, but UCS-4 always uses four bytes per character. The UTF-8 characters that would take four bytes also take four bytes in UCS-4, so you don't need to allocate more than 4x the space just in case: three will do.

Strings that don't fit in the destination buffer will be truncated, but will always be null-terminated and never have an incomplete UCS-4 sequence at the end. If the buffer length is 0, this function does nothing.

Parameters

src Null-terminated source string in UTF-8 format.
dst Buffer to store converted UCS-4 string.
len Size, in bytes, of destination buffer.

void PHYSFS_utf8ToUtf16 (const char * src, PHYSFS_uint16 * dst, PHYSFS_uint64 len)

Convert a UTF-8 string to a UTF-16 string.

Warning

This function will not report an error if there are invalid UTF-8 sequences in the source string. It will replace them with a '?' character and continue on.

UTF-16 strings are 16-bits per character (except some chars, which are 32-bits): TCHAR on Windows, when building with Unicode support. Modern Windows releases use UTF-16. Windows releases before 2000 used TCHAR, but only handled UCS-2. UTF-16 is UCS-2, except for the characters that are 4 bytes, which aren't representable in UCS-2 at all anyhow. If you aren't sure, you should be using UTF-16 at this point on Windows.

To ensure that the destination buffer is large enough for the conversion, please allocate a buffer that is double the size of the source buffer. UTF-8 uses from one to four bytes per character, but UTF-16 always uses two to four, so an entirely low-ASCII string will double in size! The UTF-16 characters that would take four bytes also take four bytes in UTF-8, so you don't need to allocate 4x the space just in case: double will do.

Strings that don't fit in the destination buffer will be truncated, but will always be null-terminated and never have an incomplete UTF-16 surrogate pair at the end. If the buffer length is 0, this function does nothing.

Parameters

src Null-terminated source string in UTF-8 format.
dst Buffer to store converted UTF-16 string.
len Size, in bytes, of destination buffer.

PHYSFS_sint64 PHYSFS_writeBytes (PHYSFS_File * handle, const void * buffer, PHYSFS_uint64 len)

Write data to a PhysicsFS filehandle. The file must be opened for writing.

Please note that while (len) is an unsigned 64-bit integer, you are limited to 63 bits (9223372036854775807 bytes), so we can return a negative value on error. If length is greater than 0x7FFFFFFFFFFFFFFF, this function will immediately fail. For systems without a 64-bit datatype, you are limited to 31 bits (0x7FFFFFFF, or 2147483647 bytes). We trust most things won't need to do multiple gigabytes of i/o in one call anyhow, but why limit things?

Parameters

buffer buffer of (len) bytes to write to (handle).
len number of bytes being written to (handle).

Returns

number of bytes written. This may be less than (len); in the case of an error, the system may try to write as many bytes as possible, so an incomplete write might occur. PHYSFS_getLastErrorCode() can shed light on the reason this might be < (len). -1 if complete failure.
