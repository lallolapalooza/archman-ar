intPHYSFS_setRoot(const char *archive, const char *subdir)

Hace que un subdirectorio de un archivo sea su directorio raíz. Esto te permite delimitar los archivos accesibles dentro de un archivo específico. Por ejemplo, si tienes x.zip con un archivo en y/z.txt montado a /a, si llamas a PHYSFS_setRoot("x.zip", "/y"), la llamada a PHYSFS_openRead("/a/z.txt") tendrá éxito.

Puedes cambiar la raíz de un archivo en cualquier momento, alterando así el árbol de archivos interpolado (dependiendo de dónde se muevan las rutas, un archivo diferente puede proporcionar archivos diferentes). Si estableces la raíz a NULL o "/", el archivo será tratado como si no tuviera una raíz especial (como si el archivo se montara normalmente).

Cambiar la raíz solo afecta a las operaciones futuras en las rutas de archivo; un archivo que se abrió desde una ruta que cambió debido a un setRoot no se verá afectado.

Establecer una nueva raíz no se limita a los archivos en el directorio de búsqueda; puedes establecer una en el directorio de escritura, lo cual puede ser útil si tienes archivos abiertos para escribir y no puedes cambiar el directorio de escritura en este momento.

No es un error establecer un subdirectorio que no existe como la raíz de un archivo; sin embargo, en ese caso, no se verán archivos. Si los directorios faltantes se crean eventualmente (una llamada a mkdir en el sistema de archivos físico, etc.), esto se reflejará en el árbol interpolado.

Parámetros

archive directorio/archivo en el cual cambiar la raíz.
subdir nuevo subdirectorio para hacer la raíz de este archivo.

Retorna

distinto de cero en éxito, cero en error. Usa PHYSFS_getLastErrorCode() para obtener el error específico.

void PHYSFS_utf8FromLatin1 (const char * src, char * dst, PHYSFS_uint64 len)

Convert a Latin1 string to a UTF-8 string. Latin1 strings are 8-bits per character: a popular "high ASCII" encoding.

To ensure that the destination buffer is large enough for the conversion, please allocate a buffer that is double the size of the source buffer. UTF-8 expands latin1 codepoints over 127 from 1 to 2 bytes, so the string may grow in some cases.

Strings that don't fit in the destination buffer will be truncated, but will always be null-terminated and never have an incomplete UTF-8 sequence at the end. If the buffer length is 0, this function does nothing.

Please note that we do not supply a UTF-8 to Latin1 converter, since Latin1 can't express most Unicode codepoints. It's a legacy encoding; you should be converting away from it at all times.

Parameters

src Null-terminated source string in Latin1 format.
dst Buffer to store converted UTF-8 string.
len Size, in bytes, of destination buffer.

Case-insensitive compare of two UTF-8 strings. This is a strcasecmp/stricmp replacement that expects both strings to be in UTF-8 encoding. It will do "case folding" to decide if the Unicode codepoints in the strings match.

If both strings are exclusively low-ASCII characters, this will do the right thing, as that is also valid UTF-8. If there are any high-ASCII chars, this will not do what you expect!

It will report which string is "greater than" the other, but be aware that this doesn't necessarily mean anything: 'a' may be "less than" 'b', but a Japanese kuten has no meaningful alphabetically relationship to a Greek lambda, but being able to assign a reliable "value" makes sorting algorithms possible, if not entirely sane. Like stricmp, this expects both strings to be NULL-terminated.

str1 First string to compare.
str2 Second string to compare.

Returns

تحويل سلسلة UTF-8 إلى سلسلة UTF-16.

تحذير

لن تقوم هذه الوظيفة بالإبلاغ عن خطأ إذا كانت هناك تسلسلات UTF-8 غير صالحة في سلسلة الإدخال. ستقوم باستبدال هذه التسلسلات بالحرف '؟' وتستمر.

سلاسل UTF-16 تحتوي على 16 بت لكل حرف (باستثناء بعض الأحرف التي تكون 32 بت): TCHAR في Windows، عند تجميعها مع دعم Unicode. تستخدم إصدارات Windows الحديثة UTF-16. استخدمت إصدارات Windows القديمة قبل عام 2000 TCHAR، لكنها تعاملت فقط مع UCS-2. UTF-16 هو UCS-2، ما لم تكن الأحرف التي تتكون من 4 بايت غير قابلة للتمثيل بالكامل في UCS-2. إذا لم تكن متأكدًا، يجب عليك استخدام UTF-16 في هذه المرحلة في Windows.

للتأكد من أن مخزن الوجهة كبير بما فيه الكفاية للتحويل، يرجى تخصيص مخزن بحجم ضعف حجم مخزن الإدخال. يستخدم UTF-8 من 1 إلى 4 بايت لكل حرف، ولكن UTF-16 يستخدم دائمًا من 2 إلى 4 بايت، لذلك سلسلة ASCII منخفضة بالكامل ستتضاعف في الحجم! الأحرف UTF-16 التي ستتطلب 4 بايت ستتطلب أيضًا 4 بايت في UTF-8، لذلك لا تحتاج إلى تخصيص 4 أضعاف المساحة، فقط مضاعفة.

سيتم اقتطاع السلاسل التي لا تتناسب مع مخزن الوجهة، ولكن سيتم دائمًا إنهاؤها بحرف فارغ ولن تحتوي على زوج استبدال غير مكتمل في النهاية. إذا كان طول المخزن 0، فلن تفعل هذه الوظيفة شيئًا.

NAME

PHYSFS_writeUBE16, PHYSFS_writeUBE32, PHYSFS_writeUBE64, PHYSFS_writeULE16, PHYSFS_writeULE32, PHYSFS_writeULE64 — write platform-specific integer types to a file in a specific endian format

Description

These functions write an unsigned integer of a specified size (16, 32, or 64 bits) to a file handle in a specified endian format (big-endian or little-endian).

These are convenience functions that attempt to convert the value from the platform's native byte order to the specified endian format before writing. If the platform's native byte order is already the desired endian format, no conversion is performed.

zero on failure, non-zero on success. On failure, you can find out what went wrong from PHYSFS_getLastErrorCode().
