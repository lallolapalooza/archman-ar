int PHYSFS_caseFold (const PHYSFS_uint32 from, PHYSFS_uint32 * to)

"Fold" a Unicode codepoint to a lowercase equivalent. (This is for limited, hardcore use. If you don't immediately see a need for it, you can probably ignore this forever.)

This will convert a Unicode codepoint into its lowercase equivalent. Bogus codepoints and codepoints without a lowercase equivalent will be returned unconverted.

Note that you might get multiple codepoints in return! The German Eszett, for example, will fold down to two lowercase latin 's' codepoints. The theory is that if you fold two strings, one with an Eszett and one with "SS" down, they will match.

Warning

Anyone that is a student of Unicode knows about the "Turkish I" problem. This API does not handle it. Assume this one letter in all of Unicode will definitely fold sort of incorrectly. If you don't know what this is about, you can probably ignore this problem for most of the planet, but perfection is impossible.

Parameters

from The codepoint to fold.
to Buffer to store the folded codepoint values into. This should point to space for at least 3 PHYSFS_uint32 slots.

Returns

The number of codepoints the folding produced. Between 1 and 3.

int PHYSFS_close (PHYSFS_File * handle)

Close a PhysicsFS filehandle. This call is capable of failing if the operating system was buffering writes to the physical media, and, now forced to write those changes to physical media, can not store the data for some reason. In such a case, the filehandle stays open. A well-written program should ALWAYS check the return value from the close call in addition to every writing call!

Parameters

Returns

int PHYSFS_deinit (void )

Deinitialize the PhysicsFS library. This closes any files opened via PhysicsFS, blanks the search/write paths, frees memory, and invalidates all of your file handles.

Note that this call can FAIL if there's a file open for writing that refuses to close (for example, the underlying operating system was buffering writes to network filesystem, and the fileserver has crashed, or a hard drive has failed, etc). It is usually best to close all write handles yourself before calling this function, so that you can gracefully handle a specific failure.

Once successfully deinitialized, PHYSFS_init() can be called again to restart the subsystem. All default API states are restored at this point, with the exception of any custom allocator you might have specified, which survives between initializations.

Returns

nonzero on success, zero on error. Specifics of the error can be gleaned from PHYSFS_getLastError(). If failure, state of PhysFS is undefined, and probably badly screwed up.

int PHYSFS_delete (const char * filename)

Delete a file or directory. (filename) is specified in platform-independent notation in relation to the write dir.

A directory must be empty before this call can delete it.

Deleting a symlink will remove the link, not what it points to, regardless of whether you "permitSymLinks" or not.

So if you've got the write dir set to "C:\mygame\writedir" and call PHYSFS_delete("downloads/maps/level1.map") then the file "C:\mygame\writedir\downloads\maps\level1.map" is removed from the physical filesystem, if it exists and the operating system permits the deletion.

Note that on Unix systems, deleting a file may be successful, but the actual file won't be removed until all processes that have an open filehandle to it (including your program) close their handles.

Chances are, the bits that make up the file still exist, they are just made available to be written over at a later point. Don't consider this a security method or anything. :)

Parameters

filename Filename to delete.

Returns

nonzero on success, zero on error. Use PHYSFS_getLastErrorCode() to obtain the specific error.

int PHYSFS_deregisterArchiver (const char * ext)

Remove an archiver from the system. If for some reason, you only need your previously-registered archiver to live for a portion of your app's lifetime, you can remove it from the system once you're done with it through this function.

This fails if there are any archives still open that use this archiver.

This function can also remove internally-supplied archivers, like .zip support or whatnot. This could be useful in some situations, like disabling support for them outright or overriding them with your own implementation. Once an internal archiver is disabled like this, PhysicsFS provides no mechanism to recover them, short of calling PHYSFS_deinit() and PHYSFS_init() again.

PHYSFS_deinit() will automaticall up the المُخصص المستخدم حاليًا. يمكن أن يكون هذا مفيدًا للتطبيقات التي ترغب في الوصول إلى روتينيات التخصيص الداخلية الافتراضية لـ PhysicsFS، وكذلك للكود الخارجي الذي يرغب في مشاركة نفس المُخصص، حتى لو قام التطبيق بتحديد مُخصصه الخاص.

هذه الدعوة صالحة فقط بين استدعاءات PHYSFS_init() و PHYSFS_deinit()؛ ستُعيد NULL إذا لم تكن المكتبة مُهيأة. بما أنه لا يمكننا ضمان حالة المُخصصات الداخلية إلا إذا كانت المكتبة مُهيأة، فلا يجب عليك استخدام أي مُخصص مُعاد هنا بعد استدعاء PHYSFS_deinit().

لا تستدعِ طرق Init() أو Deinit() للمُخصص المُعاد بأي حال من الأحوال.

إذا لم تكن متأكدًا تمامًا مما يجب فعله بهذه الدالة، يمكنك تجاهلها بأمان تمامًا.

الإرجاع

المُخصص الحالي، كما تم تعيينه بواسطة PHYSFS_setAllocator()، أو المُخصص الداخلي الافتراضي لـ PhysicsFS إذا لم يتم تعيين مُخصص محدد من قبل التطبيق حاليًا. ستُعيد NULL إذا لم تكن المكتبة مُهيأة.

char ** PHYSFS_getCdRomDirs (void )

احصل على مصفوفة من المسارات لمحركات أقراص CD-ROM المتاحة. الأدلة المُعادة تعتمد على المنصة ("D:\" على Win32، "/cdrom" أو شيء من هذا القبيل على Unix). لا تُعاد الأدلة إلا إذا كان هناك قرص جاهز ومتاح في المحرك. لذلك إذا كان لديك محركين (D: و E:)، وكان E: فقط يحتوي على قرص، فهذا كل ما تحصل عليه. إذا أدخل المستخدم قرصًا في D: واستدعيت هذه الدالة مرة أخرى، فستحصل على كلا المحركين. إذا، على صندوق Unix، قام المستخدم بإزالة قرص وإعادة تحميله في مكان آخر، فإن الاستدعاء التالي لهذه الدالة سيعكس هذا التغيير. تشير هذه الدالة إلى وسائط "CD-ROM"، ولكنها تعني حقًا "وسائط القرص المُدخل"، مثل DVD-ROM، HD-DVD، CDRW، وأقراص Blu-Ray. إنها تبحث عن أنظمة الملفات، وبذلك لن تُبلغ عن قرص صوتي، إلا إذا كان هناك مسار نظام ملفات مُحمل عليه. القيمة المُعادة هي مصفوفة من السلاسل النصية، مع إدخال NULL للإشارة إلى نهاية القائمة: @code char **cds = PHYSFS_getCdRomDirs(); char **i; for (i = cds; *i != NULL; i++) printf("cdrom dir [%s] is available.\n", *i); PHYSFS_freeList(cds); @endcode

قد تتوقف هذه الدعوة مؤقتًا أثناء دوران المحركات. كن حذرًا.

عندما تنتهي من المعلومات المُعادة، يمكنك التخلص من الموارد عن طريق استدعاء PHYSFS_freeList() مع المؤشر المُعاد.

الإرجاع

مصفوفة منتهية بـ NULL من السلاسل النصية المنتهية بـ NULL.

احصل على معلومات خطأ نصية يمكن قراءتها.

تم إهمالها

استخدم PHYSFS_getLastErrorCode() و PHYSFS_getErrorByCode() بدلاً من ذلك.

تحذير

اعتبارًا من PhysicsFS 2.1، تم إضعاف هذه الدالة. قبل PhysicsFS 2.1، كانت هذه الدالة هي الطريقة الوحيدة للحصول على تفاصيل الأخطاء بخلاف القيمة الأساسية التي تُعيدها الدالة. كان من المفترض أن تكون سلسلة نصية يمكن قراءتها من قبل الإنسان بإحدى لغات متعددة، ولم تكن مفيدة لتحليل التطبيقات. كانت هذه مشكلة، لأن المطور وليس المستخدم اختار اللغة عند الترجمة، وكان على صائني PhysicsFS (بشكل سيء) صيانة قدر كبير من العمل المحلي. لم يكن التطبيق قادرًا على تحليل السلاسل النصية، حتى لو اعتمد على لغة معينة، حيث أن بعضها كان يتم إنشاؤه ديناميكيًا. في الإصدار 2.1 والإصدارات الأحدث، تُعيد هذه الدالة دائمًا سلسلة نصية ثابتة باللغة الإنجليزية؛ يمكنك استخدامها كمفتاح لسلاسل الترجمة الخاصة بك إذا أردت، حيث سنعدك بعدم تغيير سلاسل الأخطاء الموجودة. أيضًا، إذا رغب تطبيقك في فحص أخطاء معينة، فإننا نقدم الآن خيارًا أفضل: استخدم PHYSFS_getLastErrorCode() بدلاً من ذلك.

احصل على آخر رسالة خطأ لـ PhysicsFS كسلسلة نصية منتهية بـ NULL يمكن قراءتها من قبل الإنسان. ستُعيد هذه الدالة NULL إذا لم يكن هناك خطأ منذ آخر استدعاء لهذه الدالة. يشير المؤشر الذي تُعيده هذه الدعوة إلى مخزن مؤقت داخلي. كل خيط لديه حالة خطأ فريدة مرتبطة به، ولكن في كل مرة يتم فيها تعيين رسالة خطأ جديدة، فإنها ستحل محل الرسالة السابقة المرتبطة بهذا الخيط. من الآمن استدعاء هذه الدالة في أي وقت، حتى قبل PHYSFS_init().

تقوم كل من PHYSFS_getLastError() و PHYSFS_getLastErrorCode() بإعادة تعيين نفس حالة الخطأ الخاصة بالخيط. سيؤدي استدعاء إحداهما إلى مسح بيانات الأخرى. إذا احتجت إلى كليهما، فاستدعِ PHYSFS_getLastErrorCode()، ثم مرر تلك القيمة إلى PHYSFS_getErrorByCode().

اعتبارًا من PhysicsFS 2.1، تعرض هذه الدالة نصوصًا باللغة الإنجليزية فقط، ولكن السلاسل النصية ثابتة، لذا يمكنك استخدامها كمفاتيح في قاموس الترجمة الخاص بك. هذه السلاسل مخصصة ليتم تمريرها مباشرة إلى المستخدم.

بشكل عام، يجب أن تهتم التطبيقات فقط بما إذا كانت دالة معينة قد فشلت؛ ومع ذلك، إذا كان الكود الخاص بك يتطلب تفاصيل أكثر، فيجب عليك استخدام PHYSFS_getLastErrorCode() بدلاً من هذه الدالة.

الإرجاع

سلسلة للقراءة فقط لآخر رسالة خطأ.

بشكل افتراضي، سيقوم PhysicsFS بالتحقق مما إذا كان الملف رابطًا رمزيًا بالفعل أثناء استدعاءات الفتح وسيفشل إذا كان كذلك. بخلاف ذلك، يمكن للرابط أن يخرجك من مسارات الكتابة والبحث، ويشكل خطرًا أمنيًا.

إذا كنت ترغب في تحمل هذا الخطر، فاستدع هذه الدالة بمعامل غير صفري. لاحظ أن هذا يتعلق أكثر بعزل لغة البرمجة النصية للبرنامج، في حالة محاولة النصوص البرمجية غير الموثوق بها تعريض النظام للخطر. بشكل عام، يمكن للمستخدم أن يكون لديه سبب مشروع لإعداد رابط رمزي، لذلك ما لم تشعر بوجود خطر محدد في السماح به، يجب عليك السماح به.

يتم التحقق من الروابط الرمزية صراحة فقط عند التعامل مع أسماء الملفات بالترميز المستقل عن المنصة. أي، عند إعداد مسارات البحث والكتابة، وما إلى ذلك، لا يتم التحقق من الروابط الرمزية مطلقًا.

يرجى ملاحظة أن PHYSFS_stat() سيتحقق دائمًا من المسار المحدد؛ إذا كان هذا المسار رابطًا رمزيًا، فلن يتم اتباعه في أي حال. إذا لم تكن الروابط الرمزية مسموحًا بها من خلال هذه الدالة، فإن PHYSFS_stat() يتجاهلها، وسيعامل الاستعلام كما لو كان المسار غير موجود على الإطلاق.

يمكن تمكين أو تعطيل إذن الروابط الرمزية في أي وقت بعد استدعاء PHYSFS_init()، ويتم تعطيله افتراضيًا.

int PHYSFS_setRoot (const char * archive, const char * subdir)

يجعل دليلًا فرعيًا لأرشيف ما هو دليله الجذر. هذا يسمح لك بتقييد الملفات التي يمكن الوصول إليها داخل أرشيف معين. على سبيل المثال، إذا كان لديك x.zip مع ملف في y/z.txt تم تحميله إلى /a، وإذا قمت باستدعاء PHYSFS_setRoot("x.zip", "/y")، فسيتم استدعاء PHYSFS_openRead("/a/z.txt") بنجاح.

يمكنك تغيير جذر الأرشيف في أي وقت، وبالتالي تغيير شجرة الملفات المستقاة (اعتمادًا على مكان تحرك المسارات، قد يوفر أرشيف مختلف ملفات مختلفة). إذا قمت بتعيين الجذر إلى NULL أو إلى "/"، فسيتم التعامل مع الأرشيف كما لو لم يكن هناك جذر خاص (كما لو تم تحميل الأرشيف بشكل طبيعي).

يؤثر تغيير الجذر فقط على العمليات المستقبلية على مسارات الملفات؛ لن يتأثر الملف الذي تم فتحه من مسار تغير بسبب setRoot.

لا يقتصر تعيين جذر جديد على الملفات في دليل البحث؛ يمكنك تعيينه إلى دليل الكتابة أيضًا، والذي قد يكون مفيدًا إذا كان لديك ملفات مفتوحة للكتابة ولا يمكنك تغيير دليل الكتابة الآن.

ليس من الخطأ تعيين دليل فرعي غير موجود كجذر لأرشيف، على الرغم من أنه لن يتم عرض أي ملفات في هذه الحالة. إذا تم إنشاء الأدلة المفقودة في النهاية (mkdir إلى نظام الملفات الفعلي، وما إلى ذلك)، فسيتم عكس ذلك في الشجرة المستقاة.

المعاملات

archive الدليل/الأرشيف الذي سيتم تغيير الجذر إليه.
subdir الدليل الفرعي الجديد ليصبح جذر هذا الأرشيف.

يعود

غير صفري عند النجاح، صفري عند الخطأ. استخدم PHYSFS_getLastErrorCode() للحصول على الخطأ المحدد.

int PHYSFS_setSaneConfig (const char * organization, const char * appName, const char * archiveExt, int includeCdRoms, int archivesFirst)

يقوم بتكوين المسارات المنطقية، والمسارات الافتراضية. وظيفة مساعدة.

سيتم تعيين دليل الكتابة إلى الدليل البادئ الذي تم إرجاعه بواسطة

PHYSFS_getPrefDir(organization, appName)

، والذي يتم إنشاؤه إذا لم يكن موجودًا.

الجزء السابق كافٍ لضمان أن مجلد تكوين برنامجك منفصل عن ملفات الفوضى الأخرى ومستقل عن النظام الأساسي.

سيكون مسار البحث:

  • دليل الكتابة (يتم إنشاؤه إذا لم يكن موجودًا)
  • دليل القاعدة (PHYSFS_getBaseDir())
  • جميع أدلة الأقراص المدمجة التي تم العثور عليها (اختياري)

يتم البحث في هذه الأدلة حسب الامتدادات (archiveExt)، والتي، إذا كانت صالحة ومدعومة، يتم إضافتها أيضًا إلى مسار البحث. إذا حددت "PKG" لـ (archiveExt) وكان هناك ملف يسمى data.PKG في دليل القاعدة، فسيتم التحقق منه. يمكن إضافة الأرشيفات أو إلحاقها بمسار البحث بترتيب أبجدي، بغض النظر عن مكان العثور عليها. يتم تحميل جميع الأرشيفات إلى جذر نظام الملفات الافتراضي ("/").

كل هذا يمكن القيام به من التطبيق، لكن هذا يقوم بكل شيء من أجلك. لديك حرية إضافة المزيد إلى مسار البحث يدويًا أيضًا.

المعاملات

organization اسم شركتك/مجموعتك/إلخ لاستخدامه كدليل، لذا اجعله صغيرًا وخاليًا من الحيل.
appName اسم البرنامج المحدد لتطبيقك، لفصله عن البرامج الأخرى التي تستخدم PhysicsFS.
archiveExt الامتداد الذي يستخدمه برنامجك لتحديد أرشيف. على سبيل المثال، يستخدم Quake 3 "pk3"، على الرغم من أنها مجرد ملفات مضغوطة. حدد NULL لعدم البحث عن الأرشيفات تلقائيًا. لا تحدد النقطة "."; إذا كنت تريد البحث عن ملفات ZIP، فحدد "ZIP" وليس ".ZIP" ... البحث عن الأرشيفات غير حساس لحالة الأحرف.
includeCdRoms غير صفري لتضمين الأقراص المدمجة في مسار البحث، و (إذا كان (archiveExt) != NULL) البحث عنها بواسطة الأرشيفات. قد يتسبب هذا في تأخير كبير عند الوصول إلى الأقراص، وإذا لم تكن هناك أقراص في محرك الأقراص (أو حتى لم يتم تحميلها على أنظمة Unix)، فقد لا تكون متاحة. يمكنك تحديد صفر والتعامل مع تكوين القرص بنفسك.
archivesFirst غير صفري لإلحاق الأرشيفات بمسار البحث. صفري لإلحاقها. تم التجاهل إذا كان !(archiveExt).

يعود

const PHYSFS_ArchiveInfo ** PHYSFS_supportedArchiveTypes (void )

احصل على قائمة بأنواع الأرشيفات المدعومة. احصل على قائمة بأنواع الأرشيفات التي تدعمها هذه التنفيذات من PhysicsFS. هذه هي تنسيقات الأرشيفات القابلة للاستخدام لإدخالات المسار. هذه مجرد معلومات إعلامية. لاحظ أن الامتداد المذكور هو مجرد اصطلاح: إذا قمت بسرد "ZIP"، فيمكنك فتح أرشيف متوافق مع PkZip بامتداد "XYZ" إذا كنت ترغب في ذلك.

القيمة المرجعة هي مصفوفة من المؤشرات إلى هياكل PHYSFS_ArchiveInfo، مع عنصر NULL للإشارة إلى نهاية القائمة:

PHYSFS_ArchiveInfo **i;
for (i = PHYSFS_supportedArchiveTypes(); *i != NULL; i++)
{
    printf("Supported archive: [%s], which is [%s].\n",
             (*i)->extension, (*i)->description);
}

القيم المرجعة هي مؤشرات إلى ذاكرة داخلية ويجب اعتبارها للقراءة فقط وعدم تحريرها أبدًا. القيم المرجعة صالحة حتى الاستدعاء التالي لـ PHYSFS_deinit() أو PHYSFS_registerArchiver() أو PHYSFS_deregisterArchiver().

يعود

مصفوفة من هياكل للقراءة فقط، تنتهي بـ NULL.
