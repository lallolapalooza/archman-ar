PHYSFS_sint64 PHYSFS_getLastModTime (const char * filename)

Obtén la hora de última modificación de un archivo.

Desacreditado

Desde PhysicsFS 2.1, usa PHYSFS_stat() en lugar de esta función. Esta función solo lo envuelve.

La hora de modificación se devuelve en segundos desde el epoch Unix (midnight, 1 de enero de 1970). La exactitud de esta hora depende del archivero particular. Si no hay una manera razonable de obtener esta información para un archivero particular, o hubo algún error, esta función devuelve -1.

Debes usar esta función y no PHYSFS_stat() si hay compatibilidad binaria importante con PhysicsFS 2.0 (lo cual podría no ser el caso para muchos usuarios).

Parámetros

filename nombre de archivo a verificar, en notación independiente del sistema.

Devuelve

hora de modificación del archivo. -1 si no se puede determinar.

const char * PHYSFS_getPrefDir (const char * org, const char * app)

Obtén la ruta de directorio específica para donde se puedan escribir archivos. Función de ayuda.

Obtén el "pref dir". Este es el lugar donde los usuarios pueden escribir archivos personales (preferencias y juegos salvados, etc) específicos de tu aplicación. Este directorio es único por usuario y por aplicación.

Esta función decide la ubicación adecuada en el sistema de archivos nativo, crea el directorio si es necesario y devuelve una cadena en notación del sistema, adecuada para pasar a PHYSFS_setWriteDir().

En Windows, podría parecer así: "C:\\Users\\bob\\AppData\\Roaming\\My Company\\My Program Name"

En Linux, podría parecer así: "/home/bob/.local/share/My Program Name"

En Mac OS X, podría parecer así: "/Users/bob/Library/Application Support/My Program Name"

(etc.)

Deberías usar la pref dir para tu directorio de escritura, y también colócalo al principio de tu ruta de búsqueda. Versiones antiguas de PhysicsFS ofrecían solo PHYSFS_getUserDir() y dejaban a ti decidir donde los archivos deberían estar bajo ese árbol. Esta encuentra la ubicación correcta para cualquier plataforma, que no solo cambia entre sistemas operativos, sino también entre versiones del mismo sistema operativo.

Especifícalo el nombre de tu organización (si no es una organización real, tu nombre o un dominio Internet que poseas podría hacerlo), y el nombre de tu aplicación. Estos deben ser nombres correctos.

Ambos los strings (org) y (app) pueden convertirse parte de un nombre de directorio, así que por favor sigue estos reglas:

  • Usa el mismo string de organización (incluyendo la sensibilidad de caso) para todas tus aplicaciones que usen esta función.
  • Usa siempre un string único para cada aplicación, y asegúrate de que no cambie para una aplicación una vez que lo hayas decidido.
  • Caracteres Unicode son válidos, siempre que estén codificados como UTF-8, pero...
  • ...solo use letras, números y espacios. Evita caracteres como "Game Name 2: Bad Guy's Revenge!" ... "Game Name 2" es suficiente.

El puntero devuelto por esta función permanece válido hasta que lo llames de nuevo o llames PHYSFS_deinit(). No es necesariamente un llamado rápido, así que deberías llamarlo una vez al inicio y copiar la cadena si la necesitas.

Deberías asumir que el camino devuelto por esta función es el único lugar seguro para escribir archivos (y que PHYSFS_getUserDir() y PHYSFS_getBaseDir(), aunque puedan ser escritos, o incluso padres de la ruta devuelta, no son el lugar donde debes escribir).

Parámetros

org nombre de tu organización.
app nombre de tu aplicación.

Devuelve

cadena READ-ONLY de la ruta de directorio de usuario en notación del sistema. NULL si hay un problema (creación de directorio falló, etc).

const char *physFS_getRealDir (const char * filename)

Determina dónde en la ruta de búsqueda se encuentra un archivo. El archivo se especifica en notación independiente del sistema. El nombre devuelto será el elemento de la ruta de búsqueda donde se encontró el archivo, que podría ser un directorio o un archivero. Even if there are multiple matches in different parts of the search path, only the first one found is used, just like when opening a file.

Por ejemplo, si estás buscando "maps/level1.map" y C:\mygame está en tu ruta de búsqueda y C:\mygame\maps\level1.map existe, se devuelve "C:\mygame".

Si alguna parte de una coincidencia es un enlace simbólico y no has explicitamente permitido enlaces simbólicos, será ignorado y la búsqueda continuará.

Si especificas un directorio ficticio que solo exista como un punto de montaje, se asociará con el primer archivero montado allí, incluso si ese directorio no está contenido en un archivero real.

Advertencia

Este devolverá NULL si no hay un directorio real asociado (filename). Específicamente, PHYSFS_mountIo(), PHYSFS_mountMemory() y PHYSFS_mountHandle() devolverán NULL incluso si el nombre está encontrado en la ruta de búsqueda. Planea así.

Parámetros

filename archivo a buscar.

Devuelve

cadena READ-ONLY de elemento de la ruta de búsqueda que contiene el archivo en cuestión. NULL si no se encuentra.

char ** PHYSFS_getSearchPath (void )

Obtén la ruta de búsqueda actual. La ruta por defecto es un lista vacía.

El valor devuelto es un array de strings, con un NULL para señalar el final de la lista:

char **i;
for (i = PHYSFS_getSearchPath(); *i != NULL; i++)
    printf("[%s] es en la ruta de búsqueda.\n", *i);

Devuelve

Array de strings nulo-terminado. NULL si hubo un problema (le: OUT OF MEMORY).

UTF-16 هو UCS-2، باستثناء الأحرف التي تتكون من 4 بايت، والتي لا يمكن تمثيلها في UCS-2 على أي حال. إذا لم تكن متأكدًا، فيجب عليك استخدام UTF-16 في هذه المرحلة على Windows.

للتأكد من أن المخزن المؤقت الوجهة كبير بما فيه الكفاية للتحويل، يرجى تخصيص مخزن مؤقت بحجم ضعف حجم المخزن المؤقت المصدر. لا يستخدم UTF-8 أكثر من 32 بت لكل حرف، لذا بينما قد يقلل من حجم سلسلة UTF-16، فقد يوسعها أيضًا.

سيتم اقتطاع السلاسل التي لا تتناسب مع المخزن المؤقت الوجهة، ولكنها ستنتهي دائمًا بحرف null ولن تحتوي أبدًا على تسلسل UTF-8 غير مكتمل في النهاية. إذا كان طول المخزن المؤقت 0، فلن تقوم هذه الدالة بأي شيء.
