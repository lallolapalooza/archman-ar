int PHYSFS_enumerate (const char * dir, PHYSFS_EnumerateCallback c, void * d)

الحصول على قائمة بالملفات من دليل معين في مسار البحث، باستخدام دالة رد اتصال يحددها المستخدم، مع إبلاغ الأخطاء. داخليًا، تستدعي PHYSFS_enumerateFiles() هذه الدالة فقط ثم تبني قائمة قبل إعادتها إلى التطبيق، لذا فإن الوظائف متطابقة باستثناء كيفية تقديم المعلومات للتطبيق.

على عكس PHYSFS_enumerateFiles()، هذه الدالة لا تعيد مصفوفة. بدلاً من ذلك، تستدعي دالة يحددها التطبيق مرة واحدة لكل عنصر في مسار البحث:

static physfs_EnumerateCallbackResult printDir(void *data, const char *origdir, const char *fname)
{
    printf(" * We've got [%s] in [%s].\n", fname, origdir);
    return PHYSFS_ENUM_OK;  // أعطني المزيد من البيانات، من فضلك.
}
// ...
PHYSFS_enumerate("/some/path", printDir, NULL);

العناصر التي يتم تمريرها إلى دالة رد الاتصال ليست مضمونة لتكون بأي ترتيب معين. لا يتم إجراء أي ترتيب على هذا المستوى، وإذا كنت بحاجة إليه، يجب عليك استخدام PHYSFS_enumerateFiles()، والتي تضمن الترتيب الأبجدي. هذه الطريقة تبلغ عما تم العثور عليه في كل أرشيف قبل الانتقال إلى التالي. حتى داخل أرشيف واحد، لا يمكننا ضمان الترتيب الذي يتم به اكتشاف البيانات. أي ترتيب تجده في دوال رد الاتصال هذه هو مجرد حظ. لا تعتمد عليه. بما أن هذه الدالة تمر عبر قائمة الأرشيفات بأكملها، قد تتلقى أسماء ملفات مكررة.

يمكن لواجهة برمجة التطبيقات هذه ودوال رد الاتصال نفسها الإبلاغ عن الأخطاء. قبل واجهة برمجة التطبيقات هذه، كان على دوال رد الاتصال قبول كل عنصر تم تعداده، حتى لو كانوا يبحثون فقط عن عنصر معين ويرغبون في التوقف بعد ذلك، أو كان لديهم خطأ فادح ولم يتمكنوا من إبلاغ أي شخص. علاوة على ذلك، إذا واجهت PhysicsFS نفسها مشكلة (خطأ في القرص أو شيء من هذا القبيل)، لم نتمكن من إبلاغ التطبيق، وكان سيتعين علينا فقط تخطي العناصر أو إيقاف التعداد تمامًا، ولن يعرف المتصل أنه فقد بعض البيانات في الطريق.

الآن يمكن للمتصل التأكد من أنه حصل على مجموعة كاملة من البيانات، وإذا أراد إيقاف التعداد مبكرًا، فإن دالة رد الاتصال الخاصة به تتحكم في ذلك. راجع وثائق PHYSFS_EnumerateCallback للحصول على تفاصيل حول كيفية سلوك دالة رد الاتصال الخاصة بك.

المعاملات

dir الدليل، بتنسيق مستقل عن نظام التشغيل، ليتم تعداده.
c دالة رد الاتصال للإبلاغ عن عناصر مسار البحث.
d بيانات محددة من قبل التطبيق يتم تمريرها إلى دالة رد الاتصال. يمكن أن تكون NULL.

يعيد

غير صفر في حالة النجاح، وصفر في حالة الفشل. استخدم PHYSFS_getLastErrorCode() للحصول على الخطأ المحدد. إذا أعادت دالة رد الاتصال PHYSFS_ENUM_STOP للإيقاف المبكر، فسيتم اعتبار ذلك نجاحًا. ستؤدي دوال رد الاتصال التي تعيد PHYSFS_ENUM_ERROR إلى عودة هذه الدالة بصفر وتعيين رمز الخطأ إلى PHYSFS_ERR_APP_CALLBACK.

char **rc = PHYSFS_enumerateFiles("savegames");
char **i;
for (i = rc; *i != NULL; i++)
    printf(" * We've got [%s].\n", *i);
PHYSFS_freeList(rc);

* We've got [z.sav].
* We've got [w.sav]..fi

void PHYSFS_permitirEnlacesSimbolicos(int permitir)

Habilita o deshabilita el seguimiento de enlaces simbólicos. Algunos sistemas de archivos físicos y archivados contienen archivos que son simplemente punteros a otros archivos. Al abrir un enlace simbólico físico, este se abrirá transparentemente al archivo que se refiere.

Por defecto, PhysicsFS revisará si un archivo es realmente un enlace simbólico durante las llamadas de abrir y fallará si es así. De lo contrario, el enlace podría llevarte fuera de los caminos de lectura y escritura, comprometiendo la seguridad.

Si quieres tomar ese riesgo, llama a esta función con un valor no cero. Nota que esto es más para el sandboxing de un lenguaje de programación de scripts, en caso de scripts no confiados intenten comprometer el sistema. Generalmente, un usuario podría tener una razón legítima para crear un enlace simbólico, por lo que no deberías deshabilitarlo si no sientes una específica amenaza.

Los enlaces simbólicos se verán explícitamente solo cuando se estén trabajando con nombres de archivos en notación independiente de plataforma. Es decir, cuando se configuren tus caminos de búsqueda y escritura, etc., los enlaces simbólicos nunca se verán para verificar.

Nota: PHYSFS_stat() siempre verificará el camino especificado; si ese camino es un enlace simbólico, no se lo seguirá en ningún caso. Si no se permite a través de esta función, PHYSFS_stat() ignorará el enlace simbólico y tratará la consulta como si el camino no existiera.

La permisión de enlaces simbólicos puede habilitarse o deshabilitarse en cualquier momento después de haber llamado PHYSFS_init(), y está deshabilitada por defecto.

Parámetros

permitir no cero para permitir enlaces simbólicos, cero para deshabilitar el enlace.

Lee datos de un archivo de PhysicsFS. El archivo debe estar abierto para lectura.

Obsoleto

Desde PhysicsFS 2.1, usa PHYSFS_leerBytes() en su lugar. Esta función solo la envuelve. Esta función nunca aclaró qué pasaría si leías un objeto parcial, por lo que trabajar a nivel de byte es más limpio para todos, especialmente ahora que las interfaces PHYSFS_Io pueden ser proporcionadas por la aplicación.

numObj número de objetos (tamObj) a leer (manejador).

número de objetos leídos. PHYSFS_obtenerUltimoCodigoError() puede revelar el motivo por el cual este podría ser < (numObj), como también PHYSFS_eof(). -1 si hay falla completa.

تحذير

هذا موضوع متقدم وصعب. لست بحاجة إليه، إلا إذا كنت تعرف ما تفعله. معظم التطبيقات لن تحتاج إليه.

يتم البحث عن هذه الأدلة حسب الامتدادات (archiveExt)، والتي، إذا كانت صالحة ومدعومة، سيتم إضافتها أيضًا إلى قائمة البحث. إذا حددت "PKG" لـ (archiveExt)، وكان هناك ملف يسمى data.PKG في الدليل الأساسي، فسيتم فحصه. يمكن إضافة المجلدات أو إدراجها في قائمة البحث بترتيب أبجدي، بغض النظر عن مكان العثور عليها. يتم تحميل جميع الأرشيفات في جذر نظام الملفات الظاهري ("/")

كل ما سبق يمكن القيام به من البرنامج، ولكن هذه الدالة تقوم به نيابة عنك. يمكنك إضافة المزيد إلى قائمة البحث يدويًا أيضًا.

PHYSFS_swapULE64 — Convert and write an unsigned 64-bit littleendian value.

#include <physfs.h>

Detailed Description

Convert and write an unsigned 64-bit littleendian value. Convenience function. Convert an unsigned 64-bit value from the platform's native byte order to littleendian and write it to a file.

Parameters

file PhysicsFS file handle to which to write.
val Value to convert and write.

Returns

zero on failure, non-zero on success. On failure, you can find out what went wrong from PHYSFS_getLastErrorCode().

Warning

Remember, PHYSFS_uint64 is only 32 bits on platforms without any sort of 64-bit support.
