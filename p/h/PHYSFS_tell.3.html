تحذير

ما لم تكن لديك حاجة خاصة ومنخفضة المستوى، يجب عليك استخدام PHYSFS_mount() بدلاً من هذا.

قد تكون الأرشيفات داخل أرشيفات أخرى بطيئة جدًا! بينما يمكن لـ PHYSFS_File البحث حتى عندما تكون البيانات مضغوطة، فقد يتم ذلك عن طريق الرجوع إلى البداية وفك ضغط كل شيء قبل نقطة البحث. قد يؤدي الاستخدام العادي للأرشيف إلى الكثير من عمليات البحث في الخلفية. على هذا النحو، قد تجد أن الاستخدام العادي للأرشيف مؤلم للغاية إذا تم تحميله بهذه الطريقة. خطط وفقًا لذلك: إذا كان لديك، على سبيل المثال، ملف .zip ذاتي الاستخراج، وتريد تحميل شيء بداخله، فقم بضغط محتويات الأرشيف الداخلي وتأكد من أن ملف .zip الخارجي لا يضغط الأرشيف الداخلي أيضًا.

تعمل هذه الوظيفة تمامًا مثل PHYSFS_mount()، ولكنها تأخذ واجهة PHYSFS_File بدلاً من اسم مسار. تحتوي هذه الواجهة على جميع بيانات الأرشيف، ويتم استخدامها بدلاً من ملف حقيقي في نظام الملفات المادي. قد تكون الواجهة PHYSFS_File مدعومة بملف حقيقي في نظام الملفات المادي، ولكن ليس بالضرورة. الاستخدام الأكثر شيوعًا لهذا هو على الأرجح تحميل الأرشيفات المخزنة داخل أرشيفات أخرى.

(newDir) يجب أن يكون سلسلة فريدة لتحديد هذا الأرشيف. يتم استخدامه لتحسين اختيار الأرشيف (إذا سميته XXXXX.zip، فقد نجرب أولاً أرشيف ZIP، على سبيل المثال، أو نختار مباشرة أرشيفًا يمكنه الوثوق فقط بأن البيانات صالحة عن طريق امتداد اسم الملف). لا يحتاج إلى الإشارة إلى ملف حقيقي على الإطلاق. إذا لم يكن امتداد اسم الملف مفيدًا، فسيحاول النظام كل أرشيف حتى يعمل أحدهم أو لا يعمل أي منهم. يجب أن يكون اسم الملف هذا فريدًا، حيث لن يسمح لك النظام بوجود أرشيفين بنفس الاسم.

(file) يجب أن يظل موجودًا حتى يتم إلغاء تحميل الأرشيف. عند إلغاء تحميل الأرشيف، ستقوم الخدمة باستدعاء PHYSFS_close(file). إذا كنت بحاجة إلى بقاء هذه الواجهة، فستحتاج إلى تغليف هذا في PHYSFS_Io واستخدام PHYSFS_mountIo() بدلاً من ذلك.

إذا فشلت هذه الوظيفة، فلن يتم استدعاء PHYSFS_close(file).

المعلمات

file واجهة PHYSFS_File التي تحتوي على بيانات الأرشيف.
newDir اسم ملف يمكن أن يمثل هذا التدفق.
mountPoint موقع في الشجرة المستقرضة سيتم "تحميل" هذا الأرشيف فيه، بتنسيق مستقل عن المنصة. NULL أو "" يعادل "/".
appendToPath غير صفر للإلحاق بمسار البحث، صفر للاستباق.

الإرجاع

غير صفر إذا تم الإضافة إلى المسار، صفر عند الفشل (أرشيف غير صالح، إلخ). استخدم PHYSFS_getLastErrorCode() للحصول على الخطأ المحدد.

void PHYSFS_utf8ToUtf16 (const char * src, PHYSFS_uint16 * dst, PHYSFS_uint64 len)

Convert a UTF-8 string to a UTF-16 string.

Warning

This function will not report an error if there are invalid UTF-8 sequences in the source string. It will replace them with a '?' character and continue on.

UTF-16 strings are 16-bits per character (except some chars, which are 32-bits): TCHAR on Windows, when building with Unicode support. Modern Windows releases use UTF-16. Windows releases before 2000 used TCHAR, but only handled UCS-2. UTF-16 is UCS-2, except for the characters that are 4 bytes, which aren't representable in UCS-2 at all anyhow. If you aren't sure, you should be using UTF-16 at this point on Windows.

To ensure that the destination buffer is large enough for the conversion, please allocate a buffer that is double the size of the source buffer. UTF-8 uses from one to four bytes per character, but UTF-16 always uses two to four, so an entirely low-ASCII string will double in size! The UTF-16 characters that would take four bytes also take four bytes in UTF-8, so you don't need to allocate 4x the space just in case: double will do.

Strings that don't fit in the destination buffer will be truncated, but will always be null-terminated and never have an incomplete UTF-16 surrogate pair at the end. If the buffer length is 0, this function does nothing.

Parameters

src Null-terminated source string in UTF-8 format.
dst Buffer to store converted UTF-16 string.
len Size, in bytes, of destination buffer.

PHYSFS_sint64 PHYSFS_writeBytes (PHYSFS_File * handle, const void * buffer, PHYSFS_uint64 len)

Write data to a PhysicsFS filehandle. The file must be opened for writing.

Please note that while (len) is an unsigned 64-bit integer, you are limited to 63 bits (9223372036854775807 bytes), so we can return a negative value on error. If length is greater than 0x7FFFFFFFFFFFFFFF, this function will immediately fail. For systems without a 64-bit datatype, you are limited to 31 bits (0x7FFFFFFF, or 2147483647 bytes). We trust most things won't need to do multiple gigabytes of i/o in one call anyhow, but why limit things?
