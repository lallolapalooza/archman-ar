تعريف توافق API 1.0. PHYSFS_file مطابق لـ PHYSFS_File. هذا التعريف موجود للتوافق مع الإصدارات السابقة مع واجهة برمجة التطبيقات 1.0، والتي كانت لديها اتفاقية اصطلاح كتابة غير متسقة في هذه الحالة. يجب أن تستخدم الرموز البرمجية الجديدة PHYSFS_File، حيث قد يختفي هذا التعريف في المستقبل.

int PHYSFS_init (const char * argv0)

Initialize the PhysicsFS library. This must be called before any other PhysicsFS function.

This should be called prior to any attempts to change your process's current working directory.

Warning

On Android, argv0 should be a non-NULL pointer to a PHYSFS_AndroidInit struct. This struct must hold a valid JNIEnv * and a JNI jobject of a Context (either the application context or the current Activity is fine). Both are cast to a void * so we don't need jni.h included wherever physfs.h is. PhysicsFS uses these objects to query some system details. PhysicsFS does not hold a reference to the JNIEnv or Context past the call to PHYSFS_init(). If you pass a NULL here, PHYSFS_init can still succeed, but PHYSFS_getBaseDir() and PHYSFS_getPrefDir() will be incorrect.

argv0 the argv[0] string passed to your program's mainline. This may be NULL on most platforms (such as ones without a standard main() function), but you should always try to pass something in here. Many Unix-like systems need to pass argv[0] from main() in here. See warning about Android, too!

int PHYSFS_mount (const char * newDir, const char * mountPoint, int appendToPath)

Add an archive or directory to the search path. If this is a duplicate, the entry is not added again, even though the function succeeds. You may not add the same archive to two different mountpoints: duplicate checking is done against the archive and not the mountpoint.

When you mount an archive, it is added to a virtual file system...all files in all of the archives are interpolated into a single hierachical file tree. Two archives mounted at the same place (or an archive with files overlapping another mountpoint) may have overlapping files: in such a case, the file earliest in the search path is selected, and the other files are inaccessible to the application. This allows archives to be used to override previous revisions; you can use the mounting mechanism to place archives at a specific point in the file tree and prevent overlap; this is useful for downloadable mods that might trample over application data or each other, for example.

The mountpoint does not need to exist prior to mounting, which is different than those familiar with the Unix concept of "mounting" may expect. As well, more than one archive can be mounted to the same mountpoint, or mountpoints and archive contents can overlap...the interpolation mechanism still functions as usual.

Specifying a symbolic link to an archive or directory is allowed here, regardless of the state of PHYSFS_permitSymbolicLinks(). That function only deals with symlinks inside the mounted directory or archive.

Parameters

newDir directory or archive to add to the path, in platform-dependent notation.
mountPoint Location in the interpolated tree that this archive will be "mounted", in platform-independent notation. NULL or "" is equivalent to "/".
appendToPath nonzero to append to search path, zero to prepend.

Returns

nonzero if added to path, zero on failure (bogus archive, dir missing, etc). Use PHYSFS_getLastErrorCode() to obtain the specific error.

int PHYSFS_setRoot (const char * archive, const char * subdir)

ينشئ مجلدًا فرعيًا من أرشيف كدليل جذر. يسمح لك هذا بتقييد الملفات التي يمكن الوصول إليها داخل أرشيف معين. على سبيل المثال، إذا كان لديك x.zip بملف في y/z.txt، تم تحميله على /a، وإذا قمت باستدعاء PHYSFS_setRoot("x.zip", "/y")، فإن استدعاء PHYSFS_openRead("/a/z.txt") سينجح.

يمكنك تغيير الدليل الجذر لأرشيف في أي وقت، وبالتالي تعديل شجرة الملفات المستنتجة (اعتمادًا على مكان مطابقة المسارات، يمكن لأرشيف مختلف توفير ملفات مختلفة). إذا قمت بتعيين الدليل الجذر إلى NULL أو إلى "/"، فسيتم التعامل مع الأرشيف كما لو لم يتم تعيينه بشكل خاص (كما لو تم تحميل الأرشيف بشكل طبيعي).

تغيير الدليل الجذر يؤثر فقط على العمليات المستقبلية على مسارات الملفات؛ لن يتأثر ملف تم فتحه من مسار تم تغييره بسبب setRoot.

لا يقتصر تعيين دليل جذر جديد على الملفات الموجودة في مسار البحث؛ يمكنك تعيينه إلى دليل الكتابة أيضًا، والذي قد يكون مفيدًا إذا كان لديك ملفات مفتوحة للكتابة ولا يمكنك تغيير دليل الكتابة حاليًا.

ليس خطأ تعيين دليل فرعي غير موجود كدليل جذر لأرشيف؛ ومع ذلك، لن يتم رؤية أي ملفات في هذه الحالة. إذا تم إنشاء الأدلة المفقودة في النهاية (mkdir إلى نظام الملفات الفعلي، وما إلى ذلك)، فسيتم عكس ذلك في الشجرة المستنتجة.

المعلمات

archive الدليل/الأرشيف الذي سيتم تغيير الدليل الجذر فيه.
subdir الدليل الفرعي الجديد لجعله الدليل الجذر لهذا الأرشيف.

العودة

غير صفري عند النجاح، وصفر عند الخطأ. استخدم PHYSFS_getLastErrorCode() للحصول على الخطأ المحدد.

int PHYSFS_setSaneConfig (const char * organization, const char * appName, const char * archiveExt, int includeCdRoms, int archivesFirst)

يضبط مسارات منطقية، مسارات افتراضية. وظيفة مساعدة.

سيتم تعيين دليل الكتابة إلى الدليل المفضل الذي تم إرجاعه بواسطة

PHYSFS_getPrefDir(organization, appName)

، والذي يتم إنشاؤه إذا لم يكن موجودًا.

الجزء أعلاه كافٍ لضمان أن مجلد تكوين برنامجك منفصل عن الفوضى الأخرى ومستقل عن نظام التشغيل.

سيكون مسار البحث:

  • دليل الكتابة (تم إنشاؤه إذا لم يكن موجودًا)
  • الدليل الأساسي (PHYSFS_getBaseDir())
  • جميع أدلة CD-ROM التي تم العثور عليها (اختياري)

يتم البحث في هذه الأدلة عن الامتدادات (archiveExt)، والتي، إذا كانت صالحة ومدعومة، يتم إضافتها أيضًا إلى مسار البحث. إذا حددت "PKG" لـ (archiveExt)، وكان هناك ملف يسمى data.PKG في الدليل الأساسي، فسيتم التحقق منه. يمكن إضافة الأرشيفات أو إلحاقها بمسار البحث بترتيب أبجدي، بغض النظر عن مكان العثور عليها. يتم تحميل جميع الأرشيفات في جذر نظام الملفات الافتراضي ("/") .

يمكن القيام بكل ما سبق من التطبيق، ولكن هذا يفعل كل شيء لك. يمكنك إضافة المزيد إلى مسار البحث يدويًا أيضًا.

المعلمات

organization اسم شركتك/مجموعتك/إلخ لاستخدامه كاسم دليل، لذا حافظ عليه صغيرًا وبسيطًا.
appName اسم برنامجك المحدد، لفصله عن البرامج الأخرى التي تستخدم PhysicsFS.
archiveExt الامتداد الذي يستخدمه برنامجك لتحديد أرشيف. على سبيل المثال، يستخدم Quake 3 "pk3"، على الرغم من أنها مجرد ملفات مضغوطة. حدد NULL لعدم البحث تلقائيًا عن الأرشيفات. لا تحدد الحرف "." إذا كنت تريد البحث عن ملفات ZIP، فحدد "ZIP" وليس ".ZIP" ... البحث عن الملفات غير حساس لحالة الأحرف.
includeCdRoms غير صفري لتضمين أقراص CD-ROM في مسار البحث، و (إذا كان (archiveExt) != NULL) للبحث عنها بحثًا عن الأرشيفات. قد يؤدي هذا إلى إغلاق كبير أثناء الوصول إلى الأقراص، وإذا لم تكن هناك أقراص في محرك الأقراص (أو حتى لم يتم تحميلها في أنظمة Unix)، فقد لا تكون متاحة. يمكنك تحديد صفر والتعامل مع تكوين القرص بنفسك.
archivesFirst غير صفري لإلحاق الأرشيفات بمسار البحث. صفر لإلحاقها. يتم تجاهلها إذا كان !(archiveExt).

العودة

PHYSFS_ArchiveInfo **i;
for (i = PHYSFS_supportedArchiveTypes(); *i != NULL; i++)

    printf("Supported archive: [%s], which is [%s].\n",
             (*i)->extension, (*i)->description);
}
