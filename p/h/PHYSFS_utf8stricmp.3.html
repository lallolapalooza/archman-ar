PHYSFS_enumerateFiles

PHYSFS_enumerateFiles

char **PHYSFS_enumerateFiles(const char *directory);

Get a list of all files and directories in a given directory.

The list is terminated by a NULL pointer. The list itself and all strings it contains are allocated with malloc() and must be freed with PHYSFS_freeList().

The directory paths are formed by concatenating the given directory with each entry found. You can recreate the full path to an entry with $origdir/$fname, where $origdir is the directory passed to the function, and $fname is the entry name from the list. As of PhysicsFS 1.1, the directory parameter is assumed to be a path relative to the current working directory, or an absolute path.

Parameters

directory The directory to list. If NULL, the current working directory is used.

Returns

A NULL-terminated array of strings, representing the files and directories in the specified directory. Returns NULL on error.

Warning

As of PhysicsFS 2.1, the callback-based PHYSFS_enumerate() is preferred; it is more efficient and provides more control.

PHYSFS_getVersion

PHYSFS_Version PHYSFS_VERSION;

This is a macro that defines the version of the PhysicsFS library that was compiled with. It is defined in `physfs.h`.

The version is represented as a triple of integers: MAJOR.MINOR.PATCH. For example, version 2.0.1 would be represented as (2,0,1).

You can use this macro to check the version of the library at compile time. For example:

#if PHYSFS_VERSION_MAJOR > 2 || \
    (PHYSFS_VERSION_MAJOR == 2 && PHYSFS_VERSION_MINOR > 0) || \
    (PHYSFS_VERSION_MAJOR == 2 && PHYSFS_VERSION_MINOR == 0 && PHYSFS_VERSION_PATCH >= 1)
    // Code for PhysicsFS 2.0.1 or later
#endif

Note that this macro represents the version of the library headers you compiled against. If you dynamically linked the library, you might have a slightly newer or older version at runtime. That version can be determined with PHYSFS_getLinkedVersion(), which, unlike PHYSFS_VERSION, is not a macro.

Parameters

x A pointer to a PHYSFS_Version struct to initialize.

PHYSFS_EnumerateCallbackResult

typedef void(* PHYSFS_EnumFilesCallback) (void *data, const char *origdir, const char *fname)

Function signature for callbacks that enumerate files.

Warning

As of PhysicsFS 2.1, Use PHYSFS_EnumerateCallback with PHYSFS_enumerate() instead; it gives you more control over the process.

These are used to report a list of directory entries to an original caller, one file/dir/symlink per callback. All strings are UTF-8 encoded. Functions should not try to modify or free any string's memory.

These callbacks are used, starting in PhysicsFS 1.1, as an alternative to functions that would return lists that need to be cleaned up with PHYSFS_freeList(). The callback means that the library doesn't need to allocate an entire list and all the strings up front.

Be aware that promised data ordering in the list versions are not necessarily so in the callback versions. Check the documentation on specific APIs, but strings may not be sorted as you expect and you might get duplicate strings.

Parameters

data User-defined data pointer, passed through from the API that eventually called the callback.
origdir A string containing the full path, in platform-independent notation, of the directory containing this file. In most cases, this is the directory on which you requested enumeration, passed in the callback for your convenience.
fname The filename that is being enumerated. It may not be in alphabetical order compared to other callbacks that have fired, and it will not contain the full path. You can recreate the fullpath with $origdir/$fname ... The file can be a subdirectory, a file, a symlink, etc.

Values that represent specific causes of failure. Most of the time, you should only concern yourself with whether a given operation failed or not, but there may be occasions where you plan to handle a specific failure case gracefully, so we provide specific error codes.

سيقوم بالإبلاغ عن أي سلسلة "أكبر من" الأخرى، ولكن كن على علم أن هذا لا يعني بالضرورة شيئًا: قد تكون 'a' "أقل من" 'b'، ولكن لا توجد علاقة أبجدية ذات مغزى بين Kuten ياباني وحرف لامدا يوناني، ولكن القدرة على تعيين "قيمة" موثوقة تجعل خوارزميات الفرز ممكنة، وإن لم تكن منطقية تمامًا. يجب على معظم الحالات التعامل مع القيمة المرجعة على أنها "متساوية" أو "غير متساوية".

مثل stricmp، يتوقع أن تكون كلتا السلسلتين منتهيتين بحرف null.

str2 السلسلة الثانية للمقارنة.

القيم المعادة

-1 إذا كانت السلسلة str1 "أقل من" str2، و 1 إذا كانت "أكبر من"، و 0 إذا كانت متساوية.

تحويل سلسلة نصية بصيغة UTF-8 إلى سلسلة نصية بصيغة UCS-2.

تحذير

من شبه المؤكد أنك يجب أن تستخدم PHYSFS_utf8ToUtf16()، التي أصبحت متاحة في PhysicsFS 2.1، إلا إذا كنت تعرف ما تفعله.

لن تقوم هذه الدالة بالإبلاغ عن خطأ إذا كانت هناك تسلسلات UTF-8 غير صالحة في السلسلة المصدر. ستقوم باستبدالها بحرف '؟' وتستمر.

سلاسل UCS-2 هي 16 بت لكل حرف: TCHAR على Windows، عند البناء بدعم Unicode. يرجى ملاحظة أن الإصدارات الحديثة من Windows تستخدم UTF-16، وهو شكل موسع من UCS-2، وليس UCS-2 نفسه. من شبه المؤكد أنك تريد PHYSFS_utf8ToUtf16() بدلاً من ذلك، ولكنك تحتاج إلى فهم كيف يغير ذلك الأمور أيضًا.

لضمان أن يكون المخزن المؤقت الوجهة كبيرًا بما يكفي للتحويل، يرجى تخصيص مخزن مؤقت بحجم ضعف حجم المخزن المؤقت المصدر. تستخدم UTF-8 من بايت واحد إلى أربعة بايتات لكل حرف، ولكن UCS-2 دائمًا ما يستخدم بايتين، لذلك ستتضاعف حجم السلسلة ذات ASCII المنخفضة بالكامل!

سيتم اقتطاع السلاسل النصية التي لا تناسب المخزن المؤقت الوجهة، ولكنها ستنتهي دائمًا بحرف null ولن تحتوي أبدًا على تسلسل UCS-2 غير مكتمل في النهاية. إذا كان طول المخزن المؤقت 0، فلن تقوم هذه الدالة بأي شيء.

void PHYSFS_utf8ToUtf16 (const char * src, PHYSFS_uint16 *dst, PHYSFS_uint64 len)

تحويل سلسلة نصية بصيغة UTF-8 إلى سلسلة نصية بصيغة UTF-16.

تحذير

هذه الدالة لن تبلغ عن خطأ إذا كانت هناك تسلسلات غير صالحة بصيغة UTF-8 في السلسلة المصدر. ستقوم باستبدالها بحرف '؟' وتتابع العملية.

السلاسل النصية بصيغة UTF-16 هي 16 بت لكل حرف (باستثناء بعض الأحرف التي تكون 32 بت): TCHAR على Windows، عند البناء مع دعم Unicode. إصدارات Windows الحديثة تستخدم UTF-16. إصدارات Windows قبل عام 2000 استخدمت TCHAR، لكنها تعاملت فقط مع UCS-2. UTF-16 *هو* UCS-2، باستثناء الأحرف التي تتكون من 4 بايت، والتي لا يمكن تمثيلها في UCS-2 على أي حال. إذا لم تكن متأكدًا، يجب عليك استخدام UTF-16 في هذه المرحلة على Windows.

للتأكد من أن المخزن المؤقت الوجهة كبير بما يكفي للتحويل، يرجى تخصيص مخزن مؤقت بحجم مضاعف لحجم المخزن المؤقت المصدر. تستخدم UTF-8 من بايت واحد إلى أربعة بايتات لكل حرف، ولكن UTF-16 تستخدم دائمًا من اثنين إلى أربعة، لذا فإن سلسلة ASCII منخفضة بالكامل ستتضاعف في الحجم! الأحرف بصيغة UTF-16 التي تتطلب أربعة بايتات تتطلب أيضًا أربعة بايتات في UTF-8، لذلك لا تحتاج إلى تخصيص 4 أضعاف المساحة كإجراء احترازي: ضعف الحجم سيكون كافيًا.

سيتم اقتطاع السلاسل النصية التي لا تتناسب مع المخزن المؤقت الوجهة، ولكنها ستنتهي دائمًا بحرف null ولن تحتوي أبدًا على زوج بديل غير مكتمل بصيغة UTF-16 في النهاية. إذا كان طول المخزن المؤقت 0، فلن تقوم هذه الدالة بأي شيء.
