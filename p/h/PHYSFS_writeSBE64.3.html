Error Codes

enum PHYSFS_ErrorCode

Generic error codes. These are the codes returned by functions that can fail. A return value of zero from a PhysicsFS function usually signifies success, while a non-zero value signifies failure. You can get the specific error code for the most recent failure by calling PHYSFS_getLastErrorCode().

Deinitialize the PhysicsFS library. This closes any files opened via PhysicsFS, blanks the search/write paths, frees memory, and invalidates all of your file handles.

int PHYSFS_delete (const char * filename)

Delete a file or directory. (filename) is specified in platform-independent notation in relation to the write dir.

A directory must be empty before this call can delete it.

Deleting a symlink will remove the link, not what it points to, regardless of whether you "permitSymLinks" or not.

So if you've got the write dir set to "C:\mygame\writedir" and call PHYSFS_delete("downloads/maps/level1.map") then the file "C:\mygame\writedir\downloads\maps\level1.map" is removed from the physical filesystem, if it exists and the operating system permits the deletion.

int PHYSFS_enumerate (const char * dir, PHYSFS_EnumerateCallback c, void * d)

Obtener una lista de archivos de un directorio de una ruta de búsqueda, usando un callback definido por la aplicación, con errores reportados. Internamente, PHYSFS_enumerateFiles() solo llama a esta función y luego construye una lista antes de devolver a la aplicación, así que la funcionalidad es idéntica, excepto por cómo la información se presenta a la aplicación.

Diferente de PHYSFS_enumerateFiles(), esta función no devuelve un array. En lugar de eso, llama a una función especificada por la aplicación una vez por cada elemento de la ruta de búsqueda:

static PHYSFS_EnumerateCallbackResult printDir(void *data, const char *origdir, const char *fname)
{
    printf(" * We've got [%s] in [%s].\n", fname, origdir);
    return PHYSFS_ENUM_OK;  // darme más datos, por favor.
}
// ...
PHYSFS_enumerate("/some/path", printDir, NULL);

Los elementos enviados al callback no están garantizados estar en cualquier orden. No se realiza el ordenamiento en este nivel, y si necesitas eso, deberías usar PHYSFS_enumerateFiles(), que garantiza el orden alfabético. Esta forma reporta lo que se encuentra en cada archive antes de pasar a la siguiente. Even within one archive, we can't guarantee the order in which data is discovered. Any sorting you find in these callbacks is just pure luck. Do not rely on it. Como esta camina por toda la lista de archivos, puedes recibir nombres de archivos duplicados.

Esta API y los callbacks mismos pueden reportar errores. Antes de esta API, los callbacks tenían que aceptar cada elemento enumerado, incluso si solo buscaban un específico y querían detenerse después, o tenían un error grave y no podían alertar a nadie. Además, si PhysicsFS mismo tenia un problema (error de disco o lo que sea), no podría reportarlo a la aplicación llamada, simplemente habría de saltar los elementos o detener la enumeración, y el llamador no sabría que había perdido algunos datos durante el camino.

Ahora el llamador puede estar seguro de haber obtenido un conjunto completo de datos, y su callback controla si detiene la enumeración temprano. Consulta la documentación para PHYSFS_EnumerateCallback para detalles de cómo debe comportarse tu callback.

Parámetros

dir Directorio, en notación independiente de plataforma, a enumerar.
c Función de callback para notificar sobre elementos de la ruta.
d Datos definidos por la aplicación pasados al callback. Puede ser NULL.

Devuelve

No cero en éxito, cero en falla. Usa PHYSFS_getLastErrorCode() para obtener el error específico. Si el callback devuelve PHYSFS_ENUM_STOP, esto se considera éxito. Callbacks devolviendo PHYSFS_ENUM_ERROR harán este función devolver cero y establecer el código de error a PHYSFS_ERR_APP_CALLBACK.

char ** PHYSFS_enumerateFiles (const char * dir)

Obtener una lista de archivos de un directorio de una ruta de búsqueda.

Advertencia

En versiones de PhysicsFS anteriores a 2.1, esta función devolvería tantos elementos como fuera posible en caso de una condición de fallo (error de memoria, error de i/o del disco, etc). Debido a esto, los aplicadores no podrían distinguir entre un éxito completo y una falla parcial, y ya que la función podía devolver NULL para reportar fallos catastróficos, en PhysicsFS 2.1 esta política cambió: devolverá una lista completa de resultados o devolverá NULL en caso de cualquier fallo, así podemos garantizar que la enumeración se completó y no hay espacios en sus resultados.

Los directorios coincidentes se interpolan. Es decir, si "C:\mydir" está en la ruta de búsqueda y contiene un directorio "savegames" que contiene "x.sav", "y.sav" y "z.sav", y también hay un directorio "C:\userdir" en la ruta de búsqueda que tiene un subdirectorio "savegames" con "w.sav", entonces el siguiente código:

char **rc = PHYSFS_enumerateFiles("savegames");
char **i;
for (i = rc; *i != NULL; i++)
    printf(" * We've got [%s].\n", *i);
PHYSFS_freeList(rc);
* We've got [x.sav].
* We've got [y.sav].
* We've got [z.sav].
* We've got [w.sav]..
Libremente puedes ordenar la lista como prefieras. Sin embargo, los datos devueltos siempre contienen sin duplicados y están siempre ordenados alfabéticamente (más bien: ordenado por Unicode caso sensible).
Recuerda llamar PHYSFS_freeList() con el valor devuelto de esta función cuando termines con él.
Parámetros
dir directorio en notación independiente de plataforma a enumerar.
Devuelve
Array de strings nulo-terminado de strings nulos, o NULL en casos de falla.

افتراضيًا، ستتحقق PhysicsFS مما إذا كان الملف رابطًا رمزيًا بالفعل أثناء استدعاءات الفتح وستفشل إذا كان كذلك. خلاف ذلك، قد يؤدي الرابط إلى الخروج من مسارات القراءة والكتابة، مما يضر بالأمان.

سيتم اقتطاع السلاسل التي لا تناسب المخزن المؤقت الوجهة، ولكنها ستنتهي دائمًا بحرف null ولن يكون لديها أبدًا تسلسل UTF-8 غير مكتمل في النهاية. إذا كان طول المخزن المؤقت 0، فلن تقوم هذه الوظيفة بأي شيء.

إذا كانت كلتا السلسلتين تتكونان حصريًا من أحرف ASCII المنخفضة، فستعمل هذه الوظيفة بشكل صحيح، لأن هذا يعتبر أيضًا UTF-8 صالحًا. إذا كانت هناك أي أحرف ASCII عالية، فلن تعمل هذه الوظيفة كما تتوقع!

ستبلغ عن أي سلسلة "أكبر من" الأخرى، ولكن كن على علم بأن هذا لا يعني بالضرورة شيئًا: قد تكون 'a' "أقل من" 'b'، ولكن لا توجد علاقة أبجدية ذات معنى بين "kuten" ياباني و "lambda" يوناني، ولكن القدرة على تعيين "قيمة" موثوقة تجعل خوارزميات الفرز ممكنة، حتى لو لم تكن منطقية تمامًا. يجب أن تتعامل معظم الحالات مع القيمة المرجعة على أنها "متساوية" أو "غير متساوية".

الإرجاع

-1 إذا كانت السلسلة الأولى "أقل من" السلسلة الثانية، 1 إذا كانت "أكبر من"، 0 إذا كانت متساوية.

تحويل سلسلة نصية بنظام UTF-8 إلى سلسلة نصية بنظام UCS-2.

تحذير

من شبه المؤكد أنك يجب أن تستخدم PHYSFS_utf8ToUtf16()، والتي أصبحت متاحة في PhysicsFS 2.1، إلا إذا كنت تعرف ما تفعله.

لن تقوم هذه الوظيفة بالإبلاغ عن خطأ إذا كانت هناك تسلسلات UTF-8 غير صالحة في السلسلة المصدر. ستقوم باستبدالها بحرف "?" وتستمر.

سلاسل UCS-2 هي 16 بت لكل حرف: TCHAR على Windows، عند البناء مع دعم Unicode. يرجى ملاحظة أن الإصدارات الحديثة من Windows تستخدم UTF-16، وهو شكل موسع من UCS-2، وليس UCS-2 نفسه. من شبه المؤكد أنك تريد PHYSFS_utf8ToUtf16() بدلاً من ذلك، ولكنك تحتاج إلى فهم كيف يغير ذلك الأمور أيضًا.
