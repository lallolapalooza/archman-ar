Function Documentation

PHYSFS_apiVersion

Return the version of the library you are using.

This is the version of the library that is linked into your application. It is determined by what header the compiler uses. Note that if you dynamically linked the library, you might have a slightly newer or older version at runtime. That version can be determined with PHYSFS_getLinkedVersion(), which, unlike PHYSFS_VERSION, is not a macro.

Parameters

None

Returns

A pointer to a PHYSFS_Version struct that identifies the library's version.

int PHYSFS_deinit(void)

Deinitialize the PhysicsFS library. This closes any files opened via PhysicsFS, blanks the search/write paths, frees memory, and invalidates all of your file handles.

Note that this call can FAIL if there's a file open for writing that refuses to close (for example, the underlying operating system was buffering writes to network filesystem, and the fileserver has crashed, or a hard drive has failed, etc). It is usually best to close all write handles yourself before calling this function, so that you can gracefully handle a specific failure.

Once successfully deinitialized, PHYSFS_init() can be called again to restart the subsystem. All default API states are restored at this point, with the exception of any custom allocator you might have specified, which survives between initializations.

int PHYSFS_delete(const char *filename)

Delete a file or directory. (filename) is specified in platform-independent notation in relation to the write dir.

A directory must be empty before this call can delete it.

Deleting a symlink will remove the link, not what it points to, regardless of whether you "permitSymLinks" or not.

So if you've got the write dir set to "C:\mygame\writedir" and call PHYSFS_delete("downloads/maps/level1.map") then the file "C:\mygame\writedir\downloads\maps\level1.map" is removed from the physical filesystem, if it exists and the operating system permits the deletion.

Note that on Unix systems, deleting a file may be successful, but the actual file won't be removed until all processes that have an open filehandle to it (including your program) close their handles.

Chances are, the bits that make up the file still exist, they are just made available to be written over at a later point. Don't consider this a security method or anything. :)

Parameters

filename Filename to delete.

Returns

nonzero on success, zero on error. Use PHYSFS_getLastErrorCode() to obtain the specific error.

احصل على قائمة ملفات من دليل في مسار بحث، باستخدام دالة استدعاء محددة من قبل التطبيق، مع الإبلاغ عن الأخطاء. داخليًا، PHYSFS_enumerateFiles() تستدعي هذه الدالة فقط ثم تبني قائمة قبل العودة إلى التطبيق، لذا فإن الوظيفة متطابقة، باستثناء كيفية تقديم المعلومات إلى التطبيق.

على عكس PHYSFS_enumerateFiles()، هذه الدالة لا تعيد مصفوفة. بدلاً من ذلك، تستدعي دالة محددة من قبل التطبيق مرة واحدة لكل عنصر في مسار البحث:

    printf(" * We've got [%s] in [%s].\n", fname, origdir);
    return PHYSFS_ENUM_OK;  // امنحني المزيد من البيانات، من فضلك.
}

يمكن لواجهة برمجة التطبيقات هذه ودوال الاستدعاء نفسها الإبلاغ عن الأخطاء. قبل واجهة برمجة التطبيقات هذه، كان على دوال الاستدعاء قبول كل عنصر تم سرده، حتى لو كانوا يبحثون عن عنصر معين فقط ويريدون التوقف بعد ذلك، أو كان لديهم خطأ فادح ولم يتمكنوا من تنبيه أي شخص. علاوة على ذلك، إذا كانت PhysicsFS نفسها بها مشكلة (خطأ في القرص أو ما شابه)، فلن تتمكن من إبلاغ التطبيق المستدعي، بل سيتعين عليها فقط تخطي العناصر أو إيقاف التعداد تمامًا، ولن يعرف المستدعي أنه فقد بعض البيانات في الطريق.

الآن يمكن للمستدعي التأكد من حصوله على مجموعة كاملة من البيانات، وإذا أراد إيقاف التعداد مبكرًا، فسيكون لدى دالة الاستدعاء الخاصة به التحكم. راجع وثائق PHYSFS_EnumerateCallback للحصول على تفاصيل حول كيفية سلوك دالة الاستدعاء الخاصة بك.

تحذير

اعتبارًا من PhysicsFS 2.1، تم إضعاف هذه الدالة. قبل PhysicsFS 2.1، كانت هذه الدالة هي الطريقة الوحيدة للحصول على تفاصيل الأخطاء بخلاف القيمة الأساسية المُعادة من دالة معينة. كان المقصود منها أن تكون سلسلة نصية سهلة القراءة بإحدى لغات متعددة، ولم تكن مفيدة لتحليل التطبيق. كان هذا مشكلة، لأن المطور وليس المستخدم هو من يختار اللغة وقت الترجمة، وكان على القائمين على صيانة PhysicsFS (بشكل سيء) صيانة قدر كبير من العمل المحلي. لم يتمكن التطبيق من تحليل السلاسل النصية، حتى لو اعتمد على لغة معينة، لأن بعضها كان يتم إنشاؤه ديناميكيًا. في الإصدار 2.1 والإصدارات الأحدث، تعيد هذه الدالة دائمًا سلسلة نصية ثابتة باللغة الإنجليزية؛ يمكنك استخدامها كسلسلة مفتاح لترجماتك الخاصة إذا أردت، حيث سنعد بعدم تغيير سلاسل الأخطاء الحالية. أيضًا، إذا أراد تطبيقك النظر إلى أخطاء محددة، فإننا نقدم الآن خيارًا أفضل: استخدم PHYSFS_getLastErrorCode() بدلاً من ذلك.

الحصول على رسالة خطأ PhysicsFS الأخيرة كسلسلة نصية سهلة القراءة ومنتهية بـ NULL. سيعيد هذا NULL إذا لم يكن هناك خطأ منذ آخر استدعاء لهذه الدالة. المؤشر المُعاد بواسطة هذا الاستدعاء يشير إلى مخزن مؤقت داخلي. كل خيط له حالة خطأ فريدة مرتبطة به، ولكن في كل مرة يتم فيها تعيين رسالة خطأ جديدة، فإنها ستتجاوز الرسالة السابقة المرتبطة بهذا الخيط. من الآمن استدعاء هذه الدالة في أي وقت، حتى قبل PHYSFS_init().

PHYSFS_getLastError() و PHYSFS_getLastErrorCode() يقومان بإعادة تعيين نفس حالة الخطأ الخاصة بالخيط. استدعاء أحدهما سيمحو بيانات الآخر. إذا كنت بحاجة إلى كليهما، استدع PHYSFS_getLastErrorCode()، ثم مرر هذه القيمة إلى PHYSFS_getErrorByCode().

اعتبارًا من PhysicsFS 2.1، تعرض هذه الدالة النصوص باللغة الإنجليزية فقط، ولكن السلاسل النصية ثابتة، لذا يمكنك استخدامها كمفاتيح في قاموس الترجمة الخاص بك. هذه السلاسل النصية مخصصة ليتم تمريرها مباشرة إلى المستخدم.

بشكل عام، يجب على التطبيقات الاهتمام فقط بما إذا كانت دالة معينة قد فشلت؛ ومع ذلك، إذا كان الكود الخاص بك يتطلب مزيدًا من التفاصيل، فيجب عليك استخدام PHYSFS_getLastErrorCode() بدلاً من هذه الدالة.

int PHYSFS_mount (const char * newDir, const char * mountPoint, int appendToPath)

Add an archive or directory to the search path. If this is a duplicate, the entry is not added again, even though the function succeeds. You may not add the same archive to two different mountpoints: duplicate checking is done against the archive and not the mountpoint.

When you mount an archive, it is added to a virtual file system...all files in all of the archives are interpolated into a single hierachical file tree. Two archives mounted at the same place (or an archive with files overlapping another mountpoint) may have overlapping files: in such a case, the file earliest in the search path is selected, and the other files are inaccessible to the application. This allows archives to be used to override previous revisions; you can use the mounting mechanism to place archives at a specific point in the file tree and prevent overlap; this is useful for downloadable mods that might trample over application data or each other, for example.

The mountpoint does not need to exist prior to mounting, which is different than those familiar with the Unix concept of "mounting" may expect. As well, more than one archive can be mounted to the same mountpoint, or mountpoints and archive contents can overlap...the interpolation mechanism still functions as usual.

Specifying a symbolic link to an archive or directory is allowed here, regardless of the state of PHYSFS_permitSymbolicLinks(). That function only deals with symlinks inside the mounted directory or archive.

Parameters

newDir directory or archive to add to the path, in platform-dependent notation.
mountPoint Location in the interpolated tree that this archive will be "mounted", in platform-independent notation. NULL or "" is equivalent to "/".
appendToPath nonzero to append to search path, zero to prepend.

Returns

nonzero if added to path, zero on failure (bogus archive, dir missing, etc). Use PHYSFS_getLastErrorCode() to obtain the specific error.

void PHYSFS_utf8FromLatin1 (const char * src, char * dst, PHYSFS_uint64 len)

تحويل سلسلة UTF-8 إلى سلسلة Latin1. سلاسل Latin1 هي 8 بتات لكل حرف: ترميز شائع "لـ ASCII العالي".

للتأكد من أن المخزن المؤقت الوجهة كبير بما يكفي للتحويل، يرجى تخصيص مخزن مؤقت بحجم ضعف حجم المخزن المؤقت المصدر. تقوم UTF-8 بتوسيع نقاط ترميز Latin1 فوق 127 من بايت واحد إلى بايتين، لذا قد تنمو السلسلة في بعض الحالات.

سيتم اقتطاع السلاسل التي لا تتناسب مع المخزن المؤقت الوجهة، ولكنها ستنتهي دائمًا بحرف NULL ولن تحتوي أبدًا على تسلسل UTF-8 غير مكتمل في النهاية. إذا كان طول المخزن المؤقت 0، فلن تقوم هذه الوظيفة بأي شيء.

يرجى ملاحظة أننا لا نقدم محول من UTF-8 إلى Latin1، لأن Latin1 لا يمكنه تمثيل معظم نقاط ترميز Unicode. إنه ترميز قديم؛ يجب عليك التحويل بعيدًا عنه في جميع الأوقات.

dst المخزن المؤقت لتخزين سلسلة UTF-8 المحولة.

void PHYSFS_utf8FromUcs2 (const PHYSFS_uint16 * src, char * dst, PHYSFS_uint64 len)

تحويل سلسلة UCS-2 إلى سلسلة UTF-8.

تحذير

من شبه المؤكد أنك يجب أن تستخدم PHYSFS_utf8FromUtf16()، التي أصبحت متاحة في PhysicsFS 2.1، إلا إذا كنت تعرف ما تفعله.

لن تقوم هذه الوظيفة بالإبلاغ عن خطأ إذا كانت هناك قيم UCS-2 غير صالحة في السلسلة المصدر. ستقوم باستبدالها بحرف '؟' وتستمر.

سلاسل UCS-2 هي 16 بت لكل حرف: TCHAR على Windows، عند البناء مع دعم Unicode. يرجى ملاحظة أن الإصدارات الحديثة من Windows تستخدم UTF-16، وهي شكل ممتد من UCS-2، وليس UCS-2 نفسه. أنت شبه المؤكد تريد PHYSFS_utf8FromUtf16() بدلاً من ذلك.

للتأكد من أن المخزن المؤقت الوجهة كبير بما يكفي للتحويل، يرجى تخصيص مخزن مؤقت بحجم ضعف حجم المخزن المؤقت المصدر. لا تستخدم UTF-8 أبدًا أكثر من 32 بت لكل حرف، لذا بينما قد تقلص سلسلة UCS-2، فقد تتوسع أيضًا.

سيتم اقتطاع السلاسل التي لا تتناسب مع المخزن المؤقت الوجهة، ولكنها ستنتهي دائمًا بحرف NULL ولن تحتوي أبدًا على تسلسل UTF-8 غير مكتمل في النهاية. إذا كان طول المخزن المؤقت 0، فلن تقوم هذه الوظيفة بأي شيء.

لن تقوم هذه الوظيفة بالإبلاغ عن خطأ إذا كانت هناك قيم UCS-4 غير صالحة في السلسلة المصدر. ستقوم باستبدالها بحرف '؟' وتستمر.

سلاسل UCS-4 (المعروفة أيضًا باسم UTF-32) هي 32 بت لكل حرف: wchar_t على Unix.

للتأكد من أن المخزن المؤقت الوجهة كبير بما يكفي للتحويل، يرجى تخصيص مخزن مؤقت بحجم مساوٍ لحجم المخزن المؤقت المصدر. لا تستخدم UTF-8 أبدًا أكثر من 32 بت لكل حرف، لذا بينما قد تقلص سلسلة UCS-4، فلن تتوسع أبدًا.

سيتم اقتطاع السلاسل التي لا تتناسب مع المخزن المؤقت الوجهة، ولكنها ستنتهي دائمًا بحرف NULL ولن تحتوي أبدًا على تسلسل UTF-8 غير مكتمل في النهاية. إذا كان طول المخزن المؤقت 0، فلن تقوم هذه الوظيفة بأي شيء.

تحويل سلسلة UTF-16 إلى سلسلة UTF-8.

تحذير

لن تقوم هذه الوظيفة بالإبلاغ عن خطأ إذا كانت هناك تسلسلات UTF-16 غير صالحة في السلسلة المصدر. ستقوم باستبدالها بحرف '؟' وتستمر.

سلاسل UTF-16 هي 16 بت لكل حرف (باستثناء بعض الأحرف، التي تكون 32 بت): TCHAR على Windows، عند البناء مع دعم Unicode. تستخدم إصدارات Windows الحديثة UTF-16. استخدمت إصدارات Windows قبل عام 2000 TCHAR، ولكنها تعاملت فقط مع UCS-2. UTF-16 هو UCS-2، باستثناء الأحرف التي تكون 4 بايت، والتي لا يمكن تمثيلها في UCS-2 على الإطلاق على أي حال. إذا لم تكن متأكدًا، فيجب عليك استخدام UTF-16 في هذه المرحلة على Windows.

للتأكد من أن المخزن المؤقت الوجهة كبير بما يكفي للتحويل، يرجى تخصيص مخزن مؤقت بحجم ضعف حجم المخزن المؤقت المصدر. لا تستخدم UTF-8 أبدًا أكثر من 32 بت لكل حرف، لذا بينما قد تقلص سلسلة UTF-16، فقد تتوسع أيضًا.

سيتم اقتطاع السلاسل التي لا تتناسب مع المخزن المؤقت الوجهة، ولكنها ستنتهي دائمًا بحرف NULL ولن تحتوي أبدًا على تسلسل UTF-8 غير مكتمل في النهاية. إذا كان طول المخزن المؤقت 0، فلن تقوم هذه الوظيفة بأي شيء.

int PHYSFS_utf8stricmp (const char * str1, const char * str2)

مقارنة غير حساسة لحالة الأحرف لسلسلتين UTF-8. هذا بديل لـ strcasecmp/stricmp يتوقع أن تكون كلتا السلسلتين بتشفير UTF-8. سيقوم "بطي حالة الأحرف" لتحديد ما إذا كانت نقاط ترميز Unicode في السلاسل متطابقة.

إذا كانت كلتا السلسلتين حصريًا أحرف ASCII منخفضة، فستقوم هذه الوظيفة بالمطلوب، لأن هذا أيضًا UTF-8 صالح. إذا كانت هناك أي أحرف ASCII عالية، فلن تفعل هذه الوظيفة ما تتوقعه!

ستبلغ عن السلسلة التي هي "أكبر من" الأخرى، ولكن كن على علم بأن هذا لا يعني بالضرورة شيئًا: قد تكون 'a' "أقل من" 'b'، ولكن لا توجد علاقة أبجدية ذات معنى بين Kuten ياباني و Lambda يوناني، ولكن القدرة على تعيين "قيمة" موثوقة تجعل خوارزميات الفرز ممكنة، حتى لو لم تكن منطقية تمامًا. يجب أن يعامل معظم الحالات القيمة المرجعة على أنها "متساوية" أو "غير متساوية".

مثل stricmp، تتوقع هذه الوظيفة أن تكون كلتا السلسلتين منتهيتين بـ NULL.

المعلمات

str1 السلسلة الأولى للمقارنة.
str2 السلسلة الثانية للمقارنة.

القيم المرجعة

-1 إذا كانت السلسلة الأولى "أقل من" السلسلة الثانية، 1 إذا كانت "أكبر من"، 0 إذا كانت متساوية.

void PHYSFS_utf8ToUcs2 (const char * src, PHYSFS_uint16 * dst, PHYSFS_uint64 len)

تحويل سلسلة UTF-8 إلى سلسلة UCS-2.

تحذير

من شبه المؤكد أنك يجب أن تستخدم PHYSFS_utf8ToUtf16()، التي أصبحت متاحة في PhysicsFS 2.1، إلا إذا كنت تعرف ما تفعله.

لن تقوم هذه الوظيفة بالإبلاغ عن خطأ إذا كانت هناك تسلسلات UTF-8 غير صالحة في السلسلة المصدر. ستقوم باستبدالها بحرف '؟' وتستمر.

سلاسل UCS-2 هي 16 بت لكل حرف: TCHAR على Windows، عند البناء مع دعم Unicode. يرجى ملاحظة أن الإصدارات الحديثة من Windows تستخدم UTF-16، وهي شكل ممتد من UCS-2، وليس UCS-2 نفسه. أنت شبه المؤكد تريد PHYSFS_utf8ToUtf16() بدلاً من ذلك، ولكن عليك أن تفهم كيف يغير ذلك الأمور أيضًا.
