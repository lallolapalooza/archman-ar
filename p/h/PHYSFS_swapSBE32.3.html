احصل على معلومات الخطأ بصيغة بشرية.

مهمل

استخدم PHYSFS_getLastErrorCode() و PHYSFS_getErrorByCode() بدلاً من ذلك.

ملاحظة

منذ PhysicsFS 2.1، تم "إضعاف" هذه الوظيفة. قبل 2.1، كانت هذه هي الطريقة الوحيدة للحصول على تفاصيل الخطأ خارج القيم المرجعة لوظيفة فردية. كانت هذه عن قصد سلسلة نصية بشرية بلغة واحدة من عدة لغات، ولكنها غير مفيدة لتحليل التطبيق. كانت مشكلة، حيث كان المطور، وليس المستخدم، يختار اللغة وقت الترجمة، وكان على صياني PhysicsFS (بشكل سيء للغاية) الحفاظ على كمية كبيرة من أعمال الترجمة. لم يتمكن التطبيق من تحليل السلاسل النصية، حتى لو كان يعتمد على لغة معينة، لأن بعضها تم إنشاؤه ديناميكيًا. منذ 2.1 وما بعده، فإنها تعيد دائمًا سلسلة نصية ثابتة باللغة الإنجليزية؛ يمكنك استخدامها كمفتاح لترجمتك الخاصة إذا رغبت في ذلك، حيث نتعهد بعدم تغيير السلاسل القديمة. علاوة على ذلك، إذا كان تطبيقك يريد رؤية أخطاء محددة، فإننا نقدم الآن خيارًا أفضل: استخدم PHYSFS_getLastErrorCode().

احصل على آخر رسالة خطأ من PhysicsFS كسلسلة نصية قابلة للقراءة البشرية، منتهية بـ NULL. ستعيد NULL إذا لم يكن هناك خطأ منذ آخر استدعاء لهذه الوظيفة. يشير المؤشر المرجع إلى مخزن مؤقت داخلي. كل خيط له حالة خطأ فريدة مرتبطة به، ولكن في كل مرة يتم فيها تعيين رسالة خطأ جديدة، فإنها تحدّث الحالة السابقة المرتبطة بهذا الخيط. من الآمن استدعاء هذه الوظيفة في أي وقت، حتى قبل PHYSFS_init().

PHYSFS_getLastError() و PHYSFS_getLastErrorCode() كلاهما يعيدان تعيين نفس حالة الخطأ الخاصة بالخيط. استدعاء أحدهما سيمحو بيانات الآخر. إذا كنت بحاجة إلى كليهما، فاستدع PHYSFS_getLastErrorCode()، ثم قم بتمرير تلك القيمة إلى PHYSFS_getErrorByCode().

منذ PhysicsFS 2.1، تقدم هذه الوظيفة نصوصًا باللغة الإنجليزية فقط، ولكن السلاسل النصية ثابتة، لذلك يمكنك استخدامها كمفاتيح في قاموس الترجمة الخاص بك. يمكن تمرير هذه السلاسل مباشرة إلى المستخدم.

بشكل عام، تهتم التطبيقات فقط بما إذا كانت وظيفة ما قد فشلت؛ ومع ذلك، إذا كان الكود الخاص بك يتطلب مزيدًا من التفاصيل، فيجب عليك استخدام PHYSFS_getLastErrorCode() بدلاً من هذه الوظيفة.

Set the buffer size for a file handle. This controls how much data is buffered in RAM before being written to disk (for output streams), or how much data is read from disk at once (for input streams).

A buffer size of zero will disable buffering and cause every read and write to go directly to the underlying file system. Note that this implicitly causes a flush...check your return values!

Seeking, etc transparently accounts for buffering.

PhysicsFS file handles are unbuffered by default.

The write dir will be set to the pref dir returned by

  • The Base Dir (PHYSFS_getBaseDir())
  • All found CD-ROM dirs (optionally)

Detailed Description

These are convenience functions for writing simple integer types to a file handle. They will convert the value from the platform's native byte order to the specified endianness (either big-endian or little-endian) before writing.

The swap functions (PHYSFS_swapSBE16, etc.) convert the value from the platform's native byte order to the specified byte order, and return the new value. They don't write anything to disk.

The write functions (PHYSFS_writeUBE16, etc.) convert the value from the platform's native byte order to the specified byte order and write it to the specified file handle.

All functions return zero on failure, non-zero on success.
