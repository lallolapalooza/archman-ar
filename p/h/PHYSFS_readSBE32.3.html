int PHYSFS_caseFold (const PHYSFS_uint32 from, PHYSFS_uint32 * to)

"Fold" a Unicode codepoint to a lowercase equivalent. (This is for limited, hardcore use. If you don't immediately see a need for it, you can probably ignore this forever.)

This will convert a Unicode codepoint into its lowercase equivalent. Bogus codepoints and codepoints without a lowercase equivalent will be returned unconverted.

Note that you might get multiple codepoints in return! The German Eszett, for example, will fold down to two lowercase latin 's' codepoints. The theory is that if you fold two strings, one with an Eszett and one with "SS" down, they will match.

Warning

Anyone that is a student of Unicode knows about the "Turkish I" problem. This API does not handle it. Assume this one letter in all of Unicode will definitely fold sort of incorrectly. If you don't know what this is about, you can probably ignore this problem for most of the planet, but perfection is impossible.

Parameters

from The codepoint to fold.
to Buffer to store the folded codepoint values into. This should point to space for at least 3 PHYSFS_uint32 slots.

Returns

The number of codepoints the folding produced. Between 1 and 3.

int PHYSFS_deinit (void )

Deinitialize the PhysicsFS library. This closes any files opened via PhysicsFS, blanks the search/write paths, frees memory, and invalidates all of your file handles.

Note that this call can FAIL if there's a file open for writing that refuses to close (for example, the underlying operating system was buffering writes to network filesystem, and the fileserver has crashed, or a hard drive has failed, etc). It is usually best to close all write handles yourself before calling this function, so that you can gracefully handle a specific failure.

Once successfully deinitialized, PHYSFS_init() can be called again to restart the subsystem. All default API states are restored at this point, with the exception of any custom allocator you might have specified, which survives between initializations.

Returns

nonzero on success, zero on error. Specifics of the error can be gleaned from PHYSFS_getLastError(). If failure, state of PhysFS is undefined, and probably badly screwed up.

int PHYSFS_delete (const char * filename)

Delete a file or directory. (filename) is specified in platform-independent notation in relation to the write dir.

A directory must be empty before this call can delete it.

Deleting a symlink will remove the link, not what it points to, regardless of whether you "permitSymLinks" or not.

So if you've got the write dir set to "C:\mygame\writedir" and call PHYSFS_delete("downloads/maps/level1.map") then the file "C:\mygame\writedir\downloads\maps\level1.map" is removed from the physical filesystem, if it exists and the operating system permits the deletion.

Note that on Unix systems, deleting a file may be successful, but the actual file won't be removed until all processes that have an open filehandle to it (including your program) close their handles.

Chances are, the bits that make up the file still exist, they are just made available to be written over at a later point. Don't consider this a security method or anything. :)

Parameters

filename Filename to delete.

Returns

nonzero on success, zero on error. Use PHYSFS_getLastErrorCode() to obtain the specific error.

const char * PHYSFS_getErrorByCode (PHYSFS_ErrorCode code)

الحصول على وصف نصي سهل القراءة لرمز خطأ معين. يعيد سلسلة ثابتة، بتنسيق UTF-8، والتي تمثل وصفًا باللغة الإنجليزية لرمز الخطأ المحدد.

يُضمن أن هذه السلاسل لن تتغير (على الرغم من أنه قد نضيف سلاسل جديدة لرموز خطأ جديدة في إصدارات مستقبلية من PhysicsFS)، لذا يمكنك استخدامها كمفتاح لقاموس ترجمة.

من الآمن استدعاء هذه الدالة في أي وقت، حتى قبل PHYSFS_init().

هذه السلاسل مخصصة للتمرير مباشرة إلى المستخدم. بشكل عام، تهتم التطبيقات فقط بما إذا فشلت دالة معينة، ولكن ليس كثيرًا بالتفاصيل المحددة.

لا تحاول تحرير السلاسل التي تم إرجاعها؛ فهي للقراءة فقط ولا تملك مساحة الذاكرة الخاصة بصفحاتها.

المعلمات

code رمز الخطأ لتحويله إلى سلسلة نصية.

يعيد

سلسلة نصية منتهية بـ NULL لرسالة الخطأ المطلوبة، NULL إذا لم يكن رمز خطأ صالحًا من PhysicsFS. تحقق دائمًا من NULL إذا كنت تبحث عن رمز خطأ لم يكن موجودًا في إصدار سابق من PhysicsFS.

void PHYSFS_utf8ToUtf32 (PHYSFS_utf8_t * src, PHYSFS_utf32_t * dst, PHYSFS_uint64 len)

Convertir una cadena UTF-8 en una cadena UCS-4.

Advertencia

Esta función no reportará un error si hay secuencias UTF-8 inválidas en la cadena de entrada. Reemplazará estas secuencias con un carácter '?' y continuará.

Las cadenas UCS-4 tienen 32 bits por carácter. UTF-8 usa de uno a cuatro bytes por carácter. Por lo tanto, cualquier cadena codificada en UTF-8 que encaje en un buffer también lo hará en un buffer UCS-4 del mismo tamaño. Si el tamaño del buffer de destino no es lo suficientemente grande, la cadena de salida será truncada, pero siempre se asegurará de que termine en null y nunca contendrá una secuencia incompleta de UCS-4 al final. Si el tamaño del buffer es 0, esta función no hace nada.

Parámetros

src Cadena de fuente en formato UTF-8 nula.
dst Buffer para almacenar la cadena UCS-4 convertida.
len Tamaño, en bytes, del buffer de destino.

void PHYSFS_utf8ToUtf16 (const char * src, PHYSFS_uint16 * dst, PHYSFS_uint64 len)

Convertir una cadena UTF-8 en una cadena UTF-16.

Advertencia

Esta función no reportará un error si hay secuencias UTF-8 inválidas en la cadena de entrada. Reemplazará estas secuencias con un carácter '?' y continuará.

Las cadenas UTF-16 tienen 16 bits por carácter (a excepción de algunos caracteres, que son 32 bits): TCHAR en Windows, cuando se usa la soporte de Unicode. Las release modernas de Windows usan UTF-16. Las release antiguas de Windows antes de 2000 usaron TCHAR, pero solo manejaron UCS-2. UTF-16 es UCS-2, excepto para los caracteres que son 4 bytes, que no pueden representarse adecuadamente en UCS-2. Si no estás seguro, debes estar utilizando UTF-16 en este punto en Windows.

Para asegurar que el buffer de destino sea lo suficientemente grande para la conversión, por favor allocate un buffer que sea doble en tamaño que el buffer de fuente. UTF-8 usa de un a cuatro bytes por carácter, pero UTF-16 siempre usa dos a cuatro bytes, por lo que una cadena totalmente en ASCII baja duplicará en tamaño! Los caracteres UTF-16 que tomarían cuatro bytes también tomarán cuatro bytes en UTF-8, por lo que no necesitas alojar 4 veces el espacio, solo duplicarás.

Las cadenas que no se ajustan al buffer de destino se truncarán, pero siempre serán nulas y nunca contará con una pareja de surroupe incompleta al final. Si el tamaño del buffer es 0, esta función no hace nada.

Parámetros

src Cadena de fuente en formato UTF-8 nula.
dst Buffer para almacenar la cadena UTF-16 convertida.
len Tamaño, en bytes, del buffer de destino.

handle Valor devuelto de PHYSFS_openWrite() o PHYSFS_openAppend().
buffer Buffer de bytes a escribir (handle).
objSize Tamaño en bytes de los objetos a escribir (handle).
objCount Número de objetos (objSize) a escribir (handle).

Retorno

Número de objetos escritos. PHYSFS_getLastErrorCode() puede mostrar la razón por la cual este podría ser menor que (objCount). -1 si es un error completo.

PHYSFS_writeBytes

PHYSFS_sint64 PHYSFS_writeBytes (PHYSFS_File * handle, const void * buffer, PHYSFS_uint64 len)

Escribir datos en un archivo PhysicsFS. El archivo debe estar abierto para escritura.

Nota: aunque (len) es un entero de 64 bits sin signo, estás limitado a 63 bits (9223372036854775807 bytes), por lo que podemos devolver un valor negativo en caso de error. Si la longitud es mayor que 0x7FFFFFFFFFFFFFFF, esta función fallará inmediatamente. Para sistemas sin tipo de 64 bits, estás limitado a 31 bits (0x7FFFFFFF, o 2147483647 bytes). Confiamos que casi nada necesitará hacer múltiples gigabytes de I/O en una sola llamada, pero ¿por qué limitar las cosas?

Parámetros

handle Valor devuelto de PHYSFS_openWrite() o PHYSFS_openAppend().
buffer Buffer de (len) bytes a escribir (handle).
len Número de bytes a escribir (handle).

Retorno

Número de bytes escritos. Esto podría ser menor que (len); en el caso de un error, el sistema podría intentar escribir tantos bytes como sea posible, por lo que podría ocurrir una escritura incompleta. PHYSFS_getLastErrorCode() puede revelar la razón por la cual este podría ser menor que (len). -1 si es un error completo.
