void PHYSFS_permitSymbolicLinks (int allow)

Habilita o deshabilita el seguimiento de enlaces simbólicos. Algunos sistemas de archivos físicos y archivados contienen archivos que son simplemente punteros a otros archivos. Al abrir un enlace simbólico físico, el sistema abrirá transparentemente el archivo al que se refiere.

Por defecto, PhysicsFS verificará si un archivo es realmente un enlace simbólico durante las llamadas de apertura y fallará si lo es. De lo contrario, el enlace podría llevarte fuera de las rutas de lectura y escritura, comprometiendo la seguridad.

Si deseas asumir ese riesgo, llama a esta función con un valor distinto de cero. Ten en cuenta que esto es más para el sandboxing de lenguajes de scripting de programas, en caso de que scripts no confiables intenten comprometer el sistema. En general, un usuario podría tener una razón legítima para crear un enlace simbólico, por lo que no deberías deshabilitarlos a menos que creas que existe un peligro específico al permitirlos.

Los enlaces simbólicos se verifican solo cuando se manejan nombres de archivos en notación independiente del sistema operativo. Es decir, cuando configuras tus rutas de búsqueda y escritura, etc., los enlaces simbólicos nunca se verifican.

Por favor, ten en cuenta que PHYSFS_stat() siempre verifica la ruta especificada; si esa ruta es un enlace simbólico, no se seguirá en ningún caso. Si los enlaces simbólicos no están permitidos a través de esta función, PHYSFS_stat() los ignorará y tratará la consulta como si la ruta no existiera.

La permutación de permisos de enlaces simbólicos se puede habilitar o deshabilitar en cualquier momento después de haber llamado PHYSFS_init(), y está deshabilitada por defecto.

Parámetros

allow distinto de cero para permitir enlaces simbólicos, cero para deshabilitar el enlace.

تحذير

Detailed Description

These functions are designed to make it easier to write integer values to files in a specific byte order, regardless of the platform's native byte order. This is essential for cross-platform compatibility, especially when dealing with binary file formats.

The `swap` functions (e.g., `PHYSFS_swapSLE16`) convert a value from the platform's native byte order to the specified byte order (Little Endian or Big Endian) and return the swapped value. They do not write to any file.

The `write` functions (e.g., `PHYSFS_writeSLE16`) combine the swapping process with writing the resulting value directly to a `PHYSFS_File` handle.

Byte Orderings:

  • LE (Little Endian): The least significant byte is stored at the lowest memory address. Common on x86 architectures.
  • BE (Big Endian): The most significant byte is stored at the lowest memory address. Common on older architectures like 68k and SPARC.

Data Types:

  • `PHYSFS_uint16`: An unsigned 16-bit integer.
  • `PHYSFS_uint32`: An unsigned 32-bit integer.
  • `PHYSFS_uint64`: An unsigned 64-bit integer.

Return Values:

All these functions return non-zero on success and zero on failure. On failure, you can use `PHYSFS_getLastErrorCode()` to determine the specific error.
