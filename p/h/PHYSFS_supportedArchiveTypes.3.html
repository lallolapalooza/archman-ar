DESCRIPTION

The PhysicsFS library provides aabstraction layer over a filesystem. It allows you to read and write files from various archives (like ZIP files, tarballs, etc.) and directories in a platform-independent way. This is useful for games that need to package their data files into archives.

The library primarily deals with the concept of a search path, which is a list of directories and archives where PhysicsFS looks for files. You can add or remove entries from this path using functions like PHYSFS_mount and PHYSFS_unmount.

PhysicsFS also provides functions for handling byte order conversions (endianness) for different data types, reading and writing data in various formats, and manipulating strings.

Key concepts:

Search Path:
A list of directories and archives that PhysicsFS searches through to find files. The order matters; files in earlier entries of the path take precedence.
Archives:
Supported archive formats (e.g., ZIP, RAR, 7z) that PhysicsFS can read from. These are treated as directories within the search path.
Mount Point:
A logical name given to an archive or directory when it's added to the search path. This allows you to refer to the contents of the archive/directory as if it were a directory at that mount point.
Byte Order (Endianness):
Functions are provided to swap byte orders for 16-bit, 32-bit, and 64-bit integers, allowing you to read and write data consistently across different platforms.

The library offers low-level functions for direct byte reading and writing, as well as higher-level functions for managing file I/O and converting character encodings.

Error handling is done through error codes returned by functions and can be retrieved using PHYSFS_getLastErrorCode.

FUNCTIONS AND MACROS

Byte Order Swapping:
  • PHYSFS_swapSLE16, PHYSFS_swapULE16, PHYSFS_swapSLE32, PHYSFS_swapULE32, PHYSFS_swapSLE64, PHYSFS_swapULE64: Swap little-endian signed and unsigned integers (16, 32, 64 bits) to the platform's native byte order.
  • PHYSFS_swapSBE16, PHYSFS_swapUBE16, PHYSFS_swapSBE32, PHYSFS_swapUBE32, PHYSFS_swapSBE64, PHYSFS_swapUBE64: Swap big-endian signed and unsigned integers (16, 32, 64 bits) to the platform's native byte order.
Reading and Writing Formatted Data:
  • PHYSFS_readSLE16, PHYSFS_readULE16, PHYSFS_readSBE16, PHYSFS_readUBE16: Read and convert signed and unsigned 16-bit little-endian and big-endian values from a file.
  • PHYSFS_readSLE32, PHYSFS_readULE32, PHYSFS_readSBE32, PHYSFS_readUBE32: Read and convert signed and unsigned 32-bit little-endian and big-endian values from a file.
  • PHYSFS_readSLE64, PHYSFS_readULE64, PHYSFS_readSBE64, PHYSFS_readUBE64: Read and convert signed and unsigned 64-bit little-endian and big-endian values from a file.
  • PHYSFS_writeSLE16, PHYSFS_writeULE16, PHYSFS_writeSBE16, PHYSFS_writeUBE16: Convert and write signed and unsigned 16-bit little-endian and big-endian values to a file.
  • PHYSFS_writeSLE32, PHYSFS_writeULE32, PHYSFS_writeSBE32, PHYSFS_writeUBE32: Convert and write signed and unsigned 32-bit little-endian and big-endian values to a file.
  • PHYSFS_writeSLE64, PHYSFS_writeULE64, PHYSFS_writeSBE64, PHYSFS_writeUBE64: Convert and write signed and unsigned 64-bit little-endian and big-endian values to a file.
Initialization and State:
  • PHYSFS_init: Initializes the PhysicsFS library.
  • PHYSFS_deinit: Shuts down the PhysicsFS library.
  • PHYSFS_isInit: Determines if the PhysicsFS library is initialized.
  • PHYSFS_symbolicLinksPermitted: Determines if symbolic links are permitted.
  • PHYSFS_setAllocator: Hooks custom memory allocation routines into PhysicsFS.
  • PHYSFS_getAllocator: Discovers the current memory allocator.
Mounting and Search Path Management:
  • PHYSFS_mount: Adds an archive or directory to the search path.
  • PHYSFS_mountIo: Adds an archive, built on a PHYSFS_Io, to the search path.
  • PHYSFS_mountMemory: Adds an archive contained in a memory buffer to the search path.
  • PHYSFS_mountHandle: Adds an archive contained in a PHYSFS_File handle to the search path.
  • PHYSFS_getMountPoint: Determines a mounted archive's mountpoint.
  • PHYSFS_unmount: Removes a directory or archive from the search path.
  • PHYSFS_setRoot: Makes a subdirectory of an archive its root directory.
Directory and File Enumeration:
  • PHYSFS_getCdRomDirsCallback: Enumerates CD-ROM directories using a callback.
  • PHYSFS_getSearchPathCallback: Enumerates the search path using a callback.
  • PHYSFS_enumerateFilesCallback: Gets a file listing of a search path's directory using a callback.
  • PHYSFS_enumerate: Gets a file listing with error reporting using a callback.
String Conversion and Comparison:
  • PHYSFS_utf8FromUcs4: Converts a UCS-4 string to a UTF-8 string.
  • PHYSFS_utf8ToUcs4: Converts a UTF-8 string to a UCS-4 string.
  • PHYSFS_utf8FromUcs2: Converts a UCS-2 string to a UTF-8 string.
  • PHYSFS_utf8ToUcs2: Converts a UTF-8 string to a UCS-2 string.
  • PHYSFS_utf8FromLatin1: Converts a Latin1 string to a UTF-8 string.
  • PHYSFS_utf8FromUtf16: Converts a UTF-16 string to a UTF-8 string.
  • PHYSFS_utf8ToUtf16: Converts a UTF-8 string to a UTF-16 string.
  • PHYSFS_caseFold: Folds a Unicode codepoint to a lowercase equivalent.
  • PHYSFS_utf8stricmp: Case-insensitive compare of two UTF-8 strings.
  • PHYSFS_utf16stricmp: Case-insensitive compare of two UTF-16 strings.
  • PHYSFS_ucs4stricmp: Case-insensitive compare of two UCS-4 strings.
File I/O:
  • PHYSFS_openRead, PHYSFS_openWrite, PHYSFS_openAppend: Opens a file for reading, writing, or appending.
  • PHYSFS_close: Closes a PhysicsFS file handle.
  • PHYSFS_read, PHYSFS_readBytes: Reads bytes from a PhysicsFS file handle.
  • PHYSFS_write, PHYSFS_writeBytes: Writes data to a PhysicsFS file handle.
  • PHYSFS_eof: Checks if the end-of-file has been reached.
  • PHYSFS_seek: Seeks to a position in a file.
  • PHYSFS_tell: Returns the current position in a file.
  • PHYSFS_fileLength: Returns the length of a file.
  • PHYSFS_flush: Flushes any buffered data to the underlying file system.
File Information:
  • PHYSFS_stat: Gets various information about a directory or a file.
Error Handling:
  • PHYSFS_getLastErrorCode: Gets machine-readable error information.
  • PHYSFS_getErrorByCode: Gets a human-readable description string for a given error code.
  • PHYSFS_setErrorCode: Sets the current thread's error code.
Archive Registration:
  • PHYSFS_registerArchiver: Adds a new archiver to the system.
  • PHYSFS_deregisterArchiver: Removes an archiver from the system.
Preference Directory:
  • PHYSFS_getPrefDir: Gets the user-and-app-specific path where files can be written.

int PHYSFS_mount (const char * newDir, const char * mountPoint, int appendToPath)

Add an archive or directory to the search path. If this is a duplicate, the entry is not added again, even though the function succeeds. You may not add the same archive to two different mountpoints: duplicate checking is done against the archive and not the mountpoint.

When you mount an archive, it is added to a virtual file system...all files in all of the archives are interpolated into a single hierachical file tree. Two archives mounted at the same place (or an archive with files overlapping another mountpoint) may have overlapping files: in such a case, the file earliest in the search path is selected, and the other files are inaccessible to the application. This allows archives to be used to override previous revisions; you can use the mounting mechanism to place archives at a specific point in the file tree and prevent overlap; this is useful for downloadable mods that might trample over application data or each other, for example.

The mountpoint does not need to exist prior to mounting, which is different than those familiar with the Unix concept of "mounting" may expect. As well, more than one archive can be mounted to the same mountpoint, or mountpoints and archive contents can overlap...the interpolation mechanism still functions as usual.

Specifying a symbolic link to an archive or directory is allowed here, regardless of the state of PHYSFS_permitSymbolicLinks(). That function only deals with symlinks inside the mounted directory or archive.

Parameters

newDir directory or archive to add to the path, in platform-dependent notation.
mountPoint Location in the interpolated tree that this archive will be "mounted", in platform-independent notation. NULL or "" is equivalent to "/".
appendToPath nonzero to append to search path, zero to prepend.

Returns

nonzero if added to path, zero on failure (bogus archive, dir missing, etc). Use PHYSFS_getLastErrorCode() to obtain the specific error.

void PHYSFS_bufferize_handle (PHYSFS_File * handle)

Cause the handle to be buffered.

This function attempts to allocate a buffer and attach it to the specified file handle. If successful, all subsequent read and write operations on this handle will be buffered.

If the handle is already buffered, this function will attempt to resize the existing buffer to the new size. If the new size is zero, the buffer will be freed and the handle will become unbuffered again.

Note that simply calling this function without checking return values is a bug. If an error occurs, the handle will remain unbuffered, or the buffering operation will fail. You MUST check the return value of this function!

PhysicsFS file handles are unbuffered by default.

int PHYSFS_setRoot (const char * archive, const char * subdir)

Make a subdirectory of an archive its root directory. This lets you narrow down the accessible files in a specific archive. For example, if you have x.zip with a file in y/z.txt, mounted to /a, if you call PHYSFS_setRoot("x.zip", "/y"), then the call PHYSFS_openRead("/a/z.txt") will succeed.

It is not an error to set a subdirectory that does not exist to be the root of an archive; however, no files will be visible in this case. If the missing directories end up getting created (a mkdir to the physical filesystem, etc) then this will be reflected in the interpolated tree.

Set up sane, default paths. Helper function.

The write dir will be set to the pref dir returned by

PHYSFS_getPrefDir(organization, appName)

, which is created if it doesn't exist.

The above is sufficient to make sure your program's configuration directory is separated from other clutter, and platform-independent.

The search path will be:

  • The Write Dir (created if it doesn't exist)
  • The Base Dir (PHYSFS_getBaseDir())
  • All found CD-ROM dirs (optionally)

These directories are then searched for files ending with the extension (archiveExt), which, if they are valid and supported archives, will also be added to the search path. If you specified "PKG" for (archiveExt), and there's a file named data.PKG in the base dir, it'll be checked. Archives can either be appended or prepended to the search path in alphabetical order, regardless of which directories they were found in. All archives are mounted in the root of the virtual file system ("/") .

All of this can be accomplished from the application, but this just does it all for you. Feel free to add more to the search path manually, too.

Parameters

archiveExt File extension used by your program to specify an archive. For example, Quake 3 uses "pk3", even though they are just zipfiles. Specify NULL to not dig out archives automatically. Do not specify the '.' char; If you want to look for ZIP files, specify "ZIP" and not ".ZIP" ... the archive search is case-insensitive.

archivesFirst Non-zero to prepend the archives to the search path. Zero to append them. Ignored if !(archiveExt).

void PHYSFS_utf8ToUcs4 (const char * src, PHYSFS_uint32 * dst, PHYSFS_uint64 len)

تحويل سلسلة UTF-8 إلى سلسلة UCS-4.

تحذير

لن تقوم هذه الدالة بالإبلاغ عن خطأ في حالة وجود تسلسلات UTF-8 غير صالحة في السلسلة المصدر. سيتم استبدالها بحرف "؟" وستستمر.

سلاسل UCS-4 هي 32 بت لكل حرف. سلاسل UTF-8 تستخدم من بايت واحد إلى أربعة بايتات لكل حرف. هذا يعني أن سلاسل UCS-4 ستكون دائمًا أكبر من سلاسل UTF-8 المكافئة لها (عادةً ما تكون أربعة أضعاف الحجم).

لضمان أن يكون المخزن المؤقت الوجهة كبيرًا بما يكفي للتحويل، يرجى تخصيص مخزن مؤقت بحجم أربعة أضعاف حجم المخزن المؤقت المصدر. سلاسل UTF-8 التي تستخدم أربعة بايتات لكل حرف ستظل بحاجة إلى أربعة بايتات في UCS-4، وبالتالي لن ترى زيادة في الحجم. يجب تخصيص أربعة أضعاف المساحة لضمان عدم حدوث اقتطاع.

سيتم اقتطاع السلاسل التي لا تتناسب مع المخزن المؤقت الوجهة، ولكنها ستكون دائمًا منتهية بـ null ولن تحتوي أبدًا على تسلسل UCS-4 غير مكتمل في النهاية. إذا كان طول المخزن المؤقت 0، فلن تقوم هذه الدالة بأي شيء.

void PHYSFS_utf8ToUtf16 (const char * src, PHYSFS_uint16 * dst, PHYSFS_uint64 len)

تحويل سلسلة UTF-8 إلى سلسلة UTF-16.

تحذير

لن تقوم هذه الدالة بالإبلاغ عن خطأ في حالة وجود تسلسلات UTF-8 غير صالحة في السلسلة المصدر. سيتم استبدالها بحرف "؟" وستستمر.

سلاسل UTF-16 هي 16 بت لكل حرف (باستثناء بعض الأحرف، والتي هي 32 بت): TCHAR على Windows، عند البناء مع دعم Unicode. إصدارات Windows الحديثة تستخدم UTF-16. إصدارات Windows قبل عام 2000 استخدمت TCHAR، لكنها تعاملت فقط مع UCS-2. UTF-16 هو UCS-2، باستثناء الأحرف التي تستغرق 4 بايتات، والتي لا يمكن تمثيلها في UCS-2 على أي حال. إذا لم تكن متأكدًا، فيجب أن تستخدم UTF-16 في هذه المرحلة على Windows.

لضمان أن يكون المخزن المؤقت الوجهة كبيرًا بما يكفي للتحويل، يرجى تخصيص مخزن مؤقت بحجم ضعف حجم المخزن المؤقت المصدر. يستخدم UTF-8 من بايت واحد إلى أربعة بايتات لكل حرف، ولكن UTF-16 يستخدم دائمًا من اثنين إلى أربعة، لذا ستتضاعف مساحة سلسلة ASCII المنخفضة بالكامل! الأحرف UTF-16 التي ستأخذ أربعة بايتات تأخذ أيضًا أربعة بايتات في UTF-8، لذلك لا تحتاج إلى تخصيص مساحة 4x فقط في حالة الطوارئ: ضعف الحجم يكفي.

سيتم اقتطاع السلاسل التي لا تتناسب مع المخزن المؤقت الوجهة، ولكنها ستكون دائمًا منتهية بـ null ولن تحتوي أبدًا على زوج بديل UTF-16 غير مكتمل في النهاية. إذا كان طول المخزن المؤقت 0، فلن تقوم هذه الدالة بأي شيء.
