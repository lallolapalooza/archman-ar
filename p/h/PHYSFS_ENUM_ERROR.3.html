مهمل

منذ PhysFS 2.1، استخدم PHYSFS_stat() بدلاً من PHYSFS_getLastModTime(). هذه الوظيفة هي مجرد غلاف بسيط.

يتم إرجاع وقت التعديل كرقم بالثواني منذ عصر يونكس (منتصف الليل، 1 يناير 1970). تعتمد دقة واستخلاص هذا الوقت على المستخرج. إذا لم تكن هناك معلومات معقولة متاحة لمستخرج معين، أو إذا حدث خطأ، فسترجع هذه الوظيفة -1.

يجب عليك استخدام هذه الوظيفة وليس PHYSFS_stat() إذا كانت التوافقية الثنائية مع PhysFS 2.0 مهمة (وهو ما قد لا يكون هو الحال بالنسبة للعديد من المستخدمين).

المعاملات

filename اسم الملف للتحقق منه، بتنسيق مستقل عن النظام.

الارجاع

وقت تعديل الملف. -1 إذا تعذر تحديده.

على نظام Mac OS X، قد يبدو الأمر كالتالي: "/Users/bob/Library/Application Support/My Program Name"

(إلخ)

من المحتمل أن ترغب في استخدام مسار الكتابة هذا لدليل الكتابة الخاص بك، ووضعه أيضًا في بداية قائمة البحث الخاصة بك. الإصدارات القديمة من PhysFS قدمت فقط PHYSFS_getUserDir() وتركت لك تحديد مكان تخزين الملفات تحت هذا الدليل. هذه الوظيفة تجد الموقع الصحيح لأي منصة، والتي لا تقتصر على أنظمة التشغيل المختلفة، ولكن أيضًا الإصدارات المختلفة من نفس نظام التشغيل.

تقوم بتحديد اسم مؤسستك (إذا كانت مؤسسة حقيقية، اسمك، أو اسم نطاق إنترنت تمتلكه) واسم تطبيقك. يجب أن تكون هذه أسماء صالحة.

يمكن لكلا السلسلتين (org) و (app) أن تصبحا جزءًا من اسم مجلد، لذا يرجى اتباع هذه القواعد:

  • حاول استخدام نفس سلسلة المؤسسة (بما في ذلك حالة الأحرف) لجميع تطبيقاتك التي تستخدم هذه الوظيفة.
  • استخدم دائمًا سلسلة تطبيق فريدة لكل تطبيق، وتأكد من أنها لا تتغير بعد قرار استخدامها.
  • الأحرف Unicode مسموحة، طالما أنها مشفرة بنظام UTF-8، ولكن...
  • ... الأحرف المسموح بها هي فقط الأحرف والأرقام والمسافات. تجنب أحرف مثل "Game Name 2: Bad Guy's Revenge!" ... "Game Name 2" يكفي.

المؤشر المرتجع صالح حتى تقوم باستدعاء هذه الوظيفة مرة أخرى أو استدعاء PHYSFS_deinit(). ليس بالضرورة أن يكون استدعاءً سريعًا، لذلك يجب عليك استدعاؤه مرة واحدة عند التهيئة ونسخ السلسلة إذا كنت بحاجة إليها.

يجب أن تفترض أن المسار المرتجع هو المكان الوحيد الآمن لكتابة الملفات (وأن PHYSFS_getUserDir() و PHYSFS_getBaseDir()، على الرغم من أنهما قد يكونان قابلين للكتابة، أو حتى أصل السلسلة المرتجعة، ليسا المكان الذي يجب أن تكتب فيه).

تحديد مكان وجود ملف في مسار البحث. يتم تحديد الملف بتنسيق مستقل عن النظام. سيكون اسم الملف المرتجع هو العنصر في مسار البحث حيث تم العثور على الملف، والذي قد يكون دليلاً، أو أرشيفًا. حتى لو كان هناك مطابقات متعددة في أجزاء مختلفة من مسار البحث، يتم استخدام أول تطابق تم العثور عليه فقط، تمامًا كما هو الحال عند فتح ملف.

إذا كان جزء من المطابقة رابطًا رمزيًا ولم تسمح صراحةً بالروابط الرمزية، فسيتم تجاهله وسيستمر البحث.

void PHYSFS_permitSymbolicLinks(int allow)

Permite o deniega el seguimiento de enlaces simbólicos. Algunos sistemas de archivos físicos y arquitecturas contienen archivos que son solo referencias a otros archivos. Al abrir un enlace simbólico físico, este abrirá de forma transparente el archivo al que se refiere.

Por defecto, PhysicsFS verificará si un archivo es realmente un enlace simbólico durante las llamadas de apertura y fallará si lo es. De lo contrario, el enlace podría llevarte fuera de las rutas de lectura y escritura, comprometiendo la seguridad.

Si deseas asumir ese riesgo, llama a esta función con un valor distinto de cero. Ten en cuenta que esto es más para el aislamiento de seguridad de lenguajes de scripting de un programa, en caso de que scripts no confiables intenten comprometer el sistema. En general, un usuario podría tener una razón legítima para configurar un enlace simbólico, así que no deberías deshabilitarlos, a menos que sientas que hay un peligro específico.

Los enlaces simbólicos solo se verifican explícitamente cuando se manejan nombres de archivos en notación independiente de plataforma. Es decir, cuando configuras tus rutas de búsqueda y escritura, etc., los enlaces simbólicos nunca se verifican.

Por favor, ten en cuenta que PHYSFS_stat() siempre verificará la ruta especificada; si esa ruta es un enlace simbólico, no se seguirá en ningún caso. Si los enlaces simbólicos no están permitidos a través de esta función, PHYSFS_stat() los ignorará y tratará la consulta como si la ruta no existiera.

El permiso de enlaces simbólicos se puede habilitar o deshabilitar después de haber llamado PHYSFS_init(), y está deshabilitado por defecto.

Parámetros

allow distinto de cero para permitir enlaces simbólicos, cero para deshabilitar el enlace.

NAME

PHYSFS_writeUBE16, PHYSFS_writeUBE32, PHYSFS_writeUBE64, PHYSFS_writeULE16, PHYSFS_writeULE32, PHYSFS_writeULE64 - Convert and write an unsigned integer value in a specific endian format.

SYNOPSIS

int PHYSFS_writeUBE16(PHYSFS_File *file, PHYSFS_uint16 val);

int PHYSFS_writeUBE32(PHYSFS_File *file, PHYSFS_uint32 val);

int PHYSFS_writeUBE64(PHYSFS_File *file, PHYSFS_uint64 val);

int PHYSFS_writeULE16(PHYSFS_File *file, PHYSFS_uint16 val);

int PHYSFS_writeULE32(PHYSFS_File *file, PHYSFS_uint32 val);

int PHYSFS_writeULE64(PHYSFS_File *file, PHYSFS_uint64 val);

Detailed Description

These functions convert an unsigned integer from the platform's native byte order to a specified endian format (big-endian or little-endian) and then write it to the given PHYSFS_File handle.

These are convenience functions for writing numerical data in a platform-independent way.

Parameters

file PhysicsFS file handle to which to write.

val Value to convert and write.

Returns

zero on failure, non-zero on success. On failure, you can find out what went wrong from PHYSFS_getLastErrorCode().

Warning

Remember, PHYSFS_uint64 is only 32 bits on platforms without any sort of 64-bit support.
