int PHYSFS_caseFold (const PHYSFS_uint32 from, PHYSFS_uint32 * to)

"Fold" a Unicode codepoint to a lowercase equivalent. (This is for limited, hardcore use. If you don't immediately see a need for it, you can probably ignore this forever.)

This will convert a Unicode codepoint into its lowercase equivalent. Bogus codepoints and codepoints without a lowercase equivalent will be returned unconverted.

Note that you might get multiple codepoints in return! The German Eszett, for example, will fold down to two lowercase latin 's' codepoints. The theory is that if you fold two strings, one with an Eszett and one with "SS" down, they will match.

Warning

Anyone that is a student of Unicode knows about the "Turkish I" problem. This API does not handle it. Assume this one letter in all of Unicode will definitely fold sort of incorrectly. If you don't know what this is about, you can probably ignore this problem for most of the planet, but perfection is impossible.

Parameters

from The codepoint to fold.
to Buffer to store the folded codepoint values into. This should point to space for at least 3 PHYSFS_uint32 slots.

Returns

The number of codepoints the folding produced. Between 1 and 3.

int PHYSFS_deinit (void )

Deinitialize the PhysicsFS library. This closes any files opened via PhysicsFS, blanks the search/write paths, frees memory, and invalidates all of your file handles.

Note that this call can FAIL if there's a file open for writing that refuses to close (for example, the underlying operating system was buffering writes to network filesystem, and the fileserver has crashed, or a hard drive has failed, etc). It is usually best to close all write handles yourself before calling this function, so that you can gracefully handle a specific failure.

Once successfully deinitialized, PHYSFS_init() can be called again to restart the subsystem. All default API states are restored at this point, with the exception of any custom allocator you might have specified, which survives between initializations.

Returns

nonzero on success, zero on error. Specifics of the error can be gleaned from PHYSFS_getLastError(). If failure, state of PhysFS is undefined, and probably badly screwed up.

int PHYSFS_delete (const char * filename)

Delete a file or directory. (filename) is specified in platform-independent notation in relation to the write dir.

A directory must be empty before this call can delete it.

Deleting a symlink will remove the link, not what it points to, regardless of whether you "permitSymLinks" or not.

So if you've got the write dir set to "C:\mygame\writedir" and call PHYSFS_delete("downloads/maps/level1.map") then the file "C:\mygame\writedir\downloads\maps\level1.map" is removed from the physical filesystem, if it exists and the operating system permits the deletion.

Note that on Unix systems, deleting a file may be successful, but the actual file won't be removed until all processes that have an open filehandle to it (including your program) close their handles.

Chances are, the bits that make up the file still exist, they are just made available to be written over at a later point. Don't consider this a security method or anything. :)

Parameters

filename Filename to delete.

Returns

nonzero on success, zero on error. Use PHYSFS_getLastErrorCode() to obtain the specific error.

void PHYSFS_setErrorCode (PHYSFS_ErrorCode code)

Establece el código de error actual de la línea de hilos. Esto te permite establecer el valor que se devolverá por el próximo llamado a PHYSFS_getLastErrorCode(). Esto reemplazará cualquier código de error existente, ya sea establecido por tu aplicación o por PhysicsFS internal.

Los códigos de error se guardan por hilos; lo que estableces aquí no será accesible para otro hilo.

Cualquier llamada a PhysicsFS puede cambiar el código de error actual, por lo que cualquier código que estableces aquí es bastante frágil, y por eso no deberías construir un framework de reporting de errores serio en esta función. El objetivo principal de esta función es permitir que PHYSFS_Io implementaciones establezcan el estado de error, que generalmente será devuelto a tu aplicación cuando se llama a una llamada PHYSFS_Io que falla internamente.

Esta función no importa si el código de error es un valor conocido por PhysicsFS o no (pero PHYSFS_getErrorByCode() devolverá NULL para valores desconocidos). El valor será reportado sin interferencia por PHYSFS_getLastErrorCode().

int PHYSFS_setRoot (const char * archive, const char * subdir)

Hace un subdirectorio de un archivo su directorio raíz. Esto te permite reducir los archivos accesibles en un archivo específico. Por ejemplo, si tienes x.zip con un archivo en y/z.txt montado a /a, y llamas PHYSFS_setRoot("x.zip", "/y"), entonces la llamada PHYSFS_openRead("/a/z.txt") será exitosa.

Puedes cambiar la raíz de un archivo en cualquier momento, modificando así el árbol de archivos interpolado (dependiendo de donde se desplacen los caminos, un archivo diferente puede proporcionar diversos archivos). Si estableces la raíz a NULL o a "/", el archivo se trata como si no hubiera sido establecida especularmente.

Cambiar la raíz solo afecta operaciones futuras en caminos de archivos; un archivo que fue abierto a partir de un camino que cambió debido a un setRoot no será afectado.

Establecer una nueva raíz no está limitado a archivos en el camino de búsqueda; también puedes establecer una en el directorio de escritura, lo cual podría ser útil si tienes archivos abiertos para escribir y no puedes cambiar el directorio de escritura en este momento.

Es inadmisible establecer un subdirectorio que no exista como raíz de un archivo; sin embargo, en este caso no se verán archivos. Si los directorios ausentes terminan siendo creados (una mkdir al sistema de archivos físico, etc), esto se reflejará en el árbol interpolado.

Parámetros

archive directorio/archivo sobre el cual cambiar la raíz.
subdir subdirectorio nuevo para hacer la raíz de este archivo.

Devuelve

no cero en éxito, cero en error. Usa PHYSFS_getLastErrorCode() para obtener el error específico.

El directorio de escritura se establecerá en el directorio pref definido por

PHYSFS_getPrefDir(organization, appName)

La información anterior es suficiente para asegurar que el directorio de configuración de tu programa esté separado de otros desordenados, y sea independiente del sistema.

El camino de búsqueda será:

  • Directorio de escritura (creado si no existe)
  • Directorio base (PHYSFS_getBaseDir())
  • Todos los directorios CD-ROM encontrados (opcional)

Estos directorios se buscan por extensiones (archiveExt), que, si son válidas y soportadas, también se añaden al camino de búsqueda. Si especificaste "PKG" para (archiveExt) y hay un archivo llamado data.PKG en el directorio base, se verificará. Los archivos pueden ser añadidos al inicio o al final del camino de búsqueda en orden alfabético, independientemente de dónde los encontraron. Todos los archivos se montan en la raíz del sistema de archivos virtual ("/").

Todo lo anterior puede realizarse desde el programa, pero esta función lo hace todo por ti. Puedes añadir más a la lista de caminos de búsqueda manualmente, también.

void PHYSFS_utf8ToUcs4(const char *src, PHYSFS_uint32 *dst, PHYSFS_uint64 len)

Convert a UTF-8 string to a UCS-4 string.

Warning

This function will not report an error if there are invalid UTF-8 sequences in the source string. It will replace them with a '?' character and continue on.

UCS-4 strings are 32-bits per character. This is also the native character set on macOS. UTF-8 uses from one to four bytes per character, so a destination buffer of the same size as the source buffer is always large enough.

Strings that don't fit in the destination buffer will be truncated, but will always be null-terminated and never have an incomplete UCS-4 sequence at the end. If the buffer length is 0, this function does nothing.

void PHYSFS_utf8ToUtf16(const char *src, PHYSFS_uint16 *dst, PHYSFS_uint64 len)

Convert a UTF-8 string to a UTF-16 string.

Warning

This function will not report an error if there are invalid UTF-8 sequences in the source string. It will replace them with a '?' character and continue on.

UTF-16 strings are 16-bits per character (except some chars, which are 32-bits): TCHAR on Windows, when building with Unicode support. Modern Windows releases use UTF-16. Windows releases before 2000 used TCHAR, but only handled UCS-2. UTF-16 is UCS-2, except for the characters that are 4 bytes, which aren't representable in UCS-2 at all anyhow. If you aren't sure, you should be using UTF-16 at this point on Windows.

To ensure that the destination buffer is large enough for the conversion, please allocate a buffer that is double the size of the source buffer. UTF-8 uses from one to four bytes per character, but UTF-16 always uses two to four, so an entirely low-ASCII string will double in size! The UTF-16 characters that would take four bytes also take four bytes in UTF-8, so you don't need to allocate 4x the space just in case: double will do.

Strings that don't fit in the destination buffer will be truncated, but will always be null-terminated and never have an incomplete UTF-16 surrogate pair at the end. If the buffer length is 0, this function does nothing.

Parameters

src Null-terminated source string in UTF-8 format.
dst Buffer to store converted UTF-16 string.
len Size, in bytes, of destination buffer.

NAME

PHYSFS_writeUBE16, PHYSFS_writeUBE32, PHYSFS_writeUBE64, PHYSFS_writeULE16, PHYSFS_writeULE32, PHYSFS_writeULE64 — PHYSFS_writeBYTE(3) convenience functions for writing endian-specific integer values.

SYNOPSIS

int PHYSFS_writeUBE16(PHYSFS_File *file, PHYSFS_uint16 val);
int PHYSFS_writeUBE32(PHYSFS_File *file, PHYSFS_uint32 val);
int PHYSFS_writeUBE64(PHYSFS_File *file, PHYSFS_uint64 val);
int PHYSFS_writeULE16(PHYSFS_File *file, PHYSFS_uint16 val);
int PHYSFS_writeULE32(PHYSFS_File *file, PHYSFS_uint32 val);
int PHYSFS_writeULE64(PHYSFS_File *file, PHYSFS_uint64 val);

Detailed Description

These functions offer a simpler interface for writing numeric values to a PHYSFS_File handle. They handle the byte-order conversion from the host system's native format to either big-endian or little-endian, and then write the result to the file.

The functions are named as follows:

U
Indicates an unsigned value.
BE
Indicates Big-Endian byte order.
LE
Indicates Little-Endian byte order.
16, 32, 64
Indicates the size of the value in bits.

For example, PHYSFS_writeUBE16 converts an unsigned 16-bit integer from the host's native byte order to big-endian and writes it to the specified file.
