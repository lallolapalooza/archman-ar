إذا كنت ترغب في توفير أداة أرشفة خاصة بك (على سبيل المثال، تنسيق ملف أرشيف مخصص، أو شيء افتراضي تريد جعله يبدو كنظام ملفات يمكنك الوصول إليه من خلال واجهات برمجة تطبيقات PhysicsFS العادية)، فهذا هو المكان الذي تبدأ منه. بمجرد تسجيل أداة أرشفة بنجاح، يمكنك بعد ذلك استخدام PHYSFS_mount() لإضافة أرشيفات تدعمها أداة الأرشفة الخاصة بك إلى مسار البحث، أو ربما استخدامها كدليل للكتابة. داخليًا، تستخدم PhysicsFS هذه الوظيفة لتسجيل أدوات الأرشفة المضمنة الخاصة بها، مثل دعم .zip، وما إلى ذلك.

لا يمكنك الحصول على أداتي أرشفة تتعاملان مع نفس الامتداد. إذا كان هناك تعارض، يمكنك إلغاء تسجيل أداة الأرشفة الأخرى (بما في ذلك الأدوات المضمنة) باستخدام PHYSFS_deregisterArchiver().

يتم نسخ البيانات الموجودة في (archiver)؛ يمكنك تحرير هذا المؤشر عند عودة هذه الدالة.

بمجرد عودة هذه الدالة بنجاح، ستتمكن PhysicsFS من دعم الأرشيفات من هذا النوع حتى تقوم بإلغاء تسجيل أداة الأرشفة مرة أخرى.

المعلمات

archiver أداة الأرشفة المراد تسجيلها.

القيم المعادة

صفر عند الخطأ، غير صفر عند النجاح.

int PHYSFS_addCallback (PHYSFS_Io_ptr handle, int (*callback)(PHYSFS_Io_ptr, void *), void * userdata)

Add a callback to an IO handle. This callback will be called whenever a read or write operation occurs on this handle. The callback should return zero on success, and non-zero on failure. The `userdata` pointer can be used to pass arbitrary data to the callback. The callback will receive the handle and the userdata pointer.

Parameters

handle The IO handle to add the callback to.
callback The callback function to be called.
userdata Arbitrary user data to be passed to the callback.

Returns

non-zero on success, zero on failure.

int PHYSFS_allocWriteCache (PHYSFS_Io_ptr handle, size_t bufsize)

Allocates a write cache for the given file handle. This function will only succeed on handles opened for writing. The buffer will be flushed automatically when the handle is closed, or when the buffer becomes full. A buffer size of zero will free an existing buffer.

This function implicitly causes a flush of any existing buffer. Check your return values!

Seeking, etc transparently accounts for buffering.

You can resize an existing buffer by calling this function more than once on the same file. Setting the buffer size to zero will free an existing buffer.

PhysicsFS file handles are unbuffered by default.

Please check the return value of this function! Failures can include not being able to seek backwards in a read-only file when removing the buffer, not being able to allocate the buffer, and not being able to flush the buffer to disk, among other unexpected problems.

Parameters

handle handle returned from PHYSFS_open*().
bufsize size, in bytes, of buffer to allocate.

Returns

nonzero if successful, zero on error.

void PHYSFS_setErrorCode (PHYSFS_ErrorCode code)

Set the current thread's error code. This lets you set the value that will be returned by the next call to PHYSFS_getLastErrorCode(). This will replace any existing error code, whether set by your application or internally by PhysicsFS.

Error codes are stored per-thread; what you set here will not be accessible to another thread.

Any call into PhysicsFS may change the current error code, so any code you set here is somewhat fragile, and thus you shouldn't build any serious error reporting framework on this function. The primary goal of this function is to allow PHYSFS_Io implementations to set the error state, which generally will be passed back to your application when PhysicsFS makes a PHYSFS_Io call that fails internally.

This function doesn't care if the error code is a value known to PhysicsFS or not (but PHYSFS_getErrorByCode() will return NULL for unknown values). The value will be reported unmolested by PHYSFS_getLastErrorCode().

Parameters

code Error code to become the current thread's new error state.

See also

PHYSFS_getLastErrorCode

int PHYSFS_setRoot (const char * archive, const char * subdir)

Make a subdirectory of an archive its root directory. This lets you narrow down the accessible files in a specific archive. For example, if you have x.zip with a file in y/z.txt, mounted to /a, if you call PHYSFS_setRoot("x.zip", "/y"), then the call PHYSFS_openRead("/a/z.txt") will succeed.

You can change an archive's root at any time, altering the interpolated file tree (depending on where paths shift, a different archive may be providing various files). If you set the root to NULL or "/", the archive will be treated as if no special root was set (as if the archive was just mounted normally).

Changing the root only affects future operations on pathnames; a file that was opened from a path that changed due to a setRoot will not be affected.

Setting a new root is not limited to archives in the search path; you may set one on the write dir, too, which might be useful if you have files open for write and thus can't change the write dir at the moment.

It is not an error to set a subdirectory that does not exist to be the root of an archive; however, no files will be visible in this case. If the missing directories end up getting created (a mkdir to the physical filesystem, etc) then this will be reflected in the interpolated tree.

Parameters

archive dir/archive on which to change root.
subdir new subdirectory to make the root of this archive.

Returns

nonzero on success, zero on failure. Use PHYSFS_getLastErrorCode() to obtain the specific error.

int PHYSFS_setSaneConfig (const char * organization, const char * appName, const char * archiveExt, int includeCdRoms, int archivesFirst)

Set up sane, default paths. Helper function.

The write dir will be set to the pref dir returned by

PHYSFS_getPrefDir(organization, appName)

, which is created if it doesn't exist.

The above is sufficient to make sure your program's configuration directory is separated from other clutter, and platform-independent.

The search path will be:

  • The Write Dir (created if it doesn't exist)
  • The Base Dir (PHYSFS_getBaseDir())
  • All found CD-ROM dirs (optionally)

These directories are then searched for files ending with the extension (archiveExt), which, if they are valid and supported archives, will also be added to the search path. If you specified "PKG" for (archiveExt), and there's a file named data.PKG in the base dir, it'll be checked. Archives can either be appended or prepended to the search path in alphabetical order, regardless of which directories they were found in. All archives are mounted in the root of the virtual file system ("/").

All of this can be accomplished from the application, but this just does it all for you. Feel free to add more to the search path manually, too.

Parameters

organization Name of your company/group/etc to be used as a dirname, so keep it small, and no-frills.
appName Program-specific name of your program, to separate it from other programs using PhysicsFS.
archiveExt File extension used by your program to specify an archive. For example, Quake 3 uses "pk3", even though they are just zipfiles. Specify NULL to not dig out archives automatically. Do not specify the '.' char; If you want to look for ZIP files, specify "ZIP" and not ".ZIP" ... the archive search is case-insensitive.
includeCdRoms Non-zero to include CD-ROMs in the search path, and (if (archiveExt) != NULL) search them for archives. This may cause a significant amount of blocking while discs are accessed, and if there are no discs in the drive (or even not mounted on Unix systems), then they may not be made available anyhow. You may want to specify zero and handle the disc setup yourself.
archivesFirst Non-zero to prepend the archives to the search path. Zero to append them. Ignored if !(archiveExt).

Returns

nonzero on success, zero on error. Use PHYSFS_getLastErrorCode() to obtain the specific error.

const PHYSFS_ArchiveInfo ** PHYSFS_supportedArchiveTypes (void )

Get a list of supported archive types. Get a list of archive types supported by this implementation of PhysicFS. These are the file formats usable for search path entries. This is for informational purposes only. Note that the extension listed is merely convention: if we list "ZIP", you can open a PkZip-compatible archive with an extension of "XYZ", if you like.

The returned value is an array of pointers to PHYSFS_ArchiveInfo structures, with a NULL entry to signify the end of the list:

PHYSFS_ArchiveInfo **i;
for (i = PHYSFS_supportedArchiveTypes(); *i != NULL; i++)
{
    printf("Supported archive: [%s], which is [%s].\n",
             (*i)->extension, (*i)->description);
}

The return values are pointers to internal memory, and should be considered READ ONLY, and never freed. The returned values are valid until the next call to PHYSFS_deinit(), PHYSFS_registerArchiver(), or PHYSFS_deregisterArchiver().

Returns

READ ONLY Null-terminated array of READ ONLY structures.

int PHYSFS_ucs4stricmp (const PHYSFS_uint32 * str1, const PHYSFS_uint32 * str2)

Case-insensitive compare of two UCS-4 strings. This is a strcasecmp/stricmp replacement that expects both strings to be in UCS-4 (aka UTF-32) encoding. It will do "case folding" to decide if the Unicode codepoints in the strings match.

It will report which string is "greater than" the other, but be aware that this doesn't necessarily mean anything: 'a' may be "less than" 'b', but a Japanese kuten has no meaningful alphabetically relationship to a Greek lambda, but being able to assign a reliable "value" makes sorting algorithms possible, if not entirely sane. Most cases should treat the return value as "equal" or "not equal".

Like stricmp, this expects both strings to be NULL-terminated.

Parameters

str1 First string to compare.
str2 Second string to compare.

Returns

-1 if str1 is "less than" str2, 1 if "greater than", 0 if equal.

void PHYSFS_utf8FromLatin1 (const char * src, char * dst, PHYSFS_uint64 len)

تحويل سلسلة نصية بتنسيق UTF-8 إلى سلسلة نصية بتنسيق Latin1. سلاسل Latin1 هي 8 بت لكل حرف: ترميز شائع لـ "ASCII عالي".

للتأكد من أن المخزن المؤقت الوجهة كبير بما يكفي للتحويل، يرجى تخصيص مخزن مؤقت بحجم ضعف حجم المخزن المؤقت المصدر. يقوم UTF-8 بتوسيع نقاط ترميز Latin1 فوق 127 من بايت واحد إلى بايتين، لذا قد ينمو النص في بعض الحالات.

سيتم اقتطاع السلاسل النصية التي لا تناسب المخزن المؤقت الوجهة، ولكنها ستنتهي دائمًا بحرف null ولن تحتوي أبدًا على تسلسل UTF-8 غير مكتمل في النهاية. إذا كان طول المخزن المؤقت 0، فلن تقوم هذه الدالة بأي شيء.

يرجى ملاحظة أننا لا نوفر محولًا من UTF-8 إلى Latin1، حيث لا يمكن لـ Latin1 التعبير عن معظم نقاط ترميز Unicode. إنه ترميز قديم؛ يجب عليك التحويل منه في جميع الأوقات.

المعلمات

src سلسلة مصدر منتهية بـ null بتنسيق Latin1.
dst مخزن مؤقت لتخزين سلسلة UTF-8 المحولة.
len حجم المخزن المؤقت الوجهة بالبايت.

من شبه المؤكد أنك يجب أن تستخدم PHYSFS_utf8FromUtf16()، والتي أصبحت متاحة في PhysicsFS 2.1، ما لم تكن تعرف ما تفعله.

هذه الدالة لن تبلغ عن خطأ إذا كانت هناك قيم UCS-2 غير صالحة في السلسلة المصدر. ستقوم باستبدالها بحرف '؟' وتستمر.

سلاسل UCS-2 هي 16 بت لكل حرف: TCHAR على Windows، عند البناء مع دعم Unicode. يرجى ملاحظة أن الإصدارات الحديثة من Windows تستخدم UTF-16، وهو شكل موسع من UCS-2، وليس UCS-2 نفسه. من شبه المؤكد أنك تريد PHYSFS_utf8FromUtf16() بدلاً من ذلك.

void PHYSFS_utf8FromUtf16 (const PHYSFS_uint16 * src, char * dst, PHYSFS_uint64 len)

تحويل سلسلة UTF-16 إلى سلسلة UTF-8.

تحذير

هذه الدالة لن تبلغ عن خطأ إذا كانت هناك تسلسلات UTF-16 غير صالحة في السلسلة المصدر. ستقوم باستبدالها بحرف '؟' وتستمر.

سلاسل UTF-16 هي 16 بت لكل حرف (باستثناء بعض الأحرف، التي هي 32 بت): TCHAR على Windows، عند البناء مع دعم Unicode. تستخدم إصدارات Windows الحديثة UTF-16. تستخدم إصدارات Windows قبل عام 2000 TCHAR، ولكنها كانت تتعامل فقط مع UCS-2. UTF-16 *هو* UCS-2، باستثناء الأحرف التي تستخدم 4 بايت، والتي لا يمكن تمثيلها في UCS-2 على الإطلاق. إذا لم تكن متأكدًا، فيجب عليك استخدام UTF-16 في هذه النقطة على Windows.

سيتم اقتطاع السلاسل النصية التي لا تناسب المخزن المؤقت الوجهة، ولكنها ستنتهي دائمًا بحرف null ولن تحتوي أبدًا على تسلسل UTF-8 غير مكتمل في النهاية. إذا كان طول المخزن المؤقت 0، فلن تقوم هذه الدالة بأي شيء.

int PHYSFS_utf8stricmp (const char * str1, const char * str2)

مقارنة غير حساسة لحالة الأحرف لسلسلتين نصيتين بتنسيق UTF-8. هذا بديل لـ strcasecmp/stricmp يتوقع أن تكون كلتا السلسلتين بتنسيق UTF-8. ستقوم بتنفيذ "طي الأحرف" لتحديد ما إذا كانت نقاط ترميز Unicode في السلاسل متطابقة.

إذا كانت كلتا السلسلتين تقتصران على أحرف ASCII المنخفضة، فستقوم هذه الدالة بالشيء الصحيح، حيث أن ذلك يعد أيضًا UTF-8 صالحًا. إذا كانت هناك أي أحرف ASCII عالية، فلن تفعل هذه الدالة ما تتوقعه!

ستقوم بالإبلاغ عن السلسلة التي هي "أكبر من" الأخرى، ولكن كن على علم أن هذا لا يعني بالضرورة شيئًا: قد تكون 'a' "أقل من" 'b'، ولكن ليس للسلسلة اليابانية نظام علاقة أبجدي ذا معنى مع حرف لامدا اليوناني، ولكن القدرة على تعيين "قيمة" موثوقة تجعل خوارزميات الفرز ممكنة، حتى لو لم تكن عقلانية تمامًا. يجب أن يعامل معظم الحالات القيمة المرجعة على أنها "متساوية" أو "غير متساوية".

مثل stricmp، تتوقع هذه الدالة أن تكون كلتا السلسلتين منتهيتين بـ NULL.

المعلمات

str1 السلسلة الأولى للمقارنة.
str2 السلسلة الثانية للمقارنة.

القيم المرجعة

-1 إذا كانت السلسلة الأولى "أقل من" السلسلة الثانية، 1 إذا كانت "أكبر من"، 0 إذا كانت متساوية.
