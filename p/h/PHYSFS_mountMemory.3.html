تحذير

أي شخص يدرس Unicode يعرف مشكلة "الحرف التركي I". هذه الواجهة لا تتعامل معها. افترض أن هذا الحرف الواحد في كل Unicode سيتم طيه بشكل غير صحيح تقريبًا. إذا كنت لا تعرف ما يدور حوله هذا، يمكنك على الأرجح تجاهل هذه المشكلة بالنسبة لمعظم الكوكب، ولكن الكمال مستحيل.

يجب أن يكون الدليل فارغًا قبل أن تتمكن هذه الدالة من حذفه.

سيؤدي حذف رابط رمزي إلى إزالة الرابط، وليس ما يشير إليه، بغض النظر عما إذا كنت قد قمت بـ "السماح بالروابط الرمزية" أم لا.

لذلك إذا كان لديك دليل الكتابة معينًا على "C:\mygame\writedir" واستدعيت PHYSFS_delete("downloads/maps/level1.map") فسيتم إزالة الملف "C:\mygame\writedir\downloads\maps\level1.map" من نظام الملفات الفعلي، إذا كان موجودًا وإذا سمح نظام التشغيل بالحذف.

لاحظ أنه في أنظمة Unix، قد يكون حذف ملف ناجحًا، ولكن الملف الفعلي لن تتم إزالته حتى تقوم جميع العمليات التي لديها مقبض ملف مفتوح له (بما في ذلك برنامجك) بإغلاق مقابضها.

من المرجح أن تكون أجزاء الملف لا تزال موجودة، بل تم جعلها متاحة لكتابة فوقها لاحقًا. لا تعتبر هذه طريقة أمنية أو أي شيء من هذا القبيل. :)

Physical File System API

This section describes the API for the Physical File System library. This library allows applications to abstract access to file systems, and to access archives (like ZIP files) as if they were directories in the file system.

int PHYSFS_ActionAtExit (int (*callback) (void))

Register a callback function to be executed when PhysicsFS is shut down. This allows you to add custom cleanup code. The callback function should return a non-zero value to indicate success, and zero to indicate failure.

Parameters

callback A pointer to the function to be called on exit.

Returns

Non-zero on success, zero on failure.

int PHYSFS_enumerate (const char * dir, PHYSFS_EnumerateCallback c, void * d)

Get a file listing of a search path's directory, using an application-defined callback, with errors reported. Internally, PHYSFS_enumerateFiles() just calls this function and then builds a list before returning to the application, so functionality is identical except for how the information is represented to the application.

Unlike PHYSFS_enumerateFiles(), this function does not return an array. Rather, it calls a function specified by the application once per element of the search path:

static PHYSFS_EnumerateCallbackResult printDir(void *data, const char *origdir, const char *fname)
{
    printf(" * We've got [%s] in [%s].\n", fname, origdir);
    return PHYSFS_ENUM_OK;  // give me more data, please.
}
// ...
PHYSFS_enumerate("/some/path", printDir, NULL);

Items sent to the callback are not guaranteed to be in any order whatsoever. There is no sorting done at this level, and if you need that, you should probably use PHYSFS_enumerateFiles() instead, which guarantees alphabetical sorting. This form reports whatever is discovered in each archive before moving on to the next. Even within one archive, we can't guarantee what order it will discover data. Any sorting you find in these callbacks is just pure luck. Do not rely on it. As this walks the entire list of archives, you may receive duplicate filenames.

This API and the callbacks themselves are capable of reporting errors. Prior to this API, callbacks had to accept every enumerated item, even if they were only looking for a specific thing and wanted to stop after that, or had a serious error and couldn't alert anyone. Furthermore, if PhysicsFS itself had a problem (disk error or whatnot), it couldn't report it to the calling app, it would just have to skip items or stop enumerating outright, and the caller wouldn't know it had lost some data along the way.

Now the caller can be sure it got a complete data set, and its callback has control if it wants enumeration to stop early. See the documentation for PHYSFS_EnumerateCallback for details on how your callback should behave.

Parameters

dir Directory, in platform-independent notation, to enumerate.
c Callback function to notify about search path elements.
d Application-defined data passed to callback. Can be NULL.

Returns

non-zero on success, zero on failure. Use PHYSFS_getLastErrorCode() to obtain the specific error. If the callback returns PHYSFS_ENUM_STOP to stop early, this will be considered success. Callbacks returning PHYSFS_ENUM_ERROR will make this function return zero and set the error code to PHYSFS_ERR_APP_CALLBACK.

See also

char ** PHYSFS_enumerateFiles (const char * dir)

Get a file listing of a search path's directory.

Warning

In PhysicsFS versions prior to 2.1, this function would return as many items as it could in the face of a failure condition (out of memory, disk i/o error, etc). Since this meant apps couldn't distinguish between complete success and partial failure, and since the function could always return NULL to report catastrophic failures anyway, in PhysicsFS 2.1 this function's policy changed: it will either return a list of complete results or it will return NULL for any failure of any kind, so we can guarantee that the enumeration ran to completion and has no gaps in its results.

char **rc = PHYSFS_enumerateFiles("savegames");
char **i;
for (i = rc; *i != NULL; i++)
    printf(" * We've got [%s].\n", *i);
PHYSFS_freeList(rc);
* We've got [x.sav].
* We've got [y.sav].
* We've got [z.sav].
* We've got [w.sav]..fi

Don't forget to call PHYSFS_freeList() with the return value from this function when you are done with it.

Get an array of paths to available CD-ROM drives. The dirs returned are platform-dependent ("D:\" on Win32, "/cdrom" or whatnot on Unix). تحويل سلسلة نصية بصيغة UTF-8 إلى سلسلة نصية بصيغة UCS-2.

تحذير

من شبه المؤكد أنك يجب أن تستخدم PHYSFS_utf8ToUtf16()، والتي أصبحت متاحة في PhysicsFS 2.1، إلا إذا كنت تعرف ما تفعله.

لن تقوم هذه الدالة بالإبلاغ عن خطأ إذا كانت هناك تسلسلات UTF-8 غير صالحة في السلسلة المصدر. ستقوم باستبدالها بحرف '؟' وتستمر.

سلاسل UCS-2 تستخدم 16 بت لكل حرف: TCHAR على Windows، عند البناء بدعم Unicode. يرجى ملاحظة أن الإصدارات الحديثة من Windows تستخدم UTF-16، وهي شكل موسع من UCS-2، وليس UCS-2 نفسه. من شبه المؤكد أنك تريد PHYSFS_utf8ToUtf16() بدلاً من ذلك، ولكنك بحاجة إلى فهم كيف يغير ذلك الأمور أيضًا.

للتأكد من أن المخزن المؤقت الوجهة كبير بما يكفي للتحويل، يرجى تخصيص مخزن مؤقت بحجم ضعف حجم المخزن المؤقت المصدر. تستخدم UTF-8 من بايت واحد إلى أربعة بايتات لكل حرف، ولكن UCS-2 يستخدم دائمًا بايتين، لذا ستتضاعف السلسلة النصية ذات ASCII المنخفضة بالكامل في الحجم!

سيتم اقتطاع السلاسل النصية التي لا تتناسب مع المخزن المؤقت الوجهة، ولكنها ستنتهي دائمًا بحرف null ولن تحتوي أبدًا على تسلسل UCS-2 غير مكتمل في النهاية. إذا كان طول المخزن المؤقت 0، فلن تقوم هذه الدالة بأي شيء.

dst مخزن مؤقت لتخزين السلسلة النصية المحولة بصيغة UCS-2.
