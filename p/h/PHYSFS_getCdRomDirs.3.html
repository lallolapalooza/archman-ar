مهجور

منذ PhysicsFS 2.1، استخدم PHYSFS_stat() بدلاً من ذلك. هذه الوظيفة هي مجرد غلاف لها.

يتم إرجاع وقت التعديل كعدد من الثواني منذ الحقبة Unix (منتصف الليل، 1 يناير 1970). يعتمد التحديد الدقيق والدقة لهذا الوقت على الأرشيف المحدد. إذا لم تكن هناك طريقة معقولة للحصول على هذه المعلومات لأرشيف معين، أو إذا حدث خطأ، فإن هذه الوظيفة ترجع (-1).

إذا كانت التوافقية الثنائية مع PhysicsFS 2.0 مهمة (وهو ما قد لا يكون صحيحًا للعديد من المستخدمين)، فيجب عليك استخدام هذه الوظيفة وليس PHYSFS_stat().

المعلمات

filename اسم الملف المراد فحصه، بتدوين مستقل عن النظام.

يعيد

وقت تعديل الملف. -1 إذا تعذر تحديده.

void PHYSFS_getLinkedVersion (PHYSFS_Version * ver)

الحصول على إصدار PhysicsFS المرتبط ببرنامجك. إذا كنت تستخدم إصدارًا مشتركًا (DLL) من PhysFS، فقد يكون مختلفًا عن الإصدار الذي قمت بتجميعه.

هذه وظيفة حقيقية؛ الماكرو PHYSFS_VERSION يخبرك بإصدار PhysFS الذي قمت بتجميعه:

PHYSFS_Version compiled;
PHYSFS_Version linked;
PHYSFS_VERSION(&compiled);
PHYSFS_getLinkedVersion(&linked);
printf("لقد قمنا بالتجميع ضد PhysicsFS الإصدار %d.%d.%d ...\n",
          compiled.major, compiled.minor, compiled.patch);
printf("ومع ذلك، فقد ارتبطنا بـ PhysicsFS الإصدار %d.%d.%d.\n",
          linked.major, linked.minor, linked.patch);

يمكن استدعاء هذه الوظيفة بأمان في أي وقت، حتى قبل PHYSFS_init().

حدد اسم مؤسستك (إذا لم تكن مؤسسة حقيقية، فإن اسمك أو اسم نطاق إنترنت لديك قد يفي بالغرض) واسم برنامجك. يجب أن تكون هذه أسماء صحيحة.

  • حاول استخدام نفس سلسلة المؤسسة (حتى اختلاف الأحرف الكبيرة) لجميع تطبيقاتك التي تستخدم هذه الوظيفة.
  • استخدم دائمًا سلسلة فريدة لكل تطبيق وتأكد من أنها لا تتغير بعد اختيار السلسلة.
  • الأحرف Unicode صالحة طالما أنها مشفرة بـ UTF-8، ولكن...
  • ... استخدم فقط الأحرف والأرقام والمسافات. تجنب أحرف مثل "Game Name 2: Bad Guy's Revenge!" ... "Game Name 2" كافٍ.

المؤشر الذي يتم إرجاعه بواسطة هذه الوظيفة يظل صالحًا حتى تستدعيه مرة أخرى أو تستدعي PHYSFS_deinit(). على الرغم من أنها ليست استدعاءً سريعًا، يجب عليك استدعائها مرة واحدة عند البدء ونسخ السلسلة إذا احتجت إليها.

يجب أن تفترض أن المسار الذي تم إرجاعه بواسطة هذه الوظيفة هو المسار الوحيد والآمن لكتابة الملفات (وأن PHYSFS_getUserDir() و PHYSFS_getBaseDir()، على الرغم من أنهما قد يكونان قابلين للكتابة، أو حتى آباء للمسار المرجع، ليسا المكان الذي يجب أن تكتب فيه).

تحديد مكان وجود الملف في قائمة البحث. يتم تحديد الملف بتدوين مستقل عن النظام. سيكون الاسم المرجع هو عنصر قائمة البحث حيث تم العثور على الملف، والذي يمكن أن يكون دليلًا أو ملفًا أرشيفيًا. حتى لو كانت هناك مطابقات متعددة في أجزاء مختلفة من المسار البحثي، يتم استخدام المطابقة الأولى التي تم العثور عليها فقط، تمامًا كما هو الحال عند فتح ملف.

لذلك، إذا كنت تبحث عن "maps/level1.map" وكان C:\mygame في قائمة البحث الخاصة بك و C:\mygame\maps\level1.map موجودًا، فسيتم إرجاع "C:\mygame".

إذا كان أي جزء من المطابقة رابطًا رمزيًا ولم تسمح بالروابط الرمزية بشكل صريح، فسيتم تجاهله وسيستمر البحث.

إذا قمت بتحديد دليل وهمي موجود فقط كنقطة تحميل، فسيتم ربطه بأول ملف أرشيفي هناك، على الرغم من أن هذا الدليل ليس بالضرورة موجودًا في ملف حقيقي.

تحذير

سترجع NULL إذا لم يكن هناك دليل حقيقي مرتبط (filename). على وجه التحديد، PHYSFS_mountIo() و PHYSFS_mountMemory() و PHYSFS_mountHandle() سترجع NULL حتى لو تم العثور على الاسم في قائمة البحث. خطط وفقًا لذلك.

إذا كنت ترغب في تحمل هذا الخطر، قم باستدعاء هذه الوظيفة بمعامل غير صفري. لاحظ أن هذا يتعلق بصندوق الحماية الخاص بلغة برمجة نصية للبرنامج، في حالة محاولة البرامج النصية غير الموثوق بها اختراق النظام. بشكل عام، قد يكون لدى المستخدم سبب مشروع لإنشاء رابط رمزي، لذا ما لم تشعر بوجود خطر معين في السماح به، يجب عليك السماح به.

يتم التحقق من الروابط الرمزية بشكل صريح فقط عند التعامل مع أسماء الملفات بالترميز المستقل عن المنصة. أي، عند إعداد مسارات البحث والكتابة الخاصة بك، وما إلى ذلك، لا يتم التحقق من الروابط الرمزية أبدًا.

يرجى ملاحظة أن PHYSFS_stat() سيتحقق دائمًا من المسار المحدد؛ إذا كان هذا المسار رابطًا رمزيًا، فلن يتم اتباعه بأي حال من الأحوال. إذا لم تسمح الروابط الرمزية من خلال هذه الوظيفة، فإن PHYSFS_stat() يتجاهلها، وسيعامل الاستعلام كما لو كان المسار غير موجود على الإطلاق.

يمكن تمكين أو تعطيل إذن الرابط الرمزي في أي وقت بعد استدعاء PHYSFS_init()، وهو معطل بشكل افتراضي.

void PHYSFS_utf8ToUcs4 (const char * src, PHYSFS_uint32 * dst, PHYSFS_uint64 len)

Convert a UTF-8 string to a UCS-4 string.

Warning

This function will not report an error if there are invalid UTF-8 sequences in the source string. It will replace them with a '?' character and continue on.

UCS-4 strings are 32-bits per character. They are the simplest way to handle Unicode strings, but they are also the least space-efficient. Most modern systems use UTF-16 (which is 16-bits per character, but can expand to 32-bits for some characters), but this is often considered a "compromise" in space and complexity.

To ensure that the destination buffer is large enough for the conversion, please allocate a buffer that is four times the size of the source buffer. UTF-8 uses from one to four bytes per character, but UCS-4 always uses four bytes per character. Therefore, a string that is entirely low-ASCII will quadruple in size!

Strings that don't fit in the destination buffer will be truncated, but will always be null-terminated and never have an incomplete UCS-4 sequence at the end. If the buffer length is 0, this function does nothing.

Parameters

src Null-terminated source string in UTF-8 format.
dst Buffer to store converted UCS-4 string.
len Size, in bytes, of destination buffer.

void PHYSFS_utf8ToUtf16 (const char * src, PHYSFS_uint16 * dst, PHYSFS_uint64 len)

Convert a UTF-8 string to a UTF-16 string.

Warning

This function will not report an error if there are invalid UTF-8 sequences in the source string. It will replace them with a '?' character and continue on.

UTF-16 strings are 16-bits per character (except some chars, which are 32-bits): TCHAR on Windows, when building with Unicode support. Modern Windows releases use UTF-16. Windows releases before 2000 used TCHAR, but only handled UCS-2. UTF-16 is UCS-2, except for the characters that are 4 bytes, which aren't representable in UCS-2 at all anyhow. If you aren't sure, you should be using UTF-16 at this point on Windows.

To ensure that the destination buffer is large enough for the conversion, please allocate a buffer that is double the size of the source buffer. UTF-8 uses from one to four bytes per character, but UTF-16 always uses two to four, so an entirely low-ASCII string will double in size! The UTF-16 characters that would take four bytes also take four bytes in UTF-8, so you don't need to allocate 4x the space just in case: double will do.

Strings that don't fit in the destination buffer will be truncated, but will always be null-terminated and never have an incomplete UTF-16 surrogate pair at the end. If the buffer length is 0, this function does nothing.

Parameters

src Null-terminated source string in UTF-8 format.
dst Buffer to store converted UTF-16 string.
len Size, in bytes, of destination buffer.

PHYSFS_sint64 PHYSFS_writeBytes (PHYSFS_File * handle, const void * buffer, PHYSFS_uint64 len)

Write data to a PhysicsFS filehandle. The file must be opened for writing.

Please note that while (len) is an unsigned 64-bit integer, you are limited to 63 bits (9223372036854775807 bytes), so we can return a negative value on error. If length is greater than 0x7FFFFFFFFFFFFFFF, this function will immediately fail. For systems without a 64-bit datatype, you are limited to 31 bits (0x7FFFFFFF, or 2147483647 bytes). We trust most things won't need to do multiple gigabytes of i/o in one call anyhow, but why limit things?

Parameters

handle retval from PHYSFS_openWrite() or PHYSFS_openAppend().
buffer buffer of (len) bytes to write to (handle).
len number of bytes being written to (handle).

Returns

number of bytes written. This may be less than (len); in the case of an error, the system may try to write as many bytes as possible, so an incomplete write might occur. PHYSFS_getLastErrorCode() can shed light on the reason this might be < (len). -1 if complete failure.
