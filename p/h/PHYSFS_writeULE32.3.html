DESCRIPTION

The PhysicsFS library provides a platform-independent API for accessing files. It allows applications to read and write files from various sources, such as directories, archives (like ZIP files), and CD-ROMs, in a unified manner. This abstraction hides the underlying filesystem details, making it easier to manage game data and resources.

The library offers functions for:

  • Byte order swapping (little-endian and big-endian) for integer types (32-bit and 64-bit).
  • Reading and writing data in various byte orders from/to files.
  • Checking the initialization status of the library and the permission for symbolic links.
  • Customizing memory allocation.
  • Mounting and unmounting archives and directories into the search path.
  • Retrieving information about mounted directories and the search path.
  • Enumerating files within directories using callbacks.
  • Converting strings between different character encodings (UTF-8, UCS-4, UCS-2, Latin1).
  • Performing case-insensitive string comparisons for various encodings.
  • Getting file status information.
  • Reading and writing raw bytes to/from file handles.
  • Mounting archives from various sources, including I/O interfaces, memory buffers, and file handles.
  • Error handling, including retrieving error codes and descriptions.
  • Accessing the user-specific preference directory.
  • Registering and deregistering custom archiver types.
  • Setting the root directory within an archive.

Byte Swapping Functions:

These functions swap the byte order of integer values between little-endian and the platform's native byte order, or between big-endian and the platform's native byte order.

  • PHYSFS_swapSLE32, PHYSFS_swapULE32: Swap 32-bit signed and unsigned integers, respectively.
  • PHYSFS_swapSLE64, PHYSFS_swapULE64: Swap 64-bit signed and unsigned integers, respectively.
  • PHYSFS_swapSBE16, PHYSFS_swapUBE16: Swap 16-bit signed and unsigned integers, respectively.
  • PHYSFS_swapSBE32, PHYSFS_swapUBE32: Swap 32-bit signed and unsigned integers, respectively.
  • PHYSFS_swapSBE64, PHYSFS_swapUBE64: Swap 64-bit signed and unsigned integers, respectively.

File I/O Functions:

These functions handle reading and writing data from/to PhysicsFS file handles, including conversion between different byte orders.

  • PHYSFS_readSLE16, PHYSFS_readULE16, PHYSFS_readSBE16, PHYSFS_readUBE16: Read and convert 16-bit signed/unsigned integers in little-endian or big-endian format.
  • PHYSFS_readSLE32, PHYSFS_readULE32, PHYSFS_readSBE32, PHYSFS_readUBE32: Read and convert 32-bit signed/unsigned integers in little-endian or big-endian format.
  • PHYSFS_readSLE64, PHYSFS_readULE64, PHYSFS_readSBE64, PHYSFS_readUBE64: Read and convert 64-bit signed/unsigned integers in little-endian or big-endian format.
  • PHYSFS_writeSLE16, PHYSFS_writeULE16, PHYSFS_writeSBE16, PHYSFS_writeUBE16: Convert and write 16-bit signed/unsigned integers in little-endian or big-endian format.
  • PHYSFS_writeSLE32, PHYSFS_writeULE32, PHYSFS_writeSBE32, PHYSFS_writeUBE32: Convert and write 32-bit signed/unsigned integers in little-endian or big-endian format.
  • PHYSFS_writeSLE64, PHYSFS_writeULE64, PHYSFS_writeSBE64, PHYSFS_writeUBE64: Convert and write 64-bit signed/unsigned integers in little-endian or big-endian format.
  • PHYSFS_readBytes: Read raw bytes from a file handle.
  • PHYSFS_writeBytes: Write raw bytes to a file handle.

Initialization and Configuration:

  • PHYSFS_isInit: Checks if PhysicsFS has been initialized.
  • PHYSFS_symbolicLinksPermitted: Checks if symbolic links are allowed.
  • PHYSFS_setAllocator: Allows setting a custom memory allocator.
  • PHYSFS_getAllocator: Retrieves the current memory allocator.
  • PHYSFS_getPrefDir: Gets the path for user-specific preference files.

Mounting and Search Path Management:

  • PHYSFS_mount: Adds a directory or archive to the search path.
  • PHYSFS_mountIo: Mounts an archive provided via a PHYSFS_Io interface.
  • PHYSFS_mountMemory: Mounts an archive from a memory buffer.
  • PHYSFS_mountHandle: Mounts an archive from a PHYSFS_File handle.
  • PHYSFS_getMountPoint: Retrieves the mount point for a given directory.
  • PHYSFS_getCdRomDirsCallback: Enumerates CD-ROM directories via a callback.
  • PHYSFS_getSearchPathCallback: Enumerates the search path via a callback.
  • PHYSFS_enumerateFilesCallback: Lists files in a directory using a callback.
  • PHYSFS_enumerate: Similar to PHYSFS_enumerateFilesCallback but also reports errors.
  • PHYSFS_unmount: Removes an entry from the search path.
  • PHYSFS_setRoot: Sets a subdirectory of an archive as the root.

String and Encoding Utilities:

  • PHYSFS_utf8FromUcs4: Converts UCS-4 to UTF-8.
  • PHYSFS_utf8ToUcs4: Converts UTF-8 to UCS-4.
  • PHYSFS_utf8FromUcs2: Converts UCS-2 to UTF-8.
  • PHYSFS_utf8ToUcs2: Converts UTF-8 to UCS-2.
  • PHYSFS_utf8FromLatin1: Converts Latin1 to UTF-8.
  • PHYSFS_utf8FromUtf16: Converts UTF-16 to UTF-8.
  • PHYSFS_utf8ToUtf16: Converts UTF-8 to UTF-16.
  • PHYSFS_caseFold: Folds a Unicode codepoint to its lowercase equivalent.
  • PHYSFS_utf8stricmp: Case-insensitive comparison of UTF-8 strings.
  • PHYSFS_utf16stricmp: Case-insensitive comparison of UTF-16 strings.
  • PHYSFS_ucs4stricmp: Case-insensitive comparison of UCS-4 strings.

Archiver Management:

  • PHYSFS_registerArchiver: Adds a new type of archive handler.
  • PHYSFS_deregisterArchiver: Removes an archive handler.

Error Handling:

  • PHYSFS_getLastErrorCode: Retrieves the last error code.
  • PHYSFS_getErrorByCode: Gets a human-readable description for an error code.
  • PHYSFS_setErrorCode: Sets the current thread's error code.

File Information:

  • PHYSFS_stat: Retrieves status information about a file or directory.

PHYSFS_EnumerateCallbackResult

typedef void(* PHYSFS_EnumFilesCallback) (void *data, const char *origdir, const char *fname)

Function signature for callbacks that enumerate files.

Warning

As of PhysicsFS 2.1, Use PHYSFS_EnumerateCallback with PHYSFS_enumerate() instead; it gives you more control over the process.

These are used to report a list of directory entries to an original caller, one file/dir/symlink per callback. All strings are UTF-8 encoded. Functions should not try to modify or free any string's memory.

These callbacks are used, starting in PhysicsFS 1.1, as an alternative to functions that would return lists that need to be cleaned up with PHYSFS_freeList(). The callback means that the library doesn't need to allocate an entire list and all the strings up front.

Be aware that promised data ordering in the list versions are not necessarily so in the callback versions. Check the documentation on specific APIs, but strings may not be sorted as you expect and you might get duplicate strings.

data User-defined data pointer, passed through from the API that eventually called the callback.

int PHYSFS_enumerate (const char * dir, PHYSFS_EnumerateCallback c, void * d)

احصل على قائمة بالملفات من مسار بحث، باستخدام رد اتصال معرف من قبل التطبيق، مع الإبلاغ عن الأخطاء. داخليًا، PHYSFS_enumerateFiles() تستدعي هذه الدالة فقط ثم تبني قائمة قبل أن تعود إلى التطبيق، لذا فإن الوظيفة متطابقة باستثناء كيفية تقديم المعلومات إلى التطبيق.

بخلاف PHYSFS_enumerateFiles()، هذه الدالة لا تعيد مصفوفة. بدلاً من ذلك، فإنها تستدعي دالة محددة من قبل التطبيق مرة واحدة لكل عنصر في مسار البحث:

static physfs_EnumerateCallbackResult printDir(void *data, const char *origdir, const char *fname)
{
    printf(" * We've got [%s] in [%s].\n", fname, origdir);
    return PHYSFS_ENUM_OK;  // أعطني المزيد من البيانات، من فضلك.
}
// ...
PHYSFS_enumerate("/some/path", printDir, NULL);

العناصر المقدمة إلى رد الاتصال ليست مضمونة أن تكون بأي ترتيب. لا يتم إجراء أي فرز على هذا المستوى، وإذا كنت بحاجة إلى ذلك، فيجب عليك استخدام PHYSFS_enumerateFiles()، التي تضمن الترتيب الأبجدي. هذا الشكل يبلغ عن ما تم العثور عليه في كل أرشيف قبل الانتقال إلى التالي. حتى داخل أرشيف واحد، لا يمكننا ضمان ترتيب اكتشاف البيانات. أي فرز تجده في ردود الاتصال هذه هو مجرد حظ. لا تعتمد عليه. نظرًا لأن هذا يمر عبر قائمة الملفات بأكملها، فقد تتلقى أسماء ملفات مكررة.

يمكن لهذه الواجهة و ردود الاتصال نفسها الإبلاغ عن الأخطاء. قبل هذه الواجهة، كان على ردود الاتصال قبول كل عنصر تم تعدادها، حتى لو كانوا يبحثون فقط عن كائن معين ويريدون التوقف بعد ذلك، أو كان لديهم خطأ خطير ولم يتمكنوا من تنبيه أي شخص. علاوة على ذلك، إذا كانت PhysicsFS نفسها لديها مشكلة (خطأ في القرص أو ما شابه)، فلن تتمكن من إبلاغ التطبيق، بل ستمرر العناصر أو توقف التعداد، ولن يعرف المتصل أنه فقد بيانات في الطريق.

الآن يمكن للمتصل أن يكون متأكدًا من أنه حصل على مجموعة كاملة من البيانات، ورد اتصال المتصل يتحكم فيما إذا كان يريد إيقاف التعداد مبكرًا. راجع وثائق PHYSFS_EnumerateCallback للحصول على تفاصيل حول كيفية سلوك رد الاتصال الخاص بك.

مهمل

تحذير

منذ PhysicsFS 2.1، تم التخلي عن هذه الدالة. قبل PhysicsFS 2.1، كانت الطريقة الوحيدة للحصول على تفاصيل خطأ تتجاوز القيمة المرجعة من دالة معينة. كان هذا مخصصًا كسلسلة نصية قابلة للقراءة للمستخدم بلغات متعددة، ولكنه غير مفيد لتحليل التطبيق. خارج السياق، لم يختر المطور اللغة في وقت الترجمة، وكان على مسؤولي PhysicsFS (بشكل سيء) الاحتفاظ بعمل ضخم للترجمة. لم يتمكن التطبيق من تحليل السلاسل، حتى لو كانت بلغة معينة، لأن بعضها تم إنشاؤه ديناميكيًا. في الإصدار 2.1 وما بعده، تعيد دائمًا سلسلة ثابتة باللغة الإنجليزية؛ يمكنك استخدامها كسلسلة مفتاح لترجماتك الخاصة إذا أردت، حيث لن تغير السلاسل القديمة. بالإضافة إلى ذلك، إذا كان تطبيقك يرغب في رؤية أخطاء محددة، فإننا نقدم الآن خيارًا أفضل: استخدم PHYSFS_getLastErrorCode().

الحصول على آخر رسالة خطأ PhysicsFS كسلسلة نصية قابلة للقراءة للمستخدم، NULL إذا لم يكن هناك خطأ منذ آخر استدعاء لهذه الدالة. المؤشر المرجع يشير إلى مخزن مؤقت داخلي. لكل خيط حالة خطأ فريدة مرتبطة به، ولكن في كل مرة يتم فيها تعيين رسالة خطأ جديدة، فإنها تتجاوز الحالة السابقة المرتبطة بذلك الخيط. من الآمن استدعاء هذه الدالة في أي وقت، حتى قبل PHYSFS_init().

PHYSFS_getLastError() و PHYSFS_getLastErrorCode() يعيدان تعيين نفس حالة الخطأ الخاصة بالخيط. استدعاء أحدهما سيمحو بيانات الآخر. إذا كنت بحاجة إلى كليهما، فاستدع PHYSFS_getLastErrorCode()، ثم مرر تلك القيمة إلى PHYSFS_getErrorByCode().

منذ PhysicsFS 2.1، تعرض هذه الدالة نصًا باللغة الإنجليزية فقط، ولكن السلاسل ثابتة، لذلك يمكنك استخدامها كمفاتيح في قاموس الترجمة الخاص بك. هذه السلاسل مخصصة لتمريرها مباشرة للمستخدم.

بشكل عام، تهتم التطبيقات فقط بما إذا كانت دالة ما قد فشلت؛ ومع ذلك، إذا كان الكود الخاص بك يتطلب مزيدًا من التفاصيل، فيجب عليك استخدام PHYSFS_getLastErrorCode() بدلاً من هذه الدالة.

void PHYSFS_permitSymbolicLinks(int allow)

Habilita o deshabilita el seguimiento de enlaces simbólicos. Algunos sistemas de archivos físicos y arquitecturas contienen archivos que son simplemente referencias a otros archivos. Al abrir un enlace simbólico físico, se abre automáticamente el archivo al que se refiere.

Por defecto, PhysicsFS verificará si un archivo es realmente un enlace simbólico durante las llamadas de apertura y fallará si lo es. De lo contrario, el enlace podría llevarte fuera de las rutas de lectura y escritura, comprometiendo la seguridad.

Si quieres asumir ese riesgo, llama a esta función con un valor distinto de cero. Ten en cuenta que esto es más para el sandboxing de lenguajes de scripting de programas, en caso de que scripts no confiables intenten comprometer el sistema. Generalmente, un usuario podría tener una razón legítima para establecer un enlace simbólico, por lo que no deberías deshabilitarlo a menos que sientas que existe un peligro específico.

Los enlaces simbólicos se verifican solo cuando se tratan nombres de archivos en notación independiente de plataforma. Es decir, cuando configures tus rutas de búsqueda y escritura, etc., los enlaces simbólicos nunca se verifican.

Nota: PHYSFS_stat() siempre verifica la ruta especificada; si es un enlace simbólico, no lo seguirá en ningún caso. Si no está permitido a través de esta función, PHYSFS_stat() ignorará los enlaces simbólicos y tratará la consulta como si la ruta no existiera.

El permiso de enlaces simbólicos se puede habilitar o deshabilitar después de haber llamado PHYSFS_init(), y está deshabilitado por defecto.

Parámetros

allow distinto de cero para permitir enlaces simbólicos, cero para deshabilitar el enlace.

void PHYSFS_utf8ToUcs4 (const char * src, PHYSFS_uint32 * dst, PHYSFS_uint64 len)

Convert a UTF-8 string to a UCS-4 string.

UTF-32 strings are 32-bits per character, but are an ever-increasing rarity outside of Linux/Unix systems. Modern Windows releases use UTF-16. Linux systems use UTF-8. There are never any 4-byte characters in UTF-16; they are represented with surrogate pairs. These surrogate pairs are two 16-bit values that make up a single 32-bit value. So, this function can convert a string to an array of 32-bit values.

To ensure that the destination buffer is large enough for the conversion, please allocate a buffer that is double the size of the source buffer. UTF-8 uses from one to four bytes per character, but UCS-4 always uses four bytes per character. So an entirely low-ASCII string will grow 4x in size. The UTF-8 characters that would take four bytes also take four bytes in UCS-4, so you don't need to allocate 4x the space just in case: double will do.

Strings that don't fit in the destination buffer will be truncated, but will always be null-terminated and never have an incomplete UCS-4 sequence at the end. If the buffer length is 0, this function does nothing.

Parameters

src Null-terminated source string in UTF-8 format.
dst Buffer to store converted UCS-4 string.
len Size, in bytes, of destination buffer.
