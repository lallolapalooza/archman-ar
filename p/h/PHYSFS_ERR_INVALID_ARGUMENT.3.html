DESCRIPTION

PhysicsFS is a library that provides an abstraction layer over various data sources. It allows you to treat directories and archive files (like ZIP, RAR, PNG!, etc.) as if they were a single, unified directory hierarchy. This can be useful for games and other applications that need to access large amounts of data that might be stored in various formats.

The library is designed to be portable and efficient. It supports various platforms and file systems, and it minimizes the overhead associated with data access.

Byte Order Conversion

The following functions convert data between little-endian and big-endian byte orders and the platform's native byte order. These are useful when reading or writing data from/to files that may have been created on a different architecture.

Reading and Writing Data

These functions provide low-level access to read and write raw bytes from and to PhysicsFS file handles.

Mounting Archives and Directories

These functions allow you to add archives or directories to the PhysicsFS search path. This makes their contents accessible as if they were part of the main file system hierarchy.

PHYSFS_mount()
Mounts a directory or archive file. The appendToPath argument determines whether the new directory is added to the beginning or end of the search path.
PHYSFS_mountIo()
Mounts an archive provided via a custom PHYSFS_Io interface.
PHYSFS_mountMemory()
Mounts an archive contained within a memory buffer.
PHYSFS_mountHandle()
Mounts an archive contained within an existing PHYSFS_File handle.
PHYSFS_unmount()
Removes a previously mounted directory or archive from the search path.
PHYSFS_setRoot()
Sets the root directory for an archive, allowing access to its subdirectories as if they were the top-level directory.

File Information and Enumeration

These functions provide ways to query information about files and directories and to list the contents of directories.

PHYSFS_stat()
Retrieves detailed information about a file or directory (size, modification time, etc.).
PHYSFS_enumerateFilesCallback()

غير معروف

تحذير

منذ PhysicsFS 2.1، تم حذف هذه الوظيفة. قبل PhysicsFS 2.1، كانت هذه هي الطريقة الوحيدة للحصول على تفاصيل الخطأ خارج التقييم الأساسي لوظيفة ما. كان من المفترض أن تكون سلسلة قابلة للقراءة بلغات متعددة ولم تكن مفيدة لتحليل التطبيقات. كانت مشكلة، حيث اختار المطور اللغة في وقت الترجمة، وكان على مسؤولي PhysicsFS الاحتفاظ بعمل ترجمة كبير. لم يتمكن التطبيق من تحليل السلاسل، حتى لو كانت بلغة معينة، لأن بعضها تم إنشاؤه ديناميكيًا. منذ 2.1 وما بعده، ترجع دائمًا سلسلة ثابتة باللغة الإنجليزية؛ يمكنك استخدامها كمفتاح سلسلة لترجمتك الخاصة، طالما أننا نعدك بعدم تغيير سلاسل الخطأ الحالية. أيضًا، إذا أراد تطبيقك رؤية أخطاء محددة، فنحن نقدم الآن خيارًا أفضل: استخدم PHYSFS_getLastErrorCode().

الحصول على آخر رسالة خطأ من PhysicsFS كسلسلة قابلة للقراءة، منتهية بـ NULL. سترجع NULL إذا لم يكن هناك خطأ منذ آخر استدعاء لهذه الوظيفة. يشير المؤشر المرجع إلى مخزن مؤقت داخلي. لكل خيط حالة خطأ فريدة مرتبطة به، ولكن في كل مرة يتم فيها تعيين رسالة خطأ جديدة، فإنها ستحل محل الرسالة السابقة المرتبطة بذلك الخيط. من الآمن استدعاء هذه الوظيفة في أي وقت، حتى قبل PHYSFS_init().

PHYSFS_getLastError() و PHYSFS_getLastErrorCode() كلاهما يعيدان تعيين حالة الخطأ المرتبطة بخيط معين. استدعاء أحدهما سيمسح بيانات الآخر. إذا كنت بحاجة إلى كليهما، استدعاء PHYSFS_getLastErrorCode()، ثم تمرير تلك القيمة إلى PHYSFS_getErrorByCode().

منذ PhysicsFS 2.1، تعرض هذه الوظيفة نصًا باللغة الإنجليزية فقط، ولكن السلاسل ثابتة، لذا يمكنك استخدامها كمفاتيح في قاموس الترجمة الخاص بك. هذه السلاسل مخصصة ليتم تمريرها مباشرة إلى المستخدم.

void PHYSFS_permitSymbolicLinks (int allow)

Habilita o deshabilita el seguimiento de enlaces simbólicos. Algunos sistemas de archivos físicos y arquitecturas contienen archivos que son simplemente punteros a otros archivos. Al abrir un enlace simbólico físico, se abrirá transparentemente el archivo al que se apunta.

Por defecto, PhysicsFS verificará si un archivo es realmente un enlace simbólico durante las llamadas de apertura y fallará si es así. En caso de no tener esta función activada, el enlace podría llevarte fuera de los caminos de lectura y escritura, comprometiendo la seguridad.

Si deseas asumir ese riesgo, llama a esta función con un valor distinto de cero. Ten en cuenta que esto es más para el sandboxing de un lenguaje de scripting del programa, en caso de que scripts no confiables intenten comprometer el sistema. En general, un usuario podría tener una razón legítima para establecer un enlace simbólico, así que no deberías deshabilitarlos a menos que sientas un peligro específico.

Los enlaces simbólicos solo se verán cuando se manejen nombres de archivos en notación independiente de plataforma. Es decir, cuando configures tus caminos de búsqueda y escritura, etc., los enlaces simbólicos nunca se verán.

Nota: PHYSFS_stat() siempre verificará la ruta especificada; si esa ruta es un enlace simbólico, no se seguirá en ningún caso. Si no se permite a través de esta función, PHYSFS_stat() ignorará el enlace y se tratará como si la ruta no existiera.

La permisión de enlaces simbólicos se puede activar o desactivar en cualquier momento después de haber llamado a PHYSFS_init(), y está deshabilitada por defecto.

Parámetros

allow distinto de cero para permitir enlaces simbólicos, cero para deshabilitar el enlace.

void PHYSFS_utf8FromLatin1 (const char * src, char * dst, PHYSFS_uint64 len)

Convert a Latin1 string to a UTF-8 string. Latin1 strings are 8-bits per character: a popular "high ASCII" encoding.

To ensure that the destination buffer is large enough for the conversion, please allocate a buffer that is double the size of the source buffer. UTF-8 expands latin1 codepoints over 127 from 1 to 2 bytes, so the string may grow in some cases.

Strings that don't fit in the destination buffer will be truncated, but will always be null-terminated and never have an incomplete UTF-8 sequence at the end. If the buffer length is 0, this function does nothing.

Please note that we do not supply a UTF-8 to Latin1 converter, since Latin1 can't express most Unicode codepoints. It's a legacy encoding; you should be converting away from it at all times.

src Null-terminated source string in Latin1 format.
dst Buffer to store converted UTF-8 string.
len Size, in bytes, of destination buffer.

If both strings are exclusively low-ASCII characters, this will do the right thing, as that is also valid UTF-8. If there are any high-ASCII chars, this will not do what you expect!

str2 Second string to compare.

Write data to a PhysicsFS filehandle. The file must be opened for writing.

Please note that while (len) is an unsigned 64-bit integer, you are limited to 63 bits (9223372036854775807 bytes), so we can return a negative value on error.
