int PHYSFS_caseFold (const PHYSFS_uint32 from, PHYSFS_uint32 * to)

"Fold" a Unicode codepoint to a lowercase equivalent.
(This is for limited, hardcore use. If you don't immediately see a need for
it, you can probably ignore this forever.)

This will convert a Unicode codepoint into its lowercase
equivalent. Bogus codepoints and codepoints without a lowercase equivalent
will be returned unconverted.

Note that you might get multiple codepoints in return! The German
Eszett, for example, will fold down to two lowercase latin 's' codepoints.
The theory is that if you fold two strings, one with an Eszett and one with
"SS" down, they will match.

Warning

Anyone that is a student of Unicode knows about the
"Turkish I" problem. This API does not handle it. Assume this one
letter in all of Unicode will definitely fold sort of incorrectly. If you
don't know what this is about, you can probably ignore this problem for most
of the planet, but perfection is impossible.

Parameters

from The codepoint to fold.
to Buffer to store the folded codepoint values into. This should point to
space for at least 3 PHYSFS_uint32 slots.

Returns

The number of codepoints the folding produced. Between 1
and 3.

int PHYSFS_deinit (void )

Deinitialize the PhysicsFS library. This closes any files opened
via PhysicsFS, blanks the search/write paths, frees memory, and invalidates
all of your file handles.

Note that this call can FAIL if there's a file open for writing
that refuses to close (for example, the underlying operating system was
buffering writes to network filesystem, and the fileserver has crashed, or a
hard drive has failed, etc). It is usually best to close all write handles
yourself before calling this function, so that you can gracefully handle a
specific failure.

Once successfully deinitialized, PHYSFS_init() can be
called again to restart the subsystem. All default API states are restored
at this point, with the exception of any custom allocator you might have
specified, which survives between initializations.

Returns

nonzero on success, zero on error. Specifics of the error
can be gleaned from PHYSFS_getLastError(). If failure, state of PhysFS
is undefined, and probably badly screwed up.

int PHYSFS_delete (const char * filename)

Delete a file or directory. (filename) is specified in
platform-independent notation in relation to the write dir.

A directory must be empty before this call can delete it.

Deleting a symlink will remove the link, not what it points to,
regardless of whether you "permitSymLinks" or not.

So if you've got the write dir set to
"C:\mygame\writedir" and call
PHYSFS_delete("downloads/maps/level1.map") then the file
"C:\mygame\writedir\downloads\maps\level1.map" is removed from the
physical filesystem, if it exists and the operating system permits the
deletion.

Note that on Unix systems, deleting a file may be successful, but
the actual file won't be removed until all processes that have an open
filehandle to it (including your program) close their handles.

Chances are, the bits that make up the file still exist, they are
just made available to be written over at a later point. Don't consider this
a security method or anything. :)

Parameters

filename Filename to delete.

Returns

nonzero on success, zero on error. Use
PHYSFS_getLastErrorCode() to obtain the specific error.

const char *PHYSFS_getPrefDir (const char * org, const char * app)

احصل على مسار الدليل الخاص حيث يمكن كتابة الملفات. دالة مساعدة.

احصل على "pref dir". يستخدم هذا للسماح للمستخدمين بكتابة ملفات شخصية (تفضيلات وألعاب محفوظة ، وما إلى ذلك) خاصة بتطبيقك. هذا الدليل فريد لكل مستخدم ولكل تطبيق.

تقرر هذه الدالة الموقع المناسب في نظام الملفات الأصلي ، وتنشئ الدليل إذا لزم الأمر ، وترجع سلسلة بتدوين نظام التشغيل ، ومناسبة للتمرير إلى PHYSFS_setWriteDir().

على Windows ، قد تبدو مثل: "C:\\Users\\bob\\AppData\\Roaming\\My Company\\My Program Name"

على Linux ، قد تبدو مثل: "/home/bob/.local/share/My Program Name"

على Mac OS X ، قد تبدو مثل: "/Users/bob/Library/Application Support/My Program Name"

(إلخ.)

يجب عليك استخدام "pref dir" لمسار الكتابة الخاص بك ، ويجب أيضًا وضعه بالقرب من بداية مسار البحث الخاص بك. قدمت الإصدارات القديمة من PhysicsFS PHYSFS_getUserDir() فقط وتركت لك تحديد مكان وضع الملفات تحت هذه الشجرة. تجد هذه الدالة الموقع الصحيح لأي منصة ، والذي لا يتغير فقط بين أنظمة التشغيل ، ولكن أيضًا بين إصدارات نظام التشغيل نفسه.

اسم مؤسستك (إذا لم تكن مؤسسة حقيقية ، فيمكن أن يكون اسمك أو اسم نطاق إنترنت تملكه) واسم تطبيقك. يجب أن تكون هذه أسماء مناسبة.

يمكن تحويل كل من سلاسل (org) و (app) إلى جزء من اسم دليل ، لذا يرجى اتباع هذه القواعد:

  • استخدم نفس سلسلة المؤسسة (بما في ذلك حالة الأحرف) لجميع تطبيقاتك التي تستخدم هذه الدالة.
  • استخدم سلسلة تطبيق فريدة لكل منها ، وتأكد من أنها لا تتغير لتطبيق بمجرد أن تقررها.

int PHYSFS_registerArchiver (const PHYSFS_Archiver * archiver)

يضيف archiver جديدًا إلى النظام.

ملاحظة

هذه أداة متقدمة وصعبة الاستخدام. لا تحتاج إليها إلا إذا كنت تعرف حقًا ما الذي تفعله. معظم التطبيقات لن تحتاج إليها.

إذا كنت ترغب في توفير archiver الخاص بك (على سبيل المثال، تنسيق ملف مخصص أو شيء افتراضي تريد رؤيته كنظام ملفات يمكنك الوصول إليه عبر واجهات PhysicsFS العادية)، فهذا هو المكان الذي تبدأ فيه. بمجرد تسجيل archiver بنجاح، يمكنك استخدام PHYSFS_mount() لإضافة الملفات التي يدعمها archiver الخاص بك إلى مسار البحث، أو استخدامه كدليل للكتابة. داخليًا، تستخدم PhysicsFS هذه الدالة لتسجيل archivers الخاصة بها، مثل دعم ZIP، وما إلى ذلك.

يمكن أن يكون لديك archivers اثنان يتعاملان مع نفس امتداد الملف. إذا كنت تريد تجنب التعارض، يمكنك إلغاء تسجيل archiver الآخر (بما في ذلك archivers الداخلية) باستخدام PHYSFS_deregisterArchiver().

يتم نسخ البيانات الموجودة في (archiver)؛ يمكنك تحرير هذا المؤشر عند عودة هذه الدالة.

بمجرد عودة هذه الدالة بنجاح، ستتمكن PhysicsFS من دعم الملفات من هذا النوع حتى تقوم بإلغاء تسجيل archiver مرة أخرى.

int PHYSFS_setRoot(const char *archive, const char *subdir)

يجعل دليلًا فرعيًا داخل أرشيف كدليل الجذر له. هذا يسمح لك بتقييد الملفات التي يمكن الوصول إليها داخل أرشيف معين. على سبيل المثال، إذا كان لديك x.zip مع ملف موجود في y/z.txt تم تحميله إلى /a، وإذا قمت باستدعاء PhysFS_openRead("/a/z.txt")، فسيكون ذلك ناجحًا. إذا قمت باستدعاء PhysFS_setRoot("x.zip"، "/y")، فسيتم استدعاء PhysFS_openRead("/a/z.txt") بنجاح.

يمكنك تغيير جذر الأرشيف في أي وقت، مما يؤثر على شجرة الملفات التي يتم استيعابها (حسب المكان الذي تنتقل إليه المسارات، قد يوفر ملفات مختلفة من أرشيف مختلف). إذا قمت بتعيين الجذر إلى NULL أو إلى "/"، فسيتم التعامل مع الأرشيف كما لو لم يكن له جذر خاص (كما لو تم تحميل الأرشيف بشكل طبيعي).

تغيير الجذر يؤثر فقط على العمليات المستقبلية على مسارات الدلائل؛ لن يتأثر الملف الذي تم فتحه من مسار تغير بسبب setRoot.

لا يقتصر تعيين جذر جديد على الأرشيفات في دليل البحث؛ يمكنك تعيين واحد في دليل الكتابة، والذي قد يكون مفيدًا إذا كانت لديك ملفات مفتوحة للكتابة ولا يمكنك تغيير دليل الكتابة الآن.

غير مسموح بتعيين دليل فرعي غير موجود كجذر لأرشيف؛ ومع ذلك، فلن يتم رؤية أي ملفات في هذه الحالة. إذا تم إنشاء الدلائل المفقودة في النهاية ( mkdir إلى نظام الملفات الفعلي، وما إلى ذلك)، فسينعكس ذلك في شجرة الملفات المستوعبة.

المعلمات

archive الدليل/الأرشيف الذي سيتم تغيير الجذر له.
subdir الدليل الفرعي الجديد لجعله الجذر لهذا الأرشيف.

العودة

int PHYSFS_setSaneConfig(const char *organization, const char *appName, const char *archiveExt, int includeCdRoms, int archivesFirst)

يقوم بتعيين مسارات معقولة، مسارات افتراضية. دالة مساعدة.

سيتم تعيين دليل الكتابة إلى الدليل المفضل الذي تم إرجاعه بواسطة

PHYSFS_getPrefDir(organization, appName)

، والذي يتم إنشاؤه إذا لم يكن موجودًا.

المعلومات أعلاه كافية لضمان فصل مجلد تكوين برنامجك عن ملفات الفوضى الأخرى وأن يكون مستقلاً عن نظام التشغيل.

سيكون مسار البحث:

  • دليل الكتابة (يتم إنشاؤه إذا لم يكن موجودًا)
  • دليل الأساس (PHYSFS_getBaseDir())
  • جميع دلائل الأقراص المدمجة التي تم العثور عليها (اختياري)

يتم البحث عن هذه الدلائل بامتدادات (archiveExt)، والتي، إذا كانت صالحة ومدعومة، تتم إضافتها أيضًا إلى البحث عن الملفات. إذا حددت "PKG" لـ (archiveExt)، وكان هناك ملف يسمى data.PKG في الدليل الأساسي، فسيتم فحصه. يمكن إضافة الملفات إلى بداية أو نهاية البحث عن الملفات بترتيب أبجدي، بغض النظر عن مكان العثور عليها. يتم تحميل جميع الملفات في جذر نظام الملفات الافتراضي ("/") .

يمكن تحقيق كل ما سبق من البرنامج، ولكن هذه الدالة تقوم بكل ذلك نيابة عنك. يمكنك إضافة المزيد إلى البحث عن الملفات يدويًا أيضًا.

المعلمات

الحصول على قائمة بأنواع الأرشيفات المدعومة. الحصول على قائمة بأنواع الأرشيفات المدعومة بواسطة هذا التطبيق لـ PhysicsFS. هذه هي تنسيقات الملفات القابلة للاستخدام لمدخلات البحث. هذا فقط للمعلومات. ملاحظة: الامتداد المذكور هو مجرد اصطلاح: إذا ذكرت "ZIP"، فيمكنك فتح أرشيف متوافق مع "XYZ" إذا أردت.

PHYSFS_ArchiveInfo **i;
for (i = PHYSFS_supportedArchiveTypes(); *i != NULL; i++)
{
    printf("Supported archive: [%s], which is [%s].\n",
             (*i)->extension, (*i)->description);
}

القيم المرجعة هي مؤشرات إلى ذاكرة داخلية ويجب اعتبارها للقراءة فقط وغير قابلة للتحرير. القيم المرجعة صالحة حتى الاستدعاء التالي لـ PHYSFS_deinit()، PHYSFS_registerArchiver()، أو PHYSFS_deregisterArchiver().

العودة
