int PHYSFS_enumerate (const char * dir, PHYSFS_EnumerateCallback c, void * d)

الحصول على قائمة بالملفات من دليل في مسار البحث، باستخدام دالة استدعاء معرفة من قبل المستخدم، مع الإبلاغ عن الأخطاء. داخليًا، PHYSFS_enumerateFiles() تستدعي هذه الدالة فقط ثم تبني قائمة قبل إرجاعها إلى التطبيق، لذا فإن الوظيفة متطابقة، باستثناء كيفية تقديم المعلومات إلى التطبيق.

على عكس PHYSFS_enumerateFiles()، لا تُرجع هذه الدالة مصفوفة. بدلاً من ذلك، تقوم باستدعاء دالة يحددها التطبيق مرة واحدة لكل عنصر في مسار البحث:

static physfs_EnumerateCallbackResult printDir(void *data, const char *origdir, const char *fname)
{
    printf(" * We've got [%s] in [%s].\n", fname, origdir);
    return PHYSFS_ENUM_OK;  // أعطني المزيد من البيانات، من فضلك.
}
// ...
PHYSFS_enumerate("/some/path", printDir, NULL);

العناصر المرسلة إلى دالة الاستدعاء غير مضمونة بأي ترتيب. لا يتم إجراء أي فرز على هذا المستوى، وإذا كنت بحاجة إليه، فيجب عليك استخدام PHYSFS_enumerateFiles()، والذي يضمن الترتيب الأبجدي. هذا الشكل يبلغ عما يتم العثور عليه في كل أرشيف قبل الانتقال إلى التالي. حتى داخل أرشيف واحد، لا يمكننا ضمان ترتيب اكتشاف البيانات. أي فرز تجده في دوال الاستدعاء هذه هو مجرد حظ. لا تعتمد عليه. نظرًا لأن هذا يمر عبر قائمة الأرشيفات بأكملها، فقد تتلقى أسماء ملفات مكررة.

واجهة برمجة التطبيقات هذه ودوال الاستدعاء نفسها قادرة على الإبلاغ عن الأخطاء. قبل واجهة برمجة التطبيقات هذه، كان على دوال الاستدعاء قبول كل عنصر تم إدراجه، حتى لو كانوا يبحثون فقط عن كائن معين وأرادوا التوقف بعد ذلك، أو لديهم خطأ جسيم ولم يتمكنوا من إبلاغ أي شخص. علاوة على ذلك، إذا واجه PhysicsFS نفسه مشكلة (خطأ في القرص، وما إلى ذلك)، فلن يتمكن من إبلاغ التطبيق بها، بل سيمرر ببساطة عناصر أو يوقف الإدراج، ولن يعرف المتصل أنه فقد بيانات.

الآن يمكن للمتصل التأكد من حصوله على مجموعة كاملة من البيانات، ولديه دالة الاستدعاء تحكم فيما إذا كان يريد إيقاف الإدراج مبكرًا. راجع المستند الخاص بـ PHYSFS_EnumerateCallback للحصول على تفاصيل حول كيفية سلوك دالة الاستدعاء الخاصة بك.

المعلمات

dir الدليل، بترميز مستقل عن نظام التشغيل، الذي سيتم إدراجه.
c دالة الاستدعاء للإبلاغ عن عناصر المسار.
d بيانات معرفة من قبل التطبيق يتم تمريرها إلى دالة الاستدعاء. يمكن أن تكون NULL.

القيمة المرجعة

قيمة غير صفرية عند النجاح، صفر عند الفشل. استخدم PHYSFS_getLastErrorCode() للحصول على الخطأ المحدد. إذا أعادت دالة الاستدعاء PHYSFS_ENUM_STOP، فسيتم اعتبار ذلك نجاحًا. دوال الاستدعاء التي تعيد PHYSFS_ENUM_ERROR ستجعل هذه الدالة تعيد صفرًا وتضبط رمز الخطأ على PHYSFS_ERR_APP_CALLBACK.

تحذير

في إصدارات PhysicsFS قبل 2.1، كانت هذه الدالة تعيد أكبر عدد ممكن من العناصر في حالة حدوث فشل (خطأ في الذاكرة، خطأ في إدخال/إخراج القرص، إلخ). نظرًا لأن هذا جعل التطبيقات غير قادرة على التمييز بين النجاح الكامل والفشل الجزئي، وبما أن الدالة كانت دائمًا قادرة على إعادة NULL للإبلاغ عن فشل كارثي، فقد تغيرت سياسة هذه الدالة في PhysicsFS 2.1: ستعيد قائمة نتائج كاملة أو ستعيد NULL في حالة حدوث أي فشل، حتى نتمكن من ضمان انتهاء الإدراج بشكل صحيح وعدم وجود فجوات في نتائجه.

يتم استيفاء الأدلة المتطابقة. أي، إذا كان "C:\mydir" موجودًا في مسار البحث ويحتوي على دليل "savegames" يحتوي على "x.sav"، "y.sav"، و "z.sav"، وإذا كان هناك أيضًا دليل "C:\userdir" في مسار البحث به دليل فرعي "savegames" يحتوي على "w.sav"، فإن الكود التالي:

char **rc = PHYSFS_enumerateFiles("savegames");
char **i;
for (i = rc; *i != NULL; i++)
    printf(" * We've got [%s].\n", *i);
PHYSFS_freeList(rc);
* We've got [x.sav].
* We've got [y.sav].
* We've got [z.sav].
* We've got [w.sav]..fi
يمكنك فرز القائمة كما تشاء بحرية. ومع ذلك، فإن البيانات المرجعة لا تحتوي دائمًا على تكرارات وهي دائمًا مرتبة أبجديًا (أو بالأحرى: مرتبة حسب حساسية حالة أحرف Unicode) لك.
تذكر استدعاء PHYSFS_freeList() مع القيمة المرجعة من هذه الدالة عند الانتهاء منها.

PHYSFS_Allocator * PHYSFS_getAllocator (void )

Get the currently used allocator. This can be useful for apps that want to access PhysicsFS's internal, default allocation routines, as well as for external code that wants to share the same allocator, even if the application specified their own.

This call is only valid between PHYSFS_init() and PHYSFS_deinit() calls; it will return NULL if the library isn't initialized. As we can't guarantee the state of the internal allocators unless the library is initialized, you shouldn't use any allocator returned here after a call to PHYSFS_deinit().

Do not call the returned allocator's Init() or Deinit() methods under any circumstances.

If you aren't immediately sure what to do with this function, you can safely ignore it altogether.

Returns

Current allocator, as set by PHYSFS_setAllocator(), or PhysicsFS's internal, default allocator if no application defined allocator is currently set. Will return NULL if the library is not initialized.

تعمل هذه الدالة تمامًا مثل PHYSFS_mount()، ولكنها تأخذ مقبض PHYSFS_File بدلاً من مسار اسم. يحتوي هذا المقبض على جميع بيانات الأرشيف، ويتم استخدامه بدلاً من ملف حقيقي في نظام الملفات المادي. قد يكون PHYSFS_File مدعومًا بملف حقيقي في نظام الملفات المادي، ولكنه ليس بالضرورة كذلك. الاستخدام الأكثر شيوعًا لهذا هو على الأرجح لتركيب الأرشيفات المخزنة داخل أرشيفات أخرى.

int PHYSFS_ucs4stricmp (const PHYSFS_uint32 * str1, const PHYSFS_uint32 * str2)

مقارنة غير حساسة لحالة الأحرف لسلسلتين UCS-4. هذا بديل لـ strcasecmp/stricmp ويتوقع أن تكون كلتا السلسلتين بتشفير UCS-4 (المعروف أيضًا باسم UTF-32). سيقوم بإجراء "طي للحالة" لتحديد ما إذا كانت نقاط ترميز Unicode في السلاسل متطابقة.

سيبلغ عن أي سلسلة "أكبر من" الأخرى، ولكن كن على علم بأن هذا لا يعني بالضرورة شيئًا: قد يكون 'a' "أقل من" 'b'، ولكن اليابانية kuten ليس لها علاقة أبجدية ذات معنى مع lambda اليونانية، ولكن القدرة على تعيين "قيمة" موثوقة تجعل خوارزميات الفرز ممكنة، وإن لم تكن دائمًا منطقية. يجب أن تعامل معظم الحالات القيمة المرجعة على أنها "متساوية" أو "غير متساوية".

مثل stricmp، يتوقع هذا أن تكون كلتا السلسلتين منتهيتين بـ NULL.

المعلمات

str1 السلسلة الأولى للمقارنة.
str2 السلسلة الثانية للمقارنة.

المرتجعات

-1 إذا كانت str1 "أقل من" str2، 1 إذا كانت "أكبر من"، 0 إذا كانت متساوية.

سيبلغ عن أي سلسلة "أكبر من" الأخرى، ولكن كن على علم بأن هذا لا يعني بالضرورة شيئًا: قد يكون 'a' "أقل من" 'b'، ولكن اليابانية kuten ليس لها علاقة أبجدية ذات معنى مع lambda اليونانية، ولكن القدرة على تعيين "قيمة" موثوقة تجعل خوارزميات الفرز ممكنة، وإن لم تكن دائمًا منطقية. يجب أن تعامل معظم الحالات القيمة المرجعة على أنها "متساوية" أو "غير متساوية".

مثل stricmp، يتوقع هذا أن تكون كلتا السلسلتين منتهيتين بـ NULL.

void PHYSFS_utf8ToUcs4(const char * src, PHYSFS_uint32 * dst, PHYSFS_uint32 len)

Convert a UTF-8 string to a UCS-4 string.

Warning

This function will not report an error if there are invalid UTF-8 sequences in the source string. It will replace them with a '?' character and continue on.

UCS-4 strings are 32-bits per character. UTF-8 uses from one to four bytes per character. To ensure that the destination buffer is large enough for the conversion, please allocate a buffer that is four times the size of the source buffer.

Strings that don't fit in the destination buffer will be truncated, but will always be null-terminated and never have an incomplete UCS-4 sequence at the end. If the buffer length is 0, this function does nothing.

Parameters

src Null-terminated source string in UTF-8 format.
dst Buffer to store converted UCS-4 string.
len Size, in bytes, of destination buffer.

void PHYSFS_utf8ToUtf16 (const char * src, PHYSFS_uint16 * dst, PHYSFS_uint64 len)

Convert a UTF-8 string to a UTF-16 string.

Warning

This function will not report an error if there are invalid UTF-8 sequences in the source string. It will replace them with a '?' character and continue on.

UTF-16 strings are 16-bits per character (except some chars, which are 32-bits): TCHAR on Windows, when building with Unicode support. Modern Windows releases use UTF-16. Windows releases before 2000 used TCHAR, but only handled UCS-2. UTF-16 is UCS-2, except for the characters that are 4 bytes, which aren't representable in UCS-2 at all anyhow. If you aren't sure, you should be using UTF-16 at this point on Windows.

To ensure that the destination buffer is large enough for the conversion, please allocate a buffer that is double the size of the source buffer. UTF-8 uses from one to four bytes per character, but UTF-16 always uses two to four, so an entirely low-ASCII string will double in size! The UTF-16 characters that would take four bytes also take four bytes in UTF-8, so you don't need to allocate 4x the space just in case: double will do.

Strings that don't fit in the destination buffer will be truncated, but will always be null-terminated and never have an incomplete UTF-16 surrogate pair at the end. If the buffer length is 0, this function does nothing.

Parameters

src Null-terminated source string in UTF-8 format.
dst Buffer to store converted UTF-16 string.
len Size, in bytes, of destination buffer.

PHYSFS_sint64 PHYSFS_writeBytes (PHYSFS_File * handle, const void * buffer, PHYSFS_uint64 len)

Write data to a PhysicsFS filehandle. The file must be opened for writing.

Please note that while (len) is an unsigned 64-bit integer, you are limited to 63 bits (9223372036854775807 bytes), so we can return a negative value on error. If length is greater than 0x7FFFFFFFFFFFFFFF, this function will immediately fail. For systems without a 64-bit datatype, you are limited to 31 bits (0x7FFFFFFF, or 2147483647 bytes). We trust most things won't need to do multiple gigabytes of i/o in one call anyhow, but why limit things?

Parameters

handle retval from PHYSFS_openWrite() or PHYSFS_openAppend().
buffer buffer of (len) bytes to write to (handle).
len number of bytes being written to (handle).

Returns

number of bytes written. This may be less than (len); in the case of an error, the system may try to write as many bytes as possible, so an incomplete write might occur. PHYSFS_getLastErrorCode() can shed light on the reason this might be < (len). -1 if complete failure.
