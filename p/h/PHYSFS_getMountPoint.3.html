int PHYSFS_caseFold(const PHYSFS_uint32 from, PHYSFS_uint32 * to)

"Fold" a Unicode codepoint to a lowercase equivalent. (This is for limited, hardcore use. If you don't immediately see a need for it, you can probably ignore this forever.)

This will convert a Unicode codepoint into its lowercase equivalent. Bogus codepoints and codepoints without a lowercase equivalent will be returned unconverted.

Note that you might get multiple codepoints in return! The German Eszett, for example, will fold down to two lowercase latin 's' codepoints. The theory is that if you fold two strings, one with an Eszett and one with "SS" down, they will match.

Warning

Anyone that is a student of Unicode knows about the "Turkish I" problem. This API does not handle it. Assume this one letter in all of Unicode will definitely fold sort of incorrectly. If you don't know what this is about, you can probably ignore this problem for most of the planet, but perfection is impossible.

Parameters

from The codepoint to fold.
to Buffer to store the folded codepoint values into. This should point to space for at least 3 PHYSFS_uint32 slots.

Returns

The number of codepoints the folding produced. Between 1 and 3.

int PHYSFS_deinit(void )

Deinitialize the PhysicsFS library. This closes any files opened via PhysicsFS, blanks the search/write paths, frees memory, and invalidates all of your file handles.

Note that this call can FAIL if there's a file open for writing that refuses to close (for example, the underlying operating system was buffering writes to network filesystem, and the fileserver has crashed, or a hard drive has failed, etc). It is usually best to close all write handles yourself before calling this function, so that you can gracefully handle a specific failure.

Once successfully deinitialized, PHYSFS_init() can be called again to restart the subsystem. All default API states are restored at this point, with the exception of any custom allocator you might have specified, which survives between initializations.

Returns

nonzero on success, zero on error. Specifics of the error can be gleaned from PHYSFS_getLastError(). If failure, state of PhysFS is undefined, and probably badly screwed up.

int PHYSFS_delete(const char * filename)

Delete a file or directory. (filename) is specified in platform-independent notation in relation to the write dir.

A directory must be empty before this call can delete it.

Deleting a symlink will remove the link, not what it points to, regardless of whether you "permitSymLinks" or not.

So if you've got the write dir set to "C:\mygame\writedir" and call PHYSFS_delete("downloads/maps/level1.map") then the file "C:\mygame\writedir\downloads\maps\level1.map" is removed from the physical filesystem, if it exists and the operating system permits the deletion.

Note that on Unix systems, deleting a file may be successful, but the actual file won't be removed until all processes that have an open filehandle to it (including your program) close their handles.

Chances are, the bits that make up the file still exist, they are just made available to be written over at a later point. Don't consider this a security method or anything. :)

Parameters

filename Filename to delete.

Returns

nonzero on success, zero on error. Use PHYSFS_getLastErrorCode() to obtain the specific error.

int PHYSFS_enumerate (const char * dir, PHYSFS_EnumerateCallback c, void * d)

الحصول على قائمة ملفات دليل مسار البحث، باستخدام دالة رد نداء معرفة من قبل التطبيق، مع الإبلاغ عن الأخطاء. داخلياً، تستدعي PHYSFS_enumerateFiles() هذه الوظيفة ثم تبني قائمة قبل العودة إلى التطبيق، لذا فإن الوظيفة متطابقة باستثناء كيفية تمثيل المعلومات للتطبيق.

على عكس PHYSFS_enumerateFiles()، لا تُرجع هذه الوظيفة مصفوفة. بدلاً من ذلك، تستدعي دالة يحددها التطبيق مرة واحدة لكل عنصر في مسار البحث:

static PHYSFS_EnumerateCallbackResult printDir(void *data, const char *origdir, const char *fname)
{
    printf(" * We've got [%s] in [%s].\n", fname, origdir);
    return PHYSFS_ENUM_OK;  // give me more data, please.
}
// ...
PHYSFS_enumerate("/some/path", printDir, NULL);

لا يُضمن أن العناصر المرسلة إلى دالة رد النداء ستكون بأي ترتيب معين على الإطلاق. لا يتم إجراء أي فرز على هذا المستوى، وإذا كنت بحاجة إلى ذلك، فمن المحتمل أن تستخدم PHYSFS_enumerateFiles() بدلاً من ذلك، والتي تضمن الفرز الأبجدي. هذا الشكل يبلغ عن كل ما يتم اكتشافه في كل أرشيف قبل الانتقال إلى التالي. حتى داخل أرشيف واحد، لا يمكننا ضمان ترتيب اكتشاف البيانات. أي فرز تجده في دوال رد النداء هذه هو مجرد حظ. لا تعتمد عليه. نظراً لأن هذا يجتاز قائمة الأرشيفات بأكملها، فقد تتلقى أسماء ملفات مكررة.

هذه الواجهة البرمجية (API) ودوال رد النداء نفسها قادرة على الإبلاغ عن الأخطاء. قبل هذه الواجهة البرمجية، كان على دوال رد النداء قبول كل عنصر تم استرداده، حتى لو كانت تبحث فقط عن شيء معين وترغب في التوقف بعد ذلك، أو واجهت خطأ جسيماً ولم تتمكن من تنبيه أي شخص. علاوة على ذلك، إذا كان لدى PhysicsFS نفسه مشكلة (خطأ في القرص أو ما شابه)، فلا يمكنه إبلاغ التطبيق المستدعي، بل سيتعين عليه فقط تخطي العناصر أو التوقف عن الاسترداد تماماً، ولن يعرف المتصل أنه فقد بعض البيانات على طول الطريق.

الآن يمكن للمتصل التأكد من أنه حصل على مجموعة بيانات كاملة، ودالة رد النداء الخاصة به تتحكم إذا كان يرغب في إيقاف الاسترداد مبكراً. انظر وثائق PHYSFS_EnumerateCallback للحصول على تفاصيل حول كيفية سلوك دالة رد النداء الخاصة بك.

المعلمات

dir دليل، بتدوين مستقل عن المنصة، لاسترداده.
c دالة رد نداء لإعلام عناصر مسار البحث.
d بيانات معرفة من قبل التطبيق تم تمريرها إلى دالة رد النداء. يمكن أن تكون NULL.

القيمة المرجعة

قيمة غير صفرية عند النجاح، وصفر عند الفشل. استخدم PHYSFS_getLastErrorCode() للحصول على الخطأ المحدد. إذا أعادت دالة رد النداء PHYSFS_ENUM_STOP للإيقاف المبكر، فسيتم اعتبار هذا نجاحاً. دوال رد النداء التي تعيد PHYSFS_ENUM_ERROR ستجعل هذه الوظيفة تعيد صفراً وتضبط رمز الخطأ إلى PHYSFS_ERR_APP_CALLBACK.

تحذير

في إصدارات PhysicsFS السابقة لـ 2.1، كانت هذه الوظيفة تعيد أكبر عدد ممكن من العناصر في مواجهة حالة فشل (نفاد الذاكرة، خطأ إدخال/إخراج القرص، إلخ). نظراً لأن هذا يعني أنه لا يمكن للتطبيقات التمييز بين النجاح الكامل والفشل الجزئي، ونظراً لأن الوظيفة يمكنها دائماً إعادة NULL للإبلاغ عن حالات الفشل الكارثية، فقد تغيرت سياسة هذه الوظيفة في PhysicsFS 2.1: ستعيد إما قائمة بنتائج كاملة أو ستعيد NULL لأي فشل من أي نوع، حتى نتمكن من ضمان أن الاسترداد قد اكتمل ولا توجد فجوات في نتائجه.

يتم استيفاء الدلائل المطابقة. أي، إذا كان "C:\mydir" موجوداً في مسار البحث ويحتوي على دليل "savegames" الذي يحتوي على "x.sav" و "y.sav" و "z.sav"، وإذا كان هناك أيضاً "C:\userdir" في مسار البحث الذي يحتوي على دليل فرعي "savegames" مع "w.sav"، فإن الكود التالي:

char **rc = PHYSFS_enumerateFiles("savegames");
char **i;
for (i = rc; *i != NULL; i++)
    printf(" * We've got [%s].\n", *i);
PHYSFS_freeList(rc);
* We've got [x.sav].
* We've got [y.sav].
* We've got [z.sav].
* We've got [w.sav]..fi
لا تتردد في فرز القائمة كيفما شئت. ومع ذلك، فإن البيانات المعادة لن تحتوي أبداً على تكرارات، وسيتم فرزها دائماً أبجدياً (الأصح: Unicode حساس لحالة الأحرف) من أجلك.
لا تنس استدعاء PHYSFS_freeList() بالقيمة المعادة من هذه الوظيفة عند الانتهاء منها.

على نظام Mac OS X، قد يبدو هكذا: "/Users/bob/Library/Application Support/My Program Name"

حدد اسم مؤسستك (إذا لم تكن مؤسسة حقيقية، فقد يكون اسمك أو نطاق تملكه مناسبًا) واسم تطبيقك. يجب أن تكون هذه أسماء مناسبة.

  • حاول استخدام نفس السلسلة (بما في ذلك حساسية الأحرف) لجميع تطبيقاتك التي تستخدم هذه الدالة.
  • استخدم دائمًا سلسلة فريدة لكل تطبيق، وتأكد من أنها لا تتغير أبدًا بمجرد تحديدها.
  • الأحرف Unicode قانونية، طالما أنها مشفرة بصيغة UTF-8، ولكن...
  • ...استخدم فقط الأحرف والأرقام والمسافات. تجنب أحرف مثل "Game Name 2: Bad Guy's Revenge!" ... "Game Name 2" يكفي.

المؤشر الذي تعيده هذه الدالة يبقى صالحًا حتى تقوم باستدعائها مرة أخرى أو تستدعي PHYSFS_deinit(). على الرغم من أنها ليست سريعة، يجب عليك استدعائها مرة واحدة عند البدء ونسخ السلسلة إذا كنت بحاجة إليها.

int PHYSFS_setRoot (const char * archive, const char * subdir)

Hace un subdirectorio de un archivo su directorio raíz. Esto te permite reducir los archivos accesibles en un específico archivo. Por ejemplo, si tienes x.zip con un archivo en y/z.txt montado en /a, si llamas PHYSFS_setRoot("x.zip", "/y"), entonces el llamado PHYSFS_openRead("/a/z.txt") será exitoso.

Puedes cambiar el directorio raíz de un archivo en cualquier momento, alterando así el árbol de archivos interpolado (dependiendo de donde se muevan las rutas, un archivo diferente puede proporcionar archivos diferentes). Si estableces el directorio raíz a NULL o a "/", el archivo será tratado como si no hubiera sido establecido previamente (como si el archivo hubiera sido montado normally).

Cambiar el directorio raíz solo afecta las operaciones futuras en rutas de archivos; un archivo que fue abierto desde una ruta que cambió debido a un llamado a setRoot no será afectado.

Establecer un nuevo directorio raíz no está limitado a archivos en la ruta de búsqueda; puedes establecer uno en el directorio de escritura también, lo cual puede ser útil si tienes archivos abiertos para escribir y no puedes cambiar el directorio de escritura ahora.

Es inofensivo establecer un subdirectorio que no exista como directorio raíz de un archivo; sin embargo, no se verán archivos en este caso. Si los directorios faltantes terminan siendo creados (una mkdir en el sistema de archivos físico, etc), esto se reflejará en el árbol interpolado.

Parámetros

archive directorio/archivo sobre el cual cambiar el directorio raíz.
subdir nuevo subdirectorio para hacer el directorio raíz de este archivo.

Retorno

no cero en éxito, cero en error. Usa PHYSFS_getLastErrorCode() para obtener el error específico.

NAME

PHYSFS_writeUBE16 — Convert and write an unsigned 16-bit bigendian value

SYNOPSIS

#include <physfs.h>

int PHYSFS_writeUBE16(PHYSFS_File *file, PHYSFS_uint16 val);

Detailed Description

Convert and write an unsigned 16-bit bigendian value. Convenience function. Convert an unsigned 16-bit value from the platform's native byte order to bigendian and write it to a file.

Parameters

file PhysicsFS file handle to which to write.
val Value to convert and write.

Returns

zero on failure, non-zero on success. On failure, you can find out what went wrong from PHYSFS_getLastErrorCode().
