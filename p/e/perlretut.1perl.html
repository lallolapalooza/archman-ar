الاسم

perlretut - دروس Perl حول التعبيرات النمطية

الوصف

توفر هذه الصفحة دروسًا أساسية حول فهم وإنشاء واستخدام التعبيرات النمطية في Perl. إنها بمثابة مكمل لصفحة المرجع الخاصة بالتعبيرات النمطية perlre. التعبيرات النمطية جزء لا يتجزأ من عوامل التشغيل "m//"، "s///"، "qr//" و "split"، وبالتالي تتداخل هذه الدروس أيضًا مع "عوامل تشغيل تشبه الاقتباس للتعبيرات النمطية" في perlop و "split" في perlfunc.

تشتهر Perl بتميزها في معالجة النصوص، وتعد التعبيرات النمطية أحد العوامل الكبيرة وراء هذه الشهرة. تظهر تعبيرات Perl النمطية كفاءة ومرونة غير معروفة في معظم لغات الكمبيوتر الأخرى. إتقان الأساسيات حتى للتعبيرات النمطية سيمكنك من معالجة النصوص بسهولة مدهشة.

ما هو التعبير النمطي؟ في أبسط صوره، التعبير النمطي هو قالب يستخدم لتحديد ما إذا كان السلسلة النصية تمتلك خصائص معينة. السلسلة النصية غالبًا ما تكون نصًا، مثل سطر، جملة، صفحة ويب، أو حتى كتاب كامل، ولكن ليس بالضرورة. يمكن أن تكون بيانات ثنائية، على سبيل المثال. يستخدم علماء الأحياء Perl بشكل متكرر للبحث عن أنماط في تسلسلات الحمض النووي الطويلة.

لنفترض أننا نريد تحديد ما إذا كان النص الموجود في المتغير $var يحتوي على تسلسل الأحرف "m u s h r o o m" (تمت إضافة مسافات للوضوح). يمكننا الكتابة في Perl:

$var =~ m/mushroom/

ستكون قيمة هذا التعبير صحيحة إذا كان $var يحتوي على تسلسل الأحرف هذا في أي مكان بداخله، وخاطئة بخلاف ذلك. الجزء المحاط بأحرف '/' يمثل الخاصية التي نبحث عنها. نستخدم مصطلح نمط له. عملية البحث لمعرفة ما إذا كان النمط يحدث في السلسلة النصية تسمى مطابقة، وعامل التشغيل "=~" جنبًا إلى جنب مع "m//" يخبران Perl بمحاولة مطابقة النمط مع السلسلة النصية. لاحظ أن النمط هو أيضًا سلسلة نصية، ولكنها نوع خاص جدًا منها، كما سنرى. الأنماط شائعة الاستخدام في هذه الأيام؛ الأمثلة هي الأنماط التي يتم إدخالها في محرك بحث للعثور على صفحات الويب والأنماط المستخدمة لسرد الملفات في دليل، على سبيل المثال، ""ls *.txt"" أو ""dir *.*"". في Perl، لا تُستخدم الأنماط الموصوفة بالتعبيرات النمطية للبحث في السلاسل النصية فحسب، بل أيضًا لاستخراج الأجزاء المطلوبة من السلاسل النصية، وللقيام بعمليات البحث والاستبدال.

تتمتع التعبيرات النمطية بسمعة غير مستحقة بأنها مجردة وصعبة الفهم. هذا ينبع ببساطة من أن الترميز المستخدم للتعبير عنها يميل إلى أن يكون موجزًا ​​وكثيفًا، وليس بسبب تعقيد جوهري. نوصي باستخدام معدّل التعبير النمطي "/x" (الموصوف أدناه) جنبًا إلى جنب مع الكثير من المسافات البيضاء لجعلها أقل كثافة، وأسهل في القراءة. تُبنى التعبيرات النمطية باستخدام مفاهيم بسيطة مثل الجمل الشرطية والحلقات، وهي ليست أكثر صعوبة في الفهم من جمل "if" والحلقات "while" المقابلة لها في لغة Perl نفسها.

تُسوي هذه الدروس منحنى التعلم عن طريق مناقشة مفاهيم التعبيرات النمطية، جنبًا إلى جنب مع الترميز الخاص بها، واحدًا تلو الآخر ومع العديد من الأمثلة. الجزء الأول من الدروس سيتدرج من أبسط عمليات البحث عن الكلمات إلى مفاهيم التعبيرات النمطية الأساسية. إذا أتقنت الجزء الأول، فستكون لديك جميع الأدوات اللازمة لحل حوالي 98٪ من احتياجاتك. الجزء الثاني من الدروس مخصص لأولئك الذين يشعرون بالراحة مع الأساسيات، ويتوقون لمزيد من أدوات القوة. يناقش عوامل تشغيل التعبيرات النمطية الأكثر تقدمًا ويقدم أحدث الابتكارات.

ملاحظة: لتوفير الوقت، غالبًا ما يتم اختصار "التعبير النمطي" باسم regexp أو regex. regexp هو اختصار أكثر طبيعية من regex، ولكنه أصعب في النطق. وثائق pod الخاصة بـ Perl مقسمة بالتساوي بين regexp و regex؛ في Perl، هناك أكثر من طريقة لاختصارها. سنستخدم regexp في هذه الدروس.

جديد في الإصدار 5.22، يطبق "use re 'strict'" قواعد أكثر صرامة من المعتاد عند تجميع أنماط التعبيرات النمطية. يمكنه العثور على أشياء، بينما هي قانونية، قد لا تكون ما كنت تقصده.

الجزء الأول: الأساسيات

مطابقة الكلمات البسيطة

أبسط تعبير نمطي هو ببساطة كلمة، أو بشكل عام، سلسلة من الأحرف. تعبير نمطي يتكون فقط من كلمة يطابق أي سلسلة نصية تحتوي على تلك الكلمة:

"Hello World" =~ /World/;  # يطابق

ماذا يعني بيان Perl هذا؟ "Hello World" هو سلسلة نصية بسيطة محاطة بعلامات اقتباس مزدوجة. "World" هو التعبير النمطي، و "//" الذي يحيط بـ "/World/" يخبر Perl بالبحث في السلسلة النصية عن تطابق. عامل التشغيل "=~" يربط السلسلة النصية بمطابقة التعبير النمطي وينتج قيمة صحيحة إذا تطابق التعبير النمطي، أو خاطئة إذا لم يتطابق. في حالتنا، "World" يطابق الكلمة الثانية في "Hello World"، لذا فإن التعبير صحيح. عبارات مثل هذه مفيدة في الجمل الشرطية:

if ("Hello World" =~ /World/) {
    print "It matches\n";
}
else {
    print "It doesn't match\n";
}

هناك اختلافات مفيدة على هذا الموضوع. يمكن عكس معنى المطابقة باستخدام عامل التشغيل "!~":

if ("Hello World" !~ /World/) {
    print "It doesn't match\n";
}
else {
    print "It matches\n";
}

يمكن استبدال السلسلة النصية الحرفية في التعبير النمطي بمتغير:

my $greeting = "World";
if ("Hello World" =~ /$greeting/) {
    print "It matches\n";
}
else {
    print "It doesn't match\n";
}

إذا كنت تطابق ضد المتغير الافتراضي الخاص $_، يمكن حذف جزء "$_ =~":

$_ = "Hello World";
if (/World/) {
    print "It matches\n";
}
else {
    print "It doesn't match\n";
}

وأخيرًا، يمكن تغيير الفواصل الافتراضية "//" للمطابقة إلى فواصل اعتباطية عن طريق وضع 'm' في المقدمة:

"Hello World" =~ m!World!;   # يطابق، مفصول بـ '!'
"Hello World" =~ m{World};   # يطابق، لاحظ الزوج '{}'
"/usr/bin/perl" =~ m"/perl"; # يطابق بعد '/usr/bin'،
                             # '/' يصبح حرفًا عاديًا

جميع "/World/"، "m!World!"، و "m{World}" تمثل نفس الشيء. عندما، على سبيل المثال، يتم استخدام علامة الاقتباس ('"') كفاصل، يصبح الخط المائل '/' حرفًا عاديًا ويمكن استخدامه في هذا التعبير النمطي دون مشكلة.

دعنا ننظر في كيف ستطابق تعبيرات نمطية مختلفة "Hello World":

"Hello World" =~ /world/;  # لا يطابق
"Hello World" =~ /o W/;    # يطابق
"Hello World" =~ /oW/;     # لا يطابق
"Hello World" =~ /World /; # لا يطابق

التعبير النمطي الأول "world" لا يطابق لأن التعبيرات النمطية حساسة لحالة الأحرف افتراضيًا. التعبير النمطي الثاني يطابق لأن السلسلة النصية الفرعية 'o W' تحدث في السلسلة النصية "Hello World". يتم التعامل مع حرف المسافة ' ' مثل أي حرف آخر في التعبير النمطي وهو ضروري للمطابقة في هذه الحالة. عدم وجود حرف مسافة هو سبب عدم مطابقة التعبير النمطي الثالث 'oW'. التعبير النمطي الرابع ""World """ لا يطابق لأنه توجد مسافة في نهاية التعبير النمطي، ولكن ليس في نهاية السلسلة النصية. الدرس هنا هو أن التعبيرات النمطية يجب أن تطابق جزءًا من السلسلة النصية بالضبط لكي يكون البيان صحيحًا.

إذا طابق تعبير نمطي في أكثر من مكان في السلسلة النصية، فإن Perl ستطابق دائمًا في أقرب نقطة ممكنة في السلسلة النصية:

"Hello World" =~ /o/;       # يطابق

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

'o' في 'Hello' "That hat is red" =~ /hat/; # يطابق 'hat' في 'That'

فيما يتعلق بمطابقة الأحرف، هناك بعض النقاط الإضافية التي تحتاج إلى معرفتها. أولاً وقبل كل شيء، لا يمكن استخدام جميع الأحرف "كما هي" في المطابقة. بعض الأحرف، تسمى الأحرف الخاصة، محجوزة بشكل عام للاستخدام في تدوين التعبيرات النمطية. الأحرف الخاصة هي

{}[]()^$.|*+?-#\

هذه القائمة ليست قاطعة كما قد تبدو (أو كما قد يُدعى في وثائق أخرى). على سبيل المثال، "#" هو حرف خاص فقط عندما يتم استخدام المعدل "/x" للتعبير النمطي (الموضح أدناه)، وكلا من "}" و "]" هما أحرف خاصة فقط عندما تقترنان بـ "{" أو "[" على التوالي؛ توجد تفاصيل دقيقة أخرى.

سيتم شرح أهمية كل من هذه في بقية البرنامج التعليمي، ولكن الآن، المهم هو معرفة أن الحرف الخاص يمكن مطابقته كما هو بوضع شرطة مائلة عكسية قبله. يُطلق على هذا "الهروب" أو "الاقتباس". بعض الأمثلة:

"2+2=4" =~ /2+2/;    # لا يطابق، + هو حرف خاص
"2+2=4" =~ /2\+2/;   # يطابق، \+ يعامل كـ + عادي
"The interval is [0,1)." =~ /[0,1)./     # خطأ في بناء الجملة!
"The interval is [0,1)." =~ /\[0,1\)\./  # يطابق
"#!/usr/bin/perl" =~ /#!\/usr\/bin\/perl/;  # يطابق

في التعبير النمطي الأخير، تم أيضاً وضع شرطة مائلة عكسية على الشرطة المائلة الأمامية '/'، لأنها تستخدم لتحديد التعبير النمطي. ومع ذلك، يمكن أن يؤدي هذا إلى متلازمة "عصا المصاصة المائلة" (LTS)، وغالبًا ما يكون من الأسهل القراءة تغيير المحددات.

"#!/usr/bin/perl" =~ m!#\!/usr/bin/perl!;  # أسهل للقراءة

حرف الشرطة المائلة العكسية '\' هو حرف خاص بحد ذاته ويحتاج إلى أن يتم وضع شرطة مائلة عكسية قبله:

'C:\WIN32' =~ /C:\\WIN/;   # يطابق

في الحالات التي لا يكون فيها للحرف الخاص معنى منطقي لما يعنيه عادةً، فإنه يفقد تلقائياً طبيعته كحرف خاص ويصبح حرفًا عاديًا يُطابق حرفيًا. على سبيل المثال، '}' هو حرف خاص فقط عندما يكون مطابقًا لحرف خاص '{'. بخلاف ذلك، يُعامل كـ RIGHT CURLY BRACKET حرفي. قد يؤدي هذا إلى نتائج غير متوقعة. يمكن لـ "use re 'strict'" اكتشاف بعض هذه الحالات.

بالإضافة إلى الأحرف الخاصة، هناك بعض أحرف ASCII التي لا تحتوي على مكافئات للأحرف القابلة للطباعة وبدلاً من ذلك يتم تمثيلها بواسطة تسلسلات الهروب. الأمثلة الشائعة هي "\t" للمسافة الأفقية (tab)، "\n" لسطر جديد، "\r" لعودة المؤشر، و "\a" للجرس (أو تنبيه). إذا كان يمكن اعتبار سلسلتك بمثابة تسلسل بايتات عشوائية، فقد يكون تسلسل الهروب الثماني، على سبيل المثال، "\033"، أو تسلسل الهروب الست عشري، على سبيل المثال، "\x1B" تمثيلاً طبيعيًا لبايتاتك. إليك بعض الأمثلة على تسلسلات الهروب:

"1000\t2000" =~ m(0\t2)   # يطابق
"1000\n2000" =~ /0\n20/   # يطابق
"1000\t2000" =~ /\000\t2/ # لا يطابق، "0" ليست مثل "\000"
"cat"   =~ /\o{143}\x61\x74/ # يطابق في ASCII، ولكن طريقة غريبة
                             # لكتابة cat

إذا كنت قد استخدمت Perl لفترة، فقد تبدو كل هذه المحادثات حول تسلسلات الهروب مألوفة. تُستخدم تسلسلات هروب مشابهة في السلاسل ذات علامات الاقتباس المزدوجة، وفي الواقع، تُعامل تعبيرات Perl النمطية في الغالب كسلاسل ذات علامات اقتباس مزدوجة. هذا يعني أنه يمكن استخدام المتغيرات في تعبيرات Perl النمطية أيضًا. تمامًا مثل السلاسل ذات علامات الاقتباس المزدوجة، سيتم استبدال قيم المتغيرات في التعبير النمطي قبل تقييم التعبير النمطي لأغراض المطابقة. لذا لدينا:

$foo = 'house';
'housecat' =~ /$foo/;      # يطابق
'cathouse' =~ /cat$foo/;   # يطابق
'housecat' =~ /${foo}cat/; # يطابق

حتى الآن، كل شيء على ما يرام. بالمعرفة المذكورة أعلاه، يمكنك بالفعل إجراء عمليات بحث بأي تعبير نمطي حرفي تقريبًا يمكنك تخيله. إليك محاكاة بسيطة جدًا لبرنامج grep الخاص بـ Unix:

% cat > simple_grep
#!/usr/bin/perl
$regexp = shift;
while (<>) {
    print if /$regexp/;
}
^D
% chmod +x simple_grep
% simple_grep abba /usr/dict/words
Babbage
cabbage
cabbages
sabbath
Sabbathize
Sabbathizes
sabbatical
scabbard
scabbards

هذا البرنامج سهل الفهم. "#!/usr/bin/perl" هي الطريقة القياسية لتشغيل برنامج perl من سطر الأوامر. "$regexp = shift;" يحفظ الوسيطة الأولى في سطر الأوامر كتعبير نمطي سيتم استخدامه، تاركاً بقية الوسائط في سطر الأوامر لتُعامل كملفات. "while (<>)" يمر عبر جميع الأسطر في جميع الملفات. لكل سطر، "print if /$regexp/;" يطبع السطر إذا طابق التعبير النمطي السطر. في هذا السطر، كل من "print" و "/$regexp/" يستخدم المتغير الافتراضي $_ ضمنياً.

مع جميع التعبيرات النمطية المذكورة أعلاه، إذا طابق التعبير النمطي في أي مكان في السلسلة، فقد اعتبر ذلك مطابقًا. ومع ذلك، في بعض الأحيان، نرغب في تحديد مكان يجب على التعبير النمطي محاولة المطابقة فيه داخل السلسلة. للقيام بذلك، سنستخدم مرتكزات الأحرف الخاصة '^' و '$'. الارتكاز '^' يعني المطابقة في بداية السلسلة، والارتكاز '$' يعني المطابقة في نهاية السلسلة، أو قبل سطر جديد في نهاية السلسلة. إليك كيفية استخدامها:

"housekeeper" =~ /keeper/;    # يطابق
"housekeeper" =~ /^keeper/;   # لا يطابق
"housekeeper" =~ /keeper$/;   # يطابق
"housekeeper\n" =~ /keeper$/; # يطابق

التعبير النمطي الثاني لا يطابق لأن '^' يقيد "keeper" ليطابق فقط في بداية السلسلة، ولكن "housekeeper" يحتوي على keeper يبدأ في المنتصف. التعبير النمطي الثالث يطابق، بما أن '$' يقيد "keeper" ليطابق فقط في نهاية السلسلة.

عند استخدام كل من '^' و '$' في نفس الوقت، يجب أن يطابق التعبير النمطي بداية السلسلة ونهايتها، أي، يطابق التعبير النمطي السلسلة بأكملها. انظر

"keeper" =~ /^keep$/;      # لا يطابق
"keeper" =~ /^keeper$/;    # يطابق
""       =~ /^$/;          # ^$ يطابق سلسلة فارغة

التعبير النمطي الأول لا يطابق لأن السلسلة تحتوي على أكثر من "keep". بما أن التعبير النمطي الثاني هو السلسلة بالضبط، فإنه يطابق. استخدام كل من '^' و '$' في تعبير نمطي يجبر السلسلة بأكملها على المطابقة، لذا فإنه يمنحك تحكمًا كاملاً في السلاسل التي تطابق وتلك التي لا تطابق. افترض أنك تبحث عن شخص يدعى bert، معزولاً في سلسلة:

"dogbert" =~ /bert/;   # يطابق، ولكن ليس ما تريده
"dilbert" =~ /^bert/;  # لا يطابق، ولكن ..
"bertram" =~ /^bert/;  # يطابق، لذا لا يزال غير كافٍ
"bertram" =~ /^bert$/; # لا يطابق، جيد
"dilbert" =~ /^bert$/; # لا يطابق، جيد
"bert"    =~ /^bert$/; # يطابق، مثالي

بالطبع، في حالة سلسلة حرفية، يمكن للمرء بسهولة استخدام مقارنة السلاسل "$string eq 'bert'" وسيكون ذلك أكثر كفاءة. يصبح التعبير النمطي "^...$" مفيدًا حقًا عندما نضيف أدوات التعبير النمطي الأكثر قوة أدناه.

استخدام فئات الأحرف

على الرغم من أنه يمكن القيام بالكثير بالفعل باستخدام تعبيرات Perl النمطية الحرفية المذكورة أعلاه، إلا أننا لم نكشط سوى سطح تكنولوجيا التعبيرات النمطية. في هذا القسم والأقسام التالية، سنقدم مفاهيم التعبير النمطي (والرموز الخاصة بالأحرف الخاصة المرتبطة بها) التي ستسمح للتعبير النمطي بتمثيل ليس فقط تسلسل أحرف واحد، بل مجموعة كاملة منها.

أحد هذه المفاهيم هو فئة الأحرف. تسمح فئة الأحرف بمجموعة من الأحرف الممكنة، بدلاً من حرف واحد، للمطابقة في نقطة معينة في التعبير النمطي. يمكنك تعريف فئات الأحرف المخصصة الخاصة بك. يتم تمييزها بأقواس "[...]"، مع مجموعة الأحرف التي يمكن مطابقتها بالداخل. إليك بعض الأمثلة:

/cat/;       # يطابق 'cat'
/[bcr]at/;   # يطابق 'bat', 'cat', أو 'rat'
/item[0123456789]/;  # يطابق 'item0' أو ... أو 'item9'
"abc" =~ /[cab]/;    # يطابق 'a'

في العبارة الأخيرة، على الرغم من أن 'c' هو الحرف الأول في الفئة، إلا أن 'a' يطابق لأن موضع الحرف الأول في السلسلة هو أبكر نقطة يمكن للتعبير النمطي المطابقة فيها.

/[yY][eE][sS]/;      # يطابق 'yes' بطريقة غير حساسة لحالة الأحرف
                     # 'yes', 'Yes', 'YES', إلخ.

يعرض هذا التعبير النمطي مهمة شائعة: إجراء مطابقة غير حساسة لحالة الأحرف. توفر Perl طريقة لتجنب كل هذه الأقواس عن طريق إضافة 'i' ببساطة إلى نهاية المطابقة. ثم يمكن إعادة كتابة "/[yY][eE][sS]/;" كـ "/yes/i;". الحرف 'i' يعني غير حساس لحالة الأحرف وهو مثال على معدّل لعملية المطابقة. سنتعرف على معدلات أخرى لاحقًا في البرنامج التعليمي.

رأينا في القسم أعلاه أنه كانت هناك أحرف عادية، والتي مثلت نفسها، وأحرف خاصة، والتي احتاجت إلى شرطة مائلة عكسية '\' لتمثيل نفسها. وينطبق الشيء نفسه في فئة الأحرف، ولكن مجموعات الأحرف العادية والخاصة داخل فئة الأحرف تختلف عن تلك الموجودة خارج فئة الأحرف. الأحرف الخاصة لفئة الأحرف هي "-]\^$" (ومحدد النمط، أياً كان). ']' خاص لأنه يشير إلى نهاية فئة الأحرف. '$' خاص لأنه يشير إلى متغير عددي. '\' خاص لأنه يستخدم في تسلسلات الهروب، تمامًا كما هو الحال أعلاه. إليك كيفية التعامل مع الأحرف الخاصة "]$\":

/[\]c]def/; # يطابق ']def' أو 'cdef'
$x = 'bcr';
/[$x]at/;   # يطابق 'bat', 'cat', أو 'rat'
/[\$x]at/;  # يطابق '$at' أو 'xat'
/[\\$x]at/; # يطابق '\at', 'bat', 'cat', أو 'rat'

The special character '-' acts as a range\n operator within character classes, so that a contiguous set of characters\n can be written as a range. With ranges, the unwieldy\n "[0123456789]" and\n "[abc...xyz]" become the svelte\n "[0-9]" and\n "[a-z]". Some examples are

If '-' is the first or last character in a\n character class, it is treated as an ordinary character;\n "[-ab]",\n "[ab-]" and\n "[a\\-b]" are all equivalent.

The special character '^' in the first\n position of a character class denotes a negated character class,\n which matches any character but those in the brackets. Both\n "[...]" and\n "[^...]" must match a character, or the\n match fails. Then

\n

Note in the last example, the end of the string is considered a\n word boundary.

You might wonder why '.' matches\n everything but "\\n" - why not every\n character? The reason is that often one is matching against lines and would\n like to ignore the newline characters. For instance, while the string\n "\\n" represents one line, we would like to\n think of it as empty. Then

\n
""   =~ /^$/;    # matches\n"\\n" =~ /^$/;    # matches, $ anchors before "\\n"\n""   =~ /./;      # doesn't match; it needs a char\n""   =~ /^.$/;    # doesn't match; it needs a char\n"\\n" =~ /^.$/;    # doesn't match; it needs a char other than "\\n"\n"a"  =~ /^.$/;    # matches\n"a\\n"  =~ /^.$/;  # matches, $ anchors before "\\n"
\n

This behavior is convenient, because we usually want to ignore\n newlines when we count and match characters in a line. Sometimes, however, we\n want to keep track of newlines. We might even want\n '^' and '$' to anchor at the\n beginning and end of lines within the string, rather than just the beginning\n and end of the string. Perl allows us to choose between ignoring and paying\n attention to newlines by using the "/s"\n and "/m" modifiers.\n "/s" and\n "/m" stand for single line and multi-line\n and they determine whether a string is to be treated as one continuous\n string, or as a set of lines. The two modifiers affect two aspects of how\n the regexp is interpreted: 1) how the '.' character\n class is defined, and 2) where the anchors '^' and\n '$' are able to match. Here are the four possible\n combinations:

\n
    \n
  • no modifiers: Default behavior. '.' matches any\n character except "\\n".\n '^' matches only at the beginning of the string\n and '$' matches only at the end or before a\n newline at the end.
    • \n
  • s modifier ("/s"): Treat string as a\n single long line. '.' matches any character, even\n "\\n". '^'\n matches only at the beginning of the string and\n '$' matches only at the end or before a newline at\n the end.
    • \n
  • m modifier ("/m"): Treat string as a set\n of multiple lines. '.' matches any character\n except "\\n". '^'\n and '$' are able to match at the start or end of\n any line within the string.
    • \n
  • both s and m modifiers ("/sm"): Treat\n string as a single long line, but detect multiple lines.\n '.' matches any character, even\n "\\n". '^' and\n '$', however, are able to match at the start or\n end of any line within the string.
    • \n
\n

في معظم الأحيان، تحدث كل هذه الحركة للأمام والتراجع بسرعة ويكون البحث سريعًا. ومع ذلك، هناك بعض التعبيرات العادية المرضية، التي ينمو وقت تنفيذها أسيًا مع حجم السلسلة. الهيكل النموذجي الذي ينفجر في وجهك هو من الشكل

/(a|b+)*/;

المشكلة هي المحددات غير المحددة المتداخلة. هناك العديد من الطرق المختلفة لتقسيم سلسلة بطول n بين '+' و '*': تكرار واحد مع "b+" بطول n، تكرارين مع الأول "b+" بطول k والثاني بطول n-k، m تكرارات تضيف أجزاؤها ما يصل إلى طول n، إلخ. في الواقع، هناك عدد أسي من الطرق لتقسيم سلسلة كدالة لطولها. قد يحالف التعبير العادي الحظ ويطابق مبكرًا في العملية، ولكن إذا لم يكن هناك تطابق، فإن Perl سيحاول كل احتمال قبل الاستسلام. لذا كن حذرًا مع التداخل بين '*''s و "{n,m}"'s و '+''s. يقدم الكتاب Mastering Regular Expressions لجيفري فريدل مناقشة رائعة لهذه القضايا وغيرها من قضايا الكفاءة.

محددات امتلاكية

قد يكون التراجع أثناء البحث الدؤوب عن تطابق مضيعة للوقت، خاصة عندما يكون من المؤكد فشل المطابقة. ضع في اعتبارك النمط البسيط

/^\w+\s+\w+$/; # كلمة، مسافات، كلمة

كلما تم تطبيق هذا على سلسلة لا تلبي توقعات النمط بشكل صحيح مثل "abc  " أو "abc  def "، سيتراجع محرك التعبير العادي، مرة واحدة تقريبًا لكل حرف في السلسلة. لكننا نعلم أنه لا توجد طريقة لتجنب أخذ جميع أحرف الكلمات الأولية لمطابقة التكرار الأول، وأن جميع المسافات يجب أن تؤكل من قبل الجزء الأوسط، وينطبق الشيء نفسه على الكلمة الثانية.

مع إدخال المحددات الامتلاكية في Perl 5.10، لدينا طريقة لإبلاغ محرك التعبير العادي بعدم التراجع، مع المحددات العادية الملحقة '+' بها. هذا يجعلها طماعة وكذلك بخيلة؛ بمجرد نجاحها، لن تتخلى عن أي شيء للسماح بحل آخر. لها المعاني التالية:

  • "a{n,m}+" تعني: المطابقة مرة واحدة على الأقل "n"، وليس أكثر من "m"، قدر الإمكان، ولا تتخلى عن أي شيء. "a?+" اختصار لـ "a{0,1}+"
  • "a{n,}+" تعني: المطابقة مرة واحدة على الأقل "n"، ولكن قدر الإمكان، ولا تتخلى عن أي شيء. "a++" اختصار لـ "a{1,}+".
  • "a{,n}+" تعني: المطابقة قدر الإمكان حتى "n" كحد أقصى، ولا تتخلى عن أي شيء. "a*+" اختصار لـ "a{0,}+".
  • "a{n}+" تعني: المطابقة بالضبط "n" مرات. إنها موجودة فقط للاتساق الرمزي.

تمثل هذه المحددات الامتلاكية حالة خاصة لمفهوم أكثر عمومية، وهو التعبيير الفرعي المستقل، انظر أدناه.

كمثال حيث يكون المحدد الامتلاكي مناسبًا، نأخذ في الاعتبار مطابقة سلسلة مقتبسة، كما تظهر في العديد من لغات البرمجة. يتم استخدام الشرطة المائلة للخلف كحرف هروب يشير إلى أن الحرف التالي يجب أن يؤخذ حرفيًا، كحرف آخر للسلسلة. لذلك، بعد علامة الاقتباس الافتتاحية، نتوقع تسلسلًا (ربما فارغًا) من البدائل: إما حرف ما باستثناء علامة اقتباس أو شرطة مائلة للخلف غير مهربة أو حرف مهرب.

/"(?:[^"\\]++|\\.)*+"/;

بناء تعبير عادي

في هذه المرحلة، لدينا جميع المفاهيم الأساسية للتعبير العادي مغطاة، لذا دعنا نقدم مثالًا أكثر تعقيدًا لتعبير عادي. سنقوم ببناء تعبير عادي يطابق الأرقام.

المهمة الأولى في بناء تعبير عادي هي تحديد ما نريد مطابقته وما نريد استبعاده. في حالتنا، نريد مطابقة الأعداد الصحيحة والأعداد العشرية، ونريد رفض أي سلسلة ليست رقمًا.

المهمة التالية هي تقسيم المشكلة إلى مشاكل أصغر يمكن تحويلها بسهولة إلى تعبير عادي.

أبسط حالة هي الأعداد الصحيحة. تتكون هذه من تسلسل من الأرقام، مع إشارة اختيارية في المقدمة. يمكننا تمثيل الأرقام بـ "\d+" ويمكن مطابقة الإشارة بـ "[+-]". وبالتالي فإن تعبير الأعداد الصحيحة هو

/[+-]?\d+/;  # يطابق الأعداد الصحيحة

العدد العشري لديه احتمالية وجود إشارة، جزء صحيح، فاصلة عشرية، جزء كسري، وأس. واحد أو أكثر من هذه الأجزاء اختياري، لذا نحتاج إلى فحص الاحتمالات المختلفة. تشمل الأعداد العشرية ذات الشكل الصحيح 123.، 0.345، .34، -1e6، و 25.4E-72. كما هو الحال مع الأعداد الصحيحة، فإن الإشارة في المقدمة اختيارية تمامًا ويمكن مطابقتها بـ "[+-]?". يمكننا أن نرى أنه إذا لم يكن هناك أس، فيجب أن تحتوي الأعداد العشرية على فاصلة عشرية، وإلا فهي أعداد صحيحة. قد نكون نميل إلى نمذجة هذه بـ "\d*\.\d*"، ولكن هذا سيطابق أيضًا فاصلة عشرية واحدة، وهي ليست رقمًا. لذا فإن الحالات الثلاث للأعداد العشرية بدون أس هي

/[+-]?\d+\./;  # 1.، 321.، إلخ.
/[+-]?\.\d+/;  # .1، .234، إلخ.
/[+-]?\d+\.\d+/;  # 1.0، 30.56، إلخ.

يمكن دمج هذه في تعبير عادي واحد مع تبديل ثلاثي:

/[+-]?(\d+\.\d+|\d+\.|\.\d+)/;  # عدد عشري، بدون أس

في هذا التبديل، من المهم وضع '\d+\.\d+' قبل '\d+\.'. إذا كان '\d+\.' هو الأول، فسيقوم التعبير العادي بمطابقته بسعادة وتجاهل الجزء الكسري من الرقم.

الآن دعنا نفكر في الأعداد العشرية مع الأسس. الملاحظة الرئيسية هنا هي أن كلاً من الأعداد الصحيحة والأرقام ذات النقاط العشرية هي كلها

= "\QThat !^*&%~& cat!"; $x =~ /\Q!^*&%~&\E/; # التحقق من لغة غير لائقة

لا تحمي '$' أو '@'، لذلك يمكن استبدال المتغيرات.

"\Q"، "\L"، "\l"، "\U"، "\u" و "\E" هي في الواقع جزء من بناء جملة الاقتباس المزدوج، وليست جزءًا من بناء جملة التعبير العادي بحد ذاته. ستعمل إذا ظهرت في تعبير عادي مضمن مباشرة في برنامج، ولكن ليس عند تضمينها في سلسلة نصية يتم تفسيرها في نمط.

يمكن لتعبيرات Perl العادية التعامل مع أكثر من مجرد مجموعة الأحرف ASCII القياسية. يدعم Perl Unicode، وهو معيار لتمثيل أبجديات جميع اللغات المكتوبة تقريبًا في العالم، ومجموعة كبيرة من الرموز. سلاسل Perl النصية هي سلاسل Unicode، لذلك يمكن أن تحتوي على أحرف بقيمة (نقطة ترميز أو رقم حرف) أعلى من 255.

ماذا يعني هذا للتعبيرات العادية؟ حسنًا، لا يحتاج مستخدمو التعبيرات العادية إلى معرفة الكثير عن التمثيل الداخلي للسلاسل النصية في Perl. ولكنهم يحتاجون إلى معرفة 1) كيفية تمثيل أحرف Unicode في تعبير عادي و 2) أن عملية المطابقة ستعامل السلسلة المراد البحث فيها كمتوالية من الأحرف، وليس البايتات. الإجابة على 1) هي أن أحرف Unicode الأكبر من chr(255) يتم تمثيلها باستخدام تدوين "\x{hex}"، لأن "\x"XY (محددة برقمين ست عشريين بدون أقواس معقوفة) لا تتجاوز 255. (بدءًا من Perl 5.14، إذا كنت من محبي الأرقام الثمانية، يمكنك أيضًا استخدام "\o{oct}".)

/\x{263a}/;   # مطابقة وجه ابتسامة Unicode :)
/\x{ 263a }/; # نفس الشيء

ملاحظة: في Perl 5.6.0، كان يجب عليك كتابة "use utf8" لاستخدام أي ميزات Unicode. لم يعد هذا هو الحال: بالنسبة لجميع معالجة Unicode تقريبًا، لا يلزم وجود التوجيه الصريح "utf8". (الحالة الوحيدة التي يهم فيها هي إذا كان نص Perl النصي بتنسيق Unicode ومشفرًا بتنسيق UTF-8، فعندئذ يلزم وجود "use utf8" صريح.)

يعد اكتشاف التسلسل الست عشري لحرف Unicode الذي تريده أو فك تشفير تعبير Unicode الست عشري لشخص آخر أمرًا ممتعًا مثل البرمجة بلغة الآلة. لذا فإن طريقة أخرى لتحديد أحرف Unicode هي استخدام تسلسل الهروب للحرف المسمى "\N{name}". name هو اسم لحرف Unicode، كما هو محدد في معيار Unicode. على سبيل المثال، إذا أردنا تمثيل أو مطابقة العلامة الفلكية للكوكب عطارد، يمكننا استخدام

$x = "abc\N{MERCURY}def";
$x =~ /\N{MERCURY}/;   # يطابق
$x =~ /\N{ MERCURY }/; # يطابق أيضًا

يمكن أيضًا استخدام أسماء "قصيرة":

print "\N{GREEK SMALL LETTER SIGMA} is called sigma.\n";
print "\N{greek:Sigma} is an upper-case sigma.\n";

يمكنك أيضًا تقييد الأسماء بأبجدية معينة عن طريق تحديد توجيه charnames:

use charnames qw(greek);
print "\N{sigma} is Greek sigma\n";

يتوفر فهرس لأسماء الأحرف عبر الإنترنت من اتحاد Unicode، https://www.unicode.org/charts/charindex.html؛ مواد توضيحية مع روابط لموارد أخرى على https://www.unicode.org/standard/where.

بدءًا من Perl v5.32، يتوفر بديل لـ "\N{...}" للأسماء الكاملة، وهو كتابة

/\p{Name=greek small letter sigma}/

حالة اسم الحرف ليست ذات صلة عند استخدامها في "\p{}"، وكذلك معظم المسافات وعلامات الشرطة السفلية والواصلات. (تسبب بعض الأحرف الشاذة مشاكل في تجاهل كل هذه دائمًا. التفاصيل (التي يمكنك البحث عنها عندما تصبح أكثر كفاءة، وإذا لزم الأمر) موجودة في https://www.unicode.org/reports/tr44/tr44-24.html#UAX44-LM2).

الإجابة على المتطلب 2) هي أن التعبير العادي (في الغالب) يستخدم أحرف Unicode. "في الغالب" هو لأسباب تتعلق بالتوافق مع الإصدارات السابقة، ولكن بدءًا من Perl 5.14، سيقوم أي تعبير عادي تم تجميعه في نطاق "use feature 'unicode_strings'" (والذي يتم تشغيله تلقائيًا ضمن نطاق "use v5.12" أو أعلى) بتحويل "في الغالب" إلى "دائمًا". إذا كنت ترغب في التعامل مع Unicode بشكل صحيح، يجب عليك التأكد من تشغيل 'unicode_strings'. داخليًا، يتم ترميز ذلك إلى بايتات باستخدام UTF-8 أو ترميز 8 بت أصلي، اعتمادًا على تاريخ السلسلة، ولكنه من الناحية المفاهيمية متوالية من الأحرف، وليس البايتات. انظر perlunitut للحصول على برنامج تعليمي حول ذلك.

دعنا الآن نناقش فئات أحرف Unicode، والتي يطلق عليها عادةً "خصائص الأحرف". يتم تمثيل هذه بواسطة تسلسل الهروب "\p{name}". النفي لهذا هو "\P{name}". على سبيل المثال، لمطابقة الأحرف الصغيرة والكبيرة،

$x = "BOB";
$x =~ /^\p{IsUpper}/;   # يطابق، فئة الأحرف الكبيرة
$x =~ /^\P{IsUpper}/;   # لا يطابق، فئة الأحرف بدون الأحرف الكبيرة
$x =~ /^\p{IsLower}/;   # لا يطابق، فئة الأحرف الصغيرة
$x =~ /^\P{IsLower}/;   # يطابق، فئة الأحرف بدون الأحرف الصغيرة

(اختياري " Is ")

هناك العديد والعديد من خصائص أحرف Unicode. للحصول على القائمة الكاملة، راجع perluniprops. معظمها له أسماء مرادفة أقصر، مدرجة هناك أيضًا. بعض الأسماء المرادفة تتكون من حرف واحد. بالنسبة لهذه، يمكنك إسقاط الأقواس. على سبيل المثال، "\pM" هو نفس الشيء مثل "\p{Mark}"، مما يعني أشياء مثل علامات التشكيل.

خصائص Unicode "\p{Script}" و "\p{Script_Extensions}" تُستخدم لتصنيف كل حرف Unicode في النص الذي يُكتب به. على سبيل المثال، الإنجليزية والفرنسية والعديد من اللغات الأوروبية الأخرى تُكتب بنص لاتيني. ولكن هناك أيضًا النص اليوناني، والنص التايلاندي، والنص الكاتاكانا، إلخ. ("Script" هو شكل أقدم وأقل تقدمًا من "Script_Extensions"، ويتم الاحتفاظ به فقط للتوافق مع الإصدارات السابقة.) يمكنك اختبار ما إذا كان الحرف ضمن نص معين باستخدام، على سبيل المثال "\p{Latin}"، "\p{Greek}"، أو "\p{Katakana}". لاختبار ما إذا كان ليس ضمن النص البالينيزي، ستستخدم "\P{Balinese}". (تستخدم كل هذه "Script_Extensions" داخليًا، لأن هذا يعطي نتائج أفضل.)

ما وصفناه حتى الآن هو الشكل المفرد لفئات الأحرف "\p{...}". هناك أيضًا شكل مركب قد تصادفه. تبدو هذه مثل "\p{name=value}" أو "\p{name:value}" (يمكن استخدام علامة يساوي والنقطتين بشكل قابل للتبديل). هذه أكثر عمومية من الشكل المفرد، وفي الواقع فإن معظم الأشكال المفردة هي مجرد اختصارات محددة من Perl للأشكال المركبة الشائعة. على سبيل المثال، يمكن كتابة أمثلة النص في الفقرة السابقة بشكل مكافئ على أنها "\p{Script_Extensions=Latin}"، "\p{Script_Extensions:Greek}"، "\p{script_extensions=katakana}"، و "\P{script_extensions=balinese}" (حالة الأحرف غير ذات صلة بين أقواس "{}"). قد لا تضطر أبدًا إلى استخدام الأشكال المركبة، ولكنها ضرورية في بعض الأحيان، ويمكن أن يؤدي استخدامها إلى جعل شفرتك أسهل في الفهم.

"\X" هو اختصار لفئة أحرف تتكون من مجموعة حروف رسومية ممتدة لـ Unicode. يمثل هذا "حرفًا منطقيًا": ما يبدو كحرف واحد، ولكنه قد يكون ممثلاً داخليًا بأكثر من واحد. على سبيل المثال، باستخدام أسماء Unicode الكاملة، على سبيل المثال، "A + COMBINING RING" هي مجموعة رسومية تحتوي على الحرف الأساسي "A" والحرف المدمج "COMBINING RING، والتي تُترجم باللغة الدنماركية إلى "A" مع دائرة فوقها، كما في كلمة Ångstrom.

للحصول على المعلومات الكاملة والأحدث حول Unicode، راجع أحدث معيار Unicode، أو موقع اتحاد Unicode الإلكتروني https://www.unicode.org

كما لو أن كل هذه الفئات لم تكن كافية، فإن Perl يحدد أيضًا فئات الأحرف من نمط POSIX. هذه لها الشكل "[:name:]"، مع name اسم فئة POSIX. فئات POSIX هي "alpha"، "alnum"، "ascii"، "blank"، "cntrl"، "digit"، "graph"، "lower"، "print"، "punct"، "space"، "upper"، "xdigit"، و "word" (امتداد Perl لمطابقة "\w"). يقتصر المعدل "/a" على هذه المطابقة فقط في نطاق ASCII؛ بخلاف ذلك، يمكن أن تطابق نفس ما تطابقه فئات Unicode المقابلة لها في Perl: "[:upper:]" هو نفس "\p{IsUpper}"، إلخ. (هناك بعض الاستثناءات والمشكلات مع هذا؛ راجع perlrecharclass للحصول على مناقشة كاملة.) "[:digit:]"، "[:word:]"، و "[:space:]" تتوافق مع فئات الأحرف المألوفة "\d"، "\w"، و "\s". لنفي فئة POSIX، ضع '^' قبل الاسم، بحيث، على سبيل المثال، "&\b" تنظر إلى الأمام والخلف، لترى ما إذا كانت الأحرف على أي من الجانبين تختلف في "طبيعتها الكلمية".

عبارات البحث الأمامي والخلفي هي تعميم لمفهوم المرساة. البحث الأمامي والخلفي هما عبارتان ذواتا عرض صفري تسمحان لنا بتحديد الأحرف التي نريد اختبارها. تتم الإشارة إلى عبارة البحث الأمامي بالرمز "(?=regexp)" أو (بدءًا من 5.32، تجريبيًا في 5.28) "(*pla:regexp)" أو "(*positive_lookahead:regexp)"؛ وتتم الإشارة إلى عبارة البحث الخلفي بالرمز "(?<=fixed-regexp)" أو (بدءًا من 5.32، تجريبيًا في 5.28) "(*plb:fixed-regexp)" أو "(*positive_lookbehind:fixed-regexp)". بعض الأمثلة هي

$x = "I catch the housecat 'Tom-cat' with catnip";
$x =~ /cat(*pla:\s)/;   # يطابق 'cat' في 'housecat'
@catwords = ($x =~ /(?<=\s)cat\w+/g);  # يطابق،
                                       # $catwords[0] = 'catch'
                                       # $catwords[1] = 'catnip'
$x =~ /\bcat\b/;  # يطابق 'cat' في 'Tom-cat'
$x =~ /(?<=\s)cat(?=\s)/; # لا يطابق؛ لا يوجد 'cat' معزول في
                          # وسط $x

لاحظ أن الأقواس في هذه الحالات هي أقواس غير استيعابية، نظرًا لأنها عبارات ذات عرض صفري. وبالتالي في التعبير العادي الثاني، السلاسل النصية المستوعبة هي تلك الخاصة بالتعبير العادي بأكمله. يمكن للبحث الأمامي مطابقة تعبيرات عادية اعتباطية، ولكن البحث الخلفي قبل 5.30 "(?<=fixed-regexp)" يعمل فقط مع التعبيرات العادية ذات العرض الثابت، أي، طول بعدد ثابت من الأحرف. وبالتالي "(?<=(ab|bc))" صحيح، ولكن "(?<=(ab)*)" قبل 5.30 ليس كذلك.

تتم الإشارة إلى الإصدارات المنفية لعبارات البحث الأمامي والخلفي بالرمز "(?!regexp)" و "(?<!fixed-regexp)" على التوالي. أو، بدءًا من 5.32 (تجريبيًا في 5.28)، "(*nla:regexp)"، "(*negative_lookahead:regexp)"، "(*nlb:regexp)"، أو "(*negative_lookbehind:regexp)". يتم تقييمها على أنها صحيحة إذا كانت التعبيرات العادية لا تطابق:

$x = "foobar";
$x =~ /foo(?!bar)/;  # لا يطابق، 'bar' يتبع 'foo'
$x =~ /foo(?!baz)/;  # يطابق، 'baz' لا يتبع 'foo'
$x =~ /(?<!\s)foo/;  # يطابق، لا يوجد \s قبل 'foo'

هنا مثال حيث يتم تقسيم سلسلة نصية تحتوي على كلمات مفصولة بمسافات، وأرقام، وشرطات فردية إلى مكوناتها. استخدام "/\s+/" وحده لن يعمل، لأن المسافات غير مطلوبة بين الشرطات، أو كلمة، أو شرطة. يتم إنشاء أماكن إضافية للتقسيم عن طريق البحث الأمامي والخلفي:

$str = "one two - --6-8";
@toks = split / \s+              # سلسلة من المسافات
              | (?<=\S) (?=-)    # أي حرف غير مسافة يتبعه '-'
              | (?<=-)  (?=\S)   # '-' يتبعه أي حرف غير مسافة
              /x, $str;          # @toks = qw(one two - - - 6 - 8)

استخدام التعابير الفرعية المستقلة لمنع التراجع

التعابير الفرعية المستقلة (أو التعابير الذرية) هي تعابير عادية، في سياق تعبير عادي أكبر، تعمل بشكل مستقل عن التعبير العادي الأكبر. أي أنها تستهلك من السلسلة النصية قدر ما ترغب فيه دون اعتبار لقدرة التعبير العادي الأكبر على المطابقة. يتم تمثيل التعابير الفرعية المستقلة بالرمز "(?>regexp)" أو (بدءًا من 5.32، تجريبيًا في 5.28) "(*atomic:regexp)". يمكننا توضيح سلوكها بالنظر أولاً إلى تعبير عادي عادي:

$x = "ab";
$x =~ /a*ab/;  # يطابق

هذا يطابق بوضوح، ولكن أثناء المطابقة، استوعبت العبارة الفرعية "a*" حرف 'a' أولاً. القيام بذلك، ومع ذلك، لن يسمح للتعبير العادي بأكمله بالمطابقة، لذلك بعد التراجع، "a*" أعادت حرف 'a' وطابقت السلسلة الفارغة. هنا، ما طابقته "a*" كان معتمدًا على ما طابقه باقي التعبير العادي.

قارن ذلك بتعبير فرعي مستقل:

$x =~ /(?>a*)ab/;  # لا يطابق!

العبارة الفرعية المستقلة "(?>a*)" لا تهتم بباقي التعبير العادي، لذلك ترى حرف 'a' وتستوعبه. ثم باقي التعبير العادي "ab" لا يمكنه المطابقة. نظرًا لأن "(?>a*)" مستقل، فلا يوجد تراجع ولا تتخلى العبارة الفرعية المستقلة عن حرف 'a'. وبالتالي يفشل تطابق التعبير العادي ككل. يحدث سلوك مماثل مع التعبيرات العادية المستقلة تمامًا:

$x = "ab";
$x =~ /a*/g;   # يطابق، يستهلك حرف 'a'
$x =~ /\Gab/g; # لا يطابق، لا يوجد 'a' متاح

هنا و "\G" تنشئان تبادلًا "فريق عمل" للسلسلة النصية من تعبير عادي إلى آخر. التعبيرات العادية التي تحتوي على عبارة فرعية مستقلة تشبه هذا كثيرًا، مع تبادل السلسلة النصية إلى العبارة الفرعية المستقلة، وتبادل السلسلة النصية مرة أخرى إلى التعبير العادي المحيط.

يمكن أن تكون قدرة العبارة الفرعية المستقلة على منع التراجع مفيدة جدًا. لنفترض أننا نريد مطابقة سلسلة غير فارغة محاطة بأقواس حتى عمق مستويين. ثم يطابق التعبير العادي التالي:

$x = "abc(de(fg)h";  # أقواس غير متوازنة
$x =~ /\( ( [ ^ () ]+ | \( [ ^ () ]* \) )+ \)/xx;

يطابق التعبير العادي قوسًا مفتوحًا، ونسخة واحدة أو أكثر من بديل، وقوسًا مغلقًا. البديل ثنائي الاتجاه، مع البديل الأول "[^()]+" يطابق سلسلة نصية لا تحتوي على أقواس، والبديل الثاني "\([^()]*\)" يطابق سلسلة نصية محددة بأقواس. المشكلة مع هذا التعبير العادي هي أنه مرض: لديه كميات محددة متداخلة من الشكل "(a+|b)+". ناقشنا في الجزء الأول كيف يمكن للكميات المتداخلة مثل هذه أن تستغرق وقتًا طويلاً بشكل أسي للتنفيذ إذا لم يكن هناك تطابق ممكن. لمنع الانفجار الأسي، نحتاج إلى منع التراجع غير المجدي في مرحلة ما. يمكن القيام بذلك عن طريق تغليف الكمية الداخلية كعبارة فرعية مستقلة:

$x =~ /\( ( (?> [ ^ () ]+ ) | \([ ^ () ]* \) )+ \)/xx;

هنا، "(?>[^()]+)" يكسر انحلال تقسيم السلسلة النصية عن طريق استيعاب أكبر قدر ممكن من السلسلة النصية والاحتفاظ بها. ثم تفشل المطابقات بشكل أسرع بكثير.

عبارات شرطية

العبارة الشرطية هي شكل من أشكال عبارة إذا-ثم-غير ذلك تسمح لنا باختيار الأنماط التي سيتم مطابقتها، بناءً على شرط ما. هناك نوعان من العبارات الشرطية: "(?(condition)yes-regexp)" و "(?(condition)yes-regexp|no-regexp)". "(?(condition)yes-regexp)" يشبه عبارة 'if () {}' في Perl. إذا كان condition صحيحًا، فسيتم مطابقة yes-regexp. إذا كان condition خاطئًا، فسيتم تخطي yes-regexp وسينتقل Perl إلى عنصر التعبير العادي التالي. الشكل الثاني يشبه عبارة 'if () {} else {}' في Perl. إذا كان condition صحيحًا، فسيتم مطابقة yes-regexp، وإلا فسيتم مطابقة no-regexp.

يمكن أن يأخذ condition عدة أشكال. الشكل الأول هو مجرد عدد صحيح بين قوسين "(integer)". يكون صحيحًا إذا كان الاستشهاد الخلفي المقابل "\integer" قد طابق سابقًا في التعبير العادي. يمكن القيام بنفس الشيء مع اسم مرتبط بمجموعة التقاط، مكتوبًا كـ "(<name>)" أو "('name')". الشكل الثاني هو عبارة صفرية العرض مجردة "(?...)"، إما بحث أمامي، أو بحث خلفي، أو عبارة كود (نوقشت في القسم التالي). توفر المجموعات الثلاثة من الأشكال اختبارات تُرجع صحيحًا إذا تم تنفيذ التعبير ضمن تكرار ("(R)") أو يتم استدعاؤه من بعض مجموعات الالتقاط، ويشار إليه إما بالرقم ("(R1)"، "(R2)"،...) أو بالاسم ("(R&name)").

يسمح شكل العدد الصحيح أو الاسم لـ "condition" لنا باختيار، بمرونة أكبر، ما يجب مطابقته بناءً على ما طابق سابقًا في التعبير العادي. هذا يبحث عن كلمات بالشكل "$x$x" أو "$x$y$y$x":

% simple_grep '^(\w+)(\w+)?(?(2)\g2\g1|\g1)$' /usr/dict/words
beriberi
coco
couscous
deed
...
toot
toto
tutu

يسمح البحث الخلفي "condition"، جنبًا إلى جنب مع الاستشهادات الخلفية، لجزء سابق من المطابقة بالتأثير على جزء لاحق من المطابقة. على سبيل المثال،

/[ATGC]+(?(?<=AA)G|C)$/;

يطابق تسلسل DNA بحيث ينتهي إما بـ "AAG"، أو مزيج آخر من أزواج القواعد و 'C'. لاحظ أن الشكل هو "(?(?<=AA)G|C)" وليس "(?((?<=AA))G|C)"؛ بالنسبة لعبارات البحث الأمامي، أو البحث الخلفي، أو عبارات الكود، لا يلزم وجود الأقواس حول الشرط.

أنماط متكررة

This feature (introduced in Perl 5.10) significantly extends the power of Perl's pattern matching. By referring to some other capture group anywhere in the pattern with the construct "(?group-ref)", the pattern within the referenced group is used as an independent subpattern in place of the group reference itself. Because the group reference may be contained within the group it refers to, it is now possible to apply pattern matching to tasks that hitherto required a recursive parser.

To illustrate this feature, we'll design a pattern that matches if a string contains a palindrome. (This is a word or a sentence that, while ignoring spaces, interpunctuation and case, reads the same backwards as forwards. We begin by observing that the empty string or a string containing just one word character is a palindrome. Otherwise it must have a word character up front and the same at its end, with another palindrome in between.

/(?: (\w) (?...Here be a palindrome...) \g{ -1 } | \w? )/x

Adding "\W*" at either end to eliminate what is to be ignored, we already have the full pattern:

my $pp = qr/^(\W* (?: (\w) (?1) \g{-1} | \w? ) \W*)$/ix;
for $s ( "saippuakauppias", "A man, a plan, a canal: Panama!" ){
    print "'$s' is a palindrome\n" if $s =~ /$pp/;
}

In "(?...)" both absolute and relative backreferences may be used. The entire pattern can be reinserted with "(?R)" or "(?0)". If you prefer to name your groups, you can use "(?&name)" to recurse into that group.

القليل من السحر: تنفيذ كود Perl في تعبير عادي

Normally, regexps are a part of Perl expressions. Code evaluation expressions turn that around by allowing arbitrary Perl code to be a part of a regexp. A code evaluation expression is denoted "(?{code})", with code a string of Perl statements.

Code expressions are zero-width assertions, and the value they return depends on their environment. There are two possibilities: either the code expression is used as a conditional in a conditional expression "(?(condition)...)", or it is not. If the code expression is a conditional, the code is evaluated and the result (i.e., the result of the last statement) is used to determine truth or falsehood. If the code expression is not used as a conditional, the assertion always evaluates true and the result is put into the special variable $^R. The variable $^R can then be used in code expressions later in the regexp. Here are some silly examples:

$x = "abcdef";
$x =~ /abc(?{print "Hi Mom!";})def/; # matches,
                                     # prints 'Hi Mom!'
$x =~ /aaa(?{print "Hi Mom!";})def/; # doesn't match,
                                     # no 'Hi Mom!'

Pay careful attention to the next example:

$x =~ /abc(?{print "Hi Mom!";})ddd/; # doesn't match,
                                     # no 'Hi Mom!'
                                     # but why not?

At first glance, you'd think that it shouldn't print, because obviously the "ddd" isn't going to match the target string. But look at this example:

$x =~ /abc(?{print "Hi Mom!";})[dD]dd/; # doesn't match,
                                        # but _does_ print

Hmm. What happened here? If you've been following along, you know that the above pattern should be effectively (almost) the same as the last one; enclosing the 'd' in a character class isn't going to change what it matches. So why does the first not print while the second one does?

The answer lies in the optimizations the regexp engine makes. In the first case, all the engine sees are plain old characters (aside from the "?{}" construct). It's smart enough to realize that the string 'ddd' doesn't occur in our target string before actually running the pattern through. But in the second case, we've tricked it into thinking that our pattern is more complicated. It takes a look, sees our character class, and decides that it will have to actually run the pattern to determine whether or not it matches, and in the process of running it hits the print statement before it discovers that we don't have a match.

To take a closer look at how the engine does optimizations, see the section "Pragmas and debugging" below.

More fun with "?{}":

$x =~ /(?{print "Hi Mom!";})/;         # matches,
                                       # prints 'Hi Mom!'
$x =~ /(?{$c = 1;})(?{print "$c";})/;  # matches,
                                       # prints '1'
$x =~ /(?{$c = 1;})(?{print "$^R";})/; # matches,
                                       # prints '1'

The bit of magic mentioned in the section title occurs when the regexp backtracks in the process of searching for a match. If the regexp backtracks over a code expression and if the variables used within are localized using "local", the changes in the variables produced by the code expression are undone! Thus, if we wanted to count how many times a character got matched inside a group, we could use, e.g.,

$x = "aaaa";
$count = 0;  # initialize 'a' count
$c = "bob";  # test if $c gets clobbered
$x =~ /(?{local $c = 0;})         # initialize count
       ( a                        # match 'a'
         (?{local $c = $c + 1;})  # increment count
       )*                         # do this any number of times,
       aa                         # but match 'aa' at the end
       (?{$count = $c;})          # copy local $c var into $count
      /x;
print "'a' count is $count, \$c variable is '$c'\n";

This prints

'a' count is 2, $c variable is 'bob'

If we replace the " (?{local $c = $c + 1;})" with " (?{$c = $c + 1;})", the variable changes are not undone during backtracking, and we get

'a' count is 4, $c variable is 'bob'

Note that only localized variable changes are undone. Other side effects of code expression execution are permanent. Thus

$x = "aaaa";
$x =~ /(a(?{print "Yow\n";}))*aa/;

produces

Yow
Yow
Yow
Yow

The result $^R is automatically localized, so that it will behave properly in the presence of backtracking.

If you try to use code expressions where the code text is contained within an interpolated variable, rather than appearing literally in the pattern, Perl may surprise you:

$bar = 5;
$pat = '(?{ 1 })';
/foo(?{ $bar })bar/; # compiles ok, $bar not interpolated
/foo(?{ 1 })$bar/;   # compiles ok, $bar interpolated
/foo${pat}bar/;      # compile error!
$pat = qr/(?{ $foo = 1 })/;  # precompile code regexp
/foo${pat}bar/;      # compiles ok

If a regexp has a variable that interpolates a code expression, Perl treats the regexp as an error. If the code expression is precompiled into a variable, however, interpolating is ok. The question is, why is this an error?

The reason is that variable interpolation and code expressions together pose a security risk. The combination is dangerous because many programmers who write search engines often take user input and plug it directly into a regexp:

$regexp = <>;       # read user-supplied regexp
$chomp $regexp;     # get rid of possible newline
$text =~ /$regexp/; # search $text for the $regexp

If the $regexp variable contains a code expression, the user could then execute arbitrary Perl code. For instance, some joker could search for "system('rm -rf *');" to erase your files.
