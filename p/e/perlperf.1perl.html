الفرق واضح ويمكن رؤيته، ونهج إلغاء المرجع أبطأ. بينما تمكن من تنفيذ متوسط 628,930 مرة في الثانية خلال اختبارنا، تمكن النهج المباشر من العمل 204,403 مرة إضافية، لسوء الحظ. لسوء الحظ، لأن هناك العديد من الأمثلة على الأكواد المكتوبة باستخدام الوصول المباشر متعدد الطبقات للمتغيرات، وهو عادة ما يكون مروعًا. ومع ذلك، فهو أسرع بشكل طفيف. يبقى السؤال ما إذا كانت المكاسب الطفيفة تستحق بالفعل إجهاد العين، أو فقدان قابلية الصيانة.

البحث والاستبدال أو tr

إذا كان لدينا سلسلة نصية تحتاج إلى تعديل، فبينما سيكون التعبير المنتظم (regex) دائمًا أكثر مرونة بكثير، فإن "tr"، وهي أداة غالبًا ما تكون غير مستخدمة، لا تزال مفيدة. قد يكون أحد السيناريوهات هو استبدال جميع حروف العلة بحرف آخر. قد يبدو حل التعبير المنتظم هكذا:

$str =~ s/[aeiou]/x/g

البديل "tr" قد يبدو هكذا:

$str =~ tr/aeiou/xxxxx/

يمكننا وضع ذلك في ملف اختبار يمكننا تشغيله للتحقق من النهج الأسرع، باستخدام متغير $STR عام لتعيين قيمة لمتغير "my $str" لتجنب محاولة Perl تحسين أي من العمل من خلال ملاحظة أنه يتم تعيينه مرة واحدة فقط.

# regex-transliterate

#!/usr/bin/perl
use v5.36;
use Benchmark;
my $STR = "$$-this and that";
timethese(1000000, {
'sr'  => sub { my $str = $STR; $str =~ s/[aeiou]/x/g; return $str; },
'tr'  => sub { my $str = $STR; $str =~ tr/aeiou/xxxxx/; return $str; },
});

تشغيل الكود يعطينا النتائج:

$> perl regex-transliterate
Benchmark: timing 1000000 iterations of sr, tr...
        sr:  2 wallclock secs ( 1.19 usr +  0.00 sys =  1.19 CPU) @ 840336.13/s (n=1000000)
        tr:  0 wallclock secs ( 0.49 usr +  0.00 sys =  0.49 CPU) @ 2040816.33/s (n=1000000)

إصدار "tr" هو الفائز الواضح. حل واحد مرن، والآخر سريع - وهو بحق اختيار المبرمج لمن يستخدمه.

تحقق من وثائق "Benchmark" للمزيد من التقنيات المفيدة.

أدوات التحليل

قطعة كود أكبر قليلاً ستوفر شيئًا يمكن لأداة التحليل إنتاج إحصائيات تقارير أكثر تفصيلاً بشأنه. يستخدم هذا المثال برنامج "wordmatch" المبسط الذي يحلل ملف إدخال معين وينتج تقريرًا قصيرًا عن المحتويات.

# wordmatch

#!/usr/bin/perl
use v5.36;
=head1 NAME
filewords - word analysis of input file
=head1 SYNOPSIS
    filewords -f inputfilename [-d]
=head1 DESCRIPTION
This program parses the given filename, specified with C<-f>, and
displays a simple analysis of the words found therein.  Use the C<-d>
switch to enable debugging messages.
=cut
use FileHandle;
use Getopt::Long;
my $debug   =  0;
my $file    = '';
my $result = GetOptions (
    'debug'         => \$debug,
    'file=s'        => \$file,
);
die("invalid args") unless $result;
unless ( -f $file ) {
    die("Usage: $0 -f filename [-d]");
}
my $FH = FileHandle->new("< $file")
                              or die("unable to open file($file): $!");
my $i_LINES = 0;
my $i_WORDS = 0;
my %count   = ();
my @lines = <$FH>;
foreach my $line ( @lines ) {
    $i_LINES++;
    $line =~ s/\n//;
    my @words = split(/ +/, $line);
    my $i_words = scalar(@words);
    $i_WORDS = $i_WORDS + $i_words;
    debug("line: $i_LINES supplying $i_words words: @words");
    my $i_word = 0;
    foreach my $word ( @words ) {
        $i_word++;
        $count{$i_LINES}{spec} += matches($i_word, $word,
                                          '[^a-zA-Z0-9]');
        $count{$i_LINES}{only} += matches($i_word, $word,
                                          '^[^a-zA-Z0-9]+$');
        $count{$i_LINES}{cons} += matches($i_word, $word,
                                    '^[(?i:bcdfghjklmnpqrstvwxyz)]+$');
        $count{$i_LINES}{vows} += matches($i_word, $word,
                                          '^[(?i:aeiou)]+$');
        $count{$i_LINES}{caps} += matches($i_word, $word,
                                          '^[(A-Z)]+$');
    }
}
print report( %count );
sub matches {
    my $i_wd  = shift;
    my $word  = shift;
    my $regex = shift;
    my $has = 0;
    if ( $word =~ /($regex)/ ) {
        $has++ if $1;
    }
    debug( "word: $i_wd "
          . ($has ? 'matches' : 'does not match')
          . " chars: /$regex/");
    return $has;
}
sub report {
    my %report = @_;
    my %rep;
    foreach my $line ( keys %report ) {
        foreach my $key ( keys $report{$line}->%* ) {
            $rep{$key} += $report{$line}{$key};
        }
    }
    my $report = qq|
$0 report for $file:
lines in file: $i_LINES
words in file: $i_WORDS
words with special (non-word) characters: $i_spec
words with only special (non-word) characters: $i_only
words with only consonants: $i_cons
words with only capital letters: $i_caps
words with only vowels: $i_vows
|;
    return $report;
}
sub debug {
    my $message = shift;
    if ( $debug ) {
        print STDERR "DBG: $message\n";
    }
}
exit 0;

عند تشغيل هذا البرنامج، قم بإعادة توجيه "STDOUT" حتى يكون من الممكن التحقق من صحة الإخراج من الاختبارات التالية واستخدام أداة "time" الخاصة بالنظام للتحقق من وقت التشغيل الإجمالي.

استغرق البرنامج أكثر من 17 ثانية بالتوقيت الفعلي للتشغيل. لاحظ القيم المختلفة التي تخرجها "time" ، من المهم دائمًا استخدام نفس القيمة، وعدم الخلط بين ما يعنيه كل منها.

الوقت الفعلي المنقضي Time
الوقت الإجمالي، أو وقت الساعة، بين وقت استدعاء "time" ووقت انتهائه. يشمل الوقت المنقضي أوقات المستخدم والنظام، والوقت المستغرق في انتظار المستخدمين والعمليات الأخرى على النظام. حتمًا، هذا هو الأكثر تقريبًا للقياسات المعطاة.
وقت وحدة المعالجة المركزية للمستخدم CPU Time
وقت المستخدم هو مقدار الوقت الذي استغرقه كامل العملية نيابة عن المستخدم على هذا النظام لتنفيذ هذا البرنامج.
وقت وحدة المعالجة المركزية للنظام CPU Time
وقت النظام هو مقدار الوقت الذي استغرقه النواة نفسها في تنفيذ الروتينات، أو استدعاءات النظام، نيابة عن مستخدم هذه العملية.

تشغيل نفس العملية كـ "تحويل شفارتز Schwarzian Transform" من الممكن القضاء على مصفوفات الإدخال والإخراج لتخزين جميع البيانات، والعمل على الإدخال مباشرة عند وصوله أيضًا. خلاف ذلك، يبدو الكود مشابهًا إلى حد ما:

# sort-apache-log-schwarzian

#!/usr/bin/perl -n
use v5.36;
print
    map $_->[0] =>
    sort {
        $a->[4] cmp $b->[4]
                ||
        $a->[3] cmp $b->[3]
                ||
        $a->[1] cmp $b->[1]
                ||
        $a->[2] cmp $b->[2]
                ||
        $a->[5] cmp $b->[5]
    }
    map  [ $_, m/^(
        ([\w\.\-]+)             # client
        \s*-\s*-\s*\[
        ([^]]+)                 # date
        \]\s*"\w+\s*
        (\S+)                   # query
        [^"]+"\s*
        (\d+)                   # status
        \s+\S+\s+"[^"]*"\s+"
        ([^"]*)                 # browser
        "
        .*
    )$/xo ]
    => <>;
exit 0;

التسجيل

جزء أساسي من أي عملية تطوير جيدة هو معالجة الأخطاء المناسبة مع رسائل إعلامية مناسبة، ومع ذلك هناك مدرسة فكرية تقترح أن ملفات السجل يجب أن تكون ثرثارة، كما لو أن سلسلة الإخراج غير المنقطعة تضمن بقاء البرنامج. إذا كانت السرعة قضية بأي شكل من الأشكال، فهذا النهج خاطئ.

المشهد الشائع هو كود يبدو شيئًا كهذا:

logger->debug( "A logging message via process-id: $$ INC: "
                                                      . Dumper(\%INC) )

المشكلة هي أن هذا الكود سيتم تحليله وتنفيذه دائمًا، حتى عندما يكون مستوى التصحيح المحدد في ملف إعدادات التسجيل صفرًا. بمجرد دخول التابع الفرعي debug() ، وتأكيد أن المتغير الداخلي $debug يساوي صفرًا، على سبيل المثال، سيتم تجاهل الرسالة التي تم إرسالها وسيستمر البرنامج. في المثال المعطى، سيتم بالفعل إلقاء تجزئة "\%INC"، وسيتم بناء سلسلة الرسالة، وكل هذا العمل يمكن تجاوزه بواسطة متغير تصحيح على مستوى العبارة، مثل هذا:

logger->debug( "A logging message via process-id: $$ INC: "
                                           . Dumper(\%INC) ) if $DEBUG;

يمكن إظهار هذا التأثير عن طريق إعداد برنامج نصي اختباري بكلتا الصيغتين، بما في ذلك تابع فرعي debug() لمحاكاة وظائف logger() النموذجية.

# ifdebug

#!/usr/bin/perl
use v5.36;
use Benchmark;
use Data::Dumper;
my $DEBUG = 0;
sub debug {
    my $msg = shift;
    if ( $DEBUG ) {
        print "DEBUG: $msg\n";
    }
};
timethese(100000, {
        'debug'       => sub {
            debug( "A $0 logging message via process-id: $$" . Dumper(\%INC) )
        },
        'ifdebug'  => sub {
            debug( "A $0 logging message via process-id: $$" . Dumper(\%INC) ) if $DEBUG
        },
});

دعنا نرى ما الذي تفعله "Benchmark" بهذا:

            (warning: too few iterations for a reliable count)

في حالة واحدة، الكود، الذي يفعل بالضبط نفس الشيء فيما يتعلق بإخراج أي معلومات تصحيح، أي لا شيء، يستغرق 14 ثانية، وفي الحالة الأخرى، الكود يستغرق جزء من مائة من الثانية. يبدو الأمر حاسمًا. استخدم متغير $DEBUG قبل استدعاء التابع الفرعي، بدلاً من الاعتماد على الوظائف الذكية بداخله.

التسجيل إذا كان DEBUG (ثابت)

من الممكن أخذ الفكرة السابقة إلى أبعد قليلاً، باستخدام ثابت "DEBUG" وقت الترجمة.

# ifdebug-constant

#!/usr/bin/perl
use v5.36;
use Benchmark;
use Data::Dumper;
use constant
    DEBUG => 0
;
sub debug {
    if ( DEBUG ) {
        my $msg = shift;
        print "DEBUG: $msg\n";
    }
};
timethese(100000, {
        'debug'       => sub {
            debug( "A $0 logging message via process-id: $$" . Dumper(\%INC) )
        },
        'constant'  => sub {
            debug( "A $0 logging message via process-id: $$" . Dumper(\%INC) ) if DEBUG
        },
});

تشغيل هذا البرنامج ينتج الإخراج التالي:

$> perl ifdebug-constant
Benchmark: timing 100000 iterations of constant, sub...
  constant:  0 wallclock secs (-0.00 usr +  0.00 sys = -0.00 CPU) @ -7205759403792793600000.00/s (n=100000)
            (warning: too few iterations for a reliable count)
       sub: 14 wallclock secs (13.09 usr +  0.00 sys = 13.09 CPU) @ 7639.42/s (n=100000)

الثابت "DEBUG" يتفوق على متغير $debug ، حيث يسجل بوقت سالب صفر ثانية، ويولد رسالة "تحذير: عدد تكرارات قليل جدًا لعدد موثوق" كدفعة إضافية. لرؤية ما يحدث حقًا، ولماذا كان لدينا عدد قليل جدًا من التكرارات عندما اعتقدنا أننا طلبنا 100000، يمكننا استخدام "B::Deparse" المفيد جدًا لفحص الكود الجديد:

$> perl -MO=Deparse ifdebug-constant
use Benchmark;
use Data::Dumper;
use constant ('DEBUG', 0);
sub debug {
    use warnings;
    use strict 'refs';
    0;
}
use warnings;
use strict 'refs';
timethese(100000, {'sub', sub {
    debug "A $0 logging message via process-id: $$" . Dumper(\%INC);
}
, 'constant', sub {
    0;
}
});
ifdebug-constant syntax OK

يوضح الإخراج أن التابع الفرعي constant() الذي نختبره يتم استبداله بقيمة الثابت "DEBUG": صفر. تم تحسين سطر الاختبار بالكامل، ولا يمكنك الحصول على أكثر كفاءة من ذلك.

ملاحظة ختامية

قدمت هذه الوثيقة عدة طرق لتحديد النقاط الساخنة، والتحقق مما إذا كانت أي تعديلات قد حسنت وقت تشغيل الكود.

كفكرة أخيرة، تذكر أنه ليس من الممكن (في وقت كتابة هذا التقرير) إنتاج برنامج مفيد يعمل في وقت صفر أو سالب وهذا المبدأ الأساسي يمكن كتابته كالتالي: البرامج المفيدة بطيئة بحكم تعريفها. من الممكن بالطبع كتابة برنامج فوري تقريبًا، ولكنه لن يفعل الكثير، إليك برنامج فعال للغاية:

$> perl -e 0
