PERLCYGWIN(1perl) Perl Programmers Reference Guide PERLCYGWIN(1perl)

NAME

perlcygwin - Perl for Cygwin

SYNOPSIS

This document will help you configure, make, test and install Perl on Cygwin. This document also describes features of Cygwin that will affect how Perl behaves at runtime.

NOTE: There are pre-built Perl packages available for Cygwin and a version of Perl is provided in the normal Cygwin install. If you do not need to customize the configuration, consider using one of those packages.

PREREQUISITES FOR COMPILING PERL ON CYGWIN

Cygwin = GNU+Cygnus+Windows (Don't leave UNIX without it)

The Cygwin tools are ports of the popular GNU development tools for Win32 platforms. They run thanks to the Cygwin library which provides the UNIX system calls and environment these programs expect. More information about this project can be found at:

https://www.cygwin.com/

A recent net or commercial release of Cygwin is required.

At the time this document was last updated, Cygwin 3.0.7 was current.

Cygwin Configuration

While building Perl some changes may be necessary to your Cygwin setup so that Perl builds cleanly. These changes are not required for normal Perl usage.

NOTE: The binaries that are built will run on all Win32 versions. They do not depend on your host system or your Cygwin configuration (binary/text mounts, cygserver). The only dependencies come from hard-coded pathnames like /usr/local. However, your host system and Cygwin configuration will affect Perl's runtime behavior (see "TEST").

  • "PATH"

    Set the "PATH" environment variable so that Configure finds the Cygwin versions of programs. Any not-needed Windows directories should be removed or moved to the end of your "PATH".

  • nroff

    If you do not have nroff (which is part of the groff package), Configure will not prompt you to install man pages.

CONFIGURE PERL ON CYGWIN

The default options gathered by Configure with the assistance of hints/cygwin.sh will build a Perl that supports dynamic loading (which requires a shared cygperl5_16.dll).

This will run Configure and keep a record:

./Configure 2>&1 | tee log.configure

If you are willing to accept all the defaults run Configure with -de. However, several useful customizations are available.

Stripping Perl Binaries on Cygwin

It is possible to strip the EXEs and DLLs created by the build process. The resulting binaries will be significantly smaller. If you want the binaries to be stripped, you can either add a -s option when Configure prompts you,

Any additional ld flags (NOT including libraries)? [none] -s
Any special flags to pass to g++ to create a dynamically loaded
library?
[none] -s
Any special flags to pass to gcc to use dynamic linking? [none] -s

or you can edit hints/cygwin.sh and uncomment the relevant variables near the end of the file.

Optional Libraries for Perl on Cygwin

Several Perl functions and modules depend on the existence of some optional libraries. Configure will find them if they are installed in one of the directories listed as being used for library searches. Pre-built packages for most of these are available from the Cygwin installer.

  • "-lcrypt"

    The crypt package distributed with Cygwin is a Linux compatible 56-bit DES crypt port by Corinna Vinschen.

    Alternatively, the crypt libraries in GNU libc have been ported to Cygwin.

    As of libcrypt 1.3 (March 2016), you will need to install the libcrypt-devel package for Configure to detect crypt().

  • "-lgdbm_compat" ("use GDBM_File")

    GDBM is available for Cygwin.

    NOTE: The GDBM library only works on NTFS partitions.

  • "-ldb" ("use DB_File")

    BerkeleyDB is available for Cygwin.

    NOTE: The BerkeleyDB library only completely works on NTFS partitions.

  • "cygserver" ("use IPC::SysV")

    A port of SysV IPC is available for Cygwin.

    NOTE: This has not been extensively tested. In particular, "d_semctl_semun" is undefined because it fails a Configure test. It also creates a compile time dependency because perl.h includes <sys/ipc.h> and <sys/sem.h> (which will be required in the future when compiling CPAN modules). CURRENTLY NOT SUPPORTED!

  • "-lutil"

    Included with the standard Cygwin netrelease is the inetutils package which includes libutil.a.

Configure-time Options for Perl on Cygwin

The INSTALL document describes several Configure-time options. Some of these will work with Cygwin, others are not yet possible. Also, some of these are experimental. You can either select an option when Configure prompts you or you can define (undefine) symbols on the command line.

  • "-Uusedl"

    Undefining this symbol forces Perl to be compiled statically.

  • "-Dusemymalloc"

    By default Perl does not use the malloc() included with the Perl source, because it was slower and not entirely thread-safe. If you want to force Perl to build with the old -Dusemymalloc define this.

  • "-Uuseperlio"

    Undefining this symbol disables the PerlIO abstraction. PerlIO is now the default; it is not recommended to disable PerlIO.

  • "-Dusemultiplicity"

    Multiplicity is required when embedding Perl in a C program and using more than one interpreter instance. This is only required when you build a not-threaded perl with "-Uuseithreads".

  • "-Uuse64bitint"

    By default Perl uses 64 bit integers. If you want to use smaller 32 bit integers, define this symbol.

  • "-Duselongdouble"

    gcc supports long doubles (12 bytes). However, several additional long double math functions are necessary to use them within Perl ({atan2, cos, exp, floor, fmod, frexp, isnan, log, modf, pow, sin, sqrt}l, strtold). These are not yet available with newlib, the Cygwin libc.

  • "-Uuseithreads"

    Define this symbol if you want not-threaded faster perl.

  • "-Duselargefiles"

    Cygwin uses 64-bit integers for internal size and position calculations, this will be correctly detected and defined by Configure.

  • "-Dmksymlinks"

    Use this to build perl outside of the source tree. Details can be found in the INSTALL document. This is the recommended way to build perl from sources.

MAKE ON CYGWIN

The standard make will work fine.

TEST ON CYGWIN

The make test will compile and run a large suite of tests to check that Perl has been built correctly. However, there are some things that you need to be aware of:

  • "make test"

    This will run all the tests. Most tests should pass without incident. A few tests may fail. These are often due to your Cygwin configuration, or the way your Cygwin system is set up.

    Specifically, tests that rely on sockets or pipes may fail if you are using Cygwin with cygserver not running, or if you have not configured Cygwin correctly for networking.

    Tests that rely on file permissions might fail if you are not using Cygwin on an NTFS partition. FAT and FAT32 partitions do not have POSIX ACLs, and Cygwin's emulation of them is limited.

  • "TEST_FILES"

    If you wish to skip tests that are known to fail on Cygwin, you can use the TEST_FILES variable:

    make test TEST_FILES="t/foo t/bar"

    This will run only the tests in t/foo and t/bar.

  • "PERL_TEST_FLAKY"

    Some tests are known to be flaky, meaning they fail intermittently. Setting the PERL_TEST_FLAKY environment variable to 1 will cause these tests to be run.

    make test PERL_TEST_FLAKY=1

INSTALL ON CYGWIN

The standard make install will work fine.

This will install Perl into /usr/local by default. If you want to install Perl elsewhere, you can specify a prefix option to Configure.

For example:

./Configure -Dprefix=/opt/perl5
make
make install

This will install Perl into /opt/perl5.

RUNNING PERL ON CYGWIN

Shebang Lines

Cygwin translates shebang lines like this:

#!/usr/bin/perl

into a call to the Cygwin Perl interpreter. If you are using the Perl installed by the Cygwin installer, this should work fine. If you have installed Perl into a non-standard location, you may need to:

  • Use an explicit path: 
    #!/usr/local/bin/perl
  • Use the env command: 
    #!/usr/bin/env perl

    This is the recommended approach, as it relies on the user's PATH environment variable to find the Perl interpreter.

File and Directory Names

Cygwin provides a POSIX-like environment on top of Win32. This means that Perl scripts running under Cygwin will see file and directory names in a POSIX-like format (e.g., /usr/bin/perl). These will be translated into their Win32 equivalents by the Cygwin library.

You can also use Win32-style paths (e.g., C:\Program Files) in your Perl scripts, but they are generally not recommended unless you are mixing Cygwin and non-Cygwin applications.

Environment Variables

Environment variables are handled in the standard POSIX way. However, there are some differences from a standard Unix system:

  • "PATH"

    The PATH environment variable is used to find executables. Cygwin will search both POSIX-style paths (e.g., /usr/bin) and Win32-style paths (e.g., C:\WINDOWS\system32).

  • "HOME"

    The HOME environment variable is typically set to your user's home directory on the Cygwin filesystem (e.g., /home/username). If not set, it defaults to the root of the Cygwin installation (e.g., /).

  • "TMPDIR"

    The TMPDIR environment variable is used to specify a temporary directory. If not set, Cygwin defaults to using /tmp.

Line Endings

Cygwin generally handles line endings correctly. Files created on Windows typically use CRLF (\r\n) line endings, while Unix-style files use LF (\n). Cygwin attempts to translate these automatically when reading and writing files.

However, if you encounter problems with line endings, you may need to explicitly handle them in your Perl scripts, or configure your file mounts appropriately.

Case Sensitivity

By default, Cygwin file systems are case-insensitive (like most Windows file systems). This means that File.txt and file.txt are considered the same file.

This can cause problems for Perl scripts that rely on case-sensitive file names. If you need case-sensitive file system behavior, you can enable it by creating a file named ._FORCE_CASE_SENSITIVE in the root of your Cygwin installation.

KNOWN PROBLEMS

The following are known issues when running Perl on Cygwin:

  • "fork()"

    The fork() system call is emulated by Cygwin using the pthreads library. It may not be as efficient as on native Unix systems, and some programs that rely heavily on fork() may exhibit performance issues.

  • "IPC::SysV"

    As mentioned in the "Optional Libraries" section, support for IPC::SysV is currently experimental and not fully supported.

  • "Win32::API"

    The Win32::API module allows Perl scripts to call Win32 API functions directly. While this module generally works well, there can be subtle issues related to data type conversions and calling conventions between Perl and the Win32 API.

  • "Network Access"

    Network access from Cygwin Perl may be affected by the Cygwin network configuration and any firewalls that are active on your system.

الاختبار على CYGWIN

هناك خطوتان لتشغيل مجموعة الاختبارات:

make test 2>&1 | tee log.make-test
cd t; ./perl harness 2>&1 | tee ../log.harness

يتم تشغيل نفس الاختبارات في كلتا المرتين، ولكن يتم توفير المزيد من المعلومات عند التشغيل كـ "./perl harness"، ويمكنك تشغيل الاختبارات بالتوازي عن طريق تحديد بدلاً من ذلك:

cd t; TEST_JOBS=n ./perl harness 2>&1 | tee ../log.harness

حيث n هو الحد الأقصى لعدد الاختبارات التي سيتم تشغيلها بالتوازي.

تختلف نتائج الاختبار اعتمادًا على نظام المضيف الخاص بك وتكوين Cygwin الخاص بك. إذا كان الاختبار يمكن أن ينجح في بعض إعدادات Cygwin، فسيتم دائمًا محاولة فشل الاختبارات المبررة وتوثيقها. من الممكن أن يجتاز Perl جميع الاختبارات، ولكن من المرجح أن تفشل بعض الاختبارات لأحد الأسباب المدرجة أدناه.

أذونات الملفات على Cygwin

تعتمد أذونات ملفات UNIX على مجموعات من بتات الوضع لـ {القراءة، الكتابة، التنفيذ} لكل {مستخدم، مجموعة، آخر}. افتراضيًا، يتتبع Cygwin فقط سمة القراءة فقط لنظام Win32 الممثلة كبت كتابة المستخدم للملفات UNIX (الملفات قابلة للقراءة دائمًا، الملفات قابلة للتنفيذ إذا كان لها امتداد .{com,bat,exe} أو تبدأ بـ "#!"، الدلائل قابلة للقراءة والتنفيذ دائمًا). على WinNT مع إعداد ntea "CYGWIN"، يتم تخزين بتات الوضع الإضافية كسمات ملف ممتدة. على WinNT مع إعداد ntsec الافتراضي "CYGWIN"، تستخدم الأذونات واصفات أمان WinNT القياسية وقوائم التحكم في الوصول. بدون أحد هذه الخيارات، ستفشل هذه الاختبارات (القائمة لم يتم تحديثها بعد):

ميزات محددة لمنفذ Cygwin

قابلية نقل البرامج النصية على Cygwin

يقوم Cygwin بعمل ممتاز في توفير دلالات شبيهة بـ UNIX فوق أنظمة Win32. ومع ذلك، بالإضافة إلى العناصر المذكورة أعلاه، هناك بعض الاختلافات التي يجب أن تعرفها. هذا دليل موجز جدًا لقابلية النقل، ويمكن العثور على مزيد من المعلومات في وثائق Cygwin.

  • أسماء المسارات

    يتم فصل أسماء مسارات Cygwin بشرطات مائلة (/)، ويتم أيضًا دعم رموز التسمية العالمية (//UNC). منذ cygwin-1.7، لا ينبغي استخدام أسماء المسارات غير POSIX. قد تحتوي الأسماء على جميع الأحرف القابلة للطباعة.

    أسماء الملفات غير حساسة لحالة الأحرف، ولكنها تحتفظ بحالة الأحرف. اسم المسار الذي يحتوي على شرطة مائلة للخلف أو حرف محرك أقراص هو اسم مسار Win32، ولا يخضع للترجمات المطبقة على أسماء المسارات بأسلوب POSIX، ولكن cygwin سيحذرك، لذلك من الأفضل تحويلها إلى POSIX.

    للتحويل، لدينا Cygwin::win_to_posix_path() و Cygwin::posix_to_win_path().

    منذ cygwin-1.7، تم ترميز أسماء المسارات بـ UTF-8.

  • نص/ثنائي

    منذ cygwin-1.7، تم إيقاف استخدام mounts النصية وتم تثبيطها بشدة.

    عند فتح ملف، يكون في وضع نصي أو ثنائي. في وضع النص، يخضع الملف لترجمات CR/LF/Ctrl-Z. مع Cygwin، يتم تحديد الوضع الافتراضي لـ open() بواسطة وضع التحميل الذي يكمن وراء الملف. انظر "Cygwin::is_binmount"(). يوفر Perl وظيفة binmode() لتعيين الوضع الثنائي على الملفات التي سيتم التعامل معها كملفات نصية بخلاف ذلك. sysopen() مع العلامة "O_TEXT" يعين الوضع النصي على الملفات التي سيتم التعامل معها كملفات ثنائية بخلاف ذلك:

    sysopen(FOO, "bar", O_WRONLY|O_CREAT|O_TEXT)

    lseek() و tell() و sysseek() تعمل فقط مع الملفات المفتوحة في الوضع الثنائي.

    تتم تغطية مسألة النص/الثنائي بالتفصيل في وثائق Cygwin.

  • PerlIO

    يتجاوز PerlIO سلوك النص/الثنائي الافتراضي لـ Cygwin. سيتم دائمًا التعامل مع الملف كملف ثنائي، بغض النظر عن وضع التحميل الذي يوجد عليه، تمامًا كما هو الحال في UNIX. لذا، يجب طلب ترجمة CR/LF إما في استدعاء open() على هذا النحو:

    open(FH, ">:crlf", "out.txt");

    والذي سيقوم بالتحويل من LF إلى CR/LF عند الإخراج، أو في إعدادات البيئة (أضف هذا إلى .bashrc الخاص بك):

    export PERLIO=crlf

    والذي سيجلب طبقة PerlIO crlf التي تقوم بتحويل LF -> CRLF عند كل إخراج يتم إنتاجه بواسطة perl.

  • .exe

    تجعل وظائف stat() و lstat() و readlink() في Cygwin امتداد .exe شفافًا من خلال البحث عن foo.exe عندما تطلب foo (ما لم يكن foo موجودًا أيضًا). لا يتطلب Cygwin امتداد .exe، ولكن gcc يضيفه تلقائيًا عند بناء برنامج. ومع ذلك، عند الوصول إلى ملف تنفيذي كملف عادي (على سبيل المثال، cp في ملف make)، فإن .exe ليس شفافًا. يضيف برنامج install المضمن مع Cygwin تلقائيًا لاحقة .exe عند الضرورة.

  • معرفات العمليات Cygwin مقابل Windows

    تمتلك عمليات Cygwin معرفات عمليات خاصة بها، وهي تختلف عن معرفات عمليات Windows الأساسية. تتوقع معظم وظائف Proc المتوافقة مع posix معرفات عمليات cygwin، ولكن العديد من وظائف Win32::Process تتوقع معرفات عمليات win32. على سبيل المثال، $$ هو معرف عمليات cygwin لـ /usr/bin/perl، وهو ليس معرف عمليات win32. استخدم Cygwin::pid_to_winpid() و Cygwin::winpid_to_pid() للتحويل بينهما.

  • أخطاء Cygwin مقابل Windows

    في ظل Cygwin، $^E هو نفس $!. عند استخدام وظائف واجهة برمجة التطبيقات Win32، استخدم Win32::GetLastError() للحصول على آخر خطأ في Windows.

  • أخطاء إعادة التوزيع عند fork أو system

    قد يؤدي استخدام fork() أو system() إلى perl آخر بعد تحميل العديد من dlls إلى تعارض في عنوان قاعدة DLL. الخطأ الداخلي لـ cygwin يبدو كالتالي:

    0 [main] perl 8916 child_info_fork::abort: data segment start:
parent (0xC1A000) != child(0xA6A000)

    أو:

    183 [main] perl 3588 C:\cygwin\bin\perl.exe: *** fatal error -
unable to remap C:\cygwin\bin\cygsvn_subr-1-0.dll to same address
as parent(0x6FB30000) != 0x6FE60000 46 [main] perl 3488 fork: child
3588 - died waiting for dll loading, errno11

    انظر https://cygwin.com/faq/faq.html#faq.using.fixing-fork-failures يساعد إذا لم يتم تحميل الكثير من DLLs في الذاكرة بحيث يكون مساحة العنوان المتاحة أكبر، على سبيل المثال، قد يساعد إيقاف تشغيل MS Internet Explorer.

    +استخدم أدوات إعادة التوزيع لحل عناوين DLL المتعارضة. يتم تضمين حزمة إعادة التوزيع في إعداد Cygwin. استخدم setup.exe من https://cygwin.com/install.html لتثبيتها.

    1. قم بإنهاء جميع عمليات perl وتشغيل
    "</bin/find <dir" -xdev -name \*.dll | /bin/rebase -OT ->> أو

    2. قم بإنهاء جميع عمليات وخدمات cygwin، وتشغيل setup.exe.

  • متفرقات

    قفل الملفات باستخدام الأمر "F_GETLK" إلى fcntl() هو مجرد وظيفة وهمية تعيد "ENOSYS".

    تنفيذ chroot() في Cygwin به ثغرات (لا يمكنه تقييد الوصول إلى الملفات بواسطة برامج Win32 الأصلية).

    تحرير الملفات في المكان "perl -i" للملفات لا يعمل بدون عمل نسخة احتياطية من الملف الذي يتم تحريره "perl -i.bak" بسبب القيود الشبيهة بالنوافذ، وبالتالي يضيف Perl اللاحقة ".bak" تلقائيًا إذا استخدمت "perl -i" دون تحديد لاحقة احتياطية.

NAME

perlcygwin – perl port to Cygwin

SYNOPSIS

This document describes the Perl port to Cygwin.

PREREQUISITES FOR COMPILING PERL ON CYGWIN

A recent version of the Cygwin environment.

You may need a POSIX-like compiler toolchain, like GCC, that is part of the Cygwin installation.

CONFIGURE PERL ON CYGWIN

Run

    sh Configure -des -Dprefix=/usr/local

or similar.

If you want to compile Perl for Cygwin under Windows (native compilation), you can use MinGW/MSYS. This is not recommended, as it is complex and may have compatibility issues.

If you use MSYS2, then it should be similar to configure on Linux.

MAKE ON CYGWIN

Run

    make

TEST ON CYGWIN

Run

    make test

Specific features of the Cygwin port

Cygwin implements a POSIX API layer on top of the Windows NT kernel. This means that some POSIX features are available that are not part of native Windows APIs.

The Cygwin port of Perl attempts to leverage these POSIX features where possible. This includes support for things like symbolic links, case-insensitive file systems, and user/group IDs.

However, there are limitations. Cygwin's emulation is not perfect, and some POSIX features may not be fully supported or may behave differently than on native POSIX systems.

For example, the emulation of user and group IDs is not complete. While Cygwin provides functions like setuid() and setgid(), these functions do not map directly to the underlying Windows security model. This means that operations that rely on changing user or group IDs may not work as expected.

BUGS ON CYGWIN

Support for swapping real and effective user and group IDs is incomplete. On WinNT Cygwin provides setuid(), seteuid(), setgid() and setegid(). However, additional Cygwin calls for manipulating WinNT access tokens and security contexts are required.
