تحديد مجموعات رموز الأحرف


من الممكن تحديد مجموعة الأحرف التي تعمل تحتها. ولكن أولاً تحتاج إلى
    التأكد حقًا حقًا من أنك بحاجة إلى القيام بذلك. سيكون كودك أبسط وربما
    محمولًا بنفس القدر إذا لم تكن بحاجة إلى اختبار مجموعة الأحرف والقيام
    بأشياء مختلفة، اعتمادًا على ذلك. في الواقع، هناك فقط عدد قليل جدًا من
    الظروف التي يكون فيها من السهل كتابة كود مباشر محمول لجميع مجموعات
    الأحرف. انظر "Unicode and EBCDIC" في perluniintro حول كيفية
    تحديد الأحرف بشكل محمول.


ولكن هناك بعض الحالات التي قد ترغب فيها في معرفة مجموعة الأحرف التي
    تعمل تحتها. أحد الأمثلة الممكنة هو إجراء الفرز في الحلقات الداخلية حيث يكون
    الأداء حرجًا.


لتحديد ما إذا كنت تعمل تحت ASCII أو EBCDIC، يمكنك استخدام القيمة
    المرجعة من ord() أو chr()
    لاختبار قيمة حرف واحد أو أكثر. على سبيل المثال:


$is_ascii  = "A" eq chr(65);
$is_ebcdic = "A" eq chr(193);
$is_ascii  = ord("A") == 65;
$is_ebcdic = ord("A") == 193;


هناك حاجة أقل للتمييز بين صفحات رموز EBCDIC، ولكن للقيام بذلك حاول
    النظر إلى واحد أو أكثر من الأحرف التي تختلف بينها.


$is_ascii           = ord('[') == 91;
$is_ebcdic_37       = ord('[') == 186;
$is_ebcdic_1047     = ord('[') == 173;
$is_ebcdic_POSIX_BC = ord('[') == 187;


ومع ذلك، سيكون من غير الحكمة كتابة اختبارات مثل:


$is_ascii = "\r" ne chr(13);  #  WRONG
$is_ascii = "\n" ne chr(10);  #  ILL ADVISED


من الواضح أن الأول من هذه لن يميز معظم منصات ASCII عن أي من منصات
    EBCDIC CCSID 0037، أو 1047، أو POSIX-BC لأن
    ""\r" eq chr(13)"
    تحت جميع مجموعات رموز الأحرف تلك. ولكن لاحظ أيضًا أنه نظرًا لأن
    "\n" هو chr(13)
    و "\r" هو chr(10)
    على نظام Mac القديم (وهو منصة ASCII) فإن اختبار
    $is_ascii الثاني سيؤدي إلى مشاكل هناك.


لتحديد ما إذا كان Perl قد تم بناؤه تحت صفحة رموز EBCDIC أم لا،
    يمكنك استخدام وحدة Config على النحو التالي:


use Config;
$is_ebcdic = $Config{'ebcdic'} eq 'define';

اختلافات العوامل


يعامل عامل النطاق ".." نطاقات
    أحرف معينة بعناية على منصات EBCDIC. على سبيل المثال، سيكون للمصفوفة التالية
    ستة وعشرون عنصرًا سواء على منصة EBCDIC أو منصة ASCII:


@alphabet = ('A'..'Z');   #  $#alphabet == 25


قد تعيد العوامل البتية مثل & ^ | نتائج مختلفة عند التشغيل على
    بيانات السلسلة أو الأحرف في برنامج Perl يعمل على منصة EBCDIC مقارنة
    بتشغيله على منصة ASCII. إليك مثال مقتبس من perlop:


# أمثلة مستندة إلى EBCDIC
print "j p \n" ^ " a h";                      # تطبع "JAPH\n"
print "JA" | "  ph\n";                        # تطبع "japh\n"
print "JAPH\nJunk" & "\277\277\277\277\277";  # تطبع "japh\n";
print 'p N$' ^ " E<H\n";                      # تطبع "Perl\n";


خاصية مثيرة للاهتمام لـ 32 حرف تحكم C0 في جدول ASCII هي أنه يمكن
    إنشاؤها "حرفيًا" كأحرف تحكم في Perl، على سبيل المثال
    "(chr(0)" eq
    "\c@")>
    "(chr(1)" eq
    "\cA")>، وهكذا. تم نقل Perl على منصات
    EBCDIC لتأخذ "\c@" إلى
    chr(0) و "\cA"
    إلى chr(1)، وما إلى ذلك أيضًا، ولكن الأحرف الناتجة
    تعتمد على صفحة الرموز التي تستخدمها. يستخدم الجدول أدناه الاختصارات القياسية
    للضوابط. مجموعات POSIX-BC و 1047 متطابقة في هذا النطاق وتختلف عن مجموعة
    0037 في نقطة واحدة فقط (21 عشري). لاحظ أن حرف نهاية السطر قد يتم إنشاؤه
    بواسطة "\cJ" على منصات ASCII ولكن بواسطة
    "\cU" على منصات 1047 أو POSIX-BC ولا يمكن
    إنشاؤه كحرف تحكم "\c.letter." على منصات
    0037. لاحظ أيضًا أن "\c\" لا يمكن أن يكون
    العنصر الأخير في سلسلة أو تعبير عادي، لأنه سيمتص الفاصل. ولكن
    "\c\X"
    هو "FILE SEPARATOR" مدموج مع X لجميع
    X. الرمز الشاذ "\c?" على ASCII،
    الذي ينتج حرف تحكم غير C0 "DEL"، ينتج حرف التحكم الشاذ
    "APC" على EBCDIC، وهو الرمز الذي ليس في كتلة الضوابط المتجاورة.
    لاحظ أن تفصيلاً لذلك هو أن "\c?" على
    منصات ASCII هو حرف ASCII، بينما لا يعادل أي حرف ASCII على منصات
    EBCDIC.

اختلافات الوظائف

chr()
chr() يجب أن تُعطى وسيطة رقم رمز EBCDIC لإنتاج قيمة حرفية مرغوبة على منصة EBCDIC. على سبيل المثال: 
$CAPITAL_LETTER_A = chr(193);
ord()
ord() ستعيد قيم أرقام رموز EBCDIC على منصة EBCDIC. على سبيل المثال: 
$the_number_193 = ord("A");
pack()
القوالب "c" و "C" لـ pack() تعتمد على ترميز مجموعة الأحرف. أمثلة على الاستخدام على EBCDIC تشمل: 
$foo = pack("CCCC",193,194,195,196);
# $foo eq "ABCD"
$foo = pack("C4",193,194,195,196);
# نفس الشيء
$foo = pack("ccxxcc",193,194,195,196);
# $foo eq "AB\0\0CD"

تم نقل القالب "U" ليعني "Unicode" على جميع المنصات بحيث

pack("U", 65) eq 'A'

يكون صحيحًا على جميع المنصات. إذا كنت تريد نقاط رمز أصلية لأقل 256، فاستخدم القالب "W". هذا يعني أن المعادلات

pack("W", ord($character)) eq $character
unpack("W", $character) == ord $character

ستكون صحيحة.

print()
يجب أن تكون حذرًا مع القيم العددية والسلاسل النصية التي يتم تمريرها إلى print والتي تحتوي على ترميزات ASCII. مكان شائع لحدوث ذلك هو في إخراج رأس نوع MIME لكتابة نص CGI. على سبيل المثال، توصي العديد من أدلة البرمجة بلغة Perl بشيء مشابه لـ: 
print "Content-type:\ttext/html\015\012\015\012";
# قد يكون هذا خطأ على EBCDIC

يمكنك بدلاً من ذلك كتابة

print "Content-type:\ttext/html\r\n\r\n"; # OK for DGW et al

وجعله يعمل بشكل محمول.

ذلك لأن الترجمة من EBCDIC إلى ASCII تتم بواسطة خادم الويب في هذه الحالة. استشر وثائق خادم الويب الخاص بك لمزيد من التفاصيل.

printf()
ستكون التنسيقات التي يمكنها تحويل الأحرف إلى أرقام والعكس صحيح مختلفة عن نظيراتها في ASCII عند تشغيلها على منصة EBCDIC. تشمل الأمثلة: 
printf("%c%c%c",193,194,195);  # يطبع ABC
sort()
قد تختلف نتائج فرز EBCDIC عن نتائج فرز ASCII خاصة بالنسبة للسلاسل المختلطة حالة الأحرف. يناقش هذا بمزيد من التفصيل أدناه.
sprintf()
انظر مناقشة "printf()" أعلاه. مثال على استخدام sprintf سيكون: 
$CAPITAL_LETTER_A = sprintf("%c",193);
unpack()
انظر مناقشة "pack()" أعلاه.

لاحظ أنه من الممكن كتابة كود محمول لهذه عن طريق تحديد الأشياء بأرقام Unicode، واستخدام وظيفة تحويل:

printf("%c",utf8::unicode_to_native(65));  # يطبع A على جميع
                                           # المنصات
print utf8::native_to_unicode(ord("A"));   # بالمثل، يطبع 65

انظر "Unicode and EBCDIC" في perluniintro و "CONVERSIONS" لخيارات أخرى.

اختلافات التعبيرات النمطية

يمكنك كتابة تعبيراتك النمطية تمامًا كما يفعل شخص ما على منصة ASCII. ولكن ضع في اعتبارك أن استخدام الترميز الثماني أو الست عشري لتحديد نقطة رمز معينة سيمنحك الحرف الذي تقوم صفحة رمز EBCDIC بتعيينه بشكل أصلي له. (هذا صحيح أيضًا لجميع السلاسل النصية المزدوجة الاقتباس.) إذا كنت تريد الكتابة بشكل محمول، فما عليك سوى استخدام التدوين "\N{U+...}" في كل مكان كنت ستستخدم فيه "\x{...}"، ولا تستخدم الترميز الثماني على الإطلاق.

بدءًا من Perl v5.22، ينطبق هذا على النطاقات في فئات الأحرف المحاطة بأقواس. إذا قلت، على سبيل المثال، "qr/[\N{U+20}-\N{U+7F}]/"، فهذا يعني الأحرف "\N{U+20}"، "\N{U+21}"، ...، "\N{U+7F}". هذا النطاق هو جميع الأحرف القابلة للطباعة التي تحتوي عليها مجموعة أحرف ASCII.

قبل v5.22، لم يكن بإمكانك تحديد أي نطاقات بشكل محمول، باستثناء (بدءًا من Perl v5.5.3) تم ترميز جميع المجموعات الفرعية لنطاقات "[A-Z]" و "[a-z]" بشكل خاص لعدم التقاط أحرف الفجوات. على سبيل المثال، الأحرف مثل "ô" ("o WITH CIRCUMFLEX") التي تقع بين "I" و "J" لن يتم مطابقتها بواسطة نطاق التعبير النمطي "/[H-K]/". ولكن إذا تم تحديد أي من نقاط نهاية النطاق رقميًا بشكل صريح (ولم يتم تحديد أي منهما بواسطة "\N{U+...}")، فسيتم مطابقة أحرف الفجوات:

/[\x89-\x91]/

سيطابق "\x8e"، على الرغم من أن "\x89" هو "i" و "\x91 " هو "j"، و "\x8e" هو حرف فجوة، من وجهة نظر أبجدية.

هناك بناء آخر يجب الحذر منه وهو الاستخدام غير المناسب للثوابت الست عشرية (ما لم تستخدم "\N{U+...}") أو الثمانية في التعبيرات النمطية. انظر مجموعة الدوال التالية:

sub is_c0 {
    my $char = substr(shift,0,1);
    $char =~ /[\000-\037]/;
}
sub is_print_ascii {
    my $char = substr(shift,0,1);
    $char =~ /[\040-\176]/;
}
sub is_delete {
    my $char = substr(shift,0,1);
    $char eq "\177";
}
sub is_c1 {
    my $char = substr(shift,0,1);
    $char =~ /[\200-\237]/;
}
sub is_latin_1 {    # But not ASCII; not C1
    my $char = substr(shift,0,1);
    $char =~ /[\240-\377]/;
}

هذه الدوال صالحة فقط على منصات ASCII. بدءًا من Perl v5.22، مجرد تغيير الثوابت الثمانية إلى ما يعادلها من قيم "\N{U+...}" يجعلها محمولة:

sub is_c0 {
    my $char = substr(shift,0,1);
    $char =~ /[\N{U+00}-\N{U+1F}]/;
}
sub is_print_ascii {
    my $char = substr(shift,0,1);
    $char =~ /[\N{U+20}-\N{U+7E}]/;
}
sub is_delete {
    my $char = substr(shift,0,1);
    $char eq "\N{U+7F}";
}
sub is_c1 {
    my $char = substr(shift,0,1);
    $char =~ /[\N{U+80}-\N{U+9F}]/;
}
sub is_latin_1 {    # But not ASCII; not C1
    my $char = substr(shift,0,1);
    $char =~ /[\N{U+A0}-\N{U+FF}]/;
}

sub Is_c0 {
    my $char = substr(shift,0,1);
    return $char =~ /[[:cntrl:]]/a && ! Is_delete($char);
    # Alternatively:
    # return $char =~ /[[:cntrl:]]/
    #        && $char =~ /[[:ascii:]]/
    #        && ! Is_delete($char);
}
sub Is_print_ascii {
    my $char = substr(shift,0,1);
    return $char =~ /[[:print:]]/a;
    # Alternatively:
    # return $char =~ /[[:print:]]/ && $char =~ /[[:ascii:]]/;
    # Or
    # return $char
    #      =~ /[ !"\#\$%&'()*+,\-.\/0-9:;<=>?\@A-Z[\\\]^_`a-z{|}~]/;
}
sub Is_delete {
    my $char = substr(shift,0,1);
    return utf8::native_to_unicode(ord $char) == 0x7F;
}
sub Is_c1 {
    use feature 'unicode_strings';
    my $char = substr(shift,0,1);
    return $char =~ /[[:cntrl:]]/ && $char !~ /[[:ascii:]]/;
}
sub Is_latin_1 {    # But not ASCII; not C1
    use feature 'unicode_strings';
    my $char = substr(shift,0,1);
    return ord($char) < 256
           && $char !~ /[[:ascii:]]/
           && $char !~ /[[:cntrl:]]/;
}
