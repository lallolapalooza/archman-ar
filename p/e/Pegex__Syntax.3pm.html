Pegex Syntax

يمكن استخدام المصطلح "Pegex" للإشارة إلى كل من إطار عمل محلل Pegex ولغة بناء جملة قواعد Pegex المستخدمة لكتابة ملفات قواعد Pegex. توضح هذه الوثيقة بناء جملة Pegex.

Pegex هي لغة ذاتية الاستضافة. هذا يعني أن بناء جملة تعريف لغة Pegex مكتوب بلغة Pegex نفسها. يمكنك رؤيته بنفسك هنا: https://github.com/ingydotnet/pegex-pgx/blob/master/pegex.pgx.

أشجعك على إلقاء نظرة سريعة على هذا الرابط حتى الآن. تتكون قاعدة Pegex (مثل هذه) من جزأين: قسم بيانات وصفية وقسم قواعد.

يحتوي قسم البيانات الوصفية فقط على سمات بيانات وصفية للكلمات الرئيسية/القيم حول القاعدة. أشياء مثل اسم القاعدة والإصدار.

اللحم الحقيقي لقاعدة Pegex موجود في قواعدها. القاعدة الأولى جدًا من القاعدة أعلاه هي (بشكل أساسي):

grammar: meta_section rule_section

والتي تقول، القاعدة هي قسم بيانات وصفية متبوعًا بـ قسم القواعد. ولكن مهلاً، كنا نعرف ذلك بالفعل!

Meta Section

تبدو عبارات البيانات الوصفية في أعلى ملف القاعدة هكذا:

%pegexKeyword value

دعنا نلقي نظرة على أعلى قاعدة pegex.pgx:

# This is the Pegex grammar for Pegex grammars!
%grammar pegex
%version 0.1.0

يحدد هذا قيمتين للبيانات الوصفية: "grammar" و "version"، والتي تحدد اسم وإصدار القاعدة على التوالي.

ستلاحظ أيضًا أن السطر الأول هو تعليق. تبدأ التعليقات بـ "#" وتمتد حتى نهاية السطر. يُسمح بالتعليقات في أي مكان تقريبًا في القاعدة، سواء في أسطر خاصة بها، أو بعد العبارات، أو حتى داخل تعريفات التعبيرات العادية كما سنرى لاحقًا.

ينتهي قسم البيانات الوصفية لـ Pegex عندما يبدأ قسم قواعد Pegex (مع تعريف القاعدة الأولى).

Rule Section

باقي قاعدة Pegex هو مجموعة من القواعد المسماة. كل قاعدة هي اسم قاعدة، متبوعًا بـ ':', متبوعًا بتعريف القاعدة، متبوعًا بـ ';' أو سطر جديد.

هنا بعض القواعد من قاعدة pegex.pgx. (هذه هي القواعد التي تبدأ في تعريف قاعدة!).

rule_definition:
    rule_start
    rule_group
    ending
rule_start: /
    ( rule_name )     # Capture the rule_name
    BLANK*
    COLON -
/

تعريفات القواعد هي تعبيرات لاحقة. تتكون من رموز مميزة مفصولة بعوامل، مع أقواس لتوضيح أسبقية الربط. هناك 3 أنواع مميزة من الرموز و 3 عوامل.

أنواع الرموز الثلاثة هي: مرجع قاعدة، تعبير عادي، ورسالة خطأ. العوامل الثلاثة هي AND (' ')، OR ('|')، و ALT ('%'، '%%').

إليك مثال من قاعدة Pegex لتحليل JSON:

json: hash | array
array: / LSQUARE / ( node* % / COMMA / ) (
    / RSQUARE / | `missing ']'` )

هذا يعني: "json إما قيمة مجزأة أو مصفوفة. مصفوفة هي '[', صفر أو أكثر من العقد مفصولة بفواصل، و ']'. خطأ إذا لم يتم العثور على ']'."

"hash"، "array"، و "node" هي مراجع للقواعد، مما يعني أنها تشير إلى قواعد مسماة داخل القاعدة التي يجب أن تتطابق في تلك النقطة. النص المحاط بزوج من علامات '/' يشكل تعبيرًا عاديًا. النص المحاط بعلامات الاقتباس الخلفية هو رسالة خطأ.

"LSQUARE"، "RSQUARE"، و "COMMA" هي أيضًا مراجع للقواعد. يمكن الإشارة إلى القواعد داخل التعبيرات العادية، طالما أنها تشير إلى تعبيرات عادية بنفسها. بهذه الطريقة، يمكن تجميع التعبيرات العادية الكبيرة من تعبيرات أصغر، مما يؤدي إلى إعادة الاستخدام وقابلية القراءة. أخيرًا، '*' بعد "node" تسمى "محدد كمي". المزيد عن تلك لاحقًا.

Rule References

مرجع القاعدة هو اسم قاعدة داخل أقواس زاوية. الأقواس اختيارية عادةً. داخل تعبير عادي، يجب أن يسبق مرجع قاعدة بدون "<>" حرف مسافة بيضاء.

<sub_rule_name>
sub_rule_name

عند استخدامه خارج تعبير عادي، يمكن أن يكون للمرجع عدد من معدلات البادئة. لاحظ أن الأقواس الزاوية ليست مطلوبة هنا، ولكنها تضيف إلى سهولة القراءة.

=rule  # Zero-width positive assertion (look-ahead)
!rule  # Zero-width negative assertion (look-ahead)
.rule  # Skip (ie: parse but don't capture a subpattern)
-rule  # Flat (flatten the array captures)
+rule  # Always wrap

(يتم شرح التخطي والتغليف في [Return Values].)

يمكن أن يكون للمرجع أيضًا عدد من محددات الكمية اللاحقة. على غرار بناء جملة التعبيرات العادية، يشير محدد الكمية إلى عدد المرات التي يجب أن تتطابق فيها القاعدة (المرجع).

rule?      # optional
rule*      # 0 or more times
rule+      # 1 or more times
<rule>8    # exactly 8 times
<rule>2+   # 2 or more times
<rule>2-3  # 2 or 3 times
<rule>0-6  # 0 to 6 times

لاحظ أنه يجب عليك استخدام الأقواس الزاوية إذا كنت تستخدم محددًا رقميًا:

rule8    # WRONG!  This would match rule "rule8".
rule2+   # WRONG!  This would match rule "rule2", 1 or more times.
rule2-3  # WRONG!  Pegex syntax error

هناك مجموعة خاصة من "الذرات" المعرفة مسبقًا التي تشير إلى أجزاء من التعبيرات العادية. توجد الذرات لكل حرف ترقيم ولكل الأحرف الموجودة عادةً في التعبيرات العادية. تعزز الذرات قابلية القراءة في نصوص القواعد، وتسمح باستخدام الأحرف الخاصة (مثل الشرطة المائلة أو علامة الهاش) كبناء جملة Pegex.

على سبيل المثال، قد يكون التعبير العادي لمطابقة تعليق هو '#' متبوعًا بأي شيء، متبوعًا بسطر جديد. في Pegex، ستكتب:

comment: / HASH ANY* EOL /

بدلاً من:

comment: /#.*\r?\n/

سيقوم Pegex بتجميع الأول في الأخير.

إليك بعض الذرات:

DASH    # -
PLUS    # +
TILDE   # ~
SLASH   # /
HASH    # # (literal)
QMARK   # ? (literal)
STAR    # * (literal)
LPAREN  # ( (literal)
RPAREN  # ) (literal)
WORD    # \w
WS      # \s

يمكن العثور على القائمة الكاملة في [مصدر الذرات |<https://metacpan.org/source/Pegex::Grammar::Atoms].>

Regexes

في Pegex، نسمي بناء الجملة للتعبير العادي "تعبير عادي". أي عندما يُستخدم المصطلح "تعبير عادي"، فإنه يشير إلى بناء جملة Pegex، وعندما يُستخدم المصطلح "تعبير عادي"، فإنه يشير إلى التعبير العادي الفعلي الذي يتم تجميعه فيه.

التعبير العادي هو سلسلة نصية داخل شرطات مائلة.

/regex/

يتبع بناء جملة التعبير العادي بشكل أساسي Perl، مع الاستثناءات التالية:

# Any rules in angle brackets are referenced in the regex
/ ( <rule1> | 'non_rule' ) /  # "non_rule" is interpreted literally
# The syntax implies a /x modifier, so whitespace and comments are
# ignored.
/ (
    rule1+   # Match rule1 one or more times
    |
    rule2
) /
# Whitespace is declared with dash and plus.
/ - rule3 + /  # - = \s*, + = \s+, etc.
# Any (?XX ) syntax can have the question mark removed
/ (: a | b ) /  # same as / (?: a | b ) /

Error Message

رسالة الخطأ هي سلسلة نصية داخل علامات اقتباس خلفية. إذا وصل المحلل إلى رسالة خطأ في القاعدة، فإنه يرمي خطأ تحليل بهذه الرسالة.

`error message`

Operators

عوامل Pegex بترتيب الأسبقية التنازلي هي: ALT، AND، و OR.

AND و OR هما الأكثر شيوعًا. يتم تمثيل AND بغياب عامل. كما في هذه القواعد:

r1: <a><b>
r2: a b

كلاهما متماثلان. إنهما يعنيان القاعدة "a" AND (متبوعة مباشرة بـ) القاعدة "b".

OR يعني المطابقة أحدهما أو الآخر.

r: a | b | c

يعني مطابقة القاعدة "a" OR القاعدة "b" OR القاعدة "c". يتم فحص القواعد بالترتيب وإذا تطابقت إحداها، يتم تخطي الأخريات.

ALT يعني التناوب. إنها طريقة لتحديد فاصل في قائمة.

r: a+ % b
