أوامر المصحح

تُستخدم أوامر المصحح (debugger) للتنقل عبر التعليمات البرمجية خطوة بخطوة، وفحص المتغيرات، وتحديد الأخطاء.

DB<4> v
6               'this' => qw(that),
7               'tom' => qw(and jerry),
8               'welcome' => q(Hello World),
9               'zip' => q(welcome),
10      );

في السطر رقم 4 يوجد مؤشر مفيد، يخبرك بمكانك الحالي. لرؤية المزيد من التعليمات البرمجية، اكتب 'v' مرة أخرى:

DB<4> v
8               'welcome' => q(Hello World),
9               'zip' => q(welcome),
10      );
11:     my @data = keys %data;
12:     print "All OK\n" if grep($key, keys %data);
13:     print "$data{$key}\n";
14:     print "done: '$data{$key}'\n";
15:     exit;

وإذا كنت ترغب في عرض السطر 5 مرة أخرى، اكتب 'l 5'، (لاحظ المسافة):

DB<4> l 5
5:      my %data = (

في هذه الحالة، لا يوجد الكثير لرؤيته، ولكن بالطبع عادة ما تكون هناك صفحات من الأشياء يجب اجتيازها، ويمكن أن يكون 'l' مفيدًا جدًا. لإعادة تعيين عرضك إلى السطر الذي سنقوم بتنفيذه قريبًا، اكتب نقطة مفردة '.':

DB<5> .
main::(./data_a:4):     my $key = 'welcome';

السطر المعروض هو السطر الذي سيتم تنفيذه التالي، لم يحدث ذلك بعد. لذا بينما يمكننا طباعة متغير باستخدام الحرف 'p'، في هذه المرحلة لن نحصل إلا على قيمة فارغة (غير محددة). ما نحتاج إلى القيام به هو التمرير عبر البيان التنفيذي التالي باستخدام 's':

DB<6> s
main::(./data_a:5):     my %data = (
main::(./data_a:6):             'this' => qw(that),
main::(./data_a:7):             'tom' => qw(and jerry),
main::(./data_a:8):             'welcome' => q(Hello World),
main::(./data_a:9):             'zip' => q(welcome),
main::(./data_a:10):    );

الآن يمكننا إلقاء نظرة على المتغير الأول ($key):

DB<7> p $key
welcome

السطر 13 هو حيث يحدث الإجراء، لذا دعنا نستمر في النزول إلى هناك عبر الحرف 'c'، والذي بالمناسبة، يدرج نقطة توقف 'مرة واحدة فقط' في السطر أو الروتين الفرعي المحدد:

DB<8> c 13
All OK
main::(./data_a:13):    print "$data{$key}\n";

لقد تجاوزنا التحقق الخاص بنا (حيث تمت طباعة 'All OK') وتوقفنا قبل جوهر مهمتنا. كان بإمكاننا محاولة طباعة زوج من المتغيرات لمعرفة ما يحدث:

DB<9> p $data{$key}

ليس هناك الكثير في الداخل، دعنا نلقي نظرة على الـ hash الخاص بنا:

DB<10> p %data
Hello Worldziptomandwelcomejerrywelcomethisthat
DB<11> p keys %data
Hello Worldtomwelcomejerrythis

حسنًا، هذا ليس سهل القراءة، وباستخدام الدليل المفيد (h h)، يبدو الأمر 'x' واعدًا:

DB<12> x %data
0  'Hello World'
1  'zip'
2  'tom'
3  'and'
4  'welcome'
5  undef
6  'jerry'
7  'welcome'
8  'this'
9  'that'

هذا ليس مفيدًا جدًا، هناك بعض عبارات 'welcome' في الداخل، ولكن لا يوجد مؤشر على أي منها مفاتيح، وأيها قيم، إنها مجرد قائمة مفروغة للمصفوفة، وفي هذه الحالة، ليست مفيدة بشكل خاص. الحيلة هنا هي استخدام مرجع لهيكل البيانات:

DB<13> x \%data
0  HASH(0x8194bc4)
   'Hello World' => 'zip'
   'jerry' => 'welcome'
   'this' => 'that'
   'tom' => 'and'
   'welcome' => undef

تم تفريغ المرجع حقًا ويمكننا أخيرًا رؤية ما نتعامل معه. كان الاقتباس الخاص بنا صالحًا تمامًا ولكنه خاطئ لأغراضنا، حيث تم التعامل مع 'and jerry' كـ 2 كلمتين منفصلتين بدلاً من عبارة، مما أدى إلى إخراج هيكل الـ hash الزوجي بالتساوي من المحاذاة.

كان مفتاح '-w' ليخبرنا بهذا، لو استخدمناه في البداية، وأنقذنا الكثير من المتاعب:

> perl -w data
Odd number of elements in hash assignment at ./data line 5.

نقوم بإصلاح الاقتباس الخاص بنا: 'tom' => q(and jerry)، ونشغله مرة أخرى، هذه المرة نحصل على الإخراج المتوقع:

> perl -w data
Hello World

بينما نحن هنا، ألق نظرة أقرب على الأمر 'x'، إنه مفيد حقًا وسيفرغ المراجع المتداخلة، والكائنات الكاملة، والكائنات الجزئية - أي شيء تقريبًا ترميه إليه:

دعنا ننشئ كائنًا سريعًا ونقوم بتفجيره، أولاً سنبدأ المصحح: إنه يريد شكلاً من أشكال الإدخال من STDIN، لذا نعطيه شيئًا غير ملتزم، صفرًا:

> perl -de 0
Default die handler restored.
Loading DB routines from perl5db.pl version 1.07
Editor support available.
Enter h or `h h' for help, or `man perldebug' for more help.
main::(-e:1):   0

الآن قم بإنشاء كائن في الوقت المناسب عبر سطرين (لاحظ الشرطة المائلة للخلف):

DB<1> $obj = bless({'unique_id'=>'123', 'attr'=> \
cont:  {'col' => 'black', 'things' => [qw(this that etc)]}}, 'MY_class')

ودعنا نلقي نظرة عليه:

       'things' => ARRAY(0x828abb8)
               0  'this'
               1  'that'

مفيد، أليس كذلك؟ يمكنك تقييم أي شيء تقريبًا هناك، وتجربة أجزاء من التعليمات البرمجية أو التعبيرات العادية حتى تعود الأبقار إلى المنزل:

DB<3> @data = qw(this that the other atheism leather theory scythe)
DB<4> p 'saw -> '.($cnt += map { print "\t:\t$_\n" } grep(/the/, sort @data))

إذا كنت تريد رؤية سجل الأوامر، اكتب 'H':

التمرير عبر التعليمات البرمجية

هذا برنامج بسيط يحول بين مئوية وفهرنهايت، وبه مشكلة أيضًا:

#!/usr/bin/perl
use v5.36;
my $arg = $ARGV[0] || '-c20';
if ($arg =~ /^\-(c|f)((\-|\+)*\d+(\.\d+)*)$/) {
       my ($deg, $num) = ($1, $2);
       my ($in, $out) = ($num, $num);
       if ($deg eq 'c') {
               $deg = 'f';
               $out = &c2f($num);
       } else {
               $deg = 'c';
               $out = &f2c($num);
       }
       $out = sprintf('%0.2f', $out);
       $out =~ s/^((\-|\+)*\d+)\.0+$/$1/;
       print "$out $deg\n";
} else {
       print "Usage: $0 -[c|f] num\n";
}
exit;
sub f2c {
       my $f = shift;
       my $c = 5 * $f - 32 / 9;
       return $c;
}
sub c2f {
       my $c = shift;
       my $f = 9 * $c / 5 + 32;
       return $f;
}

لسبب ما، فشل تحويل فهرنهايت إلى مئوية في إرجاع الإخراج المتوقع. هذا ما يفعله:

> temp -c0.72
33.30 f
> temp -f33.3
162.94 c

غير متسق على الإطلاق! سنضع نقطة توقف في التعليمات البرمجية يدويًا ونقوم بتشغيلها تحت المصحح لمعرفة ما يجري. نقطة التوقف هي علامة، سيقوم المصحح بالتشغيل إليها دون انقطاع، وعندما يصل إلى نقطة التوقف، سيتوقف التنفيذ وسيقدم مطالبة للتفاعل الإضافي. في الاستخدام العادي، يتم تجاهل أوامر المصحح هذه تمامًا، وهي آمنة - وإن كانت فوضوية بعض الشيء - لتركها في كود الإنتاج.

my ($in, $out) = ($num, $num);
$DB::single=2; # insert at line 9!
if ($deg eq 'c')
        ...
> perl -d temp -f33.3
Default die handler restored.
Loading DB routines from perl5db.pl version 1.07
Editor support available.
Enter h or `h h' for help, or `man perldebug' for more help.
main::(temp:4): my $arg = $ARGV[0] || '-c100';

DB<1> c
main::(temp:10):                if ($deg eq 'c') {

متبوعًا بأمر عرض لرؤية مكاننا:

DB<1> v
7:              my ($deg, $num) = ($1, $2);
8:              my ($in, $out) = ($num, $num);
9:              $DB::single=2;

وطباعة لعرض القيم التي نستخدمها حاليًا:

DB<1> p $deg, $num
f33.3

يمكننا وضع نقطة توقف أخرى على أي سطر يبدأ بنقطتين رأسيتين، سنستخدم السطر 17 لأنه فور خروجنا من الروتين الفرعي، ونود التوقف هناك لاحقًا:

DB<2> b 17

لا يوجد رد فعل على هذا، ولكن يمكنك رؤية نقاط التوقف التي تم تعيينها باستخدام أمر القائمة 'L':

DB<3> L
temp:
        17:            print "$out $deg\n";
        break if (1)

لاحظ أن لحذف نقطة توقف استخدم 'B'.

لاحظ أنه إذا كان هناك استدعاء لروتين فرعي بيننا وبين السطر 29، وأردنا التمرير خطوة بخطوة خلاله، يمكننا استخدام أمر 's'، وللتمرير فوقه سنستخدم 'n' والذي سيقوم بتنفيذ الروتين الفرعي، ولكنه لن ينزل فيه للفحص. في هذه الحالة، سنستمر ببساطة إلى السطر 29:

DB<4> c 29
main::f2c(temp:29):             return $c;

ولإلقاء نظرة على القيمة المرجعة:

DB<5> p $c
162.944444444444

هذه ليست الإجابة الصحيحة على الإطلاق، ولكن المجموع يبدو صحيحًا. أتساءل عما إذا كان له علاقة بترتيب العمليات؟ سنحاول إمكانيات أخرى مع مجموعنا:

DB<6> p (5 * $f - 32 / 9)

DB<7> p 5 * $f - (32 / 9)
162.944444444444
DB<8> p (5 * $f) - 32 / 9
162.944444444444
DB<9> p 5 * ($f - 32) / 9
0.722222222222221

:-) هذا أقرب! حسنًا، الآن يمكننا تعيين متغير الإرجاع وسنعود من الروتين الفرعي باستخدام 'r':

DB<10> $c = 5 * ($f - 32) / 9
DB<11> r
scalar context return from main::f2c: 0.722222222222221

نصائح الإخراج

للحصول على كل المخرجات من سجل الأخطاء الخاص بك، وعدم تفويت أي رسائل عبر تخزين نظام التشغيل المؤقت المفيد، قم بإدراج سطر مثل هذا في بداية البرنامج النصي الخاص بك:

$|=1;

لمشاهدة ذيل ملف سجل ينمو ديناميكيًا، (من سطر الأوامر):

tail -f $error_log

يمكن أن يكون تغليف جميع استدعاءات die في روتين معالج مفيدًا لرؤية كيف وأين يتم استدعاؤها، perlvar لديه المزيد من المعلومات:

BEGIN { $SIG{__DIE__} = sub { require Carp; Carp::confess(@_) } }

تم شرح تقنيات مختلفة مفيدة لإعادة توجيه مقبض ملفات STDOUT و STDERR في perlopentut و perlfaq8.

CGI

مجرد تلميح سريع هنا لجميع مبرمجي CGI الذين لا يستطيعون فهم كيفية تجاوز مطالبة "الانتظار للإدخال"، عند تشغيل برنامج CGI النصي الخاص بهم من سطر الأوامر، جرب شيئًا مثل هذا:

> perl -d my_cgi.pl -nodebug

بالطبع، سيخبرك CGI و perlfaq9 بالمزيد.

واجهات المستخدم الرسومية

تم دمج واجهة سطر الأوامر بإحكام مع امتداد emacs وهناك واجهة vi أيضًا.

لست مضطرًا للقيام بكل هذا على سطر الأوامر، على الرغم من ذلك، هناك بعض خيارات واجهة المستخدم الرسومية المتاحة. الشيء الجيد في هذه الواجهات هو أنه يمكنك تمرير مؤشر الفأرة فوق متغير وسيظهر تفريغ لبياناته في نافذة مناسبة، أو في فقاعة منبثقة، لا مزيد من الكتابة المرهقة لـ 'x $varname' :-)

بشكل خاص، ابحث عن ما يلي:

ptkdb غلاف يعتمد على perlTK للمصحح المدمج

ddd مصحح عرض البيانات

PerlDevKit و PerlBuilder خاصان بنظام NT

ملاحظة. (المزيد من المعلومات حول هذه وغيرها موضع تقدير).

ملخص

لقد رأينا كيف نشجع ممارسات الترميز الجيدة باستخدام use strict و -w. يمكننا تشغيل مصحح Perl perl -d scriptname لفحص بياناتك من داخل مصحح Perl باستخدام الأوامر p و x. يمكنك التجول في الكود الخاص بك، وتعيين نقاط توقف باستخدام b والتجول في هذا الكود باستخدام s أو n، والمتابعة باستخدام c والعودة من دالة فرعية باستخدام r. أشياء بديهية إلى حد ما عندما تتعمق فيها.

هناك بالطبع الكثير لاكتشافه، هذا مجرد خدش للسطح. أفضل طريقة لمعرفة المزيد هي استخدام perldoc لمعرفة المزيد عن اللغة، وقراءة المساعدة عبر الإنترنت (perldebug ربما هو المكان التالي للذهاب)، وبالطبع، التجربة.
