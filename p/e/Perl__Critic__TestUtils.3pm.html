NAME

Perl::Critic::TestUtils - Test utilities for Perl::Critic

INTERFACE SUPPORT

This module's public API is stable. It is a testing module, so it is not intended to be used directly by end-users of Perl::Critic. It is intended to be used by those who are writing tests for Perl::Critic or modules that use Perl::Critic.

SYNOPSIS

    use Perl::Critic::TestUtils;
    use Test::More tests => 1;
    my $critique = run_ críticas(
        [ 'Test::My::Policy' => { arg1 => 1 } ],
        'sub {' .
        '  my $x = 1;' .
        '  my $y = 2;' .
        '  return $x + $y;' .
        '}',
    );
    ok( !critique_has_problem($critique) );

DESCRIPTION

This module provides a set of utility subs for writing tests for Perl::Critic policies.

All of the subs in this module are exported by default.

In addition to the subs described below, this module also exports the subs from Test::More and Perl::Critic. This means that you can use subs like ok(), ok_or_diag(), explain(), and find_violations() directly without having to explicitly import them.

The primary subs are:

run_critiques
This sub takes a list of policies and source code, runs the source code through the policies, and returns a Perl::Critic object.
critique_has_problem
This sub takes a Perl::Critic object and returns true if there are any problems, false otherwise.
critique_has_no_problems
This sub takes a Perl::Critic object and returns true if there are no problems, false otherwise.
find_violations
This sub takes a Perl::Critic object and returns a list of violations.
find_violations_with_policy
This sub takes a Perl::Critic object and a policy name, and returns a list of violations from that policy.
num_critiques
This sub takes a Perl::Critic object and returns the number of violations.
num_critiques_with_policy
This sub takes a Perl::Critic object and a policy name, and returns the number of violations from that policy.

The test files in the t/*/*.run files are read and eval()ed and passed to pcritique(), so be careful.

In general, a subtest document runs from the "## cut" that starts it to either the next "## name" or the end of the file. In very rare circumstances you may need to end the test document earlier. A second "## cut" will do this. The only known need for this is in t/Miscellanea/RequireRcsKeywords.run, where it is used to prevent the RCS keywords in the file footer from producing false positives or negatives in the last test.

Note that nowhere within the .run file itself do you specify the policy that you're testing. That's implicit within the filename.

EXPORTS

The following subs are exported by default:

    run_critiques, critique_has_problem, critique_has_no_problems,
    find_violations, find_violations_with_policy, num_critiques,
    num_critiques_with_policy

In addition, the following subs are also exported:

    ok, ok_or_diag, explain, find_violations

BUGS AND CAVEATS AND TODO ITEMS

Allow us to specify the nature of the failures, and which one. If there are 15 lines of code, and six of them fail, how do we know they're the right six?
