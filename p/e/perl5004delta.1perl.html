الاسم

perl5004delta - ما هو الجديد في perl5.004

الوصف

تصف هذه الوثيقة الاختلافات بين الإصدار 5.003 (كما هو موثق في Programming Perl، الطبعة الثانية - كتاب الجمل) وهذا الإصدار.

البيئات المدعومة

يتم بناء Perl5.004 جاهزًا للتشغيل على Unix، و Plan 9، و LynxOS، و VMS، و OS/2، و QNX، و AmigaOS، و Windows NT. يعمل Perl أيضًا على Windows 95، ولكن لا يمكن بناؤه هناك، لعدم وجود مترجم أوامر مناسب.

التغييرات الأساسية

الأهم من ذلك، تم إصلاح العديد من الأخطاء، بما في ذلك العديد من مشاكل الأمان. انظر ملف Changes في التوزيع للحصول على التفاصيل.

تعيين القائمة إلى %ENV يعمل

"%ENV = ()" و "%ENV = @list" تعملان الآن كما هو متوقع (باستثناء VMS حيث ينتج عنه خطأ قاتل).

تغيير في خطأ "لا يمكن العثور على Foo.pm في @INC"

الخطأ "لا يمكن العثور على Foo.pm في @INC" يسرد الآن محتويات @INC لتسهيل تصحيح الأخطاء.

خيار الترجمة: التوافق الثنائي مع 5.003

هناك سؤال تهيئة جديد يسأل عما إذا كنت تريد الحفاظ على التوافق الثنائي مع Perl 5.003. إذا اخترت التوافق الثنائي، فلن تضطر إلى إعادة ترجمة ملحقاتك، ولكن قد تواجه تعارضات في الرموز إذا قمت بتضمين Perl في تطبيق آخر، تمامًا كما في الإصدار 5.003. افتراضيًا، يتم الحفاظ على التوافق الثنائي على حساب تلوث جدول الرموز.

متغير البيئة $PERL5OPT

يمكنك الآن وضع خيارات Perl في متغير البيئة $PERL5OPT. ما لم يكن Perl يعمل مع فحوصات التلطيخ، فسيقوم بتفسير هذا المتغير كما لو كانت محتوياته قد ظهرت في سطر "#!perl" في بداية البرنامج النصي الخاص بك، باستثناء أن الشرطات اختيارية. يمكن استخدام PERL5OPT فقط لتعيين المفاتيح التالية: -[DIMUdmw].

قيود على خيارات -M و -m و -T

لم يعد مسموحًا بخيارات "-M" و "-m" في سطر "#!" للبرنامج النصي. إذا احتاج برنامج نصي إلى وحدة، فيجب عليه استدعاؤها باستخدام الـ pragma "use".

يُمنع أيضًا خيار -T في سطر "#!" لبرنامج نصي، ما لم يكن موجودًا في سطر أوامر Perl. نظرًا للطريقة التي تعمل بها "#!"، هذا يعني عادةً أنه يجب أن يكون -T في الوسيط الأول. وبالتالي:

#!/usr/bin/perl -T -w

قد يعمل هذا البرنامج النصي القابل للتنفيذ عند استدعائه باسم "scriptname"، بينما:

#!/usr/bin/perl -w -T

قد يفشل في ظل نفس الظروف. (أنظمة غير Unix قد لا تتبع هذه القاعدة.) ولكن "perl scriptname" مضمون الفشل، حيث لن تكون هناك فرصة للعثور على -T في سطر الأوامر قبل العثور عليه في سطر "#!".

تحذيرات أكثر دقة

إذا قمت بإزالة خيار -w من نصوص Perl 5.003 الخاصة بك لأنه جعل Perl كثير الكلام، فإننا نوصيك بإعادته عند الترقية إلى Perl 5.004. يميل كل إصدار جديد من Perl إلى إزالة بعض التحذيرات غير المرغوب فيها، مع إضافة تحذيرات جديدة قد تلتقط الأخطاء في نصوصك.

مهمل: "AUTOLOAD" الموروث لغير الوظائف

قبل Perl 5.004، تم البحث عن وظائف "AUTOLOAD" كـ methods (باستخدام التسلسل الهرمي لـ @ISA)، حتى عندما تم استدعاء الوظيفة المراد تحميلها تلقائيًا كـ وظيفة عادية (مثل Foo::bar())، وليس كـ method (مثل "Foo->bar()" أو "$obj->bar()").

سيستخدم Perl 5.005 البحث عن methods فقط لـ "AUTOLOAD" الخاصة بالـ methods. ومع ذلك، هناك قاعدة أساسية كبيرة من التعليمات البرمجية الحالية التي قد تستخدم السلوك القديم. لذلك، كخطوة انتقالية، يصدر Perl 5.004 تحذيرًا اختياريًا عند استخدام وظيفة غير method لـ "AUTOLOAD" موروثة.

القاعدة البسيطة هي: لن يعمل الوراثة عند التحميل التلقائي لغير الوظائف. الحل البسيط للتعليمات البرمجية القديمة هو: في أي وحدة كانت تعتمد سابقًا على وراثة "AUTOLOAD" لغير الوظائف من فئة أساسية تسمى "BaseClass"، قم بتنفيذ "*AUTOLOAD = \&BaseClass::AUTOLOAD" أثناء بدء التشغيل.

%OVERLOAD الذي تم إهماله سابقًا لم يعد قابلاً للاستخدام

كان استخدام %OVERLOAD لتعريف التجاوز مهملاً في 5.003. يتم الآن تعريف التجاوز باستخدام pragma overload. لا يزال %OVERLOAD يستخدم داخليًا ولكن لا ينبغي استخدامه بواسطة برامج Perl النصية. انظر overload لمزيد من التفاصيل.

يتم إنشاء وسيطات الإجراء الفرعي فقط عند تعديلها

في Perl 5.004، يتم إنشاء عناصر المصفوفة والجدول غير الموجودة المستخدمة كوسائط للإجراء الفرعي فقط إذا تم تعيين قيمة لها بالفعل (عبر @_).

تختلف إصدارات Perl السابقة في معالجتها لهذه الوسائط. كانت إصدارات Perl 5.002 و 5.003 تنشئها دائمًا. كانت إصدارات Perl 5.000 و 5.001 تنشئها فقط إذا لم تكن الوسيط الأول (والتي كانت على الأرجح خطأ). لم تنشئها إصدارات Perl السابقة مطلقًا.

على سبيل المثال، بالنظر إلى هذا الكود:

undef @a; undef %a;
sub show { print $_[0] };
sub change { $_[0]++ };
show($a[2]);
change($a{b});

بعد تنفيذ هذا الكود في Perl 5.004، يوجد $a{b} ولكن $a[2] لا يوجد. في Perl 5.002 و 5.003، كان كل من $a{b} و $a[2] موجودين (لكن قيمة $a[2] كانت غير محددة).

متجه المجموعة قابل للتغيير باستخدام $)

المتغير الخاص $) كان دائمًا (حسنًا، في Perl 5 على الأقل) يعكس ليس فقط المجموعة الفعالة الحالية، ولكن أيضًا قائمة المجموعات كما تم إرجاعها بواسطة دالة C getgroups() (إذا كانت موجودة). ومع ذلك، حتى هذا الإصدار، لم تكن هناك طريقة لاستدعاء دالة C setgroups() من Perl.

في Perl 5.004، يعكس التعيين إلى $) بشكل متماثل تمامًا مع فحصه: يتم استخدام الرقم الأول في قيمته النصية كـ gid فعال؛ إذا كانت هناك أرقام بعد الرقم الأول، يتم تمريرها إلى دالة C setgroups() (إذا كانت موجودة).

تم إصلاح تحليل $$<digit>، &$<digit>، إلخ.

في الإصدارات السابقة من Perl، كان يتم التعامل مع الحروف التي تبدأ برقم بعد $ أو @ على أنها معرفات متغيرة (مثل $1، @2) بدلاً من علامات التنصيص (مثل "$1"، "@2"). تم إصلاح هذا للسلوك الصحيح.

مفاتيح كقيمة يسارية (lvalue)
كقيمة يسارية (lvalue)، يسمح لك "keys" بزيادة عدد دلاء التجزئة المخصصة للتجزئة المعطاة. يمكن أن يمنحك هذا قدرًا من الكفاءة إذا كنت تعلم أن التجزئة ستصبح كبيرة. (هذا مشابه للتوسيع المسبق لمصفوفة عن طريق تعيين رقم أكبر لـ $#array.) إذا قلت 
keys %hash = 200;

فسيتم تخصيص 200 دلو على الأقل لـ %hash. سيتم الاحتفاظ بهذه الدلاء حتى لو قمت بتنفيذ "%hash = ()"؛ استخدم undef %hash إذا كنت تريد تحرير التخزين بينما لا يزال %hash ضمن النطاق. لا يمكنك تقليص عدد الدلاء المخصصة للتجزئة باستخدام "keys" بهذه الطريقة (ولكن لا داعي للقلق بشأن القيام بذلك عن طريق الخطأ، حيث أن المحاولة لا يكون لها أي تأثير).

my() في هياكل التحكم
يمكنك الآن استخدام my() (مع أو بدون الأقواس) في تعبيرات التحكم للهياكل التحكم مثل: 
while (defined(my $line = <>)) {
    $line = lc $line;
} continue {
    print $line;
}
if ((my $answer = <STDIN>) =~ /^y(es)?$/i) {
    user_agrees();
} elsif ($answer =~ /^n(o)?$/i) {
    user_disagrees();
} else {
    chomp $answer;
    die "`$answer' is neither `yes' nor `no'";
}

أيضًا، يمكنك الإعلان عن متغير تحكم في حلقة foreach كمتغير موضعي (lexical) عن طريق وضعه مسبقًا بكلمة "my". على سبيل المثال، في:

foreach my $i (1, 2, 3) {
    some_function();
}

$i هو متغير موضعي، ويمتد نطاق $i إلى نهاية الحلقة، ولكن ليس بعدها.

لاحظ أنه لا يزال يتعذر عليك استخدام my() على المتغيرات الرمزية العالمية مثل $_ وما شابه.

pack() و unpack()
يمثل تنسيق 'w' الجديد عددًا صحيحًا مضغوطًا بصيغة BER (كما هو محدد في ASN.1). تنسيقه هو تسلسل من بايت واحد أو أكثر، كل منها يوفر سبعة بتات للقيمة الإجمالية، مع كون البت الأكثر أهمية أولاً. يتم تعيين البت الثامن لكل بايت، باستثناء البايت الأخير، الذي يكون فيه البت الثامن واضحًا.

إذا تم إعطاء 'p' أو 'P' قيمة undef، فإنهما ينتجان الآن مؤشر NULL.

كل من pack() و unpack() تفشل الآن عندما تحتوي قوالبها على أنواع غير صالحة. (تم تجاهل الأنواع غير الصالحة في السابق.)

sysseek()
العامل الجديد sysseek() هو نوع فرعي من seek() يقوم بتعيين واسترداد موضع القراءة/الكتابة للنظام للملف، باستخدام استدعاء النظام lseek(2). إنها الطريقة الوحيدة الموثوقة للبحث قبل استخدام sysread() أو syswrite(). قيمتها المرجعة هي الموضع الجديد، أو القيمة غير المعرفة عند الفشل.
استخدام VERSION
إذا كان المعامل الأول لـ "use" هو رقم، فسيتم التعامل معه كرقم إصدار بدلاً من اسم وحدة. إذا كان إصدار مترجم Perl أقل من VERSION، فسيتم طباعة رسالة خطأ وسيخرج Perl فورًا. نظرًا لأن "use" يحدث في وقت الترجمة، يتم إجراء هذا الفحص فورًا أثناء عملية الترجمة، على عكس "require VERSION"، الذي ينتظر حتى وقت التشغيل لإجراء الفحص. هذا مفيد غالبًا إذا كنت بحاجة إلى التحقق من إصدار Perl الحالي قبل "use" وحدات المكتبة التي تغيرت بطرق غير متوافقة من إصدارات أقدم من Perl. (نحن نحاول ألا نفعل ذلك أكثر من اللازم.)
استخدام Module VERSION LIST
إذا كان المعامل VERSION موجودًا بين Module و LIST، فإن "use" ستستدعي الطريقة VERSION في الفئة Module مع الإصدار المحدد كمعامل. الطريقة الافتراضية VERSION، الموروثة من الفئة UNIVERSAL، تموت إذا كان الإصدار المحدد أكبر من قيمة المتغير $Module::VERSION. (لاحظ أنه لا توجد فاصلة بعد VERSION!)

آلية التحقق من الإصدار هذه مشابهة لتلك المستخدمة حاليًا في وحدة Exporter، ولكنها أسرع ويمكن استخدامها مع الوحدات التي لا تستخدم Exporter. إنها الطريقة الموصى بها للكود الجديد.

prototype(FUNCTION)
يعيد النموذج الأولي لدالة كسلسلة نصية (أو "undef" إذا لم يكن للدالة نموذج أولي). FUNCTION هو مرجع أو اسم الدالة التي تريد استرداد نموذجها الأولي. (ليس جديدًا في الواقع؛ لم يتم توثيقه من قبل.)
srand
تم تغيير قيمة البذرة الافتراضية لـ "srand"، والتي كانت سابقًا "time". الآن هي مزيج قوي من القيم التي يصعب التنبؤ بها وتعتمد على النظام، والتي ينبغي أن تكون كافية لمعظم الاستخدامات اليومية.

قبل الإصدار 5.004، كان استدعاء "rand" دون استدعاء "srand" أولاً ينتج نفس تسلسل الأرقام العشوائية على معظم أو كل الآلات. الآن، عندما ترى perl أنك تستدعي "rand" ولم تقم بعد باستدعاء "srand"، فإنها تستدعي "srand" بقيمة البذرة الافتراضية. لا يزال يتعين عليك استدعاء "srand" يدويًا إذا كان من الممكن تشغيل الكود الخاص بك على نظام أقدم من 5.004، بالطبع، أو إذا كنت تريد قيمة بذرة بخلاف الافتراضية.

$_ كافتراضي
الدوال الموثقة في Camel (الجمل) تفترض افتراضيًا $_ الآن في الواقع، وجميع تلك الدوال التي تقوم بذلك موثقة في perlfunc.
"m//gc" لا تعيد تعيين موضع البحث عند الفشل
كان بناء جملة تكرار المطابقة "m//g" يعيد دائمًا تعيين موضع بحث سلسلة الهدف (الذي يمكن رؤيته من خلال عامل "pos") عند فشل المطابقة؛ ونتيجة لذلك، تبدأ مطابقة "m//g" التالية بعد فشل من بداية السلسلة. مع Perl 5.004، يمكن تعطيل هذه الميزة عن طريق إضافة المعدل "c" (لـ "continue")، أي "m//gc". هذه الميزة، بالاقتران مع التأكيد الصفري العرض "\G"، تجعل من الممكن ربط التطابقات معًا. انظر perlop و perlre.
"m//x" تتجاهل المسافات البيضاء قبل ?*+{}
كان بناء جملة "m//x" يهدف دائمًا إلى تجاهل جميع المسافات البيضاء غير المهروة. ومع ذلك، قبل Perl 5.004، كان للمسافات البيضاء تأثير الهروب من معدلات التكرار مثل "*" أو "?"؛ على سبيل المثال، تم تفسير "/a *b/x" (بشكل خاطئ) على أنه "/a\*b/x". تم إصلاح هذا الخطأ في 5.004.
عمل الإغلاقات المتداخلة "sub{}" الآن
قبل إصدار 5.004، لم تكن الدوال المجهولة المتداخلة تعمل بشكل صحيح. إنها تعمل الآن.
عمل التنسيقات بشكل صحيح على المتغيرات الموضعية المتغيرة
تمامًا مثل الدوال المجهولة التي تحتوي على متغيرات موضعية تتغير (مثل متغير فهرس موضعي لحلقة "foreach")، تعمل التنسيقات الآن بشكل صحيح. على سبيل المثال، فشلت هذه بشكل صامت من قبل (طبعت فقط الأصفار)، ولكنها جيدة الآن: 
my $i;
foreach $i ( 1 .. 10 ) {
    write;
}
format =
    my i is @#
    $i
.

ومع ذلك، لا يزال يفشل (بدون تحذير) إذا كان foreach داخل روتين فرعي:

my $i;
sub foo {
  foreach $i ( 1 .. 10 ) {
    write;
  }
}
foo;
format =
    my i is @#
    $i
.

طرق مضمنة جديدة

تحتوي الحزمة "UNIVERSAL" تلقائيًا على الطرق التالية التي ترثها جميع الفئات الأخرى:

isa(CLASS)
"isa" يعيد صحيح إذا كان كائنه مخصصًا لفئة فرعية من "CLASS"

"isa" يمكن تصديره أيضًا ويمكن استدعاؤه كدالة فرعية بمعاملين. هذا يسمح بالقدرة على التحقق مما يشير إليه المرجع. مثال:

use UNIVERSAL qw(isa);
if(isa($ref, 'ARRAY')) {
   ...
}
can(METHOD)
"can" يتحقق مما إذا كان كائنه يحتوي على طريقة تسمى "METHOD"، إذا كان الأمر كذلك، فسيتم إرجاع مرجع للدالة الفرعية؛ إذا لم يكن كذلك، فسيتم إرجاع undef.
VERSION( [NEED] )
"VERSION" يعيد رقم إصدار الفئة (الحزمة). إذا تم توفير المعامل NEED، فسيتحقق من أن الإصدار الحالي (كما هو محدد بواسطة المتغير $VERSION في الحزمة المعطاة) ليس أقل من NEED؛ سيموت إذا لم يكن الأمر كذلك. يتم استدعاء هذه الطريقة عادةً كطريقة فئة. يتم استدعاء هذه الطريقة تلقائيًا بواسطة نموذج "VERSION" لـ

New Perl API Functions

"perl_eval_pv"
A new function handy for eval'ing strings of Perl code inside C code. This function returns the value from the eval statement, which can be used instead of fetching globals from the symbol table. See perlguts, perlembed and perlcall for details and examples.
Extended API for manipulating hashes
Internal handling of hash keys has changed. The old hashtable API is still fully supported, and will likely remain so. The additions to the API allow passing keys as "SV*"s, so that "tied" hashes can be given real scalars as keys rather than plain strings (nontied hashes still can only use strings as keys). New extensions must use the new hash access functions and macros if they wish to use "SV*" keys. These additions also make it feasible to manipulate "HE*"s (hash entries), which can be more efficient. See perlguts for details.

New Diagnostics

Several new conditions will trigger warnings that were silent before. Some only affect certain platforms. The following new warnings and errors outline these. These messages are classified as follows (listed in increasing order of desperation):

(W) A warning (optional).
(D) A deprecation (optional).
(S) A severe warning (mandatory).
(F) A fatal error (trappable).
(P) An internal error you should never see (trappable).
(X) A very fatal error (nontrappable).
(A) An alien error message (not generated by Perl).
"my" variable %s masks earlier declaration in same scope
(W) A lexical variable has been redeclared in the same scope, effectively eliminating all access to the previous instance. This is almost always a typographical error. Note that the earlier variable will still exist until the end of the scope or until all closure referents to it are destroyed.
%s argument is not a HASH element or slice
(F) The argument to delete() must be either a hash element, such as 
$foo{$bar}
$ref->[12]->{"susie"}

or a hash slice, such as

@foo{$bar, $baz, $xyzzy}
@{$ref->[12]}{"susie", "queue"}
Allocation too large: %lx
(X) You can't allocate more than 64K on an MS-DOS machine.
Allocation too large
(F) You can't allocate more than 2^31+"small amount" bytes.
Applying %s to %s will act on scalar(%s)
(W) The pattern match (//), substitution (s///), and transliteration (tr///) operators work on scalar values. If you apply one of them to an array or a hash, it will convert the array or hash to a scalar value (the length of an array or the population info of a hash) and then work on that scalar value. This is probably not what you meant to do. See "grep" in perlfunc and "map" in perlfunc for alternatives.
Attempt to free nonexistent shared string
(P) Perl maintains a reference counted internal table of strings to optimize the storage and access of hash keys and other strings. This indicates someone tried to decrement the reference count of a string that can no longer be found in the table.
Attempt to use reference as lvalue in substr
(W) You supplied a reference as the first argument to substr() used as an lvalue, which is pretty strange. Perhaps you forgot to dereference it first. See "substr" in perlfunc.
Bareword "%s" refers to nonexistent package
(W) You used a qualified bareword of the form "Foo::", but the compiler saw no other uses of that namespace before that point. Perhaps you need to predeclare a package?
Can't redefine active sort subroutine %s
(F) Perl optimizes the internal handling of sort subroutines and keeps pointers into them. You tried to redefine one such sort subroutine when it was currently active, which is not allowed. If you really want to do this, you should write "sort { &func } @x" instead of "sort func @x".
Can't use bareword ("%s") as %s ref while "strict refs" in use
(F) Only hard references are allowed by "strict refs". Symbolic references are disallowed. See perlref.
Cannot resolve method `%s' overloading `%s' in package `%s'
(P) Internal error trying to resolve overloading specified by a method name (as opposed to a subroutine reference).
Constant subroutine %s redefined
(S) You redefined a subroutine which had previously been eligible for inlining. See "Constant Functions" in perlsub for commentary and workarounds.
Constant subroutine %s undefined
(S) You undefined a subroutine which had previously been eligible for inlining. See "Constant Functions" in perlsub for commentary and workarounds.
Copy method did not return a reference
(F) The method which overloads "=" is buggy. See "Copy Constructor" in overload.
Died
(F) You passed die() an empty string (the equivalent of "die """) or you called it with no args and both $@ and $_ were empty.
Exiting pseudo-block via %s
(W) You are exiting a rather special block construct (like a sort block or subroutine) by unconventional means, such as a goto, or a loop control statement. See "sort" in perlfunc.
Identifier too long
(F) Perl limits identifiers (names for variables, functions, etc.) to 252 characters for simple names, somewhat more for compound names (like $A::B). You've exceeded Perl's limits. Future versions of Perl are likely to eliminate these arbitrary limitations.
Illegal character %s (carriage return)
(F) A carriage return character was found in the input. This is an error, and not a warning, because carriage return characters can break multi-line strings, including here documents (e.g., "print <<EOF;").
Illegal switch in PERL5OPT: %s
(X) The PERL5OPT environment variable may only be used to set the following switches: -[DIMUdmw].
Integer overflow in hex number
(S) The literal hex number you have specified is too big for your architecture. On a 32-bit architecture the largest hex literal is 0xFFFFFFFF.
Integer overflow in octal number
(S) The literal octal number you have specified is too big for your architecture. On a 32-bit architecture the largest octal literal is 037777777777.
internal error: glob failed
(P) Something went wrong with the external program(s) used for "glob" and "<*.c>". This may mean that your csh (C shell) is broken. If so, you should change all of the csh-related variables in config.sh: If you have tcsh, make the variables refer to it as if it were csh (e.g. "full_csh='/usr/bin/tcsh'"); otherwise, make them all empty (except that "d_csh" should be 'undef') so that Perl will think csh is missing. In either case, after editing config.sh, run "./Configure -S" and rebuild Perl.
Invalid conversion in %s: "%s"
(W) Perl does not understand the given format conversion. See "sprintf" in perlfunc.
Invalid type in pack: '%s'
(F) The given character is not a valid pack type. See "pack" in perlfunc.
Invalid type in unpack: '%s'
(F) The given character is not a valid unpack type. See "unpack" in perlfunc.
Name "%s::%s" used only once: possible typo
(W) Typographical errors often show up as unique variable names. If you had a good reason for having a unique name, then just mention it again somehow to suppress the message (the "use vars" pragma is provided for just this purpose).
