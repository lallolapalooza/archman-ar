الاسم

perf_event_open - إعداد مراقبة الأداء

المكتبة

مكتبة C القياسية (libc، -lc)

الملخص

#include <linux/perf_event.h>    /* تعريف ثوابت PERF_* */
#include <linux/hw_breakpoint.h> /* تعريف ثوابت HW_* */
#include <sys/syscall.h>         /* تعريف ثوابت SYS_* */
#include <unistd.h>
int syscall(SYS_perf_event_open, struct perf_event_attr *attr,
            pid_t pid, int cpu, int group_fd, unsigned long flags);

ملاحظة: لا توفر glibc غلافًا لـ perf_event_open()، مما يستلزم استخدام syscall(2).

الوصف

بالنظر إلى قائمة من المعلمات، تعيد perf_event_open() واصف ملف، لاستخدامه في استدعاءات النظام اللاحقة (read(2)، mmap(2)، prctl(2)، fcntl(2)، إلخ).

يقوم استدعاء perf_event_open() بإنشاء واصف ملف يسمح بقياس معلومات الأداء. يتوافق كل واصف ملف مع حدث واحد يتم قياسه؛ يمكن تجميع هذه الأحداث لقياس أحداث متعددة في نفس الوقت.

يمكن تمكين الأحداث وتعطيلها بطريقتين: عبر ioctl(2) وعبر prctl(2). عندما يتم تعطيل حدث ما، فإنه لا يعد أو يولد تجاوزات ولكنه يستمر في الوجود والحفاظ على قيمة عدّه.

تأتي الأحداث بنكهتين: عدّ وأخذ عينات. الحدث العدّ هو حدث يستخدم لعد العدد الإجمالي للأحداث التي تحدث. بشكل عام، يتم جمع نتائج حدث العدّ باستدعاء read(2). يقوم حدث أخذ العينات بكتابة القياسات بشكل دوري إلى مخزن مؤقت يمكن الوصول إليه بعد ذلك عبر mmap(2).

المعلمات

تسمح المعلمتان pid و cpu بتحديد العملية ووحدة المعالجة المركزية المراد مراقبتها:

pid == 0 و cpu == -1
يقيس هذا العملية/الخيط المتصل على أي وحدة معالجة مركزية.
pid == 0 و cpu >= 0
يقيس هذا العملية/الخيط المتصل فقط عند تشغيله على وحدة المعالجة المركزية المحددة.
pid > 0 و cpu == -1
يقيس هذا العملية/الخيط المحدد على أي وحدة معالجة مركزية.
pid > 0 و cpu >= 0
يقيس هذا العملية/الخيط المحدد فقط عند تشغيله على وحدة المعالجة المركزية المحددة.
pid == -1 و cpu >= 0
يقيس هذا جميع العمليات/الخيوط على وحدة المعالجة المركزية المحددة. يتطلب هذا صلاحية CAP_PERFMON (منذ Linux 5.8) أو CAP_SYS_ADMIN أو قيمة /proc/sys/kernel/perf_event_paranoid أقل من 1.
pid == -1 و cpu == -1
هذا الإعداد غير صالح وسيعيد خطأ.

عندما تكون pid أكبر من صفر، يتم تنظيم الإذن بتنفيذ استدعاء النظام هذا بواسطة CAP_PERFMON (منذ Linux 5.9) وفحص وضع الوصول ptrace PTRACE_MODE_READ_REALCREDS على إصدارات Linux الأقدم؛ انظر ptrace(2).

تسمح المعلمة group_fd بإنشاء مجموعات أحداث. تحتوي مجموعة الأحداث على حدث واحد هو قائد المجموعة. يتم إنشاء القائد أولاً، مع group_fd = -1. يتم إنشاء بقية أعضاء المجموعة باستدعاءات perf_event_open() لاحقة مع تعيين group_fd إلى واصف ملف قائد المجموعة. (يتم إنشاء حدث واحد بمفرده مع group_fd = -1 ويعتبر مجموعة واحدة بها عضو واحد.) يتم جدولة مجموعة الأحداث على وحدة المعالجة المركزية كوحدة واحدة: سيتم وضعها على وحدة المعالجة المركزية فقط إذا كان يمكن وضع جميع الأحداث في المجموعة على وحدة المعالجة المركزية. هذا يعني أنه يمكن مقارنة قيم أحداث الأعضاء بشكل هادف - إضافتها، قسمتها (للحصول على نسب)، وما إلى ذلك - مع بعضها البعض، لأنها عدّت الأحداث لنفس مجموعة التعليمات المُنفذة.

يتم تشكيل المعلمة flags عن طريق ORing صفرًا أو أكثر من القيم التالية:

PERF_FLAG_FD_CLOEXEC (منذ Linux 3.14)
يُمكّن هذا العلم علم الإغلاق عند التنفيذ لواصف ملف الحدث المُنشأ، بحيث يتم إغلاق واصف الملف تلقائيًا عند execve(2). يؤدي تعيين أعلام الإغلاق عند الإنشاء، بدلاً من لاحقًا باستخدام fcntl(2)، إلى تجنب حالات السباق المحتملة حيث يقوم الخيط المتصل باستدعاء perf_event_open() و fcntl(2) في نفس الوقت الذي يقوم فيه خيط آخر باستدعاء fork(2) ثم execve(2).
PERF_FLAG_FD_NO_GROUP
يخبر هذا العلم الحدث بتجاهل المعلمة group_fd باستثناء الغرض من إعداد إعادة توجيه الإخراج باستخدام العلم PERF_FLAG_FD_OUTPUT.
PERF_FLAG_FD_OUTPUT (معطل منذ Linux 2.6.35)
يعيد هذا العلم توجيه إخراج عينات الحدث ليتم تضمينه بدلاً من ذلك في المخزن المؤقت mmap للحدث المحدد بواسطة group_fd.
PERF_FLAG_PID_CGROUP (منذ Linux 2.6.39)
يمكّن هذا العلم المراقبة الشاملة للنظام لكل حاوية. الحاوية هي تجريد يعزل مجموعة من الموارد لتحكم أدق (وحدات المعالجة المركزية، الذاكرة، إلخ). في هذا الوضع، يتم قياس الحدث فقط إذا كان الخيط الذي يعمل على وحدة المعالجة المركزية المُراقبة ينتمي إلى الحاوية (cgroup) المعينة. يتم تحديد cgroup عن طريق تمرير واصف ملف تم فتحه على دليله في نظام الملفات cgroupfs. على سبيل المثال، إذا كانت cgroup المراد مراقبتها تسمى test، فيجب تمرير واصف ملف تم فتحه على /dev/cgroup/test (بافتراض أن cgroupfs مثبت على /dev/cgroup) كمعلمة pid. مراقبة cgroup متاحة فقط للأحداث الشاملة للنظام وقد تتطلب أذونات إضافية.

يتم وصف حقول بنية perf_event_attr بمزيد من التفصيل أدناه:

type
يحدد هذا الحقل نوع الحدث العام. له أحد القيم التالية:
PERF_TYPE_HARDWARE
يشير هذا إلى أحد أحداث الأجهزة "المعممة" التي يوفرها النواة. انظر تعريف حقل config لمزيد من التفاصيل.
PERF_TYPE_SOFTWARE
يشير هذا إلى أحد الأحداث المعرفة برمجيًا التي يوفرها النواة (حتى لو لم يكن هناك دعم للأجهزة).
PERF_TYPE_TRACEPOINT
يشير هذا إلى نقطة تتبع يوفرها نظام نقاط التتبع في النواة.
PERF_TYPE_HW_CACHE
يشير هذا إلى حدث ذاكرة تخزين مؤقت للأجهزة. له ترميز خاص، موصوف في تعريف حقل config.
PERF_TYPE_RAW
يشير هذا إلى حدث "خام" خاص بتنفيذ معين في حقل config.
PERF_TYPE_BREAKPOINT (منذ Linux 2.6.33)
يشير هذا إلى نقطة توقف للأجهزة كما توفرها وحدة المعالجة المركزية. يمكن أن تكون نقاط التوقف عبارة عن عمليات وصول للقراءة/الكتابة إلى عنوان أو تنفيذ عنوان تعليمات.
PMU ديناميكي
منذ Linux 2.6.38، يمكن لـ perf_event_open() دعم وحدات PMU متعددة. لتمكين ذلك، يمكن استخدام قيمة تم تصديرها بواسطة النواة في حقل type للإشارة إلى وحدة PMU المراد استخدامها. يمكن العثور على القيمة المراد استخدامها في نظام الملفات sysfs: يوجد دليل فرعي لكل مثيل PMU تحت /sys/bus/event_source/devices. في كل دليل فرعي، يوجد ملف type يحتوي على عدد صحيح يمكن استخدامه في حقل type. على سبيل المثال، /sys/bus/event_source/devices/cpu/type يحتوي على القيمة لوحدة PMU الأساسية لوحدة المعالجة المركزية، وهي عادةً 4.
kprobe
uprobe (كلاهما منذ Linux 4.17)
تقوم وحدات PMU الديناميكية هاتان بإنشاء kprobe/uprobe وإرفاقها بمقبض الملف الذي تم إنشاؤه بواسطة perf_event_open. سيتم تدمير kprobe/uprobe عند تدمير مقبض الملف. انظر الحقول kprobe_func و uprobe_path و kprobe_addr و probe_offset لمزيد من التفاصيل.
size
حجم بنية perf_event_attr للتوافق الأمامي/الخلفي. قم بتعيين هذا باستخدام sizeof(struct perf_event_attr) للسماح للنواة برؤية حجم البنية وقت الترجمة.
التعريف المرتبط PERF_ATTR_SIZE_VER0 تم تعيينه إلى 64؛ كان هذا حجم البنية الأولى المنشورة. PERF_ATTR_SIZE_VER1 هو 72، يتوافق مع إضافة نقاط التوقف في Linux 2.6.33. PERF_ATTR_SIZE_VER2 هو 80 يتوافق مع إضافة عينات الفروع في Linux 3.4. PERF_ATTR_SIZE_VER3 هو 96 يتوافق مع إضافة sample_regs_user و sample_stack_user في Linux 3.7. PERF_ATTR_SIZE_VER4 هو 104 يتوافق مع إضافة sample_regs_intr في Linux 3.19. PERF_ATTR_SIZE_VER5 هو 112 يتوافق مع إضافة aux_watermark في Linux 4.1.
config
يحدد هذا الحدث الذي تريده، بالاقتران مع حقل type. يتم أيضًا أخذ الحقلين config1 و config2 في الاعتبار في الحالات التي لا يكون فيها 64 بت كافيًا لتحديد الحدث بالكامل. ترميز هذه الحقول يعتمد على الحدث.
هناك طرق مختلفة لتعيين حقل config تعتمد على قيمة حقل type الموصوف سابقًا. ما يلي هو إعدادات مختلفة ممكنة لـ config مفصولة حسب type.
إذا كان type هو PERF_TYPE_HARDWARE، فإننا نقيس أحد أحداث وحدة المعالجة المركزية الأجهزة المعممة. ليست كل هذه الأحداث متاحة على جميع المنصات. قم بتعيين config إلى أحد الخيارات التالية:
PERF_COUNT_HW_CPU_CYCLES
إجمالي الدورات. كن حذرًا مما يحدث أثناء تغيير تردد وحدة المعالجة المركزية.
PERF_COUNT_HW_INSTRUCTIONS
التعليمات المنفذة. كن حذرًا، يمكن أن تتأثر هذه بمشاكل مختلفة، أبرزها عدد المقاطعات الأجهزة.
PERF_COUNT_HW_CACHE_REFERENCES
عمليات الوصول إلى ذاكرة التخزين المؤقت. عادةً ما يشير هذا إلى عمليات الوصول إلى ذاكرة التخزين المؤقت من المستوى الأخير (Last Level Cache)، ولكن هذا قد يختلف اعتمادًا على وحدة المعالجة المركزية الخاصة بك. قد يشمل ذلك التنبؤ المسبق ورسائل التناسق؛ مرة أخرى، هذا يعتمد على تصميم وحدة المعالجة المركزية الخاصة بك.
PERF_COUNT_HW_CACHE_MISSES
فقدان ذاكرة التخزين المؤقت. عادةً ما يشير هذا إلى فقدان ذاكرة التخزين المؤقت من المستوى الأخير؛ هذا مخصص للاستخدام جنبًا إلى جنب مع الحدث PERF_COUNT_HW_CACHE_REFERENCES لحساب معدل فقدان ذاكرة التخزين المؤقت.
PERF_COUNT_HW_BRANCH_INSTRUCTIONS
تعليمات الفروع المنفذة. قبل Linux 2.6.35، كان هذا يستخدم الحدث الخاطئ على معالجات AMD.
PERF_COUNT_HW_BRANCH_MISSES
تعليمات الفروع المتنبأ بها بشكل خاطئ.
PERF_COUNT_HW_BUS_CYCLES
دورات الناقل، والتي يمكن أن تكون مختلفة عن إجمالي الدورات.
PERF_COUNT_HW_STALLED_CYCLES_FRONTEND (منذ Linux 3.0)
الدورات المتوقفة أثناء الإصدار.
PERF_COUNT_HW_STALLED_CYCLES_BACKEND (منذ Linux 3.0)
الدورات المتوقفة أثناء التقاعد.
PERF_COUNT_HW_REF_CPU_CYCLES (منذ Linux 3.3)
إجمالي الدورات؛ لا يتأثر بتغيير تردد وحدة المعالجة المركزية.
إذا كان type هو PERF_TYPE_SOFTWARE، فإننا نقيس الأحداث البرمجية التي يوفرها النواة. قم بتعيين config إلى أحد الخيارات التالية:
PERF_COUNT_SW_CPU_CLOCK
يقوم هذا بالإبلاغ عن ساعة وحدة المعالجة المركزية، وهي ساعة لكل نواة عالية الدقة.
PERF_COUNT_SW_TASK_CLOCK
يقوم هذا بالإبلاغ عن عدد ساعات خاص بالمهمة قيد التشغيل.
PERF_COUNT_SW_PAGE_FAULTS
يقوم هذا بالإبلاغ عن عدد أخطاء الصفحة.
PERF_COUNT_SW_CONTEXT_SWITCHES
يقوم هذا بحساب تبديلات السياق. حتى Linux 2.6.34، تم الإبلاغ عن كل هذه كأحداث مساحة المستخدم، وبعد ذلك تم الإبلاغ عنها على أنها تحدث في النواة.
PERF_COUNT_SW_CPU_MIGRATIONS
يقوم هذا بالإبلاغ عن عدد المرات التي انتقلت فيها العملية إلى نواة جديدة.
PERF_COUNT_SW_PAGE_FAULTS_MIN
يقوم هذا بحساب عدد أخطاء الصفحة البسيطة. لم تتطلب هذه إدخال/إخراج من القرص للتعامل معها.
PERF_COUNT_SW_PAGE_FAULTS_MAJ
يقوم هذا بحساب عدد أخطاء الصفحة الكبيرة. هذه تطلبت إدخال/إخراج من القرص للتعامل معها.
PERF_COUNT_SW_ALIGNMENT_FAULTS (منذ Linux 2.6.33)

PERF_SAMPLE_INFO

If PERF_SAMPLE_IDENTIFIER is set in attr.sample_type, then the data read back will contain an identifier for the event, to disambiguate events when reading multiple events or when using CPU (or thread) wide sampling.

The identifier is a 64-bit value, as specified by the attr.event_identifier field.

If PERF_SAMPLE_TIME is set, then a timestamp (in nanoseconds, relative to the time the event was enabled) is included.

If PERF_SAMPLE_CPU is set, then the CPU number (a 32-bit value) is included.

If PERF_SAMPLE_TID is set, then the process ID (a 32-bit value) and thread ID (a 32-bit value) are included.

If PERF_SAMPLE_PERIOD is set, then the remaining period (a 64-bit value) is included.

If PERF_SAMPLE_STREAM_KEY is set, then the stream_key (a 64-bit value) is included.

If PERF_SAMPLE_FLAGS is set, then the flags (a 64-bit value) are included.

If PERF_SAMPLE_PHYS_CCODE is set, then the physical code (a 64-bit value) is included.

If PERF_SAMPLE_PREV_TIME is set, then the previous time (a 64-bit value) is included.

If PERF_SAMPLE_BRANCH_STACK is set, then the kernel will dump a stack of branch entries. Each entry is composed of a branch target address (64 bits) and flags (64 bits).

The flags indicate the type of branch that was taken and the privilege level (PLM) of the target. The privilege value is encoded in the lower 3 bits of the flags field.

PERF_SAMPLE_BRANCH_USER
Branch target is in user space.
PERF_SAMPLE_BRANCH_KERNEL
Branch target is in kernel space.
PERF_SAMPLE_BRANCH_HV
Branch target is in hypervisor.
PERF_SAMPLE_BRANCH_PLM_ALL
A convenience value that is the three preceding values ORed together.

In addition to the privilege value, at least one or more of the following bits must be set.

PERF_SAMPLE_BRANCH_ANY
Any branch type.
PERF_SAMPLE_BRANCH_ANY_CALL
Any call branch (includes direct calls, indirect calls, and far jumps).
PERF_SAMPLE_BRANCH_IND_CALL
Indirect calls.
PERF_SAMPLE_BRANCH_CALL (since Linux 4.4)
Direct calls.
PERF_SAMPLE_BRANCH_ANY_RETURN
Any return branch.
PERF_SAMPLE_BRANCH_IND_JUMP (since Linux 4.2)
Indirect jumps.
PERF_SAMPLE_BRANCH_COND (since Linux 3.16)
Conditional branches.
PERF_SAMPLE_BRANCH_ABORT_TX (since Linux 3.11)
Transactional memory aborts.
PERF_SAMPLE_BRANCH_IN_TX (since Linux 3.11)
Branch in transactional memory transaction.
PERF_SAMPLE_BRANCH_NO_TX (since Linux 3.11)
Branch not in transactional memory transaction. PERF_SAMPLE_BRANCH_CALL_STACK (since Linux 4.1) Branch is part of a hardware-generated call stack. This requires hardware support, currently only found on Intel x86 Haswell or newer.
sample_regs_user (since Linux 3.7)
This bit mask defines the set of user CPU registers to dump on samples. The layout of the register mask is architecture-specific and is described in the kernel header file arch/ARCH/include/uapi/asm/perf_regs.h.
sample_stack_user (since Linux 3.7)
This defines the size of the user stack to dump if PERF_SAMPLE_STACK_USER is specified.
clockid (since Linux 4.1)
If use_clockid is set, then this field selects which internal Linux timer to use for timestamps. The available timers are defined in linux/time.h, with CLOCK_MONOTONIC, CLOCK_MONOTONIC_RAW, CLOCK_REALTIME, CLOCK_BOOTTIME, and CLOCK_TAI currently supported.
aux_watermark (since Linux 4.1)
This specifies how much data is required to trigger a PERF_RECORD_AUX sample.
sample_max_stack (since Linux 4.8)
When sample_type includes PERF_SAMPLE_CALLCHAIN, this field specifies how many stack frames to report when generating the callchain.
aux_sample_size (since Linux 5.5)
When PERF_SAMPLE_AUX flag is set, specify the desired size of AUX data. Note that it can get smaller data than the specified size.
sig_data (since Linux 5.13)
This data will be copied to user's signal handler (through si_perf in the siginfo_t) to disambiguate which event triggered the signal.

قراءة النتائج

بمجرد فتح واصف الملف perf_event_open()، يمكن قراءة قيم الأحداث من واصف الملف. القيم الموجودة هناك محددة بواسطة الحقل read_format في هيكل attr وقت الفتح.

إذا حاولت القراءة في مخزن مؤقت غير كبير بما يكفي لاحتواء البيانات، فستحدث الخطأ ENOSPC.

إليك تخطيط البيانات التي تم إرجاعها بواسطة القراءة:

•
إذا تم تحديد PERF_FORMAT_GROUP للسماح بقراءة جميع الأحداث في مجموعة مرة واحدة:

struct read_format {
    u64 nr;            /* The number of events */
    u64 time_enabled;  /* if PERF_FORMAT_TOTAL_TIME_ENABLED */
    u64 time_running;  /* if PERF_FORMAT_TOTAL_TIME_RUNNING */
    struct {
        u64 value;     /* The value of the event */
        u64 id;        /* if PERF_FORMAT_ID */
        u64 lost;      /* if PERF_FORMAT_LOST */
    } values[nr];
};

•
إذا لم يتم تحديد PERF_FORMAT_GROUP:

struct read_format {
    u64 value;         /* The value of the event */
    u64 time_enabled;  /* if PERF_FORMAT_TOTAL_TIME_ENABLED */
    u64 time_running;  /* if PERF_FORMAT_TOTAL_TIME_RUNNING */
    u64 id;            /* if PERF_FORMAT_ID */
    u64 lost;          /* if PERF_FORMAT_LOST */
};

القيم المقروءة هي كما يلي:

nr
عدد الأحداث في واصف الملف هذا. متاح فقط إذا تم تحديد PERF_FORMAT_GROUP.
time_enabled
time_running
الوقت الإجمالي الذي كان فيه الحدث ممكّنًا ويعمل. عادةً ما تكون هاتان القيمتان متساويتين. يحدث التضاعف إذا كان عدد الأحداث أكثر من عدد فتحات عدادات PMU المتاحة. في هذه الحالة، تعمل الأحداث فقط جزءًا من الوقت ويمكن استخدام القيمتين time_enabled و time running لتحجيم قيمة مقدرة للعد.
value
قيمة 64 بت غير موقعة تحتوي على نتيجة العداد.
id
قيمة فريدة عالميًا لهذا الحدث المحدد؛ موجودة فقط إذا تم تحديد PERF_FORMAT_ID في read_format.
lost
عدد العينات المفقودة لهذا الحدث؛ موجودة فقط إذا تم تحديد PERF_FORMAT_LOST في read_format.

تخطيط MMAP

عند استخدام perf_event_open() في وضع العينات، يتم تسجيل الأحداث غير المتزامنة (مثل تجاوز سعة العداد أو تتبع mmap لـ PROT_EXEC) في مخزن مؤقت دائري. يتم إنشاء هذا المخزن المؤقت الدائري والوصول إليه من خلال mmap(2).

يجب أن يكون حجم mmap هو 1+2^n صفحة، حيث تكون الصفحة الأولى صفحة بيانات وصفية (struct perf_event_mmap_page) تحتوي على معلومات متنوعة مثل موقع رأس المخزن المؤقت الدائري.

قبل Linux 2.6.39، يوجد خطأ يعني أنه يجب تخصيص مخزن مؤقت دائري mmap عند أخذ العينات حتى لو لم تكن تخطط للوصول إليه.

هيكل صفحة البيانات الوصفية الأولى لـ mmap هو كما يلي:


struct perf_event_mmap_page {
    __u32 version;        /* version number of this structure */
    __u32 compat_version; /* lowest version this is compat with */
    __u32 lock;           /* seqlock for synchronization */
    __u32 index;          /* hardware counter identifier */
    __s64 offset;         /* add to hardware counter value */
    __u64 time_enabled;   /* time event active */
    __u64 time_running;   /* time event on CPU */
    union {
        __u64   capabilities;
        struct {
            __u64   cap_usr_time / cap_usr_rdpmc / cap_bit0 : 1,
                  cap_bit0_is_deprecated : 1,
                  cap_user_rdpmc         : 1,
                  cap_user_time          : 1,
                  cap_user_time_zero     : 1,
        };
    };
    __u16 pmc_width;
    __u16 time_shift;
    __u32 time_mult;
    __u64 time_offset;
    __u64 __reserved[120];   /* Pad to 1 k */
    __u64 data_head;         /* head in the data section */
    __u64 data_tail;         /* user-space written tail */
    __u64 data_offset;       /* where the buffer starts */
    __u64 data_size;         /* data buffer size */
    __u64 aux_head;
    __u64 aux_tail;
    __u64 aux_offset;
    __u64 aux_size;
}

يصف السرد التالي الحقول في هيكل perf_event_mmap_page بمزيد من التفصيل:

version
رقم إصدار هذا الهيكل.
compat_version
أدنى إصدار يتوافق معه.
lock
قفل تسلسلي للمزامنة.
index
معرف فريد للعداد الأجهزة.
offset
عند استخدام rdpmc للقراءة، يجب إضافة قيمة الإزاحة هذه إلى القيمة التي تم إرجاعها بواسطة rdpmc للحصول على العدد الإجمالي الحالي للحدث.
time_enabled
الوقت الذي كان فيه الحدث نشطًا.
time_running
الوقت الذي كان فيه الحدث قيد التشغيل.
cap_usr_time / cap_usr_rdpmc / cap_bit0 (since Linux 3.4)
كان هناك خطأ في تعريف cap_usr_time و cap_usr_rdpmc من Linux 3.4 حتى Linux 3.11. تم تعريف كلا البتين ليشير إلى نفس الموقع، لذلك كان من المستحيل معرفة ما إذا كان cap_usr_time أو cap_usr_rdpmc قد تم تعيينهما بالفعل.
بدءًا من Linux 3.12، تم تغيير اسمها إلى cap_bit0 ويجب عليك استخدام حقلي cap_user_time و cap_user_rdpmc بدلاً من ذلك.
c
ap_bit0_is_deprecated (منذ لينكس 3.12)
إذا تم تعيينه، تشير هذه البتة إلى أن النواة تدعم البتات المنفصلة بشكل صحيح cap_user_time و cap_user_rdpmc.
إذا لم يتم تعيينها، فإنها تشير إلى نواة أقدم حيث cap_usr_time و cap_usr_rdpmc تتوافق مع نفس البتة وبالتالي يجب استخدام كلا الميزتين بحذر.
cap_user_rdpmc (منذ لينكس 3.12)
إذا كانت الأجهزة تدعم قراءة مساحة المستخدم لعدادات الأداء بدون استدعاء نظام (هذه هي تعليمة "rdpmc" على x86)، فيمكن استخدام الكود التالي للقيام بالقراءة:

u32 seq, time_mult, time_shift, idx, width;
u64 count, enabled, running;
u64 cyc, time_offset;
do {
    seq = pc->lock;
    barrier();
    enabled = pc->time_enabled;
    running = pc->time_running;
    if (pc->cap_usr_time && enabled != running) {
        cyc = rdtsc();
        time_offset = pc->time_offset;
        time_mult   = pc->time_mult;
        time_shift  = pc->time_shift;
    }
    idx = pc->index;
    count = pc->offset;
    if (pc->cap_usr_rdpmc && idx) {
        width = pc->pmc_width;
        count += rdpmc(idx - 1);
    }
    barrier();
} while (pc->lock != seq);

cap_user_time (منذ لينكس 3.12)
تشير هذه البتة إلى أن الأجهزة لديها عداد طوابع زمنية ثابت وغير متوقف (TSC على x86).
cap_user_time_zero (منذ لينكس 3.12)
تشير إلى وجود time_zero الذي يسمح بربط قيم الطوابع الزمنية بالساعة الأجهزة.
pmc_width
إذا كانت cap_usr_rdpmc، فإن هذا الحقل يوفر عرض البت للقيمة المقروءة باستخدام تعليمة rdpmc أو ما يعادلها. يمكن استخدام هذا لتوسيع الإشارة لليمين مثل:

pmc <<= 64 - pmc_width;
pmc >>= 64 - pmc_width;  // signed shift right
count += pmc;

time_shift
time_mult
time_offset
إذا كانت cap_usr_time، فيمكن استخدام هذه الحقول لحساب فرق الوقت منذ time_enabled (بالنانوثانية) باستخدام rdtsc أو ما شابه.

u64 quot, rem;
u64 delta;
quot  = cyc >> time_shift;
rem   = cyc & (((u64)1 << time_shift) - 1);
delta = time_offset + quot * time_mult +
        ((rem * time_mult) >> time_shift);

حيث تتم قراءة time_offset و time_mult و time_shift و cyc في حلقة seqcount الموضحة أعلاه. يمكن بعد ذلك إضافة هذا الفارق إلى العناصر الممكنة والممكنة (إذا كان idx)، مما يحسن القياس:

enabled += delta;
if (idx)
    running += delta;
quot  = count / running;
rem   = count % running;
count = quot * enabled + (rem * enabled) / running;

time_zero (منذ لينكس 3.12)
إذا تم تعيين cap_usr_time_zero، فيمكن حساب الساعة الأجهزة (عداد الطوابع الزمنية TSC على x86) من القيم time_zero و time_mult و time_shift:

time = timestamp - time_zero;
quot = time / time_mult;
rem  = time % time_mult;
cyc  = (quot << time_shift) + (rem << time_shift) / time_mult;

والعكس صحيح:

quot = cyc >> time_shift;
rem  = cyc & (((u64)1 << time_shift) - 1);
timestamp = time_zero + quot * time_mult +
            ((rem * time_mult) >> time_shift);

data_head
يشير هذا إلى رأس قسم البيانات. تزداد القيمة باستمرار، ولا تلتف. تحتاج القيمة إلى الالتفاف يدويًا حسب حجم المخزن المؤقت mmap قبل الوصول إلى العينات.
على المنصات التي تدعم SMP، بعد قراءة قيمة data_head، يجب على مساحة المستخدم إصدار rmb().
data_tail
عندما يكون التعيين PROT_WRITE، يجب على مساحة المستخدم كتابة قيمة data_tail لتعكس آخر بيانات مقروءة. في هذه الحالة، لن تتجاوز النواة البيانات غير المقروءة.
data_offset (منذ لينكس 4.1)
يحتوي على إزاحة الموقع في المخزن المؤقت mmap حيث تبدأ بيانات عينة perf.
data_size (منذ لينكس 4.1)
يحتوي على حجم منطقة عينة perf داخل المخزن المؤقت mmap.
aux_head
aux_tail
aux_offset
aux_size (منذ لينكس 4.1)
تسمح منطقة AUX بـ mmap(2) لمخزن مؤقت عينة منفصل لتدفقات البيانات عالية النطاق (منفصلة عن المخزن المؤقت عينة perf الرئيسي). مثال على تدفق عالي النطاق هو دعم تتبع التعليمات، كما هو موجود في معالجات Intel الأحدث.
لإعداد منطقة AUX، يجب أولاً تعيين aux_offset بإزاحة أكبر من data_offset + data_size ويجب تعيين aux_size إلى حجم المخزن المؤقت المطلوب. يجب أن تكون الإزاحة والحجم المطلوبان محاذيين للصفحات، ويجب أن يكون الحجم قوة لاثنين. يتم بعد ذلك تمرير هذه القيم إلى mmap لتعيين المخزن المؤقت AUX. يتم تضمين صفحات المخزن المؤقت AUX كجزء من حد الموارد RLIMIT_MEMLOCK (انظر setrlimit(2))، وأيضًا كجزء من مخصص perf_event_mlock_kb.
بشكل افتراضي، سيتم اقتطاع المخزن المؤقت AUX إذا لم يتناسب مع المساحة المتاحة في المخزن المؤقت الدائري. إذا تم تعيين المخزن المؤقت AUX كمخزن مؤقت للقراءة فقط، فسيعمل في وضع المخزن المؤقت الدائري حيث سيتم استبدال البيانات القديمة بالجديدة. في وضع الاستبدال، قد لا يكون من الممكن استنتاج مكان بدء البيانات الجديدة، وتقع على عاتق المستهلك مهمة تعطيل القياس أثناء القراءة لتجنب سباقات البيانات المحتملة.
تشيرؤ مؤشرات المخزن المؤقت الدائري aux_head و aux_tail إلى نفس السلوك وقواعد الترتيب كما في data_head و data_tail الموصوفة سابقًا.

الصفحات الـ 2^n من المخزن المؤقت الدائري التالية لها التخطيط الموصوف أدناه.

إذا تم تعيين perf_event_attr.sample_id_all، فسيتم الحصول على جميع أنواع الأحداث على الحقول المحددة sample_type المتعلقة بمكان / وقت (الهوية) حدوث الحدث (TID، TIME، ID، CPU، STREAM_ID) الموصوفة في PERF_RECORD_SAMPLE أدناه، وسيتم تخزينها بعد perf_event_header مباشرة والحقول الموجودة بالفعل للحقول الموجودة، أي في نهاية الحمولة. هذا يسمح بدعم ملف perf.data أحدث بواسطة أدوات perf أقدم، مع تجاهل الحقول الاختيارية الجديدة.

تبدأ قيم mmap برأس:


struct perf_event_header {
    __u32   type;
    __u16   misc;

PERF_RECORD_SAMPLE
يشير هذا السجل إلى عينة.

struct {
    struct perf_event_header header;
    u64    sample_id;   /* if PERF_SAMPLE_IDENTIFIER */
    u64    ip;          /* if PERF_SAMPLE_IP */
    u32    pid, tid;    /* if PERF_SAMPLE_TID */
    u64    time;        /* if PERF_SAMPLE_TIME */
    u64    addr;        /* if PERF_SAMPLE_ADDR */
    u64    id;          /* if PERF_SAMPLE_ID */
    u64    stream_id;   /* if PERF_SAMPLE_STREAM_ID */
    u32    cpu, res;    /* if PERF_SAMPLE_CPU */
    u64    period;      /* if PERF_SAMPLE_PERIOD */
    struct read_format v;
                        /* if PERF_SAMPLE_READ */
    u64    nr;          /* if PERF_SAMPLE_CALLCHAIN */
    u64    ips[nr];     /* if PERF_SAMPLE_CALLCHAIN */
    u32    size;        /* if PERF_SAMPLE_RAW */
    char   data[size];  /* if PERF_SAMPLE_RAW */
    u64    bnr;         /* if PERF_SAMPLE_BRANCH_STACK */
    struct perf_branch_entry lbr[bnr];
                        /* if PERF_SAMPLE_BRANCH_STACK */
    u64    abi;         /* if PERF_SAMPLE_REGS_USER */
    u64    regs[weight(mask)];
                        /* if PERF_SAMPLE_REGS_USER */
    u64    size;        /* if PERF_SAMPLE_STACK_USER */
    char   data[size];  /* if PERF_SAMPLE_STACK_USER */
    u64    dyn_size;    /* if PERF_SAMPLE_STACK_USER &&
                           size != 0 */
    union perf_sample_weight weight;
                        /* if PERF_SAMPLE_WEIGHT */
                        /* || PERF_SAMPLE_WEIGHT_STRUCT */
    u64    data_src;    /* if PERF_SAMPLE_DATA_SRC */
    u64    transaction; /* if PERF_SAMPLE_TRANSACTION */
    u64    abi;         /* if PERF_SAMPLE_REGS_INTR */
    u64    regs[weight(mask)];
                        /* if PERF_SAMPLE_REGS_INTR */
    u64    phys_addr;   /* if PERF_SAMPLE_PHYS_ADDR */
    u64    cgroup;      /* if PERF_SAMPLE_CGROUP */
    u64    data_page_size;
                      /* if PERF_SAMPLE_DATA_PAGE_SIZE */
    u64    code_page_size;
                      /* if PERF_SAMPLE_CODE_PAGE_SIZE */
    u64    size;        /* if PERF_SAMPLE_AUX */
    char   data[size];  /* if PERF_SAMPLE_AUX */
};

sample_id
إذا تم تمكين PERF_SAMPLE_IDENTIFIER، يتم تضمين معرف فريد 64 بت. هذا تكرار لقيمة id الخاصة بـ PERF_SAMPLE_ID، ولكنه مضمن في بداية العينة حتى تتمكن المحللات من الحصول على القيمة بسهولة.
ip
إذا تم تمكين PERF_SAMPLE_IP، يتم تضمين قيمة مؤشر تعليمات 64 بت.
pid
tid
إذا تم تمكين PERF_SAMPLE_TID، يتم تضمين معرف عملية 32 بت ومعرف خيط 32 بت.
time
إذا تم تمكين PERF_SAMPLE_TIME، يتم تضمين طابع زمني 64 بت. يتم الحصول عليه عبر local_clock() وهو طابع زمني للأجهزة إذا كان متاحًا وقيمة jiffies إذا لم يكن.
addr
إذا تم تمكين PERF_SAMPLE_ADDR، يتم تضمين عنوان 64 بت. هذا عادةً ما يكون عنوان نقطة تتبع أو نقطة توقف أو حدث برنامج؛ وإلا فإن القيمة هي 0.
id
إذا تم تمكين PERF_SAMPLE_ID، يتم تضمين معرف فريد 64 بت. إذا كان الحدث عضوًا في مجموعة أحداث، يتم إرجاع معرف قائد المجموعة. هذا المعرف هو نفسه المعرف الذي تم إرجاعه بواسطة PERF_FORMAT_ID.
stream_id
إذا تم تمكين PERF_SAMPLE_STREAM_ID، يتم تضمين معرف فريد 64 بت. على عكس PERF_SAMPLE_ID، يتم إرجاع المعرف الفعلي، وليس قائد المجموعة. هذا المعرف هو نفسه المعرف الذي تم إرجاعه بواسطة PERF_FORMAT_ID.
cpu
res
إذا تم تمكين PERF_SAMPLE_CPU، فهذه قيمة 32 بت تشير إلى وحدة المعالجة المركزية (CPU) التي كانت قيد الاستخدام، بالإضافة إلى قيمة 32 بت محجوزة (غير مستخدمة).
period
إذا تم تمكين PERF_SAMPLE_PERIOD، يتم كتابة قيمة 64 بت تشير إلى فترة الاستعيان الحالية.
v
إذا تم تمكين PERF_SAMPLE_READ، يتم تضمين بنية من نوع read_format تحتوي على قيم لجميع الأحداث في مجموعة الأحداث. تعتمد القيم المتضمنة على قيمة read_format المستخدمة في وقت perf_event_open().
nr
ips[nr]
إذا تم تمكين PERF_SAMPLE_CALLCHAIN، يتم تضمين رقم 64 بت يشير إلى عدد مؤشرات التعليمات التالية 64 بت التي ستتبع. هذه هي سلسلة الاستدعاء الحالية.
size
data[size]
إذا تم تمكين PERF_SAMPLE_RAW، يتم تضمين قيمة 32 بت تشير إلى حجم البيانات تليها بيانات عشوائية.

معالجة تجاوز الحد

يمكن ضبط الأحداث لإعلام عند تجاوز حد معين، مما يشير إلى تجاوز الحد. يمكن التقاط ظروف تجاوز الحد عن طريق مراقبة واصف الملف الخاص بالحدث باستخدام poll(2)، select(2)، أو epoll(7). بدلاً من ذلك، يمكن التقاط أحداث تجاوز الحد عبر معالج إشارة، عن طريق تمكين إشارات الإدخال/الإخراج على واصف الملف؛ انظر المناقشة حول العمليات F_SETOWN و F_SETSIG في fcntl(2).

يتم إنشاء تجاوزات الحد فقط بواسطة أحداث العينات (يجب أن تكون sample_period بقيمة غير صفرية).

هناك طريقتان لتوليد إشعارات تجاوز الحد.

الأولى هي تعيين قيمة wakeup_events أو wakeup_watermark التي سيتم تشغيلها إذا تم كتابة عدد معين من العينات أو البايتات إلى مخزن الحلقة mmap. في هذه الحالة، يتم الإشارة إلى POLL_IN.

الطريقة الأخرى هي استخدام ioctl PERF_EVENT_IOC_REFRESH. يضيف ioctl هذا إلى عداد ينقص كل مرة يتجاوز فيها الحد. عندما يكون غير صفري، يتم الإشارة إلى POLL_IN، ولكن بمجرد وصول العداد إلى 0 يتم الإشارة إلى POLL_HUP ويتم تعطيل الحد الأساسي.

تحديث قائد مجموعة الأحداث يقوم بتحديث جميع الأشقاء والتحديث بقيمة 0 حاليًا يتيح تحديثات لا نهائية؛ هذه السلوكيات غير مدعومة ولا ينبغي الاعتماد عليها.

بدءًا من لينكس 3.18، يتم الإشارة إلى POLL_HUP إذا كان الحد الذي يتم مراقبته مرتبطًا بعملية مختلفة وخرجت تلك العملية.

تعليمة rdpmc

بدءًا من لينكس 3.4 على x86، يمكنك استخدام تعليمة rdpmc للحصول على قراءات بزمن استجابة منخفض دون الحاجة للدخول إلى النواة. لاحظ أن استخدام rdpmc ليس بالضرورة أسرع من الطرق الأخرى لقراءة قيم الأحداث.

يمكن اكتشاف الدعم لهذا باستخدام حقل cap_usr_rdpmc في صفحة mmap؛ يمكن العثور على وثائق حول كيفية حساب قيم الأحداث في هذا القسم.

في الأصل، عند تمكين دعم rdpmc، كان يمكن لأي عملية (ليس فقط العمليات التي لديها حدث perf نشط) استخدام تعليمة rdpmc للوصول إلى العدادات. بدءًا من لينكس 4.0، يُسمح بدعم rdpmc فقط إذا تم تمكين حدث حالي في سياق عملية. لاستعادة السلوك القديم، اكتب القيمة 2 إلى /sys/devices/cpu/rdpmc.

NAME

perf_event_open - set up performance monitoring

SYNOPSIS

#include <linux/perf_event.h>
#include <sys/ioctl.h>

int perf_event_open(struct perf_event_attr *attr,
                    pid_t pid, int cpu, int group_fd, unsigned long flags);

DESCRIPTION

The perf_event_open() system call is the interface for setting up performance monitoring counters. It returns a file descriptor which can be used to read the event data, and can be further manipulated with read(2), write(2), and ioctl(2).

The first argument, attr, is a pointer to a struct perf_event_attr structure, which describes the event to be monitored. The structure must be zero-initialized before setting the desired fields.

The fields of struct perf_event_attr are:

unsigned int type;
The type of event to monitor. This can be one of the types defined in <linux/perf_event.h>, such as PERF_TYPE_HARDWARE, PERF_TYPE_SOFTWARE, PERF_TYPE_TRACEPOINT, or PERF_TYPE_HW_CACHE.
unsigned int size;
The size of the struct perf_event_attr structure. This should be set to sizeof(struct perf_event_attr).
__u64 config;
The specific event configuration. The meaning of this field depends on the type field. For example, if type is PERF_TYPE_HARDWARE, config can be one of the PERF_COUNT_HW_* values. If type is PERF_TYPE_SOFTWARE, config can be one of the PERF_COUNT_SW_* values. If type is PERF_TYPE_TRACEPOINT, config specifies the tracepoint ID. If type is PERF_TYPE_HW_CACHE, config specifies the cache operation and level.
unsigned long long sample_period;
For sampling events, this field specifies the period. For counter events, it is the number of occurrences.
unsigned long long sample_freq;
For sampling events, this field specifies the frequency. Only one of sample_period or sample_freq should be specified.
__u32 sample_type;
Specifies the format of the sample data. This can be a bitmask of PERF_SAMPLE_* flags.
__u32 read_format;
Specifies the format of the data returned by read(2) when the event is not in sample mode. This can be a bitmask of PERF_FORMAT_* flags.
unsigned int disabled :1;
If set, the event is initially disabled.
unsigned int inherit :1;
If set, the event will be inherited by child processes.
unsigned int frequent :1;
If set, the event is allowed to be scheduled more frequently.
unsigned int exclude_user :1;
If set, exclude user-space events.
unsigned int exclude_kernel :1;
If set, exclude kernel-space events.
unsigned int exclude_hv :1;
If set, exclude hypervisor events.
unsigned int exclusive :1;
If set, the event runs only when no other events are running.
unsigned int pdc :1;
If set, enable precise event counting.
unsigned int :4;
Reserved.
__u64 wakeup_events;
Generate a wakeup event after wakeup_events samples.
__u64 wakeup_watermark;
Generate a wakeup event when the number of unread samples reaches wakeup_watermark.
__u32 bp_type;
Breakpoint type. Used when type is PERF_TYPE_BREAKPOINT.
__u64 bp_addr;
Breakpoint address. Used when type is PERF_TYPE_BREAKPOINT.
__u64 bp_len;
Breakpoint length. Used when type is PERF_TYPE_BREAKPOINT.
__u32 branch_sample_type;
Branch sampling type. Used when type is PERF_TYPE_HARDWARE and config is PERF_COUNT_HW_BRANCH_STRUCTIONS.
__u32 reserved;
Reserved.

The pid argument specifies the process ID to monitor. If pid is 0, the event is attached to the calling process. If pid is -1, the event is attached to the system-wide. Note that system-wide monitoring requires root privileges.

The cpu argument specifies the CPU to monitor. If cpu is -1, the event is attached to the calling process (if pid is 0) or system-wide (if pid is -1). If cpu is a specific CPU number, the event is attached to that CPU.

The group_fd argument specifies the file descriptor of a performance event group. If group_fd is -1, the event is in its own group. If group_fd is a valid file descriptor, the new event is added to the group.

The flags argument can be used to specify additional options. Currently, the only supported flag is PERF_FLAG_FD_CLOEXEC, which sets the close-on-exec flag on the returned file descriptor.

RETURN VALUE

On success, perf_event_open() returns a file descriptor. On failure, it returns -1 and sets errno appropriately.

ERRORS

EACCES
The user does not have permission to monitor the specified event.
EBADF
Invalid file descriptor.
EINVAL
Invalid value for attr, pid, cpu, group_fd, or flags.
ENOSPC
The system limit for the number of performance events has been reached.
ENOSYS
The kernel does not support performance event monitoring.
EOPNOTSUPP
The requested event is not supported by the hardware.
EPERM
The user does not have permission to perform system-wide monitoring.

EXAMPLE

The following example demonstrates how to open a performance event to count CPU cycles:

#include <linux/perf_event.h>
#include <sys/ioctl.h>
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

int main() {
    struct perf_event_attr pe;
    int fd;

    // Initialize the perf_event_attr structure
    memset(&pe, 0, sizeof(struct perf_event_attr));
    pe.type = PERF_TYPE_HARDWARE;
    pe.size = sizeof(struct perf_event_attr);
    pe.config = PERF_COUNT_HW_CPU_CYCLES;
    pe.disabled = 1; // Start disabled

    // Open the performance event
    fd = perf_event_open(&pe, 0, -1, -1, 0);
    if (fd == -1) {
        perror("perf_event_open");
        exit(EXIT_FAILURE);
    }

    // Enable the event
    ioctl(fd, PERF_EVENT_IOC_ENABLE, 0);

    // Do some work
    for (int i = 0; i < 1000000; ++i);

    // Disable the event
    ioctl(fd, PERF_EVENT_IOC_DISABLE, 0);

    // Read the event count
    unsigned long long count;
    read(fd, &count, sizeof(unsigned long long));

    printf("CPU cycles: %llu\n", count);

    // Close the file descriptor
    close(fd);

    return 0;
}

NOTES

Performance event monitoring is a powerful feature that allows you to profile your application's performance at a low level. It can be used to identify performance bottlenecks, optimize code, and understand hardware behavior.

The available hardware and software events depend on the specific CPU architecture and the Linux kernel version.

System-wide monitoring requires root privileges and should be used with caution, as it can impact system performance.

The perf_event_open interface is complex and requires a good understanding of performance monitoring concepts. For more advanced usage, refer to the Linux kernel documentation and other resources.
