NAME

perlapio — Perl API for I/O Layers

SYNOPSIS

#include "perlio.h"

PerlIO_fast_gets(f)
PerlIO_has_cntptr(f)
PerlIO_canset_cnt(f)
PerlIO_get_cnt(f)
PerlIO_get_ptr(f)
PerlIO_set_ptrcnt(f,p,c)
PerlIO_set_cnt(f,c)
PerlIO_has_base(f)
PerlIO_get_base(f)
PerlIO_get_bufsiz(f)

PerlIO_apply_layers(aTHX_ f,mode,layers)
PerlIO_binmode(aTHX_ f,ptype,imode,layers)
PerlIO_debug(fmt,...)

DESCRIPTION

This man page describes the Perl I/O API, which is an abstraction layer over Perl's input/output mechanisms. It allows different underlying I/O implementations (e.g., standard C stdio, POSIX stdio, or custom implementations) to be used interchangeably.

The main interface is through a PerlIO handle, which is a pointer to a PerlIO struct. This handle is opaque to the user; it is opaque to the user; it is passed around to all the functions described below.

Fast Get Interface

The following functions provide a fast path for reading data from a buffer without making a system call.

PerlIO_fast_gets(f)
Returns true if the underlying implementation supports the fast get interface. This is a shorthand for: 
PerlIO_has_cntptr(f) && \
                      PerlIO_canset_cnt(f) && \
                      'Can set pointer into buffer'
PerlIO_has_cntptr(f)
The implementation can return a pointer to the current position in the "buffer" and a count of bytes available in the buffer. Do not use this directly; use PerlIO_fast_gets.
PerlIO_get_cnt(f)
Returns the count of readable bytes in the buffer. A zero or negative return value indicates that no more bytes are available.
PerlIO_get_ptr(f)
Returns a pointer to the next readable byte in the buffer. Accessing the pointer (dereferencing) is only safe if PerlIO_get_cnt() has returned a positive value. Only positive offsets up to the value returned by PerlIO_get_cnt() are allowed.
PerlIO_set_ptrcnt(f,p,c)
Sets the pointer into the buffer and a count of bytes still in the buffer. Should only be used to set the pointer within the range implied by previous calls to "PerlIO_get_ptr" and "PerlIO_get_cnt". The two values must be consistent with each other (the implementation may only use one or the other, or may require both).
PerlIO_canset_cnt(f)
The implementation can adjust its idea of the number of bytes in the buffer. Do not use this directly; use PerlIO_fast_gets.
PerlIO_set_cnt(f,c)
Obscure - sets the count of bytes in the buffer. Deprecated. Only usable if PerlIO_canset_cnt() returns true. Currently used only in doio.c to force a count less than -1 to -1. Perhaps it should be PerlIO_set_empty or similar. This call might actually do nothing if the "count" is deduced from the pointer and a "limit". Do not use this; use PerlIO_set_ptrcnt().
PerlIO_has_base(f)
Returns true if the implementation has a buffer and can return a pointer to the whole buffer and its size. Used by Perl for -T / -B tests. Other uses would be very obscure...
PerlIO_get_base(f)
Returns the *start* of the buffer. Access positive offsets in the buffer only, up to the value returned by PerlIO_get_bufsiz().
PerlIO_get_bufsiz(f)
Returns the *total number of bytes* in the buffer. This is neither the number that can be read, nor the amount of memory allocated to the buffer. Rather, it is what the operating system and/or implementation happened to read() (or whatever) the last time I/O was requested.

Other Functions

PerlIO_apply_layers(aTHX_ f,mode,layers)
The new interface to the USE_PERLIO implementation. The layers ":crlf" and ":raw" are the only ones allowed for other implementations, and those are silently ignored. (As of perl5.8 ":raw" is deprecated.) Use PerlIO_binmode() below for the portable case.
PerlIO_binmode(aTHX_ f,ptype,imode,layers)
The hook used by Perl's "binmode" operator. ptype is Perl's character for the type of I/O:
'<' read
'>' write
'+' read/write

imode is "O_BINARY" or "O_TEXT".

layers is a string of layers to apply; only ":crlf" makes sense in the non-USE_PERLIO case. (As of perl5.8 ":raw" is deprecated in favor of passing NULL.)

Portable cases are:

    PerlIO_binmode(aTHX_ f,ptype,O_BINARY,NULL);
and
    PerlIO_binmode(aTHX_ f,ptype,O_TEXT,":crlf");

On Unix, these calls probably have no effect whatsoever. Elsewhere, they alter "\n" to CR,LF translation and possibly cause a special text "end of file" indicator to be written or honored on read. The effect of making the call after performing any I/O on the handle depends on the implementation. (It might be ignored, affect data that is already buffered, or only apply to subsequent data.)

PerlIO_debug(fmt,...)
PerlIO_debug is a printf()-like function that can be used for debugging. It has no return value. Its main use is inside PerlIO, where using real printf, warn(), etc., would recursively call PerlIO and cause problems.

PerlIO_debug writes to the file named by $ENV{'PERLIO_DEBUG'}, or defaults to stderr if the environment variable is not defined. Typical use might be:

Bourne shells (sh, ksh, bash, zsh, ash, ...):
 PERLIO_DEBUG=/tmp/perliodebug.log ./perl -Di somescript some args
Csh/Tcsh:
 setenv PERLIO_DEBUG /tmp/perliodebug.log
 ./perl -Di somescript some args
If you have the "env" utility:
 env PERLIO_DEBUG=/tmp/perliodebug.log ./perl -Di somescript args
Win32:
 set PERLIO_DEBUG=perliodebug.log
 perl -Di somescript some args

On a Perl built without "-DDEBUGGING", or when the "-Di" command-line switch is not specified, or under taint mode, PerlIO_debug() is a no-op.
