NAME

perf-c2c - محلل البيانات المشتركة C2C/HITM.

SYNOPSIS

perf c2c record [<options>] <command>
perf c2c record [<options>] -- [<record command options>] <command>
perf c2c report [<options>]

DESCRIPTION

C2C تعني Cache To Cache (من الذاكرة المخبئية إلى الذاكرة المخبئية).

توفر أداة perf c2c وسائل لتحليل البيانات المشتركة C2C/HITM. وهي تتيح لك تتبع تضارب خطوط الذاكرة المخبئية.

على معالجات Intel، تعتمد الأداة على أحداث زمن استجابة التحميل (load latency) ومرفق التخزين الدقيق (precise store facility) التي توفرها معالجات Intel. على معالجات PowerPC، تستخدم الأداة أخذ عينات من التعليمات العشوائية مع ميزة الحد. على معالجات AMD، تستخدم الأداة وحدة PMU لعمليات IBS (بسبب قيود الأجهزة، لا تدعم perf c2c معالجات Zen3). على معالجات Arm64، تستخدم SPE لأخذ عينات من عمليات التحميل والتخزين، لذا يتطلب ذلك دعم الأجهزة والنواة. راجع perf-arm-spe(1) للحصول على دليل الإعداد. نظرًا للطبيعة الإحصائية لأخذ عينات SPE على Arm، لن يتم أخذ عينات من كل عملية ذاكرة.

توفر هذه الأحداث: - عنوان الذاكرة للوصول - نوع الوصول (تفاصيل التحميل والتخزين) - زمن الاستجابة (بالدورات) لوصول التحميل.

توفر أداة c2c وسائل لتسجيل هذه البيانات وإرجاع تفاصيل الوصول لخطوط الذاكرة المخبئية ذات أعلى تضارب - أعلى عدد من عمليات HITM.

يتبع سير العمل الأساسي مع هذه الأداة مرحلتي التسجيل/التقرير القياسيتين. يستخدم المستخدم أمر التسجيل لتسجيل بيانات الأحداث وأمر التقرير لعرضها.

RECORD OPTIONS

-e, --event=

حدد حدث PMU. استخدم perf c2c record -e list لسرد الأحداث المتاحة.

-v, --verbose

كن أكثر تفصيلاً (اعرض أخطاء فتح العداد، إلخ).

-l, --ldlat

قم بتكوين زمن استجابة التحميل (mem-loads latency). مدعوم على معالجات Intel و Arm64 وبعض معالجات AMD. يتم تجاهله على الأبنية الأخرى. 
على معالجات AMD المدعومة:
- الملف /sys/bus/event_source/devices/ibs_op/caps/ldlat يحتوي على '1'.
- قيم زمن الاستجابة المدعومة هي من 128 إلى 2048 (كلاهما شامل).
- زمن الاستجابة الذي يكون من مضاعفات 128 يفرض عبئًا أقل على التنميط
  مقارنة بالقيم الأخرى.
- تم تعطيل ترشيح زمن استجابة التحميل بشكل افتراضي.

-k, --all-kernel

قم بتكوين جميع الأحداث المستخدمة للتشغيل في مساحة النواة.

-u, --all-user

قم بتكوين جميع الأحداث المستخدمة للتشغيل في مساحة المستخدم.

REPORT OPTIONS

-k, --vmlinux=<file>

مسار vmlinux

-v, --verbose

كن أكثر تفصيلاً (اعرض أخطاء فتح العداد، إلخ).

-i, --input

حدد ملف الإدخال للمعالجة.

-N, --node-info

اعرض معلومات إضافية عن العقدة في التقرير (انظر قسم معلومات العقدة NODE INFO)

-c, --coalesce

حدد حقول الفرز لعرض خط ذاكرة مخبئية واحد. الحقول التالية متاحة: tid,pid,iaddr,dso (انظر COALESCE)

-g, --call-graph

قم بإعداد معلمات سلسلة الاستدعاءات (callchains). يرجى الرجوع إلى صفحة دليل perf-report للتفاصيل.

--stdio

فرض إخراج stdio (انظر STDIO OUTPUT)

--stats

عرض جداول الإحصائيات فقط وفرض وضع stdio.

--full-symbols

عرض الطول الكامل للرموز.

--no-source

لا تعرض عمود المصدر:السطر (Source:Line).

--show-all

اعرض جميع أسطر HITM الملتقطة، بغض النظر عن نسبة HITM 0.0005.

-f, --force

لا تقم بالتحقق من الملكية.

-d, --display

التبديل إلى نوع HITM (rmt, lcl) أو نوع التنصت على الأقران (peer) للعرض والفرز. إجمالي HITMs (tot) هو الافتراضي، باستثناء Arm64 الذي يستخدم وضع الأقران افتراضيًا.

--stitch-lbr

اعرض رسم بياني للاستدعاءات مع LBRs المدمجة، والتي قد تحتوي على رسم بياني استدعاء أكثر اكتمالاً. يجب أن يكون ملف perf.data قد تم الحصول عليه باستخدام perf c2c record --call-graph lbr. معطل افتراضيًا. في الحالات الشائعة التي تعاني من تجاوز سعة مكدس الاستدعاءات، يمكنه إعادة إنشاء مكدسات استدعاء أفضل من إخراج مكدس استدعاء lbr الافتراضي. لكن هذا النهج ليس مضمونًا. قد تكون هناك حالات ينشئ فيها مكدسات استدعاء غير صحيحة من مطابقات غير صحيحة. تشمل القيود المعروفة معالجة الاستثناءات مثل setjmp/longjmp حيث لن تتطابق الاستدعاءات/العودات.

--double-cl

تجميع اكتشاف أحداث مشاركة خط الذاكرة المخبئية إلى حجم خط ذاكرة مخبئية مزدوج. تمتلك بعض الأبنية ميزة جلب خط الذاكرة المخبئية المجاور (Adjacent Cacheline Prefetch)، مما يجعل مشاركة خط الذاكرة المخبئية تتصرف كما لو كان حجم خط الذاكرة المخبئية مضاعفًا.

C2C RECORD

يقوم أمر perf c2c record بإعداد الخيارات المتعلقة بتحليل الذاكرة المخبئية HITM واستدعاء أمر perf record القياسي.

خيارات perf record التالية يتم تكوينها افتراضيًا: (راجع صفحة دليل perf record للتفاصيل)

-W,-d,--phys-data,--sample-cpu

ما لم يتم تحديده بخلاف ذلك باستخدام الخيار -e، يتم مراقبة الأحداث التالية افتراضيًا على معالجات Intel:

cpu/mem-loads,ldlat=30/P
cpu/mem-stores/P

على معالجات AMD:

ibs_op//

وعلى معالجات PowerPC:

cpu/mem-loads/
cpu/mem-stores/

يمكن للمستخدم تمرير أي خيار من خيارات perf record خلف العلامة --، مثل (لتمكين سلاسل الاستدعاءات والمراقبة على مستوى النظام):

$ perf c2c record -- -g -a

يرجى مراجعة قسم RECORD OPTIONS للحصول على خيارات c2c record المحددة.

C2C REPORT

يعرض أمر perf c2c report تحليل البيانات المشتركة. يأتي في وضعين للعرض: stdio و tui (الافتراضي).

يتبع سير عمل أمر التقرير ما يلي: - فرز جميع البيانات بناءً على عنوان خط الذاكرة المخبئية - تخزين تفاصيل الوصول لكل خط ذاكرة مخبئية - فرز جميع خطوط الذاكرة المخبئية بناءً على إعدادات المستخدم - عرض البيانات

بشكل عام، يتكون إخراج perf report من عرضين أساسيين: 1) قائمة خطوط الذاكرة المخبئية الأكثر تكلفة 2) تفاصيل الإزاحة لكل خط ذاكرة مخبئية.

لكل خط ذاكرة مخبئية في القائمة 1)، نعرض البيانات التالية: (كلا الوضعين stdio و TUI يتبعان نفس إخراج الحقول)

Index
- فهرس يبدأ من الصفر لتحديد خط الذاكرة المخبئية
Cacheline
- عنوان خط الذاكرة المخبئية (رقم سداسي عشري)
Rmt/Lcl Hitm (العرض بأنواع HITM)
- نسبة خط الذاكرة المخبئية من إجمالي عمليات Remote/Local HITM
Peer Snoop (العرض بنوع الأقران)
- نسبة خط الذاكرة المخبئية من إجمالي وصول الأقران
LLC Load Hitm - Total, LclHitm, RmtHitm (للعرض بأنواع HITM)
- عدد عمليات تحميل HITM الإجمالية/المحلية/البعيدة
Load Peer - Total, Local, Remote (للعرض بنوع الأقران)
- عدد عمليات التحميل الإجمالية/المحلية/البعيدة من ذاكرة تخزين الأقران المؤقتة أو DRAM
Total records
- مجموع جميع وصولات خطوط الذاكرة المخبئية
Total loads
- مجموع جميع وصولات التحميل
Total stores
- مجموع جميع وصولات التخزين
Store Reference - L1Hit, L1Miss, N/A
  L1Hit - وصولات التخزين التي أصابت L1
  L1Miss - وصولات التخزين التي أخطأت L1
  N/A - وصولات التخزين التي لم يتوفر لها مستوى الذاكرة
Core Load Hit - FB, L1, L2
- عدد إصابات التحميل في FB (Fill Buffer) و L1 و L2
LLC Load Hit - LlcHit, LclHitm
- عدد وصولات التحميل LLC، يتضمن إصابات LLC وعمليات HITM في LLC
RMT Load Hit - RmtHit, RmtHitm
- عدد وصولات التحميل البعيدة، يتضمن الإصابات البعيدة وعمليات HITM البعيدة؛
  على نوى Arm Neoverse، يتم استخدام RmtHit لتسجيل الوصولات البعيدة،
  بما في ذلك الوصولات البعيدة إلى DRAM أو أي مستوى ذاكرة مخبئية أعلى في العقدة البعيدة
Load Dram - Lcl, Rmt
- عدد وصولات DRAM المحلية والبعيدة

لكل إزاحة في القائمة 2)، نعرض البيانات التالية:

HITM - Rmt, Lcl (العرض بأنواع HITM)
- نسبة وصولات Remote/Local HITM للإزاحة المعطاة ضمن خط الذاكرة المخبئية
Peer Snoop - Rmt, Lcl (العرض بنوع الأقران)
- نسبة وصولات Remote/Local للأقران للإزاحة المعطاة ضمن خط الذاكرة المخبئية

NAME

perf-c2c - Tool to trace cache-to-cache transfers

SYNOPSIS

perf c2c record [] []
perf c2c report []

DESCRIPTION

This tool records and analyzes cache-to-cache (C2C) transfers. These transfers occur when a cache line is modified by one CPU and then read or modified by another CPU without going back to memory.

This can indicate potential False Sharing issues or NUMA problems.

RECORD OPTIONS

The perf c2c record command records events related to cache-to-cache transfers. Available options include:

-e          Specify the performance event(s) to trace.
-o            Specify the output file for recording.
-f                  Overwrite existing file.
-W           Specify the cache line size.

REPORT OPTIONS

The perf c2c report command displays the recorded data. Available options include:

-i            Specify the input file.
-N                  Specify the format for Node information.
-x       Specify the output field separator.
-f                  Display fields in compact format.
-c                  Coalesce identical entries.
-d                  Display raw data.
-p             Filter by process ID.
-t             Filter by thread ID.
-m         Minimum latency to display.
-M         Maximum latency to display.
-S            Minimum size for shared cache lines.
-C            Filter by CPU list.
-L                  Display latency information.

C2C RECORD

When using perf c2c record, the following fields are collected:

Store Refs - L1 Hit, L1 Miss, N/A
- % of store accesses that hit L1, missed L1 and N/A (no available) memory
  level for given offset within cacheline
Data address - Offset
- offset address
Pid
- pid of the process responsible for the accesses
Tid
- tid of the process responsible for the accesses
Code address
- code address responsible for the accesses
cycles - rmt hitm, lcl hitm, load (Display with HITM types)
  - sum of cycles for given accesses - Remote/Local HITM and generic load
cycles - rmt peer, lcl peer, load (Display with peer type)
  - sum of cycles for given accesses - Remote/Local peer load and generic load
cpu cnt
  - number of cpus that participated on the access
Symbol
  - code symbol related to the 'Code address' value
Shared Object
  - shared object name related to the 'Code address' value
Source:Line
  - source information related to the 'Code address' value
Node
  - nodes participating on the access (see NODE INFO section)

C2C REPORT

When using perf c2c report, the output is organized to help analyze cache-to-cache transfers. The default output includes fields like:

Store Refs - L1 Hit, L1 Miss, N/A
- % of store accesses that hit L1, missed L1 and N/A (no available) memory
  level for given offset within cacheline
Data address - Offset
- offset address
Pid
- pid of the process responsible for the accesses
Tid
- tid of the process responsible for the accesses
Code address
- code address responsible for the accesses
cycles - rmt hitm, lcl hitm, load (Display with HITM types)
  - sum of cycles for given accesses - Remote/Local HITM and generic load
cycles - rmt peer, lcl peer, load (Display with peer type)
  - sum of cycles for given accesses - Remote/Local peer load and generic load
cpu cnt
  - number of cpus that participated on the access
Symbol
  - code symbol related to the 'Code address' value
Shared Object
  - shared object name related to the 'Code address' value
Source:Line
  - source information related to the 'Code address' value
Node
  - nodes participating on the access (see NODE INFO section)

NODE INFO

The Node field displays nodes that accesses given cacheline offset. Its output comes in 3 flavors: - node IDs separated by , - node IDs with stats for each ID, in following format: Node{cpus %hitms %stores} (Display with HITM types) Node{cpus %peers %stores} (Display with peer type) - node IDs with list of affected CPUs in following format: Node{cpu list}

User can switch between above flavors with -N option or use n key to interactively switch in TUI mode.

COALESCE

User can specify how to sort offsets for cacheline.

Following fields are available and governs the final output fields set for cacheline offsets output:

tid   - coalesced by process TIDs
pid   - coalesced by process PIDs
iaddr - coalesced by code address, following fields are displayed:
           Code address, Code symbol, Shared Object, Source line
dso   - coalesced by shared object

By default the coalescing is setup with pid,iaddr.

STDIO OUTPUT

The stdio output displays data on standard output.

Following tables are displayed: Trace Event Information - overall statistics of memory accesses

Global Shared Cache Line Event Information
- overall statistics on shared cachelines
Shared Data Cache Line Table
- list of most expensive cachelines
Shared Cache Line Distribution Pareto
- list of all accessed offsets for each cacheline

TUI OUTPUT

The TUI output provides interactive interface to navigate through cachelines list and to display offset details.

For details please refer to the help window by pressing ? key.
