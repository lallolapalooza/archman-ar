NAME

perlnumber - semantics of numbers and numeric operations in Perl

SYNOPSIS

$n = 1234;              # decimal integer
$n = 0b1110011;         # binary integer
$n = 01234;             # octal integer
$n = 0x1234;            # hexadecimal integer
$n = 12.34e-56;         # exponential notation
$n = "-12.34e56";       # number specified as a string
$n = "1234";            # number specified as a string
$n = "01234";           # Same as "1234"; a leading 0 in a string
                        # does not indicate that it is octal

DESCRIPTION

This document describes how Perl internally handles numeric values.

Perl's operator overloading facility is completely ignored here. Operator overloading allows user-defined behaviors for numbers, such as operations over arbitrarily large integers, floating point numbers with arbitrary precision, operations over "exotic" numbers such as modular arithmetic or p-adic arithmetic, and so on. See overload for details.

Storing numbers

Perl can internally represent numbers in 3 different ways: as native integers, as native floating point numbers, and as decimal strings. Decimal strings may have an exponential notation part, as in "12.34e-56". Native here means "a format supported by the C compiler which was used to build perl".

The term "native" does not mean quite as much when we talk about native integers, as it does when native floating point numbers are involved. The only implication of the term "native" on integers is that the limits for the maximal and the minimal supported true integral quantities are close to powers of 2. However, "native" floats have a most fundamental restriction: they may represent only those numbers which have a relatively "short" representation when converted to a binary fraction. For example, 0.9 cannot be represented by a native float, since the binary fraction for 0.9 is infinite:

binary0.1110011001100...

with the sequence 1100 repeating again and again. In addition to this limitation, the exponent of the binary number is also restricted when it is represented as a floating point number. On typical hardware, floating point values can store numbers with up to 53 binary digits, and with binary exponents between -1024 and 1024. In decimal representation this is close to 16 decimal digits and decimal exponents in the range of -304..304. The upshot of all this is that Perl cannot store a number like 12345678901234567 as a floating point number on such architectures without loss of information.

Similarly, decimal strings can represent only those numbers which have a finite decimal expansion. Being strings, and thus of arbitrary length, there is no practical limit for the exponent or number of decimal digits for these numbers. (But realize that what we are discussing the rules for just the storage of these numbers. The fact that you can store such "large" numbers does not mean that the operations over these numbers will use all of the significant digits. See "Numeric operators and numeric conversions" for details.)

In fact numbers stored in the native integer format may be stored either in the signed native form, or in the unsigned native form. Thus the limits for Perl numbers stored as native integers would typically be -2**31..2**32-1, with appropriate modifications in the case of 64-bit integers. Again, this does not mean that Perl can do operations only over integers in this range: it is possible to store many more integers in floating point format.

Summing up, Perl numeric values can store only those numbers which have a finite decimal expansion or a "short" binary expansion.

Numeric operators and numeric conversions

As mentioned earlier, Perl can store a number in any one of three formats, but most operators typically understand only one of those formats. When a numeric value is passed as an argument to such an operator, it will be converted to the format understood by the operator.

Six such conversions are possible:

native integer        --> native floating point       (*)
native integer        --> decimal string
native floating_point --> native integer              (*)
native floating_point --> decimal string              (*)
decimal string        --> native integer
decimal string        --> native floating point       (*)

These conversions are governed by the following general rules:

  • If the source number can be represented in the target form, that representation is used.
  • If the source number is outside of the limits representable in the target form, a representation of the closest limit is used. (Loss of information)
  • If the source number is between two numbers representable in the target form, a representation of one of these numbers is used. (Loss of information)
  • In "native floating point --> native integer" conversions the magnitude of the result is less than or equal to the magnitude of the source. ("Rounding to zero".)
  • If the "decimal string --> native integer" conversion cannot be done without loss of information, the result is compatible with the conversion sequence "decimal_string --> native_floating_point --> native_integer". In particular, rounding is strongly biased to 0, though a number like "0.99999999999999999999" has a chance of being rounded to 1.

RESTRICTION: The conversions marked with "(*)" above involve steps performed by the C compiler. In particular, bugs/features of the compiler used may lead to breakage of some of the above rules.

Flavors of Perl numeric operations

Perl operations which take a numeric argument treat that argument in one of four different ways: they may force it to one of the integer, floating, or string formats; or they may behave differently depending on the format of the operand. Forcing a numeric value to a particular format does not change the number stored in the value.

All the operators which need an argument in the integer format treat the argument as in modular arithmetic, e.g., "mod 2**32" on a 32-bit architecture. "sprintf "%u", -1" therefore provides the same result as "sprintf "%u", ~0".

Arithmetic operators
The binary operators "+" "-" "*" "/" "%" "==" "!=" ">" "<" ">=" "<=" and the unary operators "-" "abs" and "--" will attempt to convert arguments to integers. If both conversions are possible without loss of precision, and the operation can be performed without loss of precision then the integer result is used. Otherwise arguments are converted to floating point format and the floating point result is used. The caching of conversions (as described above) means that the integer conversion does not throw away fractional parts on floating point numbers.
++
"++" behaves as the other operators above, except that if it is a string matching the format "/^[a-zA-Z]*[0-9]*\z/" the string increment described in perlop is used.

تخزين الأرقام

يمكن لبيرل تمثيل الأرقام داخليًا بثلاث طرق مختلفة: كأعداد صحيحة أصلية، كأرقام عشرية أصلية، وكأوتار عشرية. قد تحتوي الأوتار العشرية على جزء ترميز أسي، كما في "12.34e-56". الأصلي هنا يعني "تنسيق مدعوم من مترجم C الذي تم استخدامه لبناء بيرل".

مصطلح "الأصلي" لا يعني الكثير عند الحديث عن الأعداد الصحيحة الأصلية، كما هو الحال عند التعامل مع الأرقام العشرية الأصلية. الأثر الوحيد لمصطلح "الأصلي" على الأعداد الصحيحة هو أن حدود الكميات الصحيحة الحقيقية القصوى والدنيا المدعومة قريبة من قوى 2. ومع ذلك، فإن الأرقام العشرية "الأصلية" لديها قيد أساسي للغاية: قد تمثل فقط تلك الأرقام التي لديها تمثيل "قصير" نسبيًا عند تحويلها إلى كسور ثنائية. على سبيل المثال، لا يمكن تمثيل 0.9 برقم عشري أصلي، حيث أن الكسر الثنائي لـ 0.9 لا نهائي:

binary0.1110011001100...

مع تكرار التسلسل 1100 مرارًا وتكرارًا. بالإضافة إلى هذا القيد، فإن أس الرقم الثنائي مقيد أيضًا عند تمثيله كرقم عشري. على الأجهزة النموذجية، يمكن للقيم العشرية تخزين أرقام تصل إلى 53 رقمًا ثنائيًا، وأسس ثنائية بين -1024 و 1024. بالتمثيل العشري، هذا قريب من 16 رقمًا عشريًا وأسس عشرية في النطاق من -304..304. النتيجة النهائية لكل هذا هي أن بيرل لا يمكنها تخزين رقم مثل 12345678901234567 كرقم عشري على هذه المعماريات دون فقدان للمعلومات.

وبالمثل، يمكن للأوتار العشرية تمثيل فقط تلك الأرقام التي لها توسع عشري منتهي. كونها أوتارًا، وبالتالي بطول تعسفي، لا يوجد حد عملي للأس أو عدد الأرقام العشرية لهذه الأرقام. (ولكن أدرك أننا نناقش قواعد *تخزين* هذه الأرقام فقط. حقيقة أنه يمكنك تخزين مثل هذه الأرقام "الكبيرة" لا تعني أن *العمليات* على هذه الأرقام ستستخدم جميع الأرقام الهامة. انظر "عمليات الأرقام والتحويلات الرقمية" لمزيد من التفاصيل.)

في الواقع، قد يتم تخزين الأرقام المخزنة بالتنسيق الصحيح الأصلي إما بالشكل الأصلي الموقع، أو بالشكل الأصلي غير الموقع. وبالتالي، فإن حدود أرقام بيرل المخزنة كأعداد صحيحة أصلية ستكون عادةً -2**31..2**32-1، مع تعديلات مناسبة في حالة الأعداد الصحيحة 64 بت. مرة أخرى، هذا لا يعني أن بيرل يمكنها إجراء عمليات فقط على الأعداد الصحيحة في هذا النطاق: من الممكن تخزين المزيد من الأعداد الصحيحة بتنسيق عشري.

تلخيصًا، يمكن لقيم بيرل الرقمية تخزين فقط تلك الأرقام التي لها توسع عشري منتهي أو توسع ثنائي "قصير".

عمليات الأرقام والتحويلات الرقمية

كما ذكرنا سابقًا، يمكن لبيرل تخزين رقم بأي تنسيق من ثلاثة تنسيقات، ولكن معظم العمليات تفهم عادةً تنسيقًا واحدًا فقط من هذه التنسيقات. عندما يتم تمرير قيمة رقمية كوسيط لهذه العملية، فسيتم تحويلها إلى التنسيق الذي تفهمه العملية.

هناك ستة تحويلات ممكنة:

عدد صحيح أصلي        --> رقم عشري أصلي       (*)
عدد صحيح أصلي        --> وتر عشري
رقم عشري أصلي        --> عدد صحيح أصلي              (*)
رقم عشري أصلي        --> وتر عشري              (*)
وتر عشري        --> عدد صحيح أصلي
وتر عشري        --> رقم عشري أصلي       (*)

يتم تنظيم هذه التحويلات بواسطة القواعد العامة التالية:

  • إذا كان الرقم المصدر يمكن تمثيله بالتنسيق الهدف، فسيتم استخدام هذا التمثيل.
  • إذا كان الرقم المصدر خارج الحدود التي يمكن تمثيلها بالتنسيق الهدف، فسيتم استخدام تمثيل أقرب حد. (فقدان للمعلومات)
  • إذا كان الرقم المصدر بين رقمين يمكن تمثيلهما بالتنسيق الهدف، فسيتم استخدام تمثيل أحد هذين الرقمين. (فقدان للمعلومات)
  • في تحويلات "رقم عشري أصلي --> عدد صحيح أصلي"، يكون حجم النتيجة أقل من أو يساوي حجم المصدر. ("التقريب إلى الصفر".)
  • إذا كان تحويل "وتر عشري --> عدد صحيح أصلي" لا يمكن إجراؤه دون فقدان للمعلومات، فإن النتيجة متوافقة مع تسلسل التحويل "وتر_عشري --> رقم_عشري_أصلي --> عدد_صحيح_أصلي". على وجه الخصوص، يميل التقريب بشدة نحو 0، على الرغم من أن رقمًا مثل "0.99999999999999999999" لديه فرصة للتقريب إلى 1.

قيد: التحويلات المميزة بـ "(*)" أعلاه تتضمن خطوات يقوم بها مترجم C. على وجه الخصوص، قد تؤدي الأخطاء/الميزات في المترجم المستخدم إلى كسر بعض القواعد المذكورة أعلاه.

أنواع عمليات الأرقام في بيرل

العمليات في بيرل التي تأخذ وسيطًا رقميًا تتعامل مع هذا الوسيط بإحدى الطرق الأربع المختلفة: قد تجبره على أحد تنسيقات الأعداد الصحيحة أو العشرية أو الأوتار؛ أو قد تتصرف بشكل مختلف اعتمادًا على تنسيق المعامل. فرض قيمة رقمية على تنسيق معين لا يغير الرقم المخزن في القيمة.

جميع العمليات التي تحتاج إلى وسيط بتنسيق الأعداد الصحيحة تعامل الوسيط كما في الحساب النمطي، على سبيل المثال، "mod 2**32" على بنية 32 بت. "sprintf "%u", -1" لذلك يوفر نفس نتيجة "sprintf "%u", ~0".

عمليات حسابية
العمليات الثنائية "+" "-" "*" "/" "%" "==" "!=" ">" "<" ">=" "<=" والعمليات الأحادية "-" "abs" و "--" ستحاول تحويل الوسائط إلى أعداد صحيحة. إذا كان كلا التحويلين ممكنين دون فقدان للدقة، وإذا كان يمكن إجراء العملية دون فقدان للدقة، فسيتم استخدام نتيجة العدد الصحيح. بخلاف ذلك، يتم تحويل الوسائط إلى تنسيق عشري وسيتم استخدام نتيجة الرقم العشري. التخزين المؤقت للتحويلات (كما هو موضح أعلاه) يعني أن تحويل العدد الصحيح لا يتخلص من الأجزاء الكسرية في الأرقام العشرية.
++
"++" يتصرف مثل العمليات الأخرى المذكورة أعلاه، باستثناء أنه إذا كان سلسلة نصية تطابق التنسيق "/^[a-zA-Z]*[0-9]*\z/" فسيتم استخدام زيادة السلسلة النصية الموصوفة في perlop.
عمليات حسابية أثناء "use integer"
في النطاقات التي تكون فيها "use integer;" مفعلة، تقريبًا جميع العمليات المدرجة

NAME

perlnumber - Perl numeric context and conversions

SYNOPSIS

    use integer;
    use bignum;
    use bigrat;
    use utf8;
    
    $x = 100000000000000000000.0;
    $y = $x + 1;
    print $y;

DESCRIPTION

This document describes how Perl performs numeric conversions and the effects of the "use integer;", "use bignum;" and "use bigrat;" pragmas.

Storing numbers

Perl stores numbers internally as doubles. When a number is needed for an operation, Perl may convert the number to a double. For example, if you assign an integer to a scalar variable, and then use that scalar in a numeric context, Perl will convert the integer to a double.

This conversion is done once. If the number is needed again, Perl will reuse the converted value. This means that although the first conversion may be time-consuming, repeated operations will not need to redo the conversion.

For example:

    $x = 123;
    $y = $x + 1; # $x is converted to a double here

If the number is too large to be represented as a double, or if you use the "use bignum;" pragma, Perl will use a floating-point representation or a big integer library.

Numeric operators and numeric conversions

Perl has a few different ways of performing numeric operations. Some operators always perform floating-point arithmetic, while others may perform integer arithmetic.

The following operators force their arguments into integer format, and return an integer result:

abs, ++ and --
These operators force their arguments into integer format, and return an integer result. The exceptions, "abs", "++" and "--", do not change their behavior with "use integer;"
Other mathematical operators
Operators such as "**", "sin" and "exp" force arguments to floating point format.
Bitwise operators
Arguments are forced into the integer format if not strings.
Bitwise operators during "use integer"
forces arguments to integer format. Also shift operations internally use signed integers rather than the default unsigned.
Operators which expect an integer
force the argument into the integer format. This is applicable to the third and fourth arguments of "sysread", for example.
Operators which expect a string
force the argument into the string format. For example, this is applicable to "printf "%s", $value".

Though forcing an argument into a particular form does not change the stored number, Perl remembers the result of such conversions. In particular, though the first such conversion may be time-consuming, repeated operations will not need to redo the conversion.

Flavors of Perl numeric operations

Perl has several ways of performing numeric operations. These are determined by the context of the operation, the pragmas in effect, and the types of the operands.

Default
By default, Perl performs floating-point arithmetic. This means that integers are converted to floating-point numbers before the operation is performed.
use integer;
This pragma forces Perl to perform all arithmetic operations using integers. This means that floating-point numbers are truncated to integers before the operation is performed.
use bignum;
This pragma forces Perl to use arbitrary-precision integers for all arithmetic operations. This means that numbers can be represented with much higher precision than standard floating-point numbers.
use bigrat;
This pragma forces Perl to use arbitrary-precision rational numbers for all arithmetic operations. This means that numbers are represented as fractions, which allows for exact representation of all rational numbers.
