pelican-theming(1)

الحزمة: pelican

التراخيص: AGPL-3.0-or-later

PELICAN-THEMING(1) PELICAN PELICAN-THEMING(1)

الاسم

pelican-theming - كيفية إنشاء سمات لـ Pelican

يرجى ملاحظة أنه بينما نبذل قصارى جهدنا لمراجعة ودمج مساهمات السمات، فإنها مقدمة من مجتمع Pelican وبالتالي قد تكون لديها مستويات متفاوتة من الدعم والتوافق.

إنشاء السمات

لتوليد موقعك باستخدام سمة قمت بإنشائها (أو قمت بتنزيلها يدويًا ثم تعديلها)، يمكنك تحديد تلك السمة باستخدام العلامة -t:

pelican content -s pelicanconf.py -t /projects/your-site/themes/your-theme

إذا كنت تفضل عدم تحديد السمة في كل مرة، يمكنك تعريف THEME في إعداداتك للإشارة إلى موقع سمتك المفضلة.

الهيكل

لإنشاء سمتك الخاصة، يجب عليك اتباع الهيكل التالي:

├── static
│   ├── css
│   └── images
└── templates
    ├── archives.html         // لعرض الأرشيفات
    ├── article.html          // تتم معالجته لكل مقال
    ├── author.html           // تتم معالجته لكل مؤلف
    ├── authors.html          // يجب أن يسرد جميع المؤلفين
    ├── categories.html       // يجب أن يسرد جميع الفئات
    ├── category.html         // تتم معالجته لكل فئة
    ├── index.html            // الفهرس (يسرد جميع المقالات)
    ├── page.html             // تتم معالجته لكل صفحة
    ├── period_archives.html  // لعرض أرشيفات الفترات الزمنية
    ├── tag.html              // تتم معالجته لكل وسم
    └── tags.html             // يجب أن يسرد جميع الوسوم. يمكن أن يكون سحابة وسوم.
  • static يحتوي على جميع الأصول الثابتة، والتي سيتم نسخها إلى مجلد theme الخاص بالمخرجات. يتضمن تخطيط نظام الملفات أعلاه مجلدات CSS والصور، ولكن هذه مجرد أمثلة. ضع ما تحتاجه هنا.
  • templates يحتوي على جميع القوالب التي سيتم استخدامها لتوليد المحتوى. ملفات القوالب المذكورة أعلاه إلزامية؛ يمكنك إضافة قوالبك الخاصة إذا كان ذلك يساعدك على الحفاظ على تنظيم الأشياء أثناء إنشاء سمتك.

القوالب والمتغيرات

الفكرة هي استخدام صيغة بسيطة يمكنك تضمينها في صفحات HTML الخاصة بك. يصف هذا المستند أي القوالب يجب أن توجد في سمة، وأي المتغيرات سيتم تمريرها إلى كل قالب في وقت الإنشاء.

سيتم تمرير جميع المتغيرات المعرفة في ملف الإعدادات الخاص بك إلى جميع القوالب، طالما أنها بأحرف كبيرة. يمكنك الوصول إليها مباشرة.

المتغيرات الشائعة

ستكون جميع هذه الإعدادات متاحة لجميع القوالب.

متغير الوصف
output_file اسم الملف الذي يتم إنشاؤه حاليًا. على سبيل المثال، عندما تقوم Pelican بعرض الصفحة الرئيسية، سيكون output_file هو "index.html".
articles قائمة المقالات، مرتبة تنازليًا حسب التاريخ. جميع العناصر هي كائنات Article، لذا يمكنك الوصول إلى سماتها (مثل العنوان، الملخص، المؤلف، إلخ). في بعض الأحيان يتم حجبها (على سبيل المثال، في صفحة الوسوم). ستجد معلومات عنها في متغير all_articles.
dates نفس قائمة المقالات، ولكن مرتبة حسب التاريخ، تصاعديًا.
hidden_articles قائمة المقالات المخفية
drafts قائمة مسودات المقالات
period_archives قاموس يحتوي على عناصر تتعلق بأرشيفات الفترات الزمنية (إذا تم تمكينها). راجع قسم سرد وربط أرشيفات الفترات للحصول على التفاصيل.
authors قائمة من أزواج (مؤلف، مقالات)، تحتوي على جميع المؤلفين والمقالات المقابلة (القيم)
categories قائمة من أزواج (فئة، مقالات)، تحتوي على جميع الفئات والمقالات المقابلة (القيم)
tags قائمة من أزواج (وسم، مقالات)، تحتوي على جميع الوسوم والمقالات المقابلة (القيم)
pages قائمة الصفحات
hidden_pages قائمة الصفحات المخفية
draft_pages قائمة مسودات الصفحات

الفرز

ملفات التغليف الخاصة بالروابط (الفئات، الوسوم، والمؤلفون حاليًا) لديها طرق مقارنة تسمح بفرزها بسهولة حسب الاسم:

تنسيق التاريخ

{{ article.date|strftime('%d %B %Y') }}

التحقق من التحميلات الإضافية

يوفر Pelican اختبار Jinja plugin_enabled للتحقق مما إذا كان ملحق معين ممكّنًا. يقبل هذا الاختبار اسم ملحق كسلسلة نصية وسيعيد قيمة منطقية. يمكن تحديد الملحقات ذات المسافات باستخدام الاسم الكامل (pelican.plugins.plugin_name) أو الاسم المختصر (plugin_name). يستخدم المثال التالي الملحق webassets لتقليص حجم CSS إذا كان الملحق ممكّنًا وبخلاف ذلك يعود إلى CSS العادي:

{% if "webassets" is plugin_enabled %}
    {% assets filters="cssmin", output="css/style.min.css", "css/style.scss" %}
        <link rel="stylesheet" href="{{SITEURL}}/{{ASSET_URL}}">
    {% endassets %}
{% else %}
    <link rel="stylesheet" href="{{SITEURL}}/css/style.css}">
{% endif %}

article.html

سيتم معالجة هذا القالب لكل مقالة، مع إنشاء المخرجات وفقًا للإعداد ARTICLE_SAVE_AS (الافتراضي: {slug}.html). المتغيرات التالية متاحة عند العرض.

متغير الوصف
article كائن المقالة المطلوب عرضه
category اسم فئة المقالة الحالية

أي بيانات وصفية تضعها في رأس ملف مصدر المقالة ستكون متاحة كحقول في كائن article. سيكون اسم الحقل هو نفسه اسم حقل البيانات الوصفية، باستثناء أنه بأحرف صغيرة بالكامل.

على سبيل المثال، يمكنك إضافة حقل يسمى FacebookImage إلى البيانات الوصفية لمقالتك، كما هو موضح أدناه:

Title: أحب بايثون أكثر من الموسيقى
Date: 2013-11-06 10:06
Tags: personal, python
Category: Tech
Slug: python-je-l-aime-a-mourir
Author: Francis Cabrel
FacebookImage: http://franciscabrel.com/images/pythonlove.png

هذه البيانات الوصفية الجديدة ستكون متاحة كـ article.facebookimage في قالب article.html الخاص بك. هذا سيسمح لك، على سبيل المثال، بتحديد صورة لعلامات open graph الخاصة بفيسبوك التي ستتغير مع كل مقالة:

<meta property="og:image" content="{{ article.facebookimage }}"/>

period_archives.html

This template will be processed for each year of your posts if a path for YEAR_ARCHIVE_SAVE_AS is defined, each month if MONTH_ARCHIVE_SAVE_AS is defined, and each day if DAY_ARCHIVE_SAVE_AS is defined.

Variable Description
period A tuple of the form (year, month, day) that indicates the current time period. year and day are numbers while month is a string. This tuple only contains year if the time period is a given year. It contains both year and month if the time period is over years and months and so on.
period_num A tuple of the form (year, month, day), as in period, except all values are numbers.

You can see an example of how to use period in the "simple" theme period_archives.html template.

Listing and Linking to Period Archives

The period_archives variable can be used to generate a list of links to the set of period archives that Pelican generates. As a common variable, it is available for use in any template, so you can implement such an index in a custom direct template, or in a sidebar visible across different site pages.

period_archives is a dict that may contain year, month, and/or day keys, depending on which *_ARCHIVE_SAVE_AS settings are enabled. The corresponding value is a list of dicts, where each dict in turn represents a time period (ordered according to the NEWEST_FIRST_ARCHIVES setting) with the following keys and values:

Key Value
period The same tuple as described in period_archives.html, e.g. (2023, 'June', 18).
period_num The same tuple as described in period_archives.html, e.g. (2023, 6, 18).
url The URL to the period archive page, e.g. posts/2023/06/18/. This is controlled by the corresponding *_ARCHIVE_URL setting.
save_as The path to the save location of the period archive page file, e.g. posts/2023/06/18/index.html. This is used internally by Pelican and is usually not relevant to themes.
articles A list of Article objects that fall under the time period.
dates Same list as articles, but ordered according to the NEWEST_FIRST_ARCHIVES setting.

Here is an example of how period_archives can be used in a template:

<ul>
{% for archive in period_archives.month %}
    <li>
        <a href="{{ SITEURL }}/{{ archive.url }}">
            {{ archive.period | reverse | join(' ') }} ({{ archive.articles|count }})
        </a>
    </li>
{% endfor %}
</ul>

You can change period_archives.month in the for statement to period_archives.year or period_archives.day as appropriate, depending on the time period granularity desired.
