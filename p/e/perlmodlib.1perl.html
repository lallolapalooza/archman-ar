الاسم

perlmodlib - بناء وحدات Perl جديدة والعثور على الوحدات الموجودة

مكتبة وحدات Perl

تتضمن توزيعة Perl العديد من الوحدات. توصف هذه الوحدات أدناه، وجميعها تنتهي بـ .pm. قد تكتشف ملفات مكتبة مترجمة (عادة ما تنتهي بـ .so) أو أجزاء صغيرة من الوحدات ليتم تحميلها تلقائيًا (تنتهي بـ .al)؛ تم إنشاء هذه تلقائيًا بواسطة عملية التثبيت. قد تكتشف أيضًا ملفات في دليل المكتبة تنتهي بـ .pl أو .ph. هذه مكتبات قديمة تم توفيرها حتى تستمر البرامج القديمة التي تستخدمها في العمل. سيتم تحويل ملفات .pl في النهاية إلى وحدات قياسية، وملفات .ph التي تم إنشاؤها بواسطة h2ph ستنتهي على الأرجح كوحدات امتداد تم إنشاؤها بواسطة h2xs. (قد تكون بعض قيم .ph متاحة بالفعل من خلال وحدات POSIX أو Errno أو Fcntl.) قد يساعد ملف pl2pm في التوزيع في تحويلك، ولكنه مجرد عملية ميكانيكية وبالتالي بعيد عن أن يكون مضمونًا.

الوحدات النفعية (Pragmatic Modules)

تعمل هذه الوحدات إلى حد ما مثل توجيهات المترجم (pragmata) لأنها تميل إلى التأثير على ترجمة برنامجك، وبالتالي تعمل بشكل جيد عادةً فقط عند استخدامها داخل "use" أو "no". معظم هذه الوحدات ذات نطاق معجمي، لذلك قد يبطلها نطاق داخلي بالقول:

no integer;
no strict 'refs';
no warnings;

والتي تستمر حتى نهاية ذلك النطاق (BLOCK).

بعض الوحدات النفعية ذات نطاق معجمي - عادةً تلك التي تؤثر على المتغير $^H (hints) - تؤثر وحدات أخرى على الحزمة الحالية بدلاً من ذلك، مثل "use vars" و "use subs"، والتي تسمح لك بتعريف مسبق للمتغيرات أو الروتينات الفرعية داخل ملف معين بدلاً من مجرد نطاق. هذه الإعلانات تكون فعالة للملف بأكمله الذي تم الإعلان عنها فيه. لا يمكنك إلغاؤها باستخدام "no vars" أو "no subs".

Modules may implement methods by loading dynamic C or C++ objects, or by using an `AUTOLOAD` function to load subroutine definitions on demand. Only the `.pm` file is required to exist.\n\n## Guidelines for Module Creation\n\n### Reuse Existing Modules\n\n* Check if similar modules already exist. Try to reuse them or inherit useful features.\n* If extending an existing set of modules, coordinate with the author and follow their naming and interaction schemes.\n\n### Design for Extensibility and Reusability\n\n* Use `use warnings;` (or `use warnings qw(...);`).\n* Use blessed references with the two-argument form of `bless`.\n* Pass arrays as references for future parameter additions.\n* Convert functions to methods where appropriate.\n* Split large methods into smaller, more flexible ones.\n* Inherit methods from other modules if suitable.\n* Avoid class name tests like `die \"Invalid\" unless ref $ref eq 'FOO'`. Let objects manage themselves.\n* Avoid hard-wired class names whenever possible.\n* Prefer inheritance (`@ISA`) over direct class method calls like `$r->Class::func()`.\n* Use autosplit for infrequently used or new functions to avoid burdening users.\n* Add test functions after `__END__` using AutoSplit or by evaluating `main::DATA`.\n* Ensure your module passes the 'empty subclass' test: a subclass should be usable exactly like the parent class.\n* Avoid keeping state information in packages; store it in objects.\n* Always use `-w` (implicit with `use warnings`).\n* Try to use `use strict;` (or `use strict qw(...);`).\n\n### Simple Style Guidelines\n\nRefer to the `perlstyle` manual for detailed style points.\n\n* **Variable Names:** Use underscores for readability (e.g., `$var_names_like_this`).\n* **Package/Module Names:** Normally start with a capital letter and use mixed case without underscores (e.g., `MyModule`). Lowercase names are reserved for pragmas (e.g., `strict`).\n* **Case Usage:**\n * `$ALL_CAPS_HERE`: Constants (beware clashes with Perl variables).\n * `$Some_Caps_Here`: Package-wide global/static variables.\n * `$no_caps_here`: Function-scoped `my()` or `local()` variables.\n* **Function/Method Names:** Generally all lowercase (e.g., `$obj->as_string()`).\n* **Internal Use:** Use a leading underscore for variables or functions intended for internal use within a package.\n\n### Select What to Export\n\n* **Do NOT export method names.**\n* **Do NOT export anything by default without a good reason.** Exports pollute the user's namespace.\n* Prefer `@EXPORT_OK` over `@EXPORT` to reduce the risk of name clashes.\n* Avoid short or common names for exported symbols.\n* Symbols not exported are accessible via `ModuleName::item_name` or `$blessed_ref->method()`.\n* Use a leading underscore informally to indicate 'internal' items.\n* If the module is object-oriented, export nothing.     إرشادات لتحويل نصوص مكتبة Perl 4 إلى وحدات

    • لا يوجد شرط لتحويل أي شيء.

      إذا لم يكن معطلاً، فلا تصلحه! يجب أن تستمر نصوص مكتبة Perl 4 في العمل دون مشاكل. قد تحتاج إلى إجراء بعض التغييرات الطفيفة (مثل الهروب من '@' غير المصفوفات في سلاسل الاقتباس المزدوج) ولكن لا حاجة لتحويل ملف .pl إلى وحدة لهذا الغرض فقط.

    • ضع في اعتبارك الآثار المترتبة.

      ستحتاج جميع تطبيقات Perl التي تستخدم النص إلى تغيير (بشكل طفيف) إذا تم تحويل النص إلى وحدة. هل الأمر يستحق ذلك إلا إذا كنت تخطط لإجراء تغييرات أخرى في نفس الوقت؟

    • استفد إلى أقصى حد من الفرصة.

      إذا كنت ستقوم بتحويل النص إلى وحدة، يمكنك استخدام الفرصة لإعادة تصميم الواجهة. تتضمن الإرشادات لإنشاء الوحدات أعلاه العديد من القضايا التي يجب أن تأخذها في الاعتبار.

    • الأداة المساعدة pl2pm ستبدأ لك.

      تقرأ هذه الأداة المساعدة ملفات *.pl (المعطاة كمعلمات) وتكتب ملفات *.pm المقابلة. تقوم الأداة pl2pm بما يلي:

    • تضيف أسطر المقدمة القياسية للوحدة
    • تحول مواصفات الحزمة من ' إلى ::
    • تحول die(...) إلى croak(...)
    • العديد من التغييرات الطفيفة الأخرى

    كونها عملية ميكانيكية، فإن pl2pm ليست مضمونة. سيحتاج الكود المحول إلى فحص دقيق، خاصة أي عبارات حزمة. لا تحذف ملف .pl الأصلي حتى يعمل ملف .pm الجديد!

    إرشادات لإعادة استخدام كود التطبيق

    • التطبيقات الكاملة نادرًا ما تنتمي إلى مكتبة وحدات Perl.
    • العديد من التطبيقات تحتوي على بعض كود Perl الذي يمكن إعادة استخدامه.

      ساعد في إنقاذ العالم! شارك الكود الخاص بك في شكل يسهل إعادة استخدامه.

    • فصل الكود القابل لإعادة الاستخدام في ملف واحد أو أكثر من ملفات الوحدات المنفصلة.
    • اغتنم الفرصة لإعادة النظر وإعادة تصميم الواجهات.
    • في بعض الحالات، يمكن بعد ذلك تقليل 'التطبيق' إلى جزء صغير

      من الكود المبني فوق الوحدات القابلة لإعادة الاستخدام. في هذه الحالات، يمكن استدعاء التطبيق على النحو التالي:

           % perl -e 'use Module::Name; method(@ARGV)' ...
or
     % perl -mModule::Name ...    (in perl5.002 or higher)

    ملاحظة

    لا تفرض Perl أجزاء خاصة وعامة من وحداتها كما قد تكون معتادًا عليها في لغات أخرى مثل C++ أو Ada أو Modula-17. Perl لا تمتلك هوسًا بالخصوصية القسرية. تفضل أن تظل خارج غرفة معيشتها لأنك لم تتم دعوتك، وليس لأنها تحمل بندقية.

    الوحدة ومستخدمها لديهما عقد، جزء منه قانون عرفي، وجزء منه "مكتوب". جزء من القانون العرفي هو أن الوحدة لا تلوث أي مساحة أسماء لم يُطلب منها ذلك. العقد المكتوب للوحدة (المعروف أيضًا بالتوثيق) قد يقدم أحكامًا أخرى. ولكنك تعلم بعد ذلك عندما "use RedefineTheWorld" أنك تعيد تعريف العالم وتتحمل العواقب.
