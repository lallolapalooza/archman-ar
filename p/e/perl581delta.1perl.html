Core Changes

Deferred Signals (Safe Signals)

Up to Perl 5.8.0, signal handlers were always executed immediately when the signal arrived. This could lead to problems if the signal arrived while Perl was in the middle of an operation that might get corrupted by an immediate interrupt. For example, string or numeric conversions that required internal data structures to be in a consistent state, or memory management operations. In the worst case this could lead to crashes.

Starting with Perl 5.8.1, signals are only processed when Perl is between opcodes. This means that signal handlers are no longer run immediately but instead "between opcodes", when it is safe to do so. The earlier immediate handling easily could corrupt the internal state of Perl, resulting in mysterious crashes.

However, the new safer model has its problems too. Because now an opcode, a basic unit of Perl execution, is never interrupted but instead let to run to completion, certain operations that can take a long time now really do take a long time. For example, certain network operations have their own blocking and timeout mechanisms, and being able to interrupt them immediately would be nice.

Therefore perl 5.8.1 introduces a "backdoor" to restore the pre-5.8.0 (pre-5.7.3, really) signal behaviour. Just set the environment variable PERL_SIGNALS to "unsafe", and the old immediate (and unsafe) signal handling behaviour returns. See "PERL_SIGNALS" in perlrun and "Deferred Signals (Safe Signals)" in perlipc.

In completely unrelated news, you can now use safe signals with POSIX::SigAction. See "POSIX::SigAction" in POSIX.

Tied Arrays with Negative Array Indices

Formerly, the indices passed to "FETCH", "STORE", "EXISTS", and "DELETE" methods in tied array class were always non-negative. If the actual argument was negative, Perl would call FETCHSIZE implicitly and add the result to the index before passing the result to the tied array method. This behaviour is now optional. If the tied array class contains a package variable named $NEGATIVE_INDICES which is set to a true value, negative values will be passed to "FETCH", "STORE", "EXISTS", and "DELETE" unchanged.

local ${$x}

The syntaxes

local ${$x}
local @{$x}
local %{$x}

now do localise variables, given that the $x is a valid variable name.

Unicode Character Database 4.0.0

The copy of the Unicode Character Database included in Perl 5.8 has been updated to 4.0.0 from 3.2.0. This means for example that the Unicode character properties are as in Unicode 4.0.0.

Deprecation Warnings

There is one new feature deprecation. Perl 5.8.0 forgot to add some deprecation warnings, these warnings have now been added. Finally, a reminder of an impending feature removal.

(Reminder) Pseudo-hashes are deprecated (really)

Pseudo-hashes were deprecated in Perl 5.8.0 and will be removed in Perl 5.10.0, see perl58delta for details. Each attempt to access pseudo-hashes will trigger the warning "Pseudo-hashes are deprecated". If you really want to continue using pseudo-hashes but not to see the deprecation warnings, use:

no warnings 'deprecated';

Or you can continue to use the fields pragma, but please don't expect the data structures to be pseudohashes any more.

(Reminder) 5.005-style threads are deprecated (really)

5.005-style threads (activated by "use Thread;") were deprecated in Perl 5.8.0 and will be removed after Perl 5.8, see perl58delta for details. Each 5.005-style thread creation will trigger the warning "5.005 threads are deprecated". If you really want to continue using the 5.005 threads but not to see the deprecation warnings, use:

no warnings 'deprecated';

(Reminder) The $* variable is deprecated (really)

The $* variable controlling multi-line matching has been deprecated and will be removed after 5.8. The variable has been deprecated for a long time, and a deprecation warning "Use of $* is deprecated" is given, now the variable will just finally be removed. The functionality has been supplanted by the "/s" and "/m" modifiers on pattern matching. If you really want to continue using the $*-variable but not to see the deprecation warnings, use:

no warnings 'deprecated';

Miscellaneous Enhancements

"map" in void context is no longer expensive. "map" is now context aware, and will not construct a list if called in void context.

If a socket gets closed by the server while printing to it, the client now gets a SIGPIPE. While this new feature was not planned, it fell naturally out of PerlIO changes, and is to be considered an accidental feature.

PerlIO::get_layers(FH) returns the names of the PerlIO layers active on a filehandle.

PerlIO::via layers can now have an optional UTF8 method to indicate whether the layer wants to "auto-:utf8" the stream.

utf8::is_utf8() has been added as a quick way to test whether a scalar is encoded internally in UTF-8 (Unicode).

تحسينات التثبيت والتهيئة

لم يعد موقع Perl القياسي في Unix، /usr/bin/perl، يتم الكتابة فوقه افتراضيًا إذا كان موجودًا. كان هذا التغيير حكيمًا جدًا لأن العديد من بائعي Unix يوفرون بالفعل /usr/bin/perl، ولكن في الوقت نفسه قد تعتمد العديد من أدوات النظام على هذا الإصدار المحدد من Perl، لذلك من الأفضل عدم الكتابة فوقه.

يمكن الآن تحديد مجلدات التثبيت لصفحات man و HTML الخاصة بالموقع والبائع، ولفقرات الموقع والبائع. انظر INSTALL.

يمكن الآن تحديد دليل وجهة لتثبيت Perl عن طريق تحديد متغير DESTDIR لـ "make install". (هذه الميزة تختلف قليلاً عن "Configure -Dinstallprefix=..." السابقة.) انظر INSTALL.

قدمت إصدارات gcc 3.x تحذيرًا جديدًا تسبب في الكثير من الضوضاء أثناء تجميع Perl: "gcc -Ialreadyknowndirectory (warning: changing search order)". تم الآن تجنب هذا التحذير عن طريق قيام Configure بالتخلص من مثل هذه الدلائل قبل التجميع.

يمكن الآن بناء مجموعات فرعية من وحدات Perl الأساسية باستخدام أعلام Configure "-Dnoextensions=..." و "-Donlyextensions=..."، انظر INSTALL.

إصلاحات أخطاء مختارة

الإغلاقات، eval، والكلمات المتغيرة

كانت هناك العديد من الإصلاحات في مجال الوظائف الفرعية المجهولة، والكلمات المتغيرة، والإغلاقات. على الرغم من أن هذا يعني أن Perl أصبح الآن "أكثر صحة"، فمن الممكن أن يتعطل بعض الكود الحالي الذي يعتمد بالصدفة على السلوك الخاطئ. في الواقع، هذا غير مرجح ما لم يكن الكود الخاص بك يحتوي على تداخل معقد جدًا للوظائف الفرعية المجهولة، وعمليات eval، والكلمات المتغيرة.

إصلاحات عامة

إذا تم تمييز مقبض ملف إدخال ":utf8" ورأى Perl UTF-8 غير صالح قادمًا عند القيام بـ "<FH>"، فإذا تم تمكين التحذيرات، يتم إصدار تحذير على الفور - بدلاً من الصمت بشأنه وكون Perl غير راضٍ عن البيانات المعطلة لاحقًا. (الطبقة :encoding(utf8) تعمل بنفس الطريقة.)

binmode(SOCKET, ":utf8") كان يعمل فقط على جانب الإدخال، وليس على جانب الإخراج للمقبس. الآن يعمل في كلا الاتجاهين.

بالنسبة لـ Perl الخيوطي، تنمو بعض دوال قاعدة البيانات النظامية مثل getpwent() و getgrent() الآن بشكل ديناميكي المخزن المؤقت للنتائج، بدلاً من الفشل. هذا يعني أنه في المواقع التي تضم عددًا كبيرًا من المستخدمين والمجموعات، لم تعد الدوال تفشل عن طريق إرجاع نتائج جزئية فقط.

في Perl 5.8.0، تم عن طريق الخطأ كسر قدرة المستخدمين على تعريف تعيينات Unicode الخاصة بهم من الأحرف الكبيرة إلى الصغيرة (كما هو معلن عنه في Camel). تم إصلاح هذه الميزة وهي موثقة بشكل أفضل أيضًا.

في 5.8.0، كان هذا

$some_unicode .= <FH>;

لم يعمل بشكل صحيح بل أفسد البيانات. تم إصلاح هذا الآن.

قد تقوم طرق Tied مثل FETCH وما إلى ذلك الآن بالوصول بأمان إلى القيم المرتبطة، أي أنها تؤدي إلى استدعاء متكرر لـ FETCH وما إلى ذلك. تذكر كسر التكرار، مع ذلك.

عند بدء التشغيل، يقوم Perl بحظر إشارة SIGFPE لأنه لا يوجد الكثير مما يمكن لـ Perl فعله بشأنها. سابقًا، كان هذا الحظر ساري المفعول أيضًا للبرامج التي تم تنفيذها من داخل Perl. الآن يستعيد Perl روتين معالجة SIGFPE الأصلي، مهما كان، قبل تشغيل البرامج الخارجية.

يمكن أن تكون أرقام الأسطر في نصوص Perl الآن أكبر من 65536، أو 2**16. (كانت نصوص Perl دائمًا قادرة على أن تكون أكبر من ذلك، فقط أن رقم السطر للأخطاء والتحذيرات المبلغ عنها قد "دار"). في حين أن النصوص الكبيرة جدًا تشير عادةً إلى الحاجة إلى إعادة التفكير في الكود الخاص بك قليلاً، فإن مثل هذه النصوص Perl موجودة، على سبيل المثال، كنتائج للكود الذي تم إنشاؤه. الآن يمكن أن تصل أرقام الأسطر إلى 4294967296، أو 2**32.

إذا كنت ترغب في استخدام mod_perl 2.x مع Perl 5.8.1، فستحتاج إلى mod_perl-1.99_10 أو أعلى. الإصدارات الأقدم من mod_perl 2.x لا تعمل مع الهاشات العشوائية. (mod_perl 1.x يعمل بشكل جيد.) ستحتاج أيضًا إلى Apache::Test 1.04 أو أعلى.

تم ترك العديد من المنصات النادرة التي كانت تعمل بنسبة 100٪ أو قريبة جدًا منها مع perl 5.8.0 بدون رعاية قليلاً منذ أن كان المسؤولون عنها مشغولين بأمور أخرى مؤخرًا، وبالتالي ستكون هناك المزيد من حالات الفشل على تلك المنصات. تشمل هذه المنصات Mac OS Classic و IBM z/OS (وغيرها من منصات EBCDIC) و NetWare. المنصات الأكثر شيوعًا في Perl (Unix والشبيهة بـ Unix، ومنصات Microsoft، و VMS) لديها اختبارات كافية وسكان خبراء بحيث أنها تعمل بشكل جيد.

تجزئات مرتبطة في سياق عددي

تجزئات مرتبطة لا تُرجع حاليًا أي شيء مفيد في سياق عددي، على سبيل المثال عند استخدامها كاختبارات منطقية:

if (%tied_hash) { ... }

السلوك غير المنطقي الحالي هو دائمًا إرجاع خطأ، بغض النظر عما إذا كانت التجزئة فارغة أو تحتوي على عناصر.

السبب الجذري هو عدم وجود واجهة لمنفذي تجزئات مرتبطة لتنفيذ سلوك تجزئة في سياق عددي.

فشل Net::Ping 450_service و 510_ping_udp

قد تفشل الاختبارات الفرعية 9 و 18 من lib/Net/Ping/t/450_service.t، والاختبار الفرعي 2 من lib/Net/Ping/t/510_ping_udp.t إذا كان لديك إعداد شبكة غير عادي. على سبيل المثال، في الحالة الأخيرة، يحاول الاختبار إرسال اختبار UDP إلى عنوان IP 127.0.0.1.

HP-UX: تحذيرات HP cc حول sendfile و sendpath

مع إصدارات معينة من مترجم HP C (مثل B.11.11.02) ستتلقى العديد من التحذيرات مثل هذه (تم التفاف الأسطر لسهولة القراءة):

cc: "/usr/include/sys/socket.h", line 504: warning 562:
  Redeclaration of "sendfile" with a different storage class specifier:
    "sendfile" will have internal linkage.
cc: "/usr/include/sys/socket.h", line 505: warning 562:
  Redeclaration of "sendpath" with a different storage class specifier:
    "sendpath" will have internal linkage.

تظهر التحذيرات أثناء بناء Perl وأثناء بعض اختبارات lib/ExtUtils التي تستدعي مترجم C. ومع ذلك، فإن التحذير ليس خطيرًا ويمكن تجاهله.

IRIX: t/uni/tr_7jis.t يفشل بشكل خاطئ

من المعروف أن الاختبار t/uni/tr_7jis.t يبلغ عن فشل أثناء 'make test' أو في نظام الاختبار مع إصدارات معينة من IRIX (على الأقل IRIX 6.5 ومترجمات MIPSpro الإصدار 7.3.1.1m)، ولكن عند تشغيله يدويًا، يجتاز الاختبار بالكامل.

Mac OS X: لا يوجد usemymalloc

مدير تخصيص الذاكرة في Perl ("-Dusemymalloc") لا يعمل على الإطلاق في Mac OS X. ومع ذلك، هذا ليس خطيرًا جدًا، لأن مدير تخصيص الذاكرة الأصلي يعمل بشكل جيد.

Tru64: لا توجد عمليات بناء متوازية مع GNU cc (gcc)

في أحدث إصدارات Tru64 (مثل v5.1B أو أحدث)، لا يمكن استخدام gcc لتجميع Perl متوازي (-Duseithreads) لأن ملف "<pthread.h>" الخاص بالنظام لا يعرف عن gcc.

Win32: sysopen، sysread، syswrite

اعتبارًا من الإصدار 5.8.0، لا تعمل sysopen()/sysread()/syswrite() كما كانت في السابق في 5.6.1 والإصدارات الأقدم فيما يتعلق بوضع "النص". تعمل هذه الدوال المضمنة الآن دائمًا في وضع "ثنائي" (حتى لو تم تمرير علامة O_TEXT إلى sysopen()، أو إذا تم استخدام binmode() على مقبض الملف). لاحظ أن هذه المشكلة يجب أن تحدث فرقًا فقط لملفات الأقراص، حيث كانت المقابس والأنابيب دائمًا في وضع "ثنائي" في منفذ Windows. نظرًا لأن هذا السلوك يعتبر حاليًا خطأ، فقد تتم إعادة تقديم سلوك متوافق في إصدار مستقبلي. حتى ذلك الحين، لا يدعم استخدام sysopen() و sysread() و syswrite() لعمليات وضع "النص".

الاتجاهات المستقبلية

الأشياء التالية قد تحدث في المستقبل. ستكون الإصدارات الأولى المتاحة للجمهور التي تتمتع بهذه الخصائص هي إصدارات المطورين Perl 5.9.x، والتي ستتوج بالإصدار Perl 5.10.0. هذه هي أفضل تخميناتنا في الوقت الحالي: نحتفظ بالحق في إعادة التفكير.

  • سيصبح PerlIO هو الافتراضي. حاليًا (في Perl 5.8.x) لا يزال يتم استخدام مكتبة stdio إذا اعتقد Perl أنه يمكنه استخدام حيل معينة لجعل stdio يعمل بسرعة فائقة. بالنسبة للإصدارات المستقبلية، هدفنا هو جعل PerlIO أسرع.
  • ستكون ميزة جديدة تسمى assertions متاحة. هذا يعني أنه يمكن أن يكون لديك رمز يسمى assertions مبعثرًا في الكود: عادةً ما يتم تحسينها، ولكن يمكن تمكينها باستخدام الخيار "-A".
  • سيكون عامل تشغيل جديد "//" (عرف-أو) متاحًا. هذا يعني أنه سيكون بإمكانك كتابة 
    $a // $b

    بدلاً من

    defined $a ? $a : $b

    و

    $c //= $d;

    بدلاً من

    $c = $d unless defined $c;

    سيكون للعامل الأسبقية والترابط نفس "||". سيكون تصحيح الكود المصدري ضد مصادر Perl 5.8.1 متاحًا في CPAN باسم authors/id/H/HM/HMBRAND/dor-5.8.1.diff.

  • سيتم تفكيك unpack() افتراضيًا من $_.
  • سيتم التحقيق في تقنيات Copy-On-Write المختلفة على أمل تسريع Perl.
  • ستصبح CPANPLUS و Inline و Module::Build وحدات أساسية.
  • سيتم تقديم القدرة على كتابة pragma حقيقية ذات نطاق معجمي.
  • سيستمر العمل على مترجم البايت ومحمل البايت.
  • من المقرر إيقاف استخدام السلاسل v كما هي موجودة حاليًا. سيصبح الشكل الخالي من v (1.2.3) "كائن إصدار" عند استخدامه مع "use" و "require" و $VERSION. سيكون $^V أيضًا "كائن إصدار" لذلك لن تكون هناك حاجة لبناء printf("%vd",...) بعد الآن. سيصبح الإصدار الممتلئ بـ v (v1.2.3) قديمًا. سيختفي تكافؤ السلاسل والسلاسل v (على سبيل المثال، أن 5.8.0 حاليًا يساوي "\5\8\0"). قد لا يكون هناك تحذير إيقاف استخدام للسلاسل v، لأنه من الصعب جدًا اكتشاف متى يتم استخدام السلاسل v بأمان، ومتى لا يتم استخدامها.
  • سيتم إزالة Threads 5.005
  • سيتم إزالة المتغير $* (تم إيقافه منذ فترة طويلة)
  • سيتم إزالة Pseudohashes

الإبلاغ عن الأخطاء

إذا وجدت ما تعتقد أنه خطأ، فقد ترغب في التحقق من المقالات المنشورة مؤخرًا في مجموعة الأخبار comp.lang.perl.misc وقاعدة بيانات أخطاء Perl على http://bugs.perl.org/ . قد تكون هناك أيضًا معلومات على http://www.perl.com/ ، الصفحة الرئيسية لـ Perl.

إذا كنت تعتقد أن لديك خطأ لم يتم الإبلاغ عنه، فيرجى تشغيل البرنامج perlbug المضمن مع إصدارك. تأكد من تقليص خطئك إلى حالة اختبار صغيرة ولكن كافية. سيتم إرسال تقرير خطأك، جنبًا إلى جنب مع مخرجات "perl -V"، إلى perlbug@perl.org ليتم تحليلها بواسطة فريق نقل Perl. يمكنك تصفح والبحث عن أخطاء Perl 5 على http://bugs.perl.org/
