الاسم

perlreapi - واجهة توصيل التعبيرات النمطية لـ Perl

الوصف

اعتبارًا من Perl 5.9.5، يوجد واجهة جديدة لتوصيل واستخدام محركات تعبيرات نمطية غير الافتراضية.

يُفترض أن يوفر كل محرك وصولاً إلى بنية ثابتة بالتنسيق التالي:

typedef struct regexp_engine {
    REGEXP* (*comp) (pTHX_
                     const SV * const pattern, const U32 flags);
    I32     (*exec) (pTHX_
                     REGEXP * const rx,
                     char* stringarg,
                     char* strend, char* strbeg,
                     SSize_t minend, SV* sv,
                     void* data, U32 flags);
    char*   (*intuit) (pTHX_
                       REGEXP * const rx, SV *sv,
                       const char * const strbeg,
                       char *strpos, char *strend, U32 flags,
                       struct re_scream_pos_data_s *data);
    SV*     (*checkstr) (pTHX_ REGEXP * const rx);
    void    (*free) (pTHX_ REGEXP * const rx);
    void    (*numbered_buff_FETCH) (pTHX_
                                    REGEXP * const rx,
                                    const I32 paren,
                                    SV * const sv);
    void    (*numbered_buff_STORE) (pTHX_
                                    REGEXP * const rx,
                                    const I32 paren,
                                    SV const * const value);
    I32     (*numbered_buff_LENGTH) (pTHX_
                                     REGEXP * const rx,
                                     const SV * const sv,
                                     const I32 paren);
    SV*     (*named_buff) (pTHX_
                           REGEXP * const rx,
                           SV * const key,
                           SV * const value,
                           U32 flags);
    SV*     (*named_buff_iter) (pTHX_
                                REGEXP * const rx,
                                const SV * const lastkey,
                                const U32 flags);
    SV*     (*qr_package)(pTHX_ REGEXP * const rx);
#ifdef USE_ITHREADS
    void*   (*dupe) (pTHX_ REGEXP * const rx, CLONE_PARAMS *param);
#endif
    REGEXP* (*op_comp) (...);

عند تجميع تعبير نمطي، يتم تعيين حقله "engine" ليشير إلى البنية المناسبة، بحيث عندما يحتاج إلى الاستخدام، يمكن لـ Perl العثور على الروتينات الصحيحة للقيام بذلك.

لتثبيت معالج تعبيرات نمطية جديد، يتم تعيين $^H{regcomp} إلى عدد صحيح (عند تحويله بشكل مناسب) يؤدي إلى أحد هذه الهياكل. عند التجميع، يتم تنفيذ طريقة "comp"، ومن المتوقع أن يشير حقل "engine" الخاص ببنية "regexp" الناتجة مرة أخرى إلى نفس البنية.

الرمز pTHX_ في التعريف هو ماكرو تستخدمه Perl تحت تعدد الخيوط لتوفير وسيط إضافي للروتين الذي يحمل مؤشرًا يعود إلى المفسر الذي ينفذ التعبير النمطي. لذا، تحت تعدد الخيوط، تحصل جميع الروتينات على وسيط إضافي.

الاستدعاءات

comp

REGEXP* comp(pTHX_ const SV * const pattern, const U32 flags);

قم بتجميع النمط المخزن في "pattern" باستخدام "flags" المعطاة وإرجاع مؤشر إلى بنية "REGEXP" مُجهزة يمكنها إجراء المطابقة. راجع "بنية REGEXP" أدناه للحصول على شرح للحقول الفردية في هيكل REGEXP.

المعلمة "pattern" هي القياسية التي تم استخدامها كنمط. كانت الإصدارات السابقة من Perl تمرر مؤشرين "char*" يشيران إلى بداية ونهاية النمط المُمثّل كسلسلة نصية؛ يمكن استخدام المقتطف التالي للحصول على المعلمات القديمة:

STRLEN plen;
char*  exp = SvPV(pattern, plen);
char* xend = exp + plen;

نظرًا لأنه يمكن تمرير أي قياسية كنمط، فمن الممكن تنفيذ محرك يقوم بشيء ما مع مصفوفة (""ook" =~ [ qw/ eek hlagh / ]") أو مع الشكل غير المُمثّل كسلسلة نصية لتعبير نمطي مُجمّع (""ook" =~ qr/eek/"). سيقوم محرك Perl دائمًا بتمثيل كل شيء كسلسلة نصية باستخدام المقتطف أعلاه، ولكن هذا لا يعني أن المحركات الأخرى يجب أن تفعل ذلك.

المعلمة "flags" هي حقل بت يشير إلى أي من علامات "msixpn" تم تجميع التعبير النمطي بها. كما أنها تحتوي على معلومات إضافية، مثل ما إذا كانت "use locale" مفعلة.

يتم تجريد علامات "eogc" قبل تمريرها إلى طريقة comp. لا يحتاج محرك التعبير النمطي إلى معرفة ما إذا كانت أي من هذه العلامات مضبوطة، حيث يجب أن تؤثر هذه العلامات فقط على ما تفعله Perl بالنمط ومتغيرات المطابقة الخاصة به، وليس كيفية تجميعها وتنفيذها.

بحلول الوقت الذي يتم فيه استدعاء استدعاء comp، كان لبعض هذه العلامات تأثير بالفعل (ملاحظة أدناه حيثما ينطبق ذلك). ومع ذلك، يحدث معظم تأثيرها بعد انتهاء استدعاء comp، في الروتينات التي تقرأ حقل "rx->extflags" الذي تقوم بتعبئته.

بشكل عام، يجب الاحتفاظ بالعلامات في "rx->extflags" بعد التجميع، على الرغم من أن محرك التعبير النمطي قد يرغب في إضافة أو حذف بعضها لتفعيل أو تعطيل سلوك خاص في Perl. تم توثيق العلامات مع أي سلوك خاص تسببه أدناه:

"extflags"

سيستخدم هذا بواسطة Perl لمعرفة الأعلام التي تم تجميع التعبير العادي بها، وسيتم تعيين هذا عادةً إلى قيمة معلمة `comp` بواسطة رد الاتصال `comp`. راجع توثيق `comp` للأعلام الصالحة.

"minlen" "minlenret"

الحد الأدنى لطول السلسلة (بالأحرف) المطلوب لمطابقة النمط. يستخدم هذا لتقليم مساحة البحث عن طريق عدم الإزعاج بالمطابقة بالقرب من نهاية السلسلة أكثر مما يسمح بالمطابقة. على سبيل المثال، لا فائدة من بدء محرك التعبير العادي إذا كان `minlen` هو 10 ولكن السلسلة طولها 5 أحرف فقط. لا توجد طريقة يمكن للنمط أن يطابق بها.

`"minlenret"` هو الحد الأدنى للطول (بالأحرف) للسلسلة التي سيتم العثور عليها في $& بعد المطابقة.

يمكن رؤية الفرق بين `"minlen"` و `"minlenret"` في النمط التالي:

/ns(?=\d)/

حيث سيكون `"minlen"` هو 3 ولكن `"minlenret"` سيكون فقط 2 حيث أن `\d` مطلوب لمطابقته ولكنه غير مضمن فعليًا في المحتوى المطابق. هذا التمييز مهم بشكل خاص لأن منطق الاستبدال يستخدم `"minlenret"` لمعرفة ما إذا كان يمكنه إجراء استبدالات في المكان (والتي يمكن أن تؤدي إلى تسريع كبير).

"gofs"

الإزاحة اليسرى من `pos()` لبدء المطابقة عندها.

"substrs"

بيانات السلسلة الفرعية حول السلاسل التي يجب أن تظهر في المطابقة النهائية. يستخدم هذا حاليًا داخليًا فقط بواسطة محرك Perl، ولكن قد يتم استخدامه في المستقبل لجميع المحركات لتحسينات.

"nparens", "logical_nparens"

تستخدم هذه الحقول لتتبع عدد مجموعات التقاط الأقواس المادية والمنطقية، والتي قد تختلف إذا كان النمط يتضمن استخدام بناء إعادة تعيين الفرع `"(?| ... | ... )"`. على سبيل المثال، النمط `/(?|(foo)|(bar))/` يحتوي على مخزنين مؤقتين للالتقاط ماديين، ولكن مخزن مؤقت التقاط منطقي واحد فقط. معظم منطق العمليات الداخلية في محرك التعبير العادي يستخدم معرفات مخزن التقاط الالتقاط المادي، ولكن المنطق المكشوف للمستخدم يستخدم معرفات مخزن التقاط الالتقاط المنطقية. راجع القسم التالي لهياكل البيانات التي تسمح بالتحويل من أحدهما إلى الآخر.

"logical_to_parno", "parno_to_logical", "parno_to_logical_next"

تسهل هذه الحقول التحويل بين أرقام مخزن التقاط الالتقاط المنطقية والمادية. `"logical_to_parno"` هي مصفوفة يحتوي عنصرها Kth على أقل معرف مخزن التقاط التقاط مادي للمخزن الالتقاط المنطقي Kth. `"parno_to_logical"` هي مصفوفة يحتوي عنصرها Kth على مخزن التقاط الالتقاط المنطقي المرتبط بمخزن الالتقاط المادي Kth. `"parno_to_logical_next"` هي مصفوفة يحتوي عنصرها Kth على مخزن التقاط الالتقاط المادي التالي بنفس معرف الالتقاط المنطقي، أو 0 إذا لم يكن هناك.

لاحظ أن جميع هذه المصفوفات الثلاثة يتم تعبئتها فقط عندما يتضمن النمط استخدام مفهوم إعادة تعيين الفرع. الأنماط التي لا تستخدم إعادة تعيين الفرع يكون لها فعليًا تعيين 1:1 بين المنطقي والمادي، لذلك لا حاجة لهذه البيانات الوصفية.

الجدول التالي يقدم مثالًا على كيفية عمل ذلك.

Pattern /(a) (?| (b) (c) (d) | (e) (f) | (g) ) (h)/
Logical: $1      $2  $3  $4    $2  $3    $2    $5
Physical: 1       2   3   4     5   6     7     8
Next:     0       5   6   0     7   0     0     0

لاحظ أيضًا أن العنصر 0 من أي من هذه المصفوفات لا يتم استخدامه حيث أنه يمثل "النمط الكامل".

"lastparen", and "lastcloseparen"

تستخدم هذه الحقول لتتبع: أي قوس كان الأعلى الذي تم إغلاقه (انظر "$+" في `perlvar`)؛ وأي قوس كان الأكثر حداثة الذي تم إغلاقه (انظر "$^N" في `perlvar`).

"intflags"

نسخة المحرك الخاصة بالأعلام التي تم تجميع النمط بها. عادةً ما تكون هذه هي نفس `"extflags"` ما لم يقرر المحرك تعديل أحدها.

"pprivate"

مؤشر `void*` يشير إلى بنية بيانات محددة بواسطة المحرك. يستخدم محرك Perl البنية `"regexp_internal"` (انظر "Base Structures" في `perlreguts`) ولكن يجب على محرك مخصص استخدام شيء آخر.

"offs"

بنية `"regexp_paren_pair"` تحدد الإزاحات في السلسلة التي تتم مطابقتها والتي تتوافق مع الالتقاطات `$&` و `$1`، `$2` إلخ، يتم تعريف بنية `"regexp_paren_pair"` على النحو التالي:

typedef struct regexp_paren_pair {
    I32 start;
    I32 end;
} regexp_paren_pair;

إذا كان `"->offs[num].start"` أو `"->offs[num].end"` هو `-1` فهذا يعني أن مجموعة الالتقاط لم تتطابق. يمثل `"->offs[0].start/end"` `$&` (أو `"${^MATCH}"` تحت `"/p"`) ويتطابق `"->offs[paren].end"` مع `$$paren` حيث ` $paren` = 1>.

"RX_PRECOMP" "RX_PRELEN"

تستخدم لتحسينات الأداء. `"RX_PRECOMP"` يحمل نسخة من النمط الذي تم تجميعه و `"RX_PRELEN"` طوله. عندما يتم تجميع نمط جديد (مثل داخل حلقة) فإن عامل التشغيل الداخلي `"regcomp"` يتحقق مما إذا كان `"RX_PRECOMP"` و `"RX_PRELEN"` الخاص بـ `"REGEXP"` المجمعة مؤخرًا مكافئان للجديد، وإذا كان الأمر كذلك فإنه يستخدم النمط القديم بدلاً من تجميع نمط جديد.

في الإصدارات القديمة من Perl، كان هذان الماكروان في الواقع حقلين في البنية بالاسمين `"precomp"` و `"prelen"` على التوالي.

"paren_names"

هذه خريطة تستخدم داخليًا لتتبع أسماء مجموعات الالتقاط وإزاحاتها. المفاتيح هي أسماء المخازن المؤقتة والقيم هي متغيرات مزدوجة، مع احتواء خانة IV على عدد المخازن المؤقتة بالاسم المعطى و pv هو مصفوفة مدمجة من I32. قد يتم أيضًا احتواء القيم بشكل مستقل في مصفوفة البيانات في الحالات التي يتم فيها استخدام المراجع الخلفية المسماة.

"substrs"

تحتوي على معلومات حول أطول سلسلة يجب أن تظهر في إزاحة ثابتة من بداية النمط، وأطول سلسلة يجب أن تظهر في إزاحة عائمة من بداية النمط. تستخدم لإجراء بحث Fast-Boyer-Moore على السلسلة لمعرفة ما إذا كان الأمر يستحق استخدام محرك التعبير العادي على الإطلاق، وإذا كان الأمر كذلك ففي أي مكان في السلسلة للبحث.

"subbeg" "sublen" "saved_copy" "suboffset" "subcoffset"

تستخدم أثناء مرحلة التنفيذ لإدارة أنماط البحث والاستبدال، ولتوفير النص لـ `$&`، `$1` إلخ. يشير `"subbeg"` إلى مخزن مؤقت (إما السلسلة الأصلية، أو نسخة في حالة `RX_MATCH_COPIED(rx_sv)`), و `"sublen"` هو طول المخزن المؤقت. وحدات الماكرو `"RX_OFFS_START(rx_sv,n)"` و `"RX_OFFS_END(rx_sv,n)"` تشير إلى هذا المخزن المؤقت. وكذلك تفعل البنية التي تم إرجاعها بواسطة `RX_OFFSp(rx_sv)` ولكن يجب ألا تستخدم ذلك مباشرة.

في وجود علامة `"REXEC_COPY_STR"`، ولكن مع إضافة علامات `"REXEC_COPY_SKIP_PRE"` أو `"REXEC_COPY_SKIP_POST"`، يمكن للمحرك

perlreapi - Perl API for Regular Expressions

NAME

perlreapi - Perl API for Regular Expressions

DESCRIPTION

This document describes the API for implementing Perl regular expression engines. This includes the structures and callbacks that Perl uses to interact with an engine.

Callbacks

This is a list of the callbacks that a custom regular expression engine must provide. These are passed to Perl via the "regcomp" function.

regcomp
Compile a regular expression. Takes a string and returns a "REGEXP" structure. May set "RXf_PMf_KEEPCOPY" if the string must be copied.
regfree
Free a compiled regular expression.
regexec
Execute a compiled regular expression against a string.
regfree_backup
Free the backup copy of a compiled regular expression.
regclone
Clone a compiled regular expression.
regduplicate
Duplicate a compiled regular expression.
reg_set_paren_bit
Set a bit in the parenthesis capture information.
reg_get_paren_bit
Get a bit in the parenthesis capture information.
reg_set_paren_num
Set the number of a parenthesis capture.
reg_get_paren_num
Get the number of a parenthesis capture.
reg_set_paren_count
Set the total number of parenthesis captures.
reg_get_paren_count
Get the total number of parenthesis captures.
reg_set_paren_start
Set the starting position of a parenthesis capture.
reg_get_paren_start
Get the starting position of a parenthesis capture.
reg_set_paren_end
Set the ending position of a parenthesis capture.
reg_get_paren_end
Get the ending position of a parenthesis capture.
reg_set_paren_len
Set the length of a parenthesis capture.
reg_get_paren_len
Get the length of a parenthesis capture.
reg_set_paren_capture_count
Set the number of captures within a parenthesis group.
reg_get_paren_capture_count
Get the number of captures within a parenthesis group.
reg_set_paren_name
Set the name of a parenthesis capture.
reg_get_paren_name
Get the name of a parenthesis capture.
reg_set_paren_name_map
Set the map of names to parenthesis captures.
reg_get_paren_name_map
Get the map of names to parenthesis captures.
reg_set_paren_highest_bit
Set the highest bit used in parenthesis captures.

The REGEXP structure

This is the structure that holds the compiled regular expression. It is opaque to the user, but the engine has access to its members.

The following members are relevant:

RXf_PMf_KEEPCOPY
A flag indicating whether the input string should be copied. If this is set, the engine should copy the string and return a pointer to the copy. Otherwise, it can use the original string.
PL_sawampersand
A flag indicating whether the last match involved "&". This is used to determine whether to copy the matched string.
suboffset
The offset from the logical start of the buffer to the physical start. This is used when the buffer is not contiguous (e.g., when using "IO::AIO").
subcoffset
The number of characters in the suboffset. This is needed to support character-based offsets like "@-" and "@+".

An engine may choose not to copy the full buffer (although it must still do so in the presence of "RXf_PMf_KEEPCOPY" or the relevant bits being set in "PL_sawampersand"). In this case, it may set "suboffset" to indicate the number of bytes from the logical start of the buffer to the physical start (i.e. "subbeg"). It should also set "subcoffset", the number of characters in the offset. The latter is needed to support "@-" and "@+" which work in characters, not bytes.

"RX_WRAPPED" "RX_WRAPLEN"

Macros which access the string the "qr//" stringifies to. The Perl engine for example stores "(?^:eek)" in the case of "qr/eek/".

When using a custom engine that doesn't support the "(?:)" construct for inline modifiers, it's probably best to have "qr//" stringify to the supplied pattern, note that this will create undesired patterns in cases such as:

my $x = qr/a|b/;  # "a|b"
my $y = qr/c/i;   # "c"
my $z = qr/$x$y/; # "a|bc"

There's no solution for this problem other than making the custom engine understand a construct like "(?:)".

RX_REFCNT()

The number of times the structure is referenced. When this falls to 0, the regexp is automatically freed by a call to "pregfree". This should be set to 1 in each engine's "comp" routine. Note that in older perls this was a member in the struct called "refcnt" but in more modern perls where the regexp structure was unified with the SV structure this is an alias to SvREFCNT().
