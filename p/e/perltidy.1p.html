-xbt, --extended-block-tightness
There are two controls for spacing within curly braces, namely --block-brace-tightness=n for code block braces and --brace-tightness=n for all other braces.

There is a little fuzziness in this division of brace types though because the curly braces considered by perltidy to contain code blocks for formatting purposes, such as highlighting code structure, exclude some of the small code blocks used by Perl mainly for isolating terms. These include curly braces following a keyword where an indirect object might occur, or curly braces following a type symbol. For example, perltidy does not mark the following braces as code block braces:

print {*STDERR} $message;
return ${$foo};

Consequently, the spacing within these small braced containers by default follows the flag --brace-tightness=n rather than --block-brace-tightness=n, as one might expect.

If desired, small blocks such as these can be made to instead follow the spacing defined by the --block-brace-tightness=n flag by setting --extended-block-tightness. The specific types of small blocks to which this parameter applies is controlled by a companion control parameter, described in the next section.

Note that if the two flags --block-brace-tightness=n and --brace-tightness=n have the same value n then there would be no reason to set this flag.

-xbtl=s, --extended-block-tightness-list=s
The previous parameter --extended-block-tightness (-xbt) can be made to apply to curly braces preceded by any of the keywords 
print printf exec system say

and/or the special symbols

$ @ % & * $#

The parameter string s may contain a selection of these keywords and symbols to indicate the brace types to which --extended-block-tightness applies. For convenience, all of the keywords can be selected with 'k', and all of the special symbols can be selected with 't'. The default is equivalent to -xbtl='k', which selects all of the keywords.

Examples:

-xbtl='k'          # selects just the keywords [DEFAULT]
-xbtl="t"          # selects just the special type symbols
-xbtl="k t"        # selects all keywords and symbols, or simply
-xbtl="kt"         # selects all keywords and symbols
-xbtl="print say"  # selects just keywords B<print> and B<say>:

Here are some formatting examples using the default values of --brace-tightness=n and --block-brace-tightness=n. Note that in these examples $ref is in block braces but $key is not.

# default formatting
print {*STDERR} $message;
my $val = ${$ref}{$key};
# perltidy -xbt           or
# perltidy -xbt -xbtl=k
print { *STDERR } $message;
my $val = ${$ref}{$key};
# perltidy -xbt -xbtl=t
print {*STDERR} $message;
my $val = ${ $ref }{$key};
# perltidy -xbt -xbtl=kt
print { *STDERR } $message;
my $val = ${ $ref }{$key};

Finally, note that this parameter merely changes the way that the parameter --extended-block-tightness works. It has no effect unless --extended-block-tightness is actually set.

-tso, --tight-secret-operators
The flag -tso causes certain perl token sequences (secret operators) which might be considered to be a single operator to be formatted "tightly" (without spaces). The operators currently modified by this flag are:

For example the sequence 0 +, which converts a string to a number, would be formatted without a space: 0+ when the -tso flag is set. This flag is off by default.

Detailed whitespace controls around tokens
For those who want more detailed control over the whitespace around tokens, there are four parameters which can directly modify the default whitespace rules built into perltidy for any token. They are:

-wls=s or --want-left-space=s,

-nwls=s or --nowant-left-space=s,

-wrs=s or --want-right-space=s,

-nwrs=s or --nowant-right-space=s.

These parameters are each followed by a quoted string, s, containing a list of token types. No more than one of each of these parameters should be specified, because repeating a command-line parameter always overwrites the previous one before perltidy ever sees it.

To illustrate how these are used, suppose it is desired that there be no space on either side of the token types = + - / *. The following two parameters would specify this desire:

-nwls="= + - / *"    -nwrs="= + - / *"

(Note that the token types are in quotes, and that they are separated by spaces). With these modified whitespace rules, the following line of math:

$root = -$b + sqrt( $b * $b - 4. * $a * $c ) / ( 2. * $a );

becomes this:

$root=-$b+sqrt( $b*$b-4.*$a*$c )/( 2.*$a );

These parameters should be considered to be hints to perltidy rather than fixed rules, because perltidy must try to resolve conflicts that arise between them and all of the other rules that it uses. One conflict that can arise is if, between two tokens, the left token wants a space and the right one doesn't. In this case, the token not wanting a space takes priority.

It is necessary to have a list of all token types in order to create this type of input. Such a list can be obtained by the command --dump-token-types. Also try the -D flag on a short snippet of code and look at the .DEBUG file to see the tokenization.

To illustrate, suppose we do not want a space after a colon which introduces a sub attribute. We need to know its type. It is not a colon because that is the type of a ternary operator. The output of --dump-token-types states that it is token type 'A'. To verify this, we can run "perltidy -D" on a short piece of code containing such a colon, such as

sub foo : lvalue;

This produces a .DEBUG file which contains

1: sub foo : lvalue;
1: SSSSSSSbAbwwwwww;

The top line is the input, and the bottom line shows the token types. The 'A' beneath the colon verifies that it is type A.

So to prevent a space on the right of this colon we can use

# perltidy -nwrs='A'
sub foo :lvalue;

WARNING Be sure to put these tokens in quotes to avoid having them misinterpreted by your command shell.

Note1: Perltidy does always follow whitespace controls
The various parameters controlling whitespace within a program are requests which perltidy follows as well as possible, but there are a number of situations where changing whitespace could change program behavior and is not done.

عند تعيين هذه العلامة، ولم يتم تعطيل تخطي الكود، يبدأ تخطي الكود من بداية الملف على الرغم من عدم وجود تعليق بداية لتخطي الكود. بعبارة أخرى، تعيين هذه العلامة يشبه وجود سطر بداية العلامة '#<<V' قبل السطر الأول من الملف مباشرة. سيستمر تخطي الكود حتى يتم الوصول إلى تعليق النهاية.

تنسيق أقسام الكود المميزة فقط

يتوفر الأمر --skip-formatting-except-id=tag، أو -sfei=tag، لجعل perltidy يقوم بتنسيق أقسام الكود التي تم تمييزها بالعلامة المحددة في تعليقات "format-skipping" فقط.

على سبيل المثال، قد تحتوي الأقسام المميزة على جداول يتم تنسيقها بشكل أفضل باستخدام قيم خاصة للمعلمة --maximum-line-length. أو ربما يكون القسم المميز جدولًا متداخلًا بعمق والذي من شأنه أن يتجنب فواصل الأسطر غير المرغوب فيها إذا تم تنسيقه بمسافة بادئة أقل باستخدام قيمة خاصة للمعلمة --starting-indentation-level=n.

يتم تقديم اسم العلامة مع النص المضاف id=NAME بعد مسافة واحدة أو أكثر في تعليق تخطي التنسيق الافتتاحي. يمكن أن تكون العلامة NAME أي مزيج من الأحرف والأرقام، ويجب ألا تكون هناك مسافة حول علامة المساواة.

على سبيل المثال

#<<< id=LongLines
  ...
#>>>

سيتم التعامل مع الكود في هذا القسم مثل أي قسم آخر يتم تخطي تنسيقه ما لم يتم إدخال المعلمة --skip-formatting-except-id=LongLines. في هذه الحالة، سيتم تنسيقه.

فيما يلي بعض النقاط المتعلقة بهذا الخيار:

  • الخيار الخاص --skip-formatting-except-id='-'، أو -sfei='-'، يعني تخطي كل التنسيقات (نظرًا لعدم وجود علامة باسم '-' ). سيسمح هذا بفحص الكود بحثًا عن المشكلات، ولكن لن يتم تغيير التنسيق. يمكن أيضًا استخدام المعلمة -notidy لتخطي التنسيق، ولكنها تنتهي في نقطة مبكرة من العملية، لذا فهي تعمل بشكل أسرع ولكنها لا تقوم بالعديد من عمليات فحص الكود.
  • الخيار الخاص --skip-formatting-except-id='*'، أو -sfei='*'، يعني تنسيق جميع الأقسام المميزة لتخطي التنسيق، بغض النظر عن أي تعليق id=. يمكن أن يلغي هذا الحاجة إلى إضافة id= إلى علامات تخطي التنسيق في الحالات البسيطة.
  • يمكن تحديد الأقسام التي يتم تخطيها أو تنسيقها عن طريق تفريغ ملف سجل باستخدام المعلمة -g.
  • عند استخدام هذا الخيار، لا يزال يتم تخمين المسافة البادئة الأولية من الكود الأول في الملف، حتى لو لم يتم تنسيقه. إذا أدى ذلك إلى مسافة بادئة غير مرغوب فيها للقسم المميز، فيمكن استخدام المعلمة --starting-indentation-level=n، أو -sil=n، لتعيين المسافة البادئة المطلوبة.
  • إذا كانت علامة تخطي التنسيق الأولى في ملف هي علامة نهاية، فإنها تنهي قسم تخطي تنسيق يبدأ من السطر الأول من الملف بدون علامة بداية. لذلك لا يمكن استخدام الطريقة المعتادة لوضع علامة تعريف على علامة البداية. في هذه الحالة الخاصة، يمكن وضع معرف لهذا القسم على علامة النهاية. هذه هي الحالة الوحيدة التي يتم فيها قراءة معرف من علامة نهاية.

تنسيق نطاق محدود من الأسطر

يتوفر الأمر --line-range-tidy=n1:n2 لمعالجة نطاق محدد من أسطر تدفق الإدخال باستخدام perltidy. هذا الأمر ذو أهمية أساسية لبرمجة محررات الأكواد التفاعلية. عند استخدامه، يتم قراءة تدفق الإدخال بالكامل ولكن يتم فقط معالجة نطاق الأسطر المحدد من ملف الإدخال بواسطة محلل perltidy ومنسقه، ثم يتم إعادة تجميع التدفق للإخراج. تحتاج الأسطر المحددة إلى احتواء عبارة كاملة أو حاوية متوازنة. وإلا، سيحدث خطأ في بناء الجملة ولن يتم تنسيق الكود. هناك عدد قليل من القيود على استخدام هذا الأمر: (1) لا يمكن تطبيقه على ملفات متعددة، و (2) ينطبق فقط على تنسيق الكود وليس، على سبيل المثال، تنسيق html.

-lrt=n1:n2، --line-range-tidy=n1:n2
يتم تحديد نطاق الأسطر بواسطة الأعداد الصحيحة n1 و n2، حيث n1 هو رقم السطر الأول الذي سيتم تنسيقه (ابدأ العد بالرقم 1) و n2 هو رقم السطر الأخير الذي سيتم تنسيقه. إذا لم يتم تقديم n2، أو تجاوز العدد الفعلي للأسطر، فسيستمر التنسيق حتى نهاية الملف.

أمثلة:

--line-range-tidy=43:109      # تنسيق الأسطر من 43 إلى 109
--line-range-tidy=' 43 : 109' # تنسيق الأسطر من 43 إلى 109
--line-range-tidy=1:          # تنسيق جميع الأسطر
--line-range-tidy=0:90        # خطأ (يجب أن يكون n1 >= 1)

يوضح المثال الثاني أن المسافات مقبولة إذا تم وضعها بين علامتي اقتباس.

التحكم في فواصل الأسطر

تتحكم المعلمات في هذا القسم والأقسام التالية في الفواصل بعد الأسطر غير الفارغة من الكود. يتم التحكم في الأسطر الفارغة بشكل منفصل بواسطة المعلمات في قسم "التحكم في الأسطر الفارغة".

-dnl، --delete-old-newlines
بشكل افتراضي، يقوم perltidy أولاً بحذف جميع مواقع فواصل الأسطر القديمة، ثم يبحث عن نقاط فاصل جيدة لمطابقة طول السطر المطلوب. استخدم -ndnl أو --nodelete-old-newlines لإجبار perltidy على الاحتفاظ بجميع نقاط فواصل الأسطر القديمة.
-anl، --add-newlines
بشكل افتراضي، سيضيف perltidy فواصل أسطر عند الضرورة لإنشاء استمرارات للأسطر الطويلة وتحسين مظهر البرنامج النصي. استخدم -nanl أو --noadd-newlines لمنع أي فواصل أسطر جديدة.

هذه العلامة لا تمنع perltidy من إزالة فواصل الأسطر الموجودة؛ راجع --freeze-newlines لمنع التغييرات في نقاط فواصل الأسطر تمامًا.

-fnl، --freeze-newlines
إذا كنت لا ترغب في إجراء أي تغييرات على فواصل الأسطر داخل أسطر الكود في برنامجك النصي، فقم بتعيين -fnl، وستبقى ثابتة، وبقية الأوامر في هذا القسم وقسمي "التحكم في تنسيق القوائم" و "الاحتفاظ بفواصل الأسطر الحالية أو تجاهلها". قد ترغب في استخدام --nooutdent-long-lines مع هذا.

ملاحظة: إذا كنت ترغب أيضًا في الحفاظ على أسطرك الفارغة تمامًا كما هي، يمكنك استخدام علامة --freeze-blank-lines التي تم وصفها في قسم "التحكم في الأسطر الفارغة".

التحكم في الفواصل عند الأقواس المتعرجة، والأقواس الدائرية، والأقواس المربعة

-ce، --cuddled-else
تمكين نمط "else المتلاصق"، حيث يتبع "else" و "elsif" مباشرة بعد القوس المتعرج الذي يغلق الكتلة السابقة. الافتراضي هو عدم استخدام else المتلاصقة، ويتم الإشارة إليه بالعلامة -nce أو --nocuddled-else. إليك مقارنة بين البدائل: 
# -ce
if ($task) {
    yyy();
} else {
    zzz();
}
# -nce (افتراضي)
if ($task) {
    yyy();
}
else {
    zzz();
}

في هذا المثال، يتم وضع الكلمة المفتاحية else على نفس السطر الذي يبدأ بقوس الكتلة الإغلاق السابق وينتهي بقوس الكتلة الافتتاحي الخاص به على نفس السطر. الكلمات المفتاحية الأخرى وأسماء الدوال التي يتم تنسيقها بهذا النمط "المتلاصق" هي elsif، continue، catch، finally.

يمكن تنسيق أنواع الكتل الأخرى عن طريق تحديد أسمائها في معلمة منفصلة --cuddled-block-list، الموضحة في قسم لاحق.

يتطلب التلاصق بين زوج من كتل الأكواد أن يبدأ القوس المتعرج للإغلاق للكتلة الأولى سطرًا جديدًا. إذا كانت هذه الكتلة بالكامل على سطر واحد في ملف الإدخال، فمن الضروري تحديد ما إذا كان ينبغي كسرها للسماح بالتلاصق. يتم التحكم في هذا القرار بواسطة العلامة --cuddled-break-options=n (-cbo=n) الموضحة أدناه. الافتراضي والقيمة الموصى بها -cbo=1 تستند إلى هذه القرار على الكتلة الأولى في السلسلة. إذا امتدت عبر أسطر متعددة، فسيتم إجراء التلاصق ويستمر في السلسلة، بغض النظر عن أحجام الكتل اللاحقة. وإلا، تظل الأسطر القصيرة سليمة.

لذا، على سبيل المثال، لن يكون للعلامة --cuddled-else أي تأثير إذا تم إعادة كتابة المقتطف أعلاه على النحو التالي

if ($task) { yyy() }
else {    zzz() }

إذا امتدت الكتلة الأولى عبر أسطر متعددة، فيمكن إجراء التلاصق وسيستمر للكتل اللاحقة في السلسلة، كما هو موضح في المقتطف السابق.

إذا كانت هناك أسطر فارغة بين الكتل المتلاصقة، فسيتم حذفها. إذا كانت هناك تعليقات بعد القوس المغلق حيث سيحدث التلاصق، فسيتم منع التلاصق. إذا حدث ذلك، سيعاد بدء التلاصق لاحقًا في السلسلة إذا كان ذلك ممكنًا.

-cb، --cuddled-blocks
هذه العلامة تعادل --cuddled-else (-ce).
-cbl، --cuddled-block-list
أنواع الكتل المتلاصقة الافتراضية المضمنة هي else, elsif, continue, catch, finally.

يمكن تعريف أنواع الكتل الإضافية التي ينطبق عليها نمط --cuddled-blocks باستخدام هذه المعلمة. هذه المعلمة هي سلسلة أحرف

g, مع قائمة بأنواع الكتل مفصولة بفواصل أو مسافات. على سبيل المثال، لدمج كتل التعليمات البرمجية من النوع `sort` و `map` و `grep`، بالإضافة إلى الأنواع الافتراضية، يمكن تعيين السلسلة إلى -cbl="sort map grep" أو بشكل مكافئ -cbl=sort,map,grep لاحظ مع ذلك أن أنواع الكتل هذه عادة ما تكون قصيرة لذا قد لا يكون هناك الكثير من الفرص لأسلوب التنسيق المدمج. يمنع استخدام الفواصل الحاجة إلى حماية المسافات بعلامات الاقتباس. كفحص تشخيصي، يمكن استخدام العلامة --dump-cuddled-block-list أو -dcbl لعرض تجزئة القيم التي يتم إنشاؤها بواسطة هذه العلامة. أخيرًا، لاحظ أن المعلمة --cuddled-block-list بحد ذاتها تحدد فقط الكتل التي يتم تنسيقها بأسلوب التنسيق المدمج. ليس لها تأثير ما لم يتم تفعيل أسلوب التنسيق هذا باستخدام --cuddled-else.
-cblx, --cuddled-block-list-exclusive
عند تحديد تنسيق `else` المدمج باستخدام --cuddled-else، يتسبب تعيين هذه العلامة في تجاهل `perltidy` لإعداداته الافتراضية المضمنة والاعتماد حصريًا على أنواع الكتل المحددة في علامة --cuddled-block-list الموضحة في القسم السابق. على سبيل المثال، لتجنب استخدام `catch` و `finally` المدمجين، وهما من بين الإعدادات الافتراضية، يمكن استخدام مجموعة المعلمات التالية: perltidy -ce -cbl='else elsif continue' -cblx
-cbo=n, --cuddled-break-option=n
يكون التنسيق المدمج ممكنًا فقط بين زوج من كتل التعليمات البرمجية إذا بدأ القوس المغلق للكتلة الأولى سطرًا جديدًا. إذا تم مواجهة كتلة موجودة بالكامل في سطر واحد، وتم تحديد التنسيق المدمج، فمن الضروري اتخاذ قرار بشأن ما إذا كان سيتم "كسر" الكتلة أم لا، مما يعني جعلها تمتد عبر عدة أسطر. تتحكم هذه المعلمة في هذا القرار. الخيارات هي: cbo=0 لا تجبر أبدًا على كسر كتلة قصيرة. cbo=1 إذا تم كسر الكتلة الأولى من زوج من الكتل في ملف الإدخال ، فقم بكسر الثانية [افتراضي]. cbo=2 افتح جميع الكتل لتحقيق أقصى قدر من التنسيق المدمج. الافتراضي والموصى به هو cbo=1. مع هذه القيمة، إذا امتدت الكتلة البادئة لسلسلة عبر عدة أسطر، فسيحدث تتابع من الكسور للكتل المتبقية مما يتسبب في دمج السلسلة بأكملها. يمكن أن ينتج الخيار cbo=0 تدمجًا غير منتظم إذا كانت هناك العديد من الكتل ذات السطر الواحد. ينتج الخيار cbo=2 أقصى دمج ولكنه لن يسمح بأي كتل قصيرة.
-bl, --opening-brace-on-new-line, أو --brace-left
استخدم العلامة -bl لوضع قوس كتلة مفتوح في سطر جديد: if ( $input_file eq '-' ) { ... } تطبق بشكل افتراضي على جميع الكتل الهيكلية باستثناء sort map grep eval والوظائف الفرعية المجهولة. الافتراضي هو -nbl الذي يضع قوسًا مفتوحًا في نفس السطر مع الكلمة المفتاحية التي تقدمه إذا أمكن. على سبيل المثال، # افتراضي if ( $input_file eq '-' ) { ... } عند تعيين -bl، يمكن التحكم في الكتل التي تنطبق عليها هذه الخاصية باستخدام المعلمتين --brace-left-list و --brace-left-exclusion-list الموضحتين في الأقسام التالية.
-bll=s, --brace-left-list=s
استخدم هذه المعلمة لتغيير أنواع أقواس الكتل التي تنطبق عليها علامة -bl؛ انظر "تحديد أنواع الكتل". على سبيل المثال، -bll='if elsif else sub' سيطبقها فقط على كتل "if/elsif/else" والكتل الفرعية المسماة. الافتراضي هو جميع الكتل، -bll='*'.
-blxl=s, --brace-left-exclusion-list=s
استخدم هذه المعلمة لاستبعاد أنواع أقواس الكتل التي تنطبق عليها علامة -bl؛ انظر "تحديد أنواع الكتل". على سبيل المثال، الإعدادات الافتراضية -bll='*' و -blxl='sort map grep eval asub' تعني جميع الكتل باستثناء sort map grep eval والكتل الفرعية المجهولة. ملاحظة أن القائمتين -bll=s و -blxl=s تتحكمان في سلوك علامة -bl ولكن ليس لهما تأثير ما لم يتم تعيين علامة -bl. توفر هاتان القائمتان تحكمًا كاملاً لهذه العلامة، ولكن تتوفر علامتا اختصار موصوفتان في الأقسام التالية.
-sbl, --opening-sub-brace-on-new-line
علامة -sbl توفر طريقة اختصار لتشغيل -bl فقط للوظائف الفرعية المسماة. يمكن تحقيق نفس التأثير عن طريق تشغيل -bl مع تعيين قائمة الكتل على -bll='sub'. لتجنب التعارضات، يوصى إما باستخدام طريقة القائمة الأكثر عمومية الموضحة أعلاه للتحكم في -bl، أو طريقة الاختصار هذه، ولكن ليس كلاهما. على سبيل المثال، perltidy -sbl ينتج هذه النتيجة: sub message { if (!defined($_[0])) { print("Hello, World\n"); } else { print($_[0], "\n"); } } هذه النسخة السلبية من هذه العلامة، -nsbl، تقوم بإيقاف تشغيل -bl للوظائف الفرعية المسماة. يمكن تحقيق نفس التأثير باستخدام طريقة قائمة الاستبعاد، -blxl=sub.
-asbl, --opening-anonymous-sub-brace-on-new-line
علامة -asbl تشبه علامة -sbl باستثناء أنها تنطبق على الوظائف الفرعية المجهولة بدلاً من الوظائف الفرعية المسماة. يمكن تحقيق نفس التأثير عن طريق تشغيل -bl مع تعيين قائمة الكتل لتشمل -bll='asub'. على سبيل المثال perltidy -asbl ينتج هذه النتيجة: $a = sub { if ( !defined( $_[0] ) ) { print("Hello, World\n"); } else { print( $_[0], "\n" ); } }; هذه النسخة السلبية من هذه العلامة، -nasbl، تقوم بإيقاف تشغيل -bl للوظائف الفرعية المجهولة.
-bli, --brace-left-and-indent
علامة -bli مشابهة لعلامة -bl ولكنها بالإضافة إلى ذلك تتسبب في وضع وحدة واحدة من مسافة البادئة المستمرة (انظر --continuation-indentation) قبل أقواس الكتل المفتوحة والمغلقة. على سبيل المثال # perltidy -bli if ( $input_file eq '-' ) { important_function(); } بشكل افتراضي، يحدث هذا المسافة البادئة الإضافية لأنواع الكتل: if، elsif، else، unless، while، for، foreach، do، وكذلك الوظائف الفرعية المسماة والكتل المسبوقة بـ label. العنصر التالي يوضح كيفية تغيير هذا. ملاحظة: علامة -bli مشابهة لعلامة -bl، والفرق هو أن الأقواس تحصل على مسافة بادئة. ولكن هاتين العلامتين منفصلتان في التنفيذ، ولهما إعدادات افتراضية مختلفة لأسباب تاريخية. إذا رغبت في ذلك، يمكن تحقيق مزيج من التأثيرات إذا رغبت في ذلك عن طريق تشغيلهما كليهما بإعدادات -list مختلفة. في حالة تحديد كلا الإعدادين لنوع كتلة معين، فإن أسلوب -bli له الأولوية.
-blil=s, --brace-left-and-indent-list=s
استخدم هذه المعلمة لتغيير أنواع أقواس الكتل التي تنطبق عليها علامة -bli؛ انظر "تحديد أنواع الكتل". الافتراضي هو -blil='if else elsif unless while for foreach do : sub'.
-blixl=s, --brace-left-and-indent-exclusion-list=s
استخدم هذه المعلمة لاستبعاد أنواع أقواس الكتل التي تنطبق عليها علامة -bli؛ انظر "تحديد أنواع الكتل". قد يكون هذا مفيدًا بالاقتران مع تحديد جميع الكتل -blil='*'. الإعداد الافتراضي هو -blixl=' '، والذي لا يستبعد أي كتل. لاحظ أن المعلمتين -blil و -blixl تتحكمان في سلوك علامة -bli ولكن ليس لهما تأثير ما لم يتم تعيين علامة -bli.
-bar, --opening-brace-always-on-right
الأسلوب الافتراضي، -nbl يضع قوس كتلة التعليمات البرمجية المفتوح في سطر جديد إذا لم يتناسب مع نفس السطر مع الكلمة المفتاحية المفتوحة، مثل هذا: if ( $bigwasteofspace1 && $bigwasteofspace2 || $bigwasteofspace3 && $bigwasteofspace4 ) { big_waste_of_time(); } لإجبار القوس المفتوح على أن يكون دائمًا على اليمين، استخدم العلامة -bar. في هذه الحالة، يصبح المثال أعلاه if ( $bigwasteofspace1 && $bigwasteofspace2 || $bigwasteofspace3 && $bigwasteofspace4 ) { big_waste_of_time(); } يحدث تعارض إذا تم تحديد كل من --opening-brace-on_new-line (-bl) و -bar.
-cpb, --cuddled-paren-brace

-cpbw, --cuddled-paren-brace-weld

# perltidy -wn -vtc=2
$x->badd( bmul(
    $class->new( abs(
        $sx * int( $xr->num() ) & $sy * int( $yr->num() ) ) ),

خيار التنسيق هذا عام جدًا ولكن هناك بعض القيود.

أحد القيود هو أن أي حد لطول السطر لا يزال مطبقًا ويمكن أن يسبب تكسير الأجزاء المتلاصقة الطويلة إلى أسطر متعددة.

أيضًا، تكديس الحاويات المعرفة بهذه الراية له أولوية على أي رايات تكديس حاويات أخرى. وذلك لأن أي لحام يتم أولاً.

-wfc, --weld-fat-comma
عندما تكون راية -wfc مضبوطة، إلى جانب -wn (--weld-nested-containers)، يُسمح لـ perltidy بلحام قوس فتح إلى حاوية فتح داخلية عندما تكون مفصولة بمفتاح هاش وفاصلة سمينة (=>). على سبيل المثال: 
# perltidy -wn -wfc
elf->call_method( method_name_foo => {
    some_arg1       => $foo,
    some_other_arg3 => $bar->{'baz'},
} );

هذا الخيار معطل افتراضيًا.

-wnxl=s, --weld-nested-exclusion-list
توفر راية -wnxl=s بعض التحكم في أنواع الحاويات التي يمكن لحامها. راية -wn افتراضيًا تكون "جشعة" في لحام الحاويات المتجاورة. إذا لحمت أنواعًا أكثر من الحاويات مما هو مرغوب فيه، توفر هذه الراية القدرة على تقليل كمية اللحام عن طريق تحديد قائمة بالأشياء التي **يجب** ألا يتم لحامها.

المنطق في perltidy لتطبيق هذا مباشر. عند النظر إلى كل رمز حاوية للانضمام إلى لحام، يتم استشارة أي قواعد استبعاد واستخدامها لرفض اللحام إذا كان ضروريًا.

هذه القائمة هي سلسلة نصية مع عناصر مفصولة بمسافات. كل عنصر يتكون من ما يصل إلى ثلاثة أجزاء من المعلومات: (1) موضع اختياري، (2) نوع سابق اختياري، و (3) نوع حاوية.

المعلومة الوحيدة المطلوبة هي نوع حاوية، وهو واحد من '(', '[', '{' أو 'q'. الثلاثة الأولى هي رموز حاويات والأخيرة تمثل قائمة محاطة بعلامات اقتباس. على سبيل المثال السلسلة النصية

-wnxl='[ { q'

تعني **لا** تشمل الأقواس المربعة، الأقواس المتعرجة، أو علامات الاقتباس في أي لحام. الحاوية الوحيدة غير المحددة هي '(', لذا هذه السلسلة النصية تعني أنه سيتم إجراء اللحامات التي تتضمن الأقواس فقط.

للتوضيح، المقطع الملحوم التالي يتكون من سلسلة من ثلاث حاويات ملحومة بأنواع '(', '[' و 'q':

# perltidy -wn
skip_symbols( [ qw(
    Perl_dump_fds
    Perl_ErrorNo
    Perl_GetVars
    PL_sys_intern
) ] );

حتى لو استخدم مصطلح qw الأقواس كفاصل لعلامة الاقتباس، إلا أنه يظهر بنوع خاص 'q' هنا. إذا ظهر في لحام، فإنه يظهر دائمًا في نهاية سلسلة اللحام.

يمكن لأي من أنواع الحاويات '[', '{', و '(' أن يسبقها مؤشر موضع وهو إما '^'، للإشارة إلى الرمز الأول في تسلسل ملحوم، أو '.'، للإشارة إلى رمز داخلي في تسلسل ملحوم. (نظرًا لأن السلسلة المحاطة بعلامات اقتباس 'q' تنتهي دائمًا بسلسلة، فهي لا تحتاج إلى مؤشر موضع).

على سبيل المثال، إذا كنا لا نريد أن يبدأ تسلسل الحاويات الملحومة بقوس مربع، يمكننا استخدام

-wnxl='^['

في المقطع أعلاه، يوجد قوس مربع ولكنه لا يبدأ السلسلة، لذا سيبقى التنسيق دون تغيير إذا تم تنسيقه بهذا القيد.

يمكن تقديم معلومة اختيارية ثالثة وهي حرف أبجدي رقمي يستخدم لتقييد التحديد بشكل أكبر اعتمادًا على نوع الرمز الذي يسبق الحاوية مباشرة. إذا تم تقديمه، فإنه يأتي مباشرة قبل رمز الحاوية. الأحرف الممكنة حاليًا هي 'k', 'K', 'f', 'F', 'w', و 'W'، مع هذه المعاني (انظر "تحديد أنواع الأقواس"):

'k' يطابق إذا كان الرمز السابق غير الفارغ هو كلمة مفتاحية في بيرل
    (مثل 'if', 'while')،
'K' يطابق إذا لم يكن 'k': الرمز السابق ليس كلمة مفتاحية
'f' يطابق إذا كان الرمز السابق دالة (وليس كلمة مفتاحية)
'F' يطابق إذا لم يكن 'f'
'w' يطابق إذا كان 'k' أو 'f' يطابقان
'W' يطابق إذا لم يكن 'w'

على سبيل المثال، قارن

# perltidy -wn
if ( defined( $_Cgi_Query{
    $Config{'methods'}{'auth'}{'remote'}{'cgi'}{'username'}
} ) )

مع

# perltidy -wn -wnxl='^K( {'
if ( defined(
    $_Cgi_Query{ $Config{'methods'}{'auth'}{'remote'}{'cgi'}
          {'username'} }
) )

الحالة الأولى تقوم بأقصى لحام. في الحالة الثانية، يتم الاحتفاظ بالقوس البادئ بواسطة القاعدة (كان سيتم رفضه إذا سبقه غير كلمة مفتاحية) ولكن يتم رفض القوس المتعرج بواسطة القاعدة.

إليك بعض أمثلة السلاسل النصية الإضافية ومعانيها:

'^('   - يجب ألا يبدأ اللحام بقوس
'.('   - لا يمكن أن تكون الرموز الثانية وما بعدها أقواس
'.w('  - لا يمكن أن تكون الرموز الثانية وما بعدها أقواس كلمات مفتاحية أو استدعاء
'('    - لا توجد أقواس في لحام
'^K('  - استبعاد قوس بادئ سبقه غير كلمة مفتاحية
'.k('  - استبعاد قوس ثانوي سبقه كلمة مفتاحية
'[ {'  - استبعاد جميع الأقواس المربعة والمتعرجة
'[ ( ^K{' - استبعاد كل شيء باستثناء الهياكل المتداخلة مثل do {{  ... }}
الضيق الرأسي للأقواس المتعرجة غير كتلية، والأقواس، والأقواس المربعة.
تتحكم هذه المعلمات فيما سيتم تسميته بالضيق الرأسي. إليك النقاط الرئيسية:
  • تتحكم معلمات -vt=n، أو --vertical-tightness=n، في الرموز البادئة (باستثناء أقواس الكتل)، حيث 
    -vt=0 كسر دائمًا السطر بعد الرمز البادئ (افتراضي).
-vt=1 لا تكسر ما لم ينتج عن ذلك أكثر من خطوة
        واحدة في المسافة البادئة في السطر.
-vt=2 لا تكسر السطر أبدًا بعد الرمز البادئ
  • يجب عليك أيضًا استخدام راية -lp (--line-up-parentheses) عند استخدام راية -vt؛ السبب موضح أدناه.
  • تتحكم معلمات -vtc=n، أو --vertical-tightness-closing=n، في الرموز اللاحقة (باستثناء أقواس الكتل)، حيث 
    -vtc=0 كسر دائمًا السطر قبل الرمز اللاحق (افتراضي)،
-vtc=1 لا تكسر قبل الرمز اللاحق متبوعًا بفاصلة منقوطة أو رمز لاحق آخر، وليس في
       بيئة قائمة.
-vtc=2 لا تكسر أبدًا قبل الرمز اللاحق.
-vtc=3 مثل -vtc=1 ولكن دائمًا كسر قبل الرمز اللاحق
       إذا كان الرمز البادئ المقابل يتبع = أو =>.

    تم تصميم قواعد -vtc=1 و -vtc=3 للحفاظ على توازن معقول بين الضيق وقابلية القراءة في القوائم المعقدة.

  • يمكن تطبيق ضوابط مختلفة على أنواع الرموز المختلفة، ومن الممكن أيضًا التحكم في أقواس الكتل؛ انظر أدناه.
  • أخيرًا، يرجى ملاحظة أن هذه الرايات للضيق الرأسي هي مجرد تلميحات للمنسق، ولا يمكنه دائمًا اتباعها. الأشياء التي تجعلها صعبة أو مستحيلة تشمل التعليقات، الأسطر الفارغة، كتل التعليمات البرمجية داخل قائمة، وربما عدم وجود المعلمة --line-up-parentheses. أيضًا، قد يتم تجاهل هذه الرايات للقوائم الصغيرة جدًا (2 أو 3 أسطر).

يتم إنتاج أضيق، وأقل قابلية للقراءة، شيفرة برمجية بكل من "-vt=2" و "-vtc=2":

تطبق المعلمات -vt=n و -vtc=n على كل نوع من رموز الحاويات. إذا رغبت في ذلك، يمكن تطبيق ضوابط الضيق الرأسي بشكل مستقل على كل نوع من أنواع رموز الحاويات اللاحقة.

المعلمات للتحكم في الأقواس هي -pvt=n أو --paren-vertical-tightness=n، و -pvtc=n أو --paren-vertical-tightness-closing=n.

العلامة -boc هي طريقة أخرى لمنع إعادة تنسيق القوائم المفصولة بفواصل. باستخدام -boc على المثال أعلاه، بالإضافة إلى علامات إضافية للاحتفاظ بالنمط الأصلي، ينتج عن ذلك

أحد عيوب هذه العلامة مقارنة بالطرق المذكورة أعلاه هو أنه يجب أن تكون جميع الجداول في الملف منسقة بشكل جيد بالفعل. يمكن استخدام معامل القسم التالي لتحديد الجداول التي تنطبق عليها.

-boct=s, --break-at-old-comma-types=s
يمكن استخدام هذا المعامل لجعل علامة -boc في القسم السابق تنطبق فقط على الفواصل في أنواع معينة من الحاويات. سلسلة المعامل s هي قائمة مفصولة بمسافات لأنواع الحاويات. يمكن أن تشمل أيًا من رموز حاويات القائمة (، {، و [. بالإضافة إلى ذلك، يمكن أن يسبق رمز القوس أي من الأحرف 'k'، 'K'، 'f'، 'F'، 'w'، و 'W'، لتقييد أنواع الأقواس التي تنطبق عليها -boc بشكل أكبر (انظر "تحديد أنواع الأقواس").

على سبيل المثال:

-boct='('  يعني الحفاظ على فواصل الفواصل القديمة في قوائم الأقواس
-boct='f(' يعني الحفاظ على فواصل الفواصل القديمة في قوائم استدعاء الدوال

يمكن تحديد الفواصل التي لا تقع ضمن أي من أنواع حاويات القائمة الثلاثة، مثل تلك الموجودة في استدعاء دالة بدون أقواس، باستخدام حرف ';'. ويجب فصل الاختيارات المتعددة بمسافات.

على سبيل المثال، -boct='; (' يعني الحفاظ على فواصل عند الفواصل غير المحتواة وعند الفواصل في الأقواس.

لاحظ أن هذا المعامل ليس له تأثير ما لم يتم تعيين -break-at-old-comma-breakpoints، أو -boc، أيضًا.

-btct=s, --break-at-trailing-comma-types=s

s=1 أو '*' : كل فاصلة لاحقة
s=m فاصلة لاحقة في قائمة متعددة الأسطر
s=b فاصلة لاحقة فارغة
s=0 لا شيء

);

سيقوم التنسيق الافتراضي بتسطيح هذا إلى سطر واحد. ولكن يمكن إبقاء الحاوية مفتوحة باستخدام

# perltidy -btct='b'
$w->bind(
    '<Page_Down>' => xx,
);

يمكن أن يكون هذا مفيدًا بشكل خاص لاستدعاءات الدوال القصيرة مثل هذه، حيث لا يحافظ تنسيق perltidy الافتراضي على الحاوية مفتوحة.

يمكن استخدام الخيارين s=m و s=1 لفتح الحاويات بفواصل لاحقة غير فارغة. على سبيل المثال، بالنظر إلى هذا الإدخال

$w->bind( '<Page_Down>' => xx, );

يمكننا فتحه باستخدام

# perltidy -btct=1
$w->bind(
    '<Page_Down>' => xx,
);

بعد ذلك، يمكننا التبديل إلى -btct='b' لأن الفاصلة اللاحقة فارغة الآن. ولكن يجب الاحتفاظ بالمعامل -btct في هذه الحالة لأنه بخلاف ذلك سيتم تسطيح هذه القائمة الصغيرة في المرة التالية التي يتم فيها تنسيقها.

يمكن تقييد هذا المنطق بأنواع حاويات محددة عن طريق تضمين رمز فتح مسبق للحرف في الجدول أعلاه. على سبيل المثال

-btct='(b'

يعني أن هذه العملية ستنطبق فقط على الفواصل اللاحقة الفارغة داخل الأقواس.

بالنسبة للأقواس، يمكن تقديم معلومة إضافية وهي حرف أبجدي رقمي يُستخدم لزيادة تقييد الاختيار اعتمادًا على نوع الرمز الذي يسبق القوس المفتوح مباشرة. الأحرف الممكنة حاليًا هي 'k'، 'K'، 'f'، 'F'، 'w'، و 'W'، مع هذه المعاني لمطابقة أي شيء يسبق قوسًا مفتوحًا (انظر "تحديد أنواع الأقواس"):

'k' يطابق إذا كان الرمز غير الفارغ السابق كلمة رئيسية في بيرل
    (مثل 'if'، 'while')،
'K' يطابق إذا لم يكن 'k' كذلك: الرمز السابق ليس كلمة رئيسية
'f' يطابق إذا كان الرمز السابق دالة (ليس كلمة رئيسية)
'F' يطابق إذا لم يكن 'f' كذلك.
'w' يطابق إذا تطابق 'k' أو 'f'.
'W' يطابق إذا لم يتطابق 'w'.

هذه هي نفس الرموز المستخدمة لـ --line-up-parentheses-inclusion-list. على سبيل المثال،

-btct='f(b'

يعني أن الفواصل اللاحقة الفارغة في قوائم استدعاء الدوال في تيار الإدخال يجب أن يتبعها فواصل أسطر في تيار الإخراج المنسق.

يصف القسم "إضافة وحذف الفواصل" ضوابط إضافية للعمل مع الفواصل اللاحقة. يمكن دمج هذه مع المعامل -break-trailing-comma-types لمزيد من التحكم في تنسيق القائمة.

-bocp=s, --break-open-compact-parens=s
عندما تكون القائمة الموجودة داخل الأقواس طويلة جدًا بحيث لا يمكن عرضها على سطر واحد، ولكنها قصيرة بما يكفي لعرضها على سطرين، فإن الافتراضي هو عرضها بشكل مضغوط على سطرين. إذا كانت هناك حاجة إلى أكثر من سطرين، فإن الافتراضي هو وضع فواصل أسطر بعد القوس المفتوح وقبل القوس المغلق. على سبيل المثال، يتم عرض القائمة القصيرة التالية بالتنسيق الافتراضي: 
initialize_warn_variable_types( $wvt_in_args, $num_files,
    $line_range_clipped );

يمكن استخدام المعامل -bocp=s للتسبب في كسر قوائم قصيرة مثل هذه بنفس الطريقة التي تُكسر بها القوائم الأطول. المعامل s هو حرف واحد يشير إلى أنواع الأقواس التي ينطبق عليها هذا. قد يكون هذا الحرف أحد الخيارات التالية (انظر "تحديد أنواع الأقواس"):

'1' أو '*' يطابق جميع الأقواس
'k' يطابق إذا كان الرمز غير الفارغ السابق كلمة رئيسية في بيرل
    (مثل 'my'، 'return')،
'K' يطابق إذا لم يكن 'k' كذلك: الرمز السابق ليس كلمة رئيسية
'f' يطابق إذا كان الرمز السابق دالة (ليس كلمة رئيسية)
'F' يطابق إذا لم يكن 'f' كذلك.
'w' يطابق إذا تطابق 'k' أو 'f'.
'W' يطابق إذا لم يتطابق 'w'.
'0' يعطل هذا المعامل [افتراضي]

في هذه الحالة، أكثر هذه الخيارات فائدة هي f (دالة)، k (كلمة رئيسية)، و w (كلاهما).

لذلك للتوضيح:

# perltidy -bocp='f'
initialize_warn_variable_types(
    $wvt_in_args, $num_files, $line_range_clipped
);
-mft=s, --maximum-fields-per-table=s
سيستخدم Perltidy قواعد تنسيق خاصة للقوائم الصغيرة نسبيًا، غير المنتظمة، أو المرتبطة بكلمات مفتاحية معينة مثل "sprintf". بمعنى آخر، للبيانات التي قد لا تظهر بشكل جيد كجدول. بالنسبة للقوائم الأخرى، سيقوم بإنشاء جدول بعدد معين من الحقول n الذي تم حسابه ليناسب عرض الصفحة والبيانات. يمكن التحكم في هذا الرقم n باستخدام معامل الإدخال هذا.

إذا كان s رقمًا موجبًا n، وتجاوز العدد المحسوب للحقول في الجدول n، فسيتم تقليله إلى n. يمكن استخدام هذا المعامل، على سبيل المثال، على قسم صغير من التعليمات البرمجية لإجبار قائمة على أن تحتوي على عدد معين من الحقول لكل سطر، وبعد ذلك يمكن استخدام العلامة -boc للاحتفاظ بهذا التنسيق، أو يمكن إدخال سطر فارغ أو تعليق في مكان ما لتجميد التنسيق في تطبيقات مستقبلية لـ perltidy. على سبيل المثال،

# perltidy -mft=2
@month_of_year = (
    'Jan', 'Feb',
    'Mar', 'Apr',
    'May', 'Jun',
    'Jul', 'Aug',
    'Sep', 'Oct',
    'Nov', 'Dec'
);

القيمة الافتراضية هي n=0، والتي لا تضع حدًا لعدد الحقول في الجدول.

بدءًا من الإصدار 20250311.05 من perltidy، يسمح معامل إدخال اختياري أكثر عمومية بتحديد بعض الجداول التي ينطبق عليها هذا الخيار. يمكن أن يسبق الرقم الصحيح n أحد أنواع الحاويات "("، "["، أو "{" لتحديد نوع حاوية واحد فقط. يمكن تعيين قيم رقمية مختلفة لأنواع حاويات مختلفة. على سبيل المثال، الإدخال

-mft='(1 [2'

يعني استخدام حقل واحد للجداول داخل الأقواس، وحقلين للجداول داخل الأقواس المربعة، وعدم التحكم في الحقول داخل الأقواس المتعرجة.

بالإضافة إلى ذلك، يمكن أن تسبق الأقواس أحد أحرف التحكم في الأقواس "k f w K F W" لزيادة تحديد الجداول التي سيتم التحكم في عدد حقولها (انظر الجدول أعلاه أو "تحديد أنواع الأقواس"). أحد استخدامات هذا هو مطابقة التحكم في عدد حقول الجدول مع المعامل --break-open-compact-parens الموضح أعلاه. وبالتالي فإن الجمع

-bocp='f' -mft='f(1'

يقول إن قوائم الأقواس التي تلي استدعاءات الدوال يجب أن تُكسر، ويجب أن تحتوي هذه القوائم نفسها على حقل واحد لكل سطر عند تنسيقها كجدول.

-cab=n, --comma-arrow-breakpoints=n
تُمنح الفاصلة التي تلي سهم فاصلة، '=>'، اعتبارًا خاصًا. في قائمة طويلة، من الشائع الانكسار عند جميع هذه الفواصل. يمكن استخدام هذا المعامل للتحكم في كيفية الانكسار في perltidy عند هذه الفواصل. (ومع ذلك، لن يكون له أي تأثير إذا تم فرض فواصل فواصل قديمة لأن -boc مستخدم). القيم الممكنة لـ n هي: 
n=0 الانكسار عند جميع الفواصل بعد =>
n=1 مستقر: الانكسار عند جميع الفواصل بعد => إذا كانت الحاوية مفتوحة،
    باستثناء الحاويات ذات السطر الواحد
n=2 الانكسار عند جميع الفواصل بعد =>، ولكن حاول تكوين أقصى
    أطوال الحاويات ذات السطر الواحد
n=3 لا تعامل الفواصل بعد => بشكل خاص على الإطلاق
n=4 كسر كل شيء: مثل n=0 ولكن أيضًا كسر حاوية قصيرة مع
    => لا يتبعها فاصلة عند استخدام -vt=0
n=5 مستقر: مثل n=1 ولكن أيضًا كسر الحاويات المفتوحة ذات السطر الواحد عند
    استخدام -vt=0 (افتراضي)

على سبيل المثال، بالنظر إلى السطر الواحد التالي، لن يضيف perltidy فواصل أسطر افتراضيًا لأنه سيقوم بكسر الحاوية الموجودة ذات السطر الواحد:

bless { B => $B, Root => $Root } => $package;

class="Pp">باستخدام -cab=0، سيتم فرض فاصل بعد كل عنصر بفاصلة وسهم (&gt;).

# perltidy -cab=0:
bless {
    B    =&gt; $B,
    Root =&gt; $Root
} =&gt; $package;

إذا تم تشغيل perltidy لاحقًا مع كسر هذا الحاوية، فبشكل افتراضي سيتم كسرها بعد كل '=&gt;' لأن الحاوية مكسورة الآن. لإعادة تشكيل حاوية ذات سطر واحد، يمكن استخدام المعامل -cab=2.

يمكن استخدام العلامة -cab=3 لمنع هذه الفواصل من أن تُعامل بشكل خاص. في هذه الحالة، يتم التعامل مع عنصر مثل "01" =&gt; 31 كعنصر واحد في جدول. سيتم تحديد عدد الحقول في هذا الجدول بنفس القواعد المستخدمة لأي جدول آخر. إليك مثال.

# perltidy -cab=3
my %last_day = (
    "01" =&gt; 31, "02" =&gt; 29, "03" =&gt; 31, "04" =&gt; 30,
    "05" =&gt; 31, "06" =&gt; 30, "07" =&gt; 31, "08" =&gt; 31,
    "09" =&gt; 30, "10" =&gt; 31, "11" =&gt; 30, "12" =&gt; 31
);
-qwaf، --qw-as-function
تخبر هذه الخيار perltidy بتنسيق قائمة qw التي تحددها الأقواس كما لو كانت استدعاء دالة حيث وسائط الاستدعاء هي قائمة بالعناصر المقتبسة. بشكل طبيعي، يتم إخراج قائمة qw كما هي باستثناء تعديل المسافة البادئة للإشارة إلى مستوى المسافة البادئة. على سبيل المثال، إليك مثال على التنسيق الافتراضي لقائمة qw سيئة التنسيق:

# perltidy
@fields = qw( $st_dev     $st_ino    $st_mode $st_nlink   $st_uid
  $st_gid $st_rdev    $st_size $st_atime   $st_mtime  $st_ctime
  $st_blksize $st_blocks);

إذا قمنا بالتنسيق باستخدام -qwaf، فستكون النتيجة:

# perltidy -qwaf
@fields = qw(
    $st_dev   $st_ino   $st_mode  $st_nlink
    $st_uid   $st_gid   $st_rdev  $st_size
    $st_atime $st_mtime $st_ctime $st_blksize
    $st_blocks
);

كيف يعمل هذا هو أنه قبل بدء التنسيق مباشرة، يتم استبدال الرموز النصية لـ qw برموز استدعاء دالة مكافئة مع قائمة مفصولة بفواصل من العناصر المقتبسة كوسائط استدعاء. ثم يتم تنسيقها مثل أي قائمة أخرى. يتم استخدام رموز فواصل خاصة، ليس لها نص معروض، لذا عندما يتم عرض الكود في النهاية، يظل اقتباس qw صالحًا.

بعض النقاط التي يجب ملاحظتها:

  • يعمل هذا فقط مع اقتباسات qw التي تبدأ بـ qw(، بدون مسافة قبل القوس.
  • إذا تم استخدام الخيار --space-function-paren، فسيتم تجاهله لهذه الاستدعاءات الخاصة للدالة لأنه سيعطلها.
  • بخلاف ذلك، تعمل علامات التحكم في التنسيق المختلفة على هذه القوائم كما هو الحال مع القوائم الأخرى المفصولة بفواصل. وبشكل خاص، لاحظ أنه إذا تم تعيين --break-at-old-comma-breakpoints، أو -boc، فستتم المحافظة على مواقع فواصل الأسطر القديمة. وسيتم الاحتفاظ بفواصل الأسطر القديمة إذا كانت هناك أي أسطر فارغة بين الأقواس الافتتاحية والختامية.
  • قبل استخدام هذا الخيار للمرة الأولى، من الجيد مسح الكود وتحديد ما إذا كانت هناك قوائم ذات ترتيب خاص يجب الحفاظ عليه. يمكن تحقيق ذلك على سبيل المثال عن طريق تغيير رموز الاقتباس إلى شيء آخر غير الأقواس، أو عن طريق إدراج سطر فارغ كما نوقش في بداية هذا القسم.

إضافة وحذف الفواصل

-drc، --delete-repeated-commas
يتسبب هذا الخيار في إزالة الفواصل المتكررة. على سبيل المثال، نظرًا لهذه القائمة ذات الفاصل المتكرر 
ignoreSpec( $file, "file",, \%spec, \%Rspec );

يمكننا إزالته باستخدام -drc

# perltidy -drc:
ignoreSpec( $file, "file", \%spec, \%Rspec );

يقوم هذا المعامل أيضًا بإزالة الفواصل الدهنية المتكررة، '=&gt;'. قائمة الإجراءات الكاملة التي تم اتخاذها عند تعيين هذه العلامة هي كما يلي:

  • يتم إزالة الفواصل المتكررة مثل ',,' مع تحذير.
  • يتم إزالة الفواصل الدهنية المتكررة مثل '=&gt; =&gt;' مع تحذير.
  • التركيبة '=&gt;,' تنتج تحذيرًا ولكن لا يتم تغييرها (من المحتمل أن تكون خطأ ولكن مؤلفها فقط سيعرف كيفية إصلاحه).
  • التركيبة المتبقية ',=&gt;' (تسمى أحيانًا 'فاصل دهني يغمز') يتم تجاهلها بواسطة هذا المعامل.
  • هذه التحذيرات لا يتم إخراجها إلا إذا تم تعيين علامة --warning-output، أو -w.

هذا الخيار قيد التشغيل افتراضيًا. استخدم -ndrc لإيقاف تشغيله.

إضافة وحذف الفواصل اللاحقة
الفاصل اللاحق هو فاصل يأتي بعد العنصر الأخير في القائمة. يسمح Perl بالفواصل اللاحقة ولكنها ليست إلزامية. يمكن أن يؤدي تضمينها أحيانًا إلى تبسيط صيانة القوائم الكبيرة أو المعقدة، والمساعدة في عرض الهيكل. ولكنها قد لا تكون مناسبة في جميع القوائم، على سبيل المثال في قائمة لها دائمًا حد واحد. افتراضيًا، لا يضيف perltidy أو يحذف الفواصل اللاحقة، ولكن من الممكن معالجتها باستخدام مجموعة المعاملات المتعلقة التالية:

  • --want-trailing-commas=s, -wtc=s - يحدد أين تكون الفواصل اللاحقة مرغوبة (النمط)
  • --add-trailing-commas, -atc - يعطي الإذن بإضافة فواصل لاحقة لمطابقة النمط المطلوب
  • --delete-trailing-commas, -dtc - يعطي الإذن بحذف الفواصل اللاحقة التي لا تتطابق مع النمط المطلوب

المعامل --want-trailing-commas=s، أو -wtc=s، يحدد نمطًا مفضلاً. السلسلة s تشير إلى أي قوائم يجب أن تحصل على فواصل لاحقة، على النحو التالي:

s=1 أو '*' : كل قائمة
s=m قائمة متعددة الأسطر
s=b قائمة متعددة الأسطر، فاصل لاحق فارغ
s=i قائمة متعددة الأسطر، فاصل لاحق فارغ، حوالي فاصل واحد في كل سطر
s=h قائمة متعددة الأسطر، فاصل لاحق فارغ، حوالي زوج مفتاح=&gt;قيمة واحد في كل سطر
s=0 : لا توجد قائمة
s=' ' أو غير معرف : ترك الفواصل اللاحقة دون تغيير [افتراضي]

حيث:

  • قائمة هنا تُعتبر بشكل أساسي حاوية عناصر (أقواس، أقواس مربعة، أو أقواس معقوفة)، ليست كتلة كود، تحتوي على فاصل واحد أو أكثر أو فواصل دهنية. تنطبق هذه المعاملات فقط على شيء يناسب هذا التعريف للقائمة.

    قائمة وسائط بدون أقواس ليست قائمة بهذا التعريف، لذا لا تنطبق هذه المعاملات على قوائم بدون أقواس.

  • قائمة متعددة الأسطر هي قائمة تكون فيها الأقواس الافتتاحية والختامية على أسطر مختلفة.
  • فاصل لاحق فارغ هو فاصل في نهاية السطر. أي أن رمز الحاوية الختامي يأتي في سطر مختلف. لذا فإن قائمة ذات فاصل لاحق فارغ هي حالة خاصة من قائمة متعددة الأسطر.
  • في الواقع، يمكن النظر إلى الخيارات المذكورة أعلاه للفواصل اللاحقة كسلسلة هرمية من المجموعات المتداخلة التي يمكن التعبير عنها كـ 
    1 > m > b > i > h > 0

    يشير هذا إلى أن الفواصل اللاحقة متعددة الأسطر m هي مجموعة فرعية من جميع الفواصل اللاحقة، والفواصل اللاحقة الفارغة b هي مجموعة فرعية من جميع الفواصل اللاحقة متعددة الأسطر، وهكذا.

هذا المعامل بحد ذاته يشير فقط إلى مكان الفواصل اللاحقة المرغوبة. لا يضيف perltidy هذه الفواصل اللاحقة إلا إذا تم منح الإذن عن طريق تعيين العلامة --add-trailing-commas، أو -atc. ولا يحذف perltidy الفواصل اللاحقة غير المرغوبة إلا إذا تم تعيين العلامة --delete-trailing-commas، أو -dtc.

فيما يلي بعض مجموعات المعاملات الممثلة ومعانيها

-wtc=0 -dtc   : حذف جميع الفواصل اللاحقة
-wtc=1 -atc   : إضافة فواصل لاحقة إلى جميع القوائم
-wtc=m -atc   : إضافة فواصل لاحقة إلى جميع القوائم متعددة الأسطر
                (تبقى القوائم ذات السطر الواحد دون تغيير)
-wtc=b -atc   : إضافة فواصل بحيث تكون لجميع القوائم التي يبدأ قوسها الختامي
                سطرًا جديدًا فواصل لاحقة
-wtc=b -dtc   : يتم حذف جميع الفواصل اللاحقة التي ليست فارغة
                (غير متبوعة بسطر جديد).
-wtc=b -atc -dtc  : يتم إجراء العمليتين أعلاه بحيث تكون
                    جميع الفواصل اللاحقة فارغة

على سبيل المثال، بالنظر إلى الإدخال التالي

$wine_list = $top-&gt;Box(
    "-length" =&gt; 5,
    "-width"  =&gt; 3
)-&gt;select( "red", "white", "gold", );

لدينا

# perltidy -wtc=b -atc -dtc
$wine_list = $top-&gt;Box(
    "-length" =&gt; 5,
    "-width"  =&gt; 3,
)-&gt;select( "red", "white", "gold" );

تمت إضافة فاصل بعد 3، لأنه فارغ، وتم حذف فاصل بعد "gold"، لأنه غير فارغ.

من الممكن تطبيق نمط مختلف على كل نوع من رموز الحاويات بإدراج رمز فتح قبل رمز النمط في الجدول أعلاه. على سبيل المثال

-wtc='(m [b'

يعني أن القوائم الموجودة داخل الأقواس يجب أن تحتوي على فواصل لاحقة متعددة الأسطر، وأن القوائم الموجودة داخل الأقواس المربعة تحتوي على فواصل لاحقة فارغة. نظرًا لعدم وجود مواصفات للأقواس المعقوفة في هذا المثال، ستظل فواصلها اللاحقة دون تغيير.

بالنسبة للأقواس، هناك معلومة إضافية يمكن تقديمها وهي حرف أبجدي رقمي يستخدم لتحديد الاختيار بشكل أكبر اعتمادًا على نوع الرمز الذي يسبق القوس مباشرة. الأحرف الممكنة حاليًا هي 'k'، 'K'، 'f'، 'F'، 'w'، و 'W'، بالمعاني التالية لمطابقة أي شيء يسبق القوس (انظر "تحديد أنواع الأقواس"):

'k' تتطابق إذا كان الرمز السابق غير الفارغ كلمة مفتاحية في Perl
    (مثل 'if'، 'while')،
'K' تتطابق إذا لم يتطابق 'k': الرمز السابق ليس كلمة مفتاحية
'f' تتطابق إذا كان الرمز السابق دالة (ليس كلمة مفتاحية)
'F' تتطابق إذا لم يتطابق 'f'.
'w' تتطابق إذا تطابق 'k' أو 'f'.
'W' تتطابق إذا لم يتطابق 'w'.

هذه هي نفس الرموز المستخدمة لـ --line-up-parentheses-inclusion-list. على سبيل المثال،

-wtc='w(m'

يعني أن الفواصل اللاحقة مطلوبة للقوائم ذات الأقواس متعددة الأسطر التي تتبع استدعاء دالة أو كلمة مفتاحية.

أخيرًا، يمكن وضع علامة + في بداية أي مصطلح للإشارة إلى أنه ينطبق فقط عند إضافة الفواصل. تشير علامة - في البداية إلى أنها تنطبق فقط عند حذف الفواصل. على سبيل المثال،

-wtc='+h -b' -atc -dtc

يعني أنه يجب إضافة الفواصل اللاحقة المفقودة إلى قوائم أزواج المفاتيح =&gt; القيم، ويجب حذف الفواصل اللاحقة التي ليست فارغة. لا تتم أي تغييرات أخرى. عندما يتم استخدام كل من المصطلحات الإيجابية والسلبية بهذا الشكل، يجب ألا تتعارض. لا يوجد تعارض في هذا المثال لأن مواقع الفواصل اللاحقة لأزواج المفاتيح =&gt; القيم المحددة

إزالتها عن طريق تعيين --noindent-leading-semicolon أيضًا.

# perltidy -bos -nils
$z = sqrt( $x**2 + $y**2 )
;

الافتراضي هو عدم القيام بذلك، -nbos.

-bok, --break-at-old-keyword-breakpoints
بشكل افتراضي، ستحتفظ perltidy بنقطة توقف قبل الكلمات المفتاحية التي يمكن أن تعيد قوائم، مثل "sort" و "map". هذا يسمح بتسلسل هذه العوامل ليتم عرضها سطرًا واحدًا لكل سطر. استخدم -nbok لمنع الاحتفاظ بنقاط التوقف هذه.
-bot, --break-at-old-ternary-breakpoints
بشكل افتراضي، إذا تم كسر عامل شرطي (ثلاثي) عند ":"، فسيظل مكسورًا. لمنع ذلك، وبالتالي تكوين أسطر أطول، استخدم -nbot.
-boa, --break-at-old-attribute-breakpoints
بشكل افتراضي، إذا تم كسر قائمة سمات عند ":" في ملف المصدر، فستظل مكسورة. على سبيل المثال، بالنظر إلى الكود التالي، سيتم الاحتفاظ بكسر الأسطر عند النقاط ':' : 
my @field
  : field
  : Default(1)
  : Get('Name' => 'foo') : Set('Name');

إذا كانت السمات في سطر واحد في الكود المصدري، فستبقى في سطر واحد إن أمكن.

لمنع ذلك، وبالتالي تكوين أسطر أطول دائمًا، استخدم -nboa.

الاحتفاظ بنقاط توقف قديمة عند أنواع رموز محددة
من الممكن تجاوز اختيار فواصل الأسطر التي تقوم بها perltidy، وإجبارها على اتباع فواصل أسطر معينة في تدفق الإدخال، باستخدام هذين المعيارين:

-kbb=s أو --keep-old-breakpoints-before=s، و

-kba=s أو --keep-old-breakpoints-after=s

يتبع كل من هذين المعيارين سلسلة نصية مقتبسة، s، تحتوي على قائمة بأنواع الرموز (مفصولة بمسافات فقط). لا ينبغي تحديد أكثر من واحد من كل من هذين المعيارين، لأن تكرار معلمة سطر الأوامر يقوم دائمًا بالكتابة فوق السابقة قبل أن تراها perltidy.

على سبيل المثال، -kbb='=>' يعني أنه إذا بدأ سطر الإدخال بـ '=>'، فيجب أن يكون لدى البرنامج النصي الناتج أيضًا فاصل سطر قبل هذا الرمز.

على سبيل المثال، بالنظر إلى البرنامج النصي:

method 'foo'
  => [ Int, Int ]
  => sub {
    my ( $self, $x, $y ) = ( shift, @_ );
    ...;
  };
# perltidy [default]
method 'foo' => [ Int, Int ] => sub {
    my ( $self, $x, $y ) = ( shift, @_ );
    ...;
};
# perltidy -kbb='=>'
method 'foo'
  => [ Int, Int ]
  => sub {
    my ( $self, $x, $y ) = ( shift, @_ );
    ...;
  };

بالنسبة لرموز الحاوية '{'، '[' و '('، ونظائرها المغلقة، استخدم رمز الرمز. وبالتالي، فإن الأمر للحفاظ على فاصل بعد جميع الأقواس المفتوحة هو:

perltidy -kba='('

من الممكن أن تكون أكثر تحديدًا في مطابقة الأقواس عن طريق تمييزها بحرف. الأحرف الممكنة هي 'k'، 'K'، 'f'، 'F'، 'w'، و 'W'، مع هذه المعاني (انظر "تحديد أنواع الأقواس"):

'k' تتطابق إذا كان الرمز السابق غير الفارغ كلمة مفتاحية بيرل
    (مثل 'if'، 'while')،
'K' تتطابق إذا لم يكن 'k' كذلك: الرمز السابق ليس كلمة مفتاحية
'f' تتطابق إذا كان الرمز السابق دالة (ليس كلمة مفتاحية)
'F' تتطابق إذا لم يكن 'f' كذلك.
'w' تتطابق إذا تطابق 'k' أو 'f'.
'W' تتطابق إذا لم يتطابق 'w'.

لذلك، على سبيل المثال، سيحافظ المعيار التالي على فواصل بعد أقواس استدعاء الدوال المفتوحة:

perltidy -kba='f('

ملاحظة: سيتم تجاهل طلب التوقف قبل حاوية مفتوحة، مثل -kbb='('، بصمت لأنه قد يؤدي إلى عدم استقرار التنسيق. وبالمثل، سيتم تجاهل طلب التوقف بعد حاوية مغلقة، مثل -kba=')'، بصمت أيضًا.

-iob, --ignore-old-breakpoints
استخدم هذا العلم لإخبار perltidy بتجاهل فواصل الأسطر الحالية إلى أقصى حد ممكن. هذا يميل إلى إنتاج أطول حاويات ممكنة، بغض النظر عن النوع، التي لا تتجاوز حد طول السطر. ولكن يرجى ملاحظة أن هذا المعيار له الأولوية على جميع المعايير الأخرى التي تطلب الاحتفاظ بنقاط توقف قديمة معينة.

لتوضيح ذلك، انظر النص المدخل التالي:

has subcmds => (
    is => 'ro',
    default => sub { [] },
);

التنسيق الافتراضي سيحافظ على كسر الحاوية، مما يؤدي إلى

# perltidy [default]
has subcmds => (
    is      => 'ro',
    default => sub { [] },
);

إذا تم تجاهل نقاط التوقف القديمة، فسيتم تسطيح القائمة:

# perltidy -iob
has subcmds => ( is => 'ro', default => sub { [] }, );

بالإضافة إلى تسطيح القوائم، ينطبق هذا المعيار أيضًا على الأسطر المكسورة عند نقاط توقف منطقية معينة مثل 'if' و 'or'.

حتى لو لم يتم استخدام هذا المعيار عالميًا، فإنه يوفر طريقة ملائمة لتسطيح قوائم محددة من داخل محرر.

-kis, --keep-interior-semicolons
استخدم العلم -kis لمنع الكسر عند فاصلة منقوطة إذا لم يكن هناك كسر هناك في ملف الإدخال. عادةً ما تضع perltidy سطرًا جديدًا بعد كل فاصلة منقوطة تنهي جملة ما لم يتم احتواء عدة جمل ضمن كتلة أقواس ذات سطر واحد. للتوضيح، انظر أسطر الإدخال التالية: 
dbmclose(%verb_delim); undef %verb_delim;
dbmclose(%expanded); undef %expanded;

الافتراضي هو الكسر بعد كل جملة، مما يؤدي إلى

dbmclose(%verb_delim);
undef %verb_delim;
dbmclose(%expanded);
undef %expanded;

مع perltidy -kis يتم الاحتفاظ بالجمل المتعددة:

dbmclose(%verb_delim); undef %verb_delim;
dbmclose(%expanded);   undef %expanded;

لا تزال الجمل تخضع للقيمة المحددة لـ maximum-line-length وسيتم كسرها إذا تجاوزت هذه القيمة.

التحكم في الأسطر الفارغة

يمكن للأسطر الفارغة تحسين قابلية قراءة البرنامج النصي إذا تم وضعها بعناية. تحتوي perltidy على العديد من الأوامر للتحكم في إدخال الأسطر الفارغة والاحتفاظ بها وإزالتها.

-fbl, --freeze-blank-lines
قم بتعيين -fbl إذا كنت تريد أن تظل الأسطر الفارغة في برنامجك النصي كما هي بالضبط. قد يتم بعد ذلك تجاهل بقية المعايير في هذا القسم. (ملاحظة: تعيين العلم -fbl يعادل تعيين -mbl=0 و -kbl=2).
-bbc, --blanks-before-comments
سيتم إدخال سطر فارغ قبل تعليق سطر كامل. هذا هو الافتراضي. استخدم -nbbc أو --noblanks-before-comments لمنع إدخال مثل هذه الأسطر الفارغة.
-blbs=n, --blank-lines-before-subs=n
يطلب المعيار -blbs=n أن يسبق الحد الأدنى n من الأسطر الفارغة تعريف دالة لا يتبع تعليقًا وهي أطول من سطر واحد. الافتراضي هو -blbs=1. يتم تضمين كتل BEGIN و END.

سيتم إدخال عدد الأسطر الفارغة المطلوبة بغض النظر عن قيمة --maximum-consecutive-blank-lines=n (-mbl=n) باستثناء أنه إذا كان -mbl=0 فلن يتم إخراج أي أسطر فارغة.

يتفاعل هذا المعيار مع القيمة k للمعميار --maximum-consecutive-blank-lines=k (-mbl=k) على النحو التالي:

1. إذا كان -mbl=0 فلن يتم إخراج أي أسطر فارغة. هذا يسمح بإخماد جميع الأسطر الفارغة بمعيار واحد. بخلاف ذلك،

2. إذا كان عدد الأسطر الفارغة القديمة في البرنامج النصي أقل من n، فسيتم إدخال أسطر فارغة إضافية لجعل المجموع n بغض النظر عن قيمة -mbl=k.

3. إذا كان عدد الأسطر الفارغة القديمة في البرنامج النصي يساوي أو يتجاوز n، فلن يكون لهذا المعيار أي تأثير، ومع ذلك لن يتجاوز المجموع القيمة المحددة في العلم -mbl=k.

-blbp=n, --blank-lines-before-packages=n
يطلب المعيار -blbp=n أن يسبق الحد الأدنى n من الأسطر الفارغة حزمة لا تتبع تعليقًا. الافتراضي هو -blbp=1.

يتفاعل هذا المعيار مع القيمة k للمعيمار --maximum-consecutive-blank-lines=k (-mbl=k) بنفس الطريقة الموضحة للعنصر السابق -blbs=n.

-bbs, --blanks-before-subs
للتوافق مع الإصدارات السابقة، -bbs أو --blanks-before-subs يعادل -blbp=1 و -blbs=1.

وبالمثل، -nbbs أو --noblanks-before-subs يعادل -blbp=0 و -blbs=0.

-bbb, --blanks-before-blocks
سيتم إدخال سطر فارغ قبل كتل الترميز المحددة بواسطة for، foreach، while، until، و if، unless، في الظروف التالية:
  • الكتلة لا يسبقها تعليق.
  • الكتلة ليست كتلة ذات سطر واحد.
  • عدد الأسطر غير الفارغة المتتالية عند عمق المسافة الحالية لا يقل عن -lbl (انظر القسم التالي).

هذا هو الافتراضي. الهدف من هذا الخيار هو إدخال بعض المسافات داخل الترميز الكثيف. يتم نفي ذلك باستخدام -nbbb أو --noblanks-before-blocks.

-lbl=n --long-block-line-count=n
يتحكم هذا في عدد المرات التي يُسمح فيها لـ perltidy بإضافة أسطر فارغة قبل أنواع كتل معينة (انظر القسم السابق). الافتراضي هو 8. إدخال قيمة 0 يعادل إدخال رقم كبير جدًا.
-blao=i أو --blank-lines-after-opening-block=i
يضع هذا التحكم حدًا أدنى من i من الأسطر الفارغة بعد سطر ينتهي بقوس كتلة مفتوح من النوع المحدد. بشكل افتراضي، ينطبق هذا فقط على كتلة sub مسماة، ولكن يمكن تغيير ذلك (انظر -blaol أدناه). الافتراضي هو عدم القيام بذلك (i=0).

يرجى الرجوع إلى الملاحظة أدناه حول استخدام الخيارين -blao و -blbc.

-blbc=i أو --blank-lines-before-closing-block=i
يضع هذا التحكم بحد أدنى i من الأسطر الفارغة قبل سطر يبدأ بقوس كتلة إغلاق من نوع محدد. افتراضيًا، ينطبق هذا فقط على كتلة sub مسماة، ولكن يمكن تغيير ذلك (انظر -blbcl أدناه). الافتراضي هو عدم القيام بذلك (i=0).
-blaol=s أو --blank-lines-after-opening-block-list=s
المعلمة s هي قائمة بكلمات مفتاحية لأنواع الكتل التي يجب أن ينطبق عليها العلامة -blao. يوضح قسم "تحديد أنواع الكتل" كيفية سرد أنواع الكتل.
-blbcl=s أو --blank-lines-before-closing-block-list=s
هذه المعلمة هي قائمة بكلمات مفتاحية لأنواع الكتل التي يجب أن ينطبق عليها العلامة -blbc. يوضح قسم "تحديد أنواع الكتل" كيفية سرد أنواع الكتل.
ملاحظة حول استخدام الخيارين -blao و -blbc.
تقدم عناصر التحكم هذه للأسطر الفارغة عددًا أدنى معينًا من الأسطر الفارغة في النص، ولكن العدد النهائي للأسطر الفارغة قد يكون أكبر، اعتمادًا على قيم عناصر التحكم الأخرى للأسطر الفارغة وعدد الأسطر الفارغة القديمة. والنتيجة هي أن إدخال الأسطر الفارغة باستخدام هذه العناصر وعناصر التحكم الأخرى لا يمكن التراجع عنه بالضبط، لذا يوصى ببعض التجارب مع هذه العناصر قبل استخدامها.

إذا لزم الأمر، يمكن التراجع تقريبًا عن هذه العناصر وعناصر التحكم الأخرى للأسطر الفارغة باستخدام المعلمة --keep-old-blank-lines-exceptions=s الموضحة أدناه.

-mbl=n --maximum-consecutive-blank-lines=n
تحدد هذه المعلمة الحد الأقصى لعدد الأسطر الفارغة المتتالية التي سيتم إخراجها داخل أقسام التعليمات البرمجية في البرنامج النصي. الافتراضي هو n=1. إذا كان ملف الإدخال يحتوي على أكثر من n من الأسطر الفارغة المتتالية، فسيتم تقليل العدد إلى n باستثناء ما هو مذكور أعلاه للمعلمات --blank-lines-before-subs و --blank-lines-before-subs. إذا كان n=0 فلن يتم إخراج أي أسطر فارغة (ما لم يتم الاحتفاظ بجميع الأسطر الفارغة القديمة باستخدام العلامة --keep-old-blank-lines=2 في القسم التالي).

هذه العلامة لا تنطبق بوضوح على أقسام pod، و here-documents، والاقتباسات.

-kbl=n, --keep-old-blank-lines=n
تمنحك العلامة -kbl=n التحكم في كيفية التعامل مع الأسطر الفارغة الحالية.

القيم الممكنة لـ n هي:

n=0 تجاهل جميع الأسطر الفارغة القديمة
n=1 ثابت: الاحتفاظ بالأسطر الفارغة القديمة، ولكن محدودة بالعلامة B<-mbl=n>، ولكن
    إزالة الأسطر الفارغة الموجودة التي تتطابق مع العلامة B<--kblx=s> (انظر أدناه)
n=2 الاحتفاظ بجميع الأسطر الفارغة القديمة، بغض النظر عن العلامة B<-mbl=n>

الإعداد الافتراضي والموصى به هو n=1. باستخدام هذا الخيار، يمكنك تصفية الأسطر الفارغة المحددة بشكل انتقائي من تدفق الإدخال قبل بدء التنسيق باستخدام المعلمة الموضحة في القسم التالي.

يجب استخدام الإعداد n=0 بحذر لأنه سيزيل جميع الأسطر الفارغة، بما في ذلك الأسطر التي قد تكون ضرورية للتحكم في المحاذاة الرأسية، ولمنع التعليقات الجانبية غير المرغوب فيها.

-kblx=s, --keep-old-blank-lines-exceptions=s
تحدد معظم عناصر التحكم للأسطر الفارغة الموضحة أعلاه الحد الأدنى من الأسطر الفارغة، بدلاً من الحد الأقصى، لذلك لا يمكن استخدامها لإزالة الأسطر. تسمح هذه المعلمة بإزالة الأسطر الفارغة عن طريق تجاهلها بشكل انتقائي في تدفق الإدخال. تعمل عندما يكون --keep-old-blank-lines=1، وهو الإعداد الافتراضي كما هو موضح أعلاه. يتم تحديد الأسطر الفارغة المراد استثناؤها باستخدام سلسلة تحتوي على واحد أو أكثر من القيم الخاصة التالية: 
'b{' 'b}' '{b' '}b' 'bp' 'bs' 'bc' 'cb'

في هذه الرموز، يشير الحرف b إلى موقع الأسطر الفارغة بالنسبة لنوع الرمز التالي أو السابق. أنواع الرموز { و } هي أقواس الكتل البرمجية المفتوحة والمغلقة، الحرف p هو عبارة package، s هو تعريف sub، و c هو تعليق كتلة.

لذلك، على سبيل المثال، تعني bs أنه سيتم تجاهل سطر واحد أو أكثر من الأسطر الفارغة قبل sub في تدفق الإدخال. لاحظ أن هذا هو عكس تقريبًا للمعلمة -blanks-before-subs الموضحة أعلاه.

في الواقع، توفر هذه المعلمات عكسًا تقريبيًا لجميع خيارات الأسطر الفارغة الموضحة سابقًا. لتبسيط الأمور، أنواع الكتل التي تنطبق عليها عوامل "{" و "}" هي نفس نوع العامل المقابل الذي يضيف أسطرًا فارغة، والموضح أعلاه. يوضح الجدول التالي هذه العلاقات:

kblx=   عكس   ينطبق على أنواع الكتل
b{      -bbb      if unless while until for foreach
b}      -blbc=i  -blbcl=s [الافتراضي = sub]
{b      -blao=i  -blaol=s [الافتراضي = sub]
}b      [لا شيء]   -blaol=s
bp      -blbp=n
bs      -blbs=n
bc      -bbc
cb      [لا شيء - تعليقات قبل الأسطر الفارغة]

لذلك، على سبيل المثال، يشير الجدول إلى أنه لإزالة الأسطر الفارغة التي تم إدخالها بواسطة عملية -blao تقريبًا، يمكننا استخدام -kblx='{b'.

بعض الملاحظات حول استخدام هذه المعلمة:

  • يمكن أن تحتوي سلسلة المعلمة على عوامل متعددة شريطة أن تكون مفصولة بمسافات.
  • ستحتفظ عناصر التحكم في حذف التعليقات بسطر فارغ واحد على الأقل بين مجموعات التعليقات، وبين تعليق جانبي وسطر تعليق لاحق.
  • تحدث هذه العمليات على تدفق الإدخال، قبل عمليات الأسطر الفارغة الأخرى، لذلك يمكن استخدامها في نفس التشغيل مع عناصر تحكم الأسطر الفارغة الأخرى. لذلك يمكن أن يحدث أن تقوم هذه العناصر بإزالة الأسطر الفارغة من تدفق الإدخال بينما تضيف عناصر تحكم أخرى أسطرًا فارغة مرة أخرى.
  • عادةً ما تكون هذه العمليات مطلوبة فقط بشكل متقطع لتصحيح بعض المشكلات، أو للتراجع عن عملية غير مرغوب فيها.
-sob, --swallow-optional-blank-lines
هذا يعادل --keep-old-blank-lines=0 وهو مدرج للتوافق مع الإصدارات السابقة.
-nsob, --noswallow-optional-blank-lines
هذا يعادل --keep-old-blank-lines=1 وهو مدرج للتوافق مع الإصدارات السابقة.

عناصر التحكم في الأسطر الفارغة حول أسطر الكلمات المفتاحية المتتالية

توفر المعلمات في هذا القسم بعض التحكم في وضع الأسطر الفارغة داخل وحول مجموعات العبارات التي تبدأ بكلمات مفتاحية مختارة. تسمى هذه الأسطر الفارغة هنا أسطر فارغة لمجموعات الكلمات المفتاحية، وجميع المعلمات تبدأ بـ --keyword-group-blanks*، أو -kgb* اختصارًا. الإعدادات الافتراضية لا تستخدم عناصر التحكم هذه ولكن يمكن تمكينها باستخدام المعلمات التالية:

-kgbl=s أو --keyword-group-blanks-list=s؛ s هي سلسلة محاطة بعلامات اقتباس من الكلمات المفتاحية

-kgbs=s أو --keyword-group-blanks-size=s؛ s تعطي عدد الكلمات المفتاحية المطلوبة لتشكيل مجموعة.

-kgbb=n أو --keyword-group-blanks-before=n؛ n = (0، 1، أو 2) يتحكم في سطر فارغ رائد

-kgba=n أو --keyword-group-blanks-after=n؛ n = (0، 1، أو 2) يتحكم في سطر فارغ لاحق

-kgbi أو --keyword-group-blanks-inside هو مفتاح لإضافة أسطر فارغة بين المجموعات الفرعية

-kgbd أو --keyword-group-blanks-delete هو مفتاح لإزالة الأسطر الفارغة الأولية بين الكلمات المفتاحية

-kgbr=n أو --keyword-group-blanks-repeat-count=n يمكن أن يحدد عدد المرات التي يتم فيها تطبيق هذا المنطق

بالإضافة إلى ذلك، تتوفر الاختصارات التالية للاستخدام المبسط:

-kgb أو --keyword-group-blanks هو اختصار لـ -kgbb=2 -kgba=2 kgbi

-nkgb أو --nokeyword-group-blanks، هو اختصار لـ -kgbb=1 -kgba=1 nkgbi

محاذاة unless و if اللاحقة باستخدام --valign-if-unless أو -viu

print "Tried to add: @Resolve\n" if ( @Resolve and !$Quiet );

print "Output:\n"                  unless $Quiet;

The -viu flag causes a postfix unless to be treated as if it were a postfix if for purposes of alignment, and thus they align:

# perltidy -viu
print "Tried to add: @Resolve\n"   if ( @Resolve and !$Quiet );

محاذاة الأرقام الموقعة باستخدام --valign-signed-numbers أو -vsn
Setting -vsn causes columns of numbers containing both signed and unsigned values to have leading signs placed in their own column. For example: 
# perltidy -vsn
my @correct = (
    [  123456.79,   86753090000.868,  11 ],
    [ -123456.79,  -86753090000.868, -11 ],
    [  123456.001,  80.080,           10 ],
    [ -123456.001, -80.080,           0 ],
    [  10.9,        10.9,             11 ],
);

The default is -vsn. This can be turned off to get is strict left justification:

# perltidy -nvsn
my @correct = (
    [ 123456.79,   86753090000.868,  11 ],
    [ -123456.79,  -86753090000.868, -11 ],
    [ 123456.001,  80.080,           10 ],
    [ -123456.001, -80.080,          0 ],
    [ 10.9,        10.9,             11 ],
);

Some points regarding -vsn are:

  • This option works by inserting a single space ahead of unsigned numbers when possible. This is not done if it would require increasing the maximum width of a column.
  • This option is mainly limited to lists of comma-separated numbers. For multiline lists of numbers, having trailing commas can sometimes improve the results. If missing, perltidy can add them for example with parameters -wtc=b -atc. See "Adding and Deleting Commas".
  • This option has a control parameter --valign-signed-number-limit=N, or -vsnl=N. This value controls formatting of very long columns of numbers and should not normally need to be changed. To see its purpose, consider a very long column of just unsigned numbers, say 1000 lines. If we add a single negative number, it is undesirable to move all of the other numbers over by one space. This could create many lines of file differences but not really improve the appearance when a local section of the table was viewed. The number N avoids this problem by not adding extra indentation to a run of more than N lines of unsigned numbers. The default value, N=20, is set to be a number of lines for which the ends of a long column of unsigned numbers are not normally both in view.
محاذاة عوامل التعيين باستخدام --valign-wide-equals أو -vwe
The following assignment operators are aligned independently by default: 
= **= += *= &= <<= &&= -= /= |= >>= ||= //= .= %= ^= x= ^^=

Setting --valign-wide-equals, or -vwe, causes them to be vertically aligned together with the trailing = all aligned. For example, here is the default formatting for some code with several of these operators:

$str .= SPACE x $total_pad_count;
$str_len += $total_pad_count;
$total_pad_count = 0;
$str .= $rfields->[$j];
$str_len += $rfield_lengths->[$j];

And here is the same code formatted with -vwe:

# perltidy -vwe
$str             .= SPACE x $total_pad_count;
$str_len         += $total_pad_count;
$total_pad_count  = 0;
$str             .= $rfields->[$j];
$str_len         += $rfield_lengths->[$j];

This option was added for issue git #135 and can improve readability, but it is off by default to avoid changing existing formatting.

صيغة ممتدة

This section describes some parameters for dealing with extended syntax.

For another method of handling extended syntax see the section "Skipping Selected Sections of Code".

Also note that the module Perl::Tidy supplies a pre-filter and post-filter capability. This requires calling the module from a separate program rather than through the binary perltidy.

-xs, --extended-syntax
This flag allows perltidy to handle certain common extensions to the standard syntax without complaint.

For example, without this flag a structure such as the following would generate a syntax error:

Method deposit( Num $amount) {
    $self->balance( $self->balance + $amount );
}

This flag is enabled by default but it can be deactivated with -nxs. Probably the only reason to deactivate this flag is to generate more diagnostic messages when debugging a script.

-sal=s, --sub-alias-list=s
This flag causes one or more words to be treated the same as if they were the keyword sub. The string s contains one or more alias words, separated by spaces or commas.

For example,

perltidy -sal='method fun _sub M4'

will cause the perltidy to treat the words 'method', 'fun', '_sub' and 'M4' the same as if they were 'sub'. Note that if the alias words are separated by spaces then the string of words should be placed in quotes.

Note that several other parameters accept a list of keywords, including 'sub' (see "Specifying Block Types"). You do not need to include any sub aliases in these lists. Just include keyword 'sub' if you wish, and all aliases are automatically included.

-gal=s, --grep-alias-list=s
This flag allows a code block following an external 'list operator' function to be formatted as if it followed one of the built-in keywords grep, map or sort. The string s contains the names of one or more such list operators, separated by spaces or commas.

By 'list operator' is meant a function which is invoked in the form

word {BLOCK} @list

Perltidy tries to keep code blocks for these functions intact, since they are usually short, and does not automatically break after the closing brace since a list may follow. It also does some special handling of continuation indentation.

For example, the code block arguments to functions 'My_grep' and 'My_map' can be given formatting like 'grep' with

perltidy -gal='My_grep My_map'

By default, the following list operators in List::Util are automatically included:

all any first none notall reduce reductions

Any operators specified with --grep-alias-list are added to this list. The next parameter can be used to remove words from this default list.

-gaxl=s, --grep-alias-exclusion-list=s
The -gaxl=s flag provides a method for removing any of the default list operators given above by listing them in the string s. To remove all of the default operators use -gaxl='*'.
-uf=s, --use-feature=s
This flag tells perltidy to allow or disallow the syntax associated a pragma in string s. The current possible settings are:
  • --use-feature='class'. This tells perltidy to recognized the special words class, method, field, and ADJUST as defined for this feature.
  • --use-feature='noclass'. This tells perltidy not to treat words class, method, field, ADJUST specially.
  • Neither of these (--use-feature not defined). This is the DEFAULT and recommended setting. In this case perltidy will try to automatically handle both the newer "feature 'class'" syntax as well as some conflicting uses of some of these special words by existing modules.

Note that this parameter is independent of any use feature control lines within a script. Perltidy does not look for or read such control lines. This is because perltidy must be able to work on small chunks of code sent from an editor, so it cannot assume that such lines will be within the lines being formatted.

حذف النص المحدد
يمكن لـ Perltidy حذف التعليقات و/أو وثائق Pod بشكل انتقائي. يقوم الأمر -dac أو --delete-all-comments بحذف جميع التعليقات و جميع وثائق Pod، تاركًا فقط الكود وأي سطور تحكم نظام بادئة.

يقوم الأمر -dp أو --delete-pod بإزالة جميع وثائق Pod (ولكن ليس التعليقات).

هناك أمران يحذفان التعليقات (ولكن ليس Pod): -dbc أو --delete-block-comments و -dsc أو --delete-side-comments. (سيتم حذف التعليقات الجانبية المتدلية مع التعليقات الجانبية هنا.)

عند حذف التعليقات الجانبية، سيتم الاحتفاظ بأي تعليقات تحكم جانبية خاصة للأقواس غير الإزاحة ما لم يتم تعطيلها بعلامة -nnib.

تعمل سلبيات هذه الأوامر أيضًا، وهي الافتراضية. عند حذف تعليقات الكتل، سيتم الاحتفاظ بأي "hash-bang" بادئ. أيضًا، إذا تم استخدام علامة -x، فسيتم الاحتفاظ بأي أوامر نظام قبل "hash-bang" بادئ (حتى لو كانت في شكل تعليقات).

كتابة النص المحدد إلى ملف
عندما يكتب Perltidy ملف نص منسق، فإنه لديه القدرة على إرسال نص محدد إلى ملف بامتداد .TEE. يمكن أن يشمل هذا النص التعليقات ووثائق Pod.

يقوم الأمر -tac أو --tee-all-comments بكتابة جميع التعليقات و جميع وثائق Pod.

يقوم الأمر -tp أو --tee-pod بكتابة جميع وثائق Pod (ولكن ليس التعليقات).

الأوامر التي تكتب التعليقات (ولكن ليس Pod) هي: -tbc أو --tee-block-comments و -tsc أو --tee-side-comments. (سيتم كتابة التعليقات الجانبية المتدلية مع التعليقات الجانبية هنا.)

تعمل سلبيات هذه الأوامر أيضًا، وهي الافتراضية.

ملف perltidyrc

استخدام ملف أوامر .perltidyrc
إذا كنت تستخدم Perltidy بشكل متكرر، فمن المحتمل أنك لن تكون سعيدًا حتى تقوم بإنشاء ملف .perltidyrc لتجنب كتابة المعلمات شائعة الاستخدام. سيبحث Perltidy أولاً في الدليل الحالي عن ملف أوامر يسمى .perltidyrc. إذا لم يجده، فسيستمر في البحث عنه في مواقع قياسية أخرى.

هذه المواقع الأخرى تعتمد على النظام، ويمكن عرضها باستخدام الأمر "perltidy -dpro". تحت أنظمة Unix، سيبحث أولاً عن متغير البيئة PERLTIDY. ثم سيبحث عن ملف .perltidyrc في الدليل الرئيسي، ثم عن ملف على مستوى النظام /usr/local/etc/perltidyrc، ثم سيبحث عن /etc/perltidyrc. لاحظ أن هذين الملفين الأخيرين على مستوى النظام ليس لديهما نقطة بادئة. سيتم العثور على مزيد من المعلومات الخاصة بالنظام في ملف INSTALL الموزع مع Perltidy.

تحت Windows، سيبحث Perltidy أيضًا عن ملف تكوين يسمى perltidy.ini نظرًا لأن Windows لا يسمح بالملفات ذات النقطة البادئة (.). استخدم "perltidy -dpro" لرؤية المواقع المحتملة لنظامك. قد يكون مثالاً C:\Documents and Settings\All Users\perltidy.ini.

خيار آخر هو استخدام متغير البيئة PERLTIDY. تعتمد طريقة تعيين متغيرات البيئة على إصدار Windows الذي تستخدمه.

تحت Windows NT / 2000 / XP، يمكن وضع متغير البيئة PERLTIDY إما في قسم المستخدم أو في قسم النظام. الأخير يجعل ملف التكوين مشتركًا لجميع المستخدمين على الجهاز. تأكد من إدخال المسار الكامل لملف التكوين في قيمة متغير البيئة. مثال: PERLTIDY=C:\Documents and Settings\perltidy.ini

ملف التكوين هو بتنسيق حر، وهو ببساطة قائمة بالمعلمات، تمامًا كما سيتم إدخالها في سطر الأوامر. يمكن استخدام أي عدد من الأسطر، مع أي عدد من المعلمات لكل سطر، على الرغم من أنه قد يكون من الأسهل قراءته مع معلمة واحدة لكل سطر. يبدأ نص التعليق بـ #، ويجب أن يكون هناك أيضًا مسافة قبل # للتعليقات الجانبية. من الجيد وضع المعلمات المعقدة إما في علامات اقتباس فردية أو مزدوجة.

إليك مثال لملف .perltidyrc:

# هذا مثال بسيط لملف تكوين .perltidyrc
# هذا يطبق أسلوبًا متباعدًا للغاية
-se    # أخطاء إلى مخرج الخطأ القياسي
-w     # عرض جميع التحذيرات
-bl    # أقواس في أسطر جديدة
-pt=0  # أقواس غير محكمة على الإطلاق
-bt=0  # أقواس غير محكمة
-sbt=0 # أقواس مربعة غير محكمة

يتم تثبيت المعلمات الموجودة في ملف .perltidyrc أولاً، لذلك سيكون لأي معلمات معطاة في سطر الأوامر الأولوية عليها.

لتجنب الارتباك، يتجاهل Perltidy أي أمر في ملف .perltidyrc من شأنه أن يتسبب في نوع من التفريغ والخروج. تشمل هذه:

-h -v -ddf -dln -dop -dsn -dtt -dwls -dwrs -ss

هناك العديد من الخيارات التي قد تكون مفيدة في تصحيح ملف .perltidyrc:

  • أمر مفيد جدًا هو --dump-profile أو -dpro. يكتب قائمة بجميع أسماء ملفات التكوين التي تم اختبارها إلى المخرج القياسي، وإذا تم العثور على ملف، فإنه يفرغ المحتوى إلى المخرج القياسي قبل الخروج. لذا، لمعرفة أين يبحث Perltidy عن ملفات التكوين الخاصة به، وأيها إذا كان أي منها، فقط أدخل 
    perltidy -dpro
  • قد يكون من الأسهل تطوير واختبار ملفات التكوين بأسماء بديلة، واستدعائها باستخدام -pro=filename على سطر الأوامر. ثم أعد تسمية الملف المطلوب إلى .perltidyrc عند الانتهاء.
  • يمكن إيقاف تشغيل المعلمات الموجودة في ملف .perltidyrc باستخدام الخيار -npro على سطر الأوامر.
  • يمكن تجاوز أي معلمة في ملف .perltidyrc بقيمة استبدال على سطر الأوامر. هذا لأن سطر الأوامر تتم معالجته بعد ملف .perltidyrc.
  • الأوامر --dump-options و --dump-defaults و --dump-long-names و --dump-short-names، وجميعها موصوفة أدناه، قد تكون مفيدة.
تخطي سطر بمعلمة غير معروفة
الإصدارات من Perltidy أكبر من 20240511 لديها خيار لتصفية المعلمات غير المعترف بها من ملف أوامر Perltidy. إذا بدأ سطر في الملف بثلاث شرطات متبوعة باسم معلمة (بدلاً من واحدة أو اثنتين)، فسيتم إزالة السطر إذا كانت المعلمة غير معروفة. وإلا، ستتم إزالة شرطة لجعل السطر صالحًا. تمت إضافة هذا الخيار للسماح باستخدام ملف أوامر واحد أثناء الانتقال إلى إصدار جديد من Perltidy.
إنشاء اختصار جديد
يتوفر ترميز خاص للاستخدام في ملف .perltidyrc لإنشاء اختصار لمجموعة من الخيارات. يمكن استخدامه لإنشاء اختصار لنمط واحد أو أكثر يستخدم بشكل متكرر، ولكن ليس دائمًا. الترميز هو تجميع الخيارات داخل أقواس متعرجة مسبوقة باسم الاسم المستعار (بدون شرطات بادئة)، مثل هذا: 
newword {
-opt1
-opt2
}

حيث newword هو الاختصار، و opt1، إلخ، هي معلمات موجودة أو اختصارات أخرى. متطلب بناء الجملة الرئيسي هو أن الاختصار الجديد مع قوسه المتعرج الافتتاحي يجب أن يبدأ في سطر جديد. المسافة قبل وبعد الأقواس المتعرجة اختيارية.

كمثال محدد، التعريف التالي

debug {
   --warn-similar-keys
   --warn-unique-keys
}

أو بشكل مكافئ، مع الاختصارات،

debug { -wsk -wuk }

يمكن وضعه في ملف .perltidyrc. الاسم الجديد، في هذه الحالة debug، عشوائي بشرط أنه لا يتعارض مع معلمة موجودة. سيتم تجاهل فحوصات التحذير الإضافية المعرفة بهذه المعلمة الجديدة ما لم تتم إضافة المعلمة الجديدة -debug إلى سطر الأوامر. تظل جميع الإعدادات الأخرى في ملف .perltidyrc سارية. وبالتالي يوفر طريقة لإجراء بعض الفحوصات الإضافية عند استدعاء Perltidy باستخدام

perltidy -debug ...

(يمكن استخدام -debug أو --debug).

تخطي أوامر Perl البادئة غير Perl باستخدام -x أو --look-for-hash-bang
إذا كان لديك سطور بادئة من أوامر النظام أو نص آخر ليست رموز Perl صالحة، وهي مفصولة عن بداية رمز Perl بسطر "hash-bang" (سطر بالشكل "#!...perl")، فيجب عليك استخدام علامة -x لإخبار Perltidy بعدم تحليل وتنسيق أي سطور قبل سطر "hash-bang". يقوم هذا الخيار أيضًا بتشغيل Perl بعلامة -x عند التحقق من بناء الجملة. تم إضافة هذا الخيار في الأصل للسماح لـ Perltidy بتحليل نصوص VMS التفاعلية، ولكن يجب استخدامه لأي نص يتم استدعاؤه عادةً باستخدام "perl -x".

يرجى ملاحظة: لا تستخدم هذه العلامة إلا إذا كنت متأكدًا من أن نصك يحتاجها. يمكن أن تحدث أخطاء في التحليل إذا لم يكن لديه "hash-bang"، أو، على سبيل المثال، إذا كان أول "hash-bang" فعلي في مستند here-doc. في هذه الحالة، سيحدث خطأ في التحليل لأن التقطيع سيبدأ في منتصف مستند here-doc.

يمكن الإبلاغ عن سلسلة من الكتل if-elsif-... كعنصر سطر واحد عن طريق إدخال الكلمة elsif مع عدد صحيح لاحق، كما هو موضح في العنصر الأخير في هذه القائمة. يحدد العدد الصحيح عدد كتل elsif المطلوبة ليتم الإبلاغ عن سلسلة. إذا استخدمت هذا، فقد ترغب أيضًا في استخدام -dbl=n، مع عدد أقل من الأسطر n من الافتراضي.

بالإضافة إلى ذلك، يمكن تحديد أنواع حلقات الكتل المحددة المتداخلة في حلقات أخرى عن طريق إضافة + بعد اسم الكتلة. (الحلقات المتداخلة هي غالبًا مرشحين جيدين لإعادة الهيكلة).

الافتراضي هو -dbt='sub'.

في الأمثلة التالية، يتم إنشاء جدول "block.csv" لملف "somefile.pl":

  • يحدد هذا كل من "subs" و "packages" التي تحتوي على 20 سطرًا أو أكثر من التعليمات البرمجية. يمكن أن يكون هذا مفيدًا في التعليمات البرمجية التي تحتوي على حزم متعددة. 
    perltidy -dbs -dbt='sub package' somefile.pl >blocks.csv
  • يحدد هذا الكتل التي تحتوي على سطرين أو أكثر من التعليمات البرمجية من نوع "sub" أو التي هي حلقات داخلية. 
    perltidy -dbs -dbl=2 -dbt='sub +' somefile.pl >blocks.csv
  • يحدد هذا كل كتلة وحزمة. 
    perltidy -dbs -dbl=1 -dbt='* closure' somefile.pl >blocks.csv
  • يحدد هذا كل سلسلة if التي تحتوي على كتلتين أو أكثر من "elsif": 
    perltidy -dbs -dbl=1 -dbt='elsif2' somefile.pl >blocks.csv
  • يحدد هذا كل كتلة "while" تحتوي على 6 أسطر برمجية أو أكثر 
    perltidy -dbs -dbt=while -dbl=6 somefile.pl >while.csv
استخدام --dump-unusual-variables للعثور على المتغيرات غير المستخدمة، المعاد استخدامها، وبعض المتغيرات الأخرى ذات الأهمية
يمكن سرد المتغيرات ذات خصائص معينة تهم المبرمج باستخدام --dump-unusual-variables أو -duv. يجب أن يكون هذا المعامل موجودًا في سطر الأوامر، إلى جانب اسم ملف واحد. يتسبب هذا في أن يقوم perltidy بفحص الملف لأنواع معينة من المتغيرات، ويكتب أي شيء تم العثور عليه إلى المخرج القياسي، ثم يخرج فورًا دون إجراء أي تنسيق. على سبيل المثال 
perltidy -duv somefile.pl >vars.txt

ينتج ملفًا يحتوي على أسطر تبدو كالتالي

1778:u: my $input_file
6089:r: my $j: reused - see line 6076

القيم الموجودة في السطر مفصولة بنقطتين رأسيتين ولها المعنى التالي:

line number   - رقم سطر الملف المدخل
issue         - حرف واحد يشير إلى المشكلة، انظر أدناه
variable name - اسم المتغير، مسبوقًا بكلمة مفتاحية
note          - ملاحظة اختيارية تشير إلى سطر آخر

إذا كان هناك عدد كبير من المشكلات، فقد يكون من المناسب قراءة الملف في جدول بيانات.

يتم إجراء الفحوصات للمتغيرات التي تم تقديمها بواسطة الكلمات المفتاحية my و state و our، بالإضافة إلى المتغيرات المعرفة باستخدام use vars و use constant. من الجيد أيضًا تعيين use strict في البرنامج النصي حتى يتمكن Perl نفسه من العثور على مشكلات تتعلق بالمتغيرات التي تظهر في برنامج نصي بدون إحدى هذه الطرق.

يتم تحديد أنواع الفحوصات التي يتم إجراؤها في المخرج بأحد الأحرف r أو s أو p أو u أو c على النحو التالي:

r: اسم متغير معاد استخدامه
هذه هي المتغيرات التي يتم إعادة تعريفها في نطاق متغير بنفس الاسم. يمكن أن يكون هذا مربكًا، ربما ليس عندما تتم كتابة التعليمات البرمجية لأول مرة، ولكن ربما لاحقًا أثناء أعمال الصيانة. على سبيل المثال، يمكن أن يجعل هذا من الصعب تحديد المتغير الصحيح باستخدام محرر عند إجراء تغييرات. يمكن تجنب هذه المشكلة عن طريق إعادة تسمية أحد المتغيرات المتعارضة. لاحظ أن هذا مشابه لسياسة Perl::Critic Variables::ProhibitReusedNames.
s: تغيير sigil ولكن تم إعادة استخدام bareword
هذه هي المتغيرات التي لها نفس اسم bareword ولكن sigil مختلف ($ أو @ أو %) عن متغير آخر في نفس النطاق. على سبيل المثال، يحدث هذا إذا كانت المتغيرات $data و %data تشترك في نفس النطاق. يمكن أن يكون هذا مربكًا أيضًا للأسباب المذكورة أعلاه ويمكن تجنبه عن طريق إعادة تسمية أحد المتغيرات.
p: متغيرات تتجاوز الحزمة
هذه هي المتغيرات المعجمية التي تم تعريفها في حزمة واحدة ولا تزال مرئية في الإجراءات الفرعية لحزمة مختلفة في نفس الملف. يمكن أن يكون هذا مربكًا، وقد يتسبب في تشغيل البرنامج بشكل مختلف، أو فشله، إذا تم تقسيم الحزم في أي وقت إلى ملفات منفصلة. يمكن عادةً تجنب هذه المشكلة عن طريق وضع التعليمات البرمجية في أقواس كتلة من أي نوع. على سبيل المثال، غالبًا ما توجد هذه المشكلة في تعليمات الاختبار البرمجية ويمكن أحيانًا إصلاحها باستخدام الهيكل 
main();
sub main { #<<<
## old main code goes here
}

تعليق جانبي "#<<<" non-indenting-braces ليس مطلوبًا ولكنه سيحافظ على المسافة البادئة للتعليمات البرمجية القديمة دون تغيير.

يتم تطبيق هذا الفحص فقط على عبارات الحزمة التي لا يتم تضمينها في أقواس الكتلة لتجنب التحذيرات عند تغييرات الحزمة المؤقتة.

u: متغيرات غير مستخدمة
هذه هي المتغيرات المعجمية المعرفة باستخدام "my" أو "state" (ولكن ليس "our") ولم يتم الإشارة إليها مرة أخرى داخل نطاقها. تسميتها غير مستخدمة أمر مناسب ولكنه ليس دقيقًا حقًا؛ هذه "منطقة رمادية" للبرنامج. هناك بعض الأسباب الوجيهة لوجود مثل هذه المتغيرات. على سبيل المثال، قد تحدث في قائمة قيم مقدمة بواسطة روتين آخر أو بنية بيانات، وبالتالي يجب إدراجها، على الرغم من أنها قد لا تتم الإشارة إليها مرة أخرى. وجود مثل هذه المتغيرات يمكن أن يجعلها متاحة على الفور للتطوير المستقبلي والتصحيح، ويمكن أن يكون مفيدًا لوضوح البرنامج.

ولكن في بعض الأحيان يمكن أن تحدث بسبب اليتمان من تغيير في التعليمات البرمجية، أو بسبب خطأ إملائي، أو بسبب وجود "my" سابق غير مقصود. لذلك يستحق الأمر مراجعتها، خاصة بالنسبة للتعليمات البرمجية الجديدة. فيما يلي مثال على متغير غير مستخدم في برنامج نصي تم العثور عليه بهذه الطريقة:

BEGIN { my $string = "" }
...
$string .= "ok";

يبدو هذا لطيفًا للوهلة الأولى، ولكن نطاق تعريف "my" يقتصر على الأقواس المحيطة، لذلك فهو ليس نفس المتغير مثل $string الآخر ويجب بالتالي الإبلاغ عنه على أنه غير مستخدم. تم التقاط هذه المشكلة بالذات بواسطة perl إذا استخدم المؤلف "strict".

c: ثوابت غير مستخدمة
هذه هي الأسماء التي تم تعريفها باستخدام "use constant" ولم تتم رؤية مرجع لها مرة أخرى داخل حزمتها. قد تكون مطلوبة بواسطة حزمة خارجية، أو مجموعة من التعريفات القياسية، أو متاحة للتطوير المستقبلي. وفي بعض الحالات غير العادية، قد يكون perltidy قد فاته مرجع. ولكنها قد تكون أيضًا بقايا غير مستخدمة من تطوير التعليمات البرمجية، أو بسبب خطأ إملائي، لذلك يمكن أن يكون من المفيد مراجعتها.

perltidy -wvt='*' somefile.pl

perltidy -wvt='s r' somefile.pl

Use --exclude-partial-match=SUFFIX to suppress warnings for unused variables with a suffix
This option can be used to suppress warnings for unused variables that have a specific suffix. For example, if you have a variable named $value_unused that you know is intentionally unused, you can add its suffix to the exclusion list to prevent perltidy from issuing a warning. This is done with the following option: 
-w --exclude-partial-match=_unused

This partial match option provides a way to trigger a warning message when a new unused variable is detected in a script. This can be accomplished by adding a unique suffix to the names of existing unused variables, such as "_unused". This suffix is then added to the exclusion list.

As a specific example, consider the following line which is part of some debug code which only references the latter three variables (but might someday need to reference the package variable too).

my ( $package_uu, $filename, $line, $subroutine ) = caller();

The unused variable, $package_uu, has been specially marked with suffix "_uu". No type u (unused variable) warning will be produced provided that this wildcard suffix is in the exclusion list:

-wvxl='*_uu'
Use --dump-unique-keys to help locate misspelled hash keys
The parameter --dump-unique-keys, or -duk, dumps a list of hash keys which appear to be used just once, and do not appear among the quoted strings in a file. For example: 
perltidy -duk File.pm >output.txt

The lines in the output file list unique keys and line numbers.

Many programs contain sets of hash keys which are largely unique to that program but which are used for communication with other programs. A filter is used to avoid listing such keys. This filter is described in the next section.

A program "dump_unique_keys.pl" at https://github.com/perltidy/perltidy/tree/master/examples can run perltidy with -duk on multiple files, and then remove any common keys from the list.

Use --warn-unique-keys-cutoff=N, or -wukc=N, to adjust the unique keys filter.
This parameter controls the filter used by both --dump-unique-keys and its counterpart --warn-unique-keys, described below. The filter works as follows: if a related set of keys has more than N unique keys, then none of them are listed. The default value is N=1, which causes the minimum number of keys to be reported. Increasing N above 1 will allow more unique keys to be reported.

Thus, a value N=1 will catch up to 1 error per set of related keys. A value N=2 will catch up to two errors per set, but at the same time may produce more unwanted warnings.

For the special case N=1 some extra filtering is done to minimize unwanted warnings. For examples, unique keys in ALL CAPS are not reported for N=1.

Use --warn-unique-keys to warn of possible misspelled hash keys
The parameter --warn-unique-keys, or -wuk, can be used to produce a warning of a possible misspelled hash key during normal processing. It works like the previous -dump version but writes to the standard error output if unique keys are found during normal formatting.

For some scripts, this will produce unwanted warnings for a few keys, even though the filter described above attempts to avoid this. A way to avoid warnings for specific keys is to list them somewhere in the program in a qw list. This will be seen during the key scan, and the then keys will not be considered unique.

Use --dump-similar-keys to help locate misspelled hash keys
The parameter --dump-similar-keys, or -dsk, provides another way to help locate errors in hash keys. It dumps a list of hash keys which are very similar but different. For example: 
perltidy -dsk File.pm >output.txt

The lines in the output file contain pairs of similar keys, and the number of times each was found in the file. For example, the following line is from an actual script:

recieve,receive,2,6

This tells us that the key "recieve" (a spelling error) occurs 2 times and the correct key "receive" occurs 6 times:

Note that if this error had occurred just once then it could have also been found with --dump-unique-keys or --warn-unique-keys. But since it occurs more than once, the --dump-similar-keys option or its --warn- version is needed to locate it.

Use --warn-similar-keys, or -wsk, to warn of hash keys which are similar but different.
This is the like the --dump-similar-keys option but writes to the error output file during normal formatting.

In most cases, the warnings will be for perfectly valid hash keys. So this parameter is probably most useful for occasional debugging. See "Creating a new abbreviation" for a convenient way to include it in a .perltidyrc.

Controls for --dump-similar keys and --warn-similar-keys
The default parameters which control the search for similar keys should be normally be adequate, but they can be modified if necessary. They are as follows:
--similar-keys-maximum-difference=n, or -skmd=n, specifies the maximum difference between two keys for similarity.
The integer n gives the maximum number of differences to use when checking for hash key similarity. The default is n=1. The basic rules are that one difference is counted for each of the following conditions:
  • a change in case of a letter, any number of times, such as "LENGTH, length". This is implemented by making comparisons with lower case copies of the strings if any case change is detected.
  • one or more same-character changes, such as "number-of-lines, number_of_lines". This is implemented by remembering any change such as - to _ in this example, and counting it just once.
  • transposed characters, such as "recieve, receive"
  • a missing or extra character, such as "color, colour" or "color, _color"
  • any other character difference, such as "transparent, transparant"

To help filter out unwanted matches, an additional rule is that one extra difference is counted if the leading letters are different when we ignore their case.

For example, "_xmin, _Xmin" has a difference of one because of the case change, but the first letter is the same except for the case change. So the difference is one and this pair will be reported with the default setting n=1.

On the other hand, the pair "_xmin, _ymin" has a different first letter which is not due to a case change, so the total difference score is 2, and it will not be reported with the default setting n=1. And this type of difference is unlikely to be an error.

So the default value -skmd=1 will catch most common errors without producing excessive output, but for a more thorough check it can be increased to n=2.

Values greater than 2 can produce a large amount output, so rather than use higher values, it might be better to dump all of the keys and examine them with the --dump-hash-keys parameter described below.

--similar-keys-minimum-length=n, or -skml=n, defines a minimum hash key length.
Hash keys with fewer than n characters will be ignored when checking for similar keys. The default is n=4.
--similar-keys-maximum-pairs=n, or -skmp=n, defines the maximum number of similar pairs to display
Each similar pair found is displayed on one line of output, so this is equivalent to the maximum number of output lines. The default is 25.
Use --dump-hash-keys to dump a list of hash keys
The parameter --dump-hash-keys, or -dhk, dumps a list of all hash keys found by perltidy to the standard output and exits. It can produce a lot of output, but it might be useful as a last resort when searching for a hash key problem. For example: 
perltidy -dhk File.pm >output.txt

The lines in the output file list the keys and number of occurrences.

Use --dump-mixed-call-parens to find functions called both with and without parens
The parameter --dump-mixed-call-parens, or -dmcp, provides information on the use of call parens within a program. It produces a list of keywords and sub names which occur both with and without parens. In other words, with a mixed style. This might be useful if one is working to standardize the call style for some particular keyword or function. For example, 
perltidy -dmcp somefile.pl >output.txt

will analyze the text of somefile.pl, write the results to output.txt, and then immediately exit (like all dump- parameters).

The output shows a list of operators and the number of times they were used with parens and the number of times without parens. For example, here is a small section of the output from one file in a past Perl distribution:

The 'k' indicates that "length" is a Perl builtin keyword ('U' would mean user-defined sub, and 'w' would mean unknown bareword). NAME

perltidy - Tidy Perl code, with options to format HTML and POD

SYNOPSIS

perltidy [options] [file ...]

DESCRIPTION

perltidy is a Perl script that pretty-prints and formats Perl code. It can be used to reformat existing Perl scripts, or to format Perl code as it is being developed. It is highly configurable, and can be used to enforce a consistent coding style within a project or organization.

perltidy can also format embedded HTML and POD documentation within Perl scripts. It can convert POD documentation to HTML, and can also be used to format HTML files directly.

EXAMPLES

Format a Perl script and overwrite the original file:

    perltidy MyScript.pl

Format multiple Perl scripts and save the reformatted versions to new files:

    perltidy -o MyScript.new.pl MyScript.pl MyOtherScript.pl

Format a Perl script and save the reformatted version to standard output:

    perltidy -st MyScript.pl

Format a Perl script and embed the reformatted version in an HTML file:

    perltidy -html MyScript.pl

POD Options

System Options
