Perl__Critic__Policy__ErrorHandling__RequireCheckingReturnValueOfEval(3pm)

الحزمة: perl-perl-critic

التراخيص: PerlArtistic

Perl::Critic::Policy::ErrorHandling::RequireCheckingReturnValueOfEval(3pm) User Contributed Perl Documentation Perl::Critic::Policy::ErrorHandling::RequireCheckingReturnValueOfEval(3pm)

الاسم

Perl::Critic::Policy::ErrorHandling::RequireCheckingReturnValueOfEval - لا يمكنك الاعتماد على قيمة "$@" / "$EVAL_ERROR" لتحديد ما إذا كان "eval" قد فشل.

الانتماء

هذه السياسة جزء من التوزيع الأساسي لـ Perl::Critic.

الوصف

الاصطلاح الشائع في بيرل للتعامل مع الأخطاء المحتملة هو استخدام "eval" متبوعًا بفحص $@/$EVAL_ERROR:

eval {
    ...
};
if ($EVAL_ERROR) {
    ...
}

هناك مشكلة في هذا: يمكن أن تتغير قيمة $EVAL_ERROR بين نهاية "eval" وعبارة "if". المشكلة هي مدمرات الكائنات (object destructors):

package Foo;
...
sub DESTROY {
    ...
    eval { ... };
    ...
}
package main;
eval {
    my $foo = Foo->new();
    ...
};
if ($EVAL_ERROR) {
    ...
}

بافتراض عدم وجود مراجع أخرى لـ $foo تم إنشاؤها، عند الخروج من كتلة "eval" في "main"، سيتم استدعاء Foo::DESTROY()، بغض النظر عما إذا كان "eval" قد انتهى بشكل طبيعي أم لا. إذا فشل "eval" في "main"، ولكن نجح "eval" في Foo::DESTROY()، فسيكون $EVAL_ERROR فارغًا بحلول الوقت الذي يتم فيه تنفيذ "if". تنشأ مشكلات إضافية إذا اعتمدت على المحتويات الدقيقة لـ $EVAL_ERROR وفشل كلا الـ "eval"، لأن رسائل كلا الأمرين سيتم دمجها.

حتى لو لم يكن هناك "eval" مباشرة في رمز الطريقة DESTROY()، فقد تستدعي رمزًا يستخدم "eval" أو يؤثر بطريقة أخرى على $EVAL_ERROR.

الحل هو التأكد من أن "eval"، عند الخروج الطبيعي، يعيد قيمة حقيقية (true) واختبار تلك القيمة:

# المنشئات ليست مشكلة.
my $object = eval { Class->new() };
# لتغطية إمكانية أن تعيد عملية قيمة زائفة (false) بشكل صحيح، اختتم الكتلة بـ "1":
if ( eval { something(); 1 } ) {
    ...
}
eval {
    ...
    1;
}
    or do {
        # معالجة الأخطاء هنا
    };

لسوء الحظ، لا يمكنك استخدام الدالة "defined" لاختبار النتيجة؛ "eval" يعيد سلسلة فارغة عند الفشل.

تمت كتابة وحدات مختلفة لأخذ بعض الألم من العزل الصحيح وفحص $@/$EVAL_ERROR. على سبيل المثال:

use Try::Tiny;
try {
    ...
} catch {
    # معالجة الأخطاء هنا؛
    # الاستثناء في $_/$ARG، وليس $@/$EVAL_ERROR.
};  # لاحظ الفاصلة المنقوطة.

"لكننا لا نستخدم DESTROY() في أي مكان في كودنا!" كما تقول. قد يكون هذا هو الحال، ولكن هل لدى أي من الوحدات الخارجية التي تستخدمها؟ ماذا عن أي وحدات قد تستخدمها في المستقبل أو إصدارات محدثة من الوحدات التي تستخدمها بالفعل؟

التكوين

هذه السياسة غير قابلة للتكوين باستثناء الخيارات القياسية.

انظر أيضًا
