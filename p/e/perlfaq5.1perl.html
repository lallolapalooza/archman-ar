كيف أفرّغ/ألغي تخزين مقبض ملف إخراج؟ لماذا يجب عليّ فعل ذلك؟

(ساهم به brian d foy)

قد ترغب في قراءة "Suffering From Buffering" لمارك جيسون دومينوس على http://perl.plover.com/FAQs/Buffering.html .

يقوم Perl عادةً بتخزين الإخراج مؤقتًا حتى لا يقوم باستدعاء نظام لكل جزء من الإخراج. فبتراكم الإخراج، يقوم بعدد أقل من استدعاءات النظام المكلفة. على سبيل المثال، في هذا الجزء الصغير من الشيفرة، تريد طباعة نقطة على الشاشة لكل سطر تعالجه لمتابعة تقدم برنامجك. بدلاً من رؤية نقطة لكل سطر، يخزّن Perl الإخراج مؤقتًا وتنتظر طويلاً قبل أن ترى صفًا من 50 نقطة دفعة واحدة:

# انتظار طويل، ثم صف من النقاط دفعة واحدة
while( <> ) {
    print ".";
    print "\n" unless ++$count % 50;
    #... عمليات معالجة أسطر مكلفة
}

للتحايل على ذلك، عليك إلغاء تخزين مقبض ملف الإخراج، في هذه الحالة، "STDOUT". يمكنك تعيين المتغير الخاص $| إلى قيمة صحيحة (للتذكير: جعل مقابض ملفاتك "ساخنة كالأنابيب"):

$|++;
# تُعرض النقطة فورًا
while( <> ) {
    print ".";
    print "\n" unless ++$count % 50;
    #... عمليات معالجة أسطر مكلفة
}

إن $| هو أحد المتغيرات الخاصة لكل مقبض ملف، لذا لكل مقبض ملف نسخته الخاصة من قيمته. إذا كنت تريد دمج الإخراج القياسي والخطأ القياسي مثلاً، عليك إلغاء تخزين كل منهما (رغم أن STDERR قد يكون غير مخزّن افتراضيًا):

{
    my $previous_default = select(STDOUT);  # احفظ الافتراضي السابق
    $|++;                                   # تفريغ تلقائي لـ STDOUT
    select(STDERR);
    $|++;                                   # تفريغ تلقائي لـ STDERR، للتأكد
    select($previous_default);              # استعد الافتراضي السابق
}
# الآن يجب أن تتناوب . و +
while( 1 ) {
    sleep 1;
    print STDOUT ".";
    print STDERR "+";
    print STDOUT "\n" unless ++$count % 25;
}

إلى جانب المتغير الخاص $|، يمكنك استخدام "binmode" لإعطاء مقبض ملفك طبقة ":unix"، وهي غير مخزّنة:

binmode( STDOUT, ":unix" );
while( 1 ) {
    sleep 1;
    print ".";
    print "\n" unless ++$count % 50;
}

لمزيد من المعلومات حول طبقات الإخراج، راجع المدخلات الخاصة بـ "binmode" و open في perlfunc، و وثائق وحدة PerlIO.

إذا كنت تستخدم IO::Handle أو إحدى فئاته الفرعية، يمكنك استدعاء الدالة "autoflush" لتغيير إعدادات مقبض الملف:

use IO::Handle;
open my( $io_fh ), ">", "output.txt";
$io_fh->autoflush(1);

تمتلك كائنات IO::Handle أيضًا دالة "flush". يمكنك تفريغ المخزن المؤقت في أي وقت تريد دون تفريغ تلقائي

$io_fh->flush;

كيف أغيّر أو أحذف أو أُدرج سطرًا في ملف، أو أُضيف إلى بداية ملف؟

(ساهم به brian d foy)

الفكرة الأساسية لإدراج أو تغيير أو حذف سطر من ملف نصي تتضمن قراءة وطباعة الملف حتى النقطة التي تريد إجراء التغيير عندها، ثم إجراء التغيير، ثم قراءة وطباعة بقية الملف. لا يوفر Perl وصولاً عشوائيًا إلى الأسطر (خاصةً أن فاصل إدخال السجلات، $/، قابل للتغيير)، رغم أن وحدات مثل Tie::File يمكنها محاكاة ذلك.

يأخذ برنامج Perl للقيام بهذه المهام الشكل الأساسي لفتح ملف، وطباعة أسطره، ثم إغلاق الملف:

open my $in,  '<',  $file      or die "Can't read old file: $!";
open my $out, '>', "$file.new" or die "Can't write new file: $!";
while( <$in> ) {
        print $out $_;
}
close $out;

ضمن ذلك الشكل الأساسي، أضف الأجزاء التي تحتاجها لإدراج أو تغيير أو حذف الأسطر.

لإضافة أسطر إلى البداية، اطبع تلك الأسطر قبل أن تدخل الحلقة التي تطبع الأسطر الموجودة.

open my $in,  '<',  $file      or die "Can't read old file: $!";
open my $out, '>', "$file.new" or die "Can't write new file: $!";
print $out "# Add this line to the top\n"; # <--- هنا السحر
while( <$in> ) {
        print $out $_;
}
close $out;

لتغيير الأسطر الموجودة، أدرج الشيفرة لتعديل الأسطر داخل حلقة "while". في هذه الحالة، تجد الشيفرة جميع النسخ المكتوبة بأحرف صغيرة من "perl" وتحوّلها إلى أحرف كبيرة. يحدث هذا لكل سطر، لذا تأكد من أنك من المفترض أن تفعل ذلك على كل سطر!

open my $in,  '<',  $file      or die "Can't read old file: $!";
open my $out, '>', "$file.new" or die "Can't write new file: $!";
print $out "# Add this line to the top\n";
while( <$in> ) {
    s/\b(perl)\b/Perl/g;
    print $out $_;
}
close $out;

لتغيير سطر معين فقط، فإن رقم سطر الإدخال، $.، مفيد. أولاً اقرأ واطبع الأسطر حتى السطر الذي تريد تغييره. بعد ذلك، اقرأ السطر الوحيد الذي تريد تغييره، وغيّره، واطبعه. بعد ذلك، اقرأ بقية الأسطر واطبع تلك:

while( <$in> ) { # اطبع الأسطر قبل التغيير
    print $out $_;
    last if $. == 4; # رقم السطر قبل التغيير
}
my $line = <$in>;
$line =~ s/\b(perl)\b/Perl/g;
print $out $line;
while( <$in> ) { # اطبع بقية الأسطر
    print $out $_;
}

لتخطي الأسطر، استخدم أدوات التحكم في الحلقات. إن "next" في هذا المثال تتخطى أسطر التعليقات، و"last" توقف كل المعالجة بمجرد أن تصادف إما "__END__" أو "__DATA__".

while( <$in> ) {
    next if /^\s+#/;             # تخطَّ أسطر التعليقات
    last if /^__(END|DATA)__$/;  # توقف عند علامة نهاية الشيفرة
    print $out $_;
}

افعل الشيء نفسه لحذف سطر معين باستخدام "next" لتخطي الأسطر التي لا تريد ظهورها في الإخراج. يتخطى هذا المثال كل سطر خامس:

while( <$in> ) {
    next unless $. % 5;
    print $out $_;
}

إذا كنت، لسبب غريب ما، تريد حقًا رؤية الملف بأكمله دفعة واحدة بدلاً من معالجته سطرًا بسطر، يمكنك ابتلاعه بالكامل (طالما يمكنك احتواء كل شيء في الذاكرة!):

open my $in,  '<',  $file      or die "Can't read old file: $!";
open my $out, '>', "$file.new" or die "Can't write new file: $!";
my $content = do { local $/; <$in> }; # ابتلاع!
    # افعل سحرك هنا
print $out $content;

يمكن أن تساعد وحدات مثل Path::Tiny و Tie::File في ذلك أيضًا. ومع ذلك، إن أمكن، تجنّب قراءة الملف بأكمله دفعة واحدة. لن يعيد Perl تلك الذاكرة إلى نظام التشغيل حتى تنتهي العملية.

يمكنك أيضًا استخدام أوامر Perl أحادية السطر لتعديل ملف في مكانه. تُغيّر الأوامر التالية جميع 'Fred' إلى 'Barney' في inFile.txt، مع الكتابة فوق الملف بالمحتويات الجديدة. مع مفتاح "-p"، يلفّ Perl حلقة "while" حول الشيفرة التي تحددها بـ "-e"، و "-i" تشغّل التحرير في المكان. إن السطر الحالي في $_. مع "-p"، يطبع Perl تلقائيًا قيمة $_ في نهاية الحلقة. راجع perlrun لمزيد من التفاصيل.

perl -pi -e 's/Fred/Barney/' inFile.txt

لعمل نسخة احتياطية من "inFile.txt"، أعطِ "-i" امتداد ملف لإضافته:

perl -pi.bak -e 's/Fred/Barney/' inFile.txt

لتغيير السطر الخامس فقط، يمكنك إضافة اختبار يفحص $.، رقم سطر الإدخال، ثم تنفيذ العملية فقط عندما ينجح الاختبار:

perl -pi -e 's/Fred/Barney/ if $. == 5' inFile.txt

لإضافة أسطر قبل سطر معين، يمكنك إضافة سطر (أو أسطر!) قبل أن يطبع Perl المتغير $_:

perl -pi -e 'print "Put before third line\n" if $. == 3' inFile.txt

يمكنك حتى إضافة سطر إلى بداية الملف، لأن السطر الحالي يُطبع في نهاية الحلقة:

perl -pi -e 'print "Put before first line\n" if $. == 1' inFile.txt

لإدراج سطر بعد سطر موجود بالفعل في الملف، استخدم المفتاح "-n". إنه تمامًا مثل "-p" باستثناء أنه لا يطبع $_ في نهاية الحلقة، لذا عليك القيام بذلك بنفسك. في هذه الحالة، اطبع $_ أولاً، ثم اطبع السطر الذي تريد إضافته.

perl -ni -e 'print; print "Put after fifth line\n" if $. == 5' inFile.txt

لحذف الأسطر، اطبع فقط الأسطر التي تريدها.

perl -ni -e 'print if /d/' inFile.txt

كيف أحسب عدد الأسطر في ملف؟

(ساهم به brian d foy)

من الناحية المفاهيمية، أسهل طريقة لحساب الأسطر في ملف هي ببساطة قراءتها وحسابها:

my $count = 0;
while( <$fh> ) { $count++; }

لكنك لست مضطرًا فعليًا لحسابها بنفسك، لأن Perl يفعل ذلك بالفعل باستخدام المتغير $.، وهو رقم السطر الحالي من آخر قراءة لمقبض الملف:

1 while( <$fh> );
my $count = $.;

إذا كنت تريد استخدام $.، يمكنك اختصاره إلى سطر واحد بسيط، مثل أحد هذين:

% perl -lne '} print $.; {'    file
% perl -lne 'END { print $. }' file

لكن هذه قد تكون غير فعالة إلى حد ما. إذا لم تكن سريعة بما يكفي بالنسبة لك، يمكنك ببساطة قراءة أجزاء من البيانات وحساب عدد الأسطر الجديدة:

my $lines = 0;
open my($fh), '<:raw', $filename or die "Can't open $filename: $!";
while( sysread $fh, $buffer, 4096 ) {
    $lines += ( $buffer =~ tr/\n// );
}
close $fh;

ومع ذلك، هذا لا يعمل إذا لم تكن نهاية السطر سطرًا جديدًا. قد تغير "tr///" إلى "s///" حتى تتمكن من حساب عدد المرات التي يظهر فيها فاصل سجل الإدخال، $/:

my $lines = 0;
open my($fh), '<:raw', $filename or die "Can't open $filename: $!";
while( sysread $fh, $buffer, 4096 ) {
    $lines += ( $buffer =~ s|$/||g );
}
close $fh;

إذا لم تمانع من استدعاء الصدفة، فإن الأمر "wc" عادةً هو الأسرع، حتى مع الحمل الإضافي بين العمليات. تأكد من أن لديك اسم ملف غير ملوث:

#!perl -T
$ENV{PATH} = undef;
my $lines;
if( $filename =~ /^([0-9a-z_.]+)\z/ ) {
    $lines = `/usr/bin/wc -l $1`;
    chomp $lines;
}

كيف أحذف آخر N سطرًا من ملف؟

(ساهم به brian d foy)

أسهل حل مفاهيمي هو حساب الأسطر في الملف ثم البدء من البداية وطباعة عدد الأسطر (ناقص آخر N) إلى ملف جديد.

في أغلب الأحيان، السؤال الحقيقي هو كيف يمكنك حذف آخر N سطرًا دون إجراء أكثر من تمريرة واحدة على الملف، أو كيف تفعل ذلك دون الكثير من النسخ. المفهوم السهل هو الواقع الصعب عندما يكون لديك ملايين الأسطر في ملفك.

إحدى الحيل هي استخدام File::ReadBackwards، الذي يبدأ من نهاية الملف. توفر هذه الوحدة كائنًا يغلف مقبض الملف الحقيقي لتسهيل التنقل في الملف. بمجرد وصولك إلى النقطة التي تحتاجها، يمكنك الحصول على مقبض الملف الفعلي والعمل معه كالمعتاد. في هذه الحالة، تحصل على موضع الملف في نهاية آخر سطر تريد الاحتفاظ به وتقتطع الملف إلى تلك النقطة:

use File::ReadBackwards;
my $filename = 'test.txt';
my $Lines_to_truncate = 2;
my $bw = File::ReadBackwards->new( $filename )
    or die "Could not read backwards in [$filename]: $!";
my $lines_from_end = 0;
until( $bw->eof or $lines_from_end == $Lines_to_truncate ) {
    print "Got: ", $bw->readline;
    $lines_from_end++;
}
truncate( $filename, $bw->tell );

تتميز وحدة File::ReadBackwards أيضًا بميزة تعيين فاصل سجل الإدخال إلى تعبير نمطي.

يمكنك أيضًا استخدام وحدة Tie::File التي تتيح لك الوصول إلى الأسطر عبر مصفوفة مربوطة. يمكنك استخدام عمليات المصفوفة العادية لتعديل ملفك، بما في ذلك تعيين الفهرس الأخير واستخدام "splice".

كيف يمكنني استخدام خيار "-i" في Perl من داخل برنامج؟

يضبط "-i" قيمة المتغير $^I في Perl، والذي بدوره يؤثر على سلوك "<>"؛ راجع perlrun لمزيد من التفاصيل. من خلال تعديل المتغيرات المناسبة مباشرة، يمكنك الحصول على نفس السلوك داخل برنامج أكبر. على سبيل المثال:

# ...
{
    local($^I, @ARGV) = ('.orig', glob("*.c"));
    while (<>) {
        if ($. == 1) {
            print "This line should appear at the top of each file\n";
        }
        s/\b(p)earl\b/${1}erl/i;        # Correct typos, preserving case
        print;
        close ARGV if eof;              # Reset $.
    }
}
# $^I and @ARGV return to their old values here

تعدل هذه الكتلة جميع ملفات ".c" في الدليل الحالي، وتترك نسخة احتياطية من البيانات الأصلية من كل ملف في ملف ".c.orig" جديد.

كيف يمكنني نسخ ملف؟

(ساهم به brian d foy)

استخدم وحدة File::Copy. تأتي مع Perl ويمكنها إجراء نسخ حقيقي عبر أنظمة الملفات، وتقوم بسحرها بطريقة محمولة.

use File::Copy;
copy( $original, $new_copy ) or die "Copy failed: $!";

إذا لم تتمكن من استخدام File::Copy، فسيتعين عليك القيام بالعمل بنفسك: افتح الملف الأصلي، وافتح ملف الوجهة، ثم اطبع إلى ملف الوجهة أثناء قراءة الأصل. عليك أيضًا أن تتذكر نسخ الأذونات والمالك والمجموعة إلى الملف الجديد.

كيف أصنع اسم ملف مؤقت؟

إذا كنت لا تحتاج إلى معرفة اسم الملف، يمكنك استخدام open() مع "undef" بدلاً من اسم الملف. في Perl 5.8 أو أحدث، تنشئ الدالة open() ملفًا مؤقتًا مجهولاً:

open my $tmp, '+>', undef or die $!;

بخلاف ذلك، يمكنك استخدام وحدة File::Temp.

use File::Temp qw/ tempfile tempdir /;
my $dir = tempdir( CLEANUP => 1 );
($fh, $filename) = tempfile( DIR => $dir );
# or if you don't need to know the filename
my $fh = tempfile( DIR => $dir );

كانت File::Temp وحدة قياسية منذ Perl 5.6.1. إذا لم يكن لديك Perl حديث بما يكفي مثبتًا، فاستخدم طريقة الصنف "new_tmpfile" من وحدة IO::File للحصول على مقبض ملف مفتوح للقراءة والكتابة. استخدمها إذا كنت لا تحتاج إلى معرفة اسم الملف:

use IO::File;
my $fh = IO::File->new_tmpfile()
    or die "Unable to make new temporary file: $!";

إذا كنت ملتزمًا بإنشاء ملف مؤقت يدويًا، فاستخدم معرف العملية و/أو قيمة الوقت الحالية. إذا كنت بحاجة إلى العديد من الملفات المؤقتة في عملية واحدة، فاستخدم عدادًا:

BEGIN {
    use Fcntl;
    use File::Spec;
    my $temp_dir  = File::Spec->tmpdir();
    my $file_base = sprintf "%d-%d-0000", $$, time;
    my $base_name = File::Spec->catfile($temp_dir, $file_base);
    sub temp_file {
        my $fh;
        my $count = 0;
        until( defined(fileno($fh)) || $count++ > 100 ) {
            $base_name =~ s/-(\d+)$/"-" . (1 + $1)/e;
            # O_EXCL is required for security reasons.
            sysopen $fh, $base_name, O_WRONLY|O_EXCL|O_CREAT;
        }
        if( defined fileno($fh) ) {
            return ($fh, $base_name);
        }
        else {
            return ();
        }
    }
}

كيف يمكنني التعامل مع الملفات ذات طول السجلات الثابت؟

الطريقة الأكثر كفاءة هي استخدام pack() وunpack(). هذا أسرع من استخدام substr() عند التعامل مع العديد والعديد من السلاسل. إنه أبطأ لعدد قليل فقط.

إليك جزء نموذجي من الكود لتقسيم وإعادة تجميع بعض أسطر الإدخال ذات التنسيق الثابت، في هذه الحالة من مخرجات ps العادي بأسلوب Berkeley:

# sample input line:
#   15158 p5  T      0:00 perl /home/tchrist/scripts/now-what
my $PS_T = 'A6 A4 A7 A5 A*';
open my $ps, '-|', 'ps';
print scalar <$ps>;
my @fields = qw( pid tt stat time command );
while (<$ps>) {
    my %process;
    @process{@fields} = unpack($PS_T, $_);
    for my $field ( @fields ) {
        print "$field: <$process{$field}>\n";
    }
    print 'line=', pack($PS_T, @process{@fields} ), "\n";
}

لقد استخدمنا شريحة تجزئة (hash slice) للتعامل بسهولة مع حقول كل صف. تخزين المفاتيح في مصفوفة يسهل التعامل معها كمجموعة أو التكرار عليها باستخدام "for". كما أنه يتجنب تلويث البرنامج بالمتغيرات العامة واستخدام المراجع الرمزية.

كيف يمكنني جعل مقبض ملف محليًا لإجراء فرعي؟ كيف أمرر مقابض الملفات بين الإجراءات الفرعية؟ كيف أصنع مصفوفة من مقابض الملفات؟

اعتبارًا من perl5.6، تقوم open() بإنشاء مقابض الملفات والدلائل تلقائيًا كمراجع إذا مررت لها متغيرًا عدديًا غير مهيأ. يمكنك بعد ذلك تمرير هذه المراجع تمامًا مثل أي متغير عددي آخر، واستخدامها بدلاً من المقابض المسماة.

open my    $fh, $file_name;
open local $fh, $file_name;
print $fh "Hello World!\n";
process_file( $fh );

إذا أردت، يمكنك تخزين مقابض الملفات هذه في مصفوفة أو تجزئة. إذا وصلت إليها مباشرة، فهي ليست متغيرات عددية بسيطة وتحتاج إلى إعطاء "print" مساعدة صغيرة بوضع مرجع مقبض الملف بين أقواس معقوفة. لا يستطيع Perl اكتشافه بمفرده إلا عندما يكون مرجع مقبض الملف متغيرًا عدديًا بسيطًا.

my @fhs = ( $fh1, $fh2, $fh3 );
for( $i = 0; $i <= $#fhs; $i++ ) {
    print {$fhs[$i]} "just another Perl answer, \n";
}

قبل perl5.6، كان عليك التعامل مع أساليب typeglob المتنوعة التي قد تراها في الشيفرة الأقدم.

open FILE, "> $filename";
process_typeglob(   *FILE );
process_reference( \*FILE );
sub process_typeglob  { local *FH = shift; print FH  "Typeglob!" }
sub process_reference { local $fh = shift; print $fh "Reference!" }

إذا كنت تريد إنشاء العديد من المقابض المجهولة، فعليك التحقق من وحدتي Symbol أو IO::Handle.

كيف يمكنني استخدام مقبض ملف بشكل غير مباشر؟

مقبض الملف غير المباشر هو استخدام شيء آخر غير رمز في موضع يُتوقع فيه مقبض ملف. فيما يلي طرق للحصول على مقابض ملفات غير مباشرة:

$fh =   SOME_FH;       # bareword is strict-subs hostile
$fh =  "SOME_FH";      # strict-refs hostile; same package only
$fh =  *SOME_FH;       # typeglob
$fh = \*SOME_FH;       # ref to typeglob (bless-able)
$fh =  *SOME_FH{IO};   # blessed IO::Handle from *SOME_FH typeglob

أو يمكنك استخدام طريقة "new" من إحدى وحدات IO::* لإنشاء مقبض ملف مجهول وتخزينه في متغير عددي.

use IO::Handle;                     # 5.004 or higher
my $fh = IO::Handle->new();

ثم استخدم أيًا من تلك المقابض كما تستخدم مقبض ملف عادي. في أي مكان يتوقع فيه Perl مقبض ملف، يمكن استخدام مقبض ملف غير مباشر بدلاً منه. مقبض الملف غير المباشر هو مجرد متغير عددي يحتوي على مقبض ملف. الدوال مثل "print"، "open"، "seek"، أو معامل الماسة "<FH>" ستقبل إما مقبض ملف مسمّى أو متغيرًا عدديًا يحتوي على واحد:

($ifh, $ofh, $efh) = (*STDIN, *STDOUT, *STDERR);
print $ofh "Type it: ";
my $got = <$ifh>;
print $efh "What was that: $got";

إذا كنت تمرر مقبض ملف إلى دالة، يمكنك كتابة الدالة بطريقتين:

sub accept_fh {
    my $fh = shift;
    print $fh "Sending to indirect filehandle\n";
}

أو يمكنها توطين typeglob واستخدام مقبض الملف مباشرة:

sub accept_fh {
    local *FH = shift;
    print  FH "Sending to localized filehandle\n";
}

كلا الأسلوبين يعملان مع الكائنات أو typeglobs لمقابض ملفات حقيقية. (قد يعملان أيضًا مع السلاسل النصية في بعض الظروف، لكن هذا محفوف بالمخاطر.)

accept_fh(*STDOUT);
accept_fh($handle);

في الأمثلة أعلاه، أسندنا مقبض الملف إلى متغير عددي قبل استخدامه. ذلك لأن المتغيرات العددية البسيطة فقط، وليس التعبيرات أو الفهارس السفلية للتجزئات أو المصفوفات، يمكن استخدامها مع الدوال المدمجة مثل "print"، "printf"، أو معامل الماسة. استخدام شيء آخر غير متغير عددي بسيط كمقبض ملف غير قانوني ولن يُترجم حتى:

my @fd = (*STDIN, *STDOUT, *STDERR);
print $fd[1] "Type it: ";                           # WRONG
my $got = <$fd[0]>                                  # WRONG
print $fd[2] "What was that: $got";                 # WRONG

مع "print" و "printf"، تتغلب على هذا باستخدام كتلة وتعبير حيث تضع مقبض الملف:

print  { $fd[1] } "funny stuff\n";
printf { $fd[1] } "Pity the poor %x.\n", 3_735_928_559;
# Pity the poor deadbeef.

تلك الكتلة هي كتلة صحيحة مثل أي كتلة أخرى، لذا يمكنك وضع شيفرة أكثر تعقيدًا هناك. هذا يرسل الرسالة إلى أحد مكانين:

my $ok = -x "/bin/cat";
print { $ok ? $fd[1] : $fd[2] } "cat stat $ok\n";
print { $fd[ 1+ ($ok || 0) ]  } "cat stat $ok\n";

هذا النهج في التعامل مع "print" و "printf" كأنها استدعاءات دوال كائنات لا يعمل مع معامل الماسة. ذلك لأنه معامل حقيقي، وليس مجرد دالة بوسيط بدون فاصلة. بافتراض أنك كنت تخزن typeglobs في بنيتك كما فعلنا أعلاه، يمكنك استخدام الدالة المدمجة المسماة "readline" لقراءة سجل تمامًا كما يفعل "<>". بالنظر إلى التهيئة الموضحة أعلاه لـ @fd، سيعمل هذا، ولكن فقط لأن readline() يتطلب typeglob. لا يعمل مع الكائنات أو السلاسل النصية، والذي قد يكون خطأً لم نصلحه بعد.

$got = readline($fd[0]);

تجدر الإشارة إلى أن هشاشة مقابض الملفات غير المباشرة ليست مرتبطة بما إذا كانت سلاسل نصية أو typeglobs أو كائنات أو أي شيء آخر. إنها صياغة المعاملات الأساسية. لعب لعبة الكائنات لا يساعدك على الإطلاق هنا.

كيف يمكنني فتح مقبض ملف إلى سلسلة نصية؟

(مساهمة من Peter J. Holzer، hjp-usenet2@hjp.at)

منذ Perl 5.8.0 يمكن إنشاء مقبض ملف يشير إلى سلسلة نصية عن طريق استدعاء open بمرجع إلى تلك السلسلة النصية بدلاً من اسم الملف. يمكن بعد ذلك استخدام مقبض الملف هذا للقراءة من أو الكتابة إلى السلسلة النصية:

open(my $fh, '>', \$string) or die "Could not open string for writing";
print $fh "foo\n";
print $fh "bar\n";    # $string now contains "foo\nbar\n"
open(my $fh, '<', \$string) or die "Could not open string for reading";
my $x = <$fh>;    # $x now contains "foo\n"

مع الإصدارات الأقدم من Perl، توفر وحدة IO::String وظائف مماثلة.

كيف يمكنني إعداد تنسيق تذييل لاستخدامه مع write()؟

لا توجد طريقة مدمجة للقيام بذلك، لكن perlform لديه بضعة تقنيات لجعل ذلك ممكنًا للمبرمج الجريء.

كيف يمكنني write() إلى سلسلة نصية؟

(مساهمة من brian d foy)

إذا كنت تريد "write" إلى سلسلة نصية، فعليك فقط <open> مقبض ملف إلى سلسلة نصية، وهو ما كان Perl قادرًا على فعله منذ Perl 5.6:

open FH, '>', \my $string;
write( FH );

بما أنك تريد أن تكون مبرمجًا جيدًا، فمن المحتمل أنك تريد استخدام مقبض ملف معجمي، على الرغم من أن التنسيقات مصممة للعمل مع مقابض ملفات bareword لأن أسماء التنسيق الافتراضية تأخذ اسم مقبض الملف. ومع ذلك، يمكنك التحكم في ذلك باستخدام بعض متغيرات Perl الخاصة لكل مقبض ملف: $^، الذي يسمي تنسيق أعلى الصفحة، و $~ الذي يظهر تنسيق السطر. عليك تغيير مقبض الملف الافتراضي لتعيين هذه المتغيرات:

open my($fh), '>', \my $string;
{ # set per-filehandle variables
    my $old_fh = select( $fh );
    $~ = 'ANIMAL';
    $^ = 'ANIMAL_TOP';
    select( $old_fh );
}
format ANIMAL_TOP =
 ID  Type    Name
.
format ANIMAL =
@##   @<<<    @<<<<<<<<<<<<<<
$id,  $type,  $name
.

على الرغم من أن write يمكن أن يعمل مع المتغيرات المعجمية أو متغيرات الحزمة، إلا أن المتغيرات التي تستخدمها يجب أن تكون في نطاق التنسيق. هذا على الأرجح يعني أنك ستريد توطين بعض متغيرات الحزمة:

{
    local( $id, $type, $name ) = qw( 12 cat Buster );
    write( $fh );
}
print $string;

هناك أيضًا بعض الحيل التي يمكنك تجربتها مع "formline" ومتغير التراكم $^A، لكنك تفقد الكثير من قيمة التنسيقات لأن "formline" لن يتعامل مع ترقيم الصفحات وما إلى ذلك. ينتهي بك الأمر بإعادة تنفيذ التنسيقات عند استخدامها.

كيف يمكنني إخراج أرقامي مع إضافة الفواصل؟

(مساهمة من brian d foy و Benjamin Goldberg)

تعرف وحدة CLDR::Number (مستودع بيانات اللغة المشتركة لليونيكود) كيفية تنسيق الأرقام بناءً على لغة محلية لاستخدام تجميع أرقامها وفاصلها:

use CLDR::Number;
my $number = 1234567890;
foreach my $locale ( qw(en-US de-DE en-IN) ) {
    my $cldr = CLDR::Number->new( locale => $locale );
    my $decimal = $cldr->decimal_formatter;
    printf "%-5s %s\n", $locale, $decimal->format( $number );
    }

يُظهر الإخراج نفس الرقم منسقًا وفقًا لقواعد كل لغة محلية. يستخدم "en" المجرد الفواصل بين مجموعات من ثلاثة، ويستخدم "de" النقاط ومجموعات من ثلاثة، ويستخدم "en-IN" قاعدة 3:2:2 مع الفواصل:

en-US 1,234,567,890
de-DE 1.234.567.890
en-IN 1,23,45,67,890

لدى CLDR::Number العديد من الميزات المتقدمة للتعامل مع أي شيء تقريبًا قد تريده. مقالة Olaf Alders "Stop Writing Your Own Commify Functions" تحتوي على المزيد من الأمثلة (https://www.olafalders.com/2015/09/04/stop-writing-your-own-commify-functions/).

إذا كنت تعرف بالضبط ما تريده، فقد يكفي إجراء فرعي بسيط. هذا المثال سيضيف فواصل إلى رقمك بين مجموعات من ثلاثة أرقام (أو أي تجميع). هذا يستخدم مجموعات من ثلاثة و فاصلة:

sub commify {
    local $_  = shift;
    1 while s/^([-+]?\d+)(\d{3})/$1,$2/;
    return $_;
}

هذا التعبير النمطي من Benjamin Goldberg يفعل الشيء نفسه بدون الحلقة:

s/(^[-+]?\d+?(?=(?>(?:\d{3})+)(?!\d))|\G\d{3}(?=\d))/$1,/g;

من الأسهل رؤيته مع التعليقات:

s/(
    ^[-+]?             # beginning of number.
    \d+?               # first digits before first comma
    (?=                # followed by, (but not included in the match) :
        (?>(?:\d{3})+) # some positive multiple of three digits.
        (?!\d)         # an *exact* multiple, not x * 3 + 1 or whatever.
    )
    |                  # or:
    \G\d{3}            # after the last group, get three digits
    (?=\d)             # but they have to have more digits after them.
)/$1,/xg;

كيف يمكنني ترجمة علامات التلدة (~) في اسم ملف؟

استخدم المعامل <> (glob())، الموثّق في perlfunc. تتطلب إصدارات Perl الأقدم من 5.6 أن يكون لديك صدفة (shell) مثبتة تفهم علامة التلدة (~). الإصدارات اللاحقة من Perl تحتوي على هذه الميزة مدمجة. توفر وحدة File::KGlob (المتاحة من CPAN) وظيفة glob أكثر قابلية للنقل.

داخل Perl، يمكنك استخدام هذا مباشرة:

$filename =~ s{
  ^ ~             # find a leading tilde
  (               # save this in $1
      [^/]        # a non-slash character
            *     # repeated 0 or more times (0 means me)
  )
}{
  $1
      ? (getpwnam($1))[7]
      : ( $ENV{HOME} || $ENV{LOGDIR} )
}ex;

عندما أفتح ملفًا للقراءة والكتابة، لماذا يُمحى محتواه؟

لأنك تستخدم شيئًا كهذا، والذي يقتطع الملف ثم يمنحك صلاحية القراءة والكتابة:

open my $fh, '+>', '/path/name'; # WRONG (almost always)

عذرًا. يجب عليك بدلاً من ذلك استخدام هذا، والذي سيفشل إذا لم يكن الملف موجودًا:

open my $fh, '+<', '/path/name'; # open for update

استخدام ">" دائمًا يمحو المحتوى أو ينشئ الملف. استخدام "<" لا يفعل أيًا منهما أبدًا. علامة "+" لا تغيّر ذلك.

فيما يلي أمثلة على أنواع عديدة من عمليات فتح الملفات. تلك التي تستخدم "sysopen" تفترض جميعها أنك قد استوردت الثوابت من Fcntl:

use Fcntl;

لفتح ملف للقراءة:

open my $fh, '<', $path                               or die $!;
sysopen my $fh, $path, O_RDONLY                       or die $!;

لفتح ملف للكتابة، وإنشاء ملف جديد إذا لزم الأمر أو اقتطاع الملف القديم:

open my $fh, '>', $path                               or die $!;
sysopen my $fh, $path, O_WRONLY|O_TRUNC|O_CREAT       or die $!;
sysopen my $fh, $path, O_WRONLY|O_TRUNC|O_CREAT, 0666 or die $!;

لفتح ملف للكتابة، وإنشاء ملف جديد، ويجب ألا يكون الملف موجودًا:

sysopen my $fh, $path, O_WRONLY|O_EXCL|O_CREAT        or die $!;
sysopen my $fh, $path, O_WRONLY|O_EXCL|O_CREAT, 0666  or die $!;

لفتح ملف للإلحاق، وإنشاء الملف إذا لزم الأمر:

open my $fh, '>>', $path                              or die $!;
sysopen my $fh, $path, O_WRONLY|O_APPEND|O_CREAT      or die $!;
sysopen my $fh, $path, O_WRONLY|O_APPEND|O_CREAT, 0666 or die $!;

لفتح ملف للإلحاق، ويجب أن يكون الملف موجودًا:

sysopen my $fh, $path, O_WRONLY|O_APPEND              or die $!;

لفتح ملف للتحديث، ويجب أن يكون الملف موجودًا:

open my $fh, '+<', $path                              or die $!;
sysopen my $fh, $path, O_RDWR                         or die $!;

لفتح ملف للتحديث، وإنشاء الملف إذا لزم الأمر:

sysopen my $fh, $path, O_RDWR|O_CREAT                 or die $!;
sysopen my $fh, $path, O_RDWR|O_CREAT, 0666           or die $!;

لفتح ملف للتحديث، ويجب ألا يكون الملف موجودًا:

sysopen my $fh, $path, O_RDWR|O_EXCL|O_CREAT          or die $!;
sysopen my $fh, $path, O_RDWR|O_EXCL|O_CREAT, 0666    or die $!;

لفتح ملف دون حجب، وإنشاء الملف إذا لزم الأمر:

sysopen my $fh, '/foo/somefile', O_WRONLY|O_NDELAY|O_CREAT
    or die "can't open /foo/somefile: $!";

كن حذرًا من أن إنشاء الملفات أو حذفها ليس مضمونًا أن يكون عملية ذرية (atomic) عبر NFS. أي أن عمليتين قد تنجحان كلتاهما في إنشاء أو إزالة ارتباط الملف نفسه! لذلك فإن O_EXCL ليس حصريًا كما قد تتمنى.

انظر أيضًا perlopentut.

لماذا أحصل أحيانًا على "Argument list too long" عندما أستخدم <*>؟

يقوم المعامل "<>" بعملية glob (انظر أعلاه). في إصدارات Perl الأقدم من v5.6.0، يقوم المعامل الداخلي glob() بتفريع csh(1) لتنفيذ توسيع glob الفعلي، لكن csh لا يمكنه التعامل مع أكثر من 127 عنصرًا ولذلك يعطي رسالة الخطأ "Argument list too long". الأشخاص الذين ثبّتوا tcsh كـ csh لن يواجهوا هذه المشكلة، لكن مستخدميهم قد يفاجؤون بها.

للتحايل على ذلك، إما أن ترقّي إلى Perl v5.6.0 أو أحدث، أو أن تنفذ glob بنفسك باستخدام readdir() والأنماط، أو أن تستخدم وحدة مثل File::Glob، وهي وحدة لا تستخدم الصدفة لتنفيذ glob.

كيف يمكنني فتح ملف اسمه يبدأ بـ ">" أو ينتهي بمسافات؟

(مساهمة من Brian McCauley)

الصيغة الخاصة ذات المعاملين لدالة open() في Perl تتجاهل المسافات اللاحقة في أسماء الملفات وتستنتج النمط من أحرف بادئة معينة (أو من "|" لاحقة). في الإصدارات الأقدم من Perl كانت هذه هي الصيغة الوحيدة لـ open() ولذلك فهي شائعة في الشيفرة القديمة والكتب.

ما لم يكن لديك سبب خاص لاستخدام الصيغة ذات المعاملين، يجب عليك استخدام الصيغة ذات المعاملات الثلاثة لـ open() والتي لا تعامل أي حرف في اسم الملف على أنه خاص.

open my $fh, "<", "  file  ";  # filename is "   file   "
open my $fh, ">", ">file";     # filename is ">file"

كيف يمكنني إعادة تسمية ملف بشكل موثوق؟

إذا كان نظام التشغيل لديك يدعم أداة mv(1) المناسبة أو ما يعادلها وظيفيًا، فإن هذا يعمل:

rename($old, $new) or system("mv", $old, $new);

قد يكون استخدام وحدة File::Copy أكثر قابلية للنقل. عليك فقط النسخ إلى الملف الجديد بالاسم الجديد (مع التحقق من قيم الإرجاع)، ثم حذف الملف القديم. هذا ليس مكافئًا دلاليًا حقًا لـ rename()، الذي يحافظ على المعلومات الوصفية مثل الأذونات والطوابع الزمنية ومعلومات inode وغيرها.

كيف يمكنني قفل ملف؟

دالة flock() المدمجة في Perl (انظر perlfunc للتفاصيل) ستستدعي flock(2) إذا كانت موجودة، وfcntl(2) إذا لم تكن موجودة (في إصدار Perl 5.004 وما بعده)، وlockf(3) إذا لم يكن أي من استدعاءي النظام السابقين موجودًا. في بعض الأنظمة، قد تستخدم حتى شكلًا مختلفًا من القفل الأصلي. فيما يلي بعض المزالق مع flock() في Perl:

1.
يُنتج خطأً قاتلًا إذا لم يكن أي من استدعاءات النظام الثلاثة (أو ما يعادلها القريب) موجودًا.
2.
lockf(3) لا يوفر القفل المشترك، ويتطلب أن يكون مقبض الملف مفتوحًا للكتابة (أو الإلحاق، أو القراءة/الكتابة).
3.
بعض إصدارات flock() لا يمكنها قفل الملفات عبر الشبكة (مثلًا على أنظمة ملفات NFS)، لذا ستحتاج إلى فرض استخدام fcntl(2) عند بناء Perl. لكن حتى هذا مشكوك فيه في أفضل الأحوال. انظر مدخل flock في perlfunc وملف INSTALL في توزيعة المصدر للحصول على معلومات حول بناء Perl للقيام بذلك.

هناك دلالتان محتملتان لـ flock غير واضحتين لكنهما تقليديتان: أنه ينتظر إلى ما لا نهاية حتى يُمنح القفل، وأن أقفاله استشارية فقط. هذه الأقفال التقديرية أكثر مرونة، لكنها تقدم ضمانات أقل. هذا يعني أن الملفات المقفلة بـ flock() قد تُعدَّل بواسطة برامج لا تستخدم flock() أيضًا. السيارات التي تتوقف عند الإشارات الحمراء تتفاهم مع بعضها البعض، لكن ليس مع السيارات التي لا تتوقف عند الإشارات الحمراء. انظر صفحة perlport، أو التوثيق الخاص بمنفذك، أو صفحات الدليل المحلية الخاصة بنظامك للحصول على التفاصيل. من الأفضل افتراض السلوك التقليدي إذا كنت تكتب برامج قابلة للنقل. (إذا لم تكن كذلك، يجب عليك كما هو الحال دائمًا أن تشعر بالحرية التامة في الكتابة وفقًا لخصوصيات نظامك (تسمى أحيانًا "ميزات"). لا ينبغي للالتزام العبودي بمخاوف قابلية النقل أن يعيق إنجاز عملك.)

لمزيد من المعلومات حول قفل الملفات، انظر أيضًا "File Locking" في perlopentut إذا كان لديك (جديد في 5.6).

لماذا لا يمكنني ببساطة استخدام open(FH, ">file.lock")؟

جزء شائع من الشيفرة يجب عدم استخدامه هو هذا:

sleep(3) while -e 'file.lock';    # PLEASE DO NOT USE
open my $lock, '>', 'file.lock'; # THIS BROKEN CODE

هذا حالة سباق كلاسيكية: تأخذ خطوتين لفعل شيء يجب أن يُفعل في خطوة واحدة. لهذا السبب توفر عتاديات الحاسوب تعليمة اختبار وتعيين ذرية. نظريًا، "يُفترض" أن يعمل هذا:

sysopen my $fh, "file.lock", O_WRONLY|O_EXCL|O_CREAT
    or die "can't open  file.lock: $!";

إلا أنه للأسف، إنشاء الملفات (وحذفها) ليس ذريًا عبر NFS، لذا لن يعمل هذا (على الأقل، ليس في كل مرة) عبر الشبكة. اقتُرحت مخططات متنوعة تتضمن link()، لكنها تميل إلى تضمين الانتظار المشغول (busy-wait)، وهو أيضًا أقل من مرغوب.

ما زلت لا أفهم القفل. أريد فقط زيادة الرقم في الملف. كيف يمكنني فعل ذلك؟

ألم يخبرك أحد قط أن عدادات زيارات صفحات الويب عديمة الفائدة؟ إنها لا تحسب عدد الزيارات، وهي مضيعة للوقت، ولا تخدم سوى إرضاء غرور الكاتب. من الأفضل اختيار رقم عشوائي؛ فهو أكثر واقعية.

على أي حال، هذا ما يمكنك فعله إذا لم تستطع مقاومة نفسك.

use Fcntl qw(:DEFAULT :flock);
sysopen my $fh, "numfile", O_RDWR|O_CREAT or die "can't open numfile: $!";
flock $fh, LOCK_EX                        or die "can't flock numfile: $!";
my $num = <$fh> || 0;
seek $fh, 0, 0                            or die "can't rewind numfile: $!";
truncate $fh, 0                           or die "can't truncate numfile: $!";
(print $fh $num+1, "\n")                  or die "can't write numfile: $!";
close $fh                                 or die "can't close numfile: $!";

إليك عداد زيارات صفحات ويب أفضل بكثير:

$hits = int( (time() - 850_000_000) / rand(1_000) );

إذا لم يُعجب العدد أصدقاءك، فقد تُعجبهم الشيفرة. :-)

كل ما أريده هو إلحاق كمية صغيرة من النص بنهاية ملف. هل لا يزال يتعين عليّ استخدام القفل؟

إذا كنت على نظام يطبّق "flock" بشكل صحيح وتستخدم مثال كود الإلحاق من "perldoc -f flock" فسيكون كل شيء على ما يرام حتى لو كان نظام التشغيل الذي تعمل عليه لا يطبّق وضع الإلحاق بشكل صحيح (إن وُجد مثل هذا النظام). لذا إذا كنت راضيًا بتقييد نفسك بأنظمة تشغيل تطبّق "flock" (وهذا ليس تقييدًا كبيرًا في الواقع) فهذا ما ينبغي عليك فعله.

إذا كنت تعلم أنك ستستخدم فقط نظامًا يطبّق الإلحاق بشكل صحيح (أي ليس Win32) فيمكنك حذف "seek" من الكود في الإجابة السابقة.

إذا كنت تعلم أنك تكتب كودًا ليعمل فقط على نظام تشغيل ونظام ملفات يطبّق وضع الإلحاق بشكل صحيح (نظام ملفات محلي على يونكس حديث مثلاً)، وتبقي الملف في وضع التخزين المؤقت بالكتل (block-buffered) وتكتب أقل من سعة مخزن مؤقت واحد من المخرجات بين كل تفريغ يدوي للمخزن المؤقت، فإن كل حمولة مخزن مؤقت مضمونة تقريبًا أن تُكتب إلى نهاية الملف في كتلة واحدة دون أن تختلط بمخرجات أي شخص آخر. يمكنك أيضًا استخدام الدالة "syswrite" وهي ببساطة غلاف حول استدعاء النظام write(2) في نظامك.

لا تزال هناك فرصة نظرية صغيرة أن تقاطع إشارة عملية write() على مستوى النظام قبل اكتمالها. وهناك أيضًا احتمال أن تستدعي بعض تطبيقات STDIO عدة استدعاءات write() على مستوى النظام حتى لو كان المخزن المؤقت فارغًا في البداية. قد توجد بعض الأنظمة التي ينخفض فيها هذا الاحتمال إلى الصفر، وهذا ليس مصدر قلق عند استخدام ":perlio" بدلاً من STDIO الخاص بنظامك.

كيف أحدّث ملفًا ثنائيًا بشكل عشوائي؟

إذا كنت تحاول فقط ترقيع ملف ثنائي، ففي كثير من الحالات ينجح شيء بسيط كهذا:

perl -i -pe 's{window manager}{window mangler}g' /usr/bin/emacs

ومع ذلك، إذا كانت لديك سجلات ذات حجم ثابت، فقد تفعل شيئًا أشبه بهذا:

my $RECSIZE = 220; # size of record, in bytes
my $recno   = 37;  # which record to update
open my $fh, '+<', 'somewhere' or die "can't update somewhere: $!";
seek $fh, $recno * $RECSIZE, 0;
read $fh, $record, $RECSIZE == $RECSIZE or die "can't read record $recno: $!";
# munge the record
seek $fh, -$RECSIZE, 1;
print $fh $record;
close $fh;

القفل والتحقق من الأخطاء متروكان كتمرين للقارئ. لا تنسَهما وإلا ستندم كثيرًا.

كيف أحصل على الطابع الزمني لملف في بيرل؟

إذا كنت تريد استرجاع الوقت الذي قُرئ فيه الملف آخر مرة، أو كُتب فيه، أو تغيّرت بياناته الوصفية (المالك، إلخ)، فاستخدم عمليات اختبار الملف -A أو -M أو -C كما هو موثق في perlfunc. تسترجع هذه عمر الملف (مقاسًا مقابل وقت بدء برنامجك) بالأيام كعدد عشري. قد لا تحتوي بعض المنصات على كل هذه الأوقات. راجع perlport للتفاصيل. لاسترجاع الوقت "الخام" بالثواني منذ الحقبة، ستستدعي دالة stat، ثم تستخدم localtime() أو gmtime() أو POSIX::strftime() لتحويل ذلك إلى صيغة مقروءة للبشر.

إليك مثالاً:

my $write_secs = (stat($file))[9];
printf "file %s updated at %s\n", $file,
    scalar localtime($write_secs);

إذا كنت تفضل شيئًا أكثر وضوحًا، فاستخدم وحدة File::stat (جزء من التوزيعة القياسية في الإصدار 5.004 وما بعده):

# error checking left as an exercise for reader.
use File::stat;
use Time::localtime;
my $date_string = ctime(stat($file)->mtime);
print "file $file updated at $date_string\n";

نهج POSIX::strftime() له ميزة أنه، نظريًا، مستقل عن اللغة المحلية الحالية. راجع perllocale للتفاصيل.

كيف أضبط الطابع الزمني لملف في بيرل؟

تستخدم الدالة utime() الموثقة في "utime" في perlfunc. على سبيل المثال، إليك برنامج صغير ينسخ أوقات القراءة والكتابة من وسيطه الأول إلى جميع الباقين.

if (@ARGV < 2) {
    die "usage: cptimes timestamp_file other_files ...\n";
}
my $timestamp = shift;
my($atime, $mtime) = (stat($timestamp))[8,9];
utime $atime, $mtime, @ARGV;

التحقق من الأخطاء، كالعادة، متروك كتمرين للقارئ.

تحتوي وثائق perldoc الخاصة بـ utime أيضًا على مثال له نفس تأثير touch(1) على الملفات الموجودة بالفعل.

بعض أنظمة الملفات لديها قدرة محدودة على تخزين الأوقات على ملف بالمستوى المتوقع من الدقة. على سبيل المثال، نظاما ملفات FAT وHPFS غير قادرين على إنشاء تواريخ على الملفات بدقة أدق من ثانيتين. هذا قيد في أنظمة الملفات، وليس في utime().

كيف أطبع إلى أكثر من ملف واحد في وقت واحد؟

لربط مقبض ملف واحد بعدة مقابض ملفات إخراج، يمكنك استخدام وحدتي IO::Tee أو Tie::FileHandle::MultiPlex.

إذا كان عليك فعل ذلك مرة واحدة فقط، فيمكنك الطباعة بشكل فردي إلى كل مقبض ملف.

for my $fh ($fh1, $fh2, $fh3) { print $fh "whatever\n" }

كيف يمكنني قراءة ملف كامل دفعة واحدة؟

النهج المعتاد في بيرل لمعالجة جميع الأسطر في ملف هو القيام بذلك سطرًا واحدًا في كل مرة:

open my $input, '<', $file or die "can't open $file: $!";
while (<$input>) {
    chomp;
    # do something with $_
}
close $input or die "can't close $file: $!";

هذا أكثر كفاءة بكثير من قراءة الملف بأكمله في الذاكرة كمصفوفة من الأسطر ثم معالجته عنصرًا واحدًا في كل مرة، وهو غالبًا--إن لم يكن دائمًا تقريبًا--النهج الخاطئ. كلما رأيت شخصًا يفعل هذا:

my @lines = <INPUT>;

يجب أن تفكر طويلاً وبعمق في سبب حاجتك إلى تحميل كل شيء دفعة واحدة. إنه ببساطة ليس حلاً قابلاً للتوسع.

إذا قمت بعمل "mmap" للملف باستخدام وحدة File::Map من CPAN، فيمكنك تحميل الملف بأكمله ظاهريًا في سلسلة نصية دون تخزينه فعليًا في الذاكرة:

use File::Map qw(map_file);
map_file my $string, $filename;

بمجرد تعيينه، يمكنك التعامل مع $string كما تتعامل مع أي سلسلة نصية أخرى. نظرًا لأنك لا تحتاج بالضرورة إلى تحميل البيانات، فإن mmap يمكن أن يكون سريعًا جدًا وقد لا يزيد من بصمة ذاكرتك.

قد تجد أيضًا أنه أكثر متعة استخدام وحدة Tie::File القياسية، أو ارتباطات $DB_RECNO في وحدة DB_File، التي تسمح لك بربط مصفوفة بملف بحيث يؤدي الوصول إلى عنصر من المصفوفة فعليًا إلى الوصول إلى السطر المقابل في الملف.

إذا كنت تريد تحميل الملف بأكمله، يمكنك استخدام وحدة Path::Tiny للقيام بذلك في خطوة واحدة بسيطة وفعالة:

use Path::Tiny;
my $all_of_it = path($filename)->slurp; # entire file in scalar
my @all_lines = path($filename)->lines; # one line per element

أو يمكنك قراءة محتويات الملف بأكمله في متغير عددي هكذا:

my $var;
{
    local $/;
    open my $fh, '<', $file or die "can't open $file: $!";
    $var = <$fh>;
}

هذا يجعل فاصل السجلات الخاص بك غير معرّف مؤقتًا، وسيغلق الملف تلقائيًا عند الخروج من الكتلة. إذا كان الملف مفتوحًا بالفعل، فاستخدم هذا فقط:

my $var = do { local $/; <$fh> };

يمكنك أيضًا استخدام @ARGV محليًا للتخلص من "open":

my $var = do { local( @ARGV, $/ ) = $file; <> };

كيف يمكنني قراءة ملف حسب الفقرات؟

استخدم المتغير $/ (راجع perlvar للتفاصيل). يمكنك إما ضبطه على "" للتخلص من الفقرات الفارغة ("abc\n\n\n\ndef"، على سبيل المثال، يُعامل كفقرتين وليس ثلاث)، أو "\n\n" لقبول الفقرات الفارغة.

لاحظ أن السطر الفارغ يجب ألا يحتوي على أي مسافات. لذا فإن "fred\n \nstuff\n\n" هي فقرة واحدة، لكن "fred\n\nstuff\n\n" هي فقرتان.

كيف يمكنني قراءة حرف واحد من ملف؟ من لوحة المفاتيح؟

يمكنك استخدام الدالة المدمجة getc() لمعظم مقابض الملفات، لكنها لن تعمل (بسهولة) على جهاز طرفي. بالنسبة لـ STDIN، إما استخدم وحدة Term::ReadKey من CPAN أو استخدم الكود النموذجي في "getc" في perlfunc.

إذا كان نظامك يدعم واجهة برمجة أنظمة التشغيل المحمولة (POSIX)، يمكنك استخدام الكود التالي، الذي ستلاحظ أنه يوقف معالجة الصدى أيضًا.

#!/usr/bin/perl -w
use strict;
$| = 1;
for (1..4) {
    print "gimme: ";
    my $got = getone();
    print "--> $got\n";
}
exit;
BEGIN {
    use POSIX qw(:termios_h);
    my ($term, $oterm, $echo, $noecho, $fd_stdin);
    my $fd_stdin = fileno(STDIN);
    $term     = POSIX::Termios->new();
    $term->getattr($fd_stdin);
    $oterm     = $term->getlflag();
    $echo     = ECHO | ECHOK | ICANON;
    $noecho   = $oterm & ~$echo;
    sub cbreak {
        $term->setlflag($noecho);
        $term->setcc(VTIME, 1);
        $term->setattr($fd_stdin, TCSANOW);
    }
    sub cooked {
        $term->setlflag($oterm);
        $term->setcc(VTIME, 0);
        $term->setattr($fd_stdin, TCSANOW);
    }
    sub getone {
        my $key = '';
        cbreak();
        sysread(STDIN, $key, 1);
        cooked();
        return $key;
    }
}
END { cooked() }

قد تكون وحدة Term::ReadKey من CPAN أسهل في الاستخدام. تتضمن الإصدارات الحديثة أيضًا دعمًات أيضاً للأنظمة غير القابلة للنقل.

use Term::ReadKey;
open my $tty, '<', '/dev/tty';
print "أعطني حرفاً: ";
ReadMode "raw";
my $key = ReadKey 0, $tty;
ReadMode "normal";
printf "\nقلت %s، رقم الحرف %03d\n",
    $key, ord $key;

كيف يمكنني معرفة ما إذا كان هناك حرف في انتظار على مقبض ملف؟

أول شيء يجب عليك فعله هو البحث في الحصول على امتداد Term::ReadKey من CPAN. كما ذكرنا سابقاً، أصبح لديه الآن حتى دعم محدود للأنظمة غير القابلة للنقل (اقرأ: ليست أنظمة مفتوحة، مغلقة، احتكارية، ليست POSIX، ليست يونكس، إلخ).

يجب عليك أيضاً الاطلاع على قائمة الأسئلة الشائعة في comp.unix.* لأشياء مثل هذه: الإجابة هي نفسها أساساً. إنها تعتمد على النظام بشكل كبير. إليك حل واحد يعمل على أنظمة BSD:

sub key_ready {
    my($rin, $nfd);
    vec($rin, fileno(STDIN), 1) = 1;
    return $nfd = select($rin,undef,undef,0);
}

إذا كنت تريد معرفة عدد الأحرف التي تنتظر، هناك أيضاً استدعاء ioctl FIONREAD الذي يجب النظر إليه. أداة h2ph التي تأتي مع Perl تحاول تحويل ملفات التضمين C إلى كود Perl، والذي يمكن "require"ه. ينتهي FIONREAD معرّفاً كدالة في ملف sys/ioctl.ph:

require './sys/ioctl.ph';
$size = pack("L", 0);
ioctl(FH, FIONREAD(), $size)    or die "Couldn't call ioctl: $!\n";
$size = unpack("L", $size);

إذا لم يتم تثبيت h2ph أو لم يعمل معك، يمكنك استخدام grep على ملفات التضمين يدوياً:

% grep FIONREAD /usr/include/*/*
/usr/include/asm/ioctls.h:#define FIONREAD      0x541B

أو اكتب برنامج C صغيراً باستخدام محرر الأبطال:

% cat > fionread.c
#include <sys/ioctl.h>
main() {
    printf("%#08x\n", FIONREAD);
}
^D
% cc -o fionread fionread.c
% ./fionread
0x4004667f

ثم قم بتضمينه بشكل ثابت، تاركاً النقل كتمرين لخليفتك.

$FIONREAD = 0x4004667f;         # XXX: opsys dependent
$size = pack("L", 0);
ioctl(FH, $FIONREAD, $size)     or die "Couldn't call ioctl: $!\n";
$size = unpack("L", $size);

يتطلب FIONREAD مقبض ملف متصلاً بتدفق، مما يعني أن المقابس والأنابيب وأجهزة tty تعمل، لكن ليس الملفات.

كيف أفعل "tail -f" في perl؟

جرّب أولاً

seek($gw_fh, 0, 1);

العبارة "seek($gw_fh, 0, 1)" لا تغيّر الموضع الحالي، لكنها تمسح حالة نهاية الملف على المقبض، بحيث يجعل "<$gw_fh>" التالي Perl يحاول مرة أخرى قراءة شيء ما.

إذا لم ينجح ذلك (فهو يعتمد على ميزات تنفيذ stdio الخاص بك)، فأنت بحاجة إلى شيء أشبه بهذا:

for (;;) {
  for ($curpos = tell($gw_fh); <$gw_fh>; $curpos =tell($gw_fh)) {
    # search for some stuff and put it into files
  }
  # sleep for a while
  seek($gw_fh, $curpos, 0);  # seek to where we had been
}

إذا لم ينجح هذا بعد، فابحث في طريقة "clearerr" من IO::Handle، التي تعيد تعيين حالات الخطأ ونهاية الملف على المقبض.

كيف أقوم بـ dup() لمقبض ملف في Perl؟

إذا راجعت "open" في perlfunc، سترى أن عدة طرق لاستدعاء open() يجب أن تؤدي الغرض. على سبيل المثال:

open my $log, '>>', '/foo/logfile';
open STDERR, '>&', $log;

أو حتى باستخدام واصف رقمي حرفي:

my $fd = $ENV{MHCONTEXTFD};
open $mhcontext, "<&=$fd";  # like fdopen(3S)

لاحظ أن "<&STDIN" يصنع نسخة، لكن "<&=STDIN" يصنع اسماً مستعاراً. هذا يعني أنك إذا أغلقت مقبضاً مستعاراً، تصبح جميع الأسماء المستعارة غير قابلة للوصول. هذا غير صحيح مع نسخة.

فحص الأخطاء، كما هو الحال دائماً، تُرك كتمرين للقارئ.

كيف أغلق واصف ملف برقمه؟

إذا كان لديك، لسبب ما، واصف ملف بدلاً من مقبض ملف (ربما استخدمت "POSIX::open")، يمكنك استخدام دالة close() من وحدة POSIX:

use POSIX ();
POSIX::close( $fd );

هذا يجب أن يكون نادراً ما يكون ضرورياً، لأن دالة close() في Perl تُستخدم للأشياء التي فتحها Perl نفسه، حتى لو كانت نسخة من واصف رقمي كما في "MHCONTEXT" أعلاه. لكن إذا كان عليك حقاً، قد تتمكن من فعل هذا:

require './sys/syscall.ph';
my $rc = syscall(SYS_close(), $fd + 0);  # must force numeric
die "can't sysclose $fd: $!" if $rc == -1;

أو، فقط استخدم ميزة fdopen(3S) في open():

{
    open my $fh, "<&=$fd" or die "Cannot reopen fd=$fd: $!";
    close $fh;
}

لماذا لا يمكنني استخدام "C:\temp\foo" في مسارات DOS؟ لماذا لا يعمل `C:\temp\foo.exe`؟

عذراً! لقد وضعت للتو علامة جدولة ونموذج تغذية في اسم الملف هذا! تذكر أنه داخل السلاسل النصية المزدوجة الاقتباس ("like\this")، الشرطة المائلة العكسية هي حرف هروب. القائمة الكاملة لهذه موجودة في "Quote and Quote-like Operators" في perlop. ليس مفاجئاً، ليس لديك ملف يسمى "c:(tab)emp(formfeed)oo" أو "c:(tab)emp(formfeed)oo.exe" على نظام ملفات DOS القديم الخاص بك.

إما أن تضع سلاسلك النصية بين علامات اقتباس مفردة، أو (يفضل) استخدم الشرطات المائلة الأمامية. بما أن جميع إصدارات DOS وWindows منذ شيء مثل MS-DOS 2.0 أو نحو ذلك تعاملت مع "/" و "\" بنفس الطريقة في المسار، قد ترغب أيضاً في استخدام الذي لا يتعارض مع Perl--أو مع صدفة POSIX وANSI C و C++ وawk وTcl وJava أو Python، على سبيل المثال لا الحصر. مسارات POSIX أكثر قابلية للنقل أيضاً.

لماذا لا يحصل glob("*.*") على جميع الملفات؟

لأنه حتى على المنافذ غير اليونكسية، تتبع دالة glob في Perl دلالات glob اليونكسية القياسية. ستحتاج إلى glob("*") للحصول على جميع الملفات (غير المخفية). هذا يجعل glob() قابلاً للنقل حتى للأنظمة القديمة. قد يتضمن منفذك دوال glob احتكارية أيضاً. راجع توثيقه للتفاصيل.

لماذا تسمح لي Perl بحذف الملفات للقراءة فقط؟ لماذا يقوم "-i" بتدمير الملفات المحمية؟ أليس هذا خطأً في Perl؟

هذا موصوف بشكل مفصل ومضنٍ في مقالة file-dir-perms في مجموعة "Far More Than You Ever Wanted To Know" في http://www.cpan.org/misc/olddoc/FMTEYEWTK.tgz .

الملخص التنفيذي: تعلم كيف يعمل نظام الملفات الخاص بك. الأذونات على ملف تحدد ما يمكن أن يحدث للبيانات في ذلك الملف. الأذونات على دليل تحدد ما يمكن أن يحدث لقائمة الملفات في ذلك الدليل. إذا حذفت ملفاً، فأنت تزيل اسمه من الدليل (لذا تعتمد العملية على أذونات الدليل، وليس على الملف). إذا حاولت الكتابة إلى الملف، فإن أذونات الملف تحكم ما إذا كان مسموحاً لك بذلك.

كيف أختار سطراً عشوائياً من ملف؟

بصرف النظر عن تحميل الملف في قاعدة بيانات أو فهرسة الأسطر في الملف مسبقاً، هناك بضعة أشياء يمكنك القيام بها.

إليك خوارزمية أخذ عينات الخزان من كتاب الجمل:

srand;
rand($.) < 1 && ($line = $_) while <>;

هذا له ميزة كبيرة في المساحة على قراءة الملف بأكمله دفعة واحدة. يمكنك العثور على إثبات لهذه الطريقة في The Art of Computer Programming، المجلد 2، القسم 3.4.2، بقلم Donald E. Knuth.

يمكنك استخدام وحدة File::Random التي توفر دالة لتلك الخوارزمية:

use File::Random qw/random_line/;
my $line = random_line($filename);

طريقة أخرى هي استخدام وحدة Tie::File، التي تعامل الملف بأكمله كمصفوفة. ببساطة الوصول إلى عنصر مصفوفة عشوائي.

لماذا أحصل على مسافات غريبة عندما أطبع مصفوفة من الأسطر؟

(ساهم بها brian d foy)

إذا كنت ترى مسافات بين عناصر مصفوفتك عندما تطبع المصفوفة، فمن المحتمل أنك تُدخل المصفوفة في علامات اقتباس مزدوجة:

my @animals = qw(camel llama alpaca vicuna);
print "animals are: @animals\n";

إنها علامات الاقتباس المزدوجة، وليس "print"، التي تفعل هذا. كلما أدخلت مصفوفة في سياق علامات اقتباس مزدوجة، تربط Perl العناصر بمسافات (أو أي شيء في $"، وهو مسافة افتراضياً):

animals are: camel llama alpaca vicuna

هذا يختلف عن طباعة المصفوفة بدون الإدخال:

my @animals = qw(camel llama alpaca vicuna);
print "animals are: ", @animals, "\n";

الآن المخرجات لا تحتوي على المسافات بين العناصر لأن عناصر @animals ببساطة تصبح جزءاً من القائمة إلى "print":

animals are: camelllamaalpacavicuna

قد تلاحظ هذا عندما ينتهي كل عنصر من عناصر @array بسطر جديد. تتوقع طباعة عنصر واحد لكل سطر، لكن لاحظ أن كل سطر بعد الأول مُزاح:

this is a line
 this is another line
 this is the third line

تلك المسافة الإضافية تأتي من إدخال المصفوفة. إذا كنت لا تريد وضع أي شيء بين عناصر مصفوفتك، لا تستخدم المصفوفة بين علامتي اقتباس مزدوجتين. يمكنك إرسالها إلى print بدونها:

print @lines;

كيف أجتاز شجرة دليل؟

(ساهم بها brian d foy)

وحدة File::Find، التي تأتي مع Perl، تقوم بكل العمل الشاق لاجتياز بنية دليل. ما عليك سوى استدعاء الروتين الفرعي "find" مع روتين فرعي للاستدعاء الراجع والأدلة التي تريد اجتيازها:

use File::Find;
find( \&wanted, @directories );
sub wanted {
    # المسار الكامل في $File::Find::name
    # اسم الملف فقط في $_
    ... افعل ما تريد فعله ...
}

وحدة File::Find::Closures، التي يمكنك تنزيلها من CPAN، توفر العديد من الروتينات الفرعية الجاهزة للاستخدام التي يمكنك استخدامها مع File::Find.

وحدة File::Finder، التي يمكنك تنزيلها من CPAN، يمكنها مساعدتك في إنشاء الروتين الفرعي للاستدعاء الراجع باستخدام شيء أقرب إلى صياغة أداة سطر الأوامر "find":

use File::Find;
use File::Finder;
my $deep_dirs = File::Finder->depth->type('d')->ls->exec('rmdir','{}');
find( $deep_dirs->as_options, @places );

وحدة File::Find::Rule، التي يمكنك تنزيلها من CPAN، لها واجهة مشابهة، لكنها تقوم بالاجتياز نيابة عنك أيضًا:

use File::Find::Rule;
my @files = File::Find::Rule->file()
                         ->name( '*.pm' )
                         ->in( @INC );

كيف أحذف شجرة دليل؟

(ساهم بها brian d foy)

إذا كان لديك دليل فارغ، يمكنك استخدام "rmdir" المدمج في Perl. إذا لم يكن الدليل فارغًا (أي يحتوي على ملفات أو أدلة فرعية)، فعليك إما إفراغه بنفسك (عمل كثير) أو استخدام وحدة لمساعدتك.

وحدة File::Path، التي تأتي مع Perl، لديها "remove_tree" التي يمكنها الاعتناء بكل العمل الشاق نيابة عنك:

use File::Path qw(remove_tree);
remove_tree( @directories );

وحدة File::Path لديها أيضًا واجهة قديمة للروتين الفرعي الأقدم "rmtree".
