p_val_status(3)

الحزمة: dnssec-tools

التراخيص: BSD

libval(3) دليل المبرمج libval(3)

الاسم

val_create_context() val_free_context() - إدارة سياق المدقق

val_context_setqflags() - إدارة علامات سياق المدقق

val_resolve_and_check(), val_free_result_chain() - الاستعلام عن نتائج خادم أسماء DNS والتحقق منها

val_istrusted() - التحقق مما إذا كانت قيمة الحالة تتوافق مع إجابة موثوقة

val_isvalidated() - التحقق مما إذا كانت قيمة الحالة تمثل إجابة تتسلسل بشكل تشفيري من مرساة ثقة مهيأة

val_does_not_exist() - التحقق مما إذا كانت قيمة الحالة تمثل أحد أنواع عدم الوجود

p_val_status(), p_ac_status(), p_val_error() - عرض حالة التحقق، حالة سلسلة المصادقة، ومعلومات الخطأ

val_log_add_optarg - التحكم في تفاصيل رسائل السجل وموقع الإخراج

الوصف

تقوم الدالة val_resolve_and_check() بالاستعلام من مجموعة من خوادم الأسماء لـ <domain_name, type, class> والتحقق من صحة الرد وتصديقه. يتضمن التحقق فحص RRSIGs، والتصديق هو التحقق من سلسلة مصادقة من مرساة ثقة مهيأة.

يمكن استخدام المعامل flags للتحكم في نتائج التصديق. القيم التالية، التي يمكن دمجها معًا، معرفة حاليًا لهذا الحقل:

VAL_QUERY_DONT_VALIDATE
هذه العلامة تجعل المدقق يعطل التصديق لهذا الاستعلام.
VAL_QUERY_IGNORE_SKEW
هذه العلامة تجعل المدقق يعطل فحص أوقات بدء وانتهاء التوقيعات على RRSIGs.
VAL_QUERY_AC_DETAIL
هذه العلامة تجعل المدقق ينسخ تفاصيل سلسلة المصادقة إلى العضو val_rc_answer ضمن بنية val_result_chain التي تم إرجاعها.
VAL_QUERY_ASYNC
هذه العلامة تمكن حل الاستعلام غير المتزامن لهذا البحث.
VAL_QUERY_NO_DLV
هذه العلامة تجعل المدقق يعطل معالجة DLV لهذا الاستعلام. هذا متاح فقط إذا تم تجميع مكتبة libval(3) مع دعم DLV.
VAL_QUERY_NO_EDNS0_FALLBACK
في الاستعلام عن خوادم أسماء مختلفة، تحاول libsres(3) أيضًا أحجام EDNS0 متعددة، وتنتهي باستعلام تم فيه تعطيل EDNS0 (أي، لم يتم تعيين بت CD). هذه العلامة تجعل libval يعطل الرجوع إلى EDNS0 للاستعلام.
VAL_QUERY_ITERATE
هذه العلامة تجبر libval على إجراء بحث تكراري للاستعلام عن طريق الاستعلام من خوادم أسماء مختلفة في هرمية التفويض، بدلاً من طلب هذه المعلومات من أي خادم أسماء ذاكرة مؤقتة قد يتم تكوينه في dnsval.conf.
VAL_QUERY_SKIP_RESOLVER
هذه العلامة تجبر libval على النظر فقط في ذاكرتها المؤقتة أثناء محاولة حل اسم.
VAL_QUERY_SKIP_CACHE
هناك مستويان من التخزين المؤقت يحدثان داخل libval: على مستوى التأكيد وعلى مستوى الإجابة. هذه العلامة تجبر libval على تجاهل البيانات في كلتا الذاكرتين المؤقتتين أثناء محاولة حل اسم.
VAL_QUERY_SKIP_ANS_CACHE
هناك مستويان من التخزين المؤقت يحدثان داخل libval: على مستوى التأكيد وعلى مستوى الإجابة. هذه العلامة تجبر libval على تجاهل البيانات في ذاكرة التخزين المؤقت للإجابة أثناء محاولة حل اسم. إذا كان هناك بالفعل تأكيد للاسم والفئة والنوع المعطيين، يتم إعادة استخدام هذا التأكيد حتى انتهاء صلاحيته. بمجرد انتهاء صلاحيته، يتم البحث عن الاسم عبر استعلام حتى لو كان سجل أحدث (تم جلبه بواسطة تأكيد آخر في نفس السياق أو سياق مختلف) متاحًا في ذاكرة التخزين المؤقت لإجابته.

المعلمة الأولى لـ val_resolve_and_check() هي سياق المدقق. يمكن للتطبيقات إنشاء سياق مدقق جديد باستخدام الدالة val_create_context(). تقوم هذه الدالة بتحليل ملفات تكوين المستحل والمدقق وتنشئ مؤشر newcontext لهذه المعلومات المحللة. تشمل المعلومات المخزنة كجزء من سياق المدقق سياسة التصديق وسياسة المستحل.

يتم قراءة سياسات المدقق والمستحل افتراضيًا من الملفات /etc/dnsval.conf و /etc/resolv.conf. يوفر /etc/root.hints معلومات التمهيد للمدقق عندما يعمل كمستحل كامل (انظر dnsval.conf(3)). قد تختلف هذه الافتراضيات إذا تم تحديد أي قيمة أخرى في وقت تكوين المكتبة. إذا لم يتم العثور على ملف تكوين المستحل الافتراضي في الموقع المحدد، ستحاول libval أيضًا الرجوع إلى /etc/resolv.conf كملاذ أخير.

قد تقوم التطبيقات أيضًا بإنشاء سياق مدقق بسياسة مخصصة باستخدام الدالة val_create_context_ex().

يشير المعامل opt في val_create_context_ex() إلى البنية التالية:

typedef struct val_context_opt {
    unsigned int vc_qflags;
    unsigned int vc_polflags;
    char *vc_valpol;
    char *vc_nslist;
    char *vc_val_conf;
    char *vc_res_conf;
    char *vc_root_conf;
    val_global_opt_t *gopt, 
} val_context_opt_t;

تحدد vc_qflags علامات الاستعلام الافتراضية للاستعلامات المرتبطة بالسياق. هذا الحقل مطابق للمعامل flags في الدالة val_resolve_and_check().

يمكن استخدام الحقول vc_val_conf و vc_res_conf و vc_root_conf لتحديد ملفات تكوين بديلة بدلاً من الملفات الافتراضية المستخدمة لمعلومات تكوين المدقق والمستحل وجذور التلميحات.

يمكن استخدام حقل vc_valpol لتوفير "مقتطف" تكوين مدقق مخصص للمدقق. يقوم المدقق بتحليل هذه المعلومات وتطبيقها على تكوين المدقق الافتراضي إما كتوسيع أو كإلغاء، كما هو محدد في حقل vc_polflags. وبالمثل، يمكن استخدام حقل vc_nslist لتوفير قائمة مخصصة بخوادم الأسماء التكرارية لإرسال الاستعلامات إليها، بالإضافة إلى (أو بدلاً من) قائمة خوادم الأسماء المحددة في ملف resolv.conf. يجب تحديد قائمة خوادم الأسماء في vc_res_conf كقائمة مفصولة بمسافات بيضاء من عناوين IP أو IPv6.

يمكن إنشاء تعيين مخصص بين منطقة واسم خادم باستخدام الدالة val_context_store_ns_for_zone().

يمكن تكوين vc_polflags بالقيم التالية:

CTX_DYN_POL_VAL_OVR
عند تعيين هذه العلامة، يتم استخدام تكوين المدقق المحدد فقط في حقل vc_valpol لتكوين المدقق. يتم تجاهل الخيارات المحددة في ملف dnsval.conf.
CTX_DYN_POL_RES_OVR
عند تعيين هذه العلامة، يتم استخدام تكوين المستحل المحدد في حقل vc_res_conf لتكوين المستحل. يتم تجاهل الخيارات المحددة في ملف resolv.conf.

تساعد الدالة val_context_setqflags() في تعيين علامات الاستعلام التي تم تحديدها في vc_qflags في بنية val_context_opt. يمكن استدعاء الدالة val_context_setqflags() في أي وقت بعد إنشاء سياق المدقق.

يمكن استخدام الدالة val_free_context() لتحرير الذاكرة التي تم تخصيصها لـ context.

ترجع الدالة val_resolve_and_check() بنية val_result_chain. يحتوي هذا الهيكل على معلومات حول الاستعلام والإجابة، بما في ذلك، إذا تم تمكين تفاصيل سلسلة المصادقة، سلسلة المصادقة التي تم تحليلها.

تحتوي بنية val_result_chain على الحقول التالية:

val_rc_domain
اسم النطاق الذي تم الاستعلام عنه.
val_rc_class
فئة DNS (مثل IN).
val_rc_type
نوع سجل DNS (مثل A، MX، إلخ).
val_rc_status
قيمة حالة التحقق (انظر val_status_t).
val_rc_auth_chain_status
قيمة حالة سلسلة المصادقة (انظر val_astatus_t).
val_rc_answer
قائمة مؤشرات إلى هياكل val_answer التي تحتوي على السجلات الفعلية المستلمة.
val_rc_why
مؤشر إلى سلسلة توضح سبب الوصول إلى نتيجة التحقق.
val_rc_why_len
طول سلسلة val_rc_why.

يجب تحرير الذاكرة المخصصة لهيكل val_result_chain (بما في ذلك أي سلاسل فرعية أو هياكل val_answer) باستخدام الدالة val_free_result_chain().

تساعد الدوال p_val_status() و p_ac_status() و p_val_error() في تحويل قيم حالة التحقق وسلسلة المصادقة والأخطاء إلى سلاسل وصفية سهلة القراءة.

تساعد الدوال val_istrusted() و val_isvalidated() و val_does_not_exist() في فحص قيم حالة التحقق.

تتيح الدالة val_log_add_optarg() تعديل سلوك تسجيل الأخطاء والإعلامات الخاصة بالمكتبة. يمكن تمرير وسائط سطر الأوامر القياسية لـ syslogd (مثل -v، -d) في الوسيط args. إذا تم تعيين use_stderr إلى قيمة غير صفرية، فسيتم إرسال رسائل السجل إلى الإخراج القياسي.

تساعد الدالة val_context_store_ns_for_zone() في تحديد خادم أسماء معين لمنطقة معينة. إذا تم تعيين recursive إلى قيمة غير صفرية، فسيتم استخدام خادم الأسماء هذا للاستعلامات التكرارية.

قيم الإرجاع

تُرجع معظم الدوال قيمة 0 عند النجاح، وقيمة سالبة عند الفشل. تُرجع الدوال التي تبدأ بـ p_ مؤشرًا إلى سلسلة نصية عند النجاح، ومؤشرًا فارغًا عند الفشل.

يشير الحقل gopt إلى البنية التالية:

typedef struct val_global_opt {
    int local_is_trusted;
    long edns0_size;
    int env_policy;
    int app_policy;
    char *log_target;
    int closest_ta_only;
    int rec_fallback;
    long max_refresh;
    int proto;
} val_global_opt_t;

تعيين قيمة 1 للحقل local_is_trusted يعادل تحديد الخيار trust-oob-answers في ملف dnsval.conf إلى yes. وبالمثل، فإن تعيين الأعضاء closest_ta_only و rec_fallback إلى 1 يعادل تحديد الخيارين closest-ta-only و rec-fallback إلى yes في ملف dnsval.conf. القيمة 0 تعادل الإعداد no لهذه الخيارات.

تعيين العضو edns0_size إلى قيمة معينة له نفس تأثير تعيين الخيار edns0-size في ملف dnsval.conf.

تعيين العضو max_refresh إلى قيمة معينة له نفس تأثير تعيين الخيار max-refresh في ملف dnsval.conf.

تعيين العضو proto إلى قيمة معينة له نفس تأثير تعيين الخيار proto في ملف dnsval.conf.

يمكن تعيين env_policy و app_policy إلى أحد القيم التالية: VAL_POL_GOPT_DISABLE، VAL_POL_GOPT_ENABLE، أو VAL_POL_GOPT_OVERRIDE. تتوافق هذه القيم مباشرة مع الخيارات disable و enable و override لإعدادات env-policy و app-policy في ملف dnsval.conf.

تُعامل القيم -1 للحقول المذكورة أعلاه كشروط "تجاهل" بحيث لا يقوم المدقق بتضمين خيارات عامة يتم توفيرها ديناميكيًا بقيمة -1 عند إنشاء سياقه. هذا يسمح للتطبيق بتجاوز مجموعة فرعية من الخيارات العامة مع استخدام الخيارات العامة المقدمة في ملف dnsval.conf افتراضيًا.

يمكّن الحقل log_target التطبيق من توفير أهداف تسجيل بالإضافة إلى تلك التي تم تكوينها في ملف التكوين.

انظر dnsval.conf(3) لمزيد من التفاصيل حول تحديد سياسة المدقق.

يمكن تعيين أعلام الاستعلام الافتراضية وإلغاء تعيينها لسياق معين باستخدام val_context_setqflags(). هذا يسمح للتطبيق بتغيير معالجة مدقق DNSSEC، مع الاستمرار في الحصول على معظم التكوين الافتراضي الأكثر دقة المحدد في ملف التكوين الخاص به. يمكن تعيين المعلمة action إلى أحد القيم التالية.

VAL_CTX_FLAG_SET
يسبب هذا الخيار للمدقق تعيين العلم المحدد كأحد أعلام الاستعلام الافتراضية.
VAL_CTX_FLAG_RESET
يسبب هذا الخيار للمدقق إعادة تعيين العلم المحدد إذا تم تعيينه كأحد أعلام الاستعلام الافتراضية للسياق.

الإجابات التي يتم إرجاعها بواسطة val_resolve_and_check() متاحة في القائمة المرتبطة *results. تتوافق كل إجابة مع RRset مميز؛ الأجزاء المتعددة داخل RRset هي جزء من نفس الإجابة. من الممكن وجود إجابات متعددة عندما يكون type هو ns_t_any أو ns_t_rrsig.

تشير العناصر الفردية في *results إلى قوائم مرتبطة val_authentication_chain. تحتوي عناصر سلسلة المصادقة في val_authentication_chain على RRsets الفعلية التي تم إرجاعها بواسطة خادم الأسماء استجابةً للاستعلام.

يمكن تحويل قيم نتيجة التحقق التي يتم إرجاعها في val_result_chain إلى تنسيق ASCII باستخدام p_val_status(). يمكن تحويل حالات سلسلة المصادقة التي يتم إرجاعها في كل عنصر من عناصر القائمة المرتبطة val_authentication_chain إلى تنسيق ASCII باستخدام وظيفتي p_ac_status().

بينما قد تقوم بعض التطبيقات مثل أدوات استكشاف أخطاء DNSSEC وإصلاحها وأدوات فحص الحزم بالنظر إلى عناصر سلسلة المصادقة الفردية لتحديد الأسباب الفعلية لخطأ التحقق، فإن معظم التطبيقات ستكون مهتمة فقط برمز خطأ واحد لتحديد أصالة البيانات.

val_isvalidated() تحدد ما إذا كانت حالة نتيجة التحقق المحددة تتوافق مع إجابة تم التحقق منها والتأكد منها بشكل تشفيري باستخدام مرساة ثقة مهيأة محليًا.

val_istrusted() تحدد ما إذا كانت حالة مدقق معينة موثوقة. قد تكون الإجابة موثوقة محليًا دون أن يتم التحقق منها.

val_does_not_exist() تحدد ما إذا كانت حالة مدقق معينة تتوافق مع أحد أنواع عدم الوجود.

تقوم مكتبة libval بتخصيص الذاكرة داخليًا لـ *results ويجب تحريرها بواسطة التطبيق المستدعي باستخدام واجهة free_result_chain().

هياكل البيانات

struct val_result_chain
struct val_result_chain
{
    val_status_t                     val_rc_status;
    char                            *val_rc_alias;
    struct val_rrset_rec            *val_rc_rrset;
    struct val_authentication_chain *val_rc_answer;
    int                              val_rc_proof_count;
    struct val_authentication_chain *val_rc_proofs[MAX_PROOFS];
    struct val_result_chain         *val_rc_next;
};
val_rc_answer
سلسلة المصادقة لـ RRset معين.
val_rc_next
مؤشر إلى RRset التالي في مجموعة الإجابات التي تم إرجاعها لاستعلام.
val_rc_proofs
مؤشر إلى سلاسل المصادقة لأي دليل على عدم الوجود تم إرجاعه للاستعلام.
val_rc_proof_count
عدد عناصر الدليل المخزنة في val_rc_proofs. لا يمكن أن يتجاوز العدد MAX_PROOFS.
val_rc_alias
بالنسبة لعنصر val_result_chain الذي يشير إلى اسم مستعار، يحتوي هذا الحقل على القيمة الهدف.
val_rc_rrset
بالنسبة لعنصر val_result_chain الذي يحتوي على حقل val_rc_answer صالح (ليس NULL)، يشير الحقل val_rc_rrset إلى أعلى عنصر val_rrset_rec في سلسلة المصادقة val_rc_answer.
val_rc_status
حالة التحقق لـ RRset معين. يمكن أن تكون إحدى القيم التالية:
VAL_SUCCESS
تم استلام الإجابة والتحقق منها بنجاح.
VAL_NONEXISTENT_NAME
لم يكن الاسم موجودًا وتم إرجاع دليل صالح على عدم الوجود يؤكد الاسم المفقود (نطاق NSEC أو NSEC3). تم التحقق أيضًا من مكونات الدليل بشكل فردي.
VAL_NONEXISTENT_TYPE
لم يكن النوع موجودًا للاسم وتم إرجاع دليل صالح على عدم الوجود يؤكد الاسم المفقود. تم التحقق أيضًا من مكونات الدليل بشكل فردي.
VAL_NONEXISTENT_NAME_NOCHAIN
لم يكن الاسم موجودًا وتم إرجاع دليل صالح على عدم الوجود يؤكد الاسم المفقود. تم أيضًا تحديد أن مكونات الدليل موثوقة، ولكن لم يتم التحقق منها بشكل فردي.
VAL_NONEXISTENT_TYPE_NOCHAIN
لم يكن النوع موجودًا للاسم وتم إرجاع دليل صالح على عدم الوجود يؤكد الاسم المفقود (نطاق NSEC أو NSEC3). تم أيضًا تحديد أن مكونات الدليل موثوقة، ولكن لم يتم التحقق منها بشكل فردي.
VAL_PINSECURE
كان السجل أو أحد أسلاف السجل في سلسلة المصادقة باتجاه مرساة الثقة معروفًا بأنه غير آمن بشكل قابل للإثبات.
VAL_PINSECURE_UNTRUSTED
كان السجل أو أحد أسلاف السجل في سلسلة المصادقة باتجاه مرساة الثقة معروفًا بأنه غير آمن بشكل قابل للإثبات. ولكن تم تكوين حالة عدم الأمان القابلة للإثبات على أنها غير موثوقة.
VAL_BARE_RRSIG
لا يمكن التحقق من DNSSEC، كان الاستعلام عن RRSIG.
VAL_IGNORE_VALIDATION
تم تكوين السياسة المحلية لتجاهل التحقق من المنطقة التي تم استلام البيانات منها.
VAL_UNTRUSTED_ZONE
تم تكوين السياسة المحلية لرفض أي بيانات تم استلامها من المنطقة المحددة.
VAL_OOB_ANSWER
تم الحصول على الإجابة باستخدام طريقة خارج النطاق (Out Of Band)، مثل ملف تكوين محلي.
VAL_BOGUS
لم يكن من الممكن التحقق من الاستجابة بسبب فشل التحقق من التوقيع أو عدم القدرة على التحقق من الأدلة في سلسلة المصادقة.
VAL_DNS_ERROR
تم مواجهة خطأ ما أثناء معالجة DNS.
VAL_INDETERMINATE
لم يكن من الممكن التحقق من الاستجابة بسبب عدم وجود بيانات DNSSEC الوصفية.
p_val_status(3) — dnssec-tools

NAME

p_val_status, p_val_error, p_val_log_level, p_val_log_status — validator library status functions

SYNOPSIS

#include <dns/validator.h>

int
p_val_status(void);

const char *
p_val_error(int status);

void
p_val_log_level(int level);

int
p_val_log_status(void);

DESCRIPTION

These functions provide access to the status of the validator library and the error messages associated with various return codes.

p_val_status returns the current status code of the validator library. The status code is updated by the various functions within the library.

p_val_error takes a status code as input and returns a human-readable string describing the error. The strings returned are static and should not be modified.

p_val_log_level sets the logging level for the validator library. The level can be set to one of the following values:

0
No logging.
1
Error messages only.
2
Error messages and authentication chains details.
7
Debug level information.

p_val_log_status returns the current logging level.

DATA STRUCTURES

There are no data structures associated with these functions.

LOGGING

The validator library can be configured to log messages at various levels using the p_val_log_level function. The default logging level is 1 (Error messages only).

Logging levels:

0: No logging
1: Error messages only
2: Gives details on authentication chains
7: Gives debug level information

RETURN VALUES

Return values for various functions are given below. These values can be displayed in ASCII format using the p_val_error() function.

VAL_NO_ERROR
No error was encountered.
VAL_NOT_IMPLEMENTED
Functionality not yet implemented.
VAL_RESOURCE_UNAVAILABLE
Some resource (crypto possibly) was unavailable. Currently not implemented.
VAL_BAD_ARGUMENT
Bad arguments passed as parameters.
VAL_INTERNAL_ERROR
Encountered some internal error.
VAL_NO_PERMISSION
No permission to perform operation. Currently not implemented.
VAL_CONF_PARSE_ERROR
Error in parsing some configuration file.
VAL_CONF_NOT_FOUND
A configuration file was not available.
VAL_NO_POLICY
The policy identifier being referenced was invalid.

FILES

The validator library reads configuration information from two files, resolv.conf and dnsval.conf.

See dnsval.conf(5) for a description of the syntax for these files.
