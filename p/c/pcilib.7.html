الاسم

pcilib - مكتبة للوصول إلى أجهزة PCI

الوصف

مكتبة PCI (المعروفة أيضًا باسم pcilib و libpci) هي مكتبة محمولة للوصول إلى أجهزة PCI ومساحة التكوين الخاصة بها.

طرق الوصول

تدعم المكتبة مجموعة متنوعة من الطرق للوصول إلى مساحة التكوين على أنظمة تشغيل مختلفة. بشكل افتراضي، يتم استخدام أول طريقة مطابقة في هذه القائمة، ولكن يمكنك تحديد تجاوز القرار (راجع مفتاح -A الخاص بـ lspci).

linux-sysfs
نظام الملفات /sys في Linux 2.6 والإصدارات الأحدث. رأس مساحة التكوين القياسي متاح لجميع المستخدمين، والباقي للجذر فقط. يدعم مساحة التكوين الموسعة، و نطاقات PCI، و VPD (من Linux 2.6.26)، والفتحات المادية (أيضًا منذ Linux 2.6.26) ومعلومات حول برامج تشغيل النواة المرفقة.
linux-proc
واجهة /proc/bus/pci التي تدعمها Linux 2.1 والإصدارات الأحدث. رأس مساحة التكوين القياسي متاح لجميع المستخدمين، والباقي للجذر فقط.
intel-conf1
وصول مباشر إلى الأجهزة عبر آلية تكوين Intel 1. متاح على i386 والمتوافق معها على Linux، Solaris/x86، GNU Hurd، Windows، BeOS و Haiku. يتطلب صلاحيات الجذر.
intel-conf2
وصول مباشر إلى الأجهزة عبر آلية تكوين Intel 2. متاح على i386 والمتوافق معها على Linux، Solaris/x86، GNU Hurd، Windows، BeOS و Haiku. يتطلب صلاحيات الجذر. تحذير: هذه الطريقة قادرة على الوصول إلى أول 16 جهازًا فقط في أي ناقل ويبدو أنها غير موثوقة للغاية في العديد من الحالات.
mmio-conf1
وصول مباشر إلى الأجهزة عبر آلية تكوين Intel 1 عبر الإدخال/الإخراج المعين بالذاكرة (memory-mapped I/O). يستخدم غالبًا على الأنظمة غير i386. يتطلب صلاحيات الجذر. تحذير: تحتاج هذه الطريقة إلى تكوين مناسب عبر المعلمة mmio-conf1.addrs.
mmio-conf1-ext
وصول مباشر إلى الأجهزة عبر آلية تكوين PCIe الموسعة Intel 1 عبر الإدخال/الإخراج المعين بالذاكرة. يستخدم غالبًا على الأنظمة غير i386. يتطلب صلاحيات الجذر. تحذير: تحتاج هذه الطريقة إلى تكوين مناسب عبر المعلمة mmio-conf1-ext.addrs.
ecam
وصول مباشر إلى الأجهزة عبر آلية الوصول إلى التكوين المحسن (ECAM) لـ PCIe. متاح على جميع الأجهزة المتوافقة مع PCIe. يتطلب صلاحيات الجذر والوصول إلى الذاكرة المادية (على أنظمة Linux، تم تعطيل خيار CONFIG_STRICT_DEVMEM). على الأنظمة المتوافقة مع ACPI، يتم قراءة تعيين ECAM من جدول MCFG المحدد بواسطة المعلمة ecam.acpimcfg. على الأنظمة المتوافقة مع EFI، يمكن تحديد موقع جدول ACPI MCFG في الذاكرة المادية عبر جدول نظام EFI المحدد بواسطة المعلمة ecam.efisystab. على أنظمة FreeBSD/NetBSD، يمكن تحديد العنوان المادي لجدول ACPI MCFG بواسطة واجهة kenv أو sysctl عندما لا يتم تعطيل المعلمة ecam.bsd. على أنظمة x86 BIOS المتوافقة، يمكن تحديد موقع جدول ACPI MCFG في الذاكرة المادية عن طريق مسح ذاكرة x86 BIOS عندما لا يتم تعطيل المعلمة ecam.x86bios. بدلاً من ذلك، يمكن تحديد تعيينات ECAM بواسطة المعلمة ecam.addrs والتي لها الأسبقية على جدول ACPI MCFG. هذا الخيار مطلوب على الأنظمة التي لا تحتوي على ACPI وكذلك على الأنظمة التي لا تحتوي على EFI أو x86 BIOS.
fbsd-device
جهاز /dev/pci على FreeBSD. يتطلب صلاحيات الجذر.
aix-device
طريقة الوصول المستخدمة على AIX. يتطلب صلاحيات الجذر.
nbsd-libpci
جهاز /dev/pci0 على NetBSD الذي يتم الوصول إليه باستخدام مكتبة libpci المحلية.
obsd-device
جهاز /dev/pci على OpenBSD. يتطلب صلاحيات الجذر.
dump
قراءة محتويات مسجلات التكوين من ملف محدد في المعلمة dump.name. يتوافق التنسيق مع مخرجات lspci -x.
darwin
طريقة الوصول المستخدمة على Mac OS X / Darwin. يجب تشغيلها كجذر ويجب أن يكون النظام قد تم تشغيله مع debug=0x144.
win32-cfgmgr32
قائمة الأجهزة على أنظمة Windows باستخدام مدير تكوين Windows عبر مكتبة النظام cfgmgr32.dll. لا تتطلب هذه الطريقة أي حقوق مسؤول أو امتيازات خاصة. يوفر مدير التكوين معلومات أساسية فقط حول الأجهزة والموارد المعينة وهيكل شجرة الجهاز. لا يوجد وصول إلى مساحة تكوين PCI ولكن libpci تحاول إما استخدام طريقة وصول أخرى للوصول إلى مساحة التكوين أو توفر محاكاة للقراءة فقط قائمة على المعلومات من مدير التكوين. يمكن اختيار طريقة وصول أخرى بواسطة المعلمة win32.cfgmethod. افتراضيًا، يتم تحديد أول طريقة عمل (إن وجدت). بدءًا من Windows 8 (NT 6.2)، لا يمكن استرداد الموارد من تطبيق 32 بت أو مكتبة على نظام 64 بت.
win32-sysdbg
الوصول إلى مساحة تكوين PCI عبر واجهة NT SysDbg على أنظمة Windows. يحتاج العملية إلى امتياز تصحيح الأخطاء (Debug privilege)، والذي يمتلكه المسؤولون المحليون افتراضيًا. غير متاح على الأنظمة 64 بت ولا على الأنظمة 32 بت الحديثة. يمكن الوصول فقط إلى الأجهزة من النطاق الأول وفقط أول 256 بايت من مساحة تكوين PCI يمكن الوصول إليها عبر هذه الطريقة.
win32-kldbg
الوصول إلى مساحة تكوين PCI عبر برنامج تشغيل تصحيح الأخطاء المحلي للنواة kldbgdrv.sys. هذا البرنامج التشغيل ليس جزءًا من نظام Windows ولكنه جزء من أداة Microsoft WinDbg. يلزم تثبيت kldbgdrv.sys في الدليل system32 أو وجود ملف windbg.exe أو kd.exe في PATH. يحتوي ملف windbg.exe أو kd.exe على برنامج تشغيل kldbgdrv.sys مضمن يمكن لـ libpci فك ضغطه وتسجيله تلقائيًا. نظرًا لاستخدام البرنامج التشغيل المضمن، يلزم أن يتطابق بنية ملف windbg.exe أو kd.exe مع بنية النظام، وليس بنية تطبيق libpci. لذلك، لتشغيل تطبيق i386 libpci على نظام AMD64، يلزم وجود إصدار AMD64 من برنامج تشغيل kldbgdrv.sys في الدليل system32 الأصلي أو إصدار AMD64 من ملف windbg.exe أو kd.exe في PATH. لن تعمل إصدارات i386 من هذه الملفات. تدعم طريقة الوصول win32-kldbg المترجمة للتطبيقات 32 بت كلاً من أنظمة التشغيل المضيفة 32 بت و 64 بت، وبالتالي يمكن لتطبيق i386 libpci مع طريقة win32-kldbg الوصول إلى مساحة تكوين PCI أيضًا على نظام مضيف AMD64. يحتوي برنامج تشغيل kldbgdrv.sys على بعض القيود. تحتاج العملية إلى امتياز تصحيح الأخطاء ويجب تشغيل نظام Windows مع خيار تصحيح الأخطاء. يمكن تمكين خيار تصحيح الأخطاء عن طريق استدعاء (يصبح ساري المفعول بعد التمهيد التالي): bcdedit /debug on

NAME

pcilib — PCI library

DESCRIPTION

This library provides access to the PCI bus devices for user-space applications. It hides the details of accessing the configuration space of PCI devices and provides a generic interface to read and write information about them.

The library automatically detects the underlying hardware platform and chooses the most appropriate access method. If you want to override the default behavior, you can specify the desired access method using parameters.

Default access method

The library tries to use the following access methods in order:

  • /dev/pci (Linux kernel driver)
  • /dev/mem (memory access)
  • Intel Configuration Mechanism 1 (I/O ports 0xcf8 and 0xcf c)
  • sysfs (Linux sysfs filesystem)
  • efi (EFI memory map)

Supported access methods

The library supports a wide range of access methods for different operating systems and architectures:

linux-kernel
Access through the /dev/pci device provided by the Linux kernel PCI driver.
sysfs
Access through the sysfs filesystem (available on Linux 2.6+). This method uses files in /sys/bus/pci/ to discover devices and their properties. It requires the sysfs filesystem to be mounted.
procfs
Access through the /proc/bus/pci filesystem (available on Linux 2.4 and earlier). This method requires the procfs filesystem to be mounted.
x86-ebda
Access through the EBDA (Extended BIOS Data Area) on x86 systems. This method is used for older systems that do not have a PCI BIOS.
x86-bios
Access through the PCI BIOS services on x86 systems. This is the standard method for accessing PCI devices on older x86 hardware.
x86-msi
Access through the PCI MSI (Message Signaled Interrupts) interface on x86 systems. This method is used for newer systems that support MSI.
intel-conf1
Access using the Intel Configuration Mechanism 1 (I/O ports 0xcf8 and 0xcfc). This is the standard method for accessing PCI configuration space on most x86 systems.
intel-conf1-mmio
Access using memory-mapped I/O ports for Intel Configuration Mechanism 1. This method is used when the configuration space is mapped into memory.
intel-conf1-ext
Access using the Extended Intel Configuration Mechanism 1 for PCIe systems.
intel-conf1-ext-mmio
Access using memory-mapped I/O ports for Extended Intel Configuration Mechanism 1.
amd-conf
Access using the AMD Configuration Mechanism.
arm-platform
Access through the platform-specific mechanisms on ARM systems. This may involve accessing device tree information or specific hardware registers.
efi-pci
Access through the EFI (Extensible Firmware Interface) PCI services. This method is available on systems that boot using UEFI.
freebsd-kernel
Access through the /dev/pci device provided by the FreeBSD kernel PCI driver.
netbsd-kernel
Access through the /dev/pci device provided by the NetBSD kernel PCI driver.
openbsd-kernel
Access through the /dev/pci device provided by the OpenBSD kernel PCI driver.
windows-mmio
Access through memory-mapped I/O on Windows systems. This requires proper driver support.
windows-nt
Access through the Windows NT Native API. This method may require administrator privileges.
windows-cfgmgr32
Access using the cfgmgr32 library on Windows systems. This provides read-only access to configuration information.
rt-thread-smart
The /proc/pci filesystem provided by RT-Thread Smart OS. This method requires PCI support (with the procfs feature enabled) to be available in the driver subsystem, and the DFS v2-based procfs must be mounted in a rootfs-enabled environment. It provides access to the standard PCI configuration space, with limited information available.
aos-expansion
Access method used on PowerPC Amiga running OS4+. Access is made through Expansion.library. It offers read and write access to configuration space.

PARAMETERS

The library is controlled by several parameters. They should have sensible default values, but in case you want to do something unusual (or even something weird), you can override them (see the -O switch of lspci).

Parameters of specific access methods

dump.name
Name of the bus dump file to read from.
fbsd.path
Path to the FreeBSD PCI device.
nbsd.path
Path to the NetBSD PCI device.
obsd.path
Path to the OpenBSD PCI device.
proc.path
Path to the procfs bus tree.
sysfs.path
Path to the sysfs device tree.
rt-thread-smart-dm.path
Path to the rt-thread smart DM procfs device tree.
devmem.path
Path to the /dev/mem device or path to the \Device\PhysicalMemory NT section or name of the platform specific physical address access method. Generally on POSIX systems it is path to memory device and on Windows systems it is path to memory NT section. Additionally on 32-bit Windows systems are recognized also platform methods: vxdcall, w32skrnl. On DOS/DJGPP systems are recognized only platform methods: auto, devmap, physmap. DJGPP's devmap method uses DPMI 1.0 functions 0508H (Map Device in Memory Block) and 0509H (Map Conventional Memory in Memory Block). DJGPP's physmap method uses DPMI 0.9 function 0800H (Physical Address Mapping). DJGPP's auto parameter automatically chooses one of the mentioned method supported by the system.
mmio-conf1.addrs
Physical addresses of memory-mapped I/O ports for Intel configuration mechanism 1. CF8 (address) and CFC (data) I/O port addresses are separated by slash and multiple addresses for different PCI domains are separated by commas. Format: 0xaddr1/0xdata1,0xaddr2/0xdata2,...
mmio-conf1-ext.addrs
Physical addresses of memory-mapped I/O ports for Extended PCIe Intel configuration mechanism 1. It has same format as mmio-conf1.addrs parameter.
ecam.addrs
Physical addresses of PCIe ECAM mappings. Each mapping must contains first PCI bus number and physical address where mapping starts. And then it may contain the length of the mapping, the last PCI bus number and PCI domain number. When the last PCI bus number is not provided then it is calculated from the length of the mapping or it is assumed 0xff. When length of the mapping is provided then it is calculated from the last PCI bus number. And when PCI domain is not provided then 0x0 is assumed. All numbers must be supplied in hexadecimal form (leading prefix 0x is not required). Multiple mappings are separated by commas. Format: [domain:]start_bus[-end_bus]:start_addr[+length],...
ecam.acpimcfg
Path to the ACPI MCFG table. Processed by the glob(3) function, so it may contain wildcards (*).
ecam.efisystab
Path to the EFI system table.
ecam.bsd
When not set to 0 then use BSD kenv or sysctl to find ACPI MCFG table. Default value is 1 on BSD systems.
ecam.x86bios
When not set to 0 then scan x86 BIOS memory for ACPI MCFG table. Default value is 1 on x86 systems.
win32.cfgmethod
Config space access method to use with win32-cfgmgr32 on Windows systems. Value auto or an empty string selects the first access method which supports access to the config space on Windows. Value win32-cfgmgr32 or none only builds a read-only virtual emulated config space with information from the Configuration Manager.

Parameters for resolving of ID's via DNS

net.domain
DNS domain containing the ID database.
net.cache_name
Name of the file used for caching of resolved ID's. An initial ~/ is expanded to the user's home directory.

Parameters for resolving of ID's via UDEV's HWDB

hwdb.disable
Disable use of HWDB if set to a non-zero value.
