الاسم

pcilmr - هوامش وصلات PCIe

ملخص

pcilmr [--margin] [<خيارات مشتركة>] <منفذ الوصلة> [<خيارات الوصلة>] [<منفذ الوصلة> [<خيارات الوصلة>] ...]
pcilmr --full [<خيارات مشتركة>]
pcilmr --scan

التكوين

قائمة المتطلبات للوصلات وإعدادات النظام لتشغيل اختبار الهامش.

إعدادات BIOS (تعتمد على النظام، ذات صلة بلوحات الخادم الأساسية بوحدات معالجة مركزية Xeon):

•
إيقاف ميزة دلو تسرب PCIe، إعادة الموازنة، وتدهور الوصلة؛
•
ضبط حدود الخطأ على 0؛
•
Intel VMD لوحدات NVMe SSD - في حالة السلوك الغريب لـ pcilmr، حاول تشغيله مع إيقاف تشغيل VMD.

متطلبات الجهاز (الوصلة):

تم التكوين بواسطة المستخدم قبل تشغيل الأداة المساعدة، الأداة المساعدة لا تغيرها:
•
يجب أن يكون معدل بيانات الوصلة الحالي 16.0 GT/s أو أعلى (تدعم الأداة المساعدة حاليًا وصلات 16 GT/s و 32 GT/s)؛
•
يجب أن يكون مكون الوصلة السفلي في حالة إدارة الطاقة D0.
تم التكوين بواسطة الأداة المساعدة أثناء التشغيل، تعيد الأداة المساعدة ضبطها إلى حالتها الأصلية بعد استلام النتائج:
•
يجب تعطيل ASPM في كل من المنفذ السفلي والمنفذ العلوي؛
•
يجب تعيين بت تعطيل سرعة الأجهزة المستقلة لوصلة التحكم 2 في كل من المنفذ السفلي والمنفذ العلوي؛
•
يجب تعيين بت تعطيل عرض الأجهزة المستقلة لوصلة التحكم في كل من المنفذ السفلي والمنفذ العلوي.

الوصف

تسمح الأداة المساعدة pcilmr بالاستفادة من قدرة هوامش مسارات PCIe عند المستقبل (Lane Margining at the Receiver) وهي إلزامية لجميع المنافذ التي تدعم معدل بيانات يبلغ 16.0 GT/s أو أعلى، بما في ذلك المنافذ الزائفة (Retimers). تتيح خاصية هوامش المسارات عند المستقبل لبرنامج النظام الحصول على معلومات الهامش لمستقبل معين بينما تكون الوصلة في حالة L0. تتضمن معلومات الهامش كل من الجهد والوقت، في أي اتجاه من موضع المستقبل الحالي. دعم الهامش للتوقيت مطلوب، في حين أن الدعم للجهد اختياري عند 16.0 GT/s ومطلوب عند 32.0 GT/s ومعدلات بيانات أعلى. أيضًا، الهامش الزمني المستقل والهامش الجهد المستقل اختياريان.

تسمح الأداة المساعدة بالحصول على تقريب لمخطط هامش العين (eye margin diagram) في شكل معين (بأربع نقاط). تتيح قدرة هوامش المسارات عند المستقبل للمستخدمين اختبار هوامش وصلات PCIe بدون مصحح أخطاء الأجهزة وبدون الحاجة إلى إيقاف النظام المستهدف. يمكن أن تكون الأداة المساعدة مفيدة لتصحيح مشاكل الوصلات بسبب هوامش المستقبل.

تتطلب pcilmr صلاحيات الجذر (للوصول إلى مساحة التكوين الموسعة)، ولكن خلال اختباراتنا لم تكن هناك مشاكل مع الأجهزة وعادت بنجاح إلى حالتها الأولية الطبيعية بعد نهاية الاختبار.

تقييم النتائج

يوفر مواصفات PCIe قيم مرجعية لمخطط العين، والتي تستخدمها أيضًا pcilmr لتقييم النتائج، ولكن يبدو أنه من المنطقي الاتصال بالشركة المصنعة لجهاز معين للحصول على المراجع.

تستخدم الأداة المساعدة القيم المحددة في مواصفات PCIe الأساسية Rev. 5.0 القسم 8.4.2 كمرجع افتراضي لعرض العين وارتفاعها. تم أخذ القيم الموصى بها من مواصفات اختبار فيزيائية معمارية PCIe Rev 5.0 (امتثال الإرسال الكهربائي).

قيم التقييم المرجعية المستخدمة حاليًا بواسطة الأداة المساعدة مقدمة في الجدول أدناه:

16 GT/s (Gen 4) 32 GT/s (Gen 5)
EW EH EW EH
الحد الأدنى 18.75 ps 30% UI 15 mV 9.375 ps 30% UI 15 mV
الموصى به 23.75 ps 38% UI 21 mV 10.157 ps 33% UI 19.75 mV

تستخدم pcilmr قيم عرض وارتفاع العين الكاملة لتقييم المسارات. ومع ذلك، فمن الممكن أن يدعم الجهاز هامشًا من جانب واحد فقط. في مثل هذه الحالات، ستقوم الأداة المساعدة بشكل افتراضي بحساب EW أو EH كضعف نتيجة جانب واحد.

إذا كانت المعلومات متاحة لجهاز معين، يمكنك تكوين معايير التقييم وتعديل سلوك الأداة المساعدة في حالات جانب واحد فقط لجهازك باستخدام خيار الوصلة -g (انظر أدناه).

دعم حلول الأجهزة الخاصة

بفضل الاختبارات أو مباشرة من وثائق الشركة المصنعة، نعلم أن بعض الأجهزة تتطلب معالجة خاصة أثناء الهامش. تكتشف الأداة المساعدة مثل هذه الأجهزة بناءً على زوج معرف البائع - معرف الجهاز الخاص بها. حاليًا، قائمة الأجهزة الخاصة مشفرة بشكل ثابت في الملف margin_hw. بالنسبة لهذه الأجهزة، يمكن للأداة المساعدة تعديل معلمات هامش المنفذ أو خيارات التقييم تلقائيًا.

على سبيل المثال، بالنسبة لمنافذ RC لوحدات معالجة Ice Lake المركزية، ستقوم pcilmr بتغيير قيمة MaxVoltageOffset للجهاز وستفرض استخدام وضع التقييم 'جانب واحد هو الكل'.

خيارات

محدد الجهاز

يمكنك تحديد المنفذ السفلي أو المنفذ العلوي للوصلة.

<الجهاز/المكون>
[<النطاق>:]<الحافلة>:<الجهاز>.<الوظيفة> (انظر lspci(8))

أوضاع الأداة المساعدة

--margin <المكونات السفلية> ...
اختبار هوامش الوصلات المحددة.
--full
اختبار هوامش جميع الوصلات الجاهزة للاختبار (بمعنى مشابه لخيار --scan) في النظام (واحدة تلو الأخرى).
--scan
البحث عن وصلات بسرعة تفاوض 16 GT/s أو أعلى. وضع علامة "جاهز" على تلك التي يكون فيها جانب واحد على الأقل من الوصلة لديه بت "Margining Ready" مضبوطًا، مما يعني أن هذه الوصلات جاهزة للاختبار ويمكنك تشغيل الأداة المساعدة عليها.

خيارات الهامش المشتركة (لجميع الوصلات المحددة)

-c طباعة قدرات هوامش مسارات الجهاز فقط. لا تقم بتشغيل الهامش.

-e <الأخطاء>
تحديد حد عدد الأخطاء للهامش.
الافتراضي: 4.
-o <الدليل>
حفظ نتائج الهامش بصيغة csv في الدليل المحدد. ستقوم الأداة المساعدة بإنشاء ملف بالاسم على شكل "lmr_<المنفذ>_Rx#_<الطابع الزمني>.csv" لكل مستقبل تم اختباره بنجاح.
-d <الوقت>

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

OPTIONS

The utility supports optional configuration file.

-c <config>
Specify configuration file.
Default config file is ~/.config/pcilmr.conf.

General options

-d <device>
Specify PCI device. Device can be specified in the following formats: bus:device.function, vendor:device, bus:device, vendor, device.
By default, utility tries to use the first suitable device.
-h
Show help message and exit.
-v
Be verbose.
-q
Be quiet.
-o <output_format>
Specify output format. Possible formats: csv, json, yaml.
Default: human readable text.
-i <iterations>
Specify number of iterations for the margining.
-w <wait_time>
Specify wait time in seconds after each step of margining.

Margining options

-s <step>
Specify step size for margining.
Default: 1.
-t <time>
Specify dwell time in seconds for the margining step.
Default: 1 s

Margining Link specific options

-l <lane>[,<lane>...]
Specify lanes for margining.
Remember that Device may use Lane Reversal for Lane numbering. However, utility uses logical lane numbers in arguments and for logging. Utility will automatically determine Lane Reversal and tune its calls.
Default: all link lanes.
-r <recvn>[,<recvn>...]
Specify Receivers to select margining targets.
Default: all available Receivers (including Retimers).
-p <parallel_lanes>
Specify number of lanes to margin simultaneously.
According to spec it's possible for Receiver to margin up to MaxLanes + 1 lanes simultaneously, but during testing, performing margining on several lanes simultaneously led to results that were different from sequential margining, so this feature requires additional verification and -p option right now is for experiments mostly.
Default: 1.

Use only one of -T/-t options at the same time (same for -V/-v).
Without these options utility will use MaxSteps from Device capabilities as test limit.

-T
Time Margining will continue until the Error Count is no more than an Error Count Limit. Use this option to find Link limit.
-t <steps>
Specify maximum number of steps for Time Margining.
-V
Same as -T option, but for Voltage.
-v <steps>
Specify maximum number of steps for Voltage Margining.
-g <recvn>t=<criteria>{%|ps}[,f]
<recvn>t=f[,<criteria>{%|ps}]
<recvn>v=<criteria>[,f]
<recvn>v=f[,<criteria>]
Specify pass/fail grading criteria for eye width (timing - t) or height (voltage - v) for one of the link receivers. For EW you must choose one of the units (% UI or ps), for EH mV is used.
Additional flag f is for situations when port doesn't support two side independent margining. In such cases by default utility will calculate EW or EH as a double one side result. You can add f flag for -g option to tell the utility that the result in one direction is actually the measurement of the full eye and it does not need to be multiplied. This is so called 'one side is the whole' grading mode.

EXAMPLES

Utility syntax example:

pcilmr -o csv ab:0.0 -r 1,6 -g 1t=20% -g 1v=f,30 52:0.0 -l 0,1,2 -TV

Examples of collected results on different systems.
