TEXT MODE IN GENERAL

The initial screen in text mode shows if pcp-atop runs with restricted view (unprivileged user) or unrestricted view (privileged user). In case of restricted view pcp-atop does not have the privileges (root identity or necessary capabilities) to retrieve all counter values on system level and on process level. does not have the privileges (no root identity nor the necessary capabilities) to retrieve all counter values on system level and on process level.

With every interval information is shown about the resource occupation on system level (CPU, memory, disks and network layers), followed by a list of processes which have been active during the last interval. Notice that all processes that were unchanged during the last interval re not shown, unless the key 'a' has been pressed or unless sorting on memory occupation is done (then inactive processes are relevant as well). If the list of active processes does not entirely fit on the screen, only the top of the list is shown (sorted in order of activity).
The intervals are repeated till the number of samples (specified as command argument) is reached, or till the key 'q' is pressed in interactive mode.

When invoked via the pcp(1) command, the PCPIntro(1) options -A/--align, -a/--archive, -h/--host, -O/--origin, -S/--start, -s/--samples, -T/--finish, -t/--interval, -v/--version, -z/--hostzone and -z/--timezone become indirectly available. Additionally, the --hotproc option can be used to request the per-process PCP metrics be used instead of the default proc metrics from pmdaproc(1).

When pcp-atop is started, it checks whether the standard output channel is connected to a screen, or to a file/pipe. In the first case it produces screen control codes (via the ncurses library) and behaves interactively; in the second case it produces flat text output.

In interactive mode, the output of pcp-atop scales dynamically to the current dimensions of the screen/window.
If the window is resized horizontally, columns will be added or removed automatically. For this purpose, every column has a particular weight. The columns with the highest weights that fit within the current width will be shown.
If the window is resized vertically, lines of the process/thread list will be added or removed automatically.

In interactive mode the output of pcp-atop can be controlled by pressing particular keys. However it is also possible to specify such key as flag on the command line. In that case pcp-atop switches to the indicated mode on beforehand. This mode can be modified again interactively. Specifying such key as flag is especially useful when running pcp-atop with output to a pipe or file (non-interactively). These flags are the same as the keys that can be pressed in interactive mode (see section INTERACTIVE COMMANDS).
Additional flags are available to support storage of pcp-atop data in PCP archive format (see section PCP DATA STORAGE).

COLORS

For the resource consumption on system level, pcp-atop uses colors in text mode to indicate that a critical occupation percentage has been (almost) reached. A critical occupation percentage means that is likely that this load causes a noticeable negative performance influence for applications using this resource. The critical percentage depends on the type of resource: e.g. the performance influence of a disk with a busy percentage of 80% might be more noticeable for applications/users than a CPU with a busy percentage of 90%.
Currently pcp-atop uses the following default values to calculate a weighted percentage per resource:

 Processor
A busy percentage of 90% or higher is considered 'critical' (also in bar graph mode).
 Disk
A busy percentage of 90% or higher is considered 'critical'.
 Network
A busy percentage of 90% or higher for the load of an interface is considered 'critical'.
 Memory
An occupation percentage of 90% is considered 'critical'. Notice that this occupation percentage is the accumulated memory consumption of the kernel (including slab) and all processes. The memory for the page cache ('cache' and 'buff' in the MEM-line) and the reclaimable part of the slab ('slrec') is not implied!
If the number of pages swapped out ('swout' in the PAG-line) is larger than 10 per second, the memory resource is considered 'critical'. A value of at least 1 per second is considered 'almost critical'.
If the committed virtual memory exceeds the limit ('vmcom' and 'vmlim' in the SWP-line), the SWP-line is colored due to overcommitting the system.
 Swap
An occupation percentage of 80% is considered 'critical' because swap space might be completely exhausted in the near future. It is not critical from a performance point-of-view.

These default values can be modified in the configuration file (see separate pcp-atoprc(5) man page).

When a resource exceeds its critical occupation percentage, the concerning values in the screen line are colored red by default.
When a resource exceeds (by default) 80% of its critical percentage (so it is almost critical), the concerning values in the screen line are colored cyan by default. This 'almost critical percentage' (one value for all resources) can be modified in the configuration file (see separate pcp-atoprc(5) man page).
The default colors red and cyan can be modified in the configuration file as well (see separate man-page of pcp-atoprc(5)).

With the key 'x' (or flag -x), the use of colors can be suppressed in text mode. The use of colors is however mandatory in case of bar graph mode.

NETATOP BPF MODULE

Per-process and per-thread network activity can be measured by the netatop BPF module that can be separately installed with pmdabpf(1). or pmdabcc(1).
When pcp-atop gathers counters for a new interval, it verifies if the eBPF module is currently active. If so, pcp-atop obtains the relevant network counters from this module and shows the number of sent and received packets per process/thread in the generic screen. Besides, detailed counters can be requested by pressing the 'n' key.

GPU STATISTICS GATHERING

GPU statistics can be gathered by pmdanvidia(1) which is a separate data collection daemon process. It gathers cumulative utilization counters of every Nvidia GPU in the system, as well as utilization counters of every process that uses a GPU. When pcp-atop notices that the daemon is active, it reads these GPU utilization counters with every interval.

Find a description about the utilization counters in the section OUTPUT DESCRIPTION.

INTERACTIVE COMMANDS

When running pcp-atop interactively (no output redirection), keys can be pressed to control the output. In general, lower case keys can be used to show other information for the active processes while certain upper case keys can be used to influence the sort order of the active process/thread list. Some of these keys can also be used to switch from bar graph mode to particular detailed process information in text mode.

g
Show generic output (default).

Per process the following fields are shown in case of a window-width of 80 positions: process-id, CPU consumption during the last interval in system and user mode, the virtual and resident memory growth of the process.
The data transfer per process for read/write on disk can only be shown when pcp-atop accesses metrics with root privileges.
When the optional pmdabpf(1) or pmdabcc(1) module netatop is loaded, the data transfer for send/receive of network packets is shown for each process.
The last columns contain the state, the occupation percentage for the chosen resource (default: CPU) and the process name.

When more than 80 positions are available, other information is added.

m
Show memory related output.

Per process the following fields are shown in case of a window width of 80 positions: process-id, minor and major memory faults, size of virtual shared text, total virtual process size, total resident process size, virtual and resident growth during last interval, memory occupation percentage and process name.

When more than 80 positions are available, other information is added.

For memory consumption, always all processes are shown (also the processes that were not active during the interval).

d
Show disk-related output.

When pcp-atop runs with root privileges, the following fields are shown: process-id, amount of data read from disk, amount of data written to disk, amount of data that was written but has been withdrawn again (WCANCL), disk occupation percentage and process name.

n
Show network related output.

Per process the following fields are shown in case of a window width of 80 positions: process-id, thread-id, total bandwidth for received packets, total bandwidth for sent packets, number of received TCP packets with the average size per packet (in bytes), number of sent TCP packets with the a

n
Show network statistics per process.

Per process the following fields are shown in case of a window width of 80 positions: process-id, the total number of received TCP packets with the average size per packet (in bytes), number of received UDP packets with the average size per packet (in bytes), number of sent UDP packets with the average size per packet (in bytes), the network occupation percentage and process name.
This information can only be shown when the optional pmdabpf(1) or pmdabcc(1) module netatop is installed.

When more than 80 positions are available, other information is added.

s
Show scheduling characteristics.

Per process the following fields are shown in case of a window width of 80 positions: process-id, number of threads in state 'running' (R), number of threads in state 'interruptible sleeping' (S), number of threads in state 'uninterruptible sleeping' (D), number of threads in state 'idle' (I), scheduling policy (normal timesharing, realtime round-robin, realtime fifo), nice value, priority, realtime priority, current processor, status, exit code, state, the occupation percentage for the chosen resource and the process name.

When more than 80 positions are available, other information is added.

v
Show various process characteristics.

Per process the following fields are shown in case of a window width of 80 positions: process-id, user name and group, start date and time, status (e.g. exit code if the process has finished), state, the occupation percentage for the chosen resource and the process name.

When more than 80 positions are available, other information is added.

c
Show the command line of the process.

Per process the following fields are shown: process-id, the occupation percentage for the chosen resource and the command line including arguments.

X
Show cgroup v2 information.

Per process the following fields are shown: process-id, the command name, and the cgroup path name (horizontally scrollable).

e
Show GPU utilization.

Per process at least the following fields are shown: process-id, range of GPU numbers on which the process currently runs, GPU busy percentage on all GPUs, memory busy percentage (i.e. read and write accesses on memory) on all GPUs, memory occupation at the moment of the sample, average memory occupation during the sample, and GPU percentage.

When the pmdanvidia daemon does not run with root privileges, the GPU busy percentage and the memory busy percentage are not available on process level. In that case, the GPU percentage on process level reflects the GPU memory occupation instead of the GPU busy percentage (which is preferred).

o
Show the user-defined line of the process.

In the configuration file the keyword ownprocline can be specified with the description of a user-defined output-line.
Refer to the man-page of pcp-atoprc(5) for a detailed description.

y
Show the individual threads within a process (toggle).

Single-threaded processes are still shown as one line.
For multi-threaded processes, one line represents the process while additional lines show the activity per individual thread (in a different color). Depending on the option 'a' (all or active toggle), all threads are shown or only the threads that were active during the last interval. Depending on the option 'Y' (sort threads), the threads per process will be sorted on the chosen sort criterion or not.
Whether this key is active or not can be seen in the header line.

Y
Sort the threads per process when combined with option 'y' (toggle).
u
Show the process activity accumulated per user.

Per user the following fields are shown: number of processes active or terminated during last interval (or in total if combined with command 'a'), accumulated CPU consumption during last interval in system and user mode, the current virtual and resident memory space consumed by active processes (or all processes of the user if combined with command 'a').
When pcp-atop access metrics with root privileges, the accumulated read and write throughput on disk is shown. When the optional pmdabpf(1) or pmdabcc(1) module 'netproc' has been installed, the number of receive and send network calls are shown.
The last columns contain the accumulated occupation percentage for the chosen resource (default: CPU) and the user name.

p
Show the process activity accumulated per program (i.e. process name).

Per program the following fields are shown: number of processes active or terminated during last interval (or in total if combined with command 'a'), accumulated CPU consumption during last interval in system and user mode, the current virtual and resident memory space consumed by active processes (or all processes of the user if combined with command 'a').
When pcp-atop access metrics with root privileges, the accumulated read and write throughput on disk is shown. When the pmdabcc(1) module 'netproc' has been installed, the number of receive and send network calls are shown.
The last columns contain the accumulated occupation percentage for the chosen resource (default: CPU) and the program name.

j
Show the process activity accumulated per container/pod.

Per container (e.g. Docker/Podman) or pod (e.g. Kubernetes) the following fields are shown: number of processes active or terminated during last interval (or in total if combined with command 'a'), accumulated CPU consumption during last interval in system and user mode, the current virtual and resident memory space consumed by active processes (or all processes of the user if combined with command 'a').
When pcp-atop access metrics with root privileges, the accumulated read and write throughput on disk is shown. When the pmdabpf(1) or pmdabcc(1) module 'netproc' has been installed, the number of receive and send network calls are shown.
The last columns contain the accumulated occupation percentage for the chosen resource (default: CPU) and the container/pod name (CID/POD).

C
Sort the current list in the order of CPU consumption (default). The one-but-last column changes to 'CPU'.
E
Sort the current list in the order of GPU utilization (preferred, but only applicable when the pmdanvidia daemon runs under root privileges) or the order of GPU memory occupation). The one-but-last column changes to 'GPU'.
M
Sort the current list in the order of resident memory consumption. The one-but-last column changes to 'MEM'. In case of sorting on memory, the full process list will be shown (not only the active processes).
D
Sort the current list in the order of disk accesses issued. The one-but-last column changes to 'DSK'.
N
Sort the current list in the order of network bandwidth (received and transmitted). The one-but-last column changes to 'NET'.
A
Sort the current list automatically in the order of the most busy system resource during this interval. The one-but-last column shows either 'ACPU', 'AMEM', 'ADSK' or 'ANET' (the preceding 'A' indicates automatic sorting-order). The most busy resource is determined by comparing the weighted busy-percentages of the system resources, as described earlier in the section COLORS.
This option remains valid until another sorting-order is explicitly selected again.
A sorting order for disk is only possible when pcp-atop runs with root privileges. A sorting-order for network is only possible when the pmdabpf(1) or pmdabcc(1) module 'netproc' has been installed.

وصف الإخراج - مستوى النظام

تتكون معلومات مستوى النظام في الوضع النصي من أسطر الإخراج التالية:

PRC
إجماليات العمليات والخيوط.
يحتوي هذا السطر على إجمالي وقت وحدة المعالجة المركزية المستهلك في وضع النظام ('sys') وفي وضع المستخدم ('user')، وإجمالي عدد العمليات الموجودة في هذه اللحظة ('#proc')، وإجمالي عدد الخيوط الموجودة في هذه اللحظة في حالة 'تشغيل' ('#trun')، و'نوم قابل للمقاطعة' ('#tslpi')، و'نوم غير قابل للمقاطعة' ('#tslpu')، و'خامل' ('#tidle')، وعدد عمليات الزومبي ('#zombie')، وعدد استدعاءات نظام النسخ المتماثل ('clones')، وعدد العمليات التي انتهت خلال الفترة ('#exit') عند استخدام محاسبة العمليات. بدلاً من '#exit'، قد يشير العمود الأخير إلى أنه لم يكن من الممكن تفعيل محاسبة العمليات ('no procacct').
إذا كان عرض الشاشة لا يسمح بجميع هذه العدادات، يتم عرض مجموعة فرعية ذات صلة فقط.
CPU
استخدام وحدة المعالجة المركزية.
يتم عرض سطر واحد على الأقل للإشغال الكلي لجميع وحدات المعالجة المركزية معًا.
في حالة نظام متعدد المعالجات، يتم عرض سطر إضافي لكل معالج فردي (بحرف 'cpu' صغير)، مرتبًا حسب النشاط. لن يتم عرض وحدات المعالجة المركزية غير النشطة افتراضيًا. تحتوي الأسطر التي تعرض إشغال كل وحدة معالجة مركزية على رقم وحدة المعالجة المركزية في الحقل المدمج مع نسبة الانتظار.

يحتوي كل سطر على نسبة وقت وحدة المعالجة المركزية المستغرق في وضع النواة ('sys') لجميع العمليات النشطة، ونسبة وقت وحدة المعالجة المركزية المستهلكة في وضع المستخدم ('user') لجميع العمليات النشطة (بما في ذلك العمليات التي تعمل بقيمة "nice" أكبر من الصفر)، ونسبة وقت وحدة المعالجة المركزية المستغرق لمعالجة المقاطعات ('irq') بما في ذلك المقاطعات الناعمة، ونسبة وقت وحدة المعالجة المركزية غير المستخدم بينما لم تكن هناك عمليات تنتظر إدخال/إخراج القرص ('idle')، ونسبة وقت وحدة المعالجة المركزية غير المستخدم بينما كانت عملية واحدة على الأقل تنتظر إدخال/إخراج القرص ('wait').
في حالة إشغال كل وحدة معالجة مركزية، يتم عرض رقم وحدة المعالجة المركزية ونسبة الانتظار ('w') لتلك الوحدة. قد يكون عدد الأسطر التي تعرض إشغال كل وحدة معالجة مركزية محدودًا.

بالنسبة للأجهزة الافتراضية، تظهر نسبة السرقة ('steal') نسبة وقت وحدة المعالجة المركزية المسروقة بواسطة الأجهزة الافتراضية الأخرى التي تعمل على نفس الأجهزة.
بالنسبة للأجهزة المادية التي تستضيف جهازًا افتراضيًا واحدًا أو أكثر، تظهر نسبة الضيف ('guest') نسبة وقت وحدة المعالجة المركزية المستخدمة بواسطة الأجهزة الافتراضية. لاحظ أن هذه النسبة تتداخل مع نسبة المستخدم!

عندما تدعم وحدة المعالجة المركزية والنواة عدادات مراقبة الأداء PMC (ويعمل pmdaperfevent(1) بامتيازات الجذر)، يتم عرض عدد التعليمات لكل دورة معالج ('ipc'). تعرض العينة الأولى دائمًا القيمة 'initial'، لأن العدادات تم تنشيطها للتو في اللحظة التي يبدأ فيها pcp-atop.
عندما تكون نسبة انشغال وحدة المعالجة المركزية مرتفعة و IPC أقل من 1.0، فمن المحتمل أن وحدة المعالجة المركزية تنتظر وصول الذاكرة بشكل متكرر أثناء تنفيذ التعليمات (قد تكون ذاكرة التخزين المؤقت الكبيرة لوحدة المعالجة المركزية أو الذاكرة الأسرع مفيدة لتحسين الأداء). عندما تكون نسبة انشغال وحدة المعالجة المركزية مرتفعة و IPC أكبر من 1.0، فمن المحتمل أن وحدة المعالجة المركزية مقيدة بالتعليمات (قد تكون وحدات المعالجة المركزية / الأسرع الأسرع مفيدة لتحسين الأداء).
علاوة على ذلك، يتم عرض العدد الفعلي للدورات ('cycl') لكل وحدة معالجة مركزية. يمكن أن تصل هذه القيمة إلى تردد وحدة المعالجة المركزية الحالي إذا كانت وحدة المعالجة المركزية هذه مشغولة بنسبة 100%. عندما يتم إيقاف وحدة معالجة مركزية خاملة، يمكن أن يكون عدد الدورات الفعلي أقل (بشكل كبير) من التردد الحالي.
لاحظ أن متوسط التعليمات لكل دورة وعدد الدورات يتم عرضه في سطر وحدة المعالجة المركزية لكل وحدة معالجة مركزية.

GPU
استخدام وحدة معالجة الرسومات (Nvidia).
اقرأ قسم تجميع إحصائيات وحدة معالجة الرسومات في هذا المستند لمعرفة التفاصيل حول تفعيل خادم pmdanvidia.

في العمود الأول من كل سطر، يتم عرض معرف الناقل (آخر تسعة أحرف) ورقم وحدة معالجة الرسومات. تعرض الأعمدة التالية النسبة المئوية للوقت الذي كانت فيه نواة واحدة أو أكثر قيد التنفيذ على وحدة معالجة الرسومات ('gpubusy')، والنسبة المئوية للوقت الذي كانت فيه ذاكرة الجهاز (العالمية) تُقرأ أو تُكتب ('membusy')، ونسبة إشغال الذاكرة ('memocc')، وإجمالي الذاكرة ('total')، والذاكرة المستخدمة في لحظة العينة ('used')، ومتوسط الذاكرة المستخدمة خلال وقت العينة ('usavg')، وعدد العمليات النشطة على وحدة معالجة الرسومات في لحظة العينة ('#proc')، ونوع وحدة معالجة الرسومات.

إذا كان عرض الشاشة لا يسمح بجميع هذه العدادات، يتم عرض مجموعة فرعية ذات صلة فقط.
يمكن أن يكون عدد الأسطر التي تعرض وحدات معالجة الرسومات محدودًا.

MEM
إشغال الذاكرة (سطران).
تحتوي هذه الأسطر على إجمالي حجم الذاكرة الفعلية ('tot')، وحجم الذاكرة الحرة حاليًا ('free')، وحجم الذاكرة المتاح للأعباء الجديدة دون دفع النظام إلى الـ swap ('avail')، وحجم الذاكرة المستخدمة كذاكرة تخزين مؤقت للصفحات بما في ذلك إجمالي الذاكرة المشتركة المقيمة ('cache')، وحجم الذاكرة داخل ذاكرة التخزين المؤقت للصفحات التي يجب مسحها إلى القرص ('dirty')، وحجم الذاكرة المستخدمة لبيانات تعريف نظام الملفات ('buff')، وحجم الذاكرة المستخدمة لمخصّصات النواة ('slab')، وحجم الذاكرة في slab التي يمكن استعادتها ('slrec')، والحجم المقيم لذاكرة SYSV المشتركة بما في ذلك tmpfs باستثناء الصفحات الكبيرة الثابتة ('shmem')، والحجم المقيم لذاكرة SYSV المشتركة بما في ذلك الصفحات الكبيرة الثابتة ('shrss')، وحجم ذاكرة SYSV المشتركة التي تم تبديلها حاليًا ('shswp')، وحجم الذاكرة المستخدم حاليًا لجداول الصفحات ('pgtab')، وعدد عقد NUMA في هذا النظام ('numnode')، وحجم الذاكرة المطالب بها حاليًا بواسطة برنامج تشغيل بالون VMware ('vmbal')، وحجم الذاكرة المطالب بها حاليًا بواسطة ARC (ذاكرة التخزين المؤقت) لـ ZFSonlinux ('zfarc')، وحجم الذاكرة المستخدمة للصفحات الكبيرة الشفافة المجهولة ('anthp')، وحجم الذاكرة المطالب بها للصفحات الكبيرة ('hptot')، وحجم ذاكرة الصفحات الكبيرة المستخدمة فعليًا ('hpuse')، وحجم الذاكرة المستخدمة لمقابس TCP ('tcps')، وحجم الذاكرة المستخدمة لمقابس UDP ('udps').

إذا كان عرض الشاشة لا يسمح بجميع هذه العدادات، يتم عرض مجموعة فرعية ذات صلة فقط.

SWP
إشغال الـ Swap ومعلومات الإفراط في الالتزام.
يحتوي هذا السطر على إجمالي مساحة الـ swap على القرص ('tot') ومقدار مساحة الـ swap الحرة ('free')، وحجم ذاكرة التخزين المؤقت للـ swap ('swcac')، وحجم التخزين المضغوط المستخدم لـ zswap ('zswap')، والحجم الفعلي (غير المضغوط) للصفحات المخزنة في zswap ('zstor')، وإجمالي حجم الذاكرة المستخدمة لـ KSM ('ksuse'، أي مشتركة)، وإجمالي حجم الذاكرة المحفوظة (مكررة) بواسطة KSM ('kssav'، أي مشاركة).
علاوة على ذلك، يتم عرض المساحة الملتزمة بالذاكرة الافتراضية ('vmcom') والحد الأقصى لحد المساحة الملتزمة ('vmlim'، والذي يكون افتراضيًا هو حجم الـ swap + 50٪ من حجم الذاكرة). المساحة الملتزمة هي المساحة الافتراضية المحجوزة لجميع تخصيصات مساحة الذاكرة الخاصة للعمليات. تتحقق النواة فقط مما إذا كانت المساحة الملتزمة تتجاوز الحد إذا تم تكوين معالجة صارمة للإفراط في الالتزام (vm.overcommit_memory هو 2).
LLC
ذاكرة التخزين المؤقت من المستوى الأخير لوحدة المعالجة المركزية.
يحتوي هذا السطر على عرض النطاق الترددي الإجمالي للذاكرة لـ LLC ('tot')، وعرض النطاق الترددي لعقدة NUMA المحلية ('loc')، ونسبة استخدام LLC ('LLCXX YY%').

لاحظ أن هذه الميزة تعتمد على نظام الملفات الزائف 'resctrl'. تأكد من بناء النواة بالتكوين ذي الصلة واعتنِ بتركيب نظام الملفات الزائف:

  mount -t resctrl resctrl -o mba_MBps /sys/fs/resctrl (على Intel)
  mount -t resctrl resctrl -o cdp /sys/fs/resctrl (على AMD)

NUM
استخدام الذاكرة لكل عقدة NUMA (لا يتم عرضه لنظام واحد.

تم إخراجه إلى صفحة بسبب نقص الذاكرة (بينما كانت العملية نفسها في حالة سبات).

لكل عملية، قد تظهر الحقول التالية (بترتيب أبجدي)، اعتمادًا على وضع الإخراج الحالي كما هو موصوف في القسم INTERACTIVE COMMANDS واعتمادًا على العرض الحالي لنافذتك:

AVGRSZ
متوسط حجم عملية القراءة من القرص.
AVGWSZ
متوسط حجم عملية الكتابة على القرص.
BANDWI
إجمالي عرض النطاق الترددي لحزم TCP و UDP المستلمة التي تستهلكها هذه العملية (بت في الثانية). يمكن مقارنة هذه القيمة بقيمة "si" على مستوى الواجهة (عرض النطاق الترددي المستخدم لكل واجهة).
ستظهر هذه المعلومات فقط عند تثبيت الوحدة النمطية "netproc" الاختيارية من pmdabpf(1) أو pmdabcc(1).
BANDWO
إجمالي عرض النطاق الترددي لحزم TCP و UDP المرسلة التي تستهلكها هذه العملية (بت في الثانية). يمكن مقارنة هذه القيمة بقيمة "so" على مستوى الواجهة (عرض النطاق الترددي المستخدم لكل واجهة).
ستظهر هذه المعلومات فقط عند تثبيت الوحدة النمطية "netproc" الاختيارية من pmdabpf(1) أو pmdabcc(1).
BDELAY
تأخير مجمع في إدخال/إخراج الكتل، أي الوقت المستغرق في انتظار إدخال/إخراج القرص.
CGROUP
اسم مسار cgroup (الإصدار 2) الذي تنتمي إليه هذه العملية. اسم المسار هذا نسبي إلى دليل جذر cgroup، والذي عادة ما يكون '/sys/fs/cgroup'.
CID/POD
معرف الحاوية (مثل Docker أو Podman) أو اسم الحاوية (مثل Kubernetes) الذي يشير إلى الحاوية/الحاوية التي تعمل فيها العملية/الخيط. إذا كان اسم الحاوية أطول من 15 حرفًا، فسيتم عرض آخر 15 حرفًا فقط.

إذا تم بدء عملية وانتهت خلال الفترة الزمنية الأخيرة، فسيتم عرض علامة '؟' لأن معرف الحاوية أو اسم الحاوية ليس جزءًا من سجل المحاسبة القياسي للعملية.

سيتم عرض هذا العمود فقط عند تشغيل atop بامتيازات المستخدم الخارق وعند اكتشاف عملية واحدة على الأقل في حاويات.

CMD
اسم العملية. يمكن أن يكون هذا الاسم محاطًا بعلامتي "أقل/أكبر" ('<name>') مما يعني أن العملية قد انتهت خلال الفترة الزمنية الأخيرة. يتم كتابة سجل محاسبة واحد للعملية بأكملها عند إنهاء آخر خيط في العملية. عند خروج الخيط الرئيسي، يتم تغيير اسم العملية إلى اسم الخيط.
خلف الاختصار "CMD" في سطر الرأس، يتم عرض رقم الصفحة الحالية وإجمالي عدد الصفحات لقائمة العمليات/الخيوط.
COMMAND-LINE
سطر الأوامر الكامل للعملية (بما في ذلك الوسائط). إذا تجاوز طول سطر الأوامر طول سطر الشاشة، يمكن استخدام مفتاحي الأسهم - > و <- للتمرير الأفقي.

يمكن استخدام خيار سطر الأوامر "-z <regex>" لإضافة متغيرات البيئة المطابقة إلى سطر الأوامر المعروض. يتم استخدام صيغة تعبيرات Regex الموسعة POSIX (انظر regex(3)). عندما يكون متغير البيئة المطابق طويلاً جدًا (يتجاوز المخزن المؤقت الذي يجب أن يحتوي على سطر الأوامر)، سيتم اقتطاعه.
خلف الكلمة "COMMAND-LINE" في سطر الرأس، يتم عرض رقم الصفحة الحالي وإجمالي عدد الصفحات لقائمة العمليات/الخيوط.

CPU
نسبة إشغال هذه العملية فيما يتعلق بالسعة المتاحة لهذا المورد على مستوى النظام.
CPUNR
تحديد وحدة المعالجة المركزية (CPU) التي يعمل عليها الخيط (الرئيسي) أو كان يعمل عليها مؤخرًا.
CTID
معرف الحاوية (OpenVZ). إذا تم بدء عملية وانتهت خلال الفترة الزمنية الأخيرة، فسيتم عرض علامة '؟' لأن معرف الحاوية ليس جزءًا من سجل المحاسبة القياسي للعملية.
DSK
نسبة إشغال هذه العملية فيما يتعلق بإجمالي الحمل الناتج عن جميع العمليات (أي، إجمالي عمليات الوصول إلى القرص من قبل جميع العمليات خلال الفترة الزمنية الأخيرة).
يتم عرض هذه المعلومات عند تنشيط "محاسبة التخزين" لكل عملية في النواة.
EGID
معرف المجموعة الفعال الذي تنفذ هذه العملية بموجبه.
ENDATE
تاريخ انتهاء العملية. إذا كانت العملية لا تزال قيد التشغيل، فسيعرض هذا الحقل "active".
ENTIME
وقت انتهاء العملية. إذا كانت العملية لا تزال قيد التشغيل، فسيعرض هذا الحقل "active".
ENVID
تم تحديد البيئة الافتراضية (OpenVZ فقط).
EUID
معرف المستخدم الفعال الذي تنفذ هذه العملية بموجبه.
EXC
رمز الخروج لعملية منتهية (الموضع الثاني من العمود "ST" هو E) أو رقم الإشارة القاتلة (الموضع الثاني من العمود "ST" هو S أو C).
FSGID
معرف مجموعة نظام الملفات الذي تنفذ هذه العملية بموجبه.
FSUID
معرف مستخدم نظام الملفات الذي تنفذ هذه العملية بموجبه.
GPU
عندما لا يتم تشغيل برنامج demon pmdanvidia بامتيازات المستخدم الجذر، فإن نسبة GPU تعكس نسبة إشغال ذاكرة GPU (ذاكرة جميع وحدات معالجة الرسومات هي 100٪).
عند تشغيل برنامج demon pmdanvidia بامتيازات المستخدم الجذر، فإن نسبة GPU تعكس نسبة استخدام GPU.
GPUBUSY
نسبة الاستخدام على جميع وحدات معالجة الرسومات (وحدة معالجة رسومات واحدة هي 100٪).
عندما لا يتم تشغيل برنامج demon pmdanvidia بامتيازات المستخدم الجذر، فإن هذه القيمة غير متوفرة.
GPUNUMS
قائمة مفصولة بفواصل لوحدات معالجة الرسومات المستخدمة بواسطة العملية خلال الفترة. عندما تتجاوز القائمة المفصولة بفواصل عرض العمود، يتم عرض قيمة سداسية عشرية.
LOCKSZ
الحجم الافتراضي للذاكرة المقفلة (أي غير قابلة للتبديل) بواسطة هذه العملية (أو المستخدم).
MAJFLT
عدد أخطاء الصفحات التي أصدرتها هذه العملية والتي تم حلها عن طريق إنشاء/تحميل صفحة الذاكرة المطلوبة.
MEM
نسبة إشغال هذه العملية فيما يتعلق بالسعة المتاحة لهذا المورد على مستوى النظام.
MEMAVG
متوسط إشغال الذاكرة خلال الفترة على جميع وحدات معالجة الرسومات المستخدمة.
MEMBUSY
نسبة استخدام ذاكرة جميع وحدات معالجة الرسومات (وحدة معالجة رسومات واحدة هي 100٪)، أي الوقت اللازم لعمليات القراءة والكتابة على الذاكرة.
عندما لا يتم تشغيل برنامج demon pmdanvidia بامتيازات المستخدم الجذر، فإن هذه القيمة غير متوفرة.
MEMNOW
إشغال الذاكرة في لحظة العينة على جميع وحدات معالجة الرسومات المستخدمة.
MINFLT
عدد أخطاء الصفحات التي أصدرتها هذه العملية والتي تم حلها عن طريق استعادة صفحة الذاكرة المطلوبة من قائمة الصفحات الحرة.
NET
نسبة إشغال هذه العملية فيما يتعلق بإجمالي الحمل الناتج عن جميع العمليات (أي، استهلاك عرض النطاق الترددي للشبكة لجميع العمليات خلال الفترة الزمنية الأخيرة).
ستظهر هذه المعلومات فقط عند تثبيت الوحدة النمطية "netproc" الاختيارية من pmdabpf(1) أو pmdabcc(1).
NICE
الأولوية الثابتة نسبيًا والتي يمكن منحها لعملية على مقياس من -20 (أولوية عالية) إلى +19 (أولوية منخفضة).
NIVCSW
عدد المرات التي تم فيها تبديل سياق العملية/الخيط بشكل غير طوعي، في حالة انتهاء شريحة الوقت.
NPROCS
عدد العمليات النشطة والمنتهية المتراكمة لهذا المستخدم أو البرنامج.
NVCSW
عدد المرات التي تم فيها تبديل سياق العملية/الخيط طوعًا في حالة استدعاء نظام يحظر، على سبيل المثال، الانتظار لإكمال عملية إدخال/إخراج.
PID
معرف العملية.
POLI
تشير السياسات "norm" (عادي، وهو SCHED_OTHER)، "btch" (دفعة) و "idle" (خمول) إلى عمليات مشاركة الوقت. تشير السياسات "fifo" (SCHED_FIFO) و "rr" (دوران دائري، وهو SCHED_RR) إلى عمليات الوقت الفعلي.
PPID
معرف العملية الأب.
PRI
تتراوح أولوية العملية من 0 (أعلى أولوية) إلى 139 (أدنى أولوية). تستخدم الأولوية من 0 إلى 99 للعمليات ذات الوقت الفعلي (أولوية ثابتة بغض النظر عن سلوكها) والأولوية من 100 إلى 139 لعمليات مشاركة الوقت (أولوية متغيرة تعتمد على استهلاكها لوحدة المعالجة المركزية مؤخرًا وقيمة "nice").
PSIZE
حجم الذاكرة النسبي لهذه العملية (أو المستخدم).
تتشارك كل عملية في الذاكرة المقيمة مع العمليات الأخرى. على سبيل المثال، عند بدء برنامج معين عدة مرات، لا يتم تحميل صفحات التعليمات البرمجية (النص) إلا مرة واحدة في الذاكرة ويتم مشاركتها بواسطة جميع التجسيدات. كما أن رمز المكتبات المشتركة يتم مشاركته بواسطة جميع العمليات التي تستخدم تلك المكتبة المشتركة، بالإضافة إلى الذاكرة المشتركة والملفات المعينة بالذاكرة. لحساب PSIZE لعملية ما، يتم تقسيم الذاكرة المقيمة لعملية مشتركة مع عمليات أخرى على عدد المشاركين. هذا يعني أنه يتم محاسبة كل عملية بجزء نسبي من تلك الذاكرة. يؤدي تجميع قيم PSIZE لجميع العمليات في النظام إلى انطباع موثوق عن إجمالي المقيم.

بيئة PCP

تُستخدم متغيرات البيئة التي تبدأ بالبادئة PCP_ لتحديد أسماء الملفات والدلائل التي يستخدمها PCP. في كل تثبيت، يحتوي الملف /etc/pcp.conf على القيم المحلية لهذه المتغيرات. يمكن استخدام المتغير $PCP_CONF لتحديد ملف تكوين بديل، كما هو موضح في pcp.conf(5).

بالنسبة لمتغيرات البيئة التي تؤثر على أدوات PCP، راجع pmGetOptions(3).

خيارات التصحيح

يُمكّن الخيار -D أو --debug الخاص بـ pcp من إخراج تشخيصات إضافية على stderr للمساعدة في تتبع المشكلات، على الرغم من أن المعلومات تكون في بعض الأحيان غامضة ومخصصة بشكل أساسي لتوفير التوجيه للمطورين بدلاً من المستخدمين النهائيين. debug هي قائمة مفصولة بفواصل لخيارات التصحيح؛ استخدم pmdbg(1) مع الخيار -l للحصول على قائمة بالخيارات المتاحة وتفسيرها.

خيارات التصحيح الخاصة بـ pcp-atop هي كالتالي:

الخيار الوصف
appl0 تشخيصات عامة
appl1 استرجاع المقاييس ومجالات المثيلات
