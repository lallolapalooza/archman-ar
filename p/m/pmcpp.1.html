NAME

pmcpp - Preprocessor for Performance Metrics XML and Plog files

SYNOPSIS

pmcpp [-C|-c] [-D macro[=value]] [-I dir] [-P file] [-R] [-s] [-v] [-w] [infile]

DESCRIPTION

The pmcpp utility is a general-purpose C preprocessor that has been tailored for use with Performance Co-Pilot (PCP) configuration files, such as those found in the $PCP_DIR/etc directory. It supports the standard C preprocessor directives (#define, #include, #ifdef, etc.) and also includes extensions for generating XML files. It can also be used to preprocess Plog files for use with pmlog(1). The standard C preprocessor syntax and semantics are used for all preprocessor directives.

The default behavior of pmcpp is to read from standard input and write to standard output. If an infile is specified, it will be read instead of standard input.

Macros defined via the -D option, or in a configuration file specified by -P, are available for use within the input file.

The default include path for #include directives is the current directory. The -I option can be used to add additional directories to the include search path.

OPTIONS

-C
Retain C-style comments (i.e., do not remove them).
-c
Remove C-style comments. This is the default behavior.
-D macro[=value]
Define macro, optionally with the given value. This is equivalent to specifying `#define macro [value]' in the input file.
-I dir
Add dir to the list of directories to be searched for include files.
-P file
Process the specified file first. This is useful for defining common macros or include directives that apply to multiple input files.
-R
Recursively expand macros. This means that if a macro's definition contains another macro, the inner macro will also be expanded.
-s
Enable the generation of statistics. This option is primarily used for debugging pmcpp itself.
-v
Enable verbose output. This will print information about the preprocessing steps being performed, such as which files are being included.
-w
Enable warnings. By default, pmcpp may issue warnings about potential problems in the input file.

EXAMPLES

The following example shows how pmcpp can be used to generate different logging frequencies based on a macro definition.

Given the following input file (named frequencies):

%ifndef dk_freq
%define dk_freq 1minute
%endif

%ifndef cpu_freq
%define cpu_freq 15sec
%endif

log mandatory on %dk_freq {
    disk.dev
}

# note no %want_cpu here

%ifdef want_cpu
%define cpu_pfx
    'kernel.all.cpu.'
log mandatory on %cpu_freq {
    %{cpu_pfx}user
    %{cpu_pfx}sys
}
%endif

Running pmcpp without any special options:

$ pmcpp < frequencies

Produces the following output:

log mandatory on 1minute {
    disk.dev
}

# note no %want_cpu here

Running pmcpp with the -D option:

$ pmcpp -D want_cpu < frequencies

Produces the following output:

log mandatory on 1minute {
    disk.dev
}

# note no %want_cpu here

%define cpu_pfx
    'kernel.all.cpu.'
log mandatory on 15sec {
     kernel.all.cpu.user
     kernel.all.cpu.sys
}

PCP ENVIRONMENT

Environment variables with the prefix PCP_ are used to parameterize the file and directory names used by PCP. On each installation, the file /etc/pcp.conf contains the local values for these variables. The $PCP_CONF variable may be used to specify an alternative configuration file, as described in pcp.conf(5).

For environment variables affecting PCP tools, see pmGetOptions(3).
