الحزمة: pcp

PMDAOVERHEAD(1) دليل الأوامر العامة PMDAOVERHEAD(1)

الاسم

pmdaoverhead - وكيل نطاق مقاييس الأداء (PMDA) الذي يصدر مقاييس استهلاك الموارد لمجموعات العمليات

الملخص

$PCP_PMDAS_DIR/overhead/pmdaoverhead [-C] [-c config] [-D debug] [-d domain] [-l logfile] [-R interval]

الوصف

pmdaoverhead هو وكيل نطاق مقاييس الأداء (PMDA) قابل للتكوين لتصدير استهلاك الموارد لمجموعات العمليات ذات الصلة.

خيارات سطر الأوامر الخاصة بـ pmdaoverhead هي:

-C
تحليل ملف (ملفات) التكوين والخروج بعد الإبلاغ عن أي أخطاء.
-c
ملف (ملفات) التكوين، config يمكن أن يكون ملفًا أو دليلاً؛ في الحالة الأخيرة، يُفترض أن جميع الملفات داخل config هي ملفات تكوين لـ pmdaoverhead وسيتم معالجتها جميعًا.

يحدد كل ملف تكوين "مجموعة" واحدة أو أكثر من العمليات ذات الأهمية، باستخدام الصيغة الموضحة في قسم "التكوين" أدناه.

افتراضيًا، يتم استخدام جميع ملفات التكوين الموجودة في الدليل $PCP_SYSCONF_DIR/overhead/conf.d/.

-d
من الضروري للغاية أن يكون رقم نطاق المقاييس domain المحدد هنا فريدًا ومتسقًا. أي، يجب أن يكون domain مختلفًا لكل PMDA على نفس المضيف، ويجب استخدام نفس رقم domain لنفس PMDA على جميع المضيفين.
-l
موقع ملف السجل. افتراضيًا، يتم كتابة ملف سجل يسمى overhead.log في الدليل الحالي لـ pmcd(1) عند بدء تشغيل pmdaoverhead، أي $PCP_LOG_DIR/pmcd. إذا لم يتمكن من إنشاء ملف السجل أو لم يكن قابلاً للكتابة، يتم كتابة المخرجات إلى الخطأ القياسي بدلاً من ذلك.
-R
يستخدم PMDA خيطًا منفصلاً لمسح جميع العمليات بشكل دوري لتحديد العمليات التي تعتبر "مثيرة للاهتمام" في كل مجموعة، واستخراج استهلاك الموارد لتلك العمليات. يحدد interval (بالثواني) عدد مرات إجراء هذا المسح وحساب الموارد، الافتراضي هو 60 (ثانية).

التكوين

يحدد كل ملف تكوين "مجموعة" واحدة أو أكثر من العمليات. تنسيق الملف بسيط ويتبع القواعد التالية.

1.
تُعامل الأسطر التي تبدأ بعلامة الهاش "#" على أنها تعليقات. بشكل عام، باستثناء عبارة pattern: الموضحة أدناه، يتم التعامل مع كل النص بين علامة هاش ونهاية السطر على أنه تعليق.
2.
المسافات البيضاء (مسافات أو علامات جدولة أو أسطر جديدة) مطلوبة للفصل بين المكونات المعجمية. يتم تجاهل المسافات وعلامات الجدولة بخلاف ذلك. بخلاف إنهاء التعليقات و regex في عبارة pattern:، يتم تجاهل الأسطر الجديدة أيضًا.
3.
يتم تقديم كل مجموعة بواسطة عبارة group لها الشكل
group name { parameters }
حيث name هو اسم فريد للمجموعة عبر جميع المجموعات في ملفات تكوين pmdaoverhead. نظرًا لأن name يصبح جزءًا لا يتجزأ من مساحة أسماء مقاييس الأداء (PMNS) فيجب أن يتبع قواعد مكونات اسم المقياس كما هو موضح في PMNS(5)، وتحديدًا يبدأ بحرف أبجدي، يليه صفر أو أكثر من الأحرف المأخوذة من الأبجديات والأرقام وحرف الشرطة السفلية "_".
4.
يجب أن تتضمن parameters عبارة id: واحدة وعبارة pattern: واحدة.
5.
عبارة id: لها الشكل
id: ident
حيث ident هو رقم معرف فريد للمجموعة عبر جميع المجموعات في ملفات تكوين pmdaoverhead. القيم الصالحة لـ ident هي في النطاق من 0 إلى 4094 (شامل).
6.
عبارة pattern: لها الشكل
pattern: regex
حيث regex هو تعبير عادي ممتد بأسلوب egrep(1). تبدأ regex عند أول حرف غير مسافة بيضاء بعد pattern: وتمتد إلى السطر الجديد التالي.

العمليات التي تعتبر أعضاء في المجموعة هي تلك التي يتطابق فيها اسم الأمر، كما هو المبلغ عنه بواسطة
$ pminfo -f proc.psinfo.cmd
مع regex **بالإضافة إلى** جميع العمليات المنحدرة من تلك العمليات. لذا على سبيل المثال، regex ^pmcd$ ستتطابق مع pmcd(1) وجميع عمليات PMDA التي بدأها pmcd(1) وأي من أطفالها، إلخ.

التثبيت

إذا كنت تريد الوصول إلى الأسماء والنصوص المساعدة والقيم الخاصة بمقاييس الأداء الرئيسية، فقم بما يلي بصفتك root:

# cd $PCP_PMDAS_DIR/overhead
# ./Install

إذا كنت ترغب في إلغاء التثبيت، فقم بما يلي بصفتك root:

# cd $PCP_PMDAS_DIR/overhead
# ./Remove

يتم تشغيل pmdaoverhead بواسطة pmcd ولا يجب تنفيذه مباشرة أبدًا. تقوم نصوص التثبيت والإزالة بإخطار pmcd عند تثبيت الوكيل أو إزالته.

الملفات

$PCP_PMCDCONF_PATH
خيارات سطر الأوامر المستخدمة لبدء تشغيل pmdaoverhead
$PCP_PMDAS_DIR/overhead/Install
نص التثبيت لوكيل pmdaoverhead
$PCP_PMDAS_DIR/overhead/Remove
نص إلغاء التثبيت لوكيل pmdaoverhead
$PCP_LOG_DIR/pmcd/overhead.log
ملف السجل الافتراضي لرسائل الخطأ والمعلومات الأخرى من pmdaoverhead
$PCP_SYSCONF_DIR/overhead/conf.d
الدليل الذي يحتوي على ملفات التكوين لمقاييس الأداء الرئيسية

بيئة PCP

تُستخدم متغيرات البيئة التي تبدأ بـ PCP_ لإنشاء معلمات لأسماء الملفات والأدلة المستخدمة بواسطة PCP. عند كل تثبيت، يحتوي الملف /etc/pcp.conf على القيم المحلية لهذه المتغيرات. يمكن استخدام المتغير $PCP_CONF لتحديد ملف تكوين بديل، كما هو موضح في pcp.conf(5).

خيارات التصحيح

يتيح الخيار -D أو --debug إخراج تشخيصات إضافية على stderr للمساعدة في تشخيص المشاكل، على الرغم من أن المعلومات غالبًا ما تكون مشفرة ومخصصة في المقام الأول لتوجيه المطورين بدلاً من المستخدمين النهائيين. debug هي قائمة مفصولة بفواصل من خيارات التصحيح؛ استخدم pmdbg(1) مع الخيار -l للحصول على قائمة بخيارات التصحيح المتاحة ومعناها.

خيارات التصحيح الخاصة بـ pmdaoverhead هي كالتالي:

الخيار الوصف
appl0 تحليل configfile
appl1 الطوابع الزمنية لبدء / نهاية refresh()
appl2 اختيار /proc في refresh()

انظر أيضًا

PCPIntro(1)، pmcd(1)، pmdaproc(1)، pcp.conf(5)، pcp.env(5) و PMNS(5).

NAME

pmdaoverhead - Performance Co-Pilot (PCP) metric domain agent for overhead monitoring

SYNOPSIS

$PCP_PMDA_DIR/pmdaoverhead

DESCRIPTION

The pmdaoverhead is a Performance Co-Pilot (PCP) metric domain agent (PMDA) that monitors and exposes performance metrics related to the overhead of collecting metrics within the PCP system itself. It provides insights into the resource consumption (CPU, memory, etc.) of the PCP agents and collectors.

This PMDA is useful for understanding the performance impact of PCP instrumentation and for identifying potential bottlenecks in metric collection.

CONFIGURATION

The pmdaoverhead PMDA typically does not require extensive configuration. It is usually installed and enabled as part of the PCP installation. Any specific configuration options would be documented within the PCP framework or the specific PCP installation guide.

INSTALLATION

The pmdaoverhead PMDA is typically installed as part of the PCP package. No separate installation is usually required. If it needs to be installed or managed manually, refer to the PCP installation and administration documentation.

FILES

This section is usually specific to the installation and may not have a generic entry.

PCP ENVIRONMENT

The behavior of pmdaoverhead can be influenced by various PCP environment variables, such as:

  • $PCP_CONF: Specifies the main PCP configuration file.
  • $PCP_PMCD_PORT: The port used by the Performance Metrics Collector Daemon (PMCD).
  • $PCP_PMDAS_DIR: Directory containing PMDA binaries.

DEBUGGING OPTIONS

To enable debugging for pmdaoverhead, you might need to consult the PCP documentation for PMDA-specific debugging flags or environment variables. This could involve:

  • Setting environment variables like PCP_DEBUG.
  • Running the PMDA in a foreground mode with verbose output.

Refer to the PCP administration manual for detailed debugging procedures.
