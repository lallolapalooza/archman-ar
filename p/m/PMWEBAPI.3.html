PMWEBAPI(3) دليل الوظائف PMWEBAPI(3)

NAME

PMWEBAPI - مقدمة لواجهة برمجة تطبيقات الويب لـ Performance Metrics

HTTP SYNOPSIS

GET /metrics
GET /series/...
GET /search/...
GET /pmapi/...
POST /logger/...

C SYNOPSIS

#include <pcp/pmwebapi.h>

... روتينات متنوعة ...

cc ... -lpcp_web -lpcp

DESCRIPTION

PMWEBAPI هي مجموعة من الواجهات التي تقدم خدمات مقاييس الأداء لتطبيقات الويب. وهي تشمل واجهات برمجة التطبيقات لتطبيقات الويب التي تستعلم وتحلل بيانات المقاييس في الوقت الفعلي والتاريخية، بالإضافة إلى واجهات برمجة التطبيقات المستخدمة بواسطة خوادم الويب.

تنطبق قواعد معلمات HTTP القياسية، وتتبع طلبات PMWEBAPI REST دائمًا الاصطلاح:

/api/endpoint?parameter1=value1&parameter2=value2

تستخدم الأمثلة في الأقسام التالية أداة curl(1) مع خادم محلي pmproxy(1) يستمع على المنفذ 44322 (المنفذ الافتراضي). تُستخدم الأداة المساعدة pmjson(1) لتنسيق أي إخراج JSON بشكل نظيف، على عكس التنسيق المضغوط (بأقل مساحة بيضاء) الافتراضي. تستخدم الأمثلة في قسم السلسلة الزمنية القابلة للتوسع بيانات تاريخية تم تسجيلها بواسطة خدمة pmlogger(1)، جنبًا إلى جنب مع خادم مفتاح-قيمة محلي.

OPEN METRICS AND OPEN TELEMETRY

يتوفر تصدير المقاييس في الوقت الفعلي بتنسيق Open Metrics (https://openmetrics.io) أو بتنسيق Open Telemetry (https://opentelemetry.io).

تُجرى جميع الطلبات على المضيف الافتراضي لخادم الويب، ما لم يتم تحديد معلمة hostspec.

GET /metrics

المعلمات النوع الشرح
names سلسلة نصية قائمة بأسماء المقاييس مفصولة بفواصل
filter سلسلة نصية قائمة بأسماء المقاييس المستبعدة مفصولة بفواصل
match سلسلة نصية وضع المطابقة (exact, glob, or regex)
times قيمة منطقية إرفاق أوقات العينات (مللي ثانية منذ بداية الحقبة)
hostspec سلسلة نصية مخطط المضيف كما هو موصوف في PCPIntro(1)

استرداد القيم الحالية والبيانات الوصفية لجميع المقاييس، أو فقط تلك المشار إليها بواسطة قائمة مفصولة بفواصل من names.

لجميع المقاييس التي تبدأ بالبادئة الرقمية NAME، قم بإنشاء تنسيق إخراج نصي مفتوح يعطي قيمتها الحالية والبيانات الوصفية ذات الصلة.

يتم اختيار تنسيق الإخراج باستخدام رأس HTTP Accept. بدون رأس، يكون التنسيق الافتراضي هو نص Open Metrics. يغير استخدام الرأس بالقيمة application/json الاستجابة إلى تنسيق Open Telemetry JSON.

في وضع استجابة Open Telemetry، يتم دائمًا تضمين أوقات العينات ويتم الإبلاغ عنها بدقة بالنانوثانية.

$ curl -H Accept:application/json -s http://localhost:44322/metrics?names=disk.dev,filesys | pmjson
{
    "resourceMetrics": [
        {
            "resource": {
                "attributes": [ ... ]
            },
            "scopeMetrics": [
                {
                    "scope": { ... },
                    "metrics": [
                        {
                            "name": "disk.dev.total.bytes",
                            "description": "عدد البايتات المقروءة والمكتوبة لكل قرص",
                            "unit": "KiBy",
                            "sum": {
                                "aggregationTemporality": "CUMULATIVE",
                                "isMonotonic": true,
                                "dataPoints": [
                                    {
                                        "attributes": [ ... ]
                                        "timeUnixNano": "1753934255798173",
                                        "asInt": "68927569"
                                    }
                                ]
                            }
                        },
                        ...

في وضع استجابة Open Metrics، يتم عرض البيانات الوصفية الأصلية للمقياس (الاسم، النوع، indom، الدلالة، والوحدات) أولاً لكل مقياس مع البادئة # PCP. البيانات الوصفية المبلغ عنها هي بالشكل الموصوف في pmTypeStr(3)، pmInDomStr(3)، pmSemStr(3) و pmUnitsStr(3) على التوالي. إذا كانت سلسلة الوحدات pmUnitsStr(3) فارغة، يتم عرض none. قد تحتوي سلسلة البيانات الوصفية للوحدات على مسافات وتمتد إلى نهاية السطر.

تتم مطابقة أسماء مقاييس PCP بحيث يتم تبديل الفواصل . بـ _ (: في وضع التوافق، حيث يكون # PCP هو لاحقة الخط التعريفية). يتم تمثيل كل من تسميات المقاييس والمثيلات كتسميات Open Metrics، مع أسماء المثيلات الخارجية بين علامتي اقتباس ونشر هرمية تسمية PCP مع كل قيمة.

عند مطابقة أسماء المقاييس باستخدام خيار filter، يكون الوضع الافتراضي هو المطابقة بنمط النكرة (glob matching). يمكن استخدام خيار match لطلب مطابقة تعبير عادي (regex) أو مطابقة دقيقة للمقاييس.

$ curl -s http://localhost:44322/metrics?names=proc.nprocs,kernel.pernode.cpu.intr,filesys.blocksize
# PCP5 proc.nprocs 3.8.99 u32 PM_INDOM_NULL instant none
# HELP proc_nprocs instantaneous number of processes
# TYPE proc_nprocs gauge
proc_nprocs {hostname="app1"} 7
# PCP5 kernel.pernode.cpu.intr 60.0.66 u64 60.19 counter millisec
# HELP kernel_pernode_cpu_intr total interrupt CPU [...]
# TYPE kernel_pernode_cpu_intr counter
kernel_pernode_cpu_intr{hostname="app1",instname="node0"} 25603
# PCP5 filesys.blocksize 60.5.9 u32 60.5 instant byte
# HELP filesys_blocksize Size of each block on mounted file[...]
# TYPE filesys_blocksize gauge
filesys_blocksize{hostname="app1",instname="/dev/sda1"} 4096
filesys_blocksize{hostname="app1",instname="/dev/sda2"} 4096

SCALABLE TIME SERIES

قدرات الاستعلام عن السلاسل الزمنية السريعة والقابلة للتطوير التي توفرها أداة pmseries(1) متاحة أيضًا عبر واجهة برمجة تطبيقات REST. تسمح هذه الاستعلامات بالوصول إلى بيانات المقاييس (البيانات الوصفية والقيم) من مضيفين متعددين في وقت واحد، بأسلوب مناسب للاسترداد الفعال بواسطة أي عدد من تطبيقات الويب.

يمكن أن تكون جميع الطلبات في هذه المجموعة مصحوبة بمعلمة اختيارية client. يتم إرسال القيمة المارة في الطلب مرة أخرى في الاستجابة - ستكون جميع الاستجابات بتنسيق كائن JSON في هذه الحالة، مع حقول عليا client و result.

يمكن لعملاء REST API اختياريًا إرسال سلسلة استعلام مشفرة بـ URL في نص طلب HTTP، ما لم يُنص على خلاف ذلك. في هذه الحالة، يجب استخدام طريقة POST بدلاً من طريقة GET.

GET /series/ping

اختبار حياة بسيط للعملاء للتحقق مما إذا كان الخادم يعمل ويدعم واجهة برمجة التطبيقات /series.

GET /series/values - pmSeriesValues(3)

المعلمات النوع الشرح
series سلسلة نصية قائمة بمعرفات السلاسل مفصولة بفواصل
client سلسلة نصية معرف الطلب الذي يتم إرجاعه مع الاستجابة
samples رقم عدد العينات المطلوب إرجاعها
interval سلسلة نصية الوقت بين العينات المتتالية
start سلسلة نصية وقت بداية نافذة العينة
finish سلسلة نصية وقت نهاية نافذة العينة
offset سلسلة نصية إزاحة نافذة العينة
align سلسلة نصية محاذاة وقت العينة
zone سلسلة نصية المنطقة الزمنية لنافذة الوقت

يقوم باسترداد القيم لواحدة أو أكثر من معرفات السلاسل الزمنية. يحتوي استجابة JSON على نفس المعلومات التي يوفرها خيار pmseries -q/--query باستخدام أي من معلمات النطاق الزمني الموصوفة في pmseries(1). إذا لم يتم تحديد أي معلمات للنطاق الزمني، يتم استرداد أحدث عينة فردية.

$ curl -s http://localhost:44322/series/values?series=605fc77742cd0317597291329561ac4e50c0dd12 | pmjson
[
  {
    "series": "605fc77742cd0317597291329561ac4e50c0dd12",
    "timestamp": 1317633022959.959241041,
    "value": "71660"
  }
]

GET /series/labels - pmSeriesLabels(3), pmSeriesLabelValues(3)

المعلمات النوع الشرح
series سلسلة نصية قائمة بمعرفات السلاسل مفصولة بفواصل
match سلسلة نصية سلسلة نمط glob للمطابقة على جميع التسميات
name سلسلة نصية البحث عن جميع القيم المعروفة للتسمية للاسم المحدد
names سلسلة نصية قائمة بأسماء التسميات مفصولة بفواصل
client سلسلة نصية معرف الطلب الذي يتم إرجاعه مع الاستجابة

يعمل هذا الأمر في أحد ثلاثة أوضاع. يمكنه إجراء بحث عن مجموعة تسميات لواحد أو أكثر من معرفات السلاسل الزمنية (عند توفير معلمة series). يمكنه إنتاج قائمة بجميع أسماء التسميات المعروفة، في غياب المعلمات name أو names أو series. تحتوي استجابات JSON لهذه الأوضاع على نفس المعلومات التي يوفرها خيار pmseries -l/--labels.

بدلاً من ذلك، يمكنه إنتاج قائمة بجميع القيم المعروفة للتسمية لاسم تسمية أو أسماء تسميات معينة. تحتوي استجابة JSON لهذا الوضع على نفس المعلومات التي يوفرها خيار pmseries -v/--values.

Proporciona todas las entidades (instancias, métricas) relacionadas con indom, incluyéndose a sí mismo, que se envían al servidor a través del parámetro query.

خدمات المضيف PMAPI

يمكن الوصول إلى خدمات تقديم العروض الحية المتاحة عبر pmcd(1) أيضًا عبر واجهة برمجة تطبيقات REST.

تُجرى جميع الطلبات على الخادم الافتراضي، ما لم يتم استخدام hostspec أو context في الطلب. يمكن استخدام hostname بدلاً من hostspec.

تُستخدم معرفات السياق كطريقة دائمة للإشارة إلى سياقات PMAPI في طلبات الويب ذات الصلة. تنتهي صلاحية هذه السياقات بعد فترة محددة من عدم النشاط، ويتم تعيينها بشكل صريح عبر الواجهة /pmapi/context، أو ضمنيًا عبر الواجهات الأخرى.

يمكن تكوين مهلة الوقت عند إنشاء السياق، لذلك يمكن استخدام المعلمة polltimeout في أي طلب يتم فيه تحديد hostspec. تحدد هذه المعلمة مهلة السياق من حيث عدم النشاط. وحدة قيمة المهلة هي ثوانٍ والقيمة الافتراضية هي 5.

لتحديد سياق موجود في أي طلب PMAPI، يمكن الوصول إلى نقاط النهاية باستخدام المعلمة context أو تضمينها في عنوان URL لنقطة النهاية، مثل /pmapi/[number]/fetch.

pmwebapi(3)

الاسم

pmwebapi - واجهة برمجة تطبيقات الويب لـ Performance Co-Pilot

ملخص HTTP

GET /?names=cpu.user&hosts=localhost&from=1678878341&until=1678879341
GET /?names=cpu.user&hosts=localhost&interval=1000

ملخص C

#include <pcp/pmapi.h>
#include <pcp/pmwebapi.h>

int pmwebapi_request(const char *host, pmRequest *req, pmResult **res);

الوصف

تتيح واجهة برمجة تطبيقات الويب لـ PCP (Performance Co-Pilot) استرداد بيانات الأداء من مضيف واحد أو أكثر عبر بروتوكول HTTP. تستخدم هذه الواجهة التنسيق القياسي لـ PMAPI لتحديد المقاييس المطلوبة، والنطاقات الزمنية، والمضيفين.

المقاييس المفتوحة والقياس عن بعد المفتوح

تدعم واجهة برمجة تطبيقات الويب لـ PCP أيضًا تنسيقات Open Metrics و Open Telemetry، مما يتيح التكامل مع أدوات المراقبة الحديثة.

سلاسل زمنية قابلة للتطوير

تم تصميم واجهة برمجة تطبيقات الويب لـ PCP لتكون قابلة للتطوير، مع القدرة على التعامل مع كميات كبيرة من البيانات والاستعلامات المعقدة.

بحث النص الكامل

تسمح واجهة برمجة تطبيقات الويب لـ PCP بإجراء عمليات بحث في النص الكامل على المقاييس والبيانات الوصفية، مما يسهل العثور على المعلومات المطلوبة.

خدمات المضيف PMAPI

تعمل واجهة برمجة تطبيقات الويب لـ PCP كواجهة لخدمات المضيف PMAPI، مما يوفر وصولاً موحدًا إلى بيانات الأداء عبر الشبكة.

خطاف الويب للأرشيف - LOGARCHIVE(5)

تدعم واجهة برمجة تطبيقات الويب لـ PCP أيضًا خطاف الويب للأرشيف، مما يسمح بتشغيل إجراءات مخصصة عند إنشاء أو تعديل ملفات الأرشيف.

ملاحظات

تتطلب واجهة برمجة تطبيقات الويب لـ PCP تشغيل خادم الويب لـ PCP (pmwebd) على المضيف الهدف.
