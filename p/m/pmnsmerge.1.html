pmnsmerge(1)

الحزمة: pcp

التراخيص: GPL-2.0-or-later, LGPL-2.1-or-later, CC-BY-3.0

PMNSMERGE(1) دليل الأوامر العامة PMNSMERGE(1)

الاسم

pmnsmerge - دمج إصدارات متعددة من مساحة أسماء مقاييس الأداء (PMNS) الخاصة بـ Performance Co-Pilot

الملخص

$PCP_BINADM_DIR/pmnsmerge [-adfxv] [-D debug] infile [...] outfile

الوصف

يقوم pmnsmerge بدمج مثيلات متعددة لمساحة أسماء مقاييس الأداء (PMNS)، كما تستخدمها مكونات Performance Co-Pilot (PCP).

يسمي كل وسيط infile ملفًا يتضمن جذر PMNS، بالشكل


root {
    /* تعسفي */
}

يتم تحديد الترتيب الذي يتم به معالجة ملفات infile حسب وجود أو عدم وجود أسطر تحكم مضمنة بالشكل

#define _DATESTAMP YYYYMMDD

يتم معالجة الملفات التي لا تحتوي على سطر تحكم أولاً وبالترتيب الذي تظهر به في سطر الأوامر. ثم يتم معالجة الملفات الأخرى بترتيب تصاعدي لـ _DATESTAMP.

الخيار -a يمنع إعادة ترتيب الوسائط ويعالج جميع الملفات بالترتيب الذي تظهر به في سطر الأوامر.

يتم الدمج عن طريق مطابقة الأسماء في PMNS، حيث يتم النظر فقط في الأسماء **الجديدة** في كل PMNS، ويتم إضافتها بعد أي مقاييس موجودة ذات أطول بادئة مطابقة ممكنة في أسمائها. على سبيل المثال، دمج ملفات PMNS الإدخالية هذين


root {                    root {
                              surprise  1:1:3
    mine       1:1:1          mine      1:1:1
    foo                       foo
                              yawn
    yours      1:1:2
}                         }
foo {                     foo {
    fumble     1:2:1
                              mumble    1:2:3
    stumble    1:2:2          stumble   1:2:2
}                         }
                          yawn {
                              sleepy    1:3:1
                          }

ينتج عنه PMNS الناتج في out.


root {
    mine      1:1:1
    foo
    yours     1:1:2
    surprise  1:1:3
    yawn
}
foo {
    fumble    1:2:1
    stumble   1:2:2
    mumble    1:2:3
}
yawn {
    sleepy    1:3:1
}

لتجنب الكتابة فوق ملفات PMNS عن طريق الخطأ، يُتوقع أن لا يكون outfile موجودًا عند بدء pmnsmerge. يسمح الخيار -f بإلغاء ربط outfile موجود (إن أمكن) واقتطاعه قبل بدء الكتابة.

عادةً ما يُسمح بأسماء مكررة لنفس معرف مقياس الأداء (PMID) في PMNS. الخيار -d هو الخيار الافتراضي وهو مدرج للتوافق مع الإصدارات السابقة. يعكس الخيار -x** الافتراضي، وسيقوم **pmnsmerge بالإبلاغ عن خطأ والخروج بحالة غير صفرية إذا تم العثور على اسم مكرر لـ PMID في أي من ملفات input PMNS أو في PMNS output المدمج.

ينتج الخيار -v سطرًا واحدًا من إخراج التشخيص مع معالجة كل infile.

بمجرد اكتمال جميع عمليات الدمج، سيحاول pmnsmerge تحميل مساحة الأسماء الناتجة باستخدام pmLoadASCIINameSpace(3) - إذا فشل هذا لأي سبب، سيظل outfile يتم إنشاؤه، ولكن pmnsmerge سيبلغ عن المشكلة ويخرج بحالة غير صفرية.

استخدام pmnsmerge** مع وسيط input* واحد يسمح بالتحقق من ملف PMNS هذا. بالإضافة إلى التحقق النحوي، سيؤدي تحديد **-x** أيضًا إلى تمكين التحقق من الأسماء المكررة لجميع معرفات PMIDs.

الخيارات

الخيارات المتاحة لسطر الأوامر هي:

-a
معالجة الملفات بترتيب سطر الأوامر.
-d, --dupok
السماح بأسماء مقاييس مكررة لكل PMID. هذا هو الافتراضي.
-f, --force
الكتابة فوق ملف الإخراج إذا كان موجودًا بالفعل.
-v, --verbose
معالجة إدخال مفصلة.
-x, --nodups
عدم السماح بأسماء مقاييس مكررة لكل PMID.
-?, --help
عرض رسالة الاستخدام والخروج.

تحذيرات

بمجرد بدء كتابة ملف outfile الجديد، سيتم تجاهل الإشارات SIGINT و SIGHUP و SIGTERM لحماية سلامة الملف الجديد.

بيئة PCP

تُستخدم متغيرات البيئة التي تحمل البادئة PCP_ لتحديد أسماء الملفات والمجلدات التي تستخدمها PCP. في كل تثبيت، يحتوي الملف /etc/pcp.conf على القيم المحلية لهذه المتغيرات. يمكن استخدام المتغير $PCP_CONF لتحديد ملف تكوين بديل، كما هو موضح في pcp.conf(5).

خيارات التصحيح

يمكّن الخيار -D** أو **--debug** إخراج تشخيصات إضافية على stderr للمساعدة في تصنيف المشاكل، على الرغم من أن المعلومات تكون أحيانًا غامضة ومخصصة بشكل أساسي لتوفير التوجيه للمطورين بدلاً من المستخدمين النهائيين. debug هي قائمة مفصولة بفواصل من خيارات التصحيح؛ استخدم pmdbg(1) مع الخيار -l** للحصول على قائمة بخيارات التصحيح المتاحة ومعناها.
