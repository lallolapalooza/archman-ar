NAME

pmlogger - إنشاء أرشيف لمقاييس الأداء

SYNOPSIS

pmlogger [-CLNoPruy?] [-c conffile] [-D debug] [-d directory] [-h host] [-H hostname] [-I version] [-K spec] [-l logfile] [-m note] [-n pmnsfile] [-p pid] [-s endsize] [-t interval] [-T endtime] [-U username] [-v volsize] [-V version] [-x fd] [archive]

DESCRIPTION

يقوم pmlogger بإنشاء أرشيفات لقيم مقاييس الأداء التي يمكن "تشغيلها" بواسطة أدوات Performance Co-Pilot (PCP) الأخرى (انظر PCPIntro(1)). تشكل هذه السجلات أساس نموذج الفيديو (VCR) وخدمات تحليل الأداء الاستعادية الشائعة في مجموعة أدوات PCP.

الوسيط الإلزامي archive هو إما الاسم الأساسي للملفات المادية التي تشكل أرشيفًا على نظام الملفات المحلي، أو خادم HTTP البعيد الذي سيتلقى البيانات المسجلة.

قد يحتوي الوسيط المحلي archive على أحرف تعريف وصفية لـ strftime(3)، والتي سيتم استبدالها قبل إنشاء ملفات الأرشيف. عندما يتم تشغيل pmlogger كخدمة (انظر pmlogger_daily(1))، فإن قالب اسم الأرشيف الأساسي القياسي هو %Y%m%d.%H.%M.

يشير شكل archive البعيد إلى موقع خادم pmproxy(1) الذي سيتم إرسال مكونات الأرشيف إليه أثناء إنشائها بواسطة pmlogger. يجب أن يحتوي القيمة المقدمة على البروتوكول واسم المضيف والمنفذ الاختياري، على سبيل المثال http://example.com:44322. سيختار خادم pmproxy هذا اسم أرشيف بناءً على وقت البدء، بطريقة مشابهة للنموذج المستخدم افتراضيًا في pmlogger_check(1).

يحدد الخيار -V الإصدار الخاص بالأرشيف الذي تم إنشاؤه. افتراضيًا، يتم استخدام إصدار الأرشيف $PCP_ARCHIVE_VERSION (المعيّن إلى 3 في إصدارات PCP الحالية)، والقيم الوحيدة المدعومة حاليًا لـ version هي 2 أو 3.

ما لم يتم توجيهه إلى مضيف آخر بواسطة الخيار -h أو عند استخدام PMDAs مباشرةً عبر الخيار -o، سيتصل pmlogger بـ خادم جمع مقاييس الأداء (PMCD) على المضيف المحلي ويستخدمه كمصدر لقيم المقاييس التي سيتم تسجيلها.

لدعم المرونة والتحكم المطلوبين فيما يتم تسجيله ومتى، يحتفظ pmlogger بحالة تسجيل مستقلة من مستويين لكل مثيل من كل مقياس أداء. في المستوى الأول (الإلزامي)، يُسمح بالتسجيل بأن يكون قيد التشغيل (مع فاصل زمني مرتبط بين العينات)، أو متوقف، أو ربما. في الحالة الأخيرة، يُسمح لمستوى التسجيل الثاني (الإرشادي) بأن يكون قيد التشغيل (مع فاصل زمني مرتبط بين العينات)، أو متوقف.

يسمح المستوى الإلزامي بالتحديد الشامل بأن بعض المقاييس يجب تسجيلها، أو يجب عدم تسجيلها. الحالة الافتراضية لجميع مثيلات جميع المقاييس عند بدء تشغيل pmlogger هي "ربما" إلزامي وإيقاف إرشادي.

استخدم pmlc(1) للاستعلام وتغيير حالة التسجيل بمجرد تشغيل pmlogger.

إذا كانت حالة المقياس إلزامية (قيد التشغيل أو متوقف) وتم إجراء طلب لتغييرها إلى "ربما" إلزامي، فإن الحالة الجديدة هي "ربما" إلزامي وإيقاف إرشادي. إذا كانت حالة المقياس إرشادية بالفعل (قيد التشغيل أو متوقف) وتم إجراء طلب لتغييرها إلى "ربما" إلزامي، فسيتم الاحتفاظ بالحالة الحالية.

ليس من الممكن لـ pmlogger تسجيل مثيلات محددة لمقياس ومثيلات جميع المقاييس في نفس الوقت. إذا كان يتم تسجيل مثيلات محددة وتم إجراء طلب لتسجيل جميع المثيلات، فسيتم تسجيل جميع مثيلات المقياس وفقًا للطلب الجديد، مما يلغي أي طلب تسجيل سابق للمقياس. سيؤدي طلب تسجيل جميع مثيلات المقياس إلى إلغاء أي طلب سابق لتسجيل جميع المثيلات. يتم رفض طلب تسجيل مثيلات محددة لمقياس عندما تكون جميع المثيلات مسجلة بالفعل. للقيام بذلك، يجب إيقاف التسجيل لجميع مثيلات المقياس أولاً. في كل حالة، يتم التحقق من صحة الطلب أولاً؛ على سبيل المثال، طلب تغيير حالة تسجيل مقياس إلى إرشادي قيد التشغيل عندما يكون حاليًا إلزاميًا متوقفًا غير مسموح به أبدًا (من الضروري تغيير الحالة إلى "ربما" إلزامي أولاً).

اختياريًا، يمكن تكوين كل نظام يشغل pmcd(1) لتشغيل نسخة "أساسية" من pmlogger. يتم تشغيل نسخة pmlogger هذه بواسطة $PCP_RC_DIR/pmlogger، وتتأثر بالملفات $PCP_SYSCONF_DIR/pmlogger/control، $PCP_SYSCONF_DIR/pmlogger/control.d/* (استخدم chkconfig(8)، systemctl(1) أو أوامر أخرى خاصة بالنظام لتنشيط أو تعطيل نسخة pmlogger الأساسية)، $PCP_SYSCONFIG_DIR/pmlogger (إعدادات متغيرات البيئة لـ pmlogger الأساسي)، $PCP_SYSCONF_DIR/pmlogger/pmlogger.options (خيارات سطر الأوامر التي تم تمريرها إلى pmlogger الأساسي) و $PCP_VAR_DIR/config/pmlogger/config.default (ملف التكوين الأولي الافتراضي لـ pmlogger الأساسي).

يتم تحديد نسخة pmlogger الأساسية بواسطة الخيار -P. يمكن أن يكون هناك نسخة "أساسية" واحدة على الأكثر من pmlogger على كل نظام. يجب تشغيل نسخة pmlogger الأساسية (إن وجدت) على نفس المضيف الذي يتصل به pmcd(1) (إن وجد)، لذلك الخياران -h و -P متعارضان.

من الممكن تسجيل بعض المقاييس حتى في غياب pmcd(1) محلي، باستخدام وضع تشغيل "السياق المحلي". يتم تنشيط هذا باستخدام الخيار -o، ويؤدي إلى استخدام pmlogger لـ PMDAs الخاصة بـ DSO بدلاً من الاتصال بـ pmcd(1). عند العمل باستخدام سياق محلي، يمكن استخدام الخيار -K للتحكم في PMDAs الخاصة بـ DSO التي يجب جعلها متاحة. يتوافق الوسيط spec مع بناء الجملة الموضح في pmSpecLocalPMDA(3). يمكن استخدام أكثر من خيار -K واحد.

عند التشغيل كنسخة غير أساسية، سيخرج pmlogger فورًا إذا لم يتسبب ملف التكوين في جدولة أي تسجيل للمقاييس. يتجاوز الخيار -L هذا السلوك، ويتسبب في "بقاء" نسخة pmlogger غير الأساسية، ربما في انتظار أي إعادة تكوين ديناميكي مستقبلي وتغيير للحالة عبر pmlc(1). سيبقى pmlogger أيضًا بدون استخدام الخيار -L إذا تم تسجيل جميع المقاييس المراد تسجيلها كمقاييس مرة واحدة فقط. عند تسجيل مقاييس المرة الواحدة، سيتم إنشاء رسالة تحذير تفيد بأن قائمة الأحداث فارغة ولن يتم جدولة المزيد من الأحداث.

افتراضيًا، تتم كتابة جميع التشخيصات والأخطاء من pmlogger إلى الملف pmlogger.log في الدليل الذي يتم فيه تشغيل pmlogger. يمكن استخدام الخيار -l لتجاوز السلوك الافتراضي. إذا لم يكن من الممكن إنشاء ملف السجل أو لم يكن قابلاً للكتابة، تتم كتابة الإخراج إلى الخطأ القياسي بدلاً من ذلك. إذا كان ملف السجل logfile الخاص بالخيار -l هو "-" (أي -l-) فسيتم كتابة رسائل السجل إلى مجرى الإخراج القياسي. يمكن أن يكون هذا مفيدًا بشكل خاص عند تشغيل pmlogger يدويًا، بدلاً من كخدمة خادمة.

يوجه الخيار -N pmlogger لإخطار مدير الخدمة، عادةً systemd(1)، عندما يبدأ ويوشك على البدء في كتابة أرشيفات PCP. لا يُستخدم هذا الخيار عادةً إلا عندما يتم تشغيل pmlogger كخدمة خادمة تحت سيطرة مدير الخدمة. لمزيد من التفاصيل، انظر __pmServerNotifyServiceManagerReady(3) و systemd(1). على الأنظمة التي لا تستخدم مدير خدمة يدعم الإشعارات، يعتبر الخيار -N في الأساس لا يقوم بأي شيء.

إذا تم تحديده، فإن الخيار -s يوجه pmlogger إلى الإنهاء بعد تراكم حجم معين من السجلات أو البايتات أو وحدات الوقت. إذا كان endsize عددًا صحيحًا، فسيتم كتابة endsize سجل إلى الأرشيف. إذا كان endsize عددًا صحيحًا متبوعًا بـ b أو bytes، فسيتم كتابة endsize بايت من بيانات الأرشيف (لاحظ، ومع ذلك، أن حدود سجل الأرشيف لن يتم كسرها، وقد يتم تجاوز هذا الحد قليلاً). تشمل وحدات حجم الملفات الصالح الأخرى: K، Kb، KiB، Kbyte، Kilobyte للكيلوبايت و M، Mb، MiB

/b>، Mbyte، Megabyte للميجابايت، وG،Gb، GiB،Gbyte،Gigabyte للجيجابايت. قد تُتبع هذه الوحدات اختياريًا بحرف s وقد تكون بأحرف مختلطة. بدلاً من ذلك، قد يكون *endsize* عددًا صحيحًا أو رقمًا عشريًا متبوعًا بوحدة زمنية كما هو موضح في PCPIntro(1) بالنسبة للوسيط *interval* (لخيار سطر الأوامر القياسي لـ PCP **-t**).

بعض الأمثلة للتنسيقات المختلفة:
-s 100
-s 100bytes
-s 100K
-s 100Mb
-s 10Gbyte
-s 10mins
-s 1.5hours
الافتراضي هو أن **pmlogger** يعمل إلى الأبد.

يتسبب الخيار **-r** في الإبلاغ عن حجم السجلات المادية لكل مجموعة من المقاييس والمساهمة المتوقعة للمجموعة في حجم أرشيف PCP ليوم كامل من التجميع في ملف السجل. يتم الإبلاغ عن هذه المعلومات في المرة الأولى التي تتم فيها كتابة كل مجموعة بنجاح إلى الأرشيف.

يحدد الخيار **-U** حساب المستخدم الذي سيتم تشغيل **pmlogger** بموجبه. الافتراضي هو حساب المستخدم الحالي للاستخدام التفاعلي. عند التشغيل كخدمة، يتم استخدام حساب "pcp" غير المميز في الإصدارات الحالية من PCP، ولكن في الإصدارات القديمة كان يتم استخدام حساب المستخدم الخارق ("root") افتراضيًا.

قد يكون الأرشيف مجموعة بيانات متعددة وحدات، ويتسبب الخيار **-v** في قيام **pmlogger** ببدء وحدة جديدة بعد تجميع حجم معين بالسجلات أو البايتات أو وحدات الوقت للوحدة الحالية. تنسيق تحديد هذا الحجم مطابق لتنسيق الخيار **-s** (انظر أعلاه). الافتراضي هو أن **pmlogger** ينشئ أرشيفًا بوحدة واحدة. يمكن أيضًا فرض تبديلات وحدات إضافية بشكل غير متزامن إما باستخدام pmlc(1) أو بإرسال إشارة SIGHUP إلى **pmlogger** (انظر أدناه). لاحظ، إذا كان تبديل وحدة مجدول قيد التشغيل بسبب الخيار **-v**، فسيتم إعادة تعيين عداداته بعد تبديل غير متزامن.

بشكل مستقل عن أي خيار **-v**، يتم تحديد حجم كل وحدة في الأرشيف بما لا يزيد عن 2^31 بايت، لذا سيقوم *pmlogger* تلقائيًا بإنشاء وحدة جديدة للأرشيف قبل الوصول إلى هذا الحد.

عادةً ما يعمل **pmlogger** على مساحة اسم مقاييس الأداء الموزعة (PMNS)، ومع ذلك، إذا تم تحديد الخيار **-n**، يتم تحميل مساحة اسم PMNS محلية بديلة من الملف *pmnsfile*.

في الظروف العادية، سيعمل **pmlogger** إلى الأبد (باستثناء خيار **-s** أو إشارة إنهاء). يمكن استخدام الخيار **-T** لتحديد وقت التنفيذ باستخدام تنسيق الوقت المحدد في PCPIntro(1). يتم تفسير الوقت ضمن المنطقة الزمنية لخادم PMCD، إلا إذا تم إعطاء الخيار **-y**، وفي هذه الحالة يتم استخدام المنطقة الزمنية في مضيف المسجل هذا.

بعض الأمثلة للتنسيقات المختلفة:
-T 10mins
-T '@ 11:30'
من هذا يتضح أن **-T 10mins** و **-s 10mins** تؤديان إجراءات متطابقة.

بدلاً من ذلك، يمكن تحديد مدة تشغيل **pmlogger** لعمر عملية أخرى باستخدام الخيار **-p** أو **--PID** لتحديد معرف العملية (PID) للعملية المعنية. في هذه الحالة، سيخرج **pmlogger** عندما تختفي العملية الأخرى.

عندما يتلقى **pmlogger** إشارة SIGHUP، يتم إغلاق الوحدة الحالية للأرشيف، ويتم فتح وحدة جديدة. يمكن استخدام هذه الآلية (أو الآلية البديلة عبر pmlc(1)) لإدارة نمو ملفات الأرشيف - بمجرد إغلاق وحدة سجل، يمكن أرشفة هذا الملف دون التأثير سلبًا على التشغيل المستمر لـ **pmlogger**. انظر أيضًا الخيار **-v** أعلاه.

عندما يتلقى **pmlogger** إشارة SIGUSR2، يتم إغلاق الأرشيف الحالي، ويتم فتح أرشيف جديد. لكي ينجح هذا، يجب أن يتضمن الوسيط *archive* الأصلي أحرف تعريف التنسيق strftime(3) (مثل **%Y%m%d.%H.%M**)، وإلا فسيخرج **pmlogger** لأن ملفات الأرشيف موجودة بالفعل ولن يقوم **pmlogger** بالكتابة فوق ملفات الأرشيف الموجودة. لاحظ أن SIGUSR2 يؤدي إلى قيام **pmlogger** بإعادة تنفيذ نفسه وإعادة تحليل جميع الوسائط الأصلية. هذا يعني أن أي حدود زمنية نسبية مفروضة على وقت إنهاء أو حد أخذ العينات يتم إعادة تعيينها وتبدأ من جديد. يؤثر هذا فقط على أوقات الإنهاء النسبية، وليس الأوقات المطلقة، على سبيل المثال، يتأثر **-T 5s**، ولكن **-T 5pm** لا يتأثر.

تاريخيًا، يمكن مسح المخازن المؤقتة للأرشيف الحالي على القرص باستخدام أمر *flush* الخاص بـ pmlc(1)، أو باستخدام الخيار **-u**. الإصدار الحالي من *pmlogger* والروتينات *libpcp* التي تدعم *pmlogger* تستخدم بشكل غير مشروط كتابات غير مخزنة مؤقتًا وكتابة واحدة fwrite(3) لكل سجل منطقي مكتوب، وبالتالي فإن "المسح" لا يجبر على كتابة أي بيانات إضافية إلى نظام الملفات. يتم الاحتفاظ بالخيار **-u** وأمر *flush* الخاص بـ pmlc(1) للتوافق مع الإصدارات السابقة.

عند تشغيله بالخيار **-x**، سيقبل pmlogger طلبات تحكم غير متزامنة على واصف الملف *fd*. من المتوقع استخدام هذا الخيار داخليًا فقط من قبل تطبيقات PCP التي تدعم "وضع السجل المباشر".

يسمح الخيار **-m** بإلحاق السلسلة *note* بملف الخريطة لهذا المثيل من **pmlogger** في الدليل **$PCP_TMP_DIR/pmlogger**. يتم استخدامه حاليًا داخليًا لتوثيق واصف الملف (*fd*) عند استخدام الخيار **-x**، أو للإشارة إلى أن هذا المثيل من **pmlogger** قد بدأ تحت سيطرة pmlogger_check(1) ( **-m pmlogger_check** ) أو تم إعادة تنفيذه (انظر execvp(3) ) بسبب استلام إشارة SIGUSR2 كما هو موضح أعلاه ( **-m reexec** ).

يسمح الخيار **-H** بتجاوز اسم المضيف المكتوب في تسمية الأرشيف. هذا يعكس الخيار **-H** الخاص بـ pmcd(1)، ولكنه يسمح بتحديده على عملية **pmlogger**. بدون هذا الخيار، يتم استخدام القيمة المرجعة من PMCD المسجل.

سيؤدي الخيار **-C** إلى تحليل ملف التكوين وسيخرج *pmlogger* بعد ذلك دون إنشاء أرشيف إخراج، لذلك عندما يتم تحديد **-C**، لا يلزم الوسيط *archive* لسطر الأوامر. يتم الإبلاغ عن أي أخطاء في ملف التكوين.

يمكن استخدام الخيار **-d** أو **--directory** لتحديد الدليل الذي يجب إنشاء *archive* فيه. قد يتضمن *directory* رموز sh مثل **$(**...**)** أو **`**...**`** أو **$** *var* وسيقوم **pmlogger** بتوسيعها لإنتاج مسار دليل نهائي. يجب أن يكون المسار الناتج مطلقًا، وليس نسبيًا. الخيار **-d** مخصص بشكل أساسي للاستخدام بواسطة pmlogger_check(1) ولن يحتاج المستخدمون العاديون عادةً إلى استخدام الخيار، حيث يتم استنتاج الدليل الخاص بـ *archive* إما من *archive* إذا كان يحتوي على مكونات دليل وإلا يكون الدليل الحالي افتراضيًا.

تنسيق ملف التكوين

يمكن تحديد ملف التكوين باستخدام الخيار **-c**. إذا لم يكن الأمر كذلك، يتم قراءة مواصفات التكوين من الإدخال القياسي.

إذا لم يكن *conffile* موجودًا، فسيتم البحث في الدليل **$PCP_VAR_DIR/config/pmlogger** عن ملف بنفس الاسم، وإذا تم العثور عليه، يتم استخدام هذا الملف، على سبيل المثال، إذا لم يكن *config.mumble* موجودًا في الدليل الحالي وكان الملف **$PCP_VAR_DIR/config/pmlogger/config.mumble** موجودًا، فإن **-c config.mumble** و **-c $PCP_VAR_DIR/config/pmlogger/config.mumble** متكافئان.

تنسيق ملف التكوين كما يلي.

1.
يتم فصل الكلمات بمسافات بيضاء (مسافة، علامة جدولة، أو سطر جديد).
2.
الرمز "#" (هاش) يقدم تعليقًا، ويتم تجاهل كل النص حتى السطر الجديد التالي.
3.
يجب أن تظهر الكلمات المفتاحية (المعروضة بالخط العريض أدناه) حرفيًا (أي بالأحرف الصغيرة).
4.
يبدأ كل تحديد بالكلمة المفتاحية الاختيارية **log**، متبوعة بواحدة من الحالات: **mandatory on**، **mandatory off**، **mandatory maybe**، **advisory on**، أو **advisory off**.
5.
بالنسبة للحالات **on**، يجب أن يتبع فاصل زمني للتسجيل باستخدام تنسيق "**once**"، أو "**default**"، أو "**every** *N timeunits*"، أو ببساطة "*N timeunits*" - *N* هو عدد صحيح غير موقع، و*timeunits* هي واحدة من الكلمات المفتاحية **msec**، **millisecond**، **sec**، **second**، **min**، **minute**، **hour**، أو الشكل الجمعي لأحد ما سبق.

تتطلب القيود الداخلية أن يكون الفاصل الزمني أصغر من (تقريبًا) 74 ساعة. قيمة الفاصل الزمني صفر مرادفة لـ **once**. الفاصل الزمني **default** يعني استخدام فاصل التسجيل الافتراضي البالغ 60 ثانية؛ يمكن تغيير هذه القيمة الافتراضية إلى *interval* باستخدام خيار سطر الأوامر **-t**.

يتبع الوسيط *interval* التنسيق الموضح في PCPIntro(1)، وفي أبسط أشكاله قد يكون عددًا صحيحًا غير موقع (الوحدات الضمنية في هذه الحالة هي ثوانٍ).
6.
بعد تحديد الحالة والفاصل الزمني المحتمل، تأتي "{"، متبوعة بقائمة من مواصفات مقياس واحد على الأقل و"}" مغلقة. يتم فصل القائمة بمسافات بيضاء (أو فاصلة). إذا كان هناك مواصفات مقياس واحدة فقط في القائمة، فإن الأقواس اختيارية.
7.
تتكون مواصفات المقياس من اسم المقياس متبوعًا اختياريًا بمجموعة من أسماء المثيلات. يتبع اسم المقياس اتفاقيات تسمية PCP القياسية، انظر PMNS(5)، وإذا كان اسم المقياس عقدة غير ورقية في PMNS (انظر PMNS(5))، فسيقوم **pmlogger** بالنزول بشكل متكرر في PMNS وتطبيق مواصفات التسجيل على جميع أسماء المقاييس الفرعية التي هي عقد ورقية في PMNS. مجموعة أسماء المثيلات هي "[", متبوعة بقائمة من اسم واحد أو أكثر، أرقام، أو سلاسل مفصولة بمسافات (أو فواصل)، و"]" مغلق. تعتبر العناصر في القائمة التي هي أرقام معرفات مثيلات داخلية، وتعتبر العناصر الأخرى معرفات مثيلات خارجية - انظر pmGetInDom(3) لمزيد من المعلومات.

إذا لم يتم تقديم أي مثيلات، فسيتم تطبيق مواصفات التسجيل على جميع مثيلات المقياس المرتبط.

8.
قد يكون هناك عدد تعسفي من مواصفات التسجيل.
9.
اعتبارًا من إصدار PCP 4.0 والإصدارات الأحدث، أي مواصفات اسم مقياس لا تُحل إلى عقدة ورقية في PMNS يتم إضافتها إلى قائمة داخلية

PMDAs can dynamically create new metrics below a dynamic root node in their PMNS, and send a notification to clients that the PMNS has changed, see pmdaExtSetFlags(3) and in particular the METRIC CHANGES section for API details. This mechanism is currently supported by pmdaopenmetrics(1) and pmdammv(1). When a fetch issued by pmlogger returns with the PMDA_EXT_NAMES_CHANGE flag set, pmlogger will traverse the internal list of possible dynamic subtree nodes and dynamically discover any new metrics. In effect, as of PCP version 4.0 and later, pmlogger can be configured to dynamically log new metrics that appear in the future, after the configuration file is initially parsed.
10.
Following all of the logging specifications, there may be an optional access control section, introduced by the literal token [access]. Thereafter come access control rules that allow or disallow operations from particular hosts or groups of hosts.

The operations may be used to interrogate or control a running pmlogger using pmlc(1) and fall into the following classes:

enquire
interrogate the status of pmlogger and the metrics it is logging
advisory
Change advisory logging.
mandatory
Change mandatory logging.
all
All of the above.

Access control rules are of the form ``allow hostlist : operationslist ;'' and ``disallow hostlist : operationslist ;''.

The hostlist follows the syntax and semantics for the access control mechanisms used by PMCD and are fully documented in pmcd(1). An operationslist is a comma separated list of the operations advisory, mandatory, enquire and all.

A missing [access] section allows all access and is equivalent to allow * : all;.

The configuration (either from standard input or conffile) is initially scanned by pmcpp(1) with the options -rs and -I $PCP_VAR_DIR/config/pmlogger. This extends the configuration file syntax with include file processing (%include), a common location to search for include files ($PCP_VAR_DIR/config/pmlogger), macro definitions (%define), macro expansion (%name and %{name}) and conditional inclusion of lines (%ifdef name ... %else ... %endif and %ifndef name ... %else ... %endif).

OPTIONS

The available command line options are:

-c conffile, --config=conffile
Specify the conffile file to use.
-C, --check
Parse configuration and exit.
-h host, --host=host
Fetch performance metrics from pmcd(1) on host, rather than from the default localhost.
-H hostname, --labelhost=hostname
Specify the hostname to use instead of the one returned by pmcd(1).
-I version, --pmlc-ipc-version=version
Normally, pmlogger and pmlc(1) will autonegotiate a mutually acceptable version for their private IPC channel. Use -I to force pmlogger to offer (at most) version as the version to be used. This option may be required if pmlogger needs to be managed by an older version of pmlc(1) that fails to autonegotiate correctly.
-K spec, --spec-local=spec
When fetching metrics from a local context (see -o), the -K option may be used to control the DSO PMDAs that should be made accessible. The spec argument conforms to the syntax described in pmSpecLocalPMDA(3). More than one -K option may be used.
-l logfile, --log=logfile
Write all diagnostics to logfile instead of the default pmlogger.log.
-L, --linger
Run even if not the primary logger instance and nothing to log.
-m note, --note=note
Append note to the port map file for this instance.
-n pmnsfile, --namespace=pmnsfile
Load an alternative Performance Metrics Name Space (PMNS(5)) from the file pmnsfile.
-N, --notify
Notify service manager such as systemd(1) as needed.
-o, --local-PMDA
Use a local context to collect metrics from DSO PMDAs on the local host without PMCD. See also -K.
-p PID, --PID=PID
Log specified metrics for the lifetime of the process identified by PID.
-P, --primary
Run as primary logger instance. See above for more detailed description of this.
-r, --report
Report record sizes and archive growth rate.
-s endsize, --size=endsize
Terminate after archive size exceeds endsize.
-t interval, --interval=interval
Specify the logging interval. The default value is 60 seconds. Please refer to the ENVIRONMENT and FILES sections below regarding the PMLOGGER_INTERVAL environment variable and its impact on the default logging interval.
-T endtime, --finish=endtime
Specify the endtime when to end logging.
-u
Use unbuffered output. This is the default (so this option does nothing).
-U username, --username=username
When in daemon mode, run as user username.
-v volsize, --volsize=volsize
Switch volumes after reaching archive volume size volsize.
-V version, --version=version
Specify archive version. The default and the only accepted value is 2.
-x fd
Allow asynchronous control requests on the file descriptor fd.
-y
Use local timezone instead of the timezone from the pmcd(1) host.
-?, --help
Display usage message and exit.

EXAMPLES

For each PCP utility, there is a sample pmlogger configuration file that could be used to create an archive suitable for replaying with that tool (i.e. includes all of the performance metrics used by the tool). For a tool named foo this configuration file is located in $PCP_VAR_DIR/config/pmlogger/config.foo.

The following is a simple default configuration file for a primary pmlogger instance, and demonstrates most of the capabilities of the configuration specification language.


log mandatory on once { hinv.ncpu hinv.ndisk }
log mandatory on every 10 minutes {
    disk.all.write
    disk.all.read
    network.interface.in.packets [ "et0" ]
    network.interface.out.packets [ "et0" ]
    nfs.server.reqs [ "lookup" "getattr" "read" "write" ]
}
log advisory on every 30 minutes {
    environ.temp
    pmcd.pdu_in.total
    pmcd.pdu_out.total
}
%include "macros.default"
%ifdef %disk_detail
log mandatory on %disk_detail_freq {
    disk.dev
}
%endif
[access]
disallow * : all except enquire;
allow localhost : mandatory, advisory;

HOSTNAME CHANGES

The hostname of the PMCD that is providing metrics to pmlogger is used in several ways.

PMCD's hostname (or the argument from the -H option) is included in the archive label and may be used to ensure that subsequent operations on multiple archives, e.g. pmlogextract(1), are only applied to archives from the same host.

For pmlogger instances using a local PMCD that are launched and managed by pmlogger_check(1) and pmlogger_daily(1), (or the systemd(1) or cron(8) services that use these scripts), the local hostname may also be used to construct the name of a directory where all the archives for the one host are stored, e.g. $PCP_ARCHIVE_DIR/<hostname>.

And PMCD's hostname is also stored in the archive via the pmcd.pmlogger.hostname metr
