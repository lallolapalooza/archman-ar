PMDAINSTANCE(3) دليل وظائف المكتبة PMDAINSTANCE(3)

الاسم

pmdaInstance - إرجاع أوصاف المثيلات لـ PMDA

C الملخص

#include <pcp/pmapi.h>
#include <pcp/pmda.h>

int pmdaInstance(pmInDom indom,
int inst, char *name, pmInResult **result, pmdaExt *pmda);

cc ... -lpcp_pmda -lpcp

الوصف

pmdaInstance يستخدم هياكل بيانات PMDA(3) القياسية لإرجاع معلومات تتعلق بمجال المثيل indom.

يتم بناء هيكل result بواسطة pmdaInstance وسيحتوي على اسم مثيل واحد أو أكثر و/أو معرفات كما هو محدد بواسطة الوسيطات inst و name.

إذا كانت قيمة inst هي PM_IN_NULL وكان name سلسلة فارغة، فسيحتوي result على جميع أسماء المثيلات ومعرفاتها في مجال المثيل.

إذا كان inst هو PM_IN_NULL ولكن name هو اسم مثيل في مجال المثيل indom، فسيحتوي result على معرف المثيل للاسم name. لاحظ أنه إذا لم يكن name يحتوي على مسافات، فسيتم إجراء مطابقة جزئية حتى أول مسافة في اسم المثيل، أي أن ``1'' سيطابق اسم المثيل ``1 minute''. إذا كان name يحتوي على مسافة مضمنة، فلن يتم إجراء مطابقة جزئية ويجب أن يتطابق name مع أحد أسماء المثيلات بالضبط.

إذا كان name سلسلة فارغة ولكن inst هو معرف مثيل في مجال المثيل indom، فسيحتوي result على الاسم للمثيل inst. يتم تخصيص هيكل result باستخدام malloc(3) ويجب على المتصل تحريره باستخدام free(3).

تسمية المثيلات متعددة الأبعاد

بالإضافة إلى الوصف أعلاه لـ name، يتم توفير مجموعة القواعد التي تصف أسماء المثيلات الخارجية في صفحة دليل pmdaCacheStore(3).

تضيف مجالات المثيلات بعدًا آخر (مجموعة من القيم) إلى المقاييس. ومع ذلك، قد لا يكون هذا كافياً لوصف مواقف مجالات المثيلات المعقدة متعددة الأبعاد. في هذه الحالة، النهج الذي تستخدمه عدد من PMDAs هو هيكلة أسماء المثيلات الخارجية باستخدام فاصل (``/'' أو ``::'' هما الأكثر شيوعًا) للسماح بفصل الأبعاد الأخرى. في هذا الموقف، يجب استخدام تسميات مجال المثيل لتحديد أسماء لكل مكون من مكونات اسم المثيل. يتيح هذا لأدوات عميل PMAPI(3) تحديد وتوضيح جلب القيم لأبعاد معينة ذات أهمية.

على سبيل المثال، بعض مجالات المثيلات لمقاييس cgroup (مجموعة التحكم) في نواة Linux متعددة الأبعاد. يمثل مجال المثيل قيمًا فردية عبر كل من مجموعات التحكم ووحدات المعالجة المركزية، مما يجعل هذا مجال مثيل ثنائي الأبعاد. تم هيكلة أسماء المثيلات المرتبطة بهذه المقاييس cgroup باستخدام الفاصل ``::'' لفصل البعدين. تم تسمية مجال المثيل نفسه وفقًا لذلك، على النحو التالي.

$ pminfo --desc --fetch --labels cgroup.cpuacct.usage_percpu
cgroup.cpuacct.usage_percpu
نوع البيانات: عدد صحيح غير موقع 64 بت InDom: 3.22 0xc00016
الدلالات: عداد الوحدات: نانو ثانية
مثيل [0 أو "/::cpu0"] قيمة 713787
مثيل [1 أو "/::cpu1"] قيمة 353969
مثيل [2 أو "/app::cpu0"] قيمة 407816
مثيل [3 أو "/app::cpu1"] قيمة 202747
مثيل [0 أو "/::cpu0"] تسميات {"device_type":"cpu","cgroup":"/","cpu":0}
مثيل [1 أو "/::cpu1"] تسميات {"device_type":"cpu","cgroup":"/","cpu":1}
مثيل [2 أو "/app::cpu0"] تسميات {"device_type":"cpu","cgroup":"/app","cpu":0}
مثيل [3 أو "/app::cpu1"] تسميات {"device_type":"cpu","cgroup":"/app","cpu":1}

$ pminfo --labels 3.22
InDom: 3.22 0xc00016
تسميات {"device_type":"cpu"}

كما هو موضح أعلاه، ترث المثيلات الفردية التسميات من مجال المثيل، ويطبق PMDA أيضًا تسميات إضافية لكل مثيل تصف أسماء cgroup ووحدة المعالجة المركزية الفردية. عندما يتم استخدام هذا النموذج بواسطة PMDA، يمكن لأدوات عميل PMAPI تقييد استعلاماتها بمثيلات مقياس cgroup - في المثال، تقييد المعالج "cpu0" باستخدام تسمية "cpu"، ربما، أو فقط بمقاييس cgroup "/app" باستخدام تسمية "cgroup".

علاوة على ذلك، باستخدام نظام التسمية هذا، يمكن لأدوات العميل أيضًا ربط المثيلات ذات الصلة عبر مجالات مثيلات مختلفة.

$ pminfo --desc --fetch --labels kernel.percpu.cpu.irq.soft
kernel.percpu.cpu.irq.soft
نوع البيانات: عدد صحيح غير موقع 64 بت InDom: 60.0 0xf000000
الدلالات: عداد الوحدات: ميلي ثانية
مثيل [0 أو "cpu0"] قيمة 6770
مثيل [1 أو "cpu1"] قيمة 100
مثيل [0 أو "cpu0"] تسميات {"device_type":"cpu"}
مثيل [1 أو "cpu1"] تسميات {"device_type":"cpu"}

$ pminfo --labels 60.0
InDom: 60.0 0xf000000
تسميات {"device_type":"cpu"}

على الرغم من أن هذين المقياسين لهما مجالات مثيلات مختلفة (60.0 و 3.22 على التوالي) ويتم استخراجهما من PMDAs مختلفة، فإن تسمية "device_type" تحدد الجهاز المشترك الذي تتعلق به هذه القيم.

تحذير

يجب أن يستخدم PMDA PMDA_INTERFACE_2 أو أحدث، كما هو محدد في استدعاء pmdaDSO(3) أو pmdaDaemon(3). إذا تم إجراء تسمية أسماء المثيلات متعددة الأبعاد، فيجب على PMDA استخدام PMDA_INTERFACE_7 أو أحدث.

نظرًا للمطابقة الجزئية الاختيارية حتى أول مسافة في اسم المثيل، يجب على مطور PMDA التأكد من أنه إذا كان يُسمح لأسماء المثيلات بأن تحتوي على مسافات، فإن الأسماء تكون فريدة حتى أول مسافة.

التشخيصات

إذا حدثت أي أخطاء أثناء تنفيذ pmdaInstance، فسيتم إلغاء تخصيص هيكل result. إذا لم يكن مجال المثيل indom مدعومًا بواسطة PMDA، فسيرجع pmdaInstance القيمة PM_ERR_INDOM.

إذا كان inst أو name لا يتوافق مع أي مثيلات في مجال indom، فسيرجع pmdaInstance القيمة PM_ERR_INST.

pmdaInstance(3)

PMDA(3) Perl Modules PMDA(3)

NAME

pmdaInstance - Perl module for accessing Performance Co-Pilot (PCP) Performance Metrics Domain Agent (PMDA) instances.

SYNOPSIS

use pmdaInstance;

DESCRIPTION

The pmdaInstance Perl module provides a way to interact with Performance Co-Pilot (PCP) Performance Metrics Domain Agents (PMDA) instances. It allows you to retrieve information about PMDA instances, such as their names, descriptions, and the metrics they expose.

FUNCTIONS

get_pmda_instances()

Returns a list of available PMDA instances.

get_pmda_info(instance_name)

Returns detailed information about a specific PMDA instance.

get_pmda_metrics(instance_name)

Returns a list of metrics exposed by a specific PMDA instance.

EXAMPLE

use pmdaInstance;

my @instances = get_pmda_instances();
foreach my $instance (@instances) {
    print "PMDA Instance: $instance\n";
    my $info = get_pmda_info($instance);
    print "  Description: $info->{description}\n";
    my @metrics = get_pmda_metrics($instance);
    print "  Metrics:\n";
    foreach my $metric (@metrics) {
        print "    - $metric\n";
    }
}
