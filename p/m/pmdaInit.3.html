الوصف

تقوم pmdaInit بتهيئة PMDA ليصبح جاهزًا لاستقبال PDUs من pmcd(1). تتوقع الدالة كوسائط جدول نطاق المثيل (indoms) وجدول وصف المقياس (metrics) اللذين يتم تهيئتهما بواسطة PMDA. يجب ضبط الوسائط nindoms و nmetrics على عدد المثيلات والمقاييس في الجداول، على التوالي.

يمكن تهيئة جزء كبير من بنية pmdaInterface تلقائيًا باستخدام pmdaDaemon(3)، pmdaGetOpt(3) و pmdaDSO(3). تكمل pmdaInit مرحلة تهيئة PMDA بثلاث عمليات. تقوم العملية الأولى بإضافة أرقام النطاق والمثيل إلى جداول المثيل والمقياس. يجب تعيين المقاييس الفردية (المقاييس بدون نطاق مثيل) إلى النطاق PM_INDOM_NULL في حقل indom لبنية pmDesc (انظر pmLookupDesc(3)). المقاييس التي تحتوي على نطاق مثيل يجب أن تعين هذا الحقل ليكون الرقم التسلسلي لنطاق المثيل في جدول indoms.

يمكن جعل جدول نطاق المثيل فارغًا عن طريق تعيين indoms إلى NULL و nindoms إلى 0. هذا يسمح للمستدعي بتوفير وظائف رد اتصال مخصصة للاسترداد والمثيلات. يمكن جعل جدول المقياس فارغًا عن طريق تعيين metrics إلى NULL و nmetrics إلى 0. هذا يسمح للمستدعي بتوفير وظائف رد اتصال مخصصة للاسترداد والواصفات.

مثال

على سبيل المثال، يحتوي PMDA على ثلاثة مقاييس: A، B، و C، ونطاقي مثيل X و Y، مع مثيلين في كل نطاق مثيل. يمكن تعريف جداول وصف نطاق المثيل والمقاييس على النحو التالي:

static pmdaInstid _X[] = {
    { 0, "X1" }, { 1, "X2" }
};
static pmdaInstid _Y[] = {
    { 0, "Y1" }, { 1, "Y2" }
};
static pmdaIndom indomtab[] = {
#define X_INDOM 0
    { X_INDOM, 2, _X },
#define Y_INDOM 3
    { Y_INDOM, 2, _Y }
};
static pmdaMetric metrictab[] = {
/* A */
    { (void *)0,
      { PMDA_PMID(0,0), PM_TYPE_U32, PM_INDOM_NULL, PM_SEM_INSTANT,
        { 0,0,0,0,0,0} }, },
/* B */
    { (void *)0,
      { PMDA_PMID(0,1), PM_TYPE_U32, X_INDOM, PM_SEM_INSTANT,
        { 0,0,0,0,0,0} }, },
/* C */
    { (void *)0,
      { PMDA_PMID(0,2), PM_TYPE_DOUBLE, Y_INDOM, PM_SEM_INSTANT,
        { 0,1,0,0,PM_TIME_SEC,0} }, }
};

يحدد جدول وصف المقياس المقياس A بدون نطاق مثيل، والمقياس B مع نطاق المثيل X، والمقياس C مع نطاق المثيل Y. المقياس C له وحدات ثوانٍ، بينما المقاييس الأخرى ليس لها وحدات (عدادات بسيطة). ستقوم pmdaInit بأخذ هذه الهياكل وتعيين رقم نطاق PMDA(3) إلى حقل it_indom لكل نطاق مثيل. هذا المعرف يستبدل أيضًا حقل indom لجميع المقاييس التي تحتوي على هذا النطاق المثيل، بحيث يتم ربطها بشكل صحيح.

المرحلة الثانية تفتح ملف نص المساعدة، إذا تم تحديده باستخدام الخيار -h لسطر الأوامر (انظر pmdaGetOpt(3)) أو كوسيط helptext لـ pmdaDSO(3) أو pmdaDaemon(3).

المرحلة النهائية تتضمن إعداد استراتيجية البحث في جدول المقياس.

البحث في المقاييس

عندما يتم إجراء طلبات الاسترداد والواصفات من PMDA، يجب ربط كل PMID مطلوب بإدخال في جدول المقياس. توجد حاليًا ثلاث استراتيجيات لتنفيذ هذا الربط - مباشر، خطي، ومجزأ (hashed). لكل منها مجموعة من المقايضات، ويجب اختيار استراتيجية مناسبة لكل PMDA.

إذا كانت جميع أرقام عناصر PMID للمقياس تتوافق مع الموضع في جدول metrics، يتم استخدام الربط المباشر. هذه هي الوظيفة الأكثر كفاءة للبحث لأنها تتضمن فهرس مصفوفة مباشر (لا يتطلب ذاكرة إضافية ولا أي عبء معالجة إضافي). إذا تم استيفاء متطلب ترقيم PMID بواسطة PMDA، فهذا مثالي. يمكن طلب هذه الاستراتيجية بشكل صريح عن طريق استدعاء pmdaSetFlags(pmda، PMDA_EXT_FLAG_DIRECT) قبل استدعاء pmdaInit. في هذه الحالة، إذا لم يكن الربط المباشر ممكنًا (على سبيل المثال، بسبب إغفال من جانب مطور PMDA)، يتم تسجيل تحذير ويتم استخدام الاستراتيجية الخطية بدلاً من ذلك.

الاستراتيجية الثانية (البحث الخطي) هي الافتراضية، عندما لا يمكن إنشاء ربط مباشر. يوفر هذا مرونة أكبر في مخطط ترقيم PMID، حيث لا يلزم أن تكون أرقام عناصر PMDA فريدة (وبالتالي، يمكن استخدام أرقام تجميع PMID بحرية أكبر، وهو ما يكون غالبًا مريحًا للغاية لمطور PMDA). ومع ذلك، يتضمن البحث مشيًا خطيًا من بداية جدول المقياس حتى يتم العثور على PMID مطابق، لكل PMID مطلوب في طلب.

يمكن طلب الاستراتيجية الثالثة (البحث المجزأ) عن طريق استدعاء pmdaSetFlags(pmda، PMDA_EXT_FLAG_HASHED) قبل استدعاء pmdaInit. هذه الاستراتيجية مفيدة جدًا لـ PMDAs التي تحتوي على أعداد كبيرة من المقاييس (مئات، أو آلاف). ستستخدم هذه الـ PMDAs تقريبًا دائمًا مخطط الترقيم بالتجميع، لذا يصبح مخطط البحث المباشر غير مناسب. قد يكونون مستعدين أيضًا للتضحية بكمية صغيرة من الذاكرة الإضافية لجدول تجزئة، يربط PMID بإزاحات جدول المقياس، لتسريع عمليات البحث في جداول المقاييس الضخمة الخاصة بهم.

يمكن أيضًا استخدام هذه الاستراتيجية النهائية بواسطة PMDAs التي تقدم مقاييس مرقمة ديناميكيًا. في هذه الحالة، يجب استخدام الدالة pmdaRehash لاستبدال جدول المقياس عند توفر مقاييس جديدة، أو عند إزالة المقاييس الموجودة. سيتم إعادة حساب ربط تجزئة PMID في نفس الوقت الذي يتم فيه تثبيت جدول المقياس الجديد.

تغييرات المقاييس

يجب أن يفهم مؤلفو PMDA تمامًا أن البيانات الوصفية للمقاييس الفردية ثابتة، ومن المثالي ألا تتغير أبدًا. في الحالة التي تكون فيها البيانات الوصفية غير صحيحة ويتم تحديثها، يتطلب هذا التغيير تصحيح المقاييس المسجلة باستخدام pmlogrewrite(1)، ونتيجة لذلك يجب تجنبه كلما أمكن ذلك.

ومع ذلك، قد يصبح PMDA على دراية بمقاييس النطاق الجديدة في وقت التشغيل، وفي هذه الحالة من المثالي تصديرها فورًا (دون أي إعادة تشغيل لنظام الجامع). في هذا الموقف، يمكن لـ PMDA إبلاغ جميع عملاء PMAPI قيد التشغيل الذين ربما يكونون قد استكشفوا بالفعل مساحة اسم المقياس (على سبيل المثال، باستخدام pmTraversePMNS(3)) بالتغيير في مساحة اسم المقياس.

يتم تحقيق ذلك باستخدام pmdaSetFlags(pmda، PMDA_EXT_NAMES_CHANGE) مما يؤدي إلى إرسال إشعار تغيير الحالة PMCD_NAMES_CHANGE إلى كل عميل PMAPI عند الاسترداد التالي. إذا كانت المقاييس المكتشفة حديثًا تحتوي على بيانات وصفية للعناوين المرتبطة بها، فقد يتم أيضًا تعيين العلم PMDA_EXT_LABEL_CHANGE، مما يؤدي إلى إرسال إشعار PMCD_LABEL_CHANGE أيضًا.

pmdaExtSetFlags يعادل pmdaSetFlags، ويتم توفيره كواجهة ملائمة في الحالات التي تكون فيها pmdaExt متاحة بسهولة أكبر من بنية pmdaInterface.

سمات الاتصال

يجب على الوكلاء الذين يستخدمون سمات المصادقة أو الحاويات الإشارة إلى ذلك باستخدام واجهة pmdaSetCommFlags. يشير هذا إلى الحاجة إلى نقل هذه السمات على قناة الاتصال.

NAME

pmdaInit, pmdaDSO - initialize Performance Metrics Domain Agent (PMDA)

C SYNOPSIS

#include <pcp/pmapi.h>
#include <pcp/pmda.h>
int
pmdaInit(pmdaInterface_t *iface, pmdaExt_t **ext);
int
pmdaDSO(pmdaInterface_t *iface, pmdaExt_t **ext);

DESCRIPTION

The pmdaInit and pmdaDSO functions are the primary initialization routines for a Performance Metrics Domain Agent (PMDA). They are called by the Performance Co-Pilot (PCP) collector daemon, pmcd(1), when a PMDA is loaded either as a dynamically loadable object (DSO) or as a child process.

The iface argument is a pointer to a PMAPI(3) interface structure, which is used to register PMDA callbacks for various PCP services.

The ext argument is a pointer to a pointer to a PMDA(3) extension structure. On return, if successful, *ext will point to a valid PMDA(3) extension structure allocated by pmdaInit. This structure may be used to store PMDA private data.

pmdaDSO is a legacy function and is typically called by pmdaInit. New PMDAs should call pmdaInit directly.

EXAMPLE

A typical PMDA initialization might look like this:

#include <pcp/pmapi.h>
#include <pcp/pmda.h>

static pmdaExt_t *my_ext; /* PMDA private data pointer */

static int my_fetch(pmID_t pmid, __pm_va_list_t args, void **private_data)
{
    /* Fetch metric value */
    return PM_ERR_PMID;
}

static int my_text(pmid_t pmid, int fmt, __pm_va_list_t args)
{
    /* Return help text */
    return PM_ERR_PMID;
}

static int my_init(pmdaInterface_t *iface, pmdaExt_t **ext)
{
    int version;
    int ret;

    /* Check PMDA interface version */
    if ((version = pmdaInterfaceVersion(iface)) < PMDA_INTERFACE_1) {
        /* Handle older interface version */
        return PM_ERR_INIT;
    }

    /* Register callbacks */
    iface->pmdaDispatch = PMDA_DISPATCH_FN;
    iface->pmdaFetchCallBack = my_fetch;
    iface->pmdaTextCallBack = my_text;

    /* Allocate PMDA extension structure */
    *ext = pmdaNewExt(sizeof(my_ext_data)); /* my_ext_data is a struct for private data */
    if (*ext == NULL) {
        return PM_ERR_NOMEM;
    }
    my_ext = *ext; /* Store globally for easier access */
    /* Initialize private data */
    my_ext->my_private_data->some_value = 0;

    /* Set flags if needed */
    if (version >= PMDA_INTERFACE_7) {
        pmdaSetFlags(my_ext, PMDA_FLAG_CONTAINER);
    }

    return 0; /* Success */
}

/* In main or other entry point */
int main(int argc, char **argv)
{
    pmdaInterface_t iface;
    pmdaExt_t *ext;
    int ret;

    /* Initialize PMDA interface */
    pmdaInterface(0, &iface);

    /* Call the initialization routine */
    ret = my_init(&iface, &ext);
    if (ret != 0) {
        /* Handle initialization error */
        exit(1);
    }

    /* Start the PMDA event loop */
    pmdaMain(iface.pmdaDispatch, ext);

    return 0;
}

METRIC LOOKUP

During initialization, the PMDA should register its metrics with PCP. This is typically done by providing a PMAPI(3) metric description table to the PMDA interface. The structure of the metric description table and how it is registered depends on the PMDA interface version used.

METRIC CHANGES

If a PMDA needs to notify pmcd(1) about changes in its metrics (e.g., adding or removing metrics), it can use the pmdaSetFlags function (available from PMDA interface version 7 onwards). The relevant flags are PMDA_FLAG_METRIC_ADD and PMDA_FLAG_METRIC_REMOVE.

COMMUNICATION ATTRIBUTES

The pmdaInit function can be used to set communication attributes between the PMDA and pmcd or local context client. Valid flags are PMDA_FLAG_AUTHORIZE (for authentication related attributes) and PMDA_FLAG_CONTAINER (for container name related attributes).

PRIVATE DATA

A facility for associating private PMDA data with the pmdaExt structure is available. This allows a PMDA to associate an arbitrary (and typically not global) pointer with the pmdaExt such that it can be later obtained during callbacks. The interfaces for setting this pointer are pmdaSetData and pmdaExtSetData, and pmdaExtGetData for subsequently retrieving it.

CAVEAT

The PMDA must be using PMDA_INTERFACE_2 or later, as specified in the call to pmdaDSO(3) or pmdaDaemon(3) to use pmdaInit.

The PMDA must use PMDA_INTERFACE_7 or later to issue state change notifications using pmdaSetFlags or pmdaExtSetFlags.

DIAGNOSTICS

pmdaInit will set dispatch->status to a value less than zero if there is an error that would prevent the PMDA(3) from successfully running. pmcd(1) will terminate the connection to the PMDA(3) if this occurs.

pmdaInit may issue any of these messages:

PMDA interface version interface not supported
The interface version is not supported by pmdaInit.
Using pmdaFetch() but fetch call back not set
The fetch callback, pmdaFetch(3), requires an additional callback to be provided using pmdaSetFetchCallBack(3).
Illegal instance domain inst for metric pmid
The instance domain inst that was specified for metric pmid is not within the range of the instance domain table.
No help text path specified
The help text callback, pmdaText(3), requires a help text file for the metrics to have been opened, however no path to the help text was specified as a command line option, or as an argument to pmdaDSO(3) or pmdaDaemon(3). This message is only a warning.
Direct mapping for metrics disabled @ num
The unit numbers of the metrics did not correspond to the index in the metric description table. The direct mapping failed for metric number num in the metrics table. This is less efficient but is not fatal and the message is only a warning.
Hashed mapping for metrics disabled @ num
A memory allocation failure occurred while building the hash table to index the metric description table. This is a non-fatal warning message - a fallback to linear searching will be automatically performed should this situation arise.
