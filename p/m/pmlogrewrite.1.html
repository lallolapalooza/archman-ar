PMLOGREWRITE(1) دليل الأوامر العامة PMLOGREWRITE(1)

الاسم

pmlogrewrite - إعادة كتابة أرشيفات Performance Co-Pilot

الملخص

pmlogrewrite [-Cdiqsvw?] [-c config] [-D debug] [-V version] inlog [outlog]

الوصف

يقرأ pmlogrewrite مجموعة من أرشيفات Performance Co-Pilot (PCP) المحددة بواسطة inlog وينشئ أرشيف PCP في outlog. في الاستخدام العادي، سيتم استخدام الخيار -c لتسمية ملف أو ملفات تكوين تحتوي على مواصفات (انظر قسم صيغة قواعد إعادة الكتابة أدناه) تصف كيف يجب تحويل البيانات والبيانات الوصفية من inlog لإنتاج outlog.

الاستخدامات النموذجية لـ pmlogrewrite ستكون لاستيعاب تطور وكلاء مجال مقاييس الأداء (PMDAs) حيث قد تتغير أسماء المقاييس والبيانات الوصفية ودلالاتها ومجالات المثيل المرتبطة بها بمرور الوقت، على سبيل المثال، ترقية نوع مقياس من عدد صحيح 32 بت إلى 64 بت، أو إعادة تسمية مجموعة من المقاييس. ارجع إلى قسم الأمثلة لبعض حالات الاستخدام الإضافية.

قد يستخدم pmlogrewrite أيضًا لتنقيح المعلومات الحساسة من أرشيفات PCP في الحالات التي تتطلب فيها شحن الأرشيفات إلى منظمة أخرى أو لتلبية سياسات الخصوصية أو المتطلبات التشريعية. انظر pmlogredact(1) كمثال لاستخدام pmlogrewrite في هذا السياق.

pmlogrewrite يكون أكثر فائدة عندما تؤدي تغييرات PMDA، أو الأخطاء في بيئة الإنتاج، إلى أرشيفات لا يمكن دمجها مع pmlogextract(1). عن طريق المعالجة المسبقة للأرشيفات باستخدام pmlogrewrite، قد تتمكن الأرشيفات الناتجة من الاندماج مع pmlogextract(1).

يجب أن يكون inlog المدخل مجموعة من أرشيفات PCP التي أنشأها pmlogger(1)، أو ربما أحد الأدوات التي تقرأ وتنشئ أرشيفات PCP، مثل pmlogextract(1) و pmlogreduce(1). inlog هي قائمة مفصولة بفواصل من الأسماء، قد يكون كل منها هو الاسم الأساسي للأرشيف أو اسم دليل يحتوي على أرشيف واحد أو أكثر.

إذا لم يتم تحديد خيار -c، فإن السلوك الافتراضي ببساطة ينشئ outlog كنسخة من inlog. هذا أكثر تعقيدًا قليلاً من cat(1)، نظرًا لأن كل أرشيف PCP يتكون من عدة ملفات فعلية.

بينما يمكن استخدام pmlogrewrite لإصلاح بعض مشكلات تناسق البيانات في أرشيفات PCP، هناك أيضًا فئة من مهام الإصلاح التي لا يمكن التعامل معها بواسطة pmlogrewrite وقد يكون pmloglabel(1) أداة مفيدة في هذه الحالات.

الخيارات

الخيارات المتاحة في سطر الأوامر هي:

-c config, --config=config
إذا كان config ملفًا أو رابطًا رمزيًا، فاقرأ وحلل قواعد إعادة الكتابة منه. إذا كان config دليلًا، فسيتم استخدام جميع الملفات أو الروابط الرمزية في هذا الدليل (باستثناء تلك التي تبدأ بنقطة "'.") لتوفير قواعد إعادة الكتابة. يُسمح بخيارات -c متعددة.
-C, --check
تحليل قواعد إعادة الكتابة والخروج. لا يتم إنشاء outlog، لذا فإن وسيطة سطر الأوامر هذه اختيارية مع -C. عند تحديد -C، يتم تعيين -v و -w أيضًا بحيث يتم عرض جميع التحذيرات والرسائل المطولة أثناء تحليل config.
-d, --desperate
وضع يائس. عادةً، إذا حدث خطأ فادح، يتم إزالة جميع آثار أرشيف PCP الذي يتم كتابته جزئيًا outlog. مع الخيار -d، لا يتم إزالة أرشيف outlog الذي تم إنشاؤه جزئيًا.
-i
بدلاً من إنشاء outlog، يتم إعادة كتابة inlog في مكانه عند استخدام الخيار -i. يتم إنشاء أرشيف جديد باستخدام أسماء ملفات مؤقتة ثم إعادة تسميته إلى inlog بطريقة بحيث إذا تم العثور على أي أخطاء (وليس تحذيرات)، يظل inlog دون تغيير.
-q, --quick
وضع سريع، حيث إذا لم تكن هناك إجراءات إعادة كتابة يجب تنفيذها (لن يتم تغيير أي من البيانات العامة أو مجالات المثيل أو المقاييس من inlog)، فسيخرج pmlogrewrite (بحالة نجاح 0، لذا نجاح) فورًا بعد تحليل ملفات التكوين ولا يتم إنشاء outlog.
-s, --scale
عند تغيير "وحدات" المقياس، إذا لم يتغير البعد من حيث المساحة والوقت والعد، فإن عامل القياس يتغير، على سبيل المثال، BYTE إلى KBYTE، أو MSEC-1 إلى USEC-1، أو المركب MBYTE.SEC-1 إلى KBYTE.USEC-1. قد يكون الدافع هو (أ) أن البيانات الوصفية الأصلية كانت خاطئة ولكن القيم في inlog صحيحة، أو (ب) البيانات الوصفية تتغير لذا يجب تغيير القيم أيضًا. يتطابق السلوك الافتراضي لـ pmlogrewrite مع الحالة (أ). إذا انطبقت الحالة (ب)، فاستخدم الخيار -s وسيتم إعادة قياس قيم جميع المقاييس التي يتغير عامل قياسها في كل نتيجة. للحصول على تحكم أدق في إعادة قياس القيم، ارجع إلى الخيار RESCALE لـ UNITS الخاص بقاعدة إعادة كتابة المقياس الموضح أدناه.
-v, --verbose
تمكين الوضع المطول.
-V version, --version=version
يحدد إصدار أرشيف PCP الناتج. حاليًا، يتم دعم الإصدارين 2 و 3 من تنسيق الأرشيف. يجب أن يكون إصدار inlog على الأقل version (لذا يُسمح بترقية الإصدار، ولكن ليس خفضه). بشكل افتراضي، في حالة عدم وجود الخيار -V، يكون إصدار outlog هو نفسه إصدار inlog.
-w, --warnings
إصدار تحذيرات. عادةً ما يظل pmlogrewrite صامتًا لأي تحذير غير فادح ومن المتوقع أنه لأرشيف معين، قد لا تنطبق بعض (أو كل) مواصفات إعادة الكتابة. على سبيل المثال، قد يتم التقاط التغييرات في PMDA في مجموعة من قواعد إعادة الكتابة، ولكن قد لا يحتوي أرشيف واحد على جميع المقاييس المعدلة ولا جميع مجالات المثيل و/أو المثيلات المعدلة. نظرًا لأن هذه الحالات متوقعة، فإنها لا تمنع pmlogrewrite من التنفيذ، ويتم تجاهل القواعد التي لا تنطبق على inlog بصمت افتراضيًا. وبالمثل، قد لا تتضمن بعض قواعد إعادة الكتابة أي تغيير لأن البيانات الوصفية في inlog تطابق بالفعل هدف قاعدة إعادة الكتابة لتصحيح البيانات من إصدار سابق من PMDA. يجبر العلم -w على إصدار تحذيرات لجميع هذه الحالات.
-?, --help
عرض رسالة الاستخدام والخروج.

الوسيط outlog مطلوب في جميع الحالات، باستثناء عند تحديد -i.

صيغة قواعد إعادة الكتابة

يحتوي ملف التكوين على صفر أو أكثر من قواعد إعادة الكتابة كما هو محدد أدناه.

الكلمات المفتاحية والأحرف الخاصة بعلامات الترقيم موضحة أدناه بخط **غامق مائل** وهي غير حساسة لحالة الأحرف، لذا فإن METRIC و metric و Metric كلها مكافئة في قواعد إعادة الكتابة.

الحرف "#" يقدم تعليقًا ويتم تجاهل بقية السطر. بخلاف ذلك، يكون الإدخال بتنسيق حر نسبيًا مع مسافة بيضاء اختيارية (مسافات أو علامات جدولة أو أسطر جديدة) بين العناصر المعجمية في القواعد.

قاعدة إعادة كتابة **عامة** تكون بالشكل:

GLOBAL { globalspec ... }

حيث globalspec هي صفر أو أكثر من العبارات التالية:

HOSTNAME -> hostname

يعدل سجلات التسمية في أرشيف PCP outlog، بحيث تظهر المقاييس وكأنها تم جمعها من المضيف hostname.

TIME -> delta

تحمل كل من قيم المقاييس والبيانات الوصفية لمجال المثيل في أرشيف PCP طوابع زمنية. تجبر هذه العبارة على تعديل جميع الطوابع الزمنية بواسطة delta، حيث delta هي علامة اختيارية "+" (ث

The enclosing delimiters cannot be escaped, so to embed a literal slash, use double quotes as the delimiter, or vice versa.

A text rewriting rule modifies a help text record and has the form:

TEXT textid [ texttype ] [ "textcontent" ] { textspec ... }

where textid identifies the metric or instance domain with which the text is currently associated, and is either METRIC metricid or INDOM domain.serial.

metricid has the same form and meaning as for a METRIC rewriting rule (see above) and domain.serial has the same form and meaning as for an INDOM rewriting rule (see above).

The optional texttype identifies the type of text and may be one of ONELINE to select the one line help text, HELP to select the full help text, or ALL or an asterisk ``*'' to select both types of help text. If texttype is not specified, then the default is ONELINE.

The optional textcontent further restricts the selected text records to those containing the specified content. Characters such as double quotes may be escaped by preceding them with a backslash ``\''.

If a designated help text record is not in inlog the rule has no effect.

The textspec is zero or more of the following clauses:

DELETE

The selected text is completely removed from outlog.

INDOM -> newdomain.newserial

Re-associates the text with the specified instance domain. As a special case, newserial could be an asterisk ``*'' which means use serial from the text rewriting rule, although this is most useful when serial is also an asterisk. So for example:

text indom 29.* all { indom -> 109.* }
will re-associate all text associated with instance domains from domain 29 to domain 109.

METRIC -> newdomain.newcluster.newitem

Re-associates the text with the specified metric. As special cases, newcluster could be an asterisk ``*'' which means use cluster from the text rewriting rule and/or item could be an asterisk which means use item from the text rewriting rule. This is most useful when cluster and/or item is also an asterisk. So for example:

text metric 30.*.* all { metric -> 123.*.* }
will re-associate all text associated with metrics from domain 30 to domain 123.

TEXT -> "new-text"

Replaces the content of the selected text with new-text.

A label rewriting rule modifies a label record and has the form:

LABEL labelid [ instance ] [ "label-name" ] [ "label-value" ] { labelspec ... }

where labelid refers to the global context or identifies the metric domain, metric cluster, metric item, instance domain, or instance domain instances with which the label is currently associated, and is either CONTEXT or DOMAIN domainid or CLUSTER domainid.clusterid or ITEM metricid or INDOM domain.serial or INSTANCES domain.serial.

metricid has the same form and meaning as for a METRIC rewriting rule (see above). clusterid may be an asterisk ``*'' which means the rule applies to every metric with a domain number of domainid in the same way as an asterisk may be used for the cluster within metricid.

domain.serial has the same form and meaning as for an INDOM rewriting rule (see above).

In the case of an INSTANCES labelid, the name or number of a specific instance may be optionally specified as instance. This name or number number may be omitted or specified as an asterisk ``*'' to indicate that labels for all instances of the specified instance domain are selected. If an instance name is specified, it must be within double quotes. If the instance name contains any embedded spaces then special care needs to be taken in respect of the PCP instance naming rule that treats the leading non-space part of the instance name as the unique portion of the name for the purposes of matching and ensuring uniqueness within an instance domain, refer to pmdaInstance(3) for a discussion of this issue.

In all cases, a "label-name" and/or a "label-value" may be optionally specified in double quotes in order to select labels with the given name and/or given value. These may individually be omitted or specified as asterisks ``*'' to indicate that labels with all names and/or values are selected.

If a designated label record is not in inlog the rule has no effect.

The labelspec is zero or more of the following clauses:

DELETE

The selected labels are completely removed from outlog.

NEW "new-label-name" "new-label-value"

A new label with the name "new-label-name" and the value "new-label-value" is created and associated with the specified labelid and optional instance (in the case of a INSTANCES labelid). If "label-name" or "label-value" were specified, then they are ignored with a warning. If instance is not specified for an INSTANCES labelid, then a new label will be created for each instance in the specified instance domain.

LABEL -> "new-label-name"

The name of the selected label(s) is changed to "new-label-name".

VALUE -> "new-label-value"

The value of the selected label(s) is changed to "new-label-value".

DOMAIN -> newdomain

Re-associates the selected label(s) with the specified metric domain. For example:

label domain 30 { domain -> 123 }
will re-associate all labels associated with domains from domain 30 to domain 123.

CLUSTER -> newdomain.newcluster

Re-associates the selected label(s) with the specified metric cluster. As a special case, newcluster could be an asterisk ``*'' which means use cluster from the label rewriting rule. This is most useful when cluster is also an asterisk. So for example:

label cluster 30.* { cluster -> 123.* }
will re-associate all labels associated with clusters from domain 30 to domain 123.

ITEM -> newdomain.newcluster.newitem

Re-associates the selected label(s) with the specified metric item. As special cases, newcluster could be an asterisk ``*'' which means use cluster from the label rewriting rule and/or item could be an asterisk which means use item from the label rewriting rule. This is most useful when cluster and/or item is also an asterisk. So for example:

label item 30.*.* { item -> 123.*.* }
will re-associate all labels associated with metrics from domain 30 to domain 123.

INDOM -> newdomain.newserial
