أوصاف المقاييس

يتطلب كل مقياس وصفًا (pmDesc)، والذي يحتوي على معرف مقياس الأداء (PMID) الخاص به، وتحديد نوع البيانات، ونطاق المثيل، والدلالات، والوحدات (انظر pmLookupDesc(3)). يتم أيضًا توفير مقبض للمعلومات الخاصة بالتطبيق في البنية pmdaMetric:

/*
 * Metric description: handle for extending description,
 * and the description.
 */
typedef struct {
    void*       m_user;         /* for users external use */
    pmDesc      m_desc;         /* metric description */
} pmdaMetric;

يحدد PMDA البسيط المقاييس على النحو التالي:

static pmdaMetric metrictab[] = {
/* numfetch */
    { (void *)0,
      { PMDA_PMID(0,0), PM_TYPE_U32, PM_INDOM_NULL, PM_SEM_INSTANT,
        { 0,0,0,0,0,0} }, },
/* color */
    { (void *)0,
      { PMDA_PMID(0,1), PM_TYPE_32, COLOR_INDOM, PM_SEM_INSTANT,
        { 0,0,0,0,0,0} }, },
/* time.user */
    { (void*)0,
      { PMDA_PMID(1,2), PM_TYPE_DOUBLE, PM_INDOM_NULL, PM_SEM_COUNTER,
      	{ 0, 1, 0, 0, PM_TIME_SEC, 0 } }, },
/* time.sys */
    { (void*)0,
      { PMDA_PMID(1,3), PM_TYPE_DOUBLE, PM_INDOM_NULL, PM_SEM_COUNTER,
      	{ 0, 1, 0, 0, PM_TIME_SEC, 0 } }, },
/* now */
    { NULL,
      { PMDA_PMID(2,4), PM_TYPE_U32, NOW_INDOM, PM_SEM_INSTANT,
        { 0,0,0,0,0,0 } }, },
};

يتم استخدام الماكرو PMDA_PMID (المعرفة في /usr/include/pcp/pmda.h) لتحديد حقلي cluster و item لكل مقياس من pmID المرتبط به. كما هو الحال مع نطاقات المثيل، يتم تعيين حقل domain بواسطة pmdaInit(3) في وقت التشغيل، ومع ذلك، يُفترض أن يكون النطاق الافتراضي معرفًا بواسطة PMDA في الماكرو MYDOMAIN.

لا تحتاج جدولة المقاييس الموضحة أعلاه والتي يتم تمريرها عادةً إلى pmdaInit(3) إلى الإنشاء إذا أراد المرء كتابة وظائف Fetch و Descriptor الخاصة به. انظر pmdaInit(3) لمزيد من التفاصيل.

DSO PMDA

يتم فتح PMDA الذي يعمل كوحدة تخزين ديناميكية (DSO) بواسطة pmcd(1) باستخدام dlopen(3). سيقوم pmcd(1) باستدعاء دالة تهيئة PMDA المحددة في $PCP_PMCDCONF_PATH. يتم تمرير مؤشر إلى بنية pmdaInterface لهذه الدالة، والتي يجب إكمالها. يجب تحديد أي استدعاءات عكسية ليست استدعاءات مكتبة دعم PMDA الافتراضية في بنية pmdaInterface.

يستخدم PMDA البسيط مخزن الاستدعاء العكسي الخاص به ووظيفة الاسترداد. يستدعي simple_fetch() الدالة pmdaFetch(3) التي تتطلب تعيين استدعاء عكسي باستخدام pmdaSetFetchCallBack(3) كما يمكن رؤيته في $PCP_PMDAS_DIR/simple/simple.c.

يتم استخدام العلامة _isDSO لتحديد ما إذا كان PMDA برنامجًا خادمًا أم وحدة تخزين ديناميكية (DSO) بحيث يتم استدعاء روتين التهيئة الصحيح، pmdaDaemon(3) أو pmdaDSO(3).

DAEMON PMDA

يتم استنساخ وتنفيذ PMDA الذي يعمل كخادم بواسطة pmcd(1). لذلك، على عكس PMDA وحدة التخزين الديناميكية (DSO)، فإن نقطة البداية لـ PMDA الخادم هي main(). يجب على الوكيل تحليل وسيطات سطر الأوامر، وإنشاء ملف سجل، وتهيئة بعض هياكل البيانات التي سيقوم pmcd(1) بتهيئتها لوكيل وحدة التخزين الديناميكية (DSO).

يجب تعريف بنية pmdaInterface بالكامل بواسطة PMDA الخادم. يمكن استدعاء الدالة pmdaDaemon(3) في بداية main() لتعيين معظم هذه الحقول. يمكن تبسيط تحليل سطر الأوامر باستخدام pmdaGetOpt(3)، والذي يشبه getopt(2)، ولكنه يستخرج مجموعة مشتركة من الخيارات في بنية pmdaInterface. يمكن تعيين stderr إلى ملف سجل باستخدام pmdaOpenLog(3) لتبسيط تصحيح الأخطاء ورسائل الخطأ. يمكن إجراء الاتصال بـ pmcd(1) باستخدام pmdaConnect(3) ويجب أن تكون الحلقة التي تتعامل مع وحدات PDU الواردة، pmdaMain(3)، هي الوظيفة الأخيرة التي يتم استدعاؤها. يمكن رؤية ذلك في $PCP_PMDAS_DIR/simple/simple.c.

روتين simple_init() مشترك للوكيل الذي يمكن تشغيله كـ PMDA خادم و PMDA وحدة تخزين ديناميكية (DSO) على حد سواء.

نص المساعدة

يجب أن يكون كل PMDA قادرًا على تزويد pmcd(1) بنص المساعدة لكل مقياس. تستخدم معظم PMDAs ملفات تم إنشاؤها خصيصًا مع فهارس لدعم الاسترجاع الفعال لنص المساعدة. يتم تزويد الأدوات بـ PCP لإنشاء ملفات نص المساعدة بالتنسيق المناسب. انظر newhelp(1).

التثبيت والإزالة

يتم تعريف سلسلة من إجراءات Shell في $PCP_SHARE_DIR/lib/pmdaproc.sh التي تبسط إلى حد كبير تثبيت PMDA وإزالته.

يجب أن تحتاج نصوص Install لمعظم PMDAs فقط إلى تحديد اسم PMDA في iam، واستدعاء pmdaSetup الذي يقوم بإعداد بعض المتغيرات الافتراضية، ويتحقق من الأذونات (يجب أن تكون "root" لتثبيت أو إزالة PMDA)، ويتحقق من أنك في الدليل الصحيح (مكان ينتهي بـ /pmdas/$iam)، ويولد اختياريًا ملفات مساحة اسم المقاييس (PMNS) وملفات أرقام نطاق PMDA لـ Perl أو Python PMDAs، ويتحقق من أن رقم نطاق PMDA صالح، وما إلى ذلك، ويحدد بروتوكولات الاتصال، وأخيرًا يستدعي pmdaInstall للقيام بكل العمل المتمثل في تحديث PMNS، وتحديث ملف تحكم pmcd(1)، وإخطار pmcd(1) أو إعادة تشغيله.

بالإضافة إلى pmdaSetup و pmdaInstall، هناك روتين مساعد اختياري آخر وهو pmdaChooseConfigFile والذي يمكن استخدامه لتحديد أو إنشاء ملف تكوين خاص بـ PMDA بشكل تفاعلي، على سبيل المثال pmdalogger(1).

نصوص Remove أبسط حتى لأن إعداد بروتوكولات الاتصال غير مطلوب، لذلك قم بتعيين اسم PMDA في iam، ثم استدعاء pmdaSetup متبوعًا باستدعاء لـ pmdaRemove.

مزيد من المعلومات موجودة في الملف $PCP_SHARE_DIR/lib/pmdaproc.sh والقسم التالي.

اختياريًا، قد يوفر PMDA نص Upgrade بجانب Install و Remove. إذا كان موجودًا، فسيتم استخدام هذا النص بواسطة عملية بدء تشغيل pmcd للتأكد من إجراء التصحيحات على التثبيت قبل بدء تشغيل PMDA. تشمل الأمثلة على هذه التصحيحات: تحديثات لـ pmcd.conf عند إعادة تسمية نص أو ثنائي PMDA، عندما يدعم PMDA تنسيقًا جديدًا لملف التكوين الخاص به، أو إذا كانت هناك مشكلة كامنة من تثبيت سابق (على سبيل المثال، قد تحتاج بعض PMDAs إلى تقديم استخدام الكلمة المفتاحية notready في pmcd.conf، كما هو موضح أدناه).

تحسينات التثبيت

كما هو موضح أدناه، هناك عدد من المتغيرات التي يمكن تعيينها في نص Install الخاص بـ PMDA للتأثير على سلوك إجراءات التثبيت. عادةً ما تحتاج هذه إلى تعيينها قبل استدعاء pmdaInstall، ولكن في بعض الحالات (مثل $iam والحالات المذكورة خصيصًا أدناه)، قبل استدعاء pmdaSetup.

تتحكم المتغيرات التالية في خيارات الاتصال بين PMDA و pmcd(1). يجب تعيين واحد على الأقل من $daemon_opt أو $dso_opt أو $perl_opt أو $python_opt لتحديد وضع (أو أوضاع) الاتصال المدعومة. إذا تم تعيين أكثر من واحد من هؤلاء، فسيتم مطالبة المستخدم بإجراء اختيار عند تشغيل نص Install.

daemon_opt
نحن على استعداد لتثبيت PMDA كخادم.
الافتراضي: true
dso_opt
نحن على استعداد لتثبيت PMDA كوحدة تخزين ديناميكية (DSO)، لذا سيستخدم pmcd(1) محمل الربط الديناميكي لربط DSO الخاص بـ PMDA في وقت التشغيل، ويستخدم الاتصال من pmcd(1) إلى PMDA والعودة استدعاءات الإجراءات، وليس قناة IPC.
الافتراضي: false
dso_entry
بالنسبة لـ DSO PMDA، هذا هو اسم دالة التهيئة الخاصة بـ PMDA.
الافتراضي: ${iam}_init
dso_name
بالنسبة لـ DSO PMDA، هذا هو المسار الكامل لملف DSO الخاص بـ PMDA.
الافتراضي: $PCP_PMDAS_DIR/$iam/pmda_$iam.$dso_suffix
pipe_opt
بالنسبة لـ PMDA الخادم، هل قناة IPC الافتراضية عبر pipe(2)؟
الافتراضي: يعتمد على المنصة، لذا true لمعظمها، ولكن false لنظام Windows
perl_opt
نحن على استعداد لتثبيت PMDA كنص Perl وسيستخدم pmcd(1) مفسر perl(1) لتشغيل PMDA.
الافتراضي: false
pmda_dir
المسار الكامل للدليل الذي توجد فيه ملفات تثبيت PMDA (الملف التنفيذي، النص، مصدر PMNS، مصدر نص المساعدة، إلخ).
الافتراضي: ناتج pwd(1)

إذا تم تعيينه، يجب القيام بذلك قبل استدعاء pmdaSetup.

pmda_name
بالنسبة لـ PMDA الخادم، هذا هو اسم الملف الثنائي التنفيذي الخاص بـ PMDA بالنسبة للدليل $pmda_dir.
الافتراضي: pmda$iam
python_opt
نحن على استعداد لتثبيت PMDA كنص Python وسيستخدم pmcd(1) مفسر python(1) لتشغيل PMDA.
الافتراضي: false
