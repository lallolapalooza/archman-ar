PMLOGEXTRACT(1) دليل الأوامر العامة PMLOGEXTRACT(1)

الاسم

pmlogextract - تقليل، استخراج، دمج وضم أرشيفات Performance Co-Pilot

الملخص

pmlogextract [-dfmwxz?] [-c ملف_الإعداد] [-D تصحيح] [-S وقت_البداية] [-s عينات] [-T وقت_النهاية] [-V إصدار] [-v حجم_وحدة] [-Z منطقة_زمنية] المدخل [...] المخرج

الوصف

يقرأ pmlogextract أرشيف واحد أو أكثر من Performance Co-Pilot (PCP) معرفة بواسطة المدخل وينشئ أرشيف PCP مدمج و/أو مخفض في المخرج. كل وسيط مدخل هو إما اسم أو قائمة أسماء مفصولة بفواصل، وكل اسم هو اسم ملف واحد من أرشيف أو الاسم الأساسي لأرشيف أو اسم دليل يحتوي على أرشيف واحد أو أكثر. يتم التحكم في طبيعة الدمج بواسطة عدد أرشيفات المدخل، بينما يتم التحكم في طبيعة تقليل البيانات بواسطة وسائط سطر الأوامر. يجب أن تكون وسائط المدخل أرشيفات تم إنشاؤها بواسطة pmlogger(1) مع بيانات أداء تم جمعها من نفس المضيف، ولكن عادةً عبر فترات زمنية مختلفة وربما (على الرغم من أنه ليس عادةً) مع مقاييس أداء مختلفة يتم تسجيلها.

إذا تم تحديد مدخل واحد فقط، فإن السلوك الافتراضي ينسخ ببساطة أرشيف PCP المدخل (مع تحويل محتمل إلى إصدار أحدث من تنسيق الأرشيف، انظر -V أدناه)، إلى أرشيف PCP المخرج. عند تحديد أرشيفين أو أكثر من PCP كوسائط مدخل، يتم دمج الأرشيفات (أو تسلسلها) وكتابتها إلى المخرج.

في أرشيف المخرج، قد يتم إدراج سجل <mark> في وقت يقع بعد نهاية كل أرشيف مدخل للإشارة إلى وجود انقطاع زمني محتمل بين نهاية أرشيف مدخل واحد وبداية أرشيف مدخل التالي. انظر قسم سجلات العلامة أدناه لمزيد من المعلومات. لا يوجد سجل <mark> بعد نهاية آخر (بالترتيب الزمني) سجلات من أرشيفات المدخل.

الخيارات

الخيارات المتاحة لسطر الأوامر هي:

-c إعداد, --config=إعداد
استخرج فقط المقاييس المحددة في إعداد من أرشيف (أو أرشيفات) PCP المدخل. تم شرح بناء جملة الإعداد المقبولة بواسطة pmlogextract بمزيد من التفصيل في قسم بناء جملة ملف الإعداد.
-d, --desperate
وضع اليأس. عادةً، إذا حدث خطأ فادح، تتم إزالة جميع آثار أرشيف PCP المخرج المكتوب جزئيًا. مع الخيار -d، لا تتم إزالة أرشيف المخرج.
-f, --first
للاستخدامات الأكثر شيوعًا، سيتم جمع جميع أرشيفات المدخل في نفس المنطقة الزمنية. ولكن إذا لم يكن هذا هو الحال، فيجب على pmlogextract اختيار إحدى المناطق الزمنية من أرشيفات المدخل لاستخدامها كمنطقة زمنية لأرشيف المخرج. الافتراضي هو استخدام المنطقة الزمنية من أرشيف المدخل الأخير. يجبر الخيار -f على استخدام المنطقة الزمنية من أرشيف المدخل الأول.
-m, --mark
كما هو موضح في قسم سجلات العلامة أدناه، من الممكن في بعض الأحيان حذف سجلات <mark> بأمان من أرشيف المخرج. إذا تم تحديد الخيار -m، فسيتم تخطي اختبار النهاية والبداية وسيتم دائمًا إدراج سجل <mark> في نهاية كل أرشيف مدخل (باستثناء الأخير). هذا هو السلوك الأصلي لـ pmlogextract.
-S وقت_البداية, --start=وقت_البداية
تحديد بداية نافذة زمنية لتقييد السجلات المعالجة؛ ارجع إلى PCPIntro(1). انظر أيضًا الخيار -w.
-s عينات, --samples=عينات
يحدد الوسيط عينات عدد العينات (أو السجلات) التي سيتم كتابتها إلى المخرج. إذا كانت عينات تساوي 0 أو لم يتم تحديد -s، فسيستمر pmlogextract حتى نهاية جميع أرشيفات المدخل أو حتى نهاية النافذة الزمنية كما هو محدد بواسطة -T، أيهما يأتي أولاً. سيتجاوز الخيار -s الخيار -T إذا حدث قبل ذلك.
-T وقت_النهاية, --finish=وقت_النهاية
تحديد نهاية نافذة زمنية لتقييد السجلات المعالجة؛ ارجع إلى PCPIntro(1). انظر أيضًا الخيار -w.
-V إصدار, --outputversion=إصدار
لكل أرشيف PCP إصدار لتنسيق السجل المادي، حاليًا 2 أو 3. افتراضيًا، يتم إنشاء أرشيف المخرج بإصدار يساوي الحد الأقصى لإصدار أرشيفات المدخل. يمكن استخدام الخيار -V لفرض الإصدار صراحةً لـ المخرج، شريطة ألا يكون الإصدار أصغر من إصدار الأرشيف الذي كان سيتم اختياره بواسطة القاعدة الافتراضية.

على سبيل المثال، قد يتم استخدام تحديد -V 3 لإنتاج أرشيف مخرج من الإصدار 3 من أرشيفات مدخل يمكن أن تكون مزيجًا من الإصدار 2 و/أو 3.

-v حجم_وحدة
من المحتمل أن يكون أرشيف المخرج عبارة عن مجموعة بيانات متعددة الوحدات، ويؤدي الخيار -v إلى قيام pmlogextract ببدء وحدة جديدة بعد الوصول إلى حجم وحدة الأرشيف حجم_وحدة. إذا كان حجم_وحدة عبارة عن عدد صحيح، فسيتم كتابة 100 سجل على الأكثر إلى كل وحدة. إذا كان حجم_وحدة عبارة عن عدد صحيح متبوع بـ b أو bytes، فسيتم كتابة 100 بايت على الأكثر إلى كل وحدة. وحدات حجم الملف الأخرى الصالحة تشمل: K، Kb، KiB، Kbyte، Kilobyte للكيلوبايت و M، Mb، MiB، Mbyte، Megabyte للميجابايت و G، Gb، GiB، Gbyte، Gigabyte للجيجابايت. قد يتم إضافة s اختياريًا إلى هذه الوحدات وقد تكون بأحرف مختلطة. بدلاً من ذلك، قد يكون حجم_وحدة عددًا صحيحًا أو رقمًا عشريًا متبوعًا بوحدة زمنية كما هو موضح في PCPIntro(1) للوسيط الفاصل الزمني (إلى خيار سطر الأوامر القياسي لـ PCP -t). 
بعض الأمثلة للتنسيقات المختلفة:
-s 100
-s 100bytes
-s 100K
-s 100Mb
-s 10Gbyte
-s 10mins
-s 1.5hours

الافتراضي هو أن يقوم pmlogextract بإنتاج أقل عدد ممكن من الوحدات.

بصرف النظر عن أي خيار -v، فإن كل وحدة من الأرشيف محدودة بما لا يزيد عن 2^31 بايت، لذا سيقوم pmlogextract تلقائيًا بإنشاء وحدة جديدة للأرشيف قبل الوصول إلى هذا الحد.

-w
حيث يحدد -S و -T نافذة زمنية داخل نفس اليوم، سيؤدي العلم -w إلى استخراج البيانات داخل النافذة الزمنية، لكل يوم في الأرشيف. على سبيل المثال، تحدد الخيارات -w -S @11:00 -T @15:00 أن pmlogextract يجب أن يشمل سجلات الأرشيف فقط للفترات من 11 صباحًا إلى 3 مساءً كل يوم. عند استخدام -w، سيحتوي أرشيف المخرج على سجلات <mark> للإشارة إلى الانقطاع الزمني بين نهاية نافذة زمنية واحدة وبداية النافذة التالية.
-x
من المتوقع أن تكون البيانات الوصفية (الاسم، PMID، النوع، الدلالات، والوحدات) لكل مقياس متسقة عبر جميع أرشيفات PCP المدخل التي يظهر فيها هذا المقياس. في حالات نادرة، على سبيل المثال في التطوير، في ضمان الجودة وعند ترقية PMDA، قد لا يكون هذا هو الحال وسيقوم pmlogextract بالإبلاغ عن المشكلة والإجهاض دون إنشاء أرشيف المخرج. يتم ذلك لتصحيح المشكلة باستخدام pmlogrewrite(1) قبل إعادة محاولة الدمج. في البيئات غير المراقبة أو بيئات ضمان الجودة، قد يكون من الأفضل فرض الدمج واستبعاد المقاييس ذات البيانات الوصفية غير المتطابقة. يقوم الخيار -x بذلك.
-Z منطقة_زمنية, --timezone=منطقة_زمنية

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

OPTIONS

-t
Use timezone when displaying the date and time in diagnostics. Timezone is in the format of the environment variable TZ as described in environ(7). The default is to initially use the timezone of the local host.
-z, --hostzone
Use the local timezone of the host from the input archive(s) when displaying the date and time in diagnostics. The default is to initially use the timezone of the local host.
-?, --help
Display usage message and exit.

تنسيق ملف التكوين

يحتوي configfile على المقاييس ذات الأهمية - فقط تلك المقاييس (أو المثيلات) المذكورة بشكل صريح أو ضمني في ملف التكوين سيتم تضمينها في أرشيف output. يجب أن يبدأ كل تحديد في سطر جديد، وقد يمتد عبر عدة أسطر في ملف التكوين. يمكن أيضًا تحديد المثيلات، ولكنها اختيارية. تنسيق كل تحديد هو

        metric
or
        metric [ instance ... ]

حيث يمكن أن يكون metric عقدة طرفية أو عقدة غير طرفية في مساحة أسماء مقاييس الأداء (PMNS، انظر PMNS(5)). إذا أشارت metric إلى عقدة غير طرفية في PMNS، فإن pmlogextract سينزل بشكل متكرر في PMNS وسيشمل جميع المقاييس المقابلة للعقد الطرفية المنحدرة.

المثيلات اختيارية ويتم تحديدها كقائمة مفصولة بمسافة (أو فاصلة) من معرفات instance، مع إحاطة القائمة بأقواس مربعة. قد يكون كل معرف instance رقمًا أو سلسلة نصية (محاطة بعلامات اقتباس فردية أو مزدوجة). يُفترض أن معرفات instance التي هي أرقام هي معرفات مثيلات داخلية، وإلا يُفترض أن القيم النصية هي معرفات مثيلات خارجية؛ انظر pmGetInDom(3) لمزيد من المعلومات. إذا لم يتم تقديم أي مثيلات، فسيتم استخراج **جميع** مثيلات المقاييس المرتبطة.

يتم تجاهل أي مسافات بيضاء إضافية ويمكن إضافة تعليقات باستخدام البادئة '#'.

مثال على ملف التكوين

هذا مثال على configfile صالح:


#
# config file for pmlogextract
#


kernel.all.cpu
kernel.percpu.cpu.sys ["cpu0","cpu1"]
disk.dev ["dks0d1"]

سجلات العلامات

عندما يساهم أكثر من أرشيف input واحد ببيانات الأداء في أرشيف output، يمكن إدراج سجلات <mark> للإشارة إلى انقطاع محتمل في بيانات الأداء.

يحتوي سجل <mark> على طابع زمني ولا يحتوي على بيانات أداء ويستخدم للإشارة إلى وجود فترة زمنية في أرشيف PCP حيث لا نعرف قيم **أي** مقاييس أداء، لأنه لم يكن هناك pmlogger(1) يجمع بيانات الأداء خلال هذه الفترة. نظرًا لأن هذه الفترات غالبًا ما ترتبط بإعادة تشغيل خدمة أو pmcd(1) أو إعادة تشغيل النظام، فقد يكون هناك شك كبير في استمرارية بيانات الأداء عبر هذه الفترة الزمنية.

يتم إنشاء معظم الأرشيفات الحالية بسجل prologue في البداية وسجل epilogue في النهاية. تحدد هذه السجلات حالة pmcd(1) في ذلك الوقت، وقد تستخدمها pmlogextract لتحديد عدم وجود انقطاع بين نهاية أرشيف والسجل التالي في الإخراج، ونتيجة لذلك، يمكن حذف سجل <mark> بأمان من أرشيف output.

يمكن توضيح منطق سجلات <mark> بمثال. ضع في اعتبارك أرشيف input واحد يبدأ في 00:10 وينتهي في 09:15 في نفس اليوم، وأرشيف input آخر يبدأ في 09:20 في نفس اليوم وينتهي في 00:10 صباح اليوم التالي. ستكون هذه حالة شائعة جدًا للأرشيفات التي تتم إدارتها وتدويرها بواسطة pmlogger_check(1) و pmlogger_daily(1).

سيحتوي أرشيف output الذي تم إنشاؤه بواسطة pmlogextract على:
00:10.000    السجل الأول من أرشيف الإدخال الأول
...
09:15.000    السجل الأخير من أرشيف الإدخال الأول
09:15.001    سجل <mark>
09:20.000    السجل الأول من أرشيف الإدخال الثاني
...
01:10.000    السجل الأخير من أرشيف الإدخال الثاني

الفترة الزمنية التي تكون فيها بيانات الأداء مفقودة تبدأ بعد 09:15 مباشرة وتنتهي قبل 09:20 مباشرة. عند معالجة أرشيف output باستخدام أي من أدوات إعداد تقارير PCP، يتم استخدام سجل <mark> للإشارة إلى فترة البيانات المفقودة. على سبيل المثال، باستخدام أرشيف output أعلاه، تخيل أنك تقوم بالإبلاغ عن متوسط معدل الإدخال/الإخراج على فترات 30 دقيقة محاذية للساعة ونصف الساعة. مقياس عدد الإدخال/الإخراج هو عداد، لذلك يتطلب متوسط معدل الإدخال/الإخراج قيمتين صالحتين من أوقات العينات المتتالية. ستكون هناك قيم لجميع الفترات التي تنتهي في 09:00، ثم لا توجد قيم في 09:30 بسبب سجل <mark>، ثم لا توجد قيم في 10:00 لأن القيمة "السابقة" في 09:30 غير متوفرة، ثم سيتم الإبلاغ عن المعدل مرة أخرى في 10:30 وسيستمر كل 30 دقيقة حتى آخر قيمة تم الإبلاغ عنها في 01:00.

يمكن التحقق من وجود سجلات <mark> في أرشيف PCP باستخدام pmlogdump(1) حيث يتم استخدام طابع زمني وتعليق <mark> للإشارة إلى سجل <mark>.

فحوصات البيانات الوصفية

عند تحديد أكثر من أرشيف input واحد، يقوم pmlogextract بإجراء عدد من الفحوصات للتأكد من اتساق البيانات الوصفية للمقاييس التي تظهر في أكثر من أرشيف input واحد. تشمل هذه الفحوصات:

  • نوع بيانات المقياس هو نفسه
  • دلالات المقياس هي نفسها
  • وحدات المقياس هي نفسها
  • المقياس هو دائمًا مفرد أو له دائمًا نفس نطاق المثيل
  • المقاييس بنفس الاسم لها نفس PMID
  • المقاييس بنفس PMID لها نفس الاسم

إذا فشل أي من هذه الفحوصات، يقوم pmlogextract بالإبلاغ عن التفاصيل ويتوقف دون إنشاء أرشيف output.

لمعالجة هذه المشكلات الدلالية، استخدم pmlogrewrite(1) لترجمة أرشيفات input إلى أرشيفات مكافئة ببيانات وصفية متسقة قبل استخدام pmlogextract.

راجع خيارات سطر الأوامر -x و -d أعلاه للبدائل لمعالجة الأخطاء الافتراضية أثناء فحوصات البيانات الوصفية.

تحذيرات

قد لا تكون مقاييس prologue (pmcd.pmlogger.archive, pmcd.pmlogger.host, و pmcd.pmlogger.port)، والتي يسجلها pmlogger تلقائيًا في بداية الأرشيف، موجودة في الأرشيف الذي تم إنتاجه بواسطة pmlogextract. هذه المقاييس ذات صلة فقط أثناء إنشاء الأرشيف، وليس لها أهمية بمجرد انتهاء التسجيل.

التشخيص

يتم الإبلاغ عن جميع حالات الخطأ التي يكتشفها pmlogextract على stderr مع شرح نصي (وإن كان موجزًا في بعض الأحيان).

إذا كان أحد أرشيفات input لا يحتوي على أي سجلات أرشيف، يتم إصدار تحذير "أرشيف فارغ" ويتم تخطي هذا الأرشيف.

في حال كان أحد أرشيفات input تالفًا (يمكن أن يحدث هذا إذا توقفت عملية pmlogger التي تكتب الأرشيف فجأة)، فإن pmlogextract سيكتشف ويبلغ عن موضع التلف في الملف، ولن تتم معالجة أي معلومات لاحقة من هذا الأرشيف.

إذا تم اكتشاف أي خطأ، سيخرج pmlogextract بحالة غير صفرية.

الملفات

لكل أرشيف input و output، يتم استخدام عدة ملفات فعلية.

archive.meta
البيانات الوصفية (أوصاف المقاييس، نطاقات المثيلات، إلخ) للأرشيف
archive.0
المجلد الأولي لقيم المقاييس (المجلدات اللاحقة لها لاحقات 1، 2، ...) - بالنسبة للمدخلات input، قد تكون هذه الملفات مضغوطة مسبقًا باستخدام bzip2(1) أو gzip(1) وبالتالي قد يكون لها لاحقة إضافية .bz2 أو .gz.
archive.index
فهرس زمني لدعم الوصول العشوائي السريع إلى الملفات الأخرى في الأرشيف.

بيئة PCP

تُستخدم متغيرات البيئة ذات البادئة PCP_ لتحديد أسماء الملفات والأدلة التي تستخدمها PCP. في كل تثبيت، يحتوي الملف /etc/pcp.conf على القيم المحلية لهذه المتغيرات. يمكن استخدام المتغير $PCP_CONF لتحديد ملف تكوين بديل، كما هو موضح في pcp.conf(5).

بالنسبة لمتغيرات البيئة التي تؤثر على أدوات PCP، انظر pmGetOptions(3).

خيارات التصحيح

يمكّن الخيار -D أو --debug من إخراج تشخيصات إضافية على stderr للمساعدة في تتبع المشكلات، على الرغم من أن المعلومات تكون غامضة أحيانًا ومخصصة بشكل أساسي لتوفير التوجيه للمطورين بدلاً من المستخدمين النهائيين. debug هي قائمة مفصولة بفواصل من خيارات التصحيح؛ استخدم pmdbg(1) مع الخيار -l للحصول على قائمة بخيارات التصحيح المتاحة ومعناها.

NAME

pmlogextract - extract performance metrics from archive records

SYNOPSIS

pmlogextract [-cconfigfile] [-h] [-r] [-tindention] [-Ttitle] [-v] [logfile]

DESCRIPTION

pmlogextract is a utility that extracts performance metrics from a Performance Co-Pilot (PCP) archive, and may optionally format them for display.

The extracted metrics are described by a configuration file, which is specified using the -c option. If no configuration file is provided, a default configuration is used.

The extracted metrics are printed to standard output in a human-readable format. The output may be customized using the options described below.

OPTIONS

-cconfigfile
Specify the name of the configuration file to use. If this option is not specified, a default configuration file will be used. See also the CONFIGURATION FILE SYNTAX section.
-h
Print a help message and exit.
-r
Print the extracted metrics in reverse order of time.
-tindention
Specify the indentation string to use for the output. The default indentation string is two spaces.
-Ttitle
Specify a title string to be printed at the beginning of the output. The default title is "pmlogextract".
-v
Print verbose output, including debugging information.

CONFIGURATION FILE SYNTAX

The configuration file specifies the performance metrics to be extracted and how they should be formatted. The configuration file is a text file that contains a series of stanzas, each of which describes a set of metrics to be extracted.

Each stanza consists of a type identifier followed by a list of metric descriptions. The type identifier specifies the type of operations to be performed. The following type identifiers are supported:

debug

enable parser diagnostics for configfile if -c specified

appl1

memory allocations and reclist operations

appl2

time window and end-of-file tests

appl3

input and output archive version decisions

appl4

instance domain juggling

appl5

output volume switching

A metric description consists of a metric name followed by a list of optional arguments. The metric name is a string that identifies the metric. The arguments are used to specify how the metric should be extracted and formatted.

The following arguments are supported:

archive
Extract the metric from the specified archive.
interval
Extract the metric at the specified interval.
print
Print the extracted metric in the specified format.
where
Extract the metric only when the specified condition is met.

CONFIGURATION FILE EXAMPLE

The following is an example of a configuration file:

appl1 {
    metric1 print("value: %d\n") archive("/var/log/pcp/pmlog.1") interval(1000)
    metric2 print("value: %d\n") archive("/var/log/pcp/pmlog.2") interval(500)
}
appl2 {
    metric3 print("value: %d\n") where("time > 10000")
}

MARK RECORDS

The pmlogextract utility can be used to extract and display mark records from a PCP archive. Mark records are special records that are used to annotate the archive with important events or information.

To extract mark records, you can use the -m option. This option takes a comma-separated list of mark names to extract. If no mark names are specified, all mark records will be extracted.

For example, to extract all mark records, you would use the following command:

pmlogextract -m logfile

To extract only mark records named "START" and "STOP", you would use the following command:

pmlogextract -m START,STOP logfile

METADATA CHECKS

The pmlogextract utility performs several metadata checks to ensure the integrity of the PCP archive. These checks include verifying the archive header, checking for corrupted records, and ensuring that the archive is consistent with the system's metadata.

If any of these checks fail, pmlogextract will report an error and exit. You can use the -v option to enable verbose output, which will provide more detailed information about the metadata checks.

CAVEATS

The pmlogextract utility is a powerful tool, but it should be used with caution. Incorrectly configured or used, it can lead to unexpected results or data loss.

DIAGNOSTICS

The pmlogextract utility generates various diagnostic messages, which are printed to standard error. These messages provide information about the utility's operation, including any errors or warnings that may have occurred. The verbosity of these messages can be controlled using the -v option.

If the -c option is specified, parser diagnostics for the specified configuration file can be enabled. This is useful for debugging issues with the configuration file syntax or content.

Diagnostics Table
Type Description
debug parser diagnostics for configfile if -c specified
appl1 memory allocations and reclist operations
appl2 time window and end-of-file tests
appl3 input and output archive version decisions
appl4 instance domain juggling
appl5 output volume switching

FILES

The default configuration file is located at $PCP_SYSCONFDIR/pmlogextract.conf.

PCP ENVIRONMENT

Environment variables with the prefix PCP_ are used to control the behavior of pmlogextract, as described in pcp.env(5).

DEBUGGING OPTIONS

The -v option enables verbose output, which can be helpful for debugging. For more advanced debugging, you can set the PCP_DEBUG environment variable to a comma-separated list of debugging keywords. See pcp.env(5) for a list of available debugging keywords.
