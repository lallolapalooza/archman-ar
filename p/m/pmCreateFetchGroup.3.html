الوصف

وظائف مجموعة الجلب (fetchgroup) تنفذ آلية قائمة على التسجيل لجلب مجموعات من مقاييس الأداء، بما في ذلك الأتمتة للتحويلات العامة للوحدات، المعدلات، والأنواع، بالإضافة إلى ترميزات ملائمة للحالات والقيم. تشكل بديلاً قوياً وموجزاً لواجهة برمجة تطبيقات مقاييس الأداء التقليدية (PMAPI(3)) التي تتكون من تسلسل منفصل من وظائف البحث، التحقق، الجلب، التكرار، الاستخراج، والتحويل.

الفكرة العامة تتكون من مرحلتين. في مرحلة الإعداد، يحدد التطبيق المقاييس ذات الأهمية بالاسم ومع التحويلات المطلوبة، ويسجل موقع إخراج فريد pmAtomValue حيث يجب على نظام مجموعة الجلب لاحقًا إيداع النتيجة. من الممكن أيضًا تحديد مقياس مع نطاق حالات (instance domain)، وتسجيل متجه فريد من كائنات pmAtomValue لها. في مرحلة التشغيل، تقوم وظيفة pmFetchGroup بسيطة واحدة بجلب، فك تشفير، تحويل، وتخزين جميع المقاييس في وجهاتها، حيث يمكن للتطبيق *قراءتها* مباشرة. يمكن استدعاء هذه الوظيفة بشكل متكرر، وفي كل مرة سيتم تخزين قيم pmAtomValue جديدة في نفس الوجهات. يمكن طلب تحويلات المعدل بين العينات المتتالية.

ترتبط كل مجموعة جلب بسياق PMAPI خاص، لذلك يمكنها معالجة ملفات تعريف الحالات (instance profiles) وحالة أخرى دون تعطيل السياقات الأخرى. يتم معالجة ملف تعريف الحالات لتحسين عمليات جلب العناصر الفردية، حتى لو كانت بعضها مقاييس مشتقة. سياق PMAPI الخاص هذا ينتمي إلى مجموعة الجلب، ويستخدم لجميع عملياته الداخلية، وسيتم تدميره.

يمكن استخدام مجموعات جلب متعددة بشكل متزامن، بشكل مستقل. يستخدم نوع غير شفاف pmFG لتحديد مجموعة جلب، والذي يتم تمريره إلى جميع استدعاءات الوظائف ذات الصلة.

إنشاء مجموعة جلب

int pmCreateFetchGroup(pmFG *ptr،
int type، const char *name);

تقوم هذه الوظيفة بإنشاء مجموعة جلب جديدة، مرتبطة بسياق PMAPI جديد. يتم تمرير المعاملين type و name إلى pmNewContext(3) لإنشاء السياق. يتم إرجاع معرّف مجموعة الجلب عند النجاح عبر المؤشر ptr. يتم استخدام هذا الكائن لاحقًا كمعامل لجميع وظائف مجموعة الجلب الأخرى. يمكن الوصول إلى سياق PMAPI الخاص باستخدام pmGetFetchGroupContext، إذا لزم الأمر.

رمز الإرجاع الطبيعي للوظيفة هو صفر، ويتم تعيين ptr. قد تفشل هذه الوظيفة في حالة أخطاء pmNewContext أو أخطاء تخصيص الذاكرة. تتم الإشارة إلى هذه الأخطاء برمز إرجاع سلبي وقيمة ptr مسحوبة.

الحصول على سياق PMAPI الخاص

int pmGetFetchGroupContext(pmFG pmfg);

تقوم هذه الوظيفة بإرجاع سياق PMAPI الخاص الذي تستخدمه مجموعة الجلب المحددة. يمكن استخدامه بأمان لتعديل بعض معلمات تكوين السياق، مثل عبر pmSetMode(3)، قبل بدء تمديد مجموعة الجلب وجلب البيانات.

ومع ذلك، فإن *تغيير* هذا السياق بواسطة وظائف PMAPI بعد هذا الوقت قد يعطل وظائف مجموعة الجلب. على سبيل المثال، يمكن لاستدعاء pmSetMode إبطال خطوة زمنية واحدة لتحويل المعدل.

رمز الإرجاع الطبيعي للوظيفة هو رقم السياق.

تمديد مجموعة جلب بمقياس حالة محل اهتمام

int pmExtendFetchGroup_item(pmFG pmfg،
const char *metric، const char *instance، const char *scale، pmAtomValue *out_value، int out_type، int *out_sts);

تسجل هذه الوظيفة الاهتمام بمقياس واحد وحالة اختيارية. يتم توفير اسم المقياس في المعامل الإلزامي metric، والذي يتم التحقق منه فورًا عبر pmLookupName(3) واستدعاءات أخرى. إذا وفقط إذا كان للمقياس نطاق حالات، يمكن تسمية الحالة المحددة محل الاهتمام بواسطة المعامل instance، والذي يتم التحقق منه فورًا عبر pmNameInDom(3)؛ بخلاف ذلك، مرر NULL. إذا كان سياق مجموعة الجلب هو مجموعة من الأرشيفات، فمن الممكن أن زوج المقياس / الحالة غير معرف بعد عند أصل الوقت الحالي. لذلك، قد تحاول هذه الوظيفة البحث في *نهاية* مجموعة الأرشيفات الحالية *مؤقتًا* لإعادة محاولة البحث عن المقياس / الحالة.

المعامل الاختياري scale يحدد التحويلات المطلوبة للوحدة / المقياس / المعدل لقيمة المقياس. يمكن أن يأخذ القيم التالية:

NULL
لا يوجد تحويل وحدة / مقياس. إذا كان للمقياس دلالات PM_SEM_COUNTER، فقم بإجراء تحويل المعدل.
rate
إجراء تحويل المعدل بغض النظر عن الدلالات، ولا يوجد تحويل وحدة / مقياس.
instant
لا تقم بإجراء تحويل المعدل بغض النظر عن الدلالات، ولا يوجد تحويل وحدة / مقياس.
EXPRESSION
إجراء تحويل الوحدة / المقياس / المعدل كما هو محدد بواسطة التعبير، والذي يتم تحليله بواسطة pmParseUnitsStr(3). قد يكون هذا مفيدًا لفرض تحجيم معياري لقيمة المقياس الناتجة، بشكل مستقل عن إصدار PCP أو التكوين. يجب أن تتطابق الأبعاد مع المقياس، باستثناء إذا تم طلب تحويل المعدل، وفي هذه الحالة يجب أن يكون بُعد الوقت أصغر بواحد من بُعد وقت المقياس. لاحظ أن نوع تحويل المعدل الذي تم إجراؤه هنا يطابق وظيفة rate(x) في تعبيرات المقاييس المشتقة، حيث يتم حسابه كالفرق الحسابي البسيط بين القيم السابقة والحالية للمقياس، مقسومًا على الوقت المنقضي. على سبيل المثال، إذا التف عداد، أو انخفضت قيمة غير عداد، فقد يتم حساب معدل إخراج *سلبي*.

المعامل الاختياري ولكن المعتاد out_value يحدد pmAtomValue حيث يجب تخزين النتيجة المحولة لاحقًا.

NAME

pmCreateFetchGroup, pmDestroyFetchGroup, pmExtendFetchGroup_item, pmExtendFetchGroup_indom, pmExtendFetchGroup_timeval, pmExtendFetchGroup_timestamp, pmFetchGroup - create, extend, and fetch from a fetchgroup

C SYNOPSIS

int pmDestroyFetchGroup(pmFG pmfg);

int pmExtendFetchGroup_item(pmFG pmfg, const char *name, const char *units, const char *legacy_units, pmAtomValue *result, pm_type_t pmtype, int *sts);

int pmExtendFetchGroup_indom(pmFG pmfg, const char *name, const char *legacy_units, const char *instlist, char **instnames, pmAtomValue *values, pm_type_t pmtype, int *stss, int maxinst, int *numinst, int *sts);

int pmExtendFetchGroup_timeval(pmFG pmfg, struct timeval *t);

int pmExtendFetchGroup_timestamp(pmFG pmfg, pmTime_t *t);

int pmClearFetchGroup(pmFG pmfg);

int pmFetchGroup(pmFG pmfg);

DESCRIPTION

A fetchgroup is a collection of Performance Metrics Analysis API (PMAPI) metrics that are fetched together, either for efficiency, or to ensure that the values are consistent with respect to time. The context for the fetchgroup is established when it is created using pmCreateFetchGroup.

The pmfg argument is a pointer to an opaque structure that represents the fetchgroup. Fetchgroups are created by pmCreateFetchGroup and destroyed by pmDestroyFetchGroup.

Metrics are added to a fetchgroup using the various pmExtendFetchGroup_* functions. The arguments to these functions specify the metric name, optional units, an output location for the metric's value, the expected data type, and an optional status code location.

The result argument to pmExtendFetchGroup_item, pmExtendFetchGroup_indom, and pmExtendFetchGroup_timestamp are pointers to a pmAtomValue structure. The pmAtomValue structure is a union that can hold a value of any of the PMAPI's primitive data types.

The sts argument to pmExtendFetchGroup_item and pmExtendFetchGroup_indom is a pointer to an integer that will receive a performance metric status code. These status codes are used to report errors that occurred when fetching individual metrics or instances, and are distinct from the status codes returned by the fetchgroup functions themselves.

The legacy_units argument to pmExtendFetchGroup_item and pmExtendFetchGroup_indom allows for the specification of units that were valid in older versions of PCP. If non-NULL, these units will be used to convert the metric's value into the specified units. If NULL, no unit conversion will be performed.

The instlist, instnames, values, pmtype, stss, maxinst, and numinst arguments to pmExtendFetchGroup_indom are used to fetch instances of a metric. instlist is a comma-separated list of instance names to fetch. instnames will be populated with the actual instance names, values will be populated with the instance values, pmtype specifies the expected data type, stss will be populated with instance status codes, maxinst specifies the maximum number of instances to fetch, and numinst will be set to the actual number of instances fetched.

The t argument to pmExtendFetchGroup_timeval and pmExtendFetchGroup_timestamp is a pointer to a struct timeval or pmTime_t structure, respectively. These are used to store the timestamp associated with the fetched values. The timestamp is updated by pmFetchGroup to reflect the time at which the values were fetched.

Once metrics have been added to a fetchgroup, they can be fetched using pmFetchGroup. This function attempts to fetch all registered metrics and updates the corresponding output variables.

The fetchgroup may be cleared of its current fetch state using pmClearFetchGroup. This releases any dynamically stored state but keeps the PMAPI context intact for subsequent use. It frees any pointers such as indom instance names or strings that may have been stored in output variables.

When the fetchgroup is no longer needed, it may be explicitly freed with pmDestroyFetchGroup. This function releases all dynamically stored state, including the PMAPI context, and frees any pointers such as indom instance names or strings that may have been stored in output variables.

Clearing a fetchgroup

int pmClearFetchGroup(pmFG pmfg);

When the current fetch state of a fetchgroup is no longer needed, it may be explicitly reset with this function. It releases any dynamically stored state but keeps the private PMAPI context intact for subsequent use (i.e. no change to the context is made at all and the context remains at the current fetch offset). It frees any pointers such as indom instance names or strings that may have been stored in output variables.

Destroying a fetchgroup

int pmDestroyFetchGroup(pmFG pmfg);

When the fetchgroup is no longer needed, it may be explicitly freed with this function. It releases any dynamically stored state, as well as the private PMAPI context. It clears frees any pointers such as indom instance names or strings that may have been stored in output variables.

EXAMPLE

The following program demonstrates fetchgroup usage. Run it with different $PCP_DISK_UNITS environment variables to see different unit/rate conversion in effect.

#include <pcp/pmapi.h>
#include <stdio.h>
#define pcpassert(sts) \
    while (sts<0) { fprintf(stderr, "%s\n", pmErrStr(sts)); exit(42); }
int main()
{
    pmFG fg;
    pmAtomValue v, v2;
    enum { v3_maxnum = 100 };
    pmAtomValue v3_values[v3_maxnum];
    char *v3_names[v3_maxnum];
    int v3_stss[v3_maxnum];
    unsigned int v3_num;
    int sts, i;
    char *diskunits = getenv("PCP_DISK_UNITS");
    struct timeval t;
    sts = pmCreateFetchGroup(&fg, PM_CONTEXT_HOST, "local:");
    pcpassert(sts);
    sts = pmExtendFetchGroup_item(fg, "kernel.all.load", "1 minute",
                                  NULL, &v, PM_TYPE_FLOAT, NULL);
    pcpassert(sts);
    sts = pmExtendFetchGroup_item(fg, "kernel.all.idletime", NULL,
                                  "hour", &v2, PM_TYPE_DOUBLE, NULL);
    pcpassert(sts);
    sts = pmExtendFetchGroup_indom(fg, "disk.dev.total", diskunits,
                                   NULL, v3_names,
                                   v3_values, PM_TYPE_STRING,
                                   v3_stss, v3_maxnum, &v3_num, NULL);
    pcpassert(sts);
    sts = pmExtendFetchGroup_timeval(fg, &t);
    pcpassert(sts);
    for (i=0; i < 10; i++) {
        unsigned int j;
        char stamp[28];
        sts = pmFetchGroup(fg);
        pcpassert(sts);
        printf("%s", pmCtime(&t.tv_sec, stamp));
        printf("1-minute load: %f; idletime: %f h\n", v.f, v2.d);
        for (j=0; j < v3_num; j++) {
            if (v3_stss[j] == 0)
                 printf("disk %s i/o operations (%s): %s\n",
                        v3_names[j] ? v3_names[j] : "?",
                        diskunits ? diskunits : "-",
                        v3_values[j].cp);
        }
        sleep(1);
    }
    sts = pmDestroyFetchGroup(fg);
    pcpassert(sts);
    return 0;
}

UNUSUAL SITUATIONS

The fetchgroup API supports only the numeric, string and event metric types. Aggregates are rejected during pmExtendFetchGroup_*.

Any strings supplied by the fetchgroup API to the application are "owned" by the API. The application should consider them read-only, so it should not modify them nor free them.

Error codes are always negative integers, whether returned from fetchgroup functions as return value, or stored in out_sts type variables. Normal result codes are always zero.

Because of the unique ways in which extracted data is shared between the application and a fetchgroup, the functions in this API are not protected by the multi-threading mutexes conventional in other parts of PMAPI. Specifically, for any given pmFG, it is not safe to concurrently call two or more fetchgroup API functions, nor to traverse the registered output variables while calling one of the functions. Instead, the calling application must ensure that only one thread at a time uses these calls and the registered output variables. On the other hand, concurrency between different pmFG instances is unrestricted, because they share no global data.

Any pointers passed to a successful pmFetchGroupExtent_* call must stay valid throughout the lifetime of the fetchgroup, since future pmFetchGroup calls may write into them.

DIAGNOSTICS

The fetchgroup API offers several options for collecting diagnostics. Negative integer error codes may be returned from each function for serious conditions.

In addition, each output pmAtomValue may have a corresponding integer variable, where pmFetchGroup can store per-metric per-instance error codes.

As an alternative, per-metric per-instance error conditions are also signalled by setting the corresponding pmAtomValue to a sentinel value. If unambiguous and precise error detection is not required, this may be sufficient. The sentinel value is negative one for all integers (including unsigned integers - i.e. all bits are set), NaN for floating point types, a NULL pointer for strings, and 0.0s for the timestamp. The fetchgroup API guarantees that once an output pmAtomValue is registered (during a successful pmExtendFetchGroup_* call), it will be cleared to the sentinel value or to a valid converted metric value, from the time of registration until the pmDestroyFetchGroup call.

COMPATIBILITY

Prior to PCP 7.0 the pmExtendFetchGroup_timestamp was an alias for pmExtendFetchGroup_timeval. To support PMAPI transition, the old interface and semantics can be used if applications are recompiled with -DPMAPI_VERSION=2.

pmExtendFetchGroup_timestamp although this is now deprecated and compile-time support will be removed in a future release.
