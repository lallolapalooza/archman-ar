الحزمة: pcp

PMDAPIPE(1) دليل الأوامر العامة PMDAPIPE(1)

الاسم

pmdapipe - وكيل مجال مقاييس الأداء لالتقاط مخرجات الأوامر (PMDA).

الملخص

$PCP_PMDAS_DIR/pipe/pmdapipe [-c ملف_التكوين] [-D التصحيح] [-d المجال] [-l ملف_السجل] [-m الذاكرة]

الوصف

pmdapipe هو وكيل مجال مقاييس أداء (PMDA) قابل للتكوين لمراقبة مخرجات الأوامر. يمكن اعتباره مكافئًا لقشرة مقيدة، حيث يمكن تمرير خيارات لأوامر محددة مسبقًا، ويتم تحويل كل سطر من مخرجاتها إلى حدث أداء. يمكن استهلاك هذه الأحداث بواسطة أدوات العميل مثل pmval(1).

يقوم PMDA pipe بتصدير كل من المقاييس بأسلوب الأحداث التي تعكس سجلات الأحداث المرفقة بالختم الزمني لمخرجات الأوامر النصية، بالإضافة إلى المقاييس التقليدية بأسلوب العينات مثل عدد الأحداث وقيم حجم الإنتاجية.

يتم تكوين PMDA عبر ملف_التكوين الذي يحتوي على سطر واحد لكل عملية يمكن التقاط مخرجاتها، كما هو موضح في قسم ``التكوين'' أدناه.

يتبع وصف موجز لخيارات سطر الأوامر لـ pmdapipe:

-c
يحدد ملف تكوين بديل لـ PMDA. افتراضيًا، يتم استخدام ملف باسم $PCP_PMDAS_DIR/pipe/pipe.conf وأي ملفات موجودة تحت الدليل $PCP_SYSCONF_DIR/pipe.conf.d/.
-d
من الأهمية بمكان أن يكون رقم المجال الخاص بمقاييس الأداء المحدد هنا فريدًا ومتسقًا. أي، يجب أن يكون المجال مختلفًا لكل PMDA على نفس المضيف، ويجب استخدام نفس رقم المجال لنفس PMDA على جميع المضيفين.
-l
موقع ملف السجل. افتراضيًا، يتم كتابة ملف سجل باسم pipe.log في الدليل الحالي لـ pmcd(1) عند بدء تشغيل pmdapipe، أي $PCP_LOG_DIR/pmcd. إذا تعذر إنشاء ملف السجل أو لم يكن قابلاً للكتابة، فسيتم كتابة المخرجات إلى الخطأ القياسي بدلاً من ذلك.
-m
يحد من الذاكرة الفعلية التي يستخدمها PMDA لتخزين سجلات الأحداث مؤقتًا إلى حجم_أقصى بايت. عندما تصل أحداث السجل إلى PMDA، يجب تخزينها مؤقتًا حتى تطلب أدوات العميل الفردية الدفعة التالية منذ دفعتها السابقة من الأحداث. الحد الأقصى الافتراضي هو 2 ميغابايت.

التكوين

يتم تكوين مجموعة أوامر الأنابيب المسموح بها بواسطة ملف (ملفات) نصي بسيط. التنسيق هو سطر واحد لكل أمر متبوعًا بقسم اختياري للتحكم في الوصول.

الأسطر الفارغة والتعليقات مسموح بها (بل ومشجعة) في ملف التكوين. يبدأ التعليق بحرف ``#'' وينتهي في نهاية السطر.

كل سطر تكوين أمر يكون بالشكل:

مثيل اسم_المستخدم الأمر خيارات

حيث:

مثيل
هو سلسلة نصية تحدد أمر الأنبوب، ويتم تصديرها أيضًا كمعرف مثيل للمقياس.
اسم_المستخدم
هو اسم حساب المستخدم الذي يجب تشغيل الأمر تحته (على سبيل المثال، ``root'')
الأمر
هو المسار إلى الملف الثنائي الذي سيتم تشغيله لتوليد المخرجات الممررة
خيارات
هي قائمة اختيارية مفصولة بمسافات للمعلمات التي سيتم تمريرها إلى الأمر
قد تحتوي قائمة الخيارات هذه على معلمات رقمية مسبوقة بعلامة الدولار ($)، وسيتم استبدال هذه المعلمات بقيم يحددها المستخدم في وقت تشغيل الأمر (مشابهة لاستبدال معلمات القشرة).

يتم تمرير المعلمات كسلسلة نصية واحدة مفصولة بمسافات أو بفواصل إلى مقياس pipe.firehose، باستخدام واجهة pmStore (3). يوفر الأمر pmval الوصول إلى التخزين عبر خياره -x. تقتصر المعلمات التي يحددها المستخدم على احتوائها على أحرف أبجدية رقمية.

يجب أن يبدأ قسم التحكم في الوصول في الملف بسطر بالشكل:

[access]

قد تظهر مسافات بادئة ولواحق حول وبين الأقواس، ولا يتم تجاهل حالة كلمة access. لا يجوز ظهور أي نص آخر في السطر باستثناء تعليق لاحق.

بعد هذا السطر، يجب أن يحتوي باقي ملف التكوين على أسطر تسمح أو تمنع استخدام الأوامر من مستخدمين أو مجموعات معينة.

سيتم التحقق من أسماء المستخدمين والمجموعات باستخدام ملفات /etc/passwd و /etc/groups المحلية (أو خدمة دليل بديلة)، باستخدام الإجراءات getpwent(3) و getgrent(3).

يتم السماح أو منع الوصول للمستخدمين أو المجموعات عن طريق تحديد عبارات بالشكل:

allow user اسم_المستخدم : مثيل
disallow user اسم_المستخدم : مثيل
allow group اسم_المجموعة : مثيل
disallow group اسم_المجموعة : مثيل

سيتم التحقق من أسماء اسم_المستخدم و اسم_المجموعة باستخدام ملفات /etc/passwd و /etc/groups المحلية (أو خدمة دليل بديلة)، باستخدام الإجراءات getpwent(3) و getgrent(3).

يمكن استخدام الحرف النائب ``*'' للإشارة إلى جميع أسماء المثيلات.

التثبيت

إذا كنت ترغب في الوصول إلى الأسماء والنصوص المساعدة والقيم الخاصة بمقاييس أداء الأنابيب، فقم بما يلي بصفتك root:

# cd $PCP_PMDAS_DIR/pipe
# ./Install

هذه عملية تثبيت تفاعلية تطلب لكل مسار سجل سيتم مراقبته (أو أمر سيتم تشغيله)، واسم مثيل للمقياس لتحديده، وما إذا كان سيتم تقييد الوصول (راجع الخيار -x للأمر pmval(1) لمزيد من التفاصيل).

إذا كنت ترغب في التراجع عن التثبيت، فقم بما يلي بصفتك root:

# cd $PCP_PMDAS_DIR/pipe
# ./Remove

يتم تشغيل pmdapipe بواسطة pmcd ولا يجب تنفيذه مباشرة أبدًا. تقوم نصوص التثبيت والإزالة بإخطار pmcd عند تثبيت الوكيل أو إزالته.

أمثلة

فيما يلي مثال بسيط لتكوين pmdapipe واستخدام مقاييس الأنابيب لتشغيل الأمر btrace، بواسطة المستخدم bob:


bob> cat $PCP_PMDAS_DIR/pipe/pipe.conf
# instance      user      command
rw_syscalls     root      perf script rw-by-file $1
bdev_trace      root      btrace -w $1 /dev/$2
[access]
allow user bob : *;
allow user jane : bdev_trace;
allow group perf : rw_syscalls;
bob> pmval -i bdev_trace -x '5 sda' pipe.firehose
 8,2  5  1  0.000000000 25227  A  WS 734332384 + 24 <- (253,2) 734330336
 8,0  5  2  0.000000414 25227  A  WS 735358432 + 24 <- (8,2) 734332384
 8,0  5  3  0.000000756 25227  Q  WS 735358432 + 24 [qemu-kvm]
 [...5 seconds worth]
bob>

الملفات

$PCP_PMCDCONF_PATH
خيارات سطر الأوامر المستخدمة لتشغيل pmdapipe
$PCP_PMDAS_DIR/pipe/pipe.conf
ملف التكوين الافتراضي لمقاييس الأنابيب
$PCP_PMDAS_DIR/pipe/help
ملف النص المساعد الافتراضي لمقاييس الأنابيب
$PCP_PMDAS_DIR/pipe/Install
سكريبت التثبيت لوكيل pmdapipe
$PCP_PMDAS_DIR/pipe/Remove
سكريبت إلغاء التثبيت لوكيل pmdapipe
$PCP_LOG_DIR/pmcd/pipe.log
ملف السجل الافتراضي لرسائل الخطأ والمعلومات الأخرى من pmdapipe
$PCP_SYSCONF_DIR/pipe.conf.d
الدليل الذي يحتوي على ملفات تكوين إضافية لمقاييس الأنابيب

بيئة PCP

تُستخدم متغيرات البيئة التي تبدأ بالبادئة PCP_ لضبط أسماء الملفات والأدلة المستخدمة بواسطة PCP. عند كل تثبيت، يتم استخدام ملف

pmdapipe(1) — Performance Co-Pilot

FILES

/etc/pcp.conf contains the local values for these variables.

The $PCP_CONF variable may be used to specify an alternative configuration file, as described in pcp.conf(5).

DEBUGGING OPTIONS

The -D or --debug option enables the output of additional diagnostics on stderr to help triage problems, although the information is sometimes cryptic and primarily intended to provide guidance for developers rather end-users. debug is a comma separated list of debugging options; use pmdbg(1) with the -l option to obtain a list of the available debugging options and their meaning.

Debugging options specific to pmdapipe are as follows:

Option Description
appl0 event processing and generation, interactions with pmcd(1), client context handling, command execution
appl1 access controls, user and group diagnostics
appl2 configfile handling, bad command argument diagnostics, select(2) handling
