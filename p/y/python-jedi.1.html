قد يكون استيراد numpy بطيئًا جدًا في بعض الأحيان، وكذلك تحميل الوحدات المدمجة لأول مرة. إذا كنت ترغب في تسريع الأمور، يمكنك تحميل الوحدات مسبقًا في Jedi، باستخدام preload_module(). ومع ذلك، بمجرد تحميلها، لا ينبغي أن تكون هذه مشكلة بعد ذلك. وينطبق الشيء نفسه على الوحدات الضخمة مثل PySide و wx و tensorflow و pandas وما إلى ذلك.

الأمان

لـ Script

الأمان موضوع مهم لـ Jedi. افتراضيًا، لا يتم تنفيذ أي كود داخل Jedi. طالما أنك تكتب Python نقيًا، يتم استنتاج كل شيء بشكل ثابت. إذا قمت بتمكين load_unsafe_extensions=True لـ Project الخاص بك واستخدمت وحدات مدمجة (c_builtin) فسيقوم Jedi بتنفيذ هذه الوحدات. إذا كنت لا تثق في قاعدة كود، فيرجى عدم تمكين هذا الخيار. قد يؤدي ذلك إلى تنفيذ تعليمات برمجية عشوائية.

لـ Interpreter

إذا كنت تريد الأمان لـ Interpreter، فلا تستخدمه. يقوم Jedi بتنفيذ الخصائص وبشكل عام ليس حذرًا جدًا لتجنب تنفيذ الكود. هذا متعمد: يثق معظم الناس في قواعد الكود التي استوردوها، لأنه في تلك المرحلة ستكون قاعدة كود ضارة قد قامت بالفعل بتنفيذ الكود.

نظرة عامة على واجهة برمجة التطبيقات

ملاحظة:

هذه الوثائق مخصصة في الغالب لمطوري الإضافات، الذين يرغبون في تحسين محرراتهم/بيئات التطوير المتكاملة الخاصة بهم باستخدام Jedi.

تتكون واجهة برمجة التطبيقات من عدة أجزاء مختلفة:

  • نقاط البداية الرئيسية للإكمال/الانتقال إلى: Script و Interpreter. إذا كنت تعمل مع Jedi، فأنت تريد فهم هذه الفئات أولاً.
  • فئات نتائج واجهة برمجة التطبيقات
  • دعم إصدارات Python/البيئات الافتراضية مع وظائف مثل find_system_environments() و find_virtualenvs()
  • طريقة للعمل مع المجلدات / المشاريع المختلفة
  • وظائف مفيدة: preload_module() و set_debug_function()

Script

class jedi.Script(code=None, *, path=None, environment=None, project=None)
Script هو الأساس للإكمال، الانتقال إلى، أو أي شيء آخر تريد القيام به مع Jedi. النظير لهذه الفئة هو Interpreter، الذي يعمل مع القواميس الفعلية ويمكنه العمل مع REPL. يجب استخدام هذه الفئة عندما يقوم المستخدم بتحرير الكود في محرر.

يمكنك استخدام المعلمة code أو path لقراءة ملف. عادةً ما ترغب في استخدام كليهما (في محرر).

sys.path الخاص بـ Script قابل للتخصيص بدرجة كبيرة:

  • إذا تم توفير project مع sys_path، فسيتم استخدام ذلك.
  • إذا تم توفير environment، فسيتم استخدام sys.path الخاص به (راجع Environment.get_sys_path)؛
  • بخلاف ذلك، سيتطابق sys.path مع المسار الافتراضي لـ Jedi، والذي يتطابق عادةً مع المسار الذي تم استخدامه عند استيراد Jedi.

تحتوي معظم الأساليب على معلمة line و column. الأسطر في Jedi دائمًا ما تكون بقاعدة 1، والأعمدة دائمًا ما تكون بقاعدة صفر. لتجنب التكرار، لا يتم توثيقها دائمًا. يمكنك حذف كل من line و column. سيقوم Jedi بعد ذلك بتنفيذ أي إجراء تستدعيه في نهاية الملف. إذا قمت بتوفير السطر فقط، فسيتم الإكمال في نهاية هذا السطر.

تحذير:

افتراضيًا، يتم تمكين jedi.settings.fast_parser، مما يعني أن parso يعيد استخدام الوحدات (أي أنها ليست ثابتة). مع هذا الإعداد، Jedi ليس آمنًا للاستخدام المتوازي وليس آمنًا أيضًا استخدام مثيلات Script متعددة وتعريفاتها في نفس الوقت.

الأخطاء

استثناء jedi.InternalError
قد يحدث هذا الخطأ عند تعطل عملية فرعية. السبب في ذلك عادة ما يكون رمز C تالفًا في مكتبات الطرف الثالث. هذا ليس شائعًا جدًا ومن الآمن استخدام Jedi مرة أخرى. ومع ذلك، قد يؤدي استخدام نفس الاستدعاءات إلى نفس الخطأ مرة أخرى.
استثناء jedi.RefactoringError
يمكن أن تفشل عمليات إعادة الهيكلة لأسباب مختلفة. لذلك، إذا كنت تعمل مع عمليات إعادة هيكلة مثل Script.rename()، Script.inline()، Script.extract_variable() و Script.extract_function()، تأكد من التقاطها. الأوصاف في الأخطاء تكون عادة قيمة للمستخدمين النهائيين.

سيخبر خطأ RefactoringError نموذجي المستخدم بأنه لا يمكن تضمين النص إذا لم يكن هناك اسم تحت المؤشر.

    This document describes the changes in jedi across its versions.

    0.19.2 (2024-11-18)

    • Improved completion for dataclass fields.
    • More accurate type inference for async generators.
    • Various bugfixes and performance improvements.

    • Fixed a bug causing incorrect completion in complex type hint scenarios.
    • Improved handling of partial function applications.
    • Enhanced support for PEP 695 (Type Parameter Syntax).

    0.19.0 (2024-09-15)

    • New feature: Support for PEP 695 (Type Parameter Syntax).
    • New feature: Improved completion for type aliases.
    • New feature: More robust handling of stub files (.pyi).
    • Refactored internal API for better maintainability.
    • Several bugfixes and performance enhancements.

    • Fixed a regression in completion for class methods.

    • New feature: Significant improvements to type inference for complex generics.
