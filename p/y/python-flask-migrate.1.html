الاسم

flask-migrate - وثائق Flask-Migrate

Flask-Migrate هو امتداد يعالج ترحيلات قواعد بيانات SQLAlchemy لتطبيقات Flask باستخدام Alembic. تتوفر عمليات قاعدة البيانات من خلال واجهة سطر الأوامر لـ Flask.

لماذا نستخدم Flask-Migrate مقابل Alembic مباشرة؟

Flask-Migrate هو امتداد يقوم بتكوين Alembic بالطريقة الصحيحة للعمل مع تطبيق Flask و Flask-SQLAlchemy الخاص بك. من حيث ترحيلات قاعدة البيانات الفعلية، يتم التعامل مع كل شيء بواسطة Alembic، لذلك تحصل على نفس الوظائف تمامًا.

التثبيت

قم بتثبيت Flask-Migrate باستخدام pip:

pip install Flask-Migrate

مثال

هذا مثال لتطبيق يعالج ترحيلات قاعدة البيانات من خلال Flask-Migrate:

from flask import Flask
from flask_sqlalchemy import SQLAlchemy
from flask_migrate import Migrate
app = Flask(__name__)
app.config['SQLALCHEMY_DATABASE_URI'] = 'sqlite:///app.db'
db = SQLAlchemy(app)
migrate = Migrate(app, db)
class User(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    name = db.Column(db.String(128))

مع التطبيق أعلاه، يمكنك إنشاء مستودع ترحيلات باستخدام الأمر التالي:

$ flask db init

سيؤدي ذلك إلى إضافة مجلد migrations إلى تطبيقك. يجب إضافة محتويات هذا المجلد إلى التحكم في الإصدار جنبًا إلى جنب مع ملفات المصدر الأخرى الخاصة بك.

يمكنك بعد ذلك إنشاء ترحيل أولي:

ثم يمكنك تطبيق التغييرات الموصوفة في نص الترحيل على قاعدة بياناتك:

$ flask db upgrade

في كل مرة تتغير فيها نماذج قاعدة البيانات، كرر أوامري migrate و upgrade.

لمزامنة قاعدة البيانات في نظام آخر، ما عليك سوى تحديث مجلد migrations من التحكم في الإصدار وتشغيل أمر upgrade.

لرؤية جميع الأوامر المتاحة، قم بتشغيل هذا الأمر:

$ flask db --help

لاحظ أن نص التطبيق يجب تعيينه في متغير البيئة FLASK_APP لكي تعمل جميع الأوامر المذكورة أعلاه، كما هو مطلوب بواسطة الأمر flask.

إذا كان اسم مجموعة الأوامر db غير مناسب، يمكن تغييره إلى اسم مختلف باستخدام الوسيطة command التي يتم تمريرها إلى الفئة Migrate:

migrate = Migrate(app, db, command='migrate')

خيارات تكوين Alembic

بدءًا من الإصدار 4.0، يُمكّن Flask-Migrate تلقائيًا الخيارات التالية التي يتم تعطيلها افتراضيًا في Alembic:

  • compare_type=True: يقوم هذا الخيار بتكوين نظام إنشاء الترحيل التلقائي لاكتشاف تغييرات أنواع الأعمدة.
  • render_as_batch=True: يقوم هذا الخيار بإنشاء نصوص ترحيل باستخدام وضع الدفعة، وهو وضع تشغيل يعمل على تجاوز قيود العديد من أوامر ALTER في قاعدة بيانات SQLite من خلال تنفيذ سير عمل "نقل ونسخ". لا ينبغي أن يؤدي تمكين هذا الوضع إلى أي فرق عند العمل مع قواعد بيانات أخرى.
migrate = Migrate(app, db, render_as_batch=False)

دوال استدعاء التكوين

في بعض الأحيان تحتاج التطبيقات إلى إدراج إعداداتها الخاصة ديناميكيًا في تكوين Alembic. سيتم استدعاء دالة مزينة بدالة استدعاء configure بعد قراءة التكوين، وقبل تطبيقه. يمكن للدالة تعديل كائن التكوين، أو استبداله بآخر.

@migrate.configure
def configure_alembic(config):
    # modify config object
    return config

يمكن تعريف دوال استدعاء تكوين متعددة ببساطة عن طريق تزيين دوال متعددة. ترتيب استدعاء دوال متعددة غير محدد.

دعم قواعد البيانات المتعددة

لإنشاء مستودع ترحيلات متعدد قواعد البيانات، أضف الوسيطة --multidb إلى أمر init:

$ flask db init --multidb

بهذا الأمر، سيتم إعداد مستودع الترحيلات لتتبع الترحيلات على قاعدة بياناتك الرئيسية، وعلى أي قواعد بيانات إضافية معرفة في خيار التكوين SQLALCHEMY_BINDS.

مرجع الأوامر

يكشف Flask-Migrate عن فئة واحدة تسمى Migrate. تحتوي هذه الفئة على جميع وظائف الامتداد.

يقوم المثال التالي بتهيئة الامتداد مع واجهة سطر الأوامر القياسية لـ Flask:

from flask_migrate import Migrate
migrate = Migrate(app, db)

الوسيطتان لـ Migrate هما نسخة التطبيق ونسخة قاعدة بيانات Flask-SQLAlchemy. يأخذ مُنشئ Migrate أيضًا وسائط زوج مفتاح-قيمة إضافية، والتي يتم تمريرها إلى طريقة EnvironmentContext.configure() الخاصة بـ Alembic. كما هو معتاد لجميع امتدادات Flask، يمكن تهيئة Flask-Migrate باستخدام طريقة init_app أيضًا:

from flask_sqlalchemy import SQLAlchemy
from flask_migrate import Migrate
db = SQLAlchemy()
migrate = Migrate()
def create_app():
     """Application-factory pattern"""
     ...
     ...
     db.init_app(app)
     migrate.init_app(app, db)
     ...
     ...
     return app

بعد تهيئة الامتداد، ستتم إضافة مجموعة db إلى خيارات سطر الأوامر مع العديد من الأوامر الفرعية. فيما يلي قائمة بالأوامر الفرعية المتاحة:

•
flask db --help
يعرض قائمة بالأوامر المتاحة.
•
flask db list-templates
يعرض قائمة بقوالب مستودع قاعدة البيانات المتاحة.
•
flask db init [--multidb] [--template TEMPLATE] [--package]
يهيئ دعم الترحيلات للتطبيق. الوسيطة الاختيارية --multidb تمكّن الترحيلات لقواعد بيانات متعددة

NAME

python-flask-migrate — Database schema migration for Flask applications using Alembic.

WHY USE FLASK-MIGRATE VS. ALEMBIC DIRECTLY?

Flask-Migrate is a Flask-specific wrapper around Alembic. It makes it easy to manage database schema migrations for Flask applications. Instead of configuring Alembic manually, Flask-Migrate handles the configuration for you. This means you can get started with database migrations in your Flask application with minimal setup.

However, if you need more advanced features or finer control over the migration process, you can always use Alembic directly. Flask-Migrate provides a convenient way to integrate Alembic into your Flask application, but it doesn't prevent you from using Alembic's full power when needed.

INSTALLATION

To install Flask-Migrate, you can use pip:

pip install Flask-Migrate

You will also need to have SQLAlchemy installed, as Flask-Migrate relies on it for database interactions.

pip install SQLAlchemy

EXAMPLE

Here's a simple example of how to use Flask-Migrate in your Flask application:

from flask import Flask
from flask_sqlalchemy import SQLAlchemy
from flask_migrate import Migrate, MigrateCommand

app = Flask(__name__)
app.config['SQLALCHEMY_DATABASE_URI'] = 'sqlite:///tmp/test.db'
db = SQLAlchemy(app)
migrate = Migrate(app, db)

# Define your models here
class User(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    username = db.Column(db.String(80), unique=True, nullable=False)

if __name__ == '__main__':
    # You can now use Flask-Migrate commands from your terminal
    # e.g., python manage.py db init, python manage.py db migrate, python manage.py db upgrade
    app.run(debug=True)

In this example, we initialize Flask-Migrate with our Flask app and SQLAlchemy database instance. You can then use the provided commands to manage your database migrations.

ALEMBIC CONFIGURATION OPTIONS

Flask-Migrate uses Alembic for migrations, and therefore all of Alembic's configuration options are available. These options can be set in your application's configuration, prefixed with SQLALCHEMY_MIGRATE_. For example, to set the Alembic script location, you would use:

app.config['SQLALCHEMY_MIGRATE_SCRIPT_LOCATION'] = 'migrations'

Refer to the Alembic documentation for a full list of available configuration options.

CONFIGURATION CALLBACKS

Flask-Migrate supports Alembic's configuration callbacks. These are functions that Alembic will call at various points during the migration process. This allows you to customize the migration behavior.

For example, you can define a env.py file in your migrations directory with the following:

from alembic import context
from my_flask_app.models import Base  # Import your SQLAlchemy base

# this is the Alembic Config object, which provides
# access to the values within the .ini file in use.
config = context.config

# Interpret the config file for Python values.
# This is necessary for Alembic to recognize the Flask app configuration.
def load_app():
    from my_flask_app import create_app
    app = create_app()
    return app

# add your model's MetaData object here
# for 'autogenerate' support
# from my_flask_app.models import Base
# target_metadata = Base.metadata
target_metadata = None

def run_migrations_offline():
    """Run migrations in 'offline' mode.

    This configures the context with just a URL
    and not an Engine, though an Engine is acceptable
    here as well.  By de fault the connection is selected
    using the URL stored in the ALEMBI C_CONFIG object.
    """
    app = load_app()
    context.configure(
        url=app.config.get('SQLALCHEMY_DATABASE_URI'),
        target_metadata=target_metadata
    )

    with context.begin_transaction():
        context.run_migrations()

def run_migrations_online():
    """Run migrations in 'online' mode.

    In this mode we don't know anything about the database,
    so we must get the state information from the database
    connection.
    """
    app = load_app()
    connectable = app.extensions['sqlalchemy'].db.engine

    with connectable.connect() as connection:
        context.configure(
            connection=connection,
            target_metadata=target_metadata
        )

        with context.begin_transaction():
            context.run_migrations()

if context.is_offline_mode():
    run_migrations_offline()
else:
    run_migrations_online()

This example shows how to load your Flask application and configure Alembic to use its database connection and metadata. This allows Alembic to automatically detect changes in your SQLAlchemy models and generate migration scripts.

MULTIPLE DATABASE SUPPORT

Flask-Migrate supports multiple databases. You can configure different database URIs in your Flask app's configuration and Flask-Migrate will use them accordingly.

For example:

app.config['SQLALCHEMY_DATABASE_URI'] = 'sqlite:///tmp/main.db'
app.config['SQLALCHEMY_BINDS'] = {
    'users': 'postgresql://user:password@host/users_db',
    'logs': 'mysql://user:password@host/logs_db'
}

When creating migrations, you can specify which database to target using the --bind option:

flask db migrate -m "Add users table" --bind users

COMMAND REFERENCE

Flask-Migrate provides a set of command-line commands that you can use to manage your database migrations. These commands are typically accessed via a Python script (e.g., manage.py) that initializes Flask-Migrate.

The following commands are available:

init
Initializes a new migrations repository.
revision
Creates a new migration revision.
migrate
Creates a new migration revision based on the current database schema.
upgrade
Upgrades the database to a specific revision.
downgrade
Downgrades the database to a specific revision.
show
Shows the contents of a specific migration revision.
edit
Edits a specific migration revision.
stamp
Stamps the database with a specific revision, without running any migrations.

API REFERENCE

In addition to the command-line interface, Flask-Migrate also exposes an API that you can use directly in your Python code for greater scripting flexibility.

The main components of the API are:

  • Migrate class: This class is used to initialize Flask-Migrate with your Flask application and SQLAlchemy database instance.

    from flask_migrate import Migrate
migrate = Migrate(app, db)

  • MigrateCommand class: This class provides the command-line interface commands for Flask-Migrate. It can be integrated with Flask-Script or other command-line argument parsers.

    from flask_migrate import MigrateCommand
from flask_script import Manager

manager = Manager(app)
manager.add_command('db', MigrateCommand)

You can also use Alembic's API directly by importing it:

  • The full Alembic API is available through the alembic package. This allows you to programmatically control all aspects of the migration process.

    from alembic import command
from alembic.config import Config

config = Config("alembic.ini")
command.revision(config, message="Add new feature")

Using the Alembic API directly gives you the most flexibility, but it also requires a deeper understanding of Alembic's inner workings. For most common use cases, the Flask-Migrate commands or the Flask-Migrate API should be sufficient.

Note that the alembic.ini file's configuration options will override any settings that are passed through the Flask-Migrate extension itself. This is by design, to allow for a more centralized configuration of the migration process.

For greater scripting flexibility you can also use the API exposed by Alembic directly.
