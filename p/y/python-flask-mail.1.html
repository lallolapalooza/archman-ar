تثبيت Flask-Mail

قم بالتثبيت باستخدام pip و easy_install:

pip install Flask-Mail

أو قم بتنزيل أحدث إصدار من نظام التحكم بالإصدار:

git clone https://github.com/mattupstate/flask-mail.git
cd flask-mail
python setup.py install

إذا كنت تستخدم virtualenv، فمن المفترض أنك تقوم بتثبيت flask-mail في نفس البيئة الافتراضية مثل تطبيق (تطبيقات) Flask الخاص بك.

تهيئة Flask-Mail

يتم تكوين Flask-Mail من خلال واجهة تكوين Flask القياسية. هذه هي الخيارات المتاحة (يتم شرح كل منها لاحقًا في التوثيق):

  • MAIL_SERVER : الافتراضي 'localhost'
  • MAIL_PORT : الافتراضي 25
  • MAIL_USE_TLS : الافتراضي False
  • MAIL_USE_SSL : الافتراضي False
  • MAIL_DEBUG : الافتراضي app.debug
  • MAIL_USERNAME : الافتراضي None
  • MAIL_PASSWORD : الافتراضي None
  • MAIL_DEFAULT_SENDER : الافتراضي None
  • MAIL_MAX_EMAILS : الافتراضي None
  • MAIL_SUPPRESS_SEND : الافتراضي app.testing
  • MAIL_ASCII_ATTACHMENTS : الافتراضي False

بالإضافة إلى ذلك، يتم استخدام خيار تكوين TESTING القياسي لـ Flask بواسطة Flask-Mail في اختبارات الوحدة (انظر أدناه).

تتم إدارة رسائل البريد الإلكتروني من خلال مثيل Mail:

from flask import Flask
from flask_mail import Mail
app = Flask(__name__)
mail = Mail(app)

في هذه الحالة، يتم إرسال جميع رسائل البريد الإلكتروني باستخدام قيم التكوين للتطبيق الذي تم تمريره إلى مُنشئ الفئة Mail.

بدلاً من ذلك، يمكنك إعداد مثيل Mail الخاص بك لاحقًا في وقت التكوين، باستخدام الطريقة init_app:

mail = Mail()
app = Flask(__name__)
mail.init_app(app)

في هذه الحالة، سيتم إرسال رسائل البريد الإلكتروني باستخدام قيم التكوين من متغير current_app العام للسياق في Flask. هذا مفيد إذا كان لديك تطبيقات متعددة تعمل في نفس العملية ولكن بخيارات تكوين مختلفة.

إرسال الرسائل

لإرسال رسالة، قم أولاً بإنشاء مثيل Message:

from flask_mail import Message
@app.route("/")
def index():
    msg = Message("Hello",
                  sender="from@example.com",
                  recipients=["to@example.com"])

يمكنك تعيين عناوين البريد الإلكتروني للمستلمين على الفور، أو بشكل فردي:

msg.recipients = ["you@example.com"]
msg.add_recipient("somebodyelse@example.com")

إذا قمت بتعيين MAIL_DEFAULT_SENDER، فلن تحتاج إلى تعيين مرسل الرسالة بشكل صريح، حيث سيستخدم هذه القيمة تكوين افتراضيًا:

msg = Message("Hello",
              recipients=["to@example.com"])

إذا كان sender عبارة عن زوج من العناصر، فسيتم تقسيمه إلى اسم وعنوان:

msg = Message("Hello",
              sender=("Me", "me@example.com"))
assert msg.sender == "Me <me@example.com>"

يمكن أن تحتوي الرسالة على نص أساسي و/أو HTML:

msg.body = "testing"
msg.html = "<b>testing</b>"

أخيرًا، لإرسال الرسالة، يمكنك استخدام مثيل Mail الذي تم تكوينه مع تطبيق Flask الخاص بك:

mail.send(msg)

رسائل البريد الإلكتروني المجمعة

عادةً في تطبيق الويب، سترسل رسالة بريد إلكتروني أو رسالتين لكل طلب. في حالات معينة، قد ترغب في أن تكون قادرًا على إرسال عشرات أو مئات رسائل البريد الإلكتروني دفعة واحدة - ربما في عملية خارجية مثل نص برمجي سطر الأوامر أو مهمة cron.

في هذه الحالة، تقوم بالأشياء بشكل مختلف قليلاً:

with mail.connect() as conn:
    for user in users:
        message = '...'
        subject = "hello, %s" % user.name
        msg = Message(recipients=[user.email],
                      body=message,
                      subject=subject)
        conn.send(msg)

يتم الاحتفاظ بالاتصال بمضيف البريد الإلكتروني الخاص بك مفتوحًا ويتم إغلاقه تلقائيًا بمجرد إرسال جميع الرسائل.

تحدد بعض خوادم البريد الإلكتروني حدًا لعدد رسائل البريد الإلكتروني المرسلة في اتصال واحد. يمكنك تعيين الحد الأقصى لعدد رسائل البريد الإلكتروني المرسلة قبل إعادة الاتصال عن طريق تحديد الإعداد MAIL_MAX_EMAILS.

المرفقات

إضافة المرفقات أمر بسيط:

with app.open_resource("image.png") as fp:
    msg.attach("image.png", "image/png", fp.read())

انظر API لمزيد من التفاصيل.

إذا تم تعيين MAIL_ASCII_ATTACHMENTS إلى True، فسيتم تحويل أسماء الملفات إلى ما يعادلها ASCII. يمكن أن يكون هذا مفيدًا عند استخدام مرحل بريد يغير محتوى البريد الإلكتروني ويتلف مواصفات Content-Disposition عندما تكون أسماء الملفات مرمزة بـ UTF-8. التحويل إلى ASCII هو إزالة أساسية للأحرف غير ASCII. يجب أن يكون جيدًا لأي حرف يونيكود يمكن تفكيكه بواسطة NFKD إلى حرف ASCII واحد أو أكثر. إذا كنت بحاجة إلى استيعاب/نقل صوتي (أي ß → ss) فيجب على تطبيقك القيام بذلك وتمرير سلسلة ASCII مناسبة.

اختبارات الوحدة وكتم الرسائل

عندما ترسل رسائل داخل اختبارات الوحدة، أو في بيئة التطوير، من المفيد أن تكون قادرًا على كتم إرسال البريد الإلكتروني.

إذا تم تعيين الإعداد TESTING إلى True، فسيتم كتم رسائل البريد الإلكتروني. لن يؤدي استدعاء send() على رسائلك إلى إرسال أي رسائل فعليًا.

بدلاً من ذلك، خارج بيئة الاختبار، يمكنك تعيين MAIL_SUPPRESS_SEND إلى False. سيكون لهذا نفس التأثير.

ومع ذلك، لا يزال من المفيد تتبع رسائل البريد الإلكتروني التي كان من الممكن إرسالها عند كتابة اختبارات الوحدة.

لتتبع رسائل البريد الإلكتروني المرسلة، استخدم الطريقة record_messages:

with mail.record_messages() as outbox:
    mail.send_message(subject='testing',
                      body='test',
                      recipients=emails)
    assert len(outbox) == 1
    assert outbox[0].subject == "testing"

outbox هي قائمة بمثيلات Message المرسلة.

يجب تثبيت حزمة blinker لكي تعمل هذه الطريقة.

لاحظ أن الطريقة القديمة للقيام بالأشياء، وإلحاق outbox بالكائن g، تم إيقافها الآن.

دعم الإشارات

تمت الإضافة في الإصدار 0.4.

يوفر Flask-Mail الآن دعمًا للإشارات من خلال إشارة email_dispatched. يتم إرسال هذه الإشارة كلما تم إرسال بريد إلكتروني (حتى لو لم يتم إرسال البريد الإلكتروني فعليًا، أي في بيئة اختبار).

تأخذ الدالة التي تتصل بإشارة email_dispatched مثيل Message كوسيط أول، ومثيل تطبيق Flask كوسيط اختياري:

def log_message(message, app):
    app.logger.debug(message.subject)
email_dispatched.connect(log_message)
