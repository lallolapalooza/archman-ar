البدء

ما هو Socket.IO؟

Socket.IO هو بروتوكول نقل يتيح الاتصال ثنائي الاتجاه في الوقت الفعلي المستند إلى الأحداث بين العملاء (عادةً، ولكن ليس دائمًا، متصفحات الويب) وخادم. التطبيقات الرسمية لمكونات العميل والخادم مكتوبة بلغة JavaScript. توفر هذه الحزمة تطبيقات بلغة Python لكليهما، مع وجود متغيرات قياسية ومتغيرات asyncio.

التوافق بين الإصدارات

مر بروتوكول Socket.IO بعدد من المراجعات، وقد أدخل بعضها تغييرات غير متوافقة مع الإصدارات السابقة، مما يعني أنه يجب على العميل والخادم استخدام إصدارات متوافقة لكي يعمل كل شيء.

إذا كنت تستخدم عميل وخادم Python، فإن أسهل طريقة لضمان التوافق هي استخدام نفس إصدار هذه الحزمة للعميل والخادم. إذا كنت تستخدم هذه الحزمة مع عميل أو خادم مختلف، فيجب عليك التأكد من أن الإصدارات متوافقة.

يحتوي الرسم البياني التالي للتوافق بين الإصدارات على ربط إصدارات هذه الحزمة بإصدارات تطبيق JavaScript المرجعي وإصدارات بروتوكولات Socket.IO و Engine.IO.

أمثلة العميل

يوضح المثال التالي عميلاً بسيطًا بلغة Python:

import socketio
sio = socketio.Client()
@sio.event
def connect():
    print('connection established')
@sio.event
def my_message(data):
    print('message received with ', data)
    sio.emit('my response', {'response': 'my response'})
@sio.event
def disconnect():
    print('disconnected from server')
sio.connect('http://localhost:5000')
sio.wait()

فيما يلي عميل مشابه، تم ترميزه لـ asyncio (Python 3.5+ فقط):

import asyncio
import socketio
sio = socketio.AsyncClient()
@sio.event
async def connect():
    print('connection established')
@sio.event
async def my_message(data):
    print('message received with ', data)
    await sio.emit('my response', {'response': 'my response'})
@sio.event
async def disconnect():
    print('disconnected from server')
async def main():
    await sio.connect('http://localhost:5000')
    await sio.wait()
if __name__ == '__main__':
    asyncio.run(main())

ميزات العميل

  • يمكن الاتصال بخوادم Socket.IO أخرى متوافقة مع خادم Socket.IO المرجعي بلغة JavaScript.
  • متوافق مع Python 3.8+.
  • يحتوي على نسختين من العميل، واحدة لـ Python القياسي وأخرى لـ asyncio.
  • يستخدم بنية قائمة على الأحداث منفذة باستخدام المزخرفات التي تخفي تفاصيل البروتوكول.
  • ينفذ بروتوكولات HTTP long-polling و WebSocket.
  • يعيد الاتصال بالخادم تلقائيًا إذا انقطع الاتصال.

عملاء Socket.IO

تحتوي هذه الحزمة على عميلين لـ Socket.IO:

  • عميل "بسيط"، يوفر واجهة برمجة تطبيقات بسيطة كافية لمعظم التطبيقات
  • عميل "قائم على الأحداث"، يوفر الوصول إلى جميع ميزات بروتوكول Socket.IO

يأتي كل من هؤلاء العملاء في نوعين: أحدهما لمكتبة Python القياسية، والآخر للتطبيقات غير المتزامنة المبنية باستخدام حزمة asyncio.

التثبيت

لتثبيت عميل Python القياسي مع تبعياته، استخدم الأمر التالي:

pip install "python-socketio[client]"

pip install "python-socketio[asyncio_client]"

استخدام العميل البسيط

ميزة العميل البسيط هي أنه يجرّد المنطق المطلوب للحفاظ على اتصال Socket.IO. يتعامل هذا العميل مع حالات الانقطاع وإعادة الاتصال بطريقة شفافة تمامًا، دون إضافة أي تعقيد للتطبيق.

إنشاء مثيل للعميل

أسهل طريقة لإنشاء عميل Socket.IO هي استخدام واجهة مدير السياق:

import socketio
# standard Python
with socketio.SimpleClient() as sio:
    # ... connect to a server and use the client
    # ... no need to manually disconnect!
# asyncio
async with socketio.AsyncSimpleClient() as sio:
    # ... connect to a server and use the client
    # ... no need to manually disconnect!

مع هذا الاستخدام، سيضمن مدير السياق قطع اتصال العميل بشكل صحيح قبل الخروج من كتلة with أو async with.

إذا كنت تفضل ذلك، يمكن إنشاء مثيل للعميل يدويًا:

import socketio
# standard Python
sio = socketio.SimpleClient()
# asyncio
sio = socketio.AsyncSimpleClient()

الاتصال بخادم

يتم إنشاء الاتصال بخادم عن طريق استدعاء الدالة connect():

sio.connect('http://localhost:5000')

في حالة عميل asyncio، تكون الدالة عبارة عن coroutine:

await sio.connect('http://localhost:5000')

بشكل افتراضي، يتصل العميل أولاً بالخادم باستخدام آلية النقل طويلة الأمد (long-polling)، ثم يحاول ترقية الاتصال لاستخدام WebSocket. للاتصال مباشرة باستخدام WebSocket، استخدم الوسيط transports:

sio.connect('http://localhost:5000', transports=['websocket'])

عند الاتصال، يقوم الخادم بتعيين معرف جلسة فريد للعميل. يمكن للتطبيق العثور على هذا المعرف في السمة sid:

print('my sid is', sio.sid)

يمكن الحصول على آلية نقل Socket.IO المستخدمة في الاتصال من السمة transport:

print('my transport is', sio.transport)

يتم تقديم آلية النقل كسلسلة نصية، ويمكن أن تكون إما 'websocket' أو 'polling'.

دعم TLS/SSL

يدعم العميل اتصالات TLS/SSL. لتمكينها، استخدم عنوان URL للاتصال يبدأ بـ https://:

sio.connect('https://example.com')

أو عند استخدام asyncio:

await sio.connect('https://example.com')

يقوم العميل بالتحقق من شهادات الخادم افتراضيًا. راجع الوثائق الخاصة بعميل الأحداث لمعرفة كيفية تخصيص هذا السلوك.

إرسال الأحداث

يمكن للعميل إرسال حدث إلى الخادم باستخدام الدالة emit():

sio.emit('my message', {'foo': 'bar'})

أو في حالة asyncio، كـ coroutine:

await sio.emit('my message', {'foo': 'bar'})

الوسائط المقدمة إلى الدالة هي اسم الحدث المراد إرساله والبيانات الاختيارية التي يتم تمريرها إلى الخادم. يمكن أن تكون البيانات من نوع str، bytes، dict، list أو tuple. عند إرسال list أو tuple، يجب أن تكون العناصر الموجودة فيها من أي من الأنواع المسموح بها باستثناء tuple. عند استخدام tuple، سيتم تمرير عناصر tuple كوسائط فردية لدالة معالج الأحداث من جانب الخادم.

استقبال الأحداث

يمكن للعميل الانتظار حتى يقوم الخادم بإرسال حدث باستخدام الدالة receive():

event = sio.receive()
print(f'received event: "{event[0]}" with arguments {event[1:]}')

عند استخدام asyncio، يجب انتظار هذه الدالة:

event = await sio.receive()
print(f'received event: "{event[0]}" with arguments {event[1:]}')

القيمة المرجعة من receive() هي قائمة. العنصر الأول في هذه القائمة هو اسم الحدث، بينما العناصر المتبقية هي الوسائط التي يمررها الخادم.

مع الاستخدام الموضح أعلاه، ستُرجع الدالة receive() فقط عندما يتم استلام حدث من الخادم. يمكن تمرير مهلة اختيارية بالثواني لمنع العميل من الانتظار إلى الأبد:

from socketio.exceptions import TimeoutError
try:
    event = sio.receive(timeout=5)
except TimeoutError:
    print('timed out waiting for event')
else:
    print('received event:', event)

أو مع asyncio:

from socketio.exceptions import TimeoutError
try:
    event = await sio.receive(timeout=5)
except TimeoutError:
    print('timed out waiting for event')
else:
    print('received event:', event)

قطع الاتصال بالخادم

في أي وقت، يمكن للعميل طلب قطع الاتصال بالخادم عن طريق استدعاء الدالة disconnect():

sio.disconnect()

بالنسبة لعميل asyncio، هذه coroutine:

await sio.disconnect()

التصحيح واستكشاف الأخطاء وإصلاحها

لمساعدتك في تصحيح المشكلات، يمكن تكوين العميل لإخراج السجلات إلى الطرفية:

import socketio
# standard Python
sio = socketio.Client(logger=True, engineio_logger=True)
# asyncio
sio = socketio.AsyncClient(logger=True, engineio_logger=True)

تتحكم الوسيطة logger في التسجيل المتعلق ببروتوكول Socket.IO، بينما تتحكم engineio_logger في السجلات التي تنشأ في طبقة النقل Engine.IO منخفضة المستوى. يمكن تعيين هذه الوسائط على True لإخراج السجلات إلى stderr، أو إلى كائن متوافق مع حزمة logging في Python حيث يجب إصدار السجلات. القيمة False تقوم بتعطيل التسجيل.

يمكن أن يساعد التسجيل في تحديد سبب مشاكل الاتصال، والانقطاعات غير المتوقعة، والمشكلات الأخرى.

استخدام عميل الأحداث

إنشاء مثيل للعميل

لإنشاء مثيل لعميل Socket.IO، قم ببساطة بإنشاء مثيل للفئة المناسبة للعميل:

import socketio
# standard Python
sio = socketio.Client()
# asyncio
sio = socketio.AsyncClient()

تحديد معالجات الأحداث

بروتوكول Socket.IO يعتمد على الأحداث. عندما يريد الخادم التواصل مع عميل، فإنه يرسل حدثًا. لكل حدث اسم، وقائمة من الوسائط. يسجل العميل دوال معالج الأحداث باستخدام المزخرفات socketio.Client.event() <#socketio.Client.event> أو socketio.Client.on() <#socketio.Client.on>:

@sio.event
def message(data):
    print('I received a message!')
@sio.on('my message')
def on_message(data):
    print('I received a message!')

في المثال الأول، يتم الحصول على اسم الحدث من اسم دالة المعالج. المثال الثاني أكثر تفصيلاً قليلاً، ولكنه يسمح بأن يكون اسم الحدث مختلفًا عن اسم الدالة أو أن يتضمن أحرفًا غير قانونية في أسماء الدوال، مثل المسافات.

بالنسبة لعميل asyncio، يمكن أن تكون معالجات الأحداث دوال عادية كما في الأعلى، أو يمكن أن تكون أيضًا coroutines:

@sio.event
async def message(data):
    print('I received a message!')

إذا قام الخادم بتضمين وسائط مع حدث، يتم تمريرها إلى دالة المعالج كوسائط.

معالجات الأحداث العامة ومساحات الأسماء العامة

يتم استدعاء معالج حدث "عام" لأي أحداث لا يوجد لها معالج حدث. يمكنك تعريف معالج عام باستخدام '*' كاسم حدث:

@sio.on('*')
def any_event(event, sid, data):
     pass

يمكن لخوادم Asyncio أيضًا استخدام coroutine:

@sio.on('*')
async def any_event(event, sid, data):
    pass

يستلم معالج الأحداث العام اسم الحدث كوسيطة أولى. الوسائط المتبقية هي نفسها معالج الأحداث العادي.

يجب تعريف أحداث connect و disconnect بشكل صريح ولا يتم استدعاؤها على معالج حدث عام.

وبالمثل، يتم استدعاء معالج مساحة أسماء "عام" لأي مساحات أسماء متصلة لا يوجد بها معالج أحداث معرف صراحةً. كما هو الحال مع الأحداث العامة، يتم استخدام '*' بدلاً من مساحة الأسماء:

@sio.on('my_event', namespace='*')
def my_event_any_namespace(namespace, sid, data):
    pass

بالنسبة لهذه الأحداث، يتم تمرير مساحة الأسماء كوسيطة أولى، تليها الوسائط العادية للحدث.

أخيرًا، من الممكن أيضًا

le لتحديد معالج "catch-all" لجميع الأحداث على جميع المساحات: 
@sio.on('*', namespace='*')
def any_event_any_namespace(event, namespace, sid, data):
    pass

تتلقى معالجات الأحداث ذات الأحداث والمساحات الشاملة اسم الحدث والمساحة كوسيطين أول وثاني.

معالجات أحداث الاتصال، وخطأ الاتصال، والانفصال

الأحداث connect و connect_error و disconnect خاصة؛ يتم استدعاؤها تلقائيًا عند اتصال عميل بالخادم أو انفصاله عنه:

@sio.event
def connect():
    print("أنا متصل!")
@sio.event
def connect_error(data):
    print("فشل الاتصال!")
@sio.event
def disconnect(reason):
    print("لقد انفصلت! السبب:", reason)

يتم استدعاء معالج connect_error عند فشل محاولة الاتصال. إذا قام الخادم بتوفير وسائط، يتم تمريرها إلى المعالج. يمكن للخادم استخدام وسيطة لتوفير معلومات للعميل فيما يتعلق بفشل الاتصال.

يتم استدعاء معالج disconnect عند الانفصالات التي يبدأها التطبيق، أو الانفصالات التي يبدأها الخادم، أو الانفصالات العرضية، على سبيل المثال بسبب فشل الشبكة. في حالة الانفصال العرضي، سيحاول العميل إعادة الاتصال فورًا بعد استدعاء معالج الانفصال. بمجرد إعادة إنشاء الاتصال، سيتم استدعاء معالج الاتصال مرة أخرى. يتلقى المعالج وسيطة reason توفر سبب الانفصال:

@sio.event
def disconnect(reason):
    if reason == sio.reason.CLIENT_DISCONNECT:
        print('العميل انفصل')
    elif reason == sio.reason.SERVER_DISCONNECT:
        print('الخادم فصل العميل')
    else:
        print('سبب الانفصال:', reason)

راجع السمة socketio.Client.reason <#socketio.Client.reason> للحصول على قائمة بأسباب الانفصال الممكنة.

يجب تعريف الأحداث connect و connect_error و disconnect بشكل صريح ولا يتم استدعاؤها في معالج أحداث شامل.

إصدار الأحداث

يمكن للعميل إصدار حدث للخادم باستخدام الطريقة emit():

sio.emit('my message', {'foo': 'bar'})

أو في حالة asyncio، كـ coroutine:

await sio.emit('my message', {'foo': 'bar'})

الوسائط المقدمة إلى الطريقة هي اسم الحدث المراد إصداره والبيانات الاختيارية التي يتم تمريرها إلى الخادم. يمكن أن تكون البيانات من نوع str أو bytes أو dict أو list أو tuple. عند إرسال list أو tuple، يجب أن تكون العناصر الموجودة فيها من أي أنواع مسموح بها باستثناء tuple. عند استخدام tuple، سيتم تمرير عناصر tuple كوسائط فردية إلى دالة معالج الأحداث من جانب الخادم.

يمكن استدعاء الطريقة emit() داخل معالج أحداث كرد على حدث خادم، أو في أي جزء آخر من التطبيق، بما في ذلك المهام الخلفية.

ردود نداء الأحداث

عندما يقوم خادم بإصدار حدث إلى عميل، يمكنه اختياريًا توفير دالة رد نداء، ليتم استدعاؤها كوسيلة إقرار بأن الخادم قد عالج الحدث. بينما يتم إدارة هذا بالكامل بواسطة الخادم، يمكن للعميل توفير قائمة بالقيم التي سيتم تمريرها إلى دالة رد النداء التي أعدها الخادم. يتم تحقيق ذلك ببساطة عن طريق إرجاع القيم المطلوبة من دالة المعالج:

@sio.event
def my_event(sid, data):
    # معالجة الرسالة
    return "OK", 123

وبالمثل، يمكن للعميل طلب استدعاء دالة رد نداء بعد معالجة الخادم لحدث ما. تحتوي الطريقة socketio.Server.emit() <#socketio.Server.emit> على وسيطة اختيارية callback يمكن تعيينها إلى دالة قابلة للاستدعاء. إذا تم توفير هذه الوسيطة، فسيتم استدعاء الدالة القابلة للاستدعاء بعد معالجة الخادم للحدث، وسيتم تمرير أي قيم يتم إرجاعها بواسطة معالج الخادم كوسائط لهذه الدالة.

المساحات

يدعم بروتوكول Socket.IO اتصالات منطقية متعددة، يتم مضاعفتها جميعًا على نفس الاتصال الفعلي. يمكن للعملاء فتح اتصالات متعددة عن طريق تحديد namespace مختلف في كل منها. تستخدم المساحات صيغة مسار تبدأ بشرطة مائلة للأمام. يمكن تقديم قائمة بالمساحات بواسطة العميل في استدعاء connect(). على سبيل المثال، يقوم هذا المثال بإنشاء اتصاليين منطقيين، الاتصال الافتراضي بالإضافة إلى اتصال ثانٍ تحت مساحة /chat:

وبالمثل، يمكن للعميل إصدار حدث للخادم على مساحة عن طريق توفيرها في استدعاء emit():

إذا لم يتم توفير الوسيطة namespaces لاستدعاء connect()، فسيتم توصيل أي مساحات مستخدمة في معالجات الأحداث تلقائيًا.

Gevent

عندما يكون خادم الويب متعدد الخيوط غير قادر على تلبية متطلبات التزامن وقابلية التوسع للتطبيق، فإن أحد الخيارات التي يمكن تجربتها هو Gevent http://www.gevent.org. Gevent هي مكتبة تزامن قائمة على الكوروتين، وهي أخف بكثير من الخيوط.

ستستخدم مثيلات الفئة socketio.Server تلقائيًا Gevent إذا كانت المكتبة مثبتة. لطلب تحديد gevent صراحة، يمكن توفير الخيار async_mode في المنشئ:

sio = socketio.Server(async_mode='gevent')

يجب أن يكون خادم Socket.IO ملفوفًا بالفئة socketio.WSGIApp <#socketio.WSGIApp>، ليكون متوافقًا مع بروتوكول WSGI:

app = socketio.WSGIApp(sio)

sio = socketio.Server(async_mode='gevent')
app = socketio.WSGIApp(sio, other_wsgi_app)

يتم نشر خادم تم تكوينه لـ Gevent كتطبيق WSGI عادي باستخدام socketio.WSGIApp المقدم:

راجع قسم Gunicorn أعلاه للحصول على معلومات حول كيفية استخدام Gunicorn مع عدة عمال.

عند العمل مع التطبيقات الموزعة، غالبًا ما يكون من الضروري الوصول إلى وظائف Socket.IO من عمليات متعددة. هناك حالتان استخدام محددتان:

  • قد ترغب التطبيقات عالية التوفر في استخدام التوسع الأفقي لخادم Socket.IO لتكون قادرة على التعامل مع عدد كبير جدًا من العملاء المتزامنين.
  • قد تحتاج التطبيقات التي تستخدم قوائم انتظار العمل مثل Celery http://www.celeryproject.org/ إلى إرسال حدث إلى عميل بمجرد اكتمال مهمة في الخلفية. المكان الأكثر ملاءمة للقيام بهذه المهمة هو عملية العامل التي تعاملت مع هذه المهمة.

كحل للمشكلات المذكورة أعلاه، يمكن تكوين خادم Socket.IO للاتصال بقائمة انتظار رسائل مثل Redis http://redis.io/ أو RabbitMQ https://www.rabbitmq.com/، للتواصل مع خوادم Socket.IO أخرى ذات صلة أو عمال مساعدين.

Redis

لاستخدام قائمة انتظار رسائل Redis، يجب تثبيت عميل Python Redis:

# socketio.Server class
pip install redis

يتم تكوين قائمة انتظار Redis من خلال الفئتين socketio.RedisManager <#socketio.RedisManager> و socketio.AsyncRedisManager <#socketio.AsyncRedisManager>. تتصل هذه الفئات مباشرة بمخزن Redis وتستخدم وظيفة النشر/الاشتراك (pub/sub) لقائمة الانتظار:

# socketio.Server class
mgr = socketio.RedisManager('redis://')
sio = socketio.Server(client_manager=mgr)
# socketio.AsyncServer class
mgr = socketio.AsyncRedisManager('redis://')
sio = socketio.AsyncServer(client_manager=mgr)

يُعلم الوسيط client_manager الخادم بالاتصال بقائمة انتظار الرسائل المحددة، والتنسيق مع العمليات الأخرى المتصلة بقائمة الانتظار.

Kombu

Kombu http://kombu.readthedocs.org/en/latest/ هي حزمة بايثون توفر الوصول إلى RabbitMQ والعديد من قوائم انتظار الرسائل الأخرى. يمكن تثبيتها باستخدام pip:

pip install kombu

لاستخدام RabbitMQ أو قوائم انتظار أخرى متوافقة مع بروتوكول AMQP، هذا هو الاعتماد الوحيد المطلوب. ولكن بالنسبة لقوائم انتظار الرسائل الأخرى، قد تتطلب Kombu حزمًا إضافية. على سبيل المثال، لاستخدام قائمة انتظار Redis عبر Kombu، يجب أيضًا تثبيت حزمة بايثون لـ Redis:

pip install redis

يتم تكوين قائمة الانتظار من خلال socketio.KombuManager <#socketio.KombuManager>:

mgr = socketio.KombuManager('amqp://')
sio = socketio.Server(client_manager=mgr)

يتم تمرير عنوان URL للاتصال الذي تم تمريره إلى منشئ KombuManager مباشرة إلى كائن Connection الخاص بـ Kombu http://kombu.readthedocs.

فئة socketio.Client(reconnection=True, reconnection_attempts=0, reconnection_delay=1, reconnection_delay_max=5, randomization_factor=0.5, logger=False, serializer='default', json=None, handle_sigint=True, **kwargs)
عميل Socket.IO.

تنفذ هذه الفئة عميل ويب Socket.IO متوافق بالكامل مع دعم وسائل النقل websocket و long-polling.

المعلمات
  • reconnection -- True إذا كان يجب على العميل محاولة إعادة الاتصال تلقائيًا بالخادم بعد انقطاع، أو False لعدم إعادة الاتصال. الافتراضي هو True.
  • reconnection_attempts -- عدد محاولات إعادة الاتصال التي يجب إصدارها قبل الاستسلام، أو 0 لمحاولات لا نهائية. الافتراضي هو 0.
  • reconnection_delay -- المدة التي يجب الانتظار فيها بالثواني قبل محاولة إعادة الاتصال الأولى. كل محاولة لاحقة تضاعف هذه المهلة.
  • reconnection_delay_max -- أقصى مهلة بين محاولات إعادة الاتصال.
  • randomization_factor -- مقدار العشوائية لكل تأخير بين محاولات إعادة الاتصال. الافتراضي هو 0.5، مما يعني أن كل تأخير يتم تعديله عشوائيًا بنسبة +/- 50%.
  • logger -- لتمكين التسجيل، قم بتعيينها على True أو مرر كائن logger للاستخدام. لتعطيل التسجيل، قم بتعيينها على False. الافتراضي هو False. لاحظ أن الأخطاء الفادحة يتم تسجيلها حتى عندما يكون logger هو False.
  • serializer -- طريقة التسلسل المراد استخدامها عند نقل الحزم. القيم الصالحة هي 'default' و 'pickle' و 'msgpack' و 'cbor'. بدلاً من ذلك، يمكن توفير فئة فرعية من فئة Packet مع تطبيقات مخصصة لطرق encode() و decode(). يجب على العميل والخادم استخدام سلاسل تسلسل متوافقة.
  • json -- وحدة json بديلة للاستخدام في ترميز وفك ترميز الحزم. يجب أن تحتوي وحدات json المخصصة على دالات dumps و loads المتوافقة مع إصدارات المكتبة القياسية.
  • handle_sigint -- قم بتعيينها على True لمعالجة قطع الاتصال تلقائيًا عند مقاطعة العملية، أو على False لترك معالجة المقاطعة للتطبيق المستدعي. لا يمكن تمكين معالجة المقاطعة إلا عندما يتم إنشاء مثيل العميل في الخيط الرئيسي.

event(*args, **kwargs)
Decorator to register an event handler.

This is a simplified version of the on() method that takes the event name from the decorated function.

Example usage:

@sio.event

@sio.on('my_event')

on(event, handler=None, namespace=None)
Register an event handler.
Parameters
  • event -- The event name. It can be any string. The event names 'connect', 'message' and 'disconnect' are reserved and should not be used. The '*' event name can be used to define a catch-all event handler.
  • handler -- The function that should be invoked to handle the event. When this parameter is not given, the method acts as a decorator for the handler function.
  • namespace -- The Socket.IO namespace for the event. If this argument is omitted the handler is associated with the default namespace. A catch-all namespace can be defined by passing '*' as the namespace.

Example usage:

# as a decorator:
@sio.on('connect', namespace='/chat')
def connect_handler(sid, environ):
    print('Connection request')
    if environ['REMOTE_ADDR'] in blacklisted:
        return False  # reject
# as a method:
def message_handler(sid, msg):
    print('Received message: ', msg)
    sio.send(sid, 'response')
socket_io.on('message', namespace='/chat', handler=message_handler)

The arguments passed to the handler function depend on the event type:

  • The 'connect' event handler receives the sid (session ID) for the client and the WSGI environment dictionary as arguments.
  • The 'disconnect' handler receives the sid for the client as only argument.
  • The 'message' handler and handlers for custom event names receive the sid for the client and the message payload as arguments. Any values returned from a message handler will be passed to the client's acknowledgement callback function if it exists.
  • A catch-all event handler receives the event name as first argument, followed by any arguments specific to the event.
  • A catch-all namespace event handler receives the namespace as first argument, followed by any arguments specific to the event.
  • A combined catch-all namespace and catch-all event handler receives the event name as first argument and the namespace as second argument, followed by any arguments specific to the event.

NAME

python-socketio — Python Socket.IO server and client

GETTING STARTED

This is a manual page for python-socketio.

The official documentation can be found at http://python-socketio.readthedocs.io/.

THE SOCKET.IO CLIENTS

This library provides a Socket.IO client implementation for Python.

To install the client:

pip install python-socketio[client]

To connect to a Socket.IO server:

import socketio

sio = socketio.Client()
sio.connect('http://localhost:5000')
sio.emit('myevent', {'data': 'mydata'})
sio.disconnect()

THE SOCKET.IO SERVER

This library provides a Socket.IO server implementation that can be integrated with various Python web frameworks such as Flask, Django, and FastAPI.

To install the server:

pip install python-socketio[server]

A simple Flask-based example:

from flask import Flask, render_template
import socketio

sio = socketio.Server()
app = Flask(__name__)
wsgi_app = socketio.WSGIApp(sio, app)

@app.route('/')
def index():
    return render_template('index.html')

@sio.event
def connect(sid, environ):
    print('connect ', sid)

@sio.event
def my_message(sid, message):
    print('message from ', sid, message)
    sio.send('Hello from server')

@sio.event
def disconnect(sid):
    print('disconnect ', sid)

if __name__ == '__main__':
    import eventlet
    eventlet.wsgi.server(eventlet.listen(('127.0.0.1', 5000)), wsgi_app)
