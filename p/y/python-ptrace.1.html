تتبع استدعاءات النظام (syscalls)

يمكن لـ python-ptrace تتبع استدعاءات النظام باستخدام PTRACE_SYSCALL.

PtraceSyscall

تحتوي وحدة ptrace.syscall على فئة PtraceSyscall: إنها محلل لاستدعاءات النظام في لينكس مشابه لبرنامج strace.

مثال:

connect(5, <sockaddr_in sin_family=AF_INET, sin_port=53, sin_addr=212.27.54.252>, 28) = 0
open('/usr/lib/i686/cmov/libcrypto.so.0.9.8', 0, 0 <read only>) = 4
mmap2(0xb7e87000, 81920, 3, 2066, 4, 297) = 0xb7e87000
rt_sigaction(SIGWINCH, 0xbfb7d4a8, 0xbfb7d41c, 8) = 0

يمكنك الحصول على مزيد من المعلومات: نوع النتيجة، عنوان القيمة، أنواع الوسائط، وأسماء الوسائط.

أمثلة:

long open(const char* filename='/usr/lib/i686/cmov/libcrypto.so.0.9.8' at 0xb7efc027, int flags=0, int mode=0 <read only>) = 4
long fstat64(unsigned long fd=4, struct stat* buf=0xbfa46e2c) = 0
long set_robust_list(struct robust_list_head* head=0xb7be5710, size_t len_ptr=12) = 0

  • عرض لطيف للإشارات: انظر [[signal|معالجة إشارات python-ptrace]]

gdb.py

gdb.py هو مصحح أخطاء سطر الأوامر مشابه لـ gdb، ولكن بميزات أقل: لا يدعم الرموز، لا يدعم لغة C، لا يدعم الخيوط، إلخ.

بعض الأوامر

  • cont: استمر في التنفيذ
  • stepi: نفذ تعليمة واحدة
  • step: نفذ تعليمة واحدة، ولكن لا تدخل في الاستدعاءات

اكتب help لسرد جميع الأوامر المتاحة.

•

أحداث عمليات python-ptrace

أحداث العملية

تعتمد جميع أحداث العمليات على الفئة ProcessEvent.

  • ProcessExit: خرجت العملية برمز خروج، أو قُتلت بإشارة، أو خرجت بشكل غير طبيعي
  • ProcessSignal: تلقت العملية إشارة
  • NewProcessEvent: تم إنشاء عملية جديدة، على سبيل المثال، بعد استدعاء نظام fork()

السمات:

  • تحتوي جميع الأحداث على سمة "process"
  • تحتوي ProcessExit على سمتين "exitcode" و "signum" (يمكن أن تكون كلتاهما None)
  • تحتوي ProcessSignal على سمتين "signum" و "name"

بالنسبة لـ NewProcessEvent، استخدم سمة process.parent للحصول على العملية الأصل.

ملاحظة: تحتوي ProcessSignal على دالة display() لعرض محتوياتها. استخدمها فور تلقي الرسالة لأنها تقرأ ذاكرة العملية لتحليل أسباب إرسال الإشارة.

انتظر أي حدث عملية

الدالة الأكثر عمومية هي waitProcessEvent(): تنتظر أي حدث عملية (خروج، إشارة، أو عملية جديدة):

event = debugger.waitProcessEvent()

للانتظار لإشارة واحدة أو أكثر، استخدم دالة waitSignals(). بدون وسيط، تنتظر أي إشارة. يتم رفع الأحداث الأخرى غير الإشارات كاستثناءات بايثون. أمثلة:

signal = debugger.waitSignals()
signal = debugger.waitSignals(SIGTRAP)
signal = debugger.waitSignals(SIGINT, SIGTERM)

ملاحظة: الإشارة هي كائن ProcessSignal، استخدم signal.signum للحصول على رقم الإشارة.

انتظر أحداث عملية محددة

للانتظار أي حدث من عملية، استخدم دالة waitEvent():

event = process.waitEvent()

للانتظار إشارة واحدة أو أكثر، استخدم دالة waitSignals(). بدون وسيط، تنتظر أي إشارة. يتم رفع أحداث العمليات الأخرى كاستثناءات بايثون. أمثلة:

signal = process.waitSignals()
signal = process.waitSignals(SIGTRAP)
signal = process.waitSignals(SIGINT, SIGTERM)

ملاحظة: كما هو الحال مع debugger.waitSignals()، فإن الإشارة هي كائن ProcessSignal.

معالجة إشارات python-ptrace

مقدمة

يحاول PtraceSignal عرض معلومات مفيدة عند تلقي إشارة. اعتمادًا على رقم الإشارة، يعرض معلومات مختلفة.

يستخدم التعليمات الحالية المفككة كرمز آلي لفهم سبب إطلاق الإشارة.

يتم دعم Intel x86 (i386، ربما x86_64) فقط الآن.

عندما تتلقى عملية إشارة، يحاول python-ptrace شرح سبب إطلاق الإشارة.
