This extension provides Flask integration with SQLAlchemy, a powerful and flexible ORM for Python.

It handles session management, connection pooling, and model definition using Flask's application context. This allows you to seamlessly integrate SQLAlchemy into your Flask applications.

Getting Started

To use Flask-SQLAlchemy, you need to install it:

pip install Flask-SQLAlchemy

Then, in your Flask application, you can initialize the extension:

from flask import Flask
from flask_sqlalchemy import SQLAlchemy

db = SQLAlchemy()

def create_app():
    app = Flask(__name__)
    # Configure the database URI
    app.config['SQLALCHEMY_DATABASE_URI'] = 'sqlite:///mydatabase.db'
    # Disable modification tracking to save resources
    app.config['SQLALCHEMY_TRACK_MODIFICATIONS'] = False

    db.init_app(app)

    # Import models here to ensure they are registered with the extension
    from . import models

    return app

You'll also need to define your database models. They should inherit from db.Model:

# models.py
from flask_sqlalchemy import SQLAlchemy

db = SQLAlchemy()

class User(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    username = db.Column(db.String(80), unique=True, nullable=False)
    email = db.Column(db.String(120), unique=True, nullable=False)

    def __repr__(self):
        return '<User %r>' % self.username

With the models defined and the extension initialized, you can now create the database tables:

from your_app import create_app, db

app = create_app()

with app.app_context():
    db.create_all()

To interact with the database, you can use the db.session object:

from your_app import db, User

# Add a new user
new_user = User(username='john', email='john@example.com')
db.session.add(new_user)
db.session.commit()

# Query users
users = db.session.execute(db.select(User)).scalars().all()
print(users)

Querying Data

You can query data using SQLAlchemy's select statements.

from flask_sqlalchemy import SQLAlchemy
from sqlalchemy import select

db = SQLAlchemy()

# Assuming you have a User model defined as above

def get_user_by_id(user_id):
    # Use db.session.execute with select for modern SQLAlchemy
    stmt = select(User).filter_by(id=user_id)
    result = db.session.execute(stmt)
    # .scalar_one_or_none() fetches a single row or None
    user = result.scalar_one_or_none()
    return user

def get_all_users():
    # For fetching multiple rows
    stmt = select(User)
    result = db.session.execute(stmt)
    # .scalars() returns an iterator of the first column of each row
    users = result.scalars().all()
    return users

You may see uses of Model.query to build queries. This is an older interface for queries that is considered legacy in SQLAlchemy. Prefer using db.session.execute(db.select(...)) instead.

See Modifying and Querying Data for more information about queries.

What to Remember

For the most part, you should use SQLAlchemy as usual. The SQLAlchemy extension instance creates, configures, and gives access to the following things:

  • SQLAlchemy.Model declarative model base class. It sets the table name automatically instead of needing __tablename__.
  • SQLAlchemy.session is a session that is scoped to the current Flask application context. It is cleaned up after every request.
  • SQLAlchemy.metadata and SQLAlchemy.metadatas gives access to each metadata defined in the config.
  • SQLAlchemy.engine and SQLAlchemy.engines gives access to each engine defined in the config.
  • SQLAlchemy.create_all() creates all tables.
  • You must be in an active Flask application context to execute queries and to access the session and engine.

Configuration

Configuration Keys

Configuration is loaded from the Flask app.config when SQLAlchemy.init_app() is called. The configuration is not read again after that. Therefore, all configuration must happen before initializing the application.

flask_sqlalchemy.config.SQLALCHEMY_DATABASE_URI
The database connection URI used for the default engine. It can be either a string or a SQLAlchemy URL instance. See below and Engine Configuration for examples.

At least one of this and SQLALCHEMY_BINDS must be set.

Changed in version 3.0: No longer defaults to an in-memory SQLite database if not set.

flask_sqlalchemy.config.SQLALCHEMY_ENGINE_OPTIONS
A dict of arguments to pass to sqlalchemy.create_engine() for the default engine.

This takes precedence over the engine_options argument to SQLAlchemy, which can be used to set default options for all engines.

Changed in version 3.0: Only applies to the default bind.

Added in version 2.4.

flask_sqlalchemy.config.SQLALCHEMY_BINDS
A dict mapping bind keys to engine options. The value can be a string or a SQLAlchemy URL instance. Or it can be a dict of arguments, including the url key, that will be passed to sqlalchemy.create_engine(). The None key can be used to configure the default bind, but SQLALCHEMY_ENGINE_OPTIONS and SQLALCHEMY_DATABASE_URI take precedence.

At least one of this and SQLALCHEMY_DATABASE_URI must be set.

Added in version 0.12.

flask_sqlalchemy.config.SQLALCHEMY_ECHO
The default value for echo and echo_pool for every engine. This is useful to quickly debug the connections and queries issued from SQLAlchemy.

Changed in version 3.0: Sets echo_pool in addition to echo.

flask_sqlalchemy.config.SQLALCHEMY_RECORD_QUERIES
If enabled, information about each query during a request will be recorded. Use get_recorded_queries() to get a list of queries that were issued during the request.

Changed in version 3.0: Not enabled automatically in debug or testing mode.

flask_sqlalchemy.config.SQLALCHEMY_TRACK_MODIFICATIONS
If enabled, all insert, update, and delete operations on models are recorded, then sent in models_committed and before_models_committed signals when session.commit() is called.

Changed in version 3.0: Disabled by default.

Added in version 2.0.

Changed in version 3.1: Removed SQLALCHEMY_COMMIT_ON_TEARDOWN.

Changed in version 3.0: Removed SQLALCHEMY_NATIVE_UNICODE, SQLALCHEMY_POOL_SIZE, SQLALCHEMY_POOL_TIMEOUT, SQLALCHEMY_POOL_RECYCLE, and SQLALCHEMY_MAX_OVERFLOW.

Default Driver Options

Some default options are set for SQLite and MySQL engines to make them more usable by default in web applications.

SQLite relative file paths are relative to the Flask instance path instead of the current working directory. In-memory databases use a static pool and check_same_thread to work across requests.

MySQL (and MariaDB) servers are configured to drop connections that have been idle for 8 hours, which can result in an error like 2013: Lost connection to MySQL server during query. A default pool_recycle value of 2 hours (7200 seconds) is used to recreate connections before that timeout.

Engine Configuration Precedence

Because Flask-SQLAlchemy has support for multiple engines, there are rules for which config overrides other config. Most applications will only have a single database and only need to use SQLALCHEMY_DATABASE_URI and SQLALCHEMY_ENGINE_OPTIONS.

  • If the engine_options argument is given to SQLAlchemy, it sets default options for all engines. SQLALCHEMY_ECHO sets the default value for both echo and echo_pool for all engines.
  • The options for each engine in SQLALCHEMY_BINDS override those defaults.
  • SQLALCHEMY_ENGINE_OPTIONS overrides the None key in SQLALCHEMY_BINDS, and SQLALCHEMY_DATABASE_URI overrides the url key in that engine's options.

Timeouts

Certain databases may be configured to close inactive connections after a period of time. MySQL and MariaDB are configured for this by default, but database services may also configure this type of limit. This can result in an error like 2013: Lost connection to MySQL server during query.

If you encounter this error, try setting pool_recycle in the engine options to a value less than the database's timeout.

Alternatively, you can try setting pool_pre_ping if you expect the database to close connections often, such as if it's running in a container that may restart.

Models and Tables

Use the db.Model class to define models, or the db.Table class to create tables. Both handle Flask-SQLAlchemy's bind keys to associate with a specific engine.

تهيئة الامتداد

بعد تحديد الفئة الأساسية، قم بإنشاء كائن db باستخدام مُنشئ SQLAlchemy.

أنشئ فئة فرعية من db.Model لإنشاء فئة نموذج. على عكس SQLAlchemy العادي، سيقوم نموذج Flask-SQLAlchemy تلقائيًا بإنشاء اسم جدول إذا لم يتم تعيين \_\_tablename\_\_ وتم تعريف عمود مفتاح أساسي.

from sqlalchemy.orm import Mapped, mapped_column
class User(db.Model):
    id: Mapped[int] = mapped_column(db.Integer, primary_key=True)
    username: Mapped[str] = mapped_column(db.String, unique=True, nullable=False)
    email: Mapped[str] = mapped_column(db.String)

لا يؤدي تعريف نموذج إلى إنشائه في قاعدة البيانات. استخدم create_all() لإنشاء النماذج والجداول بعد تعريفها. إذا قمت بتعريف النماذج في وحدات فرعية، فيجب عليك استيرادها حتى تعرفها SQLAlchemy قبل استدعاء create_all.

قم بإنشاء مثيلات من db.Table لتعريف الجداول. تأخذ الفئة اسم الجدول، ثم أي أعمدة وأجزاء جدول أخرى مثل الأعمدة والقيود. على عكس SQLAlchemy العادي، لا يلزم وسيطة metadata. سيتم اختيار بيانات وصفية بناءً على وسيطة bind_key، أو سيتم استخدام الافتراضي.

سبب شائع لإنشاء جدول مباشرة هو عند تعريف علاقات متعدد إلى متعدد. لا يحتاج جدول الارتباط إلى فئة نموذج خاصة به، حيث سيتم الوصول إليه من خلال سمات العلاقة ذات الصلة على النماذج المرتبطة.

import sqlalchemy as sa
user_book_m2m = db.Table(
    "user_book",
    sa.Column("user_id", sa.ForeignKey(User.id), primary_key=True),
    sa.Column("book_id", sa.ForeignKey(Book.id), primary_key=True),
)

عكس الجداول

إذا كنت تتصل بقاعدة بيانات تحتوي بالفعل على جداول، فيمكن لـ SQLAlchemy اكتشاف هذا المخطط وإنشاء جداول بأعمدة تلقائيًا. يُطلق على هذا اسم الانعكاس. يمكن أيضًا تعيين هذه الجداول لفئات النماذج باستخدام السمة \_\_table\_\_ بدلاً من تعريف النموذج الكامل.

قم باستدعاء الطريقة reflect() على الامتداد. ستقوم بعكس جميع الجداول لكل مفتاح ربط. ستحتوي سمة tables لكل بيانات وصفية على كائنات الجدول المكتشفة.

with app.app_context():
    db.reflect()
class User:
    __table__ = db.metadatas["auth"].tables["user"]

في معظم الحالات، سيكون من الأسهل صيانة تعريف فئات النماذج بنفسك. تحتاج فقط إلى تعريف النماذج والأعمدة التي ستستخدمها فعليًا، حتى لو كنت تتصل بمخطط أوسع. ستعرف بيئات التطوير المتكاملة السمات المتاحة، ويمكن لأدوات الترحيل مثل Alembic اكتشاف التغييرات وإنشاء ترحيلات المخطط.

تعديل البيانات والاستعلام عنها

إدراج، تحديث، حذف

لإدراج البيانات، قم بتمرير كائن النموذج إلى db.session.add():

user = User()
db.session.add(user)
db.session.commit()

لتحديث البيانات، قم بتعديل السمات على كائنات النموذج:

user.verified = True
db.session.commit()

لحذف البيانات، قم بتمرير كائن النموذج إلى db.session.delete():

db.session.delete(user)
db.session.commit()

بعد تعديل البيانات، يجب عليك استدعاء db.session.commit() لتثبيت التغييرات في قاعدة البيانات. وإلا، فسيتم تجاهلها في نهاية الطلب.

استعلامات للعروض

إذا كتبت دالة عرض Flask، فغالبًا ما يكون من المفيد إرجاع خطأ 404 Not Found للإدخالات المفقودة. يوفر Flask-SQLAlchemy بعض طرق الاستعلام الإضافية.

  • SQLAlchemy.get_or_404() سيثير خطأ 404 إذا لم يكن الصف بالمعرف المحدد موجودًا، وإلا فسيرجع المثيل.
  • SQLAlchemy.first_or_404() سيثير خطأ 404 إذا لم يُرجع الاستعلام أي نتائج، وإلا فسيرجع النتيجة الأولى.
  • SQLAlchemy.one_or_404() سيثير خطأ 404 إذا لم يُرجع الاستعلام نتيجة واحدة بالضبط، وإلا فسيرجع النتيجة.
@app.route("/user-by-id/<int:id>")
def user_by_id(id):
    user = db.get_or_404(User, id)
    return render_template("show_user.html", user=user)
@app.route("/user-by-username/<username>")
def user_by_username(username):
    user = db.one_or_404(db.select(User).filter_by(username=username))
    return render_template("show_user.html", user=user)

يمكنك إضافة رسالة مخصصة لخطأ 404:

user = db.one_or_404(
    db.select(User).filter_by(username=username),
    description=f"No user named '{username}'."
)

تقسيم نتائج الاستعلام

إذا كان لديك الكثير من النتائج، فقد ترغب فقط في عرض عدد معين في كل مرة، مما يسمح للمستخدم بالنقر على روابط التالي والعودة لرؤية صفحات من البيانات. يُطلق على هذا أحيانًا اسم ترقيم الصفحات، ويستخدم الفعل paginate.

قم باستدعاء SQLAlchemy.paginate() على بيان تحديد للحصول على كائن Pagination.

أثناء الطلب، سيأخذ هذا وسيطات page و per_page من سلسلة الاستعلام request.args. قم بتمرير max_per_page لمنع المستخدمين من طلب الكثير من النتائج في صفحة واحدة. إذا لم يتم توفيره، فإن القيم الافتراضية.

سأكون الصفحة 1 مع 20 عنصراً في كل صفحة.

page = db.paginate(db.select(User).order_by(User.join_date))
return render_template("user/list.html", page=page)

أداة اختيار الصفحة

يمتلك كائن Pagination سمات يمكن استخدامها لإنشاء أداة اختيار صفحات عن طريق التكرار فوق أرقام الصفحات والتحقق من الصفحة الحالية. سينتج iter_pages() ما يصل إلى ثلاث مجموعات من الأرقام، مفصولة بـ None. افتراضياً، يعرض رقمين للصفحتين في كل طرف، ورقمين قبل الحالي، والصفحة الحالية، و4 أرقام بعد الحالي. على سبيل المثال، إذا كان هناك 20 صفحة والصفحة الحالية هي 7، فسيتم إنتاج القيم التالية.

users.iter_pages()
[1, 2, None, 5, 6, 7, 8, 9, 10, 11, None, 19, 20]

يمكنك استخدام السمة total لعرض العدد الإجمالي للنتائج، و first و last لعرض نطاق العناصر في الصفحة الحالية.

يقوم ماكرو Jinja التالي بعرض أداة ترقيم صفحات بسيطة.

{% macro render_pagination(pagination, endpoint) %}

    {{ pagination.first }} - {{ pagination.last }} of {{ pagination.total }}
  </div>
  <div class=pagination>

        {% if page != pagination.page %}

        {% else %}
          <strong>{{ page }}</strong>
        {% endif %}
      {% else %}
        <span class=ellipsis>…</span>
      {% endif %}
    {% endfor %}
  </div>
{% endmacro %}

سياق تطبيق Flask

يُعد سياق تطبيق Flask النشط مطلوباً لإجراء الاستعلامات والوصول إلى db.engine و db.session. هذا لأن الجلسة مقيدة بالسياق بحيث يتم تنظيفها بشكل صحيح بعد كل طلب أو أمر CLI.

بغض النظر عن كيفية تهيئة التطبيق بالامتداد، فإنه لا يتم تخزينه للاستخدام لاحقاً. بدلاً من ذلك، يستخدم الامتداد وكيل current_app الخاص بـ Flask للحصول على التطبيق النشط، والذي يتطلب سياق تطبيق نشط.

السياق التلقائي

عندما يقوم Flask بمعالجة طلب أو أمر CLI، سيتم دفع سياق تطبيق تلقائياً. لذلك، لا تحتاج إلى القيام بأي شيء خاص لاستخدام قاعدة البيانات أثناء الطلبات أو أوامر CLI.

السياق اليدوي

إذا حاولت استخدام قاعدة البيانات عندما لا يكون سياق التطبيق نشطاً، فسوف ترى الخطأ التالي.

RuntimeError: Working outside of application context.
This typically means that you attempted to use functionality that needed
the current application. To solve this, set up an application context
with app.app_context(). See the documentation for more information.

إذا وجدت نفسك في موقف تحتاج فيه إلى قاعدة البيانات ولا يوجد لديك سياق، يمكنك دفع سياق باستخدام app_context. هذا شائع عند استدعاء db.create_all لإنشاء الجداول، على سبيل المثال.

def create_app():
    app = Flask(__name__)
    app.config.from_object("project.config")
    import project.models
    with app.app_context():
        db.create_all()
    return app

الاختبارات

إذا قمت باختبار تطبيقك باستخدام عميل اختبار Flask لإجراء طلبات إلى نقاط النهاية الخاصة بك، فسيكون السياق متاحاً كجزء من الطلب. إذا كنت بحاجة إلى اختبار شيء يتعلق بقاعدة البيانات أو النماذج الخاصة بك مباشرة، بدلاً من المرور عبر طلب، فأنت بحاجة إلى دفع سياق يدوياً.

قم بدفع سياق فقط في المكان والمدة التي يحتاجها كل اختبار. لا تدفع سياق تطبيق عالمياً لكل اختبار، لأن ذلك قد يتعارض مع كيفية تنظيف الجلسة.

def test_user_model(app):
    user = User()
    with app.app_context():
        db.session.add(user)
        db.session.commit()

إذا وجدت نفسك تكتب العديد من الاختبارات مثل هذه، يمكنك استخدام fixture من pytest لدفع سياق لاختبار معين.

import pytest
@pytest.fixture
def app_ctx(app):
    with app.app_context():
        yield
@pytest.mark.usefixtures("app_ctx")
def test_user_model():
    user = User()
    db.session.add(user)
    db.session.commit()

قواعد بيانات متعددة مع روابط

يمكن لـ SQLAlchemy الاتصال بأكثر من قاعدة بيانات واحدة في المرة الواحدة. وهو يشير إلى محركات مختلفة باسم "روابط". يقوم Flask-SQLAlchemy بتبسيط كيفية عمل الروابط عن طريق ربط كل محرك بسلسلة قصيرة، وهي "مفتاح ربط"، ثم ربط كل نموذج وجدول بمفتاح ربط. ستختار الجلسة أي محرك تستخدمه للاستعلام بناءً على مفتاح الربط للشيء الذي يتم الاستعلام عنه. إذا لم يتم إعطاء مفتاح ربط، يتم استخدام المحرك الافتراضي.

تهيئة الروابط

يتم تهيئة الرابط الافتراضي عن طريق تعيين SQLALCHEMY_DATABASE_URI، و SQLALCHEMY_ENGINE_OPTIONS لأي خيارات محرك. يتم توفير روابط إضافية في SQLALCHEMY_BINDS، وهو قاموس يربط مفاتيح الربط بعناوين URL للمحرك. لتحديد خيارات المحرك لرابط، يمكن أن تكون القيمة قاموساً من خيارات المحرك مع المفتاح "url"، بدلاً من مجرد سلسلة URL.

SQLALCHEMY_DATABASE_URI = "postgresql:///main"
SQLALCHEMY_BINDS = {
    "meta": "sqlite:////path/to/meta.db",
    "auth": {
        "url": "mysql://localhost/users",
        "pool_recycle": 3600,
    },
}

تعريف النماذج والجداول مع الروابط

سيقوم Flask-SQLAlchemy بإنشاء بيانات وصفية ومحرك لكل رابط تم تكوينه. سيتم تسجيل النماذج والجداول ذات مفتاح الربط مع البيانات الوصفية المقابلة، وستقوم الجلسة بالاستعلام عنها باستخدام المحرك المقابل.

لتعيين الرابط لنموذج، قم بتعيين سمة الفئة __bind_key__. عدم تعيين مفتاح ربط يعادل تعيينه إلى None، وهو المفتاح الافتراضي.

class User(db.Model):
    __bind_key__ = "auth"
    id = db.Column(db.Integer, primary_key=True)

النماذج التي ترث من هذا النموذج ستشارك نفس مفتاح الربط، أو يمكنها تجاوزه.

لتعيين الرابط لجدول، قم بتمرير الوسيطة المفتاحية bind_key.

user_table = db.Table(
    "user",
    db.Column("id", db.Integer, primary_key=True),
    bind_key="auth",
)

في النهاية، تقوم الجلسة بالبحث عن مفتاح الربط في البيانات الوصفية المرتبطة بالنموذج أو الجدول. يحدث هذا الارتباط أثناء الإنشاء. لذلك، تغيير مفتاح الربط بعد إنشاء نموذج أو جدول لن يكون له أي تأثير.

الوصول إلى البيانات الوصفية والمحركات

قد تحتاج إلى فحص البيانات الوصفية أو المحرك لرابط. لاحظ أنه يجب عليك تنفيذ الاستعلامات من خلال الجلسة، وليس مباشرة على المحرك.

المحرك الافتراضي هو SQLAlchemy.engine، والبيانات الوصفية الافتراضية هي SQLAlchemy.metadata. SQLAlchemy.engines و SQLAlchemy.metadatas عبارة عن قواميس تربط جميع مفاتيح الروابط.

إنشاء وحذف الجداول

تعمل الطرق create_all() و drop_all() على جميع الروابط افتراضياً. يمكن أن يكون الوسيط bind_key لهذه الطرق سلسلة أو None للعمل على رابط واحد، أو قائمة من السلاسل أو None للعمل على مجموعة فرعية من الروابط. نظراً لأن هذه الطرق تصل إلى المحركات، فيجب استدعاؤها داخل سياق تطبيق.

# create tables for all binds
db.create_all()
# create tables for the default and "auth" binds
db.create_all(bind_key=[None, "auth"])
# create tables for the "meta" bind
db.create_all(bind_key="meta")
# drop tables for the default bind
db.drop_all(bind_key=None)

يمكن لـ Flask-SQLAlchemy إعداد جلسته لتتبع الإدراج والتحديثات والحذف للنماذج، ثم إرسال إشارة Blinker بقائمة بهذه التغييرات إما قبل أو أثناء استدعاءات session.flush() و session.commit().

from flask_sqlalchemy.track_modifications import models_committed
def get_modifications(sender: Flask, changes: list[tuple[t.Any, str]]) -> None:

models_committed.connect(get_modifications)

تخصيص متقدم

يمكن تخصيص الكائنات المختلفة التي تديرها الوظيفة الإضافية عن طريق تمرير وسائط إلى مُنشئ SQLAlchemy.

فئة النموذج

ترث جميع نماذج SQLAlchemy من فئة أساس إعلانية. يتم عرض هذا باسم db.Model في Flask-SQLAlchemy، والذي تمتد منه جميع النماذج. يمكن تخصيص ذلك عن طريق إنشاء فئة فرعية للفئة الافتراضية وتمرير الفئة المخصصة إلى model_class.

يعطي المثال التالي كل نموذج مفتاحًا أساسيًا صحيحًا، أو مفتاحًا خارجيًا لوراثة الجدول المشتركة.

ملاحظة:

المفاتيح الأساسية الصحيحة لكل شيء ليست بالضرورة أفضل تصميم قاعدة بيانات (ذلك يعود إلى متطلبات مشروعك)، هذا مجرد مثال.
from sqlalchemy import Integer, String, ForeignKey
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column, declared_attr
class Base(DeclarativeBase):
    @declared_attr.cascading
    @classmethod
    def id(cls):
        for base in cls.__mro__[1:-1]:
            if getattr(base, "__table__", None) is not None:
                    return mapped_column(ForeignKey(base.id), primary_key=True)
            else:
                return mapped_column(Integer, primary_key=True)
db = SQLAlchemy(app, model_class=Base)
class User(db.Model):
    name: Mapped[str] = mapped_column(String)
class Employee(User):
    title: Mapped[str] = mapped_column(String)

نماذج مجردة و Mixins

إذا كان السلوك مطلوبًا فقط في بعض النماذج وليس كلها، فاستخدم فئة أساس نموذج مجردة لتخصيص تلك النماذج فقط. على سبيل المثال، إذا كان ينبغي لبعض النماذج تتبع وقت إنشائها أو تحديثها.

from datetime import datetime
from sqlalchemy import DateTime, Integer, String
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column, declared_attr
class TimestampModel(db.Model):
    __abstract__ = True
    created: Mapped[datetime] = mapped_column(DateTime, nullable=False, default=datetime.utcnow)
    updated: Mapped[datetime] = mapped_column(DateTime, default=datetime.utcnow, onupdate=datetime.utcnow)
class Author(db.Model):
    id: Mapped[int] = mapped_column(Integer, primary_key=True)
    username: Mapped[str] = mapped_column(String, unique=True, nullable=False)
class Post(TimestampModel):
    id: Mapped[int] = mapped_column(Integer, primary_key=True)
    title: Mapped[str] = mapped_column(String, nullable=False)

يمكن القيام بذلك أيضًا باستخدام فئة mixin، ترث من db.Model بشكل منفصل.

class TimestampMixin:
    created: Mapped[datetime] = mapped_column(DateTime, nullable=False, default=datetime.utcnow)
    updated: Mapped[datetime] = mapped_column(DateTime, default=datetime.utcnow, onupdate=datetime.utcnow)
class Post(TimestampMixin, db.Model):
    id: Mapped[int] = mapped_column(Integer, primary_key=True)
    title: Mapped[str] = mapped_column(String, nullable=False)

تعطيل إنشاء أسماء الجداول

يفضل بعض المشاريع تعيين __tablename__ لكل نموذج يدويًا بدلاً من الاعتماد على اكتشاف وإنشاء Flask-SQLAlchemy. الطريقة البسيطة لتحقيق ذلك هي تعيين __tablename__ لكل نموذج وعدم تعديل الفئة الأساسية. ومع ذلك، يمكن تعطيل إنشاء اسم الجدول عن طريق تعيين disable_autonaming=True في مُنشئ SQLAlchemy.

class Base(sa_orm.DeclarativeBase):
    pass
db = SQLAlchemy(app, model_class=Base, disable_autonaming=True)

فئة الجلسة

تختار فئة Session الخاصة بـ Flask-SQLAlchemy المحرك الذي سيتم الاستعلام منه بناءً على مفتاح الربط المرتبط بالنموذج أو الجدول. ومع ذلك، هناك استراتيجيات أخرى مثل التجزئة الأفقية التي يمكن تنفيذها باستخدام فئة جلسة مختلفة. المفتاح class_ لحجة session_options للوظيفة الإضافية لتغيير فئة الجلسة.

ستقوم Flask-SQLAlchemy دائمًا بتمرير مثيل الوظيفة الإضافية كوسيط db للجلسة، لذا يجب أن تقبل ذلك للاستمرار في العمل. يمكن استخدام ذلك للوصول إلى db.engines.

from sqlalchemy.ext.horizontal_shard import ShardedSession
from flask_sqlalchemy.session import Session
class CustomSession(ShardedSession, Session):
    ...
db = SQLAlchemy(session_options={"class_": CustomSession})

فئة الاستعلام

تحذير:

تعتبر واجهة الاستعلام قديمة في SQLAlchemy. يشمل ذلك session.query و Model.query و db.Query والعلاقات lazy="dynamic". يفضل استخدام session.execute(select(...)) بدلاً من ذلك.

من الممكن تخصيص واجهة الاستعلام المستخدمة بواسطة الجلسة والنماذج والعلاقات. يمكن استخدام ذلك لإضافة طرق استعلام إضافية. على سبيل المثال، يمكنك إضافة طريقة get_or التي تحصل على صف أو تعيد قيمة افتراضية.

from flask_sqlalchemy.query import Query
class GetOrQuery(Query):
    def get_or(self, ident, default=None):
        out = self.get(ident)
        if out is None:
            return default
        return out
db = SQLAlchemy(query_class=GetOrQuery)
user = User.query.get_or(user_id, anonymous_user)

سيؤدي تمرير الوسيط query_class إلى تخصيص db.Query و db.session.query و Model.query والعلاقات db.relationship(lazy="dynamic"). من الممكن أيضًا تخصيص ذلك لكل كائن على حدة.

لتخصيص خاصية query لنموذج معين، قم بتعيين السمة query_class على فئة النموذج.

class User(db.Model):
    query_class = GetOrQuery

لتخصيص علاقة ديناميكية معينة، قم بتمرير الوسيط query_class إلى العلاقة.

db.relationship(User, lazy="dynamic", query_class=GetOrQuery)

لتخصيص session.query فقط، قم بتمرير المفتاح query_cls إلى الوسيط session_options إلى المُنشئ.

db = SQLAlchemy(session_options={"query_cls": GetOrQuery})

USER GUIDE

This is a basic example of how to use Flask-SQLAlchemy.

from flask import Flask
from flask_sqlalchemy import SQLAlchemy

app = Flask(__name__)
app.config['SQLALCHEMY_DATABASE_URI'] = 'sqlite:///tmp/test.db'
db = SQLAlchemy(app)

class User(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    username = db.Column(db.String(80), unique=True, nullable=False)
    email = db.Column(db.String(120), unique=True, nullable=False)

    def __repr__(self):
        return '<User %r>' % self.username

with app.app_context():
    db.create_all()

    # Create a new user
    admin = User(username='admin', email='admin@example.com')
    db.session.add(admin)
    db.session.commit()

    # Query users
    users = User.query.all()
    print(users)

    # Query a specific user
    user = User.query.filter_by(username='admin').first()
    print(user)

    # Update a user
    user.email = 'admin_updated@example.com'
    db.session.commit()

    # Delete a user
    db.session.delete(user)
    db.session.commit()
