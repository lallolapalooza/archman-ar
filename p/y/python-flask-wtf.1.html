يمكن استخدامها مع كل من فئات FileField و MultipleFileField الخاصة بـ Flask-WTF و WTForms.

FileAllowed تعمل بشكل جيد مع Flask-Uploads.

from flask_uploads import UploadSet, IMAGES
from flask_wtf import FlaskForm
from flask_wtf.file import FileField, FileAllowed, FileRequired
images = UploadSet('images', IMAGES)
class UploadForm(FlaskForm):
    upload = FileField('image', validators=[
        FileRequired(),
        FileAllowed(images, 'Images only!')
    ])

يمكن استخدامها بدون Flask-Uploads عن طريق تمرير الامتدادات مباشرة.

class UploadForm(FlaskForm):
    upload = FileField('image', validators=[
        FileRequired(),
        FileAllowed(['jpg', 'png'], 'Images only!')
    ])

Recaptcha

يوفر Flask-WTF أيضًا دعم Recaptcha من خلال RecaptchaField:

from flask_wtf import FlaskForm, RecaptchaField
from wtforms import TextField
class SignupForm(FlaskForm):
    username = TextField('Username')
    recaptcha = RecaptchaField()

يأتي هذا مع عدد من متغيرات التكوين، بعضها يجب عليك تكوينه.

RECAPTCHA_PUBLIC_KEY مطلوب مفتاح عام.
RECAPTCHA_PRIVATE_KEY مطلوب مفتاح خاص.
RECAPTCHA_API_SERVER اختياري حدد خادم واجهة برمجة تطبيقات Recaptcha الخاص بك.
RECAPTCHA_PARAMETERS اختياري قاموس بمعلمات JavaScript (api.js).
RECAPTCHA_DATA_ATTRS اختياري قاموس بخيارات سمات البيانات. https://developers.google.com/recaptcha/docs/display#javascript_resource_apijs_parameters

مثال على RECAPTCHA_PARAMETERS و RECAPTCHA_DATA_ATTRS:

RECAPTCHA_PARAMETERS = {'hl': 'zh', 'render': 'explicit'}
RECAPTCHA_DATA_ATTRS = {'theme': 'dark'}

لتسهيل الأمر عليك، عند اختبار تطبيقك، إذا كان app.testing هو True، فسيكون حقل recaptcha صالحًا دائمًا.

ويمكن إعداده بسهولة في القوالب:

حماية CSRF

أي عرض يستخدم FlaskForm لمعالجة الطلب يحصل بالفعل على حماية CSRF. إذا كانت لديك عروض لا تستخدم FlaskForm أو تجري طلبات AJAX، فاستخدم امتداد CSRF المقدم لحماية تلك الطلبات أيضًا.

الإعداد

لتمكين حماية CSRF بشكل عام لتطبيق Flask، قم بتسجيل امتداد CSRFProtect.

from flask_wtf.csrf import CSRFProtect
csrf = CSRFProtect(app)

مثل امتدادات Flask الأخرى، يمكنك تطبيقها بشكل كسول:

csrf = CSRFProtect()
def create_app():
    app = Flask(__name__)
    csrf.init_app(app)

ملاحظة:

تتطلب حماية CSRF مفتاحًا سريًا لتوقيع الرمز المميز بشكل آمن. افتراضيًا، سيستخدم هذا SECRET_KEY الخاص بتطبيق Flask. إذا كنت ترغب في استخدام رمز مميز منفصل، يمكنك تعيين WTF_CSRF_SECRET_KEY.

نماذج HTML

عند استخدام FlaskForm، قم بعرض حقل CSRF الخاص بالنموذج بشكل طبيعي.

<form method="post">
    {{ form.csrf_token }}
</form>

إذا لم يستخدم القالب FlaskForm، فقم بعرض حقل إدخال مخفي بالرمز المميز في النموذج.

<form method="post">
    <input type="hidden" name="csrf_token" value="{{ csrf_token() }}"/>
</form>

طلبات JavaScript

عند إرسال طلب AJAX، أضف رأس X-CSRFToken إليه. على سبيل المثال، في jQuery يمكنك تكوين جميع الطلبات لإرسال الرمز المميز.

<script type="text/javascript">
    var csrf_token = "{{ csrf_token() }}";
    $.ajaxSetup({
        beforeSend: function(xhr, settings) {
            if (!/^(GET|HEAD|OPTIONS|TRACE)$/i.test(settings.type) && !this.crossDomain) {
                xhr.setRequestHeader("X-CSRFToken", csrf_token);
            }
        }
    });
</script>

في Axios، يمكنك تعيين الرأس لجميع الطلبات باستخدام axios.defaults.headers.common.

from flask_wtf.csrf import CSRFError
@app.errorhandler(CSRFError)
def handle_csrf_error(e):
    return render_template('csrf_error.html', reason=e.description), 400

استثناء العروض من الحماية

نقترح بشدة أن تقوم بحماية جميع عروضك باستخدام CSRF. ولكن إذا لزم الأمر، يمكنك استثناء بعض العروض باستخدام مزخرف.

@app.route('/foo', methods=('GET', 'POST'))
@csrf.exempt
def my_handler():
    # ...
    return 'ok'

يمكنك استثناء جميع عروض مخطط.

csrf.exempt(account_blueprint)

يمكنك تعطيل حماية CSRF في جميع العروض افتراضيًا، عن طريق تعيين WTF_CSRF_CHECK_DEFAULT إلى False، واستدعاء protect() بشكل انتقائي فقط عند الحاجة. يتيح لك هذا أيضًا إجراء بعض المعالجة المسبقة للطلبات قبل التحقق من رمز CSRF المميز.

RECAPTCHA_HTML optional Override default HTML template for Recaptcha.
RECAPTCHA_DATA_ATTRS optional A dict of data- attrs to use for Recaptcha div
RECAPTCHA_SCRIPT optional Override the default captcha script URI in case an alternative service to reCAPtCHA, e.g. hCaptcha is used. Default is 'https://www.google.com/recaptcha/api.js'
RECAPTCHA_DIV_CLASS optional Override the default class of the captcha div in case an alternative captcha service is used. Default is 'g-recaptcha'
RECAPTCHA_VERIFY_SERVER optional Override the default verification server in case an alternative service is used. Default is 'https://www.google.com/recaptcha/api/siteverify'

Logging

CSRF errors are logged at the INFO level to the flask_wtf.csrf logger. You still need to configure logging in your application in order to see these messages.

    NAME

    flask-wtf - WTForms integration with Flask

    FEATURES

    • Form validation.
    • CSRF protection.
    • File uploads.

    USER'S GUIDE

    To install Flask-WTF, run:

    $ pip install Flask-WTF

    Then, in your Flask application:

    from flask import Flask
from flask_wtf import FlaskForm
from wtforms import StringField, SubmitField
from wtforms.validators import DataRequired

app = Flask(__name__)
app.config['SECRET_KEY'] = 'a very secret key'`

class MyForm(FlaskForm):
    name = StringField('Name', validators=[DataRequired()])
    submit = SubmitField('Submit')

@app.route('/', methods=['GET', 'POST'])
def index():
    form = MyForm()
    if form.validate_on_submit():
        return f'Hello {form.name.data}!'
    return render_template('index.html', form=form)

    This example shows a simple form with a single text field and a submit button. The form is validated on submission, and if valid, a greeting is returned. Otherwise, the form is rendered again with error messages.

    For more advanced usage, including CSRF protection and file uploads, refer to the official documentation.

    ADDITIONAL NOTES

    Contributions to Flask-WTF are welcome. Before submitting a pull request, please ensure that your changes are well-tested and documented. Follow these steps:

    • Fork the repository on GitHub.

    • Create a new branch for your feature or bug fix:

      $ git checkout -b your-branch-name

    • Make your changes and add tests.

    • Run the tests to ensure everything is working correctly.

      $ pytest

      If you need to run the full test suite, use tox:

      $ tox

    • Commit your changes.

      $ git commit -am "Add new feature"

    • Push your branch to your fork:

      $ git push --set-upstream fork your-branch-name

    • Create a pull request on GitHub.

    $ git push --set-upstream fork your-branch-name

Running the tests

Run the basic test suite with pytest.

$ pytest

This runs the tests for the current environment, which is usually sufficient. CI will run the full suite when you submit your pull request. You can run the full test suite with tox if you don't want to wait.

$ tox

Running test coverage

Generating a report of lines that do not have test coverage can indicate where to start contributing. Run pytest using coverage and generate a report.

$ pip install coverage
$ coverage run -m pytest
$ coverage html

Open htmlcov/index.html in your browser to explore the report.

Building the docs

$ cd docs
$ make html

Open _build/html/index.html in your browser to view the docs.
