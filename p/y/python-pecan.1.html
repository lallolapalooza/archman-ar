تحديد مقاطع المسار الصريحة

في بعض الأحيان، قد ترغب في استخدام مقطع مسار في التوجيه الخاص بك لا يعمل مع نهج Pecan التصريحي للتوجيه بسبب القيود في بناء جملة Python. على سبيل المثال، إذا كنت ترغب في التوجيه لمسار يتضمن واصلات، مثل /some-path/، فإن ما يلي ليس صالحًا في Python:

class RootController(object):
    @pecan.expose()
    def some-path(self):
        return dict()

لتجاوز ذلك، يسمح لك Pecan بتحديد مقطع مسار صريح في مزخرف expose():

class RootController(object):
    @pecan.expose(route='some-path')
    def some_path(self):
        return dict()

في هذا المثال، سيستجيب تطبيق Pecan برمز HTTP 200 للطلبات التي تم إجراؤها على /some-path/، ولكن الطلبات التي تم إجراؤها على /some_path/ ستؤدي إلى HTTP 404.

يمكن أيضًا استخدام route() بشكل صريح كبديل للوسيط route في expose():

class RootController(object):
    @pecan.expose()
    def some_path(self):
        return dict()
pecan.route('some-path', RootController.some_path)

يمكن معالجة التوجيه إلى وحدات التحكم الفرعية بالمثل عن طريق استخدام route():

class ChildController(object):
    @pecan.expose()
    def child(self):
        return dict()
class RootController(object):
    pass
pecan.route(RootController, 'child-path', ChildController())

في هذا المثال، سيستجيب تطبيق Pecan برمز HTTP 200 للطلبات التي تم إجراؤها على /child-path/child/.

التوجيه بناء على طريقة الطلب

يوفر الوسيط generic لـ expose() دعمًا لتجاوز عناوين URL بناءً على طريقة الطلب. في المثال التالي، يمكن خدمة نفس عنوان URL بواسطة طريقتين مختلفتين (واحدة لمعالجة HTTP GET، وأخرى لـ HTTP POST) باستخدام وحدات التحكم العامة:

from pecan import expose
class RootController(object):
    # HTTP GET /
    @expose(generic=True, template='json')
    def index(self):
        return dict()
    # HTTP POST /
    @index.when(method='POST', template='json')
    def index_POST(self, **kw):
        uuid = create_something()
        return dict(uuid=uuid)

خوارزمية توجيه Pecan

في بعض الأحيان، لا يكون التوجيه القياسي للكائنات كافيًا لتوجيه عنوان URL بشكل صحيح إلى وحدة تحكم. يوفر Pecan عدة طرق لقطع نظام توجيه الكائنات لمعالجة عناوين URL بتحكم أكبر، بما في ذلك الأساليب الخاصة _lookup() و _default() و _route(). يمنح تعريف هذه الأساليب على كائنات وحدة التحكم الخاصة بك مرونة إضافية لمعالجة كل أو جزء من عنوان URL.

التوجيه إلى وحدات التحكم الفرعية باستخدام _lookup

توفر الطريقة الخاصة _lookup() طريقة لمعالجة جزء من عنوان URL، ثم إرجاع كائن وحدة تحكم جديد للتوجيه إليه للباقي.

قد تقبل الطريقة _lookup() وسيطًا واحدًا أو أكثر، وهي مقاطع من مسار عنوان URL للمعالجة (مقسومة على /). يجب أن تأخذ _lookup() أيضًا وسائط موضعية متغيرة تمثل بقية المسار، ويجب أن تتضمن أي جزء من المسار لا تعالجه في قيمتها المرجعة. يستخدم المثال أدناه قائمة *remainder التي سيتم تمريرها إلى وحدة التحكم المرجعة عندما تستمر خوارزمية توجيه الكائن.

بالإضافة إلى استخدامها لإنشاء وحدات تحكم ديناميكيًا، يتم استدعاء _lookup() كملاذ أخير، عندما لا تتطابق أي طريقة وحدة تحكم أخرى مع عنوان URL ولا توجد طريقة _default().

from pecan import expose, abort
from somelib import get_student_by_name
class StudentController(object):
    def __init__(self, student):
        self.student = student
    @expose()
    def name(self):
        return self.student.name
class RootController(object):
    @expose()
    def _lookup(self, primary_key, *remainder):
        student = get_student_by_primary_key(primary_key)
        if student:
            return StudentController(student), remainder
        else:
            abort(404)

سيؤدي طلب HTTP GET إلى /8/name إلى إرجاع اسم الطالب حيث primary_key == 8.

الاحتياط باستخدام _default

يتم استدعاء الطريقة _default() كملاذ أخير عندما لا تتطابق أي طرق وحدة تحكم أخرى مع عنوان URL عبر توجيه الكائنات القياسي.

from pecan import expose
class RootController(object):
    @expose()
    def english(self):
        return 'hello'
    @expose()
    def french(self):
        return 'bonjour'
    @expose()
    def _default(self):
        return 'I cannot say hello in that language'

في المثال أعلاه، سيتم توجيه طلب إلى /spanish إلى RootController._default().

تعريف التوجيه المخصص باستخدام _route

تسمح الطريقة _route() لوحدة تحكم بتجاوز آلية توجيه Pecan بالكامل. يستخدم Pecan نفسه الطريقة _route() لتنفيذ RestController الخاص به. إذا كنت ترغب في تصميم نظام توجيه بديل فوق Pecan، فإن تعريف فئة وحدة تحكم أساسية تحدد طريقة _route() سيمكنك من الحصول على تحكم كامل.

التفاعل مع كائن الطلب والاستجابة

لكل طلب HTTP، يحتفظ Pecan مرجع محلي للخيط لكائن الطلب والاستجابة، pecan.request و pecan.response. هذه مثيلات لـ pecan.Request و pecan.Response على التوالي، ويمكن التفاعل معها من داخل رمز وحدة تحكم Pecan:

@pecan.expose()
def login(self):
    assert pecan.request.path == '/login'
    username = pecan.request.POST.get('username')
    password = pecan.request.POST.get('password')
    pecan.response.status = 403
    pecan.response.text = 'Bad Login!'

بينما يقوم Pecan بتجريد الكثير من الحاجة إلى التفاعل مع هذه الكائنات مباشرة، قد تكون هناك مواقف ترغب فيها في الوصول إليها، مثل:

  • فحص مكونات URI
  • تحديد جوانب الطلب، مثل عنوان IP للمستخدم، أو ترويسة المرجع
  • تعيين ترويسات استجابة محددة
  • عرض جسم استجابة يدويًا

تحديد استجابة مخصصة

قم بتعيين رمز استجابة HTTP محدد (مثل 203 معلومات غير موثوقة) عن طريق تعديل السمة status لكائن الاستجابة.

from pecan import expose, response
class RootController(object):
    @expose('json')
    def hello(self):
        response.status = 203
        return {'foo': 'bar'}

استخدم وظيفة الأداة المساعدة abort() لإطلاق أخطاء HTTP.

from pecan import expose, abort
class RootController(object):
    @expose('json')
    def hello(self):
        abort(404)

abort() يطلق مثيلًا لـ WSGIHTTPException الذي يستخدمه Pecan لعرض أجسام استجابة افتراضية لأخطاء HTTP. يتم تخزين هذا الاستثناء في بيئة طلب WSGI في pecan.original_exception، حيث يمكن الوصول إليه لاحقًا في دورة الطلب (بواسطة، على سبيل المثال، برامج وسيطة أخرى أو مستندات خطأ مخصصة).

إذا كنت ترغب في إرجاع استجابة صريحة، يمكنك القيام بذلك باستخدام Response:

from pecan import expose, Response
class RootController(object):
    @expose()
    def hello(self):
        return Response('Hello, World!', 202)

توسيع كائنات الطلب والاستجابة في Pecan

تطبيقات الطلب والاستجابة التي يوفرها WebOb قوية، ولكن في بعض الأحيان، قد يكون من المفيد توسيع سلوكيات خاصة بالتطبيق على طلبك واستجابتك (مثل التحليل المتخصص لترويسات الطلب أو تسلسل جسم الاستجابة المخصص). للقيام بذلك، قم بتعريف فئات مخصصة ترث من pecan.Request و pecan.Response على التوالي:

class MyRequest(pecan.Request):
    pass
class MyResponse(pecan.Response):
    pass

وقم بتعديل تكوين التطبيق الخاص بك لاستخدامها:

from myproject import MyRequest, MyResponse
app = {
    'root' : 'project.controllers.root.RootController',
    'modules' : ['project'],
    'static_root'   : '%(confdir)s/public',
    'template_path' : '%(confdir)s/project/templates',
    'request_cls': MyRequest,
    'response_cls': MyResponse
}

SECURE

The secure() decorator is used to protect controller methods and classes. This decorator takes one argument: the name of the method (as a string) which should be called to determine if the request should proceed. If the method returns True, the request proceeds; otherwise, an HTTPUnauthorized exception is raised.

from pecan import expose
from pecan.secure import secure
class RootController(object):
    def is_admin(self):
        return True
    @secure('is_admin')
    @expose()
    def index(self):
        return 'Admin Page'

In the example above, is_admin() is called when the user attempts to access the index() method. If is_admin() returns False, the user will be presented with a 401 Unauthorized error.

You can also use secure() to secure entire controller classes. When used to decorate a class, it will check the security method before entering any method within that controller.

from pecan import expose
from pecan.secure import secure
class SecureController(object):
    def check_access(self):
        return True
    @expose()
    def index(self):
        return 'Welcome'
    @expose()
    def another_page(self):
        return 'Another Page'
root = secure(SecureController(), 'check_access')

In this example, the check_access() method will be called before either index() or another_page() are invoked.

The secure() method also accepts a function argument. When passing a function, make sure that the function is imported from another file or defined in the same file before the class definition, otherwise you will likely get error during module import.

from pecan import expose
from pecan.secure import secure
from myapp.auth import user_authenitcated
class RootController(object):
    @secure(user_authenticated)
    @expose()
    def index(self):
        return 'Logged in'

You can also use the secure() method to change the behavior of a SecureController. Decorating a method or wrapping a subcontroller tells Pecan to use another security function other than the default controller method. This is useful for situations where you want a different level or type of security.

from pecan import expose
from pecan.secure import SecureController, secure
from myapp.auth import user_authenticated, admin_user
class ApiController(object):
    pass
class RootController(SecureController):
    @classmethod
    def check_permissions(cls):
        return user_authenticated()
    @classmethod
    def check_api_permissions(cls):
        return admin_user()
    @expose()
    def index(self):
        return 'logged in user'
    api = secure(ApiController(), 'check_api_permissions')

In the example above, pecan will only call admin_user() when a request is made for /api/.

Multiple Secure Controllers

Secure controllers can be nested to provide increasing levels of security on subcontrollers. In the example below, when a request is made for /admin/index/, Pecan first calls check_permissions() on the RootController and then calls check_permissions() on the AdminController.

from pecan import expose
from pecan.secure import SecureController
from myapp.auth import user_logged_in, is_admin
class AdminController(SecureController):
    @classmethod
    def check_permissions(cls):
        return is_admin()
    @expose()
    def index(self):
        return 'admin dashboard'
class RootController(SecureController):
    @classmethod
    def check_permissions(cls):
        return user_logged_in
    @expose()
    def index(self):
        return 'user dashboard'

PECAN HOOKS

Although it is easy to use WSGI middleware with Pecan, it can be hard (sometimes impossible) to have access to Pecan's internals from within middleware. Pecan Hooks are a way to interact with the framework, without having to write separate middleware.

Hooks allow you to execute code at key points throughout the life cycle of your request:

  • on_route(): called before Pecan attempts to route a request to a controller
  • before(): called after routing, but before controller code is run
  • after(): called after controller code has been run
  • on_error(): called when a request generates an exception

Implementating a Pecan Hook

In the below example, a simple hook will gather some information about the request and print it to stdout.

Your hook implementation needs to import PecanHook so it can be used as a base class. From there, you'll want to override the on_route(), before(), after(), or on_error() methods to define behavior.

from pecan.hooks import PecanHook
class SimpleHook(PecanHook):
    def before(self, state):
        print "\nabout to enter the controller..."
    def after(self, state):
        print "\nmethod: \t %s" % state.request.method
        print "\nresponse: \t %s" % state.response.status

on_route(), before(), and after() are each passed a shared state object which includes useful information, such as the request and response objects, and which controller was selected by Pecan's routing:

from pecan.hooks import PecanHook
import webob
import inspect
class SimpleHook(PecanHook):
    def on_route(self, state):
        print "\nabout to map the URL to a Python method (controller)..."
        assert state.controller is None  # Routing hasn't occurred yet
        assert isinstance(state.request, webob.Request)
        assert isinstance(state.response, webob.Response)
        assert isinstance(state.hooks, list)  # A list of hooks to apply
    def before(self, state):
        print "\nabout to enter the controller..."
        if state.request.path == '/':
            #
            # `state.controller` is a reference to the actual
            # `@pecan.expose()`-ed controller that will be routed to
            # and used to generate the response body
            #
            from myapp.controllers import RootController # Assuming RootController is in myapp.controllers
            assert state.controller.__func__ is RootController.index.__func__
            assert isinstance(state.arguments, inspect.Arguments)
            print state.arguments.args
            print state.arguments.varargs
            print state.arguments.keywords
        assert isinstance(state.request, webob.Request)
        assert isinstance(state.response, webob.Response)
        assert isinstance(state.hooks, list)

on_error() is passed a shared state object and the original exception. If an on_error() handler returns a Response object, this response will be returned to the end user and no furthur on_error() hooks will be executed:

from pecan.hooks import PecanHook
import webob
class CustomErrorHook(PecanHook):
    def on_error(self, state, exc):

Attaching Hooks

Hooks can be attached in a project-wide manner by specifying a list of hooks in your project's configuration file.

app = {
    'root' : 'myapp.controllers.RootController',
    'modules': ['myapp'],
    'static_root': '%(confdir)s/public',
    'template_path': '%(confdir)s/templates',
    'debug': True,
    'hooks': lambda: [SimpleHook()] # Assuming SimpleHook is defined in the same file or imported
}

Hooks can also be applied selectively to controllers and their sub-controllers using the __hooks__ attribute on one or more controllers and subclassing HookController.

from pecan import expose
from pecan.hooks import HookController
# Assuming SimpleHook is imported from my_hooks module
# from my_hooks import SimpleHook
# Placeholder for SimpleHook if not imported
class SimpleHook:
    def before(self, state):
        print("\nabout to enter the controller...")
    def after(self, state):
        print("\nmethod: \t %s" % state.request.method)
        print("\nresponse: \t %s" % state.response.status)
class SimpleController(HookController):
    __hooks__ = [SimpleHook()]
    @expose('json')
    def index(self):
        print "DO SOMETHING!"
        return dict()

Hooks can be inherited from parent class or mixins. Just make sure to subclass from HookController.

from pecan import expose
from pecan.hooks import PecanHook, HookController
class ParentHook(PecanHook):
    priority = 1
    def before(self, state):
        print "\nabout to enter the parent controller..."
class CommonHook(PecanHook):
    priority = 2
    def before(self, state):
        print "\njust a common hook..."
class SubHook(PecanHook):
    def before(self, state):
        print "\nabout to enter the subcontroller..."
class SubMixin(object):
    __hooks__ = [SubHook()]
# We'll use the same instance for both controllers,
# to avoid double calls
common = CommonHook()
class SubController(HookController, SubMixin):
    __hooks__ = [common]
    @expose('json')
    def index(self):
        print "\nI AM THE SUB!"
        return dict()
class RootController(HookController):
    __hooks__ = [common, ParentHook()]
    @expose('json')
    def index(self):
        print "\nI AM THE ROOT!"
        return dict()
    sub = SubController()

Let's see what happens when we run the app. First loading the root controller:

pecan serve config.py
serving on 0.0.0.0:8080 view at http://127.0.0.1:8080
GET / HTTP/1.1" 200
about to enter the parent controller...
just a common hook
I AM THE ROOT!

Then loading the sub controller:

pecan serve config.py
serving on 0.0.0.0:8080 view at http://127.0.0.1:8080
GET /sub HTTP/1.1" 200
about to enter the parent controller...
just a common hook
about to enter the subcontroller...
I AM THE SUB!

NOTE:

Make sure to set proper priority values for nested hooks in order to get them executed in the desired order.

WARNING:

Two hooks of the same type will be added/executed twice, if passed as different instances to a parent and a child controller. If passed as one instance variable - will be invoked once for both controllers.

import os
import cherrypy
from cheroot import wsgi
from cheroot.wsgi import PathInfoDispatcher
from pecan.deploy import deploy
simpleapp_wsgi_app = deploy('/path/to/production_config.py')
public_path = os.path.abspath(os.path.join(os.path.dirname(__file__), 'public'))
# A dummy class for our Root object
# necessary for some CherryPy machinery
class Root(object):
    pass
def make_static_config(static_dir_name):
    """
    All custom static configurations are set here, since most are common, it
    makes sense to generate them just once.
    """
    static_path = os.path.join('/', static_dir_name)
    path = os.path.join(public_path, static_dir_name)
    configuration = {
        static_path: {
            'tools.staticdir.on': True,
            'tools.staticdir.dir': path
        }
    }
    return cherrypy.tree.mount(Root(), '/', config=configuration)

    server.start()

  • تمت إضافة دعم لتعطيل pecan.request و pecan.response threadlocals على مستوى تطبيق WSGI لصالح تمرير المرجع الصريح. لمزيد من المعلومات، راجع Context/Thread-Locals مقابل تمرير الوسيطات الصريح.
  • تمت إضافة دعم أفضل لتكوين الخطافات عبر التوريث والمزج. لمزيد من المعلومات، راجع إرفاق الخطافات.
  • تمت إضافة دعم لتحديد تطبيقات طلب واستجابة مخصصة على مستوى تطبيق WSGI للأشخاص الذين يرغبون في توسيع الوظائف التي توفرها الفئات الأساسية في webob.
  • يمكن لوحدات تحكم Pecan الآن إرجاع مثيل webob.Response صريح لتجاوز عرض قوالب Pecan والتسلسل.
  • بالنسبة للدوال العامة التي ترجع HTTP 405، يقوم pecan الآن بإنشاء رأس Allow لتوصيل الطرق المقبولة للعميل.
  • تم إصلاح خطأ في الالتزام بـ RFC2616: إذا أعادت طريقة مكشوفة عدم وجود جسم استجابة (أو مساحة اسم)، فإن pecan ستفرض الآن استجابة HTTP 204 (بدلاً من HTTP 200).
  • تم إصلاح خطأ في الالتزام بـ RFC2616: عندما تستجيب pecan بـ HTTP 204 أو HTTP 304، يتم تجريد رأس Content-Type تلقائيًا (لأن هذه الأنواع من استجابات HTTP لا تحتوي على محتوى جسم).
  • تم إصلاح خطأ: الآن عندما يطلب العملاء JSON عبر رأس Accept، يتم تسلسل استثناءات HTTP webob كـ JSON، وليس تمثيلها الأصلي لـ HTML.
  • تم إصلاح خطأ كسر التطبيقات التي حددت default_renderer = json.

  • تم إصلاح خطأ متعلق بالتكرار في البرامج الوسيطة لمستند الخطأ.
  • تم إصلاح خطأ في أمر gunicorn_pecan تسبب في تسرب بيانات threading.local بين خيوط green eventlet/gevent.
  • تم تحسين الوثائق من خلال الإصلاحات والبرامج التعليمية السردية لتطبيقات pecan النموذجية.
