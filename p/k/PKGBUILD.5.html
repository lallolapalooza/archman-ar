PKGBUILD(5)

الحزمة: pacman

التراخيص: GPL-2.0-or-later

NAME

PKGBUILD - Arch build script

SYNOPSIS

PKGBUILD

DESCRIPTION

A PKGBUILD is a shell script containing an array of variables and functions that define how a package is built. It is used by makepkg(8) to build Arch Linux packages.

The script is executed using bash(1), and is split into several distinct parts.

The first part consists of metadata variable definitions:

pkgbase
The name used to refer to the group of packages in the output of makepkg and in the naming of source-only tarballs. If not specified, the first element in the pkgname array is used.
pkgname
An array of package names this PKGBUILD builds. If only one package is built, this can be a single string.
pkgver
The package version.
pkgrel
The package release. Incremented for related changes to the PKGBUILD that do not modify the package version.
epoch
An optional non-zero integer. If specified, it replaces the package version and release number for dependency checking purposes. This is typically used to reset the package release number when a change to the packaging itself is not sufficient (e.g. if a dependency changes to a newer version).
pkgdesc
A string describing the package.
arch
An array of architectures the package supports. Use 'any' for packages that are architecture-independent.
url
The upstream URL for the software.
license
An array of licenses the package conforms to. See makepkg.conf(5) for available license identifiers.
groups
An array of groups the package belongs to. For example, 'base-devel'.
depends
An array of packages that must be installed for this package to work.
makedepends
An array of packages that are required for building the package, but not for running it.
checkdepends
An array of packages required for running the package's integrity checks (e.g. test suite).
optdepends
An array of optional dependencies. Each element can be a package name or a package name followed by a description of the functionality it enables. These are not installed by default.
provides
An array of virtual packages or functionalities that this package provides.
conflicts
An array of packages that conflict with this package. Installing one will uninstall the other.
replaces
An array of packages that this package replaces. Installing this package will remove the replaced packages.
backup
An array of files or directories to be backed up when the package is upgraded or removed. This is useful for configuration files that might be modified by the user.
options
An array of build options. See makepkg.conf(5) for available options.
install
The filename of an install script to be executed by pacman.
changelog
The filename of a changelog file.

The second part consists of arrays defining sources and checksums:

source
An array of filenames or URLs for the source files needed to build the package. Local files are expected to be in the same directory as the PKGBUILD.
noextract
An array of filenames or patterns that should not be extracted by makepkg. Useful for non-archive source files.
sha256sums
An array of SHA256 checksums for the files in the source array. Use 'SKIP' for integrity-checked sources like VCS checkouts or signed tarballs.
md5sums
An array of MD5 checksums. Prefer sha256sums.
sha1sums
An array of SHA1 checksums. Prefer sha256sums.
sha512sums
An array of SHA512 checksums. Prefer sha256sums.
b2sums
An array of BLAKE2 sums. Prefer sha256sums.

The third part consists of build functions:

prepare()
This function is used for any necessary build-time modifications to the source code, like patching or running a build system's configure script prior to compilation. It is run after sources are downloaded and extracted.
build()
This function is used for compiling the package. It is run after prepare().
check()
This function is used for running the package's integrity checks, such as its test suite. It is run after build().
package()
This function is used for installing the compiled package into a fake root environment (the directory specified by $pkgdir). It is run after check().

The following functions can also be defined and are executed by pacman during package installation, upgrade, or removal:

pre_install()
Runs before any files are extracted.
post_install()
Runs after all files have been extracted.
pre_upgrade()
Runs before any files are extracted during an upgrade. It receives the new and old package versions as arguments.
post_upgrade()
Runs after all files have been extracted during an upgrade. It receives the new and old package versions as arguments.
pre_remove()
Runs before any files are removed.
post_remove()
Runs after all files have been removed.

The default behavior of makepkg is to build packages sequentially in the order defined in the pkgname array. However, if the PKGBUILD builds multiple related packages (e.g., a library and its development files), it can be configured to build them as a split package group.

OPTIONS AND DIRECTIVES

The PKGBUILD file supports a number of options and directives that control the build process. These can be set globally in makepkg.conf(5) or overridden on a per-package basis.

The following options can be set:

buildflags
Flags passed to the compiler during the build process. Examples include Cflags, CXXflags, LDFLAGS.
makeflags
Flags passed to the make command. Often used to specify the number of parallel jobs, e.g., -j$(nproc).
validjournalymdhms
A timestamp string used to validate the package. If the package's build time is older than this timestamp, makepkg will refuse to build it.

PACKAGING FUNCTIONS

The following functions are used to define package metadata and behavior:

pkgdesc
Description of the package.
arch
Supported architectures.
url
Upstream URL.
license
Package license(s).
groups
Package groups.
depends
Runtime dependencies.
optdepends
Optional runtime dependencies.
provides
Provides clauses.
conflicts
Conflicts clauses.
replaces
Replaces clauses.
backup
Files/directories to back up.
options
Build options.
install
Install script filename.
changelog
Changelog filename.

PACKAGE SPLITTING

All options and directives for the split packages default to the global values given in the PKGBUILD. Nevertheless, the following ones can be overridden within each split package’s packaging function: pkgdesc, arch, url, license, groups, depends, optdepends, provides, conflicts, replaces, backup, options, install, and changelog.

Note that makepkg does not consider split package depends when checking if dependencies are installed before package building and with --syncdeps. All packages required to make the package are required to be specified in the global depends and makedepends arrays.

An optional global directive is available when building a split package:

pkgbase

The name used to refer to the group of packages in the output of makepkg and in the naming of source-only tarballs. If not specified, the first element in the pkgname array is used. Valid characters for this variable are alphanumerics, and any of the following characters: “@ . _ + -”. Additionally, the variable is not allowed to start with hyphens or dots.

INSTALL/UPGRADE/REMOVE SCRIPTING

Pacman has the ability to store and execute a package-specific script when it installs, removes, or upgrades a package. This allows a package to configure itself after installation and perform an opposite action upon removal.

The exact time the script is run varies with each operation, and should be self-explanatory. Note that during an upgrade operation, none of the install or remove functions will be called.

Scripts are passed either one or two “full version strings”, where a full version string is either pkgver-pkgrel or epoch:pkgver-pkgrel, if epoch is non-zero.

pre_install

Run right before files are extracted. One argument is passed: new package full version string.

post_install

Run right after files are extracted. One argument is passed: new package full version string.

pre_upgrade

Run right before files are extracted. Two arguments are passed in this order: new package full version string, old package full version string.

post_upgrade

Run after files are extracted. Two arguments are passed in this order: new package full version string, old package full version string.

pre_remove

Run right before files are removed. One argument is passed: old package full version string.

post_remove

Run right after files are removed. One argument is passed: old package full version string.

To use this feature, create a file such as pkgname.install and put it in the same directory as the PKGBUILD script. Then use the install directive:

install=pkgname.install

The install script does not need to be specified in the source array. A template install file is available in /usr/share/pacman as proto.install for reference with all of the available functions defined.

USING VCS SOURCES

Building a developmental version of a package using sources from a version control system (VCS) is enabled by specifying the source in the form:

source=('directory::url#fragment?query')

Currently makepkg supports the Bazaar, Git, Subversion, Fossil and Mercurial version control systems. For other version control systems, manual cloning of upstream repositories must be done in the prepare() function.

Some VCS Sources like Git support pinning the checkout by a checksum of its content using deterministic export functionality like “git archive”.

The source URL is divided into four components:

directory

(optional) Specifies an alternate directory name for makepkg to download the VCS source into.

url

The URL to the VCS repository. This must include the VCS in the URL protocol for makepkg to recognize this as a VCS source. If the protocol does not include the VCS name, it can be added by prefixing the URL with vcs+. For example, using a Git repository over HTTPS would have a source URL in the form: git+https://....

fragment

(optional) Allows specifying a revision number or branch for makepkg to checkout from the VCS. A fragment has the form type=value, for example to checkout a given revision the source line would be source=(url#revision=123). The available types depends on the VCS being used:

bzr

revision (see 'bzr help revisionspec' for details)

fossil

branch, commit, tag

git

branch, commit, tag

hg

branch, revision, tag

svn

revision

query

(optional) Allows specifying whether a VCS checkout should be checked for PGP-signed revisions. The source line should have the format source=(url#fragment?signed) or source=(url?signed#fragment). Currently only supported by Git.

EXAMPLE

The following is an example PKGBUILD for the patch package. For more examples, look through the build files of your distribution’s packages.

# Maintainer: Joe User <joe.user@example.com>
pkgname=patch
pkgver=2.7.1
pkgrel=1
pkgdesc="A utility to apply patch files to original sources"
arch=('i686' 'x86_64')
url="https://www.gnu.org/software/patch/patch.html"
license=('GPL')
groups=('base-devel')
depends=('glibc')
makedepends=('ed')
optdepends=('ed: for "patch -e" functionality')
source=("ftp://ftp.gnu.org/gnu/$pkgname/$pkgname-$pkgver.tar.xz"{,.sig})
sha256sums=('9124ba46db0abd873d0995c2ca880e81252676bb6c03e0a37dfc5f608a9b0ceb'
            'SKIP')
build() {
        cd "$srcdir/$pkgname-$pkgver"
        ./configure --prefix=/usr
        make
}
package() {
        cd "$srcdir/$pkgname-$pkgver"
        make DESTDIR="$pkgdir/" install}
