الاسم

pk12util - تصدير واستيراد المفاتيح والشهادات إلى أو من ملف PKCS #12 وقاعدة بيانات NSS

الملخص

pk12util [-i p12File|-l p12File|-o p12File] [-c keyCipher] [-C certCipher] [-d directory] [-h tokenname] [-m | --key-len keyLength] [-M hashAlg] [-n certname] [-P dbprefix] [-r] [-v] [--cert-key-len certKeyLength] [-k slotPasswordFile|-K slotPassword] [-w p12filePasswordFile|-W p12filePassword]

الحالة

هذه الوثائق لا تزال قيد العمل. يرجى المساهمة في المراجعة الأولية في خطأ NSS الخاص بـ Mozilla 836477[1]

الوصف

تتيح أداة PKCS #12، pk12util، مشاركة الشهادات بين أي خادم يدعم PKCS #12. يمكن للأداة استيراد الشهادات والمفاتيح من ملفات PKCS #12 إلى قواعد بيانات الأمان، وتصدير الشهادات، وإدراج الشهادات والمفاتيح.

الخيارات والحجج

الخيارات

-i p12file

استيراد المفاتيح والشهادات من ملف PKCS #12 إلى قاعدة بيانات أمان.

-l p12file

قائمة المفاتيح والشهادات في ملف PKCS #12.

-o p12file

تصدير المفاتيح والشهادات من قاعدة بيانات الأمان إلى ملف PKCS #12.

الحجج

-c keyCipher

تحديد خوارزمية تشفير المفتاح.

-C certCipher

تحديد خوارزمية تشفير الشهادة.

-d directory

تحديد دليل قاعدة البيانات الذي سيتم الاستيراد إليه أو التصدير منه للشهادات والمفاتيح.

تدعم pk12util نوعين من قواعد البيانات: قواعد بيانات الأمان القديمة (cert8.db, key3.db, و secmod.db) وقواعد بيانات SQLite الجديدة (cert9.db, key4.db, و pkcs11.txt). إذا لم يتم استخدام البادئة dbm:، فستفترض الأداة أن قواعد البيانات المعطاة بتنسيق SQLite.

-h tokenname

تحديد اسم الرمز المميز للاستيراد إليه أو التصدير منه.

-k slotPasswordFile

تحديد الملف النصي الذي يحتوي على كلمة مرور الفتحة.

-K slotPassword

تحديد كلمة مرور الفتحة.

-m | --key-len keyLength

تحديد الطول المطلوب للمفتاح المتماثل الذي سيتم استخدامه لتشفير المفتاح الخاص.

-M hashAlg

تحديد خوارزمية التجزئة المستخدمة في pkcs #12 mac. تحدد هذه الخوارزمية أيضًا HMAC المستخدم في prf عند استخدام pkcs #5 v2.

--cert-key-len certKeyLength

تحديد الطول المطلوب للمفتاح المتماثل الذي سيتم استخدامه لتشفير الشهادات والبيانات الوصفية الأخرى.

-n certname

تحديد الاسم المستعار للشهادة والمفتاح الخاص المراد تصديره.

يمكن أن يكون الاسم المستعار أيضًا عنوان URI لـ PKCS #11. على سبيل المثال، إذا كان لديك شهادة باسم "my-server-cert" على مخزن الشهادات الداخلي، يمكن تحديدها بشكل لا لبس فيه على النحو "pkcs11:token=NSS%20Certificate%20DB;object=my-server-cert". للحصول على تفاصيل حول التنسيق، راجع RFC 7512.

-P prefix

تحديد البادئة المستخدمة في قواعد بيانات الشهادات والمفاتيح. يتم توفير هذا الخيار كحالة خاصة. لا يُنصح بتغيير أسماء قواعد بيانات الشهادات والمفاتيح.

-r

يفرغ كل البيانات في شكلها الخام (ثنائي). يجب حفظها كملف DER. الافتراضي هو إرجاع المعلومات بتنسيق ASCII جميل الطباعة، والذي يعرض معلومات حول الشهادات والمفاتيح العامة في ملف p12.

-v

تمكين تسجيل التصحيح عند الاستيراد.

-w p12filePasswordFile

تحديد الملف النصي الذي يحتوي على كلمة مرور ملف PKCS #12.

-W p12filePassword

تحديد كلمة مرور ملف PKCS #12.

أمثلة

استيراد المفاتيح والشهادات

الاستخدام الأساسي لـ pk12util لاستيراد شهادة أو مفتاح هو ملف إدخال PKCS #12 (-i) وطريقة لتحديد قاعدة بيانات الأمان التي يتم الوصول إليها (إما -d للدليل أو -h للرمز المميز).

pk12util -i p12File [-h tokenname] [-v] [-d directory] [-P dbprefix] [-k slotPasswordFile|-K slotPassword] [-w p12filePasswordFile|-W p12filePassword]

على سبيل المثال:

# pk12util -i /tmp/cert-files/users.p12 -d /home/my/sharednssdb

تصدير المفاتيح والشهادات

يتطلب استخدام أمر pk12util لتصدير الشهادات والمفاتيح كلاً من اسم الشهادة لاستخراجها من قاعدة البيانات (-n) وملف الإخراج بتنسيق PKCS #12 للكتابة إليه. هناك معلمات اختيارية يمكن استخدامها لتشفير الملف لحماية مواد الشهادة.

pk12util -o p12File -n certname [-c keyCipher] [-C certCipher] [-m|--key_len keyLen] [-n|--cert_key_len certKeyLen] [-d directory] [-P dbprefix] [-k slotPasswordFile|-K slotPassword] [-w p12filePasswordFile|-W p12filePassword]

# pk12util -o certs.p12 -n Server-Cert -d /home/my/sharednssdb

قائمة المفاتيح والشهادات

المعلومات الموجودة في ملف .p12 ليست قابلة للقراءة بواسطة الإنسان. يمكن طباعة (إدراج) الشهادات والمفاتيح الموجودة في الملف بتنسيق جميل الطباعة قابل للقراءة بواسطة الإنسان يعرض المعلومات لكل شهادة وأي مفاتيح عامة في ملف .p12.

pk12util -l p12File [-h tokenname] [-r] [-d directory] [-P dbprefix] [-k slotPasswordFile|-K slotPassword] [-w p12filePasswordFile|-W p12filePassword]

اسم

pk12util - أداة إدارة شهادات PKCS #12

ملخص

pk12util [options]

الحالة

يمكن استدعاء هذه الأداة باستخدام pk12util.

الوصف

تسمح أداة pk12util بإنشاء واستيراد وتصدير بيانات PKCS #12. PKCS #12 هو تنسيق ملف موحد لتخزين مفاتيح التشفير الخاصة والشهادات. يستخدم بشكل شائع لنقل شهادة SSL/TLS والمفاتيح الخاصة المقترنة بها.

يحتوي ملف PKCS #12 (والذي يُعرف أيضًا باسم PFX) على مفتاح خاص، وشهادة عامة، وشهادات CA الموثوقة. يمكن استخدامه لتمكين HTTPS على خادم ويب، أو لتسجيل الدخول إلى خادم، أو لتوقيع رسائل البريد الإلكتروني.

تتطلب معظم العمليات التي تقوم بها pk12util توفير كلمة مرور لتشفير/فك تشفير المفاتيح الخاصة. إذا لم يتم توفير كلمة مرور، فستطلب الأداة منك إدخالها.

يمكن لـ pk12util التعامل مع كل من ملفات PKCS #12 المشفرة وغير المشفرة.

الخيارات والحجج

يدعم pk12util العديد من الخيارات للتحكم في سلوكه. فيما يلي بعض الخيارات الشائعة:

-i pkcs12file
استيراد ملف PKCS #12. يحدد pkcs12file مسار الملف المراد استيراده.
-o pkcs12file
تصدير بيانات PKCS #12. يحدد pkcs12file مسار الملف المراد إنشاؤه.
-l
عرض محتويات ملف PKCS #12. يقوم هذا الخيار بطباعة قائمة بالشهادات والمفاتيح الموجودة في الملف.
-e
تصدير الشهادات إلى ملفات منفصلة. بدلاً من إنشاء ملف PKCS #12 واحد، يقوم هذا الخيار بتصدير كل شهادة إلى ملف DER ثنائي منفصل.
-n nickname
استخدم اسم مستعار محدد. يحدد nickname اسمًا مستعارًا لشهادة أو مفتاح لتحديده.
-d dirpath
استخدم قاعدة بيانات NSS في المسار المحدد. يحدد dirpath المسار إلى دليل يحتوي على ملفات قاعدة بيانات NSS (مثل cert9.db و key4.db).
-P password
استخدم كلمة المرور المحددة. يحدد password كلمة المرور المستخدمة لتشفير/فك تشفير ملف PKCS #12. إذا تم حذف هذا الخيار، فسيتم سؤالك عن كلمة المرور.
-c cipher
تحديد خوارزمية التشفير. يحدد cipher خوارزمية التشفير المستخدمة لتشفير المفاتيح الخاصة والشهادات. إذا لم يتم تحديد ذلك، فسيتم استخدام الافتراضي.
-a
تصدير في تنسيق PEM. يقوم بتصدير البيانات بتنسيق PEM بدلاً من DER الثنائي.
-r
تصدير الشهادات إلى ملفات DER ثنائية منفصلة. هذا مشابه للخيار -e ولكنه يركز على ملفات DER.

رموز الإرجاع

يعيد pk12util قيمة 0 عند النجاح، وقيمة غير صفرية عند الفشل.

تشفير كلمة المرور

يوفر PKCS #12 حماية للمفاتيح الخاصة بالإضافة إلى الشهادات والبيانات الوصفية المرتبطة بالمفاتيح. يستخدم التشفير المستند إلى كلمة المرور لحماية المفاتيح الخاصة عند التصدير إلى ملف PKCS #12، وبشكل اختياري، الشهادات المرتبطة. إذا لم يتم تحديد أي خوارزمية، فإن الأداة تستخدم افتراضيًا PKCS #12 SHA-1 و 3-key triple DES لتشفير المفتاح الخاص. عند عدم العمل في وضع FIPS، يتم استخدام PKCS #12 SHA-1 و 40-bit RC4 لتشفير الشهادة. عند العمل في وضع FIPS، لا يوجد تشفير للشهادة. إذا لم يكن تشفير الشهادة مرغوبًا فيه، فحدد "NONE" كوسيط للخيار -C.

يتم حماية المفتاح الخاص دائمًا بتشفير قوي افتراضيًا.

تدعم عدة أنواع من خوارزميات التشفير.

تشفير PKCS #5 المستند إلى كلمة المرور

•PBES2 مع AES-CBC-Pad كآلية تشفير أساسية ("AES-128-CBC"، "AES-192-CBC"، و "AES-256-CBC")

تشفير PKCS #12 المستند إلى كلمة المرور

•SHA-1 و 128-bit RC4 ("PKCS #12 V2 PBE With SHA-1 And 128 Bit RC4" أو "RC4")
•SHA-1 و 40-bit RC4 ("PKCS #12 V2 PBE With SHA-1 And 40 Bit RC4") (يستخدم افتراضيًا لتشفير الشهادة في الوضع غير FIPS)
•SHA-1 و 3-key triple-DES ("PKCS #12 V2 PBE With SHA-1 And 3KEY Triple DES-CBC" أو "DES-EDE3-CBC")
•SHA-1 و 128-bit RC2 ("PKCS #12 V2 PBE With SHA-1 And 128 Bit RC2 CBC" أو "RC2-CBC")
•SHA-1 و 40-bit RC2 ("PKCS #12 V2 PBE With SHA-1 And 40 Bit RC2 CBC")

مع PKCS #12، قد يكون مزود التشفير هو وحدة التشفير اللينة أو وحدة الأجهزة الخارجية. إذا لم تدعم وحدة التشفير الخوارزمية المطلوبة، فسيتم اختيار أفضل بديل (عادةً الافتراضي). إذا لم يتم العثور على بديل مناسب للخوارزمية المطلوبة، فإن الأداة تعيد الخطأ no security module can perform the requested operation.

أنواع قواعد بيانات NSS

استخدمت NSS في الأصل قواعد بيانات BerkeleyDB لتخزين معلومات الأمان. الإصدارات الأخيرة من هذه قواعد البيانات القديمة هي:

•cert8.db للشهادات
•key3.db للمفاتيح
•secmod.db لمعلومات وحدة PKCS #11

ومع ذلك، فإن BerkeleyDB لديها قيود على الأداء، مما يمنع استخدامها بسهولة بواسطة تطبيقات متعددة في وقت واحد. تمتلك NSS بعض المرونة التي تسمح للتطبيقات باستخدام محرك قاعدة بياناتها المستقل الخاص بها مع الاحتفاظ بقاعدة بيانات مشتركة وتجاوز مشكلات الوصول. ومع ذلك، تتطلب NSS مزيدًا من المرونة لتوفير قاعدة بيانات أمان مشتركة حقًا.

في عام 2009، قدمت NSS مجموعة جديدة من قواعد البيانات وهي قواعد بيانات SQLite بدلاً من BerkleyDB. توفر قواعد البيانات الجديدة هذه مزيدًا من إمكانية الوصول والأداء:

•cert9.db للشهادات
•key4.db للمفاتيح
•pkcs11.txt، وهو قائمة بجميع وحدات PKCS #11 الموجودة في دليل فرعي جديد في دليل قواعد بيانات الأمان

نظرًا لأن قواعد بيانات SQLite مصممة لتكون مشتركة، فهذه هي نوع قاعدة البيانات المشتركة. يفضل نوع قاعدة البيانات المشتركة؛ يتم تضمين التنسيق القديم للتوافق مع الإصدارات السابقة.

افتراضيًا، تفترض الأدوات (certutil، pk12util، modutil) أن قواعد بيانات الأمان المقدمة تستخدم نوع SQLite. يجب تحديد قواعد البيانات القديمة يدويًا باستخدام البادئة dbm: مع دليل الأمان المحدد. على سبيل المثال:

# pk12util -i /tmp/cert-files/users.p12 -d dbm:/home/my/sharednssdb

لتعيين نوع قاعدة البيانات القديمة كنوع افتراضي للأدوات، قم بتعيين متغير البيئة NSS_DEFAULT_DB_TYPE إلى dbm:

export NSS_DEFAULT_DB_TYPE="dbm"

يمكن إضافة هذا السطر إلى ملف ~/.bashrc لجعله تغييرًا دائمًا.

لمسودة هندسية حول التغييرات في قواعد بيانات NSS المشتركة، راجع wiki مشروع NSS:

•https://wiki.mozilla.org/NSS_Shared_DB

ملاحظات التوافق

تغير سلوك التصدير الخاص بـ pk12util بمرور الوقت، بينما لا يزال استيراد الملفات التي تم تصديرها باستخدام إصدارات أقدم من NSS مدعومًا.

حتى الإصدار 3.30، استخدم pk12util ترميز UTF-16 لآليات التشفير المستندة إلى كلمة مرور PKCS #5، بينما التوصية هي ترميز كلمات المرور بـ UTF-8 إذا تم تعريف آلية التشفير المستخدمة خارج معيار PKCS #12.

حتى الإصدار 3.31، حتى عند تقديم "AES-128-CBC" أو "AES-192-CBC" من سطر الأوامر، استخدم pk12util دائمًا AES 256 بت كآلية تشفير أساسية.

لأسباب تاريخية، يقبل pk12util آليات تشفير مستندة إلى كلمة مرور غير مدرجة في هذا المستند. ومع ذلك، فإن هذه الآليات غير مدعومة رسميًا وقد تواجه مشكلات في التوافق مع الأدوات الأخرى.

NAME

pk12util - PKCS#12 utility program

DESCRIPTION

pk12util is a command-line utility to manage PKCS#12 files. PKCS#12 is a common file format for storing cryptographic objects, such as private keys, certificates, and certificate chains.

OPTIONS

The following options are supported:

-c, --create
Create a new PKCS#12 file.
-e, --export
Export objects from a PKCS#12 file.
-i, --import
Import objects into a PKCS#12 file.
-o, --output filename
Specify the output filename.
-n, --nokeys
Do not export private keys.
-d, --dir dirpath
Directory containing the NSS security database.
-h, --help
Display help message and exit.
-v, --version
Display version information and exit.

EXAMPLES

Create a PKCS#12 file named mykeystore.p12 containing a private key and certificate:

pk12util -c -o mykeystore.p12

Export certificates from mykeystore.p12 without private keys:

pk12util -e -n -o mycerts.p12 -i mykeystore.p12
