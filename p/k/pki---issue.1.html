الاسم

pki --issue - إصدار شهادة باستخدام شهادة ومفتاح CA

ملخص

وصف

يُستخدم هذا الأمر الفرعي لـ pki(1) لإصدار شهادة باستخدام شهادة CA ومفتاح خاص.

خيارات

-h, --help
طباعة معلومات الاستخدام مع ملخص للخيارات المتاحة.
-v, --debug مستوى
تعيين مستوى التصحيح، الافتراضي: 1.
-+, --options ملف
قراءة خيارات سطر الأوامر من ملف.
-i, --in ملف
ملف المفتاح العام أو طلب شهادة PKCS#10 المراد إصداره. إذا لم يتم تحديده، يتم قراءة المفتاح/الطلب من STDIN.
-t, --type نوع
نوع المدخلات. أحد الخيارات التالية: pub (مفتاح عام)، priv (مفتاح خاص)، rsa (مفتاح خاص RSA)، ecdsa (مفتاح خاص ECDSA)، ed25519 (مفتاح خاص Ed25519)، ed448 (مفتاح خاص Ed448) أو pkcs10 (طلب شهادة PKCS#10)، الافتراضي: pub.
-k, --cakey ملف
ملف المفتاح الخاص لـ CA. مطلوب إما هذا أو --cakeyid.
-x, --cakeyid سداسي عشري
معرّف كائن المفتاح الخاص لبطاقة ذكية أو TPM بتنسيق سداسي عشري مع بادئة 0x اختيارية. مطلوب إما هذا أو --cakey.
-c, --cacert ملف
ملف شهادة CA. مطلوب.
-d, --dn اسم-الموضوع
اسم موضوع الشهادة المميز (DN) للشهادة المصدرة.
-a, --san اسم-بديل-للموضوع
ملحق SubjectAltName لتضمينه في الشهادة. يمكن استخدامه عدة مرات.
-l, --lifetime أيام
عدد الأيام التي تكون فيها الشهادة صالحة، الافتراضي: 1095. يتم تجاهله إذا تم إعطاء كل من وقت البدء والانتهاء المطلق.
-F, --not-before تاريخ ووقت
الوقت المطلق الذي تبدأ فيه صلاحية الشهادة. يتم تحديد تنسيق التاريخ والوقت بواسطة الخيار --dateform.
-T, --not-after تاريخ ووقت
الوقت المطلق الذي تنتهي فيه صلاحية الشهادة. يتم تحديد تنسيق التاريخ والوقت بواسطة الخيار --dateform.
-D, --dateform تنسيق
تنسيق strptime(3) للخيارات --not-before و --not-after، الافتراضي: %d.%m.%y %T
-s, --serial سداسي عشري
الرقم التسلسلي بالسداسي عشري. يتم تخصيصه عشوائيًا افتراضيًا.
-e, --flag علم
إضافة علامة extendedKeyUsage. أحد الخيارات التالية: serverAuth، clientAuth، crlSign، ocspSigning أو msSmartcardLogon. يمكن استخدامه عدة مرات. بدون معدلات، يتجاوز هذا العلامات من طلبات شهادة PKCS#10. البادئة بعلامة + تضيفها إلى مجموعة العلامات المقروءة من الطلب، والبادئة بعلامة - تزيلها من تلك المجموعة.
-g, --digest هضم
الهضم المستخدم لإنشاء التوقيع. أحد الخيارات التالية: md5، sha1، sha224، sha256، sha384، أو sha512. يتم تحديد الافتراضي بناءً على نوع وحجم مفتاح التوقيع.
-R, --rsa-padding حشو
الحشو المستخدم لتوقيعات RSA. إما pkcs1 أو pss، الافتراضي هو pkcs1.
-f, --outform تشفير
تشفير ملف الشهادة المنشأ. إما der (ASN.1 DER) أو pem (Base64 PEM)، الافتراضي هو der.
-b, --ca
تضمين ملحق BasicConstraint الخاص بـ CA في الشهادة.
-u, --crl uri
عنوان URL لنقطة توزيع CRL لتضمينه في الشهادة. يمكن استخدامه عدة مرات.
-I, --crlissuer مصدر
مصدر CRL اختياري لـ CRL في نقطة التوزيع السابقة.
-o, --ocsp uri
عنوان URL لـ AuthorityInfoAccess الخاص بـ OCSP لتضمينه في الشهادة. يمكن استخدامه عدة مرات.
-p, --pathlen طول
تعيين قيد طول المسار.
-B, --addrblock كتلة
كتلة عنوان RFC 3779 لتضمينها في الشهادة. كتلة إما شبكة CIDR (مثل 10.0.0.0/8) أو نطاق عناوين عشوائي (192.168.1.7-192.168.1.13). يمكن تكرارها لتضمين كتل متعددة. يرجى ملاحظة أن الكتل المقدمة يتم تضمينها في الشهادة كما هي، لذا للامتثال للمعايير، يجب تقديم كتل متعددة بالترتيب الصحيح ويجب دمج الكتل المجاورة. ارجع إلى RFC 3779 للحصول على التفاصيل.
-n, --nc-permitted اسم
إضافة ملحق NameConstraint مسموح به إلى الشهادة. بالنسبة لقيود DNS أو البريد الإلكتروني، لا يمكن دائمًا اكتشاف نوع الهوية بالاسم المقدم. استخدم البادئة dns: أو email: لفرض نوع القيد.
-N, --nc-excluded اسم
إضافة ملحق NameConstraint مستبعد إلى الشهادة. بالنسبة لقيود DNS أو البريد الإلكتروني، لا يمكن دائمًا اكتشاف نوع الهوية بالاسم المقدم. استخدم البادئة dns: أو email: لفرض نوع القيد.
-X, --critical oid
إضافة ملحق حرج بالمعرف الكائن (OID) المحدد.
-M, --policy-mapping issuer-oid:subject-oid
إضافة تعيين سياسة (policyMapping) من معرف الكائن الخاص بالمصدر إلى معرف الكائن الخاص بالهدف.
-E, --policy-explicit طول
إضافة قيد requireExplicitPolicy.
-H, --policy-inhibit طول
إضافة inhibitPolicyMap

pki(1) — issue

NAME

pki-issue

issue a certificate

SYNOPSIS

‐‐issue [options] [in] [out]

DESCRIPTION

The pki-issue command is used to issue certificates. Either an existing PKCS#10 certificate request or a set of subject properties can be provided.

If no input file is specified, the certificate request is read from standard input. If no output file is specified, the issued certificate is written to standard output.

Options

The following options are available:

-s, --serial hex
Serial number of the certificate to issue. Required.
-c, --cacert file
CA certificate to sign the new certificate with. Required.
-k, --cakey file
CA private key to sign the new certificate with. Required.
-p, --p12 file
PKCS#12 file containing CA certificate and private key.
-P, --p12key password
Password of the PKCS#12 file.
-d, --digest algo
Digest algorithm to use for signing. Default is sha256.
-D, --not-before time
Validity period 'not before'. Defaults to current time.
-T, --not-after time
Validity period 'not after'. Defaults to 7 days from now.
-l, --lifetime days
Validity period in days. Use with -D and -T to specify start and end dates.
-t, --type type
Certificate type. Default is pkcs10.
-f, --flag flag
Add certificate flags. Supported flags are: ca, serverAuth, clientAuth, codeSign, emailSign, timeStamping, ocspSigning, crlSign.
-e, --eku oid
Add extended key usage OID.
-r, --rev-group oid
Add issuerRevocationList constraint.
-m, --mda oid
Add authorityKeyIdentifier constraint.
-g, --gateway-id id
Add gatewayId constraint.
-i, -- inhibit-any-policy
Add inhibitAnyPolicy constraint.
-A, --policy-any len
Add inhibitAnyPolicy constraint.

Certificate Policy

Multiple certificatePolicy extensions can be added. Each with the following information:

-P, --cert-policy oid
OID to include in certificatePolicy extension. Required.
-C, --cps-uri uri
Certification Practice statement URI for certificatePolicy.
-U, --user-notice text
User notice for certificatePolicy.

EXAMPLES

To save repetitive typing, command line options can be stored in files. Lets assume pki.opt contains the following contents:

  --cacert ca_cert.der --cakey ca_key.der --digest sha256
  --flag serverAuth --lifetime 1460 --type pkcs10

Then the following command can be used to issue a certificate based on a given PKCS#10 certificate request and the options above:

  pki --issue --options pki.opt --in req.der > cert.der
