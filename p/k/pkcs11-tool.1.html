pkcs11-tool(1)

الحزمة: opensc

التراخيص: LGPL

PKCS11-TOOL(1) أدوات OpenSC PKCS11-TOOL(1)

الاسم

pkcs11-tool - أداة لإدارة واستخدام رموز الأمان PKCS #11

الملخص

pkcs11-tool [خيارات]

الوصف

تُستخدم الأداة pkcs11-tool لإدارة كائنات البيانات على البطاقات الذكية ورموز الأمان PKCS #11 المماثلة. يمكن للمستخدمين سرد وقراءة رموز PIN والمفاتيح والشهادات المخزنة على الرمز. يتم إجراء مصادقة PIN للمستخدم للعمليات التي تتطلب ذلك.

الخيارات

--attr-from اسم_الملف

استخراج المعلومات من اسم_الملف (ملف شهادة مشفر بتنسيق DER) وإنشاء السمات المقابلة عند كتابة كائن إلى الرمز. مثال: يتم استخدام اسم موضوع الشهادة لإنشاء السمة CKA_SUBJECT.

--change-pin, -c

تغيير رمز PIN للمستخدم على الرمز.

--unlock-pin

إلغاء قفل رمز PIN للمستخدم (بدون --login إلغاء القفل في جلسة مسجلة الدخول؛ وإلا، يجب أن يكون --login-type "محدد بالسياق").

--hash, -h

تجزئة بعض البيانات.

--hash-algorithm آلية

تحديد خوارزمية التجزئة المستخدمة مع توقيع RSA-PKCS-PSS أو فك تشفير RSA-OAEP. القيم المسموح بها هي "SHA-1" و "SHA256" و "SHA384" و "SHA512"، وقد تسمح بعض الرموز أيضًا بـ "SHA224". الافتراضي هو "SHA-1".

لاحظ أن الإدخال لـ RSA-PKCS-PSS يجب أن يكون بحجم مساوٍ لخوارزمية التجزئة المحددة. على سبيل المثال، لـ SHA256، يجب أن يكون إدخال التوقيع 32 بايت بالضبط (بالنسبة لآليات SHA256-RSA-PKCS-PSS لا يوجد مثل هذا القيد). بالنسبة لـ RSA-OAEP، يجب أن يكون حجم الإدخال النصي العادي mLen على الأكثر keyLen - 2 - 2 * hashLen. على سبيل المثال، لمفتاح RSA 3072 بت و SHA384، فإن أطول نص عادي لتشفيره باستخدام RSA-OAEP هو (مع جميع الأحجام بالبايت): 384 - 2 - 2 * 48 = 286، أي 286 بايت.

--id معرف, -d معرف

تحديد معرف الكائن الذي سيتم العمل عليه.

--init-pin

تهيئة رمز PIN للمستخدم. تختلف هذه الخيار عن --change-pin في أنها تقوم بتعيين رمز PIN للمستخدم للمرة الأولى. بمجرد تعيينه، يمكن تغيير رمز PIN للمستخدم باستخدام --change-pin.

--init-token

تهيئة الرمز: تعيين تسمية الرمز بالإضافة إلى رمز PIN الخاص بمسؤول الأمان (يجب تحديد التسمية باستخدام --label).

--input-file اسم_الملف, -i اسم_الملف

تحديد المسار إلى ملف للإدخال.

--keypairgen, -k

إنشاء زوج مفاتيح جديد (مفتاح عام ومفتاح خاص).

--keygen

إنشاء مفتاح جديد.

--key-type مواصفات

تحديد نوع و (ليس دائمًا إلزاميًا) نكهة (طول المفتاح المتماثل بالبايت، طول المفتاح غير المتماثل بالبت، معرف المنحنى البيضاوي، إلخ) للمفتاح المراد إنشاؤه، على سبيل المثال RSA:2048، EC:prime256v1، GOSTR3410-2012-256:B، DES:8، DES3:24، AES:16، AES: أو GENERIC:64. إذا كان نوع المفتاح محددًا بشكل غير كامل، يتم سرد القيم الممكنة.

--usage-sign

تحديد علامة استخدام المفتاح "sign" (تعيين SIGN في المفتاح الخاص، تعيين VERIFY في المفتاح العام).

--usage-decrypt

تحديد علامة استخدام المفتاح "decrypt".

بالنسبة لمفاتيح RSA، يقوم بتعيين DECRYPT في المفتاح الخاص و ENCRYPT في المفتاح العام. بالنسبة للمفاتيح السرية، يقوم بتعيين كل من DECRYPT و ENCRYPT.

--usage-derive

تحديد علامة استخدام المفتاح "derive" (EC فقط).

--usage-wrap

تحديد علامة استخدام المفتاح "wrap".

--label اسم, -a اسم

تحديد اسم الكائن المراد العمل عليه (أو تسمية الرمز عند استخدام --init-token).

--list-mechanisms, -M

عرض قائمة الآليات التي يدعمها الرمز.

--list-objects, -O

عرض قائمة بالكائنات.

يمكن استخدام الخيارات --keytype و --label و --id أو --application-id لتصفية الكائنات المدرجة.

--list-slots, -L

عرض قائمة بالفتحات المتاحة على الرمز.

--list-token-slots, -T

سرد الفتحات التي تحتوي على رموز.

--list-interfaces

سرد واجهات مكتبة PKCS #11 3.0.

--session-rw,

يفرض فتح جلسة PKCS#11 باستخدام CKF_RW_SESSION.

--login, -l

المصادقة على الرمز قبل إجراء عمليات أخرى. هذا الخيار غير ضروري إذا تم توفير رمز PIN في سطر الأوامر.

--login-type

تحديد نوع تسجيل الدخول ('so'، 'user'، 'context-specific'؛ افتراضي: 'user').

--mechanism آلية, -m آلية

استخدام الآلية المحددة لعمليات الرمز. راجع -M للحصول على قائمة بالآليات التي يدعمها الرمز الخاص بك. يمكن أيضًا تحديد الآلية بصيغة سداسية عشرية، على سبيل المثال، 0x80001234.

--mgf وظيفة

استخدام وظيفة توليد الرسائل (MGF) المحددة لتوقيعات RSA-PKCS-PSS أو فك تشفير RSA-OAEP. الوسيطات المدعومة هي MGF1-SHA1 إلى MGF1-SHA512 إذا كانت مدعومة بواسطة المشغل. الافتراضي يعتمد على اختيار التجزئة.

--module مود

تحديد وحدة (أو مكتبة) PKCS#11 لتحميلها.

--moz-cert اسم_الملف, -z اسم_الملف

اختبار إنشاء زوج مفاتيح يشبه Mozilla وطلب شهادة. تحديد اسم_الملف لملف الشهادة.

--output-file اسم_الملف, -o اسم_الملف

تحديد المسار إلى ملف للإخراج.

--pin pin, -p pin

استخدام pin المحدد لعمليات الرمز. إذا تم تعيينه إلى env:VARIABLE، يتم استخدام قيمة متغير البيئة VARIABLE. تحذير: كن حذرًا عند استخدام هذا الخيار لأن المستخدمين الآخرين قد يتمكنون من قراءة سطر الأوامر من النظام أو إذا تم تضمينه في نص برمجي. إذا تم تعيينه إلى env:VARIABLE، يتم استخدام قيمة متغير البيئة VARIABLE.

سيقوم هذا الخيار أيضًا بتعيين الخيار --login.

--puk puk

توفير رمز PIN الخاص بالمستخدم (PUK) في سطر الأوامر.

--new-pin pin

توفير رمز PIN جديد للمستخدم في سطر الأوامر.

--sensitive

تعيين السمة CKA_SENSITIVE (لا يمكن الكشف عن الكائن بصيغة نص عادي).

--extractable

تعيين السمة CKA_EXTRACTABLE (يمكن استخراج الكائن).

--undestroyable

تعيين السمة CKA_DESTROYABLE إلى false (لا يمكن تدمير الكائن).

--set-id معرف, -e معرف

تعيين CKA_ID للكائن.

--show-info, -I

عرض معلومات عامة عن الرمز.

--sign, -s

توقيع بعض البيانات.

--decrypt,

فك تشفير بعض البيانات.

--encrypt,

تشفير بعض البيانات.

--unwrap,

فك تغليف المفتاح.

--wrap,

تغليف المفتاح.

--derive,

اشتقاق مفتاح سري باستخدام مفتاح آخر وبعض البيانات.

--derive-pass-der,

اشتقاق مفتاح عام مشفر بصيغة DER لـ ECDHpass للتوافق مع بعض تطبيقات PKCS#11.

--salt-len بايت

تحديد عدد البايتات للملح التي يجب استخدامها في توقيعات RSA-PSS. يقبل قيمتين خاصتين: "-1" يعني أن طول الملح يساوي طول التجزئة، "-2" أو "-3" يعني استخدام أقصى طول مسموح به. لعملية التحقق، "-2" يعني أن طول الملح يتم استعادته تلقائيًا من التوقيع. الخيار "-2" لعملية التحقق مدعوم لمشغل OpenSC pkcs#11 فقط. الافتراضي هو طول التجزئة (-1).

--slot معرف

تحديد معرف الفتحة المراد استخدامها (يقبل تنسيق HEX مع بادئة 0x.. أو رقم عشري).

--slot-description وصف_الفتحة

يجب استخدام الفتحات التي لها وصف مطابقة.

--token-label تسمية

يجب استخدام الرموز التي لها تسمية مطابقة.

--verbose, -v

تفعيل الإخراج المفصل.

--verify, -V

التحقق من التوقيع.

--wrap-mech آلية

استخدام الآلية المحددة لتغليف/فك تغليف المفاتيح.

--wrap-key-type نوع_المفتاح

نوع المفتاح المراد استخدامه لتغليف/فك تغليف المفاتيح.

أمثلة

pkcs11-tool --list-slots

يسرد جميع الفتحات المتاحة.

pkcs11-tool --login --change-pin -p 1234 -f newpin.txt

يغير رمز PIN للمستخدم الحالي إلى الرمز الموجود في newpin.txt.

pkcs11-tool --login --init-pin -l mytoken -p 12345678

يهيئ رمز PIN للمستخدم الجديد.

pkcs11-tool --login --keypairgen --key-type rsa:2048 --label mykey

ينشئ زوج مفاتيح RSA بحجم 2048 بت على الرمز.

pkcs11-tool --login --sign --input-file message.txt --output-file signature.bin

يوقع ملف message.txt باستخدام المفتاح الخاص الافتراضي.

pkcs11-tool --login --verify --signature-file signature.bin --input-file message.txt

يتحقق من توقيع ملف message.txt.

pkcs11-tool --login --encrypt --input-file plaintext.txt --output-file ciphertext.bin

يشفر ملف plaintext.txt باستخدام المفتاح العام الافتراضي.

pkcs11-tool --login --decrypt --input-file ciphertext.bin --output-file decrypted.txt

يفك تشفير ملف ciphertext.bin باستخدام المفتاح الخاص الافتراضي.

pkcs11-tool --login --wrap --object-id 1 --wrap-key-type aes-128 --output-file wrappedkey.bin

يلف مفتاحًا (بمعرف 1) باستخدام مفتاح AES 128 بت.

pkcs11-tool --login --unwrap --input-file wrappedkey.bin --output-file unwrappedkey.bin

يفك تغليف مفتاح باستخدام المفتاح الخاص الافتراضي.

OPTIONS

--library library, -l library

Specify the PKCS#11 library to use.

--module library

Specify the PKCS#11 library to use.

--provider provider

Specify the PKCS#11 library to use.

--token-label label

Specify the label of token. Will be used the first slot, that has the inserted token with this label.

--token-manufacturer manufacturer

Specify the manufacturer ID of token. Will be used the first slot, that has the inserted token with this manufacturer ID.

--token-model model

Specify the model name of token. Will be used the first slot, that has the inserted token with this model name.

--token-serial serial

Specify the serial number of token. Will be used the first slot, that has the inserted token with this serial number.

--login

Login to the token.

--login-type type

Specify the login type. Valid types are: normal, so, user. Default is normal.

--pin pin

Use the given pin to log in to the token. If set to env:VARIABLE, the value of the environment variable VARIABLE is used. The PIN is not echoed to the terminal. For security reasons, it is recommended to use the env:VARIABLE method rather than typing the PIN directly on the command line.

--password-fd fd

Read the password from the given file descriptor.

--password-file filename

Read the password from the given file.

--change-pin

Change the PIN of the token. You will be prompted for the old PIN and the new PIN.

--init-pin

Initialize the PIN of the token. You will be prompted for the new PIN. This is typically used for the first-time initialization of a token.

--generate-key keytype

Generate a new key pair of the specified type. Valid keytypes are: rsa1024, rsa2048, rsa4096, dsa1024, dsa2048, dsa3072, dsa4096, ec, ec256, ec384, ec521.

--key-type keytype

Specify the type of key to generate. See --generate-key for a list of valid key types.

--key-curve curve

Specify the elliptic curve to use for EC key generation. Valid curves are: nistp256, nistp384, nistp521, secp256k1.

--key-exponent exponent

Specify the public exponent for RSA key generation. Only 3 or 65537 are generally useful.

--key-bits bits

Specify the number of bits for the key.

--key-mechanism mechanism

Specify the key generation mechanism.

--keypairgen

Generate a new key pair. The key type is specified with --key-type.

--sign

Sign data using a private key. The data to sign is read from stdin or from the file specified with --input-file.

--encrypt

Encrypt data using a public key or a symmetric key. The data to encrypt is read from stdin or from the file specified with --input-file.

--decrypt

Decrypt data using a private key or a symmetric key. The data to decrypt is read from stdin or from the file specified with --input-file.

--wrap

Wrap (encrypt) a key using a public key or a symmetric key. The key to wrap is specified with --key-type, --key-bits, --key-curve, or by reading a key from a file specified with --input-file.

--unwrap

Unwrap (decrypt) a key using a private key or a symmetric key. The unwrapped key is stored on the token.

--id id

Specify the ID of the object to operate on.

--label label

Specify the label of the object to operate on.

--mechanism mechanism

Specify the PKCS#11 mechanism to use.

--input-file filename, -i filename

Specify the input file.

--output-file filename, -o filename

Specify the output file.

--list-objects, -l

List objects on the token.

--attribute attribute[=value]

Get or set an object attribute.

--attributes attributes

Get or set multiple object attributes.

--user-type type

Specify the user type. Valid types are: normal, so, user. Default is normal.

--slot slot

Specify the slot to use.

--slot-description description

Specify the description of the slot to use.

--slot-index index

Specify the index of the slot to use.

--object-index index

Specify the index of the object to use.

--use-locking

Tell pkcs11 module it should use OS thread locking.

--test-threads options

Test a pkcs11 module's thread implication. (See source code).

--token-label label

Specify the label of token. Will be used the first slot, that has the inserted token with this label.

--so-pin pin

Use the given pin as the Security Officer PIN for some token operations (token initialization, user PIN initialization, etc). If set to env:VARIABLE, the value of the environment variable VARIABLE is used. The same warning as --pin also applies here.

--test, -t

Perform some tests on the token. This option is most useful when used with either --login or --pin.

--test-hotplug

Test hotplug capabilities (C_GetSlotList + C_WaitForSlotEvent).

--private

Set the CKA_PRIVATE attribute (object is only viewable after a login).

--always-auth

Set the CKA_ALWAYS_AUTHENTICATE attribute to a private key object. If set, the user has to supply the PIN for each use (sign or decrypt) with the key.

--allowed-mechanisms mechanisms

Sets the CKA_ALLOWED_MECHANISMS attribute to a key objects when importing an object or generating a keys. The argument accepts comma-separated list of algorithmsm, that can be used with the given key.

--test-ec

Test EC (best used with the --login or --pin option).

--test-fork

Test forking and calling C_Initialize() in the child.

--type type, -y type

Specify the type of object to operate on. Valid value are cert, privkey, pubkey, secrkey and data.

--verbose, -v

Cause pkcs11-tool to be more verbose.

NB! This does not affect OpenSC debugging level! To set OpenSC PKCS#11 module into debug mode, set the OPENSC_DEBUG environment variable to a non-zero number.

--verify,

Verify signature of some data.

--read-object, -r

Get object's CKA_VALUE attribute (use with --type).

--delete-object, -b

Delete an object.

--application-label label

Specify the application label of the data object (use with --type data).

--application-id id

Specify the application ID of the data object (use with --type data).

--issuer data

Specify the issuer in hexadecimal format (use with --type cert).

--subject data

Specify the subject in hexadecimal format (use with --type cert/privkey/pubkey).

--signature-file filename

The path to the signature file for signature verification

--signature-format format

Format for ECDSA signature: 'rs' (default), 'sequence', 'openssl'.

--write-object filename, -w filename

Write a key or certificate object to the token. filename points to the DER-encoded certificate or key file.

--generate-random num

Get num bytes of random data.

--allow-sw

Allow using software mechanisms that do not have the CKF_HW flag set. May be required when using software tokens and emulators.

--iv data

Initialization vector for symmetric ciphers. The data is hexadecimal number, i.e. "000013aa7bffa0".

--mac-general-param num

Sets the length of the MAC for the general-length MACing mechanisms to num bytes.

--aad data

Additional authenticated data for AEAD ciphers. The data is an hexadecimal number.

--tag-bits-len num

Sets the length of the tag for AEAD ciphers to num bits.

--salt-file filename

Specify the file containing the salt for HKDF (optional)

--info-file filename

Specify the file containing the info for HKDF (optional)

EXAMPLES

Perform a basic functionality test of the card:

pkcs11-tool --test --login

List all certificates on the smart card:

pkcs11-tool --list-objects --type cert

Read the certificate with ID CERT_ID in DER format from smart card and convert it to PEM via OpenSSL:

pkcs11-tool --read-object --id $CERT_ID --type cert \
					--output-file cert.der
openssl x509 -inform DER -in cert.der -outform PEM > cert.pem

Write a certificate to token:

pkcs11-tool --login --write-object certificate.der --type cert

Generate new RSA Key pair:

pkcs11-tool --login --keypairgen --key-type RSA:2048

Generate new extractable RSA Key pair:

pkcs11-tool --login --keypairgen --key-type RSA:2048 --extractable

Generate an elliptic curve key pair with OpenSSL and import it to the card as $ID:

openssl genpkey -out EC_private.der -outform DER \
	-algorithm EC -pkeyopt ec_paramgen_curve:P-521
pkcs11-tool --write-object EC_private.der --id "$ID" \
	--type privkey --label "EC private key" -p "$PIN"
openssl pkey -in EC_private.der -out EC_public.der \
	-pubout -inform DER -outform DER
pkcs11-tool --write-object EC_public.der --id "$ID" \
	--type pubkey  --label "EC public key" -p $PIN

List private keys:

pkcs11-tool --login --list-objects --type privkey

Sign some data stored in file data using the private key with ID ID and using the RSA-PKCS mechanism:

pkcs11-tool --sign --id $ID --mechanism RSA-PKCS \
	--input-file data --output-file data.sig

The same is also possible by piping the data from stdin rather than specifying a input file:

dd if=data bs=128 count=1 \
	| pkcs11-tool --sign --id $ID --mechanism RSA-PKCS \
	> data.sig

Verify the signed data:

pkcs11-tool --id ID --verify -m RSA-PKCS \
	--input-file data --signature-file data.sig

To encrypt file using the AES key with ID 85 and using mechanism AES-CBC with padding:

pkcs11-tool --login --encrypt --id 85 -m AES-CBC-PAD \
	--iv "00000000000000000000000000000000" \
	-i file.txt -o encrypted_file.data

Decipher the encrypted file:

pkcs11-tool --login --decrypt --id 85 -m AES-CBC-PAD \
	--iv "00000000000000000000000000000000" \
	--i encrypted_file.data -o decrypted.txt

Use the key with ID 75 using mechanism AES-CBC-PAD, with initialization vector "00000000000000000000000000000000" to wrap the key with ID 76 into output file exported_aes.key

pkcs11-tool --login --wrap --id 75 --mechanism AES-CBC-PAD \
	--iv "00000000000000000000000000000000" \
	--application-id 76 \
	--output-file exported_aes.key

Use the key with ID 22 and mechanism RSA-PKCS to unwrap key from file aes_wrapped.key. After a successful unwrap operation, a new AES key is created on token. ID of this key is set to 90 and label of this key is set to unwrapped-key Note: for the MyEID card, the AES key size must be present in key specification i.e. AES:16

pkcs11-tool --login --unwrap --mechanism RSA-PKCS --id 22 \
	-i aes_wrapped.key --key-type AES: \
	--application-id 90 --applicatin-label unwrapped-key

Use the SO-PIN to initialize or re-set the PIN:

pkcs11-tool --login --login-type so --init-pin

اقرأ دليل التثبيت الكامل

إدارة الحزم

يستخدم Arch Linux مدير الحزم pacman.

  • تحديث النظام: pacman -Syu
  • تثبيت حزمة: pacman -S packagename
  • إزالة حزمة: pacman -R packagename

تعرف على المزيد حول pacman

خدمات النظام

تتم إدارة الخدمات باستخدام systemd.

  • بدء خدمة: systemctl start servicename
  • تمكين خدمة عند التمهيد: systemctl enable servicename
