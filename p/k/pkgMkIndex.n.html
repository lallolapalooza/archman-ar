pkgMkIndex(n)

الحزمة: tcl

التراخيص: TCL

NAME

pkgMkIndex ‑ create a Tcl package index file

SYNOPSIS

package require Tcl


proc pkgMkIndex { dir pattern ?args...? }

DESCRIPTION

The pkgMkIndex command creates a package index file (named pkgIndex.tcl) in the directory specified by dir. This index file allows the Tcl auto-loader to find and load packages when they are requested by a package require command.

The pattern argument is a glob-style pattern that matches the files to be indexed. The args can include options that control how the index is generated.

The pkgMkIndex command should be run from within a Tcl interpreter. It will generate a file named pkgIndex.tcl in the directory dir. This file will contain Tcl commands that load packages found in files matching the pattern. The commands generated are typically of the form:

if {![package names] contains pkgName} {
    set auto_path [linsert $auto_path 0 $dir]
    package ifneeded $pkgName $version [list source [file join $dir file.tcl]]
}

where pkgName is the name of the package found in file.tcl, and version is the version of the package.

OPTIONS

The following options can be provided after the pattern argument:

-load pkgPat
This option causes pkgMkIndex to load any packages matching pkgPat into the interpreter before processing the specified files. This is useful for handling dependencies, especially for binary packages. pkgPat is a glob pattern that matches package names.
-noImplicitLoad
By default, pkgMkIndex will attempt to load packages found in the specified files to determine their names and versions. This option disables this implicit loading. This is useful when dealing with packages that have complex initialization requirements or external dependencies that should not be loaded automatically.
-comment string
Adds a comment string to the generated index file. This can be used for documentation or identifying the purpose of the index.
-force
Overwrites an existing pkgIndex.tcl file without prompting.

PACKAGES AND THE AUTO-LOADER

The Tcl auto-loader mechanism relies on index files like pkgIndex.tcl to locate and load packages on demand. When a package require command is executed, Tcl searches the directories listed in the auto_path variable for a pkgIndex.tcl file. If found, it reads the file and loads the requested package if it hasn't been loaded already.

HOW IT WORKS

pkgMkIndex works by creating a temporary Tcl interpreter. It then loads each of the files matching the provided pattern into this interpreter. For each loaded file, it inspects the file to determine the package name and version it provides. This information is then used to generate the appropriate Tcl commands for the pkgIndex.tcl file.

DIRECT LOADING

In simple cases, where each script or file contains exactly one package, and packages are not split across multiple files, the process is straightforward. You can simply provide all the files to be indexed, possibly using glob patterns, in any order.

COMPLEX CASES

If each script or file contains one package, and packages are only contained in one file, then things are easy. You simply specify all files to be indexed in any order with some glob patterns.

In general, it is OK for scripts to have dependencies on other packages. If scripts contain package require commands, these are stubbed out in the interpreter used to process the scripts, so these do not cause problems. If scripts call into other packages in global code, these calls are handled by a stub unknown command. However, if scripts make variable references to other package's variables in global code, these will cause errors. That is also bad coding style.

If binary files have dependencies on other packages, things can become tricky because it is not possible to stub out C-level APIs such as Tcl_PkgRequire API when loading a binary file. For example, suppose the BLT package requires Tk, and expresses this with a call to Tcl_PkgRequire in its Blt_Init routine. To support this, you must run pkg_mkIndex in an interpreter that has Tk loaded. You can achieve this with the -load pkgPat option. If you specify this option, pkgMkIndex will load any packages listed by info loaded and that match pkgPat into the interpreter used to process files. In most cases this will satisfy the Tcl_PkgRequire calls made by binary files.

If you are indexing two binary files and one depends on the other, you should specify the one that has dependencies last. This way the one without dependencies will get loaded and indexed, and then the package it provides will be available when the second file is processed. You may also need to load the first package into the temporary interpreter used to create the index by using the -load flag; it will not hurt to specify package patterns that are not yet loaded.

If you have a package that is split across scripts and a binary file, then you should avoid the -load flag. The problem is that if you load a package before computing the index it masks any other files that provide part of the same package. If you must use -load, then you must specify the scripts first; otherwise the package loaded from the binary file may mask the package defined by the scripts.
