Proc__Simple(3pm)

الحزمة: perl-proc-simple

التراخيص: PerlArtistic, GPL

Simple(3) توثيق مساهمي Perl Simple(3)

الاسم

Proc::Simple -- تشغيل والتحكم بالعمليات في الخلفية

الملخص

use Proc::Simple;
$myproc = Proc::Simple->new();        # إنشاء كائن عملية جديد
$myproc->start("shell-command-line"); # تشغيل برنامج خارجي
$myproc->start("command",             # تشغيل برنامج خارجي
               "param", ...);         # مع معلمات

$myproc->start(sub { ... });          # تشغيل روتين فرعي Perl
$myproc->start(\&subroutine);         # تشغيل روتين فرعي Perl
$myproc->start(\&subroutine,          # تشغيل روتين فرعي Perl
               $param, ...);          # مع معلمات
$running = $myproc->poll();           # فحص حالة العملية
$exit_status = $myproc->wait();       # انتظار انتهاء العملية
$proc->kill_on_destroy(1);            # التصرف كـ kill عند التدمير
$proc->signal_on_destroy("KILL");     # تحديد الإشارة المراد إرسالها
                                      # عند التدمير
$myproc->kill();                      # إنهاء العملية (SIGTERM)
$myproc->kill("SIGUSR1");             # إرسال إشارة محددة
$myproc->exit_status();               # إرجاع حالة خروج العملية
Proc::Simple::debug($level);          # تفعيل التصحيح

الوصف

توفر الفئة Proc::Simple كائنات تحاكي العمليات الحقيقية من منظور المستخدم. يتم إنشاء كائن عملية جديد عن طريق

$myproc = Proc::Simple->new();

يمكن تشغيل كل من البرامج الخارجية وروتينات Perl الفرعية كعمليات في الخلفية والتحكم فيها.

يمكن تشغيل عملية انتظار لمدة 10 ثوانٍ، على سبيل المثال، كبرنامج خارجي، كما في

$myproc->start("/bin/sleep 10");    # أو
$myproc->start("/bin/sleep", "10");

أو كروتين فرعي Perl، كما في

sub mysleep { sleep(shift); }    # تعريف mysleep()
$myproc->start(\&mysleep, 10);   # تشغيله.

أو حتى هكذا

$myproc->start(sub { sleep(10); });

يعود الأسلوب start فورًا بعد تشغيل العملية المحددة في الخلفية، أي بشكل غير حاجز. يعيد 1 إذا تم تشغيل العملية بنجاح و 0 إذا فشل.

الأسلوب poll يتحقق مما إذا كانت العملية لا تزال قيد التشغيل

$running = $myproc->poll();

ويعيد 1 إذا كانت كذلك، و 0 إذا لم تكن. أخيرًا،

$myproc->kill();

ينهي العملية بإرسال إشارة SIGTERM إليها. كخيار، يمكن تحديد إشارة أخرى.

$myproc->kill("SIGUSR1");

يرسل إشارة SIGUSR1 إلى العملية قيد التشغيل. يعيد الأسلوب kill القيمة 1 إذا نجح في إرسال الإشارة، و 0 إذا لم ينجح.

تمت مناقشة الأساليب بمزيد من التفصيل في القسم التالي.

يتم توفير مزيل بحيث يمكن إرسال إشارة إلى العملية الفرعية تلقائيًا إذا تم تدمير كائن العملية أو إذا تم إنهاء العملية. افتراضيًا، يكون هذا الخيار معطلاً (راجع الأساليب kill_on_destroy و signal_on_destroy).

الأساليب

الأساليب التالية متاحة:

new (منشئ)
ينشئ كائنًا جديدًا من هذه الفئة عن طريق كتابة

$proc = new Proc::Simple;

أو

$proc = Proc::Simple->new();

لا يقبل حجج.

start
يبدأ عملية جديدة. يمكن استخدام الأسلوب start لبدء كل من البرامج الخارجية (مثل /bin/echo) وروتينات فرعية خاصة بالمستخدم (مثل foo()) في عملية جديدة.

$status = $proc->start("program-name");

لبدء برنامج خارجي، استدعِ

$status = $proc->start("program-name");

إذا كنت تريد تمرير معلمات متعددة إلى البرنامج الذي تم تشغيله، فهناك خياران: يمكنك تمريرها كحجة واحدة، كما في

$status = $proc->start("/bin/echo hello world");

أو كمعلمات متعددة، كما في

$status = $proc->start("/bin/echo", "hello", "world");

كما هو الحال في أسلوب system() الخاص بـ Perl، هناك فرق كبير بين الطريقتين: إذا قمت بتمرير حجة تحتوي على سطر أوامر مفصول بمسافات، فإن shell الخاص بك سيعالج أي أحرف خاصة (إذا قررت استخدام أي منها) قبل أن يتم تشغيل العملية فعليًا:

$status = $proc->start("/bin/ls -l /etc/initt*");

هذا المثال يوسع /etc/initt* إلى /etc/inittab قبل تنفيذ أمر /bin/ls. إذا، بدلاً من ذلك، قلت

$status = $proc->start("/bin/ls", "-l", "*");

سيتم الاحتفاظ بـ * دون توسيع، مما يعني أنك ستبحث عن ملف بالاسم الحرفي * (وهو أمر غير مرجح على نظامك، ما لم تقم بإنشاء ملفات بأسماء مربكة عن طريق الخطأ). لمزيد من المعلومات حول هذا، راجع perldoc -f exec.

إذا، بدلاً من ذلك، كنت ترغب في بدء روتين فرعي Perl في الخلفية، فما عليك سوى توفير مرجع إلى الروتين الفرعي كما في

$status = $proc->start(\&your_function);

أو توفير روتين فرعي مجهول:

$status = $proc->start( sub { sleep(1) } );

يمكنك أيضًا توفير معلمات إضافية لتمريرها إلى الروتين الفرعي:

$status = $proc->start(\&printme, "hello", "world");

يعود الأسلوب start فورًا بعد بدء العملية المحددة في الخلفية، أي في وضع غير حاجز. يعيد 1 إذا تم بدء العملية بنجاح و 0 إذا فشل.

poll
يتحقق الأسلوب poll مما إذا كانت العملية لا تزال قيد التشغيل

$running = $myproc->poll();

ويعيد 1 إذا كانت كذلك، و 0 إذا لم تكن.

kill
الأسلوب kill:

$myproc->kill();

ينهي العملية بإرسال إشارة SIGTERM إليها. كخيار، يمكن تحديد إشارة أخرى.

$myproc->kill("SIGUSR1");

يرسل إشارة SIGUSR1 إلى العملية قيد التشغيل. يعيد الأسلوب kill القيمة 1 إذا نجح في إرسال الإشارة، و 0 إذا لم ينجح.

kill_on_destroy
يضبط علامة لتحديد ما إذا كان يجب إنهاء العملية المرتبطة بهذا الكائن عند تدمير الكائن. افتراضيًا، تكون هذه العلامة معطلة. تتم إعادة القيمة الحالية.

$current = $proc->kill_on_destroy;
$proc->kill_on_destroy(1); # تفعيل العلامة
$proc->kill_on_destroy(0); # تعطيل العلامة
signal_on_destroy
أسلوب لضبط الإشارة التي سيتم إرسالها إلى العملية عند تدمير الكائن (بافتراض أن kill_on_destroy نشط). يعيد القيمة الحالية للإعداد.

$current = $proc->signal_on_destroy;
$proc->signal_on_destroy("KILL");
redirect_output
إعادة توجيه الإخراج القياسي و / أو خطأ الإخراج القياسي لعملية إلى ملف. حدد undef لترك مقابض stdout / stderr للعملية سليمة.

# stdout إلى ملف، stderr لا يتغير
$proc->redirect_output ("/tmp/someapp.stdout", undef);

# stderr إلى ملف، stdout لا يتغير
$proc->redirect_output (undef, "/tmp/someapp.stderr");

# stdout و stderr إلى ملف منفصل
$proc->redirect_output ("/tmp/someapp.stdout", "/tmp/someapp.stderr");

استدعِ هذا الأسلوب قبل استدعاء الأسلوب start.

pid
يعيد pid العملية الفرعية المرتبطة بهذا الكائن

$pid = $proc->pid;
t0
يعيد وقت البدء (t0) للعملية الفرعية المرتبطة بهذا الكائن

$t0 = $proc->t0();
t1
يعيد وقت الانتهاء (t1) للعملية الفرعية المرتبطة بهذا الكائن

$t1 = $proc->t1();
Proc::Simple(3pm)

NAME

Proc::Simple - Perl module to simplify running external processes

SYNOPSIS

use Proc::Simple;

my $proc = Proc::Simple->new();
$proc->start('command && another');
my $output = $proc->capture('command && another');
$proc->run('command && another');

if ($proc->has_error()) {
    die $proc->error();
}

my $status = $proc->wait();
my $exit_status = $proc->exit_status();

# check how long the process ran
print $proc->t1() - $proc->t0(), "\n";

DESCRIPTION

Proc::Simple is a Perl module to simplify running external processes. It handles process creation, error checking, status retrieval, and timing.

METHODS

new()
Constructor. Creates a new Proc::Simple object.
start(command, [args...])
Starts the given command asynchronously. If additional arguments are provided, they are passed as separate arguments to the command. 
$proc->start('ls', '-l', '/tmp');
This is equivalent to: 
$proc->start('ls -l /tmp');
but the former is safer if the command or its arguments contain shell metacharacters.

The process is started in its own process group.

Also see Proc::Simple::start(3pm).

run(command, [args...])
Runs the given command synchronously. This method waits until the command finishes execution and returns its exit status. 
$proc->run('sleep 1 && echo done');
$exit_status = $proc->exit_status();
capture(command, [args...])
Runs the given command synchronously and captures its standard output. This method waits until the command finishes execution. 
$output = $proc->capture('ls -l');
$exit_status = $proc->exit_status();
kill(signal)
Sends the specified signal to the process. 
$proc->kill(9); # SIGKILL
poll()
Checks if the process is still running. Returns true if running, false otherwise. 
if ($proc->poll()) {
    print "Process still running...\n";
}
waitpid()
Waits for the process to terminate and returns its process ID. This is a low-level interface. Use wait for a higher-level interface.
wait
The wait method: 
$exit_status = $myproc->wait();
waits until the process is done and returns its exit status.
error()
Returns the error message if an error occurred during process execution (e.g., command not found). Returns "undef" if no error occurred.
has_error()
Returns true if an error occurred, false otherwise.
pid()
Returns the process ID of the running process.
kill_on_destroy(boolean)
If set to true, the process associated with the object will be killed when the object is destroyed. Defaults to false.
signal_on_destroy(signal)
Specifies the signal to be sent to the process when it's killed on destroy. Defaults to SIGTERM.
t0()
Returns the time the process was started (epoch seconds).
t1()
Returns the time the process finished (epoch seconds).

$t1 = $proc->t1();
DESTROY (Destructor)
Object destructor. This method is called when the object is destroyed (eg with "undef" or on exiting perl). If kill_on_destroy is true the process associated with the object is sent the signal_on_destroy signal (SIGTERM if undefined).
exit_status
Returns the exit status of the process as the $! variable indicates. If the process is still running, "undef" is returned.
wait
The wait method: 
$exit_status = $myproc->wait();

waits until the process is done and returns its exit status.

debug
Switches debug messages on and off -- Proc::Simple::debug(1) switches them on, Proc::Simple::debug(0) keeps Proc::Simple quiet.
cleanup
Proc::Simple keeps around data of terminated processes, e.g. you can check via t0() and t1() how long a process ran, even if it's long gone. Over time, this data keeps occupying more and more memory and if you have a long-running program, you might want to run "Proc::Simple->cleanup()" every once in a while to get rid of data pertaining to processes no longer in use.

NOTE

Please keep in mind that there is no guarantee that the SIGTERM signal really terminates a process. Processes can have signal handlers defined that avoid the shutdown. If in doubt, whether a process still exists, check it repeatedly with the poll routine after sending the signal.

Shell Processes

If you pass a shell program to Proc::Simple, it'll use exec() to launch it. As noted in Perl's exec() manpage, simple commands for the one-argument version of exec() will be passed to execvp() directly, while commands containing characters like ";" or "*" will be passed to a shell to make sure those get the shell expansion treatment.

This has the interesting side effect that if you launch something like

$p->start("./womper *");

then you'll see two processes in your process list:

$ ps auxww | grep womper
mschilli  9126 11:21 0:00 sh -c ./womper *
mschilli  9127 11:21 0:00 /usr/local/bin/perl -w ./womper ...

A regular kill() on the process PID would only kill the first process, but Proc::Simple's kill() will use a negative signal and send it to the first process (9126). Since it has marked the process as a process group leader when it created it previously (via setsid()), this will cause both processes above to receive the signal sent by kill().
