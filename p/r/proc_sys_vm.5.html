الاسم

/proc/sys/vm/ - نظام الذاكرة الافتراضية

الوصف

/proc/sys/vm/
يحتوي هذا الدليل على ملفات لضبط إدارة الذاكرة، والمخازن المؤقتة، وإدارة ذاكرة التخزين المؤقت.
/proc/sys/vm/admin_reserve_kbytes (منذ لينكس 3.10)
يحدد هذا الملف مقدار الذاكرة المجانية (بالكيلوبايت) على النظام التي يجب تخصيصها للمستخدمين الذين لديهم القدرة CAP_SYS_ADMIN.
القيمة الافتراضية في هذا الملف هي الحد الأدنى من [3٪ من الصفحات المجانية، 8MiB] معبرًا عنها بالكيلوبايت. الهدف الافتراضي هو توفير ما يكفي للمستخدم الخارق لتسجيل الدخول وقتل عملية، إذا لزم الأمر، في وضع "التقدير" الافتراضي للإفراط في التخصيص (أي، 0 في /proc/sys/vm/overcommit_memory).
يجب على الأنظمة التي تعمل في وضع "عدم الإفراط في التخصيص مطلقًا" (أي، 2 في /proc/sys/vm/overcommit_memory) زيادة القيمة في هذا الملف لتغطية الحجم الكامل للذاكرة الافتراضية للبرامج المستخدمة للاسترداد (على سبيل المثال، login(1) ssh(1)، و top(1)). بخلاف ذلك، قد لا يتمكن المستخدم الخارق من تسجيل الدخول لاستعادة النظام. على سبيل المثال، على x86-64، القيمة المناسبة هي 131072 (128MiB محجوزة).
يتخذ تغيير القيمة في هذا الملف تأثيرًا كلما طلبت التطبيقات ذاكرة.
/proc/sys/vm/compact_memory (منذ لينكس 2.6.35)
عند كتابة 1 إلى هذا الملف، يتم ضغط جميع المناطق بحيث تكون الذاكرة المجانية متاحة في كتل متجاورة حيثما أمكن. يمكن رؤية تأثير هذا الإجراء بفحص /proc/buddyinfo.
موجود فقط إذا تم تكوين النواة مع CONFIG_COMPACTION.
/proc/sys/vm/drop_caches (منذ لينكس 2.6.16)
يؤدي الكتابة إلى هذا الملف إلى قيام النواة بإسقاط ذاكرة التخزين المؤقت النظيفة، و dentry، و inode من الذاكرة، مما يجعل تلك الذاكرة مجانية. يمكن أن يكون هذا مفيدًا لاختبار إدارة الذاكرة وإجراء اختبارات أداء نظام الملفات المتكررة. نظرًا لأن الكتابة إلى هذا الملف يؤدي إلى فقدان فوائد التخزين المؤقت، يمكن أن يؤدي إلى تدهور أداء النظام العام.
لتحرير pagecache، استخدم:

echo 1 > /proc/sys/vm/drop_caches

لتحرير dentry و inode، استخدم:

echo 2 > /proc/sys/vm/drop_caches

لتحرير pagecache، dentry، و inode، استخدم:

echo 3 > /proc/sys/vm/drop_caches

نظرًا لأن الكتابة إلى هذا الملف عملية غير مدمرة ولا يمكن تحرير الكائنات المتسخة، يجب على المستخدم تشغيل sync(1) أولاً.
/proc/sys/vm/hugetlb_shm_group (منذ لينكس 2.6.7)
يحتوي هذا الملف القابل للكتابة على معرف مجموعة مسموح له بتخصيص الذاكرة باستخدام صفحات كبيرة. إذا كان لدى العملية معرف مجموعة نظام ملفات أو أي معرف مجموعة تكميلي يتطابق مع معرف المجموعة هذا، فيمكنها إجراء تخصيصات صفحات كبيرة دون الاحتفاظ بالقدرة CAP_IPC_LOCK؛ انظر memfd_create(2)، mmap(2)، و shmget(2).
/proc/sys/vm/legacy_va_layout (منذ لينكس 2.6.9)
إذا كان غير صفري، فإنه يعطل تخطيط الذاكرة الجديد 32 بت؛ ستستخدم النواة تخطيط الإرث (2.4) لجميع العمليات.
/proc/sys/vm/memory_failure_early_kill (منذ لينكس 2.6.32)
التحكم في كيفية قتل العمليات عند اكتشاف خطأ في الذاكرة غير مصحح (عادةً خطأ بمقدار 2 بت في وحدة ذاكرة) لا يمكن للنواة معالجته في الخلفية بواسطة الأجهزة. في بعض الحالات (مثل وجود نسخة صالحة للصفحة على القرص)، ستتعامل النواة مع الفشل بشفافية دون التأثير على أي تطبيقات. ولكن إذا لم تكن هناك نسخة أخرى محدثة من البيانات، فستقوم بقتل العمليات لمنع انتشار أي تلف في البيانات.
الملف له إحدى القيم التالية:
1
اقتل جميع العمليات التي لديها الصفحة التالفة وغير القابلة لإعادة التحميل معروضة فور اكتشاف التلف. لاحظ أن هذا غير مدعوم لعدد قليل من أنواع الصفحات، مثل البيانات المخصصة داخليًا للنواة أو ذاكرة التخزين المؤقت للتبديل، ولكنه يعمل لمعظم صفحات المستخدم.
0
قم بإلغاء تعيين الصفحة التالفة من جميع العمليات واقتل العملية فقط إذا حاولت الوصول إلى الصفحة.
يتم إجراء القتل باستخدام إشارة SIGBUS مع تعيين si_code إلى BUS_MCEERR_AO. يمكن للعمليات التعامل مع هذا إذا رغبت في ذلك؛ انظر sigaction(2) لمزيد من التفاصيل.
هذه الميزة نشطة فقط على البنيات/المنصات التي لديها معالجة متقدمة لفحص الأجهزة وتعتمد على قدرات الأجهزة.
يمكن للتطبيقات تجاوز إعداد memory_failure_early_kill بشكل فردي باستخدام عملية prctl(2) PR_MCE_KILL.
موجود فقط إذا تم تكوين النواة مع CONFIG_MEMORY_FAILURE.
/proc/sys/vm/memory_failure_recovery (منذ لينكس 2.6.32)
تمكين استرداد فشل الذاكرة (عندما تدعمه المنصة).
1
محاولة الاسترداد.
0
دائما يحدث panic عند فشل الذاكرة.
موجود فقط إذا تم تكوين النواة مع CONFIG_MEMORY_FAILURE.
/proc/sys/vm/oom_dump_tasks (منذ لينكس 2.6.25)
يُمكّن إنتاج تفريغ شامل للمهام (باستثناء خيوط النواة) عندما تقوم النواة بتنفيذ عملية قتل بسبب نفاد الذاكرة (OOM). يشمل التفريغ المعلومات التالية لكل مهمة (خيط، عملية): معرف الخيط، معرف المستخدم الفعلي، معرف مجموعة الخيط (معرف العملية)، حجم الذاكرة الافتراضية، حجم المجموعة المقيمة، وحدة المعالجة المركزية التي تم جدولة المهمة عليها، درجة oom_adj (انظر وصف /proc/pid/oom_adj)، واسم الأمر. هذا مفيد لتحديد سبب استدعاء قاتل OOM وتحديد المهمة المارقة التي تسببت في ذلك.
إذا كانت تحتوي على القيمة صفر، يتم قمع هذه المعلومات. على الأنظمة الكبيرة جدًا التي تحتوي على آلاف المهام، قد لا يكون من الممكن تفريغ معلومات حالة الذاكرة لكل منها. يجب ألا تُجبر هذه الأنظمة على تحمل عقوبة الأداء في مواقف OOM عندما قد لا تكون المعلومات مرغوبة.
إذا تم تعيينها على قيمة غير صفرية، يتم عرض هذه المعلومات كلما قام قاتل OOM بالفعل بقتل مهمة تستهلك الذاكرة بكثرة.
القيمة الافتراضية هي 0.
/proc/sys/vm/oom_kill_allocating_task (منذ لينكس 2.6.24)
يُمكّن أو يعطل قتل المهمة التي تسببت في نفاد الذاكرة في حالات نفاد الذاكرة.
إذا تم تعيين هذه القيمة على صفر، فسيقوم قاتل OOM بفحص قائمة المهام بأكملها واختيار مهمة بناءً على استدلال لقتلها. عادةً ما يختار هذا مهمة مارقة تستهلك الذاكرة بكثرة والتي تحرر كمية كبيرة من الذاكرة عند قتلها.
إذا تم تعيين هذه القيمة على قيمة غير صفرية، فإن قاتل OOM ببساطة يقتل المهمة التي أدت إلى حالة نفاد الذاكرة. هذا يتجنب فحصًا مكلفًا محتملًا لقائمة المهام.
إذا كانت /proc/sys/vm/panic_on_oom غير صفرية، فإنها تأخذ الأولوية على أي قيمة مستخدمة في /proc/sys/vm/oom_kill_allocating_task.
القيمة الافتراضية هي 0.
/proc/sys/vm/overcommit_kbytes (منذ لينكس 3.14)
يوفر هذا الملف القابل للكتابة بديلاً لـ /proc/sys/vm/overcommit_ratio للتحكم في CommitLimit عندما تكون قيمة /proc/sys/vm/overcommit_memory هي 2. يسمح بتحديد مقدار تجاوز تخصيص الذاكرة كقيمة مطلقة (بالكيلوبايت)، بدلاً من نسبة مئوية، كما هو الحال مع overcommit_ratio. هذا يسمح بتحكم أكثر دقة في CommitLimit على الأنظمة ذات أحجام الذاكرة الكبيرة جدًا.
يمكن أن يكون لواحد فقط من overcommit_kbytes أو overcommit_ratio تأثير: إذا كانت overcommit_kbytes قيمة غير صفرية، فسيتم استخدامه لحساب CommitLim

/proc/sys/vm/overcommit_memory
This file contains the kernel virtual memory accounting mode. Values are:
0: heuristic overcommit (this is the default)
1: always overcommit, never check
2: always check, never overcommit
In mode 0, calls of mmap(2) with MAP_NORESERVE are not checked, and the default check is very weak, leading to the risk of getting a process "OOM-killed".
In mode 1, the kernel pretends there is always enough memory, until memory actually runs out. One use case for this mode is scientific computing applications that employ large sparse arrays. Before Linux 2.6.0, any nonzero value implies mode 1.
In mode 2 (available since Linux 2.6), the total virtual address space that can be allocated (CommitLimit in /proc/meminfo) is calculated as

CommitLimit = (total_RAM - total_huge_TLB) *
	      overcommit_ratio / 100 + total_swap

where:
•
total_RAM is the total amount of RAM on the system;
•
total_huge_TLB is the amount of memory set aside for huge pages;
•
overcommit_ratio is the value in /proc/sys/vm/overcommit_ratio; and
•
total_swap is the amount of swap space.
For example, on a system with 16 GB of physical RAM, 16 GB of swap, no space dedicated to huge pages, and an overcommit_ratio of 50, this formula yields a CommitLimit of 24 GB.
Since Linux 3.14, if the value in /proc/sys/vm/overcommit_kbytes is nonzero, then CommitLimit is instead calculated as:

CommitLimit = overcommit_kbytes + total_swap

See also the description of /proc/sys/vm/admin_reserve_kbytes and /proc/sys/vm/user_reserve_kbytes.
/proc/sys/vm/overcommit_ratio (since Linux 2.6.0)
This writable file defines a percentage by which memory can be overcommitted. The default value in the file is 50. See the description of /proc/sys/vm/overcommit_memory.
/proc/sys/vm/panic_on_oom (since Linux 2.6.18)
This enables or disables a kernel panic in an out-of-memory situation.
If this file is set to the value 0, the kernel's OOM-killer will kill some rogue process. Usually, the OOM-killer is able to kill a rogue process and the system will survive.
If this file is set to the value 1, then the kernel normally panics when out-of-memory happens. However, if a process limits allocations to certain nodes using memory policies (mbind(2) MPOL_BIND) or cpusets (cpuset(7)) and those nodes reach memory exhaustion status, one process may be killed by the OOM-killer. No panic occurs in this case: because other nodes' memory may be free, this means the system as a whole may not have reached an out-of-memory situation yet.
If this file is set to the value 2, the kernel always panics when an out-of-memory condition occurs.
The default value is 0. 1 and 2 are for failover of clustering. Select either according to your policy of failover.
/proc/sys/vm/swappiness
The value in this file controls how aggressively the kernel will swap memory pages. Higher values increase aggressiveness, lower values decrease aggressiveness. The default value is 60.
/proc/sys/vm/user_reserve_kbytes (since Linux 3.10)
Specifies an amount of memory (in KiB) to reserve for user processes. This is intended to prevent a user from starting a single memory hogging process, such that they cannot recover (kill the hog). The value in this file has an effect only when /proc/sys/vm/overcommit_memory is set to 2 ("overcommit never" mode). In this case, the system reserves an amount of memory that is the minimum of [3% of current process size, user_reserve_kbytes].
The default value in this file is the minimum of [3% of free pages, 128MiB] expressed as KiB.
If the value in this file is set to zero, then a user will be allowed to allocate all free memory with a single process (minus the amount reserved by /proc/sys/vm/admin_reserve_kbytes). Any subsequent attempts to execute a command will result in "fork: Cannot allocate memory".
Changing the value in this file takes effect whenever an application requests memory.
/proc/sys/vm/unprivileged_userfaultfd (since Linux 5.2)
This (writable) file exposes a flag that controls whether unprivileged processes are allowed to employ userfaultfd(2). If this file has the value 1, then unprivileged processes may use userfaultfd(2). If this file has the value 0, then only processes that have the CAP_SYS_PTRACE capability may employ userfaultfd(2). The default value in this file is 1.
