lso يوفر vlimit(). يجب كتابة جميع التطبيقات الجديدة باستخدام setrlimit().

اختلافات واجهة برمجة التطبيقات (ABI) بين مكتبة C ونواة النظام

منذ glibc 2.13، لم تعد دوال الغلاف getrlimit() و setrlimit() في glibc تستدعي استدعاءات النظام المقابلة، بل تستخدم prlimit()، للأسباب الموضحة في قسم BUGS.

اسم دالة الغلاف في glibc هو prlimit()؛ استدعاء النظام الأساسي هو prlimit64().

مشاكل (BUGS)

في نواة لينكس القديمة، كانت إشارات SIGXCPU و SIGKILL التي يتم تسليمها عندما تواجه العملية حدود RLIMIT_CPU الناعمة والصلبة يتم تسليمها بعد ثانية واحدة (وحدة المعالجة المركزية) مما ينبغي. تم إصلاح هذا في Linux 2.6.8.

في نواة لينكس 2.6.x قبل Linux 2.6.17، كان حد RLIMIT_CPU الذي يساوي 0 يُعامل بشكل خاطئ على أنه "لا يوجد حد" (مثل RLIM_INFINITY). منذ Linux 2.6.17، فإن تعيين حد يساوي 0 له تأثير، ولكنه يُعامل فعليًا على أنه حد ثانية واحدة.

خطأ في النواة يعني أن RLIMIT_RTPRIO لا يعمل في Linux 2.6.12؛ تم إصلاح المشكلة في Linux 2.6.13.

في Linux 2.6.12، كان هناك خطأ في التفاوت بقيمة واحدة بين نطاقات الأولوية التي ترجعها getpriority(2) و RLIMIT_NICE. كان لهذا التأثير أن السقف الفعلي لقيمة "nice" تم حسابه على أنه 19 - rlim_cur. تم إصلاح هذا في Linux 2.6.13.

منذ Linux 2.6.12، إذا وصلت العملية إلى حد RLIMIT_CPU الناعم وكان لديها معالج مثبت لـ SIGXCPU، فبالإضافة إلى استدعاء معالج الإشارة، تقوم النواة بزيادة الحد الناعم بمقدار ثانية واحدة. يتكرر هذا السلوك إذا واصلت العملية استهلاك وقت وحدة المعالجة المركزية، حتى تصل إلى الحد الصلب، وعند هذه النقطة يتم إنهاء العملية. التطبيقات الأخرى لا تغير الحد الناعم RLIMIT_CPU بهذه الطريقة، ومن المحتمل أن يكون سلوك لينكس غير متوافق مع المعايير؛ يجب أن تتجنب التطبيقات المحمولة الاعتماد على هذا السلوك الخاص بلغة لينكس. الحد RLIMIT_RTTIME الخاص بلينكس يُظهر نفس السلوك عند مصادفة الحد الناعم.

لم تقم النوى قبل Linux 2.4.22 بتشخيص خطأ EINVAL لـ setrlimit() عندما كان rlim->rlim_cur أكبر من rlim->rlim_max.

لا تُرجع لينكس خطأً عند فشل محاولة تعيين RLIMIT_CPU، لأسباب تتعلق بالتوافق.

تمثيل قيم حدود الموارد "الكبيرة" على منصات 32 بت

تستخدم دوال الغلاف getrlimit() و setrlimit() في glibc نوع بيانات rlim_t بـ 64 بت، حتى على منصات 32 بت. ومع ذلك، فإن نوع بيانات rlim_t المستخدم في استدعاءات النظام getrlimit() و setrlimit() هو unsigned long (32 بت). علاوة على ذلك، في لينكس، تمثل النواة حدود الموارد على منصات 32 بت كـ unsigned long. ومع ذلك، فإن نوع بيانات 32 بت ليس عريضًا بما فيه الكفاية. الحد الأكثر صلة هنا هو RLIMIT_FSIZE، الذي يحدد الحد الأقصى للحجم الذي يمكن أن ينمو به الملف: ليكون مفيدًا، يجب تمثيل هذا الحد باستخدام نوع عريض بما يكفي مثل نوع البيانات المستخدم لتمثيل إزاحات الملفات - أي، بنفس عرض off_t بـ 64 بت (بافتراض برنامج تم تجميعه مع _FILE_OFFSET_BITS=64).

للتغلب على هذا القيد في النواة، إذا حاول برنامج تعيين حد موارد لقيمة أكبر مما يمكن تمثيله في unsigned long بـ 32 بت، فإن دالة الغلاف setrlimit() في glibc قامت بتحويل قيمة الحد بصمت إلى RLIM_INFINITY. بمعنى آخر، تم تجاهل طلب تعيين حد الموارد بصمت.

منذ glibc 2.13، تتجاوز glibc قيود استدعاءات النظام getrlimit() و setrlimit() عن طريق تنفيذ setrlimit() و getrlimit() كدوال غلاف تستدعي prlimit().

أمثلة (EXAMPLES)

يوضح البرنامج التالي استخدام prlimit().

#define _GNU_SOURCE
#define _FILE_OFFSET_BITS 64
#include <err.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/resource.h>
#include <time.h>
int
main(int argc, char *argv[])
{
    pid_t          pid;
    struct rlimit  old, new;
    struct rlimit  *newp;
    if (!(argc == 2 || argc == 4)) {
        fprintf(stderr, "Usage: %s <pid> [<new-soft-limit> "
                "<new-hard-limit>]\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    pid = atoi(argv[1]);        /* PID of target process */
    newp = NULL;
    if (argc == 4) {
        new.rlim_cur = atoi(argv[2]);
        new.rlim_max = atoi(argv[3]);
        newp = &new;
    }
    /* Set CPU time limit of target process; retrieve and display
       previous limit */
    if (prlimit(pid, RLIMIT_CPU, newp, &old) == -1)
        err(EXIT_FAILURE, "prlimit-1");
    printf("Previous limits: soft=%jd; hard=%jd\n",
           (intmax_t) old.rlim_cur, (intmax_t) old.rlim_max);
    /* Retrieve and display new CPU time limit */
    if (prlimit(pid, RLIMIT_CPU, NULL, &old) == -1)
        err(EXIT_FAILURE, "prlimit-2");
    printf("New limits: soft=%jd; hard=%jd\n",
           (intmax_t) old.rlim_cur, (intmax_t) old.rlim_max);
    exit(EXIT_SUCCESS);
}
