الوصف

الوظائف التي تتعامل مع وحدات MIB تقع ضمن أربع مجموعات - تلك التي تتعامل مع التهيئة والإغلاق، مع قراءة وتحليل ملفات MIB، مع البحث في شجرة MIB، ووظائف الإخراج.

التهيئة والإغلاق

add_mibdir تستخدم لإضافة الدليل المحدد إلى مسار المواقع التي يتم البحث فيها عن الملفات التي تحتوي على وحدات MIB. لاحظ أن هذا لا يقوم فعليًا بتحميل وحدات MIB الموجودة في هذا الدليل، ولكنه مجرد خطوة تهيئة لجعلها متاحة لـ netsnmp_read_module. تعيد هذه الوظيفة عدد الملفات الموجودة في الدليل، أو -1 إذا حدث خطأ. يجب استدعاؤها *قبل* استدعاء netsnmp_init_mib.

netsnmp_init_mib يقوم بتهيئة مسار البحث عن دليل MIB (باستخدام add_mibdir)، ويقوم بإعداد إطار عمل MIB الداخلي، ثم يقوم بتحميل وحدات MIB المناسبة (باستخدام netsnmp_read_module و read_mib). انظر قسم المتغيرات البيئية (ENVIRONMENTAL VARIABLES) للتفاصيل.
يجب استدعاؤها قبل أي روتين آخر يقوم بمعالجة شجرة MIB أو الوصول إليها (ولكن بعد أي استدعاءات إضافية لـ add_mibdir).

shutdown_mib ستقوم بمسح المعلومات التي تم جمعها بواسطة netsnmp_read_module و add_mibdir و add_module_replacement. يوصى بشدة بعدم استدعاء shutdown_mib أثناء إدارة جلسات SNMP بنشاط.

قراءة وتحليل ملفات MIB

netsnmp_read_module تأخذ اسم وحدة MIB (والذي قد لا يكون هو نفس اسم الملف الذي يحتوي على الوحدة)، وتحدد موقعها ضمن القائمة المهيأة لأدلة MIB، وتقوم بتحميل التعريفات من الوحدة إلى شجرة MIB النشطة. كما أنها تقوم بتحميل أي وحدات MIB مدرجة في بند IMPORTS لهذه الوحدة.

read_mib مشابهة، ولكنها تأخذ اسم الملف الذي يحتوي على وحدة MIB. لاحظ أن هذا الملف قد لا يكون موجودًا ضمن قائمة البحث عن دليل MIB (على الرغم من أن أي وحدات مدرجة في بند IMPORTS يجب أن تكون كذلك).

read_all_mibs ستقوم بقراءة جميع وحدات MIB الموجودة في قائمة البحث عن دليل MIB.

بشكل عام، يكون المحلل صامتًا بشأن الغرائب التي يراها في ملفات MIB. للحصول على تقارير عن التحذيرات، قم باستدعاء snmp_set_mib_warnings بمستوى 1 (أو 2 لمزيد من التحذيرات).

يمكن استخدام add_module_replacement للسماح لوحدات MIB الجديدة بإبطال الوحدات القديمة، دون الحاجة إلى تعديل بنود IMPORTS للوحدات الأخرى. تأخذ أسماء الوحدات القديمة والجديدة، جنبًا إلى جنب مع مؤشر على الأجزاء من الوحدة القديمة التي تم التأثير عليها.

tag len تحميل الوحدة الجديدة عندما:
NULL 0 دائمًا (الوحدة القديمة هي مجموعة فرعية صارمة من
الوحدة الجديدة)
name 0 فقط للعلامة المحددة
name non-0 لأي معرف له هذا البادئة
يمكن استخدامها أيضًا للتعامل مع الأخطاء في معرفات الوحدات المستخدمة في بنود MIB IMPORTS (مثل الإشارة إلى RFC1213 بدلاً من RFC1213-MIB).

البحث في شجرة MIB

read_objid تأخذ سلسلة نصية تحتوي على تمثيل نصي لمعرف الكائن (بشكل رقمي أو وصفي)، وتحولها إلى قائمة المعرفات الفرعية المقابلة. يتم إرجاع هذا في المعلمة output، مع عدد المعرفات الفرعية التي تم إرجاعها عبر out_len. عند استدعائها، يجب أن تحتوي out_len على الحد الأقصى لطول مصفوفة output. إذا كان يتم معالجة معرفات كائنات متعددة، فيجب إعادة تعيين هذا الطول قبل كل استدعاء. تعيد هذه الوظيفة قيمة 1 إذا نجحت في تحليل السلسلة و 0 بخلاف ذلك.

snmp_parse_oid مشابهة، ولكنها تعيد مؤشرًا إلى مخزن OID المحلل (أو NULL).

get_module_node تأخذ وصفًا واسم وحدة، وتعيد قائمة OID المقابلة، بنفس طريقة read_objid أعلاه.
إذا تم تحديد اسم الوحدة على أنه "ANY"، فستفترض هذه الروتين أن الوصف المعطى فريد داخل الشجرة، وستعيد الإدخال المطابق. إذا كان هذا الافتراض غير صحيح، فإن سلوك المتغير الذي تم إرجاعه يعتمد على التنفيذ.

الإخراج

print_mib ستطبع تمثيلًا لشجرة MIB النشطة حاليًا إلى مؤشر ملف FILE المحدد.

print_objid ستأخذ معرف كائن (كما تم إرجاعه بواسطة read_objid أو snmp_parse_oid أو get_module_node)، وتطبع الشكل النصي لـ OID هذا إلى الإخراج القياسي.

fprint_objid تقوم بنفس الشيء، ولكنها تطبع إلى مؤشر ملف FILE المحدد بواسطة المعلمة الأولية.

snprint_objid تطبع نفس المعلومات في المخزن المؤقت المشار إليه بواسطة buf بطول len. تعيد عدد الأحرف المطبوعة، أو -1 إذا لم يكن المخزن المؤقت كبيرًا بما يكفي. في الحالة الأخيرة، سيحتوي buf عادةً على نسخة مقطوعة من المعلومات (ولكن هذا السلوك غير مضمون).

print_description و fprint_description و snprint_description تأخذ معرف كائن مشابه وتطبع نسخة من تعريف MIB لهذا الكائن، جنبًا إلى جنب مع OID الكامل. تتحكم المعلمة width في كيفية تخطيط OID.

بشكل افتراضي، لا يقوم المحلل بحفظ الأوصاف نظرًا لأنها قد تكون ضخمة. لكي تكون قادرًا على طباعتها، من الضروري

print_description(3) - Net-SNMP API Documentation

NAME

print_description - Print the textual description of a MIB object

SYNOPSIS

#include <net-snmp/library/mib.h>

char *
print_description(oid *objid, size_t objid_len);

DESCRIPTION

The print_description function takes an OID and returns its textual description from the loaded MIB modules.

The description is returned as a dynamically allocated string, which must be freed by the caller using free(3).

This function relies on the MIB modules being loaded into the MIB database. You should call snmp_set_save_descriptions(1)before calling init_mib (or similar).

ENVIRONMENT VARIABLES

The main use of environmental variables with respect to these API calls is to configure which MIB modules should be loaded, and where they are located.

MIBDIRS
A colon separated list of directories to search for MIB modules.
Default: /usr/share/snmp/mibs
Used by init_mib, netsnmp_read_module, read_all_mibs and (implicitly) by read_mib.
MIBS
A colon separated list of MIB modules to load.
The default list of modules will depend on how the Net-SNMP software was originally compiled, but is typically:
IP-MIB:IF-MIB:TCP-MIB:UDP-MIB:SNMPv2-MIB:RFC1213-MIB:UCD-SNMP-MIB:HOST-RESOURCES-MIB
If the value of the MIBS environmental variable starts with a '+' character, then these MIB modules will be added to the default list. Otherwise these modules (plus any that they IMPORT from) will be loaded instead of the default list.
If the MIBS environmental variable has the value ALL then read_all_mibs will be called to load the full collection of all available MIB modules.
Used by init_mib only.
MIBFILES
A colon separated list of files to load.
Default: (none)
Used by init_mib only.
