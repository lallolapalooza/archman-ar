procps(3)

الحزمة: procps-ng

التراخيص: GPL, LGPL

PROCPS(3) دليل دوال المكتبة PROCPS(3)

الاسم

procps - واجهة برمجة تطبيقات للوصول إلى معلومات مستوى النظام في نظام الملفات /proc

مُلَخَّص

يتم تمثيل خمس واجهات متميزة في هذا الملخص وتسميتها بناءً على الملفات التي تصل إليها في نظام الملفات الزائف /proc: diskstats، meminfo، slabinfo، stat و vmstat.

#include <libproc2/named_interface.h>
int procps_new   (struct info **info);
int procps_ref   (struct info  *info);
int procps_unref (struct info **info);
struct result *procps_get (
    struct info *info,
[   const char *name,      ]   diskstats api only
    enum item item);
struct stack *procps_select (
    struct info *info,
[   const char *name,      ]   diskstats api only
    enum item *items,
    int numitems);
struct reaped *procps_reap (
    struct info *info,
[   enum reap_type what,   ]   stat api only
    enum item *items,
    int numitems);
struct stack **procps_sort (
    struct info *info,
    struct stack *stacks[],
    int numstacked,
    enum item sortitem,
    enum sort_order order);

الدوال والهياكل المذكورة أعلاه عامة، ولكن الواجهة المحددة named_interface ستكون أيضًا جزءًا من أي معرفات. على سبيل المثال، ستكون ‘procps_new’ في الواقع ‘procps_meminfo_new’ وستكون ‘info’ في الواقع ‘diskstats_info’، إلخ.

يتم استخدام نفس named_interface في اسم كل ملف رأس مع لاحقة ‘.h’.

اربط مع -lproc2.

الوصف

نظرة عامة

السمة المركزية لهذه الواجهات هي هيكل ‘result’ بسيط يعكس ‘item’ بالإضافة إلى قيمته (في اتحاد مع أنواع لغة C القياسية كأعضاء). يتم تخصيص جميع هياكل ‘result’ تلقائيًا وتوفيرها بواسطة المكتبة.

من خلال تحديد مصفوفة من ‘items’، يمكن تنظيم هذه الهياكل كـ ‘stack’، مما قد ينتج عنه العديد من النتائج باستدعاء دالة واحدة. وبالتالي، يمكن النظر إلى ‘stack’ كسجل متغير الطول يتم تحديده بالكامل بواسطة المستخدم.

كجزء من كل واجهة، هناك مُعدادان فريدان. العناصر ‘noop’ و ‘extra’ موجودة للاحتفاظ بالقيم الخاصة بالمستخدم. لا يتم تعيينها أبدًا بواسطة المكتبة، ولكن سيتم مسح النتيجة ‘extra’ مع كل تفاعل للمكتبة.

سيكون ملف الرأس named_interface وثيقة أساسية أثناء تطوير برنامج المستخدم. هناك ستجد العناصر المتاحة، نوع إرجاعها (اسم عضو هيكل ‘result’) ومصدر هذه القيم. يتم أيضًا توثيق مُعدادات وهياكل إضافية هناك.

الاستخدام

التسلسل التالي سيكون تسلسلاً نموذجيًا لاستدعاء هذه الواجهات.

1. procps_new()
2. procps_get(), procps_select() or procps_reap()
3. procps_unref()

تُستخدم دالة get لاسترداد هيكل ‘result’ لـ ‘item’ واحد. بدلاً من ذلك، يتوفر ماكرو GET عندما تكون قيمة الإرجاع فقط هي محل اهتمام.

يمكن لدالة select استرداد هياكل ‘result’ متعددة في ‘stack’ واحد.

للنتائج غير المتوقعة المتغيرة، تصدّر الواجهات diskstats، slabinfo و stat دالة reap. تُستخدم لاسترداد ‘stacks’ متعددة تحتوي كل منها على هياكل ‘result’ متعددة. اختياريًا، يمكن للمستخدم اختيار sort تلك النتائج.

للاستفادة من أي ‘stack’، والوصول إلى هياكل ‘result’ الفردية، يلزم وجود relative_enum كما هو موضح في ماكرو VAL المعرف في ملف الرأس. يمكن أن تكون مثل هذه القيم ثابتة بالترميز كـ: 0 إلى numitems-1. ومع ذلك، يتم عادةً تلبية هذه الحاجة عن طريق إنشاء مُعدادات خاصة بك تتوافق مع ترتيب مصفوفة ‘items’.

ملاحظات

الدوال new، ref، unref، get و select متاحة في جميع الواجهات الخمس.

بالنسبة لدوال new و unref، يجب توفير عنوان مؤشر هيكل info. مع new يجب أن يكون قد تم تهيئته إلى NULL. مع unref سيتم إعادة تعيينه إلى NULL إذا وصل عداد المراجع إلى الصفر.

في حالة واجهة diskstats، يحدد المعامل name في دوال get و select اسم القرص أو القسم.

بالنسبة لواجهة stat، يحدد المعامل what في دالة reap ما إذا كان سيتم جمع البيانات لوحدات المعالجة المركزية فقط أو لوحدات المعالجة المركزية وعقد NUMA.

عند استخدام دالة sort، فإن المعاملات stacks و numstacked ستكون عادةً هي تلك التي تم إرجاعها في هيكل ‘reaped’.

قيمة الإرجاع

الدوال التي تُرجع ‘int’

سيتم الإشارة إلى خطأ برقم سالب يكون دائمًا معكوسًا لبعض قيم errno.h المعروفة.

يتم الإشارة إلى النجاح بقيمة إرجاع صفر. ومع ذلك، تُرجع الدوال ref و unref عداد المراجع الحالي لهيكل info.

الدوال التي تُرجع ‘address’

سيتم الإشارة إلى خطأ بمؤشر إرجاع NULL مع توضيح السبب في قيمة errno الرسمية.

يتم الإشارة إلى النجاح بمؤشر إلى الهيكل المسمى.

التصحيح

للمساعدة في تطوير البرامج، يوجد شرط يمكن أن يساعد في ضمان توافق مراجع أعضاء ‘result’ مع توقعات المكتبة. يفترض أن يتم استخدام ماكرو مقدم في ملف الرأس للوصول إلى قيمة ‘result’.

يمكن تنشيط هذه الميزة من خلال أي من الطرق التالية وسيتم كتابة أي اختلافات إلى stderr.

1)
أضف CFLAGS='-DXTRA_PROCPS_DEBUG' إلى أي خيارات أخرى لـ ./configure مستخدمة.
2)
أضف #include <libproc2/xtra-procps-debug.h> إلى أي برنامج بعد تضمينات الواجهة المسماة.

تتحمل ميزة التحقق هذه عبئًا كبيرًا. لذلك، من المهم أنه *لا* يتم تنشيطها لبناء إنتاجي/إصدار.
