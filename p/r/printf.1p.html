PRINTF(1P) دليل مبرمج POSIX PRINTF(1P)

مقدمة

هذه الصفحة من الدليل هي جزء من دليل مبرمج POSIX. قد يختلف تطبيق Linux لهذه الواجهة (استشر صفحة دليل Linux المقابلة لتفاصيل سلوك Linux)، أو قد لا تكون الواجهة مطبقة على Linux.

الاسم

printf — كتابة إخراج منسق

الموجز

printf format [argument...]

الوصف

تقوم الأداة printf بكتابة المعاملات المنسقة إلى الإخراج القياسي. يتم تنسيق معاملات argument تحت سيطرة معامل format.

الخيارات

لا شيء.

المعاملات

سيتم دعم المعاملات التالية:

format
سلسلة تصف التنسيق المستخدم لكتابة المعاملات المتبقية. انظر قسم الوصف الموسع.
argument
السلاسل النصية التي ستتم كتابتها إلى الإخراج القياسي، تحت سيطرة format. انظر قسم الوصف الموسع.

الإدخال القياسي

غير مستخدم.

ملفات الإدخال

لا شيء.

متغيرات البيئة

ستؤثر متغيرات البيئة التالية على تنفيذ printf:

LANG
توفير قيمة افتراضية لمتغيرات التدويل غير المعينة أو الفارغة. (انظر المجلد الأساسي للتعريفات POSIX.1-2017، القسم 8.2، متغيرات التدويل أولوية متغيرات التدويل المستخدمة لتحديد قيم فئات الإعداد المحلي.)
LC_ALL
إذا تم تعيينها إلى قيمة سلسلة غير فارغة، فستتجاوز جميع متغيرات التدويل الأخرى.
LC_CTYPE
تحديد الإعداد المحلي لتفسير تسلسلات البايتات للنصوص كأحرف (على سبيل المثال، أحرف أحادية البايت مقابل أحرف متعددة البايت في المعاملات).
LC_MESSAGES

تحديد الإعداد المحلي الذي يجب استخدامه للتأثير على تنسيق ومحتويات رسائل التشخيص المكتوبة إلى الخطأ القياسي.
LC_NUMERIC

تحديد الإعداد المحلي للتنسيق الرقمي. سيؤثر على تنسيق الأرقام المكتوبة باستخدام حروف مواصفات التحويل e، E، f، g، و G (إذا تم دعمها).
NLSPATH
تحديد موقع كتالوجات الرسائل لمعالجة LC_MESSAGES.

الأحداث غير المتزامنة

افتراضي.

انظر قسم الوصف الموسع.

الخطأ القياسي

يجب استخدام الخطأ القياسي فقط لرسائل التشخيص.

ملفات الإخراج

لا شيء.

الوصف الموسع

سيتم استخدام معامل format كسلسلة format الموصوفة في المجلد الأساسي للتعريفات POSIX.1-2017، الفصل 5، تدوين تنسيق الملف مع الاستثناءات التالية:

1.
يجب معاملة <مسافة> في سلسلة التنسيق، في أي سياق بخلاف علامة في مواصفات التحويل، كحرف عادي يتم نسخه إلى الإخراج.
2.
يجب معاملة حرف '' في سلسلة التنسيق كحرف ''، وليس كـ <مسافة>.
3.
بالإضافة إلى تسلسلات الهروب الموضحة في المجلد الأساسي للتعريفات POSIX.1-2017، الفصل 5، تدوين تنسيق الملف ('\\'، '\a'، '\b'، '\f'، '\n'، '\r'، '\t'، '\v')، يجب كتابة "\ddd"، حيث ddd هو رقم ثماني مكون من رقم واحد أو رقمين أو ثلاثة أرقام، كبايت بقيمة رقمية محددة بالرقم الثماني.
4.
لا يجب على التطبيق أن يسبق أو يلحق الإخراج من مواصفات التحويل d أو u بأحرف <مسافة> غير محددة بمعامل format.
5.
لا يجب على التطبيق أن يسبق الإخراج من مواصفات التحويل o بأصفار غير محددة بمعامل format.
6.
لا يلزم دعم مواصفات التحويل a، A، e، E، f، F، g، و G.
7.
سيتم دعم مواصفات تحويل إضافية، b، على النحو التالي. سيتم أخذ المعامل كسلسلة نصية يمكن أن تحتوي على تسلسلات هروب <الشرطة المائلة للخلف>. سيتم دعم تسلسلات الهروب <الشرطة المائلة للخلف> التالية:
--
تسلسلات الهروب المدرجة في المجلد الأساسي للتعريفات POSIX.1-2017، الفصل 5، تدوين تنسيق الملف ('\\'، '\a'، '\b'، '\f'، '\n'، '\r'، '\t'، '\v')، والتي سيتم تحويلها إلى الأحرف التي تمثلها.
--
"\0ddd"، حيث ddd هو رقم ثماني مكون من صفر أو واحد أو اثنين أو ثلاثة أرقام سيتم تحويله إلى بايت بقيمة رقمية محددة بالرقم الثماني.
--
'\c'، والذي لن تتم كتابته وسيؤدي إلى قيام printf بتجاهل أي أحرف متبقية في معامل السلسلة الذي يحتوي عليه، وأي معاملات سلاسل نصية متبقية، وأي أحرف إضافية في معامل format.

تفسير <شرطة مائلة للخلف> متبوعة بأي تسلسل آخر من الأحرف غير محدد.

سيتم كتابة البايتات من السلسلة المحولة حتى نهاية السلسلة أو الوصول إلى عدد البايتات المشار إليها بمواصفات الدقة. إذا تم حذف الدقة، فيجب اعتبارها لا نهائية، لذلك سيتم كتابة جميع البايتات حتى نهاية السلسلة المحولة.

8.
لكل مواصفات تحويل تستهلك معاملًا، سيتم تقييم معامل argument التالي وتحويله إلى النوع المناسب للتحويل كما هو محدد أدناه.
9.
سيتم إعادة استخدام معامل format حسب الحاجة لإرضاء معاملات argument. سيتم تقييم أي مواصفات تحويل b، c، أو s إضافية كما لو تم توفير معامل سلسلة فارغة؛ سيتم تقييم مواصفات التحويل الإضافية الأخرى كما لو تم توفير معامل صفر. إذا كان معامل format لا يحتوي على مواصفات تحويل وتم تقديم معاملات argument، فإن النتائج غير محددة.
10.
إذا بدأت تسلسل أحرف في معامل format بحرف '%'، ولكنه لا يشكل مواصفة تحويل صالحة، فإن السلوك غير محدد.
11.
يمكن أن يكون المعامل لمواصفات التحويل c سلسلة نصية تحتوي على صفر أو أكثر من البايتات. إذا كانت تحتوي على بايت واحد أو أكثر، فسيتم كتابة البايت الأول وسيتم تجاهل أي بايتات إضافية. إذا كانت المعامل عبارة عن سلسلة فارغة، فمن غير المحدد ما إذا كان سيتم كتابة لا شيء أو بايت فارغ.

سيتم التعامل مع معاملات argument كسلاسل نصية إذا كانت مواصفات التحويل المقابلة هي b، c، أو s، وسيتم تقييمها كما لو كانت بواسطة الدالة strtod() إذا كانت مواصفات التحويل المقابلة هي a، A، e، E، f، F، g، أو G. بخلاف ذلك، سيتم تقييمها

EXTENDED DESCRIPTION

The printf utility shall format and print data. The behavior of printf is based on the printf() function defined in the System Interfaces volume of POSIX.1‐2017.

The format operand is a character string containing zero or more conversion specifications; characters that do not belong to conversion specifications shall be copied to standard output in their unspecified order.

Each conversion specification shall begin with a '%' character; the character immediately following the '%' shall determine which conversion specification is used. If the character following the '%' is not an escape character defined in the following table, the behavior is undefined.

The following conversion specifications shall be supported:

%a
The argument shall be converted to a hexadecimal floating-point number. The format shall be a hexadecimal point, a '%' and a letter 'a', 'x', 'X', 'p', or 'P' (hexadecimal digits chosen by the implementation). The result is the same as for %f.
%A
The argument shall be converted to a hexadecimal floating-point number. The format shall be a hexadecimal point, a '%' and a letter 'a', 'x', 'X', 'p', or 'P' (hexadecimal digits chosen by the implementation). The result is the same as for %F.
%b
The argument shall be a string. Backslash escape sequences are interpreted as shown in the EXTENDED DESCRIPTION section of echo. The result is the same as for %s.
%c
The argument shall be interpreted as a single character whose numeric value is in the underlying codeset.
%C
The argument shall be interpreted as a single character wide character whose numeric value is in the underlying codeset.
%d
The argument shall be converted to signed decimal integer notation.
%e
The argument shall be converted to decimal exponential notation in the form "-d.ddddde+dd" (where the applicable average number of digits is written). The minimum number of digits specified after the period is written.
%E
The argument shall be converted to decimal exponential notation in the form "-d.ddddddE+dd" (where the applicable average number of digits is written). The minimum number of digits specified after the period is written.
%f
The argument shall be converted to decimal fractional notation in the form "-ddd.dddddd" (where the minimum number of digits specified after the period is written).
%F
The argument shall be converted to decimal fractional notation in the form "-ddd.dddddd" (where the minimum number of digits specified after the period is written). This is the same as %f.
%g
The argument shall be converted in the same way as for %e unless that would be larger than the value that would be written by %f, in which case it is converted as if by %f. The trailing zeros are removed after the decimal point.
%G
The argument shall be converted in the same way as for %E unless that would be larger than the value that would be written by %f, in which case it is converted as if by %f. The trailing zeros are removed after the decimal point.
%i
The argument shall be converted to signed decimal integer notation.
%n
No argument is converted, but the number of characters written so far is stored into the pointer to variable indicated by the argument. The argument shall be interpreted as an integer pointer.
%p
The argument shall be the address of a thing. The result is implementation-defined.
%s
The argument shall be a string.
%S
The argument shall be a wide-character string.
%u
The argument shall be converted to unsigned decimal integer notation.
%x
The argument shall be converted to unsigned hexadecimal integer notation using standard hexadecimal digits (0-9 and a-f).
%X
The argument shall be converted to unsigned hexadecimal integer notation using standard hexadecimal digits (0-9 and A-F).

A precision may be specified between the '%' and the conversion specification character. If no conversion specification character is supported, the behavior is undefined. Precision values are specified as a decimal integer, preceded by a period ('.'). A period without a decimal number following it is treated as an error. If a decimal number is specified, the behavior depends on the conversion specification, as follows:

a, A, e, E, f, F, g, G
The number of digits to be written after the decimal-point character. If a decimal-point character appears, at least one digit after it is written, even if all the digits are zero. If precision is zero and a decimal-point character appears, the decimal-point character is written without any digits. If precision is not specified, the precision is taken to be enough to represent the value exactly.
d, i, u, X, x
The minimum number of digits to be written in decimal integer representation. Leading zeros are used to pad to this minimum width.
s, b
The maximum number of characters to be written from the argument. If a period is specified without a decimal number, the precision is taken to be zero. If the precision is not specified, the argument is written until the end of the string.

A field width may be specified between the '%' and the conversion specification character. If a decimal number is specified, the value is used as the minimum field width. If the value is smaller than the number of characters produced by the conversion, the field is padded with the fill character. The fill character is space unless the fill character is specified by a preceding 0 flag. If the flag character is '0', the fill character is '0'; otherwise, the fill character is space. A negative field width is treated as an error.

Optional flags can precede the field width or precision:

'-'
The conversion shall be left adjusted on the field width. The default behavior is to pad with spaces on the left.
'+'
The sign character ('+' or '-') shall be placed before any digits or other characters in the conversion. The default behavior is to omit the sign character for unsigned numbers and to place the sign character before any digits for signed numbers.
' '
A leading space character shall be placed before any signed numeric conversion. If the sign character ('+' or '-') is already present, this flag is ignored.
'0'
Leading zeros shall be used to pad the field width. A sign character ('+' or '-') precedes the zeros. This flag is ignored if the '-' flag is also present.

For numeric conversions, the argument operand shall be interpreted as unsuffixed C integer constants, as described by the ISO C standard, with the following extensions:

*
A leading or shall be allowed.
*
If the leading character is a single-quote or double-quote, the value shall be the numeric value in the underlying codeset of the character following the single-quote or double-quote.
*
Suffixed integer constants may be allowed.

If an argument operand cannot be completely converted into an internal value appropriate to the corresponding conversion specification, a diagnostic message shall be written to standard error and the utility shall not exit with a zero exit status, but shall continue processing any remaining operands and shall write the value accumulated at the time the error was detected to standard output.

It shall not be considered an error if an argument operand is not completely used for a b, c, or s conversion.

EXIT STATUS

The following exit values shall be returned:

 0
Successful completion.
>0
An error occurred.

CONSEQUENCES OF ERRORS

Default.

The following sections are informative.

APPLICATION USAGE

The floating-point formatting conversion specifications of printf() are not required because all arithmetic in the shell is integer arithmetic. The awk utility performs floating-point calculations and provides its own printf function. The bc utility can perform arbitrary-precision floating-point arithmetic, but does not provide extensive formatting capabilities. (This printf utility cannot really be used to format bc output; it does not support arbitrary precision.) Implementations are encouraged to support the floating-point conversions as an extension.

Note that this printf utility, like the printf() function defined in the System Interfaces volume of POSIX.1‐2017 on which it is based, makes no special provision for dealing with multi-byte characters when using the %c conversion specification or when a precision is specified in a %b or %s conversion specification. Applications should be extremely cautious using either of these features when there are multi-byte characters in the character set.

No provision is made in this volume of POSIX.1‐2017 which allows field widths and precisions to be specified as '*' since the '*' can be replaced directly in the format operand using shell variable substitution. Implementations can also provide this feature as an extension if they so choose.

Hexadecimal character constants as defined in the ISO C standard are not recognized in the format operand because there is no consistent way to detect the end of the constant. Octal character constants are limited to, at most, three octal digits, but hexadecimal character constants are only terminated by a non-hex-digit character. In the ISO C standard, the "##" concatenation operator can be used to terminate a constant and follow it with a hexadecimal character to be written. In the shell, concatenation occurs before the printf utility has a chance to parse the end of the hexadecimal constant.

The %b conversion specification is not part of the ISO C standard; it has been added here as a portable way to process <backslash>-escapes expanded in string operands as provided by the echo utility. See also the APPLICATION USAGE section of echo for ways to use printf as a replacement for all of the traditional versions of the echo utility.

If an argument cannot be parsed correctly for the corresponding conversion specification, the printf utility is required to report an error. Thus, overflow and extraneous characters at the end of an argument being used for a numeric conversion shall be reported as errors.

EXAMPLES

To alert the user and then print and read a series of prompts:

printf "\aPlease fill in the following: \nName: "
read name
printf "Phone number: "
read phone

To read out a list of right and wrong answers from a file, calculate the percentage correctly, and print them out. The numbers are right-justified and separated by a single <tab>. The percentage is written to one decimal place of accuracy:

while read right wrong ; do
    percent=$(echo "scale=1;($right*100)/($right+$wrong)" | bc)
    printf "%2d right\t%2d wrong\t(%s%%)\n" \
        $right $wrong $percent
done < database_file

The command:

printf "%5d%4d\n" 1 21 321 4321 54321

produces:

    1  21
  3214321
54321   0

Note that the format operand is used three times to print all of the given strings and that a '0' was supplied by printf to satisfy the last %4d conversion specification.

The printf utility is required to notify the user when conversion errors are detected while producing numeric output; thus, the following results would be expected on an implementation with 32-bit twos-complement integers when %d is specified as the format operand:

Standard
Argument Output Diagnostic Output
5a 5 printf: "5a" not completely converted
9999999999 2147483647 printf: "9999999999" arithmetic overflow
-9999999999 -2147483648 printf: "-9999999999" arithmetic overflow
ABC 0 printf: "ABC" expected numeric value

The diagnostic message format is not specified, but these examples convey the type of information that should be reported. Note that the value shown on standard output is what would be expected as the return value from the strtol() function as defined in the System Interfaces volume of POSIX.1‐2017. A similar correspondence exists between %u and strtoul() and %e, %f, and %g (if the implementation supports floating-point conversions) and strtod().

In a locale using the ISO/IEC 646:1991 standard as the underlying codeset, the command:

printf "%d\n" 3 +3 -3 \'3 \"+3 "'-3"

produces:

3
Numeric value of constant 3
3
Numeric value of constant 3
-3
Numeric value of constant -3
51
Numeric value of the character '3' in the ISO/IEC 646:1991 standard codeset
43
Numeric value of the character '+' in the ISO/IEC 646:1991 standard codeset
45
Numeric value of the character '-' in the ISO/IEC 646:1991 standard codeset

Note that in a locale with multi-byte characters, the value of a character is intended to be the value of the equivalent of the wchar_t representation of the character as described in the System Interfaces volume of POSIX.1‐2017.

RATIONALE

The printf utility was added to provide functionality that has historically been provided by echo. However, due to irreconcilable differences in the various versions of echo extant, the version has few special features, leaving those to this new printf utility, which is based on one in the Ninth Edition system.

The EXTENDED DESCRIPTION section almost exactly matches the printf() function in the ISO C standard, although it is described in terms of the file format notation in the Base Definitions volume of POSIX.1‐2017, Chapter 5, File Format Notation.

Earlier versions of this standard specified that arguments for all conversions other than b, c, and s were evaluated in the same way (as C constants, but with stated exceptions). For implementations supporting the floating-point conversions it was not clear whether integer conversions need only accept integer constants and floating-point conversions need only accept floating-point constants, or whether both types of conversions should accept both types of constants. Also by not distinguishing between them, the requirement relating to a leading single-quote or double-quote applied to floating-point conversions even though this provided no useful functionality to applications that was not already available through the integer conversions. The current standard clarifies the situation by specifying that the arguments for floating-point conversions are evaluated as if by strtod(), and the arguments for integer conversions are evaluated as C integer constants, with the special treatment of leading single-quote and double-quote applying only to integer conversions.
