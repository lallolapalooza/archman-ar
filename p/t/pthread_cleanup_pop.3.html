pthread_cleanup_push(3) دليل الوظائف المكتبية pthread_cleanup_push(3)

الاسم

pthread_cleanup_push, pthread_cleanup_pop - دفع وإزالة معالجات إلغاء الخيط

المكتبة

مكتبة خيوط POSIX (libpthread, -lpthread)

الملخص

#include <pthread.h>
void pthread_cleanup_push(typeof(void (void *)) *routine, void *arg);
void pthread_cleanup_pop(int execute);

الوصف

تقوم هذه الوظائف بمعالجة مكدس معالجات تنظيف إلغاء الخيط. معالج التنظيف هو وظيفة يتم تنفيذها تلقائيًا عند إلغاء خيط (أو في ظروف أخرى مختلفة موصوفة أدناه)؛ قد يقوم، على سبيل المثال، بإلغاء قفل قفل لمنحه متاحًا للخيوط الأخرى في العملية.

تقوم وظيفة pthread_cleanup_push() بدفع routine إلى أعلى مكدس معالجات التنظيف. عندما يتم استدعاء routine لاحقًا، سيتم تمرير arg كوسيط لها.

تقوم وظيفة pthread_cleanup_pop() بإزالة المعالج في أعلى مكدس معالجات التنظيف، وتنفيذه اختياريًا إذا كان execute غير صفري.

يتم إزالة معالج تنظيف الإلغاء من المكدس وتنفيذه في الظروف التالية:

•
عند إلغاء خيط، يتم إزالة جميع معالجات التنظيف المكدسة وتنفيذها بترتيب عكسي للترتيب الذي تم دفعها به إلى المكدس.
•
عند انتهاء خيط عن طريق استدعاء pthread_exit(3)، يتم تنفيذ جميع معالجات التنظيف كما هو موضح في النقطة السابقة. (لا يتم استدعاء معالجات التنظيف إذا انتهى الخيط عن طريق إجراء return من وظيفة بدء الخيط.)
•
عندما يستدعي خيط pthread_cleanup_pop() مع وسيط execute غير صفري، يتم إزالة المعالج الأعلى في المكدس وتنفيذه.

يسمح POSIX.1 بتنفيذ pthread_cleanup_push() و pthread_cleanup_pop() كماكرات تتوسع إلى نص يحتوي على '{' و '}' على التوالي. لهذا السبب، يجب على المتصل التأكد من أن استدعاءات هذه الوظائف مقترنة داخل نفس الوظيفة، وفي نفس مستوى التداخل المعجمي. (بمعنى آخر، يتم إنشاء معالج تنظيف فقط أثناء تنفيذ قسم معين من التعليمات البرمجية.)

استدعاء longjmp(3) (siglongjmp(3)) يؤدي إلى نتائج غير محددة إذا تم إجراء أي استدعاء لـ pthread_cleanup_push() أو pthread_cleanup_pop() بدون الاستدعاء المطابق للزوج منذ ملء مخزن القفز بواسطة setjmp(3) (sigsetjmp(3)). وبالمثل، فإن استدعاء longjmp(3) (siglongjmp(3)) من داخل معالج تنظيف يؤدي إلى نتائج غير محددة ما لم يتم ملء مخزن القفز أيضًا بواسطة setjmp(3) (sigsetjmp(3)) داخل المعالج.

قيمة الإرجاع

هذه الوظائف لا تعيد قيمة.

الأخطاء

لا توجد أخطاء.

السمات

لشرح المصطلحات المستخدمة في هذا القسم، راجع attributes(7).

الواجهة السمة القيمة
pthread_cleanup_push (), pthread_cleanup_pop () سلامة الخيط MT-Safe

الإصدارات

على glibc، يتم تنفيذ وظائف pthread_cleanup_push() و pthread_cleanup_pop() كماكرات تتوسع إلى نص يحتوي على '{' و '}' على التوالي. هذا يعني أن المتغيرات المعلنة ضمن نطاق الاستدعاءات المقترنة لهذه الوظائف ستكون مرئية فقط ضمن هذا النطاق.

يقول POSIX.1 أن تأثير استخدام return، break، continue، أو goto للخروج المبكر من كتلة محاطة بـ pthread_cleanup_push() و pthread_cleanup_pop() غير محدد. يجب على التطبيقات المحمولة تجنب القيام بذلك.

أمثلة

يقدم البرنامج أدناه مثالًا بسيطًا على استخدام الوظائف الموصوفة في هذه الصفحة. يقوم البرنامج بإنشاء خيط ينفذ حلقة محاطة بـ pthread_cleanup_push() و pthread_cleanup_pop(). تزيد هذه الحلقة من متغير عام، cnt، مرة واحدة كل ثانية. اعتمادًا على وسائط سطر الأوامر المقدمة، يرسل الخيط الرئيسي طلب إلغاء للخيط الآخر، أو يضبط متغيرًا عامًا يتسبب في خروج الخيط الآخر من حلقته والإنهاء بشكل طبيعي (عن طريق إجراء return).

في جلسة shell التالية، يرسل الخيط الرئيسي طلب إلغاء للخيط الآخر:


$ ./a.out;
New thread started
cnt = 0
cnt = 1
Canceling thread
Called clean-up handler
Thread was canceled; cnt = 0

من أعلاه، نرى أن الخيط تم إلغاؤه، وأن معالج تنظيف الإلغاء تم استدعاؤه وقام بإعادة تعيين قيمة المتغير العام cnt إلى 0.

في التشغيل التالي، يضبط البرنامج الرئيسي متغيرًا عامًا يتسبب في إنهاء الخيط الآخر بشكل طبيعي:


$ ./a.out x;
New thread started
cnt = 0
cnt = 1
Thread terminated normally; cnt = 2

من أعلاه، نرى أن معالج التنظيف لم يتم تنفيذه (لأن cleanup_pop_arg كان 0)، وبالتالي لم يتم إعادة تعيين قيمة cnt.

في التشغيل التالي، يضبط البرنامج الرئيسي متغيرًا عامًا يتسبب في إنهاء الخيط الآخر بشكل طبيعي، ويوفر قيمة غير صفرية لـ cleanup_pop_arg:


$ ./a.out x 1;
New thread started
cnt = 0
cnt = 1
Called clean-up handler
Thread terminated normally; cnt = 0

في أعلاه، نرى أنه على الرغم من عدم إلغاء الخيط، تم تنفيذ معالج التنظيف، لأن الوسيط المعطى لـ pthread_cleanup_pop() كان غير صفري.

مصدر البرنامج

#include <err.h>
#include <errno.h>
#include <pthread.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <unistd.h>
static int done = 0;
static int cleanup_pop_arg = 0;
static int cnt = 0;
static void
cleanup_handler(void *arg)
{
    printf("Called clean-up handler\n");
    cnt = 0;
}
static void *
thread_start(void *arg)
{
    time_t curr;
    printf("New thread started\n");
    pthread_cleanup_push(cleanup_handler, NULL);
    curr = time(NULL);
    while (!done) {
        pthread_testcancel();           /* A cancelation point */
        if (curr < time(NULL)) {
            curr = time(NULL);
            printf("cnt = %d\n", cnt);  /* A cancelation point */
            cnt++;
        }
    }
    pthread_cleanup_pop(cleanup_pop_arg);
    return NULL;
}
int
main(int argc, char *argv[])
{
    pthread_t thr;
    int s;
    void *res;
    s = pthread_create(&thr, NULL, thread_start, NULL);
    if (s != 0)
        errc(EXIT_FAILURE, s, "pthread_create");
    sleep(2);           /* Allow new thread to run a while */
    if (argc > 1) {
        if (argc > 2)
            cleanup_pop_arg = atoi(argv[2]);
        done = 1;
    } else {
        printf("Canceling thread\n");
        s = pthread_cancel(thr);
        if (s != 0)
            errc(EXIT_FAILURE, s, "pthread_cancel");
    }
    s = pthread_join(thr, &res);
    if (s != 0)
        errc(EXIT_FAILURE, s, "pthread_join");
    if (res == PTHREAD_CANCELED)
        printf("Thread was canceled; cnt = %d\n", cnt);
    else
        printf("Thread terminated normally; cnt = %d\n", cnt);
    exit(EXIT_SUCCESS);
}
