pthread_mutexattr_setrobust(3) دليل وظائف المكتبة pthread_mutexattr_setrobust(3)

الاسم

pthread_mutexattr_getrobust, pthread_mutexattr_setrobust - الحصول وتعيين سمة المتانة لكائن سمات القفل

المكتبة

مكتبة خيوط POSIX (libpthread, -lpthread)

الملخص

#include <pthread.h>
int pthread_mutexattr_getrobust(const pthread_mutexattr_t *attr,
                                int *robustness);
int pthread_mutexattr_setrobust(pthread_mutexattr_t *attr,
                                int robustness);
متطلبات سمة الاختبار لـ glibc (انظر feature_test_macros(7)):

pthread_mutexattr_getrobust(), pthread_mutexattr_setrobust():

    _POSIX_C_SOURCE >= 200809L

الوصف

تقوم الدالة pthread_mutexattr_getrobust() بوضع قيمة سمة المتانة لكائن سمات القفل المشار إليه بواسطة attr في *robustness. تقوم الدالة pthread_mutexattr_setrobust() بتعيين قيمة سمة المتانة لكائن سمات القفل المشار إليه بواسطة attr إلى القيمة المحددة في *robustness.

تحدد سمة المتانة سلوك القفل إذا مات الخيط المالك دون إلغاء قفله. القيم التالية صالحة لـ robustness:

PTHREAD_MUTEX_STALLED
هذه هي القيمة الافتراضية لكائن سمات القفل. إذا تم تهيئة قفل بسمة PTHREAD_MUTEX_STALLED ومات مالكه دون إلغاء قفله، يظل القفل مقفلاً بعد ذلك وأي محاولات مستقبلية لاستدعاء pthread_mutex_lock(3) على القفل ستتوقف إلى أجل غير مسمى.
PTHREAD_MUTEX_ROBUST
إذا تم تهيئة قفل بسمة PTHREAD_MUTEX_ROBUST ومات مالكه دون إلغاء قفله، فإن أي محاولات مستقبلية لاستدعاء pthread_mutex_lock(3) على هذا القفل ستنجح وتعيد EOWNERDEAD للإشارة إلى أن المالك الأصلي لم يعد موجودًا وأن القفل في حالة غير متسقة. عادةً بعد أن تعيد EOWNERDEAD، يجب على المالك التالي استدعاء pthread_mutex_consistent(3) على القفل الذي تم الحصول عليه لجعله متسقًا مرة أخرى قبل استخدامه بشكل أكبر.
إذا قام المالك التالي بإلغاء قفل القفل باستخدام pthread_mutex_unlock(3) قبل جعله متسقًا، فإن القفل سيصبح غير قابل للاستخدام بشكل دائم وأي محاولات لاحقة لقفلها باستخدام pthread_mutex_lock(3) ستفشل مع الخطأ ENOTRECOVERABLE. العملية المسموح بها الوحيدة على مثل هذا القفل هي pthread_mutex_destroy(3).
إذا قام المالك التالي بالإنهاء قبل استدعاء pthread_mutex_consistent(3)، فإن عمليات pthread_mutex_lock(3) اللاحقة على هذا القفل ستظل تعيد EOWNERDEAD.

لاحظ أن الوسيط attr للدالتين pthread_mutexattr_getrobust() و pthread_mutexattr_setrobust() يجب أن يشير إلى كائن سمات قفل تم تهيئته بواسطة pthread_mutexattr_init(3)، وإلا فإن السلوك غير محدد.

قيمة الإرجاع

عند النجاح، تعيد هذه الدوال القيمة 0. عند حدوث خطأ، تعيد رقم خطأ موجب.

في تنفيذ glibc، تعيد pthread_mutexattr_getrobust() دائمًا صفر.

الأخطاء

EINVAL
تم تمرير قيمة أخرى غير PTHREAD_MUTEX_STALLED أو PTHREAD_MUTEX_ROBUST إلى pthread_mutexattr_setrobust().

الإصدارات

في تنفيذ Linux، عند استخدام أقفال قوية مشتركة بين العمليات، يتلقى الخيط المنتظر أيضًا إشعار EOWNERDEAD إذا قام مالك قفل قوي بإجراء execve(2) دون إلغاء قفل القفل أولاً. لا تحدد POSIX.1 هذه التفاصيل، ولكن نفس السلوك يحدث أيضًا في بعض التطبيقات الأخرى على الأقل.

المعايير

POSIX.1-2008.

التاريخ

glibc 2.12. POSIX.1-2008.

قبل إضافة pthread_mutexattr_getrobust() و pthread_mutexattr_setrobust() إلى POSIX، عرفت glibc الدوال غير القياسية المكافئة التالية إذا تم تعريف _GNU_SOURCE:

[[deprecated]]
int pthread_mutexattr_getrobust_np(const pthread_mutexattr_t *attr,
                                   int *robustness);
[[deprecated]]
int pthread_mutexattr_setrobust_np(const pthread_mutexattr_t *attr,
                                   int robustness);

وبالمثل، تم تعريف الثوابت PTHREAD_MUTEX_STALLED_NP و PTHREAD_MUTEX_ROBUST_NP.

هذه واجهات برمجة التطبيقات الخاصة بـ GNU، والتي ظهرت لأول مرة في glibc 2.4، أصبحت الآن قديمة ولا ينبغي استخدامها في البرامج الجديدة؛ منذ glibc 2.34 تم تمييز واجهات برمجة التطبيقات هذه على أنها مهملة.

أمثلة

يوضح البرنامج أدناه استخدام سمة المتانة لكائن سمات القفل. في هذا البرنامج، يموت خيط يمسك القفل قبل الأوان دون إلغاء قفله. يحصل الخيط الرئيسي لاحقًا على القفل بنجاح ويحصل على الخطأ EOWNERDEAD، وبعد ذلك يجعله متسقًا.

توضح جلسة shell التالية ما نراه عند تشغيل هذا البرنامج:


$ ./a.out;
[original owner] Setting lock...
[original owner] Locked.  Now exiting without unlocking.
[main] Attempting to lock the robust mutex.
[main] pthread_mutex_lock() returned EOWNERDEAD
[main] Now make the mutex consistent
[main] Mutex is now consistent; unlocking

مصدر البرنامج

#include <err.h>
#include <errno.h>
#include <pthread.h>
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
static pthread_mutex_t mtx;
static void *
original_owner_thread(void *ptr)
{
    printf("[original owner] Setting lock...\n");
    pthread_mutex_lock(&mtx);
    printf("[original owner] Locked.  Now exiting without unlocking.\n");
    pthread_exit(NULL);
}
int
main(void)
{
    pthread_t thr;
    pthread_mutexattr_t attr;
    int s;
    pthread_mutexattr_init(&attr);
    pthread_mutexattr_setrobust(&attr, PTHREAD_MUTEX_ROBUST);
    pthread_mutex_init(&mtx, &attr);
    pthread_create(&thr, NULL, original_owner_thread, NULL);
    sleep(2);
    /* "original_owner_thread" should have exited by now.  */
    printf("[main] Attempting to lock the robust mutex.\n");
    s = pthread_mutex_lock(&mtx);
    if (s == EOWNERDEAD) {
        printf("[main] pthread_mutex_lock() returned EOWNERDEAD\n");
        printf("[main] Now make the mutex consistent\n");
        s = pthread_mutex_consistent(&mtx);
        if (s != 0)
            errc(EXIT_FAILURE, s, "pthread_mutex_consistent");
        printf("[main] Mutex is now consistent; unlocking\n");
        s = pthread_mutex_unlock(&mtx);
        if (s != 0)
            errc(EXIT_FAILURE, s, "pthread_mutex_unlock");
        exit(EXIT_SUCCESS);
    } else if (s == 0) {
        printf("[main] pthread_mutex_lock() unexpectedly succeeded\n");
        exit(EXIT_FAILURE);
    } else {
        printf("[main] pthread_mutex_lock() unexpectedly failed\n");
        errc(EXIT_FAILURE, s, "pthread_mutex_lock");
    }
}
