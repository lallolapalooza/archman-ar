PTHREAD_RWLOCK_DESTROY(3P) دليل مبرمج POSIX PTHREAD_RWLOCK_DESTROY(3P)

مقدمة

هذه الصفحة الدليلية هي جزء من دليل مبرمج POSIX. قد يختلف تطبيق Linux لهذه الواجهة (راجع صفحة دليل Linux المقابلة لتفاصيل سلوك Linux)، أو قد لا تكون الواجهة مطبقة على Linux.

الاسم

pthread_rwlock_destroy, pthread_rwlock_init — تدمير وتهيئة كائن قفل القراءة/الكتابة

الملخص

#include <pthread.h>
int pthread_rwlock_destroy(pthread_rwlock_t *rwlock);
int pthread_rwlock_init(pthread_rwlock_t *restrict rwlock,
    const pthread_rwlockattr_t *restrict attr);
pthread_rwlock_t rwlock = PTHREAD_RWLOCK_INITIALIZER;

الوصف

تقوم الدالة pthread_rwlock_destroy() بتدمير كائن قفل القراءة/الكتابة الذي يشير إليه rwlock وتحرير أي موارد تستخدمها القفل. يكون تأثير الاستخدام اللاحق للقفل غير محدد حتى تتم إعادة تهيئة القفل بواسطة استدعاء آخر لـ pthread_rwlock_init(). قد يتسبب التنفيذ في تعيين الكائن الذي تشير إليه rwlock إلى قيمة غير صالحة بواسطة pthread_rwlock_destroy(). النتائج غير محددة إذا تم استدعاء pthread_rwlock_destroy() عندما يمتلك أي خيط rwlock. محاولة تدمير قفل قراءة/كتابة غير مهيأ يؤدي إلى سلوك غير محدد.

تقوم الدالة pthread_rwlock_init() بتخصيص أي موارد مطلوبة لاستخدام قفل القراءة/الكتابة الذي يشير إليه rwlock وتهيئته إلى حالة غير مقفلة مع السمات التي تشير إليها attr. إذا كان attr NULL، فسيتم استخدام سمات قفل القراءة/الكتابة الافتراضية؛ التأثير هو نفسه كما لو تم تمرير عنوان كائن سمات قفل القراءة/الكتابة الافتراضي. بمجرد تهيئته، يمكن استخدام القفل أي عدد من المرات دون الحاجة إلى إعادة تهيئته. النتائج غير محددة إذا تم استدعاء pthread_rwlock_init() مع تحديد قفل قراءة/كتابة مهيأ بالفعل. النتائج غير محددة إذا تم استخدام قفل قراءة/كتابة دون تهيئته أولاً.

إذا فشلت الدالة pthread_rwlock_init()، فلن يتم تهيئة rwlock وستكون محتويات rwlock غير محددة.

انظر القسم 2.9.9، نسخ كائنات المزامنة والتعيينات البديلة لمزيد من المتطلبات.

في الحالات التي تكون فيها سمات قفل القراءة/الكتابة الافتراضية مناسبة، يمكن استخدام الثابت PTHREAD_RWLOCK_INITIALIZER لتهيئة أقفال القراءة/الكتابة. سيكون التأثير مكافئًا للتهيئة الديناميكية بواسطة استدعاء لـ pthread_rwlock_init() مع تحديد المعلمة attr كـ NULL، باستثناء عدم إجراء أي فحوصات للأخطاء.

السلوك غير محدد إذا كانت القيمة المحددة بواسطة المعلمة attr لـ pthread_rwlock_init() لا تشير إلى كائن سمات قفل قراءة/كتابة مهيأ.

قيمة الإرجاع

إذا نجحت، تعيد الدالتان pthread_rwlock_destroy() و pthread_rwlock_init() الصفر؛ وإلا، يتم إرجاع رقم خطأ للإشارة إلى الخطأ.

الأخطاء

ستفشل الدالة pthread_rwlock_init() في الحالات التالية:

EAGAIN
افتقر النظام إلى الموارد اللازمة (بخلاف الذاكرة) لتهيئة قفل قراءة/كتابة آخر.
ENOMEM
لا توجد ذاكرة كافية لتهيئة قفل القراءة/الكتابة.
EPERM
لا يمتلك المتصل الامتياز لإجراء العملية.

لن تعيد هذه الدوال رمز خطأ [EINTR].

الأقسام التالية إعلامية.

أمثلة

لا يوجد.

استخدام التطبيق

قد تخضع التطبيقات التي تستخدم هذه الدوال المتعلقة بقفل القراءة/الكتابة وانعكاس الأولوية، كما نوقش في مجلد التعريفات الأساسية من POSIX.1-2017، القسم 3.291، انعكاس الأولوية.

التعليل

إذا اكتشف تنفيذ أن القيمة المحددة بواسطة المعلمة rwlock لـ pthread_rwlock_destroy() لا تشير إلى كائن قفل قراءة/كتابة مهيأ، فمن المستحسن أن تفشل الدالة وتُبلغ عن خطأ [EINVAL].

إذا اكتشف تنفيذ أن القيمة المحددة بواسطة المعلمة attr لـ pthread_rwlock_init() لا تشير إلى كائن سمات قفل قراءة/كتابة مهيأ، فمن المستحسن أن تفشل الدالة وتُبلغ عن خطأ [EINVAL].

إذا اكتشف تنفيذ أن القيمة المحددة بواسطة المعلمة rwlock لـ pthread_rwlock_destroy() أو pthread_rwlock_init() تشير إلى كائن قفل قراءة/كتابة مقفل، أو اكتشف أن القيمة المحددة بواسطة المعلمة rwlock لـ pthread_rwlock_init() تشير إلى كائن قفل قراءة/كتابة مهيأ بالفعل، فمن المستحسن أن تفشل الدالة وتُبلغ عن خطأ [EBUSY].

pthread_rwlock_destroy(3p)

pthread_rwlock_destroy - destroy a read-write lock

SYNOPSIS

#include <pthread.h>

int pthread_rwlock_destroy(pthread_rwlock_t *rwlock );

DESCRIPTION

The pthread_rwlock_destroy() function shall destroy the read-write lock referenced by rwlock; the memory associated with the lock becomes available for reuse. At the time of destruction, no thread shall hold a read or write lock. If any thread holds or has attempted to acquire a lock on the read-write lock, the results are undefined.

The pthread_rwlock_destroy() function, if successful, is a no-op regarding the state of any other thread.

After a read-write lock has been destroyed, it shall no longer be used by any thread. If a thread attempts to use a destroyed read-write lock, the results are undefined.

A read-write lock object is destroyed by another thread calling pthread_rwlock_destroy() on it.

RETURN VALUE

On success, the pthread_rwlock_destroy() function shall return 0; otherwise, an error number shall be returned to indicate the error.

ERRORS

The pthread_rwlock_destroy() function may fail if:

[EBUSY]
The value specified by rwlock is currently in use.

These functions shall fail if:

[EINVAL]
The value specified by rwlock is not a valid read-write lock.
[ENOMEM]
Insufficient memory exists to destroy the read-write lock.
