PTHREAD_KEY_CREATE(3P) دليل مبرمج POSIX PTHREAD_KEY_CREATE(3P)

ملحق

صفحة الدليل هذه جزء من دليل مبرمج POSIX. قد يختلف تطبيق Linux لهذا الواجهة (استشر صفحة دليل Linux المقابلة لتفاصيل سلوك Linux)، أو قد لا تكون الواجهة مطبقة على Linux.

الاسم

pthread_key_create — إنشاء مفتاح بيانات خاص بالخيط

الملخص

#include <pthread.h>
int pthread_key_create(pthread_key_t *key, void (*destructor)(void*));

الوصف

تقوم الدالة pthread_key_create() بإنشاء مفتاح بيانات خاص بالخيط مرئي لجميع الخيوط في العملية. قيم المفاتيح التي توفرها pthread_key_create() هي كائنات غير شفافة تستخدم لتحديد موقع البيانات الخاصة بالخيط. على الرغم من أن نفس قيمة المفتاح قد يتم استخدامها بواسطة خيوط مختلفة، إلا أن القيم المرتبطة بالمفتاح بواسطة pthread_setspecific() تتم صيانتها على أساس كل خيط وتستمر طوال عمر الخيط المستدعي.

عند إنشاء المفتاح، ترتبط القيمة NULL بالمفتاح الجديد في جميع الخيوط النشطة. عند إنشاء الخيط، ترتبط القيمة NULL بجميع المفاتيح المحددة في الخيط الجديد.

يمكن ربط دالة تدمير اختيارية بكل قيمة مفتاح. عند خروج الخيط، إذا كانت قيمة المفتاح تحتوي على مؤشر تدمير غير NULL، وكان الخيط يحتوي على قيمة غير NULL مرتبطة بهذا المفتاح، يتم تعيين قيمة المفتاح إلى NULL، ثم يتم استدعاء الدالة المشار إليها مع القيمة المرتبطة سابقًا كوسيط وحيد لها. ترتيب استدعاءات التدمير غير محدد إذا كان هناك أكثر من دالة تدمير واحدة لخيط عند خروجه.

إذا، بعد استدعاء جميع دوال التدمير لجميع القيم غير NULL ذات دوال التدمير المرتبطة، لا تزال هناك بعض القيم غير NULL ذات دوال التدمير، فسيتم تكرار العملية. إذا، بعد ما لا يقل عن {PTHREAD_DESTRUCTOR_ITERATIONS} تكرار لاستدعاءات التدمير للقيم غير NULL المعلقة، لا تزال هناك بعض القيم غير NULL ذات دوال التدمير، فقد تتوقف التطبيقات عن استدعاء دوال التدمير، أو قد تستمر في استدعاء دوال التدمير حتى لا توجد قيم غير NULL ذات دوال التدمير، على الرغم من أن هذا قد يؤدي إلى حلقة لا نهائية.

قيمة الإرجاع

إذا نجحت، تقوم الدالة pthread_key_create() بتخزين قيمة المفتاح المنشأ حديثًا في *key وتعيد صفرًا. وإلا، سيتم إرجاع رقم خطأ للإشارة إلى الخطأ.

الأخطاء

ستفشل الدالة pthread_key_create() إذا:

EAGAIN
افتقد النظام الموارد اللازمة لإنشاء مفتاح بيانات خاص بالخيط آخر، أو تم تجاوز الحد الذي يفرضه النظام على العدد الإجمالي للمفاتيح لكل عملية {PTHREAD_KEYS_MAX}.
ENOMEM
لا توجد ذاكرة كافية لإنشاء المفتاح.

لن تعيد الدالة pthread_key_create() رمز خطأ [EINTR].

الأقسام التالية إعلامية.

أمثلة

يوضح المثال التالي دالة تهيئ مفتاح بيانات خاص بالخيط عند استدعائها لأول مرة، وتربط كائنًا خاصًا بالخيط بكل خيط مستدعي، مع تهيئة هذا الكائن عند الضرورة.

static pthread_key_t key;
static pthread_once_t key_once = PTHREAD_ONCE_INIT;
static void
make_key()
{
    (void) pthread_key_create(&key, NULL);
}
func()
{
    void *ptr;
    (void) pthread_once(&key_once, make_key);
    if ((ptr = pthread_getspecific(key)) == NULL) {
        ptr = malloc(OBJECT_SIZE);
        ...
        (void) pthread_setspecific(key, ptr);
    }
    ...
}

لاحظ أنه يجب تهيئة المفتاح قبل أن يتمكن pthread_getspecific() أو pthread_setspecific() من استخدامه. يمكن استدعاء pthread_key_create() بشكل صريح في روتين تهيئة وحدة، أو يمكن القيام بذلك ضمنيًا عند أول استدعاء لوحدة كما في هذا المثال. أي محاولة لاستخدام المفتاح قبل تهيئته هي خطأ برمجي، مما يجعل الكود أدناه غير صحيح.

static pthread_key_t key;
func()
{
    void *ptr;
   /* المفتاح غير مهيأ!!! هذا لن يعمل!!! */
    if ((ptr = pthread_getspecific(key)) == NULL &&
        pthread_setspecific(key, NULL) != 0) {
        pthread_key_create(&key, NULL);
        ...
    }
}

التعليل

دوال التدمير

عادةً، تكون القيمة المرتبطة بالمفتاح نيابة عن خيط معين مؤشرًا إلى مساحة تم تخصيصها ديناميكيًا نيابة عن الخيط المستدعي. تهدف دوال التدمير المحددة مع pthread_key_create() إلى استخدامها لتحرير هذه المساحة عند خروج الخيط. لا يمكن استخدام معالجات تنظيف إلغاء الخيط لهذا الغرض لأن البيانات الخاصة بالخيط قد تستمر خارج النطاق المعجمي الذي تعمل فيه معالجات تنظيف الإلغاء.

إذا كانت القيمة المرتبطة بمفتاح تحتاج إلى تحديث أثناء عمر الخيط، فقد يكون من الضروري تحرير المساحة المرتبطة بالقيمة القديمة قبل ربط القيمة الجديدة. على الرغم من أن الدالة pthread_setspecific() يمكن أن تفعل ذلك تلقائيًا، إلا أن هذه الميزة ليست مطلوبة بشكل متكرر بما يكفي لتبرير التعقيد الإضافي. بدلاً من ذلك، يكون المبرمج مسؤولاً عن تحرير المساحة القديمة:

pthread_getspecific(key, &old);
new = allocate();
destructor(old);
pthread_setspecific(key, new);
ملاحظة:
قد يتسرب التخزين في المثال أعلاه إذا تم تشغيله مع تمكين الإلغاء غير المتزامن. لا تحدث مثل هذه المشاكل في حالة الإلغاء الافتراضية إذا لم تحدث نقاط إلغاء بين الحصول على القيمة وتعيينها.

لا يوجد مفهوم لدالة آمنة للتدمير. إذا لم تقم التطبيقات باستدعاء pthread_exit() من معالج إشارة، أو إذا قامت بحظر أي إشارة قد يستدعي معالجها pthread_exit() أثناء استدعاء دوال غير آمنة للإلغاء، فيمكن استدعاء جميع الدوال بأمان من دوال التدمير.

إنشاء مفتاح بيانات غير متكرر

كانت هناك طلبات لجعل pthread_key_create() متكررة فيما يتعلق بمعلمة key المعطاة. سيسمح هذا للتطبيقات باستدعاء pthread_key_create() عدة مرات لمثيل key معين وسيضمن أنه سيتم إنشاء مفتاح واحد فقط. يتطلب القيام بذلك تهيئة قيمة المفتاح مسبقًا (ربما وقت الترجمة) إلى قيمة فارغة معروفة ويتطلب إجراء استبعاد متبادل ضمني بناءً على عنوان ومحتويات معلمة key لضمان إنشاء مفتاح واحد فقط.

للأسف، لن يقتصر الاستبعاد المتبادل الضمني على pthread_key_create() فقط. في العديد من التطبيقات، سيتعين أيضًا إجراء استبعاد متبادل ضمني بواسطة pthread_getspecific() و pthread_setspecific() لحماية ضد استخدام قيم المفاتيح التي تم تخزينها بشكل غير كامل أو غير مرئية بعد. يمكن أن يؤدي هذا إلى زيادة تكلفة العمليات المهمة بشكل كبير، وخاصة pthread_getspecific().

لذلك، تم رفض هذا الاقتراح. لا تقوم الدالة pthread_key_create() بأي تزامن ضمني. تقع على عاتق المبرمج مسؤولية التأكد من استدعائها مرة واحدة فقط لكل مفتاح قبل استخدام المفتاح. يمكن استخدام العديد من الآليات البسيطة بالفعل لتحقيق ذلك، بما في ذلك استدعاء وظائف تهيئة الوحدات الصريحة، واستخدام الأقفال (mutexes)، واستخدام pthread_once(). هذا لا يضع عبئًا كبيرًا على المبرمج، ولا يقدم آلية تزامن ضمنية ad hoc مربكة محتملة، ويسمح بشكل محتمل بأن تكون عمليات البيانات الخاصة بالخيط المستخدمة بشكل شائع أكثر كفاءة.
