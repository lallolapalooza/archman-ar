pt-kill(1p)

الحزمة: percona-toolkit

التراخيص: GPL

--defaults-file
short form: -F; type: string

فقط اقرأ خيارات mysql من الملف المحدد. يجب عليك تقديم مسار مطلق.

--filter
type: string

تجاهل الأحداث التي لا تعيد فيها كود Perl هذا قيمة صحيحة.

هذا الخيار هو سلسلة من كود Perl أو ملف يحتوي على كود Perl يتم تجميعه في روتين فرعي بحجة واحدة: $event. هذا هو hashref. إذا كانت القيمة المعطاة ملفًا قابلاً للقراءة، فإن pt-kill يقرأ الملف بأكمله ويستخدم محتوياته ككود. يجب ألا يحتوي الملف على سطر shebang (#!/usr/bin/perl).

إذا أعاد الكود قيمة صحيحة، تستمر سلسلة الاستدعاءات؛ وإلا فإنها تنتهي. الكود هو آخر عبارة في الروتين الفرعي بخلاف "return $event". قالب الروتين الفرعي هو:

sub { $event = shift; filter && return $event; }

يتم تغليف عوامل التصفية المعطاة في سطر الأوامر داخل أقواس مثل "( filter )". بالنسبة لعوامل التصفية المعقدة ومتعددة الأسطر، يجب وضع الكود داخل ملف حتى لا يتم تغليفه داخل أقواس. في كلتا الحالتين، يجب أن ينتج عامل التصفية كودًا صالحًا نحويًا بالنظر إلى القالب. على سبيل المثال، لن يكون فرع if-else المعطى في سطر الأوامر صالحًا:

--filter 'if () { } else { }'  # WRONG

نظرًا لأنه يتم توفيره في سطر الأوامر، سيتم تغليف فرع if-else داخل أقواس وهذا ليس صالحًا نحويًا. لذلك، لتحقيق شيء أكثر تعقيدًا مثل هذا سيتطلب وضع الكود في ملف، على سبيل المثال filter.txt:

my $event_ok; if (...) { $event_ok=1; } else { $event_ok=0; } $event_ok

ثم حدد "--filter filter.txt" لقراءة الكود من filter.txt.

إذا لم يتمكن كود عامل التصفية من التجميع، فسيؤدي pt-kill إلى فشل مع حدوث خطأ. إذا تم تجميع كود عامل التصفية، فقد لا يزال يحدث خطأ في وقت التشغيل إذا حاول الكود القيام بشيء خاطئ (مثل مطابقة نمط لقيمة غير معرفة). لا يوفر pt-kill أي ضمانات، لذا اكتب الكود بعناية!

يجوز للكود أن يكون له آثار جانبية (لتغيير $event).

--group-by
type: string

تطبيق التطابقات على كل فئة من الاستعلامات المجمعة بواسطة عمود SHOW PROCESSLIST هذا. بالإضافة إلى الأعمدة الأساسية لـ SHOW PROCESSLIST (user، host، command، state، إلخ)، يمكن مطابقة الاستعلامات بواسطة "fingerprint" الذي يجرد استعلام SQL في عمود "Info".

بشكل افتراضي، لا يتم تجميع الاستعلامات، لذا تنطبق التطابقات والإجراءات على جميع الاستعلامات. يسمح التجميع للتطابقات والإجراءات بتطبيقها على فئات من الاستعلامات المتشابهة، إذا تطابقت أي استعلامات في الفئة.

على سبيل المثال، يتطلب اكتشاف الازدحام في ذاكرة التخزين المؤقت (انظر "all-but-oldest" تحت "--victims" لشرح هذا المصطلح) تجميع الاستعلامات حسب السمة "arg". هذا ينشئ فئات من الاستعلامات المتطابقة (مجردة من التعليقات). لذلك، يتم تجميع الاستعلامين "SELECT c FROM t WHERE id=1" و "SELECT c FROM t WHERE id=1" في نفس الفئة، ولكن الاستعلام "SELECT c FROM t WHERE id=3" ليس مطابقًا للاستعلامين الأولين، لذا يتم تجميعه في فئة أخرى. ثم عند تحديد "--victims" "all-but-oldest"، يتم إنهاء كل استعلام باستثناء أقدم استعلام في كل فئة لكل فئة استعلامات تطابق معايير المطابقة.

--help
عرض المساعدة والخروج.
--host
short form: -h; type: string; default: localhost

الاتصال بالمضيف.

--interval
type: time

كم مرة للتحقق من الاستعلامات التي سيتم إنهاؤها. إذا لم يتم تحديد "--busy-time"، فإن الفاصل الافتراضي هو 30 ثانية. بخلاف ذلك، يكون الافتراضي نصف مدة "--busy-time". إذا تم تحديد كل من "--interval" و "--busy-time"، فسيتم استخدام قيمة "--interval" الصريحة.

انظر أيضًا "--run-time".

--log
type: string

طباعة جميع المخرجات إلى هذا الملف عند تشغيل البرنامج كخدمة.

--log-dsn
type: DSN

تخزين كل استعلام تم إنهاؤه في DSN هذا.

يحدد الوسيط جدولاً لتخزين جميع الاستعلامات التي تم إنهاؤها. يجب أن يحتوي DSN الذي تم تمريره على خيارات قاعدة البيانات (D) والجدول (t). يجب أن يحتوي الجدول على الأعمدة التالية على الأقل. يمكنك إضافة المزيد من الأعمدة لأغراضك الخاصة، ولكن لن يتم استخدامها بواسطة pt-kill. يستخدم تعريف الجدول التالي CREATE TABLE أيضًا لـ "--create-log-table". MAGIC_create_log_table:

CREATE TABLE kill_log (
   kill_id     int(10) unsigned NOT NULL AUTO_INCREMENT,
   server_id   bigint(4) NOT NULL DEFAULT '0',
   timestamp   DATETIME,
   reason      TEXT,
   kill_error  TEXT,
   Id          bigint(4) NOT NULL DEFAULT '0',
   User        varchar(16) NOT NULL DEFAULT '',
   Host        varchar(64) NOT NULL DEFAULT '',
   db          varchar(64) DEFAULT NULL,
   Command     varchar(16) NOT NULL DEFAULT '',
   Time        int(7) NOT NULL DEFAULT '0',
   State       varchar(64) DEFAULT NULL,
   Info        longtext,
   Time_ms     bigint(21) DEFAULT '0', # NOTE, TODO: currently not used
   PRIMARY KEY (kill_id)
) DEFAULT CHARSET=utf8
--json
طباعة الاستعلامات التي تم إنهاؤها بتنسيق JSON، يجب استخدامه مع "--print". على سبيل المثال: 
--print --json

لن يتم عرض الإخراج النصي العادي المعتاد من "--print".

سيكون إخراج JSON بالتنسيق التالي:

{
   "Command": "Query",
   "Host": "10.0.0.1:9999",
   "Id": 1234,
   "Info": "SELECT SLEEP(5)",
   "State": "User sleep",
   "Time": 10,
   "User": "my_user",
   "Db": "my_db",
   "Kill_Error": "",
   "Digest": "58A43A7DA83F58C1",
   "Reason": "Exceeds busy time\nQuery matches Command spec",
   "Timestamp": "2022-01-01T00:00:00"
}
--json-fields
type: string

حدد قائمة بالأزواج الإضافية للمفتاح:القيمة لتضمينها في إخراج JSON عند استخدام "--json"، يجب تحديد قيمة هذا المعلمة بالتنسيق التالي:

--json-fields key1:value1,key2:value2

سيتم تضمين أي حقول محددة باستخدام "--json-fields" في إخراج "--json".

على سبيل المثال:

--print --json --json-fields hostname:$(hostname),tag:my_tag

سيؤدي إلى كتابة سجلات JSON إلى "kill_log.json" باستخدام هذا التنسيق:

{
   "Command": "Query",
   "Host": "10.0.0.1:9999",
   "Id": 1234,
   "Info": "SELECT SLEEP(5)",
   "State": "User sleep",
   "Time": 10,
   "User": "my_user",
   "Db": "my_db",
   "Kill_Error": "",
   "Digest": "58A43A7DA83F58C1",
   "Reason": "Exceeds busy time\nQuery matches Command spec",
   "Timestamp": "2022-01-01T00:00:00",
   "hostname": "my_host",
   "tag": "my_tag"
}
--password
short form: -p; type: string

كلمة المرور المستخدمة عند الاتصال. إذا كانت كلمة المرور تحتوي على فواصل، فيجب تهريبها بشرطة مائلة للخلف: "exam\,ple"

--pid
type: string

إنشاء ملف PID المحدد. لن يبدأ الأداة إذا كان ملف PID موجودًا بالفعل وكانت PID التي يحتوي عليها مختلفة عن PID الحالية. ومع ذلك، إذا كان ملف PID موجودًا ولم تعد PID التي يحتوي عليها قيد التشغيل، فستقوم الأداة بالكتابة فوق ملف PID باستخدام PID الحالية. يتم إزالة ملف PID تلقائيًا عند خروج الأداة.

--port
short form: -P; type: int

رقم المنفذ المستخدم للاتصال.

--query-id
طباعة معرف الاستعلام الذي تم إنهاؤه للتو. هذا يعادل إخراج "ID" من pt-query-digest. هذا يسمح بالإسناد المرجعي لمخرجات كلا الأداتين.

مثال:

Query ID 0xE9800998ECF8427E

لاحظ أن هذا هو هضم (أو تجزئة) لـ "بصمة" الاستعلام، لذلك سيكون للاستعلامات من نفس الشكل ولكن بقيم مختلفة نفس المعرف. انظر pt-query-digest لمزيد من المعلومات.

--rds
يشير إلى أن المثيل المعني موجود على Amazon RDS. بشكل افتراضي، يقوم pt-kill بتشغيل أمر MySQL "kill" لـ "--kill" و "kill query" "--kill-query". في RDS، هذان الأمران غير متوفرين ويتم استبدالهما باستدعاءات الوظائف. يعدل هذا الخيار "--kill" لاستخدام "CALL mysql.rds_kill(thread-id)" بدلاً من ذلك و "--kill-query" لاستخدام "CALL mysql.rds_kill_query(thread-id)"
--run-time
type: time

كم من الوقت للتشغيل قبل الخروج. بشكل افتراضي، يعمل pt-kill إلى الأبد، أو حتى يتم إنهاء عمليته أو إيقافه عن طريق إنشاء ملف "--sentinel". إذا تم تحديد هذا الخيار، يعمل pt-kill للمدة المحددة وينام "--interval" ثوانٍ بين كل فحص لـ PROCESSLIST.

--sentinel
type: string; default: /tmp/pt-kill-sentinel

اخرج إذا كان هذا الملف موجودًا.

سيؤدي وجود الملف المحدد بواسطة "--sentinel" إلى إنهاء جميع النسخ النشطة من pt-kill. قد تجد هذا مفيدًا لإيقاف وظائف cron بأمان إذا لزم الأمر. انظر أيضًا "--stop".

--set-vars
type: Array

قم بتعيين متغيرات MySQL في هذه القائمة المفصولة بفواصل من أزواج "variable=value".

بشكل افتراضي، يقوم الأداة بتعيين:

wait_timeout=10000

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.
