pt-mysql-summary(1p)

الحزمة: percona-toolkit

التراخيص: GPL

PT-MYSQL-SUMMARY(1) وثائق Perl مساهمة من المستخدم PT-MYSQL-SUMMARY(1)

الاسم

pt-mysql-summary - تلخيص معلومات MySQL بشكل لطيف.

الملخص

الاستخدام: pt-mysql-summary [خيارات]

يقوم pt-mysql-summary بتلخيص حالة وخادم قاعدة بيانات MySQL وتكوينه بشكل مناسب لتتعرف عليه بنظرة واحدة. إنه ليس أداة ضبط أو تشخيص. ينتج تقريرًا يسهل مقارنته ويمكن لصقه في رسائل البريد الإلكتروني دون فقدان التنسيق. يجب أن يعمل بشكل جيد على أي أنظمة UNIX حديثة.

المخاطر

Percona Toolkit ناضجة، تم اختبارها في العالم الواقعي، وتم اختبارها جيدًا، ولكن جميع أدوات قواعد البيانات يمكن أن تشكل خطرًا على النظام وخادم قاعدة البيانات. قبل استخدام هذه الأداة، يرجى:

  • اقرأ وثائق الأداة
  • راجع "الأخطاء" المعروفة للأداة
  • اختبر الأداة على خادم غير إنتاجي
  • قم بعمل نسخة احتياطية من خادم الإنتاج الخاص بك وتحقق من النسخ الاحتياطية

الوصف

يعمل pt-mysql-summary عن طريق الاتصال بخادم قاعدة بيانات MySQL والاستعلام منه للحصول على معلومات الحالة والتكوين. يقوم بحفظ هذه البيانات في ملفات في دليل مؤقت، ثم يقوم بتنسيقها بشكل أنيق باستخدام awk ولغات البرمجة النصية الأخرى.

للاستخدام، قم بتنفيذه ببساطة. اختياريًا، أضف شرطة مزدوجة ثم نفس خيارات سطر الأوامر التي ستستخدمها للاتصال بـ MySQL، مثل ما يلي:

pt-mysql-summary --user=root

تتفاعل الأداة بشكل طفيف مع الخادم الذي تعمل عليه. تفترض أنك ستقوم بتشغيلها على نفس الخادم الذي تقوم بفحصه، وبالتالي تفترض أنها ستتمكن من العثور على ملف التكوين my.cnf، على سبيل المثال. ومع ذلك، يجب أن تتعامل بشكل جيد إذا لم يكن هذا هو الحال. لاحظ، مع ذلك، أن مخرجاتها لا تشير إلى أي معلومات تأتي من قاعدة بيانات MySQL وأيها تأتي من نظام التشغيل المضيف، لذلك من الممكن إنشاء مخرجات مربكة إذا قمت بتشغيل الأداة على خادم واحد والاتصال بخادم قاعدة بيانات MySQL يعمل على خادم آخر.

الإخراج

تم تقريب العديد من مخرجات هذه الأداة عمدًا لإظهار حجمها ولكن ليس التفاصيل الدقيقة. وهذا ما يسمى بالتقريب الضبابي. الفكرة هي أنه لا يهم ما إذا كان الخادم يعمل 918 استعلامًا في الثانية أو 921 استعلامًا في الثانية؛ هذا الاختلاف الصغير غير مهم، ويجعل من الصعب مقارنة المخرجات بالخوادم الأخرى. التقريب الضبابي يقوم بالتقريب بزيادات أكبر كلما زاد المدخل. يبدأ بالتقريب إلى أقرب 5، ثم أقرب 10، أقرب 25، ثم يتكرر بعامل أكبر بـ 10 (50، 100، 250)، وما إلى ذلك، مع نمو المدخلات.

فيما يلي عينة من التقرير الذي تنتجه الأداة:

# Percona Toolkit MySQL Summary Report #######################
              System time | 2012-03-30 18:46:05 UTC
                            (local TZ: EDT -0400)
# Instances ##################################################
  Port  Data Directory             Nice OOM Socket
  ===== ========================== ==== === ======
  12345 /tmp/12345/data            0    0   /tmp/12345.sock
  12346 /tmp/12346/data            0    0   /tmp/12346.sock
  12347 /tmp/12347/data            0    0   /tmp/12347.sock

يعرض القسمان الأولان الخادم الذي تم إنشاء التقرير عليه وخوادم MySQL التي تعمل على الخادم. يتم اكتشاف ذلك من مخرجات "ps" ولا يكتشف دائمًا جميع الخوادم والمعلمات، ولكنه غالبًا ما يعمل بشكل جيد. من هذه النقطة فصاعدًا، سيركز التقرير على خادم MySQL واحد، على الرغم من أنه قد تظهر عدة خوادم في الفقرة أعلاه.

# Report On Port 12345 #######################################
                     User | msandbox@%
                     Time | 2012-03-30 14:46:05 (EDT)
                 Hostname | localhost.localdomain
                  Version | 5.5.20-log MySQL Community Server (GPL)
                 Built On | linux2.6 i686
                  Started | 2012-03-28 23:33 (up 1+15:12:09)
                Databases | 4
                  Datadir | /tmp/12345/data/
                Processes | 2 connected, 2 running
              Replication | Is not a slave, has 1 slaves connected
                  Pidfile | /tmp/12345/data/12345.pid (exists)

هذا القسم هو ملخص سريع لخادم MySQL: الإصدار، وقت التشغيل، وغيرها من المعلمات الأساسية جدًا. يتم إنشاء إخراج الوقت من خادم MySQL، على عكس تاريخ ووقت النظام المطبوعين سابقًا، بحيث يمكنك معرفة ما إذا كانت أوقات قاعدة البيانات ونظام التشغيل متطابقة.

# Processlist ################################################
  Command                        COUNT(*) Working SUM(Time) MAX(Time)
  ------------------------------ -------- ------- --------- ---------
  Binlog Dump                           1       1    150000    150000
  Query                                 1       1         0         0
  User                           COUNT(*) Working SUM(Time) MAX(Time)
  ------------------------------ -------- ------- --------- ---------
  msandbox                              2       2    150000    150000
  Host                           COUNT(*) Working SUM(Time) MAX(Time)
  ------------------------------ -------- ------- --------- ---------
  localhost                             2       2    150000    150000
  db                             COUNT(*) Working SUM(Time) MAX(Time)
  ------------------------------ -------- ------- --------- ---------
  NULL                                  2       2    150000    150000
  State                          COUNT(*) Working SUM(Time) MAX(Time)
  ------------------------------ -------- ------- --------- ---------
  Master has sent all binlog to         1       1    150000    150000
  NULL                                  1       1         0         0

هذا القسم هو ملخص لمخرجات SHOW PROCESSLIST. كل قسم فرعي مجمع حسب عنصر مختلف، والذي يظهر كرأس العمود الأول. عند التلخيص حسب الأمر، يتم تضمين كل صف في SHOW PROCESSLIST، ولكن بخلاف ذلك، يتم استبعاد الصفوف التي يكون أمرها Sleep من أعمدة SUM و MAX، حتى لا تؤثر بشكل كبير على الأرقام. في المثال المعروض، الخادم خامد باستثناء هذه الأداة نفسها، ونسخة متصلة واحدة، تقوم بتنفيذ Binlog Dump.

الأعمدة هي عدد الصفوف المتضمنة، وعددها ليس في حالة Sleep، ومجموع عمود Time، والحد الأقصى لعمود Time. يتم تقريب الأرقام ضبابيًا.

# Status Counters (Wait 10 Seconds) ##########################
Variable                            Per day  Per second     10 secs
Binlog_cache_disk_use                     4
Binlog_cache_use                         80
Bytes_received                     15000000         175         200
Bytes_sent                     15000000         175        2000
Com_admin_commands                        1
...................(many lines omitted)............................
Threads_created                          40                       1
Uptime                                90000           1           1

يعرض هذا القسم عدادات محددة من لقطتين لـ SHOW GLOBAL STATUS، تم جمعهما بفارق حوالي 10 ثوانٍ وتم تقريبهما ضبابيًا. يتضمن فقط العناصر التي تزيد العدادات؛ لا يتضمن أرقامًا مطلقة مثل متغير حالة Threads_running، الذي يمثل قيمة حالية، بدلاً من عدد مجمع بمرور الوقت.

العمود الأول هو اسم المتغير، والعمود الثاني هو العداد من اللقطة الأولى مقسومًا على 86400 (عدد الثواني في اليوم)، بحيث يمكنك رؤية حجم تغيير العداد في اليوم. 86400 يقرب ضبابيًا إلى 90000، لذلك يجب أن يكون عداد Uptime دائمًا حوالي 90000.

العمود الثالث هو القيمة من اللقطة الأولى، مقسومة على Uptime ثم مقربة ضبابيًا، لذا فهي تمثل تقريبًا مدى سرعة نمو العداد في الثانية الواحدة على مدار وقت تشغيل الخادم.

العمود الرابع هو الفرق التزايدي من اللقطة الأولى والثانية، مقسومًا على الفرق في وقت التشغيل ثم مقربًا ضبابيًا. لذلك، يوضح مدى سرعة نمو العداد في الثانية الواحدة في وقت إنشاء التقرير.

# Table cache ################################################
                     Size | 400
                    Usage | 15%

يعرض هذا القسم حجم ذاكرة التخزين المؤقت للجداول، متبوعًا بنسبة ذاكرة التخزين المؤقت للجداول المستخدمة. يتم تقريب الاستخدام ضبابيًا.

OPTIONS

--character-sets
type: boolean; default: false

Show character set information.

--config
type: string

Read this option file if it is missing. If the file is present, no other option files are read.

--defaults-file
type: string

Use only the given MySQL option file.

--dry-run
type: boolean; default: false

Show what would be done, but do not do it.

--help
type: boolean; default: false

Show help and exit.

--host
short form: -h; type: string

Connect to host.

--ignore-checking
type: string

Ignore given checks. The following values are supported:

  • character-set - ignore character set check
  • collation - ignore collation check
  • db-privileges - ignore database privileges check
  • privileges - ignore all privileges check

For example, use "--ignore-checking=privileges,db-privileges" to ignore privileges checks.

--information-schema
type: boolean; default: false

Use the Information Schema to retrieve table information. Note that some Information Schema tables can be slow.

--password
short form: -p; type: string

Password to use when connecting. If password contains commas they must be escaped with a backslash: "exam\,ple"

--port
short form: -P; type: int

Port number to use for connection.

--read-samples
type: string

Create a report from the files found in this directory.

--save-samples
type: string

Save the data files used to generate the summary in this directory.

--sleep
type: int; default: 10

Seconds to sleep when gathering status counters.

--socket
short form: -S; type: string

Socket file to use for connection.

--user
short form: -u; type: string

User for login if not current user.

--version
Print tool's version and exit.

ENVIRONMENT

This tool does not use any environment variables.

SYSTEM REQUIREMENTS

This tool requires Bash v3 or newer, Perl 5.8 or newer, and binutils. These are generally already provided by most distributions. On BSD systems, it may require a mounted procfs.
