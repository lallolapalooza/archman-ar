pt-fk-error-logger(1p)

الحزمة: percona-toolkit

التراخيص: GPL

PT-FK-ERROR-LOGGER(1) توثيق Perl مساهمة المستخدم PT-FK-ERROR-LOGGER(1)

الاسم

pt-fk-error-logger - تسجيل أخطاء المفاتيح الخارجية لـ MySQL.

الملخص

الاستخدام: pt-fk-error-logger [خيارات] [DSN]

يسجل pt-fk-error-logger معلومات حول أخطاء المفاتيح الخارجية على DSN المحدد. تتم طباعة المعلومات إلى "STDOUT"، ويمكن أيضًا حفظها في جدول عن طريق تحديد "--dest". تعمل الأداة إلى الأبد ما لم يتم تحديد "--run-time" أو "--iterations".

طباعة أخطاء المفاتيح الخارجية على المضيف host1:

pt-fk-error-logger h=host1

طباعة أخطاء المفاتيح الخارجية على المضيف host1 مرة واحدة ثم الخروج:

pt-fk-error-logger h=host1 --iterations 1

حفظ أخطاء المفاتيح الخارجية على المضيف host1 في percona_schema.fke على المضيف host2:

pt-fk-error-logger h=host1 --dest h=host2,D=percona_schema,t=fke

المخاطر

Percona Toolkit ناضج، مثبت في العالم الحقيقي، وتم اختباره جيدًا، ولكن جميع أدوات قاعدة البيانات يمكن أن تشكل خطرًا على النظام وخادم قاعدة البيانات. قبل استخدام هذه الأداة، يرجى:

  • قراءة وثائق الأداة
  • مراجعة "الأخطاء" المعروفة للأداة
  • اختبار الأداة على خادم غير إنتاجي
  • عمل نسخة احتياطية من خادم الإنتاج الخاص بك والتحقق من النسخ الاحتياطية

الوصف

تطبع pt-fk-error-logger أو تحفظ نص أخطاء المفاتيح الخارجية من "SHOW INNODB STATUS". لا يتم تحليل الأخطاء أو تفسيرها بأي شكل من الأشكال. يتم التعرف على أخطاء المفاتيح الخارجية بشكل فريد بواسطة الطابع الزمني الخاص بها. يتم طباعة أو حفظ الأخطاء الجديدة (الأحدث) فقط.

افتراضيًا، تعمل الأداة إلى الأبد، وتتحقق كل "--interval" ثانية من أخطاء المفاتيح الخارجية الجديدة. حدد "--run-time" و/أو "--iterations" لتحديد مدة عمل الأداة.

المخرجات

يتم طباعة نص خطأ المفتاح الخارجي من "SHOW ENGINE INNODB STATUS" إلى "STDOUT"، ما لم يتم تحديد "--quiet". تتم طباعة الأخطاء والتحذيرات إلى "STDERR".

الخيارات

تقبل هذه الأداة وسائط سطر أوامر إضافية. ارجع إلى "الملخص" ومعلومات الاستخدام للتفاصيل.

--ask-pass
يطالب بكلمة مرور عند الاتصال بـ MySQL.
--charset
الشكل المختصر: -A؛ النوع: string

مجموعة الأحرف الافتراضية. إذا كانت القيمة utf8، فإنه يضبط وضع binmode في STDOUT على utf8، ويمرر الخيار mysql_enable_utf8 إلى DBD::mysql، ويقوم بتشغيل SET NAMES UTF8 بعد الاتصال بـ MySQL. أي قيمة أخرى تضبط وضع binmode في STDOUT بدون طبقة utf8، وتقوم بتشغيل SET NAMES بعد الاتصال بـ MySQL.

--config
النوع: Array

قراءة هذه القائمة المفصولة بفواصل من ملفات التكوين؛ إذا تم تحديدها، فيجب أن تكون هذا هو الخيار الأول في سطر الأوامر.

--daemonize
إنشاء عملية فرعية في الخلفية وفصلها عن الصدفة. أنظمة التشغيل POSIX فقط.
--database
الشكل المختصر: -D؛ النوع: string

الاتصال بقاعدة البيانات هذه.

--defaults-file
الشكل المختصر: -F؛ النوع: string

قراءة خيارات MySQL فقط من الملف المحدد. يجب عليك توفير مسار مطلق.

--dest
النوع: DSN

حفظ أخطاء المفاتيح الخارجية في هذا الجدول. يجب أن يحدد DSN قاعدة بيانات (D) وجدول (t).

يتم استلهام قيم DSN المفقودة من DSN الذي تتم مراقبته، لذلك يمكنك حذف معظم القيم إذا كنت تحفظ أخطاء المفاتيح الخارجية على نفس المضيف.

يُقترح الجدول التالي:

CREATE TABLE foreign_key_errors (
  ts datetime NOT NULL,
  error text NOT NULL,
  PRIMARY KEY (ts)
)

المعلومات الوحيدة المحفوظة هي الطابع الزمني ونص خطأ المفتاح الخارجي.

--help
إظهار المساعدة والخروج.
--host
الشكل المختصر: -h؛ النوع: string

الاتصال بالمضيف.

--interval
النوع: time؛ الافتراضي: 30

كم مرة للتحقق من أخطاء المفاتيح الخارجية.

--iterations
النوع: int

كم عدد المرات للتحقق من أخطاء المفاتيح الخارجية. افتراضيًا، هذا الخيار غير محدد مما يعني عددًا لا نهائيًا من التكرارات. تخرج الأداة دائمًا بالنسبة لـ "--run-time"، بغض النظر عن القيمة المحددة لهذا الخيار. على سبيل المثال، ستخرج الأداة بعد دقيقة واحدة مع "--run-time 1m --iterations 4 --interval 30" لأن 4 تكرارات بفواصل زمنية مدتها 30 ثانية ستستغرق دقيقتين، أطول من وقت التشغيل البالغ دقيقة واحدة.

--log
النوع: string

طباعة جميع المخرجات إلى هذا الملف عند التشغيل كخدمة.

--password
الشكل المختصر: -p؛ النوع: string

كلمة المرور المستخدمة عند الاتصال. إذا كانت كلمة المرور تحتوي على فواصل، فيجب الهروب منها بشرطة مائلة عكسية: "exam\,ple"

--pid
النوع: string

إنشاء ملف PID المحدد. لن تبدأ الأداة إذا كان ملف PID موجودًا وكان PID الذي يحتويه مختلفًا عن PID الحالي. ومع ذلك، إذا كان ملف PID موجودًا وكان PID الذي يحتويه لم يعد قيد التشغيل، فستقوم الأداة بالكتابة فوق ملف PID بـ PID الحالي. يتم إزالة ملف PID تلقائيًا عند خروج الأداة.

--port
الشكل المختصر: -P؛ النوع: int

رقم المنفذ المستخدم للاتصال.

--quiet
لا تطبع أخطاء المفاتيح الخارجية؛ اطبع الأخطاء والتحذيرات فقط إلى "STDERR".
--run-time
النوع: time

كم من الوقت سيتم تشغيل الأداة قبل الخروج. افتراضيًا، تعمل الأداة إلى الأبد.

--set-vars
النوع: Array

تعيين متغيرات MySQL في هذه القائمة المفصولة بفواصل من أزواج "variable=value".

افتراضيًا، تقوم الأداة بتعيين:

wait_timeout=10000

تتجاوز المتغيرات المحددة في سطر الأوامر هذه القيم الافتراضية. على سبيل المثال، تحديد "--set-vars wait_timeout=500" يتجاوز القيمة الافتراضية 10000.

تطبع الأداة تحذيرًا وتستمر إذا تعذر تعيين متغير.

--socket
الشكل المختصر: -S؛ النوع: string

ملف المقبس المستخدم للاتصال.

--user
الشكل المختصر: -u؛ النوع: string

المستخدم لتسجيل الدخول إذا لم يكن المستخدم الحالي.

--version
إظهار الإصدار والخروج.
--[no]version-check
الافتراضي: yes

التحقق من أحدث إصدار من Percona Toolkit و MySQL والبرامج الأخرى.

هذه ميزة قياسية "للتحقق من التحديثات تلقائيًا"، مع ميزتين إضافيتين. أولاً، تتحقق الأداة من إصدارها الخاص وأيضًا من إصدارات البرامج التالية: نظام التشغيل، Percona Monitoring and Management (PMM)، MySQL، مشغل MySQL لـ Perl (DBD::mysql)، و Percona Toolkit. ثانيًا، تتحقق وتحذر من الإصدارات التي بها مشاكل معروفة. على سبيل المثال، كان MySQL 5.5.25 يحتوي على خطأ حرج وتم إصداره مرة أخرى كـ 5.5.25a.

يتم إجراء اتصال آمن بخادم قاعدة بيانات التحقق من الإصدارات من Percona لإجراء هذه الشيكات. يتم تسجيل كل طلب بواسطة الخادم، بما في ذلك أرقام إصدارات البرامج ومعرف فريد للنظام الذي تم فحصه. يتم إنشاء المعرف بواسطة برنامج تثبيت Percona Toolkit أو عند إجراء استدعاء قاعدة بيانات التحقق من الإصدارات لـ f

pt-fk-error-logger(1p) — Arch Linux

NAME

pt-fk-error-logger — logs foreign key errors.

SYNOPSIS

pt-fk-error-logger [OPTIONS] DSN

RISKS

This tool connects to a MySQL server and can modify data. Before using it, please read the "RISKS" section of the percona-toolkit manpage.

DESCRIPTION

This tool logs foreign key errors from MySQL servers. It can capture all foreign key errors that occur on a server and store them in a table. This is useful for debugging and troubleshooting foreign key constraint issues.

OUTPUT

The tool logs foreign key errors to a specified table on the MySQL server. The table contains details about the error, including the query that caused it, the specific foreign key constraint, and the affected rows.

--defaults-file, --defaults-file=file

Only read default options from the given file. This option is deprecated and replaced by "--defaults-file". For more information, see https://www.percona.com/doc/percona-toolkit/LATEST/percona-db-options.html#cmdoption-mysqld_client_options---defaults-file.

--help, -h

Show help and exit.

--host, -h

Connect to host. The default is localhost.

--password, -p

Password to use when connecting. If password contains commas they must be escaped with a backslash: "exam\,ple"

--port, -P

Port number to use for connection. The default is 3306.

--socket, -S

Socket file to use for connection. The default is taken from the MYSQL_UNIX_PORT environment variable or "/var/run/mysqld/mysqld.sock".

--table, -t

Table in which to store foreign key errors. The default is "fk_errors".

--user, -u

User for login if not current user.

--version, -v

Show program version and exit.

--[no]version-check

Enable or disable checking for upgrades. When enabled, pt-fk-error-logger checks for the latest version of itself and prints a message if a new version is available. The check is performed only once per run. The check does not interfere with the tool's operation.

This feature is enabled by default. To disable it, specify "--no-version-check". The check is performed only once per run.

You can enable or disable this feature with the "--version-check" and "--no-version-check" options. The check is performed only once per run.

Any updates or known problems are printed to STDOUT before the tool's normal output. This feature should never interfere with the normal operation of the tool.

For more information, visit https://www.percona.com/doc/percona-toolkit/LATEST/version-check.html.

DSN OPTIONS

These DSN options are used to create a DSN. Each option is given like "option=value". The options are case-sensitive, so P and p are not the same option. There cannot be whitespace before or after the "=" and if the value contains whitespace it must be quoted. DSN options are comma-separated. See the percona-toolkit manpage for full details.

  • A

    dsn: charset; copy: yes

    Default character set.

  • D

    dsn: database; copy: yes

    Default database.

  • F

    dsn: mysql_read_default_file; copy: yes

    Only read default options from the given file

  • h

    dsn: host; copy: yes

    Connect to host.

  • p

    dsn: password; copy: yes

    Password to use when connecting. If password contains commas they must be escaped with a backslash: "exam\,ple"

  • P

    dsn: port; copy: yes

    Port number to use for connection.

  • S

    dsn: mysql_socket; copy: yes

    Socket file to use for connection.

  • t

    Table in which to store foreign key errors.

  • u

    dsn: user; copy: yes

    User for login if not current user.

  • s

    dsn: mysql_ssl; copy: yes

    Create SSL connection

ENVIRONMENT

The environment variable "PTDEBUG" enables verbose debugging output to STDERR. To enable debugging and capture all output to a file, run the tool like:

PTDEBUG=1 pt-fk-error-logger ... > FILE 2>&1

Be careful: debugging output is voluminous and can generate several megabytes of output.

ATTENTION

Using <PTDEBUG> might expose passwords. When debug is enabled, all command line parameters are shown in the output.

SYSTEM REQUIREMENTS

You need Perl, DBI, DBD::mysql, and some core packages that ought to be installed in any reasonably new version of Perl.
