PTHREAD_COND_DESTROY(3P) دليل مبرمج POSIX PTHREAD_COND_DESTROY(3P)

مقدمة

هذه الصفحة من الدليل هي جزء من دليل مبرمج POSIX. قد يختلف تطبيق لينكس لهذه الواجهة (راجع صفحة دليل لينكس المقابلة لتفاصيل سلوك لينكس)، أو قد لا تكون الواجهة مطبقة في لينكس.

الاسم

pthread_cond_destroy, pthread_cond_init — تدمير وتهيئة متغيرات الشرط

الملخص

#include <pthread.h>
int pthread_cond_destroy(pthread_cond_t *cond);
int pthread_cond_init(pthread_cond_t *restrict cond,
    const pthread_condattr_t *restrict attr);
pthread_cond_t cond = PTHREAD_COND_INITIALIZER;

الوصف

تقوم الدالة pthread_cond_destroy() بتدمير متغير الشرط المحدد بواسطة cond؛ يصبح الكائن، فعليًا، غير مهيأ. قد يتسبب التطبيق في أن تقوم pthread_cond_destroy() بتعيين الكائن المشار إليه بواسطة cond إلى قيمة غير صالحة. يمكن إعادة تهيئة كائن متغير شرط تم تدميره باستخدام pthread_cond_init()؛ النتائج المترتبة على الإشارة إلى الكائن بطريقة أخرى بعد تدميره غير محددة.

يجب أن يكون من الآمن تدمير متغير شرط مهيأ لم يتم حظر أي خيوط عليه حاليًا. محاولة تدمير متغير شرط تم حظر خيوط أخرى عليه حاليًا يؤدي إلى سلوك غير محدد.

تقوم الدالة pthread_cond_init() بتهيئة متغير الشرط المشار إليه بواسطة cond بالسمات المشار إليها بواسطة attr. إذا كان attr فارغًا (NULL)، فسيتم استخدام سمات متغير الشرط الافتراضية؛ التأثير هو نفسه كما لو تم تمرير عنوان كائن سمات متغير شرط افتراضي. عند نجاح التهيئة، تصبح حالة متغير الشرط مهيأة.

راجع القسم 2.9.9، نسخ كائنات المزامنة والتعيينات البديلة لمزيد من المتطلبات.

محاولة تهيئة متغير شرط مهيأ بالفعل يؤدي إلى سلوك غير محدد.

في الحالات التي تكون فيها سمات متغير الشرط الافتراضية مناسبة، يمكن استخدام الثابت PTHREAD_COND_INITIALIZER لتهيئة متغيرات الشرط. سيكون التأثير مكافئًا للتهيئة الديناميكية باستدعاء pthread_cond_init() مع تعيين المعامل attr إلى NULL، باستثناء أنه لا يتم إجراء أي فحوصات للأخطاء.

السلوك غير محدد إذا كانت القيمة المحددة للمعامل cond إلى pthread_cond_destroy() لا تشير إلى متغير شرط مهيأ.

السلوك غير محدد إذا كانت القيمة المحددة للمعامل attr إلى pthread_cond_init() لا تشير إلى كائن سمات متغير شرط مهيأ.

قيمة الإرجاع

في حالة النجاح، تعيد الدالتان pthread_cond_destroy() و pthread_cond_init() صفرًا؛ بخلاف ذلك، يتم إرجاع رقم خطأ للإشارة إلى الخطأ.

الأخطاء

ستفشل الدالة pthread_cond_init() في الحالات التالية:

EAGAIN
لم تكن لدى النظام الموارد اللازمة (بخلاف الذاكرة) لتهيئة متغير شرط آخر.
ENOMEM
لا توجد ذاكرة كافية لتهيئة متغير الشرط.

لن تعيد هذه الدوال رمز خطأ [EINTR].

الأقسام التالية إعلامية.

أمثلة

يمكن تدمير متغير الشرط مباشرة بعد إيقاظ جميع الخيوط المحظورة عليه. على سبيل المثال، ضع في اعتبارك الشفرة التالية:

struct list {
    pthread_mutex_t lm;
    ...
}
struct elt {
    key k;
    int busy;
    pthread_cond_t notbusy;
    ...
}
/* البحث عن عنصر قائمة وحجزه. */
struct elt *
list_find(struct list *lp, key k)
{
    struct elt *ep;
    pthread_mutex_lock(&lp->lm);
    while ((ep = find_elt(l, k) != NULL) && ep->busy)
        pthread_cond_wait(&ep->notbusy, &lp->lm);
    if (ep != NULL)
        ep->busy = 1;
    pthread_mutex_unlock(&lp->lm);
    return(ep);
}
delete_elt(struct list *lp, struct elt *ep)
{
    pthread_mutex_lock(&lp->lm);
    assert(ep->busy);
    ... إزالة ep من القائمة ...
    ep->busy = 0;  /* للتحقق */
(A) pthread_cond_broadcast(&ep->notbusy);
    pthread_mutex_unlock(&lp->lm);
(B) pthread_cond_destroy(&ep->notbusy);
    free(ep);
}

في هذا المثال، يمكن تحرير متغير الشرط وعنصر القائمة الخاص به (السطر B) مباشرة بعد إيقاظ جميع الخيوط التي تنتظر عليه (السطر A)، نظرًا لأن القفل والشفرة تضمن أن أي خيط آخر لا يمكنه لمس العنصر المراد حذفه.

استخدام التطبيق

لا يوجد.

الأساس المنطقي

إذا اكتشف تطبيق أن القيمة المحددة للمعامل cond إلى pthread_cond_destroy() لا تشير إلى متغير شرط مهيأ، فمن المستحسن أن تفشل الدالة وترجع خطأ [EINVAL].

إذا اكتشف تطبيق أن القيمة المحددة للمعامل cond إلى pthread_cond_destroy() أو pthread_cond_init() تشير إلى متغير شرط قيد الاستخدام (على سبيل المثال، في مكالمة pthread_cond_wait()) بواسطة خيط آخر، أو اكتشف أن القيمة المحددة للمعامل cond إلى pthread_cond_init() تشير إلى متغير شرط مهيأ بالفعل، فمن المستحسن أن تفشل الدالة وترجع خطأ [EBUSY].

إذا اكتشف تطبيق أن القيمة المحددة للمعامل attr إلى pthread_cond_init() لا تشير إلى كائن سمات متغير شرط مهيأ، فمن المستحسن أن تفشل الدالة وترجع خطأ [EINVAL].

راجع أيضًا pthread_mutex_destroy().
