PTHREAD_SETCANCELSTATE(3P) دليل مبرمج POSIX PTHREAD_SETCANCELSTATE(3P)

مقدمة

هذه الصفحة الدليلية هي جزء من دليل مبرمج POSIX. قد يختلف تطبيق لينكس لهذه الواجهة (راجع صفحة دليل لينكس المقابلة لمعرفة تفاصيل سلوك لينكس)، أو قد لا تكون الواجهة مطبقة في لينكس.

الاسم

pthread_setcancelstate, pthread_setcanceltype, pthread_testcancel — تعيين حالة قابلية الإلغاء

الملخص

#include <pthread.h>
int pthread_setcancelstate(int state, int *oldstate);
int pthread_setcanceltype(int type, int *oldtype);
void pthread_testcancel(void);

الوصف

تقوم الدالة pthread_setcancelstate() بتعيين حالة قابلية الإلغاء للخيط المتصل إلى state المحدد وإرجاع حالة قابلية الإلغاء السابقة في الموقع المشار إليه بواسطة oldstate بشكل ذري. القيم القانونية لـ state هي PTHREAD_CANCEL_ENABLE و PTHREAD_CANCEL_DISABLE.

تقوم الدالة pthread_setcanceltype() بتعيين نوع قابلية الإلغاء للخيط المتصل إلى type المحدد وإرجاع نوع قابلية الإلغاء السابق في الموقع المشار إليه بواسطة oldtype بشكل ذري. القيم القانونية لـ type هي PTHREAD_CANCEL_DEFERRED و PTHREAD_CANCEL_ASYNCHRONOUS.

ستكون حالة ونوع قابلية الإلغاء لأي خيوط جديدة تم إنشاؤها، بما في ذلك الخيط الذي تم فيه استدعاء الدالة main() لأول مرة، PTHREAD_CANCEL_ENABLE و PTHREAD_CANCEL_DEFERRED على التوالي.

تقوم الدالة pthread_testcancel() بإنشاء نقطة إلغاء في الخيط المتصل. لن يكون للدالة pthread_testcancel() أي تأثير إذا كانت قابلية الإلغاء معطلة.

قيمة الإرجاع

إذا نجحت، فإن الدوال pthread_setcancelstate() و pthread_setcanceltype() تُرجع صفرًا؛ وإلا، يتم إرجاع رقم خطأ للإشارة إلى الخطأ.

الأخطاء

قد تفشل الدالة pthread_setcancelstate() إذا:

EINVAL
الحالة المحددة ليست PTHREAD_CANCEL_ENABLE أو PTHREAD_CANCEL_DISABLE.

قد تفشل الدالة pthread_setcanceltype() إذا:

EINVAL
النوع المحدد ليس PTHREAD_CANCEL_DEFERRED أو PTHREAD_CANCEL_ASYNCHRONOUS.

لن تُرجع هذه الدوال رمز خطأ [EINTR].

الأقسام التالية إعلامية.

أمثلة

لا شيء.

استخدام التطبيق

لكتابة معالج إشارة لإشارة غير متزامنة يمكن تشغيلها بأمان في خيط قابل للإلغاء، يجب استخدام pthread_setcancelstate() لتعطيل الإلغاء لمدة استدعاءات التي تقوم بها معالجة الإشارة والتي هي نقاط إلغاء. ومع ذلك، فإن المعيار لا يسمح للتطبيقات المتوافقة تمامًا باستدعاء pthread_setcancelstate() من معالج إشارة نظرًا لعدم تطلبه حاليًا أن يكون آمنًا للإشارة غير المتزامنة. في التنفيذ حيث pthread_setcancelstate() ليست آمنة للإشارة غير المتزامنة، البدائل هي ضمان أن الإشارات المقابلة محظورة أثناء تنفيذ الدوال غير الآمنة للإلغاء غير المتزامن أو أن الإلغاء معطل خلال الأوقات التي يمكن فيها تسليم تلك الإشارات. يتم تشجيع التنفيذ بقوة على جعل pthread_setcancelstate() آمنة للإشارة غير المتزامنة.

المنطق

تتحكم الدوال pthread_setcancelstate() و pthread_setcanceltype() في النقاط التي قد يتم فيها إلغاء خيط بشكل غير متزامن. لكي تكون السيطرة على الإلغاء قابلة للاستخدام بطريقة وحدوية، يجب اتباع بعض القواعد.

يمكن اعتبار الكائن تعميمًا للإجراء. إنه مجموعة من الإجراءات والمتغيرات العامة المكتوبة كوحدة ويتم استدعاؤها بواسطة العملاء الذين لا يعرفهم الكائن. قد تعتمد الكائنات على كائنات أخرى.

أولاً، يجب فقط تعطيل قابلية الإلغاء عند الدخول إلى كائن، وعدم تمكينها صراحةً أبدًا. عند الخروج من كائن، يجب دائمًا استعادة حالة قابلية الإلغاء إلى قيمتها عند دخول الكائن.

هذا يتبع من حجة الوحدوية: إذا كان عميل كائن (أو عميل كائن يستخدم هذا الكائن) قد قام بتعطيل قابلية الإلغاء، فذلك لأنه لا يريد أن يقلق بشأن التنظيف إذا تم إلغاء الخيط أثناء تنفيذ سلسلة من الإجراءات. إذا تم استدعاء كائن في مثل هذه الحالة وقام بتمكين قابلية الإلغاء وكان طلب إلغاء معلقًا لهذا الخيط، فسيتم إلغاء الخيط، على عكس رغبة العميل الذي قام بالتعطيل.

ثانيًا، يمكن تعيين نوع قابلية الإلغاء صراحةً إلى deferred أو asynchronous عند الدخول إلى كائن. ولكن كما هو الحال مع حالة قابلية الإلغاء، عند الخروج من كائن، يجب دائمًا استعادة نوع قابلية الإلغاء إلى قيمته عند دخول الكائن.

أخيرًا، لا يمكن استدعاء سوى الدوال التي تعتبر آمنة للإلغاء من خيط قابل للإلغاء بشكل غير متزامن.

الاتجاهات المستقبلية

قد تتم إضافة الدالة pthread_setcancelstate() إلى جدول الدوال الآمنة للإشارة غير المتزامنة في القسم 2.4.3، إجراءات الإشارة.

pthread_setcancelstate(3p)

pthread_setcancelstate - set thread cancelability state

SYNOPSIS

#include <pthread.h>

int pthread_setcancelstate(int state, int *oldstate);

DESCRIPTION

The pthread_setcancelstate() function shall set the cancelability state of the calling thread to either PTHREAD_CANCEL_ENABLE or PTHREAD_CANCEL_DISABLE.

If the oldstate argument is not NULL, the previous cancelability state of the calling thread shall be stored in the location referred to by oldstate.

The state argument must have the value PTHREAD_CANCEL_ENABLE or PTHREAD_CANCEL_DISABLE.

PTHREAD_CANCEL_DISABLE prevents asynchronous cancelability. If the thread's cancelability type is asynchronous, setting the cancelability state to PTHREAD_CANCEL_DISABLE defers any pending cancel requests until the cancelability state is set back to PTHREAD_CANCEL_ENABLE.

PTHREAD_CANCEL_ENABLE allows asynchronous cancelability. If the thread's cancelability type is asynchronous and a cancel request is pending, the thread shall be canceled immediately when the cancelability state is set to PTHREAD_CANCEL_ENABLE.

RETURN VALUE

On success, pthread_setcancelstate() shall return 0.

On error, it shall return an error number. The value of oldstate is undefined on error.

ERRORS

EINVAL
The value specified by state is not PTHREAD_CANCEL_ENABLE or PTHREAD_CANCEL_DISABLE.

The following sections are not specified by the POSIX standard:

ENOTRECOVERABLE
State could not be changed.

EXAMPLES

None.

APPLICATION USAGE

The pthread_setcancelstate() function is intended to be called only by library routines that need to temporarily disable or enable thread cancellation. Applications should generally not call this function directly. Applications that need to control thread cancellation should use pthread_setcanceltype() to set the cancelability type and pthread_testcancel() to establish cancellation points.

RATIONALE

None.

FUTURE DIRECTIONS

None.
