NAME

pt-slave-restart - Automatically restart MySQL replicas that have stopped.

SYNOPSIS

pt-slave-restart [OPTIONS] [--pid=FILE] [--slave-count=N]
  [--interval=S] [--check-compatibility] [--daemonize] [--dry-run]
  [--log=FILE] [--set-master-symlink] [--set-slave-parallel-type]
  [--print-interval=S] [--loop-forever] [--help] [--version]

RISKS

This tool restarts MySQL replicas. You must understand the risks associated with restarting a replica, especially if it is not fully synchronized with its primary server.

You must test this tool thoroughly in a non-production environment before using it in production. Understand the following:

  • The replica's synchronization status.
  • The potential for data loss if the replica is not caught up.
  • The impact of restarting a replica on your application.

It is strongly recommended that you use the --dry-run option first to see what the tool will do without actually doing it.

DESCRIPTION

This tool monitors MySQL replicas and automatically restarts them if they have stopped. It is designed to be run as a daemon, but can also be run once to check the status of replicas.

The tool connects to the MySQL server specified by DSN options and checks the status of all replicas. If a replica has stopped, it will attempt to restart it. The tool can also perform various other tasks, such as setting master symlinks and slave parallel types.

The tool is intended to be run as a daemon, but can also be run once to check the status of replicas. It should be run on a machine that has network access to all replicas it is monitoring.

OUTPUT

When run as a daemon, the tool prints status messages to STDOUT. These messages indicate which replicas are being monitored, when they are restarted, and any errors encountered.

The tool also logs information to a file if the --log option is specified.

SLEEP

The tool sleeps for the interval specified by the --interval option between checks. This interval should be set to a reasonable value to avoid excessive load on the MySQL servers.

GLOBAL TRANSACTION IDS

The tool supports global transaction IDs (GTIDs). If GTIDs are enabled, the tool will use them to determine the position of the replica. If GTIDs are not enabled, the tool will use traditional binary log positions.

EXIT STATUS

The tool exits with a status of 0 on success, and a non-zero status on error. The specific exit status indicates the type of error encountered.

COMPATIBILITY

The tool is compatible with MySQL 5.1 and later. It has been tested with Percona Server and MySQL Community Server.

OPTIONS

The tool accepts the following options:

--help
Show help message and exit.
--version
Show program version and exit.
--pid=FILE
Create a PID file and write the process ID to it. This is useful for managing the daemon.
--slave-count=N
The number of replicas to monitor. If not specified, the tool will attempt to detect the number of replicas automatically.
--interval=S
The interval in seconds between checks. Default is 60 seconds.
--check-compatibility
Check for compatibility issues before starting.
--daemonize
Run the tool as a daemon in the background.
--dry-run
Simulate the restart process without actually performing it. Useful for testing.
--log=FILE
Log output to the specified file.
--set-master-symlink
Set the master-slave symlinks. This option is only available if the replica is not already configured with master-slave symlinks.
--set-slave-parallel-type
Set the slave parallel type. This option is only available if the replica is not already configured with a slave parallel type.
--print-interval=S
Print status messages every S seconds.
--loop-forever
Keep running indefinitely. This option is equivalent to --daemonize and should not be used together.
