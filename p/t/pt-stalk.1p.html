الاسم

pt-stalk - جمع البيانات الجنائية لـ MySQL عندما تحدث مشاكل.

الملخص

الاستخدام: pt-stalk [خيارات]

ينتظر pt-stalk حدوث شرط الزناد، ثم يجمع البيانات للمساعدة في تشخيص المشاكل. تم تصميم الأداة للعمل كخادم بامتيازات الجذر، بحيث يمكنك تشخيص المشاكل المتقطعة التي لا يمكنك ملاحظتها مباشرة. يمكنك أيضًا استخدامه لتنفيذ أمر مخصص، أو لجمع البيانات عند الطلب دون انتظار حدوث الزناد.

المخاطر

Percona Toolkit ناضج، ومثبت في العالم الواقعي، وتم اختباره جيدًا، ولكن جميع أدوات قواعد البيانات يمكن أن تشكل خطرًا على النظام وخادم قاعدة البيانات. قبل استخدام هذه الأداة، يرجى:

  • قراءة وثائق الأداة
  • مراجعة "الأخطاء" المعروفة للأداة
  • اختبار الأداة على خادم غير إنتاجي
  • عمل نسخة احتياطية من خادم الإنتاج الخاص بك والتحقق من النسخ الاحتياطية

الوصف

في بعض الأحيان تحدث مشكلة بشكل غير متكرر ولفترة قصيرة، مما يمنحك فرصة لمشاهدة النظام عندما يحدث ذلك. كيف تحل مشاكل MySQL المتقطعة عندما لا يمكنك ملاحظتها؟ لهذا السبب يوجد pt-stalk. بالإضافة إلى استخدامه عندما تكون هناك مشكلة معروفة على خوادمك، فمن الجيد تشغيل pt-stalk طوال الوقت، حتى عندما تعتقد أنه لا يوجد خطأ. ستقدر البيانات التي تجمعها عندما تحدث مشكلة، لأن المشاكل مثل تعليق MySQL أو زيادة النشاط عادةً لا تترك أي دليل لاستخدامه في تحليل السبب الجذري.

يقوم pt-stalk بأمرين: يراقب خادم MySQL وينتظر حدوث شرط الزناد، ويجمع بيانات التشخيص عند حدوث هذا الزناد. لتجنب الإيجابيات الكاذبة الناتجة عن المشاكل قصيرة الأمد، يجب أن يكون شرط الزناد صحيحًا على الأقل "--دورات" مرات قبل تشغيل "--جمع".

للتأكد من فعالية pt-stalk، تحتاج إلى تعريف زناد جيد. الزناد الجيد حساس بما يكفي ليتم تفعيله بشكل موثوق عند حدوث مشكلة، حتى لا تفوت فرصة لحل المشاكل. من ناحية أخرى، الزناد الجيد ليس عرضة للإيجابيات الكاذبة، لذلك لا تجمع المعلومات عندما يعمل الخادم بشكل طبيعي.

تعتبر استعلامات SHOW GLOBAL STATUS مثل عدد الاتصالات بالخادم وعدد الاستعلامات التي تعمل بشكل متزامن من بين أكثر المحفزات موثوقية لـ MySQL. هذه متاحة في أمر SHOW GLOBAL STATUS كـ Threads_connected و Threads_running. في بعض الأحيان لا يكون Threads_connected مؤشرًا موثوقًا للمشاكل، ولكن Threads_running عادةً ما يكون كذلك. مهمتك، كمستخدم للأداة، هي تحديد شرط زناد مناسب للأداة. اختر بعناية، لأن جودة نتائجك ستعتمد على الزناد الذي تختاره.

يمكنك تعريف الزناد باستخدام خيارات "--function" و "--variable" و "--threshold" و "--cycles". تحدد القيم الافتراضية لهذه الخيارات زنادًا معقولاً، ولكن يجب عليك تعديلها أو تغييرها لتناسب نظامك واحتياجاتك الخاصة.

افتراضيًا، تراقب أداة pt-stalk خادم MySQL إلى الأبد حتى يحدث الزناد، ثم تجمع بيانات التشخيص لفترة، ثم تنام بعدها لتجنب جمع البيانات بشكل متكرر إذا ظل الزناد صحيحًا. الترتيب العام للعمليات هو:

while true; do
   if --variable from --function > --threshold; then
      cycles_true++
      if cycles_true >= --cycles; then
         --notify-by-email
         if --collect; then
            if --disk-bytes-free and --disk-pct-free ok; then
               (--collect for --run-time seconds) &
            fi
            rm files in --dest older than --retention-time
         fi
         iter++
         cycles_true=0
      fi
      if iter < --iterations; then
         sleep --seconds seconds
      else
         break
      fi
   else
      if iter < --iterations; then
         sleep --interval seconds
      else
         break
      fi
   fi
done
rm old --dest files older than --retention-time
if --collect process are still running; then
   wait up to --run-time * 3 seconds
   kill any remaining --collect processes
fi

تتم كتابة بيانات التشخيص في ملفات تبدأ أسماؤها بتاريخ ووقت، بحيث يمكنك التمييز بين العينات في حالة قيام الأداة بجمع البيانات عدة مرات. تم تصميم أداة pt-sift للمساعدة في تصفح وتحليل عينات البيانات الناتجة.

على الرغم من أن هذا يبدو بسيطًا بما فيه الكفاية، إلا أنه في الممارسة العملية هناك عدد من الفروق الدقيقة، مثل اكتشاف متى يبدأ القرص في الامتلاء حتى لا تتسبب الأداة في نفاد مساحة القرص من الخادم. تتعامل هذه الأداة مع هذه الأنواع من المشاكل المحتملة، لذلك من الجيد استخدام هذه الأداة بدلاً من كتابة شيء من الصفر وربما تجربة بعض المخاطر التي تم تصميم هذه الأداة لتجنبها.

الإعداد

يمكنك استخدام ملفات تكوين Percona Toolkit القياسية لتعيين خيارات سطر الأوامر.

من المحتمل أن ترغب في تشغيل الأداة كخادم وتخصيص "--threshold" على الأقل. إليك ملف تكوين نموذجي لتشغيل الزناد عندما يكون هناك أكثر من 20 استعلام قيد التشغيل في وقت واحد:

daemonize
threshold=20

إذا لم تقم بتشغيل الأداة كـ root، فستحتاج إلى تحديد عدة خيارات، مثل "--pid" و "--log" و "--dest"، وإلا قد تفشل الأداة في البدء.

الخيارات

--ask-pass
طلب كلمة مرور عند الاتصال بـ MySQL.
--collect
الافتراضي: نعم؛ قابل للنفي: نعم

جمع بيانات التشخيص عند حدوث الزناد. حدد "--no-collect" لجعل الأداة تراقب النظام ولكن لا تجمع البيانات.

انظر أيضًا "--stalk".

--collect-gdb
جمع تتبعات المكدس GDB. يتم ذلك عن طريق الاتصال بـ MySQL وطباعة تتبعات المكدس من جميع الخيوط. سيؤدي هذا إلى تجميد الخادم لفترة من الوقت، تتراوح من ثانية أو نحو ذلك إلى وقت أطول في الأنظمة شديدة الاستخدام مع الكثير من الذاكرة والعديد من الخيوط في الخادم. لهذا السبب، يتم تعطيله افتراضيًا. ومع ذلك، إذا كنت تحاول تشخيص توقف الخادم أو تعليقه، فإن تجميد الخادم لا يسبب ضررًا إضافيًا، ويمكن أن تكون تتبعات المكدس حيوية للتشخيص.

بالإضافة إلى تجميد الخادم، هناك أيضًا بعض المخاطر من تعطل الخادم أو أدائه السيئ بعد فصل GDB عنه.

--collect-oprofile
جمع بيانات oprofile. يتم ذلك عن طريق بدء جلسة oprofile، والسماح لها بالعمل لوقت التجميع، ثم إيقاف وحفظ بيانات الملف الشخصي الناتجة في الموقع الافتراضي للنظام. يرجى قراءة وثائق oprofile الخاصة بنظامك لمعرفة المزيد عن هذا.
--collect-strace
جمع بيانات strace. يتم ذلك عن طريق ربط strace بالخادم، مما سيجعله يعمل ببطء شديد حتى ينفصل strace. تنطبق نفس التحذيرات كما هو مدرج في --collect-gdb. يجب ألا تقوم بتمكين هذا الخيار مع --collect-gdb، لأن GDB و strace لا يمكنهما الاتصال بعملية الخادم في وقت واحد.
--collect-tcpdump
جمع بيانات tcpdump. يتسبب هذا الخيار في قيام tcpdump بالتقاط جميع حركة المرور على جميع الواجهات للمنفذ الذي يستمع إليه MySQL. يمكنك لاحقًا استخدام pt-query-digest لفك تشفير بروتوكول MySQL واستخراج سجل لحركة الاستعلامات منه.
--config
النوع: سلسلة نصية

قراءة هذه القائمة من ملفات التكوين المفصولة بفواصل. إذا تم تحديده، يجب أن يكون هذا هو الخيار الأول في سطر الأوامر.

--cycles
النوع: عدد صحيح؛ الافتراضي: 5

كم مرة يجب أن يكون "--variable" أكبر من "--threshold" قبل تشغيل "--collect". يساعد هذا في منع الإيجابيات الكاذبة، ويجعل شرط الزناد أقل عرضة للتفعيل عندما يتعافى الخادم بسرعة.

--daemonize
تحويل الأداة إلى عملية خادمة. هذا يتسبب في قيام الأداة بالانفصال إلى الخلفية وتسجيل مخرجاتها كما هو محدد في --log.

--disk-bytes-free
type: size; default: 100M

Do not "--collect" if the disk has less than this much free space. This prevents the tool from filling up the disk with diagnostic data.

If the "--dest" directory contains a previously captured sample of data, the tool will measure its size and use that as an estimate of how much data is likely to be gathered this time, too. It will then be even more pessimistic, and will refuse to collect data unless the disk has enough free space to hold the sample and still have the desired amount of free space. For example, if you'd like 100MB of free space and the previous diagnostic sample consumed 100MB, the tool won't collect any data unless the disk has 200MB free.

Valid size value suffixes are k, M, G, and T.

--disk-pct-free
type: int; default: 5

Do not "--collect" if the disk has less than this percent free space. This prevents the tool from filling up the disk with diagnostic data.

This option works similarly to "--disk-bytes-free" but specifies a percentage margin of safety instead of a bytes margin of safety. The tool honors both options, and will not collect any data unless both margins are satisfied.

--function
type: string; default: status

What to watch for the trigger. The default value watches "SHOW GLOBAL STATUS", but you can also watch "SHOW PROCESSLIST" and specify a file with your own custom code. This function supplies the value of "--variable", which is then compared against "--threshold" to see if the the trigger condition is met. Additional options may be required as well; see below. Possible values are:

  • status

    Watch "SHOW GLOBAL STATUS" for the trigger. The value of "--variable" then defines which status counter is the trigger.

  • processlist

    Watch "SHOW FULL PROCESSLIST" for the trigger. The trigger value is the count of processes whose "--variable" column matches the "--match" option. For example, to trigger "--collect" when more than 10 processes are in the "statistics" state, specify:

    --function processlist \
--variable State       \
--match statistics     \
--threshold 10

In addition, you can specify a file that contains your custom trigger function, written in Unix shell script. This can be a wrapper that executes anything you wish. If the argument to "--function" is a file, then it takes precedence over built-in functions, so if there is a file in the working directory named "status" or "processlist" then the tool will use that file even though are valid built-in values.

The file works by providing a function called "trg_plugin", and the tool simply sources the file and executes the function. For example, the file might contain:

trg_plugin() {
   mysql $EXT_ARGV -e "SHOW ENGINE INNODB STATUS" \
     | grep -c "has waited at"
}

This snippet will count the number of mutex waits inside InnoDB. It illustrates the general principle: the function must output a number, which is then compared to "--threshold" as usual. The $EXT_ARGV variable contains the MySQL options mentioned in the "SYNOPSIS" above.

The file should not alter the tool's existing global variables. Prefix any file-specific global variables with "PLUGIN_" or make them local.

Print all output to this file when daemonized.

type: string

The pattern to use when watching SHOW PROCESSLIST. See "--function" for details.

--notify-by-email
type: string

Send an email to these addresses for every "--collect".

--password
short form: -p; type: string

Password to use when connecting. If password contains commas they must be escaped with a backslash: "exam\,ple"

--pid
type: string; default: /var/run/pt-stalk.pid

Create the given PID file. The tool won't start if the PID file already exists and the PID it contains is different than the current PID. However, if the PID file exists and the PID it contains is no longer running, the tool will overwrite the PID file with the current PID. The PID file is removed automatically when the tool exits.

--plugin
type: string

Load a plugin to hook into the tool and extend is functionality. The specified file does not need to be executable, nor does its first line need to be shebang line. It only needs to define one or more of these Bash functions:

before_stalk
Called before stalking.
before_collect
Called when the trigger occurs, before running a "--collect" subprocesses in the background.
after_collect
Called after running a collector process. The PID of the collector process is passed as the first argument. This hook is called before "after_collect_sleep".
after_collect_sleep
Called after sleeping "--sleep" seconds for the collector process to finish. This hook is called after "after_collect".
after_interval_sleep
Called after sleeping "--interval" seconds after each trigger check.
after_stalk
Called after stalking. Since pt-stalk stalks forever by default, this hook is only called if "--iterations" is specified.

For example, a very simple plugin that touches a file when "--collect" is triggered:

before_collect() {
   touch /tmp/foo
}

Since the plugin is completely sourced (imported) into the tool's namespace, be careful not to define other functions or global variables that already exist in the tool. You should prefix all plugin-specific functions and global variables with "plugin_" or "PLUGIN_".

Plugins have access to all command line options but they should not modify them. Each option is a global variable like $OPT_DEST which corresponds to "--dest". Therefore, the global variable for each command line option is "OPT_" plus the option name in all caps with hyphens replaced by underscores.

Plugins can stop the tool by setting the global variable "OKTORUN" to 1. In this case, the global variable "EXIT_REASON" should also be set to indicate why the tool was stopped.

Plugin writers should keep in mind that the file destination prefix currently in use should be accessed through the $prefix variable, rather than $OPT_PREFIX.

--mysql-only
Trigger only MySQL related captures, ignoring all others. The only not MySQL related value being collected is the disk space, because it is needed to calculate the available free disk space to write the result files. This option is useful for RDS instances.

NAME

pt-stalk - Collects troubleshooting data when a MySQL server is failing.

SYNOPSIS

pt-stalk [OPTIONS] [--host=H --user=U --password=P --port=P --socket=S]

RISKS

pt-stalk is designed to collect troubleshooting data. The data it collects may be sensitive, and it can also consume disk space. Be sure to understand what data it collects, where it stores it, and how much space it consumes before deploying it in a production environment. For example, it may collect the contents of tables, and it may collect sensitive information from table rows. You must not use this tool if sensitive data, such as passwords, are in the table. If you believe sensitive data is in a table, and you believe it should not be, you must remove it from the table and re-create the table after you have removed the sensitive data.

DESCRIPTION

pt-stalk is a tool to collect troubleshooting data when a MySQL server is failing. It watches a specified MySQL server for a specified condition and when that condition is met, it collects specified troubleshooting data and saves it to a specified directory. When the condition is no longer met, it stops collecting data.

This tool is useful for capturing data from intermittent failures, such as those that occur under heavy load or at specific times of day.

CONFIGURING

pt-stalk can be configured using a configuration file or by passing options on the command line. The configuration file is a text file with a format similar to MySQL option files. The options are specified as key-value pairs, with the key being the option name and the value being the option value. The configuration file can be specified using the --config option. If no configuration file is specified, pt-stalk will look for a file named pt-stalk.cnf in the current directory or in the user's home directory.

OPTIONS

pt-stalk accepts the following options:

--config=file
Specifies the configuration file to use. If not specified, pt-stalk will look for a file named pt-stalk.cnf in the current directory or in the user's home directory.
--daemonize
Runs pt-stalk as a daemon process.
--pid=file
Specifies the file to write the process ID to when running as a daemon.
--interval=seconds
Specifies the interval in seconds to check for the specified condition. Default is 1 second.
--condition=condition
Specifies the condition to watch for. This can be a MySQL query that returns a non-zero value when the condition is met, or a file that exists. For example, --condition="SELECT COUNT(*) FROM information_schema.processlist WHERE command = 'Query' AND time > 10" or --condition=/path/to/trigger_file.
--output-dir=dir
Specifies the directory to store the collected data. Default is the current directory.
--data-to-collect=list
Specifies a comma-separated list of data to collect. Supported values include: processlist, VARIABLES, SHOW STATUS, SHOW CREATE TABLE, table schema, table data, slow log, error log, general log, mysqldump, SHOW ENGINE INNODB STATUS.
--mysqldump-options=options
Specifies options to pass to mysqldump when collecting table data.
--log-file=file
Specifies the file to write log messages to.
--log-level=level
Specifies the log level. Supported values are INFO, WARNING, ERROR, DEBUG.
--help
Displays help message and exits.
--version
Displays version information and exits.

ENVIRONMENT

The following environment variables can be used:

MYSQL_HOST
MySQL server host.
MYSQL_USER
MySQL user.
MYSQL_PASSWORD
MySQL password.
MYSQL_PORT
MySQL port.
MYSQL_SOCKET
MySQL socket file.

Percona Toolkit runs on the following systems:

  • Linux, macOS, FreeBSD, OpenBSD, Solaris, Windows.

  • Perl 5.8.0 or later.
  • A MySQL client library.
  • A MySQL server (any version supported by the client library).
