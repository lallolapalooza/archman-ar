NAME

pthread_cleanup_push, pthread_cleanup_pop - thread cleanup handling

SYNOPSIS

#include <pthread.h>

void pthread_cleanup_push(void (*routine)(void *), void *arg);

void pthread_cleanup_pop(int execute);

DESCRIPTION

The POSIX threads library provides mechanisms for threads to manage resource cleanup in the face of asynchronous cancellation. These functions are typically used in pairs, like this:

pthread_cleanup_push(cleanup_handler, cleanup_arg);
    /* Do work that might be cancelled */
    ...
pthread_cleanup_pop(1); /* or 0 */
routine
A pointer to a function that will be called when the cleanup is performed. This function takes a single argument, arg.
arg
The argument to be passed to the cleanup handler function.

When pthread_cleanup_push is called, the specified cleanup handler (routine, arg) is pushed onto a thread-local stack of cleanup handlers.

When pthread_cleanup_pop is called, the top handler is popped from the stack. If the execute argument is non-zero, the popped handler is executed.

A thread can have multiple cleanup handlers registered. The cleanup handlers are executed in the reverse order that they were pushed.

These functions are intended to be used to manage resources like memory, mutexes, file descriptors, etc., that must be released when a thread is cancelled. Cancellation occurs when another thread calls pthread_cancel on the target thread.

The cleanup handlers are invoked in the following situations:

  • When the thread is cancelled via pthread_cancel.
  • When the thread calls pthread_exit.
  • When the thread returns from its initial start routine (in this case, the handlers are popped but not executed).
  • When pthread_cleanup_pop is called with a non-zero execute argument.

Note that cancellation points are points in the execution where a thread may be asynchronously cancelled. These include functions like read, write, select, pthread_join, pthread_testcancel, etc. If a thread is cancelled at a cancellation point, all pending cleanup handlers are executed (in reverse order of being pushed) and then the thread is terminated.

RETURN VALUE

These functions do not return values.

ERRORS

No errors are returned by these functions.

EXAMPLES

The following example shows how to use these functions to protect a mutex from being left locked if the thread is cancelled:

void *thread_routine(void *arg) {
    pthread_mutex_t *mutex = (pthread_mutex_t *)arg;
    int s;

    s = pthread_mutex_lock(mutex);
    if (s != 0)
        /* handle error */ ;

    pthread_cleanup_push(mutex_cleanup_handler, mutex);

    /* Do work that requires the mutex */
    sleep(5); /* This is a cancellation point */

    pthread_cleanup_pop(1); /* Remove and execute the handler */

    s = pthread_mutex_unlock(mutex);
    if (s != 0)
        /* handle error */ ;

    return NULL;
}

void mutex_cleanup_handler(void *arg) {
    pthread_mutex_t *mutex = (pthread_mutex_t *)arg;
    pthread_mutex_unlock(mutex);
}

APPLICATION USAGE

The pthread_cleanup_push and pthread_cleanup_pop functions are macros. Their usage is subject to the following restrictions:

  • They must be used in pairs within the same lexical scope.
  • A pthread_cleanup_pop must occur after its corresponding pthread_cleanup_push.
  • They cannot be used inside a signal handler.
  • They cannot be used within a function that contains a goto statement that jumps over the corresponding pthread_cleanup_pop, or a continue or break statement that would cause control to be transferred out of the lexical scope enclosed by the pair.

Because they are implemented as macros, the code between the pthread_cleanup_push and pthread_cleanup_pop calls is effectively wrapped in a block scope. This can affect variable scoping and the behavior of control flow statements like return.

RATIONALE

Note that the specified cleanup handling mechanism is especially tied to the C language and, while the requirement for a uniform mechanism for expressing cleanup is language-independent, the mechanism used in other languages may be quite different. In addition, this mechanism is really only necessary due to the lack of a real exception mechanism in the C language, which would be the ideal solution.

There is no notion of a cancellation cleanup-safe function. If an application has no cancellation points in its signal handlers, blocks any signal whose handler may have cancellation points while calling async-unsafe functions, or disables cancellation while calling async-unsafe functions, all functions may be safely called from cancellation cleanup routines.

الاسم

pthread_cleanup_push, pthread_cleanup_pop - معالجة تنظيف الخيط

الملخص

#include <pthread.h>

void pthread_cleanup_push(void (*routine)(void *), void *arg);

void pthread_cleanup_pop(int execute);

الوصف

توفر مكتبة POSIX threads آليات للخيوط لإدارة تنظيف الموارد في مواجهة الإلغاء غير المتزامن. تُستخدم هذه الوظائف عادةً في أزواج، على هذا النحو:

pthread_cleanup_push(cleanup_handler, cleanup_arg);
    /* قم بالعمل الذي قد يتم إلغاؤه */
    ...
pthread_cleanup_pop(1); /* أو 0 */
routine
مؤشر إلى دالة سيتم استدعاؤها عند إجراء التنظيف. تأخذ هذه الدالة وسيطًا واحدًا، arg.
arg
الوسيط الذي سيتم تمريره إلى دالة معالج التنظيف.

عند استدعاء pthread_cleanup_push، يتم دفع معالج التنظيف المحدد (routine، arg) إلى مكدس معالجات التنظيف الخاص بالخيط.

عند استدعاء pthread_cleanup_pop، يتم إخراج المعالج العلوي من المكدس. إذا كان الوسيط execute غير صفري، فسيتم تنفيذ المعالج الذي تم إخراجه.

يمكن أن يحتوي الخيط على معالجات تنظيف متعددة مسجلة. يتم تنفيذ معالجات التنظيف بترتيب عكسي لترتيب دفعها.

الغرض من هذه الوظائف هو إدارة الموارد مثل الذاكرة، والأقفال، ومقابض الملفات، وما إلى ذلك، التي يجب تحريرها عند إلغاء خيط. يحدث الإلغاء عندما يستدعي خيط آخر pthread_cancel على الخيط المستهدف.

يتم استدعاء معالجات التنظيف في المواقف التالية:

  • عند إلغاء الخيط عبر pthread_cancel.
  • عندما يستدعي الخيط pthread_exit.
  • عندما يعود الخيط من روتينه البدئي الأولي (في هذه الحالة، يتم إخراج المعالجات ولكن لا يتم تنفيذها).
  • عند استدعاء pthread_cleanup_pop مع وسيط execute غير صفري.

لاحظ أن نقاط الإلغاء هي نقاط في التنفيذ حيث يمكن إلغاء الخيط بشكل غير متزامن. تشمل هذه الوظائف مثل read، write، select، pthread_join، pthread_testcancel، إلخ. إذا تم إلغاء خيط عند نقطة إلغاء، فسيتم تنفيذ جميع معالجات التنظيف المعلقة (بترتيب عكسي لترتيب دفعها) ثم يتم إنهاء الخيط.

قيمة الإرجاع

لا تقوم هذه الوظائف بإرجاع قيم.

الأخطاء

لا يتم إرجاع أي أخطاء بواسطة هذه الوظائف.

أمثلة

يوضح المثال التالي كيفية استخدام هذه الوظائف لحماية قفل mutex من تركه مقفلاً إذا تم إلغاء الخيط:

void *thread_routine(void *arg) {
    pthread_mutex_t *mutex = (pthread_mutex_t *)arg;
    int s;

    s = pthread_mutex_lock(mutex);
    if (s != 0)
        /* معالجة الخطأ */ ;

    pthread_cleanup_push(mutex_cleanup_handler, mutex);

    /* قم بالعمل الذي يتطلب mutex */
    sleep(5); /* هذه نقطة إلغاء */

    pthread_cleanup_pop(1); /* إزالة وتنفيذ المعالج */

    s = pthread_mutex_unlock(mutex);
    if (s != 0)
        /* معالجة الخطأ */ ;

    return NULL;
}

void mutex_cleanup_handler(void *arg) {
    pthread_mutex_t *mutex = (pthread_mutex_t *)arg;
    pthread_mutex_unlock(mutex);
}

استخدام التطبيق

pthread_cleanup_push و pthread_cleanup_pop هي وحدات ماكرو. يخضع استخدامها للقيود التالية:

  • يجب استخدامها في أزواج داخل نفس النطاق المعجمي.
  • يجب أن تحدث pthread_cleanup_pop بعد pthread_cleanup_push المقابلة لها.
  • لا يمكن استخدامها داخل معالج إشارة.
  • لا يمكن استخدامها داخل دالة تحتوي على عبارة goto تقفز فوق pthread_cleanup_pop المقابلة، أو عبارة continue أو break تتسبب في نقل التحكم خارج النطاق المعجمي المحاط بالزوج.

نظرًا لأنها منفذة كوحدات ماكرو، فإن الكود بين استدعاءات pthread_cleanup_push و pthread_cleanup_pop يتم تغليفه فعليًا في نطاق كتلة. يمكن أن يؤثر هذا على نطاق المتغيرات وسلوك عبارات تدفق التحكم مثل return.

المنطق

لاحظ أن آلية معالجة التنظيف المحددة مرتبطة بشكل خاص بلغة C، وبينما يعد مطلب آلية موحدة للتعبير عن التنظيف مستقلاً عن اللغة، فإن الآلية المستخدمة في لغات أخرى قد تكون مختلفة تمامًا. بالإضافة إلى ذلك، هذه الآلية ضرورية حقًا فقط بسبب عدم وجود آلية استثناء حقيقية في لغة C، والتي ستكون الحل المثالي.

لا يوجد مفهوم لدالة آمنة للتنظيف من الإلغاء. إذا لم يكن لدى التطبيق نقاط إلغاء في معالجات الإشارة الخاصة به، أو قام بحظر أي إشارة قد تحتوي معالجاتها على نقاط إلغاء أثناء استدعاء وظائف غير آمنة بشكل غير متزامن، أو قام بتعطيل الإلغاء أثناء استدعاء وظائف غير آمنة بشكل غير متزامن، فيمكن استدعاء جميع الوظائف بأمان من روتينات تنظيف الإلغاء.
