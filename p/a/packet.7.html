packet(7) دليل المعلومات المتنوعة packet(7)

الاسم

packet - واجهة الحزمة على مستوى الجهاز

الملخص

#include <sys/socket.h>
#include <linux/if_packet.h>
#include <net/ethernet.h> /* بروتوكولات الطبقة 2 */
packet_socket = socket(AF_PACKET, int socket_type, int protocol);

الوصف

تُستخدم مقابس الحزم لاستقبال أو إرسال حزم خام على مستوى برنامج تشغيل الجهاز (طبقة النظام البصري 2). تسمح للمستخدم بتنفيذ وحدات البروتوكول في مساحة المستخدم فوق الطبقة المادية.

socket_type هي إما SOCK_RAW للحزم الخام بما في ذلك رأس طبقة الارتباط أو SOCK_DGRAM للحزم المعالجة مع إزالة رأس طبقة الارتباط. تتوفر معلومات رأس طبقة الارتباط بتنسيق مشترك في بنية sockaddr_ll. protocol هو رقم بروتوكول IEEE 802.3 بترتيب بايت الشبكة. انظر ملف التضمين <linux/if_ether.h> للحصول على قائمة البروتوكولات المسموح بها. عندما يتم تعيين البروتوكول إلى htons(ETH_P_ALL)، يتم استقبال جميع البروتوكولات. سيتم تمرير جميع الحزم الواردة من هذا النوع البروتوكولي إلى مقبس الحزمة قبل تمريرها إلى البروتوكولات المنفذة في النواة. إذا تم تعيين protocol إلى الصفر، فلا يتم استقبال أي حزم. يمكن استدعاء bind(2) اختياريًا مع sll_protocol غير صفري لبدء استقبال الحزم للبروتوكولات المحددة.

لإنشاء مقبس حزمة، يجب أن تمتلك العملية القدرة CAP_NET_RAW في مساحة اسم المستخدم التي تحكم مساحة اسم شبكتها.

يتم تمرير حزم SOCK_RAW من وإلى برنامج تشغيل الجهاز دون أي تغييرات في بيانات الحزمة. عند استقبال حزمة، لا يزال العنوان يتم تحليله وتمريره في بنية عنوان sockaddr_ll قياسية. عند إرسال حزمة، يجب أن يحتوي المخزن المؤقت الذي يوفره المستخدم على رأس الطبقة المادية. ثم يتم وضع الحزمة في قائمة انتظار دون تعديل إلى برنامج تشغيل الشبكة للواجهة المحددة بواسطة عنوان الوجهة. تضيف بعض برامج تشغيل الأجهزة دائمًا رؤوسًا أخرى. SOCK_RAW مشابهة ولكنها غير متوافقة مع AF_INET/SOCK_PACKET القديمة في Linux 2.0.

يعمل SOCK_DGRAM على مستوى أعلى قليلاً. يتم إزالة رأس الطبقة المادية قبل تمرير الحزمة إلى المستخدم. يتم إرفاق رأس طبقة مادية مناسب للحزم المرسلة عبر مقبس حزمة SOCK_DGRAM بناءً على المعلومات الموجودة في عنوان الوجهة sockaddr_ll قبل وضعها في قائمة الانتظار.

افتراضيًا، يتم تمرير جميع الحزم من نوع البروتوكول المحدد إلى مقبس حزمة. للحصول على حزم من واجهة معينة فقط، استخدم bind(2) مع تحديد عنوان في struct sockaddr_ll لربط مقبس الحزمة بواجهة. الحقول المستخدمة للربط هي sll_family (يجب أن تكون AF_PACKET) و sll_protocol و sll_ifindex.

لا يتم دعم عملية connect(2) على مقابس الحزم.

عند تمرير علامة MSG_TRUNC إلى recvmsg(2) أو recv(2) أو recvfrom(2)، يتم دائمًا إرجاع الحجم الحقيقي للحزمة على السلك، حتى لو كان أطول من المخزن المؤقت.

أنواع العناوين

بنية sockaddr_ll هي عنوان طبقة مادية مستقل عن الجهاز.


struct sockaddr_ll {
    unsigned short sll_family;   /* دائما AF_PACKET */
    unsigned short sll_protocol; /* بروتوكول الطبقة المادية */
    int            sll_ifindex;  /* رقم الواجهة */
    unsigned short sll_hatype;   /* نوع الأجهزة ARP */
    unsigned char  sll_pkttype;  /* نوع الحزمة */
    unsigned char  sll_halen;    /* حجم العنوان */
    unsigned char  sll_addr[8];  /* عنوان الطبقة المادية */
};

حقول هذه البنية هي كالتالي:

sll_protocol
هو نوع بروتوكول الإيثرنت القياسي بترتيب بايت الشبكة كما هو محدد في ملف التضمين <linux/if_ether.h>. الافتراضي هو بروتوكول المقبس.
sll_ifindex
هو فهرس الواجهة للواجهة (انظر netdevice(7))؛ 0 يطابق أي واجهة (مسموح بها فقط للربط). sll_hatype هو نوع ARP كما هو محدد في ملف التضمين <linux/if_arp.h>.
sll_pkttype
يحتوي على نوع الحزمة. الأنواع الصالحة هي PACKET_HOST للحزمة الموجهة إلى المضيف المحلي، PACKET_BROADCAST لحزمة البث على الطبقة المادية، PACKET_MULTICAST لحزمة مرسلة إلى عنوان بث متعدد على الطبقة المادية، PACKET_OTHERHOST لحزمة موجهة إلى مضيف آخر تم التقاطها بواسطة برنامج تشغيل جهاز في وضع الترصد، و PACKET_OUTGOING لحزمة مصدرها المضيف المحلي ويتم إعادتها إلى مقبس حزمة. هذه الأنواع ذات معنى فقط للاستقبال.
sll_addr
sll_halen
تحتوي على عنوان الطبقة المادية (مثل IEEE 802.3) وحجمه. التفسير الدقيق يعتمد على الجهاز.

عند إرسال الحزم، يكفي تحديد sll_family و sll_addr و sll_halen و sll_ifindex و sll_protocol. يجب أن تكون الحقول الأخرى 0. يتم تعيين sll_hatype و sll_pkttype على الحزم المستلمة لمعلوماتك.

خيارات المقبس

يتم تكوين خيارات مقبس الحزمة عن طريق استدعاء setsockopt(2) بالمستوى SOL_PACKET.

PACKET_ADD_MEMBERSHIP
PACKET_DROP_MEMBERSHIP
يمكن استخدام مقابس الحزم لتهيئة بث الطبقة المادية ووضع الترصد. PACKET_ADD_MEMBERSHIP يضيف ربطًا و PACKET_DROP_MEMBERSHIP يسقطه. كلاهما يتوقع بنية packet_mreq كوسيط:

struct packet_mreq {
    int            mr_ifindex;    /* فهرس الواجهة */
    unsigned short mr_type;       /* الإجراء */
    unsigned short mr_alen;       /* حجم العنوان */
    unsigned char  mr_address[8]; /* عنوان الطبقة المادية */
};

يحتوي mr_ifindex على فهرس الواجهة للواجهة التي يجب تغيير حالتها. يحدد حقل mr_type الإجراء المراد تنفيذه. PACKET_MR_PROMISC يمكّن استقبال جميع الحزم على وسيط مشترك (يُعرف غالبًا باسم "وضع الترصد")، PACKET_MR_MULTICAST يربط المقبس بمجموعة البث المتعدد على الطبقة المادية المحددة في mr_address و mr_alen، و PACKET_MR_ALLMULTI يضبط المقبس لاستقبال جميع حزم البث المتعدد التي تصل إلى الواجهة.
بالإضافة إلى ذلك، يمكن استخدام أوامر ioctls التقليدية SIOCSIFFLAGS و SIOCADDMULTI و SIOCDELMULTI لنفس الغرض.
PACKET_AUXDATA (منذ Linux 2.6.21)
إذا تم تمكين هذا الخيار الثنائي، فإن مقبس الحزمة يمرر بنية بيانات وصفية مع كل حزمة في حقل التحكم الخاص بـ recvmsg(2). يمكن قراءة البنية باستخدام cmsg(3). تم تعريفها كالتالي:

struct tpacket_auxdata {
    __u32 tp_status;
    __u32 tp_len;      /* حجم الحزمة */
    __u32 tp_snaplen;  /* حجم الالتقاط */
    __u16 tp_mac;
    __u16 tp_net;
    __u16 tp_vlan_tci;
    __u16 tp_vlan_tpid; /* منذ Linux 3.14؛ سابقًا، كانت هذه
                           بايتات حشو غير مستخدمة */
};

PACKET_FANOUT (منذ Linux 3.1)
لتحسين القياس عبر المواضيع، يمكن لمقابس الحزم تكوين مجموعة fanout. في هذا الوضع، يتم وضع كل حزمة مطابقة في مقبس واحد فقط في المجموعة. ينضم المقبس إلى مجموعة fanout عن طريق استدعاء setsockopt(2).

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

'>setsockopt(2) مع المستوى SOL_PACKET والخيار PACKET_FANOUT. يمكن أن تحتوي كل مساحة شبكة على ما يصل إلى 65536 مجموعة مستقلة. يختار المقبس مجموعة عن طريق ترميز المعرف في أول 16 بت من قيمة الخيار الصحيحة. أول مقبس حزمة ينضم إلى مجموعة يقوم بإنشائها ضمنيًا. للانضمام بنجاح إلى مجموعة موجودة، يجب أن تحتوي مقابس الحزمة اللاحقة على نفس البروتوكول، وإعدادات الجهاز، ووضع التوزيع، والأعلام (انظر أدناه). يمكن لمقابس الحزمة مغادرة مجموعة التوزيع فقط عن طريق إغلاق المقبس. يتم حذف المجموعة عندما يتم إغلاق آخر مقبس.
يدعم التوزيع خوارزميات متعددة لتوزيع حركة المرور بين المقابس، على النحو التالي:
•
الوضع الافتراضي، PACKET_FANOUT_HASH، يرسل الحزم من نفس التدفق إلى نفس المقبس للحفاظ على ترتيب التدفق لكل تدفق. لكل حزمة، يختار مقبسًا عن طريق أخذ تجزئة التدفق للحزمة modulo عدد المقابس في المجموعة، حيث تجزئة التدفق هي تجزئة على عنوان طبقة الشبكة وحقول منفذ طبقة النقل الاختيارية.
•
وضع موازنة التحميل PACKET_FANOUT_LB ينفذ خوارزمية التوزيع الدائري.
•
PACKET_FANOUT_CPU يختار المقبس بناءً على وحدة المعالجة المركزية التي وصلت إليها الحزمة.
•
PACKET_FANOUT_ROLLOVER يعالج جميع البيانات على مقبس واحد، وينتقل إلى التالي عندما يصبح أحدها مكتظًا.
•
PACKET_FANOUT_RND يختار المقبس باستخدام مولد أرقام شبه عشوائية.
•
PACKET_FANOUT_QM (متاح منذ Linux 3.14) يختار المقبس باستخدام تعيين قائمة الانتظار المسجل للحزمة المستلمة skb.
يمكن لوضعيات التوزيع أن تأخذ خيارات إضافية. تسبب تجزئة IP الحزم من نفس التدفق في الحصول على تجزئات تدفق مختلفة. العلم PACKET_FANOUT_FLAG_DEFRAG، إذا تم تعيينه، يتسبب في تجزئة الحزم قبل تطبيق التوزيع، للحفاظ على الترتيب حتى في هذه الحالة. يتم نقل وضع التوزيع والخيارات في آخر 16 بت من قيمة الخيار الصحيحة. العلم PACKET_FANOUT_FLAG_ROLLOVER يمكّن آلية التدوير كاستراتيجية احتياطية: إذا اختار خوارزمية التوزيع الأصلية مقبسًا مكتظًا، فإن الحزمة تدور إلى التالية المتاحة.
PACKET_LOSS (مع PACKET_TX_RING)
عندما يتم مواجهة حزمة مشوهة في حلقة إرسال، يكون الافتراضي هو إعادة تعيين tp_status الخاص بها إلى TP_STATUS_WRONG_FORMAT وإلغاء الإرسال على الفور. الحزمة المشوهة تحجب نفسها والحزم المضافة لاحقًا من الإرسال. يجب إصلاح خطأ التنسيق، وإعادة تعيين tp_status المرتبط إلى TP_STATUS_SEND_REQUEST، وإعادة تشغيل عملية الإرسال عبر send(2). ومع ذلك، إذا تم تعيين PACKET_LOSS، فسيتم تخطي أي حزمة مشوهة، وإعادة تعيين tp_status الخاص بها إلى TP_STATUS_AVAILABLE، وسيتم متابعة عملية الإرسال.
PACKET_RESERVE (مع PACKET_RX_RING)
بشكل افتراضي، تكتب حلقة استقبال الحزم الحزم مباشرة بعد بنية البيانات الوصفية وحشو المحاذاة. يقوم هذا الخيار الصحيح بحجز مساحة رأس إضافية.
PACKET_RX_RING
إنشاء مخزن حلقي مدمج في الذاكرة لاستقبال الحزم غير المتزامن. يقوم مقبس الحزمة بحجز منطقة متجاورة من مساحة عنوان التطبيق، ويرتبها في مصفوفة من فتحات الحزم وينسخ الحزم (حتى tp_snaplen) إلى الفتحات اللاحقة. يسبق كل حزمة بنية بيانات وصفية تشبه tpacket_auxdata. تقوم حقول البروتوكول بتشفير الإزاحة إلى البيانات من بداية رأس البيانات الوصفية. tp_net يخزن الإزاحة إلى طبقة الشبكة. إذا كان مقبس الحزمة من النوع SOCK_DGRAM، فإن tp_mac هو نفسه. إذا كان من النوع SOCK_RAW، فإن هذا الحقل يخزن الإزاحة إلى إطار طبقة الارتباط. يتواصل مقبس الحزمة والتطبيق بين الرأس والذيل للحلقة عبر الحقل tp_status. يمتلك مقبس الحزمة جميع الفتحات التي تكون فيها tp_status مساوية لـ TP_STATUS_KERNEL. بعد ملء فتحة، يغير حالة الفتحة لنقل الملكية إلى التطبيق. أثناء التشغيل العادي، تكون قيمة tp_status الجديدة تحتوي على الأقل على البت TP_STATUS_USER معين للإشارة إلى أنه تم تخزين حزمة مستلمة. عندما ينتهي التطبيق من معالجة حزمة، فإنه ينقل ملكية الفتحة مرة أخرى إلى المقبس عن طريق تعيين tp_status مساويًا لـ TP_STATUS_KERNEL.
تنفيذ مقابس الحزمة أنواعًا متعددة من الحلقة الحزمية. تفاصيل التنفيذ موصوفة في Documentation/networking/packet_mmap.rst في شجرة مصادر نواة Linux.
PACKET_STATISTICS
استرداد إحصائيات مقبس الحزمة في شكل بنية

struct tpacket_stats {
    unsigned int tp_packets;  /* إجمالي عدد الحزم */
    unsigned int tp_drops;    /* عدد الحزم المتساقطة */
};

استقبال الإحصائيات يعيد تعيين العدادات الداخلية. تختلف بنية الإحصائيات عند استخدام حلقة من النوع TPACKET_V3.
PACKET_TIMESTAMP (مع PACKET_RX_RING؛ منذ Linux 2.6.36)
تقوم حلقة استقبال الحزم دائمًا بتخزين طابع زمني في رأس البيانات الوصفية. بشكل افتراضي، هذا طابع زمني تم إنشاؤه بواسطة البرنامج عند نسخ الحزمة إلى الحلقة. يحدد هذا الخيار الصحيح نوع الطابع الزمني. بالإضافة إلى الافتراضي، فهو يدعم تنسيقي الأجهزة الموصوفين في Documentation/networking/timestamping.rst في شجرة مصادر نواة Linux.
PACKET_TX_RING (منذ Linux 2.6.31)
إنشاء مخزن حلقي مدمج في الذاكرة لإرسال الحزم. هذا الخيار مشابه لـ PACKET_RX_RING ويأخذ نفس الوسائط. يكتب التطبيق الحزم في فتحات حيث tp_status مساوٍ لـ TP_STATUS_AVAILABLE وجداولها للإرسال عن طريق تغيير tp_status إلى TP_STATUS_SEND_REQUEST. عندما تكون الحزم جاهزة للإرسال، يستدعي التطبيق send(2) أو متغيرًا منه. يتم تجاهل حقلي buf و len لهذا الاستدعاء. إذا تم تمرير عنوان باستخدام sendto(2) أو sendmsg(2)، فإنه يتجاوز افتراضي المقبس. عند الإرسال بنجاح، يعيد المقبس تعيين tp_status إلى TP_STATUS_AVAILABLE. يلغي فورًا الإرسال عند حدوث خطأ ما لم يتم تعيين PACKET_LOSS.
PACKET_VERSION (مع PACKET_RX_RING؛ منذ Linux 2.6.27)
بشكل افتراضي، يقوم PACKET_RX_RING بإنشاء حلقة استقبال حزم من النوع TPACKET_V1. لإنشاء نوع آخر، قم بتكوين النوع المطلوب عن طريق تعيين هذا الخيار الصحيح قبل إنشاء الحلقة.
PACKET_QDISC_BYPASS (منذ Linux 3.14)
بشكل افتراضي، تمر الحزم المرسلة عبر مقابس الحزم عبر طبقة qdisc (التحكم في حركة المرور) في النواة، وهو أمر جيد لمعظم حالات الاستخدام. بالنسبة لأجهزة مولدات حركة المرور التي تستخدم مقابس الحزم والتي تنوي إغراق الشبكة بالقوة - على سبيل المثال، لاختبار الأجهزة تحت الحمل بطريقة مماثلة لـ pktgen - يمكن تجاوز هذه الطبقة عن طريق تعيين هذا الخيار الصحيح إلى 1. التأثير الجانبي هو تجنب تخزين الحزم المؤقت في طبقة qdisc، مما سيؤدي إلى زيادة التساقطات عندما تكون قوائم انتظار إرسال جهاز الشبكة مشغولة؛ لذلك، استخدم على مسؤوليتك الخاصة.

استدعاءات Ioctls

SIOCGSTAMP يمكن استخدامه لاسترداد الطابع الزمني لآخر حزمة تم استقبالها. الوسيطة هي متغير struct timeval.

بالإضافة إلى ذلك، فإن جميع استدعاءات ioctl القياسية المحددة في netdevice(7) و socket(7) صالحة على مقابس الحزم.

معالجة الأخطاء

لا تجري مقابس الحزم أي معالجة للأخطاء بخلاف الأخطاء التي تحدث أثناء تمرير الحزمة إلى مشغل الجهاز. ليس لديها مفهوم خطأ معلق.

الأخطاء

EADDRNOTAVAIL
عنوان مجموعة بث متعدد غير معروف تم تمريره.
EFAULT
مرر المستخدم عنوان ذاكرة غير صالح.
EINVAL
وسيطة غير صالحة.
EMSGSIZE
الحزمة أكبر من MTU الواجهة.
ENETDOWN
الواجهة ليست قيد التشغيل.
ENOBUFS
لا توجد ذاكرة كافية لتخصيص الحزمة.
ENODEV
اسم جهاز غير معروف أو فهرس واجهة محدد في عنوان الواجهة.
ENOENT
لم يتم استلام حزمة.
ENOTCONN
لم يتم تمرير عنوان واجهة.
ENXIO

NAME

packet - packet interface for the Linux kernel

SYNOPSIS


#include <sys/socket.h>
#include <linux/if_packet.h>
#include <net/ethernet.h>
#include <netinet/if_ether.h>
#include <linux/if_arp.h>

int
sockfd = socket(AF_PACKET, SOCK_RAW, htons(ETH_P_ALL));
int
sockfd = socket(AF_PACKET, SOCK_DGRAM, htons(ETH_P_ALL));

DESCRIPTION

The packet socket interface allows a socket to be bound to a specific network device to receive and/or send raw network frames. It provides a way to send and receive raw packets on the network, bypassing most of the protocol stack. This can be used for device drivers, network testing, firewalls, packet filtering, etc.

When creating a packet socket, the address family must be AF_PACKET. The socket type can be either SOCK_RAW or SOCK_DGRAM.

SOCK_RAW
With SOCK_RAW, the socket receives and sends raw frames. The protocol field in the socket address structure must specify the desired protocol. For example, to receive all Ethernet frames, use htons(ETH_P_ALL). To receive only IP packets, use htons(ETH_P_IP).
SOCK_DGRAM
With SOCK_DGRAM, the socket receives and sends link-layer frames. The protocol field in the socket address structure is used to filter incoming packets. Incoming packets are not multiplexed on the DSAP/SSAP protocol fields; instead, they are supplied to the user as protocol ETH_P_802_2 with the LLC header prefixed. It is thus not possible to bind to ETH_P_802_3; bind to ETH_P_802_2 instead and do the protocol multiplex yourself. The default for sending is the standard Ethernet DIX encapsulation with the protocol filled in.

Packet sockets are not subject to the input or output firewall chains.

Compatibility

In Linux 2.0, the only way to get a packet socket was with the call:


socket(AF_INET, SOCK_PACKET, protocol)

This is still supported, but deprecated and strongly discouraged. The main difference between the two methods is that SOCK_PACKET uses the old struct sockaddr_pkt to specify an interface, which doesn't provide physical-layer independence.


struct sockaddr_pkt {
    unsigned short spkt_family;
    unsigned char  spkt_device[14];
    unsigned short spkt_protocol;
};

spkt_family contains the device type, spkt_protocol is the IEEE 802.3 protocol type as defined in <sys/if_ether.h> and spkt_device is the device name as a null-terminated string, for example, eth0.

This structure is obsolete and should not be used in new code.

ERRORS

EACCES
The user does not have permission to create a packet socket. Creating a raw packet socket requires root privileges.
EINVAL
An invalid argument was supplied. For example, an invalid protocol was specified.
ENETDOWN
The network interface is down.
ENOBUFS
Insufficient buffer space is available.
ENODEV
The specified network device does not exist.
ENOTSUP
The requested protocol is not supported.
EPERM
The user does not have sufficient privileges to perform the requested operation.

VERSIONS

The packet socket interface was introduced in Linux kernel 2.0.

NOTES

When creating a packet socket with SOCK_RAW, the kernel automatically creates the 802.3 frame and fills out the size field; the user has to supply the LLC header to get a fully conforming packet. Incoming 802.3 packets are not multiplexed on the DSAP/SSAP protocol fields; instead they are supplied to the user as protocol ETH_P_802_2 with the LLC header prefixed. It is thus not possible to bind to ETH_P_802_3; bind to ETH_P_802_2 instead and do the protocol multiplex yourself. The default for sending is the standard Ethernet DIX encapsulation with the protocol filled in.

Packet sockets are not subject to the input or output firewall chains.

BUGS

LLC header handling

The IEEE 802.2/803.3 LLC handling could be considered as a bug.

MSG_TRUNC issues

The MSG_TRUNC recvmsg(2) extension is an ugly hack and should be replaced by a control message. There is currently no way to get the original destination address of packets via SOCK_DGRAM.

spkt_device device name truncation

The spkt_device field of sockaddr_pkt has a size of 14 bytes, which is less than the constant IFNAMSIZ defined in <net/if.h> which is 16 bytes and describes the system limit for a network interface name. This means the names of network devices longer than 14 bytes will be truncated to fit into spkt_device. All these sizes include the terminating null byte ('\0')).

Issues from this with old code typically show up with very long interface names used by the Predictable Network Interface Names feature enabled by default in many modern Linux distributions.

The preferred solution is to rewrite code to avoid SOCK_PACKET. Possible user solutions are to disable Predictable Network Interface Names or to rename the interface to a name of at most 13 bytes, for example using the ip(8) tool.

Documentation issues

Socket filters are not documented.
