DESCRIPTION

The Pattern class provides a C++ interface to POSIX regular expressions.

The Pattern class supports the following syntax for its patterns:

  • ERE (Extended Regular Expressions) syntax
  • POSIX character classes
  • POSIX bracket expressions

The following extensions are supported:

  • The REG_ICASE flag may be specified to enable case-insensitive matching.
  • The REG_NOSUB flag may be specified to disable subexpression matching.
  • The REG_UTF8 flag may be specified to enable UTF-8 matching.

The Pattern class supports the following syntax for its patterns:

  • ERE (Extended Regular Expressions) syntax
  • POSIX character classes
  • POSIX bracket expressions

The following extensions are supported:

  • The REG_ICASE flag may be specified to enable case-insensitive matching.
  • The REG_NOSUB flag may be specified to disable subexpression matching.
  • The REG_UTF8 flag may be specified to enable UTF-8 matching.

In addition, the following flags may be specified:

  • REG_EXTENDED: Use Extended Regular Expressions.
  • REG_NEWLINE: The caret (^) matches the empty string at the beginning of the string, and the dollar sign ($) matches the empty string at the end of the string. By default, a newline in the string is not considered a separator, so ^ matches at the beginning of the string, and $ matches at the end of the string, regardless of any newlines. When REG_NEWLINE is in effect, $ matches at the end of the string and also before a newline that is the last character in the string. Similarly, ^ matches at the beginning of the string and also after a newline that is the first character in the string.

CONSTRUCTORS

o
Pattern(std::string const &pattern, bool caseSensitive = true, size_t nSub = 10, int options = REG_EXTENDED | REG_NEWLINE):
Constructs a Pattern object from the given pattern. The caseSensitive parameter determines whether the matching is case-sensitive or not. The nSub parameter determines the maximum number of subexpressions that may be matched. The options parameter is a bitmask of flags that control the matching behavior. See the regcomp(3) manual page for details about the options. If the pattern cannot be compiled, an FBB::Exception is thrown.

MEMBER FUNCTIONS

o
Pattern &before(std::string const &text):
Installs the text as a new pattern. This member function's parameters are identical to the constructor's parameters. Refer to the constructor for details about the parameters. Like the constructor, an FBB::Exception exception is thrown if the new pattern could not be compiled.
o
std::string const &before() const:
Returns the text preceding the first match. If no match has occurred yet, or if the match failed, an empty string is returned.
o
Pattern &beyond(std::string const &text):
Installs the text as a new pattern. This member function's parameters are identical to the constructor's parameters. Refer to the constructor for details about the parameters. Like the constructor, an FBB::Exception exception is thrown if the new pattern could not be compiled.
o
std::string const &beyond() const:
Returns the text succeeding the first match. If no match has occurred yet, or if the match failed, an empty string is returned.
o
std::string const &matched() const:
Returns the text of the first match. If no match has occurred yet, or if the match failed, an empty string is returned.
o
bool match(std::string const &text, int matchOptions = 0):
Attempts to match the text against the pattern. The matchOptions parameter is a bitmask of flags that control the matching behavior. See the regexec(3) manual page for details about the options. Returns true if the match was successful, false otherwise. If the match was successful, the member functions before(), matched(), beyond(), and position() can be used to retrieve information about the match. If the pattern was compiled with the REG_NOSUB flag, this function returns true if the pattern matches the text, and false otherwise. In this case, the member functions before(), matched(), beyond(), and position() are not affected by the match.
o
static size_t end():
Returns the number of subexpressions plus one (for the full match). This value is determined at compile-time by the nSub parameter passed to the constructor or the setPattern() member function.
o
Pattern::Position position(size_t index) const:
With index == 0 the fully matched text is returned (identical to matched()). Other index values return the corresponding subexpressions. std::string::npos, std::string::npos is returned if index is at least end() (which may happen at index value 0).
o
void setPattern(std::string const &pattern, bool caseSensitive = true, size_t nSub = 10, int options = REG_EXTENDED | REG_NEWLINE):
This member function installs a new compiled pattern in its Pattern object. This member’s parameters are identical to the second constructor’s parameters. Refer to that constructor for details about the parameters. Like the constructor, an FBB::Exception exception is thrown if the new pattern could not be compiled.
o
void swap(Pattern &other):
The content of the current object and the other object are swapped.

OVERLOADED OPERATORS

o
std::string operator[](size_t index) const:
Returns the matched text (for index 0) or the text of a subexpression. An empty string is returned for index values which are at least end().
o
Pattern &operator<<(int matchOptions):
Defines match-options to be used with the following overloaded operator.
o
bool operator<<(std::string const &text):
Performs a match(text, matchOptions) call, catching any exception that might be thrown. If no matchOptions were set using the above overloaded operator, none are used. The options set this way are not `sticky’: when necessary, they have to be re-inserted before each new pattern matching. The function returns true if the matching was successful, false otherwise.

EXAMPLE

#include "driver.h"
#include <bobcat/pattern>
using namespace std;
using namespace FBB;
#include <algorithm>
#include <cstring>
void showSubstr(string const &str)
{
    static int count = 0;
    cout << "String " << ++count << " is ’" << str << "’\n";
}
void match(Pattern const &patt, string const &text)
try
{
     Pattern pattern{ patt };
    pattern.match(text);
    Pattern p3(pattern);
    cout << "before:  " << p3.before() << "\n"
            "matched: " << p3.matched() << "\n"
            "beyond:  " << pattern.beyond() << "\n"
            "end() = " << pattern.end() << ’\n’;
    for (size_t idx = 0; idx != pattern.end(); ++idx)
    {
        string str = pattern[idx];
        if (str.empty())
            cout << "part " << idx << " not present\n";
        else
        {
            Pattern::Position pos = pattern.position(idx);
            cout << "part " << idx << ": ’" << str << "’ (" <<
                        pos.first << "-" << pos.second << ")\n";
        }
    }
}
catch (exception const &exc)
{
    cout << exc.what() << ’\n’;
}
int main(int argc, char **argv)
{
    string patStr = R"(\d+)";
    do
    {
        cout << "Pattern: ’" << patStr << "’\n";
        try
        {
                // by default: case sensitive
                // use any args. for case insensitive
            Pattern patt(patStr, argc == 1);
            cout << "Compiled pattern: " << patt.pattern() << ’\n’;
            while (true)
            {
                cout << "string to match : ";
                string text;
                getline(cin, text);
                if (text.empty())
                    break;
                cout << "String: ’" << text << "’\n";
                match(patt, text);
            }
        }
        catch (exception const &exc)
        {
            cout << exc.what() << ": compilation failed\n";
        }
        cout << "New pattern: ";
    }
    while (getline(cin, patStr) and not patStr.empty());
}

BUGS

Using Pattern objects as static data members of classes (or as global objects) is potentially dangerous. If the object files defining these static data members are stored in a dynamic library they may not be initialized properly or timely, and their eventual destruction may result in a segmentation fault. This is a well-known problem with static data, see, e.g., http://www.parashift.com/c++-faq-lite/ctors.html#faq-10.15. In situations like this prefer the use of a (shared, unique) pointer to a Pattern, initializing the pointer when, e.g., first used.
