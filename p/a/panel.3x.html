NAME

panel - curses extension for managing a stack of windows

SYNOPSIS

cc -lpanel -lcurses ... file.c

#include <panel.h>

SCREEN* new_screent( WINDOW* stdscr ); PANEL* new_panel( WINDOW* win ); void del_panel( PANEL* pan ); void hide_panel( PANEL* pan ); void show_panel( PANEL* pan ); void top_panel( PANEL* pan ); void bottom_panel( PANEL* pan ); PANEL* move_panel( PANEL* pan, int y, int x ); int panel_top( void ); PANEL* panel_bottom( void ); PANEL* panel_above( PANEL* pan ); PANEL* panel_below( PANEL* pan ); WINDOW* panel_window( PANEL* pan ); int update_panels( void ); int panel_hidden( PANEL* pan ); void set_panel_userptr( PANEL* pan, void* data ); void* panel_userptr( PANEL* pan ); int panel_connect( void* client_data ); int panel_disconnect( void* client_data );

DESCRIPTION

The panel library provides a mechanism for managing a stack of windows. This can be useful for implementing applications with overlapping windows, dialog boxes, or menus.

A PANEL is a pointer to an internal structure that represents a window in the panel stack. The library keeps track of the order of the panels. The panel at the top of the stack is the one most likely to be visible. When a panel is updated, only the portions of the screen that are not covered by panels above it are refreshed.

The panel library is an extension of the curses library. It uses curses internally, and you must initialize curses using initscr or newterm before calling any panel functions. You must also call endwin when you are finished.

The panel library requires the curses library and the panel library. These should be linked in that order.

FUNCTIONS

The panel library functions are:

new_screent
This function is a wrapper for newterm. It is used internally by the panel library to manage the screen.
new_panel
Creates a new panel associated with the given win window. The new panel is pushed onto the panel stack, above all other panels. The panel is associated with the window win. The window is not cleared or redrawn.
del_panel
Deletes the panel pan from the panel stack and deallocates the panel structure. It does not delete the associated window.
hide_panel
Hides the panel pan. The panel is removed from the stack, and the screen is updated to reflect the change. This is equivalent to calling bottom_panel and then calling update_panels.
show_panel
Makes the panel pan visible. If the panel was previously hidden, it is removed from the hidden list and inserted into the panel stack according to its original position relative to other visible panels. If the panel is already visible, it is moved to the top of the stack.
top_panel
Moves the panel pan to the top of the panel stack. The screen is updated to reflect the change.
bottom_panel
Moves the panel pan to the bottom of the panel stack. The screen is updated to reflect the change.
move_panel
Moves the panel pan to the specified y and x coordinates. The window associated with the panel is not changed, only its position in the stack. The screen is updated.
panel_top
Returns a pointer to the panel at the top of the stack.
panel_bottom
Returns a pointer to the panel at the bottom of the stack.
panel_above
Returns a pointer to the panel directly above the given panel pan in the stack.
panel_below
Returns a pointer to the panel directly below the given panel pan in the stack.
panel_window
Returns a pointer to the window associated with the panel pan.
update_panels
Updates the virtual screen to reflect the current state of the panel stack. This function should be called after any changes to the panel stack (e.g., adding, deleting, hiding, showing, or moving panels). After calling update_panels, you must call doupdate to refresh the physical screen.
panel_hidden
Returns true if the panel pan is hidden, false otherwise.
set_panel_userptr
Sets the user-defined pointer for the panel pan to data. This can be used to associate arbitrary data with a panel.
panel_userptr
Returns the user-defined pointer for the panel pan.
panel_connect
Connects to the panel server, passing client_data as client data.
panel_disconnect
Disconnects from the panel server, using client_data.

RETURN VALUE

Functions that return a pointer to a PANEL structure return NULL on error. Functions that return an int return 0 on success and -1 on error.

NOTES

The panel library is a curses extension, and all panel functions must be called between calls to initscr (or newterm) and endwin.

The functions show_panel and top_panel work with displayed or hidden panels. show_panel makes a hidden panel visible and inserts it into the stack. top_panel moves an already-visible panel to the top of the stack.

The panel library is not part of the X/Open Curses standard.

PORTABILITY

The panel library is based on the System V Release 4 (SVr4) panel library. The ncurses and PDCurses implementations provide compatible interfaces.

In the System V implementation, show_panel is intended for making a hidden panel visible (at the top of the stack) and top_panel is intended for making an already-visible panel move to the top of the stack. You are cautioned to use the correct function to ensure compatibility with System V panel libraries.

HISTORY

A panel facility was documented in SVr4.2's Character User Interface Programming document.

It is not part of X/Open Curses.

A few implementations exist:

  • Systems based on SVr4 source code, such as Solaris, provide this library.
  • ncurses (since version 0.6 in 1993) and PDCurses (since version 2.2 in 1995) provide a panel library whose common ancestor is a public domain implementation by Warren Tucker published in u386mon 2.20 (1990).
According to Tucker, the System V panel library was first released in SVr3.2 (1988), and his implementation helped with a port to SVr3.1 (1987).
Several developers have improved each of these; they are no longer the same as Tucker's implementation.
•
NetBSD 8 (2018) has a panel library begun by Valery Ushakov in 2015, based on the System V documentation.

AUTHORS

Warren Tucker <wht@n4hgf.mt-park.ga.us> originally wrote this implementation, primarily to assist in porting u386mon to systems without a native panel library.

Zeyd ben-Halim repackaged it for ncurses.

Juergen Pfeifer and Thomas E. Dickey revised and improved the library.
