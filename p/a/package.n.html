package(n)

الحزمة: tcl

التراخيص: TCL

package(n) أوامر Tcl المدمجة package(n)

الاسم

package - تسهيلات لتحميل الحزم وإدارة الإصدارات

الموجز

package forget ?package package ...?
package ifneeded package version ?script?
package names
package present package ?requirement...?
package present -exact package version
package provide package ?version?
package require package ?requirement...?
package require -exact package version
package unknown ?command?
package vcompare version1 version2
package versions package
package vsatisfies version requirement...
package prefer ?latest|stable?

الوصف

يقوم هذا الأمر بالاحتفاظ بقاعدة بيانات بسيطة للحزم المتاحة للاستخدام من قبل المفسر الحالي وكيفية تحميلها في المفسر. يدعم إصدارات متعددة لكل حزمة ويرتب تحميل الإصدار الصحيح للحزمة بناءً على ما هو مطلوب بواسطة التطبيق. يكتشف هذا الأمر أيضًا تعارضات الإصدارات ويبلغ عنها. عادةً، يتم استدعاء الأوامر package require و package provide فقط في نصوص Tcl العادية؛ تُستخدم الأوامر الأخرى بشكل أساسي بواسطة نصوص النظام التي تحتفظ بقاعدة بيانات الحزم.

يتم تحديد سلوك الأمر package بواسطة وسيطته الأولى. الأشكال التالية مسموح بها:

package forget ?package package ...?
يزيل جميع المعلومات المتعلقة بكل حزمة محددة من هذا المفسر، بما في ذلك المعلومات المقدمة بواسطة كل من package ifneeded و package provide.
package ifneeded package version ?script?
يظهر هذا الأمر عادةً فقط في نصوص تكوين النظام لإعداد قاعدة بيانات الحزم. يشير إلى أن إصدارًا معينًا من حزمة معينة متاح إذا لزم الأمر، وأنه يمكن إضافة الحزمة إلى المفسر عن طريق تنفيذ script. يتم حفظ النص في قاعدة بيانات لاستخدام أوامر package require اللاحقة؛ عادةً، يقوم script بإعداد التحميل التلقائي للأوامر في الحزمة (أو استدعاء load و/أو source مباشرة)، ثم يستدعي package provide للإشارة إلى أن الحزمة موجودة. قد تكون هناك معلومات في قاعدة البيانات لعدة إصدارات مختلفة لحزمة واحدة. إذا كانت قاعدة البيانات تحتوي بالفعل على معلومات لـ package و version، فإن script الجديد يحل محل القائم. إذا تم حذف وسيطة script، فسيتم إرجاع النص الحالي للإصدار version من الحزمة package، أو سلسلة فارغة إذا لم يتم استدعاء أمر package ifneeded لهذه الحزمة package والإصدار version.
package names
يعيد قائمة بأسماء جميع الحزم في المفسر التي تم تقديم إصدار لها (عبر package provide) أو التي يتوفر لها نص package ifneeded. ترتيب العناصر في القائمة عشوائي.
package present ?-exact? package ?requirement...?
هذا الأمر يعادل package require باستثناء أنه لا يحاول تحميل الحزمة إذا لم تكن محملة بالفعل.
package provide package ?version?
يتم استدعاء هذا الأمر للإشارة إلى أن الإصدار version من الحزمة package موجود حاليًا في المفسر. يتم استدعاؤه عادةً مرة واحدة كجزء من نص ifneeded، ومرة أخرى بواسطة الحزمة نفسها عند تحميلها في النهاية. يحدث خطأ إذا تم تقديم إصدار مختلف من package بواسطة أمر package provide سابق. إذا تم حذف وسيطة version، فإن الأمر يعيد رقم الإصدار الذي تم تقديمه حاليًا، أو سلسلة فارغة إذا لم يتم استدعاء أمر package provide للحزمة package في هذا المفسر.
package require package ?requirement...?
يتم استدعاء هذا الأمر عادةً بواسطة كود Tcl الذي يرغب في استخدام إصدار معين من حزمة معينة. تشير الوسائط إلى الحزمة المطلوبة، ويتأكد الأمر من تحميل إصدار مناسب للحزمة في المفسر. إذا نجح الأمر، فإنه يعيد رقم الإصدار الذي تم تحميله؛ وإلا فإنه يولد خطأ.

الإصدار المناسب للحزمة هو أي إصدار يلبي متطلبًا واحدًا على الأقل، وفقًا لقواعد package vsatisfies. إذا كانت هناك عدة إصدارات مناسبة، يتم اختيار التنفيذ ذي الإصدار الأعلى. يتأثر هذا الجزء الأخير أيضًا بوضع التحديد المحدد باستخدام package prefer.

في وضع التحديد "stable" (مستقر)، سيختار الأمر أعلى إصدار مستقر يلبي المتطلبات، إن وجد. إذا لم يلبي أي إصدار مستقر المتطلبات، فسيتم اختيار أعلى إصدار غير مستقر يلبي المتطلبات. في وضع التحديد "latest" (الأحدث)، سيقبل الأمر أعلى إصدار يلبي جميع المتطلبات، بغض النظر عن استقراره.

إذا تم تقديم إصدار من package بالفعل (عن طريق استدعاء الأمر package provide)، فيجب أن يفي رقم الإصدار بالمتطلبات requirements ويعود الأمر فورًا. بخلاف ذلك، يبحث الأمر في قاعدة بيانات المعلومات المقدمة بواسطة أوامر package ifneeded السابقة لمعرفة ما إذا كان هناك إصدار مقبول للحزمة متاحًا. إذا كان الأمر كذلك، يتم تقييم النص الخاص بأعلى إصدار مقبول في النطاق العام؛ يجب أن يقوم بكل ما هو ضروري لتحميل الحزمة، بما في ذلك استدعاء package provide للحزمة. إذا لم تحتوِ قاعدة بيانات package ifneeded على إصدار مقبول للحزمة وتم تحديد أمر package unknown للمفسر، فسيتم تقييم هذا الأمر في النطاق العام؛ عند اكتماله، يتحقق Tcl مرة أخرى لمعرفة ما إذا كانت الحزمة مقدمة الآن أو إذا كان هناك نص package ifneeded لها. إذا فشلت كل هذه الخطوات في توفير إصدار مقبول للحزمة، فإن الأمر يعيد خطأ.

package require -exact package version
يستخدم هذا الشكل من الأمر عندما يكون الإصدار المحدد version من الحزمة package فقط هو المقبول للمتصل. هذا الأمر يعادل package require package version-version.
package unknown ?command?
يقوم هذا الأمر بتوفير أمر "الملاذ الأخير" لاستدعائه أثناء package require إذا لم يتم العثور على إصدار مناسب لحزمة في قاعدة بيانات package ifneeded. إذا تم توفير وسيطة command، فإنها تحتوي على الجزء الأول من أمر؛ عند استدعاء الأمر أثناء أمر package require، يلحق Tcl وسيطة أو أكثر إضافية تعطي اسم الحزمة المطلوب والمتطلبات. على سبيل المثال، إذا كان command هو foo bar ولاحقًا تم استدعاء الأمر package require test 2.4، فسيقوم Tcl بتنفيذ الأمر foo bar test 2.4 لتحميل الحزمة. إذا لم يتم توفير متطلبات لأمر package require، فسيتم فقط إضافة الاسم إلى الأمر المستدعى. إذا تم تحديد الأمر package unknown كسلسلة فارغة، فسيتم إزالة نص package unknown الحالي، إن وجد. إذا تم استدعاء package unknown بدون وسيطة command، فسيتم إرجاع نص package unknown الحالي، أو سلسلة فارغة إذا لم يكن هناك نص.
package vcompare version1 version2
يقارن رقمي الإصدار version1 و version2. يعيد -1 إذا كان version1 إصدارًا أقدم من version2، و 0 إذا كانا متساويين، و 1 إذا كان version1 أحدث من version2.
package versions package
يعيد قائمة بجميع أرقام إصدارات الحزمة package التي تم تقديم معلومات لها بواسطة أوامر package ifneeded.
package vsatisfies version requirement...
يعيد 1 إذا كان version يلبي متطلبًا واحدًا على الأقل من المتطلبات المعطاة، و 0 غ

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

package(n)

NAME

package, package prefer — Manage Tcl package loading and status

SYNOPSIS

package require ?-exact? packageName ?version?
package provide packageName ?version?
package versions packageName ?pattern?
package present ?-exact? packageName ?version?
package unknown ?script?
package prefer ?latest|stable?

DESCRIPTION

These commands are used to manage the loading and availability of packages within Tcl scripts. A package is a collection of Tcl code that is intended to be shared among multiple scripts. Packages typically define new commands or procedures, and may also change the behavior of existing commands.

The core commands are package require and package provide.

package provide packageName ?version?

Declares that the current Tcl interpreter provides the package packageName with the given version. If version is omitted, it defaults to 0.

package require ?-exact? packageName ?version?

Requests that the package packageName with at least the specified version be loaded. If version is omitted, it defaults to 0. If the -exact flag is given, the requested version must match exactly. If the package is not already loaded, Tcl will attempt to find and load it. If a suitable version cannot be found or loaded, an error is raised. Otherwise, the command returns the actual version of the package that was loaded.

The process of finding and loading packages is determined by the unknown script set by the package unknown command. By default, this script attempts to load the package by running source on a file named packageName.tcl in a directory specified by the auto_path variable. If -exact is not specified, the requested version must satisfy the requirement specified.

package versions packageName ?pattern?

Returns a list of all versions of packageName that are currently available to the interpreter. If pattern is specified, only versions matching the glob-style pattern are returned.

package present ?-exact? packageName ?version?

Checks if a package is available, returning the actual version loaded if it is, or an empty string otherwise. This command does not attempt to load packages. The version argument specifies the minimum acceptable version (or exact version if -exact is given).

package unknown ?script?

Controls how Tcl attempts to load packages that are not already loaded. If called with no arguments, it returns the current unknown script. If called with a script argument, that script is installed as the new unknown script. The default unknown script attempts to load the package using the standard Tcl library search paths.

Package version requirements are specified as follows:

min
This form is called “min-bounded”.
min-
This form is called “min-unbound”.
min-max
This form is called “bounded”.

where “min” and “max” are valid version numbers. The legacy syntax is a special case of the extended syntax, keeping backward compatibility. Regarding satisfaction the rules are:

[1]
The version has to pass at least one of the listed requirements to be satisfactory.
[2]
A version satisfies a “bounded” requirement when
[a]
For min equal to the max if, and only if the version is equal to the min.
[b]
Otherwise if, and only if the version is greater than or equal to the min, and less than the max, where both min and max have been padded internally with “a0”. Note that while the comparison to min is inclusive, the comparison to max is exclusive.
[3]
A “min-bounded” requirement is a “bounded” requirement in disguise, with the max part implicitly specified as the next higher major version number of the min part. A version satisfies it per the rules above.
[4]
A version satisfies a “min-unbound” requirement if, and only if it is greater than or equal to the min, where the min has been padded internally with “a0”. There is no constraint to a maximum.
package prefer ?latest|stable?
With no arguments, the commands returns either “latest” or “stable”, whichever describes the current mode of selection logic used by package require.

When passed the argument “latest”, it sets the selection logic mode to “latest”.

When passed the argument “stable”, if the mode is already “stable”, that value is kept. If the mode is already “latest”, then the attempt to set it back to “stable” is ineffective and the mode value remains “latest”.

When passed any other value as an argument, raise an invalid argument error.

When an interpreter is created, its initial selection mode value is set to “stable” unless the environment variable TCL_PKG_PREFER_LATEST is set. If that environment variable is defined (with any value) then the initial (and permanent) selection mode value is set to “latest”.

VERSION NUMBERS

Version numbers consist of one or more decimal numbers separated by dots, such as 2 or 1.162 or 3.1.13.1. The first number is called the major version number. Larger numbers correspond to later versions of a package, with leftmost numbers having greater significance. For example, version 2.1 is later than 1.3 and version 3.4.6 is later than 3.3.5. Missing fields are equivalent to zeroes: version 1.3 is the same as version 1.3.0 and 1.3.0.0, so it is earlier than 1.3.1 or 1.3.0.2. In addition, the letters “a” (alpha) and/or “b” (beta) may appear exactly once to replace a dot for separation. These letters semantically add a negative specifier into the version, where “a” is -2, and “b” is -1. Each may be specified only once, and “a” or “b” are mutually exclusive in a specifier. Thus 1.3a1 becomes (semantically) 1.3.-2.1, 1.3b1 is 1.3.-1.1. Negative numbers are not directly allowed in version specifiers. A version number not containing the letters “a” or “b” as specified above is called a stable version, whereas presence of the letters causes the version to be called is unstable. A later version number is assumed to be upwards compatible with an earlier version number as long as both versions have the same major version number. For example, Tcl scripts written for version 2.3 of a package should work unchanged under versions 2.3.2, 2.4, and 2.5.1. Changes in the major version number signify incompatible changes: if code is written to use version 2.1 of a package, it is not guaranteed to work unmodified with either version 1.7.3 or version 3.1.

PACKAGE INDICES

The recommended way to use packages in Tcl is to invoke package require and package provide commands in scripts, and use the procedure pkg_mkIndex to create package index files. Once you have done this, packages will be loaded automatically in response to package require commands. See the documentation for pkg_mkIndex for details.

EXAMPLES

To state that a Tcl script requires the Tk and http packages, put this at the top of the script:

package require Tk
package require http

To test to see if the Snack package is available and load if it is (often useful for optional enhancements to programs where the loss of the functionality is not critical) do this:

if {[catch {package require Snack}]} {
    # Error thrown - package not found.
    # Set up a dummy interface to work around the absence
} else {
    # We have the package, configure the app to use it
}
