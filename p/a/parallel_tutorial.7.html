دليل GNU Parallel

يوضح هذا الدليل الكثير من وظائف GNU parallel. الغرض من الدليل هو تعلم الخيارات والصياغة الخاصة بـ GNU parallel. الدليل ليس لعرض أمثلة واقعية من العالم الحقيقي.

دليل القارئ

إذا كنت تفضل قراءة كتاب، فاشترِ GNU Parallel 2018 من https://www.lulu.com/shop/ole-tange/gnu-parallel-2018/paperback/product-23558902.html أو قم بتنزيله من: https://doi.org/10.5281/zenodo.1146014

بخلاف ذلك، ابدأ بمشاهدة الفيديوهات التمهيدية للحصول على مقدمة سريعة: https://www.youtube.com/playlist?list=PL284C9FF2488BC6D1

ثم تصفح الأمثلة (man parallel_examples). سيمنحك ذلك فكرة عما يمكن أن يفعله GNU parallel.

إذا كنت ترغب في التعمق أكثر: اقضِ بضع ساعات في استعراض الدليل (man parallel_tutorial). ستشكرك سطر الأوامر الخاص بك على ذلك.

أخيرًا، قد ترغب في الاطلاع على بقية الدليل (man parallel) إذا كانت لديك احتياجات خاصة لم يتم تناولها بالفعل.

إذا كنت ترغب في معرفة القرارات التصميمية وراء GNU parallel، جرب: man parallel_design. هذا أيضًا مقدمة جيدة إذا كنت تنوي تعديل GNU parallel.

سيظل معظم الدليل يعمل على الإصدارات الأقدم أيضًا.

ملف abc:
يمكن إنشاء الملف بهذا الأمر: 
parallel -k echo ::: A B C > abc-file
ملف def:
يمكن إنشاء الملف بهذا الأمر: 
parallel -k echo ::: D E F > def-file
ملف abc0:
يمكن إنشاء الملف بهذا الأمر: 
perl -e 'printf "A\0B\0C\0"' > abc0-file
ملف abc_:
يمكن إنشاء الملف بهذا الأمر: 
perl -e 'printf "A_B_C_"' > abc_-file
ملف tsv-file.tsv
يمكن إنشاء الملف بهذا الأمر: 
perl -e 'printf "f1\tf2\nA\tB\nC\tD\n"' > tsv-file.tsv
num8
يمكن إنشاء الملف بهذا الأمر: 
perl -e 'for(1..8){print "$_\n"}' > num8
num128
يمكن إنشاء الملف بهذا الأمر: 
perl -e 'for(1..128){print "$_\n"}' > num128
num30000
يمكن إنشاء الملف بهذا الأمر: 
perl -e 'for(1..30000){print "$_\n"}' > num30000
num1000000
يمكن إنشاء الملف بهذا الأمر: 
perl -e 'for(1..1000000){print "$_\n"}' > num1000000
num_%header
يمكن إنشاء الملف بهذا الأمر: 
(echo %head1; echo %head2; \
 perl -e 'for(1..10){print "$_\n"}') > num_%header
fixedlen
يمكن إنشاء الملف بهذا الأمر: 
perl -e 'print "HHHHAAABBBCCC"' > fixedlen
للتشغيل عن بعد: يجب أن يعمل تسجيل الدخول عبر SSH على خادمين بدون كلمة مرور في $SERVER1 و $SERVER2.
SERVER1=server.example.com
SERVER2=server2.example.net

لذلك يجب أن تكون قادرًا على القيام بذلك دون إدخال كلمة مرور:

ssh $SERVER1 echo works
ssh $SERVER2 echo works

يمكن إعداده عن طريق تشغيل ssh-keygen -t dsa; ssh-copy-id $SERVER1 واستخدام عبارة مرور فارغة، أو يمكنك استخدام ssh-agent.

مصادر الإدخال

يقرأ GNU parallel المدخلات من مصادر الإدخال. يمكن أن تكون هذه ملفات، سطر الأوامر، والمدخل القياسي (stdin) (الإدخال القياسي أو الأنبوب).

مصدر إدخال واحد

يمكن قراءة الإدخال من سطر الأوامر:

parallel echo ::: A B C

المخرجات (قد يكون الترتيب مختلفًا لأن المهام تعمل بالتوازي):

A
B
C

يمكن أن يكون مصدر الإدخال ملفًا:

parallel -a abc-file echo

المخرجات: نفس ما سبق.

يمكن أن يكون المدخل القياسي (STDIN) هو مصدر الإدخال:

cat abc-file | parallel echo

المخرجات: نفس ما سبق.

مصادر إدخال متعددة

يمكن لـ GNU parallel أخذ مصادر إدخال متعددة محددة في سطر الأوامر. يقوم GNU parallel بعد ذلك بإنشاء جميع التركيبات لمصادر الإدخال:

parallel echo ::: A B C ::: D E F

المخرجات (قد يكون الترتيب مختلفًا):

A D
A E
A F
B D
B E
B F
C D
C E
C F

يمكن أن تكون مصادر الإدخال ملفات:

parallel -a abc-file -a def-file echo

المخرجات: نفس ما سبق.

يمكن أن يكون المدخل القياسي (STDIN) أحد مصادر الإدخال باستخدام -:

cat abc-file | parallel -a - -a def-file echo

المخرجات: نفس ما سبق.

بدلاً من -a، يمكن تقديم الملفات بعد :::::

cat abc-file | parallel echo :::: - def-file

المخرجات: نفس ما سبق.

يمكن خلط ::: و :::::

parallel echo ::: A B C :::: def-file

المخرجات: نفس ما سبق.

ربط الوسائط من مصادر الإدخال

باستخدام --link، يمكنك ربط مصادر الإدخال والحصول على وسيط واحد من كل مصدر إدخال:

parallel --link echo ::: A B C ::: D E F

المخرجات (قد يكون الترتيب مختلفًا):

A D
B E
C F

إذا كان أحد مصادر الإدخال قصيرًا جدًا، فستلتف قيمه:

parallel --link echo ::: A B C D E ::: F G

المخرجات (قد يكون الترتيب مختلفًا):

A F
B G
C F
D G
E F

لربط أكثر مرونة، يمكنك استخدام :::+ و ::::+. تعمل هذه مثل ::: و :::: باستثناء أنها تربط مصدر الإدخال السابق بمصدر الإدخال هذا.

سيؤدي هذا إلى ربط ABC بـ GHI:

parallel echo :::: abc-file :::+ G H I :::: def-file

المخرجات (قد يكون الترتيب مختلفًا):

A G D
A G E
A G F
B H D
B H E
B H F
C I D
C I E
C I F

سيؤدي هذا إلى ربط GHI بـ DEF:

parallel echo :::: abc-file ::: G H I ::::+ def-file

المخرجات (قد يكون الترتيب مختلفًا):

A G D
A H E
A I F
B G D
B H E
B I F
C G D
C H E
C I F

إذا كان أحد مصادر الإدخال قصيرًا جدًا عند استخدام :::+ أو ::::+، فسيتم تجاهل الباقي:

parallel echo ::: A B C D E :::+ F G

المخرجات (قد يكون الترتيب مختلفًا):

A F
B G

تغيير فاصل الوسائط.

يمكن لـ GNU parallel استخدام فواصل أخرى غير ::: أو ::::. يكون هذا مفيدًا عادةً إذا تم استخدام ::: أو :::: في الأمر المراد تشغيله:

parallel --arg-sep ,, echo ,, A B C ::

تحتاج بعض المهام إلى قاعدة بيانات مشتركة لجميع المهام. يمكن لـ GNU parallel نقل هذه القاعدة باستخدام --basefile والذي سينقل الملف قبل المهمة الأولى:

echo common data > common_file
parallel --basefile common_file -S $ SERVER1 \
  cat common_file\; echo {} ::: foo

النتيجة:

common data
foo

لإزالته من الجهاز البعيد بعد المهمة الأخيرة، استخدم --cleanup.

مجلد العمل

مجلد العمل الافتراضي على الأجهزة البعيدة هو مجلد تسجيل الدخول. يمكن تغيير هذا باستخدام --workdir mydir.

ستكون الملفات المنقولة باستخدام --transferfile و --return نسبية لمجلد mydir على أجهزة الكمبيوتر البعيدة، وسيتم تنفيذ الأمر في المجلد mydir.

ستقوم القيمة الخاصة mydir وهي ... بإنشاء مجلدات عمل تحت ~/.parallel/tmp على أجهزة الكمبيوتر البعيدة. إذا تم توفير --cleanup، فستتم إزالة هذه المجلدات.

القيمة الخاصة mydir وهي . تستخدم مجلد العمل الحالي. إذا كان مجلد العمل الحالي تحت مجلد المنزل الخاص بك، فسيتم التعامل مع القيمة . كمسار نسبي لمجلد المنزل الخاص بك. هذا يعني أنه إذا كان مجلد المنزل الخاص بك مختلفًا على أجهزة الكمبيوتر البعيدة (على سبيل المثال، إذا كان تسجيل الدخول الخاص بك مختلفًا)، فسيظل المسار النسبي نسبيًا لمجلد المنزل الخاص بك.

parallel -S $ SERVER1 pwd ::: ""
parallel --workdir . -S $ SERVER1 pwd ::: ""
parallel --workdir ... -S $ SERVER1 pwd ::: ""

النتيجة:

[مجلد تسجيل الدخول على $ SERVER1]
[مجلد العمل الحالي النسبي على $ SERVER1]
[مجلد في ~/.parallel/tmp/...]

تجنب التحميل الزائد على sshd

إذا تم تشغيل العديد من المهام على نفس الخادم، فقد يتم التحميل الزائد على sshd. يمكن لـ GNU parallel إدخال تأخير بين كل مهمة يتم تشغيلها على نفس الخادم:

parallel -S $ SERVER1 --sshdelay 0.2 echo ::: 1 2 3

النتيجة (قد يختلف الترتيب):

1
2
3

سيتم تحميل sshd بشكل أقل إذا تم استخدام --controlmaster، والذي سيقوم بتنويع اتصالات SSH:

parallel --controlmaster -S $ SERVER1 echo ::: 1 2 3

النتيجة: نفس ما سبق.

تجاهل المضيفين المعطلين

في المجموعات التي تضم العديد من المضيفين، غالبًا ما يكون عدد قليل منها معطلاً. يمكن لـ GNU parallel تجاهل هؤلاء المضيفين. في هذه الحالة، المضيف 173.194.32.46 معطل:

parallel --filter-hosts -S 173.194.32.46,$ SERVER1 echo ::: bar

النتيجة:

bar

تشغيل نفس الأوامر على جميع المضيفين

يمكن لـ GNU parallel تشغيل نفس الأمر على جميع المضيفين:

parallel --onall -S $ SERVER1,$ SERVER2 echo ::: foo bar

النتيجة (قد يختلف الترتيب):

foo
bar
foo
bar

غالبًا ما سترغب فقط في تشغيل أمر واحد على جميع المضيفين بدون وسيطات. --nonall هو --onall بدون وسيطات:

parallel --nonall -S $ SERVER1,$ SERVER2 echo foo bar

النتيجة:

foo bar
foo bar

عند استخدام --tag مع --nonall و --onall، يكون --tagstring هو المضيف:

parallel --nonall --tag -S $ SERVER1,$ SERVER2 echo foo bar

النتيجة (قد يختلف الترتيب):

$ SERVER1 foo bar
$ SERVER2 foo bar

--jobs يحدد عدد الخوادم التي سيتم تسجيل الدخول إليها بالتوازي.

نقل متغيرات البيئة والدوال

env_parallel هي دالة shell تنقل جميع الأسماء المستعارة والدوال والمتغيرات والمصفوفات. يمكنك تفعيلها عن طريق التشغيل:

source `which env_parallel.bash`

استبدل bash بالمفسر الذي تستخدمه.

الآن يمكنك استخدام env_parallel بدلاً من parallel ولا يزال لديك بيئتك:

alias myecho=echo
myvar="Joe's var is"
env_parallel -S $ SERVER1 'myecho $myvar' ::: green

النتيجة:

Joe's var is green

Semaphore

يمكن لـ GNU parallel العمل كـ counting semaphore. هذا أبطأ وأقل كفاءة من وضعه العادي.

يشبه counting semaphore صفًا من المراحيض. الأشخاص الذين يحتاجون إلى مرحاض يمكنهم استخدام أي مرحاض، ولكن إذا كان عدد الأشخاص أكبر من عدد المراحيض، فسيتعين عليهم الانتظار حتى يصبح أحد المراحيض متاحًا.

اسم بديل لـ parallel --semaphore هو sem.

سيتبع sem شخصًا إلى المراحيض، وينتظر حتى يصبح المرحاض متاحًا، ويترك الشخص في المرحاض ويخرج.

sem --fg سيتبع شخصًا إلى المراحيض، وينتظر حتى يصبح المرحاض متاحًا، ويبقى مع الشخص في المرحاض ويخرج عندما يخرج الشخص.

sem --wait سينتظر حتى يغادر جميع الأشخاص المراحيض.

لا يمتلك sem انضباط طابور، لذا يتم اختيار الشخص التالي عشوائيًا.

يحدد -j عدد المراحيض.

Mutex

الافتراضي هو وجود مرحاض واحد فقط (وهذا يسمى mutex). يبدأ البرنامج في الخلفية ويخرج sem فورًا. استخدم --wait للانتظار حتى تنتهي جميع أوامر sem:

sem 'sleep 1; echo The first finished' &&
  echo The first is now running in the background &&
  sem 'sleep 1; echo The second finished' &&
  echo The second is now running in the background
sem --wait

المخرجات:

The first is now running in the background
The first finished
The second is now running in the background
The second finished

يمكن تشغيل الأمر في الواجهة الأمامية باستخدام --fg، والذي لن يخرج إلا عند اكتمال الأمر:

sem --fg 'sleep 1; echo The first finished' &&
  echo The first finished running in the foreground &&
  sem --fg 'sleep 1; echo The second finished' &&
  echo The second finished running in the foreground
sem --wait

الفرق بين هذا وبين تشغيل الأمر ببساطة هو أنه يتم تعيين mutex، بحيث إذا كانت هناك أوامر sem أخرى تعمل في الخلفية، فلن يعمل سوى واحد في كل مرة.

للتحكم في أي semaphore يتم استخدامه، استخدم --semaphorename/--id. قم بتشغيل هذا في طرفية واحدة:

sem --id my_id -u 'echo First started; sleep 10; echo First done'

وفي نفس الوقت قم بتشغيل هذا في طرفية أخرى:

sem --id my_id -u 'echo Second started; sleep 10; echo Second done'

لاحظ كيف أن الأمر الثاني لن يبدأ إلا بعد انتهاء الأمر الأول.

Counting semaphore

يشبه mutex وجود مرحاض واحد: عندما يكون قيد الاستخدام، سيتعين على الآخرين الانتظار. يشبه counting semaphore وجود عدة مراحيض: يمكن لعدة أشخاص استخدام المراحيض، ولكن عندما تكون جميعها قيد الاستخدام، سيتعين على الآخرين الانتظار.

يمكن لـ sem محاكاة counting semaphore. استخدم --jobs لتحديد عدد المراحيض على النحو التالي:

sem --jobs 3 --id my_id -u 'echo Start 1; sleep 5; echo 1 done' &&
sem --jobs 3 --id my_id -u 'echo Start 2; sleep 6; echo 2 done' &&
sem --jobs 3 --id my_id -u 'echo Start 3; sleep 7; echo 3 done' &&
sem --jobs 3 --id my_id -u 'echo Start 4; sleep 8; echo 4 done' &&
sem --wait --id my_id

المخرجات:

Start 2
Start 3
1 done
Start 4
2 done
3 done
4 done

sem --id foo -u 'echo Slow started; sleep 5; echo Slow ended' &&
sem --id foo --semaphoretimeout 1 'echo Forced running after 1 sec' &&

GNU Parallel Tutorial

                    
This tutorial is for GNU Parallel 20150522.
                        

                        Copyleft 2010-2015 Ole Tange, Free Software Foundation.
                        

                        License GFDLv1.3+: GNU Free Documentation License version 1.3 or later
                        https://www.gnu.org/licenses/fdl-1.3.html.
                        

                        This is free documentation: you can redistribute it and/or modify it.
                        

                        It is not warranted to be useful or for any purpose.

                

                

                    
Prerequisites

                    
You need to have GNU Parallel installed.

                    
You need to have a computer with more than one CPU core.

                    
sudo apt-get install parallel

                

                

                    
Input sources

                    
GNU Parallel can read input from stdin, from a file, or from a list of arguments.

                    
parallel echo ::: A B C
echo A B C | parallel echo
parallel echo :::: file.txt

                    
The last example reads one line from file.txt and passes it as an argument to echo.

                    
If you want GNU Parallel to read multiple lines from a file use:

                    
parallel echo :::: file.txt

                    
This is equivalent to:

                    
cat file.txt | parallel echo

                    
The most common way to provide input is with --args:

                    
parallel echo --args A B C

                    
For example, to find all files larger than 10MB:

                    
find . -type f -size +10M | parallel ls -lh

                    
To find all files modified in the last 24 hours:

                    
find . -type f -mtime -1 | parallel ls -lh

                

                

                    
Building the command line

                    
By default GNU Parallel appends the input arguments to the command line.

                    
parallel echo ::: A B C
# Output:
# A
# B
# C

                    
To insert the arguments in the middle of the command line use {}.

                    
parallel echo Processing file {} ::: A B C
# Output:
# Processing file A
# Processing file B
# Processing file C

                    
This is useful for commands that take the filename as an argument, but not as the last argument.

                    
parallel convert {} -resize 50% small-{} ::: *.jpg
# This converts all jpg files to smaller versions.

                    
The {} can be replaced by the job sequence number {#}.

                    
parallel echo Job {#} started ::: A B C
# Output:
# Job 1 started
# Job 2 started
# Job 3 started

                    
You can also use {.} to get the basename without suffix.

                    
parallel echo Processing file {.} ::: *.jpg
# This will print "Processing file foo" for each file foo.jpg.

                    
And {/} to get the basename.

                    
parallel echo Processing file {/} ::: dir/subdir/foo.jpg
# Output:
# Processing file foo.jpg

                    
And {..} to get the dirname.

                    
parallel echo Processing file {..} ::: dir/subdir/foo.jpg
# Output:
# Processing file dir/subdir

                    
And {%} to get the extension.

                    
parallel echo Processing file {%} ::: dir/subdir/foo.jpg
# Output:
# Processing file jpg

                

                

                    
Controlling the output

                    
By default the output is printed to stdout.

                    
Use --results to save output to files.

                    
parallel --results outputdir echo ::: A B C
# This will create files outputdir/A, outputdir/B, outputdir/C with the output.

                    
You can specify the output file name using {}.

                    
parallel --results outputdir/{} echo ::: A B C

                    
Use --joblog to log job information.

                    
parallel --joblog joblog.txt echo ::: A B C

                    
Use --resume to resume jobs.

                    
parallel --joblog joblog.txt --resume echo ::: A B C

                    
Use --timeout to set a timeout for each job.

                    
parallel --timeout 10 sleep {} ::: 5 15

                    
Use --eta to show estimated time of arrival.

                    
parallel --eta sleep 5 ::: $(seq 1 10)

                    
Use --bar to show a progress bar.

                    
parallel --bar sleep 1 ::: $(seq 1 10)

                

                

                    
Controlling the execution

                    
By default GNU Parallel runs as many jobs in parallel as there are CPU cores.

                    
Use -j to specify the number of jobs.

                    
parallel -j 2 echo ::: A B C D
# Runs 2 jobs in parallel.

                    
Use -j 0 to run as many jobs as possible.

                    
Use -j 100% to run as many jobs as possible.

                    
Use -j 50% to run half as many jobs as possible.

                    
Use --nice to set the niceness of the jobs.

                    
parallel --nice 10 echo ::: A B C D

                    
Use --delay to set a delay between jobs.

                    
parallel --delay 5 echo ::: A B C D

                

                

                    
Remote execution

                    
GNU Parallel can run jobs on remote machines using SSH.

                    
parallel --sshlogin server1,server2 echo ::: A B C

                    
You can specify the number of jobs per host:

                    
parallel --sshlogin server1 --onall echo ::: A B C

                    
Or specify the number of parallel jobs on each host:

                    
parallel --sshlogin server1 --jobs 4 echo ::: A B C

                    
Use --skip to skip a host if SSH fails.

                    
Use --timeout to set a timeout for remote jobs.

                    
See also man parallel and parallel --citation.

                    
parallel --cleanup
parallel --onall
--nonall

--pipe          Split stdin (standard input) to multiple jobs.
--recend str    Record end separator for --pipe.
--recstart str  Record start separator for --pipe.

See 'man parallel' for details

Saving output to shell variables (advanced)

                    
You can save the output of GNU Parallel to shell variables.

                    
eval $(parallel --results /tmp/parallel-joblog echo ::: A B C)

                    
This will create shell variables like /tmp/parallel-joblog/A.

                

                

                    
Saving to an SQL base (advanced)

                    
GNU Parallel can save output to an SQL database.

                    
parallel --sql sqlite3:output.db echo ::: A B C

                

                

                    
Shebang

                    
You can use GNU Parallel in scripts by adding the shebang line:

                    
#!/usr/bin/parallel --shpart

                    
Example:

                    
#!/usr/bin/parallel --shpart
# The rest of the script is executed by parallel
echo "Hello World"
sleep 2
echo "Done"


                

                

                    
Semaphore

                    
You can use semaphores to limit the number of parallel jobs that access a resource.

                    
parallel --semaphore --semaphore-joblog sem.log -j 10 --eta echo ::: $(seq 1 100)

                    
This will run echo jobs, but only 10 at a time can access the resource protected by the semaphore.

Profiles

                    
The defaults for GNU parallel can be changed systemwide by
                        putting the command line options in /etc/parallel/config. They can be
                        changed for a user by putting them in ~/.parallel/config.

                    
Profiles work the same way, but have to be referred to with
                        --profile:

                    
echo '--nice 17' > ~/.parallel/nicetimeout
echo '--timeout 300%' >> ~/.parallel/nicetimeout
parallel --profile nicetimeout echo ::: A B C

                    
Output:

                    
A
B
C

                    
Profiles can be combined:

                    
echo '-vv --dry-run' > ~/.parallel/dryverbose
parallel --profile dryverbose --profile nicetimeout echo ::: A B C

                    
Output:

                    
echo A
echo B
echo C
