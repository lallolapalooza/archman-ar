Params__Validate(3pm)

الحزمة: perl-params-validate

Params::Validate(3pm) User Contributed Perl Documentation Params::Validate(3pm)

الاسم

Params::Validate - التحقق من صحة معلمات الطرق/الوظائف

الإصدار

version 1.31

الملخص

use Params::Validate qw(:all);
# تأخذ معلمات مسماة (تجزئة أو مرجع تجزئة)
sub foo {
    validate(
        @_, {
            foo => 1,    # مطلوب
            bar => 0,    # اختياري
        }
    );
}
# تأخذ معلمات موضعية
sub bar {
    # أول اثنتين مطلوبة، الثالثة اختيارية
    validate_pos( @_, 1, 1, 0 );
}
sub foo2 {
    validate(
        @_, {
            foo =>
                # تحديد نوع
                { type => ARRAYREF },
            bar =>
                # تحديد واجهة
                { can => [ 'print', 'flush', 'frobnicate' ] },
            baz => {
                type      => SCALAR,     # قيمة عددية ...
                                         # ... يجب أن تكون عددًا صحيحًا عاديًا ...
                regex     => qr/^\d+$/,
                callbacks => {           # ... وأصغر من 90
                    'أقل من 90' => sub { shift() < 90 },
                },
            }
        }
    );
}
sub callback_with_custom_error {
    validate(
        @_,
        {
            foo => {
                callbacks => {
                    'عدد صحيح' => sub {
                        return 1 if $_[0] =~ /^-?[1-9][0-9]*$/;
                        die "$_[0] ليست قيمة عدد صحيح صالحة";
                    },
                },
            }
        }
    );
}
sub with_defaults {
    my %p = validate(
        @_, {
            # مطلوب
            foo => 1,
            # ستكون $p{bar} تساوي 99 إذا لم يتم تقديم bar. bar الآن
            # اختياري.
            bar => { default => 99 }
        }
    );
}
sub pos_with_defaults {
    my @p = validate_pos( @_, 1, { default => 99 } );
}
sub sets_options_on_call {
    my %p = validate_with(
        params => \@_,
        spec   => { foo => { type => SCALAR, default => 2 } },
        normalize_keys => sub { $_[0] =~ s/^-//; lc $_[0] },
    );
}

الوصف

أوصي بشدة بأن تفكر في استخدام Params::ValidationCompiler بدلاً من ذلك. هذه الوحدة، على الرغم من كونها Perl نقية، إلا أنها أسرع بشكل ملحوظ من هذه الوحدة، مقابل تكلفة تبني نظام أنواع مثل Specio، Type::Tiny، أو النظام الذي يأتي مع Moose.

تتيح لك هذه الوحدة التحقق من صحة معلمات استدعاء الطريقة أو الوظيفة بمستوى عشوائي من التحديد. في أبسط مستوياتها، فهي قادرة على التحقق من أن المعلمات المطلوبة تم تقديمها وأنه لم يتم تمرير معلمات إضافية غير محددة.

وهي أيضًا قادرة على تحديد أن معلمة من نوع معين، أو أنها كائن من تسلسل هرمي لفئة معينة، أو أنها تمتلك طرقًا معينة، أو تطبيق استدعاءات تحقق على الوسائط.

تصدير

تقوم الوحدة دائمًا بتصدير الدوال validate() و validate_pos().

لديها أيضًا وظيفة إضافية متاحة للتصدير، "validate_with"، والتي يمكن استخدامها للتحقق من أي نوع من المعلمات، وتعيين خيارات مختلفة على أساس كل استدعاء.

بالإضافة إلى ذلك، يمكنها تصدير الثوابت التالية، والتي تستخدم كجزء من التحقق من النوع. هذه هي "SCALAR"، "ARRAYREF"، "HASHREF"، "CODEREF"، "GLOB"، "GLOBREF"، و "SCALARREF"، "UNDEF"، "OBJECT"، "BOOLEAN"، و "HANDLE". يتم شرح هذه في قسم التحقق من النوع.

الثوابت متاحة عبر العلامة ":types" المصدرة. هناك أيضًا علامة ":all" التي تتضمن جميع الثوابت بالإضافة إلى الدالة validation_options().

التحقق من صحة المعلمات

يمكن لآليات التحقق التي توفرها هذه الوحدة التعامل مع معلمات مسماة أو موضعية. في الغالب، تتوفر نفس الميزات لكليهما. الاختلاف الأكبر هو الطريقة التي يتم بها تقديم مواصفات التحقق إلى الروتين الفرعي ذي الصلة. الاختلاف الآخر هو في رسائل الخطأ التي يتم إنتاجها عند فشل فحوصات التحقق.

عند التعامل مع المعلمات المسماة، ستقبل الوحدة إما تجزئة أو مرجع تجزئة.

يجب على الروتينات الفرعية التي تتوقع معلمات مسماة استدعاء الروتين الفرعي validate() هكذا:

validate(
    @_, {
        parameter1 => validation spec,
        parameter2 => validation spec,
        ...
    }
);

يجب على الروتينات الفرعية التي تتوقع معلمات موضعية استدعاء الروتين الفرعي validate_pos() هكذا:

validate_pos( @_, { validation spec }, { validation spec } );

المعلمات المطلوبة/الاختيارية

إذا كنت ترغب فقط في تحديد أن بعض المعلمات مطلوبة وأن البعض الآخر اختياري، فيمكن القيام بذلك ببساطة شديدة.

بالنسبة لروتين فرعي يتوقع معلمات مسماة، ستقوم بما يلي:

validate( @_, { foo => 1, bar => 1, baz => 0 } );

هذا يعني أن معلمتي "foo" و "bar" مطلوبتان وأن معلمة "baz" اختيارية. وجود أي معلمات أخرى سيؤدي إلى حدوث خطأ.

بالنسبة لروتين فرعي يتوقع معلمات موضعية، ستقوم بما يلي:

validate_pos( @_, 1, 1, 0, 0 );

هذا يعني أنك تتوقع ما لا يقل عن 2 ولا يزيد عن 4 معلمات. إذا كان لديك روتين فرعي يحتوي على الحد الأدنى من المعلمات ولكنه يمكن أن يأخذ أي عدد أقصى، يمكنك القيام بما يلي:

validate_pos( @_, 1, 1, (0) x (@_ - 2) );

سيكون هذا صحيحًا دائمًا طالما تم تقديم معلمتين على الأقل. يمكن استخدام بنية مماثلة للمعلمات التحقق الأكثر تعقيدًا الموضحة لاحقًا.

يرجى ملاحظة أن هذا:

validate_pos( @_, 1, 1, 0, 1, 1 );

ليس له أي معنى على الإطلاق، لذا لا تفعل ذلك. يجب أن تأتي أي أصفار في نهاية مواصفات التحقق.

بالإضافة إلى ذلك، إذا حددت أن معلمة يمكن أن يكون لها قيمة افتراضية، فإنها تعتبر اختيارية.

التحقق من النوع

تدعم هذه الوحدة الأنواع البسيطة التالية، والتي يمكن تصديرها كثوابت:

  • SCALAR

    قيمة عددية ليست مرجعًا، مثل 10 أو 'hello'. القيمة غير المعرفة لا تُعامل كقيمة عددية. إذا كنت تريد السماح بالقيم غير المعرفة، فستحتاج إلى تحديد "SCALAR | UNDEF".

  • ARRAYREF

    مرجع مصفوفة مثل "[1, 2, 3]" أو "\@foo".

  • HASHREF

    مرجع تجزئة مثل "{ a => 1, b => 2 }" أو "\%bar".

  • CODEREF

    مرجع لدالة فرعية مثل "\&foo_sub" أو "sub { print "hello" }".

  • GLOB

    هذه صعبة بعض الشيء. سيكون الـ glob شيئًا مثل *FOO، ولكن ليس "\*FOO"، وهو مرجع glob. تجدر الإشارة إلى أن هذه الحيلة:

    my $fh = do { local *FH; };

    تجعل $fh قيمة glob، وليس مرجع glob. من ناحية أخرى، فإن القيمة المرجعة من "Symbol::gensym" هي مرجع glob. يمكن استخدام أي منهما كمقبض ملف أو دليل.

  • GLOBREF

    مرجع glob مثل "\*FOO". انظر إدخال GLOB أعلاه لمزيد من التفاصيل.

  • SCALARREF

    مرجع لقيمة عددية مثل "\$x".

  • UNDEF

    قيمة غير معرفة

  • OBJECT

    مرجع مبارك.

  • BOOLEAN

    هذا خيار خاص، وهو مجرد اختصار لـ "UNDEF | SCALAR".

  • HANDLE

    هذا الخيار خاص أيضًا، وهو مجرد اختصار لـ "GLOB | GLOBREF". ومع ذلك، يبدو من المحتمل أن يكون معظم الأشخاص المهتمين إما بالـ globs أو بـ glob references مهتمين حقًا بما إذا كان المعلمة قيد الفحص يمكن أن تكون مقبض ملف أو دليل صالحًا.

لتحديد أن المعلمة يجب أن تكون من نوع معين عند استخدام معلمات مسماة، قم بما يلي:

validate(
    @_, {
        foo => { type => SCALAR },
        bar => { type => HASHREF }
    }
);

إذا كانت المعلمة يمكن أن تكون من أكثر من نوع واحد، فاستخدم عامل التشغيل OR الثنائي (bitwise or) ("|") لدمجها.

validate( @_, { foo => { type => GLOB | GLOBREF } );

بالنسبة للمعلمات الموضعية، يمكن تحديد ذلك على النحو التالي:

validate_pos( @_, { type => SCALAR | ARRAYREF }, { type => CODEREF } );

التحقق من الواجهة

لتحديد أن المعلمة يُتوقع أن تحتوي على مجموعة معينة من الطرق، يمكننا القيام بما يلي:

   validate(
       @_, {
           foo =>
               # يجب أن تكون قادرة على ->bar فقط
               { can => 'bar' }
       }
   );
... أو ...
   validate(
       @_, {
           foo =>
               # يجب أن تكون قادرة على ->bar و ->print
               { can => [qw( bar print )] }
       }
   );

التحقق من الفئة

كلمة تحذير. عند بناء واجهاتك الخارجية، من الأفضل ربما تحديد الطرق التي تتوقع أن يمتلكها الكائن بدلاً من الفئة التي يجب أن ينتمي إليها (أو فئة فرعية منها). سيجعل هذا واجهة برمجة التطبيقات (API) الخاصة بك أكثر مرونة.

مع أخذ ذلك في الاعتبار، إذا كنت ترغب في التحقق من أن المعلمة الواردة تنتمي إلى فئة (أو فئة فرعية) أو فئات، فقم بما يلي:

   validate(
       @_,
       { foo => { isa => 'My::Frobnicator' } }
   );
... أو ...
   validate(
       @_,
       # يجب أن يكونا كلاهما، وليس أي منهما!
       { foo => { isa => [qw( My::Frobnicator IO::Handle )] } }
   );

التحقق من التعبيرات العادية

إذا كنت ترغب في تحديد أن المعلمة المعطاة يجب أن تتطابق مع تعبير عادي محدد، يمكن القيام بذلك باستخدام مفتاح المواصفات "regex". على سبيل المثال:

validate(
    @_,
    { foo => { regex => qr/^\d+$/ } }
);

قد تكون قيمة "regex" إما سلسلة نصية أو تعبير عادي تم تجميعه مسبقًا تم إنشاؤه عبر "qr".

إذا كانت القيمة التي يتم التحقق منها مقابل تعبير عادي غير محددة، يتم فحص التعبير العادي بشكل صريح مقابل السلسلة الفارغة ('')، لتجنب تحذيرات "استخدام قيمة غير مهيأة".

الوحدة "Regexp::Common" على CPAN هي مصدر ممتاز للتعبيرات العادية المناسبة للتحقق من صحة الإدخال.

التحقق من الاستدعاء

إذا لم يكن أي مما سبق كافياً، فمن الممكن تمرير استدعاء واحد أو أكثر للتحقق من صحة المعلمة. سيتم إعطاء الاستدعاء قيمة المعلمة كوسيط أول لها. الوسيط الثاني سيكون جميع المعلمات، كمرجع إما لهاش أو مصفوفة. يتم تحديد الاستدعاءات كمرجع لهاش. المفتاح هو معرف للاستدعاء (يستخدم في رسائل الخطأ) والقيمة هي مرجع لروتين فرعي، مثل:

validate(
    @_,
    {
        foo => {
            callbacks => {
                'smaller than a breadbox' => sub { shift() < $breadbox },
                'green or blue'           => sub {
                    return 1 if $_[0] eq 'green' || $_[0] eq 'blue';
                    die "$_[0] is not green or blue!";
                }
            }
        }
    }
);
validate(
    @_, {
        foo => {
            callbacks => {
                'bigger than baz' => sub { $_[0] > $_[1]->{baz} }
            }
        }
    }
);

يجب أن يعيد الاستدعاء قيمة حقيقية إذا كانت القيمة صالحة. إذا لم يكن كذلك، يمكن أن يعيد قيمة خاطئة أو يموت. إذا قمت بإرجاع قيمة خاطئة، فسيتم طرح رسالة خطأ عامة بواسطة "Params::Validate".

إذا مات الاستدعاء بدلاً من ذلك، يمكنك توفير رسالة خطأ مخصصة. إذا مات الاستدعاء بسلسلة نصية عادية، فسيتم إلحاق هذه السلسلة برسالة استثناء تم إنشاؤها بواسطة "Params::Validate". إذا مات الاستدعاء بمرجع (مبارك أو غير مبارك)، فسيتم إعادة إطلاقه كما هو بواسطة "Params::Validate".

إلغاء التدليس

إذا كنت تريد أن تكون القيم غير مدلسة، قم بتعيين المفتاح "untaint" في مواصفات الهاش إلى قيمة حقيقية، كالتالي:

my %p = validate(
    @_, {
        foo => { type => SCALAR, untaint => 1 },
        bar => { type => ARRAYREF }
    }
);

سيؤدي هذا إلى إلغاء تدليس المعلمة "foo" إذا كانت المعلمات صالحة.

لاحظ أنه لا يتم إلغاء التدليس إلا إذا كانت جميع المعلمات صالحة. أيضًا، فقط قيم الإرجاع هي التي يتم إلغاء تدليسها، وليس القيم الأصلية التي تم تمريرها إلى دالة التحقق.

طلب إلغاء تدليس قيمة مرجعية لن يفعل شيئًا، حيث أن "Params::Validate" سيحاول فقط إلغاء تدليس المرجع نفسه.

الإلزامية/الاختيارية - نظرة أخرى

إذا كنت ترغب في تحديد شيء مثل النوع أو الواجهة، بالإضافة إلى حقيقة أن المعلمة يمكن أن تكون اختيارية، فقم بما يلي:

validate(
    @_, {
        foo => { type => SCALAR },
        bar => { type => ARRAYREF, optional => 1 }
    }
);

أو هذا للمعلمات الموضعية:

validate_pos(
    @_,
    { type => SCALAR },
    { type => ARRAYREF, optional => 1 }
);

افتراضيًا، تُفترض المعلمات أنها إلزامية ما لم يتم تحديدها على أنها اختيارية.

التبعيات

من الممكن أيضًا تحديد أن معلمة اختيارية معينة تعتمد على وجود معلمة اختيارية أخرى واحدة أو أكثر.

validate(
    @_, {
        cc_number => {
            type     => SCALAR,
            optional => 1,
            depends  => [ 'cc_expiration', 'cc_holder_name' ],
        },
        cc_expiration  => { type => SCALAR, optional => 1 },
        cc_holder_name => { type => SCALAR, optional => 1 },
    }
);

في هذه الحالة، "cc_number" و "cc_expiration" و "cc_holder_name" كلها اختيارية. ومع ذلك، إذا تم توفير "cc_number"، فيجب أيضًا توفير "cc_expiration" و "cc_holder_name".

يتيح لك هذا تجميع مجموعات من المعلمات التي يجب توفيرها معًا.

نسخة validate_pos() من التبعيات مختلفة قليلاً، حيث يمكنك الاعتماد على معلمة أخرى واحدة فقط. أيضًا، إذا كانت المعلمة الثانية، على سبيل المثال، تعتمد على المعلمة الرابعة، فإنها تعني ضمنًا تبعية على المعلمة الثالثة أيضًا. هذا لأنه إذا كانت المعلمة الرابعة مطلوبة، فيجب على المستخدم أيضًا توفير معلمة ثالثة حتى يكون هناك أربع معلمات في المجموع.

"Params::Validate" سيموت إذا حاولت الاعتماد على معلمة غير معلنة كجزء من مواصفات معلمتك.

تحديد القيم الافتراضية

إذا تم استدعاء الدوال validate() أو validate_pos() في سياق قائمة، فستعيد تجزئة أو تحتوي على المعلمات الأصلية بالإضافة إلى القيم الافتراضية كما هو موضح في مواصفات التحقق.

إذا لم يتم استدعاء الدالة في سياق قائمة، فإن توفير قيمة افتراضية في مواصفات التحقق لا يزال يشير إلى أن المعلمة اختيارية.

التجزئة أو المصفوفة التي تم إرجاعها من الدالة ستكون دائمًا نسخة من المعلمات الأصلية، وذلك لترك @_ دون تغيير للدالة المستدعية.

أمثلة بسيطة للقيم الافتراضية ستكون:

my %p = validate( @_, { foo => 1, bar => { default => 99 } } );
my @p = validate_pos( @_, 1, { default => 99 } );

في سياق القياسي، سيتم إرجاع مرجع تجزئة أو مرجع مصفوفة، حسب الاقتضاء.

ملاحظات الاستخدام

فشل التحقق

افتراضيًا، عند فشل التحقق، تستدعي "Params::Validate" Carp::confess(). يمكن تجاوز هذا عن طريق تعيين الخيار "on_fail"، والذي تم وصفه في قسم "OPTIONS GLOBAL".

استدعاءات الدوال

عند استخدام هذه الوحدة للتحقق من صحة المعلمات التي تم تمريرها إلى استدعاء دالة، قد ترغب في إزالة الفئة/الكائن من قائمة المعلمات قبل استدعاء validate() أو validate_pos(). إذا كانت دالتك تتوقع معلمات مسماة، فهذا ضروري لكي تعمل دالة validate() بالفعل، وإلا فإن @_ لن تكون قابلة للاستخدام كتجزئة، لأنها ستحتوي أولاً على الكائن الخاص بك (أو الفئة) متبوعًا بمجموعة من المفاتيح والقيم.

لذلك، فإن الاستخدام الاصطلاحي لـ validate() في استدعاء دالة سيبدو كالتالي:

sub method {
    my $self = shift;
    my %params = validate(
        @_, {
            foo => 1,
            bar => { type => ARRAYREF },
        }
    );
}

تسريع التحقق

في معظم الحالات، ستظل مواصفات التحقق كما هي لكل استدعاء لدالة فرعية. في هذه الحالة، يمكنك تسريع التحقق عن طريق تحديد مواصفات التحقق مرة واحدة فقط، بدلاً من كل استدعاء للدالة الفرعية:

my %spec = ( ... );
sub foo {
    my %params = validate( @_, \%spec );
}

يمكنك أيضًا استخدام

Mantén toda la estructura del archivo.

Utiliza la funcionalidad "state" para realizar esto:

use feature 'state';
sub foo {
    state $spec = { ... };
    my %params = validate( @_, $spec );
}

"GLOBAL" OPTIONS

Porque la API para las funciones validate() y validate_pos() no permite especificar cualquier opción aparte de la especificación de validación, es posible establecer algunas opciones como "globales pseudométricos". Estas permiten especificar cosas como si la validación de parámetros nombrados debe ser sensible al caso, por ejemplo.

Estas opciones se denominan "globales pseudométricos" porque estas configuraciones se aplican sólo a llamadas que provengan del paquete que establece las opciones.

En otras palabras, si estoy en el paquete "Foo" y llamo a validation_options(), estos ajustes solo se aplican cuando llamo a validate() desde el mismo paquete "Foo".

Aunque esto es bastante diferente de cómo operan otros módulos, me siento que es necesario para permitir que una sola módulo/aplicación use Params::Validate mientras continúe utilizando otros módulos que también usen Params::Validate, tal vez con opciones diferentes.

La desventaja es que si estás escribiendo una aplicación con estilo de invocación estándar para todas las funciones y tu aplicación tiene diez módulos, cada módulo debe incluir una llamada a validation_options(). Puedes escribir un módulo que todos tus módulos usen que use trucos para hacer esto cuando se importe.

Options

  • normalize_keys => $callback

    Esta opción es relevante solo cuando se trata de parámetros nombrados.

    Este callback se utilizará para transformar las claves del hash de ambos los parámetros y la especificación de parámetros cuando se llame a validate() o validate_with().

    Cualquier alteración realizada por este callback se reflejará en el hash de parámetros devuelto por la función de validación. Por ejemplo:

    sub foo {
        return validate_with(
            params => \@_,
            spec   => { foo => { type => SCALAR } },
            normalize_keys =>
                sub { my $k = shift; $k =~ s/^-//; return uc $k },
        );
    }
    %p = foo( foo => 20 );
    # $p{FOO} es ahora 20
    %p = foo( -fOo => 50 );
    # $p{FOO} es ahora 50

    El callback debe retornar un valor definido.

    Si se proporciona un callback, los opciones antiguas ignore_case y strip_leading se ignoran.

  • allow_extra => $boolean

    Si es verdadero, la rutina de validación permitirá parámetros no nombrados en la especificación de validación. En el caso de parámetros posicionales, permite un número ilimitado de parámetros máximos (aunque un mínimo puede aún ser establecido). Por defecto es falso.

  • on_fail => $callback

    Si se proporciona, este callback se llama cuando se produce una verificación de validación que falle. Se le pasa un único parámetro, que será una cadena describiendo la falla. Esto es útil si deseas que este módulo lances objetos en lugar de strings, por ejemplo.

    Este callback es esperado para die() internamente. Si no lo hace, la validación continuará con resultados impredecibles.

    El default es usar la función confess() de Carp por defecto.

  • stack_skip => $number

    Este indica a Params::Validate cuántos frames de pila deben ser omitidos cuando se busca el nombre de la subroutine para mensajes de error. Por defecto, busca uno frame atrás, en el llamador inmediato a validate() o validate_pos(). Si esta opción se establece, se omiten el número dado.

  • ignore_case => $boolean

    DEPRECATED

    Esta es solo relevante cuando se tratan parámetros nombrados. Si es verdadero, el código de validación ignorará el caso de los nombres de parámetros. Por defecto es falso.

  • strip_leading => $characters

    DEPRECATED

    Esta también es solo relevante cuando se tratan parámetros nombrados. Si se proporciona, cualquier parámetro que comience con estos caracteres se considera equivalente a uno que no lo tenga. Por ejemplo, si se especifica '-', "-foo" y "foo" se consideran idénticos.

PER-INVOCATION OPTIONS

La función validate_with() puede usarse para establecer las opciones listadas anteriormente de forma per-invocación. Por ejemplo:

my %p = validate_with(
    params => \@_,
    spec   => {
        foo => { type    => SCALAR },
        bar => { default => 10 }
    },
    allow_extra => 1,
);

Además de las opciones listadas anteriormente, también es posible establecer la opción called, que debe ser una cadena. Esta cadena se utilizará en cualquier mensaje de error causado por una falla en la especificación de validación.

Esta subrutina validará los parámetros nombrados como un hash si el parámetro spec es un referencia a un hash. Si es un arreglo, los parámetros se asumen como posicionales.

my %p = validate_with(
    params => \@_,
    spec   => {
        foo => { type    => SCALAR },
        bar => { default => 10 }
    },
    allow_extra => 1,
    called      => 'The Quux::Baz class constructor',
);
my @p = validate_with(
    params => \@_,
    spec   => [
        { type    => SCALAR },
        { default => 10 }
    ],
    allow_extra => 1,
    called      => 'The Quux::Baz class constructor',
);

DISABLING VALIDATION

Si la variable entorno "PERL_NO_VALIDATION" está establecida a algo verdadero, se desactiva la validación. Esto puede ser útil si solo quieres usar este módulo durante el desarrollo pero no quieres el impacto de la velocidad en producción.

La única error que se capturará será cuando se le pasen un número impar de parámetros a una función o método que espera un hash.

Si quieres activar y desactivar la validación en tiempo de ejecución, puedes directamente establecer la variable global $Params::Validate::NO_VALIDATION. Es fuertemente recomendado que localices cualquier cambio a esta variable, ya que otros módulos que estés usando puedan esperar que la validación esté activa cuando se ejecuten. Por ejemplo:

{
    local $Params::Validate::NO_VALIDATION = 1;
    # no error
    foo( bar => 2 );
}
# error
foo( bar => 2 );
sub foo {
    my %p = validate( @_, { foo => 1 } );
    ...;
}

Pero si quieres dispararte la pierna y simplemente apagarla, hazlo!

SPECIFYING AN IMPLEMENTATION

Este módulo viene con dos implementaciones equivalentes, una en XS y otra en Perl pura. Por defecto, intentará cargar la versión XS y se basará en la implementación Perl pura cuando sea necesario. Si quieres solicitar una versión específica, puedes establecer la variable entorno "PARAMS_VALIDATE_IMPLEMENTATION" en "XS" o "PP". Si la implementación que solicitas no puede cargarse, este módulo se cargará y se crashará.

TAINT MODE

La implementación XS del módulo tiene algunos problemas bajo modo taint con versiones de Perl anteriores a 5.14. Si la validación falla, en lugar de recibir el mensaje de error esperado, obtendrás un mensaje como Insecure dependency in eval_sv. Esto puede ser trabajado alrededor con una desactivación de taint manual, usando la implementación Perl pura o actualizando tu Perl.

LIMITATIONS

Hasta ahora no hay manera (a menos de un callback) de especificar que algo debe ser de una lista de clases o que debe poseer una lista de métodos. Si deseas esto, puede agregarse en el futuro.

Idealmente, habría solo una función de validación. Si alguien figura out cómo hacer esto, por favor avísame.
