الاسم

pam_yubico - وحدة للمصادقة YubiKey

الملخص

pam_yubico [...]

الوصف

الوحدة مخصصة للمصادقة على YubiKeys، إما مع التحقق عبر الإنترنت من OTP، أو التحقق دون اتصال مع HMAC-SHA1 تحدي-استجابة.

خيارات

debug

تشغيل التصحيح.

debug_file=ملف

اسم الملف لكتابة التصحيح إليه، يجب أن يكون الملف موجودًا وأن يكون ملفًا عاديًا. الافتراضي هو stdout.

mode=[client|challenge-response]

وضع التشغيل، client للمصادقة على OTP و challenge-response للمصادقة على تحدي-استجابة. الافتراضي هو client.

authfile=ملف

موقع الملف الذي يحتوي على تعيينات معرفات YubiKey المميزة إلى أسماء المستخدمين. التنسيق هو username:first_public_id:second_public_id:... الموقع الافتراضي للملف هو $HOME/.yubico/authorized_yubikeys.

id=id

معرف عميل API الخاص بك لخادم التحقق.

key=key

مفتاح العميل الخاص بك بتنسيق base64. يُعرف مفتاح العميل أيضًا باسم مفتاح API، ويوفر السلامة في الاتصال بين العميل (أنت) وخادم التحقق. إذا كنت ترغب في الحصول على واحد لاستخدامه مع خدمة YubiCloud الافتراضية، يرجى الذهاب إلى: https://upgrade.yubico.com/getapikey/

alwaysok

النجاح في جميع محاولات المصادقة (خطير، وضع العرض).

try_first_pass

قبل مطالبة المستخدم بكلمة المرور الخاصة به، تحاول الوحدة أولاً كلمة المرور من الوحدة المكدسة السابقة في حال كانت تفي بمتطلبات هذه الوحدة أيضًا.

use_first_pass

تجبر الوحدة على استخدام كلمة مرور من وحدات مكدسة سابقة ولن تطالب المستخدم أبدًا - إذا لم تكن هناك كلمة مرور متاحة أو لم تكن كلمة المرور مناسبة، فسيتم رفض وصول المستخدم.

always_prompt

إذا تم تعيينه، فلن تحاول إجراء بحث لتحديد ما إذا كان المستخدم لديه YubiKey مهيأة، بل ستطالب بواحدة بغض النظر عن أي شيء. هذا مفيد في حالة تمكين ldap_bind_as_user ولكن يتم استخدام هذه الوحدة لقراءة كلمة مرور المستخدم (في سيناريو مصادقة YubiKey + OTP).

nullok

لا تفشل عندما لا تكون هناك رموز مميزة معلنة للمستخدم في ملفات تعيين الترخيص أو في LDAP. يمكن استخدام هذا لجعل مصادقة YubiKey اختيارية ما لم يكن المستخدم قد قام بإقران رموز مميزة.

ldap_starttls

إذا تم تعيينه، قم بإصدار أمر STARTTLS لاتصال LDAP قبل محاولة ربطه به. هذا إعداد شائع للخوادم التي تستمع فقط على المنفذ 389 ولكنها لا تزال تتطلب TLS.

ldap_bind_as_user

استخدم المستخدم الذي يقوم بتسجيل الدخول للربط بـ ldap. سيستخدم هذا كلمة المرور المقدمة من المستخدم عبر PAM. إذا تم تعيين هذا، فيجب أيضًا تعيين ldapdn و uid_attr. سيؤدي تمكين هذا إلى تجاهل ldap_bind_user و ldap_bind_password.

urllist=قائمة

قائمة قوالب عناوين URL المراد استخدامها. يتم تعيين هذا عن طريق استدعاء ykclient_set_url_bases. يجب أن تكون القائمة بالتنسيق: https://api1.example.com/wsapi/2.0/verify;https://api2.example.com/wsapi/2.0/verify

url=url

لا ينبغي استخدام هذا الخيار، يرجى استخدام خيار urllist بدلاً من ذلك. قم بتعيين قالب عنوان URL المراد استخدامه، يتم تعيين هذا عن طريق استدعاء ykclient_set_url_template. يجب تعيين عنوان URL بالتنسيق https://api.example.com/wsapi/2.0/verify?id=%d&otp=%s

capath=مسار

المسار حيث يتم تخزين شهادات X509. هذا مطلوب إذا تم استخدام https أو ldaps في url و ldap_uri، على التوالي.

cainfo=ملف

خيار للسماح باستخدام حزمة CA بدلاً من المسار.

proxy=proxy

الوكيل للاتصال بخادم التحقق. المخططات الصالحة هي http://, https://, socks4://, socks4a://, socks5:// أو socks5h://. يطلب Socks5h من الوكيل إجراء حل DNS. إذا لم يتم تحديد مخطط أو منفذ، فسيتم استخدام منفذ وكيل HTTP 1080. مثال: socks5h://user:pass@10.10.0.1:1080

verbose_otp

عرض كلمة المرور لمرة واحدة عند إدخالها، أي تمكين صدى الطرفية للأحرف المدخلة. ننصحك بعدم استخدام هذا، إذا كنت تستخدم المصادقة الثنائية لأن ذلك سيعرض كلمة المرور الخاصة بك على الشاشة. هذا يتطلب من الخدمة التي تستخدم وحدة PAM عرض حقول مخصصة. لا يمكن استخدام هذا الخيار مع OpenSSH.

ldap_uri=uri

URI خادم LDAP (مثل ldap://localhost).

ldap_server=server

مضيف خادم LDAP (يتم استخدام منفذ LDAP الافتراضي). مهمل. استخدم ldap_uri بدلاً من ذلك.

ldapdn=dn

الاسم المميز (DN) حيث يتم تخزين المستخدمين (على سبيل المثال: ou=users,dc=domain,dc=com). إذا تم استخدام ldap_filter، فهذا هو الأساس الذي سيتم منه إجراء بحث الشجرة الفرعية.

ldap_clientcertfile=clientcertfile

المسار إلى ملف شهادة العميل لاستخدامه عند التحدث إلى خادم LDAP. لاحظ أن هذا يتطلب تعيين ldap_clientkeyfile أيضًا.

ldap_clientkeyfile=clientkeyfile

المسار إلى مفتاح لاستخدامه مع شهادة العميل عند التحدث إلى خادم LDAP. لاحظ أن هذا يتطلب تعيين ldap_clientcertfile أيضًا.

user_attr=attr

سمة LDAP المستخدمة لتخزين أسماء المستخدمين (على سبيل المثال: cn).

yubi_attr=attr

سمة LDAP المستخدمة لتخزين معرف YubiKey.

yubi_attr_prefix=prefix

بادئة قيمة السمة في LDAP، في حالة وجود سمة عامة، تستخدم لتخزين أنواع مختلفة من المعرفات.

token_id_length=length

طول المعرف الذي يسبق OTP (هذا 12 إذا كنت تستخدم YubiCloud).

ldap_bind_user=user

المستخدم لمحاولة الربط بـ LDAP به.

ldap_bind_password=password

كلمة المرور لاستخدامها عند ربط LDAP.

ldap_filter=filter

عامل تصفية LDAP لاستخدامه لمحاولة العثور على الكائن الصحيح في LDAP. في هذه السلسلة، سيتم استبدال %u باسم المستخدم.

ldap_cacertfile=cacertfile

ملف شهادة CA لاتصال LDAP.

chalresp_path=path

مسار دليل على مستوى النظام حيث يمكن العثور على ملفات التحدي والاستجابة للمستخدمين. الموقع الافتراضي هو $HOME/.yubico/.

mysql_server=mysqlserver

اسم المضيف/عنوان خادم mysql. مثال 10.0.0.1

mysql_port=mysqlport

منفذ شبكة خادم mysql.

mysql_user=mysqluser

مستخدم للوصول إلى قاعدة البيانات. يوصى بشدة باستخدام مستخدم محدد مع إمكانية القراءة فقط.

mysql_password=mysqlpassword

كلمة المرور mysql المرتبطة بالمستخدم.

mysql_database=mysqldatabase

اسم قاعدة البيانات. مثال: otp

أمثلة

auth sufficient pam_yubico.so id=16 debug
auth required pam_yubico.so mode=challenge-response
auth required pam_yubico.so id=16 ldap_uri=ldaps://ldap.example.com ldap_filter=(uid=%u) yubi_attr=yubiKeyId

ملفات

$HOME/.yubico/authorized_yubikeys

إذا لم يتم تعيين authfile، فسيتم استخدام هذا الملف لتعيين معرف YubiKey العام في وضع client.

$HOME/.yubico/challenge, $HOME/.yubico/challenge-serial_number

إذا لم يتم تعيين chalresp_path، فسيتم استخدام هذه الملفات

NAME

pam_yubico ― YubiKey PAM module

SYNOPSIS

pam_yubico.so [options]

DESCRIPTION

The pam_yubico module is a Pluggable Authentication Module (PAM) that adds YubiKey hardware authentication to systems running Linux. It allows users to authenticate using their YubiKey in combination with a password or another authentication method. The module supports various authentication modes, including validation against Yubico’s cloud validation service or against a local YubiKey OTP validation server. It can also be configured for challenge-response authentication.

OPTIONS

The following options can be passed to the module:

authfile=FILE
Specifies the path to the file containing YubiKey public IDs. This file is used for local validation. The format is one public ID per line. If chalresp_path is set, the filename will be username instead of challenge.
authorman
If this option is present, the module will attempt to read the YubiKey public ID from the author name field of the YubiKey. This is only supported by certain YubiKey models.
chalresp_file=FILE
Specifies the path to the file containing the challenge-response secrets. This file is used for challenge-response authentication.
chalresp_path=PATH
Specifies the path to a directory where challenge-response secrets are stored. The filename will be username.
debug
Enables debug logging.
id=YUBICO_ID
Specifies the Yubico Account ID for cloud validation. If not provided, the module will attempt to read it from the YubiKey.
key=API_KEY
Specifies the API key for cloud validation. If not provided, the module will attempt to read it from the YubiKey.
mode=MODE
Specifies the authentication mode. Supported modes are:
client
Use Yubico’s cloud validation service.
local
Use a local validation server (requires a running `ykval-web` instance).
otp
Validate OTPs directly (default).
chalresp
Challenge-response mode.
noverify
Disables certificate verification for cloud validation. Use with caution.
pam_service=SERVICE
Specifies the PAM service name to use for challenge-response mode.
secret=SECRET_KEY
Specifies the secret key for local validation. If not provided, the module will attempt to read it from the YubiKey.
timeout=SECONDS
Sets the timeout for validation requests in seconds.
url=URL
Specifies the URL of the validation server. This is used for local validation.
user=USERNAME
Specifies the username for cloud validation. If not provided, the module will attempt to read it from the YubiKey.

EXAMPLES

Example PAM configuration for SSH login using YubiKey OTP validation against Yubico’s cloud service:

auth    required    pam_yubico.so id=YOUR_YUBICO_ID key=YOUR_API_KEY
auth    sufficient  pam_unix.so
account required    pam_unix.so
session required    pam_unix.so

Example PAM configuration for challenge-response authentication:

auth    requisite   pam_yubico.so chalresp_path=/etc/yubico/chalresp
auth    required    pam_unix.so
account required    pam_unix.so
session required    pam_unix.so

The challenge-response files are created using the ykpamcfg utility. For example, to generate a secret for user 'alice' and store it in /etc/yubico/chalresp/alice:

# ykpamcfg -2 -v -H sha1 -f /etc/yubico/chalresp alice

This command will prompt for the YubiKey, generate a secret, and store it in the specified file. The ‘-2’ option indicates that the YubiKey should be used for challenge-response authentication. The ‘-H sha1’ option specifies the hashing algorithm. If ‘-H’ is not specified, the default hashing algorithm is MD5.

The challenge-response mode expects the user to first enter their YubiKey OTP, then the module will prompt them to enter the response to a challenge. The user must enter their YubiKey OTP again, this time pressing the button after the desired challenge string. The module will then extract the response from the YubiKey OTP and compare it with the expected response. The expected response is generated by hashing the challenge string with the secret key associated with the user.

If chalresp_path is set, the module will store the challenge-response secret in a file named after the user in the specified path. If chalresp_file is set, the module will use the specified file for challenge-response secrets.
