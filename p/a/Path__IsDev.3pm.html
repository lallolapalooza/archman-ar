Path__IsDev(3pm)

الحزمة: perl-path-isdev

التراخيص: PerlArtistic

Path::IsDev(3) وثائق Perl التي ساهم بها المستخدم Path::IsDev(3)

الاسم

Path::IsDev - تحديد ما إذا كان المسار المحدد يشبه شجرة تطوير مصدر

الإصدار

version 1.001003

ملخص

use Path::IsDev qw(is_dev);
if( is_dev('/some/path') ) {
    ...
} else {
    ...
}

الوصف

هذه الوحدة هي عبارة عن مجموعة من الاستدلالات لتحديد ما إذا كان المسار المحدد هو جذر شجرة تطوير من نوع ما.

هذا له العديد من التطبيقات المفيدة، وخاصة تلك التي تتطلب أن تكون السلوكيات للوحدات "المثبتة" مختلفة عن تلك التي لا تزال "قيد التطوير".

الوظائف

debug

دالة استدعاء التصحيح.

لتفعيل التصحيح:

export PATH_ISDEV_DEBUG=1

"is_dev"

باستخدام "is_dev" تم "import"ed:

if( is_dev( $path ) ) {
}

على الرغم من أن الاستدلالات الفعلية المستخدمة ستعتمد على كيفية استدعاء "import".

بالإضافة إلى ذلك، يمكنك استدعاء

Path::IsDev::is_dev

بدون استدعاء "import" أي شيء، وستتصرف تمامًا كما لو كنت قد استدعيت باستخدام

use Path::IsDev qw( is_dev );

أي، لا يوجد مواصفات "set" قابلة للتطبيق، لذلك ستحصل فقط على "الافتراضي".

فهم وتصحيح هذه الوحدة

فهم كيفية عمل هذه الوحدة أمر بالغ الأهمية لفهم أين يمكنك استخدامها، وعواقب استخدامها.

تعمل هذه الوحدة على مستوى بسيط جدًا، ومن السهل حدوث نتائج إيجابية خاطئة.

هناك نوعان من الاستدلالات: استدلالات إيجابية / مؤكدة، واستدلالات سلبية / نافية.

تعتمد الاستدلالات الإيجابية والسلبية على وجود ملفات علامة محددة في دليل، أو أدلة علامة خاصة.

على سبيل المثال، تعد الملفات "META.yml"، "Makefile.PL"، و "Build.PL" كلها علامات استدلال إيجابي، لأن وجودها غالبًا ما يشير إلى "جذر" شجرة تطوير.

وعلى سبيل المثال، تعد الأدلة "t/"، "xt/"، و ".git/" أيضًا علامات استدلال إيجابي، لأن هذه الهياكل شائعة في أشجار تطوير "perl"، وغير شائعة في أشجار التثبيت.

ومع ذلك، فإن هذه العلامات قد تخطئ أحيانًا، على سبيل المثال، ضع في اعتبارك أن لديك تثبيت "local::lib" أو "perlbrew" في $HOME

$HOME/
$HOME/lib/
$HOME/perl5/perls/perl-5.19.3/lib/site_perl/

إلخ.

في الظروف العادية، لا يعتبر كل من $HOME أو هذه المسارات الثلاثة "dev".

ومع ذلك، كل ما يتطلبه الأمر لإحداث نتيجة إيجابية خاطئة هو أن يقوم شخص ما بتثبيت دليل "t" أو "xt"، أو ملف علامة في أحد الأدلة المذكورة أعلاه لكي تعيد path_isdev($dir) قيمة صحيحة.

قد لا تكون هذه مشكلة، على الأقل، حتى تستخدم "Path::FindDev" الذي يجمع "Path::IsDev" مع اجتياز متكرر للأعلى.

$HOME/
$HOME/lib/
$HOME/perl5/perls/perl-5.19.3/lib/site_perl/
find_dev('$HOME/perl5/perls/perl-5.19.3/lib/site_perl/') # يعيد خطأ، لأنه ليس داخل دليل dev
mkdir $HOME/t
find_dev('$HOME/perl5/perls/perl-5.19.3/lib/site_perl/') # يعيد $HOME، لأن $HOME/t موجود.

وهذا هو النوع من المشاكل الذي يفاجئ الناس عادة.

PATH_ISDEV_DEBUG=1 \

Path::IsDev - Perl Modules

NOMBRE

Path::IsDev - تحديد ما إذا كان المسار المحدد يبدو وكأنه مسار تطوير

VERSION

1.001003

SYNOPSIS

 use Path::IsDev qw( is_dev );
 if ( is_dev( '/home/user/.config' ) ) {
     print "This is likely a development path\n";
 }
 if ( is_dev( '/usr/bin/perl' ) ) {
     print "This is likely not a development path\n";
 }

DESCRIPTION

يحدد ما إذا كان المسار المحدد يبدو وكأنه مسار تطوير.

يتم ذلك عن طريق البحث عن ملفات أو أدلة معروفة بوجودها غالبًا في مستودعات التطوير.

بعض الأمثلة على هذه الملفات والأدلة:

  • "Build.PL" ملف
  • ".git" دليل

FUNCTIONS

•
is_dev( $path ): يعيد قيمة منطقية تشير إلى ما إذا كان المسار المحدد يعتبر مسار تطوير.

ENTENDIMIENTO Y DEBUGGING DE ESTE MODULO

للتحقق من سبب اتخاذ قرار معين، يمكنك تعيين متغير البيئة PATH_ISDEV_DEBUG:

 export PATH_ISDEV_DEBUG=1
 use Path::IsDev qw( is_dev );
 is_dev('/some/path');
 # سيقوم بإخراج سبب القرار

HEURISTICS

هذا الموديول يستخدم مجموعة من "المحفزات" أو "الحدسيات" لتحديد ما إذا كان المسار هو مسار تطوير.

هذه المحفزات هي ببساطة وجود ملفات أو أدلة معينة. إذا تم العثور على أي من هذه المحفزات، يعتبر المسار مسار تطوير.

USO AVANZADO

Custom Sets

"Path::IsDev" has a system of heuristic "sets" to allow for pluggable and flexible heuristic types.

Although, for most use cases, this is unnecessary.

use Path::IsDev is_dev => { set => 'Basic' };
use Path::IsDev is_dev => { set => 'SomeOtherSet' , -as => 'is_dev_other' };

Overriding the default set

If for any reason the "Basic" set is insufficient, or if for some reason there are false positives on your system, the "default" set can be overridden.

export PATH_ISDEV_DEFAULT_SET="SomeOtherSet"
...
use Path::IsDev qw( is_dev );
is_dev('/some/path') # uses SomeOtherSet

Although this will only take precedence in the event that the set is not specified during "import"

If this represents a security risk to the user, this security hole can be patched by declaring the set you want in code:

export PATH_ISDEV_DEFAULT_SET="SomeOtherSet"
...
use Path::IsDev  is_dev => { set => 'Basic' };
is_dev('/some/path') # uses Basic, regardless of environment

SEGURIDAD

It is conceivable that a malicious user could construct a malicious set, containing arbitrary and vulnerable code, and possibly be storing it within a poorly secured privileged user’s @INC

And if they were able to do that, if they could poison a privileged user’s %ENV, they could rope a privileged user into executing arbitrary code.

Although that said, if you can do either of the two things mentioned, you are likely already vulnerable, and even so, if you can do either of the two things, you could do far worse via:

export PERL5OPT="-MEvil::Module"

With that in mind, to say that this module has a default utility that is "insecure" is largely an empty argument.

And to that end, this module does nothing to "lock down" that mechanism, and this module recommends that you **do not** force a set, unless you **need** to, and strongly suggests that forcing a set for the purpose of security will not achieve any security advancements, while simultaneously reducing utility.
