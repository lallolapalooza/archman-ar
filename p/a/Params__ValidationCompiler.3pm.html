Params::ValidationCompiler(3) وثائق Perl المساهمة من المستخدمين Params::ValidationCompiler(3)

NAME

Params::ValidationCompiler - إنشاء مدقق معلمات مخصص وفعال، يمكن استخدامه دائمًا

VERSION

الإصدار 0.31

SYNOPSIS

use Types::Standard qw( Int Str );
use Params::ValidationCompiler qw( validation_for );
{
    my $validator = validation_for(
        params => {
            foo => { type => Int },
            bar => {
                type     => Str,
                optional => 1,
            },
            baz => {
                type    => Int,
                default => 42,
            },
        },
    );
    sub foo {
        my %args = $validator->(@_);
    }
}
{
    my $validator = validation_for(
        params => [
            { type => Int },
            {
                type     => Str,
                optional => 1,
            },
        ],
    );
    sub bar {
        my ( $int, $str ) = $validator->(@_);
    }
}
{
    my $validator = validation_for(
        params => [
            foo => { type => Int },
            bar => {
                type     => Str,
                optional => 1,
            },
        ],
        named_to_list => 1,
    );
    sub baz {
        my ( $foo, $bar ) = $validator->(@_);
    }
}

DESCRIPTION

تنشئ هذه الوحدة مدقق معلمات مخصصًا وفعالًا، يمكن استخدامه دائمًا. يمكنها التعامل مع المعلمات المسماة أو الموضعية، ويمكنها إرجاع المعلمات كأزواج مفتاح-قيمة أو قائمة قيم.

بالإضافة إلى فحوصات النوع، تدعم أيضًا القيم الافتراضية والمعلمات الاختيارية والمعلمات الإضافية "slurpy".

PARAMETERS

تحتوي هذه الوحدة على خيارين للتصدير، validation_for و source_for. كلاهما يقبل نفس الخيارات:

params

مصفوفة مرجعية أو قاموس مرجعي يحتوي على مواصفات معلمة.

إذا مررت قاموسًا مرجعيًا، فسينتظر المدقق الذي تم إنشاؤه معلمات مسماة. يجب أن يكون القاموس المرجعي params قاموسًا حيث أسماء المعلمات هي المفاتيح والمواصفات هي القيم.

إذا مررت مصفوفة مرجعية و named_to_list هو خاطئ، فسينتظر المدقق معلمات موضعية. يجب أن يكون كل عنصر في مصفوفة params المرجعية مواصفات معلمة.

إذا مررت مصفوفة مرجعية و named_to_list صحيح، فسينتظر المدقق معلمات مسماة، ولكنه سيعيد قائمة قيم. في هذه الحالة، يجب أن تحتوي المصفوفة المرجعية على قائمة أزواج مفتاح-قيمة، حيث أسماء المعلمات هي المفاتيح والمواصفات هي القيم.

يمكن أن تحتوي كل مواصفات على قيمة منطقية أو قاموس مرجعي. إذا كانت المواصفات قيمة منطقية، فهذا يشير إلى ما إذا كانت المعلمة إلزامية (صحيح) أو اختيارية (خطأ).

يقبل القاموس المرجعي للمواصفات المفاتيح التالية:

  • type

    كائن نوع. يمكن أن يكون هذا نوع Moose (من Moose أو MooseX::Types)، أو نوع Type::Tiny، أو نوع Specio.

    إذا كان للنوع تحويلات، فسيتم استخدامها دائمًا.

  • default

    يمكن أن يكون هذا قيمة قابلة للقياس بسيطة (غير مرجعية) أو مرجعًا لوظيفة فرعية. سيتم استدعاء الوظيفة الفرعية بدون وسائط (حتى الآن).

  • optional

    قيمة منطقية تشير إلى ما إذا كانت المعلمة اختيارية. افتراضيًا، تكون المعلمات إلزامية، إلا إذا تم إعطاؤها قيمة افتراضية.

slurpy

إذا كانت هذه قيمة صحيحة، فإن الوظيفة الفرعية التي تم إنشاؤها تقبل وسائط إضافية غير محددة في params. افتراضيًا، تتسبب الوسائط الإضافية في استثناء.

يمكنك أيضًا تمرير قيد نوع هنا، والذي يجب أن تكون جميع الوسائط الإضافية قيمًا من النوع المحدد.

named_to_list

إذا كان هذا صحيحًا، فستتوقع الوظيفة الفرعية التي تم إنشاؤها قائمة بأزواج مفتاح-قيمة أو قاموسًا مرجعيًا وستعيد قائمة قيم. يجب أن تكون المعلمات التي تمررها مصفوفة مرجعية لأزواج مفتاح-قيمة. يحدد ترتيب هذه الأزواج الترتيب الذي يتم به إرجاع القيم.

لا يمكنك الجمع بين slurpy و named_to_list، لأنه لا يُعرف كيفية ترتيب القيم الإضافية المرجعة.

return_object

إذا كان هذا صحيحًا، فستعيد الوظيفة الفرعية التي تم إنشاؤها كائنًا بدلاً من قاموس مرجعي. لا يمكنك تعيين هذا الخيار إذا كنت تستخدم slurpy أو named_to_list.

يتوافق طريقة هذا الكائن مع أسماء المعلمات الممررة إلى الوظيفة الفرعية. على الرغم من أن استدعاء الطرق على كائن أبطأ من الوصول إلى قاموس مرجعي، فإن الفائدة هي أنه إذا كان لديك خطأ إملائي في اسم معلمة، فسوف يعطيك رسالة مفيدة.

إذا كانت مكتبة Class::XSAccessor مثبتة، فسيتم استخدامها لإنشاء طرق الفئة، مما يجعلها سريعة جدًا.

الكائن المرجع موجود في فئة تم إنشاؤها. لا تنخدع باسم هذه الفئة ولا تستخدم isa أو DOES أو أي شيء مشابه للتحقق من هذا الكائن.

عندما يكون return_object صحيحًا، يقبل القاموس المرجعي للمواصفات أيضًا المفاتيح الإضافية التالية:

  • getter

    استخدم هذا لتعيين طريقة وصول صريحة للمعلمة. افتراضيًا، سيكون اسم الطريقة هو نفس اسم المعلمة. لاحظ أنه إذا لم يكن اسم المعلمة اسم وظيفة فرعية صالحًا، فستحصل على خطأ عند تجميع وظيفة التحقق من الصحة، إلا إذا قمت بتحديد getter لهذه المعلمة.

  • predicate

    استخدم هذا لطلب طريقة predicate لهذه المعلمة. ترجع طريقة predicate صحيحًا إذا تم تمرير المعلمة وخطأ إذا لم يتم تمريرها. لاحظ أن هذا مفيد فقط للمعلمات الاختيارية، ولكن يمكنك طلب predicate لأي معلمة.

EXPORTS

الوظائف الفرعية المصدرة هي:

validation_for(...)

هذه تعيد وظيفة فرعية تنفذ التحقق من صحة معلمات محددة. تتوقع هذه الوظيفة الفرعية أن يتم تمرير المعلمات للتحقق منها في @_. إذا كانت جميع المعلمات صالحة، فستعيد المعلمات التي تم التحقق منها (مع قيم افتراضية مناسبة)، كقائمة أزواج مفتاح-قيمة أو كقائمة قيم. إذا كانت أي معلمة غير صالحة، فستطلق استثناء.

بالنسبة للمدققين الذين يتوقعون معلمات مسماة، تقبل الوظيفة الفرعية التي تم إنشاؤها قائمة بأزواج مفتاح-قيمة أو قاموسًا مرجعيًا واحدًا. خلاف ذلك، يتوقع المدقق قائمة قيم.

حاليًا، ستحتاج إلى إزاحة المستدعي بنفسك.

تقبل هذه الوظيفة الفرعية المعلمات الإضافية التالية:

  • name

    إذا تم توفير هذا، فسيتم تسمية الوظيفة الفرعية التي تم إنشاؤها باستخدام Sub::Util. هذا موصى به بشدة، لأنه يسمح بالتمييز بين وظائف التحقق المختلفة عند التنميط أو في تتبعات المكدس.

    سيتم أيضًا استخدام هذا الاسم في بعض رسائل الخطأ، حتى إذا لم يتم تثبيت Sub::Util.

    ملاحظة: يجب عليك تثبيت Sub::Util بشكل منفصل، لأنه ليس مطلوبًا لهذا التوزيع، لتجنب الحاجة إلى مترجم.

  • name_is_optional

    إذا كان هذا صحيحًا، فسيتم تجاهل الاسم عند عدم تثبيت Sub::Util. إذا كان هذا خطأ، فإن تمرير اسم عند فشل تحميل Sub::Util يتسبب في استثناء.

    هذا مفيد لوحدات CPAN حيث تريد تعيين اسم، ولكنك لا تريد إضافة متطلب مسبق لـ Sub::Util.

  • debug

    تعيين متغير البيئة EVAL_CLOSURE_PRINT_SOURCE إلى صحيح قبل استدعاء Eval::Closure.

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

Params::ValidationCompiler - Arch Linux Man Pages

NAME

Params::ValidationCompiler - Compile parameter validators into subroutines

VERSION

This document describes version 0.31 of Params::ValidationCompiler.

SYNOPSIS

This module is part of Params::ValidationCompiler. See its documentation for details.

DESCRIPTION

This module is part of Params::ValidationCompiler. See its documentation for details.

This module can be used to get the source code of the generated subroutine. This is primarily useful for debugging, or for use in environments where "eval" is disallowed, or for inspecting the code that Params::ValidationCompiler generates.

It's important to note that this module is not meant to be used directly by application developers. It is intended for use by other modules that want to compile their own parameter validation code.

eval_closure()

The "eval_closure" function is exported by this module. It is a wrapper around "Eval::Closure::eval_closure".

When this function is called, the source code of the subroutine is printed to STDOUT using the "Data::Dumper" module. This causes the source of the subroutine to be printed before it's "eval"'d.

SOURCE FOR(...)

This returns a two element list. The first is a string containing the source code for the generated sub. The second is a hashref of "environment" variables to be used when generating the subroutine. These are the arguments that are passed to Eval::Closure.
