pack200(1) أدوات نشر Java pack200(1)

الاسم

pack200 - يقوم بتعبئة ملف JAR في ملف pack200 مضغوط لنشر الويب.

الملخص

pack200 [خيارات] ملف-الإخراج ملف-JAR

يمكن أن تكون الخيارات بأي ترتيب. الخيار الأخير في سطر الأوامر أو في ملف خصائص يلغي جميع الخيارات المحددة مسبقًا.

خيارات
خيارات سطر الأوامر. انظر الخيارات.
ملف-الإخراج
اسم ملف الإخراج.
ملف-JAR
اسم ملف الإدخال.

الوصف

الأمر pack200 هو تطبيق Java يقوم بتحويل ملف JAR إلى ملف pack200 مضغوط باستخدام ضاغط Java gzip. ملفات pack200 هي ملفات مضغوطة للغاية يمكن نشرها مباشرة لتوفير النطاق الترددي وتقليل وقت التنزيل.

يحتوي الأمر pack200 على العديد من الخيارات لضبط وضبط محرك الضغط. الاستخدام النموذجي موضح في المثال التالي، حيث يتم إنتاج myarchive.pack.gz باستخدام الإعدادات الافتراضية للأمر pack200:

pack200 myarchive.pack.gz myarchive.jar

الخيارات

-r, --repack

ينتج ملف JAR عن طريق تعبئة وفك تجميع ملف JAR. يمكن استخدام الملف الناتج كمدخل لأداة jarsigner(1). يقوم المثال التالي بتعبئة وفك تجميع ملف myarchive.jar: 
pack200 --repack myarchive-packer.jar myarchive.jar
pack200 --repack myarchive.jar

يقوم المثال التالي بالحفاظ على ترتيب الملفات في ملف الإدخال.

-g, --no-gzip

ينتج ملف pack200. مع هذا الخيار، يجب استخدام ضاغط مناسب، ويجب أن يستخدم النظام الهدف ضاغطًا مقابلًا. 
pack200 --no-gzip myarchive.pack myarchive.jar
-G, --strip-debug

يقوم بإزالة سمات التصحيح من الإخراج. تشمل هذه السمات SourceFile, LineNumberTable, LocalVariableTable و LocalVariableTypeTable. يؤدي إزالة هذه السمات إلى تقليل حجم التنزيلات والتثبيتات، ولكنه يقلل من فائدة المصححات.
--keep-file-order

يحافظ على ترتيب الملفات في ملف الإدخال. هذا هو السلوك الافتراضي.
-O, --no-keep-file-order

يقوم المُعبئ بإعادة ترتيب وإرسال جميع العناصر. يمكن للمُعبئ أيضًا إزالة أسماء أدلة JAR لتقليل حجم التنزيل. ومع ذلك، قد لا تعمل بعض تحسينات ملف JAR، مثل الفهرسة، بشكل صحيح.
-Sقيمة , --segment-limit=قيمة

القيمة هي الحجم المستهدف المقدر N (بالبايت) لكل جزء من الأرشيف. إذا تجاوز ملف إدخال واحد N بايت، فسيتم توفير جزء الأرشيف الخاص به. كحالة خاصة، تنتج القيمة -1 جزءًا واحدًا كبيرًا مع جميع ملفات الإدخال، بينما تنتج القيمة 0 جزءًا واحدًا لكل فئة. تؤدي أجزاء الأرشيف الأكبر إلى تجزئة أقل وضغط أفضل، ولكن معالجتها تتطلب المزيد من الذاكرة.

يتم تقدير حجم كل جزء عن طريق حساب حجم كل ملف إدخال سيتم إرساله في الجزء مع حجم اسمه وخصائصه المرسلة الأخرى.

القيمة الافتراضية هي -1، مما يعني أن المُعبئ ينشئ ملف إخراج بجزء واحد. في الحالات التي يتم فيها إنشاء ملفات إخراج كبيرة جدًا، يتم تشجيع المستخدمين بشدة على استخدام التقسيم أو تقسيم ملف الإدخال إلى ملفات JAR أصغر.

يتم تعبئة ملف JAR بحجم 10 ميجابايت بدون هذا الحد عادةً بنسبة 10 بالمائة أصغر، ولكن قد يتطلب المُعبئ ذاكرة Java أكبر (حوالي 10 أضعاف حد الجزء).

-Eقيمة , --effort=قيمة

إذا تم تعيين القيمة على رقم عشري واحد، فإن المُعبئ يستخدم مقدار الجهد المشار إليه في ضغط الأرشيف. قد ينتج المستوى 1 حجمًا أكبر قليلاً وسرعة ضغط أسرع، بينما يستغرق المستوى 9 وقتًا أطول بكثير، ولكنه يمكن أن ينتج ضغطًا أفضل. القيمة الخاصة 0 تطلب من الأمر pack200 نسخ ملف JAR الأصلي مباشرة دون أي ضغط. يتطلب معيار JSR 200 أن يفهم أي مُفكك ضغط هذه الحالة الخاصة كتمرير للأرشيف بأكمله.

القيمة الافتراضية هي 5، لاستثمار قدر معتدل من الوقت لإنتاج ضغط معقول.

-Hقيمة , --deflate-hint=قيمة

يلغي الإعداد الافتراضي، الذي يحافظ على معلومات الإدخال، ولكنه يمكن أن يتسبب في أن يكون الأرشيف المرسل أكبر. القيم الممكنة هي: true (صحيح)، false (خطأ)، أو keep (احتفاظ).

إذا كانت القيمة هي true أو false، فإن الأمر packer200 يقوم بتعيين تلميح الضغط وفقًا لذلك في أرشيف الإخراج ولا يرسل تلميحات الضغط الفردية لعناصر الأرشيف.

القيمة keep تحتفظ بتلميحات الضغط المرصودة في ملف JAR للإدخال. هذه هي القيمة الافتراضية.

-mقيمة , --modification-time=قيمة

القيم الممكنة هي latest (الأحدث) و keep (احتفاظ).

إذا كانت القيمة هي latest، فإن المُعبئ يحاول تحديد أحدث وقت تعديل، من بين جميع الإدخالات المتاحة في الأرشيف الأصلي، أو أحدث وقت تعديل لجميع الإدخالات المتاحة في هذا الجزء. يتم إرسال هذه القيمة الواحدة كجزء من الجزء وتطبيقها على جميع الإدخالات في كل جزء. هذا يمكن أن يقلل بشكل طفيف من حجم الأرشيف المرسل على حساب تعيين جميع الملفات المثبتة إلى تاريخ واحد.

إذا كانت القيمة هي keep، يتم الاحتفاظ بأوقات التعديل المرصودة في ملف JAR للإدخال. هذه هي القيمة الافتراضية.

-Pملف , --pass-file=ملف

يشير إلى أنه يجب تمرير ملف بايت ببايت دون ضغط. بتكرار الخيار، يمكن تحديد ملفات متعددة. لا يوجد تحويل للمسار، باستثناء أن فاصل ملف النظام يتم استبداله بفاصل ملف JAR بشرطة مائلة (/). يجب أن تتطابق أسماء الملفات الناتجة تمامًا كسلاسل نصية مع حدوثها في ملف JAR. إذا كان ملف اسم دليل، فسيتم تمرير جميع الملفات الموجودة تحت هذا الدليل.
-Uإجراء , --unknown-attribute=إجراء

يلغي السلوك الافتراضي، مما يعني أن ملف الفئة الذي يحتوي على السمة غير المعروفة يتم تمريره بالإجراء المحدد. القيم الممكنة للإجراءات هي error (خطأ)، strip (إزالة)، أو pass (تمرير).

إذا كانت القيمة هي error، فإن عملية الأمر pack200 بأكملها تفشل مع شرح مناسب.

إذا كانت القيمة هي strip، يتم إسقاط السمة. قد يؤدي إزالة سمات آلة Java الافتراضية (JVM) المطلوبة إلى فشل مُحمل الفئة.

إذا كانت القيمة هي pass، فسيتم إرسال الفئة بأكملها كما لو كانت موردًا.

-Cاسم-السمة=تخطيط , --class-attribute=اسم-السمة=إجراء

    انظر الخيار التالي.
  

  
-Fاسم-السمة=تخطيط ,
    --field-attribute=اسم-السمة=إجراء

  

    

    انظر الخيار التالي.
  

  
-Mاسم-السمة=تخطيط ,
    --method-attribute=اسم-السمة=إجراء

  

    

    انظر الخيار التالي.
  

  
-Dاسم-السمة=تخطيط ,
    --code-attribute=اسم-السمة=إجراء

  

    

    مع الخيارات الأربعة السابقة، يمكن تحديد تخطيط السمة لكيان فئة، مثل
      class-attribute (سمة الفئة)، field-attribute (سمة الحقل)،
      method-attribute (سمة الطريقة)، و code-attribute (سمة الكود).
      اسم-السمة هو اسم السمة التي يتم تحديد التخطيط أو الإجراء لها.

NAME

  
pack200 - A tool for packing Java archive files

  

  

  
SYNOPSIS

  
pack200 [OPTIONS] archive.pack.gz archive.jar

  
pack200 [OPTIONS] -m archive.pack archive.jar

  
pack200 [OPTIONS] --upgrade archive.jar archive.jar

  

  

  
DESCRIPTION

  
The pack200 command is a utility that uses the Java
      Techniques for Large Applications (JLTLA) packing format to compress Java
      archive (JAR) files. It is useful for reducing the download size of JAR
      files.

  
The pack200 command takes a JAR file as input and
      produces a compressed archive file that can be decompressed by the
      unpack200 command.

  

  

  
OPTIONS

  

      
-c, --class-attribute=attribute

      

      

      Sets the action to take when an unknown class attribute is encountered.
          The possible values for action are
          some-layout-string, error, strip, pass.
      
some-layout-string: The layout language is defined in
          the JSR 200 specification, for example:
          --class-attribute=SourceFile=RUH.

      
If the value is error, then the pack200
          operation fails with an explanation.

      
If the value is strip, then the attribute is removed
          from the output. Removing JVM-required attributes can cause class loader
          failures. For example, --class-attribute=CompilationID=pass
          causes the class file that contains this attribute to be passed through
          without further action by the packer.

      
If the value is pass, then the entire class is
          transmitted as though it is a resource.

      

      
-f pack.properties ,
      --config-file=pack.properties

      

      

      A configuration file, containing Java properties to initialize the packer,
      can be specified on the command line.
          
pack200 -f pack.properties myarchive.pack.gz myarchive.jar

      
more pack.properties

      
# Generic properties for the packer.

      
modification.time=latest

      
deflate.hint=false

      
keep.file.order=false

      
# This option will cause the files bearing new attributes to

      
# be reported as an error rather than passed uncompressed.

      
unknown.attribute=error

      
# Change the segment limit to be unlimited.

      
segment.limit=-1

      

      

      
-v, --verbose

      

      

      Outputs minimal messages. Multiple specification of this option will create
          more verbose messages.

      
-q, --quiet

      

      

      Specifies quiet operation with no messages.

      
-lfilename ,
      --log-file=filename

      

      

      Specifies a log file to output messages.

      
-?, -h, --help

      

      

      Prints help information about this command.

      
-V, --version

      

      

      Prints version information about this command.

      
-Joption

      

      

      Passes the specified option to the Java Virtual Machine. For more
          information, see the reference page for the java(1) command. For example,
          -J-Xms48m sets the startup memory to 48 MB.

  

  

  

  
EXIT STATUS

  
The following exit values are returned: 0 for successful
      completion and a number greater than 0 when an error occurs.

  

  

  
NOTES

  
This command should not be confused with pack(1). The
      pack and pack200 commands are separate products.

  
The Java SE API Specification provided with the JDK is the
      superseding authority, when there are discrepancies.
