الاسم

psql - طرفية PostgreSQL التفاعلية

ملخص

psql [خيار...] [اسم_قاعدة_البيانات [اسم_المستخدم]]

الوصف

psql هي واجهة أمامية قائمة على الطرفية لـ PostgreSQL. تتيح لك كتابة استعلامات تفاعليًا، وإصدارها إلى PostgreSQL، ورؤية نتائج الاستعلام. بدلاً من ذلك، يمكن أن يأتي الإدخال من ملف أو من وسائط سطر الأوامر. بالإضافة إلى ذلك، توفر psql عددًا من الأوامر الوصفية وميزات تشبه الصدفة لتسهيل كتابة النصوص البرمجية وأتمتة مجموعة واسعة من المهام.

خيارات

-a
--echo-all

اطبع جميع أسطر الإدخال غير الفارغة إلى المخرج القياسي عند قراءتها. (لا ينطبق هذا على الأسطر المقروءة تفاعليًا.) هذا يعادل تعيين المتغير ECHO على all.

-A
--no-align

التبديل إلى وضع الإخراج غير المحاذاة. (وضع الإخراج الافتراضي هو المحاذاة.) هذا يعادل \pset format unaligned.

-b
--echo-errors

اطبع أوامر SQL الفاشلة إلى المخرج القياسي للأخطاء. هذا يعادل تعيين المتغير ECHO على errors.

-c command
--command=command

يحدد أن psql يجب أن تنفذ سلسلة الأوامر المعطاة، command. يمكن تكرار هذا الخيار ودمجه بأي ترتيب مع الخيار -f. عند تحديد -c أو -f، لا تقرأ psql الأوامر من المدخل القياسي؛ بدلاً من ذلك، تنتهي بعد معالجة جميع خيارات -c و -f بالتتابع.

يجب أن تكون command إما سلسلة أوامر يمكن تحليلها بالكامل بواسطة الخادم (أي أنها لا تحتوي على ميزات خاصة بـ psql)، أو أمر شرطة مائل واحد. لذلك لا يمكنك مزج SQL وأوامر psql الوصفية داخل خيار -c. لتحقيق ذلك، يمكنك استخدام خيارات -c مكررة أو توجيه السلسلة إلى psql، على سبيل المثال:

psql -c '\x' -c 'SELECT * FROM foo;'

أو

echo '\x \\ SELECT * FROM foo;' | psql

( \\ هو أمر فاصل وصفي.)

يتم إرسال كل سلسلة أوامر SQL المقدمة إلى -c إلى الخادم كطلب واحد. بسبب هذا، يقوم الخادم بتنفيذه كمعاملة واحدة حتى لو كانت السلسلة تحتوي على أوامر SQL متعددة، ما لم تكن هناك أوامر BEGIN/COMMIT صريحة متضمنة في السلسلة لتقسيمها إلى معاملات متعددة. (انظر القسم 54.2.2.1 لمزيد من التفاصيل حول كيفية تعامل الخادم مع السلاسل متعددة الاستعلامات.)

إذا لم تكن ترغب في تنفيذ عدة أوامر في معاملة واحدة، استخدم أوامر -c مكررة أو قم بتغذية أوامر متعددة إلى المدخل القياسي لـ psql، إما باستخدام echo كما هو موضح أعلاه، أو عبر مستند هنا للصدى، على سبيل المثال:

psql <<EOF
\x
SELECT * FROM foo;
EOF

--csv

التبديل إلى وضع إخراج CSV (قيم مفصولة بفواصل). هذا يعادل \pset format csv.

-d dbname
--dbname=dbname

يحدد اسم قاعدة البيانات للاتصال بها. هذا يعادل تحديد dbname كوسيط غير خيار أول على سطر الأوامر. يمكن أن يكون dbname سلسلة اتصال. إذا كان الأمر كذلك، فإن معلمات سلسلة الاتصال ستتجاوز أي خيارات متعارضة في سطر الأوامر.

-e
--echo-queries

انسخ جميع أوامر SQL المرسلة إلى الخادم إلى المخرج القياسي أيضًا. هذا يعادل تعيين المتغير ECHO على queries.

-E
--echo-hidden

اطبع الاستعلامات الفعلية التي تم إنشاؤها بواسطة \d والأوامر الوصفية الأخرى. يمكنك استخدام هذا لدراسة العمليات الداخلية لـ psql. هذا يعادل تعيين المتغير ECHO_HIDDEN على on.

-f filename
--file=filename

اقرأ الأوامر من الملف filename، بدلاً من المدخل القياسي. يمكن تكرار هذا الخيار ودمجه بأي ترتيب مع الخيار -c. عند تحديد -c أو -f، لا تقرأ psql الأوامر من المدخل القياسي؛ بدلاً من ذلك، تنتهي بعد معالجة جميع خيارات -c و -f بالتتابع. بخلاف ذلك، هذا الخيار يعادل إلى حد كبير الأمر الوصفي \i.

إذا كان filename هو - (شرطة)، فسيتم قراءة المدخل القياسي حتى يتم الإشارة إلى EOF أو أمر \q الوصفي. يمكن استخدام هذا للتبديل بين الإدخال التفاعلي والإدخال من الملفات. لاحظ مع ذلك أنه لا يتم استخدام Readline في هذه الحالة (تمامًا كما لو تم تحديد -n).

استخدام هذا الخيار يختلف بشكل طفيف عن كتابة psql < filename. بشكل عام، سيؤدي كلاهما إلى ما تتوقعه، ولكن استخدام -f يتيح بعض الميزات الرائعة مثل رسائل الخطأ مع أرقام الأسطر. هناك أيضًا احتمال طفيف بأن يؤدي استخدام هذا الخيار إلى تقليل الحمل الزائد لبدء التشغيل. من ناحية أخرى، فإن المتغير الذي يستخدم إعادة توجيه الإدخال للصدى مضمون (نظريًا) أن ينتج بالضبط نفس الإخراج الذي كنت ستحصل عليه لو كنت قد أدخلت كل شيء يدويًا.

-F separator
--field-separator=separator

استخدم separator كمفصل للحقول للإخراج غير المحاذاة. هذا يعادل \pset fieldsep أو \f.

-h hostname
--host=hostname

يحدد اسم المضيف للجهاز الذي يعمل عليه الخادم. إذا كانت القيمة تبدأ بشرطة مائلة، فسيتم استخدامها كدليل لمقبس Unix domain.

-H
--html

التبديل إلى وضع الإخراج HTML. هذا يعادل \pset format html أو الأمر \H.

-l
--list

سرد جميع قواعد البيانات المتاحة، ثم الخروج. يتم تجاهل خيارات الاتصال الأخرى. هذا يشبه الأمر الوصفي \list.

عند استخدام هذا الخيار، ستتصل psql بقاعدة البيانات postgres، ما لم يتم تسمية قاعدة بيانات مختلفة في سطر الأوامر (الخيار -d أو وسيط غير خيار، ربما عبر إدخال خدمة، ولكن ليس عبر متغير بيئة).

-L filename
--log-file=filename

اكتب جميع مخرجات الاستعلام في الملف filename، بالإضافة إلى وجهة الإخراج العادية.

-n
--no-readline

لا تستخدم Readline لتعديل الأسطر ولا تستخدم سجل الأوامر (انظر القسم المسمى “تعديل سطر الأوامر” أدناه).

-o filename
--output=filename

ضع جميع مخرجات الاستعلام في الملف filename. هذا يعادل الأمر \o.

-p port
--port=port

يحدد منفذ TCP أو امتداد ملف مقبس Unix domain المحلي الذي يستمع إليه الخادم للاتصالات. الافتراضي هو قيمة المتغير PGPORT في البيئة أو، إذا لم يتم تعيينه، المنفذ المحدد وقت الترجمة، عادةً 5432.

-P assignment
--pset=assignment

يحدد خيارات الطباعة، بأسلوب \pset. لاحظ أنه هنا يجب عليك فصل الاسم والقيمة بعلامة يساوي بدلاً من مسافة. على سبيل المثال، لتعيين تنسيق الإخراج إلى LaTeX، يمكنك كتابة -P format=latex.

-q
--quiet

يحدد أن psql يجب أن تقوم بعملها بهدوء. افتراضيًا، تطبع رسائل الترحيب وإخراج المعلومات المختلفة. إذا تم استخدام هذا الخيار، فلن يحدث أي من هذا. هذا مفيد مع الخيار -c. هذا يعادل تعيين المتغير QUIET على on.

-R separator
--record-separator=separator

استخدم separator كمفصل للسجلات للإخراج غير المحاذاة. هذا يعادل \pset recordsep.

-s
--single-step

قم بالتشغيل في وضع الخطوة الواحدة. هذا يعني أن المستخدم يتم سؤاله قبل إرسال كل أمر إلى الخادم، مع خيار إلغاء التنفيذ أيضًا. استخدم هذا لتصحيح الأخطاء في البرامج النصية.

-S
--single-line

>
يعمل في وضع السطر الواحد حيث يؤدي السطر الجديد إلى إنهاء أمر SQL، كما يفعل الفاصلة المنقوطة.

ملاحظة
تم توفير هذا الوضع لمن يصرون عليه، لكن لا يتم بالضرورة تشجيعك على استخدامه. على وجه الخصوص، إذا قمت بخلط أوامر SQL والأوامر الوصفية على سطر واحد، فقد لا يكون ترتيب التنفيذ واضحًا دائمًا للمستخدم غير المتمرس.

-t
--tuples-only

قم بإيقاف طباعة أسماء الأعمدة وتذييلات عدد صفوف النتائج، وما إلى ذلك. هذا يعادل \t أو \pset tuples_only.

-T table_options
--table-attr=table_options

تحدد الخيارات التي سيتم وضعها داخل علامة الجدول HTML. انظر \pset tableattr للتفاصيل.

-U username
--username=username

اتصل بقاعدة البيانات كمستخدم username بدلاً من المستخدم الافتراضي. (يجب أن يكون لديك الإذن للقيام بذلك، بالطبع.)

-v assignment
--set=assignment
--variable=assignment

قم بإجراء تعيين متغير، مثل الأمر الوصفي \set. لاحظ أنه يجب عليك فصل الاسم والقيمة، إن وجدت، بعلامة يساوي على سطر الأوامر. لإلغاء تعيين متغير، اترك علامة يساوي. لتعيين متغير بقيمة فارغة، استخدم علامة يساوي ولكن اترك القيمة فارغة. يتم إجراء هذه التعيينات أثناء معالجة سطر الأوامر، لذلك سيتم استبدال المتغيرات التي تعكس حالة الاتصال لاحقًا.

-V
--version

اطبع إصدار psql واخرج.

-w
--no-password

لا تطرح أبدًا سؤالاً عن كلمة المرور. إذا كان الخادم يتطلب مصادقة كلمة المرور ولم تكن كلمة المرور متاحة من مصادر أخرى مثل ملف .pgpass، فسيفشل محاولة الاتصال. يمكن أن يكون هذا الخيار مفيدًا في مهام الدُفعات والبرامج النصية حيث لا يوجد مستخدم لإدخال كلمة المرور.

لاحظ أن هذا الخيار سيظل مضبوطًا طوال الجلسة، وبالتالي يؤثر على استخدام الأمر الوصفي \connect بالإضافة إلى محاولة الاتصال الأولية.

-W
--password

أجبر psql على المطالبة بكلمة مرور قبل الاتصال بقاعدة بيانات، حتى لو لم يتم استخدام كلمة المرور.

إذا كان الخادم يتطلب مصادقة كلمة المرور ولم تكن كلمة المرور متاحة من مصادر أخرى مثل ملف .pgpass، فسوف يطالب psql بكلمة مرور على أي حال. ومع ذلك، سيضيع psql محاولة اتصال لمعرفة أن الخادم يريد كلمة مرور. في بعض الحالات، يستحق كتابة -W لتجنب محاولة الاتصال الإضافية.

لاحظ أن هذا الخيار سيظل مضبوطًا طوال الجلسة، وبالتالي يؤثر على استخدام الأمر الوصفي \connect بالإضافة إلى محاولة الاتصال الأولية.

-x
--expanded

قم بتشغيل وضع تنسيق الجدول الموسع. هذا يعادل \x أو \pset expanded.

-X
--no-psqlrc

لا تقرأ ملف بدء التشغيل (لا ملف psqlrc على مستوى النظام ولا ملف ~/.psqlrc للمستخدم).

-z
--field-separator-zero

اضبط فاصل الحقول للإخراج غير المحاذي على بايت صفري. هذا يعادل \pset fieldsep_zero.

-0
--record-separator-zero

اضبط فاصل السجلات للإخراج غير المحاذي على بايت صفري. هذا مفيد للتفاعل، على سبيل المثال، مع xargs -0. هذا يعادل \pset recordsep_zero.

-1
--single-transaction

يمكن استخدام هذا الخيار فقط بالاشتراك مع خيار واحد أو أكثر من -c و/أو -f. يتسبب في إصدار psql لأمر BEGIN قبل الخيار الأول وأمر COMMIT بعد الأخير، مما يغلف جميع الأوامر في معاملة واحدة. إذا فشل أي من الأوامر وتم تعيين المتغير ON_ERROR_STOP، يتم إرسال أمر ROLLBACK بدلاً من ذلك. يضمن هذا إما أن جميع الأوامر تكتمل بنجاح، أو لا يتم تطبيق أي تغييرات.

إذا كانت الأوامر نفسها تحتوي على BEGIN أو COMMIT أو ROLLBACK، فلن يكون لهذا الخيار التأثير المطلوب. أيضًا، إذا تعذر تنفيذ أمر فردي داخل كتلة معاملة، فإن تحديد هذا الخيار سيتسبب في فشل المعاملة بأكملها.

-?
--help[=topic]

عرض المساعدة حول psql والخروج. يحدد المعلم topic الاختياري (الافتراضي هو options) أي جزء من psql يتم شرحه: commands يصف الأوامر المائلة للخلف الخاصة بـ psql؛ options يصف خيارات سطر الأوامر التي يمكن تمريرها إلى psql؛ و variables يعرض المساعدة حول متغيرات تكوين psql.

حالة الخروج

يعيد psql القيمة 0 إلى shell إذا اكتمل بشكل طبيعي، 1 إذا حدث خطأ فادح خاص به (مثل نفاد الذاكرة، عدم العثور على ملف)، 2 إذا ساء الاتصال بالخادم ولم تكن الجلسة تفاعلية، و 3 إذا حدث خطأ في برنامج نصي وتم تعيين المتغير ON_ERROR_STOP.

الاستخدام

الاتصال بقاعدة بيانات

psql هو تطبيق عميل PostgreSQL عادي. للاتصال بقاعدة بيانات، تحتاج إلى معرفة اسم قاعدة البيانات المستهدفة، واسم المضيف ورقم منفذ الخادم، واسم مستخدم قاعدة البيانات الذي تريد الاتصال به. يمكن إخبار psql بهذه المعلمات عبر خيارات سطر الأوامر، وهي -d و -h و -p و -U على التوالي. إذا تم العثور على وسيط لا ينتمي إلى أي خيار، فسيتم تفسيره على أنه اسم قاعدة البيانات (أو اسم مستخدم قاعدة البيانات، إذا تم إعطاء اسم قاعدة البيانات بالفعل). ليست كل هذه الخيارات مطلوبة؛ توجد افتراضيات مفيدة. إذا حذفت اسم المضيف، فسيتصل psql عبر مقبس Unix-domain بخادم على المضيف المحلي، أو عبر TCP/IP إلى localhost على Windows. المنفذ الافتراضي هو المنفذ الافتراضي الذي يتم تحديده أثناء الترجمة. نظرًا لأن خادم قاعدة البيانات يستخدم نفس الافتراضي، فلن تحتاج إلى تحديد المنفذ في معظم الحالات. اسم مستخدم قاعدة البيانات الافتراضي هو اسم مستخدم نظام التشغيل الخاص بك. بمجرد تحديد اسم مستخدم قاعدة البيانات، يتم استخدامه كاسم قاعدة بيانات افتراضي. لاحظ أنه لا يمكنك الاتصال بأي قاعدة بيانات باسم مستخدم قاعدة بيانات معين. يجب أن يكون مسؤول قاعدة البيانات الخاص بك قد أبلغك بحقوق الوصول الخاصة بك.

عندما لا تكون الافتراضيات مناسبة تمامًا، يمكنك توفير على نفسك الكثير من الكتابة عن طريق تعيين متغيرات البيئة PGDATABASE و PGHOST و PGPORT و/أو PGUSER إلى قيم مناسبة. (لمتغيرات البيئة الإضافية، انظر القسم 32.15). من الملائم أيضًا وجود ملف ~/.pgpass لتجنب الحاجة إلى كتابة كلمات المرور بانتظام. انظر القسم 32.16 لمزيد من المعلومات.

طريقة بديلة لتحديد معلمات الاتصال هي في سلسلة conninfo أو URI، والتي تستخدم بدلاً من اسم قاعدة البيانات. تمنحك هذه الآلية تحكمًا واسعًا جدًا في الاتصال. على سبيل المثال:

$ psql "service=myservice sslmode=require"
$ psql postgresql://dbmaster:5433/mydb?sslmode=require

بهذه الطريقة يمكنك أيضًا استخدام LDAP للبحث عن معلمات الاتصال كما هو موضح في القسم 32.18. انظر القسم 32.1.2 لمزيد من المعلومات حول جميع خيارات الاتصال المتاحة.

إذا تعذر إجراء الاتصال لأي سبب (مثل عدم كفاية الأذونات، الخادم لا يعمل على المضيف المستهدف، إلخ)، فسيعيد psql خطأ ويخرج.

إذا كان كل من الإدخال القياسي والإخراج القياسي عبارة عن طرفية، فإن psql يضبط ترميز العميل على "auto"، والذي سيكتشف ترميز العميل المناسب من إعدادات الموقع (متغير البيئة LC_CTYPE في أنظمة Unix). إذا لم يعمل هذا كما هو متوقع، يمكن تجاوز ترميز العميل باستخدام متغير البيئة PGCLIENTENCODING.

إدخال أوامر SQL

في التشغيل العادي، يوفر psql موجهًا باسم قاعدة البيانات التي يتصل بها psql حاليًا، متبوعًا بالسلسلة =>. على سبيل المثال:

$ psql testdb
psql (18.1)
Type "help" for help.
testdb=>

عند الموجه، يمكن للمستخدم كتابة أوامر SQL. بشكل عام، يتم إرسال أسطر الإدخال إلى الخادم عند الوصول إلى فاصلة منقوطة تنهي الأمر. نهاية السطر لا تنهي أمرًا. وبالتالي يمكن توزيع الأوامر على عدة أسطر للوضوح. إذا تم إرسال الأمر وتنفيذه بدون خطأ، يتم عرض نتائج الأمر على الشاشة.

إذا كان لدى المستخدمين غير الموثوق بهم وصول إلى قاعدة بيانات لم تعتمد نمط استخدام مخطط آمن، فابدأ جلستك بإزالة المخططات القابلة للكتابة بشكل عام من search_path. يمكن للمرء إضافة الخيارات -csearch_path= إلى سلسلة الاتصال أو إصدار SELECT pg_catalog.set_config('search_path', '', false) قبل أوامر SQL الأخرى. هذا الاعتبار ليس خاصًا بـ psql؛ فهو ينطبق على كل واجهة لتنفيذ أوامر SQL عشوائية.

كلما تم تنفيذ أمر، يقوم psql أيضًا باستطلاع أحداث الإشعارات غير المتزامنة التي تم إنشاؤها بواسطة LISTEN و NOTIFY.

بينما يتم تمرير تعليقات الكتل على غرار C إلى الخادم للمعالجة والإزالة، تتم إزالة تعليقات معيار SQL بواسطة psql.

\gdesc

Shows the description (that is, the column names and data types) of the result of the current query buffer. The query is not actually executed; however, if it contains some type of syntax error, that error will be reported in the normal way.

If the current query buffer is empty, the most recently sent query is described instead.

\getenv psql_var env_var

Gets the value of the environment variable env_var and assigns it to the psql variable psql_var. If env_var is not defined in the psql process's environment, psql_var is not changed. Example: 
=> \getenv home HOME
=> \echo :home
/home/postgres

\gexec

Sends the current query buffer to the server, then treats each column of each row of the query's output (if any) as an SQL statement to be executed. For example, to create an index on each column of my_table: 
=> SELECT format('create index on my_table(%I)', attname)
-> FROM pg_attribute
-> WHERE attrelid = 'my_table'::regclass AND attnum > 0
-> ORDER BY attnum
-> \gexec
CREATE INDEX
CREATE INDEX
CREATE INDEX
CREATE INDEX

The generated queries are executed in the order in which the rows are returned, and left-to-right within each row if there is more than one column. NULL fields are ignored. The generated queries are sent literally to the server for processing, so they cannot be psql meta-commands nor contain psql variable references. If any individual query fails, execution of the remaining queries continues unless ON_ERROR_STOP is set. Execution of each query is subject to ECHO processing. (Setting ECHO to all or queries is often advisable when using \gexec.) Query logging, single-step mode, timing, and other query execution features apply to each generated query as well.

If the current query buffer is empty, the most recently sent query is re-executed instead.

\gset [ prefix ]

Sends the current query buffer to the server and stores the query's output into psql variables (see Variables below). The query to be executed must return exactly one row. Each column of the row is stored into a separate variable, named the same as the column. For example: 
=> SELECT 'hello' AS var1, 10 AS var2
-> \gset
=> \echo :var1 :var2
hello 10

If you specify a prefix, that string is prepended to the query's column names to create the variable names to use:

=> SELECT 'hello' AS var1, 10 AS var2
-> \gset result_
=> \echo :result_var1 :result_var2
hello 10

If a column result is NULL, the corresponding variable is unset rather than being set.

If the query fails or does not return one row, no variables are changed.

If the current query buffer is empty, the most recently sent query is re-executed instead.

\gx [ (option=value [...]) ] [ filename ]
\gx [ (option=value [...]) ] [ |command ]

\gx is equivalent to \g, except that it forces expanded output mode for this query, as if expanded=on were included in the list of \pset options. See also \x.

\h or \help [ command ]

Gives syntax help on the specified SQL command. If command is not specified, then psql will list all the commands for which syntax help is available. If command is an asterisk (*), then syntax help on all SQL commands is shown.

Unlike most other meta-commands, the entire remainder of the line is always taken to be the argument(s) of \help, and neither variable interpolation nor backquote expansion are performed in the arguments.


Note
To simplify typing, commands that consists of several words do not have to be quoted. Thus it is fine to type \help alter table.

\H or \html

Turns on HTML query output format. If the HTML format is already on, it is switched back to the default aligned text format. This command is for compatibility and convenience, but see \pset about setting other output options.

\i or \include filename

Reads input from the file filename and executes it as though it had been typed on the keyboard.

If filename is - (hyphen), then standard input is read until an EOF indication or \q meta-command. This can be used to intersperse interactive input with input from files. Note that Readline behavior will be used only if it is active at the outermost level.

If you want to see the lines on the screen as they are read you must set the variable ECHO to all.

\if expression
\elif expression
\else
\endif

This group of commands implements nestable conditional blocks. A conditional block must begin with an \if and end with an \endif. In between there may be any number of \elif clauses, which may optionally be followed by a single \else clause. Ordinary queries and other types of backslash commands may (and usually do) appear between the commands forming a conditional block.

The \if and \elif commands read their argument(s) and evaluate them as a Boolean expression. If the expression yields true then processing continues normally; otherwise, lines are skipped until a matching \elif, \else, or \endif is reached. Once an \if or \elif test has succeeded, the arguments of later \elif commands in the same block are not evaluated but are treated as false. Lines following an \else are processed only if no earlier matching \if or \elif succeeded.

The expression argument of an \if or \elif command is subject to variable interpolation and backquote expansion, just like any other backslash command argument. After that it is evaluated like the value of an on/off option variable. So a valid value is any unambiguous case-insensitive match for one of: true, false, 1, 0, on, off, yes, no. For example, t, T, and tR will all be considered to be true.

Expressions that do not properly evaluate to true or false will generate a warning and be treated as false.

Lines being skipped are parsed normally to identify queries and backslash commands, but queries are not sent to the server, and backslash commands other than conditionals (\if, \elif, \else, \endif) are ignored. Conditional commands are checked only for valid nesting. Variable references in skipped lines are not expanded, and backquote expansion is not performed either.

All the backslash commands of a given conditional block must appear in the same source file. If EOF is reached on the main input file or an \include-ed file before all local \if-blocks have been closed, then psql will raise an error.

Here is an example:

-- check for the existence of two separate records in the database and store
-- the results in separate psql variables
SELECT
    EXISTS(SELECT 1 FROM customer WHERE customer_id = 123) as is_customer,
    EXISTS(SELECT 1 FROM employee WHERE employee_id = 456) as is_employee
\gset
\if :is_customer
    SELECT * FROM customer WHERE customer_id = 123;
\elif :is_employee
    \echo 'is not a customer but is an employee'
    SELECT * FROM employee WHERE employee_id = 456;
\else
    \if yes
        \echo 'not a customer or employee'
    \else
        \echo 'this will never print'
    \endif
\endif

\ir or \include_relative filename

The \ir command is similar to \i, but resolves relative file names differently. When executing in interactive mode, the two commands behave identically. However, when invoked from a script, \ir interprets file names relative to the directory in which the script is located, rather than the current working directory.

هذا اختصار لـ \dp (“عرض الصلاحيات”).

\! [ command ]

بدون وسيط (argument)، يخرج إلى shell فرعي؛ يستأنف psql عند انتهاء shell الفرعي. مع وسيط، ينفذ أمر shell command.

\? [ topic ]

يعرض معلومات المساعدة. يحدد الوسيط الاختياري topic (الافتراضي هو commands) أي جزء من psql سيتم شرحه: commands يصف أوامر الشرطة المائلة العكسية لـ psql؛ options يصف خيارات سطر الأوامر التي يمكن تمريرها إلى psql؛ و variables يعرض المساعدة حول متغيرات تكوين psql.

\;

الشرطة المائلة العكسية متبوعة بفاصلة منقوطة (\;) ليست أمرًا وصفيًا بنفس طريقة الأوامر السابقة؛ بدلاً من ذلك، فإنها ببساطة تتسبب في إضافة فاصلة منقوطة إلى مخزن الاستعلام دون أي معالجة إضافية.

عادةً، يقوم psql بإرسال أمر SQL إلى الخادم بمجرد وصوله إلى الفاصلة المنقوطة التي تنهي الأمر، حتى لو كان هناك المزيد من الإدخال متبقيًا في السطر الحالي. على سبيل المثال، إدخال

select 1; select 2; select 3;

سيؤدي إلى إرسال أوامر SQL الثلاثة بشكل فردي إلى الخادم، مع عرض نتائج كل منها قبل الانتقال إلى الأمر التالي. ومع ذلك، فإن الفاصلة المنقوطة المدخلة كـ \; لن تشغل معالجة الأمر، بحيث يتم دمج الأمر الذي يسبقها وتلك التي تليه فعليًا وإرسالها إلى الخادم في طلب واحد. على سبيل المثال

select 1\; select 2\; select 3;

يؤدي إلى إرسال أوامر SQL الثلاثة إلى الخادم في طلب واحد، عند الوصول إلى الفاصلة المنقوطة غير المائلة. يقوم الخادم بتنفيذ مثل هذا الطلب كمعاملة واحدة، ما لم تكن هناك أوامر BEGIN/COMMIT صريحة مدرجة في السلسلة لتقسيمها إلى معاملات متعددة. (انظر القسم 54.2.2.1 لمزيد من التفاصيل حول كيفية معالجة الخادم للسلاسل متعددة الاستعلامات.)

Patterns

تقبل الأوامر \d المختلفة وسيط pattern لتحديد أسماء الكائنات المراد عرضها. في أبسط حالة، يكون النمط هو اسم الكائن الدقيق. يتم عادةً طي الأحرف داخل النمط إلى أحرف صغيرة، تمامًا كما في أسماء SQL؛ على سبيل المثال، \dt FOO سيعرض الجدول المسمى foo. كما هو الحال في أسماء SQL، فإن وضع علامات اقتباس مزدوجة حول النمط يوقف الطي إلى أحرف صغيرة. إذا كنت بحاجة إلى تضمين حرف اقتباس مزدوج فعلي في نمط، فاكتبه كزوج من علامات الاقتباس المزدوجة داخل تسلسل علامات اقتباس مزدوجة؛ مرة أخرى، هذا يتوافق مع قواعد معرفات SQL المقتبسة. على سبيل المثال، \dt "FOO""BAR" سيعرض الجدول المسمى FOO"BAR (وليس foo"bar). على عكس القواعد العادية لأسماء SQL، يمكنك وضع علامات اقتباس مزدوجة حول جزء فقط من النمط، على سبيل المثال \dt FOO"FOO"BAR سيعرض الجدول المسمى fooFOObar.

عندما يتم حذف الوسيط pattern تمامًا، تعرض أوامر \d جميع الكائنات المرئية في مسار البحث الحالي للمخطط (schema) - وهذا يعادل استخدام * كنمط. (يُقال إن الكائن مرئي إذا كان المخطط الذي يحتويه في مسار البحث ولم يظهر أي كائن من نفس النوع والاسم قبله في مسار البحث. وهذا يعادل القول بأن الكائن يمكن الإشارة إليه بالاسم دون تأهيل مخطط صريح.) لرؤية جميع الكائنات في قاعدة البيانات بغض النظر عن الرؤية، استخدم *.* كنمط.

داخل النمط، يطابق * أي تسلسل من الأحرف (بما في ذلك لا شيء) ويطابق ? أي حرف واحد. (هذه الترميز يمكن مقارنتها بأنماط أسماء ملفات shell في Unix.) على سبيل المثال، \dt int* يعرض الجداول التي تبدأ أسماؤها بـ int. ولكن داخل علامات الاقتباس المزدوجة، تفقد * و ? معانيهما الخاصة ويتم مطابقتهما حرفيًا.

نمط العلاقة (relation pattern) الذي يحتوي على نقطة (.) يتم تفسيره كنمط اسم مخطط متبوع بنمط اسم كائن. على سبيل المثال، \dt foo*.*bar* يعرض جميع الجداول التي تتضمن أسماء جداولها bar والتي تكون في مخططات تبدأ أسماؤها بـ foo. عندما لا تظهر نقطة، فإن النمط يطابق فقط الكائنات المرئية في مسار البحث الحالي للمخطط. مرة أخرى، تفقد النقطة داخل علامات الاقتباس المزدوجة معناها الخاص ويتم مطابقتها حرفيًا. نمط العلاقة الذي يحتوي على نقطتين (.) يتم تفسيره كاسم قاعدة بيانات متبوع بنمط اسم مخطط متبوع بنمط اسم كائن. لن يتم التعامل مع جزء اسم قاعدة البيانات كنمط ويجب أن يتطابق مع اسم قاعدة البيانات المتصلة حاليًا، وإلا فسيتم رفع خطأ.

نمط المخطط الذي يحتوي على نقطة (.) يتم تفسيره كاسم قاعدة بيانات متبوع بنمط اسم مخطط. على سبيل المثال، \dn mydb.*foo* يعرض جميع المخططات التي تتضمن أسماء مخططاتها foo. لن يتم التعامل مع جزء اسم قاعدة البيانات كنمط ويجب أن يتطابق مع اسم قاعدة البيانات المتصلة حاليًا، وإلا فسيتم رفع خطأ.

يمكن للمستخدمين المتقدمين استخدام تدوينات التعبيرات العادية (regular-expression) مثل فئات الأحرف، على سبيل المثال [0-9] لمطابقة أي رقم. تعمل جميع أحرف التعبيرات العادية الخاصة كما هو موضح في القسم 9.7.3، باستثناء . التي تعتبر فاصلة كما ذكر أعلاه، * التي يتم تحويلها إلى تدوين التعبيرات العادية .*، ? التي يتم تحويلها إلى .، و $ التي تتم مطابقتها حرفيًا. يمكنك محاكاة أحرف النمط هذه عند الحاجة بكتابة ? بدلاً من .، (R+|) بدلاً من R*، أو (R|) بدلاً من R?. لا حاجة لـ $ كحرف تعبير عادي حيث يجب أن يتطابق النمط مع الاسم بأكمله، على عكس التفسير العادي للتعبيرات العادية (بمعنى آخر، يتم إضافة $ تلقائيًا إلى نمطك). اكتب * في البداية و/أو النهاية إذا كنت لا ترغب في أن يكون النمط مثبتًا (anchored). لاحظ أنه داخل علامات الاقتباس المزدوجة، تفقد جميع أحرف التعبيرات العادية الخاصة معانيها الخاصة ويتم مطابقتها حرفيًا. أيضًا، تتم مطابقة أحرف التعبيرات العادية الخاصة حرفيًا في أنماط أسماء المعاملات (أي، وسيط \do).

ميزات متقدمة

Variables

يوفر psql ميزات استبدال المتغيرات مشابهة لأصداف Unix الشائعة. المتغيرات هي ببساطة أزواج اسم/قيمة، حيث يمكن أن تكون القيمة أي سلسلة بأي طول. يجب أن يتكون الاسم من أحرف (بما في ذلك الأحرف غير اللاتينية) وأرقام وشرطات سفلية.

لتعيين متغير، استخدم الأمر الوصفي لـ psql \set. على سبيل المثال،

testdb=> \set foo bar

يضبط المتغير foo إلى القيمة bar. لاسترداد محتوى المتغير، قم بوضع نقطتين فوق بعضهما (:) قبل الاسم، على سبيل المثال:

testdb=> \echo :foo
bar

يعمل هذا في كل من أوامر SQL العادية والأوامر الوصفية؛ هناك مزيد من التفاصيل في SQL Interpolation، أدناه.

إذا قمت باستدعاء \set بدون وسيط ثانٍ، فسيتم تعيين المتغير إلى قيمة سلسلة فارغة. لإلغاء تعيين (أي حذف) متغير، استخدم الأمر \unset. لعرض قيم جميع المتغيرات، استدعِ \set بدون أي وسيط.


Note

تخضع وسائط \set لنفس قواعد الاستبدال كما في الأوامر الأخرى. وبالتالي يمكنك بناء مراجع مثيرة للاهتمام مثل \set :foo 'something' والحصول على "روابط مرنة" أو "متغيرات متغيرات" من Perl أو PHP، على التوالي. للأسف (أو لحسن الحظ؟)، لا توجد طريقة للقيام بأي شيء مفيد بهذه البنى. من ناحية أخرى، \set bar :foo هو طريقة صالحة تمامًا لنسخ متغير.

يتم التعامل مع عدد من هذه المتغيرات بشكل خاص بواسطة psql. إنها تمثل بعض إعدادات الخيارات التي يمكن تغييرها أثناء التشغيل عن طريق تغيير قيمة المتغير، أو في بعض الحالات تمثل حالة psql قابلة للتغيير. بالاتفاق، أسماء جميع المتغيرات التي يتم التعامل معها بشكل خاص تتكون من جميع أحرف الأبجدية الإنجليزية الكبيرة (وربما الأرقام والشرطات السفلية). لضمان أقصى قدر من التوافق في المستقبل، تجنب استخدام مثل هذه الأسماء للمتغيرات لأغراضك الخاصة.

المتغيرات التي تتحكم في سلوك psql بشكل عام لا يمكن إلغاء تعيينها أو تعيينها لقيم غير صالحة. يُسمح بأمر \unset ولكن يتم تفسيره على أنه تعيين المتغير إلى قيمته الافتراضية. يتم تفسير أمر \set بدون وسيط ثانٍ على أنه تعيين المتغير إلى on، للمتغيرات التحكمية التي تقبل هذه القيمة، ويتم رفضه لغيرها. أيضًا، المتغيرات التحكمية التي تقبل قيم on و off ستقبل أيضًا تهجئات أخرى شائعة للقيم المنطقية، مثل true و false.

المتغيرات التي يتم التعامل معها بشكل خاص هي:

AUTOCOMMIT

عند التشغيل (on) (الافتراضي)، يتم التزام كل أمر SQL تلقائيًا عند اكتماله بنجاح. لتأجيل الالتزام في هذا الوضع، يجب عليك إدخال أمر SQL BEGIN أو START TRANSACTION. عند إيقاف التشغيل (off) أو إلغاء التعيين، لا يتم الالتزام بأوامر SQL حتى تقوم بشكل صريح بإصدار COMMIT أو END. يعمل وضع autocommit-off عن طريق إصدار BEGIN ضمني لك، قبل أي أمر ليس بالفعل في كتلة معاملة ولا هو أمر BEGIN أو أمر تحكم في المعاملة آخر، ولا أمر لا يمكن تنفيذه داخل كتلة معاملة (مثل VACUUM).

Note
في وضع autocommit-off، يجب عليك التخلي صراحة عن أي معاملة فشلت عن طريق إدخال ABORT أو ROLLBACK. ضع في اعتبارك أيضًا ثd line option -s.

SQLSTATE

رمز الخطأ (انظر الملحق A) المرتبط بفشل آخر استعلام SQL، أو 00000 إذا نجح.

USER

مستخدم قاعدة البيانات الذي تتصل به حاليًا. يتم تعيين هذا في كل مرة تتصل فيها بقاعدة بيانات (بما في ذلك بدء تشغيل البرنامج)، ولكن يمكن تغييره أو إلغاؤه.

VERBOSITY

يمكن تعيين هذا المتغير إلى القيم default، verbose، terse، أو sqlstate للتحكم في تفصيل تقارير الأخطاء. (انظر أيضًا \errverbose، للاستخدام عندما تريد نسخة مفصلة من الخطأ الذي حصلت عليه للتو.)

VERSION
VERSION_NAME
VERSION_NUM

يتم تعيين هذه المتغيرات عند بدء تشغيل البرنامج لتعكس إصدار psql، على التوالي كسلسلة مفصلة، وسلسلة قصيرة (على سبيل المثال، 9.6.2، 10.1، أو 11beta1)، ورقم (على سبيل المثال، 90602 أو 100001). يمكن تغييرها أو إلغاؤها.

WATCH_INTERVAL

يحدد هذا المتغير الفاصل الزمني الافتراضي، بالثواني، الذي ينتظره \watch بين تنفيذ الاستعلام. الافتراضي هو 2 ثانية. تحديد فاصل زمني في الأمر يتجاوز هذا المتغير.

استيفاء SQL

ميزة رئيسية لمتغيرات psql هي أنه يمكنك استبدال ("استيفاء") هذه المتغيرات في عبارات SQL العادية، وكذلك في وسائط الأوامر الوصفية. علاوة على ذلك، يوفر psql تسهيلات لضمان أن القيم المتغيرة المستخدمة كقيم حرفية ومعرفات SQL يتم اقتباسها بشكل صحيح. صيغة استيفاء قيمة بدون أي اقتباس هي إضافة نقطتين رأسيتين (:) قبل اسم المتغير. على سبيل المثال:

testdb=> \set foo 'my_table'
testdb=> SELECT * FROM :foo;

سيستعلم عن الجدول my_table. لاحظ أن هذا قد يكون غير آمن: يتم نسخ قيمة المتغير حرفيًا، لذلك يمكن أن تحتوي على علامات اقتباس غير متوازنة، أو حتى أوامر الشرطة المائلة العكسية. يجب عليك التأكد من أنها منطقية حيث تضعها.

عندما يراد استخدام قيمة كقيمة حرفية أو معرف SQL، فإن أكثر الطرق أمانًا هي التأكد من اقتباسها. لاقتباس قيمة متغير كقيمة حرفية SQL، اكتب نقطتين رأسيتين متبوعتين باسم المتغير بعلامات اقتباس فردية. لاقتباس القيمة كمعرف SQL، اكتب نقطتين رأسيتين متبوعتين باسم المتغير بعلامات اقتباس مزدوجة. هذه التراكيب تتعامل بشكل صحيح مع علامات الاقتباس والأحرف الخاصة الأخرى المضمنة داخل قيمة المتغير. المثال السابق سيكون أكثر أمانًا إذا كتب بهذه الطريقة:

testdb=> \set foo 'my_table'
testdb=> SELECT * FROM :"foo";

لن يتم إجراء استيفاء المتغيرات داخل القيم الحرفية والمعرفات SQL المقتبسة. لذلك، فإن إنشاء مثل ':foo' لا يعمل لإنتاج قيمة حرفية مقتبسة من قيمة متغير (وسيكون غير آمن إذا عمل، لأنه لن يعالج بشكل صحيح علامات الاقتباس المضمنة في القيمة).

أحد الاستخدامات لهذا الآلية هو نسخ محتويات ملف إلى عمود جدول. قم أولاً بتحميل الملف إلى متغير ثم استوفِ قيمة المتغير كسلسلة مقتبسة:

testdb=> \set content `cat my_file.txt`
testdb=> INSERT INTO my_table VALUES (:'content');

(لاحظ أن هذا لا يزال لن يعمل إذا كان my_file.txt يحتوي على بايتات NUL. psql لا يدعم بايتات NUL المضمنة في قيم المتغيرات.)

نظرًا لأن النقاط الرأسية يمكن أن تظهر بشكل قانوني في أوامر SQL، فإن محاولة استيفاء واضحة (أي، :name، :'name'، أو :"name") لا يتم استبدالها ما لم يكن المتغير المسمى معينًا حاليًا. في أي حال، يمكنك تجاوز نقطة رأسية بشرطة مائلة عكسية لحمايتها من الاستبدال.

الصيغة الخاصة :{?name} ترجع TRUE أو FALSE اعتمادًا على ما إذا كان المتغير موجودًا أم لا، وبالتالي يتم استبدالها دائمًا، ما لم يتم تجاوز النقطة الرأسية بشرطة مائلة عكسية.

صيغة النقطة الرأسية للمتغيرات هي SQL قياسية للغات الاستعلام المضمنة، مثل ECPG. صيغ النقطة الرأسية لشرائح المصفوفات ورميات الأنواع هي امتدادات PostgreSQL، والتي يمكن أن تتعارض أحيانًا مع الاستخدام القياسي. صيغة النقطة الرأسية-الاقتباس لتهريب قيمة المتغير كقيمة حرفية أو معرف SQL هي امتداد psql.

التحفيز

يمكن تخصيص المحفزات التي يصدرها psql حسب تفضيلاتك. المتغيرات الثلاثة PROMPT1، PROMPT2، و PROMPT3 تحتوي على سلاسل وتسلسلات هروب خاصة تصف مظهر المحفز. المحفز 1 هو المحفز العادي الذي يتم إصداره عندما يطلب psql أمرًا جديدًا. المحفز 2 يتم إصداره عندما يكون هناك المزيد من الإدخال متوقعًا أثناء إدخال الأمر، على سبيل المثال لأن الأمر لم يتم إنهاؤه بفاصلة منقوطة أو لم يتم إغلاق علامة اقتباس. المحفز 3 يتم إصداره عندما تقوم بتشغيل أمر SQL COPY FROM STDIN وتحتاج إلى كتابة قيمة صف على الطرفية.

تتم طباعة قيمة المتغير المحفز المحدد حرفيًا، باستثناء الحالات التي يتم فيها العثور على علامة النسبة المئوية (%). اعتمادًا على الحرف التالي، يتم استبدال نص معين بدلاً منه. الاستبدالات المعرفة هي:

%M

اسم المضيف الكامل (مع اسم النطاق) لخادم قاعدة البيانات، أو [local] إذا كان الاتصال عبر مقبس نطاق Unix، أو [local:/dir/name]، إذا لم يكن مقبس نطاق Unix في الموقع المدمج.

%m

اسم مضيف خادم قاعدة البيانات، مقتطع عند النقطة الأولى، أو [local] إذا كان الاتصال عبر مقبس نطاق Unix.

%>

رقم المنفذ الذي يستمع إليه خادم قاعدة البيانات.

%n

اسم مستخدم جلسة قاعدة البيانات. (قد يتغير توسيع هذه القيمة أثناء جلسة قاعدة البيانات نتيجة للأمر SET SESSION AUTHORIZATION.)

%s

اسم الخدمة.

%/

اسم قاعدة البيانات الحالية.

%~

مثل %/، ولكن الإخراج هو ~ (تيش) إذا كانت قاعدة البيانات هي قاعدة البيانات الافتراضية الخاصة بك.

%#

إذا كان مستخدم الجلسة هو مستخدم قاعدة بيانات خارق، فسيتم عرض #، وإلا فسيتم عرض >. (قد يتغير توسيع هذه القيمة أثناء جلسة قاعدة البيانات نتيجة للأمر SET SESSION AUTHORIZATION.)

%p

معرف العملية للخلفية المتصلة حاليًا.

%P

حالة خط الأنابيب: متوقف عند عدم وجود خط أنابيب، قيد التشغيل عند وجود خط أنابيب مستمر أو إلغاء عند وجود خط أنابيب ملغي.

%R

في المحفز 1 عادةً ما يكون =، ولكن @ إذا كانت الجلسة في فرع غير نشط من كتلة شرطية، أو ^ إذا كان في وضع سطر واحد، أو ! إذا كان الجلسة غير متصلة بقاعدة البيانات (وهو ما يمكن أن يحدث إذا فشل \connect). في المحفز 2، يتم استبدال %R بحرف يعتمد على سبب توقع psql لمزيد من الإدخال: - إذا لم يتم إنهاء الأمر ببساطة بعد، ولكن * إذا كان هناك تعليق /* ... */ غير مكتمل، علامة اقتباس فردية إذا كان هناك سلسلة مقتبسة غير مكتملة، علامة اقتباس مزدوجة إذا كان هناك معرف مقتبس غير مكتمل، علامة الدولار إذا كان هناك سلسلة مقتبسة بالدولار غير مكتملة، أو ( إذا كان هناك قوس أيسر غير متطابق. في المحفز 3، لا ينتج %R شيئًا.

%x

حالة المعاملة: سلسلة فارغة عند عدم وجود كتلة معاملات، أو * عند وجود كتلة معاملات، أو ! عند وجود كتلة معاملات فاشلة، أو ? عندما تكون حالة المعاملة غير مؤكدة (على سبيل المثال، بسبب عدم وجود اتصال).

%l

رقم السطر داخل العبارة الحالية، بدءًا من 1.

%digits

يتم استبدال الحرف بالرمز الثماني المحدد.

%:name:

قيمة متغير psql name. انظر المتغيرات، أعلاه، للحصول على التفاصيل.

%`command`

إخراج command، مشابه لاستبدال "الشرطة المائلة العكسية" العادي.

%[ ... %]

يمكن أن تحتوي المحفزات على أحرف تحكم في الطرفية والتي، على سبيل المثال، تغير لون أو خلفية أو نمط نص المحفز، أو تغير عنوان نافذة الطرفية. لكي تعمل ميزات تحرير الأسطر الخاصة بـ Readline بشكل صحيح، يجب تحديد أحرف التحكم غير القابلة للطباعة هذه على أنها غير مرئية عن طريق إحاطتها بـ %[ و %]. يمكن أن تحدث أزواج متعددة من هذه داخل المحفز. على سبيل المثال: 
testdb=> \set PROMPT1 '%[%033[1;33;40m%]%n@%/%R%[%033[0m%]%# '

ينتج عنه محفز أصفر غامق (1؛33؛40) على خلفية سوداء (33؛40) على الطرفيات المتوافقة مع VT100 والقادرة على الألوان.

%w

مسافة بيضاء بنفس العرض الذي كان عليه آخر إخراج لـ PROMPT1. يمكن استخدام هذا كإعداد لـ PROMPT2، بحيث تتم محاذاة العبارات متعددة الأسطر مع السطر الأول، ولكن لا يوجد محفز ثانوي مرئي.
لإدراج علامة النسبة المئوية في المحفز الخاص بك، اكتب %%. المحفزات الافتراضية هي '%/%R%x%# ' للمحفزين 1 و 2، و '>> ' للمحفز 3.

تحرير سطر الأوامر

يستخدم psql مكتبة Readline أو libedit، إذا كانت متاحة، لتحرير واسترجاع الأسطر بشكل مريح. يتم حفظ سجل الأوامر تلقائيًا عند خروج psql ويتم إعادة تحميله عند بدء psql. اضغط على السهم لأعلى أو control-P لاسترجاع الأسطر السابقة.

(اعتمادًا على المكتبة المستخدمة، قد تحتاج إلى الضغط على TAB أكثر من مرة للحصول على قائمة.)

$if psql

البيئة

الأعمدة

إذا كانت أعمدة \pset صفرًا ، فإنها تتحكم في العرض للتنسيق الملتف والعرض لتحديد ما إذا كان الإخراج الواسع يتطلب قارئ الشاشة أو يجب تبديله إلى التنسيق العمودي في وضع الالتفاف التلقائي الموسع.

PGDATABASE
PGHOST
PGPORT
PGUSER

معلمات الاتصال الافتراضية (انظر القسم 32.15).

PG_COLOR

يحدد ما إذا كان سيتم استخدام اللون في رسائل التشخيص. القيم الممكنة هي دائمًا ، تلقائي ، وأبدًا.

PSQL_EDITOR
EDITOR
VISUAL

المحرر المستخدم بواسطة أوامر \e و \ef و \ev. يتم فحص هذه المتغيرات بالترتيب المذكور؛ يتم استخدام أول متغير تم تعيينه. إذا لم يتم تعيين أي منها ، فإن الافتراضي هو استخدام vi على أنظمة Unix أو notepad.exe على أنظمة Windows.

PSQL_EDITOR_LINENUMBER_ARG

عند استخدام \e أو \ef أو \ev مع وسيط رقم سطر ، يحدد هذا المتغير وسيط سطر الأوامر المستخدم لتمرير رقم السطر المبدئي إلى محرر المستخدم. بالنسبة للمحررات مثل Emacs أو vi ، يكون هذا عبارة عن علامة زائد. قم بتضمين مسافة لاحقة في قيمة المتغير إذا كانت هناك حاجة لمسافة بين اسم الخيار ورقم السطر. أمثلة: 
PSQL_EDITOR_LINENUMBER_ARG='+'
PSQL_EDITOR_LINENUMBER_ARG='--line '

الافتراضي هو + على أنظمة Unix (يتوافق مع المحرر الافتراضي vi ، وهو مفيد للعديد من المحررات الشائعة الأخرى) ؛ ولكن لا يوجد افتراضي على أنظمة Windows.

PSQL_HISTORY

موقع بديل لملف سجل الأوامر. يتم إجراء توسيع العلامة ~ ( ).

PSQL_PAGER
PAGER

PSQL_WATCH_PAGER

عند تنفيذ استعلام بشكل متكرر باستخدام الأمر \watch ، لا يتم استخدام قارئ الشاشة افتراضيًا. يمكن تغيير هذا السلوك عن طريق تعيين PSQL_WATCH_PAGER إلى أمر قارئ شاشة ، على أنظمة Unix. يمكن لقارئ الشاشة pspg (ليس جزءًا من PostgreSQL ولكنه متاح في العديد من توزيعات البرامج مفتوحة المصدر) عرض مخرجات \watch إذا تم تشغيله بالخيار --stream.

PSQLRC

موقع بديل لملف .psqlrc الخاص بالمستخدم. يتم إجراء توسيع العلامة ~ ( ).

SHELL

الأمر الذي يتم تنفيذه بواسطة الأمر \!.

TMPDIR

الدليل لتخزين الملفات المؤقتة. الافتراضي هو /tmp.

تستخدم هذه الأداة ، مثل معظم أدوات PostgreSQL الأخرى ، أيضًا متغيرات البيئة التي تدعمها libpq (انظر القسم 32.15).

الملفات

psqlrc و ~/.psqlrc

ما لم يتم تمرير خيار -X إليه ، يحاول psql قراءة وتنفيذ الأوامر من ملف بدء التشغيل على مستوى النظام (psqlrc) ثم ملف بدء التشغيل الشخصي للمستخدم ( ~/.psqlrc) ، بعد الاتصال بقاعدة البيانات ولكن قبل قبول الأوامر العادية. يمكن استخدام هذه الملفات لإعداد العميل و/أو الخادم حسب الرغبة ، عادةً بأوامر \set و SET.

يُطلق على ملف بدء التشغيل على مستوى النظام اسم psqlrc. افتراضيًا ، يتم البحث عنه في دليل "تهيئة النظام" الخاص بالتثبيت ، والذي يتم تحديده بشكل موثوق عن طريق تشغيل pg_config --sysconfdir. عادةً ما يكون هذا الدليل ../etc/ بالنسبة للدليل الذي يحتوي على ملفات تنفيذ PostgreSQL. يمكن تعيين الدليل الذي سيتم البحث فيه صراحةً عبر متغير البيئة PGSYSCONFDIR.

يُطلق على ملف بدء التشغيل الشخصي للمستخدم اسم .psqlrc ويتم البحث عنه في الدليل الرئيسي للمستخدم الذي يقوم بالاستدعاء. على أنظمة Windows ، يُطلق على ملف بدء التشغيل الشخصي بدلاً من ذلك اسم %APPDATA%\postgresql\psqlrc.conf. في كلتا الحالتين ، يمكن تجاوز مسار الملف الافتراضي هذا عن طريق تعيين متغير البيئة PSQLRC.

يمكن جعل كل من ملف بدء التشغيل على مستوى النظام وملف بدء التشغيل الشخصي للمستخدم مخصصًا لإصدار psql عن طريق إضافة شرطة ومعرف إصدار PostgreSQL الرئيسي أو الثانوي إلى اسم الملف ، على سبيل المثال ~/.psqlrc-18 أو ~/.psqlrc-18.1. سيتم قراءة الملف الأكثر تحديدًا الذي يتطابق مع الإصدار قبل الملف غير المحدد الإصدار. تتم إضافة هذه اللواحق الإصدار بعد تحديد مسار الملف كما هو موضح أعلاه.

.psql_history

يتم تخزين سجل سطر الأوامر في الملف ~/.psql_history ، أو %APPDATA%\postgresql\psql_history على Windows.

يمكن تعيين موقع ملف السجل صراحةً عبر متغير psql HISTFILE أو متغير البيئة PSQL_HISTORY.

● يعمل psql بشكل أفضل مع الخوادم من نفس الإصدار الرئيسي أو إصدار أقدم. من المرجح أن تفشل أوامر الشرطة المائلة العكسية بشكل خاص إذا كان الخادم من إصدار أحدث من psql نفسه. ومع ذلك ، يجب أن تعمل أوامر الشرطة المائلة العكسية من عائلة \d مع الخوادم من إصدارات ترجع إلى 9.2 ، ولكن ليس بالضرورة مع الخوادم الأحدث من psql نفسه. يجب أن تعمل الوظيفة العامة لتشغيل أوامر SQL وعرض نتائج الاستعلام مع الخوادم من إصدار رئيسي أحدث ، ولكن لا يمكن ضمان ذلك في جميع الحالات.

إذا كنت ترغب في استخدام psql للاتصال بالعديد من الخوادم ذات الإصدارات الرئيسية المختلفة ، فمن المستحسن استخدام أحدث إصدار من psql. بدلاً من ذلك ، يمكنك الاحتفاظ بنسخة من psql من كل إصدار رئيسي والتأكد من استخدام الإصدار الذي يتوافق مع الخادم المعني. ولكن في الواقع ، لا ينبغي أن يكون هذا التعقيد الإضافي ضروريًا.

● قبل PostgreSQL 9.6 ، كان الخيار -c يعني -X (--no-psqlrc) ؛ لم يعد هذا هو الحال.
● قبل PostgreSQL 8.4 ، سمح psql بالوسيط الأول لأمر شرطة مائلة عكسية بحرف واحد بالبدء مباشرة بعد الأمر ، دون مسافات بيضاء فاصلة. الآن ، هناك حاجة إلى بعض المسافات البيضاء.

ملاحظات لمستخدمي Windows

تم بناء psql كـ "تطبيق وحدة تحكم". نظرًا لأن نوافذ وحدة التحكم في Windows تستخدم ترميزًا مختلفًا عن بقية النظام ، يجب عليك اتخاذ عناية خاصة عند استخدام أحرف 8 بت داخل psql. إذا اكتشف psql صفحة رمز وحدة تحكم إشكالية ، فسيحذرك عند بدء التشغيل. لتغيير صفحة رمز وحدة التحكم ، يلزم شيئان:

•قم بتعيين صفحة الرمز عن طريق إدخال cmd.exe /c chcp 1252. (1252 هي صفحة رمز مناسبة للألمانية ؛ استبدلها بقيمتك.) إذا كنت تستخدم Cygwin ، يمكنك وضع هذا الأمر في /etc/profile.
•قم بتعيين خط وحدة التحكم إلى Lucida Console ، لأن خط نقطة الحبر لا يعمل مع صفحة رمز ANSI.

NAME

psql - PostgreSQL interactive terminal

SYNOPSIS

psql [option...] [dbname [username]]

DESCRIPTION

psql is a front-end program that allows you to type SQL queries interactively, send them to a PostgreSQL database, and see the results. It also provides a number of meta-commands and shell-like features for convenience. Additionally, it can process input from a file or from standard input.

When psql is used interactively, it prompts the user for input, parses the input as either SQL or one of its meta-commands, and executes the command. When used in batch mode (i.e., standard input is not a terminal), it executes commands from the input and exits.

The following are some of the most common meta-commands:

\?
Shows available meta-commands.
\l
Lists available databases.
\dt
Lists available tables.
\d table
Describes the columns of a table.
\q
Quits psql.

OPTIONS

psql accepts a wide range of command-line options to control its behavior. Some of the most useful options include:

-d dbname
Specifies the name of the database to connect to. If this option is omitted and a database name is provided as a positional argument, that argument is used as the database name.
-U username
Specifies the username to connect as. If omitted, the default is the current operating system username.
-h hostname
Specifies the hostname of the machine on which the server is running. If omitted, psql attempts to connect via a local Unix domain socket, or falls back to using TCP/IP based on the `PGHOST` environment variable.
-p port
Specifies the TCP port or local Unix domain socket file extension on which the server is listening for connections. If omitted, the default is the `PGPORT` environment variable or the default port compiled into PostgreSQL (usually 5432).
-W
Force psql to prompt for a password before connecting to a database.
-f filename
Read commands from the specified file and exit when done.
-c command
Specifies that psql should execute the single command string and exit.
-e
Echo the commands as they are sent to the server. This is useful for debugging.
-x
Produce extended table listings (like the output of \d+).
-t
Print only the table data, without the result header and footer.

EXIT STATUS

psql exits with a status of 0 if it successfully completes all commands, and 1 if any error occurs.

USAGE

The interactive prompt indicates the database name and username. For example:

testdb=>

If you are connected as user `postgres` to database `testdb`, the prompt will look like this:

postgres@testdb=>

Meta-commands begin with a backslash (\). These are internal commands to psql, not SQL commands. For example, \dt lists tables.

SQL commands can be entered directly. They must end with a semicolon (;) to be executed.

testdb=> SELECT count(*) FROM pg_catalog.pg_tables;
 count
-------
    39
(1 row)

If a command is too long to fit on one line, psql will indicate this with an indented continuation prompt:

testdb=> SELECT *
testdb-> FROM pg_catalog.pg_tables
testdb-> WHERE schemaname = 'public';
  schemaname   | tablename  | storage_type | table_type | has_oids | has_row_level_security | is_insertable_into | is_typed
---------------+------------+--------------+------------+----------+------------------------+--------------------+----------
 public        | my_table   | heap         | ordinary   | f        | f                      | t                  | f
(1 row)

ENVIRONMENT

The following environment variables can be used to control psql's behavior:

PGDATABASE
Default database name.
PGUSER
Default username.
PGHOST
Default host name.
PGPORT
Default port.
PGPASSWORD
Default password.
PGOPTIONS
Additional connection options.
PGCLIENTENCODING
Default client encoding.
MYSQL_HOME
Used by the \connect_mysql command. Specify the installation directory of MySQL client libraries.
MYSQL_UNIX_PORT
Used by the \connect_mysql command. Specify the path to the MySQL socket file.
PGCONNECT_TIMEOUT
Number of seconds to wait for a connection attempt to establish.
TZ
Used to determine the timezone to display times in.

FILES

~/.psqlrc

This file is read at the start of every interactive session. It can be used to set up psql variables or define custom meta-commands.

NOTES

Meta-commands provide a convenient way to interact with the database and psql itself. Many meta-commands accept arguments and can be used in various ways. For example, \d can be used without arguments to list all tables, or with a table name to describe a specific table.

The \d command also works for other database objects like views, sequences, and indexes.

You can set various variables within psql using the \set meta-command. For example, \set HISTSIZE 1000 sets the command history size.

psql supports query cancellation using Ctrl+C.

NOTES FOR WINDOWS USERS

On Windows, psql might not be able to use Unix domain sockets. In such cases, it will use TCP/IP connections even for local connections. The default port is 5432.
