psx_load_syscalls(3)

الحزمة: libcap

التراخيص: BSD-3-Clause OR GPL-2.0-only

LIBPSX(3) دليل مبرمج Linux LIBPSX(3)

الاسم

psx_syscall3, psx_syscall6, psx_set_sensitivity - دلالات POSIX لاستدعاءات النظام

الملخص

#include <sys/psx_syscall.h>
long int psx_syscall3(long int syscall_nr,
                      long int arg1, long int arg2, long int arg3);
long int psx_syscall6(long int syscall_nr,
                      long int arg1, long int arg2, long int arg3,
                      long int arg4, long int arg5, long int arg6);
int psx_set_sensitivity(psx_sensitivity_t sensitivity);
void psx_load_syscalls(long int (**syscall_fn)(long int,
                                    long int, long int, long int),
                       long int (**syscall6_fn)(long int,
                                    long int, long int, long int,
                                    long int, long int, long int));

يمكن ربط أي رمز يستخدم أحد الدوال المذكورة أعلاه على النحو التالي:

ld ... -lpsx -lpthread

gcc ... -lpsx -lpthread

لاحظ، يلزم وجود علامات خاصة لجعل -lcap يعمل مع القدرات الخاصة بالعملية عند ربطه مع -lpsx. وبالتحديد، استخدم ملف خيار pkg-config: gcc ... -lcap $(pkg-config --libs --cflags libpsx). المزيد من التفاصيل متاحة في صفحة الدليل cap_get_proc(3).

الوصف

تحاول مكتبة libpsx سد فجوة تركتها عملية تنفيذ pthreads(7) على Linux. لكي تكون خيوط POSIX متوافقة، وعبر آلية setxid الخاصة بـ nptl(7)، تحافظ glibc على اتساق بيانات اعتماد UID و GID بين جميع الخيوط المرتبطة بالعملية الحالية. ومع ذلك، فإن حالة الاعتماد الأخرى غير مدعومة بواسطة هذا التجريد. لدعم سمات الأمان الممتدة التي تديرها النواة، توفر libpsx زوجًا أكثر عمومية من دوال استدعاء النظام المغلفة: psx_syscall3() و psx_syscall6(). على غرار آلية setxid، يتم تنسيق حالة الخيط عبر إشارة الوقت الفعلي. بينما تستخدم آلية nptl:setxid signo=33 (التي تخفيها glibc أسفل SIGRTMIN المعاد تعريفه)، تدرج libpsx نفسها في مكدس معالج SIGSYS. تبذل جهودًا كبيرة لتكون أول معالج من هذا القبيل ولكنها تعمل كمرر لاستخدامات SIGSYS الأخرى.

تدعم خدعة ماكرو غير فعالة دالة psx_syscall() الزائفة التي تأخذ من 1 إلى 7 وسائط، اعتمادًا على احتياجات المتصل. تقوم الماكرو (التي تستدعي في النهاية __psx_syscall()) بحشو الاستدعاء لاستخدام psx_syscall3() أو psx_syscall6() بالفعل مع أصفار تملأ الوسائط المفقودة. بينما سيجعل استخدام هذا في شفرة المصدر يبدو نظيفًا، فإن بصمة الشفرة الفعلية أكبر. يتم تشجيعك على استخدام الدوال psx_syscall3() و psx_syscall6() الأكثر وضوحًا حسب الحاجة.

تقوم psx_set_sensitivity() بتغيير سلوك استدعاءات النظام المنسوخة: PSX_IGNORE تضمن تجاهل الاختلافات (السلوك الافتراضي)؛ PSX_WARNING تطبع إشعارًا على stderr حول كيفية اختلاف النتائج؛ PSX_ERROR تطبع تفاصيل الخطأ وتنشئ إشارة SIGSYS.

يمكن استخدام psx_load_syscalls() لتعيين مؤشرات وظائف محددة من قبل المتصل لاستدعاء استدعاءات النظام ذات 3 و 6 وسائط. يمكن استخدام هذه الدالة لتكوين مكتبة، أو برنامج لتغيير السلوك عند ربطه بمكتبة libpsx. في الواقع، تستخدم libcap هذه الدالة من libpsx لتجاوز واجهة برمجة التطبيقات الخاصة بها المستندة إلى استدعاءات النظام افتراضيًا بنمط الخيوط. عند الربط مع libpsx، يمكن لـ libcap العمل على جميع خيوط البرنامج متعدد الخيوط للعمل وفقًا لدلالات POSIX.

قيمة الإرجاع

قيمة الإرجاع لدوال استدعاء النظام هي عمومًا القيمة التي ترجعها النواة، أو -1 في حالة حدوث خطأ. في مثل هذه الحالات، يتم تعيين errno(3) إلى قيمة الخطأ المفصلة. تحاول الدوال psx_syscall3() و psx_syscall6() إجراء استدعاء نظام بشريط واحد وتعود فورًا في حالة حدوث خطأ. إذا نجح هذا الاستدعاء، فسيتم تنفيذ نفس استدعاءات النظام من معالج إشارة على كل من الخيوط الأخرى للعملية.

متوافق مع

احتياجات libcap(3) لدلالات POSIX لمعالجة القدرات. يمكنك قراءة المزيد حول سبب الحاجة إلى ذلك هنا:

https://sites.google.com/site/fullycapable/who-ordered-libpsx

إصدارات libpsx قبل 2.72 كانت تدعم pthreads فقط. منذ libpsx-2.72، تعمل المكتبة مع جميع تطبيقات خيوط Linux حيث تعمل على أدنى مستوى من تجريد الخيوط، LWPs.
