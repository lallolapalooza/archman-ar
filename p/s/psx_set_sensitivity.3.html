psx_set_sensitivity(3)

الحزمة: libcap

التراخيص: BSD-3-Clause OR GPL-2.0-only

LIBPSX(3) دليل مبرمج Linux LIBPSX(3)

الاسم

psx_syscall3, psx_syscall6, psx_set_sensitivity - دلالات POSIX لاستدعاءات النظام

الشكل العام

#include <sys/psx_syscall.h>
long int psx_syscall3(long int syscall_nr,
                      long int arg1, long int arg2, long int arg3);
long int psx_syscall6(long int syscall_nr,
                      long int arg1, long int arg2, long int arg3,
                      long int arg4, long int arg5, long int arg6);
int psx_set_sensitivity(psx_sensitivity_t sensitivity);
void psx_load_syscalls(long int (**syscall_fn)(long int,
                                    long int, long int, long int),
                       long int (**syscall6_fn)(long int,
                                    long int, long int, long int,
                                    long int, long int, long int));

يمكن ربط أي كود يستخدم إحدى الوظائف المذكورة أعلاه على النحو التالي:

ld ... -lpsx -lpthread

gcc ... -lpsx -lpthread

ملاحظة، هناك حاجة إلى علامات خاصة لجعل -lcap يعمل مع قدرات عملية كاملة عند ربطه مع -lpsx. وهي تحديداً، استخدم ملف خيارات pkg-config: gcc ... -lcap $(pkg-config --libs --cflags libpsx). المزيد من التفاصيل متاحة في صفحة الدليل cap_get_proc(3).

الوصف

تحاول مكتبة libpsx سد فجوة تركتها عملية تطبيق pthreads(7) على Linux. لكي تكون خيوط POSIX متوافقة، عبر آلية setxid الخاصة بـ nptl(7)، تحتفظ glibc ببيانات اعتماد UID و GID متسقة بين جميع الخيوط المرتبطة بالعملية الحالية. ومع ذلك، فإن حالة الاعتماد الأخرى غير مدعومة بواسطة هذا التجريد. لدعم سمات الأمان الممتدة التي تديرها النواة، توفر libpsx زوجًا أكثر عمومية من وظائف استدعاء النظام الغامضة: psx_syscall3() و psx_syscall6(). مثل آلية setxid، يتم تنسيق حالة الخيط بواسطة إشارة في الوقت الفعلي. بينما تستخدم آلية nptl:setxid الإشارة signo=33 (التي تخفيها glibc أسفل SIGRTMIN معاد تعريفه)، تدرج libpsx نفسها في مكدس معالج SIGSYS. تبذل جهودًا كبيرة لتكون أول معالج كهذا ولكنها تعمل كواجهة مرور لاستخدامات SIGSYS الأخرى.

ماكرو غير فعال يدعم الدالة الوهمية psx_syscall() التي تأخذ من 1 إلى 7 وسائط، اعتمادًا على احتياجات المتصل. تقوم الماكرو (التي تستدعي في النهاية __psx_syscall()) بحشو الاستدعاء لاستخدام psx_syscall3() أو psx_syscall6() فعليًا مع أصفار تملأ الوسائط المفقودة. بينما سيجعل استخدام هذا في الكود المصدري يبدو نظيفًا، فإن بصمة الكود الفعلية أكبر. يتم تشجيعك على استخدام الوظائف الأكثر صراحة psx_syscall3() و psx_syscall6() حسب الحاجة.

psx_set_sensitivity() يغير سلوك استدعاءات النظام المتطابقة: PSX_IGNORE تضمن تجاهل الاختلافات (السلوك الافتراضي)؛ PSX_WARNING يطبع إشعارًا قياسيًا عن كيفية اختلاف النتائج؛ و PSX_ERROR يطبع تفاصيل الخطأ وينشئ إشارة SIGSYS.

psx_load_syscalls() يمكن استخدامها لتعيين مؤشرات وظائف محددة من قبل المتصل لاستدعاء استدعاءات النظام ذات 3 و 6 وسائط. يمكن استخدام هذه الوظيفة لتكوين مكتبة، أو برنامج لتغيير السلوك عند ربطه مقابل libpsx. بالفعل، تستخدم libcap هذه الوظيفة من libpsx لتجاوز واجهة برمجة التطبيقات الخاصة بها المستندة إلى استدعاء النظام والتي نطاقها هو الخيط. عند الربط مع libpsx، يمكن لـ libcap العمل على جميع خيوط برنامج متعدد الخيوط للعمل بدلالات POSIX.

قيمة الإرجاع

قيمة الإرجاع لوظائف استدعاء النظام هي عمومًا القيمة التي تم إرجاعها بواسطة النواة، أو -1 في حالة حدوث خطأ. في مثل هذه الحالات، يتم تعيين errno(3) إلى قيمة الخطأ التفصيلية. تحاول الوظائف psx_syscall3() و psx_syscall6() إجراء استدعاء نظام أحادي الخيط والعودة فورًا في حالة حدوث خطأ. إذا نجح هذا الاستدعاء، فسيتم تنفيذ نفس استدعاءات النظام من معالج إشارة على كل خيط آخر في العملية.

متوافق مع

احتياجات libcap(3) لدلالات POSIX لمعالجة القدرات. يمكنك قراءة المزيد حول سبب الحاجة إلى ذلك هنا:

https://sites.google.com/site/fullycapable/who-ordered-libpsx

الإصدارات من libpsx قبل 2.72 كانت تدعم pthreads فقط. منذ libpsx-2.72، تعمل المكتبة مع جميع تطبيقات خيوط Linux لأنها تعمل على أدنى مستوى من تجريد الخيوط، LWPs.
