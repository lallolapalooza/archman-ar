select(2) دليل استدعاءات النظام select(2)

الاسم

select, pselect, FD_CLR, FD_ISSET, FD_SET, FD_ZERO, fd_set - تعدد إرسال الإدخال/الإخراج المتزامن

المكتبة

مكتبة C القياسية (libc, -lc)

ملخص

#include <sys/select.h>
typedef /* ... */ fd_set;
int select(int nfds, fd_set *_Nullable restrict readfds,
           fd_set *_Nullable restrict writefds,
           fd_set *_Nullable restrict exceptfds,
           struct timeval *_Nullable restrict timeout);
void FD_CLR(int fd, fd_set *set);
int  FD_ISSET(int fd, const fd_set *set);
void FD_SET(int fd, fd_set *set);
void FD_ZERO(fd_set *set);
int pselect(int nfds, fd_set *_Nullable restrict readfds,
           fd_set *_Nullable restrict writefds,
           fd_set *_Nullable restrict exceptfds,
           const struct timespec *_Nullable restrict timeout,
           const sigset_t *_Nullable restrict sigmask);

الوصف

تحذير: يمكن لـ select() مراقبة واصفات الملفات التي أرقامها أقل من FD_SETSIZE (1024) فقط - وهو حد غير معقول لمعظم التطبيقات الحديثة - ولن يتغير هذا الحد. يجب على جميع التطبيقات الحديثة استخدام poll(2) أو epoll(7) بدلاً من ذلك، والتي لا تعاني من هذا الحد.

يسمح select() للبرنامج بمراقبة واصفات ملفات متعددة، والانتظار حتى يصبح واحد أو أكثر من واصفات الملفات "جاهزًا" لفئة ما من عمليات الإدخال/الإخراج (مثل، إمكانية الإدخال). يعتبر واصف الملف جاهزًا إذا كان من الممكن إجراء عملية إدخال/إخراج مقابلة (مثل read(2)، أو write(2) صغيرة بما يكفي) دون حظر.

fd_set

نوع بنية يمكنه تمثيل مجموعة من واصفات الملفات. وفقًا لـ POSIX، الحد الأقصى لعدد واصفات الملفات في بنية fd_set هو قيمة الثابت FD_SETSIZE.

مجموعات واصفات الملفات

الوسائط الرئيسية لـ select() هي ثلاث "مجموعات" من واصفات الملفات (معرفة بنوع fd_set)، والتي تسمح للمستدعي بالانتظار لثلاث فئات من الأحداث على المجموعة المحددة من واصفات الملفات. يمكن تحديد كل من وسائط fd_set كـ NULL إذا لم يكن هناك واصفات ملفات لمراقبتها لفئة الأحداث المقابلة.

ملاحظة مهمة: عند العودة، يتم تعديل كل مجموعة من واصفات الملفات في مكانها للإشارة إلى واصفات الملفات التي هي حاليًا "جاهزة". لذلك، إذا كنت تستخدم select() داخل حلقة، يجب إعادة تهيئة المجموعات قبل كل استدعاء.

يمكن معالجة محتويات مجموعة واصفات الملفات باستخدام الثوابت التالية:

FD_ZERO()
يقوم هذا الثابت بمسح (إزالة جميع واصفات الملفات من) set. يجب استخدامه كخطوة أولى في تهيئة مجموعة واصفات الملفات.
FD_SET()
يقوم هذا الثابت بإضافة واصف الملف fd إلى set. إضافة واصف ملف موجود بالفعل في المجموعة لا تفعل شيئًا، ولا تنتج خطأ.
FD_CLR()
يقوم هذا الثابت بإزالة واصف الملف fd من set. إزالة واصف ملف غير موجود في المجموعة لا تفعل شيئًا، ولا تنتج خطأ.
FD_ISSET()
يقوم select() بتعديل محتويات المجموعات وفقًا للقواعد الموضحة أدناه. بعد استدعاء select()، يمكن استخدام الثابت FD_ISSET() لاختبار ما إذا كان واصف الملف لا يزال موجودًا في مجموعة. يعيد FD_ISSET() قيمة غير صفرية إذا كان واصف الملف fd موجودًا في set، وصفر إذا لم يكن كذلك.

الوسائط

وسائط select() هي كما يلي:

readfds
تتم مراقبة واصفات الملفات في هذه المجموعة لمعرفة ما إذا كانت جاهزة للقراءة. واصف الملف يكون جاهزًا للقراءة إذا كانت عملية قراءة لن تحظر؛ على وجه الخصوص، يكون واصف الملف جاهزًا أيضًا عند نهاية الملف.
بعد عودة select()، سيتم مسح readfds من جميع واصفات الملفات باستثناء تلك الجاهزة للقراءة.
writefds
تتم مراقبة واصفات الملفات في هذه المجموعة لمعرفة ما إذا كانت جاهزة للكتابة. واصف الملف يكون جاهزًا للكتابة إذا كانت عملية كتابة لن تحظر. ومع ذلك، حتى لو أشار واصف الملف على أنه قابل للكتابة، فقد لا تزال عملية كتابة كبيرة تحظر.
بعد عودة select()، سيتم مسح writefds من جميع واصفات الملفات باستثناء تلك الجاهزة للكتابة.
exceptfds
تتم مراقبة واصفات الملفات في هذه المجموعة لـ "الظروف الاستثنائية". لأمثلة على بعض الظروف الاستثنائية، انظر مناقشة POLLPRI في poll(2).
بعد عودة select()، سيتم مسح exceptfds من جميع واصفات الملفات باستثناء تلك التي حدثت فيها حالة استثنائية.
nfds
يجب تعيين هذه الوسيطة لتكون أعلى رقم واصف ملف في أي من المجموعات الثلاث، بالإضافة إلى 1. يتم فحص واصفات الملفات المحددة في كل مجموعة، حتى هذا الحد (لكن انظر BUGS).
timeout
الوسيطة timeout هي بنية timeval (موضحة أدناه) تحدد الفترة الزمنية التي يجب أن يحظر فيها select() انتظارًا لوصف الملف ليصبح جاهزًا. سيتم حظر الاستدعاء حتى:
•
يصبح واصف ملف جاهزًا؛
•
يتم مقاطعة الاستدعاء بواسطة معالج الإشارات؛ أو
•
تنتهي مهلة الانتظار.
لاحظ أن الفترة الزمنية timeout سيتم تقريبها لأعلى إلى دقة ساعة النظام، وقد تتجاوز تأخيرات جدولة النواة فترة الحظر بمقدار صغير.
إذا كان كلا حقلي بنية timeval صفرين، فإن select() يعود على الفور. (هذا مفيد للاستقصاء).
إذا تم تحديد timeout كـ NULL، فإن select() يحظر إلى أجل غير مسمى في انتظار أن يصبح واصف ملف جاهزًا.

pselect()

يسمح استدعاء النظام pselect() للتطبيق بالانتظار بأمان حتى يصبح واصف ملف جاهزًا أو حتى يتم التقاط إشارة.

عمل select() و pselect() متطابق، بخلاف هذه الاختلافات الثلاثة:

•
يستخدم select() مهلة هي struct timeval (مع ثوانٍ وميكروثوانٍ)، بينما يستخدم pselect() struct timespec (مع ثوانٍ ونانوثوانٍ).
•
قد يقوم select() بتحديث الوسيطة timeout للإشارة إلى مقدار الوقت المتبقي. لا يقوم pselect() بتغيير هذه الوسيطة.
•
لا يحتوي select() على وسيطة sigmask، ويتصرف كما لو تم استدعاء pselect() مع NULL sigmask.

sigmask هو مؤشر لقناع إشارة (انظر sigprocmask(2))؛ إذا لم يكن NULL، فإن pselect() يستبدل أولاً القناع الحالي للإشارة بالقناع.

pselect6(2) — Arch manual pages

NAME

pselect6, select, pselect - synchronous I/O multiplexing

LIBRARY

Standard C library (libc, -lc)

SYNOPSIS

#include <sys/select.h>
int select(int nfds, fd_set *restrict readfds, fd_set *restrict writefds, fd_set *restrict exceptfds, struct timeval *restrict timeout);
int pselect6(int nfds, fd_set *restrict readfds, fd_set *restrict writefds, fd_set *restrict exceptfds, const struct timespec *restrict timeout, const sigset_t *restrict sigmask);
int pselect(int nfds, fd_set *restrict readfds, fd_set *restrict writefds, fd_set *restrict exceptfds, struct timeval *restrict timeout, const sigset_t *restrict sigmask);

DESCRIPTION

The select(), pselect6(), and pselect() system calls monitor a specified set of file descriptors to determine whether any would block when a read, write, or exception condition is requested. This is called polling or multiplexing.

The first three arguments to select() and pselect6() are file descriptor sets, which tell the kernel which file descriptors the calling process is interested in. The last argument, nfds, is the number of file descriptors to be checked. The kernel checks only the file descriptors numbered 0 up to (but not including) nfds. The actual file descriptor numbers are the indices into the arrays of integers that make up the fd_set. If a file descriptor is not set in any of the sets, it is ignored. nfds should be set to the highest-numbered file descriptor plus 1.

The arguments readfds, writefds, and exceptfds point to objects of type fd_set, which is a type defined in <sys/select.h>. This type is a structure that contains a fixed number of bits, where each bit corresponds to a file descriptor. The macros FD_ZERO(), FD_SET(), FD_CLR(), and FD_ISSET() are provided to manipulate these structures.

  • FD_ZERO(&fdset);

    Initializes the set fdset to have zero bits set.

  • FD_SET(fd, &fdset);

    Initializes the bit corresponding to file descriptor fd in the set fdset.

  • FD_CLR(fd, &fdset);

    Clears the bit corresponding to file descriptor fd in the set fdset.

  • FD_ISSET(fd, &fdset);

    Returns a non-zero value if the bit corresponding to file descriptor fd is set in fdset, and zero otherwise.

select() examines the file descriptors specified in readfds for readiness to read, those in writefds for readiness to write, and those in exceptfds for exceptional conditions. If any descriptor in any of the sets is ready (or times out), select() returns. Otherwise, select() blocks until the timeout expires or until a descriptor becomes ready.

The timeout argument points to a `struct timeval` (defined in <sys/time.h>) which specifies the time interval to wait. If timeout is not NULL, select() blocks for at most that long. If timeout is NULL, select() blocks indefinitely.

If the call is interrupted by a signal, select() returns -1 and sets errno to EINTR. If the timeout expires before any file descriptor is ready, select() returns 0. Otherwise, select() returns the total number of file descriptors that are ready for some kind of operation. The file descriptor sets are modified to indicate which file descriptors are ready.

pselect6() is similar to select(), but it adds a sixth argument, sigmask, which is a pointer to a sigset_t. pselect6() atomically replaces the calling process's signal mask with the one specified by sigmask and then waits for an activity on any of the specified file descriptors. When the call returns (either due to activity, timeout, or interrupt), the signal mask is reset to its original value.

pselect() is a wrapper around pselect6() that takes a `struct timeval *` for the timeout argument, like select().

The nfds argument to select() and pselect() specifies the highest-numbered file descriptor in any of the three sets, plus one. File descriptors numbering from 0 to nfds-1 are checked. Any file descriptor greater than or equal to nfds in any of the sets is ignored. The value of nfds should be at least 1.

The file descriptor sets are modified by the call to indicate which file descriptors are ready. If the timeout expires, all sets are empty on return. If the call returns due to an error, the contents of the sets are undefined.

The timeout argument is modified by select() to indicate the remaining time. This behavior is not portable. The glibc wrapper for pselect() avoids this by copying the timeout to a local variable.

The file descriptor sets are value-result arguments. This means that before the call, the calling process specifies the file descriptors it is interested in. Upon return, the kernel indicates which of those file descriptors are ready. This is a design error that is avoided in poll(2) and epoll(7).

FD_SETSIZE

The range of file descriptors that can be specified in a file descriptor set. The Linux kernel imposes no fixed limit, but the glibc implementation makes fd_set a fixed-size type, with FD_SETSIZE defined as 1024, and the FD_*() macros operating according to that limit. To monitor file descriptors greater than 1023, use poll(2) or epoll(7) instead.

POLLIN, POLLPRI, and POLLOUT, POLLERR, and POLLNVAL

select() monitors for readability, writability, and exceptional conditions. These correspond to the following conditions:

  • readfds: ready for reading

  • writefds: ready for writing

  • exceptfds: exceptional conditions exist

For sockets, these correspond to the following conditions:

  • POLLIN: data is available for read.

  • POLLPRI: urgent data is available for read.

  • POLLOUT: the file descriptor is writable.

  • POLLERR: an error occurred on the file descriptor.

  • POLLNVAL: an invalid file descriptor was given in one of the sets.

RETURN VALUE

On success, select() returns the total number of file descriptors contained in the selected sets that are ready for the requested I/O operation. If the timeout expires before any file descriptor is ready, it returns 0. On error, it returns -1 and sets errno to indicate the error.

ERRORS

EBADF
An invalid file descriptor was passed in one of the sets. Or, the nfds argument was negative. Or, a file descriptor was greater than or equal to the system limit (RLIMIT_NOFILE).
EINTR
A signal was caught before any of the specified file descriptors were ready.
EINVAL
An invalid timeout value was provided. Or, nfds was zero.
ENOMEM
Could not allocate memory to copy the file descriptor sets.

VERSIONS

The timeout argument to select() was previously modified to reflect the remaining time. This behavior is not portable. The glibc wrapper for pselect() avoids this by internally copying the timeout to a local variable and passing that variable to the system call.

STANDARDS

select() conforms to POSIX.1-2001, POSIX.1-2008.

pselect6() is specified by POSIX.1-2008.

pselect() is specified by SUSv2, POSIX.1-2001, and POSIX.1-2008.

HISTORY

The select() function first appeared in 4.3BSD.

pselect() was introduced in Linux 2.6.11.

pselect6() was introduced in Linux 2.6.32.

NOTES

The implementation of the fd_set arguments as value-result arguments is a design error that is avoided in poll(2) and epoll(7).

According to POSIX, select() should check all specified file descriptors in the three file descriptor sets, up to the limit nfds-1. However, the current implementation ignores any file descriptor in these sets that is greater than the maximum file descriptor number that the process currently has open. According to POSIX, any such file descriptor that is specified in one of the sets should result in the error EBADF.

Starting with glibc 2.1, glibc provided an emulation of pselect() that was implemented using sigprocmask(2) and select(). This implementation remained vulnerable to the very race condition that pselect() was designed to prevent. Modern versions of glibc use the (race-free) pselect() system call on kernels where it is provided.

On Linux, select() may report a socket file descriptor as "ready for reading", while nevertheless a subsequent read blocks. This could for example happen when data has arrived but upon examination has the wrong checksum and is discarded. There may be other circumstances in which a file descriptor is spuriously reported as ready. Thus it may be safer to use O_NONBLOCK on sockets that should not block.

On Linux, select() also modifies timeout if the call is interrupted by a signal handler (i.e., the EINTR error return). This is not permitted by POSIX.1. The Linux pselect() system call has the same behavior, but the glibc wrapper hides this behavior by internally copying the timeout to a local variable and passing that variable to the system call.

EXAMPLES

#include <stdio.h>
#include <stdlib.h>
#include <sys/select.h>
#include <sys/time.h>
int
main(void)
{
    int             retval;
    fd_set          rfds;
    struct timeval  tv;
    /* Watch stdin (fd 0) to see when it has input.  */
    FD_ZERO(&rfds);
    FD_SET(0, &rfds);
    /* Wait up to five seconds.  */
    tv.tv_sec = 5;
    tv.tv_usec = 0;
    retval = select(1, &rfds, NULL, NULL, &tv);
    /* Don't rely on the value of tv now! */
    if (retval == -1)
        perror("select()");
    else if (retval)
        printf("Data is available now.\n");
        /* FD_ISSET(0, &rfds) will be true.  */
    else
        printf("No data within five seconds.\n");
    exit(EXIT_SUCCESS);
}
