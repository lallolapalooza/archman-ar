putenv(3) دليل الدوال المكتبية putenv(3)

الاسم

putenv - تغيير أو إضافة متغير بيئة

المكتبة

مكتبة C القياسية (libc، -lc)

الملخص

#include <stdlib.h>
int putenv(char *string);
متطلبات ماكرو اختبار الميزة لـ glibc (انظر feature_test_macros(7)):

putenv():

    _XOPEN_SOURCE
        || /* glibc >= 2.19: */ _DEFAULT_SOURCE
        || /* glibc <= 2.19: */ _SVID_SOURCE

الوصف

تقوم الدالة putenv() بإضافة أو تغيير قيمة متغيرات البيئة. الوسيط string يكون على شكل name=value. إذا كان name غير موجود بالفعل في البيئة، تتم إضافة string إلى البيئة. إذا كان name موجودًا بالفعل، يتم تغيير قيمة name في البيئة إلى value. السلسلة النصية التي يشير إليها string تصبح جزءًا من البيئة، لذا فإن تغيير السلسلة النصية يغير البيئة.

قيمة الإرجاع

تُرجع الدالة putenv() القيمة صفر عند النجاح. عند الفشل، تُرجع قيمة غير صفرية، ويتم تعيين errno للإشارة إلى الخطأ.

الأخطاء

ENOMEM
مساحة غير كافية لتخصيص بيئة جديدة.

الخصائص

لشرح المصطلحات المستخدمة في هذا القسم، انظر attributes(7).

الواجهة الخاصية القيمة
putenv () سلامة الخيوط MT-Unsafe const:env

المعايير

POSIX.1-2008.

التاريخ

POSIX.1-2001، SVr2، 4.3BSD-Reno.

لا يُشترط أن تكون الدالة putenv() قابلة لإعادة الدخول، وتلك الموجودة في glibc 2.0 ليست كذلك، ولكن الإصدار 2.1 من glibc هو كذلك.

منذ glibc 2.1.2، يتوافق تنفيذ glibc مع SUSv2: يتم استخدام المؤشر string المُمرر إلى putenv(). على وجه الخصوص، تصبح هذه السلسلة النصية جزءًا من البيئة؛ تغييرها لاحقًا سيغير البيئة. (وبالتالي، من الخطأ استدعاء putenv() باستخدام متغير تلقائي كوسيط، ثم العودة من الدالة المستدعية بينما لا يزال string جزءًا من البيئة.) ومع ذلك، من glibc 2.0 إلى glibc 2.1.1، يختلف الأمر: يتم استخدام نسخة من السلسلة النصية. من ناحية، يتسبب هذا في تسرب للذاكرة، ومن ناحية أخرى، ينتهك SUSv2.

يستخدم إصدار 4.3BSD-Reno، مثل glibc 2.0، نسخة؛ تم إصلاح هذا في جميع أنظمة BSD الحديثة.

يزيل SUSv2 const من النموذج الأولي، وكذلك glibc 2.1.3.

يوفر تنفيذ مكتبة GNU C امتدادًا غير قياسي. إذا لم تتضمن string علامة يساوي:


putenv("NAME");

فإنه تتم إزالة المتغير المسمى من بيئة المستدعي.
