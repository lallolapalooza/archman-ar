pg_recvlogical(1)

الحزمة: postgresql

التراخيص: PostgreSQL

PG_RECVLOGICAL(1) وثائق PostgreSQL 18.1 PG_RECVLOGICAL(1)

الاسم

pg_recvlogical - التحكم في تدفقات النسخ المنطقي لـ PostgreSQL

ملخص

pg_recvlogical [خيار...]

الوصف

pg_recvlogical يتحكم في فتحات النسخ المنطقي ويقوم ببث البيانات من هذه الفتحات.

يقوم بإنشاء اتصال بنمط النسخ، لذا فهو يخضع لنفس القيود التي يخضع لها pg_receivewal(1)، بالإضافة إلى قيود النسخ المنطقي (انظر الفصل 47).

pg_recvlogical لا يمتلك ما يعادل أوضاع المعاينة والحصول لواجهة فك النسخ المنطقي SQL. يرسل تأكيدات إعادة التشغيل للبيانات بشكل متراخٍ أثناء استلامها وعند الخروج النظيف. لفحص البيانات المعلقة في فتحة دون استهلاكها، استخدم pg_logical_slot_peek_changes.

في غياب الأخطاء الفادحة، سيستمر pg_recvlogical في العمل حتى يتم إنهاؤه بواسطة إشارة SIGINT (Control+C) أو SIGTERM.

عندما يستلم pg_recvlogical إشارة SIGHUP، فإنه يغلق ملف الإخراج الحالي ويفتح ملفًا جديدًا باستخدام اسم الملف المحدد بواسطة الخيار --file. هذا يسمح لنا بتدوير ملف الإخراج عن طريق إعادة تسمية الملف الحالي أولاً ثم إرسال إشارة SIGHUP إلى pg_recvlogical.

الخيارات

يجب تحديد واحد على الأقل من الخيارات التالية لتحديد إجراء:

--create-slot

إنشاء فتحة نسخ منطقي جديدة بالاسم المحدد بواسطة --slot، باستخدام المكون الإضافي للإخراج المحدد بواسطة --plugin، لقاعدة البيانات المحددة بواسطة --dbname.

الخياران --slot و --dbname مطلوبان لهذا الإجراء.

يمكن تحديد الخيارين --enable-two-phase و --enable-failover مع --create-slot.

--drop-slot

حذف فتحة النسخ بالاسم المحدد بواسطة --slot، ثم الخروج.

الخيار --slot مطلوب لهذا الإجراء.

--start

بدء بث التغييرات من فتحة النسخ المنطقي المحددة بواسطة --slot، والاستمرار حتى يتم إنهاؤه بواسطة إشارة. إذا انتهى بث التغييرات من جانب الخادم بإيقاف تشغيل الخادم أو قطع الاتصال، فحاول إعادة المحاولة في حلقة ما لم يتم تحديد --no-loop.

الخياران --slot و --dbname و --file مطلوبة لهذا الإجراء.

يتم تحديد تنسيق التدفق بواسطة المكون الإضافي للإخراج المحدد عند إنشاء الفتحة.

يجب أن يكون الاتصال بنفس قاعدة البيانات المستخدمة لإنشاء الفتحة.

يمكن تحديد --create-slot و --start معًا. لا يمكن دمج --drop-slot مع إجراء آخر.

تتحكم خيارات سطر الأوامر التالية في موقع وتنسيق الإخراج وسلوك النسخ الآخر:

-E lsn
--endpos=lsn

في وضع --start، قم بإيقاف النسخ تلقائيًا والخروج بحالة خروج طبيعية 0 عند وصول الاستلام إلى LSN المحدد. إذا تم تحديده عند عدم وجوده في وضع --start، فسيتم رفع خطأ.

إذا كان هناك سجل له LSN مطابق بالضبط لـ lsn، فسيتم إخراج السجل.

الخيار --endpos ليس على دراية بحدود المعاملات وقد يقوم بقص الإخراج في منتصف معاملة. سيتم إعادة تشغيل أي معاملة تم إخراجها جزئيًا مرة أخرى عند قراءة الفتحة منها في المرة التالية. لا يتم قص الرسائل الفردية مطلقًا.

--enable-failover

يمكّن الفتحة من المزامنة مع النسخ الاحتياطي. يمكن تحديد هذا الخيار فقط مع --create-slot.

-f filename
--file=filename

اكتب البيانات المستلمة والمفككة للمعاملات في هذا الملف. استخدم - للإخراج القياسي.

هذا المعامل مطلوب لـ --start.

-F interval_seconds
--fsync-interval=interval_seconds

يحدد مدى تكرار استدعاء pg_recvlogical لدالة fsync() لضمان تفريغ ملف الإخراج بأمان على القرص.

سيطلب الخادم من العميل بشكل دوري إجراء تفريغ والإبلاغ عن موضع التفريغ إلى الخادم. هذا الإعداد هو بالإضافة إلى ذلك، لإجراء التفريغ بشكل متكرر.

تحديد فترة فاصلة قدرها 0 يعطل استدعاء استدعاءات fsync() تمامًا، مع الاستمرار في إبلاغ الخادم بالتقدم. في هذه الحالة، يمكن فقدان البيانات في حالة حدوث تعطل.

-I lsn
--startpos=lsn

في وضع --start، ابدأ النسخ من LSN المحدد. للحصول على تفاصيل حول تأثير هذا، راجع الوثائق في الفصل 47 والقسم 54.4. يتم تجاهله في الأوضاع الأخرى.

--if-not-exists

لا ترفع خطأ عند تحديد --create-slot ووجود فتحة بالاسم المحدد بالفعل.

-n
--no-loop

عند فقدان الاتصال بالخادم، لا تحاول إعادة المحاولة في حلقة، فقط اخرج.

-o name[=value]
--option=name[=value]

مرر الخيار name إلى المكون الإضافي للإخراج مع، إذا تم تحديده، قيمة الخيار value. تعتمد الخيارات الموجودة وتأثيراتها على المكون الإضافي للإخراج المستخدم.

-P plugin
--plugin=plugin

عند إنشاء فتحة، استخدم مكون النسخ المنطقي الإضافي للإخراج المحدد. انظر الفصل 47. هذا الخيار ليس له تأثير إذا كانت الفتحة موجودة بالفعل.

-s interval_seconds
--status-interval=interval_seconds

هذا الخيار له نفس تأثير الخيار بنفس الاسم في pg_receivewal(1). انظر الوصف هناك.

-S slot_name
--slot=slot_name

في وضع --start، استخدم فتحة النسخ المنطقي الموجودة المسماة slot_name. في وضع --create-slot، قم بإنشاء الفتحة بهذا الاسم. في وضع --drop-slot، احذف الفتحة بهذا الاسم.

هذا المعامل مطلوب لأي من الإجراءات.

-t
--enable-two-phase
--two-phase (مهمل)

يمكّن فك المعاملات المحضرة. يمكن تحديد هذا الخيار فقط مع --create-slot.

-v
--verbose

يمكّن الوضع المطول.

تتحكم خيارات سطر الأوامر التالية في معلمات اتصال قاعدة البيانات.

-d dbname
--dbname=dbname

قاعدة البيانات للاتصال بها. انظر وصف الإجراءات لما يعنيه هذا بالتفصيل. يمكن أن يكون dbname سلسلة اتصال. إذا كان الأمر كذلك، فإن معلمات سلسلة الاتصال ستبطل أي خيارات سطر أوامر متعارضة.

هذا المعامل مطلوب لـ --create-slot و --start.

-h hostname-or-ip
--host=hostname-or-ip

يحدد اسم المضيف للجهاز الذي يعمل عليه الخادم. إذا بدأت القيمة بشرطة مائلة، فسيتم استخدامها كدليل لمقبس Unix domain socket. يتم أخذ الافتراضي من متغير البيئة PGHOST، إذا تم تعيينه، وإلا فسيتم محاولة اتصال مقبس Unix domain socket.

-p port
--port=port

يحدد منفذ TCP أو امتداد ملف مقبس Unix domain socket المحلي الذي يستمع إليه الخادم للاتصالات. الافتراضي هو متغير البيئة PGPORT، إذا تم تعيينه، أو افتراضي مدمج.

-U user
--username=user

اسم المستخدم للاتصال به. الافتراضي هو اسم مستخدم نظام التشغيل الحالي.

-w
--no-password

لا تطالب بكلمة مرور أبدًا. إذا كان الخادم يتطلب مصادقة كلمة المرور ولم تكن كلمة المرور متاحة بوسائل أخرى مثل ملف .pgpass، فسيفشل محاولة الاتصال. يمكن أن يكون هذا الخيار مفيدًا في الدُفعات والنصوص البرمجية حيث لا يوجد مستخدم لإدخال كلمة مرور.

-W
--password

يجبر pg_recvlogical على المطالبة بكلمة مرور قبل الاتصال بقاعدة بيانات.

هذا الخيار ليس ضروريًا أبدًا، حيث سيطالب pg_recvlogical تلقائيًا بكلمة مرور

pg_recvlogical(1) — PostgreSQL 18.1

NAME

pg_recvlogical — receive and store PostgreSQL Write-Ahead Log (WAL) data

SYNOPSIS

pg_recvlogical [-D datadir] [-E method] [-H host] [-p port] [-P pathprefix] [-U username] [-w | -W] [-d dbname] [-l logfile] [-S primary_slotname] [connstr]

DESCRIPTION

pg_recvlogical is a utility to receive and store PostgreSQL WAL data from a standby server or a logical decoding client. It can be used to stream WAL from a primary server to one or more standby servers or logical decoding clients.

It connects to the server using the PostgreSQL Wire Protocol and receives WAL records from a specific WAL stream. The received WAL data is stored in files on the local disk in the directory specified by the -D option.

pg_recvlogical supports the following connection options:

  • -D datadir: Specifies the data directory of the standby server or logical decoding client. This is where the received WAL files will be stored.
  • -E method: Specifies the output method for the received WAL data. Possible values are stream (default) and fetch. stream uses the streaming replication protocol, while fetch uses the pg_receivewal() function.
  • -H host: Specifies the hostname of the server to connect to.
  • -p port: Specifies the TCP port of the server to connect to.
  • -P pathprefix: Specifies the path prefix for the WAL files.
  • -U username: Specifies the username to connect to the server.
  • -w: Never prompt for a password. If the server requires password authentication, the connection attempt will fail if the password cannot be supplied automatically.
  • -W: Force pg_recvlogical to prompt for a password before connecting to a database.
  • -d dbname: Specifies the database name to connect to. This option is not required for replication connections.
  • -l logfile: Specifies the name of the WAL log file.
  • -S primary_slotname: Specifies the name of the WAL replication slot to use on the server. This is required for logical decoding.
  • connstr: Specifies connection parameters as a connection string.

If the server demands password authentication. However, pg_recvlogical will waste a connection attempt finding out that the server wants a password. In some cases it is worth typing -W to avoid the extra connection attempt.

OPTIONS

The following additional options are available:

-V
--version

Print the pg_recvlogical version and exit.

-?
--help

Show help about pg_recvlogical command line arguments, and exit.

EXIT STATUS

pg_recvlogical will exit with status 0 when terminated by the SIGINT or SIGTERM signal. (That is the normal way to end it. Hence it is not an error.) For fatal errors or other signals, the exit status will be nonzero.

ENVIRONMENT

This utility, like most other PostgreSQL utilities, uses the environment variables supported by libpq (see Section 32.15).

The environment variable PG_COLOR specifies whether to use color in diagnostic messages. Possible values are always, auto and never.

NOTES

pg_recvlogical will preserve group permissions on the received WAL files if group permissions are enabled on the source cluster.

EXAMPLES

See Section 47.1 for an example.
