podman-remote(1)

الحزمة: podman

التراخيص: Apache-2.0

podman-remote(1) دليل الأوامر العامة podman-remote(1)

الاسم

podman-remote - واجهة سطر أوامر بعيدة لـ Podman: أداة إدارة بسيطة للحاويات (pods) والأجهزة (containers) والصور (images).

الملخص

podman-remote [خيارات] أمر

الوصف

Podman (مدير الحاويات) هو محرك حاويات كامل الميزات وهو أداة بسيطة لا تعتمد على خادم. يوفر Podman واجهة سطر أوامر مشابهة لواجهة Docker CLI، مما يسهل الانتقال من محركات الحاويات الأخرى ويتيح إدارة الحاويات (pods) والأجهزة (containers) والصور (images). ببساطة: alias docker=podman. يمكن تشغيل معظم أوامر Podman كمستخدم عادي، دون الحاجة إلى امتيازات إضافية.

يستخدم Podman أداة Buildah(1) داخليًا لإنشاء صور الحاويات. تشترك الأداتان في تخزين الصور (وليس الأجهزة)، وبالتالي يمكن لكل منهما استخدام أو التعامل مع الصور (ولكن ليس الأجهزة) التي أنشأتها الأخرى.

يوفر Podman-remote عميلًا محليًا يتفاعل مع عقدة Podman الخلفية من خلال واجهة برمجة تطبيقات RESTful يتم تمريرها عبر اتصال SSH. في هذا السياق، عقدة Podman هي نظام Linux مثبت عليه Podman وتم تنشيط خدمة API الخاصة به. يمكن تمرير بيانات الاعتماد لهذه الجلسة باستخدام الأعلام، أو متغيرات البيئة، أو في ملف containers.conf.

يتم وضع ملف containers.conf تحت $HOME/.config/containers/containers.conf على أنظمة Linux و Mac و %APPDATA%\containers\containers.conf على أنظمة Windows.

podman [خيارات عامة]

الخيارات العامة

--connection=الاسم, -c

اسم الاتصال البعيد

يتجاوز متغير البيئة CONTAINER_CONNECTION إذا تم تعيينه.

--help, -h

طباعة بيان الاستخدام

--identity=المسار

مسار ملف هوية SSH. إذا كان ملف الهوية مشفرًا، سيطلب Podman من المستخدم كلمة المرور. إذا لم يتم توفير ملف هوية ولم يتم تحديد مستخدم، فسيقوم Podman افتراضيًا بالمستخدم الذي يقوم بتشغيل أمر podman. سيطلب Podman كلمة مرور تسجيل الدخول على الخادم البعيد.

أسبقية حل قيمة الهوية:
- القيمة الموجودة في سطر الأوامر
- متغير البيئة CONTAINER_SSHKEY، إذا تم العثور على CONTAINER_HOST
- containers.conf

--log-level=المستوى

تسجيل الرسائل أعلى من المستوى المحدد: debug، info، warn، error (افتراضي)، fatal أو panic

--url=القيمة

عنوان URL للوصول إلى خدمة Podman (افتراضي من containers.conf، بالنسبة للمستخدم العادي "unix:///run/user/$UID/podman/podman.sock" أو بصلاحيات الجذر "unix:///run/podman/podman.sock").

  • CONTAINER_HOST بصيغة <schema>://[<user[:<password>]@]<host>[:<port>][<path>]
  • CONTAINER_PROXY بصيغة <socks5|socks5h>://[<user[:<password>]@]<host>[:<port>]

التفاصيل:
- schema هو أحد الخيارات التالية:
* ssh (افتراضي): مقبس Unix(7) محلي على host و port المحددين، يمكن الوصول إليه عبر SSH
* tcp: اتصال TCP غير مشفر وغير مصادق عليه إلى host و port المحددين، يمكن أن يعمل مع وكيل إذا تم تعيين CONTAINER_PROXY
* unix: مقبس Unix(7) محلي في path المحدد، أو الافتراضي للمستخدم
- user افتراضيًا إما root أو المستخدم الحالي قيد التشغيل (ssh فقط)
- password لا يوجد قيمة افتراضية (ssh فقط)
- يجب توفير host وهو إما عنوان IP أو اسم الجهاز الذي يستضيف خدمة Podman (ssh و tcp)
- port افتراضيًا هو 22 (ssh و tcp)
- path افتراضيًا إما /run/podman/podman.sock، أو /run/user/$UID/podman/podman.sock إذا كنت تعمل كمستخدم عادي (unix)، أو يجب تحديده صراحةً (ssh)
- CONTAINER_PROXY: استخدام وكيل (socks5 أو socks5h) للوصول إلى خدمة Podman (tcp فقط)

أسبقية حل قيمة URL:
- القيمة الموجودة في سطر الأوامر
- متغير البيئة CONTAINER_HOST
- جدول engine.service_destinations في containers.conf، باستثناء دليل /usr/share/containers
- unix:///run/podman/podman.sock

تستخدم الاتصالات البعيدة ملف containers.conf المحلي للقيم الافتراضية.

بعض أمثلة قيم URL بصيغ صالحة:
- unix:///run/podman/podman.sock
- unix:///run/user/$UID/podman/podman.sock
- ssh://notroot@localhost:22/run/user/$UID/podman/podman.sock
- ssh://root@localhost:22/run/podman/podman.sock
- tcp://localhost:34451
- tcp://127.0.0.1:34451

--version

طباعة الإصدار

متغيرات البيئة

يمكن لـ Podman إعداد متغيرات البيئة من جدول env في [engine] في containers.conf. يمكن تجاوز هذه المتغيرات عن طريق تمرير متغيرات البيئة قبل أوامر podman.

CONTAINERS_CONF

تعيين المواقع الافتراضية لملف containers.conf

CONTAINER_CONNECTION

تعيين القيمة الافتراضية لـ --connection للوصول إلى خدمة Podman.

CONTAINER_HOST

تعيين القيمة الافتراضية لـ --url للوصول إلى خدمة Podman.

CONTAINER_SSHKEY

تعيين المسار الافتراضي لـ --identity لملف مفتاح SSH المستخدم للوصول إلى خدمة Podman.

حالة الخروج

رمز الخروج من podman يوفر معلومات حول سبب فشل تشغيل الحاوية أو لماذا خرجت. عندما تخرج أوامر podman برمز غير صفري، تتبع رموز الخروج معيار chroot، انظر أدناه:

125 الخطأ يتعلق بـ podman نفسه

$ podman run --foo busybox; echo $?
Error: unknown flag: --foo
125

126 تنفيذ أمر محتوى و الأمر لا يمكن استدعاؤه

$ podman run busybox /etc; echo $?
Error: container_linux.go:346: starting container process caused "exec: \"/etc\": permission denied": OCI runtime error
126

127 تنفيذ أمر محتوى و الأمر لا يمكن العثور عليه
$ podman run busybox foo; echo $?
Error: container_linux.go:346: starting container process caused "exec: \"foo\": executable file not found in $PATH": OCI runtime error
127

رمز الخروج رمز خروج الأمر المحتوى

$ podman run busybox /bin/sh -c 'exit 3'; echo $?
3
