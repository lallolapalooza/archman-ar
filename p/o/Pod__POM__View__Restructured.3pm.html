الحزمة: perl-pod-pom-view-restructured

التراخيص: GPL-1.0-or-later, Artistic-2.0

Pod::POM::View::Restructured(3) توثيق Perl من مساهمات المستخدم Pod::POM::View::Restructured(3)

الاسم

Pod::POM::View::Restructured - عرض لـ Pod::POM يخرج نصًا معادًا تركيبه

الملخص

use Pod::POM::View::Restructured;

my $view = Pod::POM::View::Restructured->new;
my $parser = Pod::POM->new;
my $pom = $parser->parse_file("$top_dir/lib/Pod/POM/View/Restructured.pm");
my $out = $pom->present($view);

الوصف

تخرج هذه الوحدة نصًا معاد التركيب يُتوقع استخدامه مع Sphinx. الأقسام الحرفية (الفقرات ذات المسافة البادئة) في POD سيتم إخراجها مع تمييز بناء الجملة لكود Perl افتراضيًا. انظر "أوامر POD الخاصة بالنص المعاد تركيبه" لمعرفة كيفية تغيير ذلك لكتلة معينة.

يمكن تنزيل هذه الوحدة من https://metacpan.org/release/Pod-POM-View-Restructured.

الأساليب

new(\%params)

المنشئ. \%params اختياري. إذا كان موجودًا، فإن المفاتيح التالية صالحة:

"callbacks"
راجع التوثيق أدناه لـ convert_file().
"namespace"
إذا تم تعريف مساحة أسماء، يتم تحويل الروابط إلى تلك المساحة إلى إشارات مرجعية ويتم إضافة مرساة لكل وسم عنوان.

"convert_file($source_file, $title, $dest_file, $callbacks)"

يحول POD في $source_file إلى نص معاد التركيب. إذا تم تعريف $dest_file، فسيتم كتابة الإخراج هناك. إذا تم تعريف $title، فسيتم استخدامه لعنوان المستند. بخلاف ذلك، يتم محاولة استنتاج العنوان من قسم الاسم (يتحقق مما إذا كان الجسم يبدو مثل "/\A\s*(\w+(?:::\w+)+)\s+-\s+/s").

يُرجع الإخراج كسلسلة نصية.

$source_file و $dest_file يمكن أن يكونا أسماء ملفات أو مقابض ملفات.

"convert_files($file_spec, $index_file, $index_title, $out_dir)"

يحول الملفات المعطاة في $file_spec إلى نص معاد التركيب. إذا تم توفير $index_file، فهو المسار إلى ملف الفهرس الذي سيتم إنشاؤه (مع جدول محتويات يشير إلى جميع الملفات التي تم إنشاؤها). إذا تم توفير $index_title، فسيتم استخدامه كعنوان قسم لملف الفهرس. $out_dir هو الدليل الذي سيتم كتابة الملفات المولدة فيه.

$file_spec هو مرجع إلى مصفوفة من الهاشات تحدد السمات لكل ملف سيتم تحويله. المفاتيح الصالحة هي:

"source_file"
الملف المراد تحويله.
"dest_file"
الملف لإخراج النص المعاد تركيبه. إذا لم يتم توفيره، فسيتم إنشاء اسم ملف بناءً على العنوان.
"title"
عنوان القسم للنص المعاد تركيبه المولّد. إذا لم يتم توفيره، فسيتم محاولة استنتاج العنوان من قسم الاسم في POD، إذا كان موجودًا. كحل أخير، سيتم إنشاء عنوان يبدو مثل "section_(\d+)".
"callbacks"
مرجع إلى هاش يحتوي على الأسماء والاستدعاءات المقابلة.

حالياً، الاستدعاء الصالح الوحيد هو "link". يُعطى النص الموجود داخل قسم L<> من POD، ويتوقع أن يُرجع زوجًا "($url, $label)". إذا كانت القيمة المُرجعة لـ $label غير معرفة، فإن قيمة $url تُستخدم كتسمية.

"no_toc"
يتسبب في عدم طباعة العنصر في الفهرس أو إرجاعه في حقل "toc".

تُرجع هذه الطريقة مرجع هاش يحتوي على جدول محتويات (حقل "toc") مناسب لجدول محتويات نص معاد تركيبه.

مثال:

my $conv = Pod::POM::View::Restructured->new;

my $files = [
              { source_file => "$base_dir/Restructured.pm" },
              { source_file => "$base_dir/DWIW.pm" },
              { source_file => "$base_dir/Wrapper.pm" },
             ];

my $rv = $conv->convert_files($files, "$dest_dir/index.rst", 'My Big Test', $dest_dir);

أوامر POD الخاصة بالنص المعاد تركيبه

يمكن استخدام التسلسلات التالية في POD لطلب إجراءات خاصة بهذه الوحدة.

=for pod2rst next-code-block: lang

يقوم هذا بإعداد القسم الحرفي التالي، أي، الفقرة التالية ذات المسافة البادئة، ليتم تمييزها وفقًا لبناء جملة لغة البرمجة/التوصيف/التكوين lang. يُفترض أن تكون الأقسام الحرفية كود Perl افتراضيًا. يستخدم Sphinx Pygments لتمييز بناء الجملة في هذه الأقسام، لذا يمكنك استخدام أي قيمة لـ lang يدعمها Pygments، مثل Python، C، C++، Javascript، SQL، إلخ.

أمثلة

تحويل ملف واحد باستخدام "pod2rst"
pod2rst --infile=Restructured.pm --outfile=restructured.rst

بحاجة إلى توثيق:

توثيق مثال لإعداد بناء Sphinx، وتوليد rst من pod، والبناء

قيد الإنجاز

تمييز بناء الجملة للكود
حاليًا، يتم إخراج كتلة حرفية (فقرة ذات مسافة بادئة) ككتلة كود Perl افتراضيًا في النص المعاد تركيبه. يجب أن يكون هناك خيار (على سبيل المثال، في المنشئ) لتغيير اللغة لأغراض التمييز (لجميع الكتل الحرفية)، أو تعطيل تمييز بناء الجملة وجعلها مجرد فقرة منسقة مسبقًا. هناك طريقة للقيام بذلك في POD (انظر "أوامر POD الخاصة بالنص المعاد تركيبه")، ولكن يجب أن يكون هناك أيضًا خيار في المنشئ.
تحسين الهروب
لا يتم هروب كتل النص بشكل صحيح، لذا من الممكن حاليًا استدعاء أمر في النص المعاد تركيبه عن طريق الخطأ.

Pod::POM::View::Restructured (perl): RestructuredText view for Pod::POM

NAME

Pod::POM::View::Restructured - RestructuredText view for Pod::POM

SYNOPSIS

  use Pod::POM::View::Restructured;
  my $view = Pod::POM::View::Restructured->new;
  print $view->render($pom);

DESCRIPTION

This is a view for Pod::POM that renders the pod document as reStructuredText. It is not an reStructuredText parser, but a view for the POD object model.

It can be used to convert POD to reStructuredText, but the main use is to get a clean and semantic reStructuredText representation of the document.

METHODS

This class provides the following methods:

new
Creates a new view object. May be used to pass options to the view. Currently, no options are supported.
render
Takes a Pod::POM object and returns the reStructuredText representation of the document.

POD commands specifically for reStructuredText

This module understands the following POD commands:

X{code}
Renders as a literal code block in reStructuredText. This is a non-standard POD command, and only understood by this module.
X{rest}
Renders as a raw reStructuredText block. This is a non-standard POD command, and only understood by this module.

EXAMPLES

This is a simple example of how to convert a POD document to reStructuredText:

  use Pod::POM;
  use Pod::POM::View::Restructured;

  my $pom = Pod::POM->new;
  $pom->parse_file('MyModule.pm');

  my $view = Pod::POM::View::Restructured->new;
  my $rst = $view->render($pom);

  print $rst;
