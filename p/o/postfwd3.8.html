الوصف

مقدمة

تمت كتابة postfwd3 لدمج قيود Postfix المعقدة في مجموعة قواعد مماثلة لتلك الموجودة في معظم جدران الحماية. يستخدم البرنامج بروتوكول تفويض سياسة Postfix للتحكم في الوصول إلى نظام البريد قبل قبول الرسالة (يرجى زيارة http://www.postfix.org/SMTPD_POLICY_README.html لمزيد من المعلومات).

يسمح لك postfwd3 باختيار إجراء (مثل رفض، لا أعرف) لمجموعة من معلمات SMTP المختلفة (مثل عنوان المرسل والمستلم، الحجم، أو بصمة TLS للعميل). كما يوفر وحدات ماكرو/ACL بسيطة يجب أن تسمح بإعدادات واضحة وسهلة القراءة.

الميزات:

* مجموعات معقدة من معلمات SMTP

* عمليات بحث مدمجة لـ RBL/RHSBL مع إجراءات اعتباطية اعتمادًا على النتائج

* نظام تسجيل النقاط

* قواعد تعتمد على التاريخ والوقت

* وحدات ماكرو/ACL، مجموعات ديناميكية، نفي

* مقارنة سمات الطلب (مثل client_name و helo_name)

* ذاكرة تخزين مؤقت داخلية للطلبات واستعلامات DNS

* إحصائيات مدمجة لتحليل كفاءة القواعد

الإعدادات

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

pre>rblcount - يحتوي على عدد إجابات RBL rhsblcount - يحتوي على عدد إجابات RHSBL matches - يحتوي على عدد العناصر المطابقة dnsbltext - يحتوي على جزء TXT الخاص بـ DNS لجميع ردود RBL و RHSBL بالشكل rbltype:rblname:<txt>; rbltype:rblname:<txt>; ...

سيتم تغيير هذه العناصر الخاصة لأي قاعدة مطابقة:

request_hits    - يحتوي على معرفات جميع القواعد المطابقة

هذا يعني أنه قد يكون من الضروري حفظها، إذا كنت تخطط لاستخدام هذه القيم في القواعد اللاحقة:

# تعيين القيم
id=RBL01 ; rhsblcount=all; rblcount=all
        action=set(HIT_rhls=$$rhsblcount,HIT_rbls=$$rblcount,HIT_txt=$$dnsbltext)
        rbl=list.dsbl.org, bl.spamcop.net, dnsbl.sorbs.net, zen.spamhaus.org
        rhsbl_client=rddn.dnsbl.net.au, rhsbl.ahbl.org, rhsbl.sorbs.net
        rhsbl_sender=rddn.dnsbl.net.au, rhsbl.ahbl.org, rhsbl.sorbs.net
# مقارنة
id=RBL02 ; HIT_rhls>=1 ; HIT_rbls>=1 ; action=554 5.7.1 blocked using $$HIT_rhls RHSBLs and $$HIT_rbls RBLs [INFO: $$HIT_txt]
id=RBL03 ; HIT_rhls>=2               ; action=554 5.7.1 blocked using $$HIT_rhls RHSBLs [INFO: $$HIT_txt]
id=RBL04 ; HIT_rbls>=2               ; action=554 5.7.1 blocked using $$HIT_rbls RBLs [INFO: $$HIT_txt]

الملفات

منذ postfwd1 v1.15 و postfwd3 v0.18، يمكن تخزين قوائم العناصر الطويلة في ملفات منفصلة:

id=R001 ;  ccert_fingerprint==file:/etc/postfwd/wl_ccerts ;  action=DUNNO

سيقرأ postfwd3 قائمة بالعناصر (عنصر واحد لكل سطر) من /etc/postfwd/wl_ccerts. التعليقات مسموحة:

# client1
11:22:33:44:55:66:77:88:99
# client2
22:33:44:55:66:77:88:99:00
# client3
33:44:55:66:77:88:99:00:11

لاستخدام الجداول الموجودة بتنسيق key=value، يمكنك استخدام:

id=R001 ;  ccert_fingerprint==table:/etc/postfwd/wl_ccerts ;  action=DUNNO

سيتجاهل هذا القيمة الموجودة على الجانب الأيمن. يمكن خلط العناصر:

id=R002 ;  action=REJECT
        client_name==unknown
        client_name==file:/etc/postfwd/blacklisted

وللعناصر غير PCRE (مفصولة بفواصل):

id=R003 ;  action=REJECT
        client_address==10.1.1.1, file:/etc/postfwd/blacklisted
id=R004 ;  action=REJECT
        rbl=myrbl.home.local, zen.spamhaus.org, file:/etc/postfwd/rbls_changing

يمكنك التحقق من تكوينك باستخدام الخيار --show_config في سطر الأوامر:

# postfwd3 --showconfig --rule='action=DUNNO; client_address=10.1.0.0/16, file:/etc/postfwd/wl_clients, 192.168.2.1'

يجب أن يعطي شيئًا مثل:

Rule   0: id->"R-0"; action->"DUNNO"; client_address->"=;10.1.0.0/16, =;194.123.86.10, =;186.4.6.12, =;192.168.2.1"

إذا تعذر قراءة ملف، فسيتم تجاهله:

# postfwd3 --showconfig --rule='action=DUNNO; client_address=10.1.0.0/16, file:/etc/postfwd/wl_clients, 192.168.2.1'
[LOG warning]: error: file /etc/postfwd/wl_clients not found - file will be ignored ?
Rule   0: id->"R-0"; action->"DUNNO"; client_address->"=;10.1.0.0/16, =;192.168.2.1"

يتم تقييم عناصر الملف في مرحلة التكوين. لذلك، يحتاج postfwd3 إلى إعادة تحميله إذا تغير ملف.

إذا كنت ترغب في تحديد ملف سيتم إعادة تحميله لكل طلب، يمكنك استخدام lfile: و ltable:

id=R001; client_address=lfile:/etc/postfwd/client_whitelist; action=dunno

سيتحقق هذا من وقت تعديل /etc/postfwd/client_whitelist في كل مرة يتم فيها تقييم القاعدة وإعادة تحميلها حسب الضرورة. بالطبع، قد يؤدي هذا إلى زيادة الحمل على النظام، لذا يرجى استخدامه بحذر.

يوضح الخيار --showconfig الفرق:

## تم التقييم في مرحلة التكوين
# postfwd3 --nodaemon -L --rule='client_address=table:/etc/postfwd/clients; action=dunno' -C
Rule   0: id->"R-0"; action->"dunno"; client_address->"=;1.1.1.1, =;1.1.1.2, =;1.1.1.3"
## تم التقييم لأي مطابقة قاعدة
# postfwd3 --nodaemon -L --rule='client_address=ltable:/etc/postfwd/clients; action=dunno' -C
Rule   0: id->"R-0"; action->"dunno"; client_address->"=;ltable:/etc/postfwd/clients"

يمكن للملفات الإشارة إلى ملفات أخرى. ما يلي صالح.

-- FILE /etc/postfwd/rules.cf --
id=R01; client_address=file:/etc/postfwd/clients_master.cf; action=DUNNO
-- FILE /etc/postfwd/clients_master.cf --
192.168.1.0/24
file:/etc/postfwd/clients_east.cf
file:/etc/postfwd/clients_west.cf
-- FILE /etc/postfwd/clients_east.cf --
192.168.2.0/24
-- FILE /etc/postfwd/clients_west.cf --
192.168.3.0/24

لاحظ أنه لا يوجد حاليًا اكتشاف للحلقات (/a/file يستدعي /a/file) وأن هذه الميزة متاحة فقط مع postfwd1 v1.15 و postfwd3 v0.18 والإصدارات الأعلى.

الإجراءات

عام

سيتم تنفيذ الإجراءات عندما تتطابق جميع عناصر القاعدة مع طلب (أو عنصر واحد على الأقل من أي قائمة عناصر). يمكنك الإشارة إلى سمات الطلب عن طريق وضع $$ قبلها، مثل:

id=R-003; client_name = !!$$helo_name; action=WARN helo '$$helo_name' does not match DNS '$$client_name'
# أو
id=R-003; client_name = !!$$helo_name; action=WARN helo '$$(helo_name)' does not match DNS '$$(client_name)'

إجراءات postfix

سيتم الرد على الإجراءات من قبل postfix كنتيجة لطلبات تفويض السياسة. أي إجراء يفهمه postfix مسموح به - انظر "man 5 access" أو http://www.postfix.org/access.5.html لوصف. إذا لم يتم تحديد إجراء، فسيتم استخدام إجراء WARN الخاص بـ postfix الذي يقوم ببساطة بتسجيل الحدث للقاعدة المقابلة.

سيعيد postfwd3 dunno إذا وصل إلى نهاية مجموعة القواعد ولم تتطابق أي قاعدة. يمكن تغيير ذلك عن طريق وضع قاعدة أخيرة تحتوي فقط على بيان إجراء:

...
action=dunno ; sender=@domain.local     # المرسل مقبول
action=reject                           # رفض افتراضي

إجراءات postfwd3

تتحكم إجراءات postfwd3 في سلوك البرنامج. حاليًا، يمكنك تحديد ما يلي:

jump (<id>)
يقفز إلى القاعدة ذات المعرف <id>، استخدم هذا لتخطي قواعد معينة.
يمكنك القفز للخلف - ولكن تذكر أنه لا يوجد اكتشاف للحلقات
في الوقت الحالي! سيتم تخطي القفزات إلى معرفات غير موجودة.
score (<score>)
سيتم تعديل درجة الطلب بواسطة <score> المحدد،
والتي يجب أن تكون قيمة نقطة عائمة. يمكن أن يكون المعدل إما
        +n.nn   يضيف n.nn إلى النتيجة الحالية
        -n.nn   يطرح n.nn من النتيجة الحالية
        *n.nn   يضرب النتيجة الحالية بـ n.nn
        /n.nn   يقسم النتيجة الحالية على n.nn

وحدات الماكرو / قوائم الوصول (MACROS/ACLS)

يمكن اختصار الاستخدام المتعدد للعناصر الطويلة أو مجموعاتها بواسطة وحدات الماكرو. يجب أن تسبق هذه بـ '&&' (حرفان '&'). أولاً، يجب تعريف وحدات الماكرو على النحو التالي:

&&RBLS { rbl=zen.spamhaus.org,list.dsbl.org,bl.spamcop.net,dnsbl.sorbs.net,ix.dnsbl.manitu.net; };

ثم يمكن استخدام هذه في قواعدك، مثل:

&&RBLS ;  client_name=^unknown$                         ; action=REJECT
&&RBLS ;  client_name=(\d+[\.-_]){4}                    ; action=REJECT
&&RBLS ;  client_name=[\.-_](adsl|dynamic|ppp|)[\.-_]   ; action=REJECT

يمكن أن تحتوي وحدات الماكرو على إجراءات أيضًا:

# تعريف
&&GONOW { action=REJECT your request caused our spam detection policy to reject this message. More info at http://www.domain.local; };
# قواعد
&&GONOW ;  &&RBLS ;  client_name=^unknown$
&&GONOW ;  &&RBLS ;  client_name=(\d+[\.-_]){4}
&&GONOW ;  &&RBLS ;  client_name=[\.-_](adsl|dynamic|ppp|)[\.-_]

يمكن أن تحتوي وحدات الماكرو على وحدات ماكرو أخرى أيضًا:

# تعريف
&&RBLS{
        rbl=zen.spamhaus.org
        rbl=list.dsbl.org
        rbl=bl.spamcop.net
        rbl=dnsbl.sorbs.net
        rbl=ix.dnsbl.manitu.net
};
&&DYNAMIC{
        client_name=^unknown$
        client_name=(\d+[\.-_]){4}
        client_name=[\.-_](adsl|dynamic|ppp|)[\.-_]
};
&&GOAWAY { &&RBLS; &&DYNAMIC; };
# قواعد
&&GOAWAY ; action=REJECT dynamic client and listed on RBL

بشكل أساسي، وحدات الماكرو هي استبدالات نصية بسيطة - انظر قسم "PARSER" لمزيد من المعلومات.

المجموعات الديناميكية (DYNAMIC GROUPS)

المجموعات الديناميكية هي كائنات قائمة. يمكنك إضافة أو إزالة عناصر ومقارنة عناصر الطلب بمحتواها ضمن مجموعة القواعد الخاصة بك. يتم حفظ المجموعات بشكل دائم للطلبات اللاحقة. بهذه الطريقة يمكنك حفظ المعلومات للاستخدام لاحقًا. كل عنصر في المجموعة لديه قيمة فترة صلاحية (time-to-live).

يجب أن تسبق أسماء المجموعات بحرفي '%'-، مثل %%GROUPNAME:

# إضافة client_address إلى المجموعة %%BLACKLISTED، إذا تم الإرسال إلى spamtrap
id=SPAMTRAP; recipient==spamtrap@domain.local; action=groupadd(%%BLACKLISTED/client_address)
# رفض أي طلب من client_address في المجموعة %%BLACKLISTED
id=BLACKLISTED; client_address=%%BLACKLISTED; action=REJECT

تتلقى الدالة groupadd() الوسائط التالية. قيمة <ttl> اختيارية. إذا لم يتم تحديدها، سيستخدم postfwd3 القيمة الافتراضية --default_group_ttl [300s]:

groupadd ( <Groupname> / <item> [ / <ttl> ] )

سيقوم postfwd بحفظ هذه البيانات في الهيكل التالي:

%Group_Cache -> %<Groupname> -> $<item> = <ttl>

تقوم الدالة groupdel() بإزالة عنصر من مجموعة:

groupdel ( <Groupname> / <item> )

سيتم إزالة الأعضاء المنتهية صلاحيتها عند مرحلة التنظيف بعد --cleanup_groups <i> ثانية.

لمقارنة الطلبات بالمجموعات الديناميكية، يجب الإشارة إليها عن طريق إضافة حرفي '%%' مسبقين:

<item> = %%<Groupname>

المجموعات الفارغة تقارن دائمًا بشكل خاطئ. يمكن أن تكون مجموعة القواعد التالية ممكنة:

# السماح بأي طلب من client_address في المجموعة %%WHITELISTED
id=WHITEGROUP; client_address=%%WHITELISTED; action=DUNNO
# رفض أي طلب من client_address في المجموعة %%BLACKLISTED
id=BLACKGROUP; client_address=%%BLACKLISTED; action=REJECT
# ... قواعد أخرى ...
# ... ملف القائمة البيضاء ...
id=W_TRUST; action=set(WHITE=1)
    client_address=file:/etc/postfwd/whitelist_networks
# ... DNS القائمة البيضاء ...
id=W_DNSWL; action=set(WHITE=1)
    rbl=list.dnswl.org
# ... -> إضافته إلى القائمة البيضاء ليوم واحد والسماح بالطلب
id=W_GROUP; WHITE==1
    action=groupadd(%%WHITELISTED/client_address/86400)
    action=DUNNO
# ... أو حظره عن طريق الإرسال إلى spamtrap ...
id=B_SPAMTRAP; action=set(BLACK=1)
    recipient==spamtrap@domain.local
# ... أو تم حظره عن طريق DNS ...
id=B_DNSBL; action=set(BLACK=1)
    rbl=zen.spamhaus.org
# ... -> إضافته إلى المجموعة BLACKLISTED لمدة ساعة ورفضه
id=B_GROUP; BLACK==1
    action=groupadd(%%BLACKLISTED/client_address/3600)
    action=REJECT

القيود

حاليًا، يتم الاحتفاظ بالمجموعات الديناميكية في الذاكرة. افتراضيًا، سيقبل postfwd3 بحد أقصى 999999 عضوًا في المجموعة. لإلغاء تفعيل هذا الحد، قم بتعيين --group_maxitems إلى '-1'.

مع شخصية PreFork، يجب أن تكون على علم بأن هذه المعلومات يجب مشاركتها من خلال خادم التخزين المؤقت.

باختصار: لا تدع هذه القوائم تصبح كبيرة جدًا إلا إذا كان لديك سعة نظام كافية للقيام بذلك. إذا لزم الأمر، اضبط إعداداتك عن طريق تعيين <ttl> و --group_maxitems.

الإضافات (PLUGINS)

الوصف

تسمح واجهة الإضافات بتعريف عمليات التحقق الخاصة بك وتعزيز وظائف postfwd. لا تتردد في مشاركة الأشياء المفيدة!

تحذير

لاحظ أن واجهة الإضافات لا تزال في مرحلة التطوير. يرجى اختبار الإضافات الخاصة بك بعناية، لأن الأخطاء قد تتسبب في تعطل postfwd! يُسمح أيضًا بتجاوز السمات أو الوظائف المدمجة، ولكن تأكد من أنك تعرف ما تفعله لأن بعضها يستخدم داخليًا.

يرجى وضع الأمان في الاعتبار عند الوصول إلى موارد حساسة ولا تقم مطلقًا بتشغيل postfwd كمستخدم لديه صلاحيات! لا تثق أبدًا بمدخلاتك (خاصة أسماء المضيف وعناوين البريد الإلكتروني).

العناصر (ITEMS)

عناصر الإضافات هي روتينات Perl تدمج سمات إضافية في الطلبات قبل تقييمها مقابل مجموعة قواعد postfwd مثل أي عنصر آخر في بروتوكول تفويض السياسة. هذا يسمح لك بإنشاء عمليات التحقق الخاصة بك.

لا يمكن استخدام عناصر الإضافات بشكل انتقائي. سيتم تنفيذ هذه الوظائف لكل طلب يتلقاه postfwd، لذا ضع الأداء في الاعتبار.

SYNOPSIS: postfwd_items_plugin{<name>}($request)

يعني أن الروتين الفرعي الخاص بك، المسمى <name>، لديه إمكانية الوصول إلى مرجع تجزئة يسمى $request، والذي يحتوي على جميع سمات الطلب، مثل $request->{client_name} ويحفظ القيم بالشكل التالي:

save: $result->{<item>} = <value>

يقوم هذا بإنشاء العنصر الجديد <item> الذي يحتوي على <value>، والذي سيتم دمجه في طلب تفويض السياسة وبالتالي يمكن استخدامه في مجموعة قواعد postfwd.

# لا تقم بإزالة السطر التالي
%postfwd_items_plugin = (
        # أمثلة - مدمجة في postfwd. لا حاجة لتنشيطها هنا.

                # يسمح بالتحقق من إصدار postfwd في مجموعة القواعد
                "version" => sub {
                        my($request) = shift;
                        $request->{version} => $NAME." ".$VERSION,
                },

                # sender_domain و recipient_domain
                "address_parts" => sub {
                        my($request) = shift;
                        $request->{sender} =~ /@([^@]*)$/;
                        $request->{sender_domain} = ($1 || '');
                        $request->{recipient} =~ /@([^@]*)$/;
                        $request->{recipient_domain} = ($1 || '');
                },
# لا تقم بإزالة السطر التالي
);

المقارنة (COMPARE)

تسمح إضافات المقارنة بتعريف كيفية مقارنة عناصرك الجديدة بمجموعة القواعد. هذه اختيارية. إذا لم تحدد واحدة، فسيتم استخدام الإعداد الافتراضي (== للمطابقة التامة، =~ لـ PCRE، ...).

SYNOPSIS:  <item> => sub { return &{$postfwd_compare{<type>}}(@_); },
# لا تقم بإزالة السطر التالي
%postfwd_compare_plugin = (
        أمثلة - مدمجة في postfwd. لا حاجة لتنشيطها هنا.

                # مثال بسيط
                # SYNOPSIS:  <result> = <item> (return &{$postfwd_compare{<type>}}(@_))
                "client_address"  => sub { return &{$postfwd_compare{cidr}}(@_); },
                "size"            => sub { return &{$postfwd_compare{numeric}}(@_); },
                "recipient_count" => sub { return &{$postfwd_compare{numeric}}(@_); },

                # مثال معقد
                # SYNOPSIS:  <result> = <item>(<operator>, <ruleset value>, <request value>, <request>)
                "numeric" => sub {
                        my($cmp,$val,$myitem,$request) = @_;
                        my($myresult) = undef;  $myitem ||= "0"; $val ||= "0";
                        if ($cmp eq '==') {
                                $myresult = ($myitem == $val);
                        } elsif ($cmp eq '=<') {
                                $myresult = ($myitem <= $val);
                        } elsif ($cmp eq '=>') {
                                $myresult = ($myitem >= $val);
                        } elsif ($cmp eq '<') {
                                $myresult = ($myitem < $val);
                        } elsif ($cmp eq '>') {
                                $myresult = ($myitem > $val);
                        } elsif ($cmp eq '!=') {
                                $myresult = not($myitem == $val);
                        } elsif ($cmp eq '!<') {
                                $myresult = not($myitem <= $val);
                        } elsif ($cmp eq '!>') {
                                $myresult = not($myitem >= $val);
                        } else {
                                $myresult = ($myitem >= $val);
                        };
                        return $myresult;
                },
# لا تقم بإزالة السطر التالي
);

الإجراءات (ACTIONS)

تسمح إضافات الإجراءات بتعريف إجراءات postfwd جديدة. عن طريق تعيين العلامة $stop، يمكنك تحديد ما إذا كنت تريد الاستمرار في تحليل مجموعة القواعد أو إيقافه.

SYNOPSIS:  (<stop rule parsing>, <next rule index>, <return action>, <logprefix>) =
                <action> (<current rule index>, <current time>, <command name>, <argument>, <logprefix>, <request>)
# لا تقم بإزالة السطر التالي
%postfwd_actions_plugin = (
        # أمثلة - مدمجة في postfwd. لا حاجة لتنشيطها هنا.

                # أمر note(<logstring>)
                "note"  => sub {
                        my($index,$now,$mycmd,$myarg,$myline,$request
) = @_;
                        my($myaction) = 'dunno'; my($stop) = 0;
                        log_info " [RULES] ".$myline." - note: ".$myarg if $myarg;
                        return ($stop,$index,$myaction,$myline);
                },

                # skips next  rules
                "skip" => sub {
                        my($index,$now,$mycmd,$myarg,$myline,$request) = @_;
                        my($myaction) = 'dunno'; my($stop) = 0;
                        $index += $myarg if ( $myarg and not(($index + $myarg) > $#Rules) );
                        return ($stop,$index,$myaction,$myline);

                # dumps current request contents to syslog
                "dumprequest" => sub {
                        my($index,$now,$mycmd,$myarg,$myline,$request) = @_;
                        my($myaction) = 'dunno'; my($stop) = 0;
                        map { log_info "[DUMP] rule=$index, Attribute: $_=$request{$_}" } (keys %{$request});
                        return ($stop,$index,$myaction,$myline);
                },
# do NOT remove the next line
);

NAME

postfwd3 - Postfix Mail Filter Daemon

SYNOPSIS

postfwd3 [-P|--perfmon] [-v|--verbose] [-D|--defaults] [-c config_dir] [-f config_file] [-r rule]–f config_file–r rule

postfwd3 [-C|--showconfig] [-v|--verbose] [-f config_file] [-r rule]–f config_file–r rule

postfwd3 [-V|--version]

postfwd3 [-h|--help]

postfwd3 [-m|--manual]

postfwd3 [--dumpstats]

postfwd3 [--dumpcache]

postfwd3 [--delcache item]

postfwd3 [--delrate item]

DESCRIPTION

The postfwd3 daemon processes incoming SMTP requests and accepts or rejects them based on a set of rules. postfwd3 can be used to implement custom spam-filtering, whitelisting, blacklisting, RBL checks, rate limiting, greylisting, size checks and more.

The daemon is started typically from a script in /etc/init.d/. The ruleset can be specified on the command line or be read from a configuration file.

postfwd3 reads its ruleset in the order defined. The first rule that matches will be executed. A rule consists of one or more conditions and one action. Conditions are combined with AND logic.

In daemon mode postfwd3 reloads it's ruleset after receiving a HUP signal. See also the description of the '-I' switch to have your configuration refreshed for every request postfwd3 receives.

Items can be checked for equality, inequality, comparison, regular expression matches or inclusion in a list. You can use the following operators:

=       equal
!=      not equal
<       less than
<=      less than or equal
>       greater than
>=      greater than or equal
~=      regular expression match (Perl compatible)
!~      not regular expression match
in      member of list
not in  not member of list

Items can be combined in lists, separated by commas. Example:

client_address=192.168.1.10,192.168.1.11

Regular expressions must be valid Perl regular expressions. Special characters need to be escaped with a backslash. Example:

client_name =~ /\.gmx\.(net|de)$/

If the value contains spaces or special characters, it must be quoted.

Lists can also be specified for RBL/RHSBL checks:

rbl=list1.dnsbl.org,list2.dnsbl.org

The RBL check will be performed for all lists.

The following items can be grouped and compared:

rblcount=2                     # hit in at least 2 RBLs
rblcount=2-4                   # hit in 2 to 4 RBLs
rblcount=all                   # hit in all specified RBLs
rhsblcount=all                 # hit in all specified RHSBLs

The following items can be used for rate limiting:

rate(key/max_count/timeout/action)
rate(key/max_count/timeout/action)
    key: defines the key for rate limiting (e.g. client_address, sender_address,
         client_name, recipient_address)
    max_count: maximum number of hits allowed within the timeout
    timeout: time in seconds
    action: action to take if max_count is exceeded (e.g. REJECT, TEMPFAIL,
            WARN, dunno, check_postgrey, jump(rule_id))

Example for rate limiting:

action=rate(client_address/30/3600/REJECT\ your\ connection\ is\ rate\ limited)

The following items can be used for size limiting:

size(key/max_size/timeout/action)
    key: defines the key for size limiting (e.g. client_address, sender_address)
    max_size: maximum size in bytes
    timeout: time in seconds
    action: action to take if max_size is exceeded

Example for size limiting:

action=size(client_address/1572864/600/REJECT\ your\ mail\ is\ too\ big)

The following actions are available:

DUNNO                     accept the mail
REJECT message        reject the mail with a 5xx error message
TEMPFAIL message      temporarily reject the mail with a 4xx error message
WARN message          log a warning message and accept the mail
score(value)          add value to the current score
jump(rule_id)         jump to another rule with the given ID
set(var=value,...)    set variables which can be checked later
check_postgrey          forward the request to postgrey

It is possible to group rules together using the group keyword. This can simplify configuration significantly.

group=MY_GROUP
    condition1=value1
    condition2=value2
    ...

Rules can then refer to the group:

id=RULE_USING_GROUP ; group=MY_GROUP ; action=DUNNO

The conditions specified in the group are implicitly added to the rule.

OPTIONS

DAEMON OPTIONS

-c config_dir
Directory containing the postfwd3 configuration files. Default is /etc/postfwd.
-f config_file
File containing the postfwd3 ruleset. Can be specified multiple times. Rules are read in the order of the arguments.
-r rule
Specify a single rule directly on the command line. Can be specified multiple times. Rules are processed in the order of the arguments.
-I, --reload_config
Reloads the ruleset on HUP signal. Default is to reload rules on SIGHUP.
-i, --no_reload_config
Does not reload the ruleset on SIGHUP.
--keep_groups
With this option postfwd reloads groups from cache on reload. Please note that you have to restart (not reload) postfwd with this option if any group based rules are changed.
--save_groups file
(default=none) With this option postfwd saves existing groups to disk and reloads them on program start. This allows persistent rate limits across program restarts or reboots. Please note that postfwd needs read and write access to the specified file.
--keep_rates
(default=0) With this option postfwd3 does not clear the rate limit counters on reload. Please note that you have to restart (not reload) postfwd with this option if any rate limit rules are changed.
--save_rates file
(default=none) With this option postfwd saves existing rate limit counters to disk and reloads them on program start. This allows persistent rate limits across program restarts or reboots. Please note that postfwd needs read and write access to the specified file.
-A, --aggregate_addrs, --noaggregate_addrs
Pre-computes ip address lists to subnets, so that e.g.: 
   client_address=10.0.0.0/24, 10.0.1.0/24, 10.0.2.0/24, 10.0.3.0/24
        will result in
   client_address=10.0.0.0/22

This increases the performance of cidr-matching

--no_netaddr
Do not use functions from module NetAddr::IP, even if it was found on the system. This option implicitly disables --aggregate_addrs.
--no_netcidr
Do not use functions from module Net::CIDR::Lite, even if it was found on the system.
--cidr_method=s
(default=autodetect) Use method <s> for network checks. Valid arguments are: 
  netcidr       - compare networks using Net::CIDR::Lite Module (v4 and v6 cidr)
  netaddr       - compare networks using NetAddr::IP Module (v4 and v6 cidr)
  postfwd       - old but very fast method (v4=cidr, v6=regex)

If not specified postfwd tries to load modules in the above order and falls back to 'postfwd' if nothing found.

## whitelisting

# 2. client_names *.gmx.net and *.gmx.de
# 3. sender *@someshop.tld from 11.22.33.44
id=WL001; action=dunno ; client_address=192.168.1.0/24, 192.168.2.4
id=WL002; action=dunno ; client_name=\.gmx\.(net|de)$
id=WL003; action=dunno ; sender=@someshop\.tld$ ; client_address=11.22.33.44
## TLS control
# 1. *@authority.tld only with correct TLS fingerprint
# 2. *@secret.tld only with keysizes >=64
id=TL001; action=dunno                          ; sender=@authority\.tld$ ; ccert_fingerprint=AA:BB:CC..
id=TL002; action=REJECT wrong TLS fingerprint   ; sender=@authority\.tld$
id=TL003; action=REJECT tls keylength < 64      ; sender=@secret\.tld$ ; encryption_keysize=64
## Combined RBL checks
# This will reject mail if
# 1. listed on ix.dnsbl.manitu.net
# 2. listed on zen.spamhaus.org (sbl and xbl, dns cache timeout 1200s instead of 3600s)
# 3. listed on min 2 of bl.spamcop.net, list.dsbl.org, dnsbl.sorbs.net
# 4. listed on bl.spamcop.net and one of rhsbl.ahbl.org, rhsbl.sorbs.net
id=RBL01 ; action=REJECT listed on ix.dnsbl.manitu.net  ; rbl=ix.dnsbl.manitu.net
id=RBL02 ; action=REJECT listed on zen.spamhaus.org     ; rbl=zen.spamhaus.org/127.0.0.[2-8]/1200
id=RBL03 ; action=REJECT listed on too many RBLs        ; rblcount=2 ; rbl=bl.spamcop.net, list.dsbl.org, dnsbl.sorbs.net
id=RBL04 ; action=REJECT combined RBL+RHSBL check       ; rbl=bl.spamcop.net ; rhsbl=rhsbl.ahbl.org, rhsbl.sorbs.net
## Message size (requires message_size_limit to be set to 30000000)
# 1. 30MB for systems in *.customer1.tld
# 2. 20MB for SASL user joejob
# 3. 10MB default
id=SZ001; protocol_state==END-OF-MESSAGE; action=DUNNO; size<=30000000 ; client_name=\.customer1.tld$
id=SZ002; protocol_state==END-OF-MESSAGE; action=DUNNO; size<=20000000 ; sasl_username==joejob
id=SZ002; protocol_state==END-OF-MESSAGE; action=DUNNO; size<=10000000
id=SZ100; protocol_state==END-OF-MESSAGE; action=REJECT message too large
## Selective Greylisting
##
## Note that postfwd does not include greylisting. This setup requires a running postgrey service
## at port 10031 and the following postfix restriction class in your main.cf:
##
##      smtpd_restriction_classes = check_postgrey, ...
##      check_postgrey = check_policy_service inet:127.0.0.1:10031
#
# 1. if listed on zen.spamhaus.org with results 127.0.0.10 or .11, dns cache timeout 1200s
# 2. Client has no rDNS
# 3. Client comes from several dialin domains
id=GR001; action=check_postgrey ; rbl=dul.dnsbl.sorbs.net, zen.spamhaus.org/127.0.0.1[01]/1200
id=GR002; action=check_postgrey ; client_name=^unknown$
id=GR003; action=check_postgrey ; client_name=\.(t-ipconnect|alicedsl|ish)\.de$

PARSER

CONFIGURATION

The postfwd3 ruleset can be specified at the commandline (-r option) or be read from files (-f). The order of your arguments will be kept. You should check the parser with the -C | --showconfig switch at the command line before applying a new config. The following call:

postfwd3 --showconfig \
        -r "id=TEST; recipient_count=100; action=WARN mail with 100+ recipients" \
        -f /etc/postfwd.cf \
        -r "id=DEFAULT; action=dunno";

will produce the following output:

Rule   0: id->"TEST" action->"WARN mail with 100+ recipients"; recipient_count->"100"
...
... <content of /etc/postfwd.cf> ...
...
Rule <n>: id->"DEFAULT" action->"dunno"

Multiple items of the same type will be added to lists (see the "ITEMS" section for more info):

postfwd3 --showconfig \
        -r "client_address=192.168.1.0/24; client_address=172.16.26.32; action=dunno"

will result in:

Rule   0: id->"dunno" client_address->"192.168.1.0/24" client_address->"172.16.26.32"

* يجب أن تحتفظ إعادة توزيع الشيفرة المصدرية بإشعار حقوق النشر أعلاه، وقائمة الشروط هذه، وإخلاء المسؤولية التالي.

* لا يجوز استخدام اسم المؤلفين ولا أسماء المساهمين به لتأييد أو الترويج للمنتجات المشتقة من هذا البرنامج دون إذن خطي مسبق ومحدد.

يتم توفير هذا البرنامج "كما هو" من قبلي، ويتم إخلاء المسؤولية عن أي ضمانات صريحة أو ضمنية، بما في ذلك، على سبيل المثال لا الحصر، الضمانات الضمنية لقابلية التسويق والملاءمة لغرض معين. لن يكون المسؤول بأي حال من الأحوال عن أي أضرار مباشرة أو غير مباشرة أو عرضية أو خاصة أو استثنائية أو تبعية (بما في ذلك، على سبيل المثال لا الحصر، شراء سلع أو خدمات بديلة؛ خسارة الاستخدام أو البيانات أو الأرباح؛ أو انقطاع الأعمال) بغض النظر عن سببها وعلى أي نظرية للمسؤولية، سواء في العقد أو المسؤولية الصارمة أو الضرر (بما في ذلك الإهمال أو غير ذلك) الناشئ بأي شكل من الأشكال عن استخدام هذا البرنامج، حتى لو تم إعلامه بإمكانية حدوث مثل هذا الضرر.
