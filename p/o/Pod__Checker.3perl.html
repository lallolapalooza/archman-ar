NAME

Pod::Checker - Comprobar la sintaxis de POD

VERSION

Este documento describe la versión 1.60 de Pod::Checker.

SYNOPSIS

    use Pod::Checker;
    my $checker = Pod::Checker->new( );
    my $error_count = $checker->parse_file( 'mi_archivo.pod' );
    # o
    my $error_count = $checker->parse_string( \$string_pod );

DESCRIPTION

Este módulo comprueba la sintaxis de los archivos POD. Utiliza Pod::Parser para analizar el POD, y luego verifica el árbol de análisis para detectar errores de sintaxis.

Las advertencias y errores se imprimen en la salida de error estándar (STDERR). La salida estándar se deja intacta.

Este módulo se utiliza como backend para el script de línea de comandos podchecker.

WARNINGS AND ERRORS

  • =back sin un =over correspondiente

    Se encontró un comando =back sin un comando =over correspondiente antes en el mismo nivel de anidamiento.

  • Hay un espacio en blanco en la línea: LINE

    Hay un espacio en blanco en una línea aparentemente vacía. POD es muy sensible a este tipo de cosas, por lo que esto se marca como advertencia. usuarios de vi pueden encender la opción list para evitar este problema.

  • =item tiene contenido vacío

    Hay una lista "=item" que tiene contenido vacío. Probablemente quieras eliminar los items vacíos.

  • No puedes tener =items (como en la línea N) sin que la primera cosa después de =over sea un =item

    Una lista introducida por "=over" comienza con un párrafo de texto o un párrafo verbatim, pero continúa con "=item"s. Mueve el párrafo no-item fuera del bloque "=over"/"=back".

  • Se espera que el =item tenga el valor EXPECTED VALUE
  • Se espera que el =item tenga *'
  • Hay un tipo de =item inadecuado: 'x' se encuentra al principio de una definición de =item

    Una lista empezada por, por ejemplo, una =item similar a un punto y seguido, y continuada con una numerada. Esto es claramente incoherente. Para los traductores principales, el tipo del primer "=item" determina el tipo de la lista.

  • Hay =item x en lugar del esperado =item N
  • El número de =item está mal numérico: necesitan ascender consecutivamente.
  • Contenido de E<CONTENT> desconocido

    Se encontró un carácter de entidad que no pertenece al conjunto estándar ISO o a los especiales de POD "verbar" y "sol". Actualmente, este aviso aparece solo si se encontró un carácter de entidad que no tenga un carácter Unicode. Debe corregirse para mantener el aviso original.

  • bloque =over/=back vacío

    La lista se abre con "=over" y no contiene nada.

  • bloque de sección vacío en la sección anterior

    La sección anterior (introducida por un comando "=head") no contiene contenido válido. Esto suele indicar que algo está faltando. Nota: Un "=head1" seguido inmediatamente por "=head2" no activa este aviso.

  • párrafo verbatim en la sección NAME

    La sección NAME ("=head1 NAME") debe consistir en un párrafo único con el nombre del módulo/script, seguido de un guion `-` y una descripción muy corta del uso del objeto.

  • =headn sin preceder a un nivel superior

    Por ejemplo, si hay un "=head2" antes de un "=head1" en el archivo POD.

  • Z<> no vacío

    El conjunto "Z<>" debe ser vacío. Nota: este problema se detecta en Pod::Simple y se marcará como ERROR por cualquier código cliente; cualquier contenido de "Z<...>" se ignorará, por el momento.

Hyperlinks

Hay algunas advertencias con respecto a enlaces mal formados:

  • se ignora el espacio en blanco al inicio o al final del contenido de L<...>

    Hay espacio en blanco al inicio o al final del contenido de L<...>.

  • el texto alternativo/nodo '%s' contiene caracteres no escapados | o /

    Los caracteres "|" y "/" son especiales en el contexto de L<...>. Aunque el parser de enlaces intenta determinar cuál es texto y cuál es un separador en duda, debería escapar estos caracteres literales así:

    /     E<sol>
|     E<verbar>

Nota: El número de línea de la advertencia/error puede referirse al número de línea de inicio del párrafo en el que se encuentra la advertencia/error, no al número de línea en la que se encuentra el error/error. Esta bug está presente en errores/advertencias relacionadas con el formato de los códigos. Debería ser corregido.

RETURN VALUE

podchecker devuelve el número de errores de sintaxis de POD encontrados o -1 si no se encontraron ningún comando de POD en el archivo.

SCRIPTS

El script podchecker que viene con esta distribución es un wrapper ligero alrededor de este módulo. Vea el manual en línea con

podchecker -help

INTERFACE

Mientras se verifica, este módulo recopila propiedades del documento, por ejemplo, los nodos para enlaces ("=headX", "=item") y entradas de índice ("X<>"). Los traductores de POD pueden usar esta funcionalidad para verificar la sintaxis y obtener los nodos en un primer paso antes de convertir. Este es caro en términos de tiempo de ejecución, pero permite conversiones muy robustas.

Desde v1.24 el módulo Pod::Checker usa solo el método poderror para imprimir errores y advertencias. El resumen de salida (por ejemplo, "Pod syntax OK") ha sido eliminada del módulo y ha sido incluida en podchecker (el script). Esto permite a los usuarios de Pod::Checker controlar completamente el comportamiento de salida. Los usuarios de podchecker (el script) obtienen el comportamiento conocido.

v1.45 hereda de Pod::Simple como opposed a todos los versiones anteriores que heredan de Pod::Parser. No deben usar la interfaz de Pod::Simple cuando estén usando Pod::Checker, a menos que esté documentada aquí. Repito, NO DEBEN USAR LA INTERFAZ DE POD::SIMPLE.
