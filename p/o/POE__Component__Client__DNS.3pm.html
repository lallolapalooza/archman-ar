POE__Component__Client__DNS(3pm)

الحزمة: perl-poe-component-client-dns

التراخيص: GPL, PerlArtistic

POE::Component::Client::DNS(3) وثائق Perl من مساهمات المستخدم POE::Component::Client::DNS(3)

الاسم

POE::Component::Client::DNS - عميل DNS غير مانع ومتوازي

الإصدار

الإصدار 1.054

الملخص

use POE qw(Component::Client::DNS);
my $named = POE::Component::Client::DNS->spawn(
  Alias => "named"
);
POE::Session->create(
  inline_states  => {
    _start   => \&start_tests,
    response => \&got_response,
  }
);
POE::Kernel->run();
exit;
sub start_tests {
  my $response = $named->resolve(
    event   => "response",
    host    => "localhost",
    context => { },
  );
  if ($response) {
    $_[KERNEL]->yield(response => $response);
  }
}
sub got_response {
  my $response = $_[ARG0];
  my @answers = $response->{response}->answer();
  foreach my $answer (@answers) {
    print(
      "$response->{host} = ",
      $answer->type(), " ",
      $answer->rdatastr(), "\n"
    );
  }
}

الوصف

يوفر POE::Component::Client::DNS طلبات DNS غير مانعة ومتوازية باستخدام Net::DNS. باستخدام POE، فإنه يسمح لمهام أخرى بالعمل أثناء انتظار خوادم الأسماء للرد.

لحل أسماء بسيط، بما في ذلك المعالجة الذكية لعناوين IPv6، يرجى الاطلاع على POE::Component::Resolver.

طرق عامة

spawn
يجب على البرنامج استخدام (spawn) مثيل POE::Component::Client::DNS واحد على الأقل قبل إجراء طلبات DNS في الخلفية. يمثل كل مثيل اتصالاً بخادم أسماء واحد أو أكثر. إذا كان البرنامج يحتاج فقط إلى إجراء طلبات DNS من خادم واحد، فإنه يحتاج فقط إلى مثيل POE::Component::Client::DNS واحد.

منذ الإصدار 0.98، يمكنك استبدال المهلة الافتراضية لكل طلب. من هذه النقطة فصاعدًا، لا يلزم إنشاء مثيلات متعددة للتأثير على مهلات مختلفة لكل طلب.

تأخذ طريقة "spawn" لـ PoCo::Client::DNS معلمات مسماة متعددة:

يحدد Alias اسم مستعار للمكون. يتم إرسال الطلبات إلى هذا الاسم المستعار. الاسم المستعار الافتراضي للمكون هو "resolver" إذا لم يتم توفيره. البرامج التي تنشئ مكونات عميل DNS متعددة يجب أن تحدد أسماء مستعارة لـ N-1 منها، وإلا تحدث تضاربات في الأسماء المستعارة.

Alias => $session_alias,  # الافتراضي هو "resolver"

تحدد Timeout مهلة افتراضية للمكون. يمكن استبدال المهلة حسب الطلب. راجع الحدث "request"، أدناه. إذا لم يتم تحديد مهلة، ينتظر المكون 90 ثانية لكل طلب افتراضيًا.

يمكن أن تكون المهلات أرقامًا حقيقية. تكون المهلات أكثر دقة إذا كان لديك Time::HiRes مثبتًا. سيستخدم POE (وبالتالي هذا المكون) Time::HiRes تلقائيًا إذا كان متاحًا.

Timeout => $seconds_to_wait,  # الافتراضي هو 90

يحتفظ Nameservers بمرجع لقائمة خوادم الأسماء التي يجب تجربتها. يتم تمرير القائمة مباشرة إلى طريقة nameservers() في Net::DNS::Resolver. افتراضيًا، يستعلم POE::Component::Client::DNS عن خوادم الأسماء المذكورة في /etc/resolv.conf أو ما يعادله.

Nameservers => \@name_servers,  # الافتراضي هو /etc/resolv.conf's

يحتفظ HostsFile (اختياري) باسم ملف مضيفين محدد لحل العناوين الثابتة. افتراضيًا، يبحث عن ملف يسمى /etc/hosts.

على أنظمة Windows، قد يبحث في الأماكن الأخرى التالية:

$ENV{SystemRoot}\System32\Drivers\Etc\hosts
$ENV{SystemRoot}\System\Drivers\Etc\hosts
$ENV{SystemRoot}\hosts
resolve
يطلب resolve() من المكون حل اسم مضيف. سيعيد مرجع تجزئة (موصوف في رسائل الاستجابة، أدناه) إذا كان بإمكانه تلبية الطلب على الفور (ربما من ذاكرة التخزين المؤقت). خلاف ذلك، يعيد undef إذا كان يجب عليه الاستعلام عن محلل بشكل غير متزامن.

يتم إرسال الطلبات كقائمة من الحقول المسماة.

$resolver->resolve(
  class       => $dns_record_class,  # الافتراضي هو "IN"
  type        => $dns_record_type,   # الافتراضي هو "A"
  host        => $request_host,      # مطلوب
  context     => $request_context,   # مطلوب
  event       => $response_event,    # مطلوب
  timeout     => $request_timeout,   # الافتراضي هو Timeout لـ spawn()
  nameservers => $nameservers,       # الافتراضي هو $resolver's Nameservers
);

يحدد حقلا "class" و "type" نوع المعلومات المطلوب إرجاعها حول اسم المضيف. في معظم الحالات، يتم طلب عناوين IP لأسماء المضيفين، لذا فإن الفئة والنوع الافتراضيين هما "IN" (إنترنت) و "A" (عنوان)، على التوالي.

يحدد الحقل "host" اسم المضيف المطلوب البحث عنه. وهو مطلوب.

يشير الحقل "event" إلى الحدث الذي يجب إرساله عند توفر استجابة. وهو مطلوب، ولكنه لن يستخدم إذا كان resolve() قادرًا على إرجاع استجابة مخزنة فورًا.

يشير "timeout" إلى المدة التي يجب الانتظار فيها للحصول على استجابة لهذا الطلب. الافتراضي هو المهلة التي تم تمريرها إلى طريقة spawn().

"context" يتضمن بيانات خارجية تربط الاستجابات بطلباتها. يتم توفير سياق البيانات بواسطة البرنامج الذي يستخدم POE::Component::Client::DNS. سيمرر المكون السياق دون تعديل إلى البرنامج. الحقل "context" مطلوب ويمكن أن يحتوي على أي شيء يناسب قيمة عددية.

shutdown
يسبب shutdown() إنهاء المكون بأمان. سيتم إنهاء معالجة الطلبات المعلقة وسيتم الإغلاق.
get_resolver
يستخدم POE::Component::Client::DNS كائن Net::DNS::Resolver داخليًا. يعيد get_resolver() هذا الكائن ليتم استجوابه أو تعديله. راجع Net::DNS::Resolver للخيارات.

يمكنك تعيين المحلل للتحقق من منفذ غير قياسي 1153:

$poco_client_dns->get_resolver()->port(1153);

رسائل الاستجابة

يستجيب POE::Component::Client::DNS بطريقتين. سيعيد resolve() استجابة على الفور إذا كان بإمكانه العثور عليها في ذاكرة التخزين المؤقت للمكون. خلاف ذلك، يعيد المكون الاستجابة في $_[ARG0]. في كلتا الحالتين، الاستجابة هي مرجع تجزئة يحتوي على نفس الحقول:

host     => $request_host,
type     => $request_type,
class    => $request_class,
context  => $request_context,
response => $net_dns_packet,
error    => $net_dns_error,

الحقول "host" و "type" و "class" و "context" متطابقة مع تلك التي تم تمريرها في رسالة الطلب.

"response" يحتوي على كائن Net::DNS::Packet إذا نجح الاستعلام، أو undef إذا فشل الاستعلام. يصف كائن Net::DNS::Packet الاستجابة لطلب البرنامج. قد يحتوي على سجلات DNS متعددة. راجع Net::DNS و Net::DNS::Packet لمزيد من المعلومات.

"error" يحتوي على وصف لأي خطأ حدث. وهو صالح فقط إذا كان "response" غير معرف.

انظر أيضًا

POE - يعتمد POE::Component::Client::DNS بشكل كبير على POE.

POE::Component::Resolver - محلل أسماء، بما في ذلك دعم IPv6 وما يدعمه نظامك.

Net::DNS - يستخدم هذه الوحدة Net::DNS داخليًا.

Net::DNS::Packet - يتم إرجاع الاستجابات ككائنات Net::DNS::Packet.

POE::Component::Client::DNS(3pm) — Perl POE Component Client DNS

DEPRECATIONS

The POE::Component::Client::DNS module has been deprecated. Please see the POE::Component::Resolver manpage for more information. POE::Component::Client::DNS will continue to work, but they will generate mandatory warnings. Those warnings will persist until April 2005.

As of April 2005 the mandatory warnings will be upgraded to mandatory errors. Support for the deprecated interfaces will be removed entirely.

As of late January 2011, POE::Component::Resolver provides basic system resolver support, including IPv6 and mDNS if your resolver's configured ot use it. The use of POE::Component::Client::DNS for basic resolution is deprecated, however it's still the best option for actual DNS server requests.
