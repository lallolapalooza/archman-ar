الاسم

Pod::Simple::XHTML — تنسيق Pod بصيغة XHTML مع التحقق من صحة HTML

الملخص

use Pod::Simple::XHTML;
my $parser = Pod::Simple::XHTML->new();
...
$parser->parse_file('path/to/file.pod');

الوصف

هذه الفئة هي مُنسّق يأخذ Pod ويعرضه كـ XHTML مع التحقق من صحة HTML.

هذه الفئة هي فئة فرعية من Pod::Simple::Methody وترث جميع أساليبها. التنفيذ مختلف تمامًا عن Pod::Simple::HTML، ولكنه يحافظ تقريبًا على الواجهة.

الحد الأدنى من الكود

use Pod::Simple::XHTML;
my $psx = Pod::Simple::XHTML->new;
$psx->output_string(\my $html);
$psx->parse_file('path/to/Module/Name.pm');
open my $out, '>', 'out.html' or die "Cannot open 'out.html': $!\n";
print $out $html;

يمكنك أيضًا التحكم في ترميز الأحرف والكيانات. على سبيل المثال، إذا كنت متأكدًا من أن POD مُرمّز بشكل صحيح (باستخدام الأمر "=encoding")، يمكنك منع ترميز الأحرف ذات البتات العالية ككيانات HTML والإعلان عن مجموعة أحرف الإخراج كـ UTF-8 قبل التحليل، هكذا:

  $psx->html_charset('UTF-8');
use warnings;
  $psx->html_encode_chars(q{&<>'"});

الأساليب

توفر Pod::Simple::XHTML عدة أساليب تعدل تنسيق HTML الناتج. استدعِ هذه الأساليب بعد إنشاء كائن المحلل، ولكن قبل استدعاء "parse_file":

my $parser = Pod::PseudoPod::HTML->new();
$parser->set_optional_param("value");
$parser->parse_file($file);

لاحقة عنوان URL لـ perldoc

ما الذي يجب وضعه بعد "Foo%3a%3aBar" في عنوان URL؟ هذه الخيار غير موجود افتراضيًا.

بادئة عنوان URL لدليل man

ما الذي يجب وضعه قبل "1/crontab" عند تحويل "crontab" (5) إلى http://whatever/man/1/crontab؟ القيمة الافتراضية: "http://man.he.net/man".

بادئة العنوان، لاحقة العنوان

ما الذي يجب وضعه قبل وبعد العنوان في رأس الصفحة؟ يجب أن تكون القيم مُشفرة بالفعل باستخدام &.

HTML CSS

$parser->html_css('path/to/style.css');

عنوان URL أو المسار النسبي لملف CSS ليتم تضمينه. هذا الخيار غير موجود افتراضيًا.

HTML JavaScript

عنوان URL أو المسار النسبي لملف JavaScript ليتم تضمينه. هذا الخيار غير موجود افتراضيًا.

HTML doctype

علامة نوع المستند للملف. هذا الخيار غير موجود افتراضيًا.

HTML charset

مجموعة الأحرف التي سيتم الإعلان عنها في علامة meta لنوع المحتوى التي يتم إنشاؤها افتراضيًا لـ "html_header_tags". ملاحظة: سيتم تجاهل هذا الخيار إذا تم تغيير قيمة "html_header_tags". القيمة الافتراضية هي "ISO-8859-1".

HTML header tags

علامات HTML إضافية لرأس المستند. القيمة الافتراضية هي مجرد علامة نوع المحتوى:

<meta http-equiv="Content-Type" content="text/html; charset=ISO-8859-1">

أضف المزيد من علامات meta هنا، أو كتل CSS أو JavaScript (ملفوفة في العلامات المناسبة).

html_encode_chars

سلسلة نصية تحتوي على جميع الأحرف التي يجب ترميزها ككيانات HTML، يتم تحديدها باستخدام صيغة فئات الأحرف العادية (ما تجده بين قوسين في التعبيرات العادية). يتم تمرير هذه القيمة كوسيط ثانٍ إلى الدالة "encode_entities" في HTML::Entities. إذا لم يتم تثبيت HTML::Entities، فسيتم ترميز أي حرف غير &lt; &gt; رقميًا.

مستوى H في HTML

هذا هو مستوى عنصر HTML "Hn" الذي يتوافق مع "head1" في Pod. على سبيل المثال، إذا تم تعيين "html_h_level" على 2، فإن head1 سينتج H2، و head2 سينتج H3، وهكذا.

العنوان الافتراضي

يعيّن عنوانًا افتراضيًا للصفحة إذا لم يكن من الممكن تحديده من المحتوى. يجب أن تكون قيمة هذه السلسلة النصية مُشفرة بالفعل باستخدام &.

فرض العنوان

يفرض عنوانًا للصفحة (لا يحاول تحديده من المحتوى). يجب أن تكون قيمة هذه السلسلة النصية مُشفرة بالفعل باستخدام &.

رأس HTML، ذيل HTML

يعيّن HTML الناتج في بداية ونهاية كل ملف. يتضمن الرأس الافتراضي عنوانًا، وعلامة doctype (إذا تم تعيين "html_doctype")، وعلامة محتوى (يتم تخصيصها بواسطة "html_header_tags")، وعلامة ملف CSS (إذا تم تعيين "html_css")، وعلامة ملف JavaScript (إذا تم تعيين "html_javascript"). يغلق الذيل الافتراضي علامتي "html" و "body".

تُخصص الخيارات المذكورة أعلاه أجزاءً من الرأس الافتراضي، ولكن تعيين "html_header" أو "html_footer" بالكامل سيستبدل الرأس أو الذيل الافتراضي. قد تكون هذه مفيدة إذا كنت ترغب في استخدام علامات القوالب بدلاً من HTML الثابت أو إذا كنت تدمج صفحات مُحوّلة من POD في موقع ويب أكبر.

إذا كنت تريد عدم عرض أي رؤوس أو ذيول في HTML، فعيّن هذه الخيارات إلى سلسلة فارغة.

NAME

Pod::Simple::XHTML - A simple Pod parser that converts to XHTML

SYNOPSIS

use Pod::Simple::XHTML;

my $parser = Pod::Simple::XHTML->new();
$parser->parse_file('SomeFile.pod');
# or
$parser->parse_string($string_of_pod);

DESCRIPTION

Pod::Simple::XHTML is a subclass of Pod::Simple that converts POD (Plain Old Documentation) markup into XHTML 1.0 Transitional. It tries to be as faithful to the original POD as possible, while still producing valid XHTML.

It handles all of the standard POD formatting commands, such as bold, italics, code, etc., as well as the standard POD document structure (sections, paragraphs, lists, etc.).

METHODS

In addition to the methods inherited from Pod::Simple, Pod::Simple::XHTML provides the following methods:

constructor

my $parser = Pod::Simple::XHTML->new();
my $parser = Pod::Simple::XHTML->new(
    # see Pod::Simple documentation for options
);

Calls the constructor of Pod::Simple, passing any arguments to it.

start_document

sub start_document {
    my ($self) = @_;
    $self->SUPER::start_document(@_);
    $self->print("<!DOCTYPE html PUBLIC \"-//W3C//DTD XHTML 1.0 Transitional//EN\"\n");
    $self->print("\"http://www.w3.org/TR/xhtml1/DTD/xhtml1-transitional.dtd\"\gt;\n");
    $self->print("<html>\n");
    $self->print("<head>\n");
    $self->print("<title>");
    $self->print($self->{parser_state}{title} || 'Untitled Document');
    $self->print("</title>\n");
    $self->print("</head>\n");
    $self->print("<body>\n");
}

Prints the DOCTYPE declaration, html, head, title, and body tags. The title is taken from the POD title command (if any), or defaults to "Untitled Document".

end_document

sub end_document {
    my ($self) = @_;
    $self->print("</body>\n");
    $self->print("</html>\n");
    $self->SUPER::end_document(@_);
}

Closes the body and html tags.

handle_text

This method handles the body of text within any element: it's the body of a paragraph, or everything between a "=begin" tag and the corresponding "=end" tag, or the text within an L entity, etc. You would want to override this if you are adding a custom element type that does more than just display formatted text. Perhaps adding a way to generate HTML tables from an extended version of POD.

So, let's say you want to add a custom element called 'foo'. In your subclass's "new" method, after calling "SUPER::new" you'd call:

$new->accept_targets_as_text( 'foo' );

Then override the "start_for" method in the subclass to check for when "$flags->{'target'}" is equal to 'foo' and set a flag that marks that you're in a foo block (maybe "$self->{'in_foo'} = 1"). Then override the "handle_text" method to check for the flag, and pass $text to your custom subroutine to construct the HTML output for 'foo' elements, something like:

sub handle_text {
    my ($self, $text) = @_;
    if ($self->{'in_foo'}) {
        $self->{'scratch'} .= build_foo_html($text);
        return;
    }
    $self->SUPER::handle_text($text);
}

handle_code

This method handles the body of text that is marked up to be code. You might for instance override this to plug in a syntax highlighter. The base implementation just escapes the text.

The callback methods "start_code" and "end_code" emits the "code" tags before and after "handle_code" is invoked, so you might want to override these together with "handle_code" if this wrapping isn't suitable.

Note that the code might be broken into multiple segments if there are nested formatting codes inside a "C<...>" sequence. In between the calls to "handle_code" other markup tags might have been emitted in that case. The same is true for verbatim sections if the "codes_in_verbatim" option is turned on.

accept_targets_as_html

This method behaves like "accept_targets_as_text", but also marks the region as one whose content should be emitted literally, without HTML entity escaping or wrapping in a "div" element.

resolve_pod_page_link

my $url = $pod->resolve_pod_page_link('Net::Ping', 'INSTALL');
my $url = $pod->resolve_pod_page_link('perlpodspec');
my $url = $pod->resolve_pod_page_link(undef, 'SYNOPSIS');

Resolves a POD link target (typically a module or POD file name) and section name to a URL. The resulting link will be returned for the above examples as:

https://metacpan.org/pod/Net::Ping#INSTALL
https://metacpan.org/pod/perlpodspec
#SYNOPSIS

Note that when there is only a section argument the URL will simply be a link to a section in the current document.

resolve_man_page_link

my $url = $pod->resolve_man_page_link('crontab(5)', 'EXAMPLE CRON FILE');
my $url = $pod->resolve_man_page_link('crontab');

Resolves a man page link target and numeric section to a URL. The resulting link will be returned for the above examples as:

http://man.he.net/man5/crontab
http://man.he.net/man1/crontab

Note that the first argument is required. The section number will be parsed from it, and if it's missing will default to 1. The second argument is currently ignored, as man.he.net http://man.he.net does not currently include linkable IDs or anchor names in its pages. Subclass to link to a different man page HTTP server.

idify

my $id   = $pod->idify($text);
my $hash = $pod->idify($text, 1);

This method turns an arbitrary string into a valid XHTML ID attribute value. The rules enforced, following http://webdesign.about.com/od/htmltags/a/aa031707.htm, are:

  • The id must start with a letter (a-z or A-Z)
  • All subsequent characters can be letters, numbers (0-9), hyphens (-), underscores (_), colons (:), and periods (.).
  • The final character can't be a hyphen, colon, or period. URLs ending with these characters, while allowed by XHTML, can be awkward to extract from plain text.
  • Each id must be unique within the document.

In addition, the returned value will be unique within the context of the Pod::Simple::XHTML object unless a second argument is passed a true value. ID attributes should always be unique within a single XHTML document, but pass the true value if you are creating not an ID but a URL hash to point to an ID (i.e., if you need to put the "#foo" in "<a href="#foo">foo</a>".

batch_mode_page_object_init

$pod->batch_mode_page_object_init($batchconvobj, $module, $infile, $outfile, $depth);

Called by Pod::Simple::HTMLBatch so that the class has a chance to initialize the converter. Internally it sets the "batch_mode" property to true and sets batch_mode_current_level(), but Pod::Simple::XHTML does not currently use those features. Subclasses might, though.

SUBCLASSING

You can subclass Pod::Simple::XHTML to customize the output further. For example, you might want to override the following methods:

"handle_text"
To process text content in a custom way. See the example in the "handle_text" method description.
"handle_code"
To apply syntax highlighting to code blocks.
"start_document" and "end_document"
To modify the surrounding HTML structure (e.g., add CSS links, change the doctype).
"resolve_pod_page_link" and "resolve_man_page_link"
To change how POD and man page links are resolved (e.g., link to a different online documentation server).
"idify"
To customize how IDs are generated for anchors.
