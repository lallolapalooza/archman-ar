podman-push(1)

الحزمة: podman

التراخيص: Apache-2.0

NAME

podman-push

push container images to a registry

SYNOPSIS

podman push [OPTIONS] IMAGE [REGISTRY[/REPOSITORY[:TAG]]]

DESCRIPTION

Push the specified image to a container registry or a local directory.

If the destination is not specified, podman push uses containers-transports(5) as the default destination.

A tag can be appended to the image name to specify the destination tag. If no tag is specified, the tag of the image is used.

For registries, the destination can be specified in the format REGISTRY[/REPOSITORY[:TAG]]. If REPOSITORY is not specified, the repository name of the image is used. If TAG is not specified, the tag of the image is used.

If a destination is not specified, podman push will push the image to the registry that the image was pulled from.

OPTIONS

--all-tags
Push all tags of the image.
--authfile path
Path to the authentication file. The default is ${XDG_RUNTIME_DIR}/containers/auth.json. Use podman login to add entries to the authentication file.
--cert-dir path
Path to directory containing TLS trust certificates. For custom CA certificates, place them in this directory.
--digestfile path
Write the digest of the pushed image to the specified file.
--remove-destination
Remove the image from the destination registry if the push is successful. Note that this only works for registries that support deletion, which is not common.
-e, --})^{{image_name=image:tag}}
Push the image to the specified registry. If image:tag is not specified, the image will be pushed to the registry that the image was pulled from.
--format format
Signature format used for the image. Valid formats are docker, oci, and v2s1.
-h, --help
Print usage statement for the command.
--ignore-push-errors
Exit with a zero exit code even if there are push errors. This option is useful for pushing to multiple registries and not failing the entire operation if one of the registries is temporarily unavailable.
--password-stdin
Use the password provided via STDIN for authentication. This option is useful for scripting and for avoiding exposing the password in the command line. The password must be the last line read from STDIN.
-q, --quiet
Suppress progress output during the push operation.
--sign-by keyname
Sign the image with the specified GPG key.
--tls-verify
Require TLS for registries and ignore certificate errors. This is the default for registries defined in containers-registries.conf(5). If not specified, TLS verification is used unless the target registry is listed as an insecure registry in containers-registries.conf(5).

EXAMPLES

Push the specified image to a local directory:

# podman push imageID dir:/path/to/image

Push the specified image to a local directory in OCI format:

# podman push imageID oci-archive:/path/to/layout:image:tag

Push the specified image to a container registry:

# podman push imageID docker://registry.example.com/repository:tag

Push the specified image to a container registry and save the digest in the specified file:

# podman push --digestfile=/tmp/mydigest imageID docker://registry.example.com/repository:tag

Push the specified image into the local Docker daemon container store:

# podman push imageID docker-daemon:image:tag

Push the specified image with a different image name using credentials from an alternate authfile path:

# podman push --authfile temp-auths/myauths.json alpine docker://docker.io/umohnani/alpine
