podman-manifest(1)

الحزمة: podman

التراخيص: Apache-2.0

podman-manifest(1) دليل الأوامر العامة podman-manifest(1)

الاسم

podman-manifest - إنشاء ومعالجة قوائم البيانات الوصفية وفهارس الصور

الملخص

podman manifest subcommand

الوصف

يوفر أمر podman manifest أوامر فرعية يمكن استخدامها لـ:

* إنشاء قائمة بيانات وصفية Docker عاملة أو فهرس صور OCI.

الأوامر الفرعية

الأمر صفحة الدليل الوصف
add podman-manifest-add(1) إضافة صورة أو قطعة أثرية إلى قائمة بيانات وصفية أو فهرس صور.
annotate podman-manifest-annotate(1) إضافة وتحديث معلومات حول صورة أو قطعة أثرية في قائمة بيانات وصفية أو فهرس صور.
create podman-manifest-create(1) إنشاء قائمة بيانات وصفية أو فهرس صور.
exists podman-manifest-exists(1) التحقق مما إذا كانت قائمة البيانات الوصفية المحددة موجودة في التخزين المحلي
inspect podman-manifest-inspect(1) عرض قائمة بيانات وصفية أو فهرس صور.
push podman-manifest-push(1) دفع قائمة بيانات وصفية أو فهرس صور إلى مسجل.
remove podman-manifest-remove(1) إزالة عنصر من قائمة بيانات وصفية أو فهرس صور.
rm podman-manifest-rm(1) إزالة قائمة البيانات الوصفية أو فهرس الصور من التخزين المحلي.

أمثلة

بناء قائمة بيانات وصفية متعددة الأركان من Containerfile

بافتراض أن تعليمات RUN تستخدم في Containerfile، يحتاج المضيف إلى طريقة لتنفيذ ثنائيات غير أصلية. تكوين هذا يتجاوز نطاق هذا المثال. يمكن بناء قائمة بيانات وصفية متعددة الأركان shazam بالتوازي عبر 4 سلاسل (threads) على النحو التالي:

    $ platarch=linux/amd64,linux/ppc64le,linux/arm64,linux/s390x
    $ podman build --jobs=4 --platform=$platarch --manifest shazam .

ملاحظة: الوسيط --jobs اختياري. لا تستخدم خيار --tag (أو -t) الخاص بأمر podman build عند بناء قائمة بيانات وصفية متعددة الأركان.

تجميع بيان متعدد الأركان من صور مبنية بشكل منفصل

بافتراض أن صور example.com/example/shazam:$arch مبنية بشكل منفصل على مضيفات أخرى وتم دفعها إلى مسجل example.com. يمكن دمجها في قائمة بيانات وصفية، ودفعها باستخدام حلقة بسيطة:

    $ REPO=example.com/example/shazam
    $ podman manifest create $REPO:latest
    $ for IMGTAG in amd64 s390x ppc64le arm64; do   
              podman manifest add $REPO:latest docker://$REPO:IMGTAG;   
          done
    $ podman manifest push --all $REPO:latest

ملاحظة: ترتيب وسيطة أمر add هو <manifest> ثم <image>. أيضًا، يلزم خيار الدفع --all لضمان دفع جميع المحتويات، وليس فقط المنصة/الهيكل الأصلي.

إزالة ووضع علامة على قائمة البيانات الوصفية قبل الدفع

يلزم عناية خاصة عند إزالة ودفع قوائم البيانات الوصفية، على عكس المحتويات. تريد دائمًا استخدام الأوامر الفرعية manifest rm و manifest push --all. على سبيل المثال، يمكن إجراء إعادة تسمية ودفع على النحو التالي:

    $ podman tag localhost/shazam example.com/example/shazam
    $ podman manifest rm localhost/shazam
    $ podman manifest push --all example.com/example/shazam
