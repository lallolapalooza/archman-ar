NAME

postfix2dlf - convert postfix logfile to DLF format

SYNOPSIS

postfix2dlf [ options ] [ logfile ]

DESCRIPTION

postfix2dlf filters a postfix logfile, and converts it into the DLF (Delivery Failure Log) format. DLF is a generic format for logs of mail delivery failures.

The logs are processed in two phases. The first phase (postfix2dlf_pre(1)) is for pre-processing the logfile: it extracts the queueids from the logs, and it writes a temporary file in a format more easily parsed by the second phase.

The second phase (postfix2dlf_main(1)) reads the temporary file, parses it, and outputs the DLF formatted loglines. The temporary file is automatically deleted.

RATIONALE

We need a generic logfile format for mail delivery failures, so that other programs can use it to process these failures. The DLF format is intended for this purpose.

Postfix logs are not easily parsable, especially the queueids. We have devised a way to extract the queueids from the logs, and to use them to uniquely identify a delivery attempt. This is needed because some mail servers don't report the original recipient of the mail, so we can't track deliveries based on recipients alone.

EXAMPLE

To convert your postfix logfile to DLF format, run:

$ postfix2dlf /var/log/maillog

This will print the DLF formatted log lines to standard output.

postfix2dlf_pre info memory stats: vsize=5900K rss=4508K majflt=430

postfix2dlf_main info read 177027 lines; output 61671 DLF lines; 0 errors
postfix2dlf_main info memory stats: vsize=5976K rss=4656K majflt=427
postfix2dlf_main info elapsed time in seconds real=245 user=152.05 system=4.15

PERFORMANCE

The two-phase processing seems to be necessary, because Postfix logs are not easily parsable. Without the intermediate file, we'd have to store a lot of information in memory.

The logfile is scanned twice. The first scan produces a temporary file, which is about the same size as the original logfile. The second scan reads this temporary file and produces the DLF output.

The log processing is relatively fast, but it can take some time for very large logfiles. The example log shown above took 626 + 245 = 871 seconds (about 14.5 minutes) to process on a Pentium III 733MHz with 256MB of RAM. This is approximately 195257 / 871 = 224 lines per second.

EXAMPLES

postfix2dlf will be rarely used on its own, but is more likely called by lr_log2report:

$ lr_run lr_log2report postfix < /var/log/maillog

BUGS

This script needs a lot of space in TMPDIR: it creates a tmpfile which is about the same in size as the raw log it's being fed.

Occasionally, postfix reuses its queueids very fast. We can't cope with this.
