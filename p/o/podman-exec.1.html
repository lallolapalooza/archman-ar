الحزمة: podman

التراخيص: Apache-2.0

podman-exec(1) دليل الأوامر العامة podman-exec(1)

الاسم

podman-exec - تنفيذ أمر في حاوية قيد التشغيل

الخلاصة

podman exec [خيارات] حاوية أمر [وسيط ...]

podman container exec [خيارات] حاوية أمر [وسيط ...]

الوصف

podman exec ينفذ أمرًا في حاوية قيد التشغيل.

الخيارات

--cidfile=ملف

اقرأ معرّف الحاوية المستهدفة من الـ ملف المحدد.

--detach, -d

ابدأ جلسة التنفيذ، ولكن لا تتصل بها. يتم تشغيل الأمر في الخلفية، ويتم إزالة جلسة التنفيذ تلقائيًا عند اكتمالها. تقوم الأوامر podman exec بطباعة معرّف جلسة التنفيذ والخروج فورًا بعد بدئها.

--detach-keys=تسلسل

حدد تسلسل المفاتيح لفصل الحاوية. التنسيق هو حرف واحد [a-Z] أو حرف واحد أو أكثر من ctrl-<value> حيث <value> هو واحد مما يلي: a-z، @، ^، [، , أو _. تحديد "" يعطل هذه الميزة. الافتراضي هو ctrl-p,ctrl-q.

يمكن أيضًا تعيين هذا الخيار في ملف containers.conf(5).

--env, -e=متغير

تعيين متغيرات البيئة.

يسمح هذا الخيار بمتغيرات بيئة عشوائية متاحة للعملية التي سيتم تشغيلها داخل الحاوية. إذا تم تحديد متغير بيئة بدون قيمة، يتحقق Podman من بيئة المضيف بحثًا عن قيمة ويقوم بتعيين المتغير فقط إذا تم تعيينه في المضيف. كحالة خاصة، إذا تم تحديد متغير بيئة ينتهي بـ * بدون قيمة، يبحث Podman في بيئة المضيف عن متغيرات تبدأ بالبادئة ويضيف تلك المتغيرات إلى الحاوية.

--env-file=ملف

قراءة ملف متغيرات البيئة مفصولة بسطور.

--interactive, -i

عند تعيينه إلى true، اجعل stdin متاحًا للعملية المحتواة. إذا كان false، يكون stdin للعملية المحتواة فارغًا ويتم إغلاقه فورًا.

إذا تم الاتصال، يتم توجيه stdin إلى العملية المحتواة. إذا تم فصله، فإن قراءة stdin ستمنع حتى يتم الاتصال لاحقًا.

تنبيه: سيستهلك Podman المدخلات من stdin بمجرد توفرها، حتى لو لم تطلبها العملية المحتواة.

--latest, -l

بدلاً من توفير اسم الحاوية أو معرّفها، استخدم آخر حاوية تم إنشاؤها. ملاحظة: قد تكون آخر حاوية تم تشغيلها من مستخدمين آخرين لـ Podman على الجهاز المضيف. (هذا الخيار غير متاح مع عميل Podman عن بعد، بما في ذلك أجهزة Mac و Windows (باستثناء WSL2)).

--preserve-fd=FD1[,FD2,...]

مرر واصفات الملفات الإضافية المحددة في القائمة المفصولة بفواصل إلى العملية. يمكن تحديده عدة مرات. هذا الخيار مدعوم فقط مع محرك OCI crun. قد يكون استخدامه خطرًا أمنيًا مع محركات OCI أخرى.

(هذا الخيار غير متاح مع عميل Podman عن بعد، بما في ذلك أجهزة Mac و Windows (باستثناء WSL2)).

--preserve-fds=N

مرر N واصفات ملفات إضافية إلى العملية (بالإضافة إلى 0، 1، 2). إجمالي واصفات الملفات هو 3+N. (هذا الخيار غير متاح مع عميل Podman عن بعد، بما في ذلك أجهزة Mac و Windows (باستثناء WSL2)).

--privileged

منح امتيازات موسعة لهذه الحاوية. الافتراضي هو false.

افتراضيًا، الحاويات غير مميزة (=false) ولا يمكنها، على سبيل المثال، تعديل أجزاء من نظام التشغيل. وذلك لأن الحاوية افتراضيًا يُسمح لها فقط بالوصول المحدود إلى الأجهزة. يتم منح الحاوية "المميزة" نفس الوصول إلى الأجهزة مثل المستخدم الذي يقوم بتشغيل الحاوية، باستثناء وحدات التحكم الافتراضية (/dev/tty\d+) عند التشغيل في وضع systemd (--systemd=always).

الحاوية المميزة تعطل الميزات الأمنية التي تعزل الحاوية عن المضيف. يتم تعطيل القدرات المهملة، والأجهزة المحدودة، ونقاط التركيب للقراءة فقط، والفصل بين Apparmor/SELinux، ومرشحات Seccomp. بسبب الميزات الأمنية المعطلة، يجب عدم تعيين الحقل المميز تقريبًا أبدًا حيث يمكن للحاويات كسر القيود بسهولة.

لا يمكن للحاويات التي تعمل في مساحة مستخدم (مثل الحاويات غير الجذرية) أن تحصل على امتيازات أكثر من المستخدم الذي قام بتشغيلها.

--tty, -t

تخصيص TTY وهمي. الافتراضي هو false.

عند تعيينه إلى true، يقوم Podman بتخصيص TTY وهمي والاتصال بالمدخل القياسي للحاوية. يمكن استخدام هذا، على سبيل المثال، لتشغيل shell تفاعلي مؤقت.

ملاحظة: علامة --tty تمنع إعادة توجيه المخرجات القياسية. تجمع بين STDOUT و STDERR، وقد تقوم بإدراج أحرف التحكم، وقد تتسبب في تعليق الأنابيب. يتم استخدام هذا الخيار فقط عند التشغيل بشكل تفاعلي في طرفية. عند تغذية المدخلات إلى Podman، استخدم -i فقط، وليس -it.

--user, -u=مستخدم[:مجموعة]

يعين اسم المستخدم أو UID المستخدم، وبشكل اختياري، اسم المجموعة أو GID للأمر المحدد. يمكن أن يكون كل من مستخدم و مجموعة رمزيين أو رقميين.

بدون هذا الوسيط، يتم تشغيل الأمر كالمستخدم المحدد في صورة الحاوية. ما لم يتم تجاوزه بأمر USER في ملف Containerfile أو بقيمة تم تمريرها إلى هذا الخيار، فإن هذا المستخدم افتراضيًا هو الجذر.

عندما لا يتم استخدام مساحة مستخدم، يتطابق UID و GID المستخدم داخل الحاوية وعلى المضيف. ومع ذلك، عند استخدام مساحات المستخدم، قد يتوافق UID و GID في الحاوية مع UID و GID آخرين على المضيف. في الحاويات غير الجذرية، على سبيل المثال، يتم استخدام مساحة مستخدم دائمًا، والجذر في الحاوية افتراضيًا يتوافق مع UID و GID للمستخدم الذي يستدعي Podman.

--workdir, -w=دليل

دليل العمل داخل الحاوية.

دليل العمل الافتراضي لتشغيل البرامج التنفيذية داخل الحاوية هو الدليل الجذر (/). يمكن لمطور الصورة تعيين افتراضي مختلف باستخدام تعليمات WORKDIR. يمكن للمشغل تجاوز دليل العمل باستخدام الخيار -w.

حالة الخروج

يقدم رمز الخروج من podman exec معلومات حول سبب فشل تشغيل الأمر داخل الحاوية أو سبب خروجه. عندما يخرج podman exec برمز غير صفري، تتبع رموز الخروج معيار chroot، انظر أدناه:

125 الخطأ يتعلق بـ Podman نفسه

$ podman exec --foo ctrID /bin/sh; echo $?
Error: unknown flag: --foo
125

126 لا يمكن استدعاء الأمر المحتوى

$ podman exec ctrID /etc; echo $?
Error: container_linux.go:346: starting container process caused "exec: \"/etc\": permission denied": OCI runtime error
126

127 لا يمكن العثور على الأمر المحتوى

$ podman exec ctrID foo; echo $?
Error: container_linux.go:346: starting container process caused "exec: \"foo\": executable file not found in $PATH": OCI runtime error
127

رمز الخروج رمز خروج الأمر المحتوى

$ podman exec ctrID /bin/sh -c 'exit 3'; echo $?
3

أمثلة

تنفيذ أمر في حاوية مختارة مع تخصيص stdin و tty:

$ podman exec -it ctrID ls

تنفيذ أمر مع تجاوز دليل العمل في حاوية مختارة مع تخصيص stdin و tty:

$ podman exec -it -w /tmp myCtr pwd

تنفيذ أمر كمستخدم محدد في حاوية مختارة:

$ podman exec --user root ctrID ls

تنفيذ أمر ولكن لا تتصل بجلسة التنفيذ، تاركًا الأمر يعمل في الخلفية:

$ podman exec -d ctrID find /path/to/search -name yourfile

NAME

podman-exec - Execute a command in a running container

SYNOPSIS

podman exec [OPTIONS] CONTAINER COMMAND [ARG...]

podman container exec [OPTIONS] CONTAINER COMMAND [ARG...]

DESCRIPTION

The podman exec command runs a new command inside a running container. The command can be any executable in the container's $PATH or an absolute path to an executable. The command can also take arguments.

A new namespace is created for the command. The command is run with the same options, environment, and security settings as the container itself.

If podman exec is used to run the sh or bash command, the --tty option should be used to allocate a pseudo-TTY. This is necessary to have an interactive shell.

If the CONTAINER is not running, the command will not be executed.

OPTIONS

--detach, -d
Run the command in the background (detached mode).
--env, -e
Set environment variables. The variable format is VAR=value. This option can be used multiple times. Podman does not support using the --env option to pass sensitive data like passwords or encryption keys.
--env-file
Read environment variables from a file. The file format is the same as docker-compose.yml. You can use this option multiple times.
--gid
Run the command as a specific group ID. The default is the GID of the container's user. If the user is not specified, the default GID is 0.
--interactive, -i
Keep STDIN open even if not attached.
--name
Assign a name to the process. This is useful for identifying the process later with podman ps.
--preserve-credentials
Preserve the credentials from the original container. This is useful when running commands in a container that requires authentication, such as accessing a private registry.
--quiet, -q
Suppress all output and only print the ID of the command.
--tty, -t
Allocate a pseudo-TTY. This is necessary for interactive shells.
--user, -u
Run the command as a specific user ID or name. The default is the user specified in the container image. If the user is not specified, the default user is root.
--workdir, -w
Set the working directory for the command.

Exit Status

The exit status of podman exec is the exit status of the command specified by COMMAND.

EXAMPLES

Run the ls command in the container mycontainer:

podman exec mycontainer ls

Run the bash command in the container mycontainer and get an interactive shell:

podman exec -it mycontainer bash

Run the echo command in the container mycontainer with a custom environment variable:

podman exec -e MYVAR=myvalue mycontainer echo $MYVAR

Run the sleep command in the container mycontainer in the background:

podman exec -d mycontainer sleep 300
