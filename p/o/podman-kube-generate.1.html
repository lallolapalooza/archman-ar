podman-kube-generate(1)

الحزمة: podman

التراخيص: Apache-2.0

podman-kube-generate(1) دليل الأوامر العامة podman-kube-generate(1)

الاسم

podman kube generate - إنشاء ملفات YAML لـ Kubernetes بناءً على الحاويات أو البودات أو وحدات التخزين

الملخص

podman kube generate [خيارات] حاوية... | بود... | وحدة تخزين...

الوصف

يقوم podman kube generate بإنشاء ملفات YAML لـ Kubernetes (مواصفات v1) من حاويات Podman أو البودات أو وحدات التخزين. بغض النظر عما إذا كان الإدخال للحاويات أو البودات، يقوم Podman بإنشاء المواصفات كـ Pod افتراضيًا. قد يكون الإدخال على شكل حاوية واحدة أو أكثر، أو بودات، أو أسماء أو معرفات وحدات تخزين.

حاويات أو بودات Podman

تظهر وحدات التخزين في ملف YAML الذي تم إنشاؤه وفقًا لنوعين مختلفين من وحدات التخزين. تصبح وحدات التخزين المثبتة (Bind-mounted) من نوع وحدة تخزين hostPath، وتصبح وحدات التخزين المسماة (named volumes) من نوع persistentVolumeClaim. أنواع وحدات التخزين hostPath التي تم إنشاؤها هي واحدة من ثلاث أنواع فرعية اعتمادًا على حالة المسار المضيف: DirectoryOrCreate عندما لا يوجد ملف أو دليل في المضيف، Directory عندما يكون المسار المضيف دليلاً، أو File عندما يكون المسار المضيف ملفًا. القيمة لـ claimName لـ persistentVolumeClaim هي اسم وحدة التخزين المسماة المسجلة في Podman.

يتم تجنب تضارب الأسماء المحتمل بين وحدات التخزين عن طريق استخدام مخطط تسمية قياسي لكل نوع وحدة تخزين. يتم تسمية أنواع وحدات التخزين hostPath وفقًا للمسار على الجهاز المضيف، مع استبدال الشرطات المائلة الأمامية بشرطات أقل، باستثناء الشرطة المائلة الأمامية الرائدة والنهائية. الحالة الخاصة لجذر نظام الملفات، /، تترجم إلى الاسم root. بالإضافة إلى ذلك، يتم إلحاق الاسم بـ -host لتجنب تضارب الأسماء مع وحدات التخزين من نوع persistentVolumeClaim. يستخدم كل نوع وحدة تخزين persistentVolumeClaim اسم وحدة التخزين المسماة المرتبطة بها، مع إلحاق -pvc.

لاحظ أنه إذا تم إنشاء حاوية تهيئة (init container) من النوع once وتم تشغيل البود، فإنها لا تظهر في ملف YAML لـ Kubernetes على أنها من النوع once لأن حاويات التهيئة التي تعمل لمرة واحدة يتم حذفها بعد تشغيلها. إذا تم إنشاء البود فقط ولم يتم تشغيله، فإنه يظهر في ملف YAML لـ Kubernetes. حاويات التهيئة التي تم إنشاؤها من النوع always يتم إنشاؤها دائمًا في ملف YAML لـ Kubernetes لأنها لا يتم حذفها أبدًا، حتى بعد الانتهاء من التشغيل.

ملاحظة: عند استخدام وحدات التخزين وإنشاء ملف YAML لـ Kubernetes لحاوية podman غير مميزة وغير جذرية (unprivileged and rootless) على نظام يدعم SELinux، يجب إكمال أحد الخيارات التالية:
* أضف الخيار "privileged: true" إلى مواصفات البود
* أضف type: spc_t ضمن securityContext seLinuxOptions في مواصفات البود
* أعد تسمية وحدة التخزين عبر أمر CLI chcon -t container_file_t -R <directory>

بمجرد الانتهاء، تكون الأذونات الصحيحة متاحة للوصول إلى وحدة التخزين عند إنشاء البود/الحاوية في مجموعة Kubernetes.

لاحظ أنه يمكن استخدام ملف YAML لـ Kubernetes الذي تم إنشاؤه لإعادة تشغيل النشر عبر podman-play-kube(1).

لاحظ أنه إذا تم إنشاء البود الذي يتم إنشاؤه باستخدام العلامة --infra-name، فسيكون ملف YAML لـ Kubernetes يحتوي على علامة io.podman.annotations.infra.name حيث تكون القيمة هي اسم حاوية البنية التحتية التي حددها المستخدم.

لاحظ أن Deployment و DaemonSet يمكن أن يكون لهما فقط restartPolicy معينًا إلى Always.

لاحظ أن Job يمكن أن يكون له فقط restartPolicy معينًا إلى OnFailure أو Never. افتراضيًا، يضبطه podman على Never عند إنشاء ملف YAML لـ Kubernetes باستخدام kube generate.

خيارات

--filename, -f=اسم الملف

الإخراج إلى الملف المحدد بدلاً من STDOUT. إذا كان الملف موجودًا بالفعل، يرفض kube generate استبداله ويعيد خطأ.

--podman-only

إضافة علامات محمية خاصة بـ podman فقط في ملف YAML الذي تم إنشاؤه (لا يمكن استخدامها بواسطة Kubernetes)

--replicas, -r=عدد النسخ المتماثلة

القيمة التي سيتم تعيين replicas إليها عند إنشاء Deployment. ملاحظة: يمكن تعيين هذا فقط باستخدام الخيار --type=deployment.

--service, -s

إنشاء كائن خدمة Kubernetes بالإضافة إلى البودات. يستخدم لإنشاء مواصفات خدمة لمخرجات البود المقابلة. على وجه الخصوص، إذا كان الكائن لديه ربط منافذ (portmap bindings)، فإن مواصفات الخدمة تتضمن تعريف NodePort لتصدير الخدمة. يتم تعيين منفذ عشوائي بواسطة Podman في المواصفات.

--type, -t=pod | deployment | daemonset | job

نوع Kubernetes الذي سيتم إنشاؤه في ملف YAML. حاليًا، المواصفات الوحيدة المدعومة في Kubernetes هي Pod، Deployment، Job، و DaemonSet. افتراضيًا، يتم إنشاء مواصفات Pod.

أمثلة

إنشاء ملف YAML لـ Kubernetes Pod للحاوية المحددة.

$ podman kube generate some-mariadb
# حفظ مخرجات هذا الملف واستخدام kubectl create -f لاستيرادها
# إلى Kubernetes.
#
# تم الإنشاء باستخدام podman-4.8.2
# ملاحظة: إذا قمت بإنشاء هذا الـ yaml من حاوية podman غير مميزة وغير جذرية على نظام يدعم SELinux،
# تحقق من صفحة دليل podman generate kube للحصول على الخطوات الواجب اتباعها لضمان حصول البود/الحاوية الخاصة بك
# على الأذونات الصحيحة للوصول إلى وحدات التخزين المضافة.
---
apiVersion: v1
kind: Pod
metadata:
  creationTimestamp: "2024-01-09T02:24:55Z"
  labels:
    app: some-mariadb-pod
  name: some-mariadb-pod
spec:
  containers:
  - args:
    - mariadbd
    env:
    - name: MARIADB_ROOT_PASSWORD
      value: x
    image: docker.io/library/mariadb:10.11
    name: some-mariadb
    ports:
    - containerPort: 3306
      hostPort: 34891
    volumeMounts:
    - mountPath: /var/lib/mysql
      name: mariadb_data-pvc
  volumes:
  - name: mariadb_data-pvc
    persistentVolumeClaim:
      claimName: mariadb_data

إنشاء ملف YAML لـ Kubernetes Deployment بثلاث نسخ متماثلة للحاوية المحددة.

$ podman kube generate --type deployment --replicas 3 dep-ct
r
# حفظ مخرجات هذا الملف واستخدام kubectl create -f لاستيرادها
# إلى Kubernetes.
#
# تم الإنشاء باستخدام podman-4.5.0-dev
apiVersion: apps/v1
kind: Deployment
metadata:
  creationTimestamp: "2023-03-27T20:45:08Z"
  labels:
    app: dep-ctr-pod
  name: dep-ctr-pod-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: dep-ctr-pod
  template:
    metadata:
      annotations:
        io.podman.annotations.ulimit: nofile=524288:524288,nproc=127332:127332
      creationTimestamp: "2023-03-27T20:45:08Z"
      labels:
        app: dep-ctr-pod
      name: dep-ctr-pod
    spec:
      containers:
      - command:
        - top
        image: docker.io/library/alpine:latest
        name: dep-ctr

إنشاء ملف YAML لـ Kubernetes Pod للحاوية المحددة مع تثبيت الدليل المضيف /home/user/my-data على مسار الحاوية /volume.

$ podman kube generate my-container-with-bind-mounted-data
# حفظ مخرجات هذا الملف واستخدام kubectl create -f لاستيرادها
# إلى Kubernetes.
#
# تم الإنشاء باستخدام podman-3.1.0-dev
apiVersion: v1
kind: Pod
metadata:
  creationTimestamp: "2021-03-18T16:26:08Z"
  labels:
    app: my-container-with-bind-mounted-data
  name: my-container-with-bind-mounted-data
spec:
  containers:
  - command:
    - /bin/sh
    image: docker.io/library/alpine:latest
    name: test-bind-mount
    volumeMounts:
    - mountPath: /volume
      name: home-user-my-data-host
  restartPolicy: Never
  volumes:
  - hostPath:
      path: /home/user/my-data
      type: Directory
    name: home-user-my-data-host

إنشاء ملف YAML لـ Kubernetes Pod للحاوية المحددة مع تثبيت وحدة التخزين المسماة priceless-data على مسار الحاوية /volume.

$ podman kube generate my-container-using-priceless-data
# حفظ مخرجات هذا الملف واستخدام kubectl create -f لاستيرادها
# إلى Kubernetes.
#
# تم الإنشاء باستخدام podman-3.1.0-dev
apiVersion: v1
kind: Pod
metadata:
  creationTimestamp: "2021-03-18T16:26:08Z"
  labels:
    app: my-container-using-priceless-data
  name: my-container-using-priceless-data
spec:
  containers:
  - command:
    - /bin/sh
    image: docker.io/library/alpine:latest
    name: test-bind-mount
    volumeMounts:
    - mountPath: /volume
      name: priceless-data-pvc
  restartPolicy: Never
  volumes:
  - name: priceless-data-pvc
    persistentVolumeClaim:
      claimName: priceless-data

$ sudo podman kube generate
