Pod::Usage(3perl) Perl Programmers Reference Guide Pod::Usage(3perl)

NAME

Pod::Usage - يستخرج وثائق POD ويعرض معلومات الاستخدام

SYNOPSIS

use Pod::Usage;
my $message_text  = "This text precedes the usage message.";
my $exit_status   = 2;          ## The exit status to use
my $verbose_level = 0;          ## The verbose level to use
my $filehandle    = \*STDERR;   ## The filehandle to write to
pod2usage($message_text);
pod2usage($exit_status);
pod2usage( { -message => $message_text ,
             -exitval => $exit_status  ,
             -verbose => $verbose_level,
             -output  => $filehandle } );
pod2usage(   -msg     => $message_text ,
             -exitval => $exit_status  ,
             -verbose => $verbose_level,
             -output  => $filehandle );
pod2usage(   -verbose => 2,
             -noperldoc => 1  );
pod2usage(   -verbose => 2,
             -perlcmd => $path_to_perl,
             -perldoc => $path_to_perldoc,
             -perldocopt => $perldoc_options );

ARGUMENTS

pod2usage يجب أن تُعطى إما وسيطًا واحدًا، أو قائمة وسائط تقابل مصفوفة ترابطية (a "hash"). عندما يُعطى وسيط واحد، يجب أن يقابل واحدًا مما يلي بالضبط:

  • نص يحتوي على نص رسالة ليتم طباعته قبل طباعة رسالة الاستخدام
  • قيمة رقمية تقابل حالة الخروج المطلوبة
  • مرجع إلى hash

إذا تم إعطاء أكثر من وسيط واحد، فيُفترض أن قائمة الوسائط بأكملها هي hash. إذا تم توفير hash (إما كمرجع أو كقائمة)، فيجب أن يحتوي على عنصر واحد أو أكثر بالخصائص التالية:

"-message" string
"-msg" string
نص رسالة ليتم طباعته مباشرة قبل طباعة رسالة استخدام البرنامج.
"-exitval" value
حالة الخروج المطلوبة ليتم تمريرها إلى الدالة exit(). يجب أن يكون هذا عددًا صحيحًا، أو السلسلة النصية "NOEXIT" للإشارة إلى أنه يجب ببساطة إعادة التحكم دون إنهاء العملية المستدعية.
"-verbose" value
مستوى "الإسهاب" المطلوب استخدامه عند طباعة رسالة الاستخدام. إذا كانت القيمة 0، فسيتم طباعة أقسام "SYNOPSIS" و/أو "USAGE" فقط. إذا كانت القيمة 1، فسيتم طباعة أقسام "SYNOPSIS" و/أو "USAGE"، جنبًا إلى جنب مع أي قسم بعنوان "OPTIONS" أو "ARGUMENTS" أو "OPTIONS AND ARGUMENTS". إذا كانت القيمة المقابلة 2 أو أكثر، فسيتم طباعة صفحة الدليل الكاملة، باستخدام perldoc إذا كانت متاحة؛ وإلا سيتم استخدام Pod::Text للتنسيق. لتحسين القراءة، يتم تحويل العناوين المكتوبة بأحرف كبيرة بالكامل إلى أحرف صغيرة، على سبيل المثال: "SYNOPSIS" => "Synopsis".

يتطلب مستوى الإسهاب الخاص 99 تحديد المعلمة -sections أيضًا؛ ثم يتم استخراج هذه الأقسام وطباعتها.

"-sections" spec
هناك طريقتان لتحديد الاختيار. إما سلسلة نصية (scalar) تمثل تعبيرًا عاديًا للاختيار للأقسام التي سيتم طباعتها عندما تكون قيمة -verbose هي 99، على سبيل المثال: 
"NAME|SYNOPSIS|DESCRIPTION|VERSION"

باستخدام التعبير العادي أعلاه، سيتم عرض كل المحتوى الذي يلي (وبما في ذلك) أي من العناوين "=head1" المعطاة. من الممكن تقييد الإخراج لأقسام فرعية معينة فقط، على سبيل المثال:

"DESCRIPTION/Algorithm"

سيؤدي هذا إلى إخراج العنوان "=head2 Algorithm" والمحتوى داخل قسم "=head1 DESCRIPTION" فقط. الربط بالتعبير العادي أقوى من فاصل القسم، بحيث على سبيل المثال:

"DESCRIPTION|OPTIONS|ENVIRONMENT/Caveats"

سيؤدي هذا إلى طباعة أي قسم "=head2 Caveats" (فقط) ضمن أي من أقسام "=head1" الثلاثة.

بدلاً من ذلك، يمكن استخدام مرجع مصفوفة لمواصفات الأقسام:

pod2usage(-verbose => 99, -sections => [
  qw(DESCRIPTION DESCRIPTION/Introduction) ] );

سيؤدي هذا إلى طباعة محتوى أقسام "=head1 DESCRIPTION" و "=head2 Introduction" فقط، ولكن لا شيء آخر من "=head2"، ولا شيء آخر من "=head1" أيضًا.

"-output" handle
مرجع إلى مقبض ملف، أو مسار ملف يجب كتابة رسالة الاستخدام إليه. الافتراضي هو "\*STDERR" ما لم تكن قيمة الخروج أقل من 2 (في هذه الحالة يكون الافتراضي "\*STDOUT").
"-input" handle
مرجع إلى مقبض ملف، أو مسار ملف يجب قراءة وثائق pod الخاصة بالبرنامج المستدعي منه. القيمة الافتراضية هي الملف المحدد بواسطة $0 ($PROGRAM_NAME لمستخدمي English.pm).

إذا كنت تستدعي pod2usage() من وحدة نمطية وترغب في عرض وثائق POD الخاصة بتلك الوحدة، يمكنك استخدام هذا:

use Pod::Find qw(pod_where);
pod2usage( -input => pod_where({-inc => 1}, __PACKAGE__) );
"-pathlist" string
قائمة بمسارات الأدلة. إذا كان ملف الإدخال غير موجود، فسيتم البحث عنه في قائمة الأدلة المعطاة (بالترتيب الذي تظهر به الأدلة في القائمة). القيمة الافتراضية هي قائمة الأدلة المستمدة من $ENV{PATH}. يمكن تحديد القائمة إما عن طريق مرجع لمصفوفة، أو عن طريق سلسلة نصية من مسارات الأدلة التي تستخدم نفس فاصل المسار مثل $ENV{PATH} على نظامك (على سبيل المثال، ":" لـ Unix، ";" لـ MSWin32 و DOS).
"-noperldoc"
افتراضيًا، سيقوم Pod::Usage باستدعاء perldoc عندما تكون قيمة -verbose >= 2 محددة. هذا لا يعمل بشكل جيد، على سبيل المثال، إذا تم تعبئة البرنامج بـ PAR. هذا الخيار يمنع الاستدعاء الخارجي لـ perldoc ويستخدم منسق النص البسيط (Pod::Text) لطباعة POD.
"-perlcmd"
افتراضيًا، سيقوم Pod::Usage باستدعاء perldoc عندما تكون قيمة -verbose >= 2 محددة. في حالة تثبيتات Perl الخاصة أو غير العادية، يمكن استخدام هذا الخيار لتوفير المسار إلى قابل تنفيذي perl يجب أن يشغل perldoc.
"-perldoc" path-to-perldoc
افتراضيًا، سيقوم Pod::Usage باستدعاء perldoc عندما تكون قيمة -verbose >= 2 محددة. في حالة عدم تثبيت perldoc حيث يعتقد مفسر perl أنه موجود (انظر Config)، يمكن استخدام الخيار -perldoc لتوفير المسار الصحيح إلى perldoc.
"-perldocopt" string
افتراضيًا، سيقوم Pod::Usage باستدعاء perldoc عندما تكون قيمة -verbose >= 2 محددة. يمكن استخدام هذا الخيار لتوفير خيارات لـ perldoc. يمكن أن تحتوي السلسلة النصية على عدة خيارات مفصولة بمسافات.

الفئة الأساسية للتنسيق

منسق النص الافتراضي هو Pod::Text. يمكن تحديد الفئة الأساسية لـ Pod::Usage عن طريق تعيين $Pod::Usage::Formatter مسبقًا قبل تحميل Pod::Usage، على سبيل المثال:

BEGIN { $Pod::Usage::Formatter = 'Pod::Text::Termcap'; }
use Pod::Usage qw(pod2usage);

يستخدم Pod::Usage طريقة _handle_element_end() الخاصة بـ Pod::Simple لتنفيذ اختيار القسم، وفي حالة الإسهاب < 2 يقوم بتحويل العناوين المكتوبة بأحرف كبيرة بالكامل إلى الحرف الأول ثم بقية الأحرف الصغيرة، ويضيف نقطتين رأسيتين/سطرًا جديدًا في نهاية العناوين، لتحسين القراءة. نفس الشيء ينطبق على الإسهاب = 99.

DESCRIPTION

سيقوم pod2usage بطباعة رسالة استخدام للبرنامج النصي المستدعي (باستخدام وثائق pod المضمنة فيه) ثم إنهاء البرنامج النصي بحالة الخروج المطلوبة. قد تحتوي رسالة الاستخدام المطبوعة على أحد المستويات الثلاثة من "الإسهاب": إذا كان مستوى الإسهاب 0، فسيتم طباعة ملخص فقط. إذا كان مستوى الإسهاب

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

حافظ على هيكل الملف. إذا كانت قيمة vel تساوي 1، فسيتم طباعة الملخص ووصف (إن وجد) لمعلمات خيارات سطر الأوامر ومعاملاته. إذا كان مستوى التفصيل يساوي 2، فسيتم طباعة صفحة الدليل الكاملة. ما لم يتم تحديدها صراحةً، يتم تحديد القيم الافتراضية لحالة الخروج ومستوى التفصيل وتدفق الإخراج على النحو التالي: - إذا لم يتم تحديد أي من حالات الخروج أو مستوى التفصيل، فإن القيمة الافتراضية هي حالة خروج 2 مع مستوى تفصيل 0. - إذا تم تحديد حالة خروج ولكن لم يتم تحديد مستوى التفصيل، فسيتم تعيين مستوى التفصيل افتراضيًا إلى 1 إذا كانت حالة الخروج أقل من 2، وإلى 0 بخلاف ذلك. - إذا لم يتم تحديد حالة الخروج ولكن تم تحديد مستوى التفصيل، فسيتم تعيين حالة الخروج افتراضيًا إلى 2 إذا كان مستوى التفصيل 0، وإلى 1 بخلاف ذلك. - إذا كانت حالة الخروج المستخدمة أقل من 2، فسيتم طباعة الإخراج إلى STDOUT، وإلا فإلى STDERR. على الرغم من أن المحتوى أعلاه قد يبدو مربكًا بعض الشيء في البداية، إلا أنه يؤدي عمومًا إلى النتائج الصحيحة في معظم الحالات. يعتمد تحديد القيم الافتراضية هذا على اصطلاحات Unix النموذجية التالية: - تشير حالة الخروج 0 إلى "نجاح". على سبيل المثال، يخرج diff(1) بحالة خروج 0 إذا كان الملفان متطابقين في المحتوى. - تشير حالة الخروج 1 إلى إنهاء غير طبيعي للبرنامج ولكنه ليس معيبًا. على سبيل المثال، يخرج grep(1) بحالة خروج 1 إذا لم يعثر على سطر يطابق التعبير المنتظم المحدد. - تشير حالة الخروج 2 أو أكثر إلى خطأ فادح. على سبيل المثال، يخرج ls(1) بحالة خروج 2 إذا تم تحديد خيار غير صالح (غير موجود) في سطر الأوامر. - يجب توجيه رسائل الاستخدام الصادرة بسبب خطأ في بناء الجملة في سطر الأوامر إلى STDERR. ومع ذلك، يجب توجيه رسائل الاستخدام الصادرة بسبب طلب صريح لطباعة الاستخدام (مثل تحديد -help في سطر الأوامر) إلى STDOUT، في حال رغب المستخدم في تمرير الإخراج إلى عارض (مثل more(1)). - إذا طلب المستخدم صراحةً استخدام البرنامج، فغالبًا ما يكون من المرغوب الخروج بحالة خروج 1 (بدلاً من 0) بعد طباعة رسالة الاستخدام المطلوبة من قبل المستخدم. من المرغوب أيضًا تقديم وصف أكثر تفصيلاً لاستخدام البرنامج في هذه الحالة. لا تفرض pod2usage هذه الاصطلاحات عليك، ولكنها ستستخدم هذه القيم الافتراضية إذا لم تقدم إشعارًا صريحًا. تجعل قدرة pod2usage() على قبول رقم أو سلسلة نصية استخدامها كوظيفة معالجة أخطاء غير مؤذية: ```perl use strict; use Pod::Usage; use Getopt::Long; ## تحليل الخيارات my %opt; GetOptions(\%opt, "help|?", "man", "flag1") || pod2usage(2); pod2usage(1) if ($opt{help}); pod2usage(-exitval => 0, -verbose => 2) if ($opt{man}); ## تحقق من عدد كبير جدًا من أسماء الملفات pod2usage("$0: Too many files given.\n") if (@ARGV > 1); ``` قد يشعر بعض المستخدمين أن "اقتصاد التعبير" السابق ليس قابلاً للقراءة أو الاتساق بشكل خاص ويفضلون القيام بشيء أقرب إلى ما يلي: ```perl use strict; use Pod::Usage qw(pod2usage); use Getopt::Long qw(GetOptions); ## تحليل الخيارات my %opt; GetOptions(\%opt, "help|?", "man", "flag1") || pod2usage(-verbose => 0); pod2usage(-verbose => 1) if ($opt{help}); pod2usage(-verbose => 2) if ($opt{man}); ## تحقق من عدد كبير جدًا من أسماء الملفات pod2usage(-verbose => 2, -message => "$0: Too many files given.\n") if (@ARGV > 1); ``` كما هو الحال مع كل شيء في Perl، هناك أكثر من طريقة للقيام بذلك، وتتبع pod2usage() هذه الفلسفة. إذا كنت ترغب في رؤية عدد من الطرق المختلفة لاستدعاء pod2usage (على الرغم من أنها ليست شاملة)، فيرجى الرجوع إلى "أمثلة". ### نصوص برمجية يتضمن توزيع Pod::Usage نصًا برمجيًا يسمى pod2usage يوفر واجهة سطر أوامر لوظائف Pod::Usage. ارجع إلى pod2usage. ### أمثلة سيقوم كل استدعاء لـ pod2usage() التالي بطباعة قسم SYNOPSIS فقط إلى STDERR والخروج بحالة 2: ```perl pod2usage(); pod2usage(2); pod2usage(-verbose => 0); pod2usage(-exitval => 2); pod2usage({-exitval => 2, -output => \*STDERR}); pod2usage({-verbose => 0, -output => \*STDERR}); pod2usage(-exitval => 2, -verbose => 0); pod2usage(-exitval => 2, -verbose => 0, -output => \*STDERR); ``` سيقوم كل استدعاء لـ pod2usage() التالي بطباعة رسالة خطأ "Syntax error." (مع سطر جديد) إلى STDERR، متبوعة بقسم SYNOPSIS (مطبوع أيضًا إلى STDERR) وسيخرج بحالة 2: ```perl pod2usage("Syntax error."); pod2usage(-message => "Syntax error.", -verbose => 0); pod2usage(-msg => "Syntax error.", -exitval => 2); pod2usage({-msg => "Syntax error.", -exitval => 2, -output => \*STDERR}); pod2usage({-msg => "Syntax error.", -verbose => 0, -output => \*STDERR}); pod2usage(-msg => "Syntax error.", -exitval => 2, -verbose => 0); pod2usage(-message => "Syntax error.", -exitval => 2, -verbose => 0, -output => \*STDERR); ``` سيقوم كل استدعاء لـ pod2usage() التالي بطباعة قسم SYNOPSIS وأي أقسام خيارات أو معاملات إلى STDOUT والخروج بحالة 1: ```perl pod2usage(1); pod2usage(-verbose => 1); pod2usage(-exitval => 1); pod2usage({-exitval => 1, -output => \*STDOUT}); pod2usage({-verbose => 1, -output => \*STDOUT}); pod2usage(-exitval => 1, -verbose => 1); pod2usage(-exitval => 1, -verbose => 1, -output => \*STDOUT); ``` سيقوم كل استدعاء لـ pod2usage() التالي بطباعة صفحة الدليل الكاملة إلى STDOUT والخروج بحالة 1: ```perl pod2usage(-verbose => 2); pod2usage({-verbose => 2, -output => \*STDOUT}); pod2usage(-exitval => 1, -verbose => 2); pod2usage({-exitval => 1, -verbose => 2, -output => \*STDOUT}); ``` ### الاستخدام الموصى به يجب على النصوص البرمجية طباعة رسالة استخدام إلى STDERR عند وجود خطأ في بناء الجملة في سطر الأوامر. يجب عليها أيضًا توفير خيار (عادةً -H أو -help) لطباعة رسالة استخدام (ربما أكثر تفصيلاً) إلى STDOUT. قد تسمح بعض النصوص البرمجية حتى بطباعة وثائقها الكاملة إلى STDOUT (ربما عبر خيار -man). يستخدم المثال الكامل التالي Pod::Usage مع Getopt::Long للقيام بكل هذا: ```perl use strict; use Getopt::Long qw(GetOptions); use Pod::Usage qw(pod2usage); my $man = 0; my $help = 0; ## تحليل الخيارات وطباعة الاستخدام إذا كان هناك خطأ في بناء الجملة، ## أو إذا تم طلب الاستخدام صراحةً. GetOptions('help|?' => \$help, man => \$man) or pod2usage(2); pod2usage(1) if $help; pod2usage(-verbose => 2) if $man; ## إذا لم يتم تقديم أي معاملات، فسيتم السماح باستخدام STDIN فقط ## إذا لم يكن متصلاً بطرفية (وإلا فسيتم طباعة الاستخدام) pod2usage("$0: No files given.") if ((@ARGV == 0) && (-t STDIN)); __END__ =head1 NAME sample - Using GetOpt::Long and Pod::Usage =head1 SYNOPSIS sample [options] [file ...] Options: -help brief help message -man full documentation =head1 OPTIONS =over 4 =item B<-help> Prints a brief help message and exits. =item B<-man> Prints the manual page and exits. =back =head1 DESCRIPTION This program will read the given input file(s) and do something useful with the contents thereof. =cut ``` ### محاذير افتراضيًا، ستستخدم pod2usage() $0 كمسار لملف إدخال pod. لحسن الحظ، لا تقوم جميع الأنظمة التي تعمل عليها Perl بتعيين $0 بشكل صحيح (على الرغم من أنه إذا لم يتم العثور على $0، فستبحث pod2usage() في $ENV{PATH} أو القائمة المحددة بواسطة خيار -pathlist). إذا كان هذا هو الحال بالنسبة لنظامك، فقد تحتاج إلى تحديد المسار إلى مستندات pod للنص البرمجي المستدعى بشكل صريح باستخدام شيء مشابه لما يلي: ```perl pod2usage(-exitval => 2, -input => "/path/to/your/pod/docs"); ``` في الحالة الشاذة التي يتم فيها استدعاء نص برمجي باستخدام اسم مسار نسبي ويقوم النص البرمجي نفسه بتغيير الدليل الحالي (انظر "chdir" في perlfunc) قبل استدعاء pod2usage()، ستفشل Pod::Usage حتى على المنصات القوية. لا تفعل ذلك. أو استخدم FindBin لتحديد موقع النص البرمجي: ```perl use FindBin; pod2usage(-input => $FindBin::Bin . "/" . $FindBin::Script); ``` ### الدعم تتم إدارة هذه الوحدة في مستودع GitHub، https://github.com/Dual-Life/Pod-Usage يمكنك إجراء استنساخ والمساهمة، أو استنساخ وإرسال الإصلاحات! يرجى استخدام https://github.com/Dual-Life/Pod-Usage/issues/new للإبلاغ عن خطأ. نظام التذاكر السابق، https://rt.cpan.org/Dist/Display.html?Queue=Pod-Usage، قديم لهذا الحزمة. يجب توجيه الأسئلة العامة أو المناقشات حول POD إلى قائمة البريد "pod-people@perl.org". أرسل بريدًا إلكترونيًا فارغًا إلى "pod-people-subscribe@perl.org" للاشتراك. ### المؤلف Marek Rouchal <marekr@cpan.org> Nicolas R <nicolas@atoomic.org> Brad Appleton <bradapp@enteract.com> يعتمد هذا الكود على كود Pod::Text::pod2text() الذي كتبه Tom Christi ansen <tchrist@mox.perl.com>
