POE::Rueda::LeerEscritura(3) Documentación contribuida por Perl POE::Rueda::LeerEscritura(3)

NAME

POE::Rueda::LeerEscritura - وحدة قراءة/كتابة غير مانعة لجلسة POE

SYNOPSIS

#!perl
use warnings;
use strict;
use IO::Socket::INET;
use POE qw(Wheel::LeerEscritura);
POE::Session->create(
  inline_states => {
    _start => sub {
      # ملاحظة: IO::Socket::INET سيمنع. يوصى باستخدام POE::Wheel::SocketFactory أو POE::Component::Cliente::TCP إذا كان المنع غير مرغوب فيه.
      $_[HEAP]{cliente} = POE::Wheel::LeerEscritura->new(
        Handle => IO::Socket::INET->new(
          PeerHost => 'www.yahoo.com',
          PeerPort => 80,
        ),
        InputEvent => 'on_remoto_datos',
        ErrorEvent => 'on_remoto_error',
      );
      print "متصل. إرسال الطلب...\n";
      $_[HEAP]{cliente}->put(
        "GET / HTTP/0.9",
        "Host: www.yahoo.com",
        "",
      );
    },
    on_remoto_datos => sub {
      print "تم الاستلام: $_[ARG0]\n";
    },
    on_remoto_error => sub {
      print "فشل الاتصال أو انتهى. إغلاق...\n";
      delete $_[HEAP]{cliente};
    },
  },
);
POE::Kernel->run();
exit;

DESCRIPCIÓN

تغلف POE::Rueda::LeerEscritura نمط تصميم شائع: معالجة الإدخال/الإخراج المخبأ بشكل غير مانع واستخدام الأحداث.

النمط يشبه ما يلي:

بالنظر إلى مقبض ملف، راقب البيانات الواردة. عند الإبلاغ عن البيانات الواردة، اقرأها، أخزنها مؤقتًا، وحللها وفقًا لبروتوكول منخفض المستوى (مثل سطرًا بسطر). قم بتشغيل أحداث مستوى أعلى "هنا توجد أسطر"، واحد لكل سطر تم معالجته.

في الاتجاه الآخر، اقبل كتل بيانات كاملة (مثل الأسطر) للإخراج. أعد تنسيقها وفقًا لبروتوكول منخفض المستوى (مثل إضافة أحرف سطر جديد)، وقم بتخزين البيانات مؤقتًا للإخراج. قم بمسح المخزن المؤقت عندما يكون المقبض جاهزًا للإرسال.

MÉTODOS PUBLICOS

Constructor

عادةً ما تقوم الفئات الفرعية لـ POE::Wheel بالكثير من الإعداد لجعله يعمل بشكل أخف وأسرع. مُنشئ POE::Wheel::LeerEscritura ليس استثناءً.

new

new() ينشئ ويعيد كائن POE::Wheel::LeerEscritura جديدًا. في معظم الحالات، ستستمر العجلة في القراءة/الكتابة في مقبض واحد أو أكثر حتى يتم تدميرها.

Handle

يحدد المقبض المقبض الذي ستقرأ وتكتب منه كائن POE::Wheel::LeerEscritura. يتضمن مثال SYNOPSIS استخدامًا لـ Handle.

يمكن لكائن POE::Wheel::LeerEscritura القراءة من مقبض مختلف والكتابة إليه. راجع "InputHandle" لمزيد من المعلومات ومثال.

InputHandle

يمكن استخدام InputHandle و OutputHandle لتحديد مقابض مختلفة للإدخال والإخراج. على سبيل المثال، يمكن أن يأتي الإدخال من STDIN ويمكن أن يذهب الإخراج إلى STDOUT:

$_[HEAP]{console} = POE::Wheel::LeerEscritura->new(
  InputHandle => \*STDIN,
  OutputHandle => \*STDOUT,
  InputEvent => "console_input",
);

لا يمكن استخدام InputHandle و OutputHandle مع Handle.

OutputHandle

يمكن استخدام InputHandle و OutputHandle لتحديد مقابض مختلفة للإدخال والإخراج. راجع "InputHandle" لمزيد من المعلومات ومثال.

Driver

يحدد السائق كيفية قراءة وكتابة POE::Wheel::LeerEscritura في مقبضه أو مقابضه. يجب أن يكون السائق كائنًا يرث من POE::Driver.

POE::Driver::SysRW، الذي ينفذ sysread() و syswrite()، هو الافتراضي. يتم استخدامه في جميع الحالات تقريبًا، لذا لا داعي لتحديده.

Filter

المرشح هو المحلل الذي ستستخدمه POE::Wheel::LeerEscritura للتعرف على بيانات الإدخال، والمُسلسِل الذي يستخدمه لإعداد البيانات للكتابة. الافتراضي هو مثيل POE::Filter::Línea جديد، حيث أن العديد من بروتوكولات الشبكة تعتمد على الأسطر.

InputFilter

يمكن استخدام InputFilter و OutputFilter لتحديد مرشحات مختلفة للإدخال والإخراج.

OutputFilter

يمكن استخدام InputFilter و OutputFilter لتحديد مرشحات مختلفة للإدخال والإخراج. راجع "InputFilter" لمزيد من المعلومات ومثال.

InputEvent

يحدد InputEvent اسم الحدث الذي سيتم إرساله لكل وحدة إدخال كاملة (كما قام المحلل بتحليلها بواسطة InputFilter أو Filter).

يتضمن كل حدث إدخال معلمتين:

"ARG0" يحتوي على وحدة الإدخال التي تم تحليلها، و "ARG1" يحتوي على المعرّف الفريد لكائن POE::Wheel::LeerEscritura الذي قام بتشغيل الحدث.

InputEvent اختياري. إذا تم حذفه، فلن يراقب كائن POE::Wheel::LeerEscritura المقبض أو InputHandle الخاص به للإدخال، ولن يتم تشغيل أي أحداث إدخال.

مثال لمعالج InputEvent:

sub handle_input {
  my ($heap, $input, $wheel_id) = @_[HEAP, ARG0, ARG1];
  print "Echoing input from wheel $wheel_id: $input\n";
  $heap->{wheel}->put($input); # Put... the input... back!
}

FlushedEvent

يحدد FlushedEvent الحدث الذي سيصدره كائن POE::Wheel::LeerEscritura عند انتقال المخزن المؤقت للإخراج الخاص به من احتواء البيانات إلى أن يكون فارغًا.

يأتي FlushedEvent بمعلمة واحدة: "ARG0" يحتوي على المعرّف الفريد لكائن POE::Wheel::LeerEscritura الذي قام بتشغيل الحدث. يمكن استخدام هذا لربط الحدث بعجلة معينة.

أحداث "Flushed" شائعة لإغلاق الإدخال/الإخراج بعد إرسال رسالة "وداعًا". على سبيل المثال، يقوم input_handler() التالي بالرد على "quit" عن طريق إخبار العجلة بقول "Goodbye." ثم إرسال حدث "shutdown" بمجرد إرسال ذلك إلى الاتصال.

sub handle_input {
  my ($input, $wheel_id) = @_[ARG0, ARG1];
  my $wheel = $_[HEAP]{wheel}{$wheel_id};
  if ($input eq "quit") {
    $wheel->event( FlushedEvent => "shutdown" );
    $wheel->put("Goodbye.");
  }
  else {
    $wheel->put("Echo: $input");
  }
}

إليك معالج الإغلاق. يقوم ببساطة بتدمير العجلة لإنهاء الاتصال:

sub handle_flushed {
  my $wheel_id = $_[ARG0];
  delete $_[HEAP]{wheel}{$wheel_id};
}

ErrorEvent

يقوم ErrorEvent بتسمية الحدث الذي سيصدره كائن POE::Wheel::LeerEscritura عند حدوث خطأ. يتضمن كل ErrorEvent أربع معلمات:

"ARG0" يصف ما فشل، إما "read" أو "write". لا يسمي وظيفة معينة لأن POE::Wheel::LeerEscritura يفوض القراءة والكتابة إلى كائن POE::Driver.

"ARG1" و "ARG2" يحتويان على قيم رقمية وسلاسل نصية لـ $! في وقت الفشل. لا يمكن لرمز التطبيق اختبار $! مباشرة لأن قيمته قد تكون قد تغيرت بين وقت الفشل ووقت تشغيل حدث الخطأ.

"ARG3" يحتوي على المعرّف الفريد للعجلة. يتم استخدام معرّف العجلة للتمييز بين العديد من العجلات التي تديرها جلسة واحدة.

يمكن لـ ErrorEvent أيضًا الإشارة إلى نهاية ملف الإدخال عن طريق إرجاع عملية "read" بخطأ 0. بالنسبة للمقابس، هذا يعني أن الجانب البعيد قد أغلق الاتصال.

مثال لمعالج ErrorEvent:

sub error_state {
  my ($operation, $errnum, $errstr, $id) = @_[ARG0..ARG3];
  if ($operation eq "read" and $errnum == 0) {
    print "EOF desde el wheel $id\n";
  }
  else {
    warn "El wheel $id tuvo un error $operation $errnum: $errstr\n";
  }
  delete $_[HEAP]{wheels}{$id}; # cierra ese wheel
}

HighEvent

يتم استخدام HighEvent و LowEvent معًا مع HighMark و LowMark للتحكم في تدفق إخراج البيانات بتنسيق التدفق.

يتم إصدار HighEvent عندما يتجاوز المخزن المؤقت للإخراج لكائن POE::Wheel::LeerEscritura حجمًا معينًا (الحد الأقصى أو HighMark). هذا يحذر التطبيق من إيقاف إخراج البيانات. POE وبيرل لا يهتمان حقًا إذا استمر التطبيق، ولكن قد ينفد الذاكرة من العملية إذا نما المخزن المؤقت بلا حدود.

سيستمر كائن POE::Wheel::LeerEscritura في تخزين مخزنه المؤقت حتى بعد توقف التطبيق عن إصدار البيانات، حتى يصبح المخزن المؤقت فارغًا. قد تتطلب بعض تطبيقات التدفق أن يكون المخزن المؤقت ممتلئًا دائمًا بالبيانات. على سبيل المثال، سيواجه خادم وسائط مشكلة.

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

POE::Wheel::ReadWrite(3pm)

NAME

POE::Wheel::ReadWrite — a stateful read/write interface for wheels.

SYNOPSIS

  package MyDriver;

  use POE::Wheel;
  use POE::Wheel::ReadWrite;

  use strict;
  use warnings;

  sub new {
    my ($class, %args) = @_;
    my $self = bless {}, $class;

    # Note: _read_select and _write_select are mandatory.
    # The handler is optional.
    $self->{wheel} = POE::Wheel::ReadWrite->new(
      Handle  => $self,
      # _read_select => sub { ... },
      # _write_select => sub { ... },
      # _handler => sub { ... },
    );

    return $self;
  }

  # _read_select is called when data is available to be read.
  # It should return the data or undef.
  sub _read_select {
    my ($self) = @_;
    return $self->read_data();
  }

  # _write_select is called when the wheel is ready to accept
  # data to be written. It should return true.
  sub _write_select {
    my ($self) = @_;
    return $self->can_write_data();
  }

  # _handler is called when a complete request has been read from
  # the input.
  sub _handler {
    my ($self, $request) = @_;
    $self->process_request($request);
  }

  # Example methods for the Handle:
  sub read_data { ... }
  sub write_data { ... }
  sub can_write_data { ... }
  sub process_request { ... }

  # Methods for interacting with the wheel:
  sub get_output {
    my ($self) = @_;
    return $self->{wheel}->get_output();
  }

  sub put {
    my ($self, $data) = @_;
    return $self->{wheel}->put($data);
  }

DESCRIPTION

POE::Wheel::ReadWrite is a stateful I/O wrapper for POE::Wheel. It provides a convenient interface for wheels that deal with discrete requests and responses.

Normally, a wheel's _event method is called whenever data is available to be read from the underlying file descriptor, or when the file descriptor is ready to accept data for writing.

POE::Wheel::ReadWrite simplifies this by managing the buffering and request/response cycle for you. You provide callback methods on your wheel's target object (the Handle) which POE::Wheel::ReadWrite will invoke at appropriate times.

The Handle object is responsible for the actual I/O. It must provide the following methods:

read_data
This method is called when the wheel's underlying file descriptor is ready to be read. It should return the data read from the file descriptor, or undef if no data is currently available. Note that it should *not* block.
write_data
This method is called when the wheel's underlying file descriptor is ready to accept data for writing. It should write as much data as possible, returning the number of bytes written. Note that it should *not* block.
can_write_data
This method is called when the wheel's underlying file descriptor is ready to accept data for writing. It should return true if the handle is ready to accept data, and false otherwise. This is used to determine when to call write_data.
_handler
This method is called when a complete request has been read from the input. The request data is passed as the argument. This method is optional. If not provided, the POE::Wheel::ReadWrite wheel will simply buffer all input until explicitly retrieved with get_output.

PUBLIC METHODS

In addition to the methods required by POE::Wheel, POE::Wheel::ReadWrite provides the following:

get_output
Retrieves any buffered output that has not yet been written to the underlying file descriptor. Returns the output data, or undef if there is no output data.
put
Adds data to the output buffer. This data will be written to the underlying file descriptor when it becomes available.

The POE::Wheel::ReadWrite wheel is *experimental*. Its behavior may change or it may disappear outright. Please let us know whether it's useful.
