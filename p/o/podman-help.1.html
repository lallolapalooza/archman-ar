podman-help(1)

الحزمة: podman

التراخيص: Apache-2.0

>

يمكن أيضًا إدارة معلومات الاتصال باستخدام ملف containers.conf.

رموز الخروج

يمنح رمز الخروج من podman معلومات حول سبب فشل الحاوية في التشغيل أو سبب خروجها. عندما تنتهي أوامر podman برمز غير صفري، تتبع رموز الخروج معيار chroot، انظر أدناه:

125 الخطأ يتعلق بـ podman نفسه

$ podman run --foo busybox; echo $?
Error: unknown flag: --foo
125

126 تنفيذ أمر حاوية و الأمر لا يمكن استدعاؤه

$ podman run busybox /etc; echo $?
Error: container_linux.go:346: starting container process caused "exec: \"/etc\": permission denied": OCI runtime error
126

127 تنفيذ أمر حاوية و الأمر لا يمكن العثور عليه

$ podman run busybox foo; echo $?
Error: container_linux.go:346: starting container process caused "exec: \"foo\": executable file not found in $PATH": OCI runtime error
127

رمز الخروج بخلاف ذلك، يعيد podman رمز الخروج الخاص بـ أمر الحاوية

$ podman run busybox /bin/sh -c 'exit 3'; echo $?
3

ملفات التكوين

containers.conf (/usr/share/containers/containers.conf, /etc/containers/containers.conf, $HOME/.config/containers/containers.conf)

يحتوي Podman على إعدادات افتراضية مدمجة لخيارات سطر الأوامر. يمكن تجاوز هذه الإعدادات الافتراضية باستخدام ملفات تكوين containers.conf.

تقوم التوزيعات بتوفير ملف /usr/share/containers/containers.conf بالإعدادات الافتراضية الخاصة بها. يمكن للمسؤولين تجاوز الحقول في هذا الملف عن طريق إنشاء ملف /etc/containers/containers.conf. يمكن للمستخدمين تعديل الإعدادات الافتراضية بشكل أكبر عن طريق إنشاء ملف $HOME/.config/containers/containers.conf. يدمج Podman الإعدادات الافتراضية المدمجة مع الحقول المحددة من هذه الملفات، إذا كانت موجودة. الحقول المحددة في ملف المستخدم تتجاوز ملف المسؤول، والذي يتجاوز ملف التوزيع، والذي يتجاوز الإعدادات الافتراضية المدمجة.

يستخدم Podman الإعدادات الافتراضية المدمجة إذا لم يتم العثور على أي ملف containers.conf.

إذا تم تعيين متغير البيئة CONTAINERS_CONF، فسيتم استخدام قيمته لملف containers.conf بدلاً من القيمة الافتراضية.

mounts.conf (/usr/share/containers/mounts.conf)

يحدد ملف mounts.conf مجلدات تحميل وحدات التخزين التي يتم تحميلها تلقائيًا داخل الحاويات عند تنفيذ أوامر podman run أو podman start. يمكن للمسؤولين تجاوز ملف الإعدادات الافتراضية عن طريق إنشاء /etc/containers/mounts.conf.

عند تشغيل Podman في وضع بدون جذر (rootless)، يتجاوز الملف $HOME/.config/containers/mounts.conf الإعدادات الافتراضية إذا كان موجودًا. للتفاصيل، انظر containers-mounts.conf(5).

policy.json (/etc/containers/policy.json, $HOME/.config/containers/policy.json)

تُستخدم ملفات سياسة التحقق من التوقيع لتحديد السياسة، على سبيل المثال، المفاتيح الموثوق بها، والتي تنطبق عند تحديد ما إذا كان سيتم قبول صورة، أو توقيعات فردية لتلك الصورة، كصالح. للتفاصيل، انظر containers-policy.json(5).

registries.conf (/etc/containers/registries.conf, $HOME/.config/containers/registries.conf)

registries.conf هو ملف التكوين الذي يحدد سجلات الحاويات التي يتم استشارتها عند إكمال أسماء الصور التي لا تتضمن جزء السجل أو النطاق.

يمكن لمستخدمي Podman غير الجذر إنشاء ملف $HOME/.config/containers/registries.conf لاستخدامه بدلاً من الإعدادات الافتراضية للنظام.

إذا تم تعيين متغير البيئة CONTAINERS_REGISTRIES_CONF، فسيتم استخدام قيمته لملف registries.conf بدلاً من القيمة الافتراضية.

storage.conf (/etc/containers/storage.conf, $HOME/.config/containers/storage.conf)

storage.conf هو ملف تكوين التخزين لجميع الأدوات التي تستخدم containers/storage.

يحدد ملف تكوين التخزين جميع خيارات تخزين الحاويات المتاحة للأدوات التي تستخدم تخزين الحاويات المشترك.

عند تشغيل Podman في وضع بدون جذر (rootless)، يتم استخدام الملف $HOME/.config/containers/storage.conf بدلاً من الإعدادات الافتراضية للنظام.

إذا تم تعيين متغير البيئة CONTAINERS_STORAGE_CONF، فسيتم استخدام قيمته لملف storage.conf بدلاً من القيمة الافتراضية.
