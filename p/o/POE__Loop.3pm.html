NAME

POE::Loop — an event loop interface.

SYNOPSIS

This module is intended for use as a base class.

    package My::Event::Loop;

    use base 'POE::Loop';

    sub new { ... }
    sub pause { ... }
    sub run { ... }
    sub stop { ... }
    sub yield { ... }

    # ... and so on.

DESCRIPTION

POE::Loop is a base class for creating POE event loops. It defines the methods that POE expects an event loop to have.

A POE event loop is responsible for handling and dispatching events. It is the heart of a POE-based application.

POE will look for a suitable event loop at startup time. If you have installed a module that provides an event loop (e.g. POE::Loop::Poll or POE::Loop::Select), POE will use it. Otherwise, it will fall back to its default event loop.

GENERAL NOTES

POE's event loop is an abstract interface. Implementations of this interface are expected to perform event loop operations such as running, stopping, yielding, and pausing.

Event loop implementations should aim to be as efficient as possible. POE relies heavily on the performance of its event loop.

PUBLIC INTERFACE

new
pause
run
stop
yield

This module does not expose a public interface beyond the standard methods expected of an event loop. Please refer to the POE documentation for details on these methods.

HOW POE FINDS EVENT LOOP BRIDGES

When POE starts, it consults the value of the $POE::Loop::Default variable. If this variable is set to an event loop class name, POE will attempt to use that class.

If $POE::Loop::Default is not set, POE will search for installed event loop modules in a predefined order. The first one found will be used.

The search order is as follows:

  1. POE::Loop::Poll
  2. POE::Loop::Select
  3. POE::Loop::Wheel (if available)

If none of these are found, POE will use its built-in default event loop.

You can explicitly specify an event loop class when starting POE:

    POE::Kernel->runall( Loop => 'My::Event::Loop' );
