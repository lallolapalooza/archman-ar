الحزمة: podman

التراخيص: Apache-2.0

NAME

podman-container-restore – Restore a container from a checkpoint

SYNOPSIS

podman container restore [OPTION…] [CONTAINER…]

DESCRIPTION

The podman container restore command restores one or more containers from a checkpoint. The checkpoint can be either a directory or a tar archive.

If the checkpoint is a directory, it is assumed to be a criu pre-dump directory. If the checkpoint is a tar archive, it is assumed to be created by `podman container checkpoint --export`.

A container can be restored in two ways:

podman container restore --import=FILE CONTAINER

This will restore the container CONTAINER from the checkpoint file FILE. The checkpoint file must be a tar archive created using podman container checkpoint --export.

podman container restore --import-previous=PRE_FILE --import=FILE CONTAINER

This will restore the container CONTAINER using two checkpoint files. PRE_FILE is a criu pre-dump directory, and FILE is the checkpoint tar archive.

If the CONTAINER is not specified, then the checkpoint must be a tar archive and it will be restored as a new container.

If the CONTAINER is specified, it can be either a container name or ID. If the container is already running, it will be stopped before being restored.

The restore operation requires the criu tool to be installed.

OPTIONS

When restoring from a checkpoint tar archive created by podman container checkpoint --export:

-i, --import=FILE
Path to the checkpoint tar archive to restore from.
-p, --import-previous=PRE_FILE
Path to the previous checkpoint directory (pre-dump).
-n, --name=NAME
Assign a name to the restored container. This option can only be used when restoring from a checkpoint tar archive without specifying a container name or ID.
-P, --publish=HOST_PORT:CONTAINER_PORT
Publish a container’s network ports to the host. This option can only be used when restoring from a checkpoint tar archive without specifying a container name or ID.
-e, --env=VARIABLE=VALUE
Set environment variables inside the restored container. This option can only be used when restoring from a checkpoint tar archive without specifying a container name or ID.
-l, --live-restore
Perform a live restore. This option is only supported when restoring from a checkpoint tar archive created with podman container checkpoint --live-restore.
-L, --leave-running
Do not stop the container after creating the checkpoint. This option can only be used when restoring from a checkpoint tar archive without specifying a container name or ID.
-h, --help
Print usage statement.

When restoring from a criu pre-dump directory:

-i, --import=FILE
Path to the checkpoint tar archive to restore from.
-p, --import-previous=PRE_FILE
Path to the criu pre-dump directory.
-C, --cpu-share=WEIGHT
CPU shares (relative weight). Default is 1024.
-M, --memory=MAX_MEMORY
Memory limit. Default is unlimited.
-N, --network=NETWORK
Join a network. Default is bridge.
-p, --publish=HOST_PORT:CONTAINER_PORT
Publish a container’s network ports to the host. Default is to preserve original TCP connections.

The default is false.

EXAMPLES

Restore the container "mywebserver".

# podman container restore mywebserver

Import a checkpoint file and a pre-checkpoint file.

# podman container restore --import-previous pre-checkpoint.tar.gz --import checkpoint.tar.gz

Start the container "mywebserver". Make a checkpoint of the container and export it. Restore the container with other port ranges from the exported file.

$ podman run --rm -p 2345:80 -d webserver
# podman container checkpoint -l --export=dump.tar
# podman container restore -p 5432:8080 --import=dump.tar

Start a container with the name "foobar-1". Create a checkpoint image "foobar-checkpoint". Restore the container from the checkpoint image with a different name.

# podman run --name foobar-1 -d webserver
# podman container checkpoint --create-image foobar-checkpoint foobar-1
# podman inspect foobar-checkpoint
# podman container restore --name foobar-2 foobar-checkpoint
# podman container restore --name foobar-3 foobar-checkpoint
