Template Toolkit Views

كان أحد دوافع كتابة هذه الوحدة هو تسهيل تخصيص وثائق Pod لمظهرك وملمسك الخاص أو لاتفاقيات التنسيق المحلية. من خلال الفصل الواضح بين المحتوى (الممثل بنموذج كائن Pod) وأسلوب العرض (الممثل بواسطة واحد أو أكثر من طرق العرض) يصبح تحقيق ذلك أسهل بكثير.

أحدث إصدار من Template Toolkit (2.06 في وقت الكتابة) يوفر مكونًا إضافيًا لـ Pod للتفاعل مع هذه الوحدة. كما أنه يطبق توجيه VIEW جديدًا (ولكنه تجريبي) يمكن استخدامه لبناء أنماط عرض مختلفة لتحويل Pod إلى تنسيقات أخرى. Template Toolkit متاح من CPAN:

http://www.cpan.org/modules/by-module/Template/

طرق عرض Template Toolkit مشابهة لكائنات Pod::POM::View الموضحة أعلاه، باستثناء أنها تسمح بكتابة أسلوب العرض لكل مكون Pod كملف قالب أو كتلة بدلاً من تابع كائن. الصيغة والبنية الدقيقة لتوجيه VIEW تخضع للتغيير (نظرًا لأنها لا تزال تجريبية)، ولكن في الوقت الحالي يمكن استخدامها لتعريف طريقة عرض تشبه:

[% VIEW myview %]
   [% BLOCK view_head1 %]
      <h1>[% item.title.present(view) %]</h1>
      [% item.content.present(view) %]
   [% END %]

   [% BLOCK view_head2 %]
      <h2>[% item.title.present(view) %]</h2>
      [% item.content.present(view) %]
   [% END %]
   ...
[% END %]

يتم توفير مكون إضافي للتفاعل مع وحدة Pod::POM:

[% USE pod %]
[% pom = pod.parse('/path/to/podfile') %]

يمكن بعد ذلك التنقل في مثيل نموذج كائن Pod الذي تم إرجاعه وعرضه عبر طريقة العرض بأي طريقة يمكن تخيلها تقريبًا:

<h1>Table of Contents</h1>
<ul>
[% FOREACH section = pom.head1 %]
   <li>[% section.title.present(view) %]
[% END %]
</ul>
<hr>
[% FOREACH section = pom.head1 %]
   [% section.present(myview) %]
[% END %]

يمكنك إما تمرير مرجع إلى VIEW (myview) إلى التابع present() لعقدة Pod::POM:

[% pom.present(myview) %]       # present entire document

أو بدلاً من ذلك استدعاء التابع print() على VIEW، وتمرير عقدة Pod::POM كوسيط:

[% myview.print(pom) %]

داخليًا، تقوم طريقة العرض باستدعاء التابع present() على العقدة، وتمرير نفسها كوسيط. وبالتالي فهي مكافئة للمثال السابق.

تتعاون عقدة Pod::POM وطريقة العرض لـ "القيام بالشيء الصحيح" لمعالجة كتلة القالب الصحيحة للعقدة. مرجع إلى العقدة متاح داخل القالب كمتغير 'item'.

[% BLOCK view_head2 %]
   <h2>[% item.title.present(view) %]</h2>
   [% item.content.present(view) %]
[% END %]

تحتوي وثائق Template Toolkit على مزيد من المعلومات حول تعريف واستخدام طرق العرض. ومع ذلك، كما هو مذكور أعلاه، قد يخضع هذا للتغيير أو يكون غير مكتمل بانتظار المزيد من التطوير لتوجيه VIEW.

METHODS

new(\%config)

تابع البناء الذي يقوم بإنشاء وإرجاع كائن محلل Pod::POM جديد.

use Pod::POM;
my $parser = Pod::POM->new();

يمكن تمرير مرجع إلى تجزئة مصفوفة من خيارات التكوين كوسيط.

my $parser = Pod::POM->new( { warn => 1 } );

للراحة، يمكن أيضًا تمرير خيارات التكوين كقائمة من أزواج (مفتاح => قيمة).

my $parser = Pod::POM->new( warn => 1 );

خيارات التكوين التالية معرفة:

code
يمكن تعيين هذا الخيار لتخزين جميع الأجزاء غير Pod في المستند المدخل ضمن نموذج الكائن كعناصر 'code'، ممثلة بكائنات من فئة Pod::POM::Node::Code. إنه معطل افتراضيًا ويتم تجاهل أقسام الكود. 
my $parser = Pod::POM->new( code => 1 );
my $podpom = $parser->parse(\*DATA);
foreach my $code ($podpom->code()) {
    print "<pre>$code</pre>\n";
}
__DATA__
This is some program code.
=head1 NAME
...

سيؤدي هذا إلى إنشاء الإخراج:

<pre>This is some program code.</pre>

لاحظ أن عناصر الكود مخزنة داخل عنصر POM الذي تم العثور عليها فيه. على سبيل المثال، عنصر الكود أدناه المضمن بين أقسام Pod يتم تخزينه في المصفوفة التي يمكن استردادها عن طريق استدعاء "$podpom->head1->[0]->code()".

=head1 NAME
My::Module::Name;
=cut
Some program code embedded in Pod.
=head1 SYNOPSIS
...
warn
يتم تخزين التحذيرات غير القاتلة التي تم العثور عليها أثناء تحليل مستند Pod داخليًا وتصبح متاحة لاحقًا عبر التابع warnings(). 
my $parser = Pod::POM->new();
my $podpom = $parser->parse_file($filename);
foreach my $warning ($parser->warnings()) {
    warn $warning, "\n";
}

يمكن تعيين خيار 'warn' لرفع التحذيرات تلقائيًا عبر warn() عند اكتشافها.

my $parser = Pod::POM->new( warn => 1 );
my $podpom = $parser->parse_file($filename);

إذا تم تحديد قيمة التكوين كمرجع لروتين فرعي، فسيتم استدعاء الكود في كل مرة يتم فيها رفع تحذير، وتمرير رسالة التحذير كوسيط.

sub my_warning {
    my $msg = shift;
    warn $msg, "\n";
};
my $parser = Pod::POM->new( warn => \&my_warning );
my $podpom = $parser->parse_file($filename);
meta
يمكن تعيين خيار 'meta' للسماح بعلامات "=meta" داخل مستند Pod. 
my $parser = Pod::POM->new( meta => 1 );
my $podpom = $parser->parse_file($filename);

هذه ميزة تجريبية ليست جزءًا من POD القياسي. على سبيل المثال:

=meta author Andy Wardley

تتاح هذه كعناصر بيانات وصفية داخل العقدة الجذرية لـ POM المحلل.

my $author = $podpom->metadata('author');

انظر قسم METADATA أدناه لمزيد من المعلومات.

parse_file($file)

يقوم بتحليل الملف المحدد بالاسم أو المرجع إلى مقبض ملف. يعيد مرجعًا إلى كائن Pod::POM::Node::Pod الذي يمثل العقدة الجذرية لنموذج كائن Pod عند النجاح. عند حدوث خطأ، يتم إرجاع undef ويمكن استرداد رسالة الخطأ التي تم إنشاؤها عن طريق استدعاء error().

my $podpom = $parser->parse_file($filename)
    || die $parser->error();
my $podpom = $parser->parse_file(\*STDIN)
    || die $parser->error();

يمكن فحص أي تحذيرات تم العثور عليها عن طريق استدعاء التابع warnings().

foreach my $warn ($parser->warnings()) {
    warn $warn, "\n";
}

parse_text($text)

يقوم بتحليل سلسلة نص Pod المارة كوسيط إلى نموذج كائن Pod، كما هو الحال في parse_file().

parse($text_or_$file)

تابع عام الغرض يحاول القيام بالشيء الصحيح في استدعاء parse_file() أو parse_text() وفقًا للوسيط المار.

يمكن تمرير مرجع تجزئة كوسيط يحتوي على مفتاح 'text' أو 'file' والقيمة المقابلة.

my $podpom = $parser->parse({ file => $filename })
    || die $parser->error();

بخلاف ذلك، يمكن أن يكون الوسيط مرجعًا إلى مقبض إدخال يتم تمريره إلى parse_file().

my $podpom = $parser->parse(\*DATA)
    || die $parser->error();

إذا كان الوسيط عبارة عن سلسلة نصية تبدو كنص Pod (أي أنها تحتوي على '=' في بداية أي سطر) فسيتم تمريرها إلى parse_text().

my $podpom = $parser->parse($podtext)
    || die $parser->error();

بخلاف ذلك، يُفترض أنه اسم ملف ويتم تمريره إلى parse_file().

my $podpom = $parser->parse($podfile)
    || die $parser->error();

NODE TYPES, ATTRIBUTES AND ELEMENTS

يسرد هذا القسم العقد المختلفة التي قد تكون موجودة في نموذج كائن Pod. يتم تنفيذ هذه كنسخ كائنات Pod::POM::Node::* (على سبيل المثال، head1 => Pod::POM::Node::Head1). لعرض عقدة، يجب أن تطبق طريقة العرض تابعًا يتوافق مع اسم العقدة مسبوقًا بـ 'view_' (على سبيل المثال، head1 => view_head1()).
