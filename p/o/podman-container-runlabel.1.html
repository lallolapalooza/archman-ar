NAME

podman-container-runlabel — Run a container based on a label

SYNOPSIS

podman container runlabel [options] label [command [arg ...]]

DESCRIPTION

The podman container runlabel command runs a container based on a label that has been set on one or more containers. The command finds containers that have the specified label and then runs a new container based on the image and configuration of the first container found.

This command is useful for starting a new instance of a container that has specific configurations or environment variables set via labels.

VARIABLES

The following environment variables are available:

  • PULL_POLICY: Controls when Podman pulls images. Valid values are always, missing, never. Defaults to missing.

OPTIONS

--annotation, -a key=value
Add an annotation to the container. This option can be used multiple times.
--arch architecture
Run container for a specific architecture.
--blkio-weight weight
Block I/O (Blkio) weight (10-1000). Default is 0 (means disabled).
--cap-add capability
Add Linux capabilities to the container. This option can be used multiple times.
--cap-drop capability
Drop Linux capabilities from the container. This option can be used multiple times.
--cgroup-manager cgroup-manager
The cgroup manager to use. Valid values are cgroupfs and systemd.
--cpu-period cpu-period
Limit the CPU usage of the container. Default is 0 (no limit).
--cpu-quota cpu-quota
Limit the CPU usage of the container. Default is 0 (no limit).
--cpu-shares cpu-shares
CPU shares (relative weight). Default is 0 (no limit).
--cpuset-cpus cpus
Limit the allowed CPUs of the container.
--cpuset-mems mems
Limit the allowed memory nodes of the container.
--device device
Add a device to the container. This option can be used multiple times.
--dns dns
Set up custom DNS entries. This option can be used multiple times.
--dns-opt dns-opt
Set DNS options. This option can be used multiple times.
--dns-search dns-search
Set DNS search domains. This option can be used multiple times.
--entrypoint entrypoint
Override the default entrypoint of the image.
--env, -e variable
Set environment variables in the container. This option can be used multiple times.
--env-file file
Read in a file line-by-line to set environment variables.
--group, -g group
Run container in a specific group.
--health-cmd string
The command to run to check the container's health.
--health-interval duration
Time between health checks. Format: `( N(h|m|s) )`. Default: 30s.
--health-retries non-negative integer
Number of consecutive failures before the container is marked unhealthy. Default: 3.
--health-timeout duration
Time to wait for a health check to succeed. Format: `( N(h|m|s) )`. Default: 0s.
--host
Run the container in host mode. This means the container shares the host's network stack and other resources.
--hostname hostname
Set the container's hostname.
--idmap-gid map
Map GIDs from the container to the host. Format: `container_id:container_gid:host_gid`.
--idmap-uid map
Map UIDs from the container to the host. Format: `container_id:container_uid:host_uid`.
--init
Run an init process inside the container that forwards signals and reaps processes.
--ip ip
Specify the container's IP address.
--ip6 ip6
Specify the container's IPv6 address.
--kernel-memory limit
Kernel memory limit.
--label, -l key=value
Set metadata on the container. This option can be used multiple times.
--label-file file
Read in a file line-by-line to set labels.
--latency-sec duration
Deprecated. Use --health-timeout instead.
--link-local-ip ip
Assign metadata in the form of IP addresses that will be advertised when this container is discovered via documentation.
--log-driver driver
Logging driver for the container. (e.g., json-file, journald, syslog)
--log-opt key=value
Logging driver options.
--mac-address mac
Specify a MAC address for the container.
--memory, -m limit
Memory limit.
--memory-reservation limit
Memory reservation.
--memory-swap limit
Total memory (memory + swap).
--mount type=type[,source=source][,destination=destination][,options]
Attach a filesystem mount to the container.
--name name
Assign a name to the container.
--network, -net network
Connect to a network. Default: none.
--no-healthcheck
Disable healthcheck for the container.
--oom-score-adj adj
Tune the container's OOM score.
--os operating system
Run container for a specific operating system.
--pid pid
PID setting for the container. Valid values are private and host.
--platform platform
Run container for a specific platform.
--privileged
Give extended privileges to the container.
--pull policy
Set the image pull policy. Valid values are always, missing, never. Default: missing.
--read-only
Mount the container's root filesystem as read-only.
--restart policy
Restart policy for the container. Valid values are no, on-failure, always, unless-stopped.
--rm
Automatically remove the container when it exits.
--security-opt option
Security option for the container. This option can be used multiple times.
--stop-signal signal
Signal to stop the container.
--stop-timeout seconds
Optional timeout in seconds to stop the container.
--sysctl ctl
Set kernel parameters for the container. This option can be used multiple times.
--tmpfs tmpfs
Mount a temporary filesystem into the container. This option can be used multiple times.
--tz timezone
Set the timezone for the container. For example, America/New_York.
--ulimit ulimit
Ulimit options. This option can be used multiple times.
--user, -u user
Run container in as specified user. Default: root.
--uts uts
Set up a custom UTS namespace. The format is <host-name>[:<domain-name>].
--variant variant
Run container for a specific variant.
--volumes-from container
Mount volumes from the specified container(s).
--workdir, -w dir
Working directory inside the container.

EXAMPLES

Run a container based on the container with the label com.example.my-app:

$ podman container runlabel com.example.my-app

Run a container based on the container with the label com.example.my-app and override the entrypoint:

$ podman container runlabel --entrypoint /bin/bash com.example.my-app

Run a container based on the container with the label com.example.my-app and set an environment variable:

$ podman container runlabel -e MY_VAR=my_value com.example.my-app
