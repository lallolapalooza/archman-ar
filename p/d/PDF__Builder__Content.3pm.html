linejoin, line_join

$content->linejoin($style)
Sets the style of join to be used at corners of a path (within a multisegment polyline).

Alternate name: "line_join"

This is provided for compatibility with PDF::API2.

"miter" or "m" or 0 = Miter Join, default
The outer edges of the strokes extend until they meet, up to the limit specified by miterlimit. If the limit would be surpassed, a bevel join is used instead. For a given linewidth, the more acute the angle is (closer to 0 degrees), the higher the ratio of miter length to linewidth will be, and that's what miterlimit controls -- a very "pointy" join is replaced by a bevel.
"round" or "r" or 1 = Round Join
A filled circle with a diameter equal to the linewidth is drawn around the corner point, producing a rounded corner. The arc will meet up with the sides of the line in a smooth tangent.
"bevel" or "b" or 2 = Bevel Join
A filled triangle is drawn to fill in the notch between the two strokes.

If no $style is given, the current setting is returned. If the style is being set, $self is returned so that calls may be chained.

Either a number or a string (case-insensitive) may be given.

miterlimit, miter_limit

$content->miterlimit($ratio)
Sets the miter limit when the line join style is a miter join.

The ratio is the maximum length of the miter (inner to outer corner) divided by the line width. Any miter above this ratio will be converted to a bevel join. The practical effect is that lines meeting at shallow angles are chopped off instead of producing long pointed corners.

The default miter limit is 10.0 (approximately 11.5 degree cutoff angle). The smaller the limit, the larger the cutoff angle.

If no $ratio is given, the current setting is returned. If the ratio is being set, $self is returned so that calls may be chained.

Alternate name: "miter_limit"

This is provided for compatibility with PDF::API2. Long ago, in a distant galaxy, this method was misnamed meterlimit, but that was removed a while ago. Any code using that name should be updated!

linedash, line_dash_pattern

$content->linedash()
$content->linedash($length)
$content->linedash($dash_length, $gap_length, ...)
$content->linedash('pattern' => [$dash_length, $gap_length, ...], 'shift' => $offset)
Sets the line dash pattern.

If called without any arguments, a solid line will be drawn.

If called with one argument, the dashes and gaps (strokes and spaces) will have equal lengths.

If called with two or more arguments, the arguments represent alternating dash and gap lengths.

If called with a hash of arguments, the pattern array may have one or more elements, specifying the dash and gap lengths. A dash phase may be set (shift), which is a positive integer specifying the distance into the pattern at which to start the dashed line. Note that if you wish to give a shift amount, using "shift", you need to use "pattern" instead of one or two elements.

If an odd number of dash array elements are given, the list is repeated by the reader software to form an even number of elements (pairs).

If a single argument of -1 is given, the current setting is returned. This is an array consisting of two elements: an anonymous array containing the dash pattern (default: empty), and the shift (offset) amount (default: 0). It may be used directly in a linedash() call, as linedash will recognize the special pattern [ array, number ].

If the dash pattern is being set, $self is returned so that calls may be chained.

Alternate name: "line_dash_pattern"

This is provided for compatibility with PDF::API2.

flatness, flatness_tolerance

$content->flatness($tolerance)
(Advanced) Sets the maximum variation in output pixels when drawing curves. The defined range of $tolerance is 0 to 100, with 0 meaning use the device default flatness. According to the PDF specification, you should not try to force visible line segments (the curve's approximation); results will be unpredictable. Usually, results for different flatness settings will be indistinguishable to the eye.

The $tolerance value is silently clamped to be between 0 and 100.

If no $tolerance is given, the current setting is returned. If the tolerance is being set, $self is returned so that calls may be chained.

Alternate name: "flatness_tolerance"

This is provided for compatibility with PDF::API2.

Path Construction (Drawing)

move

$content->move($x,$y)
Starts a new path at the specified coordinates. Note that multiple x,y pairs can be given, although this isn't that useful (only the last pair would have an effect).

close

$content->close()
Closes and ends the current path by extending a line from the current position to the starting position.

Straight line constructs

Note: None of these will actually be visible until you call "stroke", "fill", or "fillstroke". They are merely setting up the path to draw.

line

$content->line($x,$y)
$content->line($x,$y, $x2,$y2,...)
Extends the path in a line from the current coordinates to the specified coordinates, and updates the current position to be the new coordinates.

Multiple additional "[$x,$y]" pairs are permitted, to draw joined multiple line segments. Note that this is not equivalent to a polyline (see "poly"), because the first "[$x,$y]" pair in a polyline is a move operation. Also, the "linecap" setting will be used rather than the "linejoin" setting for treating the ends of segments.

hline, vline

$content->hline($x)
$content->vline($y)
Shortcuts for drawing horizontal and vertical lines from the current position. They are like line(), but to the new x and current y ("hline"), or to the the current x and new y ("vline").

polyline

$content->polyline($x1,$y1, ..., $xn,$yn)
This is a shortcut for creating a polyline path from the current position. It extends the path in line segments along the specified coordinates. The current position is changed to the last "[$x,$y]" pair given.

A critical distinction between the "polyline" method and the "poly" method is that in this ("polyline"), the first pair of coordinates are treated as a draw order (unlike the move order in "poly").

Thus, while this is provided for compatibility with PDF::API2, it is not really an alias or alternate name for "poly"!

poly

$content->poly($x1,$y1, ..., $xn,$yn)
This is a shortcut for creating a polyline path. It moves to "[$x1,$y1]", and then extends the path in line segments along the specified coordinates. The current position is changed to the last "[$x,$y]" pair given.

The difference between a polyline and a "line" with multiple "[$x,$y]" pairs is that the first pair in a polyline are a move, while in a line they are a draw. Also, "line_join" instead of "line_cap" is used to control the appearance of the ends of line segments.

A critical distinction between the "polyline" method and the "poly" method is that in this ("poly"), the first pair of coordinates are treated as a move order.

rectangle

$content = $content->rectangle($x1, $y1, $x2, $y2)
Creates a new rectangle-shaped path, between the two corner points "[$x1, $y1]" and "[$x2, $y2]". The corner points are swapped if necessary, to make "1" the lower left and "2" the upper right (x2 > x1 and y2 > y1). The object (here, $content) is returned, to permit chaining.

Note that this is not an alias or alternate name for "rect". It handles only one rectangle, and takes corner coordinates for corner "2", rather than the width and height.

rect

$content = $content->rect($x,$y, $w,$h)
$content = $content->rect($x1,$y1, $w1,$h1, ..., $xn,$yn, $wn,$hn)
This creates paths for one or more rectangles, with their lower left points at "[$x,$y]" and specified widths (+x direction) and heights (+y direction). Negative widths and heights are permitted, which draw to the left (-x) and below (-y) the given corner point, respectively. rectxy

$content->rectxy($x1,$y1, $x2,$y2)
ينشئ هذا مسارًا مستطيلًا، مع تحديد "[$x1,$y1]" و "[$x2,$y2]" **بالزوايا المقابلة**. يمكن أن تكون هذه الزاوية السفلية اليسرى والعلوية اليمنى، **أو** الزاوية العلوية اليسرى والسفلية اليمنى، بأي ترتيب، طالما أنها متقابلة قطريًا. يتغير الموضع الحالي إلى الزوج (الأول) "[$x1,$y1]".

هذا ليس مجرد اسم مستعار أو اسم بديل للدالة "rectangle"، لأنه يسمح بتحديد نقاط الزاوية بأي ترتيب.

إنشاءات الخطوط المنحنية

ملاحظة: لن تكون أي من هذه العناصر **مرئية** بالفعل حتى تستدعي "stroke" أو "fill" أو "fillstroke". إنها تقوم فقط بإعداد المسار للرسم.

circle

$content->circle($xc,$yc, $radius)
ينشئ هذا مسارًا دائريًا مركزه "[$xc,$yc]" بنصف القطر المحدد. **لا** يغير هذا الموضع الحالي.

ellipse

$content->ellipse($xc,$yc, $rx,$ry)
ينشئ هذا مسارًا بيضاويًا مغلقًا مركزه "[$xc,$yc]"، مع أنصاف أقطار المحاور (أنصاف الأقطار) المحددة بواسطة $rx (محور x) و $ry (محور y)، على التوالي. لا يغير هذا الموضع الحالي.

arc

$content->arc($xc,$yc, $rx,$ry, $alpha,$beta, $move, $dir)
$content->arc($xc,$yc, $rx,$ry, $alpha,$beta, $move)
يوسع هذا المسار على طول قوس من قطع ناقص مركزه "[$xc,$yc]". أنصاف الأقطار للمنحنى البيضاوي هي $rx (محور x) و $ry (محور y)، على التوالي، ويمتد القوس من $alpha درجة إلى $beta درجة. يتم تعيين الموضع الحالي بعد ذلك إلى نقطة نهاية القوس.

اضبط $move على قيمة **حقيقية** إذا كان هذا القوس هو بداية مسار جديد بدلاً من استمرار لمسار موجود. في كلتا الحالتين، سيتم تحديث الموضع الحالي إلى نهاية القوس. استخدم "$rx == $ry" لقوس دائري.

الاتجاه الاختياري لمسح القوس $dir افتراضيًا على 0 (**خاطئ**)، لمسح عكس اتجاه عقارب الساعة. اضبطه على 1 (**صحيح**) لمسح في اتجاه عقارب الساعة.

pie

$content->pie($xc,$yc, $rx,$ry, $alpha,$beta, $dir)
$content->pie($xc,$yc, $rx,$ry, $alpha,$beta)
ينشئ هذا مسارًا على شكل قطعة فطيرة من قطع ناقص مركزه "[$xc,$yc]". أنصاف الأقطار للمحور السيني والصادي للقطع الناقص هي $rx و $ry، على التوالي، ويمتد القوس من $alpha درجة إلى $beta درجة. لا يغير هذا الموضع الحالي. اعتمادًا على زوايا المسح والاتجاه، يمكن رسم "شريحة" قطعة الفطيرة أو بقية قطعة الفطيرة (مع إزالة الشريحة). استخدم "$rx == $ry" لقطعة فطيرة دائرية. استخدم "[$xc,$yc]" مختلفة للشريحة، لإزاحتها عن بقية قطعة الفطيرة.

الاتجاه الاختياري لمسح القوس $dir افتراضيًا على 0 (**خاطئ**)، لمسح عكس اتجاه عقارب الساعة. اضبطه على 1 (**صحيح**) لمسح في اتجاه عقارب الساعة.

هذه طريقة مختصرة لرسم جزء من قوس قطع ناقص (أو دائري) وتوصيله بمركز القطع الناقص أو الدائرة، لتشكيل شكل قطعة فطيرة.

curve

$content->curve($cx1,$cy1, $cx2,$cy2, $x,$y)
يوسع هذا المسار في منحنى من النقطة الحالية إلى "[$x,$y]"، باستخدام نقطتي **التحكم** المحددتين لإنشاء **منحنى بيزييه تكعيبية**، ويقوم بتحديث الموضع الحالي ليكون النقطة الجديدة ("[$x,$y]").

ضمن كائن **نص**، يتبع خط الأساس للنص منحنى بيزييه.

لاحظ أنه بينما يُسمح بمجموعات متعددة من ثلاث أزواج "[x,y]"، يتم التعامل مع هذه كمنحنيات بيزييه تكعيبية **مستقلة**. لا توجد محاولة لدمج منحنى بسلاسة في التالي!

qbspline, spline

$content->qbspline($cx1,$cy1, $x,$y)
يوسع هذا المسار في منحنى من النقطة الحالية إلى "[$x,$y]"، باستخدام النقطتين المحددتين لإنشاء منحنى بيزييه تربيعي، ويقوم بتحديث الموضع الحالي ليكون النقطة الجديدة.

داخليًا، هذه المنحنيات هي منحنى بيزييه تكعيبية واحد أو أكثر (انظر "curve") حيث يتم تصنيع نقطتي التحكم من النقطتين المعطاة (نقطة تحكم ونقطة نهاية منحنى بيزييه **تربيعي**).

لاحظ أنه بينما يُسمح بمجموعات متعددة من زوجين "[x,y]"، يتم التعامل مع هذه كمنحنيات بيزييه تربيعية **مستقلة**. لا توجد محاولة لدمج منحنى بسلاسة في التالي!

لاحظ أيضًا أن هذا "المنحنى" لا يتطابق مع التعريف الشائع للمنحنى كمنحنى **مستمر** يمر **عبر** **جميع** النقاط المعطاة! إنه منحنى بيزييه تكعيبية مقطعي غير مستمر. استخدم بحذر، ولا تضع افتراضات حول المنحنيات لك أو لقراءك. قد ترغب في استخدام استدعاء "bspline" للحصول على منحنى مستمر سلس يمر عبر جميع النقاط المعطاة.

يتم استهلاك أزواج النقاط (نقطة التحكم ونقطة النهاية) في حلقة. إذا بقيت نقطة أو إحداثيات غير مستخدمة في النهاية، فسيتم تجاهلها (كما هو الممارسة المعتادة للبيانات الزائدة لروتين). لا يوجد فحص للنقاط المكررة أو الانحلالات الأخرى.

**اسم بديل:** "spline"

لا تزال هذه الدالة تسمى "spline" في PDF::API2، وللتوافق، يمكن استخدام هذا الاسم هنا. نظرًا لوجود منحنيات تربيعية وتكعيبية متاحة في PDF، يُفضل استخدام أسماء وصفية أكثر مثل "qbspline" و "cbspline" لتقليل الارتباك.

bspline, cbspline

$content->bspline($ptsRef, %opts)
يوسع هذا المسار في منحنى من النقطة الحالية إلى نهاية قائمة أزواج الإحداثيات في المصفوفة المشار إليها بواسطة $ptsRef. تُستخدم منحنيات بيزييه تكعيبية مستمرة بسلاسة لإنشاء منحنى يمر **عبر** **جميع** النقاط المعطاة. يتم تصنيع نقاط تحكم متعددة؛ لا يتم توفيرها في الاستدعاء. يتم تحديث الموضع الحالي إلى النقطة الأخيرة.

داخليًا، هذه المنحنيات هي منحنى بيزييه تكعيبية واحد (انظر "curve") لكل زوج من نقاط الإدخال، مع تصنيع نقطتي التحكم من المماس عبر كل نقطة كما تم تعيينها بواسطة الخط المتعدد الذي يربط كل نقطة بجيرانها. الهدف هو أن يتبع المنحنى الناتج عن كثب الخط المتعدد الذي يربط النقاط، ويجب أن يتجنب أي انحرافات كبيرة. انظر المناقشات أدناه لمعالجة نقاط التحكم عند نقاط النهاية (النقطة الحالية والنقطة الأخيرة المدخلة). النقطة في نهاية آخر خط أو منحنى تم رسمه تصبح النقطة الحالية الجديدة.

يحدد لون الملء (المنطقة المغلقة) أو لون الخط (المسار). المنطقة الداخلية للأحرف النصية يتم ملؤها، و (إذا تم ترتيبها بواسطة "render") يتم رسم المخطط الخارجي. 
# استخدم لونًا مسمى
# -> نموذج لون RGB
# هناك المئات من الألوان المسماة المعرفة في
# PDF::Builder::Resource::Colors
$content->fillcolor('blue');
# استخدم لون RGB (# متبوعًا بـ 3، 6، 9، أو 12 رقمًا ست عشريًا)
# -> نموذج لون RGB
# هذا يعادل قيم 0-1.0 للأحمر والأخضر والأزرق
$content->fillcolor('#FF0000');   # أحمر
# استخدم لون CMYK (% متبوعًا بـ 4، 8، 12، أو 16 رقمًا ست عشريًا)
# -> نموذج لون CMYK
# هذا يعادل قيم 0-1.0 للسماوي والأرجواني والأصفر والأسود
$content->fillcolor('%FF000000');   # سماوي
# ملاحظة: قد ترغب في الاستفادة من حزم مثل
#  HashData::Color::PantoneToCMYK لتعيين أسماء/رموز ألوان "Pantone" إلى
#  مجموعة من قيم CMYK
# استخدم لون HSV (! متبوعًا بـ 3، 6، 9، أو 12 رقمًا ست عشريًا)
# -> نموذج لون RGB
# هذا يعادل 0-360 درجة لدرجة اللون، وقيم 0-1.0 لـ
# التشبع والقيمة
$content->fillcolor('!FF0000');
# استخدم لون HSL (& متبوعًا بـ 3، 6، 9، أو 12 رقمًا ست عشريًا)
# -> نموذج لون L*a*b
# هذا يعادل 0-360 درجة لدرجة اللون، وقيم 0-1.0 لـ
# التشبع والإضاءة. لاحظ أن 360 درجة = 0 درجة (تلتف)
$content->fillcolor('&FF0000');
# استخدم لون L*a*b ($ متبوعًا بـ 3، 6، 9، أو 12 رقمًا ست عشريًا)
# -> نموذج لون L*a*b
# هذا يعادل 0-100 لـ L، -100 إلى 100 لـ a و b
$content->fillcolor('$FF0000');

في جميع الحالات، إذا تم تقديم عدد قليل جدًا من الأرقام، فسيتم إلحاق الأرقام المعطاة بـ 0's (أصفار) بشكل صامت. إذا تم تقديم عدد غير صحيح من الأرقام، فسيتم استخدام أقل عدد صحيح متوقع من الأرقام، وسيتم تجاهل الأرقام المتبقية بشكل صامت.

# رقم واحد بين 0.0 (أسود) و 1.0 (أبيض) هو طريقة بديلة
# لتحديد مقياس الرمادي.
$content->fillcolor(0.5);
# ثلاثة عناصر مصفوفة بين 0.0 و 1.0 هي طريقة بديلة لـ
# تحديد لون RGB.
$content->fillcolor(0.3, 0.59, 0.11);
# أربعة عناصر مصفوفة بين 0.0 و 1.0 هي طريقة بديلة لـ
# تحديد لون CMYK.
$content->fillcolor(0.1, 0.9, 0.3, 1.0);

في جميع الحالات، إذا كان الرقم أقل من 0، فسيتم تحويله بشكل صامت إلى 0. إذا كان الرقم أكبر من 1، فسيتم تحويله بشكل صامت إلى 1. هذا "يُثبت" جميع القيم في النطاق 0.0-1.0.

# يتم التعامل مع مرجع واحد كنمط أو مساحة تظليل.
# يتم التعامل مع إدخالين أو أكثر حيث يكون العنصر الأول مرجع Perl، إما
# كمرجع لمساحة ألوان مفهرسة + فهرس (فهارس) اللون، أو
# كمرجع لمساحة ألوان مخصصة + معلمة (معلمات).

إذا لم يتم تمرير أي قيمة، فسيتم إرجاع مصفوفة لون الملء الحالي (أو لون الخط)، وإلا فسيتم إرجاع $self.

أسماء بديلة: "fill_color" و "stroke_color".

هذه متوفرة لتوافق PDF::API2.

كائنات خارجية

image

$content->image($image_object, $x,$y, $width,$height)
$content->image($image_object, $x,$y, $scale)
$content->image($image_object, $x,$y)
$content->image($image_object)
# مثال
my $image_object = $pdf->image_jpeg($my_image_file);
$content->image($image_object, 100, 200);
يضع صورة على الصفحة في الموقع المحدد (يحدد الزاوية السفلية اليسرى للصورة). الموقع الافتراضي هو "[0,0]".

إذا تم إجراء تحويلات إحداثيات (انظر تحويلات الإحداثيات أعلاه)، فسيكون الموضع والمقياس نسبيين للإحداثيات المحدثة. بخلاف ذلك، ستمثل "[0,0]" الزاوية السفلية اليسرى للصفحة، وسيتم قياس $width و $height بدقة 72 نقطة في البوصة.

على سبيل المثال، إذا كان لديك صورة بدقة 600x600 تريد عرضها بدقة 600 نقطة في البوصة (أي، مربع بوصة واحدة)، فاضبط العرض والارتفاع على 72. (72 نقطة كبيرة تساوي بوصة واحدة)

إذا تم تمرير ناتج image_svg()، فستقوم image() ببساطة بتمريره إلى الطريقة object()، مع معلمات معدلة. لاحظ أن هذا الاستخدام يتطلب أن يتم استبدال "width" و "height" بقيم "scale_x" و "scale_y" (اختياريًا).

formimage

$content->formimage($form_object, $x,$y, $scaleX, $scaleY)
$content->formimage($form_object, $x,$y, $scale)
$content->formimage($form_object, $x,$y)
$content->formimage($form_object)
يضع كائن XObject على الصفحة في الموقع المحدد (معطيًا الزاوية السفلية اليسرى للصورة) والمقياس (يتم تطبيقه على الارتفاع والعرض الأصليين للصورة). إذا لم يتم تحديد مقياس، استخدم 1 لكل من X و Y. إذا تم تحديد مقياس واحد، استخدمه لكل من X و Y. إذا تم تحديد مقياسين، فهما لـ X و Y (بشكل منفصل). بشكل عام، لا يجب عليك تشويه الصورة بشكل كبير باستخدام عوامل قياس مختلفة بشكل كبير في X و Y، على الرغم من أنه أصبح من الممكن الآن عندما يكون هذا التأثير مرغوبًا فيه. الافتراضي لـ "$x,$y" هو "[0,0]".

لاحظ أنه بينما سميت هذه الطريقة form image، فإنها تستخدم أيضًا للصور الزائفة التي تم إنشاؤها بواسطة إجراءات الباركود. الصور لا أبعاد لها بشكل طبيعي (مربع 1 نقطة) وتحتاج في مرحلة ما إلى تكبيرها إلى حجم النقاط المطلوب. الباركود لها حجم طبيعي بالنقاط، ويجب قياسها بحوالي 1. لذلك، سيؤدي ذلك إلى تكبير الباركود بشكل كبير جدًا عن طريق الضرب بعرض وارتفاع الصورة داخل "formimage"، ويتطلب قياس 1/width و 1/height في الاستدعاء. لذلك، نترك القياس دون تغيير داخل "formimage" ونجعل المستخدم يقوم يدويًا بقياس الصور بعرض وارتفاع الصورة (بالبكسل) في الاستدعاء إلى "formimage".

object

$content->object($object, $x,$y, $scale_x,$scale_y)
$content->object($object, $x,$y, $scale)
$content->object($object, $x,$y)
$content->object($object)
يضع صورة أو كائن خارجي آخر (يُعرف أيضًا باسم XObject) على الصفحة في الموقع المحدد (معطيًا الزاوية العلوية اليسرى للكائن). لاحظ أن هذا التموضع يختلف عن image() و formimage()، اللتين تعطيان الزاوية السفلية اليسرى!

يمكن تقديم ما يصل إلى أربعة وسائط اختيارية، مع افتراضياتها كما هو موضح أدناه.

$x و $y هما الركن الأعلى الأيسر للكائن. إذا تم حذفهما، فسيتم وضع الكائن مع ركنه الأدنى الأيسر عند "[0, 0]". لاحظ أنه إذا كان مربع الإحاطة للكائن يحتوي على القيمة الرابعة (أقصى صاعد) أكبر من 0، فقد تحتاج إلى طرح هذه القيمة من "y" للحصول على الموضع الرأسي المطلوب! سيكون للتطبيق النموذجي مربع إحاطة "[0, -height, width, 0]"، ولا يلزم إجراء تصحيح. إذا كان مربع الإحاطة هو "[0, -max_descender, width, max_ascender]"، فقد تحتاج إلى إضافة التصحيح.

بالنسبة للصور، تمثل $scale_x و $scale_y عرض وارتفاع الصورة على الصفحة، بالنقاط. إذا تم حذف $scale_x، فسيكون الافتراضي 72 بكسل لكل بوصة. إذا تم حذف $scale_y، فسيتم قياس الصورة بشكل متناسب، بناءً على أبعاد الصورة.

بالنسبة للكائنات الخارجية الأخرى، بما في ذلك صور SVG، فإن المقياس هو عامل مضاعف، حيث يمثل 1 (الافتراضي) 100٪ (أي، لا تغيير).

إذا تم إجراء تحويلات إحداثيات (انظر تحويلات الإحداثيات أعلاه)، فسيكون الموضع والمقياس نسبيين للإحداثيات المحدثة.

إذا لم تكن هناك حاجة إلى تحويلات إحداثيات،

احتفظ بالهيكل الكامل للملف.

يمكن استدعاء new() لضبط المعلمة compress على 'flate' (القيمة الافتراضية) لضغط جميع تدفقات الكائنات، أو على 'none' لكبت الضغط والسماح لك برؤية الإخراج في محرر.

textstart

$content->textstart()
يبدأ كائن نصي (يتم تجاهله إذا كنت بالفعل داخله). أوصي باستخدام الطريقة text() (سياق نصي، وليس إخراج نصي) بدلاً من ذلك.

ملاحظة: عند استدعاء هذه الطريقة، بالإضافة إلى إصدار علامة BT، سيتم إعادة تعيين معظم إعدادات النص إلى قيمها الافتراضية. بالإضافة إلى ذلك، ستقوم BT نفسها بإعادة تعيين بعض مصفوفات التحويل.

textend

$content->textend()
ينهي كائن نصي (يتم تجاهله إذا لم تكن داخله).

ملاحظة: عند استدعاء هذه الطريقة، بالإضافة إلى إصدار علامة ET، سيتم إصدار أي محتوى مجمع من poststream.
