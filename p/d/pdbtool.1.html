الاسم

pdbtool --- تطبيق لاختبار وتحويل قواعد قاعدة بيانات الأنماط {{ site.product.short_name }}

ملخص

pdbtool [أمر] [خيارات]

الوصف

صفحة الدليل هذه هي مجرد ملخص.

يمكن لتطبيق syslog-ng OSE مطابقة محتويات رسائل السجل مع قاعدة بيانات لأنماط الرسائل المحددة مسبقًا (تسمى أيضًا patterndb). من خلال مقارنة الرسائل بالأنماط المعروفة، يمكن لـ syslog-ng OSE تحديد النوع الدقيق للرسائل، ووضع علامات على الرسائل، وفرزها في فئات رسائل. يمكن استخدام فئات الرسائل لتصنيف نوع الحدث الموصوف في رسالة السجل. وظيفة قاعدة بيانات الأنماط مشابهة لمشروع logcheck، ولكن نهج syslog-ng OSE أسرع، ويتوسع بشكل أفضل، وأسهل بكثير في الصيانة مقارنة بالتعبيرات العادية لـ logcheck.

تطبيق pdbtool هو أداة يمكن استخدامها لـ:

  • اختبار الرسائل، أو قواعد محددة
  • تحويل قاعدة بيانات أنماط قديمة إلى أحدث تنسيق قاعدة بيانات
  • دمج قواعد بيانات الأنماط في ملف واحد
  • إنشاء قواعد بيانات أنماط تلقائيًا من كمية كبيرة من رسائل السجل
  • تفريغ شجرة RADIX المبنية من قاعدة بيانات الأنماط (أو جزء منها) لاستكشاف كيفية عمل مطابقة الأنماط.

أمر القاموس

dictionary [خيارات]

يسرد كل زوج اسم-قيمة يمكن تعيينه بواسطة قواعد قاعدة بيانات الأنماط.

•
--dump-tag أو -T

يسرد العلامات بدلاً من أسماء أزواج الاسم-القيمة.

•
--pdb <مسار-إلى-ملف> أو -p <مسار-إلى-ملف>

اسم ملف قاعدة بيانات الأنماط المراد استخدامه.

•
--program <اسم-البرنامج> أو -P <اسم-البرنامج>

يسرد فقط أزواج الاسم-القيمة التي يمكن تعيينها لرسائل تطبيق ${PROGRAM} المحدد.

أمر التفريغ

dump [خيارات]

يعرض شجرة RADIX المبنية من الأنماط. هذا يوضح كيف يتم تمثيل الأنماط في syslog-ng OSE وقد يساعد أيضًا في تتبع مشاكل مطابقة الأنماط. يمكن لأداة التفريغ تفريغ الشجرة المستخدمة لمطابقة أجزاء PROGRAM أو MSG.

•
--debug أو -d

تمكين رسائل التصحيح/التشخيص على stderr.

•
--pdb أو -p

اسم ملف قاعدة بيانات الأنماط المراد استخدامه.

•
--program أو -P

يعرض شجرة RADIX المبنية من الأنماط التي تنتمي إلى تطبيق ${PROGRAM}.

•
--program-tree أو -T

يعرض شجرة ${PROGRAM}.

•
--verbose أو -v

تمكين الرسائل المطولة على stderr.

مثال وإخراج نموذجي

pdbtool dump -p patterndb.xml  -P 'sshd'
'p'
    'assword for'
    @QSTRING:@
        'from'
        @QSTRING:@
            'port '
            @NUMBER:@ rule_id='fc49054e-75fd-11dd-9bba-001e6806451b'
                ' ssh' rule_id='fc55cf86-75fd-11dd-9bba-001e6806451b'
                    '2' rule_id='fc4b7982-75fd-11dd-9bba-001e6806451b'
    'ublickey for'
    @QSTRING:@
        'from'
        @QSTRING:@
            'port '
            @NUMBER:@ rule_id='fc4d377c-75fd-11dd-9bba-001e6806451b'
                ' ssh' rule_id='fc5441ac-75fd-11dd-9bba-001e6806451b'
                    '2' rule_id='fc44a9fe-75fd-11dd-9bba-001e6806451b'

أمر المطابقة

match [خيارات]

استخدم أمر المطابقة لاختبار القواعد في قاعدة بيانات الأنماط. يحاول الأمر مطابقة الرسالة المحددة مع أنماط قاعدة البيانات، ويقيم المحللات النحوية للنمط، ويعرض أيضًا أي جزء من الرسالة تم تحليله بنجاح. يعود الأمر برمز إرجاع 0 (نجاح) أو 1 (عدم تطابق) ويعرض المعلومات التالية:

  • الفئة المعينة للرسالة (أي، نظام، انتهاك، وما إلى ذلك)،
  • معرف القاعدة التي طابقت الرسالة، و
  • قيم المحللات النحوية (إذا كانت هناك محللات نحوية في النمط المطابق).

يحتوي أمر المطابقة على الخيارات التالية:

•
--color-out أو -c

لون مخرجات الطرفية لتمييز جزء الرسالة الذي تم تحليله بنجاح.

•
--debug أو -d

تمكين رسائل التصحيح/التشخيص على stderr.

•
--debug-csv أو -C

طباعة معلومات التصحيح التي تم إرجاعها بواسطة خيار --debug-pattern كقيم مفصولة بفواصل.

•
--debug-pattern أو -D

طباعة معلومات التصحيح حول مطابقة الأنماط. انظر أيضًا الخيار --debug-csv.

•
--file=<اسم-الملف-مع-المسار> أو -f

معالجة رسائل ملف السجل المحدد باستخدام قاعدة بيانات الأنماط. يسمح هذا الخيار بتصنيف الرسائل دون اتصال بالإنترنت، وتطبيق قاعدة بيانات الأنماط على ملفات السجل الموجودة بالفعل. لقراءة الرسائل من الإدخال القياسي (stdin)، قم بتحديد حرف واصلة (-) بدلاً من اسم الملف.

•
--filter=<تعبير-التصفية> أو -F

طباعة الرسائل التي تطابق تعبير تصفية syslog-ng OSE المحدد فقط.

•
--message أو -M

نص رسالة السجل للمطابقة (الجزء MESSAGE فقط بدون رؤوس syslog).

•
--pdb أو -p

اسم ملف قاعدة بيانات الأنماط المراد استخدامه.

•
--program أو -P

اسم البرنامج المراد استخدامه، كما هو موجود في جزء PROGRAM من رسالة syslog.

•
--template=<تعبير-القالب> أو -T

تعبير قالب syslog-ng OSE يستخدم لتنسيق رسائل الإخراج.

•
--verbose أو -v

تمكين الرسائل المطولة على stderr.

مثال - التحقق

يقوم الأمر التالي بالتحقق مما إذا كان ملف patterndb.xml يتعرف على الرسالة Accepted publickey for myuser from 127.0.0.1 port 59357 ssh6:

pdbtool match -p patterndb.xml -P sshd -M "Accepted publickey for myuser from 127.0.0.1 port 59357 ssh6"

مثال - التطبيق

يطبق المثال التالي ملف قاعدة بيانات الأنماط sshd.pdb على رسائل السجل المخزنة في الملف /var/log/messages، ويعرض فقط الرسائل التي تلقت علامة useracct.

pdbtool match -p sshd.pdb \
    –file /var/log/messages \
    –filter ‘tags(“usracct”);’

أمر الدمج

merge [خيارات]

استخدم أمر الدمج لدمج ملفات قاعدة بيانات الأنماط المنفصلة في ملف واحد (عادةً ما يتم تخزين قواعد بيانات الأنماط في ملفات منفصلة لكل تطبيق لتبسيط الصيانة). إذا كان الملف يستخدم تنسيق قاعدة بيانات أقدم، فسيتم تحديثه تلقائيًا إلى أحدث تنسيق (V3). انظر دليل مسؤول syslog-ng OSE للحصول على تفاصيل حول إصدارات قاعدة بيانات الأنماط المختلفة.

•
--debug أو -d

تمكين رسائل التصحيح/التشخيص على stderr.

•
--directory أو -D

الدليل الذي يحتوي على ملفات XML الخاصة بقاعدة بيانات الأنماط المراد دمجها.

•
--glob أو -G

تحديد أسماء الملفات لـ

NAME

pdbtool - command-line tool for managing syslog-ng pattern databases

SYNOPSIS

pdbtool merge [options]

pdbtool patternize [options]

pdbtool test [options]

DESCRIPTION

The pdbtool utility is a command-line tool that helps manage syslog-ng pattern databases. It supports the following operations:

  • merge: Merge multiple pattern database files into a single file.
  • patternize: Automatically create a pattern database from a log file.
  • test: Validate a pattern database XML file.

The dictionary command

pdbtool dictionary [options]

This command is used to create and manage pattern dictionary files. Pattern dictionaries are used by syslog-ng to store and retrieve frequently used patterns, improving parsing performance.

•
--dictionary=<path> or -d

Specifies the path to the pattern dictionary file.

•
--file=<path> or -f

The logfile containing the log messages to create dictionary entries from. To receive the log messages from the standard input (stdin), use -.

•
--verbose or -v

Enable verbose messages on stderr.

Example - dictionary

pdbtool dictionary --file=/var/log/messages --dictionary=/etc/syslog-ng/dictionary.xml

The dump command

pdbtool dump [options]

This command is used to dump the contents of a pattern database file in a human-readable format. This is useful for inspecting the patterns stored in the database.

•
--file=<path> or -f

The pattern database file to dump.

•
--verbose or -v

Enable verbose messages on stderr.

Example - dump

pdbtool dump --file=/var/lib/syslog-ng/patterndb.xml

The match command

pdbtool match [options]

This command is used to test how well a pattern database matches a given set of log messages. It can help identify potential issues with pattern definitions or suggest improvements.

•
--file=<path> or -f

The logfile containing the log messages to match against.

•
--pdb=<path> or -p

The pattern database file to use for matching.

•
--verbose or -v

Enable verbose messages on stderr.

Example - match

pdbtool match --file=/var/log/messages --pdb=/var/lib/syslog-ng/patterndb.xml

The merge command

pdbtool merge [options]

Merges multiple pattern database files into a single file. This is useful when you have patterns defined in different files and want to combine them into one.

•
--directory=<path> or -d

Directory containing pattern database files to be merged. The files can be specified using a glob pattern, for example, using wildcards. For details on glob patterns, see man glob. This pattern is applied only to the filenames, and not on directory names.

•
--pdb or -p

Name of the output pattern database file.

•
--recursive or -r

Merge files from subdirectories as well.

•
--sort or -s

Sort files into alphabetic order during the merge (first sort by filename, then by directory name).

•
--verbose or -v

Enable verbose messages on stderr.

Example - merge

pdbtool merge --recursive --directory /home/me/mypatterns/  --pdb /var/lib/syslog-ng/patterndb.xml

Currently it is not possible to convert a file without merging, so if you only want to convert an older pattern database file to the latest format, you have to copy it into an empty directory.

The patternize command

patternize [options]

Automatically create a pattern database from a log file containing a large number of log messages. The resulting pattern database is printed to the standard output (stdout). The pdbtool patternize command uses a data clustering technique to find similar log messages and replacing the differing parts with @ESTRING:: @ parsers. For details on pattern databases and message parsers, see the The syslog-ng OSE Administrator Guide ⟨https://www.syslog-ng.com/⟩. The patternize command is available only in version 3.2 and later.

•
--debug or -d

Enable debug/diagnostic messages on stderr.

•
--file=<path> or -f

The logfile containing the log messages to create patterns from. To receive the log messages from the standard input (stdin), use -.

•
--iterate-outliers or -o

Recursively iterate on the log lines to cover as many log messages with patterns as possible.

•
--named-parsers or -n

The number of example log messages to include in the pattern database for every pattern. Default value: 1

•
--no-parse or -p

Do not parse the input file, treat every line as the message part of a log message.

•
--samples=<number-of-samples>

Include a generated name in the parsers, for example, .dict.string1, .dict.string2, and so on.

•
--support=<number> or -S

A pattern is added to the output pattern database if at least the specified percentage of log messages from the input logfile match the pattern. For example, if the input logfile contains 1000 log messages and the --support=3.0 option is used, a pattern is created only if the pattern matches at least 3 percent of the log messages (that is, 30 log messages). If patternize does not create enough patterns, try to decrease the support value.

Default value: 4.0

•
--verbose or -v

Enable verbose messages on stderr.

Example - patternize

pdbtool patternize --support=2.5 --file=/var/log/messages

The test command

test [options]

Use the test command to validate a pattern database XML file. Note that you must have the xmllint application installed. The test command is available only in syslog-ng OSE version 3.2 and later.

•
--color-out or -c

Enable coloring in terminal output.

•
--debug or -d

Enable debug/diagnostic messages on stderr.

•
--debug or -D

Print debugging information on non-matching patterns.

•
--rule-id or -r

Test only the patterndb rule (specified by its rule id) against its example.

•
--validate

Validate a pattern database XML file.

•
--verbose or -v

Enable verbose messages on stderr.

Example - test

pdbtool test --validate /home/me/mypatterndb.pdb
