DESCRIPTION

The unbound library is a validating, recursive, and caching DNS resolver. It is designed to be simple, fast, and secure. It implements DNSSEC (DNS security extensions) and provides a DNS resolver API for applications.

The main handle for the unbound library is the struct ub_ctx context. It holds the configuration, state and security information for a resolver instance. Create a context with ub_ctx_create and destroy it with ub_ctx_delete.

Configuration can be loaded from a file using ub_ctx_config, or from resolver configuration using ub_ctx_resolvconf. If neither is called, default system settings are used. Options can also be set directly using ub_ctx_set_option and retrieved using ub_ctx_get_option.

The following options are available:

  • verbosity: verbosity of debug output. (default 0).
  • log-ident: prefix for log messages.
  • log-queries: if true, log all queries.
  • root-hints: file with root hints.
  • harden-dnssec-stripped: if true, harden against DNSSEC stripping attacks.
  • use-caps-for-id: if true, use a random source port and IP address for queries.
  • private-address: RFC 1918 addresses are not returned.
  • private-domain: RFC 1918 domains are not returned.
  • do-not-query-localhost: do not query localhost (127.0.0.1/::1) reverse lookups.
  • prefetch: enable prefetching of expired resource records.
  • prefetch-key: enable prefetching of DNSKEY records.
  • num-threads: number of worker threads.
  • outgoing-range: number of outgoing ports to use.
  • outgoing-interface: set the outgoing interface.
  • outgoing-ip: set the outgoing IP address.
  • so-rcvbuf: set socket receive buffer size.
  • so-sndbuf: set socket send buffer size.
  • sndbuf-advance: if true, increase send buffer size when needed.
  • edns-buffer-size: set the advertised EDNS0 buffer size.
  • max-udp-size: set the maximum UDP packet size.
  • max-tcp-size: set the maximum TCP packet size.
  • max-hash-chain: limit the length of hash chains.
  • cache-min-ttl: minimum TTL for cache entries.
  • cache-max-ttl: maximum TTL for cache entries.
  • qname-minimisation: enable qname minimisation.
  • anonimiserenames: enable anonymous domain name mapping.
  • id-prefix: prefix for query IDs.
  • trust-anchor-file: filename for trust anchor information.
  • anchor-use-default: use default root anchor if file not found.
  • add-subnet: add client subnet information to queries.
  • subnet-zone: zone for client subnet information.
  • subnet-privacy: privacy level for client subnet information.
  • ssl-upstream: enable DNS-over-TLS for upstream queries.
  • ssl-dot: enable DNS-over-TLS for all queries.
  • ssl-anchor-file: filename for trust anchors for DNS-over-TLS.
  • ssl-host-name: hostname for DNS-over-TLS verification.

Trust anchors are used for DNSSEC validation. They can be loaded from files using ub_ctx_trustedkeys, ub_ctx_add_ta_file, or ub_ctx_add_ta_autr. Individual trust anchors can be added using ub_ctx_add_ta.

Debugging output can be directed to a specific file stream using ub_ctx_debugout, and the verbosity level can be set using ub_ctx_debuglevel.

The library supports both synchronous and asynchronous resolution. Synchronous resolution is done using ub_resolve, which blocks until the result is available. Asynchronous resolution is done using ub_resolve_async, which returns immediately and calls a callback function when the result is ready. The ub_ctx_async function controls whether asynchronous operations use threads or processes.

For asynchronous operations, ub_poll can be used to check if any results are ready. ub_fd returns a file descriptor that can be monitored for readability. When results are available, ub_process must be called to process them and trigger callbacks. ub_wait waits for all pending asynchronous queries to complete.

The ub_cancel function can be used to cancel an asynchronous query. The ub_resolve_free function should be called to free the memory allocated for the result structure. ub_strerror converts error codes to human-readable strings.

Local authority information can be managed using the ub_ctx_zone_add, ub_ctx_zone_remove, ub_ctx_data_add, and ub_ctx_data_remove functions. ub_ctx_print_local_zones can be used for debugging.

FUNCTIONS

ub_ctx_create
Create a new Unbound context. Returns NULL on error.
ub_ctx_delete
Delete an Unbound context and free all associated resources.
ub_ctx_set_option
Set an option for the context. Options are specified as strings. Returns 0 on success, or an error code.
ub_ctx_set_option_int
Set an integer option for the context. Returns 0 on success, or an error code.
ub_ctx_get_option
Get the string value of an option for the context. The returned string must be freed by the caller using free(). Returns 0 on success, or an error code.
ub_ctx_get_option_int
Get the integer value of an option for the context. Returns 0 on success, or an error code.
ub_ctx_config
Load configuration from the specified file. Returns 0 on success, or an error code.
ub_ctx_resolvconf
Load resolver configuration (like nameservers) from the specified file. Returns 0 on success, or an error code.
ub_ctx_trustedkeys
Add trust anchors to the context from a BIND-style trusted-keys file. Returns 0 on success, or an error code.
ub_ctx_add_ta
Add a trust anchor to the context. The trust anchor is specified as a string in zone file format (e.g., "example.com. IN DNSKEY ..."). Both DS and DNSKEY records are accepted. Returns 0 on success, or an error code.
ub_ctx_add_ta_file
Add trust anchors to the context from a file containing DS and DNSKEY records in zone file format. Returns 0 on success, or an error code.
ub_ctx_add_ta_autr
Add a filename containing a managed trust anchor to the context. This file can be created with unbound-anchor(8) or can be an initial file with one DNSKEY or DS record. If the file is writable, it is updated when the trust anchor changes. Returns 0 on success, or an error code.
ub_ctx_debugout
Set the output stream for debug and error messages. Pass NULL to disable output. Defaults to stderr.
ub_ctx_debuglevel
Set the debug verbosity level for the context. Higher levels produce more output. Output is directed to the stream set by ub_ctx_debugout.
ub_ctx_async
Set the behavior for asynchronous operations. If enable is true, threading is used. If false, a process is forked. Changes take effect for subsequent calls. Returns 0 on success, or an error code.
ub_poll
Check if the context has any new results to process. Returns non-zero if results are available, 0 otherwise. This should not be called in a loop; instead, monitor the file descriptor returned by ub_fd.
ub_wait
Wait for all pending asynchronous queries in the context to complete. Calls ub_process internally. After this call, there are no more outstanding asynchronous queries.
ub_fd
Get the file descriptor associated with the context. This file descriptor will become readable when results are available from asynchronous queries. Returns the file descriptor or -1 on error.
ub_process
Process any available results from asynchronous queries. This function should be called when the file descriptor returned by ub_fd indicates readability. It performs necessary callbacks.
ub_resolve
Perform a synchronous DNS resolution and validation for the given name, rrtype, and rrclass. The result is returned in the structure pointed to by result, which is newly allocated. Returns 0 on success, or an error code.
ub_resolve_async
Perform an asynchronous DNS resolution and validation. The callback function is called when the result is ready. mydata is a pointer that is passed to the callback. async_id will contain a unique identifier for this request, which can be used with ub_cancel. Returns 0 on success, or an error code.
ub_cancel
Cancel an asynchronous query in progress identified by async_id. May return an error if the query does not exist or is already being delivered. Returns 0 on success, or an error code.
ub_resolve_free
Free the memory allocated for a struct ub_result structure and its contents.
ub_strerror
Convert an Unbound library error code to a human-readable string. Returns a pointer to a zero-terminated string.
ub_ctx_print_local_zones
Prints the local authority information to the debug output stream for debugging purposes.
ub_ctx_zone_add
Adds a new zone to the local authority information, similar to the local-zone statement in unbound.conf(5). Returns 0 on success, or an error code.
ub_ctx_zone_remove
Deletes a zone from the local authority information. Returns 0 on success, or an error code.
ub_ctx_data_add
Adds resource record data to the local authority information, similar to the local-data statement in unbound.conf(5). Returns 0 on success, or an error code.
ub_ctx_data_remove
Deletes local authority data for the given name, type, and class. Returns 0 on success, or an error code.

RESULT DATA STRUCTURE

The result of DNS resolution and validation is returned in a struct ub_result structure, which contains the following members:

struct ub_result {
     char* qname;         /* The original question name. */
     int qtype;           /* The type code of the query. */
     int qclass;          /* The class code of the query. */
     char** data;         /* Array of RDATA items (strings). NULL terminated. */
     int* len;            /* Array with lengths of RDATA items. */
     char* canonname;     /* Canonical name of the result (for CNAMEs). */
     int rcode;           /* Additional error code (e.g., for NOERROR with no data). */
     void* answer_packet; /* Pointer to the full network format answer packet. */
     int answer_len;      /* Length of the answer packet in octets. */
     int havedata;        /* True if the result contains data. */
     int nxdomain;        /* True if the name does not exist (NXDOMAIN). */
     int secure;          /* True if the result is DNSSEC validated as secure. */
     int bogus;           /* True if a DNSSEC validation failure occurred. */
     char* why_bogus;     /* String explaining why the result is bogus, if applicable. */
     int was_ratelimited; /* True if the query was rate-limited (SERVFAIL) by unbound. */
     int ttl;             /* Time-to-live (in seconds) for the cached result. */
};

If both secure and bogus are false, security was not enabled for the query's domain. Otherwise, exactly one of them will be true.

RETURN VALUES

Most functions return 0 on success. Non-zero values indicate error codes. These codes can be passed to ub_strerror to obtain a human-readable error message. ub_ctx_create returns NULL on error (e.g., memory allocation failure). ub_poll returns non-zero if results are available, and 0 otherwise. ub_fd returns a valid file descriptor or -1 on error. ub_ctx_config and ub_ctx_resolvconf may leave errno set to provide more information on file read failures.
