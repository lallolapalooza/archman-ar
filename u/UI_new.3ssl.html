DESCRIPTION

UI تعني واجهة المستخدم، وهي مجموعة عامة من الروتينات لاستجواب المستخدم للحصول على معلومات نصية. من خلال طرق يكتبها المستخدم (انظر UI_create_method(3))، يمكن إجراء الاستجواب بأي طريقة يمكن تخيلها، سواء كان ذلك استجوابًا نصيًا عاديًا، أو من خلال مربعات حوار، أو من هاتف خلوي.

تعمل جميع الوظائف من خلال سياق من النوع UI. يحتوي هذا السياق على جميع المعلومات اللازمة للاستجواب بشكل صحيح بالإضافة إلى مرجع لطريقة UI_METHOD، وهي متجه مرتب من الوظائف التي تقوم بتنفيذ الاستجواب الفعلي.

أول شيء يجب فعله هو إنشاء واجهة مستخدم باستخدام UI_new() أو UI_new_method()، ثم إضافة معلومات إليها باستخدام وظائف UI_add أو UI_dup. أيضًا، يمكن تمرير بيانات عشوائية معرفة من قبل المستخدم إلى الطريقة الأساسية من خلال استدعاءات لـ UI_add_user_data() أو UI_dup_user_data(). الطريقة الافتراضية لواجهة المستخدم لا تهتم بهذه البيانات، ولكن الطرق الأخرى قد تهتم. أخيرًا، استخدم UI_process() لإجراء الاستجواب فعليًا واستخدم UI_get0_result() و UI_get_result_length() للعثور على نتيجة الاستجواب وطولها.

يمكن أن تحتوي واجهة المستخدم على أكثر من استجواب واحد، والتي يتم تنفيذها بالترتيب المحدد. يحصل كل استجواب على رقم فهرس يتم إرجاعه بواسطة وظائف UI_add و UI_dup، ويجب استخدامه للحصول على النتيجة المقابلة باستخدام UI_get0_result() و UI_get_result_length().

يمكن استدعاء UI_process() أكثر من مرة على نفس واجهة المستخدم، مما يسمح لواجهة المستخدم بأن يكون لها عمر طويل، ولكن يمكن أن يكون لها أيضًا عمر قصير.

الوظائف هي كما يلي:

UI_new() تنشئ واجهة مستخدم جديدة باستخدام طريقة واجهة المستخدم الافتراضية. عند الانتهاء من هذه الواجهة، يجب تحريرها باستخدام UI_free().

UI_new_method() تنشئ واجهة مستخدم جديدة باستخدام طريقة واجهة المستخدم المحددة. عند الانتهاء من هذه الواجهة، يجب تحريرها باستخدام UI_free().

UI_OpenSSL() ترجع طريقة واجهة المستخدم المدمجة (ملاحظة: ليست بالضرورة الطريقة الافتراضية، نظرًا لأنه يمكن تغيير الافتراضي. انظر المزيد). هذه الطريقة هي الجزء الأكثر اعتمادًا على الجهاز/نظام التشغيل في OpenSSL وعادة ما تولد معظم المشاكل عند النقل.

UI_null() ترجع طريقة واجهة مستخدم لا تفعل شيئًا. استخدامها هو تجنب الحصول على الافتراضيات الداخلية لمؤشرات UI_METHOD الممررة.

UI_free() تزيل واجهة مستخدم من الذاكرة، جنبًا إلى جنب مع جميع أجزاء الذاكرة الأخرى المتصلة بها، مثل سلاسل الإدخال المكررة، والنتائج، وغيرها. إذا كان ui هو NULL، فلن يتم فعل شيء.

UI_add_input_string() و UI_add_verify_string() تضيف استجوابًا إلى واجهة المستخدم، بالإضافة إلى العلامات ومخزن نتائج وحجمي الحد الأدنى والأقصى المطلوبين للنتيجة، لا يشمل الحرف NUL النهائي. تستخدم المعلومات المقدمة للاستجواب للحصول على معلومات، على سبيل المثال كلمة مرور، وللتحقق من كلمة مرور (أي مطالبة المستخدم بإدخالها مرتين والتحقق من أنه تم إدخال نفس السلسلة مرتين). تأخذ UI_add_verify_string() وسيطًا إضافيًا يجب أن يكون مؤشرًا إلى مخزن نتائج سلسلة الإدخال التي يجب التحقق منها، وإلا فسيفشل التحقق.

UI_add_input_boolean() تضيف استجوابًا إلى واجهة المستخدم يُفترض الإجابة عليه بطريقة منطقية، بحرف واحد للإجابة بنعم وحرف مختلف للإجابة بلا. يتم توفير مجموعة من الأحرف التي يمكن استخدامها لإلغاء الاستجواب أيضًا. ينقسم الاستجواب نفسه إلى جزأين، أحدهما هو النص الوصفي (المقدم عبر الوسيط prompt) والآخر يصف الإجابات الممكنة (المقدم عبر الوسيط action_desc).

UI_add_info_string() و UI_add_error_string() تضيف سلاسل يتم عرضها في نفس الوقت مع الاستجواب للحصول على معلومات إضافية أو لعرض سلسلة خطأ. الفرق بين الاثنين هو مجرد مفاهيمي. مع الطريقة المدمجة، لا يوجد فرق تقني بينهما. قد تجعل الطرق الأخرى فرقًا بينهما، مع ذلك.

العلامات المدعومة حاليًا هي UI_INPUT_FLAG_ECHO، والتي تكون ذات صلة بـ UI_add_input_string() وسيجعل استجابة المستخدم تُعرض (عند المطالبة بكلمة مرور، يجب بالطبع عدم استخدام هذه العلامة، و UI_INPUT_FLAG_DEFAULT_PWD، والتي تعني أنه سيتم استخدام كلمة مرور افتراضية من نوع ما (يعتمد كليًا على التطبيق وطريقة واجهة المستخدم).

UI_dup_input_string()، UI_dup_verify_string()، UI_dup_input_boolean()، UI_dup_info_string() و UI_dup_error_string() هي أساسًا نفس نظائرها UI_add، باستثناء أنها تقوم بعمل نسخ خاصة بها من جميع السلاسل.

UI_construct_prompt() هي وظيفة مساعدة يمكن استخدامها لإنشاء استجواب من جزأين من المعلومات: وصف عبارة phrase_desc واسم كائن object_name، حيث يمكن أن يكون الأخير NULL. المنشئ الافتراضي (إذا لم يتم توفير أي بواسطة الطريقة المستخدمة) ينشئ السلسلة "Enter phrase_desc for object_name:" حيث يتم حذف جزء " for object_name" إذا كان object_name هو NULL. مع الوصف "pass phrase" واسم الملف "foo.key"، يصبح "Enter pass phrase for foo.key:". قد تنشئ الطرق الأخرى أي سلسلة وقد تتضمن ترميزات سيتم معالجتها بواسطة وظائف الطريقة الأخرى.

UI_add_user_data() تضيف مؤشر بيانات مستخدم لاستخدامه من قبل الطريقة في أي وقت. الطريقة الافتراضية لواجهة المستخدم لا تهتم بهذه المعلومات. لاحظ أن استدعاءات متعددة لهذه الوظيفة لا تضيف بيانات، بل تستبدل الكتلة السابقة بتلك المقدمة كوسيط.

UI_dup_user_data() تكرر بيانات المستخدم وتعمل كبديل لـ UI_add_user_data() عندما تحتاج بيانات المستخدم إلى الاحتفاظ بها لفترة أطول، ربما حتى عمر التطبيق. يتولى كائن واجهة المستخدم ملكية هذه النسخة وسيحررها كلما تم استبدالها أو تدمير واجهة المستخدم. ترجع UI_dup_user_data() 0 عند النجاح، أو -1 عند فشل تخصيص الذاكرة أو إذا كانت الطريقة لا تحتوي على وظيفة تكرار.

UI_get0_user_data() تسترد البيانات التي تم تمريرها مؤخرًا إلى واجهة المستخدم باستخدام UI_add_user_data() أو UI_dup_user_data.

UI_get0_result() ترجع مؤشرًا إلى مخزن نتائج مرتبط بالمعلومات المفهرسة بواسطة i.

DESCRIPTION

The OpenSSL library supports user interaction for tasks like asking for passwords, confirmations, etc. This interaction is handled by a UI_METHOD. The library provides a default method UI_OpenSSL() that handles the most common tasks.

A UI structure contains all the data for a specific user interaction sequence. It is created using UI_new() or UI_new_method() which allocates and initializes a UI structure and associates it with the specified method. The structure is freed by UI_free().

The functions UI_add_* and UI_dup_* add various types of user interaction requests to the UI structure. The difference between the add and dup variants is that the dup versions make a copy of the prompt strings, while the add versions use the provided pointers. The add_*_string functions add a prompt for free-form text input. The prompt is displayed, and the user input is stored in result up to maxlen bytes. The input must be at least minlen bytes long.

The add_input_boolean functions add a prompt for a yes/no answer. The strings yes_str and no_str are used to display the options. The result is stored in the integer pointed to by result. The exact value stored is method-dependent.

The add_info_string functions add a string that is simply displayed to the user, for informational purposes.

The add_error_string functions add an error message that is displayed to the user.

The add_verify_string functions add a string that requires user verification, typically for confirmation.

UI_construct_prompt() is a helper function that uses the information about an object to construct a prompt string. It is intended for use by UI methods that need to present information about an object to the user.

UI_get0_result() retrieves the result of the i-th user interaction request. The index i starts at 0. The return value is a pointer to the result string. This string is owned by the UI structure and should not be freed by the caller. It might be NULL if the index is out of bounds or an error occurred.

UI_get_result_length() retrieves the length of the result of the i-th user interaction request. The index i starts at 0. The return value is the length of the result string, or 0 if the index is out of bounds. It returns -1 on error.

UI_dup_user_data() duplicates the user-defined data associated with the UI structure. This is useful when you want to preserve the user data across multiple operations or contexts.

UI_process() goes through the information given so far, does all the printing and prompting and returns the final status, which is -2 on out-of-band events (Interrupt, Cancel, ...), -1 on error and 0 on success.

UI_ctrl() adds extra control for the application author. For now, it understands two commands: UI_CTRL_PRINT_ERRORS, which makes UI_process() print the OpenSSL error stack as part of processing the UI, and UI_CTRL_IS_REDOABLE, which returns a flag saying if the used UI can be used again or not.

UI_set_default_method() changes the default UI method to the one given. This function is not thread-safe and should not be called at the same time as other OpenSSL functions.

UI_get_default_method() returns a pointer to the current default UI method.

UI_get_method() returns the UI method associated with a given UI.

UI_set_method() changes the UI method associated with a given UI.

NOTES

The resulting strings that the built in method UI_OpenSSL() generate are assumed to be encoded according to the current locale or (for Windows) code page. For applications having different demands, these strings need to be converted appropriately by the caller. For Windows, if the OPENSSL_WIN32_UTF8 environment variable is set, the built-in method UI_OpenSSL() will produce UTF-8 encoded strings instead.

RETURN VALUES

UI_new() and UI_new_method() return a valid UI structure or NULL if an error occurred.

UI_add_input_string(), UI_dup_input_string(), UI_add_verify_string(), UI_dup_verify_string(), UI_add_input_boolean(), UI_dup_input_boolean(), UI_add_info_string(), UI_dup_info_string(), UI_add_error_string() and UI_dup_error_string() return a positive number on success or a value which is less than or equal to 0 otherwise.

UI_construct_prompt() returns a string or NULL if an error occurred.

UI_dup_user_data() returns 0 on success or -1 on error.

UI_get0_result() returns a string or NULL on error.

UI_get_result_length() returns a positive integer or 0 on success; otherwise it returns -1 on error.

UI_process() returns 0 on success or a negative value on error.

UI_ctrl() returns a mask on success or -1 on error.

UI_get_default_method(), UI_get_method(), UI_OpenSSL(), UI_null() and UI_set_method() return either a valid UI_METHOD structure or NULL respectively.

HISTORY
