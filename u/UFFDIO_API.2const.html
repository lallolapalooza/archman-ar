UFFDIO_API(2const) UFFDIO_API(2const)

الاسم

UFFDIO_API - تمكين تشغيل userfaultfd وإجراء مصافحة API

المكتبة

مكتبة C القياسية (libc, -lc)

الملخص

#include <linux/userfaultfd.h>  /* تعريف ثوابت UFFD* */
#include <sys/ioctl.h>
int ioctl(int fd, UFFDIO_API, struct uffdio_api *argp);
#include <linux/userfaultfd.h>
struct uffdio_api {
    __u64 api;       /* إصدار API المطلوب (مدخل) */
    __u64 features;  /* الميزات المطلوبة (مدخل/مخرج) */
    __u64 ioctls;    /* عمليات ioctl() المتاحة (مخرج) */
};

الوصف

تمكين تشغيل userfaultfd وإجراء مصافحة API.

يشير الحقل api إلى إصدار API الذي يطلبه التطبيق. تتحقق النواة مما إذا كانت تدعم إصدار API المطلوب، وتعيّن حقلي features و ioctls إلى أقنعة بت تمثل جميع الميزات المتاحة وعمليات ioctl(2) العامة المتاحة.

قبل Linux 4.11، يجب تهيئة الحقل features إلى الصفر قبل استدعاء UFFDIO_API، ويتم وضع الصفر (أي، لا توجد بتات ميزات) في الحقل features بواسطة النواة عند العودة من ioctl(2).

منذ Linux 4.11، يدعم userfaultfd الميزات التي تحتاج إلى تمكين صريح. لتمكين أي من الميزات، يحتاج المرء إلى تعيين بتات الميزات المقابلة في features عند إصدار استدعاء UFFDIO_API.

لأسباب تاريخية، يلزم وجود userfaultfd مؤقت لاستكشاف ميزات userfaultfd التي تدعمها النواة. يحتاج التطبيق إلى إنشاء userfaultfd مؤقت، وإصدار استدعاء UFFDIO_API مع تعيين features إلى الصفر. بعد أن يعود استدعاء UFFDIO_API بنجاح، يجب أن يحتوي features على جميع ميزات userfaultfd التي تدعمها النواة. يمكن إغلاق userfaultfd المؤقت بأمان بعد الاستكشاف.

إذا قام التطبيق بتعيين بتات ميزات غير مدعومة، فستقوم النواة بإعادة تعيين بنية uffdio_api المُعادة إلى الصفر وسترجع EINVAL.

قد يتم تعيين بتات الميزات التالية:

UFFD_FEATURE_EVENT_FORK (منذ Linux 4.11)
عند تمكين هذه الميزة، يتم تكرار كائنات userfaultfd المرتبطة بالعملية الأم في العملية الابنة أثناء fork(2) ويتم تسليم حدث UFFD_EVENT_FORK إلى مراقب userfaultfd.
UFFD_FEATURE_EVENT_REMAP (منذ Linux 4.11)
إذا تم تمكين هذه الميزة، فعندما تستدعي العملية المسببة للخطأ mremap(2)، سيتلقى مراقب userfaultfd حدثًا من النوع UFFD_EVENT_REMAP.
UFFD_FEATURE_EVENT_REMOVE (منذ Linux 4.11)
إذا تم تمكين هذه الميزة، فعندما تستدعي العملية المسببة للخطأ madvise(2) مع قيمة المشورة MADV_DONTNEED أو MADV_REMOVE لتحرير منطقة ذاكرة افتراضية، سيتلقى مراقب userfaultfd حدثًا من النوع UFFD_EVENT_REMOVE.
UFFD_FEATURE_EVENT_UNMAP (منذ Linux 4.11)
إذا تم تمكين هذه الميزة، فعندما تقوم العملية المسببة للخطأ بإلغاء تعيين الذاكرة الافتراضية إما صراحةً باستخدام munmap(2)، أو ضمنياً أثناء mmap(2) أو mremap(2)، سيتلقى مراقب userfaultfd حدثًا من النوع UFFD_EVENT_UNMAP.
UFFD_FEATURE_MISSING_HUGETLBFS (منذ Linux 4.11)
إذا تم تعيين بت الميزة هذا، فإن النواة تدعم تسجيل نطاقات userfaultfd على مناطق الذاكرة الافتراضية hugetlbfs.
UFFD_FEATURE_MISSING_SHMEM (منذ Linux 4.11)
إذا تم تعيين بت الميزة هذا، فإن النواة تدعم تسجيل نطاقات userfaultfd على مناطق الذاكرة المشتركة. يشمل ذلك جميع واجهات برمجة تطبيقات الذاكرة المشتركة للنواة: ذاكرة النظام V المشتركة، tmpfs(5)، تعيينات مشتركة لـ /dev/zero، mmap(2) مع تعيين علامة MAP_SHARED، memfd_create(2)، وما إلى ذلك.
UFFD_FEATURE_SIGBUS (منذ Linux 4.14)
إذا تم تعيين بت الميزة هذا، فلن يتم تسليم أي أحداث خطأ صفحة (UFFD_EVENT_PAGEFAULT). بدلاً من ذلك، سيتم إرسال إشارة SIGBUS إلى العملية المسببة للخطأ. لن تتطلب التطبيقات التي تستخدم هذه الميزة استخدام مراقب userfaultfd لمعالجة الوصول إلى الذاكرة للمناطق المسجلة مع userfaultfd.
UFFD_FEATURE_THREAD_ID (منذ Linux 4.14)
إذا تم تعيين بت الميزة هذا، فسيتم تعيين uffd_msg.pagefault.feat.ptid إلى معرف الخيط المسبب للخطأ لكل رسالة خطأ صفحة.
UFFD_FEATURE_PAGEFAULT_FLAG_WP (منذ Linux 5.10)
إذا تم تعيين بت الميزة هذا، فإن userfaultfd يدعم أخطاء الحماية من الكتابة للذاكرة المجهولة. (لاحظ أن دعم shmem / hugetlbfs مشار إليه بميزة منفصلة.)
UFFD_FEATURE_MINOR_HUGETLBFS (منذ Linux 5.13)
إذا تم تعيين بت الميزة هذا، فإن النواة تدعم تسجيل نطاقات userfaultfd في الوضع الثانوي لمناطق الذاكرة المدعومة بـ hugetlbfs.
UFFD_FEATURE_MINOR_SHMEM (منذ Linux 5.14)
إذا تم تعيين بت الميزة هذا، فإن النواة تدعم تسجيل نطاقات userfaultfd في الوضع الثانوي لمناطق الذاكرة المدعومة بـ shmem.
UFFD_FEATURE_EXACT_ADDRESS (منذ Linux 5.18)
إذا تم تعيين بت الميزة هذا، فسيتم تعيين uffd_msg.pagefault.address إلى عنوان خطأ الصفحة الدقيق الذي أبلغته الأجهزة، ولن يقوم بإخفاء الإزاحة داخل الصفحة. لاحظ أن إصدارات Linux القديمة قد تشير أيضًا إلى العنوان الدقيق، على الرغم من عدم تعيين بت الميزة.
UFFD_FEATURE_WP_HUGETLBFS_SHMEM (منذ Linux 5.19)
إذا تم تعيين بت الميزة هذا، فإن userfaultfd يدعم أخطاء الحماية من الكتابة لذاكرة hugetlbfs و shmem / tmpfs.
UFFD_FEATURE_WP_UNPOPULATED (منذ Linux 6.4)
إذا تم تعيين بت الميزة هذا، فإن النواة ستتعامل مع الذاكرة المجهولة بنفس طريقة الذاكرة الملفية، من خلال السماح للمستخدم بحماية إدخالات جدول الصفحات غير المعبأة من الكتابة.
UFFD_FEATURE_POISON (منذ Linux 6.6)
إذا تم تعيين بت الميزة هذا، فإن النواة تدعم حل الأخطاء باستخدام استدعاء UFFDIO_POISON.
UFFD_FEATURE_WP_ASYNC (منذ Linux 6.7)
إذا تم تعيين بت الميزة هذا، فسيتم حل أخطاء حماية الكتابة بشكل غير متزامن بواسطة النواة.
UFFD_FEATURE_MOVE (منذ Linux 6.8)
إذا تم تعيين بت الميزة هذا، فإن النواة تدعم حل الأخطاء باستخدام استدعاء UFFDIO_MOVE.

يمكن أن يحتوي الحقل argp->ioctls المُعاد على البتات التالية:

1 << _UFFDIO_API
عملية UFFDIO_API مدعومة.
1 << _UFFDIO_REGISTER
عملية UFFDIO_REGISTER مدعومة.
1 << _UFFDIO_UNREGISTER
عملية UFFDIO_UNREGISTER مدعومة.

قيمة الإرجاع

عند النجاح، يتم إرجاع 0.

عند حدوث خطأ، يتم إرجاع -1 وتعيين errno للإشارة إلى الخطأ.

الأخطاء

EFAULT
argp يشير إلى عنوان يقع خارج مساحة العنوان التي يمكن الوصول إليها لعملية الاستدعاء.
EINVAL
إصدار واجهة برمجة التطبيقات المطلوب في الحقل api غير مدعوم بواسطة هذه النواة، أو أن الحقل features الذي تم تمريره إلى النواة يتضمن بتات ميزات غير مدعومة بواسطة إصدار النواة الحالي.
EINVAL
تم بالفعل تمكين ميزة واحدة أو أكثر لهذه الـ userfaultfd بواسطة استدعاء UFFDIO_API سابق. يُسمح صراحةً باستدعاء UFFDIO_API مرتين، في المرة الأولى بدون تعيين أي ميزات، وفقًا لمصافحة اكتشاف الميزات المكونة من خطوتين.
EPERM
تم تمكين ميزة UFFD_FEATURE_EVENT_FORK، ولكن عملية الاستدعاء لا تمتلك صلاحية CAP_SYS_PTRACE.

تنبيهات

إذا حدث خطأ، فقد تقوم النواة بمسح البنية uffdio_api المقدمة. يجب على المتصل التعامل مع محتوياتها على أنها غير محددة، وإعادة تهيئتها قبل إعادة محاولة استدعاء UFFDIO_API آخر.

أخطاء

لكشف ميزات userfault المتاحة وتمكين مجموعة فرعية من تلك الميزات، يجب إغلاق واصف الملف userfaultfd بعد عملية UFFDIO_API الأولى التي تستعلم عن توفر الميزات، وإعادة فتحه قبل عملية UFFDIO_API الثانية التي تقوم بالفعل بتمكين الميزات المطلوبة.
