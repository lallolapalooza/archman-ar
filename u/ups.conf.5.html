ups.conf

Configuration file for NUT

NAME

ups.conf
upsd(8), nutupsdrv(8), upsdrvctl(8), upsdrvsvcctl(8)

configuration file for Network UPS Tools

DESCRIPTION

The ups.conf file is used by the upsd(8) daemon to configure the UPS devices it will manage.

It is a plain text file, organized into sections. Each section defines a UPS device or a global configuration setting.

The file is parsed line by line. Lines starting with '#' or ';' are considered comments and are ignored.

Empty lines are also ignored.

Global Directives

The following directives can be used in the global section of the configuration file (before the first UPS definition). The global section does not need a specific name.

driver.precedence
Specifies the order in which drivers should be loaded. This can be useful for overriding the default driver loading order. The value is a comma-separated list of driver names. For example: driver.precedence = usbhid,snmp-ups.
poll.interval
Sets the default polling interval (in seconds) for all UPS devices. This can be overridden by individual UPS definitions. Default is 30 seconds.
maxstartdelay
Sets the maximum delay (in seconds) before starting up the UPS. This is useful to prevent power

UPS Fields

Each UPS device is defined by a section that starts with the name of the UPS, followed by an equals sign, and then the driver name to use for that UPS.

[ups_name]
    driver = driver_name
    port = device_path
    desc = "UPS Description"
    option = value
    ...
driver
The name of the driver to use for this UPS. This is a required parameter.
port
The communication port for the UPS. This can be a serial device path (e.g., /dev/ttyS0 or /dev/ttyUSB0), a network address (e.g., 192.168.1.100), or a specific identifier for the driver. This is a required parameter for most drivers.
desc
A descriptive string for the UPS. This is optional.
poll.interval
The polling interval (in seconds) for this specific UPS. Overrides the global setting.
synchronous
Set to yes to make communication with this UPS synchronous. This can be useful for troubleshooting but may impact performance. Default is no.
off.delay
The delay (in seconds) before shutting down the UPS when the system is shutting down.
off.grace
The grace period (in seconds) during which the UPS will remain on after a shutdown command is issued, before actually shutting down. This allows connected devices to perform a clean shutdown.
nolock
Set to yes to disable file locking for this UPS. This is generally not recommended unless you know what you are doing. Default is no.
shutdown.delay
The delay (in seconds) before initiating a system shutdown when the UPS is on battery power and the battery is low.
shutdown.timeout
The timeout (in seconds) for initiating a system shutdown. If the system does not shut down within this time, NUT will proceed with shutting down the UPS.
shutdown.return
Set to yes to have the system automatically reboot after shutdown and power restoration. Default is no.
backup.method
Specifies the method for handling power failure. Possible values are best (default), first, last, wall, or a specific driver name.
backup.poweron
Specifies the time (in seconds) to wait before powering on the UPS after power is restored.
backup.chargeonly
Set to yes to keep the UPS charging and not powering connected devices until grid power is stable.
server.timeout
Timeout (in seconds) for the UPS daemon to connect to the NUT master server.

Example

# Global settings
poll.interval = 30

# APC Smart-UPS 1500 on COM1
[myups]
    driver = usbhid
    port = /dev/ttyS0
    desc = "APC Smart-UPS 1500VA"
    off.delay = 30
    shutdown.delay = 120

# Another UPS on USB
[myups2]
    driver = hidups
    port = /dev/usb/hiddev0
    desc = "CyberPower CP850PFCLCD"
    poll.interval = 60

IMPORTANT NOTES

  • The port directive is driver-specific. Consult the documentation for each driver to understand the expected format of the port value.
  • Some drivers may require additional configuration options specific to the UPS model or communication protocol. These options should also be specified within the UPS section.
  • Always test your configuration after making changes to ensure that the UPS is managed correctly and that shutdown procedures work as expected.
