This page is a manual page for umask. It is part of the Shell Commands section of the IEEE Std 1003.1-2017 (POSIX.1-2017) standard.

The page formerly had the section number 1. This was changed to 1p to distinguish it from the POSIX.1-2001 `umask(1)` page.

NAME

umask - set file mode creation mask

SYNOPSIS

umask [*mode*]

DESCRIPTION

The umask utility shall set the file mode creation mask of the current shell execution environment.

The file mode creation mask is a three-byte set of bits (or potentially more if extended ACLs are supported) that determines the default permissions that are set for files and directories when they are created. The system uses the mask to turn off permission bits.

If the *mode* argument is present, it shall be interpreted as described in OPERANDS. The umask utility shall set the file mode creation mask to the specified *mode*. If the *mode* argument is absent, the umask utility shall write the current file mode creation mask to standard output. The format of the output is implementation-defined, but it shall be in a format that can be used as a valid *mode* argument on a subsequent invocation of umask.

OPTIONS

None.

OPERANDS

The following operands shall be supported:

mode
A symbolic or octal string representing the new file mode creation mask. The interpretation of the symbolic and octal strings is the same as that used by chmod(1) for symbolic modes and octal modes, respectively, with the following exceptions:

Symbolic modes are interpreted relative to the current mask. They are not used to specify absolute permissions. For example, u+x adds execute permission for the user to the current mask (meaning that execute permission will be permitted for the user when creating files).

The symbolic mode a=rw sets the mask so that subsequent files are created with read and write permissions for user, group, and others. The symbolic modes u, g, and o specify the user, group, and other write bits, respectively. The symbolic modes r and x specify the read and execute bits, respectively.

The symbolic modes u=, g=, and o= turn off all permissions for user, group, and others respectively.

The symbolic mode a-all turns off all permissions.

The octal mode specifies the bits that are to be turned off in the file permission bits. For example, 022 means that write permission will be turned off for both the group and others.

The symbolic modes u=, g=, and o=, when used with an octal number, specify the bits that are to be turned off in the file permission bits for user, group, and others respectively. For example, u=077 sets the mask so that the user is not given any permissions and the group and others are not given any permissions.

It is implementation-defined whether the symbolic modes S (setuid/setgid bits) and t (sticky bit) are supported. If they are supported, they represent the setting of the SUID and SGID bits and the sticky bit, respectively.

The interpretation of the octal number is the same as that for the chmod utility. The octal number is interpreted as a bitmask of permissions to be disallowed.

If the mode argument begins with a hyphen-minus, it must be preceded by -- to prevent it from being interpreted as an option.

STDIN

Not used.

INPUT FILES

None.

ENVIRONMENT VARIABLES

None.

ASYNCHRONOUS EVENTS

Default.

STDOUT

When the mode argument is omitted, the current file mode creation mask is written to standard output. The format is implementation-defined. When the mode argument is present, standard output is not used.

STDERR

The standard error shall be used for diagnostic messages.

OUTPUT FILES

None.

EXTENDED DESCRIPTION

None.

EXIT STATUS

The umask utility shall exit with status 0 if the file mode creation mask was successfully set or if no *mode* argument was given. Otherwise, it shall exit with status greater than 0.

CONSEQUENCES OF ERRORS

None.

APPLICATION USAGE

The umask utility is used to control the default permissions of files created by the application. For example, umask 022 would mean that newly created files would not be writable by group or others. umask -S is used to display the current mask in symbolic format.

EXAMPLES

To display the current file mode creation mask:

umask

To display the current file mode creation mask in symbolic format:

umask -S

The output might be:

u=rwx,g=rx,o=rx

To set the file mode creation mask so that subsequently created files have their group and other write bits cleared (the default permissions are often 666 for files and 777 for directories):

umask 022

To remove the execute permission for the group and others from the current mask:

umask g-x,o-x

To remove all permissions for the group and others from the current mask:

umask g=,o=

To remove all write permissions for user, group, and others from the current mask:

umask -- -w

The command:

umask -- -w

sets the mode mask so that subsequently created files have all their write bits cleared. Note that mask operands -r, -w, -x or anything beginning with a <hyphen-minus>, must be preceded by "--" to keep it from being interpreted as an option.

RATIONALE

Since umask affects the current shell execution environment, it is generally provided as a shell regular built-in. If it is called in a subshell or separate utility execution environment, such as one of the following:

(umask 002)
nohup umask ...
find . -exec umask ... \;

it does not affect the file mode creation mask of the environment of the caller.

The description of the historical utility was modified to allow it to use the symbolic modes of chmod. The -s option used in early proposals was changed to -S because -s could be confused with a symbolic_mode form of mask referring to the S_ISUID and S_ISGID bits.

The default output style is unspecified to permit implementors to provide migration to the new symbolic style at the time most appropriate to their users. A -o flag to force octal mode output was omitted because the octal mode may not be sufficient to specify all of the information that may be present in the file mode creation mask when more secure file access permission checks are implemented.

It has been suggested that trusted systems developers might appreciate ameliorating the requirement that the mode mask ``affects'' the file access permissions, since it seems access control lists might replace the mode mask to some degree. The wording has been changed to say that it affects the file permission bits, and it leaves the details of the behavior of how they affect the file access permissions to the description in the System Interfaces volume of POSIX.1‐2017.
