unshare(2) دليل استدعاءات النظام unshare(2)

الاسم

unshare - فصل أجزاء من سياق تنفيذ العملية

المكتبة

مكتبة C القياسية (libc، -lc)

الملخص

#define _GNU_SOURCE
#include <sched.h>
int unshare(int flags);

الوصف

يسمح unshare() للعملية (أو الخيط) بفصل أجزاء من سياق تنفيذها التي تتم مشاركتها حاليًا مع عمليات (أو خيوط) أخرى. جزء من سياق التنفيذ، مثل مساحة اسم التركيب، تتم مشاركته ضمنيًا عند إنشاء عملية جديدة باستخدام fork(2) أو vfork(2)، بينما قد تتم مشاركة أجزاء أخرى، مثل الذاكرة الافتراضية، بطلب صريح عند إنشاء عملية أو خيط باستخدام clone(2).

الاستخدام الرئيسي لـ unshare() هو السماح للعملية بالتحكم في سياق تنفيذها المشترك دون إنشاء عملية جديدة.

الوسيط flags هو قناع بت يحدد أي أجزاء من سياق التنفيذ يجب فصلها. يتم تحديد هذا الوسيط عن طريق ORing صفر أو أكثر من الثوابت التالية:

CLONE_FILES
عكس تأثير علامة clone(2) CLONE_FILES. افصل جدول واصفات الملفات، بحيث لا تشارك العملية المتصلة واصفات ملفاتها مع أي عملية أخرى.
CLONE_FS
عكس تأثير علامة clone(2) CLONE_FS. افصل سمات نظام الملفات، بحيث لا تشارك العملية المتصلة دليل الجذر الخاص بها (chroot(2)) أو الدليل الحالي (chdir(2)) أو سمات umask (umask(2)) مع أي عملية أخرى.
CLONE_NEWCGROUP (منذ Linux 4.6)
هذه العلامة لها نفس تأثير علامة clone(2) CLONE_NEWCGROUP. افصل مساحة اسم cgroup. يتطلب استخدام CLONE_NEWCGROUP القدرة CAP_SYS_ADMIN.
CLONE_NEWIPC (منذ Linux 2.6.19)
هذه العلامة لها نفس تأثير علامة clone(2) CLONE_NEWIPC. افصل مساحة اسم IPC، بحيث يكون لدى العملية المتصلة نسخة خاصة من مساحة اسم IPC التي لا تتم مشاركتها مع أي عملية أخرى. تحديد هذه العلامة يتضمن تلقائيًا CLONE_SYSVSEM أيضًا. يتطلب استخدام CLONE_NEWIPC القدرة CAP_SYS_ADMIN.
CLONE_NEWNET (منذ Linux 2.6.24)
هذه العلامة لها نفس تأثير علامة clone(2) CLONE_NEWNET. افصل مساحة اسم الشبكة، بحيث يتم نقل العملية المتصلة إلى مساحة اسم شبكة جديدة لا تتم مشاركتها مع أي عملية سابقة. يتطلب استخدام CLONE_NEWNET القدرة CAP_SYS_ADMIN.
CLONE_NEWNS
هذه العلامة لها نفس تأثير علامة clone(2) CLONE_NEWNS. افصل مساحة اسم التركيب، بحيث يكون لدى العملية المتصلة نسخة خاصة من مساحة اسمها لا تتم مشاركتها مع أي عملية أخرى. تحديد هذه العلامة يتضمن تلقائيًا CLONE_FS أيضًا. يتطلب استخدام CLONE_NEWNS القدرة CAP_SYS_ADMIN. لمزيد من المعلومات، انظر mount_namespaces(7).
CLONE_NEWPID (منذ Linux 3.8)
هذه العلامة لها نفس تأثير علامة clone(2) CLONE_NEWPID. افصل مساحة اسم PID، بحيث يكون لدى العملية المتصلة مساحة اسم PID جديدة لأطفالها لا تتم مشاركتها مع أي عملية سابقة. العملية المتصلة *لا* يتم نقلها إلى مساحة الاسم الجديدة. سيكون لدى الطفل الأول الذي تم إنشاؤه بواسطة العملية المتصلة معرف العملية 1 وسيتولى دور init(1) في مساحة الاسم الجديدة. CLONE_NEWPID يتضمن تلقائيًا CLONE_THREAD أيضًا. يتطلب استخدام CLONE_NEWPID القدرة CAP_SYS_ADMIN. لمزيد من المعلومات، انظر pid_namespaces(7).
CLONE_NEWTIME (منذ Linux 5.6)
افصل مساحة اسم الوقت، بحيث يكون لدى العملية المتصلة مساحة اسم وقت جديدة لأطفالها لا تتم مشاركتها مع أي عملية سابقة. العملية المتصلة *لا* يتم نقلها إلى مساحة الاسم الجديدة. يتطلب استخدام CLONE_NEWTIME القدرة CAP_SYS_ADMIN. لمزيد من المعلومات، انظر time_namespaces(7).
CLONE_NEWUSER (منذ Linux 3.8)
هذه العلامة لها نفس تأثير علامة clone(2) CLONE_NEWUSER. افصل مساحة اسم المستخدم، بحيث يتم نقل العملية المتصلة إلى مساحة اسم مستخدم جديدة لا تتم مشاركتها مع أي عملية سابقة. كما هو الحال مع العملية التابعة التي تم إنشاؤها بواسطة clone(2) مع علامة CLONE_NEWUSER، تحصل الجهة المتصلة على مجموعة كاملة من القدرات في مساحة الاسم الجديدة.
يتطلب CLONE_NEWUSER ألا تكون العملية المتصلة متعددة الخيوط؛ يتضمن CLONE_NEWUSER تلقائيًا CLONE_THREAD. منذ Linux 3.9، يتضمن CLONE_NEWUSER أيضًا تلقائيًا CLONE_FS. يتطلب CLONE_NEWUSER أن تكون معرفات المستخدم والمجموعة للعملية المتصلة mapped إلى معرفات المستخدم والمجموعة في مساحة اسم المستخدم للعملية المتصلة في وقت المكالمة.
لمزيد من المعلومات حول مساحات أسماء المستخدمين، انظر user_namespaces(7).
CLONE_NEWUTS (منذ Linux 2.6.19)
هذه العلامة لها نفس تأثير علامة clone(2) CLONE_NEWUTS. افصل مساحة اسم UTS IPC، بحيث يكون لدى العملية المتصلة نسخة خاصة من مساحة اسم UTS لا تتم مشاركتها مع أي عملية أخرى. يتطلب استخدام CLONE_NEWUTS القدرة CAP_SYS_ADMIN.
CLONE_SYSVSEM (منذ Linux 2.6.26)
هذه العلامة تعكس تأثير علامة clone(2) CLONE_SYSVSEM. افصل قيم تعديل semafor System V (semadj)، بحيث يكون لدى العملية المتصلة قائمة semadj فارغة جديدة لا تتم مشاركتها مع أي عملية أخرى. إذا كانت هذه هي العملية الأخيرة التي لديها مرجع لقائمة semadj الحالية للعملية، فسيتم تطبيق التعديلات في تلك القائمة على semafor المقابلة، كما هو موضح في semop(2).

بالإضافة إلى ذلك، يمكن تحديد CLONE_THREAD و CLONE_SIGHAND و CLONE_VM في flags إذا كانت الجهة المتصلة أحادية الخيط (أي أنها لا تشارك مساحة عنوانها مع عملية أو خيط آخر). في هذه الحالة، ليس لهذه العلامات أي تأثير. (لاحظ أيضًا أن تحديد CLONE_THREAD يتضمن تلقائيًا CLONE_VM، وتحديد CLONE_VM يتضمن تلقائيًا CLONE_SIGHAND.) إذا كانت العملية متعددة الخيوط، فإن استخدام هذه العلامات يؤدي إلى حدوث خطأ.

إذا تم تحديد flags كصفر، فإن unshare() لا تفعل شيئًا؛ لا يتم إجراء أي تغييرات على سياق تنفيذ العملية المتصلة.

قيمة الإرجاع

عند النجاح، يتم إرجاع صفر. عند الفشل، يتم إرجاع -1 ويتم تعيين errno للإشارة إلى الخطأ.

الأخطاء

EINVAL
تم تحديد بت غير صالح في flags.
EINVAL
تم تحديد CLONE_THREAD أو CLONE_SIGHAND أو CLONE_VM في flags، والجهة المتصلة متعددة الخيوط.
EPERM
لم يكن لدى العملية المتصلة القدرة CAP_SYS_ADMIN المطلوبة لإنشاء مساحات أسماء جديدة (CLONE_NEWCGROUP، CLONE_NEWIPC، CLONE_NEWNET، CLONE_NEWNS، CLONE_NEWPID، CLONE_NEWTIME، CLONE_NEWUSER، CLONE_NEWUTS). لمساحات أسماء المستخدمين، قد يكون الخطأ أيضًا نتيجة لعدم إمكانية تعيين معرفات المستخدم والمجموعة للعملية المتصلة في مساحة اسم المستخدم الجديدة.
ENOMEM
فشل تخصيص الذاكرة اللازمة لإنشاء مساحات الأسماء الجديدة.

المعايير

تمت إضافة استدعاء النظام unshare() إلى Linux 2.6.19. العديد من العلامات الموضحة هنا تمثل أجزاء من سياق التنفيذ الذي تم تقديمه مع عزل مساحات الأسماء، والتي تهدف إلى دعم المفهوم الجديد لحاويات Linux. يمكن العثور على تفاصيل حول تفاعل هذه العلامات في المستندات الخاصة بمساحات الأسماء ذات الصلة (على سبيل المثال، pid_namespaces(7)).

ERRORS

EINVAL
تم تحديد CLONE_NEWIPC في flags، ولكن لم يتم تكوين النواة مع خيارات CONFIG_SYSVIPC و CONFIG_IPC_NS.
EINVAL
تم تحديد CLONE_NEWNET في flags، ولكن لم يتم تكوين النواة مع خيار CONFIG_NET_NS.
EINVAL
تم تحديد CLONE_NEWPID في flags، ولكن لم يتم تكوين النواة مع خيار CONFIG_PID_NS.
EINVAL
تم تحديد CLONE_NEWUSER في flags، ولكن لم يتم تكوين النواة مع خيار CONFIG_USER_NS.
EINVAL
تم تحديد CLONE_NEWUTS في flags، ولكن لم يتم تكوين النواة مع خيار CONFIG_UTS_NS.
EINVAL
تم تحديد CLONE_NEWPID في flags، ولكن العملية قامت بالفعل باستدعاء unshare() مع العلامة CLONE_NEWPID.
ENOMEM
لا يمكن تخصيص ذاكرة كافية لنسخ أجزاء من سياق المتصل التي تحتاج إلى فصل.
ENOSPC (منذ لينكس 3.7)
تم تحديد CLONE_NEWPID في flags، ولكن تم تجاوز الحد الأقصى لعمق تداخل مساحات أسماء PID؛ انظر pid_namespaces(7).
ENOSPC (منذ لينكس 4.9؛ سابقًا EUSERS)
تم تحديد CLONE_NEWUSER في flags، واستدعاء العملية قد يؤدي إلى تجاوز الحد الأقصى لعدد مساحات أسماء المستخدم المتداخلة. انظر user_namespaces(7).
من لينكس 3.11 إلى لينكس 4.8، كان الخطأ الذي تم تشخيصه في هذه الحالة هو EUSERS.
ENOSPC (منذ لينكس 4.9)
إحدى القيم في flags حددت إنشاء مساحة أسماء مستخدم جديدة، ولكن القيام بذلك كان سيؤدي إلى تجاوز الحد المحدد في الملف المقابل في /proc/sys/user. لمزيد من التفاصيل، انظر namespaces(7).
EPERM
لم تكن لدى العملية المتصلة الامتيازات المطلوبة لهذه العملية.
EPERM
تم تحديد CLONE_NEWUSER في flags، ولكن إما معرف المستخدم الفعال أو معرف المجموعة الفعال للمتصل ليس له تخطيط في مساحة الأسماء الأم (انظر user_namespaces(7)).
EPERM (منذ لينكس 3.9)
تم تحديد CLONE_NEWUSER في flags والمتصل موجود في بيئة chroot (أي أن دليل الجذر للمتصل لا يتطابق مع دليل الجذر لمساحة الأسماء التي يوجد فيها).
EUSERS (من لينكس 3.11 إلى لينكس 4.8)
تم تحديد CLONE_NEWUSER في flags، وسيتم تجاوز الحد الأقصى لعدد مساحات أسماء المستخدم المتداخلة. انظر مناقشة خطأ ENOSPC أعلاه.

ملاحظات

ليست كل سمات العملية التي يمكن مشاركتها عند إنشاء عملية جديدة باستخدام clone(2) يمكن فصلها باستخدام unshare(). على وجه الخصوص، كما في النواة 3.8، لا يقوم unshare() بتنفيذ العلامات التي تعكس تأثيرات CLONE_SIGHAND، CLONE_THREAD، أو CLONE_VM. قد تضاف مثل هذه الوظائف في المستقبل، إذا لزم الأمر.

إنشاء جميع أنواع مساحات الأسماء، باستثناء مساحات أسماء المستخدم، يتطلب الامتياز CAP_SYS_ADMIN. ومع ذلك، نظرًا لأن إنشاء مساحة أسماء مستخدم تمنح تلقائيًا مجموعة كاملة من الامتيازات، فإن إنشاء كل من مساحة أسماء مستخدم وأي نوع آخر من مساحات الأسماء في نفس استدعاء unshare() لا يتطلب امتياز CAP_SYS_ADMIN في مساحة الأسماء الأصلية.

أمثلة

يوفر البرنامج أدناه تطبيقًا بسيطًا لأمر unshare(1)، الذي يفصل مساحات أسماء واحدة أو أكثر وينفذ الأمر المقدم في وسيطات سطر الأوامر. إليك مثال على استخدام هذا البرنامج، وتشغيل shell في مساحة أسماء تحميل جديدة، والتحقق من أن shell الأصلي و shell الجديد موجودان في مساحات أسماء تحميل منفصلة:


$ readlink /proc/$$/ns/mnt;
mnt:[4026531840]
$ sudo ./unshare -m /bin/bash;
# readlink /proc/$$/ns/mnt;
mnt:[4026532325]

يظهر الإخراج المختلف لأمري readlink(1) أن shellين مختلفين في مساحات أسماء تحميل مختلفة.

مصدر البرنامج

/* unshare.c
   A simple implementation of the unshare(1) command: unshare
   namespaces and execute a command.
*/
#define _GNU_SOURCE
#include <err.h>
#include <sched.h>
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
static void
usage(char *pname)
{
    fprintf(stderr, "Usage: %s [options] program [arg...]\n", pname);
    fprintf(stderr, "Options can be:\n");
    fprintf(stderr, "    -C   unshare cgroup namespace\n");
    fprintf(stderr, "    -i   unshare IPC namespace\n");
    fprintf(stderr, "    -m   unshare mount namespace\n");
    fprintf(stderr, "    -n   unshare network namespace\n");
    fprintf(stderr, "    -p   unshare PID namespace\n");
    fprintf(stderr, "    -t   unshare time namespace\n");
    fprintf(stderr, "    -u   unshare UTS namespace\n");
    fprintf(stderr, "    -U   unshare user namespace\n");
    exit(EXIT_FAILURE);
}
int
main(int argc, char *argv[])
{
    int flags, opt;
    flags = 0;
    while ((opt = getopt(argc, argv, "CimnptuU")) != -1) {
        switch (opt) {
        case 'C': flags |= CLONE_NEWCGROUP;     break;
        case 'i': flags |= CLONE_NEWIPC;        break;
        case 'm': flags |= CLONE_NEWNS;         break;
        case 'n': flags |= CLONE_NEWNET;        break;
        case 'p': flags |= CLONE_NEWPID;        break;
        case 't': flags |= CLONE_NEWTIME;       break;
        case 'u': flags |= CLONE_NEWUTS;        break;
        case 'U': flags |= CLONE_NEWUSER;       break;
        default:  usage(argv[0]);
        }
    }
    if (optind >= argc)
        usage(argv[0]);
    if (unshare(flags) == -1)
        err(EXIT_FAILURE, "unshare");
    execvp(argv[optind], &argv[optind]);
    err(EXIT_FAILURE, "execvp");
}
