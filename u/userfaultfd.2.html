userfaultfd(2)

userfaultfd(2) دليل استدعاءات النظام userfaultfd(2)

الاسم

userfaultfd - إنشاء واصف ملف لمعالجة أخطاء الصفحة في مساحة المستخدم

المكتبة

مكتبة C القياسية (libc, -lc)

الملخص

#include <fcntl.h>             /* تعريف الثوابت O_* */
#include <sys/syscall.h>       /* تعريف الثوابت SYS_* */
#include <linux/userfaultfd.h> /* تعريف الثوابت UFFD_* */
#include <unistd.h>
int syscall(SYS_userfaultfd, int flags);

ملاحظة: لا توفر glibc غلافًا لـ userfaultfd()، مما يتطلب استخدام syscall(2).

الوصف

يقوم userfaultfd() بإنشاء كائن userfaultfd جديد يمكن استخدامه لتفويض معالجة أخطاء الصفحة إلى تطبيق مساحة المستخدم، ويعيد واصف ملف يشير إلى الكائن الجديد. يتم تكوين كائن userfaultfd الجديد باستخدام ioctl(2).

بمجرد تكوين كائن userfaultfd، يمكن للتطبيق استخدام read(2) لتلقي إشعارات userfaultfd. قد تكون القراءات من userfaultfd محظورة أو غير محظورة، اعتمادًا على قيمة flags المستخدمة لإنشاء userfaultfd أو الاستدعاءات اللاحقة لـ fcntl(2).

يمكن أن تكون القيم التالية ORed بيتياً في flags لتغيير سلوك userfaultfd():

O_CLOEXEC
تمكين علامة الإغلاق عند التنفيذ لواصف ملف userfaultfd الجديد. انظر وصف علامة O_CLOEXEC في open(2).
O_NONBLOCK
تمكين التشغيل غير المحظور لكائن userfaultfd. انظر وصف علامة O_NONBLOCK في open(2).
UFFD_USER_MODE_ONLY
هذه علامة خاصة بـ userfaultfd تم تقديمها في Linux 5.11. عند تعيينها، سيكون كائن userfaultfd قادرًا فقط على معالجة أخطاء الصفحة التي نشأت من مساحة المستخدم على المناطق المسجلة. عند حدوث خطأ صفحة من أصل النواة على النطاق المسجل مع userfaultfd هذا، سيتم تسليم إشارة SIGBUS.

عند إغلاق آخر واصف ملف يشير إلى كائن userfaultfd، يتم إلغاء تسجيل جميع نطاقات الذاكرة التي تم تسجيلها مع الكائن ويتم مسح الأحداث غير المقروءة.

يدعم Userfaultfd ثلاثة أوضاع للتسجيل:

UFFDIO_REGISTER_MODE_MISSING (منذ Linux 4.10)
عند التسجيل بوضع UFFDIO_REGISTER_MODE_MISSING، ستتلقى مساحة المستخدم إشعارًا بخطأ الصفحة عند الوصول إلى صفحة مفقودة. سيتوقف الخيط ذو الخطأ عن التنفيذ حتى يتم حل خطأ الصفحة من مساحة المستخدم بواسطة استدعاء ioctl إما UFFDIO_COPY أو UFFDIO_ZEROPAGE.
UFFDIO_REGISTER_MODE_MINOR (منذ Linux 5.13)
عند التسجيل بوضع UFFDIO_REGISTER_MODE_MINOR، ستتلقى مساحة المستخدم إشعارًا بخطأ الصفحة عند حدوث خطأ صفحة ثانوي. هذا يعني، عندما تكون صفحة الدعم موجودة في ذاكرة التخزين المؤقت للصفحات، ولكن لم يتم إنشاء إدخالات جدول الصفحات بعد. سيتوقف الخيط ذو الخطأ عن التنفيذ حتى يتم حل خطأ الصفحة من مساحة المستخدم بواسطة استدعاء ioctl UFFDIO_CONTINUE.
UFFDIO_REGISTER_MODE_WP (منذ Linux 5.7)
عند التسجيل بوضع UFFDIO_REGISTER_MODE_WP، ستتلقى مساحة المستخدم إشعارًا بخطأ الصفحة عند الكتابة إلى صفحة محمية من الكتابة. سيتوقف الخيط ذو الخطأ عن التنفيذ حتى تقوم مساحة المستخدم بإزالة الحماية من الكتابة للصفحة باستخدام استدعاء ioctl UFFDIO_WRITEPROTECT.

يمكن تمكين أوضاع متعددة في نفس الوقت لنفس نطاق الذاكرة.

منذ Linux 4.14، يمكن لإشعار خطأ صفحة userfaultfd تضمين معلومات معرّف الخيط ذي الخطأ بشكل انتقائي في الإشعار. يحتاج المرء إلى تمكين هذه الميزة صراحةً باستخدام بت الميزة UFFD_FEATURE_THREAD_ID عند تهيئة سياق userfaultfd. بشكل افتراضي، يكون الإبلاغ عن معرّف الخيط معطلاً.

الاستخدام

تم تصميم آلية userfaultfd للسماح لخيط في برنامج متعدد الخيوط بأداء ترقيم الصفحات في مساحة المستخدم للخيوط الأخرى في العملية. عند حدوث خطأ في الصفحة لأحد النطاقات المسجلة في كائن userfaultfd، يتم إيقاف الخيط ذي الخطأ مؤقتًا ويتم إنشاء حدث يمكن قراءته عبر واصف ملف userfaultfd. يقرأ خيط معالجة الأخطاء الأحداث من واصف الملف هذا ويعالجها باستخدام العمليات الموضحة في ioctl_userfaultfd(2). عند معالجة أحداث خطأ الصفحة، يمكن لخيط معالجة الأخطاء تشغيل استيقاظ للخيط المتوقف.

من الممكن أن تعمل الخيوط التي تسبب الأخطاء والخيوط التي تعالج الأخطاء في سياق عمليات مختلفة. في هذه الحالة، قد تنتمي هذه الخيوط إلى برامج مختلفة، ولن يتعاون البرنامج الذي ينفذ الخيوط التي تسبب الأخطاء بالضرورة مع البرنامج الذي يعالج أخطاء الصفحة. في الوضع غير التعاوني هذا، يحتاج البرنامج الذي يراقب userfaultfd ويعالج أخطاء الصفحة إلى الوعي بالتغييرات في تخطيط الذاكرة الظاهرية للعملية التي تسبب الأخطاء لتجنب تلف الذاكرة.

منذ Linux 4.11، يمكن لـ userfaultfd أيضًا إخطار خيوط معالجة الأخطاء بالتغييرات في تخطيط الذاكرة الظاهرية للعملية التي تسبب الأخطاء. بالإضافة إلى ذلك، إذا قامت العملية التي تسبب الأخطاء باستدعاء fork(2)، فقد يتم تكرار كائنات userfaultfd المرتبطة بالعملية الأم إلى العملية الابنة وسيتم إخطار مراقب userfaultfd (عبر UFFD_EVENT_FORK الموضح أدناه) بواصف الملف المرتبط بكائنات userfault التي تم إنشاؤها للعملية الابنة، مما يسمح لمراقب userfaultfd بأداء ترقيم الصفحات في مساحة المستخدم للعملية الابنة. على عكس أخطاء الصفحة التي يجب أن تكون متزامنة وتتطلب استيقاظًا صريحًا أو ضمنيًا، يتم تسليم جميع الأحداث الأخرى بشكل غير متزامن وتستأنف العملية غير التعاونية التنفيذ بمجرد قيام مدير userfaultfd بتنفيذ read(2). يجب على مدير userfaultfd مزامنة استدعاءات UFFDIO_COPY بعناية مع معالجة الأحداث.

نموذج التسليم غير المتزامن الحالي للأحداث مثالي لتطبيقات مدير userfaultfd غير التعاوني أحادي الخيط.

منذ Linux 5.7، قادر userfaultfd على تتبع الصفحات المتسخة بشكل متزامن باستخدام وضع تسجيل الحماية من الكتابة الجديد. يجب على المرء التحقق مقابل بت الميزة UFFD_FEATURE_PAGEFAULT_FLAG_WP قبل استخدام هذه الميزة. على غرار وضع userfaultfd المفقود الأصلي، سيقوم وضع الحماية من الكتابة بإنشاء إشعار userfaultfd عند كتابة الصفحة المحمية. يحتاج المستخدم إلى حل خطأ الصفحة عن طريق إزالة الحماية من الصفحة التي حدث فيها الخطأ وتشغيل الخيط ذي الخطأ للمتابعة. لمزيد من المعلومات، يرجى الرجوع إلى قسم "وضع الحماية من الكتابة في userfaultfd".

عملية Userfaultfd

بعد إنشاء كائن userfaultfd باستخدام userfaultfd()، يجب على التطبيق تمكينه باستخدام عملية UFFDIO_API ioctl(2). تسمح هذه العملية بتسليم مصافحة من خطوتين بين النواة ومساحة المستخدم لتحديد إصدار API والميزات التي تدعمها النواة، ثم لتمكين تلك الميزات التي تريدها مساحة المستخدم. يجب تنفيذ هذه العملية قبل أي عمليات ioctl(2) أخرى موصوفة أدناه (وإلا ستفشل تلك العمليات بالخطأ EINVAL).

بعد عملية UFFDIO_API ناجحة، يقوم التطبيق بعد ذلك بتسجيل نطاقات عناوين الذاكرة باستخدام عملية UFFDIO_REGISTER ioctl(2). بعد اكتمال عملية UFFDIO_REGISTER بنجاح، سيقوم النواة بتحويل خطأ الصفحة الذي يحدث في نطاق الذاكرة المطلوب، والذي يفي بالوضع المحدد في وقت التسجيل، إلى التطبيق في مساحة المستخدم. يمكن للتطبيق بعد ذلك استخدام مختلف (مثل، UFFDIO_COPY، UFFDIO_ZEROPAGE، أو UFFDIO_CONTINUE) mremap(2).

remap.len
الحجم الأصلي لنطاق الذاكرة الذي تمت إعادة تعيينه باستخدام mremap(2).
remove.start
عنوان البداية لنطاق الذاكرة الذي تم تحريره باستخدام madvise(2) أو إلغاء تعيينه
remove.end
عنوان النهاية لنطاق الذاكرة الذي تم تحريره باستخدام madvise(2) أو إلغاء تعيينه

يمكن أن تفشل عملية read(2) على واصف ملف userfaultfd مع الأخطاء التالية:

EINVAL
لم يتم تمكين كائن userfaultfd بعد باستخدام عملية UFFD_API ioctl(2)

إذا كان العلم O_NONBLOCK ممكّنًا في وصف الملف المفتوح المرتبط، فيمكن مراقبة واصف ملف userfaultfd باستخدام poll(2) و select(2) و epoll(7). عند توفر الأحداث، يشير واصف الملف إلى أنه قابل للقراءة. إذا لم يكن العلم O_NONBLOCK ممكّنًا، فإن poll(2) (دائمًا) يشير إلى الملف على أنه يحتوي على شرط POLLERR، ويشير select(2) إلى واصف الملف على أنه قابل للقراءة والكتابة.

قيمة الإرجاع

عند النجاح، ترجع userfaultfd() واصف ملف جديد يشير إلى كائن userfaultfd. عند حدوث خطأ، يتم إرجاع -1، ويتم تعيين errno للإشارة إلى الخطأ.

الأخطاء

EINVAL
تم تحديد قيمة غير مدعومة في flags.
EMFILE
تم الوصول إلى حد العملية لكل عملية لعدد واصفات الملفات المفتوحة
ENFILE
تم الوصول إلى الحد على مستوى النظام لعدد الملفات المفتوحة الإجمالي.
ENOMEM
كانت ذاكرة النواة غير كافية متاحة.
EPERM (منذ Linux 5.2)
المتصل ليس لديه امتيازات (ليس لديه القدرة CAP_SYS_PTRACE في مساحة اسم المستخدم الأولية)، و /proc/sys/vm/unprivileged_userfaultfd له القيمة 0.

ملاحظات

يمكن استخدام آلية userfaultfd كبديل لتقنيات تبديل الصفحات التقليدية في مساحة المستخدم القائمة على استخدام إشارة SIGSEGV و mmap(2). يمكن أيضًا استخدامها لتطبيق الاستعادة الكسولة لآليات النسخ الاحتياطي/الاستعادة، وكذلك الهجرة بعد النسخ للسماح بتنفيذ (شبه متواصل) عند نقل الأجهزة الافتراضية وحاويات Linux من مضيف إلى آخر.

الأخطاء

إذا كان UFFD_FEATURE_EVENT_FORK ممكّنًا وتم مقاطعة استدعاء نظام من عائلة fork(2) بواسطة إشارة أو فشل، فقد يتم إنشاء واصف userfaultfd قديم. في هذه الحالة، سيتم تسليم UFFD_EVENT_FORK مضلل لمراقب userfaultfd.

أمثلة

يوضح البرنامج أدناه استخدام آلية userfaultfd. ينشئ البرنامج خيطين، أحدهما يعمل كمعالج لخطأ الصفحة للعملية، للصفحات في منطقة صفرية ذات صفحة عند الطلب تم إنشاؤها باستخدام mmap(2).

يأخذ البرنامج وسيطة سطر أوامر واحدة، وهي عدد الصفحات التي سيتم إنشاؤها في تعيين سيتم معالجة أخطاء صفحاته عبر userfaultfd. بعد إنشاء كائن userfaultfd، يقوم البرنامج بعد ذلك بإنشاء تعيين خاص مجهول بالحجم المحدد وتسجيل نطاق العناوين لهذا التعيين باستخدام عملية UFFDIO_REGISTER ioctl(2). ثم يقوم البرنامج بإنشاء خيط ثانٍ سيؤدي مهمة معالجة أخطاء الصفحات.

يتنقل الخيط الرئيسي بعد ذلك عبر صفحات التعيين التي تسترد بايتات من صفحات متتالية. نظرًا لأنه لم يتم الوصول إلى الصفحات بعد، فإن الوصول الأول لبايت في كل صفحة سيؤدي إلى حدث خطأ صفحة على واصف ملف userfaultfd.

يتم معالجة كل خطأ من أخطاء الصفحات بواسطة الخيط الثاني، والذي يجلس في حلقة تعالج المدخلات من واصف ملف userfaultfd. في كل تكرار للحلقة، يقوم الخيط الثاني أولاً باستدعاء poll(2) للتحقق من حالة واصف الملف، ثم يقرأ حدثًا من واصف الملف. يجب أن تكون جميع هذه الأحداث أحداث UFFD_EVENT_PAGEFAULT، والتي يعالجها الخيط عن طريق نسخ صفحة من البيانات إلى المنطقة المسببة للخطأ باستخدام عملية UFFDIO_COPY ioctl(2).

مصدر البرنامج

/* userfaultfd_demo.c
   مرخص بموجب ترخيص جنو العام العام الإصدار 2 أو أحدث.
*/
#define _GNU_SOURCE
#include <err.h>
#include <errno.h>
#include <fcntl.h>
#include <inttypes.h>
#include <linux/userfaultfd.h>
#include <poll.h>
#include <pthread.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/ioctl.h>
#include <sys/mman.h>
#include <sys/syscall.h>
#include <unistd.h>
static int page_size;
static void *
fault_handler_thread(void *arg)
{
    int                 nready;
    long                uffd;   /* واصف ملف userfaultfd */
    ssize_t             nread;
    struct pollfd       pollfd;
    struct uffdio_copy  uffdio_copy;
    static int      fault_cnt = 0; /* عدد الأخطاء التي تم التعامل معها حتى الآن */
    static char     *page = NULL;
    static struct uffd_msg  msg;  /* البيانات المقروءة من userfaultfd */
    uffd = (long) arg;
    /* إنشاء صفحة سيتم نسخها إلى المنطقة المسببة للخطأ.  */
    if (page == NULL) {
        page = mmap(NULL, page_size, PROT_READ | PROT_WRITE,
                    MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
        if (page == MAP_FAILED)
            err(EXIT_FAILURE, "mmap");
    }
    /* حلقة، ومعالجة الأحداث الواردة على واصف ملف userfaultfd
       .  */
    for (;;) {
        /* انظر ما يخبرنا به poll() عن userfaultfd.  */
        pollfd.fd = uffd;
        pollfd.events = POLLIN;
        nready = poll(&pollfd, 1, -1);
        if (nready == -1)
            err(EXIT_FAILURE, "poll");
        printf("\nfault_handler_thread():\n");
        printf("    poll() returns: nready = %d; "
               "POLLIN = %d; POLLERR = %d\n", nready,
               (pollfd.revents & POLLIN) != 0,
               (pollfd.revents & POLLERR) != 0);
        /* قراءة حدث من userfaultfd.  */
        nread = read(uffd, &msg, sizeof(msg));
        if (nread == 0) {
            printf("EOF on userfaultfd!\n");
            exit(EXIT_FAILURE);
        }
        if (nread == -1)
            err(EXIT_FAILURE, "read");
        /* نتوقع نوعًا واحدًا فقط من الأحداث؛ التحقق من هذا الافتراض.  */
        if (msg.event != UFFD_EVENT_PAGEFAULT) {
            fprintf(stderr, "Unexpected event on userfaultfd\n");
            exit(EXIT_FAILURE);
        }
        /* عرض معلومات حول حدث خطأ الصفحة.  */
        printf("    UFFD_EVENT_PAGEFAULT event: ");
        printf("flags = %"PRIx64"; ", msg.arg.pagefault.flags);
        printf("address = %"PRIx64"\n", msg.arg.pagefault.address);
        /* نسخ الصفحة التي يشير إليها 'page' إلى المنطقة المسببة للخطأ
           .  تغيير المحتويات التي يتم نسخها، بحيث يكون أكثر وضوحًا أن كل خطأ
           يتم التعامل معه بشكل منفصل.  */
        memset(page, 'A' + fault_cnt % 20, page_size);
        fault_cnt++;
        uffdio_copy.src = (unsigned long) page;
        /* نحتاج إلى التعامل مع أخطاء الصفحات بوحدات الصفحات (!).
           لذلك، تقريب العنوان المسبب للخطأ إلى بداية الصفحة.  */
        uffdio_copy.dst = (unsigned long) msg.arg.pagefault.address &
                                           ~(page_size - 1);
        uffdio_copy.len = page_size;
        uffdio_copy.mode = 0;
        uffdio_copy.copy = 0;
        if (ioctl(uffd, UFFDIO_COPY, &uffdio_copy) == -1)
            err(EXIT_FAILURE, "ioctl-UFFDIO_COPY");
        printf("        (uffdio_copy.copy returned %"PRId64")\n",
               uffdio_copy.copy);
    }
}
int
main(int argc, char *argv[])
{
    int        s;
    char       c;
    char       *addr;   /* بداية المنطقة التي يعالجها userfaultfd */
    long       uffd;    /* واصف ملف userfaultfd */
    size_t     size, i;  /* حجم المنطقة التي يعالجها userfaultfd */
    pthread_t  thr;     /* معرف الخيط الذي يعالج أخطاء الصفحات */
    struct uffdio_api       uffdio_api;
