الوصف

Unbound هو تطبيق لمحلل DNS، يقوم بالتخزين المؤقت والتحقق من DNSSEC. هذه هي واجهة برمجة التطبيقات للمكتبة، لاستخدام مكتبة -lunbound. يتم وصف خادم الخدمة في unbound(8). تعمل المكتبة بشكل مستقل عن خادم unbound قيد التشغيل، ويمكن استخدامها لتحويل أسماء المضيفين إلى عناوين IP، والعكس، والحصول على معلومات أخرى من DNS. تقوم المكتبة بإجراء التحقق بالمفتاح العام للنتائج باستخدام DNSSEC.

تستخدم المكتبة متغيرًا من النوع struct ub_ctx للحفاظ على السياق بين الاستدعاءات. يجب على المستخدم الاحتفاظ به، وإنشاؤه باستخدام ub_ctx_create وحذفه باستخدام ub_ctx_delete. يمكن إنشاؤه وحذفه في أي وقت. يؤدي إنشاؤه من جديد إلى إزالة أي تكوين سابق (مثل المفاتيح الموثوقة) ومسح أي نتائج مخزنة مؤقتًا.

الدوال آمنة للخيوط، ويمكن استخدام السياق في بيئة متعددة الخيوط (وكذلك في بيئة غير متعددة الخيوط). كما يمكن إجراء التحليل (والتحقق) بشكل حاجب وغير حاجب (يُسمى أيضًا غير متزامن). تعود الطريقة غير المتزامنة من الاستدعاء فورًا، بحيث يمكن أن تستمر المعالجة، بينما تصبح النتائج متاحة لاحقًا.

تتم مناقشة الدوال واحدة تلو الأخرى أدناه.

الدوال

ub_ctx_create
إنشاء سياق جديد، مهيأ بالإعدادات الافتراضية. لا يتم استخدام المعلومات من /etc/resolv.conf و /etc/hosts افتراضيًا. استخدم ub_ctx_resolvconf و ub_ctx_hosts لقراءتها. قبل استدعاء هذا، استخدم دوال openssl CRYPTO_set_id_callback و CRYPTO_set_locking_callback لإعداد العملية غير المتزامنة إذا كنت تستخدم lib openssl (يستدعي التطبيق هذه الدوال مرة واحدة للتهيئة). يستخدم Openssl 1.0.0 أو أحدث دالة CRYPTO_THREADID_set_callback.
ub_ctx_delete
حذف سياق التحقق وتحرير الموارد المرتبطة به. يتم إلغاء الاستعلامات غير المتزامنة المعلقة ولا يتم استدعاء ردود النداء الخاصة بها.
ub_ctx_set_option
واجهة للمستخدم المتقدم تتيح لك تحديد أحد الخيارات من تنسيق ملف التكوين، انظر unbound.conf(5). ليست كل الخيارات ذات صلة. بالنسبة لبعض الخيارات المحددة، مثل إضافة مراسي الثقة، توجد إجراءات خاصة. مرر اسم الخيار مع ':' اللاحقة.
ub_ctx_get_option
واجهة للمستخدم المتقدم تحصل على قيمة خيار. بعض الخيارات لا يمكن الحصول عليها، والبعض الآخر يعيد قائمة مفصولة بسطر جديد. مرر اسم الخيار بدون ':' اللاحقة. يجب على المستدعي تحرير القيمة المُعادة باستخدام free(2).
ub_ctx_config
واجهة للمستخدم المتقدم تتيح لك تحديد ملف تكوين unbound، انظر unbound.conf(5)، الذي يُقرأ للتكوين. ليست كل الخيارات ذات صلة. بالنسبة لبعض الخيارات المحددة، مثل إضافة مراسي الثقة، توجد إجراءات خاصة. هذه الدالة آمنة للخيوط فقط إذا كان هناك نسخة واحدة من ub_ctx* موجودة في التطبيق. إذا وُجدت عدة نسخ يجب على التطبيق التأكد من عدم استدعاء ub_ctx_config بالتوازي من قبل النسخ المختلفة.
ub_ctx_set_fwd
تعيين الجهاز لإعادة توجيه استعلامات DNS إليه، وهو محلل التخزين المؤقت المراد استخدامه. عنوان IP4 أو IP6. يعيد توجيه جميع طلبات DNS إلى ذلك الجهاز، والذي يُتوقع أن يشغل محللًا تعاوديًا. إذا لم يكن الوكيل قادرًا على DNSSEC، فقد يفشل التحقق. يمكن استدعاؤه عدة مرات، وفي هذه الحالة تُستخدم العناوين كخوادم احتياطية. في هذا الوقت، من الممكن فقط تعيين التكوين قبل إجراء أول تحليل.
ub_ctx_set_stub
تعيين منطقة stub، خوادم DNS الموثوقة لاستخدامها لمنطقة معينة. عنوان IP4 أو IP6. إذا كان العنوان NULL تتم إزالة إدخال stub. عيّن isprime إلى true إذا كنت تُكوّن تلميحات الجذر به. بخلاف ذلك مشابه لعنصر منطقة stub من ملف تكوين unbound. يمكن استدعاؤه عدة مرات، لمناطق مختلفة، أو لإضافة عناوين متعددة لمنطقة معينة. في هذا الوقت، من الممكن فقط تعيين التكوين قبل إجراء أول تحليل.
ub_ctx_set_tls
تمكين DNS عبر TLS (DoT) للأجهزة المعينة باستخدام ub_ctx_set_fwd. في هذا الوقت، من الممكن فقط تعيين التكوين قبل إجراء أول تحليل.
ub_ctx_resolvconf
افتراضيًا يتم الاستعلام عن خوادم الجذر ويُستخدم وضع المحلل الكامل، ولكن يمكنك استخدام هذا الاستدعاء لقراءة قائمة خوادم الأسماء المراد استخدامها من اسم الملف المعطى. عادةً "/etc/resolv.conf". يستخدم خوادم الأسماء هذه كوكلاء تخزين مؤقت. إذا لم تكن تدعم DNSSEC، فقد يفشل التحقق. يتم التقاط خوادم الأسماء فقط، ويتم تجاهل searchdomain و ndots والإعدادات الأخرى من resolv.conf(5). إذا تم تمرير fname بقيمة NULL، يُستخدم "/etc/resolv.conf" (إذا كنت على Windows، يتم اختيار خادم الأسماء المُكوّن على مستوى النظام بدلاً من ذلك). في هذا الوقت، من الممكن فقط تعيين التكوين قبل إجراء أول تحليل.
ub_ctx_hosts
قراءة قائمة المضيفين من اسم الملف المعطى. عادةً "/etc/hosts". عند الاستعلام عنها، لا يتم تمييز هذه العناوين كآمنة DNSSEC. إذا تم تمرير fname بقيمة NULL، يُستخدم "/etc/hosts" (إذا كنت على Windows، يتم اختيار etc/hosts من WINDIR بدلاً من ذلك). في هذا الوقت، من الممكن فقط تعيين التكوين قبل إجراء أولتم الحل.
ub_ctx_add_ta
إضافة مرساة ثقة إلى السياق المحدد. في هذا الوقت، لا يمكن إلا إضافة مفاتيح موثوقة قبل إجراء أول حل. التنسيق هو سلسلة، مشابهة لتنسيق ملف المنطقة، [domainname] [type] [rdata contents]. يتم قبول سجلات DS وDNSKEY معًا.
ub_ctx_add_ta_autr
إضافة اسم ملف مع مرساة ثقة يتم تتبعها تلقائيًا إلى السياق المحدد. مرر اسم ملف مع مرساة الثقة المُدارة. يمكنك إنشاء هذا الملف باستخدام unbound-anchor(8) لمرساة الجذر. يمكنك أيضًا إنشاؤه بملف أولي يحتوي على سطر واحد مع سجل DNSKEY أو DS. إذا كان الملف قابلاً للكتابة، يتم تحديثه عند تغير مرساة الثقة. في هذا الوقت، لا يمكن إلا إضافة مفاتيح موثوقة قبل إجراء أول حل .
ub_ctx_add_ta_file
إضافة مراسي ثقة إلى السياق المحدد. مرر اسم ملف مع سجلات DS و DNSKEY بتنسيق ملف المنطقة. في هذا الوقت، لا يمكن إلا إضافة مفاتيح موثوقة قبل إجراء أول حل.
ub_ctx_trustedkeys
إضافة مراسي ثقة إلى السياق المحدد. مرر اسم ملف تكوين بنمط bind مع trusted-keys{}. في هذا الوقت، لا يمكن إلا إضافة مفاتيح موثوقة قبل إجراء أول حل.
ub_ctx_debugout
تعيين إخراج سجل التصحيح والأخطاء إلى التدفق المحدد. مرر NULL لتعطيل الإخراج. الافتراضي هو stderr. يمكن تمكين أسماء الملفات أو استخدام syslog باستخدام خيارات التكوين، هذا الروتين لاستخدام التدفق الخاص بك.
ub_ctx_debuglevel
تعيين مستوى إسهاب التصحيح للسياق. يتم توجيه الإخراج إلى stderr. مستوى تصحيح أعلى يعطي إخراجًا أكثر.
ub_ctx_async
تعيين سلوك السياق للإجراء غير المتزامن. إذا تم التعيين على true، يتم تمكين الخيوط واستدعاء ub_resolve_async ينشئ خيطًا لمعالجة العمل في الخلفية. إذا كان false، يتم تفرع عملية لمعالجة العمل في الخلفية. التغييرات على هذا الإعداد بعد إجراء استدعاءات ub_resolve_async ليس لها تأثير (احذف وأعد إنشاء السياق للتغيير).
ub_poll
استقصاء سياق لمعرفة ما إذا كان لديه أي نتائج جديدة. لا تستقصِ في حلقة، بدلاً من ذلك استخرج fd أدناه للاستقصاء عن الجاهزية، ثم تحقق، أو انتظر باستخدام روتين الانتظار. يعيد 0 إذا لم يكن هناك شيء للقراءة، أو غير صفري إذا كانت هناك نتيجة متاحة. إذا كان غير صفري، استدعِ ub_process لتنفيذ عمليات الاستدعاء.
ub_wait
انتظر حتى ينتهي سياق من النتائج. يستدعي ub_process بعد الانتظار نيابة عنك. بعد الانتظار، لا توجد المزيد من الاستعلامات غير المتزامنة المعلقة.
ub_fd
الحصول على واصف الملف. انتظر حتى يصبح قابلاً للقراءة، في هذه النقطة يتم إرجاع الإجابات من المحلل المُتحقق غير المتزامن. ثم استدعِ ub_process لمتابعة المعالجة.
ub_process
استدعِ هذا الروتين لمتابعة معالجة النتائج من المحلل المُتحقق (عندما يصبح fd قابلاً للقراءة). سينفذ عمليات الاستدعاء الضرورية.
ub_resolve
إجراء حل والتحقق من صحة الاسم الهدف. الاسم هو اسم نطاق في سلسلة نصية منتهية بصفر. rrtype وrrclass هما رمزا نوع وفئة DNS. يتم تخصيص بنية النتيجة حديثًا مع البيانات الناتجة.
ub_resolve_async
إجراء حل والتحقق من صحة الاسم الهدف بشكل غير متزامن. الوسائط تعني نفس الشيء كما في ub_resolve باستثناء عدم إرجاع البيانات فورًا، بدلاً من ذلك يتم استدعاء دالة استدعاء لاحقًا. تتلقى دالة الاستدعاء نسخة من مؤشر mydata، الذي يمكنك استخدامه لتمرير المعلومات إلى دالة الاستدعاء. نوع دالة الاستدعاء هو مؤشر دالة إلى دالة معلنة كـ:
void my_callback_function(void* my_arg, int err,
                struct ub_result* result);

يتم إرجاع async_id حتى تتمكن (بناءً على اختيارك) من اتخاذ قرار لتتبعه وإلغاء الطلب إذا لزم الأمر. إذا مررت مؤشر NULL فلن يتم إرجاع async_id.

ub_cancel
إلغاء استعلام غير متزامن قيد التقدم. قد يعيد هذا خطأً إذا لم يكن الاستعلام موجودًا، أو إذا كان الاستعلام يتم تسليمه بالفعل، في هذه الحالة قد لا تزال تحصل على دالة استدعاء للاستعلام.
ub_resolve_free
تحرير محتويات ub_result الهيكلية بعد الاستخدام.
ub_strerror
تحويل قيمة الخطأ من إحدى دوال مكتبة unbound إلى سلسلة قابلة للقراءة البشرية.
ub_ctx_print_local_zones
طباعة تصحيح معلومات السلطة المحلية إلى إخراج التصحيح.
ub_ctx_zone_add
إضافة منطقة جديدة إلى معلومات السلطة المحلية، مثل عبارة local-zone unbound.conf(5).
ub_ctx_zone_remove
حذف المنطقة من معلومات السلطة المحلية.
ub_ctx_data_add
إضافة بيانات سجل الموارد إلى معلومات السلطة المحلية، مثل عبارة local-data unbound.conf(5).
ub_ctx_data_remove
حذف بيانات السلطة المحلية من الاسم المعطى.

بنية بيانات النتيجة

يتم إرجاع نتيجة حل DNS والتحقق كـ struct ub_result. تحتوي بنية النتيجة على الإدخالات التالية:

struct ub_result {
     char* qname;         /* text string, original question */
     int qtype;           /* type code asked for */
     int qclass;          /* class code asked for */
     char** data;         /* array of rdata items, NULL terminated*/
     int* len;            /* array with lengths of rdata items */
     char* canonname;     /* canonical name of result */
     int rcode;           /* additional error code in case of no data */
     void* answer_packet; /* full network format answer packet */
     int answer_len;      /* length of packet in octets */
     int havedata;        /* true if there is data */
     int nxdomain;        /* true if nodata because name does not exist */
     int secure;          /* true if result is secure */
     int bogus;           /* true if a security failure happened */
     char* why_bogus;     /* string with error if bogus */
     int was_ratelimited; /* true if the query was ratelimited (SERVFAIL) by unbound */
     int ttl;             /* number of seconds the result is valid */
};

إذا كان كل من secure وbogus خطأ، لم يتم تمكين الأمان لنطاق الاستعلام. وإلا، فهما ليسا صحيحين معًا، أحدهما صحيح.

قيم الإرجاع

تعيد العديد من الروتينات رمز خطأ. القيمة 0 (صفر) تشير إلى عدم حدوث خطأ. يمكن تمرير قيم أخرى إلى ub_strerror للحصول على سلسلة خطأ قابلة للقراءة. تعيد ub_strerror سلسلة منتهية بصفر. تعيد ub_ctx_create NULL عند حدوث خطأ (فشل malloc). تعيد ub_poll صحيحًا إذا كانت بعض المعلومات قد تكون متاحة، وخطأً بخلاف ذلك. تعيد ub_fd واصف ملف أو -1 عند حدوث خطأ. تحاول ub_ctx_config وub_ctx_resolvconf ترك errno مفيدًا عند إرجاع الدالة مع فشل قراءة الملف.
