val in_channel_of_descr : file_descr -> in_channel

إنشاء قناة إدخال تقرأ من الوصف المحدد. تكون القناة مبدئيًا في وضع ثنائي؛ استخدم set_binary_mode_in ic false إذا كان الوضع النصي مرغوبًا. وضع النص مدعوم فقط إذا كان الوصف يشير إلى ملف أو أنبوب، ولكنه غير مدعوم إذا كان يشير إلى مقبس.

على نظام Windows: تفشل set_binary_mode_in دائمًا على القنوات التي تم إنشاؤها بهذه الدالة.

احذر من أن قنوات الإدخال مخزنة مؤقتًا، لذلك قد تكون قد قُرأت أحرف أكثر من الوصف مقارنة بتلك التي تم الوصول إليها باستخدام دوال القناة. تحتفظ القنوات أيضًا بنسخة من الموضع الحالي في الملف.

إغلاق القناة ic التي تم إرجاعها بواسطة in_channel_of_descr fd باستخدام close_in ic يغلق أيضًا الوصف الأساسي fd. من غير الصحيح إغلاق كل من القناة ic والوصف fd.

إذا تم إنشاء عدة قنوات على نفس الوصف، فيجب إغلاق إحدى القنوات، ولكن ليس الأخريات. ضع في اعتبارك على سبيل المثال وصفًا s متصلًا بمقبس وقناتين ic = in_channel_of_descr s و oc = out_channel_of_descr s. بروتوكول الإغلاق الموصى به هو تنفيذ close_out oc، والذي يقوم بتفريغ الإخراج المخزن مؤقتًا إلى المقبس ثم يغلق المقبس. يجب عدم إغلاق القناة ic وسيتم جمعها بواسطة جامع القمامة في النهاية.

val out_channel_of_descr : file_descr -> out_channel

إنشاء قناة إخراج تكتب على الوصف المحدد. تكون القناة مبدئيًا في وضع ثنائي؛ استخدم set_binary_mode_out oc false إذا كان الوضع النصي مرغوبًا. وضع النص مدعوم فقط إذا كان الوصف يشير إلى ملف أو أنبوب، ولكنه غير مدعوم إذا كان يشير إلى مقبس.

على نظام Windows: تفشل set_binary_mode_out دائمًا على القنوات التي تم إنشاؤها بهذه الدالة.

احذر من أن قنوات الإخراج مخزنة مؤقتًا، لذلك قد تحتاج إلى استدعاء flush للتأكد من إرسال جميع البيانات إلى الوصف. تحتفظ القنوات أيضًا بنسخة من الموضع الحالي في الملف.

إغلاق القناة oc التي تم إرجاعها بواسطة out_channel_of_descr fd باستخدام close_out oc يغلق أيضًا الوصف الأساسي fd. من غير الصحيح إغلاق كل من القناة ic والوصف fd.

راجع Unix.in_channel_of_descr لمناقشة بروتوكول الإغلاق عند إنشاء عدة قنوات على نفس الوصف.

تعيين الملفات في الذاكرة

val map_file : file_descr -> ?pos:int64 -> kind:('a, 'b) Bigarray.kind -> layout:'c Bigarray.layout -> shared:bool -> dims:int array -> ('a, 'b, 'c) Bigarray.Genarray.t

تعيين ملف في الذاكرة كمصفوفة كبيرة (Bigarray). ترجع map_file fd ~kind ~layout ~shared ~dims مصفوفة كبيرة من النوع kind، والتخطيط layout، والأبعاد المحددة في dims. البيانات الموجودة في هذه المصفوفة الكبيرة هي محتويات الملف المشار إليه بواسطة وصف الملف fd (كما تم فتحه مسبقًا باستخدام UnixLabels.openfile، على سبيل المثال). المعلمة الاختيارية pos هي إزاحة البايت في الملف للبيانات التي يتم تعيينها؛ افتراضيًا هي 0 (تعيين من بداية الملف).

إذا كانت shared تساوي true، فإن جميع التعديلات التي تم إجراؤها على المصفوفة تنعكس في الملف. يتطلب هذا أن يتم فتح fd بأذونات الكتابة. إذا كانت shared تساوي false، فإن التعديلات التي تم إجراؤها على المصفوفة تتم في الذاكرة فقط، باستخدام النسخ عند الكتابة للصفحات المعدلة؛ لا يتأثر الملف الأساسي.

تعتبر UnixLabels.map_file أكثر كفاءة بكثير من قراءة الملف بالكامل في مصفوفة كبيرة، وتعديل تلك المصفوفة الكبيرة، ثم كتابتها لاحقًا.

لضبط أبعاد المصفوفة الكبيرة تلقائيًا لتتناسب مع الحجم الفعلي للملف، يمكن إعطاء البعد الرئيسي (أي، البعد الأول لمصفوفة ذات تخطيط C، والبعد الأخير لمصفوفة ذات تخطيط Fortran) كـ -1. تقوم UnixLabels.map_file بعد ذلك بتحديد البعد الرئيسي من حجم الملف. يجب أن يحتوي الملف على عدد صحيح من المصفوفات الفرعية كما تم تحديده بواسطة الأبعاد غير الرئيسية، وإلا يتم رفع Failure.

إذا تم إعطاء جميع أبعاد المصفوفة الكبيرة، تتم مطابقة حجم الملف مع حجم المصفوفة الكبيرة. إذا كان الملف أكبر من المصفوفة الكبيرة، يتم فقط تعيين الجزء الأولي من الملف إلى المصفوفة الكبيرة. إذا كان الملف أصغر من المصفوفة الكبيرة، يتم توسيع الملف تلقائيًا إلى حجم المصفوفة الكبيرة. يتطلب هذا أذونات الكتابة على fd.

يتم التحقق من حدود الوصول إلى المصفوفة، ولكن يتم تحديد الحدود بواسطة الاستدعاء الأولي لـ map_file. لذلك، يجب عليك التأكد من عدم قيام أي عملية أخرى بتعديل الملف المعين أثناء وصولك إليه، وإلا قد يتم رفع إشارة SIGBUS. يحدث هذا، على سبيل المثال، إذا تم تقليص حجم الملف.

قد يتم رفع Invalid_argument أو Failure في الحالات التي تفشل فيها عملية التحقق من صحة الوسيطات.

Opening and closing processes

The following functions allow to create new processes and to communicate with them by pipes.

val open_process_in : string -> in_channel

open_process_in cmd executes the shell command cmd and returns an input channel connected to the standard output of the command. The command is executed asynchronously, in the background. The standard error of the command is not redirected. If the command does not need to be run through the shell, UnixLabels.open_process_args_in can be used instead of UnixLabels.open_process_in .

val open_process_out : string -> out_channel

Same as UnixLabels.open_process_in , but returns an output channel connected to the standard input of the command.

If the command does not need to be run through the shell, UnixLabels.open_process_args_out can be used instead of UnixLabels.open_process_out .

val open_process : string -> in_channel * out_channel

Same as UnixLabels.open_process_out , but redirects both the standard input and standard output of the command to pipes connected to the two returned channels. The input channel is connected to the output of the command, and the output channel to the input of the command. If the command does not need to be run through the shell, UnixLabels.open_process_args can be used instead of UnixLabels.open_process .

val open_process_full : string -> env:string array -> in_channel * out_channel * in_channel

Similar to UnixLabels.open_process , but the second argument specifies the environment passed to the command. The result is a triple of channels connected respectively to the standard output, standard input, and standard error of the command. If the command does not need to be run through the shell, UnixLabels.open_process_args_full can be used instead of UnixLabels.open_process_full .

val open_process_args : string -> string array -> in_channel * out_channel

open_process_args prog args runs the program prog with arguments args . Note that the first argument, args.(0) , is by convention the filename of the program being executed, just like Sys.argv.(0) . The new process executes concurrently with the current process. The standard input and output of the new process are redirected to pipes, which can be respectively read and written via the returned channels. The input channel is connected to the output of the program, and the output channel to the input of the program.

Warning: writes on output channels are buffered, hence be careful to call flush at the right times to ensure correct synchronization.

The executable file prog is searched for in the path. This behaviour changed in 4.12; previously prog was looked up only in the current directory.

The new process has the same environment as the current process.

روابط رمزية

val symlink : ?to_dir:bool -> src:string -> dst:string -> unit

symlink ?to_dir ~src ~dst creates the file dst as a symbolic link to the file src . On Windows, ~to_dir indicates if the symbolic link points to a directory or a file; if omitted, symlink examines src using stat and picks appropriately, if src does not exist then false is assumed (for this reason, it is recommended that the ~to_dir parameter be specified in new code). On Unix, ~to_dir is ignored.

Windows symbolic links are available in Windows Vista onwards. There are some important differences between Windows symlinks and their POSIX counterparts.

Windows symbolic links come in two flavours: directory and regular, which designate whether the symbolic link points to a directory or a file. The type must be correct - a directory symlink which actually points to a file cannot be selected with chdir and a file symlink which actually points to a directory cannot be read or written (note that Cygwin's emulation layer ignores this distinction).

When symbolic links are created to existing targets, this distinction doesn't matter and symlink will automatically create the correct kind of symbolic link. The distinction matters when a symbolic link is created to a non-existent target.

The other caveat is that by default symbolic links are a privileged operation. Administrators will always need to be running elevated (or with UAC disabled) and by default normal user accounts need to be granted the SeCreateSymbolicLinkPrivilege via Local Security Policy (secpol.msc) or via Active Directory.

UnixLabels.has_symlink can be used to check that a process is able to create symbolic links.

val has_symlink : unit -> bool

Returns true if the user is able to create symbolic links. On Windows, this indicates that the user not only has the SeCreateSymbolicLinkPrivilege but is also running elevated, if necessary. On other platforms, this is simply indicates that the symlink system call is available.

val select : read:file_descr list -> write:file_descr list -> except:file_descr list -> timeout:float -> file_descr list * file_descr list * file_descr list

Wait until some input/output operations become possible on some channels. The three list arguments are, respectively, a set of descriptors to check for reading (first argument), for writing (second argument), or for exceptional conditions (third argument). The fourth argument is the maximal timeout, in seconds; a negative fourth argument means no timeout (unbounded wait). The result is composed of three sets of descriptors: those ready for reading (first component), ready for writing (second component), and over which an exceptional condition is pending (third component).

On Windows, if one of descriptor lists exceeds FD_SETSIZE elements (64 by default), or if at least one non-socket file descriptor is used, the maximal timeout is capped to 2^32 milliseconds.

| F_ULOCK (* Unlock a region
*)
| F_LOCK (* Lock a region for writing, and block if already locked
*)
| F_TLOCK (* Lock a region for writing, or fail if already locked
*)
| F_TEST (* Test a region for other process locks
*)
| F_RLOCK (* Lock a region for reading, and block if already locked
*)
| F_TRLOCK (* Lock a region for reading, or fail if already locked
*)

Commands for UnixLabels.lockf .

val lockf : file_descr -> mode:lock_command -> len:int -> unit

lockf fd ~mode ~len puts a lock on a region of the file opened as fd . The region starts at the current read/write position for fd (as set by UnixLabels.lseek ), and extends len bytes forward if len is positive, len bytes backwards if len is negative, or to the end of the file if len is zero. A write lock prevents any other process from acquiring a read or write lock on the region. A read lock prevents any other process from acquiring a write lock on the region, but lets other processes acquire read locks on it.

The F_LOCK and F_TLOCK commands attempts to put a write lock on the specified region. The F_RLOCK and F_TRLOCK commands attempts to put a read lock on the specified region. If one or several locks put by another process prevent the current process from acquiring the lock, F_LOCK and F_RLOCK block until these locks are removed, while F_TLOCK and F_TRLOCK fail immediately with an exception. The F_ULOCK removes whatever locks the current process has on the specified region. Finally, the F_TEST command tests whether a write lock can be acquired on the specified region, without actually putting a lock. It returns immediately if successful, or fails otherwise.

وظائف اتصال الشبكة عالية المستوى

val open_connection : sockaddr -> in_channel * out_channel

الاتصال بخادم على العنوان المحدد. إرجاع زوج من القنوات المخزنة مؤقتًا المتصلة بالخادم. تذكر استدعاء flush على قناة الإخراج في الأوقات المناسبة لضمان المزامنة الصحيحة.

تشترك القناتان اللتان تم إرجاعهما بواسطة open_connection في واصف لمقبس. لذلك، عند انتهاء الاتصال، يجب عليك استدعاء close_out على قناة الإخراج، والتي ستغلق أيضًا المقبس الأساسي. لا تستدع close_in على قناة الإدخال؛ سيتم جمعها بواسطة GC في النهاية.

val shutdown_connection : in_channel -> unit

"إيقاف" الاتصال الذي تم إنشاؤه باستخدام UnixLabels.open_connection ؛ أي، إرسال حالة نهاية الملف إلى الخادم الذي يقرأ على الجانب الآخر من الاتصال. هذا لا يغلق المقبس والقنوات المستخدمة بواسطة الاتصال. انظر Unix.open_connection لمعرفة كيفية إغلاقها بمجرد انتهاء الاتصال.

val establish_server : (in_channel -> out_channel -> unit) -> addr:sockaddr -> unit

إنشاء خادم على العنوان المحدد. يتم استدعاء الدالة المعطاة كمعامل أول لكل اتصال مع قناتين مخزنتين مؤقتًا متصلتين بالعميل. يتم إنشاء عملية جديدة لكل اتصال. الدالة UnixLabels.establish_server لا تعود بشكل طبيعي.

تشترك القناتان المعطاة للدالة في واصف لمقبس. لا تحتاج الدالة إلى إغلاق القنوات، حيث يحدث هذا تلقائيًا عند عودة الدالة. إذا فضلت الدالة الإغلاق الصريح، فيجب عليها إغلاق قناة الإخراج باستخدام close_out وترك قناة الإدخال غير مغلقة، لأسباب موضحة في Unix.in_channel_of_descr.

يثير Invalid_argument على Windows. استخدم مؤشرات الترابط بدلاً من ذلك.

val getaddrinfo : string -> string -> getaddrinfo_option list -> addr_info list

getaddrinfo host service opts ترجع قائمة بسجلات UnixLabels.addr_info تصف معلمات المقبس وعناوين مناسبة للتواصل مع المضيف والخدمة المحددين. يتم إرجاع قائمة فارغة إذا كانت أسماء المضيف أو الخدمة غير معروفة، أو تعذر تلبية القيود المعبر عنها في opts.

host هو إما اسم مضيف أو تمثيل سلسلة لنص لعنوان IP. يمكن تقديم host كسلسلة فارغة؛ في هذه الحالة، يتم استخدام عنوان "أي" أو عنوان "loopback"، اعتمادًا على ما إذا كان opts يحتوي على AI_PASSIVE. service هو إما اسم خدمة أو تمثيل سلسلة لرقم منفذ. يمكن تقديم service كسلسلة فارغة؛ في هذه الحالة، يتم تعيين حقل المنفذ للعناوين المرجعة إلى 0. opts هي قائمة خيارات قد تكون فارغة تسمح للمتصل بفرض نطاق مقبس معين (مثل IPv6 فقط أو IPv4 فقط) أو نوع مقبس معين (مثل TCP فقط أو UDP فقط).
