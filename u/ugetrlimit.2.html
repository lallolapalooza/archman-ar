c أيضًا يوفر vlimit(). يجب كتابة جميع التطبيقات الجديدة باستخدام setrlimit().

اختلافات مكتبة C/واجهة ثنائية للتطبيق في النواة

منذ glibc 2.13، لم تعد دوال الغلاف getrlimit() و setrlimit() الخاصة بـ glibc تستدعي استدعاءات النظام المقابلة، بل تستخدم prlimit()، للأسباب الموضحة في BUGS.

اسم دالة الغلاف الخاصة بـ glibc هو prlimit()؛ استدعاء النظام الأساسي هو prlimit64().

الأخطاء (BUGS)

في نواة لينكس القديمة، كانت الإشارات SIGXCPU و SIGKILL التي يتم تسليمها عندما تواجه العملية الحدود الناعمة والصلبة لـ RLIMIT_CPU يتم تسليمها متأخرة بثانية واحدة (من وقت وحدة المعالجة المركزية) عما ينبغي أن تكون عليه. تم إصلاح هذا في Linux 2.6.8.

في نواة Linux 2.6.x قبل Linux 2.6.17، يتم التعامل مع حد RLIMIT_CPU بقيمة 0 بشكل خاطئ على أنه "لا يوجد حد" (مثل RLIM_INFINITY). منذ Linux 2.6.17، فإن تحديد حد بقيمة 0 له تأثير، ولكنه يعامل فعليًا كحد ثانية واحدة.

هناك خطأ في النواة يعني أن RLIMIT_RTPRIO لا تعمل في Linux 2.6.12؛ تم إصلاح المشكلة في Linux 2.6.13.

في Linux 2.6.12، كان هناك خطأ في النطاق بمقدار واحد بين نطاقات الأولوية التي تم إرجاعها بواسطة getpriority(2) و RLIMIT_NICE. كان لهذا تأثير أن الحد الأقصى الفعلي لقيمة "nice" تم حسابه على أنه 19 - rlim_cur. تم إصلاح هذا في Linux 2.6.13.

منذ Linux 2.6.12، إذا وصلت العملية إلى الحد الناعم لـ RLIMIT_CPU وكان لديها معالج مثبت لـ SIGXCPU، فعندئذٍ، بالإضافة إلى استدعاء معالج الإشارة، تزيد النواة الحد الناعم بمقدار ثانية واحدة. يتكرر هذا السلوك إذا استمرت العملية في استهلاك وقت وحدة المعالجة المركزية، حتى يتم الوصول إلى الحد الصلب، وعند هذه النقطة يتم إنهاء العملية. التنفيذات الأخرى لا تغير الحد الناعم لـ RLIMIT_CPU بهذه الطريقة، ومن المحتمل أن يكون سلوك Linux غير متوافق مع المعايير؛ يجب على التطبيقات المحمولة تجنب الاعتماد على هذا السلوك الخاص بـ Linux. حد RLIMIT_RTTIME الخاص بـ Linux يعرض نفس السلوك عند مواجهة الحد الناعم.

لم تقم النوى قبل Linux 2.4.22 بتشخيص خطأ EINVAL لـ setrlimit() عندما تكون rlim->rlim_cur أكبر من rlim->rlim_max.

لا تعيد Linux خطأ عند فشل محاولة تعيين RLIMIT_CPU، لأسباب تتعلق بالتوافق.

تمثيل قيم حدود الموارد "الكبيرة" على المنصات 32 بت

تستخدم دوال الغلاف getrlimit() و setrlimit() الخاصة بـ glibc نوع بيانات rlim_t 64 بت، حتى على المنصات 32 بت. ومع ذلك، فإن نوع بيانات rlim_t المستخدم في استدعاءات النظام getrlimit() و setrlimit() هو unsigned long (32 بت). علاوة على ذلك، في Linux، تمثل النواة حدود الموارد على المنصات 32 بت كـ unsigned long. ومع ذلك، فإن نوع بيانات 32 بت ليس واسعًا بما فيه الكفاية. الحد الأكثر صلة هنا هو RLIMIT_FSIZE، والذي يحدد الحد الأقصى للحجم الذي يمكن أن ينمو إليه الملف: ليكون مفيدًا، يجب تمثيل هذا الحد باستخدام نوع بنفس عرض النوع المستخدم لتمثيل إزاحات الملفات - أي بنفس عرض off_t 64 بت (بافتراض برنامج تم تجميعه باستخدام _FILE_OFFSET_BITS=64).

للتغلب على هذا القيد في النواة، إذا حاول برنامج تعيين حد مورد إلى قيمة أكبر مما يمكن تمثيله في unsigned long 32 بت، فإن دالة الغلاف setrlimit() الخاصة بـ glibc حولت قيمة الحد بصمت إلى RLIM_INFINITY. بعبارة أخرى، تم تجاهل تعيين حد المورد المطلوب بصمت.

منذ glibc 2.13، تتغلب glibc على قيود استدعاءات النظام getrlimit() و setrlimit() عن طريق تنفيذ setrlimit() و getrlimit() كدوال غلاف تستدعي prlimit().

أمثلة

يوضح البرنامج أدناه استخدام prlimit().

#define _GNU_SOURCE
#define _FILE_OFFSET_BITS 64
#include <err.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/resource.h>
#include <time.h>
int
main(int argc, char *argv[])
{
    pid_t          pid;
    struct rlimit  old, new;
    struct rlimit  *newp;
    if (!(argc == 2 || argc == 4)) {
        fprintf(stderr, "Usage: %s <pid> [<new-soft-limit> "
                "<new-hard-limit>]\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    pid = atoi(argv[1]);        /* PID of target process */
    newp = NULL;
    if (argc == 4) {
        new.rlim_cur = atoi(argv[2]);
        new.rlim_max = atoi(argv[3]);
        newp = &new;
    }
    /* Set CPU time limit of target process; retrieve and display
       previous limit */
    if (prlimit(pid, RLIMIT_CPU, newp, &old) == -1)
        err(EXIT_FAILURE, "prlimit-1");
    printf("Previous limits: soft=%jd; hard=%jd\n",
           (intmax_t) old.rlim_cur, (intmax_t) old.rlim_max);
    /* Retrieve and display new CPU time limit */
    if (prlimit(pid, RLIMIT_CPU, NULL, &old) == -1)
        err(EXIT_FAILURE, "prlimit-2");
    printf("New limits: soft=%jd; hard=%jd\n",
           (intmax_t) old.rlim_cur, (intmax_t) old.rlim_max);
    exit(EXIT_SUCCESS);
}
