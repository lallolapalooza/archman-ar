جميع عمليات systemd-run لك (انظر قسم أمر app).

يتم تشغيل المُركِّب (compositor) افتراضيًا في session.slice (كما هو موصى به بواسطة systemd.special(7)).

إيقاف التشغيل

يمكن البدء به عن طريق أي من التالي:

  • تشغيل uwsm stop
  • إيقاف wayland-wm@*.service
  • بدء wayland-session-shutdown.target

يقوم systemd بإيقاف جميع وحدات المستخدم بترتيب عكسي، كما يفعل عادةً. أثناء إلغاء تنشيط graphical-session-pre.target، يقوم خدمة تحميل البيئة المسبق بتنظيف بيئات التنشيط عن طريق إلغاء تعيين جميع المتغيرات التي تم تمييزها للإزالة أثناء مراحل البدء والإنهاء.

لا تستخدم آلية الخروج الأصلية للمُركِّب أو تقتل عمليته مباشرة.

أوامر فرعية

select

يحدد مُركِّب جلسة Wayland الافتراضي لملف إدخال سطح المكتب (Desktop Entry).

uwsm select

يستدعي قائمة whiptail لاختيار الجلسة الافتراضية من بين إدخالات سطح المكتب في تسلسل هرم بيانات XDG الخاص بـ wayland-sessions. يكتب إلى ${XDG_CONFIG_HOME}/uwsm/default-id. لا يتم فعل أي شيء آخر. يعود بـ 1 إذا تم إلغاء الاختيار. يمكن استخدامه لبرمجة شرط الإطلاق في ملف تعريف shell.

check

يجري الاختبارات، ويعود بـ 0 عند النجاح، و 1 عند الفشل.

is-active:

uwsm check is-active [-h] [-v] [compositor]
-v عرض معلومات إضافية
compositor التحقق من مُركِّب محدد

يتحقق مما إذا كانت الوحدة النمطية لمُركِّب معين أو graphical-session*.target بشكل عام في حالة نشطة أو قيد التنشيط.

may-start:

uwsm check may-start [-h] [-g [S]] [-v|-q] [N ...]
-g S الانتظار S ثانية لوحدة graphical.target في قائمة الانتظار (افتراضي: 60؛ 0 أو أقل يعطل التحقق).
-v عرض جميع الاختبارات الفاشلة
-q كن هادئًا
N ... أرقام VT المسموح بها (افتراضي: 1)

يتحقق مما إذا كان من الممكن تشغيل جلسة Wayland وفقًا للشروط التالية:

  • التشغيل من shell تسجيل الدخول
  • النظام في graphical.target
  • وحدات graphical-session*.target للمستخدم لم يتم تنشيطها بعد
  • أن يكون VT الأمامي ضمن المسموح به (افتراضي: 1)

start

ينشئ وحدات نمطية لسطر أوامر المُركِّب المحدد أو إدخال سطح المكتب ويقوم بتشغيلها.

uwsm start [-h] [-D name[:name...]] [-a|-e] [-N Name] [-C Comment] [-U {run|home}] [-t] [-o] [-n] -- compositor [args ...]
-F وضع الترميز الثابت، اكتب دائمًا سطر الأوامر إلى وحدات الإسقاط واستخدم المسارات الكاملة.
-D name[:name...] الأسماء لملء XDG_CURRENT_DESKTOP بها (مفصولة بـ :-). محتوى المتغير الحالي هو نقطة بداية إذا لم تكن هناك جلسة نشطة قيد التشغيل.
-a إلحاق أسماء سطح المكتب التي تم تعيينها بواسطة -D بمصادر أخرى (افتراضي).
-e استخدم أسماء سطح المكتب التي تم تعيينها بواسطة -D حصريًا، وتجاهل المصادر الأخرى.
-N Name اسم أنيق للمُركِّب (يتم ملؤه من إدخال سطح المكتب افتراضيًا).
-C Comment وصف أنيق للمُركِّب (يتم ملؤه من إدخال سطح المكتب افتراضيًا).
-U {run|home} حدد المسار لملفات الوحدات النمطية التي تم إنشاؤها: run: $XDG_RUNTIME_DIR/systemd/user (افتراضي)، أو home: $XDG_CONFIG_HOME/systemd/user. سيؤدي الوجهة الدائمة إلى توفير بعض الوقت عن طريق إزالة الحاجة إلى إعادة تحميل systemd. سيتم إزالة الملفات المُدارة من مسار آخر. يمكن تعيينها مسبقًا بواسطة متغير البيئة UWSM_UNIT_RUNG.
-t لا تقم بإنشاء (وإزالة) ملفات تعديل. يمكن تعيينها مسبقًا بواسطة متغير البيئة UWSM_NO_TWEAKS.
-g S انتظر S ثانية لوحدة system graphical.target في قائمة الانتظار وقم بالتحذير إذا انتهت المهلة أو لم تكن في قائمة الانتظار (الافتراضي: 60، قيمة سالبة للتعطيل).
-G S انتظر S ثانية لوحدة system graphical.target في قائمة الانتظار وألغِ العملية إذا انتهت المهلة أو لم تكن في قائمة الانتظار (يتجاوز -g، الافتراضي: -1، (معطل)).
-o قم بإنشاء الوحدات النمطية فقط، ولكن لا تقم بتشغيلها.
-n تجربة محاكاة، لا تقم بالكتابة أو التشغيل.

يعمل الوسيط الأول لسطر أوامر المُركِّب كمعرّف ويجب أن يكون أحد مما يلي:

  • اسم تنفيذي
  • معرف إدخال سطح المكتب (اختياريًا مع معرف إجراء مفصول بـ ":")
  • قيمة خاصة:
  • select - استدعاء قائمة لاختيار المُركِّب.
  • default - تشغيل المُركِّب الذي تم اختياره سابقًا (أو تحديده إذا لم يتم حفظ أي تحديد).

إذا تم توفيرها كمسار، فسيتم استخدام وضع الترميز الثابت ضمنيًا.

استخدم دائمًا "--" لتمييز الوسائط التي تبدأ بشرطة مخصصة لـ المُركِّب نفسه.

بعد إعادة إنشاء الوحدات النمطية (أو إنشائها)، يتم تشغيل wayland-session-bindpid@${PID}.service، لتتبع معرف العملية (PID) لـ uwsm الذي تم استدعاؤه، ثم يستبدل عملية uwsm نفسها بتنفيذ systemctl الذي يبدأ wayland-wm@${ID}.service وينتظر حتى تنتهي.

لإكمال تسلسل البدء، يجب على المُركِّب وضع WAYLAND_DISPLAY في بيئة تنشيط systemd. يمكن القيام بذلك صراحةً عن طريق جعل المُركِّب يشغل أمر "uwsm finalize" (انظر القسم الفرعي التالي).

finalize

للتشغيل بواسطة المُركِّب عند بدء التشغيل.

uwsm finalize [-h] [VAR_NAME ...]

يصدر WAYLAND_DISPLAY و DISPLAY وأي متغيرات معرفة تم ذكرها بالأسماء في الوسائط أو في المتغير UWSM_FINALIZE_VARNAMES (مفصولة بمسافات). ثم يرسل إشعار بدء تشغيل للوحدة إلى مدير مستخدم systemd.

هذا مطلوب إذا لم يضع المُركِّب نفسه WAYLAND_DISPLAY في بيئة تنشيط systemd، وإلا فإن الوحدة النمطية wayland-session@.service أو وحدة wayland-session-waitenv.service المخصصة ستنتهي بسبب انتهاء مهلة بدء التشغيل.

يمكن تعيين المتغير UWSM_FINALIZE_VARNAMES مسبقًا بواسطة الإضافات.

التعيين المباشر كـ VAR_NAME=value ممكن أيضًا، ولكنه موصى به فقط لإنشاء علامات لآلية UWSM_WAIT_VARNAMES.

stop

يوقف المُركِّب ويقوم اختياريًا بإزالة الوحدات النمطية التي تم إنشاؤها.

uwsm stop [-h] [-r [compositor] [-U {run|home}] [-n]
-r [compositor] قم أيضًا بإزالة الوحدات النمطية (كلها أو فقط الوحدات النمطية الخاصة بـ compositor).
-U {run|home} حدد المسار لملفات الوحدات النمطية التي تم إنشاؤها: run: $XDG_RUNTIME_DIR/systemd/user (افتراضي)، أو home: $XDG_CONFIG_HOME/systemd/user. سيؤدي الوجهة الدائمة إلى توفير بعض الوقت عن طريق إزالة الحاجة إلى إعادة تحميل systemd. سيتم إزالة الملفات المُدارة من مسار آخر. يمكن تعيينها مسبقًا بواسطة متغير البيئة UWSM_UNIT_RUNG.
-n تجربة محاكاة، لا تقم بالإيقاف أو الإزالة.

app

مشغل التطبيقات إلى وحدات نمطية مع دعم إدخالات سطح المكتب.

uwsm app [-h] [-s {a,b,s,custom.slice}] [-t {scope,service}] [-a app_name] [-u unit_name] [-d unit_description] [-S ] [-T] -- application [args ...]
-s {a,b,s,custom.slice} محدد الشريحة (افتراضي: a):
a - app-graphical.slice
b - background-graphical.slice
s - session-graphical.slice
أي شريحة بالاسم الكامل
-t {scope,service} نوع الوحدة التي سيتم تشغيلها (افتراضي: scope، يمكن تعيينها مسبقًا بواسطة متغير البيئة UWSM_APP_UNIT_TYPE).
-a app_name تجاوز اسم التطبيق (سلسلة فرعية في اسم الوحدة).
-u unit_name تجاوز اسم الوحدة النمطية المُنشأة تلقائيًا بالكامل.
-d unit_description وصف الوحدة النمطية.
-p Property=value تعيين خاصية وحدة نمطية إضافية (يمكن تكرار الخيار).
-S {out,err,both} كتم الصوت stdout، stderr، أو كليهما.
-T تشغيل التطبيق في طرفية. يسمح بأن يكون الأمر فارغًا لمجرد تشغيل طرفية.

يمكن تقديم التطبيق كأمر مع وسائط اختيارية، أو معرف إدخال سطح مكتب، اختياريًا مضافًا إليه معرف إجراء مفصول بـ ":". إذا كان سيتم تشغيل إدخال سطح المكتب، فيجب أن تكون الوسائط متوافقة معه.

استخدم دائمًا "--" لتمييز الوسائط التي تبدأ بشرطة والمخصصة للتطبيق نفسه.

aux

للاستخدام في خدمات مستخدم systemd. يمكن استدعاؤها فقط بواسطة مدير مستخدم systemd.

prepare-env يعد البيئة (للاستخدام في ExecStart في wayland-wm-env@.service المرتبطة بـ wayland-session-pre@.target).
cleanup-env ينظف البيئة (للاستخدام في ExecStop في wayland-wm-env@.service المرتبطة بـ wayland-session-pre@.target).
exec ينفذ أمرًا

uwsm(1)

الحزمة: uwsm

التراخيص: MIT

NAME

uwsm - Unified Wayland Session Manager

SYNOPSIS

uwsm [OPTIONS] SUBCOMMAND [ARGS]...

DESCRIPTION

uwsm is a tool to manage Wayland compositors and sessions. It can be used to start, stop, and select Wayland compositors, and to integrate with systemd for session management.

SUBCOMMANDS

The following subcommands are available:

start [OPTIONS] [COMPOSITOR]
Starts a Wayland compositor. If COMPOSITOR is not specified, it attempts to start a default compositor.
stop
Stops the currently running Wayland compositor.
select
Presents a menu to select and start a Wayland compositor.
list
Lists available Wayland compositors.
check CHECKER [ARGS]...
Checks if a certain condition is met. Used for shell profile integration.
app [OPTIONS] [ARGS]...
Launches an application within the Wayland session.
daemon
Starts the app daemon.

CONFIGURATION

Configuration for uwsm is typically found in /etc/uwsm/config and ~/.config/uwsm/config.

OPERATION OVERVIEW

uwsm aims to provide a unified interface for managing Wayland sessions. It leverages systemd for session management and integrates with desktop environments and login managers.

The core idea is to abstract away the complexities of starting and managing different Wayland compositors, allowing users to easily switch between them or have a consistent session startup experience.

SUBCOMMANDS

This section details specific subcommands and their usage.

app

The uwsm app command is used to launch applications within the Wayland session. It can be used directly or via the app daemon for faster startup.

When used with arguments or a desktop entry (for use in wayland-wm@.service bound to wayland-session@.target).

app-daemon

Daemon for faster app argument generation, used by uwsm-app client.

APP DAEMON

Provided as wayland-wm-app-daemon.service to be started on-demand.

Daemon receives app arguments from ${XDG_RUNTIME_DIR}/uwsm-app-daemon-in pipe. Resulting arguments are formatted as shell code and written to ${XDG_RUNTIME_DIR}/uwsm-app-daemon-out pipe.

Arguments are expected to be \0-delimited, leading \0 are stripped. One command is received per write+close.

The first argument determines the behavior:

  • app the rest is processed the same as in "uwsm app"
  • ping just "pong" is returned
  • stop daemon is stopped

Single commands are prepended with exec, iterated commands are assembled with trailing & each, followed by wait.

The purpose of all this is to skip all the expensive Python startup and import routines that slow things down every time "uwsm app" is called. Instead the daemon does it once and then listens for requests, while a simple shell script may dump arguments to one pipe and run the code received from another via eval, which is much faster.

The simplest script is:

#!/bin/sh
printf '0%s' app "$@" > "${XDG_RUNTIME_DIR}/uwsm-app-daemon-in"
IFS='' read -r cmd < "${XDG_RUNTIME_DIR}/uwsm-app-daemon-out"
eval "$cmd"

Provided uwsm-app client script is a bit smarter: it can start the daemon, applies timeouts, and supports newlines in returned args.

SHELL PROFILE INTEGRATION

To launch uwsm automatically on login, add one of constructs below (or similar) to shell profile.

This asks to select a compositor (or refuse and continue with login shell) when logged in on VT 1:

if uwsm may-start && uwsm select; then
	exec systemd-cat -t uwsm_start uwsm start default
fi

This just starts a specific compositor depending on foreground VT:

if uwsm may-start 1; then
	exec systemd-cat -t uwsm_start uwsm start sway.desktop
elif uwsm may-start 2; then
	exec systemd-cat -t uwsm_start uwsm start labwc.desktop
fi

Using "uwsm check may-start" as a condition is essential, not only to prevent accidental startup attempts where they are not expected, but also since startup may involve sourcing shell profile, which might lead to nasty loops.

See check subcommand section for info on may-start checker.

exec allows uwsm to replace login shell in order to properly bind to user session and handle session termination.

"systemd-cat -t uwsm_start" (optional) executes the command given to it (uwsm) with its stdout and stderr connected to the systemd journal, tagged with identifier "uwsm_start". See systemd-cat(1) for more options.

USE INSIDE DESKTOP ENTRY

To launch uwsm from a display/login manager, "uwsm start" can be used inside Desktop Entries. Example /usr/local/share/wayland-sessions/my-compositor.desktop:

[Desktop Entry]
Name=My compositor (with UWSM)
Comment=My cool compositor
Exec=uwsm start -N "My compositor" -D mycompositor -C "My cool compositor" mywm
DesktopNames=mycompositor
Type=Application

Things to keep in mind:

  • For consistency, command line arguments should mirror the keys of the entry
  • Command in Exec= should start with "uwsm start"
  • It should not point to itself (as a combination of Desktop Entry ID and Action ID)
  • It should not point to a Desktop Entry ID and Action ID that also uses `uwsm`

Potentially such entries may be found and used by uwsm itself, i.e. in shell profile integration situation, or when launched manually. Following the principles above ensures uwsm will properly recognize itself and parse requested arguments inside the entry without any side effects.
