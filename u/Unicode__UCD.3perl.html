NAME

Unicode::UCD - Unicode character database

SYNOPSIS

use Unicode::UCD 'charprop';

my $casespec = casespec($codepoint);

DESCRIPTION

The Unicode::UCD module offers a series of functions that provide a simple interface to the Unicode Character Database.

code point argument

Some of the functions are called with a code point argument, which is either a decimal or a hexadecimal scalar designating a code point in the platform's native character set (extended to Unicode), or a string containing "U+" followed by hexadecimals designating a Unicode code point. A leading 0 will force a hexadecimal interpretation, as will a hexadecimal digit that isn't a decimal digit.

Examples:

223     # Decimal 223 in native character set
0223    # Hexadecimal 223, native (= 547 decimal)
0xDF    # Hexadecimal DF, native (= 223 decimal)
'0xDF'  # String form of hexadecimal (= 223 decimal)
'U+DF'  # Hexadecimal DF, in Unicode's character set
                          (= LATIN SMALL LETTER SHARP S)

Note that the largest code point in Unicode is U+10FFFF.

charinfo()

use Unicode::UCD 'charinfo';
my $charinfo = charinfo(0x41);

This returns information about the input "code point argument" as a reference to a hash of fields as defined by the Unicode standard. If the "code point argument" is not assigned in the standard (i.e., has the general category "Cn" meaning "Unassigned") or is a non-character (meaning it is guaranteed to never be assigned in the standard), "undef" is returned.

Fields that aren't applicable to the particular code point argument exist in the returned hash, and are empty.

For results that are less "raw" than this function returns, or to get the values for any property, not just the few covered by this function, use the "charprop()" function.

The keys in the hash with the meanings of their values are:

code
the input native "code point argument" expressed in hexadecimal, with leading zeros added if necessary to make it contain at least four hexdigits
name
name of code, all IN UPPER CASE. Some control-type code points do not have names. This field will be empty for "Surrogate" and "Private Use" code points, and for the others without a name, it will contain a description enclosed in angle brackets, like "<control>".
category
The short name of the general category of code. This will match one of the keys in the hash returned by "general_categories()".

The "prop_value_aliases()" function can be used to get all the synonyms of the category name.

combining
the combining class number for code used in the Canonical Ordering Algorithm. For Unicode 5.1, this is described in Section 3.11 "Canonical Ordering Behavior" available at http://www.unicode.org/versions/Unicode5.1.0/

The "prop_value_aliases()" function can be used to get all the synonyms of the combining class number.

bidi
bidirectional type of code. This will match one of the keys in the hash returned by "bidi_types()".

The "prop_value_aliases()" function can be used to get all the synonyms of the bidi type name.

decomposition
is empty if code has no decomposition; or is one or more codes (separated by spaces) that, taken in order, represent a decomposition for code. Each has at least four hexdigits. The codes may be preceded by a word enclosed in angle brackets, then a space, like "<compat> ", giving the type of decomposition

This decomposition may be an intermediate one whose components are also decomposable. Use Unicode::Normalize to get the final decomposition in one step.

decimal
if code represents a decimal digit this is its integer numeric value
digit
if code represents some other digit-like number, this is its integer numeric value
numeric
if code represents a whole or rational number, this is its numeric value. Rational values are expressed as a string like "1/4".
mirrored
"Y" or "N" designating if code is mirrored in bidirectional text
unicode10
name of code in the Unicode 1.0 standard if one existed for this code point and is different from the current name
comment
As of Unicode 6.0, this is always empty.
upper
is, if non-empty, the uppercase mapping for code expressed as at least four hexdigits. This indicates that the full uppercase mapping is a single character, and is identical to the simple (single-character only) mapping. When this field is empty, it means that the simple uppercase mapping is code itself; you'll need some other means, (like "charprop()" or "casespec()" to get the full mapping.
lower
is, if non-empty, the lowercase mapping for code expressed as at least four hexdigits. This indicates that the full lowercase mapping is a single character, and is identical to the simple (single-character only) mapping. When this field is empty, it means that the simple lowercase mapping is code itself; you'll need some other means, (like "charprop()" or "casespec()" to get the full mapping.
titlecase
is, if non-empty, the titlecase mapping for code expressed as at least four hexdigits. This indicates that the full titlecase mapping is a single character, and is identical to the simple (single-character only) mapping. When this field is empty, it means that the simple titlecase mapping is code itself; you'll need some other means, (like "charprop()" or "casespec()" to get the full mapping.
simpleuppercase
is, if non-empty, the simple uppercase mapping for code expressed as at least four hexdigits. This indicates that the full uppercase mapping is this single character. When this field is empty, it means that the simple uppercase mapping is code itself.
simplelowercase
is, if non-empty, the simple lowercase mapping for code expressed as at least four hexdigits. This indicates that the full lowercase mapping is this single character. When this field is empty, it means that the simple lowercase mapping is code itself.
simpletitlecase
is, if non-empty, the simple titlecase mapping for code expressed as at least four hexdigits. This indicates that the full titlecase mapping is this single character. When this field is empty, it means that the simple titlecase mapping is code itself.
uppercasemapping
is empty if code has no uppercase mapping; or is one or more codes (separated by spaces) that, taken in order, represent an uppercase mapping for code. Each has at least four hexdigits. Note that this may be a multi-character mapping.
lowercasemapping
is empty if code has no lowercase mapping; or is one or more codes (separated by spaces) that, taken in order, represent a lowercase mapping for code. Each has at least four hexdigits. Note that this may be a multi-character mapping.
titlecasemapping
is empty if code has no titlecase mapping; or is one or more codes (separated by spaces) that, taken in order, represent a titlecase mapping for code. Each has at least four hexdigits. Note that this may be a multi-character mapping.
casefoldmapping
is empty if code has no casefolding mapping; or is one or more codes (separated by spaces) that, taken in order, represent a casefolding mapping for code. Each has at least four hexdigits. Note that this may be a multi-character mapping.
numericType
This field is deprecated and should not be used.
script
The name of the script that the character belongs to (e.g., 'Latin', 'Greek', 'Cyrillic', 'Han'). This will match one of the keys in the hash returned by "charscripts()".
script_extensions
A string containing a comma-separated list of script names for scripts that the character belongs to, in addition to the primary script. Returns an empty string if there are no additional script extensions.
block
The name of the block that the character belongs to (e.g., 'Basic Latin', 'Latin-1 Supplement', 'Greek and Coptic'). This will match one of the keys in the hash returned by "charblocks()".
east_asian_width
The East Asian Width property of the character. Returns one of 'F' (Fullwidth), 'W' (Wide), 'Na' (Narrow), 'H' (Halfwidth), 'A' (Ambiguous), 'N' (Neutral).
line_break
The Line Break property of the character. Returns one of 'Al' (Ambiguous Numeric Like), 'An' (Ambiguous Numeric), 'B' (Break Otherwise), 'CB' (Contingent Break), 'CL' (Close Parenthesis), 'CP' (Close Parenthesis), 'CR' (Carriage Return), 'EX' (Exclamation), 'H2' (Hebrew Letter Like), 'H3' (Hebrew Number Like), 'HL' (Hebrew Letter Like), 'IN' (Infix Numeric Operator), 'IS' (Infix Separator), 'IT' (Iterative Numeric Operator), 'L' (Left-to-Right), 'LF' (Line Feed), 'NL' (Next Line), 'NU' (Numeric), 'OP' (Postfix or Prefix Numeric Operator), 'QU' (Question Mark), 'RI' (Regional Indicator), 'S' (Space Separator), 'SA' (Suffix Area), 'SG' (Should Not Break), 'SP' (Space Separator), 'WJ' (Word Joiner), 'X' (Any), 'XX' (Unknown).
joining_type
The Joining Type property of the character. Returns one of 'D' (Dual Joining), 'C' (Causemed) 'U' (Unjoinable), 'L' (Left Joining), 'R' (Right Joining).
joining_group
The Joining Group property of the character. Valid values are 'No_Joining_Group', 'Ain', 'Alaph', 'Beh', 'Bet', 'Burushaski_Hah', 'Dal', 'E', 'Fah', 'Feh', 'Final_Apostrophe', 'Gaf', 'Gimel', 'He', 'Hah', 'Heh', 'High_Hamza_A', 'Ingush_I', 'Jeem', 'Khah', 'Lam', 'Lam_Alef', 'Meem', 'Nun', 'O', 'Pe', 'Qaf', 'Rish', 'Sad', 'Seen', 'Shin', 'Swash_Kaf', 'Tah', 'Teh_Marbuta', 'Teh', 'Teth', 'Theh', 'To', 'U', 'Waw', 'Waw_Ring', 'Ya', 'Yodh', 'Zah', 'Zain'.
green_red_green_blue
For characters that are part of the "Green / Red / Green / Blue" color specification, this will contain the color value. Otherwise, it is empty.
vertical_orientation
The Vertical Orientation property of the character. Returns one of 'Rotated', 'Upright', 'Use My Settings'.

charprop()

use Unicode::UCD 'charprop';
my $value = charprop(0x61, 'lowercase');

This function returns the value of a given property for a given character.

The property argument can be any of the property names that are used in the Unicode Character Database. These names are case-insensitive. Property names can be given in their short form (e.g., "GC" for General Category) or their long form (e.g., "General_Category"). Aliases are also supported, e.g., "lower" for "Lowercase_Mapping".

The return value depends on the property requested. For properties that have single values (like General Category, Script, Bidi_Class, etc.), the short name for that value is returned. For properties that can have multiple values (like Decomposition Mapping), a space-separated string of the values is returned. For properties that map characters to other characters (like Lowercase Mapping, Uppercase Mapping, etc.), the code point of the mapped character is returned as a hexadecimal string (e.g., "0061").

If the property is not applicable to the character, or if the character is unassigned, "undef" is returned.

charprops_all()

use Unicode::UCD 'charprops_all';
my $all_props = charprops_all(0x61);

This function returns a reference to a hash containing all the properties and their values for the given character. This is similar to calling `charinfo()`, but it includes all properties, not just the ones listed in the `charinfo()` documentation.

The keys of the hash are the property names (long form, e.g., "General_Category") and the values are their corresponding values. For properties that have short names (like GC), the short name is included as a key as well (e.g., "GC").

If the character is unassigned, an empty hash reference is returned.

casefold()

use Unicode::UCD 'casefold';
my $folded = casefold(0x130); # Turkish I with dot above

Returns the casefolding mapping for the given code point. Casefolding is a more aggressive form of lowercasing, intended for caseless matching of strings. It maps characters to a plain ASCII representation where possible.

If the character has no casefolding mapping, the character itself (as a hexadecimal string) is returned.

all_casefolds()

my $casefolds_ref = Unicode::UCD::all_casefolds();

Returns a reference to a hash where keys are code points (as hexadecimal strings) and values are their casefolding mappings (also as hexadecimal strings).

casespec()

use Unicode::UCD 'casespec';
my $case_spec = casespec(0x130); # Turkish I with dot above

Returns a string describing the case mappings (simple uppercase, simple lowercase, simple titlecase, full uppercase, full lowercase, full titlecase) for the given code point. This is intended for use by the Unicode Normalization Algorithm.

The format of the returned string is:

    SimpleUpper SEP SimpleLower SEP SimpleTitle SEP FullUpper SEP FullLower SEP FullTitle

Where

  • SimpleUpper, SimpleLower, SimpleTitle are the single-character uppercase, lowercase, and titlecase mappings, respectively. They are represented as hexadecimal strings (e.g., "0041"). If the mapping is the character itself, the field will be empty.
  • FullUpper, FullLower, FullTitle are the potentially multi-character uppercase, lowercase, and titlecase mappings. They are represented as space-separated hexadecimal strings. If there is no mapping, the field will be empty.
  • SEP is the character "\0" (null).

If the character is unassigned or a non-character, "undef" is returned.

charblock()

use Unicode::UCD 'charblock';
my $block_name = charblock(0x41); # 'A'
# Returns 'Basic Latin'

Returns the name of the block the character belongs to.

charscript()

use Unicode::UCD 'charscript';
my $script_name = charscript(0x61); # 'a'
# Returns 'Latin'

Returns the name of the script the character belongs to.

charblocks()

my $blocks_ref = Unicode::UCD::charblocks();

Returns a reference to a hash where keys are block names and values are references to arrays of code points belonging to that block.

charscripts()

my $scripts_ref = Unicode::UCD::charscripts();

Returns a reference to a hash where keys are script names and values are references to arrays of code points belonging to that script.

charinrange()

use Unicode::UCD 'charinrange';
my $script_name = 'Latin';
my $codepoint = 0x61;
my $range = Unicode::UCD::charscript($script_name);
if (charinrange($range, $codepoint)) {
    print "$codepoint is in $script_name\n";
}

Checks if a given code point falls within the range of code points associated with a given script or block.

The first argument, $range, should be obtained from either "charscript()" or "charblock()".

The second argument, $codepoint, is the code point to check.

Returns true if the code point is within the range, false otherwise.

general_categories()

my $categories_ref = Unicode::UCD::general_categories();

Returns a reference to a hash where keys are the short names of the general categories (e.g., 'Lu', 'Ll', 'Lo') and values are references to arrays of code points belonging to that category.

bidi_types()

my $bidi_types_ref = Unicode::UCD::bidi_types();

Returns a reference to a hash where keys are the names of the bidirectional types (e.g., 'L', 'R', 'AL', 'EN') and values are references to arrays of code points belonging to that type.

prop_aliases()

use Unicode::UCD 'prop_aliases';
my @space_names = prop_aliases('Space');

Given a property name (short or long form), returns a list of all its aliases (short, long, and any other recognized names).

prop_value_aliases()

use Unicode::UCD 'prop_value_aliases';
my @gc_punct_names = prop_value_aliases('Gc', 'Punctuation');

Given a property name and a value name (short or long form), returns a list of all its aliases for that specific value.

prop_values()

use Unicode::UCD 'prop_values';
my @all_EA_widths = prop_values('East_Asian_Width');

Given a property name, returns a list of all possible values for that property.

prop_invlist()

use Unicode::UCD 'prop_invlist';
my @punctuation_chars = prop_invlist('Gc=Punctuation');

Returns a reference to an array containing all code points that match the given property and value. The property and value are specified in the format "Property=Value" (e.g., "GC=Letter", "Script=Greek").

The property and value names are case-insensitive and aliases are supported.

prop_invmap()

my ($list_ref, $map_ref, $format, $missing) = Unicode::UCD::prop_invmap('General Category');

Returns data structures suitable for implementing an inverse mapping from property values back to code points. This is primarily intended for internal use or for advanced applications.

The returned values are:

list_ref
A reference to an array of strings, where each string represents a character range or a single character, along with its corresponding property value.
map_ref
A reference to a hash where keys are property values and values are references to arrays of character ranges or single characters matching that value.
format
A string indicating the format of the data in $list_ref and $map_ref.
missing
A reference to an array of code points that are unassigned or non-characters.

search_invlist()

my $index = Unicode::UCD::search_invlist(\@invlist, $code_point);

Searches an inverse list (generated by "prop_invmap()") for a given code point. Returns the index of the matching entry or undef if not found.

compexcl()

my $compexcl = Unicode::UCD::compexcl($codepoint);

This function is related to composition exclusion in the Unicode Normalization Algorithm. It returns information about whether a character should be excluded from normalization composition.

Note: This function is intended for internal use within normalization implementations and may not be the most suitable choice for general use.

namedseq()

my $namedseq = Unicode::UCD::namedseq($named_sequence_name);

Given the name of a Unicode character sequence (e.g., "LATIN SMALL LETTER SHARP S"), this function returns the corresponding code point(s) as a space-separated string of hexadecimal values.

If the name is not found, "undef" is returned.

UnicodeVersion()

my $version = Unicode::UCD::UnicodeVersion();

Returns the version of the Unicode Character Database that the module is using (e.g., "15.0.0").

num()

my $numeric_value = Unicode::UCD::num("\N{VAI DIGIT ONE}\N{VAI DIGIT TWO}");

Converts a string containing Unicode character names (e.g., "\N{...}") or numeric representations into its numeric value. This function is useful for parsing strings that represent numbers using Unicode characters.

num()

This function takes a string of one or more Unicode characters and returns the numeric value of that string. This is primarily useful for handling digits from non-Latin scripts, or other characters that have a numeric value.

The function recognizes Rumi numerals, Arabic-Indic digits, and Devanagari digits.

use Unicode::UCD 'num';
say num("\N{ARABIC-INDIC DIGIT ONE}");        # 1
say num("\N{DEVANAGARI DIGIT TWO}");        # 2
say num("\N{RUMI DIGIT ONE}");             # 1
say num("\N{RUMI NUMBER TWENTY}");          # 20

It can also be used to parse a string containing multiple digits from a single script:

say num("\N{ARABIC-INDIC DIGIT ONE}\N{ARABIC-INDIC DIGIT TWO}"); # 12
say num("\N{DEVANAGARI DIGIT ONE}\N{DEVANAGARI DIGIT TWO}"); # 12

However, it can't handle mixing digits from different scripts.

say num("\N{ARABIC-INDIC DIGIT ONE}\N{DEVANAGARI DIGIT TWO}"); # undef

If you pass a string containing characters that do not have a numeric value, or a mixture of scripts, it returns "undef". This function takes an optional second argument, a scalar reference, into which it will store the length of the valid initial substring that it was able to parse. If the entire string was valid, the length stored will be the length of the string. If the string was invalid from the start, zero will be stored. If the string was partially valid, the length of the valid prefix will be stored.

my $len;
my $value = num("\N{RUMI DIGIT ONE}", \$len);
say $len, " ", (defined $value) ? $value : "undef";  # 1 1

$value = num("abc", \$len);
say $len, " ", (defined $value) ? $value : "undef";  # 0 undef

$value = num("\N{RUMI DIGIT ONE}\N{RUMI DIGIT TWO}", \$len);
say $len, " ", (defined $value) ? $value : "undef";  # 1 undef
# Note that Rumi digits only handle single digits, not sequences.

Rumi numerals are a special case. They have characters for one through nine, ten, twenty, and so forth. "num" correctly returns the values of these in isolation.

my $rumi_one = num("\N{RUMI DIGIT ONE}");
my $rumi_two = num("\N{RUMI DIGIT TWO}");
my $rumi_twenty = num("\N{RUMI NUMBER TWENTY}");
say "$rumi_one $rumi_two $rumi_twenty";     # 1 2 20

Because these do not follow modern decimal positional notation, stringing more than one of these together doesn't mean what you likely would think it means. So, "num" correctly returns "undef" if you try. If you request the length of the valid initial substring in this case, that length would be one.

my $len;
my $value = num("\N{RUMI DIGIT ONE}\N{RUMI DIGIT TWO}", \$len);
say $len, " ", (defined $value) ? $value : "undef";  # 1 undef

How to represent numbers like twelve gets complicated, and Unicode doesn't give any guidance, so "num" can't either.

Strings of multiple sub- and superscripts are not recognized as numbers. You can use either of the compatibility decompositions in Unicode::Normalize to change these into digits, and then call "num" on the result.

prop_aliases()

use Unicode::UCD 'prop_aliases';
my ($short_name, $full_name, @other_names) = prop_aliases("space");
my $same_full_name = prop_aliases("Space");     # Scalar context
my ($same_short_name) = prop_aliases("Space");  # gets 0th element
print "The full name is $full_name\n";
print "The short name is $short_name\n";
print "The other aliases are: ", join(", ", @other_names), "\n";
prints:
The full name is White_Space
The short name is WSpace
The other aliases are: Space

Most Unicode properties have several synonymous names. Typically, there is at least a short name, convenient to type, and a long name that more fully describes the property, and hence is more easily understood.

If you know one name for a Unicode property, you can use "prop_aliases" to find either the long name (when called in scalar context), or a list of all of the names, somewhat ordered so that the short name is in the 0th element, the long name in the next element, and any other synonyms are in the remaining elements, in no particular order.

The long name is returned in a form nicely capitalized, suitable for printing.

The input parameter name is loosely matched, which means that white space, hyphens, and underscores are ignored (except for the trailing underscore in the old_form grandfathered-in "L_", which is better written as "LC", and both of which mean "General_Category=Cased Letter").

If the name is unknown, "undef" is returned (or an empty list in list context). Note that Perl typically recognizes property names in regular expressions with an optional ""Is_"" (with or without the underscore) prefixed to them, such as "\p{isgc=punct}". This function does not recognize those in the input, returning "undef". Nor are they included in the output as possible synonyms.

"prop_aliases" does know about the Perl extensions to Unicode properties, such as "Any" and "XPosixAlpha", and the single form equivalents to Unicode properties such as "XDigit", "Greek", "In_Greek", and "Is_Greek". The final example demonstrates that the "Is_" prefix is recognized for these extensions; it is needed to resolve ambiguities. For example, prop_aliases('lc') returns the list "(lc, Lowercase_Mapping)", but prop_aliases('islc') returns "(Is_LC, Cased_Letter)". This is because "islc" is a Perl extension which is short for "General_Category=Cased Letter". The lists returned for the Perl extensions will not include the "Is_" prefix (whether or not the input had it) unless needed to resolve ambiguities, as shown in the "islc" example, where the returned list had one element containing "Is_", and the other without.

It is also possible for the reverse to happen: prop_aliases('isc') returns the list "(isc, ISO_Comment)"; whereas prop_aliases('c') returns "(C, Other)" (the latter being a Perl extension meaning "General_Category=Other". "Properties accessible through Unicode::UCD" in perluniprops lists the available forms, including which ones are discouraged from use.

Those discouraged forms are accepted as input to "prop_aliases", but are not returned in the lists. prop_aliases('isL&') and prop_aliases('isL_'), which are old synonyms for "Is_LC" and should not be used in new code, are examples of this. These both return "(Is_LC, Cased_Letter)". Thus this function allows you to take a discouraged form, and find its acceptable alternatives. The same goes with single-form Block property equivalences. Only the forms that begin with "In_" are not discouraged; if you pass "prop_aliases" a discouraged form, you will get back the equivalent ones that begin with "In_". It will otherwise look like a new-style block name (see. "Old-style versus new-style block names").

"prop_aliases" does not know about any user-defined properties, and will return "undef" if called with one of those. Likewise for Perl internal properties, with the exception of "Perl_Decimal_Digit" which it does know about (and which is documented below in "prop_invmap()").

  The full name is Punctuation

Some Unicode properties have a restricted set of legal values. For example, all binary properties are restricted to just "true" or "false"; and there are only a few dozen possible General Categories.

You can use "prop_values()" to find out if a given property is one which has a restricted set of values, and if so, what those values are. But usually each value actually has several synonyms. For example, in Unicode binary properties, truth can be represented by any of the strings "Y", "Yes", "T", or "True"; and the General Category "Punctuation" by that string, or "Punct", or simply "P".

Like property names, there is typically at least a short name for each such property-value, and a long name. If you know any name of the property-value (which you can get by "prop_values()", you can use "prop_value_aliases"() to get the long name (when called in scalar context), or a list of all the names, with the short name in the 0th element, the long name in the next element, and any other synonyms in the remaining elements, in no particular order, except that any all-numeric synonyms will be last.

The long name is returned in a form nicely capitalized, suitable for printing.
