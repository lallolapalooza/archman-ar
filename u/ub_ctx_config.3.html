الوصف

Unbound هو تطبيق لمحلل DNS، يقوم بالتخزين المؤقت والتحقق من صحة DNSSEC. هذه هي واجهة برمجة التطبيقات للمكتبة، لاستخدام مكتبة -lunbound. يتم وصف خادم الخدمة في unbound(8). تعمل المكتبة بشكل مستقل عن خادم unbound قيد التشغيل، ويمكن استخدامها لتحويل أسماء المضيفين إلى عناوين IP، والعكس صحيح، والحصول على معلومات أخرى من DNS. تقوم المكتبة بإجراء تحقق من صحة المفتاح العام للنتائج مع DNSSEC.

تستخدم المكتبة متغيرًا من النوع struct ub_ctx للاحتفاظ بالسياق بين المكالمات. يجب على المستخدم الاحتفاظ به، وإنشائه باستخدام ub_ctx_create وحذفه باستخدام ub_ctx_delete. يمكن إنشاؤه وحذفه في أي وقت. يؤدي إنشاؤه حديثًا إلى إزالة أي تكوين سابق (مثل مفاتيح الثقة) ومسح أي نتائج مخزنة مؤقتًا.

الوظائف آمنة للاستخدام في الخيوط المتوازية (threads-safe)، ويمكن استخدام سياق في بيئة متعددة الخيوط (وكذلك في بيئة غير متعددة الخيوط). يمكن أيضًا إجراء التحليل (والتحقق) بشكل متزامن (blocking) وغير متزامن (يُعرف أيضًا باسم غير متزامن). طريقة غير المتزامن تعود من المكالمة على الفور، بحيث يمكن معالجة النتائج لاحقًا.

تتم مناقشة الوظائف بالتتابع أدناه.

الوظائف

ub_ctx_create
ينشئ سياقًا جديدًا، مع تهيئته بالقيم الافتراضية. لا يتم استخدام المعلومات من /etc/resolv.conf و /etc/hosts افتراضيًا. استخدم ub_ctx_resolvconf و ub_ctx_hosts لقراءتها. قبل استدعاء هذه الوظيفة، استخدم وظائف openssl CRYPTO_set_id_callback و CRYPTO_set_locking_callback لتهيئة التشغيل غير المتزامن إذا كنت تستخدم مكتبة openssl (تستدعي التطبيقات هذه الوظائف مرة واحدة للتهيئة). يستخدم openssl 1.0.0 أو أحدث الوظيفة CRYPTO_THREADID_set_callback.
ub_ctx_delete
يحذف سياق التحقق ويحرر الموارد المرتبطة به. يتم إلغاء الاستعلامات غير المتزامنة المعلقة ولا يتم استدعاء ردود الاتصال لها.
ub_ctx_set_option
واجهة للمستخدمين المتقدمين تسمح لك بتحديد أحد الخيارات بتنسيق ملف التكوين، انظر unbound.conf(5). ليست كل الخيارات ذات صلة. لبعض الخيارات المحددة، مثل إضافة مرساة الثقة، توجد إجراءات خاصة. قم بتمرير اسم الخيار مع ':' اللاحقة.
ub_ctx_get_option
واجهة للمستخدمين المتقدمين تحصل على قيمة الخيار. بعض الخيارات لا يمكن الحصول عليها، والبعض الآخر يعيد قائمة مفصولة بسطر جديد. قم بتمرير اسم الخيار بدون ':' اللاحقة. يجب على المتصل تحرير القيمة المرجعة باستخدام free(2).
ub_ctx_config
واجهة للمستخدمين المتقدمين تسمح لك بتحديد ملف تكوين unbound، انظر unbound.conf(5)، الذي يتم قراءته للتكوين. ليست كل الخيارات ذات صلة. لبعض الخيارات المحددة، مثل إضافة مرساة الثقة، توجد إجراءات خاصة. هذه الوظيفة آمنة للاستخدام في الخيوط المتوازية فقط إذا كان هناك مثيل واحد من ub_ctx* موجود في التطبيق. إذا كانت هناك عدة مثيلات، يجب على التطبيق التأكد من عدم استدعاء ub_ctx_config بالتوازي بواسطة المثيلات المختلفة.
ub_ctx_set_fwd
تعيين الجهاز لإعادة توجيه استعلامات DNS إليه، وهو محلل التخزين المؤقت للاستخدام. عنوان IP4 أو IP6. يقوم بإعادة توجيه جميع طلبات DNS إلى هذا الجهاز، الذي يُتوقع أن يقوم بتشغيل محلل تكراري. إذا لم يكن الوكيل قادرًا على DNSSEC، فقد تفشل عملية التحقق. يمكن استدعاؤه عدة مرات، وفي هذه الحالة يتم استخدام العناوين كخوادم احتياطية. في هذا الوقت، من الممكن فقط تعيين التكوين قبل إجراء أول تحليل.
ub_ctx_set_stub
تعيين منطقة وهمية (stub zone)، وهي خوادم DNS مسؤولة لاستخدامها لمنطقة معينة. عنوان IP4 أو IP6. إذا كان العنوان NULL، يتم إزالة إدخال الوهم. قم بتعيين isprime إلى true إذا كنت تقوم بتكوين تلميحات الجذر (root hints) معها. بخلاف ذلك، فهي مشابهة لعنصر المنطقة الوهمية من ملف تكوين unbound. يمكن استدعاؤه عدة مرات، لمناطق مختلفة، أو لإضافة عناوين متعددة لمنطقة معينة. في هذا الوقت، من الممكن فقط تعيين التكوين قبل إجراء أول تحليل.
ub_ctx_set_tls
تمكين DNS عبر TLS (DoT) للأجهزة التي تم تعيينها باستخدام ub_ctx_set_fwd. في هذا الوقت، من الممكن فقط تعيين التكوين قبل إجراء أول تحليل.
ub_ctx_resolvconf
افتراضيًا، يتم الاستعلام عن الخوادم الجذرية ويتم استخدام وضع المحلل الكامل، ولكن يمكنك استخدام هذا الاستدعاء لقراءة قائمة خوادم الأسماء للاستخدام من اسم الملف المحدد. عادةً "/etc/resolv.conf". تستخدم خوادم الأسماء هذه كوكلاء تخزين مؤقت. إذا لم تدعم DNSSEC، فقد تفشل عملية التحقق. يتم التقاط خوادم الأسماء فقط، ويتم تجاهل searchdomain و ndots والإعدادات الأخرى من resolv.conf(5). إذا تم تمرير fname NULL، فسيتم استخدام "/etc/resolv.conf" (إذا كان على Windows، فسيتم اختيار خادم النظام المحدد في النظام بدلاً من ذلك). في هذا الوقت، من الممكن فقط تعيين التكوين قبل إجراء أول تحليل.
ub_ctx_hosts
اقرأ قائمة المضيفين من اسم الملف المحدد. عادةً "/etc/hosts". عند الاستعلام عن هذه العناوين، لا يتم تمييزها على أنها آمنة بـ DNSSEC. إذا تم تمرير fname NULL، فسيتم استخدام "/etc/hosts" (إذا كان على Windows، فسيتم اختيار etc/hosts من WINDIR بدلاً من ذلك). في هذا الوقت، من الممكن فقط تعيين التكوين قبل إجراء أول تحليل.

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

DESCRIPTION

The unbound validating resolver library provides functions to perform DNS lookups with validation (DNSSEC) from within applications. This library is used by the unbound daemon itself, and can be used by other applications.

The library uses a context object, which holds the configuration and state of the resolver. It is created with ub_ctx_create and destroyed with ub_ctx_destroy. All other functions operate on this context.

The context should be configured before use. This can be done by calling ub_ctx_config with a configuration file name, for example the standard unbound.conf file, or by calling ub_ctx_resolvconf to read the system's resolv.conf file to find upstream servers.

Trust anchors can be added to the context. These are used for validating DNSSEC data. See ub_ctx_add_ta, ub_ctx_add_ta_file, and ub_ctx_trustedkeys.

By default, debug messages are sent to stderr. You can change this with ub_ctx_debugout and set the verbosity with ub_ctx_debuglevel.

By default, asynchronous operations are performed using threads. If you want to use forking instead, set the flag with ub_ctx_async to false. Note that this setting has no effect after the first asynchronous operation has been started.

The library can be used in a synchronous or asynchronous manner. For synchronous use, call ub_resolve. This function blocks until the result is available. For asynchronous use, call ub_resolve_async. This function returns immediately, and the result is delivered later via a callback function.

To use the asynchronous functions, you need to poll the context for activity. You can do this by calling ub_poll periodically, or by using the file descriptor returned by ub_fd with a select(2) call. When ub_poll returns non-zero, or the file descriptor becomes readable, you should call ub_process to process the results and call any pending callbacks. Alternatively, you can use ub_wait, which blocks until results are available and then calls ub_process.

If you are using asynchronous operations, you can cancel a pending query using ub_cancel.

The results of a query are returned in a struct ub_result. This structure should be freed using ub_resolve_free when no longer needed.

Error codes returned by the library functions can be converted to human-readable strings using ub_strerror.

Local zones and data can be added to the context for authoritative serving. See ub_ctx_zone_add, ub_ctx_data_add, and their corresponding remove functions.

FUNCTIONS

ub_ctx_create
Create a new context for the unbound library. Returns a pointer to the context, or NULL on memory allocation failure.
ub_ctx_destroy
Destroy the given context and free all associated resources. This should be called when the context is no longer needed.
ub_ctx_config
Configure the context using settings from the given configuration file. This can be called multiple times, but typically should be called only once before the first resolve operation.
ub_ctx_resolvconf
Configure the context using upstream servers from the given resolv.conf file. This can be called multiple times, but typically should be called only once before the first resolve operation.
ub_ctx_add_ta
Add a trust anchor to the given context. At this time it is only possible to add trusted keys before the first resolve is done. The format is a string, similar to the zone-file format, [domainname] [type] [rdata contents]. Both DS and DNSKEY records are accepted.
ub_ctx_add_ta_autr
Add filename with automatically tracked trust anchor to the given context. Pass name of a file with the managed trust anchor. You can create this file with unbound-anchor(8) for the root anchor. You can also create it with an initial file with one line with a DNSKEY or DS record. If the file is writable, it is updated when the trust anchor changes. At this time it is only possible to add trusted keys before the first resolve is done.
ub_ctx_add_ta_file
Add trust anchors to the given context. Pass name of a file with DS and DNSKEY records in zone file format. At this time it is only possible to add trusted keys before the first resolve is done.
ub_ctx_trustedkeys
Add trust anchors to the given context. Pass the name of a bind-style config file with trusted-keys{}. At this time it is only possible to add trusted keys before the first resolve is done.
ub_ctx_debugout
Set debug and error log output to the given stream. Pass NULL to disable output. Default is stderr. File-names or using syslog can be enabled using config options, this routine is for using your own stream.
ub_ctx_debuglevel
Set debug verbosity for the context. Output is directed to stderr. Higher debug level gives more output.
ub_ctx_async
Set a context behaviour for asynchronous action. if set to true, enables threading and a call to ub_resolve_async creates a thread to handle work in the background. If false, a process is forked to handle work in the background. Changes to this setting after ub_resolve_async calls have been made have no effect (delete and re-create the context to change).
ub_poll
Poll a context to see if it has any new results. Do not poll in a loop, instead extract the fd below to poll for readiness, and then check, or wait using the wait routine. Returns 0 if nothing to read, or nonzero if a result is available. If nonzero, call ub_process to do callbacks.
ub_wait
Wait for a context to finish with results. Calls ub_process after the wait for you. After the wait, there are no more outstanding asynchronous queries.
ub_fd
Get file descriptor. Wait for it to become readable, at this point answers are returned from the asynchronous validating resolver. Then call the ub_process to continue processing.
ub_process
Call this routine to continue processing results from the validating resolver (when the fd becomes readable). Will perform necessary callbacks.
ub_resolve
Perform resolution and validation of the target name. The name is a domain name in a zero terminated text string. The rrtype and rrclass are DNS type and class codes. The result structure is newly allocated with the resulting data.
ub_resolve_async
Perform asynchronous resolution and validation of the target name. Arguments mean the same as for ub_resolve except no data is returned immediately, instead a callback is called later. The callback receives a copy of the mydata pointer, that you can use to pass information to the callback. The callback type is a function pointer to a function declared as:
void my_callback_function(void* my_arg, int err,
                struct ub_result* result);

The async_id is returned so you can (at your option) decide to track it and cancel the request if needed. If you pass a NULL pointer the async_id is not returned.

ub_cancel
Cancel an async query in progress. This may return an error if the query does not exist, or the query is already being delivered, in that case you may still get a callback for the query.
ub_resolve_free
Free struct ub_result contents after use.
ub_strerror
Convert error value from one of the unbound library functions to a human readable string.
ub_ctx_print_local_zones
Debug printout the local authority information to debug output.
ub_ctx_zone_add
Add new zone to local authority info, like local-zone unbound.conf(5) statement.
ub_ctx_zone_remove
Delete zone from local authority info.
ub_ctx_data_add
Add resource record data to local authority info, like local-data unbound.conf(5) statement.
ub_ctx_data_remove
Delete local authority data from the name given.

RESULT DATA STRUCTURE

The result of the DNS resolution and validation is returned as struct ub_result. The result structure contains the following entries:

struct ub_result {
     char* qname;         /* نص، السؤال الأصلي */
     int qtype;           /* رمز النوع المطلوب */
     int qclass;          /* رمز الفئة المطلوبة */
     char** data;         /* مصفوفة من عناصر rdata، منتهية بـ NULL*/
     int* len;            /* مصفوفة بأطوال عناصر rdata */
     char* canonname;     /* الاسم القانوني للنتيجة */
     int rcode;           /* رمز خطأ إضافي في حالة عدم وجود بيانات */
     void* answer_packet; /* حزمة إجابة كاملة بتنسيق الشبكة */
     int answer_len;      /* طول الحزمة بالبايت */
     int havedata;        /* صحيح إذا كانت هناك بيانات */
     int nxdomain;        /* صحيح إذا لم تكن هناك بيانات لأن الاسم غير موجود */
     int secure;          /* صحيح إذا كانت النتيجة آمنة */
     int bogus;           /* صحيح إذا حدث فشل أمني */
     char* why_bogus;     /* سلسلة نصية مع الخطأ إذا كانت مزيفة */
     int was_ratelimited; /* صحيح إذا تم تحديد معدل استعلام unbound (SERVFAIL) */
     int ttl;             /* عدد الثواني التي تكون النتيجة صالحة فيها */
};

If both secure and bogus are false, security was not enabled for the domain of the query. Else, they are not both true, one of them is true.

RETURN VALUES

Many routines return an error code. The value 0 (zero) denotes no error happened. Other values can be passed to ub_strerror to obtain a readable error string. ub_strerror returns a zero terminated string. ub_ctx_create returns NULL on an error (a malloc failure). ub_poll returns true if some information may be available, false otherwise. ub_fd returns a file descriptor or -1 on error. ub_ctx_config and ub_ctx_resolvconf attempt to leave errno informative on a function return with file read failure.
