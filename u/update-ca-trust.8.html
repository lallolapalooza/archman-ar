الحزمة: ca-certificates-utils

UPDATE-CA-TRUST(8)   UPDATE-CA-TRUST(8)

الاسم

update-ca-trust - إدارة التكوين الموحد والديناميكي لشهادات CA والثقة المرتبطة بها

الملخص

update-ca-trust [extract] [-o DIR|--output=DIR]

الوصف

يُستخدم update-ca-trust(8) لإدارة ميزة تكوين موحدة وديناميكية لشهادات هيئة المصادقة (CA) والثقة المرتبطة بها.

الميزة متاحة للتطبيقات الجديدة التي تقرأ ملفات التكوين الموحدة الموجودة في الدليل /etc/ca-certificates/extracted أو التي تقوم بتحميل وحدة PKCS#11 p11-kit-trust.so

يتم توفير أجزاء من الميزة الجديدة بطريقة تجعلها مفيدة للتطبيقات القديمة.

تتوقع العديد من التطبيقات القديمة شهادات CA وتكوين الثقة في موقع ثابت، موجودة في ملفات ذات مسار واسم معينين، أو عن طريق الإشارة إلى وحدة ثقة PKCS#11 كلاسيكية توفرها مكتبة التشفير NSS.

توفر ميزة التكوين الديناميكي بدائل متوافقة وظيفيًا للملفات الكلاسيكية وللوحدة الكلاسيكية NSS المسماة libnssckbi.

لتمكين التطبيقات القديمة، التي تقرأ الملفات الكلاسيكية أو تصل إلى الوحدة الكلاسيكية، من الاستفادة من ميزة التكوين الموحد والديناميكي الجديدة، تم تغيير أسماء الملفات الكلاسيكية إلى روابط رمزية. تشير الروابط الرمزية إلى مخرجات تم إنشاؤها ديناميكيًا وتوحيدها مخزنة أسفل التسلسل الهرمي للدليل /etc/ca-certificates/extracted.

يتم إنتاج المخرجات باستخدام الأمر update-ca-trust (بدون معلمات)، أو باستخدام الأمر update-ca-trust extract. لإنتاج المخرجات، يتم قراءة مجموعة مرنة من تكوينات المصدر، كما هو موضح في قسم تكوين المصدر.

بالإضافة إلى ذلك، تم استبدال وحدة PKCS#11 الكلاسيكية بوحدة PKCS#11 جديدة (p11-kit-trust.so) تقرأ نفس تكوينات المصدر ديناميكيًا.

تكوين المصدر

تستخدم ميزة التكوين الديناميكي عدة أدلة مصدر سيتم مسحها ضوئيًا لأي عدد من ملفات المصدر. من المهم اختيار الدليل الفرعي الصحيح لإضافة الملفات، حيث يحدد الدليل الفرعي كيف سيتم الثقة في الشهادات الموجودة أو عدم الثقة بها، وما هي تنسيقات الملفات التي يتم قراءتها.

تحتوي الملفات الموجودة في الأدلة الفرعية أسفل التسلسل الهرمي للدليل /usr/share/ca-certificates/trust-source/ على شهادات CA وإعدادات الثقة بتنسيق ملف PEM. سيتم تفسير إعدادات الثقة الموجودة هنا بأولوية منخفضة.

تحتوي الملفات الموجودة في الأدلة الفرعية أسفل التسلسل الهرمي للدليل /etc/ca-certificates/trust-source/ على شهادات CA وإعدادات الثقة بتنسيق ملف PEM. سيتم تفسير إعدادات الثقة الموجودة هنا بأولوية عالية.

يمكنك استخدام القواعد العامة التالية لتحديد ما إذا كان يجب إضافة ملفات التكوين الخاصة بك إلى /etc أو بالأحرى إلى التسلسل الهرمي للدليل /usr:

•إذا كنت تضيف ملف تكوين يدويًا إلى نظام، فمن المحتمل أنك تريده أن يتجاوز أي تكوين افتراضي آخر، ومن الأرجح أن تضيفه إلى الدليل الفرعي المناسب في تسلسل /etc الهرمي.
•إذا كنت تقوم بإنشاء حزمة توفر شهادات CA جذر إضافية، والمخصصة للتوزيع على عدة أنظمة كمبيوتر، ولكنك لا تزال ترغب في السماح للمسؤول بتجاوز قائمتك، فيجب على حزمتك إضافة ملفاتك إلى الدليل الفرعي المناسب في تسلسل /usr الهرمي.
•إذا كنت تقوم بإنشاء حزمة مخصصة لتجاوز إعدادات الثقة الافتراضية للنظام، والمخصصة للتوزيع على عدة أنظمة كمبيوتر، فيجب على حزمتك تثبيت الملفات في الدليل الفرعي المناسب في تسلسل /etc الهرمي.

مساعدة سريعة 1: لإضافة شهادة بتنسيقات ملف PEM أو DER البسيطة إلى قائمة CA الموثوق بها على النظام:

•أضفها كملف جديد إلى الدليل /etc/ca-certificates/trust-source/anchors/
•قم بتشغيل update-ca-trust extract

مساعدة سريعة 2: إذا كانت شهادتك بتنسيق ملف BEGIN TRUSTED الموسع (الذي قد يحتوي على علامات رفض/حظر الثقة، أو علامات ثقة لاستخدامات أخرى غير TLS) فقم بما يلي:

•أضفها كملف جديد إلى الدليل /etc/ca-certificates/trust-source/
•قم بتشغيل update-ca-trust extract

لتوفير البساطة والمرونة، تعتمد طريقة معالجة ملفات الشهادات على الدليل الفرعي الذي تم تثبيتها فيه.

•الدليل الفرعي لمراسي الثقة البسيطة: /usr/share/ca-certificates/trust-source/anchors/ أو /etc/ca-certificates/trust-source/anchors/
•قائمة الحظر البسيطة (رفض الثقة) الدليل الفرعي: /usr/share/ca-certificates/trust-source/blocklist/ أو /etc/ca-certificates/trust-source/blocklist/
•دليل التنسيق الموسع: /usr/share/ca-certificates/trust-source/ أو /etc/ca-certificates/trust-source/

في الأدلة الرئيسية /usr/share/ca-certificates/trust-source/ أو /etc/ca-certificates/trust-source/ يمكنك تثبيت ملف واحد أو أكثر بالتنسيقات التالية:

•ملفات الشهادات التي تتضمن علامات الثقة، بتنسيق ملف BEGIN/END TRUSTED CERTIFICATE (أي اسم ملف)، والتي تم إنشاؤها باستخدام أداة openssl x509 وخيارات -addreject -addtrust. يتم دعم ملفات التجميع مع شهادات متعددة.
•الملفات بتنسيق ملف p11-kit باستخدام امتداد اسم الملف .p11-kit، والتي يمكن (على سبيل المثال) استخدامها لرفض الثقة في الشهادات بناءً على الرقم التسلسلي واسم المُصدر، دون توفر الشهادة الكاملة. (هذا حاليًا تنسيق غير موثق، سيتم توسيعه لاحقًا. للحصول على أمثلة للتنسيقات المدعومة، انظر الملفات التي تم شحنها مع حزمة ca-certificates-mozilla.)
•ملفات الشهادات بدون علامات ثقة إما بتنسيق ملف DER أو بتنسيق ملف PEM (BEGIN/END CERTIFICATE) (أي اسم ملف). سيتم التعامل مع هذه الملفات بثقة محايدة، لا موثوق بها ولا مرفوضة. سيتم ببساطة معرفتها من قبل النظام، مما قد يكون مفيدًا لمساعدة برامج التشفير في بناء سلاسل الشهادات. (إذا كنت تريد أن تكون شهادة CA بهذه التنسيقات مفضلة، يجب عليك إزالتها من هذا الدليل ونقلها إلى الدليل الفرعي ./anchors بدلاً من ذلك.)

في الأدلة الفرعية لمراسي الثقة /usr/share/ca-certificates/trust-source/anchors/ أو /etc/ca-certificates/trust-source/anchors/ يمكنك تثبيت شهادة واحدة أو أكثر إما بتنسيق ملف DER أو بتنسيق ملف PEM (BEGIN/END CERTIFICATE). سيتم التعامل مع كل شهادة على أنها موثوق بها لجميع الأغراض.

في الأدلة الفرعية لقائمة الحظر /usr/share/ca-certificates/trust-source/blocklist/ أو /etc/ca-certificates/trust-source/blocklist/ يمكنك تثبيت شهادة واحدة أو أكثر إما بتنسيق ملف DER أو بتنسيق ملف PEM (BEGIN/END CERTIFICATE). سيتم التعامل مع كل شهادة على أنها مرفوضة لجميع الأغراض.

يرجى الرجوع إلى صفحة الدليل x509(1) للحصول على وثائق تنسيقات ملفات BEGIN/END CERTIFICATE و BEGIN/END TRUSTED CERTIFICATE.

التطبيقات التي تعتمد على ملف ثابت لقائمة CA الموثوق بها قد تقوم بتحميل أحد الملفات الموجودة في الدليل /etc/ca-certificates/extracted. بعد تعديل أي ملف في /usr/share/ca-certificates/trust-source/ أو /etc/ca-certificates/trust-source/ أو في أي من أدلتها الفرعية، أو بعد إضافة ملف، يجب تشغيل الأمر update-ca-trust extract، لتحديث الملفات الموحدة في /etc/ca-certificates/extracted/.

التطبيقات التي تقوم بتحميل وحدة PKCS#11 الكلاسيكية باستخدام اسم الملف libnssckbi.so (والتي تم تحويلها إلى رابط رمزي يشير إلى الوحدة الجديدة) وأي تطبيق قادر على تحميل وحدات PKCS#11 وتحميل p11-kit-trust.so، ستستفيد من المجموعة المدمجة ديناميكيًا من الشهادات ومعلومات الثقة المخزنة في /usr/share/ca-certificates/trust-source/ و /etc/ca-certificates/trust-source/ الأدلة.

التكوين المستخرج

يحتوي الدليل /etc/ca-certificates/extracted/ على ملفات تجميع شهادات CA التي تم إنشاؤها وتحديثها، بناءً على تكوين المصدر عن طريق تشغيل الأمر update-ca-trust extract.

إذا لم يكن تطبيقك قادرًا على تحميل وحدة PKCS#11 p11-kit-trust.so، فيمكنك استخدام هذه الملفات في تطبيقك لتحميل قائمة

update-ca-trust(8) — Arch Linux

NAME

update-ca-trust — update the trusted CA certificate store

SYNOPSIS

update-ca-trust [COMMAND] [OPTIONS]...

DESCRIPTION

The purpose of the update-ca-trust command is to manage the system's collection of trusted certificates. It consolidates certificates from multiple sources into various formats that applications can use to verify the identity of servers and other entities.

The command reads configuration files from specified source directories, processes them, and generates updated certificate bundles and keystores in the extracted configuration directory. This process ensures that the system's trust store is consistent and up-to-date with the installed certificates.

SOURCE CONFIGURATION

The source configuration directory hierarchy is used to define which CA certificates should be considered trusted or distrusted. It consists of two main directories:

/usr/share/ca-certificates/trust-source/
This directory contains low-priority source configuration files. Files placed here are considered less important and are processed after files in the high-priority directory.
/etc/ca-certificates/trust-source/
This directory contains high-priority source configuration files. Files placed here are processed first and override or supplement settings from the low-priority directory. This is the preferred location for system administrators to add custom trusted or distrusted certificates.

Within these directories, you can create subdirectories (e.g., /etc/ca-certificates/trust-source/anchors/) to organize your certificates. Certificates placed in these subdirectories are automatically included in the trust store based on their type and format.

For detailed information on how to structure your source configuration and specify trust or distrust flags, refer to the documentation for the specific trust module being used (e.g., the `trust` command man page).

EXTRACTED CONFIGURATION

The directory /etc/ca-certificates/extracted/ stores the consolidated and automatically generated configuration files that are ready for consumption by applications. These files are produced by running the update-ca-trust extract command.

Important: Please never manually edit the files stored in this directory, because your changes will be lost and the files automatically overwritten, each time the update-ca-trust extract command gets executed.

In order to install new trusted or distrusted certificates, please rather install them in the respective subdirectory below the /usr/share/ca-certificates/trust-source/ or /etc/ca-certificates/trust-source/ directories, as described in the SOURCE CONFIGURATION section.

The directory /etc/ca-certificates/extracted/ contains a CA certificate bundle in the java keystore file format. Distrust information cannot be represented in this file format, and distrusted certificates are missing from these files. File java-cacerts.jks contains CA certificates trusted for TLS server authentication.

It also contains CA certificate bundle files in the extended BEGIN/END TRUSTED CERTIFICATE file format, as described in the x509(1) manual page. File ca-bundle.trust.crt contains the full set of all trusted or distrusted certificates, including the associated trust flags.

It also contains CA certificate bundle files in the simple BEGIN/END CERTIFICATE file format, as described in the x509(1) manual page. Distrust information cannot be represented in this file format, and distrusted certificates are missing from these files. File tls-ca-bundle.pem contains CA certificates trusted for TLS server authentication. File email-ca-bundle.pem contains CA certificates trusted for E-Mail protection. File objsign-ca-bundle.pem contains CA certificates trusted for code signing.

It also contains a CA certificate bundle ("edk2-cacerts.bin") in the "sequence of EFI_SIGNATURE_LISTs" format, defined in the UEFI-2.7 specification, sections "31.4.1 Signature Database" and "EFI_CERT_X509_GUID". Distrust information cannot be represented in this file format, and distrusted certificates are missing from these files. File "edk2-cacerts.bin" contains CA certificates trusted for TLS server authentication.

COMMANDS

(absent/empty command)

Same as the extract command described below. (However, the command may print fewer warnings, as this command is being run during rpm package installation, where non-fatal status output is undesired.)

extract

Instruct update-ca-trust to scan the SOURCE CONFIGURATION and produce updated versions of the consolidated configuration files stored below the /etc/ca-certificates/extracted directory hierarchy.

EXTRACT OPTIONS

-o DIR, --output=DIR

Write the extracted trust store into the given directory instead of updating /etc/ca-certificates/extracted.

FILES

/etc/ssl/cert.pem

Classic filename, file contains a list of CA certificates trusted for TLS server authentication usage, in the simple BEGIN/END CERTIFICATE file format, without distrust information. This file is a symbolic link that refers to the consolidated output created by the update-ca-trust command.

/etc/ssl/certs/

Classic directory, contains individual CA certificates trusted for TLS server authentication usage, in the simple BEGIN/END CERTIFICATE file format, without distrust information. Also includes the necessary hash symlinks expected by OpenSSL. The files are symbolic links that refer to the output created by the update-ca-trust command.

/etc/ssl/certs/ca-bundle.crt

Classic filename for compatibility with RHEL/Fedora, file contains a list of CA certificates trusted for TLS server authentication usage, in the simple BEGIN/END CERTIFICATE file format, without distrust information. This file is a symbolic link that refers to the consolidated output created by the update-ca-trust command.

/etc/ssl/certs/ca-certificates.crt

Classic filename for compatibility with Debian, file contains a list of CA certificates trusted for TLS server authentication usage, in the simple BEGIN/END CERTIFICATE file format, without distrust information. This file is a symbolic link that refers to the consolidated output created by the update-ca-trust command.

/etc/ssl/certs/java/cacerts

Classic filename, file contains a list of CA certificates trusted for TLS server authentication usage, in the Java keystore file format, without distrust information. This file is a symbolic link that refers to the consolidated output created by the update-ca-trust command.

/usr/share/ca-certificates/trust-source

Contains multiple, low priority source configuration files as explained in section SOURCE CONFIGURATION. Please pay attention to the specific meanings of the respective subdirectories.

/etc/ca-certificates/trust-source

Contains multiple, high priority source configuration files as explained in section SOURCE CONFIGURATION. Please pay attention to the specific meanings of the respective subdirectories.

/etc/ca-certificates/extracted

Contains consolidated and automatically generated configuration files for consumption by applications, which are created using the update-ca-trust extract command. Don’t edit files in this directory, because they will be overwritten. See section EXTRACTED CONFIGURATION for additional details.

/etc/ca-certificates/extracted/ca-bundle.trust.crt

File contains a list of CA certificates in the extended BEGIN/END TRUSTED CERTIFICATE file format, which includes trust (and/or distrust) flags specific to certificate usage. This file is consolidated output created by the update-ca-trust command.

/etc/ca-certificates/extracted/email-ca-bundle.pem

File contains a list of CA certificates trusted for E-Mail protection, in the simple BEGIN/END CERTIFICATE file format, without distrust information. This file is consolidated output created by the update-ca-trust command.

/etc/ca-certificates/extracted/objsign-ca-bundle.pem

File contains a list of CA certificates trusted for code signing, in the simple BEGIN/END CERTIFICATE file format, without distrust information. This file is consolidated output created by the update-ca-trust command.

/etc/ca-certificates/extracted/tls-ca-bundle.pem

File contains a list of CA certificates trusted for TLS server authentication, in the simple BEGIN/END CERTIFICATE file format, without distrust information. This file is consolidated output created by the update-ca-trust command.

/etc/ca-certificates/extracted/cadir/

Contains individual CA certificates trusted for TLS server authentication usage, in the simple BEGIN/END CERTIFICATE file format, without distrust information. Also includes the necessary hash symlinks expected by OpenSSL. These files are maintained by the update-ca-trust command.

/etc/ca-certificates/extracted/edk2-cacerts.bin

File contains a list of CA certificates trusted for TLS server authentication usage, in the UEFI signature database format, without distrust information. This file is consolidated output created by the update-ca-trust command.

/etc/ca-certificates/extracted/java-cacerts.jks

File contains a list of CA certificates trusted for TLS server authentication usage, in the Java keystore file format, without distrust information. This file is consolidated output created by the update-ca-trust command.
