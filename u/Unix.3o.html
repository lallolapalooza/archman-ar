exception Unix_error of error * string * string

يتم إثارتها بواسطة استدعاءات النظام أدناه عند مواجهة خطأ. المكون الأول هو رمز الخطأ؛ المكون الثاني هو اسم الدالة؛ المكون الثالث هو المعلمة النصية للدالة، إذا كانت موجودة، أو السلسلة الفارغة بخلاف ذلك.

UnixLabels.Unix_error و Unix.Unix_error متماثلان، والتقاط أحدهما سيangkap الآخر.

val error_message : error -> string

إرجاع سلسلة نصية تصف رمز الخطأ المعطى.

val handle_unix_error : ('a -> 'b) -> 'a -> 'b

handle_unix_error f x يطبق f على x ويرجع النتيجة. إذا تم إثارة الاستثناء Unix.Unix_error ، فإنه يطبع رسالة تصف الخطأ ويخرج بالرمز 2.

الوصول إلى بيئة العملية

val environment : unit -> string array

إرجاع بيئة العملية، كمصفوفة من السلاسل النصية بالتنسيق ``variable=value''. تكون المصفوفة المرجعة فارغة إذا كانت للعملية امتيازات خاصة.

val unsafe_environment : unit -> string array

إرجاع بيئة العملية، كمصفوفة من السلاسل النصية بالتنسيق ``variable=value''. على عكس Unix.environment ، ترجع هذه الدالة مصفوفة مملوءة حتى لو كانت للعملية امتيازات خاصة. انظر التوثيق لـ Unix.unsafe_getenv لمزيد من التفاصيل.

منذ 4.06 (4.12 في UnixLabels)

val getenv : string -> string

إرجاع القيمة المرتبطة بمتغير في بيئة العملية، إلا إذا كانت للعملية امتيازات خاصة.

يثير Not_found إذا كان المتغير غير مرتبط أو إذا كانت للعملية امتيازات خاصة.

هذه الدالة متطابقة مع Sys.getenv .

val unsafe_getenv : string -> string

إرجاع القيمة المرتبطة بمتغير في بيئة العملية.

على عكس Unix.getenv ، ترجع هذه الدالة القيمة حتى لو كانت للعملية امتيازات خاصة. تعتبر غير آمنة لأن مبرمج برنامج setuid أو setgid يجب أن يكون حذرًا لتجنب استخدام متغيرات البيئة التي تم إنشاؤها بشكل خبيث في مسار البحث للملفات التنفيذية، ومواقع الملفات المؤقتة أو السجلات، وما شابه ذلك.

منذ 4.06

يثير Not_found إذا كان المتغير غير مرتبط.

val putenv : string -> string -> unit

putenv name value يحدد القيمة المرتبطة بمتغير في بيئة العملية. name هو اسم متغير البيئة، و value هي قيمته الجديدة المرتبطة.

قنوات

تتيح لك هذه الدوال إنشاء قنوات الإدخال والإخراج من وإلى واصفات الملفات.

val in_channel_of_descr : file_descr -> in_channel

إنشاء قناة إدخال للقراءة من الواصف المحدد. تبدأ القناة في الوضع الثنائي؛ استخدم set_binary_mode_in ic false إذا كنت ترغب في وضع النص. وضع النص مدعوم فقط إذا كان الواصف يشير إلى ملف أو أنبوب، ولكنه غير مدعوم إذا كان يشير إلى مقبس.

على نظام Windows: تفشل set_binary_mode_in دائمًا على القنوات التي تم إنشاؤها باستخدام هذه الدالة.

احذر من أن قنوات الإدخال تكون مخزنة مؤقتًا، لذلك قد تتم قراءة المزيد من الأحرف من الواصف أكثر من تلك التي تم الوصول إليها باستخدام وظائف القناة. تحتفظ القنوات أيضًا بنسخة من الموضع الحالي في الملف.

إغلاق القناة ic التي تم إرجاعها بواسطة in_channel_of_descr fd باستخدام close_in ic يغلق أيضًا الواصف الأساسي fd . من غير الصحيح إغلاق كل من القناة ic والواصف fd .

إذا تم إنشاء عدة قنوات على نفس الواصف، فيجب إغلاق إحدى القنوات، ولكن ليس غيرها. ضع في اعتبارك على سبيل المثال واصفًا s متصلًا بمقبس وقناتين ic = in_channel_of_descr s و oc = out_channel_of_descr s . بروتوكول الإغلاق الموصى به هو تنفيذ close_out oc ، والذي يقوم بتفريغ الإخراج المخزن مؤقتًا إلى المقبس ثم يغلق المقبس. يجب عدم إغلاق القناة ic وسيتم جمعها بواسطة GC في النهاية.

val out_channel_of_descr : file_descr -> out_channel

إنشاء قناة إخراج للكتابة على الواصف المحدد. تبدأ القناة في الوضع الثنائي؛ استخدم set_binary_mode_out oc false إذا كنت ترغب في وضع النص. وضع النص مدعوم فقط إذا كان الواصف يشير إلى ملف أو أنبوب، ولكنه غير مدعوم إذا كان يشير إلى مقبس.

على نظام Windows: تفشل set_binary_mode_out دائمًا على القنوات التي تم إنشاؤها باستخدام هذه الدالة.

احذر من أن قنوات الإخراج تكون مخزنة مؤقتًا، لذلك قد تحتاج إلى استدعاء flush لضمان إرسال جميع البيانات إلى الواصف. تحتفظ القنوات أيضًا بنسخة من الموضع الحالي في الملف.

إغلاق القناة oc التي تم إرجاعها بواسطة out_channel_of_descr fd باستخدام close_out oc يغلق أيضًا الواصف الأساسي fd . من غير الصحيح إغلاق كل من القناة ic والواصف fd .

تعيين الملفات في الذاكرة

val map_file : file_descr -> ?pos:int64 -> ('a, 'b) Bigarray.kind -> 'c Bigarray.layout -> bool -> int array -> ('a, 'b, 'c) Bigarray.Genarray.t

تعيين الذاكرة لملف كـ Bigarray. ترجع map_file fd kind layout shared dims Bigarray من النوع kind ، والتخطيط layout ، والأبعاد كما هو محدد في dims . البيانات الموجودة في هذا Bigarray هي محتويات الملف المشار إليه بواسطة واصف الملف fd (كما تم فتحه مسبقًا باستخدام Unix.openfile ، على سبيل المثال). المعلمة الاختيارية pos هي إزاحة البايت في الملف للبيانات التي يتم تعيينها؛ افتراضاتها هي 0 (تعيين من بداية الملف).

إذا كان shared هو true ، فإن جميع التعديلات التي تم إجراؤها على المصفوفة تنعكس في الملف. يتطلب هذا أن يتم فتح fd بأذونات الكتابة. إذا كان shared هو false ، يتم إجراء التعديلات التي تم إجراؤها على المصفوفة في الذاكرة فقط، باستخدام النسخ عند الكتابة للصفحات المعدلة؛ لا يتأثر الملف الأساسي.

Unix.map_file أكثر كفاءة بكثير من قراءة الملف بأكمله في Bigarray، وتعديل هذا Bigarray، وكتابته لاحقًا.

لضبط أبعاد Bigarray تلقائيًا مع الحجم الفعلي للملف، يمكن إعطاء البعد الرئيسي (أي، البعد الأول لمصفوفة بتخطيط C، والبعد الأخير لمصفوفة بتخطيط Fortran) على أنه -1 . تحدد Unix.map_file بعد ذلك البعد الرئيسي من حجم الملف. يجب أن يحتوي الملف على عدد صحيح من المصفوفات الفرعية كما هو محدد بواسطة الأبعاد غير الرئيسية، وإلا فسيتم رفع Failure .

إذا تم إعطاء جميع أبعاد Bigarray، تتم مطابقة حجم الملف مع حجم Bigarray. إذا كان الملف أكبر من Bigarray، يتم فقط تعيين الجزء الأولي من الملف إلى Bigarray. إذا كان الملف أصغر من Bigarray، يتم توسيع الملف تلقائيًا إلى حجم Bigarray. يتطلب هذا أذونات الكتابة على fd .

يتم فحص حدود وصول المصفوفة، ولكن يتم تحديد الحدود بواسطة الاستدعاء الأولي لـ map_file . لذلك، يجب عليك التأكد من عدم قيام أي عملية أخرى بتعديل الملف المعين أثناء وصولك إليه، وإلا فقد يتم رفع إشارة SIGBUS. يحدث هذا، على سبيل المثال، إذا تم تقليص حجم الملف.

قد يتم رفع Invalid_argument أو Failure في الحالات التي يفشل فيها التحقق من صحة الوسيطات.

val set_close_on_exec : file_descr -> unit

تعيين علامة "الإغلاق عند التنفيذ" على الواصف المعطى. يتم إغلاق الواصف الذي يحمل علامة الإغلاق عند التنفيذ تلقائيًا عندما تبدأ العملية الحالية برنامجًا آخر باستخدام إحدى وظائف exec أو create_process أو open_process.

غالبًا ما يكون تسريب واصفات الملفات المفتوحة على ملف خاص، على سبيل المثال، إلى برنامج خارجي يمثل ثغرة أمنية: يحصل البرنامج بعد ذلك على وصول إلى الملف الخاص ويمكنه فعل أشياء سيئة به. وبالتالي، يوصى بشدة بتعيين علامة "الإغلاق عند التنفيذ" لجميع واصفات الملفات، باستثناء الحالات القليلة جدًا التي يحتاج فيها واصف الملف بالفعل إلى نقله إلى برنامج آخر.

أفضل طريقة لتعيين واصف ملف في وضع "الإغلاق عند التنفيذ" هي إنشاؤه بهذه الحالة. لهذا الغرض، تحتوي وظيفة openfile على علامتي O_CLOEXEC و O_KEEPEXEC لفرض وضع "الإغلاق عند التنفيذ" أو وضع "الاحتفاظ عند التنفيذ" على التوالي. تحتوي جميع العمليات الأخرى في وحدة Unix التي تنشئ واصفات ملفات على وسيط اختياري ?cloexec:bool للإشارة إلى ما إذا كان يجب إنشاء واصف الملف في وضع "الإغلاق عند التنفيذ" (بكتابة ~cloexec:true) أو في وضع "الاحتفاظ عند التنفيذ" (بكتابة ~cloexec:false). لأسباب تاريخية، الوضع الافتراضي لإنشاء واصف الملف هو "الاحتفاظ عند التنفيذ" إذا لم يتم تقديم وسيط اختياري cloexec. هذا ليس وضعًا افتراضيًا آمنًا، لذلك يوصى بشدة بتمرير وسيطات cloexec صريحة إلى العمليات التي تنشئ واصفات ملفات.

تم تقديم الوسيطات الاختيارية cloexec والعلامة O_KEEPEXEC في OCaml 4.05. في السابق، كانت الممارسة الشائعة هي إنشاء واصفات الملفات في الوضع الافتراضي "الاحتفاظ عند التنفيذ"، ثم استدعاء set_close_on_exec على تلك الواصفات التي تم إنشاؤها حديثًا. هذا ليس آمنًا مثل إنشاء واصف الملف في وضع "الإغلاق عند التنفيذ" لأنه في البرامج متعددة الخيوط، توجد نافذة ضعف بين الوقت الذي تم فيه إنشاء واصف الملف والوقت الذي يكتمل فيه set_close_on_exec. إذا قام خيط آخر بتشغيل برنامج آخر خلال هذه النافذة، فسيتسرب الواصف، حيث لا يزال في وضع "الاحتفاظ عند التنفيذ".

فيما يتعلق بضمانات الذرية التي يوفرها ~cloexec:true أو استخدام العلامة O_CLOEXEC: على جميع المنصات، من المضمون أن خيط Caml الذي يتم تنفيذه بشكل متزامن لا يمكنه تسريب الواصف عن طريق بدء عملية جديدة. على Linux، يمتد هذا الضمان إلى خيوط C التي يتم تنفيذها بشكل متزامن. اعتبارًا من فبراير 2017، تفتقر أنظمة التشغيل الأخرى إلى استدعاءات النظام اللازمة ولا تزال تعرض نافذة ضعف يمكن أن يرى خلالها خيط C واصف الملف الذي تم إنشاؤه حديثًا في وضع "الاحتفاظ عند التنفيذ".

وظائف اتصال الشبكة عالية المستوى

: sockaddr -> in_channel * out_channel

الاتصال بخادم على العنوان المحدد. إرجاع زوج من القنوات المخزنة مؤقتًا المتصلة بالخادم. تذكر استدعاء flush على قناة الإخراج في الأوقات المناسبة لضمان التزامن الصحيح.

تشترك القناتان المرجعتان من open_connection في واصف لمقبس. لذلك، عند انتهاء الاتصال، يجب استدعاء close_out على قناة الإخراج، والتي ستغلق أيضًا المقبس الأساسي. لا تستدعِ close_in على قناة الإدخال؛ سيتم جمعها بواسطة جامع القمامة في النهاية.

: in_channel -> unit

"إغلاق" اتصال تم إنشاؤه باستخدام Unix.open_connection؛ أي، إرسال شرط نهاية الملف إلى الخادم الذي يقرأ على الجانب الآخر من الاتصال. هذا لا يغلق المقبس والقنوات المستخدمة للاتصال. انظر Unix.open_connection لكيفية إغلاقها بمجرد انتهاء الاتصال.

: (in_channel -> out_channel -> unit) -> sockaddr -> unit

إنشاء خادم على العنوان المحدد. يتم استدعاء الدالة المعطاة كحجة أولى لكل اتصال بقناتين مخزنتين مؤقتًا متصلتين بالعميل. يتم إنشاء عملية جديدة لكل اتصال. الدالة Unix.establish_server لا تعود أبدًا بشكل طبيعي.

تشترك القناتان المعطاتان للدالة في واصف لمقبس. لا تحتاج الدالة إلى إغلاق القنوات، حيث يحدث هذا تلقائيًا عند عودة الدالة. إذا كانت الدالة تفضل الإغلاق الصريح، فيجب عليها إغلاق قناة الإخراج باستخدام close_out وترك قناة الإدخال غير مغلقة، لأسباب موضحة في Unix.in_channel_of_descr.

NAME

Unix - Interface to a POSIX operating system

Module

Unix

Documentation

This module provides access to the POSIX API for Unix systems.

The functions are grouped into several modules:

  • Process management (`fork`, `exec`, `wait`, etc.)
  • File descriptor manipulation (`open`, `close`, `read`, `write`, `ioctl`, etc.)
  • Directory operations (`opendir`, `readdir`, `closedir`, etc.)
  • File and directory metadata (`stat`, `lstat`, `access`, `chmod`, etc.)
  • Signal handling (`signal`, `sigprocmask`, `sigpending`, etc.)
  • Terminal I/O (`tcgetattr`, `tcsetattr`, etc.)
  • Inter-Process Communication (IPC) (`pipe`, `mkfifo`, `semop`, `shmget`, etc.)
  • System information (`getpid`, `getpgrp`, `getuid`, `getgid`, etc.)
  • Time functions (`time`, `gettimeofday`, `sleep`, `alarm`, etc.)
  • Network socket programming (see module `Unix.Socket`)
  • Error reporting (`error_message`)

This module also defines several exception types that are raised on errors:

  • `Unix_error` (for POSIX API errors)
  • `Unix_wait_error` (for errors returned by `wait`)
  • `Exit_status` (for program termination)
  • `Signal_received` (for signals received by the process)

The POSIX API is quite large, and this module does not provide access to all of it. However, it covers the most common and important functions.

The module `Unix.Process` provides functions for process management.

The module `Unix.File` provides functions for file descriptor manipulation.

The module `Unix.Dir` provides functions for directory operations.

The module `Unix.Info` provides functions for file and directory metadata.

The module `Unix.Signal` provides functions for signal handling.

The module `Unix.Termios` provides functions for terminal I/O.

The module `Unix.Ipc` provides functions for Inter-Process Communication.

The module `Unix.System` provides functions for system information.

The module `Unix.Time` provides functions for time-related operations.

The module `Unix.Socket` provides functions for network socket programming.

The module `Unix.Error` provides functions for error reporting.

val tcgetattr : file_descr -> terminal_io

Return the status of the terminal referred to by the given file descriptor.

Raises Invalid_argument on Windows

type setattr_when =
| TCSANOW
| TCSADRAIN
| TCSAFLUSH

val tcsetattr : file_descr -> setattr_when -> terminal_io -> unit

Set the status of the terminal referred to by the given file descriptor. The second argument indicates when the status change takes place: immediately ( TCSANOW ), when all pending output has been transmitted ( TCSADRAIN ), or after flushing all input that has been received but not read ( TCSAFLUSH ). TCSADRAIN is recommended when changing the output parameters; TCSAFLUSH , when changing the input parameters.

Raises Invalid_argument on Windows

val tcsendbreak : file_descr -> int -> unit

Send a break condition on the given file descriptor. The second argument is the duration of the break, in 0.1s units; 0 means standard duration (0.25s).

Raises Invalid_argument on Windows

val tcdrain : file_descr -> unit

Waits until all output written on the given file descriptor has been transmitted.

Raises Invalid_argument on Windows

type flush_queue =
| TCIFLUSH
| TCOFLUSH
| TCIOFLUSH

val tcflush : file_descr -> flush_queue -> unit

Discard data written on the given file descriptor but not yet transmitted, or data received but not yet read, depending on the second argument: TCIFLUSH flushes data received but not read, TCOFLUSH flushes data written but not transmitted, and TCIOFLUSH flushes both.

Raises Invalid_argument on Windows

type flow_action =
| TCOOFF
| TCOON
| TCIOFF
| TCION

val tcflow : file_descr -> flow_action -> unit

Suspend or restart reception or transmission of data on the given file descriptor, depending on the second argument: TCOOFF suspends output, TCOON restarts output, TCIOFF transmits a STOP character to suspend input, and TCION transmits a START character to restart input.

Raises Invalid_argument on Windows

val setsid : unit -> int

Put the calling process in a new session and detach it from its controlling terminal.
