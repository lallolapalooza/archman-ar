NAME

udisksd — Daemon for managing storage devices

DESCRIPTION

udisksd is a daemon that provides an interface to manage storage devices. It exposes storage devices as objects and provides methods for common operations such as formatting, mounting, unmounting, and managing partitioning. It also provides information about device properties, such as model, serial number, capacity, and partition table type.

udisksd listens for device events from udev(7) and exports storage device information and functionality via the D-Bus¹ system message bus.

The D-Bus API provided by udisksd is intended to be used by higher-level applications such as desktop shells (e.g. GNOME) and disk management tools (e.g. GNOME Disks). The API is designed to be stable and easy to use, and it provides a convenient way to interact with storage devices without needing to deal with low-level details.

udisksd is also capable of managing hardware RAID arrays, software RAID arrays, and other storage technologies through plugins.

udisksd requires elevated privileges to perform certain operations, such as formatting or partitioning disks. These operations are typically exposed through polkit(8) policies.

The udisksd daemon is typically started automatically at boot time by the system's init system. It can also be started manually using the udisksd(8) command.

ACCESS CONTROL

udisksd uses polkit(8) to control access to its functionality. This allows for fine-grained control over which users or applications can perform specific actions on storage devices. For example, a user might be allowed to mount and unmount devices, but not to format or partition them. The default polkit rules allow users in the storage or wheel groups to perform most actions.

DRIVE CONFIGURATION

udisksd can manage various aspects of drive configuration, including partition tables, file systems, and swap devices. It supports common partition table types such as MBR and GPT, and can create, delete, and resize partitions. It also supports various file systems, including FAT, NTFS, ext2/3/4, and XFS. When creating file systems, udisksd uses the appropriate tools from the util-linux(8) package.

udisksd can also manage swap devices, including creating, enabling, and disabling swap partitions.

DEVICE INFORMATION

udisksd provides detailed information about storage devices, including:

  • Device model and vendor
  • Serial number
  • Capacity and free space
  • Partition table type and layout
  • File system type and label
  • Mount status and location
  • Device media status (e.g., present, empty)
  • Supported technologies (e.g., SMART, TRIM)

This information can be accessed via the D-Bus API or by using the udisksctl(1) command-line tool.

API STABILITY

The D-Bus API provided by udisksd is intended to be stable across releases. However, as with any evolving software, there may be minor changes or additions between major versions. Applications that rely heavily on the udisksd API should be prepared to handle potential changes and test thoroughly with new versions.

For applications that require long-term stability and a guaranteed stable interface, it is recommended to use lower-level APIs such as udev(7), libudev⁸, or direct access to the sysfs⁷ filesystem. Alternatively, higher-level APIs like GVolumeMonitor¹¹ can provide a more stable and desktop-environment-integrated experience.

It is generally discouraged for third-party applications to directly depend on a specific version of the udisksd library or API, as this can lead to compatibility issues when the system's udisksd is updated. Instead, applications should interact with udisksd via D-Bus or use higher-level abstractions.

The command-line interface provided by udisksctl(1) is also subject to change and should not be relied upon by applications. It is intended for interactive use by users.

Refer to the API CHANGES file in the udisks source code for details on changes between versions.

For more details on the low-level interfaces, see udev(7), polkit(8), udisksd(8), udisksctl(1), umount.udisks2(8), gnome-disks(1).

AUDIENCE

The intended audience of udisks include operating system developers working on the higher-level parts of the operating system, for example the desktop shell (such as GNOME⁵) and disk management applications (e.g. GNOME's Disks⁶ application). Software on this level typically depend on a specific (major) version of udisks and may even have support for previous versions of udisks or alternative interfaces performing the same role as udisks.

While udisks indeed provides a stable API and a clear upgrade path, it may not be an appropriate dependency for third party applications. For example, if the operating system switches to udisks version N.x and an application is still using the udisks (N-1).x API, the application will not work unless udisks (N-1).x is installed. While this situation is still workable (since both udisks N.x and udisks (N-1).x can be installed) it may not be desirable to ask the user to install the old version - in fact, the operating system vendor may not even provide a packaged version of the old version. Hence, if an application does not want to tie itself to a specific version of the operating system, it should not use udisks.

Viable alternatives to udisks are APIs that are guaranteed to be around for longer time-frames, including:

•Low-level APIs and commands such as e.g. sysfs⁷, libudev⁸, /proc/self/mountinfo⁹ and util-linux¹⁰.
•High-level APIs such as GVolumeMonitor¹¹.

In particular, for desktop applications it is a much better idea to use something like GVolumeMonitor since it will make the application show the same devices as the desktop shell (e.g. file manager, file chooser and so on) is showing.
