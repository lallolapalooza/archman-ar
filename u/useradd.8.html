unique

يسمح بإنشاء حساب باستخدام معرف مستخدم (UID) موجود بالفعل.

هذا الخيار صالح فقط بالاشتراك مع الخيار -u. بما أن معرف المستخدم يعمل كمفتاح لربط المستخدمين من ناحية، والصلاحيات، وملكية الملفات، والجوانب الأخرى التي تحدد سلوك النظام من ناحية أخرى، فإن أكثر من اسم تسجيل دخول واحد سيصل إلى حساب معرف المستخدم (UID) المحدد.

-p, --password PASSWORD

يحدد كلمة مرور أولية للحساب. يُتوقع أن تكون كلمة المرور (PASSWORD) مشفرة، كما يتم إرجاعها بواسطة crypt(3). داخل نص برمجي (shell script)، يسمح هذا الخيار بإنشاء دفعات من المستخدمين بكفاءة.

بدون هذا الخيار، سيتم قفل الحساب الجديد ولن يتم تحديد كلمة مرور، أي علامة تعجب واحدة في الحقل المقابل في /etc/shadow. هذه حالة لن يتمكن المستخدم فيها من الوصول إلى الحساب أو تحديد كلمة مرور بنفسه.

ملاحظة: تجنب هذا الخيار على سطر الأوامر لأن كلمة المرور (أو كلمة المرور المشفرة) ستكون مرئية للمستخدمين الذين يسردون العمليات.

يجب عليك التأكد من أن كلمة المرور تلتزم بسياسة كلمات المرور الخاصة بالنظام.

-r, --system

إنشاء حساب نظام.

سيتم إنشاء مستخدمي النظام بدون معلومات شيخوخة في /etc/shadow، وسيتم اختيار معرفاتهم الرقمية في النطاق SYS_UID_MIN-SYS_UID_MAX، المحدد في /etc/login.defs، بدلاً من UID_MIN-UID_MAX (ومقابلاتها من معرفات المجموعات GID لإنشاء مجموعات).

لاحظ أن useradd لن يقوم بإنشاء دليل رئيسي لمثل هذا المستخدم، بغض النظر عن الإعداد الافتراضي في /etc/login.defs (CREATE_HOME). يجب عليك تحديد الخيار -m إذا كنت تريد إنشاء دليل رئيسي لحساب نظام.

لاحظ أن هذا الخيار لن يقوم بتحديث /etc/subuid و /etc/subgid. يجب عليك تحديد الخيار -F إذا كنت تريد تحديث الملفات لإنشاء حساب نظام.

-R, --root CHROOT_DIR

تطبيق التغييرات في الدليل CHROOT_DIR واستخدام ملفات التكوين من الدليل CHROOT_DIR. المسارات المطلقة فقط هي المدعومة.

-P, --prefix PREFIX_DIR

تطبيق التغييرات على ملفات التكوين تحت نظام الملفات الجذر الموجود تحت الدليل PREFIX_DIR. هذا الخيار لا يقوم بتغيير الجذر (chroot) وهو مخصص لإعداد هدف ترجمة متقاطعة (cross-compilation). بعض القيود: لا يتم التحقق من مستخدمي / مجموعات NIS و LDAP. يستخدم مصادقة PAM ملفات المضيف. لا يوجد دعم لـ SELINUX.

-s, --shell SHELL

يحدد المسار إلى shell تسجيل دخول المستخدم. بدون هذا الخيار، سيستخدم النظام المتغير SHELL المحدد في /etc/default/useradd، أو إذا لم يتم تعيينه أيضًا، فسيظل حقل shell تسجيل الدخول في /etc/passwd فارغًا.

-u, --uid UID

القيمة الرقمية لمعرف المستخدم. يجب أن تكون هذه القيمة فريدة، إلا إذا تم استخدام الخيار -o. يجب أن تكون القيمة غير سالبة. الافتراضي هو استخدام أصغر قيمة معرف أكبر من أو تساوي UID_MIN وأكبر من كل مستخدم آخر.

انظر أيضًا الخيار -r ووصف UID_MAX.

-U, --user-group

إنشاء مجموعة بنفس اسم المستخدم، وإضافة المستخدم إلى هذه المجموعة.

يتم تعريف السلوك الافتراضي (إذا لم يتم تحديد الخيارات -g و -N و -U) بواسطة المتغير USERGROUPS_ENAB في /etc/login.defs.

-Z, --selinux-user SEUSER

يحدد مستخدم SELinux للحساب الجديد. بدون هذا الخيار، يستخدم SELinux المستخدم الافتراضي. لاحظ أن نظام shadow لا يقوم بتخزين selinux-user، بل يستخدم semanage(8) لذلك.

--selinux-range SERANGE

يحدد نطاق SELinux MLS للحساب الجديد. بدون هذا الخيار، يستخدم SELinux النطاق الافتراضي. لاحظ أن نظام shadow لا يقوم بتخزين selinux-range، بل يستخدم semanage(8) لذلك.

هذا الخيار صالح فقط إذا تم تحديد الخيار -Z (أو --selinux-user).

تغيير القيم الافتراضية

عند استدعائه مع الخيار -D فقط، سيعرض useradd القيم الافتراضية الحالية. عند استدعائه مع -D بالإضافة إلى خيارات أخرى، سيقوم useradd بتحديث القيم الافتراضية للخيارات المحددة. الخيارات الصالحة لتغيير الافتراضيات هي:

-b, --base-dir BASE_DIR

يحدد المسار البادئ للدليل الرئيسي للمستخدم الجديد. سيتم إضافة اسم المستخدم إلى نهاية BASE_DIR لتشكيل اسم الدليل الرئيسي للمستخدم الجديد، إذا لم يتم استخدام الخيار -d عند إنشاء حساب جديد.

هذا الخيار يحدد المتغير HOME في /etc/default/useradd.

-e, --expiredate EXPIRE_DATE

يحدد التاريخ الذي سيتم فيه تعطيل حسابات المستخدمين التي تم إنشاؤها حديثًا.

هذا الخيار يحدد المتغير EXPIRE في /etc/default/useradd.

-f, --inactive INACTIVE

يحدد عدد الأيام بعد انتهاء صلاحية كلمة المرور التي لا يزال بإمكان المستخدم تسجيل الدخول خلالها. بعد هذه الفترة، يتم قفل الحساب.

هذا الخيار يحدد المتغير INACTIVE في /etc/default/useradd.

-g, --gid GROUP

يحدد المجموعة الأساسية الافتراضية للمستخدمين الذين تم إنشاؤهم حديثًا، بقبول أسماء المجموعات أو معرف مجموعة رقمي. يجب أن تكون المجموعة المسماة موجودة، ويجب أن يكون لمعرف المجموعة (GID) إدخال موجود.

هذا الخيار يحدد المتغير GROUP في /etc/default/useradd.

-s, --shell SHELL

يحدد shell تسجيل الدخول الافتراضي للمستخدمين الجدد.

هذا الخيار يحدد المتغير SHELL في /etc/default/useradd.

ملاحظات

مسؤول النظام مسؤول عن وضع ملفات المستخدم الافتراضية في الدليل /etc/skel/ (أو أي دليل هيكل عظمي آخر محدد في /etc/default/useradd أو على سطر الأوامر).

محاذير

لا يجوز لك إضافة مستخدم إلى مجموعة NIS أو LDAP. يجب القيام بذلك على الخادم المقابل.

وبالمثل، إذا كان اسم المستخدم موجودًا بالفعل في قاعدة بيانات مستخدم خارجية مثل NIS أو LDAP، فسترفض useradd طلب إنشاء حساب المستخدم.

قد تحتوي أسماء المستخدمين فقط على حروف أبجدية (صغيرة وكبيرة) وأرقام وشرطات سفلية أو شرطات. يمكن أن تنتهي بعلامة الدولار. الشرطات غير مسموح بها في بداية اسم المستخدم. أسماء المستخدمين الرقمية بالكامل وأسماء المستخدمين "." أو ".." غير مسموح بها أيضًا. لا يُنصح باستخدام أسماء المستخدمين التي تبدأ بحرف "." لأن أدلتها الرئيسية ستكون مخفية في إخراج ls.

يمكن أن تكون أسماء المستخدمين قصيرة بحد أقصى 256 حرفًا.

التكوين

تغير متغيرات التكوين التالية في /etc/login.defs سلوك هذه الأداة:

CREATE_HOME (boolean)

يشير إلى ما إذا كان يجب إنشاء دليل رئيسي افتراضي للمستخدمين الجدد.

لا ينطبق هذا الإعداد على مستخدمي النظام، ويمكن تجاوزه على سطر الأوامر.

GID_MAX (number), GID_MIN (number)

نطاق معرفات المجموعات المستخدمة لإنشاء مجموعات عادية بواسطة useradd و groupadd أو newusers.

القيمة الافتراضية لـ GID_MIN (على التوالي GID_MAX) هي 1000 (على التوالي 60000).

HOME_MODE (number)

الوضع (mode) للأدلة الرئيسية الجديدة. إذا لم يتم تحديده، يتم استخدام UMASK لإنشاء الوضع.

تستخدم useradd و newusers هذا لتعيين وضع الدليل الرئيسي الذي ينشئونه.

LASTLOG_UID_MAX (number)

أعلى رقم معرف مستخدم يجب تحديث إدخالات lastlog له. نظرًا لأنه يتم عادةً تتبع معرفات المستخدمين الأعلى بواسطة خدمات هوية المستخدم والمصادقة عن بُعد، فلا داعي لإنشاء ملف lastlog ضخم غير متصل بالإنترنت لها.

عدم وجود خيار LASTLOG_UID_MAX في التكوين يعني عدم وجود حد لمعرف المستخدم لكتابة إدخالات lastlog.

MAIL_DIR (string)

دليل البريد (mail spool directory). هذا ضروري لمعالجة صندوق بريد المستخدم عند تعديل حسابه المقابل أو حذفه. إذا لم يتم تحديده، يتم استخدام افتراضي وقت الترجمة (compile-time). يحدد المعامل CREATE_MAIL_SPOOL في /etc/default/useradd ما إذا كان يجب إنشاء صندوق بريد المستخدم.

MAIL_FILE (string)

يحدد موقع ملفات صندوق بريد المستخدمين بالنسبة إلى دليلهم الرئيسي.

تستخدم المتغيرات MAIL_DIR و MAIL_FILE بواسطة useradd و usermod و userdel لإنشاء أو نقل أو حذف صندوق بريد المستخدم.

MAX_MEMBERS_PER_GROUP (number)

أقصى عدد من الأعضاء لكل إدخال مجموعة. عند الوصول إلى الحد الأقصى، يتم بدء إدخال مجموعة جديد (سطر) في /etc/group (بنفس الاسم، ونفس كلمة المرور، ونفس معرف المجموعة GID).

القيمة الافتراضية هي 0، مما يعني عدم وجود حدود لعدد الأعضاء في المجموعة.

هذه الميزة (المجموعة المقسمة) تسمح بالحد من طول الأسطر في ملف المجموعة. هذا مفيد للتأكد من أن الأسطر الخاصة بمجموعات NIS ليست أطول من 1024 حرفًا.

إذا كنت بحاجة إلى فرض هذا الحد، يمكنك استخدام 25.

ملاحظة: قد لا يتم دعم المجموعات المقسمة بواسطة جميع الأدوات (حتى في مجموعة أدوات Shadow). يجب عدم استخدام هذا المتغير ما لم تكن بحاجة إليه حقًا.

PASS_MAX_DAYS (number)

الحد الأقصى لعدد الأيام التي يمكن استخدام كلمة المرور خلالها. إذا كانت كلمة المرور أقدم من ذلك، فسيتم فرض تغيير كلمة المرور. إذا لم يتم تحديده، فسيتم افتراض -1 (مما يعطل القيد).

PASS_MIN_DAYS (number)

الحد الأدنى لعدد الأيام المسموح به بين تغييرات كلمات المرور. سيتم رفض أي محاولات لتغيير كلمة المرور قبل هذا الوقت. إذا لم يتم تحديده، فسيتم افتراض 0 (مما يعطل القيد).

PASS_WARN_AGE (number)

عدد الأيام من التحذير المعطى قبل انتهاء صلاحية كلمة المرور. صفر يعني أنه يتم تقديم التحذير فقط في يوم انتهاء الصلاحية، وقيمة -1 تعني عدم تقديم أي تحذير. إذا لم يتم تحديده، فلن يتم تقديم أي تحذير.

useradd(8)

الحزمة: shadow

التراخيص: BSD-3-Clause

NAME

useradd - add a user or update a group of users

SYNOPSIS

useradd [-options] [-G group,...] [-g group] [-u UID] LOGIN

useradd -D

DESCRIPTION

The useradd utility is a low level utility that is to be used by system administrators to add users to a system. Depending on the system's configuration, the useradd command may or may not be able to add users to the system. It is usually used in combination with other tools like userdel to remove users, usermod to modify users, groupadd to add groups, groupdel to remove groups, and groupmod to modify groups.

The primary map for user information is the user account information file, which by default is passwd(5).

The useradd command creates a new user or updates the system with defaults that will be used by the incremental user creation programs. The useradd command also supports the creation of private groups for each user when so configured.

Use the passwd command to set or change a user's password.

The command may be run in two modes: add a user or update the default values.

When the -D option is used, useradd will not create a new user. Instead, it will update the default values used by useradd when creating new users. The default values are stored in login.defs(5).

OPTIONS

The options that apply to the creation of a new user are:

-c comment
The comment field, typically the user's full name. This string is stored in the user account's GECOS field.
-d home_dir
The new user's login directory. The default is to append the login name to HOME_DIR and use that as the login directory name. The directory must exist or be created by the -m option.
-e expire_date
The date on which a user account will be expired. The date can be specified in the format MM/DD/YY (Month, Day, Year) or YYYY-MM-DD (Year-Month-Day).
-f inactive
The number of days after a password expires until the account is permanently disabled. A value of 0 disables the check. A value of -1 disables the check.
-g group
The group ID or name of the user's initial login group. If this option is not specified, the behavior depends on the `USERGROUPS_ENAB` option in login.defs(5). If `USERGROUPS_ENAB` is set to `yes`, a group with the same name as the user is created and the user is made a member of this group. Otherwise, the user is added to the default group (usually `users`).
-G group,...
A list of supplementary groups that the user will be a member of. Each group must exist. Each group name is separated by a comma, with no intervening whitespace. The default is to allocate no supplementary groups. It is possible to specify groups that do not exist, but they will not be created.
-h home_dir
Same as -d.
-k skel_dir
The skeleton directory. The contents of the skeleton directory are copied to the user's home directory when the -m option is specified. This option is only used if the -m option is given.
-m
Create the user's home directory if it does not exist. The contents of the directory specified by the -k option (or the default skeleton directory, usually /etc/skel) will be copied to the home directory. The permissions of the home directory will be taken from UMASK in login.defs(5).
-M
Do not create the user's home directory, even if the system default is to do so. This is the default behavior if the -d option is not specified.
-n
Do not assign a password to the newly created user.
-o
Allow a user to be created with a duplicate (non-unique) UID.
-p password
The encrypted password string. The default is to have no password (the account is locked).
-s shell
The name of the user's login shell. The default is to leave this field blank (which will often be interpreted as no shell by login programs).
-u UID
The numerical value of the user's ID. This value must be unique, unless the -o option is used. The value must be between UID_MIN and UID_MAX (inclusive) unless the -o option is used.

The options that apply to updating the defaults are:

-D
Update the default values for user creation. This option can be combined with any of the options described above except for -u and -g. If -D is used, useradd will update the default values in login.defs(5). The new user will not be created.

NOTES

The useradd command is intended to be used by system administrators. Normal users should use the chfn and chsh commands to change their own information.

If the system is configured to use shadow passwords, useradd will create the user's entry in the shadow password file (usually /etc/shadow) as well as in the /etc/passwd file. It will also create the user's entry in the shadow group file (usually /etc/gshadow) if the user is added to a group.

When adding a user, the system tries to determine the correct values for UID, GID, and home directory based on the system configuration files. These files are typically login.defs(5), /etc/passwd, /etc/group, /etc/shadow, and /etc/gshadow.

The values for UID_MIN, UID_MAX, GID_MIN, and GID_MAX in login.defs(5) define the range of user and group IDs that will be used for the creation of regular users and groups.

The values for SYS_UID_MIN, SYS_UID_MAX, SYS_GID_MIN, and SYS_GID_MAX in login.defs(5) define the range of user and group IDs that will be used for the creation of system users and groups.

The values for SUB_UID_MIN, SUB_UID_MAX, and SUB_UID_COUNT in login.defs(5) define the range and number of subordinate user IDs that will be assigned to a user.

The values for SUB_GID_MIN, SUB_GID_MAX, and SUB_GID_COUNT in login.defs(5) define the range and number of subordinate group IDs that will be assigned to a user.

The useradd command will attempt to create subordinate UIDs and GIDs if the corresponding files (/etc/subuid and /etc/subgid) exist and the user is not already assigned subordinate UIDs or GIDs.

CAVEATS

The useradd utility should not be used to add users to the NIS+ namespace. Use the nisadduser command instead.

CONFIGURATION

The following configuration variables in login.defs(5) can affect the behavior of useradd:

GID_MIN (number), GID_MAX (number)

Range of group IDs used for the creation of regular groups by groupadd, useradd, or newusers.

The default value for GID_MIN (resp. GID_MAX) is 1000 (resp. MAX_GID).

HOME_MODE (number)

The file mode for the user's home directory. If not specified, the mode will be determined by the value of UMASK.

MAX_GID (number)

The maximum value for a group ID.

MAX_UID (number)

The maximum value for a user ID.

PASS_MAX_DAYS (number)

The maximum number of days a password may be used. If set to 0, there is no limit.

PASS_MIN_DAYS (number)

The minimum number of days allowed between password changes. If set to 0, there is no limit.

PASS_WARN_AGE (number)

The number of days before expiration that a user is warned.

SUB_GID_MAX (number), SUB_GID_COUNT (number)

If /etc/subuid exists, the commands useradd and newusers (unless the user already have subordinate group IDs) allocate SUB_GID_COUNT unused group IDs from the range SUB_GID_MIN to SUB_GID_MAX for each new user.

The default values for SUB_GID_MIN, SUB_GID_MAX, SUB_GID_COUNT are respectively 100000, 600100000 and 65536.

SUB_UID_MIN (number), SUB_UID_MAX (number), SUB_UID_COUNT (number)

If /etc/subuid exists, the commands useradd and newusers (unless the user already have subordinate user IDs) allocate SUB_UID_COUNT unused user IDs from the range SUB_UID_MIN to SUB_UID_MAX for each new user.

The default values for SUB_UID_MIN, SUB_UID_MAX, SUB_UID_COUNT are respectively 100000, 600100000 and 65536.

SYS_GID_MAX (number), SYS_GID_MIN (number)

Range of group IDs used for the creation of system groups by useradd, groupadd, or newusers.

The default value for SYS_GID_MIN (resp. SYS_GID_MAX) is 101 (resp. GID_MIN-1).

SYS_UID_MAX (number), SYS_UID_MIN (number)

Range of user IDs used for the creation of system users by useradd or newusers.

The default value for SYS_UID_MIN (resp. SYS_UID_MAX) is 101 (resp. UID_MIN-1).

UID_MAX (number), UID_MIN (number)

Range of user IDs used for the creation of regular users by useradd or newusers.

The default value for UID_MIN (resp. UID_MAX) is 1000 (resp. 60000).

UMASK (number)

The file mode creation mask is initialized to this value. If not specified, the mask will be initialized to 022.

useradd and newusers use this mask to set the mode of the home directory they create if HOME_MODE is not set.

It is also used by pam_umask as the default umask value.

USERGROUPS_ENAB (boolean)

If set to yes, userdel will remove the user's group if it contains no more members, and useradd will create by default a group with the name of the user.

FILES

/etc/passwd

User account information.

/etc/shadow

Secure user account information.

/etc/group

Group account information.

/etc/gshadow

Secure group account information.

/etc/default/useradd

Default values for account creation.

/etc/shadow-maint/useradd-pre.d/*, /etc/shadow-maint/useradd-post.d/*

Run-part files to execute during user addition. The environment variable ACTION will be populated with useradd and SUBJECT with the username. useradd-pre.d will be executed prior to any user addition. useradd-post.d will execute after user addition. If a script exits non-zero then execution will terminate.

/etc/skel/

Directory containing default files.

/etc/subgid

Per user subordinate group IDs.

/etc/subuid

Per user subordinate user IDs.

/etc/login.defs

Shadow password suite configuration.

2

10
