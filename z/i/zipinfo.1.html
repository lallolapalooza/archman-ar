zipinfo(1)

الحزمة: unzip

التراخيص: custom

ZIPINFO(1L) ZIPINFO(1L)

NAME

zipinfo - list detailed information about a ZIP archive

SYNOPSIS

zipinfo [-12smlvhMtTz] file[.zip] [file(s) ...] [-x xfile(s) ...]

unzip -Z [-12smlvhMtTz] file[.zip] [file(s) ...] [-x xfile(s) ...]

DESCRIPTION

zipinfo lists technical information about files in a ZIP archive, most commonly found on MS-DOS systems. Such information includes file access permissions, encryption status, type of compression, version and operating system or file system of compressing program, and the like. The default behavior (with no options) is to list single-line entries for each file in the archive, with header and trailer lines providing summary information for the entire archive. The format is a cross between Unix ``ls -l'' and ``unzip -v'' output. See DETAILED DESCRIPTION below. Note that zipinfo is the same program as unzip (under Unix, a link to it); on some systems, however, zipinfo support may have been omitted when unzip was compiled.

ARGUMENTS

file[.zip]
Path of the ZIP archive(s). If the file specification is a wildcard, each matching file is processed in an order determined by the operating system (or file system). Only the filename can be a wildcard; the path itself cannot. Wildcard expressions are similar to Unix egrep(1) (regular) expressions and may contain:
*
matches a sequence of 0 or more characters
?
matches exactly 1 character
[...]
matches any single character found inside the brackets; ranges are specified by a beginning character, a hyphen, and an ending character. If an exclamation point or a caret (`!' or `^') follows the left bracket, then the range of characters within the brackets is complemented (that is, anything except the characters inside the brackets is considered a match). To specify a verbatim left bracket, the three-character sequence ``[[]'' has to be used.
(Be sure to quote any character that might otherwise be interpreted or modified by the operating system, particularly under Unix and VMS.) If no matches are found, the specification is assumed to be a literal filename; and if that also fails, the suffix .zip is appended. Note that self-extracting ZIP files are supported, as with any other ZIP archive; just specify the .exe suffix (if any) explicitly.
[file(s)]
An optional list of archive members to be processed, separated by spaces. (VMS versions compiled with VMSCLI defined must delimit files with commas instead.) Regular expressions (wildcards) may be used to match multiple members; see above. Again, be sure to quote expressions that would otherwise be expanded or modified by the operating system.
[-x xfile(s)]
An optional list of archive members to be excluded from processing.

OPTIONS

-1
list filenames only, one per line. This option excludes all others; headers, trailers and zipfile comments are never printed. It is intended for use in Unix shell scripts.
-2
list filenames only, one per line, but allow headers (-h), trailers (-t) and zipfile comments (-z), as well. This option may be useful in cases where the stored filenames are particularly long.
-s
list zipfile info in short Unix ``ls -l'' format. This is the default behavior; see below.
-m
list zipfile info in medium Unix ``ls -l'' format. Identical to the -s output, except that the compression factor, expressed as a percentage, is also listed.
-l
list zipfile info in long Unix ``ls -l'' format. As with -m except that the compressed size (in bytes) is printed instead of the compression ratio.
-v
list zipfile information in verbose, multi-page format.
-h
list header line. The archive name, actual size (in bytes) and total number of files is printed.
-M
pipe all output through an internal pager similar to the Unix more(1) command. At the end of a screenful of output, zipinfo pauses with a ``--More--'' prompt; the next screenful may be viewed by pressing the Enter (Return) key or the space bar. zipinfo can be terminated by pressing the ``q'' key and, on some systems, the Enter/Return key. Unlike Unix more(1), there is no forward-searching or editing capability. Also, zipinfo doesn't notice if long lines wrap at the edge of the screen, effectively resulting in the printing of two or more lines and the likelihood that some text will scroll off the top of the screen before being viewed. On some systems the number of available lines on the screen is not detected, in which case zipinfo assumes the height is 24 lines.
-t
list totals for files listed or for all files. The number of files listed, their uncompressed and compressed total sizes , and their overall compression factor is printed; or, if only the totals line is being printed, the values for the entire archive are given. The compressed total size does not include the 12 additional header bytes of each encrypted entry. Note that the total compressed (data) size will never match the actual zipfile size, since the latter includes all of the internal zipfile headers in addition to the compressed data.
-T
print the file dates and times in a sortable decimal format (yymmdd.hhmmss). The default date format is a more standard, human-readable version with abbreviated month names (see examples below).
-U
[UNICODE_SUPPORT only] modify or disable UTF-8 handling. When UNICODE_SUPPORT is available, the option -U forces unzip to escape all non-ASCII characters from UTF-8 coded filenames as ``#Uxxxx''. This option is mainly provided for debugging purpose when the fairly new UTF-8 support is suspected to mangle up extracted filenames.
The option -UU allows to entirely disable the recognition of UTF-8 encoded filenames. The handling of filename codings within unzip falls back to the behaviour of previous versions.
-z
include the archive comment (if any) in the listing.

DETAILED DESCRIPTION

zipinfo has a number of modes, and its behavior can be rather difficult to fathom if one isn't familiar with Unix ls(1) (or even if one is). The default behavior is to list files in the following format:

-rw-rws---  1.9 unx    2802 t- defX 11-Aug-91 13:48 perms.2660

The last three fields are the modification date and time of the file, and its name. The case of the filename is respected; thus files that come from MS-DOS PKZIP are always capitalized. If the file was zipped with a stored directory name, that is also displayed as part of the filename.

The second and third fields indicate that the file was zipped under Unix with version 1.9 of zip. Since it comes from Unix, the file permissions at the beginning of the line are printed in Unix format. The uncompressed file-size (2802 in this example) is the fourth field.

تُستخدم الحقول الإضافية لأغراض مختلفة (انظر مناقشة الخيار -v أدناه) بما في ذلك تخزين سمات ملف VMS، والتي من المفترض أن تكون الحالة هنا. لاحظ أن سمات الملف مدرجة بتنسيق VMS. بعض الاحتمالات الأخرى لنظام التشغيل المضيف (وهو في الواقع تسمية خاطئة - نظام ملفات المضيف أكثر صحة) تشمل OS/2 أو NT مع نظام الملفات عالي الأداء (HPFS)، MS-DOS، OS/2 أو NT مع نظام ملفات تخصيص الجدول (FAT)، وماكنتوش. يتم تمييزها على النحو التالي:

-rw-a--     1.0 hpf    5358 Tl i4:3  4-Dec-91 11:33 longfilename.hpfs
-r--ahs     1.1 fat    4096 b- i4:2 14-Jul-91 12:58 EA DATA. SF
--w-------  1.0 mac   17357 bx i8:2  4-May-92 04:02 unzip.macr

تشير سمات الملف في الحالتين الأوليين بتنسيق شبيه بيونكس، حيث تشير الحقول الفرعية السبعة إلى ما إذا كان الملف: (1) دليل، (2) قابل للقراءة (دائمًا صحيح)، (3) قابل للكتابة، (4) قابل للتنفيذ (تم تخمينه بناءً على الامتداد - تفترض ملفات .exe و .com و .bat و .cmd و .btm أنها كذلك)، (5) لديه بت الأرشيف الخاص به معينًا، (6) مخفي، و (7) ملف نظام. تفسير سمات ملف ماكنتوش غير موثوق به لأن بعض أرشيفات ماكنتوش لا تخزن أي سمات في الأرشيف.

أخيرًا، يشير الحقل السادس إلى طريقة الضغط و الطريقة الفرعية المحتملة المستخدمة. هناك ست طرق معروفة في الوقت الحالي: التخزين (بدون ضغط)، وتقليل، وتقلص، وتفجير، وترميز (لم يتم إصداره علنًا على الإطلاق)، والتخفيف. بالإضافة إلى ذلك، هناك أربعة مستويات من التقليل (1 حتى 4)؛ أربعة أنواع من التفجير (قاموس انزلاقي 4K أو 8K، و 2 أو 3 أشجار شانون-فانو)؛ وأربعة مستويات من التخفيف (فائق السرعة، سريع، عادي، أقصى ضغط). zipinfo يمثل هذه الطرق و طرقها الفرعية على النحو التالي: stor؛ re:1، re:2، إلخ؛ shrk؛ i4:2، i8:3، إلخ؛ tokn؛ و defS، defF، defN، و defX.

القوائم المتوسطة والطويلة متطابقة تقريبًا مع التنسيق القصير باستثناء أنها تضيف معلومات حول ضغط الملف. المتوسط يسرد التنسيق عامل ضغط الملف كنسبة مئوية تشير إلى مقدار المساحة التي تم "إزالتها":

-rw-rws---  1.5 unx    2802 t- 81% defX 11-Aug-91 13:48 perms.2660

في هذا المثال، تم ضغط الملف بأكثر من عامل خمسة؛ البيانات المضغوطة هي فقط 19% من الحجم الأصلي. الطويل يعطي التنسيق حجم الملف المضغوط بالبايت، بدلاً من ذلك:

-rw-rws---  1.5 unx    2802 t-     538 defX 11-Aug-91 13:48 perms.2660

على عكس قوائم unzip، فإن أرقام الحجم المضغوط في تنسيق القائمة هذا تشير إلى الحجم الكامل للبيانات المضغوطة، بما في ذلك 12 بايت رأس إضافي في حالة الإدخالات المشفرة.

إضافة الخيار -T يغير تاريخ ووقت الملف إلى تنسيق عشري:

-rw-rws---  1.5 unx    2802 t-     538 defX 910811.134804 perms.2660

لاحظ أنه بسبب القيود في تنسيق MS-DOS المستخدم لتخزين أوقات الملفات، يتم دائمًا تقريب حقل الثواني إلى أقرب ثانية زوجية. بالنسبة لملفات Unix، من المتوقع أن يتغير هذا في الإصدارات الرئيسية التالية من zip(1L) و unzip.

يعطي سطر الرأس اسم الأرشيف وحجمه الإجمالي وعدد الملفات الإجمالي؛ يعطي التذييل عدد الملفات المدرجة وإجمالي حجمها غير المضغوط وإجمالي حجمها المضغوط (لا يشمل أي من نفقات zip الداخلية). إذا، مع ذلك، تم توفير ملف(ملفات) واحد أو أكثر، فلن يتم إدراج سطور الرأس والتذييل. هذا السلوك مشابه أيضًا لسلوك "ls -l" في Unix؛ يمكن تجاوزه عن طريق تحديد الخيارات -h و -t بشكل صريح. في مثل هذه الحالة، يجب أيضًا تحديد تنسيق الإدراج بشكل صريح، نظرًا لأن -h أو -t (أو كلاهما) في غياب خيارات أخرى يعني أن سطر الرأس أو التذييل (أو كلاهما) فقط هو المدرج. انظر قسم أمثلة أدناه للحصول على ترجمة شبه مفهومة لهذا الهراء.

قائمة الإسهاب ذاتي التفسير إلى حد كبير. كما أنها تسرد تعليقات الملف وتعليق zipfile، إن وجد، ونوع وعدد البايتات في أي حقول إضافية مخزنة. تشمل الأنواع المعروفة حاليًا من الحقول الإضافية معلومات المصادقة من PKWARE ("AV")؛ سمات OS/2 الموسعة؛ معلومات نظام ملفات VMS، كل من إصدارات PKWARE و Info-ZIP؛ مكونات موارد ماكنتوش؛ معلومات Acorn/Archimedes SparkFS؛ وما إلى ذلك. (لاحظ أنه في حالة سمات OS/2 الموسعة - ربما الاستخدام الأكثر شيوعًا لحقول zipfile الإضافية - قد لا يتطابق حجم EAs المخزنة كما بلغت عنها zipinfo مع الرقم الذي قدمه أمر dir الخاص بـ OS/2: تقوم OS/2 دائمًا بالإبلاغ عن عدد البايتات المطلوبة بتنسيق 16 بت، بينما zipinfo تبلغ دائمًا عن التخزين 32 بت.)

مرة أخرى، تشمل أرقام الحجم المضغوط للإدخالات الفردية 12 بايت رأس إضافي للإدخالات المشفرة. على النقيض من ذلك، إجمالي حجم الأرشيف المضغوط ونسبة الضغط المتوسطة المعروضة في خط الملخص السفلي يتم حسابها بدون 12 بايت رأس إضافي للإدخالات المشفرة.

خيارات البيئة

تعديل سلوك zipinfo الافتراضي عبر الخيارات الموجودة في متغير بيئة يمكن أن يكون معقدًا بعض الشيء لشرحه، بسبب محاولات zipinfo لمعالجة الافتراضات المختلفة بطريقة بديهية، ولكنها تشبه Unix. (حاول ألا تضحك.) ومع ذلك، هناك بعض المنطق الأساسي. باختصار، هناك ثلاثة "مستويات أولوية" للخيارات: الخيارات الافتراضية؛ خيارات البيئة، التي يمكنها تجاوز الافتراضات أو إضافتها؛ والخيارات الصريحة التي يقدمها المستخدم، والتي يمكنها تجاوز أي من ما سبق أو إضافته.

يتوافق تنسيق الإدراج الافتراضي، كما لوحظ أعلاه، تقريبًا مع الأمر "zipinfo -hst" (باستثناء عندما يتم تحديد أعضاء zipfile فرديين). يمكن للمستخدم الذي يفضل تنسيق الإدراج الطويل (-l) الاستفادة من متغير بيئة zipinfo لتغيير هذا الافتراض:

Unix Bourne shell:
ZIPINFO=-l; export ZIPINFO
Unix C shell:
setenv ZIPINFO -l
OS/2 أو MS-DOS:
set ZIPINFO=-l
VMS (علامات اقتباس لـ حروف صغيرة):
define ZIPINFO_OPTS "-l"

إذا، بالإضافة إلى ذلك، كان المستخدم لا يحب سطر التذييل، يمكن استخدام مفهوم zipinfo لـ "الخيارات السلبية" لتجاوز الإدراج الافتراضي لهذا السطر. يتم تحقيق ذلك عن طريق وضع علامة ناقص قبل الخيار غير المرغوب فيه: على سبيل المثال، ``-l-t'' أو ``--tl''، في هذا المثال. الواصلة الأولى هي حرف التبديل العادي، ولكن الواصلة قبل `t' هي علامة ناقص. قد يبدو الاستخدام المزدوج للواصلات غريبًا بعض الشيء، ولكنه بديهي بشكل معقول: فقط تجاهل الواصلة الأولى واستمر من هناك. وهو أيضًا متسق مع سلوك الأمر Unix nice(1).

كما هو مقترح أعلاه، فإن أسماء المتغيرات الافتراضية هي ZIPINFO_OPTS لـ VMS (حيث سيتم الخلط بين الرمز المستخدم لتثبيت zipinfo كأمر خارجي مع متغير البيئة) و ZIPINFO لجميع أنظمة التشغيل الأخرى. لضمان التوافق مع zip(1L)، يتم قبول ZIPINFOOPT أيضًا (لا تسأل). إذا كان كل من ZIPINFO و ZIPINFOOPT معرفين، فإن ZIPINFO له الأولوية. يمكن استخدام خيار التشخيص الخاص بـ unzip (-v بدون اسم zipfile) للتحقق من قيم جميع متغيرات البيئة الأربعة المحتملة لـ unzip و zipinfo.

أمثلة

للحصول على قائمة أساسية قصيرة لمحتويات أرشيف ZIP بالكامل storage.zip، مع سطري الرأس والإجمالي، استخدم اسم الأرشيف فقط كوسيط لـ zipinfo:

zipinfo storage

لإنتاج قائمة أساسية طويلة (ليست تفصيلية)، بما في ذلك سطري الرأس والإجمالي، استخدم -l:

zipinfo -l storage

لإدراج المحتويات الكاملة للأرشيف بدون سطري الرأس والإجمالي، إما عكس الخيارين -h و -t أو تحديد المحتويات بشكل صريح:

zipinfo --h-t storage
zipinfo storage \*

(حيث تكون الشرطة المائلة مطلوبة فقط إذا كان shell سيقوم بتوسيع الحرف البدل `*' بخلاف ذلك، كما هو الحال في Unix عندما يكون التفليش ممكّنًا - كانت علامات الاقتباس المزدوجة حول النجمة ستعمل أيضًا). لإيقاف تشغيل سطر الإجمالي افتراضيًا، استخدم متغير البيئة (يُفترض C shell هنا):

setenv ZIPINFO --t
zipinfo storage

للحصول على القائمة الكاملة ذات التنسيق القصير للمثال الأول مرة أخرى، بالنظر إلى أن متغير البيئة تم تعيينه كما في المثال السابق، فمن الضروري تحديد الخيار -s بشكل صريح، نظرًا لأن الخيار -t بمفرده يعني أن سطر التذييل فقط هو الذي سيتم طباعته:

setenv ZIPINFO --t
zipinfo -t storage            [only totals line]
zipinfo -st storage           [full listing]

يتضمن الخيار -s، مثل -m و -l، رؤوسًا وتذييلات افتراضيًا، ما لم يتم تحديد خلاف ذلك. نظرًا لأن متغير البيئة لم يحدد أي تذييلات وهذا له أولوية أعلى من السلوك الافتراضي لـ -s، كان هناك حاجة لخيار -t صريح لإنتاج القائمة الكاملة. لم يتم الإشارة إلى أي شيء بشأن الرأس، ومع ذلك، لذا كان الخيار -s كافيًا. لاحظ أن كلا الخيارين -h و -t، عند استخدامهما بمفردهما
