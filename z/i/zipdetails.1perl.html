NAME

zipdetails - display the internal structure of zip files

SYNOPSIS

zipdetails [options] zipfile.zip

DESCRIPTION

This program creates a detailed report on the internal structure of zip files. For each item of metadata within a zip file the program will output

the offset into the zip file where the item is located.
a textual representation for the item.
an optional hex dump of the item.

The program assumes a prior understanding of the internal structure of Zip files. You should have a copy of the zip file definition, APPNOTE.TXT https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT, at hand to help understand the output from this program.

Default Behaviour

By default the program expects to be given a well-formed zip file. It will navigate the zip file by first parsing the zip "Central Directory" at the end of the file. If the "Central Directory" is found, it will then walk sequentally through the zip records starting at the beginning of the file. See "Advanced Analysis" for other processing options.

If the program finds any structural or portability issues with the zip file it will print a message at the point it finds the issue and/or in a summary at the end of the output report. Whilst the set of issues that can be detected it exhaustive, don't assume that this program can find all the possible issues in a zip file - there are likely edge conditions that need to be addressed.

If you have suggestions for use-cases where this could be enhanced please consider creating an enhancement request (see "SUPPORT").

Date & Time fields

Date/time fields found in zip files are displayed in local time. Use the "--utc" option to display these fields in Coordinated Universal Time (UTC).

Filenames & Comments

Filenames and comments are decoded/encoded using the default system encoding of the host running "zipdetails". When the sytem encoding cannot be determined "cp437" will be used.

The exceptions are

  • when the "Language Encoding Flag" is set in the zip file, the filename/comment fields are assumed to be encoded in UTF-8.
  • the definition for the metadata field implies UTF-8 charset encoding

See "Filename Encoding Issues" and "Filename & Comment Encoding Options" for ways to control the encoding of filename/comment fields.

OPTIONS

General Options

"-h", "--help"
Display help
"--redact"
Obscure filenames and payload data in the output. Handy for the use case where the zip files contains sensitive data that cannot be shared.
"--scan"
Pessimistically scan the zip file loking for possible zip records. Can be error-prone. For very large zip files this option is slow. Consider using the "--walk" option first. See "Advanced Analysis Options"
"--utc"
By default, date/time fields are displayed in local time. Use this option to display them in in Coordinated Universal Time (UTC).
"-v"
Enable Verbose mode. See "Verbose Output".
"--version"
Display version number of the program and exit.
"--walk"
Optimistically walk the zip file looking for possible zip records. See "Advanced Analysis Options"

Filename & Comment Encoding Options

See "Filename Encoding Issues"

"--encoding name"
Use encoding "name" when reading filenames/comments from the zip file.

When this option is not specified the default the system encoding is used.

" --no-encoding"
Disable all filename & comment encoding/decoding. Filenames/comments are processed as byte streams.

This option is not enabled by default.

"--output-encoding name"
Use encoding "name" when writing filename/comments to the display. By default the system encoding will be used.
"--language-encoding", "--no-language-encoding"
Modern zip files set a metadata entry in zip files, called the "Language encoding flag", when they write filenames/comments encoded in UTF-8.

Occasionally some applications set the "Language Encoding Flag" but write data that is not UTF-8 in the filename/comment fields of the zip file. This will usually result in garbled text being output for the filenames/comments.

To deal with this use-case, set the "--no-language-encoding" option and, if needed, set the "--encoding name" option to encoding actually used.

Default is "--language-encoding".

"--debug-encoding"
Display extra debugging info when a filename/comment encoding has changed.

Message Control Options

"--messages", "--no-messages"
Enable/disable the output of all info/warning/error messages.

Disabling messages means that no checks are carried out to check that the zip file is well-formed.

Default is enabled.

"--exit-bitmask", "--no-exit-bitmask"
Enable/disable exit status bitmask for messages. Default disabled. Bitmask values are: 1 for info, 2 for warning and 4 for error.

Default Output

By default "zipdetails" will output each metadata field from the zip file in three columns.

1.
The offset, in hex, to the start of the field relative to the beginning of the file.
2.
The name of the field.
3.
Detailed information about the contents of the field. The format depends on the type of data:
  • Numeric Values

    If the field contains an 8-bit, 16-bit, 32-bit or 64-bit numeric value, it will be displayed in both hex and decimal -- for example ""002A (42)"".

    Note that Zip files store most numeric values in little-endian encoding (there area few rare instances where big-endian is used). The value read from the zip file will have the endian encoding removed before being displayed.

    Next, is an optional description of what the numeric value means.

  • String

    If the field corresponds to a printable string, it will be output enclosed in single quotes.

  • Binary Data

    The term Binary Data is just a catch-all for all other metadata in the zip file. This data is displayed as a series of ascii-hex byte values in the same order they are stored in the zip file.

For example, assuming you have a zip file, "test,zip", with one entry

$ unzip -l  test.zip
Archive:  test.zip
Length      Date    Time    Name
---------  ---------- -----   ----
    446  2023-03-22 20:03   lorem.txt
---------                     -------
    446                     1 file

Running "zipdetails" will gives this output

$ zipdetails test.zip
0000 LOCAL HEADER #1       04034B50 (67324752)
0004 Extract Zip Spec      14 (20) '2.0'
0005 Extract OS            00 (0) 'MS-DOS'
0006 General Purpose Flag  0000 (0)
     [Bits 1-2]            0 'Normal Compression'
0008 Compression Method

الاسم

zipdetails - عرض البنية الداخلية لملفات zip

الملخص

zipdetails [خيارات] zipfile.zip

الوصف

يقوم هذا البرنامج بإنشاء تقرير مفصل عن البنية الداخلية لملفات zip. لكل عنصر من البيانات الوصفية داخل ملف zip، سيقوم البرنامج بإخراج

الموقع في ملف zip حيث يوجد العنصر.
تمثيل نصي للعنصر.
تفريغ سداسي اختياري للعنصر.

يفترض البرنامج فهمًا مسبقًا للبنية الداخلية لملفات Zip. يجب أن يكون لديك نسخة من تعريف ملف zip، APPNOTE.TXT https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT، في متناول اليد للمساعدة في فهم مخرجات هذا البرنامج.

السلوك الافتراضي

افتراضيًا، يتوقع البرنامج أن يتم تزويده بملف zip صحيح التكوين. سوف يتنقل في ملف zip عن طريق تحليل "دليل المركز" في نهاية الملف أولاً. إذا تم العثور على "دليل المركز"، فسيقوم بعد ذلك بالمرور بشكل تسلسلي عبر سجلات zip بدءًا من بداية الملف. انظر "التحليل المتقدم" لخيارات المعالجة الأخرى.

إذا وجد البرنامج أي مشكلات هيكلية أو مشكلات قابلية النقل مع ملف zip، فسيقوم بطباعة رسالة في النقطة التي يجد فيها المشكلة و/أو في ملخص في نهاية تقرير الإخراج. بينما مجموعة المشكلات التي يمكن اكتشافها ليست شاملة، لا تفترض أن هذا البرنامج يمكنه العثور على *جميع* المشكلات المحتملة في ملف zip - من المحتمل أن تكون هناك حالات طرفية تحتاج إلى معالجة.

إذا كانت لديك اقتراحات لحالات استخدام يمكن تحسينها، يرجى التفكير في إنشاء طلب تحسين (انظر "الدعم").

حقول التاريخ والوقت

يتم عرض حقول التاريخ/الوقت الموجودة في ملفات zip بالتوقيت المحلي. استخدم الخيار "--utc" لعرض هذه الحقول بالتوقيت العالمي المنسق (UTC).

أسماء الملفات والتعليقات

يتم فك ترميز/ترميز أسماء الملفات والتعليقات باستخدام ترميز النظام الافتراضي للمضيف الذي يقوم بتشغيل "zipdetails". عندما لا يمكن تحديد ترميز النظام، سيتم استخدام "cp437".

الاستثناءات هي

  • عند تعيين "علم ترميز اللغة" في ملف zip، يفترض أن أسماء الملفات/التعليقات مرمزة بـ UTF-8.
  • يشير تعريف حقل البيانات الوصفية إلى ترميز مجموعة أحرف UTF-8

انظر "مشكلات ترميز أسماء الملفات" و "خيارات ترميز أسماء الملفات والتعليقات" لمعرفة طرق التحكم في ترميز حقول أسماء الملفات/التعليقات.

الخيارات

خيارات عامة

"-h", "--help"
عرض المساعدة
"--redact"
إخفاء أسماء الملفات وبيانات الحمولة في الإخراج. مفيد لحالة الاستخدام التي تحتوي فيها ملفات zip على بيانات حساسة لا يمكن مشاركتها.
"--scan"
مسح ملف zip بشكل متشائم بحثًا عن سجلات zip محتملة. قد يكون عرضة للخطأ. بالنسبة لملفات zip الكبيرة جدًا، يكون هذا الخيار بطيئًا. ضع في اعتبارك استخدام الخيار "--walk" أولاً. انظر "خيارات التحليل المتقدم"
"--utc"
افتراضيًا، يتم عرض حقول التاريخ/الوقت بالتوقيت المحلي. استخدم هذا الخيار لعرضها بالتوقيت العالمي المنسق (UTC).
"-v"
تمكين وضع الإسهاب. انظر "الإخراج الإسهابي".
"--version"
عرض رقم إصدار البرنامج والخروج.
"--walk"
اجتياز ملف zip بتفاؤل بحثًا عن سجلات zip محتملة. انظر "خيارات التحليل المتقدم"

خيارات ترميز أسماء الملفات والتعليقات

انظر "مشكلات ترميز أسماء الملفات"

"--encoding name"
استخدم الترميز "name" عند قراءة أسماء الملفات/التعليقات من ملف zip.

عندما لا يتم تحديد هذا الخيار، يتم استخدام ترميز النظام الافتراضي.

" --no-encoding"
تعطيل جميع ترميز/فك ترميز أسماء الملفات والتعليقات. تتم معالجة أسماء الملفات/التعليقات كسلسلة بايت.

لا يتم تمكين هذا الخيار افتراضيًا.

"--output-encoding name"
استخدم الترميز "name" عند كتابة أسماء الملفات/التعليقات إلى الشاشة. افتراضيًا، سيتم استخدام ترميز النظام.
"--language-encoding", "--no-language-encoding"
تقوم ملفات zip الحديثة بتعيين إدخال بيانات وصفية في ملفات zip، يسمى "علم ترميز اللغة"، عندما تقوم بكتابة أسماء الملفات/التعليقات مرمزة بـ UTF-8.

في بعض الأحيان تقوم بعض التطبيقات بتعيين "علم ترميز اللغة" ولكنها تكتب بيانات ليست UTF-8 في حقول أسماء الملفات/التعليقات في ملف zip. سيؤدي هذا عادةً إلى ظهور نص مشوش لأسماء الملفات/التعليقات.

للتعامل مع حالة الاستخدام هذه، قم بتعيين الخيار "--no-language-encoding"، وإذا لزم الأمر، قم بتعيين الخيار "--encoding name" إلى الترميز المستخدم فعليًا.

الافتراضي هو "--language-encoding".

"--debug-encoding"
عرض معلومات تصحيح إضافية عند تغيير ترميز اسم ملف/تعليق.

خيارات التحكم في الرسائل

"--messages", "--no-messages"
تمكين/تعطيل إخراج جميع رسائل المعلومات/التحذير/الخطأ.

يعني تعطيل الرسائل أنه لا يتم إجراء أي فحوصات للتحقق من أن ملف zip صحيح التكوين.

الافتراضي ممكّن.

"--exit-bitmask", "--no-exit-bitmask"
تمكين/تعطيل قناع بت حالة الخروج للرسائل. معطل افتراضيًا. قيم قناع البت هي: 1 للمعلومات، 2 للتحذير، و 4 للخطأ.

الإخراج الافتراضي

افتراضيًا، سيقوم "zipdetails" بإخراج كل حقل بيانات وصفية من ملف zip في ثلاثة أعمدة.

1.
الموقع، بالنظام السداسي عشري، لبداية الحقل بالنسبة لبداية الملف.
2.
اسم الحقل.
3.
معلومات مفصلة حول محتويات الحقل. يعتمد التنسيق على نوع البيانات:
  • القيم الرقمية

    إذا كان الحقل يحتوي على قيمة رقمية 8 بت، 16 بت، 32 بت، أو 64 بت، فسيتم عرضها بالنظام السداسي عشري والعشري - على سبيل المثال ""002A (42)"".

    لاحظ أن ملفات Zip تخزن معظم القيم الرقمية بترتيب little-endian (هناك عدد قليل من الحالات النادرة التي يستخدم فيها big-endian). سيتم إزالة ترميز endian للقيمة المقروءة من ملف zip قبل عرضها.

    بعد ذلك، يوجد وصف اختياري لما تعنيه القيمة الرقمية.

  • سلسلة نصية

    إذا كان الحقل يتوافق مع سلسلة نصية قابلة للطباعة، فسيتم إخراجه محاطًا بعلامات اقتباس مفردة.

  • بيانات ثنائية

    مصطلح البيانات الثنائية هو مجرد مصطلح شامل لجميع البيانات الوصفية الأخرى في ملف zip. يتم عرض هذه البيانات كسلسلة من قيم البايت السداسي عشري ASCII بنفس الترتيب الذي يتم تخزينها به في ملف zip.

على سبيل المثال، بافتراض أن لديك ملف zip، "test.zip"، مع إدخال واحد

$ unzip -l  test.zip
Archive:  test.zip
Length      Date    Time    Name
---------  ---------- -----   ----
    446  2023-03-22 20:03   lorem.txt
---------                     -------
    446                     1 file

سيؤدي تشغيل "zipdetails" إلى إعطاء هذا الإخراج

$ zipdetails test.zip
0000 LOCAL HEADER #1       04034B50 (67324752)
0004 Extract Zip Spec      14 (20) '2.0'
0005 Extract OS            00 (0) 'MS-DOS'
0006 General Purpose Flag  0000 (0)
     [Bits 1-2]            0 'Normal Compression'
0008 Compression Method
="Sh">

حدود

ميزات ملف مضغوط التالية غير مدعومة من قبل هذا البرنامج:

  • الأرشيفات المضغوطة متعددة الأجزاء / المقسمة / الممتدة.

    لا يمكن لهذا البرنامج تقديم تقرير شامل عن الأجزاء المجمعة لملف مضغوط متعدد الأجزاء.

    أفضل ما يمكنك فعله هو التشغيل إما مع خيارات "--scan" أو "--walk" ضد الأجزاء الفردية. سيحتوي البعض على بيانات وصفية لملف مضغوط سيتم اكتشافها وسيحتوي البعض الآخر فقط على بيانات حمولة مضغوطة.

  • دليل مركزي مشفر

    عند تمكين pkzip التشفير القوي في ملف مضغوط، لا يزال بإمكان هذا البرنامج تحليل معظم البيانات الوصفية في الملف المضغوط. الاستثناء هو عندما يتم تشفير "الدليل المركزي" لملف مضغوط أيضًا. لا يمكن لهذا البرنامج تحليل أي بيانات وصفية من "الدليل المركزي" مشفر.

  • ملفات مضغوطة تالفة

    عندما يصادف "zipdetails" ملفًا مضغوطًا تالفًا، سيقوم بأحد الإجراءات التالية أو أكثر:

  • عرض تفاصيل التلف والمتابعة
  • عرض تفاصيل التلف وإنهاء البرنامج
  • إنهاء البرنامج برسالة عامة

يعتمد ما سيتم إخراجه من بين الخيارات أعلاه على شدة التلف.

إخراج JSON/YML

إخراج بعض البيانات الوصفية لملف مضغوط كمستند JSON أو YML.

ملفات مضغوطة تالفة

على الرغم من أن اكتشاف وإبلاغ معظم حالات الاستخدام الشائعة للتلف موجود في "zipdetails"، فمن المحتمل أن تكون هناك حالات حافة أخرى تحتاج إلى دعم.

إذا كان لديك ملف مضغوط تالف لا تتم معالجته بشكل صحيح، فيرجى الإبلاغ عنه (انظر "الدعم").

انظر أيضًا
