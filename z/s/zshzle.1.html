يقوم الأمر المضمن zle بتنفيذ عدد من الإجراءات المختلفة المتعلقة بـ ZLE.

بدون خيارات ولا وسيطات، سيتم تعيين حالة الإرجاع فقط. إنها صفر إذا كان ZLE نشطًا حاليًا وكان يمكن استدعاء الأدوات باستخدام هذا الأمر المضمن وغير صفري بخلاف ذلك. لاحظ أنه حتى لو تم إرجاع حالة غير صفرية، قد يظل ZLE نشطًا كجزء من نظام الإكمال؛ هذا لا يسمح باستدعاءات مباشرة لأدوات ZLE.

بخلاف ذلك، تعتمد العملية التي يقوم بها على خياراته:

-l [ -L | -a ] [ string ]
سرد جميع الأدوات المعرفة من قبل المستخدم الموجودة. إذا تم استخدام الخيار -L، فقم بالسرد في شكل أوامر zle لإنشاء الأدوات.

عند دمجه مع الخيار -a، يتم سرد جميع أسماء الأدوات، بما في ذلك المضمنة. في هذه الحالة يتم تجاهل الخيار -L.

إذا تم توفير سلسلة واحدة على الأقل string، وتم توفير -a أو لم يتم استخدام -L، فلن يتم طباعة أي شيء. ستكون حالة الإرجاع صفرًا إذا كانت جميع السلاسل string هي أسماء لأدوات موجودة وغير صفرية إذا كانت سلسلة واحدة على الأقل string ليست اسمًا لأداة معرفة. إذا تم توفير -a أيضًا، يتم استخدام جميع أسماء الأدوات للمقارنة بما في ذلك الأدوات المضمنة، وإلا فسيتم استخدام الأدوات المعرفة من قبل المستخدم فقط.

إذا تم توفير سلسلة واحدة على الأقل string وتم استخدام الخيار -L، يتم سرد الأدوات المعرفة من قبل المستخدم التي تطابق أي string في شكل أوامر zle لإنشاء الأدوات.

-D widget ...
حذف الأدوات المسماة widget.
-A old-widget new-widget
اجعل اسم new-widget اسمًا مستعارًا لـ old-widget، بحيث تشير كلا الاسمين إلى نفس الأداة. الاسماء لها نفس المكانة؛ إذا تم حذف أحدهما، يبقى الآخر. إذا كانت هناك أداة بالفعل بالاسم new-widget، فسيتم حذفها.
-N widget [ function ]
إنشاء أداة معرفة من قبل المستخدم. إذا كانت هناك أداة بالفعل بالاسم المحدد، فسيتم استبدالها. عند استدعاء الأداة الجديدة من داخل المحرر، سيتم استدعاء الدالة shell function المحددة. إذا لم يتم تحديد اسم الدالة، فسيتم افتراضيًا إلى نفس اسم الأداة. لمزيد من المعلومات، انظر القسم `Widgets' أدناه.
-f flag [ flag... ]
تعيين علامات مختلفة على الأداة قيد التشغيل. القيم الممكنة لـ flag هي:

yank للإشارة إلى أن الأداة قد قامت بسحب نص إلى المخزن المؤقت. إذا كانت الأداة تغلف أداة داخلية موجودة، فلا يلزم اتخاذ أي إجراءات إضافية، ولكن إذا قامت بإدراج النص يدويًا، فيجب عليها أيضًا التأكد من تعيين YANK_START و YANK_END بشكل صحيح. yankbefore تقوم بنفس الشيء ولكنها تستخدم عندما يظهر النص المسحوب بعد المؤشر.

kill للإشارة إلى أن النص قد تم قتله في مخزن النسخ. عند استدعاء أداة قتل بشكل متكرر، يتم إلحاق النص بمخزن النسخ بدلاً من استبداله، ولكن عند تغليف هذه الأدوات، يلزم استدعاء `zle -f kill' للاحتفاظ بهذا التأثير.

vichange للإشارة إلى أن الأداة تمثل تغييرًا في vi يمكن تكراره كوحدة واحدة باستخدام `vi-repeat-change'. يجب تعيين العلامة في وقت مبكر من الدالة قبل فحص قيمة NUMERIC أو استدعاء أدوات أخرى. هذا ليس له تأثير على أداة تم استدعاؤها من وضع الإدراج. إذا كان وضع الإدراج نشطًا عند انتهاء الأداة، فإن التغيير يمتد حتى العودة إلى وضع الأوامر.

-C widget completion-widget function
إنشاء أداة إكمال معرفة من قبل المستخدم تسمى widget. ستتصرف أداة الإكمال مثل أداة الإكمال المضمنة التي اسمها completion-widget. لتوليد الإكمالات، سيتم استدعاء الدالة shell function. لمزيد من المعلومات، انظر zshcompwid(1).
-R [ -c ] [ display-string ] [ string ... ]
إعادة عرض سطر الأوامر. إذا تم توفير display-string ولم تكن فارغة، فسيتم عرضها في سطر الحالة (أسفل السطر الذي يتم تحريره مباشرة).

إذا تم توفير السلاسل الاختيارية strings، فسيتم سردها أسفل المطالبة بنفس الطريقة التي يتم بها طباعة قوائم الإكمال. إذا لم يتم توفير سلاسل strings ولكن تم استخدام الخيار -c، فسيتم مسح مثل هذه القائمة.

لاحظ أنه مباشرة بعد العودة من تشغيل الأدوات، سيتم إعادة عرض سطر الأوامر وسيتم مسح السلاسل المعروضة. لذلك، هذا الخيار مفيد فقط للأدوات التي لا تنتهي فور استخدامه.

يمكن استدعاء هذا الأمر بأمان خارج الأدوات المعرفة من قبل المستخدم؛ إذا كان ZLE نشطًا، فسيتم تحديث العرض، بينما إذا كان ZLE غير نشط، فلن يكون للأمر أي تأثير. في هذه الحالة، لن تكون هناك عادةً وسيطات أخرى.

الحالة صفر إذا كان ZLE نشطًا، وإلا واحد.

-M string
كما هو الحال مع الخيار -R، سيتم عرض string أسفل سطر الأوامر؛ على عكس الخيار -R، لن يتم وضع السلسلة في سطر الحالة ولكن سيتم طباعتها بشكل طبيعي أسفل المطالبة. هذا يعني أن string سيتم عرضها لاحقًا بعد عودة الأداة (حتى يتم استبدالها بأوامر لاحقة).
-U string
هذا يقوم بدفع الأحرف في string إلى مكدس الإدخال لـ ZLE. بعد انتهاء الأداة التي يتم تنفيذها حاليًا، سيتصرف ZLE كما لو أن الأحرف في string قد تم كتابتها بواسطة المستخدم.

نظرًا لأن ZLE يستخدم مكدسًا، إذا تم استخدام هذا الخيار بشكل متكرر، فستتم معالجة آخر سلسلة تم دفعها إلى المكدس أولاً. ومع ذلك، سيتم معالجة الأحرف في كل string بالترتيب الذي تظهر به في السلسلة.

-K keymap
يحدد خريطة المفاتيح المسماة keymap. سيتم عرض رسالة خطأ إذا لم تكن هناك خريطة مفاتيح كهذه.

يؤثر اختيار خريطة المفاتيح هذه على تفسير ضغطات المفاتيح اللاحقة ضمن هذا الاستدعاء لـ ZLE. سيبدأ أي استدعاء لاحق (على سبيل المثال، سطر الأوامر التالي) كالمعتاد مع اختيار خريطة المفاتيح `main'.

-F [ -L | -w ] [ fd [ handler ] ]
متاح فقط إذا كان نظامك يدعم أحد استدعاءات النظام `poll` أو `select`؛ معظم الأنظمة الحديثة تفعل ذلك.

يقوم بتثبيت handler (اسم دالة shell) للتعامل مع الإدخال من واصف الملف fd. تثبيت معالج لـ fd يتم التعامل معه بالفعل يؤدي إلى استبدال المعالج الحالي. يمكن تثبيت أي عدد من المعالجات لأي عدد من واصفات الملفات القابلة للقراءة. لاحظ أن zle لا يحاول التحقق مما إذا كان fd هذا قابل للقراءة فعليًا عند تثبيت المعالج. يجب على المستخدم اتخاذ ترتيباته الخاصة للتعامل مع واصف الملف عندما لا يكون ZLE نشطًا.

عندما يحاول ZLE قراءة البيانات، سيقوم بفحص كل من الطرفية وقائمة fds المعالجة. إذا أصبحت البيانات متاحة على fd معالج، فإن ZLE يستدعي handler مع fd الذي أصبح جاهزًا للقراءة كحجة أولى. في الظروف العادية، هذه هي الحجة الوحيدة، ولكن إذا تم اكتشاف خطأ، فإن حجة ثانية توفر التفاصيل: `hup' للانقطاع، `nval' لوصف مغلق أو غير صالح بخلاف ذلك، أو `err' لأي شرط آخر. الأنظمة التي تدعم استدعاء النظام `select` فقط تستخدم دائمًا `err'.

إذا تم استخدام الخيار -w أيضًا، فإن handler يكون بدلاً من ذلك أداة محرر أسطر، وعادةً ما تكون دالة shell تم تحويلها إلى أداة باستخدام `zle -N'. في هذه الحالة، يمكن لـ handler استخدام جميع مرافق ZLE لتحديث سطر التحرير الحالي. لاحظ، مع ذلك، أنه نظرًا لأن التعامل مع fd يحدث على مستوى منخفض، فلن تظهر التغييرات في العرض تلقائيًا؛ يجب على الأداة استدعاء `zle -R' لفرض إعادة العرض. في وقت كتابة هذا، تدعم معالجات الأدوات حجة واحدة فقط وبالتالي لا يتم تمرير سلسلة لحالة الخطأ أبدًا، لذا يجب أن تكون الأدوات مستعدة لاختبار الواصف بنفسها.

إذا أنتج أي نوع من المعالجات إخراجًا إلى الطرفية، فيجب عليه استدعاء `zle -I' قبل القيام بذلك (انظر أدناه). يجب ألا تحاول المعالجات القراءة من الطرفية.

إذا لم يتم توفير handler، ولكن تم توفير fd، يتم إزالة أي معالج لهذا fd. إذا لم يكن هناك، يتم طباعة رسالة خطأ وإرجاع الحالة 1.

إذا لم يتم توفير وسيطات، أو تم توفير الخيار -L، يتم طباعة قائمة بالمعالجات في شكل يمكن تخزينه للتنفيذ لاحقًا.

يمكن (وليس handler) اختياريًا توفير fd مع الخيار -L؛ في هذه الحالة، ستسرد الدالة المعالج إذا كان موجودًا، وإلا ستعود بصمت بالحالة 1.

لاحظ أنه يجب استخدام هذه الميزة بحذر. قد يتسبب النشاط على أحد fds التي لم يتم التعامل معها بشكل صحيح في جعل الطرفية غير قابلة للاستخدام. قد يتسبب إزالة معالج fd من داخل مصيدة إشارة في سلوك غير متوقع.

إليك مثال بسيط لاستخدام هذه الميزة. يتم إنشاء اتصال بمنفذ TCP بعيد باستخدام الأمر ztcp؛ انظر وصف الوحدة zsh/net/tcp في zshmodules(1). ثم يتم تثبيت معالج يقوم ببساطة بطباعة أي بيانات تصل عبر هذا الاتصال. لاحظ أن `select` سيشير إلى أن واصف الملف يحتاج إلى معالجة إذا أغلق الجانب البعيد الاتصال؛ نتعامل مع ذلك عن طريق الاختبار لقراءة فاشلة.

if ztcp pwspc 2811; then
  tcpfd=$REPLY
  handler() {
    zle -I
    local line
    if ! read -r line <&$1; then
      # select marks this fd if we reach EOF,
      # so handle this specially.
      print "[Read on fd $1 f
ailed, removing.]" >&2 zle -F $1 return 1 fi print -r - $line } zle -F $tcpfd handler fi
-I
على نحو غير عادي، يكون هذا الخيار مفيدًا خارج دوال الأداة العادية، على الرغم من أنه يمكن استخدامه داخليًا إذا كان الإخراج العادي إلى الطرفية مطلوبًا. إنه يبطل عرض zle الحالي استعدادًا للإخراج؛ عادةً ما يكون هذا من دالة فخ. ليس له تأثير إذا لم يكن zle نشطًا. عند خروج فخ، يتحقق الصدفة مما إذا كانت الشاشة تحتاج إلى استعادة، وبالتالي فإن ما يلي سيطبع الإخراج بطريقة لا تزعج السطر الذي يتم تحريره:
TRAPUSR1() {
  # Invalidate zle display
  [[ -o zle ]] && zle -I
  # Show output
  print Hello
}

بشكل عام، قد تحتاج دالة الفخ إلى اختبار ما إذا كان zle نشطًا قبل استخدام هذه الطريقة (كما هو موضح في المثال)، نظرًا لأن وحدة zsh/zle قد لا يتم تحميلها حتى؛ إذا لم تكن كذلك، يمكن تخطي الأمر.

من الممكن استدعاء `zle -I' عدة مرات قبل إعادة التحكم إلى المحرر؛ سيتم إلغاء صلاحية الشاشة مرة واحدة فقط في المرة الأولى لتقليل الاضطراب.

لاحظ أنه توجد عادةً طرق أفضل لمعالجة الشاشة من داخل أدوات zle؛ انظر، على سبيل المثال، `zle -R' أعلاه.

الرمز المرتجع هو صفر إذا تم إلغاء صلاحية zle، حتى لو كان ذلك قد تم بواسطة استدعاء سابق لـ `zle -I' أو بواسطة إشعار نظام. لاختبار ما إذا كان يمكن استدعاء أداة zle في هذه النقطة، قم بتنفيذ zle بدون حجج وافحص الرمز المرتجع.

-T
يُستخدم هذا لإضافة أو سرد أو إزالة التحويلات الداخلية على المعالجة التي يقوم بها محرر الأسطر. يُستخدم عادةً فقط لتصحيح الأخطاء أو الاختبار وبالتالي فهو غير مهم للمستخدم العام.

`zle -T transformation func' يحدد أن التحويل المعطى (انظر أدناه) يتم تنفيذه بواسطة دالة الصدفة func.

`zle -Tr transformation' يزيل التحويل المعطى إذا كان موجودًا (ليس خطأ إذا لم يكن هناك).

يمكن استخدام `zle -TL' لسرد جميع التحويلات قيد التشغيل حاليًا.

حاليًا، التحويل الوحيد هو tc. يُستخدم هذا بدلاً من إخراج رموز termcap إلى الطرفية. عند تشغيل التحويل، يتم تمرير رمز termcap الذي سيتم إخراجه إلى دالة الصدفة كوسيط أول لها؛ إذا كان المطلوب من العملية وسيط رقمي، فسيتم تمريره كوسيط ثانٍ. يجب أن تعيّن الدالة المتغير REPLY في الصدفة إلى رمز termcap المحول. عادةً ما يُستخدم هذا لإنتاج نسخة منسقة ببساطة من الرمز والوسيط الاختياري لأغراض تصحيح الأخطاء أو الاختبار. لاحظ أن هذا التحويل لا ينطبق على الأحرف الأخرى غير القابلة للطباعة مثل carriage returns وnewlines.

widget [ -n num ] [ -f flag ] [ -Nw ] [ -K keymap ] args ...
استدعاء الأداة المحددة. لا يمكن القيام بذلك إلا عندما يكون ZLE نشطًا؛ عادةً ما يكون هذا ضمن أداة محددة بواسطة المستخدم.

باستخدام الخيارات -n و -N، سيتم حفظ الوسيط الرقمي الحالي ثم استعادته بعد استدعاء الأداة؛ `-n num' يعيّن الوسيط الرقمي مؤقتًا إلى num، بينما `-N' يعيّنه إلى الافتراضي، أي كما لو لم يكن هناك.

باستخدام الخيار -K، سيتم استخدام keymap كخريطة مفاتيح حالية أثناء تنفيذ الأداة. سيتم استعادة خريطة المفاتيح السابقة عند خروج الأداة.

عادةً، لا يؤدي استدعاء أداة بهذه الطريقة إلى تعيين المعلمة الخاصة WIDGET والمعلمات ذات الصلة، بحيث تبدو البيئة كما لو كانت الأداة العليا التي استدعاها المستخدم لا تزال نشطة. باستخدام الخيار -w، يتم تعيين WIDGET والمعلمات ذات الصلة لتعكس الأداة التي يتم تنفيذها بواسطة استدعاء zle.

عادةً، عندما تعود الأداة، ستشير المعلمة الخاصة LASTWIDGET إليها. يمكن منع ذلك عن طريق تمرير الخيار -f nolast.

سيتم تمرير أي حجج إضافية إلى الأداة؛ لاحظ أنه نظرًا لإجراء معالجة الحجج القياسية، يجب أن تسبق أي قائمة حجج عامة --. إذا كانت دالة صدفة، يتم تمريرها كمعلمات موضعية؛ بالنسبة للأدوات المضمنة، يعتمد الأمر على الأداة المعنية بما تفعله بها. حاليًا، يتم التعامل مع الحجج فقط بواسطة أوامر البحث التزايدي، و history-search-forward و -backward والدوال المقابلة التي تبدأ بـ vi-، وبواسطة universal-argument. لا يتم الإبلاغ عن خطأ إذا لم تستخدم الأمر الحجج، أو استخدمت بعضها فقط.

يعكس الرمز المرتجع نجاح أو فشل العملية التي قامت بها الأداة، أو إذا كانت أداة محددة بواسطة المستخدم، الرمز المرتجع لدالة الصدفة.

يؤدي الرمز المرتجع غير الصفري إلى جعل الصدفة تصدر صوت تنبيه عند خروج الأداة، ما لم يتم إلغاء تعيين الخيار BEEP أو تم استدعاء الأداة عبر الأمر zle. وبالتالي، إذا كانت أداة محددة بواسطة المستخدم تتطلب تنبيهًا فوريًا، فيجب عليها استدعاء الأداة beep مباشرة.

أدوات ZLE

تتم جميع الإجراءات في المحرر بواسطة `الأدوات'. وظيفة الأداة ببساطة هي تنفيذ إجراء صغير. أوامر ZLE التي يتم ربط تسلسلات المفاتيح بها في خرائط المفاتيح هي في الواقع أدوات. يمكن أن تكون الأدوات محددة بواسطة المستخدم أو مدمجة.

الأدوات القياسية المدمجة في ZLE مدرجة في القسم `الأدوات القياسية' أدناه. يمكن تعريف أدوات أخرى مدمجة بواسطة وحدات أخرى (انظر zshmodules(1)). لكل أداة مدمجة اسمان: اسمها الرسمي القياسي، ونفس الاسم مسبوقًا بـ `.'. الاسم `.' خاص: لا يمكن إعادة ربطه بأداة مختلفة. هذا يجعل الأداة متاحة حتى عندما يتم إعادة تعريف اسمها المعتاد.

يتم تعريف الأدوات المحددة بواسطة المستخدم باستخدام `zle -N'، ويتم تنفيذها كدوال صدفة. عند تنفيذ الأداة، يتم تنفيذ دالة الصدفة المقابلة، ويمكنها أداء إجراءات التحرير (أو غيرها). يوصى بأن أسماء الأدوات المحددة بواسطة المستخدم لا تبدأ بـ `.'.

الأدوات المحددة بواسطة المستخدم

الأدوات المحددة بواسطة المستخدم، كونها منفذة كدوال صدفة، يمكنها تنفيذ أي أمر صدفة عادي. يمكنها أيضًا تشغيل أدوات أخرى (سواء كانت مدمجة أو محددة بواسطة المستخدم) باستخدام الأمر المضمن zle. يتم إعادة توجيه الإدخال القياسي للدالة من /dev/null لمنع الأوامر الخارجية من إعاقة ZLE عن قصد عن طريق القراءة من الطرفية، ولكن يمكن استخدام read -k أو read -q لقراءة الأحرف. أخيرًا، يمكنها فحص وتحرير مخزن ZLE الذي يتم تحريره عن طريق قراءة وتعيين المعلمات الخاصة الموضحة أدناه.

هذه المعلمات الخاصة متاحة دائمًا في دوال الأدوات، ولكنها ليست خاصة بأي شكل من الأشكال خارج ZLE. إذا كان لديها قيمة عادية خارج ZLE، فإن تلك القيمة غير متاحة مؤقتًا، ولكنها ستعود عند خروج دالة الأداة. هذه المعلمات الخاصة في الواقع لها نطاق محلي، مثل المعلمات التي تم إنشاؤها في دالة باستخدام local.

داخل أدوات الإكمال والفخاخ التي تم استدعاؤها أثناء نشاط ZLE، تكون هذه المعلمات متاحة للقراءة فقط.

لاحظ أن المعلمات تظهر محليًا لأي أداة ZLE تظهر فيها. لذلك، إذا كان المطلوب هو تجاوزها، فيجب القيام بذلك داخل دالة متداخلة:

widget-function() {
  # $WIDGET here refers to the special variable
  # that is local inside widget-function
  () {
     # This anonymous nested function allows WIDGET
     # to be used as a local variable.  The -h
     # removes the special status of the variable.
     local -h WIDGET
  }
}

vi-search (unbound) (/ ?) (unbound)
Search forward or backward for a string. The string may begin with `^' to anchor the search to the beginning of the line.

A restricted set of editing functions is available in the mini-buffer. An interrupt signal, as defined by the stty setting, will stop the search. The functions available in the mini-buffer are: accept-line, backward-delete-char, vi-backward-delete-char, backward-kill-word, vi-backward-kill-word, clear-screen, redisplay, quoted-insert and vi-quoted-insert.

vi-cmd-mode is treated the same as accept-line, and magic-space is treated as a space. Any other character that is not bound to self-insert or self-insert-unmeta will beep and be ignored. If the function is called from vi command mode, the bindings of the current insert mode will be used.

If called from a function by the zle command with arguments, the first argument is taken as the string for which to search, rather than the first word in the buffer.

insert-last-word (ESC-_ ESC-.) (unbound) (unbound)
Insert the last word from the previous history event at the cursor position. If a positive numeric argument is given, insert that word from the end of the previous history event. If the argument is zero or negative insert that word from the left (zero inserts the previous command word). Repeating this command replaces the word just inserted with the last word from the history event prior to the one just used; numeric arguments can be used in the same way to pick a word from that event.

When called from a shell function invoked from a user-defined widget, the command can take one to three arguments. The first argument specifies a history offset which applies to successive calls to this widget: if it is -1, the default behaviour is used, while if it is 1, successive calls will move forwards through the history. The value 0 can be used to indicate that the history line examined by the previous execution of the command will be reexamined. Note that negative numbers should be preceded by a `--' argument to avoid confusing them with options.

If two arguments are given, the second specifies the word on the command line in normal array index notation (as a more natural alternative to the numeric argument). Hence 1 is the first word, and -1 (the default) is the last word.

If a third argument is given, its value is ignored, but it is used to signify that the history offset is relative to the current history line, rather than the one remembered after the previous invocations of insert-last-word.

For example, the default behaviour of the command corresponds to

zle insert-last-word -- -1 -1

while the command

zle insert-last-word -- -1 1 -

always copies the first word of the line in the history immediately before the line being edited. This has the side effect that later invocations of the widget will be relative to that line.

CHARACTER HIGHLIGHTING

The line editor has the ability to highlight characters or regions of the line that have a particular significance. This is controlled by the array parameter zle_highlight, if it has been set by the user.

If the parameter contains the single entry none all highlighting is turned off. Note the parameter is still expected to be an array.

Otherwise each entry of the array should consist of a word indicating a context for highlighting, then a colon, then a comma-separated list of the types of highlighting to apply in that context.

The contexts available for highlighting are the following:

default
Any text within the command line not affected by any other highlighting. Text outside the editable area of the command line is not affected.
isearch
When one of the incremental history search widgets is active, the area of the command line matched by the search string or pattern.
region
The currently selected text. In emacs terminology, this is referred to as the region and is bounded by the cursor (point) and the mark. The region is only highlighted if it is active, which is the case after the mark is modified with set-mark-command or exchange-point-and-mark. Note that whether or not the region is active has no effect on its use within emacs style widgets, it simply determines whether it is highlighted. In vi mode, the region corresponds to selected text in visual mode.
special
Individual characters that have no direct printable representation but are shown in a special manner by the line editor. These characters are described below.
suffix
This context is used in completion for characters that are marked as suffixes that will be removed if the completion ends at that point, the most obvious example being a slash (/) after a directory name. Note that suffix removal is configurable; the circumstances under which the suffix will be removed may differ for different completions.
paste
Following a command to paste text, the characters that were inserted.

When region_highlight is set, the contexts that describe a region -- isearch, region, suffix, and paste -- are applied first, then region_highlight is applied, then the remaining zle_highlight contexts are applied. If a particular character is affected by multiple specifications, the last specification wins.

zle_highlight may contain additional fields for controlling how terminal sequences to change colours are output. Each of the following is followed by a colon and a string in the same form as for key bindings. This will not be necessary for the vast majority of terminals as the defaults shown in parentheses are widely used.

fg_start_code (\e[3)
The start of the escape sequence for the foreground colour. This is followed by one to three ASCII digits representing the colour. Only used for palette colors, i.e. not 24-bit colors specified via a color triplet.
fg_default_code (9)
The number to use instead of the colour to reset the default foreground colour.
fg_end_code (m)
The end of the escape sequence for the foreground colour.
bg_start_code (\e[4)
The start of the escape sequence for the background colour. See fg_start_code above.
bg_default_code (9)
The number to use instead of the colour to reset the default background colour.
bg_end_code (m)
The end of the escape sequence for the background colour.

The available types of highlighting are the following. Note that not all types of highlighting are available on all terminals:

none
No highlighting is applied to the given context. It is not useful for this to appear with other types of highlighting; it is used to override a default.
fg=colour
The foreground colour should be set to colour, a decimal integer, the name of one of the eight most widely-supported colours or as a `#' followed by an RGB triplet in hexadecimal format.

Not all terminals support this and, of those that do, not all provide facilities to test the support, hence the user should decide based on the terminal type. Most terminals support the colours black, red, green, yellow, blue, magenta, cyan and white, which can be set by name. In addition. default may be used to set the terminal's default foreground colour. Abbreviations are allowed; b or bl selects black. Some terminals may generate additional colours if the bold attribute is also present.

On recent terminals and on systems with an up-to-date terminal database the number of colours supported may be tested by the command `echotc Co'; if this succeeds, it indicates a limit on the number of colours which will be enforced by the line editor. The number of colours is in any case limited to 256 (i.e. the range 0 to 255).

Some modern terminal emulators have support for 24-bit true colour (16 million colours). In this case, the hex triplet format can be used. This consists of a `#' followed by either a three or six digit hexadecimal number describing the red, green and blue components of the colour. Hex triplets can also be used with 88 and 256 colour terminals via the zsh/nearcolor module (see zshmodules(1)).

Colour is also known as color.

bg=colour
The background colour should be set to colour. This works similarly to the foreground colour, except the background is not usually affected by the bold attribute.
bold
The characters in the given context are shown in a bold font. Not all terminals distinguish bold fonts.
standout
The characters in the given context are shown in the terminal's standout mode. The actual effect is specific to the terminal; on many terminals it is inverse video. On some such terminals, where the cursor does not blink it appears with standout mode negated, making it less than clear where the cursor actually is. On such terminals one of the other effects may be preferable for highlighting the region and matched search string.
underline
The characters in the given context are shown underlined. Some terminals show the foreground in a different colour instead; in this case whitespace will not be highlighted.
