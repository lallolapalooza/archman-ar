[expr1] ; [expr2] ; [expr3] )) do list done
يتم تقييم التعبير الحسابي expr1 أولاً (انظر القسم `تقييم الحساب'). يتم تقييم التعبير الحسابي expr2 بشكل متكرر حتى يتم تقييمه إلى صفر وعندما يكون غير صفري، يتم تنفيذ list وتقييم التعبير الحسابي expr3. إذا تم حذف أي تعبير، فإنه يتصرف كما لو تم تقييمه إلى 1.
while list do list done
قم بتنفيذ do list طالما أن while list يعيد حالة خروج صفرية.
until list do list done
قم بتنفيذ do list طالما أن until list يعيد حالة خروج غير صفرية.
repeat word do list done
word يتم توسيعه ومعاملته كتعبير حسابي، والذي يجب أن يقيم إلى رقم n. ثم يتم تنفيذ list n مرات.

تم تعطيل صيغة repeat افتراضيًا عند بدء تشغيل الصدفة في وضع يحاكي صدفة أخرى. يمكن تمكينها باستخدام الأمر `enable -r repeat'

case word in [ [(] pattern [ | pattern ] ... ) list (;;|;&|;|) ] ... esac
قم بتنفيذ list المرتبط بـ pattern الأول الذي يطابق word، إن وجد. شكل الأنماط هو نفس الشكل المستخدم لتوليد أسماء الملفات. انظر القسم `توليد أسماء الملفات'.

لاحظ أيضًا أنه ما لم يكن الخيار SH_GLOB مضبوطًا، فإن النمط بالكامل مع البدائل يتم التعامل معه بواسطة الصدفة كمعادل لمجموعة من الأنماط داخل أقواس، على الرغم من أنه قد تظهر مسافات بيضاء حول الأقواس والشريط العمودي وسيتم تجريدها من النمط في تلك النقاط. قد تظهر مسافات بيضاء في أماكن أخرى في النمط؛ لا يتم تجريدها. إذا تم ضبط الخيار SH_GLOB، بحيث يمكن معاملة القوس الفاتح بشكل لا لبس فيه كجزء من صيغة case، يتم تحليل التعبير إلى كلمات منفصلة ويتم التعامل معها كبدائل صارمة (كما في الصدفات الأخرى).

إذا تم إنهاء list الذي يتم تنفيذه بـ ;& بدلاً من ;;، فسيتم تنفيذ القائمة التالية أيضًا. يتم تطبيق قاعدة المنهي للقائمة التالية ;;، ;& أو ;| ما لم يتم الوصول إلى esac.

إذا تم إنهاء list الذي يتم تنفيذه بـ ;|، تستمر الصدفة في مسح patterns بحثًا عن المطابقة التالية، وتنفيذ list المقابل، وتطبيق القاعدة على المنتهي المقابل ;;، ;& أو ;|. لاحظ أنه لا يتم إعادة توسيع word؛ يتم اختبار جميع patterns القابلة للتطبيق بنفس word.

select name [ in word ... term ] do list done
حيث term هو واحد أو أكثر من السطور الجديدة أو ; لإنهاء words. اطبع مجموعة words، كل منها مسبوق برقم. إذا تم حذف in word، استخدم المعلمات الموضعية. تتم طباعة موجه PROMPT3 وقراءة سطر من محرر الأسطر إذا كانت الصدفة تفاعلية وكان نشطًا، وإلا فإن الإدخال القياسي. إذا كان هذا السطر يتكون من رقم أحد words المدرجة، فسيتم تعيين المعلمة name إلى word المقابلة لهذا الرقم. إذا كان هذا السطر فارغًا، فسيتم طباعة قائمة الاختيار مرة أخرى. بخلاف ذلك، يتم تعيين قيمة المعلمة name إلى فارغة. يتم حفظ محتويات السطر المقروء من الإدخال القياسي في المعلمة REPLY. يتم تنفيذ list لكل اختيار حتى يتم مواجهة مقاطعة أو نهاية الملف.
( list )
قم بتنفيذ list في صدفة فرعية. يتم إعادة تعيين عمليات المقاطعة التي تم تعيينها بواسطة الأداة المساعدة trap إلى قيمها الافتراضية أثناء تنفيذ list؛ الاستثناء هو أن الإشارات التي تم تجاهلها ستستمر في التجاهل إذا تم ضبط الخيار POSIXTRAPS.
{ list }
قم بتنفيذ list.
{ try-list } always { always-list }
قم بتنفيذ try-list أولاً. بغض النظر عن الأخطاء، أو أوامر break أو continue التي تمت مواجهتها داخل try-list، قم بتنفيذ always-list. ثم يستمر التنفيذ من نتيجة تنفيذ try-list؛ بمعنى آخر، يتم التعامل مع أي خطأ، أو أمر break أو continue بالطريقة العادية، كما لو لم يكن always-list موجودًا. يشار إلى قطعتي الشفرة باسم `try block` و `always block`.

قد تظهر سطور جديدة أو فاصلات اختيارية بعد always؛ لاحظ، مع ذلك، أنه لا يجوز أن تظهر بين القوس الختامي السابق و always.

يشير "الخطأ" في هذا السياق إلى شرط مثل خطأ في بناء الجملة يتسبب في إنهاء الصدفة لتنفيذ الدالة الحالية، أو البرنامج النصي، أو القائمة. أخطاء بناء الجملة التي تمت مواجهتها أثناء قيام الصدفة بتحليل الشفرة لا تتسبب في تنفيذ always-list. على سبيل المثال، سيؤدي وجود كتلة if مبنية بشكل خاطئ في try-list إلى إنهاء الصدفة أثناء التحليل، بحيث لا يتم تنفيذ always-list، بينما سيؤدي استبدال خاطئ مثل ${*foo*} إلى خطأ في وقت التشغيل، وبعد ذلك سيتم تنفيذ always-list.

يمكن اختبار شرط الخطأ وإعادة تعيينه باستخدام المتغير الصحيح الخاص TRY_BLOCK_ERROR. خارج always-list، القيمة غير ذات صلة، ولكنها تهيأ إلى -1. داخل always-list، تكون القيمة 1 إذا حدث خطأ في try-list، وإلا 0. إذا تم تعيين TRY_BLOCK_ERROR إلى 0 أثناء always-list، يتم إعادة تعيين شرط الخطأ الناجم عن try-list، ويستمر تنفيذ الصدفة بشكل طبيعي بعد نهاية always-list. تغيير القيمة أثناء try-list ليس مفيدًا (ما لم يشكل هذا جزءًا من كتلة always مغلفة).

بغض النظر عن TRY_BLOCK_ERROR، بعد نهاية always-list، فإن حالة الصدفة العادية $? هي القيمة التي تم إرجاعها من try-list. ستكون هذه القيمة غير صفرية إذا كان هناك خطأ، حتى لو تم تعيين TRY_BLOCK_ERROR إلى صفر.

يقوم ما يلي بتنفيذ الشفرة المعطاة، مع تجاهل أي أخطاء تسببها. هذا بديل للاتفاقية المعتادة لحماية الشفرة عن طريق تنفيذها في صدفة فرعية.

{
    # code which may cause an error
    # الشفرة التي قد تسبب خطأ
  } always {
    # This code is executed regardless of the error.
    # يتم تنفيذ هذه الشفرة بغض النظر عن الخطأ.
    (( TRY_BLOCK_ERROR = 0 ))
}
# The error condition has been reset.
# تمت إعادة تعيين شرط الخطأ.

عندما تحدث كتلة try خارج أي دالة، فإن return أو exit التي تم مواجهتها في try-list لا تسبب تنفيذ always-list. بدلاً من ذلك، تخرج الصدفة فورًا بعد تنفيذ أي EXIT trap. بخلاف ذلك، سيؤدي أمر return الذي تم مواجهته في try-list إلى تنفيذ always-list، تمامًا مثل break و continue.

function [ -T ] word ... [ () ] [ term ] { list }
word ... () [ term ] { list }
word ... () [ term ] command
حيث term هو واحد أو أكثر من السطور الجديدة أو ;. قم بتعريف دالة يتم الإشارة إليها بواسطة أي واحد من word. عادةً، يتم توفير word واحدة فقط؛ غالبًا ما تكون words المتعددة مفيدة فقط لتعيين عمليات المقاطعة. جسم الدالة هو list بين { و }. انظر القسم `Functions'.

الخيارات الخاصة بـ function لها المعاني التالية:

-T
تمكين التتبع لهذه الدالة، كما لو كان باستخدام functions -T. انظر توثيق الخيار -f للأداة المساعدة typeset، في zshbuiltins(1).

إذا تم ضبط الخيار SH_GLOB للتوافق مع الصدفات الأخرى، فقد تظهر مسافات بيضاء بين القوس الأيسر والقوس الأيمن عندما يكون هناك word واحد؛ بخلاف ذلك، سيتم التعامل مع الأقواس على أنها تشكل نمطًا للعولمة في تلك الحالة.

في أي من الأشكال أعلاه، قد يظهر إعادة توجيه خارج جسم الدالة، على سبيل المثال

func() { ... } 2>&1

يتم تخزين إعادة التوجيه مع الدالة ويتم تطبيقه كلما تم تنفيذ الدالة. يتم توسيع أي متغيرات في إعادة التوجيه عند نقطة تنفيذ الدالة، ولكن خارج نطاق الدالة.

time [ pipeline ]
يتم تنفيذ pipeline، ويتم الإبلاغ عن إحصائيات التوقيت على الخطأ القياسي بالشكل المحدد بواسطة المعلمة TIMEFMT. إذا تم حذف pipeline، فقم بطباعة إحصائيات حول عملية الصدفة وأبنائها.
[[ exp ]]
قم بتقييم التعبير الشرطي exp وأعد حالة خروج صفرية إذا كان صحيحًا. انظر القسم `Conditional Expressions' لوصف exp.

صيغ بديلة للأوامر المعقدة

العديد من الأوامر المعقدة في zsh لها صيغ بديلة. هذه غير قياسية ومن المحتمل ألا تكون واضحة حتى للمبرمجين المتمرسين في الصدفة؛ لا ينبغي استخدامها في أي مكان تكون فيه قابلية نقل شفرة الصدفة مصدر قلق.

الصيغ القصيرة أدناه تعمل فقط إذا كان sublist بصيغة `{ list }' أو إذا تم ضبط الخيار SHORT_LOOPS. بالنسبة للأوامر if، while و until، في كلتا الحالتين يجب أن يكون جزء الاختبار من الحلقة محددًا بشكل مناسب، مثل `[[ ... ]]' أو `(( ... ))'، وإلا فلن يتم التعرف على نهاية الاختبار. بالنسبة للأوامر for، repeat، case و select، لا يلزم وجود صيغة خاصة للوسائط، ولكن الشرط الآخر (الصيغة الخاصة لـ sublist أو استخدام الخيار SHORT_LOOPS) لا يزال ساريًا. الخيار SHORT_REPEAT متاح لتمكين الصيغة القصيرة فقط لأمر repeat.

if list { list } [ elif list { list } ] ... [ else { list } ]
شكل بديل للأمر if. القواعد تعني أن
if [[ -o ignorebraces ]] {
  print yes
}

يعمل، ولكن

if true {  # لا يعمل!
  print yes
}

لا يعمل، حيث أن الشرط ليس محددًا بشكل مناسب.

if list sublist
شكل مختصر للشكل البديل للأمر if. تنطبق نفس القيود على شكل list كما هو الحال بالنسبة للشكل السابق.
for name ... ( word ... ) sublist
شكل مختصر للأمر for.
for name ... [ in word ... ] term sublist
حيث term هو سطر جديد واحد على الأقل أو ;. شكل مختصر آخر للأمر for.
for (( [expr1] ; [expr2] ; [expr3] )) sublist
شكل مختصر لأمر for الحسابي.
foreach name ... ( word ... ) list end
شكل آخر للأمر for.
while list { list }
شكل بديل للأمر while. لاحظ القيود المفروضة على شكل list المذكورة أعلاه.
until list { list }
شكل بديل للأمر until. لاحظ القيود المفروضة على شكل list المذكورة أعلاه.
repeat word sublist
هذا شكل مختصر للأمر repeat.
case word { [ [(] pattern [ | pattern ] ... ) list (;;|;&|;|) ] ... }
شكل بديل للأمر case.
select name [ in word ... term ] sublist
حيث term هو سطر جديد واحد على الأقل أو ;. شكل مختصر للأمر select.
function word ... [ () ] [ term ] sublist
هذا شكل مختصر للأمر function.

الكلمات المفتاحية

تُعرف الكلمات التالية ككلمات مفتاحية عند استخدامها كأول كلمة لأمر ما ما لم تكن مقتبسة أو معطلة باستخدام disable -r:

do done esac then elif else fi for case if while function repeat time until select coproc nocorrect foreach end ! [[ { } declare export float integer local readonly typeset

بالإضافة إلى ذلك، يتم التعرف على `}' في أي موضع إذا لم يتم تعيين أي من الخيارين IGNORE_BRACES أو IGNORE_CLOSE_BRACES.

الأخطاء

يعتبر المحارة بعض الأخطاء قاتلة: في محارة تفاعلية، تتسبب في عودة التحكم إلى سطر الأوامر، وفي محارة غير تفاعلية تتسبب في إنهاء المحارة. في الإصدارات الأقدم من zsh، لم تكن المحارة غير التفاعلية التي تشغل نصًا برمجيًا تنتهي تمامًا، بل تستأنف التنفيذ عند الأمر التالي للقراءة من النص البرمجي، متجاوزة ما تبقى من أي وظائف أو هياكل محارة مثل الحلقات أو الشروط؛ يمكن استعادة هذا السلوك غير المنطقي إلى حد ما عن طريق تعيين الخيار CONTINUE_ON_ERROR.

تشمل الأخطاء القاتلة التي تم العثور عليها في المحارات غير التفاعلية:

•
فشل في تحليل خيارات المحارة التي تم تمريرها عند استدعاء المحارة
•
فشل في تغيير الخيارات باستخدام الأمر المدمج set
•
أخطاء في التحليل بجميع أنواعها، بما في ذلك الفشل في تحليل التعبيرات الرياضية
•
فشل في تعيين أو تعديل سلوك المتغيرات باستخدام typeset، local، declare، export، integer، float
•
تنفيذ هياكل التحكم في الحلقات غير الموضوعة بشكل صحيح (continue، break)
•
محاولات استخدام تعبيرات منتظمة بدون توفر وحدة تعبيرات منتظمة
•
عمليات غير مسموح بها عند تعيين الخيار RESTRICTED
•
فشل في إنشاء أنبوب مطلوب لخط الأنابيب
•
فشل في إنشاء متعدد
•
فشل في تحميل وحدة مطلوبة لميزة محارة معلنة
•
أخطاء في إنشاء بدائل الأوامر أو العمليات
•
أخطاء بناء الجملة في مؤهلات العولمة
•
أخطاء إنشاء الملفات حيث لم يتم التقاطها بواسطة الخيار BAD_PATTERN
•
جميع الأنماط السيئة المستخدمة للمطابقة داخل عبارات case
•
فشل إنشاء الملفات حيث لم تكن ناتجة عن خيارات NO_MATCH أو ما شابه ذلك
•
جميع أخطاء إنشاء الملفات حيث تم استخدام النمط لإنشاء متعدد
•
أخطاء الذاكرة حيث تم اكتشافها بواسطة المحارة
•
فهارس غير صالحة لمتغيرات المحارة
•
محاولات التعيين للمتغيرات المقروءة فقط
•
أخطاء منطقية مع المتغيرات مثل التعيين لنوع خاطئ
•
استخدام أسماء متغيرات غير صالحة
•
أخطاء في بناء جملة استبدال المتغيرات
•
فشل تحويل الأحرف في تعبيرات $'...'

إذا تم تعيين الخيار POSIX_BUILTINS، فسيتم اعتبار المزيد من الأخطاء المتعلقة بالأوامر المدمجة للمحارة قاتلة، كما هو محدد في معيار POSIX.

التعليقات

في المحارات غير التفاعلية، أو في المحارات التفاعلية مع تعيين الخيار INTERACTIVE_COMMENTS، فإن كلمة تبدأ بالحرف الثالث من معامل histchars (`#' افتراضيًا) تجعل تلك الكلمة وجميع الأحرف التالية حتى سطر جديد يتم تجاهلها.

الأسماء المستعارة

يتم فحص كل كلمة مؤهلة في مدخلات المحارة لمعرفة ما إذا كان هناك اسم مستعار معرف لها. إذا كان الأمر كذلك، يتم استبدالها بنص الاسم المستعار إذا كانت في موضع الأمر (إذا كان يمكن أن تكون الكلمة الأولى لأمر بسيط)، أو إذا كان الاسم المستعار عامًا. إذا انتهى نص الاستبدال بمسافة، فإن الكلمة التالية في مدخلات المحارة تكون مؤهلة دائمًا لأغراض توسيع الاسم المستعار.

يُعد اسم الوظيفة، word، في بناء جملة تعريف الوظيفة المتوافقة مع sh `word () ...' كلمة نتجت عن توسيع اسم مستعار خطأ، ما لم يتم تعيين الخيار ALIAS_FUNC_DEF.

يتم تعريف اسم مستعار باستخدام الأمر المدمج alias؛ يمكن تعريف الأسماء المستعارة العامة باستخدام الخيار -g لهذا الأمر المدمج.

يتم تعريف word على النحو التالي:

•
أي سلسلة نصية عادية أو نمط عولمة
•
أي سلسلة نصية مقتبسة، باستخدام أي طريقة اقتباس (لاحظ أن علامات الاقتباس يجب أن تكون جزءًا من تعريف الاسم المستعار لتكون مؤهلة)
•
أي مرجع معلمة أو استبدال أمر
•
أي سلسلة من المذكور أعلاه، متصلة بدون مسافات بيضاء أو رموز أخرى بينها
•
أي كلمة مفتاحية (case، do، else، إلخ)
•
مع الاستعارة العامة، أي فاصل أو عامل إعادة توجيه، و `(' أو `)' عندما لا تكون جزءًا من نمط عولمة

يتم إجراء توسيع الاسم المستعار على مدخلات المحارة قبل أي توسيع آخر باستثناء توسيع السجل. لذلك، إذا تم تعريف اسم مستعار للكلمة foo، يمكن تجنب توسيع الاسم المستعار عن طريق اقتباس جزء من الكلمة، على سبيل المثال \foo. تعمل أي شكل من أشكال الاقتباس، على الرغم من عدم وجود ما يمنع تعريف اسم مستعار للشكل المقتبس مثل \foo أيضًا.

على وجه الخصوص، لاحظ أنه يجب استخدام الاقتباس عند استخدام unalias لإزالة الأسماء المستعارة العامة:

% alias -g foo=bar
% unalias foo
unalias: no such hash table element: bar
% unalias \foo
%

عند تعيين POSIX_ALIASES، تكون السلاسل النصية العادية غير المقتبسة فقط مؤهلة للاستعارة. لا يرفض الأمر المدمج alias الأسماء المستعارة غير المؤهلة، ولكن لا يتم توسيعها.

للاستخدام مع الإكمال، الذي من شأنه إزالة الشرطة المائلة للخلف الأولية متبوعة بحرف غير خاص، قد يكون من الأنسب اقتباس الكلمة عن طريق البدء بعلامة اقتباس مفردة، أي 'foo؛ سيضيف الإكمال تلقائيًا علامة الاقتباس المفردة الختامية.

صعوبات الأسماء المستعارة

على الرغم من أنه يمكن استخدام الأسماء المستعارة بطرق تحني قواعد المحارة العادية، إلا أنه لا يمكن استخدام كل سلسلة من الأحرف غير البيضاء كاسم مستعار.

أي مجموعة من الأحرف غير المدرجة ككلمة أعلاه ليست كلمة، وبالتالي لا يتم بذل أي محاولة لتوسيعها كاسم مستعار، بغض النظر عن كيفية تعريفها (أي عبر الأمر المدمج أو المعامل الخاص aliases الموصوف في قسم وحدة ZSH/المعامل في zshmodules(1)). ومع ذلك، كما هو مذكور في حالة POSIX_ALIASES أعلاه، لا تحاول المحارة استنتاج ما إذا كانت السلسلة تتوافق مع كلمة وقت إنشاء الاسم المستعار.

على سبيل المثال، تعبير يحتوي على علامة = في بداية سطر الأوامر هو تعيين ولا يمكن توسيعه كاسم مستعار؛ علامة = منفردة ليست تعيينًا ولكن لا يمكن تعيينها إلا كاسم مستعار باستخدام المعامل، وإلا فإن علامة = تُعتبر جزءًا من بناء الجملة الخاص بالأمر المدمج.

لا يمكن حاليًا استعارة رمز `((' الذي يبدأ التعبيرات الحسابية، لأنه حتى يتم تحليل عبارة كاملة، لا يمكن تمييزها عن رمزين `(' متتاليين يبدآن قوائم فرعية متداخلة. أيضًا، إذا تم استعارة فاصل مثل &&، فإن \&& تتحول إلى الرمزين \& و &، يمكن استعارة كل منهما بشكل منفصل. وينطبق الشيء نفسه على \<<، \>|، إلخ.

هناك مشكلة شائعة مع الأسماء المستعارة موضحة بالكود التالي:

alias echobar='echo bar'; echobar

هذا يطبع a

sion، تم البحث صراحةً بواسطة المستخدم، يتم البحث عن element لتعريف الوظيفة دون مقارنة عمرها بعمر الملفات الأخرى؛ في الواقع، لا يلزم أن يكون هناك دليل يسمى element بدون اللاحقة. وبالتالي فإن تضمين عنصر مثل `/usr/local/funcs.zwc' في fpath سيسرع البحث عن الوظائف، مع عيب أن الوظائف المضمنة يجب إعادة تجميعها يدويًا بشكل صريح قبل أن تلاحظ الصدفة أي تغييرات.

element/function.zwc
ملف تم إنشاؤه بواسطة zcompile، ومن المتوقع أن يحتوي على تعريف لـ function. قد يتضمن تعريفات وظائف أخرى أيضًا، ولكن لا يتم تحميلها ولا تنفيذها؛ يتم البحث عن ملف تم العثور عليه بهذه الطريقة فقط لتعريف function.
element/function
ملف نص أوامر zsh، يُفترض أنه تعريف لـ function.

باختصار، ترتيب البحث هو أولاً، في آباء الأدلة في fpath عن الأحدث من دليل مجمّع أو دليل في fpath؛ ثانيًا، إذا احتوى أكثر من واحد من هذه على تعريف للوظيفة المطلوبة، يتم اختيار الأيسر في fpath؛ وثالثًا، داخل الدليل، الأحدث من وظيفة مجمّعة أو تعريف وظيفة عادي يتم استخدامه.

إذا تم تعيين الخيار KSH_AUTOLOAD، أو إذا احتوى الملف على تعريف بسيط للوظيفة فقط، فسيتم تنفيذ محتويات الملف. سيؤدي هذا عادةً إلى تعريف الوظيفة المعنية، ولكنه قد يؤدي أيضًا إلى تهيئة، والتي يتم تنفيذها في سياق تنفيذ الوظيفة، وقد تحدد بالتالي معلمات محلية. يعد خطأ إذا لم يتم تعريف الوظيفة عن طريق تحميل الملف.

بخلاف ذلك، يُفترض أن يكون جسم الوظيفة (بدون `funcname() {...}' المحيطة) هو المحتوى الكامل للملف. يسمح هذا الشكل باستخدام الملف مباشرة كـ نص برمجي للصدفة قابل للتنفيذ. إذا أدى معالجة الملف إلى إعادة تعريف الوظيفة، فلا يتم إعادة تنفيذ الوظيفة نفسها. لإجبار الصدفة على إجراء التهيئة ثم استدعاء الوظيفة المعرفة، يجب أن يحتوي الملف على رمز تهيئة (والذي سيتم تنفيذه ثم تجاهله) بالإضافة إلى تعريف كامل للوظيفة (والذي سيتم الاحتفاظ به للاستدعاءات اللاحقة للوظيفة)، واستدعاء لوظيفة الصدفة، بما في ذلك أي وسائط، في النهاية.

على سبيل المثال، افترض أن ملف التحميل التلقائي func يحتوي على

func() { print This is func; }
print func is initialized

ثم `func; func' مع تعيين KSH_AUTOLOAD سيؤدي إلى إظهار كلا الرسالتين عند الاستدعاء الأول، ولكن فقط الرسالة `This is func' عند الاستدعاء الثاني واللاحق. بدون تعيين KSH_AUTOLOAD، سيؤدي إلى ظهور رسالة التهيئة عند الاستدعاء الأول، والرسالة الأخرى عند الاستدعاء الثاني واللاحق.

من الممكن أيضًا إنشاء وظيفة غير معلمة كـ تحميل تلقائي، ولكنها تقوم بتحميل تعريفها الخاص عن طريق البحث في fpath، باستخدام `autoload -X' داخل وظيفة صدفة. على سبيل المثال، ما يلي متكافئ:

myfunc() {
  autoload -X
}
myfunc args...

و

unfunction myfunc   # if myfunc was defined
autoload myfunc
myfunc args...

في الواقع، يقوم أمر functions بإخراج `builtin autoload -X' كجسم لوظيفة محمّلة تلقائيًا. يتم ذلك بحيث

eval "$(functions)"

ينتج نتيجة معقولة. يمكن التعرف على وظيفة تحميل تلقائي حقيقية من خلال وجود التعليق `# undefined' في الجسم، لأن جميع التعليقات يتم تجاهلها من الوظائف المعرفة.

لتحميل تعريف وظيفة محمّلة تلقائيًا myfunc بدون تنفيذ myfunc، استخدم:

autoload +X myfunc

وظائف مجهولة

إذا لم يتم إعطاء اسم للوظيفة، فإنها تكون `مجهولة' ويتم التعامل معها بشكل خاص. يمكن استخدام أي شكل من أشكال تعريف الوظيفة: `()' بدون اسم سابق، أو `function' مع قوس مفتوح يتبعه مباشرة. يتم تنفيذ الوظيفة فورًا عند نقطة التعريف ولا يتم تخزينها للاستخدام المستقبلي. يتم تعيين اسم الوظيفة إلى `(anon)'.

يمكن تحديد الوسائط للوظيفة ككلمات تلي القوس المغلق الذي يحدد الوظيفة، وبالتالي إذا لم تكن هناك أي وسائط (بخلاف $0) يتم تعيينها. هذا اختلاف عن طريقة تحليل الوظائف الأخرى: يمكن أن يتبع تعريفات الوظائف العادية كلمات مفتاحية معينة مثل `else' أو `fi'، والتي ستُعامل كوسائط للوظائف المجهولة، بحيث يلزم وجود سطر جديد أو فاصلة منقوطة لإجبار تفسير الكلمات المفتاحية.

لاحظ أيضًا أن قائمة وسائط أي نص برمجي أو وظيفة محيطة يتم إخفاؤها (كما هو الحال مع أي وظيفة أخرى يتم استدعاؤها في هذه النقطة).

يمكن تطبيق عمليات إعادة التوجيه على الوظيفة المجهولة بنفس الطريقة التي تطبق بها على هيكل صدفة حالي محاط بأقواس. الاستخدام الرئيسي للوظائف المجهولة هو توفير نطاق للمتغيرات المحلية. هذا مريح بشكل خاص في ملفات بدء التشغيل لأنها لا توفر نطاق متغيرات محلي خاص بها.

على سبيل المثال،

variable=outside
function {
  local variable=inside
  print "I am $variable with arguments $*"
} this and that
print "I am $variable"

يخرج ما يلي:

I am inside with arguments this and that
I am outside

لاحظ أن تعريفات الوظائف ذات الوسائط التي تتوسع إلى لا شيء، على سبيل المثال `name=; function $name { ... }'، لا تُعامل على أنها وظائف مجهولة. بدلاً من ذلك، تُعامل على أنها تعريفات وظائف عادية حيث يتم تجاهل التعريف بصمت.

وظائف خاصة

وظائف معينة، إذا تم تعريفها، لها معنى خاص للصدفة.

وظائف الخطاف

بالنسبة للوظائف أدناه، من الممكن تعريف مصفوفة لها نفس اسم الوظيفة مع إلحاق `_functions'. يُفترض أن يكون أي عنصر في مثل هذه المصفوفة اسم وظيفة سيتم تنفيذها؛ يتم تنفيذها في نفس السياق وبنفس الوسائط وبنفس القيمة الأولية لـ $? مثل الوظيفة الأساسية. على سبيل المثال، إذا كانت $chpwd_functions مصفوفة تحتوي على القيم `mychpwd'، `chpwd_save_dirstack'، فإن الصدفة تحاول تنفيذ الوظائف `chpwd'، `mychpwd'، و `chpwd_save_dirstack'، بهذا الترتيب. يتم تجاهل أي وظيفة غير موجودة بصمت. يُشار إلى وظيفة تم العثور عليها بهذه الآلية في مكان آخر باسم وظيفة خطاف. خطأ في أي وظيفة يتسبب في عدم تشغيل الوظائف اللاحقة. لاحظ علاوة على ذلك أن خطأ في خطاف precmd يتسبب في عدم تشغيل وظيفة periodic تالية فورًا (على الرغم من أنها قد تعمل في الفرصة التالية).

chpwd
يتم تنفيذها كلما تم تغيير دليل العمل الحالي.
periodic
إذا تم تعيين المعلمة PERIOD، فسيتم تنفيذ هذه الوظيفة كل $PERIOD ثانية، قبل المطالبة مباشرة. لاحظ أنه إذا تم تعريف وظائف متعددة باستخدام المصفوفة periodic_functions، يتم تطبيق فترة واحدة فقط على المجموعة الكاملة من الوظائف، ولا يتم إعادة تعيين الوقت المجدول إذا تم تغيير قائمة الوظائف. لذلك يتم استدعاء مجموعة الوظائف معًا دائمًا.
precmd
يتم تنفيذها قبل كل مطالبة. لاحظ أنه لا يتم إعادة تنفيذ وظائف ما قبل الأمر لمجرد إعادة رسم سطر الأوامر، كما يحدث، على سبيل المثال، عند عرض إشعار بشأن مهمة تنتهي.
preexec
يتم تنفيذها مباشرة بعد قراءة الأمر وقبل تنفيذه. إذا كانت آلية السجل نشطة (بغض النظر عما إذا كان السطر قد تم تجاهله من مخزن السجل المؤقت)، فسيتم تمرير السلسلة التي كتبها المستخدم كوسيط أول، وإلا فهي سلسلة فارغة. سيتم تمرير الأمر الفعلي الذي سيتم تنفيذه (بما في ذلك الأسماء المستعارة الموسعة) في شكلين مختلفين: الوسيط الثاني هو نسخة أحادية السطر، محدودة الحجم من الأمر (مع حذف أشياء مثل أجسام الوظائف)؛ الوسيط الثالث يحتوي على النص الكامل الذي يتم تنفيذه.
zshaddhistory
يتم تنفيذها عند قراءة سطر سجل تفاعليًا، ولكن قبل تنفيذه. الوسيط الوحيد هو سطر السجل الكامل (بحيث يظل أي حرف سطر جديد نهائي حاضرًا).

إذا أعادت أي من وظائف الخطاف الحالة 1 (أو أي قيمة غير صفرية غير 2، على الرغم من أن هذا غير مضمون للإصدارات المستقبلية من الصدفة) فلن يتم حفظ سطر السجل، على الرغم من أنه يبقى في السجل حتى يتم تنفيذ السطر التالي، مما يسمح لك بإعادة استخدامه أو تعديله على الفور.

إذا أعادت أي من وظائف الخطاف الحالة 2، فسيتم حفظ سطر السجل في قائمة السجل الداخلية، ولكن لن يتم كتابته إلى ملف السجل. في حالة التعارض، يتم أخذ أول قيمة غير صفرية.

قد تستدعي وظيفة الخطاف `fc -p ...' لتبديل سياق السجل بحيث يتم حفظ السجل في ملف مختلف عن الملف الموجود في المعلمة العامة HISTFILE. يتم التعامل مع هذا بشكل خاص: يتم استعادة سياق السجل تلقائيًا بعد انتهاء معالجة سطر السجل.

تعمل وظيفة المثال التالية مع أحد الخيارات INC_APPEND_HISTORY أو SHARE_HISTORY المعين، بحيث يتم كتابة السطر فورًا بعد إضافة إدخال السجل. تضيف أولاً سطر السجل إلى السجل العادي مع إزالة حرف السطر الجديد، وهو عادةً السلوك الصحيح. ثم تقوم بتبديل سياق السجل بحيث يتم كتابة السطر إلى ملف سجل في الدليل الحالي.

zshaddhistory() {
  print -sr -- ${1%%$'\n'}
  fc -p .zsh_local_history
}

تعبيرات شرطية

تعبير شرطي يستخدم مع الأمر المركب [[ لاختبار سمات الملفات ومقارنة السلاسل النصية. يمكن بناء كل تعبير من واحد أو أكثر من التعبيرات الأحادية أو الثنائية التالية:

-a file
صحيح إذا كان file موجودًا.
-b file
صحيح إذا كان file موجودًا وكان ملفًا خاصًا بالكتل.
-c file
صحيح إذا كان file موجودًا وكان ملفًا خاصًا بالأحرف.
-d file
صحيح إذا كان file موجودًا وكان مجلدًا.
-e file
صحيح إذا كان file موجودًا.
-f file
صحيح إذا كان file موجودًا وكان ملفًا عاديًا.
-g file
صحيح إذا كان file موجودًا وكان لديه بت setgid مضبوطًا.
-h file
صحيح إذا كان file موجودًا وكان رابطًا رمزيًا.
-k file
صحيح إذا كان file موجودًا وكان لديه بت sticky مضبوطًا.
-n string
صحيح إذا كان طول string غير صفري.
-o option
صحيح إذا كان الخيار المسمى option مفعلًا. يمكن أن يكون option حرفًا واحدًا، وفي هذه الحالة يكون اسم خيار بحرف واحد. (انظر القسم `تحديد الخيارات').

عندما لا يوجد خيار باسم option، ولم يتم تعيين الخيار POSIX_BUILTINS، يتم إرجاع 3 مع تحذير. إذا تم تعيين هذا الخيار، يتم إرجاع 1 بدون تحذير.

-p file
صحيح إذا كان file موجودًا وكان ملف FIFO خاصًا (أنبوب مسمى).
-r file
صحيح إذا كان file موجودًا ويمكن قراءته بواسطة العملية الحالية.
-s file
صحيح إذا كان file موجودًا وكان حجمه أكبر من صفر.
-t fd
صحيح إذا كان واصف الملف رقم fd مفتوحًا ومرتبطًا بجهاز طرفي. (ملاحظة: fd ليس اختياريًا)
-u file
صحيح إذا كان file موجودًا وكان لديه بت setuid مضبوطًا.
-v varname
صحيح إذا كان متغير shell varname معينًا.
-w file
صحيح إذا كان file موجودًا ويمكن الكتابة فيه بواسطة العملية الحالية.
-x file
صحيح إذا كان file موجودًا ويمكن تنفيذه بواسطة العملية الحالية. إذا كان file موجودًا وكان مجلدًا، فإن العملية الحالية لديها إذن البحث في المجلد.
-z string
صحيح إذا كان طول string صفرًا.
-L file
صحيح إذا كان file موجودًا وكان رابطًا رمزيًا.
-O file
صحيح إذا كان file موجودًا وكان مملوكًا لمعرف المستخدم الفعال لهذه العملية.
-G file
صحيح إذا كان file موجودًا وكانت مجموعته تتطابق مع معرف المجموعة الفعال لهذه العملية.
-S file
صحيح إذا كان file موجودًا وكان مقبسًا.
-N file
صحيح إذا كان file موجودًا ولم يكن وقت الوصول إليه أحدث من وقت التعديل.
file1 -nt file2
صحيح إذا كان file1 موجودًا وكان أحدث من file2.
file1 -ot file2
صحيح إذا كان file1 موجودًا وكان أقدم من file2.
file1 -ef file2
صحيح إذا كان file1 و file2 موجودين ويشيران إلى نفس الملف.
string = pattern
string == pattern
صحيح إذا كان string يطابق pattern. الشكلان متطابقان تمامًا. الشكل `=' هو بناء الجملة التقليدي للشل (وبالتالي فهو الوحيد المستخدم عمومًا مع الأوامر المدمجة test و [)؛ الشكل `==' يوفر التوافق مع أنواع أخرى من لغات الكمبيوتر.
string != pattern
صحيح إذا كان string لا يطابق pattern.
string =~ regexp
صحيح إذا كان string يطابق التعبير العادي regexp. إذا كان الخيار RE_MATCH_PCRE معينًا، يتم اختبار regexp كتعبير عادي PCRE باستخدام الوحدة النمطية zsh/pcre، وإلا يتم اختباره كتعبير عادي POSIX موسع باستخدام الوحدة النمطية zsh/regex. عند المطابقة الناجحة، سيتم تحديث بعض المتغيرات؛ لا يتم تغيير أي متغيرات إذا فشلت المطابقة.

إذا لم يتم تعيين الخيار BASH_REMATCH، يتم تعيين المعلمة العددية MATCH إلى السلسلة الفرعية التي طابقت النمط، والمعلمتين العدديتين MBEGIN و MEND إلى فهرس البداية والنهاية، على التوالي، للمطابقة في string، بحيث إذا كانت string موجودة في المتغير var، فإن التعبير `${var[$MBEGIN,$MEND]}' يكون مطابقًا لـ `$MATCH'. يتم احترام تعيين الخيار KSH_ARRAYS. وبالمثل، يتم تعيين المصفوفة match إلى السلاسل الفرعية التي طابقت التعبيرات الفرعية الموضوعة بين قوسين، والمصفوفتين mbegin و mend إلى مواضع البداية والنهاية، على التوالي، للسلاسل الفرعية داخل string. لا يتم تعيين المصفوفات إذا لم تكن هناك تعبيرات فرعية موضوعة بين قوسين. على سبيل المثال، إذا تم مطابقة السلسلة `a short string' مع التعبير العادي `s(...)t'، فإن (بافتراض أن الخيار KSH_ARRAYS غير معين) MATCH و MBEGIN و MEND تكون `short' و 3 و 7، على التوالي، بينما match و mbegin و mend هي مصفوفات أحادية الإدخال تحتوي على السلاسل `hor' و `4' و `6'، على التوالي.

إذا تم تعيين الخيار BASH_REMATCH، يتم تعيين المصفوفة BASH_REMATCH إلى السلسلة الفرعية التي طابقت النمط متبوعة بالسلاسل الفرعية التي طابقت التعبيرات الفرعية الموضوعة بين قوسين داخل النمط.

string1 < string2
صحيح إذا كانت string1 تأتي قبل string2 بناءً على القيمة ASCII لأحرفها.
string1 > string2
صحيح إذا كانت string1 تأتي بعد string2 بناءً على القيمة ASCII لأحرفها.
exp1 -eq exp2
صحيح إذا كان exp1 مساويًا عدديًا لـ exp2. لاحظ أنه للمقارنات العددية البحتة، يكون استخدام الأمر المدمج ((...)) الموضح في القسم `تقييم العمليات الحسابية' أكثر ملاءمة من التعبيرات الشرطية.
exp1 -ne exp2
صحيح إذا كان exp1 لا يساوي عدديًا exp2.
exp1 -lt exp2
صحيح إذا كان exp1 أقل عدديًا من exp2.
exp1 -gt exp2
صحيح إذا كان exp1 أكبر عدديًا من exp2.
exp1 -le exp2
صحيح إذا كان exp1 أقل من أو يساوي عدديًا exp2.
exp1 -ge exp2
صحيح إذا كان exp1 أكبر من أو يساوي عدديًا exp2.
( exp )
صحيح إذا كان exp صحيحًا.
! exp
صحيح إذا كان exp خاطئًا.
exp1 && exp2
صحيح إذا كان exp1 و exp2 كلاهما صحيحين.
exp1 || exp2
صحيح إذا كان exp1 أو exp2 صحيحًا.

للتوافق، إذا كان هناك وسيط واحد غير مهم نحويًا، عادةً متغير، يتم التعامل مع الشرط كاختبار لما إذا كان التعبير يتوسع كسلسلة ذات طول غير صفري. بمعنى آخر، [[ $var ]] هو نفس [[ -n $var ]]. يوصى باستخدام الشكل الثاني، الصريح، حيثما أمكن.

يتم إجراء توسع shell العادي على وسائط file و string و pattern، ولكن يتم تقييد نتيجة كل توسع لتكون كلمة واحدة، مشابهة لتأثير علامات الاقتباس المزدوجة.

لا يتم إجراء توليد أسماء الملفات على أي شكل من أشكال الوسائط للشروط. ومع ذلك، يمكن فرض ذلك في أي حالة يكون فيها توسع shell العادي صالحًا وعندما يكون الخيار EXTENDED_GLOB فعالًا باستخدام محدد glob صريح بالشكل (#q) في نهاية السلسلة. قد يظهر تعبير محدد glob عادي بين `q' والقوس المغلق؛ إذا لم يظهر أي شيء، فإن التعبير ليس له تأثير يتجاوز التسبب في توليد أسماء الملفات. يتم ضم نتائج توليد أسماء الملفات لتشكيل كلمة واحدة، كما هو الحال مع نتائج أشكال التوسع الأخرى.

هذا الاستخدام الخاص لتوليد أسماء الملفات متاح فقط مع بناء الجملة [[. إذا كان الشرط يحدث داخل الأوامر المدمجة [ أو test، يحدث globing بدلاً من ذلك كجزء من توسع سطر الأوامر العادي قبل تقييم الشرط. في هذه الحالة، قد يولد كلمات متعددة من المرجح أن تربك بناء جملة الاختبار.

eric ألوان مسموح بها في الصيغة الثانية أيضًا.
%K (%k)
بدء (إيقاف) استخدام لون خلفية مختلف. بناء الجملة مطابق لتلك الخاصة بـ %F و %f.
%{...%}
تضمين سلسلة كنص تسلسلي حرفي. يجب ألا تغير السلسلة داخل الأقواس موضع المؤشر. يمكن تداخل أزواج الأقواس.

يتم التعامل مع وسيط رقمي موجب بين % و { كما هو موضح لـ %G أدناه.

%G
داخل تسلسل %{...%}، قم بتضمين "خلل": أي، افترض أنه سيتم إخراج عرض حرف واحد. هذا مفيد عند إخراج أحرف لا يمكن للصدفة معالجتها بشكل صحيح بطريقة أخرى، مثل مجموعة الأحرف البديلة على بعض الطرفيات. يمكن تضمين الأحرف المعنية داخل تسلسل %{...%} بالإضافة إلى العدد المناسب من تسلسلات %G للإشارة إلى العرض الصحيح. يشير عدد صحيح بين "%" و "G" إلى عرض حرف غير واحد. وبالتالي %{seq%2G%} يخرج seq ويفترض أنه يأخذ عرض حرفين قياسيين.

تتراكم استخدامات %G المتعددة بالطريقة الواضحة؛ موضع %G غير مهم. لا يتم التعامل مع الأعداد الصحيحة السالبة.

لاحظ أنه عند استخدام اقتطاع المطالبة، يُنصح بتقسيم الإخراج إلى أحرف فردية داخل كل مجموعة %{...%} بحيث يمكن العثور على نقطة الاقتطاع الصحيحة.

سلاسل فرعية مشروطة في المطالبات

%v
قيمة العنصر الأول من معلمة المصفوفة psvar. بعد "%" برقم صحيح يعطي هذا العنصر من المصفوفة. الأعداد الصحيحة السالبة تعد من نهاية المصفوفة.
%(x.true-text.false-text)
يحدد تعبيرًا ثلاثيًا. الحرف الذي يلي x عشوائي؛ يُستخدم نفس الحرف لفصل النص لنتيجة "صحيحة" عن نص نتيجة "خاطئة". لا يجوز أن يظهر هذا الفاصل في true-text، إلا كجزء من تسلسل هروب %. قد تظهر ")" في false-text على هيئة "%)". يمكن لكل من true-text و false-text أن يحتوي على تسلسلات هروب متداخلة بشكل عشوائي، بما في ذلك تعبيرات ثلاثية إضافية.

قد يسبق القوس الأيسر أو يتبعه عدد صحيح موجب n، والذي يكون افتراضيًا صفرًا. سيتم ضرب العدد الصحيح السالب في -1، باستثناء ما هو مذكور أدناه لـ "l". قد يكون حرف الاختبار x أيًا مما يلي:

!
صحيح إذا كانت الصدفة تعمل بصلاحيات.
#
صحيح إذا كان معرف المستخدم الفعال للعملية الحالية هو n.
?
صحيح إذا كانت حالة خروج الأمر الأخير هي n.
_
صحيح إذا تم بدء n على الأقل من هياكل الصدفة.
C
/
صحيح إذا كان المسار المطلق الحالي يحتوي على n على الأقل من العناصر بالنسبة للدليل الجذر، وبالتالي يعتبر / 0 عناصر.
c
.
~
صحيح إذا كان المسار الحالي، مع استبدال البادئة، يحتوي على n على الأقل من العناصر بالنسبة للدليل الجذر، وبالتالي يعتبر / 0 عناصر.
D
صحيح إذا كان الشهر يساوي n (يناير = 0).
d
صحيح إذا كان يوم الشهر يساوي n.
e
صحيح إذا كان عمق التقييم n على الأقل.
g
صحيح إذا كان معرف المجموعة الفعال للعملية الحالية هو n.
j
صحيح إذا كان عدد الوظائف n على الأقل.

صحيح إذا كان المعلم SHLVL يساوي n على الأقل.
l
صحيح إذا تم بالفعل طباعة n حرف على الأقل على السطر الحالي. عندما يكون n سالبًا، يكون صحيحًا إذا تبقى abs(n) على الأقل من الأحرف قبل الهامش المقابل (وبالتالي الهامش الأيسر لـ RPROMPT).
S

T
صحيح إذا كان الوقت بالساعات يساوي n.
t
صحيح إذا كان الوقت بالدقائق يساوي n.

صحيح إذا كانت المصفوفة psvar تحتوي على n على الأقل من العناصر.
V
صحيح إذا تم تعيين العنصر n من المصفوفة psvar وهو غير فارغ.
w

%>string>
%[xstring]
يحدد سلوك الاقتطاع لبقية سلسلة المطالبة. الصيغة الثالثة، المهملة، تعادل `%xstringx'، أي x يمكن أن تكون `<' أو `>'. ستُعرض السلسلة string بدلاً من الجزء المقتطع من أي سلسلة؛ لاحظ أن هذا لا يخضع لتوسيع المطالبة.

الوسيط الرقمي، والذي قد يظهر في الصيغة الثالثة مباشرة بعد `[`، يحدد الحد الأقصى المسموح به لطول السلاسل المختلفة التي يمكن عرضها في المطالبة. في الصيغتين الأوليين، قد يكون هذا الوسيط الرقمي سالبًا، وفي هذه الحالة يتم تحديد طول الاقتطاع بطرح القيمة المطلقة للوسيط الرقمي من عدد مواضع الأحرف المتبقية في سطر المطالبة الحالي. إذا أدى ذلك إلى طول صفر أو سالب، يتم استخدام طول 1. بعبارة أخرى، يرتب الوسيط السالب أنه بعد الاقتطاع، يتبقى n على الأقل من الأحرف قبل الهامش الأيمن (الهامش الأيسر لـ RPROMPT).

تقوم الصيغ التي تحتوي على `<' بالاقتطاع من يسار السلسلة، والصيغ التي تحتوي على `>' بالاقتطاع من يمين السلسلة. على سبيل المثال، إذا كان الدليل الحالي هو `/home/pike'، فإن المطالبة `%8<..<%/' ستتوسع إلى `..e/pike'. في هذه السلسلة، يمكن اقتباس الحرف المنتهي (`<'، `>' أو `]')، أو في الواقع أي حرف، بواسطة `\' مسبق؛ لاحظ عند استخدام print -P، ومع ذلك، يجب مضاعفة ذلك لأن السلسلة تخضع أيضًا لمعالجة print القياسية، بالإضافة إلى أي علامات هروب تمت إزالتها بواسطة سلسلة مقتبسة مزدوجة: لذلك فإن أسوأ حالة هي `print -P "%<\\\\<<..."'.

إذا كانت السلسلة string أطول من طول الاقتطاع المحدد، فستظهر بالكامل، لتحل محل السلسلة المقتطعة بالكامل.

يمتد جزء سلسلة المطالبة المراد اقتطاعه إلى نهاية السلسلة، أو إلى نهاية مجموعة متداخلة تالية من بنية `%('، أو إلى الاقتطاع التالي الذي تم مواجهته في نفس مستوى التجميع (أي، الاقتطاعات داخل `%(' منفصلة)، أيهما يأتي أولاً. على وجه الخصوص، يحدد الاقتطاع ذو الوسيط صفر (على سبيل المثال، `%<<') نهاية نطاق السلسلة المراد اقتطاعها مع تعطيل الاقتطاع من هناك فصاعدًا. على سبيل المثال، ستطبع المطالبة `%10<...<%~%<<%# ' تمثيلًا مقتطعًا للدليل الحالي، يتبعه `%' أو `#'، يتبعه مسافة. بدون `%<<'، سيتم تضمين هذين الحرفين في السلسلة المراد اقتطاعها. لاحظ أن `%-0<<' ليس مكافئًا لـ `%<<' ولكنه يحدد أن المطالبة يتم اقتطاعها عند الهامش الأيمن.

ينطبق الاقتطاع فقط ضمن كل سطر فردي من المطالبة، كما هو محدد بأحرف الأسطر الجديدة المضمنة (إن وجدت). إذا كان الطول الإجمالي لأي سطر من المطالبة بعد الاقتطاع أكبر من عرض الطرفية، أو إذا كان الجزء المراد اقتطاعه يحتوي على أحرف أسطر جديدة مضمنة، فإن سلوك الاقتطاع غير محدد وقد يتغير في إصدار مستقبلي من الصدفة. استخدم `%-n(l.true-text.false-text)' لإزالة أجزاء من المطالبة عندما تكون المساحة المتاحة أقل من n.

zshmisc — أوامر zsh متنوعة

الوصف

هذه الصفحة تصف بعض الأوامر التي لا تنتمي إلى فئات أخرى.

متنوع

يمكن استدعاء معظم الأوامر الموضحة في هذه الصفحة كأوامر قائمة بذاتها، أو كجزء من سطر الأوامر.

هروب الشرطة المائلة العكسية

يتم استخدام الشرطة المائلة العكسية (\) للهروب من الحرف التالي، مما يعني أنه سيتم تفسيره حرفيًا بدلاً من تفسيره على أنه حرف خاص.

استبدال الأوامر

يمكن استبدال الأوامر باستخدام الأقواس المائلة (`$(command)`) أو الأقواس المائلة العكسية (`` `command` ``).

استبدال العمليات

يمكن استخدام استبدال العمليات (`>(command)` أو `<(command)`) لتمرير ناتج أمر كملف إلى أمر آخر، أو قراءة ملف كمدخل لأمر.

توسع العمليات الحسابية

يمكن إجراء العمليات الحسابية باستخدام الأقواس المربعة المزدوجة (`((expression))`).

العبارات الشرطية

يمكن استخدام العبارات الشرطية مثل `if` و `case` و `select` لتنفيذ أوامر بناءً على شروط معينة.

بنى التكرار

يمكن استخدام بنى التكرار مثل `for` و `while` و `until` لتنفيذ أوامر بشكل متكرر.

الوظائف

يمكن تعريف الوظائف باستخدام الكلمة المفتاحية `function` أو باستخدام الصيغة `name () { ... }`.

الوظائف المحملة تلقائيًا

يمكن تكوين zsh لتحميل الوظائف تلقائيًا عند استدعائها.

الوظائف المجهولة

يمكن إنشاء وظائف مجهولة باستخدام الكلمة المفتاحية `function` دون اسم.

الوظائف الخاصة

يقوم zsh بتوفير بعض الوظائف الخاصة مثل `zsh_available_options` و `zsh_option_description`.

الوظائف

يمكن إدارة الوظائف في الخلفية باستخدام أوامر مثل `bg` و `fg` و `jobs`.

الإشارات

يمكن إرسال الإشارات إلى العمليات باستخدام أوامر مثل `kill`.

تقييم العمليات الحسابية

يمكن تقييم التعبيرات الحسابية باستخدام `((...))`.

التعابير الشرطية

يمكن استخدام التعابير الشرطية في العبارات الشرطية وبعض الأوامر الأخرى.

توسع تسلسلات الموجه

يمكن استخدام تسلسلات خاصة في موجهات zsh لتضمين معلومات ديناميكية.

هروب الموجه البسيط

هناك العديد من الهروب البسيط للموجه المتاح، مثل %n لاسم المستخدم.
