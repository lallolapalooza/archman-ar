الاسم

zshoptions - خيارات zsh

تحديد الخيارات

يتم الإشارة إلى الخيارات بشكل أساسي بالاسم. هذه الأسماء غير حساسة لحالة الأحرف ويتم تجاهل الشرطات السفلية. على سبيل المثال، `allexport' مكافئة لـ `A__lleXP_ort'.

يمكن عكس معنى اسم الخيار عن طريق إضافة `no' قبله، لذا فإن `setopt No_Beep' مكافئة لـ `unsetopt beep'. يمكن إجراء هذا العكس مرة واحدة فقط، لذا فإن `nonobeep' ليست مرادفًا لـ `beep'. وبالمثل، فإن `tify' ليست مرادفًا لـ `nonotify' (عكس `notify').

بعض الخيارات لها أيضًا اسم واحد أو أكثر من أحرف مفردة. هناك مجموعتان من خيارات الأحرف المفردة: واحدة تستخدم افتراضيًا، وأخرى تستخدم لمحاكاة sh/ksh (تستخدم عندما يتم تعيين خيار SH_OPTION_LETTERS). يمكن استخدام خيارات الأحرف المفردة على سطر أوامر shell، أو مع الأوامر المدمجة set، setopt و unsetopt، كخيارات Unix عادية مسبوقة بـ `-'.

يمكن عكس معنى خيارات الأحرف المفردة باستخدام `+' بدلاً من `-'. تشير بعض أسماء خيارات الأحرف المفردة إلى أن الخيار معطل، وفي هذه الحالة يشير عكس هذا الاسم إلى أن الخيار ممكّن. على سبيل المثال، `+n' هو الاسم المختصر لـ `exec'، و `-n' هو الاسم المختصر لعكسه، `noexec'.

في سلاسل خيارات الأحرف المفردة المقدمة إلى shell عند البدء، سيتم تجاهل المسافات البيضاء اللاحقة؛ على سبيل المثال، ستتم معاملة السلسلة `-f ' تمامًا مثل `-f'، ولكن السلسلة `-f i' هي خطأ. هذا لأن العديد من الأنظمة التي تنفذ آلية `#!' لاستدعاء البرامج النصية لا تزيل المسافات البيضاء اللاحقة.

من الممكن تعيين الخيارات ضمن نطاق الدالة. انظر وصف الخيار LOCAL_OPTIONS أدناه.

وصف الخيارات

في القائمة التالية، يتم تمييز الخيارات التي تم تعيينها افتراضيًا في جميع المحاكاة بـ <D>؛؛ تلك التي تم تعيينها افتراضيًا فقط في محاكاة csh، ksh، sh، أو zsh يتم تمييزها بـ <C>، <K>، <S>، <Z> على التوالي. عند سرد الخيارات (بواسطة `setopt'، `unsetopt'، `set -o' أو `set +o')، تظهر تلك التي تم تشغيلها افتراضيًا في القائمة مسبوقة بـ `no'. وبالتالي (ما لم يتم تعيين KSH_OPTION_PRINT)، يعرض `setopt' جميع الخيارات التي تغيرت إعداداتها عن الافتراضي.

تغيير الأدلة

AUTO_CD (-J)
إذا تم إصدار أمر لا يمكن تنفيذه كأمر عادي، وكان الأمر هو اسم دليل، فقم بتنفيذ الأمر cd إلى هذا الدليل. هذا الخيار قابل للتطبيق فقط إذا تم تعيين الخيار SHIN_STDIN، أي إذا كانت الأوامر تُقرأ من الإدخال القياسي. تم تصميم الخيار للاستخدام التفاعلي؛ يوصى باستخدام cd بشكل صريح في البرامج النصية لتجنب الغموض.
AUTO_PUSHD (-N)
اجعل cd يدفع الدليل القديم إلى مكدس الأدلة.
CDABLE_VARS (-T)
إذا كان الوسيط للأمر cd (أو cd ضمني مع تعيين الخيار AUTO_CD) ليس دليلًا، ولا يبدأ بشرطة مائلة، فحاول توسيع التعبير كما لو كان مسبوقًا بـ `~' (انظر القسم `توسيع أسماء الملفات').
CD_SILENT
لا تطبع أبدًا الدليل الحالي بعد cd (سواء كان صريحًا أو ضمنيًا مع تعيين الخيار AUTO_CD). يقوم cd عادةً بطباعة الدليل الحالي عندما يكون الوسيط المعطى له هو -، أو إدخال في المكدس، أو اسم دليل تم العثور عليه ضمن CDPATH. لاحظ أن هذا يختلف عن سلوك طباعة المكدس الخاص بـ pushd، والذي يتم التحكم فيه بواسطة PUSHD_SILENT. هذا الخيار يتجاوز التأثيرات المتعلقة بالطباعة الخاصة بـ POSIX_CD.
CHASE_DOTS
عند التغيير إلى دليل يحتوي على جزء مسار `..' والذي كان سيُعامل بخلاف ذلك كإلغاء للجزء السابق في المسار (بمعنى آخر، ستتم إزالة `foo/..' من المسار، أو إذا كان `..' هو الجزء الأول من المسار، فستتم إزالة الجزء الأخير من الدليل الحالي العامل)، قم بدلاً من ذلك بحل المسار إلى الدليل الفعلي. يتم تجاوز هذا الخيار بواسطة CHASE_LINKS.

على سبيل المثال، افترض أن /foo/bar هو رابط للدليل /alt/rod. بدون تعيين هذا الخيار، يتغير `cd /foo/bar/..' إلى /foo؛ مع تعيينه، يتغير إلى /alt. وينطبق الشيء نفسه إذا كان الدليل الحالي هو /foo/bar وتم استخدام `cd ..'. لاحظ أنه سيتم أيضًا حل جميع الروابط الرمزية الأخرى في المسار.

CHASE_LINKS (-w)
حل الروابط الرمزية إلى قيمها الحقيقية عند تغيير الدليل. هذا له أيضًا تأثير CHASE_DOTS، أي سيتم التعامل مع جزء المسار `..' على أنه يشير إلى الدليل الأصل الفعلي، حتى لو كان جزء المسار السابق رابطًا رمزيًا.
POSIX_CD <K> <S>
يعدل سلوك الأوامر cd، chdir و pushd لجعلها أكثر توافقًا مع معيار POSIX. السلوك مع إلغاء تعيين الخيار موصوف في وثائق الأمر المدمج cd في zshbuiltins(1). إذا تم تعيين الخيار، فلا يقوم shell باختبار الأدلة الموجودة تحت الدليل المحلي (`.') حتى بعد اختبار جميع الأدلة في cdpath، ولا تتعرف الأوامر cd و chdir على الوسائط ذات الشكل `{+|-}n' كإدخالات في مكدس الأدلة.

أيضًا، إذا تم تعيين الخيار، يتم تعديل الظروف التي يطبع فيها shell الدليل الجديد بعد التغيير إليه. لم يعد مقصورًا على shells التفاعلية (على الرغم من أن طباعة مكدس الأدلة باستخدام pushd لا تزال مقصورة على shells التفاعلية)؛ وأي استخدام لمكون من CDPATH، بما في ذلك `.' ولكن باستثناء مكون فارغ يتم التعامل معه بخلاف ذلك على أنه `.'، يتسبب في طباعة الدليل.

PUSHD_IGNORE_DUPS
لا تدفع نسخًا متعددة من نفس الدليل إلى مكدس الأدلة.
PUSHD_MINUS
يتبادل معاني `+' و `-' عند استخدامها مع رقم لتحديد دليل في المكدس.
PUSHD_SILENT (-E)
لا تطبع مكدس الأدلة بعد pushd أو popd.
PUSHD_TO_HOME (-D)
اجعل pushd بدون وسائط يتصرف مثل `pushd $HOME'.

الإكمال

ALWAYS_LAST_PROMPT <D>
إذا تم إلغاء تعيينه، تحاول الوظائف الرئيسية التي تسرد الإكمالات العودة إلى آخر موجه إذا تم إعطاؤها وسيطًا رقميًا. إذا تم تعيينه، تحاول هذه الوظائف العودة إلى آخر موجه إذا تم إعطاؤها وسيطًا رقميًا فارغًا.
ALWAYS_TO_END
إذا تم إجراء إكمال مع المؤشر داخل كلمة، وتم إدراج إكمال كامل، يتم نقل المؤشر إلى نهاية الكلمة. أي أنه يتم نقل المؤشر إلى نهاية الكلمة إذا تم إدراج تطابق واحد أو تم إجراء إكمال قائمة.
AUTO_LIST (-9) <D>
قم بسرد الخيارات تلقائيًا عند إكمال غامض.
AUTO_MENU <D>
استخدم تلقائيًا إكمال القائمة بعد الطلب الثاني المتتالي للإكمال، على سبيل المثال عن طريق الضغط على مفتاح علامة التبويب بشكل متكرر. يتم تجاوز هذا الخيار بواسطة MENU_COMPLETE.
AUTO_NAME_DIRS
أي معامل تم تعيينه للاسم المطلق لدليل يصبح على الفور اسمًا لهذا الدليل، والذي سيتم استخدامه بواسطة تسلسلات الموجه `%~' والتسلسلات ذات الصلة، وسيتم

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

PROMPT_BANG <K>
إذا تم تعيينه، يتم التعامل مع `!' بشكل خاص في توسيع المطالبة. انظر توسيع تسلسلات المطالبة في zshmisc(1).
PROMPT_CR (+V) <D>
اطبع حرف إرجاع سطر قبل طباعة مطالبة في محرر الأسطر. هذا مفعل افتراضياً لأن التحرير متعدد الأسطر ممكن فقط إذا كان المحرر يعرف أين يبدأ السطر.
PROMPT_SP <D>
حاول الحفاظ على سطر جزئي (أي سطر لم ينتهِ بسطر جديد) والذي قد يتم تغطيته بمطالبة الأوامر بسبب الخيار PROMPT_CR. يتم ذلك عن طريق إخراج بعض أحرف التحكم في المؤشر، بما في ذلك سلسلة من المسافات، والتي يجب أن تجعل الجهاز ينقّل إلى السطر التالي عند وجود سطر جزئي (لاحظ أن هذا ينجح فقط إذا كان جهازك يحتوي على هوامش تلقائية، وهو أمر شائع).

عند الحفاظ على سطر جزئي، سترى افتراضيًا حرفًا معكوسًا + عريضًا في نهاية السطر الجزئي: `%' لمستخدم عادي أو `#' للمستخدم الجذر. إذا تم تعيينه، يمكن استخدام المعلمة الخاصة بالصدفة (shell parameter) PROMPT_EOL_MARK لتخصيص كيفية عرض نهايات الأسطر الجزئية.

ملاحظة: إذا لم يتم تعيين الخيار PROMPT_CR، فلن يكون لهذا الخيار أي تأثير. هذا الخيار مفعل افتراضيًا.

PROMPT_PERCENT <C> <Z>
إذا تم تعيينه، يتم التعامل مع `%' بشكل خاص في توسيع المطالبة. انظر توسيع تسلسلات المطالبة في zshmisc(1).
PROMPT_SUBST <K> <S>
إذا تم تعيينه، يتم إجراء توسيع المعلمة و استبدال الأوامر و التوسيع الحسابي في المطالبات. لا تؤثر الاستبدالات داخل المطالبات على حالة الأمر.
TRANSIENT_RPROMPT
إزالة أي مطالبة يمنى من العرض عند قبول سطر الأوامر. قد يكون هذا مفيدًا مع الأجهزة التي تحتوي على طرق نسخ/لصق أخرى.

النصوص البرمجية والوظائف

ALIAS_FUNC_DEF <S>
افتراضيًا، لا تسمح zsh بتعريف الوظائف باستخدام صيغة `اسم ()' إذا تم توسيع الاسم كاسم مستعار (alias): يسبب هذا خطأ. هذا هو السلوك المطلوب عادةً، لأنه بخلاف ذلك، يمكن أن يسبب الجمع بين اسم مستعار ووظيفة بناءً على نفس التعريف مشاكل بسهولة.

عند تعيين هذا الخيار، يمكن استخدام الأسماء المستعارة لتعريف الوظائف.

على سبيل المثال، ضع في اعتبارك التعريفات التالية كما قد تظهر في ملف بدء التشغيل.

alias foo=bar
foo() {
  print This probably does not do what you expect.
}

هنا، يتم توسيع foo كاسم مستعار لـ bar قبل مواجهة ()، لذلك ستكون الوظيفة المعرفة باسم bar. افتراضيًا، هذا خطأ في الوضع الأصلي (native mode). لاحظ أن اقتباس أي جزء من اسم الوظيفة، أو استخدام الكلمة الرئيسية function، يتجنب المشكلة، لذا يوصى به عندما يمكن أن يكون اسم الوظيفة اسمًا مستعارًا أيضًا.

C_BASES
إخراج الأرقام السداسية عشرية بالتنسيق القياسي C، على سبيل المثال `0xFF' بدلاً من `16#FF' المعتاد. إذا تم تعيين الخيار OCTAL_ZEROES أيضًا (وهو ليس افتراضيًا)، فستتم معالجة الأرقام الثمانية بشكل مشابه وبالتالي تظهر كـ `077' بدلاً من `8#77'. لا يؤثر هذا الخيار على اختيار قاعدة الإخراج، ولا على إخراج القواعد بخلاف السداسي عشري والثماني. لاحظ أن هذه التنسيقات ستكون مفهومة عند الإدخال بغض النظر عن تعيين C_BASES.
C_PRECEDENCES
يغير هذا أسبقية عوامل التشغيل الحسابية لتكون أقرب إلى C ولغات البرمجة الأخرى؛ يحتوي قسم تقييم الحساب في zshmisc(1) على قائمة صريحة.
DEBUG_BEFORE_CMD <D>
تشغيل مصيدة DEBUG قبل كل أمر؛ وإلا يتم تشغيله بعد كل أمر. تعيين هذا الخيار يحاكي سلوك ksh 93؛ مع إلغاء تعيين الخيار يكون السلوك هو سلوك ksh 88.
ERR_EXIT (-e, ksh: -e)
إذا كان الأمر له حالة خروج غير صفرية، قم بتنفيذ مصيدة ZERR، إذا تم تعيينها، واخرج. هذا معطل أثناء تشغيل نصوص التهيئة.

يتم تعطيل السلوك أيضًا داخل مصائد DEBUG. في هذه الحالة، يتم معالجة الخيار بشكل خاص: يتم إلغاء تعيينه عند الدخول إلى المصيدة. إذا تم تعيين الخيار DEBUG_BEFORE_CMD، كما هو الحال افتراضيًا، وتم العثور على الخيار ERR_EXIT معينًا عند الخروج، فسيتم تخطي الأمر الذي يتم تنفيذ مصيدة DEBUG من أجله. يتم استعادة الخيار بعد خروج المصيدة.

يتم تجاهل الحالة غير الصفرية في قائمة أوامر تحتوي على && أو || للأوامر التي ليست في نهاية القائمة. وبالتالي

false && true

لا يؤدي إلى الخروج.

الخروج بسبب ERR_EXIT له تفاعلات معينة مع المهام غير المتزامنة المذكورة في قسم المهام في zshmisc(1).

ERR_RETURN
إذا كان للأمر حالة خروج غير صفرية، فارجع فورًا من الدالة المحيطة. المنطق مشابه لمنطق ERR_EXIT، باستثناء أنه يتم تنفيذ عبارة return ضمنية بدلاً من exit. سيؤدي هذا إلى الخروج في المستوى الخارجي للنص البرمجي غير التفاعلي.

عادةً ما يرث هذا الخيار سلوك ERR_EXIT بأن الكود متبوعًا بـ `&&' `||' لا يؤدي إلى العودة. وبالتالي في المثال التالي:

summit || true

لا يتم فرض العودة حيث أن التأثير المجمع له دائمًا حالة عودة صفرية.

ملاحظة. ومع ذلك، إذا كان summit في المثال أعلاه هو نفسه دالة، فإن الكود الموجود داخلها يتم اعتباره بشكل منفصل: قد يفرض العودة من summit (بافتراض أن الخيار لا يزال معينًا داخل summit)، ولكن ليس من السياق المحيط. يختلف هذا السلوك عن ERR_EXIT الذي لا يتأثر بنطاق الدالة.

EVAL_LINENO <Z>
إذا تم تعيينه، يتم تتبع أرقام الأسطر للتعبيرات التي تم تقييمها باستخدام الأمر المدمج eval بشكل منفصل عن البيئة المحيطة. ينطبق هذا على كل من المعلمة LINENO ورقم السطر الذي يتم إخراجه بواسطة تسلسل المطالبة %i. إذا تم تعيين الخيار، فإن تسلسل المطالبة %N سيخرج السلسلة `(eval)` بدلاً من اسم النص البرمجي أو الدالة كمؤشر. (عادةً ما يتم استخدام تسلسلي المطالبة هذين في المعلمة PS4 لإخراجهما عند تعيين الخيار XTRACE.) إذا لم يتم تعيين EVAL_LINENO، فسيتم الاحتفاظ برقم السطر للنص البرمجي أو الدالة المحيطة أثناء التقييم.
EXEC (+n, ksh: +n) <D>
قم بتنفيذ الأوامر. بدون هذا الخيار، تتم قراءة الأوامر والتحقق من أخطاء الصياغة، ولكن لا يتم تنفيذها. لا يمكن إلغاء هذا الخيار في صدفه تفاعلية، باستثناء عندما يتم توفير `-n' للصدفه عند بدء التشغيل.
FUNCTION_ARGZERO <C> <Z>
عند تنفيذ دالة صدفه أو استدعاء نص برمجي، قم بتعيين $0 مؤقتًا إلى اسم الدالة/النص البرمجي. لاحظ أن تبديل FUNCTION_ARGZERO من تشغيل إلى إيقاف (أو إيقاف إلى تشغيل) لا يغير القيمة الحالية لـ $0. يؤثر فقط حالة الدخول إلى الدالة أو النص البرمجي. قارن بـ POSIX_ARGZERO.
LOCAL_LOOPS
عندما لا يكون هذا الخيار معينًا، قد تنتشر آثار أوامر break و continue خارج نطاق الدالة، مما يؤثر على الحلقات في الدوال المستدعية. عند تعيين الخيار في دالة مستدعية، ينتج عن break أو continue التي لا يتم التقاطها داخل دالة مستدعاة (بغض النظر عن تعيين الخيار داخل تلك الدالة) تحذير ويتم إلغاء التأثير.
LOCAL_OPTIONS <K>
إذا تم تعيين هذا الخيار عند نقطة العودة من دالة صدفه، يتم استعادة معظم الخيارات (بما في ذلك هذا الخيار) التي كانت سارية عند الدخول إلى الدالة؛ الخيارات التي لا يتم استعادتها هي PRIVILEGED و RESTRICTED. بخلاف ذلك، يتم استعادة هذا الخيار فقط، وخيارات LOCAL_LOOPS و XTRACE و PRINT_EXIT_VALUE. لذلك، إذا تم إلغاء تعيين هذا الخيار صراحةً بواسطة دالة صدفه، فإن الخيارات الأخرى السارية عند نقطة العودة ستبقى كذلك. يمكن لدالة صدفه أيضًا أن تضمن لنفسها تكوين صدفه معروفًا بصيغة مثل `emulate -L zsh'؛ ينشط -L LOCAL_OPTIONS.
LOCAL_PATTERNS
إذا تم تعيين هذا الخيار عند نقطة العودة من دالة صدفه، يتم استعادة حالة تعطيلات الأنماط، كما تم تعيينها باستخدام الأمر المدمج `disable -p'، إلى ما كانت عليه عند دخول الدالة. سلوك هذا الخيار مشابه لتأثير LOCAL_OPTIONS على الخيارات؛ وبالتالي `emulate -L sh' (أو أي محاكاة أخرى باستخدام الخيار -L) ينشط LOCAL_PATTERNS.
LOCAL_TRAPS <K>
إذا تم تعيين هذا الخيار عند تعيين مصيدة إشارة داخل دالة، فسيتم استعادة الحالة السابقة للمصيدة لتلك الإشارة عند خروج الدالة. لاحظ أن هذا الخيار يجب تعيينه قبل تغيير سلوك المصيدة في دالة؛ على عكس LOCAL_OPTIONS، فإن القيمة عند الخروج من الدالة غير ذات صلة. ومع ذلك، لا يلزم تعيينه قبل أي مصيدة عامة ليتم استعادتها بشكل صحيح بواسطة دالة. على سبيل المثال،
unsetopt localtraps
trap - INT
fn() { setopt localtraps; trap '' INT; sleep 3; }

سيؤدي ذلك إلى استعادة التعامل الطبيعي مع SIGINT بعد خروج الدالة.

MULTI_FUNC_DEF <Z>
السماح بتعريف دوال متعددة دفعة واحدة بالشكل `fn1 fn2...()؛ إذا لم يتم تعيين الخيار، يتسبب هذا في خطأ في التحليل. تعريف الدوال المتعددة باستخدام الكلمة المفتاحية function مسموح به دائمًا. تعريفات الدوال المتعددة ليست شائعة الاستخدام ويمكن أن تسبب أخطاء غامضة.
MULTIOS <Z>
إجراء عمليات tee أو cat ضمنية عند محاولة إعادة توجيه متعددة (انظر القسم 'إعادة التوجيه').
OCTAL_ZEROES <S>
تفسير أي ثابت عددي يبدأ بصفر على أنه ثماني، وفقًا لمعيار IEEE Std 1003.2-1992 (ISO 9945-2:1993). لم يتم تمكين هذا افتراضيًا لأنه يسبب مشاكل في تحليل سلاسل التاريخ والوقت ذات الأصفار البادئة على سبيل المثال.

تسلسلات الأرقام التي تشير إلى قاعدة رقمية مثل المكون `08' في `08#77' يتم تفسيرها دائمًا على أنها عشرية، بغض النظر عن الأصفار البادئة.

PIPE_FAIL
افتراضيًا، عند انتهاء خط الأنابيب، تعكس حالة الخروج المسجلة بواسطة الصدفة والمرتجعة بواسطة متغير الصدفة $? حالة العنصر الأقصى يمينًا في خط الأنابيب. إذا تم تعيين هذا الخيار، فإن حالة الخروج تعكس بدلاً من ذلك حالة العنصر الأقصى يمينًا في خط الأنابيب الذي كان غير صفري، أو صفري إذا خرجت جميع العناصر بحالة صفرية.
SOURCE_TRACE
إذا تم تعيينه، ستعرض zsh رسالة إعلامية تعلن عن اسم كل ملف تقوم بتحميله. تنسيق الإخراج مشابه للخيار XTRACE، مع الرسالة <sourcetrace>. قد يتم تحميل ملف بواسطة الصدفة نفسها عند بدء التشغيل وإيقاف التشغيل (ملفات بدء التشغيل/إيقاف التشغيل) أو باستخدام الأوامر المضمنة `source' و `dot'.
TYPESET_SILENT
إذا تم إلغاء تعيين هذا، فإن تنفيذ أي من أوامر عائلة `typeset' بدون خيارات وقائمة من المعلمات التي ليس لها قيم ليتم تعيينها ولكنها موجودة بالفعل سيعرض قيمة المعلمة. إذا تم تعيين الخيار، فسيتم عرضها فقط عند تحديد المعلمات باستخدام الخيار `-m'. الخيار `-p' متاح سواء تم تعيين الخيار أم لا.
TYPESET_TO_UNSET <K> <S>
عند الإعلان عن معلمة جديدة باستخدام أي من الأوامر المتعلقة بعائلة `typeset'، تظل المعلمة غير معينة إلا وعندما يتم تعيين قيمة لها بشكل صريح، إما في الأمر `typeset' نفسه أو كعبارة تعيين لاحقة.
VERBOSE (-v, ksh: -v)
طباعة أسطر إدخال الصدفة أثناء قراءتها.
XTRACE (-x, ksh: -x)
طباعة الأوامر ومعاملاتها أثناء تنفيذها. يسبق الإخراج قيمة $PS4، ويتم تنسيقه كما هو موضح في قسم EXPANSION OF PROMPT SEQUENCES في zshmisc(1).

محاكاة الصدفة

APPEND_CREATE <K> <S>
ينطبق هذا الخيار فقط عندما يكون NO_CLOBBER (-C) ساري المفعول.

إذا لم يتم تعيين هذا الخيار، ستصدر الصدفة خطأ عند استخدام إعادة توجيه الإلحاق (>>) على ملف غير موجود بالفعل (السلوك التقليدي لـ zsh لـ NO_CLOBBER). إذا تم تعيين الخيار، فلن يصدر أي خطأ (سلوك POSIX).

BASH_REMATCH
عند التعيين، ستؤدي المطابقات التي تم إجراؤها باستخدام عامل التشغيل =~ إلى تعيين المتغير المصفوفة BASH_REMATCH، بدلاً من المتغيرات الافتراضية MATCH و match. سيحتوي العنصر الأول من مصفوفة BASH_REMATCH على النص المطابق بالكامل وستحتوي العناصر اللاحقة على أجزاء مستخرجة. هذا الخيار له معنى أكبر عندما يتم تعيين KSH_ARRAYS أيضًا، بحيث يتم تخزين الجزء المطابق بالكامل في الفهرس 0 ويكون الجزء الفرعي الأول في الفهرس 1. بدون هذا الخيار، يحتوي المتغير MATCH على النص المطابق بالكامل وتحتوي مصفوفة المتغير match على أجزاء فرعية.
BSD_ECHO <S>
اجعل الأمر المضمن echo متوافقًا مع أمر echo(1) الخاص بـ BSD. هذا يعطل تسلسلات الهروب المسبوقة بشرطة مائلة عكسية في سلاسل echo ما لم يتم تحديد الخيار -e.
CONTINUE_ON_ERROR
إذا تم العثور على خطأ فادح (انظر القسم ERRORS في zshmisc(1))، وكان الكود قيد التشغيل في نص برمجي، فستستأنف الصدفة التنفيذ عند العبارة التالية في النص البرمجي على المستوى الأعلى، أي خارج جميع الدوال أو هياكل الصدفة مثل الحلقات والشروط. هذا يحاكي سلوك الصدفات التفاعلية، حيث تعود الصدفة إلى محرر الأسطر لقراءة أمر جديد؛ كان هذا هو السلوك الطبيعي في إصدارات zsh قبل 5.0.1.
CSH_JUNKIE_HISTORY <C>
سيشير مرجع التاريخ بدون محدد حدث دائمًا إلى الأمر السابق. بدون هذا الخيار، يشير مرجع التاريخ هذا إلى نفس الحدث الذي يشير إليه مرجع التاريخ السابق في سطر الأمر الحالي، افتراضيًا إلى الأمر السابق.
CSH_JUNKIE_LOOPS <C>
السماح لجسم الحلقة بأن يكون بالشكل `list; end' بدلاً من `do list; done'.
CSH_JUNKIE_QUOTES <C>
يغير قواعد النص المحاط بعلامات اقتباس فردية ومزدوجة لتتناسب مع csh. تتطلب هذه الأسطر الجديدة المضمنة أن تسبقها شرطة مائلة عكسية؛ الأسطر الجديدة غير المسبوقة بشرطة مائلة عكسية ستسبب رسالة خطأ. في السلاسل المقتبسة مزدوجًا، يصبح من المستحيل الهروب من `$'، ``' أو `"' (و `\' نفسه لم يعد بحاجة إلى الهروب). يتم توسيع استبدالات الأوامر مرة واحدة فقط، ولا يمكن تداخلها.
CSH_NULLCMD <C>
لا تستخدم قيم NULLCMD و READNULLCMD عند تشغيل عمليات إعادة التوجيه بدون أمر. هذا يجعل عمليات إعادة التوجيه هذه تفشل (انظر القسم 'إعادة التوجيه').
KSH_ARRAYS <K> <S>
محاكاة التعامل مع المصفوفات في ksh قدر الإمكان. إذا تم تعيين هذا الخيار، يتم ترقيم عناصر المصفوفة بدءًا من الصفر، وتشير معلمة المصفوفة بدون فهرس إلى العنصر الأول بدلاً من المصفوفة بأكملها، وتتطلب الأقواس المعقوفة لتحديد الفهرس (`${path[2]}' بدلاً من `$path[2]') أو لتطبيق المعدلات على أي معلمة (`${PWD:h}' بدلاً من `$PWD:h').
KSH_AUTOLOAD <K> <S>
محاكاة التحميل التلقائي للدوال في ksh. هذا يعني أنه عند تحميل دالة تلقائيًا، يتم ببساطة تنفيذ الملف المقابل، ويجب أن يقوم بتعريف الدالة بنفسه. (افتراضيًا، يتم تعريف الدالة بمحتويات الملف. ومع ذلك، فإن الحالة الأكثر شيوعًا على غرار ksh - حيث يحتوي الملف على تعريف بسيط للدالة فقط - يتم التعامل معها دائمًا بطريقة متوافقة مع ksh.)
KSH_OPTION_PRINT <K>
يغير طريقة طباعة إعدادات الخيارات: بدلاً من قوائم منفصلة للخيارات المعينة والخيارات غير المعينة، يتم عرض جميع الخيارات، مميزة بـ 'on' إذا كانت في حالة غير افتراضية، و 'off' بخلاف ذلك.
KSH_TYPESET
تم إهمال هذا الخيار الآن: يتم الحصول على تقريب أفضل لسلوك الأصداف الأخرى باستخدام الواجهة الكلمة المحجوزة لـ declare، export، float، integer، local، readonly و typeset. لاحظ أن الخيار يتم تطبيقه فقط عندما لا تكون الواجهة الكلمة المحجوزة قيد الاستخدام.

يغير طريقة معالجة المعاملات لأوامر عائلة typeset، بما في ذلك declare، export، float، integer، local و readonly. بدون هذا الخيار، ستقوم zsh بإجراء تقسيم الكلمات العادي بعد توسيع الأمر والمعلمة في معاملات التعيين؛ معها، لا يحدث تقسيم الكلمات في تلك الحالات.

KSH_ZERO_SUBSCRIPT
يعامل استخدام فهرس بقيمة صفر في تعابير المصفوفة أو السلسلة كمرجع للعنصر الأول، أي العنصر الذي له عادةً الفهرس 1. يتم تجاهله إذا تم تعيين KSH_ARRAYS أيضًا.

إذا لم يتم تعيين هذا الخيار ولا KSH_ARRAYS، فإن الوصول إلى عنصر مصفوفة أو سلسلة بفهرس صفر يعيد عنصرًا أو سلسلة فارغة، بينما تعتبر محاولات تعيين العنصر صفر لمصفوفة أو سلسلة خطأ. ومع ذلك، فإن محاولات تعيين نطاق فهرس صالح بخلاف ذلك والذي يشمل الصفر ستنجح. على سبيل المثال، إذا لم يتم تعيين KSH_ZERO_SUBSCRIPT، فإن

array[0]=(element)

هو خطأ، بينما

array[0,1]=(element)

ليس كذلك وسيستبدل العنصر الأول من المصفوفة.

هذا الخيار للتوافق مع الإصدارات الأقدم من الصدفة ولا يوصى به في التعليمات البرمجية الجديدة.

OPTIONS

Options are interpreted by the shell in the order that they appear on the command line. If the shell is invoked with the -o option, the options specified are interpreted first. Otherwise, the options are interpreted in the order they appear on the command line.

Option Syntax

Options can be specified in two ways:

  • A single letter option is preceded by a single dash (e.g. -i). Multiple single letter options can be strung together after a single dash (e.g. -ix is equivalent to -i -x).
  • A multi-letter option is preceded by two dashes (e.g. --emacs).

Options can also be specified using the built-in setopt and unsetopt commands.

With the exception of the options listed in Single Letter Options section, all options described below may be preceded by no to negate their meaning. For example, -noCLOBBER is equivalent to +C or unsetopt CLOBBER.

NAME

zshoptions — how to specify options

SPECIFYING OPTIONS

A number of shell options may be set to turn features on or off. The
options are described below. Options may be specified in one of the
following ways:

     a) As arguments to the set builtin.
     b) As arguments to the setopt builtin.
     c) As arguments to the unsetopt builtin.
     d) As arguments to the emulate builtin.
     e) As arguments to the shopt builtin.
     f) In the startup files (e.g. ~/.zshenv,
        ~/.zshrc, ~/.zprofile).

The options described in the following sections are those that are
available in the standard shell. Note that some options may only be
available if certain features are enabled at compile time.

DESCRIPTION OF OPTIONS

-a
ALL_EXPORT. If this option is set, then all variables that are created are exported by default.
-b
BEEP. If this option is set, the terminal will beep if a command returns a non-zero exit status.
-c
CLOBBER. If this option is set, the shell will allow the user to overwrite existing files when using redirection. This is the default. If this option is unset, the shell will not allow the user to overwrite existing files when using redirection. This is the default behavior for the Bourne shell.
-d
DUMMY. This option is ignored.
-e
errexit. If this option is set, the shell will exit immediately if a command exits with a non-zero status. This is the default behavior for the Bourne shell.
-f
FILE_FIND. If this option is set, the shell will perform filename expansion in a manner similar to the Bourne shell. This is the default.
-h
HASH_CMDS. If this option is set, the shell will hash the location of all commands that are executed. This is the default.
-i
INTERACTIVE. If this option is set, the shell will be interactive.
-m
MONITOR. If this option is set, the shell will monitor the jobs that are running in the background. This is the default.
-p
PROMPT_SUBST. If this option is set, the shell will perform parameter expansion, command substitution and arithmetic expansion in prompts. This is the default.
-q
IGNORE_EOF. If this option is set, the shell will ignore the end-of-file character. This is the default.
-r
RESTRICTED. If this option is set, the shell will be run in restricted mode.
-s
SH_WORD_SPLIT. If this option is set, the shell will perform word splitting in a manner similar to the Bourne shell. This is the default.
-t
SINGLE_COMMAND. If this option is set, the shell will read and execute only one command.
-u
NO_UNSET. If this option is set, the shell will exit immediately if a variable that is not set is referenced.
-v
VERBOSE. If this option is set, the shell will print each command as it is read.
-x
XTRACE. If this option is set, the shell will print each command that is executed after all substitutions have been performed.

-A
Used by set for setting arrays
-b
Used on the command line to specify end of option processing
-c
Used on the command line to specify a single command
-m
Used by setopt for pattern-matching option setting
-o
Used in all places to allow use of long option names
-s
Used by set to sort positional parameters
