ZSHPARAM(1) General Commands Manual ZSHPARAM(1)

NAME

zshparam - zsh parameters

DESCRIPTION

A parameter has a name, a value, and a number of attributes. A name may be any sequence of alphanumeric characters and underscores, or the single characters `*', `@', `#', `?', `-', `$', or `!'. A parameter whose name begins with an alphanumeric or underscore is also referred to as a variable.

The attributes of a parameter determine the type of its value, often referred to as the parameter type or variable type, and also control other processing that may be applied to the value when it is referenced. The value type may be a scalar (a string, an integer, or a floating point number), an array (indexed numerically), or an associative array (an unordered set of name-value pairs, indexed by name, also referred to as a hash).

Named scalar parameters may have the exported, -x, attribute, to copy them into the process environment, which is then passed from the shell to any new processes that it starts. Exported parameters are called environment variables. The shell also imports environment variables at startup time and automatically marks the corresponding parameters as exported. Some environment variables are not imported for reasons of security or because they would interfere with the correct operation of other shell features.

Parameters may also be special, that is, they have a predetermined meaning to the shell. Special parameters cannot have their type changed or their readonly attribute turned off, and if a special parameter is unset, then later recreated, the special properties will be retained.

To declare the type of a parameter, or to assign a string or numeric value to a scalar parameter, use the typeset builtin.

The value of a scalar parameter may also be assigned by writing:

name=value

In scalar assignment, value is expanded as a single string, in which the elements of arrays are joined together; filename expansion is not performed unless the option GLOB_ASSIGN is set.

When the integer attribute, -i, or a floating point attribute, -E or -F, is set for name, the value is subject to arithmetic evaluation. Furthermore, by replacing `=' with `+=', a parameter can be incremented or appended to. See the section `Array Parameters' and Arithmetic Evaluation (in zshmisc(1)) for additional forms of assignment.

Note that assignment may implicitly change the attributes of a parameter. For example, assigning a number to a variable in arithmetic evaluation may change its type to integer or float, and with GLOB_ASSIGN assigning a pattern to a variable may change its type to an array.

To reference the value of a parameter, write `$name' or `${name}'. See Parameter Expansion in zshexpn(1) for complete details. That section also explains the effect of the difference between scalar and array assignment on parameter expansion.

ARRAY PARAMETERS

To assign an array value, write one of:

set -A name value ...
name=(value ...)
name=([key]=value ...)

If no parameter name exists, an ordinary array parameter is created. If the parameter name exists and is a scalar, it is replaced by a new array.

In the third form, key is an expression that will be evaluated in arithmetic context (in its simplest form, an integer) that gives the index of the element to be assigned with value. In this form any elements not explicitly mentioned that come before the largest index to which a value is assigned are assigned an empty string. The indices may be in any order. Note that this syntax is strict: [ and ]= must not be quoted, and key may not consist of the unquoted string ]=, but is otherwise treated as a simple string. The enhanced forms of subscript expression that may be used when directly subscripting a variable name, described in the section `Array Subscripts' below, are not available.

The syntaxes with and without the explicit key may be mixed. An implicit key is deduced by incrementing the index from the previously assigned element. Note that it is not treated as an error if latter assignments in this form overwrite earlier assignments.

For example, assuming the option KSH_ARRAYS is not set, the following:

array=(one [3]=three four)

causes the array variable array to contain four elements one, an empty string, three and four, in that order.

In the forms where only value is specified, full command line expansion is performed.

In the [key]=value form, both key and value undergo all forms of expansion allowed for single word shell expansions (this does not include filename generation); these are as performed by the parameter expansion flag (e) as described in zshexpn(1). Nested parentheses may surround value and are included as part of the value, which is joined into a plain string; this differs from ksh which allows the values themselves to be arrays. A future version of zsh may support that. To cause the brackets to be interpreted as a character class for filename generation, and therefore to treat the resulting list of files as a set of values, quote the equal sign using any form of quoting. Example:

name=([a-z]'='*)

To append to an array without changing the existing values, use one of the following:

name+=(value ...)
name+=([key]=value ...)

In the second form key may specify an existing index as well as an index off the end of the old array; any existing value is overwritten by value. Also, it is possible to use [key]+=value to append to the existing value at that index.

Within the parentheses on the right hand side of either form of the assignment, newlines and semicolons are treated the same as white space, separating individual values. Any consecutive sequence of such characters has the same effect.

Ordinary array parameters may also be explicitly declared with:

typeset -a name

Associative arrays must be declared before assignment, by using:

typeset -A name

When name refers to an associative array, the list in an assignment is interpreted as alternating keys and values:

set -A name key value ...
name=(key value ...)
name=([key]=value ...)

Note that only one of the two syntaxes above may be used in any given assignment; the forms may not be mixed. This is unlike the case of numerically indexed arrays.

Every key must have a value in this case. Note that this assigns to the entire array, deleting any elements that do not appear in the list. The append syntax may also be used with an associative array:

name+=(key value ...)
name+=([key]=value ...)

This adds a new key/value pair if the key is not already present, and replaces the value for the existing key if it is. In the second form it is also possible to use [key]+=value to append to the existing value at that key. Expansion is performed identically to the corresponding forms for normal arrays, as described above.

To create an empty array (including associative arrays), use one of:

set -A name
name=()

مؤشرات المصفوفات

يمكن تحديد العناصر الفردية للمصفوفة باستخدام مؤشر. يحدد المؤشر بالشكل [exp] العنصر الفردي exp، حيث exp هو تعبير حسابي سيخضع للتوسيع الحسابي كما لو كان محاطًا بـ `$((...))'. تبدأ ترقيم العناصر من 1، ما لم يتم تعيين الخيار KSH_ARRAYS، وفي هذه الحالة يتم ترقيمها من الصفر.

يمكن استخدام المؤشرات داخل أقواس معقوفة تحدد اسم المعلمة، وبالتالي `${foo[2]}' تعادل `$foo[2]'. إذا تم تعيين الخيار KSH_ARRAYS، فإن الشكل ذي الأقواس المعقوفة هو الوحيد الذي يعمل، حيث لا يتم التعامل مع التعبيرات ذات الأقواس المربعة كمؤشرات.

إذا لم يتم تعيين الخيار KSH_ARRAYS، فافتراضيًا، فإن الوصول إلى عنصر مصفوفة بمؤشر يقيم إلى الصفر يعيد سلسلة فارغة، بينما يُعامل محاولة كتابة هذا العنصر كخطأ. للتوافق مع الإصدارات السابقة، يمكن تعيين الخيار KSH_ZERO_SUBSCRIPT لجعل قيم المؤشرات 0 و 1 متكافئة؛ راجع وصف الخيار في zshoptions(1).

يتم استخدام نفس صيغة المؤشرات للمصفوفات الترابطية، باستثناء أنه لا يتم تطبيق توسيع حسابي على exp. ومع ذلك، لا تزال قواعد التحليل للتعبيرات الحسابية تنطبق، مما يؤثر على كيفية حماية بعض الأحرف الخاصة من التفسير. راجع تحليل المؤشرات أدناه للحصول على التفاصيل.

يقوم المؤشر بالشكل `[*]' أو `[@]' بتقييم جميع عناصر المصفوفة؛ لا يوجد فرق بين الاثنين إلا عند ظهورهما داخل علامتي اقتباس مزدوجتين. `"$foo[*]"' تقيم إلى `"$foo[1] $foo[2] ..."'، بينما `"$foo[@]"' تقيم إلى `"$foo[1]" "$foo[2]" ...'. بالنسبة للمصفوفات الترابطية، `[*]' أو `[@]' تقيم إلى جميع القيم، بترتيب غير محدد. لاحظ أن هذا لا يستبدل المفاتيح؛ راجع وثائق علامة `k' ضمن علامات توسيع المعلمات في zshexpn(1) للحصول على تفاصيل كاملة. عندما تتم الإشارة إلى معلمة مصفوفة بالشكل `$name' (بدون مؤشر) فإنها تقيم إلى `$name[*]'، ما لم يتم تعيين الخيار KSH_ARRAYS، وفي هذه الحالة تقيم إلى `${name[0]}' (بالنسبة لمصفوفة ترابطية، هذا يعني قيمة المفتاح `0'، والتي قد لا تكون موجودة حتى لو كانت هناك قيم لمفاتيح أخرى).

يقوم المؤشر بالشكل `[exp1,exp2]' بتحديد جميع العناصر في النطاق exp1 إلى exp2، شاملة. (المصفوفات الترابطية غير مرتبة، وبالتالي لا تدعم النطاقات.) إذا قام أحد المؤشرات بتقييم إلى رقم سالب، مثلاً -n، فسيتم استخدام العنصر الـ n من نهاية المصفوفة. وبالتالي `$foo[-3]' هو العنصر الثالث من نهاية المصفوفة foo، و `$foo[1,-1]' هو نفس `$foo[*]'.

قد يتم إجراء المؤشرات أيضًا على القيم غير المصفوفية، وفي هذه الحالة تحدد المؤشرات سلسلة فرعية لاستخراجها. على سبيل المثال، إذا تم تعيين FOO إلى `foobar'، فإن `echo $FOO[2,5]' يطبع `ooba'. لاحظ أن بعض أشكال المؤشرات الموضحة أدناه تقوم بمطابقة الأنماط، وفي هذه الحالة تمتد السلسلة الفرعية من بداية المطابقة للمؤشر الأول إلى نهاية المطابقة للمؤشر الثاني. على سبيل المثال،

string="abcdefghijklm"
print ${string[(r)d?,(r)h?]}

يطبع `defghi'. هذه تعميم واضح للقاعدة المطابقات ذات الحرف الواحد. للمؤشر الواحد، يتم الرجوع إلى حرف واحد فقط (وليس نطاق الأحرف الذي تغطيه المطابقة).

لاحظ أنه في عمليات السلسلة الفرعية، يتم التعامل مع المؤشر الثاني بشكل مختلف بواسطة علامتي المؤشر r و R: الأولى تأخذ أقصر مطابقة كطول والأخيرة أطول مطابقة. وبالتالي في الحالة الأولى يكون الرمز * في النهاية زائدًا عن الحاجة بينما في الحالة الأخيرة يطابق بقية السلسلة بأكملها. هذا لا يؤثر على نتيجة حالة المؤشر الواحد حيث يكون طول المطابقة هنا غير مهم.

تعيين عناصر المصفوفة

يمكن استخدام المؤشر على الجانب الأيسر من عملية تعيين هكذا:

name[exp]=value

في هذا الشكل من التعيين، يتم استبدال العنصر أو النطاق المحدد بواسطة exp بالتعبير الموجود على الجانب الأيمن. يمكن إنشاء مصفوفة (ولكن ليس مصفوفة ترابطية) عن طريق التعيين لنطاق أو عنصر. المصفوفات لا تتداخل، لذا فإن تعيين قائمة محاطة بأقواس من القيم لعنصر أو نطاق يغير عدد العناصر في المصفوفة، مع إزاحة العناصر الأخرى لاستيعاب القيم الجديدة. (هذا غير مدعوم للمصفوفات الترابطية.)

تعمل هذه الصيغة أيضًا كمعامل لأمر typeset:

typeset "name[exp]"=value

value قد لا يكون قائمة محاطة بأقواس في هذه الحالة؛ لا يمكن إجراء تعيينات لعنصر واحد فقط باستخدام typeset. لاحظ أن علامات الاقتباس ضرورية في هذه الحالة لمنع تفسير الأقواس كعوامل توليد أسماء ملفات. يمكن استخدام المعدل noglob قبل الأمر بدلاً من ذلك.

لحذف عنصر من مصفوفة عادية، قم بتعيين `()' لهذا العنصر. لحذف عنصر من مصفوفة ترابطية، استخدم الأمر unset:

unset "name[exp]"

علامات المؤشر

إذا كان القوس الفاتح، أو الفاصلة في النطاق، في أي تعبير مؤشر متبوعًا مباشرة بقوس فاتح، فإن السلسلة حتى القوس المغلق المطابق تعتبر قائمة من العلامات، كما في `name[(flags)exp]'.

تأخذ العلامات s و n و b معاملًا؛ يتم عرض المحدد أدناه كـ `:'، ولكن يمكن استخدام أي حرف، أو أزواج متطابقة `(...)'، `{...}'، `[...]'، أو `<...>'، ولكن لاحظ أنه يمكن استخدام `<...>' فقط إذا كان المؤشر داخل تعبير مقتبس مزدوج أو استبدال معلمة محاطة بأقواس معقوفة، وإلا فسيتم تفسير التعبير كإعادة توجيه.

العلامات المعروفة حاليًا هي:

w
إذا كانت المعلمة ذات المؤشر عبارة عن قيمة قياسية، فإن هذه العلامة تجعل المؤشرات تعمل على الكلمات بدلاً من الأحرف. الفاصل الافتراضي للكلمات هو المسافة البيضاء. عند دمجها مع العلامة i أو I، يكون التأثير هو إنتاج فهرس الحرف الأول من الكلمة الأولى/الأخيرة التي تطابق النمط المحدد؛ لاحظ أن المطابقة الفاشلة في هذه الحالة تنتج دائمًا 0.
s:string:
هذا يوفر string الذي يفصل الكلمات (للاستخدام مع العلامة w). الحرف المحدد : هو تعسفي؛ انظر أعلاه.
p
تتعرف على نفس تسلسلات الهروب مثل الأمر المضمن print في وسيطة السلسلة للعلامة `s' اللاحقة.
f
إذا كانت المعلمة ذات المؤشر عبارة عن قيمة قياسية، فإن هذه العلامة تجعل المؤشرات تعمل على الأسطر بدلاً من الأحرف، أي مع العناصر المفصولة بأسطر جديدة. هذا اختصار لـ `pws:\n:'.
r
المؤشرات العكسية: إذا تم إعطاء هذه العلامة، يتم اعتبار exp نمطًا والنتيجة هي أول عنصر مصفوفة، سلسلة فرعية، أو كلمة مطابقة (إذا كانت المعلمة مصفوفة، أو إذا كانت قيمة قياسية، أو إذا كانت قيمة قياسية وتم استخدام العلامة `w'، على التوالي). المؤشر المستخدم هو رقم العنصر المطابق، بحيث تكون أزواج المؤشرات مثل `$foo[(r)??,3]' و `$foo[(r)??,(r)f*]' ممكنة إذا لم تكن المعلمة مصفوفة ترابطية. إذا كانت المعلمة مصفوفة ترابطية، تتم مقارنة الجزء القيمي فقط من كل زوج مع النمط، والنتيجة هي تلك القيمة.

إذا فشلت عملية البحث في مصفوفة عادية، فإن البحث يضبط المؤشر على ما بعد نهاية المصفوفة، وبالتالي فإن ${array[(r)pattern]} سيستبدل بالسلسلة الفارغة. وبالتالي يمكن اختبار نجاح البحث باستخدام العلامة (i)، على سبيل المثال (بافتراض أن الخيار KSH_ARRAYS غير نشط):

[[ ${array[(i)pattern]} -le ${#array} ]]

إذا كان KSH_ARRAYS نشطًا، فيجب استبدال -le بـ -lt.

R
مثل `r'، ولكن يعطي المطابقة الأخيرة. بالنسبة للمصفوفات الترابطية، يعطي جميع المطابقات الممكنة. يمكن استخدامه للتعيين لعناصر مصفوفات عادية، ولكن ليس للتعيين للمصفوفات الترابطية. عند الفشل، بالنسبة للمصفوفات العادية يكون التأثير هو إرجاع العنصر المقابل للمؤشر 0؛ هذا فارغ ما لم يتم تفعيل أحد الخيارين KSH_ARRAYS أو KSH_ZERO_SUBSCRIPT.

لاحظ أنه في المؤشرات التي تحتوي على كل من `r' و `R' فإن أحرف النمط نشطة حتى لو تم استبدالها بمعلمة (بغض النظر عن تعيين GLOB_SUBST الذي يتحكم في هذه الميزة في مطابقة الأنماط العادية). يمكن إضافة العلامة `e' لمنع مطابقة الأنماط. بما أن هذه العلامة لا تمنع أشكال الاستبدال الأخرى، فلا يزال يتطلب الحذر؛ استخدام معلمة لتخزين المفتاح له التأثير المطلوب:

key2='original key'
print ${array[(Re)$key2]}
i
مثل `r'، ولكن يعطي فهرس المطابقة بدلاً من ذلك؛ لا يمكن دمج هذا مع معامل ثانٍ. على الجانب الأيسر من التعيين، يتصرف مثل `r'. بالنسبة للمصفوفات الترابطية، تتم مقارنة الجزء المفتاحي لكل زوج مع النمط، والنتيجة هي أول مفتاح مطابق يتم العثور عليه. عند الفشل، يستبدل بطول المصفوفة زائد واحد، كما نوقش تحت وصف `r'، أو السلسلة الفارغة لمصفوفة ترابطية.

ملاحظة: على الرغم من أن `i' يمكن تطبيقه على استبدال قيمة قياسية للعثور على إزاحة سلسلة فرعية، إلا أن النتائج من المحتمل أن تكون مضللة عند البحث داخل استبدالات تعيد سلسلة فارغة، أو عند البحث عن سلسلة فرعية فارغة.

قائمة مفصولة بنقطتين رأسيتين لقواعد بيانات terminfo، والتي تستخدمها مكتبة `terminfo' عندما تكون متوفرة في النظام؛ انظر terminfo(5). يتم استخدام هذا المتغير فقط بواسطة بعض مكتبات الطرفية، وخاصة ncurses؛ انظر terminfo(5) للتحقق من الدعم على نظامك. إذا تم تعيينها، يتسبب هذا في قيام الصدفة بإعادة تهيئة الطرفية، مما يجعل الحل البديل `TERM=$TERM' غير ضروري. لاحظ أنه على عكس المصفوفات الأخرى المفصولة بنقطتين رأسيتين، فإن هذا ليس مرتبطًا بمصفوفة zsh.
TIMEFMT
تنسيق تقارير وقت العملية باستخدام الكلمة المفتاحية time. الافتراضي هو `%J %U user %S system %P cpu %*E total'. يتعرف على تسلسلات الهروب التالية، على الرغم من أنه قد لا يكون بعضها متاحًا على جميع الأنظمة، وقد لا يكون بعضها مفيدًا:
%%
علامة `%'.
%U
ثواني وحدة المعالجة المركزية التي تم قضاؤها في وضع المستخدم.
%S
ثواني وحدة المعالجة المركزية التي تم قضاؤها في وضع النواة.
%E
الوقت المنقضي بالثواني.
%P
نسبة وحدة المعالجة المركزية، محسوبة كـ 100*(%U+%S)/%E.
%W
عدد المرات التي تم فيها تبديل العملية.
%X
متوسط مقدار المساحة النصية (المشتركة) المستخدمة بالكيلوبايت.
%D
متوسط مقدار المساحة (غير المشتركة) للبيانات/المكدس المستخدمة بالكيلوبايت.
%K
إجمالي المساحة المستخدمة (%X+%D) بالكيلوبايت.
%M
الحد الأقصى للذاكرة التي استخدمتها العملية في أي وقت بالكيلوبايت.
%F
عدد أخطاء الصفحة الرئيسية (الصفحة التي تحتاج إلى جلبها من القرص).
%R
عدد أخطاء الصفحة الثانوية.
%I
عدد عمليات الإدخال.
%O
عدد عمليات الإخراج.
%r
عدد رسائل المقبس المستلمة.
%s
عدد رسائل المقبس المرسلة.
%k
عدد الإشارات المستلمة.
%w
عدد تحولات السياق الطوعية (انتظارات).
%c
عدد تحولات السياق غير الطوعية.
%J
اسم هذه المهمة.

يمكن إدخال نجمة بين علامة النسبة المئوية وعلامات تنسيق الوقت (على سبيل المثال، `%*E'); يتسبب هذا في طباعة الوقت بتنسيق `hh:mm:ss.ttt' (الساعات والدقائق تُطبع فقط إذا لم تكن صفرًا). بدلاً من ذلك، يمكن استخدام `m' أو `u' (على سبيل المثال، `%mE') لإنتاج مخرجات الوقت بالمللي ثانية أو الميكرو ثانية، على التوالي.

TMOUT
إذا تم تعيين هذا المتغير على قيمة غير صفرية، فستتلقى الصدفة إشارة ALRM إذا لم يتم إدخال أمر في غضون العدد المحدد من الثواني بعد إصدار مطالبة. إذا كان هناك فخ لـ SIGALRM، فسيتم تنفيذه وسيتم جدولة إنذار جديد باستخدام قيمة المتغير TMOUT بعد تنفيذ الفخ. إذا لم يتم تعيين أي فخ، ولم تكن فترة خمول الطرفية أقل من قيمة المتغير TMOUT، فسيتم إنهاء zsh. بخلاف ذلك، سيتم جدولة إنذار جديد لمدة TMOUT ثانية بعد آخر ضغطة مفتاح.
TMPPREFIX
بادئة مسار سيستخدمها الصدفة لجميع الملفات المؤقتة. لاحظ أن هذا يجب أن يتضمن جزءًا أوليًا لاسم الملف بالإضافة إلى أي أسماء دليل. الافتراضي هو `/tmp/zsh'.
TMPSUFFIX
لاحقة اسم ملف ستستخدمها الصدفة للملفات المؤقتة التي تم إنشاؤها بواسطة عمليات الاستبدال (على سبيل المثال، `=(list)'). لاحظ أن القيمة يجب أن تتضمن نقطة بادئة `.' إذا كان المقصود تفسيرها كامتداد ملف. الافتراضي هو عدم إلحاق أي لاحقة، وبالتالي يجب تعيين هذا المتغير فقط عند الحاجة ثم إلغاء تعيينه مرة أخرى.
WORDCHARS <S>
قائمة بالأحرف غير الأبجدية الرقمية التي تعتبر جزءًا من كلمة بواسطة محرر الأسطر.
ZBEEP
إذا تم تعيينه، فهذه سلسلة من الأحرف، يمكنها استخدام جميع الرموز نفسها مثل الأمر bindkey كما هو موضح في إدخال وحدة zsh/zle في zshmodules(1)، والتي سيتم إخراجها إلى الطرفية بدلاً من إصدار صوت صفير. قد يكون لهذا تأثير مرئي بدلاً من تأثير مسموع؛ على سبيل المثال، السلسلة `\e[?5h\e[?5l' على vt100 أو xterm سيكون لها تأثير وميض الفيديو العكسي تشغيل وإيقاف (إذا كنت تستخدم عادةً الفيديو العكسي، يجب عليك استخدام السلسلة `\e[?5l\e[?5h' بدلاً من ذلك). هذا له الأسبقية على الخيار NOBEEP.
ZDOTDIR
الدليل للبحث فيه عن ملفات بدء تشغيل الصدفة (.zshrc، إلخ)، إذا لم يكن $HOME.
zle_bracketed_paste
تمتلك العديد من محاكيات الطرفية ميزة تسمح للتطبيقات بتحديد متى يتم لصق النص في الطرفية بدلاً من كتابته بشكل طبيعي. بالنسبة لـ ZLE، هذا يعني أنه يمكن إدراج أحرف خاصة مثل علامات الجدولة والأسطر الجديدة بدلاً من استدعاء أوامر المحرر. علاوة على ذلك، يشكل النص الملصق حدث تراجع واحد، وإذا كانت المنطقة نشطة، فسيستبدل النص الملصق المنطقة.

تحتوي هذه المصفوفة ذات العنصرين على تسلسلات هروب الطرفية لتمكين وتعطيل الميزة. يتم استخدام تسلسلات الهروب هذه لتمكين اللصق ذي الأقواس عندما يكون ZLE نشطًا وتعطيله في أوقات أخرى. إلغاء تعيين المتغير له تأثير ضمان بقاء اللصق ذي الأقواس معطلاً.

zle_highlight
مصفوفة تصف السياقات التي يجب على ZLE فيها تمييز النص المدخل. انظر تمييز الأحرف في zshzle(1).
ZLE_LINE_ABORTED
يتم تعيين هذا المتغير بواسطة محرر الأسطر عند حدوث خطأ. يحتوي على السطر الذي كان يتم تحريره عند نقطة الخطأ. يمكن استخدام `print -zr -- $ZLE_LINE_ABORTED' لاستعادة السطر. يتم تذكر السطر الأخير من هذا النوع فقط.
ZLE_REMOVE_SUFFIX_CHARS
ZLE_SPACE_SUFFIX_CHARS
تستخدم هذه المتغيرات بواسطة محرر الأسطر. في ظروف معينة، سيتم إزالة اللواحق (عادةً المسافة أو الشرطة المائلة) التي يضيفها نظام الإكمال تلقائيًا، إما لأن الأمر التالي للمحرر لم يكن حرفًا قابلاً للإدراج، أو لأن الحرف تم تمييزه بحيث يتطلب إزالة اللاحقة.

يمكن أن تحتوي هذه المتغيرات على مجموعات الأحرف التي ستؤدي إلى إزالة اللاحقة. إذا تم تعيين ZLE_REMOVE_SUFFIX_CHARS، فإن تلك الأحرف ستؤدي إلى إزالة اللاحقة؛ إذا تم تعيين ZLE_SPACE_SUFFIX_CHARS، فإن تلك الأحرف ستؤدي إلى إزالة اللاحقة واستبدالها بمسافة.

إذا لم يتم تعيين ZLE_REMOVE_SUFFIX_CHARS، فإن السلوك الافتراضي يعادل:

ZLE_REMOVE_SUFFIX_CHARS=$' \t\n;&|'

إذا تم تعيين ZLE_REMOVE_SUFFIX_CHARS ولكنه فارغ، فلا توجد أحرف لها هذا السلوك. يتمتع ZLE_SPACE_SUFFIX_CHARS بالأسبقية، بحيث:

ZLE_SPACE_SUFFIX_CHARS=$'&|'

يتسبب في أن الأحرف `&' و `|' تزيل اللاحقة ولكن تستبدلها بمسافة.

للتوضيح، لنفترض أن الخيار AUTO_REMOVE_SLASH ساري المفعول وتم إكمال الدليل DIR للتو، مع إضافة /، وبعد ذلك يكتب المستخدم `&'. النتيجة الافتراضية هي `DIR&'. مع تعيين ZLE_REMOVE_SUFFIX_CHARS ولكن بدون تضمين `&'، تكون النتيجة `DIR/&'. مع تعيين ZLE_SPACE_SUFFIX_CHARS لتضمين `&'، تكون النتيجة `DIR &'.

لاحظ أن بعض عمليات الإكمال قد توفر سلوكًا خاصًا بها لإزالة أو استبدال اللواحق والذي يتجاوز القيم الموصوفة هنا. انظر وثائق نظام الإكمال في zshcompsys(1).

ZLE_RPROMPT_INDENT <S>
إذا تم تعيينه، يستخدم لإعطاء المسافة البادئة بين الجانب الأيمن من الموجه الأيمن في محرر الأسطر كما هو محدد بواسطة RPS1 أو RPROMPT والجانب الأيمن من الشاشة. إذا لم يتم تعيينه، يتم استخدام القيمة 1.

عادةً ما يستخدم هذا لتعيين القيمة إلى 0 بحيث يظهر الموجه محاذيًا للجانب الأيمن من الشاشة. هذا ليس الافتراضي لأن العديد من الطرفيات لا تتعامل مع هذا بشكل صحيح، خاصة عندما يظهر الموجه في أقصى اليمين السفلي من الشاشة. الطرفيات الافتراضية الحديثة من المرجح أن تتعامل مع هذه الحالة بشكل صحيح. يلزم بعض التجريب.
