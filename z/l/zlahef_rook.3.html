توثيق الوظيفة/الروتين الفرعي

subroutine zlahef_rook (character uplo, integer n, integer nb, integer kb, complex*16, dimension( lda, * ) a, integer lda, integer, dimension( * ) ipiv, complex*16, dimension( ldw, * ) w, integer ldw, integer info)

الغرض:

!>
!> ZLAHEF_ROOK يقوم بحساب تحليل جزئي لمصفوفة هيرميتية معقدة A باستخدام
!> طريقة التنقيط القطري لـ Bunch-Kaufman () المقيدة. التحليل الجزئي له الشكل:
!>
!> A  =  ( I  U12 ) ( A11  0  ) (  I      0     )  إذا كان UPLO = 'U'، أو:
!>       ( 0  U22 ) (  0   D  ) ( U12**H U22**H )
!>
!> A  =  ( L11  0 ) (  D   0  ) ( L11**H L21**H )  إذا كان UPLO = 'L'
!>       ( L21  I ) (  0  A22 ) (  0      I     )
!>
!> حيث يكون ترتيب D في الحد الأقصى NB. يتم إرجاع الترتيب الفعلي في
!> الوسيط KB، وهو إما NB أو NB-1، أو N إذا كان N <= NB.
!> لاحظ أن U**H تشير إلى منقولة A المعقدة لـ U.
!>
!> ZLAHEF_ROOK هو روتين مساعد يتم استدعاؤه بواسطة ZHETRF_ROOK. يستخدم
!> التعليمات البرمجية المجمعة (استدعاء BLAS المستوى 3) لتحديث المصفوفة الفرعية
!> A11 (إذا كان UPLO = 'U') أو A22 (إذا كان UPLO = 'L').
!>

المعلمات

UPLO 
!>          UPLO هو CHARACTER*1
!>          يحدد ما إذا كان الجزء العلوي أو السفلي المثلثي للمصفوفة
!>          الهيرميتية A مخزنًا:
!>          = 'U':  مثلثي علوي
!>          = 'L':  مثلثي سفلي
!>

N

!>          N هو INTEGER
!>          ترتيب المصفوفة A.  N >= 0.
!>

NB

!>          NB هو INTEGER
!>          الحد الأقصى لعدد الأعمدة في المصفوفة A التي يجب
!>          تحليلها.  يجب أن تكون NB على الأقل 2 للسماح بكتل التنقيط 2x2.
!>

KB

!>          KB هو INTEGER
!>          عدد الأعمدة في A التي تم تحليلها بالفعل.
!>          KB إما NB-1 أو NB، أو N إذا كان N <= NB.
!>

A

!>          A هو مصفوفة COMPLEX*16، البعد (LDA,N)
!>          عند الدخول، المصفوفة الهيرميتية A.  إذا كان UPLO = 'U'، فإن الجزء
!>          العلوي المثلثي من A الذي يصل إلى n x n يحتوي على الجزء
!>          المثلثي العلوي للمصفوفة A، والجزء المثلثي السفلي الصارم
!>          من A لا يتم الرجوع إليه.  إذا كان UPLO = 'L'، فإن الجزء
!>          السفلي المثلثي من A الذي يصل إلى n x n يحتوي على الجزء
!>          المثلثي السفلي للمصفوفة A، والجزء المثلثي العلوي الصارم
!>          من A لا يتم الرجوع إليه.
!>          عند الخروج، تحتوي A على تفاصيل التحليل الجزئي.
!>

LDA

!>          LDA هو INTEGER
!>          البعد الرائد للمصفوفة A.  LDA >= max(1,N).
!>

IPIV

!>          IPIV هو مصفوفة INTEGER، البعد (N)
!>          تفاصيل التبادلات وهيكل كتلة D.
!>
!>          إذا كان UPLO = 'U':
!>             يتم تعيين العناصر KB الأخيرة فقط من IPIV.
!>
!>             إذا كان IPIV(k) > 0، فقد تم تبديل الصفوف والأعمدة k و IPIV(k)
!>             و D(k,k) هي كتلة قطرية 1x1.
!>
!>             إذا كان IPIV(k) < 0 و IPIV(k-1) < 0، فقد تم تبديل الصفوف
!>             والأعمدة k و -IPIV(k) وتم تبديل الصفوف
!>             والأعمدة k-1 و -IPIV(k-1)،
!>             D(k-1:k,k-1:k) هي كتلة قطرية 2x2.
!>
!>          إذا كان UPLO = 'L':
!>             يتم تعيين العناصر KB الأولى فقط من IPIV.
!>
!>             إذا كان IPIV(k) > 0، فقد تم تبديل الصفوف والأعمدة k و IPIV(k)
!>             و D(k,k) هي كتلة قطرية 1x1.
!>
!>             إذا كان IPIV(k) < 0 و IPIV(k+1) < 0، فقد تم تبديل الصفوف
!>             والأعمدة k و -IPIV(k) وتم تبديل الصفوف
!>             والأعمدة k+1 و -IPIV(k+1)،
!>             D(k:k+1,k:k+1) هي كتلة قطرية 2x2.
!>

W

!>          W هي مصفوفة COMPLEX*16، البعد (LDW,NB)
!>

LDW

!>          LDW هو INTEGER
!>          البعد الرائد للمصفوفة W.  LDW >= max(1,N).
!>

INFO

!>          INFO هو INTEGER
!>          = 0: خروج ناجح
!>          > 0: إذا كان INFO = k، فإن D(k,k) تساوي صفرًا تمامًا.  تم
!>               إكمال التحليل، ولكن المصفوفة القطرية D
!>               هي بشكل فريد متفردة.
!>
