توثيق الوظيفة/الروتين الفرعي

subroutine zlahef_rook (character uplo, integer n, integer nb, integer kb, complex*16, dimension( lda, * ) a, integer lda, integer, dimension( * ) ipiv, complex*16, dimension( ldw, * ) w, integer ldw, integer info)

الغرض:

!>
!> ZLAHEF_ROOK تحسب تحليلاً جزئياً لمصفوفة هيرميتية معقدة A باستخدام
!> طريقة التقسيم القطرية المحصورة Bunch-Kaufman (). التحليل الجزئي له الشكل:
!>
!> A  =  ( I  U12 ) ( A11  0  ) (  I      0     )  إذا كان UPLO = 'U'، أو:
!>       ( 0  U22 ) (  0   D  ) ( U12**H U22**H )
!>
!> A  =  ( L11  0 ) (  D   0  ) ( L11**H L21**H )  إذا كان UPLO = 'L'
!>       ( L21  I ) (  0  A22 ) (  0      I     )
!>
!> حيث ترتيب D لا يزيد عن NB. يتم إرجاع الترتيب الفعلي في
!> الوسيط KB، وهو إما NB أو NB-1، أو N إذا كان N <= NB.
!> لاحظ أن U**H يمثل التبديل المترافق لـ U.
!>
!> ZLAHEF_ROOK هو روتين مساعد يتم استدعاؤه بواسطة ZHETRF_ROOK. يستخدم
!> الشفرة المجمعة (استدعاء BLAS من المستوى 3) لتحديث المصفوفة الفرعية
!> A11 (إذا كان UPLO = 'U') أو A22 (إذا كان UPLO = 'L').
!>

المعاملات

UPLO 
!>          UPLO هو CHARACTER*1
!>          يحدد ما إذا كان الجزء العلوي أو السفلي المثلثي للمصفوفة
!>          الهيرميتية A مخزنًا:
!>          = 'U':  مثلثي علوي
!>          = 'L':  مثلثي سفلي
!>

N

!>          N هو INTEGER
!>          ترتيب المصفوفة A.  N >= 0.
!>

NB

!>          NB هو INTEGER
!>          الحد الأقصى لعدد الأعمدة في المصفوفة A التي يجب
!>          تحليلها.  يجب أن يكون NB على الأقل 2 للسماح بكتل المحاور 2x2.
!>

KB

!>          KB هو INTEGER
!>          عدد الأعمدة في A التي تم تحليلها بالفعل.
!>          KB هو إما NB-1 أو NB، أو N إذا كان N <= NB.
!>

A

!>          A هو مصفوفة COMPLEX*16، البعد (LDA,N)
!>          عند الإدخال، المصفوفة الهيرميتية A.  إذا كان UPLO = 'U'، فإن الجزء
!>          المثلثي العلوي NxN الرائد في A يحتوي على الجزء
!>          المثلثي العلوي للمصفوفة A، والجزء المثلثي السفلي الصارم
!>          في A لا تتم الإشارة إليه.  إذا كان UPLO = 'L'، فإن الجزء
!>          المثلثي السفلي N-x-N الرائد في A يحتوي على الجزء
!>          المثلثي السفلي للمصفوفة A، والجزء المثلثي العلوي الصارم
!>          في A لا تتم الإشارة إليه.
!>          عند الخروج، تحتوي A على تفاصيل التحليل الجزئي.
!>

LDA

!>          LDA هو INTEGER
!>          البعد الرائد للمصفوفة A.  LDA >= max(1,N).
!>

IPIV

!>          IPIV هو مصفوفة INTEGER، البعد (N)
!>          تفاصيل التبادلات وهيكل الكتلة لـ D.
!>
!>          إذا كان UPLO = 'U':
!>             يتم تعيين العناصر KB الأخيرة فقط من IPIV.
!>
!>             إذا كان IPIV(k) > 0، فقد تم تبديل الصفوف والأعمدة k و IPIV(k)
!>             وكان D(k,k) كتلة قطرية 1x1.
!>
!>             إذا كان IPIV(k) < 0 و IPIV(k-1) < 0، فقد تم تبديل الصفوف و
!>             الأعمدة k و -IPIV(k) وتم تبديل الصفوف و
!>             الأعمدة k-1 و -IPIV(k-1)،
!>             وكان D(k-1:k,k-1:k) كتلة قطرية 2x2.
!>
!>          إذا كان UPLO = 'L':
!>             يتم تعيين العناصر KB الأولى فقط من IPIV.
!>
!>             إذا كان IPIV(k) > 0، فقد تم تبديل الصفوف والأعمدة k و IPIV(k)
!>             وكان D(k,k) كتلة قطرية 1x1.
!>
!>             إذا كان IPIV(k) < 0 و IPIV(k+1) < 0، فقد تم تبديل الصفوف و
!>             الأعمدة k و -IPIV(k) وتم تبديل الصفوف و
!>             الأعمدة k+1 و -IPIV(k+1)،
!>             وكان D(k:k+1,k:k+1) كتلة قطرية 2x2.
!>

W

!>          W هي مصفوفة COMPLEX*16، البعد (LDW,NB)
!>

LDW

!>          LDW هو INTEGER
!>          البعد الرائد للمصفوفة W.  LDW >= max(1,N).
!>

INFO

!>          INFO هو INTEGER
!>          = 0: خروج ناجح
!>          > 0: إذا كان INFO = k، فإن D(k,k) يساوي صفرًا تمامًا.  تم
!>               إكمال التحليل، ولكن المصفوفة القطرية المجمعة D
!>               غير منفردة تمامًا.
!>
