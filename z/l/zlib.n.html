zlib(n)

zlib(n) أوامر Tcl المضمنة zlib(n)

الاسم

zlib - عمليات الضغط وفك الضغط

الملخص

zlib subcommand arg ...

الوصف

يوفر الأمر zlib الوصول إلى مرافق الضغط والتحقق من المجموع (check-summing) الخاصة بمكتبة Zlib لـ Jean-loup Gailly و Mark Adler. لديه الأوامر الفرعية التالية.

أوامر الضغط الفرعية

zlib compress string ?level?
يعيد بيانات ثنائية مضغوطة بتنسيق zlib من السلسلة الثنائية في string. إذا كانت موجودة، فإن level تحدد مستوى الضغط المراد استخدامه (من 0، وهو غير مضغوط، إلى 9، أقصى ضغط).
zlib decompress string ?bufferSize?
يعيد الإصدار غير المضغوط من البيانات الثنائية المضغوطة الخام في string. إذا كانت موجودة، فإن bufferSize هي تلميح لحجم المخزن المؤقت الذي سيتم استخدامه لاستقبال البيانات.
zlib deflate string ?level?
يعيد بيانات ثنائية مضغوطة خام من السلسلة الثنائية في string. إذا كانت موجودة، فإن level تحدد مستوى الضغط المراد استخدامه (من 0، وهو غير مضغوط، إلى 9، أقصى ضغط).
zlib gunzip string ?-headerVar varName?
يعيد المحتويات غير المضغوطة للسلسلة الثنائية string، والتي يجب أن تكون بتنسيق gzip. إذا تم تحديد -headerVar، قم بتخزين قاموس يصف محتويات رأس gzip في المتغير المسمى varName. المفاتيح الموجودة في القاموس التي قد تكون موجودة هي:
comment
حقل التعليق من الرأس، إذا كان موجودًا.
crc
قيمة منطقية تصف ما إذا كان سيتم حساب CRC للرأس.
filename
حقل اسم الملف من الرأس، إذا كان موجودًا.
os
حقل رمز نوع نظام التشغيل من الرأس (إذا لم يكن القيمة QW غير معروفة). راجع RFC 1952 لمعرفة معنى هذه الرموز.
size
حجم البيانات غير المضغوطة.
time
حقل الوقت من الرأس إذا كان غير صفري، ومن المتوقع أن يكون الوقت الذي تم فيه تعديل الملف المسمى في حقل filename. مناسب للاستخدام مع clock format.
type
نوع البيانات غير المضغوطة (binary أو text) إذا كانت معروفة.
zlib gzip string ?-level level? ?-header dict?
يعيد المحتويات المضغوطة للسلسلة الثنائية string بتنسيق gzip. إذا تم تحديد -level، فإن level يحدد مستوى الضغط المراد استخدامه (من 0، وهو غير مضغوط، إلى 9، أقصى ضغط). إذا تم تحديد -header، فإن dict هو قاموس يحتوي على القيم المستخدمة لرأس gzip. يمكن تعريف المفاتيح التالية:
comment
أضف التعليق المحدد إلى رأس بيانات تنسيق gzip.
crc
قيمة منطقية تحدد ما إذا كان سيتم حساب CRC للرأس. لاحظ أنه إذا كان سيتم تبادل البيانات مع برنامج gzip، فلا ينبغي حساب CRC للرأس.
filename
اسم الملف الذي جاءت منه البيانات المراد ضغطها.
os
رمز نوع نظام التشغيل، والذي يجب أن يكون أحد القيم الموضحة في RFC 1952.
time
الوقت الذي تم فيه تعديل الملف المسمى في مفتاح filename آخر مرة. سيكون هذا بنفس صيغة ما يتم إرجاعه بواسطة clock seconds أو file mtime.
type
نوع البيانات التي يتم ضغطها، وهي binary أو text.
zlib inflate string ?bufferSize?
يعيد الإصدار غير المضغوط من البيانات الثنائية المضغوطة الخام في string. إذا كانت موجودة، فإن bufferSize هي تلميح لحجم المخزن المؤقت الذي سيتم استخدامه لاستقبال البيانات.

أمر القناة الفرعي

zlib push mode channel ?options ...?
يدفع تحويل ضغط أو فك ضغط إلى القناة channel. يمكن إزالة التحويل مرة أخرى باستخدام chan pop. يحدد الوسيط mode نوع التحويل الذي يتم دفعه؛ الأنواع التالية مدعومة:
compress
سيكون التحويل تحويل ضغط ينتج بيانات بتنسيق zlib على channel، والذي يجب أن يكون قابلاً للكتابة.
decompress
سيكون التحويل تحويل فك ضغط يقرأ بيانات بتنسيق zlib من channel، والذي يجب أن يكون قابلاً للقراءة.
deflate
سيكون التحويل تحويل ضغط ينتج بيانات مضغوطة خام على channel، والذي يجب أن يكون قابلاً للكتابة.
gunzip
سيكون التحويل تحويل فك ضغط يقرأ بيانات بتنسيق gzip من channel، والذي يجب أن يكون قابلاً للقراءة.
gzip
سيكون التحويل تحويل ضغط ينتج بيانات بتنسيق gzip على channel، والذي يجب أن يكون قابلاً للكتابة.
inflate
سيكون التحويل تحويل فك ضغط يقرأ بيانات مضغوطة خام من channel، والذي يجب أن يكون قابلاً للقراءة.

يمكن تعيين الخيارات التالية عند إنشاء تحويل عبر "options ..." لأمر zlib push:

-dictionary binData
يعين القاموس الذي سيتم استخدامه عند العمل مع ضغط أو فك ضغط البيانات ليكون binData. غير صالح للتحويلات التي تعمل مع بيانات بتنسيق gzip. يجب أن تتكون القاموس من سلاسل (تسلسلات بايت) من المرجح العثور عليها لاحقًا في البيانات المراد ضغطها، مع وضع السلاسل الأكثر استخدامًا في نهاية القاموس. لا يوفر Tcl آلية لاختيار قاموس جيد لم تسلسل بيانات معين.
-header dictionary
يمرر وصفًا لرأس gzip لإنشائه، بنفس التنسيق الذي يفهمه zlib gzip.
-level compressionLevel
مدى صعوبة ضغط البيانات. يجب أن يكون عددًا صحيحًا من 0 (غير مضغوط) إلى 9 (أقصى ضغط).
-limit readaheadLimit
الحد الأقصى لعدد البايتات التي يجب قراءتها مسبقًا عند فك الضغط.

أصبح هذا الخيار غير ذي صلة. تم تقديمه في الأصل لمنع Tcl من القراءة بما يتجاوز نهاية تيار مضغوط في قنوات متعددة التيارات لضمان ترك البيانات اللاحقة دون تغيير لمزيد من القراءة، على حساب السرعة.

يقوم Tcl الآن تلقائيًا بإعادة أي بايتات قرأها بما يتجاوز نهاية تيار مضغوط إلى القناة، مما يجعلها تبدو كأنها غير مقروءة للقراء اللاحقين.

تضيف تحويلات قنوات الضغط وفك الضغط خيارات تكوين إضافية يمكن الوصول إليها من خلال chan configure. الخيارات هي:

checksum
يحدد ما إذا كان سيتم حساب CRC للبيانات عند إخراجها من التحويل. يتمتع هذا الخيار بقيم true و false. افتراضيًا، يتم حسابه.

أمثلة

    # Compress some data
    set compressed [zlib gzip $data]
    # Decompress it again
    set original [zlib gunzip $compressed]

    # Compress data using a custom header
    set data "some binary data"
    set header [dict create filename "mydata.bin" comment "This is a test"]
    set compressed [zlib gzip $data -header $header]

    # Create a compressing channel
    set outfile [open "compressed.dat" "wb"]
    zlib push $outfile gzip -level 6
    puts $outfile $data
    close $outfile

    # Create a decompressing channel
    set infile [open "compressed.dat" "rb"]
    zlib push $infile gunzip
    set original [read $infile]
    close $infile
