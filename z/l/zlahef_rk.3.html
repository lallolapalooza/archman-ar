ZLAHEF_RK تحسب تحليلاً جزئيًا لمصفوفة هيرميتية معقدة غير محددة باستخدام طريقة التنقيط القطري لـ Bunch-Kaufman (rook) المقيد.

الغرض:

!> ZLAHEF_RK تحسب تحليلاً جزئيًا لمصفوفة هيرميتية معقدة A باستخدام
!> طريقة التنقيط القطري المقيد لـ Bunch-Kaufman (rook). التحليل الجزئي له الصيغة:
!>
!> A  =  ( I  U12 ) ( A11  0  ) (  I       0    )  إذا كان UPLO = 'U'، أو:
!>       ( 0  U22 ) (  0   D  ) ( U12**H U22**H )
!>
!> A  =  ( L11  0 ) (  D   0  ) ( L11**H L21**H )  إذا كان UPLO = 'L'،
!>       ( L21  I ) (  0  A22 ) (  0       I    )
!>
!> حيث رتبة D لا تتجاوز NB. الرتبة الفعلية تُعاد في المعامل KB، وتكون إما NB أو NB-1، أو N إذا كان N <= NB.
!>
!> ZLAHEF_RK هو إجراء مساعد يتم استدعاؤه بواسطة ZHETRF_RK. يستخدم
!> التعليمات البرمجية المجمعة (استدعاء BLAS المستوى 3) لتحديث المصفوفة الفرعية
!> A11 (إذا كان UPLO = 'U') أو A22 (إذا كان UPLO = 'L').
!>

المعاملات

UPLO 
!>          UPLO هو CHARACTER*1
!>          يحدد ما إذا كان الجزء المثلثي العلوي أو السفلي من المصفوفة الهيرميتية A مخزنًا:
!>          = 'U':  مثلثي علوي
!>          = 'L':  مثلثي سفلي
!>

N

!>          N هو INTEGER
!>          رتبة المصفوفة A.  N >= 0.
!>

NB

!>          NB هو INTEGER
!>          الحد الأقصى لعدد أعمدة المصفوفة A التي يجب تحليلها.
!>          يجب أن تكون NB على الأقل 2 للسماح بكتل التنقيط 2x2.
!>

KB

!>          KB هو INTEGER
!>          عدد أعمدة A التي تم تحليلها فعليًا.
!>          KB هي إما NB-1 أو NB، أو N إذا كان N <= NB.
!>

A

!>          A هو مصفوفة COMPLEX*16، أبعادها (LDA,N)
!>          عند الدخول، المصفوفة الهيرميتية A.
!>            إذا كان UPLO = 'U': الجزء العلوي المثلثي الذي طوله N في N من A يحتوي على الجزء العلوي المثلثي للمصفوفة A،
!>            والجزء السفلي المثلثي الصارم لـ A غير مستخدم.
!>
!>            إذا كان UPLO = 'L': الجزء السفلي المثلثي الذي طوله N في N من A يحتوي على الجزء السفلي المثلثي للمصفوفة A،
!>            والجزء العلوي المثلثي الصارم لـ A غير مستخدم.
!>
!>          عند الخروج، تحتوي على:
!>            أ) عناصر القطر فقط للمصفوفة القطرية الهيرميتية المجمعة D على قطر A، أي D(k,k) = A(k,k)؛
!>               (العناصر فوق القطرية (أو تحت القطرية) لـ D مخزنة عند الخروج في المصفوفة E)، و
!>            ب) إذا كان UPLO = 'U': العامل U في الجزء فوق القطري لـ A.
!>               إذا كان UPLO = 'L': العامل L في الجزء تحت القطري لـ A.
!>

LDA

!>          LDA هو INTEGER
!>          البعد الرائد للمصفوفة A.  LDA >= max(1,N).
!>

E

!>          E هي مصفوفة COMPLEX*16، أبعادها (N)
!>          عند الخروج، تحتوي على العناصر فوق القطرية (أو تحت القطرية)
!>          للمصفوفة القطرية الهيرميتية المجمعة D
!>          بكتل قطرية 1x1 أو 2x2، حيث:
!>          إذا كان UPLO = 'U': E(i) = D(i-1,i)، i=2:N، E(1) مضبوط على 0؛
!>          إذا كان UPLO = 'L': E(i) = D(i+1,i)، i=1:N-1، E(N) مضبوط على 0.
!>
!>          ملاحظة: بالنسبة لكتلة قطرية 1x1 D(k)، حيث
!>          1 <= k <= N، يتم ضبط العنصر E(k) على 0 في كل من
!>          حالات UPLO = 'U' أو UPLO = 'L'.
!>

IPIV

!>          IPIV هي مصفوفة INTEGER، أبعادها (N)
!>          تصف IPIV مصفوفة التبديل P في تحليل المصفوفة A كالتالي. القيمة المطلقة لـ IPIV(k)
!>          تمثل فهرس الصف والعمود اللذين تم تبديلهما مع الصف والعمود k. قيمة UPLO
!>          تصف ترتيب تطبيق التبادلات.
!>          أيضًا، علامة IPIV تمثل البنية المجمعة
!>          للمصفوفة القطرية الهيرميتية المجمعة D بكتل قطرية 1x1 أو 2x2
!>          التي تتوافق مع تبادلات 1 أو 2
!>          في كل خطوة تحليل.
!>
!>          إذا كان UPLO = 'U'،
!>          (في ترتيب التحليل، k ينقص من N إلى 1):
!>            أ) إدخال موجب فردي IPIV(k) > 0 يعني:
!>               D(k,k) هي كتلة قطرية 1x1.
!>               إذا كان IPIV(k) != k، تم تبديل الصفوف والأعمدة k و IPIV(k)
!>               في المصفوفة الفرعية A(1:N,N-KB+1:N)؛
!>               إذا كان IPIV(k) = k، لم يحدث تبديل.
!>
!>
!>            ب) زوج من الإدخالات المتتالية السالبة
!>               IPIV(k) < 0 و IPIV(k-1) < 0 يعني:
!>               D(k-1:k,k-1:k) هي كتلة قطرية 2x2.
!>               (ملاحظة: الإدخالات السالبة في IPIV تظهر فقط في أزواج).
!>               1) إذا كان -IPIV(k) != k، تم تبديل الصفوف والأعمدة
!>                  k و -IPIV(k)
!>                  في المصفوفة A(1:N,N-KB+1:N).
!>                  إذا كان -IPIV(k) = k، لم يحدث تبديل.
!>               2) إذا كان -IPIV(k-1) != k-1، تم تبديل الصفوف والأعمدة
!>                  k-1 و -IPIV(k-1)
!>                  في المصفوفة الفرعية A(1:N,N-KB+1:N).
!>                  إذا كان -IPIV(k-1) = k-1، لم يحدث تبديل.
!>
!>            ج) في كلتا الحالتين أ) وب) يكون دائمًا ABS( IPIV(k) ) <= k.
!>
!>            د) ملاحظة: أي إدخال IPIV(k) يكون دائمًا غير صفري عند الخروج.
!>
!>          إذا كان UPLO = 'L'،
!>          (في ترتيب التحليل، k يزداد من 1 إلى N):
!>            أ) إدخال موجب فردي IPIV(k) > 0 يعني:
!>               D(k,k) هي كتلة قطرية 1x1.
!>               إذا كان IPIV(k) != k، تم تبديل الصفوف والأعمدة k و IPIV(k)
!>               في المصفوفة الفرعية A(1:N,1:KB).
!>               إذا كان IPIV(k) = k، لم يحدث تبديل.
!>
!>            ب) زوج من الإدخالات المتتالية السالبة
!>               IPIV(k) < 0 و IPIV(k+1) < 0 يعني:
!>               D(k:k+1,k:k+1) هي كتلة قطرية 2x2.
!>               (ملاحظة: الإدخالات السالبة في IPIV تظهر فقط في أزواج).
!>               1) إذا كان -IPIV(k) != k، تم تبديل الصفوف والأعمدة
!>                  k و -IPIV(k)
!>                  في المصفوفة الفرعية A(1:N,1:KB).
!>                  إذا كان -IPIV(k) = k، لم يحدث تبديل.
!>               2) إذا كان -IPIV(k+1) != k+1، تم تبديل الصفوف والأعمدة
!>                  k-1 و -IPIV(k-1)
!>                  في المصفوفة الفرعية A(1:N,1:KB).
!>                  إذا كان -IPIV(k+1) = k+1، لم يحدث تبديل.
!>
!>            ج) في كلتا الحالتين أ) وب) يكون دائمًا ABS( IPIV(k) ) >= k.
!>
!>            د) ملاحظة: أي إدخال IPIV(k) يكون دائمًا غير صفري عند الخروج.
!>

W

!>          W هي مصفوفة COMPLEX*16، أبعادها (LDW,NB)
!>

LDW

!>          LDW هو INTEGER
!>          البعد الرائد للمصفوفة W.  LDW >= max(1,N).
!>

INFO

!>          INFO هو INTEGER
!>          = 0: خروج ناجح
!>
!>          < 0: إذا كان INFO = -k، فإن المعامل k كان له قيمة غير قانونية
!>
!>          > 0: إذا كان INFO = k، فإن المصفوفة A مفردة، بسبب:
!>                 إذا كان UPLO = 'U': العمود k في الجزء
!>                 المثلثي العلوي من A يحتوي على جميع الأصفار.
!>                 إذا كان UPLO = 'L': العمود k في الجزء
!>                 المثلثي السفلي من A يحتوي على جميع الأصفار.
!>
!>               لذلك D(k,k) هو صفر بالضبط، وعناصر ما فوق القطر
!>               للعمود k من U (أو عناصر ما تحت القطر
!>               للعمود k من L)
!>

NAME

zlahef_rk - high level interface for the unbiased solution of a linear matrix equation

SYNOPSIS

 SUBROUTINE ZLAHEF_RK(
     &           UPLO, TRANS, EQUED, N, NRHS, A, LDA, AF, LDAF, IPIV,
     &           Q, LDQ, WORK, RWORK, INFO
     &           )
    CHARACTER * 1 :: UPLO, TRANS, EQUED
    INTEGER :: N, NRHS, LDA, LDAF, LDQ, INFO
    INTEGER :: IPIV( * )
    COMPLEX*16 :: A( * ), AF( * ), Q( * ), WORK( * )
    DOUBLE PRECISION :: RWORK( * )

Function/Subroutine Documentation

This routine is part of the LAPACK routines that compute the solution to a linear matrix equation.

The purpose of this routine is to provide a high-level interface for the unbiased solution of a linear matrix equation. It first checks if the input matrix A is well-conditioned. If it is, the routine proceeds to compute the factorization and then the solution.

The routine uses a block version of the Roberts-Kailath (RK) factorization, which is a variant of the Roberts factorization designed for improved numerical stability. The RK factorization decomposes a matrix A into the form:

A = P * K * F

where P is a permutation matrix, K is an upper triangular matrix, and F is a unit upper triangular matrix. The factorization is performed in place on the matrix A.

The routine also handles potential singularity issues. If the matrix is found to be singular during the factorization, the INFO parameter will be set to a non-zero value, indicating the position of the singularity. If a singularity is detected, the factorization still completes, but the block diagonal matrix D may be exactly singular. Division by zero might occur if this singular D is used to solve a system of equations.

The INFO parameter stores only the first occurrence of a singularity. Subsequent occurrences are not stored in INFO, even though the factorization always completes.
