ZMQ_PULL

يُستخدم مقبس من النوع ZMQ_PULL بواسطة عقدة خط أنابيب لاستقبال الرسائل من عقد خط الأنابيب المتصلة سابقًا. يتم توزيع الرسائل بشكل عادل من بين جميع عقد خط الأنابيب المتصلة سابقًا. لا يتم تنفيذ وظيفة zmq_send() لهذا النوع من المقابس.

نمط التوزيع والجمع

نمط التوزيع والجمع هو النسخة الآمنة من نمط خط الأنابيب. يستخدم نمط التوزيع والجمع لتوزيع البيانات على العقد المرتبة في خط أنابيب. تتدفق البيانات دائمًا لأسفل خط الأنابيب، وكل مرحلة من مراحل خط الأنابيب متصلة بـ عقدة واحدة على الأقل. عندما يتم توصيل مرحلة خط الأنابيب بـ عقد متعددة، يتم توزيع البيانات بالتناوب بين جميع العقد المتصلة.
ZMQ_SCATTER
^^^^^^^^
يُستخدم مقبس من نوع 'ZMQ_SCATTER' بواسطة عقدة التوزيع والجمع لإرسال رسائل إلى عقد التوزيع والجمع المتصلة لاحقًا. يتم توزيع الرسائل بالتناوب إلى جميع العقد المتصلة لاحقًا. لا يتم تنفيذ وظيفة _zmq_recv()_ لهذا النوع من المقابس.
عندما يدخل مقبس 'ZMQ_SCATTER' في حالة 'الكتم' بسبب وصوله إلى علامة التدفق العالي لجميع العقد المتصلة لاحقًا، أو، بالنسبة لبروتوكولات النقل الموجهة بالاتصال، إذا تم تعيين الخيار ZMQ_IMMEDIATE ولم تكن هناك عقد متصلة لاحقًا على الإطلاق، فإن أي عمليات linkzmq:zmq_send[3] على المقبس يجب أن يتم حظرها حتى تنتهي حالة الكتم أو تصبح عقدة واحدة على الأقل متصلة لاحقًا متاحة للإرسال؛ لا يتم تجاهل الرسائل.
ملاحظة: مقابس 'ZMQ_SCATTER' آمنة من حيث تعدد الخيوط. لا تقبل ZMQ_RCVMORE في عمليات الاستقبال. هذا يحدها إلى بيانات من جزء واحد.

نمط الزوج الحصري

يُستخدم نمط الزوج الحصري لتوصيل نظير بنظير آخر بالضبط. يستخدم هذا النمط للاتصال بين الخيوط عبر بروتوكول النقل inproc.

يتم تعريف نمط الزوج الحصري رسميًا بواسطة http://rfc.zeromq.org/spec:31.

ZMQ_PAIR

يمكن توصيل مقبس من النوع ZMQ_PAIR بنظير واحد فقط في أي وقت. لا يتم إجراء أي توجيه أو تصفية للرسائل على الرسائل المرسلة عبر مقبس ZMQ_PAIR.

عندما يدخل مقبس ZMQ_PAIR في حالة الكتم بسبب وصوله إلى علامة التدفق العالي للنظير المتصل، أو، بالنسبة لبروتوكولات النقل الموجهة بالاتصال، إذا تم تعيين الخيار ZMQ_IMMEDIATE ولم يكن هناك نظير متصل، فإن أي عمليات zmq_send(3) على المقبس يجب أن يتم حظرها حتى يصبح النظير متاحًا للإرسال؛ لا يتم تجاهل الرسائل.

في حين أنه يمكن استخدام مقابس ZMQ_PAIR عبر بروتوكولات نقل أخرى غير zmq_inproc(7)، فإن عدم قدرتها على إعادة الاتصال تلقائيًا، بالإضافة إلى حقيقة أن الاتصالات الواردة الجديدة سيتم إنهاؤها بينما توجد أي اتصالات سابقة (بما في ذلك تلك التي في حالة إغلاق)، تجعلها غير مناسبة لـ TCP في معظم الحالات.


ملاحظة

تم تصميم مقابس ZMQ_PAIR للاتصال بين الخيوط عبر بروتوكول النقل zmq_inproc(7) ولا تنفذ وظائف مثل إعادة الاتصال التلقائي.

نمط نظير إلى نظير

يُستخدم نمط نظير إلى نظير لتوصيل نظير بعدة نظراء. يمكن للنظير الاتصال والربط، وخلط كليهما بنفس المقبس. نمط نظير إلى نظير مفيد لبناء شبكات نظير إلى نظير (مثل zyre، bitcoin، torrent) حيث يمكن للنظير قبول اتصالات من نظراء آخرين أو الاتصال بهم.


ملاحظة

لا يزال نمط نظير إلى نظير في مرحلة المسودة.

ZMQ_PEER

يتواصل مقبس ZMQ_PEER مع مجموعة من مقابس ZMQ_PEER.

للاتصال وجلب معرف التوجيه للنظير، استخدم zmq_connect_peer(3).

كل رسالة مستلمة لها معرف توجيه وهو عدد صحيح غير مؤشر بحجم 32 بت. يمكن للتطبيق استرداد هذا باستخدام zmq_msg_routing_id(3).

لإرسال رسالة إلى نظير ZMQ_PEER معين، يجب على التطبيق تعيين معرف التوجيه للنظير على الرسالة، باستخدام zmq_msg_set_routing_id(3).

إذا لم يتم تحديد معرف التوجيه، أو لم يشير إلى نظير عميل متصل، فسيفشل استدعاء الإرسال مع EHOSTUNREACH. إذا كان مخزن الإرسال المؤقت للنظير ممتلئًا، فيجب أن يتم حظر استدعاء الإرسال، ما لم يتم استخدام ZMQ_DONTWAIT في الإرسال، وفي هذه الحالة سيفشل مع EAGAIN. لن يقوم مقبس ZMQ_PEER بتجاهل الرسائل في أي حال.


ملاحظة

مقابس ZMQ_PEER آمنة من حيث تعدد الخيوط. لا تقبل خيار ZMQ_SNDMORE في عمليات الإرسال ولا ZMQ_RCVMORE في عمليات الاستقبال. هذا يحدها إلى بيانات من جزء واحد.

النمط الأصلي

يُستخدم النمط الأصلي للتواصل مع نظراء TCP ويسمح بالطلبات والاستجابات غير المتزامنة في أي من الاتجاهين.

ZMQ_STREAM

يُستخدم مقبس من النوع ZMQ_STREAM لإرسال واستقبال بيانات TCP من نظير غير 0MQ، عند استخدام بروتوكول النقل tcp://. يمكن لمقبس ZMQ_STREAM أن يعمل كعميل و/أو خادم، ويرسل و/أو يستقبل بيانات TCP بشكل غير متزامن.

عند استقبال بيانات TCP، سيقوم مقبس ZMQ_STREAM بإضافة جزء رسالة يحتوي على معرف التوجيه للنظير المصدر قبل تمريره إلى التطبيق. يتم توزيع الرسائل المستلمة بشكل عادل من بين جميع النظراء المتصلين.

عند إرسال بيانات TCP، سيقوم مقبس ZMQ_STREAM بإزالة الجزء الأول من الرسالة واستخدامه لتحديد معرف التوجيه للنظير الذي سيتم توجيه الرسالة إليه، وستؤدي الرسائل غير القابلة للتوجيه إلى خطأ EHOSTUNREACH أو EAGAIN.

zmq_socket(3)

الحزمة: zeromq

التراخيص: MPL2

NAME

zmq_socket — create a ZeroMQ socket of a specific type

SYNOPSIS

                    void *zmq_socket (void *context, int type);

DESCRIPTION

The zmq_socket function shall create and return a new socket associated with the specified context and of the specified type.

The type argument specifies the socket type and shall be one of the following constants:

ZMQ_REQ — Asynchronous client socket. ZMQ_REQ sockets are used to send requests and receive replies. ZMQ_REQ sockets must be used in conjunction with ZMQ_REP sockets.

ZMQ_REP — Asynchronous server socket. ZMQ_REP sockets are used to receive requests and send replies. ZMQ_REP sockets must be used in conjunction with ZMQ_REQ sockets.

ZMQ_DEALER — Untyped socket. ZMQ_DEALER sockets are used for asynchronous request-reply communication. They are similar to ZMQ_REQ and ZMQ_REP sockets, but they do not enforce any specific message sequencing.

ZMQ_ROUTER — Untyped socket. ZMQ_ROUTER sockets are used for asynchronous request-reply communication. They are similar to ZMQ_REQ and ZMQ_REP sockets, but they do not enforce any specific message sequencing.

ZMQ_PUB — Publish socket. ZMQ_PUB sockets are used to publish messages to multiple subscribers. ZMQ_PUB sockets must be used in conjunction with ZMQ_SUB sockets.

ZMQ_SUB — Subscribe socket. ZMQ_SUB sockets are used to subscribe to messages published by ZMQ_PUB sockets.

ZMQ_PUSH — Forward socket. ZMQ_PUSH sockets are used to send messages to multiple peers in a pipeline. ZMQ_PUSH sockets must be used in conjunction with ZMQ_PULL sockets.

ZMQ_PULL — Pull socket. ZMQ_PULL sockets are used to receive messages from multiple peers in a pipeline. ZMQ_PULL sockets must be used in conjunction with ZMQ_PUSH sockets.

ZMQ_PAIR — Pair socket. ZMQ_PAIR sockets are used for simple, unidirectional communication between two peers. ZMQ_PAIR sockets can only be used in pairs.

ZMQ_STREAM — Stream socket. ZMQ_STREAM sockets are used for bidirectional communication with multiple peers. They are similar to ZMQ_REQ and ZMQ_REP sockets, but they do not enforce any specific message sequencing.

RETURN VALUE

The zmq_socket function shall return a pointer to the created socket if the call is successful. Otherwise, it shall return NULL and set errno to one of the values listed below.

ERRORS

EINVAL — The provided context is invalid or the provided type is not a valid socket type.

EMFILE — EMFILE — Maximum file descriptor number reached.

ENFILE — ENFILE — Maximum number of open files reached.

ENODEV — ENODEV — The operating system does not support the requested socket type.

ENOMEM — ENOMEM — Insufficient memory to create the socket.

ENOTSOCK — ENOTSOCK — The provided context is not a valid context.

EXAMPLE

Example usage of zmq_socket:

#include <zmq.h>
#include <stdio.h>
#include <assert.h>
#include <string.h>

int main (void) {
        void *ctx = zmq_ctx_new ();
        void *socket = zmq_socket (ctx, ZMQ_REP);
        assert (socket);

        /* ... use the socket ... */

        zmq_close (socket);
        zmq_ctx_destroy (ctx);
        return 0;
}

The following example demonstrates a simple request-reply scenario where a server receives a request and sends a reply.

/*  Get HTTP request; routing id frame and then request */
        routing_id_size = zmq_recv (socket, routing_id, 256, 0);
        assert (routing_id_size > 0);
        do {
                raw_size = zmq_recv (socket, raw, 256, 0);
                assert (raw_size >= 0);
        } while (raw_size == 256);
        /* Prepares the response */
        char http_response [] =
                "HTTP/1.0 200 OK\r\n"
                "Content-Type: text/plain\r\n"
                "\r\n"
                "Hello, World!";
        /* Sends the routing id frame followed by the response */
        zmq_send (socket, routing_id, routing_id_size, ZMQ_SNDMORE);
        zmq_send (socket, http_response, strlen (http_response), 0);
        /* Closes the connection by sending the routing id frame followed by a zero response */
        zmq_send (socket, routing_id, routing_id_size, ZMQ_SNDMORE);
        zmq_send (socket, 0, 0, 0);
}
zmq_close (socket);
zmq_ctx_destroy (ctx);
