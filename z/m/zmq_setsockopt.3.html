الحزمة: zeromq

التراخيص: MPL2

ZMQ_ROUTING_ID: Set socket identity

Set the identity of the socket. The identity is a sequence of octets, at most 255 octets long. When using the ZMQ_ROUTER socket type, the identity is prepended to all messages sent by the socket. When using the ZMQ_DEALER socket type, the identity is appended to all messages sent by the socket. The identity is used to establish a named connection to a socket at the other end of a connection-oriented transport.

Option value type binary data
Option value unit N/A
Default value not set
Applicable socket types ZMQ_ROUTER, ZMQ_DEALER, ZMQ_STREAM

ZMQ_ROUTER_HANDOVER: Enable router handover

When set to 1, the ZMQ_ROUTER socket will hand over incoming connections to newly created sockets of the same type bound to the same endpoint. This is useful for dynamic updates of applications.

Option value type int
Option value unit 0, 1
Default value 0 (false)
Applicable socket types ZMQ_ROUTER

ZMQ_ROUTER_NOTIFY: Enable router notification on new connections

When set to 1, the ZMQ_ROUTER socket will send a notification message when a new client connects. This message will contain the identity of the client.

Option value type int
Option value unit 0, 1
Default value 0 (false)
Applicable socket types ZMQ_ROUTER

ZMQ_STREAM_OVERRIDE_ENDPOINTS: Override stream endpoints for connections

When set, the socket will override the endpoints for connections made using the ZMQ_STREAM socket type. This option allows for dynamically changing the endpoint for outgoing connections.

Option value type character string
Option value unit N/A
Default value not set
Applicable socket types ZMQ_STREAM

ZMQ_TCP_KEEPALIVE: Enable TCP keepalive

The ZMQ_TCP_KEEPALIVE option shall enable or disable the TCP keepalive mechanism on the specified socket. When enabled, the socket will periodically send keepalive messages to the peer to detect whether the connection is still alive. The value 0 disables keepalive, non-zero enables it.

Option value type int
Option value unit 0, 1
Default value 0 (false)
Applicable socket types all, when using TCP transport

ZMQ_TCP_KEEPCNT: Set number of TCP keepalives to send

The ZMQ_TCP_KEEPCNT option shall set the number of TCP keepalive probes to send before considering the connection dead. This option is only valid if ZMQ_TCP_KEEPALIVE is also enabled.

Option value type int
Option value unit N/A
Default value implementation dependent
Applicable socket types all, when using TCP transport

ZMQ_TCP_KEEPIDLE: Set idle time before sending TCP keepalives

The ZMQ_TCP_KEEPIDLE option shall set the idle time before sending TCP keepalive probes. This option is only valid if ZMQ_TCP_KEEPALIVE is also enabled.

Option value type int
Option value unit seconds
Default value implementation dependent
Applicable socket types all, when using TCP transport

ZMQ_TCP_KEEPINTVL: Set interval between TCP keepalives

The ZMQ_TCP_KEEPINTVL option shall set the interval between sending TCP keepalive probes. This option is only valid if ZMQ_TCP_KEEPALIVE is also enabled.

Option value type int
Option value unit seconds
Default value implementation dependent
Applicable socket types all, when using TCP transport

ZMQ_TCP_LAST_WHISPER: Set the last message sent before disconnecting

The ZMQ_TCP_LAST_WHISPER option shall set the message that is sent just before a connection is closed. This option is useful for graceful shutdowns and for sending final status information to the peer.

Option value type binary data
Option value unit N/A
Default value NULL
Applicable socket types all, when using TCP transport

ZMQ_THREAD_SAFE: Check if socket is thread safe

The ZMQ_THREAD_SAFE option is a read-only option that returns 1 if the socket is thread safe, and 0 otherwise.

Option value type int
Option value unit 0, 1

ZMQ_USE_FD: Use file descriptor

The ZMQ_USE_FD option allows the application to use an existing file descriptor instead of creating a new one. This is useful for integrating ZeroMQ with other event loops or libraries that manage file descriptors.

Option value type int

ZMQ_ZAP_DOMAIN: Set ZAP domain

The ZMQ_ZAP_DOMAIN option sets the domain for ZAP authentication. ZAP (ZeroMQ Authentication and Authorization Protocol) is a protocol for authenticating and authorizing clients connecting to ZeroMQ servers. The domain is a string that identifies a security domain for ZAP.

Option value type character string
Option value unit N/A
Default value not set
Applicable socket types all, when using TCP or IPC transport

ZMQ_ZAP_PRINCIPAL: Set ZAP principal

The ZMQ_ZAP_PRINCIPAL option sets the principal for ZAP authentication. The principal is a string that identifies the client or server for ZAP authentication.

Option value type character string
Option value unit N/A
Default value not set
Applicable socket types all, when using TCP or IPC transport

ZMQ_IDENTITY: Set identity of socket

This option name is now deprecated. Use ZMQ_ROUTING_ID instead. ZMQ_IDENTITY remains as an alias for now.

ZMQ_IMMEDIATE: Queue messages only to completed connections

By default queues will fill on outgoing connections even if the connection has not completed. This can lead to "lost" messages on sockets with round-robin routing (REQ, PUSH, DEALER). If this option is set to 1, messages shall be queued only to completed connections. This will cause the socket to block if there are no other connections, but will prevent queues from filling on pipes awaiting connection.

Option value type int
Option value unit boolean
Default value 0 (false)
Applicable socket types all, only for connection-oriented transports.

ZMQ_INVERT_MATCHING: Invert message filtering

Reverses the filtering behavior of PUB-SUB sockets, when set to 1.

On PUB and XPUB sockets, this causes messages to be sent to all connected sockets except those subscribed to a prefix that matches the message. On SUB sockets, this causes only incoming messages that do not match any of the socket’s subscriptions to be received by the user.

Whenever ZMQ_INVERT_MATCHING is set to 1 on a PUB socket, all SUB sockets connecting to it must also have the option set to 1. Failure to do so will have the SUB sockets reject everything the PUB socket sends them. XSUB sockets do not need to do this because they do not filter incoming messages.

Option value type int
Option value unit 0,1
Default value 0
Applicable socket types ZMQ_PUB, ZMQ_XPUB, ZMQ_SUB

ZMQ_IPV6: Enable IPv6 on socket

Set the IPv6 option for the socket. A value of 1 means IPv6 is enabled on the socket, while 0 means the socket will use only IPv4. When IPv6 is enabled the socket will connect to, or accept connections from, both IPv4 and IPv6 hosts.

Option value type int
Option value unit boolean
Default value 0 (false)
Applicable socket types all, when using TCP transports.

ZMQ_LINGER: Set linger period for socket shutdown

The ZMQ_LINGER option shall set the linger period for the specified socket. The linger period determines how long pending messages which have yet to be sent to a peer shall linger in memory after a socket is disconnected with zmq_disconnect(3) or closed with zmq_close(3), and further affects the termination of the socket’s context with zmq_ctx_term(3). The following outlines the different behaviours:

•A value of -1 specifies an infinite linger period. Pending messages shall not be discarded after a call to zmq_disconnect() or zmq_close(); attempting to terminate the socket’s context with zmq_ctx_term() shall block until all pending messages have been sent to a peer.
•The value of 0 specifies no linger period. Pending messages shall be discarded immediately after a call to zmq_disconnect() or zmq_close().
•Positive values specify an upper bound for the linger period in milliseconds. Pending messages shall not be discarded after a call to zmq_disconnect() or zmq_close(); attempting to terminate the socket’s context with zmq_ctx_term() shall block until either all pending messages have been sent to a peer, or the linger period expires, after which any pending messages shall be discarded.
Option value type int
Option value unit milliseconds
Default value -1 (infinite)
Applicable socket types all

ZMQ_MAXMSGSIZE: Maximum acceptable inbound message size

Limits the size of the inbound message. If a peer sends a message larger than ZMQ_MAXMSGSIZE it is disconnected. Value of -1 means no limit.

Option value type int64_t
Option value unit bytes
Default value -1
Applicable socket types all

ZMQ_METADATA: Add application metadata properties to a socket

The ZMQ_METADATA option shall add application metadata to the specified socket, the metadata is exchanged with peers during connection setup. A metadata property is specified as a string, delimited by a colon, starting with the metadata property followed by the metadata value, for example "X-key:value". Property names are restricted to maximum 255 characters and must be prefixed by "X-". Multiple application metadata properties can be added to a socket by executing zmq_setsockopt() multiple times. As the argument is a null-terminated string, binary data must be encoded before it is added e.g. using Z85 (zmq_z85_encode(3)).

Option value type character string
Option value unit N/A

Applicable socket types all

ZMQ_MULTICAST_HOPS: Maximum network hops for multicast packets

Sets the time-to-live field in every multicast packet sent from this socket. The default is 1 which means that the multicast packets don’t leave the local network.

Option value type int
Option value unit network hops
Default value 1
Applicable socket types all, when using multicast transports

ZMQ_MULTICAST_MAXTPDU: Maximum transport data unit size for multicast packets

Sets the maximum transport data unit size used for outbound multicast packets.

This must be set at or below the minimum Maximum Transmission Unit (MTU) for all network paths over which multicast reception is required.

Option value type int
Option value unit bytes
Default value 1500
Applicable socket types all, when using multicast transports

ZMQ_PLAIN_PASSWORD: Set PLAIN security password

Sets the password for outgoing connections over TCP or IPC. If you set this to a non-null value, the security mechanism used for connections shall be PLAIN, see zmq_plain(7). If you set this to a null value, the security mechanism used for connections shall be NULL, see zmq_null(3).

Option value type character string

ZMQ_PLAIN_SERVER: ضبط دور خادم PLAIN

يحدد ما إذا كانت المقبس ستعمل كخادم لأمان PLAIN، انظر zmq_plain(7). القيمة 1 تعني أن المقبس ستعمل كخادم PLAIN. القيمة 0 تعني أن المقبس لن تعمل كخادم PLAIN، ودور أمنها سيعتمد بعد ذلك على إعدادات الخيارات الأخرى. سيؤدي ضبط هذه القيمة على 0 إلى إعادة تعيين أمن المقبس إلى NULL.

نوع قيمة الخيار int
وحدة قيمة الخيار 0, 1
القيمة الافتراضية 0
أنواع المقابس المطبقة الجميع، عند استخدام نقل TCP

ZMQ_PLAIN_USERNAME: ضبط اسم المستخدم لأمان PLAIN

يضبط اسم المستخدم للاتصالات الصادرة عبر TCP أو IPC. إذا قمت بتعيين هذا إلى قيمة غير فارغة، فستكون آلية الأمان المستخدمة للاتصالات هي PLAIN، انظر zmq_plain(7). إذا قمت بتعيين هذا إلى قيمة فارغة، فستكون آلية الأمان المستخدمة للاتصالات هي NULL، انظر zmq_null(3).

نوع قيمة الخيار سلسلة أحرف
وحدة قيمة الخيار N/A
القيمة الافتراضية غير معين
أنواع المقابس المطبقة الجميع، عند استخدام نقل TCP

ZMQ_USE_FD: ضبط واصف ملف المقبس المخصص مسبقًا

عند ضبطه على قيمة عدد صحيح موجب قبل استدعاء zmq_bind على المقبس، ستستخدم المقبس واصف الملف المقابل للاتصالات عبر TCP أو IPC بدلاً من تخصيص واصف ملف جديد. مفيد لكتابة خدمات يتم تنشيطها بواسطة المقبس systemd. إذا تم ضبطه على -1 (افتراضي)، فسيتم تخصيص واصف ملف جديد بدلاً من ذلك (السلوك الافتراضي).


ملاحظة

إذا تم ضبطه بعد استدعاء zmq_bind، فلن يكون لهذا الخيار أي تأثير. ملاحظة: يجب أن يكون واصف الملف الذي تم تمريره قد تم تشغيله عبر استدعاءات النظام "bind" و "listen" مسبقًا. أيضًا، يجب أن يتم تعيين الخيارات التي عادةً ما يتم تمريرها عبر zmq_setsockopt مثل طول مخازن مؤقت TCP، أو TCP، أو SO_REUSEADDR مسبقًا بواسطة المتصل، حيث يجب تعيينها قبل ربط المقبس.

نوع قيمة الخيار int
وحدة قيمة الخيار واصف ملف
القيمة الافتراضية -1
أنواع المقابس المطبقة جميع المقابس المرتبطة، عند استخدام نقل IPC أو TCP

ZMQ_PROBE_ROUTER: تهيئة الاتصالات بمقابس ROUTER

عند ضبطه على 1، سترسل المقبس تلقائيًا رسالة فارغة عند إجراء اتصال جديد أو قبوله. يمكنك ضبط هذا على مقابس REQ أو DEALER أو ROUTER المتصلة بمقبس ROUTER. يجب على التطبيق تصفية هذه الرسائل الفارغة. يوفر خيار ZMQ_PROBE_ROUTER فعليًا لتطبيق ROUTER حدثًا يشير إلى وصول نظير جديد.

ZMQ_RCVHWM: ضبط العلامة المائية العالية للرسائل الواردة

سيقوم الخيار ZMQ_RCVHWM بضبط العلامة المائية العالية للرسائل الواردة على المقبس المحدد. العلامة المائية العالية هي حد صارم على الحد الأقصى لعدد الرسائل المعلقة التي سيقوم 0MQ بتخزينها مؤقتًا في الذاكرة لأي نظير فردي يتواصل معه المقبس المحدد. القيمة صفر تعني عدم وجود حد.

إذا تم الوصول إلى هذا الحد، سيدخل المقبس في حالة استثنائية، واعتمادًا على نوع المقبس، سيتخذ 0MQ الإجراء المناسب مثل الحظر أو إسقاط الرسائل المرسلة. ارجع إلى أوصاف المقابس الفردية في zmq_socket(3) للحصول على تفاصيل حول الإجراء الدقيق المتخذ لكل نوع مقبس.


ملاحظة

لا يضمن 0MQ أن يكون المقبس قادرًا على تخزين عدد رسائل يصل إلى ZMQ_RCVHWM، وقد يكون الحد الفعلي أقل أو أعلى، اعتمادًا على نقل المقبس. مثال جدير بالذكر هو المقابس التي تستخدم نقل TCP؛ انظر zmq_tcp(7).

نوع قيمة الخيار int
وحدة قيمة الخيار رسائل
القيمة الافتراضية 1000
أنواع المقابس المطبقة الجميع

ZMQ_RCVTIMEO: الحد الأقصى للوقت قبل أن تعود عملية الاستلام (recv) بالخطأ EAGAIN

نوع قيمة الخيار int

القيمة الافتراضية -1 (لا نهائي)

ZMQ_ROUTER

ZMQ_ROUTER_RAW: تبديل مقبس ROUTER إلى الوضع الخام

يحدد الوضع الخام على ROUTER، عند تعيينه إلى 1. عندما يكون مقبس ROUTER في الوضع الخام، وعند استخدام بروتوكول النقل tcp://، فإنه سيقرأ ويكتب بيانات TCP بدون تأطير 0MQ. هذا يسمح لتطبيقات 0MQ بالتواصل مع تطبيقات غير 0MQ. عند استخدام الوضع الخام، لا يمكنك تعيين هويات صريحة، ويتم تجاهل علامة ZMQ_SNDMORE عند إرسال رسائل البيانات. في الوضع الخام، يمكنك إغلاق اتصال معين عن طريق إرسال رسالة ذات طول صفري إليه (بعد إطار معرف التوجيه).


ملاحظة

هذا الخيار مهمل، يرجى استخدام مقابس ZMQ_STREAM بدلاً منه.

نوع قيمة الخيار int
وحدة قيمة الخيار 0, 1
القيمة الافتراضية 0
أنواع المقابس المطبقة ZMQ_ROUTER

ZMQ_ROUTING_ID: تعيين معرف توجيه المقبس

يحدد الخيار ZMQ_ROUTING_ID معرف التوجيه للمقبس socket المحدد عند الاتصال بمقبس ROUTER.

يجب أن يكون معرف التوجيه على الأقل بايت واحد وبحد أقصى 255 بايت طولاً. الهويات التي تبدأ ببايت صفري محفوظة للاستخدام من قبل البنية التحتية لـ 0MQ.

إذا استخدم عميلان نفس معرف التوجيه عند الاتصال بـ ROUTER، فإن النتائج ستعتمد على إعداد خيار ZMQ_ROUTER_HANDOVER. إذا لم يتم تعيين هذا الخيار (أو تم تعيينه إلى القيمة الافتراضية صفر)، فسيرفض مقبس ROUTER العملاء الذين يحاولون الاتصال بمعرف توجيه مستخدم بالفعل. إذا تم تعيين هذا الخيار إلى 1، فسيقوم مقبس ROUTER بتسليم الاتصال إلى العميل الجديد وقطع اتصال العميل الحالي.

نوع قيمة الخيار بيانات ثنائية
وحدة قيمة الخيار غير قابلة للتطبيق
القيمة الافتراضية NULL
أنواع المقابس المطبقة ZMQ_REQ, ZMQ_REP, ZMQ_ROUTER, ZMQ_DEALER.

ZMQ_SNDHWM: تعيين علامة الحد الأقصى للرسائل الصادرة

يحدد الخيار ZMQ_SNDHWM علامة الحد الأقصى للرسائل الصادرة على المقبس socket المحدد. علامة الحد الأقصى هي حد صارم على الحد الأقصى لعدد الرسائل المعلقة التي يجب على 0MQ وضعها في قائمة انتظار في الذاكرة لأي نظير فردي يتواصل معه المقبس socket المحدد. القيمة صفر تعني عدم وجود حد.

إذا تم الوصول إلى هذا الحد، سيدخل المقبس في حالة استثنائية، وبناءً على نوع المقبس، سيتخذ 0MQ الإجراء المناسب مثل حظر أو إسقاط الرسائل المرسلة. راجع أوصاف المقابس الفردية في zmq_socket(3) للحصول على تفاصيل حول الإجراء الدقيق المتخذ لكل نوع مقبس.


ملاحظة

لا يضمن 0MQ أن المقبس سيقبل ما يصل إلى ZMQ_SNDHWM رسالة، وقد يكون الحد الفعلي أقل بنسبة تصل إلى 90٪ اعتمادًا على تدفق الرسائل على المقبس. قد يكون المقبس قادرًا على قبول المزيد من الرسائل أكثر من عتبة ZMQ_SNDHWM؛ مثال بارز هو للمقابس التي تستخدم بروتوكول النقل TCP؛ انظر zmq_tcp(7).

ZMQ_SNDTIMEO: الحد الأقصى للوقت قبل أن تعود عملية الإرسال بـ EAGAIN

يحدد مهلة عملية الإرسال على المقبس. إذا كانت القيمة 0، فإن zmq_send(3) ستعود على الفور، مع خطأ EAGAIN إذا تعذر إرسال الرسالة. إذا كانت القيمة -1، فسوف تمنع حتى يتم إرسال الرسالة. بالنسبة لجميع القيم الأخرى، ستحاول إرسال الرسالة لتلك المدة قبل العودة بخطأ EAGAIN.

نوع قيمة الخيار int

ZMQ_IN_BATCH_SIZE: Maximal receive batch size

Sets the maximal amount of messages that can be received in a single recv system call. WARNING: this option should almost never be changed. The default has been chosen to offer the best compromise between latency and throughtput. In the vast majority of cases, changing this option will result in worst result if not outright breakages.

Cannot be zero.
