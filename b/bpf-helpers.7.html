long bpf_skb_store_bytes(struct sk_buff *skb, u32 offset, const void *from, u32 len, u64 flags)
الوصف
قم بتخزين len بايت من العنوان from في الحزمة المرتبطة بـ skb، عند offset. flags هي تركيبة من القيم التالية:
BPF_F_RECOMPUTE_CSUM
قم بتحديث skb->csum تلقائيًا بعد تخزين البايتات.
BPF_F_INVALIDATE_HASH
قم بتعيين skb->hash، و skb->swhash، و skb->l4hash إلى 0.

استدعاء هذا المساعد يمكن أن يغير مخزن الحزمة الأساسي. لذلك، عند التحميل، يتم إبطال جميع الفحوصات على المؤشرات التي أجراها المدقق سابقًا ويجب إجراؤها مرة أخرى، إذا تم استخدام المساعد بالاشتراك مع الوصول المباشر للحزمة.

long bpf_l3_csum_replace(struct sk_buff *skb, u32 offset, u64 from, u64 to, u64 size)
الوصف
أعد حساب مجموع التحقق من الطبقة 3 (مثل IP) للحزمة المرتبطة بـ skb. الحساب تزايدي، لذا يجب أن يعرف المساعد القيمة السابقة لمجال الرأس الذي تم تعديله (from)، والقيمة الجديدة لهذا المجال (to)، وعدد البايتات (2 أو 4) لهذا المجال، المخزنة في size. بدلاً من ذلك، من الممكن تخزين الفرق بين القيم السابقة والجديدة لمجال الرأس في to، عن طريق تعيين from و size إلى 0. لكلتا الطريقتين، offset يحدد موقع مجموع التحقق IP داخل الحزمة.

يعمل هذا المساعد بالاشتراك مع bpf_csum_diff()، الذي لا يقوم بتحديث مجموع التحقق في مكانه، ولكنه يوفر مرونة أكبر ويمكنه التعامل مع أحجام أكبر من 2 أو 4 لمجموع التحقق المراد تحديثه.

long bpf_l4_csum_replace(struct sk_buff *skb, u32 offset, u64 from, u64 to, u64 flags)
الوصف
أعد حساب مجموع التحقق للطبقة 4 (مثل TCP أو UDP أو ICMP) للحزمة المرتبطة بـ skb. الحساب تزايدي، لذا يجب أن يعرف المساعد القيمة السابقة لمجال الرأس الذي تم تعديله (from)، والقيمة الجديدة لهذا المجال (to)، وعدد البايتات (2 أو 4) لهذا المجال، المخزنة في أدنى أربع بتات من flags. بدلاً من ذلك، من الممكن تخزين الفرق بين القيم السابقة والجديدة لمجال الرأس في to، عن طريق تعيين from وأدنى أربع بتات من flags إلى 0. لكلتا الطريقتين، offset يحدد موقع مجموع التحقق IP داخل الحزمة. بالإضافة إلى حجم المجال، يمكن إضافة flags (OR بتي) علامات فعلية. مع BPF_F_MARK_MANGLED_0، لا يتم لمس مجموع التحقق الفارغ (إلا إذا تمت إضافة BPF_F_MARK_ENFORCE أيضًا)، وللتحديثات التي تؤدي إلى مجموع تحقق فارغ، يتم تعيين القيمة إلى CSUM_MANGLED_0 بدلاً من ذلك. تشير العلامة BPF_F_PSEUDO_HDR إلى أن مجال الرأس المعدل هو جزء من الرأس الزائف. يجب تعيين العلامة BPF_F_IPV6 لحزم IPv6.

يعمل هذا المساعد بالاشتراك مع bpf_csum_diff()، الذي لا يقوم بتحديث مجموع التحقق في مكانه، ولكنه يوفر مرونة أكبر ويمكنه التعامل مع أحجام أكبر من 2 أو 4 لمجموع التحقق المراد تحديثه.

استدعاء هذا المساعد يمكن أن يغير مخزن الحزمة الأساسي. لذلك، عند التحميل، يتم إبطال جميع الفحوصات على المؤشرات التي أجراها المدقق سابقًا ويجب إجراؤها مرة أخرى، إذا تم استخدام المساعد بالاشتراك مع الوصول المباشر للحزمة.

long bpf_tail_call(void *ctx, struct bpf_map *prog_array_map, u32 index)
الوصف
يستخدم هذا المساعد الخاص لتشغيل "مكالمة ذيلية"، أو بعبارة أخرى، للقفز إلى برنامج eBPF آخر. يتم استخدام نفس إطار المكدس (ولكن القيم الموجودة على المكدس وفي السجلات للمستدعي ليست متاحة للمستدعى). تسمح هذه الآلية بسلسلة البرامج، إما لزيادة الحد الأقصى لعدد تعليمات eBPF المتاحة، أو لتنفيذ برامج معينة في كتل شرطية. لأسباب أمنية، يوجد حد أقصى لعدد مكالمات الذيل المتتالية التي يمكن إجراؤها.

عند استدعاء هذا المساعد، يحاول البرنامج القفز إلى برنامج مشار إليه بالمعامل index في prog_array_map، وهو خريطة خاصة من النوع BPF_MAP_TYPE_PROG_ARRAY، ويمرر ctx، وهو مؤشر إلى السياق.

إذا نجح الاستدعاء، تقوم النواة على الفور بتشغيل التعليمات الأولى للبرنامج الجديد. هذه ليست مكالمة دالة، ولا تعود أبدًا إلى البرنامج السابق. إذا فشل الاستدعاء، فإن المساعد ليس له تأثير، ويستمر المستدعي في تشغيل تعليماته اللاحقة. يمكن أن تفشل المكالمة إذا كان برنامج الوجهة للقفزة غير موجود (أي أن index أكبر من عدد الإدخالات في prog_array_map)، أو إذا تم الوصول إلى الحد الأقصى لعدد مكالمات الذيل لهذه السلسلة من البرامج. يتم تعريف هذا الحد في النواة بواسطة الماكرو MAX_TAIL_CALL_CNT (غير متاح لمساحة المستخدم)، والذي تم تعيينه حاليًا إلى 33.

long bpf_clone_redirect(struct sk_buff *skb, u32 ifindex, u64 flags)
الوصف
قم بنسخ وإعادة توجيه الحزمة المرتبطة بـ skb إلى جهاز شبكة آخر من الفهرس ifindex. يمكن استخدام كل من واجهات الإدخال والإخراج لإعادة التوجيه. يتم استخدام قيمة BPF_F_INGRESS في flags للتمييز (يتم تحديد مسار الإدخال إذا كانت العلامة موجودة، ومسار الإخراج بخلاف ذلك). هذا هو العلم الوحيد المدعوم في الوقت الحالي.

مقارنةً بالمساعد bpf_redirect()، فإن bpf_clone_redirect() لها تكلفة مرتبطة بنسخ مخزن الحزمة، ولكن يمكن تنفيذ ذلك خارج برنامج eBPF. على العكس من ذلك، فإن bpf_redirect() أكثر كفاءة، ولكن يتم التعامل معها من خلال رمز إجراء حيث يحدث إعادة التوجيه فقط بعد عودة برنامج eBPF.

استدعاء هذا المساعد يمكن أن يغير مخزن الحزمة الأساسي. لذلك، عند التحميل، يتم إبطال جميع الفحوصات على المؤشرات التي أجراها المدقق سابقًا ويجب إجراؤها مرة أخرى، إذا تم استخدام المساعد بالاشتراك مع الوصول المباشر للحزمة.

الإرجاع
0 عند النجاح، أو خطأ سالب في حالة الفشل. يشير الخطأ الموجب إلى احتمال إسقاط أو ازدحام في الجهاز المستهدف. أكواد الخطأ الموجبة المحددة غير معرفة.

long bpf_get_branch_snapshot(void *entries, u32 size, u64 flags)
Description
Get branch trace from hardware engines like Intel LBR. The hardware engine is stopped shortly after the helper is called. Therefore, the user need to filter branch entries based on the actual use case. To capture branch trace before the trigger point of the BPF program, the helper should be called at the beginning of the BPF program.

The data is stored as struct perf_branch_entry into output buffer entries. size is the size of entries in bytes. flags is reserved for now and must be zero.

Return
On success, number of bytes written to buf. On error, a negative value.

-EINVAL if flags is not zero.

-ENOENT if architecture does not support branch records.

long bpf_find_vma(struct task_struct *task, u64 addr, void *callback_fn, void *callback_ctx, u64 flags)
Description
Find vma of task that contains addr, call callback_fn function with task, vma, and callback_ctx. The callback_fn should be a static function and the callback_ctx should be a pointer to the stack. The flags is used to control certain aspects of the helper. Currently, the flags must be 0.

The expected callback signature is

long (*callback_fn)(struct task_struct *task, struct vm_area_struct *vma, void *callback_ctx);

Return
0 on success. -ENOENT if task->mm is NULL, or no vma contains addr. -EBUSY if failed to try lock mmap_lock. -EINVAL for invalid flags.
long bpf_loop(u32 nr_loops, void *callback_fn, void *callback_ctx, u64 flags)
Description
For nr_loops, call callback_fn function with callback_ctx as the context parameter. The callback_fn should be a static function and the callback_ctx should be a pointer to the stack. The flags is used to control certain aspects of the helper. Currently, the flags must be 0. Currently, nr_loops is limited to 1 << 23 (~8 million) loops.

long (*callback_fn)(u64 index, void *ctx);

where index is the current index in the loop. The index is zero-indexed.

If callback_fn returns 0, the helper will continue to the next loop. If return value is 1, the helper will skip the rest of the loops and return. Other return values are not used now, and will be rejected by the verifier.

Return
The number of loops performed, -EINVAL for invalid flags, -E2BIG if nr_loops exceeds the maximum number of loops.
