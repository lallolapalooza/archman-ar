bindtags(n)

الحزمة: tk

التراخيص: TCL

bindtags(n) أوامر Tk المضمنة bindtags(n)

اسم

bindtags - تحديد الارتباطات التي تنطبق على نافذة، وترتيب تقييمها

الموجز

bindtags window ?tagList?

الوصف

عند إنشاء ارتباط باستخدام الأمر bind، يتم ربطه إما بنافذة معينة مثل .a.b.c، أو اسم فئة مثل Button، أو الكلمة المفتاحية all، أو أي سلسلة نصية أخرى. تسمى كل هذه الأشكال وسوم ارتباط. تحتوي كل نافذة على قائمة بوسوم ارتباط تحدد كيفية معالجة الأحداث لهذه النافذة. عندما يحدث حدث في نافذة، يتم تطبيقه على كل وسوم النافذة بالترتيب: لكل وسم، يتم تنفيذ الارتباط الأكثر تحديدًا الذي يطابق الوسم والحدث المعطى. راجع الأمر bind لمزيد من المعلومات حول عملية المطابقة.

افتراضيًا، تحتوي كل نافذة على أربعة وسوم ارتباط تتكون من اسم النافذة، واسم فئة النافذة، واسم أقرب سلف علوي للنافذة، و all، بهذا الترتيب. تحتوي النوافذ العلوية على ثلاثة وسوم فقط افتراضيًا، حيث أن اسم النافذة العلوية هو نفس اسم النافذة. يسمح الأمر bindtags بقراءة وتعديل وسوم الارتباط لنافذة.

إذا تم استدعاء bindtags بوسيط واحد فقط، فسيتم إرجاع المجموعة الحالية من وسوم الارتباط لـ window كقائمة. إذا تم تحديد الوسيط tagList لـ bindtags، فيجب أن تكون قائمة صحيحة؛ يتم تغيير وسوم window إلى عناصر القائمة. يمكن أن تكون عناصر tagList سلاسل نصية عشوائية؛ ومع ذلك، يتم التعامل مع أي وسم يبدأ بنقطة كاسم نافذة؛ إذا لم توجد نافذة بهذا الاسم في وقت معالجة الحدث، فسيتم تجاهل الوسم لهذا الحدث. يحدد ترتيب العناصر في tagList الترتيب الذي سيتم به تنفيذ نصوص الربط استجابة للأحداث. على سبيل المثال، الأمر

bindtags .b {all . Button .b}
يعكس ترتيب تقييم نصوص الربط لزر اسمه .b بحيث يتم استدعاء ارتباطات all أولاً، ثم الارتباطات الخاصة بالسلف العلوي لـ .b ( ".”) ، ثم ارتباطات الفئة، ثم الارتباطات الخاصة بـ .b. إذا كان tagList قائمة فارغة، فسيتم إرجاع وسوم الارتباط لـ window إلى الحالة الافتراضية الموضحة أعلاه.

يمكن استخدام الأمر bindtags لإدخال وسوم ارتباط إضافية عشوائية لنافذة، أو لإزالة الوسوم القياسية. على سبيل المثال، الأمر

bindtags .b {.b TrickyButton . all}
يستبدل وسم Button لـ .b بـ TrickyButton. هذا يعني أن ارتباطات الأداة الافتراضية للأزرار، والتي ترتبط بالوسم Button، لن تنطبق بعد الآن على .b، ولكن ستنطبق أي ارتباطات مرتبطة بـ TrickyButton (ربما سلوك زر جديد).

مثال

إذا كان لديك مجموعة من أدوات frame المتداخلة وتريد أن يتم تسليم الأحداث المرسلة إلى أداة button أيضًا إلى جميع الأدوات وصولاً إلى toplevel الحالي (على عكس السلوك الافتراضي لـ Tk، حيث لا يتم تسليم الأحداث إلى تلك النوافذ الوسيطة) لتسهيل وجود مسرعات نشطة فقط لجزء من نافذة، يمكنك استخدام إجراء مساعد مثل هذا للمساعدة في إعداد ذلك:

proc setupBindtagsForTreeDelivery {widget} {
    set tags [list $widget [winfo class $widget]]
    set w $widget
    set t [winfo toplevel $w]
    while {$w ne $t} {
        set w [winfo parent $w]
        lappend tags $w
    }
    lappend tags all
    bindtags $widget $tags
}
