buildah-manifest(1)

الحزمة: buildah

التراخيص: Apache-2.0

buildah-manifest(1) دليل الأوامر العامة buildah-manifest(1)

الاسم

buildah-manifest - إنشاء ومعالجة قوائم التعريفات وفهارس الصور.

الملخص

buildah manifest COMMAND [OPTIONS] [ARG...]

الوصف

يوفر الأمر buildah manifest أوامر فرعية يمكن استخدامها للأغراض التالية:

* إنشاء قائمة تعريفات Docker عاملة أو فهرس صور OCI.
* إضافة إدخال إلى قائمة تعريفات أو فهرس صور لصورة محددة.
* إضافة إدخال إلى فهرس صور لتعريف قطعة أثرية يشير إلى ملف.
* إضافة أو تحديث معلومات حول إدخال في قائمة تعريفات أو فهرس صور.
* حذف حاوية عاملة أو صورة.
* دفع قائمة تعريفات أو فهرس صور إلى سجل أو موقع آخر.

الأوامر الفرعية

الأمر صفحة الدليل الوصف
add buildah-manifest-add(1) إضافة صورة أو قطعة أثرية إلى قائمة تعريفات أو فهرس صور.
annotate buildah-manifest-annotate(1) إضافة أو تحديث معلومات حول صورة أو قطعة أثرية في قائمة تعريفات أو فهرس صور.
create buildah-manifest-create(1) إنشاء قائمة تعريفات أو فهرس صور.
exists buildah-manifest-exists(1) التحقق مما إذا كانت قائمة التعريفات موجودة في التخزين المحلي.
inspect buildah-manifest-inspect(1) عرض محتويات قائمة التعريفات أو فهرس الصور.
push buildah-manifest-push(1) دفع قائمة تعريفات أو فهرس صور إلى سجل أو موقع آخر.
remove buildah-manifest-remove(1) إزالة صورة من قائمة تعريفات أو فهرس صور.
rm buildah-manifest-rm(1) إزالة قائمة التعريفات من التخزين المحلي.

أمثلة

بناء قائمة تعريفات متعددة المعمارية من Containerfile

بافتراض أن Containerfile يستخدم تعليمات RUN، يحتاج المضيف إلى طريقة لتنفيذ ثنائيات غير أصلية. تكوين هذا خارج نطاق هذا المثال. يمكن بناء قائمة تعريفات متعددة المعمارية shazam بالتوازي عبر 4 خيوط هكذا:

    $ platarch=linux/amd64,linux/ppc64le,linux/arm64,linux/s390x
    $ buildah build --jobs=4 --platform=$platarch --manifest shazam .

ملاحظة: الوسيطة --jobs اختيارية، ويجب استخدام الخيار --manifest بدلاً من الخيارات -t أو --tag.

تجميع تعريف متعدد المعمارية من صور مبنية بشكل منفصل

بافتراض أن صور example.com/example/shazam:$arch تم بناؤها بشكل منفصل على مضيفات أخرى وتم دفعها إلى السجل example.com. يمكن دمجها في قائمة تعريفات، ودفعها باستخدام حلقة بسيطة:

    $ REPO=example.com/example/shazam
    $ buildah manifest create $REPO:latest
    $ for IMGTAG in amd64 s390x ppc64le arm64; do   
              buildah manifest add $REPO:latest docker://$REPO:IMGTAG;   
          done
    $ buildah manifest push --all $REPO:latest

ملاحظة: ترتيب وسيطة تعليمات add هو <manifest> ثم <image>. أيضًا، الخيار --all للدفع مطلوب لضمان دفع جميع المحتويات، وليس فقط المنصة/المعمارية الأصلية.

إزالة وتصنيف قائمة تعريفات قبل الدفع

هناك حاجة إلى عناية خاصة عند إزالة ودفع قوائم التعريفات، على عكس المحتويات. تريد دائمًا تقريبًا استخدام الأوامر الفرعية manifest rm و manifest push --all. على سبيل المثال، يمكن إجراء إعادة تسمية ودفع بهذه الطريقة:

    $ buildah tag localhost/shazam example.com/example/shazam
    $ buildah manifest rm localhost/shazam
    $ buildah manifest push --all example.com/example/shazam
