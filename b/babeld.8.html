local-path path
This specifies the filesystem path to a socket on which babeld will listen for connections from a configuration client in read-only mode, and is equivalent to the command-line option -g.
local-path-readwrite path
This specifies the filesystem path to a socket on which babeld will listen for connections from a configuration client in read-write mode, and is equivalent to the command-line option -G. Any user with write access to that socket will be able to change babeld's configuration.
export-table table
This specifies the kernel routing table to use for routes inserted by babeld, and is equivalent to the command-line option -t.
import-table table
This specifies a kernel routing table from which routes are redistributed by babeld, and can be specified multiple times with a cumulative effect. This is equivalent to the command-line option -T.
kernel-check-interval seconds
This specifies the interval between two kernel routing table dumps. The default is 300s (5 minutes). This may be set to 0 in order to never perform periodic kernel dumps.
shutdown-delay-ms milliseconds
During shutdown we first notify neighbours of our imminent shutdown by sending route retractions, wait for the specified number of milliseconds and then flush kernel routes. This ensures any inflight traffic is still properly forwarded. You may want to ensure the delay is appropriate for the maximum delay path in your network. Setting this to zero is permissible.
link-detect {true|false}
This specifies whether to use carrier sense for determining interface availability, and is equivalent to the command-line option -l.
smoothing-half-life seconds
This specifies the half-life in seconds of the exponential decay used for smoothing metrics for performing route selection, and is equivalent to the command-line option -M.
daemonise {true|false}
This specifies whether to daemonize at startup, and is equivalent to the command-line option -D.
skip-kernel-setup {true|false}
If this flag is set, no kernel (sysctl) setup is performed on startup, and it is assumed that enabling forwarding, disabling redirects and disabling the reverse-path filter is performed by other means. This can be useful when running in environments where system permissions prevent setting kernel parameters, for instance without root permissions or inside a Linux container.
router-id id
Specify the router-id explicitly, as a modified EUI-64 or a MAC-48 address. If two nodes have the same router-id, bad things will happen. Don't use this option unless you know what you are doing.
state-file filename
This specifies the name of the file used for preserving long-term information between invocations of the babeld daemon, and is equivalent to the command-line option -S.
log-file filename
This specifies the name of the file used to log random messages to, and is equivalent to the command-line option -L.
pid-file filename
This specifies the name of the file to which babeld writes out its process id, and is equivalent to the command-line option -I.
first-rule-priority priority
This specifies smallest (highest) rule priority used with source-specific routes. The default is 100.
key id id type {hmac-sha256|blake2s128} value value
Configure a key for use with the key interface option. The type is one of hmac-sha256 or blake2s128. The value is a hexadecimal string (up to 64 bytes for hmac-sha256, up to 32 bytes for blake2s128).

تكوين الواجهة

يتم تكوين الواجهة بواسطة سطر بالتنسيق التالي:

interface name [parameter...]

حيث name هو اسم الواجهة (شيء مثل eth0). يمكن تغيير القيمة الافتراضية لمعامل الواجهة بواسطة سطر بالشكل

default [parameter...]

يمكن أن يكون كل parameter أحد:

type {auto|wired|wireless|tunnel}

القيمة الافتراضية هي auto ما لم يتم تحديد علامة سطر الأوامر -w.

link-quality {true|false|auto}
تحدد هذه القيمة ما إذا كان يجب إجراء تقدير جودة الارتباط على هذه الواجهة. القيمة الافتراضية هي إجراء تقدير جودة الارتباط على الواجهات اللاسلكية فقط.
split-horizon {true|false|auto}
تحدد هذه القيمة ما إذا كان يجب إجراء معالجة تقسيم الأفق على هذه الواجهة. القيمة الافتراضية هي إجراء معالجة تقسيم الأفق على الواجهات السلكية، ما لم يتم تعيين علامة -s.
rxcost cost
يحدد هذا تكلفة استقبال الإطارات على الواجهة المعطاة في ظل ظروف مثالية (لا فقدان للحزم)؛ كيف يرتبط هذا بالتكلفة الفعلية المستخدمة لحساب المقاييس للمسارات التي تمر عبر هذه الواجهة يعتمد على ما إذا كان تقدير جودة الارتباط يتم. القيمة الافتراضية هي 256 إذا كانت الواجهة لاسلكية، و 96 بخلاف ذلك.
hello-interval interval
يحدد هذا الفاصل الزمني بين حزم الترحيب المرسلة على هذه الواجهة. القيمة الافتراضية محددة بواسطة علامتي سطر الأوامر -h و -H.
update-interval interval
يحدد هذا الفاصل الزمني بين جداول التوجيه الكاملة المرسلة على هذه الواجهة؛ نظرًا لأن Babel يستخدم التحديثات التي يتم تشغيلها ولا يعد إلى ما لا نهاية، يمكن تعيين هذا إلى قيمة كبيرة جدًا، ما لم يكن من المتوقع فقدان كبير للحزم. القيمة الافتراضية هي أربعة أضعاف فاصل الترحيب.
enable-timestamps {true|false}
تمكين إرسال الطوابع الزمنية مع كل رسالة Hello و IHU لحساب قيم RTT. القيمة الافتراضية هي true لواجهات النفق، و false بخلاف ذلك.
unicast {true|false}
إرسال نسخ متعددة من TLVs بخلاف Hellos إلى جميع الجيران بدلاً من إرسال حزمة بث متعدد واحدة. القيمة الافتراضية هي false.
rfc6126-compatible {true|false}
تعطيل بعض الميزات غير المتوافقة مع RFC 6126 (الإصدار الأقدم لبروتوكول Babel)، مثل التوجيه الخاص بالمصدر وتقدير RTT عبر البث الأحادي. القيمة الافتراضية هي false.
rtt-decay decay
يحدد هذا عامل التحلل للمتوسط المتحرك الأسي لعينات RTT، بوحدات 1/256. يجب أن يكون بين 1 و 256، شاملاً. القيم الأعلى تتجاهل العينات القديمة بشكل أسرع. القيمة الافتراضية هي 42.
rtt-min rtt
يحدد هذا الحد الأدنى لـ RTT، بالمللي ثانية، بدءًا من الزيادة التي نزيد بها التكلفة للجوار. التكلفة الإضافية خطية في (rtt - rtt-min). القيمة الافتراضية هي 10 مللي ثانية.
rtt-max rtt
يحدد هذا الحد الأقصى لـ RTT، بالمللي ثانية، الذي لا نزيد فيه التكلفة للجوار. القيمة الافتراضية هي 120 مللي ثانية.
max-rtt-penalty cost
يحدد هذا الحد الأقصى للتكلفة المضافة إلى الجوار بسبب RTT، أي عندما يكون RTT أعلى من أو يساوي rtt-max. القيمة الافتراضية هي 96 إذا كان نوع الواجهة tunnel، و 0 بخلاف ذلك.
هل يجب الإعلان عن مسارات IPv4 عبر هذه الواجهة حتى عندما لا يكون هناك
عنوان IPv4. تعتمد القيمة الافتراضية على إصدار النواة.
key id
تمكين أمان HMAC على هذه الواجهة، واستخدام المفتاح id.
accept-bad-signatures {true|false}
قبول الحزم التي لا تحتوي على توقيع أو تحتوي على توقيع غير صحيح. هذا له تأثير فقط إذا تم تكوين مفتاح على واجهة. القيمة الافتراضية هي false.

قواعد التصفية

يتم تعريف قاعدة تصفية بسطر واحد بالتنسيق التالي:

filter selector... action

Filter يحدد الفلتر الذي سيتم إضافة هذا الإدخال إليه، ويمكن أن يكون أحد in (يتم تطبيقه على المسارات المتعلمة من جيران Babel)، out (يتم تطبيقه على المسارات المعلنة لجيران Babel)، redistribute (يتم تطبيقه على المسارات التي تم إعادة توزيعها من النواة)، أو install (يتم تطبيقه على المسارات المثبتة في النواة).
