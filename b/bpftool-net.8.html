bpftool-net(8)

الحزمة: bpf

التراخيص: GPL-2.0-only

BPFTOOL-NET(8) دليل مدير النظام BPFTOOL-NET(8)

الاسم

bpftool-net - أداة لفحص ارتباطات برامج bpf المتعلقة بالشبكات

الملخص

bpftool [خيارات] net أمر

خيارات := { { -j | --json } [{ -p | --pretty }] | { -d | --debug } }

الأوامر := { show | list | attach | detach | help }

أوامر الشبكة

bpftool net { show | list } [ dev اسم ]
bpftool net attach نوع_الربط برنامج dev اسم [ overwrite ]
bpftool net detach نوع_الربط dev اسم
bpftool net help
برنامج := { id معرف_البرنامج | pinned ملف | tag وسم_البرنامج | name اسم_البرنامج }
نوع_الربط := { xdp | xdpgeneric | xdpdrv | xdpoffload | tcx_ingress | tcx_egress }

الوصف

bpftool net { show | list } [ dev اسم ]
عرض ارتباطات برامج bpf في النظام الفرعي للشبكات في النواة.

حاليًا، تم تنفيذ ارتباطات xdp الخاصة بمشغل الجهاز، و tcx، و netkit، وارتباطات المصنف/الإجراء tc القديمة، و flow_dissector، بالإضافة إلى ارتباطات netfilter، أي لأنواع البرامج BPF_PROG_TYPE_XDP، BPF_PROG_TYPE_SCHED_CLS، BPF_PROG_TYPE_SCHED_ACT، BPF_PROG_TYPE_FLOW_DISSECTOR، BPF_PROG_TYPE_NETFILTER.

بالنسبة للبرامج المرتبطة بمجموعة cgroup معينة، على سبيل المثال، BPF_PROG_TYPE_CGROUP_SKB، BPF_PROG_TYPE_CGROUP_SOCK، BPF_PROG_TYPE_SOCK_OPS و BPF_PROG_TYPE_CGROUP_SOCK_ADDR، يمكن للمستخدمين استخدام bpftool cgroup لعرض ارتباطات cgroup. بالنسبة لبرامج sk_{filter, skb, msg, reuseport} و lwt/seg6 bpf، يجب على المستخدمين الرجوع إلى أدوات أخرى، على سبيل المثال، iproute2.

سيتم إدراج الإخراج الحالي أولاً مع جميع ارتباطات برامج xdp، يليه جميع ارتباطات برامج tcx، و netkit، ثم tc classifier/qdisc bpf، ثم جميع ارتباطات برامج flow_dissector وأخيراً برامج netfilter. يتم ترتيب كل من برامج xdp وبرامج tcx/netkit/tc بناءً على رقم ifindex. إذا تم ربط برامج bpf متعددة بنفس جهاز الشبكة من خلال tc، فسيكون الترتيب أولاً جميع برامج bpf المرتبطة بـ tcx، و netkit، ثم فئات tc، ثم جميع برامج bpf المرتبطة بـ qdiscs غير clsact، وأخيرًا جميع برامج bpf المرتبطة بـ qdisc الأساسية و clsact.

bpftool net attach نوع_الربط برنامج dev اسم [ overwrite ]
ربط برنامج bpf برنامج بواجهة الشبكة اسم بالنوع المحدد بواسطة نوع_الربط. يمكن استبدال برنامج bpf المرتبط مسبقًا بالأمر المستخدم مع خيار overwrite. حاليًا، يتم دعم أوضاع XDP فقط لـ نوع_الربط.

يمكن أن يكون نوع_الربط: xdp - محاولة استخدام XDP الأصلي والرجوع إلى XDP العام إذا لم يدعم مشغل بطاقة الشبكة ذلك؛ xdpgeneric - XDP عام. يعمل عند خطاف XDP العام عندما تدخل الحزمة بالفعل في مسار الاستقبال كـ skb؛ xdpdrv - XDP أصلي. يعمل عند أقرب نقطة في مسار الاستقبال الخاص بالمشغل؛ xdpoffload - تفريغ XDP. يعمل مباشرة على بطاقة الشبكة عند استقبال كل حزمة؛ tcx_ingress - TCX الوارد. يعمل على حركة مرور الشبكة الواردة؛ tcx_egress - TCX الصادر. يعمل على حركة مرور الشبكة الصادرة؛

bpftool net detach نوع_الربط dev اسم
فصل برنامج bpf المرتبط بواجهة الشبكة اسم بالنوع المحدد بواسطة نوع_الربط. لفصل برنامج bpf، يجب تحديد نفس نوع_الربط الذي تم استخدامه مسبقًا للربط. حاليًا، يتم دعم أوضاع XDP فقط لـ نوع_الربط.
bpftool net help
طباعة رسالة مساعدة مختصرة.

الخيارات

-h, --help
طباعة رسالة مساعدة مختصرة (مشابهة لـ bpftool help).
-V, --version
طباعة رقم إصدار bpftool (مشابه لـ bpftool version)، ورقم إصدار libbpf المستخدم، والميزات الاختيارية التي تم تضمينها عند تجميع bpftool. تشمل الميزات الاختيارية الربط بـ LLVM أو libbfd لتوفير المفكك للبرامج المترجمة (JIT) (bpftool prog dump jited) واستخدام هياكل BPF (قد تعتمد بعض الميزات مثل bpftool prog profile أو عرض pids المرتبطة بكائنات BPF عليها).
-j, --json
إنشاء إخراج JSON. بالنسبة للأوامر التي لا يمكنها إنتاج JSON، لا يكون لهذا الخيار أي تأثير.
-p, --pretty
إنشاء إخراج JSON قابل للقراءة للبشر. يتضمن -j.
-d, --debug
طباعة جميع السجلات المتاحة، حتى معلومات مستوى التصحيح. يشمل ذلك السجلات من libbpf وكذلك من المدقق، عند محاولة تحميل البرامج.
