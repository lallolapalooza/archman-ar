Options:
--help, -h Show help message.
--quiet, -q Only display errors and warnings.
--usage Show usage message and options.

Import sources from a directory, tarball or zip file

This command will import a directory, tarball or zip file into a bzr tree, replacing any versioned files already present. If a directory is specified, it is used as the target. If the directory does not exist, or is not versioned, it is created.

Tarballs may be gzip or bzip2 compressed. This is autodetected.

If the tarball or zip has a single root directory, that directory is stripped when extracting the tarball. This is not done for directories.

Make a directory into a versioned branch.

Use this to create an empty branch, or before importing an existing project.

If there is a repository in a parent directory of the location, then the history of the branch will be stored in the repository. Otherwise init creates a standalone branch which carries its own history in the .bzr directory.

If there is already a branch at the location but it has no working tree, the tree can be populated with 'brz checkout'.

Recipe for importing a tree of files:


cd ~/project
brz init
brz add .
brz status
brz commit -m "imported project"

Aliases: init-shared-repo, init-repo

See also: branch, checkout, init, repositories

Create a shared repository for branches to share storage space.

New branches created under the repository directory will store their revisions in the repository, not in the branch directory. For branches with shared history, this reduces the amount of storage needed and speeds up the creation of new branches.

If the --no-trees option is given then the branches in the repository will not have working trees by default. They will still exist as directories on disk, but they will not have separate copies of the files at a certain revision. This can be useful for repositories that store branches which are interacted with through checkouts or remote branches, such as on a server.

Examples:
Create a shared repository holding just branches:


brz init-shared-repo --no-trees repo
brz init repo/trunk


Make a lightweight checkout elsewhere:


brz checkout --lightweight repo/trunk trunk-checkout
cd trunk-checkout
(add files here)

brz join TREE

Options:
--help, -h Show help message.
--quiet, -q Only display errors and warnings.
--usage Show usage message and options.
--verbose, -v Display more information.

See also: split

Combine a tree into its containing tree.

This command requires the target tree to be in a rich-root format.

The TREE argument should be an independent tree, inside another tree, but not part of it. (Such trees can be produced by "brz split", but also by running "brz branch" with the target inside a tree.)

The result is a combined tree, with the subtree no longer an independent part. This is marked as a merge of the subtree into the containing tree, and all history is preserved.

انظر أيضًا: merge, pull

إرسال بريد إلكتروني أو إنشاء توجيه دمج لتقديم التغييرات.

يوفر توجيه الدمج العديد من الأشياء المطلوبة لطلب عمليات الدمج:

* وصف قابل للقراءة آليًا لعملية الدمج المطلوب تنفيذها

* رقعة اختيارية لمعاينة التغييرات المطلوبة

* حزمة اختيارية لبيانات المراجعة، بحيث يمكن تطبيق التغييرات
مباشرة من توجيه الدمج، دون استرداد البيانات من
فرع.

ينشئ `brz send` مجموعة بيانات مضغوطة، والتي عند تطبيقها باستخدام `brz merge`، لها نفس تأثير الدمج من الفرع المصدر.

افتراضيًا، يكون توجيه الدمج مكتفياً ذاتيًا ويمكن تطبيقه على أي فرع يحتوي على `submit_branch` في أسلافه دون الحاجة إلى الوصول إلى الفرع المصدر.

إذا تم تحديد `--no-bundle`، فلن يرسل Breezy محتويات المراجعات، بل فقط طلبًا منظمًا للدمج من `public_location`. في هذه الحالة، يكون `public_branch` مطلوبًا ويجب أن يكون محدثًا ومتاحًا للمستلم. يتم تضمين `public_branch` دائمًا إذا كان معروفًا، حتى يتمكن الأشخاص من التحقق منه لاحقًا.

يكون الفرع المرسل هو الأب للفرع المصدر افتراضيًا، ولكن يمكن تجاوزه. سيتم تذكر كل من الفرع المرسل والفرع العام في `branch.conf` في المرة الأولى التي يتم استخدامهما فيها لفرع معين. الفرع المصدر هو الفرع الذي يحتوي على دليل العمل افتراضيًا، ولكن يمكن تغييره باستخدام `--from`.

يتبع كل من الفرع المرسل والفرع العام السلوك المعتاد فيما يتعلق بـ `--remember`: إذا لم يتم تعيين موقع افتراضي، فإن أول عملية إرسال ستقوم بتعيينه (استخدم `--no-remember` لتجنب تعيينه). بعد ذلك، يمكنك حذف الموقع لاستخدام الافتراضي. لتغيير الافتراضي، استخدم `--remember`. سيتم حفظ القيمة فقط إذا كان يمكن الوصول إلى الموقع.

لحساب هذه التغييرات، يجب على `brz` تحليل الفرع المرسل. لذلك، من الأكثر كفاءة أن يكون الفرع المرسل نسخة محلية. إذا كان الموقع العام معروفًا للفرع المرسل، يتم استخدام هذا الموقع في توجيه الدمج.

السلوك الافتراضي هو إرسال توجيه الدمج عبر البريد الإلكتروني، ما لم يتم تحديد `-o`، وفي هذه الحالة يتم إرساله إلى ملف.

يتم إرسال البريد الإلكتروني باستخدام برنامج البريد المفضل لديك. يجب أن يكون هذا شفافًا على نظام Windows (يستخدم MAPI). على نظام Unix، يتطلب أداة `xdg-email`. إذا لم يتم العثور على العميل المفضل (أو استخدامه)، فسيتم استخدام محرر النصوص الخاص بك.

لاستخدام برنامج بريد إلكتروني معين، قم بتعيين خيار التكوين `mail_client`. القيم المدعومة للعملاء المحددين هي "claws" و "evolution" و "kmail" و "mail.app" (Mail.app الخاص بنظام MacOS X) و "mutt" و "thunderbird"؛ الخيارات العامة هي "default" و "editor" و "emacsclient" و "mapi" و "xdg-email". قد تضيف الإضافات عملاء مدعومين أيضًا.

إذا كان يتم إرسال البريد الإلكتروني، فإن عنوان الوجهة مطلوب. يمكن توفيره إما من سطر الأوامر، عن طريق تعيين خيار التكوين `submit_to` في الفرع نفسه أو خيار التكوين `child_submit_to` في الفرع المرسل.

يمكن تطبيق توجيهات الدمج التي تم إنشاؤها بواسطة `brz send` باستخدام `brz merge` أو `brz pull` عن طريق تحديد ملف يحتوي على توجيه دمج كموقع.

يستخدم `brz send` المواقع العامة بشكل مكثف لربط المواقع المحلية بعناوين URL التي يمكن للآخرين استخدامها. انظر `brz help configuration` لتعيينها، واستخدم `brz info` لعرضها.

انظر أيضًا: configuration, unshelve

وضع بعض التغييرات جانبًا مؤقتًا من الشجرة الحالية.

يسمح لك `shelve` بوضع التغييرات التي أجريتها "على الرف" مؤقتًا، أي بعيدًا عن الطريق، حتى وقت لاحق يمكنك فيه استعادتها من الرف باستخدام أمر `unshelve`. يتم تخزين التغييرات بجوار شجرة عملك، وبالتالي لن تنتشر مع فرعك ولن تنجو من حذفه.

إذا تم تحديد `shelve --list`، فسيتم سرد التغييرات المخزنة مسبقًا.

الغرض من `shelve` هو المساعدة في فصل مجموعات متعددة من التغييرات التي تم خلطها بشكل غير صحيح. إذا كنت ترغب فقط في التخلص من جميع التغييرات ولا تحتاج إلى استعادتها لاحقًا، فاستخدم `revert`. إذا كنت ترغب في وضع جميع تغييرات النص جانبًا دفعة واحدة، فاستخدم `shelve --all`.

إذا تم تحديد أسماء الملفات، فسيتم وضع التغييرات على هذه الملفات فقط جانبًا. سيتم ترك الملفات الأخرى دون تغيير.
