buildah-run(1)

الحزمة: buildah

التراخيص: Apache-2.0

NAME

buildah-run

- Run a command inside a working container.

SYNOPSIS

buildah run [—annotation=key=value] [—authfile=path] [—block-device=path] [—cap=capability] [—cap-add=capability] [—cap-drop=capability] [—cgroup-conf=path] [—cgroupns=cgroupns] [—cmd=command] [—conmon=path] [—cpu-shares=n] [—device=path[:path[:mode]]] [—device-cgroup-rule=rule] [—device-cgroup-devices=devices] [—device-read-bps=path=rate] [—device-read-iops=path=ops] [—device-write-bps=path=rate] [—device-write-iops=path=ops] [—dev=bool] [—dns=ip] [—dns-opt=opt] [—dns-search=domain] [—entrypoint=command] [—env=var] [—env-file=path] [—exec=path] [—gidmap=gidmap] [—group=group] [—health-cmd=command] [—health-fail-count=n] [—health-interval=duration] [—health-retries=n] [—health-start-period=duration] [—health-timeout=duration] [—host=path] [—hostname=name] [—hooks-dir=path] [—image-volume=name] [—ip=ip] [—ip6=ip6] [—kernel-memory=bytes] [—label=key=value] [—label-file=path] [—legacy=bool] [—link=name=alias] [—log-driver=driver] [f—log-opt=key=value] [—mac-address=mac] [—memory=bytes] [—memory-reservation=bytes] [—memory-swap=bytes] [—mount=type=bind,src=path,dst=path[,ro]] [—mounts-file=path] [—name=name] [—network=namespace] [—no-healthcheck] [—oom-score-adj=n] [—pid=pid] [—pids-limit=n] [—platform=platform] [—privileged] [—pull-always=bool] [—pull-never=bool] [—quiet] [—read-only] [—read-only-volume=name] [—restart=policy] [—rm] [—rootfs-image=image] [—runtime=path] [—runtime-arg=arg] [—security-opt=label] [—stop-timeout=duration] [—sysctl=key=value] [—tmpfs=path] [—tty] [—ulimit=ulimit] [—user=user] [—uts=uts] [—volume=path:path[:mode]] [—volumes-from=container] [—workdir=dir] [—`command`...] containerID [—] [args...])

DESCRIPTION

The buildah run command runs a command inside of a container. It can be used to execute commands in a container that has already been created and started.

The buildah run command allows you to mount volumes inside of a container. You can specify volumes with the —volume or —mount options. When using the —volume option, the syntax is host-path:container-path:options. The options can include ro for read-only access, and z or Z for SELinux separation. The z option labels the volume content so that it may be shared by multiple containers, and the Z option labels the volume content so that it may be used only by the current container.

When using the —mount option, the syntax is type=TYPE,src=HOST-PATH,dst=CONTAINER-PATH[,OPTIONS]. Currently, only type=bind is supported.

If the container is not created with the —mount option, then any mounts specified with the —volume option are only visible to the container. However, if the container is created with the —mount option, then any mounts specified with the —mount option will be visible inside of the container. Any mounts completed on the host for that volume will be visible only inside of the container. To control the mount propagation property of the volume use the —mount option with the :rshared, :rslave or :rprivate propagation flag. The propagation property can be specified only for bind mounted volumes and not for internal volumes or named volumes. For mount propagation to work on the source mount point (the mount point where source dir is mounted on) it has to have the right propagation properties. For shared volumes, the source mount point has to be shared. And for slave volumes, the source mount has to be either shared or slave. [1] ⟨#Footnote1⟩

Use df <source-dir> to determine the source mount and then use findmnt -o TARGET,PROPAGATION <source-mount-dir> to determine propagation properties of source mount, if findmnt utility is not available, the source mount point can be determined by looking at the mount entry in /proc/self/mountinfo. Look at optional fields and see if any propagation properties are specified. shared:X means the mount is shared, master:X means the mount is slave and if nothing is there that means the mount is private. [1] ⟨#Footnote1⟩

To change propagation properties of a mount point use the mount command. For example, to bind mount the source directory /foo do mount --bind /foo /foo and mount --make-private --make-shared /foo. This will convert /foo into a shared mount point. The propagation properties of the source mount can be changed directly. For instance if / is the source mount for /foo, then use mount --make-shared / to convert / into a shared mount.

--workingdir directory

Temporarily set the working directory for the running process. Unlike buildah config --workingdir, the workingdir will not persist to later calls to buildah run or the built image.

NOTE: End parsing of options with the —— option, so that other options can be passed to the command inside of the container.

EXAMPLE

buildah run containerID -- ps -auxw

buildah run --hostname myhost containerID -- ps -auxw

buildah run containerID -- sh -c 'echo $PATH'

buildah run --runtime-flag log-format=json containerID /bin/bash

buildah run --runtime-flag debug containerID /bin/bash

buildah run --tty containerID /bin/bash

buildah run --tty=false containerID ls /

buildah run --volume /path/on/host:/path/in/container:ro,z containerID sh

buildah run -v /path/on/host:/path/in/container:z,U containerID sh

buildah run --mount type=bind,src=/tmp/on:host,dst=/in:container,ro containerID sh

FOOTNOTES

⟨1⟩ The Buildah project is committed to inclusivity, a core value of open source. The master and slave mount propagation terminology used here is problematic and divisive, and should be changed. However, these terms are currently used within the Linux kernel and must be used as-is at this time. When the kernel maintainers rectify this usage, Buildah will follow suit immediately.
