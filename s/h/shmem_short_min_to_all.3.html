الوصف

تقوم روتينات الذاكرة المشتركة (SHMEM) للحسابات المجمعة بإجراء حسابات مجمعة واحدة أو أكثر على مصفوفات متناظرة عبر وحدات معالجة افتراضية متعددة. تقوم الحسابات المجمعة بإجراء عملية ثنائية ترابطية عبر مجموعة من القيم. للحصول على قائمة بروتينات SHMEM المجمعة الأخرى، انظر intro_shmem(3).

كما هو الحال مع جميع روتينات SHMEM الجماعية، تفترض كل هذه الروتينات أن وحدات المعالجة في المجموعة النشطة هي فقط التي تستدعي الروتين. إذا استدعت وحدة معالجة ليست في المجموعة النشطة روتين SHMEM جماعي، فستكون النتيجة سلوكًا غير محدد.

يحدد الوسيط nreduce عدد العمليات المجمعة المنفصلة المراد إجراؤها. توفر مصفوفة المصدر على جميع وحدات المعالجة في المجموعة النشطة عنصرًا واحدًا لكل عملية تجميع. يتم وضع نتائج العمليات المجمعة في مصفوفة الهدف على جميع وحدات المعالجة في المجموعة النشطة. يتم تحديد المجموعة النشطة بواسطة ثلاثي PE_start، logPE_stride، PE_size.

قد تكون مصفوفات المصدر والهدف هي نفس المصفوفة، لكن لا يمكن أن تكون مصفوفات متداخلة.

الوسطاء هم كما يلي:

target
مصفوفة متناظرة بطول nreduce عنصر لتلقي نتائج عمليات التجميع. يختلف نوع بيانات target مع إصدار روتين التجميع الذي يتم استدعاؤه. عند الاستدعاء من C/C++، ارجع إلى قسم الملخص للحصول على معلومات نوع البيانات. عند الاستدعاء من Fortran، أنواع بيانات الهدف هي كما يلي:

shmem_int4_min_to_all: عدد صحيح، بحجم عنصر 4 بايت

shmem_int8_min_to_all: عدد صحيح، بحجم عنصر 8 بايت

shmem_real4_min_to_all: حقيقي، بحجم عنصر 4 بايت

shmem_real8_min_to_all: حقيقي، بحجم عنصر 8 بايت

shmem_real16_min_to_all: حقيقي، بحجم عنصر 16 بايت

source
مصفوفة متناظرة بطول nreduce عنصر، تحتوي على عنصر واحد لكل عملية تجميع منفصلة. يجب أن يكون الوسيط source له نفس نوع بيانات target.
nreduce
عدد العناصر في مصفوفات target و source. يجب أن يكون nreduce من نوع integer. إذا كنت تستخدم Fortran، فيجب أن تكون قيمة integer افتراضية.
PE_start
أقل رقم PE افتراضي للمجموعة النشطة من وحدات المعالجة. يجب أن يكون PE_start من نوع integer. إذا كنت تستخدم Fortran، فيجب أن تكون قيمة integer افتراضية.
logPE_stride
اللوغاريتم (الأساس 2) للخطوة بين أرقام PE الافتراضية المتتالية في المجموعة النشطة. يجب أن يكون logPE_stride من نوع integer. إذا كنت تستخدم Fortran، فيجب أن تكون قيمة integer افتراضية.
PE_size
عدد وحدات المعالجة في المجموعة النشطة. يجب أن يكون PE_size من نوع integer. إذا كنت تستخدم Fortran، فيجب أن تكون قيمة integer افتراضية.
pWrk
مصفوفة عمل متناظرة. يجب أن يكون للوسيط pWrk نفس نوع بيانات target. في C/C++، تحتوي على max(nreduce/2 + 1, _SHMEM_REDUCE_MIN_WRKDATA_SIZE) عنصرًا. في Fortran، تحتوي على max(nreduce/2 + 1, SHMEM_REDUCE_MIN_WRKDATA_SIZE) عنصرًا.
pSync
مصفوفة عمل متناظرة. في C/C++، pSync من نوع long وحجم _SHMEM_REDUCE_SYNC_SIZE. في Fortran، pSync من نوع integer وحجم SHMEM_REDUCE_SYNC_SIZE. إذا كنت تستخدم Fortran، فيجب أن تكون قيمة integer افتراضية. يجب تهيئة كل عنصر من هذه المصفوفة بالقيمة _SHMEM_SYNC_VALUE (في C/C++) أو SHMEM_SYNC_VALUE (في Fortran) قبل أن تدخل أي من وحدات المعالجة في المجموعة النشطة روتين التجميع.

يجب أن تكون قيم الوسطاء nreduce و PE_start و logPE_stride و PE_size متساوية على جميع وحدات المعالجة في المجموعة النشطة. يجب تمرير نفس مصفوفات target و source، ونفس مصفوفات العمل pWrk و pSync، إلى جميع وحدات المعالجة في المجموعة النشطة.

قبل أن تستدعي أي وحدة معالجة روتين تجميع، يجب عليك التأكد من وجود الشروط التالية (غالبًا ما تكون هناك حاجة لمزامنة عبر حاجز أو طريقة أخرى لضمان ذلك): مصفوفات pWrk و pSync على جميع وحدات المعالجة في المجموعة النشطة لا تزال قيد الاستخدام من استدعاء سابق لروتين SHMEM جماعي. مصفوفة target على جميع وحدات المعالجة في المجموعة النشطة جاهزة لاستقبال نتائج التجميع.

عند العودة من روتين تجميع، تكون الأمور التالية صحيحة لوحدة المعالجة المحلية: تم تحديث مصفوفة target. تم استعادة قيم مصفوفة pSync إلى القيم الأصلية.

ملاحظات

المصطلحات الجماعية، المتناظرة، والمتوافقة مع الذاكرة المخبأة معرفة في intro_shmem(3). جميع روتينات SHMEM المجمعة تعيد تعيين القيم في pSync قبل أن تعود، لذلك لا يلزم تهيئة مخزن pSync المعين إلا في المرة الأولى التي يتم استخدامه فيها.

يجب عليك التأكد من أن مصفوفة pSync لا يتم تحديثها على أي وحدة معالجة في المجموعة النشطة أثناء مشاركة أي من وحدات المعالجة في معالجة روتين SHMEM تجميع. كن حذرًا من المواقف التالية: إذا تم تهيئة مصفوفة pSync وقت التشغيل، فيلزم نوع من المزامنة لضمان أن جميع وحدات المعالجة في مجموعة العمل قد قامت بتهيئة pSync قبل أن يدخل أي منها روتين SHMEM يتم استدعاؤه مع مصفوفة المزامنة pSync. يمكن إعادة استخدام مصفوفة pSync أو pWrk في استدعاء روتين تجميع لاحق فقط إذا لم تكن أي من وحدات المعالجة في المجموعة النشطة لا تزال تعالج استدعاء روتين تجميع سابق استخدم نفس مصفوفات pSync أو pWrk. بشكل عام، لا يمكن ضمان ذلك إلا عن طريق القيام بنوع من المزامنة. ومع ذلك، في الحالة الخاصة لروتينات التجميع التي يتم استدعاؤها بنفس المجموعة النشطة، يمكنك تخصيص مصفوفتي pSync و pWrk والتبديل بينهما في الاستدعاءات المتتالية.

SYNOPSIS

This man page is part of the Open MPI package. Open MPI is a project that aims to be the most complete and widely used implementation of MPI (Message Passing Interface) and related standards.

The following synopsis is for the Fortran interface:

SUBROUTINE SHMEM_REAL8_MIN_TO_ALL( target, source, nlong, logPe, pe,
& npes, pWrk, pSync )
INTEGER :: target, source, nlong, logPe, pe, npes
REAL(8) :: pWrk(*)
INTEGER :: pSync(*)
END SUBROUTINE SHMEM_REAL8_MIN_TO_ALL

The following synopsis is for the C/C++ interface:

void shmem_real8_min_to_all( double *target, const double *source,
& size_t nlong, int logPe, int pe, int npes,
& void *pWrk, long pSync[] );

DESCRIPTION

The shmem_real8_min_to_all routines perform a global minimum reduction operation. The input values are taken from the source array on each processing element (PE), and the result is placed in the target array on all PEs. The reduction operation is the minimum of the real8 (double-precision floating-point) values.

The reduction is performed across the PEs specified by the arguments pe and npes. The logPe argument indicates whether the reduction is performed across all PEs (logPe = 0) or across PEs in a participating group (logPe = 1).

The nlong argument specifies the number of elements in the source and target arrays.

The pWrk argument is a pointer to a working array that must be provided by the caller. The size of this array is dependent on the number of PEs involved in the reduction and the size of the data type being reduced. The caller must ensure that pWrk is large enough to accommodate the reduction operation.

The pSync argument is a synchronization array that must be provided by the caller. This array is used to ensure that all PEs involved in the reduction have completed their operations before proceeding. The size of this array is specified by the SHMEM_REDUCE_SYNC_SIZE macro (in Fortran) or can be determined by the implementation (in C/C++).

NOTES

The shmem_real8_min_to_all routine is a collective operation that must be called by all PEs in the participating group. All calls within a participating group must have the same values for nlong, logPe, pe, npes, and the size of pWrk and pSync.

The source and target arrays may be the same. In this case, the reduction is performed in place.

The pSync array must be initialized with the value SHMEM_SYNC_VALUE (in Fortran) or the appropriate synchronization value (in C/C++). After the call, the pSync array will contain updated synchronization values.

EXAMPLES

Example 1: Fortran code snippet:

INCLUDE "mpp/shmem.fh"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL FOO, FOOMIN, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOMIN, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_REAL8_MIN_TO_ALL(FOOMIN, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOMIN
ENDIF

Example 2: Consider the following C/C++ call:

shmem_int_min_to_all( target, source, 3, 0, 0, 8, pwrk, psync );

The preceding call is more efficient, but semantically equivalent to, the combination of the following calls:

shmem_int_min_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_int_min_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_int_min_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);

Note that two sets of pWrk and pSync arrays are used alternately because no synchronization is done between calls.
