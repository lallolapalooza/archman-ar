NAME

\n

shard.yml - metadata for projects managed by shards(1)

\n
\n
\n

DESCRIPTION

\n

The file shard.yml is a YAML file with metadata about a\n project managed by shards, known as a shard. It must contain at least\n name and version attributes plus optional additional\n attributes.

\n

Both libraries and applications will benefit from\n shard.yml.

\n

The metadata for libraries are expected to have more information\n (e.g., list of authors, description, license) than applications that may\n only have a name, version and dependencies.

\n
\n
\n

FORMAT

\n

The file must be named shard.yml and be a valid YAML file\n with UTF-8 encoding. It must not contain duplicate attributes in any\n mapping. It should use an indent of 2 spaces. It should not use advanced\n YAML features, only simple mappings, sequences and strings (Failsafe\n Schema).

\n
\n
\n

REQUIRED ATTRIBUTES

\n

name

\n
The name of the project (string, required).\n
•It must be unique.
\n
•It must be 50 characters or less.
\n
•It should be lowercase (a-z).
\n
•It should not contain crystal.
\n
•It may contain digits (0-9) but not start with\n one.
\n
•It may contain underscores or dashes but not\n start/end with one.
\n
•It must not have consecutive underscores or\n dashes.
\n

Examples: minitest, mysql2,\n battery-horse.

\n
\n

version

\n
The version number of the project (string, required).\n
•It must contain digits.
\n
•It may contain dots and dashes but not\n consecutive ones.
\n
•It may contain a letter to make it a\n 'prerelease'.
\n

Examples: 1.2.3, 2.0.0.1, 1.0.0.alpha\n 2.0.0-rc1 or 2016.09.

\n

While Shards doesn’t enforce it, following a rational\n versioning scheme like Semantic Versioning http://semver.org/\n or Calendar Versioning http://calver.org/ is highly\n recommended.

\n
\n
\n
\n

OPTIONAL ATTRIBUTES

\n

authors

\n
A list of authors, along with their contact email\n (optional) (sequence of string).\n
•Each author must have a name.
\n
•Each author may have an email address, within\n angle bracket (< and >) chars.
\n

Example:

\n
\n
authors:\n- Ary\n- Julien Portalier <julien@example.org>
\n
\n
\n

crystal

\n
A restriction to indicate which are the supported crystal\n versions. This will usually express a lower and upper-bound constraints\n (string, recommended)\n

When resolving dependencies, this information is not used. After\n dependencies have been determined shards checks all of them are expected to\n work with the current crystal version. If not, a warning appears for the\n offending dependencies. The resolved versions are installed and can be used\n at your own risk.

\n

The valid values are mostly the same as for\n dependencies.version:

\n
•A version number prefixed by an operator:\n <, <=, >, >=, != or\n ~>.
\n
•Just \"*\" if any version will do\n (this is the default if unspecified).
\n
•Multiple requirements can be separated by\n commas.
\n

There is a special legacy behavior (its use is discouraged) when\n just a version number is used as the value: it works exactly the same as a\n >= check: x.y.z is interpreted as\n \">= x.y.z\"

\n

You are welcome to also specify the upper bound to be lower than\n the next (future) major Crystal version, because there’s no guarantee\n that it won’t break your library.

\n

Example:

\n
\n
crystal: \">= 0.35, < 2.0\"
\n
\n
\n

dependencies

\n
A list of required dependencies (mapping).\n

Each dependency begins with the name of the dependency as a key\n (string) then a list of attributes (mapping) that depend on the resolver\n type.

\n

Example:

\n
\n
dependencies:\n  minitest:\n    github: ysbaddaden/minitest.cr\n    version: 0.1.0
\n
\n
\n

development_dependencies

\n
A list of dependencies required to work on the project,\n but not necessary to build and run the project (mapping).\n

They will be installed for the main project or library itself.\n When the library is installed as a dependency for another project the\n development dependencies will never be installed.

\n

Development dependencies follow the same scheme as\n dependencies.

\n

Example:

\n
\n
development_dependencies:\n  minitest:\n    github: ysbaddaden/minitest.cr\n    version: ~> 0.1.3
\n
\n
\n

description

\n
A single line description of the project (string,\n recommended).
\n

documentation

\n
The URL to a website providing the project’s\n documentation for online browsing (string).
\n

executables

\n
A list of executables to be installed (sequence).\n

The executables can be of any type or language (e.g., shell,\n binary, ruby), must exist in the bin folder of the Shard, and have\n the executable bit set (on POSIX platforms). When installed as a dependency\n for another project the executables will be copied to the bin folder\n of that project.

\n

Executables are always installed last, after the\n postinstall script is run, so libraries can build the executables\n when they are installed by Shards. Installation can be disabled by passing\n the flag --skip-executables.

\n

Example:

\n
\n
executables:\n- micrate\n- icr
\n
\n
\n

homepage

\n
The URL of the project’s homepage (string).
\n

libraries

\n
A list of shared libraries the shard tries to link to\n (mapping).\n

This field is purely informational. It serves as a canonical way\n to discover non Crystal dependencies in shards, both for tools as well as\n humans.

\n

A shard must only list libraries it directly links to, it must not\n include libraries that are only referenced by dependencies. It must include\n all libraries it directly links to, regardless of a dependency doing it\n too.

\n

It should map from the soname without any extension, path or\n version, for example libsqlite3 for\n /usr/lib/libsqlite3.so.0.8.6, to a version constraint.

\n

The version constraint has the following format:

\n
•It may be a version number.
\n
•It may be \"*\" if any version\n will do.
\n
•The version number may be prefixed by an\n operator: <, <=, >, >=, != or\n ~>.
\n
\n
libraries:\n  libQt5Gui: \"*\"\n  libQt5Help: \"~> 5.7\"\n  libQtBus: \">>= 4.8\"\n
\n
\n
\n

license

\n
An SPDX license expression\n https://spdx.github.io/spdx-spec/v3.0.1/annexes/spdx-license-expressions/\n or an URL to a license file (string, recommended).\n

The OSI publishes a list\n https://opensource.org/licenses-old/category of open source licenses\n and their corresponding SPDX identifiers.

\n

Examples: Apache-2.0, GPL-3.0-or-later,\n Apache-2.0 OR MIT, Apache-2.0 WITH Swift-exception, https://example.com/LICENSE.

\n
\n

repository

\n
The URL of the project’s canonical repository\n (string, recommended).\n

The URL should be compatible with typical VCS tools without\n modif

\n
\n
