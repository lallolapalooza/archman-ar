الوصف (DESCRIPTION)

تقوم روتينات الذاكرة المشتركة (SHMEM) الجماعية بحساب عملية تجميع واحدة أو أكثر عبر مصفوفات متماثلة على وحدات معالجة افتراضية متعددة. عملية التجميع تقوم بتطبيق عملية ثنائية ترابطية عبر مجموعة من القيم. لقائمة بروتينات التجميع الأخرى لـ SHMEM، انظر intro_shmem(3).

كما هو الحال مع جميع روتينات SHMEM الجماعية، تفترض كل من هذه الروتينات أن وحدات المعالجة (PEs) ضمن المجموعة النشطة فقط هي التي تستدعي الروتين. إذا قامت وحدة معالجة (PE) ليست ضمن المجموعة النشطة باستدعاء روتين جماعي لـ SHMEM، فستكون النتيجة غير محددة.

يحدد الوسيط `nreduce` عدد عمليات التجميع المنفصلة المراد إجراؤها. مصفوفة المصدر (`source`) على جميع وحدات المعالجة (PEs) في المجموعة النشطة توفر عنصرًا واحدًا لكل عملية تجميع. توضع نتائج عمليات التجميع في المصفوفة المستهدفة (`target`) على جميع وحدات المعالجة (PEs) في المجموعة النشطة. يتم تعريف المجموعة النشطة بواسطة الثلاثي `PE_start`, `logPE_stride`, `PE_size`.

قد تكون مصفوفتا المصدر والمستهدف نفس المصفوفة، ولكنهما لا يمكن أن تكونا مصفوفتين متداخلتين.

الوسائط هي كما يلي:

target
كائن البيانات الصحيح القابل للوصول عن بعد الذي سيتم تحديثه على وحدة المعالجة (PE) البعيدة. إذا كنت تستخدم C/C++، يجب أن يتطابق نوع `target` مع النوع المشار إليه في قسم الملخص (SYNOPSIS). إذا كنت تستخدم مترجم Fortran، فيجب أن يكون من نوع عدد صحيح (integer) بحجم عنصر 4 بايت لـ SHMEM_INT4_ADD و 8 بايت لـ SHMEM_INT8_ADD.
value
القيمة المراد إضافتها بشكل ذري إلى `target`. إذا كنت تستخدم C/C++، يجب أن يتطابق نوع `value` مع النوع المشار إليه في قسم الملخص (SYNOPSIS). إذا كنت تستخدم Fortran، فيجب أن يكون من نوع عدد صحيح (integer) بنفس حجم عنصر `target`.
pe
عدد صحيح يشير إلى رقم وحدة المعالجة (PE) المستهدفة للتحديث. إذا كنت تستخدم Fortran، فيجب أن يكون قيمة عدد صحيح افتراضية.
target
مصفوفة متماثلة بطول `nreduce` عنصر لاستقبال نتائج عمليات التجميع.
نوع بيانات `target` يختلف حسب إصدار روتين التجميع المستخدم واللغة. عند الاستدعاء من C/C++، ارجع إلى قسم الملخص (SYNOPSIS) لمعلومات نوع البيانات.
عند الاستدعاء من Fortran، أنواع بيانات `target` هي كما يلي:

shmem_comp4_sum_to_all:** COMPLEX(KIND=4).

shmem_comp8_sum_to_all:** Complex. إذا كنت تستخدم Fortran، فيجب أن يكون
قيمة مركبة (complex) افتراضية.

shmem_int4_sum_to_all:** INTEGER(KIND=4).

shmem_int8_sum_to_all:** Integer. إذا كنت تستخدم Fortran، فيجب أن يكون
قيمة عدد صحيح (integer) افتراضية.

shmem_real4_sum_to_all:** REAL(KIND=4).

shmem_real8_sum_to_all:** Real. إذا كنت تستخدم Fortran، فيجب أن يكون
قيمة حقيقية (real) افتراضية.
shmem_real16_sum_to_all:** Real. إذا كنت تستخدم Fortran، فيجب أن يكون
قيمة حقيقية (real) افتراضية.
source
مصفوفة متماثلة، بطول `nreduce` عنصر، تحتوي على عنصر واحد لكل عملية تجميع منفصلة. يجب أن يكون للوسيط `source` نفس نوع بيانات `target`.
nreduce
عدد العناصر في مصفوفتي `target` و `source`. يجب أن يكون `nreduce` من نوع عدد صحيح (integer). إذا كنت تستخدم Fortran، فيجب أن يكون قيمة عدد صحيح افتراضية.
PE_start
أصغر رقم وحدة معالجة افتراضية (PE) في المجموعة النشطة من وحدات المعالجة (PEs). يجب أن يكون `PE_start` من نوع عدد صحيح (integer). إذا كنت تستخدم Fortran، فيجب أن يكون قيمة عدد صحيح افتراضية.
logPE_stride
لوغاريتم (الأساس 2) للخطوة بين أرقام وحدات المعالجة الافتراضية (PEs) المتتالية في المجموعة النشطة. يجب أن يكون `logPE_stride` من نوع عدد صحيح (integer). إذا كنت تستخدم Fortran، فيجب أن يكون قيمة عدد صحيح افتراضية.
PE_size
عدد وحدات المعالجة (PEs) في المجموعة النشطة. يجب أن يكون `PE_size` من نوع عدد صحيح (integer). إذا كنت تستخدم Fortran، فيجب أن يكون قيمة عدد صحيح افتراضية.
pWrk
مصفوفة عمل متماثلة. يجب أن يكون للوسيط `pWrk` نفس نوع بيانات `target`. في C/C++، تحتوي على `max(nreduce/2 + 1, _SHMEM_REDUCE_MIN_WRKDATA_SIZE)` عنصر. في Fortran، تحتوي على `max(nreduce/2 + 1, SHMEM_REDUCE_MIN_WRKDATA_SIZE)` عنصر.
pSync
مصفوفة عمل متماثلة. في C/C++، `pSync` من نوع `long` وبحجم `_SHMEM_REDUCE_SYNC_SIZE`. في Fortran، `pSync` من نوع عدد صحيح (integer) وبحجم `SHMEM_REDUCE_SYNC_SIZE`. يجب أن تكون قيمة عدد صحيح افتراضية. يجب تهيئة كل عنصر في هذه المصفوفة بالقيمة `_SHMEM_SYNC_VALUE` (في C/C++) أو `SHMEM_SYNC_VALUE` (في Fortran) قبل أن تدخل أي من وحدات المعالجة (PEs) في المجموعة النشطة إلى روتين التجميع.

shmem_longlong_sum_to_all(3) — Arch manual pages

SYNOPSIS

Fortran:

   INCLUDE "mpp/shmem.fh"
   CALL SHMEM_LONG_LONG_SUM_TO_ALL(target, source, nreduce, PE_start,
                               logPE_stride, PE_size, pWrk, pSync)
   CALL SHMEM_LONG_LONG_SUM_TO_ALL_FC(target, source, nreduce, PE_start,
                                   logPE_stride, PE_size, pWrk, pSync)

C/C++:

   #include <mpp/shmem.h>
   void shmem_longlong_sum_to_all(long long *target,
                                  const long long *source,
                                  int nreduce, int PE_start,
                                  int logPE_stride, int PE_size,
                                  long long *pWrk,
                                  long long *pSync);

DESCRIPTION

All processes in the execution group execute a reduction operation. The reduction operation is a sum. The reduction operation is applied across the elements specified by nreduce. The source data is obtained from the array source. The reduction is applied to all elements in the source array specified by nreduce. The results of the reduction are placed in the array target. The reduction operation is symmetric.

The active set of PEs is determined by PE_start, logPE_stride, and PE_size. If PE_size is 0 or negative, then it is assumed to be the total number of PEs in the symmetric program. Otherwise, the active set consists of PE_size PEs. The first PE in the set is PE_start. The stride between PEs in the active set is determined by logPE_stride such that the stride is 2**logPE_stride. All PEs in the active set must execute this routine.

The elements in the source and target arrays are combined using the reduction operation. The element source[i] is combined with the element target[i] for all i from 0 to nreduce-1.

The pWrk array is a work array that must be the same size on all PEs in the active set. The size of the pWrk array is dependent on the number of elements being reduced. The minimum size of the pWrk array is given by the constant SHMEM_LONG_LONG_REDUCE_MIN_WRKDATA_SIZE.

The pSync array is a synchronization array. It must be the same size on all PEs in the active set. The size of the pSync array is given by the constant SHMEM_REDUCE_SYNC_SIZE. The pSync array is used to synchronize the PEs during the reduction operation. All elements of the pSync array must be initialized to SHMEM_SYNC_VALUE prior to the call.

The values of arguments nreduce, PE_start, logPE_stride, and PE_size must be equal on all PEs in the active set. The same target and source arrays, and the same pWrk and pSync work arrays, must be passed to all PEs in the active set.

Before any PE calls a reduction routine, you must ensure that the following conditions exist (synchronization via a barrier or some other method is often needed to ensure this): The pWrk and pSync arrays on all PEs in the active set are not still in use from a prior call to a collective SHMEM routine. The target array on all PEs in the active set is ready to accept the results of the reduction.

Upon return from a reduction routine, the following are true for the local PE: The target array is updated. The values in the pSync array are restored to the original values.

NOTES

The terms collective, symmetric, and cache aligned are defined in intro_shmem(3).

All SHMEM reduction routines reset the values in pSync before they return, so a particular pSync buffer need only be initialized the first time it is used.

You must ensure that the pSync array is not being updated on any PE in the active set while any of the PEs participate in processing of a SHMEM reduction routine. Be careful of the following situations: If the pSync array is initialized at run time, some type of synchronization is needed to ensure that all PEs in the working set have initialized pSync before any of them enter a SHMEM routine called with the pSync synchronization array. A pSync or pWrk array can be reused in a subsequent reduction routine call only if none of the PEs in the active set are still processing a prior reduction routine call that used the same pSync or pWrk arrays. In general, this can be assured only by doing some type of synchronization. However, in the special case of reduction routines being called with the same active set, you can allocate two pSync and pWrk arrays and alternate between them on successive calls.

EXAMPLES

Example 1: This Fortran example statically initializes the pSync array and finds the sum of the real variable FOO across all even PEs.

INCLUDE "mpp/shmem.fh"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL FOO, FOOSUM, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOSUM, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_INT4_SUM_TO_ALL(FOOSUM, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOSUM
ENDIF

Example 2: Consider the following C/C++ call:

shmem_int_sum_to_all( target, source, 3, 0, 0, 8, pwrk, psync );

The preceding call is more efficient, but semantically equivalent to, the combination of the following calls:

shmem_int_sum_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_int_sum_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_int_sum_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);
Note that two sets of pWrk and pSync arrays are used alternately because no
synchronization is done between calls.
