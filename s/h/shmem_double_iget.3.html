الوصف

تسترد إجراءات الحصول المتدرج بيانات المصفوفة المتوفرة في العنوان source على PE البعيد (pe). يتم فصل عناصر مصفوفة source بفاصل sst. بمجرد استلام البيانات، يتم تخزينها في عنوان الذاكرة المحلي target، مفصولة بفاصل tst. تعود الإجراءات عند نسخ البيانات إلى مصفوفة target المحلية.

الوسائط هي كما يلي:

target
المصفوفة التي سيتم تحديثها في PE المحلي.
source
المصفوفة التي تحتوي على البيانات المراد نسخها على PE البعيد.
tst
الفاصل بين العناصر المتتالية لمصفوفة الهدف. يتم قياس الفاصل بواسطة حجم العنصر لمصفوفة الهدف. تشير القيمة 1 إلى بيانات متجاورة. يجب أن يكون tst من نوع عدد صحيح. إذا كنت تستدعي من Fortran، فيجب أن تكون قيمة عدد صحيح افتراضية.
sst
الفاصل بين العناصر المتتالية لمصفوفة المصدر. يتم قياس الفاصل بواسطة حجم العنصر لمصفوفة المصدر. تشير القيمة 1 إلى بيانات متجاورة. يجب أن يكون sst من نوع عدد صحيح. إذا كنت تستدعي من Fortran، فيجب أن تكون قيمة عدد صحيح افتراضية.
len
عدد العناصر في مصفوفتي الهدف والمصدر. يجب أن يكون len من نوع عدد صحيح. إذا كنت تستخدم Fortran، فيجب أن يكون ثابتًا أو متغيرًا أو عنصر مصفوفة من نوع عدد صحيح افتراضي.
pe
رقم PE للـ PE البعيد. يجب أن يكون pe من نوع عدد صحيح. إذا كنت تستخدم Fortran، فيجب أن يكون ثابتًا أو متغيرًا أو عنصر مصفوفة من نوع عدد صحيح افتراضي.

أمثلة

يستخدم المثال البسيط التالي shmem_logical_iget في برنامج Fortran. قم بتجميع هذا المثال باستخدام خيار المترجم -lsma.

PROGRAM STRIDELOGICAL
  LOGICAL SOURCE(10), TARGET(5)
  SAVE SOURCE ! SAVE MAKES IT REMOTELY ACCESSIBLE
  DATA SOURCE /.T.,.F.,.T.,.F.,.T.,.F.,.T.,.F.,.T.,.F./
  DATA TARGET / 5*.F. /
  CALL START_PES(2)
  IF (MY_PE() .EQ. 0) THEN
    CALL SHMEM_LOGICAL_IGET(TARGET, SOURCE, 1, 2, 5, 1)
    PRINT*,'TARGET AFTER SHMEM_LOGICAL_IGET:',TARGET
  ENDIF
  CALL SHMEM_BARRIER_ALL
END

ملخص

int shmem_double_iget(void *target, const void *source, size_t len, int pe);

الوصف

الدالة shmem_double_iget هي جزء من مكتبة OpenSHMEM وهي مصممة لتنفيذ عملية نقل غير متزامن لقيم مزدوجة (double-precision floating-point numbers) بين العمليات. تأخذ الدالة المؤشر إلى الذاكرة المستهدفة (target) التي سيتم فيها تخزين البيانات المستلمة، والمؤشر إلى الذاكرة المصدر (source) التي تحتوي على البيانات المراد إرسالها. تحدد len طول البيانات بالبايت، و pe هو معرف العملية (process element) التي سيتم إرسال البيانات إليها.

تُعتبر هذه العملية غير متزامنة لأنها تبدأ عملية نقل البيانات في الخلفية ولا تنتظر اكتمالها. يجب على المبرمج التأكد من أن البيانات المستهدفة جاهزة للاستخدام بعد اكتمال عملية النقل، وغالبًا ما يتم ذلك باستخدام دالة انتظار مناسبة أو من خلال آلية أخرى لضمان التزامن.

ملاحظات

تتطلب هذه الدالة وجود بيئة OpenSHMEM مهيأة بشكل صحيح. يجب أن تكون العمليات متزامنة على الأقل عند بدء عملية النقل.

قد تختلف تفاصيل التنفيذ والتحسينات بناءً على النظام الأساسي ومكتبة OpenSHMEM المستخدمة.

أمثلة

مثال بسيط يوضح كيفية استخدام shmem_double_iget: 

    #include <stdio.h>
    #include <shmem.h>

    int main(void) {
        double data_to_send = 123.45;
        double received_data;
        int my_pe, npes;

        shmem_init();
        my_pe = shmem_my_pe();
        npes = shmem_n_pes();

        if (npes < 2) {
            printf("This program requires at least two processes.\n");
            shmem_finalize();
            return 1;
        }

        int target_pe = (my_pe == 0) ? 1 : 0; // الإرسال إلى العملية الأخرى

        // إرسال البيانات بشكل غير متزامن
        shmem_double_iget(&received_data, &data_to_send, 1, target_pe);

        // هنا يجب انتظار اكتمال عملية النقل إذا لزم الأمر،
        // أو التأكد من أن البيانات المستهدفة لن تُستخدم قبل أن تصبح جاهزة.
        // في هذا المثال البسيط، نفترض أن الانتظار ضمني أو أننا لا نحتاج إلى البيانات فوراً.
        // في التطبيقات الحقيقية، قد تحتاج إلى استخدام shmem_quiet() أو آلية أخرى.

        if (my_pe == 0) {
             printf("Process 0 sent data.\n");
        } else {
             printf("Process 1 received data: %f\n", received_data);
        }

        shmem_finalize();
        return 0;
    }
