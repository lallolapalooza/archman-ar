الوصف

تقوم إجراءات التجميع الذاكرة المشتركة (SHMEM) بحساب عملية تجميع واحدة أو أكثر عبر مصفوفات متناظرة على العديد من وحدات معالجة افتراضية (PEs). يقوم التجميع بإجراء عملية ثنائية ترابطية عبر مجموعة من القيم. للحصول على قائمة بإجراءات التجميع الأخرى من SHMEM، راجع intro_shmem(3).

كما هو الحال مع جميع إجراءات SHMEM الجماعية، تفترض كل من هذه الإجراءات أن وحدات المعالجة الموجودة في المجموعة النشطة فقط هي التي تستدعي الإجراء. إذا استدعت وحدة معالجة غير موجودة في المجموعة النشطة إجراء SHMEM جماعيًا، فإن ذلك يؤدي إلى سلوك غير محدد.

يحدد وسيط nreduce عدد عمليات التجميع المنفصلة المراد إجراؤها. يوفر المصدر (source) في جميع وحدات المعالجة في المجموعة النشطة عنصرًا واحدًا لكل عملية تجميع. يتم وضع نتائج عمليات التجميع في الهدف (target) في جميع وحدات المعالجة في المجموعة النشطة. يتم تحديد المجموعة النشطة بواسطة الثلاثي PE_start، logPE_stride، PE_size.

قد تكون مصفوفتي المصدر والهدف نفس المصفوفة، ولكنهما لا يمكن أن تكونا مصفوفتين متداخلتين.

الوسائط هي كما يلي:

target
مصفوفة متناظرة بطول nreduce عنصر لاستقبال نتائج عمليات التجميع. يختلف نوع بيانات الهدف (target) حسب إصدار إجراء التجميع الذي يتم استدعاؤه واللغة المستخدمة. عند الاستدعاء من C/C++، ارجع إلى قسم الملخص لمعلومات نوع البيانات. عند الاستدعاء من Fortran، تكون أنواع بيانات الهدف كما يلي:
shmem_comp4_prod_to_all: مركب، بحجم عنصر يساوي اثنين
قيم حقيقية بحجم 4 بايت.
shmem_comp8_prod_to_all: مركب، بحجم عنصر يساوي اثنين
قيم حقيقية بحجم 8 بايت.

shmem_int4_prod_to_all: صحيح، بحجم عنصر 4 بايت

shmem_int8_prod_to_all: صحيح، بحجم عنصر 8 بايت

shmem_real4_prod_to_all: حقيقي، بحجم عنصر 4 بايت

shmem_real8_prod_to_all: حقيقي، بحجم عنصر 8 بايت

shmem_real16_prod_to_all: حقيقي، بحجم عنصر 16 بايت

source
مصفوفة متناظرة، بطول nreduce عنصر، تحتوي على عنصر واحد لكل عملية تجميع منفصلة. يجب أن يكون الوسيط source بنفس نوع بيانات target.
nreduce
عدد العناصر في مصفوفتي target و source. يجب أن يكون nreduce من نوع صحيح. إذا كنت تستخدم Fortran، فيجب أن يكون قيمة صحيحة افتراضية.
PE_start
أدنى رقم PE افتراضي للمجموعة النشطة من وحدات PE. يجب أن يكون PE_start من نوع صحيح. إذا كنت تستخدم Fortran، فيجب أن يكون قيمة صحيحة افتراضية.
logPE_stride
لوغاريتم (الأساس 2) للإزاحة بين أرقام PE الافتراضية المتتالية في المجموعة النشطة. يجب أن يكون logPE_stride من نوع صحيح. إذا كنت تستخدم Fortran، فيجب أن يكون قيمة صحيحة افتراضية.
PE_size
عدد وحدات PE في المجموعة النشطة. يجب أن يكون PE_size من نوع صحيح. إذا كنت تستخدم Fortran، فيجب أن يكون قيمة صحيحة افتراضية.
pWrk
مصفوفة عمل متناظرة. يجب أن يكون الوسيط pWrk بنفس نوع بيانات target. في C/C++، تحتوي على عناصر max(nreduce/2 + 1, _SHMEM_REDUCE_MIN_WRKDATA_SIZE). في Fortran، تحتوي على عناصر max(nreduce/2 + 1, SHMEM_REDUCE_MIN_WRKDATA_SIZE).
pSync
مصفوفة عمل متناظرة. في C/C++، يكون pSync من نوع long وبحجم _SHMEM_REDUCE_SYNC_SIZE. في Fortran، يكون pSync من نوع integer وبحجم SHMEM_REDUCE_SYNC_SIZE. إذا كنت تستخدم Fortran، فيجب أن يكون قيمة صحيحة افتراضية. قبل أن تدخل أي من وحدات PE في المجموعة النشطة إلى إجراء التجميع، يجب تهيئة كل عنصر من هذه المصفوفة بالقيمة _SHMEM_SYNC_VALUE (في C/C++) أو SHMEM_SYNC_VALUE (في Fortran).

يجب أن تكون قيم الوسائط nreduce، PE_start، logPE_stride، و PE_size متساوية في جميع وحدات PE في المجموعة النشطة. يجب تمرير نفس مصفوفتي target و source، ونفس مصفوفتي العمل pWrk و pSync إلى جميع وحدات PE في المجموعة النشطة. قبل أن تقوم أي وحدة PE باستدعاء إجراء تجميع، يجب التأكد من وجود الشروط التالية (غالبًا ما يكون المزامنة عبر حاجز أو طريقة أخرى ضرورية لضمان ذلك): مصفوفات pWrk و pSync على جميع وحدات PE في المجموعة النشطة لا تزال قيد الاستخدام من استدعاء سابق لإجراء SHMEM جماعي. مصفوفة target على جميع وحدات PE في المجموعة النشطة جاهزة لاستقبال نتائج التجميع.

عند العودة من إجراء تجميع، تكون الأمور التالية صحيحة بالنسبة لوحدة PE المحلية: تم تحديث مصفوفة target. تم استعادة القيم الموجودة في مصفوفة pSync إلى القيم الأصلية.

shmem_longlong_prod_to_all(3) — Open MPI Community

SYNOPSIS

Fortran 

INCLUDE "mpp/shmem.fh"
CALL SHMEM_LONG_LONG_PROD_TO_ALL(target, source, nlonglong, logpe, pe, npes, pwrk, psync)

DESCRIPTION

The SHMEM reduction function SHMEM_LONG_LONG_PROD_TO_ALL computes the product of values contained in the source array on each PE, and places the product in the target array on each PE. The reduction operation is performed across the PEs specified by the pe and npes arguments, or all PEs if pe and npes are 0. The reduction operation is associative, with an identity element of 1. The reduction operation is between elements of the same index within the source and target arrays.

The target, source, and pwrk arrays are allocated by the user. The psync array is used for synchronization.

The logpe argument specifies the PE ordering, and must be 0 or 1. If logpe is 0, the reduction is performed across PEs in the order specified by pe. If logpe is 1, the reduction is performed across PEs in a balanced tree fashion. Typically, logpe=1 is more efficient.

The pe and npes arguments specify the active set of PEs. If pe=0 and npes=0, then all PEs participate in the reduction. Otherwise, the active set consists of the npes PEs starting from PE number pe.

The nlonglong argument specifies the number of 64-bit integers in the target and source arrays.

The pwrk array is a user-allocated working array. The minimum size required for the pwrk array is defined by the constant SHMEM_REDUCE_MIN_WRKDATA_SIZE.

The psync array is a user-allocated synchronization array. The size required for the psync array is defined by the constant SHMEM_REDUCE_SYNC_SIZE.

NOTES

The psync array must be initialized to the value SHMEM_SYNC_VALUE before the first call to any SHMEM symmetric communication routine. It is assumed that the psync array has been initialized by all PEs in the working set prior to the first invocation of this routine. The SHMEM library routines are not re-entrant. You must ensure that the psync array is not being updated on any PE in the active set while any of the PEs participate in processing of a SHMEM reduction routine. Be careful of the following situations: If the psync array is initialized at run time, some type of synchronization is needed to ensure that all PEs in the working set have initialized psync before any of them enter a SHMEM routine called with the psync synchronization array. A psync or pwrk array can be reused in a subsequent reduction routine call only if none of the PEs in the active set are still processing a prior reduction routine call that used the same psync or pwrk arrays. In general, this can be assured only by doing some type of synchronization. However, in the special case of reduction routines being called with the same active set, you can allocate two psync and pwrk arrays and alternate between them on successive calls.

EXAMPLES

Example 1: This Fortran example statically initializes the psync array and finds the product of the real variable FOO across all the even PEs.

INCLUDE "mpp/shmem.fh"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL FOO, FOOPROD, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOPROD, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_COMP8_PROD_TO_ALL(FOOPROD, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOPROD
ENDIF

Example 2: Consider the following C/C++ call:

shmem_longlong_prod_to_all(target, source, 3, 0, 0, 8, pwrk, psync);

The preceding call is more efficient, but semantically equivalent to, the combination of the following calls:

shmem_longlong_prod_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_longlong_prod_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_longlong_prod_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);

Note that two sets of pwrk and psync arrays are used alternately because no synchronization is done between calls.
