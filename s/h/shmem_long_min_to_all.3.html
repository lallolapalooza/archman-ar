الوصف

تقوم روتينات تقليل الذاكرة المشتركة (SHMEM) بحساب عملية تقليل واحدة أو أكثر عبر مصفوفات متماثلة على عناصر معالجة افتراضية متعددة. تقوم عملية التقليل بتنفيذ عملية ثنائية ترابطية عبر مجموعة من القيم. لقائمة بروتينات تقليل SHMEM الأخرى، انظر intro_shmem(3).

كما هو الحال مع جميع بروتينات SHMEM الجماعية، يفترض كل من هذه البروتينات أن عناصر المعالجة الموجودة في المجموعة النشطة فقط هي التي تستدعي الروتين. إذا قام عنصر معالجة غير موجود في المجموعة النشطة باستدعاء روتين جماعي لـ SHMEM، تحدث سلوكيات غير محددة.

يحدد الوسيط nreduce عدد عمليات التقليل المنفصلة التي يجب إجراؤها. توفر مصفوفة المصدر على جميع عناصر المعالجة في المجموعة النشطة عنصرًا واحدًا لكل عملية تقليل. يتم وضع نتائج عمليات التقليل في مصفوفة الهدف على جميع عناصر المعالجة في المجموعة النشطة. يتم تحديد المجموعة النشطة بواسطة الثلاثي PE_start، logPE_stride، PE_size.

قد تكون مصفوفات المصدر والهدف نفس المصفوفة، ولكن لا يجوز أن تكون مصفوفات متداخلة.

الوسائط هي كما يلي:

target
مصفوفة متماثلة بطول nreduce من العناصر لاستقبال نتائج عمليات التقليل. يختلف نوع بيانات target مع إصدار روتين التقليل الذي يتم استدعاؤه. عند الاستدعاء من C/C++، ارجع إلى قسم SYNOPSIS للحصول على معلومات نوع البيانات. عند الاستدعاء من Fortran، أنواع بيانات الهدف هي كما يلي:

shmem_int4_min_to_all: عدد صحيح، بحجم عنصر 4 بايت

shmem_int8_min_to_all: عدد صحيح، بحجم عنصر 8 بايت

shmem_real4_min_to_all: حقيقي، بحجم عنصر 4 بايت

shmem_real8_min_to_all: حقيقي، بحجم عنصر 8 بايت

shmem_real16_min_to_all: حقيقي، بحجم عنصر 16 بايت

source مصفوفة متماثلة: بطول nreduce من العناصر، تحتوي على عنصر واحد
لكل عملية تقليل منفصلة. يجب أن يكون للوسيط source نفس نوع بيانات target.
nreduce
عدد العناصر في مصفوفات target و source. يجب أن يكون nreduce من نوع عدد صحيح. إذا كنت تستخدم Fortran، فيجب أن تكون قيمة عدد صحيح افتراضية.
PE_start
أقل رقم PE افتراضي للمجموعة النشطة من PEs. يجب أن يكون PE_start من نوع عدد صحيح. إذا كنت تستخدم Fortran، فيجب أن تكون قيمة عدد صحيح افتراضية.
logPE_stride
لوغاريتم (الأساس 2) الخطوة بين أرقام PE الافتراضية المتتالية في المجموعة النشطة. يجب أن يكون logPE_stride من نوع عدد صحيح. إذا كنت تستخدم Fortran، فيجب أن تكون قيمة عدد صحيح افتراضية.
PE_size
عدد PEs في المجموعة النشطة. يجب أن يكون PE_size من نوع عدد صحيح. إذا كنت تستخدم Fortran، فيجب أن تكون قيمة عدد صحيح افتراضية.
pWrk
مصفوفة عمل متماثلة. يجب أن يكون للوسيط pWrk نفس نوع بيانات target. في C/C++، تحتوي على عناصر max(nreduce/2 + 1، _SHMEM_REDUCE_MIN_WRKDATA_SIZE). في Fortran، تحتوي على عناصر max(nreduce/2 + 1، SHMEM_REDUCE_MIN_WRKDATA_SIZE).
pSync
مصفوفة عمل متماثلة. في C/C++، pSync من نوع long وبحجم _SHMEM_REDUCE_SYNC_SIZE. في Fortran، pSync من نوع integer وبحجم SHMEM_REDUCE_SYNC_SIZE. إذا كنت تستخدم Fortran، فيجب أن تكون قيمة عدد صحيح افتراضية. يجب تهيئة كل عنصر من هذه المصفوفة بالقيمة _SHMEM_SYNC_VALUE (في C/C++) أو SHMEM_SYNC_VALUE (في Fortran) قبل أن تدخل أي من PEs في المجموعة النشطة روتين التقليل.

يجب أن تكون قيم الوسائط nreduce و PE_start و logPE_stride و PE_size متساوية على جميع PEs في المجموعة النشطة. يجب تمرير نفس مصفوفات target و source، ونفس مصفوفات العمل pWrk و pSync، إلى جميع PEs في المجموعة النشطة.

قبل أن يقوم أي PE باستدعاء روتين تقليل، يجب عليك التأكد من وجود الشروط التالية (غالبًا ما يكون المزامنة عبر حاجز أو طريقة أخرى مطلوبة لضمان ذلك): مصفوفات pWrk و pSync على جميع PEs في المجموعة النشطة ليست قيد الاستخدام من استدعاء سابق لروتين جماعي لـ SHMEM. مصفوفة target على جميع PEs في المجموعة النشطة جاهزة لاستقبال نتائج التقليل.

عند العودة من روتين تقليل، تكون الأمور التالية صحيحة بالنسبة لـ PE المحلي: تم تحديث مصفوفة target. تم استعادة القيم الموجودة في مصفوفة pSync إلى القيم الأصلية.

ملاحظات

المصطلحات جماعي (collective)، متماثل (symmetric)، ومتوافق مع ذاكرة التخزين المؤقت (cache aligned) معرفة في intro_shmem(3). تقوم جميع روتينات تقليل SHMEM بإعادة تعيين القيم في pSync قبل إرجاعها، لذلك لا يلزم تهيئة مخزن pSync معين إلا في المرة الأولى التي يتم استخدامه فيها.

يجب عليك التأكد من أن مصفوفة pSync لا يتم تحديثها على أي PE في المجموعة النشطة أثناء مشاركة أي من PEs في معالجة روتين تقليل SHMEM. كن حذرًا من المواقف التالية: إذا تم تهيئة مصفوفة pSync في وقت التشغيل، فستكون هناك حاجة إلى نوع من المزامنة لضمان أن جميع PEs في مجموعة العمل قد قامت بتهيئة pSync قبل أن يدخل أي منها روتين SHMEM تم استدعاؤه باستخدام مصفوفة مزامنة pSync. يمكن إعادة استخدام مصفوفة pSync أو pWrk في استدعاء روتين تقليل لاحق فقط إذا لم يكن أي من PEs في المجموعة النشطة لا يزال يعالج روتين تقليل سابق استخدم نفس مصفوفات pSync أو pWrk. بشكل عام، لا يمكن ضمان ذلك إلا عن طريق القيام بنوع من المزامنة. ومع ذلك، في الحالة الخاصة لروتينات التقليل التي يتم استدعاؤها بنفس المجموعة النشطة، يمكنك تخصيص مصفوفتي pSync و pWrk والتبديل بينهما في الاستدعاءات المتتالية.

shmem_long_min_to_all(3) — shmem

SYNOPSIS

All routines in the Shared Memory (shmem) library follow the Fortran 90 standard and are included in the file mpp/shmem.fh. The C/C++ header file is shmem.h.

DESCRIPTION

The symmetric, one-sided communication routines in the SHMEM library provide a set of routines for programming in a parallel, distributed-memory environment. These routines are based on the Partitioned Global Address Space (PGAS) programming model.

This man page describes the following family of routines:

shmem_type_min_to_all
(type is real8, real16, long, int, short, etc.)

These routines collect values from all processing elements (PEs) in the current job and return the minimum value of those values to all PEs. The computation is performed across all PEs in the job. The number of PEs in the job is obtained from the Nshmem environment variable.

The shmem_type_min_to_all routines perform the following operations:

  1. All PEs contribute a value from their local source object.

  2. The minimum value among all contributions is computed.

  3. The minimum value is placed into the local target object on all PEs.

The n argument specifies the number of elements to be transferred. The pe argument specifies the PE number from which the data is to be collected. The target and source arguments are pointers to the target and source data objects, respectively.

The pSync argument is an array of synchronization flags. This array must be initialized to SHMEM_SYNC_VALUE (for Fortran) or -1 (for C/C++). The size of this array is specified by SHMEM_REDUCE_SYNC_SIZE (Fortran) or SHMEM_REDUCE_SYNC_SIZE (C/C++).

The pWrk argument is a work array that provides space for intermediate communication and computation. The size of this array is specified by SHMEM_REDUCE_MIN_WRKDATA_SIZE (Fortran) or SHMEM_REDUCE_MIN_WRKDATA_SIZE (C/C++).

The pe argument is the PE number from which data is to be collected. This should be the same for all PEs participating in the reduction. The value of pe must be between 0 and Nshmem-1, inclusive.

NOTES

The shmem_type_min_to_all routines are collective routines. They must be called by all PEs in the job. All calls to shmem_type_min_to_all must have the same value for n and pe.

The synchronization flags in pSync are used to ensure that the communication operations are completed before the PEs proceed. The flags are initialized to SHMEM_SYNC_VALUE (Fortran) or -1 (C/C++). After the call, the flags are set to SHMEM_SYNC_VALUE (Fortran) or -1 (C/C++) on all PEs.

The pWrk array is used for temporary storage during the reduction operation. It is not preserved between calls. Two separate work arrays should be used if multiple calls are made without intervening synchronization.

EXAMPLES

Example 1: Fortran code demonstrating the use of SHMEM_REAL8_MIN_TO_ALL to find the minimum value of real variable FOO across all the even PEs.

INCLUDE "mpp/shmem.fh"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL FOO, FOOMIN, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOMIN, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_REAL8_MIN_TO_ALL(FOOMIN, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOMIN
ENDIF

Example 2: Consider the following C/C++ call:

shmem_int_min_to_all( target, source, 3, 0, 0, 8, pwrk, psync );

The preceding call is more efficient, but semantically equivalent to, the combination of the following calls:

shmem_int_min_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_int_min_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_int_min_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);

Note that two sets of pWrk and pSync arrays are used alternately because no synchronization is done between calls.
