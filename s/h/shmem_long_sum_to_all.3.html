الوصف

تقوم روتينات اختزال الذاكرة المشتركة (SHMEM) بحساب عملية اختزال واحدة أو أكثر عبر المصفوفات المتناظرة على وحدات PE افتراضية متعددة. يقوم الاختزال بإجراء عملية ثنائية ترابطية عبر مجموعة من القيم. للحصول على قائمة بروتينات اختزال SHMEM الأخرى، راجع intro_shmem(3).

كما هو الحال مع جميع روتينات SHMEM الجماعية، يفترض كل من هذه البروتينات أن وحدات PE في المجموعة النشطة فقط هي التي تستدعي البروتين. إذا قامت وحدة PE غير موجودة في المجموعة النشطة باستدعاء بروتين SHMEM جماعي، تحدث سلوكيات غير محددة.

يحدد الوسيط nreduce عدد عمليات الاختزال المنفصلة التي يجب إجراؤها. توفر مصفوفة المصدر على جميع وحدات PE في المجموعة النشطة عنصرًا واحدًا لكل عملية اختزال. يتم وضع نتائج الاختزالات في مصفوفة الهدف على جميع وحدات PE في المجموعة النشطة. يتم تعريف المجموعة النشطة بواسطة الثلاثي PE_start، logPE_stride، PE_size.

قد تكون مصفوفات المصدر والهدف نفس المصفوفة، ولكن لا يجوز أن تكون مصفوفات متداخلة.

الوسطاء هم كما يلي:

target
كائن البيانات الصحيح القابل للوصول عن بعد والذي سيتم تحديثه على وحدة PE البعيدة. إذا كنت تستخدم C/C++، فيجب أن يتطابق نوع target مع ما هو ضمني في قسم SYNOPSIS. إذا كنت تستخدم مترجم Fortran، فيجب أن يكون من النوع integer مع حجم عنصر 4 بايت لـ SHMEM_INT4_ADD و 8 بايت لـ SHMEM_INT8_ADD.
value
القيمة التي سيتم إضافتها بشكل ذري إلى target. إذا كنت تستخدم C/C++، فيجب أن يتطابق نوع value مع ما هو ضمني في قسم SYNOPSIS. إذا كنت تستخدم Fortran، فيجب أن يكون من النوع integer مع حجم عنصر مطابق لـ target.
pe
عدد صحيح يشير إلى رقم وحدة PE الذي سيتم تحديث target عليه. إذا كنت تستخدم Fortran، فيجب أن يكون قيمة integer افتراضية.
target
مصفوفة متناظرة بطول nreduce عنصر لتلقي نتائج عمليات الاختزال.
يختلف نوع بيانات target باختلاف إصدار بروتين الاختزال الذي يتم استدعاؤه واللغة المستخدمة. عند الاستدعاء من C/C++، ارجع إلى قسم SYNOPSIS للحصول على معلومات نوع البيانات.
عند الاستدعاء من Fortran، تكون أنواع بيانات target كما يلي:

shmem_comp4_sum_to_all:** COMPLEX(KIND=4).

shmem_comp8_sum_to_all:** Complex. إذا كنت تستخدم Fortran، فيجب أن تكون
قيمة complex افتراضية.

shmem_int4_sum_to_all:** INTEGER(KIND=4).

shmem_int8_sum_to_all:** Integer. إذا كنت تستخدم Fortran، فيجب أن يكون
قيمة integer افتراضية.

shmem_real4_sum_to_all:** REAL(KIND=4).

shmem_real8_sum_to_all:** Real. إذا كنت تستخدم Fortran، فيجب أن يكون
قيمة real افتراضية.
shmem_real16_sum_to_all:** Real. إذا كنت تستخدم Fortran، فيجب أن يكون
قيمة real افتراضية.
source
مصفوفة متناظرة، بطول nreduce عنصر، تحتوي على عنصر واحد لكل عملية اختزال منفصلة. يجب أن يكون للوسيط source نفس نوع بيانات target.
nreduce
عدد العناصر في مصفوفات target و source. يجب أن يكون nreduce من النوع integer. إذا كنت تستخدم Fortran، فيجب أن يكون قيمة integer افتراضية.
PE_start
أدنى رقم PE افتراضي للمجموعة النشطة من وحدات PE. يجب أن يكون PE_start من النوع integer. إذا كنت تستخدم Fortran، فيجب أن يكون قيمة integer افتراضية.
logPE_stride
اللوغاريتم (الأساس 2) للخطوة بين أرقام وحدات PE الافتراضية المتتالية في المجموعة النشطة. يجب أن يكون logPE_stride من النوع integer. إذا كنت تستخدم Fortran، فيجب أن يكون قيمة integer افتراضية.
PE_size
عدد وحدات PE في المجموعة النشطة. يجب أن يكون PE_size من النوع integer. إذا كنت تستخدم Fortran، فيجب أن يكون قيمة integer افتراضية.
pWrk
مصفوفة عمل متناظرة. يجب أن يكون للوسيط pWrk نفس نوع بيانات target. في C/C++، تحتوي هذه على عناصر max(nreduce/2 + 1, _SHMEM_REDUCE_MIN_WRKDATA_SIZE). في Fortran، تحتوي هذه على عناصر max(nreduce/2 + 1, SHMEM_REDUCE_MIN_WRKDATA_SIZE).
pSync
مصفوفة عمل متناظرة. في C/C++، يكون pSync من النوع long وحجم _SHMEM_REDUCE_SYNC_SIZE. في Fortran، يكون pSync من النوع integer وحجم SHMEM_REDUCE_SYNC_SIZE. يجب أن يكون قيمة integer افتراضية. يجب تهيئة كل عنصر من عناصر هذه المصفوفة بالقيمة _SHMEM_SYNC_VALUE (في C/C++) أو SHMEM_SYNC_VALUE (في Fortran) قبل أن تقوم أي من وحدات PE في المجموعة النشطة بالدخول إلى بروتين الاختزال.

SYNOPSIS

In Fortran:

INCLUDE "mpp/shmem.fh"
SUBROUTINE shmem_long_sum_to_all(target, source, nreduce, PE_start,
logPE_stride, PE_size, pWrk, pSync)

In C/C++:

void shmem_long_sum_to_all(long *target, const long *source, size_t nreduce,
int PE_start, int logPE_stride, int PE_size, long *pWrk,
long *pSync);
void shmem_long_sum_to_all_nb(long *target, const long *source, size_t nreduce,
int PE_start, int logPE_stride, int PE_size, long *pWrk,
long *pSync);

DESCRIPTION

The reduction routines compute the sum of elements of arrays on multiple PEs in the active set and place the results in the target array on all PEs in the active set. The reduction is performed symmetrically on the active set of PEs. The sum is performed element-wise on the arrays.

The specific reduction routine to be used determines the type of summation and the data type of the elements being summed. The available reduction routines are:

shmem_long_sum_to_all
Sums elements of type long.

The parameters for the reduction routines are:

target
The target array where the results of the reduction will be stored. This array must be large enough to hold nreduce elements. The contents of the target array are undefined on entry and are updated on return.
source
The source array containing the elements to be summed. This array must be large enough to hold nreduce elements.
nreduce
The number of elements in the target and source arrays to be summed.
PE_start
The starting PE index for the reduction operation.
logPE_stride
The log of the stride between PE indices for the reduction operation.
PE_size
The number of PEs in the active set for the reduction operation.
pWrk
A work array that is used by the reduction routine. This array must be large enough to hold nreduce elements.
pSync
A synchronization array used by the reduction routine. This array must be large enough to hold SHMEM_REDUCE_SYNC_SIZE elements.

The following reduction routine types are available:

Sum
The elements are summed.

The following data types are available:

long
The elements are of type long.

All arguments for the f arguments nreduce, PE_start, logPE_stride, and PE_size must be equal on all PEs in the active set. The same target and source arrays, and the same pWrk and pSync work arrays, must be passed to all PEs in the active set.

Before any PE calls a reduction routine, you must ensure that the following conditions exist (synchronization via a barrier or some other method is often needed to ensure this): The pWrk and pSync arrays on all PEs in the active set are not still in use from a prior call to a collective SHMEM routine. The target array on all PEs in the active set is ready to accept the results of the reduction.

Upon return from a reduction routine, the following are true for the local PE: The target array is updated. The values in the pSync array are restored to the original values.

NOTES

The terms collective, symmetric, and cache aligned are defined in intro_shmem(3).

All SHMEM reduction routines reset the values in pSync before they return, so a particular pSync buffer need only be initialized the first time it is used.

You must ensure that the pSync array is not being updated on any PE in the active set while any of the PEs participate in processing of a SHMEM reduction routine. Be careful of the following situations: If the pSync array is initialized at run time, some type of synchronization is needed to ensure that all PEs in the working set have initialized pSync before any of them enter a SHMEM routine called with the pSync synchronization array. A pSync or pWrk array can be reused in a subsequent reduction routine call only if none of the PEs in the active set are still processing a prior reduction routine call that used the same pSync or pWrk arrays. In general, this can be assured only by doing some type of synchronization. However, in the special case of reduction routines being called with the same active set, you can allocate two pSync and pWrk arrays and alternate between them on successive calls.

EXAMPLES

Example 1: This Fortran example statically initializes the pSync array and finds the sum of the real variable FOO across all even PEs.

INCLUDE "mpp/shmem.fh"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL FOO, FOOSUM, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOSUM, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_INT4_SUM_TO_ALL(FOOSUM, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOSUM
ENDIF

Example 2: Consider the following C/C++ call:

shmem_int_sum_to_all( target, source, 3, 0, 0, 8, pwrk, psync );

The preceding call is more efficient, but semantically equivalent to, the combination of the following calls:

shmem_int_sum_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_int_sum_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_int_sum_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);
Note that two sets of pWrk and pSync arrays are used alternately because no
synchronization is done between calls.
