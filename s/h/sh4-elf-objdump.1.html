الوصف

objdump يعرض معلومات حول ملف واحد أو أكثر من الملفات الكائنية. تتحكم الخيارات في المعلومات المحددة التي يتم عرضها. هذه المعلومات مفيدة بشكل أساسي للمبرمجين الذين يعملون على أدوات الترجمة، بدلاً من المبرمجين الذين يريدون فقط أن يتم ترجمة برنامجهم ويعمل.

ملف_كائني... هي الملفات الكائنية التي سيتم فحصها. عند تحديد الأرشيفات، يعرض objdump معلومات حول كل ملف كائني عضو.

الخيارات

الأشكال الطويلة والقصيرة للخيارات، المعروضة هنا كبدائل، متكافئة. يجب تقديم خيار واحد على الأقل من القائمة -a,-d,-D,-e,-f,-g,-G,-h,-H,-p,-P,-r,-R,-s,-S,-t,-T,-V,-x.

-a
--archive-header
إذا كان أي من ملفات ملف_كائني هو أرشيف، اعرض معلومات رأس الأرشيف (بتنسيق مشابه لـ ls -l). بالإضافة إلى المعلومات التي يمكنك سردها باستخدام ar tv، يعرض objdump -a تنسيق الملف الكائني لكل عضو في الأرشيف.
--adjust-vma=إزاحة
عند عرض المعلومات، قم أولاً بإضافة إزاحة إلى جميع عناوين الأقسام. هذا مفيد إذا كانت عناوين الأقسام لا تتوافق مع جدول الرموز، وهو ما يمكن أن يحدث عند وضع الأقسام في عناوين معينة عند استخدام تنسيق لا يمكنه تمثيل عناوين الأقسام، مثل a.out.
-b اسم_bfd
--target=اسم_bfd
حدد أن تنسيق رمز الكائن للملفات الكائنية هو اسم_bfd. قد لا يكون هذا الخيار ضروريًا؛ objdump يمكنه التعرف تلقائيًا على العديد من التنسيقات.

على سبيل المثال،

objdump -b oasys -m vax -h fu.o

يعرض معلومات موجزة من رؤوس الأقسام (-h) لـ fu.o، الذي تم تحديده صراحة (-m) كملف كائني VAX بالتنسيق الذي تنتجه مترجمات Oasys. يمكنك سرد التنسيقات المتاحة باستخدام الخيار -i.

-C
--demangle[=نمط]
فك ترميز (demangle) أسماء الرموز منخفضة المستوى إلى أسماء مستوى المستخدم. بالإضافة إلى إزالة أي شرطة سفلية أولية يضيفها النظام، يجعل هذا أسماء دوال C++ قابلة للقراءة. تختلف أساليب الترميز حسب المترجم. يمكن استخدام الوسيط الاختياري لأسلوب الترميز لاختيار أسلوب ترميز مناسب للمترجم الخاص بك.
--recurse-limit
--no-recurse-limit
--recursion-limit
--no-recursion-limit
تمكين أو تعطيل حد لمقدار التكرار الذي يتم تنفيذه أثناء فك ترميز السلاسل النصية. نظرًا لأن تنسيقات الترميز تسمح بمستوى لا نهائي من التكرار، فمن الممكن إنشاء سلاسل نصية قد يؤدي فك ترميزها إلى استنفاد مساحة المكدس المتاحة على الجهاز المضيف، مما يؤدي إلى خطأ في الذاكرة. يحاول الحد منع حدوث ذلك عن طريق تقييد التكرار إلى 2048 مستوى من التداخل.

الافتراضي هو تمكين هذا الحد، ولكن تعطيله قد يكون ضروريًا لفك ترميز الأسماء المعقدة حقًا. لاحظ مع ذلك أنه إذا تم تعطيل حد التكرار، فمن الممكن حدوث استنفاد المكدس وسيتم رفض أي تقارير أخطاء حول مثل هذا الحدث.

-g
--debugging
عرض معلومات التصحيح. يحاول هذا تحليل معلومات تنسيق تصحيح STABS المخزنة في الملف وطباعتها باستخدام بناء جملة يشبه C. إذا لم يتم العثور على أي تصحيح STABS، يعود هذا الخيار إلى الخيار -W لطباعة أي معلومات DWARF في الملف.
-e
--debugging-tags
مثل -g، ولكن يتم إنشاء المعلومات بتنسيق متوافق مع أداة ctags.
-d
--disassemble
--disassemble=رمز
عرض رموز لغة التجميع لتعليمات الآلة من الملف المدخل. يقوم هذا الخيار بتفكيك الأقسام التي يُتوقع أن تحتوي على تعليمات فقط. إذا تم توفير الوسيط الاختياري رمز، فقم بعرض رموز لغة التجميع بدءًا من رمز. إذا كان رمز اسم دالة، فسيتوقف فك التجميع عند نهاية الدالة، وإلا فسيتوقف عند مواجهة الرمز التالي. إذا لم تكن هناك مطابقات لـ رمز، فلن يتم عرض شيء.

لاحظ أنه إذا تم تمكين الخيار --dwarf=follow-links، فسيتم قراءة جداول الرموز في ملفات معلومات التصحيح المرتبطة واستخدامها عند فك التجميع.

-D
--disassemble-all
مثل -d، ولكن قم بفك تجميع

--dwarf-depth=n
تقييد تفريغ قسم ".debug_info" إلى n من الأطفال. هذا مفيد فقط مع --debug-dump=info. الافتراضي هو طباعة جميع وحدات معلومات التصحيح (DIEs)؛ القيمة الخاصة 0 لـ n سيكون لها هذا التأثير أيضًا.

مع قيمة غير صفرية لـ n، لن تتم طباعة وحدات معلومات التصحيح (DIEs) عند المستوى n أو أعمق. نطاق n يبدأ من الصفر.

--dwarf-start=n
طباعة وحدات معلومات التصحيح (DIEs) فقط بدءًا من وحدة معلومات التصحيح (DIE) المرقمة n. هذا مفيد فقط مع --debug-dump=info.

إذا تم تحديد هذا الخيار، فسوف يمنع طباعة أي معلومات رأسية وجميع وحدات معلومات التصحيح (DIEs) قبل الوحدة المرقمة n. سيتم طباعة الأشقاء والأطفال فقط للوحدة المحددة.

يمكن استخدام هذا بالاقتران مع --dwarf-depth.

بشكل افتراضي، يتم عرض اسم القسم المسمى .sframe، وهو الاسم الذي ينشره ld.

NAME

objdump - display information from object files

SYNOPSIS

objdump [-a|--all-headers] [-A|--assembly-all] [-b bfdname|--target=bfdname] [-C|--demangle[=style]] [-d[ext]|--disassemble[=ext]] [-D|--disassemble-all] [-e|--headers] [-f|--file-headers] [-g|--debugging] [-h|--section-headers] [-i|--info] [-l|--line-numbers] [-L|--dynamic-list] [-m machine|--architecture=machine] [-M options|--disassembler-options=options] [-p|--private-headers] [-P name|--private-symbol-list=name] [-r|--reloc] [-R|--reloc-uninitialized] [-s|--full-contents] [-S|--source] [-t|--syms] [-T|--dynamic-syms] [-U|--strip-symbol] [-V|--version] [-w|--wide] [-x|--all-headers] [-z|--disassemble-zeroes] [-Z|--decompress] [-EB|-EL] [-m emulation] [-m machine] [-M machine options] [--target=bfdname] [--emulation=emulation] [--file-alignment] [--heap-size] [--info-iterable] [--insn-groups] [--prefix-symbol=symbol] [--prefix-symbols=symbol] [--prefix-stripping=level] [--show-linalg] [--special-syms] [--start-address=addr] [--stop-address=addr] [--syntax-group=syntax] [--system-symbols] [--tree] [--unicode=mode] [--use-dynamic] [-file]...

DESCRIPTION

objdump is a utility to display information from object files. It is part of the GNU Binutils package.

The type of information displayed depends on the options chosen. The default action of objdump is to display the contents of the object-code sections, in assembly language.

By default, objdump will display information for all object files listed on the command line. When more than one object file is listed, objdump will print a header for each file before printing the information requested.

If the object file is a core dump, then objdump will display information about the core dump.

If no specific options are given to objdump, it will display the file's section headers, then disassemble the file's contents.
