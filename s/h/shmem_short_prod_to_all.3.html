الوصف

تقوم روتينات الاختزال للذاكرة المشتركة (SHMEM) بحساب عملية اختزال واحدة أو أكثر عبر مصفوفات متماثلة على وحدات PE افتراضية متعددة. تقوم عملية الاختزال بتنفيذ عملية ثنائية ترابطية عبر مجموعة من القيم. للحصول على قائمة بروتينات الاختزال SHMEM الأخرى، راجع intro_shmem(3).

كما هو الحال مع جميع روتينات SHMEM الجماعية، تفترض كل من هذه الروتينات أن وحدات PE في المجموعة النشطة فقط تستدعي الروتين. إذا قامت وحدة PE غير موجودة في المجموعة النشطة باستدعاء روتين SHMEM جماعي، فإن ذلك يؤدي إلى سلوك غير محدد.

يحدد الوسيط nreduce عدد عمليات الاختزال المنفصلة التي سيتم إجراؤها. توفر مصفوفة المصدر على جميع وحدات PE في المجموعة النشطة عنصرًا واحدًا لكل عملية اختزال. توضع نتائج عمليات الاختزال في مصفوفة الهدف على جميع وحدات PE في المجموعة النشطة. يتم تحديد المجموعة النشطة بواسطة الثلاثي PE_start، logPE_stride، PE_size.

قد تكون مصفوفتي المصدر والهدف نفس المصفوفة، ولكنهما لا يمكن أن تكونا مصفوفتين متداخلتين.

الوسائط هي كما يلي:

target
مصفوفة متماثلة بطول nreduce من العناصر لاستقبال نتائج عمليات الاختزال. يختلف نوع بيانات target مع إصدار روتين الاختزال الذي يتم استدعاؤه واللغة المستخدمة. عند الاستدعاء من C/C++، ارجع إلى قسم SYNOPSIS للحصول على معلومات نوع البيانات. عند الاستدعاء من Fortran، تكون أنواع بيانات الهدف كما يلي:
shmem_comp4_prod_to_all: مركب، بحجم عنصر يساوي اثنين
قيم حقيقية بحجم 4 بايت.
shmem_comp8_prod_to_all: مركب، بحجم عنصر يساوي اثنين
قيم حقيقية بحجم 8 بايت.

shmem_int4_prod_to_all: عدد صحيح، بحجم عنصر 4 بايت

shmem_int8_prod_to_all: عدد صحيح، بحجم عنصر 8 بايت

shmem_real4_prod_to_all: حقيقي، بحجم عنصر 4 بايت

shmem_real8_prod_to_all: حقيقي، بحجم عنصر 8 بايت

shmem_real16_prod_to_all: حقيقي، بحجم عنصر 16 بايت

source
مصفوفة متماثلة، بطول nreduce من العناصر، تحتوي على عنصر واحد لكل عملية اختزال منفصلة. يجب أن يكون الوسيط source له نفس نوع بيانات target.
nreduce
عدد العناصر في مصفوفتي target و source. يجب أن يكون nreduce من نوع عدد صحيح. إذا كنت تستخدم Fortran، فيجب أن يكون قيمة عدد صحيح افتراضية.
PE_start
أدنى رقم PE افتراضي للمجموعة النشطة من وحدات PE. يجب أن يكون PE_start من نوع عدد صحيح. إذا كنت تستخدم Fortran، فيجب أن يكون قيمة عدد صحيح افتراضية.
logPE_stride
لوغاريتم (أساس 2) الخطوة بين أرقام PE الافتراضية المتتالية في المجموعة النشطة. يجب أن يكون logPE_stride من نوع عدد صحيح. إذا كنت تستخدم Fortran، فيجب أن يكون قيمة عدد صحيح افتراضية.
PE_size
عدد وحدات PE في المجموعة النشطة. يجب أن يكون PE_size من نوع عدد صحيح. إذا كنت تستخدم Fortran، فيجب أن يكون قيمة عدد صحيح افتراضية.
pWrk
مصفوفة عمل متماثلة. يجب أن يكون للوسيط pWrk نفس نوع بيانات target. في C/C++، يحتوي هذا على max(nreduce/2 + 1, _SHMEM_REDUCE_MIN_WRKDATA_SIZE) عنصرًا. في Fortran، يحتوي هذا على max(nreduce/2 + 1, SHMEM_REDUCE_MIN_WRKDATA_SIZE) عنصرًا.
pSync
مصفوفة عمل متماثلة. في C/C++، يكون pSync من نوع long وحجم _SHMEM_REDUCE_SYNC_SIZE. في Fortran، يكون pSync من نوع integer وحجم SHMEM_REDUCE_SYNC_SIZE. إذا كنت تستخدم Fortran، فيجب أن يكون قيمة عدد صحيح افتراضية. قبل أن تدخل أي من وحدات PE في المجموعة النشطة إلى روتين الاختزال، يجب تهيئة كل عنصر من عناصر هذه المصفوفة بالقيمة _SHMEM_SYNC_VALUE (في C/C++) أو SHMEM_SYNC_VALUE (في Fortran).

يجب أن تكون قيم الوسائط nreduce و PE_start و logPE_stride و PE_size متساوية على جميع وحدات PE في المجموعة النشطة. يجب تمرير نفس مصفوفتي target و source، ونفس مصفوفات العمل pWrk و pSync، إلى جميع وحدات PE في المجموعة النشطة. قبل أن تقوم أي وحدة PE باستدعاء روتين اختزال، يجب عليك التأكد من وجود الظروف التالية (غالبًا ما يكون التزامن عبر حاجز أو طريقة أخرى ضروريًا لضمان ذلك): مصفوفات pWrk و pSync على جميع وحدات PE في المجموعة النشطة ليست قيد الاستخدام من استدعاء سابق لروتين SHMEM جماعي. مصفوفة target على جميع وحدات PE في المجموعة النشطة جاهزة لاستقبال نتائج الاختزال.

عند العودة من روتين اختزال، تكون الأمور التالية صحيحة بالنسبة لوحدة PE المحلية: تم تحديث مصفوفة target. تمت استعادة القيم في مصفوفة pSync إلى القيم الأصلية.

ملاحظات

تُعرّف المصطلحات جماعي، متماثل، ومتوافق مع ذاكرة التخزين المؤقت في intro_shmem(3). تقوم جميع روتينات اختزال SHMEM بإعادة تعيين القيم في pSync قبل أن تعود، لذلك لا تحتاج إلا إلى تهيئة مخزن pSync معين في المرة الأولى التي يتم استخدامه فيها.

DESCRIPTION

These functions compute the product of elements across all processing elements (PEs) in the active set. The active set is defined by the range [PE_start, PE_end] with a stride of PE_stride. The product is computed on the root PE. The PEs are numbered 0 to N_PES-1. All PEs in the active set must execute these routines. The arrays target, source, and pwrk must be allocated with sufficient size.

The shmem_prod_to_all family of functions compute the product of elements in the source array and store the result in the target array on each PE in the active set.

The routine returns in the target array on each PE in the active set the product of all the source array elements from the PEs in the active set. The size of the source and target arrays are specified by the nelem argument.

The shmem_prod_to_all routines are collectives that must be called by all PEs in the same way. The PE_start, PE_end, and PE_stride arguments define the active set of PEs that participate in the collective operation.

The pwrk array is used as a work array by the SHMEM implementation and must be large enough to hold the reduction computation. The required size is SHMEM_REDUCE_MIN_WRKDATA_SIZE elements.

The psync array is used for synchronization between PEs. It must be allocated with SHMEM_REDUCE_SYNC_SIZE elements. All elements of psync must be initialized to SHMEM_SYNC_VALUE.

The generic function shmem_prod_to_all is equivalent to calling the specific typed functions:

The target, source, pwrk, and psync arguments are pointers to the arrays used for the reduction operation.

The nelem argument specifies the number of elements in the target and source arrays.

The PE_start, PE_stride, and PE_end arguments define the active set of PEs that participate in the reduction operation.

NOTES

You must ensure that the pSync array is not being updated on any PE in the active set while any of the PEs participate in processing of a SHMEM reduction routine. Be careful of the following situations: If the pSync array is initialized at run time, some type of synchronization is needed to ensure that all PEs in the working set have initialized pSync before any of them enter a SHMEM routine called with the pSync synchronization array. A pSync or pWrk array can be reused in a subsequent reduction routine call only if none of the PEs in the active set are still processing a prior reduction routine call that used the same pSync or pWrk arrays. In general, this can be assured only by doing some type of synchronization. However, in the special case of reduction routines being called with the same active set, you can allocate two pSync and pWrk arrays and alternate between them on successive calls.

EXAMPLES

Example 1: This Fortran example statically initializes the pSync array and finds the product of the real variable FOO across all the even PEs.

INCLUDE "mpp/shmem.fh"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL FOO, FOOPROD, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOPROD, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_COMP8_PROD_TO_ALL(FOOPROD, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOPROD
ENDIF

Example 2: Consider the following C/C++ call:

shmem_short_prod_to_all(target, source, 3, 0, 0, 8, pwrk, psync);

The preceding call is more efficient, but semantically equivalent to, the combination of the following calls:

shmem_short_prod_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_short_prod_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_short_prod_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);

Note that two sets of pWrk and pSync arrays are used alternately because no synchronization is done between calls.
