الوصف

تنقسم الوظائف التي تتعامل مع وحدات MIB إلى أربع مجموعات - تلك التي تتعامل مع التهيئة والإغلاق، وقراءة وتحليل ملفات MIB، والبحث في شجرة MIB، وروتينات الإخراج.

التهيئة والإغلاق

يُستخدم add_mibdir لإضافة الدليل المحدد إلى مسار المواقع التي يتم البحث فيها عن الملفات التي تحتوي على وحدات MIB. لاحظ أن هذا لا يقوم فعليًا بتحميل وحدات MIB الموجودة في هذا الدليل، ولكنه مجرد خطوة تهيئة لجعلها متاحة لـ netsnmp_read_module. تُرجع هذه الوظيفة عدد الملفات الموجودة في الدليل، أو -1 إذا حدث خطأ. يجب استدعائها *قبل* استدعاء netsnmp_init_mib.

netsnmp_init_mib يقوم بتكوين مسار البحث عن دليل MIB (باستخدام add_mibdir)، ويقوم بإعداد إطار عمل MIB الداخلي، ثم يقوم بتحميل وحدات MIB المناسبة (باستخدام netsnmp_read_module و read_mib). انظر قسم متغيرات البيئة للحصول على التفاصيل.
يجب استدعاؤها قبل أي روتين آخر يقوم بمعالجة أو الوصول إلى شجرة MIB (ولكن بعد أي استدعاءات إضافية لـ add_mibdir).

سيقوم shutdown_mib بمسح المعلومات التي تم جمعها بواسطة netsnmp_read_module و add_mibdir و add_module_replacement. يوصى بشدة بعدم استدعاء shutdown_mib أثناء إدارة جلسات SNMP بشكل نشط.

قراءة وتحليل ملفات MIB

تأخذ netsnmp_read_module اسم وحدة MIB (والذي لا يلزم أن يكون هو نفسه اسم الملف الذي يحتوي على الوحدة)، وتحدد موقعها ضمن القائمة المكونة لأدلة MIB، وتقوم بتحميل التعريفات من الوحدة إلى شجرة MIB النشطة. كما تقوم بتحميل أي وحدات MIB مدرجة في عبارة IMPORTS لهذه الوحدة.

read_mib مشابه، ولكنه يأخذ اسم الملف الذي يحتوي على وحدة MIB. لاحظ أن هذا الملف لا يلزم أن يكون موجودًا ضمن قائمة البحث عن دليل MIB (على الرغم من أن أي وحدات مدرجة في عبارة IMPORTS يجب أن تكون كذلك).

سيقوم read_all_mibs بقراءة جميع وحدات MIB الموجودة في قائمة البحث عن دليل MIB.

بشكل عام، يكون المحلل صامتًا بشأن الغرائب التي يراها في ملفات MIB. للحصول على تقارير تحذيرات، قم باستدعاء snmp_set_mib_warnings مع مستوى 1 (أو 2 لمزيد من التحذيرات).

يمكن استخدام add_module_replacement للسماح لوحدات MIB الجديدة بإلغاء الوحدات القديمة، دون الحاجة إلى تعديل عبارات IMPORTS للوحدات الأخرى. تأخذ أسماء الوحدات القديمة والجديدة، جنبًا إلى جنب مع مؤشر للأجزاء المتأثرة من الوحدة القديمة.

tag len تحميل الوحدة الجديدة عند:
NULL 0 دائمًا (الوحدة القديمة هي مجموعة فرعية صارمة
من الجديدة)
name 0 للعلامة المحددة فقط
name غير 0 لأي معرف له هذا البادئة
يمكن استخدامه أيضًا للتعامل مع الأخطاء في معرفات الوحدات المستخدمة في عبارات IMPORTS الخاصة بـ MIB (مثل الإشارة إلى RFC1213 بدلاً من RFC1213-MIB).

البحث في شجرة MIB

تأخذ read_objid سلسلة تحتوي على تمثيل نصي لمعرف كائن (في شكل رقمي أو وصفي)، وتحولها إلى قائمة المعرفات الفرعية المقابلة. يتم إرجاع هذا في المعلمة output، مع عدد المعرفات الفرعية التي تم إرجاعها عبر out_len. عند الاستدعاء، يجب أن تحتوي out_len على الحد الأقصى لطول المصفوفة output. إذا كان سيتم معالجة معرفات كائنات متعددة، فيجب إعادة تعيين هذا الطول قبل كل استدعاء. تُرجع هذه الوظيفة قيمة 1 إذا نجحت في تحليل السلسلة و 0 بخلاف ذلك.

snmp_parse_oid مشابه، ولكنه يُرجع مؤشرًا إلى مخزن OID المحلل (أو NULL).

تأخذ get_module_node وصفًا واسم وحدة، وتُرجع قائمة OID المقابلة، بنفس طريقة read_objid أعلاه.
إذا تم تحديد اسم الوحدة كـ "ANY"، فستفترض هذه الروتينات أن الوصف المعطى فريد داخل الشجرة، وستُرجع الإدخال المطابق. إذا كان هذا الافتراض غير صحيح، فإن السلوك بشأن المتغير الذي تم إرجاعه يعتمد على التنفيذ.

الإخراج

سيقوم print_mib بطباعة تمثيل لشجرة MIB النشطة حاليًا إلى مؤشر ملف FILE المحدد.

سيقوم print_objid بأخذ معرف كائن (كما تم إرجاعه بواسطة read_objid أو snmp_parse_oid أو get_module_node)، ويطبع الشكل النصي لهذا OID إلى الإخراج القياسي.

يقوم fprint_objid بنفس الشيء، ولكنه يطبع إلى مؤشر ملف FILE الذي تم تحديده بواسطة المعلمة الأولية.

يطبع snprint_objid نفس المعلومات في المخزن المؤقت الذي يشير إليه buf والذي يبلغ طوله len. يُرجع عدد الأحرف المطبوعة، أو -1 إذا لم يكن المخزن المؤقت كبيرًا بما يكفي. في الحالة الأخيرة، سيحتوي buf عادةً على نسخة مقطوعة من المعلومات (ولكن هذا السلوك غير مضمون).

تأخذ print_description و fprint_description و snprint_description معرف كائن مشابه وتطبع نسخة من تعريف MIB لهذا الكائن، جنبًا إلى جنب مع OID الكامل. يتحكم الوسيط width في كيفية تخطيط OID.

بشكل افتراضي، لا يقوم المحلل بتخزين الأوصاف لأنها قد تكون ضخمة. لكي تكون قادرًا على طباعتها، من الضروري في

shutdown_mib(3)

NAME

shutdown_mib, shutdown_host, shutdown_trap, shutdown_utility, shutdown_session, shutdown_agent - shutdown operations

SYNOPSIS

#include <net-snmp/mib_api.h>

netsnmp_mib_handler *
netsnmp_shutdown_mib(void);
int
shutdown_host(int argc, char **argv);
int
shutdown_trap(int argc, char **argv);
int
shutdown_utility(int argc, char **argv);
int
shutdown_session(int argc, char **argv);
int
shutdown_agent(int argc, char **argv);

DESCRIPTION

The Net-SNMP library provides functions to manage MIB information and perform various SNMP operations. Some of these operations involve initialization and shutdown of specific components or functionalities.

The primary functions for managing MIBs are:

netsnmp_shutdown_mib()
This function performs cleanup operations related to the MIB management subsystem. It deallocates memory, closes file handles, and resets internal data structures used for MIB parsing and management. It should be called before the application exits or when MIB management is no longer needed.

The following functions are typically used within the context of the Net-SNMP agent or command-line utilities for performing shutdown operations on specific components or hosts:

shutdown_host()
Sends an SNMP shutdown request to a specified host. This function is usually invoked from the command line and takes arguments to identify the target host and the type of shutdown command.
shutdown_trap()
Handles the sending of SNMP shutdown traps. Traps are asynchronous notifications sent by an agent to management stations. This function may be used to initiate such notifications upon certain events.
shutdown_utility()
A general utility function for managing shutdown procedures. Its specific behavior might depend on the context in which it's called.
shutdown_session()
Closes and cleans up an active SNMP session. This involves releasing resources associated with the session, such as sockets and internal buffers.
shutdown_agent()
Initiates the shutdown sequence for the Net-SNMP agent process itself. This might involve stopping the agent's event loop, closing network connections, and performing any necessary cleanup before exiting.

Important Note: The MIB management functions, such as loading and initializing MIB modules, should generally be performed before calling functions like init_mib or similar initialization routines that rely on MIB definitions. For instance, if you need to save descriptions for MIB objects, you should call snmp_set_save_descriptions(1) before calling init_mib (or similar).

ENVIRONMENT VARIABLES

The main use of environmental variables with respect to these API calls is to configure which MIB modules should be loaded, and where they are located.

MIBDIRS
A colon separated list of directories to search for MIB modules.
Default: /usr/share/snmp/mibs
Used by init_mib, netsnmp_read_module, read_all_mibs and (implicitly) by read_mib.
MIBS
A colon separated list of MIB modules to load.
The default list of modules will depend on how the Net-SNMP software was originally compiled, but is typically:
IP-MIB:IF-MIB:TCP-MIB:UDP-MIB:SNMPv2-MIB:RFC1213-MIB:UCD-SNMP-MIB:HOST-RESOURCES-MIB
If the value of the MIBS environmental variable starts with a '+' character, then these MIB modules will be added to the default list. Otherwise these modules (plus any that they IMPORT from) will be loaded instead of the default list.
If the MIBS environmental variable has the value ALL then read_all_mibs will be called to load the full collection of all available MIB modules.
Used by init_mib only.
MIBFILES
A colon separated list of files to load.
Default: (none)
Used by init_mib only.
