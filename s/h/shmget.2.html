NAME

shmget - get shared memory segment identifier

LIBRARY

Realtime Library, librt

SYNOPSIS

#include <sys/shm.h>
int shmget(key_t key, size_t size, int shmflg);

DESCRIPTION

The shmget() system call returns the identifier of the shared memory segment associated with the argument key. This identifier can then be used in subsequent calls to shmat(2), shmctl(2), and shmdt(2).

If the argument key is equal to IPC_PRIVATE, then a new shared memory segment is created.

If the argument key is not IPC_PRIVATE, then, depending on the combination of bits set in shmflg, the function may either return the identifier of an existing segment or fail.

The argument size specifies the size of the new shared memory segment in bytes. It is rounded up to the nearest multiple of the system page size. If key is IPC_PRIVATE and size is 0, then a segment of size SHMMAX is created (see below). If a segment is being created (i.e., key is IPC_PRIVATE or if the IPC_CREAT flag is set in shmflg and no segment with the given key exists), then size specifies the size of the segment to be created.

The argument shmflg is a combination of bits that control the behavior of shmget(). The flags are:

IPC_CREAT
Create a new segment. If a segment already exists with this key, and this flag is set, then the function fails.
IPC_EXCL
Used with IPC_CREAT. If a segment already exists with this key, then the function fails. This flag is useful for creating a segment with exclusive access, preventing race conditions.

Additionally, shmflg can include permission bits, which are similar to file permissions:

0600
Read and write for owner.
0400
Read for owner.
0200
Write for owner.
0060
Read and write for group.
0040
Read for group.
0020
Write for group.
0006
Read and write for others.
0004
Read for others.
0002
Write for others.

The actual permissions for a newly created segment are the bitwise OR of the permission bits in shmflg and the umask of the creating process. For existing segments, the permission bits in shmflg are checked against the access permissions of the calling process. Specifically, if IPC_CREAT is not specified, then the permissions required are read (4) and execute (1) for the owner, group, or other, as appropriate.

If IPC_CREAT is specified, the segment is created only if a segment with the given key does not already exist. If it does exist, the requested permission bits are checked.

If IPC_CREAT and IPC_EXCL are both specified, the call fails if the segment already exists. This is the only reliable way to create a new segment.

The values of key are generated using ftok(3).

RETURN VALUE

On success, shmget() returns a nonnegative integer which is the shared memory segment identifier. On failure, it returns -1 and sets errno to indicate the error.

ERRORS

EACCES
A segment exists with the given key, but the calling process does not have permission to access it (and IPC_CREAT was not specified).
EEXIST
A segment exists with the given key, but IPC_CREAT or IPC_EXCL was specified, and the segment was not created.
EINVAL
A segment is to be created, but size is less than SHMMIN or greater than SHMMAX. Or, no segment exists with the given key, and IPC_CREAT was not specified.
ENOENT
No segment exists with the given key, and IPC_CREAT was not specified.
ENOMEM
A segment is to be created, but system memory is not available.
ENOSPC
A segment is to be created, but the system-wide limit on the total amount of shared memory (SHMALL) or the maximum number of segments (SHMMNI) has been reached.
ENOSYS
Shared memory is not supported by the operating system.

STANDARDS

POSIX.1-2008.

HISTORY

System V IPC.

NOTES

SHMALL
The total amount of shared memory, measured in units of the system page size.
On Linux, this limit can be read and modified via /proc/sys/kernel/shmall. Since Linux 3.16, the default value for this limit is:

ULONG_MAX - 2^24

The effect of this value (which is suitable for both 32-bit and 64-bit systems) is to impose no limitation on allocations. This value, rather than ULONG_MAX, was chosen as the default to prevent some cases where historical applications simply raised the existing limit without first checking its current value. Such applications would cause the value to overflow if the limit was set at ULONG_MAX.
From Linux 2.4 up to Linux 3.15, the default value for this limit was:

SHMMAX / PAGE_SIZE * (SHMMNI / 16)

If SHMMAX and SHMMNI were not modified, then multiplying the result of this formula by the page size (to get a value in bytes) yielded a value of 8 GB as the limit on the total memory used by all shared memory segments.
SHMMAX
Maximum size in bytes for a shared memory segment.
On Linux, this limit can be read and modified via /proc/sys/kernel/shmmax. Since Linux 3.16, the default value for this limit is:

ULONG_MAX - 2^24

The effect of this value (which is suitable for both 32-bit and 64-bit systems) is to impose no limitation on allocations. See the description of SHMALL for a discussion of why this default value (rather than ULONG_MAX) is used.
From Linux 2.2 up to Linux 3.15, the default value of this limit was 0x2000000 (32 MiB).
Because it is not possible to map just part of a shared memory segment, the amount of virtual memory places another limit on the maximum size of a usable segment: for example, on i386 the largest segments that can be mapped have a size of around 2.8 GB, and on x86-64 the limit is around 127 TB.
SHMMIN
Minimum size in bytes for a shared memory segment: implementation dependent (currently 1 byte, though PAGE_SIZE is the effective minimum size).
SHMMNI
System-wide limit on the number of shared memory segments. In Linux 2.2, the default value for this limit was 128; since Linux 2.4, the default value is 4096.
On Linux, this limit can be read and modified via /proc/sys/kernel/shmmni.

The implementation has no specific limits for the per-process maximum number of shared memory segments (SHMSEG).

Linux notes

Until Linux 2.3.30, Linux would return EIDRM for a shmget() on a shared memory segment scheduled for deletion.

BUGS

The name choice IPC_PRIVATE was perhaps unfortunate, IPC_NEW would more clearly show its function.
