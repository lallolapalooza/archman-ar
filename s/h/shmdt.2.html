SHMOP(2) دليل استدعاءات النظام SHMOP(2)

الاسم

shmat, shmdt - عمليات الذاكرة المشتركة لنظام V

المكتبة

مكتبة C القياسية (libc, -lc)

الملخص

#include <sys/shm.h>
void *shmat(int shmid, const void *_Nullable shmaddr, int shmflg);
int shmdt(const void *shmaddr);

الوصف

shmat()

تقوم shmat() بربط جزء الذاكرة المشتركة لنظام V المحدد بواسطة shmid بمساحة عنوان العملية المستدعية. يتم تحديد عنوان الربط بواسطة shmaddr مع أحد المعايير التالية:

•
إذا كان shmaddr فارغاً (NULL)، يختار النظام عنوانًا مناسبًا (غير مستخدم) متوافقًا مع حدود الصفحات لربط الجزء.
•
إذا كان shmaddr غير فارغ (NULL) وتم تحديد SHM_RND في shmflg، يحدث الربط على العنوان الذي يساوي shmaddr مقربًا للأسفل إلى أقرب مضاعف لـ SHMLBA.
•
خلاف ذلك، يجب أن يكون shmaddr عنوانًا متوافقًا مع حدود الصفحات يحدث عنده الربط.

بالإضافة إلى SHM_RND، يمكن تحديد العلامات التالية في قناع بت الوسيط shmflg:

SHM_EXEC (خاص بنظام Linux؛ منذ Linux 2.6.9)
السماح بتنفيذ محتويات الجزء. يجب أن يمتلك المتصل إذن التنفيذ على الجزء.
SHM_RDONLY
ربط الجزء للقراءة فقط. يجب أن يمتلك المتصل إذن القراءة للجزء. إذا لم يتم تحديد هذه العلامة، يتم ربط الجزء للقراءة والكتابة، ويجب أن يمتلك المتصل إذن القراءة والكتابة للجزء. لا يوجد مفهوم لجزء ذاكرة مشتركة للكتابة فقط.
SHM_REMAP (خاص بنظام Linux)
تحدد هذه العلامة أن ربط الجزء يجب أن يحل محل أي ربط موجود في النطاق الذي يبدأ من shmaddr ويستمر لحجم الجزء. (عادة، سيحدث خطأ EINVAL إذا كان هناك ربط موجود بالفعل في نطاق العنوان هذا.) في هذه الحالة، يجب ألا يكون shmaddr فارغاً (NULL).

قيمة brk(2) للعملية المستدعية لا تتغير بسبب الربط. سيتم فصل الجزء تلقائيًا عند خروج العملية. يمكن ربط نفس الجزء للقراءة وكقراءة وكتابة، وأكثر من مرة، في مساحة عنوان العملية.

يؤدي استدعاء shmat() الناجح إلى تحديث أعضاء بنية shmid_ds (انظر shmctl(2)) المرتبطة بجزء الذاكرة المشتركة على النحو التالي:

•
يتم تعيين shm_atime إلى الوقت الحالي.
•
يتم تعيين shm_lpid إلى معرف عملية العملية المستدعية.
•
يتم زيادة shm_nattch بواحد.

shmdt()

تقوم shmdt() بفصل جزء الذاكرة المشتركة الموجود في العنوان المحدد بواسطة shmaddr من مساحة عنوان العملية المستدعية. يجب أن يكون الجزء المراد فصله مرتبطًا حاليًا مع كون shmaddr مساويًا للقيمة المرجعة من استدعاء shmat() الذي قام بالربط.

عند استدعاء shmdt() بنجاح، يقوم النظام بتحديث أعضاء بنية shmid_ds المرتبطة بجزء الذاكرة المشتركة على النحو التالي:

•
يتم تعيين shm_dtime إلى الوقت الحالي.
•
يتم تعيين shm_lpid إلى معرف عملية العملية المستدعية.
•
يتم تخفيض shm_nattch بواحد. إذا أصبحت صفرًا وكان الجزء معلمًا للحذف، يتم حذف الجزء.

قيمة الإرجاع

عند النجاح، تُرجع shmat() عنوان الجزء المرتبط من الذاكرة المشتركة؛ عند حدوث خطأ، تُرجع (void *) -1، ويتم تعيين errno للإشارة إلى الخطأ.

عند النجاح، تُرجع shmdt() القيمة 0؛ عند حدوث خطأ تُرجع -1، ويتم تعيين errno للإشارة إلى الخطأ.

الأخطاء

يمكن أن تفشل shmat() بأحد الأخطاء التالية:

EACCES
العملية المستدعية لا تمتلك الأذونات المطلوبة لنوع الربط المطلوب، ولا تمتلك القدرة CAP_IPC_OWNER في مساحة الأسماء للمستخدم التي تحكم مساحة أسماء IPC الخاصة بها.
EIDRM
shmid يشير إلى معرف تم إزالته.
EINVAL
قيمة shmid غير صالحة، أو عنوان shmaddr غير متوافق مع حدود الصفحات (أي، غير متوافق مع حدود الصفحات ولم يتم تحديد SHM_RND) أو غير صالح، أو لا يمكن ربط الجزء على shmaddr، أو تم تحديد SHM_REMAP وكان shmaddr فارغًا (NULL).
ENOMEM
لم يتمكن من تخصيص ذاكرة للموصّف أو لجداول الصفحات.

يمكن أن تفشل shmdt() بأحد الأخطاء التالية:

EINVAL
لا يوجد جزء ذاكرة مشترك مرتبط عند shmaddr؛ أو، shmaddr غير متوافق مع حدود الصفحة.

المعايير

POSIX.1-2008.

التاريخ

POSIX.1-2001, SVr4.

في SVID 3 (أو ربما قبل ذلك)، تم تغيير نوع الوسيط shmaddr من char * إلى const void *، ونوع الإرجاع لـ shmat() من char * إلى void *.

غير POSIX.1-2024 رمز الخطأ من (void *) -1 إلى SHM_FAILED.

ملاحظات

بعد fork(2)، يرث الطفل أجزاء الذاكرة المشتركة المرتبطة.

بعد execve(2)، يتم فصل جميع أجزاء الذاكرة المشتركة المرتبطة عن العملية.

عند _exit(2)، يتم فصل جميع أجزاء الذاكرة المشتركة المرتبطة عن العملية.

يعد استخدام shmat() مع shmaddr يساوي NULL هو الطريقة المفضلة والمحمولة لربط جزء الذاكرة المشتركة. كن على علم بأن جزء الذاكرة المشتركة المرتبط بهذه الطريقة قد يتم ربطه في عناوين مختلفة في عمليات مختلفة. لذلك، يجب أن تكون أي مؤشرات محفوظة داخل الذاكرة المشتركة نسبية (عادةً بالنسبة لعنوان بداية الجزء)، بدلاً من أن تكون مطلقة.

على نظام Linux، من الممكن ربط جزء ذاكرة مشترك حتى لو كان معلمًا للحذف بالفعل. ومع ذلك، لا تحدد POSIX.1 هذا السلوك والعديد من التطبيقات الأخرى لا تدعمه.

يؤثر معلم النظام التالي على shmat():

SHMLBA
مضاعف الحد الأدنى لعنوان الجزء. عند تحديد عنوان ربط بشكل صريح في استدعاء لـ shmat()، يجب على المتصل التأكد من أن العنوان هو مضاعف لهذه القيمة. هذا ضروري في بعض البنيات، إما لضمان أداء جيد لذاكرة التخزين المؤقت للمعالج أو لضمان أن الربطات المختلفة لنفس الجزء لها رؤى متسقة داخل ذاكرة التخزين المؤقت للمعالج. SHMLBA هو عادةً مضاعف لحجم صفحة النظام. (في العديد من بنيات Linux، SHMLBA هو نفس حجم صفحة النظام.)

لا تفرض التنفيذات قيودًا جوهرية على كل عملية على عدد أجزاء الذاكرة المشتركة (SHMSEG).

أمثلة

يقوم البرنامجان الموضحان أدناه بتبادل سلسلة نصية باستخدام جزء ذاكرة مشترك. يتم تقديم مزيد من التفاصيل حول البرنامجين أدناه. أولاً، نعرض جلسة طرفية توضح استخدامهما.

في نافذة طرفية واحدة، نقوم بتشغيل برنامج "reader"، الذي ينشئ ذاكرة مشتركة لنظام V

NAME

svshm_string - shared memory and semaphore example

LIBRARY

libc, -lc

SYNOPSIS

./svshm_string_read

./svshm_string_write shmid semid string

DESCRIPTION

This example program demonstrates the use of POSIX shared memory and System V semaphores to pass a string from one process to another.

The program consists of two executables: "reader" and "writer".

svshm_string_read

The reader program first creates a System V shared memory segment and a System V semaphore set. The program prints out the IDs of the created objects, and then waits for the semaphore to change value.


$ ./svshm_string_read;
shmid = 1114194
semid = 15

In another terminal window, we run the "writer" program. The "writer" program takes three command-line arguments: the IDs of the shared memory segment and semaphore set created by the "reader", and a string. It attaches the existing shared memory segment, copies the string to the shared memory, and modifies the semaphore value.


$ ./svshm_string_write 1114194 15 'Hello, world';

Returning to the terminal where the "reader" is running, we see that the program has ceased waiting on the semaphore and has printed the string that was copied into the shared memory segment by the writer:


Hello, world

Program source: svshm_string.h

The following header file is included by the "reader" and "writer" programs:


/* svshm_string.h
   Licensed under GNU General Public License v2 or later.
*/
#ifndef SVSHM_STRING_H
#define SVSHM_STRING_H
#include <err.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/sem.h>
union semun {                   /* Used in calls to semctl() */
    int                 val;
    struct semid_ds     *buf;
    unsigned short      *array;
#if defined(__linux__)
    struct seminfo      *__buf;
#endif
};
#define MEM_SIZE 4096
#endif  // include guard

Program source: svshm_string_read.c

The "reader" program creates a shared memory segment and a semaphore set containing one semaphore. It then attaches the shared memory object into its address space and initializes the semaphore value to 1. Finally, the program waits for the semaphore value to become 0, and afterwards prints the string that has been copied into the shared memory segment by the "writer".


/* svshm_string_read.c
   Licensed under GNU General Public License v2 or later.
*/
#include <err.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/ipc.h>
#include <sys/sem.h>
#include <sys/shm.h>
#include "svshm_string.h"
int
main(void)
{
    int            semid, shmid;
    char           *addr;
    union semun    arg, dummy;
    struct sembuf  sop;
    /* Create shared memory and semaphore set containing one
       semaphore.  */
    shmid = shmget(IPC_PRIVATE, MEM_SIZE, IPC_CREAT | 0600);
    if (shmid == -1)
        err(EXIT_FAILURE, "shmget");
    semid = semget(IPC_PRIVATE, 1, IPC_CREAT | 0600);
    if (semid == -1)
        err(EXIT_FAILURE, "semget");
    /* Attach shared memory into our address space.  */
    addr = shmat(shmid, NULL, SHM_RDONLY);
    if (addr == (void *) -1)
        err(EXIT_FAILURE, "shmat");
    /* Initialize semaphore 0 in set with value 1.  */
    arg.val = 1;
    if (semctl(semid, 0, SETVAL, arg) == -1)
        err(EXIT_FAILURE, "semctl");
    printf("shmid = %d\n", shmid);
    printf("semid = %d\n", semid);
    /* Wait for semaphore value to become 0.  */
    sop.sem_num = 0;
    sop.sem_op = 0;
    sop.sem_flg = 0;
    if (semop(semid, &sop, 1) == -1)
        err(EXIT_FAILURE, "semop");
    /* Print the string from shared memory.  */
    printf("%s\n", addr);
    /* Remove shared memory and semaphore set.  */
    if (shmctl(shmid, IPC_RMID, NULL) == -1)
        err(EXIT_FAILURE, "shmctl");
    if (semctl(semid, 0, IPC_RMID, dummy) == -1)
        err(EXIT_FAILURE, "semctl");
    exit(EXIT_SUCCESS);
}

Program source: svshm_string_write.c

The writer program takes three command-line arguments: the IDs of the shared memory segment and semaphore set that have already been created by the "reader", and a string. It attaches the shared memory segment into its address space, and then decrements the semaphore value to 0 in order to inform the "reader" that it can now examine the contents of the shared memory.


/* svshm_string_write.c
   Licensed under GNU General Public License v2 or later.
*/
#include <err.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/sem.h>
#include <sys/shm.h>
#include "svshm_string.h"
int
main(int argc, char *argv[])
{
    int            semid, shmid;
    char           *addr;
    size_t         size;
    struct sembuf  sop;
    if (argc != 4) {
        fprintf(stderr, "Usage: %s shmid semid string\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    size = strlen(argv[3]) + 1;  /* +1 to include trailing '\0' */
    if (size > MEM_SIZE) {
        fprintf(stderr, "String is too big!\n");
        exit(EXIT_FAILURE);
    }
    /* Get object IDs from command-line.  */
    shmid = atoi(argv[1]);
    semid = atoi(argv[2]);
    /* Attach shared memory into our address space and copy string
       (including trailing null byte) into memory.  */
    addr = shmat(shmid, NULL, 0);
    if (addr == (void *) -1)
        err(EXIT_FAILURE, "shmat");
    memcpy(addr, argv[3], size);
    /* Decrement semaphore to 0.  */
    sop.sem_num = 0;
    sop.sem_op = -1;
    sop.sem_flg = 0;
    if (semop(semid, &sop, 1) == -1)
        err(EXIT_FAILURE, "semop");
    exit(EXIT_SUCCESS);
}
