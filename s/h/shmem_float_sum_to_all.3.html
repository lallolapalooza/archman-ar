وصف

تقوم إجراءات الذاكرة المشتركة (SHMEM) للحسابات المجمعة بحساب عملية أو أكثر من عمليات الجمع عبر مصفوفات متماثلة على وحدات معالجة افتراضية متعددة. تقوم عملية الجمع بإجراء عملية ثنائية ترابطية عبر مجموعة من القيم. للحصول على قائمة بإجراءات SHMEM المجمعة الأخرى، انظر intro_shmem(3).

كما هو الحال مع جميع إجراءات SHMEM الجماعية، تفترض كل من هذه الإجراءات أن وحدات المعالجة (PEs) في المجموعة النشطة فقط هي التي تستدعي الإجراء. إذا قامت وحدة معالجة ليست في المجموعة النشطة باستدعاء إجراء SHMEM جماعي، فستكون النتيجة سلوكًا غير محدد.

يحدد الوسيط nreduce عدد عمليات الجمع المنفصلة التي سيتم إجراؤها. توفر مصفوفة المصدر (source) على جميع وحدات المعالجة في المجموعة النشطة عنصرًا واحدًا لكل عملية جمع. يتم وضع نتائج عمليات الجمع في مصفوفة الهدف (target) على جميع وحدات المعالجة في المجموعة النشطة. يتم تعريف المجموعة النشطة بواسطة الثلاثي PE_start، logPE_stride، PE_size.

قد تكون مصفوفتي المصدر والهدف نفس المصفوفة، لكن لا يجوز أن تكونا مصفوفتين متداخلتين.

الوسطاء هم كما يلي:

target
كائن البيانات الصحيح القابل للوصول عن بعد ليتم تحديثه على وحدة المعالجة البعيدة. إذا كنت تستخدم C/C++، يجب أن يتطابق نوع target مع النوع الضمني في قسم الملخص. إذا كنت تستخدم مترجم Fortran، يجب أن يكون من نوع integer بحجم عنصر 4 بايت لـ SHMEM_INT4_ADD و 8 بايت لـ SHMEM_INT8_ADD.
value
القيمة التي سيتم إضافتها بشكل ذري إلى target. إذا كنت تستخدم C/C++، يجب أن يتطابق نوع value مع النوع الضمني في قسم الملخص. إذا كنت تستخدم Fortran، يجب أن يكون من نوع integer بحجم عنصر target.
pe
عدد صحيح يشير إلى رقم وحدة المعالجة (PE) الذي سيتم تحديث target عليه. إذا كنت تستخدم Fortran، يجب أن يكون قيمة integer افتراضية.
target
مصفوفة متماثلة بطول nreduce عنصر لاستقبال نتائج عمليات الجمع.
نوع بيانات target يختلف باختلاف إصدار روتين الجمع الذي يتم استدعاؤه واللغة المستخدمة. عند الاستدعاء من C/C++، راجع قسم الملخص للحصول على معلومات نوع البيانات.
عند الاستدعاء من Fortran، أنواع بيانات target هي كما يلي:

shmem_comp4_sum_to_all:** COMPLEX(KIND=4).

shmem_comp8_sum_to_all:** Complex. إذا كنت تستخدم Fortran، يجب أن يكون
قيمة complex افتراضية.

shmem_int4_sum_to_all:** INTEGER(KIND=4).

shmem_int8_sum_to_all:** Integer. إذا كنت تستخدم Fortran، يجب أن يكون
قيمة integer افتراضية.

shmem_real4_sum_to_all:** REAL(KIND=4).

shmem_real8_sum_to_all:** Real. إذا كنت تستخدم Fortran، يجب أن يكون
قيمة real افتراضية.
shmem_real16_sum_to_all:** Real. إذا كنت تستخدم Fortran، يجب أن يكون
قيمة real افتراضية.
source
مصفوفة متماثلة، بطول nreduce عنصر، تحتوي على عنصر واحد لكل عملية جمع منفصلة. يجب أن يكون للوسيط source نفس نوع بيانات target.
nreduce
عدد العناصر في مصفوفتي target و source. يجب أن يكون nreduce من نوع integer. إذا كنت تستخدم Fortran، يجب أن يكون قيمة integer افتراضية.
PE_start
أدنى رقم وحدة معالجة افتراضي (PE) للمجموعة النشطة من وحدات المعالجة. يجب أن يكون PE_start من نوع integer. إذا كنت تستخدم Fortran، يجب أن يكون قيمة integer افتراضية.
logPE_stride
اللوغاريتم (الأساس 2) للخطوة بين أرقام وحدات المعالجة الافتراضية المتتالية في المجموعة النشطة. يجب أن يكون logPE_stride من نوع integer. إذا كنت تستخدم Fortran، يجب أن يكون قيمة integer افتراضية.
PE_size
عدد وحدات المعالجة (PEs) في المجموعة النشطة. يجب أن يكون PE_size من نوع integer. إذا كنت تستخدم Fortran، يجب أن يكون قيمة integer افتراضية.
pWrk
مصفوفة عمل متماثلة. يجب أن يكون للوسيط pWrk نفس نوع بيانات target. في C/C++، يحتوي على _SHMEM_REDUCE_MIN_WRKDATA_SIZE عناصر (nreduce/2 + 1) بحد أقصى. في Fortran، يحتوي على SHMEM_REDUCE_MIN_WRKDATA_SIZE عناصر (nreduce/2 + 1) بحد أقصى.
pSync
مصفوفة عمل متماثلة. في C/C++، pSync من نوع long وحجم _SHMEM_REDUCE_SYNC_SIZE. في Fortran، pSync من نوع integer وحجم SHMEM_REDUCE_SYNC_SIZE. يجب أن يكون قيمة integer افتراضية. يجب تهيئة كل عنصر في هذه المصفوفة بالقيمة _SHMEM_SYNC_VALUE (في C/C++) أو SHMEM_SYNC_VALUE (في Fortran) قبل أن تدخل أي من وحدات المعالجة في المجموعة النشطة إلى روتين الجمع.

DESCRIPTION

These routines compute the sum of elements in the source array and place the result in the target array. The operation is performed across all PEs in the active set. The active set is defined by the arguments PE_start, logPE_stride, and PE_size.

The sum is computed for nreduce elements. The first element of the source array is summed into the first element of the target array, the second element of the source array is summed into the second element of the target array, and so on, for all nreduce elements.

The pWrk and pSync arrays are work arrays used by the SHMEM routines. The size of the pWrk array must be at least SHMEM_REDUCE_MIN_WRKDATA_SIZE. The size of the pSync array must be at least SHMEM_REDUCE_SYNC_SIZE.

The pSync array is used for synchronization. Each element of the pSync array must be initialized to SHMEM_SYNC_VALUE before calling the reduction routine. All PEs in the active set must initialize their pSync arrays before any PE calls a reduction routine.

The PE_start, logPE_stride, and PE_size arguments define the active set of PEs. The PE_start argument specifies the first PE in the active set. The logPE_stride argument specifies the stride between PEs in the active set in log base 2. The PE_size argument specifies the number of PEs in the active set.

The arguments nreduce, PE_start, logPE_stride, and PE_size must be equal on all PEs in the active set. The same target and source arrays, and the same pWrk and pSync work arrays, must be passed to all PEs in the active set.

Before any PE calls a reduction routine, you must ensure that the following conditions exist (synchronization via a barrier or some other method is often needed to ensure this): The pWrk and pSync arrays on all PEs in the active set are not still in use from a prior call to a collective SHMEM routine. The target array on all PEs in the active set is ready to accept the results of the reduction.

Upon return from a reduction routine, the following are true for the local PE: The target array is updated. The values in the pSync array are restored to the original values.

NOTES

The terms collective, symmetric, and cache aligned are defined in intro_shmem(3).

All SHMEM reduction routines reset the values in pSync before they return, so a particular pSync buffer need only be initialized the first time it is used.

You must ensure that the pSync array is not being updated on any PE in the active set while any of the PEs participate in processing of a SHMEM reduction routine. Be careful of the following situations: If the pSync array is initialized at run time, some type of synchronization is needed to ensure that all PEs in the working set have initialized pSync before any of them enter a SHMEM routine called with the pSync synchronization array. A pSync or pWrk array can be reused in a subsequent reduction routine call only if none of the PEs in the active set are still processing a prior reduction routine call that used the same pSync or pWrk arrays. In general, this can be assured only by doing some type of synchronization. However, in the special case of reduction routines being called with the same active set, you can allocate two pSync and pWrk arrays and alternate between them on successive calls.

EXAMPLES

Example 1: This Fortran example statically initializes the pSync array and finds the sum of the real variable FOO across all even PEs.

INCLUDE "mpp/shmem.fh"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL FOO, FOOSUM, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOSUM, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_INT4_SUM_TO_ALL(FOOSUM, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOSUM
ENDIF

Example 2: Consider the following C/C++ call:

shmem_int_sum_to_all( target, source, 3, 0, 0, 8, pwrk, psync );

The preceding call is more efficient, but semantically equivalent to, the combination of the following calls:

shmem_int_sum_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_int_sum_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_int_sum_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);
Note that two sets of pWrk and pSync arrays are used alternately because no
synchronization is done between calls.
