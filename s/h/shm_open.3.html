shm_open(3) دليل وظائف المكتبة shm_open(3)

الاسم

shm_open, shm_unlink — إنشاء/فتح أو إلغاء ربط كائنات الذاكرة المشتركة POSIX

المكتبة

مكتبة الوقت الفعلي (librt, -lrt)

الملخص

#include <sys/mman.h>
#include <sys/stat.h>        /* لثوابت الوضع */
#include <fcntl.h>           /* لثوابت O_* */
int shm_open(const char *name, int oflag, mode_t mode);
int shm_unlink(const char *name);

الوصف

تقوم shm_open() بإنشاء وفتح كائن ذاكرة مشتركة POSIX جديد، أو فتح كائن موجود. كائن الذاكرة المشتركة POSIX هو في الواقع مقبض يمكن استخدامه بواسطة عمليات غير مرتبطة لـ mmap(2) نفس منطقة الذاكرة المشتركة. تقوم وظيفة shm_unlink() بتنفيذ العملية العكسية، إزالة كائن تم إنشاؤه مسبقًا بواسطة shm_open().

عملية shm_open() مشابهة لعملية open(2). يحدد name كائن الذاكرة المشتركة المراد إنشاؤه أو فتحه. للاستخدام المتوافق، يجب تحديد كائن الذاكرة المشتركة بواسطة اسم بالشكل /somename؛ أي، سلسلة نصية تنتهي بصفر، تصل إلى NAME_MAX (أي 255) حرفًا تتكون من شرطة مائلة أولية، متبوعة بحرف واحد أو أكثر، لا يكون أي منها شرطة مائلة.

oflag هو قناع بت تم إنشاؤه عن طريق ORing معًا بالضبط واحد من O_RDONLY أو O_RDWR وأي من الأعلام الأخرى المدرجة هنا:

O_RDONLY
افتح الكائن للوصول للقراءة. يمكن ربط كائن ذاكرة مشتركة تم فتحه بهذه الطريقة بـ mmap(2) للقراءة فقط (PROT_READ) فقط.
O_RDWR
افتح الكائن للوصول للقراءة والكتابة.
O_CREAT
قم بإنشاء كائن الذاكرة المشتركة إذا لم يكن موجودًا. يتم أخذ ملكية المستخدم والمجموعة للكائن من المعرفات الفعالة المقابلة للعملية المستدعية، ويتم تعيين بتات إذن الكائن وفقًا لأقل 9 بتات من mode، باستثناء تلك البتات المعينة في قناع إنشاء وضع ملف العملية (راجع umask(2)) يتم مسحها للكائن الجديد. يتم سرد مجموعة من ثوابت الماكرو التي يمكن استخدامها لتحديد mode في open(2). (يمكن الحصول على التعريفات الرمزية لهذه الثوابت عن طريق تضمين <sys/stat.h>.)
كائن الذاكرة المشتركة الجديد له طول صفر في البداية - يمكن تعيين حجم الكائن باستخدام ftruncate(2). يتم تهيئة البايتات المخصصة حديثًا لكائن الذاكرة المشتركة تلقائيًا إلى 0.
O_EXCL
إذا تم تحديد O_CREAT أيضًا، وكان كائن الذاكرة المشتركة بالاسم name موجودًا بالفعل، فقم بإرجاع خطأ. يتم إجراء فحص وجود الكائن، وإنشاؤه إذا لم يكن موجودًا، بشكل ذري.
O_TRUNC
إذا كان كائن الذاكرة المشتركة موجودًا بالفعل، فقم بقصه إلى صفر بايت.

يمكن الحصول على تعريفات لهذه القيم الثابتة عن طريق تضمين <fcntl.h>.

عند الانتهاء بنجاح، ترجع shm_open() واصف ملف جديد يشير إلى كائن الذاكرة المشتركة. يضمن أن واصف الملف هذا هو أقل واصف ملف رقمي لم يتم فتحه مسبقًا داخل العملية. يتم تعيين علامة FD_CLOEXEC (انظر fcntl(2)) لواصف الملف.

عادةً ما يتم استخدام واصف الملف في استدعاءات لاحقة لـ ftruncate(2) (لكائن تم إنشاؤه حديثًا) و mmap(2). بعد استدعاء لـ mmap(2)، يمكن إغلاق واصف الملف دون التأثير على تعيين الذاكرة.

عملية shm_unlink() مشابهة لعملية unlink(2): تزيل اسم كائن الذاكرة المشتركة، وبمجرد أن تقوم جميع العمليات بإلغاء ربط الكائن، تقوم بتخصيص وتدمير محتويات منطقة الذاكرة المرتبطة. بعد shm_unlink() ناجحة، تفشل محاولات shm_open() لكائن بنفس الاسم name (ما لم يتم تحديد O_CREAT، وفي هذه الحالة يتم إنشاء كائن جديد ومميز).

قيمة الإرجاع

عند النجاح، ترجع shm_open() واصف ملف (عدد صحيح غير سالب). عند النجاح، ترجع shm_unlink() 0. عند الفشل، ترجع كلتا الوظيفتين -1 وتعين errno للإشارة إلى الخطأ.

الأخطاء

EACCES
تم رفض إذن shm_unlink() لكائن الذاكرة المشتركة.
EACCES
تم رفض الإذن لـ shm_open() name بالوضع mode المحدد، أو تم تحديد O_TRUNC ولم يكن لدى المستدعي إذن كتابة على الكائن.
EEXIST
تم تحديد كل من O_CREAT و O_EXCL لـ shm_open() وكان كائن الذاكرة المشتركة المحدد بالاسم name موجودًا بالفعل.
EINVAL
كان الوسيط name لـ shm_open() غير صالح.
EMFILE
تم الوصول إلى الحد الأقصى لعدد واصفات الملفات المفتوحة لكل عملية.
ENAMETOOLONG
تجاوز طول name الحد PATH_MAX.
ENFILE
تم الوصول إلى الحد الأقصى للنظام لعدد الملفات المفتوحة الإجمالي.
ENOENT
تمت محاولة shm_open() لاسم name لم يكن موجودًا، ولم يتم تحديد O_CREAT.
ENOENT
تمت محاولة shm_unlink() لاسم name غير موجود.

الإصدارات

تترك POSIX سلوك مزيج O_RDONLY و O_TRUNC غير محدد. على Linux، سيؤدي هذا إلى اقتطاع كائن ذاكرة مشترك موجود بنجاح - قد لا يكون هذا هو الحال على أنظمة UNIX الأخرى.

تستخدم آلية تنفيذ كائنات الذاكرة المشتركة POSIX على Linux نظام ملفات tmpfs(5) مخصص يتم تحميله عادةً تحت /dev/shm.

المعايير

shm_open

shm_open(3)

NAME

shm_open, shm_unlink - create, open, or remove a POSIX shared memory object

LIBRARY

Realtime library (librt, -lrt)

SYNOPSIS

#include <sys/mman.h>

int shm_open(const char *name, int oflag, mode_t mode);
int shm_openat(int dirfd, const char *name, int oflag, mode_t mode);
int shm_unlink(const char *name);

DESCRIPTION

POSIX shared memory objects provide a mechanism for processes to share memory. POSIX shared memory objects are represented by a file-like interface and exist in the file system namespace (typically under /dev/shm/).

The shm_open() function establishes a connection between a shared memory object and a file descriptor. The name argument refers to the shared memory object to be created or opened. The oflag argument is a bit mask composed of one or more of the following flags:

O_RDONLY
Open the shared memory object for reading only.
O_WRONLY
Open the shared memory object for writing only.
O_RDWR
Open the shared memory object for reading and writing.
O_CREAT
Create the shared memory object if it does not exist. The owner (user ID) and permissions (mode) of the shared memory object are set to the effective user ID and the least significant 9 bits of the mode argument, respectively. If the object already exists, its mode is not changed. The mode argument is ignored if O_CREAT is not specified. If O_CREAT is specified, the mode argument must be specified.
O_EXCL
If O_CREAT is specified, and name already exists, then shm_open() shall fail and return an error.
O_TRUNC
If O_WRONLY or O_RDWR is specified, and the shared memory object exists, it shall be truncated to zero length. The file descriptor refers to an empty object. If O_TRUNC is specified without O_WRONLY or O_RDWR, it has no effect.
O_APPEND
The file offset for future write() operations is set to the end of the file. This flag is ignored for shared memory objects.

If shm_open() is called with O_CREAT, the mode argument specifies the permissions to be used for the new shared memory object. The permissions are affected by the process's umask().

The shm_unlink() function removes the named shared memory object. A subsequent shm_open() call for the same name will create a new shared memory object. The object is removed after all processes have closed their file descriptors referring to it.

If shm_unlink() is called, and the name refers to a shared memory object that has not yet been created, the call returns an error. However, if shm_unlink() is called on an object that has already been unlinked, but is still open by other processes, the object will be removed once the last process closes its file descriptor.

The shm_openat() function is equivalent to shm_open() except that if name is a relative pathname, it is interpreted relative to the directory referred to by the file descriptor dirfd (AT_FDCWD means relative to the current working directory). If name specifies an absolute pathname, then dirfd is ignored.

Shared memory objects are typically created in the /dev/shm directory. If the name argument starts with a slash (/), it is treated as an absolute path. Otherwise, it is treated as a relative path to the current working directory, unless shm_openat() is used.

After a successful call to shm_open() or shm_openat(), the calling process can use ftruncate() to set the size of the shared memory object and mmap() to map it into its address space.

Shared memory objects are not persistent across system reboots.

Shared memory objects are subject to the file permissions system.

The maximum length of a shared memory object name is NAME_MAX.

Example usage

The following example shows how to create, write to, read from, and unlink a shared memory object.


#include <sys/mman.h>
#include <fcntl.h>
#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <err.h>
int
main(void)
{
    int         shm_fd;
    void        *ptr;
    const char  *shm_name = "/my_shm_object";
    const char  *s_msg    = "Hello, World!";
    const char  *r_msg;
    /* Create shared memory object */
    shm_fd = shm_open(shm_name, O_CREAT | O_RDWR, 0666);
    if (shm_fd == -1)
        err(EXIT_FAILURE, "shm_open");
    /* Set size of shared memory object */
    if (ftruncate(shm_fd, 4096) == -1)
        err(EXIT_FAILURE, "ftruncate");
    /* Map shared memory object into address space */
    ptr = mmap(0, 4096, PROT_READ | PROT_WRITE, MAP_SHARED, shm_fd, 0);
    if (ptr == MAP_FAILED)
        err(EXIT_FAILURE, "mmap");
    /* Write message to shared memory object */
    if (sprintf(ptr, "%s", s_msg) < 0)
        err(EXIT_FAILURE, "sprintf");
    /* Unlink shared memory object */
    if (shm_unlink(shm_name) == -1)
        err(EXIT_FAILURE, "shm_unlink");
    /* Close shared memory object */
    if (close(shm_fd) == -1)
        err(EXIT_FAILURE, "close");
    /* Read message from shared memory object */
    r_msg = (char *) ptr;
    printf("Read from shared memory: %s\n", r_msg);
    /* Unmap shared memory object */
    if (munmap(ptr, 4096) == -1)
        err(EXIT_FAILURE, "munmap");
    exit(EXIT_SUCCESS);
}

This program first creates a shared memory object named /my_shm_object, sets its size to 4096 bytes, and maps it into its address space. It then writes the string "Hello, World!" into the shared memory object, unlinks the object (so it will be removed when no longer referenced), closes the file descriptor, reads the string back, and finally unmaps the shared memory object.

If you run this program, it will print:


Read from shared memory: Hello, World!

RETURN VALUE

shm_open() and shm_openat() return a new file descriptor referring to the shared memory object on success, or -1 on error, with set to indicate the error.

shm_unlink() returns 0 on success, or -1 on error, with set to indicate the error.

ERRORS

The following errors are common to shm_open() and shm_openat():

EACCES
The named shared memory object is not allowed to be created or opened with the specified flags, or the caller does not have permission to access the shared memory object.
EINTR
shm_open() or shm_openat() was interrupted by a signal.
EINVAL
name is not a valid identifier, or oflag contains invalid flags.
EMFILE
The number of file descriptors currently open by the process is greater than or equal to the system-wide limit.
ENAMETOOLONG
name is too long.
ENOENT
O_CREAT was not specified in oflag, and the named shared memory object does not exist.
ENOSPC
The shared memory object cannot be created because there is no space left on the device.
ENOSYS
The shared memory object functionality is not implemented on the system.
ENXIO
O_TMPFILE was specified in oflag, but the underlying filesystem does not support it.
EPERM
shm_unlink() was called, but the caller does not have permission to remove the named shared memory object.
EROFS
The shared memory object cannot be created because the filesystem is mounted read-only.

The following errors are specific to shm_openat():

EBADF
dirfd is not a valid file descriptor.
ENOTDIR
name is not a relative pathname, and dirfd was specified as AT_FDCWD.

The shm_openat() function was introduced in POSIX.1-2008.
