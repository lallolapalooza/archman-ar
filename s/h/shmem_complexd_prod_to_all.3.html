shmem_complexd_prod_to_all(3)

الحزمة: openmpi

التراخيص: BSD-3-Clause AND LicenseRef-MPICH

SYNOPSIS

#include <mpp/shmem.h>

void shmem_complexd_prod_to_all(longdouble *target,
                                const longdouble *source,
                                int nreduce,
                                int PE_start,
                                int logPE_stride,
                                int PE_size,
                                void *pWrk,
                                longdouble *pSync);
void shmem_complexd_prod_to_all(longdouble *target,
                                const longdouble *source,
                                int nreduce,
                                int PE_start,
                                int logPE_stride,
                                int PE_size,
                                void *pWrk,
                                long *pSync);

DESCRIPTION

The shmem_complexd_prod_to_all routines compute the product of the elements in the source array across the PEs specified by PE_start, logPE_stride, and PE_size. The result of the reduction is placed in the target array.

The reduction is performed across the PEs in the Cartesian sub-domain defined by PE_start, logPE_stride, and PE_size. nreduce is the number of elements to be reduced. The reduction is performed element-wise. For example, if nreduce is 3, the first element of target will contain the product of the first element of source from all participating PEs, and the second element of target will contain the product of the second element of source from all participating PEs, etc.

The pWrk and pSync arrays are required for the reduction. The user must allocate and pass these arrays. The size of the pWrk array must be at least SHMEM_REDUCE_MIN_WRKDATA_SIZE elements. The size of the pSync array must be at least SHMEM_REDUCE_SYNC_SIZE elements.

The pSync array is used to synchronize the reduction operation. All PEs participating in the reduction must initialize the pSync array elements to SHMEM_SYNC_VALUE before calling the reduction routine. The pSync array is updated by the SHMEM library during the reduction and should not be modified by the user until the reduction operation is complete.

NOTES

The pSync and pWrk arrays are required for the reduction operation. These arrays must be initialized before use. The pSync array must be initialized to SHMEM_SYNC_VALUE on all participating PEs before calling a reduction routine. The pWrk array does not need to be initialized by the user.

It is the user's responsibility to ensure that the pSync array is not being updated on any PE in the active set while any of the PEs participate in processing of a SHMEM reduction routine. Be careful of the following situations:

  • If the pSync array is initialized at run time, some type of synchronization is needed to ensure that all PEs in the working set have initialized pSync before any of them enter a SHMEM routine called with the pSync synchronization array.
  • A pSync or pWrk array can be reused in a subsequent reduction routine call only if none of the PEs in the active set are still processing a prior reduction routine call that used the same pSync or pWrk arrays. In general, this can be assured only by doing some type of synchronization. However, in the special case of reduction routines being called with the same active set, you can allocate two pSync and pWrk arrays and alternate between them on successive calls.

The pSync array is initialized the first time it is used.

EXAMPLES

Example 1: This Fortran example statically initializes the pSync array and finds the product of the real variable FOO across all the even PEs.

INCLUDE "mpp/shmem.fh"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL FOO, FOOPROD, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOPROD, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_COMP8_PROD_TO_ALL(FOOPROD, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOPROD
ENDIF

Example 2: Consider the following C/C++ call:

shmem_short_prod_to_all(target, source, 3, 0, 0, 8, pwrk, psync);

The preceding call is more efficient, but semantically equivalent to, the combination of the following calls:

shmem_short_prod_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_short_prod_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_short_prod_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);

Note that two sets of pWrk and pSync arrays are used alternately because no synchronization is done between calls.

الوصف

تقوم روتينات shmem_complexd_prod_to_all بحساب حاصل ضرب العناصر في المصفوفة source عبر الـ PEs المحددة بواسطة PE_start و logPE_stride و PE_size. يتم وضع نتيجة الاختزال في المصفوفة target.

يتم إجراء الاختزال عبر الـ PEs في المجال الفرعي الديكارتي المحدد بواسطة PE_start و logPE_stride و PE_size. nreduce هو عدد العناصر المراد اختزالها. يتم إجراء الاختزال عنصرًا بعنصر. على سبيل المثال، إذا كان nreduce يساوي 3، فإن العنصر الأول من target سيحتوي على حاصل ضرب العنصر الأول من source من جميع الـ PEs المشاركة، وسيحتوي العنصر الثاني من target على حاصل ضرب العنصر الثاني من source من جميع الـ PEs المشاركة، وهكذا.

مطلوبة المصفوفتان pWrk و pSync لعملية الاختزال. يجب على المستخدم تخصيص وتمرير هاتين المصفوفتين. يجب أن يكون حجم المصفوفة pWrk على الأقل SHMEM_REDUCE_MIN_WRKDATA_SIZE عنصرًا. يجب أن يكون حجم المصفوفة pSync على الأقل SHMEM_REDUCE_SYNC_SIZE عنصرًا.

تستخدم المصفوفة pSync لمزامنة عملية الاختزال. يجب على جميع الـ PEs المشاركة في الاختزال تهيئة عناصر المصفوفة pSync إلى SHMEM_SYNC_VALUE قبل استدعاء روتين الاختزال. يتم تحديث المصفوفة pSync بواسطة مكتبة SHMEM أثناء الاختزال ويجب ألا يقوم المستخدم بتعديلها حتى تكتمل عملية الاختزال.

ملاحظات

المصفوفتان pSync و pWrk مطلوبتان لعملية الاختزال. يجب تهيئة هاتين المصفوفتين قبل الاستخدام. يجب تهيئة المصفوفة pSync إلى SHMEM_SYNC_VALUE على جميع الـ PEs المشاركة قبل استدعاء روتين اختزال. لا تحتاج المصفوفة pWrk إلى تهيئة من قبل المستخدم.

تقع على عاتق المستخدم مسؤولية التأكد من أن المصفوفة pSync لا يتم تحديثها على أي PE في المجموعة النشطة بينما تشارك أي من الـ PEs في معالجة روتين اختزال SHMEM. كن حذرًا من المواقف التالية:

  • إذا تم تهيئة المصفوفة pSync وقت التشغيل، فستكون هناك حاجة إلى نوع من المزامنة لضمان أن جميع الـ PEs في مجموعة العمل قد قامت بتهيئة pSync قبل أن تدخل أي منها روتين SHMEM تم استدعاؤه باستخدام مصفوفة المزامنة pSync.
  • يمكن إعادة استخدام مصفوفة pSync أو pWrk في استدعاء لاحق لروتين اختزال فقط إذا لم تكن أي من الـ PEs في المجموعة النشطة لا تزال تعالج استدعاء روتين اختزال سابق استخدم نفس المصفوفتين pSync أو pWrk. بشكل عام، لا يمكن ضمان ذلك إلا عن طريق إجراء نوع من المزامنة. ومع ذلك، في الحالة الخاصة لروتينات الاختزال التي يتم استدعاؤها بنفس المجموعة النشطة، يمكنك تخصيص مصفوفتين pSync و pWrk والتبديل بينهما في الاستدعاءات المتتالية.

يتم تهيئة المصفوفة pSync في المرة الأولى التي يتم استخدامها فيها.

يجب عليك التأكد من أن مصفوفة pSync لا يتم تحديثها على أي PE في المجموعة النشطة أثناء مشاركة أي من الـ PEs في معالجة روتين اختزال SHMEM. كن حذرًا من المواقف التالية: إذا تم تهيئة مصفوفة pSync وقت التشغيل، فستكون هناك حاجة إلى نوع من المزامنة لضمان أن جميع الـ PEs في مجموعة العمل قد قامت بتهيئة pSync قبل أن تدخل أي منها روتين SHMEM تم استدعاؤه باستخدام مصفوفة المزامنة pSync. يمكن إعادة استخدام مصفوفة pSync أو pWrk في استدعاء لاحق لروتين اختزال فقط إذا لم تكن أي من الـ PEs في المجموعة النشطة لا تزال تعالج استدعاء روتين اختزال سابق استخدم نفس مصفوفتي pSync أو pWrk. بشكل عام، لا يمكن ضمان ذلك إلا عن طريق إجراء نوع من المزامنة. ومع ذلك، في الحالة الخاصة لروتينات الاختزال التي يتم استدعاؤها بنفس المجموعة النشطة، يمكنك تخصيص مصفوفتين pSync و pWrk والتبديل بينهما في الاستدعاءات المتتالية.

أمثلة

مثال 1: يقوم هذا المثال بلغة Fortran بتهيئة المصفوفة pSync بشكل ثابت وإيجاد حاصل ضرب المتغير الحقيقي FOO عبر جميع الـ PEs الزوجية.

INCLUDE "mpp/shmem.h"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL FOO, FOOPROD, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOPROD, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_COMP8_PROD_TO_ALL(FOOPROD, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOPROD
ENDIF

مثال 2: ضع في اعتبارك استدعاء C/C++ التالي:

shmem_short_prod_to_all(target, source, 3, 0, 0, 8, pwrk, psync);

الاستدعاء السابق أكثر كفاءة، ولكنه مكافئ دلاليًا، لمجموعة الاستدعاءات التالية:

shmem_short_prod_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_short_prod_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_short_prod_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);

لاحظ أنه تم استخدام مجموعتين من مصفوفتي pWrk و pSync بالتناوب لأنه لم يتم إجراء مزامنة بين الاستدعاءات.
