الاسم

apptainer-build - بناء صورة Apptainer

ملخص

apptainer build [خيارات محلية...]

الوصف

مسار الصورة:

عندما يقوم Apptainer ببناء الحاوية، يمكن أن يكون الإخراج أحد التنسيقات القليلة:

  الافتراضي:    تنسيق صورة Apptainer غير القابلة للكتابة والمضغوطة (افتراضي)
  sandbox:    هذه حاوية قابلة للكتابة داخل بنية دليل

ملاحظة: إنه سير عمل شائع لاستخدام وضع "sandbox" لتطوير
الحاوية، ثم بنائها كتنسيق Apptainer افتراضي للاستخدام الإنتاجي.
التنسيق الافتراضي غير قابل للتغيير.

مواصفات البناء:

الهدف من مواصفات البناء هو ملف تعريف (def) أو صورة محلية أو URI يمكن
استخدامها لإنشاء حاوية Apptainer. توجد عدة تنسيقات مستهدفة محلية مختلفة:

  ملف def  : هذه وصفة لبناء حاوية (أمثلة أدناه)
  دليل:      بنية دليل تحتوي على نظام ملفات (ch)root
  صورة:      صورة محلية على جهازك (سيتم تحويلها إلى sif إذا
              كانت بتنسيق قديم)

يمكن أن تكون الأهداف أيضًا عن بعد ويتم تعريفها بواسطة URI بالتنسيقات التالية:

  library://  مكتبة صور (لا يوجد افتراضي)
  docker://   سجل Docker/OCI (الافتراضي Docker Hub)
  shub://     سجل Apptainer (الافتراضي Singularity Hub)
  oras://     سجل OCI يحتوي على ملفات SIF باستخدام ORAS

الملفات المؤقتة:

الموقع المستخدم للمجلدات المؤقتة هو '/tmp' افتراضيًا ولكن
يمكن تجاوزه بواسطة متغير البيئة TMPDIR، ويمكن تجاوزه بواسطة متغير البيئة
APPTAINER_TMPDIR. يجب أن يكون المجلد المؤقت المستخدم أثناء البناء على نظام
ملفات به مساحة كافية لاستيعاب صورة الحاوية بأكملها، غير مضغوطة،
بما في ذلك أي ملفات مؤقتة يتم إنشاؤها وإزالتها لاحقًا
أثناء البناء. قد تحتاج إلى تعيين APPTAINER_TMPDIR أو TMPDIR عند
بناء حاوية كبيرة على نظام به نظام /tmp صغير.

الخيارات

--arch="amd64" الهندسة المعمارية للبناء من أجلها

--arch-variant="" متغير الهندسة المعمارية للبناء من أجله

--authfile="" ملف مصادقة بأسلوب Docker لاستخدامه للكتابة/القراءة بيانات اعتماد سجل OCI

-B, --bind=[] تحديد مسار ربط المستخدم. المواصفات لها التنسيق src[:dest[:opts]]، حيث src و dest هما المسارات الخارجية والداخلية. إذا لم يتم توفير dest، فسيتم تعيينها لتكون مساوية لـ src. يمكن تحديد خيارات الربط ('opts') كـ 'ro' (للقراءة فقط) أو 'rw' (للقراءة/الكتابة، وهو الافتراضي). يمكن تقديم مسارات ربط متعددة بواسطة قائمة مفصولة بفواصل.

--build-arg=[] يحدد variable=value لاستبدال إدخالات {{ variable }} في ملف تعريف البناء

--build-arg-file="" يحدد ملفًا يحتوي على أسطر variable=value لاستبدال '{{ variable }}' بالقيمة في ملفات تعريف البناء

--disable-cache[=false] لا تستخدم ذاكرة التخزين المؤقت أو تنشئ ذاكرة تخزين مؤقت

--docker-host="" تحديد مضيف خادم Docker مخصص

--docker-login[=false] تسجيل الدخول إلى مستودع Docker تفاعليًا

-e, --encrypt[=false] بناء صورة بنظام ملفات مشفر

-f, --fakeroot[=false] البناء بمظهر التشغيل كـ root (افتراضي عند البناء من ملف تعريف بشكل غير مميز)

--fix-perms[=false] ضمان أن المالك لديه أذونات rwX على كل محتوى الحاوية لمصادر oci/docker

-F, --force[=false] الكتابة فوق ملف صورة إذا كان موجودًا

-h, --help[=false] مساعدة للبناء

--json[=false] تفسير تعريف البناء كـ JSON

--library="" عنوان مكتبة الحاوية

--mksquashfs-args="" وسيطات إضافية لتمريرها إلى mksquashfs عند إنشاء ملفات SIF

--mount=[] مواصفات تحميل مثل 'type=bind,source=/opt,destination=/hostopt'.

--no-cleanup[=false] لا تنظيف الحزمة بعد فشل البناء، قد يكون مفيدًا للتصحيح

--no-https[=false] استخدام http بدلاً من https لـ docker:// oras:// و library:///... URIs

-T, --notest[=false] البناء دون تشغيل الاختبارات في قسم %test

--nv[=false] حقن مكتبات Nvidia للمضيف أثناء البناء للأقسام post و test

--nvccli[=false] استخدام nvidia-container-cli لإعداد GPU (تجريبي)

--passphrase[=false] طلب عبارة مرور للتشفير

--pem-path="" إدخال مسار إلى مفتاح RSA بتنسيق PEM لحاوية مشفرة

--rocm[=false] حقن مكتبات Rocm للمضيف أثناء البناء للأقسام post و test

-s, --sandbox[=false] بناء الصورة بتنسيق sandbox (بنية دليل chroot)

--section=[all] تشغيل أقسام محددة فقط من ملف التعريف (setup, post, files, environment, test, labels, none)

-u, --update[=false] تشغيل التعريف فوق حاوية موجودة (يتخطى الرأس)

--userns[=false] البناء دون استخدام setuid حتى لو كان متاحًا

--warn-unused-build-args[=false] يعرض تحذيرًا بدلاً من رسالة قاتلة عندما لا تتطابق وسيطات البناء تمامًا

--writable-tmpfs[=false] أثناء قسم %test، يجعل نظام الملفات متاحًا للقراءة والكتابة مع بيانات غير دائمة (مع دعم overlay فقط)

مثال

  أساس نظام التشغيل لملف DEF:
      المكتبة:
          Bootstrap: library
          From: debian:9
      Docker:
          Bootstrap: docker
          From: tensorflow/tensorflow:latest
          IncludeCmd: yes # استخدم CMD كـ runscript بدلاً من ENTRYPOINT
      Singularity Hub:
          Bootstrap: shub
          From: singularityhub/centos
      YUM/RHEL:
          Bootstrap: yum
          OSVersion: 7
          MirrorURL: http://mirror.centos.org/centos-%{OSVERSION}/%{OSVERSION}/os/x86_64/
          Include: yum
      SUSE:
          Bootstrap: zypper # على نظام SLE، يتم استخدام تسجيل المضيف للبناء
          Include: zypper
      openSUSE:
          Bootstrap: zypper
          MirrorURL: http://download.opensuse.org/distribution/openSUSE-stable/repo/oss
          Include: zypper
      Debian/Ubuntu:
          Bootstrap: debootstrap
          OSVersion: trusty
          MirrorURL: http://us.archive.ubuntu.com/ubuntu/
      صورة محلية:
          Bootstrap: localimage
          From: /home/dave/starter.img
      Scratch:
          Bootstrap: scratch # املأ الحاوية بنظام جذر بسيط في %setup
  أقسام ملف التعريف:
  يتم تقديم الأقسام التالية بترتيب المعالجة، مع استثناء أن الملصقات والبيئة يمكن
  التلاعب بها أيضًا في %post.
      %pre
          echo "هذه كتلة نصية سيتم تنفيذها على المضيف، بصلاحيات root قبل"
          echo "أن يتم تجهيز الحاوية. هذا القسم لا يستخدم بشكل شائع."
      %setup
          echo "هذه كتلة نصية سيتم تنفيذها على المضيف، بصلاحيات root، بعد"
          echo "أن تم تجهيز الحاوية. لتثبيت الأشياء في الحاوية"
          echo "ارجع إلى موقع نظام الملفات باستخدام $APPTAINER_ROOTFS."
      %files
          /path/on/host/file.txt /path/on/container/file.txt
          relative_file.txt /path/on/container/relative_file.txt
      %post
          echo "سيتم تنفيذ قسم كتلة النص هذه من داخل الحاوية بعد"
          echo "إنشاء وتجهيز قاعدة/بناء الحاوية."
      %environment
          LUKE=goodguy
          VADER=badguy
          HAN=someguy
          export HAN VADER LUKE
      %test
          echo "حدد أي أوامر اختبار يجب تنفيذها بعد بناء الحاوية."
          echo "سيتم تنفيذ كتلة النص هذه من داخل الحاوية قيد التشغيل"
          echo "بصلاحيات المستخدم root. انتبه إلى قيمة الخروج/الإرجاع لكتلة النص هذه"
          echo "حيث سيتم افتراض أي رمز خروج غير صفري على أنه فشل."
          exit 0
      %runscript
          echo "حدد الإجراءات للحاوية ليتم تنفيذها باستخدام أمر التشغيل أو"
          echo "عند تنفيذ الحاوية."
      %startscript
          echo "حدد الإجراءات للحاوية للقيام بها عند تشغيلها كنسخة."
      %labels
          HELLO MOTO
          KEY VALUE
      %help
          هذا ملف نصي ليتم عرضه باستخدام أمر run-help.
  الأوامر:
      بناء ملف sif من ملف وصفة Apptainer:
          $ apptainer build /tmp/debian0.sif /path/to/debian.def
      بناء صورة sif من المكتبة:
          $ apptaine
