signal(2) دليل استدعاءات النظام signal(2)

الاسم

signal - التعامل مع إشارات ANSI C

المكتبة

مكتبة C القياسية (libc, -lc)

الملخص

#include <signal.h>
typedef typeof(void (int))  *sighandler_t;
sighandler_t signal(int signum, sighandler_t handler);

الوصف

تحذير: سلوك signal() يختلف عبر إصدارات UNIX، وقد اختلف تاريخيًا عبر إصدارات Linux المختلفة. تجنب استخدامه: استخدم sigaction(2) بدلاً من ذلك. انظر قابلية النقل أدناه.

تقوم signal() بتعيين تصرف الإشارة signum إلى handler، والذي يكون إما SIG_IGN، أو SIG_DFL، أو عنوان دالة معرفة من قبل المبرمج (وهي "معالج الإشارة").

إذا تم تسليم الإشارة signum إلى العملية، يحدث أحد ما يلي:

*
إذا تم تعيين التصرف إلى SIG_IGN، يتم تجاهل الإشارة.
*
إذا تم تعيين التصرف إلى SIG_DFL، يحدث الإجراء الافتراضي المرتبط بالإشارة (انظر signal(7)).
*
إذا تم تعيين التصرف إلى دالة، فسيتم أولاً إعادة تعيين التصرف إلى SIG_DFL، أو يتم حظر الإشارة (انظر قابلية النقل أدناه)، ثم يتم استدعاء handler بالوسيط signum. إذا تسبب استدعاء المعالج في حظر الإشارة، فسيتم إلغاء حظر الإشارة عند العودة من المعالج.

لا يمكن التقاط أو تجاهل الإشارتين SIGKILL و SIGSTOP.

قيمة الإرجاع

تقوم signal() بإرجاع القيمة السابقة لمعالج الإشارة. عند الفشل، ترجع SIG_ERR، ويتم تعيين errno للإشارة إلى الخطأ.

الأخطاء

EINVAL
signum غير صالح.

الإصدارات

استخدام sighandler_t هو امتداد GNU، يتم عرضه إذا تم تعريف _GNU_SOURCE؛ وتقوم glibc أيضًا بتعريف sig_t (المشتقة من BSD) إذا تم تعريف _BSD_SOURCE (glibc 2.19 والإصدارات الأقدم) أو _DEFAULT_SOURCE (glibc 2.19 والإصدارات الأحدث). التعريف القياسي لـ signal() هو:


typeof(void (int)) *signal(int signum, typeof(void (int)) *handler);

قابلية النقل

الاستخدام الوحيد القابل للنقل لـ signal() هو تعيين تصرف الإشارة إلى SIG_DFL أو SIG_IGN. تختلف دلالات استخدام signal() لإنشاء معالج إشارة عبر الأنظمة (ويسمح POSIX.1 صراحةً بهذا الاختلاف)؛ لا تستخدمه لهذا الغرض.

حل POSIX.1 مشكلة قابلية النقل بتحديد sigaction(2)، والذي يوفر تحكمًا صريحًا في الدلالات عند استدعاء معالج الإشارة؛ استخدم هذا الواجهة بدلاً من signal().

المعايير

C11, POSIX.1-2024.

التاريخ

C89, POSIX.1-2001.

في أنظمة UNIX الأصلية، عند استدعاء معالج تم إنشاؤه باستخدام signal() عن طريق تسليم إشارة، يتم إعادة تعيين تصرف الإشارة إلى SIG_DFL، ولم يقم النظام بحظر تسليم مثيلات أخرى للإشارة. هذا يعادل استدعاء sigaction(2) مع العلامات التالية:


sa.sa_flags = SA_RESETHAND | SA_NODEFER;

يوفر System V أيضًا هذه الدلالات لـ signal(). كان هذا سيئًا لأن الإشارة قد يتم تسليمها مرة أخرى قبل أن تتاح للمعالج فرصة لإعادة تأسيس نفسه. علاوة على ذلك، يمكن أن تؤدي عمليات التسليم السريعة لنفس الإشارة إلى استدعاءات متكررة للمعالج.

قامت BSD بتحسين هذا الوضع، ولكن للأسف قامت أيضًا بتغيير دلالات واجهة signal() الموجودة أثناء القيام بذلك. على BSD، عند استدعاء معالج الإشارة، لا تتم إعادة تعيين تصرف الإشارة، ويتم حظر التسليمات الإضافية للإشارة أثناء تنفيذ المعالج. علاوة على ذلك، يتم إعادة تشغيل بعض استدعاءات النظام الحاجبة تلقائيًا إذا تم مقاطعتها بواسطة معالج الإشارة (انظر signal(7)). دلالات BSD تعادل استدعاء sigaction(2) مع العلامات التالية:


sa.sa_flags = SA_RESTART;

الوضع في Linux هو كما يلي:

•
يقدم استدعاء نظام signal() في النواة دلالات System V.
•
افتراضيًا، في glibc 2 والإصدارات الأحدث، لا تستدعي دالة الغلاف signal() استدعاء النظام. بدلاً من ذلك، تستدعي sigaction(2) باستخدام علامات توفر دلالات BSD. يتم توفير هذا السلوك الافتراضي طالما تم تعريف ماكرو اختبار الميزة المناسب: _BSD_SOURCE في glibc 2.19 والإصدارات الأقدم أو _DEFAULT_SOURCE في glibc 2.19 والإصدارات الأحدث. (افتراضيًا، يتم تعريف هذه الماكرو؛ انظر feature_test_macros(7) للحصول على التفاصيل.) إذا لم يتم تعريف ماكرو اختبار الميزة هذا، فإن signal() يوفر دلالات System V.

ملاحظات

آثار signal() في عملية متعددة الخيوط غير محددة.

وفقًا لـ POSIX، فإن سلوك العملية غير محدد بعد تجاهلها إشارة SIGFPE أو SIGILL أو SIGSEGV لم يتم إنشاؤها بواسطة kill(2) أو raise(3). القسمة الصحيحة على صفر لها نتيجة غير محددة. على بعض المعماريات، ستنشئ إشارة SIGFPE. (قسمة أصغر عدد صحيح سالب على -1 قد تنشئ أيضًا SIGFPE.) تجاهل هذه الإشارة قد يؤدي إلى حلقة لا نهائية.

انظر sigaction(2) للحصول على تفاصيل حول ما يحدث عند تعيين تصرف SIGCHLD إلى SIG_IGN.

انظر signal-safety(7) للحصول على قائمة بالدوال الآمنة للإشارات غير المتزامنة التي يمكن استدعاؤها بأمان من داخل معالج إشارة.

NAME

signal - signal handling

LIBRARY

Standard C library (libc, -lc)

SYNOPSIS

#include <signal.h> typedef void (*sighandler_t)(int); sighandler_t signal(int signum, sighandler_t handler); sighandler_t sigset(int signum, sighandler_t handler);

DESCRIPTION

The signal() function is a primitive signal handling interface. It allows a process to specify how it should respond to a particular signal. The signal() function is obsolete; see sigaction(2) for details.

The signal() function installs the signal handler pointed to by handler for the signal specified by signum. The previously installed handler for signum is returned.

The value of signum must be a non-negative signal number. Special values are:

SIG_DFL
Default signal handling.
SIG_IGN
Ignore the signal.

If handler is one of these special values, it is installed as the handler for the signal signum.

Otherwise, handler must be the address of a signal-catching function. This function is known as the signal handler. When the signal signum is delivered to the process, the currently executing code is abruptly interrupted, and the signal handler is invoked with the argument signum.

When a signal handler is invoked, the kernel will automatically reset the handler for that signal to SIG_DFL. This is a historical quirk: the behavior of POSIX.1 is that if the handler is not installed in the kernel as SIG_DFL, then the handler is called. However, the behavior of most systems is that the handler is reset to SIG_DFL unless the handler function itself resets it. Therefore, if you want the handler to remain installed, it must reset it itself, e.g.

signal(signum, handler);

This behavior is specified by POSIX.1-2001 and SUSv2, but it is implementation-defined in C99.

When the signal handler returns, the process resumes execution at the point it was interrupted. If the interrupted code was in the middle of a system call, the system call may return an error. If the system call was one of those that might be interrupted by a signal (e.g., read(2), write(2), select(2), poll(2)), then the system call may return -1 with errno set to EINTR. See signal(7) for more details about interrupted system calls.

The sigset() function is identical to signal(), except that it does not automatically reset the signal handler to SIG_DFL upon signal delivery.

The default action for each signal is listed in signal(7).

RETURN VALUE

On success, signal() and sigset() return the previous value of the handler for the specified signal. On error, they return SIG_ERR, and errno is set to indicate the error.

ERRORS

EINVAL
Invalid signal number signum.

VERSIONS

The sigset() function is not specified by POSIX.1 and is provided only for backward compatibility.

STANDARDS

The signal() function is specified by the C standard and POSIX.1. The behavior regarding the resetting of the handler to SIG_DFL is implementation-defined in C99, but POSIX.1-2001 requires the reset.

HISTORY

The signal() function first appeared in Version 7 Unix. The sigset() function first appeared in BSD Unix.

NOTES

The signal() interface is considered obsolete and dangerous. It has several undesirable properties:

  • The behavior of whether the handler is automatically reset is implementation-dependent (though POSIX requires it to be reset). This makes code using signal() not portable.
  • The handling of signals delivered while the handler is running is problematic. By default, other signals are blocked while the handler is running, but this behavior is also implementation-dependent.
  • Signal handler behavior is not reliably specified when a signal occurs during a system call.
  • Signals cannot be reliably sent to other processes or threads.

Because of these problems, the sigaction(2) interface is recommended for all signal handling. It provides a much more robust and well-defined interface.

The sigset() function's primary purpose was to provide a way to install a signal handler that would persist across signal deliveries. However, even with sigset(), the other problems with the signal() interface remain.
