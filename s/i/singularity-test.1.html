الاسم

apptainer-test - تشغيل الاختبارات المعرفة من قبل المستخدم داخل حاوية

الملخص

apptainer test [خيارات التنفيذ...]

الوصف

يسمح لك الأمر 'test' بتنفيذ نص برمجي للاختبار (إذا كان متاحًا) داخل
حاوية معينة

ملاحظة:
في الحالات التي تكون فيها عملية خادم تعمل داخل الحاوية،
فإن أوامر الحاوية اللاحقة سيتم تشغيلها جميعًا داخل نفس
مساحات الأسماء. هذا يعني أنه لن يتم تكريم خيارات --writable و --contain
حيث تم تكوين مساحات الأسماء بالفعل بواسطة الأمر 'apptainer start'.

خيارات

--add-caps="" قائمة صلاحيات مفصولة بفواصل لإضافتها

--allow-setuid[=false] السماح بتنفيذ ملفات setuid داخل الحاوية (للمستخدم الجذر فقط)

--app="" تعيين تطبيق لتشغيله داخل حاوية

--apply-cgroups="" تطبيق cgroups من ملف لعمليات الحاوية (للمستخدم الجذر فقط)

--authfile="" ملف مصادقة بأسلوب Docker لاستخدامه لتسجيل قراءة بيانات اعتماد سجل OCI

-B, --bind=[] مواصفات مسار ربط المستخدم. المواصفات لها التنسيق src[:dest[:opts]]، حيث src و dest هما المسارات الخارجية والداخلية. إذا لم يتم تحديد dest، فسيتم تعيينها على أنها src. يمكن تحديد خيارات الربط ('opts') كـ 'ro' (للقراءة فقط) أو 'rw' (للقراءة/الكتابة، وهو الافتراضي). يمكن تقديم مسارات ربط متعددة كقائمة مفصولة بفواصل.

--blkio-weight=0 الوزن النسبي لـ Block IO في النطاق 10-1000، 0 لتعطيله

--blkio-weight-device=[] الوزن النسبي لـ Block IO لجهاز محدد

-e, --cleanenv[=false] تنظيف البيئة قبل تشغيل الحاوية

--compat[=false] تطبيق الإعدادات لزيادة توافق OCI/Docker. يستنتج --containall، --no-init، --no-umask، --no-eval، --writable-tmpfs.

-c, --contain[=false] استخدام الحد الأدنى من /dev ومجلدات فارغة أخرى (مثل /tmp و $HOME) بدلاً من مشاركة أنظمة الملفات من المضيف الخاص بك

-C, --containall[=false] احتواء ليس فقط أنظمة الملفات، ولكن أيضًا PID و IPC والبيئة

--cpu-shares=-1 حصة وحدة المعالجة المركزية للحاوية

--cpus="" عدد وحدات المعالجة المركزية المتاحة للحاوية

--cpuset-cpus="" قائمة وحدات المعالجة المركزية للمضيف المتاحة للحاوية

--cpuset-mems="" قائمة عقد ذاكرة المضيف المتاحة للحاوية

--cwd="" الدليل الحالي الأولي لعملية الحمولة داخل الحاوية (مرادف لـ --pwd)

--disable-cache[=false] عدم استخدام أو إنشاء ذاكرة تخزين مؤقتة

--dns="" قائمة خوادم DNS مفصولة بفواصل لإضافتها في resolv.conf

--docker-host="" تحديد مضيف Docker daemon مخصص

--docker-login[=false] تسجيل الدخول إلى مستودع Docker تفاعليًا

--drop-caps="" قائمة صلاحيات مفصولة بفواصل للإسقاط

--env=[] تمرير متغير بيئة إلى العملية المحتواة

--env-file=[] تمرير متغيرات البيئة من ملف إلى العملية المحتواة

-f, --fakeroot[=false] تشغيل الحاوية بمظهر المستخدم الجذر

--fusemount=[] مواصفات ربط نظام ملفات FUSE بالشكل: ' ' - حيث 'container' أو 'host'، مما يحدد مكان إجراء الربط ('container-daemon' أو 'host-daemon' سيشغل عملية FUSE بشكل منفصل). هو المسار إلى ملف FUSE التنفيذي، بالإضافة إلى خيارات الربط. هو الموقع داخل الحاوية حيث سيتم ربط FUSE. مثال: 'container:sshfs 10.0.0.1:/ /sshfs'. يتضمن --pid.

-h, --help[=false] مساعدة للاختبار

-H, --home="/build" مواصفات دليل المنزل. يمكن أن تكون المواصفات إما مسار مصدر أو زوج مصدر:وجهة. المصدر هو مسار دليل المنزل خارج الحاوية، والوجهة تتجاوز دليل المنزل داخل الحاوية.

--hostname="" تعيين اسم مضيف الحاوية

-i, --ipc[=false] تشغيل الحاوية في مساحة أسماء IPC جديدة

--keep-privs[=false] السماح للمستخدم الجذر بالاحتفاظ بالصلاحيات في الحاوية (للمستخدم الجذر فقط)

--memory="" حد الذاكرة بالبايت

--memory-reservation="" حد الذاكرة الناعم بالبايت

--memory-swap="" حد الذاكرة الافتراضية، استخدم -1 لذاكرة افتراضية غير محدودة

--mount=[] مواصفات ربط على سبيل المثال 'type=bind,source=/opt,destination=/hostopt'.

-n, --net[=false] تشغيل الحاوية في مساحة أسماء شبكة جديدة (يقوم بإعداد واجهة شبكة جسرية افتراضيًا)

--netns-path="" الانضمام إلى مساحة أسماء الشبكة في المسار المحدد (كجذر، أو إذا سمح به في apptainer.conf)

--network="" تحديد نوع الشبكة المطلوب مفصولة بفواصل، ستقوم كل شبكة بتشغيل واجهة مخصصة داخل الحاوية

--network-args=[] تحديد وسائط الشبكة لتمريرها إلى CNI plugins

--no-eval[=false] عدم تقييم متغيرات البيئة أو أوامر OCI ENTRYPOINT/CMD/ARGS باستخدام shell

--no-home[=false] عدم ربط دليل المنزل للمستخدمين إذا كان /home ليس الدليل الحالي

--no-https[=false] استخدام http بدلاً من https لـ docker:// oras:// و library:///... URIs

--no-init[=false] عدم بدء عملية shim باستخدام --pid

--no-mount=[] تعطيل خيار واحد أو أكثر من خيارات 'mount xxx' المحددة في apptainer.conf و/أو تحديد مسار وجهة مطلق لتعطيل إدخال مسار ربط، أو 'bind-paths' لتعطيل جميع إدخالات مسارات الربط.

--no-pid[=false] عدم تشغيل الحاوية في مساحة أسماء PID جديدة

--no-privs[=false] إسقاط جميع الصلاحيات من المستخدم الجذر في الحاوية)

--no-umask[=false] عدم نشر umask إلى الحاوية، تعيين umask افتراضي 0022

--nv[=false] تمكين دعم Nvidia

--nvccli[=false] استخدام nvidia-container-cli لإعداد GPU (تجريبي)

--oom-kill-disable[=false] تعطيل قاتل OOM

-o, --overlay=[] استخدام صورة overlayFS لتخزين البيانات الدائمة أو كطبقة قراءة فقط للحاوية

--passphrase[=false] مطالبة بكلمة مرور للتشفير

--pem-path="" إدخال مسار إلى مفتاح RSA بتنسيق PEM لحاوية مشفرة

-p, --pid[=false] تشغيل الحاوية في مساحة أسماء PID جديدة

--pids-limit=0 تحديد عدد PIDs للحاوية، استخدم -1 لعدد غير محدود

--rocm[=false] تمكين دعم Rocm التجريبي

-S, --scratch=[] تضمين دليل مؤقت داخل الحاوية يتم ربطه بدليل مؤقت (استخدم -W لفرض الموقع)

--security=[] تمكين ميزات الأمان (SELinux, Apparmor, Seccomp)

--sharens[=false] مشاركة مساحة الأسماء والصورة مع حاويات أخرى تم تشغيلها من نفس العملية الأصلية

--unsquash[=false] تحويل ملف SIF إلى صندوق رمل مؤقت قبل التشغيل

-u, --userns[=false] تشغيل الحاوية في مساحة أسماء مستخدم جديدة

--uts[=false] تشغيل الحاوية في مساحة أسماء UTS جديدة

-W, --workdir="" الدليل الحالي الذي سيتم استخدامه لـ /tmp و /var/tmp و $HOME (إذا تم استخدام -c/--contain أيضًا)

-w, --writable[=false] بشكل افتراضي، جميع حاويات Apptainer تكون قابلة للقراءة فقط. هذا الخيار يجعل نظام الملفات متاحًا للقراءة/الكتابة.

--writable-tmpfs[=false] يجعل نظام الملفات متاحًا للقراءة/الكتابة مع بيانات غير دائمة (مع دعم overlay فقط)

مثال

  قم بتعيين قسم '%test' باستخدام ملف تعريف مثل هذا:
  %test
      echo "hello from test" "$@"
  $ apptainer test /tmp/debian.sif command
      hello from test command
  للمساعدة الإضافية، يرجى زيارة صفحات الوثائق العامة الخاصة بنا والتي
  يمكن العثور عليها على:
      https://apptainer.org/docs/

singularity-test — اختبارات الوحدة لـ Singularity

NAME

singularity-test — اختبارات الوحدة لـ Singularity

SYNOPSIS

singularity-test [OPTIONS] [TEST...]

DESCRIPTION

singularity-test يقوم بتشغيل اختبارات الوحدة المضمنة لـ Singularity.

إذا لم يتم تحديد أي TEST، فسيتم تشغيل جميع الاختبارات.

تتوفر اختبارات الوحدة كملفات قابلة للتنفيذ في الدليل test/ داخل شجرة المصدر.

OPTIONS

-v, --verbose
زيادة مستوى التفاصيل.
-f, --force
فرض تشغيل الاختبارات حتى لو كانت هناك مشكلة.
-h, --help
عرض رسالة المساعدة والخروج.

EXAMPLE

تشغيل جميع اختبارات الوحدة:

singularity-test

تشغيل اختبار وحدة معين:

singularity-test -v test/container

SEE ALSO

singularity-build(1), singularity-run(1)
