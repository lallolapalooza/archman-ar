الوصف

يُستخدم استدعاء النظام sigaction() لتغيير الإجراء الذي يتخذه العملية عند استقبال إشارة معينة. (انظر signal(7) للحصول على نظرة عامة على الإشارات.)

يحدد signum الإشارة ويمكن أن تكون أي إشارة صالحة باستثناء SIGKILL و SIGSTOP.

إذا كان act غير NULL، يتم تثبيت الإجراء الجديد للإشارة signum من act. إذا كان oldact غير NULL، يتم حفظ الإجراء السابق في oldact.

يتم تعريف هيكل sigaction كالتالي:


struct sigaction {
    void     (*sa_handler)(int);
    void     (*sa_sigaction)(int, siginfo_t *, void *);
    sigset_t   sa_mask;
    int        sa_flags;
    void     (*sa_restorer)(void);
};

في بعض بنيات المعالج، يتم استخدام اتحاد: لا تقم بتعيين قيمة لكل من sa_handler و sa_sigaction.

الحقل sa_restorer ليس مخصصًا للاستخدام التطبيقي. (لا يحدد POSIX حقلاً sa_restorer.) يمكن العثور على مزيد من التفاصيل حول الغرض من هذا الحقل في sigreturn(2).

يحدد sa_handler الإجراء الذي سيتم ربطه بالإشارة signum ويمكن أن يكون أحد الإجراءات التالية:

•
SIG_DFL للإجراء الافتراضي.
•
SIG_IGN لتجاهل هذه الإشارة.
•
مؤشر إلى دالة معالجة الإشارة. تتلقى هذه الدالة رقم الإشارة كوسيط وحيد لها.

إذا تم تحديد SA_SIGINFO في sa_flags، فإن sa_sigaction (بدلاً من sa_handler) يحدد دالة معالجة الإشارة للإشارة signum. تتلقى هذه الدالة ثلاثة وسائط، كما هو موضح أدناه.

يحدد sa_mask قناعًا للإشارات التي يجب حظرها (أي، إضافتها إلى قناع الإشارات للخيط الذي يتم استدعاء معالج الإشارة فيه) أثناء تنفيذ معالج الإشارة. بالإضافة إلى ذلك، سيتم حظر الإشارة التي أدت إلى تشغيل المعالج، ما لم يتم استخدام العلامة SA_NODEFER.

يحدد sa_flags مجموعة من العلامات التي تعدل سلوك الإشارة. يتم تشكيلها بواسطة OR المنطقي لصفر أو أكثر من العلامات التالية:

SA_NOCLDSTOP
إذا كانت signum هي SIGCHLD، فلا تتلقى إشعارًا عند توقف العمليات الفرعية (أي، عند تلقيها إحدى الإشارات SIGSTOP، SIGTSTP، SIGTTIN، أو SIGTTOU) أو استئنافها (أي، عند تلقيها SIGCONT) (انظر wait(2)). هذه العلامة ذات معنى فقط عند إنشاء معالج لـ SIGCHLD.
SA_NOCLDWAIT (منذ Linux 2.6)
إذا كانت signum هي SIGCHLD، فلا تحول العمليات الفرعية إلى زومبي عند انتهائها. انظر أيضًا waitpid(2). هذه العلامة ذات معنى فقط عند إنشاء معالج لـ SIGCHLD، أو عند تعيين وضع هذه الإشارة إلى SIG_DFL.
إذا تم تعيين العلامة SA_NOCLDWAIT عند إنشاء معالج لـ SIGCHLD، فإن POSIX.1 لا تحدد ما إذا تم إنشاء إشارة SIGCHLD عند انتهاء عملية فرعية. في Linux، يتم إنشاء إشارة SIGCHLD في هذه الحالة؛ في بعض التطبيقات الأخرى، لا يتم ذلك.
SA_NODEFER
لا تضف الإشارة إلى قناع إشارات الخيط أثناء تنفيذ المعالج، ما لم تكن الإشارة محددة في act.sa_mask. نتيجة لذلك، قد يتم تسليم مثيل آخر للإشارة إلى الخيط أثناء تنفيذه للمعالج. هذه العلامة ذات معنى فقط عند إنشاء معالج إشارة.
SA_NOMASK هو مرادف قديم وغير قياسي لهذه العلامة.
SA_ONSTACK
استدعاء معالج الإشارة على مكدس إشارات بديل يتم توفيره بواسطة sigaltstack(2). إذا لم يكن مكدس بديل متاحًا، فسيتم استخدام المكدس الافتراضي. هذه العلامة ذات معنى فقط عند إنشاء معالج إشارة.
SA_RESETHAND
استعادة إجراء الإشارة إلى الوضع الافتراضي عند الدخول إلى معالج الإشارة. هذه العلامة ذات معنى فقط عند إنشاء معالج إشارة.
SA_ONESHOT هو مرادف قديم وغير قياسي لهذه العلامة.
SA_RESTART
توفير سلوك متوافق مع دلالات إشارات BSD عن طريق جعل استدعاءات النظام معينة قابلة لإعادة البدء عبر الإشارات. هذه العلامة ذات معنى فقط عند إنشاء معالج إشارة. انظر signal(7) لمناقشة إعادة تشغيل استدعاءات النظام.
SA_RESTORER
غير مخصص للاستخدام التطبيقي. تستخدم هذه العلامة بواسطة مكتبات C للإشارة إلى أن الحقل sa_restorer يحتوي على عنوان "قفزة إشارة". انظر sigreturn(2) لمزيد من التفاصيل.
SA_SIGINFO (منذ Linux 2.2)
يأخذ معالج الإشارة ثلاثة وسائط، وليس واحدًا. في هذه الحالة، يجب تعيين sa_sigaction بدلاً من sa_handler. هذه العلامة ذات معنى فقط عند إنشاء معالج إشارة.
SA_UNSUPPORTED (منذ Linux 5.11)
تستخدم للاستعلام ديناميكيًا عن دعم بتات العلامات.
إذا نجح محاولة تسجيل معالج مع تعيين هذه العلامة في act->sa_flags بجانب علامات أخرى قد لا يدعمها النواة، وتم استدعاء sigaction() لاحقًا مباشرة مع تحديد نفس رقم الإشارة ومع وسيط oldact غير NULL، وينتج عن ذلك SA_UNSUPPORTED واضح في oldact->sa_flags، فيمكن استخدام oldact->sa_flags كقناع بت يصف أي من العلامات التي قد لا تكون مدعومة مدعومة بالفعل. انظر القسم "الاستعلام ديناميكيًا عن دعم بتات العلامات" أدناه لمزيد من التفاصيل.
SA_EXPOSE_TAGBITS (منذ Linux 5.11)
عادةً، عند تسليم إشارة، يتم مسح مجموعة من بتات العلامات الخاصة ببنية المعالج من الحقل si_addr في siginfo_t. إذا تم تعيين هذه العلامة، فسيتم الاحتفاظ بمجموعة فرعية خاصة ببنية المعالج من بتات العلامات في si_addr.
يجب على البرامج التي تحتاج إلى التوافق مع إصدارات Linux الأقدم من 5.11 استخدام SA_UNSUPPORTED للاستعلام عن الدعم.

Description

This section describes the interface for signal handling in Unix-like systems. It covers signal registration, sending signals, and synchronous signal handling.

The sigaction() function

The sigaction() system call is used to change the action taken by a process on receipt of a specific signal. It allows a process to intercept signals and specifies how these signals should be handled.

The act argument points to a struct sigaction structure that specifies the new action to be associated with the signal sig. The oldact argument points to a buffer that contains the previous action, if any. If oldact is not NULL, the previous action is saved there before the new action is installed.

The struct sigaction structure contains at least the following fields:

sa_flags
Flags that modify the signal handling. Some important flags are:
SA_NOCLDSTOP
If sig is SIGCHLD, prevent SIGCHLD from being generated when a child process stops (i.e., receives SIGSTOP, SIGTSTP, SIGTTIN, or SIGTTOU).
SA_ONSTACK
Take the signal on an alternate signal stack.
SA_RESETHAND
Reset the signal handler to the default action after the signal is delivered.
SA_RESTART
Arrange for certain system calls that are interrupted by this signal to be restarted automatically after the signal handler returns.
SA_SIGINFO
Cause the signal handler to receive three arguments instead of one: the signal number, a pointer to a siginfo_t structure containing signal information, and a pointer to a ucontext_t structure containing context information.
SA_NODEFER
Do not automatically block the signal while the handler is executing.
SA_NOCLDWAIT
If sig is SIGCHLD, prevent the system from discarding the terminated child process entry. This causes the system to keep the child process entry around until the parent explicitly waits for it using wait(2) or a related function.
sa_handler
A pointer to the signal-handling function. If this is SIG_DFL, the default action is performed. If this is SIG_IGN, the signal is ignored. Otherwise, it points to a user-defined function.
sa_mask
A set of signals that will be blocked (added to the signal mask) while the signal handler is executing. If SA_NODEFER is not set, the signal being handled is also automatically added to this mask.
sa_sigaction
An alternative to sa_handler. If sa_flags includes SA_SIGINFO, then this field is used as the signal handler. It takes three arguments instead of one.

The signal mask is a set of signals that are currently blocked and will not be delivered until they are unblocked. Signal sets are manipulated using the following functions:

sigemptyset(sigset_t *set)
Initializes the set pointed to by set to be empty (no signals blocked).
sigfillset(sigset_t *set)
Initializes the set pointed to by set to contain all signals.
sigaddset(sigset_t *set, int signo)
Adds the signal signo to the set pointed to by set.
sigdelset(sigset_t *set, int signo)
Removes the signal signo from the set pointed to by set.
sigismember(const sigset_t *set, int signo)
Returns 1 if the signal signo is a member of the set pointed to by set, and 0 otherwise.

The sigprocmask() system call is used to examine and change the calling thread's signal mask.

how
Specifies how the mask is changed. It can be one of:
SIG_BLOCK
The set of blocked signals is the union of the current set and the set pointed to by set.
SIG_UNBLOCK
The set of blocked signals is the intersection of the current set and the complement of the set pointed to by set.
SIG_SETMASK
The set of blocked signals is replaced by the set pointed to by set.

The sigsuspend() system call temporarily sets the calling thread's signal mask to the set specified by mask and suspends execution until a signal is received that is not blocked.

The sigwait(), sigwaitinfo(), and sigtimedwait() functions allow a thread to wait for specific signals to occur. These functions are especially useful for synchronous signal handling, where a signal is treated as an event to be processed by the thread that is waiting for it, rather than by invoking a signal handler.

sigwait(const sigset_t *set, int *sig)
Waits for any signal in the set set to be delivered. When a signal is received, its number is stored in the location pointed to by sig, and the signal is removed from the process's pending signals. The signal mask of the calling thread is not modified.
sigwaitinfo(const sigset_t *set, siginfo_t *info)
Waits for any signal in the set set to be delivered. If info is not NULL, it points to a siginfo_t structure that is filled with information about the signal. The signal is removed from the process's pending signals. The signal mask of the calling thread is not modified.
sigtimedwait(const sigset_t *set, siginfo_t *info, const struct timespec *timeout)
Similar to sigwaitinfo(), but blocks for at most the time specified by timeout. If timeout is NULL, it behaves like sigwaitinfo(). If the timeout expires before any signal in set is delivered, sigtimedwait() returns an error with errno set to EAGAIN.

The kill(), killpg(), raise(), and pthread_kill() functions are used to send signals to processes or threads.

kill(pid_t pid, int sig)
Sends the signal sig to the process specified by pid. If pid is 0, the signal is sent to all processes in the calling process's process group. If pid is -1, the signal is sent to all processes for which the calling process has permission to send signals, except for process 1 (init).
killpg(pid_t pgrp, int sig)
Sends the signal sig to all processes in the process group specified by pgrp.
raise(int sig)
Sends the signal sig to the calling process itself. This is equivalent to calling kill(getpid(), sig).
pthread_kill(pthread_t thread, int sig)
Sends the signal sig to the thread specified by thread. If thread is the calling thread's ID, the behavior is as if raise() were called.

The sigqueue() function is similar to kill(), but it allows the sender to specify a value (an integer or a pointer) that will be delivered along with the signal. This is useful for passing additional information to the signal handler.

The psignal() and psiginfo() functions print a message describing a signal to standard error. psignal() takes a signal number, while psiginfo() takes a pointer to a siginfo_t structure. They are often used within signal handlers for logging or debugging purposes.

The syslog(), openlog(), closelog(), and setlogmask() functions provide a way to send messages to the system log daemon.

The siginfo_t structure

When a signal is delivered to a process, and the signal handler has been registered with the SA_SIGINFO flag set in sa_flags, the handler is called with three arguments: the signal number, a pointer to a siginfo_t structure, and a pointer to a ucontext_t structure.

The siginfo_t structure provides detailed information about the signal that was received.

sig
The number of the signal that caused invocation of the handler.
info
A pointer to a siginfo_t, which is a structure containing further information about the signal, as described below.
ucontext
This is a pointer to a ucontext_t structure, cast to void *. The structure pointed to by this field contains signal context information that was saved on the user-space stack by the kernel; for details, see sigreturn(2). Further information about the ucontext_t structure can be found in getcontext(3) and signal(7). Commonly, the handler function doesn't make any use of the third argument.

The siginfo_t data type is a structure with the following fields:


siginfo_t {
    int      si_signo;     /* Signal number */
    int      si_errno;     /* An errno value */
    int      si_code;      /* Signal code */
    int      si_trapno;    /* Trap number that caused
                              hardware-generated signal
                              (unused on most architectures) */
    pid_t    si_pid;       /* Sending process ID */
    uid_t    si_uid;       /* Real user ID of sending process */
    int      si_status;    /* Exit value or signal */
    clock_t  si_utime;     /* User time consumed */
    clock_t  si_stime;     /* System time consumed */
    union sigval si_value; /* Signal value */
    int      si_int;       /* POSIX.1b signal */
    void    *si_ptr;       /* POSIX.1b signal */
    int      si_overrun;   /* Timer overrun count;
                              POSIX.1b timers */
    int      si_timerid;   /* Timer ID; POSIX.1b timers */
    void    *si_addr;      /* Memory location which caused fault */
    long     si_band;      /* Band event (was int in
                              glibc 2.3.2 and earlier) */
    int      si_fd;        /* File descriptor */
    short    si_addr_lsb;  /* Least significant bit of address
                              (since Linux 2.6.32) */
    void    *si_lower;     /* Lower bound when address violation
                              occurred (since Linux 3.19) */
    void    *si_upper;     /* Upper bound when address violation
                              occurred (since Linux 3.19) */
    int      si_pkey;      /* Protection key on PTE that caused
                              fault (since Linux 4.6) */
    void    *si_call_addr; /* Address of system call instruction
                              (since Linux 3.5) */
    int      si_syscall;   /* Number of attempted system call
                              (since Linux 3.5) */
    unsigned int si_arch;  /* Architecture of attempted system call
                              (since Linux 3.5) */
}

si_signo, si_errno and si_code are defined for all signals. (si_errno is generally unused on Linux.) The rest of the struct may be a union, so that one should read only the fields that are meaningful for the given signal:

•
Signals sent with kill(2) and sigqueue(3) fill in si_pid and si_uid. In addition, signals sent with sigqueue(3) fill in si_int and si_ptr with the values specified by the sender of the signal; see sigqueue(3) for more details.
•
Signals sent by POSIX.1b timers (since Linux 2.6) fill in si_overrun and si_timerid. The si_timerid field is an internal ID used by the kernel to identify the timer; it is not the same as the timer ID returned by timer_create(2). The si_overrun field is the timer overrun count; this is the same information as is obtained by a call to timer_getoverrun(2). These fields are nonstandard Linux extensions.
•
Signals sent for message queue notification (see the description of SIGEV_SIGNAL in mq_notify(3)) fill in si_int/si_ptr, with the sigev_value supplied to mq_notify(3); si_pid, with the process ID of the message sender; and si_uid, with the real user ID of the message sender.
•
SIGCHLD fills in si_pid, si_uid, si_status, si_utime, and si_stime, providing information about the child. The si_pid field is the process ID of the child; si_uid is the child's real user ID. The si_status field contains the exit status of the child (if si_code is CLD_EXITED), or the signal number that caused the process to change state. The si_utime and si_stime contain the user and system CPU time used by the child process; these fields do not include the times used by waited-for children (unlike getrusage(2) and times(2)). Up to Linux 2.6, and since Linux 2.6.27, these fields report CPU time in units of sysconf(_SC_CLK_TCK). In Linux 2.6 kernels before Linux 2.6.27, a bug meant that these fields reported time in units of the (configurable) system jiffy (see time(7)).
•
SIGILL, SIGFPE, SIGSEGV, SIGBUS, and SIGTRAP fill in si_addr with the address of the fault. On some architectures, these signals also fill in the si_trapno field.
Some suberrors of SIGBUS, in particular BUS_MCEERR_AO and BUS_MCEERR_AR, also fill in si_addr_lsb. This field indicates the least significant bit of the reported address and therefore the extent of the corruption. For example, if a full page was corrupted, si_addr_lsb contains log2(sysconf(_SC_PAGESIZE)). When SIGTRAP is delivered in response to a ptrace(2) event (PTRACE_EVENT_foo), si_addr is not populated, but si_pid and si_uid are populated with the respective process ID and user ID responsible for delivering the trap. In the case of seccomp(2), the tracee will be shown as delivering the event. BUS_MCEERR_* and si_addr_lsb are Linux-specific extensions.
The SEGV_BNDERR suberror of SIGSEGV populates si_lower and si_upper.
The SEGV_PKUERR suberror of SIGSEGV populates si_pkey.
•
SIGIO/SIGPOLL (the two names are synonyms on Linux) fills in si_band and si_fd. The si_band event is a bit mask containing the same values as are filled in the revents field by poll(2). The si_fd field indicates the file descriptor for which the I/O event occurred; for further details, see the description of F_SETSIG in fcntl(2).
•
SIGSYS, generated (since Linux 3.5) when a seccomp filter returns SECCOMP_RET_TRAP, fills in si_call_addr, si_syscall, si_arch, si_errno, and other fields as described in seccomp(2).

The si_code field

The si_code field inside the siginfo_t argument that is passed to a SA_SIGINFO signal handler is a value (not a bit mask) indicating why this signal was sent. For a ptrace(2) event, si_code will contain SIGTRAP and have the ptrace event in the high byte:


(SIGTRAP | PTRACE_EVENT_foo << 8).

For a non-ptrace(2) event, the values that can appear in si_code are described in the remainder of this section. Since glibc 2.20, the definitions of most of these symbols are obtained from <signal.h> by defining feature test macros (before including any header file) as follows:

•
_XOPEN_SOURCE with the value 500 or greater;
•
_XOPEN_SOURCE and _XOPEN_SOURCE_EXTENDED; or
•
_POSIX_C_SOURCE with the value 200809L or greater.

For the TRAP_* constants, the symbol definitions are provided only in the first two cases. Before glibc 2.20, no feature test macros were required to obtain these symbols.

For a regular signal, the following list shows the values which can be placed in si_code for any signal, along with the reason that the signal was generated.

SI_USER
kill(2).
SI_KERNEL
Sent by the kernel.
SI_QUEUE
sigqueue(3).
SI_TIMER
POSIX, or setitimer(2) or alarm(2) timer expired.
SI_MESGQ (since Linux 2.6.6)
POSIX message queue state changed; see mq_notify(3).
SI_ASYNCIO
AIO completed.
SI_SIGIO
Queued SIGIO (only up to Linux 2.2; from Linux 2.4 onward SIGIO/SIGPOLL fills in si_code as described below).
SI_TKILL (since Linux 2.4.19)
tkill(2) or tgkill(2).
SI_ASYNCNL
Async name lookup completion.

The following values can be placed in si_code for a SIGILL signal:

ILL_ILLOPC
Illegal opcode.
ILL_ILLOPN
Illegal operand.
ILL_ILLADR
Illegal addressing mode.
ILL_ILLTRP
Illegal trap.
ILL_PRVOPC
Privileged opcode.

NAME

sigaction - examine and change a signal action

SYNOPSIS

#include <signal.h>

int sigaction(int signum, const struct sigaction *act,
              struct sigaction *oldact);

DESCRIPTION

The sigaction() system call is used to examine and change the action taken by a process upon receiving a specific signal. The argument signum specifies the signal number for which the action is to be examined or changed; this is a signal number in the range specified by signal.h. SIGKILL and SIGSTOP cannot be caught or ignored.

If the argument act is not NULL, then it is a pointer to a structure that specifies the new action to be taken when the signal signum is delivered. If the argument oldact is not NULL, then it is a pointer to a structure where the previous action for the signal signum is to be stored. If both act and oldact are NULL, then the signal handling settings for the signal signum are returned (without changing them).

The sigaction structure contains at least the following members:

void (*sa_handler)(int);
The function to be called when the signal is delivered. This can be SIG_DFL (the default action), SIG_IGN (ignore the signal), or a pointer to a signal-handling function.
sigset_t sa_mask;
An additional set of signals to be blocked during the execution of the signal handler. Signals in this set are stored in sa_mask.
int sa_flags;
Flags that modify the behavior of the signal handling.
void (*sa_restorer)(void);
This member is not to be used by applications. It is used internally by the kernel.

RETURN VALUE

On success, sigaction() returns 0. On failure, it returns -1, and errno is set to indicate the error.

ERRORS

EINVAL
An invalid signal number was specified, or the signal number was SIGKILL or SIGSTOP.

CONFORMING TO

POSIX.1-2001, POSIX.1-2008.

NOTES

The sigaction() system call provides a more reliable and flexible way to handle signals than the older signal() function. It allows finer control over signal blocking and restarting system calls.

When a signal is delivered to a process, the signal handler specified in sa_handler is executed. If sa_mask is not empty, the signals specified in sa_mask are added to the set of signals currently blocked for the process. After the signal handler returns, the set of blocked signals is restored to its previous state.

The sa_flags field can be used to modify the behavior of signal handling. Some of the important flags are:

  • SA_NOCLDSTOP: If the signal is SIGCHLD, do not send it to the calling process when a child process stops (but not terminates).
  • SA_ONSTACK: Signal handler is placed on an alternate signal stack.
  • SA_RESETHAND: Restore the signal handler to the default action after the signal is delivered.
  • SA_RESTART: Restart interrupted system calls.
  • SA_SIGINFO: Use the sa_sigaction field instead of sa_handler. This provides more information about the signal.
  • SA_NODEFER: Do not automatically block the signal being delivered.

EXAMPLE

The following example shows how to set up a signal handler for SIGINT:

#include <stdio.h>
#include <stdlib.h>
#include <signal.h>
#include <unistd.h>

void sigint_handler(int signum) {
    printf("Caught signal %d\n", signum);
    // Perform cleanup or other actions here
}

int main() {
    struct sigaction sa;

    sa.sa_handler = sigint_handler;
    sigemptyset(&sa.sa_mask); // Do not block any additional signals
    sa.sa_flags = SA_RESTART; // Restart interrupted system calls

    if (sigaction(SIGINT, &sa, NULL) == -1) {
        perror("sigaction");
        exit(EXIT_FAILURE);
    }

    printf("Waiting for SIGINT (Ctrl+C)...\n");
    pause(); // Wait for a signal

    printf("Program terminated normally.\n");
    return 0;
}
