الاسم

apptainer-run - تشغيل الأمر الافتراضي المحدد من قبل المستخدم داخل حاوية

الملخص

apptainer run [خيارات التشغيل...] [وسائط...]

الوصف

سيقوم هذا الأمر بتشغيل حاوية Apptainer وتنفيذ برنامج نصي للتشغيل
إذا تم تعريفه لهذا الحاوية. برنامج نصي للتشغيل هو ملف بيانات وصفية داخل
الحاوية يحتوي على أوامر shell. إذا كان الملف موجودًا (و
قابل للتنفيذ) فسيقوم هذا الأمر بتنفيذ هذا الملف داخل الحاوية
تلقائيًا. سيتم تمرير جميع الوسائط بعد اسم الحاوية
مباشرة إلى برنامج نصي للتشغيل.

يقبل apptainer run التنسيقات التالية للحاويات:

*.sif تنسيق صورة Singularity (SIF). أصلي لـ Singularity
(3.0+) و Apptainer (v1.0.0+)

*.sqsh تنسيق SquashFS. أصلي لـ Singularity 2.4+

*.img تنسيق ext3. أصلي لإصدارات Singularity < 2.4.

directory/ تنسيق sandbox. دليل يحتوي على نظام ملفات جذر صالح
وبشكل اختياري بيانات وصفية لـ Apptainer.

instance://* نسخة محلية قيد التشغيل لحاوية. (انظر مجموعة
أوامر instance.)

library://* حاوية SIF مستضافة في مكتبة (لا يوجد افتراضي)

docker://* حاوية Docker/OCI مستضافة على Docker Hub أو
سجل OCI آخر.

shub://* حاوية مستضافة على Singularity Hub.

oras://* حاوية SIF مستضافة على سجل OCI يدعم
مواصفات OCI Registry As Storage (ORAS).

خيارات

--add-caps="" قائمة صلاحيات مفصولة بفواصل لإضافتها

--allow-setuid[=false] السماح بملفات setuid الثنائية في الحاوية (للمستخدم الجذر فقط)

--app="" تحديد تطبيق ليتم تشغيله داخل حاوية

--apply-cgroups="" تطبيق cgroups من ملف لعمليات الحاوية (للمستخدم الجذر فقط)

--authfile="" ملف مصادقة بأسلوب Docker لاستخدامه لقراءة/كتابة بيانات اعتماد سجل OCI

-B, --bind=[] مواصفات مسار ربط للمستخدم. المواصفات لها التنسيق src[:dest[:opts]]، حيث src و dest خارج وداخل المسارات. إذا لم يتم تحديد dest، فسيتم تعيينه ليساوي src. قد يتم تحديد خيارات الربط (opts) كـ 'ro' (للقراءة فقط) أو 'rw' (للقراءة/الكتابة، وهو الافتراضي). يمكن تحديد مسارات ربط متعددة كقائمة مفصولة بفواصل.

--blkio-weight=0 وزن نسبي لـ Block IO في النطاق 10-1000، 0 لتعطيله

--blkio-weight-device=[] وزن نسبي لـ Block IO خاص بالجهاز

-e, --cleanenv[=false] تنظيف البيئة قبل تشغيل الحاوية

--compat[=false] تطبيق الإعدادات لزيادة التوافق مع OCI/Docker. يستنتج --containall، --no-init، --no-umask، --no-eval، --writable-tmpfs.

-c, --contain[=false] استخدام حد أدنى من /dev ومجلدات فارغة أخرى (مثل /tmp و $HOME) بدلاً من مشاركة أنظمة الملفات من المضيف الخاص بك

-C, --containall[=false] احتواء ليس فقط أنظمة الملفات، ولكن أيضًا PID، IPC، والبيئة

--cpu-shares=-1 حصص المعالج للحاوية

--cpus="" عدد معالجات CPUs المتاحة للحاوية

--cpuset-cpus="" قائمة وحدات المعالجة المركزية للمضيف المتاحة للحاوية

--cpuset-mems="" قائمة وحدات الذاكرة للمضيف المتاحة للحاوية

--cwd="" دليل العمل الأولي للعملية الخارجية داخل الحاوية (مرادف لـ --pwd)

--disable-cache[=false] عدم استخدام أو إنشاء ذاكرة تخزين مؤقت

--dns="" قائمة خوادم DNS مفصولة بفواصل لإضافتها في resolv.conf

--docker-host="" تحديد مضيف Docker daemon مخصص

--docker-login[=false] تسجيل الدخول إلى Docker Repository تفاعليًا

--drop-caps="" قائمة صلاحيات مفصولة بفواصل لإسقاطها

--env=[] تمرير متغير بيئة إلى العملية المضمنة

--env-file=[] تمرير متغيرات البيئة من ملف إلى العملية المضمنة

-f, --fakeroot[=false] تشغيل الحاوية بمظهر المستخدم الجذر

--fusemount=[] مواصفات تثبيت نظام ملفات FUSE بالشكل: : - حيث يكون 'container' أو 'host'، يحدد مكان إجراء التثبيت ('container-daemon' أو 'host-daemon' سيشغل عملية FUSE بشكل منفصل). هو المسار إلى الملف التنفيذي FUSE، بالإضافة إلى خيارات للتثبيت. هو موقع الحاوية حيث سيتم ربط تثبيت FUSE. مثال: 'container:sshfs 10.0.0.1:/ /sshfs'. يعني --pid.

-h, --help[=false] مساعدة لـ run

-H, --home="/build" مواصفات دليل المنزل. يمكن أن تكون المواصفات مسار src أو زوج src:dest. src هو المسار المصدر لدليل المنزل خارج الحاوية و dest يحل محل دليل المنزل داخل الحاوية.

--hostname="" تعيين اسم مضيف الحاوية

-i, --ipc[=false] تشغيل الحاوية في مساحة اسم IPC جديدة

--keep-privs[=false] السماح للمستخدم الجذر بالاحتفاظ بالصلاحيات في الحاوية (للمستخدم الجذر فقط)

--memory="" حد الذاكرة بالبايت

--memory-reservation="" حد الذاكرة الناعم بالبايت

--memory-swap="" حد الـ Swap، استخدم -1 لـ Swap غير محدود

--mount=[] مواصفات تثبيت مثل 'type=bind,source=/opt,destination=/hostopt'.

-n, --net[=false] تشغيل الحاوية في مساحة شبكة جديدة (يقوم بإعداد واجهة شبكة جسر افتراضيًا)

--netns-path="" الانضمام إلى مساحة اسم الشبكة في المسار المحدد (كمستخدم جذر، أو إذا كان مسموحًا به في apptainer.conf)

--network="" تحديد نوع الشبكة المطلوب مفصولة بفواصل، كل شبكة ستقوم بتشغيل واجهة مخصصة داخل الحاوية

--network-args=[] تحديد وسائط الشبكة لتمريرها إلى ملحقات CNI

--no-eval[=false] عدم تقييم متغيرات البيئة أو أوامر CMD/ENTRYPOINT/ARGS للحاوية OCI باستخدام shell

--no-home[=false] عدم تثبيت دليل منزل المستخدم إذا لم يكن /home هو دليل العمل الحالي

--no-https[=false] استخدام http بدلاً من https لـ docker:// oras:// و library:///... URIs

--no-init[=false] عدم تشغيل عملية shim مع --pid

--no-mount=[] تعطيل خيار واحد أو أكثر من خيارات 'mount xxx' المحددة في apptainer.conf و/أو تحديد مسار وجهة مطلق لتعطيل إدخال مسار ربط، أو 'bind-paths' لتعطيل جميع إدخالات مسارات الربط.

--no-pid[=false] عدم تشغيل الحاوية في مساحة PID جديدة

--no-privs[=false] إسقاط جميع الصلاحيات من المستخدم الجذر في الحاوية)

--no-umask[=false] عدم نشر umask إلى الحاوية، تعيين umask افتراضي 0022

--nv[=false] تمكين دعم Nvidia

--nvccli[=false] استخدام nvidia-container-cli لإعداد وحدة معالجة الرسومات (تجريبي)

--oom-kill-disable[=false] تعطيل قاتل OOM

-o, --overlay=[] استخدام صورة overlayFS لتخزين البيانات الدائمة أو كطبقة قراءة فقط للحاوية

--passphrase[=false] مطالبة بكلمة مرور تشفير

--pem-path="" إدخال مسار لمفتاح RSA بتنسيق PEM لحاوية مشفرة

-p, --pid[=false] تشغيل الحاوية في مساحة PID جديدة

--pids-limit=0 تحديد عدد PIDs للحاوية، استخدم -1 لـ غير محدود

--rocm[=false] تمكين دعم Rocm التجريبي

--runscript-timeout="" تعيين مدة انتهاء صلاحية برنامج نصي للتشغيل (افتراضي 1 دقيقة)

-S, --scratch=[] تضمين دليل مؤقت داخل الحاوية مرتبط بمسار مؤقت (استخدم -W لفرض الموقع)

--security=[] تمكين ميزات الأمان (SELinux، Apparmor، Seccomp)

--sharens[=false] مشاركة مساحة الاسم والصورة مع حاويات أخرى تم تشغيلها من نفس العملية الأم

--unsquash[=false] تحويل ملف SIF إلى sandbox مؤقت قبل التشغيل

-u, --userns[=false] تشغيل الحاوية في مساحة مستخدم جديدة

--uts[=false] تشغيل الحاوية في مساحة UTS جديدة

apptainer-run(1) - Arch Linux

NAME

apptainer-run, apptainer exec - Run an Apptainer container or execute a command within it

SYNOPSIS

apptainer run [--nv] [--writable] [--writable-tmpfs] <container> [args]

apptainer exec [--nv] [--writable] [--writable-tmpfs] <container> <command> [args]

DESCRIPTION

The Apptainer “run” command executes the default runscript defined within the container. If no runscript is defined, it will execute the default executable binary within the container. If no executable binary is defined, it will default to executing “/bin/sh”.

The Apptainer “exec” command executes a specific command within the container.

Any arguments provided after the container name are passed to the runscript or command.

OPTIONS

--nv
Use NVIDIA GPU support when running the container.
--writable[=false]
By default all Apptainer containers are available as read only. This option makes the file system accessible as read/write.
--writable-tmpfs[=false]
Makes the file system accessible as read-write with non persistent data (with overlay support only)

EXAMPLE

  # Here we see that the runscript prints "Hello world: "
  $ apptainer exec /tmp/debian.sif cat /apptainer
  #!/bin/sh
  echo "Hello world: "
  # It runs with our inputs when we run the image
  $ apptainer run /tmp/debian.sif one two three
  Hello world: one two three
  # Note that this does the same thing
  $ ./tmp/debian.sif one two three
