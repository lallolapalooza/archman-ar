signalfd(2) دليل استدعاءات النظام signalfd(2)

الاسم

signalfd - إنشاء واصف ملف لقبول الإشارات

المكتبة

مكتبة C القياسية (libc، -lc)

التركيب

#include <sys/signalfd.h>
int signalfd(int fd, const sigset_t *mask, int flags);

الوصف

تُنشئ signalfd() واصف ملف يمكن استخدامه لقبول الإشارات الموجّهة إلى المستدعي. يوفر هذا بديلاً عن استخدام معالج إشارة أو sigwaitinfo(2)، ويتميز بأن واصف الملف يمكن مراقبته بواسطة select(2) وpoll(2) وepoll(7).

تحدد وسيطة mask مجموعة الإشارات التي يرغب المستدعي في قبولها عبر واصف الملف. هذه الوسيطة عبارة عن مجموعة إشارات يمكن تهيئة محتوياتها باستخدام وحدات الماكرو الموصوفة في sigsetops(3). عادةً، ينبغي حجب مجموعة الإشارات التي ستُستقبل عبر واصف الملف باستخدام sigprocmask(2)، لمنع معالجة الإشارات وفقًا لتصرفاتها الافتراضية. لا يمكن استقبال إشارتي SIGKILL أو SIGSTOP عبر واصف ملف signalfd؛ يتم تجاهل هذه الإشارات بصمت إذا حُددت في mask.

إذا كانت وسيطة fd تساوي -1، فإن الاستدعاء ينشئ واصف ملف جديدًا ويربط مجموعة الإشارات المحددة في mask بذلك الواصف. إذا لم تكن fd تساوي -1، فيجب أن تحدد واصف ملف signalfd موجودًا صالحًا، وتُستخدم mask لاستبدال مجموعة الإشارات المرتبطة بذلك الواصف.

بدءًا من Linux 2.6.27، يمكن دمج القيم التالية بعملية OR على مستوى البت في flags لتغيير سلوك signalfd():

SFD_NONBLOCK
تعيين علامة حالة الملف O_NONBLOCK على وصف الملف المفتوح (انظر open(2)) المشار إليه بواسطة واصف الملف الجديد. استخدام هذه العلامة يوفر استدعاءات إضافية لـ fcntl(2) لتحقيق النتيجة نفسها.
SFD_CLOEXEC
تعيين علامة الإغلاق عند التنفيذ (FD_CLOEXEC) على واصف الملف الجديد. انظر وصف علامة O_CLOEXEC في open(2) للأسباب التي قد تجعل هذا مفيدًا.

حتى Linux 2.6.26، كانت وسيطة flags غير مستخدمة، ويجب تحديدها كصفر.

تُرجع signalfd() واصف ملف يدعم العمليات التالية:

read(2)
إذا كانت إشارة واحدة أو أكثر من الإشارات المحددة في mask معلّقة للعملية، فإن المخزن المؤقت المقدم إلى read(2) يُستخدم لإرجاع بنية signalfd_siginfo واحدة أو أكثر (انظر أدناه) تصف الإشارات. تُرجع read(2) معلومات لعدد الإشارات المعلّقة التي تتسع في المخزن المؤقت المقدم. يجب أن يكون المخزن المؤقت بحجم sizeof(struct signalfd_siginfo) بايت على الأقل. القيمة المُرجعة من read(2) هي إجمالي عدد البايتات المقروءة.
نتيجةً لـ read(2)، تُستهلك الإشارات، بحيث لم تعد معلّقة للعملية (أي لن تُلتقط بواسطة معالجات الإشارات، ولا يمكن قبولها باستخدام sigwaitinfo(2)).
إذا لم تكن أي من الإشارات في mask معلّقة للعملية، فإن read(2) إما تحجب حتى تُولّد إحدى الإشارات في mask للعملية، أو تفشل بالخطأ EAGAIN إذا جُعل واصف الملف غير حاجب.
poll(2)
select(2)
(وما شابه)
يكون واصف الملف قابلاً للقراءة (وسيطة readfds في select(2)؛ علامة POLLIN في poll(2)) إذا كانت إشارة واحدة أو أكثر من الإشارات في mask معلّقة للعملية.
يدعم واصف ملف signalfd أيضًا واجهات برمجة تعدد إرسال واصفات الملفات الأخرى: pselect(2) وppoll(2) وepoll(7).
close(2)
عندما لا يعود واصف الملف مطلوبًا، ينبغي إغلاقه. عندما تُغلق جميع واصفات الملفات المرتبطة بكائن signalfd نفسه، تُحرر النواة موارد الكائن.

بنية signalfd_siginfo

تنسيق بنية (بنى) signalfd_siginfo التي تُرجعها read(2) من واصف ملف signalfd هو كما يلي:


struct signalfd_siginfo {
    uint32_t ssi_signo;    /* رقم الإشارة */
    int32_t  ssi_errno;    /* رقم الخطأ (غير مستخدم) */
    int32_t  ssi_code;     /* رمز الإشارة */
    uint32_t ssi_pid;      /* معرف العملية للمرسل */
    uint32_t ssi_uid;      /* معرف المستخدم الحقيقي للمرسل */
    int32_t  ssi_fd;       /* واصف الملف (SIGIO) */
    uint32_t ssi_tid;      /* معرف مؤقت النواة (مؤقتات POSIX)
    uint32_t ssi_band;     /* حدث النطاق (SIGIO) */
    uint32_t ssi_overrun;  /* عدد تجاوزات مؤقت POSIX */
    uint32_t ssi_trapno;   /* رقم الفخ الذي تسبب في الإشارة */
    int32_t  ssi_status;   /* حالة الخروج أو الإشارة (SIGCHLD) */
    int32_t  ssi_int;      /* عدد صحيح مرسل بواسطة sigqueue(3) */
    uint64_t ssi_ptr;      /* مؤشر مرسل بواسطة sigqueue(3) */
    uint64_t ssi_utime;    /* وقت CPU للمستخدم المستهلك (SIGCHLD) */
    uint64_t ssi_stime;    /* وقت CPU للنظام المستهلك
                              (SIGCHLD) */
    uint64_t ssi_addr;     /* العنوان الذي ولّد الإشارة
                              (للإشارات المولدة عتاديًا) */
    uint16_t ssi_addr_lsb; /* البت الأقل أهمية من العنوان
                              (SIGBUS؛ منذ Linux 2.6.37) */
    uint8_t  pad[X];       /* حجم الحشو إلى 128 بايت (للسماح
                              بحقول إضافية في المستقبل) */
};

كل حقل في هذه البنية مماثل للحقل المسمى بالمثل في بنية siginfo_t. تُوصف بنية siginfo_t في sigaction(2). لن تكون جميع الحقول في بنية signalfd_siginfo المُرجعة صالحة لإشارة معينة؛ يمكن تحديد مجموعة الحقول الصالحة من القيمة المُرجعة في حقل ssi_code. هذا الحقل هو نظير حقل si_code في siginfo_t؛ انظر sigaction(2) للتفاصيل.

دلالات fork(2)

بعد fork(2)، يرث الابن نسخة من واصف ملف signalfd. ستُرجع read(2) من واصف الملف في الابن معلومات حول الإشارات الموضوعة في قائمة انتظار الابن.

دلالات تمرير واصف الملف

كما هو الحال مع واصفات الملفات الأخرى، يمكن تمرير واصفات ملف signalfd إلى عملية أخرى عبر مقبس نطاق UNIX (انظر unix(7)). في العملية المستقبلة، ستُرجع read(2) من واصف الملف المستلم معلومات حول الإشارات الموضوعة في قائمة انتظار تلك العملية.

دلالات execve(2)

تمامًا مثل أي واصف ملف آخر، يبقى واصف ملف signalfd مفتوحًا عبر execve(2)، ما لم يُعلَّم للإغلاق عند التنفيذ (انظر fcntl(2)). أي إشارات كانت متاحة للقراءة قبل execve(2) تبقى متاحة للبرنامج المحمّل حديثًا. (هذا مماثل لدلالات الإشارات التقليدية، حيث تبقى الإشارة المحجوبة المعلّقة معلّقة عبر execve(2).)

دلالات الخيوط

تعكس دلالات واصفات ملفات signalfd في برنامج متعدد الخيوط الدلالات القياسية للإشارات. بعبارة أخرى، عندما يقرأ خيط من واصف ملف signalfd، فإنه سيقرأ الإشارات الموجهة إلى الخيط نفسه والإشارات الموجهة إلى العملية (أي مجموعة الخيوط بأكملها). (لن يتمكن الخيط من قراءة الإشارات الموجهة إلى خيوط أخرى في العملية.)

دلالات epoll(7)

إذا أضافت عملية (عبر epoll_ctl(2)) واصف ملف signalfd إلى نسخة epoll(7)، فإن epoll_wait(2) يعيد الأحداث فقط للإشارات المرسلة إلى تلك العملية. على وجه الخصوص، إذا استخدمت العملية بعد ذلك fork(2) لإنشاء عملية فرعية، فستتمكن العملية الفرعية من read(2) الإشارات المرسلة إليها باستخدام واصف ملف signalfd، لكن epoll_wait(2) لن يشير إلى أن واصف ملف signalfd جاهز. في هذا السيناريو، من الحلول الممكنة أنه بعد fork(2)، يمكن للعملية الفرعية إغلاق واصف ملف signalfd الذي ورثته من العملية الأصلية ثم إنشاء واصف ملف signalfd آخر وإضافته إلى نسخة epoll. بدلاً من ذلك، يمكن للأصل والفرع تأخير إنشاء واصفات ملفات signalfd الخاصة بهما (المنفصلة) وإضافتها إلى نسخة epoll حتى بعد استدعاء fork(2).

القيمة المُعادة

عند النجاح، تُعيد signalfd() واصف ملف signalfd؛ وهو إما واصف ملف جديد (إذا كان fd يساوي -1)، أو fd إذا كان fd واصف ملف signalfd صالحًا. عند الخطأ، تُعاد -1 ويُضبط errno للإشارة إلى الخطأ.

الأخطاء

EBADF
واصف الملف fd ليس واصف ملف صالحًا.
EINVAL
fd ليس واصف ملف signalfd صالحًا.
EINVAL
flags غير صالح؛ أو، في Linux 2.6.26 أو أقدم، flags غير صفري.
EMFILE
تم الوصول إلى الحد الأقصى لكل عملية لعدد واصفات الملفات المفتوحة.
ENFILE
تم الوصول إلى الحد الأقصى على مستوى النظام لإجمالي عدد الملفات المفتوحة.
ENODEV
تعذّر تركيب جهاز inode مجهول (داخلي).
ENOMEM
لم تكن هناك ذاكرة كافية لإنشاء واصف ملف signalfd جديد.

الإصدارات

اختلافات مكتبة C/النواة

يتطلب استدعاء النظام Linux الأساسي وسيطًا إضافيًا، size_t sizemask، يحدد حجم وسيط mask. لا تتضمن دالة الغلاف signalfd() في glibc هذا الوسيط، لأنها توفر القيمة المطلوبة لاستدعاء النظام الأساسي.

هناك استدعاءا نظام Linux أساسيان: signalfd() و signalfd4() الأحدث. لا ينفذ استدعاء النظام الأول وسيط flags. ينفذ استدعاء النظام الأخير قيم flags الموصوفة أعلاه. بدءًا من glibc 2.9، ستستخدم دالة الغلاف signalfd() الدالة signalfd4() حيثما كانت متاحة.

ملاحظات

يمكن لعملية إنشاء عدة واصفات ملفات signalfd. هذا يجعل من الممكن قبول إشارات مختلفة على واصفات ملفات مختلفة. (قد يكون هذا مفيدًا إذا كانت واصفات الملفات تُراقَب باستخدام select(2) أو poll(2) أو epoll(7): وصول إشارات مختلفة سيجعل واصفات ملفات مختلفة جاهزة.) إذا ظهرت إشارة في mask أكثر من واحد من واصفات الملفات، فإن حدوث تلك الإشارة يمكن قراءته (مرة واحدة) من أي واحد من واصفات الملفات.

تُتجاهل المحاولات لتضمين SIGKILL وSIGSTOP في mask بصمت.

يمكن عرض قناع الإشارات الذي يستخدمه واصف ملف signalfd عبر الإدخال الخاص بواصف الملف المقابل في دليل /proc/pid/fdinfo الخاص بالعملية. راجع proc(5) لمزيد من التفاصيل.

القيود

لا يمكن استخدام آلية signalfd لتلقي الإشارات التي تُولَّد بشكل متزامن، مثل إشارة SIGSEGV الناتجة عن الوصول إلى عنوان ذاكرة غير صالح أو إشارة SIGFPE الناتجة عن خطأ حسابي. لا يمكن التقاط مثل هذه الإشارات إلا عبر معالج إشارات.

كما هو موضح أعلاه، في الاستخدام العادي يحجب المرء الإشارات التي سيتم قبولها عبر signalfd(). إذا تم إنشاء عملية فرعية لتنفيذ برنامج مساعد (لا يحتاج إلى واصف ملف signalfd)، فبعد استدعاء fork(2)، سترغب عادةً في إلغاء حجب تلك الإشارات قبل استدعاء execve(2)، حتى يتمكن البرنامج المساعد من رؤية أي إشارات يتوقع رؤيتها. كن على علم، مع ذلك، أن هذا لن يكون ممكنًا في حالة برنامج مساعد يتم إنشاؤه خلف الكواليس بواسطة أي دالة مكتبة قد يستدعيها البرنامج. في مثل هذه الحالات، يجب الرجوع إلى استخدام معالج إشارات تقليدي يكتب إلى واصف ملف تتم مراقبته بواسطة select(2) أو poll(2) أو epoll(7).

الأخطاء البرمجية

قبل Linux 2.6.25، لم تكن الحقول ssi_ptr وssi_int تُملأ بالبيانات المصاحبة لإشارة أُرسلت بواسطة sigqueue(3).

أمثلة

يقبل البرنامج أدناه الإشارتين SIGINT و SIGQUIT عبر واصف ملف signalfd. ينتهي البرنامج بعد قبول إشارة SIGQUIT. توضح جلسة الصدفة التالية استخدام البرنامج:


$ ./signalfd_demo
^C                   # Control-C generates SIGINT
Got SIGINT
^C
Got SIGINT
^\                    # Control-\ generates SIGQUIT
Got SIGQUIT
$

مصدر البرنامج

#include <err.h>
#include <signal.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/signalfd.h>
#include <sys/types.h>
#include <unistd.h>
int
main(void)
{
    int                      sfd;
    ssize_t                  s;
    sigset_t                 mask;
    struct signalfd_siginfo  fdsi;
    sigemptyset(&mask);
    sigaddset(&mask, SIGINT);
    sigaddset(&mask, SIGQUIT);
    /* Block signals so that they aren't handled
       according to their default dispositions.  */
    if (sigprocmask(SIG_BLOCK, &mask, NULL) == -1)
        err(EXIT_FAILURE, "sigprocmask");
    sfd = signalfd(-1, &mask, 0);
    if (sfd == -1)
        err(EXIT_FAILURE, "signalfd");
    for (;;) {
        s = read(sfd, &fdsi, sizeof(fdsi));
        if (s != sizeof(fdsi))
            err(EXIT_FAILURE, "read");
        if (fdsi.ssi_signo == SIGINT) {
            printf("Got SIGINT\n");
        } else if (fdsi.ssi_signo == SIGQUIT) {
            printf("Got SIGQUIT\n");
            exit(EXIT_SUCCESS);
        } else {
            printf("Read unexpected signal\n");
        }
    }
}
