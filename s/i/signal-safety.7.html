ملاحظات:

•
تطلبت POSIX.1-2001 و POSIX.1-2001 TC2 أن تكون الدوال fpathconf(3) و pathconf(3) و sysconf(3) آمنة للإشارة غير المتزامنة، ولكن تم إزالة هذا المطلب في POSIX.1-2008.
•
إذا قام معالج إشارة مقاطعة تنفيذ دالة غير آمنة، وانهى المعالج عبر استدعاء إلى longjmp(3) أو siglongjmp(3) وقام البرنامج بعد ذلك باستدعاء دالة غير آمنة، فإن سلوك البرنامج يكون غير محدد.
•
قد تؤدي معالجات الإشارات غير المتزامنة التي تستدعي دوال هي نقاط إلغاء وتتداخل فوق مناطق مؤجلة الإلغاء إلى تشغيل إلغاء يكون سلوكه كما لو حدث إلغاء غير متزامن وقد يتسبب في عدم اتساق حالة التطبيق.

errno

يُعد جلب قيمة errno وتعيينها آمنًا للإشارة غير المتزامنة بشرط أن يقوم معالج الإشارة بحفظ errno عند الدخول واستعادة قيمتها قبل العودة.

الانحرافات في مكتبة GNU C

تحدث الانحرافات المعروفة التالية عن المعيار في مكتبة GNU C:

•
قبل glibc 2.24، استخدمت execl(3) و execle(3) realloc(3) داخليًا، وبالتالي لم تكن آمنة للإشارة غير المتزامنة. تم إصلاح هذا في glibc 2.24.
•
تنفيذ glibc

NAME

signal-safety — async-signal-safe functions

DESCRIPTION

A function is async-signal-safe if it can be safely called from within a signal handler. Specifically, a function is async-signal-safe if it may be called at any time (including from within a signal handler) without causing problems such as deadlocks, race conditions, or data corruption.

The functions listed in the following table are async-signal-safe. The specific list is taken from the POSIX.1-2008 specification.

_exit, abort, accept, access, aio_error, aio_fsync, aio_read, aio_suspend, aio_write, bind, cfgetispeed, cfgetospeed, cfsetispeed, cfsetospeed, chdir, chmod, chown, clock_gettime, close, connect, creat, dup, dup2, execve, faccessat, fadvise64, fallocate, fchdir, fchmod, fchmodat, fchown, fchownat, fcntl, fdatasync, ffs, fgetc, fgetpos, flock, fork, fpathconf, fputc, fread, free, frexp, fsync, ftell, ftime, futex, getcwd, getdtablesize, getegid, geteuid, getgid, getgroups, gethostid, getitimer, getlogin, getpeername, getpgid, getpid, getppid, getpriority, getrlimit, getsid, getsockname, getsockopt, gettimeofday, getuid, ioctl, isatty, kill, killpg, link, listen, lseek, lstat, mkdir, mkfifo, mknod, mmap, mount, open, pathconf, pause, pipe, pwrite, pread, putc, puts, read, readlink, readv, reboot, recv, recvfrom, recvmsg, rename, rmdir, select, semop, send, sendmsg, sendto, setdomainname, setegid, seteuid, setgid, setgroups, sethostid, setitimer, setlocale, setpgid, setpriority, setregid, setresgid, setresuid, setrlimit, setsid, setsockopt, settimeofday, setuid, shutdown, sigaction, sigaddset, sigaltstack, sigdelset, sigemptyset, sigfillset, sighold, sigismember, signal, sigpause, sigpending, sigprocmask, sigremove, sigsuspend, sigtimedwait, sigwait, sigwaitinfo, sleep, socket, socketpair, stat, statfs, symlink, sync, sysconf, tcdrain, tcflow, tcflush, tcgetattr, tcsendbreak, tcsetattr, time, timer_create, timer_delete, timer_getoverrun, timer_gettime, timer_settime, times, tmpfile, truncate, tsetent, tunsetent, ttyname, ulimit, umask, uname, unlink, unsetenv, utime, utimes, vhangup, wait, waitid, waitpid, write, writev.

The following functions are explicitly *not* async-signal-safe, and should not be called from a signal handler:

aio_suspend
This is because aio_suspend(3) is not async-signal-safe because it uses pthread_mutex_lock(3) internally.
