NAME

systemd-journal-gatewayd.service, systemd-journal-gatewayd - network journal gateway

SYNOPSIS

systemd-journal-gatewayd.service

/usr/lib/systemd/systemd-journal-gatewayd [--log-level=level] [--log-target=target]

DESCRIPTION

systemd-journal-gatewayd is a systemd service that listens on the network for journal export requests, retrieves the journal data, and exports it back to the client. It is intended to be used for exporting journal data from machines that cannot access the journal files directly, for example, from embedded devices or virtual machines.

It listens on TCP port 19531 by default. See systemd.socket(5) for details on configuration.

The gateway exports journal data in the journal export format (systemd.journal-export(5)) or JSON format (systemd.journal-json(5)). Both can be requested via the HTTP Accept header.

It supports reading journal entries via the HTTP Range header, allowing clients to request specific subsets of the journal. See RFC 7233 for details.

OPTIONS

--log-level=level
Sets the logging level for the daemon. See sd_journal_print(3) for possible values.
--log-target=target
Sets the logging target for the daemon. See sd_journal_send(3) for possible values.

SUPPORTED URLS

systemd-journal-gatewayd supports the following URL paths:

/journal/
Exports the entire journal in the format specified by the Accept header. If no Accept header is provided, the journal export format is used.
/journal/since/<timestamp>
Exports journal entries recorded since the specified timestamp. The timestamp format is YYYY-MM-DD HH:MM:SS. Example: /journal/since/2023-10-27 10:00:00.
/journal/until/<timestamp>
Exports journal entries recorded until the specified timestamp.
/journal/field/<field_name>/<field_value>
Exports journal entries where the specified field matches the given value. Multiple /field/ paths can be combined to filter by multiple fields.

ACCEPT HEADER

The Accept header can be used to specify the desired output format. Supported media types are:

application/json
Exports journal entries in JSON format.
application/vnd.systemd.journal-data
Exports journal entries in the native journal export format.

RANGE HEADER

The Range header can be used to retrieve specific entries from the journal. The header value should follow the format entries=N-M, where N is the starting entry index and M is the ending entry index. Indexes are 0-based.

Example: Range: entries=0-99 retrieves the first 100 entries.

URL GET PARAMETERS

The following GET parameters can be used to filter journal entries:

_hostname=value
Filter by hostname.
_systemd_unit=value
Filter by systemd unit.
_comm=value
Filter by command name.
_pid=value
Filter by process ID.
_uid=value
Filter by user ID.
_gid=value
Filter by group ID.
_transport=value
Filter by journal transport.
_cursor=value
Start reading from the specified cursor.
_boot=value
Filter by boot ID.
_machine=value
Filter by machine ID.
PRIORITY=value
Filter by message priority.
MESSAGE=value
Filter by message content (full text search).

EXAMPLES

Export all journal entries in JSON format:

$ curl --header "Accept: application/json" http://localhost:19531/journal/

Export journal entries from the last hour in journal export format:

$ curl http://localhost:19531/journal/since/$(date -d '1 hour ago' '+%Y-%m-%d %H:%M:%S')

Export entries from the 'nginx.service' unit:

$ curl 'http://localhost:19531/journal/field/_systemd_unit/nginx.service'

Export the first 50 log entries:

$ curl --header "Range: entries=0-49" http://localhost:19531/journal/
729ab34a250b1'
