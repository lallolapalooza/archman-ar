الاسم

systemd-system.conf, system.conf.d, systemd-user.conf, user.conf.d - ملفات تكوين مدير النظام والجلسة

الملخص

/etc/systemd/system.conf, /run/systemd/system.conf, /usr/lib/systemd/system.conf, /etc/systemd/system.conf.d/*.conf, /run/systemd/system.conf.d/*.conf, /usr/lib/systemd/system.conf.d/*.conf

~/.config/systemd/user.conf, /etc/systemd/user.conf, /run/systemd/user.conf, /usr/lib/systemd/user.conf, /etc/systemd/user.conf.d/*.conf, /run/systemd/user.conf.d/*.conf, /usr/lib/systemd/user.conf.d/*.conf

الوصف

عند تشغيله كمثيل نظام، يقوم systemd بتفسير ملف التكوين system.conf والملفات الموجودة في مجلدات system.conf.d؛ وعند تشغيله كمثيل مستخدم، يقوم بتفسير ملف التكوين user.conf (حسب الأولوية، في الدليل الرئيسي للمستخدم وتحت /etc/systemd/, /run/systemd/, و /usr/lib/systemd/) والملفات الموجودة في مجلدات user.conf.d. تحتوي ملفات التكوين هذه على بعض الإعدادات التي تتحكم في عمليات المدير الأساسية.

راجع systemd.syntax(7) لوصف عام للصيغة.

مجلدات التكوين والأسبقية

يتم تحديد التكوين الافتراضي أثناء التجميع، لذا فإن التكوين مطلوب فقط عند الضرورة للانحراف عن هذه الافتراضيات. يتم تحميل ملف التكوين الرئيسي من أحد المجلدات المدرجة بترتيب الأسبقية، ويتم استخدام أول ملف يتم العثور عليه فقط: /etc/systemd/, /run/systemd/, /usr/local/lib/systemd/ [1], /usr/lib/systemd/. يحتوي إصدار البائع للملف على إدخالات معلقة تظهر الافتراضيات كدليل للمسؤول. يمكن أيضًا تعديل التكوين المحلي عن طريق إنشاء ملفات إضافية (drop-ins)، كما هو موضح أدناه. يمكن أيضًا تعديل ملف التكوين الرئيسي لهذا الغرض (أو نسخة في /etc/ إذا تم شحنها تحت /etc/)، ومع ذلك، يوصى باستخدام الملفات الإضافية للتكوين المحلي بدلاً من تعديل ملف التكوين الرئيسي.

بالإضافة إلى ملف التكوين الرئيسي، يتم قراءة مقتطفات تكوين إضافية من /usr/lib/systemd/*.conf.d/, /usr/local/lib/systemd/*.conf.d/, و /etc/systemd/*.conf.d/. هذه الملفات الإضافية لها أسبقية أعلى وتتجاوز ملف التكوين الرئيسي. يتم فرز الملفات الموجودة في الدلائل الفرعية للتكوين *.conf.d/ حسب أسمائها بترتيب أبجدي، بغض النظر عن الدليل الفرعي الذي تقيم فيه. عندما تحدد ملفات متعددة الخيار نفسه، بالنسبة للخيارات التي تقبل قيمة واحدة فقط، فإن الإدخال الموجود في الملف المصنف الأخير له الأسبقية، وبالنسبة للخيارات التي تقبل قائمة من القيم، يتم جمع الإدخالات كما تحدث في الملفات المصنفة.

عندما تحتاج الحزم إلى تخصيص التكوين، يمكنها تثبيت ملفات إضافية تحت /usr/. الملفات الموجودة في /etc/ محجوزة للمسؤول المحلي، الذي قد يستخدم هذا المنطق لتجاوز ملفات التكوين التي تثبتها حزم البائع. يجب استخدام الملفات الإضافية لتجاوز الملفات الإضافية للحزم، نظرًا لأن ملف التكوين الرئيسي له أسبقية أقل. يوصى بوضع بادئة لجميع أسماء الملفات في هذه الدلائل الفرعية برقم مكون من رقمين وشرطة، لتبسيط الترتيب. هذا يحدد أيضًا مفهوم أولويات الملفات الإضافية للسماح لموردي نظام التشغيل بشحن ملفات إضافية ضمن نطاق محدد أقل من النطاق الذي يستخدمه المستخدمون. هذا من شأنه أن يقلل من خطر تجاوز الملفات الإضافية للحزم عن طريق الخطأ للملفات الإضافية المعرفة من قبل المستخدمين. يوصى باستخدام النطاق 10-40 للملفات الإضافية في /usr/ والنطاق 60-90 للملفات الإضافية في /etc/ و /run/، للتأكد من أن الملفات الإضافية المحلية والمؤقتة لها الأسبقية على الملفات الإضافية التي يشحنها مورد نظام التشغيل.

لتعطيل ملف تكوين مقدم من البائع، فإن الطريقة الموصى بها هي وضع رابط رمزي إلى /dev/null في دليل التكوين في /etc/، بنفس اسم ملف التكوين للبائع.

الخيارات

يتم تكوين جميع الخيارات في قسم [Manager]:

LogColor=, LogLevel=, LogLocation=, LogTarget=, LogTime=, DumpCore=yes, CrashChangeVT=no, CrashShell=no, CrashAction=freeze, ShowStatus=yes, DefaultStandardOutput=journal, DefaultStandardError=inherit

يقوم بتكوين معلمات مختلفة لعمل المدير الأساسي. قد يتم تجاوز هذه الخيارات بواسطة معلمات العمليات المقابلة وسطر أوامر النواة. راجع systemd(1) للتفاصيل.

تمت الإضافة في الإصدار 198.

CtrlAltDelBurstAction=

يحدد الإجراء الذي سيتم تنفيذه إذا ضغط المستخدم على Ctrl-Alt-Delete أكثر من 7 مرات خلال 2 ثانية. يمكن ضبطه على "reboot-force"، "poweroff-force"، "reboot-immediate"، "poweroff-immediate" أو تعطيله باستخدام "none". الافتراضي هو "reboot-force".

تمت الإضافة في الإصدار 232.

StatusUnitFormat=

يأخذ name، description أو combined كقيمة. إذا كانت name، سيستخدم مدير النظام أسماء الوحدات في رسائل الحالة (على سبيل المثال، "systemd-journald.service")، بدلاً من الأوصاف الأطول والأكثر إفادة التي تم تعيينها باستخدام Description= (على سبيل المثال، "Journal Logging Service"). إذا كانت combined، سيستخدم مدير النظام كلاً من أسماء الوحدات والأوصاف في رسائل الحالة (على سبيل المثال، "systemd-journald.service - Journal Logging Service").

راجع systemd.unit(5) للحصول على تفاصيل حول أسماء الوحدات و Description=.

تمت الإضافة في الإصدار 243.

DefaultTimerAccuracySec=

يحدد الدقة الافتراضية لوحدات المؤقت. يتحكم هذا في الإعداد العام لـ AccuracySec= لوحدات المؤقت، راجع systemd.timer(5) للتفاصيل. AccuracySec= المحدد في الوحدات الفردية يتجاوز الإعداد الافتراضي العام للوحدة المحددة. الافتراضي هو 1 دقيقة. لاحظ أن دقة وحدات المؤقت تتأثر أيضًا بفترة التأخير الزمنية (slack) المكونة لـ PID 1، راجع TimerSlackNSec= أعلاه.

تمت الإضافة في الإصدار 212.

إدارة الموارد

TimerSlackNSec=

يحدد فترة التأخير الزمنية (timer slack) بالنانو ثانية لـ PID 1، والتي يتم توريثها لجميع العمليات المنفذة، ما لم يتم تجاوزها بشكل فردي، على سبيل المثال باستخدام الإعداد TimerSlackNSec= في وحدات الخدمة (للتفاصيل، راجع systemd.exec(5)). تتحكم فترة التأخير الزمنية في دقة الاستيقاظات التي تثيرها مؤقتات النظام. راجع prctl(2) لمزيد من المعلومات. لاحظ أنه على عكس معظم تعريفات الفترات الزمنية الأخرى، يأخذ هذا المعامل قيمة عددية بالنانو ثانية إذا لم يتم تحديد وحدة. الوحدات الزمنية المعتادة مفهومة أيضًا.

تمت الإضافة في الإصدار 198.

CPUAffinity=

يقوم بتكوين تقارب وحدة المعالجة المركزية (CPU affinity) لمدير الخدمة وكذلك تقارب وحدة المعالجة المركزية الافتراضي لجميع العمليات المشتقة. يأخذ قائمة بفهارس وحدات المعالجة المركزية أو نطاقات مفصولة إما بمسافة بيضاء أو بفواصل. يتم تحديد نطاقات وحدة المعالجة المركزية بواسطة فهارس وحدات المعالجة المركزية الدنيا والعليا مفصولة بشرطة. يمكن تحديد هذا الخيار أكثر من مرة، وفي هذه الحالة يتم دمج أقنعة تقارب وحدة المعالجة المركزية المحددة. إذا تم تعيين سلسلة فارغة، يتم إعادة تعيين القناع، ولن يكون لجميع التعيينات السابقة أي تأثير. قد تتجاوز الخدمات الفردية تقارب وحدة المعالجة المركزية لعملياتها باستخدام إعداد CPUAffinity= في ملفات الوحدات، راجع systemd.exec(5).

تمت الإضافة في الإصدار 198.

NUMAPolicy=

يقوم بتكوين سياسة ذاكرة NUMA لمدير الخدمة وسياسة ذاكرة NUMA الافتراضية لجميع العمليات المشتقة. قد تتجاوز الخدمات الفردية السياسة الافتراضية باستخدام إعداد NUMAPolicy= في ملفات الوحدات، راجع systemd.exec(5).

تمت الإضافة في الإصدار 243.

NUMAMask=

يقوم بتكوين قناع عقدة NUMA الذي سيتم ربطه بالسياسة NUMA المحددة. لاحظ أن سياسات NUMA default و local لا تتطلب قناع عقدة NUMA صريحًا ويمكن أن تكون قيمة الخيار فارغة. بشكل مشابه لـ NUMAPolicy=، يمكن تجاوز القيمة بواسطة خدمات فردية في ملفات الوحدات، راجع systemd.exec(5).

تمت الإضافة في الإصدار 243.

DefaultMemoryAccounting=, DefaultTasksAccounting=, DefaultIOAccounting=, DefaultIPAccounting=

يقوم بتكوين إعدادات المحاسبة الافتراضية للموارد، كما تم تكوينها لكل وحدة بواسطة

systemd.directives(7) — systemd directives

NAME

systemd.directives - List of all systemd directives

SYNOPSIS

...

DESCRIPTION

systemd is a system and service manager for Linux operating systems. It provides a mechanism for initializing and managing the userspace components of a complete operating system.

This document lists and describes the directives understood by systemd. This includes directives that may be used in various systemd unit files, configuration files, and other systemd-specific files.

The directives are grouped by the configuration files or unit sections they belong to. Directives introduced in older versions of systemd are also listed, along with their deprecation status.

CONFIGURATION DIRECTORIES AND PRECEDENCE

systemd reads configuration files from a set of directories in a well-defined order. Files in later directories override files in earlier directories. The order is as follows:

1. /etc/systemd/system/ (system administrator configuration)

2. /run/systemd/system/ (runtime configuration)

3. /usr/lib/systemd/system/ (packaged configuration)

The directories /etc/systemd/user/, /run/systemd/user/ and /usr/lib/systemd/user/ are used for user-specific configuration.

See systemd.unit(7) for more information.

NOTES 1.

OPTIONS

The following options are understood:

RESOURCE MANAGEMENT

The following directives control resource usage:

DefaultCPUAccounting=
Takes a boolean value. If set to true, CPU accounting is enabled for all services. If set to false, it is disabled. Default is false.
DefaultIOAccounting=
Takes a boolean value. If set to true, I/O accounting is enabled for all services. If set to false, it is disabled. Default is false.
DefaultMemoryAccounting=
Takes a boolean value. If set to true, memory accounting is enabled for all services. If set to false, it is disabled. Default is false.
DefaultTasksAccounting=
Takes a boolean value. If set to true, task accounting is enabled for all services. If set to false, it is disabled. Default is false.

HARDWARE WATCHDOG

RuntimeWatchdogSec=
Sets the maximum time to keep the hardware watchdog device alive. If the service does not reset the watchdog device within this time, the system will be rebooted. Default is off.
ShutdownWatchdogSec=
Sets the maximum time to keep the hardware watchdog device alive during shutdown. If the system does not shut down within this time, the watchdog will trigger a reboot. Default is off.

SECURITY

CapabilityBoundingSet=
Configures the set of capabilities that are available to processes. See capabilities(7) for more information.
AmbientCapabilities=
Configures the set of capabilities that are inherited by child processes. See capabilities(7) for more information.
SecureBits=
Configures the secure bits for processes. See capabilities(7) for more information.
NoNewPrivileges=
Takes a boolean value. If set to true, processes will not be able to gain new privileges. Default is false. See NOTES 2.

TIMEOUTS AND RATE LIMITS

DefaultTimeoutStartSec=
Sets the default timeout for starting services. Default is 90s.
DefaultTimeoutStopSec=
Sets the default timeout for stopping services. Default is 90s.
DefaultTimeoutAbortSec=
Sets the default timeout for aborting services. Default is 3min.
DefaultRestartSec=
Sets the default time to wait before restarting a service. Default is 100ms.
DefaultStartLimitIntervalSec=
Sets the interval for limiting the number of restarts. Default is 10s.
DefaultStartLimitBurst=
Sets the maximum number of restarts within the interval. Default is 5.

ENVIRONMENT

DefaultEnvironment=
Sets environment variables for all services. See environ(7) for more information.
DefaultEnvironmentFile=
Sets environment variables from a file for all services. See environ(7) for more information.

NOTES 3.

SPECIFIERS

The following specifiers are understood:

"%.1f" Host name The machine hostname, as shown by the hostname command.
"%.2f" Canonical host name The canonical hostname of the machine. This is obtained by resolving the hostname set in %.1f via DNS and then resolving the resulting canonical name back to an IP address, and finally resolving this IP address back to a hostname. If this process fails at any step, %.2f falls back to %.1f.
"%.3f" IP address The primary IP address of the machine. This is obtained by looking up the IP address associated with %.2f. If this fails, %.1f is used.
"%.s" Operating system name The operating system name, as read from the NAME= field of /etc/os-release. If not set, resolves to an empty string. See os-release(5) for more information.
"%.o" Operating system version The operating system version, as read from the VERSION= field of /etc/os-release. If not set, resolves to an empty string. See os-release(5) for more information.
"%.V" Operating system version ID The operating system version identifier of the running system, as read from the VERSION_ID= field of /etc/os-release. If not set, resolves to an empty string. See os-release(5) for more information.
"%.W" Operating system variant ID The operating system variant identifier of the running system, as read from the VARIANT_ID= field of /etc/os-release. If not set, resolves to an empty string. See os-release(5) for more information.
"%.T" Directory for temporary files This is either /tmp or the path "$TMPDIR", "$TEMP" or "$TMP" are set to. (Note that the directory may be specified without a trailing slash.)
"%.V" Directory for larger and persistent temporary files This is either /var/tmp or the path "$TMPDIR", "$TEMP" or "$TMP" are set to. (Note that the directory may be specified without a trailing slash.)
"%.h" User home directory This is the home directory of the user running the service manager instance.
"%.u" Username This is the username of the user running the service manager instance.
"%.U" User id This is the user id of the user running the service manager instance.
"%.g" Primary group This is the primary group of the user running the service manager instance.
"%.G" Primary group id This is the primary group id of the user running the service manager instance.
"%.s" User shell This is the shell of the user running the service manager instance.
"%%" Single percent sign Use "%%" in place of "%" to specify a single percent sign.

HISTORY

systemd 252

Option DefaultBlockIOAccounting= was deprecated. Please switch to the unified cgroup hierarchy.

systemd 258

DefaultCPUAccounting= setting is deprecated, because CPU accounting is always available on the unified cgroup hierarchy and such setting has no effect.
