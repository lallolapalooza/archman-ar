الوصف

المولدات هي ملفات تنفيذية صغيرة توجد في /usr/lib/systemd/system-environment-generators/ والدلائل الأخرى المذكورة أعلاه. سيقوم systemd(1) بتنفيذ هذه الملفات التنفيذية في وقت مبكر جدًا عند بدء تشغيل كل مدير وفي وقت إعادة تحميل التكوين، قبل تشغيل المولدات الموصوفة في systemd.generator(7) وقبل بدء أي وحدات. يمكن لمولدات البيئة تجاوز البيئة التي يقوم بها المدير بتصديرها للخدمات والعمليات الأخرى.

يتم تحميل المولدات من مجموعة من المسارات المحددة أثناء التجميع، كما هو مدرج أعلاه. يتم تحميل مولدات بيئة النظام والمستخدم من الدلائل التي تنتهي أسماؤها بـ system-environment-generators/ و user-environment-generators/ على التوالي. المولدات الموجودة في الدلائل المذكورة سابقًا تتجاوز تلك التي تحمل نفس الاسم في الدلائل ذات الأولوية الأقل [1]. يمكن استخدام رابط رمزي إلى /dev/null أو ملف فارغ لإخفاء مولد، مما يمنعه من التشغيل. يرجى ملاحظة أن ترتيب الدليلين ذوي الأولوية الأعلى معكوس بالنسبة لمسار تحميل الوحدة، والمولدات في /run/ تستبدل تلك الموجودة في /etc/.

بعد تثبيت مولدات جديدة أو تحديث التكوين، يمكن تنفيذ systemctl daemon-reload. سيؤدي هذا إلى إعادة تشغيل جميع المولدات، وتحديث تكوين البيئة. سيتم استخدامه لأي خدمات يتم تشغيلها لاحقًا.

يتم تنفيذ مولدات ملفات البيئة بشكل مشابه لمولدات ملفات الوحدات الموصوفة في systemd.generator(7)، مع الاختلافات التالية:

•يتم تنفيذ المولدات بالتتابع بالترتيب الأبجدي الرقمي للمكون النهائي لاسمها. يتم تحليل ناتج كل مولد على الفور ويتم استخدامه لتحديث البيئة للمولدات التي تعمل بعد ذلك. وبالتالي، يمكن للمولدات اللاحقة استخدام و/أو تعديل مخرجات المولدات السابقة.
•يتم تشغيل المولدات بواسطة كل مثيل مدير، ويمكن أن تكون مخرجاتها مختلفة لكل مستخدم.

يوصى باستخدام بادئات رقمية لأسماء المولدات لتبسيط الترتيب.

أمثلة

مثال 1. مولد بسيط يوسع متغير بيئة إذا كان الدليل موجودًا في نظام الملفات

#!/bin/sh
# SPDX-License-Identifier: MIT-0
# تعيين القيمة الافتراضية
XDG_DATA_DIRS="${XDG_DATA_DIRS:-/usr/local/share/:/usr/share}"
# إضافة دليل إذا كان موجودًا
if [ -d /opt/foo/share ]; then
    XDG_DATA_DIRS="/opt/foo/share:${XDG_DATA_DIRS}"
fi
# كتابة مخرجاتنا
echo "XDG_DATA_DIRS=${XDG_DATA_DIRS}"

مثال 2. مولد أكثر تعقيدًا يقرأ التكوين الحالي ويغير متغيرًا واحدًا

#!/usr/bin/python
# SPDX-License-Identifier: MIT-0
"""
مولد بيئة systemd لإثبات المفهوم الذي يجعل الدلائل bin
دائمًا بعد الدلائل sbin المقابلة في المسار.
(يغير /sbin:/bin:/foo/bar إلى /bin:/sbin:/foo/bar.)
يوضح هذا المولد كيفية تجاوز التكوين الذي ربما أنشأته
المولدات السابقة. سيكون من الأسهل كتابته بلغة bash، ولكن لنبقيه
في Python فقط لإثبات أننا نستطيع، ولتعويض المولدات الأكثر إثارة للاهتمام.
"""
import os
import pathlib
def rearrange_bin_sbin(path):
    """تأكد من أن أي زوج من الدلائل .../bin، .../sbin موجود في هذا الترتيب
    >>> rearrange_bin_sbin('/bin:/sbin:/usr/sbin:/usr/bin')
    '/bin:/sbin:/usr/bin:/usr/sbin'
    """
    items = [pathlib.Path(p) for p in path.split(':')]
    for i in range(len(items)):
        if 'sbin' in items[i].parts:
            ind = items[i].parts.index('sbin')
            bin = pathlib.Path(*items[i].parts[:ind], 'bin', *items[i].parts[ind+1:])
            if bin in items[i+1:]:
                j = i + 1 + items[i+1:].index(bin)
                items[i], items[j] = items[j], items[i]
    return ':'.join(p.as_posix() for p in items)
if __name__ == '__main__':
    path = os.environ['PATH'] # يجب أن يكون هذا دائمًا مضبوطًا.
                              # إذا لم يكن كذلك، فسوف نتعطل، وهذا مقبول أيضًا.
    new = rearrange_bin_sbin(path)
    if new != path:
        print('PATH={}'.format(new))
