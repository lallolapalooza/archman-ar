systemd-pcrlock-secureboot-policy.service(8)

الحزمة: systemd

التراخيص: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later, MIT-0

SYSTEMD-PCRLOCK(8) systemd-pcrlock SYSTEMD-PCRLOCK(8)

الاسم

systemd-pcrlock, systemd-pcrlock-file-system.service, systemd-pcrlock-firmware-code.service, systemd-pcrlock-firmware-config.service, systemd-pcrlock-machine-id.service, systemd-pcrlock-make-policy.service, systemd-pcrlock-secureboot-authority.service, systemd-pcrlock-secureboot-policy.service - تحليل والتنبؤ بحالات PCR لـ TPM2 وإنشاء سياسة وصول من التنبؤ

الملخص

/usr/lib/systemd/systemd-pcrlock [خيارات...]

الوصف

ملاحظة: هذه الأداة تجريبية حاليًا. بينما من المحتمل أن تصبح جزءًا منتظمًا من systemd، إلا أنها قد لا تزال تتغير في سلوكها وواجهتها.

systemd-pcrlock هي أداة يمكن استخدامها لتحليل والتنبؤ بقياسات TPM2 PCR، وإنشاء سياسات وصول TPM2 من التنبؤ الذي تخزنه في فهرس TPM2 NV (أي في الذاكرة غير المتطايرة لـ TPM2). يمكن استخدام ذلك بعد ذلك لتقييد الوصول إلى كائنات TPM2 (مثل مفاتيح تشفير القرص) إلى عمليات تمهيد النظام التي تستخدم فقط مكونات محددة وموثوقة.

يستخدم systemd-pcrlock كمدخلات لتحليله وتنبؤه:

•سجل أحداث TPM2 الثابت لبرنامج UEFI الثابت (أي /sys/kernel/security/tpm0/binary_bios_measurements) لعملية التمهيد الحالية.
•سجل أحداث TPM2 لمساحة المستخدم (أي /run/log/systemd/tpm2-measure.log) لعملية التمهيد الحالية.
•الحالة الحالية لـ PCR لشريحة TPM2.
•ملفات تعريف مكونات التمهيد (*.pcrlock و *.pcrlock.d/*.pcrlock، انظر systemd.pcrlock(5)) التي تحدد كل منها قياسات متوقعة لمكون واحد من عملية التمهيد، مما يسمح بمتغيرات بديلة لكل منها. (يمكن استخدام المتغيرات لتثبيت إصدارات متعددة من النواة أو محمل التمهيد في نفس الوقت.)

يستخدم هذه المدخلات لإنشاء سجل أحداث مدمج، والتحقق منه مقابل قيم PCR. ثم يحاول التعرف على سجلات أحداث الأحداث ومطابقتها مع المكونات المعرفة. لكل PCR حيث يمكن القيام بذلك بشكل شامل (أي حيث تمت مطابقة جميع السجلات المدرجة وجميع المكونات المعرفة)، يمكن استخدام ذلك للتنبؤ بقياسات PCR المستقبلية، مع مراعاة المتغيرات البديلة المحددة لكل مكون. يمكن بعد ذلك تحويل هذا التنبؤ إلى سياسة وصول TPM2 (تتكون من عناصر TPM2 PolicyPCR و PolicyOR)، والتي يتم تخزينها بعد ذلك في فهرس NV في TPM2. يمكن استخدام ذلك بعد ذلك لقفل الأسرار (مثل مفاتيح تشفير القرص) لهذه السياسات (عبر سياسة TPM2 PolicyAuthorizeNV).

استخدم أدوات مثل systemd-cryptenroll(1) أو systemd-repart(8) لربط تشفير القرص بسياسة TPM2 systemd-pcrlock هذه. على وجه التحديد، انظر المفاتيح --tpm2-pcrlock= لهذه الأدوات.

يتطلب منطق سياسة الوصول جهاز TPM2 الذي ينفذ الأمر "PolicyAuthorizeNV"، أي ينفذ TPM 2.0 الإصدار 1.38 أو أحدث.

الأوامر

الأوامر التالية مفهومة:

log

يقرأ هذا سجل أحداث TPM2 المدمج، ويتحقق منه، ويطابقه مع قيم PCR الحالية، ويخرج كلاهما في شكل جدولي. ادمجه مع --json= لإنشاء إخراج بتنسيق JSON.

تمت الإضافة في الإصدار 255.

cel

يقرأ هذا سجل أحداث TPM2 المدمج ويكتبه إلى STDOUT بتنسيق TCG Canonical Event Log Format (CEL-JSON)[1].

تمت الإضافة في الإصدار 255.

list-components

يعرض قائمة بتعريفات المكونات ومتغيراتها، أي ملفات *.pcrlock المكتشفة في /var/lib/pcrlock.d/ و /usr/lib/pcrlock.d/ والمجلدات الأخرى المدعومة. انظر systemd.pcrlock(5) للحصول على تفاصيل حول هذه الملفات والقائمة الكاملة للمجلدات التي يتم البحث فيها.

تمت الإضافة في الإصدار 255.

predict

يتنبأ بحالة PCR في عمليات التمهيد المستقبلية. سيقوم هذا بتحليل سجل أحداث TPM2 كما هو موضح أعلاه، والتعرف على المكونات، ثم إنشاء جميع قيم PCR الناتجة الممكنة لجميع توليفات متغيرات المكونات. لاحظ أنه لا يتم إجراء أي تنبؤ لـ PCRs التي لا تتطابق قيمتها مع سجلات أحداث الأحداث، والتي تم اكتشاف قياسات غير معروفة لها، أو التي تم تعريف مكونات لها لا يمكن العثور عليها في سجل الأحداث. هذا إجراء سلامة لضمان أن أي سياسة وصول تم إنشاؤها يمكن تلبيتها بشكل صحيح في عمليات التمهيد الحالية والمستقبلية.

تمت الإضافة في الإصدار 255.

make-policy

يقوم هذا بالتنبؤ بحالة PCR لعمليات التمهيد المستقبلية، بشكل مشابه لأمر predict أعلاه. ثم يستخدم هذه البيانات لإنشاء سياسة وصول TPM2 التي يخزنها في فهرس TPM2 NV. يتم كتابة التنبؤ والمعلومات حول TPM2 المستخدم وفهرس NV الخاص به إلى /var/lib/systemd/pcrlock.json.

يتم تخصيص فهرس NV عند الاستدعاء الأول، ويتم تحديثه عند الاستدعاءات اللاحقة.

يمكن تغيير محتويات فهرس NV (وبالتالي تحديث السياسة المخزنة فيه) عن طريق توفير رمز PIN وصول. يتم إنشاء رمز PIN هذا عادةً تلقائيًا وتخزينه بتنسيق مشفر (مع سياسة وصول تربطه بفهرس NV نفسه) في ملف سياسة JSON المذكور أعلاه. يمكن للمستخدم اختيار رمز PIN هذا، عبر المفتاح --recovery-pin=. إذا تم تحديده، يمكن استخدامه كمسار وصول بديل لتحديث السياسة.

إذا تطابق التنبؤ الجديد مع القديم، سينتهي هذا الأمر بسرعة ولن ينفذ أي عملية أخرى. (ما لم يتم تحديد --force، انظر أدناه.)

بدءًا من الإصدار 256، يتم تشفير نسخة من ملف سياسة /var/lib/systemd/pcrlock.json في بيانات اعتماد (انظر systemd-creds(1) للتفاصيل) ويتم كتابتها إلى قسم EFI System Partition أو XBOOTLDR، في الدليل الفرعي /loader/credentials/. هناك يتم التقاطها عند التمهيد بواسطة systemd-stub(7) وتمريرها إلى initrd المطلوب، حيث يمكن استخدامها لفتح نظام الملفات الجذر (الذي يحتوي عادةً على /var/، وهو المكان الذي يقع فيه النسخة الأساسية للسياسة، والتي لا يمكن بالتالي استخدامها لفتح نظام الملفات الجذر). يتم تسمية ملف بيانات الاعتماد باسم رمز إدخال التمهيد للتثبيت (انظر bootctl(1))، والذي يمكن تكوينه عبر المفتاح --entry-token=، انظر أدناه.

تمت الإضافة في الإصدار 255.

remove-policy

يزيل سياسة تم إنشاؤها مسبقًا. يحذف ملف /var/lib/systemd/pcrlock.json، ويزيل تخصيص فهرس NV.

تمت الإضافة في الإصدار 255.

is-supported

يتحقق مما إذا كان TPM2 المحلي يدعم جميع الوظائف لكي يعمل systemd-pcrlock بشكل صحيح. يقوم هذا بإجراء اختبارات مشابهة لـ systemd-analyze has-tpm2، ولكنه يتحقق أيضًا من دعم عمليات TPM2 المطلوبة بواسطة systemd-pcrlock. يخرج أحد الخيارات التالية: "no" (لا)، "partial" (جزئي - في حالة توفر بعض أجزاء دعم TPM2 في الأجهزة، البرامج الثابتة، نظام التشغيل، ولكن ليس كاملاً)، "obsolete" (قديم - إذا كان دعم TPM2 متاحًا في الأجهزة، البرامج الثابتة، ونظام التشغيل، ولكن العمليات المطلوبة لـ systemd-pcrlock مفقودة)، "yes" (نعم). يعود بحالة خروج صفر إذا كان الدعم الكامل متاحًا، وإلا غير صفري.

إذا تم دمجه مع --quiet، يتم قمع إخراج السلسلة.

حاليًا، يتحقق هذا من دعم أمر PolicyAuthorizeNV TPM2، وكذلك دعم خوارزمية تجزئة SHA-256.

تمت الإضافة في الإصدار 258.

lock-firmware-code, unlock-firmware-code

ينشئ/يزيل ملفات .pcrlock بناءً على سجل أحداث TPM2 لعملية التمهيد الحالية التي تغطي جميع السجلات لـ PCRs 0 ("platform-code") و 2 ("external-code").

تسمح هذه العملية بقفل عملية التمهيد على الإصدار الحالي للبرنامج الثابت للنظام وبطاقاته الإضافية. يجب استخدام هذه العملية فقط إذا لم يوفر بائع النظام بيانات pcrlock مناسبة مسبقًا.

لاحظ أن هذه البيانات تطابق فقط الإصدار الحالي للبرنامج الثابت. إذا تم تطبيق تحديث للبرنامج الثابت، فستكون هذه البيانات قديمة ولن تمر أي سياسة وصول تم إنشاؤها منها. لذلك يوصى باستدعاء unlock-firmware-code قبل إجراء تحديث للبرنامج الثابت، يليه make-policy لتحديث السياسة.

يتم استدعاء systemd-pcrlock lock-firmware-code تلقائيًا عند التمهيد عبر وحدة systemd-pcrlock-firmware-code.service، إذا تم تمكينها. هذا يضمن أن سياسة الوصول التي يديرها systemd-pcrlock يتم قفلها تلقائيًا على إصدار البرنامج الثابت الجديد كلما تم تحديث po

systemd.pcrlock.service(8) — systemd manual

NAME

systemd-pcrlock.service, systemd-pcrlock-unlock.service, systemd-pcrlock-unlock.timer - manage PCR values for disk encryption

SYNOPSIS

/usr/lib/systemd/systemd-pcrlock-unlock.service
/usr/lib/systemd/systemd-pcrlock-unlock.timer

DESCRIPTION

The systemd-pcrlock service is used to create and manage policies for disk encryption based on the state of the TPM's Platform Configuration Registers (PCRs). It allows defining conditions under which disk encryption keys are released, ensuring that the system's boot process has not been tampered with.

The primary goal is to automate the unlocking of disk encryption when the system boots in a trusted state. This involves using a TPM (Trusted Platform Module) to measure the boot process and store these measurements in PCRs. A policy is then created that links the unlocking of the encryption key to specific PCR values.

The systemd-pcrlock.service itself is a template unit that handles the actual unlocking process. It is activated as needed, often triggered by the systemd-pcrlock-unlock.timer.

The systemd-pcrlock-unlock.timer is a timer unit designed to periodically check and potentially unlock encrypted devices based on the defined PCR policies. This ensures that if the system is in a trusted state, the necessary decryption actions are performed automatically.

The configuration for these services is primarily managed through the systemd-creds(1) command and related policy files, typically located in /var/lib/systemd/pcrlock.

COMMANDS

The core functionality is accessed via the systemd-creds(1) utility. Relevant subcommands include:

make-policy
Creates a new PCR policy. This command captures the current PCR values and stores them as a reference policy. This policy can then be used to unlock an NV index in the TPM. When this command is used, a PIN is required to protect the TPM NV index. If no policy was created before, this PIN is used to protect the newly allocated NV index. If a policy has been created before, the PIN is used to unlock write access to the NV index. If either "hide" or "show" is used, a PIN is automatically generated, and — only in case of "show" — displayed on screen. Regardless if user supplied or automatically generated, it is stored in encrypted form in the policy metadata file. The recovery PIN may be used to regain write access to an NV index in case the access policy became out of date.
unlock
Attempts to unlock an NV index using a previously created policy. This command verifies the current PCR values against the stored policy. If they match, the NV index is unlocked, allowing access to the protected data (e.g., decryption keys).
lock
Locks an NV index in the TPM, revoking access until it is explicitly unlocked again. This is typically used to secure the system when it is shut down or when the system state is no longer considered trusted.
show
Displays information about existing PCR policies and their associated NV indices.
hide
Similar to `show`, but attempts to hide the existence of the NV index and its associated policy, providing an additional layer of security.
is-supported
Checks if the system's TPM and related functionalities are supported and configured correctly for use with systemd-pcrlock.

OPTIONS

--pin=PIN
Specifies the PIN used to unlock or manage the TPM NV index. This is required for operations like `make-policy`, `unlock`, and `lock` unless an automatic PIN generation is triggered (e.g., with `make-policy --show`). The PIN is stored encrypted in the policy metadata file.
--recovery-pin=RECOVERY_PIN
Specifies a recovery PIN. This PIN can be used to regain write access to an NV index if the primary access policy becomes outdated or inaccessible.
--pcrlock=PATH
Specifies the file system path where the generated pcrlock data should be written. This option is honored by the various `lock-*` commands. If not specified, a default path is typically used, as documented in systemd.pcrlock(5).
--policy=PATH
Specifies the file system path where the pcrlock policy metadata should be written. If not specified, it defaults to /var/lib/systemd/pcrlock.json.
--force
When used with `make-policy`, this option forces the predicted policy to be written to the NV index even if it is detected to be the same as the previously stored one.
--entry-token=TOKEN
Sets the boot entry token to be used for the file name of the pcrlock policy credential in the EFI System Partition or XBOOTLDR partition. This switch only affects the `make-policy` command. Refer to the bootctl(1) man page for expected values.
--quiet
Suppresses output when the command is invoked for `is-supported`.
--json=MODE
Formats the output as JSON. Valid modes are:
short
Shortest possible output without redundant whitespace or line breaks.
pretty
A pretty-printed version with indentation and line breaks.
off
Turns off JSON output (this is the default).
--no-pager
Do not pipe output into a pager.
-h, --help
Prints a short help text and exits.
--version
Prints a short version string and exits.

Added in version 255, unless otherwise noted.

EXIT STATUS

On success, 0 is returned. A non-zero failure code is returned otherwise.
