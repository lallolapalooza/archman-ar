FBB::SyslogStream(3bobcat) تيار إخراج لـ Syslog FBB::SyslogStream(3bobcat)

الاسم

FBB::SyslogStream - تيار إخراج لإدراج رسائل syslog

الملخص

#include <bobcat/syslogstream>
خيار الربط: -lbobcat

الوصف

يمكن استخدام كائنات FBB::SyslogStream كـ std::ostream لكتابة رسائل syslog باستخدام مرافق التيار.

يمكن استخدام إدخالات منفصلة متعددة لإنشاء رسالة syslog واحدة: لا يتم إرسال الرسالة إلى خادم syslog إلا بعد تلقي أمر flush (على سبيل المثال، بعد إدراج std::flush أو std::endl). تظهر الأحرف غير القابلة للطباعة (مثل ’\n’) في رسالة syslog كقيم ثمانية، مسبوقة بـ # (على سبيل المثال، #012 لـ ’\n’). يتم تجاهل السطر الجديد الذي يتم إدراجه عادةً بواسطة std::endl: تفسر كائنات SyslogStream std::endl مثل std::flush.

قد تحتوي سلسلة واحدة من الإدخالات على عدة أدوات تحكم std::endl أو std::flush. عند كل من هذه الأدوات، يتم إرسال رسالة جديدة إلى خادم syslog، تحتوي على جميع المعلومات التي تم تخزينها مؤقتًا حتى الآن. بعد إرسال رسالة إلى خادم syslog، يتم مسح المخزن المؤقت الداخلي لـ SyslogStream.

المنشئات

o
SyslogStream(string const &ident = "", FBB::Priority priority = FBB::NOTICE, FBB::Facility facility = FBB::USER, int option = 0):
يقوم هذا المنشئ بتهيئة كائن SyslogStream. عادةً ما يكون المعلمة ident هي اسم البرنامج. يتم إضافة محتواه إلى بداية رسائل syslog.
تحدد المعلمة priority الأهمية الافتراضية للرسالة المرسلة إلى خادم syslog. افتراضيًا، يتم إرسال الرسائل إلى خادم syslog بالأولوية FBB::NOTICE. يمكن إعطاء رسائل syslog أولوية مختلفة عن طريق إدراج أداة تحكم SyslogStream (انظر أدناه). يمكن أيضًا تعديل الأولوية المعينة وقت الإنشاء باستخدام الأعضاء setPriority و setDefaultPriority.
لا يتم تحديد الرسائل التي تظهر فعليًا في مرافق السجل حسب أولويات الرسائل، بل حسب قناع السجل الخاص بـ syslog. يمكن تعيين قناع السجل بواسطة العضو الثابت setMask (انظر أدناه).
تحدد المعلمة facility نوع البرنامج الذي يقوم بتسجيل الدخول. افتراضيًا، يتم استخدام FBB::USER.
يمكن استخدام المعلمة option لتحديد خيارات مختلفة (استخدم عامل التشغيل الثنائي `bitor` (`|`) لدمج الخيارات):
LOG_CONS: اكتب مباشرة إلى وحدة التحكم في النظام إذا كان هناك خطأ أثناء الإرسال إلى مسجل النظام
LOG_NDELAY: افتح الاتصال فورًا (عادةً، يتم فتح الاتصال عند تسجيل الرسالة الأولى)
LOG_PERROR: اطبع إلى stderr أيضًا
LOG__PID: قم بتضمين PID مع كل رسالة
افتراضيًا، لا يتم استخدام أي خيارات.

منشئات النسخ والنقل (وعوامل التعيين) غير متاحة.

NAME

syslogstream - syslog stream class

SYNOPSIS

#include <bobcat/syslogstream>
using namespace FBB;

DESCRIPTION

The FBB::SyslogStream class provides a stream-like interface to the syslog daemon. It supports the definition of message priorities and facilities, and the masking of messages based on their priorities.

NAMESPACE

namespace FBB {

class SyslogStream: public std::ostream
{
    // ...
};

} // namespace FBB

INHERITS FROM

std::ostream

ENUMERATIONS

The following enumerations are defined:

o
Priority: Defines the priority levels for syslog messages. Possible values include:
  • EMERG (Emergency)
  • ALERT (Alert)
  • CRIT (Critical)
  • ERR (Error)
  • WARNING (Warning)
  • NOTICE (Notice)
  • INFO (Informational)
  • DEBUG (Debug)
o
Facility: Defines the facilities for syslog messages. Possible values include:
  • KERN (Kernel messages)
  • USER (User-level messages)
  • MAIL (Mail system)
  • DAEMON (System daemons)
  • AUTH (Security/authorization messages)
  • SYSLOG (Internal syslog messages)
  • LPR (Line printer subsystem)
  • NEWS (Network news subsystem)
  • UUCP (UUCP subsystem)
  • CRON (Clock daemon)
  • AUTHPRIV (Security/authorization messages (private))
  • FTP (FTP daemon)
  • NTP (NTP subsystem)
  • AUDIT (Audit)
  • ALERT (Alert)
  • CLOCK (Clock daemon)
  • LOCAL0 to LOCAL7 (Reserved for local use)
o
PriorityMask: Defines the scope of priority masking.
  • SINGLE: Masks only the specified priority.
  • UPTO: Masks the specified priority and all higher priorities.

CONSTRUCTORS

o
SyslogStream(char const *ident, int option = 0, int facility = USER): Constructs a SyslogStream object.
  • ident: A string that will be prepended to every message.
  • option: A bitmask of options, such as LOG_CONS, LOG_NDELAY, etc.
  • facility: The default facility for messages. Defaults to USER.
The constructor initializes the stream and opens a connection to the syslog daemon using the provided identifier, options, and facility.

STATIC MEMBER FUNCTIONS

Syslog messages of (if upTo equals SINGLE) or up to (if upTo equals UPTO) the indicated priority are processed by the syslog daemon.
o

o
Facility stoF(std::string const &name, Facility facility = USER):
Returns the facility matching the name of the facility provided by name. Facility matching is performed case insensitively. E.g., if name contains daemon, facility FBB::DAEMON is returned. If name does not match any facility name then the value of this function’s second argument is returned. The function’s name (stoF) was used in analogy of the various sto... conversion functions that were made available by the C++11 standard.
o
Priority stoP(std::string const &name, Priority priority = NOTICE):
Returns the priority matching the name of the priority provided by name. Priority matching is performed case insensitively. E.g., if name contains emerg, priority FBB::EMERG is returned. If name does not match any priority name then the value of this function’s second argument is returned. The function’s name (stoP) was used in analogy of the various sto... conversion functions that were made available by the C++11 standard.

MANIPULATORS

The following set of manipulators are all defined as (static) members. They may be inserted into an FBB::SyslogStream object. Except for the last manipulator (strerrno), they have the following characteristics in common:

o
They change the priority of the messages that are subsequently inserted by the FBB::SyslogStream object, thus acting like a separate setPriority call.
o
When inserting multiple manipulators before the inserted message is flushed (e.g., using the std::flush or the std::endl manipulators) the last inserted FBB::SyslogStream manipulator will be used.
o
If the manipulators are not inserted into an FBB::SyslogStream object (but in another std::ostream type of object) then they perform no action.

Here are the available manipulators:

o
SyslogStream::alert:
Messages are inserted with priority FBB::ALERT.
o
SyslogStream::crit:
Message are inserted with priority FBB::CRIT.
o
SyslogStream::debug:
Messages are inserted with priority FBB::DEBUG.
o
SyslogStream::emerg:
Messages are inserted with priority FBB::EMERG.
o
SyslogStream::err:
Messages are inserted with priority FBB::ERR.
o
SyslogStream::info:
Messages are inserted with priority FBB::INFO.
o
SyslogStream::notice:
Messages are inserted with priority FBB::NOTICE.
o
SyslogStream::strerrno:
This manipulator inserts the textual interpretation of std::errno’s current value into a std::ostream. Note that, different from the other manipulators, the object into which this manipulator is inserted does not have to be a FBB::SyslogStream object.
o
SyslogStream::warning:
Messages are inserted with priority FBB::WARNING.

EXAMPLE

#include <bobcat/syslogstream>
using namespace std;
using namespace FBB;
int main(int argc, char **argv)
{
    SyslogStream sls(argv[0]);
    sls << SyslogStream::debug << "Hello world" << flush <<
           SyslogStream::strerrno << endl;
}

BUGS

The constructor’s option parameter is an int. Because of this, int values rather than enumeration values are passed to the constructor. It is the responsibility of the programmer to pass defined option values only.
