], ID_NET_NAME_PATH=prefix[Pdomain]pbussslot[ffunction][nphys_port_name|ddev_port]bnumber, ID_NET_NAME_PATH=prefix[Pdomain]pbussslot[ffunction][nphys_port_name|ddev_port]uport...[cconfig][iinterface]

يصف هذا الخاصية موقع تثبيت الجهاز. تُستخدم مخططات مختلفة اعتمادًا على نوع الناقل، كما هو موضح في الجدول أدناه. بالنسبة لأجهزة BCMA و USB، يجب معرفة معلومات مسار PCI، ويتكون الاسم الكامل من البادئة، ومعرّف فتحة PCI، وموقع USB أو BCMA. يتم تمثيل الجزأين الأولين بـ "..." في الجدول أدناه.

NAME

systemd.net-naming-scheme — Network interface naming scheme

DESCRIPTION

This document describes the network interface naming scheme used by systemd-networkd and udev. The goal is to provide consistent, predictable, and stable interface names, regardless of the order in which kernel modules are loaded or devices are detected. This is achieved by using a set of naming schemes, each with a different priority.

The following naming schemes are available:

ID_NET_NAME_ONBOARD
Onboard devices are identified by their firmware-assigned index (if available). This typically applies to devices soldered directly onto the motherboard.
ID_NET_NAME_SLOT
PCI(e) devices are identified by their firmware-assigned slot name (e.g., "ethernet 1"). This is often derived from the firmware's configuration for the specific slot.
ID_NET_NAME_MAC
Interface name derived from the MAC address. The MAC address is converted into a hexadecimal string prefixed with "enx" (for Ethernet) or "wlx" (for wireless). This is a fallback mechanism and should be used with caution as MAC addresses can be changed.
ID_NET_NAME_PATH
Interface name derived from the device's path in the sysfs tree. This scheme uses information about the bus and device location (e.g., PCI slot, USB port) to generate a stable name.
ID_NET_NAME_VLAN
For VLAN interfaces, the name is derived from the parent interface name and the VLAN ID (e.g., "eth0.100").
ID_NET_NAME_Ổ
This is a new scheme that focuses on identifying the *type* of network device and its attributes. It is designed to be more informative and flexible than previous schemes.
ID_NET_NAME_Ổ
This new scheme incorporates attributes directly from sysfs, allowing for more fine-grained control over interface naming. It supports allowlists and denylists for specific sysfs attributes.

The naming scheme is determined by iterating through the available schemes in a specific order of priority. The first scheme that yields a valid name is used.

POLICIES

Network interface naming is controlled by policies defined in /etc/udev/udev.conf, /usr/lib/udev/udev.conf, and hwdb overrides. The primary configuration setting is NAME_POLICY, which defines the order in which the naming schemes are tried. The default value is "ID_NET_NAME_Ổ=kernel,ID_NET_NAME_Ổ=slot,ID_NET_NAME_MAC=0,ID_NET_NAME_PATH=0".

The ID_NET_NAME_Ổ and ID_NET_NAME_Ổ policies allow users to explicitly enable or disable the use of specific sysfs attributes for naming. This provides fine-grained control over the naming process.

The ID_NET_NAME_Ổ policy, when set to 0, disables the use of any sysfs attribute by default. Only explicitly allowlisted attributes are used. When set to 1, udev can use any sysfs attribute unless it is explicitly forbidden. The default value is 1.

ID_NET_NAME_ALLOW_sysfsattr=BOOL

This udev property explicitly states if udev shall use the specified sysfsattr, when composing the device name.

With these options, users can set an allowlist or denylist for sysfs attributes. To create an allowlist, the user needs to set ID_NET_NAME_ALLOW=0 for the device and then list the allowed attributes with the ID_NET_NAME_ALLOW_sysfsattr=1 options. In case of a denylist, the user needs to provide the list of denied attributes with the ID_NET_NAME_ALLOW_sysfsattr=0 options.

HISTORY

The ID_NET_NAME_Ổ and ID_NET_NAME_Ổ policies were added in version 256.

LIMITING THE USE OF SPECIFIC SYSFS ATTRIBUTES

By default, udev attempts to use various sysfs attributes to generate predictable network interface names. In some cases, it might be desirable to restrict which sysfs attributes are used, either to enforce a specific naming scheme or to prevent unexpected changes. This can be achieved using the ID_NET_NAME_ALLOW and ID_NET_NAME_ALLOW_sysfsattr options.

The ID_NET_NAME_ALLOW option acts as a master switch for sysfs attribute usage. If set to 0, udev will not read any sysfs attribute by default, unless it is explicitly allowlisted using ID_NET_NAME_ALLOW_sysfsattr=1. If set to 1, udev can use any sysfs attribute unless it is explicitly forbidden using ID_NET_NAME_ALLOW_sysfsattr=0. The default value is 1.

The ID_NET_NAME_ALLOW_sysfsattr option allows fine-grained control over individual sysfs attributes. For example, ID_NET_NAME_ALLOW_ACPI_INDEX=1 would allow the use of the ACPI index for naming, while ID_NET_NAME_ALLOW_DEV_PORT=0 would explicitly forbid the use of the device port information.

These settings are typically configured using hardware database (hwdb) overrides, placed in files like /etc/udev/hwdb.d/*.hwdb.
