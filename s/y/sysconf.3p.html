NAME

sysconf, pathconf, fpathconf - get system configuration information

SYNOPSIS

#include <unistd.h>

long sysconf(int name);

long pathconf(const char *path, int name);

long fpathconf(int fd, int name);

DESCRIPTION

These functions allow applications to query the system for configuration parameters. The sysconf() function retrieves system-wide configuration values. The pathconf() and fpathconf() functions retrieve configuration values that vary according to the file system or directory on which the specified path or file descriptor fd respectively resides.

The name argument is a symbolic constant that specifies which configuration variable is requested. Symbolic constants are defined in <unistd.h>. The standard requires that sysconf() supports at least the following symbolic constants:

_SC_ARG_MAX, _SC_CHILD_MAX, _SC_CLK_TCK, _SC_NGROUPS_MAX, _SC_OPEN_MAX, _SC_PASS_MAX, _SC_JOB_CONTROL, _SC_SAVED_ANDS_MAX, _SC_VERSION, _SC_BC_BASE_MAX, _SC_BC_DIM_MAX, _SC_BC_SCALE_MAX, _SC_BC_STRING_MAX, _SC_COLL_WEIGHTS_MAX, _SC_EXPR_NEST_MAX, _SC_LINE_MAX, _SC_RE_DUP_MAX, _SC_SPECIAL_FORM_MAX, _SC_2_C_BIND, _SC_2_C_DEV, _SC_2_C_FORT, _SC_2_C_VERSION, _SC_2_CHAR_TERM, _SC_2_FORT_DEV, _SC_2_FORT_RUN, _SC_2_LOCALEDEF, _SC_2_SW_DEV, _SC_2_UPE, _SC_UIO_MAXIOV, _SC_TTY_NAME_MAX, _SC_MAX_CANON, _SC_MAX_INPUT, _SC_MIN_CANON, _SC_MIN_INPUT, _SC_HOST_NAME_MAX, _SC_SYMLINK_MAX, _SC_SYMLINK_MAX, _SC_PAGESIZE, _SC_PAGE_SIZE, _SC_SEM_NSEMS_MAX, _SC_SEM_MSGMAX, _SC_SEM_OP_MAX, _SC_SEMVMX, _SC_SHM_MAX, _SC_SHM_MNBS_MAX, _SC_SIGQUEUE_MAX, _SC_AIO_LISTIO_MAX, _SC_AIO_MAX, _SC_AIO_PRIOR_MAX, _SC_MQ_OPEN_MAX, _SC_MQ_PRIO_MAX, _SC_TIMER_MAX, _SC_DELAYTIMER_MAX, _SC_GETGR_R_SIZE_MAX, _SC_GETPW_R_SIZE_MAX, _SC_LOGIN_NAME_MAX, _SC_THREAD_KEYS_MAX, _SC_THREAD_STACK_MIN, _SC_THREAD_THREADS_MAX, _SC_THREADS, _SC_THREAD_ATTR_SIZE_MAX, _SC_THREAD_ROBUST_PRIO_MAX, _SC_THREAD_ROBUST_FUNCS_MAX, _SC_NPROCESSORS_CONF, _SC_NPROCESSORS_ONLN, _SC_AVPHYS_PAGES, _SC_AVAINTR_PAGES, _SC_PHYS_PAGES, _SC_TOKEN, _SC_TRACE, _SC_TRACE_EVENT_FILTER, _SC_TRACE_INHERIT, _SC_TRACE_LOG, _SC_LARGE_FILE, _SC_V6_ILP32_OFF32, _SC_V6_ILP32_OFFBIG, _SC_V6_ISupportS_LP64, _SC_V6_LP64_OFF64, _SC_IPV6, _SC_UNICODE_SUPPORT, _SC_UNICODE_CHARENCODING, _SC_LOCALEDEF, _SC_FD_MGMT, _SC_ATP, _SC_AT, _SC_CP, _SC_UIO_MAXIOV, _SC_TTY_NAME_MAX, _SC_MAX_CANON, _SC_MAX_INPUT, _SC_MIN_CANON, _SC_MIN_INPUT, _SC_HOST_NAME_MAX, _SC_SYMLINK_MAX, _SC_SPAWN, _SC_STREAMS, _SC_SYMLINK_MAX, _SC_USER_GROUPS_ACCESS, _SC_REGEXP, _SC_SHELL, _SC_SYMLINK_MAX, _SC_TRACE_EVENT_NAME_MAX, _SC_TRACE_NAME_MAX, _SC_TRACE_SYS_MAX, _SC_UTMP_MAX, _SC_VISIABLE_STRING_MAX.

The POSIX standard requires that pathconf() and fpathconf() support at least the following symbolic constants:

_PC_LINK_MAX, _PC_MAX_CANON, _PC_MAX_INPUT, _PC_MIN_CANON, _PC_MIN_INPUT, _PC_NAME_MAX, _PC_PATH_MAX, _PC_PIPE_BUF, _PC_CHOWN_RESTRICTED, _PC_NO_TRUNC, _PC_VDISABLE, _PC_ASYNC_IO, _PC_PRIO_IO, _PC_SYNC_IO, _PC_FILESIZEBITS, _PC_DATA_MOVING_MAX, _PC_SYMLINK_MAX, _PC_ALLOC_SIZE_MIN, _PC_REC_XFER_SIZE_MAX, _PC_REC_MAX_SOUND, _PC_REC_MIN_SOUND.

Linux supports all of these constants. Note that on Linux, _SC_PAGE_SIZE is a synonym for _SC_PAGESIZE.

On Linux, the behavior of pathconf() and fpathconf() can also be queried with sysconf() using the following constants:

_SC_ARG_MAX, _SC_CHILD_MAX, _SC_CLK_TCK, _SC_NGROUPS_MAX, _SC_OPEN_MAX, _SC_PASS_MAX, _SC_JOB_CONTROL, _SC_SAVED_ANDS_MAX, _SC_VERSION, _SC_BC_BASE_MAX, _SC_BC_DIM_MAX, _SC_BC_SCALE_MAX, _SC_BC_STRING_MAX, _SC_COLL_WEIGHTS_MAX, _SC_EXPR_NEST_MAX, _SC_LINE_MAX, _SC_RE_DUP_MAX, _SC_SPECIAL_FORM_MAX, _SC_2_C_BIND, _SC_2_C_DEV, _SC_2_C_FORT, _SC_2_C_VERSION, _SC_2_CHAR_TERM, _SC_2_FORT_DEV, _SC_2_FORT_RUN, _SC_2_LOCALEDEF, _SC_2_SW_DEV, _SC_2_UPE.

The value returned for _SC_CLK_TCK is the number of clock ticks per second. Note that this is a historical name; modern systems use a higher resolution.

The value returned for _SC_OPEN_MAX is the maximum number of file descriptors that a process may have open. This value can be changed by the system administrator.

The value returned for _SC_CLK_TCK is the number of clock ticks per second. Note that this is a historical name; modern systems use a higher resolution.

The value returned for _SC_CHILD_MAX is the maximum number of simultaneous processes that a single user may own.

The value returned for _SC_NGROUPS_MAX is the maximum number of supplementary groups that a process may have.

The value returned for _SC_ARG_MAX is the maximum length, in bytes, of the arguments to a single exec function, including environment variable space.

The value returned for _SC_PASS_MAX is the maximum length, in bytes, of the password string that can be supplied to the getpass() function. (Note: getpass() is obsolete.)

The value returned for _SC_JOB_CONTROL indicates whether job control is supported. A non-zero return value means it is supported.

The value returned for _SC_VERSION indicates the version of the POSIX standard supported. For IEEE Std 1003.1-2017, this is the value 201709L.

The values returned for the _SC_BC_*, _SC_COLL_WEIGHTS_MAX, _SC_EXPR_NEST_MAX, _SC_LINE_MAX, _SC_RE_DUP_MAX, _SC_SPECIAL_FORM_MAX, _SC_2_*, _SC_UIO_MAXIOV, _SC_TTY_NAME_MAX, _SC_MAX_CANON, _SC_MAX_INPUT, _SC_MIN_CANON, _SC_MIN_INPUT, _SC_HOST_NAME_MAX, _SC_SYMLINK_MAX, _SC_PAGESIZE, _SC_PAGE_SIZE, _SC_SEM_NSEMS_MAX, _SC_SEM_MSGMAX, _SC_SEM_OP_MAX, _SC_SEMVMX, _SC_SHM_MAX, _SC_SHM_MNBS_MAX, _SC_SIGQUEUE_MAX, _SC_AIO_LISTIO_MAX, _SC_AIO_MAX, _SC_AIO_PRIOR_MAX, _SC_MQ_OPEN_MAX, _SC_MQ_PRIO_MAX, _SC_TIMER_MAX, _SC_DELAYTIMER_MAX, _SC_GETGR_R_SIZE_MAX, _SC_GETPW_R_SIZE_MAX, _SC_LOGIN_NAME_MAX, _SC_THREAD_KEYS_MAX, _SC_THREAD_STACK_MIN, _SC_THREAD_THREADS_MAX, _SC_THREADS, _SC_THREAD_ATTR_SIZE_MAX, _SC_THREAD_ROBUST_PRIO_MAX, _SC_THREAD_ROBUST_FUNCS_MAX, _SC_NPROCESSORS_CONF, _SC_NPROCESSORS_ONLN, _SC_AVPHYS_PAGES, _SC_AVAINTR_PAGES, _SC_PHYS_PAGES, _SC_TOKEN, _SC_TRACE, _SC_TRACE_EVENT_FILTER, _SC_TRACE_INHERIT, _SC_TRACE_LOG, _SC_LARGE_FILE, _SC_V6_ILP32_OFF32, _SC_V6_ILP32_OFFBIG, _SC_V6_ISupportS_LP64, _SC_V6_LP64_OFF64, _SC_IPV6, _SC_UNICODE_SUPPORT, _SC_UNICODE_CHARENCODING, _SC_LOCALEDEF, _SC_FD_MGMT, _SC_ATP, _SC_AT, _SC_CP, _SC_UIO_MAXIOV, _SC_TTY_NAME_MAX, _SC_MAX_CANON, _SC_MAX_INPUT, _SC_MIN_CANON, _SC_MIN_INPUT, _SC_HOST_NAME_MAX, _SC_SYMLINK_MAX, _SC_SPAWN, _SC_STREAMS, _SC_SYMLINK_MAX, _SC_USER_GROUPS_ACCESS, _SC_REGEXP, _SC_SHELL, _SC_SYMLINK_MAX, _SC_TRACE_EVENT_NAME_MAX, _SC_TRACE_NAME_MAX, _SC_TRACE_SYS_MAX, _SC_UTMP_MAX, _SC_VISIABLE_STRING_MAX, _PC_LINK_MAX, _PC_MAX_CANON, _PC_MAX_INPUT, _PC_MIN_CANON, _PC_MIN_INPUT, _PC_NAME_MAX, _PC_PATH_MAX, _PC_PIPE_BUF, _PC_CHOWN_RESTRICTED, _PC_NO_TRUNC, _PC_VDISABLE, _PC_ASYNC_IO, _PC_PRIO_IO, _PC_SYNC_IO, _PC_FILESIZEBITS, _PC_DATA_MOVING_MAX, _PC_SYMLINK_MAX, _PC_ALLOC_SIZE_MIN, _PC_REC_XFER_SIZE_MAX, _PC_REC_MAX_SOUND, _PC_REC_MIN_SOUND are defined in the POSIX.1-2017 standard. The values returned are related to the POSIX extensions to the C language, shell, and utilities, and are used by the getconf() utility.

The values for _SC_GETGR_R_SIZE_MAX and _SC_GETPW_R_SIZE_MAX specify the maximum size in bytes of the buffer that can be passed to the reentrant functions getgrnam_r() and getgrgid_r(), and getpwnam_r() and getpwuid_r() respectively.

The value for _SC_LOGIN_NAME_MAX specifies the maximum number of characters in the name of the user logging in.

The value for _SC_HOST_NAME_MAX specifies the maximum number of characters in the name of the host.

The value for _SC_SYMLINK_MAX specifies the maximum number of components in a symbolic link. A value of -1 indicates no limit.

The value for _SC_PAGESIZE (and its synonym _SC_PAGE_SIZE) specifies the number of bytes in a page of memory. This is equivalent to the memory page size of the underlying hardware.

The value for _SC_UIO_MAXIOV specifies the maximum value for iov_len in a struct iovec used in readv() and writev().

The values for _SC_NPROCESSORS_CONF and _SC_NPROCESSORS_ONLN specify the number of processors configured and online, respectively.

The values for _SC_AVPHYS_PAGES, _SC_AVAINTR_PAGES, and _SC_PHYS_PAGES are related to the system's physical memory. _SC_PHYS_PAGES is the total number of physical memory pages. _SC_AVPHYS_PAGES is the number of available physical memory pages. _SC_AVAINTR_PAGES is the number of available interrupt protection memory pages.

The constants prefixed with _PC_ are used by pathconf() and fpathconf(). They query values related to a specific file path or file descriptor.

_PC_LINK_MAX: Maximum number of links to a file.

_PC_MAX_CANON: Maximum number of bytes that can be read from a terminal device before a newline is encountered.

_PC_MAX_INPUT: Maximum number of bytes that can be typed on a terminal device before they are read by a program.

_PC_MIN_CANON: Minimum number of bytes that can be read from a terminal device before a newline is encountered.

_PC_MIN_INPUT: Minimum number of bytes that can be typed on a terminal device before they are read by a program.

_PC_NAME_MAX: Maximum number of characters in a file name.

_PC_PATH_MAX: Maximum number of characters in a path name.

_PC_PIPE_BUF: Maximum number of bytes that can be written to a pipe without being fragmented.

_PC_CHOWN_RESTRICTED: Indicates if the CHOWN_RESTRICTED mount option is in effect for the file system. A non-zero return value means it is in effect.

_PC_NO_TRUNC: Indicates if the NO_TRUNC mount option is in effect for the file system. A non-zero return value means it is in effect.

_PC_VDISABLE: The value of the VEOF, VEOL, VERASE, VINTR, VQUIT, VSUSP, VSTART, VSTOP, VMIN, or VTIME terminal control characters for which is set to the value of the _POSIX_VDISABLE constant. This constant is defined in <termios.h>. A return value of -1 indicates that the constant is not defined.

_PC_SYMLINK_MAX: Maximum number of components in a symbolic link.

_PC_FILESIZEBITS: The number of bits used to represent file sizes on the file system. This is typically 32 or 64. A value of 32 indicates that the file system is limited to 2 GiB file sizes. A value of 64 indicates that the file system supports files larger than 2 GiB.

_PC_DATA_MOVING_MAX: The maximum number of bytes that can be moved by a single read() or write() operation.

_PC_ALLOC_SIZE_MIN: The minimum size in bytes of an allocation for a file system object.

_PC_REC_XFER_SIZE_MAX: The maximum number of bytes that can be transferred in a single I/O operation.

_PC_REC_MAX_SOUND: The maximum number of bytes that can be transferred in a single synchronized I/O data transfer operation.

_PC_REC_MIN_SOUND: The minimum number of bytes that can be transferred in a single synchronized I/O data transfer operation.

RETURN VALUE

On success, sysconf(), pathconf(), and fpathconf() return the value of the requested configuration variable. If the implementation does not support the requested variable, or if the variable is undefined, they return -1 and set errno to EINVAL.

For some configuration variables, such as _SC_OPEN_MAX, the return value is a maximum value, and is not an error if the actual value is different. For _SC_CLK_TCK, the return value is the number of clock ticks per second.

If a configuration variable has an indeterminate or infinite value, the function returns -1, but errno is not set.

If pathconf() or fpathconf() detect an error (e.g., the file does not exist, or permission is denied), they return -1 and set errno accordingly.

If the requested configuration variable is not defined on the system, these functions return -1 and set errno to EINVAL.

Some configuration variables return a negative value to indicate that the constant is not defined or not applicable. For example, _SC_ARG_MAX may return -1 if the system does not impose a limit on the number of arguments.

ERRORS

pathconf() may fail for the following reasons:

  • EACCES: Search permission is denied for any component of a prefix of path.
  • EINVAL: The value of name is not a recognized symbolic constant.
  • EIO: An I/O error occurred while reading from or writing to the file system.
  • ELOOP: Too many symbolic links were encountered in translating path.
  • ENAMETOOLONG: path exceeds {PATH_MAX} bytes, or a component of path exceeds {NAME_MAX} bytes.
  • ENOENT: The file named by path does not exist.
  • ENOTDIR: A component of path is not a directory.
  • ENXIO: path refers to a character special or block special file and the file does not exist.
  • EROFS: path refers to a file on a read-only file system, and the operation would require writing.

fpathconf() may fail if:

  • EBADF: fd is not a valid file descriptor.
  • EINVAL: The value of name is not a recognized symbolic constant.
  • EIO: An I/O error occurred while reading from or writing to the file system.

EXAMPLES

To get the maximum number of open files:

#include <unistd.h>
#include <stdio.h>

long open_max;

open_max = sysconf(_SC_OPEN_MAX);
if (open_max == -1) {
perror("sysconf _SC_OPEN_MAX");
}
else {
printf("Maximum number of open files: %ld\\n", open_max);
}

To get the maximum number of characters in a file name:

#include <unistd.h>
#include <stdio.h>

long name_max;

name_max = fpathconf(".", _PC_NAME_MAX);
if (name_max == -1) {
perror("fpathconf _PC_NAME_MAX");
}
else {
printf("Maximum length of filename: %ld\\n", name_max);
}

APPLICATION USAGE

Applications should generally not rely on these functions to determine resource limits. Instead, they should handle errors gracefully when resource limits are encountered. For example, an application should not attempt to allocate an array of size {PATH_MAX}, because this could lead to excessive memory usage. Instead, the application should attempt the operation and handle the error if it fails.

POSIX.1-2001 and later versions require that if an implementation does not support a particular configuration variable, it should return -1 and set errno to EINVAL. However, older implementations may not adhere to this. Applications should check for EINVAL, but also consider the possibility of an indeterminate or infinite value being returned without an error.

The values returned by these functions are intended for informational purposes only. They should not be used to determine the size of buffers to be allocated. For example, {PATH_MAX} might be defined as -1 if there is no limit, or it might be defined as a very large value that is impractical to allocate.

The POSIX standard specifies that the values returned by these functions are not guaranteed to remain constant throughout the lifetime of a process. However, on Linux, these values are generally static and do not change after system initialization unless explicitly reconfigured by a system administrator.

RATIONALE

The sysconf() function allows applications to query system-wide configuration parameters. The pathconf() and fpathconf() functions allow applications to query file system-specific configuration parameters. This separation is important because some parameters, like _PC_NAME_MAX, vary from file system to file system.

The POSIX standard specifies that the values returned by these functions are not guaranteed to remain constant throughout the lifetime of a process. This is because a system administrator might change system configuration at any time. However, for POSIX.1-2017 and later, these values are not expected to change within the lifetime of a process. This means that applications can cache these values if they are frequently accessed.

The design of these functions was influenced by the desire to provide a standardized way for applications to query system configuration information. Historically, many systems provided their own mechanisms for obtaining this information, leading to portability issues. The POSIX standard aimed to rectify this by defining a common interface.

The decision to return integer values instead of strings was made to simplify implementation and usage. While string values might offer more flexibility, they would also introduce additional complexity in parsing and handling, which was deemed undesirable for this particular set of functions. In the end, it was felt that this imposed an unreasonable level of complication and sophistication on the application developer.

This runtime facility is not meant to provide ever-changing values that applications have to check multiple times. The values are seen as changing no more frequently than once per system initialization, such as by a system administrator or operator with an automatic configuration program. This volume of POSIX.1‐2017 specifies that they shall not change within the lifetime of the process.

Some values apply to the system overall and others vary at the file system or directory level. The latter are described in fpathconf().

Note that all values returned must be expressible as integers. String values were considered, but the additional flexibility of this approach was rejected due to its added complexity of implementation and use.

Some values, such as {PATH_MAX}, are sometimes so large that they must not be used to, say, allocate arrays. The sysconf() function returns a negative value to show that this symbolic constant is not even defined in this case.

Similar to pathconf(), this permits the implementation not to have a limit. When one resource is infinite, returning an error indicating that some other resource limit has been reached is conforming behavior.
