--from-pattern=, --to-pattern=

When used in conjunction with the dot command (see above), this selects which relationships are shown in the dependency graph. Both options require a glob(7) pattern as an argument, which will be matched against the left-hand and the right-hand, respectively, nodes of a relationship.

Each of these can be used more than once, in which case the unit name must match one of the values. When tests for both sides of the relation are present, a relation must pass both tests to be shown. When patterns are also specified as positional arguments, they must match at least one side of the relation. In other words, patterns specified with those two options will trim the list of edges matched by the positional arguments, if any are given, and fully determine the list of edges shown otherwise.

Added in version 201.

--fuzz=timespan

When used in conjunction with the critical-chain command (see above), also show units, which finished timespan earlier, than the latest unit in the same level. The unit of timespan is seconds unless specified with a different unit, e.g. "50ms".

--recursive-errors=MODE

Control verification of units and their dependencies and whether systemd-analyze verify exits with a non-zero process exit status or not. With yes, return a non-zero process exit status when warnings arise during verification of either the specified unit or any of its associated dependencies. With no, return a non-zero process exit status when warnings arise during verification of only the specified unit. With one, return a non-zero process exit status when warnings arise during verification of either the specified unit or its immediate dependencies. If this option is not specified, zero is returned as the exit status regardless whether warnings arise during verification or not.

--image-policy=policy

Takes an image policy string as argument, as per systemd.image-policy(7). The policy is enforced when operating on the disk image specified via --image=, see above. If not specified, defaults to the "*" policy, i.e. all recognized file systems in the image are used.

--offline=BOOL

With security, perform an offline security review of the specified unit files, i.e. does not have to rely on PID 1 to acquire security information for the files like the security verb when used by itself does. This means that --offline= can be used with --root= and --image= as well. If a unit's overall exposure level is above that set by --threshold= (default value is 100), --offline= will return an error.

Added in version 250.

--profile=PATH

With security --offline=, takes into consideration the specified portable profile when assessing unit settings. The profile can be passed by name, in which case the well-known system locations will be searched, or it can be the full path to a specific drop-in file.

Added in version 250.

--threshold=NUMBER

With security, allow the user to set a custom value to compare the overall exposure level with, for the specified unit files. If a unit's overall exposure level, is greater than that set by the user, security will return an error. --threshold= can be used with --offline= as well and its default value is 100.

يُعلم هذا الخيار أداة التصفح بعدم إرسال سلاسل تهيئة وإلغاء تهيئة termcap إلى الطرفية. يتم تعيينه افتراضيًا للسماح بعرض مخرجات الأوامر في الطرفية حتى بعد خروج أداة التصفح. ومع ذلك، هذا يمنع بعض وظائف أداة التصفح من العمل، وخاصة لا يمكن تمرير المخرجات المصفحة بالماوس.

لاحظ أن تعيين متغير البيئة العادي $LESS ليس له تأثير على استدعاءات less بواسطة أدوات systemd.

انظر less(1) لمزيد من المناقشة.

$SYSTEMD_LESSCHARSET

تجاوز مجموعة الأحرف التي يتم تمريرها إلى less (افتراضيًا "utf-8"، إذا تم تحديد أن الطرفية المستدعية متوافقة مع UTF-8).

لاحظ أن تعيين متغير البيئة العادي $LESSCHARSET ليس له تأثير على استدعاءات less بواسطة أدوات systemd.

$SYSTEMD_PAGERSECURE

الأوامر الشائعة لأدوات التصفح مثل less(1)، بالإضافة إلى "التصفح"، أي التمرير عبر المخرجات، تدعم فتح أو كتابة ملفات أخرى وتشغيل أوامر shell تعسفية. عند استدعاء الأوامر ذات الامتيازات المرتفعة، على سبيل المثال تحت sudo(8) أو pkexec(1)، تصبح أداة التصفح حدودًا أمنية. يجب الحرص على استخدام البرامج ذات الوظائف المحدودة للغاية فقط كأدوات تصفح، وعدم السماح بالميزات التفاعلية غير المقصودة مثل فتح أو إنشاء ملفات جديدة أو بدء عمليات فرعية. قد يتم تمكين "الوضع الآمن" لأداة التصفح كما هو موضح أدناه، إذا كانت أداة التصفح تدعم ذلك (معظم أدوات التصفح ليست مكتوبة بطريقة تأخذ هذا في الاعتبار). يوصى إما بتمكين "الوضع الآمن" صراحةً أو تعطيل أداة التصفح تمامًا باستخدام --no-pager أو PAGER=cat عند السماح للمستخدمين غير الموثوق بهم بتنفيذ أوامر بامتيازات مرتفعة.

يأخذ هذا الخيار وسيطة منطقية. عند تعيينها على صحيح، يتم تمكين "الوضع الآمن" لأداة التصفح. في "الوضع الآمن"، سيتم تعيين LESSSECURE=1 عند استدعاء أداة التصفح، مما يوجه أداة التصفح لتعطيل الأوامر التي تفتح أو تنشئ ملفات جديدة أو تبدأ عمليات فرعية جديدة. حاليًا، less(1) هو الوحيد المعروف بفهم هذا المتغير وتنفيذ "الوضع الآمن".

عند تعيينها على خطأ، لا يتم وضع أي قيود على أداة التصفح. قد يسمح تعيين SYSTEMD_PAGERSECURE=0 أو عدم إزالته من البيئة الموروثة للمستخدم باستدعاء أوامر تعسفية.

عندما لا يتم تعيين $SYSTEMD_PAGERSECURE، تحاول أدوات systemd اكتشاف ما إذا كان يجب تمكين "الوضع الآمن" وما إذا كانت أداة التصفح تدعمه. يتم تمكين "الوضع الآمن" إذا لم يكن معرف المستخدم الفعال (effective UID) هو نفس مالك جلسة تسجيل الدخول، انظر geteuid(2) و sd_pid_get_owner_uid(3)، أو عند التشغيل تحت sudo(8) أو أدوات مماثلة ($SUDO_UID تم تعيينها [4]). في هذه الحالات، سيتم تعيين SYSTEMD_PAGERSECURE=1 ولن يتم استخدام أدوات التصفح غير المعروفة بتنفيذ "الوضع الآمن" على الإطلاق. لاحظ أن هذا الاكتشاف التلقائي يغطي فقط الآليات الأكثر شيوعًا لرفع الامتيازات وهو مخصص للراحة. يوصى بتعيين $SYSTEMD_PAGERSECURE صراحةً أو تعطيل أداة التصفح.

لاحظ أنه إذا كان من المفترض احترام المتغيرين $SYSTEMD_PAGER أو $PAGER، بخلاف تعطيل أداة التصفح، فيجب أيضًا تعيين $SYSTEMD_PAGERSECURE.

$SYSTEMD_COLORS

يأخذ وسيطة منطقية. عند تعيينها على صحيح، ستستخدم systemd والأدوات ذات الصلة الألوان في مخرجاتها، وإلا ستكون المخرجات أحادية اللون. بالإضافة إلى ذلك، يمكن للمتغير أن يأخذ إحدى القيم الخاصة التالية: "16"، "256" لتقييد استخدام الألوان إلى الألوان الأساسية 16 أو 256 ANSI، على التوالي. يمكن تحديد ذلك لتجاوز القرار التلقائي بناءً على $TERM وما تم توصيل وحدة التحكم به.

$SYSTEMD_URLIFY

يجب أن تكون القيمة قيمة منطقية. تتحكم فيما إذا كان يجب إنشاء روابط قابلة للنقر في المخرجات لمحاكيات الطرفية التي تدعم ذلك. يمكن تحديد ذلك لتجاوز القرار الذي تتخذه systemd بناءً على $TERM وظروف أخرى.

مثال 33. سياسة JSON

ملف JSON الذي يتم تمريره كمعلمة مسار إلى --security-policy= يحتوي على كائن JSON على مستوى أعلى، مع كون المفاتيح هي معرفات اختبار التقييم المذكورة أعلاه. يجب أن تكون القيم في الملف كائنات JSON تحتوي على واحد أو أكثر من الحقول التالية: description_na (سلسلة نصية)، description_good (سلسلة نصية)، description_bad (سلسلة نصية)، weight (عدد صحيح غير موقع)، و range (عدد صحيح غير موقع). إذا كان أي من هذه الحقول المقابلة لمعرف محدد لملف الوحدة مفقودًا من كائن JSON، فسيتم استخدام القيمة الافتراضية المضمنة المقابلة لنفس المعرف للتحليل الأمني كافتراضي. تُستخدم حقلا الوزن والنطاق في تحديد مستوى التعرض الإجمالي لملفات الوحدة: يتم تعيين قيمة كل إعداد لدرجة سوء، والتي يتم ضربها في وزن السياسة وتقسيمها على نطاق السياسة لتحديد التعرض الإجمالي الذي تعنيه الإعدادات. يتم تجميع درجة السوء المحسوبة عبر جميع الإعدادات في ملف الوحدة، وتطبيعها إلى النطاق 1...100، وتستخدم لتحديد مستوى التعرض الإجمالي للوحدة. من خلال السماح للمستخدمين بمعالجة هذه الحقول، فإن "فعل" الأمان يمنحهم الخيار لتحديد بأنفسهم أي المعرفات أكثر أهمية وبالتالي يجب أن يكون لها تأثير أكبر على مستوى التعرض. وزن "0" يعني أن الإعداد لن يتم التحقق منه.
