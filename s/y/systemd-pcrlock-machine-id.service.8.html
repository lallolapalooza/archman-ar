الاسم

systemd-pcrlock, systemd-pcrlock-file-system.service, systemd-pcrlock-firmware-code.service, systemd-pcrlock-firmware-config.service, systemd-pcrlock-machine-id.service, systemd-pcrlock-make-policy.service, systemd-pcrlock-secureboot-authority.service, systemd-pcrlock-secureboot-policy.service - تحليل وتوقع حالات TPM2 PCR وإنشاء سياسة وصول من التوقع

ملخص

/usr/lib/systemd/systemd-pcrlock [OPTIONS...]

الوصف

ملاحظة: هذه الأداة تجريبية في الوقت الحالي. على الرغم من أنها من المحتمل أن تصبح مكونًا منتظمًا لـ systemd، إلا أنها قد لا تزال تتغير في سلوكها وواجهتها.

systemd-pcrlock هي أداة يمكن استخدامها لتحليل وتوقع قياسات TPM2 PCR، وإنشاء سياسات وصول TPM2 من التوقع التي تخزنها في فهرس TPM2 NV (أي في ذاكرة TPM2 غير المتطايرة). يمكن استخدام هذا بعد ذلك لتقييد الوصول إلى كائنات TPM2 (مثل مفاتيح تشفير القرص) إلى عمليات تمهيد النظام التي تستخدم فقط مكونات محددة وموثوقة.

systemd-pcrlock يستخدم كمدخلات لتحليله وتوقعه:

•سجل أحداث UEFI TPM2 (أي /sys/kernel/security/tpm0/binary_bios_measurements) لعملية التمهيد الحالية.
•سجل أحداث TPM2 في مساحة المستخدم (أي /run/log/systemd/tpm2-measure.log) لعملية التمهيد الحالية.
•حالة PCR الحالية لشريحة TPM2.
•ملفات تعريف مكونات التمهيد (*.pcrlock و *.pcrlock.d/*.pcrlock، انظر systemd.pcrlock(5)) التي تعرف كل منها قياسات متوقعة لمكون واحد من عملية التمهيد، مما يسمح بوجود متغيرات بديلة لكل منها. (قد تُستخدم المتغيرات لمنح علامة متعددة لإصدارات نواة متعددة أو إصدارات محمل التمهيد في نفس الوقت.)

يستخدم هذه المدخلات لإنشاء سجل أحداث مدمج، والتحقق من صحته مقابل قيم PCR. ثم يحاول التعرف على سجلات الأحداث ومطابقتها مع المكونات المعرفة. لكل PCR حيث يمكن القيام بذلك بشكل شامل (أي حيث تمت مطابقة جميع السجلات المذكورة وجميع المكونات المعرفة) يمكن استخدام ذلك للتنبؤ بقياسات PCR المستقبلية، مع مراعاة المتغيرات البديلة المعرفة لكل مكون. يمكن بعد ذلك تحويل هذا التوقع إلى سياسة وصول TPM2 (تتكون من عناصر TPM2 PolicyPCR و PolicyOR)، والتي يتم تخزينها بعد ذلك في فهرس NV في TPM2. يمكن استخدام ذلك لقفل الأسرار (مثل مفاتيح تشفير القرص) لهذه السياسات (عبر سياسة TPM2 PolicyAuthorizeNV).

استخدم أدوات مثل systemd-cryptenroll(1) أو systemd-repart(8) لربط تشفير القرص بسياسة TPM2 systemd-pcrlock كهذه. على وجه التحديد، انظر خيارات --tpm2-pcrlock= لهذه الأدوات.

يتطلب منطق سياسة الوصول جهاز TPM2 الذي ينفذ أمر "PolicyAuthorizeNV"، أي ينفذ TPM 2.0 الإصدار 1.38 أو أحدث.

الأوامر

يتم فهم الأوامر التالية:

log

يقرأ هذا سجل أحداث TPM2 المدمج، ويتحقق من صحته، ويطابقه مع قيم PCR الحالية، ويخرج كلاهما في شكل جدول. ادمجه مع --json= لإنشاء إخراج بتنسيق JSON.

تمت الإضافة في الإصدار 255.

cel

يقرأ هذا سجل أحداث TPM2 المدمج ويكتبه إلى STDOUT بتنسيق TCG Canonical Event Log Format (CEL-JSON)[1].

تمت الإضافة في الإصدار 255.

list-components

يعرض قائمة بتعريفات المكونات ومتغيراتها، أي ملفات *.pcrlock التي تم اكتشافها في /var/lib/pcrlock.d/، /usr/lib/pcrlock.d/، والمجلدات المدعومة الأخرى. انظر systemd.pcrlock(5) للحصول على تفاصيل حول هذه الملفات والقائمة الكاملة للمجلدات التي تم البحث فيها.

تمت الإضافة في الإصدار 255.

predict

يتوقع حالة PCR في عمليات التمهيد المستقبلية. سيقوم هذا بتحليل سجل أحداث TPM2 كما هو موضح أعلاه، والتعرف على المكونات، ثم إنشاء جميع قيم PCR الناتجة الممكنة لجميع تركيبات متغيرات المكونات. لاحظ أنه لا يتم إجراء أي توقع لـ PCRs التي لا تتطابق قيمتها مع سجلات الأحداث، أو التي يتم اكتشاف قياسات غير معروفة لها، أو التي يتم تعريف مكونات لها ولا يمكن العثور عليها في سجل الأحداث. هذا إجراء أمان لضمان أن سياسة الوصول التي تم إنشاؤها يمكن تلبيتها بشكل صحيح في عمليات التمهيد الحالية والمستقبلية.

تمت الإضافة في الإصدار 255.

make-policy

يتوقع هذا حالة PCR لعمليات التمهيد المستقبلية، بشكل مشابه لأمر predict أعلاه. ثم يستخدم هذه البيانات لإنشاء سياسة وصول TPM2 التي يخزنها في فهرس TPM2 NV. يتم كتابة التوقع والمعلومات حول TPM2 المستخدم وفهرس NV الخاص به إلى /var/lib/systemd/pcrlock.json.

يتم تخصيص فهرس NV عند الاستدعاء الأول، ويتم تحديثه عند الاستدعاءات اللاحقة.

يمكن تغيير محتويات فهرس NV (وبالتالي تحديث السياسة المخزنة فيه) عن طريق توفير رقم تعريف شخصي للوصول. يتم عادةً إنشاء رقم التعريف الشخصي هذا تلقائيًا وتخزينه بتنسيق مشفر (مع سياسة وصول تربطه بفهرس NV نفسه) في ملف السياسة JSON المذكور أعلاه. يمكن اختيار رقم التعريف الشخصي هذا بواسطة المستخدم، عبر المفتاح --recovery-pin=. إذا تم تحديده، يمكن استخدامه كمسار وصول بديل لتحديث السياسة.

إذا تطابق التوقع الجديد مع القديم، ينتهي هذا الأمر بسرعة ولا ينفذ أي عملية أخرى. (ما لم يتم تحديد --force، انظر أدناه.)

بدءًا من الإصدار v256، يتم تشفير نسخة من ملف السياسة /var/lib/systemd/pcrlock.json في بيانات اعتماد (انظر systemd-creds(1) للحصول على التفاصيل) وكتابتها إلى قسم EFI System Partition أو قسم XBOOTLDR، في الدليل الفرعي /loader/credentials/. هناك يتم التقاطها عند التمهيد بواسطة systemd-stub(7) وتمريرها إلى initrd المستدعى، حيث يمكن استخدامها لفتح نظام الملفات الجذر (الذي يحتوي عادةً على /var/، وهو المكان الذي يوجد فيه النسخة الأساسية من السياسة، والتي لا يمكن استخدامها وبالتالي لفتح نظام الملفات الجذر). يتم تسمية ملف بيانات الاعتماد باسم رمز إدخال التمهيد للتثبيت (انظر bootctl(1))، والذي يمكن تكوينه عبر المفتاح --entry-token=، انظر أدناه.

تمت الإضافة في الإصدار 255.

remove-policy

يزيل سياسة تم إنشاؤها مسبقًا. يحذف ملف /var/lib/systemd/pcrlock.json، ويلغي تخصيص فهرس NV.

تمت الإضافة في الإصدار 255.

is-supported

يتحقق مما إذا كان TPM2 المحلي يدعم جميع الوظائف لكي يعمل systemd-pcrlock بشكل صحيح. يقوم هذا بإجراء اختبارات مماثلة لـ systemd-analyze has-tpm2، ولكنه يتحقق أيضًا من دعم عمليات TPM2 المطلوبة لـ systemd-pcrlock. ينتج أحد الخيارات التالية: "no" (لا)، "partial" (جزئي) (في حالة توفر بعض أجزاء دعم TPM2 في الأجهزة، البرنامج الثابت، نظام التشغيل، ولكن ليس بالكامل)، "obsolete" (قديم) (إذا كان دعم TPM2 متاحًا في الأجهزة، البرنامج الثابت ونظام التشغيل، ولكن العمليات المطلوبة لـ systemd-pcrlock مفقودة)، "yes" (نعم). يعيد حالة خروج صفرية إذا كان الدعم الكامل متاحًا، وإلا يعيد قيمة غير صفرية.

إذا تم دمجه مع --quiet، فإنه يقمع إخراج السلسلة.

حاليًا، يتحقق هذا من دعم أمر PolicyAuthorizeNV TPM2، وكذلك من دعم خوارزمية التجزئة SHA-256.

تمت الإضافة في الإصدار 258.

lock-firmware-code, unlock-firmware-code

ينشئ/يزيل ملفات .pcrlock بناءً على سجل أحداث TPM2 لعملية التمهيد الحالية التي تغطي جميع السجلات لـ PCRs 0 ("platform-code") و 2 ("external-code").

تسمح هذه العملية بقفل عملية التمهيد إلى الإصدار الحالي من البرامج الثابتة للنظام وبطاقاته الإضافية. يجب استخدام هذه العملية فقط إذا لم يوفر بائع النظام بيانات pcrlock مناسبة مسبقًا.

لاحظ أن هذه البيانات تطابق فقط الإصدار الحالي من البرنامج الثابت. إذا تم تطبيق تحديث للبرنامج الثابت، فستكون هذه البيانات قديمة ولن تمر أي سياسة وصول تم إنشاؤها منها. لذلك يوصى باستدعاء unlock-firmware-code قبل إجراء تحديث للبرنامج الثابت، متبوعًا بـ make-policy لتحديث السياسة.

يتم استدعاء systemd-pcrlock lock-firmware-code تلقائيًا عند التمهيد عبر الوحدة systemd-pcrlock-firmware-code.service، إذا تم تمكينها. هذا يضمن أنه يتم قفل سياسة مدارة بواسطة systemd-pcrlock تلقائيًا إلى إصدار البرنامج الثابت الجديد كلما تم تحديث السياسة.

خيارات

يتم فهم الخيارات التالية:

--allow-secureboot, --disable-secureboot

تحدد ما إذا كانت سياسة Secure Boot يجب أن يتم تضمينها في السياسة الإجمالية. يتم تعطيل Secure Boot بشكل افتراضي.

--entry-token=TOKEN

يحدد رمز إدخال التمهيد للتثبيت. القيمة الافتراضية هي "arch".

--force, -f

تفرض إنشاء سياسة جديدة، حتى لو لم يتغير التوقع. مفيد لتحديث السياسة القديمة إذا كان التوقع الجديد لا يتطابق مع القديم.

--json[=MODE]

ينتج إخراجًا بتنسيق JSON. الوضع MODE هو "enable" (تمكين)، "pretty" (جميل) أو "disable" (تعطيل).

--recovery-pin=PIN

يحدد رقم التعريف الشخصي للوصول. إذا لم يتم تحديده، فسيتم إنشاؤه تلقائيًا.

--quiet, -q

كتم الإخراج.

--system-dir=DIR

يحدد الدليل الذي يتم فيه تخزين ملفات سياسة systemd-pcrlock. الافتراضي هو /var/lib/systemd/pcrlock.json.

--unlock-policy

يفتح السياسة المخزنة حاليًا في فهرس NV. هذا يسمح بتحديث السياسة.

حالة الخروج

تُعاد رموز خروج صفرية في حالة النجاح، ورموز خروج غير صفرية في حالة الفشل.

أمثلة

لإنشاء سياسة TPM2 جديدة لتمكين الوصول إلى مفاتيح تشفير القرص:

# systemd-pcrlock make-policy

لفتح السياسة المخزنة حاليًا للسماح بتحديثها:

# systemd-pcrlock --unlock-policy make-policy

لإزالة السياسة المخزنة حاليًا:

# systemd-pcrlock remove-policy

systemd-pcrlock-machine-id.service(8)

NAME

systemd-pcrlock-machine-id.service, systemd-pcrlock-machine-id - Create and manage TPM2 PCR integrity measurements

SYNOPSIS

/usr/lib/systemd/systemd-pcrlock-machine-id.service

DESCRIPTION

The systemd-pcrlock-machine-id.service is a systemd(8) service that is used to manage the machine-id(5) integrity measurement using the TPM2 Security Module (TPM2).

It uses the TPM2 NV index to store and retrieve policy metadata for the machine-id. This ensures that the machine-id can be verified at boot time and that unauthorized modifications can be detected.

The service can be used to create, manage, and inspect TPM2 policies for the machine-id.

COMMANDS

make-policy
Creates a TPM2 policy for the machine-id. This command will create a new NV index if one does not exist, or update an existing policy if one is already present. It measures the current machine-id and stores it in the TPM2 NV index along with an access policy.
check-policy
Checks the TPM2 policy for the machine-id. This command will verify that the current machine-id matches the one stored in the TPM2 NV index. It returns an exit code of 0 if the policy is valid, and a non-zero exit code otherwise.
lock-machine-id
Locks the TPM2 NV index for the machine-id. This command will prevent any further modifications to the NV index until it is unlocked with the appropriate PIN or recovery PIN.
unlock-machine-id
Unlocks the TPM2 NV index for the machine-id. This command requires the correct PIN or recovery PIN to be provided. Once unlocked, modifications to the NV index are allowed.
is-supported
Checks if TPM2 is supported and available on the system. Returns an exit code of 0 if supported, and a non-zero exit code otherwise.

OPTIONS

The following options are available:

--pin=

Takes a PIN as argument. This PIN is used to protect the TPM2 NV index with. If no policy was created before, this PIN is used to protect the newly allocated NV index. If a policy has been created before, the PIN is used to unlock write access to the NV index. If either "hide" or "show" is used, a PIN is automatically generated, and — only in case of "show" — displayed on screen. Regardless if user supplied or automatically generated, it is stored in encrypted form in the policy metadata file. The recovery PIN may be used to regain write access to an NV index in case the access policy became out of date.

Added in version 255.

--pcrlock=

Takes a file system path as argument. If specified, configures where to write the generated pcrlock data to. Honoured by the various lock-* commands. If not specified, a default path is generally used, as documented above.

Added in version 255.

--policy=

Takes a file system path as argument. If specified, configures where to write pcrlock policy metadata to. If not specified, defaults to /var/lib/systemd/pcrlock.json.

Added in version 255.

--force

If specified with make-policy, the predicted policy will be written to the NV index even if it is detected to be the same as the previously stored one.

Added in version 255.

--entry-token=

Sets the boot entry token to use for the file name for the pcrlock policy credential in the EFI System Partition or XBOOTLDR partition. See the bootctl(1) option of the same regarding expected values. This switch has an effect on the make-policy command only.

Added in version 256.

--quiet

If specified suppresses output when invoked for is-supported.

Added in version 258.

--json=MODE

Shows output formatted as JSON. Expects one of "short" (for the shortest possible output without any redundant whitespace or line breaks), "pretty" (for a pretty version of the same, with indentation and line breaks) or "off" (to turn off JSON output, the default).

--no-pager

Do not pipe output into a pager.

-h, --help

Print a short help text and exit.

--version

Print a short version string and exit.

EXIT STATUS

On success, 0 is returned, a non-zero failure code otherwise.
