الاسم

systemd.link - إعدادات جهاز الشبكة

الملخص

link.link

الوصف

ملف نصي بسيط بصيغة ini يقوم بترميز إعدادات لأجهزة الشبكة المطابقة، يستخدمه systemd-udevd(8) وبالتحديد وظيفته المدمجة net_setup_link. انظر systemd.syntax(7) لوصف عام للصيغة.

لاحظ أن بعض التوزيعات قد تدمج ملفات .link في مرافق الإقلاع المبكر (مثل تضمين نسخ من ملفات .link في initramfs). لذلك قد يكون من الضروري اتخاذ خطوات يدوية لضمان اتساق أي تغييرات محلية مع مرافق تخزين الإقلاع المبكر. يجب استشارة الوثائق الخاصة بالتوزيع المعني.

تتم قراءة ملفات .link من الملفات الموجودة في دليل شبكة النظام /usr/lib/systemd/network و /usr/local/lib/systemd/network [1]، ودليل شبكة وقت التشغيل المؤقت /run/systemd/network، ودليل شبكة الإدارة المحلية /etc/systemd/network. يتم فرز جميع ملفات الإعدادات وتجهيزها بشكل جماعي بترتيب أبجدي، بغض النظر عن الأدلة التي توجد فيها. ومع ذلك، تستبدل الملفات ذات الأسماء المتطابقة بعضها البعض. يوصى بأن يكون لكل اسم ملف بادئة رقمية أصغر من "70" (على سبيل المثال 10-eth0.link). بخلاف ذلك، قد تكون ملفات .link الافتراضية أو تلك التي أنشأتها خدمة systemd-network-generator.service(8) لها الأسبقية على الملفات التي تم تكوينها بواسطة المستخدم. الملفات الموجودة في /etc/ لها أعلى أولوية، وتسبق الملفات الموجودة في /run/ الملفات بنفس الاسم في /usr/lib/. يمكن استخدام ذلك لتجاوز ملف رابط تم توفيره بواسطة النظام بملف محلي إذا لزم الأمر. كحالة خاصة، يؤدي ملف فارغ (حجم ملف 0) أو رابط رمزي بنفس الاسم يشير إلى /dev/null إلى تعطيل ملف الإعدادات تمامًا (يتم "إلغاؤه").

إلى جانب ملف الرابط foo.link، قد توجد مجلد "drop-in" foo.link.d/. سيتم دمج جميع الملفات ذات اللاحقة ".conf" من هذا الدليل بترتيب أبجدي وتحليلها بعد تحليل ملف الربط الرئيسي نفسه. هذا مفيد لتعديل أو إضافة إعدادات التكوين، دون الحاجة إلى تعديل ملف الإعداد الرئيسي. يجب أن يحتوي كل ملف drop-in على رؤوس أقسام مناسبة.

بالإضافة إلى /etc/systemd/network، يمكن وضع مجلدات drop-in ".d" في أدلة /usr/lib/systemd/network أو /run/systemd/network. تفضل ملفات drop-in الموجودة في /etc/ على تلك الموجودة في /run/ والتي بدورها تفضل تلك الموجودة في /usr/lib/. تفضل ملفات drop-in تحت أي من هذه الأدلة ملف الربط الرئيسي أينما كان موقعه.

يحتوي ملف الربط على قسم [Match]، والذي يحدد ما إذا كان يمكن تطبيق ملف ربط معين على جهاز معين، بالإضافة إلى قسم [Link] يحدد كيفية تكوين الجهاز. يتم تطبيق أول (من حيث الترتيب المعجمي) ملفات الربط التي تطابق جهازًا معينًا. لاحظ أن ملفًا افتراضيًا 99-default.link يتم شحنه بواسطة النظام. لذلك يجب أن يكون لأي .link تم توفيره بواسطة المستخدم اسم أبجدي سابق ليتم اعتباره على الإطلاق.

راجع udevadm(8) لتشخيص المشكلات المتعلقة بملفات .link.

خيارات قسم [MATCH]

يقال إن ملف الربط يتطابق مع واجهة إذا تم استيفاء جميع المطابقات المحددة بواسطة قسم [Match]. عندما لا يحتوي ملف الربط على إعدادات صالحة في قسم [Match]، فإن الملف سيطابق جميع الواجهات وسيصدر systemd-udevd تحذيرًا بشأن ذلك. تلميح: لتجنب التحذير ولجعل الأمر واضحًا أن جميع الواجهات يجب مطابقتها، أضف ما يلي:

OriginalName=*

يتم تطبيق أول (بترتيب أبجدي) من ملفات الربط التي تطابق واجهة معينة، ويتم تجاهل جميع الملفات اللاحقة، حتى لو كانت متطابقة أيضًا. يتم قبول المفاتيح التالية:

MACAddress=

قائمة بعناوين الأجهزة مفصولة بمسافات بيضاء. التنسيقات المقبولة هي:

سداسي عشري مفصول بنقطتين

يجب أن يكون كل حقل بايتًا واحدًا. مثال: "12:34:56:78:90:ab" أو "AA:BB:CC:DD:EE:FF".

تمت الإضافة في الإصدار 250.

سداسي عشري مفصول بشرطات

يجب أن يكون كل حقل بايتًا واحدًا. مثال: "12-34-56-78-90-ab" أو "AA-BB-CC-DD-EE-FF".

تمت الإضافة في الإصدار 250.

سداسي عشري مفصول بنقاط

يجب أن يكون كل حقل بايتين. مثال: "1234.5678.90ab" أو "AABB.CCDD.EEFF".

تمت الإضافة في الإصدار 250.

تنسيق عنوان IPv4

مثال: "127.0.0.1" أو "192.168.0.1".

تمت الإضافة في الإصدار 250.

تنسيق عنوان IPv6

مثال: "2001:0db8:85a3::8a2e:0370:7334" أو "::1".

تمت الإضافة في الإصدار 250.

يجب أن يكون الطول الإجمالي لكل عنوان MAC هو 4 (لأنفاق IPv4) أو 6 (لشبكات Ethernet) أو 16 (لأنفاق IPv6) أو 20 (لـ InfiniBand). يمكن أن يظهر هذا الخيار أكثر من مرة، وفي هذه الحالة يتم دمج القوائم. إذا تم تعيين سلسلة فارغة لهذا الخيار، يتم إعادة تعيين قائمة عناوين الأجهزة المحددة قبله. الافتراضي هو غير محدد.

تمت الإضافة في الإصدار 211.

PermanentMACAddress=

قائمة بعناوين الأجهزة الدائمة مفصولة بمسافات بيضاء. بينما تطابق MACAddress= عنوان MAC الحالي للجهاز، فإن هذا يطابق عنوان MAC الدائم للجهاز، والذي قد يختلف عن العنوان الحالي. استخدم التنسيق السداسي العشري الكامل المفصول بنقطتين أو بشرطات أو بنقاط، أو بتنسيق عنوان IPv4 أو IPv6. يمكن أن يظهر هذا الخيار أكثر من مرة، وفي هذه الحالة يتم دمج القوائم. إذا تم تعيين سلسلة فارغة لهذا الخيار، يتم إعادة تعيين قائمة عناوين الأجهزة المحددة قبله. الافتراضي هو غير محدد.

تمت الإضافة في الإصدار 245.

Path=

قائمة بأنماط shell مفصولة بمسافات بيضاء تطابق المسار الثابت، كما يكشفها خاصية udev ID_PATH.

تمت الإضافة في الإصدار 211.

Driver=

قائمة بأنماط shell مفصولة بمسافات بيضاء تطابق برنامج التشغيل المرتبط حاليًا بالجهاز، كما يكشفه خاصية udev ID_NET_DRIVER للجهاز الأصل، أو إذا لم يتم تعيين ذلك، برنامج التشغيل كما يكشفه ethtool -i للجهاز نفسه. إذا تم اقتراح القائمة بـ "!"، يتم عكس الاختبار.

تمت الإضافة في الإصدار 211.

Type=

قائمة بأنماط shell مفصولة بمسافات بيضاء تطابق نوع الجهاز، كما يكشفه networkctl list. إذا تم اقتراح القائمة بـ "!"، يتم عكس الاختبار. بعض القيم الصالحة هي "ether" و "loopback" و "wlan" و "wwan". الأنواع الصالحة مسماة إما من سمة udev "DEVTYPE" أو ماكرو "ARPHRD_" في linux/if_arp.h، لذا فهذه القائمة ليست شاملة.

تمت الإضافة في الإصدار 211.

Kind=

قائمة بأنماط shell مفصولة بمسافات بيضاء تطابق نوع الجهاز، كما يكشفه networkctl status INTERFACE أو ip -d link show INTERFACE. إذا تم اقتراح القائمة بـ "!"، يتم عكس الاختبار. بعض القيم الصالحة هي "bond" و "bridge" و "gre" و "tun" و "veth". الأنواع الصالحة معطاة بواسطة سمة netlink "IFLA_INFO_KIND"، لذا فهذه القائمة ليست شاملة.

تمت الإضافة في الإصدار 251.

Property=

قائمة بأسماء خصائص udev مفصولة بمسافات بيضاء مع قيمها بعد علامة المساواة ("="). إذا تم تحديد خصائص متعددة، يتم دمج نتائج الاختبار (AND). إذا تم اقتراح القائمة بـ "!"، يتم عكس الاختبار. إذا كانت القيمة تحتوي على مسافات بيضاء، فيجب اقتباس زوج المفتاح والقيمة بأكمله. إذا كانت القيمة تحتوي على علامات اقتباس، فيجب الهروب من علامة الاقتباس بـ "\".

مثال: إذا كان لملف .link ما يلي:

Property=ID_MODEL_ID=9999 "ID_VENDOR_FROM_DATABASE=vendor name" "KEY=with \"quotation\""

عندئذٍ، يتطابق ملف .link فقط عندما يحتوي الواجهة على جميع الخصائص الثلاث المذكورة أعلاه.

تمت الإضافة في الإصدار 243.

OriginalName=

قائمة بأنماط shell مفصولة بمسافات بيضاء تطابق اسم الجهاز، كما يكشفه خاصية udev "INTERFACE". لا يمكن استخدام هذا لمطابقة الأسماء التي تم تغييرها بالفعل من مساحة المستخدم. كن حذرًا

ENERGY EFFICIENT ETHERNET

The [EnergyEfficientEthernet] section controls the Energy Efficient Ethernet (EEE) feature of the interface, and accepts the following keys.

Enable=

Takes a boolean argument. When true, the Energy Efficient Ethernet (EEE) feature will be enabled on the interface. Defaults to unset, and the enablement of EEE will be unchanged.

Added in version 258.

TxLowPowerIdle=

Takes a boolean argument. When true, the transmit Low Power Idle (Tx-LPI) mode of the Energy Efficient Ethernet feature will be enabled on the interface. Defaults to unset, and the enablement of the mode will be unchanged.

Added in version 258.

TxLowPowerIdleSec=

Takes a timespan. This configures how long the interface should not enter the Low Power Idle mode after transmission. If it is too short, may decrease performance. If it is too long, may not gain energy saving. Defaults to unset, and the timespan will be unchanged.

Added in version 258.

LinkMode=

Takes a list of link modes, e.g. "1000baset-full". See the table for Advertise= setting in [Link] section in the above for possible values. This configures the Energy Efficient Ethernet capable connection modes to be advertised. Defaults to unset, and the advertised modes will be unchanged.

Added in version 258.

SPECIFIERS

Some settings resolve specifiers which may be used to write generic unit files referring to runtime or unit parameters that are replaced when the unit files are loaded. Specifiers must be known and resolvable for the setting to be valid. The following specifiers are understood:

Table 2. Specifiers available in unit files

Specifier Meaning Details
"%a" Architecture A short string identifying the architecture of the local system. A string such as x86, x86-64 or arm64. See the architectures defined for ConditionArchitecture= in systemd.unit(5) for a full list.
"%A" Operating system image version The operating system image version identifier of the running system, as read from the IMAGE_VERSION= field of /etc/os-release. If not set, resolves to an empty string. See os-release(5) for more information.
"%b" Boot ID The boot ID of the running system, formatted as string. See random(4) for more information.
"%B" Operating system build ID The operating system build identifier of the running system, as read from the BUILD_ID= field of /etc/os-release. If not set, resolves to an empty string. See os-release(5) for more information.
"%H" Host name The hostname of the running system.
"%l" Short host name The hostname of the running system, truncated at the first dot to remove any domain component.
"%m" Machine ID The machine ID of the running system, formatted as string. See machine-id(5) for more information.
"%M" Operating system image identifier The operating system image identifier of the running system, as read from the IMAGE_ID= field of /etc/os-release. If not set, resolves to an empty string. See os-release(5) for more information.
"%o" Operating system ID The operating system identifier of the running system, as read from the ID= field of /etc/os-release. See os-release(5) for more information.
"%q" Pretty host name The pretty hostname of the running system, as read from the PRETTY_HOSTNAME= field of /etc/machine-info. If not set, resolves to the short hostname. See machine-info(5) for more information.
"%T" Directory for temporary files This is either /tmp or the path "$TMPDIR", "$TEMP" or "$TMP" are set to. (Note that the directory may be specified without a trailing slash.)
"%v" Kernel release Identical to uname -r output.
"%V" Directory for larger and persistent temporary files This is either /var/tmp or the path "$TMPDIR", "$TEMP" or "$TMP" are set to. (Note that the directory may be specified without a trailing slash.)
"%w" Operating system version ID The operating system version identifier of the running system, as read from the VERSION_ID= field of /etc/os-release. If not set, resolves to an empty string. See os-release(5) for more information.
"%W" Operating system variant ID The operating system variant identifier of the running system, as read from the VARIANT_ID= field of /etc/os-release. If not set, resolves to an empty string. See os-release(5) for more information.

EXAMPLES

Example 1. /usr/lib/systemd/network/99-default.link

The link file 99-default.link that is shipped with systemd defines the default policies for the interface name, alternative names, and MAC address of links.

[Match]
OriginalName=*
[Link]
NamePolicy=keep kernel database onboard slot path
AlternativeNamesPolicy=database onboard slot path
MACAddressPolicy=persistent

Example 2. /etc/systemd/network/10-dmz.link

This example assigns the fixed name "dmz0" to the interface with the MAC address 00:a0:de:63:7a:e6:

[Match]
MACAddress=00:a0:de:63:7a:e6
[Link]
Name=dmz0

NamePolicy= is not set, so Name= takes effect. We use the "10-" prefix to order this file early in the list. Note that it needs to be before 99-default.link, i.e. it needs a numerical prefix, to have any effect at all.

Example 3. (Re-)applying a .link file to an interface

After a new .link file has been created, or an existing .link file modified, the new settings may be applied to the matching interface with the following commands:

$ sudo udevadm control --reload
$ sudo ip link set eth0 down
$ sudo udevadm trigger --verbose --settle --action add /sys/class/net/eth0

You may also need to stop the service that manages the network interface, e.g. systemd-networkd.service(8) or NetworkManager.service before the above operation, and then restart the service after that. For more details about udevadm command, see udevadm(8).

In this case, the interface was already renamed, so the keep policy specified as the first option in 99-default.link means that the existing name is preserved. If keep was removed, or if were in boot before the renaming has happened, we might get the following instead:

ID_NET_NAME=enp0s31f6
...

Please note that the details of output are subject to change.

Example 5. /etc/systemd/network/10-internet.link

This example assigns the fixed name "internet0" to the interface with the device path "pci-0000:00:1a.0-*":

[Match]
Path=pci-0000:00:1a.0-*
[Link]
Name=internet0
