المعلمة "acl" هي قائمة التحكم بالوصول (ACL) الجديدة بأحد أشكالها النصية المطولة أو المختصرة (انظر acl(5)). تقوم قائمة التحكم بالوصول الجديدة بالكامل باستبدال أي قائمة تحكم وصول سابقة على الملف. يجب أن تحتوي قائمة التحكم بالوصول على أذونات Unix الكاملة (على سبيل المثال، "u::rwx,g::rx,o::rx").

إذا كنت تحدد مستخدمين أو مجموعات فردية، فيجب أيضًا توفير حقل القناع (على سبيل المثال، "m::rwx")، متبوعًا بحقل (حقول) "u:ID:..." و/أو "g:ID:...". لذلك، يمكن أن يبدو سلسلة قائمة التحكم بالوصول الكاملة كالتالي:

u::rwx,g::rwx,o::rwx,m::rwx,u:500:rwx,g:500:rwx
\ أذونات Unix / \القناع/ \    قائمة التحكم بالوصول    /

يجب عليك استخدام معرفات المستخدم (UIDs) ومعرفات المجموعات (GIDs) الرقمية. لربط أسماء المستخدمين وأسماء المجموعات بالمعرف الرقمي الصحيح في سياق الضيف، استخدم دوال Augeas (انظر "$g->aug_init").

تعتمد هذه الدالة على الميزة "acl". انظر أيضًا "$g->feature-available".

المعلمات الاختيارية هي:

"readonly"
إذا كانت صحيحة، فسيتم التعامل مع الصورة للقراءة فقط. لا تزال عمليات الكتابة مسموحة، ولكن يتم تخزينها في طبقة تراكب لقطة مؤقتة يتم التخلص منها في النهاية. لا يتم تعديل القرص الذي تضيفه.
"format"
هذا يفرض تنسيق الصورة. إذا قمت بتجاهل هذا (أو استخدمت "$g->add_drive" أو "$g->add_drive_ro") فسيتم اكتشاف التنسيق تلقائيًا. تشمل التنسيقات الممكنة "raw" و "qcow2".

"name"
كان هذا الحقل يُمرر كتلميح لفحص الضيف، ولكنه لم يعد مستخدمًا.
"label"

The expression is evaluated using "aug_get" and "aug_match" semantics. The result of the evaluation must be a nodeset containing exactly one node. If the expression evaluates to something else, then an error is returned.

If the expression evaluates to NULL, then the node is cleared.

If "expr" is a nodeset, then the value of the node named by "expr" is used.

If "expr" is a node, then its value is used.

If "expr" is a string, then that string is used as the value. If the string contains special characters like `*`, it will be escaped.

If "expr" is a scalar number, then that number is used as the value.

If "expr" is a boolean, then the string "true" or "false" is used as the value.

On success, returns a pair of the number of nodes in the nodeset, and a boolean indicating if a new node was created.

This call can be used to set multiple values at once, by passing an expression that evaluates to multiple nodes. In this case, all nodes in the resulting nodeset will be set to the same value. Note that this is an expensive operation, and it is usually better to use "$g->aug_setm" for this purpose.

The argument "val" is the value to set. It can be any scalar type, or a nodeset. If it is a nodeset, then the value of the first node in the nodeset is used. If it is NULL, then the node is cleared.

The argument "name" will be the nodeset containing that single node.

guestfs API functions — صفحة دليل لينكس بالعربية This page documents the guestfs API functions.

The guestfs API provides a large number of functions for inspecting and modifying virtual machine disk images. This page lists most of them.

 use.guestfs; my $g = guestfs-new(); guestfs-add_domain($g, "my_vm"); guestfs-launch($g); # Now you can call any of the functions below guestfs-shutdown($g); guestfs-free($g); $g->lsindir ($dir, $name);

This call is an older version of "$g->lsindir_dir". It is equivalent to calling "$g->lsindir_dir($dir, $name, 0)".

 $g->lstat ($path);

Return information about a file, like stat(2). The information is returned as a hash reference containing keys like "mode", "size", "mtime", etc. The values are integers.

Note that "gid" and "uid" are not available because the remote file access protocol does not support them.

If the file does not exist, or is inaccessible, an error will be raised.

 $g->lstat_size ($path);

Return the size of the file in bytes. This is a shortcut for "lstat($path)->{size}".

 $g->mkdir ($path);

Create a directory at the given path. The parent directory must exist.

This function depends on the feature "mkdir". See also "$g->feature-available".

 $g->mkdir_parents ($path);

Create a directory, creating any parent directories as needed. This is like "mkdir -p" in the shell.

This function depends on the feature "mkdir_parents". See also "$g->feature-available".

 $path = $g->mktemp ($tmpl);

This command creates a temporary file. The "tmpl" parameter should be a full pathname for the temporary directory name with the final six characters being "XXXXXX".

For example: "/tmp/myprogXXXXXX" or "/Temp/myprogXXXXXX", the second one being suitable for Windows filesystems.

The name of the temporary file that was created is returned.

The temporary file is created with mode 0600 and is owned by root.

The caller is responsible for deleting the temporary file after use.

See also: "$g->mkdtemp".

 $g->mount ($mountable, $mountpoint);

Mount a guest disk at a position in the filesystem. Block devices are named /dev/sda, /dev/sdb and so on, as they were added to the guest. If those block devices contain partitions, they will have the usual names (eg. /dev/sda1). Also LVM /dev/VG/LV-style names can be used, or ‘mountable’ strings returned by "$g->list_filesystems" or "$g->inspect_get_mountpoints".

The rules are the same as for mount(2): A filesystem must first be mounted on / before others can be mounted. Other filesystems can only be mounted on directories which already exist.

The mounted filesystem is writable, if we have sufficient permissions on the underlying device.

Before libguestfs 1.13.16, this call implicitly added the options "sync" and "noatime". The "sync" option greatly slowed writes and caused many problems for users. If your program might need to work with older versions of libguestfs, use "$g->mount_options" instead (using an empty string for the first parameter if you don't want any options).

 $g->mount_9p ($mounttag, $mountpoint [, options => $options]);

This call does nothing and returns an error.

This function is deprecated. There is no replacement. Consult the API documentation in guestfs(3) for further information.

Deprecated functions will not be removed from the API, but the fact that they are deprecated indicates that there are problems with correct use of these functions.

 $g->mount_local ($localmountpoint [, readonly => $readonly] [, options => $options] [, cachetimeout => $cachetimeout] [, debugcalls => $debugcalls]);

This call exports the libguestfs-accessible filesystem to a local mountpoint (directory) called "localmountpoint". Ordinary reads and writes to files and directories under "localmountpoint" are redirected through libguestfs.

If the optional "readonly" flag is set to true, then writes to the filesystem return error "EROFS".

"options" is a comma-separated list of mount options. See guestmount(1) for some useful options.

"cachetimeout" sets the timeout (in seconds) for cached directory entries. The default is 60 seconds. See guestmount(1) for further information.

If "debugcalls" is set to true, then calls to this function and its underlying system calls will be logged to stderr. This is useful for debugging.

This function depends on the feature "mount_local". See also "$g->feature-available".

 $g->mount_options ($mountable, $mountpoint, $options);

Mount a guest filesystem with the specified options. This is similar to "$g->mount", but allows you to specify mount options.

See the mount(8) man page for a list of possible options.

The options string is a comma-separated list of options, e.g. "ro,noatime".

If you want to mount the filesystem with no options, pass an empty string for "options".

See also "$g->mount".

 $g->mount_ro ($mountable, $mountpoint);

Mount a guest filesystem read-only. This is equivalent to calling "$g->mount_options($mountable, $mountpoint, 'ro')".

 $g->mount_recursive ($mountpoint);

Mount all filesystems into the specified mountpoint. This is useful when the guest has multiple filesystems that you want to access through a single directory tree.

You must ensure that the innermost mountpoints have the longest pathnames, as in the example code above.

For more details see https://bugzilla.redhat.com/show_bug.cgi?id=599503

Autosync [see "$g->set_autosync", this is set by default on handles] can cause "$g->umount_all" to be called when the handle is closed which can also trigger these issues.

 $g->mknod ($mode, $devmajor, $devminor, $path);

This call creates block or character special devices, or named pipes (FIFOs).

The "mode" parameter should be the mode, using the standard constants. "devmajor" and "devminor" are the device major and minor numbers, only used when creating block and character special devices.

Note that, just like mknod(2), the mode must be bitwise OR'd with S_IFBLK, S_IFCHR, S_IFIFO or S_IFSOCK (otherwise this call just creates a regular file). These constants are available in the standard Linux header files, or you can use "$g->mknod_b", "$g->mknod_c" or "$g->mkfifo" which are wrappers around this command which bitwise OR in the appropriate constant for you.

The mode actually set is affected by the umask.

This function depends on the feature "mknod". See also "$g->feature-available".

 $g->mknod_b ($mode, $devmajor, $devminor, $path);

This call creates a block device node called "path" with mode "mode" and device major/minor "devmajor" and "devminor". It is just a convenient wrapper around "$g->mknod".

Unlike with "$g->mknod", "mode" must contain only permissions bits.

The mode actually set is affected by the umask.

This function depends on the feature "mknod". See also "$g->feature-available".

 $g->mknod_c ($mode, $devmajor, $devminor, $path);

This call creates a char device node called "path" with mode "mode" and device major/minor "devmajor" and "devminor". It is just a convenient wrapper around "$g->mknod".

Unlike with "$g->mknod", "mode" must contain only permissions bits.

The mode actually set is affected by the umask.

This function depends on the feature "mknod". See also "$g->feature-available".

 $g->mksquashfs ($path, $filename [, compress => $compress] [, excludes => $excludes]);

Create a squashfs filesystem for the specified "path".

The optional "compress" flag controls compression. If not given, then the output compressed using "gzip". Otherwise one of the following strings may be given to select the compression type of the squashfs: "gzip", "lzma", "lzo", "lz4", "xz".

The other optional arguments are:

"excludes" A list of wildcards. Files are excluded if they match any of the wildcards.

Please note that this API may fail when used to compress directories with large files, such as the resulting squashfs will be over 3GB big.

This function depends on the feature "squashfs". See also "$g->feature-available".

 $g->mkswap ($device [, label => $label] [, uuid => $uuid]);

Create a Linux swap partition on "device".

The option arguments "label" and "uuid" allow you to set the label and/or UUID of the new swap partition.

 $g->mkswap_opts ($device [, label => $label] [, uuid => $uuid]);

This is an alias of "mkswap".

 $g->mkswap_L ($label, $device);

Create a swap partition on "device" with label "label".

Note that you cannot attach a swap label to a block device (eg. /dev/sda), just to a partition. This appears to be a limitation of the kernel or swap tools.

This function is deprecated. In new code, use the "mkswap" call instead.

Deprecated functions will not be removed from the API, but the fact that they are deprecated indicates that there are problems with correct use of these functions.

 $g->mkswap_U ($uuid, $device);

Create a swap partition on "device" with UUID "uuid".

This function depends on the feature "linuxfsuuid". See also "$g->feature-available".

This function is deprecated. In new code, use the "mkswap" call instead.

 $g->mkswap_file ($path);

Create a swap file.

This command just writes a swap file signature to an existing file. To create the file itself, use something like "$g->fallocate".

 $path = $g->mktemp ($tmpl [, suffix => $suffix]);

 $g->modprobe ($modulename);

This loads a kernel module in the appliance.

This function depends on the feature "linuxmodules". See also "$g->feature-available".

يمكنك استدعاء هذا من مؤشر ترابط مختلف عن المؤشر الذي استدعى "$g->mount_local"، مع مراعاة القواعد المعتادة للمؤشرات الترابط و libguestfs (انظر "MULTIPLE HANDLES AND MULTIPLE THREADS" في guestfs(3)).

انظر "MOUNT LOCAL" في guestfs(3) للحصول على وثائق كاملة.

$g->mount_loop ($file, $mountpoint);
يسمح لك هذا الأمر بتحميل file (صورة نظام ملفات في ملف) على نقطة تحميل. إنه مكافئ تمامًا للأمر "mount -o loop file mountpoint".
$g->mount_options ($options, $mountable, $mountpoint);
هذا هو نفس الأمر "$g->mount"، ولكنه يسمح لك بتعيين خيارات التحميل كما هو الحال بالنسبة للعلم -o الخاص بالأمر mount(8).

إذا كان المعامل "options" سلسلة نصية فارغة، فلن يتم تمرير أي خيارات (جميع الخيارات افتراضية إلى أي شيء تستخدمه نظام الملفات).

$g->mount_ro ($mountable, $mountpoint);
هذا هو نفس الأمر "$g->mount"، ولكنه يقوم بتحميل نظام الملفات بعلم القراءة فقط (-o ro).
$g->mount_vfs ($options, $vfstype, $mountable, $mountpoint);
هذا هو نفس الأمر "$g->mount"، ولكنه يسمح لك بتعيين كل من خيارات التحميل ونوع نظام الملفات كما هو الحال بالنسبة للأعلام -o و -t الخاصة بالأمر mount(8).
$device = $g->mountable_device ($mountable);
إرجاع اسم الجهاز لشيء قابل للتحميل. في كثير من الحالات، الشيء القابل للتحميل هو اسم الجهاز.

ومع ذلك، هذا لا ينطبق على الأقسام الفرعية btrfs، حيث يكون الشيء القابل للتحميل مزيجًا من اسم الجهاز ومسار القسم الفرعي (انظر أيضًا "$g->mountable_subvolume" لاستخراج مسار القسم الفرعي للشيء القابل للتحميل إن وجد).

$subvolume = $g->mountable_subvolume ($mountable);
إرجاع مسار القسم الفرعي لشيء قابل للتحميل. الأشياء القابلة للتحميل في الأقسام الفرعية btrfs هي مزيج من اسم الجهاز ومسار القسم الفرعي (انظر أيضًا "$g->mountable_device" لاستخراج جهاز الشيء القابل للتحميل).

إذا كان الشيء القابل للتحميل لا يمثل قسمًا فرعيًا btrfs، فإن هذه الوظيفة تفشل ويتم تعيين "errno" إلى "EINVAL".

%mps = $g->mountpoints ();
هذا الاستدعاء مشابه لـ "$g->mounts". يقوم هذا الاستدعاء بإرجاع قائمة بالأجهزة. هذا الاستدعاء يقوم بإرجاع جدول تجزئة (خريطة) من اسم الجهاز إلى الدليل الذي تم تحميل الجهاز فيه.
@devices = $g->mounts ();
يقوم هذا بإرجاع قائمة بأنظمة الملفات المحملة حاليًا. يقوم بإرجاع قائمة بالأجهزة (على سبيل المثال، /dev/sda1، /dev/VG/LV).

لا يتم عرض بعض التحميلات الداخلية.

انظر أيضًا: "$g->mountpoints"

$g->mv ($src, $dest);
يقوم هذا بنقل ملف من "src" إلى "dest" حيث يكون "dest" إما اسم ملف وجهة أو دليل وجهة.

انظر أيضًا: "$g->rename".

$nrdisks = $g->nr_devices ();
يقوم هذا بإرجاع عدد الأجهزة الكتلية الكاملة التي تمت إضافتها. هذا هو نفس عدد الأجهزة التي سيتم إرجاعها إذا قمت باستدعاء "$g->list_devices".

لمعرفة الحد الأقصى لعدد الأجهزة التي يمكن إضافتها، استدعِ "$g->max_disks".

$status = $g->ntfs_3g_probe ($rw, $device);
يقوم هذا الأمر بتشغيل الأمر ntfs-3g.probe(8) الذي يقوم بفحص جهاز NTFS للتحقق من إمكانية التحميل. (لا يمكن تحميل جميع أقراص NTFS للقراءة والكتابة، ولا يمكن تحميل بعضها على الإطلاق).

"rw" هو علم منطقي. قم بتعيينه على true إذا كنت تريد اختبار ما إذا كان يمكن تحميل القرص للقراءة والكتابة. قم بتعيينه على false إذا كنت تريد اختبار ما إذا كان يمكن تحميل القرص للقراءة فقط.

القيمة المرجعة هي عدد صحيح وهو 0 إذا نجحت العملية، أو قيمة غير صفرية موثقة في صفحة الدليل الخاصة بـ ntfs-3g.probe(8).

تعتمد هذه الوظيفة على ميزة "ntfs3g". انظر أيضًا "$g->feature-available".

$g->ntfscat_i ($device, $inode, $filename);
تنزيل ملف معين بمعرفه (inode) من نظام ملفات NTFS وحفظه باسم filename على الجهاز المحلي.

هذا يسمح بتنزيل بعض الملفات التي يصعب الوصول إليها بطريقة أخرى مثل تلك الموجودة داخل مجلد $Extend.

يجب إلغاء تحميل نظام الملفات الذي سيتم استخراج الملف منه، وإلا ستفشل المكالمة.

$g->ntfsclone_in ($backupfile, $device);
استعادة backupfile (من مكالمة سابقة لـ "$g->ntfsclone_out") إلى device، مع الكتابة فوق أي محتويات موجودة لهذا الجهاز.

تعتمد هذه الوظيفة على ميزة "ntfs3g". انظر أيضًا "$g->feature-available".

تدفق نظام ملفات NTFS device إلى الملف المحلي backupfile. التنسيق المستخدم لملف النسخ الاحتياطي هو تنسيق خاص تستخدمه أداة ntfsclone(8).

إذا كان العلم الاختياري "metadataonly" صحيحًا، فسيتم حفظ البيانات الوصفية فقط، مع فقدان جميع بيانات المستخدم (هذا مفيد لتشخيص بعض مشاكل نظام الملفات).

الأعلام الاختيارية "rescue"، "ignorefscheck"، "preservetimestamps" و "force" لها معانٍ دقيقة مفصلة في صفحة الدليل الخاصة بـ ntfsclone(8).

استخدم "$g->ntfsclone_in" لاستعادة الملف مرة أخرى إلى جهاز libguestfs.

تعتمد هذه الوظيفة على ميزة "ntfs3g". انظر أيضًا "$g->feature-available".

$g->ntfsfix ($device [, clearbadsectors => $clearbadsectors]);
يقوم هذا الأمر بإصلاح بعض التناقضات الأساسية في NTFS، ويعيد تعيين ملف سجل NTFS، وجدولة فحص تناسق NTFS لأول تمهيد في Windows.

هذا ليس مكافئًا لـ "chkdsk" في Windows. إنه لا يقوم بفحص نظام الملفات بحثًا عن التناقضات.

العلم الاختياري "clearbadsectors" يمسح قائمة القطاعات التالفة. هذا مفيد بعد نسخ قرص به قطاعات تالفة إلى قرص جديد.

تعتمد هذه الوظيفة على ميزة "ntfs3g". انظر أيضًا "$g->feature-available".

$g->ntfsresize ($device [, size => $size] [, force => $force]);
يقوم هذا الأمر بتغيير حجم نظام ملفات NTFS، وتوسيعه أو تقليصه إلى حجم الجهاز الأساسي.

المعاملات الاختيارية هي:

"size"
الحجم الجديد (بالبايت) لنظام الملفات. إذا تم حذفه، يتم تغيير حجم نظام الملفات ليناسب الحاوية (مثل القسم).
"force"
إذا كان هذا الخيار صحيحًا، فسيتم فرض تغيير حجم نظام الملفات حتى لو تم تمييز نظام الملفات على أنه يتطلب فحص تناسق.

بعد عملية تغيير الحجم، يتم دائمًا تمييز نظام الملفات على أنه يتطلب فحص تناسق (للأمان). يجب عليك التمهيد في Windows لإجراء هذا الفحص ومسح هذا الشرط. إذا لم تقم بتعيين الخيار "force"، فلن يكون من الممكن استدعاء "$g->ntfsresize" عدة مرات على نظام ملفات واحد دون التمهيد في Windows بين كل تغيير حجم.

انظر أيضًا ntfsresize(8).

تعتمد هذه الوظيفة على ميزة "ntfsprogs". انظر أيضًا "$g->feature-available".

$g->ntfsresize_opts ($device [, size => $size] [, force => $force]);
هذا اسم مستعار لـ "ntfsresize".
$g->ntfsresize_size ($device, $size);
هذا الأمر هو نفس الأمر "$g->ntfsresize" باستثناء أنه يسمح لك بتحديد الحجم الجديد (بالبايت) بشكل صريح.

تعتمد هذه الوظيفة على ميزة "ntfsprogs". انظر أيضًا "$g->feature-available".

$g->user_cancel ();
This function cancels the current upload or download operation.

Unlike most other libguestfs calls, this function is signal safe and thread safe. You can call it from a signal handler or from another thread, without needing to do any locking.

The transfer that was in progress (if there is one) will stop shortly afterwards, and will return an error. The errno (see "guestfs_last_errno") is set to "EINTR", so you can test for this to find out if the operation was cancelled or failed because of another error.

No cleanup is performed: for example, if a file was being uploaded then after cancellation there may be a partially uploaded file. It is the caller’s responsibility to clean up if necessary.

There are two common places that you might call "$g->user_cancel":

In an interactive text-based program, you might call it from a "SIGINT" signal handler so that pressing cancels the current operation. (You also need to call "$g->set_pgroup" so that child processes don't receive the signal).

In a graphical program, when the main thread is displaying a progress bar with a cancel button, wire up the cancel button to call this function.

الوصف

Sys::Guestfs is a Perl module that provides bindings for the libguestfs library. Libguestfs is a set of tools for accessing and editing virtual machine disk images. It includes a library, guestfs(1), that can be used from C, and this Perl module allows you to use the same functionality from Perl.

The primary purpose of libguestfs is to inspect and modify virtual machines. You can use it to:

  • Inspect the filesystem of a VM.
  • Add or remove files from a VM.
  • Modify configuration files.
  • Install or remove software.
  • And much more...

This Perl module provides an object-oriented interface to the libguestfs library. You create a Sys::Guestfs object, configure it by adding disk images, launch the guestfish environment, and then call various methods to interact with the VM.

الأخطاء

Errors are typically reported by the library by throwing exceptions. You should wrap calls to Sys::Guestfs methods in an eval block or use Try::Tiny to catch exceptions.

eval {
    my $g = Sys::Guestfs->new();
    $g->launch();
    # ...
};
if ($@) {
    warn "An error occurred: $@\n";
}

الأساليب

The methods available in Sys::Guestfs mirror the functions provided by the libguestfs C library. Refer to the guestfs(3) man page for a comprehensive list and description of available methods.

Some common methods include:

  • new(): Creates a new Sys::Guestfs object.
  • add_drive(...): Adds a disk image to the virtual machine.
  • launch(): Launches the guestfish environment.
  • mount_fs(...): Mounts a filesystem within the VM.
  • umount_all(): Unmounts all filesystems.
  • shutdown(): Shuts down the guestfish environment.
  • get_backend(): Gets the backend used by libguestfs.
  • list_partitions(...): Lists partitions on a disk.
  • inspect_os(...): Inspects the operating system installed on a disk.
  • download(...): Downloads a file from the VM.
  • upload(...): Uploads a file to the VM.

التوفر

The Sys::Guestfs Perl module is part of the libguestfs package, which is available in the official Arch Linux repositories.

You can install it using pacman:

sudo pacman -S libguestfs

تخزين البيانات في المقبض

The Sys::Guestfs object can be used to store arbitrary data associated with the handle. This is useful for keeping track of metadata or state related to a particular guestfs handle.

You can use the set_data() and get_data() methods for this purpose:

my $g = Sys::Guestfs->new();
$g->set_data({ name => "my_vm", status => "running" });

my $data = $g->get_data();
print "VM Name: ", $data->{name}, "\n";
