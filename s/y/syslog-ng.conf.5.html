تطبيق syslog-ng OSE هو تطبيق تسجيل نظام مرن وقابل للتوسع بدرجة عالية. عادةً ما يُستخدم syslog-ng OSE لإدارة رسائل السجل وتنفيذ تسجيل مركزي، حيث الهدف هو جمع رسائل السجل من عدة أجهزة على خادم سجل مركزي واحد. تعمل الأجهزة المختلفة - المسماة عملاء syslog-ng OSE - على تشغيل syslog-ng OSE، وتقوم بجمع رسائل السجل من التطبيقات والملفات والمصادر الأخرى المختلفة. ترسل العملاء جميع رسائل السجل الهامة إلى خادم syslog-ng OSE PE البعيد، حيث يقوم الخادم بفرزها وتخزينها.

المفاهيم الأساسية لـ syslog-ng OSE

يقرأ تطبيق syslog-ng OSE الرسائل الواردة ويعيد توجيهها إلى الوجهات المحددة. يمكن لتطبيق syslog-ng OSE استقبال الرسائل من الملفات والمضيفين البعيدين والمصادر الأخرى.

تدخل رسائل السجل إلى syslog-ng OSE في أحد المصادر المحددة، ويتم إرسالها إلى وجهة واحدة أو أكثر.

المصادر والوجهات هي كائنات مستقلة، تحدد مسارات السجل ما يفعله syslog-ng OSE بالرسالة، وتربط المصادر بالوجهات. يتكون مسار السجل من مصدر واحد أو أكثر ووجهة واحدة أو أكثر: يتم إرسال الرسائل الواردة من مصدر إلى كل وجهة مدرجة في مسار السجل. يسمى مسار السجل المحدد في syslog-ng OSE بعبارة سجل.

اختياريًا، يمكن لمسارات السجل أن تتضمن مرشحات. المرشحات هي قواعد تحدد فقط رسائل معينة، على سبيل المثال، تحديد الرسائل المرسلة فقط بواسطة تطبيق معين. إذا تضمن مسار السجل مرشحات، يرسل syslog-ng OSE فقط الرسائل التي تتوافق مع قواعد المرشح إلى الوجهات المحددة في مسار السجل.

تشمل العناصر الاختيارية الأخرى التي يمكن أن تظهر في عبارات السجل المحللات وقواعد إعادة الكتابة. تقوم المحللات بتقسيم الرسائل إلى حقول مختلفة للمساعدة في معالجة الرسائل، بينما تقوم قواعد إعادة الكتابة بتعديل الرسائل عن طريق إضافة أجزاء من الرسائل أو استبدالها أو إزالتها.

تكوين syslog-ng OSE

•
يتكون الجسم الرئيسي لملف التكوين من تعريفات الكائنات: تحدد المصادر والوجهات ومسارات السجل الرسائل التي يتم استقبالها وأين يتم إرسالها. جميع المعرفات، وأسماء الخيارات والسمات، وأي سلاسل نصية أخرى مستخدمة في ملف تكوين syslog-ng OSE حساسة لحالة الأحرف. تعريفات الكائنات (تسمى أيضًا عبارات) لها الصيغة التالية:
type-of-the-object identifier-of-the-object {<parameters>};
  • نوع الكائن: واحد من source، destination، log، filter، parser، rewrite rule، أو template.
  • معرف الكائن: اسم فريد يحدد الكائن. عند استخدام كلمة محجوزة كمعرف، قم بتضمين المعرف بين علامتي اقتباس (\"\").

جميع المعرفات والسمات وأي سلاسل نصية أخرى مستخدمة في ملف تكوين syslog-ng OSE حساسة لحالة الأحرف.

نصيحة: استخدم معرفات تشير إلى نوع الكائن الذي تحدده. على سبيل المثال، قم ببادئة كائنات المصدر بـ s_، والوجهات بـ d_، وما إلى ذلك.

ملاحظة: تكرار تعريف كائن (أي، تعريف نفس الكائن بنفس المعرف أكثر من مرة) غير مسموح به، إلا إذا كنت تستخدم التعريف @define allow-config-dups 1 في ملف التكوين. - المعلمات: معلمات الكائن، محاطة بأقواس {parameters}. - فاصلة منقوطة: تنتهي تعريفات الكائنات بفاصلة منقوطة (;).

على سبيل المثال، السطر التالي يعرّف مصدرًا ويسميه s_internal.

source s_internal { internal(); };

يمكن الإشارة إلى الكائن لاحقًا في عبارات أخرى باستخدام معرفه، على سبيل المثال، يتم استخدام المصدر السابق كمعلمة لعبارة السجل التالية:

log { source(s_internal); destination(d_file); };
•
المعلمات والخيارات داخل عبارة تشبه استدعاءات الدوال في لغة C: اسم الخيار متبوعًا بقائمة معالمه محاطة بأقواس ومنتهية بفاصلة منقوطة.
option(parameter1, parameter2); option2(parameter1, parameter2);

على سبيل المثال، برنامج تشغيل الملف() في عبارة المصدر التالية لديه ثلاثة خيارات: اسم الملف (/var/log/apache/access.log)، follow-freq()، و flags(). برنامج تشغيل follow-freq() لديه أيضًا معلمة، بينما برنامج تشغيل flags() لديه معلمتين.

source s_tail { file("/var/log/apache/access.log"
follow-freq(1) flags(no-parse, validate-utf8)); };

قد تحتوي الكائنات على معلمات مطلوبة واختيارية. المعلمات المطلوبة موضعية، مما يعني أنه يجب تحديدها بترتيب محدد. يمكن تحديد المعلمات الاختيارية بأي ترتيب باستخدام تنسيق option(value). إذا لم يتم تحديد معلمة (اختيارية أو مطلوبة)، يتم استخدام قيمتها الافتراضية. يتم سرد المعلمات وقيمها الافتراضية في قسم المرجع للكائن المحدد.

مثال: استخدام المعلمات المطلوبة والاختيارية

برنامج تشغيل المصدر unix-stream() لديه وسيط مطلوب واحد: اسم المقبس للاستماع عليه. المعلمات الاختيارية تتبع اسم المقبس بأي ترتيب، لذا فإن تعريفات المصادر التالية لها نفس التأثير:

source s_demo_stream1 {
    unix-stream("<path-to-socket>" 
    max-connections(10) group(log)); 
};
source s_demo_stream2 {
    unix-stream("<path-to-socket>" 
    group(log) max-connections(10)); 
};
•
بعض الخيارات هي خيارات عامة، أو يمكن تعيينها بشكل عام، على سبيل المثال، ما إذا كان syslog-ng OSE يجب أن يستخدم تحليل DNS لحل عناوين IP.
options { use-dns(no); };
  • يمكن استخدام الكائنات قبل تعريفها.
  • يمكن تعريف الكائنات في نفس السطر أيضًا. هذا مفيد إذا كنت تستخدم الكائن مرة واحدة فقط (على سبيل المثال، مرشح).
  • لإضافة تعليقات إلى ملف التكوين، ابدأ سطرًا بـ # واكتب تعليقاتك. يتم تجاهل هذه الأسطر بواسطة syslog-ng OSE.
# تعليق: هذا مصدر دفق
source s_demo_stream {
unix-stream("<path-to-socket>" max-connections(10) group(log)); };

صيغة عبارات السجل هي كما يلي:

log {
    source(s1); source(s2); ...
    optional_element(filter1|parser1|rewrite1);
    optional_element(filter2|parser2|rewrite2);
    ...
    destination(d1); destination(d2); ...
    flags(flag1[, flag2...]);
};

عبارة السجل التالية ترسل جميع الرسائل الواردة إلى المضيف المحلي إلى خادم بعيد.

source s_localhost { network(ip(127.0.0.1) port(1999)); };
destination d_tcp { network("10.1.2.3" port(1999) localport(999)); };
log { source(s_localhost); destination(d_tcp); };

يحتوي تطبيق syslog-ng OSE على عدد من الخيارات العامة التي تحكم استخدام DNS، وتنسيق الطابع الزمني المستخدم، ونقاط أخرى عامة. قد يحتوي كل خيار على معلمات، بشكل مشابه لمواصفات برامج التشغيل. لتعيين الخيارات العامة، أضف عبارة خيارات إلى ملف تكوين syslog-ng OSE باستخدام الصيغة التالية:

options { option1(params); option2(params); ... };

مثال: استخدام الخيارات العامة

لتعطيل تحليل أسماء النطاقات، أضف السطر التالي إلى ملف تكوين syslog-ng OSE:

options { use-dns(no); };

المصادر والوجهات والمرشحات المتاحة في syslog-ng OSE مدرجة أدناه.

NAME

syslog-ng.conf — syslog-ng OSE configuration file

Synopsis

/etc/syslog-ng/syslog-ng.conf

Description

The syslog-ng OSE application is an enhanced log-monitoring program which can apply complex filtering and transformation rules to log messages. The behavior of syslog-ng OSE is configured by the configuration file, usually located in /etc/syslog-ng/syslog-ng.conf.

This manual page describes the configuration file syntax and provides a quick reference for the available drivers and filter functions.

For a detailed description of syslog-ng OSE features and configuration options, refer to the syslog-ng OSE Administration Guide[1].

Basic concepts of syslog-ng OSE

The configuration file consists of the following parts:

Sources
Sources define where syslog-ng OSE collects messages from. Examples include local files (like /proc/kmsg or /var/log/messages), network sockets (UDP, TCP, TLS), or other applications.
Destinations
Destinations define where syslog-ng OSE sends processed messages to. Examples include local files, remote syslog servers, databases, or other applications.
Filters
Filters define conditions that log messages must meet to be processed by certain rules. Filters can match messages based on their content, source, priority, facility, etc.
Log paths
Log paths define the flow of messages from one or more sources, through optional filters, to one or more destinations. A log path specifies which sources, filters, and destinations are connected.

Configuring syslog-ng OSE

The syslog-ng OSE configuration file consists of statements that define sources, destinations, filters, and log paths. The configuration file is parsed sequentially, and directives are processed in the order they appear.

A typical configuration file structure looks like this:

    @version: 3.36
    @include "scl.conf"

    options { ... };

    source s_local { ... };
    source s_network { ... };

    destination d_file { ... };
    destination d_remote { ... };

    filter f_error { ... };

    log {
        source(s_local);
        source(s_network);
        filter(f_error);
        destination(d_file);
        destination(d_remote);
    };

The @version directive specifies the configuration file version. The @include directive allows including other configuration files.

The options { ... }; block configures global options for syslog-ng OSE.

Sources, destinations, and filters are defined using their respective keywords, followed by a name and a block containing configuration parameters. Log paths are defined using the log { ... }; block, specifying the sources, filters, and destinations involved.
