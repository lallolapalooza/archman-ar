الاسم

syncthing-config - إعداد Syncthing

نظرة عامة

تغطي هذه الصفحة كيفية إعداد Syncthing لمزامنة الملفات، بما في ذلك إعداد الأجهزة، وتكوين المجلدات، وإعدادات الاتصال، وطرق التكوين المختلفة من خلال واجهة المستخدم الرسومية على الويب، أو سطر الأوامر، أو تحرير الملف مباشرة.

مواقع ملفات التكوين

المواقع الافتراضية لملفات التكوين وقاعدة البيانات هي:

$XDG_STATE_HOME/syncthing
$HOME/.local/state/syncthing
$HOME/Library/Application Support/Syncthing
%LOCALAPPDATA%\Syncthing

الوصف

تم التغيير في الإصدار 1.27.0: تم تغيير الموقع الافتراضي لملف التكوين وقاعدة البيانات على الأنظمة الشبيهة بـ Unix إلى $XDG_STATE_HOME/syncthing أو $HOME/.local/state/syncthing. سابقًا، كان موقع التكوين الافتراضي هو $XDG_CONFIG_HOME/syncthing أو $HOME/.config/syncthing. سابقًا، كانت قاعدة البيانات تقع في $HOME/.config/syncthing أو، إذا تم تعيين متغير البيئة، $XDG_DATA_HOME/syncthing. قد تستخدم التركيبات الحالية هذه الدلائل بدلاً من الافتراضيات الأحدث.

تم الإضافة في الإصدار 1.5.0: يمكن الآن تعيين قاعدة البيانات والتكوين بشكل منفصل. سابقًا، كانت قاعدة البيانات دائمًا تقع في نفس الدليل الذي يوجد به التكوين.

يستخدم Syncthing دليلًا واحدًا لتخزين التكوين والمفاتيح المشفرة. يحتفظ Syncthing أيضًا بقاعدة بيانات فهرسة تحتوي على بيانات تعريف الملفات، والتي يتم تخزينها بشكل افتراضي في نفس الدليل، على الرغم من أنه يمكن تجاوز ذلك.

يتم تعيين الموقع افتراضيًا إلى $XDG_STATE_HOME/syncthing أو $HOME/.local/state/syncthing (شبيه بـ Unix)، $HOME/Library/Application Support/Syncthing (Mac)، أو %LOCALAPPDATA%\Syncthing (Windows). يمكن تغييره أثناء وقت التشغيل باستخدام علامتي --config أو --home أو متغيرات البيئة المقابلة ($STCONFDIR أو STHOMEDIR). توجد الملفات التالية في هذا الدليل:

config.xml
ملف التكوين، بصيغة XML.
cert.pem، key.pem
المفتاح العام والخاص لجهاز ECDSA. يشكلان أساس معرف الجهاز. يجب الحفاظ على سرية المفتاح.
https-cert.pem، https-key.pem
الشهادة والمفتاح لاتصالات واجهة المستخدم الرسومية HTTPS. يمكن استبدالها بشهادة مخصصة لـ HTTPS حسب الرغبة.

يتم تخزين قاعدة البيانات افتراضيًا في نفس الدليل الذي يوجد به التكوين، ولكن يمكن تجاوز موقعها باستخدام علامتي --data أو --home أو متغيرات البيئة المقابلة ($STDATADIR أو STHOMEDIR).

يحتوي دليل قاعدة البيانات على الملفات التالية، من بين أمور أخرى:

index-*
قاعدة البيانات التي تحتوي على بيانات التعريف والتجزئات للملفات الموجودة حاليًا على القرص والمتوفرة من الأقران.
syncthing.log
مخرجات السجل، في بعض الأنظمة.
audit-*.log
بيانات سجل التدقيق، عند تمكينها.
panic-*.log
بيانات سجل الأعطال، عند الضرورة.

Multiple ignored folders are represented by repeated <ignoredFolder> tags in the configuration file.

maxRequestKiB
أقصى كمية من البيانات لتكون معلقة في الطلبات لهذا الجهاز. الوحدة هي الكيبيبايت.
remoteGUIPort
إذا تم ضبطه على عدد صحيح موجب، ستعرض واجهة المستخدم الرسومية رابط HTTP لعنوان IP المستخدم حاليًا للمزامنة. فقط منفذ TCP يتم استبداله بالقيمة المحددة هنا. لاحظ أن أي إعادة توجيه للمنافذ أو إعدادات جدار الحماية تحتاج إلى القيام بها يدويًا ومن المحتمل أن الرابط لن يعمل لعناوين IPv6 المحلية للقرب بسبب القيود الحديثة للمتصفح.
untrusted
هذه القيمة المنطقية تحدد جهازًا معينًا على أنه غير موثوق به، مما يمنع مشاركة أي بيانات غير مشفرة معه على الإطلاق. يجب بعد ذلك تعيين كلمة مرور تشفير لكل مجلد مشترك مع هذا الجهاز، أو يجب أن يكون بالفعل من نوع "استقبال مشفر" محليًا. ارجع إلى الشرح التفصيلي تحت الأجهزة غير الموثوق بها (المشفرة).
numConnections
عدد الاتصالات بهذا الجهاز. انظر numConnections لمزيد من المعلومات.

عنصر واجهة المستخدم الرسومية (GUI)

<gui enabled="true" tls="false">
    <address>127.0.0.1:8384</address>
    <apikey>k1dnz1Dd0rzTBjjFFh7CXPnrF12C49B1</apikey>
    <theme>default</theme>
</gui>

يجب أن يكون هناك عنصر gui واحد بالضبط. يتم استخدام تكوين واجهة المستخدم الرسومية أيضًا بواسطة واجهة برمجة تطبيقات REST و واجهة برمجة تطبيقات الأحداث. يمكن ضبط السمات التالية على عنصر gui:

enabled
إذا لم يكن true، فلن يتم تشغيل واجهة المستخدم الرسومية وواجهة برمجة التطبيقات.
tls
إذا تم ضبطه على true، فسيتم فرض TLS (HTTPS). سيتم إعادة توجيه الطلبات غير HTTPS إلى HTTPS. عند ضبطه على false، تظل اتصالات TLS ممكنة ولكنها ليست مطلوبة.

يمكن أن تكون العناصر الفرعية التالية موجودة:

address (إلزامي: يجب وجود عنصر واحد بالضبط.)
ضبط عنوان الاستماع. تنسيقات العنوان المسموح بها هي:
عنوان ومنفذ IPv4 (127.0.0.1:8384)
يتم استخدام العنوان والمنفذ كما هو معطى.
عنوان ومنفذ IPv6 ([::1]:8384)
يتم استخدام العنوان والمنفذ كما هو معطى. يجب إحاطة العنوان بأقواس مربعة.
عنوان عام ومنفذ (0.0.0.0:12345، [::]:12345، :12345)
هذه مكافئة وستؤدي إلى استماع Syncthing على جميع الواجهات عبر IPv4 و IPv6.
موقع مقبس UNIX (/var/run/st.sock)
إذا كان العنوان مسارًا مطلقًا، فسيتم تفسيره على أنه المسار إلى مقبس UNIX.
unixSocketPermissions
عندما يتم ضبط address على موقع مقبس UNIX، قم بضبط هذا على قيمة ثمانية لتجاوز الأذونات الافتراضية للمقبس.
user
تم ضبطه لطلب المصادقة.
password
يحتوي على تجزئة bcrypt لكلمة المرور الحقيقية.
apikey
إذا تم ضبطه، فهذه هي مفتاح API الذي يمكّن استخدام واجهة REST.
insecureAdminAccess
إذا كان صحيحًا، فهذا يسمح بالوصول إلى واجهة المستخدم الرسومية للويب من الخارج (أي ليس localhost) بدون تفويض. سيتم عرض تحذير بشأن هذا الإعداد عند بدء التشغيل.
insecureSkipHostcheck
عند ربط واجهة المستخدم الرسومية / واجهة برمجة التطبيقات بـ localhost، نطبق أن رأس Host يبدو مثل localhost. يتجاوز هذا الخيار هذا الفحص.
insecureAllowFrameLoading
اسمح بعرض واجهة المستخدم الرسومية داخل <iframe> أو <frame> أو <object> عن طريق عدم تعيين رأس HTTP X-Frame-Options: SAMEORIGIN. قد يكون هذا ضروريًا لخدمة واجهة المستخدم الرسومية لـ Syncthing كجزء من موقع ويب عبر وكيل.
theme
اسم السمة المراد استخدامها.
authMode
وضع المصادقة المراد استخدامه. إذا لم يكن موجودًا، يتم التحكم في وضع المصادقة (ثابت) بواسطة وجود حقول المستخدم / كلمة المرور للتوافق مع الإصدارات السابقة.
static
المصادقة باستخدام اسم المستخدم وكلمة المرور.
ldap
مصادقة LDAP. يتطلب قسم تكوين LDAP العلوي أن يكون موجودًا.
sendBasicAuthPrompt
تمت إضافته في الإصدار 1.26.0.

قبل الإصدار 1.26.0، استخدمت واجهة المستخدم الرسومية مصادقة HTTP الأساسية لتسجيل الدخول، ولكن بدءًا من الإصدار 1.26.0، استخدمت نموذج HTML بشكل افتراضي. لا تزال المصادقة الأساسية مدعومة عندما يكون رأس طلب Authorization موجودًا في طلب، ولكن بعض المتصفحات لا ترسل الرأس ما لم يتم المطالبة به باستجابة 401.

عند تمكين هذا الإعداد، سترد واجهة المستخدم الرسومية على الطلبات غير المصادق عليها باستجابة 401 تطالب بالمصادقة الأساسية، بحيث تستمر عناوين URL من نوع https://user:pass@localhost في العمل في المتصفحات القياسية. لا تحتاج العميلات الأخرى التي ترسل دائمًا رأس طلب Authorization إلى هذا الإعداد.

عند تعطيل هذا الإعداد، لن ترسل واجهة المستخدم الرسومية استجابات 401، لذا لن يرى المستخدمون نوافذ منبثقة للمتصفح تطالب باسم المستخدم وكلمة المرور.

metricsWithoutAuth
إذا كان صحيحًا، فهذا يسمح بالوصول إلى "/metrics" بدون مصادقة.

NETWORK OPTIONS





  
alwaysLocalNet

  
If set, Syncthing will always announce itself on the local network,
      even if it believes it has a public IP address. This can be used to bypass
      detection issues or to ensure discoverability on networks where the
      automatic detection might fail. This is useful for connecting devices
      that are not able to reach each other through the internet but are on the
      same LAN. Note that you can use multiple
      <alwaysLocalNet> tags in the configuration file or enter
      several networks separated by commas in the GUI.









  
overwriteRemoteDeviceNamesOnConnect

  
If set, device names will always be overwritten with the name given by
      remote on each connection. By default, the name that the remote device
      announces will only be adopted when a name has not already been set.









  
tempIndexMinBlocks

  
When exchanging index information for incomplete transfers, only take into
      account files that have at least this many blocks.









  
unackedNotificationID

  
ID of a notification to be displayed in the web GUI. Will be removed once
      the user acknowledged it (e.g. a transition notice on an upgrade).
      Multiple IDs are represented by repeated
      <unackedNotificationID> tags in the configuration file.









  
trafficClass

  
Specify an IPv4 type of service (TOS)/IPv6 traffic class for outgoing
      packets. To specify a differentiated services code point (DSCP) the value
      must be bit shifted to the left by two to take the two least significant
      ECN bits into account.









  
stunServer

  
Server to use for STUN, given as ip:port. The keyword default gets
      expanded to a set of public STUN servers, with preference given to those
      hosted by the Syncthing project.
    
To configure multiple servers, you can either: repeat
        <stunServer> tags in the configuration file or enter
        several servers separated by commas in the GUI.

  









  
stunKeepaliveStartS

  
Interval in seconds between contacting a STUN server to maintain NAT
      mapping. Default is 180 and you can set it to 0 to disable
      contacting STUN servers. The interval is automatically reduced if needed,
      down to a minimum of stunKeepaliveMinS.









  
stunKeepaliveMinS

  
Minimum for the stunKeepaliveStartS interval, in seconds.









  
setLowPriority

  
Syncthing will attempt to lower its process priority at startup.
      Specifically: on Linux, set itself to a separate process group, set the
      niceness level of that process group to nine and the I/O priority to best
      effort level five; on other Unixes, set the process niceness level to
      nine; on Windows, set the process priority class to below normal. To
      disable this behavior, for example to control process priority yourself as
      part of launching Syncthing, set this option to false.









  
maxFolderConcurrency

  
This option controls how many folders may concurrently be in I/O-intensive
      operations such as syncing or scanning. The mechanism is described in
      detail in a separate chapter.









  
crashReportingURL

  
Server URL where automatic crash reports will be sent if
    enabled.









  
crashReportingEnabled

  
Switch to opt out from the automatic crash reporting feature. Set
      false to keep Syncthing from sending panic logs on serious
      troubles. Defaults to true, to help the developers
    troubleshoot.









  
maxConcurrentIncomingRequestKiB

  
This limits how many bytes we have “in the air” in the form
      of response data being read and processed.









  
announceLANAddresses

  
Enable (the default) or disable announcing private (RFC1918) LAN IP
      addresses to global discovery.









  
sendFullIndexOnUpgrade

  
Controls whether all index data is resent when an upgrade has happened,
      equivalent to starting Syncthing with --reset-deltas. This used to
      be the default behavior in older versions, but is mainly useful as a
      troubleshooting step and causes high database churn. The default is now
      false.









  
featureFlag

  
Feature flags are simple strings that, when added to the configuration,
      may unleash unfinished or still-in-development features to allow early
      user testing. Any supported value will be separately announced with the
      feature, so that regular users do not enable it by accident. To configure
      multiple flags, you can either: repeat <featureFlag> tags in
      the configuration file or enter several flags separated by commas in the
      GUI.









  
connectionLimitEnough

  
The number of connections at which we stop trying to connect to more
      devices, zero meaning no limit. Does not affect incoming connections. The
      mechanism is described in detail in a separate chapter.









  
connectionLimitMax

  
The maximum number of connections which we will allow in total, zero
      meaning no limit. Affects incoming connections and prevents attempting
      outgoing connections. The mechanism is described in detail in a
      separate chapter.









  
auditEnabled

  
When true, analogous to --audit being set. Defaults to
      false.
    
When either this option, or --audit (or both) are
        enabled, auditing is enabled.

  









  
auditFile

  
Analogous to --auditfile. Defaults to being unset.
    
For compatibility reasons, if both this option and
        --auditfile are set, --auditfile takes priority.

The defaults element describes a template for newly added
    device and folder options. These will be used when adding a new remote
    device or folder, either through the GUI or the command line interface. The
    following child elements can be present in the defaults element:





  
device

  
Template for a device element, with the same internal structure.
      Any fields here will be used for a newly added remote device. The
      id attribute is meaningless in this context.









  
folder

  
Template for a folder element, with the same internal structure.
      Any fields here will be used for a newly added folder. The id
      attribute is meaningless in this context.









  
ignores

  
Template for the ignores element, with the same internal
      structure. Any ignored patterns specified here will be copied to a new
      folder.
