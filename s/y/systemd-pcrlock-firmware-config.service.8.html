SYSTEMD-PCRLOCK(8) systemd-pcrlock SYSTEMD-PCRLOCK(8)

الاسم

systemd-pcrlock, systemd-pcrlock-file-system.service, systemd-pcrlock-firmware-code.service, systemd-pcrlock-firmware-config.service, systemd-pcrlock-machine-id.service, systemd-pcrlock-make-policy.service, systemd-pcrlock-secureboot-authority.service, systemd-pcrlock-secureboot-policy.service - تحليل وتوقع حالات TPM2 PCR وإنشاء سياسة وصول من التوقع

الملخص

/usr/lib/systemd/systemd-pcrlock [خيارات...]

الوصف

ملاحظة: هذه الأداة تجريبية حاليًا. على الرغم من أنها من المرجح أن تصبح جزءًا منتظمًا من systemd، إلا أنها قد تتغير في السلوك والواجهة.

systemd-pcrlock هي أداة يمكن استخدامها لتحليل وتوقع قياسات TPM2 PCR، وإنشاء سياسات وصول TPM2 من التوقع التي تخزنها في مؤشر NV الخاص بـ TPM2 (أي في الذاكرة غير المتطايرة لـ TPM2). يمكن بعد ذلك استخدام هذا لتقييد الوصول إلى كائنات TPM2 (مثل مفاتيح تشفير القرص) إلى عمليات تمهيد النظام التي يتم فيها استخدام مكونات محددة وموثوقة فقط.

يستخدم systemd-pcrlock كمدخلات لتحليله وتوقعه:

•؛ سجل أحداث UEFI firmware TPM2 (أي /sys/kernel/security/tpm0/binary_bios_measurements) لعملية التمهيد الحالية.
•؛ سجل أحداث TPM2 في مساحة المستخدم (أي /run/log/systemd/tpm2-measure.log) لعملية التمهيد الحالية.
•؛ حالة PCR الحالية لشريحة TPM2.
•؛ ملفات تعريف مكونات التمهيد (*.pcrlock و *.pcrlock.d/*.pcrlock، انظر systemd.pcrlock(5)) والتي تحدد كل منها القياسات المتوقعة لمكون واحد من عملية التمهيد، مما يسمح بوجود متغيرات بديلة لكل منها. (يمكن استخدام المتغيرات لتفويض إصدارات متعددة من النواة أو محمل التمهيد في نفس الوقت.)

يستخدم هذه المدخلات لإنشاء سجل أحداث مدمج، والتحقق منه مقابل قيم PCR الحالية. ثم يحاول التعرف على سجلات أحداث القياس ومطابقتها مع المكونات المحددة. لكل PCR يمكن القيام بذلك بشكل شامل (أي حيث تمت مطابقة جميع السجلات المدرجة وجميع المكونات المحددة) يمكن بعد ذلك استخدامه للتنبؤ بقياسات PCR المستقبلية، مع مراعاة المتغيرات البديلة المحددة لكل مكون. يمكن بعد ذلك تحويل هذا التوقع إلى سياسة وصول TPM2 (تتكون من عناصر TPM2 PolicyPCR و PolicyOR)، والتي يتم تخزينها بعد ذلك في مؤشر NV في TPM2. يمكن استخدام هذا لقفل الأسرار (مثل مفاتيح تشفير القرص) لهذه السياسات (عبر سياسة TPM2 PolicyAuthorizeNV).

استخدم أدوات مثل systemd-cryptenroll(1) أو systemd-repart(8) لربط تشفير القرص بسياسة TPM2 systemd-pcrlock كهذه. على وجه التحديد، انظر المفاتيح --tpm2-pcrlock= لهذه الأدوات.

يتطلب منطق سياسة الوصول جهاز TPM2 الذي ينفذ الأمر "PolicyAuthorizeNV"، أي ينفذ TPM 2.0 الإصدار 1.38 أو أحدث.

الأوامر

تُفهم الأوامر التالية:

log

تقوم هذه القراءة بقراءة سجل أحداث TPM2 المدمج، والتحقق منه، ومطابقته مع قيم PCR الحالية، وإخراج كلاهما في شكل جدول. قم بالجمع مع --json= لتوليد إخراج بتنسيق JSON.

تمت الإضافة في الإصدار 255.

cel

تقوم هذه القراءة بقراءة سجل أحداث TPM2 المدمج وكتابته إلى STDOUT بتنسيق TCG Canonical Event Log Format (CEL-JSON)[1].

تمت الإضافة في الإصدار 255.

list-components

تعرض قائمة بتعريفات المكونات والمتغيرات الخاصة بها، أي ملفات *.pcrlock التي تم اكتشافها في /var/lib/pcrlock.d/، /usr/lib/pcrlock.d/، والدلائل الأخرى المدعومة. انظر systemd.pcrlock(5) للحصول على تفاصيل حول هذه الملفات والقائمة الكاملة للدلائل التي يتم البحث فيها.

تمت الإضافة في الإصدار 255.

predict

تتوقع حالة PCR في عمليات التمهيد المستقبلية. سيقوم هذا بتحليل سجل أحداث TPM2 كما هو موضح أعلاه، والتعرف على المكونات، ثم توليد جميع قيم PCR الناتجة الممكنة لجميع مجموعات متغيرات المكونات. لاحظ أنه لا يتم إجراء أي توقع لـ PCRs التي لا تتطابق قيمتها مع سجلات أحداث القياس، أو التي يتم اكتشاف قياسات غير معروفة لها، أو التي توجد لها مكونات محددة لا يمكن العثور عليها في سجل الأحداث. هذا إجراء سلامة لضمان أنه يمكن تلبية سياسة الوصول التي تم إنشاؤها بشكل صحيح في عمليات التمهيد الحالية والمستقبلية.

تمت الإضافة في الإصدار 255.

make-policy

تقوم هذه التنبؤ بحالة PCR لعمليات التمهيد المستقبلية، بشكل مشابه لأمر predict أعلاه. ثم تستخدم هذه البيانات لإنشاء سياسة وصول TPM2 التي تخزنها في مؤشر NV الخاص بـ TPM2. يتم كتابة التوقع والمعلومات حول TPM2 المستخدم ومؤشر NV الخاص به إلى /var/lib/systemd/pcrlock.json.

يتم تخصيص مؤشر NV عند الاستدعاء الأول، ويتم تحديثه عند الاستدعاءات اللاحقة.

يمكن تغيير محتويات مؤشر NV (وبالتالي تحديث السياسة المخزنة فيه) عن طريق توفير رقم PIN وصول. يتم إنشاء رقم PIN هذا عادةً تلقائيًا وتخزينه بتنسيق مشفر (مع سياسة وصول تربطه بمؤشر NV نفسه) في ملف السياسة JSON المذكور أعلاه. يمكن اختيار رقم PIN هذا من قبل المستخدم، عبر المفتاح --recovery-pin=. إذا تم تحديده، يمكن استخدامه كمسار وصول بديل لتحديث السياسة.

إذا تطابق التوقع الجديد مع القديم، ينتهي هذا الأمر بسرعة ولا ينفذ أي عملية أخرى. (ما لم يتم تحديد --force، انظر أدناه.)

بدءًا من الإصدار 256، يتم تشفير نسخة من ملف السياسة /var/lib/systemd/pcrlock.json في بيانات اعتماد (انظر systemd-creds(1) للتفاصيل) ويتم كتابتها إلى قسم EFI System Partition أو قسم XBOOTLDR، في الدليل الفرعي /loader/credentials/. هناك يتم التقاطها عند التمهيد بواسطة systemd-stub(7) وتمريرها إلى initrd المستدعى، حيث يمكن استخدامها لفتح نظام الملفات الجذري (الذي يحتوي عادةً على /var/، وهو المكان الذي يوجد فيه النسخة الأساسية من السياسة، والتي بالتالي لا يمكن استخدامها لفتح نظام الملفات الجذري). يتم تسمية ملف بيانات الاعتماد باسم رمز إدخال التمهيد للتثبيت (انظر bootctl(1))، والذي يمكن تكوينه عبر المفتاح --entry-token=، انظر أدناه.

تمت الإضافة في الإصدار 255.

remove-policy

يزيل سياسة تم إنشاؤها مسبقًا. يحذف ملف /var/lib/systemd/pcrlock.json، ويزيل تخصيص مؤشر NV.

تمت الإضافة في الإصدار 255.

is-supported

يتحقق مما إذا كان TPM2 المحلي يدعم جميع الوظائف لكي يعمل systemd-pcrlock بشكل صحيح. يقوم هذا بإجراء اختبارات مماثلة لاختبارات systemd-analyze has-tpm2، ولكنه يتحقق أيضًا من دعم عمليات TPM2 المطلوبة بواسطة systemd-pcrlock. يقوم بإخراج أحد الخيارات التالية: "no"، "partial" (في حالة توفر بعض أجزاء دعم TPM2 في الأجهزة، البرنامج الثابت، نظام التشغيل، ولكن ليس بشكل كامل)، "obsolete" (إذا كان دعم TPM2 متاحًا في الأجهزة، البرنامج الثابت، ونظام التشغيل، ولكن العمليات المطلوبة لـ systemd-pcrlock مفقودة)، "yes". يعيد حالة خروج صفر إذا كان الدعم الكامل متاحًا، وإلا فهو غير صفري.

إذا تم الجمع مع --quiet، يتم كتم صوت إخراج السلسلة النصية.

حاليًا، يتحقق هذا من دعم الأمر PolicAuthorizeNV الخاص بـ TPM2، وكذلك من دعم خوارزمية التجزئة SHA-256.

تمت الإضافة في الإصدار 258.

lock-firmware-code, unlock-firmware-code

يقوم بإنشاء/إزالة ملفات .pcrlock بناءً على سجل أحداث TPM2 لعملية التمهيد الحالية التي تغطي جميع السجلات الخاصة بـ PCRs 0 ("platform-code") و 2 ("external-code").

تسمح هذه العملية بقفل عملية التمهيد إلى الإصدار الحالي من البرنامج الثابت للنظام وبطاقات التوسعة الخاصة به. يجب استخدام هذه العملية فقط إذا لم يوفر بائع النظام بيانات pcrlock مناسبة مسبقًا.

لاحظ أن هذه البيانات تتطابق فقط مع الإصدار الحالي من البرنامج الثابت. إذا تم تطبيق تحديث للبرنامج الثابت، فستصبح هذه البيانات قديمة ولن تمر أي سياسة وصول تم إنشاؤها منها. لذلك يوصى باستدعاء unlock-firmware-code قبل إجراء تحديث للبرنامج الثابت، يليه make-policy لتحديث السياسة.

يتم استدعاء systemd-pcrlock lock-firmware-code تلقائيًا عند التمهيد عبر الوحدة systemd-pcrlock-firmware-code.service، إذا تم تمكينها. يضمن هذا قفل سياسة الوصول التي تديرها systemd-pcrlock تلقائيًا للإصدار الجديد من البرنامج الثابت كلما تم تحديث poli

systemd-pcrlock-firmware-config.service(8)

NAME

systemd-pcrlock-firmware-config.service, systemd-pcrlock - Implement TPM PCR value based system integrity measurement

SYNOPSIS

systemd-pcrlock-firmware-config.service

DESCRIPTION

The systemd-pcrlock-firmware-config.service service is a oneshot service that is activated early in the boot process. It reads the firmware PCR measurement values from the TPM and uses them to unlock the system's disk encryption using TPM PCR values. It is implemented as a systemd service that internally invokes systemd-pcrlock.

The systemd-pcrlock utility provides functionality to define and manage access policies for TPM NVRAM indices that are protected by PCR values. This allows system integrity measurements to be used to unlock sensitive data or features. The service ensures that the necessary PCR values are loaded and used to unlock the relevant TPM NV index, thereby enabling disk decryption or other security-sensitive operations.

The primary use case is to unlock a LUKS encrypted root filesystem or other sensitive data stores that have been configured to be unlocked by TPM PCR values. This ensures that the system can only be booted if the measured boot components (firmware, bootloader, kernel, initrd, etc.) match the expected integrity measurements.

The systemd unit file for this service is located at /usr/lib/systemd/system/systemd-pcrlock-firmware-config.service. It depends on the availability of the TPM and the correct configuration of PCR measurements.

COMMANDS

The following commands are available when using the systemd-pcrlock utility:

make-policy
Creates a new PCR lock policy. This command needs to be run with root privileges. It reads the current PCR values from the TPM and stores them as the policy. This policy can then be used to unlock the NV index later. A PIN may be specified to protect the NV index. If no PIN is provided, a random PIN is generated and displayed.
lock-nv
Locks an NV index using a previously created PCR lock policy. This command requires the NV index, the policy file, and optionally a PIN. It associates the PCR values defined in the policy with the NV index. This command must be run with root privileges.
unlock-nv
Unlocks an NV index using the current PCR values. This command requires the NV index, the policy file, and optionally a PIN. If the current PCR values match the policy and the correct PIN is provided, the NV index is unlocked, allowing write access. This command is typically used by the systemd service during boot.
show-policy
Displays the contents of a PCR lock policy file.
is-supported
Checks if the system's TPM and firmware support the necessary features for PCR locking.

OPTIONS

The systemd-pcrlock utility accepts the following options:

--pin=

Takes a PIN as argument. This PIN is used to lock and unlock the TPM2 NV index. If no PIN is specified when creating a policy (e.g. with make-policy), a random PIN is generated. This PIN is stored in encrypted form in the policy metadata file. The PIN can be used to regain write access to the NV index if the access policy becomes out of date.

Added in version 255.

--pcrlock=

Takes a file system path as argument. If specified, configures where to write the generated pcrlock data to. Honoured by the various lock-* commands. If not specified, a default path is generally used, as documented above.

Added in version 255.

--policy=

Takes a file system path as argument. If specified, configures where to write pcrlock policy metadata to. If not specified, defaults to /var/lib/systemd/pcrlock.json.

Added in version 255.

--force

If specified with make-policy, the predicted policy will be written to the NV index even if it is detected to be the same as the previously stored one.

Added in version 255.

--entry-token=

Sets the boot entry token to use for the file name for the pcrlock policy credential in the EFI System Partition or XBOOTLDR partition. See the bootctl(1) option of the same regarding expected values. This switch has an effect on the make-policy command only.

Added in version 256.

--quiet

If specified suppresses output when invoked for is-supported.

Added in version 258.

--json=MODE

Shows output formatted as JSON. Expects one of "short" (for the shortest possible output without any redundant whitespace or line breaks), "pretty" (for a pretty version of the same, with indentation and line breaks) or "off" (to turn off JSON output, the default).

--no-pager

Do not pipe output into a pager.

-h, --help

Print a short help text and exit.

--version

Print a short version string and exit.

EXIT STATUS

On success, 0 is returned, a non-zero failure code otherwise.
