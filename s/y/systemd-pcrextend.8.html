الوصف

systemd-pcrphase.service، systemd-pcrphase-sysinit.service، و systemd-pcrphase-initrd.service هي خدمات نظام تقوم بقياس سلاسل نصية محددة في PCR 11 الخاص بـ TPM2 خلال مراحل مختلفة من عملية الإقلاع.

systemd-pcrmachine.service هي خدمة نظام تقوم بقياس معرف الجهاز (انظر machine-id(5)) في PCR 15.

systemd-pcrfs-root.service و systemd-pcrfs@.service هي خدمات تقوم بقياس معلومات هوية نظام الملفات (أي نقطة التركيب، نوع نظام الملفات، التسمية و UUID، تسمية القسم و UUID) في PCR 15. تقوم systemd-pcrfs-root.service بذلك لنظام الملفات الجذر، بينما systemd-pcrfs@.service هي وحدة قالب تقوم بقياس نظام الملفات المحدد بواسطة معرف المثيل الخاص بها بدلاً من ذلك.

تتطلب هذه الخدمات استخدام systemd-stub(7) في صورة نواة موحدة (UKI). لا تنفذ أي عملية عندما لا يتم استخدام الـ stub لاستدعاء النواة. سيقوم الـ stub بقياس النواة المستدعاة والموارد المرتبطة بالمورد في PCR 11 قبل تسليم التحكم إليها؛ بمجرد استدعاء مساحة المستخدم، ستقوم هذه الخدمات بعد ذلك بتوسيع TPM2 PCR 11 بسلاسل حرفية معينة تشير إلى مراحل عملية الإقلاع. خلال عملية إقلاع منتظمة، يتم توسيع PCR 11 بالسلاسل التالية:

1."enter-initrd" — في وقت مبكر عندما تهيئ الـ initrd، قبل تفعيل صور امتداد النظام للـ initrd. وهي تعمل كحاجز بين وقت تهيئة النواة ووقت بدء تشغيل الـ initrd وتفعيل صور امتداد النظام، أي الشفرة المشحونة خارج UKI. (يحدث هذا الامتداد عند بدء تشغيل خدمة systemd-pcrphase-initrd.service(8).)
2."leave-initrd" — عندما تكون الـ initrd على وشك الانتقال إلى نظام الملفات المضيف. إنها تعمل كحاجز بين شفرة الـ initrd وشفرة نظام التشغيل المضيف. (يحدث هذا الامتداد عند إيقاف خدمة systemd-pcrphase-sysinit.service(8).)
3."sysinit" — عند اكتمال تهيئة النظام الأساسية (والتي تشمل تركيب أنظمة الملفات المحلية)، ويبدأ النظام في بدء تشغيل خدمات النظام المنتظمة. (يحدث هذا الامتداد عند بدء تشغيل خدمة systemd-pcrphase-sysinit.service(8).)
4."ready" — خلال مرحلة لاحقة من الإقلاع، بعد تفعيل أنظمة الملفات البعيدة (أي بعد remote-fs.target)، ولكن قبل السماح للمستخدمين بتسجيل الدخول (أي قبل systemd-user-sessions.service). إنها تعمل كحاجز بين الوقت الذي لا يزال فيه تسجيل دخول المستخدمين غير المميزين محظورًا والوقت الذي يُسمح فيه لهم بتسجيل الدخول. (يحدث هذا الامتداد عند بدء تشغيل خدمة systemd-pcrphase-sysinit.service(8).)
5."shutdown" — عند بدء إيقاف تشغيل النظام. إنها تعمل كحاجز بين الوقت الذي يكون فيه النظام قيد التشغيل بالكامل والوقت الذي يكون فيه على وشك الإيقاف. (يحدث هذا الامتداد عند إيقاف خدمة systemd-pcrphase.service.)
6."final" — في نهاية إيقاف تشغيل النظام. إنها تعمل كحاجز بين الوقت الذي لا يزال فيه مدير الخدمة يعمل والوقت الذي ينتقل فيه إلى مرحلة الإيقاف النهائية حيث لا تتوفر إدارة الخدمات بعد الآن. (يحدث هذا الامتداد عند إيقاف خدمة systemd-pcrphase-sysinit.service(8).)

خلال دورة حياة نظام منتظمة، يتم توسيع PCR 11 بالسلاسل "enter-initrd"، "leave-initrd"، "sysinit"، "ready"، "shutdown"، و "final".

قد تتم الإشارة إلى مراحل معينة من عملية الإقلاع عبر سلسلة السلاسل التي تم قياسها، مفصولة بنقطتين رأسيتين (مسار المرحلة). على سبيل المثال، مسار المرحلة للتشغيل العادي للنظام هو "enter-initrd:leave-initrd:sysinit:ready"، بينما بالنسبة للـ initrd فهو "enter-initrd" فقط. مسار المرحلة لمرحلة الإقلاع قبل الـ initrd هو سلسلة فارغة؛ نظرًا لصعوبة تمرير نقطة رأسية واحدة (":")، يمكن استخدامها بدلاً من ذلك. لاحظ أن السلاسل الست المذكورة أعلاه هي فقط السلاسل الافتراضية وقد تقوم الأنظمة الفردية بقياس سلاسل أخرى في أوقات أخرى، وبالتالي تنفذ مراحل إقلاع مختلفة وأكثر دقة لربط السياسة بها.

من خلال ربط سياسة كائنات TPM2 بمسار مرحلة معين، من الممكن تقييد الوصول إليها لمراحل محددة من عملية الإقلاع، على سبيل المثال، جعل الوصول إلى مفتاح تشفير نظام الملفات الجذر مستحيلاً بعد انتقال النظام من الـ initrd إلى نظام الملفات الجذر المضيف.

استخدم systemd-measure(1) لحساب قيم PCR 11 المتوقعة مسبقًا لمراحل إقلاع محددة (عبر مفتاح --phase=).

يتم سحب systemd-pcrfs-root.service و systemd-pcrfs@.service تلقائيًا إلى المعاملة الأولية بواسطة systemd-gpt-auto-generator(8) لأنظمة الملفات الجذر و /var/. سيقوم systemd-fstab-generator(8) بذلك لجميع التركيبات مع خيار التركيب x-systemd.pcrfs في /etc/fstab.

خيارات

قد يتم أيضًا استدعاء الملف التنفيذي /usr/lib/systemd/system-pcrextend من سطر الأوامر، حيث يتوقع الكلمة التي سيتم تمديدها إلى PCR 11، بالإضافة إلى المفاتيح التالية:

--bank=

يأخذ بنوك PCR لتمديد الكلمة المحددة إليها. إذا لم يتم تحديده، فستقوم الأداة تلقائيًا بتحديد جميع بنوك PCR الممكّنة وقياس الكلمة في جميعها.

تمت إضافته في الإصدار 252.

--pcr=

يأخذ فهرس PCR للتمديد. إذا تم تحديد --machine-id أو --file-system=، فيكون الافتراضي 15، وإلا يكون الافتراضي 11.

تمت إضافته في الإصدار 255.

--tpm2-device=PATH

يتحكم في جهاز TPM2 الذي سيتم استخدامه. يتوقع مسار عقدة جهاز يشير إلى شريحة TPM2 (مثل /dev/tpmrm0). بدلاً من ذلك، يمكن تحديد القيمة الخاصة "auto" لتحديد عقدة الجهاز لجهاز TPM2 مناسب تلقائيًا (يجب أن يكون هناك واحد فقط). يمكن استخدام القيمة الخاصة "list" لسرد جميع أجهزة TPM2 المناسبة المكتشفة حاليًا.

تمت إضافته في الإصدار 252.

--graceful

إذا لم يتم العثور على دعم لبرامج TPM2 الثابتة أو نواة النظام أو برنامج تشغيل النواة أو الجهاز، فقم بالخروج بحالة خروج 0 (أي الإشارة إلى النجاح). إذا لم يتم تحديد ذلك، فإن أي محاولة للقياس بدون جهاز TPM2 ستتسبب في فشل الاستدعاء.

تمت إضافته في الإصدار 253.

--machine-id

بدلاً من قياس كلمة محددة في سطر الأوامر في PCR 11، قم بقياس معرف الجهاز الخاص بالمضيف في PCR 15.

تمت إضافته في الإصدار 253.

--file-system=

بدلاً من قياس كلمة محددة في سطر الأوامر في PCR 11، قم بقياس معلومات هوية نظام الملفات المحدد في PCR 15. يجب أن يكون المعامل هو المسار إلى نقطة التركيب الثابتة لنظام الملفات المراد قياسه.

تمت إضافته في الإصدار 253.

-h, --help

اطبع نص مساعدة قصير واخرج.

--version

اطبع نص إصدار قصير واخرج.

systemd-pcrextend.8.en

NAME

systemd-pcrextend - add data to PCRs in the TPM

SYNOPSIS

systemd-pcrextend [-A auth_option] [-P pcr_id] [-i input_file] [-o output_file] [-t timeout] [-h] [-v]

DESCRIPTION

This tool is used to extend a Trusted Platform Module (TPM) Platform Configuration Register (PCR) value with arbitrary data. It is primarily intended for use by other systemd services that need to measure various system states and record them in the TPM. For example, systemd-boot measures its configuration into PCR 3, and systemd itself measures its boot-time configuration into PCR 4.

The operation consists of reading the current value of the PCR, extending it with the new data, and writing the result back. The extension operation is a cryptographic hash operation. Given the current PCR value P and the new data D, the new PCR value P' is calculated as P' = HASH(P || D), where HASH is the cryptographic hash algorithm associated with the PCR, and || denotes concatenation.

When measuring, the systemd-pcrphase.service unit is activated, which in turn invokes this tool. The tool is configured via the PCR value index, the data to be measured, and the TPM owner authorization or authorization secret. All these parameters are usually provided in the service file for systemd-pcrphase.service.

The TPM PCR state is volatile and is reset on reboot. For persistent measurements across reboots, the data needs to be re-measured after each boot. The data to be measured should be carefully chosen. In general, only data that is expected to change during an attack should be measured. For more details, see TPM2 PCR Measurements Made by systemd[3].

The command accepts the following options:

OPTIONS

-A auth_option, --auth=auth_option

Set the TPM ownership authorization or authorization secret. The auth_option should be one of owner, endorsement, or storage, possibly followed by a colon and a password if the corresponding authorization value is protected by a password.

-P pcr_id, --pcr-id=pcr_id

Set the PCR index to use. Valid values are 0 through 23 for TPM 1.2, and 0 through 31 for TPM 2.0. The default is 0.

-i input_file, --input=input_file

Read the data to be extended from input_file. If not specified, data is read from standard input.

-o output_file, --output=output_file

Write the extended PCR value to output_file. If not specified, the value is written to standard output. This is useful for debugging purposes.

-t timeout, --timeout=timeout

Set the timeout for TPM operations to timeout seconds. The default is 30 seconds.

-h, --help

Print a help message and exit.

-v, --version

Print a version message and exit.

To acquire a consistent quote from the TPM with the associated snapshot of the event log, applications should acquire a LOCK_SH lock while doing so. This is because the file is updated while the measurement is made.

Added in version 252.

FILES

/dev/tpm0, /dev/tpmrm0
TPM device nodes.
