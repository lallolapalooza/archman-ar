syslog(3) دليل وظائف المكتبة syslog(3)

الاسم

closelog, openlog, syslog, vsyslog - إرسال رسائل إلى مسجل النظام

المكتبة

مكتبة C القياسية (libc, -lc)

المُلخص

#include <syslog.h>
void openlog(const char *ident, int option, int facility);
void syslog(int priority, const char *format, ...);
void closelog(void);
void vsyslog(int priority, const char *format, va_list ap);
متطلبات ميزة الاختبار للميزات في glibc (انظر feature_test_macros(7)):

vsyslog():

    منذ glibc 2.19:
        _DEFAULT_SOURCE
    glibc 2.19 وما قبلها:
        _BSD_SOURCE

الوصف

openlog()

openlog() يفتح اتصالاً بمسجل النظام للبرنامج.

السلسلة النصية التي يشير إليها ident تُضاف إلى كل رسالة، وعادةً ما يتم تعيينها إلى اسم البرنامج. إذا كان ident هو NULL، يتم استخدام اسم البرنامج. (لا تحدد POSIX.1-2008 سلوك عندما يكون ident هو NULL.)

يحدد الوسيط option الأعلام التي تتحكم في تشغيل openlog() والمكالمات اللاحقة لـ syslog(). يقوم الوسيط facility بتعيين قيمة افتراضية لاستخدامها إذا لم يتم تحديد أي شيء في المكالمات اللاحقة لـ syslog(). القيم التي يمكن تحديدها لـ option و facility موصوفة أدناه.

استخدام openlog() اختياري؛ سيتم استدعاؤه تلقائيًا بواسطة syslog() إذا لزم الأمر، وفي هذه الحالة سيكون ident افتراضيًا NULL.

syslog() و vsyslog()

syslog() ينشئ رسالة تسجيل، والتي سيتم توزيعها بواسطة syslogd(8).

يتم تشكيل الوسيط priority عن طريق ORing معًا قيمة facility وقيمة level (موضحة أدناه). إذا لم يتم ORing أي قيمة facility في priority، فسيتم استخدام القيمة الافتراضية التي تم تعيينها بواسطة openlog()، أو، إذا لم تكن هناك مكالمة openlog() سابقة، فسيتم استخدام قيمة افتراضية لـ LOG_USER.

الوسائط المتبقية هي format، كما هو الحال في printf(3)، وأي وسائط مطلوبة بواسطة format، باستثناء أن التسلسل المكون من حرفين %m سيتم استبداله بسلسلة رسالة الخطأ strerror(errno). لا يلزم أن تحتوي سلسلة التنسيق على حرف سطر جديد في النهاية.

تقوم الدالة vsyslog() بنفس مهمة syslog() مع الاختلاف أنها تأخذ مجموعة من الوسائط التي تم الحصول عليها باستخدام وحدات الماكرو الخاصة بقائمة الوسائط المتغيرة stdarg(3).

closelog()

closelog() يغلق واصف الملف المستخدم للكتابة إلى مسجل النظام. استخدام closelog() اختياري.

القيم الخاصة بـ option

الوسيط option لـ openlog() هو قناع بت يتم إنشاؤه عن طريق ORing معًا أيًا من القيم التالية:

LOG_CONS
الكتابة مباشرة إلى وحدة التحكم بالنظام إذا كان هناك خطأ أثناء الإرسال إلى مسجل النظام.
LOG_NDELAY
فتح الاتصال فورًا (عادةً، يتم فتح الاتصال عند تسجيل الرسالة الأولى). قد يكون هذا مفيدًا، على سبيل المثال، إذا كان chroot(2) لاحقًا سيجعل المسار المستخدم داخليًا بواسطة مرفق التسجيل غير قابل للوصول.
LOG_NOWAIT
لا تنتظر العمليات الفرعية التي قد تكون قد تم إنشاؤها أثناء تسجيل الرسالة. (مكتبة GNU C لا تنشئ عملية فرعية، لذا فإن هذا الخيار ليس له تأثير على Linux.)
LOG_ODELAY
عكس LOG_NDELAY؛ يتم تأجيل فتح الاتصال حتى يتم استدعاء syslog(). (هذا هو الافتراضي، ولا يحتاج إلى تحديده.)
LOG_PERROR
(غير موجود في POSIX.1-2001 أو POSIX.1-2008.) سجل الرسالة أيضًا في stderr.
LOG_PID
تضمين معرف العملية (PID) الخاص بالمتصل مع كل رسالة.

القيم الخاصة بـ facility

يتم استخدام الوسيط facility لتحديد نوع البرنامج الذي يسجل الرسالة. هذا يتيح لملف التكوين تحديد كيفية التعامل مع الرسائل من المرافق المختلفة.

LOG_AUTH
رسائل الأمان/التفويض
LOG_AUTHPRIV
رسائل الأمان/التفويض (خاصة)
LOG_CRON
برنامج الساعة (cron و at)
LOG_DAEMON
خدمات النظام بدون قيمة مرفق منفصلة
LOG_FTP
خدمة ftp
LOG_KERN
رسائل النواة (لا يمكن إنشاؤها من عمليات المستخدم)
LOG_LOCAL0 إلى LOG_LOCAL7
محجوزة للاستخدام المحلي
LOG_LPR
نظام الطابعة
LOG_MAIL
نظام البريد
LOG_NEWS
نظام أخبار USENET
LOG_SYSLOG
الرسائل التي تم إنشاؤها داخليًا بواسطة syslogd(8)
LOG_USER (الافتراضي)
رسائل عامة لمستوى المستخدم
LOG_UUCP
نظام UUCP

القيم الخاصة بـ level

يحدد هذا أهمية الرسالة. المستويات، بترتيب الأهمية المتناقصة:

LOG_EMERG
النظام غير قابل للاستخدام
LOG_ALERT
يجب اتخاذ إجراء فوري
LOG_CRIT
ظروف حرجة
LOG_ERR
ظروف الخطأ
LOG_WARNING
ظروف التحذير
LOG_NOTICE
شرط طبيعي، ولكنه مهم
LOG_INFO
رسالة إعلامية
LOG_DEBUG
رسالة على مستوى التصحيح

يمكن استخدام الدالة setlogmask(3) لتقييد التسجيل إلى مستويات محددة فقط.

syslog(3) — Linux manual pages

NAME

syslog, openlog, closelog, vsyslog — interface to the system log

LIBRARY

Standard C library (libc, -lc)

SYNOPSIS

#include <sys/types.h>
#include <syslog.h>
void openlog(const char *ident, int option, int facility);
void closelog(void);
void syslog(int priority, const char *format, ...);
void vsyslog(int priority, const char *format, va_list ap);

DESCRIPTION

The syslog functions provide a standard way for programs to send messages to the system logger.

Before calling syslog or vsyslog, the user should initialize the logger by calling openlog. This function initializes the logging options and facility. The ident argument is a string that is prepended to every message generated by the logger. If ident is NULL, the program name is used instead.

The option argument controls various aspects of the logger's behavior. Multiple options can be combined using the bitwise OR operator (|). The available options are:

LOG_CONS
Messages are also sent to the console if there is an error during sending to the system logger.
LOG_NDELAY
Open the connection to the logger immediately (normally, the connection is opened only when the first message is sent).
LOG_NOWAIT
(This flag is obsolete and has no effect.)
LOG_ODELAY
Delay opening the connection to the logger until more data is available. This is the default behavior.
LOG_PERROR
Messages are also sent to standard error output. This option is not specified by POSIX.1-2001 or POSIX.1-2008.
LOG_PID
Include PID with each message.

The facility argument determines the category of the message. If it is zero, the default LOG_USER facility is used. Multiple facilities can be combined using the bitwise OR operator (|), although this is not usually done. The available facilities are:

LOG_AUTH
Security/authentication messages (private).
LOG_AUTHPRIV
Security/authentication messages (public).
LOG_CRON
Messages from cron daemon.
LOG_DAEMON
System daemons.
LOG_FTP
FTP daemon messages.
LOG_INSTALL
(This facility is not used.)
LOG_KERN
Kernel messages.
LOG_LOCAL0
Reserved for local use.
LOG_LOCAL1
Reserved for local use.
LOG_LOCAL2
Reserved for local use.
LOG_LOCAL3
Reserved for local use.
LOG_LOCAL4
Reserved for local use.
LOG_LOCAL5
Reserved for local use.
LOG_LOCAL6
Reserved for local use.
LOG_LOCAL7
Reserved for local use.
LOG_LPR
Messages from line printer.
LOG_MAIL
Messages from mail system.
LOG_NEWS
Messages from netnews system.
LOG_SYSLOG
Messages from syslog itself.
LOG_USER
User-level messages (default).
LOG_UUCP
Messages from UUCP subsystem.

The syslog function sends the message specified by format (and the additional arguments) to the system logger. The message format is similar to the `printf(3)` function.

The vsyslog function is similar to syslog, but takes a `va_list` argument instead of a variable number of arguments.

The closelog function closes the connection to the system logger.

The priority of a message is determined by combining a facility and a level. The available levels are:

LOG_ALERT
Something must be done immediately.
LOG_CRIT
Critical conditions.
LOG_DEBUG
Debugging messages.
LOG_EMERG
System is unusable.
LOG_ERR
Error conditions.
LOG_INFO
Informational messages.
LOG_NOTICE
Normal but significant condition.
LOG_WARNING
Warning conditions.

The priority is specified by ORing a facility and a level. For example, LOG_INFO | LOG_LOCAL0 specifies an informational message from the local0 facility.

If openlog has not been called, it will be called implicitly by syslog or vsyslog with a default ident of the program name, default options, and default facility.

The system log daemon (`syslogd(8)`) typically writes messages to files in `/var/log`. The configuration file `/etc/syslog.conf` determines which messages are written to which files.

If the LOG_PERROR option is set during the openlog call, messages are also sent to standard error. This is useful for debugging.

Messages sent via syslog are typically limited to 1024 bytes. If a message is longer than this, it may be truncated.

The closelog function is generally not needed, as the connection to the logger is automatically closed when a process terminates.

The syslog functions are thread-safe, provided that openlog is called before any other syslog functions in each thread.

The LOG_PID option causes each message to be preceded by the process ID.

The LOG_PERROR option is not part of POSIX standards.

A string is sent to syslog without interpretation. If the string contains `%s` or other format specifiers, they are passed to the logger. This means that user-supplied data should never be passed directly as the format string. If you need to log user-supplied data, use the following pattern:

syslog(priority, "%s", user_data);

The environment variable LOCALDOMAINDIR may specify a directory for local configuration files. This is unlikely to affect the syslog functions.

STANDARDS

The syslog, openlog, and closelog functions conform to POSIX.1-2008.

The vsyslog function conforms to None.

HISTORY

syslog first appeared in 4.2BSD and is also defined in SUSv2 and POSIX.1-2001.

openlog first appeared in 4.2BSD and is also defined in SUSv2 and POSIX.1-2001.

closelog first appeared in 4.3BSD and is also defined in SUSv2 and POSIX.1-2001.

vsyslog first appeared in 4.3BSD-Reno.

POSIX.1-2001 specifies only the LOG_USER and LOG_LOCAL* values for facility. However, with the exception of LOG_AUTHPRIV and LOG_FTP, the other facility values appear on most UNIX systems.

The LOG_PERROR value for option is not specified by POSIX.1-2001 or POSIX.1-2008, but is available in most versions of UNIX.

NOTES

The argument ident in the call of openlog is probably stored as-is. Thus, if the string it points to is changed, syslog may start prepending the changed string, and if the string it points to ceases to exist, the results are undefined. Most portable is to use a string constant.

Never pass a string with user-supplied data as a format, use the following instead:


syslog(priority, "%s", string);
