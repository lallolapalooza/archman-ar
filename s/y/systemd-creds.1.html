\n

NAME

\n

systemd-creds - management tool for encrypted credentials

\n
\n
\n

SYNOPSIS

\n

systemd-creds [OPTIONS...] {COMMAND} [ARGUMENT...]

\n

systemd-creds [OPTIONS...] {COMMAND} --help

\n
\n
\n

DESCRIPTION

\n

systemd-creds is a tool for managing encrypted credentials.\nIt allows creating, decrypting, and listing credentials, and binding them to\nspecific users or TPM2 keys.

\n

Credentials are stored in files, and can be encrypted using keys\nthat are either derived from the operating system installation or a TPM2 chip.\nThis allows applications to access sensitive data like passwords or API keys\nwithout exposing them in plaintext in unit files or configuration files.

\n

The tool supports several commands:

\n
    \n
  • encrypt: Encrypts data from standard input and writes it to\na specified file.
    • \n
  • decrypt: Decrypts data from a specified file and prints it to\nstandard output.
    • \n
  • cat: Decrypts data from a specified file and prints it to\nstandard output, potentially with transcoding.
    • \n
  • list: Lists available credentials, including their names,\nencryption keys, and other metadata.
    • \n
  • generate-tpm2-policy: Generates a TPM2 PCR policy for\ncredentials.
    • \n
\n
\n
\n

OPTIONS

\n

The following options are understood:

\n

--user=USER

\n
Specifies the user to encrypt the credential for. Takes a\nuser name or numeric UID. If set, implies --user. If set to the special\nstring "self" sets the user to the user of the calling process. If\n--user is used without --uid= then --uid=self is implied,\ni.e. the credential is encrypted for the calling user.\n

Added in version 256.

\n
\n

--transcode=

\n
When specified with the cat or decrypt\ncommands, transcodes the output before showing it. Takes one of\n"base64", "unbase64", "hex" or "unhex"\nas argument, in order to encode/decode the credential data with Base64 or as\nseries of hexadecimal values. The special value "help" may be used\nto list supported transcode types.\n

Note that this has no effect on the encrypt command, as\nencrypted credentials are unconditionally encoded in Base64.

\n

Added in version 250.

\n
\n

--newline=

\n
When specified with cat or decrypt controls\nwhether to add a trailing newline character to the end of the output if it\ndoes not end in one, anyway. Takes one of "auto", "yes" or\n"no". The default mode of "auto" will suffix the output\nwith a single newline character only when writing credential data to a TTY.\n

Added in version 250.

\n
\n

--pretty, -p

\n
When specified with encrypt controls whether to\nshow the encrypted credential as SetCredentialEncrypted= setting that\nmay be pasted directly into a unit file. Has effect only when used together\nwith --name= and "-" as the output file.\n

Added in version 250.

\n
\n

--name=name

\n
When specified with the encrypt command controls\nthe credential name to embed in the encrypted credential data. If not\nspecified, the name is chosen automatically from the filename component of the\nspecified output path. If specified as empty string no credential name is\nembedded in the encrypted credential, and no verification of credential name\nis done when the credential is decrypted.\n

When specified with the decrypt command control the\ncredential name to validate the credential name embedded in the encrypted\ncredential with. If not specified, the name is chosen automatically from the\nfilename component of the specified input path. If no credential name is\nembedded in the encrypted credential file (i.e. the --name= with an\nempty string was used when encrypted) the specified name has no effect as no\ncredential name validation is done.

\n

Embedding the credential name in the encrypted credential is done\nin order to protect against reuse of credentials for purposes they were not\noriginally intended for, under the assumption the credential name is chosen\ncarefully to encode its intended purpose.

\n

Added in version 250.

\n
\n

--timestamp=timestamp

\n
When specified with the encrypt command controls\nthe timestamp to embed into the encrypted credential. Defaults to the current\ntime. Takes a timestamp specification in the format described in\nsystemd.time(7).\n

When specified with the decrypt command controls the\ntimestamp to use to validate the "not-after" timestamp that was\nconfigured with --not-after= during encryption. If not specified,\ndefaults to the current system time.

\n

Added in version 250.

\n
\n

--not-after=timestamp

\n
When specified with the encrypt command controls\nthe time when the credential shall not be used anymore. This embeds the\nspecified timestamp in the encrypted credential. During decryption the\ntimestamp is checked against the current system clock, and if the timestamp is\nin the past the decryption will fail. By default, no such timestamp is set.\nTakes a timestamp specification in the format described in\nsystemd.time(7).\n

Added in version 250.

\n
\n

--with-key=, -H, -T

\n
When specified with the encrypt command controls\nthe encryption/signature key to use. Takes one of "host",\n"tpm2", "host+tpm2", "null", "auto",\n"auto-initrd". See above for details on the three key types. If set\nto "auto" (which is the default) the TPM2 key is used if a TPM2\ndevice is found and not running in a container. The host key is used if\n/var/lib/systemd/ is on persistent media. This means on typical systems the\nencryption is by default bound to both the TPM2 chip and the OS installation,\nand both need to be available to decrypt the credential again. If\n"auto" is selected but neither TPM2 is available (or running in\ncontainer) nor /var/lib/systemd/ is on persistent media, encryption will fail.\nIf set to "null" a fixed zero length key is used (thus, in this mode\nno confidentiality nor authenticity are provided!). This logic is useful to\ncover for systems that lack a TPM2 chip but where credentials shall be\ngenerated. Note that decryption of such credentials is refused on systems that\nhave a TPM2 chip and where UEFI SecureBoot is enabled (this is done so that\nsuch a locked down system cannot be tricked into loading a credential\ngenerated this way that lacks authentication information). If set to\n"auto-initrd" a TPM2 key is used if a TPM2 is found. If not a fixed\nzero length key is used, equivalent to "null" mode. This option is\nparticularly useful to generate credentials files that are\nencrypted/authenticated against TPM2 where available but still work on systems\nlacking support for this. The special value "help" may be used to\nlist supported key types.\n

The -H switch is a shortcut for --with-key=host.\nSimilar, -T is a shortcut for --with-key=tpm2.

\n

When encrypting credentials that shall be used in the initrd\n(where /var/lib/systemd/ is typically not available) make sure to use\n--with-key=auto-initrd mode, to disable binding against the host\nsecret.

\n

This switch has no effect on the decrypt command, as\ninformation on which key to use for decryption is included in the encrypted\ncredential already.

\n

Added in version 250.

\n
\n

--tpm2-device=PATH

\n
Controls the TPM2 device to use. Expects a device node\npath referring to the TPM2 chip (e.g. /dev/tpmrm0). Alternatively the special\nvalue "auto" may be specified, in order to automatically determine\nthe device node of a suitable TPM2 device (of which there must be exactly\none). The special value "list" may be used to enumerate all suitable\nTPM2 devices currently discovered.\n

Added in version 250.

\n
\n

--tpm2-pcrs=PCR[+PCR...]

\n
Configures the TPM2 PCRs (Platform Configuration\nRegisters) to bind the encryption key to. Takes a "+" separated list\nof numeric PCR indexes in the range 0...23. If an empty string is specified,\nbinds the encryption key to no PCRs at all (this is also the default if this\noption is not used). For details about the PCRs available, see the\ndocumentation of the switch of the same name for\nsystemd-cryptenroll(1).\n

Added in version 250.

\n
\n

--tpm2-public-key=PATH,\n--tpm2-public-key-pcrs=PCR[+PCR...]

\n
Configures a TPM2 signed PCR policy to bind encryption\nto, for use with the encrypt command. The --tpm2-public-key=\noption accepts a path to a PEM encoded RSA public key, to bind the encryption\nto. If this is not specified explicitly, but a file tpm2-pcr-public-key.pem\nexists in one of the directories /etc/systemd/, /run/systemd/,\n/usr/lib/systemd/ (searched in this order), it is automatically used. The\n--tpm2-public-key-pcrs= option takes a list of TPM2 PCR indexes to bind\nto (same syntax as --tpm2-pcrs= described above). If not specified,\ndefaults to 11 (i.e. this binds the policy to any unified kernel image for\nwhich a PCR signature can be provided).\n

Note the difference between --tpm2-pcrs= and\n--tpm2-public-key-pcrs=: the former binds decryption to the current,\nspecific PCR values; the latter binds decryption to any set of PCR values\nfor which a signature by the specified public key can be provided. The\nlatter is hence more useful in scenarios where software updates shall be\npossible without losing access to all previously encrypted secrets.

\n

Added in version 252.

\n
\n

--tpm2-signature=PATH

\n
Takes a path to a TPM2 PCR signature file as generated by\nthe systemd-measure(1) tool and that may be used to allow the\ndecrypt command to decrypt credentials that are bound to specific\nsigned PCR values. If this is not specified explicitly, and a credential with\na signed PCR policy is attempted to be decrypted, a suitable signature file\ntpm2-pcr-signature.json is searched for in /etc/systemd/, /run/systemd/,\n/usr/lib/systemd/ (in this order) and used.\n

Added in version 252.

\n
\n

--allow-null

\n
Allow decrypting credentials that use an empty key.\n

Added in version 256.

\n
\n

--quiet, -q

\n
Suppress additional output.\n

Added in version 251.

\n
\n

--no-pager

\n
Do not pipe output into a pager.
\n

--no-legend

\n
Do not print the legend, i.e. column headers and the\nfooter with hints.
\n

--json=MODE

\n
Shows output formatted as JSON. Expects one of\n"short" (for the shortest possible output without any redundant\nwhitespace or line breaks), "pretty" (for a pretty version of the\nsame, with indentation and line breaks) or "off" (to turn off JSON\noutput, the default).
\n
\n
\n

EXIT STATUS

\n

On success, 0 is returned.

\n
\n
\n

EXAMPLES

\n

Example 1. Encrypt a password for use as\ncredential

\n

The following command line encrypts the specified password\n"hunter2", writing the result to a file password.cred.

\n
\n
# echo -n hunter2 | systemd-creds encrypt - password.cred
\n
\n

This decrypts the file password.cred again, revealing the literal\npassword:

\n
\n
# systemd-creds decrypt password.cred\nhunter2
\n
