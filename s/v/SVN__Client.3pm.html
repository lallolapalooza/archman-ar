SVN::Client - وظائف عميل Subversion

الملخص

use SVN::Client;
my $client = new SVN::Client();
# إعداد لمعالجة المصادقة بنفس طريقة عميل سطر الأوامر
my $config_dir = undef; # استخدام الموقع الافتراضي
my $config = SVN:Core::config_get_config($config_dir);
my $config_category = $cfg->{SVN::Core::CONFIG_CATEGORY_CONFIG};
$client->auth(
  SVN::Core::cmdline_create_auth_baton(0,           #non_interactive
                                       undef,       #username
                                       undef,       #password
                                       $config_dir,
                                       0,           #no_auth_cache
                                       0,           #trust_server_cert
                                       $config_category,
                                       undef)       #cancel_callback
);
# استخدام الوسيط الأول كهدف وتوحيده قبل استخدامه
my $target;
if (SVN::Core::path_is_url($ARGV[0])) {
  $target = SVN::Core::uri_canonicalize($ARGV[0]);
} else {
  $target = SVN::Core::dirent_canonicalize($ARGV[0]);
}
# جلب آخر مراجعة للهدف
$client->cat(\*STDOUT, $target, 'HEAD');

الوصف

SVN::Client يلتف حول أعلى مستوى من الوظائف التي يوفرها subversion لإنجاز مهام محددة في واجهة برمجة تطبيقات موجهة للكائنات. تشبه الأساليب الوظائف التي توفرها واجهة برمجة التطبيقات C وقد يكون توثيقها مفيدًا في فهم هذه الواجهة.

هناك عدد قليل من الاختلافات الملحوظة عن واجهة برمجة التطبيقات C. تتخذ معظم استدعاءات وظائف C مؤشر svn_client_ctx_t كمعامل قبل الأخير. تأخذ استدعاءات أساليب Perl كائن SVN::Client كمعامل أول. هذا يسمح باستدعاء الأساليب للأساليب. على سبيل المثال، ما يلي متكافئ:

SVN::Client::add($client,$path, $recursive, $pool);
$client->add($path, $recursive, $pool);

تأخذ العديد من استدعاءات واجهة برمجة التطبيقات C أيضًا مؤشر apr_pool_t كآخر وسيط لها. تتعامل روابط Perl مع هذا بشكل عام نيابة عنك ولا تحتاج إلى تمرير وسيط pool. ومع ذلك، لا يزال بإمكانك تمرير وسيط pool كوسيط أخير لتجاوز المعالجة التلقائية لهذا الأمر نيابة عنك.

لا ينبغي للمستخدمين لهذه الواجهة معالجة قيم التجزئة الأساسية مباشرة ولكن يجب عليهم استخدام أساليب السمات المقابلة. تقوم العديد من أساليب السمات هذه بأشياء أخرى، خاصة عند تعيين سمة، بخلاف مجرد معالجة القيمة في التجزئة.

ملاحظات المعلمات

تأخذ أساليب العميل الموضحة أدناه مجموعة متنوعة من المعلمات. العديد منها متشابه. تتبع الأساليب التي تقبل المعلمات المسماة أدناه القواعد أدناه أو سيتم ملاحظتها بشكل مختلف في وصف الأسلوب.

$client
كائن SVN::Client تحصل عليه من المنشئ.
$url
هذا هو عنوان URL لمستودع subversion.
$path
هذا هو مسار ملف أو دليل في نظام الملفات المحلي. تحتاج المسارات إلى توحيدها قبل تمريرها إلى واجهات برمجة التطبيقات الفرعية. تسمى المسارات في نظام الملفات المحلي dirents ويمكن توحيدها عن طريق استدعاء "SVN::Core::dirent_canonicalize".
$paths
يمكن أن يكون هذا الوسيط إما $path واحدًا (كما هو معرف أعلاه) أو مرجعًا لمصفوفة منها.
$target
هذا هو مسار ملف أو دليل في نسخة عمل أو عنوان URL لملف أو دليل في مستودع subversion. يجب توحيد كل من المسارات وعناوين URL قبل تمريرها إلى واجهات برمجة التطبيقات الفرعية. تسمى المسارات في نظام الملفات المحلي dirents ويمكن توحيدها عن طريق استدعاء "SVN::Core::dirent_canonicalize". يمكن توحيد عناوين URL عن طريق استدعاء "SVN::Core::uri_canonicalize".
$targets
يمكن أن يكون هذا الوسيط إما $target واحدًا (كما هو معرف أعلاه) أو مرجعًا لمصفوفة منها.
$revision
يحدد هذا مراجعة في مستودع Subversion. يمكنك تحديد مراجعة بعدة طرق. الأسهل والأكثر وضوحًا هو توفير رقم المراجعة مباشرة. يمكنك أيضًا استخدام السلاسل (المعروفة أيضًا بكلمات مفتاحية للمراجعة) 'HEAD'، 'BASE'، 'COMMITTED'، و 'PREV' التي لها نفس المعاني كما في عميل سطر الأوامر. عند الإشارة إلى نسخة عمل، يمكنك استخدام السلسلة 'WORKING" للإشارة إلى BASE بالإضافة إلى أي تعديلات محلية. يمكن استخدام "undef" لتحديد مراجعة غير محددة. يمكنك أيضًا تمرير تاريخ عن طريق تحديد التاريخ داخل أقواس معقوفة '{}'. تنسيقات التاريخ المقبولة هي نفسها التي يقبلها عميل سطر الأوامر. أخيرًا، يتم قبول كائن "_p_svn_opt_revision_t" (والذي ربما تم إرجاعه بواسطة بعض وظائف Subversion).
$recursive $nonrecursive.
وسيط منطقي يحدد ما إذا كان الإجراء يجب أن يتبع الدلائل. يجب أن يكون 1 أو 0 فقط. $recursive يعني، 1 يعني النزول إلى الدلائل، 0 يعني عدم القيام بذلك. $nonrecursive له المعنى العكسي.
$pool
Pool هو دائمًا معلمة خيار. إذا كنت ترغب في تمرير معلمة pool، فيجب أن تكون كائن SVN::Pool أو apr_pool_t.

الأساليب

الأساليب التالية متاحة:

$client = SVN::Client->new( %options );
يقوم هذا الأسلوب الفئوي بإنشاء كائن "SVN::Client" جديد وإرجاع مرجع له.

يمكن توفير وسائط زوج مفتاح/قيمة لإعداد الحالة الأولية لوكيل المستخدم. الأساليب التالية تتوافق مع أساليب السمات الموضحة أدناه:

KEY                    DEFAULT
----------             ----------------------------------------
auth                   auth_baton تم تهيئته بموفرين يقرؤون خيارات المصادقة المخزنة مؤقتًا من
                       تكوين subversion فقط.
cancel                 undef
config                 تجزئة تحتوي على التكوين من
                       ملف تكوين subversion الافتراضي.
log_msg                undef
notify                 undef
pool                   يتم إنشاء pool جديد للسياق.
$client->add($path, $recursive, $pool);
مشابه لـ $client->add2()، ولكن مع $force دائمًا بقيمة FALSE.
$client->add2($path, $recursive, $force, $pool);
مشابه لـ $client->add3()، ولكن مع $no_ignore دائمًا بقيمة FALSE.
$client->add3($path, $recursive, $force, $no_ignore, $pool);
مشابه لـ $client->add4()، ولكن مع $add_parents دائمًا بقيمة FALSE و $depth محدد وفقًا لـ $recursive؛ إذا كان TRUE، فإن العمق هو $SVN::Depth::infinity، إذا كان FALSE، فإن العمق هو $SVN::Depth::empty.
$client->add4($path, $depth, $force, $no_ignore, $add_parents, $pool);
جدولة $path لنسخة العمل للإضافة إلى المستودع.

إذا كان $depth هو $SVN::Depth::empty، أضف فقط $path ولا شيء تحته. إذا كان $SVN::Depth::files، أضف $path وأي أطفال ملفات لـ $path. إذا كان $SVN::Depth::immediates، أضف $path، وأي أطفال ملفات، وأي دلائل فرعية فورية (ولكن لا شيء تحت هذه الدلائل الفرعية). إذا كان $SVN::Depth::infinity، أضف $path وكل شيء تحته بشكل كامل متكرر.

يجب أن يكون والد $path تحت سيطرة المراجعة بالفعل (ما لم يكن $add_parents هو TRUE)، ولكن $path ليس كذلك.

ما لم يكن $force هو TRUE و $path تحت سيطرة الإصدار بالفعل، فإنه يعيد كائن $SVN::Error::ENTRY_EXISTS. إذا تم تعيين $force، فلا تخطئ في العناصر التي تم إصدارها بالفعل. عند استخدامه مع $depth تم تعيينه على $SVN::Depth::infinity، فإنه سيدخل الدلائل المصدرة؛ جدولة الأطفال غير المصدرة.

يستدعي معاودة إخطار لكل عنصر تم إضافته.

إذا كان $no_ignore هو FALSE،

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

$diff_options هو مرجع إلى مصفوفة من الوسائط الإضافية التي يتم تمريرها إلى عملية diff المستدعاة لمقارنة الملفات. في معظم الحالات، سيتم استخدام [] فقط لتمرير مصفوفة فارغة لإرجاع diff سياقي موحد (مثل `diff -u`).

لا تعود بأي شيء.

$client->diff_summarize($target1, $revision1, $target2, $revision2, $recursive, $ignore_ancestry, \&summarize_func, $pool);
ينشئ ملخصًا للاختلافات يسرد العناصر المعدلة بين $target1 في $revision1 و $target2 في $revision2 دون إنشاء دلتا نصية. يمكن أن تكون $target1 و $target2 مسارات عمل أو عناوين URL.

إذا كانت $ignore_ancestry خاطئة، فقد يتم الإبلاغ عن مواقع خاطئة، حيث يمكن تعديل ملف بين مراجعتين ولكنه لا يزال يمتلك نفس المحتويات.

يمكن للدالة $summarize_func تمرير كائن svn_client_diff_summarize_t يصف الاختلاف.

انظر diff() لوصف المعلمات الأخرى.

لا تعود بأي شيء.

$client->export($from, $to, $revision, $force, $pool);
يصدر محتويات مستودع svn أو نسخة عمل svn إلى مجلد "نظيف" (أي مجلد بدون أدلة إدارية).

$from هو مسار نسخة العمل على القرص أو عنوان URL للمستودع الذي ترغب في تصديره.

$to هو مسار المجلد حيث ترغب في إنشاء نسخة العمل المصدرة.

$revision هي المراجعة المراد تصديرها، والتي تستخدم فقط عند التصدير من مستودع. قد تكون غير محددة بخلاف ذلك.

سيتم استدعاء callback الإشعارات للعناصر المصدرة.

تُرجع قيمة المراجعة المصدرة فعليًا أو $SVN::Core::INVALID_REVNUM للتصديرات المحلية.

$client->import($path, $url, $nonrecursive, $pool);
يستورد الملف أو الدليل $path إلى مجلد المستودع $url في المقدمة.

إذا كانت بعض مكونات $url غير موجودة، فسيتم إنشاء أدلة أصلية حسب الحاجة.

إذا كان $path دليلاً، فسيتم استيراد محتوياته مباشرة إلى الدليل المحدد بواسطة $url. ملاحظة: لا يتم استيراد الدليل $path نفسه؛ أي أن اسم الملف الخاص بـ $path ليس جزءًا من الاستيراد.

إذا كان $path ملفًا، فإن الدليل الأصل لـ $url هو وجهة الاستيراد. اسم الملف الخاص بـ $url هو الاسم في المستودع. في هذه الحالة، إذا كان $url موجودًا بالفعل، فسيتم طرح خطأ.

يتم استدعاء callback الإشعارات (إذا تم تحديده) أثناء عملية الاستيراد، مع أي من الإجراءات التالية: $SVN::Wc::Notify::Action::commit_added، $SVN::Wc::Notify::Action::commit_postfix_txdelta.

استخدم $nonrecursive للإشارة إلى عدم ضرورة تكرار الدلائل المستوردة في الأدلة الفرعية التي قد تكون موجودة.

استخدم callback `log_msg` لتحديد رسالة السجل للالتزام عند الحاجة.

تُرجع كائن svn_client_commit_info_t.

$client->info($path_or_url, $peg_revision, $revision, \&receiver, $recurse);
يستدعي &receiver، ويمرر إليه معلومات حول $path_or_url لـ $revision. المعلومات التي تم إرجاعها هي بيانات وصفية نظامية، وليست من نوع "خاصية" تم إنشاؤها بواسطة المستخدمين. بالنسبة للطرق المتاحة في الكائن الذي تم تمريره إلى &receiver، **انظر** svn_info_t.

إذا كان كلا وسيطي المراجعة إما svn_opt_revision_unspecified أو NULL، فسيتم الحصول على المعلومات من نسخة العمل فقط؛ لن يتم إجراء اتصالات شبكة.

بخلاف ذلك، سيتم الحصول على المعلومات من المستودع. يتم تحديد عقدة المراجعة المحددة بواسطة $path_or_url كما هو موجود في $peg_revision. إذا كانت $peg_revision غير محددة، فسيتم استخدام HEAD للعناوين URL أو WORKING لمسارات العمل.

إذا لم يكن $path_or_url مسارًا محليًا، وكانت $revision هي PREV (أو أي نوع آخر يتطلب مسارًا محليًا)، فسيتم إرجاع خطأ، لأنه لا يمكن تحديد المراجعة المطلوبة.

يستخدم عصا المصادقة المخزنة في السياق للمصادقة مع المستودع.

إذا كانت $recurse صحيحة (وكان $path_or_url دليلاً)، فستكون هذه عملية تكرارية، تستدعي &receiver على كل ابن.

my $receiver = sub {
    my( $path, $info, $pool ) = @_;
    print "Current revision of $path is ", $info->rev, "\n";
};
$client->info( 'foo/bar.c', undef, 'WORKING', $receiver, 0 );
$client->log5($targets, $peg_revision, $revision_ranges, $limit, $discover_changed_paths, $strict_node_history, $include_merged_revisions, $revprops, \&log_entry_receiver, $pool);
يستدعي &log_entry_receiver على كل رسالة سجل من كل نطاق مراجعة في $revision_ranges، بما في ذلك (ولكن دون استدعاء &log_entry_receiver أكثر من مرة لكل رسالة سجل).

$targets هو مرجع لمصفوفة من عناوين URL متبوعة بصفر أو أكثر من المسارات النسبية، أو مسار عمل واحد ترغب في الحصول على رسائل السجل له. إذا كانت المصفوفة تحتوي على عنصر واحد فقط، يمكنك تعيين $targets إلى هذا العنصر. يتم استدعاء &log_entry_receiver فقط على الرسائل التي تشمل مراجعاتها تغييرًا في أي مسار من $targets.

$peg_revision يشير إلى المراجعة التي تكون فيها $targets صالحة. إذا كانت $peg_revision undef، يتم استخدام HEAD للعناوين URL أو WORKING لمسارات العمل.

$revision_ranges هو *نطاق مراجعة* واحد أو مرجع لمصفوفة منها. يمكن تحديد *نطاق مراجعة* كمرجع لمصفوفة من عنصرين "[$start, $end]" من $revision أو كائن svn_opt_revision_range_t. أمثلة:

$revision_ranges = ['HEAD', 1];
$revision_ranges = [[2, 3], [5, 8], [13, 21]];

إذا كان $limit غير صفري، فسيتم استدعاء &log_entry_receiver فقط على أول $limit رسالة سجل.

إذا كانت $discover_changed_paths صحيحة، فسيتم ملء الحقل changed_paths2 في الوسيط &log_entry في كل استدعاء. *ملاحظة:* قد تكون حقلا text_modified و props_modified لـ changed_paths2 لهما القيمة $SVN::Tristate::unknown إذا لم يبلغ المستودع عن هذه المعلومات.

إذا كانت $strict_node_history صحيحة، فلن يتم تتبع السجل (إذا كان موجودًا) أثناء جمع السجلات لكل هدف.

إذا كانت $include_merged_revisions صحيحة، فسيتم إرجاع معلومات حول المراجعات التي تم دمجها نحو $targets.

إذا كانت $revprops undef، فسيتم استرداد جميع خصائص المراجعة. بخلاف ذلك، يجب أن تكون $revpros مرجعًا لمصفوفة من أسماء الخصائص وسيتم استرداد هذه فقط (أي، لا شيء إذا كانت المصفوفة فارغة).

استخدم $pool لأي تخصيص مؤقت.

يتم استدعاء الروتين الفرعي للإشعارات بإشارة $SVN::Wc::Notify::Action::skip لأي هدف غير مسجل.

يأخذ &log_entry_receiver الوسائط التالية: &$log_entry, $pool. $log_entry هو كائن svn_core::svn_log_entry_t.

$client->log4($targets, $peg_revision, $start, $end, $limit, $discover_changed_paths, $strict_node_history, $include_merged_revisions, $revprops, \&log_entry_receiver, $pool);
مشابه لـ &client->log5()، ولكنه يأخذ وسيطات صريحة $start و $end بدلاً من $revision_ranges.

مهمل.

$client->log3($targets, $peg_revision, $start, $end, $limit, $discover_changed_paths, $strict_node_history, \&log_message_receiver, $pool);
مشابه لـ &client->log4()، ولكنه يستخدم &log_message_receiver بدلاً من &log_entry_receiver. أيضًا، $include_merged_revisions خاطئة و $revprops هي [qw( svn:author svn:date y svn:log )].

يأخذ &log_message_receiver الوسائط التالية: &$changed_paths, $revision, $author, $date, $message, $pool. يتم استدعاؤه مرة واحدة لكل رسالة سجل من $message للمراجعة $revision في $date بواسطة $author. يمكن أن يكون $author أو $date أو $message undef.

إذا كان $changed_paths محددًا، فهو يشير إلى جدول بمفاتيح كل مسار ملتزم في $revision؛ القيم هي كائنات svn_core::svn_log_changed_path_t.

مهمل.

$client->log2($targets, $start, $end, $limit, $discover_changed_paths, $strict_node_history, \&log_message_receiver, $pool);
مشابه لـ &client->l og3()"، ولكن مع تعيين $peg_revision إلى "undef".

تم إهماله.

$client->log($targets, $start, $end, $discover_changed_paths, $strict_node_history, \&log_message_receiver, $pool);
مشابه لـ "$client->log2()"، ولكن مع تعيين $limit إلى 0.

حالة خاصة للمستودعات في المراجعة 0: إذا كان $start هو 'HEAD' و $end هو 1، فتعامل مع مستودع فارغ (لا مراجعات) بشكل خاص: بدلاً من حدوث خطأ لأن المراجعة المطلوبة 1 عندما تكون أعلى مراجعة هي 0، قم فقط باستدعاء "log_message_receiver" على المراجعة 0، مع تمرير "undef" إلى $changed_paths وسلاسل فارغة للمؤلف والتاريخ. هذا لأنه هذا المزيج المحدد من $start و $end يشير عادةً إلى الحالة الشائعة لاستدعاء السجل؛ يريد المستخدم رؤية جميع رسائل السجل من الأحدث إلى الأقدم، حيث تكون أقدم التزام هو المراجعة 1. يعمل هذا بشكل جيد، باستثناء عدم وجود التزامات في المستودع، وبالتالي هذه الحالة الخاصة.

تم إهماله.

$client->ls($target, $revision, $recursive, $pool);
يعيد قاموسًا من كائنات svn_dirent_t لـ $target في $revision.

إذا كان $target دليلًا، يعيد إدخالات لجميع محتويات الدليل. إذا كان $recursive صحيحًا، فسوف يتكرر في الأدلة الفرعية الموجودة في $target.

إذا كان $target ملفًا، يعيد إدخالًا للملف فقط.

إذا كان $target غير موجود، يثير الخطأ $SVN::Error::FS_NOT_FOUND.

$client->merge($src1, $rev1, $src2, $rev2, $target_wcpath, $recursive, $ignore_ancestry, $force, $dry_run, $pool);
دمج التغييرات من $src1/$rev1 إلى $src2/$rev2 في مسار نسخة العمل $target_wcpath.

$src1 و $src2 هما إما عناوين URL التي تشير إلى إدخالات في المستودع، أو مسارات لإدخالات في نسخة العمل.

بواسطة "الدمج"، نعني: تطبيق اختلافات الملفات وجدولة الإضافات والحذف عند الاقتضاء.

$src1 و $src2 يجب أن يمثلا نفس نوع العقدة؛ أي، إذا كان $src1 دليلًا، فيجب أن يكون $src2 كذلك، وإذا كان $src1 ملفًا، فيجب أن يكون $src2 كذلك.

إذا كان $rev1 أو $rev2 هو undef، يثير الخطأ $SVN::Error::CLIENT_BAD_REVISION.

إذا كان $recursive صحيحًا (وكانت عناوين URL أدلة)، فقم بتطبيق التغييرات بشكل متكرر؛ وإلا، قم فقط بتطبيق التغييرات في الدليل الحالي.

استخدم $ignore_ancestry للتحكم في ما إذا كان سيتم التحقق من ارتباط العناصر التي يتم مقارنتها أولاً أم لا. عادةً ما يتم نقل العناصر غير المرتبطة إلى المحرر كحذف لشيء واحد وإضافة لشيء آخر، ولكن إذا كان هذا العلم صحيحًا، فسيتم مقارنة العناصر غير المرتبطة كما لو كانت مرتبطة.

إذا لم يتم تعيين $force وكان الدمج يتضمن حذف عناصر محلية معدلة أو غير مسجلة، فستثير العملية خطأ. إذا تم تعيين $force، فسيتم حذف هذه العناصر.

يستدعي وظيفة الإشعار مرة واحدة لكل هدف تم دمجه، ويمرر مسار الهدف المحلي.

إذا كان $dry_run صحيحًا، يتم إجراء الدمج، ويتم توفير تغذية إعلامية كاملة، ولكن لا يتم تعديل نسخة العمل.

ليس له قيمة إرجاع.

$client->mkdir($targets, $pool);
مشابه لـ $client->mkdir2() باستثناء أنه يعيد كائن svn_client_commit_info_t بدلاً من كائن svn_commit_info_t.
$client->mkdir2($targets, $pool);
مشابه لـ $client->mkdir3()، ولكن مع $make_parents دائمًا FALSE، و $revprop_hash دائمًا undef.
$client->mkdir3($targets, $make_parents, $revprop_hash, $pool);
مشابه لـ $client->mkdir4()، ولكن يعيد كائن svn_commit_info_t بدلاً من ذلك من خلال وظيفة رد نداء.
$client->mkdir4($targets, $make_parents, $revprop_hash, \&commit_callback, $pool);
إنشاء دليل، إما في مستودع أو في نسخة عمل.

إذا كانت $targets تحتوي على عناوين URL، فيتم محاولة الالتزام فورًا بإنشاء الأدلة في $targets في المستودع. يعيد كائن svn_client_commit_info_t.

بخلاف ذلك، قم بإنشاء الأدلة على القرص، وحاول جدولة إضافتها. في هذه الحالة يعيد undef.

إذا كان $make_parents TRUE، قم بإنشاء أي أدلة أصل غير موجودة أيضًا.

إذا لم يكن undef، فإن $revprop_hash هو مرجع لجدول هاش يحتوي على خصائص مراجعة مخصصة إضافية (أسماء الخصائص المعينة لسلاسل) ليتم تعيينها على المراجعة الجديدة في حالة أن هذه عملية التزام. لا يمكن أن يحتوي هذا الهاش على أي خصائص Subversion قياسية.

يستدعي وظيفة رسالة السجل للاستعلام عن رسالة سجل الالتزام عند الحاجة إليها.

يستدعي وظيفة الإشعار عند إنشاء الدليل (بنجاح) في نسخة العمل، مع مسار الدليل الجديد. ملاحظة: يتم استدعاء هذا فقط للعناصر المضافة إلى نسخة العمل.

إذا لم يكن &commit_callback هو undef، فلكل التزام ناجح، قم باستدعاء &commit_callback مع كائن svn_commit_info_t للالتزام.

$client->move($src_path, $src_revision, $dst_path, $force, $pool);
نقل $src_path إلى $dst_path.

$src_path يجب أن يكون ملفًا أو دليلًا تحت التحكم في الإصدار، أو عنوان URL لعنصر مسجل في المستودع.

إذا كان $src_path عنوان URL للمستودع:

* يجب أن يكون $dst_path أيضًا عنوان URL للمستودع (موجود أو غير موجود).

* يتم استخدام $src_revision لاختيار المراجعة التي سيتم نسخ $src_path منها.

* سيتم استدعاء وظيفة log_msg لرسالة سجل الالتزام.

* سيتم الالتزام بعملية النقل فورًا. إذا نجح الالتزام، يعيد كائن svn_client_commit_info_t.

إذا كان $src_path مسار نسخة عمل

* يجب أن يكون $dst_path أيضًا مسار نسخة عمل (موجود أو غير موجود).

* يتم تجاهل $src_revision وقد يكون undef. لن يتم استدعاء وظيفة log_msg.

* هذه عملية جدولة. لن تحدث تغييرات في المستودع حتى يتم الالتزام. يمكن إزالة هذه الجدولة باستخدام $client->revert(). إذا كان $src_path ملفًا، فسيتم إزالته من نسخة العمل فورًا. إذا كان $src_path دليلًا، فسيظل في نسخة العمل ولكن سيتم إزالة جميع الملفات والعناصر غير المسجلة التي تحتوي عليها.

* إذا كان $src_path يحتوي على عناصر معدلة محليًا و/أو غير مسجلة ولم يتم تعيين $force، فسيثير النسخ خطأ. إذا تم تعيين $force، فسيتم إزالة هذه العناصر.

سيتم استدعاء وظيفة الإشعار مرتين لكل عنصر تم نقله، مرة للإشارة إلى حذف العقدة المنقولة، ومرة للإشارة إلى إضافة الموقع الجديد للعقدة.

$client->propget($propname, $target, $revision, $recursive, $pool);
يعيد مرجعًا لقاموس يحتوي على مسارات أو عناوين URL، مسبوقة بـ $target (نسخة عمل أو عنوان URL)، للعناصر التي تم تعيين خاصية $propname لها، وقيمها تمثل قيمة الخاصية لـ $propname في هذا المسار.
$client->proplist($target, $revision, $recursive, $pool);
يعيد مرجعًا لمصفوفة من كائنات svn_client_proplist_item_t.

لكل عنصر، يحتوي عضو node_name في كائن proplist_item على الاسم بالنسبة لنفس الأساس مثل $target.

إذا كان $revision هو undef، فاحصل على الخصائص من نسخة العمل، إذا كان $target نسخة عمل، أو من رأس المستودع إذا كان $target عنوان URL. وإلا، احصل على الخصائص كما في $revision.

إذا كان $recursive خطأ، أو كان $target ملفًا، فستحتوي المصفوفة المعادة على عنصر واحد فقط. بخلاف ذلك، ستحتوي على إدخال واحد لكل إدخال مسجل أسفل (بما في ذلك) $target.

إذا لم يتم العثور على $target، يثير الخطأ $SVN::Error::ENTRY_NOT_FOUND.

$client->propset($propname, $propval, $target, $recursive, $pool);
تعيين $propname إلى $propval على $target (مسار نسخة عمل أو عنوان URL).

إذا كان $recursive صحيحًا، فسيتم تعيين $propname بشكل متكرر على $target وجميع العناصر الفرعية. إذا كان $recursive خطأ، وكان $target دليلًا، فسيتم تعيين $propname **فقط** على $target.

سيؤدي تعيين $propval إلى undef إلى حذف الخاصية.

إذا كان $propname خاصية مسيطر عليها بواسطة svn (أي مسبوقة بـ svn:)، فإن المتصل مسؤول عن التأكد من أن $propval مشفر بـ UTF8 ويستخدم نهايات أسطر LF.

$client->relocate($dir, $from, $to, $recursive, $pool);
تعديل دليل نسخة العمل $dir، وتغيير أي عناوين URL للمستودع التي تبدأ بـ $from لتبدأ بـ $to بدلاً من ذلك، والتكرار في الأدلة الفرعية
$depth ليس $SVN::Depth::unknown، لذا بالإضافة إلى تحديث المسارات، فإنه يقوم أيضًا بتعيين قيمة عمق البيئة المستمرة الخاصة به إلى $depth.

إذا كان $allow_unver_obstructions صحيحًا، فإن التحديث يتسامح مع العناصر غير المدارة التي تعيق المسارات المضافة. يتم فقط التسامح مع العوائق من نفس فئة (ملف أو دليل) العنصر المضاف. يحتفظ بنص الملفات المعيقة كما هو، ويعاملها على أنها تعديلات قام بها المستخدم بعد التحديث. يتم تعيين خصائص العمل للعناصر المعيقة بنفس قيم الخصائص الأساسية. إذا كان $allow_unver_obstructions خطأ، فسيتوقف التحديث إذا كان هناك أي عنصر غير مُدار يعيق المسارات.

إذا كان $adds_as_modification صحيحًا، فإن الإضافة المحلية في نفس المسار مثل إضافة من نفس النوع في عقدة تؤدي إلى عقدة عادية مع احتمال تعديل محلي، بدلاً من تعارض في الشجرة.

إذا كان $make_parents صحيحًا، فسيقوم بإنشاء أي أدلة غير موجودة عن طريق التحقق أيضًا بعمق = فارغ.

يستدعي رد النداء notify لكل عنصر تتم إدارته بواسطة التحديث، وكذلك للملفات المستعادة من النص الأساسي.

يعيد مصفوفة مرجعية لمصفوفة من أرقام المراجعات، حيث يتم تعريف كل عنصر على أنه رقم المراجعة الذي تم حل $revision لكل عنصر في $paths.

$client->url_from_path($target, $pool); or SVN::Client::url_from_path($target, $pool);
يعيد عنوان URL لـ $target.

إذا كان $target هو بالفعل عنوان URL، يعيد $target.

إذا كان $target عنصرًا مُدارًا، يعيد عنوان URL لإدخال $target.

إذا كان $target غير مُدار (ليس له إدخال)، يعيد undef.

طرق السمات

تسمح طرق السمات التالية بتعيين تكوينات مختلفة أو استردادها. تأخذ جميعها قيمة (قيم) لتعيين السمة وتعيد قيمة السمة الجديدة، أو لا تأخذ معلمات وتعيد القيمة الحالية.

$client->auth(SVN::Client::get_username_provider());
يوفر الوصول إلى auth_baton في svn_client_ctx_t المرتبط بكائن SVN::Client.

تقبل هذه الطريقة مصفوفة أو مرجع مصفوفة من القيم التي تم إرجاعها من وظائف موفر المصادقة، والتي تحولها إلى auth_baton لك. إنها الطريقة المفضلة لتعيين auth_baton.

كما أنها تقبل قيمة قابلة للقياس تشير إلى _p_svn_auth_baton_t، مثل تلك التي يتم إرجاعها بواسطة SVN::Core::auth_open و SVN::Core::auth_open_helper.

$client->notify(\&notify);
تعيّن رد النداء notify لسياق العميل إلى مرجع رمز تمرره. تعيد دائمًا مرجع الرمز الحالي.

يتم استدعاء الإجراء الفرعي الذي يشير إليه مرجع الرمز هذا عند إجراء تغيير في نسخة العمل. يتم تجاهل القيمة المرجعة من هذه الوظيفة. الغرض الوحيد منها هو إعلامك بالتغيير.

سيتم استدعاء الإجراء الفرعي المستلم بـ 6 معلمات. المعلمة الأولى هي مسار الملف المتغير (مطلق أو نسبي إلى cwd). الثانية هي عدد صحيح يحدد نوع الإجراء المتخذ. راجع SVN::Wc للحصول على قائمة بالقيم الممكنة ومعانيها. المعلمة الثالثة هي عدد صحيح يحدد نوع عقدة المسار، والتي يمكن أن تكون: $SVN::Node::none، $SVN::Node::file، $SVN::Node::dir، $SVN::Node::unknown. المعلمة الرابعة هي نوع MIME للملف أو undef إذا كان نوع MIME غير معروف (سيكون دائمًا undef للأدلة). المعلمة الخامسة هي حالة الملف، مرة أخرى راجع SVN::Wc للحصول على قائمة بالحالات الممكنة. المعلمة السادسة والأخيرة هي رقم مراجعة الملف المتغير. سيكون رقم المراجعة -1 باستثناء عندما يكون الإجراء هو $SVN::Wc::Notify::Action::update_completed.

$client->log_msg(\&log_msg)
تعيّن رد النداء log_msg لسياق العميل إلى مرجع رمز تمرره. تعيد دائمًا مرجع الرمز الحالي.

يتم استدعاء الإجراء الفرعي الذي يشير إليه مرجع الرمز هذا للحصول على رسالة السجل لأي عملية ستلتزم بمراجعة للمستودع.

تتلقى 4 معلمات. المعلمة الأولى هي مرجع لقيمة قابلة للقياس يجب على الإجراء الفرعي وضع رسالة السجل فيها. إذا كنت ترغب في إلغاء الالتزام، يمكنك تعيين هذه القيمة إلى undef. القيمة الثانية هي مسار لأي ملف مؤقت قد يخزن رسالة السجل تلك، أو undef إذا لم يكن موجودًا (على الرغم من أنه إذا كان log_msg هو undef، فإن هذه القيمة غير محددة). يجب أن تكون رسالة السجل سلسلة UTF-8 مع فواصل أسطر LF. المعلمة الثالثة هي مرجع لمصفوفة من كائنات svn_client_commit_item3_t، والتي يمكن أن تكون مملوءة بالكامل أو جزئيًا، اعتمادًا على نوع عملية الالتزام. المعلمة الرابعة والأخيرة ستكون pool.

إذا أرادت الدالة إرجاع خطأ، يجب عليها إرجاع كائن svn_error_t تم إنشاؤه بواسطة SVN::Error::create. يتم تفسير جميع القيم الأخرى على أنها SVN_NO_ERROR.

$client->cancel(\&cancel)
تعيّن رد النداء الإلغاء لسياق العميل إلى مرجع رمز تمرره. راجع "CANCELLATION CALLBACK" لمزيد من التفاصيل. تعيد دائمًا مرجع الرمز الحالي.
$client->pool(new SVN::Pool);
طريقة تعيّن أو تحصل على الـ pool الافتراضي الذي يتم تمريره إلى الطرق التي تتطلب pool، حتى لو لم يتم تحديدها صراحة.

راجع SVN::Core لمزيد من المعلومات حول كيفية إدارة الـ pools في هذه الواجهة.

$client->config(SVN::Core::config_get_config(undef));
طريقة تسمح بالوصول إلى عضو config الخاص بـ svn_client_ctx_t. تقبل هاش Perl لتعيينه، وهو ما تعيده وظائف مثل SVN::Core:config_get_config().

تعيد قيمة قابلة للقياس _p_arp_hash_t. هذا وضع مؤقت. القيمة المرجعة ليست مفيدة بشكل خاص. في المستقبل، سيتم ربط هذه القيمة بالهاش الفعلي المستخدم بواسطة واجهة برمجة تطبيقات C.

موفرات المصادقة

تقوم الوظائف التالية باسترداد موفري المصادقة لك. وهي متاحة في شكلين: قياسي أو إصدارات الملفات، والتي تبحث عن معلومات المصادقة في دليل تكوين Subversion الذي تم تخزينه مؤقتًا سابقًا، أو إصدارات الحوار التي تستدعي إجراء فرعي للسماح للمستخدم بالمصادقة بنفسه.

SVN::Client

The SVN::Client module provides access to the Subversion client API. This is the API used by the svn command-line client. Most of the functionality available in the svn command-line client is exposed through this module.

This module is separated into several sections for easier reading:

AUTHENTICATION CALLBACKS

The Subversion client library supports several authentication callbacks. These are used to prompt the user for information when Subversion cannot determine it automatically.

SVN::Client::get_username_provider
Returns a username provider that prompts the user via a callback. Takes one or two parameters, the callback subroutine and optionally a pool parameter. The subroutine gets called with the following parameters: a svn_auth_cred_username_t object, a realm string, and a pool. The svn_auth_cred_username_t object has the following members: username and may_save.
SVN::Client::get_simple_provider
Returns a simple username/password provider that prompts the user via a callback. Takes one or two parameters, the callback subroutine and optionally a pool parameter. The subroutine gets called with the following parameters: a svn_auth_cred_simple_t object, a realm string, and a pool. The svn_auth_cred_simple_t object has the following members: username, password, and may_save.
SVN::Client::get_ssl_server_trust_file_provider
Returns a server trust provider that returns information from previously cached sessions. Takes no parameters or optionally a pool parameter.
SVN::Client::get_ssl_server_trust_prompt_provider
Returns a server trust provider that prompts the user via a callback. Takes one or two parameters the callback subroutine and optionally a pool parameter. The subroutine gets called with the following parameters. A svn_auth_cred_ssl_server_trust_t object, a realm string, an integer specifying how the certificate failed authentication, a svn_auth_ssl_server_cert_info_t object, may_save, and a pool. The svn_auth_cred_ssl_server_trust_t object has the following members: may_save and accepted_failures. The svn_auth_ssl_server_cert_info_t object has the following members (and behaves just like cred objects though you can't modify it): hostname, fingerprint, valid_from, valid_until, issuer_dname, ascii_cert.

The masks used for determining the failures are in SVN::Auth::SSL and are named:

$SVN::Auth::SSL::NOTYETVALID $SVN::Auth::SSL::EXPIRED $SVN::Auth::SSL::CNMISMATCH $SVN::Auth::SSL::UNKNOWNCA $SVN::Auth::SSL::OTHER

You reply by setting the accepted_failures of the cred object with an integer of the values for what you want to accept bitwise AND'd together.

SVN::Client::get_ssl_client_cert_file_provider
Returns a client certificate provider that returns information from previously cached sessions. Takes no parameters or optionally a pool parameter.
SVN::Client::get_ssl_client_cert_prompt_provider
Returns a client certificate provider that prompts the user via a callback. Takes two or three parameters: the first is the callback subroutine, the 2nd is the number of retries to allow, the 3rd is optionally a pool parameter. The subroutine gets called with the following parameters. A svn_auth_cred_ssl_client_cert object, a realm string, may_save, and a pool. The svn_auth_cred_ssl_client_cert the following members: cert_file and may_save.
SVN::Client::get_ssl_client_cert_pw_file_provider
Returns a client certificate password provider that returns information from previously cached sessions. Takes no parameters or optionally a pool parameter.
SVN::Client::get_ssl_client_cert_pw_prompt_provider
Returns a client certificate password provider that prompts the user via a callback. Takes two or three parameters, the first is the callback subroutine, the 2nd is the number of retries to allow, the 3rd is optionally a pool parameter. The subroutine gets called with the following parameters. A svn_auth_cred_ssl_client_cert_pw object, a realm string, may_save, and a pool. The svn_auth_cred_ssl_client_cert_pw has the following members: password and may_save.

CANCELLATION CALLBACK

This callback will be called periodically to see if the operation should be canceled. If the operation should be canceled, the function may return one of the following values:

An svn_error_t object made with SVN::Error::create.

Any true value, in which case the bindings will generate an svn_error_t object for you with the error code of SVN_ERR_CANCELLED and the string set to "By cancel callback".

A string, in which case the bindings will generate an svn_error_t object for you with the error code of SVN_ERR_CANCELLED and the string set to the string you returned.

Any other value will be interpreted as wanting to continue the operation. Generally, it's best to return 0 to continue the operation.
