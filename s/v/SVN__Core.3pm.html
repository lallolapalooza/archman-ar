الاسم

SVN::Core - وحدة التنفيذ الأساسية لـ subversion في روابط perl

ملخص

use SVN::Core; # يبدأ وينتهي سياق APR لك
# ينشئ مجمع جذري ويضبطه كمجمع افتراضي للاستخدام لاحقًا
my $pool = SVN::Pool->new_default;
sub something {
    # ينشئ مجمع فرعي من المجمع الافتراضي الحالي
    my $pool = SVN::Pool->new_default_sub;
    # بعض عمليات SVN...
    # سيتم تدمير $pool واستعادة المجمع الافتراضي السابق عند انتهاء نطاق $pool
}
# معالج IO الأصلي مثل svn_stream_t
my $stream = $txn->root->apply_text('trunk/filea', undef);
print $stream $text;
close $stream;
# معالج IO الأصلي مثل svn_stream_t
SVN::Repos::dump_fs($repos, \*STDOUT, \*STDERR,
                    0, $repos->fs->youngest_rev, 0);

الوصف

SVN::Core تنفذ وظائف المستوى الأعلى للوظائف الأساسية لـ subversion.

الوظائف

SVN::Core::auth_open([auth provider array]);
يأخذ مرجعًا لمصفوفة من مزودي المصادقة ويعيد auth_baton. إذا كنت تستخدم مزودي مصادقة مع مطالبة، فلا يمكنك استخدام هذه الوظيفة، ولكن يجب عليك استخدام auth_open_helper.
SVN::Core::auth_open_helper([auth provider array]);
يعيد مزودو المصادقة مع المطالبة قيمتين بدلاً من واحدة. المعلمة الثانية هي مرجع لما تم تمريره إليها كدالة استدعاء. يقوم auth_open_helper بتقسيم هذه الوسائط، وتمرير كائنات المزود إلى auth_open، مما يمنحك auth_baton والآخرين في مصفوفة. القيمة الأولى المعادة من هذه الوظيفة هي auth_baton، والثانية هي مرجع لمصفوفة تحتوي على مراجع لدوال الاستدعاء.

يجب تخزين هذه المصفوفات من دوال الاستدعاء في الكائن الذي يرتبط به auth_baton.

كائنات أخرى

svn_stream_t - SVN::Stream

يمكنك استخدام معالجات IO الأصلية (بما في ذلك معالجات IO العامة) مثل svn_stream_t في وظائف subversion. يتم تحويل svn_stream_t المعادة أيضًا إلى معالجات IO في Perl، لذلك يمكنك الوصول إليها باستخدام print، read، إلخ.

ملاحظة: تأخذ بعض الوظائف مجرى لقراءة أو كتابة، ولكنها لا تغلق المجرى بينما لا تزال تحتفظ بمرجع لمعالج IO. في هذه الحالة، لن يتم تدمير المعالج بشكل صحيح. يجب عليك دائمًا إعداد المجمع الافتراضي بشكل صحيح قبل استدعاء مثل هذه الوظائف.

svn_pool_t - SVN::Pool

تبسط روابط Perl بشكل كبير استخدام المجمعات، على الرغم من أنه لا يزال من الممكن تعديلها يدويًا.

بالنسبة للوظائف التي تتطلب مجمعًا كآخر وسيط (وهي جميع وظائف subversion تقريبًا)، فإن وسيط المجمع اختياري. يتم استخدام المجمع الافتراضي إذا لم يتم تحديده. عند تحميل SVN::Core، فإنه ينشئ مجمعًا افتراضيًا جديدًا، والذي يمكن الوصول إليه أيضًا من SVN::Core->gpool.

بالنسبة للوظائف التي تقدم مجمعًا إلى روتينك الفرعي، يمكنك أيضًا استخدام $pool->default لجعله المجمع الافتراضي في النطاق.

الأساليب

new([$parent])
ينشئ مجمعًا جديدًا. المجمع هو مجمع جذري إذا لم يتم توفير $parent.
new_default([$parent])
ينشئ مجمعًا جديدًا. المجمع هو مجمع جذري إذا لم يتم توفير $parent. يضبط المجمع الجديد كمجمع افتراضي.
new_default_sub
ينشئ مجمعًا فرعيًا من المجمع الافتراضي الحالي ويضبط المجمع الناتج كمجمع افتراضي جديد.
clear
مسح المجمع.
DESTROY
تدمير المجمع. إذا كان المجمع هو المجمع الافتراضي، فقم باستعادة المجمع الافتراضي السابق. يتم استدعاء هذا تلقائيًا عندما لم يعد كائن SVN::Pool مستخدمًا ويتم تدميره بواسطة جامع القمامة في Perl.

svn_error_t - SVN::Error

افتراضيًا، تتعامل روابط Perl مع الاستثناءات نيابة عنك. يقوم المعالج الافتراضي تلقائيًا بالانهيار برسالة خطأ مناسبة. هذا يكفي للبرامج النصية البسيطة، ولكن للاستخدام الأكثر تعقيدًا، يجب معالجة الاستثناءات.

يمكنك استبدال المعالج الافتراضي عن طريق تغيير المتغير $SVN::Error::handler. يحتوي هذا المتغير على مرجع لروتين فرعي في Perl يتم استدعاؤه في كل مرة يتم فيها إرجاع استثناء بواسطة وظيفة svn. سيستقبل هذا الروتين الفرعي كائن svn_error_t. يتم تجاهل قيمة الإرجاع الخاصة به.

إذا قمت بتعيين $SVN::Error::handler إلى undef، فإن كل استدعاء سيعيد كائن svn_error_t كقيمة إرجاع أولى في حالة حدوث خطأ، تليها قيم الإرجاع العادية. في حالة عدم وجود خطأ، لن يتم إرجاع كائن svn_error_t وسيتم إرجاع قيم الإرجاع العادية فقط. عند استخدام هذا الوضع، يجب أن تكون حذرًا فقط لاستدعاءات السياق الصفيف. على سبيل المثال: my ($ci) = $ctx->mkdir('http://svn/foo'); في هذه الحالة، سيكون $ci كائن svn_error_t إذا حدث خطأ وكائن svn_client_commit_info بخلاف ذلك. إذا حذفت الأقواس حول $ci (سياق القياسي)، فسيكون كائن commit_info، والذي سيكون undef في حالة حدوث خطأ.

إذا كنت تخطط لاستخدام معالجة الاستثناءات الصريحة، فمن المفيد فهم نظام معالجة الاستثناءات الذي تستخدمه واجهة برمجة تطبيقات C. يمكنك العثور على معلومات حول ذلك في ملف HACKING وتوثيق واجهة برمجة التطبيقات. قد يكون التحقق من تنفيذ SVN::Error::croak_on_error و SVN::Error::expanded_message مفيدًا أيضًا.

$svn_error_t->apr_err()
قيمة خطأ APR، قد تكون خطأ SVN مخصصًا.
$svn_error_t->message()
تفاصيل منتج الخطأ.
$svn_error_t->child()
كائن svn_error_t للخطأ الذي يتم تغطيته.
$svn_error_t->pool()
المجمع الذي يحتوي على هذا الخطأ وأي أخطاء أطفال مغطاة به.
$svn_error_t->file()
الملف الذي نشأ فيه الخطأ.
$svn_error_t->line()
سطر الملف الذي نشأ فيه الخطأ.
SVN::Error::strerror($apr_status_t)
يعيد الوصف باللغة الإنجليزية لحالة الخطأ.
$svn_error_t->strerror()
يعيد الوصف باللغة الإنجليزية لحالة خطأ apr_err لكائن svn_error_t. هذا اختصار لـ: SVN::Error::strerror($svn_error_t->apr_err());
SVN::Error::create($apr_err, $child, $message);
يعيد كائن svn_error_t جديدًا مع حالة الخطأ المحددة في $apr_err، والطفل كـ $child، ورسالة الخطأ $message.
SVN::Error::quick_wrap($child, $new_msg); أو $child->quick_wrap($new_msg);
طريقة سريعة وسهلة لإنشاء غلاف استثناء برسالتك الخاصة قبل رميه للأعلى عبر المكدس.

الـ $child هو كائن svn_error_t الذي تريد تغطيته والـ $new_msg هي رسالة الخطأ الجديدة التي تريد تعيينها.

SVN::Error::compose($chain, $new_error); أو $chain->compose($new_error);
يضيف $new_error إلى نهاية سلسلة الأخطاء لـ $chain.

سيتم نسخ $new_err إلى مجمع $chain وسيتم تدميره، لذلك يصبح $new_err غير صالح بعد هذه الوظيفة.

svn_error_t

Error objects.

SVN::Error::clear($svn_error_t); or $svn_error_t->clear();
Free the memory used by $svn_error_t, as well as all ancestors and descendants of $svn_error_t.

You must call this on every svn_error_t object you get or you will leak memory.

SVN::Error::expanded_message($svn_error_t) or $svn_error_t->expanded_message()
Returns the error message by tracing through the svn_error_t object and its children and concatenating the error messages. This is how the internal exception handlers get their error messages.
SVN::Error::is_error($value)
Returns true if value is of type svn_error. Returns false if value is anything else or undefined. This is useful for seeing if a call has returned an error.
SVN::Error::croak_on_error
Default error handler. It takes an svn_error_t and extracts the error messages from it and croaks with those messages.

It can be used in two ways. The first is detailed above as setting it as the automatic exception handler via setting $SVN::Error::handler.

The second is if you have $SVN::Error::handler set to undef as a wrapper for calls you want to croak on when there is an error, but you don't want to write an explicit error handler. For example:

my $rev = SVN::Error::croak_on_error($ctx->checkout($url,$path,'HEAD',1));

If there is no error then croak_on_error will return the arguments passed to it unchanged.

SVN::Error::confess_on_error
The same as croak_on_error except it will give a more detailed stack backtrace, including internal calls within the implementation of the perl bindings. This is useful when you are doing development work on the bindings themselves.
SVN::Error::ignore_error
This is useful for wrapping around calls which you wish to ignore any potential error. It checks to see if the first parameter is an error and if it is it clears it. It then returns all the other parameters.

svn_depth_t - SVN::Depth

An enum of the following constants:

$SVN::Depth::unknown
Depth undetermined or ignored. In some contexts, this means the client should choose an appropriate default depth. The server will generally treat it as $SVN::Depth::infinity.
$SVN::Depth::exclude
Exclude (i.e., don't descend into) directory D.

Note: In Subversion 1.5, $SVN::Depth::exclude is not supported anyhwere in the client-side (Wc/Client/etc) code; it is only supported as an argument to set_path functions in the Ra and Repos reporters. (This will enable future versions of Subversion to run updates, etc, against 1.5 servers with proper $SVN::Depth::exclude behavior, once we get a chance to implement client side support for $SVN::Depth::exclude).

$SVN::Depth::empty
Just the named directory D, no entries.

Updates will not pull in any files or subdirectories not already present.

$SVN::Depth::files
D + its files children, but not subdirs.

Updates will pull in any files not already present, but not subdirectories.

$SVN::Depth::immediates
D + immediate children (D and its entries).

Updates will pull in any files or subdirectories not already present; those subdirectories' this_dir entries will have depth-empty.

$SVN::Depth::infinity
D + all descendants (full recursion from D).

Updates will pull in any files or subdirectories not already present; those subdirectories' this_dir entries will have depth-infinity. Equivalent to the pre 1.5 default update behavior.

SVN::Core

Perl interface to Subversion core library functions.

SYNOPSIS

 use SVN::Core;

DESCRIPTION

This module provides the core functionality for the Subversion Perl bindings. You will usually use this module indirectly by using other modules such as SVN::Client, SVN::Repos, or SVN::Wc. Direct usage of this module is generally not recommended unless you know exactly what you are doing.

FUNCTIONS

None

OTHER OBJECTS

This module defines several structures that are used by the Subversion libraries. These structures are usually returned by other functions, or passed to them.

svn_log_entry_t

$entry->revision()
The revision number.
$entry->author()
The author of the commit.
$entry->date()
The date of the commit, as the number of microseconds since 00:00:00 January 1, 1970 UTC. Divide it by 1_000_000 to get a Unix time_t value.
$entry->message()
The commit message.
$entry->has_children()
Whether or not this message has children.
$entry->changed_paths2()
A reference to hash containing as keys every path committed in "$entry->revision()"; the values are "_p_svn_log_changed_path2_t" objects.
$entry->non_inheritable()
Whether "$entry->revision()" should be interpreted as non-inheritable in the same sense of "_p_svn_merge_range_t".
$entry->subtractive_merge()
Whether "$entry->revision()" is a merged revision resulting from a reverse merge.
