FBB::Semaphore(3bobcat) سيمافور دايكسترا FBB::Semaphore(3bobcat)

الاسم

FBB::Semaphore - يطبق نوع السيمافور المصمم بواسطة دايكسترا

ملخص

#include <bobcat/semaphore>

خيار الربط: -lpthread -lbobcat

الوصف

وفقًا لـ http://en.wikipedia.org/wiki/Semaphore_(programming)، السيمافور هو متغير أو نوع بيانات مجرد يستخدم للتحكم في الوصول، بواسطة عمليات متعددة، إلى مورد مشترك في بيئة برمجة متوازية أو بيئة متعددة المستخدمين. تم تصميم Semaphore كنوع بيانات حوالي عام 1962 بواسطة إدجسير دايكسترا.

طريقة مفيدة للتفكير في السيمافور هي كسجل لعدد وحدات مورد معين متوفرة، جنبًا إلى جنب مع عمليات لتعديل هذا السجل بأمان (أي، بدون حالات سباق) حيث يتم طلب الوحدات أو تصبح حرة، وإذا لزم الأمر، الانتظار حتى تتوفر وحدة من المورد.

السيمافورات أداة مفيدة في منع حالات السباق. السيمافورات التي تسمح بعدد موارد اعتباطي تسمى سيمافورات العد، بينما تسمى السيمافورات المقيدة بالقيم 0 و 1 (أو مقفل/مفتوح، غير متاح/متاح) سيمافورات ثنائية. يدعم Bobcat كلاهما في تنفيذه.

المنشئات

o
Semaphore(size_t nAvailable):
يعرف المنشئ الحالة الأولية للسيمافور. مع سيمافور عد، nAvailable تحدد، على سبيل المثال، عدد المواقع المتاحة في منطقة تخزين. يتم تنفيذ القفل/فتح، ودعم المرافق لإخطار الخيوط الأخرى المنتظرة عبر سيمافورات ثنائية، والتي تتم تهيئتها إلى 1 أو 0. السيمافور الذي يحتوي على القيمة 0 يمنع. أي، عضو wait الخاص به ينتظر حتى تتم زيادة قيمته بواسطة خيط آخر، يستدعي أحد أعضاء notify الخاصة بالسيمافور.

منشئات النسخ والنقل (وعوامل التعيين) غير متاحة.

دوال الأعضاء

o
void notify():
تتم زيادة قيمة available التي تتم صيانتها داخليًا، ويتم إخطار خيط واحد منتظر (راجع أعضاء wait أدناه)، مما يعيد تنشيط هذا الخيط.
o
void notify_all():
تتم زيادة قيمة available التي تتم صيانتها داخليًا، ويتم إخطار جميع الخيوط المنتظرة (راجع أعضاء wait أدناه). خيط واحد فقط من الخيوط المنتظرة سيكون قادرًا على الحصول على قفل السيمافور وتقليل available، ويتم إعادة تنشيط هذا الخيط المعين بعد ذلك.
o
void set(size_t available):
يمنع هذا العضو حتى يحصل على قفل std::mutex الذي تتم صيانته داخليًا بواسطة كائن Semaphore. بعد ذلك، تتلقى قيمة available الخاصة بالـ Semaphore قيمة وسيطة العضو، ويتم تحرير القفل.
o
size_t size() const:
بدون محاولة قفل mutex كائن Semaphore، يتم إرجاع القيمة الحالية لقيمة available الخاصة بالـ Semaphore.
o
void wait():
يمنع هذا العضو طالما أن القيمة المخزنة داخليًا (available) تساوي صفرًا. عند العودة من wait، يحمل الخيط الحالي قفل std::mutex الذي تتم صيانته داخليًا بواسطة كائن Semaphore. تُستخدم أعضاء Notify لزيادة available وإبلاغ wait بأنه يمكنها العودة. عندما تنتظر خيوط متعددة، يتوقف خيط واحد فقط عن الانتظار، بينما تستمر الخيوط المتبقية في الانتظار لإشعار آخر.
o
bool wait(Fun fun, Params &&...args):
هذا عضو قالب، حيث Fun هي دالة (كائن) تتلقى الوسيط الممرر إلى wait، وترجع bool. يمنع هذا العضو حتى يحصل على قفل mutex الخاص بـ Semaphore، ثم، بينما قيمة available الخاصة به تساوي 0، ينتظر حتى يتم إخطاره. بمجرد إعادة الحصول على القفل بعد الإخطار، يتم استدعاء fun، وتتلقى الوسائط المتبقية لـ wait المعاد توجيهها بشكل مثالي. يرجع هذا العضو false إذا رجعت fun قيمة false. يرجع true إذا رجعت fun قيمة true وكانت available غير صفرية بعد أن رجعت fun قيمة true. لذلك، قد تقوم الدالة بتنفيذ مهام خارج البيئة المحلية للـ Semaphore، والتي قد تتضمن حتى تحديث قيمة available الخاصة بالـ Semaphore.
o
std::cv_status wait_for(std::chrono::duration<Rep, Period> const &relTime):
يمنع هذا العضو طالما أن القيمة المخزنة داخليًا (available) تساوي صفرًا ولم تنقضِ المدة الزمنية المحددة بواسطة relTime. إذا حدث الأخير، يتم إرجاع std::cv_status::timeout، وإلا يتم إرجاع std::cv_status::no_timeout، وفي هذه الحالة يحمل الخيط الحالي قفل std::mutex الذي تتم صيانته داخليًا بواسطة كائن Semaphore. تُستخدم أعضاء Notify لزيادة available وإبلاغ wait بأنه يمكنها العودة. عندما تنتظر خيوط متعددة، يتوقف خيط واحد فقط عن الانتظار، بينما تستمر الخيوط المتبقية في الانتظار لإشعار آخر.
o
std::cv_status wait_until(std::chrono::time_point<Clock, Duration> const &absTime):
يمنع هذا العضو طالما أن القيمة المخزنة داخليًا (available) تساوي صفرًا ولم يتم الوصول إلى الوقت المحدد بواسطة absTime. إذا حدث الأخير (أو إذا كان absTime يقع في الماضي)، يتم إرجاع std::cv_status::timeout، وإلا يتم إرجاع std::cv_status::no_timeout، وفي هذه الحالة يحمل الخيط الحالي قفل std::mutex الذي تتم صيانته داخليًا بواسطة كائن Semaphore. تُستخدم أعضاء Notify لزيادة available وإبلاغ wait بأنه يمكنها العودة. عندما تنتظر خيوط متعددة، يتوقف خيط واحد فقط عن الانتظار، بينما تستمر الخيوط المتبقية في الانتظار لإشعار آخر.

مثال

    #include <bobcat/semaphore>
    using namespace FBB;
    Semaphore produce(10);          // حجم منطقة التخزين
    Semaphore consume(0);           // عدد العناصر في المخزن
    std::queue itemQueue;           // طابور التخزين
    void consumer()
    {
        while (true)
        {
            consume.wait();          // انتظر حتى يكون هناك عنصر في المخزن
                // قفل الطابور باستخدام mutex مع العديد من المستهلكين
            size_t item = itemQueue.front();
            itemQueue.pop();
            produce.notify();   // أبلغ المنتج
            process(item);      // لم يتم تنفيذه
        }
    }
    void producer()
    {
        size_t item = 0;
        while (true)
        {
            ++item;
            produce.wait();     // انتظر مساحة في المخزن
                // قفل الطابور باستخدام mutex مع العديد من المستهلكين
            itemQueue.push(item);
            consume.notify();   // أبلغ المستهلك
        }
    }
    int main()
    {
        thread cons(consumer);
        thread prod(producer);
        cons.join();            // إنهاء الخيوط لم يتم تنفيذه
        prod.join();
    }
