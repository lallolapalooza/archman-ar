selection(n)

الحزمة: tk

التراخيص: TCL

selection(n) Tk Built-In Commands selection(n)

الاسم

selection - التعامل مع تحديد X

الملخص

selection option ?arg arg ...?

الوصف

يوفر هذا الأمر واجهة Tcl لآلية تحديد X وينفذ وظائف التحديد الكاملة الموضحة في بروتوكولات الاتصال بين العملاء في X (X Inter-Client Communication Conventions Manual - ICCCM).

لاحظ أنه لإدارة تحديد CLIPBOARD (انظر أدناه)، يمكن أيضًا استخدام الأمر clipboard.

يحدد الوسيط الأول للأمر selection تنسيق الوسيطات المتبقية وسلوك الأمر. الأشكال التالية مدعومة حاليًا:

selection clear ?-displayof window? ?-selection selection?
إذا كان selection موجودًا في أي مكان في عرض window، فسيتم مسحه بحيث لا تملكه أي نافذة بعد الآن. يحدد Selection التحديد الذي يجب مسحه، ويجب أن يكون اسم ذرة (atom) مثل PRIMARY أو CLIPBOARD؛ راجع دليل اتفاقيات الاتصال بين العملاء للحصول على التفاصيل الكاملة. افتراضيًا، Selection هو PRIMARY و window هو “.”. يُرجع سلسلة فارغة.
selection get ?-displayof window? ?-selection selection? ?-type type?
يسترد قيمة selection من عرض window ويعيدها كنتيجة. افتراضيًا، Selection هو PRIMARY و window هو “.”. يحدد Type الشكل الذي يجب إرجاع التحديد به (الـ"target" المطلوب للتحويل، بمصطلحات ICCCM)، ويجب أن يكون اسم ذرة مثل STRING أو FILE_NAME؛ راجع دليل اتفاقيات الاتصال بين العملاء للحصول على التفاصيل الكاملة. افتراضيًا، Type هو STRING. قد يختار مالك التحديد إرجاع التحديد بأحد التنسيقات التمثيلية المختلفة، مثل STRING، UTF8_STRING، ATOM، INTEGER، إلخ (هذا التنسيق يختلف عن نوع التحديد؛ راجع ICCCM للحصول على كل التفاصيل المحيرة). إذا تم إرجاع التحديد بتنسيق غير نصي، مثل INTEGER أو ATOM، فإن الأمر selection يحوله إلى تنسيق نصي كمجموعة من الحقول مفصولة بمسافات: يتم تحويل الذرات إلى أسمائها النصية، ويتم تحويل أي شيء آخر إلى أعداد صحيحة بالنظام السداسي عشري. لاحظ أن selection get لا يسترد التحديد بتنسيق UTF8_STRING إلا إذا طُلب منه ذلك.
selection handle ?-selection s? ?-type t? ?-format f? window command
ينشئ معالجًا لطلبات التحديد، بحيث يتم تنفيذ command في كل مرة يكون فيها التحديد s مملوكًا بواسطة window ويحاول شخص ما استرداده بالشكل المعطى بواسطة النوع t (على سبيل المثال، يتم تحديد t في الأمر selection get). افتراضيًا، s هو PRIMARY، و t هو STRING، و f هو STRING. إذا كانت command سلسلة فارغة، فسيتم إزالة أي معالج موجود لـ window و t و s. لاحظ أنه عندما يتم التعامل مع التحديد كنوع STRING، يتم التعامل معه أيضًا تلقائيًا كنوع UTF8_STRING.

عند طلب selection، و window هو مالك التحديد، و type هو النوع المطلوب، سيتم تنفيذ command كأمر Tcl مع إضافة رقمين إضافيين إليه (مفصولين بمسافات). الرقمان الإضافيان هما offset و maxChars: يحدد offset موضع حرف البداية في التحديد ويعطي maxChars الحد الأقصى لعدد الأحرف المطلوب استردادها. يجب أن يعيد الأمر قيمة تتكون من maxChars كحد أقصى من التحديد، بدءًا من الموضع offset. بالنسبة للتحديدات الكبيرة جدًا (أكبر من maxChars) سيتم استرداد التحديد باستخدام عدة استدعاءات للأمر command بقيم offset متزايدة. إذا أعاد الأمر command سلسلة طولها أقل من maxChars، فيفترض أن القيمة المرجعة تتضمن باقي التحديد؛ إذا كان طول نتيجة command يساوي maxChars، فسيتم استدعاء command مرة أخرى، حتى يعيد في النهاية نتيجة أقصر من maxChars. قيمة maxChars ستكون دائمًا كبيرة نسبيًا (آلاف الأحرف).

إذا أعاد الأمر command خطأ، فسيتم رفض استرداد التحديد كما لو لم يكن التحديد موجودًا على الإطلاق.

يحدد الوسيط format التمثيل الذي يجب استخدامه لنقل التحديد إلى الطالب (العمود الثاني من الجدول 2 من ICCCM)، وافتراضياته هي STRING. إذا كان format هو STRING، فسيتم نقل التحديد كأحرف ASCII ذات 8 بت (أي فقط بالشكل الذي يعيده command، بتشفير النظام؛ تنسيق UTF8_STRING يستخدم دائمًا UTF-8 كتشفيره). إذا كان format هو ATOM، فسيتم تقسيم القيمة المرجعة من command إلى حقول مفصولة بمسافات بيضاء؛ يتم تحويل كل حقل إلى قيمة الذرة الخاصة به، ويتم نقل قيمة الذرة ذات 32 بت بدلاً من اسم الذرة. لأي format آخر، يتم تقسيم القيمة المرجعة من command إلى حقول مفصولة بمسافات بيضاء ويتم تحويل كل حقل إلى عدد صحيح 32 بت؛ يتم نقل مصفوفة من الأعداد الصحيحة إلى طالب التحديد.

الوسيط format مطلوب فقط للتوافق مع طالبي التحديد الذين لا يستخدمون Tk. إذا تم استخدام Tk لاسترداد التحديد، فسيتم تحويل القيمة مرة أخرى إلى سلسلة نصية في نهاية الطلب، لذلك format غير ذي صلة.

selection own ?-displayof window? ?-selection selection?
selection own ?-command command? ?-selection selection? window
الشكل الأول من selection own يعيد اسم المسار للنافذة في هذا التطبيق التي تمتلك selection على العرض الذي يحتوي على window، أو سلسلة فارغة إذا لم تكن هناك نافذة في هذا التطبيق تمتلك التحديد. افتراضيًا، Selection هو PRIMARY و window هو “.”.

الشكل الثاني من selection own يجعل window المالك الجديد لـ selection على عرض window، ويعيد سلسلة فارغة كنتيجة. يتم إخطار المالك الحالي، إن وجد، بأنه فقد التحديد. إذا تم تحديد command، فهو نص Tcl يتم تنفيذه عندما يدعي نافذة أخرى ملكية التحديد بعيدًا عن window. افتراضيًا، Selection هو PRIMARY.

مرافق الأدوات (WIDGET FACILITIES)

تحتوي أدوات text، entry، ttk::entry، listbox، spinbox و ttk::spinbox على خيار -exportselection. إذا كان لدى أداة هذا الخيار مضبوطًا على القيمة المنطقية true، فعندئذٍ (في مفسر غير آمن) يتم كتابة تحديد في الأداة تلقائيًا إلى تحديد PRIMARY.

يمكن لحدث واجهة رسومية، على سبيل المثال <<PasteSelection>>، نسخ تحديد PRIMARY إلى أدوات معينة. يتم تنفيذ هذه النسخة بواسطة ربط أداة بالحدث. يقوم نص الربط بإجراء استدعاءات مناسبة للأمر selection.

مشكلات قابلية النقل (PORTABILITY ISSUES)

على X11، يعد تحديد PRIMARY ميزة نظام عالمية لخادم X، مما يسمح بالاتصال بين العمليات المختلفة التي هي عملاء X11.

على Windows، لا يتم توفير تحديد PRIMARY بواسطة النظام، ولكن بواسطة Tk فقط، وبالتالي يتم مشاركته فقط بين نوافذ مفسر رئيسي ومفسراته الفرعية. لا تتم مشاركته بين المفسرات في عمليات مختلفة أو خيوط مختلفة. كل مفسر رئيسي لديه تحديد PRIMARY منفصل تتم مشاركته فقط مع مفسراته الفرعية التي ليست مفسرات آمنة.

الأمان (SECURITY)

لا يمكن لمفسر آمن القراءة من تحديد PRIMARY لأن أمر selection الخاص به مخفي. لهذا السبب، التحديد PRIMARY

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

الأمان

لا يمكن كتابة التحديدات إلى عناصر واجهة المستخدم الرسومية لـ Tk في مفسر آمن.

يمكن تعيين خيار -exportselection لعنصر واجهة المستخدم الرسومية لـ Tk على القيمة المنطقية true، ولكن في مفسر آمن، لا يكون لهذا الخيار أي تأثير: يتم تعطيل الكتابة من عنصر واجهة المستخدم الرسومية إلى التحديد PRIMARY.

هذه ميزات أمنية. قد يقوم مفسر آمن بتشغيل تعليمات برمجية غير موثوق بها، ويشكل خطرًا أمنيًا إذا كان هذا الرمز غير الموثوق به يمكنه قراءة أو كتابة التحديد PRIMARY المستخدم بواسطة مفسرات أخرى.

أمثلة

على منصات X11، أحد التحديدات القياسية المتاحة هو التحديد SECONDARY. لا يستخدمه سوى عدد قليل من الأشياء، ولكن إليك كيفية قراءته باستخدام Tk:

set selContents [selection get -selection SECONDARY]

قد تتوفر أنواع مختلفة من البيانات لتحديد؛ النوع الخاص TARGETS يسمح لك بالحصول على قائمة بالأنواع المتاحة:

foreach type [selection get -type TARGETS] {
   puts "Selection PRIMARY supports type $type"
}

للمطالبة بالتحديد، يجب عليك أولاً إعداد معالج لتزويد البيانات للتحديد. ثم يتعين عليك المطالبة بالتحديد...

# Set up the data handler ready for incoming requests
set foo "This is a string with some data in it... blah blah"
selection handle -selection SECONDARY . getData
proc getData {offset maxChars} {
   puts "Retrieving selection starting at $offset"
   return [string range $::foo $offset [expr {$offset+$maxChars-1}]]
}
# Now we grab the selection itself
puts "Claiming selection"
selection own -command lost -selection SECONDARY .
proc lost {} {
   puts "Lost selection"
}
