setreuid(2) دليل استدعاءات النظام setreuid(2)

الاسم

setreuid, setregid - تعيين معرف المستخدم أو المجموعة الحقيقي و/أو الفعلي

المكتبة

مكتبة C القياسية (libc،  -lc)

الخلاصة

#include <unistd.h>
int setreuid(uid_t ruid, uid_t euid);
int setregid(gid_t rgid, gid_t egid);
متطلبات ميزة الاختبار (Feature Test Macro) لـ glibc (انظر feature_test_macros(7)):

setreuid()، setregid():

    _XOPEN_SOURCE >= 500
        || /* منذ glibc 2.19: */ _DEFAULT_SOURCE
        || /* glibc <= 2.19: */ _BSD_SOURCE

الوصف

تقوم setreuid() بتعيين معرفات المستخدم الحقيقية والفعالة للعملية المتصلة.

يوفر قيمة -1 لأي من معرف المستخدم الحقيقي أو الفعلي يجبر النظام على ترك هذا المعرف دون تغيير.

قد يقوم المستخدمون غير المميزين فقط بتعيين معرف المستخدم الفعلي إلى معرف المستخدم الحقيقي، أو معرف المستخدم الفعلي، أو معرف المستخدم المعين المحفوظ.

قد يقوم المستخدمون غير المميزين فقط بتعيين معرف المستخدم الحقيقي إلى معرف المستخدم الحقيقي أو معرف المستخدم الفعلي.

إذا تم تعيين معرف المستخدم الحقيقي (أي، ruid ليس -1) أو تم تعيين معرف المستخدم الفعلي إلى قيمة لا تساوي معرف المستخدم الحقيقي السابق، فسيتم تعيين معرف المستخدم المعين المحفوظ إلى معرف المستخدم الفعلي الجديد.

وبشكل قياسي تمامًا، تقوم setregid() بتعيين معرفات المجموعة الحقيقية والفعالة للعملية المتصلة، وكل ما سبق ينطبق مع استبدال "المستخدم" بـ "المجموعة".

قيمة الإرجاع

عند النجاح، يتم إرجاع صفر. عند حدوث خطأ، يتم إرجاع -1، ويتم تعيين errno للإشارة إلى الخطأ.

ملاحظة: هناك حالات قد تفشل فيها setreuid() حتى عندما يكون المتصل هو UID 0؛ يعد عدم التحقق من فشل الإرجاع من setreuid() خطأً أمنيًا خطيرًا.

الأخطاء

EAGAIN
سيؤدي الاستدعاء إلى تغيير معرف المستخدم الحقيقي للمتصل (أي، ruid لا يتطابق مع معرف المستخدم الحقيقي للمتصل)، ولكن كان هناك فشل مؤقت في تخصيص هياكل بيانات النواة الضرورية.
EAGAIN
ruid لا يتطابق مع معرف المستخدم الحقيقي للمتصل وهذا الاستدعاء سيؤدي إلى تجاوز عدد العمليات التي تنتمي إلى معرف المستخدم الحقيقي ruid فوق حد الموارد RLIMIT_NPROC للمتصل. منذ Linux 3.1، لم يعد هذا الخطأ يحدث (ولكن يجب على التطبيقات القوية التحقق من هذا الخطأ)؛ انظر وصف EAGAIN في execve(2).
EINVAL
أحد معرفات المستخدم أو المجموعة المستهدفة أو أكثر ليس صالحًا في مساحة اسم المستخدم هذه.
EPERM
العملية المتصلة ليست مميزة (في Linux، لا تملك القدرة اللازمة في مساحة اسم المستخدم الخاصة بها: CAP_SETUID في حالة setreuid()، أو CAP_SETGID في حالة setregid()) وتم تحديد تغيير بخلاف (i) تبديل معرف المستخدم (المجموعة) الفعلي مع معرف المستخدم (المجموعة) الحقيقي، أو (ii) تعيين أحدهما لقيمة الآخر، أو (iii) تعيين معرف المستخدم (المجموعة) الفعلي لقيمة معرف المستخدم (المجموعة) المعين المحفوظ.

الإصدارات

لا يحدد POSIX.1 جميع تغييرات معرف المستخدم التي تسمح بها Linux لعملية غير مميزة. بالنسبة لـ setreuid()، يمكن جعل معرف المستخدم الفعلي نفس معرف المستخدم الحقيقي أو معرف المستخدم المعين المحفوظ، ومن غير المحدد ما إذا كان يمكن للمستخدمين غير المميزين تعيين معرف المستخدم الحقيقي إلى معرف المستخدم الحقيقي، أو معرف المستخدم الفعلي، أو معرف المستخدم المعين المحفوظ. بالنسبة لـ setregid()، يمكن تغيير معرف المجموعة الحقيقي إلى قيمة معرف المجموعة المعين المحفوظ، ويمكن تغيير معرف المجموعة الفعلي إلى قيمة معرف المجموعة الحقيقي أو معرف المجموعة المعين المحفوظ. تختلف التفاصيل الدقيقة لتغييرات المعرف المسموح بها عبر التطبيقات.

لا يقدم POSIX.1 أي مواصفات حول تأثير هذه الاستدعاءات على معرف المستخدم المعين المحفوظ ومعرف المجموعة المعين المحفوظ.

المعايير

POSIX.1-2024.

التاريخ

POSIX.1-2001، 4.3BSD (ظهر لأول مرة في 4.2BSD).

تعيين معرف المستخدم (المجموعة) الفعلي إلى معرف المستخدم (المجموعة) المعين المحفوظ ممكن منذ Linux 1.1.37 (1.1.38).

استدعاءات النظام الأصلية لـ Linux setreuid() و setregid() دعمت معرفات مستخدم ومجموعة بحجم 16 بت فقط. لاحقًا، أضاف Linux 2.4 setreuid32() و setregid32()، التي تدعم معرفات بحجم 32 بت. تتعامل دوال التغليف setreuid() و setregid() في glibc بشفافية مع الاختلافات عبر إصدارات النواة.

اختلافات مكتبة C/النواة

على مستوى النواة، تعد معرفات المستخدم والمجموعة سمة لكل مؤشر ترابط (thread). ومع ذلك، يتطلب POSIX أن تشترك جميع مؤشرات الترابط في عملية واحدة في نفس بيانات الاعتماد. يقوم تطبيق مؤشرات الترابط NPTL بمعالجة متطلبات POSIX عن طريق توفير دوال تغليف لاستدعاءات النظام المختلفة التي تغير معرفات المستخدم والمجموعة للعملية. تستخدم دوال التغليف هذه (بما في ذلك تلك الخاصة بـ setreuid() و setregid()) تقنية تعتمد على الإشارات لضمان أنه عندما يغير مؤشر ترابط واحد بيانات الاعتماد، فإن جميع مؤشرات الترابط الأخرى في العملية تغير أيضًا بيانات الاعتماد الخاصة بها. للحصول على التفاصيل، انظر nptl(7).
