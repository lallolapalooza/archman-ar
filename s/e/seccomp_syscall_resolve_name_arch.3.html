seccomp_syscall_resolve_name_arch(3)

الحزمة: libseccomp

التراخيص: LGPL-2.1-only

seccomp_syscall_resolve_name(3) توثيق libseccomp seccomp_syscall_resolve_name(3)

الاسم

seccomp_syscall_resolve_name - حل اسم استدعاء النظام

الملخص

#include <seccomp.h>

int seccomp_syscall_resolve_name(const char *name);
int seccomp_syscall_resolve_name_arch(uint32_t arch_token,
                                      const char *name);
int seccomp_syscall_resolve_name_rewrite(uint32_t arch_token,
                                         const char *name);
char *seccomp_syscall_resolve_num_arch(uint32_t arch_token, int num);

ربط مع -lseccomp.

الوصف

تقوم الدوال seccomp_syscall_resolve_name()، seccomp_syscall_resolve_name_arch()، و seccomp_syscall_resolve_name_rewrite() بحل اسم استدعاء النظام الشائع الاستخدام إلى رقم استدعاء النظام الذي يستخدمه النواة وبقية واجهة برمجة تطبيقات libseccomp، مع وظيفة seccomp_syscall_resolve_name_rewrite() التي تعيد كتابة رقم استدعاء النظام للمعمار يات التي تعدل استدعاء النظام. تحدث إعادة كتابة استدعاء النظام عادةً في حالة استدعاء نظام متعدد، مثل socketcall(2) أو ipc(2) على x86. تقوم وظيفة seccomp_syscall_resolve_num_arch() بحل رقم استدعاء النظام الذي تستخدمه النواة إلى اسم استدعاء النظام الشائع الاستخدام.

المتصل مسؤول عن تحرير السلسلة النصية المرجعة من seccomp_syscall_resolve_num_arch().

قيمة الإرجاع

في حالة seccomp_syscall_resolve_name()، seccomp_syscall_resolve_name_arch()، و seccomp_syscall_resolve_name_rewrite()، يتم إرجاع رقم استدعاء النظام المرتبط، مع إرجاع رقم استدعاء النظام الزائف السالب في الحالات التي لا يكون فيها استدعاء النظام المعطى موجودًا للمعمار ية. يتم إرجاع القيمة __NR_SCMP_ERROR في حالة حدوث خطأ. في جميع الحالات، تكون قيمة الإرجاع مناسبة للاستخدام في أي دالة لواجهة برمجة تطبيقات libseccomp تتطلب رقم استدعاء النظام، وتشمل الأمثلة seccomp_rule_add() و seccomp_rule_add_exact().

في حالة seccomp_syscall_resolve_num_arch()، يتم إرجاع اسم استدعاء النظام المرتبط ويبقى من مسؤولية المتصل تحرير السلسلة النصية المرجعة عبر free(3).

أمثلة

#include <seccomp.h>
int main(int argc, char *argv[])
{
	int rc = -1;
	scmp_filter_ctx ctx;
	ctx = seccomp_init(SCMP_ACT_KILL);
	if (ctx == NULL)
		goto out;
	/* ... */
	rc = seccomp_rule_add(ctx, SCMP_ACT_ALLOW,
	                      seccomp_syscall_resolve_name("open"), 0);
	if (rc < 0)
		goto out;
	/* ... */
	rc = seccomp_load(ctx);
	if (rc < 0)
		goto out;
	/* ... */
out:
	seccomp_release(ctx);
	return -rc;
}

ملاحظات

في حالة استدعاءات النظام العارية المنفذة فوق استدعاء نظام متعدد، يمكن استخدام seccomp_syscall_resolve_name() و seccomp_syscall_resolve_name_arch() للتحقق مما إذا كان استدعاء نظام عارٍ منفذًا لمعمار ية محددة، بينما يمكن استخدام seccomp_syscall_resolve_name_rewrite() لتحديد استدعاء النظام المتعدد الأساسي.

على الرغم من أنه يمكن إنشاء مرشح seccomp بشكل مستقل عن النواة، إلا أن دعم النواة مطلوب لتحميل وفرض مرشح seccomp الذي تم إنشاؤه بواسطة libseccomp.

يمكن العثور على موقع مشروع libseccomp، مع مزيد من المعلومات ومستودع كود المصدر، في https://github.com/seccomp/libseccomp. هذه الأداة، بالإضافة إلى مكتبة libseccomp، قيد التطوير حاليًا، يرجى الإبلاغ عن أي أخطاء في موقع المشروع أو مباشرة إلى المؤلف.
