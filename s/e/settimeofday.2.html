gettimeofday(2) دليل استدعاءات النظام gettimeofday(2)

الاسم

gettimeofday, settimeofday - الحصول / تعيين الوقت

المكتبة

مكتبة C القياسية (libc، -lc)

الملخص

#include <sys/time.h>
[[deprecated]]
int gettimeofday(struct timeval *restrict tv,
                 struct timezone *_Nullable restrict tz);
[[deprecated]]
int settimeofday(const struct timeval *tv,
                 const struct timezone *_Nullable tz);
متطلبات ماكرو اختبار الميزات لـ glibc (انظر feature_test_macros(7)):

settimeofday():

    منذ glibc 2.19:
        _DEFAULT_SOURCE
    glibc 2.19 والإصدارات السابقة:
        _BSD_SOURCE

الوصف

يمكن للدالتين gettimeofday() و settimeofday() الحصول على الوقت وتعيينه بالإضافة إلى المنطقة الزمنية.

الوسيط tv هو struct timeval (كما هو محدد في <sys/time.h>):


struct timeval {
    time_t      tv_sec;     /* ثواني */
    suseconds_t tv_usec;    /* ميكروثواني */
};

ويعطي عدد الثواني والميكروثواني منذ نقطة البداية (Epoch) (انظر time(2)).

الوسيط tz هو struct timezone:


struct timezone {
    int tz_minuteswest;     /* دقائق غرب غرينتش */
    int tz_dsttime;         /* نوع تصحيح التوقيت الصيفي */
};

إذا كان أي من tv أو tz هو NULL، فلن يتم تعيين أو إرجاع الهيكل المقابل. (ومع ذلك، سيحدث تحذيرات عند التجميع إذا كان tv هو NULL).

استخدام هيكل timezone قديم؛ يجب عادةً تحديد الوسيط tz على أنه NULL. انظر الإصدارات (VERSIONS).

تحت Linux، توجد بعض دلالات "التحريك الساعي" الغريبة المرتبطة باستدعاء النظام settimeofday() إذا كان في أول استدعاء (بعد التمهيد) يحتوي على وسيط tz غير NULL، فإن الوسيط tv هو NULL والمجال tz_minuteswest غير صفري. (يجب أن يكون المجال tz_dsttime صفرًا لهذه الحالة.) في مثل هذه الحالة، يُفترض أن ساعة CMOS بالتوقيت المحلي، وأنه يجب زيادتها بهذا المقدار للحصول على وقت نظام UTC. لا شك أن استخدام هذه الميزة فكرة سيئة.

قيمة الإرجاع

gettimeofday() و settimeofday() ترجع 0 للنجاح. عند حدوث خطأ، يتم إرجاع -1 وتعيين errno للإشارة إلى الخطأ.

الأخطاء

EFAULT
أحد tv أو tz أشار خارج مساحة العنوان القابلة للوصول.
EINVAL
(settimeofday()): timezone غير صالح.
EINVAL
(settimeofday()): tv.tv_sec سالب أو tv.tv_usec خارج النطاق [0, 999,999].
EINVAL (منذ Linux 4.3)
(settimeofday()): تم إجراء محاولة لتعيين الوقت إلى قيمة أقل من القيمة الحالية للساعة CLOCK_MONOTONIC (انظر clock_gettime(2)).
EPERM
لدى العملية المستدعية صلاحيات غير كافية لاستدعاء settimeofday()؛ تحت Linux، يلزم امتلاك الصلاحية CAP_SYS_TIME.

الإصدارات

فروقات مكتبة C / النواة

على بعض البنيات، يتم توفير تنفيذ لـ gettimeofday() في vdso(7).

تقبل النواة NULL لكل من tv و tz. تتجاهل glibc و musl الوسيط timezone، ولا تمرره إلى/من النواة. تمرر bionic التابعة لـ Android وسيط timezone إلى/من النواة، ولكن Android لا تحدث المنطقة الزمنية للنواة بناءً على المنطقة الزمنية للجهاز في الإعدادات، لذلك تكون المنطقة الزمنية للنواة عادةً UTC.

المعايير

لا شيء.

التاريخ

SVr4، 4.3BSD. وصفت POSIX.1-2001 gettimeofday() ولكن ليس settimeofday(). تم وضع علامة على POSIX.1-2008 بأن gettimeofday() قديمة، وتوصي باستخدام clock_gettime(2) بدلاً من ذلك. وبالمثل، يجب استخدام clock_settime(2) بدلاً من settimeofday(). ألغى POSIX.1-2024 gettimeofday().

تقليديًا، كانت حقول struct timeval من النوع long.

حقل tz_dsttime

على نواة غير Linux، مع glibc، سيتم تعيين مجال tz_dsttime في struct timezone إلى قيمة غير صفرية بواسطة gettimeofday() إذا كانت المنطقة الزمنية الحالية قد طُبقت عليها قاعدة توقيت صيفي أو ستُطبق عليها. بهذا المعنى، فإنها تعكس تمامًا معنى daylight(3) للمنطقة الحالية. على Linux، مع glibc، لم يتم أبدًا استخدام تعيين مجال tz_dsttime في struct timezone بواسطة settimeofday() أو gettimeofday(). وبالتالي، فإن ما يلي له أهمية تاريخية بحتة.

في الأنظمة القديمة، يحتوي المجال tz_dsttime على ثابت رمزي (القيم معطاة أدناه) يشير إلى أي جزء من العام يكون التوقيت الصيفي ساريًا. (ملاحظة: هذه القيمة ثابتة طوال العام: لا تشير إلى أن التوقيت الصيفي ساري، بل تختار خوارزمية.) خوارزميات التوقيت الصيفي المعرفة هي كما يلي:


DST_NONE     /* ليس في التوقيت الصيفي */
DST_USA      /* توقيت صيفي نمط الولايات المتحدة */
DST_AUST     /* توقيت صيفي نمط أستراليا */
DST_WET      /* توقيت صيفي غرب أوروبا */
DST_MET      /* توقيت صيفي وسط أوروبا */
DST_EET      /* توقيت صيفي شرق أوروبا */
DST_CAN      /* كندا */
DST_GB       /* بريطانيا العظمى وأيرلندا */
DST_RUM      /* رومانيا */
DST_TUR      /* تركيا */
DST_AUSTALT  /* نمط أسترالي مع تغيير في 1986 */

بالطبع، اتضح أن الفترة التي يكون فيها التوقيت الصيفي ساريًا لا يمكن تقديمها بخوارزمية بسيطة، واحدة لكل بلد؛ في الواقع، يتم تحديد هذه الفترة بقرارات سياسية غير متوقعة. لذلك تم التخلي عن هذه الطريقة لتمثيل المناطق الزمنية.

ملاحظات

الوقت الذي تم إرجاعه بواسطة gettimeofday() يتأثر بقفزات غير متقطعة في وقت النظام (على سبيل المثال، إذا قام مسؤول النظام بتغيير وقت النظام يدويًا). إذا كنت بحاجة إلى ساعة متزايدة بشكل رتيب، انظر clock_gettime(2).

يتم وصف وحدات الماكرو للعمل على هياكل timeval في timeradd(3).

NAME

settimeofday - get and set system date and time

LIBRARY

Standard C library (libc, -lc)

SYNOPSIS

#include <sys/time.h>

int settimeofday(const struct timeval *tv, const struct timezone *tz);
int gettimeofday(struct timeval *tv, struct timezone *tz);

DESCRIPTION

The gettimeofday() function fills the tv argument with the current time, as known by the system. The structure timeval is defined in <sys/time.h> as:

struct timeval { time_t tv_sec; /* Seconds */ suseconds_t tv_usec; /* Microseconds */ };

The tv_sec member contains the number of seconds since the Epoch (00:00:00 UTC, January 1, 1970). The tv_usec member contains the microseconds part of the time. The argument tz is unused and must be specified as NULL.

The settimeofday() function sets the system time to the value given by tv. This operation can only be performed by the superuser. If tz is not NULL, it is used to set the system’s timezone.

The structure timezone is defined in <sys/time.h> as:

struct timezone { int tz_minuteswest; /* Minutes west of Greenwich */ int tz_dstamp; /* Seconds east of UTC in non-DST zone or minutes west of UTC (depends on kernel version) */ };

The tz_minuteswest value specifies the number of minutes the local timezone is west of Greenwich. The tz_dstamp value indicates the type of DST correction to apply.

Historically, the timezone structure was used to set and get the system’s timezone. However, this is now deprecated. The tz_dstamp field has had varying meanings across different kernel versions and is not portable. The recommended way to handle timezones is via the tzset() function and the TZ environment variable, or by using the newtime library.

On Linux, the settimeofday() and gettimeofday() functions interact with the kernel’s timekeeping subsystem. The system time can be adjusted using these functions, but large adjustments may cause issues with applications that rely on monotonic time.

Capabilities are often used to control access to these functions. The CAP_SYS_TIME capability is typically required to call settimeofday().

RETURN VALUE

On success, gettimeofday() and settimeofday() return 0. On error, they return -1, and errno is set to indicate the error.

ERRORS

EINVAL
The value specified in tv is not representable.
EFAULT
tv points outside accessible address space.
EPERM
A non-privileged process tried to set the time (see CAP_SYS_TIME).

VERSIONS

The gettimeofday() system call was introduced in BSD. The settimeofday() system call was also introduced in BSD.

The timezone structure and its usage are deprecated and may not be supported in future versions.

STANDARDS

The gettimeofday() function conforms to POSIX.1-2008. The settimeofday() function is not part of POSIX.1 but is widely available on BSD-derived systems and Linux.

HISTORY

The gettimeofday() and settimeofday() functions first appeared in 4.2BSD.

NOTES

Using settimeofday() to change the system time can have unintended consequences for processes that rely on monotonic time (e.g., for timeouts or measuring intervals). Applications should prefer using clock_gettime(3) with CLOCK_MONOTONIC for measuring time intervals.

The timezone argument to settimeofday() is obsolete. On Linux, it is ignored. Timezone information should be managed through other mechanisms, such as the TZ environment variable or configuration files.
