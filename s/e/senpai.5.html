senpai(5)

الحزمة: senpai

التراخيص: ISC

senpai(5) دليل تنسيقات الملفات senpai(5)

الاسم

senpai - تنسيق ملف الإعدادات والإعدادات

الوصف

ملف إعدادات senpai هو ملف scfg. انظر https://git.sr.ht/~emersion/scfg.

بعض الإعدادات مطلوبة، والبعض الآخر اختياري.

الإعدادات

address (مطلوب)

العنوان (host[:port]) لخادم IRC. يستخدم senpai اتصالات TLS افتراضيًا ما لم تحدد الخيار tls ليكون false. اتصالات TLS تستخدم المنفذ 6697 افتراضيًا، والنص العادي يستخدم المنفذ 6667.

يمكن تحديد مخطط اختياري (scheme://host[:port]):

  • irc:// هو الافتراضي الضمني، يتم تمكين TLS أو تعطيله وفقًا لقيمة إعداد tls.
  • ircs:// يُمكّن TLS.
  • irc+insecure:// يعطل TLS (IRC نص عادي).
  • ircs+insecure:// يُمكّن TLS ولكنه يتجاوز التحقق من شهادة TLS. هذا يحمي من هجمات MITM السلبية ولكن ليس من هجمات MITM النشطة.

nickname (مطلوب)

اسم الشهرة الخاص بك، يتم إرساله مع رسالة IRC NICK. يجب ألا يحتوي على مسافات أو نقطتين رأسيتين (:).

realname

اسمك الحقيقي، أو في الواقع مجرد حقل سيكون متاحًا للآخرين وقد يحتوي على مسافات ونقطتين رأسيتين. يتم إرساله مع رسالة IRC USER. افتراضيًا، يتم استخدام قيمة nick.

username

اسم المستخدم الخاص بك، يتم إرساله مع رسالة IRC USER ويستخدم أيضًا للمصادقة SASL. افتراضيًا، يتم استخدام قيمة nick.

password

كلمة المرور الخاصة بك، تستخدم للمصادقة SASL. انظر أيضًا password-cmd.

password-cmd command [arguments...]

بدلاً من تقديم كلمة مرور المصادقة SASL الخاصة بك مباشرة كنص عادي، يمكنك تحديد أمر ليتم تشغيله لجلب كلمة المرور في وقت التشغيل. هذا مفيد إذا كنت تخزن كلمات المرور الخاصة بك في ملف منفصل (مشفر على الأرجح) باستخدام `gpg` أو مدير كلمات مرور سطر الأوامر مثل pass أو gopass. إذا تم توفير password-cmd، فسيتم تجاهل قيمة password وسيتم استخدام السطر الأول من إخراج password-cmd لتسجيل الدخول.

تم اقتباس الأمر والحجج بالفعل بواسطة scfg، لذلك لا حاجة لاقتباس سلسلة الأمر بأكملها بشكل إضافي. على سبيل المثال:

password-cmd pass "Messaging/irc"

channel

قائمة مفصولة بمسافات بأسماء القنوات التي سينضم إليها senpai تلقائيًا عند بدء التشغيل وإعادة الاتصال بالخادم. يمكن تحديد هذا التوجيه عدة مرات.

لا ينبغي استخدام هذا التوجيه عند استخدام bouncer، حيث يتذكر bouncer بالفعل وينضم إلى senpai إلى قنواته المحفوظة تلقائيًا.

highlight

قائمة مفصولة بمسافات بالكلمات الرئيسية التي ستؤدي إلى تشغيل إشعار ومؤشر عرض عند قولها من قبل الآخرين. يمكن تحديد هذا التوجيه عدة مرات.

افتراضيًا، سيستخدم senpai اسم الشهرة الحالي الخاص بك.

on-highlight-beep

تمكين إرسال حرف الجرس (BEL) عند تمييزك. افتراضيًا معطل.

pane-widths { ... }

تكوين عرض الأجزاء المختلفة من واجهة المستخدم.

يتم تعيين عروض الأجزاء كإعدادات فرعية للتوجيه الرئيسي pane-widths:

pane-widths {
    nicknames 16
}
يدعم هذا التوجيه الإعدادات الفرعية التالية:

nicknames

عدد الخلايا التي يشغلها عمود أسماء الشهرة في الجدول الزمني. افتراضيًا 14.

channels

عدد الخلايا التي يشغلها عمود القنوات على الشاشة. افتراضيًا 16. استخدم القيمة الخاصة 0 لجعل قائمة القنوات أفقية. إذا كانت القيمة سالبة، فستكون قائمة القنوات أفقية افتراضيًا وستأخذ قيمة العرض الموجبة (المعاكسة) عند التبديل باستخدام F7.

members

عدد الخلايا التي يشغلها عمود قائمة أعضاء القناة على الشاشة. افتراضيًا 16. استخدم القيمة الخاصة 0 لتعطيلها. إذا كانت القيمة سالبة، فستكون قائمة الأعضاء معطلة افتراضيًا وستأخذ قيمة العرض الموجبة (المعاكسة) عند التبديل باستخدام F8.

text

الحد الأقصى لعرض سطر نص الرسالة، بالخلايا. افتراضيًا، القيمة صفر، مما يعني عدم وجود حد أقصى. مفيد للحفاظ على عرض سطر قابل للقراءة على الشاشات الكبيرة.

tls

تمكين تشفير TLS. افتراضيًا true.

typings

إرسال إشعارات الكتابة التي تخبر الآخرين عندما تكون تكتب رسالة. افتراضيًا true.

mouse

تمكين أو تعطيل دعم الماوس. افتراضيًا true.

colors { ... }

إعدادات ألوان عناصر واجهة المستخدم المختلفة.

يمكن تعيين الألوان إما بالاسم ("red")، أو بالرقم (من 0 إلى 255، لألوان الطرفية الافتراضية الـ 256؛ -1 يعني الافتراضي)، أو بلون RGB الحقيقي (#rrggbb).

يتم تعيين الألوان كإعدادات فرعية للتوجيه الرئيسي colors:

colors {
    prompt green
}
إعداد فرعي الوصف
prompt <color> لون موجه ">" الذي يظهر في وضع الأوامر
unread <color> لون المقدمة لأسماء المخازن غير المقروءة في قوائم المخازن
status [...] لون المقدمة لأسطر أحداث الحالة (مثل الانضمام، المغادرة، تغييرات اسم الشهرة) في المخازن، انظر الجدول أدناه
nicks [...] نظام ألوان لأسماء الشهرة للمستخدمين، انظر الجدول أدناه
إعداد فرعي status الوصف
status <color> عرض أحداث الحالة باللون المحدد
status disabled إخفاء أحداث الحالة
إعداد فرعي nicks الوصف
nicks base عرض أسماء الشهرة بـ 16 لونًا مختلفًا (افتراضي)
nicks extended عرض أسماء الشهرة بـ 256 لونًا مختلفًا
nicks fixed [<others>] عرض أسماء الشهرة بلون ثابت، مع تحديد اختياري لألوان أسماء الشهرة الأخرى
nicks self <self> عرض اسم الشهرة الخاص بك بلون ثابت ومحدد (يمكن إضافته مع توجيهات أخرى)

debug

متقدم. تفريغ جميع البيانات المرسلة والمستلمة إلى المخزن المؤقت الرئيسي، مفيد لتصحيح الأخطاء. افتراضيًا false.

-transient

متقدم. تشغيل نسخة عابرة دون قراءة/كتابة القرص (باستثناء إعداد التكوين الأولي). يمكن أن يكون مفيدًا للنسخ العامة. افتراضيًا false.

-local-integrations

متقدم. يُمكّن التكامل مع النظام المحلي (مثل الإشعارات عبر DBus). يمكن أن يكون مفيدًا لتعطيله على الأنظمة المخطط لاستخدامها عبر SSH. افتراضيًا true.

on-highlight-path

متقدم. سيقوم senpai بإعلامك افتراضيًا دون الحاجة إلى برنامج نصي مخصص للإبراز. مسار بديل لبرنامج نصي shell ليتم تنفيذه عند تمييزك. افتراضيًا، يبحث senpai عن برنامج نصي shell للإبراز في $XDG_CONFIG_HOME/senpai/highlight. إذا لم يتم العثور على ملف في هذا المسار، ولم يتم توفير مسار بديل، فسيتم تعطيل تنفيذ أمر الإبراز.

إذا لم يتم تعيينه، فإن $XDG_CONFIG_HOME افتراضيًا إلى ~/.config/.

قبل تنفيذ البرنامج النصي للإبراز، يتم ملء متغيرات البيئة التالية:

يجب على البرامج النصية لـ Shell التأكد من أن المتغيرات تظهر مقتبسة في ملف البرنامج النصي، أو ستكون عرضة لهجمات حقن shell! يجب أن تضمن البرامج النصية لـ Shell أيضًا عدم توسيع أحرف مثل '*' و '؟'.

متغير البيئة الوصف
BUFFER المخزن الذي ظهرت فيه الرسالة
HERE يساوي 1 إذا كان BUFFER هو المخزن الحالي، 0 بخلاف ذلك
MESSAGE محتوى الرسالة
