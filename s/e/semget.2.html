semget(2)

semget(2) دليل استدعاءات النظام semget(2)

الاسم

semget - الحصول على معرف مجموعة سيمافورات النظام V

المكتبة

مكتبة C القياسية (libc، -lc)

الملخص

#include <sys/sem.h>

int semget(key_t key, int nsems, int semflg);

الوصف

يقوم استدعاء النظام semget() بإرجاع معرف مجموعة سيمافورات النظام V المرتبط بالوسيط key. يمكن استخدامه إما للحصول على معرف مجموعة سيمافورات تم إنشاؤها مسبقًا (عندما تكون semflg صفر ولا تمتلك key القيمة IPC_PRIVATE)، أو لإنشاء مجموعة جديدة.

يتم إنشاء مجموعة جديدة من nsems سيمافور إذا كانت key تمتلك القيمة IPC_PRIVATE أو إذا لم تكن هناك مجموعة سيمافورات موجودة مرتبطة بـ key وتم تحديد IPC_CREAT في semflg.

إذا حددت semflg كلًا من IPC_CREAT و IPC_EXCL وكانت هناك مجموعة سيمافورات موجودة بالفعل لـ key، فسيفشل semget() مع تعيين errno إلى EEXIST. (هذا يشبه تأثير الجمع O_CREAT | O_EXCL لـ open(2).)

عند إنشاء مجموعة سيمافورات جديدة، يقوم semget() بتهيئة بنية بيانات المجموعة المرتبطة، semid_ds (انظر semctl(2))، على النحو التالي:

•
sem_perm.cuid و sem_perm.uid يتم تعيينهما إلى معرف المستخدم الفعلي للعملية المستدعية.
•
sem_perm.cgid و sem_perm.gid يتم تعيينهما إلى معرف المجموعة الفعلي للعملية المستدعية.
•
أقل 9 بتات أهمية من sem_perm.mode يتم تعيينها إلى أقل 9 بتات أهمية من semflg.
•
sem_nsems يتم تعيينها إلى قيمة nsems.
•
sem_otime يتم تعيينها إلى 0.
•
sem_ctime يتم تعيينها إلى الوقت الحالي.

يمكن أن تكون الوسيط nsems 0 (لا تهتم) عندما لا يتم إنشاء مجموعة سيمافورات. بخلاف ذلك، يجب أن تكون nsems أكبر من 0 وأقل من أو تساوي الحد الأقصى لعدد السيمافورات لكل مجموعة سيمافورات (SEMMSL).

إذا كانت مجموعة السيمافورات موجودة بالفعل، يتم التحقق من الأذونات.

قيمة الإرجاع

عند النجاح، يعيد semget() معرف مجموعة السيمافورات (عدد صحيح غير سالب). عند الفشل، يتم إرجاع -1، ويتم تعيين errno للإشارة إلى الخطأ.

الأخطاء

EACCES
توجد مجموعة سيمافورات لـ key، ولكن العملية المستدعية ليس لديها إذن للوصول إلى المجموعة، ولا تمتلك صلاحية CAP_IPC_OWNER في مساحة اسم المستخدم التي تحكم مساحة اسم IPC الخاصة بها.
EEXIST
تم تحديد IPC_CREAT و IPC_EXCL في semflg، ولكن توجد بالفعل مجموعة سيمافورات لـ key.
EINVAL
nsems أقل من 0 أو أكبر من الحد الأقصى لعدد السيمافورات لكل مجموعة سيمافورات (SEMMSL).
EINVAL
توجد بالفعل مجموعة سيمافورات مقابلة لـ key، ولكن nsems أكبر من عدد السيمافورات في تلك المجموعة.
ENOENT
لا توجد مجموعة سيمافورات لـ key ولم تحدد semflg IPC_CREAT.
ENOMEM
يجب إنشاء مجموعة سيمافورات ولكن النظام لا يمتلك ما يكفي من الذاكرة للبنية البيانات الجديدة.
ENOSPC
يجب إنشاء مجموعة سيمافورات ولكن الحد الأقصى للنظام لعدد مجموعات السيمافورات (SEMMNI)، أو الحد الأقصى للنظام لعدد السيمافورات (SEMMNS)، سيتم تجاوزه.

المعايير

POSIX.1-2024.

التاريخ

SVr4، POSIX.1-2001.

ملاحظات

IPC_PRIVATE ليست حقل علامة بل نوع key_t. إذا تم استخدام هذه القيمة الخاصة لـ key، فإن استدعاء النظام يتجاهل كل شيء ما عدا أقل 9 بتات أهمية من semflg وينشئ مجموعة سيمافورات جديدة (عند النجاح).

تهيئة السيمافور

قيم السيمافورات في مجموعة تم إنشاؤها حديثًا غير محددة. (POSIX.1-2001 و POSIX.1-2008 صريحان بشأن هذه النقطة، على الرغم من أن POSIX.1-2008 يلاحظ أن إصدارًا مستقبليًا من المعيار قد يتطلب من التنفيذ تهيئة السيمافورات إلى 0.) على الرغم من أن Linux، مثل العديد من التطبيقات الأخرى، يقوم بتهيئة قيم السيمافورات إلى 0، إلا أن التطبيق القابل للنقل لا يمكنه الاعتماد على ذلك: يجب عليه تهيئة السيمافورات صراحةً إلى القيم المطلوبة.

يمكن إجراء التهيئة باستخدام العملية SETVAL أو SETALL الخاصة بـ semctl(2). حيث لا تعرف الأطراف المتعددة من سيقوم بتهيئة المجموعة أولاً، يمكن استخدام التحقق من sem_otime غير الصفرية في بنية البيانات المرتبطة التي تم استردادها بواسطة عملية semctl(2) IPC_STAT لتجنب حالات السباق.

حدود السيمافور

تؤثر حدود موارد مجموعات السيمافورات التالية على استدعاء semget():

SEMMNI
الحد الأقصى على مستوى النظام لعدد مجموعات السيمافورات. قبل Linux 3.19، كانت القيمة الافتراضية لهذا الحد 128. منذ Linux 3.19، القيمة الافتراضية هي 32,000. على Linux، يمكن قراءة هذا الحد وتعديله عبر الحقل الرابع من /proc/sys/kernel/sem.
SEMMSL
الحد الأقصى لعدد السيمافورات لكل معرف سيمافور. قبل Linux 3.19، كانت القيمة الافتراضية لهذا الحد 250. منذ Linux 3.19، القيمة الافتراضية هي 32,000. على Linux، يمكن قراءة هذا الحد وتعديله عبر الحقل الأول من /proc/sys/kernel/sem.
SEMMNS
الحد الأقصى على مستوى النظام لعدد السيمافورات: يعتمد على السياسة (على Linux، يمكن قراءة هذا الحد وتعديله عبر الحقل الثاني من /proc/sys/kernel/sem). لاحظ أن عدد السيمافورات على مستوى النظام محدود أيضًا بضرب SEMMSL و SEMMNI.

أخطاء

ربما كان اختيار الاسم IPC_PRIVATE مؤسفًا، IPC_NEW كان سيظهر وظيفته بشكل أوضح.

أمثلة

يستخدم البرنامج الموضح أدناه semget() لإنشاء مجموعة سيمافورات جديدة أو استرداد معرف مجموعة موجودة. يقوم بتوليد key لـ semget() باستخدام ftok(3). تُستخدم وسيطات سطر الأوامر الأولى والخاصة بالوسيطين كوسائط pathname و proj_id لـ ftok(3). الوسيط الثالث لسطر الأوامر هو عدد صحيح يحدد الوسيط nsems لـ semget(). يمكن استخدام خيارات سطر الأوامر لتحديد علامات IPC_CREAT (-c) و IPC_EXCL (-x) لاستدعاء semget(). يتم توضيح استخدام هذا البرنامج أدناه.

NAME

semget - create or access a semaphore set

LIBRARY

Realtime semaphore functions (librt), but before glibc 2.26 it was often linked with libpthread.

SYNOPSIS

#include <sys/types.h>
#include <sys/ipc.h>
#include <sys/sem.h>
int semget(key_t key, int nsems, int semflg);

DESCRIPTION

The semget function returns the identifier of a semaphore set, or it creates a new semaphore set. The semid is used in subsequent calls to semctl(2) and semop(2).

The key argument is a key used to obtain a semaphore set identifier. It is usually generated using ftok(3). If key is IPC_PRIVATE, a new semaphore set is created, and the caller will be able to access it if it has appropriate permissions.

The nsems argument specifies the number of semaphores in the set. This argument is only relevant if a new semaphore set is to be created (i.e., if IPC_CREAT is specified in semflg). If a new semaphore set is being created and nsems is zero, then it is set to the implementation limit.

The semflg argument specifies the requested access permissions and creation flags. It is a bitmask that includes one or more of the following flags:

IPC_CREAT
Create the semaphore set if it does not exist. If the set already exists, this flag has no effect, unless IPC_EXCL is also specified.
IPC_EXCL
If this flag is specified along with IPC_CREAT, then if the semaphore set already exists, semget will fail, and set errno to EEXIST. This is useful for preventing race conditions.

In addition to IPC_CREAT and IPC_EXCL, semflg may include permission bits. These are the low 9 bits, interpreted as octal numbers: 0600 (read/write for owner).

When semget is called, it checks if a semaphore set corresponding to the given key exists. If it does, it checks if the calling process has permission to access it. The access permissions are checked based on the key: 0400 (read for caller), 0200 (write for caller). If key is IPC_PRIVATE, a new set is created. If the set already exists and IPC_CREAT is not set, the existing set is returned. If IPC_CREAT is set and the set does not exist, a new set is created.

If a new set is created, the semid is returned, and the system initializes the data structure associated with the set. The nsems argument specifies the number of semaphores in the set to be created. The system initializes the semaphore set's sem_nsems field to this value. The sem_perm.uid and sem_perm.gid fields are set to the real UID and GID of the calling process. The sem_perm.cuid and sem_perm.cgid fields are set to the UID and GID of the calling process. The sem_perm.mode field is set to the low 9 bits of semflg.

RETURN VALUE

On success, semget returns the semaphore set identifier (a nonnegative integer). On failure, it returns -1 and sets errno to indicate the error.

ERRORS

EACCES
A semaphore set exists for the given key, but the calling process does not have permission to access it.
EEXIST
IPC_CREAT and IPC_EXCL flags were specified, but a semaphore set already exists for the given key.
ENOENT
No semaphore set exists for the given key, and IPC_CREAT was not specified.
EINVAL
key is not valid, or nsems is negative or too large.
ENOSPC
A new semaphore set was to be created, but the system limit on the number of semaphore sets has been reached.
ENOMEM
A new semaphore set was to be created, but the system ran out of memory.

STANDARDS

POSIX.1-2008.

HISTORY

System V IPC.

NOTES

The semflg argument can be constructed by ORing IPC_CREAT and/or IPC_EXCL with permission bits. The permission bits are:

    0400 Read by owner
    0200 Write by owner
    0040 Read by group
    0020 Write by group
    0004 Read by others
    0002 Write by others

The key argument is typically generated using ftok(3), which generates a key based on a pathname and a project identifier. The same key can be generated from different paths if those paths refer to the same inode. This can lead to collisions, where different paths unintentionally map to the same semaphore set.

The maximum number of semaphores per set and the maximum number of semaphore sets system-wide are implementation-dependent. These limits can be checked using sysconf(3) with the _SC_SEM_NSEMS_MAX and _SC_SEM_SETSIZE_MAX options, respectively.

When creating a new semaphore set, the nsems argument is used to specify the number of semaphores in the set. If nsems is 0, the system uses the implementation-defined maximum number of semaphores per set.

The key argument can also be IPC_PRIVATE. If key is IPC_PRIVATE, a new semaphore set is created, and the returned semid is unique. The caller will be able to access this set if it has the appropriate permissions.

The semget function is not thread-safe if multiple threads call it concurrently with the same key and IPC_CREAT flag without proper synchronization. This can lead to race conditions where multiple threads might create duplicate semaphore sets or incorrectly access existing ones.

EXAMPLE

We first create two files that will be used to generate keys using ftok(3), create two semaphore sets using those files, and then list the sets using ipcs(1):


$ touch mykey mykey2;
$ ./t_semget -c mykey p 1;
ID = 9
$ ./t_semget -c mykey2 p 2;
ID = 10
$ ipcs -s;
------ Semaphore Arrays --------
key        semid      owner      perms      nsems
0x7004136d 9          mtk        600        1
0x70041368 10         mtk        600        2

Next, we demonstrate that when semctl(2) is given the same key (as generated by the same arguments to ftok(3)), it returns the ID of the already existing semaphore set:


$ ./t_semget -c mykey p 1;
ID = 9

Finally, we demonstrate the kind of collision that can occur when ftok(3) is given different pathname arguments that have the same inode number:


$ ln mykey link;
$ ls -i1 link mykey;
2233197 link
2233197 mykey
$ ./t_semget link p 1;       # Generates same key as 'mykey'
ID = 9

/* t_semget.c

#include <stdio.h>
#include <stdlib.h>
#include <sys/ipc.h>
#include <sys/sem.h>
#include <unistd.h>
static void
usage(const char *pname)
{
    fprintf(stderr, "Usage: %s [-cx] pathname proj-id num-sems\n",
            pname);
    fprintf(stderr, "    -c           Use IPC_CREAT flag\n");
    fprintf(stderr, "    -x           Use IPC_EXCL flag\n");
    exit(EXIT_FAILURE);
}
int
main(int argc, char *argv[])
{
    int    semid, nsems, flags, opt;
    key_t  key;
    flags = 0;
    while ((opt = getopt(argc, argv, "cx")) != -1) {
        switch (opt) {
        case 'c': flags |= IPC_CREAT;   break;
        case 'x': flags |= IPC_EXCL;    break;
        default:  usage(argv[0]);
        }
    }
    if (argc != optind + 3)
        usage(argv[0]);
    key = ftok(argv[optind], argv[optind + 1][0]);
    if (key == -1) {
        perror("ftok");
        exit(EXIT_FAILURE);
    }
    nsems = atoi(argv[optind + 2]);
    semid = semget(key, nsems, flags | 0600);
    if (semid == -1) {
        perror("semget");
        exit(EXIT_FAILURE);
    }
    printf("ID = %d\n", semid);
    exit(EXIT_SUCCESS);
}
