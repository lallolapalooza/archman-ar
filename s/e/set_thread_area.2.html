set_thread_area(2) دليل استدعاءات النظام set_thread_area(2)

الاسم

get_thread_area, set_thread_area - معالجة معلومات مساحة تخزين الخيط المحلية

المكتبة

مكتبة C القياسية (libc، -lc)

الملخص

#include <sys/syscall.h>     /* تعريف ثوابت SYS_* */
#include <unistd.h>
#if defined __i386__ || defined __x86_64__
# include <asm/ldt.h>        /* تعريف struct user_desc */
int syscall(SYS_get_thread_area, struct user_desc *u_info);
int syscall(SYS_set_thread_area, struct user_desc *u_info);
#elif defined __m68k__
int syscall(SYS_get_thread_area);
int syscall(SYS_set_thread_area, unsigned long tp);
#elif defined __mips__ || defined __csky__
int syscall(SYS_set_thread_area, unsigned long addr);
#endif

ملاحظة: لا توفر glibc دوال مساعدة لهذه الاستدعاءات النظامية، مما يجعل استخدام syscall(2) ضروريًا.

الوصف

توفر هذه الاستدعاءات دعمًا خاصًا بالبنية لتنفيذ مساحة تخزين الخيط المحلية. في الوقت الحالي، set_thread_area() متوفرة على m68k و MIPS و C-SKY و x86 (كلا النوعين 32 بت و 64 بت)؛ get_thread_area() متوفرة على m68k و x86.

على m68k و MIPS و C-SKY، تسمح set_thread_area() بتخزين مؤشر عشوائي (مقدم في الوسيط tp على m68k وفي الوسيط addr على MIPS و C-SKY) في بنية بيانات النواة المرتبطة بالخيط المستدعي؛ يمكن استرداد هذا المؤشر لاحقًا باستخدام get_thread_area() (انظر أيضًا ملاحظات للحصول على معلومات تتعلق بالحصول على مؤشر الخيط على MIPS).

على x86، تخصص Linux ثلاث إدخالات في جدول الواصفات العام (GDT) لمساحة تخزين الخيط المحلية. لمزيد من المعلومات حول GDT، راجع دليل مطوري برامج Intel أو دليل برمجة بنية AMD.

تأخذ كلتا هاتين الاستدعاءات النظامية وسيطًا هو مؤشر إلى بنية من النوع التالي:


struct user_desc {
    unsigned int  entry_number;
    unsigned int  base_addr;
    unsigned int  limit;
    unsigned int  seg_32bit:1;
    unsigned int  contents:2;
    unsigned int  read_exec_only:1;
    unsigned int  limit_in_pages:1;
    unsigned int  seg_not_present:1;
    unsigned int  useable:1;
#ifdef __x86_64__
    unsigned int  lm:1;
#endif
};

get_thread_area() تقرأ إدخال GDT المحدد بواسطة u_info->entry_number وتملأ الحقول الأخرى في u_info.

set_thread_area() تعيّن إدخال TLS في GDT.

إدخال مصفوفة TLS الذي تم تعيينه بواسطة set_thread_area() يتوافق مع قيمة u_info->entry_number التي تم تمريرها من قبل المستخدم. إذا كانت هذه القيمة ضمن الحدود، فإن set_thread_area() تكتب الواصف TLS المشار إليه بواسطة u_info في مصفوفة TLS الخاصة بالخيط.

عند تمرير entry_number بالقيمة -1 إلى set_thread_area()، فإنها تبحث عن إدخال TLS مجاني. إذا وجدت set_thread_area() إدخال TLS مجانيًا، يتم تعيين قيمة u_info->entry_number عند الإرجاع لإظهار أي إدخال تم تغييره.

يعتبر user_desc "فارغًا" إذا تم تعيين read_exec_only و seg_not_present إلى 1 وجميع الحقول الأخرى هي 0. إذا تم تمرير واصف "فارغ" إلى set_thread_area()، فسيتم مسح إدخال TLS المقابل. انظر الأخطاء لمزيد من التفاصيل.

منذ Linux 3.19، لا يمكن استخدام set_thread_area() لكتابة مقاطع غير موجودة، أو مقاطع 16 بت، أو مقاطع التعليمات البرمجية، على الرغم من أن مسح المقطع لا يزال مقبولًا.

قيمة الإرجاع

على x86، تعيد استدعاءات النظام هذه 0 عند النجاح، و -1 عند الفشل، مع تعيين errno للإشارة إلى الخطأ.

على C-SKY و MIPS و m68k، تعيد set_thread_area() دائمًا 0. على m68k، تعيد get_thread_area() قيمة مؤشر مساحة الخيط (تم تعيينها سابقًا عبر set_thread_area()).

الأخطاء

EFAULT
u_info هو مؤشر غير صالح.
EINVAL
u_info->entry_number خارج الحدود.
ENOSYS
تم استدعاء get_thread_area() أو set_thread_area() كاستدعاء نظام 64 بت.
ESRCH
(set_thread_area()) لم يتم العثور على إدخال TLS مجاني.

ملاحظات

عادةً ما تكون استدعاءات النظام هذه مخصصة فقط لمكتبات الخيوط.

arch_prctl(2) يمكن أن تتداخل مع set_thread_area() على x86. انظر arch_prctl(2) لمزيد من التفاصيل. هذا ليس مشكلة عادةً، حيث أن arch_prctl(2) يستخدم عادةً فقط بواسطة برامج 64 بت.

على MIPS، يمكن الحصول على القيمة الحالية لمؤشر مساحة الخيط باستخدام التعليمات:


rdhwr dest, $29

هذه التعليمات تقفز ويتم التعامل معها بواسطة النواة.

أخطاء

على النوى 64 بت قبل Linux 3.19، كانت إحدى بتات الحشو في user_desc، إذا تم تعيينها، تمنع الواصف من اعتباره فارغًا (انظر modify_ldt(2)). ونتيجة لذلك، فإن الطريقة الموثوقة الوحيدة لمسح إدخال TLS هي استخدام memset(3) لمسح بنية user_desc بأكملها، بما في ذلك بتات الحشو، ثم تعيين بتات read_exec_only و seg_not_present. على Linux 3.19، سيتم أيضًا تفسير user_desc المكون من أصفار باستثناء entry_number كطلب لمسح إدخال TLS، ولكن هذا كان يتصرف بشكل مختلف على النوى الأقدم.

قبل Linux 3.19، يجب ألا تشير مسجلات مقاطع DS و ES إلى إدخالات TLS.
