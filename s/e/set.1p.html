هذا الخيار مدعوم إذا كان النظام يدعم خيار أدوات قابلية نقل المستخدم. سيقوم بتعيين خيارات مختلفة، والتي سيكون العديد منها مكافئًا لأحرف الخيارات الفردية. يجب دعم القيم التالية لـ option:
allexport
مكافئ لـ -a.
errexit
مكافئ لـ -e.
ignoreeof
يمنع الإنهاء التفاعلي للصدفة عند نهاية الملف. يمنع هذا الإعداد تسجيل الخروج العرضي عند إدخال <control>‐D. يجب على المستخدم الخروج صراحةً لترك الصدفة التفاعلية.
monitor
مكافئ لـ -m. هذا الخيار مدعوم إذا كان النظام يدعم خيار أدوات قابلية نقل المستخدم.
noclobber
مكافئ لـ -C (حرف C كبير).
noglob
مكافئ لـ -f.
noexec
مكافئ لـ -n.
nolog
يمنع إدخال تعريفات الوظائف في سجل الأوامر؛ انظر سجل الأوامر.
notify
مكافئ لـ -b.
nounset
مكافئ لـ -u.
verbose
مكافئ لـ -v.
vi
يسمح بتحرير سطر أوامر الصدفة باستخدام محرر vi المدمج. سيؤدي تمكين وضع vi إلى تعطيل أي وضع آخر لتحرير سطر الأوامر يتم توفيره كامتداد تنفيذي.

قد لا يكون من الممكن تعيين وضع vi في أطراف طرفية معينة ذات وضع كتلة.

xtrace
مكافئ لـ -x.
-u
عندما تحاول الصدفة توسيع متغير غير معين بخلاف المتغيرين الخاصين '@' و '*'، ستكتب رسالة إلى الخطأ القياسي وسيفشل التوسيع مع العواقب المحددة في القسم 2.8.1، عواقب أخطاء الصدفة.
-v
ستكتب الصدفة مدخلاتها إلى الخطأ القياسي أثناء قراءتها.
-x
ستكتب الصدفة إلى الخطأ القياسي تتبعًا لكل أمر بعد توسيعه وقبل تنفيذه. غير محدد ما إذا كان الأمر الذي يوقف التتبع سيتم تتبعه.

الافتراضي لجميع هذه الخيارات سيكون مغلقًا (غير معين) ما لم يُذكر خلاف ذلك في وصف الخيار أو ما لم تم استدعاء الصدفة بها؛ انظر sh.

سيتم تعيين الوسيطات المتبقية بالترتيب إلى المعلمات الموضعية. سيتم تعيين المعلمة الخاصة '#' لتعكس عدد المعلمات الموضعية. سيتم إلغاء تعيين جميع المعلمات الموضعية قبل تعيين أي قيم جديدة.

إذا كانت الوسيطة الأولى هي '-'، فإن النتائج غير محددة.

يمكن استخدام الوسيطة الخاصة "--" مباشرة بعد اسم الأمر set للفصل بين الوسيطات إذا بدأت الوسيطة الأولى بـ '+' أو '-'، أو لمنع الإدراج غير المقصود لجميع متغيرات الصدفة عندما لا تكون هناك وسيطات. الأمر set -- بدون argument سيقوم بإلغاء تعيين جميع المعلمات الموضعية وتعيين المعلمة الخاصة '#' إلى الصفر.

استخدام التطبيق

يجب على كُتاب التطبيقات تجنب الاعتماد على set -e داخل الوظائف. على سبيل المثال، في البرنامج النصي التالي:

set -e
start() {
    some_server
    echo some_server started successfully
}
start || echo >&2 some_server failed

يتم تجاهل إعداد -e داخل جسم الوظيفة (لأن الوظيفة هي أمر في قائمة AND-OR بخلاف الأخيرة). لذلك، إذا فشل some_server، تستمر الوظيفة في طباعة "some_serverstartedsuccessfully"، وحالة خروج الوظيفة هي صفر (مما يعني أن "some_serverfailed" لم يتم إخراجه).

أمثلة

طباعة جميع المتغيرات وقيمها:

set

تعيين $1، $2، و $3 وتعيين "$#" إلى 3:

set c a b

تشغيل الخيارين -x و -v:

set -xv

إلغاء تعيين جميع المعلمات الموضعية:

set --

تعيين $1 إلى قيمة x، حتى لو بدأت بـ '-' أو '+':

set -- "$x"

تعيين المعلمات الموضعية لتوسيع x، حتى لو توسعت x بـ '-' أو '+':

set -- $x

المنطق

تم إدراج شكل set -- على وجه التحديد في الـ SYNOPSIS على الرغم من أن هذا الاستخدام ضمني في إرشادات بناء الجملة للأدوات. يزيل شرح هذه الميزة أي غموض حول ما إذا كان يمكن إساءة تفسير شكل set -- على أنه مكافئ لـ set بدون أي خيارات أو وسيطات. تم اعتماد وظيفة هذا الشكل من KornShell. في System V، يقوم set -- فقط بإلغاء تعيين المعلمات إذا كان هناك وسيطة واحدة على الأقل؛ الطريقة الوحيدة لإلغاء تعيين جميع المعلمات هي استخدام shift. لا ينبغي أن يؤثر استخدام إصدار KornShell على برامج System V النصية لأنه لا ينبغي أن يكون هناك سبب لإصداره بدون وسيطات عمدًا؛ إذا تم إصداره على سبيل المثال:

set -- "$@"

وإذا لم تكن هناك في الواقع وسيطات ناتجة عن "$@"، فلن يكون لإلغاء تعيين المعلمات أي نتيجة.

تم حذف شكل set + في المقترحات المبكرة باعتباره تكرارًا غير ضروري لـ set وحده ولم يكن ممارسة تاريخية واسعة الانتشار.

تم تغيير خيار noclobber للسماح بـ set -C بالإضافة إلى خيار set -o noclobber. تمت إضافة الإصدار المكون من حرف واحد حتى لا يتم كسر اصطلاح "$-" التاريخي؛ انظر القسم 2.5.2، المعلمات الخاصة.

الغرض من وصف خيار -e هو مطابقة سلوك إصدار 1988 من KornShell.

العلامة -h مرتبطة بتجزئة أسماء الأوامر. انظر hash.

تم حذف أعلام set التالية عمدًا مع المنطق التالي:

-k
تمت إضافة العلامة -k في الأصل من قبل مؤلف Bourne shell لتسهيل الأمر على مستخدمي الإصدارات قبل الإصدارات التجريبية للصدفة. في الإصدارات المبكرة من Bourne shell، كان يجب استخدام البناء set name=value لتعيين قيم لمتغيرات الصدفة. المشكلة مع -k هي أن السلوك يؤثر على التحليل، مما يمنع كتابة أي مترجمات بشكل فعال. لشرح سلوك -k، من الضروري وصف خوارزمية التحليل، وهي معرفة بالتنفيذ. على سبيل المثال:
set -k; echo name=value

و:

set -k
echo name=value

يتصرفان بشكل مختلف. التفاعل مع الوظائف أكثر تعقيدًا. علاوة على ذلك، لا يلزم استخدام العلامة -k أبدًا، حيث يمكن إعادة ترتيب سطر الأوامر.

-t
يصعب تحديد العلامة -t ويكاد لا تستخدم أبدًا. يمكن إجراء الاستخدام الوحيد المعروف مع المستندات النصية. علاوة على ذلك، يختلف السلوك مع ksh و sh. تنص صفحة المرجع على أنها تخرج بعد قراءة وتنفيذ أمر واحد. ما هو أمر واحد؟ إذا كان الإدخال هو date;date، فإن sh ينفذ كلا الأمرين date بينما يقوم ksh بالأمر الأول فقط.
