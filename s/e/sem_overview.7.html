الاسم

sem_overview — نظرة عامة على C semaphores POSIX

الوصف

تسمح C semaphores POSIX للعمليات والخيوط بمزامنة إجراءاتها.

C semaphore هو عدد صحيح لا يُسمح لقيمته أبدًا بأن تقل عن الصفر. يمكن إجراء عمليتين على C semaphores: زيادة قيمة C semaphore بمقدار واحد (sem_post(3))؛ وتقليل قيمة C semaphore بمقدار واحد (sem_wait(3)). إذا كانت قيمة C semaphore حاليًا صفرًا، فإن عملية sem_wait(3) ستتعطل حتى تصبح القيمة أكبر من الصفر.

تأتي C semaphores POSIX في شكلين: C semaphores مسماة و C semaphores غير مسماة.

C semaphores مسماة
يتم تحديد C semaphore مسماة باسم بالشكل /somename؛ أي، سلسلة منتهية بصفر يصل طولها إلى NAME_MAX-4 (أي 251) حرف تتكون من شرطة مائلة أولية، تتبعها حرف واحد أو أكثر، ولا يكون أي منها شرطة مائلة. يمكن لعمليتين العمل على نفس C semaphore المسماة بتمرير نفس الاسم إلى sem_open(3).
تقوم الدالة sem_open(3) بإنشاء C semaphore مسماة جديدة أو فتح C semaphore مسماة موجودة. بعد فتح C semaphore، يمكن العمل عليها باستخدام sem_post(3) و sem_wait(3). عندما تنتهي عملية من استخدام C semaphore، يمكنها استخدام sem_close(3) لإغلاق C semaphore. عندما تنتهي جميع العمليات من استخدام C semaphore، يمكن إزالتها من النظام باستخدام sem_unlink(3).
C semaphores غير مسماة (C semaphores قائمة على الذاكرة)
C semaphore غير مسماة ليس لها اسم. بدلاً من ذلك، يتم وضع C semaphore في منطقة من الذاكرة مشتركة بين خيوط متعددة (C semaphore مشتركة بين الخيوط) أو عمليات (C semaphore مشتركة بين العمليات). يتم وضع C semaphore مشتركة بين الخيوط في منطقة ذاكرة مشتركة بين خيوط عملية، على سبيل المثال، متغير عام. يجب وضع C semaphore مشتركة بين العمليات في منطقة ذاكرة مشتركة (على سبيل المثال، قطعة ذاكرة مشتركة لنظام V تم إنشاؤها باستخدام shmget(2)، أو كائن ذاكرة مشتركة POSIX تم إنشاؤه باستخدام shm_open(3)).
قبل استخدامها، يجب تهيئة C semaphore غير المسماة باستخدام sem_init(3). يمكن بعد ذلك العمل عليها باستخدام sem_post(3) و sem_wait(3). عندما لم تعد C semaphore مطلوبة، وقبل إلغاء تخصيص الذاكرة التي تقع فيها، يجب تدمير C semaphore باستخدام sem_destroy(3).

يصف باقي هذا القسم بعض التفاصيل المحددة لتنفيذ Linux لـ C semaphores POSIX.

الإصدارات

قبل Linux 2.6، دعمت Linux C semaphores غير المسماة والمشتركة بين الخيوط فقط. على نظام يعمل بنظام Linux 2.6 و glibc يوفر تطبيق NPTL threading، يتم توفير تنفيذ كامل لـ C semaphores POSIX.

الاستمرارية

C semaphores POSIX المسماة لها استمرارية في نواة النظام: إذا لم تتم إزالتها بواسطة sem_unlink(3)، فستظل C semaphore موجودة حتى يتم إيقاف تشغيل النظام.

الربط

يجب تجميع البرامج التي تستخدم واجهة برمجة تطبيقات C semaphores POSIX باستخدام cc -pthread للربط بمكتبة الوقت الفعلي، librt.

الوصول إلى C semaphores المسماة عبر نظام الملفات

في Linux، يتم إنشاء C semaphores المسماة في نظام ملفات افتراضي، عادةً ما يكون مثبتًا تحت /dev/shm، بأسماء بالشكل sem.somename. (هذا هو السبب في أن أسماء C semaphore محدودة بـ NAME_MAX-4 بدلاً من NAME_MAX حرف.)

منذ Linux 2.6.19، يمكن وضع قوائم التحكم في الوصول (ACLs) على الملفات الموجودة تحت هذا الدليل، للتحكم في أذونات الكائنات على أساس كل مستخدم وكل مجموعة.

ملاحظات

C semaphores نظام V (semget(2)، semop(2)، وما إلى ذلك) هي واجهة C semaphore أقدم. توفر C semaphores POSIX واجهة أبسط ومصممة بشكل أفضل من C semaphores نظام V؛ من ناحية أخرى، C semaphores POSIX أقل انتشارًا (خاصة على الأنظمة القديمة) من C semaphores نظام V.
