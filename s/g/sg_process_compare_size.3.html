الوصف

توفر دوال sg_get_process_stats إحصائيات حول العمليات الجاري تشغيلها حاليًا. تأخذ كلتا الدالتين، sg_get_process_stats() و sg_get_process_stats_r()، معلمة اختيارية لعدد الإدخالات، والتي تشير (عند تقديمها) إلى حجم متغير (size_t) لأخذ عدد إدخالات المتجه المرتجعة.

توفر الدالتان sg_get_process_count_of() و sg_get_process_count_r() عرضًا مجمعًا لجدول العمليات - حيث تقدمان كمية العمليات لكل حالة عملية. sg_get_process_count() هي في الواقع ماكرو معالج مسبق للتوافق مع الإصدارات السابقة وتستدعي sg_get_process_count_of() مع المعلمة pcs من sg_entire_process_count لمحاكاة السلوك حتى الإصدار 0.17.

تقارن هذه الدوال إدخالي sg_process_stats، وتعيد قيمة int لتمثيل أيهما أكبر. الاستخدام الرئيسي لهذه الدوال هو تمريرها إلى qsort لفرز sg_process_stats حسب النوع المحدد.

مثال

size_t entries;
sg_process_stats *proc_stats = NULL;
while( NULL != ( proc_stats = sg_get_process_stats_r(&entries) ) ) {
    /* ترتيب الإدخالات بمقارنة معرف العملية */
    qsort( proc_stats, entries, sizeof(proc_stats[0]), &sg_process_compare_pid );
    show_proc_stats( proc_stats );
    sg_free_process_stats( proc_stats );
}

قيم الإرجاع

الهيكل الذي تعيده sg_get_process_stats هو من النوع sg_process_stats.

typedef struct {
        char *process_name;
        char *proctitle;
        pid_t pid;    /* معرف العملية */
        pid_t parent; /* معرف العملية الأصل */
        pid_t pgid;   /* معرف عملية قائد مجموعة العمليات */
        pid_t sessid; /* معرف جلسة العمل التي تنتمي إليها العملية */
        uid_t uid;
        uid_t euid;
        gid_t gid;
        gid_t egid;
        unsigned long long context_switches;
        unsigned long long voluntary_context_switches;
        unsigned long long involuntary_context_switches;
        unsigned long long proc_size; /* بالبايت */
        unsigned long long proc_resident; /* بالبايت */
        time_t start_time; /* متى بدأت العملية */
        time_t time_spent; /* الوقت المستغرق في التشغيل بالثواني */
        double cpu_percent;
        int nice;
        sg_process_state state;
        time_t systime;
} sg_process_stats;

typedef enum {
        SG_PROCESS_STATE_RUNNING,
        SG_PROCESS_STATE_SLEEPING,
        SG_PROCESS_STATE_STOPPED,
        SG_PROCESS_STATE_ZOMBIE,
        SG_PROCESS_STATE_UNKNOWN
} sg_process_state;
process_name
اسم الأمر الذي تم تشغيله. يعتمد محتوى هذا الحقل بشكل كبير على نظام التشغيل الأساسي، بعضها يخزن اسم الملف التنفيذي الذي تمرره استدعاءات نظام exec(2)، وبعضها المسار بأكمله. تفرض معظم أنظمة التشغيل قيودًا على حجم هذا الحقل - بعضها مثل عائلة *BSD إلى قيمة منخفضة جدًا تبلغ 15 بايتًا.

هذا الحقل غير قابل للتغيير عادةً للعمليات في مساحة المستخدم.

proctitle
سطر الأوامر ( "عنوان" ) للعملية. انتبه - يمكن تعديل هذا بواسطة العملية، لذلك لا يُضمن أن يكون سطر الأوامر الأصلي.
pid
معرف العملية.
parent
معرف العملية الأصل.
pgid
معرف العملية لقائد مجموعة العمليات.
sessid
معرف الجلسة التي تنتمي إليها العملية.
uid
معرف المستخدم الذي تعمل العملية باسمه.
euid
معرف المستخدم الفعلي الذي تعمل العملية باسمه.
gid
معرف المجموعة التي تعمل العملية باسمها.
egid
معرف المجموعة الفعلية التي تعمل العملية باسمها.
context_switches
عدد تحولات السياق لهذه العملية (طوعية وغير طوعية).
voluntary_context_switches
عدد تحولات السياق الطوعية لهذه العملية (على سبيل المثال، عن طريق استدعاء sched_yield() أو sleep()).
involuntary_context_switches
عدد تحولات السياق غير الطوعية لهذه العملية (على سبيل المثال، انتهاء شريحة الوقت أو إرسال إشارة).
proc_size
حجم الذاكرة الظاهرية للعملية بالبايت.

DESCRIPTION

The sg_process_compare_* functions are function pointers that point to comparison functions used to sort process information retrieved by other libstatgrab functions. They are meant to be used in conjunction with functions like qsort(3).

The comparison functions take two arguments, a and b, which are pointers to sg_process_stats structures. They return an integer less than, equal to, or greater than zero if a is found, respectively, to be less than, to match, or be greater than b.

The structure returned by sg_get_process_stats and sg_get_process_stats_r is of type sg_process_stats.

typedef struct{
        unsigned long long proc_resident;
        unsigned long long start_time;
        unsigned long long time_spent;
        float cpu_percent;
        int nice;
        enum sg_process_state state;
        time_t systime;
}sg_process_stats;
proc_resident
The size of the process that's resident in memory.
start_time
The time when the process has been started in seconds since epoch.
time_spent
The number of seconds the process has been running (user+system time, without time spent by child processes).
cpu_percent
The current percentage of CPU the process is using.
nice
The nice value of the process.
state
The current state of the process. See sg_process_state for permitted values.
systime
The time in seconds since epoch of the moment where the present statistic has been created. This might be (but doesn't have to be) the same moment for all returned entries, regardless whether they're fetched with one snapshot or puzzled from some kind of procfs.

The structure returned by sg_get_process_count_of and sg_get_process_count_r is of type sg_process_count.

typedef enum sg_process_count_source {
        sg_entire_process_count,
        sg_last_process_count
} sg_process_count_source;

typedef struct{
        unsigned long long total;
        unsigned long long running;
        unsigned long long sleeping;
        unsigned long long stopped;
        unsigned long long zombie;
        unsigned long long unknown;
        time_t systime;
}sg_process_count;
total
The total number of processes.
running
The number of running processes.
sleeping
The number of sleeping processes.
stopped
The number of stopped processes.
zombie
The number of zombie processes.
unknown
The number of processes not matching any of above named categories.
systime
The time in seconds since epoch of the moment where the present statistic has been created.

BUGS

The very first call of sg_get_process_count_of(sg_last_process_count) will return the same as sg_get_process_count_of(sg_entire_process_count).

The compare functions exist rather for backward compatibility than for functionality enhancements. Limited flexibility (e.g. reverse order) and lack of optimising opportunities for the compiler leads to the recommendation to implement the required compare routines locally.
