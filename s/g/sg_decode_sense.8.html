NAME

sg_decode_sense - decode SCSI sense data

SYNOPSIS

sg_decode_sense [OPTION]...

DESCRIPTION

This utility decodes SCSI sense data structures and prints them out in a human-readable format. Sense data is typically returned by SCSI devices when an operation results in an error condition.

Input can be provided either as a sequence of hexadecimal bytes on the command line, or read from standard input, or read from a file specified by the --inhex= or --binary= options.

By default, the utility attempts to decode the sense data into meaningful error messages. If the input is not valid sense data, or if decoding fails, an error message is printed to standard error.

OPTIONS

-b, --binary=BFN
Read sense data from the binary file BFN. This option is mutually exclusive with --inhex=.
-H, --hex
Print the input sense data in hexadecimal format on standard output. Useful for debugging or for passing to other utilities.
-i, --inhex=HFN
Read sense data from the hexadecimal file HFN. This option is mutually exclusive with --binary=.
-n, --nodecode
Do not attempt to decode the sense data. Only print the raw hexadecimal representation.
-s, --sense-bytes=bytes
Set the maximum number of sense bytes to read. Defaults to 96.
-v, --verbose
Increase verbosity. Can be specified multiple times.
-w, --write=WFN
Write the decoded sense data (or the original data if --nodecode is used) to the binary file WFN.

NOTES

Unlike most utilities in this package, this utility does not access a SCSI device (logical unit). This utility accesses a library associated with this package. Amongst other things the library decodes SCSI sense data.

The sg_raw utility takes a ASCII hexadecimal sequence representing a SCSI CDB. When sg_raw is given the '-vvv' option, it will attempt to decode the CDB name.

Using the option combination: "--inhex=HFN --nodecode --write=WFN" may be used to convert hexadecimal (as produced by this and other utilities in this package) to binary where the output file is WFN.

Unlike many other utilities there is no --raw option. However binary data can be input using the --binary=BFN option while binary data can be output using the --write=WFN option (in the absence of the --hex option).

EXAMPLES

Sense data is often printed out in kernel logs and sometimes on the command line when verbose or debug flags are given. It will be at least 8 bytes long, often 18 bytes long but may be longer. A sense data string might look like this:

f0 00 03 00 00 12 34 0a 00 00 00 00 11 00 00 00
00 00

Cut and paste it after the sg_decode_sense command:


sg_decode_sense f0 00 03 00 00 12 34 0a 00 00 00 00 11 00 00 00 00 00

and for this sense data the output should look like this:


Fixed format, current; Sense key: Medium Error
Additional sense: Unrecovered read error
Info fld=0x1234 [4660]

For a medium error the Info field is the logical block address (LBA) of the lowest numbered block that the associated SCSI command was not able to read (verify or write).

To convert arbitrary binary data to hex, suitable to be parsed by other sg3_utils utilities. The --nodecode option is used in this case:


sg_decode_sense -N -i vpd_zbdc.hex -w vpd_zbdc.bin

The '-HHH' will output hex to the console (stdout) in a form suitable for other utilities in this package to parse as input. And sg_decode_sense can also be used to convert from arbitrary hex to binary with:


sg_decode_sense -N -b vpd_zbdc.raw -HHH

Note that tools like hexdump and od place a counter (i.e. an index starting at 0) at the beginning of each line which is a pain when parsing hex. The '/-HHH' option(s) does not output that leading counter on each line.

EXIT STATUS

The exit status of sg_decode_sense is 0 when it is successful. Otherwise see the sg3_utils(8) man page.

اسم

sg_decode_sense - فك تشفير بيانات استشعار SCSI

ملخص

sg_decode_sense [خيار]...

وصف

تقوم هذه الأداة بفك تشفير هياكل بيانات استشعار SCSI وطباعتها بتنسيق سهل القراءة. عادةً ما يتم إرجاع بيانات الاستشعار بواسطة أجهزة SCSI عند حدوث شرط خطأ نتيجة لعملية ما.

يمكن تقديم الإدخال إما كسلسلة من البايتات السداسية عشرية على سطر الأوامر، أو قراءته من الإدخال القياسي، أو قراءته من ملف محدد بواسطة الخيارات --inhex= أو --binary=.

بشكل افتراضي، تحاول الأداة فك تشفير بيانات الاستشعار إلى رسائل خطأ ذات معنى. إذا لم يكن الإدخال بيانات استشعار صالحة، أو إذا فشل فك التشفير، فسيتم طباعة رسالة خطأ إلى الخطأ القياسي.

خيارات

-b, --binary=BFN
قراءة بيانات الاستشعار من الملف الثنائي BFN. هذا الخيار حصري بالتبادل مع --inhex=.
-H, --hex
طباعة بيانات الاستشعار المدخلة بتنسيق سداسي عشري على الإخراج القياسي. مفيد لتصحيح الأخطاء أو لتمريره إلى أدوات أخرى.
-i, --inhex=HFN
قراءة بيانات الاستشعار من الملف السداسي عشري HFN. هذا الخيار حصري بالتبادل مع --binary=.
-n, --nodecode
لا تحاول فك تشفير بيانات الاستشعار. فقط اطبع التمثيل السداسي عشري الخام.
-s, --sense-bytes=bytes
تعيين الحد الأقصى لعدد بايتات الاستشعار المراد قراءتها. الافتراضي هو 96.
-v, --verbose
زيادة الإسهاب. يمكن تحديده عدة مرات.
-w, --write=WFN
اكتب بيانات الاستشعار المفكوكة (أو البيانات الأصلية إذا تم استخدام --nodecode) إلى الملف الثنائي WFN.

ملاحظات

على عكس معظم الأدوات المساعدة في هذه الحزمة، لا تصل هذه الأداة المساعدة إلى جهاز SCSI (وحدة منطقية). تصل هذه الأداة المساعدة إلى مكتبة مرتبطة بهذه الحزمة. من بين أمور أخرى، تقوم المكتبة بفك تشفير بيانات استشعار SCSI.

تأخذ الأداة المساعدة sg_raw تسلسلًا سداسي عشري ASCII يمثل SCSI CDB. عندما يتم إعطاء sg_raw الخيار '-vvv'، ستحاول فك تشفير اسم CDB.

قد يتم استخدام تركيبة الخيار: "--inhex=HFN --nodecode --write=WFN" لتحويل السداسي عشري (كما هو ناتج عن هذه الأداة وغيرها من الأدوات المساعدة في هذه الحزمة) إلى ثنائي حيث يكون ملف الإخراج هو WFN.

على عكس العديد من الأدوات المساعدة الأخرى، لا يوجد خيار --raw. ومع ذلك، يمكن إدخال البيانات الثنائية باستخدام الخيار --binary=BFN بينما يمكن إخراج البيانات الثنائية باستخدام الخيار --write=WFN (في غياب الخيار --hex).

أمثلة

غالبًا ما يتم طباعة بيانات الاستشعار في سجلات النواة وأحيانًا على سطر الأوامر عند إعطاء علامات verbose أو debug. سيكون طولها 8 بايت على الأقل، وغالبًا 18 بايت، ولكن قد تكون أطول. قد تبدو سلسلة بيانات الاستشعار كما يلي:

f0 00 03 00 00 12 34 0a 00 00 00 00 11 00 00 00
00 00

قم بقصها ولصقها بعد أمر sg_decode_sense:


sg_decode_sense f0 00 03 00 00 12 34 0a 00 00 00 00 11 00 00 00 00 00

ولهذه البيانات الاستشعارية، يجب أن يبدو الإخراج كما يلي:


Fixed format, current; Sense key: Medium Error
Additional sense: Unrecovered read error
Info fld=0x1234 [4660]

بالنسبة لخطأ في الوسائط، يكون حقل المعلومات هو عنوان الكتلة المنطقي (LBA) لأقل كتلة مرقمة لم يتمكن أمر SCSI المرتبط من قراءتها (التحقق أو الكتابة).

لتحويل بيانات ثنائية عشوائية إلى سداسي عشري، مناسبة للتحليل بواسطة أدوات sg3_utils الأخرى. يتم استخدام الخيار --nodecode في هذه الحالة:


sg_decode_sense -N -i vpd_zbdc.hex -w vpd_zbdc.bin

سيقوم '-HHH' بإخراج سداسي عشري إلى وحدة التحكم (stdout) بتنسيق مناسب للأدوات الأخرى في هذه الحزمة للتحليل كإدخال. ويمكن أيضًا استخدام sg_decode_sense للتحويل من سداسي عشري عشوائي إلى ثنائي مع:


sg_decode_sense -N -b vpd_zbdc.raw -HHH

لاحظ أن أدوات مثل hexdump و od تضع عدادًا (أي فهرس يبدأ من 0) في بداية كل سطر وهو أمر مزعج عند تحليل السداسي عشري. الخيارات '/-HHH' لا تنتج هذا العداد البادئ في كل سطر.
