الوصف

sg_vector_create() تقوم بتخصيص وتهيئة متجه statgrab جديد مع عناصر initial_used جاهزة للاستخدام. يتم تخصيص مساحة لـ alloc_count عناصر في البداية (لتجنب الكثير من استدعاءات realloc() أثناء استدعاءات sg_vector_resize() اللاحقة). يجب أن يكون قيمة block_size قوة للرقم 2، ويتم تقريبها إلى أقرب قوة للرقم 2 عندما لا تكون كذلك. إذا لم يكن alloc_count مضاعفًا لـ block_size، فسيتم تقريبه إلى أقرب مضاعف لـ block_size. تعيد مؤشرًا إلى المتجه الجديد المنشأ.

sg_vector_clear() تدمر جميع العناصر الموجودة في المتجه المحدد. على عكس sg_vector_resize( x, 0 )، تظل المساحة المخصصة للمتجه دون تغيير.

sg_vector_resize() تزيد أو تقلل من عدد العناصر المخصصة في المتجه المحدد. عدد العناصر المخصصة هو دائمًا مضاعف للمعامل block_size الذي تم استخدامه عند التهيئة. في الحالة الخاصة، عند استدعاء sg_vector_resize() مع 0 في المعامل new_count، يتم تحرير المتجه بعد تدمير جميع عناصر المتجه. تعيد مؤشرًا إلى المتجه المعاد حجمه.

sg_vector_free() تدمر جميع عناصر المتجه وتلغي تخصيص المساحة الخاصة بالمتجه المحدد.

sg_vector_clone() تنسخ جميع عناصر المتجه المحدد إلى متجه جديد تم إنشاؤه بنفس مواصفات المتجه الأصلي. تعيد مؤشرًا إلى المتجه المنسوخ.

sg_vector_clone_into() تنسخ جميع عناصر المتجه المصدر المحدد إلى المتجه الهدف المحدد. يجب أن يكون المتجه الهدف قد تم إنشاؤه لنفس نوع بيانات العناصر مثل المتجه المصدر. تعيد رمز خطأ غير SG_ERROR_NONE إذا حدث خطأ ما.

sg_vector_compute_diff() تحسب متجه فرق بين المتجه الذي يحتوي على الإحصائيات الحالية ومتجه آخر يحتوي على إحصائيات أقدم. إذا كان عنصر موجودًا في المتجه الحالي ولكن ليس في المتجه المقابل، فسيتم نسخه إلى متجه النتيجة. إذا كان عنصر موجودًا فقط في المتجه المقابل، فلن يظهر في المتجه الهدف. تعيد sg_vector_compute_diff() رمز خطأ غير SG_ERROR_NONE إذا حدث خطأ ما.

sg_prove_vector() تثبت ما إذا كان المؤشر إلى متجه يشير حقًا إلى متجه. في حالة الإشارة إلى مؤشر المتجه ببيانات تالفة، يتم إنهاء البرنامج. عند عودة sg_prove_vector()، فإنها تعيد SG_ERROR_NONE.

sg_get_nelements() تعيد عدد العناصر التي تحتويها منطقة البيانات المحددة، والتي يشملها متجه statgrab. يتم حساب رأس المتجه داخليًا من المؤشر المحدد للعنصر الأول في المتجه.

sg_free_stats_buf() تحرر المتجه الذي يشمل منطقة البيانات المحددة.

ملاحظات

باستثناء sg_get_nelements() و sg_free_stats_buf()، لا يمكن استدعاء أي من الوظائف المذكورة أعلاه من خارج مصادر libstatgrab. قد تتغير الهياكل وواجهات برمجة التطبيقات الموثقة دون إشعار. وصف جميع واجهات برمجة التطبيقات الأخرى مخصص لمطوري libstatgrab فقط.

يتم إنشاء كل متجه من عنصرين: معلومات المتجه وقائمة العناصر:

template <class T, class Impl>
struct sg_vector {
        size_t used_count;
        size_t alloc_count;
        size_t block_shift;
        Impl vector_implementation;
        T elements[alloc_count];
};

بالطبع، هذا ليس C صالحًا، لذلك كان الحل هو بعض الحيل:

typedef struct sg_vector {
	size_t used_count;
	size_t alloc_count;
	size_t block_shift;
	struct sg_vector_init_info info;
} sg_vector;
struct sg_vector_size_helper {
	struct sg_vector v;
	long long ll;
};
#define VECTOR_SIZE offsetof(struct sg_vector_size_helper,ll)
/* Return the data ptr of a vector */
#define VECTOR_DATA(vector) \
	(vector ? (void *)(((char *)vector)+VECTOR_SIZE) : NULL)
#define VECTOR_ADDR_ARITH(ptr) \
	(sg_vector *)(((char *)(ptr))-VECTOR_SIZE)
/* Return the vector for a data */
#define VECTOR_ADDRESS(ptr) \
	((ptr) ? (SG_ERROR_NONE == sg_prove_vector(VECTOR_ADDR_ARITH(ptr)) ? VECTOR_ADDR_ARITH(ptr) : NULL ) : NULL)

هذا يسمح أيضًا لوظائف المستخدم مثل sg_get_nelements() و sg_free_stats_buf() بالتبديل بسهولة بين هيكل المتجه والمحتوى.

هيكل تخصيص المتجه

كما ذكرنا، يستخدم تنفيذ المتجه استراتيجيات من مفهوم البرمجة كائنية التوجه المسمى "تعدد الأشكال". يتم وصف المتجه بواسطة كائن صغير يحتوي على سمات جوهرية مثل حجم العنصر ومجموعة من "الأساليب الافتراضية" للقيام بمهام متعلقة بالعناصر مثل تهيئة العناصر أو تدميرها.

typedef void (*vector_init_function)(void *item);
typedef sg_error (*vector_copy_function)(const void *src, void *dst);
typedef sg_error (*vector_compute_diff_function)(void *dst, const void *src);
typedef int (*vector_compare_function)(const void *a, const void *b);
typedef void (*vector_destroy_function)(void *item);
struct sg_vector_init_info {
        size_t item_size;
        vector_init_function init_fn;
        vector_copy_function copy_fn;
        vector_compute_diff_function compute_diff_fn;
        vector_compare_function compare_fn;
        vector_destroy_function destroy_fn;
};

تتم تهيئة مثيلات struct sg_vector_init_info بشكل مفاهيمي ثابت باستخدام ماكرو المعالج المسبق VECTOR_INIT_INFO_FULL_INIT(type) أو VECTOR_INIT_INFO_EMPTY_INIT(type). إليك بعض الأمثلة لتوضيح كيفية العمل:

NAME

sg_vector_clone, VECTOR_CREATE, VECTOR_CLEAR, VECTOR_CREATE_OR_RESIZE, VECTOR_UPDATE, VECTOR_ITEM_COUNT — vector manipulation macros

SYNOPSIS

#include <statgrab.h>

struct sg_vector *sg_vector_clone(const struct sg_vector *vector);

struct sg_vector *sg_vector_create(size_t alloc_count, size_t initial_used, identifier type);

void sg_vector_clear(struct sg_vector *vector);

struct sg_vector *sg_vector_resize(struct sg_vector *vector, size_t new_count, identifier type);

struct sg_vector *VECTOR_CREATE(size_t block_size, identifier type);

void VECTOR_CLEAR(struct sg_vector *vector);

struct sg_vector *VECTOR_CREATE_OR_RESIZE(struct sg_vector *vector, size_t new_count, identifier type);

void VECTOR_UPDATE(struct sg_vector **vectorptr, size_t new_count, datatype *data, identifier datatype);

size_t VECTOR_ITEM_COUNT(struct sg_vector *vector);

DESCRIPTION

These functions and macros are used to manipulate vectors within libstatgrab. Vectors are dynamic arrays that can grow as needed. They are used to store collections of data, such as lists of processes or network connections.

sg_vector_clone() creates a new vector that is a copy of the provided vector.

sg_vector_create() creates a new vector with a specified initial allocation size and number of used elements.

sg_vector_clear() removes all elements from a vector, but does not deallocate the vector itself.

sg_vector_resize() changes the size of an existing vector. If the new size is larger than the current size, the vector will be reallocated. If the new size is smaller, the vector will be truncated.

The following macros provide a more convenient interface for common vector operations:

VECTOR_CREATE(block_size, type) calls sg_vector_create() with alloc_count = block_size and initial_used = 0 using the vector specialisation type##_vector_init_info.

VECTOR_CLEAR(vector) simply calls sg_vector_clear(). This macro exists only for conformity.

VECTOR_CREATE_OR_RESIZE(vector, new_count, type) calls sg_vector_create() when the given vector pointer points to NULL or sg_vector_resize() otherwise. The result of the appropriate function is returned.

VECTOR_UPDATE(vectorptr, new_count, data, datatype) calls VECTOR_CREATE_OR_RESIZE() and sets data to the first element of the resulting vector when a non-NULL pointer got, to NULL otherwise. When VECTOR_CREATE_OR_RESIZE() returns a NULL pointer and new_count is not equal to 0 (zero), the instructions from the macro VECTOR_UPDATE_ERROR_CLEANUP are executed to cleanup before returning from current subroutine with the error which has been occurred.

VECTOR_ITEM_COUNT(vector) returns 0 for a non-existing vector (vector == 0) and the number of containing elements otherwise.

NOTES

The type argument in VECTOR_CREATE(), VECTOR_CREATE_OR_RESIZE() and sg_vector_resize() specifies the type of elements the vector will hold. This is used to determine the correct initialization and cleanup functions for the vector.

The datatype argument in VECTOR_UPDATE() specifies the data type of the elements in the vector. This is used to correctly cast the data pointer.

RETURN VALUES

Beside error codes, the return values, if any, are always a pointer to vector structures (struct sg_vector *).
