الوصف

توفر وظائف sg_get_fs_stats إحصائيات لأنظمة الملفات المثبتة. تأخذ كلتا الوظيفتين معلمة اختيارية لعدد الإدخالات، والتي تشير (عند توفيرها) إلى قيمة `size_t` لأخذ عدد إدخالات المتجه التي تم إرجاعها.

تقوم وظائف sg_get_fs_stats() و sg_get_fs_stats_r() بتوصيل إحصائيات نظام الملفات في اللحظة التي يتم فيها استدعاء الوظيفة. تقوم وظائف sg_get_fs_stats_diff() و sg_get_fs_stats_diff_between() بتوصيل الفرق بين استدعاءين لوظيفتي sg_get_fs_stats() أو sg_get_fs_stats_r() على التوالي.

يجب تحرير متجهات sg_fs_stats المستلمة من sg_get_fs_stats_r() أو sg_get_fs_stats_diff_between() باستخدام sg_free_fs_stats() عندما لا تكون هناك حاجة إليها بعد الآن. المستدعي هو المسؤول عن القيام بذلك.

تأتي مكتبة statgrab مع قائمة مدمجة لأنواع أنظمة الملفات الصالحة اعتمادًا على نظام التشغيل الذي تم تجميعها له. توفر بعض أنظمة التشغيل بالإضافة إلى ذلك واجهة برمجة تطبيقات لمعرفة أنواع أنظمة الملفات المعروفة أو الصالحة لمثيل نظام التشغيل قيد التشغيل، والتي يتم استخدامها عند اكتشافها. ومع ذلك، هناك مشاكل معروفة عند جمع إحصائيات نظام الملفات: يتم تثبيت أنظمة الملفات الشبكية من خوادم تم إطلاقها، يقوم مطورو أنظمة الملفات بتشغيل برنامج تشغيل تجريبي وهكذا.

لمنع تعليق العمليات في الحصول على إحصائيات نظام الملفات أو السماح للمطورين باختبار برامج التشغيل الخاصة بهم، قد تقوم العمليات بتعديل قائمة أنظمة الملفات الصالحة باستخدام sg_get_valid_filesystems() و sg_set_valid_filesystems(). قائمة مؤشرات `char *` التي تعمل معها كلتا الوظيفتين تنتهي دائمًا بعنصر يشير إلى NULL.

يجب عدم تعديل القائمة التي تم إرجاعها بواسطة sg_get_valid_filesystems(). قم دائمًا بنسخ القائمة إلى بنية خاصة بك، إذا كنت تخطط لتوسيع القائمة أو تقليلها:

مثال على إزالة نظام الملفات الشبكي

int compare_fs_type(const void *va, const void *vb) {
    const char **a = (const char **)va;
    const char **b = (const char **)vb;
    return strcmp( *a, *b );
}
void filter_network_fs_types(void) {
    /* أسماء أنظمة الملفات الشبكية المعروفة على منصات مختلفة */
    const char *nfs_types[] = { "nfs", "nfs3", "nfs4", "cifs", "smbfs", "samba" };
    const size_t nfs_types_count = sizeof(nfs_types) / sizeof(nfs_types[0])
    size_t fs_entries = 0;
    const char **orig_valid_fs = sg_get_valid_filesystems(&fs_entries);
    /* مضاعفة في ذاكرة خاصة لتعديل القائمة */
    char **valid_fs = calloc( entries + 1, sizeof(valid_fs[0]) );
    memcpy( valid_fs, orig_valid_fs, (entries + 1) * sizeof(valid_fs[0]) );
    size_t i;
    for( i = 0; i < nfs_types_count; ++i ) {
        char **inv_fs = bsearch( &nfs_types[i], &valid_fs[0],
                                 fs_entries, sizeof(valid_fs[0]),
                                 compare_fs_type );
        if( NULL != inv_fs ) {
            /* نسخ بما في ذلك مؤشر NULL الختامي */
            memmove( inv_fs, inv_fs + 1, fs_entries - (inv_fs - valid_fs) );
            --fs_entries;
        }
    }
    sg_set_valid_filesystems( valid_fs );
    free( valid_fs );
}

لاحظ أنه لا توجد حاجة لمضاعفة السلاسل الموجودة في قائمة أنظمة الملفات الصالحة في المثال أعلاه - فهي لا يتم تعديلها.

قد تصبح القائمة التي تم إرجاعها بواسطة sg_get_valid_filesystems() غير صالحة عند استخدامها أثناء قيام العملية باستدعاءات لـ sg_set_valid_filesystems(). لا تقوم أي من وظائف sg_fs_stats بحماية الوصول إلى التخزين المستخدم عالميًا حيث يتم الاحتفاظ بنسخة خاصة من قائمة أنظمة الملفات الصالحة. تقع على عاتق المستدعي مسؤولية عدم خلط استدعاءات التكوين مع استدعاءات جلب الإحصائيات.

بالإضافة إلى ذلك، يتوفر دعامتان لوظيفة qsort(3): sg_fs_compare_device_name() و sg_fs_compare_mnt_point().

مثال على الفرز

size_t entries;
sg_fs_stats *fs_stats = NULL;
while( NULL != ( fs_stats = sg_get_fs_stats_diff(&entries) ) ) {
    /* ترتيب الإدخالات أبجديًا باستخدام نقطة التركيب */
    qsort( fs_stats, entries, sizeof(fs_stats[0]), &sg_fs_compare_mnt_point );
    show_fs_stats( fs_stats );
}

sg_get_fs_stats_r(3) - libstatgrab

NAME

sg_get_fs_stats_r, sg_get_fs_stats, sg_get_fs_stats_byname - get file system statistics

LIBRARY

libstatgrab (libstatgrab, -lstatgrab)

SYNOPSIS

#include <statgrab.h>

sg_fs_stats_r *
sg_get_fs_stats_r (int *n_items, sg_error **error);

sg_fs_stats_r **
sg_get_fs_stats (int *n_items, sg_error **error);

sg_fs_stats_r *
sg_get_fs_stats_byname (const char *name, sg_error **error);

DESCRIPTION

The sg_get_fs_stats_r function returns a pointer to an array of sg_fs_stats_r structures containing file system statistics. The number of elements in the array is written to the integer pointed to by n_items.

The sg_get_fs_stats function is similar to sg_get_fs_stats_r, except that it returns a pointer to an array of pointers to sg_fs_stats_r structures.

The sg_get_fs_stats_byname function returns a pointer to a single sg_fs_stats_r structure corresponding to the file system named name.

The sg_fs_stats_r structure contains the following fields:

mountpoint
The mount point of the file system.
device
The device name of the file system.
type
The type of the file system (e.g. "ext4", "tmpfs").
total
The total size of the file system in bytes.
free
The amount of free space in the file system in bytes.
reserved
The amount of space reserved for privileged users/processes (usually root).
avail
The amount of free space available to non-privileged users/processes (free space less reserved space).

avail = free - reserved

total_inodes
The total number of inodes in the file system.
used_inodes
The number of used inodes in the file system.
free_inodes
The number of free inodes in the file system.
avail_inodes
The number of free inodes available to non-privileged processes.
io_size
A suggested optimal block size for I/O operations -- if you're reading or writing lots of data, do it in chunks of this size.
block_size
The size in bytes of the minimum unit of allocation on this file system.
total_blocks
The total number of blocks in the file system.
free_blocks
The number of free blocks in the file system.
used_blocks
The number of used blocks in the file system.
avail_blocks
The number of free blocks available to non-privileged processes.
systime
The time in seconds since epoch when the statistic was retrieved from kernel.

BUGS

Only mounted file systems are recognised.

Some file systems might be reported twice when mounted on different mount points.

The compare functions exist rather for backward compatibility than for functionality enhancements. Limited flexibility (e.g. reverse order) and lack of optimising opportunities for the compiler leads to the recommendation to implement the required compare routines locally.

Calling sg_set_valid_filesystems with an empty list with clear the internal list of valid file systems. There's currently no way to reset to the initial list.
