الوصف

توفر الدوال sg_get_fs_stats إحصائيات لأنظمة الملفات المثبتة. تأخذ كلتا الدالتين معامل إدخالات اختياري، والذي يشير (عند تقديمه) إلى `size_t` لأخذ عدد إدخالات المتجه المرجعة.

تقوم الدالتان sg_get_fs_stats() وsg_get_fs_stats_r() بتقديم إحصائيات نظام الملفات في اللحظة التي يتم فيها استدعاء الدالة. تقوم الدالتان sg_get_fs_stats_diff() و sg_get_fs_stats_diff_between() بتقديم الفرق بين استدعاءين لـ sg_get_fs_stats() أو sg_get_fs_stats_r()، على التوالي.

اختصار واجهة برمجة التطبيقات

الدالة ترجع مالك البيانات
sg_get_fs_stats sg_fs_stats * libstatgrab (خيط محلي)
sg_get_fs_stats_r sg_fs_stats * المستدعي
sg_get_fs_stats_diff sg_fs_stats * libstatgrab (خيط محلي)
sg_get_fs_stats_diff_between sg_fs_stats * المستدعي
sg_get_valid_filesystems char ** libstatgrab (عام)

يجب تحرير متجهات `sg_fs_stats` المستلمة من sg_get_fs_stats_r() أو sg_get_fs_stats_diff_between() باستخدام sg_free_fs_stats() عند عدم الحاجة إليها. المستدعي مسؤول عن القيام بذلك.

تأتي مكتبة statgrab مع قائمة مدمجة بأنواع أنظمة الملفات الصالحة اعتمادًا على نظام التشغيل الذي تم تجميعها له. توفر بعض أنظمة التشغيل بالإضافة إلى ذلك واجهة برمجة تطبيقات لمعرفة أنواع أنظمة الملفات المعروفة أو الصالحة لمثيل نظام التشغيل قيد التشغيل، والتي يتم استخدامها عند اكتشافها. ومع ذلك، هناك مشاكل معروفة عند جمع إحصائيات نظام الملفات: أنظمة الملفات الشبكية مثبتة من خوادم بعيدة، ومطورو أنظمة الملفات يقومون بتشغيل برنامج تشغيل تجريبي، إلخ.

لمنع العمليات من التعليق عند الحصول على إحصائيات نظام الملفات أو للسماح للمطورين باختبار برامج التشغيل الخاصة بهم، يمكن للعمليات تعديل قائمة أنظمة الملفات الصالحة باستخدام sg_get_valid_filesystems() و sg_set_valid_filesystems(). قائمة معاملات `char *` التي تعمل معها كلتا الدالتين تنتهي دائمًا بعنصر يشير إلى NULL.

يجب عدم تعديل القائمة المرجعة من sg_get_valid_filesystems(). انسخ القائمة دائمًا إلى بنية خاصة بك، إذا كنت تخطط لتوسيع القائمة أو تقليلها:

مثال على إزالة نظام الملفات الشبكي

int compare_fs_type(const void *va, const void *vb) {
    const char **a = (const char **)va;
    const char **b = (const char **)vb;
    return strcmp( *a, *b );
}
void filter_network_fs_types(void) {
    /* أسماء أنظمة الملفات الشبكية المعروفة على منصات مختلفة */
    const char *nfs_types[] = { "nfs", "nfs3", "nfs4", "cifs", "smbfs", "samba" };
    const size_t nfs_types_count = sizeof(nfs_types) / sizeof(nfs_types[0])
    size_t fs_entries = 0;
    const char **orig_valid_fs = sg_get_valid_filesystems(&fs_entries);
    /* تكرار في ذاكرة خاصة لتعديل القائمة */
    char **valid_fs = calloc( entries + 1, sizeof(valid_fs[0]) );
    memcpy( valid_fs, orig_valid_fs, (entries + 1) * sizeof(valid_fs[0]) );
    size_t i;
    for( i = 0; i < nfs_types_count; ++i ) {
        char **inv_fs = bsearch( &nfs_types[i], &valid_fs[0],
                                 fs_entries, sizeof(valid_fs[0]),
                                 compare_fs_type );
        if( NULL != inv_fs ) {
            /* نسخ بما في ذلك مؤشر NULL النهائي */
            memmove( inv_fs, inv_fs + 1, fs_entries - (inv_fs - valid_fs) );
            --fs_entries;
        }
    }
    sg_set_valid_filesystems( valid_fs );
    free( valid_fs );
}

لاحظ أنه لا حاجة لتكرار السلاسل النصية الموجودة في قائمة أنظمة الملفات الصالحة في المثال أعلاه - لم يتم تعديلها.

قد تصبح القائمة المرجعة من sg_get_valid_filesystems() غير صالحة عند استخدامها أثناء قيام العملية باستدعاءات لـ sg_set_valid_filesystems(). لا تحمي أي من دوال `sg_fs_stats` الوصول إلى التخزين العام المستخدم حيث يتم الاحتفاظ بالنسخة الخاصة من قائمة أنظمة الملفات الصالحة. تقع على عاتق المستدعي مسؤولية عدم خلط استدعاءات التكوين مع استدعاءات لجلب الإحصائيات.

بالإضافة إلى ذلك، تتوفر دالتان مساعدتان لـ qsort(3): sg_fs_compare_device_name() و sg_fs_compare_mnt_point().

مثال على الفرز

size_t entries;
sg_fs_stats *fs_stats = NULL;
while( NULL != ( fs_stats = sg_get_fs_stats_diff(&entries) ) ) {
    /* ترتيب الإدخالات أبجديًا باستخدام نقطة التركيب */
    qsort( fs_stats, entries, sizeof(fs_stats[0]), &sg_fs_compare_mnt_point );
    show_fs_stats( fs_stats );
}

NAME

sg_get_fs_stats - get file system statistics

SYNOPSIS

#include <statgrab.h>

SG_FS_STATS *sg_get_fs_stats (int ncall);

DESCRIPTION

The sg_get_fs_stats function is used to retrieve statistics about mounted file systems.

The ncall argument is used for collecting statistics over time. When ncall is 0, the function will return the data immediately. When ncall is greater than 0, the function will return the statistics for the corresponding call number. This is useful for calculating rates and other time-based statistics.

The function returns a pointer to an array of SG_FS_STATS structures, each representing the statistics for a single mounted file system. The array is terminated by a structure with its device member set to NULL.

The SG_FS_STATS structure contains the following members:

device
The name of the device file for the file system (e.g., "/dev/sda1").
mountpoint
The mount point of the file system (e.g., "/").
filesystem
The type of the file system (e.g., "ext4", "xfs").
total
The total size of the file system in bytes.
free
The amount of free space in the file system in bytes.
reserved
The amount of space reserved for the super-user in bytes.
avail
The amount of space available to unprivileged users/processes (free space less reserved space).

avail = free - reserved

total_inodes
The total number of inodes in the file system.
used_inodes
The number of used inodes in the file system.
free_inodes
The number of free inodes in the file system.
avail_inodes
The number of free inodes available to non-privileged processes.
io_size
A suggested optimal block size for I/O operations -- if you're reading or writing lots of data, do it in chunks of this size.
block_size
The size in bytes of the minimum unit of allocation on this file system.
total_blocks
The total number of blocks in the file system.
free_blocks
The number of free blocks in the file system.
used_blocks
The number of used blocks in the file system.
avail_blocks
The number of free blocks available to non-privileged processes.
systime
The time in seconds since epoch when the statistic was retrieved from kernel.

BUGS

Only mounted file systems are recognised.

Some file systems might be reported twice when mounted on different mount points.

The compare functions exist rather for backward compatibility than for functionality enhancements. Limited flexibility (e.g. reverse order) and lack of optimising opportunities for the compiler leads to the recommendation to implement the required compare routines locally.

Calling sg_set_valid_filesystems with an empty list with clear the internal list of valid file systems. There's currently no way to reset to the initial list.
