الحزمة: sg3_utils

الاسم

sg_map - يعرض التعيين بين أجهزة sg وأجهزة SCSI الأخرى

الملخص

sg_map [-a] [-h] [-i] [-n] [-scd] [-sd] [-sr] [-st] [-V] [-x]

الوصف

في بعض الأحيان يكون من الصعب تحديد الجهاز الذي تشير إليه تسمية جهاز sg (مثل /dev/sg0). يقوم هذا الأمر بالمرور عبر أجهزة sg والعثور على اسم جهاز القرص أو مشغل الأقراص أو الشريط SCSI المقابل (إن وجد). الماسحات الضوئية هي مثال لأجهزة SCSI التي لا تحتوي على اسم جهاز SCSI بديل بخلاف اسم جهاز sg الخاص بها.

هذه الأداة تم إهمالها ولم يتم تحديثها لسنوات، وسيتم إصلاح الأخطاء الواضحة جداً فقط. ما لم تكن تستخدم إصدارًا قديماً جداً من Linux (مثل سلسلة 2.4 أو أقدم)، فيرجى استخدام أداة مثل lsscsi(8) أو المرافق التي توفرها udev(8).

الخيارات

-a
يفترض أن أجهزة sg لها أسماء أجهزة أبجدية ويمر عبر /dev/sga، /dev/sgb، إلخ. الافتراضي هو الفحص الرقمي. لاحظ أن عقد جهاز sg ذات الفهرس الأبجدي تم إهمالها منذ سلسلة نواة Linux 2.2.
-h
يطبع رسالة الاستخدام ثم يخرج.
-i
بالإضافة إلى ذلك، يقوم بإجراء استعلام INQUIRY قياسي وإخراج سلاسل المورد والمنتج والمراجعة للأجهزة التي تم العثور عليها.
-n
يفترض أن أجهزة sg لها أسماء أجهزة رقمية ويمر عبر /dev/sg0، /dev/sg1، إلخ. الافتراضي هو الفحص الرقمي.
-scd
يعرض التعيينات لأسماء أجهزة CDROM SCSI بالشكل /dev/scd0، /dev/scd1 إلخ.
-sd
يعرض التعيينات لأسماء أجهزة الأقراص SCSI.
-sr
يعرض التعيينات لأسماء أجهزة CDROM SCSI بالشكل /dev/sr0، /dev/sr1 إلخ.
-st
يعرض التعيينات لأسماء أشرطة SCSI.
-V
يطبع سلسلة الإصدار ثم يخرج (بدون مزيد من التأخير).
-x
بعد عرض كل اسم جهاز sg نشط، توجد خمسة أرقام: <رقم_المضيف> <ناقل> <معرف_scsi> <lun> <نوع_scsi>

ملاحظات

إذا لم يتم إعطاء أي خيارات تبدأ بـ "-s"، فسيتم عرض التعيين لجميع أسماء أجهزة الأقراص CDROM والأشرطة SCSI.

إذا كان نظام الملفات devfs موجودًا، فسيتم إخراج سطر يشير إلى ذلك. تجعل التسلسل الهرمي لـ devfs "الأصلي" لـ scsi العلاقة بين اسم جهاز sg وأي اسم جهاز قرص أو cdrom أو شريط مقابل سهل الفهم. هذا يحل محل الحاجة لهذا الأمر. ومع ذلك، ستستمر العديد من التطبيقات في البحث عن أسماء أجهزة SCSI الخاصة بنظام Linux في مواضعها التقليدية. [يوفر Devfs خادم توافق يسمى devfsd والذي يضيف التكوين الافتراضي الخاص به أسماء أجهزة Linux مرة أخرى في مواضعها التقليدية.

في كثير من الأحيان، يمكن استخلاص معلومات التعيين من خلال ملاحظة إخراج الأمر: "sg_map". ومع ذلك، إذا تمت إضافة أجهزة بعد بدء التشغيل، فقد يكون هذا مضللاً.

في سلسلة نواة Linux 2.6، يمكن العثور على شيء قريب من التعيين الذي تعرضه هذه الأداة من خلال تحليل sysfs. الفرق الرئيسي هو أن تحليل sysfs سيظهر التعيين بين عقد sg وعقد الأجهزة SCSI الأخرى من حيث الأرقام الرئيسية والثانوية. بينما سيكون الرئيسي 8، الثانوي 16 عادةً /dev/sdb، إلا أن هذا ليس هو الحال بالضرورة. قد تعين المرافق المرتبطة بـ udev الرقم الرئيسي 8، الثانوي 16 اسم عقدة جهاز آخر. تم توسيع إصدار sg_map هذا للتعامل مع أسماء عقد أجهزة الأقراص المتفرقة بالشكل "/dev/sd<str>" حيث يمكن أن يكون <str> أحد [a-z، aa-zz، aaa-zzz]. راجع أداة sg_map26 للحصول على طريقة أكثر دقة (أي، مسح أقل للمجلدات) لتعيين بين أسماء أجهزة sg والأسماء ذات المستوى الأعلى؛ بما في ذلك العثور على الأسماء المعرفة من قبل المستخدم.

تمت كتابة هذه الأداة في وقت لم يكن فيه دعم التوصيل الساخن لأجهزة SCSI مدعومًا في Linux. لقد استخدمت خوارزمية بسيطة لفحص عقد أجهزة sg بترتيب رقمي أو أبجدي تصاعدي، والتوقف بعد وجود 5 أخطاء متتالية.

في سلسلة نواة Linux 2.6، تستخدم هذه الأداة sysfs للعثور على عقد أجهزة sg النشطة وتفحص فقط تلك. وبالتالي، يمكن أن تكون هناك "فجوات" كبيرة في ترقيم عقد أجهزة sg (على سبيل المثال، بعد إزالة محول) ولا يزال سيتم سرد جميع عقد أجهزة sg النشطة. تفترض هذه الأداة أن عقد أجهزة sg مسماة باستخدام الاتفاقيات العادية وتبحث من /dev/sg0 إلى /dev/sg4095 شاملة.

أمثلة

يحتوي جهازي على قرص SCSI، ومشغل أقراص CD، ومشغل DVD:
$ sg_map
# ملاحظة: نظام الملفات الزائف devfs موجود
/dev/sg0 /dev/sda
/dev/sg1 /dev/sr0
/dev/sg2 /dev/sr1

للعثور على اسم جهاز sg الذي يقابل القرص:
$ sg_map -sd
# ملاحظة: نظام الملفات الزائف devfs موجود
/dev/sg0 /dev/sda
/dev/sg1
/dev/sg2

يعطي الخيار "-x" الناتج التالي:
sg_map -x
# ملاحظة: نظام الملفات الزائف devfs موجود
/dev/sg0 1 0 1 0 0 /dev/sda
/dev/sg1 2 0 4 0 5 /dev/sr0
/dev/sg2 2 0 6 0 5 /dev/sr1

عند إضافة ماسح ضوئي SCSI، يصبح الناتج:
$ sg_map
# ملاحظة: نظام الملفات الزائف devfs موجود
/dev/sg0 /dev/sda
/dev/sg1 /dev/sr0
/dev/sg2 /dev/sr1
/dev/sg3

بالاستبعاد، /dev/sg3 يجب أن يكون الماسح الضوئي.

NAME

sg_map - send generic SCSI commands to a device using the sg driver

SYNOPSIS

sg_map [OPTIONS] DEVICE

DESCRIPTION

The sg_map utility is used to send generic SCSI commands to a device using the sg driver.

OPTIONS

-a, --atus
Print the ATUS (Adapter Transport Status) value.
-A, --author
Print the author information.
-b, --bcd
Print the BCD (Binary Coded Decimal) value.
-c, --cdb=CDB
Specify the CDB (Command Descriptor Block) to send.
-d, --device=DEVICE
Specify the device to send the command to.
-e, --error
Print error information.
-f, --force
Force the operation, even if it is potentially dangerous.
-h, --help
Print a help message and exit.
-i, --inquiry
Send an inquiry command and print the results.
-k, --sense
Print the sense data.
-l, --list
List available devices.
-m, --mode=MODE
Specify the mode page to access.
-p, --packet=PACKET
Specify the packet to send.
-r, --read
Read data from the device.
-s, --scsi=SCSI_COMMAND
Specify the SCSI command to send.
-t, --test
Perform a test operation.
-u, --unmap
Unmap the device.
-v, --verbose
Print verbose output.
-w, --write
Write data to the device.
-x, --extended
Perform an extended operation.
-y, --yoda
Print Yoda-style output.
-z, --zero
Zero out the device.

EXAMPLES

Send an inquiry command to the device /dev/sg0:

sg_map -i /dev/sg0

Send a SCSI command to the device /dev/sg1:

sg_map -s "00 01 00 00 01 00" /dev/sg1

EXIT STATUS

Returns 0 on success, non-zero on failure.
