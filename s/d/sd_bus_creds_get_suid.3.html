الوصف

تقوم هذه الدوال باسترجاع معلومات بيانات الاعتماد من كائن sd_bus_creds. يمكن إنشاء كائنات بيانات الاعتماد باستخدام sd_bus_creds_new_from_pid(3)، وفي هذه الحالة تصف بيانات اعتماد العملية التي يتم تحديدها بواسطة PID المحدد، أو باستخدام sd_bus_get_name_creds(3)، وفي هذه الحالة تصف بيانات اعتماد نظير الحافلة الذي يتم تحديده بواسطة اسم الحافلة المحدد، أو باستخدام sd_bus_get_owner_creds(3)، وفي هذه الحالة تصف بيانات اعتماد منشئ الحافلة، أو باستخدام sd_bus_message_get_creds(3)، وفي هذه الحالة تصف بيانات اعتماد مرسل الرسالة.

ليست كل حقول بيانات الاعتماد جزءًا من كل كائن "sd_bus_creds". استخدم sd_bus_creds_get_mask(3) لتحديد القناع للحقول المتاحة.

sd_bus_creds_get_pid() ستسترجع PID (معرف العملية). وبالمثل، ستسترجع sd_bus_creds_get_ppid() PID الأب. لاحظ أن PID 1 ليس لديه عملية أب، وفي هذه الحالة يتم إرجاع -ENXIO.

sd_bus_creds_get_pidfd_dup() ستسترجع واصف ملف PID (pidfd)، انظر pidfd_open(2) للتفاصيل. يتم مضاعفة واصف الملف وبالتالي يجب على المتصل إغلاقه.

sd_bus_creds_get_tid() ستسترجع TID (معرف الخيط).

sd_bus_creds_get_uid() ستسترجع UID الرقمي (معرف المستخدم). وبالمثل، تُرجع sd_bus_creds_get_euid() معرف المستخدم الفعال، sd_bus_creds_get_suid() معرف المستخدم المحفوظ، و sd_bus_creds_get_fsuid() معرف نظام الملفات للمستخدم.

sd_bus_creds_get_gid() ستسترجع GID الرقمي (معرف المجموعة). وبالمثل، تُرجع sd_bus_creds_get_egid() معرف المجموعة الفعال، sd_bus_creds_get_sgid() معرف المجموعة المحفوظ، و sd_bus_creds_get_fsgid() معرف نظام الملفات للمجموعة.

sd_bus_creds_get_supplementary_gids() ستسترجع قائمة GID الملحقة.

sd_bus_creds_get_comm() ستسترجع حقل comm (اسم مختصر للملف التنفيذي، كما هو مخزن في /proc/pid/comm).

sd_bus_creds_get_tid_comm() ستسترجع حقل comm للخيط (كما هو مخزن في /proc/pid/task/tid/comm).

sd_bus_creds_get_exe() ستسترجع المسار للملف التنفيذي للبرنامج (كما هو مخزن في الرابط /proc/pid/exe، ولكن مع إزالة اللاحقة " (deleted)"). لاحظ أن خيوط النواة ليس لديها مسار تنفيذي، وفي هذه الحالة يتم إرجاع -ENXIO. لاحظ أنه لا ينبغي استخدام هذه الخاصية لأكثر من المعلومات التوضيحية، وبشكل خاص لا ينبغي استخدامها لقرارات ذات صلة بالأمان. هذا لأن الملف التنفيذي قد تم استبداله أو إزالته بحلول الوقت الذي يمكن فيه معالجة القيمة. علاوة على ذلك، تصدر النواة هذه المعلومات بطريقة غامضة (أي لا يمكن تمييز الملف التنفيذي المحذوف بأمان عن ملف لم يتم.

DESCRIPTION

These functions retrieve various metadata fields about a bus peer, which might be a local process or a remote bus peer. The credentials object c is typically obtained via sd_bus_creds_new_from_pid(3) or sd_bus_get_peer_creds(3).

The following functions retrieve numeric IDs:

sd_bus_creds_get_pid()
Retrieves the process ID (PID).
sd_bus_creds_get_tid()
Retrieves the thread ID (TID).
sd_bus_creds_get_ppid()
Retrieves the parent process ID (PPID).
sd_bus_creds_get_uid()
Retrieves the real user ID (UID).
sd_bus_creds_get_gid()
Retrieves the real group ID (GID).
sd_bus_creds_get_euid()
Retrieves the effective user ID (EUID).
sd_bus_creds_get_egid()
Retrieves the effective group ID (EGID).
sd_bus_creds_get_suid()
Retrieves the saved set-user-ID (SUID).
sd_bus_creds_get_sgid()
Retrieves the saved set-group-ID (SGID).
sd_bus_creds_get_fsuid()
Retrieves the filesystem user ID (FSUID).
sd_bus_creds_get_fsgid()
Retrieves the filesystem group ID (FSGID).
sd_bus_creds_get_supplementary_gids()
Retrieves the array of supplementary group IDs. The array is NULL-terminated. The caller must not modify or free the array. Note that this might be identical to the real GID.

The following functions retrieve string information:

sd_bus_creds_get_comm()
Retrieves the command name of the process. This is usually the name of the executable file, truncated to 15 characters. See exec(5).
sd_bus_creds_get_tid_comm()
Retrieves the command name of the thread. See prctl(2).
sd_bus_creds_get_exe()
Retrieves the absolute path to the executable. Note that kernel threads do not have an executable path, in which case -ENXIO is returned. This field may be empty if the path is unknown, or if the process is running in a container without the appropriate capabilities. Note that the kernel's implementation of this field might be subject to race conditions and might not be the same as the path stored in /proc/pid/exe (which is a symbolic link and may be altered by another process after the link is followed but before it is read). The suffix " (deleted)" is appended to the path if the executable file has been deleted.
sd_bus_creds_get_cmdline()
Retrieves an array of command line arguments (as stored in /proc/pid/cmdline). Note that kernel threads do not have a command line, in which case -ENXIO is returned.
sd_bus_creds_get_cgroup()
Retrieves the control group path. See Control Groups v2[1].
sd_bus_creds_get_unit()
Retrieves the systemd unit name (in the system instance of systemd) that the process is a part of. See systemd.unit(5). For processes that are not part of a unit, returns -ENXIO.
sd_bus_creds_get_user_unit()
Retrieves the systemd unit name (in the user instance of systemd) that the process is a part of. See systemd.unit(5). For processes that are not part of a user unit, returns -ENXIO.
sd_bus_creds_get_slice()
Retrieves the systemd slice (a unit in the system instance of systemd) that the process is a part of. See systemd.slice(5). Similarly, sd_bus_creds_get_user_slice() retrieves the systemd slice of the process, in the user instance of systemd.
sd_bus_creds_get_session()
Retrieves the identifier of the login session that the process is a part of. Please note the login session may be limited to a stub process or two. User processes may instead be started from their systemd user manager, e.g. GUI applications started using DBus activation, as well as service processes which are shared between multiple logins of the same user. For processes that are not part of a session, returns -ENXIO.
sd_bus_creds_get_owner_uid()
Retrieves the numeric UID (user identifier) of the user who owns the user unit or login session that the process is a part of. See systemd-logind.service(8). For processes that are not part of a user unit or session, returns -ENXIO.
sd_bus_creds_has_effective_cap()
Checks whether the capability specified by capability was set in the effective capabilities mask. A positive return value means that it was set, zero means that it was not set, and a negative return value indicates an error. See capabilities(7) and the AmbientCapabilities= and CapabilityBoundingSet= settings in systemd.exec(5).
sd_bus_creds_has_permitted_cap()
Similar to sd_bus_creds_has_effective_cap(), but checks the permitted capabilities mask.
sd_bus_creds_has_inheritable_cap()
Similar to sd_bus_creds_has_effective_cap(), but checks the inheritable capabilities mask.
sd_bus_creds_has_bounding_cap()
Similar to sd_bus_creds_has_effective_cap(), but checks the bounding capabilities mask.
sd_bus_creds_get_selinux_context()
Retrieves the SELinux security context (label) of the process.
sd_bus_creds_get_audit_session_id()
Retrieves the audit session identifier of the process. Returns -ENXIO for processes that are not part of an audit session.
sd_bus_creds_get_audit_login_uid()
Retrieves the audit user login identifier (the identifier of the user who is "responsible" for the session). Returns -ENXIO for processes that are not part of an audit session.
sd_bus_creds_get_tty()
Retrieves the controlling TTY, without the prefixing "/dev/". Returns -ENXIO for processes that have no controlling TTY.
sd_bus_creds_get_unique_name()
Retrieves the D-Bus unique name. See The D-Bus specification[2].
sd_bus_creds_get_well_known_names()
Retrieves the set of D-Bus well-known names. See The D-Bus specification[2].
sd_bus_creds_get_description()
Retrieves a descriptive name of the bus connection of the peer. This name is useful to discern multiple bus connections by the same peer, and may be altered by the peer with the sd_bus_set_description(3) call.
sd_bus_creds_get_pidfd_dup()
Duplicates the pidfd_open(2) file descriptor referring to the process. Returns -ENXIO for processes that do not have a pidfd, or if the PID is no longer valid. The caller is responsible for closing the returned file descriptor.

All functions that take a const char** parameter will store the answer there as an address of a NUL-terminated string. It will be valid as long as c remains valid, and should not be freed or modified by the caller.

All functions that take a char*** parameter will store the answer there as an address of an array of strings. Each individual string is NUL-terminated, and the array is NULL-terminated as a whole. It will be valid as long as c remains valid, and should not be freed or modified by the caller.

RETURN VALUE

On success, these calls return 0 or a positive integer. On failure, these calls return a negative errno-style error code.

Errors

Returned errors may indicate the following problems:

-ENODATA

The given field is not available in the credentials object c.

-ENXIO

The given field is not specified for the described process or peer. This will be returned by sd_bus_creds_get_unit(), sd_bus_creds_get_slice(), sd_bus_creds_get_user_unit(), sd_bus_creds_get_user_slice(), and sd_bus_creds_get_session() if the process is not part of a systemd system unit, systemd user unit, systemd slice, or logind session. It will be returned by sd_bus_creds_get_owner_uid() if the process is not part of a systemd user unit or logind session. It will also be returned by sd_bus_creds_get_exe() and sd_bus_creds_get_cmdline() for kernel threads (since these are not started from an executable binary, nor have a command line), and by sd_bus_creds_get_audit_session_id() and sd_bus_creds_get_audit_login_uid() when the process is not part of an audit session, and sd_bus_creds_get_tty() if the process has no controlling TTY.

-EINVAL

Specified pointer parameter is NULL.

-ENOMEM

Memory allocation failed.

NOTES

Functions described here are available as a shared library, which can be compiled against and linked to with the libsystemd pkg-config(1) file.

The code described here uses getenv(3), which is declared to be not multi-thread-safe. This means that the code calling the functions described here must not call setenv(3) from a parallel thread. It is recommended to only do calls to setenv() from an early phase of the program when no other threads have been started.
