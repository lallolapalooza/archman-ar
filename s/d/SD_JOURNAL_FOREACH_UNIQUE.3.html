SD_JOURNAL_FOREACH_UNIQUE(3) sd_journal_query_unique SD_JOURNAL_FOREACH_UNIQUE(3)

الاسم

sd_journal_query_unique, sd_journal_enumerate_unique, sd_journal_enumerate_available_unique, sd_journal_restart_unique, SD_JOURNAL_FOREACH_UNIQUE - قراءة القيم الفريدة من قاعدة بيانات السجل

الملخص

#include <systemd/sd-journal.h>

int sd_journal_query_unique(sd_journal *j, const char *field);

int sd_journal_enumerate_unique(sd_journal *j, const void **data, size_t *length);

int sd_journal_enumerate_available_unique(sd_journal *j, const void **data, size_t *length);

void sd_journal_restart_unique(sd_journal *j);

SD_JOURNAL_FOREACH_UNIQUE(sd_journal *j, const void *data, size_t length);

الوصف

sd_journal_query_unique() تستعلم قاعدة بيانات السجل عن جميع القيم الفريدة التي يمكن أن يأخذها الحقل المحدد. يتم استقبال وسيطين: السجل المراد استعلامه، واسم الحقل المراد البحث عنه. أسماء الحقول المعروفة مدرجة في systemd.journal-fields(7)، ولكن يمكن تحديد أي حقل. يجب تحديد أسماء الحقول بدون لاحقة "="." بعد نجاح تنفيذ هذه الوظيفة، يمكن استعلام قيم الحقل باستخدام sd_journal_enumerate_unique() و sd_journal_enumerate_available_unique(). استدعاء إحدى هاتين الوظيفتين سيغير اسم الحقل الذي يتم البحث عنه ويعيد تعيين فهرس التعداد إلى أول قيمة حقل مطابقة."

يمكن استخدام sd_journal_enumerate_unique() للتكرار عبر جميع بيانات الحقل التي تطابق اسم الحقل المحدد مسبقًا بواسطة sd_journal_query_unique(). في كل استدعاء، يتم إرجاع بيانات الحقل التالية التي تتوافق مع اسم الحقل. ترتيب بيانات الحقل التي تم إرجاعها غير محدد. يتم استقبال ثلاثة وسائط: كائن السجل، بالإضافة إلى زوج من المؤشرات إلى مؤشرات/حجم متغيرات حيث سيتم تخزين كائن البيانات وحجمه. البيانات المرجعة في خريطة ذاكرة للقراءة فقط وصالحة حتى يتم استدعاء sd_journal_enumerate_unique() مرة أخرى. يجب أن تلاحظ أن البيانات المرجعة يسبقها اسم الحقل و "="." يجب أن تلاحظ أن هذا الاستدعاء يخضع لحد حجم البيانات، الذي يتم التحكم فيه بواسطة sd_journal_set_data_threshold()، ويعيد فقط الجزء الأولي من الحقل حتى هذا الحد. يتم إرجاع خطأ لأي حقل لا يمكن استرداده. لمزيد من التفاصيل، انظر قائمة الأخطاء أدناه."

sd_journal_enumerate_available_unique() مشابه لـ sd_journal_enumerate_unique()، ولكنه يتجاوز عن قصد أي حقل صالح ولكنه كبير جدًا أو غير مدعوم بواسطة التطبيق الحالي."

sd_journal_restart_unique() يعيد تعيين فهرس تعداد البيانات إلى الموضع الأول في القائمة. الاستدعاء التالي لـ sd_journal_enumerate_unique() سيعيد بيانات الحقل الأولى المطابقة لاسم الحقل."

ملاحظة: يمكن استخدام الماكرو SD_JOURNAL_FOREACH_UNIQUE() كغلاف مفيد لـ sd_journal_restart_unique() و sd_journal_enumerate_available_unique()."

ملاحظة: هذه الوظائف غير متأثرة بالمطابقات التي تم إنشاؤها بواسطة sd_journal_add_match()، ولكن هذا قد يتغير في إصدار لاحق من هذا البرنامج."

لتعداد جميع أسماء الحقول المستخدمة حاليًا (وبالتالي جميع المعلمات المناسبة لـ sd_journal_query_unique())، استخدم الاستدعاء sd_journal_enumerate_fields(3)."

قيمة الإرجاع

sd_journal_query_unique() يعيد 0 في حالة النجاح أو رمز خطأ سالب. sd_journal_enumerate_unique() و sd_journal_query_available_unique() يعيدان قيمة موجبة إذا تم قراءة بيانات الحقل التالية، 0 إذا لم تعد هناك حقول، أو رمز خطأ سالب. sd_journal_restart_unique() لا يعيد شيئًا."

أمثلة

استخدم الماكرو SD_JOURNAL_FOREACH_UNIQUE() للتكرار عبر جميع القيم التي يمكن أن يأخذها حقل السجل (والتي يمكن الوصول إليها في الهندسة المعمارية الحالية وغير مضغوطة بآلية غير مدعومة). يوضح المثال التالي جميع أسماء الوحدات المشار إليها في السجل:"

/* SPDX-License-Identifier: MIT-0 */
#include <errno.h>
#include <stdio.h>
#include <systemd/sd-journal.h>
int main(int argc, char *argv[]) {
  sd_journal *j;
  const void *d;
  size_t l;
  int r;
  r = sd_journal_open(&j, SD_JOURNAL_LOCAL_ONLY);
  if (r < 0) {
    fprintf(stderr, "فشل فتح السجل: %s\n", strerror(-r));
    return 1;
  }
  r = sd_journal_query_unique(j, "_SYSTEMD_UNIT");
  if (r < 0) {
    fprintf(stderr, "فشل الاستعلام عن السجل: %s\n", strerror(-r));
    return 1;
  }
  SD_JOURNAL_FOREACH_UNIQUE(j, d, l)
    printf("%.*s\n", (int) l, (const char*) d);
  sd_journal_close(j);
  return 0;
}

NAME

SD_JOURNAL_FOREACH_UNIQUE, sd_journal_get_unique, sd_journal_get_data, sd_journal_get_data_strict, sd_journal_get_data_with_output, sd_journal_get_data_with_output_strict, sd_journal_get_args, sd_journal_get_cmdline, sd_journal_get_cwd, sd_journal_get_environ, sd_journal_stream_fd - Iterate over unique journal entries and query their metadata

SYNOPSIS

#include <systemd/sd-journal.h>

int sd_journal_foreach_unique(sd_journal *j, sd_journal_enumerate_unique_callback_t callback, void *userdata);

int sd_journal_get_unique(sd_journal *j, const char *key, char **value);

int sd_journal_get_data(sd_journal *j, const char *key, char **value);

int sd_journal_get_data_strict(sd_journal *j, const char *key, char **value);

int sd_journal_get_data_with_output(sd_journal *j, const char *key, char **value);

int sd_journal_get_data_with_output_strict(sd_journal *j, const char *key, char **value);

int sd_journal_get_args(sd_journal *j, char ***args);

int sd_journal_get_cmdline(sd_journal *j, char ***cmdline);

int sd_journal_get_cwd(sd_journal *j, char **cwd);

int sd_journal_get_environ(sd_journal *j, char ***environ);

int sd_journal_stream_fd(sd_journal *j, const char *key);

DESCRIPTION

The journal is an associative array of fields, where each field consists of a key and a value. The keys are strings, and the values are arrays of strings. This man page describes functions for iterating over journal entries and querying their metadata.

The sd_journal_foreach_unique() function iterates over all unique fields in the journal. For each unique field, it calls the specified callback function with the field's key and value, along with the provided userdata. The callback function should return a positive value to continue iteration, zero to stop, or a negative value to indicate an error.

The sd_journal_get_unique() function retrieves the value of a specific field key from the journal. The retrieved value is allocated and must be freed by the caller using free(3). If the field is not found, -ENOENT is returned.

The sd_journal_get_data() function is similar to sd_journal_get_unique(), but it retrieves the value of a field even if it is not directly associated with the current journal entry. This function is useful for retrieving fields that are inherited from parent processes or other related entries.

The sd_journal_get_data_strict() function is similar to sd_journal_get_data(), but it returns an error if the field is not found directly associated with the current journal entry. This function is useful for ensuring that you are retrieving data that is directly relevant to the current entry.

The sd_journal_get_data_with_output() and sd_journal_get_data_with_output_strict() functions are similar to sd_journal_get_data() and sd_journal_get_data_strict() respectively, but they also retrieve any associated output data. This output data can include file descriptors, pipes, or other communication channels.

The sd_journal_get_args() function retrieves the command-line arguments of the current journal entry. The arguments are returned as an array of strings, which must be freed by the caller.

The sd_journal_get_cmdline() function retrieves the command line used to start the process that generated the current journal entry. The command line is returned as an array of strings, which must be freed by the caller.

The sd_journal_get_cwd() function retrieves the current working directory of the process that generated the current journal entry. The CWD is returned as a string, which must be freed by the caller.

The sd_journal_get_environ() function retrieves the environment variables of the process that generated the current journal entry. The environment variables are returned as an array of strings, which must be freed by the caller.

The sd_journal_stream_fd() function returns the file descriptor associated with a specific field key. This function is useful for retrieving file descriptors that are used for communication with other processes or services.

RETURN VALUE

On success, these functions return a non-negative integer. On failure, they return a negative errno value.

NOTES

These functions are part of systemd, a system and service manager for Linux operating systems. They are designed to provide a simple and efficient way to interact with the system journal.

When using sd_journal_foreach_unique(), the callback function should be designed to handle the case where the journal is empty or contains no unique fields. In such cases, the callback function will not be called.

When allocating memory for retrieved values, it is important to free the memory using free(3) when it is no longer needed to avoid memory leaks.

EXAMPLES

The following example demonstrates how to use sd_journal_foreach_unique() to iterate over all unique fields in the journal and print their key-value pairs:

    #include <stdio.h>
    #include <systemd/sd-journal.h>

    static int print_unique_field(const char *key, const char *value, void *userdata) {
        printf("%s=%s\n", key, value);
        return 1; // Continue iteration
    }

    int main() {
        sd_journal *j;
        int r;

        r = sd_journal_open(&j, SD_JOURNAL_LOCAL_ONLY);
        if (r < 0) {
            fprintf(stderr, "Failed to open journal: %s\n", strerror(-r));
            return 1;
        }

        r = sd_journal_foreach_unique(j, print_unique_field, NULL);
        if (r < 0) {
            fprintf(stderr, "Failed to iterate over unique fields: %s\n", strerror(-r));
            sd_journal_close(j);
            return 1;
        }

        sd_journal_close(j);
        return 0;
    }
