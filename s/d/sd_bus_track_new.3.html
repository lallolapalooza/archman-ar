sd_bus_track_new(3)

الحزمة: systemd-libs

التراخيص: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

NAME

sd_bus_track_new, sd_bus_track_handler_t, sd_bus_track_ref, sd_bus_track_unref, sd_bus_track_unrefp, sd_bus_track_get_recursive, sd_bus_track_set_recursive, sd_bus_track_get_bus, sd_bus_track_get_userdata, sd_bus_track_set_userdata - Create and manage bus object tracks

SYNOPSIS

#include <systemd/sd-bus.h>

int sd_bus_track_new(sd_bus *bus, sd_bus_track **track, const char *path);
int sd_bus_track_ref(sd_bus_track *track);
int sd_bus_track_unref(sd_bus_track *track);
sd_bus_track *sd_bus_track_unrefp(sd_bus_track **trackp);
int sd_bus_track_get_recursive(sd_bus_track *track);
int sd_bus_track_set_recursive(sd_bus_track *track, int recursive);
sd_bus *sd_bus_track_get_bus(sd_bus_track *track);
void *sd_bus_track_get_userdata(sd_bus_track *track);
int sd_bus_track_set_userdata(sd_bus_track *track, void *userdata);

DESCRIPTION

sd_bus_track_new(), sd_bus_track_handler_t(), sd_bus_track_ref(), sd_bus_track_unref(), sd_bus_track_unrefp(), sd_bus_track_get_recursive(), sd_bus_track_set_recursive(), sd_bus_track_get_bus(), sd_bus_track_get_userdata(), and sd_bus_track_set_userdata() implement the creation and management of bus object tracks. A bus object track is a mechanism to monitor changes to a specific object path on a D-Bus connection.

sd_bus_track_new() creates a new track associated with the given bus connection, and configured to monitor the object at path. The track object is returned in the track parameter. The new track is initialized with a reference count of one. If path is NULL, the track will monitor the bus itself, i.e. all incoming and outgoing messages.

sd_bus_track_ref() increments the reference count of the track track. This function is useful for keeping track of objects that are only valid as long as at least one reference is held.

sd_bus_track_unref() decrements the reference count of the track track. If the reference count drops to zero, the track is destroyed, and all associated resources are released.

sd_bus_track_unrefp() is similar to sd_bus_track_unref(), but takes a pointer to a pointer to the track. This is useful for releasing the last reference to a track stored in a local variable, as it allows the caller to atomically set the pointer to NULL.

sd_bus_track_get_recursive() returns whether the track is configured for recursive monitoring. If non-zero, the track will monitor all subpaths of the specified path. See sd_bus_track_set_recursive().

sd_bus_track_set_recursive() configures whether the track should operate recursively. If recursive is non-zero, the track will monitor all subpaths of the specified path. If recursive is zero, only the exact path will be monitored.

sd_bus_track_get_bus() returns the bus connection associated with the track.

sd_bus_track_get_userdata() returns the arbitrary user data pointer previously attached to the track with sd_bus_track_set_userdata().

sd_bus_track_set_userdata() attaches an arbitrary user data pointer userdata to the track. This pointer is not managed by the track object and is the responsibility of the caller to manage.

RETURN VALUE

sd_bus_track_new(), sd_bus_track_ref(), sd_bus_track_unref(), sd_bus_track_set_recursive(), and sd_bus_track_set_userdata() return 0 on success, or a negative error number on failure.

sd_bus_track_unrefp() returns the previous value of *trackp.

sd_bus_track_get_recursive() returns non-zero if recursive monitoring is enabled, and zero otherwise.

sd_bus_track_get_bus() returns the bus connection associated with the track.

sd_bus_track_get_userdata() returns the user data pointer attached to the track.

REFERENCE OWNERSHIP

In the case of sd_bus_track_new(), the caller gains ownership of the first reference to the new track. This reference may be passed to other functions or released using sd_bus_track_unref().

In the case of sd_bus_track_ref(), the caller takes ownership of an additional reference to the track. This reference must be released using sd_bus_track_unref().

In the case of sd_bus_track_unrefp(), the caller releases the reference previously held by the pointer trackp. If the reference count drops to zero, the track is destroyed.

NOTES

The sd_bus_track_handler_t type is an alias for sd_bus_message_handler_t. This is used when registering callbacks for bus object tracks.

The functions described here are thread-safe; they may be called from multiple threads simultaneously from the same or different bus objects.

For a more detailed explanation of bus object tracks and their usage, refer to sd-bus(3).

int sd_bus_track_ref(sd_bus_track *track);

الوصف

sd_bus_track_new(), sd_bus_track_handler_t(), sd_bus_track_ref(), sd_bus_track_unref(), sd_bus_track_unrefp(), sd_bus_track_get_recursive(), sd_bus_track_set_recursive(), sd_bus_track_get_bus(), sd_bus_track_get_userdata(), and sd_bus_track_set_userdata() تنفذ إنشاء وإدارة مسارات كائنات الحافلة. مسار كائن الحافلة هو آلية لمراقبة التغييرات على مسار كائن محدد على اتصال D-Bus.

sd_bus_track_new() ينشئ مسارًا جديدًا مرتبطًا باتصال bus المحدد، ومهيأ لمراقبة الكائن في path. يتم إرجاع كائن المسار في المعلمة track. يتم تهيئة المسار الجديد بعدد مراجع واحد. إذا كان path هو NULL، فسيقوم المسار بمراقبة الحافلة نفسها، أي جميع الرسائل الواردة والصادرة.

sd_bus_track_ref() يزيد عدد المراجع للمسار track. هذه الوظيفة مفيدة لتتبع الكائنات التي تكون صالحة فقط طالما أن مرجعًا واحدًا على الأقل موجود.

sd_bus_track_unref() يقلل عدد المراجع للمسار track. إذا انخفض عدد المراجع إلى الصفر، يتم تدمير المسار، ويتم تحرير جميع الموارد المرتبطة به.

sd_bus_track_unrefp() مشابه لـ sd_bus_track_unref()، ولكنه يأخذ مؤشرًا إلى مؤشر للمسار. هذا مفيد لتحرير المرجع الأخير لمسار مخزن في متغير محلي، حيث يسمح للمستدعي بضبط المؤشر إلى NULL بشكل ذري.

sd_bus_track_get_recursive() يرجع ما إذا كان المسار مهيأ للمراقبة التكرارية. إذا كان غير صفري، فسوف يراقب المسار جميع المسارات الفرعية للمسار المحدد path. انظر sd_bus_track_set_recursive().

sd_bus_track_set_recursive() يقوم بتهيئة ما إذا كان المسار سيتم تشغيله بشكل تكراري. إذا كان recursive غير صفري، فسوف يراقب المسار جميع المسارات الفرعية للمسار المحدد path. إذا كان recursive صفرًا، فسيتم مراقبة المسار path المحدد بالضبط فقط.

sd_bus_track_get_bus() يرجع اتصال الحافلة المرتبط بالمسار.

sd_bus_track_get_userdata() يرجع مؤشر بيانات المستخدم العشوائي الذي تم إرفاقه بالمسار سابقًا باستخدام sd_bus_track_set_userdata().

sd_bus_track_set_userdata() يرفق مؤشر بيانات مستخدم عشوائي userdata بالمسار. لا تتم إدارة هذا المؤشر بواسطة كائن المسار وهو مسؤولية المتصل إدارته.

قيمة الإرجاع

sd_bus_track_new(), sd_bus_track_ref(), sd_bus_track_unref(), sd_bus_track_set_recursive(), and sd_bus_track_set_userdata() ترجع 0 عند النجاح، أو رقم خطأ سالب عند الفشل.

sd_bus_track_unrefp() ترجع القيمة السابقة لـ *trackp.

sd_bus_track_get_recursive() يرجع قيمة غير صفرية إذا تم تمكين المراقبة التكرارية، وصفر بخلاف ذلك.

sd_bus_track_get_bus() يرجع اتصال الحافلة المرتبط بالمسار.

sd_bus_track_get_userdata() يرجع مؤشر بيانات المستخدم المرفق بالمسار.

ملكية المرجع

في حالة sd_bus_track_new()، يكتسب المتصل ملكية المرجع الأول للمسار الجديد. يمكن تمرير هذا المرجع إلى وظائف أخرى أو تحريره باستخدام sd_bus_track_unref().

في حالة sd_bus_track_ref()، يأخذ المتصل ملكية مرجع إضافي للمسار. يجب تحرير هذا المرجع باستخدام sd_bus_track_unref().

في حالة sd_bus_track_unrefp()، يقوم المتصل بتحرير المرجع الذي كان يحتفظ به المؤشر trackp سابقًا. إذا انخفض عدد المراجع إلى الصفر، يتم تدمير المسار.

ملاحظات

sd_bus_track_handler_t هو اسم مستعار لـ sd_bus_message_handler_t. يتم استخدامه عند تسجيل ردود الاتصال لمسارات كائنات الحافلة.

الوظائف الموصوفة هنا آمنة للاستخدام من قبل الخيوط المتعددة؛ يمكن استدعاؤها من خيوط متعددة في وقت واحد من كائنات حافلة مختلفة أو نفسها.

لشرح أكثر تفصيلاً لمسارات كائنات الحافلة واستخدامها، ارجع إلى sd-bus(3).
