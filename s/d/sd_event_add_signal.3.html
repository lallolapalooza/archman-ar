NAME

sd_event_add_signal - Define a new event source for a specific signal

SYNOPSIS


    #include <systemd/sd-event.h>

    int sd_event_add_signal(sd_event *event,
                            int *fd,
                            int signum,
                            sd_event_handler_t handler,
                            void *userdata);

DESCRIPTION

Creates a new event source that is triggered when the specified signal signum is received.

The event source is associated with the event loop event. When the signal is received, the handler function is called with userdata.

The fd parameter may be NULL. If it is not NULL, the file descriptor that is used internally to receive signal events will be written into *fd. This file descriptor is set to non-blocking and close-on-exec.

The signum parameter specifies the signal number to monitor. It must be a valid signal number.

The handler parameter is a function pointer to the callback function that will be invoked when the signal is received. The handler function will receive the event loop, the signal number, and the userdata passed to sd_event_add_signal() as arguments.

The userdata parameter is a pointer to arbitrary user data that will be passed to the handler function.

If fd is not NULL, the caller is responsible for closing the file descriptor when it is no longer needed. The file descriptor will be automatically closed when the event source is removed from the event loop.

ARGUMENTS

  • event: The event loop to add the signal event source to.
  • fd: Pointer to a file descriptor to store the signal event FD.
  • signum: The signal number to monitor.
  • handler: The callback function to be invoked when the signal is received.
  • userdata: User data to be passed to the handler function.

RETURN VALUE

On success, returns a non-negative integer representing the event source ID. On failure, returns a negative errno value.

NOTES

This function is equivalent to sd_event_add_io() with the EPOLLIN flag set and a file descriptor obtained from signalfd().

Signals are delivered to a process asynchronously. The signal handler is called asynchronously when the signal is received.

Multiple event sources can be added for the same signal, but only one handler will be called for each signal delivery.

EXAMPLE


    #include <stdio.h>
    #include <stdlib.h>
    #include <systemd/sd-event.h>

    static int signal_handler(sd_event *event, int signum, void *userdata) {
        printf("Signal %d received\n", signum);
        return 0;
    }

    int main() {
        sd_event *event = NULL;
        int r;

        r = sd_event_new(&event);
        if (r < 0) {
            fprintf(stderr, "Failed to create event loop: %s\n", strerror(-r));
            return 1;
        }

        r = sd_event_add_signal(event, NULL, SIGTERM, signal_handler, NULL);
        if (r < 0) {
            fprintf(stderr, "Failed to add signal handler: %s\n", strerror(-r));
            goto finish;
        }

        printf("Waiting for SIGTERM...\n");
        r = sd_event_loop(event);
        if (r < 0) {
            fprintf(stderr, "Failed to run event loop: %s\n", strerror(-r));
        }

    finish:
        sd_event_unref(event);
        return r < 0 ? 1 : 0;
    }

HISTORY

The sd_event_add_signal() function was introduced in version 250.
