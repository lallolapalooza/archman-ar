الوصف

sd_bus_add_object_vtable() يُستخدم للإعلان عن السمات لمسار الكائن path المتصل باتصال الناقل bus تحت الواجهة interface. يمكن أن تحتوي جدول vtable على إعلانات الخصائص باستخدام SD_BUS_PROPERTY() أو SD_BUS_WRITABLE_PROPERTY()، وإعلانات الطرق باستخدام SD_BUS_METHOD()، SD_BUS_METHOD_WITH_NAMES()، SD_BUS_METHOD_WITH_OFFSET() أو SD_BUS_METHOD_WITH_NAMES_OFFSET()، وإعلانات الإشارات باستخدام SD_BUS_SIGNAL_WITH_NAMES() أو SD_BUS_SIGNAL()، انظر أدناه. تحتوي المعلمة userdata على مؤشر يتم تمريره إلى دوال الاستدعاء الراجعة المختلفة. يمكن تحديدها كـ NULL إذا لم تكن هناك حاجة لقيمة. يمكن أن تحتوي الواجهة على أي عدد من جداول vtables المرتبطة بها.

sd_bus_add_fallback_vtable() مشابه لـ sd_bus_add_object_vtable()، لكنه يُستخدم لتسجيل سمات "الاحتياط". عند البحث عن إعلان سمة، يتم النظر أولاً في مسارات الكائنات المسجلة باستخدام sd_bus_add_object_vtable(). إذا لم يكن هناك تطابق، يتم النظر في جداول vtables الاحتياطية لكل بادئة من مسار كائن الناقل، أي مع إزالة مكونات مسار الكائن تباعاً. هذا يسمح باستخدام vtable لأي عدد من الكائنات المنشأة ديناميكياً.

المعلمة find هي دالة تُستخدم لتحديد موقع الكائن الهدف بناءً على مسار كائن الناقل path. يجب أن تُرجع 1 وتضبط معلمة الإخراج ret_found على 1 إذا تم العثور على الكائن، أو تُرجع 0 إذا لم يتم العثور عليه، أو تُرجع رمز خطأ بأسلوب errno أو تهيئ بنية الخطأ ret_error في حالة حدوث خطأ. سيتم استخدام المؤشر الممرر في ret_found كمعلمة userdata لدوال الاستدعاء الراجعة (مع إزاحة بقيمة offset المحددة في إدخالات vtable).

sd_bus_add_object() يربط دالة استدعاء راجعة مباشرة بمسار الكائن path. يمكن أن يحتوي مسار الكائن على أي عدد من دوال الاستدعاء الراجعة المرتبطة به. يتم إضافة كل دالة استدعاء راجعة إلى مقدمة قائمة دوال الاستدعاء الراجعة التي تُستدعى دائماً بالترتيب. sd_bus_add_fallback() مشابه لـ sd_bus_add_object() لكنه ينطبق على مسارات الاحتياط.

sd_bus_add_filter() يثبت دالة استدعاء راجعة تُستدعى لكل رسالة D-Bus مستلمة. يمكن استخدام المرشحات للتعامل مع المنطق المشترك لجميع الرسائل المستلمة بواسطة خدمة (على سبيل المثال، المصادقة أو التفويض).

عند استلام طلب، تُستدعى أي دالة استدعاء راجعة مرتبطة بالتسلسل حتى تُرجع دالة استدعاء راجعة قيمة غير صفرية. إرجاع صفر من دالة استدعاء راجعة يسمح لدوال استدعاء راجعة أخرى بمعالجة الطلب. تُستدعى دوال جميع أسماء الوسائط. // // SD_BUS_WRITABLE_PROPERTY() // // تعريف خاصية D-Bus بالاسم member وتوقيع القيمة signature. // المعلمتان get و set هما طريقتي القارئ والكاتب. يتم استدعاؤهما بمؤشر هو معلمة userdata التي تم تمريرها إلى دالة التسجيل بإزاحة بمقدار offset بايت. // قد يتم استخدام هذا لتمرير مؤشرات إلى حقول مختلفة في نفس بنية البيانات إلى كُتّاب وقراء مختلفين في نفس vtable. // المعلمة flags هي مزيج من العلامات. // قد يتم حذف طريقتي الكاتب والقارئ (تحديدهما كـ NULL) إذا كانت الخاصية من الأنواع الأساسية أو "as" في حالة الخصائص للقراءة فقط. // في هذه الحالات، يجب أن يشير معلما userdata و offset معًا إلى متغير صالح من النوع المقابل. // سيتم توفير طريقة قارئ وكاتب افتراضية، والتي تقوم ببساطة بنسخ الوسيط بين هذا المتغير والرسالة. // // SD_BUS_PROPERTY() // // يستخدم لتعريف خاصية للقراءة فقط. // // SD_BUS_PARAM() // // يجب لف أسماء المعلمات في هذا الماكرو، انظر المثال أدناه. ```

يتم تحديد المؤشر إلى ملف البيانات الذي يتم تمريره إلى الدوال المرتبطة به بشكل مختلف قليلاً: بدلاً من إضافة معامل الإزاحة للسجل المدخل إلى مؤشر المستخدم المحدد أثناء تسجيل vtable، يتم تمرير الإزاحة مباشرة، والتي تصبح مؤشراً دون أخذ مؤشر المستخدم المحدد أثناء تسجيل vtable في الاعتبار.

SD_BUS_VTABLE_CAPABILITY(capability)

يُسمح بالوصول إلى سجل vtable هذا إذا كانت العملية المستدعية تمتلك القدرة capability، كما هو موضح في sd_bus_query_sender_privilege(3). إذا تم استخدامه مع SD_BUS_VTABLE_START()، فإنه يوفر قيمة افتراضية لجميع السجلات في المصفوفة. إذا لم يتم تحديده، يتم التحقق افتراضياً من CAP_SYS_ADMIN لكل سجل فردي أو للمصفوفة بأكملها. راجع capabilities(7) للحصول على معلومات حول القدرات.

لاحظ أن سجلات vtable يمكن تمييزها كغير مميزة ويمكن تمييز الناقل بالكامل كموثوق، كما هو مناقش في SD_BUS_VTABLE_UNPRIVILEGED أدناه.

SD_BUS_VTABLE_UNPRIVILEGED

ضع علامة على سجل vtable هذا كغير مميز. يقتصر الوصول إلى السجلات المميزة على المستخدمين ذوي القدرات المناسبة، كما هو موضح أعلاه. عملياً، يتم تمييز العديد من سجلات vtable كغير مميزة، ويمكن أن تكون مفتوحة للجميع أو يتم تحديد الوصول لاحقاً، على سبيل المثال، بالتفويض إلى polkit[2].

يمكن تمييز الناقل بالكامل كموثوق، وفي هذه الحالة يتم تجاهل التعليقات التوضيحية على مستوى السجل، كما هو موضح في sd_bus_set_trusted(3).

عند عدم تحديده، سيظهر في بيانات الاستبطان التعليق التوضيحي org.freedesktop.systemd1.Privileged بقيمة "true"。

لا يمكن تطبيق SD_BUS_VTABLE_UNPRIVILEGED على الخصائص للقراءة فقط، لكن الوصول (إلى كل من خصائص القراءة والكتابة) يكون دائماً غير مقيد.

لاحظ أن هذه الصفحة تصف عناصر التحكم المنفذة في عميل D-Bus. لدى خادم D-Bus سياسة إضافية يمكنها السماح أو رفض الاتصالات، كما هو موضح في ملف تكوين dbus-daemon(1).

أمثلة

مثال 1. إنشاء مستمع بسيط على الناقل

/* SPDX-License-Identifier: MIT-0 */  
#define _GNU_SOURCE 1  
#include <errno.h>  
#include <stdbool.h>  
#include <stddef.h>  
#include <stdlib.h>  
#include <stdio.h>  
#include <systemd/sd-bus.h>  
#define _cleanup_(f) __attribute__((cleanup(f)))  
typedef struct object {  
  char *name;  
  uint32_t number;  
} object;  
static int method(sd_bus_message *m, void *userdata, sd_bus_error *error) {  
  int r;  
  printf("Got called with userdata=%p\n", userdata);  
  if (sd_bus_message_is_method_call(m,  
                                    "org.freedesktop.systemd.VtableExample",
                                    "Method4"))  
    return 1;  
  const char *string;  
  r = sd_bus_message_read(m, "s", &string);  
  if (r < 0) {  
    fprintf(stderr, "sd_bus_message_read() failed: %s\n", strerror(-r));  
    return 0;  
  }  
  r = sd_bus_reply_method_return(m, "s", string);  
  if (r < 0) {  
    fprintf(stderr, "sd_bus_reply_method_return() failed: %s\n", strerror(-r));  
    return 0;  
  }  
  return 1;  
}  
static const sd_bus_vtable vtable[] = {  
        SD_BUS_VTABLE_START(0),  
        SD_BUS_METHOD(  
            "Method1", "s", "s", method, 0),  
        SD_BUS_METHOD_WITH_NAMES_OFFSET(  
            "Method2",  
            "so", SD_BUS_PARAM(string) SD_BUS_PARAM(path),  
            "s", SD_BUS_PARAM(returnstring),  
            method, offsetof(object, number),  
            SD_BUS_VTABLE_DEPRECATED),  
        SD_BUS_METHOD_WITH_ARGS_OFFSET(  
            "Method3",  
            SD_BUS_ARGS("s", string, "o", path),  
            SD_BUS_RESULT("s", returnstring),  
            method, offsetof(object, number),  
            SD_BUS_VTABLE_UNPRIVILEGED),  
        SD_BUS_METHOD_WITH_ARGS(  
            "Method4",  
            SD_BUS_NO_ARGS,  
            SD_BUS_NO_RESULT,  
            method,  
            SD_BUS_VTABLE_UNPRIVILEGED),  
        SD_BUS_SIGNAL(  
            "Signal1",  
            "so",  
            0),  
        SD_BUS_SIGNAL_WITH_NAMES(  
            "Signal2",  
            "so", SD_BUS_PARAM(string) SD_BUS_PARAM(path),  
            0),  
        SD_BUS_SIGNAL_WITH_ARGS(  
            "Signal3",  
            SD_BUS_ARGS("s", string, "o", path),  
            0),  
        SD_BUS_WRITABLE_PROPERTY(  
            "AutomaticStringProperty", "s", NULL, NULL,  
            offsetof(object, name),  
            SD_BUS_VTABLE_PROPERTY_EMITS_CHANGE),  
        SD_BUS_WRITABLE_PROPERTY(  
            "AutomaticIntegerProperty", "u", NULL, NULL,  
            offsetof(object, number),  
            SD_BUS_VTABLE_PROPERTY_EMITS_INVALIDATION),  
        SD_BUS_VTABLE_END  
};  
int main(int argc, char **argv) {  
  _cleanup_(sd_bus_flush_close_unrefp) sd_bus *bus = NULL;  
  int r;  
  sd_bus_default(&bus);  
  object object = { .number = 666 };  
  object.name = strdup("name");  
  if (!object.name) {  
    fprintf(stderr, "OOM\n");  
    return EXIT_FAILURE;  
  }  
  r = sd_bus_add_object_vtable(bus, NULL,  
                               "/org/freedesktop/systemd/VtableExample",
                               "org.freedesktop.systemd.VtableExample",
                               vtable,  
                               &object);  
  if (r < 0) {  
    fprintf(stderr, "sd_bus_add_object_vtable() failed: %s\n", strerror(-r));  
    return EXIT_FAILURE;  
  }  
  r = sd_bus_request_name(bus,  
                          "org.freedesktop.systemd.VtableExample",
                          0);  
  if (r < 0) {  
    fprintf(stderr, "sd_bus_request_name() failed: %s\n", strerror(-r));  
    return EXIT_FAILURE;  
  }  
  for (;;) {  
    r = sd_bus_wait(bus, UINT64_MAX);  
    if (r < 0) {  
      fprintf(stderr, "sd_bus_wait() failed: %s\n", strerror(-r));  
      return EXIT_FAILURE;  
    }  
    r = sd_bus_process(bus, NULL);  
    if (r < 0) {  
      fprintf(stderr, "sd_bus_process() failed: %s\n", strerror(-r));  
      return EXIT_FAILURE;  
    }  
  }  
  r = sd_bus_release_name(bus, "org.freedesktop.systemd.VtableExample");  
  if (r < 0) {  
    fprintf(stderr, "sd_bus_release_name() failed: %s\n", strerror(-r));  
    return EXIT_FAILURE;  
  }  
  free(object.name);  
  return 0;  
}

قيمة الإرجاع

عند النجاح، تُرجع sd_bus_add_object_vtable() وsd_bus_add_fallback_vtable() رقماً غير سالب. عند الفشل، تُرجع رمز خطأ سالب بأسلوب errno.

الأخطاء

قد تشير الأخطاء المُرجعة إلى المشكلات التالية:

-EINVAL

معامل مطلوب هو NULL أو غير صالح. تم تمرير واجهة D-Bus محجوزة كمعامل interface.

-ENOPKG

لا يمكن حل الناقل.

-ECHILD

تم إنشاء الناقل في عملية أو مكتبة أو وحدة مختلفة.

-ENOMEM

فشل تخصيص الذاكرة.

-EPROTOTYPE

تم استدعاء sd_bus_add_object_vtable() وsd_bus_add_fallback_vtable() لنفس مسار كائن الناقل، وهو ما لا يُسمح به.

-EEXIST

تم تسجيل vtable هذا بالفعل لهذه interface وpath.

ملاحظات

تشير الدوال الموصوفة إلى he.

متاحة كمكتبة مشتركة، والتي يمكن تجميعها مقابلها وربطها باستخدام ملف libsystemd pkg-config(1).

يستخدم الكود الموصوف هنا getenv(3)، والذي يُصرَّح بأنه غير آمن متعدد الخيوط. هذا يعني أن الكود الذي يستدعي الدوال الموصوفة هنا يجب ألا يستدعي setenv(3) من خيط متوازٍ. يُوصى بإجراء استدعاءات setenv() فقط من مرحلة مبكرة من البرنامج عندما لم تكن قد بدأت أي خيوط أخرى.
