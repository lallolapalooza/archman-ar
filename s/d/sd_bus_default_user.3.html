sd_bus_default_user(3)

الحزمة: systemd-libs

التراخيص: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

الاسم

sd_bus_default, sd_bus_default_user, sd_bus_default_system, sd_bus_open, sd_bus_open_user, sd_bus_open_system, sd_bus_open_system_remote, sd_bus_open_system_machine, sd_bus_open_with_description, sd_bus_open_user_with_description, sd_bus_open_system_with_description, sd_bus_open_user_machine - الاتصال بحافلة النظام أو المستخدم

الملخص

#include <systemd/sd-bus.h>

int sd_bus_default(sd_bus **bus);
int sd_bus_default_user(sd_bus **bus);
int sd_bus_default_system(sd_bus **bus);
int sd_bus_open(sd_bus **bus);
int sd_bus_open_user(sd_bus **bus);
int sd_bus_open_system(sd_bus **bus);
int sd_bus_open_system_remote(sd_bus **bus, const char *destination);
int sd_bus_open_system_machine(sd_bus **bus, const char *machine);
int sd_bus_open_with_description(sd_bus **bus, const char *description);
int sd_bus_open_user_with_description(sd_bus **bus, const char *description);
int sd_bus_open_system_with_description(sd_bus **bus, const char *description);
int sd_bus_open_user_machine(sd_bus **bus, const char *machine);

الوصف

تمثل هذه الدوال واجهة لتوفير اتصال بحافلة نظام D-Bus. الحافلة هي وسيلة لتوصيل العمليات (IPC) تسمح للعمليات بتبادل الرسائل. النظام لديه حافلة نظام مركزية (خاصة بالنظام) وحافلة مستخدم لكل مستخدم مسجل الدخول.

sd_bus_default()، sd_bus_default_user()، و sd_bus_default_system() توفر وصولاً إلى الحافلة الافتراضية. تعتمد الحافلة الافتراضية على البيئة، وقد تعتمد على المتغيرات البيئية أو الميزات الأخرى لتحديد الحافلة الصحيحة. عادةً ما تكون هذه الدوال مفيدة في التطبيقات البسيطة حيث يكون هناك اتصال حافلة واحد فقط نشط. يتم استخدام اتصال الحافلة الافتراضي غالبًا بواسطة الأدوات المساعدة التي تعمل في الخلفية أو الأدوات التي تتفاعل مع النظام.

sd_bus_open()، sd_bus_open_user()، و sd_bus_open_system() توفر طرقًا صريحة لفتح اتصال بالحافلة. sd_bus_open() هو غلاف عام يمكنه فتح حافلة المستخدم أو النظام بناءً على البيئة. sd_bus_open_user() تفتح دائمًا حافلة المستخدم، و sd_bus_open_system() تفتح دائمًا حافلة النظام.

sd_bus_open_system_remote()، sd_bus_open_system_machine()، و sd_bus_open_user_machine() تسمح بالاتصال بحافلة نظام أو مستخدم في جهاز بعيد أو آلة مسيطر عليها. هذه الدوال مفيدة للتفاعل مع الأنظمة البعيدة أو الأجهزة التي يتم إدارتها بواسطة systemd-machined.

sd_bus_open_with_description()، sd_bus_open_user_with_description()، و sd_bus_open_system_with_description() تسمح بتحديد وصف تفصيلي للحافلة التي سيتم الاتصال بها. يمكن أن يكون هذا مفيدًا لتوضيح الغرض من الاتصال أو لتتبع اتصالات الحافلات المتعددة.

بعد فتح اتصال بالحافلة، يتم تخزين مؤشر إلى هيكل sd_bus في المتغير الذي يشير إليه المعامل bus. يجب على المستدعي استدعاء sd_bus_unref(3) عندما لا يعد الاتصال مطلوبًا لتحرير الموارد.

التعامل مع الرسائل الواردة غير المقروءة

عند استخدام نظام الحافلة الافتراضي، قد تحتاج إلى التعامل مع الرسائل الواردة غير المقروءة قبل إغلاق الاتصال. يمكن القيام بذلك عن طريق استدعاء sd_bus_flush() قبل استدعاء sd_bus_close(). سيؤدي استدعاء sd_bus_close() إلى إغلاق اتصال الحافلة.

عندما تنتهي دورة حياة مؤشر الحافلة (على سبيل المثال، عند إنهاء مؤشر ترابط أو عملية)، من الجيد استدعاء sd_bus_flush() متبوعًا بـ sd_bus_close() لتحرير كائن اتصال الحافلة.

عادةً ما تحتفظ كائنات فتحات الحافلة (التي يتم إنشاؤها بواسطة sd_bus_add_match(3) والدوال المماثلة) بمرجع إلى كائن اتصال الحافلة الخاص بها. وبالتالي، طالما بقي كائن فتحة الحافلة مرجعًا، سيظل كائن الحافلة مخصصًا أيضًا. اختياريًا، يمكن وضع كائنات فتحات الحافلة في وضع "عائم". عند العمل في الوضع العائم، ترتبط دورة حياة كائن فتحة الحافلة بكائن الحافلة، أي عند تحرير كائن الحافلة، يتم إلغاء مرجع كائن فتحة الحافلة تلقائيًا أيضًا. يمكن التحكم في حالة العائم لكائن الفتحة بشكل صريح باستخدام sd_bus_slot_set_floating(3)، على الرغم من أنه عادةً ما يتم إنشاء كائنات فتحات الحافلة العائمة عن طريق تمرير NULL كمعامل slot للدوال مثل sd_bus_add_match()، مما يشير إلى أن المتصل لا يهتم مباشرة بإدارة مرجع كائن فتحة الحافلة.

تعتبر دورة حياة اتصال الحافلة الافتراضي مسؤولية الكود الذي يقوم بإنشاء/امتلاك مؤشر الترابط المرتبط بكائن اتصال الحافلة الافتراضي. يجب ألا تستدعي كود المكتبات sd_bus_flush() أو sd_bus_close() على كائنات الحافلة الافتراضية إلا إذا فعلت ذلك في مؤشر ترابط خاص بها، مخصص ذاتيًا. يجب ألا يستخدم كود المكتبات كائن الحافلة الافتراضي في مؤشرات الترابط الأخرى إلا إذا كان من الواضح أن البرنامج الذي يستخدمه سيدير دورة حياة كائن اتصال الحافلة وسيقوم بتنظيفه وإغلاقه قبل الخروج من مؤشر الترابط. في المكتبات حيث ليس من الواضح أن البرنامج المستدعي سيدير دورة حياة كائن اتصال الحافلة، يوصى باستخدام sd_bus_open_system() بدلاً من sd_bus_default_system() والدوال المماثلة.

قيمة الإرجاع

عند النجاح، تعيد هذه الدوال 0 أو عددًا صحيحًا موجبًا. عند الفشل، تعيد هذه الدوال رمز خطأ سالبًا بأسلوب errno.

الأخطاء

قد تشير الأخطاء المعادة إلى المشاكل التالية:

-EINVAL

المعاملات المحددة غير صالحة.

-ENOMEDIUM

نوع الحافلة المطلوب غير متوفر بسبب بيئة غير صالحة (على سبيل المثال، حافلة جلسة المستخدم غير متوفرة لأن $XDG_RUNTIME_DIR لم يتم تعيينها).

-ENOMEM

فشل تخصيص الذاكرة.

-ESOCKTNOSUPPORT

إصدار البروتوكول المطلوب للاتصال بالحافلة المحددة غير مدعوم.

بالإضافة إلى ذلك، قد يتم إرجاع أخطاء أخرى متعلقة بالاتصال. راجع sd_bus_send(3).

ملاحظات

الدوال الموصوفة هنا متاحة كمكتبة مشتركة، والتي يمكن تجميعها والربط بها باستخدام ملف pkg-config(1) الخاص بـ libsystemd.

الكود الموصوف هنا يستخدم getenv(3)، والتي تم الإعلان عنها على أنها ليست آمنة للاستخدام مع مؤشرات الترابط المتوازية. هذا يعني أن الكود الذي يستدعي الدوال الموصوفة هنا يجب ألا يستدعي setenv(3) من مؤشر ترابط متوازي. يوصى بإجراء استدعاءات لـ setenv() فقط في مرحلة مبكرة من البرنامج عندما لم يتم بدء أي مؤشرات ترابط أخرى.
