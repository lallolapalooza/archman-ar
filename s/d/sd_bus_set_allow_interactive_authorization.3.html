sd_bus_set_allow_interactive_authorization(3)

الحزمة: systemd-libs

التراخيص: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_BUS_SET_DESCRIPTION(3) sd_bus_set_description SD_BUS_SET_DESCRIPTION(3)

الاسم

sd_bus_set_description، sd_bus_get_description، sd_bus_set_anonymous، sd_bus_is_anonymous، sd_bus_set_trusted، sd_bus_is_trusted، sd_bus_set_allow_interactive_authorization، sd_bus_get_allow_interactive_authorization، sd_bus_get_scope، sd_bus_get_tid، sd_bus_get_unique_name - تعيين أو الاستعلام عن خصائص كائن الناقل

الملخص

#include <systemd/sd-bus.h>

int sd_bus_set_description(sd_bus *bus، const char *description);

int sd_bus_get_description(sd_bus *bus، const char **description);

int sd_bus_set_anonymous(sd_bus *bus، int b);

int sd_bus_is_anonymous(sd_bus *bus);

int sd_bus_set_trusted(sd_bus *bus، int b);

int sd_bus_is_trusted(sd_bus *bus);

int sd_bus_set_allow_interactive_authorization(sd_bus *bus، int b);

int sd_bus_get_allow_interactive_authorization(sd_bus *bus);

int sd_bus_get_scope(sd_bus *bus، const char **scope);

int sd_bus_get_tid(sd_bus *bus، pid_t *tid);

int sd_bus_get_unique_name(sd_bus *bus، const char **unique);

الوصف

sd_bus_set_description() تقوم بتعيين سلسلة الوصف التي تُستخدم في التسجيل إلى السلسلة المحددة. يتم نسخ السلسلة داخليًا وتحريرها عند إلغاء تخصيص كائن الناقل. قد يكون الوسيط description NULL، وفي هذه الحالة يتم إلغاء تعيين الوصف. يجب استدعاء هذه الدالة قبل بدء تشغيل الناقل.

sd_bus_get_description() تُرجع سلسلة وصف في description. قد تكون هذه السلسلة قد تم تعيينها سابقًا باستخدام sd_bus_set_description() أو sd_bus_open_with_description(3) أو ما شابه. إذا لم يتم تعيينها بهذه الطريقة، سيتم إرجاع سلسلة افتراضية مثل "system" أو "user" للنواقل النظام أو المستخدم، و -ENXIO بخلاف ذلك.

sd_bus_set_anonymous() تقوم بتمكين أو تعطيل "المصادقة المجهولة"، أي عدم وجود مصادقة، للطرف الآخر على الناقل. يجب استدعاء هذه الدالة قبل بدء تشغيل الناقل. انظر قسم **آليات مصادقة D-Bus**[1] في مواصفات D-Bus للحصول على التفاصيل.

sd_bus_is_anonymous() تُرجع صحيحًا إذا كان اتصال الناقل يسمح بالمصادقة المجهولة (بالمعنى الموضح في الفقرة السابقة).

sd_bus_set_trusted() تقوم بتعيين حالة "موثوق به" على كائن bus. إذا كانت صحيحة، فسيتم الوثوق بجميع الاتصالات على الناقل وسيتم منح الوصول إلى جميع الطرق المميزة وغير المميزة. يجب استدعاء هذه الدالة قبل بدء تشغيل الناقل.

sd_bus_is_trusted() تُرجع صحيحًا إذا كان اتصال الناقل موثوقًا به (بالمعنى الموضح في الفقرة السابقة).

sd_bus_set_allow_interactive_authorization() تقوم بتمكين أو تعطيل التفويض التفاعلي لاستدعاءات الطرق. إذا كانت صحيحة، فسيتم تمييز الرسائل بعلم **ALLOW_INTERACTIVE_AUTHORIZATION** المحدد بواسطة مواصفات **D-Bus**[2]، مما يُعلم الجانب المستقبل بأن المتصل مستعد للانتظار للتفويض التفاعلي، والذي قد يستغرق وقتًا طويلاً للإكمال. إذا تم تعيين هذا العلم، فقد يُطلب من المستخدم كلمات مرور أو تأكيد عبر **polkit**[3] أو إطار عمل مشابه.

sd_bus_get_allow_interactive_authorization() تُرجع صحيحًا إذا كان التفويض التفاعلي مسموحًا به وصحيحًا إذا لم يكن كذلك.

sd_bus_get_scope() تخزن نطاق كائن الناقل المحدد في scope. نطاق ناقل النظام هو "system". نطاق ناقل جلسة المستخدم هو "user". إذا لم يكن كائن الناقل المحدد هو ناقل النظام أو ناقل جلسة مستخدم، فإن sd_bus_get_scope() تُرجع خطأ.

sd_bus_get_tid() تخزن معرف مؤشر ترابط النواة للمؤشر المرتبط بكائن الناقل المحدد في tid. إذا كان bus كائن ناقل افتراضي تم الحصول عليه عن طريق استدعاء إحدى دوال عائلة sd_bus_default(3)، فإنه يخزن معرف مؤشر ترابط المؤشر الذي تم إنشاء كائن الناقل فيه. بخلاف ذلك، إذا كان كائن الناقل متصلاً بحلقة أحداث، فإنه يخزن معرف مؤشر ترابط المؤشر الذي تم إنشاء كائن حلقة الأحداث فيه. إذا لم يكن bus كائن ناقل افتراضي ولم يكن متصلاً بحلقة أحداث، فإن sd_bus_get_tid() تُرجع خطأ.

sd_bus_get_unique_name() تخزن الاسم الفريد لكائن الناقل على الناقل في unique. انظر **مواصفات D-Bus**[4] لمزيد من المعلومات حول أسماء النواقل. لاحظ أن المستدعي لا يمتلك السلسلة المخزنة في unique ويجب ألا يقوم بتحريرها.

قيمة الإرجاع

عند النجاح، تُرجع هذه الدوال عددًا صحيحًا غير سالب. عند الفشل، تُرجع رمز خطأ سالبًا بنمط errno.

الأخطاء

قد تشير الأخطاء المرجعة إلى المشكلات التالية:

-EINVAL

وسيط غير صالح.

-ENOPKG

لا يمكن حل الناقل.

-EPERM

تم بدء تشغيل الناقل بالفعل.

-ECHILD

تم إنشاء الناقل في عملية أو مكتبة أو وحدة أخرى.

-ENOMEM

فشل تخصيص الذاكرة.

-ENODATA

كائن الناقل الذي تم تمريره إلى sd_bus_get_scope() لم يكن ناقل نظام أو ناقل جلسة مستخدم.

تمت الإضافة في الإصدار 246.

-ENXIO

كائن الناقل الذي تم تمريره إلى sd_bus_get_tid() لم يكن كائن ناقل افتراضي ولم يكن متصلاً بحلقة أحداث.

كائن الناقل الذي تم تمريره إلى sd_bus_get_description() لم يكن لديه description.

تمت الإضافة في الإصدار 246.

ملاحظات

الدوال الموصوفة هنا متاحة كمكتبة مشتركة، والتي يمكن تجميعها وربطها مع ملف pkg-config(1) الخاص بـlibsystemd.

الكود الموصوف هنا يستخدم getenv(3)، والذي تم الإعلان عنه بأنه غير آمن للاستخدام مع الخيوط المتوازية. هذا يعني أن الكود الذي يستدعي الدوال الموصوفة هنا يجب ألا يستدعي setenv(3) من خيط متوازي. يوصى بإجراء استدعاءات لـsetenv() فقط من مرحلة مبكرة من البرنامج عندما لم يتم بدء أي خيوط أخرى.

sd_bus_set_allow_interactive_authorization(3) — systemd

NAME

sd_bus_set_allow_interactive_authorization - Set whether interactive authorization is allowed for a bus connection

SYNOPSIS

#include <systemd/sd-bus.h>

int sd_bus_set_allow_interactive_authorization(sd_bus *bus, int allow_interactive_authorization);

DESCRIPTION

sd_bus_set_allow_interactive_authorization() controls whether the D-Bus connection bus is allowed to engage in interactive authorization, usually via polkit(8).

If allow_interactive_authorization is non-zero, interactive authorization is allowed. If it is zero, it is disallowed.

This setting affects all subsequent D-Bus method calls originating from this connection. Specifically, it influences whether the D-Bus daemon may ask the user for authorization if a method call requires privileges that the calling process does not possess.

The default for a newly created bus connection is to allow interactive authorization.

Interactive authorization is typically used for user-facing operations. For daemon-to-daemon communication or operations running with elevated privileges, it is usually desirable to disallow interactive authorization, as there might not be an interactive user to ask.

Note that this function only affects whether the client *requests* that interactive authorization be allowed. It does not guarantee that authorization will be interactive. The D-Bus daemon decides what kind of authorization to perform, based on its own configuration and the security context of the client.

RETURN VALUE

On success, sd_bus_set_allow_interactive_authorization() returns 0. On failure, it returns a negative errno value.

NOTES

This function is available as a shared library, which can be linked against with the pkg-config(1) utility:

$ pkg-config --cflags --libs libsystemd

This function might change the underlying credentials used by the D-Bus connection. For example, if interactive authorization is enabled, the connection might be associated with a specific user session. If it is disabled, it might fall back to using system-wide authorization or another mechanism.

HISTORY

The sd_bus_set_allow_interactive_authorization() function was added in version 230.
