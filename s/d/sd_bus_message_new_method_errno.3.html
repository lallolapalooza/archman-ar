sd_bus_message_new_method_errno(3)

الحزمة: systemd-libs

التراخيص: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_BUS_MESSAGE_NEW_METHOD_ERROR(3) sd_bus_message_new_method_error SD_BUS_MESSAGE_NEW_METHOD_ERROR(3)

الاسم

sd_bus_message_new_method_error, sd_bus_message_new_method_errorf, sd_bus_message_new_method_errno, sd_bus_message_new_method_errnof - إنشاء رد خطأ لاستدعاء طريقة

الملخص

#include <systemd/sd-bus.h>

int sd_bus_message_new_method_error(sd_bus_message *call, sd_bus_message **m, const sd_bus_error *e);

int sd_bus_message_new_method_errorf(sd_bus_message *call, sd_bus_message **m, const char *name, const char *format, ...);

int sd_bus_message_new_method_errno(sd_bus_message *call, sd_bus_message **m, int error, const sd_bus_error *p);

int sd_bus_message_new_method_errnof(sd_bus_message *call, sd_bus_message **m, int error, const char *format, ...);

الوصف

تقوم الدالة sd_bus_message_new_method_error() بإنشاء كائن رسالة ناقل جديد يكون رد خطأ للرسالة call، وتعيده في المعامل الإخراجي m. تتم إضافة معلومات الخطأ من الخطأ e: يتم استخدام حقل name من e كمعرف خطأ في رأس الرد (على سبيل المثال، اسم خطأ مثل "org.freedesktop.DBus.Error.NotSupported" أو الرمز المكافئ SD_BUS_ERROR_NOT_SUPPORTED)، ويتم تعيين حقل message كسلسلة نصية قابلة للقراءة من الخطأ البشري إذا كانت موجودة. يجب أن يكون الخطأ e قد تم تعيين حقل name له، انظر sd_bus_error_is_set(3).

تقوم الدالة sd_bus_message_new_method_errorf() بإنشاء رد خطأ بشكل مشابه لـ sd_bus_message_new_method_error()، ولكن بدلاً من بنية خطأ جاهزة، تأخذ سلسلة معرف الخطأ name، بالإضافة إلى سلسلة تنسيق printf(3) format والمعاملات المقابلة. يتم إرسال رد خطأ بمعرف الخطأ name والسلسلة المنسقة كرسالة. يجب ألا يكون name و format NULL.

تقوم الدالة sd_bus_message_new_method_errno() بإنشاء رد خطأ بشكل مشابه لـ sd_bus_message_new_method_error()، ولكن بالإضافة إلى بنية الخطأ p، تأخذ قيمة خطأ errno(3) في المعامل error. إذا تم تعيين الخطأ p (انظر sd_bus_error_is_set(3))، فسيتم استخدامه في الرد. بخلاف ذلك، يتم ترجمة error إلى معرف خطأ ويتم استخدامه لإنشاء بنية خطأ جديدة باستخدام sd_bus_error_set_errno(3) ويتم استخدامها في الرد. (إذا كان error صفرًا، فلن يتم تعيين أي خطأ فعليًا، وسيتم إنشاء رد خطأ بدون معلومات.)

تقوم الدالة sd_bus_message_new_method_errnof() بإنشاء رد خطأ بشكل مشابه لـ sd_bus_message_new_method_error(). تأخذ قيمة خطأ errno(3) في المعامل error، بالإضافة إلى سلسلة تنسيق printf(3) format والمعاملات المقابلة. يمكن استخدام "%m" في سلسلة التنسيق للإشارة إلى سلسلة الخطأ المقابلة لرمز errno المحدد. يتم تهيئة رسالة الخطأ باستخدام معرف الخطأ الذي تم إنشاؤه من error والسلسلة المنسقة. (إذا كان error صفرًا، فلن يتم تعيين أي خطأ فعليًا، وسيتم إنشاء رد خطأ بدون معلومات.)

قيمة الإرجاع

تعيد هذه الدوال القيمة 0 إذا تم إنشاء رد الخطأ بنجاح، ورمز خطأ سالب من نوع errno بخلاف ذلك.

الأخطاء

قد تشير الأخطاء التي تم إرجاعها إلى المشاكل التالية:

-EINVAL

معامل رسالة الاستدعاء call أو معامل الإخراج m هو NULL.

الرسالة call ليست رسالة استدعاء طريقة.

المعامل e للخطأ في sd_bus_message_new_method_error() غير معين، انظر sd_bus_error_is_set(3).

-EPERM

تم ختم الرسالة call.

-ENOTCONN

الناقل الذي تم إرفاق الرسالة call به غير متصل.

-ENOMEM

فشل تخصيص الذاكرة.

ملاحظات

الوظائف الموصوفة هنا متاحة كمكتبة مشتركة، والتي يمكن تجميعها وربطها بملف libsystemd pkg-config(1).

يستخدم الكود الموصوف هنا getenv(3)، وهو غير آمن للاستخدام المتعدد الخيوط. هذا يعني أن الكود الذي يستدعي الوظائف الموصوفة هنا يجب ألا يستدعي setenv(3) من خيط موازٍ. يوصى فقط بإجراء استدعاءات لـ setenv() من مرحلة مبكرة من البرنامج عندما لم يتم بدء أي خيوط أخرى.
