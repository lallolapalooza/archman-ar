sd_event_add_io(3)

الحزمة: systemd-libs

التراخيص: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

NAME

sd_event_add_io, sd_event_source_get_io_events, sd_event_source_set_io_events, sd_event_source_get_io_revents, sd_event_source_get_io_fd, sd_event_source_set_io_fd, sd_event_source_get_io_fd_own, sd_event_source_set_io_fd_own — حدث إدخال/إخراج (I/O event) لـ sd-event

SYNOPSIS

#include <systemd/sd-event.h>

int sd_event_add_io(sd_event *event, sd_event_source **source, int fd, uint32_t events, sd_io_handler_t *callback, void *userdata);

uint32_t sd_event_source_get_io_events(sd_event_source *source);

int sd_event_source_set_io_events(sd_event_source *source, uint32_t events);

uint32_t sd_event_source_get_io_revents(sd_event_source *source);

int sd_event_source_get_io_fd(sd_event_source *source);

int sd_event_source_set_io_fd(sd_event_source *source, int fd);

int sd_event_source_get_io_fd_own(sd_event_source *source);

int sd_event_source_set_io_fd_own(sd_event_source *source, int own);

DESCRIPTION

Uses the sd-event(3) event loop to wait for events on a file descriptor fd. This is useful for reacting to data becoming available on a socket, a pipe, or a file.

Calls to sd_event_add_io(), sd_event_add_time(), sd_event_add_signal(), sd_event_add_child(), sd_event_add_inotify(), sd_event_add_defer(), and sd_event_add_exit() all create new event sources. The event loop object event must be valid.

The callback function is called when any of the specified events occur on the file descriptor fd. The userdata pointer is passed to the callback.

The events parameter is a bitmask of the following constants: EPOLLIN, EPOLLPRI, EPOLLOUT, EPOLLRDHUP.

The return value of the callback determines the next step. If the callback returns a value less than 0, it is interpreted as an error code and the event source is removed. If the callback returns 0, the event source is left as is. If the callback returns a positive value, it is interpreted as the next event mask, and the event source is updated accordingly.

If source is not NULL, a pointer to the newly created event source object is stored there. The event source object may be used later to modify or destroy the source.

sd_event_source_get_io_events() returns the event mask of the I/O event source source.

sd_event_source_set_io_events() changes the event mask of the I/O event source source to events.

sd_event_source_get_io_revents() returns the events that have actually occurred on the file descriptor fd of the I/O event source source. These are the events that were passed to the callback. This is only useful inside the callback.

sd_event_source_get_io_fd() returns the file descriptor associated with the I/O event source source.

sd_event_source_set_io_fd() changes the file descriptor associated with the I/O event source source to fd. If the old file descriptor was owned by the event source (see sd_event_source_set_io_fd_own()), it will be closed before the new one is associated. If the new fd is owned by the event source, it will be closed when the event source is destroyed or when the file descriptor is replaced again.

sd_event_source_set_io_fd_own() controls whether the event source takes ownership of the file descriptor fd. If own is true (non-zero), the file descriptor will be closed automatically when the event source is destroyed. If own is false (zero), the file descriptor is not closed automatically. By default, the file descriptor is not owned by the event source, and the application has to close it on its own if needed.

sd_event_source_get_io_fd_own() may be used to query the current setting of the file descriptor ownership boolean flag as set with sd_event_source_set_io_fd_own(). It returns positive if the file descriptor is closed automatically when the event source is destroyed, zero if not, and negative on error.

RETURN VALUE

On success, these functions return 0 or a positive integer. On failure, they return a negative errno-style error code.

Errors

Returned values may indicate the following problems:

-ENOMEM

Not enough memory to allocate an object.

-EINVAL

An invalid argument has been passed.

-ESTALE

The event loop is already terminated.

-ECHILD

The event loop has been created in a different process, library or module instance.

-EDOM

The passed event source is not an I/O event source.

-EPERM

The passed file descriptor does not support the epoll(7) API, for example because it is a regular file or directory. See epoll_ctl(2) for details.

Added in version 255.

NOTES

Functions described here are available as a shared library, which can be compiled against and linked to with the libsystemd pkg-config(1) file.

The code described here uses getenv(3), which is declared to be not multi-thread-safe. This means that the code calling the functions described here must not call setenv(3) from a parallel thread. It is recommended to only do calls to setenv() from an early phase of the program when no other threads have been started.
