الوصف

sd_event_add_child() يضيف مصدر حدث تغيير حالة عملية فرعية جديد إلى حلقة أحداث. يتم تحديد كائن حلقة الأحداث في المعلمة event، ويتم إرجاع كائن مصدر الحدث في المعلمة source. تحدد المعلمة pid معرف العملية (PID) للعملية المراد مراقبتها، والتي يجب أن تكون عملية فرعية مباشرة للعملية المستدعية. تحدد المعلمة options أي تغييرات في الحالة سيتم مراقبتها. يجب أن تحتوي على قناع ORed من WEXITED (مراقبة إنهاء العملية الفرعية)، WSTOPPED (مراقبة توقف العملية الفرعية بسبب إشارة)، و WCONTINUED (مراقبة استئناف العملية الفرعية بسبب إشارة). انظر waitid(2) لمزيد من المعلومات.

يجب أن تكون handler دالة يتم استدعاؤها عند تغيير حالة العملية أو NULL. سيتم تمرير المؤشر userdata إلى الدالة المعالجة، والذي يمكن اختياره بحرية من قبل المتصل. تتلقى الدالة المعالجة أيضًا مؤشرًا إلى بنية siginfo_t تحتوي على معلومات حول حدث العملية الفرعية. قد تُرجع الدالة المعالجة قيمة سالبة للإشارة إلى خطأ (انظر أدناه)، ويتم تجاهل القيم المرجعة الأخرى. إذا كانت handler هي NULL، فسيتم استخدام معالج افتراضي يستدعي sd_event_exit(3).

يمكن تثبيت معالج واحد فقط لعملية فرعية محددة. يتم تمكين المعالج لحدث واحد (SD_EVENT_ONESHOT)، ولكن يمكن تغيير هذا باستخدام sd_event_source_set_enabled(3). إذا أعادت الدالة المعالجة رمز خطأ سالبًا، فسيتم تعطيلها إما بعد الاستدعاء، حتى لو تم طلب وضع SD_EVENT_ON من قبل، أو ستتسبب في إنهاء الحلقة، انظر sd_event_source_set_exit_on_failure(3).

لتدمير كائن مصدر الحدث استخدم sd_event_source_unref(3)، ولكن لاحظ أن مصدر الحدث لا يتم إزالته من حلقة الأحداث إلا عند إسقاط جميع المراجع إلى مصدر الحدث. للتأكد من أن مصدر الحدث لا يطلق بعد الآن، حتى عندما لا يزال هناك مرجع إليه، فكر في ضبط مصدر الحدث على SD_EVENT_OFF باستخدام sd_event_source_set_enabled(3).

يجب حظر الإشارة SIGCHLD في جميع الخيوط قبل استدعاء هذه الدالة (باستخدام sigprocmask(2) أو pthread_sigmask(3)).

إذا تم تمرير المعلمة الثانية لـ sd_event_add_child() كـ NULL، فلن يتم إرجاع أي مرجع لكائن مصدر الحدث. في هذه الحالة، يعتبر مصدر الحدث "عائمًا"، وسيتم تدميره ضمنيًا عند تدمير حلقة الأحداث نفسها.

لاحظ أن الدالة handler يتم استدعاؤها في وقت لم يتم فيه بعد حصاد العملية الفرعية (وبالتالي لا تزال مكشوفة كعملية زومبي من قبل النواة). ومع ذلك، سيتم حصاد العملية الفرعية تلقائيًا بعد عودة الدالة. لن يتم حصاد العمليات الفرعية التي لا توجد لها مصادر أحداث تغيير حالة عمليات فرعية مثبتة بواسطة تنفيذ حلقة الأحداث.

إذا كانت المعلمة handler لـ sd_event_add_child() هي NULL، وسيطلق مصدر الحدث، فسيتم اعتبار ذلك طلبًا للخروج من حلقة الأحداث. في هذه الحالة، يتم تمرير المعلمة userdata، بعد تحويلها إلى عدد صحيح، كمعلمة رمز الخروج إلى sd_event_exit(3).

إذا تم تثبيت كل من مصدر حدث تغيير حالة عملية فرعية ومصدر حدث إشارة SIGCHLD في نفس حلقة الأحداث، فإن أولويات مصدر الحدث المكونة تحدد أي مصدر حدث يتم إرساله أولاً. إذا تم معالجة معالج الإشارة أولاً، فيجب أن يترك العمليات الفرعية التي تم تثبيت مصادر أحداث عمليات فرعية لها دون حصاد.

sd_event_add_child_pidfd() مشابه لـ sd_event_add_child() ولكنه يأخذ واصف ملف يشير إلى العملية ("pidfd") بدلاً من PID الرقمي. يمكن الحصول على واصف ملف مناسب عبر pidfd_open(2) والاستدعاءات ذات الصلة. لا يتم إغلاق واصف الملف المقدم عند تحرير مصدر الحدث مرة أخرى، إلا إذا تم استخدام sd_event_source_set_child_pidfd_own() لتشغيل هذا السلوك. لاحظ أنه بغض النظر عن أي من sd_event_add_child() و sd_event_add_child_pidfd() المستخدم لتخصيص مصدر حدث، يجب أن تكون العملية التي تتم مراقبتها عملية فرعية مباشرة للعملية المستدعية. في كلتا الحالتين، يجب حظر SIGCHLD في العملية المستدعية.

sd_event_source_get_child_pid() يسترد PID المكون لمصدر حدث تغيير حالة عملية فرعية تم إنشاؤه مسبقًا باستخدام sd_event_add_child(). يأخذ كائن مصدر الحدث كمعلمة source ومؤشر إلى متغير pid_t لإرجاع معرف العملية إليه.

sd_event_source_get_child_pidfd() يسترد واصف الملف الذي يشير إلى العملية التي تتم مراقبتها ("pidfd"). تستخدم حلقة الأحداث داخليًا pidfds لمراقبة العمليات الفرعية، بغض النظر عما إذا تم تخصيص مصادر الأحداث الفردية عبر sd_event_add_child() أو sd_event_add_child_pidfd(). إذا تم استخدام الاستدعاء الأخير لتخصيص مصدر الحدث، فإن هذه الدالة تُرجع واصف الملف الأصلي المستخدم للتخصيص. يأخذ هذا الاستدعاء كائن مصدر الحدث كمعلمة source ويُرجع واصف الملف الرقمي.

يمكن استخدام sd_event_source_get_child_pidfd_own() للاستعلام عما إذا كان يجب إغلاق pidfd الذي يغلّفه مصدر الحدث عند تحرير مصدر الحدث. تُرجع هذه الدالة صفرًا إذا كان يجب ترك pidfd مفتوحًا، وإيجابًا إذا كان يجب إغلاقه تلقائيًا. بشكل افتراضي، يتم تعيين هذه الإعدادات إلى قيد التشغيل إذا تم تخصيص مصدر الحدث عبر sd_event_add_child() وإلى إيقاف التشغيل إذا تم تخصيصه عبر sd_event_add_child_pidfd(). يمكن استخدام الدالة sd_event_source_set_child_pidfd_own() لتغيير الإعداد وتأخذ معلمة منطقية بالإعداد الجديد.

يمكن استخدام sd_event_source_get_child_process_own() للاستعلام عما إذا كان يجب قتل العملية التي يراقبها مصدر الحدث (باستخدام SIGKILL) وحصدها عند تحرير مصدر الحدث. تُرجع هذه الدالة صفرًا إذا كان يجب ترك العملية قيد التشغيل، وإيجابًا إذا كان يجب قتلها وحصدها تلقائيًا. افتراضيًا، يتم تعيين هذا الإعداد إلى إيقاف التشغيل. يمكن استخدام الدالة sd_event_source_set_child_process_own() لـ

DESCRIPTION

تسمح هذه الدوال بإضافة آلية لمراقبة العمليات الفرعية (الأطفال) إلى حلقة الأحداث sd_event.

عندما تنتهي العملية الفرعية المراقبة، سيتم استدعاء دالة المعالج handler مع وسائط pid (معرف العملية الفرعية)، status (حالة خروج العملية الفرعية كما تم إرجاعها بواسطة waitpid(2)) و userdata. إذا تم تمرير NULL إلى handler، فلن يتم استدعاء أي دالة معالج. إذا تم تمرير NULL إلى source، فلن يتم إرجاع مؤشر إلى مصدر الحدث.

تستخدم sd_event_add_child() و sd_event_add_child_pidfd() آلية pidfd (مؤشر إلى العملية) لمراقبة العمليات الفرعية.

pidfd
مؤشر إلى العملية لمراقبتها. يجب الحصول عليها مسبقًا باستخدام pidfd_open(2).
pid
معرف العملية الفرعية لمراقبتها. يتم استخدامه فقط إذا لم يتم توفير pidfd (أي إذا كان pidfd هو -1).

يتم استخدام الخيار options لتحديد متى يجب استدعاء دالة المعالج:

WEXITED
استدعاء المعالج عند انتهاء العملية الفرعية.
WSTOPPED
استدعاء المعالج عند إيقاف العملية الفرعية.
WCONTINUED
استدعاء المعالج عند استئناف العملية الفرعية التي تم إيقافها.

إذا تم تمرير 0 إلى options، فسيتم استدعاء المعالج عند انتهاء العملية الفرعية أو إيقافها أو استئنافها.

يتم استخدام sd_event_source_get_child_pid() لاسترداد معرف العملية الفرعية المرتبطة بمصدر حدث فرعي.

يتم استخدام sd_event_source_get_child_pidfd() لاسترداد مؤشر العملية الفرعية المرتبط بمصدر حدث فرعي.

تحدد الدوال sd_event_source_get_child_pidfd_own() و sd_event_source_set_child_pidfd_own() ما إذا كان مصدر الحدث يمتلك مؤشر العملية الفرعية الذي تمت الإشارة إليه. إذا كان يمتلكه، فسيتم إغلاقه تلقائيًا عند تحرير مصدر الحدث.

تحدد الدوال sd_event_source_get_child_process_own() و sd_event_source_set_child_process_own() ما إذا كان مصدر الحدث يمتلك العملية الفرعية التي تتم مراقبتها. إذا كان يمتلكها، فسيتم استدعاء waitid(2) بشكل تلقائي عند انتهاء العملية الفرعية.

ملاحظة: حاليًا، إذا تم إنهاء العملية المستدعية بشكل غير طبيعي، فقد تبقى العملية المراقبة على قيد الحياة حتى لو توقف مصدر الحدث عن الوجود. قد يتغير هذا السلوك في المستقبل.

يمكن استخدام sd_event_source_send_child_signal() لإرسال إشارة UNIX إلى العملية المراقبة عبر pidfd_send_signal(2). تتطابق المعلمات المحددة مع تلك الخاصة بالاستدعاء النظامي الأساسي، باستثناء أن info لا يتم تعديلها أبدًا (وبالتالي تم الإعلان عنها كثابتة). كما هو الحال مع الاستدعاء النظامي الأساسي، يجب أن تكون المعلمة flags صفرًا حاليًا.

RETURN VALUE

عند النجاح، تُرجع هذه الدوال 0 أو عددًا صحيحًا موجبًا. عند الفشل، تُرجع رمز خطأ سالبًا بنمط errno.

Errors

قد تشير الأخطاء المُرجعة إلى المشاكل التالية:

-ENOMEM

لا توجد ذاكرة كافية لتخصيص كائن.

-EINVAL

تم تمرير وسيطة غير صالحة. يشمل ذلك تحديد قناع فارغ في options أو قناع يحتوي على قيم مختلفة عن تركيبة من WEXITED و WSTOPPED و WCONTINUED.

-EBUSY

تم تثبيت معالج بالفعل لهذه العملية الفرعية، أو أن SIGCHLD محظور.

-ESTALE

تم إنهاء حلقة الأحداث بالفعل.

-ECHILD

تم إنشاء حلقة الأحداث في عملية أو مكتبة أو وحدة مختلفة.

-EDOM

مصدر الحدث الممرر ليس مصدر حدث لعملية فرعية.

EXAMPLE

مثال 1. إنهاء الحلقة عند انتهاء العملية الفرعية

/* SPDX-License-Identifier: MIT-0 */
#define _GNU_SOURCE 1
#include <assert.h>
#include <stdio.h>
#include <unistd.h>
#include <systemd/sd-event.h>
int main(int argc, char **argv) {
  pid_t pid = fork();
  assert(pid >= 0);
  /* يجب حظر إشارة SIGCHLD لكي تعمل sd_event_add_child */
  sigset_t ss;
  sigemptyset(&ss);
  sigaddset(&ss, SIGCHLD);
  sigprocmask(SIG_BLOCK, &ss, NULL);
  if (pid == 0)  /* child */
    sleep(1);
  else {         /* parent */
    sd_event *e = NULL;
    int r;
    /* إنشاء حلقة الأحداث الافتراضية */
    sd_event_default(&e);
    assert(e);
    /* نحن ننشئ مصدر حدث فرعي عائم (مرتبط بـ 'e').
     * سيتم استدعاء المعالج الافتراضي مع 666 كبيانات مستخدم، والتي
     * ستصبح قيمة الخروج للحلقة. */
    r = sd_event_add_child(e, NULL, pid, WEXITED, NULL, (void*) 666);
    assert(r >= 0);
    r = sd_event_loop(e);
    assert(r == 666);
    sd_event_unref(e);
  }
  return 0;
}
