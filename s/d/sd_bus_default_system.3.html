sd_bus_default_system(3)

الحزمة: systemd-libs

التراخيص: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

NAME

sd_bus_default_system, sd_bus_default_user, sd_bus_default - Get default bus object for the system or user instance

SYNOPSIS

#include <systemd/sd-bus.h>

int sd_bus_default_system(sd_bus **bus);
int sd_bus_default_user(sd_bus **bus);
int sd_bus_default(sd_bus **bus);

DESCRIPTION

These functions retrieve a reference to the globally unique bus object for the system bus (sd_bus_default_system()), the user bus (sd_bus_default_user()), or the bus instance determined by the $XDG_SESSION_TYPE environment variable (sd_bus_default()). The user bus is usually the session bus, but might be the system bus if running in a user systemd service. The default bus object is suitable for basic interactions with the D-Bus system or user bus.

These functions are thread-safe and may be called multiple times. Each call increases the reference count of the bus object. The bus object is only created on the first call that requires it.

The default bus object is associated with the current thread's bus context. This means that if this function is called from a thread that has already created and potentially closed a bus connection object, it will attempt to reuse that connection. If no connection exists for the thread, a new one will be created. If the bus object is explicitly closed via `sd_bus_close()` or `sd_bus_flush()` by the caller, subsequent calls to `sd_bus_default_*()` in the same thread will create a new bus connection object.

The bus object obtained may be NULL if it is not available. This happens, for example, if the system bus is unavailable (e.g. $XDG_RUNTIME_DIR is not set) or if the user bus is unavailable (e.g. $XDG_RUNTIME_DIR is not set).

The returned bus object should be released using sd_bus_unref() when it is no longer needed. It is generally recommended to close and flush the bus connection before exiting a process or thread. See sd_bus_close().

If the returned bus object is not intended to be managed by the caller, and instead should be garbage collected when the bus object is destroyed, the caller may pass NULL in the bus parameter. In this case, the reference count is not incremented, and the caller will not be able to use the bus object.

REFERENCE OWNERSHIP

The functions return a new reference to the bus object. The caller is responsible for releasing this reference when it is no longer needed, using sd_bus_unref(). The bus object is reference-counted, and will only be destroyed when the last reference is released.

When using the default bus logic, it is a good idea to first invoke sd_bus_flush() followed by sd_bus_close() when a thread or process terminates, and thus its bus connection object should be freed.

Normally, slot objects (as created by sd_bus_add_match() and similar calls) keep a reference to their bus connection object, too. Thus, as long as a bus slot object remains referenced its bus object will remain allocated too. Optionally, bus slot objects may be placed in "floating" mode. When in floating mode the life cycle of the bus slot object is bound to the bus object, i.e. when the bus object is freed the bus slot object is automatically unreferenced too. The floating state of a slot object may be controlled explicitly with sd_bus_slot_set_floating(), though usually floating bus slot objects are created by passing NULL as the slot parameter of sd_bus_add_match() and related calls, thus indicating that the caller is not directly interested in referencing and managing the bus slot object.

The life cycle of the default bus connection should be the responsibility of the code that creates/owns the thread the default bus connection object is associated with. Library code should neither call sd_bus_flush() nor sd_bus_close() on default bus objects unless it does so in its own private, self-allocated thread. Library code should not use the default bus object in other threads unless it is clear that the program using it will life cycle the bus connection object and flush and close it before exiting from the thread. In libraries where it is not clear that the calling program will life cycle the bus connection object, it is hence recommended to use sd_bus_open_system() instead of sd_bus_default_system() and related calls.

RETURN VALUE

On success, these calls return 0 or a positive integer. On failure, these calls return a negative errno-style error code.

Errors

Returned errors may indicate the following problems:

-EINVAL

The specified parameters are invalid.

-ENOMEDIUM

The requested bus type is not available because of invalid environment (for example the user session bus is not available because $XDG_RUNTIME_DIR is not set).

-ENOMEM

Memory allocation failed.

-ESOCKTNOSUPPORT

The protocol version required to connect to the selected bus is not supported.

In addition, other connection-related errors may be returned. See sd_bus_send().

NOTES

Functions described here are available as a shared library, which can be compiled against and linked to with the libsystemd pkg-config(1) file.

The code described here uses getenv(3), which is declared to be not multi-thread-safe. This means that the code calling the functions described here must not call setenv(3) from a parallel thread. It is recommended to only do calls to setenv() from an early phase of the program when no other threads have been started.
