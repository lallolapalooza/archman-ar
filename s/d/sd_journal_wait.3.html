الوصف

sd_journal_get_fd() تُرجع واصف ملف يمكن الاستقصاء بشكل غير متزامن في حلقة أحداث خارجية ويتم إعلامه بمجرد تغير السجل، لأن إدخالات أو ملفات جديدة تم إضافتها، أو حدث تدوير (rotation)، أو تم حذف ملفات، وما شابه ذلك. واصف الملف مناسب للاستخدام في poll(2). استخدم sd_journal_get_events() لقناع الأحداث الذي يجب مراقبته. يأخذ الاستدعاء وسيطًا واحدًا: كائن السجل. لاحظ أن ليست كل أنظمة الملفات قادرة على توليد الأحداث اللازمة للإيقاظ من واصف الملف هذا للتغييرات ليتم ملاحظتها فورًا. على وجه الخصوص، لا تولد أنظمة الملفات الشبكية أحداث تغيير ملف مناسبة في جميع الحالات. يمكن اكتشاف حالات مثل هذه باستخدام sd_journal_reliable_fd()، أدناه. سيضمن sd_journal_get_timeout() في هذه الحالات أن تكون الإيقاظات متكررة بما يكفي ليتم ملاحظة التغييرات، على الرغم من وجود تأخير معين.

sd_journal_get_events() ستُرجع قناع poll() للانتظار. ستُرجع هذه الدالة مزيجًا من POLLIN و POLLOUT وما شابه لملء حقل ".events" في struct pollfd.

sd_journal_get_timeout() ستُرجع قيمة مهلة لاستخدامها في poll(). تُرجع هذه القيمة بالميكروثانية منذ بداية عصر CLOCK_MONOTONIC لإنهاء poll() في timeout_usec. راجع clock_gettime(2) للحصول على تفاصيل حول CLOCK_MONOTONIC. إذا لم يكن هناك مهلة للانتظار، فسيتم ملء (uint64_t) -1 بدلاً من ذلك. لاحظ أن poll() تأخذ مهلة نسبية بالميلي ثانية بدلاً من مهلة مطلقة بالميكروثانية. لتحويل المهلة المطلقة 'us' إلى 'ms' نسبية، استخدم شيفرة مثل التالية:

uint64_t t;
int msec;
sd_journal_get_timeout(m, &t);
if (t == (uint64_t) -1)
  msec = -1;
else {
  struct timespec ts;
  uint64_t n;
  clock_gettime(CLOCK_MONOTONIC, &ts);
  n = (uint64_t) ts.tv_sec * 1000000 + ts.tv_nsec / 1000;
  msec = t > n ? (int) ((t - n + 999) / 1000) : 0;
}

الشيفرة أعلاه لا تقوم بأي فحص للأخطاء للاختصار. يمكن تمرير المتغير msec المحسوب مباشرة كمعلمة مهلة لـ poll().

بعد كل استيقاظ من poll()، يجب استدعاء sd_journal_process() لمعالجة الأحداث. سيشير هذا الاستدعاء أيضًا إلى نوع التغيير الذي تم اكتشافه (انظر أدناه؛ لاحظ أن الإيقاظات العرضية ممكنة).

بديل متزامن لاستخدام sd_journal_get_fd() و sd_journal_get_events() و sd_journal_get_timeout() و sd_journal_process() هو sd_journal_wait(). سينتظر بشكل متزامن حتى يتغير السجل. يمكن التحكم في الحد الأقصى للوقت الذي تنام فيه هذه المكالمة باستخدام المعلمة timeout_usec. قم بتمرير (uint64_t) -1 للانتظار إلى أجل غير مسمى. داخليًا، تجمع هذه المكالمة ببساطة sd_journal_get_fd() و sd_journal_get_events() و sd_journal_get_timeout() و poll() و sd_journal_process() في مكالمة واحدة.

يمكن استخدام sd_journal_reliable_fd() للتحقق مما إذا كانت أحداث الإيقاظ من واصف الملف الذي تم إرجاعه بواسطة sd_journal_get_fd() معروفة بأنها تُشغّل بسرعة. في أنظمة ملفات معينة حيث لا تتوفر أحداث تغيير الملف من نظام التشغيل (مثل NFS) (مثل NFS)، يجب استقصاء التغييرات بشكل متكرر، وبالتالي يتم اكتشافها فقط مع تأخير كبير. ستُرجع هذه المكالمة قيمة موجبة إذا تم اكتشاف تغييرات السجل بسرعة وصفر عندما تحتاج إلى استقصائها. لاحظ أنه لا توجد عادةً حاجة لاستدعاء هذه الدالة مباشرة حيث سيطلب sd_journal_get_timeout() مهلات مناسبة على أي حال.

لاحظ أن جميع واجهات إشعار التغيير المذكورة أعلاه لا تُبلغ عن التغييرات على الفور. يتم إدخال التأخيرات لأسباب متعددة: كما ذُكر، تتطلب بعض الواجهات الخلفية للتخزين استقصاءً زمنيًا، وفي حالات أخرى، يتم تحسين الإيقاظات عن طريق تجميع الأحداث، ويُدخل نظام التشغيل تأخيرات إضافية في جدولة الإدخال/الإخراج/وحدة المعالجة المركزية.

قيمة الإرجاع

sd_journal_get_fd() تُرجع واصف ملف صالح عند النجاح أو رمز خطأ سلبي بأسلوب errno.

sd_journal_get_events() تُرجع مزيجًا من POLLIN و POLLOUT وما شابه عند النجاح أو رمز خطأ سلبي بأسلوب errno.

sd_journal_reliable_fd() تُرجع عددًا صحيحًا موجبًا إذا كان واصف الملف الذي تم إرجاعه بواسطة sd_journal_get_fd() سيُنتج إيقاظات فورية لجميع تغييرات السجل. تُرجع 0 إذا كان قد يكون هناك تأخير متضمن.

sd_journal_process() و sd_journal_wait() تُرجعان رمز خطأ سلبي بأسلوب errno، أو واحدًا من SD_JOURNAL_NOP أو SD_JOURNAL_APPEND أو SD_JOURNAL_INVALIDATE عند النجاح:

•إذا تم إرجاع SD_JOURNAL_NOP، لم يتغير السجل منذ الاستدعاء الأخير.
•إذا تم إرجاع SD_JOURNAL_APPEND، فقد تم إلحاق إدخالات جديدة بنهاية السجل. في هذه الحالة، يكفي ببساطة الاستمرار في القراءة عند موقع النهاية السابق للسجل، لقراءة الإدخالات المضافة حديثًا.
•إذا تم إرجاع SD_JOURNAL_INVALIDATE، فقد تم إضافة أو إزالة ملفات السجل من مجموعة ملفات السجل التي تتم مراقبتها (على سبيل المثال، بسبب التدوير أو التنظيف)، وبالتالي قد تكون الإدخالات قد ظهرت أو اختفت في أماكن عشوائية في تدفق السجل، ربما قبل أو بعد نهاية تدفق السجل السابقة. إذا تم إرجاع SD_JOURNAL_INVALIDATE، فيجب على واجهات المستخدم ذات العرض المباشر التي ترغب في عكس حالة بيانات السجل على القرص بدقة على الشاشة، إعادة تحديث شاشتها بالكامل (بالنسبة لمؤشر إدخال السجل في أعلى الشاشة). قد تعامل البرامج المهتمة فقط بتدفق بيانات السجل المتسلسل بشكل صارم SD_JOURNAL_INVALIDATE بنفس طريقة SD_JOURNAL_APPEND، وبالتالي تتجاهل أي تغييرات في عرض السجل قبل نهاية السجل القديمة.

أمان الإشارة (SIGNAL SAFETY)

بشكل عام، sd_journal_get_fd() و sd_journal_get_events() و sd_journal_get_timeout() *ليست* "آمنة للإشارات غير المتزامنة" بالمعنى المقصود في signal-safety(7). ومع ذلك، فإن الاستدعاء الأول لأي من هذه الدوال الثلاث فقط يقوم بعمليات غير آمنة، وبالتالي فإن الاستدعاءات اللاحقة *آمنة*.

sd_journal_process() و sd_journal_wait() غير آمنتين. sd_journal_reliable_fd() آمنة.

أمثلة

التكرار عبر السجل، في عرض مباشر يتتبع جميع التغييرات:

/* SPDX-License-Identifier: MIT-0 */
#include <errno.h>
#include <stdio.h>
#include <systemd/sd-journal.h>
int main(int argc, char *argv[]) {
  int r;
  sd_journal *j;
  r = sd_journal_open(&j, SD_JOURNAL_LOCAL_ONLY);
  if (r < 0) {
    fprintf(stderr, "Failed to open journal: %s\n", strerror(-r));
    return 1;
  }
  for (;;)  {
    const void *d;
    size_t l;
    r = sd_journal_next(j);
    if (r < 0) {
      fprintf(stderr, "Failed to iterate to next
entry: %s\n", strerror(-r)); break; } if (r == 0) { /* وصلنا إلى النهاية، لننتظر التغييرات، ونحاول مرة أخرى */ r = sd_journal_wait(j, (uint64_t) -1); if (r < 0) { fprintf(stderr, "فشل الانتظار للتغييرات: %s\n", strerror(-r)); break; } continue; } r = sd_journal_get_data(j, "MESSAGE", &d, &l); if (r < 0) { fprintf(stderr, "فشل قراءة حقل الرسالة: %s\n", strerror(-r)); continue; } printf("%.*s\n", (int) l, (const char*) d); } sd_journal_close(j); return 0; }

الانتظار باستخدام poll() (هذا المثال يفتقر إلى جميع فحوصات الأخطاء من أجل البساطة):

/* SPDX-License-Identifier: MIT-0 */
#define _GNU_SOURCE 1
#include <poll.h>
#include <time.h>
#include <systemd/sd-journal.h>
int wait_for_changes(sd_journal *j) {
  uint64_t t;
  int msec;
  struct pollfd pollfd;
  sd_journal_get_timeout(j, &t);
  if (t == (uint64_t) -1)
    msec = -1;
  else {
    struct timespec ts;
    uint64_t n;
    clock_gettime(CLOCK_MONOTONIC, &ts);
    n = (uint64_t) ts.tv_sec * 1000000 + ts.tv_nsec / 1000;
    msec = t > n ? (int) ((t - n + 999) / 1000) : 0;
  }
  pollfd.fd = sd_journal_get_fd(j);
  pollfd.events = sd_journal_get_events(j);
  poll(&pollfd, 1, msec);
  return sd_journal_process(j);
}
