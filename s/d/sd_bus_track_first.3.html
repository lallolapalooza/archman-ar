sd_bus_track_first(3)

الحزمة: systemd-libs

التراخيص: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

الوصف

sd_bus_track_first() و sd_bus_track_next() تُستخدم للتكرار فوق مجموعة اتصالات الناقل المنظمة في آلية التتبع، كما تم إنشاؤها بواسطة sd_bus_track_new(3). يقوم sd_bus_track_first() بإرجاع مؤشر إلى أول عنصر في مجموعة التتبع. إذا كانت المجموعة فارغة، فسيتم إرجاع NULL. يقوم sd_bus_track_next() بإرجاع مؤشر إلى العنصر التالي في مجموعة التتبع، أو NULL إذا لم يعد هناك المزيد من العناصر.

عادةً ما يتم استخدام هاتين الدالتين معًا في حلقة:

    sd_bus_track *track;
    sd_bus *bus;
    sd_bus_error error = SD_BUS_ERROR_NULL;
    sd_bus_slot *slot;
    int r;

    r = sd_bus_track_new(bus, &track, &error);
    if (r < 0) {
        fprintf(stderr, "Failed to create track: %s\n", error.message);
        goto finish;
    }

    sd_bus_track_add_name(track, "org.freedesktop.systemd1");

    /* ... */

    for (sd_bus_slot *s = sd_bus_track_first(track); s; s = sd_bus_track_next(track)) {
        printf("Found slot: %p\n", s);
    }

finish:
    sd_bus_track_unref(track);

هذه الوظائف لا تقم بإنشاء أي اتصالات ناقل بحد ذاتها. إنها مجرد واجهة لتعداد مجموعات الاتصالات الموجودة التي تم تتبعها بالفعل.

sd_bus_track_first() و sd_bus_track_next() ليستا آمنتين للاستخدام المتوازي في مؤشرات ترابط مختلفة. يجب أن تتم جميع عمليات الوصول إلى مجموعة تتبع معينة من نفس مؤشر الترابط. إذا كانت هناك حاجة إلى تتبع الوصول المتوازي، فيجب استخدام آلية قفل خارجية.

يجب استدعاء sd_bus_track_first() في بداية مرحلة البرنامج عندما لم يتم بدء أي مؤشرات ترابط أخرى.
