DESCRIPTION

The functions described here are related to the sd-device library, which allows applications to query and monitor devices managed by systemd.

A pointer to an sd_device object is obtained, for example, through sd_device_get_dev_by_path(3), sd_device_get_dev_by_id(3), or sd_device_enumerator_next(3).

The functions sd_device_get_driver_subsystem, sd_device_get_device_id, sd_device_get_subsystem, sd_device_get_sysname, sd_device_get_sysnum, and sd_device_get_syspath retrieve various attributes of the device.

The functions sd_device_is_block, sd_device_is_partition, sd_device_is_socket, and sd_device_is_stateful return true if the device is of the specified type.

The functions sd_device_path_is_block, sd_device_path_is_directory, sd_device_path_is_file, sd_device_path_is_link, and sd_device_path_is_socket check if a given path refers to a device of the specified type.

sd_device_ref and sd_device_unref increase and decrease the reference count of an sd_device object, respectively. sd_device_unref_and_set_ptr decreases the reference count and sets the pointer to NULL.

sd_device_is_initialized returns true if the device has been initialized by systemd.

sd_device_is_native_path returns true if the device's path is the canonical path.

sd_device_watch_add adds a watch to the device. The callback function will be called when the device's state changes. The userdata parameter can be used to pass arbitrary data to the callback. The userdata_free parameter is a function that will be called to free the userdata when the watch is removed.

sd_device_watch_remove removes a watch previously added with sd_device_watch_add.

RETURN VALUE

On success, these functions return a non-negative integer. On failure, they return a negative error number.

The functions returning a boolean value return 1 for true and 0 for false.

On success, the pointer arguments are set to the requested value. On failure, they are left unchanged.

sd_device_watch_add returns a pointer to the new watch source on success, or NULL on failure.

NOTES

All functions listed here are thread-safe.

The returned strings are owned by the sd_device object and must not be freed. They are valid as long as the sd_device object is valid.

HISTORY

sd_device_get_driver_subsystem() and sd_device_get_device_id() were added in version 257.
