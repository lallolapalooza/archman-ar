الوصف

sd_event_add_time() تضيف مصدر حدث مؤقت جديد إلى حلقة أحداث. يتم تحديد كائن حلقة الأحداث في المعلمة event، ويتم إرجاع كائن مصدر الحدث في المعلمة source. تأخذ المعلمة clock معرف ساعة، أحد CLOCK_REALTIME أو CLOCK_MONOTONIC أو CLOCK_BOOTTIME أو CLOCK_REALTIME_ALARM أو CLOCK_BOOTTIME_ALARM. راجع timerfd_create(2) للحصول على تفاصيل حول أنواع الساعات المختلفة. تحدد المعلمة usec أبكر وقت، بالميكروثانية (μs)، نسبة إلى بداية الساعة، عندما يجب تشغيل المؤقت. إذا تم تحديد وقت بالفعل في الماضي (بما في ذلك 0)، فإن مصدر المؤقت هذا "يُطلق" فورًا ويكون جاهزًا للتوزيع. إذا تم تحديد المعلمة كـ UINT64_MAX فلن ينقضي حدث المؤقت أبدًا، والذي يمكن استخدامه كبديل لتعطيل مصدر حدث مؤقت صراحةً باستخدام sd_event_source_set_enabled(3). تحدد المعلمة accuracy قيمة دقة إضافية بالميكروثانية (μs) تحدد مقدار التأخير الذي قد يحدث لحدث المؤقت. استخدم 0 للاختيار الافتراضي للدقة (250 مللي ثانية). استخدم 1 ميكروثانية لأقصى دقة. ضع في اعتبارك تحديد 60000000 ميكروثانية (دقيقة واحدة) أو أكبر للأحداث طويلة التشغيل التي قد تتأخر بشكل كبير. يسمح اختيار قيم دقة أعلى للنظام بدمج أحداث المؤقت بشكل أكثر عدوانية، مما يحسن كفاءة الطاقة.

handler هي دالة سيتم استدعاؤها عند انتهاء صلاحية المؤقت أو NULL. سيتم تمرير المؤشر userdata إلى الدالة المعالجة، ويمكن اختياره بحرية من قبل المتصل. يتم أيضًا تمرير وقت التشغيل المحدد إلى المعالج، حتى لو حدث الاستدعاء فعليًا بعد ذلك بقليل، اعتمادًا على قيمة الدقة المحددة، ووقت استجابة مؤقت النواة (راجع prctl(2))، وزمن الوصول الإضافي للجدولة. للاستعلام عن الوقت الفعلي الذي تم فيه استدعاء المعالج استخدم sd_event_now(3). قد تعيد الدالة المعالجة قيمة سالبة للإشارة إلى خطأ (انظر أدناه)، وسيتم تجاهل القيم المرجعة الأخرى. إذا كان handler هو NULL، فسيتم استخدام معالج افتراضي يستدعي sd_event_exit(3).

افتراضيًا، سينقضي المؤقت مرة واحدة (SD_EVENT_ONESHOT)، ولكن يمكن تغيير ذلك باستخدام sd_event_source_set_enabled(3). إذا أعادت الدالة المعالجة رمز خطأ سالبًا، فسيتم تعطيلها بعد الاستدعاء، حتى لو تم طلب وضع SD_EVENT_ON من قبل، أو ستتسبب في إنهاء الحلقة، انظر sd_event_source_set_exit_on_failure(3). لاحظ أن مؤقت حدث تم تعيينه إلى SD_EVENT_ON سيتم تشغيله باستمرار ما لم يتم تحديث وقته المحدد باستخدام sd_event_source_set_time().

sd_event_add_time_relative() تشبه sd_event_add_time()، ولكنها تأخذ مواصفات زمنية نسبية. إنها نسبية للوقت الحالي لتكرار حلقة الأحداث، كما تم إرجاعه بواسطة sd_event_now(3).

لتدمير كائن مصدر الحدث استخدم sd_event_source_unref(3)، ولكن لاحظ أن مصدر الحدث يتم إزالته من حلقة الأحداث فقط عندما يتم إسقاط جميع المراجع إلى مصدر الحدث. للتأكد من أن مصدر الحدث لا يتم تشغيله بعد الآن، حتى لو كان لا يزال مرجعًا إليه، قم بتعطيل مصدر الحدث باستخدام sd_event_source_set_enabled(3) مع SD_EVENT_OFF.

إذا كانت المعلمة الثانية لـ sd_event_add_time() هي NULL فلا يتم إرجاع مرجع لكائن مصدر الحدث. في هذه الحالة، يعتبر مصدر الحدث "عائمًا"، وسيتم تدميره ضمنيًا عند تدمير حلقة الأحداث نفسها.

إذا كانت المعلمة handler لـ sd_event_add_time() هي NULL، وسيتم تشغيل مصدر الحدث، فسيتم اعتبار ذلك طلبًا للخروج من حلقة الأحداث. في هذه الحالة، يتم تمرير المعلمة userdata، بعد تحويلها إلى عدد صحيح، كمعلمة رمز الخروج إلى sd_event_exit(3).

استخدم CLOCK_BOOTTIME_ALARM و CLOCK_REALTIME_ALARM لتعريف مصادر الأحداث التي قد توقظ النظام من وضع الإسبات.

لإعداد مؤقتات نسبية (أي، نسبة إلى الوقت الحالي)، استرجع الوقت الحالي عبر sd_event_now(3)، أضف المدة الزمنية المطلوبة إليه، واستخدم النتيجة كمعلمة usec لـ sd_event_add_time().

لإعداد مؤقتات متكررة (أي، مؤقتات يتم تشغيلها بفواصل زمنية منتظمة)، قم بإعداد المؤقت بشكل طبيعي، للاستدعاء الأول. في كل مرة يتم فيها استدعاء معالج الحدث، قم بتحديث وقت تشغيل المؤقت باستخدام sd_event_source_set_time(3) للتكرار التالي للمؤقت، وأعد تمكين المؤقت باستخدام sd_event_source_set_enabled(). لحساب النقطة الزمنية التالية لتمريرها إلى sd_event_source_set_time()، استخدم إما الوقت usec الذي تم تمريره إلى رد الاتصال بالمؤقت، أو الطابع الزمني الذي تم إرجاعه بواسطة sd_event_now(). في الحالة الأولى ستكون أحداث المؤقت منتظمة، بينما في الحالة الأخيرة، سيستمر زمن الوصول للجدولة في التراكم على المؤقت.

sd_event_source_get_time() تسترجع قيمة الوقت المحددة لمصدر حدث تم إنشاؤه مسبقًا باستخدام sd_event_add_time() أو sd_event_add_time_relative(). تأخذ كائن مصدر الحدث ومؤشرًا إلى متغير لتخزين الوقت فيه، نسبة إلى بداية الساعة المختارة، بالميكروثانية. القيمة المرجعة نسبية إلى بداية العصر، حتى لو تم إنشاء مصدر الحدث بوقت نسبي عبر sd_event_add_time_relative().

sd_event_source_set_time() تغير وقت مصدر حدث تم إنشاؤه مسبقًا باستخدام sd_event_add_time() أو sd_event_add_time_relative(). تأخذ كائن مصدر الحدث ووقتًا نسبيًا إلى بداية الساعة المختارة، بالميكروثانية.

sd_event_source_set_time_relative() مشابه لـ sd_event_source_set_time()، ولكنه يأخذ وقتًا نسبيًا للوقت الحالي لتكرار حلقة الأحداث، كما تم إرجاعه بواسطة sd_event_now().

sd_event_source_get_time_accuracy() تسترجع قيمة الدقة المحددة لمصدر حدث تم إنشاؤه مسبقًا باستخدام sd_event_add_time(). تأخذ كائن مصدر الحدث ومؤشرًا إلى متغير لتخزين الدقة فيه. يتم تحديد الدقة بالميكروثانية.

sd_event_source_set_time_accuracy() تغير الدقة المحددة لمصدر حدث مؤقت

sd_event_add_time(3)

systemd 258.2

NAME

sd_event_add_time, sd_event_source_get_time, sd_event_source_set_time, sd_event_source_get_time_accuracy, sd_event_source_set_time_accuracy, sd_event_source_get_time_clock, sd_event_add_time_relative, sd_event_source_set_time_relative - Schedule an event in the future

SYNOPSIS

#include <systemd/sd-event.h>

int sd_event_add_time(sd_event *event, sd_event_source **source, clockid_t clock_id,
                      struct timespec *ts, struct timespec *delta, sd_event_time_handler_t *callback,
                      void *userdata);

int sd_event_source_get_time(sd_event_source *source, struct timespec *ts);

int sd_event_source_set_time(sd_event_source *source, struct timespec *ts);

int sd_event_source_get_time_accuracy(sd_event_source *source, struct timespec *delta);

int sd_event_source_set_time_accuracy(sd_event_source *source, struct timespec *delta);

int sd_event_source_get_time_clock(sd_event_source *source, clockid_t *clock_id);

int sd_event_add_time_relative(sd_event *event, sd_event_source **source, clockid_t clock_id,
                              struct timespec *delta, sd_event_time_handler_t *callback,
                              void *userdata);

int sd_event_source_set_time_relative(sd_event_source *source, struct timespec *delta);

DESCRIPTION

sd_event_add_time() may be used to register a timer event with the event loop. The timer event will be triggered and callback invoked when the specified time ts is reached on the specified clock clock_id. The delta parameter may be used to specify a relative time offset from the current time, instead of an absolute time ts. If delta is specified, ts must be NULL. The timer event is added to the event loop passed as event.

sd_event_source_get_time() retrieves the absolute time point ts the event source is scheduled for. This may fail if the event source was not created with sd_event_add_time() or sd_event_add_time_relative().

sd_event_source_set_time() may be used to change the scheduled time point of an existing timer event source to ts.

sd_event_source_get_time_accuracy() retrieves the configured accuracy delta of an event source created previously with sd_event_add_time(). It takes the event source object and a pointer to a variable to store the accuracy in.

sd_event_source_set_time_accuracy() sets the accuracy delta of an event source created previously with sd_event_add_time(). It takes the event source object and accuracy, in μs.

sd_event_source_get_time_clock() retrieves the configured clock of an event source created previously with sd_event_add_time(). It takes the event source object and a pointer to a variable to store the clock identifier in.

sd_event_add_time_relative() and sd_event_source_set_time_relative() are convenience functions that work like sd_event_add_time() and sd_event_source_set_time() respectively, but take a relative time offset delta instead of an absolute time ts. They are equivalent to calling the corresponding sd_event_add_time() or sd_event_source_set_time() function with ts set to the current time plus delta.

RETURN VALUE

On success, these functions return 0 or a positive integer. On failure, they return a negative errno-style error code.

Errors

Returned values may indicate the following problems:

-ENOMEM

Not enough memory to allocate an object.

-EINVAL

An invalid argument has been passed.

-ESTALE

The event loop is already terminated.

-ECHILD

The event loop has been created in a different process, library or module instance.

-EOPNOTSUPP

The selected clock is not supported by the event loop implementation.

-EDOM

The passed event source is not a timer event source.

-EOVERFLOW

The passed relative time is outside of the allowed range for time values (i.e. the specified value added to the current time is outside the 64 bit unsigned integer range.

Added in version 247.

NOTES

Functions described here are available as a shared library, which can be compiled against and linked to with the libsystemd pkg-config(1) file.

The code described here uses getenv(3), which is declared to be not multi-thread-safe. This means that the code calling the functions described here must not call setenv(3) from a parallel thread. It is recommended to only do calls to setenv() from an early phase of the program when no other threads have been started.
