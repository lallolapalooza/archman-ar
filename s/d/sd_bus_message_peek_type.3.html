SD_BUS_MESSAGE_READ(3) sd_bus_message_read SD_BUS_MESSAGE_READ(3)

الاسم

sd_bus_message_read, sd_bus_message_readv, sd_bus_message_peek_type - قراءة تسلسل من القيم من رسالة

الملخص

#include <systemd/sd-bus.h>

int sd_bus_message_read(sd_bus_message *m, const char *types, ...);

int sd_bus_message_readv(sd_bus_message *m, const char *types, va_list ap);

int sd_bus_message_peek_type(sd_bus_message *m, char *type, const char **contents);

الوصف

sd_bus_message_read() تقرأ تسلسلًا من الحقول من كائن الرسالة D-Bus m وتتقدم بموضع القراءة في الرسالة. سلسلة الأنواع types تصف أنواع العناصر المتوقعة في الرسالة وحجج الحقول التي تليها. يمكن أن تكون سلسلة الأنواع NULL أو فارغة، وفي هذه الحالة لا يتم قراءة أي شيء.

تتكون سلسلة الأنواع من العناصر الموصوفة في sd_bus_message_append(3)، أي الأنواع الأساسية والأنواع الحاوية. يجب أن تحتوي على صفر أو أكثر من "الأنواع الكاملة" المفردة. تنتهي سلسلة الأنواع بـ NUL.

لكل نوع محدد في سلسلة الأنواع، يجب تحديد حجة واحدة أو أكثر بعد المعلمة types، بنفس الترتيب. يجب أن تكون الحجج مؤشرات إلى أنواع مناسبة (مؤشر إلى int8_t مقابل "y" في سلسلة الأنواع، مؤشر إلى int32_t مقابل "i"، مؤشر إلى const char* مقابل "s"، ...) والتي يتم تعيينها بناءً على القيم الموجودة في الرسالة. كاستثناء، في حالة أنواع المصفوفات والمتغيرات، فإن الحجة الأولى هي حجة "إدخال" تحدد بشكل أكبر كيفية قراءة الرسالة. انظر الجدول أدناه للحصول على قائمة كاملة بالحجج المسموح بها وأنواعها. لاحظ أنه إذا كان النوع الأساسي مؤشرًا (مثل const char * في حالة السلسلة)، فإن الحجة هي مؤشر إلى مؤشر، وكذلك المؤشر الذي يتم كتابته هو مؤشر مستعار فقط ويجب نسخ المحتويات إذا كانت ستستخدم بعد نهاية عمر الرسالة. إذا كان النوع هو "h" (واصف ملف يونكس)، فإن الواصف لا يتم تكراره بواسطة هذا الاستدعاء ويظل الواصف المُرجع في حيازة كائن الرسالة، ويجب تكراره بواسطة المتصل للحفاظ على مرجع مفتوح له بعد تحرير كائن الرسالة.

يمكن أن تكون كل حجة أيضًا NULL، وفي هذه الحالة يتم قراءة القيمة وتجاهلها.

sd_bus_message_readv() تعادل sd_bus_message_read()، باستثناء أنها تستدعى باستخدام "va_list" بدلاً من عدد متغير من الحجج. هذه الوظيفة لا تستدعي الماكرو va_end(). نظرًا لأنها تستدعي الماكرو va_arg()، فإن قيمة ap غير معرفة بعد الاستدعاء.

sd_bus_message_peek_type() تحدد نوع العنصر التالي في m الذي سيتم قراءته بواسطة sd_bus_message_read() أو وظائف مماثلة. عند النجاح، يتم تخزين النوع في type، إذا لم يكن NULL. إذا كان النوع نوعًا حاويًا، يتم تخزين نوع عناصره في contents، إذا لم يكن NULL. إذا نجحت هذه الوظيفة في تحديد نوع العنصر التالي في m، فإنها ترجع عددًا صحيحًا موجبًا. إذا لم تعد هناك عناصر للقراءة، فإنها ترجع صفرًا.

قيمة الإرجاع

عند النجاح، ترجع هذه الوظائف عددًا صحيحًا غير سالب. عند الفشل، ترجع رمز خطأ سالبًا بأسلوب errno.

الأخطاء

قد تشير الأخطاء المرجعة إلى المشاكل التالية:

-EINVAL

سلسلة الأنواع المحددة غير صالحة أو أن معلمة الرسالة NULL.

-ENXIO

لا تحتوي الرسالة على النوع المحدد في الموضع الحالي.

-EBADMSG

لا يمكن تحليل الرسالة.

-EBUSY

عند القراءة من حاوية، سيتم إرجاع هذا الخطأ إذا بقيت عناصر غير مقروءة في الحاوية.

sd_bus_message_peek_type(3) — systemd — Arch Linux

NAME

sd_bus_message_peek_type, sd_bus_message_read, sd_bus_message_readv, sd_bus_message_read_basic - Read data from a D-Bus message

SYNOPSIS

#include <systemd/sd-bus.h>
int sd_bus_message_peek_type(sd_bus_message *m, char *type, uint8_t *signature_len);
int sd_bus_message_read(sd_bus_message *m, const char *fmt, ...);
int sd_bus_message_readv(sd_bus_message *m, const char *fmt, va_list ap);
int sd_bus_message_read_basic(sd_bus_message *m, char type, void *p);

DESCRIPTION

The sd_bus_message_read() function may be used to read data from the message m according to the format string fmt. The format string consists of characters representing D-Bus types, similar to printf(3) format specifiers, but mapping to D-Bus types instead.

The list of supported format characters is:

  • 'a': Array. Takes an additional argument which is the length of the array (in number of elements).
  • 'g': 64-bit signed integer. Equivalent to int64_t. This is the most generic integer type.
  • 'b': Boolean. Typically corresponds to a 32-bit integer in D-Bus. The argument should be a pointer to an integer type (like int or int32_t). Do not use C99 bool, as it might be smaller than 32 bits and cause memory corruption.
  • 'd': Double-precision floating point number.
  • 'h': File descriptor. The argument should be a pointer to an int. The file descriptor is passed by value and automatically closed when the message is destroyed unless it has been cloned using fcntl(fd, FD_DUPFD_CLOEXEC, ...) or similar.
  • 'i': 32-bit signed integer. Equivalent to int32_t.
  • 'n': 16-bit signed integer. Equivalent to int16_t.
  • 'q': 16-bit unsigned integer. Equivalent to uint16_t.
  • 's': String. The argument should be a pointer to a const char *. The string is owned by the message and must not be used after the message is destroyed.
  • 't': 64-bit unsigned integer. Equivalent to uint64_t.
  • 'u': 32-bit unsigned integer. Equivalent to uint32_t.
  • 'x': 64-bit signed integer. Equivalent to int64_t. Same as 'g'.
  • 'y': 8-bit unsigned integer. Equivalent to uint8_t.
  • 'c': 8-bit signed integer. Equivalent to int8_t.
  • 'o': D-Bus object path. Equivalent to a string.
  • 'u': D-Bus signature. Equivalent to a string.
  • '{key-type}value-type': Dictionary entry. The key and value types are specified by nested type strings. For example, a{is} describes an array of dictionaries with 32-bit signed integer keys and strings as values.
  • '(type-list)': Structure. The nested type string specifies the types of the fields in the structure. For example, (so) describes a structure containing a string and an object path.
  • 'v': Variant. The first argument to sd_bus_message_read() should be a pointer to a string for the signature, and the second argument should be a pointer to the value. The value will be read according to the provided signature.

Containers like arrays, dictionaries, structures, and variants may be nested. When reading a container, the argument for the container type itself should be a pointer to the appropriate type (e.g., int* for arrays, const char* for strings).

For arrays and dictionaries, an additional argument must be provided specifying the number of elements in the container. This is used to correctly parse the container's contents.

The sd_bus_message_readv() function is equivalent to sd_bus_message_read(), but takes the list of arguments in a va_list.

The sd_bus_message_read_basic() function reads a single value of the basic D-Bus type specified by type. The value is written into the memory location pointed to by p. This is a lower-level function and is generally only useful when parsing manually or when the type is only known at runtime.

The sd_bus_message_peek_type() function peeks at the type of the next field in the message buffer without consuming it. If the field is a container type (array, dictionary, structure, or variant), its full signature string will be returned in type. If it's a basic type, the single character representing that type is returned. If the field is a variant, the length of its signature string is returned in signature_len. This is useful for dynamically dispatching based on message contents.

The current position in the message is advanced after each successful read. If the message is malformed or the types do not match, an error is returned.

RETURN VALUE

On success, these functions return a non-negative value. On failure, they return a negative error number.

NOTES

The format string characters correspond to the D-Bus type system. See the D-Bus specification for a complete description of the type system.

When reading file descriptors with 'h', be aware that the file descriptor is owned by the message. If you need to keep the file descriptor after the message is destroyed, you must duplicate it using fcntl() or a similar mechanism.

For variants (`'v'`), the signature string is also read from the message and must be provided as the first argument to sd_bus_message_read(). The actual value is then read according to this signature. Note that the type character for the variant itself is 'v', but the type of the value inside the variant is specified by the signature string.

For arrays and dictionaries, the count of elements must be provided as an additional argument to sd_bus_message_read(). This count is also part of the D-Bus message encoding and must match the actual number of elements.

The sd_bus_message_read_basic() function is useful for reading single, non-container types when the type is determined at runtime. It does not advance the message cursor automatically and should be used with care.

EXAMPLES

Read a single basic type (a 64-bit integer):

sd_bus_message *m;
int64_t x;
sd_bus_message_read(m, "x", &x);

Read a boolean value:

sd_bus_message *m;
int x; /* Do not use C99 "bool" type here, it is typically smaller
          in memory and would cause memory corruption */
sd_bus_message_read(m, "b", &x);

Read all types of integers:

uint8_t y;
int16_t n;
uint16_t q;
int32_t i;
uint32_t u;
int64_t x;
uint64_t t;
double d;
sd_bus_message_read(m, "ynqiuxtd", &y, &n, &q, &i, &u, &x, &t, &d);

Read a structure composed of a string and a D-Bus path:

const char *s, *p;
sd_bus_message_read(m, "(so)", &s, &p);

Read a variant, with the real type "gt" (signature, unsigned integer):

const char *s;
uint64_t *v;
sd_bus_message_read(m, "v", "gt", &s, &v);

Read a dictionary containing three pairs of type {integer=>string}:

int i, j, k;
const char *s, *t, *u;
sd_bus_message_read(m, "a{is}", 3, &i, &s, &j, &t, &k, &u);

Read a single file descriptor, and duplicate it in order to keep it open after the message is freed.

sd_bus_message *m;
int fd, fd_copy;
sd_bus_message_read(m, "h", &fd);
fd_copy = fcntl(fd, FD_DUPFD_CLOEXEC, 3);

HISTORY

sd_bus_message_read() and sd_bus_message_readv() were added in version 240.

sd_bus_message_peek_type() was added in version 246.

sd_bus_message_peek_type, sd_bus_message_read, sd_bus_message_readv, sd_bus_message_read_basic - قراءة البيانات من رسالة D-Bus

الملخص

#include <systemd/sd-bus.h>
int sd_bus_message_peek_type(sd_bus_message *m, char *type, uint8_t *signature_len);

الوصف

يمكن استخدام الدالة sd_bus_message_read() لقراءة البيانات من الرسالة m وفقًا لسلسلة التنسيق fmt. تتكون سلسلة التنسيق من أحرف تمثل أنواع D-Bus، تشبه محددات تنسيق printf(3)، ولكنها تعين أنواع D-Bus بدلاً منها.

قائمة أحرف التنسيق المدعومة هي:

  • 'a': مصفوفة. تأخذ وسيطًا إضافيًا هو طول المصفوفة (بعدد العناصر).
  • 'g': عدد صحيح موقّع 64 بت. مكافئ لـ int64_t. هذا هو النوع الأكثر عمومية للأعداد الصحيحة.
  • 'b': قيمة منطقية. عادةً ما تتوافق مع عدد صحيح 32 بت في D-Bus. يجب أن يكون الوسيط مؤشرًا إلى نوع عدد صحيح (مثل int أو int32_t). لا تستخدم `bool` من C99، لأنه قد يكون أصغر من 32 بت ويتسبب في تلف الذاكرة.
  • 'd': رقم عائم مزدوج الدقة.
  • 'h': واصف ملف. يجب أن يكون الوسيط مؤشرًا إلى int. يتم تمرير واصف الملف بالقيمة ويتم إغلاقه تلقائيًا عند تدمير الرسالة ما لم يتم استنساخه باستخدام fcntl(fd, FD_DUPFD_CLOEXEC, ...) أو آلية مماثلة.
  • 'i': عدد صحيح موقّع 32 بت. مكافئ لـ int32_t.
  • 'n': عدد صحيح موقّع 16 بت. مكافئ لـ int16_t.
  • 'q': عدد صحيح غير موقّع 16 بت. مكافئ لـ uint16_t.
  • 's': سلسلة نصية. يجب أن يكون الوسيط مؤشرًا إلى const char *. السلسلة النصية مملوكة للرسالة ويجب عدم استخدامها بعد تدمير الرسالة.
  • 't': عدد صحيح غير موقّع 64 بت. مكافئ لـ uint64_t.
  • 'u': عدد صحيح غير موقّع 32 بت. مكافئ لـ uint32_t.
  • 'x': عدد صحيح موقّع 64 بت. مكافئ لـ int64_t. نفس `g`.
  • 'y': عدد صحيح غير موقّع 8 بت. مكافئ لـ uint8_t.
  • 'c': عدد صحيح موقّع 8 بت. مكافئ لـ int8_t.
  • 'o': مسار كائن D-Bus. مكافئ لسلسلة نصية.
  • 'u': توقيع D-Bus. مكافئ لسلسلة نصية.
  • '{key-type}value-type': إدخال قاموس. يتم تحديد أنواع المفتاح والقيمة بواسطة سلاسل الأنواع المتداخلة. على سبيل المثال، a{is} يصف مصفوفة من القواميس بمفاتيح أعداد صحيحة موقّعة 32 بت وسلاسل نصية كقيم.
  • '(type-list)': هيكل. تحدد سلسلة الأنواع المتداخلة أنواع الحقول في الهيكل. على سبيل المثال، (so) يصف هيكلًا يحتوي على سلسلة نصية ومسار كائن.
  • 'v': متغير. يجب أن يكون الوسيط الأول لـ sd_bus_message_read() مؤشرًا إلى سلسلة نصية للتوقيع، والوسيط الثاني يجب أن يكون مؤشرًا إلى القيمة. سيتم قراءة القيمة وفقًا للتوقيع المقدم.

يمكن أن تكون الحاويات مثل المصفوفات والقواميس والهياكل والمتغيرات متداخلة. عند قراءة حاوية، يجب أن يكون الوسيط الخاص بنوع الحاوية نفسه مؤشرًا إلى النوع المناسب (على سبيل المثال، int* للمصفوفات، const char* للسلاسل النصية).

بالنسبة للمصفوفات والقواميس، يجب توفير وسيط إضافي يحدد عدد العناصر في الحاوية. يُستخدم هذا لتحليل محتويات الحاوية بشكل صحيح.

الدالة sd_bus_message_readv() تعادل الدالة sd_bus_message_read()، ولكنها تأخذ قائمة الوسائط في va_list.

الدالة sd_bus_message_read_basic() تقرأ قيمة واحدة من نوع D-Bus الأساسي المحدد بواسطة type. يتم كتابة القيمة في الموقع الذاكرة المشار إليه بواسطة p. هذه دالة ذات مستوى أدنى وعادةً ما تكون مفيدة فقط عند التحليل يدويًا أو عندما يكون النوع معروفًا فقط في وقت التشغيل.

تستطلع الدالة sd_bus_message_peek_type() نوع الحقل التالي في مخزن الرسالة المؤقت دون استهلاكه. إذا كان الحقل نوع حاوية (مصفوفة، قاموس، هيكل، أو متغير)، فسيتم إرجاع سلسلة التوقيع الكاملة الخاصة به في type. إذا كان نوعًا أساسيًا، فسيتم إرجاع الحرف الواحد الذي يمثل هذا النوع. إذا كان الحقل متغيرًا، فسيتم إرجاع طول سلسلة التوقيع الخاصة به في signature_len. هذا مفيد للإرسال الديناميكي بناءً على محتويات الرسالة.

يتم تقديم الموضع الحالي في الرسالة بعد كل قراءة ناجحة. إذا كانت الرسالة مشوهة أو كانت الأنواع غير متطابقة، يتم إرجاع خطأ.

قيمة الإرجاع

عند النجاح، تعيد هذه الدوال قيمة غير سالبة. عند الفشل، تعيد رقم خطأ سالب.

ملاحظات

تتوافق أحرف سلسلة التنسيق مع نظام أنواع D-Bus. راجع مواصفات D-Bus للحصول على وصف كامل لنظام الأنواع.

عند قراءة واصفات الملفات باستخدام 'h'، كن على علم بأن واصف الملف مملوك للرسالة. إذا كنت بحاجة إلى الاحتفاظ بواصف الملف بعد تدمير الرسالة، يجب عليك استنساخه باستخدام fcntl() أو آلية مماثلة.

بالنسبة للمتغيرات (`'v'`)، يتم أيضًا قراءة سلسلة التوقيع من الرسالة ويجب توفيرها كوسيط أول لـ sd_bus_message_read(). ثم يتم قراءة القيمة الفعلية وفقًا لهذا التوقيع. لاحظ أن حرف النوع للمتغير نفسه هو 'v'، ولكن نوع القيمة داخل المتغير يحدده سلسلة التوقيع.

بالنسبة للمصفوفات والقواميس، يجب توفير عدد العناصر كوسيط إضافي لـ sd_bus_message_read(). هذا العدد هو أيضًا جزء من ترميز رسالة D-Bus ويجب أن يتطابق مع العدد الفعلي للعناصر.

الدالة sd_bus_message_read_basic() مفيدة لقراءة أنواع أساسية فردية غير حاويات عندما يتم تحديد النوع في وقت التشغيل. لا تقدم مؤشر الرسالة تلقائيًا ويجب استخدامها بحذر.

أمثلة

قراءة نوع أساسي واحد (عدد صحيح 64 بت):

sd_bus_message *m;
int64_t x;
sd_bus_message_read(m, "x", &x);

قراءة قيمة منطقية:

sd_bus_message *m;
int x; /* لا تستخدم نوع C99 "bool" هنا، فهو عادةً أصغر
          في الذاكرة وسيتسبب في تلف الذاكرة */
sd_bus_message_read(m, "b", &x);

قراءة جميع أنواع الأعداد الصحيحة:

uint8_t y;
int16_t n;
uint16_t q;
int32_t i;
uint32_t u;
int64_t x;
uint64_t t;
double d;
sd_bus_message_read(m, "ynqiuxtd", &y, &n, &q, &i, &u, &x, &t, &d);

قراءة هيكل يتكون من سلسلة نصية ومسار D-Bus:

const char *s, *p;
sd_bus_message_read(m, "(so)", &s, &p);

قراءة متغير، مع النوع الحقيقي "gt" (توقيع، عدد صحيح غير موقّع):

const char *s;
uint64_t *v;
sd_bus_message_read(m, "v", "gt", &s, &v);

قراءة قاموس يحتوي على ثلاثة أزواج من النوع {عدد صحيح=>سلسلة نصية}:

int i, j, k;
const char *s, *t, *u;
sd_bus_message_read(m, "a{is}", 3, &i, &s, &j, &t, &k, &u);

قراءة واصف ملف واحد، واستنساخه للاحتفاظ به مفتوحًا بعد تحرير الرسالة.

sd_bus_message *m;
int fd, fd_copy;
sd_bus_message_read(m, "h", &fd);
fd_copy = fcntl(fd, FD_DUPFD_CLOEXEC, 3);
