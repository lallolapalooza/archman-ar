الوصف

sd_bus_add_object_vtable() تُستخدم لتعريف سمات مسار الكائن path المتصل بمنفذ الناقل bus تحت الواجهة interface. يمكن أن تحتوي الـ vtable على تعريفات خصائص باستخدام SD_BUS_PROPERTY() أو SD_BUS_WRITABLE_PROPERTY()، تعريفات طرق باستخدام SD_BUS_METHOD()، SD_BUS_METHOD_WITH_NAMES()، SD_BUS_METHOD_WITH_OFFSET() أو SD_BUS_METHOD_WITH_NAMES_OFFSET()، وتعريفات إشارات باستخدام SD_BUS_SIGNAL_WITH_NAMES() أو SD_BUS_SIGNAL()، انظر أدناه. يحتوي المعامل userdata على مؤشر سيتم تمريره إلى وظائف رد الاتصال المختلفة. يمكن تحديده كـ NULL إذا لم تكن هناك حاجة لقيمة. يمكن أن تحتوي الواجهة على أي عدد من الـ vtables المرتبطة بها.

sd_bus_add_fallback_vtable() مشابه لـ sd_bus_add_object_vtable()، ولكنه يُستخدم لتسجيل سمات "fallback". عند البحث عن تعريف سمة، يتم تقييم مسارات الكائنات المسجلة باستخدام sd_bus_add_object_vtable() أولاً. إذا لم يتم العثور على تطابق، يتم تقييم vtables fallback لكل بادئة من مسار الكائن الناقل، أي مع إزالة مكونات مسار الكائن تدريجياً. هذا يسمح باستخدام الـ vtable للكائنات المنشأة ديناميكيًا بأي عدد من المرات.

المعامل find هو وظيفة تُستخدم لتحديد موقع الكائن الهدف بناءً على مسار الكائن الناقل path. يجب أن تُرجع 1 وتُعين المعامل الناتج ret_found إذا تم العثور على الكائن، وتُرجع 0 إذا لم يتم العثور عليه، وتُرجع رمز خطأ بأسلوب errno أو تهيئة بنية الخطأ ret_error في حالة حدوث خطأ. سيتم استخدام المؤشر المُمرر في ret_found كمعامل userdata لوظائف رد الاتصال (مزاح بمقدار الإزاحة المحدد في إدخالات vtable).

sd_bus_add_object() يربط رد اتصال مباشرة بمسار الكائن path. يمكن أن يحتوي مسار الكائن على أي عدد من ردود الاتصال المرتبطة به. يتم وضع كل رد اتصال في بداية قائمة ردود الاتصال التي يتم استدعاؤها دائمًا بترتيب. sd_bus_add_fallback() مشابه لـ sd_bus_add_object() ولكنه ينطبق على مسارات fallback.

sd_bus_add_filter() يقوم بتثبيت رد اتصال يتم استدعاؤه لكل رسالة D-Bus واردة. يمكن استخدام عوامل التصفية لمعالجة المنطق المشترك لجميع الرسائل التي تتلقاها خدمة (على سبيل المثال، المصادقة أو التفويض).

عندما يتم استلام طلب، يتم استدعاء جميع ردود الاتصال المرتبطة بالطلب بشكل متتابع حتى يقوم أحدها بإرجاع قيمة غير صفرية. إرجاع صفر من رد اتصال يمنح ردود الاتصال الأخرى فرصة لمعالجة الطلب. يتم استدعاء ردود الاتصال بالترتيب التالي: أولاً، يتم استدعاء ردود الاتصال العامة المثبتة باستخدام sd_bus_add_filter(). ثانيًا، يتم استدعاء ردود الاتصال المرتبطة مباشرة بمسار الكائن للطلب، متبوعة بأي ردود اتصال لطريقة D-Bus مرتبطة بمسار الكائن للطلب والواجهة والعضو. أخيرًا، يتم استدعاء ردود الاتصال الخاصة المرتبطة بمسار الكائن للطلب والواجهة والعضو. إذا قام آخر رد اتصال بإرجاع صفر، يتم إنشاء خطأ.

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

يتم تحديد الخطوة التي تتم إلى وظائف معالجات vtable المرتبطة بشكل مختلف قليلاً: بدلاً من إضافة معلمة الإزاحة من الإدخال إلى مؤشر بيانات المستخدم المحدد أثناء تسجيل vtable، يتم تمرير الإزاحة مباشرة، محولة إلى مؤشر، دون مراعاة مؤشر بيانات المستخدم المحدد أثناء تسجيل vtable.

SD_BUS_VTABLE_CAPABILITY(capability)

سيُسمح بالوصول إلى إدخال vtable هذا إذا كانت العملية المتصلة لديها القدرة capability، كما هو موضح في sd_bus_query_sender_privilege(3). إذا تم استخدامه لـ SD_BUS_VTABLE_START()، فإنه يوفر قيمة افتراضية لجميع الإدخالات في المصفوفة. إذا لم يتم تحديده، فسيتم التحقق افتراضيًا من CAP_SYS_ADMIN لكل إدخال فردي أو المصفوفة بأكملها. راجع capabilities(7) للحصول على معلومات حول القدرات.

لاحظ أنه يمكن تمييز إدخالات vtable على أنها غير مميزة، ويمكن تمييز المصفوفة بأكملها على أنها موثوقة، راجع مناقشة SD_BUS_VTABLE_UNPRIVILEGED أدناه.

SD_BUS_VTABLE_UNPRIVILEGED

يميز إدخال vtable هذا على أنه غير مميز. يقتصر الوصول إلى الإدخالات المميزة على المستخدمين الذين لديهم القدرات المناسبة، كما هو موضح أعلاه. في الممارسة العملية، يتم تمييز العديد من إدخالات vtable على أنها غير مميزة، ويمكن أن تكون مفتوحة للجميع أو يتم تحديد الوصول لاحقًا، على سبيل المثال، عن طريق التفويض إلى polkit[2].

يمكن تمييز المصفوفة بأكملها على أنها موثوقة، وفي هذه الحالة يتم تجاهل التعليقات التوضيحية على مستوى الإدخال، راجع sd_bus_set_trusted(3).

عند عدم تحديده، سيتم عرض التعليق التوضيحي org.freedesktop.systemd1.Privileged بالقيمة "true" في بيانات الفحص.

لا يمكن تطبيق SD_BUS_VTABLE_UNPRIVILEGED على الخصائص للقراءة فقط، ولكن الوصول (لكل من الخصائص للقراءة والكتابة) غير مقيد دائمًا.

لاحظ أن هذه الصفحة تصف عمليات التحقق المنفذة في عميل D-Bus. يمتلك خادم D-Bus سياسة إضافية يمكنها السماح أو رفض الاتصالات، راجع ملف التكوين في dbus-daemon(1).

أمثلة

مثال 1. إنشاء مستمع بسيط على الناقل

/* SPDX-License-Identifier: MIT-0 */
#define _GNU_SOURCE 1
#include <errno.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdlib.h>
#include <stdio.h>
#include <systemd/sd-bus.h>
#define _cleanup_(f) __attribute__((cleanup(f)))
typedef struct object {
  char *name;
  uint32_t number;
} object;
static int method(sd_bus_message *m, void *userdata, sd_bus_error *error) {
  int r;
  printf("Got called with userdata=%p\n", userdata);
  if (sd_bus_message_is_method_call(m,
                                    "org.freedesktop.systemd.VtableExample",
                                    "Method4"))
    return 1;
  const char *string;
  r = sd_bus_message_read(m, "s", &string);
  if (r < 0) {
    fprintf(stderr, "sd_bus_message_read() failed: %s\n", strerror(-r));
    return 0;
  }
  r = sd_bus_reply_method_return(m, "s", string);
  if (r < 0) {
    fprintf(stderr, "sd_bus_reply_method_return() failed: %s\n", strerror(-r));
    return 0;
  }
  return 1;
}
static const sd_bus_vtable vtable[] = {
        SD_BUS_Vtable_START(0),
        SD_BUS_METHOD(
            "Method1", "s", "s", method, 0),
        SD_BUS_METHOD_WITH_NAMES_OFFSET(
            "Method2",
            "so", SD_BUS_PARAM(string) SD_BUS_PARAM(path),
            "s", SD_BUS_PARAM(returnstring),
            method, offsetof(object, number),
            SD_BUS_VTABLE_DEPRECATED),
        SD_BUS_METHOD_WITH_ARGS_OFFSET(
            "Method3",
            SD_BUS_ARGS("s", string, "o", path),
            SD_BUS_RESULT("s", returnstring),
            method, offsetof(object, number),
            SD_BUS_VTABLE_UNPRIVILEGED),
        SD_BUS_METHOD_WITH_ARGS(
            "Method4",
            SD_BUS_NO_ARGS,
            SD_BUS_NO_RESULT,
            method,
            SD_BUS_VTABLE_UNPRIVILEGED),
        SD_BUS_SIGNAL(
            "Signal1",
            "so",
            0),
        SD_BUS_SIGNAL_WITH_NAMES(
            "Signal2",
            "so", SD_BUS_PARAM(string) SD_BUS_PARAM(path),
            0),
        SD_BUS_SIGNAL_WITH_ARGS(
            "Signal3",
            SD_BUS_ARGS("s", string, "o", path),
            0),
        SD_BUS_WRITABLE_PROPERTY(
            "AutomaticStringProperty", "s", NULL, NULL,
            offsetof(object, name),
            SD_BUS_VTABLE_PROPERTY_EMITS_CHANGE),
        SD_BUS_WRITABLE_PROPERTY(
            "AutomaticIntegerProperty", "u", NULL, NULL,
            offsetof(object, number),
            SD_BUS_VTABLE_PROPERTY_EMITS_INVALIDATION),
        SD_BUS_VTABLE_END
};
int main(int argc, char **argv) {
  _cleanup_(sd_bus_flush_close_unrefp) sd_bus *bus = NULL;
  int r;
  sd_bus_default(&bus);
  object object = { .number = 666 };
  object.name = strdup("name");
  if (!object.name) {
    fprintf(stderr, "OOM\n");
    return EXIT_FAILURE;
  }
  r = sd_bus_add_object_vtable(bus, NULL,
                                "/org/freedesktop/systemd/VtableExample",
                                "org.freedesktop.systemd.VtableExample",
                                vtable,
                                &object);
  if (r < 0) {
    fprintf(stderr, "sd_bus_add_object_vtable() failed: %s\n", strerror(-r));
    return EXIT_FAILURE;
  }
  r = sd_bus_request_name(bus,
                          "org.freedesktop.systemd.VtableExample",
                          0);
  if (r < 0) {
    fprintf(stderr, "sd_bus_request_name() failed: %s\n", strerror(-r));
    return EXIT_FAILURE;
  }
  for (;;) {
    r = sd_bus_wait(bus, UINT64_MAX);
    if (r < 0) {
      fprintf(stderr, "sd_bus_wait() failed: %s\n", strerror(-r));
      return EXIT_FAILURE;
    }
    r = sd_bus_process(bus, NULL);
    if (r < 0) {
      fprintf(stderr, "sd_bus_process() failed: %s\n", strerror(-r));
      return EXIT_FAILURE;
    }
  }
  r = sd_bus_release_name(bus, "org.freedesktop.systemd.VtableExample");
  if (r < 0) {
    fprintf(stderr, "sd_bus_release_name() failed: %s\n", strerror(-r));
    return EXIT_FAILURE;
  }
  free(object.name);
  return 0;
}

قيمة الإرجاع

في حالة النجاح، تُرجع sd_bus_add_object_vtable() و sd_bus_add_fallback_vtable() رقمًا غير سالب. في حالة الفشل، تُرجع رمز خطأ سالبًا، بأسلوب errno.

الأخطاء

قد تشير الأخطاء التي يتم إرجاعها إلى المشكلات التالية:

-EINVAL

أحد المعلمات المطلوبة هو NULL أو غير صالح. تم تمرير واجهة D-Bus محجوزة كقيمة لـ interface.

-ENOPKG

لا يمكن حل الناقل.

-ECHILD

تم إنشاء الناقل في عملية أو مكتبة أو وحدة مختلفة.

-ENOMEM

فشل تخصيص الذاكرة.

-EPROTOTYPE

تم استدعاء sd_bus_add_object_vtable() و sd_bus_add_fallback_vtable() لنفس كائن الناقل بنفس المسار، وهو أمر غير صالح.

-EEXIST

تم تسجيل vtable هذا بالفعل لهذه interface و path.
