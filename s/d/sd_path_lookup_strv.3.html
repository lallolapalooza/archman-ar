الوصف

sd_path_lookup() و sd_bus_path_lookup_strv() تعيد مسارًا واحدًا أو مجموعة من مسارات نظام الملفات المحددة بواسطة الوسيط type. في حالة sd_path_lookup()، يتم إرجاع سلسلة واحدة منتهية بـ NUL. عندما يحدد type مجموعة من المسارات، يتم ربطها باستخدام ":" كفاصل (كما هو الحال تقليديًا لـ $PATH أو $LD_LIBRARY_PATH). في حالة sd_path_lookup_strv()، يتم إرجاع مصفوفة من السلاسل منتهية بـ NULL (strv). إذا تم تقديم لاحقة suffix، يتم ربطها بكل مسار بعد شرطة مائلة ("/"). جميع المسارات التي تم إرجاعها مطلقة.

بالنسبة للمسارات التي تشير إلى مجلدات المستخدم، يتم اتباع معيار XDG ذو الصلة، مع دعم لمتغيرات البيئة مثل $XDG_DOCUMENTS_DIR، $XDG_DESKTOP_DIR، ...، والتهيئة الصريحة في /etc/xdg/user-dirs.conf أو ${XDG_CONFIG_HOME}/user-dirs.dirs. انظر مواصفات دليل المستخدم XDG[1] للتفاصيل.

systemd-path(1) هو غلاف حول sd_path_lookup() ويسمح بالاستعلام عن نفس مجموعة المسارات.

قيمة الإرجاع

عند النجاح، تعيد sd_path_lookup() و sd_path_lookup_strv() عددًا صحيحًا غير سالب. عند الفشل، يتم إرجاع رقم خطأ سالب بأسلوب errno من قبل أي من الدالتين.

يجب أن يقوم المستدعي بتحرير السلسلة أو مصفوفة السلاسل (strv) التي تم إرجاعها باستخدام free(3).

الأخطاء

قد تشير الأخطاء التي تم إرجاعها إلى المشاكل التالية:

-EOPNOTSUPP

معرف type غير معروف.

تمت الإضافة في الإصدار 246.

-EINVAL

وسيط الإخراج هو NULL.

تمت الإضافة في الإصدار 246.

-ENXIO

فشل الاستعلام بسبب متغير بيئة غير معرف (مثل SD_PATH_USER_RUNTIME عندما لا يكون $XDG_RUNTIME_DIR محددًا).

تمت الإضافة في الإصدار 246.

-ENOMEM

فشل تخصيص الذاكرة.

تمت الإضافة في الإصدار 246.

أمثلة

البحث عن موقع ~/Documents

/* SPDX-License-Identifier: MIT-0 */
#include <stdio.h>
#include <stdlib.h>
#include <systemd/sd-path.h>
int main(void) {
  int r;
  char *t;
  r = sd_path_lookup(SD_PATH_USER_DOCUMENTS, NULL, &t);
  if (r < 0)
    return EXIT_FAILURE;
  printf("~/Documents: %s\n", t);
  free(t);
  return EXIT_SUCCESS;
}

لاحظ أن الإجابة الافتراضية $HOME/Documents قد يتم تجاوزها بواسطة user-dirs.conf أو $XDG_DOCUMENTS_DIR.

ملاحظات

الوظائف الموصوفة هنا متاحة كمكتبة مشتركة، يمكن تجميعها وربطها باستخدام ملف pkg-config(1) الخاص بـ libsystemd.

الكود الموصوف هنا يستخدم getenv(3)، وهو معرّف بأنه غير آمن للاستخدام مع الخيوط المتعددة. هذا يعني أنه يجب على الكود الذي يستدعي الدوال الموصوفة هنا عدم استدعاء setenv(3) من خيط متوازي. يوصى بالقيام باستدعاءات إلى setenv() فقط من مرحلة مبكرة من البرنامج عندما لم يتم بدء أي خيوط أخرى.
