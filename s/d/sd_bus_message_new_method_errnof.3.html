sd_bus_message_new_method_errnof(3)

الحزمة: systemd-libs

التراخيص: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_BUS_MESSAGE_NEW_METHOD_ERROR(3) sd_bus_message_new_method_error SD_BUS_MESSAGE_NEW_METHOD_ERROR(3)

الاسم

sd_bus_message_new_method_error, sd_bus_message_new_method_errorf, sd_bus_message_new_method_errno, sd_bus_message_new_method_errnof - إنشاء رد خطأ لاستدعاء طريقة

ملخص

#include <systemd/sd-bus.h>

int sd_bus_message_new_method_error(sd_bus_message *call, sd_bus_message **m, const sd_bus_error *e);

int sd_bus_message_new_method_errorf(sd_bus_message *call, sd_bus_message **m, const char *name, const char *format, ...);

int sd_bus_message_new_method_errno(sd_bus_message *call, sd_bus_message **m, int error, const sd_bus_error *p);

int sd_bus_message_new_method_errnof(sd_bus_message *call, sd_bus_message **m, int error, const char *format, ...);

الوصف

تقوم الدالة sd_bus_message_new_method_error() بإنشاء كائن رسالة ناقل جديد وهو رد خطأ للرسالة call، وتعيده في المعامل الناتج m. يتم إلحاق معلومات الخطأ من الخطأ e: يتم استخدام حقل name في e كمعرف خطأ في رأس الرد (على سبيل المثال، اسم خطأ مثل "org.freedesktop.DBus.Error.NotSupported" أو الرمز المكافئ SD_BUS_ERROR_NOT_SUPPORTED)، ويتم تعيين حقل message كسلسلة نصية قابلة للقراءة للخطأ البشري إذا كانت موجودة. يجب أن يحتوي الخطأ e على حقل name معين، انظر sd_bus_error_is_set(3).

تقوم الدالة sd_bus_message_new_method_errorf() بإنشاء رد خطأ بشكل مشابه لـ sd_bus_message_new_method_error()، ولكن بدلاً من هيكل خطأ جاهز، تأخذ سلسلة معرف خطأ name، بالإضافة إلى سلسلة تنسيق printf(3) format ومعاملات مقابلة. يتم إرسال رد خطأ بمعرف الخطأ name والسلسلة المنسقة كرسالة. يجب ألا يكون name و format NULL.

تقوم الدالة sd_bus_message_new_method_errno() بإنشاء رد خطأ بشكل مشابه لـ sd_bus_message_new_method_error()، ولكن بالإضافة إلى هيكل الخطأ p، تأخذ قيمة خطأ errno(3) في المعامل error. إذا كان الخطأ p معينًا (انظر sd_bus_error_is_set(3))، فيتم استخدامه في الرد. بخلاف ذلك، يتم ترجمة error إلى معرف خطأ ويتم استخدامه لإنشاء هيكل خطأ جديد باستخدام sd_bus_error_set_errno(3) ويتم استخدامه في الرد. (إذا كان error صفرًا، فلا يتم تعيين أي خطأ فعليًا، ويتم إنشاء رد خطأ بدون معلومات.)

تقوم الدالة sd_bus_message_new_method_errnof() بإنشاء رد خطأ بشكل مشابه لـ sd_bus_message_new_method_error(). تأخذ قيمة خطأ errno(3) في المعامل error، بالإضافة إلى سلسلة تنسيق printf(3) format ومعاملات مقابلة. يمكن استخدام "%m" في سلسلة التنسيق للإشارة إلى سلسلة الخطأ المقابلة لرمز errno المحدد. يتم تهيئة رسالة الخطأ باستخدام معرف الخطأ الذي تم إنشاؤه من error والسلسلة المنسقة. (إذا كان error صفرًا، فلا يتم تعيين أي خطأ فعليًا، ويتم إنشاء رد خطأ بدون معلومات.)

قيمة الإرجاع

تعيد هذه الدوال 0 إذا تم إنشاء رد الخطأ بنجاح، ورمز خطأ سالب بأسلوب errno بخلاف ذلك.

الأخطاء

قد تشير الأخطاء التي تم إرجاعها إلى المشاكل التالية:

-EINVAL

معامل الرسالة call أو المعامل الناتج m هو NULL.

الرسالة call ليست رسالة استدعاء طريقة.

المعامل الخطأ e إلى sd_bus_message_new_method_error() غير معين، انظر sd_bus_error_is_set(3).

-EPERM

تم ختم الرسالة call.

-ENOTCONN

الناقل الذي تم إرفاق الرسالة call به غير متصل.

-ENOMEM

فشل تخصيص الذاكرة.

ملاحظات

الدوال الموصوفة هنا متاحة كمكتبة مشتركة، يمكن تجميعها وربطها بملف pkg-config(1) الخاص بـlibsystemd.

الكود الموصوف هنا يستخدم getenv(3)، والتي تم الإعلان عنها على أنها غير آمنة للخيوط المتعددة. هذا يعني أن الكود الذي يستدعي الدوال الموصوفة هنا يجب ألا يستدعي setenv(3) من خيط متوازي. يوصى بالقيام بالاستدعاءات لـ setenv() فقط من مرحلة مبكرة من البرنامج عندما لم يتم بدء أي خيوط أخرى.
