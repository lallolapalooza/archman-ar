sd_event_unrefp(3)

الحزمة: systemd-libs

التراخيص: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_EVENT_NEW(3) sd_event_new SD_EVENT_NEW(3)

الاسم

sd_event_new, sd_event_default, sd_event_ref, sd_event_unref, sd_event_unrefp, sd_event_get_tid, sd_event - الحصول على مرجع لكائن حلقة الأحداث وتحريره

ملخص

#include <systemd/sd-event.h>
typedef struct sd_event sd_event;

int sd_event_new(sd_event **event);

int sd_event_default(sd_event **event);

sd_event *sd_event_ref(sd_event *event);

sd_event *sd_event_unref(sd_event *event);

void sd_event_unrefp(sd_event **event);

int sd_event_get_tid(sd_event *event, pid_t *ret);

الوصف

sd_event_new() تخصص كائن حلقة أحداث جديد. يتم إرجاع كائن حلقة الأحداث في المعلمة event. بعد الاستخدام، قم بإسقاط المرجع الذي تم إرجاعه باستخدام sd_event_unref(). عندما يتم إسقاط آخر مرجع، يتم تحرير الكائن.

sd_event_default() يحصل على مرجع لكائن حلقة الأحداث الافتراضي للخيط الحالي، وقد يقوم بتخصيص كائن جديد إذا لم يتم تخصيص كائن حلقة أحداث افتراضي بعد لهذا الخيط. بعد الاستخدام، قم بإسقاط المرجع الذي تم إرجاعه باستخدام sd_event_unref(). عندما يتم إسقاط آخر مرجع، يتم تحرير حلقة الأحداث. إذا تم استدعاء هذه الدالة أثناء الاستمرار في الإشارة إلى الكائن الذي تم إرجاعه من استدعاء سابق من نفس الخيط، يتم إرجاع نفس الكائن مرة أخرى، ولكن يتم زيادة المرجع بمقدار واحد. يوصى باستخدام هذا الاستدعاء بدلاً من sd_event_new() لمشاركة كائنات حلقة الأحداث بين المكونات المختلفة التي يتم إرسالها في نفس الخيط. لكل خيط بالضبط صفر أو واحد من كائنات حلقة الأحداث الافتراضية مرتبطة به، ولا أكثر.

بعد تخصيص كائن حلقة أحداث، أضف مصادر الأحداث إليه باستخدام sd_event_add_io(3)، sd_event_add_time(3)، sd_event_add_signal(3)، sd_event_add_child(3)، sd_event_add_inotify(3)، sd_event_add_defer(3)، sd_event_add_post(3) أو sd_event_add_exit(3)، ثم قم بتنفيذ حلقة الأحداث باستخدام sd_event_loop(3).

sd_event_ref() تزيد عدد مراجع كائن حلقة الأحداث المحدد بمقدار واحد.

sd_event_unref() تقلل عدد مراجع كائن حلقة الأحداث المحدد بمقدار واحد. إذا وصل العدد إلى الصفر، يتم تحرير الكائن. لاحظ أنه يتم تحريره بغض النظر عما إذا كان كائن حلقة الأحداث الافتراضي للخيط أم لا. هذا يعني أن تخصيص حلقة أحداث باستخدام sd_event_default()، ثم تحريرها، ثم الحصول على واحدة جديدة باستخدام sd_event_default() سيؤدي إلى كائنين منفصلين. لاحظ أنه لتحرير كائن حلقة أحداث، يجب أيضًا تحرير جميع مصادر الأحداث المتبقية لحلقة الأحداث حيث يحتفظ كل منها بمرجع إليها.

sd_event_unrefp() مشابه لـ sd_event_unref() ولكنه يأخذ مؤشرًا إلى مؤشر لكائن sd_event. هذه الدالة مفيدة بالاقتران مع سمة متغير التنظيف (Clean-up Variable Attribute)[1] الخاصة بـ GCC و LLVM. لاحظ أن هذه الدالة معرفة كدالة مضمنة. استخدم تصريحًا مثل التالي، لتخصيص كائن حلقة أحداث يتم تحريره تلقائيًا عند مغادرة كتلة الكود:

{
        __attribute__((cleanup(sd_event_unrefp))) sd_event *event = NULL;
        int r;
        ...
        r = sd_event_default(&event);
        if (r < 0) {
          errno = -r;
          fprintf(stderr, "Failed to allocate event loop: %m\n");
        }
        ...
}

sd_event_ref() و sd_event_unref() و sd_event_unrefp() تنفذ لا شيء إذا كان كائن حلقة الأحداث الذي تم تمريره هو NULL.

sd_event_get_tid() تسترجع معرف الخيط ("TID") للخيط المرتبط به كائن حلقة الأحداث المحدد. هذا الاستدعاء مدعوم فقط لحلقات الأحداث المخصصة باستخدام sd_event_default()، ويقوم بإرجاع المعرف للخيط الذي تعتبر حلقة الأحداث هي الافتراضية له. انظر gettid(2) لمزيد من المعلومات حول معرفات الخيوط.

قيمة الإرجاع

عند النجاح، تقوم sd_event_new() و sd_event_default() و sd_event_get_tid() بإرجاع 0 أو عدد صحيح موجب. عند الفشل، تقوم بإرجاع رمز خطأ سالب من نوع errno. تقوم sd_event_ref() دائمًا بإرجاع مؤشر إلى كائن حلقة الأحداث الذي تم تمريره. تقوم sd_event_unref() دائمًا بإرجاع NULL.

الأخطاء

قد تشير الأخطاء المرجعة إلى المشاكل التالية:

-ENOMEM

لا توجد ذاكرة كافية لتخصيص الكائن.

-EMFILE

تم تخصيص الحد الأقصى لعدد حلقات الأحداث.

-ENXIO

تم استدعاء sd_event_get_tid() على كائن حلقة أحداث لم يتم تخصيصه باستخدام sd_event_default().
