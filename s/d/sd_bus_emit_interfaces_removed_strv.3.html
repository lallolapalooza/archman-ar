الوصف

sd_bus_emit_signal() هي وظيفة مساعدة لتهيئة كائن رسالة الباص وإصدار إشارة D-Bus المقابلة. تجمع وظائف sd_bus_message_new_signal(3) و sd_bus_message_append(3) و sd_bus_send(3) في استدعاء وظيفة واحدة. sd_bus_emit_signalv() تعادل sd_bus_message_append()، باستثناء أنها تُستدعى باستخدام "va_list" بدلاً من عدد متغير من الوسائط.

sd_bus_emit_signal_to() و sd_bus_emit_signal_tov() متطابقتان مع sd_bus_emit_signal() و sd_bus_emit_signalv()، باستثناء أنهما يمكنهما إصدار الإشارة إلى وجهة واحدة. أعطِ destination كـ NULL لبث الإشارة.

sd_bus_emit_interfaces_added() و sd_bus_emit_interfaces_removed() تُستخدم لتنفيذ إشارات InterfacesAdded و InterfacesRemoved من الواجهة org.freedesktop.DBus.ObjectManager. تأخذ مسارًا تم تعديل واجهاته كوسيط وقائمة متغيرة من الواجهات التي تمت إضافتها أو إزالتها، على التوالي. يجب أن يكون الوسيط الأخير المُمرر إلى sd_bus_emit_interfaces_added() و sd_bus_emit_interfaces_removed() هو NULL. هذا يسمح لكلتا الوظيفتين بتحديد عدد وسائط الواجهة المُمررة بأمان. sd_bus_emit_interfaces_added_strv() و sd_bus_emit_interfaces_removed_strv() متطابقتان مع نظائرهما، لكن كلاهما يأخذ قائمة الواجهات كوسيط واحد بدلاً من عدد متغير من الوسائط.

sd_bus_emit_properties_changed() تُستخدم لتنفيذ إشارة PropertiesChanged من الواجهة org.freedesktop.DBus.Properties. تأخذ مسار كائن، واجهة، وقائمة متغيرة من أسماء الخصائص كوسائط لها. يجب أن يكون الوسيط الأخير المُمرر إلى sd_bus_emit_properties_changed() هو NULL. هذا يسمح بتحديد عدد أسماء الخصائص المُمررة بأمان. sd_bus_emit_properties_changed_strv() متطابقة مع sd_bus_emit_properties_changed() ولكنها تأخذ قائمة أسماء الخصائص كوسيط واحد بدلاً من عدد متغير من الوسائط.

sd_bus_emit_object_added() و sd_bus_emit_object_removed() هي وظائف مساعدة لإصدار إشارات InterfacesAdded أو InterfacesRemoved لجميع الواجهات المسجلة على مسار كائن معين، على التوالي. وهذا يشمل أي جداول افتراضية للأصل إذا لم يتم تجاوزها بواسطة جدول افتراضي أكثر ملاءمة للفرع. كما أنها تشمل جميع واجهات D-Bus القياسية التي تنفذها sd-bus نفسها على أي كائن مسجل.

لاحظ أن sd_bus_emit_interfaces_added() و sd_bus_emit_interfaces_removed() و sd_bus_emit_object_added() و sd_bus_emit_object_removed() تتطلب أن يكون مدير كائن قد تم تسجيله على مسار الكائن المحدد أو أحد مسارات الكائنات الأصلية له باستخدام sd_bus_add_object_manager(3).

قيمة الإرجاع

عند النجاح، تعيد هذه الوظائف عددًا صحيحًا غير سالب. عند الفشل، تعيد رمز خطأ سلبيًا بنمط errno.

الأخطاء

قد تشير الأخطاء المُعادة إلى المشاكل التالية:

-EINVAL

أحد الوسائط المطلوبة هو NULL أو غير صالح. تم تمرير واجهة D-Bus محجوزة كوسيط interface.

-ENOPKG

لا يمكن حل الباص.

-ECHILD

تم إنشاء الباص في عملية أو مكتبة أو مثيل وحدة مختلف.

-ENOMEM

فشل تخصيص الذاكرة.

-ESRCH

تم استدعاء أحد sd_bus_emit_interfaces_added() أو sd_bus_emit_interfaces_removed() أو sd_bus_emit_object_added() أو sd_bus_emit_object_removed() على كائن بدون مدير كائن مسجل على مساره الخاص أو أحد مسارات الكائنات الأصلية له.

راجع صفحات الدليل لـ sd_bus_message_new_signal(3) و sd_bus_message_append(3) و sd_bus_send(3) لمزيد من الأخطاء المحتملة.

ملاحظات

الوظائف الموصوفة هنا متاحة كمكتبة مشتركة، والتي يمكن تجميعها وربطها باستخدام ملف pkg-config(1) الخاص بـ libsystemd.

الكود الموصوف هنا يستخدم getenv(3)، والذي يُعلن أنه ليس آمنًا للاستخدام في خيوط متعددة. هذا يعني أن الكود الذي يستدعي الوظائف الموصوفة هنا يجب ألا يستدعي setenv(3) من خيط موازٍ. يُوصى بإجراء استدعاءات لـ setenv() فقط من مرحلة مبكرة من البرنامج عندما لم يتم بدء أي خيوط أخرى.

SYNOPSIS

#include <systemd/sd-bus.h>

int sd_bus_emit_interfaces_removed_strv(sd_bus *bus, const char *path, const char *const *interfaces);
int sd_bus_emit_properties_changed(sd_bus *bus, const char *path, const char *interface, sd_bus_error *error, const char *name, ...);
int sd_bus_emit_properties_changed_strv(sd_bus *bus, const char *path, const char *interface, sd_bus_error *error, const char *const *names);
int sd_bus_emit_object_added(sd_bus *bus, const char *path, const char *const *interfaces);
int sd_bus_emit_object_removed(sd_bus *bus, const char *path, const char *const *interfaces);
int sd_bus_emit_signalv(sd_bus *bus, const char *path, const char *interface, const char *member, sd_bus_error *error, const char *signature, va_list ap);
int sd_bus_emit_signal_to(sd_bus *bus, const char *path, const char *interface, const char *member, sd_bus_error *error, const char *signature, ...);
int sd_bus_emit_signal_tov(sd_bus *bus, const char *destination, const char *path, const char *interface, const char *member, sd_bus_error *error, const char *signature, va_list ap);

DESCRIPTION

These functions may be used to emit D-Bus signals. Signals are broadcast messages that can be sent by any D-Bus service. Any D-Bus client may listen to signals emitted from any service.

The primary use case for these functions is to inform clients about changes in the state of an object.

sd_bus_emit_interfaces_removed_strv(), sd_bus_emit_properties_changed(), sd_bus_emit_properties_changed_strv(), sd_bus_emit_object_added(), and sd_bus_emit_object_removed() may be used to emit the standard org.freedesktop.DBus.ObjectManager.InterfacesRemoved, org.freedesktop.DBus.Properties.PropertiesChanged, org.freedesktop.DBus.ObjectManager.InterfacesAdded, and org.freedesktop.DBus.ObjectManager.ObjectRemoved signals, respectively. These signals are part of the Object Manager interface.

Use sd_bus_emit_properties_changed() and sd_bus_emit_properties_changed_strv() to emit the org.freedesktop.DBus.Properties.PropertiesChanged signal. This signal is emitted when one or more properties of an object change. The path parameter must be the object path of the object whose properties changed. The interface parameter must be the name of the interface on which the properties changed. The error parameter is unused. The variable arguments to sd_bus_emit_properties_changed() must be alternating property names and values, followed by a NULL pointer. The names array passed to sd_bus_emit_properties_changed_strv() must be a NULL-terminated array of strings, where each string is a property name. The values of the properties are not sent with this signal; clients must fetch them using sd_bus_get_property(3).

Use sd_bus_emit_object_added() and sd_bus_emit_object_removed() to emit the org.freedesktop.DBus.ObjectManager.InterfacesAdded and org.freedesktop.DBus.ObjectManager.ObjectRemoved signals. The path parameter is the object path of the object being added or removed. The interfaces parameter is a NULL-terminated array of strings, where each string is the name of an interface implemented by the object.

Use sd_bus_emit_interfaces_removed_strv() to emit the org.freedesktop.DBus.ObjectManager.InterfacesRemoved signal. The path parameter is the object path of the object for which interfaces are being removed. The interfaces parameter is a NULL-terminated array of strings, where each string is the name of an interface that is no longer implemented by the object.

sd_bus_emit_signalv(), sd_bus_emit_signal_to(), and sd_bus_emit_signal_tov() may be used to emit arbitrary D-Bus signals. The bus parameter is the connection to use. The path parameter is the object path of the emitting object. The interface parameter is the interface name of the signal. The member parameter is the signal name. The error parameter is unused. The signature parameter is a string describing the types of the arguments to the signal. The remaining arguments are the actual signal arguments. Use sd_bus_emit_signalv() or sd_bus_emit_signal_tov() if you have the arguments in a va_list. Use sd_bus_emit_signal_to() for a variable number of arguments.

If destination is not NULL in sd_bus_emit_signal_tov(), the signal will be sent directly to the specified bus name. Otherwise, it will be broadcast to all recipients.

RETURN VALUE

On success, these functions return a non-negative integer. On failure, they return a negative error number.

NOTES

All these functions will create and enqueue a message on the bus connection. The message is then sent asynchronously. The return value indicates whether the message was successfully enqueued. The actual sending of the message might fail later.

The signature string for sd_bus_emit_signalv(), sd_bus_emit_signal_to(), and sd_bus_emit_signal_tov() must be a valid D-Bus type string. For example, a signal with a single string argument would have the signature "s". A signal with an integer and a string argument would have the signature "is".

The arguments following the signature string in sd_bus_emit_signal_to() must match the types specified in the signature. The arguments for sd_bus_emit_signalv() and sd_bus_emit_signal_tov() are provided via the va_list and must also match the signature.

The caller is responsible for ensuring that the passed arguments are correctly formatted and match the specified signature. Failure to do so may result in D-Bus errors or unexpected behavior.

It is recommended to use the Object Manager interface functions (sd_bus_emit_properties_changed(3), etc.) when possible, as they provide a standardized way to signal changes to object state.
