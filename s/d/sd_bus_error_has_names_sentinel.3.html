الوصف

يحمل الهيكل `sd_bus_error` معلومات حول حالة خطأ D-Bus، أو عدم وجودها. يمكن استخدام الدوال الموضحة أدناه لتعيين حقول في هذا الهيكل والاستعلام عنها.

•يحتوي الحقل name على معرف مختصر لخطأ. يجب أن يتبع قواعد أسماء الأخطاء الموضحة في مواصفات D-Bus، القسم الفرعي أسماء D-Bus الصالحة[1]. يتم وصف عدد من أسماء الأخطاء الشائعة والقياسية في sd-bus-errors(3)، ولكن قد تحدد التطبيقات أخطاء إضافية خاصة بالمجال.

•عادةً ما يحتوي الحقل message على سلسلة نصية قابلة للقراءة البشرية تصف التفاصيل، ولكن قد تكون NULL.

يجب تهيئة هيكل `sd_bus_error` غير المعين بكلتا الحقلين إلى NULL، ويشير إلى عدم وجود خطأ، أي نجاح. قم بتعيين SD_BUS_ERROR_NULL إلى الهيكل لتهيئة كلا الحقلين إلى NULL. عند عدم الحاجة إليها بعد الآن، يجب تدمير الموارد التي يحتفظ بها هيكل `sd_bus_error` باستخدام sd_bus_error_free().

تقوم sd_bus_error_set() بتعيين هيكل خطأ إلى الأسماء والسلاسل النصية المحددة. سيتم نسخ السلاسل النصية إلى ذاكرة داخلية مخصصة حديثًا. من الضروري تحرير المحتويات مرة أخرى عندما لا تكون مطلوبة بعد الآن (انظر أعلاه). لا تستخدم هذا الاستدعاء على هياكل الأخطاء التي تم تعيينها بالفعل. إذا كنت تنوي إعادة استخدام هيكل خطأ، فقم بتحرير البيانات القديمة المخزنة فيه باستخدام sd_bus_error_free() أولاً.

ستعيد sd_bus_error_set() قيمة تشبه errno (انظر errno(3)) محددة من اسم الخطأ name المحدد. إذا كان name هو NULL، فمن المفترض عدم حدوث خطأ، ويتم إرجاع 0. إذا كان name غير فارغ، فسيتم دائمًا إرجاع قيمة سالبة. إذا كان e هو NULL، فلن يتم تهيئة هيكل خطأ، ولكن لا يزال name يتم تحويله إلى قيمة بأسلوب errno.

يتم تحويل العديد من أخطاء D-Bus المعروفة إلى نظائر errno المعروفة، والأخرى إلى -EIO. انظر sd-bus-errors(3) للحصول على قائمة بأسماء الأخطاء المعروفة. قد يتم تعريف تعيينات أخطاء إضافية باستخدام sd_bus_error_add_map(3).

تم تصميم sd_bus_error_set() لتكون مريحة للاستخدام في عبارة return. إذا كان message هو NULL، فلن يتم تعيين رسالة. قد تفشل هذه الاستدعاء إذا لم يمكن تخصيص ذاكرة للسلاسل النصية للاسم والرسالة، وفي هذه الحالة سيتم تعيين خطأ SD_BUS_ERROR_NO_MEMORY بدلاً من ذلك وسيتم إرجاع -ENOMEM.

sd_bus_error_setf() و sd_bus_error_setfv() مشابهتان لـ sd_bus_error_set()، ولكنهما تأخذان سلسلة تنسيق printf(3) وحجج مقابلة لإنشاء الحقل message. تستخدم sd_bus_error_setf() حججًا متغيرة، وتقبل sd_bus_error_setfv() الحجج كقائمة معلمات va_arg(3).

sd_bus_error_set_const() مشابهة لـ sd_bus_error_set()، ولكن لا يتم نسخ السلاسل النصية داخليًا، وبالتالي يجب أن تظل ثابتة وصالحة طوال عمر e. استخدم هذه الاستدعاء لتجنب تخصيص الذاكرة عند تعيين هياكل الأخطاء. نظرًا لأن هذا الاستدعاء لا يقوم بتخصيص الذاكرة، فلن يفشل مع حالة نفاد الذاكرة كما قد يحدث مع sd_bus_error_set()، كما هو موضح أعلاه. بدلاً من ذلك، قد يتم استخدام الماكرو SD_BUS_ERROR_MAKE_CONST() لإنشاء هيكل خطأ حرفي وثابت على الفور.

ستعيد sd_bus_error_set_errno() فورًا 0 إذا كان معامل الخطأ error المحدد هو 0. بخلاف ذلك، ستقوم بتعيين name من قيمة تشبه errno يتم تحويلها إلى خطأ D-Bus. سيتم استخدام strerror_r(3) لتعيين message. سيتم استخدام أسماء أخطاء D-Bus المعروفة لـ name إذا كانت قابلة للتطبيق، وإلا سيتم إنشاء اسم في مساحة الاسم "System.Error.". يتم تجاهل إشارة رقم الخطأ المحدد ويتم استخدام القيمة المطلقة ضمنيًا. إذا كان الخطأ المحدد error غير صفري، فإن الاستدعاء يعيد دائمًا قيمة سالبة، للاستخدام المريح في عبارات return. قد تفشل هذه الاستدعاء بسبب نقص الذاكرة، وفي هذه الحالة سيتم تعيين خطأ SD_BUS_ERROR_NO_MEMORY بدلاً من ذلك، وسيتم إرجاع -ENOMEM.

sd_bus_error_set_errnof() و sd_bus_error_set_errnof() مشابهتان لـ sd_bus_error_set_errno()، ولكن بالإضافة إلى error، تأخذان سلسلة تنسيق printf(3) وحجج مقابلة. سيتم إنشاء الحقل message من format والحجج. تستخدم sd_bus_error_set_errnof() حججًا متغيرة، وتقبل sd_bus_error_set_errnofv() الحجج كقائمة معلمات va_arg(3).

تقوم sd_bus_error_get_errno() بتحويل الحقل name لهيكل الخطأ إلى قيمة تشبه errno (موجبة) باستخدام نفس القواعد مثل sd_bus_error_set(). إذا كان e هو NULL، فسيتم إرجاع 0.

ستقوم sd_bus_error_copy() بتهيئة dst باستخدام القيم في e، إذا تم تعيين e بقيمة خطأ من قبل. بخلاف ذلك، ستعود فورًا. إذا تم تعيين السلاسل النصية في e باستخدام sd_bus_error_set_const()، فسيتم مشاركتها. بخلاف ذلك، سيتم نسخها. قبل هذا الاستدعاء، يجب أن يكون dst غير معين، أي إما تم تهيئته حديثًا بـ NULL أو تم إعادة تعيينه باستخدام sd_bus_error_free().

تعيد sd_bus_error_copy() بشكل عام 0 أو قيمة سالبة تشبه errno بناءً على المعامل المدخل e: 0 إذا لم يكن معينًا وقيمة سالبة إذا تم تعيينه إلى خطأ ما، على غرار sd_bus_error_set(). ومع ذلك، قد تعيد أيضًا خطأ تم إنشاؤه داخليًا.

DESCRIPTION

The sd_bus_error structure is used to pass error information between sd-bus calls. It contains two strings: name and message. The name is a unique identifier for the error, while the message is a human-readable explanation of the error. These two strings are allocated dynamically unless sd_bus_error_set_const() is used.

The error structure is initialized to an unset state when it is declared or allocated. This state is represented by both fields being NULL. It is possible to pass an unset error structure to most functions described here.

The error structure is passed by pointer. If an error occurs during an operation, the error structure pointed to by error is filled with the error information. It is the caller's responsibility to check the return value of the functions and to examine the error structure if an error occurred.

sd_bus_error_set(), sd_bus_error_setf(), and sd_bus_error_setfv() set the error structure error to the specified name and message. If error already contains an error, it is freed first. The message string is copied. sd_bus_error_setf() and sd_bus_error_setfv() are variadic functions which format the message string according to fmt and the argument list. These functions allocate memory for the error strings. They return a negative errno-like value on failure (e.g. -ENOMEM for memory allocation failure), and 0 on success.

sd_bus_error_set_const() is similar to sd_bus_error_setf(), but takes string literals for the error name and message. The strings are not copied, and no memory is allocated. This is useful for setting well-known errors.

sd_bus_error_set_errno(), sd_bus_error_set_errnof(), and sd_bus_error_set_errnofv() are similar to the functions above, but they also take an integer errnum, which is stored as the error name. This is useful for setting errors that correspond to standard errno values. The functions return 0 on success, and a negative errno-like value on failure. If errnum is 0, the error is considered unset and 0 is returned.

sd_bus_error_get_errno() returns the integer value of the error name if it was set using one of the sd_bus_error_set_errno*() functions, or if the D-Bus error name can be mapped to an errno value. Otherwise, it returns 0. This function returns false if error is NULL.

sd_bus_error_copy() copies the error information from src to dst. If dst already contains an error, it is freed first. If src is unset, dst is unset. Otherwise, memory is allocated for the error strings in dst. Returns a negative errno-like value on failure (e.g. -ENOMEM). Returns 0 if the source error is not set.

sd_bus_error_move() is similar to sd_bus_error_copy(), but will move any error information from e into dst, resetting the former. This function cannot fail, as no new memory is allocated. Note that if e is not set, dst is initialized to SD_BUS_ERROR_NULL. Moreover, if dst is NULL no operation is executed on it and resources held by e are freed and reset. Returns a converted errno-like, non-positive error value.

sd_bus_error_is_set() will return a non-zero value if e is non-NULL and an error has been set, false otherwise.

sd_bus_error_has_name() will return a non-zero value if e is non-NULL and an error with the same name has been set, false otherwise.

sd_bus_error_has_names_sentinel() is similar to sd_bus_error_has_name(), but takes multiple names to check against. The list must be terminated with NULL. sd_bus_error_has_names() is a macro wrapper around sd_bus_error_has_names_sentinel() that adds the NULL sentinel automatically.

sd_bus_error_free() will destroy resources held by e. The parameter itself will not be deallocated, and must be free(3)d by the caller if necessary. The function may also be called safely on unset errors (error structures with both fields set to NULL), in which case it performs no operation. This call will reset the error structure after freeing the data, so that all fields are set to NULL. The structure may be reused afterwards.

REFERENCE OWNERSHIP

sd_bus_error is not reference-counted. Users should destroy resources held by it by calling sd_bus_error_free(). Usually, error structures are allocated on the stack or passed in as function parameters, but they may also be allocated dynamically, in which case it is the duty of the caller to free(3) the memory held by the structure itself after freeing its contents with sd_bus_error_free().

RETURN VALUE

The functions sd_bus_error_set(), sd_bus_error_setf(), and sd_bus_error_set_const() always return 0 when the specified error value is NULL, and a negative errno-like value corresponding to the name parameter otherwise. The functions sd_bus_error_set_errno(), sd_bus_error_set_errnof() and sd_bus_error_set_errnofv(), return 0 when the specified error value is 0, and a negative errno-like value corresponding to the error parameter otherwise. If an error occurs internally, one of the negative error values listed below will be returned. This allows those functions to be conveniently used in a return statement, see the example below.

sd_bus_error_get_errno() returns false when e is NULL, and a positive errno value mapped from e->name otherwise.

sd_bus_error_copy() and sd_bus_error_move() return a negative error value converted from the source error, and zero if the error has not been set. This allows those functions to be conveniently used in a return statement, see the example below.

sd_bus_error_is_set() returns a non-zero value when e and the name field are non-NULL, zero otherwise.

sd_bus_error_has_name(), sd_bus_error_has_names(), and sd_bus_error_has_names_sentinel() return a non-zero value when e is non-NULL and the name field is equal to one of the given names, zero otherwise.

Errors

Return value may indicate the following problems in the invocation of the function itself:

-EINVAL

Error was already set in the sd_bus_error structure when one the error-setting functions was called.

-ENOMEM

Memory allocation failed.

On success, sd_bus_error_set(), sd_bus_error_setf(), sd_bus_error_set_const(), sd_bus_error_set_errno(), sd_bus_error_set_errnof(), sd_bus_error_set_errnofv(), sd_bus_error_copy(), and sd_bus_error_move() will return a negative converted errno-style value, or 0 if the error parameter is NULL or unset. D-Bus errors are converted to the integral errno-style value, and the mapping mechanism is extensible, see the discussion above. This effectively means that almost any negative errno-style value can be returned.

EXAMPLES

Example 1. Using the negative return value to propagate an error

/* SPDX-License-Identifier: MIT-0 */
#include <errno.h>
#include <string.h>
#include <unistd.h>
#include <systemd/sd-bus.h>
int writer_with_negative_errno_return(int fd, sd_bus_error *error) {
  const char *message = "Hello, World!\n";
  ssize_t n = write(fd, message, strlen(message));
  if (n >= 0)
    return n; /* On success, return the number of bytes written, possibly 0. */
  /* On error, initialize the error structure, and also propagate the errno
   * value that write(2) set for us. */
  return sd_bus_error_set_errnof(error, errno, "Failed to write to fd %i: %s", fd, strerror(errno));
}

NOTES

Functions described here are available as a shared library, which can be compiled against and linked to with the libsystemd pkg-config(1) file.

The code described here uses getenv(3), which is declared to be not multi-thread-safe. This means that the code calling the functions described here must not call setenv(3) from a parallel thread. It is recommended to only do calls to setenv() from an early phase of the program when no other threads have been started.
