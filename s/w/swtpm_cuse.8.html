swtpm_cuse(8)

الحزمة: swtpm

التراخيص: BSD-3-Clause

اختر وظيفة TPM 2؛ افتراضيًا، يتم اختيار TPM 1.2.
--log [fd=<fd>|file=<path>][,level=<n>] [,prefix=<prefix>][,truncate]
تمكين التسجيل في ملف بالمعرّف أو المسار الخاص به. استخدم '-' للمسار لكتم التسجيل.

يسمح المعامل level للمستخدم باختيار مستوى التسجيل. بدءًا من مستوى التسجيل 5، يتم تنشيط تسجيل تصحيح الأخطاء libtpms.

ستتم إضافة البادئة prefix إلى جميع الأسطر المسجلة. افتراضيًا، لا يتم إضافة أي بادئة.

إذا تم تمرير truncate، فسيتم اقتطاع ملف السجل.

--locality reject-locality-4[,allow-set-locality]
سيؤدي المعامل reject-locality-4 إلى إرجاع رسائل خطأ TPM للطلبات لتعيين TPM إلى locality 4.

يسمح المعامل allow-set-locality لـ swtpm بتلقي أوامر TPM/TPM2_SetLocality. هذا المعامل مفيد إذا تم تمكين الوصول إلى برنامج تشغيل وكيل VTPM الخاص بنظام Linux عن طريق تمرير واصف الملف. يتم تضمين هذا الخيار بواسطة الخيار --vtpm-proxy، وبالتالي لا يلزم تعيينه بشكل صريح إذا تم تمرير هذا الخيار. في جميع الحالات الأخرى، يجب توخي الحذر بشأن من يمكنه إرسال أمر TPM/TPM2_SetLocality.

--key file=<keyfile>|fd=<fd> [,format=<hex|binary>][,mode=aes-cbc|aes-256-cbc], [remove[=true|false]]
تمكين تشفير ملفات حالة TPM. يجب أن يحتوي ملف المفتاح على مفتاح AES بحجم مدعوم؛ يتم دعم مفاتيح 128 بت (16 بايت) و 256 بت (32 بايت).

قد يكون المفتاح بتنسيق ثنائي، وفي هذه الحالة يجب أن يكون حجم الملف 16 أو 32 بايت. إذا كان المفتاح بتنسيق سداسي عشري (افتراضي)، فقد يتكون المفتاح من 32 أو 64 رقمًا سداسيًا عشريًا يبدأ بـ '0x' اختياري.

يشير المعامل mode إلى وضع ربط الكتلة الذي يجب استخدامه. حاليًا، يتم دعم aes-cbc (aes-128-cbc) و aes-256-cbc. يتم حماية البيانات المشفرة باستخدام encrypt-then-mac.

سيحاول المعامل remove إزالة ملف المفتاح المحدد بمجرد قراءة المفتاح.

--key pwdfile=<passphrase file>|pwdfd=<fd> [,mode=aes-cbc|aes-256-cbc][remove[=true|false]][,kdf=sha512|pbkdf2]
يسمح هذا المتغير من معامل المفتاح للمستخدم بتوفير عبارة مرور في ملف. يتم قراءة الملف ويتم اشتقاق مفتاح منه باستخدام إما تجزئة SHA512 أو PBKDF2. افتراضيًا، يتم استخدام PBKDF2.
--migration-key file=<keyfile>|fd=<fd> [,format=<hex|binary>][,mode=aes-cbc|aes-256-cbc] [,remove[=true|false]]
يضمن توفر مفتاح الترحيل عدم الكشف عن حالة TPM في شكل غير مشفر عند استرداد مصفوفات حالة TPM من خلال واجهة ioctl. لا يستخدم مفتاح الترحيل لتشفير حالة TPM المكتوبة في الملفات، وهذا هو ما يستخدمه المعامل --key.

قد يكون مفتاح الترحيل والمفتاح المستخدم لتشفير ملفات حالة TPM هو نفسه.

بينما يحتاج المفتاح الخاص بملفات حالة TPM إلى البقاء مع تلك الملفات التي يقوم بتشفيرها، يحتاج مفتاح الترحيل إلى البقاء مع مصفوفات حالة TPM. إذا، على سبيل المثال، تم ترحيل حالة TPM بين المضيفين في مركز بيانات، فيجب أن يكون مفتاح ترحيل TPM متاحًا في جميع الوجهات، لذا فقد يكون في الواقع مفتاحًا مشتركًا عبر جميع الأجهزة في مركز البيانات. على النقيض من ذلك، يمكن أن يكون المفتاح المستخدم لتشفير ملفات حالة TPM مختلفًا لكل TPM ولا يحتاج إلا إلى أن يكون متاحًا على المضيف حيث توجد حالة TPM.

يتيح مفتاح الترحيل تشفير مصفوفات حالة TPM. يجب أن يحتوي ملف المفتاح على مفتاح AES بحجم مدعوم؛ يتم دعم مفاتيح 128 بت (16 بايت) و 256 بت (32 بايت).

قد يكون المفتاح بتنسيق ثنائي، وفي هذه الحالة يجب أن يكون حجم الملف 16 أو 32 بايت. إذا كان المفتاح بتنسيق سداسي عشري (افتراضي)، فقد يتكون المفتاح من 32 أو 64 رقمًا سداسيًا عشريًا يبدأ بـ '0x' اختياري.

يشير المعامل mode إلى وضع ربط الكتلة الذي يجب استخدامه. حاليًا، يتم دعم aes-cbc (aes-128-cbc) و aes-256-cbc. يتم حماية البيانات المشفرة باستخدام encrypt-then-mac.

سيحاول المعامل remove إزالة ملف المفتاح المحدد بمجرد قراءة المفتاح.

--migration-key pwdfile=<passphrase file>|pwdfd=<fd> [,mode=aes-cbc|aes-256-cbc][,remove[=true|false]][,pdf=sha512|pbkdf2]
يسمح هذا المتغير من معامل المفتاح للمستخدم بتوفير عبارة مرور في ملف. يتم قراءة الملف ويتم اشتقاق مفتاح منه باستخدام إما تجزئة SHA512 أو PBKDF2. افتراضيًا، يتم استخدام PBKDF2.
--pid file=<pidfile>|fd=<filedescriptor>
تسمح هذه الخيارات للمستخدم بتعيين اسم الملف الذي سيتم فيه كتابة معرف العملية (pid) الخاص بـ TPM. من الممكن أيضًا تمرير واصف ملف إلى ملف تم فتحه للكتابة.
-r|--runas <owner>
التبديل إلى المستخدم المحدد. يمكن استخدام هذا الخيار فقط عند بدء swtpm بصلاحيات الجذر.
-R|--chroot <path<gt>
تغيير الدليل الجذر إلى الدليل المحدد عند بدء التشغيل. يمكن استخدام هذا الخيار فقط عند بدء swtpm بصلاحيات الجذر.
--seccomp action=none|log|kill (منذ v0.2)
تسمح هذه الخيارات للمستخدم بتحديد الإجراء الذي سيتم اتخاذه بواسطة ملف تعريف seccomp عند تنفيذ استدعاء نظام غير مسموح به. الافتراضي هو kill. لتعطيل ملف تعريف seccomp، اختر none. يقوم الإجراء log بتسجيل استدعاءات النظام المخالفة. الإجراء log متاح فقط إذا كان libseccomp يدعم التسجيل.

هذا الخيار متاح فقط على نظام Linux وفقط إذا تم تجميع swtpm مع دعم libseccomp.

--flags [not-need-init][,startup-clear|startup-state|startup-deactivated|startup-none][,disable-auto-shutdown]
يُمكّن العلامة not-need-init TPM من قبول أوامر TPM مباشرة بعد البدء دون الحاجة إلى إرسال INIT إليها عبر قناة الأوامر (انظر الخيار '-i' لـ swtpm_ioctl).

تؤدي خيارات startup إلى إرسال أمر TPM_Startup أو TPM2_Startup تلقائيًا. الخيار startup-deactivated صالح فقط لـ TPM 1.2. هذه الخيارات تتضمن not-need-init، باستثناء الخيار startup-none، الذي ينتج عنه عدم إرسال أي أمر.

إذا تم استخدام --vtpm-proxy، فسيتم اختيار startup-clear تلقائيًا ولكن يمكن تغيير هذا باستخدام هذا الخيار.

تمنع العلامة disable-auto-shutdown swtpm من إرسال TPM2_Shutdown() تلقائيًا قبل إعادة تعيين TPM 2 أو قبل إنهاء عملية swtpm. عندما لا يتم توفير هذه العلامة، سيرسل swtpm هذا الأمر لتجنب زيادة عداد قفل هجوم القاموس (DA) وفي النهاية قفل DA بواسطة TPM 2 بسبب إغفال إرسال TPM2_Shutdown() مطلوب قبل إعادة تعيين TPM 2 أو إنهاء عملية swtpm.

The only profile that a user may modify is the 'custom' profile. Here a user may choose to disable algorithms, commands, and attributes that are allowed to be disabled. To avoid failing TPM 2 applications, care must be taken that none of them relies on disabled commands or algorithms.

--print-profiles (since v0.10)
Display the profiles supported by libtpms. Use with --tpm2 option.
--print-info (since v0.10)
Display information about the TPM from libtpms TPMLIB_GetInfo call and exit. Use the --tpm2 option for information about TPM 2. If the --tpmstate option is also provided then the output will show information about the profile as well. Note that with this option a TPM state may be created if none existed before.

The following values can be provided. All of the values can be or'ed (or added) together to get information about all of them in one query.

  • 0x1: information about the specification the TPM implementation followed
  • 0x2: information about the manufacturer, model and version of the TPM
  • 0x4: lists supported RSA and Camellia key sizes
  • 0x8: describes supported and enabled algorithms
  • 0x10: describes supported and enabled commands
  • 0x20: describes the active profile
  • 0x40: lists all built-in profiles
  • 0x80: describes supported attributes
-h|--help
Display usage info.

NOTES

If a TPM 2 is used, the user is typically required to send a TPM2_Shutdown() command to a TPM 2 to avoid possibly increasing the TPM_PT_LOCKOUT_COUNTER that may lead to a dictionary attack (DA) lockout upon next startup (TPM2_Startup()) of the TPM 2. Whether the TPM_PT_LOCKOUT_COUNTER is increased depends on previous commands sent to the TPM 2 as well as internal state of the TPM 2. One example that will trigger the counter to increase is the omission of a password when trying to access a password-protected object or NVRAM location that has the DA attribute set, followed by termination of swtpm without sending TPM2_Shutdown(). To avoid a DA lockout swtpm will make a best-effort and send a TPM2_Shutdown(SU_STATE) or TPM2_Shutdown(SU_CLEAR) if found necessary.
