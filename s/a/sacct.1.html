-P, --parsable2
سيكون الإخراج مفصولاً بـ '|' بدون '|' في النهاية. انظر أيضًا خيار --delimiter.
-r, --partition
قائمة مفصولة بفواصل للأقسام لاختيار المهام وخطوات المهام منها. الافتراضي هو جميع الأقسام.
-q, --qos
إرسال البيانات فقط حول المهام التي تستخدم هذه الأنظمة النوعية (qos). الافتراضي هو الكل.
-R, --reason=<reason_list>
قائمة مفصولة بفواصل لتصفية المهام بناءً على سبب عدم جدولة المهمة خارج الموارد/الأولوية.
-S, --starttime
تحديد المهام في أي حالة بعد الوقت المحدد. الافتراضي هو 00:00:00 من اليوم الحالي، ما لم يتم استخدام الخيارات '-s' أو '-j'. إذا تم استخدام الخيار '-s'، فإن الافتراضي هو 'الآن'. إذا تم تحديد الحالات مع الخيار '-s'، فسيتم إرجاع المهام في هذه الحالة فقط في هذا الوقت. إذا تم استخدام الخيار '-j'، فإن وقت الافتراضي هو Unix Epoch 0. انظر قسم نافذة الوقت الافتراضية (أدناه) للحصول على تفاصيل حول كيفية تحديد القيم الافتراضية لـ --starttime و --endtime.

تنسيقات الوقت الصالحة هي:
HH:MM[:SS][AM|PM]
MMDD[YY][-HH:MM[:SS]]
MM.DD[.YY][-HH:MM[:SS]]
MM/DD[/YY][-HH:MM[:SS]]
YYYY-MM-DD[THH:MM[:SS]]
today, midnight, noon, elevenses (11 AM), fika (3 PM), teatime (4 PM)
now[{+|-}count[seconds(default)|minutes|hours|days|weeks]]

-s, --state=<state_list>
يحدد المهام بناءً على حالتها خلال الفترة الزمنية المعطاة. ما لم يتم تحديد خلاف ذلك، سيكون وقت البدء والانتهاء هو الوقت الحالي عند تحديد خيار --state، ويمكن عرض المهام قيد التشغيل حاليًا فقط. يجب تحديد وقت بدء و/أو وقت انتهاء لعرض معلومات حول المهام التي لا تعمل حاليًا. انظر قسم رموز حالة المهمة (أدناه) للحصول على قائمة بمحددات الحالة. يمكن تحديد أسماء حالات متعددة باستخدام فواصل. يمكن استخدام الشكل القصير أو الطويل لاسم الحالة (على سبيل المثال، CA أو CANCELLED) والاسم غير حساس لحالة الأحرف (أي أن ca و CA كلاهما يعملان).

ملاحظة: ملاحظة لكي يتم تحديد مهمة في حالة الانتظار (PENDING)، يجب أن يكون لديها "EligibleTime" في فترة الوقت المطلوبة أو مختلفة عن "Unknown". يتم عرض "EligibleTime" بواسطة الأمر "scontrol show job". على سبيل المثال، المهام المقدمة مع الخيار "--hold" سيكون لديها "EligibleTime=Unknown" نظرًا لأنها معلقة إلى أجل غير مسمى.

ملاحظة: عند تحديد الحالات وعدم تحديد وقت بدء، يكون وقت البدء الافتراضي هو 'الآن'. هذا فقط عندما لا يتم استخدام -j. إذا تم استخدام -j، فسيكون وقت البدء الافتراضي هو 'Epoch'. في كلتا الحالتين، إذا لم يتم تحديد وقت انتهاء، فسيكون الافتراضي هو 'الآن'. انظر قسم نافذة الوقت الافتراضية (أدناه) للحصول على تفاصيل حول كيفية تغيير هذا الخيار للقيم الافتراضية لـ --starttime و --endtime.

-K, --timelimit-max
يتم تجاهله بمفرده، ولكن إذا تم تعيين timelimit_min، فسيكون هذا هو الحد الأقصى لوقت الحد. الافتراضي هو عدم وجود قيود.
-k, --timelimit-min
إرسال البيانات فقط حول المهام التي لها هذا الحد الزمني. إذا تم استخدامه مع timelimit_max، فسيكون هذا هو الحد الأدنى لوقت الحد. الافتراضي هو عدم وجود قيود.
-T, --truncate
قص الوقت. لذلك، إذا بدأت المهمة قبل --starttime، فسيتم قص وقت البدء إلى --starttime. نفس الشيء لوقت الانتهاء و --endtime.
-u, --uid=, --user=<uid_or_user_list>
استخدم هذه القائمة المفصولة بفواصل لمعرفات المستخدم (UIDs) أو أسماء المستخدمين لتحديد المهام لعرضها. افتراضيًا، يتم استخدام UID للمستخدم الحالي.
--units=[KMGTP]
عرض القيم بالوحدة المحددة. له الأسبقية على خيار --noconvert.
--usage
عرض ملخص لاستخدام الأوامر.
--use-local-uid
عند عرض UID، يستخدم sacct معرف المستخدم (UID) المخزن في قاعدة بيانات محاسبة Slurm افتراضيًا. استخدم هذا الأمر لجعل Slurm يستخدم استدعاء نظام للحصول على UID من اسم المستخدم. قد يكون هذا الخيار مفيدًا في بيئة بها عدة مجموعات (clusters) وقاعدة بيانات واحدة حيث لا تكون معرفات المستخدم (UIDs) متماثلة على جميع المجموعات.
-v, --verbose
بشكل أساسي لأغراض تصحيح الأخطاء، أبلغ عن حالة المتغيرات المختلفة أثناء المعالجة.
-V, --version
طباعة الإصدار.
-W, --wckeys=<wckey_list>
يعرض الإحصائيات فقط للمهام التي بدأت على مفاتيح wckeys المحددة بواسطة المعامل wckey_list، وهو قائمة مفصولة بفواصل بأسماء مفاتيح wckey. لا يُسمح بمسافات في wckey_list. الافتراضي هو جميع مفاتيح wckeys.
--whole-hetjob[=yes|no]
عند الاستعلام وتصفية المهام غير المتجانسة (heterogeneous jobs) باستخدام --jobs، سيقوم Slurm افتراضيًا باسترداد معلومات حول جميع مكونات المهمة إذا تم تحديد معرف المهمة غير المتجانسة (معرف القائد). إذا تم تحديد مكون مهمة غير متجانسة غير قائد، فسيتم استرداد هذا المكون فقط افتراضيًا. يمكن تغيير هذا السلوك باستخدام هذا الخيار. إذا تم تعيينه إلى 'yes' (أو بدون معامل)، فسيتم استرداد معلومات حول جميع المكونات بغض النظر عن المكون المحدد في تصفية المهمة. إذا تم تعيينه إلى 'no'، فسيتم استرداد مكون (مكونات) المهمة غير المتجانسة المحددة فقط، حتى عند تحديد القائد.
--yaml, --yaml=list, --yaml=<data_parser>
تفريغ معلومات المهمة بتنسيق YAML باستخدام المكون الإضافي الافتراضي data_parser أو data_parser محدد مع معلمات. سيتم تجاهل وسيطات الفرز والتنسيق.

حقول محاسبة المهام

يمكن العثور على أوصاف لكل خيار من خيارات الحقول أدناه. لاحظ أن حقول المحاسبة Ave* و Max* و Min* تنظر إلى القيم لجميع المهام لكل خطوة في المهمة وتعيد متوسط أو أقصى أو أدنى قيم للمهمة لتلك الخطوة. على سبيل المثال، بالنسبة لـ MaxRSS، فإن القيمة المعادة هي أقصى استهلاك للذاكرة الذي شوهد بواسطة إحدى مهام الخطوة، و MaxRSSTask يوضح المهمة التي كانت عليها.

OPTIONS

The following options are available for sacct:

-A, --acctg-freq
Sort order for accounting information. The default is acct. The available options are acct, job, user, and account.
-a, --all
Show all accounting information. This is the default.
--batch-proctrack=type
Type of proctrack used for the job. This option is valid only if the system has been configured to use more than one proctrack type. The available options are configured by the system administrator.
-c, --contiguous
A list of jobs that were run in contiguous chunks of time. It has the effect of merging jobs that were run multiple times.
--data-access-max
Maximum TRES (Total Resource) usage by the job. This option is only valid when TRES is enabled. See TRES column for more info.
--data-access-min
Minimum TRES (Total Resource) usage by the job. This option is only valid when TRES is enabled. See TRES column for more info.
--data-access-tot
Total TRES (Total Resource) usage by the job. This option is only valid when TRES is enabled. See TRES column for more info.
--data-size-max
Maximum TRES (Total Resource) usage by the job. This option is only valid when TRES is enabled. See TRES column for more info.
--data-size-min
Minimum TRES (Total Resource) usage by the job. This option is only valid when TRES is enabled. See TRES column for more info.
--data-size-tot
Total TRES (Total Resource) usage by the job. This option is only valid when TRES is enabled. See TRES column for more info.
-E, --end
End time for the jobs to be displayed. The time can be specified in various formats. Default format is YYYY-MM-DDTHH:MM:SS.
-F, --format
User specified the format of the sacct command output. This option can be used to select which fields are printed for each job and in what order. The format can be specified as a comma separated list of comma-separated values. The default format is job,user,account,cl Antennes,partition,state,submit,start,end,res,timelimit,qos,trestrqtinave,trestrqtinmax,trestrqtinmin,trestrqtin%. See the FIELDS section for a list of available fields.
-s, --state
Filter jobs based on state. The list of states can be found in the JOB STATE CODES section below.
-h, --help
Print help information and exit.
-j, --job
Select jobs based on job ID. This option can be used multiple times to specify a list of job IDs.
--max-array-tasks
Maximum number of tasks in a job array.
--max-cpus
Maximum number of CPUs used by the job.
--max-mem
Maximum memory used by the job.
--max-nodes
Maximum number of nodes used by the job.
--max-submit-sec
Maximum number of seconds from the epoch time that the job was submitted.
--max-wall-clock
Maximum wall clock time used by the job.
--megabytes
Memory format in megabytes.
--no-shares
Do not include information about shares.
--no-summary
Do not include summary information.
--no-trunc
Do not truncate output.
-o, --only-jobid
Show only the jobid.
-p, --partition
Select jobs based on partition name. This option can be used multiple times to specify a list of partition names.
--processor-binding
The processor binding for the job.
-q, --qos
Select jobs based on Quality of Service (QOS) name. This option can be used multiple times to specify a list of QOS names.
-U, --user
Select jobs based on user name. This option can be used multiple times to specify a list of user names.
-S, --start
Start time for the jobs to be displayed. The time can be specified in various formats. Default format is YYYY-MM-DDTHH:MM:SS.
--summary-only
Show only summary information.
--test-only
Do not run any file transfers or execute any commands. Print the commands that would be executed.

This example shows how the -T option truncates the start and end times of jobs to the requested time window. Without -T (normal operation) sacct output would be like this.

# sacct -S2014-07-03-11:40 -E2014-07-03-12:00 -X -ojobid,start,end,state
                    JobID                 Start                  End        State
                --------- --------------------- -------------------- ------------
                2         2014-07-03T11:33:16   2014-07-03T11:59:01   COMPLETED
                3         2014-07-03T11:35:21   Unknown               RUNNING
                4         2014-07-03T11:35:21   2014-07-03T11:45:21   COMPLETED
                5         2014-07-03T11:41:01   Unknown               RUNNING

By adding the -T option the job's start and end times are truncated to reflect only the time requested. If a job started after the start time requested or finished before the end time requested those times are not altered. The -T option is useful when determining exact run times during any given period.

# sacct -T -S2014-07-03-11:40 -E2014-07-03-12:00 -X -ojobid,jobname,user,start,end,state
                    JobID                 Start                  End        State
                --------- --------------------- -------------------- ------------
                2         2014-07-03T11:40:00   2014-07-03T11:59:01   COMPLETED
                3         2014-07-03T11:40:00   2014-07-03T12:00:00   RUNNING
                4         2014-07-03T11:40:00   2014-07-03T11:45:21   COMPLETED
                5         2014-07-03T11:41:01   2014-07-03T12:00:00   RUNNING

NOTE: If no -s (--state) option is given sacct will display eligible jobs during the specified period of time, otherwise it will return jobs that were in the state requested during that period of time.

This example demonstrates the differences running sacct with and without the --state flag for the same time period. Without the --state option, all eligible jobs in that time period are shown.

# sacct -S11:20:00 -E11:25:00 -X -ojobid,start,end,state
                       JobID               Start                 End      State
                ------------ ------------------- ------------------- ----------
                2955                    11:15:12            11:20:12  COMPLETED
                2956                    11:20:13            11:25:13  COMPLETED

With the --state=pending option, only job 2956 will be shown because it had a dependency on 2955 and was still PENDING from 11:20:00 until it started at 11:21:13. Note that even though we requested PENDING jobs, the State shows as COMPLETED because that is the current State of the job.

# sacct --state=pending -S11:20:00 -E11:25:00 -X -ojobid,start,end,state
                       JobID               Start                 End      State
                ------------ ------------------- ------------------- ----------
                2956                    11:20:13            11:25:13  COMPLETED
