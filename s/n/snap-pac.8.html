SNAP-PAC(8) snap-pac SNAP-PAC(8)

الاسم

snap-pac - خطافات Pacman تستخدم snapper لإنشاء لقطات btrfs قبل وبعد مثل YaST في openSUSE

الوصف

نظرًا لأن هذه خطافات pacman، فلا يهم كيف تستدعي pacman - سواء كان ذلك مباشرة، أو من خلال مساعد AUR، أو باستخدام اسم مستعار - سيقوم snapper بإنشاء اللقطات عند تثبيت pacman أو ترقيته أو إزالته. يتم تسجيل أمر pacman المستخدم في وصف snapper للقطات. بالإضافة إلى ذلك، يتم إخراج أرقام اللقطات إلى الشاشة وإلى سجل pacman لكل تكوين snapper أثناء معاملة pacman، بحيث يمكن للمستخدم بسهولة العثور على التغييرات التي قد يرغب في التراجع عنها.

عند تشغيل pacman، يتم إنشاء لقطات snapper قبل/بعد تلقائيًا. للحصول على مثال أكمل، انظر مثال.

إذا كان لديك عطل شديد - مثل اختفاء snapper لسبب ما ولا يمكنك استعادته - فسيتعين عليك اللجوء إلى طرق أكثر تطرفًا، مثل أخذ لقطة من اللقطة السابقة وجعلها الحجم الفرعي الافتراضي أو تحميلها كـ /. على الأرجح ستحتاج إلى استخدام USB مباشر للدخول إلى بيئة chroot للقيام بأي من هذه الأشياء. يحتوي Snapper على ميزة snapper rollback، ولكن يجب تكوين إعدادك بشكل صحيح لاستخدامها. تعتمد الإجراءات الدقيقة على إعدادك المحدد. كن حذرًا.

لاحظ أن خطافات المعاملة السابقة تحدث قبل معاملة pacman ولكن بعد مزامنة قاعدة بيانات pacman، إذا كان ذلك قابلاً للتطبيق. بعبارة أخرى، إذا قمت بتشغيل pacman -Syu وتراجعت عن الترقية وفقًا للتعليمات أعلاه، فلن تكون قد تراجعت عن قاعدة بيانات pacman إلى الحالة السابقة. وبالتالي، إذا قمت، بعد الترقية والتراجع عن الترقية، بتثبيت حزمة، فقد تكون ترقية جزئية، وهو أمر غير مدعوم.

التثبيت

قم بتثبيت حزمة snap-pac باستخدام pacman:

gpg --verify snap-pac-<version>.tar.gz.sig

حيث <version> هو رقم الإصدار الذي قمت بتنزيله.

أخيرًا، قم بتشغيل:

make install

لقد قمت بتوقيع الأرشيف الإصدار والالتزامات باستخدام مفتاح PGP الخاص بي. ابتداءً من الإصدار 2.2، تم توقيع الأرشيفات باستخدام مفتاحي ذي بصمة F7B28C61944FE30DABEEB0B01070BCC98C18BD66.

للإصدارات السابقة، كانت بصمة المفتاح 8535CEF3F3C38EE69555BF67E4B5E45AA3B8C5C3.

التبعيات

python، pacman، و snapper مطلوبة جميعًا.

الاختبار

للاختبار، يلزم pytest. لتشغيل الاختبارات قم بما يلي:

man 8 snap-pac

لبناء التوثيق، يلزم sphinx. لبناء التوثيق يمكنك القيام بما يلي:

make docs

سيتم بعد ذلك وضع توثيق html الناتج في docs/build/index.html. بالإضافة إلى ذلك، يقوم هذا بإنشاء صفحة الدليل التي ستكون موجودة تحت man8.

الإعداد

يتم الإعداد عبر ملفات تكوين Python ini. يجب أن تكون الإعدادات الافتراضية مناسبة لمعظم المستخدمين، لذلك قد لا تحتاج إلى إجراء أي إعداد على الإطلاق. افتراضيًا، يتم أخذ لقطات لتكوين root فقط.

يوجد ملف تكوين مثال مع تعليقات في /etc/snap-pac.ini.

حرره باستخدام محرر النصوص المفضل لديك. الملف معلق ويجب أن يكون واضحًا بذاته.

كل قسم يتوافق مع تكوين snapper. أضف أقسامًا إضافية لإضافة تكوينات snapper أخرى ليتم أخذ لقطات لها. افتراضيًا، يتم أخذ لقطات لتكوين root فقط. بالإضافة إلى ذلك، يمكنك إضافة قسم يسمى DEFAULT مع خيارات تنطبق على جميع تكوينات snapper ما لم يتم تجاوزها في قسم لاحق.

يمكن أن يحتوي كل قسم على الإدخالات التالية:

  • desc_limit - عدد صحيح؛ الحد الأقصى لطول سلسلة الوصف قبل اقتطاعها. الافتراضي: 72
  • important_packages - قائمة من السلاسل النصية؛ أسماء الحزم التي إذا تم تضمينها في معاملة pacman ستضيف important=yes إلى بيانات المستخدم لـ snapper لمجموعة اللقطات. الافتراضي: []
  • important_commands - قائمة من السلاسل النصية؛ الأوامر الأصلية التي ستضيف important=yes إلى بيانات المستخدم لـ snapper لمجموعة اللقطات. الافتراضي: []
  • pre_description - سلسلة نصية؛ وصف للقطة السابقة. الافتراضي: الأمر الأصلي الذي استدعى خطاف pacman.
  • post_description - سلسلة نصية؛ وصف للقطة اللاحقة. الافتراضي: قائمة مفصولة بمسافات للحزم التي تم تثبيتها أو ترقيتها أو إزالتها.
  • snapshot - قيمة منطقية؛ ما إذا كان سيتم أخذ لقطة للتكوين أم لا. الافتراضي: True لتكوين root؛ False بخلاف ذلك.
  • userdata - قائمة من السلاسل النصية؛ أزواج المفتاح والقيمة التي ستتم إضافتها إلى بيانات المستخدم لمجموعة اللقطات. الافتراضي: []

أمثلة

إيقاف تشغيل اللقطات لتكوين root وتشغيلها لتكوين home:

[root]
snapshot = False
[home]
snapshot = True

[root]
important_commands = ["pacman -Syu"]

[root]
important_packages = ["linux", "linux-lts"]

snap-pac(8) — Arch Linux manual pages

NAME

snap-pac — snapper hooks for pacman

DESCRIPTION

snap-pac is a set of pacman hooks that leverage the snapper framework to automatically create snapshots before and after package transactions.

INSTALLATION

Install the snap-pac package from the Arch User Repository (AUR).

You will need to have snapper and btrfs-progs installed and configured, and your root filesystem mounted as btrfs. See the Arch Wiki for details on setting up snapper.

CONFIGURATION

snap-pac configuration is managed through the snapper configuration files. By default, snap-pac will create snapshots for the root configuration. You can customize this behavior by creating or modifying snapper configuration files in /etc/snapper/configs/.

For example, to mark snapshots as important when linux or linux-lts packages are installed, and also when full system upgrades are performed, you can add the following to your /etc/snapper/configs/root file:

The root configuration will have important=yes when linux and linux-lts packages are part of the transaction. Additionally when full system upgrades are performed root snapshots will be marked important=yes. Note that you don't have to add snapshot = True for the root configuration since that is the default.

This file also turns one snapshots for the home snapper configuration and adds the userdata requestid=42,user=arthur to all snapshots for that configuration. Additionally he post snapshot description is overridden.

[root]
important_packages = ["linux", "linux-lts"]
important_commands = ["pacman -Syu"]
[home]
snapshot = True
userdata = ["requestid=42", "user=arthur"]
post_description = "pacman transaction post snapshot"

ENVIRONMENT VARIABLES

To temporarily prevent snapshots from being performed for a single pacman command, set the environment variable SNAP_PAC_SKIP. For example:

sudo SNAP_PAC_SKIP=y pacman -Syu

EXAMPLE

Here is an example of how the snapshots are created and how to rollback and pacman transaction. Here the nano package is installed:

(1/1) checking for file conflicts                            [######################################] 100%

The snapper snapshot number is given for each snapper configuration that is used. This is also logged in pacman's log.

Here are the snapshots created before and after the pacman transaction:

snapper -c root list -t pre-post | tail -n 1
1033  | 1034   | Fri 22 Apr 2016 01:54:13 PM CDT | Fri 22 Apr 2016 01:54:14 PM CDT | pacman -S nano      |

TROUBLESHOOTING

snap-pac is only taking snapshots of the root configuration.

That's the default behavior. See Configuration.

No snapshots are being taken when I run pacman.

No snapper configurations are set up for snap-pac's pacman hooks. By default snap-pac will take snapshots for the root configuration and any other configuration which has SNAPSHOT set to yes in its configuration file. See Configuration.

After restoring snapshot from snap-pac, the pacman database is locked.

FAQ

Does snap-pac backup non-btrfs /boot partitions?

No, but you can add a hook that does it for you. It would be something like the following:

[Trigger]
Operation = Upgrade
Operation = Install
Operation = Remove
Type = Package
Target = linux
[Action]
Description = Backing up /boot...
When = PreTransaction
Exec = /usr/bin/rsync -avzq --delete /boot /.bootbackup

Note that you will probably want to name the file with a numbered prefix less than 05 so that it is run before the snap-pac pre snapshot takes place. That will ensure that the snapshot taken will have the boot partition back-up corresponding with the state of the system. For example, you could name it 04-backupboot.hook.

How do I link old kernel modules automatically when the kernel is upgraded?

This behavior is no longer a part of this package. Use a pacman hook like the following:

[Trigger]
Operation = Upgrade
Operation = Install
Operation = Remove
Type = Package
Target = linux
[Action]
Description = Symlinking old kernel modules...
When = PostTransaction
Exec = /usr/bin/bash -c "find /usr/lib/modules -xtype l -delete; ln -sv /.snapshots/$(snapper -c root list | awk 'END{print $1}')/snapshot/usr/lib/modules/$(uname -r) /usr/lib/modules/"
