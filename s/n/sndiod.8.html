الاسم

sndiod — خادم الصوت/MIDI

الملخص

sndiod [-d] [-a علامة] [-b إطارات] [-C الحد الأدنى:الحد الأقصى] [-c الحد الأدنى:الحد الأقصى] [-e تشفير] [-F جهاز] [-f جهاز] [-j علامة] [-L عنوان] [-m وضع] [-Q منفذ] [-q منفذ] [-r معدل] [-s اسم] [-t وضع] [-U وحدة] [-v مستوى الصوت] [-w علامة] [-z إطارات]

الوصف

الخدمة sndiod هي طبقة وسيطة بين برامج الصوت أو MIDI والأجهزة. تقوم بمعالجة الصوت اللازمة للسماح لأي برنامج بالعمل على أي جهاز مدعوم. افتراضيًا، تقبل sndiod الاتصالات من البرامج التي تعمل على نفس النظام فقط؛ يتم تهيئتها فقط عندما تستخدم البرامج خدماتها، مما يسمح لـ sndiod باستهلاك كمية ضئيلة من موارد النظام في بقية الوقت. يمكن للأنظمة التي لا تحتوي على أجهزة صوت استخدام sndiod للحفاظ على قابلية الأجهزة القابلة للتبديل السريع قابلة للاستخدام افتراضيًا بتكلفة شبه معدومة.

sndiod تعمل على النحو التالي: تعرض جهازًا فرعيًا واحدًا على الأقل يمكن لأي عدد من برامج الصوت الاتصال به واستخدامه كما لو كان جهاز صوت. أثناء التشغيل، تتلقى sndiod بيانات الصوت بشكل متزامن من جميع البرامج، وتخلطها وترسل النتيجة إلى جهاز الأجهزة. وبالمثل، أثناء التسجيل، تقوم بتكرار بيانات الصوت المسجلة من الجهاز وإرسالها إلى جميع البرامج. نظرًا لأن تدفق بيانات الصوت عبر عملية sndiod، فإن لديها الفرصة لمعالجة بيانات الصوت فورًا:

  • تغيير تشفير الصوت للتغلب على عدم التوافق بين البرامج والأجهزة.
  • توجيه الصوت من قناة إلى أخرى، أو دمج ستيريو أو تقسيم أحادي.
  • التحكم في مستوى صوت التشغيل لكل تطبيق بالإضافة إلى مستوى الصوت الرئيسي.
  • مراقبة الصوت الذي يتم تشغيله، مما يسمح لبرنامج بتسجيل ما تشغله البرامج الأخرى.

يتم تكوين المعالجة لكل جهاز فرعي، مما يعني أن صوت جميع البرامج المتصلة بنفس الجهاز الفرعي سيتم معالجته وفقًا لنفس التكوين. يمكن تعريف أجهزة فرعية متعددة، مما يسمح بتعايش تكوينات متعددة. يختار المستخدم التكوين الذي سيستخدمه برنامج معين عن طريق تحديد الجهاز الفرعي الذي يستخدمه البرنامج.

sndiod تعرض صناديق MIDI (محاور)، مما يسمح للبرامج بإرسال رسائل MIDI لبعضها البعض أو لمنافذ MIDI للأجهزة بطريقة موحدة.

أخيرًا، تعرض sndiod منفذ MIDI للتحكم يمكن استخدامه من أجل:

  • التحكم في مستوى الصوت.
  • مصدر ساعة مشترك لبرامج الصوت و MIDI.
  • بدء وإيقاف وإعادة ترتيب مجموعات برامج الصوت.

الخيارات هي كما يلي:

-a علامة
التحكم فيما إذا كانت sndiod تفتح جهاز الصوت أو منفذ MIDI فقط عند الحاجة أو تبقيه مفتوحًا طوال الوقت. إذا كانت العلامة on، فسيظل جهاز الصوت أو منفذ MIDI مفتوحًا طوال الوقت، مما يضمن عدم قدرة أي برنامج آخر على سرقته. إذا كانت العلامة off، فسيتم إغلاقه تلقائيًا، مما يسمح للبرامج الأخرى بالوصول المباشر إلى جهاز الصوت، أو فصل الجهاز. الافتراضي هو off.
-b إطارات
حجم المخزن المؤقت لجهاز الصوت بالإطارات. يتكون الإطار من عينة واحدة لكل قناة في التدفق. هذا هو عدد الإطارات التي سيتم تخزينها مؤقتًا قبل التشغيل، وبالتالي يتحكم في زمن استجابة التشغيل. الافتراضي هو 7680 أو ضعف حجم الكتلة (-z)، إذا تم تعيين حجم الكتلة.
-C الحد الأدنى:الحد الأقصى, -c الحد الأدنى:الحد الأقصى
نطاق أرقام القنوات لتسجيل وتشغيل الاتجاهات، على التوالي يسمح لأي عميل باستخدامه. هذا هو مجموعة فرعية من قنوات جهاز الصوت. الافتراضي هو 0:1، أي ستيريو.
-d
تمكين التصحيح إلى الخطأ القياسي، وعدم فصل الجهاز عن الوحدة التحكم. يمكن تحديده عدة مرات لزيادة تفصيل السجلات.
-e تشفير
محاولة تكوين الجهاز لاستخدام هذا التشفير. الافتراضي هو s16. تستخدم أسماء التشفير المخطط التالي: التوقيع (s أو u) متبوعًا بالدقة بالبت، ترتيب البايت (le أو be)، عدد البايتات لكل عينة، والمحاذاة (msb أو lsb). فقط التوقيع والدقة إلزاميان. أمثلة: u8، s16le، s24le3، s24le4lsb.
-F جهاز
نفس -f باستثناء أنه إذا تم فصل الجهاز، فسيتم استخدام الجهاز الذي تم توفيره مع الخيار السابق -f أو -F.
-f جهاز
أضف جهاز الصوت sndio(7) هذا إلى الأجهزة المستخدمة للتشغيل و/أو التسجيل. تنطبق الخيارات السابقة لكل جهاز (-aberwz) على هذا الجهاز. ستكون الأجهزة الفرعية (-s) التي يتم تطبيقها لاحقًا مرفقة بهذا الجهاز. يتم تحديد وضع الجهاز والمعلمات من الأجهزة الفرعية المرفقة به. إذا لم يتم استخدام خيار -f، فستستخدم sndiod rsnd/0، rsnd/1، ...، rsnd/3.
-j علامة
التحكم فيما إذا كانت قنوات البرامج منضمة أو موسعة إذا كان عدد القنوات المطلوبة من قبل برنامج لا يساوي عدد قنوات الجهاز. إذا كانت العلامة off، فسيتم توجيه قنوات العميل إلى قناة الجهاز المقابلة، مما قد يتجاهل القنوات غير الموجودة في الجهاز. إذا كانت العلامة on، فقد يتم إرسال قناة عميل واحدة على قنوات أجهزة متعددة، أو قد يتم إرسال قنوات عملاء متعددة إلى قناة جهاز واحدة. على سبيل المثال، يمكن استخدام هذه الميزة للتحويل من أحادي إلى ستيريو. الافتراضي هو on.
-L عنوان
حدد عنوان شبكة محلي يجب أن تستمع إليه sndiod؛ ستستمع sndiod على منفذ TCP 11025+n، حيث n هو رقم الوحدة المحدد باستخدام -U. بدون هذا الخيار، تستمع sndiod فقط على مقبس مجال UNIX، ولا يمكن الوصول إليها من أي شبكة. إذا كان وسيط الخيار هو ‘-’، فستقبل sndiod الاتصالات من أي عنوان. نظرًا لأن الاتصال غير آمن، فإن هذا الخيار مناسب فقط للشبكات المحلية.

NAME

sndiod

sound daemon

SYNOPSIS

sndiod [-f host[:port]] [-n host[:port]] [-u user] [-d device] [-s subdevice] [-c channel:rate] [-r rate] [-z size] [-b blocks] [-a off] [-v volume] [-i inactivity] [-P pause] [-D] [-p] [-L]

DESCRIPTION

The sndiod daemon is the server for the sndio(7) sound system. It opens the default audio device or a specified audio device, and provides a generic interface to the audio hardware.

The daemon can be configured to provide multiple sub-devices with different characteristics, like varying volumes or channel configurations. These sub-devices are exposed to clients as separate sound devices.

The server also implements MIDI control, hot-plugging of devices, and can be configured to adjust sample rates, block sizes, and buffer settings to optimize latency.

If the server is started with the -v option, it tries to discover and expose MIDI devices. These can be controlled by clients connected to the server.

If the server is started with the -p option, it enables hot-plugging support. This allows clients to be notified when new audio devices are connected or disconnected.

OPTIONS

-f host[:port]
Specifies the host and optional port for the server's listening socket. Defaults to /tmp/sndio.
-n host[:port]
Specifies the host and optional port for the server's network socket, allowing remote access. Defaults to /tmp/sndio for local access.
-u user
Run the server as the specified user after initialization. Defaults to nobody.
-d device
Use the specified audio device instead of the default. The format depends on the underlying audio driver.
-s subdevice
Create a sub-device with the given name. Multiple -s options can be used to create multiple sub-devices.
-c channel:rate
Set the number of channels and sample rate for the default sub-device. Example: 2:44100 for stereo at 44.1kHz.
-r rate
Set the default sample rate for all sub-devices.
-z size
Set the default block size (number of frames per block) for all sub-devices.
-b blocks
Set the default number of blocks in the audio buffer for all sub-devices. This, along with -r and -z, determines the latency.
-a off
Disable automatic opening of the audio hardware. The hardware will be opened on demand by clients.
-v volume
Set the default volume for a sub-device. This option can be used multiple times to set volumes for different sub-devices or to control specific parameters. The range is typically 0-127.
-i inactivity
Set the inactivity timeout in seconds. The audio device will be closed after this period of inactivity.
-P pause
Set the pause timeout in seconds. If the server is paused, the audio device will be closed after this period.
-D
Enable debugging output.
-p
Enable hot-plugging support for audio devices.
-L
List available audio devices and exit.

MIDI CONTROL

If started with the -v option (even if not controlling volume), sndiod attempts to discover and expose MIDI input and output devices. Clients can then use these devices through the sndio(7) interface.

HOT PLUGGING

When the -p option is specified, sndiod enables support for hot-plugging of audio devices. This allows clients to detect when audio devices are connected or disconnected from the system and react accordingly.

EXAMPLES

Start the server with the default audio device, creating two sub-devices named default and rear. The default sub-device will have 2 channels and a sample rate of 44100Hz. The rear sub-device will be created with default settings.

$ sndiod -c 2:44100 -s default -s rear

Start the server creating the default sub-device with low volume (65) and an additional sub-device for high volume output (127), exposing the snd/default and snd/max devices:

$ sndiod -v 65 -s default -v 127 -s max

Start the server configuring the audio device to use a 48kHz sample frequency, 240-frame block size, and 2-block buffers. The corresponding latency is 10ms, which is the time it takes the sound to propagate 3.5 meters.

$ sndiod -r 48000 -b 480 -z 240

SEE ALSO

sndio(7)

BUGS

Resampling is low quality; down-sampling especially should be avoided when recording.

If -a off is used, sndiod creates sub-devices to expose first and then opens the audio hardware on demand. Technically, this allows sndiod to attempt to use one of the sub-devices it exposes as an audio device, creating a deadlock. There's nothing to prevent the user from shooting themselves in the foot by creating such a deadlock.
