snmpusm(1)

الحزمة: net-snmp

التراخيص: BSD

NAME

snmpusm - SNMP USM user management

SYNOPSIS

snmpusm [SNMP-OPTIONS] IN-TYPE IN-TYPE-OPTIONS IN-NAME [IN-TYPE IN-TYPE-OPTIONS IN-NAME]

DESCRIPTION

The snmpusm command is used to manage the SNMPv3 User-based Security Model (USM) users.

OPTIONS

The snmpusm command accepts the standard SNMP command-line options (see snmpcmd(1) for details), as well as the following options:

IN-TYPE
This specifies the type of input for the user's authentication and privacy parameters. It can be one of the following:
passwd: The authentication and privacy parameters are given as clear text strings.
IN-TYPE-OPTIONS
This is an optional argument that can modify the behaviour of IN-TYPE. It is not used for passwd.
IN-NAME
This is the name of the user for whom the operations are to be performed.

The operation to be performed is determined by the command-line arguments that follow the IN-NAME argument.

-a AUTHALGO
Specify the authentication algorithm to use. Possible values are MD5 and SHA.
-A AUTHKEY
Specify the authentication key.
-c COMMUNITY
Specify the SNMPv1 community string.
-l AUTHLVL
Specify the SNMPv3 security level. Possible values are noAuthNoPriv, authNoPriv, and authPriv.
-n CONTEXT
Specify the SNMPv3 security context.
-u USER
Specify the SNMPv3 username.
-v VERSION
Specify the SNMP version (1, 2c, or 3).
-x PRIVPROTO
Specify the privacy protocol to use. Possible values are DES and AES.
-X PRIVKEY
Specify the privacy key.

CREATING USERS

To create a new user, you need to specify the authentication and privacy parameters for the user. The following command creates a new user named "testuser" with MD5 authentication and no privacy:

snmpusm -v 3 -u testuser -l authNoPriv -a MD5 -A testpass localhost passwd testpass

This command creates the user "testuser" with the authentication key "testpass". The passwd keyword indicates that the authentication key is provided as a clear text string.

DELETING USERS

To delete a user, you need to specify the username and the authentication parameters. The following command deletes the user "testuser":

snmpusm -v 3 -u testuser -l authNoPriv -a MD5 -A testpass localhost -S

The -S option indicates that the user should be deleted.

CHANGING PASS PHRASES

To change the pass phrase for a user, you need to specify the old and new pass phrases. The following command changes the pass phrase for the user "wes" from "setup_passphrase" to "new_passphrase":

snmpusm -v 3 -u wes -n "" -l authNoPriv -a MD5 -A setup_passphrase localhost passwd setup_passphrase new_passphrase

After creating the user "wes" with the same passphrase as the "initial" user, we need to change his passphrase for him. The above command changes it from "setup_passphrase", which was inherited from the initial user, to "new_passphrase".

EXAMPLES

The following example shows how to create a new user named "wes" with MD5 authentication and no privacy:

snmpusm -v 3 -u wes -l authNoPriv -a MD5 -A wespass localhost passwd wespass

The following example shows how to change the pass phrase for the user "wes":

snmpusm -v 3 -u wes -l authNoPriv -a MD5 -A setup_passphrase localhost passwd setup_passphrase new_passphrase

Test the new user

snmpget -v 3 -u wes -n "" -l authNoPriv -a MD5 -A new_passphrase localhost sysUpTime.0

If the above commands were successful, this command should have properly performed an authenticated SNMPv3 GET request to the agent.

Now, go remove the vacm "group" snmpd.conf entry for the "initial" user and you have a valid user 'wes' that you can use for future transactions instead of initial.

WARNING

Manipulating the usmUserTable using this command can only be done using SNMPv3. This command will not work with the community-based versions, even if they have write access to the table.
