SNMP::Session methods

$sess->update(<fields>)
يقوم بتحديث كائن SNMP::Session بقيم الإدخالات المستلمة كقائمة من الـ hash (مشابهة لـ new(<fields>)) (تحذير: غير مطبقة بالكامل)
$sess->get(<vars> [,<callback>])
يجري SNMP GET، يقبل تنسيقات متعددة من <vars>. للعمليات المتزامنة، سيتم تحديث <vars> بالقيم والأنواع التي تم الحصول عليها، وسيقوم بإرجاع القيم التي تم الحصول عليها أيضًا. إذا تم توفير دالة <callback>، فسيتم تنفيذها بشكل غير متزامن.
$sess->fget(<vars> [,<callback>])
يجري SNMP GET مثل 'get' ويشكل القيم بناءً على المعالجات المحددة في $sess->{VarFormats} و $sess->{TypeFormats}
$sess->getnext(<vars> [,<callback>])
يجري SNMP GETNEXT، يقبل تنسيقات متعددة من <vars>، ويعيد القيم التي تم الحصول عليها، ويقوم بتحديث <vars> للإشارة إلى المثيل التالي أبجديًا من <obj>، <iid>، <val> و <type>. ملاحظة: المتغيرات البسيطة (مثل 'sysDescr.0') لا يتم تحديثها. إذا تم توفير دالة <callback>، فسيتم تنفيذها بشكل غير متزامن.
$sess->fgetnext(<vars> [,<callback>])
يجري SNMP GETNEXT مثل getnext ويشكل القيم بناءً على المعالجات المحددة في $sess->{VarFormats} و $sess->{TypeFormats}
$sess->set(<vars> [,<callback>])
يجري SNMP SET، يقبل تنسيقات متعددة من <vars>. يجب أن يكون لجميع تنسيقات <vars> تنسيق معياري (أي، تنسيق معروف) لضمان ترجمة فريدة لقيم MIB. يعيد snmp_errno. إذا تم توفير دالة <callback>، فسيتم تنفيذها بشكل غير متزامن.
$sess->getbulk(<non-repeaters>, <max-repeaters>, <vars>)
يجري SNMP GETBULK، من قائمة Varbinds، يتم الحصول على المثيل التالي أبجديًا لأول n Varbinds وفقًا لـ <non-repeaters>. بالنسبة لـ Varbinds المتبقية، يتم استرداد m مثيلات أبجديًا لكل منها، حيث m هو <max-repeaters>.
$sess->bulkwalk(<non-repeaters>, <max-repeaters>, <vars> [,<callback>])
يجري "bulkwalk" لقائمة Varbinds. يتم إرسال GETBULK لكل Varbind مطلوب (انظر getbulk() أعلاه). لكل متغير مطلوب، يتم فحص الاستجابة لمعرفة ما إذا كان المثيل التالي أبجديًا قد خرج من الشجرة الفرعية المطلوبة. يتم تجاهل أي مثيلات أخرى تم إرجاعها لهذا المتغير، ويعتبر البحث في هذه الشجرة الفرعية مكتملًا.

إذا لم تكتمل أي شجرة فرعية في نهاية الاستجابات، يتم إنشاء طلب آخر، متوافق مع المتغيرات المتبقية. تتكرر هذه العملية حتى تكتمل جميع الأشجار الفرعية، أو يتم تبادل عدد كبير جدًا من الحزم (لتجنب الحلقات).

تعيد الدالة bulkwalk() مصفوفة تحتوي على مصفوفة من Varbinds، واحدة لكل متغير مطلوب، بترتيب طلبات المتغيرات. في حالة حدوث خطأ، تعيد bulkwalk() القيمة undef وتضبط $sess->ErrorStr و $sess->ErrorNum. إذا تم توفير دالة callback، تعيد bulkwalk() معرف طلب SNMP وتعمل فورًا. يتم استدعاء دالة callback مع قائمة الوسائط المقدمة وقائمة المتغيرات التي تم إرجاعها.

ملاحظة: نظرًا لأن العميل يجب عليه "اكتشاف" أن الشجرة مكتملة عن طريق مقارنة المتغيرات التي تم إرجاعها بتلك المطلوبة، هناك "مشكلة" عند استخدام قيمة max-repeaters. ضع في اعتبارك الكود التالي لطباعة قائمة بالواجهات وعدادات البايت:

$numInts = $sess->get('ifNumber.0');
($desc, $in, $out) = $sess->bulkwalk(0, $numInts,
              [['ifDescr'], ['ifInOctets'], ['ifOutOctets']]);
for $i (0..($numInts - 1)) {
    printf "Interface %4s: %s inOctets, %s outOctets\n",
              $$desc[$i]->val, $$in[$i]->val, $$out[$i]->val;
}

ينتج هذا الكود طلبين إلى الوكيل: الأول للحصول على قيم الواجهة، والثاني لاكتشاف أن جميع المعلومات كانت في الحزمة الأولى. لتجنب ذلك، استخدم '$numInts + 1' لقيمة max_repeaters. هذا يطلب من الوكيل تضمين متغير إضافي (غير مرتبط) يشير إلى نهاية الشجرة الفرعية، مما يسمح لـ bulkwalk() بتحديد أن الطلب مكتمل.

$results = $sess->gettable(<TABLE OID>, <OPTIONS>)
سيسترد جميع بيانات الجدول ويعيد مرجعًا إلى hash بالبيانات. ستكون قيمة كل إدخال مرجعًا آخر لبيانات صف معين. ستكون مفاتيح هذا الـ hash هي أسماء الأعمدة، والقيم ستكون البيانات.

مثال:

#!/usr/bin/perl
use SNMP;
use Data::Dumper;
my $s = new SNMP::Session(DestHost => 'localhost');
print Dumper($s->gettable('ifTable'));

في جهازي ينتج:

$VAR1 = {
          '6' => {
                   'ifMtu' => '1500',
                   'ifPhysAddress' => 'PV',
                   # ...
                   'ifInUnknownProtos' => '0'
                 },
          '4' => {
                   'ifMtu' => '1480',
                   'ifPhysAddress' => '',
                   # ...
                   'ifInUnknownProtos' => '0'
                 },
          # ...
         };

بشكل افتراضي، سيحاول استرداد البيانات بطريقة محسنة. سيتم طلب أعمدة متعددة في وقت واحد، وسيتم استخدام GETBULK إذا كان ذلك ممكنًا. يمكن تحديد بعض الخيارات عن طريق تمرير hash من الخيارات OPTIONS مع معلمات متنوعة:

noindexes => 1
يخبر الكود بعدم تحليل الفهارس ووضع النتائج في الـ hash الثاني. إذا كنت لا تحتاج إلى بيانات الفهرس، فسيكون هذا أسرع.
columns => [colname1, ...]
يحدد هذا الأعمدة التي سيتم جلبها. بشكل افتراضي، سيحاول جلب جميع الأعمدة المحددة في جدول MIB.
repeat => COUNT
هو عدد Varbinds التي سيتم طلبها لكل عمود عند استخدام معامل GETBULK. تقليل هذا القيمة يعني حزم أصغر، والتي يمكن أن تساعد في بعض الأنظمة. بشكل افتراضي، يتم حساب هذه القيمة ومحاولة تخمين كم يمكن أن يتسع فيه النتيجة بأكملها في 1000 بايت. هذا الحساب آمن جدًا، على الرغم من أنه قد يكون من المفيد تعديله عن طريق رفع أو خفض الرقم باستخدام هذا الخيار. في الشبكات ذات الجودة المنخفضة، تأكد من عدم تجزئة الحزم، وتقليل هذه القيمة قد يساعد.

%SNMP::MIB

قائمة مرتبطة للوصول إلى معلومات MIB المحللة. بعد تحميل MIB، تسمح هذه القائمة بالوصول إلى البيانات الوصفية المحللة لـ MIB (أي بنية MIB (أي المخطط)). ترجع القائمة مراجع مميزة لكائنات SNMP::MIB::NODE التي تمثل سمة MIB واحدة. يمكن جلب العقد باستخدام تنسيقات 'مفتاح' متعددة - الاسم الطرفي (مثل sysDescr) أو الاسم المؤهل بالكامل/جزئيًا (مثل system.sysDescr) أو OID الرقمي المؤهل بالكامل. يدعم كائن العقدة المُرجع المجالات التالية:

objectID
OID المؤهل بالكامل بشكل عشري منقط
label
معرّف نصي طرفي (مثل 'sysDescr')
subID
مكون OID الرقمي الطرفي لـ objectID (مثل '1')
moduleID
معرّف نصي للوحدة (مثل 'RFC1213-MIB')
parent
العقدة الأم
children
مرجع مصفوفة للعقد التابعة
nextNode
العقدة التالية أبجديًا (خطأ! لا ترجع بترتيب أبجدي)
type
ترجع نوع التطبيق (انظر getType للقيم)
access
ترجع ACCESS (ReadOnly, ReadWrite, WriteOnly, NoAccess, Notify, Create)
status
ترجع STATUS (Mandatory, Optional, Obsolete, Deprecated)
syntax
ترجع 'textualConvention' إذا تم تعريفه وإلا 'type'
textualConvention
ترجع TEXTUAL-CONVENTION
TCDescription
ترجع مجال DESCRIPTION الخاص بـ TEXTUAL-CONVENTION.
units
ترجع UNITS
hint
ترجع HINT
enums
ترجع مرجع قائمة {tag => num, ...}
ranges
ترجع مرجع مصفوفة من مراجع القوائم [{low => num, high => num}, ...]
description
ترجع DESCRIPTION (يجب تعيين $SNMP::save_descriptions قبل تهيئة/تحليل MIB)
reference
ترجع جملة REFERENCE
indexes
ترجع الكائنات في جملة INDEX
implied
ترجع صحيح إذا كان آخر كائن في INDEX هو ضمنيًا (IMPLIED)

وظائف MIB

&SNMP::setMib(<file>)
يسمح بالتحليل الديناميكي لـ MIB وتحديد ملف MIB بشكل صريح بشكل مستقل عن متغيرات البيئة. عند استدعائها بدون وسائط، تعمل مثل initMib، وتقوم بتحميل MIBs المشار إليها بواسطة متغيرات البيئة (انظر وثائق Net-SNMP mib_api). تمرير وسيط ثانٍ غير صفري يجبر على تحرير MIB السابقة واستبدالها (ملاحظة: الوسيط الثاني لا يعمل لأن تحرير MIB السابقة أكثر تعقيدًا من ذي قبل).
&SNMP::initMib()
يستدعي وظيفة init_mib للمكتبة إذا لم يتم تحميل MIB بالفعل - لا يفعل شيئًا إذا تم تحميل MIB بالفعل. سيقوم بتحليل الدلائل وتحميل الوحدات وفقًا لمتغيرات البيئة الموصوفة في وثائق Net-SNMP. (انظر man mib_api، MIBDIRS، MIBS، MIBFILE(S)، إلخ.)
&SNMP::addMibDirs(<dir>,...)
يستدعي add_mibdir للمكتبة لكل دليل يتم توفيره. سيؤدي ذلك إلى إضافة الدليل(الدلائل) إلى القائمة الداخلية وجعلها متاحة للبحث في استدعاءات loadModules اللاحقة
&SNMP::addMibFiles(<file>,...)
يستدعي وظيفة read_mib للمكتبة. سيتم قراءة الملف (الملفات) المقدمة وسيتم إضافة جميع تعريفات وحدات Mib الموجودة فيها إلى بنية شجرة MIB الداخلية
&SNMP::loadModules(<mod>,...)
يستدعي وظيفة read_module للمكتبة. سيتم البحث عن الوحدة (الوحدات) المقدمة في mibdirs الحالية وإضافتها إلى بنية شجرة MIB الداخلية. تمرير <mod> خاص، 'ALL'، سيؤدي إلى تحميل جميع الوحدات المعروفة.
&SNMP::unloadModules(<mod>,...)
*غير مطبق*
&SNMP::translateObj(<var>[,arg,[arg]])
سيقوم بتحويل علامة كائن نصية إلى OID والعكس صحيح. أي لاحقة iid يتم الاحتفاظ بها رقميًا. السلوك الافتراضي عند تحويل OID رقمي إلى شكل نصي هو إرجاع المعرف الطرفي فقط (مثل 'sysDescr') ولكن عندما يكون $SNMP::use_long_names غير صفري أو يتم توفير وسيط ثانٍ غير صفري، فإنه سيرجع معرفًا نصيًا أطول. وسيط اختياري ثالث غير صفري سيؤدي إلى إضافة اسم الوحدة إلى الاسم النصي (مثل 'SNMPv2-MIB::sysDescr'). عند تحويل كائن نصي، يتم استخدام خيار $SNMP::best_guess. إذا لم يتم تحميل Mib عند الاستدعاء وتم تمكين $SNMP::auto_init_mib، فسيتم تحميل Mib. سترجع 'undef' عند الفشل.
&SNMP::getType(<var>)
ترجع نوع بيانات SNMP للمعّرف النصي المحدد OBJECTID, OCTETSTR, INTEGER, NETADDR, IPADDR, COUNTER GAUGE, TIMETICKS, OPAQUE, أو undef
&SNMP::mapEnum(<var>)
يقوم بتحويل قيمة عدد صحيح إلى علامة تعداد معرفة في Mib أو يحول علامة إلى عدد صحيح اعتمادًا على الإدخال. ستعيد الوظيفة القيمة العددية المقابلة *أو* العلامة لسمة MIB وقيمة محددة. ستكتشف الوظيفة الاتجاه الذي يجب إجراء التحويل فيه. يتم دعم تنسيقات وسائط متنوعة
$val = SNMP::mapEnum($varbind);
حيث $varbind هو SNMP::Varbind أو ما يعادله. ملاحظة: سيتم تحديث $varbind
$val = SNMP::mapEnum('ipForwarding', 'forwarding');
$val = SNMP::mapEnum('ipForwarding', 1);

التراخيص: BSD

SNMP(3pm)

Perl interface to the SNMP library

This module provides a Perl interface to the Net-SNMP library, allowing Perl programs to communicate with SNMP agents.

NAME

SNMP - Perl interface to the SNMP library

SYNOPSIS

use SNMP;

my $session = SNMP::Session->new(
    -hostname  => 'localhost',
    -community => 'public',
    -version   => 'snmpv2c',
);

my $vars = $session->get_request(
    -varbinds => ['1.3.6.1.2.1.1.1.0'], # sysDescr.0
);

if (!defined $vars) {
    print STDERR "Error: ", $session->error(), "\n";
} else {
    print "System Description: ", $vars->{'1.3.6.1.2.1.1.1.0'}, "\n";
}

my $trap_session = SNMP::TrapSession->new(
    -hostname => 'localhost',
    -port     => 162,
    -community => 'public',
);

$trap_session->trap_request(
    -trap     => 'coldStart',
    -enterprise => '1.3.6.1.4.1.11', # Example enterprise OID
    -varbinds => [
        ['1.3.6.1.2.1.1.3.0', 'Gauge32', time()], # sysUpTime.0
        ['1.3.6.1.2.1.1.1.0', 'OctetString', 'System started'], # sysDescr.0
    ],
);

DESCRIPTION

The SNMP module provides a Perl interface to the Net-SNMP library, which is a widely used implementation of the Simple Network Management Protocol (SNMP). This module allows Perl programs to send SNMP requests (GET, GETNEXT, SET) to SNMP agents and to receive SNMP traps.

The module provides two main classes: SNMP::Session for performing standard SNMP operations and SNMP::TrapSession for sending SNMP traps.

SNMP::Session

The SNMP::Session class represents an SNMP session with an agent. It provides methods for sending various types of SNMP requests.

Constructor

my $session = SNMP::Session->new(
    -hostname  => 'hostname',      # Required
    -community => 'community',     # Required
    -port      => 161,             # Optional, defaults to 161
    -version   => 'snmpv1',        # Optional, defaults to 'snmpv1'
    -timeout   => 5,               # Optional, defaults to 5 seconds
    -retries   => 1,               # Optional, defaults to 1
    -nonblocking => 0,           # Optional, defaults to 0 (blocking)
    -translate_oids => 1,      # Optional, defaults to 1 (translate OIDs)
    -oakley_paths => '/usr/local/share/snmp/snmpv3.conf', # Optional
    -secName   => 'user',          # Optional, for SNMPv3
    -secLevel  => 'authPriv',      # Optional, for SNMPv3
    -authProto => 'sha',           # Optional, for SNMPv3
    -authKey   => 'password',      # Optional, for SNMPv3
    -privProto => 'des',           # Optional, for SNMPv3
    -privKey   => 'password',      # Optional, for SNMPv3
);

Supported versions are 'snmpv1', 'snmpv2c', and 'snmpv3'. For SNMPv3, you need to provide additional security parameters.

Methods

get_request( -varbinds => [...] )
Sends an SNMP GET request. Returns a hash reference of variable bindings or undef on error.
getnext_request( -varbinds => [...] )
Sends an SNMP GETNEXT request. Returns a hash reference of variable bindings or undef on error.
set_request( -varbinds => [...] )
Sends an SNMP SET request. Returns a true value on success or undef on error.
get_bulk_request( -nonrepeaters => N, -maxrepetitions => M, -varbinds => [...] )
Sends an SNMP GETBULK request (for SNMPv2c and SNMPv3). Returns a hash reference of variable bindings or undef on error.
error()
Returns the error message string if a previous operation failed.
errno()
Returns the Net-SNMP error code if a previous operation failed.
close()
Closes the SNMP session.

SNMP::TrapSession

The SNMP::TrapSession class is used for sending SNMP traps.

Constructor

my $trap_session = SNMP::TrapSession->new(
    -hostname  => 'hostname',      # Required
    -port      => 162,             # Optional, defaults to 162
    -community => 'community',     # Required
);

Methods

trap_request( -trap => 'trap_type', -enterprise => 'enterprise_oid', -varbinds => [...] )
Sends an SNMP trap. -trap can be a standard trap name (e.g., 'coldStart', 'warmStart', 'linkDown', 'linkUp', 'authenticationFailure', 'egpNeighborLoss', 'enterpriseSpecific') or an OID. -enterprise is the enterprise OID (required if -trap is an OID or 'enterpriseSpecific'). -varbinds is an array reference of variable bindings. Returns a true value on success or undef on error.
error()
Returns the error message string if a previous operation failed.
errno()
Returns the Net-SNMP error code if a previous operation failed.
close()
Closes the SNMP trap session.

Acceptable variable formats:

Variable bindings can be specified in two ways:

  1. A hash reference where keys are OIDs (as strings) and values are the corresponding data. The module will attempt to determine the correct data type. 
    -varbinds => {
    '1.3.6.1.2.1.1.1.0' => 'My System Description',
    '1.3.6.1.2.1.1.5.0' => 'My Hostname',
}
  2. An array reference of array references, where each inner array contains the OID, the data type, and the value. This allows explicit type specification. 
    -varbinds => [
    ['1.3.6.1.2.1.1.1.0', 'OctetString', 'My System Description'],
    ['1.3.6.1.2.1.1.5.0', 'OctetString', 'My Hostname'],
    ['1.3.6.1.2.1.1.3.0', 'TimeTicks', 12345],
    ['1.3.6.1.2.1.1.4.0', 'Counter32', 100],
]

Supported data types include: OctetString, Integer, Integer32, Unsigned32, Gauge32, TimeTicks, Counter32, Counter64, Opaque, IpAddress, ObjectIdentifier, Bits, NsapAddress, Boolean, ObjectIdentity.

Acceptable callback formats

Not implemented in this version.

SNMP package variables and functions

The SNMP module also exports several utility functions and package variables.

%SNMP::MIB

A hash reference containing loaded MIB information. Keys are OIDs, and values are MIB object names. This is automatically populated when OIDs are translated.

MIB Functions

snmptranslate( $oid )
Translates an OID to its symbolic name.
snmp_oid_numeric2symbolic( $oid )
Alias for snmptranslate.
snmp_oid_symbolic2numeric( $symbolic_oid )
Translates a symbolic OID name to its numeric representation.

Exported SNMP utility functions

snmp_error()
Returns the last error message from the Net-SNMP library.
snmp_set_alarm( $seconds, $callback )
Sets a timer for a callback function.
snmp_clear_alarm( $id )
Clears a previously set alarm.
snmp_read_fd( $fd, $timeout )
Reads from a file descriptor with a timeout.
snmp_select_info( $fd_set, $timeout )
Waits for activity on file descriptors.

Trouble Shooting

If you encounter issues, ensure that the Net-SNMP development libraries are installed on your system. Check the error messages returned by the module's error() method for clues. You may also need to adjust firewall rules to allow UDP traffic on port 161 (for agents) or 162 (for traps).
