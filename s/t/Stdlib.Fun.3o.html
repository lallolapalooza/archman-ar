المُركِّبات

val id : 'a -> 'a

id هي الدالة الهوية. لأي معامل x ، id x هو x.

val const : 'a -> 'b -> 'a

const c هي دالة تُرجع دائمًا القيمة c. لأي معامل x ، (const c) x هو c.

val compose : ('b -> 'c) -> ('a -> 'b) -> 'a -> 'c

compose f g هو تركيب الدوال بتطبيق g ثم f. لأي معاملات f و g و x ، compose f g x هو f (g x).

منذ 5.2

val flip : ('a -> 'b -> 'c) -> 'b -> 'a -> 'c

flip f يعكس ترتيب معاملات الدالة الثنائية f. لأي معاملات x و y ، (flip f) x y هو f y x.

val negate : ('a -> bool) -> 'a -> bool

negate p هو نفي دالة الشرط p. لأي معامل x ، (negate p) x هو no (p x).

معالجة الاستثناءات

val protect : finally:(unit -> unit) -> (unit -> 'a) -> 'a

protect ~finally work تستدعي work () ثم finally () قبل أن تُرجع work () قيمتها أو استثناءً. في حالة حدوث استثناء، يتم إعادة إطلاق الاستثناء بعد finally (). إذا أطلق finally () استثناءً، يتم إطلاق الاستثناء Fun.Finally_raised.

يمكن استخدام protect لضمان ثوابت محلية، بغض النظر عما إذا كانت work () تُرجع بشكل طبيعي أو تُطلق استثناءً. ومع ذلك، فهي لا تحمي من الاستثناءات غير المتوقعة التي تُطلق داخل finally ()، مثل Out_of_memory أو Stack_overflow أو الاستثناءات غير المتزامنة التي تُطلق بواسطة معالجات الإشارة (مثل Sys.Break).

ملاحظة: يعتبر خطأ في البرمجة إذا تم إطلاق استثناءات أخرى بواسطة finally، حيث سيتم فقدان أي استثناء تم إطلاقه في work () في حالة استثناء Fun.Finally_raised. لذلك، يجب التأكد من معالجة هذه الاستثناءات داخل finally.

exception Finally_raised of exn

يتم إطلاق Finally_raised exn بواسطة protect ~finally work عندما تُطلق finally استثناءً exn. يشير هذا الاستثناء إلى استثناء غير متوقع أو خطأ في البرمجة. كقاعدة عامة، لا ينبغي التقاط استثناء Finally_raised إلا كجزء من معالج catch-all.

أمثلة

المُركِّبات

توفر Fun.combinators طريقة خفيفة وغالبًا ما تكون أكثر قابلية للقراءة لإنشاء دوال مجهولة، والتي يُفضل استخدامها كمعاملات قصيرة الأمد بدلاً من تعريفات ثابتة. ستوضح الأمثلة التالية هذا بشكل أساسي باستخدام الوحدة List.

[id]

List.init مع المؤشر نفسه

  # List.init 3 Fun.id;;
  - : int list = [0; 1; 2]

استخدام List.filter_map على قائمة من int option لتصفية عناصر Option.t.None

  # List.filter_map Fun.id [None; Some 2; Some 3; None; Some 5];;
  - : int list = [2; 3; 5]

يُعد الإرسال الشرطي للدوال من النوع foo -> foo أو استخدامها كمعاملات جزءًا آخر حيث يمكن أن يكون id مفيدًا. على سبيل المثال، ضع في اعتبارك دالة تسجيل تسجل سلسلة نصية ولكنها تعطي المستخدم خيارًا لمعالجة السلسلة مسبقًا قبل التسجيل، على سبيل المثال، لإدراج ختم زمني

  let log ?(preformat : string -> string = Fun.id) message =
    print_endline (preformat message)

عندما يمكن بناء الإغلاقات، غالبًا ما يتم استخدام id كحالة أساسية كعدم القيام بأي شيء. على سبيل المثال، دالة تقوم بربط قائمة من الدوال الأحادية:

  let rec chain = function
    | [] -> Fun.id
    | f :: fs -> fun x -> f (chain fs x)

[const]

List.init مع قائمة من الأصفار

  # List.init 3 (Fun.const 0);;
  - : int list = [0; 0; 0]

شرط سماح يمكن تمريره إلى أي دالة تصفية، على سبيل المثال List.filter لتعطيل التصفية والحصول على جميع القيم

  # List.filter (Fun.const true) [1; 2; 3];;
  - : int list = [1; 2; 3]

ملاحظة: تطبيق const (...) يقوم بتقييم التعبير (...) مرة واحدة ويُرجع دالة تحتوي فقط على نتيجة هذا التقييم. لإثبات ذلك، ضع في اعتبارك إذا كان (...) عبارة عن استدعاء لـ Random.bool ():

List.init n (Fun.const (Random.bool())) لأي n > 0 سيكون لها نتيجتان محتملتان بالضبط،

- [true; true; ...; true]

- [false; false; ...; false]

بينما List.init n (fun _ -> Random.bool()) سيكون لها 2^n نتائج محتملة، لأن تأثير العشوائية يتم مع كل عنصر.

لمزيد من الاستخدامات الفعلية، ضع في اعتبارك String.spellcheck بمسافة قصوى تبلغ 2، بدلاً من القيمة الافتراضية المتغيرة

  let spellcheck known_words word =
    let dict_iter yield = List.iter yield known_words in
    String.spellcheck ~max_dist:(Fun.const 2) dict_iter word

[flip]

استخدام flip لعكس المقارن الذي تم تمريره إلى List.sort، والذي يرتب بالترتيب العكسي

  # List.sort (Fun.flip Int.compare) [5; 3; 9; 0; 1; 6; 8];;
  - : int list = [9; 8; 6; 5; 3; 1; 0]

عكس قائمة عن طريق تجميع قائمة جديدة باستخدام List.fold_left، والذي يتوقع أن يكون المجمّع هو المعامل الأول للدالة الممررة. نمرر List.cons التي تحتوي على القائمة كمعامل ثانٍ، لذا فإن flip مفيد هنا

  # List.fold_left (Fun.flip List.cons) [] [1; 2; 3];;
  - : int list = [3; 2; 1]

من المثير للاهتمام أن flip يمكن أن تعمل مع دوال غير ثنائية، وتعكس أول معاملين وتترك الباقي بترتيبهم. هذا لأن دالة تأخذ n+2 معاملات هي من الناحية المفاهيمية دالة ثنائية تُرجع دالة تأخذ n معاملات. بالنظر إلى الدالة f : a -> b -> c -> d:

- سيكون نوع flip f هو b -> a -> c -> d

- سيكون نوع fun x -> flip (f x) هو a -> c -> b -> d

يُحظر استخدام flip مع دوال غير ثنائية كهذه بسبب تأثيرها السلبي على سهولة القراءة واستنتاج الأسباب.

[negate]

تُستخدم بشكل أساسي لعكس شرط في دالة تتوقع معاملًا واحدًا، مثل List.find_all والدوال المماثلة

العثور على جميع القوائم غير الفارغة باستخدام List.is_empty

  # List.find_all (Fun.negate List.is_empty) [[0]; [1; 2; 3]; []; [4; 5]];;
  - : int list list = [[0]; [1; 2; 3]; [4; 5]]

من قائمة مسارات معطاة، ابحث عن جميع المسارات غير المشغولة باستخدام Sys.file_exists

  # List.find_all (Fun.negate Sys.file_exists);;
  - : string list -> string list = <fun>

[compose]

List.map على العناصر الزوجية مع دالة على العنصر الثاني

  # List.map (Fun.compose String.length snd) [1, "one"; 2, "two"; 3, "three"];;
  - : int list = [3; 3; 5]

تنفيذ محتمل لـ Fun.negate

  let negate f = Fun.compose not f

من Fun.hid، كان يمكن استخدام compose في الفرع التكراري

  let rec chain = function
    | [] -> Fun.id
    | f :: fs -> Fun.compose f (chain fs)
أو بشكل أكثر إيجازًا 
  let chain fs = List.fold_right Fun.compose fs Fun.id

من Fun.hflip، compose و flip

الاسم

يمكن

  # Fun.compose
      (String.spellcheck ~max_dist:(Fun.const 2))
      (Fun.flip List.iter)
    ;;
  - : string list -> string -> string list = <fun>

كما يمكن رؤيته هنا، يؤثر هذا بشكل كبير على سهولة القراءة والقدرة على فهم الدالة. كل من String.spellcheck و Fun.flip ليسا أحاديين، لذلك هناك تفاعل غير تافه مع التطبيق الجزئي في هذا التعريف.
