NAME

strtoq, strtouq — convert string to quad-precision integer

LIBRARY

Standard C library (libc, -lc)

SYNOPSIS

#include <stdlib.h>

long long strtoq(const char *nptr, char **endptr, int base);
unsigned long long strtouq(const char *nptr, char **endptr, int base);

DESCRIPTION

The strtoq() and strtouq() functions convert the initial portion of the string pointed to by nptr to a long long and unsigned long long integer, respectively.

The conversion is performed according to the following rules:

  • There is an optional initial whitespace sequence (as defined by isspace()).
  • The following is an optional sign character (‘+’ or ‘-’). strtoq() accepts this sign; strtouq() ignores it.
  • If the base argument is 0, the base is determined from the string itself. An initial “0” indicates octal, and an initial “0x” or “0X” indicates hexadecimal. Otherwise, the base is decimal.
  • If base is any other value between 2 and 36, then it is used as the base for the conversion. The digits are 0-9 and then a-z and A-Z are used for values up to 36.
  • The conversion stops when the first character is encountered that is not a valid digit in the specified base, or when the end of the string is reached.

strtoq() and strtouq() set endptr to point to the first character after the last character that was converted. If no conversion was performed, endptr is set to nptr. If the converted value is out of range for the return type, the nearest representable value is returned and ERANGE is set in errno.

RETURN VALUE

strtoq() and strtouq() return the converted value. If the value would underflow, LLONG_MIN or ULLONG_MAX is returned. If the value would overflow, LLONG_MAX or ULLONG_MAX is returned.

ERRORS

EINVAL
No conversion could be performed.
ERANGE
The value to be returned is too large or too small.

VERSIONS

strtoq() and strtouq() are available since glibc 2.1.

STANDARDS

These functions are extensions to the C standard. They are not defined by POSIX.1-2001 or POSIX.1-2008.

HISTORY

strtoq() and strtouq() first appeared in glibc 2.1.

CAVEATS

These functions are not standards compliant and should not be used in portable code.

The strtouq() function is dangerous because it does not distinguish between an overflow and an underflow, as it does not accept a sign character.

In the case of strtoq() and strtouq(), the base is limited to 36. This is in contrast to strtol() and strtoul(), which accept a base of 0.

BUGS

The strtoq() and strtouq() functions are not standard and should not be used.

EXAMPLES

#include <stdio.h>
#include <stdlib.h>
#include <errno.h>

int
main(void)
{
    const char *str1 = "18446744073709551615";
    char *endptr;
    unsigned long long val;

    errno = 0;
    val = strtouq(str1, &endptr, 10);

    if (errno == ERANGE && val == ULLONG_MAX) {
        printf("range error, value = ULLONG_MAX\n");
    } else if (errno != 0 && val == 0) {
        perror("strtouq");
        exit(EXIT_FAILURE);
    }

    if (endptr == str1) {
        printf("No digits were found\n");
        exit(EXIT_FAILURE);
    }

    printf("strtouq() returned %llu\n", val);
    if (*endptr != '\0')        /* Not necessarily an error.  */
        printf("Further characters after number: \"%s\"\n", endptr);

    exit(EXIT_SUCCESS);
}

The example above demonstrates the usage of strtouq() to convert a string to an unsigned long long integer. It includes error handling for range errors and cases where no digits are found.
