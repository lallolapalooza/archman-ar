القيمة to_string : exn -> string

Printexc.to_string e تُرجع تمثيلاً نصياً للاستثناء e.

القيمة to_string_default : exn -> string

Printexc.to_string_default e تُرجع تمثيلاً نصياً للاستثناء e، متجاهلةً جميع طابعات الاستثناءات المسجلة.

منذ 4.09

القيمة print : ('a -> 'b) -> 'a -> 'b

Printexc.print fn x تُطبق fn على x وتُرجع النتيجة. إذا أدى تقييم fn x إلى استثناء، يتم طباعة اسم الاستثناء على مخرج الخطأ القياسي ويتم إعادة إلقائه. الاستخدام النموذجي هو التقاط وإبلاغ الاستثناءات التي تفلت من تطبيق الدوال.

القيمة catch : ('a -> 'b) -> 'a -> 'b

مهمل. هذه الدالة لم تعد ضرورية.

Printexc.catch fn x مشابه لـ Printexc.print، ولكنه ينهي البرنامج برمز خروج 2 بعد طباعة الاستثناء غير الملتقط. هذه الدالة مهملة: نظام وقت التشغيل الآن قادر على طباعة الاستثناءات غير الملتقطة بنفس الدقة التي توفرها Printexc.catch. علاوة على ذلك، فإن استدعاء Printexc.catch يجعل من الصعب تتبع موقع الاستثناء باستخدام المصحح أو تتبع المكدس. لذلك، لا تستخدم Printexc.catch في البرامج الجديدة.

القيمة print_backtrace : out_channel -> unit

Printexc.print_backtrace oc تطبع تتبعاً للاستثناءات إلى قناة الإخراج oc. يسرد تتبع الاستثناءات مواقع البرنامج التي تم فيها إلقاء أحدث استثناء وحيث تم نشر الاستثناء عبر استدعاءات الدوال.

إذا لم يتم العثور على الاستدعاء ضمن معالج استثناء، فإن التتبع المُعاد يكون غير محدد. إذا تم الاستدعاء بعد بعض التعليمات البرمجية لمعالجة الاستثناءات (قبل المعالج أو أثناء مطابقة المعالج باستخدام شرط عندما)، فقد يتوافق التتبع مع استثناء لاحق للاستثناء الذي تمت معالجته.

منذ 3.11

القيمة get_backtrace : unit -> string

Printexc.get_backtrace () تُرجع سلسلة نصية تحتوي على نفس تتبع الاستثناءات الذي كانت Printexc.print_backtrace ستطبعه. نفس قيد الاستخدام مثل Printexc.print_backtrace.

منذ 3.11

القيمة record_backtrace : bool -> unit

Printexc.record_backtrace b يقوم بتشغيل أو إيقاف تسجيل تتبعات الاستثناءات (إذا كان b = true) أو (إذا كان b = false). في البداية، لا يتم تسجيل تتبعات الاستثناءات، إلا إذا تم تمرير علامة b إلى البرنامج عبر متغير البيئة OCAMLRUNPARAM.

منذ 3.11

القيمة backtrace_status : unit -> bool

Printexc.backtrace_status() تُرجع true إذا كانت تتبعات الاستثناءات مسجلة حالياً، و false إذا لم تكن كذلك.

منذ 3.11

القيمة register_printer : (exn -> string option) -> unit

Printexc.register_printer fn يسجل fn كطابع استثناء. يجب أن تُرجع الطابعة None أو تُلقي استثناءً إذا كانت لا تعرف كيفية تحويل الاستثناء المُمرر، و Some مع السلسلة الناتجة s إذا كانت تستطيع تحويل الاستثناء المُمرر. يتم تجاهل الاستثناءات التي تلقيها الطابعة.

عند تحويل استثناء إلى سلسلة نصية، يتم استدعاء الطابعات بترتيب عكسي لتسجيلها، حتى تُرجع طابعة Some s (إذا لم تكن هناك مثل هذه الطابعة، فسيتم استخدام الطابعات العامة).

باستخدام هذه الآلية، يجب أن تكون على دراية بأن تتبع الاستثناء يتم إرفاقه بالخيط الذي رأى الاستثناء، وليس بالاستثناء نفسه. عملياً، هذا يعني أن التعليمات البرمجية المتعلقة بـ fn يجب ألا تستخدم التتبع إذا كانت قد ألقت استثناءً قبل نفسها.

منذ 3.11.2

القيمة use_printers : exn -> string option

Printexc.use_printers e تُرجع None إذا لم تكن هناك طابعات مسجلة، و Some s مع السلسلة الناتجة s بخلاف ذلك.

منذ 4.09

تتبعات الخلفية الخام

النوع raw_backtrace

يخزن النوع raw_backtrace تتبعاً للاستثناءات بتنسيق منخفض المستوى، والذي يمكن تحويله إلى تنسيق مفيد باستخدام raw_backtrace_entries و backtrace_slots_of_raw_entry أدناه.

تحويل تتبعات الاستثناءات إلى backtrace_slot أبطأ من التقاط التتبعات. إذا كان البرنامج يعالج العديد من التتبعات، فقد يكون من المفيد استخدام raw_backtrace لتجنب أو تأخير التحويل.

لا يمكن تسلسل تتبعات الخلفية الخام. إذا كنت بحاجة إلى التسلسل، فيجب عليك استخدام المصفوفة التي تُرجعها طريقة backtrace_slots في القسم التالي.

منذ 4.01

النوع raw_backtrace_entry = private int

raw_backtrace_entry هو عنصر من raw_backtrace.

كل raw_backtrace_entry هو عدد صحيح غير شفاف، لا تكون قيمته ثابتة بين البرامج المختلفة، أو حتى بين عمليات تشغيل مختلفة لنفس الملف التنفيذي.

يمكن تحويل raw_backtrace_entry إلى تنسيق مفيد باستخدام backtrace_slots_of_raw_entry أدناه. يجب أن تكون على علم بأنه بسبب الاستدعاءات المتداخلة، قد يتحول raw_backtrace_entry واحد إلى عدة backtrace_slots. نظرًا لأن قيم raw_backtrace_entry ليست ثابتة، فلا يمكن تسلسلها. إذا كان يجب تحويلها، فيجب أن يتم التحويل بواسطة العملية التي أنشأتها.

مرة أخرى بسبب الاستدعاءات المتداخلة، قد يكون هناك العديد من القيم المميزة لـ raw_backtrace_entry التي تتقارب إلى نفس backtrace_slots. ومع ذلك، إذا كان اثنان من raw_backtrace_entry متساويين كعدد صحيح، فإنهما يمثلان نفس backtrace_slots.

القيمة get_raw_backtrace : unit -> raw_backtrace

Printexc.get_raw_backtrace () تُرجع نفس تتبع الاستثناءات الذي كانت Printexc.print_backtrace ستطبعه، ولكن بتنسيق خام. نفس قيد الاستخدام مثل Printexc.print_backtrace.

منذ 4.01

القيمة raise_with_backtrace : exn -> raw_backtrace -> 'a

تعيد إلقاء الاستثناء باستخدام تتبع الخلفية المحدد كمصدر للاستثناء.

منذ 4.05

مكدس الاستدعاءات الحالي

القيمة get_callstack : int -> raw_backtrace

Printexc.get_callstack n تُرجع وصفاً للجزء العلوي من مكدس الاستدعاءات في النقطة الحالية من البرنامج (للخيط الحالي)، بحد أقصى n من الإدخالات. (ملاحظة: هذه الدالة لا علاقة لها بالاستثناءات، على الرغم من كونها جزءًا من الوحدة Printexc.)

منذ 4.01

استثناءات غير ملتقطة

القيمة default_uncaught_exception_handler : exn -> raw_backtrace -> unit

Printexc.default_uncaught_exception_handler تطبع الاستثناء وتتبع الخلفية إلى مخرج الخطأ القياسي.

منذ 4.11

القيمة set_uncaught_exception_handler : (exn -> raw_backtrace -> unit) -> unit

Printexc.set_uncaught_exception_handler fn يسجل fn كمعالج للاستثناءات غير الملتقطة. المعالج الافتراضي هو Printexc.default_uncaught_exception_handler.

ملاحظة: عند استدعاء fn، تكون جميع الدوال المسجلة بواسطة at_exit قد تم استدعاؤها بالفعل.
