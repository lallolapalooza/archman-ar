القيمة length : 'a array -> int

تُرجع طول (عدد العناصر) للمصفوفة المعطاة.

القيمة get : 'a array -> int -> 'a

get a n تُرجع العنصر رقم n من المصفوفة a . العنصر الأول رقمه 0. العنصر الأخير رقمه length a - 1 . يمكنك أيضًا كتابة a.(n) بدلاً من get a n .

تُطلق Invalid_argument إذا كان n خارج النطاق من 0 إلى length a - 1 .

القيمة set : 'a array -> int -> 'a -> unit

set a n x تعدل المصفوفة a في المكان، مستبدلة العنصر رقم n بـ x . يمكنك أيضًا كتابة a.(n) <-= x بدلاً من set a n x .

تُطلق Invalid_argument إذا كان n خارج النطاق من 0 إلى length a - 1 .

القيمة make : int -> 'a -> 'a array

make n x تُرجع مصفوفة جديدة بطول n، مع تهيئة جميع عناصرها بـ x . جميع عناصر هذه المصفوفة الجديدة متطابقة فيزيائيًا مع x (بالمعنى الضمني لـ ==). لذلك، إذا كان x قابلاً للتعديل، فسيكون مشتركًا بين جميع عناصر المصفوفة. سيؤدي تعديل x عبر أحد عناصر المصفوفة إلى تعديل جميع العناصر الأخرى في نفس الوقت.

تُطلق Invalid_argument إذا كان n < 0 أو n > Sys.max_array_length . إذا كانت قيمة x عددًا عشريًا، فإن الحد الأقصى للحجم هو فقط Sys.max_array_length / 2 .

القيمة create_float : int -> float array

create_float n تُرجع مصفوفة أعداد عشرية جديدة بطول n، مع بيانات غير مهيأة.

تُطلق Invalid_argument إذا كان dimx أو dimy سالباً أو أكبر من Sys.max_array_length . إذا كانت قيمة e عددًا عشريًا، فإن الحد الأقصى للحجم هو فقط Sys.max_array_length / 2 .

القيمة sub : 'a array -> pos:int -> len:int -> 'a array

sub a ~pos ~len تُرجع مصفوفة جديدة بطول len، تحتوي على العناصر من الرقم pos إلى pos + len - 1 من المصفوفة a .

تُطلق Invalid_argument إذا كان pos و len لا يحددان مصفوفة فرعية صالحة من a ؛ أي، إذا كان pos < 0 أو len < 0 أو pos + len > length a .

القيمة fill : 'a array -> pos:int -> len:int -> 'a -> unit

fill a ~pos ~len x تعدل المصفوفة a في المكان، وتخزن x في العناصر من الرقم pos إلى pos + len - 1 .

تُطلق Invalid_argument إذا كان pos و len لا يحددان مصفوفة فرعية صالحة من a .

القيمة blit : src:'a array -> src_pos:int -> dst:'a array -> dst_pos:int -> len:int -> unit

blit ~src ~src_pos ~dst ~dst_pos ~len تنسخ len عناصر من المصفوفة src، بدءًا من العنصر رقم src_pos، إلى المصفوفة dst، بدءًا من العنصر رقم dst_pos . تعمل بشكل صحيح حتى لو كانت src و dst نفس المصفوفة، وتتداخل كتل المصدر والوجهة.

تُطلق Invalid_argument إذا كان src_pos و len لا يحددان مصفوفة فرعية صالحة من src، أو إذا كان dst_pos و len لا يحددان مصفوفة فرعية صالحة من dst .

القيمة to_list : 'a array -> 'a list

القيمة of_list : 'a list -> 'a array

تُطلق Invalid_argument إذا كان طول l أكبر من Sys.max_array_length .

الفرز والخلط

val sort : cmp:('a -> 'a -> int) -> 'a array -> unit

فرز مصفوفة بترتيب تصاعدي وفقًا لدالة مقارنة. يجب أن تعيد دالة المقارنة 0 إذا كانت وسيطاتها متساوية، عددًا صحيحًا موجبًا إذا كان الأول أكبر، وعددًا صحيحًا سالبًا إذا كان الأول أصغر (انظر أدناه لمواصفات كاملة). على سبيل المثال، compare هي دالة مقارنة مناسبة. بعد استدعاء sort، يتم فرز المصفوفة في مكانها بترتيب تصاعدي. يضمن sort التشغيل في مساحة ذاكرة كومة ثابتة ومساحة مكدس لوغاريتمية (على الأكثر).

التنفيذ الحالي يستخدم فرز الكومة (Heap Sort). يعمل في مساحة مكدس ثابتة.

مواصفات دالة المقارنة: ليكن a هي المصفوفة و cmp دالة المقارنة. يجب أن يكون ما يلي صحيحًا لجميع x و y و z في a:

- cmp x y > 0 إذا وفقط إذا كان cmp y x < 0

- إذا كان cmp x y >= 0 و cmp y z >= 0 فإن cmp x z >= 0

عندما تعيد sort، تحتوي a على نفس العناصر الموجودة بها من قبل، معاد ترتيبها بطريقة أنه لجميع الفهارس i و j الصالحة لـ a:

- cmp a.(i) a.(j) >= 0 إذا كان i >= j

val stable_sort : cmp:('a -> 'a -> int) -> 'a array -> unit

نفس سلوك ArrayLabels.sort، ولكن خوارزمية الفرز مستقرة (أي يتم الاحتفاظ بالعناصر المتساوية في ترتيبها الأصلي) ولا تضمن التشغيل في مساحة ذاكرة كومة ثابتة.

التنفيذ الحالي يستخدم فرز الدمج (Merge Sort). يستخدم مصفوفة مؤقتة بطول n/2، حيث n هو طول المصفوفة. عادة ما يكون أسرع من التنفيذ الحالي لـ ArrayLabels.sort.

val fast_sort : cmp:('a -> 'a -> int) -> 'a array -> unit

نفس سلوك ArrayLabels.sort أو ArrayLabels.stable_sort، أيهما أسرع في المدخلات النموذجية.

val shuffle : rand:(int -> int) -> 'a array -> unit

shuffle ~rand a يقوم بتبديل عناصر a بشكل عشوائي باستخدام rand للعشوائية. توزيع التباديل منتظم.

يجب أن يكون rand بحيث يعيد استدعاء rand n رقمًا عشوائيًا موزّعًا بشكل منتظم في النطاق [ 0 ؛ n-1 ]. يمكن استخدام Random.int لهذا الغرض (لا تنسَ Random.self_init المولد).

المصفوفات والسلامة التزامنية

يجب توخي الحذر عند الوصول المتزامن إلى المصفوفات من مجالات متعددة: الوصول إلى مصفوفة لن يؤدي أبدًا إلى تعطل البرنامج، ولكن الوصول غير المتزامن قد ينتج عنه نتائج مفاجئة (غير متسقة تسلسليًا).

الذرية

كل عملية مصفوفة تصل إلى أكثر من عنصر مصفوفة واحد ليست ذرية. هذا يشمل التكرار، المسح، الفرز، تقسيم ودمج المصفوفات.

على سبيل المثال، ضع في اعتبارك البرنامج التالي:

let size = 100_000_000
let a = ArrayLabels.make size 1
let d1 = Domain.spawn (fun () ->
   ArrayLabels.iteri ~f:(fun i x -> a.(i) <- x + 1) a
)
let d2 = Domain.spawn (fun () ->
  ArrayLabels.iteri ~f:(fun i x -> a.(i) <- 2 * x + 1) a
)
let () = Domain.join d1; Domain.join d2

بعد تنفيذ هذا الرمز، كل حقل في المصفوفة a هو إما 2 أو 3 أو 4 أو 5. إذا كانت الذرية مطلوبة، فيجب على المستخدم تنفيذ مزامنة خاصة به (على سبيل المثال، باستخدام Mutex.t).

سباقات البيانات

إذا كان مجالان يصلان فقط إلى أجزاء غير متقاطعة من المصفوفة، فإن السلوك الملاحظ يعادل تداخلًا تسلسليًا لعمليات من المجالين.

يُقال عن سباق البيانات أنه يحدث عندما يصل مجالان إلى نفس عنصر المصفوفة دون مزامنة

NAME

Stdlib.ArrayLabels - mutable arrays

Module

module ArrayLabels : sig ... end

Documentation

The operations in this module are only safe for concurrent use if the array is not accessed from multiple domains concurrently, except for the read operations.

This module implements mutable arrays. The elements are indexed by integers starting from 0. All elements of an array have the same type.

The operations get, set, blit, fill, copy, sub, append, concat and reverse are provided.

The array type is an abstract type that supports the exceptions described below. You can create arrays with make, create, init, tabulate and of_list.

The size of an array is fixed once created. Some operations like append, concat and reverse create a new array with a different size.

Array elements can be any OCaml values, including functional values.

A data race occurs when two threads (or domains) access the same memory location concurrently, and at least one of the accesses is a write. In the absence of data races, the observed behaviour is equivalent to some sequential interleaving of the operations from different domains.

Whenever possible, data races should be avoided by using synchronization to mediate the accesses to the array elements.

Indeed, in the presence of data races, programs will not crash but the observed behaviour may not be equivalent to any sequential interleaving of operations from different domains. Nevertheless, even in the presence of data races, a read operation will return the value of some prior write to that location (with a few exceptions for float arrays).

Float arrays

Float arrays have two supplementary caveats in the presence of data races.

First, the blit operation might copy an array byte-by-byte. Data races between such a blit operation and another operation might produce surprising values due to tearing: partial writes interleaved with other operations can create float values that would not exist with a sequential execution.

For instance, at the end of

let zeros = Array.make size 0.
let max_floats = Array.make size Float.max_float
let res = Array.copy zeros
let d1 = Domain.spawn (fun () -> Array.blit zeros 0 res 0 size)
let d2 = Domain.spawn (fun () -> Array.blit max_floats 0 res 0 size)
let () = Domain.join d1; Domain.join d2
the res array might contain values that are neither 0. nor max_float .

Second, on 32-bit architectures, getting or setting a field involves two separate memory accesses. In the presence of data races, the user may observe tearing on any operation.
