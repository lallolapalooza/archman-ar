strnunvis(3bsd)

الحزمة: libbsd

التراخيص: custom

unvis(3bsd) 3bsd unvis(3bsd)

الاسم

unvis، strunvis، strnunvis، strunvisx، strnunvisx — فك ترميز تمثيل مرئي للأحرف

المكتبة

المكتبة "libbsd"

الملخص

#include <vis.h> (انظر libbsd(7) لاستخدام التضمين.)
int
unvis(char *cp, int c, int *astate, int flag);

int
strunvis(char *dst, const char *src);

int
strnunvis(char *dst, size_t dlen, const char *src);

int
strunvisx(char *dst, const char *src, int flag);

int
strnunvisx(char *dst, size_t dlen, const char *src, int flag);

الوصف

تُستخدم الدوال unvis()، strunvis()، و strunvisx() لفك ترميز تمثيل مرئي للأحرف، كما تنتجه دالة vis(3bsd)، مرة أخرى إلى شكلها الأصلي.

تُستدعى الدالة unvis() بأحرف متتالية في c حتى يتم التعرف على تسلسل صالح، وعندها يكون الحرف الذي تم فك ترميزه متاحًا في الحرف الذي يشير إليه cp.

تقوم الدالة strunvis() بفك ترميز الأحرف التي يشير إليها src في المخزن المؤقت الذي يشير إليه dst. تقوم الدالة strunvis() ببساطة بنسخ src إلى dst، مع فك ترميز أي تسلسلات هروب على طول الطريق، وتعيد عدد الأحرف التي تم وضعها في dst، أو -1 إذا تم اكتشاف تسلسل هروب غير صالح. يجب أن يكون حجم dst مساويًا لحجم src (أي، لا يحدث توسع أثناء فك الترميز).

تقوم الدالة strunvisx() بنفس عمل الدالة strunvis()، ولكنها تسمح لك بإضافة علامة تحدد نمط التشفير الذي تم تشفير السلسلة src به. حاليًا، العلامات المدعومة هي: VIS_HTTPSTYLE و VIS_MIMESTYLE.

تنفذ الدالة unvis() آلة حالة يمكن استخدامها لفك ترميز أي تدفق بايت. يتم تخزين كل حالة مرتبطة بالبايتات التي يتم فك ترميزها خارج الدالة unvis() (أي، يتم تمرير مؤشر إلى الحالة)، لذلك يمكن خلط استدعاءات فك ترميز التدفقات المختلفة بحرية. لبدء فك ترميز تدفق بايت، قم أولاً بتهيئة عدد صحيح إلى الصفر. استدعِ unvis() مع كل بايت متتابع، جنبًا إلى جنب مع مؤشر إلى هذا العدد الصحيح، ومؤشر إلى حرف وجهة. تحتوي الدالة unvis() على عدة رموز إرجاع يجب التعامل معها بشكل صحيح. وهي:

0 (صفر)
هناك حاجة إلى حرف آخر؛ لم يتم التعرف على شيء بعد.
UNVIS_VALID
تم التعرف على حرف صالح وهو متاح في الموقع الذي يشير إليه cp.
UNVIS_VALIDPUSH
تم التعرف على حرف صالح وهو متاح في الموقع الذي يشير إليه cp؛ ومع ذلك، يجب تمرير الحرف الذي تم تمريره حاليًا مرة أخرى.
UNVIS_NOCHAR
تم اكتشاف تسلسل صالح، ولكن لم يتم إنتاج أي حرف. رمز الإرجاع هذا ضروري للإشارة إلى فاصل منطقي بين الأحرف.
UNVIS_SYNBAD
تم اكتشاف تسلسل هروب غير صالح، أو أن وحدة فك الترميز في حالة غير معروفة. يتم وضع وحدة فك الترميز في حالة البداية.

عندما تتم معالجة جميع البايتات في التدفق، استدعِ unvis() مرة أخرى مع تعيين العلامة إلى UNVIS_END لاستخراج أي حرف متبقي (يتم تجاهل الحرف الذي تم تمريره).

يُستخدم الوسيط flag أيضًا لتحديد نمط تشفير المصدر. إذا تم تعيينه إلى VIS_HTTPSTYLE أو VIS_HTTP1808، فستقوم unvis() بفك ترميز سلاسل URI كما هو محدد في RFC 1808. إذا تم تعيينه إلى VIS_HTTP1866، فستقوم unvis() بفك ترميز مراجع الكيانات ومراجع الأحرف الرقمية كما هو محدد في RFC 1866. إذا تم تعيينه إلى VIS_MIMESTYLE، فستقوم unvis() بفك ترميز سلاسل MIME Quoted-Printable كما هو محدد في RFC 2045. إذا تم تعيينه إلى VIS_NOESCAPE، فلن تقوم unvis() بفك ترميز الأحرف المقتبسة بـ ‘\’.

يوضح جزء التعليمات البرمجية التالي استخدامًا سليمًا لـ unvis().

int state = 0;
char out;

while ((ch = getchar()) != EOF) {
again:
	switch(unvis(&out, ch, &state, 0)) {
	case 0:
	case UNVIS_NOCHAR:
		break;
	case UNVIS_VALID:
		(void)putchar(out);
		break;
	case UNVIS_VALIDPUSH:
		(void)putchar(out);
		goto again;
	case UNVIS_SYNBAD:
		errx(EXIT_FAILURE, "Bad character sequence!");
	}
}
if (unvis(&out, '\0', &state, UNVIS_END) == UNVIS_VALID)
	(void)putchar(out);

الأخطاء

ستعيد الدوال strunvis()، strnunvis()، strunvisx()، و strnunvisx() القيمة -1 عند حدوث خطأ وتعيين errno إلى:

[EINVAL]
تم اكتشاف تسلسل هروب غير صالح، أو أن وحدة فك الترميز في حالة غير معروفة.

بالإضافة إلى ذلك، يمكن للدالتين strnunvis() و strnunvisx() أيضًا تعيين errno عند حدوث خطأ إلى:

[ENOSPC]
لا توجد مساحة كافية لإجراء التحويل.

strnunvis(3bsd) — archlinux man pages

NAME

strnunvis, strnunvisx — convert printable representation of a character or string to raw form

LIBRARY

Libbsd-compat (-lbsd-compat)

SYNOPSIS

#include <bsd/vis.h>

int
strnunvis(char *buf, const char *str, size_t size, int flag);
int
strnunvisx(char *buf, const char *str, size_t size, int flag);

DESCRIPTION

The strnunvis() and strnunvisx() functions convert a string str containing printable characters, according to the rules specified by flag, into a raw string that is stored into buf. The destination buffer must be at least size bytes long. The null terminator is not included in the count of size bytes. The functions return the number of bytes stored into buf, not including the terminating null byte.

If the input string cannot be converted into the destination buffer, buf will contain a partially converted string, and the functions will return -1. The remaining space in buf is filled with null bytes if possible.

The flag argument is a bitmask that controls the conversion. The following flags are available:

VIS_DQ
Escape sequences starting with double quotes (") are decoded.
VIS_CSTYLE
Escape sequences starting with backslash (\) are decoded.
VIS_SPUNVIS
Space characters ( ) are converted to the characters “\s”.
VIS_NL
Newline characters (‘\n’) are converted to the characters “\n”.
VIS_TAB
Tab characters (‘\t’) are converted to the characters “\t”.
VIS_WHITE
All whitespace characters are converted to the characters “\s”.
VIS_ALL
All non-graphic characters are converted to the characters “\n”.
VIS_SAFE
The output string is safe to be used in a C string initializer.
VIS_HTTP1808
The output string is safe to be used in HTTP Basic Authentication header.
VIS_HTTP1866
The output string is safe to be used in HTTP Digest Authentication header.

strnunvis() is equivalent to strnunvisx() with the VIS_HTTP1808 and VIS_HTTP1866 flags enabled.

ERRORS

A return value of -1 indicates that the input string could not be fully converted into the destination buffer.

SEE ALSO

vis(3), strvis(3)

HISTORY

The strnunvis() and strnunvisx() functions first appeared in FreeBSD 4.4. The strnunvis() and strnunvisx() functions appeared in NetBSD 6.0.

BUGS

The names VIS_HTTP1808 and VIS_HTTP1866 are wrong. Percent-encoding was defined in RFC 1738, the original RFC for URL. RFC 1866 defines HTML 2.0, an application of SGML, from which it inherits concepts of numeric character references and entity references.
