Detailed Description

An unordered_map is a hash table-based associative container that allows for the storage of key-value pairs. It is part of the C++ Standard Library and is defined in the `<unordered_map>` header.

\n

The main characteristic of an unordered_map is its average constant time complexity for element insertion, deletion, and lookup. This is achieved by using a hash function to compute an index into an array of buckets, where the elements are stored.

\n

Key characteristics:

\n
  • Unordered: Elements are not stored in any particular order. The order may change as elements are inserted or removed.
  • Unique Keys: Each key in the map must be unique. If a duplicate key is inserted, the insertion operation may be ignored or might replace the existing element depending on the specific insertion function used.
  • Key-Value Pairs: Stores elements as pairs, where each pair consists of a key and a mapped value.
  • Hashable Keys: Keys must be hashable, meaning a hash function can be applied to them to determine their bucket. The default hash function is `std::hash<_Key>`.
  • Equality Comparable Keys: Keys must be comparable for equality using an equality predicate. The default predicate is `std::equal_to<_Key>`.
\n

Use Cases:

\n
  • Implementing dictionaries or symbol tables.
  • Fast lookups of associated values based on a key.
  • Caching mechanisms where quick retrieval of cached data is essential.
\n

Complexity:

\n
  • Average case for insertion, deletion, and lookup: O(1)
  • Worst case for insertion, deletion, and lookup: O(N), where N is the number of elements in the map. This occurs in the case of many hash collisions.
\n

The performance of an unordered_map is heavily dependent on the quality of the hash function and the load factor.
