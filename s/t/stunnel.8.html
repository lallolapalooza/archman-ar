إذا لم يتم تحديد مضيف، فسيكون المضيف الافتراضي هو localhost.

يُسمح بخيارات connect متعددة في قسم خدمة واحد. إذا تم حل المضيف إلى عناوين متعددة و/أو إذا تم تحديد خيارات connect متعددة، فسيتم اختيار العنوان البعيد باستخدام خوارزمية التوزيع الدائري.

CRLpath = DIRECTORY
دليل قوائم إلغاء الشهادات

هذا هو الدليل الذي سيبحث فيه stunnel عن CRLs عند استخدام خيارات verifyChain و verifyPeer. لاحظ أن CRLs في هذا الدليل يجب أن تسمى XXXXXXXX.r0 حيث XXXXXXXX هي قيمة تجزئة CRL.

تم تغيير خوارزمية التجزئة في OpenSSL 1.0.0. مطلوب c_rehash الدليل عند الترقية من OpenSSL 0.x.x إلى OpenSSL 1.x.x.

مسار CRLpath نسبي إلى دليل chroot إذا تم تحديده.

يسمح لك هذا المعرف بتمييز إدخالات السجل التي تم إنشاؤها لكل اتصال.

الأنواع المدعومة حاليًا:

sequential
المعرف التسلسلي الرقمي فريد فقط ضمن مثيل واحد من stunnel، ولكنه موجز جدًا. إنه مفيد جدًا لتحليل السجلات اليدوي.
unique
هذا المعرف الأبجدي الرقمي فريد عالميًا، ولكنه أطول من الرقم التسلسلي. إنه مفيد جدًا لتحليل السجلات الآلي.
thread
معرف خيط نظام التشغيل ليس فريدًا (حتى ضمن مثيل واحد من stunnel) وليس قصيرًا. إنه مفيد جدًا لتصحيح أخطاء البرامج أو مشكلات التكوين.
process
معرف عملية نظام التشغيل (PID) قد يكون مفيدًا في وضع inetd.

الافتراضي: sequential

debug = LEVEL
مستوى التصحيح

المستوى هو أحد أسماء أو أرقام مستوى syslog: emerg (0)، alert (1)، crit (2)، err (3)، warning (4)، notice (5)، info (6)، أو debug (7). سيتم عرض جميع السجلات للمستوى المحدد وجميع المستويات الأقل منه رقميًا. الافتراضي هو notice (5).

في حين أن مستوى debug = debug أو debug = 7 يولد أكثر إخراج تفصيلي، إلا أنه مخصص فقط لمطوري stunnel. يرجى استخدام هذه القيمة فقط إذا كنت مطورًا، أو تنوي إرسال سجلاتك إلى دعمنا الفني. بخلاف ذلك، ستكون السجلات التي تم إنشاؤها مربكة.

delay = yes | no

هذا الخيار مفيد لـ DNS الديناميكي، أو عندما لا يكون DNS متاحًا أثناء بدء تشغيل stunnel (VPN مسافر، تكوينات الاتصال الهاتفي).

يتم تفعيل وضع محلل التأخير تلقائيًا عندما يفشل stunnel في حل أي من أهداف connect عند بدء التشغيل لأي خدمة.

محلل التأخير يفرض failover = prio.

الافتراضي: yes

options = SSL_OPTIONS
خيارات مكتبة OpenSSL

المعلم هو اسم خيار OpenSSL كما هو موضح في صفحة الدليل SSL_CTX_set_options(3ssl)، ولكن بدون بادئة SSL_OP_. stunnel -options يسرد الخيارات التي تم العثور عليها لتكون مسموحًا بها في التركيبة الحالية لـ stunnel ومكتبة OpenSSL المستخدمة لبنائه.

يمكن استخدام عدة أسطر option لتحديد خيارات متعددة. يمكن أن يسبق اسم الخيار شرطة ("-") لتعطيل الخيار.

على سبيل المثال، للتوافق مع تطبيق Eudora TLS الخاطئ، يمكن استخدام الخيار التالي:

options = DONT_INSERT_EMPTY_FRAGMENTS

الافتراضي:

options = NO_SSLv2
options = NO_SSLv3

استخدم خيار sslVersionMax أو sslVersionMin بدلاً من تعطيل إصدارات بروتوكول TLS المحددة عند التجميع باستخدام OpenSSL 1.1.0 أو أحدث.

protocol = PROTO
بروتوكول التطبيق للتفاوض على TLS

يمكّن هذا الخيار التفاوض الأولي الخاص بالبروتوكول لتشفير TLS. لا ينبغي استخدام خيار protocol مع تشفير TLS على منفذ منفصل.

الحزمة: stunnel

التراخيص: GPL-2.0-or-later

NAME

stunnel — generic TLS/SSL wrapper

SYNOPSIS

stunnel [OPTION…]

DESCRIPTION

stunnel is a proxy daemon that allows you to secure arbitrary TCP connections with SSL/TLS. It can be used to add TLS encryption to applications that do not natively support it. stunnel can be configured to use either a single-daemon mode or a multi-daemon mode.

OPTIONS

See stunnel.conf(5) for a list of all configuration options.

CONFIGURATION FILE

See stunnel.conf(5).

RETURN VALUE

The exit code is 0 on success, and a non-zero value on error.

SIGNALS

SIGHUP
Reloads the configuration file. This will cause all running child processes to be terminated and replaced with new ones. Active connections will be dropped.
SIGTERM
Graceful shutdown. All active connections will be dropped.
SIGINT
Immediate shutdown. All active connections will be dropped.

EXAMPLES

# Example configuration file (stunnel.conf)
pid = /var/run/stunnel.pid
output = /var/log/stunnel.log

setuid = nobody
setgid = nobody

cert = /etc/stunnel/stunnel.pem

[pop3s]
accept = 995
connect = 110

[imaps]
accept = 993
connect = 143

[https]
accept = 443
connect = 8080

NOTES

PRIVATE KEY AND CERTIFICATE

Your private key and certificate must be combined in one file, usually named stunnel.pem. The private key must not be passphrase protected.

-----BEGIN RSA PRIVATE KEY-----
[encoded key]
-----END RSA PRIVATE KEY-----
-----BEGIN CERTIFICATE-----
[encoded certificate]
-----END CERTIFICATE-----

RANDOMNESS

stunnel needs to seed the PRNG (pseudo-random number generator) in order for TLS to use good randomness. The following sources are loaded in order until sufficient random data has been gathered:

  • The file specified with the RNDfile flag.
  • The file specified by the RANDFILE environment variable, if set.
  • The file .rnd in your home directory, if RANDFILE not set.
  • The file specified with '--with-random' at compile time.
  • The contents of the screen if running on Windows.
  • The egd socket specified with the EGD flag.
  • The egd socket specified with '--with-egd-sock' at compile time.
  • The /dev/urandom device.

Note that on Windows machines that do not have console user interaction (mouse movements, creating windows, etc.) the screen contents are not variable enough to be sufficient, and you should provide a random file for use with the RNDfile flag.

Note that the file specified with the RNDfile flag should contain random data -- that means it should contain different information each time stunnel is run. This is handled automatically unless the RNDoverwrite flag is used. If you wish to update this file manually, the openssl rand command in recent versions of OpenSSL, would be useful.

Important note: If /dev/urandom is available, OpenSSL often seeds the PRNG with it while checking the random state. On systems with /dev/urandom OpenSSL is likely to use it even though it is listed at the very bottom of the list above. This is the behaviour of OpenSSL and not stunnel.

DH PARAMETERS

stunnel 4.40 and later contains hardcoded 2048-bit DH parameters. Starting with stunnel 5.18, these hardcoded DH parameters are replaced every 24 hours with autogenerated temporary DH parameters. DH parameter generation may take several minutes.

Alternatively, it is possible to specify static DH parameters in the certificate file, which disables generating temporary DH parameters:

openssl dhparam 2048 >> stunnel.pem

BUGS

The execArgs option and the Win32 command line do not support quoting.
