أنواع العناصر

يمكن أن تحتوي Bigarrays على عناصر من الأنواع التالية:

-أرقام الفاصلة العائمة بنصف دقة IEEE (16 بت) ( Bigarray.float16_elt )،

-أرقام الفاصلة العائمة بدقة IEEE واحدة (32 بت) ( Bigarray.float32_elt )،

-أرقام الفاصلة العائمة بدقة IEEE مزدوجة (64 بت) ( Bigarray.float64_elt )،

-أعداد مركبة من الفاصلة العائمة بدقة IEEE واحدة (2 * 32 بت) ( Bigarray.complex32_elt )،

-أعداد مركبة من الفاصلة العائمة بدقة IEEE مزدوجة (2 * 64 بت) ( Bigarray.complex64_elt )،

-أعداد صحيحة 8 بت (موقعة أو غير موقعة) ( Bigarray.int8_signed_elt أو Bigarray.int8_unsigned_elt )،

-أعداد صحيحة 16 بت (موقعة أو غير موقعة) ( Bigarray.int16_signed_elt أو Bigarray.int16_unsigned_elt )،

-أعداد صحيحة OCaml (موقعة، 31 بت على معماريات 32 بت، 63 بت على معماريات 64 بت) ( Bigarray.int_elt )،

-أعداد صحيحة موقعة 32 بت ( Bigarray.int32_elt )،

-أعداد صحيحة موقعة 64 بت ( Bigarray.int64_elt )،

-أعداد صحيحة موقعة أصلية للمنصة (32 بت على معماريات 32 بت، 64 بت على معماريات 64 بت) ( Bigarray.nativeint_elt ).

يتم تمثيل كل نوع عنصر على مستوى النوع بأحد أنواع *_elt المعرفة أدناه (معرفة بمُنشئ واحد بدلاً من أنواع مجردة لأسباب حقنية تقنية).

لكل نوع عنصر، يرتبط به نوع OCaml، وهو نوع قيم OCaml التي يمكن تخزينها في Bigarray أو قراءتها منه. هذا النوع ليس بالضرورة نفس نوع عناصر المصفوفة نفسها: على سبيل المثال، يحتوي Bigarray الذي تكون عناصره من نوع float32_elt على أرقام فاصلة عائمة بدقة واحدة 32 بت، ولكن قراءة أو كتابة أحد عناصره من OCaml تستخدم نوع OCaml float ، وهو أرقام فاصلة عائمة بدقة مزدوجة 64 بت.

يُلتقط نوع GADT ('a, 'b) kind هذا الارتباط لنوع OCaml 'a للقيم المقروءة أو المكتوبة في Bigarray، ونوع العنصر 'b الذي يمثل المحتوى الفعلي لـ Bigarray. يسرد مُنشئوه جميع الارتباطات الممكنة لأنواع OCaml مع أنواع العناصر، ويتم إعادة تصديرها أدناه لأسباب التوافق الرجعي.

استخدام نوع بيانات جبري معمّم (GADT) هنا يسمح بكتابة دوال متعددة الأشكال جيدة النوع يكون نوعها الراجع يعتمد على نوع المعامل، مثل:

  let zero : type a b. (a, b) kind -> a = function
    | Float32 -> 0.0 | Complex32 -> Complex.zero
    | Float64 -> 0.0 | Complex64 -> Complex.zero
    | Float16 -> 0.0
    | Int8_signed -> 0 | Int8_unsigned -> 0
    | Int16_signed -> 0 | Int16_unsigned -> 0
    | Int32 -> 0l | Int64 -> 0L
    | Int -> 0 | Nativeint -> 0n
    | Char -> '\000'

لتسهيل التوافق مع التعليمات البرمجية الحالية بلغة C و Fortran، تدعم هذه المكتبة نوعين مختلفين من تخطيطات الذاكرة لـ Bigarrays، أحدهما متوافق مع اصطلاحات C، والآخر متوافق مع اصطلاحات Fortran.

في تخطيط نمط C، تبدأ فهارس المصفوفة من 0، ويتم وضع المصفوفات متعددة الأبعاد بتنسيق الصف الرئيسي (row-major). أي، بالنسبة لمصفوفة ثنائية الأبعاد، تكون جميع عناصر الصف 0 متجاورة في الذاكرة، تليها جميع عناصر الصف 1، إلخ. بمعنى آخر، تكون عناصر المصفوفة عند (x,y) و (x, y+1) متجاورة في الذاكرة.

في تخطيط نمط Fortran، تبدأ فهارس المصفوفة من 1، ويتم وضع المصفوفات متعددة الأبعاد بتنسيق العمود الرئيسي (column-major). أي، بالنسبة لمصفوفة ثنائية الأبعاد، تكون جميع عناصر العمود 1 متجاورة في الذاكرة، تليها جميع عناصر العمود 2، إلخ. بمعنى آخر، تكون عناصر المصفوفة عند (x,y) و (x+1, y) متجاورة في الذاكرة.

Module Bigarray

Arrays with at least one dimension, with optional hardware support.

The Bigarray module provides arrays of values of a fixed size, with elements of a basic type (int, float, etc.). The main purpose of these arrays is to interface with external libraries that use C arrays, but they are also useful for numerical computations when performance is critical.

Bigarrays are implemented as C arrays. They offer several advantages over the standard OCaml arrays:

  • Performance: Bigarrays are typically more efficient than OCaml arrays, especially for numerical computations. They can be allocated on the heap or the stack (using the Array1.init and Array1.create functions), and they can be accessed directly from C code.
  • Multi-dimensional arrays: Bigarrays support multi-dimensional arrays, up to 3 dimensions in the fixed-dimension modules (Array2, Array3), and arbitrarily many dimensions in the generic module (Genarray).
  • Layout control: Bigarrays allow you to choose between C-style and Fortran-style memory layouts.

The Bigarray module is divided into several submodules:

  • Genarray: Generic Bigarrays with an arbitrary number of dimensions.
  • Array0, Array1, Array2, Array3: Bigarrays with a fixed number of dimensions (0, 1, 2, or 3). These modules offer more specialized and potentially faster operations due to the statically known number of dimensions.

The module also defines two phantom types, Bigarray.c_layout and Bigarray.fortran_layout, to distinguish between C-style and Fortran-style memory layouts.

Note on concurrent access: Bigarrays are not inherently thread-safe. Concurrent access from multiple domains can lead to data races and tearing, resulting in unexpected behavior. If concurrent access is required, proper synchronization mechanisms (e.g., mutexes) must be implemented by the user.

Memory layout

The elements of a Bigarray can be laid out in memory according to one of two schemes: C-style or Fortran-style.

In C-style layout (Bigarray.c_layout), for a two-dimensional array, all elements of row 0 are contiguous in memory, followed by all elements of row 1, etc. In other terms, the array elements at (x,y) and (x, y+1) are adjacent in memory.

In Fortran-style layout (Bigarray.fortran_layout), for a two-dimensional array, all elements of column 0 are contiguous in memory, followed by all elements of column 1, etc. In other terms, the array elements at (x,y) and (x+1, y) are adjacent in memory.

Each layout style is identified at the type level by the phantom types Bigarray.c_layout and Bigarray.fortran_layout respectively.

Supported layouts

The GADT type 'a layout represents one of the two supported memory layouts: C-style or Fortran-style. Its constructors are re-exported as values below for backward-compatibility reasons.

type 'a layout =
| C_layout : c_layout layout
| Fortran_layout : fortran_layout layout

Re-shaping Bigarrays

val reshape : ('a, 'b, 'c) Genarray.t -> int array -> ('a, 'b, 'c) Genarray.t

reshape b [|d1;...;dN|] converts the Bigarray b to a N -dimensional array of dimensions d1 ... dN . The returned array and the original array b share their data and have the same layout. For instance, assuming that b is a one-dimensional array of dimension 12, reshape b [|3;4|] returns a two-dimensional array b' of dimensions 3 and 4. If b has C layout, the element (x,y) of b' corresponds to the element x * 3 + y of b . If b has Fortran layout, the element (x,y) of b' corresponds to the element x + (y - 1) * 4 of b . The returned Bigarray must have exactly the same number of elements as the original Bigarray b . That is, the product of the dimensions of b must be equal to i1 * ... * iN . Otherwise, Invalid_argument is raised.

Bigarrays and concurrency safety

Care must be taken when concurrently accessing bigarrays from multiple domains: accessing a bigarray will never crash a program, but unsynchronized accesses might yield surprising (non-sequentially-consistent) results.

Atomicity

Every bigarray operation that accesses more than one array element is not atomic. This includes slicing, bliting, and filling bigarrays.

For example, consider the following program:

open Bigarray
let size = 100_000_000
let a = Array1.init Int C_layout size (fun _ -> 1)
let update f a () =
  for i = 0 to size - 1 do a.{i} <- f a.{i} done
let d1 = Domain.spawn (update (fun x -> x + 1) a)
let d2 = Domain.spawn (update (fun x -> 2 * x + 1) a)
let () = Domain.join d1; Domain.join d2

After executing this code, each field of the bigarray a is either 2 , 3 , 4 or 5 . If atomicity is required, then the user must implement their own synchronization (for example, using Mutex.t ).

Data races

If two domains only access disjoint parts of the bigarray, then the observed behaviour is the equivalent to some sequential interleaving of the operations from the two domains.

A data race is said to occur when two domains access the same bigarray element without synchronization and at least one of the accesses is a write. In the absence of data races, the observed behaviour is equivalent to some sequential interleaving of the operations from different domains.

Whenever possible, data races should be avoided by using synchronization to mediate the accesses to the bigarray elements.

Indeed, in the presence of data races, programs will not crash but the observed behaviour may not be equivalent to any sequential interleaving of operations from different domains.

Tearing

Bigarrays have a distinct caveat in the presence of data races: concurrent bigarray operations might produce surprising values due to tearing. More precisely, the interleaving of partial writes and reads might create values that would not exist with a sequential execution. For instance, at the end of

let res = Array1.init Complex64 c_layout size (fun _ -> Complex.zero)
let d1 = Domain.spawn (fun () -> Array1.fill res Complex.one)
let d2 = Domain.spawn (fun () -> Array1.fill res Complex.i)
let () = Domain.join d1; Domain.join d2

the res bigarray might contain values that are neither Complex.i nor Complex.one (for instance 1 + i ).
