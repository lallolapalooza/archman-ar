strfmon(3p)

STRFMON(3P) translates a monetary value into a character string.

SYNOPSIS

#include <monetary.h>

size_t strfmon(char *restrict s, size_t maxwc,
               const char *restrict format, ...);

DESCRIPTION

The strfmon() function shall convert a monetary value into a character string according to the format string pointed to by format. The result is written into the character array pointed to by s. No more than maxwc characters (including the terminating null byte) will be written to s.

The format string is a null-terminated string that may contain:

  • Ordinary characters, which are copied directly to the output string.
  • Escape sequences, which are converted to the corresponding characters.
  • Format specifiers, which are introduced by the '%' character.

Format specifiers have the following general format:

%[flags][width][.precision]specifier

The specifiers are:

  • i: The character set is the user's locale monetary characters.
  • m: The character set is the user's locale monetary characters, with currency symbol.
  • x: The character set is the user's locale monetary characters, with currency symbol and grouping.

The strfmon() function supports the following flags:

  • =: Use the locale's default currency symbol.
  • !: Use the locale's international currency symbol.
  • ^: Do not use the locale's thousands separator.
  • +: Display the sign for positive values.
  • -: Display the sign for negative values.

The width and precision fields are optional and specify the minimum width of the output field and the number of digits to the left and right of the decimal point, respectively.

RETURN VALUE

Upon successful completion, strfmon() shall return the number of characters written to s, excluding the terminating null byte. If an output error occurs, strfmon() shall return (size_t) -1 and set errno to indicate the error.

ERRORS

ENOMEM
Not enough memory available.
ERANGE
The value to be converted is out of range.

STANDARDS

The strfmon() function is part of the X/Open Portability Guide, Issue 4, and is also specified in POSIX.1-2001.
