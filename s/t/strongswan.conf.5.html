الاسم

strongswan.conf - ملف تكوين strongSwan

الوصف

بينما يعتبر ملف التكوين ipsec.conf(5) مناسبًا لتعريف معلمات التكوين المتعلقة بـ IPsec، إلا أنه ليس مفيدًا للتطبيقات الأخرى في strongSwan لقراءة الخيارات من هذا الملف. الملف يصعب تحليله وipsec starter فقط هو القادر على ذلك. مع تزايد عدد مكونات مشروع strongSwan باستمرار، كانت هناك حاجة إلى ملف تكوين أكثر مرونة، يمكن توسيعه بسهولة ويمكن استخدامه من قبل جميع المكونات. مع strongSwan 4.2.1، تم تقديم strongswan.conf(5) الذي يلبي هذه المتطلبات.

الصياغة

يتكون تنسيق ملف strongswan.conf من أقسام هرمية وقائمة من أزواج المفتاح/القيمة في كل قسم. كل قسم له اسم، يليه أقواس معقوفة بأسلوب C تحدد جسم القسم. يحتوي كل جسم قسم على مجموعة من الأقسام الفرعية وأزواج المفتاح/القيمة:

settings := (section|keyvalue)*
section  := name { settings }
keyvalue := key = value\n

يجب إنهاء القيم بسطر جديد.

التعليقات ممكنة باستخدام حرف #.

قد تحتوي أسماء الأقسام والمفاتيح على أي حرف قابل للطباعة باستثناء:

. , : { } = " # \n \t space

قد يبدو ملف مثال بهذا التنسيق كما يلي:

a = b
section-one {
	somevalue = asdf
	subsection {
		othervalue = xxx
	}
	# نعم، تعليق
	yetanother = zz
}
section-two {
	x = 12
}

المسافة البادئة اختيارية، يمكنك استخدام علامات الجدولة أو المسافات.

تنسيقات الأرقام

يمكن تحديد الخيارات التي تحدد قيمة عدد صحيح على أنها عشرية (الافتراضي) أو سداسية عشرية (بادئة "0x"، يتم قبول الأحرف الكبيرة أو الصغيرة). قد يتم أيضًا قبول السلاسل النصية المعتمدة على اللغة المحلية (مثل فاصل الآلاف للمنطقة المحلية الحالية) في مناطق محلية غير "C".

يمكن تحديد الخيارات التي تحدد قيمة عدد عشري على أنها عشرية (الافتراضي) أو سداسية عشرية (بادئة "0x"، يتم قبول الأحرف الكبيرة أو الصغيرة). حرف القاعدة (الفاصل العشري) في كلتا الحالتين يعتمد على المنطقة المحلية، وعادة ما يكون ".".

تنسيقات الوقت

ما لم يُذكر خلاف ذلك، يتم تحديد الخيارات التي تحدد وقتًا بالثواني. قد يتم استخدام اللاحقات "s" و "m" و "h" و "d" لتحويل القيم المعطاة بالثواني أو الدقائق أو الساعات أو الأيام تلقائيًا (على سبيل المثال، بدلاً من تكوين وقت إعادة التشفير لمدة 4 ساعات كـ "14400" ثانية، يمكن استخدام "4h").

هناك بعض الخيارات العامة التي لا تقبل هذه اللاحقات لأنها مهيأة كقيم عددية صحيحة بالثواني أو المللي ثانية، أو حتى كأرقام عشرية (مثل مهلة إعادة الإرسال). الخيارات التي تقبل اللاحقات لها قيمة افتراضية مقابلة.

الإشارة إلى أقسام أخرى

من الممكن وراثة الإعدادات والأقسام من قسم آخر. هذه الميزة مفيدة بشكل أساسي في swanctl.conf (الذي يستخدم نفس تنسيق الملف). الصياغة كما يلي:

section    := name : references { settings }
references := absname[, absname]*
absname    := name[.name]*

سيتم وراثة جميع أزواج المفتاح/القيمة وجميع الأقسام الفرعية للأقسام المشار إليها باسمها المطلق. يمكن تجاوز القيم في القسم أو أي من أقسامه الفرعية (استخدم تعيينًا فارغًا لمسح قيمة بحيث يتم تطبيق قيمتها الافتراضية، إن وجدت). لا يمكن حاليًا تحديد مستوى التضمين أو مسح/إزالة الأقسام الفرعية الموروثة.

إذا كان الترتيب مهمًا (على سبيل المثال، لجولات المصادقة في اتصال، إذا لم يتم استخدام round)، فيجب ملاحظة أن الإعدادات/الأقسام الموروثة ستتبع تلك المعرفة في القسم الحالي (إذا تم الإشارة إلى أقسام متعددة، فسيتم تعداد إعداداتها من اليسار إلى اليمين).

يتم تقييم الإشارات ديناميكيًا في وقت التشغيل، لذلك لا توجد مشكلة في الإشارة إلى الأقسام لاحقًا في ملف التكوين أو تضمينها عبر ملفات أخرى.

إليك مثال على كيفية ظهور ذلك:

conn-defaults {
	# إعدادات افتراضية لجميع الاتصالات (على سبيل المثال، شهادة، أو مجموعات IP)
}
eap-defaults {
	# قيم افتراضية إذا تم استخدام EAP (على سبيل المثال، جولة مصادقة بعيدة)
}
child-defaults {
	# قيم افتراضية لتكوينات الأطفال (على سبيل المثال، محددات حركة المرور)
}
connections {
	conn-a : conn-defaults, eap-defaults {
		# تعيين/تجاوز الأشياء الخاصة بهذا الاتصال
		children {
			child-a : child-defaults {
				# تعيين/تجاوز الأشياء الخاصة بهذا الطفل
			}
		}
	}
	conn-b : conn-defaults {
		# تعيين/تجاوز الأشياء الخاصة بهذا الاتصال
		children {
			child-b : child-defaults {
				# تعيين/تجاوز الأشياء الخاصة بهذا الطفل
			}
		}
	}
	conn-c : connections.conn-a {
		# كل شيء موروث، بما في ذلك كل شيء ترثه conn-a
		# بالفعل من الأقسام التي تشير إليها هي وأقسامها الفرعية
	}
}

تضمين الملفات

باستخدام عبارة include، من الممكن تضمين ملفات أخرى في strongswan.conf، على سبيل المثال:

include /some/path/*.conf

إذا لم يكن اسم الملف مسارًا مطلقًا، فيعتبر نسبيًا لمجلد الملف الذي يحتوي على عبارة التضمين. قد يتضمن اسم الملف أحرف بدل عامة (انظر sh(1)). أيضًا، يمكن تداخل هذه التضمينات.

تُقوم الأقسام المحملة من الملفات المضمنة بتوسيع الأقسام المحملة سابقًا؛ يتم استبدال القيم الموجودة بالفعل. من المهم ملاحظة أن الإعدادات تضاف بالنسبة للقسم الذي توجد فيه عبارة التضمين.

على سبيل المثال، الملفات الثلاثة التالية تؤدي إلى نفس التكوين النهائي مثل الملف المذكور أعلاه:

	a = b
	section-one {
		somevalue = before include
		include include.conf
	}
	include other.conf
include.conf:
	# يتم إضافة الإعدادات المحملة من هذا الملف إلى section-one
	# هذا يستبدل القيمة السابقة
	somevalue = asdf
	subsection {
		othervalue = yyy
	}
	yetanother = zz
other.conf:
	# هذا يوسع section-one و subsection
	section-one {
		subsection {
			# هذا يستبدل القيمة السابقة
			othervalue = xxx
		}
	}
	section-two {
		x = 12
}

قراءة القيم

يتم الوصول إلى القيم باستخدام قائمة أقسام مفصولة بنقاط ومفتاح. بالإشارة إلى المثال أعلاه، سيؤدي الوصول إلى section-one.subsection.othervalue إلى إرجاع xxx.

LOGGER CONFIGURATION

Options in strongswan.conf(5) provide a much more flexible way to configure loggers for the IKE daemon charon than using the charondebug option in ipsec.conf(5).

Note: If any loggers are specified in strongswan.conf, charondebug does not have any effect.

There are currently two types of loggers:

File loggers
Log directly to a file and are defined by specifying an arbitrarily named subsection in the charon.filelog section. The full path to the file is configured in the path setting of that subsection, however, if it only contains characters permitted in section names, the setting may also be omitted and the path specified as name of the subsection. To log to the console the two special filenames stdout and stderr may be used.
Syslog loggers
Log into a syslog facility and are defined by specifying the facility to log to as the name of a subsection in the charon.syslog section. The following facilities are currently supported: daemon and auth.

Multiple loggers can be defined for each type with different log verbosity for the different subsystems of the daemon.

Subsystems

dmn
Main daemon setup/cleanup/signal handling
mgr
IKE_SA manager, handling synchronization for IKE_SA access
ike
IKE_SA
chd
CHILD_SA
job
Jobs queueing/processing and thread pool management
cfg
Configuration management and plugins
knl
IPsec/Networking kernel interface
net
IKE network communication
asn
Low-level encoding/decoding (ASN.1, X.509 etc.)
enc
Packet encoding/decoding encryption/decryption operations
tls
libtls library messages
esp
libipsec library messages
lib
libstrongswan library messages
tnc
Trusted Network Connect
imc
Integrity Measurement Collector
imv
Integrity Measurement Verifier
pts
Platform Trust Service

Loglevels

-1
Absolutely silent
0
Very basic auditing logs, (e.g. SA up/SA down)
1
تدفق تحكم عام مع الأخطاء، وهو خيار افتراضي جيد لمعرفة ما يحدث يجري
2

مثال

		charon {
			path = /var/log/charon.log

		}
	}

		}

		auth {
			default = -1
			ike = 0
		}
	}
}

إدارة أولوية الوظائف

بعض العمليات في خدمة IKEv2 charon منفذة حاليًا بشكل متزامن وتتسبب في التعليق. مثالان لمثل هذه العمليات هما الاتصال بخادم RADIUS عبر EAP-RADIUS، أو جلب معلومات CRL/OCSP أثناء التحقق من سلسلة الشهادات. في ظل ظروف التحميل العالي، قد تنفد مجموعة مؤشرات الترابط المتاحة، وقد لا يتم تنفيذ بعض الوظائف الأكثر أهمية، مثل فحص الحيوية، في الوقت المناسب.

لمنع تجويع مؤشرات الترابط في مثل هذه المواقف، تم تقديم أولويات الوظائف. ستقوم معالجة الوظائف بحجز بعض مؤشرات الترابط للوظائف ذات الأولوية الأعلى، هذه المؤشرات الترابط غير متاحة للوظائف الأقل أولوية والمانعة.

التنفيذ

حاليًا تم تحديد 4 أولويات، ويتم استخدامها في charon على النحو التالي:

حاسم
أولوية لوظائف الموزع التي تعمل لفترة طويلة.
عالي
تبادل المعلومات، كما هو مستخدم في فحص الحيوية (DPD).
متوسط
كل شيء ليس عالي/منخفض، بما في ذلك معالجة IKE_SA_INIT.
منخفض
معالجة رسالة IKE_AUTH. RADIUS وجلب CRL يتوقفان هنا

على الرغم من أن معالجة IKE_SA_INIT مكلفة حسابيًا، إلا أنها مخصصة صراحةً للفئة المتوسطة. هذا يسمح لـ charon بإجراء تبادل DH بينما تكون مؤشرات الترابط الأخرى معلقة في IKE_AUTH. لمنع الخدمة من قبول المزيد من طلبات IKE_SA_INIT مما يمكنها التعامل معه، استخدم IKE_SA_INIT DROPPING.

تعالج مجموعة مؤشرات الترابط الوظائف بترتيب أولوية صارم، مما يعني أنها ستستهلك جميع الوظائف ذات الأولوية الأعلى قبل البحث عن تلك ذات الأولوية الأدنى. علاوة على ذلك، فإنها تحجز مؤشرات ترابط لأولويات معينة. فئة الأولوية التي تم حجز n مؤشرات ترابط لها ستكون دائمًا متاحة n مؤشرات ترابط لهذه الفئة (إما لمعالجة وظيفة حاليًا، أو في انتظار وظيفة).

التكوين

لضمان وجود عدد كافٍ من مؤشرات الترابط دائمًا للمهام ذات الأولوية الأعلى، يجب حجز مؤشرات ترابط لكل فئة أولوية.

charon.processor.priority_threads.critical [0]
مؤشرات ترابط محجوزة لوظائف فئة الأولوية الحاسمة
charon.processor.priority_threads.high [0]
مؤشرات ترابط محجوزة لوظائف فئة الأولوية العالية
charon.processor.priority_threads.medium [0]
مؤشرات ترابط محجوزة لوظائف فئة الأولوية المتوسطة
charon.processor.priority_threads.low [0]
مؤشرات ترابط محجوزة لوظائف فئة الأولوية المنخفضة

لنفكر في التكوين التالي:

charon {
	processor {
		priority_threads {
			high = 1
			medium = 4
		}
	}
}

مع هذا التكوين، يتم حجز مؤشر ترابط واحد للمهام ذات الأولوية العالية. نظرًا لأن التحقق من الحيوية ومعالجة رسائل stroke تتم حاليًا فقط بأولوية عالية، يجب أن يكون مؤشر ترابط واحد أو اثنين كافيين.

تعالج الفئة المتوسطة معظم الوظائف غير المانعة. ما لم تكن إعداداتك تواجه العديد من التوقفات في الأقفال أثناء الوصول إلى الموارد المشتركة، فإن مؤشرات الترابط لعدد يتراوح بين مرة ومرتين عدد أنوية وحدة المعالجة المركزية يكون مناسبًا.

عادةً لا يلزم حجز مؤشرات ترابط للوظائف الحاسمة. نادرًا ما تعود الوظائف في هذه الفئة وتُرجع مؤشر الترابط الخاص بها إلى المجموعة.

مؤشرات الترابط المتبقية متاحة لوظائف الأولوية المنخفضة. حجز مؤشرات الترابط ليس له معنى (حتى يكون لدينا أولوية أقل).

المراقبة

لمعرفة ما تفعله مؤشرات الترابط فعليًا، قم بتشغيل ipsec statusall. في ظل التحميل العالي، سيظهر شيء مثل هذا:

worker threads: 2 or 32 idle, 5/1/2/22 working,
	job queue: 0/0/1/149, scheduled: 198

من 32 مؤشر ترابط عامل،

2
خامل حاليًا.
5
تقوم بتشغيل وظائف ذات أولوية حاسمة (التوزيع من المقابس، إلخ).
1
تقوم حاليًا بمعالجة وظيفة ذات أولوية عالية. هذا هو فعليًا مؤشر الترابط الذي يوفر حاليًا هذه المعلومات عبر stroke.
2
تقوم بمعالجة وظائف ذات أولوية متوسطة، ربما رسائل IKE_SA_INIT أو CREATE_CHILD_SA.
22
تقوم بمعالجة وظائف ذات أولوية منخفضة، ربما تنتظر استجابة EAP-RADIUS أثناء معالجة رسائل IKE_AUTH.

يُظهر تحميل قائمة انتظار الوظائف عدد الوظائف الموجودة في قائمة الانتظار لكل أولوية، جاهزة للتنفيذ. سيتم تنفيذ مهمة الأولوية المتوسطة الواحدة على الفور، حيث لدينا مؤشران ترابط إضافيان محجوزان لوظائف الفئة المتوسطة.

إسقاط IKE_SA_INIT

إذا تلقى المستجيب طلبات اتصال أكثر في الثانية مما يمكنه التعامل معه، فلا معنى لقبول المزيد من رسائل IKE_SA_INIT. وإذا تم وضعها في قائمة انتظار ولكن لا يمكن معالجتها في الوقت المناسب، فقد يتم إرسال رد بعد أن يكون العميل قد تخلى بالفعل وأعاد إعداد اتصاله. وهذا يزيد بشكل إضافي من الحمل على المستجيب.

للحد من حمل المستجيب الناتج عن محاولات الاتصال الجديدة، يمكن للخدمة إسقاط رسائل IKE_SA_INIT فور استقبالها. هناك آليتان لتحديد ما إذا كان يجب أن يحدث هذا، تم تكوينهما بالخيارات التالية:

charon.init_limit_half_open [0]
الحد بناءً على عدد IKE_SAs نصف المفتوحة. IKE_SAs نصف المفتوحة هي SAs في حالة الاتصال، ولكن لم يتم إنشاؤها بعد.
charon.init_limit_job_load [0]
الحد بناءً على عدد الوظائف الموجودة حاليًا في قائمة الانتظار للمعالجة (المجموع عبر جميع أولويات الوظائف).

يتضمن الحد الثاني الحمل من الوظائف الأخرى، مثل إعادة المفتاح. اختيار قيمة جيدة أمر صعب ويعتمد على الأجهزة والحمل المتوقع.

الحد الأول أبسط في الحساب، ولكنه يتضمن الحمل من الاتصالات الجديدة فقط. إذا كان المستجيب الخاص بك قادرًا على التفاوض على 100 نفق/ثانية، فقد تقوم بتعيين هذا الحد إلى 1000. ستقوم الخدمة بعد ذلك بإسقاط محاولات الاتصال الجديدة إذا كان إنشاء رد يتطلب أكثر من 10 ثوانٍ. إذا كنت تسمح بحد أقصى لوقت الاستجابة يزيد عن 30 ثانية، ففكر في تعديل مهلة IKE_SAs قيد الاتصال (charon.half_open_timeout). افتراضيًا، يقوم المستجيب بحذف IKE_SA إذا لم يقم المبادِر بإنشائها في غضون 30 ثانية. في ظل الحمل العالي، قد تكون هناك حاجة إلى قيمة أعلى.

اختبارات الحمل

لإجراء اختبارات الاستقرار وتحسينات الأداء، توفر خدمة IKE charon ملحق load-tester. يسمح هذا الملحق بإعداد آلاف الأنفاق بشكل متزامن ضد الخدمة نفسها أو ضد مضيف بعيد.

تحذير: لا تقم أبدًا بتمكين ملحق اختبار الحمل على الأنظمة الإنتاجية. يوفر بيانات اعتماد مهيأة مسبقًا ويسمح للمهاجم بالمصادقة كأي مستخدم.

تفاصيل التكوين

للمصادقة بالمفتاح العام، تستخدم المستجيب هوية "CN=srv, OU=load-test, O=strongSwan". بالنسبة للمبادِر، تستخدم كل محاولة اتصال هوية مختلفة في شكل "CN=c1-r1, OU=load-test, O=strongSwan"، حيث يشير الرقم الأول إلى رقم العميل، والثاني إلى جولة المصادقة (إذا تم استخدام جولات مصادقة متعددة).

للمصادقة PSK، يتم استخدام هويات FQDN. يستخدم الخادم srv.strongswan.org، ويستخدم العميل هوية في شكل c1-r1.strongswan.org.

للمصادقة EAP، يستخدم العميل NAI في شكل 100000000010001@strongswan.org.

لتكوين جولات مصادقة متعددة، قم بدمج طرق متعددة باستخدام، على سبيل المثال

initiator_auth = pubkey|psk|eap-md5|eap-aka

تستخدم المستجيب شهادة مرمزة بناءً على مفتاح RSA بقوة 1024 بت. تعمل هذه الشهادة أيضًا كشهادة CA. يستخدم النظير نفس المفتاح الخاص، ولكنه ينشئ شهادات عميل عند الطلب موقعة بواسطة شهادة CA. قم بتثبيت شهادة المستجيب/CA على المضيف البعيد للمصادقة على جميع العملاء.

لتسريع الاختبار، يقوم ملحق اختبار الحمل بتنفيذ تنفيذ Diffie-Hellman خاص يسمى modpnull. عن طريق التعيين

proposal = aes128-sha1-modpnull
يتم استخدام هذا التنفيذ السريع بشكل كبير لـ DH. لا يوفر أي أمان على الإطلاق، ولكنه يسمح بتشغيل الاختبارات دون الحمل الزائد لحساب DH.

أمثلة

في أبسط الحالات، تقوم الخدمة بإنشاء IKE_SAs ضد نفسها باستخدام واجهة الوصول المحلي. سينشئ هذا فعليًا ضعف عدد IKE_SAs، حيث تكون الخدمة مبادرة ومستجيبة لكل IKE_SA في نفس الوقت. ستفشل عملية تثبيت IPsec SAs، حيث يتم تثبيت كل SA مرتين. لمحاكاة السلوك الصحيح، يمكن تمكين واجهة نواة وهمية لا تقوم بتثبيت IPsec SAs على مستوى النواة.

قد يبدو تكوين وصول محلي بسيط كالتالي:

charon {
	# إنشاء IKE_SAs جديدة لكل CHILD_SA لمحاكاة
	# عملاء مختلفين
	reuse_ikesa = no
	# إيقاف تشغيل حماية الإنكار للخدمة
	dos_protection = no
