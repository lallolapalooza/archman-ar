يقول المعيار:

 يمتلك auto_ptr الكائن الذي يحمل مؤشراً إليه. نسخ
 auto_ptr ينسخ المؤشر وينقل الملكية إلى الوجهة. إذا كان أكثر من auto_ptr واحد يمتلك نفس الكائن
 في نفس الوقت، فإن سلوك البرنامج غير محدد.
 تشمل استخدامات auto_ptr توفير
 أمان استثناء مؤقت للذاكرة المخصصة ديناميكياً، ونقل ملكية الذاكرة المخصصة ديناميكياً إلى دالة،
 وإرجاع الذاكرة المخصصة ديناميكياً من دالة. لا يلبي auto_ptr متطلبات CopyConstructible و Assignable
 لعناصر حاويات المكتبة القياسية، وبالتالي فإن إنشاء حاوية مكتبة قياسية باستخدام auto_ptr
 يؤدي إلى سلوك غير محدد.

يشير إلى auto_ptr().

template<typename _Tp> std::auto_ptr< _Tp >::~auto_ptr () [inline]

عندما يخرج auto_ptr عن النطاق، يتم حذف الكائن الذي يملكه. إذا لم يعد يمتلك شيئًا (أي، get() هو NULL)، فلن يكون لهذا أي تأثير.

يقول معيار C++ أنه من المفترض أن يكون هناك مواصفات رمي فارغة هنا، ولكن إهمالها يعتبر متوافقًا مع المعيار. لا يمكن اكتشاف وجودها إلا إذا كان _Tp::~_Tp() يرمي استثناءً، ولكن هذا محظور. [17.4.3.6]/2

template<typename _Tp> std::auto_ptr< _Tp >::auto_ptr (auto_ptr_ref< element_type > __ref) [inline]

تحويلات تلقائية. يُفترض أن تقوم هذه العمليات بتحويل auto_ptr إلى وإلى auto_ptr_ref حسب الحاجة. سيسمح هذا بإنشاءات مثل

auto_ptr<Derived>  func_returning_auto_ptr(.....);
...
auto_ptr<Base> ptr = func_returning_auto_ptr(.....);

لكنها لا تعمل، ولن يتم إصلاحها. لمزيد من التفاصيل انظر https://cplusplus.github.io/LWG/lwg-closed.html#463

Detailed Description

The class template std::auto_ptr declares an object that manages a dynamically allocated object. When an auto_ptr object goes out of scope, it automatically deletes the managed object.

This class template is deprecated, and will be removed in a future version of C++. It is recommended to use std::unique_ptr, std::shared_ptr, or std::weak_ptr instead.
