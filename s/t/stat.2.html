stat, fstat, lstat, fstatat - الحصول على حالة الملف

المكتبة

مكتبة C القياسية (libc، -lc)

الملخص

int stat(const char *restrict path,
         struct stat *restrict statbuf);
int fstat(int fd, struct stat *statbuf);
int lstat(const char *restrict path,

#include <sys/stat.h>
int fstatat(int dirfd, const char *restrict path,

الوصف

تُرجع هذه الاستدعاءات معلومات حول ملف، في المخزن المؤقت الذي يشير إليه statbuf. لا يلزم أي أذونات على الملف نفسه، ولكن — في حالة stat() و fstatat() و lstat() — يلزم إذن التنفيذ (البحث) على جميع الدلائل في path التي تؤدي إلى الملف.

stat() و fstatat() تسترجعان معلومات حول الملف الذي يشير إليه path؛ الاختلافات لـ fstatat() موصوفة أدناه.

lstat() مماثلة لـ stat()، إلا أنه إذا كان path رابطًا رمزيًا (symbolic link)، فإنه يُرجع معلومات حول الرابط نفسه، وليس الملف الذي يشير إليه الرابط.

fstat() مماثلة لـ stat()، إلا أن الملف الذي سيتم استرجاع المعلومات حوله يتم تحديده بواسطة واصف الملف fd.

بنية stat

تقوم جميع استدعاءات النظام هذه بإرجاع بنية stat (انظر stat(3type)).

ملاحظة: لأسباب تتعلق بالأداء والبساطة، قد تحتوي حقول مختلفة في بنية stat على معلومات حالة من لحظات مختلفة أثناء تنفيذ استدعاء النظام. على سبيل المثال، إذا تم تغيير st_mode أو st_uid بواسطة عملية أخرى عن طريق استدعاء chmod(2) أو chown(2)، فقد تُرجع stat() st_mode القديمة مع st_uid الجديدة، أو st_uid القديمة مع st_mode الجديدة.

fstatat()

استدعاء النظام fstatat() هو واجهة أكثر عمومية للوصول إلى معلومات الملف والتي لا تزال قادرة على توفير سلوك مطابق لكل من stat() و lstat() و fstat().

إذا كان path نسبيًا، فسيتم تفسيره بالنسبة للدليل الذي يشير إليه واصف الملف dirfd (بدلاً من الدليل الحالي لعملية الاستدعاء، كما تفعل stat() و lstat() لمسار نسبي).

إذا كان path نسبيًا و dirfd هي القيمة الخاصة AT_FDCWD، فسيتم تفسير path بالنسبة للدليل الحالي لعملية الاستدعاء (مثل stat() و lstat()).

إذا كان path مطلقًا، فسيتم تجاهل dirfd.

يمكن أن يكون flags إما 0، أو يتضمن واحدًا أو أكثر من الأعلام التالية ORed:

AT_EMPTY_PATH (منذ Linux 2.6.39)
إذا كان path عبارة عن سلسلة فارغة (أو NULL، منذ Linux 6.11) قم بتشغيل على الملف المشار إليه بواسطة dirfd (الذي ربما تم الحصول عليه باستخدام open(2) مع علامة O_PATH). في هذه الحالة، يمكن أن يشير dirfd إلى أي نوع من الملفات، وليس فقط دليلًا، ويكون سلوك fstatat() مشابهًا لسلوك fstat(). إذا كان dirfd هو AT_FDCWD، فإن الاستدعاء يعمل على الدليل الحالي. هذا العلم خاص بـ Linux؛ قم بتعريف _GNU_SOURCE للحصول على تعريفه.
AT_NO_AUTOMOUNT (منذ Linux 2.6.38)
لا تقم بتحميل تلقائي لمكون "اسم الملف الأساسي" (basename) من path. منذ Linux 3.1 تم تجاهل هذا العلم. منذ Linux 4.11 تم تضمين هذا العلم.
AT_SYMLINK_NOFOLLOW
إذا كان path رابطًا رمزيًا، فلا تتبعه: بدلاً من ذلك، قم بإرجاع معلومات حول الرابط نفسه، مثل lstat(). (افتراضيًا، تقوم fstatat() باتباع الروابط الرمزية، مثل stat().)

راجع openat(2) لشرح الحاجة إلى fstatat().

قيمة الإرجاع

عند النجاح، يتم إرجاع الصفر. عند حدوث خطأ، يتم إرجاع -1، ويتم تعيين errno للإشارة إلى الخطأ.

الأخطاء

EACCES
يُرفض إذن البحث لأحد الدلائل في بادئة المسار path. (انظر أيضًا path_resolution(7)).
EBADF
fd ليس واصف ملف مفتوح صالح.
EBADF
(fstatat()) path نسبي ولكنه dirfd ليس AT_FDCWD وليس واصف ملف صالح.
EFAULT
عنوان سيء.
EINVAL
(fstatat()) تم تحديد علم غير صالح في flags.
ELOOP
تم العثور على عدد كبير جدًا من الروابط الرمزية أثناء اجتياز المسار.
ENAMETOOLONG
path طويل جدًا.
ENOENT
أحد مكونات path غير موجود أو هو رابط رمزي معلق.
ENOENT
path عبارة عن سلسلة فارغة ولم يتم تحديد AT_EMPTY_PATH في flags.
ENOMEM
نفاد الذاكرة (أي ذاكرة النواة).
ENOTDIR
أحد مكونات بادئة المسار path ليس دليلًا.
ENOTDIR
(fstatat()) path نسبي و dirfd هو واصف ملف يشير إلى ملف غير دليل.
EOVERFLOW
يشير path أو fd إلى ملف لا يمكن تمثيل حجمه أو رقم inode الخاص به أو عدد الكتل الخاصة به في، على التوالي، الأنواع off_t أو ino_t أو blkcnt_t. يمكن أن يحدث هذا الخطأ عندما، على سبيل المثال، يقوم تطبيق تم تجميعه على منصة 32 بت بدون -D_FILE_OFFSET_BITS=64 باستدعاء stat() على ملف يتجاوز حجمه (1<<31)-1 بايت.

stat(2)

stat, fstat, lstat, fstatat - الحصول على حالة الملف

الاسم

stat, fstat, lstat, fstatat - الحصول على حالة الملف

المكتبة

Standard C library (libc, -lc)

الملخص

#include <sys/types.h>
#include <sys/stat.h>

int stat(const char *pathname, struct stat *statbuf);
int fstat(int fd, struct stat *statbuf);
int lstat(const char *pathname, struct stat *statbuf);

#define _ATFILE_SOURCE
#include <fcntl.h>

int fstatat(int dirfd, const char *pathname, struct stat *statbuf, int flags);

الوصف

The system calls stat(), fstat(), and lstat() fill in the structure pointed to by statbuf with information about the file pointed to by the file descriptor fd or by the path name pathname.

The system call fstatat() is equivalent to fstat() except that there is a base directory specified by the file descriptor dirfd. It also allows flags to be specified.

The struct stat structure contains at least the following fields:

st_mode
Protection bits and file type. See inode(7).
st_ino
Inode number.
st_dev
ID of the device on which this file resides.
st_nlink
Number of hard links to the file.
st_uid
User ID of the owner.
st_gid
Group ID of the owner.
st_size
Total size, in bytes.
st_atime
Time of last access.
st_mtime
Time of last modification.
st_ctime
Time of last status change.
st_blksize
The preferred block size for file system I/O in 512-byte units. (This is not the physical block size.)
st_blocks
Number of blocks allocated for this file, in 512-byte units. Note that (st_blocks * 512) might be greater than (st_size) when blocks are used inefficiently.

The value of st_atime, st_mtime, and st_ctime are represented as seconds since the Epoch, and the fractional part is represented as nanoseconds. The structure member st_atim, st_mtim, and st_ctim (available since Linux 2.6.8) are used for the nanosecond resolution timestamps.

lstat() is identical to stat() except that if pathname is a symbolic link, then lstat() returns information about the link itself rather than the file the link points to.

fstatat() is similar to both stat() and lstat() depending on the value of the flags argument. The pathname argument can be a relative path or an absolute pathname. If pathname is relative, then it is interpreted relative to the directory referred to by the file descriptor dirfd. If pathname is absolute, or if dirfd is AT_FDCWD (a symbolic constant defined in <fcntl.h>), then pathname is interpreted relative to the current working directory.

If pathname specifies a relative path and dirfd is not AT_FDCWD, and if pathname does not contain a slash (i.e., it is a file name), then fstatat() behaves like lstat(). Otherwise, fstatat() behaves like stat().

The flags argument may be 0 or a bitwise OR of one or more of the following:

AT_SYMLINK_NOFOLLOW
If pathname is a symbolic link, then return information about the link itself rather than the file it points to, whether or not pathname is relative to dirfd.
AT_NO_AUTOMOUNT
