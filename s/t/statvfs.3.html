statvfs(3)

Get file system statistics

STATVFS(3) Library Functions Manual STATVFS(3)

NAME statvfs, fstatvfs - get file system statistics

LIBRARY Realtime library (libc, -lrt)

SYNOPSIS #include <sys/statvfs.h> int statvfs(const char *path, struct statvfs *buf); int fstatvfs(int fd, struct statvfs *buf);

DESCRIPTION The statvfs() function examines the file system named by the path argument and fills in the statvfs structure pointed to by buf with information about that file system. The fstatvfs() function is similar, except that it operates on an open file description referred to by the file descriptor fd (opened by open(2), creat(2), or the like). The structure `struct statvfs` contains at least the following members: unsigned long f_bsize; /* Filesystem block size */ unsigned long f_frsize; /* Fragment size (usually same as f_bsize or 1) */ fsblkcnt_t f_blocks; /* Size of fs in blocks */ fsblkcnt_t f_bfree; /* Number of free blocks */ fsblkcnt_t f_bavail; /* Number of free blocks for unprivileged users */ fsfilcnt_t f_files; /* Size of fs in inodes */ fsfilcnt_t f_ffree; /* Number of free inodes */ fsfilcnt_t f_favail; /* Number of free inodes for unprivileged users */ unsigned long f_sid; /* Filesystem ID */ unsigned long f_flag; /* Mount flags of the filesystem */ char f_fstypename[16]; /* Filesystem type name */ char f_mntonname[256]; /* Path name of the mount point */ char f_mntfromname[256]; /* Path name of the device or remote share */ unsigned long f_owner; /* User ID of the owner */ unsigned long f_group; /* Group ID of the owner */ unsigned long f_spare; /* Reserved for future use */ The fields `f_bsize`, `f_frsize`, `f_blocks`, `f_bfree`, `f_bavail`, `f_files`, and `f_ffree` are in units of `f_frsize` bytes, except for `f_blocks` and `f_bfree` which are in units of `f_bsize` bytes. The field `f_flag` contains bit flags. The following flags are defined: ST_NOSUID, ST_NODEV, ST_NOEXEC. In addition, the following flags may be set: ST_RDONLY (read-only filesystem), ST_APPEND (all writes append), ST_IMMUTABLE (file is immutable). The fields `f_fstypename`, `f_mntonname`, `f_mntfromname` are null-terminated strings. The fields `f_owner`, `f_group`, and `f_spare` are not used by Linux and are always zero. `f_frsize` is the fundamental block size for the filesystem. All other fields are measured in units of this size, except for `f_blocks` and `f_bfree` which are measured in units of `f_bsize` bytes. `f_blocks` is the total number of blocks on the filesystem. `f_bfree` is the total number of free blocks in the filesystem. `f_bavail` is the number of free blocks available to non-privileged users. If `f_bfree` is less than `f_favail` then the system is in short supply of free inodes. `f_files` is the total number of file nodes in the filesystem. `f_ffree` is the number of free file nodes in the filesystem. `f_favail` is the number of free file nodes available to non-privileged users. `f_sid` is the file system ID. `f_flag` contains information about the mount options for the file system. The possible values are:

  • ST_RDONLY: Filesystem is mounted read-only.
  • ST_NOSUID: No set-user-ID or set-group-ID bits are honored.
  • ST_NODEV: No device special files are recognized.
  • ST_NOEXEC: Execute files are not permitted.
  • ST_APPEND: All writes to the filesystem append.
  • ST_IMMUTABLE: All file modifications are forbidden.

These flags are not portable. Consult the statvfs(3) man page for more information.

RETURN VALUE On success, zero is returned. On failure, -1 is returned, and errno is set appropriately.

ERRORS EACCES A section of the path prefix denies search permission. EBADF fd is not a valid file descriptor. EFAULT buf is not a valid user address. EINTR A signal was caught during the system call. EIO An I/O error occurred while reading from or writing to the file system. ELOOP Too many symbolic links were encountered in translating path. ENAMETOOLONG path is too long. ENOENT A file name in path does not exist or an empty string was specified as path. ENOMEM Out of memory.

ATTRIBUTES For an explanation of the terms used in this section, see attributes(7). ┌──────────────────────────┬───────────────────────────┐ │Interface │ Attribute │ ├──────────────────────────┼───────────────────────────┤ │statvfs(), fstatvfs() │ Thread safety, async-safe │ └──────────────────────────┴───────────────────────────┘

VERSIONS The fstatvfs() function first appeared in the FreeBSD 4.0 operating system. statvfs() first appeared in the SVR4 operating system.

NOTES The values in `f_fstypename`, `f_mntonname`, and `f_mntfromname` are truncated if they do not fit in the allocated buffer. For a string to be guaranteed to be written completely, the buffer size must be at least 16, 256, and 256 bytes respectively.

STANDARDS POSIX.1-2008.

HISTORY The statvfs() function was introduced in POSIX.1-1990. The fstatvfs() function was introduced in POSIX.1-2001.

SEE ALSO stat(2), statx(2), syscalls(2)
