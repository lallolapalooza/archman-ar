الوصف

تقوم الدالة vis() بنسخ سلسلة تمثل الحرف c إلى dst. إذا لم يكن الحرف c بحاجة إلى ترميز، يتم نسخه دون تغيير. تنتهي السلسلة بـ null، ويتم إرجاع مؤشر إلى نهاية السلسلة. الحد الأقصى لطول أي ترميز هو أربعة بايتات (باستثناء الحرف NUL اللاحق)؛ وبالتالي، عند ترميز مجموعة من الأحرف في مخزن مؤقت، يجب أن يكون حجم المخزن المؤقت أربعة أضعاف عدد البايتات المرمزة، بالإضافة إلى واحد لـ NUL اللاحق. يتم استخدام المعلمة flag لتغيير نطاق الأحرف الافتراضي الذي يتم النظر فيه للترميز ولتغيير التمثيل المرئي. الحرف الإضافي، nextc، يستخدم فقط عند اختيار تنسيق الترميز VIS_CSTYLE (مشروح أدناه).

تنسخ الدوال strvis()، stravis()، strnvis()، strvisx()، و strnvisx() سلسلة تمثل بصريًا السلسلة src إلى dst. تقوم الدوال strvis() و strnvis() بترميز الأحرف من src حتى أول NUL. تقوم الدوال strvisx() و strnvisx() بترميز بالضبط len حرفًا من src (هذا مفيد لترميز كتلة من البيانات قد تحتوي على NUL). كلا الشكلين ينهيان dst بـ NUL. يجب أن يكون حجم dst أربعة أضعاف عدد البايتات المرمزة من src (بالإضافة إلى واحد لـ NUL). كلا الشكلين يرجعان عدد الأحرف في dst (باستثناء NUL اللاحق). الدالة stravis()

NAME

vis, strvis, strvisx, svis, strsvis, strsvisx, nvis, strnvis, strnvisx, snvis, strsnvis, strsnvisx ― escape non-printing characters and non-ASCII characters

LIBRARY

libbsd

Requires libbsd.

SYNOPSIS

#include <vis.h>
char *
strvis(char *dst, const char *src, int flag);
char *
strvisx(char *dst, const char *src, size_t dstsize, int flag);
char *
strsvis(char *dst, const char *src, int flag);
char *
strsvisx(char *dst, const char *src, size_t dstsize, int flag);
char *
strnvis(char *dst, const char *src, size_t dstsize, int flag);
char *
strnvisx(char *dst, const char *src, size_t dstsize, int flag);
char *
snvis(char *dst, const char *src, size_t dstsize, int flag);
char *
snvisx(char *dst, const char *src, size_t dstsize, int flag);

DESCRIPTION

The vis family of functions formats the characters in the input string src for the purpose of displaying them. This is useful for debugging, logging, and displaying arbitrary binary data.

The functions are:

strvis–
Visits the string src and writes the result to the buffer dst. It is the caller's responsibility to ensure that dst is large enough to hold the result, which can be up to 4 times the size of src plus 1 for the null terminator.
strvisx–
Like strvis, but the destination buffer size is limited to dstsize. This function is safer than strvis because it prevents buffer overflows.
strsvis–
Same as strvis.
strsvisx–
Same as strvisx.
strnvis–
Like strvis, but only considers the first dstsize bytes of src as input.
strnvisx–
Like strvisx, but only considers the first dstsize bytes of src as input.
nvis–
Like strnvis, but assumes the destination buffer is large enough and the source string is null-terminated. It returns a pointer to the start of the string.
snvis–
Like strnvisx, but assumes the source string is null-terminated. It returns a pointer to the start of the string.
snvisx–
Like strvisx, but assumes the source string is null-terminated. It returns a pointer to the start of the string.

The flag argument is a bitmask that can be used to modify the behavior of the functions. The following flags are available:

VIS_DQSPECIAL
Treat double quotes (") and backslashes (\) as special characters, escaping them with a backslash. This is useful for generating strings that can be safely used within C string literals.
VIS_CSTYLE
Use C-style backslash escapes for control characters. For example, newline (\n) is represented as ‘\n’, tab (\t) as ‘\t’, and bell (\a) as ‘\a’. Other control characters are represented using octal notation, e.g., ‘\007’.
VIS_SPSPECIAL
Treat the space character ( ) as a special character, escaping it with a backslash. This is useful for generating strings where spaces might otherwise be misinterpreted, such as in shell commands.
VIS_TABSPECIAL
Treat the tab character (\t) as a special character, escaping it with a backslash. This is useful for generating strings where tabs might be misinterpreted, such as in shell commands.
VIS_GLOB
Escape characters that have special meaning to the shell's globbing mechanism. This includes characters like *, ?, and [. The form is ‘^X’ where x represents a lower case hexadecimal digit.
VIS_NLSPSPECIAL
Treat the newline character (\n) as a special character, escaping it with a backslash. This is useful for generating strings that preserve newlines, such as in configuration files.
VIS_NOSLASH
Inhibits the doubling of backslashes and the backslash before the default format (that is, control characters are represented by ‘^C’ and meta characters as ‘M-C’). With this flag set, the encoding is ambiguous and non-invertible.
VIS_SAFE
Escape all characters that are not alphanumeric or one of _, ., /, @, +, -, :. This is useful for generating strings that can be safely passed as arguments to commands.
VIS_WHITE
Escape all characters that are not alphanumeric or one of _, ., /, @, +, -, :, , and \t. This is useful for generating strings that can be safely passed as arguments to commands when tabs and spaces are allowed.
VIS_OCTAL
Use octal notation for all non-ASCII characters. The form is ‘\XXX’ where X represents an octal digit.
VIS_HTTP_QUOTE
Use HTTP %-encoding as described in RFC 1738, section 2.1. The form is ‘%XX’ where x represents a lower case hexadecimal digit.
VIS_MIMESTYLE
Use MIME Quoted-Printable encoding as described in RFC 2045, only don't break lines and don't handle CRLF. The form is ‘=XX’ where X represents an upper case hexadecimal digit.

There is one additional flag, VIS_NOSLASH, which inhibits the doubling of backslashes and the backslash before the default format (that is, control characters are represented by ‘^C’ and meta characters as ‘M-C’). With this flag set, the encoding is ambiguous and non-invertible.

MULTIBYTE CHARACTER SUPPORT

These functions support multibyte character input. The encoding conversion is influenced by the setting of the LC_CTYPE environment variable which defines the set of characters that can be copied without encoding.

If VIS_NOLOCALE is set, processing is done assuming the C locale and overriding any other environment settings.

When 8-bit data is present in the input, LC_CTYPE must be set to the correct locale or to the C locale. If the locales of the data and the conversion are mismatched, multibyte character recognition may fail and encoding will be performed byte-by-byte instead.

As noted above, dst must be four times the number of bytes processed from src. But note that each multibyte character can be up to MB_LEN_MAX bytes so in terms of multibyte characters, dst must be four times MB_LEN_MAX times the number of characters processed from src.

ENVIRONMENT

LC_CTYPE
Specify the locale of the input data. Set to C if the input data locale is unknown.

ERRORS

The functions nvis() and snvis() will return NULL and the functions strnvis(), strnvisx(), strsnvis(), and strsnvisx(), will return -1 when the dlen destination buffer size is not enough to perform the conversion while setting errno to:

[ENOSPC]
The destination buffer size is not large enough to perform the conversion.

HISTORY

The vis(), strvis(), and strvisx() functions first appeared in 4.4BSD. The svis(), strsvis(), and strsvisx() functions appeared in NetBSD 1.5. The buffer size limited versions of the functions (nvis(), strnvis(), strnvisx(), snvis(), strsnvis(), and strsnvisx()) appeared in NetBSD 6.0 and FreeBSD 9.2. Multibyte character support was added in NetBSD 7.0 and FreeBSD 9.2.
