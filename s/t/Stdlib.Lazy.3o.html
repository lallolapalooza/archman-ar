الوحدة Lazy
: (module Stdlib__Lazy)

type 'a t = 'a CamlinternalLazy.t

القيمة من النوع 'a Lazy.t هي حساب مؤجل، يسمى تعليقًا، له نتيجة من النوع 'a . صيغة التعبير الخاصة lazy (expr) تنشئ تعليقًا لحساب expr ، دون حساب expr نفسه بعد. "إجبار" التعليق سيحسب بعد ذلك expr ويعيد نتيجته. مطابقة تعليق مع صيغة النمط الخاصة lazy(pattern) تحسب أيضًا التعبير الأساسي وتحاول ربطه بالنمط pattern:

      let lazy_option_map f x =
      match x with
      | lazy (Some x) -> Some (Lazy.force f x)
      | _ -> None

ملاحظة: إذا ظهرت أنماط lazy في حالات متعددة في مطابقة نمط، فقد يتم إجبار تعبيرات lazy حتى خارج الحالة التي يتم اختيارها في النهاية بواسطة مطابقة النمط. في المثال أعلاه، يتم دائمًا حساب التعليق x.

ملاحظة: lazy_t هو النوع الباني المدمج الذي يستخدمه المترجم لكلمة lazy المفتاحية. يجب ألا تستخدمه مباشرة. استخدم دائمًا Lazy.t بدلاً من ذلك.

ملاحظة: Lazy.force ليست آمنة للتزامن. إذا كنت تستخدم هذه الوحدة مع مؤشرات متعددة (fibers) أو خيوط نظام (systhreads) أو مجالات (domains)، فستحتاج إلى إضافة بعض الأقفال. ومع ذلك، تضمن الوحدة سلامة الذاكرة، وبالتالي، فإن الوصول المتزامن إلى هذه الوحدة لن يؤدي إلى تعطل ولكن السلوك غير محدد.

ملاحظة: إذا تم تجميع البرنامج باستخدام الخيار -rectypes، فإن التعريفات التكرارية غير المؤسسة بالشكل let rec x = lazy x أو let rec x = lazy(lazy(...(lazy x))) يتم قبولها بواسطة مدقق الأنواع وتؤدي، عند إجبارها، إلى قيم غير مؤسسة تسبب حلقات لا نهائية في جامع القمامة وأجزاء أخرى من نظام التشغيل. بدون الخيار -rectypes، يتم رفض هذه التعريفات التكرارية غير المؤسسة بواسطة مدقق الأنواع.

exception Undefined

ترفع عند إجبار تعليق بشكل متزامن من مؤشرات أو خيوط نظام أو مجالات متعددة، أو عندما يحاول التعليق إجبار نفسه بشكل تكراري.

val force : 'a t -> 'a

force x يجبر التعليق x ويعيد نتيجته. إذا تم إجبار x بالفعل، فإن Lazy.force x يعيد نفس القيمة مرة أخرى دون إعادة حسابها. إذا رفع استثناءً، يتم رفع نفس الاستثناء مرة أخرى.

يرفع Undefined (انظر Lazy.Undefined).

المكررات

val map : ('a -> 'b) -> 'a t -> 'b t

map f x يعيد تعليقًا، عند إجباره، يجبر x ويطبق f على قيمته.

وهو مكافئ لـ lazy (f (Lazy.force x)).

منذ 4.13

الاستدلال على التعليقات التي تم إجبارها بالفعل

val is_val : 'a t -> bool

is_val x يعيد true إذا تم إجبار x بالفعل ولم يرفع استثناءً.

منذ 4.00

val from_val : 'a -> 'a t

from_val v يحسب v أولاً (كما تفعل أي دالة) ويعيد تعليقًا تم إجباره بالفعل لنتيجته. إنه نفس let x = v in lazy x ، ولكنه يستخدم اختبارات ديناميكية لتحسين إنشاء التعليق في بعض الحالات.

منذ 4.00

val map_val : ('a -> 'b) -> 'a t -> 'b t

map_val f x يطبق f مباشرة إذا تم إجبار x بالفعل، وإلا فإنه يتصرف مثل map f x.

عندما يتم إجبار x بالفعل، فإن هذا السلوك يوفر بناء تعليق، ولكنه من ناحية أخرى يقوم بمزيد من العمل بشكل استباقي قد لا يكون مفيدًا إذا لم تقم أبدًا بإجبار نتيجة الدالة.

إذا رفع f استثناءً، فسيتم رفعه فورًا عند is_val x ، أو رفعه فقط عند إجبار التعليق بخلاف ذلك.

إذا لم يرفع map_val f x استثناءً، فإن is_val (map_val f x) يساوي is_val x.

منذ 4.13

متقدم

التعريفات التالية للاستخدامات المتقدمة فقط؛ تتطلب معرفة بنظام الترجمة الكسولة لاستخدامها بشكل مناسب.

val from_fun : (unit -> 'a) -> 'a t

from_fun f هو نفس lazy (f ()) ولكنه أكثر كفاءة قليلاً.

يجب استخدامه فقط إذا كانت الدالة f معرفة بالفعل. على وجه الخصوص، يكون دائمًا أقل كفاءة لكتابة from_fun (fun () -> expr) بدلاً من lazy expr.

منذ 4.00

val force_val : 'a t -> 'a

force_val x يجبر التعليق x ويعيد نتيجته. إذا تم إجبار x بالفعل، فإن force_val x يعيد نفس القيمة مرة أخرى دون إعادة حسابها.

إذا رفعت عملية حساب x استثناءً، فمن غير المحدد ما إذا كان force_val x يرفع نفس الاستثناء أو Lazy.Undefined.

يرفع Undefined إذا حاول إجبار x إجبار x نفسه بشكل تكراري.

يرفع Undefined (انظر Lazy.Undefined).
