العلامات الدلالية

type stag = ..

العلامات الدلالية (أو ببساطة العلامات) هي تسميات توضيحية معرفة من قبل المستخدم لربط عمليات المستخدم المحددة بالكيانات المطبوعة.

الاستخدام الشائع للعلامات الدلالية هو زخرفة النص للحصول على خط أو حجم نص محدد للعرض، أو تحديد حدود الكيانات (مثل عناصر HTML أو TeX أو تسلسلات هروب الطرفية). يمكن أن تتعامل الاستخدامات الأكثر تطورًا للعلامات الدلالية مع تعديل سلوك المنسق ديناميكيًا لطباعة المواد بشكل صحيح داخل علامات معينة. على سبيل المثال، يمكننا تعريف علامة RGB على النحو التالي:

type stag += RGB of {r:int;g:int;b:int}

من أجل تحديد حدود الكيانات المطبوعة بشكل صحيح، يجب فتح علامة دلالية قبل الكيان وإغلاقها بعده. يجب أن تكون العلامات الدلالية متداخلة بشكل صحيح مثل الأقواس باستخدام Format.pp_open_stag و Format.pp_close_stag.

تحدث العمليات الخاصة بالعلامة في كل مرة يتم فيها فتح أو إغلاق علامة. عند كل حدوث، يتم تنفيذ نوعين من العمليات: تمييز العلامة وطباعة العلامة:

-عملية تمييز العلامة هي عملية العلامة الخاصة الأبسط: إنها تكتب ببساطة سلسلة نصية خاصة بالعلامة إلى جهاز الإخراج للمنسق. تمييز العلامة لا يتداخل مع حساب تقسيم الأسطر.

-عملية طباعة العلامة هي عملية العلامة الأكثر تعقيدًا: يمكنها طباعة مواد عشوائية للمنسق. طباعة العلامة مرتبطة ارتباطًا وثيقًا بعمليات المنسق الحالية.

بشكل عام، يستخدم تمييز العلامة بشكل شائع للحصول على عرض أفضل للنصوص في جهاز العرض، بينما تسمح طباعة العلامة بالضبط روتين الطباعة لطباعة نفس الكيان بشكل مختلف وفقًا للعلامات الدلالية (أي طباعة مواد إضافية أو حتى حذف أجزاء من الإخراج).

بشكل أكثر دقة: عند فتح علامة دلالية أو إغلاقها، تحدث عمليات "طباعة العلامة" و "تمييز العلامة" المتتالية:

-طباعة علامة دلالية تعني استدعاء الدالة الخاصة بالمنسق print_open_stag (أو print_close_stag بالمقابل) مع اسم العلامة كوسيط: يمكن لهذه الدالة طباعة أي مواد عادية للمنسق (بحيث يتم إدراج هذه المواد كالمعتاد في قائمة انتظار المنسق لحسابات تقسيم الأسطر اللاحقة).

-تمييز علامة دلالية يعني استدعاء الدالة الخاصة بالمنسق mark_open_stag (أو mark_close_stag بالمقابل) مع اسم العلامة كوسيط: يمكن لهذه الدالة بعد ذلك إرجاع "علامة فتح العلامة" (أو "علامة إغلاق العلامة" بالمقابل) للإخراج المباشر إلى جهاز الإخراج الخاص بالمنسق.

يتم كتابة علامات العلامات الدلالية مباشرة في جهاز الإخراج الخاص بالمُنسق، ولا تعتبر سلاسل علامات العلامات الدلالية جزءًا من المواد الطباعية التي تقود تقسيم الأسطر (بمعنى آخر، يعتبر طول السلاسل المقابلة لعلامات العلامات صفرًا لتقسيم الأسطر).

وبالتالي، فإن التعامل مع العلامات الدلالية شفاف بطريقة ما للتنسيق الجميل ولا يتداخل مع المسافة البادئة المعتادة. لذلك، يمكن لروتين تنسيق واحد أن يُخرج كلاً من المواد "الحرفية" البسيطة أو مخرجات مزخرفة أغنى اعتمادًا على معالجة العلامات. افتراضيًا، العلامات غير نشطة، وبالتالي لا يتم تزيين الإخراج بمعلومات العلامات. بمجرد تعيين set_tags إلى true ، فإن محرك التنسيق الجميل يحترم العلامات ويزين الإخراج وفقًا لذلك.

تعمل وظائف وضع العلامات الافتراضية بنفس طريقة HTML: يتم تضمين Format.tag بين "<" و ">" بينما يتم تجاهل العلامات الأخرى؛ وبالتالي، فإن علامة الفتح لسلسلة العلامة "t" هي "" وعلامة الإغلاق هي "".

تعمل وظائف طباعة العلامات الافتراضية على عدم القيام بأي شيء.

يمكن تعريف وظائف وضع العلامات وطباعة العلامات من قبل المستخدم ويمكن تعيينها عن طريق استدعاء Format.set_formatter_stag_functions.

يمكن تشغيل أو إيقاف عمليات العلامات الدلالية باستخدام Format.set_tags. يمكن تشغيل أو إيقاف عمليات وضع العلامات باستخدام Format.set_mark_tags. يمكن تشغيل أو إيقاف عمليات طباعة العلامات باستخدام Format.set_print_tags.

الوحدة Format مرنة بما يكفي لتسمح لك بإعادة تعريف معنى إخراج التنسيق الجميل بالكامل: يمكنك تقديم وظائفك الخاصة لتحديد كيفية التعامل مع المسافة البادئة، وتقسيم الأسطر، وحتى طباعة جميع الأحرف التي يجب طباعتها!

إعادة تعريف وظائف الإخراج

type formatter_out_functions = {
out_string : string -> int -> int -> unit ;
out_width : string -> pos:int -> len:int -> int ; (* .B "منذ" 5.4
*)
out_flush : unit -> unit ;
out_newline : unit -> unit ;
out_spaces : int -> unit ;
out_indent : int -> unit ; (* .B "منذ" 4.06
*)
}

مجموعة وظائف الإخراج الخاصة بالمُنسق:

-وظيفة out_string تقوم بجميع عمليات إخراج السلاسل النصية للمُنسق. يتم استدعاؤها بسلسلة نصية s، وموضع بداية p، وعدد أحرف n؛ ومن المفترض أن تقوم بإخراج الأحرف من p إلى p + n - 1 من s.

-وظيفة out_width تُعلم محرك التنسيق بعرض السلسلة الفرعية كما تم تصويرها على جهاز الإخراج. تفاصيل العرض الصريحة المقدمة بواسطة @<n>، Format.pp_print_as أو Format.pp_print_substring_as لها الأولوية على هذه الوظيفة. علاوة على ذلك، يقوم محرك التنسيق بتقييم عرض وسائط السلسلة لـ Format.pp_print_string ووسائط السلاسل الفرعية لـ Format.pp_print_substring ككل. وبالتالي، يمكن استخدام out_width لحساب عرض تقريبي للسلاسل الفرعية أحادية الترميز.

-وظيفة out_flush تقوم بمسح جهاز إخراج المُنسق.

- out_newline يتم استدعاؤها لفتح سطر جديد عندما يقوم المُنسق بتقسيم السطر.

-وظيفة out_spaces تقوم بإخراج المسافات عندما يؤدي تلميح لكسر الأسطر إلى مسافات بدلاً من تقسيم الأسطر. يتم استدعاؤها بعدد المسافات المراد إخراجها.

-وظيفة out_indent تقوم بعمل مسافة بادئة لسطر جديد عندما يقوم المُنسق بتقسيم السطر. يتم استدعاؤها بقيمة المسافة البادئة للسطر الجديد.

منذ 5.4

NAME

Format - Formatted pretty-printing

Module

module Format : sig ... end

Documentation

This module provides a flexible and extensible pretty-printer. It is inspired by the Algorithms for pretty-printing by D. Knuth and M. R. Brown, but implements a simplified version of their algorithm.

The main idea is to describe the desired output as a hierarchical composition of boxes, where boxes can be printed either horizontally or vertically, depending on the available space. This allows for adaptive formatting, where the output can be printed compactly on a single line if it fits, or broken into multiple lines if necessary.

The pretty-printer maintains a current formatter, which is an abstract data type representing the output destination. You can print strings, numbers, or other values using the functions provided by this module. The functions typically take a formatter as their first argument.

The module defines several types of boxes:

  • `{ ... }` : A simple box. The contents are printed horizontally.
  • `@[ ... @]` : A breakable box. If the contents do not fit on the current line, they are printed vertically.
  • `<...>` : A tag. Tags are used to attach semantic information to parts of the output, but they do not affect the layout directly.
  • `<tag> ... </tag>` : A box with a tag.

Boxes can be combined using combinators. For example, `Format.hvbox` creates a box that is printed horizontally if possible, but vertically otherwise. `Format.over_box` creates a box that is printed horizontally, but if it overflows, it is printed vertically.

The module also provides functions for creating and manipulating formatters. A formatter can be created from an output channel (e.g., `stdout`), a string buffer, or a custom printing function.

The following functions are provided for printing:

  • `fprintf : formatter -> ('a, formatter, unit, unit) format -> 'a`: Prints formatted output to a given formatter.
  • `printf : ('a, unit, string, unit) format -> 'a`: Prints formatted output to `stdout`.
  • `sprintf : ('a, unit, string) format -> 'a`: Returns a string containing the formatted output.
  • `asprintf : ('a, formatter, unit, string) format4 -> 'a`: Similar to `sprintf`, but more general and handles `%a` conversions correctly.
  • `dprintf : ('a, formatter, unit, formatter -> unit) format4 -> 'a`: Creates a deferred printer that can be used with `%t` format specifiers.
  • `ifprintf : formatter -> ('a, formatter, unit) format -> 'a`: Like `fprintf`, but does nothing. Useful for conditional printing.
  • `kfprintf : (formatter -> 'a) -> formatter -> ('b, formatter, unit, 'a) format4 -> 'b`: Like `fprintf`, but passes the formatter to a continuation function after printing.
  • `kdprintf : ((formatter -> unit) -> 'a) -> ('b, formatter, unit, 'a) format4 -> 'b`: Like `dprintf`, but passes the deferred printer to a continuation function.
  • `ikfprintf : (formatter -> 'a) -> formatter -> ('b, formatter, unit, 'a) format4 -> 'b`: Like `kfprintf`, but does nothing.
  • `ksprintf : (string -> 'a) -> ('b, unit, string, 'a) format4 -> 'b`: Like `sprintf`, but passes the resulting string to a continuation function.
  • `kasprintf : (string -> 'a) -> ('b, formatter, unit, 'a) format4 -> 'b`: Like `asprintf`, but passes the resulting string to a continuation function.

The module also provides several helper functions for common printing tasks, such as printing lists, options, and numbers.

The pretty-printer uses a queue-based approach to manage the output. When the queue is flushed (e.g., by calling `Format.print_flush`), the output from different domains might be interleaved.

When using multiple and related calls to sprintf to output material on a single string, you should consider using fprintf with the predefined formatter str_formatter and call flush_str_formatter () to get the final result.

Alternatively, you can use Format.fprintf with a formatter writing to a buffer of your own: flushing the formatter and the buffer at the end of pretty-printing returns the desired string.

Examples

A few warmup examples to get an idea of how Format is used.

We have a list l of pairs (int * bool) , which the toplevel prints for us:

# let l = List.init 20 (fun n -> n, n mod 2 = 0)
  val l : (int * bool) list =
  [(0, true); (1, false); (2, true); (3, false); (4, true); (5, false);
   (6, true); (7, false); (8, true); (9, false); (10, true); (11, false);
   (12, true); (13, false); (14, true); (15, false); (16, true); (17, false);
   (18, true); (19, false)]

If we want to print it ourself without the toplevel magic, we can try this:

  # let pp_pair out (x,y) = Format.fprintf out "(%d, %b)" x y
  val pp_pair : Format.formatter -> int * bool -> unit = <fun>
  # Format.printf "l: [@[<hov>%a@]]@."
    Format.(pp_print_list ~pp_sep:(fun out () -> fprintf out ";@ ") pp_pair) l
    l: [(0, true); (1, false); (2, true); (3, false); (4, true); (5, false);
        (6, true); (7, false); (8, true); (9, false); (10, true); (11, false);
        (12, true); (13, false); (14, true); (15, false); (16, true);
        (17, false); (18, true); (19, false)]

What this does, briefly, is:

- pp_pair prints a pair bool*int surrounded in "(" ")". It takes a formatter (into which formatting happens), and the pair itself. When printing is done it returns () .

- Format.printf "l = [@[<hov>%a@]]@." ... l is like printf , but with additional formatting instructions (denoted with "@"). The pair " @[<hov> " and " @] " is a "horizontal-or-vertical box".

-"@." ends formatting with a newline. It is similar to "\n" but is also aware of the Format.formatter 's state. Do not use "\n" with Format .

-"%a" is a formatting instruction, like "%d" or "%s" for printf . However, where "%d" prints an integer and "%s" prints a string, "%a" takes a printer (of type Format.formatter -> 'a -> unit ) and a value (of type 'a ) and applies the printer to the value. This is key to compositionality of printers.

-We build a list printer using Format.pp_print_list ~pp_sep:(...) pp_pair . pp_print_list takes an element printer and returns a list printer. The ?pp_sep optional argument, if provided, is called in between each element to print a separator.

-Here, for a separator, we use (fun out () -> Format.fprintf out ";@ ") . It prints ";", and then "@ " which is a breaking space (either it prints " ", or it prints a newline if the box is about to overflow). This "@ " is responsible for the list printing splitting into several lines.

If we omit "@ ", we get an ugly single-line print:

# Format.printf "l: [@[<hov>%a@]]@."
      Format.(pp_print_list ~pp_sep:(fun out () -> fprintf out "; ") pp_pair) l
  l: [(0, true); (1, false); (2, true); (* ... *); (18, true); (19, false)]
- : unit = ()

Generally, it is good practice to define custom printers for important types in your program. If, for example, you were to define basic geometry types like so:

  type point = {
    x: float;
    y: float;
  }
  type rectangle = {
    ll: point; (* lower left *)
    ur: point; (* upper right *)
  }

For debugging purpose, or to display information in logs, or on the console, it would be convenient to define printers for these types. Here is an example of to do it. Note that "%.3f" is a float printer up to 3 digits of precision after the dot; "%f" would print as many digits as required, which is somewhat verbose; "%h" is an hexadecimal float printer.

  let pp_point out (p:point) =
    Format.fprintf out "{ @[x=%.3f;@ y=%.3f@] }" p.x p.y
  let pp_rectangle out (r:rectangle) =
    Format.fprintf out "{ @[ll=%a;@ ur=%a@] }"
      pp_point r.ll pp_point r.ur

In the .mli file, we could have:

    val pp_point : Format.formatter -> point -> unit
    val pp_rectangle : Format.formatter -> rectangle -> unit

These printers can now be used with "%a" inside other printers.

# Format.printf "some rectangle: %a@."
        (Format.pp_print_option pp_rectangle)
        (Some {ll={x=1.; y=2.}; ur={x=42.; y=500.12345}})
  some rectangle: { l={ x=1.000; y=2.000 }; ur={ x=42.000; y=500.123 } }
  # Format.printf "no rectangle: %a@."
        (Format.pp_option pp_rectangle)
        None
  no rectangle:

See how we combine pp_print_option (option printer) and our newly defined rectangle printer, like we did with pp_print_list earlier.

For a more extensive tutorial, see "Using the Format module".

A final note: the Format module is a starting point. The OCaml ecosystem has libraries that makes formatting easier and more expressive, with more combinators, more concise names, etc. An example of such a library is Fmt.

Automatic deriving of pretty-printers from type definitions is also possible, using https://github.com/ocaml-ppx/ppx_deriving or similar ppx derivers.
