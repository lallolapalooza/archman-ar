المواضع

type position = {
pos_fname : string ;
pos_lnum : int ;
pos_bol : int ;
pos_cnum : int ;
}

قيمة من النوع position تصف نقطة في ملف مصدري. pos_fname هو اسم الملف؛ pos_lnum هو رقم السطر؛ pos_bol هو الإزاحة لبداية السطر (عدد الأحرف بين بداية lexbuf وبداية السطر)؛ pos_cnum هو الإزاحة للموضع (عدد الأحرف بين بداية lexbuf والموضع). الفرق بين pos_cnum و pos_bol هو الإزاحة الحرفية داخل السطر (أي رقم العمود، بافتراض أن كل حرف يمثل عمودًا واحدًا).

انظر توثيق النوع lexbuf لمعلومات حول كيفية إدارة محرك التحليل المعجمي للمواضع.

val dummy_pos : position

قيمة من النوع position، مضمون أن تكون مختلفة عن أي موضع صالح.

مخازن المحلل المعجمي

type lexbuf = {
refill_buff : lexbuf -> unit ;

mutable lex_buffer : bytes ;

mutable lex_buffer_len : int ;

mutable lex_abs_pos : int ;

mutable lex_start_pos : int ;

mutable lex_curr_pos : int ;

mutable lex_last_pos : int ;

mutable lex_last_action : int ;

mutable lex_eof_reached : bool ;

mutable lex_mem : int array ;

mutable lex_start_p : position ;

mutable lex_curr_p : position ;
}

نوع مخازن المحلل المعجمي. مخزن المحلل المعجمي هو الوسيط الذي يتم تمريره إلى دوال المسح التي تحددها الماسحات الضوئية المولدة. يخزن مخزن المحلل المعجمي الحالة الحالية للماسح الضوئي، بالإضافة إلى وظيفة لإعادة تعبئة المخزن من المدخلات.

يمكن للمحللات المعجمية الاحتفاظ بحقول الموضع lex_curr_p و lex_start_p اختياريًا. هذا وضع "تتبع الموضع" هو الوضع الافتراضي، ويتوافق مع تمرير ~with_position:true إلى الدوال التي تنشئ مخازن المحلل المعجمي. في هذا الوضع، يكون محرك التحليل المعجمي وإجراءات المحلل المعجمي مسؤولين بشكل مشترك عن تحديث حقول الموضع بشكل صحيح، كما هو موضح في الفقرة التالية. عندما يتم تعطيل الوضع بشكل صريح (باستخدام ~with_position:false)، لن يقوم محرك التحليل المعجمي بلمس حقول الموضع ويجب على إجراءات المحلل المعجمي الحرص على عدم القيام بذلك أيضًا؛ ستظل حقول lex_curr_p و lex_start_p تحمل دائمًا الموضع غير الصالح dummy_pos. عدم تتبع المواضع يتجنب عمليات التخصيص وكتابات الذاكرة ويمكن أن يحسن أداء المحلل المعجمي بشكل كبير في السياقات التي لا تكون فيها lex_start_p و lex_curr_p مطلوبة.

يعمل وضع تتبع الموضع على النحو التالي. عند كل رمز، سيقوم محرك التحليل المعجمي بنسخ lex_curr_p إلى lex_start_p، ثم تغيير حقل pos_cnum من lex_curr_p عن طريق تحديثه بعدد الأحرف المقروءة منذ بداية lexbuf. تترك الحقول الأخرى دون تغيير بواسطة محرك التحليل المعجمي. للحفاظ على دقتها، يجب تهيئتها قبل الاستخدام الأول لمخزن المحلل المعجمي، وتحديثها بواسطة إجراءات المحلل المعجمي ذات الصلة (أي عند كل نهاية سطر - انظر أيضًا new_line).

val from_channel : ?with_positions:bool -> in_channel -> lexbuf

إنشاء مخزن محلل معجمي على قناة الإدخال المحددة. Lexing.from_channel inchan يعيد مخزن محلل معجمي يقرأ من قناة الإدخال inchan، عند موضع القراءة الحالي.

val from_string : ?with_positions:bool -> string -> lexbuf

إنشاء مخزن محلل معجمي يقرأ من السلسلة النصية المحددة. يبدأ القراءة من الحرف الأول في السلسلة. يتم إنشاء شرط نهاية الإدخال عند الوصول إلى نهاية السلسلة.

val from_function : ?with_positions:bool -> (bytes -> int -> int) -> lexbuf

إنشاء مخزن محلل معجمي مع الوظيفة المحددة كطريقة قراءة لها. عندما تحتاج الماسحة الضوئية إلى مزيد من الأحرف، فإنها ستستدعي الوظيفة المحددة، مع إعطائها تسلسل بايتات s وعدد بايتات n. يجب أن تضع الوظيفة n بايت أو أقل في s، بدءًا من الفهرس 0، وإرجاع عدد البايتات المقدمة. القيمة المرجعة 0 تعني نهاية الإدخال.

val set_position : lexbuf -> position -> unit

تعيين موضع الإدخال المتتبع الأولي لـ lexbuf إلى قيمة مخصصة. تتجاهل pos_fname. انظر Lexing.set_filename لتغيير هذا الحقل.

منذ 4.11

val set_filename : lexbuf -> string -> unit

تعيين اسم الملف في الموضع المتتبع الأولي إلى file في lexbuf.

منذ 4.11

val with_positions : lexbuf -> bool

تحديد ما إذا كان مخزن المحلل المعجمي يتتبع حقول الموضع lex_curr_p / lex_start_p، كما تم تحديده بواسطة الوسيط الاختياري المقابل للدوال التي تنشئ مخازن المحلل المعجمي (القيمة الافتراضية هي true).

عندما يكون with_positions يساوي false، يجب على إجراءات المحلل المعجمي عدم تعديل حقول الموضع. القيام بذلك على الرغم من ذلك قد يعيد تمكين وضع with_position ويقلل من الأداء.

الدوال لإجراءات المحلل المعجمي الدلالية

يمكن استدعاء الدوال التالية من الإجراءات الدلالية لتعريفات المحلل المعجمي (رمز ML المغلق بأقواس معقوفة الذي يحسب القيمة التي تعيدها دوال التحليل المعجمي). إنها توفر الوصول إلى سلسلة الأحرف التي تطابقت مع التعبير العادي المرتبط بالإجراء الدلالي. يجب تطبيق هذه الدوال على الوسيط lexbuf، والذي، في الرمز الذي تم إنشاؤه بواسطة ocamllex، يتم ربطه بمخزن المحلل المعجمي الذي تم تمريره إلى دالة التحليل.

val lexeme : lexbuf -> string

Lexing.lexeme lexbuf يعيد السلسلة النصية التي تطابقت مع التعبير العادي.

val lexeme_char : lexbuf -> int -> char

Lexing.lexeme_char lexbuf i يعيد الحرف رقم i في السلسلة النصية المتطابقة.

val lexeme_start : lexbuf -> int

Lexing.lexeme_start lexbuf يعيد الإزاحة في تيار الإدخال للحرف الأول من السلسلة النصية المتطابقة. الحرف الأول في التيار له إزاحة 0.

val lexeme_end : lexbuf -> int

Lexing.lexeme_end lexbuf يعيد الإزاحة في تيار الإدخال للحرف التالي للحرف الأخير من السلسلة النصية المتطابقة. الحرف الأول في التيار له إزاحة 0.

val lexeme_start_p : lexbuf -> position

مثل lexeme_start، ولكن يعيد position كاملة بدلاً من إزاحة. عندما يتم تعطيل تتبع الموضع، تعيد الدالة dummy_pos.

val lexeme_end_p : lexbuf -> position

مثل lexeme_end، ولكن يعيد position كاملة بدلاً من إزاحة. عندما يتم تعطيل تتبع الموضع، تعيد الدالة dummy_pos.

val new_line : lexbuf -> unit

تحديث حقل lex_curr_p لمخزن المحلل المعجمي ليعكس بداية سطر جديد. يمكنك استدعاء هذه الدالة في الإجراء الدلالي للقاعدة التي تطابق حرف نهاية السطر. لا تقوم الدالة بأي شيء عندما يتم تعطيل تتبع الموضع.

منذ 3.11

وظائف متنوعة

val flush_input : lexbuf -> unit

تجاهل محتويات المخزن وإعادة تعيين الموضع الحالي إلى 0. سيؤدي الاستخدام التالي لمخزن المحلل المعجمي إلى تشغيل إعادة التعبئة.

NAME

Stdlib.Lexing — Lexical analyzer generator

Module

This module provides the interface for the lexical analyzer generator generated by ocamllex, which is part of the OCaml distribution.

This module is used to generate scanners for OCaml programs. A scanner is a program that transforms a stream of characters into a stream of tokens. The tokens are then processed by a parser, which usually recognizes the syntactic structure of the input program.

The ocamllex tool generates a lexer from a specification file written in a subset of OCaml syntax. The generated lexer module exposes the following components:

  • lexing_error: a function that takes an exception and returns a string describing the error. This is useful for reporting errors to the user.

  • flush: a function that takes a lexer and returns the remaining input buffer. This is useful for dealing with incomplete input or for debugging.

  • buffer_len: a function that returns the length of the input buffer. This is useful for reporting errors or for debugging.

  • set_flush_action: a function that sets the action to be performed when the lexer reaches the end of the input. This is useful for handling end-of-file conditions or for performing cleanup actions.

  • set_trace: a function that enables or disables tracing of the lexer's behavior. This is useful for debugging.

  • trace: a function that returns the current trace status of the lexer. This is useful for debugging.

  • add_newline: a function that adds a newline character to the input buffer. This is useful for handling multi-line input.

  • remove_newline: a function that removes a newline character from the input buffer. This is useful for handling multi-line input.

  • check_suffix: a function that checks if the input buffer ends with a given suffix. This is useful for recognizing specific patterns in the input.

  • end_of_input: a function that returns true if the input buffer is empty, false otherwise. This is useful for checking if the lexer has reached the end of the input.

  • read_line: a function that reads a line from the input buffer. This is useful for handling multi-line input.

  • set_input_buffer: a function that sets the input buffer of the lexer. This is useful for changing the input source dynamically.

  • get_input_buffer: a function that returns the current input buffer of the lexer. This is useful for debugging.

  • set_input_channel: a function that sets the input channel of the lexer. This is useful for changing the input source dynamically.

  • get_input_channel: a function that returns the current input channel of the lexer. This is useful for debugging.

  • set_output_channel: a function that sets the output channel of the lexer. This is useful for directing the lexer's output to a specific channel.

  • get_output_channel: a function that returns the current output channel of the lexer. This is useful for debugging.

  • set_position: a function that sets the current position of the lexer in the input buffer. This is useful for debugging.

  • get_position: a function that returns the current position of the lexer in the input buffer. This is useful for debugging.

  • set_state: a function that sets the current state of the lexer. This is useful for implementing lexer states.

  • get_state: a function that returns the current state of the lexer. This is useful for debugging.

  • set_rule: a function that sets the current rule of the lexer. This is useful for debugging.

  • get_rule: a function that returns the current rule of the lexer. This is useful for debugging.

  • set_action: a function that sets the current action of the lexer. This is useful for debugging.

  • get_action: a function that returns the current action of the lexer. This is useful for debugging.

  • set_default_action: a function that sets the default action of the lexer. This is useful for debugging.

  • get_default_action: a function that returns the default action of the lexer. This is useful for debugging.

  • set_error_action: a function that sets the error action of the lexer. This is useful for debugging.

  • get_error_action: a function that returns the error action of the lexer. This is useful for debugging.
