NAME

strtod, strtof, strtold — تحويل سلسلة نصية إلى رقم مزدوج الدقة

SYNOPSIS

#include <stdlib.h>
double strtod(const char *restrict nptr, char **restrict endptr);
float strtof(const char *restrict nptr, char **restrict endptr);
long double strtold(const char *restrict nptr, char **restrict endptr);

DESCRIPTION

تتوافق الوظائف الموضحة في صفحة المرجع هذه مع معيار ISO C. أي تعارض بين المتطلبات الموضحة هنا ومعيار ISO C غير مقصود. يتنازل هذا المجلد من POSIX.1-2017 إلى معيار ISO C.

يجب أن تقوم هذه الدوال بتحويل الجزء الأولي من السلسلة النصية التي يشير إليها nptr إلى تمثيل double أو float أو long double على التوالي. أولاً، تقوم بتقسيم سلسلة الإدخال إلى ثلاثة أجزاء:

1.
تسلسل أولي، قد يكون فارغًا، من أحرف المسافة البيضاء (كما هو محدد بواسطة isspace())
2.
تسلسل موضوعي يتم تفسيره كثابت عشري أو يمثل اللانهاية أو NaN
3.
سلسلة نهائية من حرف واحد أو أكثر غير مفهومة، بما في ذلك حرف NUL الختامي لسلسلة الإدخال

ثم يجب أن تحاول تحويل التسلسل الموضوعي إلى رقم عشري، وتعيد النتيجة.

الشكل المتوقع للتسلسل الموضوعي هو علامة '+' أو '-' اختيارية، ثم أحد ما يلي:

*
تسلسل غير فارغ من الأرقام العشرية يحتوي اختياريًا على حرف فاصل عشري؛ ثم جزء أسي اختياري يتكون من الحرف 'e' أو الحرف 'E'، متبوعًا اختياريًا بعلامة '+' أو '-'، ثم متبوعًا برقم عشري واحد أو أكثر
*
0x أو 0X، ثم تسلسل غير فارغ من الأرقام الست عشرية يحتوي اختياريًا على حرف فاصل عشري؛ ثم جزء أسي ثنائي اختياري يتكون من الحرف 'p' أو الحرف 'P'، متبوعًا اختياريًا بعلامة '+' أو '-'، ثم متبوعًا برقم عشري واحد أو أكثر
*
واحد من INF أو INFINITY، مع تجاهل حالة الأحرف
*
واحد من NAN أو NAN(n-char-sequenceopt)، مع تجاهل حالة الأحرف في جزء NAN، حيث:
n-char-sequence:
    digit
    nondigit
    n-char-sequence digit
    n-char-sequence nondigit

يُعرّف التسلسل الموضوعي بأنه أطول تسلسل فرعي أولي لسلسلة الإدخال، بدءًا من أول حرف غير مسافة بيضاء، وهو بالشكل المتوقع. يحتوي التسلسل الموضوعي على لا شيء إذا لم تكن سلسلة الإدخال بالشكل المتوقع.

إذا كان للتسلسل الموضوعي الشكل المتوقع لرقم عشري، فإن تسلسل الأحرف الذي يبدأ بالرقم الأول أو حرف الفاصل العشري (أيهما يأتي أولاً) سيتم تفسيره كثابت عشري للغة C، باستثناء أن حرف الأساس سيتم استخدامه بدلاً من النقطة، وأنه إذا لم يظهر جزء أسي أو حرف فاصل عشري في رقم عشري عشري، أو إذا لم يظهر جزء أسي ثنائي في رقم عشري ستة عشري، فيفترض أن جزءًا أسيًا من النوع المناسب مع القيمة صفر يتبع آخر رقم في السلسلة. إذا بدأ التسلسل الموضوعي بشرطة سلبية ()، فيجب تفسير التسلسل على أنه سالب. سيتم تفسير تسلسل الأحرف INF أو INFINITY على أنه لانهاية، إذا كان قابلاً للتمثيل في نوع الإرجاع، وإلا فسيعامل على أنه ثابت عشري كبير جدًا بالنسبة لنطاق نوع الإرجاع. سيتم تفسير تسلسل الأحرف NAN أو NAN(n-char-sequenceopt) على أنه NaN هادئ، إذا كان مدعومًا في نوع الإرجاع، وإلا فسيعامل على أنه جزء من التسلسل الموضوعي ليس بالشكل المتوقع؛ معنى تسلسلات n-char معرّف حسب التنفيذ. يتم تخزين مؤشر إلى السلسلة النهائية في الكائن المشار إليه بواسطة endptr، بشرط ألا يكون endptr فارغًا.

إذا كان للتسلسل الموضوعي الشكل الست عشري و FLT_RADIX هو قوة للرقم 2، فسيتم تقريب القيمة الناتجة عن التحويل بشكل صحيح.

يتم تعريف حرف الأساس في الإعداد المحلي الحالي (الفئة LC_NUMERIC). في الإعداد المحلي POSIX، أو في إعداد محلي حيث لا يتم تعريف حرف الأساس، فسيكون حرف الأساس افتراضيًا إلى ('.').

في غير الإعداد المحلي C أو POSIX، قد يتم قبول أشكال إضافية للسلاسل الموضوعية الخاصة بالإعداد المحلي.

إذا كان التسلسل الموضوعي فارغًا أو لم يكن بالشكل المتوقع، فلن يتم إجراء أي تحويل؛ يتم تخزين قيمة nptr في الكائن المشار إليه بواسطة endptr، بشرط ألا يكون endptr فارغًا.

لن تقوم هذه الدوال بتغيير إعداد errno إذا نجحت.

نظرًا لأنه يتم إرجاع 0 عند حدوث خطأ وهو أيضًا قيمة صالحة عند النجاح، فيجب على التطبيق الذي يرغب في التحقق من حالات الخطأ تعيين errno إلى 0، ثم استدعاء strtod() أو strtof() أو strtold()، ثم التحقق من errno.

RETURN VALUE

عند الانتهاء بنجاح، يجب أن تعيد هذه الدوال القيمة المحولة. إذا لم يتم إجراء أي تحويل، يتم إرجاع 0، وقد يتم تعيين errno إلى [EINVAL].

إذا كانت القيمة الصحيحة خارج نطاق القيم القابلة للتمثيل، يتم إرجاع ±HUGE_VAL أو ±HUGE_VALF أو ±HUGE_VALL (وفقًا لإشارة القيمة)، ويتم تعيين errno إلى [ERANGE].

إذا كانت القيمة الصحيحة ستتسبب في نقص، يتم إرجاع قيمة لا يتجاوز حجمها أصغر رقم موجب عادي في نوع الإرجاع ويتم تعيين errno إلى [ERANGE].

ERRORS

ستفشل هذه الدوال إذا:

ERANGE
القيمة المراد إرجاعها ستسبب تجاوز أو نقص.

قد تفشل هذه الدوال إذا:

EINVAL
لم يتم إجراء أي تحويل.

NAME

strtod, strtof, strtold — convert string to double, float, and long double

SYNOPSIS

#include <stdlib.h>

double strtod(const char * nptr, char ** endptr);

float strtof(const char * nptr, char ** endptr);

long double strtold(const char * nptr, char ** endptr);

DESCRIPTION

The strtod(), strtof(), and strtold() functions convert the initial portion of the string pointed to by nptr to double, float, and long double representation, respectively.

The behavior of these functions is affected by the current locale that the program is running. See locale(7).

These functions do the following:

1. Skip leading whitespace characters (as determined by isspace(3)).

2. If the remaining string begins with a sign character ('+' or '-'), use this sign as the sign of the result.

3. Convert the succeeding characters as a sequence of digits (as determined by the locale's representation of decimal point and digits) and an optional decimal point. The characters forming the number are determined by the locale's settings. For example, in the "C" locale, the decimal point is '.' and the digits are '0' through '9'. In other locales, a comma (',') might be used as the decimal point.

4. Optionally, if the string contains a base specifier (e.g., "0x" or "0X" for hexadecimal numbers) or if the locale supports other radices, convert the number according to that radix.

5. Optionally, if the string contains an exponent part (e.g., "e10", "E+10", "p16", "P+16"), convert it to the appropriate power of the radix.

6. If endptr is not NULL, strtod() stores the address of the first invalid character in endptr. If there were no digits or sign, then this points to the initial string. If the string is empty or contains only white space, no conversion is performed and nptr is stored in the location pointed to by endptr.

7. If the value to be represented is too large to be represented in the corresponding return type, overflow occurs and the function returns the appropriate infinity (HUGE_VAL, HUGE_VALF, or HUGE_VALL) or -HUGE_VAL, -HUGE_VALF, or -HUGE_VALL. If the converted value would be subnormal, a range error may occur.

8. If no conversion can be performed, zero is returned.

The behavior of these functions is also affected by the LC_NUMERIC category of the current locale. See setlocale(3).

The strtof() function is equivalent to strtod() except for the return type. The strtold() function is equivalent to strtod() except for the return type.

The behavior of strtod(), strtof(), and strtold() is undefined if the string pointed to by nptr is not a valid number representation according to the locale settings.

The conversion stops at the first character that is not part of a valid number representation in the current locale.

For floating-point numbers, the conversion may be based on either decimal or hexadecimal notation.

In the "C" locale, the following forms are recognized:

1. Optional sign.

2. Decimal point characters ('.') followed by digits.

3. Digits followed by a decimal point character.

4. Digits, optionally followed by a decimal point character.

5. An optional exponent part consisting of 'e', 'E', 'p', or 'P', followed by an optional sign, followed by digits.

6. Alternatively, hexadecimal notation can be used. This consists of an optional sign, the string "0x" or "0X", followed by hexadecimal digits. An optional binary exponent part consisting of 'p' or 'P', followed by an optional sign, followed by decimal digits. A decimal point character ('.') within the hexadecimal digits part is also allowed.

The following are examples of valid numbers in the "C" locale:

"123", "-456.789", "+1.23e-4", "0X1A", "-0xff.aP+2"

RETURN VALUE

On success, these functions return the converted value. If the converted value cannot be represented by the return type, the value returned is implementation-defined (but usually is infinity). If the converted value is zero and the input string was not zero, but the value is too small to be represented, a range error occurs and zero is returned.

ERRORS

On overflow, strtod() sets errno to ERANGE and returns ±HUGE_VAL, ±HUGE_VALF, or ±HUGE_VALL. On underflow, zero is returned and errno may be set to ERANGE.

EXAMPLES

The following C code snippet demonstrates the usage of strtod():

#include <stdio.h>
#include <stdlib.h>

int
main(void)
{
    char *str;
    char *endptr;
    double val;

    str = "3.14159";
    val = strtod(str, &endptr);

    printf("strtod(\"%s\", &endptr) = %f\n", str, val);
    printf("endptr points to \"%s\"\n", endptr);

    str = "  -12345.6789   ";
    val = strtod(str, &endptr);

    printf("strtod(\"%s\", &endptr) = %f\n", str, val);
    printf("endptr points to \"%s\"\n", endptr);

    str = "12345";
    val = strtod(str, &endptr);

    printf("strtod(\"%s\", &endptr) = %f\n", str, val);
    printf("endptr points to \"%s\"\n", endptr);

    str = "0xFF"; /* Hexadecimal number */
    val = strtod(str, &endptr);

    printf("strtod(\"%s\", &endptr) = %f\n", str, val);
    printf("endptr points to \"%s\"\n", endptr);

    return 0;
}

The output of the above code is:

strtod("3.14159", &endptr) = 3.141590
endptr points to ""
strtod("  -12345.6789   ", &endptr) = -12345.678900
endptr points to "   "
strtod("12345", &endptr) = 12345.000000
endptr points to ""
strtod("0xFF", &endptr) = 0.000000
endptr points to "0xFF"

In the last case, the output is 0.0 because the "C" locale's `strtod` does not recognize "0xFF" as a valid number. To parse hexadecimal numbers, you would typically use `strtol` with base 16 and then cast the result to a double, or use `sscanf` with the appropriate format specifier.

Consider the following example with a different locale:

#include <stdio.h>
#include <stdlib.h>
#include <locale.h>

int
main(void)
{
    char *str;
    char *endptr;
    double val;

    /* Set locale to one that uses comma as decimal separator */
    if (setlocale(LC_NUMERIC, "fr_FR.UTF-8") == NULL) {
        fprintf(stderr, "Could not set locale");
        return 1;
    }

    str = "123,45";
    val = strtod(str, &endptr);

    printf("strtod(\"%s\", &endptr) = %f\n", str, val);
    printf("endptr points to \"%s\"\n", endptr);

    return 0;
}

The output of the above code (assuming the locale is available) is:

strtod("123,45", &endptr) = 123.450000
endptr points to ""

APPLICATION USAGE

The following code fragment demonstrates how to check for successful conversion:

#include <stdlib.h>
#include <stdio.h>
#include <errno.h>

// Function to check if a string represents an integer
int what_kind_of_number(const char *s) {
    char *endp;
    // Try converting to long first to check for integer-like format
    long val_long = strtol(s, &endp, 10); // Base 10

    // If the entire string was consumed and it was a valid long,
    // check if it might be interpreted as an integer by strtod in older C standards
    if (s != endp && *endp == '\0') {
        // In POSIX.1-1990, strtod could interpret "0x10" as integer 16
        // In POSIX.1-2001 and later, "0x10" is interpreted as float 16.0
        // We'll simulate the older behavior for demonstration.
        // Note: This simulation might not be perfectly accurate across all compilers/standards.

        // Let's assume the goal is to detect numbers that *could* be interpreted
        // as integers by a standard that allows hexadecimal integers without a dot or exponent.
        // The most straightforward check is if the string starts with "0x" or "0X"
        // and is followed by hex digits and nothing else.
        if (s[0] == '0' && (s[1] == 'x' || s[1] == 'X')) {
            // Check if the rest are valid hex digits
            const char *temp_endp;
            strtol(s, &temp_endp, 16); // Try base 16
            if (temp_endp != s && *temp_endp == '\0') {
                 // It's a valid hex integer string
                 printf("It's an integer with value %ld\n", val_long); // Using val_long from earlier strtol
                 return 0; // Success, it's an integer
            }
        }

        // If it wasn't a hex string, but was a valid integer string
        printf("It's an integer with value %ld\n", val_long);
        return 0; // Success, it's an integer
    }

    // If strtol didn't consume the whole string as a base-10 integer,
    // try interpreting it as a double using strtod.
    errno = 0; // Reset errno before the call to strtod
    double val_double = strtod(s, &endp);

    // Check for conversion errors or if the entire string was not consumed
    if (errno == ERANGE) {
        fprintf(stderr, "Error: Number out of range\n");
        return 1;
    }

    if (s != endp && *endp == '\0') {
        // The entire string was converted to a double
        printf("It's a float with value %g\n", val_double);
        return 0; // Success, it's a float
    } else {
        // Conversion failed or did not consume the entire string
        fprintf(stderr, "Error: Could not convert the entire string.\n");
        return 1;
    }
}

int main() {
    printf("Testing \\"123\\":\n");
    what_kind_of_number("123");

    printf("\nTesting \\"-45.67\\":\n");
    what_kind_of_number("-45.67");

    printf("\nTesting \\"0x10\\":\n");
    what_kind_of_number("0x10"); // This will be handled by the integer check

    printf("\nTesting \\"abc\\":\n");
    what_kind_of_number("abc");

    printf("\nTesting \\"10e3\\":\n");
    what_kind_of_number("10e3");

    return 0;
}

The above code snippet demonstrates a function that attempts to classify
a string as either an integer or a floating-point number.

Here's a breakdown:

1.  `strtol(s, &endp, 10)`: This attempts to convert the beginning of the
    string `s` into a long integer using base 10. The `endp` pointer will
    point to the first character that could not be converted.
2.  `if (s != endp && *endp == '\0')`: This condition checks if the entire
    string `s` was successfully converted into a long integer. If `s` is not
    equal to `endp`, it means at least one character was converted. If `*endp`
    is the null terminator (`\0'`), it means the conversion reached the end
    of the string.
3.  Special handling for "0x10":
    *   The code includes a specific check for strings starting with "0x" or
        "0X" to simulate behavior related to older C standards.
    *   In the ISO/IEC 9899:1990 standard, `strtod` could interpret hexadecimal
        literals like "0x10" as an integer value (16).
    *   In later standards (e.g., ISO/IEC 9899:1999 and later), `strtod`
        treats such strings as floating-point numbers (16.0), because
        hexadecimal floating-point notation was introduced without requiring
        a decimal point or binary exponent.
    *   The `what_kind_of_number` function tries to detect this specific case.
        It first uses `strtol` with base 16 to see if the "0x" string is a valid
        hexadecimal integer. If it is, it prints it as an integer.
4.  If the string was fully converted by `strtol` (base 10) and wasn't a
    hexadecimal number, it's treated as an integer.
5.  If `strtol` didn't consume the whole string as a base-10 integer, the
    code proceeds to use `strtod`.
6.  `errno = 0; double val_double = strtod(s, &endp);`: This attempts to
    convert the string `s` into a double-precision floating-point number.
    `errno` is reset before the call to catch potential range errors.
7.  Error Checking:
    *   `if (errno == ERANGE)`: Checks if the conversion resulted in overflow or
        underflow.
    *   `if (s != endp && *endp == '\0')`: Checks if the entire string was
        successfully converted into a `double`.
    *   If the conversion is successful and the entire string is consumed, it's
        printed as a float.
    *   If the string is not empty, not just whitespace, and `strtod` converts
        it entirely, it's considered a float. Otherwise, an error is reported.

Example Walkthrough:

If the function is called with:
what_kind_of_number("0x10")

The code first attempts `strtol("0x10", &endp, 10)`. This will likely fail
to convert the entire string to a base-10 integer, so `s != endp` might be
true, but `*endp` would not be `\0` (it would point to '0').

Then, it checks `if (s[0] == '0' && (s[1] == 'x' || s[1] == 'X'))`. This is
true for "0x10".
It then calls `strtol(s, &temp_endp, 16)`. This will successfully convert
"0x10" to 16, and `temp_endp` will point to the null terminator (`\0`).
The condition `temp_endp != s && *temp_endp == '\0'` will be true.
It then prints: "It's an integer with value 16" and returns 0.

This behavior aligns with the described interpretation for older C standards
where hexadecimal literals without explicit floating-point indicators were
treated as integers.

If the function is called with:
what_kind_of_number("16")

`strtol("16", &endp, 10)` will convert "16" entirely.
`s != endp` and `*endp == '\0'` will be true.
The check for "0x" or "0X" will fail.
It will print: "It's an integer with value 16" and return 0.

If the function is called with:
what_kind_of_number("16.0")

`strtol("16.0", &endp, 10)` will convert "16", and `endp` will point to '.'.
So, `*endp == '\0'` will be false.
The check for "0x" or "0X" will fail.
It proceeds to `strtod("16.0", &endp)`. This will successfully convert "16.0"
to 16.0.
`s != endp` and `*endp == '\0'` will be true.
It will print: "It's a float with value 16" and return 0.

The distinction between integer and float interpretation based on the C standard
is nuanced. This example attempts to highlight the difference in how a string
like "0x10" might be treated.

For a strict adherence to ISO/IEC 9899:1999 and later, where "0x10" is a
floating-point number, one would simply use `strtod` directly without the
special "0x" handling that assumes integer interpretation.
*/
// Example function demonstrating interpretation differences based on C standard versions.
// This is a simplified example and might not cover all edge cases or C standard nuances.
int demonstrate_strtod_behavior(const char *s) {
    char *endp;
    long val_long;
    double val_double;

    // --- ISO/IEC 9899:1990 (and earlier) interpretation ---
    // In older standards, strtod could interpret hexadecimal notation as integers.
    // A common way to check for this was to see if the entire string was consumed
    // by a base-16 conversion that didn't require a decimal point or exponent.
    // We simulate this by checking if it looks like a hex number and if strtol base 16
    // consumes the whole string.
    if (s[0] == '0' && (s[1] == 'x' || s[1] == 'X')) {
        char *hex_endp;
        // Try converting as a hex integer.
        long hex_val = strtol(s, &hex_endp, 16);
        if (s != hex_endp && *hex_endp == '\0') {
            printf("ISO/IEC 9899:1990 interpretation: It's an integer with value %ld\n", hex_val);
            // No return here to allow demonstrating the later standard's behavior too.
        }
    }

    // --- ISO/IEC 9899:1999 (and later) interpretation ---
    // In modern standards, hexadecimal notation without a decimal point or
    // binary exponent is treated as a floating-point number.
    errno = 0; // Reset errno before calling strtod
    val_double = strtod(s, &endp);

    if (errno == ERANGE) {
        fprintf(stderr, "Error: Number out of range for %s\n", s);
        return 1;
    }

    if (s != endp && *endp == '\0') {
        // Check if it was originally a hex string to specify the interpretation
        if (s[0] == '0' && (s[1] == 'x' || s[1] == 'X')) {
             printf("ISO/IEC 9899:1999 interpretation: It's a float with value %g\n", val_double);
        } else {
            // For non-hex numbers, strtod result is usually straightforward.
            // We can differentiate integer-like floats (e.g., "16.0") from others.
            // A simple check: if the double value is equal to its long integer cast.
            if (val_double == (double)(long)val_double) {
                 printf("It's an integer value with float representation %g\n", val_double);
            } else {
                 printf("It's a float with value %g\n", val_double);
            }
        }
    } else {
        fprintf(stderr, "Could not convert '%s' completely.\n", s);
        return 1;
    }
    return 0;
}

// Example usage in main for demonstration
int main() {
    printf("--- Demonstrating strtod behavior for \"0x10\" ---\n");
    demonstrate_strtod_behavior("0x10");
    printf("\n");

    printf("--- Demonstrating strtod behavior for \"16\" ---\n");
    demonstrate_strtod_behavior("16");
    printf("\n");

    printf("--- Demonstrating strtod behavior for \"16.0\" ---\n");
    demonstrate_strtod_behavior("16.0");
    printf("\n");

    printf("--- Demonstrating strtod behavior for \"1.23e4\" ---\n");
    demonstrate_strtod_behavior("1.23e4");
    printf("\n");

    printf("--- Demonstrating strtod behavior for \"abc\" ---\n");
    demonstrate_strtod_behavior("abc"); // This should report an error
    printf("\n");

    return 0;
}
