الاسم

smtpd.conf — ملف تكوين خادم SMTP

الوصف

smtpd.conf هو ملف التكوين الخاص بخادم البريد smtpd(8).

عند وصول البريد، يتم إنشاء ظرف بريد لكل أمر “RCPT TO:”. إذا تطابق الظرف مع أي من معايير محددة مسبقًا (باستخدام التوجيه match)، فسيتم قبول الرسالة للتسليم. يتم حفظ نسخة من الرسالة، بالإضافة إلى أظرفها المرتبطة، في قائمة انتظار البريد ويتم إرسالها لاحقًا وفقًا لمجموعة الإجراءات المرتبطة بها (باستخدام التوجيه action). إذا لم يتطابق الظرف مع أي خيارات، فسيتم رفضه. يتم تقييم قواعد المطابقة بالتتابع، مع فوز المطابقة الأولى.

تنسيق ملف التكوين مرن إلى حد ما. يمكن تمديد السطر الحالي عبر عدة أسطر باستخدام علامة الشرطة المائلة العكسية (‘\’). يمكن وضع التعليقات في أي مكان في الملف باستخدام علامة الهاش (‘#’)، وتمتد إلى نهاية السطر الحالي. يجب توخي الحذر عند التعليق على نص متعدد الأسطر: يكون التعليق فعالًا حتى نهاية الكتلة بأكملها. يجب وضع علامات اقتباس حول أسماء الوسائط التي لا تبدأ بحرف أو رقم أو شرطة سفلية، بالإضافة إلى الكلمات المحجوزة (مثل listen و match و port). يجب وضع الوسائط التي تحتوي على مسافات بيضاء بين علامتي اقتباس مزدوجتين (").

يتم تعريف الماكرو بأمر بالشكل name=value. يمكن أن يحتوي اسم الماكرو name على أحرف وأرقام وشرطات سفلية ولا يمكن أن يكون كلمة محجوزة. داخل الوسائط غير المقتبسة، يتم لاحقًا توسيع السلسلة $name إلى value.

على سبيل المثال:

lan_addr = "192.168.0.1"
listen on $lan_addr
listen on $lan_addr tls auth

يتم وصف بناء جملة smtpd.conf أدناه.

action name method [options]
عندما يعالج منفذ قائمة الانتظار ظرفًا من قائمة انتظار البريد، فإنه ينفذ action name، الذي تم تحديده بواسطة التوجيه match ... action عند استلام الرسالة. يوفر التوجيه action بيانات التكوين لمحاولات التسليم. يتم إجراء عمليات البحث المطلوبة في وقت كل محاولة تسليم. وبالتالي، فإن تغيير توجيه action أو الملفات التي يشير إليها وإعادة تشغيل خادم smtpd(8) يتسبب في سريان التغييرات لمحاولات التسليم اللاحقة للمرسل المعين name، حتى للرسائل التي كانت عالقة بالفعل في قائمة الانتظار قبل تغييرات التكوين.

قد يكون معامل طريقة التسليم method أحد ما يلي:

expand-only
قبول الرسالة فقط إذا تم تحديد طريقة تسليم في ملف الأسماء المستعارة أو ملف .forward.
forward-only
قبول الرسالة فقط إذا أدى المستلم إلى عنوان بعيد بعد معالجة الأسماء المستعارة أو ملف الترحيل.
lmtp destination [rcpt-to]
تسليم الرسالة إلى خادم LMTP على destination. يمكن التعبير عن الموقع كـ host:port أو كـ UNIX socket.

اختياريًا، يمكن تحديد rcpt-to لاستخدام عنوان البريد الإلكتروني للمستلم (بعد التوسيع) بدلاً من المستخدم المحلي في جلسة LMTP كـ RCPT TO.

maildir [pathname] [junk]
تسليم الرسالة إلى maildir في pathname إذا تم تحديده، أو افتراضيًا إلى ~/Maildir.

قد يحتوي المسار pathname على محددات تنسيق يتم توسيعها قبل الاستخدام (انظر محددات التنسيق).

إذا تم توفير الوسيط junk، فسيتم نقل الرسالة إلى مجلد ‘Junk’ إذا كان يحتوي على رأس ‘X-Spam’ إيجابي. سيتم إنشاء هذا المجلد تحت pathname إذا لم يكن موجودًا بالفعل.

mbox
تسليم الرسالة إلى صندوق البريد الخاص بالمستخدم مع mail.local(8).
mda command
تفويض التسليم إلى command الذي يتلقى الرسالة على مدخله القياسي (انظر أوامر MDA).

قد يحتوي الأمر command على محددات تنسيق يتم توسيعها قبل الاستخدام (انظر محددات التنسيق).

relay
إعادة توجيه الرسالة إلى خادم SMTP آخر.

تدعم طرق التسليم المحلية خيارات إضافية:

alias <table>
استخدام التعيين table لتوسيع aliases(5).
ttl n{s|m|h|d}
تحديد المدة التي يمكن أن تظل فيها الرسالة في قائمة الانتظار.
user username
تحديد اسم المستخدم username لإجراء التسليم، والبحث عنه باستخدام getpwnam(3).

يتم استخدام هذا للاستضافة الافتراضية حيث يكون اسم مستخدم واحد مسؤولًا عن معالجة التسليم لجميع المستخدمين الافتراضيين.

هذا الخيار غير قابل للاستخدام مع طريقة التسليم mbox.

سيتم معالجة ملف .forward الخاص بمستخدم التسليم فقط.

userbase <table>
استخدام التعيين table لعمليات بحث المستخدم بدلاً من وظيفة getpwnam(3).

لا ينطبق userbase على الخيار user.

virtual <table>
استخدام التعيين table للتوسيع الافتراضي. يتم وصف تنسيق جدول الأسماء المستعارة في table(5).
wrapper name
استخدام الغلاف المحدد في mda wrapper.

تدعم طرق التسليم المعاد توجيهها أيضًا خيارات إضافية:

backup
العمل كخادم بريد احتياطي يقوم بتسليم الرسائل إلى أي خادم بريد ذي أولوية أعلى.
backup mx name
العمل كخادم بريد احتياطي يقوم بتسليم الرسائل إلى أي خادم بريد ذي أولوية أعلى من خادم البريد المحدد باسم name.

[!] mail-from [regex] المرسل | <المرسل>
يحدد أن MAIL FROM للمعاملة يجب أن يتطابق مع السلسلة النصية أو جدول القائمة المرسل. الكلمة المفتاحية regex مطلوبة إذا كان المرسل تعبيرًا عاديًا أو جدولًا من التعابير العادية.
[!] rcpt-to [regex] المستلم | <المستلم>
يحدد أن RCPT TO للمعاملة يجب أن يتطابق مع السلسلة النصية أو جدول القائمة المستلم. الكلمة المفتاحية regex مطلوبة إذا كان المستلم تعبيرًا عاديًا أو جدولًا من التعابير العادية.
[!] tag [regex] علامة
يطابق المعاملات التي تم تمييزها بالعلامة المعطاة علامة. الكلمة المفتاحية regex مطلوبة إذا كان علامة تعبيرًا عاديًا.
[!] tls
يحدد أن المعاملة يجب أن تتم عبر قناة TLS.
match خيارات reject
رفض الرسالة الواردة أثناء حوار SMTP. يتم دعم نفس الخيارات كما هو الحال مع توجيه match action.
mda wrapper اسم الأمر
ربط الأمر مع غلاف وكيل تسليم البريد المسمى اسم. عندما يحدد تسليم محلي غلافًا، يتم تنفيذ الأمر المرتبط بالغلاف بدلاً من ذلك. قد يحتوي الأمر على محددات تنسيق (انظر محددات التنسيق).
mta max-deferred عدد
عندما يتم تعليق التسليم إلى مضيف معين بسبب فشل مؤقت، يتم تخزين ما لا يزيد عن عدد مظاريف لهذا المضيف بحيث يمكن تسليمها بمجرد نجاح تسليم آخر لهذا المضيف. الافتراضي هو 100.
pki اسم pki cert ملف الشهادة
ربط ملف الشهادة ملف الشهادة بمدخل pki اسم pki. يحدد مدخل pki تكوين زوج مفاتيح يمكن الإشارة إليه في قواعد المستمع وإجراءات المرحل.

يمكن إنشاء سلسلة شهادات عن طريق إلحاق شهادة واحدة أو أكثر، بما في ذلك شهادة سلطة الشهادات، إلى ملف الشهادة. توثيق إنشاء الشهادات موجود في starttls(8).

pki اسم pki key ملف المفتاح
ربط المفتاح الموجود في ملف المفتاح بمدخل pki اسم pki.
pki اسم pki dhe معلمات
تحديد معلمات DHE لاستخدامها مع مجموعات تشفير DHE مع مدخل pki اسم pki. القيم الصحيحة للمعلمات هي none، legacy، و auto. بالنسبة لـ legacy، يتم استخدام طول مفتاح ثابت قدره 1024 بت، بينما بالنسبة لـ auto، يتم تحديد طول المفتاح تلقائيًا. الافتراضي هو none، والذي يعطل مجموعات تشفير DHE.
proc اسم العملية الأمر
تسجيل عملية خارجية باسم اسم العملية من الأمر، وفقًا لـ smtpd-filters(7) API. يمكن استخدام هذه العمليات لمشاركة نفس المثيل بين عدة عوامل تصفية. إذا كان الأمر يبدأ بشرطة مائلة، فسيتم تنفيذه بمسار مطلق، وإلا فسيتم تشغيله من “/usr/lib/smtpd/opensmtpd”.
queue compression
تخزين ملفات قائمة الانتظار بتنسيق مضغوط. قد يكون هذا مفيدًا لتوفير مساحة القرص.
queue encryption [مفتاح]
تشفير ملفات قائمة الانتظار باستخدام EVP_aes_256_gcm(3). إذا لم يتم تحديد مفتاح، يتم قراءته باستخدام getpass(3). إذا تم استخدام السلسلة النصية stdin أو شرطة واحدة (‘-’) بدلاً من مفتاح، يتم قراءة المفتاح من الإدخال القياسي.
queue ttl تأخير
تعيين وقت انتهاء الصلاحية الافتراضي للرسائل غير القابلة للتسليم مؤقتًا، معطى كرقم صحيح عشري موجب متبوعًا بوحدة s، m، h، أو d. الافتراضي هو أربعة أيام (4d).
smtp ciphers تحكم
تعيين سلسلة التحكم لـ SSL_CTX_set_cipher_list(3). الافتراضي هو "HIGH:!aNULL:!MD5".
smtp limit max-mails عدد
تحديد عدد الرسائل بـ عدد لكل جلسة. الافتراضي هو 100.
smtp limit max-rcpt عدد
تحديد عدد المستلمين بـ عدد لكل معاملة. الافتراضي هو 1000.
smtp max-message-size حجم
رفض الرسائل الأكبر من حجم، المعطى كرقم موجب بالبايت أو كسلسلة نصية لتحليلها باستخدام scan_scaled(3). الافتراضي هو "35M".
smtp sub-addr-delim حرف
عند تحليل الجزء المحلي لعنوان بريد إلكتروني محلي، تجاهل حرف ASCII حرف وجميع الأحرف التي تليه. الافتراضي هو ‘+’.
srs key [backup] سر
تعيين المفتاح السري لاستخدامه في SRS، مخطط إعادة كتابة المرسل. يمكن تحديد الخيار backup لتعيين مفتاح سري لاستخدامه كاحتياطي لـ SRS؛ يمكن استخدام هذا لتنفيذ تدوير مفتاح SRS.
srs ttl تأخير
تعيين تأخير وقت انتهاء الصلاحية لمظاريف SRS. بعد هذا التأخير، سيتم تجاهل رد الارتداد إلى عنوان SRS للحد من مخاطر العناوين المزورة. الافتراضي هو أربعة أيام (4d).
table اسم [نوع:]مسار الملف
توفر الجداول معلومات تكوين إضافية لـ smtpd(8) في شكل قوائم أو تعيينات مفتاح-قيمة. يعتمد تنسيق الإدخالات على ما يستخدم الجدول من أجله. راجع table(5) للحصول على وثائق شاملة.

يتم تعريف كل جدول باسم اعتباطي وفريد اسم.

إذا كان النوع هو db، يتم تخزين المعلومات في ملف تم إنشاؤه باستخدام makemap(8)؛ إذا كان file أو محذوفًا، يتم تخزين المعلومات في ملف نص عادي باستخدام التنسيق الموضح في table(5). يجب أن يكون مسار الملف إلى الملف مطلقًا.

table اسم {قيمة [, ...]}
بدلاً من استخدام ملف منفصل، قم بتعريف جدول قائمة يحتوي على قيم ثابتة معطاة. يجب أن يحتوي الجدول على قيمة واحدة على الأقل وقد يعلن عن قيم متعددة كقائمة مفصولة بفواصل (مسافات اختيارية).
table اسم {مفتاح=قيمة [, ...]}
بدلاً من استخدام ملف منفصل، قم بتعريف جدول تعيين يحتوي على أزواج مفتاح-قيمة ثابتة معطاة. يجب أن يحتوي الجدول على زوج مفتاح-قيمة واحد على الأقل وقد يعلن عن أزواج متعددة كقائمة مفصولة بفواصل (مسافات اختيارية).

أمثلة

يستمع ملف smtpd.conf الافتراضي الذي يأتي مع OpenBSD على واجهة الشبكة المحلية (lo0) ويسمح بالبريد من المستخدمين والشياطين على الجهاز المحلي، بالإضافة إلى السماح للبريد بالوصول إلى خوادم بعيدة. بعض التكوينات الأكثر تعقيدًا مقدمة أدناه.

هذا المثال الأول مشابه للتكوين الافتراضي، ولكن يتم إعادة توجيه جميع رسائل البريد الصادرة إلى خادم SMTP بعيد. هناك حاجة إلى ملف أسرار لتحديد اسم مستخدم وكلمة مرور:

# touch /etc/smtpd/secrets
# chmod 640 /etc/smtpd/secrets
# chown root:smtpd /etc/smtpd/secrets
# echo "bob username:password" > /etc/smtpd/secrets

سيبدو ملف smtpd.conf كالتالي:

table aliases file:/etc/smtpd/aliases
table secrets file:/etc/smtpd/secrets

listen on lo0

action "local_mail" mbox alias <aliases>
action "outbound" relay host smtp+tls://bob@smtp.example.com \
	auth <secrets>

match from local for local action "local_mail"
match from local for any action "outbound"

في هذا المثال الثاني، الهدف هو السماح بتسليم البريد وإعادة توجيهه فقط للمستخدمين الذين يمكنهم المصادقة (باستخدام بيانات اعتماد تسجيل الدخول العادية الخاصة بهم). يجب توفير شهادة RSA لإثبات هوية الخادم. يستمع خادم البريد على جميع الواجهات التي تشير إليها المسارات الافتراضية. يتم إرسال البريد ذي الوجهة المحلية إلى MDA خارجي. أولاً، يتم إنشاء شهادة RSA:

# openssl genrsa -out /etc/ssl/private/mail.example.com.key 4096
# openssl req -new -x509 -key /etc/ssl/private/mail.example.com.key \
	-out /etc/ssl/mail.example.com.crt -days 365
# chmod 600 /etc/ssl/mail.example.com.crt
# chmod 600 /etc/ssl/private/mail.example.com.key

في المثال أعلاه، تم إنشاء شهادة صالحة لمدة عام. سيبدو ملف التكوين كالتالي:

pki mail.example.com cert "/etc/ssl/mail.example.com.crt"
pki mail.example.com key "/etc/ssl/private/mail.example.com.key"

table aliases file:/etc/smtpd/aliases

listen on lo0
listen on egress tls pki mail.example.com auth

action mda_with_aliases mda "/path/to/mda -f -" alias <aliases>
action mda_without_aliases mda "/path/to/mda -f -"
action "outbound" relay

match for local action mda_with_aliases
match from any for domain example.com action mda_without_aliases
match for any action "outbound"
match auth from any for any action "outbound"

بالنسبة للمواقع التي ترغب في توقيع الرسائل باستخدام DKIM، يستخدم المثال التالي opensmtpd-filter-dkimsign لتوقيع DKIM:

table aliases file:/etc/smtpd/aliases

filter "dkimsign" proc-exec "filter-dkimsign -d <domain> -s <selector> \
	-k /etc/smtpd/dkim/private.key" user _dkimsign group _dkimsign

listen on socket filter "dkimsign"
listen on lo0 filter "dkimsign"

action "local_mail" mbox alias <aliases>
action "outbound" relay

match for local action "local_mail"
match for any action "outbound"

بدلاً من ذلك، يمكن استخدام حزمة opensmtpd-filter-rspamd لتوفير التكامل مع rspamd، وهو شيطان طرف ثالث يوفر ميزات متعددة لمكافحة البريد العشوائي بالإضافة إلى توقيع DKIM. بالإضافة إلى تكوين rspamd نفسه، فإنه يتطلب استخدام الكلمة الرئيسية proc-exec:

filter "rspamd" proc-exec "filter-rspamd"

قد تتمكن المواقع التي تقبل رسائل غير محلية من تقليل حجم البريد العشوائي المستلم عن طريق رفض الرسائل المزورة التي تدعي أنها من النطاق المحلي. يستخدم المثال التالي جدول قائمة other-relays لتحديد عناوين IP الخاصة بالموجهات التي قد تنشأ بشكل شرعي رسائل بريد إلكتروني باسم مالك النطاق كمرسل.

table aliases file:/etc/smtpd/aliases
table other-relays file:/etc/smtpd/other-relays

listen on lo0
listen on egress

action "local_mail" mbox alias <aliases>
action "outbound" relay

match for local action "local_mail"
match for any action "outbound"
match !from src <other-relays> mail-from "@example.com" for any \
      reject
match from any for domain example.com action "local_mail"
