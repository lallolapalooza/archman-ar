SMARTD.CONF(5) SMART Monitoring Tools SMARTD.CONF(5)

اسم

smartd.conf - ملف تكوين شيطان مراقبة الأقراص الذكية

وصف

[صفحة الدليل هذه تم إنشاؤها لإصدار Linux من smartmontools. لا تحتوي على معلومات خاصة بالمنصات الأخرى.]

/etc/smartd.conf هو ملف التكوين الخاص بالشيء smartd.

إذا كان ملف التكوين /etc/smartd.conf موجودًا، فسيقوم smartd بقراءته عند البدء. إذا تلقى smartd لاحقًا إشارة HUP، فسيقوم بإعادة قراءة ملف التكوين. إذا كان smartd يعمل في وضع التصحيح، فإن إشارة INT ستجعله يعيد قراءة ملف التكوين أيضًا. يمكن توليد هذه الإشارة عن طريق كتابة <CONTROL-C> في نافذة الطرفية التي يعمل فيها smartd.

في غياب ملف تكوين، سيحاول smartd فتح جميع الأجهزة المتاحة (انظر صفحة الدليل smartd(8)). سيعطي ملف تكوين يحتوي على سطر واحد 'DEVICESCAN -a' نفس التأثير.

قد يكون هذا مزعجًا إذا كان لديك جهاز ATA أو SCSI يعلق أو يسلك سلوكًا خاطئًا عند تلقي أوامر SMART. حتى لو لم يتسبب هذا في أي مشاكل، فقد تكون مزعجًا بسلسلة رسائل سجل الأخطاء حول الأجهزة التي لا يمكن فتحها.

يمكن تجنب هذه المشكلة، واكتساب مزيد من التحكم في أنواع الأحداث التي يراقبها smartd، باستخدام ملف التكوين /etc/smartd.conf. يحتوي هذا الملف على قائمة بالأجهزة المراد مراقبتها، مع جهاز واحد في كل سطر. يتم تضمين ملف تكوين نموذجي مع توزيع smartmontools. ستجد ملف التكوين النموذجي هذا في /usr/share/doc/smartmontools/. للأمان، يجب ألا يكون ملف التكوين قابلاً للكتابة إلا بواسطة المستخدم الجذر (root).

  • يجب أن يكون هناك جهاز واحد مدرج في كل سطر، على الرغم من أنه يمكنك الحصول على أسطر تكون بالكامل تعليقات أو مسافات بيضاء.
  • أي نص يتبع علامة التجزئة '#' وحتى نهاية السطر يعتبر تعليقًا، ويتم تجاهله.
  • يمكن متابعة الأسطر باستخدام الشرطة المائلة للخلف '\' كآخر عنصر غير مسافة بيضاء أو تعليق في السطر.
  • ملاحظة: السطر الذي يبدأ أول حرف منه بعلامة التجزئة '#' يعامل كسطر فارغ بمسافات بيضاء، وليس كسطر غير موجود، وسوف ينهي سطر المتابعة.

إليك مثال لملف تكوين. إنه لأغراض توضيحية فقط؛ لا تقم بنسخه إلى نظامك دون قراءة حتى نهاية قسم التوجيهات أدناه!

################################################
# هذا ملف تكوين بدء تشغيل smartd نموذجي
# /etc/smartd.conf
#
# على القرص الثاني، ابدأ اختبار ذاتي طويل كل
# يوم أحد بين الساعة 3 و 4 صباحًا.
#
/dev/sda -a -m admin@example.com,root@localhost
/dev/sdb -a -I 194 -I 5 -i 12 -s L/../../7/03
#
# إرسال تحذير اختباري بالبريد الإلكتروني للمسؤول عند البدء.
#
/dev/sdc -m admin@example.com -M test
#
# قد يظهر قرص ATA كجهاز SCSI للنظام.
# إذا كانت هناك طبقة ترجمة SCSI إلى ATA (SAT)
# بين النظام والجهاز، فيمكن الإشارة إلى ذلك بالخيار '-d sat'.
/dev/sda -a -d sat
#
# الأقراص المتصلة بوحدة تحكم MegaRAID
# ابدأ اختبارات ذاتية قصيرة يوميًا بين 1-2، 2-3، و
# 3-4 صباحًا.
# Linux:
/dev/sda -d megaraid,0 -a -s S/../.././01
/dev/sda -d megaraid,1 -a -s S/../.././02
/dev/sda -d megaraid,2 -a -s S/../.././03
/dev/bus/0 -d megaraid,2 -a -s S/../.././03
#
# ثلاثة أقراص متصلة بوحدة تحكم AacRaid
# ابدأ اختبارات ذاتية قصيرة يوميًا بين 1-2، 2-3، و
# 3-4 صباحًا.
/dev/sda -d aacraid,0,0,66 -a -s S/../.././01
/dev/sda -d aacraid,0,0,67 -a -s S/../.././02
/dev/sda -d aacraid,0,0,68 -a -s S/../.././03
#
# قرصان SATA (ليسا SAS) على وحدة تحكم 3ware 9750.
# ابدأ اختبارات ذاتية طويلة أيام الأحد بين منتصف الليل و
# 1 صباحًا و 2-3 صباحًا
# تحت Linux
/dev/twl0 -d 3ware,0 -a -s L/../../7/00
/dev/twl0 -d 3ware,1 -a -s L/../../7/02
#
# قرصان متصلان بوحدة تحكم HP SmartArray الأولى
# التي تستخدم برنامج تشغيل cciss الخاص بنظام Linux. ابدأ اختبارات ذاتية طويلة
# في ليالي الأحد واختبارات ذاتية قصيرة كل ليلة وأرسل
# الأخطاء إلى root.
/dev/sda -d cciss,0 -a -s (L/../../7/02|S/../.././02) -m root
/dev/sda -d cciss,1 -a -s (L/../../7/03|S/../.././03) -m root
#
# ثلاثة أقراص SATA على وحدة تحكم HighPoint RocketRAID.
# ابدأ اختبارات ذاتية قصيرة يوميًا بين 1-2، 2-3، و
# 3-4 صباحًا.
# تحت Linux
/dev/sde -d hpt,1/1 -a -s S/../.././01
/dev/sde -d hpt,1/2 -a -s S/../.././02
/dev/sde -d hpt,1/3 -a -s S/../.././03
#
# قرصان SATA متصلان بوحدة تحكم HighPoint RocketRAID
# عبر جهاز pmport. ابدأ اختبارات ذاتية طويلة أيام الأحد
# بين منتصف الليل و 1 صباحًا و 2-3 صباحًا.
# تحت Linux
/dev/sde -d hpt,1/4/1 -a -s L/../../7/00
/dev/sde -d hpt,1/4/2 -a -s L/../../7/02
#
# ثلاثة أقراص SATA متصلة بوحدة تحكم Areca
# RAID. ابدأ اختبارات ذاتية طويلة أيام الأحد
# بين منتصف الليل و 3 صباحًا.
# تحت Linux
/dev/sg2 -d areca,1 -a -s L/../../7/00
/dev/sg2 -d areca,2 -a -s L/../../7/01
/dev/sg2 -d areca,3 -a -s L/../../7/02
#
# السطر التالي يمكّن مراقبة سجل أخطاء ATA
# وسجل أخطاء الاختبار الذاتي.
# كما أنه يتتبع التغييرات في سمات الفشل المسبق
# وسمات الاستخدام، بخلاف السمات
# 9 و 194 و 231، ويظهر استمرارية الأسطر:
#
/dev/sdd -l error \
     -l selftest \
     -t \         # السمات غير المتعقبة:
     -I 194 \     # درجة الحرارة
     -I 231 \     # درجة الحرارة أيضًا
     -I 9         # ساعات التشغيل
#

DEVICESCAN

إذا كان إدخال غير تعليقي في ملف التكوين هو السلسلة النصية DEVICESCAN بأحرف كبيرة، فسيقوم smartd بتجاهل أي أسطر متبقية في ملف التكوين، وسيقوم بالبحث عن الأجهزة. إذا لم يتبع DEVICESCAN أي توجيهات، فسيتم تطبيق '-a' على جميع الأجهزة.

قد يتبع DEVICESCAN اختياريًا توجيهات ستطبق على جميع الأجهزة التي يتم العثور عليها في المسح. على سبيل المثال:

  DEVICESCAN -m root@example.com

سيقوم بمسح جميع الأجهزة، ثم مراقبتها. سيرسل تحذيرًا واحدًا عبر البريد الإلكتروني لكل جهاز لأي مشاكل يتم العثور عليها.

  DEVICESCAN -H -m root@example.com

سيقوم بنفس الشيء، ولكنه يراقب فقط حالة صحة SMART للأجهزة، بدلاً من الوضع الافتراضي '-a'.

يمكن تحديد خيارات '-d TYPE' متعددة مع DEVICESCAN للجمع بين نتائج المسح لأكثر من TYPE واحدة.

قد تسبق إدخالات التكوين للأجهزة المحددة الإدخال DEVICESCAN. على سبيل المثال:

  DEFAULT -m root@example.com
  /dev/sda -s S/../.././02
  /dev/sdc -d ignore
  DEVICESCAN -s L/../.././02

سيقوم بمسح جميع الأجهزة باستثناء /dev/sda و /dev/sdc، ومراقبتها، وتشغيل اختبار طويل بين الساعة 2-3 صباحًا كل صباح. سيتم أيضًا مراقبة الجهاز /dev/sda، ولكن سيتم تشغيل اختبار قصير فقط. سيتم تجاهل الجهاز /dev/sdc. سيتم إرسال رسائل بريد إلكتروني تحذيرية لجميع الأجهزة المراقبة.

يتم تجاهل الجهاز بواسطة DEVICESCAN إذا كان هناك سطر تكوين بنفس اسم الجهاز موجودًا. يتم حل الارتباطات الرمزية قبل إجراء هذا الفحص. يتم أيضًا تجاهل اسم الجهاز إذا كان هناك جهاز آخر بمعلومات تعريف مطابقة (البائع، الطراز، إصدار البرنامج الثابت، الرقم التسلسلي، WWN) موجودًا بالفعل.

[NVMe: ميزة SMARTD 7.5 تجريبية جديدة] إذا كان الجهاز يدعم مساحة اسم واحدة فقط وكان سطر التكوين الذي يعالج معرف مساحة الاسم الخاصة به موجودًا بالفعل، فسيتم أيضًا تجاهل نتيجة DEVICESCAN التي لا تعالج مساحة اسم (والعكس صحيح).

الإعدادات الافتراضية

إذا بدأ إدخال في ملف التكوين بـ DEFAULT بدلاً من اسم جهاز، فسيتم تعيين جميع التوجيهات في هذا الإدخال كإعدادات افتراضية لإدخالات الأجهزة التالية.

هذا التكوين:

  DEFAULT -a -R5! -W 2,40,45 -I 194 -s L/../../7/00 -m admin@example.com
  /dev/sda
  /dev/sdb
  /dev/sdc
  DEFAULT -H -m admin@example.com
  /dev/sdd
  /dev/sde -d removable

له نفس التأثير كما لو كان:

  /dev/sda -a -R5! -W 2,40,45 -I 194 -s L/../../7/00 -m admin@example.com
  /dev/sdb -a -R5! -W 2,40,45 -I 194 -s L/../../7/00 -m admin@example.com
  /dev/sdc -a -R5! -W 2,40,45 -I 194 -s L/../../7/00 -m admin@example.com
  /dev/sdd -H -m admin@example.com
  /dev/sde -d removable -H -m admin@example.com

توجيهات ملف التكوين

يتحكم كل سطر في ملف التكوين في جهاز معين، أو يقوم بإعدادات افتراضية، أو يبدأ مسح الأجهزة.

يقمع رسائل البريد الإلكتروني التحذيرية ورسائل السجل المتكررة إذا تمت إزالة الجهاز بعد بدء التشغيل. يمكن استخدام هذا التوجيه بالاقتران مع توجيهات '-d' الأخرى.
تحذير: إزالة جهاز وتوصيل جهاز مختلف بنفس الواجهة غير مدعوم وقد يؤدي إلى تحذيرات غير صحيحة حتى يتم إعادة تشغيل smartd.

-n POWERMODE[,N][,q]
[ATA فقط] يستخدم توجيه "عدم الفحص" (nocheck) لمنع دوران القرص عندما يقوم smartd بالمسح الدوري له.

تحتوي أقراص ATA على خمسة أوضاع طاقة مختلفة. بترتيب زيادة استهلاك الطاقة هي: 'OFF'، 'SLEEP'، 'STANDBY'، 'IDLE'، و 'ACTIVE'. عادةً في أوضاع OFF و SLEEP و STANDBY لا تدور أطباق القرص. ولكن عادةً، استجابة لأوامر SMART الصادرة عن smartd، يتم تدوير أطباق القرص. لذلك إذا لم يتم استخدام هذا الخيار، فقد يتم تدوير القرص الذي يكون في وضع طاقة منخفض ووضعه في وضع طاقة أعلى عندما يقوم smartd بالمسح الدوري له.

لاحظ أنه إذا كان القرص في وضع SLEEP عند بدء تشغيل smartd، فلن يستجيب لأوامر smartd، وبالتالي لن يتم تسجيل القرص كجهاز ليراقبه smartd. إذا كان القرص في أي وضع طاقة منخفض آخر، فإن الأوامر الصادرة عن smartd لتسجيل القرص ستتسبب على الأرجح في تدويره.

يحدد توجيه '-n' (عدم الفحص) ما إذا كان سيتم إجراء فحوصات smartd الدورية أم لا عندما يكون الجهاز في وضع طاقة منخفض. يمكن استخدامه لمنع دوران القرص بسبب المسح الدوري لـ smartd. القيم المسموح بها لـ POWERMODE هي:

never - سيقوم smartd بمسح (فحص) الجهاز بغض النظر عن وضع طاقته. قد يتسبب هذا في دوران القرص المتوقف عن الدوران عند فحصه بواسطة smartd. هذا هو السلوك الافتراضي إذا لم يتم تقديم توجيه '-n'.

sleep - افحص الجهاز ما لم يكن في وضع SLEEP.

standby - افحص الجهاز ما لم يكن في وضع SLEEP أو STANDBY. في هذه الأوضاع، لا تدور معظم الأقراص، لذلك إذا كنت تريد منع قرص الكمبيوتر المحمول من الدوران في كل مرة يقوم فيها smartd بالمسح، فهذا هو ما تريده على الأرجح.

idle - افحص الجهاز ما لم يكن في وضع SLEEP أو STANDBY أو IDLE. في حالة IDLE، لا تزال معظم الأقراص تدور، لذلك قد لا يكون هذا ما تريده.

يمكن تحديد الحد الأقصى لعدد الفحوصات المتخطاة (بالتوالي) عن طريق إضافة الرقم الموجب ',N' إلى POWERMODE (مثل '-n standby,15'). بعد تخطي N فحصًا متتاليًا، يتم تجاهل وضع الطاقة ويتم إجراء الفحص على أي حال.

عند تخطي اختبار دوري، يكتب smartd عادةً رسالة سجل غير رسمية. يمكن قمع الرسالة عن طريق إضافة الخيار ',q' إلى POWERMODE (مثل '-n standby,q'). هذا يمنع قرص الكمبيوتر المحمول من الدوران بسبب هذه الرسالة.

يمكن تحديد كل من ',N' و ',q' معًا.

-T TYPE
يحدد مدى تحمل smartd لفشل أوامر SMART. الوسائط الصالحة لهذا التوجيه هي:

normal - لا تحاول مراقبة القرص إذا فشل أمر SMART إلزامي، ولكن استمر إذا فشل أمر SMART اختياري. هذا هو الافتراضي.

permissive - حاول مراقبة القرص حتى لو كان يفتقر إلى قدرات SMART. قد يكون هذا مطلوبًا لبعض الأقراص القديمة (قبل revision 4 من ATA-3) التي طبقت SMART قبل دمج معايير SMART في مواصفات ATA/ATAPI. [يرجى الاطلاع على خيار سطر الأوامر smartctl -T.]

-o VALUE
[ATA فقط] يمكّن أو يعطّل الاختبار الذاتي التلقائي لـ SMART عند بدء تشغيل smartd وليس له تأثير لاحق. الوسائط الصالحة لهذا التوجيه هي on و off.

التأخير بين الاختبارات خاص بالبائع، ولكنه عادة ما يكون أربع ساعات.

لاحظ أن الاختبار الذاتي التلقائي لـ SMART ليس جزءًا من مواصفات ATA. يرجى الاطلاع على وثائق خيار سطر الأوامر smartctl -o لمزيد من المعلومات حول هذه الميزة.

-S VALUE
يمكّن أو يعطّل الحفظ التلقائي للسمات عند بدء تشغيل smartd وليس له تأثير لاحق. الوسائط الصالحة لهذا التوجيه هي on و off. يؤثر أيضًا على أجهزة SCSI. [يرجى الاطلاع على خيار سطر الأوامر smartctl -S.]
-H [MASK]
تحقق من حالة صحة القرص. إذا أبلغ القرص عن حالة صحة فاشلة، فسيتم تسجيل رسالة بمستوى السجل LOG_CRIT في syslog. [يرجى الاطلاع على خيار سطر الأوامر smartctl -H.]

[ATA] يتحقق من نتيجة (منطقية) تم إرجاعها بواسطة أمر SMART RETURN STATUS. يتم تجاهل المعامل الاختياري MASK.

[SCSI] يتحقق من رمز الإحساس الإضافي (ASC) ومؤهل رمز الإحساس الإضافي (ASCQ) من صفحة سجل الاستثناءات غير الرسمية (IE) (إذا كان مدعومًا) و/أو من بيانات إحساس SCSI. يتم تجاهل المعامل الاختياري MASK.
ملاحظة: لأسباب تاريخية، يتم إجراء هذا الفحص دائمًا لأجهزة SCSI، بغض النظر عن توجيه '-H'.

[NVMe] يتحقق من البايت "التحذير الحرج" من سجل SMART/Health Information. إذا تم تعيين أي بت تحذير، فسيتم تسجيل رسالة بمستوى السجل LOG_CRIT في syslog.
[NVMe: ميزة SMARTD 7.5 الجديدة التجريبية] إذا تم تحديد المعامل الاختياري MASK (سداسي عشري)، فإن الفحص يقتصر على بتات التحذير المعينة في MASK. على سبيل المثال، إذا تم تحديد '-H 0xf9'، فسيتم تجاهل بت التحذير 1 ("درجة الحرارة خارج النطاق") وبت 2 ("انخفاض الموثوقية"). '-H 0xff' هو نفس '-H' بدون معامل.

-l TYPE
يبلغ عن زيادة في عدد الأخطاء في أحد سجلات SMART الثلاثة. الوسائط الصالحة لهذا التوجيه هي:

error - [ATA] أبلغ إذا زاد عدد أخطاء ATA المبلغ عنها في سجل ملخص أخطاء SMART منذ الفحص الأخير.

error - [NVMe] أبلغ إذا زاد "عدد إدخالات سجل معلومات الخطأ" من سجل SMART/Health Information منذ الفحص الأخير.
[ميزة SMARTD 7.4 الجديدة التجريبية] سيتم تسجيل هذا فقط على مستوى LOG_CRIT إذا كانت واحدة على الأقل من الأخطاء الجديدة لا تزال موجودة في سجل معلومات الخطأ وتشير حالتها إلى خطأ متعلق بالجهاز. يتم تسجيل ما يصل إلى ثمانية من أحدث هذه الأخطاء على مستوى LOG_INFO. هذا مفيد لأن سجل معلومات خطأ NVMe غير ثابت عبر دورات الطاقة أو إعادة تعيين الأجهزة.

إذا تم تحديد LLL أيضًا، يتم تحديد التأخيرات بحد أقصى LLL ساعة عن طريق حساب كل تأخير فردي كالتالي:
'((DRIVE_INDEX * NNN) mod (LLL + 1))'.

يتم تشغيل الاختبارات المجدولة فور انتهاء استطلاع الجهاز المجدول بانتظام، إذا كان التاريخ والوقت المحلي الحاليين ونوع الاختبار يتطابقون مع REGEXP. بشكل افتراضي، يحدث استطلاع الجهاز المجدول بانتظام كل ثلاثين دقيقة بعد بدء smartd. كن حذرًا إذا كنت تستخدم الخيار '-i' لجعل فترة الاستطلاع هذه أكثر من ستين دقيقة: قد لا تتزامن أوقات الاستطلاع مع أي من أوقات الاختبار التي حددتها باستخدام REGEXP. في هذه الحالة، سيتم تشغيل الاختبار بعد استطلاع الجهاز التالي.

قبل تشغيل اختبار خارجي أو ذاتي، يتحقق smartd للتأكد من عدم تشغيل اختبار ذاتي بالفعل. إذا كان هناك اختبار ذاتي قيد التشغيل بالفعل، فلن يتم مقاطعة هذا الاختبار قيد التشغيل لبدء اختبار آخر.

لن يحاول smartd تشغيل أي نوع من الاختبارات إذا تم بالفعل بدء أو تشغيل اختبار آخر في نفس الساعة.

لتجنب مشاكل الأداء أثناء تمهيد النظام، لن يحاول smartd تشغيل أي اختبارات مجدولة بعد أول استطلاع للجهاز (ما لم يتم تحديد '-q onecheck').

في كل مرة يتم فيها تشغيل اختبار، سيقوم smartd بتسجيل إدخال في SYSLOG. يمكنك استخدام هذه الإدخالات أو خيار سطر الأوامر '-q showtests' للتحقق من أنك قمت بإنشاء REGEXP بشكل صحيح. يضمن ترتيب المطابقة (L قبل S قبل C قبل O) أنه إذا كانت أنواع اختبارات متعددة مجدولة جميعًا لنفس الساعة، فإن نوع الاختبار الأطول له الأسبقية. هذا هو السلوك المرغوب فيه عادةً.

إذا تم استخدام الاختبارات المجدولة بالاشتراك مع استمرارية الحالة (خيار '-s')، فسيحاول smartd أيضًا مطابقة الساعات منذ آخر إيقاف تشغيل (أو 90 يومًا كحد أقصى). إذا كان يجب تشغيل أي اختبار أثناء فترة التوقف، فسيتم تشغيل أطول (انظر أعلاه) من هذه الاختبارات بعد استطلاع الجهاز الثاني.

إذا تم استخدام التوجيه '-n' وكان يجب تشغيل أي اختبار أثناء وضع الاستعداد للقرص، فسيتم تشغيل أطول هذه الاختبارات عند تنشيط القرص مرة أخرى.

لمستخدمي Unix: يرجى الانتباه إلى أن قواعد التعبيرات العادية الموسعة [regex(7)] ليست هي نفسها قواعد مطابقة أنماط أسماء الملفات بواسطة shell [glob(7)]. سيصدر smartd رسائل تحذير إعلامية غير ضارة إذا اكتشف أحرفًا في REGEXP تبدو وكأنها تشير إلى أنك ارتكبت هذا الخطأ.

-m ADD
إرسال بريد إلكتروني تحذيري إلى عنوان البريد الإلكتروني ADD إذا اكتشف التوجيهات '-H'، '-l error'، '-l xerror'، '-l selftest'، '-f'، '-C'، '-U'، أو '-W' فشلاً أو خطأ جديدًا، أو إذا فشل أمر SMART للقرص. يعمل هذا التوجيه فقط بالاشتراك مع هذه التوجيهات الأخرى (أو مع التوجيه الافتراضي '-a' المكافئ).

لمنع صندوق البريد الوارد الخاص بك من الامتلاء برسائل التحذير، بشكل افتراضي يتم إرسال تحذير واحد فقط (اعتمادًا على خيار '-s') ورسائل تذكير يومية لكل أنواع التنبيهات الممكّنة. انظر التوجيه '-M' أدناه للتفاصيل.

لإرسال البريد الإلكتروني إلى أكثر من مستخدم، يرجى استخدام النموذج "المفصول بفاصلة" التالي للعنوان: user1@add1,user2@add2,...,userN@addN (بدون مسافات).

لاختبار أن البريد الإلكتروني يتم إرساله بشكل صحيح، استخدم التوجيه '-M test' الموضح أدناه لإرسال رسالة بريد إلكتروني اختبار واحدة عند بدء تشغيل smartd.

بشكل افتراضي، يتم إرسال البريد الإلكتروني باستخدام أمر النظام mail(1). لكي يجد smartd هذا الأمر (عادةً /usr/bin/mail)، يجب أن يكون الملف التنفيذي في مسار shell أو البيئة التي تم بدء smartd منها. إذا كنت ترغب في تحديد مسار صريح لملف mail التنفيذي (على سبيل المثال /usr/local/bin/mail) أو برنامج نصي مخصص للتشغيل، يرجى استخدام التوجيه '-M exec' أدناه.

لاحظ أيضًا أن هناك وسيطة خاصة <nomailer> يمكن تقديمها إلى التوجيه '-m' بالاشتراك مع التوجيه '-M exec'. يرجى الاطلاع أدناه على شرح تأثيرها.

أمثلة على نصوص شل لـ '-M exec'
هذه أمثلة على نصوص شل يمكن استخدامها مع التوجيه '-M exec PATH' الموصوف سابقًا. مسارات هذه النصوص والملفات التنفيذية المماثلة هي وسيطة PATH للتوجيه '-M exec PATH'.

المثال 1: هذا النص للاستخدام مع '-m ADDRESS -M exec PATH'. يضيف مخرجات smartctl -a إلى مخرجات رسالة البريد الإلكتروني التحذيرية لـ smartd ويرسلها إلى ADDRESS.

#! /bin/sh
# حفظ رسالة البريد الإلكتروني (STDIN) في ملف:
cat > /root/msg
# إضافة مخرجات smartctl -a إلى الرسالة:
/usr/bin/smartctl -a -d $SMART_DEVICETYPE \
  $SMARTD_DEVICE >> /root/msg
# الآن أرسل الرسالة بالبريد الإلكتروني إلى المستخدم على العنوان ADD:
/usr/bin/mail -s "$SMARTD_SUBJECT" $SMARTD_ADDRESS \
  < /root/msg

المثال 2: هذا النص للاستخدام مع '-m <nomailer> -M exec PATH'. يحذر جميع المستخدمين من مشكلة في القرص، وينتظر 30 ثانية، ثم يقوم بإيقاف تشغيل الجهاز.

#! /bin/sh
# تحذير جميع المستخدمين من مشكلة
wall <<EOF
مشكلة تم اكتشافها مع القرص: $SMARTD_DEVICESTRING
رسالة التحذير من smartd هي: $SMARTD_MESSAGE
سيتم إيقاف تشغيل الجهاز بعد 30 ثانية...
EOF
# انتظر نصف دقيقة
sleep 30
# إيقاف تشغيل الجهاز
/sbin/shutdown -hf now

بعض النصوص البرمجية النموذجية موزعة مع حزمة smartmontools، في /usr/share/doc/smartmontools/examplescripts/.

يرجى ملاحظة أن هذه النصوص عادة ما تعمل كـ root، لذا يجب ألا تكون الملفات التي تقرأها / تكتبها قابلة للكتابة من قبل المستخدمين العاديين أو أن تكون موجودة في مجلدات مثل /tmp التي يمكن للمستخدمين العاديين الكتابة فيها وقد تعرض نظامك لهجمات الروابط الرمزية.

كما هو موضح سابقًا، إذا كتبت النصوص إلى STDOUT أو STDERR، فيتم تفسير ذلك على أنه مؤشر على وجود خطأ داخلي في النص، ويتم تسجيل جزء من STDOUT/STDERR في SYSLOG. ويتم التخلص من الباقي.
