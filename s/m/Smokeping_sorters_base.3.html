NAME

\n

Smokeping::sorters::base - Base Class for implementing SmokePing\n Sorters

\n
\n
\n

OVERVIEW

\n

Sorters are at the core of the SmokePing Charts feature, where the\n most interesting graphs are presented on a single page. The Sorter decides\n which graphs are considered interesting.

\n

Every sorter must inherit from the base class and provide it's own\n methods for the 'business' logic.

\n

In order to maintain a decent performance the sorters activity is\n split into two parts.

\n

The first part is active while the smokeping daemon gathers its\n data. Whenever data is received, the sorter is called to calculate a 'value'\n for the present data. On every 'query round' this information is stored in\n the sorter store directory. Each smokeping process stores it's own\n information. Since smokeping can run in multiple instances at the same time,\n the data may be split over several files

\n

The second part of the sorter is called from smokeping.cgi. It\n loads all the information from the sorter store and integrates it into a\n single 'tree'. It then calls each sorter with the pre-calculated data to get\n it sorted and to and to select the interesting information.

\n
\n
\n

DESCRIPTION

\n

Every sorter must provide the following methods:

\n
\n

new

\n

The new method expects hash elements as an argument eg\n new({x=>\\'d+',y=>\\'d+'},x=>1,y=>2). The first part is a syntax\n rule for the arguments it should expect and the second part are the\n arguments itself. The first part will be supplied by the child class as it\n calls the parent method.

\n
\n
\n

Desc

\n

Simply return the description of the function. This method must be\n overwritten by a children of the base class.

\n
\n
\n

SortTree

\n

Returns an array of 'targets'. It is up to the sorter to decide\n how many entries the list should contain. If the list is empty, the whole\n entry will be suppressed in the webfrontend.

\n

The method gets access to all the targets in the system, together\n with the last data set acquired for each target.

\n
\n
\n

CalcValues

\n

Figure out the current sorting value using te following input.

\n
$info = { uptime => w,\n          loss   => x,\n          median => y,\n          alert  => z, # (0/1)\n          pings  => [qw(a b c d)] }\n
\n

The output can have any structure you want. It will be returned to\n the sorter method for further processing.
