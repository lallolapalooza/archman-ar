الاسم

smtp-sink - خادم اختبار SMTP/LMTP المتوازي

ملخص

smtp-sink [خيارات] [inet:][المضيف]:المنفذ عدد الانتظار

smtp-sink [خيارات] unix:اسم المسار عدد الانتظار

الوصف


smtp-sink يستمع على المضيف (أو العنوان) والمنفذ المحددين. يأخذ رسائل SMTP من الشبكة ويتخلص منها. الغرض هو قياس أداء العميل، وليس الامتثال للبروتوكول.

يمكن أيضًا تكوين smtp-sink لالتقاط كل معاملة تسليم بريد إلى ملف. نظرًا لأن زمن الوصول إلى القرص كبير مقارنةً بالتأخيرات الشبكية، فإن وضع التشغيل هذا يمكن أن يقلل الأداء الأقصى بعدة مرات.

يمكن قبول الاتصالات على نقاط نهاية IPv4 أو IPv6، أو على مقابس نطاق UNIX. IPv4 و IPv6 هما الافتراضيان. هذا البرنامج هو المكمل لبرنامج smtp-source(1).

ملاحظة: هذا برنامج اختبار غير مدعوم. لا يتم بذل أي محاولة للحفاظ على التوافق بين الإصدارات المتتالية.

المعاملات:

-4
دعم IPv4 فقط. هذا الخيار ليس له تأثير عندما يتم بناء Postfix بدون دعم IPv6.
-6
دعم IPv6 فقط. هذا الخيار غير متاح عندما يتم بناء Postfix بدون دعم IPv6.
-8
لا تعلن عن دعم 8BITMIME.
-a
لا تعلن عن دعم مصادقة SASL.
-A تأخير
انتظر تأخير ثوانٍ بعد الرد على DATA، ثم قم بالإلغاء المبكر برمز رد 550. لا تقرأ المزيد من الإدخال من العميل؛ هذه محاولة لحظر العميل قبل إرسال ". ". حدد قيمة تأخير صفر للإلغاء الفوري.
-b رد-ارتداد-ناعم
استخدم رد-ارتداد-ناعم للردود المرفوضة بلطف. الرد الافتراضي هو "450 4.3.0 Error: command failed".
-B رد-ارتداد-صارم
استخدم رد-ارتداد-صارم للردود المرفوضة بصرامة. الرد الافتراضي هو "500 5.3.0 Error: command failed".
-c
عرض العدادات قيد التشغيل التي يتم تحديثها كلما انتهت جلسة SMTP، أو تم تنفيذ أمر QUIT، أو عند استلام ".".
-C
تعطيل دعم XCLIENT.
-d قالب-تفريغ
تفريغ كل معاملة بريد إلى ملف رسالة واحدة يتم إنشاء اسمه عن طريق توسيع قالب-تفريغ عبر strftime(3) وإلحاق رقم سداسي عشري شبه عشوائي (مثال: "%Y%m%d%H/%M." يتوسع إلى "2006081203/05.809a62e3"). إذا كان القالب يحتوي على أحرف "/"، يتم إنشاء الأدلة المفقودة تلقائيًا. يتم وصف تنسيق تفريغ الرسالة أدناه.

ملاحظة: هذا الخيار يحتفظ بملف التقاط واحد مفتوح لكل معاملة بريد قيد التقدم.

-D قالب-تفريغ
إلحاق معاملات البريد بملف تفريغ متعدد الرسائل يتم إنشاء اسمه عن طريق توسيع قالب-تفريغ عبر strftime(3). إذا كان القالب يحتوي على أحرف "/"، يتم إنشاء الأدلة المفقودة تلقائيًا. يتم وصف تنسيق تفريغ الرسالة أدناه.

ملاحظة: هذا الخيار يحتفظ بملف التقاط واحد مفتوح لكل معاملة بريد قيد التقدم.

-e
لا تعلن عن دعم ESMTP.
-E
لا تعلن عن دعم ENHANCEDSTATUSCODES.
-f أمر،أمر،...
رفض الأوامر المحددة برمز خطأ صارم (5xx). هذا الخيار يعني -p.

أمثلة للأوامر هي CONNECT، HELO، EHLO، LHLO، MAIL، RCPT، VRFY، DATA، .، RSET، NOOP، و QUIT. افصل أسماء الأوامر بمسافة بيضاء أو فواصل، واستخدم علامات الاقتباس لحماية المسافات البيضاء من shell. أسماء الأوامر غير حساسة لحالة الأحرف.

-F
تعطيل دعم XFORWARD.
-h اسم المضيف
استخدم اسم المضيف في تحية SMTP، وفي رد HELO، وفي رد EHLO. اسم المضيف الافتراضي هو "smtp-sink".
-H تأخير
تأخير عملية القراءة الأولى بعد استلام DATA (الوقت بالثواني). اجمع مع رسالة اختبار كبيرة وحجم نافذة TCP صغير (انظر الخيار -T) لاختبار تنفيذ Postfix client write_wait().
-L
تمكين LMTP بدلاً من SMTP.
-m عدد (الافتراضي: 256)
حد أقصى لعدد الاتصالات المتزامنة التي سيتمكن smtp-sink من معالجتها. يمنع هذا العملية من نفاد واصفات الملفات. ستبقى الاتصالات الزائدة في قائمة الانتظار في مكدس TCP/IP.
-M عدد
إنهاء بعد استلام عدد رسائل.
-n عدد
إنهاء بعد عدد جلسات.
-N
لا تعلن عن دعم DSN.
-p
لا تعلن عن دعم خط الأنابيب لأوامر ESMTP.
-P
تغيير تحية الخادم لتبدو وكأنها قادمة عبر نظام CISCO PIX. يعني -e.
-q أمر،أمر،...
قطع الاتصال (بدون رد) بعد استلام أحد الأوامر المحددة.

أمثلة للأوامر هي CONNECT، HELO، EHLO، LHLO، MAIL، RCPT، VRFY، DATA، .، RSET، NOOP، و QUIT. افصل أسماء الأوامر بمسافة بيضاء أو فواصل، واستخدم علامات الاقتباس لحماية المسافات البيضاء من shell. أسماء الأوامر غير حساسة لحالة الأحرف.

-Q أمر،أمر،...
إرسال رد 421 وقطع الاتصال بعد استلام أحد الأوامر المحددة.

أمثلة للأوامر هي CONNECT، HELO، EHLO، LHLO، MAIL، RCPT، VRFY، DATA، .، RSET، NOOP، و QUIT. افصل أسماء الأوامر بمسافة بيضاء أو فواصل، واستخدم علامات الاقتباس لحماية المسافات البيضاء من shell. أسماء الأوامر غير حساسة لحالة الأحرف.

-r أمر،أمر،...
رفض الأوامر المحددة برمز خطأ ناعم (4xx). هذا الخيار يعني -p.

أمثلة للأوامر هي CONNECT، HELO، EHLO، LHLO، MAIL، RCPT، VRFY، DATA، .، RSET، NOOP، و QUIT. افصل أسماء الأوامر بمسافة بيضاء أو فواصل، واستخدم علامات الاقتباس لحماية المسافات البيضاء من shell. أسماء الأوامر غير حساسة لحالة الأحرف.

-R دليل الجذر
تغيير دليل جذر العملية إلى الموقع المحدد. يتطلب هذا الخيار امتيازات المستخدم الخارق. انظر أيضًا الخيار -u.
-s أمر،أمر،...
تسجيل الأوامر المسماة إلى syslogd.

أمثلة للأوامر هي CONNECT، HELO، EHLO، LHLO، MAIL، RCPT، VRFY، DATA، .، RSET، NOOP، وQUIT. افصل أسماء الأوامر بمسافة بيضاء أو فواصل، واستخدم علامات الاقتباس لحماية المسافات البيضاء من shell. أسماء الأوامر غير حساسة لحالة الأحرف.

-S سلسلة بداية
سلسلة اختيارية يتم إدراجها في بداية كل رسالة يتم كتابتها إلى ملف تفريغ (انظر وصف تنسيق ملف التفريغ أدناه). تسلسلات الهروب C التالية مدعومة: \a (جرس)، \b (رجوع للخلف)، \f (تغذية نموذج)، \n (سطر جديد)، \r (عودة إلى بداية السطر)، \t (علامة جدولة أفقية)، \v (علامة جدولة رأسية)، \ddd (ما يصل إلى ثلاثة أرقام ثمانية) و \\ (الحرف الشرطة المائلة العكسية).
-t مهلة (الافتراضي: 100)
تحديد الوقت لاستلام أمر أو إرسال رد. يتم تحديد حد الوقت بالثواني.
-T حجم النافذة
تجاوز حجم نافذة TCP الافتراضي. لتجنب اختراق تطبيقات تغيير حجم النافذة TCP المعيبة، حدد قيمة > 0 و < 65536.

NAME

smtp-sink - SMTP server that logs all received mail

SYNOPSIS

smtp-sink [-4|-6] [-b] [-d] [-h hostname] [-l logname] [-p port] [-R] [-r rootdir] [-S text] [-T timeout] [-U username] [-v] [-w delay] [-W command:delay[:odds]] [inet:][host]:port ...

smtp-sink -m maildir ...

DESCRIPTION

The smtp-sink utility is a simple SMTP server that logs all received mail into the file system. It implements the SMTP protocol as specified in RFC 1869, RFC 821, RFC 822, RFC 2821, and RFC 2822. It is intended for testing, debugging, and forensic analysis of mail traffic.

The server can listen on one or more network interfaces and/or UNIX domain sockets. For each received message, it creates a separate file in a specified directory. The file name includes the client IP address, the destination recipient, and a timestamp.

The following command-line options are available:

-4
Listen on IPv4 addresses only.
-6
Listen on IPv6 addresses only.
-b
Don't fork into the background. Run in the foreground.
-d
Enable debugging output. This option can be specified multiple times to increase verbosity.
-h hostname
The hostname to use in the Received: header. Defaults to the system's network name.
-l logname
Specify the logging facility for syslog messages. Default is mail.
-m maildir
Instead of saving messages to individual files, append them to the specified maildir directory. This option can be specified multiple times. This option implies that the server should not fork into the background.
-p port
Listen on the specified TCP port. The default is 25. This option can be specified multiple times.
-R
Run in the specified directory after opening the network socket and changing the process user ID. This option is useful for security. See also the -U option.
-r rootdir
Change the process root directory to rootdir. This option is typically used with the -U option.
-S text
Prepend text to each dumped message. This is useful for adding custom headers or comments.
-T timeout
Set the idle timeout for network connections to timeout seconds. The default is 5 minutes.
-U username
Switch to the specified user privileges after opening the network socket and optionally changing the process root directory. This option is required when the process runs with super-user privileges. See also the -R option.
-v
Show the SMTP conversations.
-w delay
Wait delay seconds before responding to a DATA command.
-W command:delay[:odds]
Wait delay seconds before responding to command. If odds is also specified (a number between 1-99 inclusive), wait for a random multiple of delay. The random multiplier is equal to the number of times the program needs to roll a dice with a range of 0..99 inclusive, before the dice produces a result greater than or equal to odds.
[inet:][host]:port
Listen on network interface host (default: any interface) TCP port port. Both host and port may be specified in numeric or symbolic form.
unix:pathname
Listen on the UNIX-domain socket at pathname.
backlog
The maximum length of the queue of pending connections, as defined by the listen(2) system call.

DUMP FILE FORMAT

Each dumped message contains a sequence of text lines, terminated with the newline character. The sequence of information is as follows:

  • The optional string specified with the -S option.
  • The smtp-sink generated headers as documented below.
  • The message header and body as received from the SMTP client.
  • An empty line.

The format of the smtp-sink generated headers is as follows:

X-Client-Addr: text
The client IP address without enclosing []. An IPv6 address is prefixed with "ipv6:". This record is always present.
X-Client-Proto: text
The client protocol: SMTP, ESMTP or LMTP. This record is always present.
X-Helo-Args: text
The arguments of the last HELO or EHLO command before this mail delivery transaction. This record is present only if the client sent a recognizable HELO or EHLO command before the DATA command.
X-Mail-Args: text
The arguments of the MAIL command that started this mail delivery transaction. This record is present exactly once.
X-Rcpt-Args: text
The arguments of an RCPT command within this mail delivery transaction. There is one record for each RCPT command, and they are in the order as sent by the client.
Received: text
A message header for compatibility with mail processing software. This three-line header marks the end of the headers provided by smtp-sink, and is formatted as follows:
from helo ([addr])
The HELO or EHLO command argument and client IP address. If the client did not send HELO or EHLO, the client IP address is used instead.
by host (smtp-sink) with proto id random;
The hostname specified with the -h option, the client protocol (see X-Client-Proto above), and the pseudo-random portion of the per-message capture file name.
time-stamp
A time stamp as defined in RFC 2822.
