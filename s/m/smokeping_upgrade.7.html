SMOKEPING_UPGRADE(7) SmokePing SMOKEPING_UPGRADE(7)

الاسم

smokeping_upgrade - ملاحظات حول ترقية Smokeping

نظرة عامة

تحاول هذه الوثيقة سرد التغييرات غير المتوافقة أو الأخرى التي يراها المستخدم في إصدارات Smokeping، مع تعليمات حول كيفية إصلاح أي مشاكل محتملة. كما تذكر بشكل متقطع الميزات الجديدة وما شابه ذلك.

تبدأ الوثيقة حاليًا بالتغييرات من 1.34 إلى 1.37. إذا واجهت مشاكل في الترقية من إصدارات سابقة، يرجى إرسال وصف للمشاكل، مفضلًا مع ملاحظات حول كيفية إصلاحها، إلى القائمة البريدية "smokeping-users"، حتى يمكن إضافتها إلى هذه الوثيقة. ينطبق نفس الشيء على أي مشاكل تجدها في الإصدارات الحالية غير الموثقة هنا، بالطبع. نرحب كثيرًا بإرسال التصحيحات مقابل مصدر POD لهذا الملف.

إذا لم يتم إدراج إصدار، فلا توجد مشاكل معروفة في الترقية إليه من الإصدار السابق.

يمكن العثور على قائمة رسمية بالتغييرات مع كل إصدار في ملف CHANGES في توزيع Smokeping. تحاول هذه الوثيقة تكملة ذلك بتعليمات الترقية وما إلى ذلك.

2.4.2 إلى 2.4.3

لإصلاح التكبير لـ FF3.5، تم تحديث prototype و scriptaculous. لإكمال الإصلاح، يجب عليك أيضًا تحديث basepage.html الخاص بك وتضمين effects في سطر تحميل scriptaculous

cropper/lib/scriptaculous.js?load=builder,effects,dragdrop

2.3.6 إلى 2.4.0

تمت إضافة أداة SmokeTrace الجديدة إلى SmokePing. للحصول على تعليمات الإعداد، اقرأ صفحة دليل smoketrace.

2.3.3 إلى 2.3.4

تم تأمين بروتوكول الاتصال بين master و slave بشكل أكبر. يتطلب هذا ترقية كل من master و slave للاستمرار في العمل.

2.2.x إلى 2.3.x

2.3.0 يدور بشكل أساسي حول الميزات الجديدة. تحقق من وثائق المرجع حول hierarchies وخصائص الهدف parents و hidden و nomasterpoll.

الشيء الوحيد الذي يتعين عليك إلقاء نظرة عليه هو ملف basepage.html.dist الذي حصل على بعض خصائص CSS الجديدة. بدونها، ستبدو نتائج وظيفة التصفية الجديدة سيئة للغاية.

2.1.x إلى 2.2.0

اعتماد LWP

تتطلب وظيفة master/slave الجديدة الوحدة النمطية LWP::UserAgent من CPAN. حاليًا، التبعية اختيارية؛ ستحتاج إلى الوحدة حتى لو كنت تشغل نسخة واحدة فقط من Smokeping.

2.0.9 إلى 2.1.0

دعم Echoping 6

هذا هو أول إصدار من Smokeping يدعم echoping 6 بالكامل. إصدارات سابقة من أساليب EchoPingHttp لا تعمل مع echoping 6 بسبب عدم توافق سطر الأوامر. (لا يزال echoping 5 مدعومًا، بالطبع).

يقدم هذا الإصدار أيضًا ثلاثة أساليب جديدة تستخدم واجهة المكون الإضافي الجديدة لـ echoping المقدمة في الإصدار 6:

  • EchoPingDNS
  • EchoPingLDAP
  • EchoPingWhois

راجع وثيقة smokeping_examples للحصول على أمثلة بسيطة لاستخدام هذه الأساليب.

طريقة جديدة في base.pm (إذا كتبت أساليبك الخاصة)

تحدد الوحدة النمطية base.pm الطريقة ProbeUnit. قم بتجاوزها إذا لم تُرجع الطريقة الخاصة بك 'Seconds'. انظر FTPtransfer.pm للإلهام.

2.0.8 إلى 2.0.9

FPing

تمت إعادة متغير 'timeout' الذي تم إزالته في 2.0.5. يتم استخدامه لمنح أمر "fping" المعلمة "-t"، والتي تؤثر على ما يبدو على مهلة آخر ping في وضع العد ("-C") الذي يستخدمه Smokeping.

2.0.5 إلى 2.0.6

روابط CGI الذاتية (مرة أخرى)

تم تغيير طريقة إنشاء Smokeping للروابط الذاتية مرة أخرى. انظر القسم تحت '2.0.4 إلى 2.0.5' لوصف التغيير السابق.

أصبح السلوك الآن قابلاً للتخصيص عبر المتغير "linkstyle" في قسم "General" في ملف التكوين. الافتراضي الآن هو "relative"، مما ينشئ روابط مثل <a href="?foo=bar">. آمل أن يعمل هذا مع الجميع، ولكن إذا لم يكن كذلك، انظر smokeping_config للبدائل.

2.0.4 إلى 2.0.5

FPing

تمت إزالة متغير 'timeout'. تم استخدامه لمنح أمر "fping" المعلمة "-t"، ولكن نظرًا لأن هذه المعلمة فعالة فقط في وضع الافتراضي "fping"، بينما يستخدم Smokeping وضع العد ("-c")، فإنه لم يفعل شيئًا في الواقع.

روابط CGI الذاتية

تم تغيير طريقة إنشاء Smokeping للروابط الذاتية. استخدم السلوك القديم اسم البرنامج النصي ولكن ليس جزء المضيف، مما أدى إلى روابط مثل <a href="/path/smokeping.cgi?foo=bar">. يستخدم السلوك الجديد متغير "cgiurl": الروابط دائمًا مطلقة مثل <a href="http://some.host/path/smokeping.cgi?foo=bar">.

2.0.1 إلى 2.0.2

تنبيهات الحافة

يمكن الآن اختياريًا إرسال إشعارات التنبيه فقط عند تغيير حالة التنبيه. هذا يعني أن المطابقة الأولى للتنبيه فقط تولد إشعارًا، والمطابقات اللاحقة لا تفعل ذلك. عندما يتم مسح التنبيه، أي لم يعد هناك تطابق، يتم إرسال إشعار آخر.

يتم تمكين هذا السلوك بواسطة المتغير "edgetrigger" في قسم "Alerts". السلوك القديم (الذي يرسل إشعارًا مع كل تطابق) هو الافتراضي.

1.40 إلى 2.0

أكبر تغيير مع الإصدار 2.0 هو أن ملف التكوين يتم تحليله الآن بشكل أكثر صرامة. يجب أن يؤدي هذا إلى رسائل خطأ (يُفترض أنها مفهومة) مما يجعل التكوين أقل تجريبًا وخطأ مما كان عليه. كما أنه يقوم بأتمتة إنشاء وثائق التكوين من الكود المصدري، لذلك أصبحت المستندات الآن أكثر دقة.

تغيير أصغر جدير بالذكر هو تضمين البرنامج النصي tSmoke (مساهمة من Dan McGinn-Combs) لإرسال ملخصات البريد الإلكتروني حول حالة النظام اليومية والأسبوعية. لاحظ أنه يحتاج إلى تعريف متغير 'tmail' الجديد في ملف التكوين.

التكوين

ظلت صيغة التكوين كما هي في الغالب، باستثناء المشكلات أدناه.

PROBE_CONF
تم إهمال الأقسام الفرعية PROBE_CONF. يتم الآن تكوين جميع المتغيرات الخاصة بالهدف في نفس القسم مثل الهدف. ببساطة حذف

++ PRO

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

1.40 to 1.41

BE_CONF
The "BE_CONF" section has been removed. Configuration parameters that used to be specified there are now part of the general configuration in the "General" section. The new parameters are:
"datadir"
directory for RRD files
"moduledir"
directory for probe modules
"logdir"
directory for log files
"piddir"
directory for pid files
"htmldir"
directory for HTML files
"configdir"
directory for configuration files
The old "BE_CONF" section is now ignored, but it will cause a warning message. For a transition period, the "smokeping" command will warn about any unknown configuration lines and refuse to start if there are any such lines. This allows users to detect syntax errors and the new "--check" option is supposed to fix this (for any number of '+', obviously.)
PROBE_CONF
The existence of a "PROBE_CONF" section makes smokeping exit with an error message at parse time.
Note for distributors:
these lines could easily be removed automatically during upgrade.
Variable order
The "probe" variable must now be set before any variables that depend on the selected probe. This is because setting "probe" modifies the grammar of the rest of the section dynamically at parse time.

Additionally, "probe" must now precede "host", for reasons that have to do with the current implementation of mandatory variable checking.

Both of these errors are recognized at parse time and produce error messages accordingly.

Note for distributors: the "smokeping" command now has a new '--check' option that can be used to verify the syntax of the configuration file. It might be a good idea to do this on upgrade and give the user an explanatory note if the verification fails.

Target-specific variables in the Probes section
This is not an incompatible change, but it is mentioned here nevertheless. Target-specific variables can now be specified in the Probes section as well, and the values given become defaults for all the targets.
Timeouts
The "timeout" variable in the Probes section is now the maximum time expected for one ping to take. Previously it was the maximum time allowed for all the pings to one target. This is an incompatible change, but the code now works in the way it was documented to work even in 1.38.

Those probes offering a target-specific "timeout" variable will get a default for it from the Probes section, as noted in the previous item. This should ensure that probes that enforce the ping timeout themselves (most do) will not get killed due to timeout before they have a chance to do it.

Matchers
The matcher modules have been renamed to start with a capital letter, to differentiate the actual modules from the base classes. You have to capitalize the matcher name in the pattern definition accordingly.
Minimum number of pings
The "pings" variable now has an enforced minimum value of 3, as the whole design of Smokeping is based on the idea of sending several probes and measuring and visualizing the variation between them.
RRD parameter checking
Smokeping now checks at startup that the parameters of any existing RRD files match those specified in the configuration file. If there is a discrepancy, it will try to fix the situation and refuse to start if it can't.

This situation is most likely to happen if you have modified the "pings" variable in your configuration file. You'll then have to delete the old RRD file or somehow convert it to use the new parameters. The "rrdtune" command might be helpful here.

Configurable location for DYNAMIC-related files
There is now a new configuration variable, "dyndir", that can be used to specify the location of the DYNAMIC-related files (.adr and .snmp). These files used to be kept under "datadir" along with the RRD files, but since they need to be writable by the web server, it may be useful to separate these.

If "dyndir" is not specified, Smokeping will use the "datadir" value as the default. This should ensure that no existing setups will break.

In addition to this, some probes have had minor incompatible changes to their configuration.

RemoteFPing
The "rbinary" variable is now mandatory. This is a side effect from a bigger change: the probe is now derived from the FPing probe and supports all the variables FPing does.
FPing6
This probe is also now derived from FPing and supports all the variables FPing does.
Curl
The URL that will be used is now specified with the variable "urlformat" instead of "url". The new variable can (and usually should) include a placeholder for the "host" variable of each target as "%host%", eg. "urlformat = http://%host%/". The new variable is mandatory.

The change was made to fix the confusing situation where the "host" variable was required for each actual target, but it didn't actually have any effect (as the server to be probed came from the "url" variable.)

Timeouts are now recognized properly by looking at the curl exit code. The default timeout of this probe has been raised to 10 seconds.

The command line is now executed without an intervening /bin/sh, and so quotes are not needed anymore around the User-Agent string (the "agent" parameter). Smokeping will complain if it notices quotes around the string.

Any extra arguments for "curl" can now be specified in the "extraargs" variable.

EchoPingHttp
The default timeout of this probe has been raised to 10 seconds.
EchoPingHttps
The default timeout of this probe has been raised to 10 seconds.
EchoPingIcp
The "url" variable is now mandatory, as the old default "/" didn't make sense because it's relative rather than absolute.
LDAP
The "filter" variable is now mandatory, as Net::LDAP bails out without it.

The "sleeptime" variable was changed to "mininterval" and its semantics were changed accordingly (it's now the minimum time between two queries rather than the time slept between the end of one and the start of the another.)

Radius
The "sleeptime" variable was changed to "mininterval" and its semantics were changed accordingly. See the LDAP explanation above.
AnotherDNS
The "sleeptime" variable was changed to "mininterval" and its semantics were changed accordingly. See the LDAP explanation above. Additionally, the time is now specified in seconds rather than microseconds.
AnotherSSH
The "sleeptime" variable was changed to "mininterval" and its semantics were changed accordingly. See the LDAP explanation above. Additionally, the time is now specified in seconds rather than microseconds.
TelnetIOSPing
The name of this probe was changed: it now starts with a capital letter like all the others do.

The "target" variable was removed. The target should now be specified in the "host" variable, like it is with all the other probes.

CGI::Carp module version

The recommended version for CGI::Carp is now at least 1.24, included in CGI.pm-2.82 and the Perl standard distribution starting from 5.8.1. See the smokeping_install document.

1.38 to 1.40

The new navigation feature
The big visible difference between 1.38 and 1.40 is the new browser navigation feature: when clicking on the graphs in detail view you can select different time ranges for the graph. The creation of this feature has been sponsored by BeverlyCorp.com.

1.34 to 1.37

The RemoteFPing probe
The configuration of this probe was moved from the Targets section to the Probes section, as all the variables are really probe-specific. The moved variables were "rhost", "rbinary" and "rhost".
Logging changes
The "smokeping" daemon now warns at startup if syslog support is not turned on in the config file. This is because many diagnostic messages will otherwise get lost.
Concurrent probes
Each probe now runs in its own process, instead of them all running sequentially in one process. This makes it possible to specify different step lengths for different probes. You can get the old behaviour back by setting 'concurrentprobes = no'.

smokeping_upgrade(7) — smokeping 2.9.0

NAME

smokeping_upgrade — Upgrading smokeping

OVERVIEW

This document describes the changes and upgrade notes for Smokeping.

2.4.2 to 2.4.3

  • /usr/sbin/smokeping script fix.
  • Use /usr/bin/perl instead of /usr/bin/env perl.

2.3.6 to 2.4.0

  • A lot of changes in the core. smokeping core logic has been rewritten.
  • New target configuration syntax. See smokeping_config(5).
  • New CGI scripts.

2.3.3 to 2.3.4

  • rm-auth is now part of the main smokeping distribution.

2.2.x to 2.3.x

  • The entire configuration syntax has changed. Read smokeping_config(5) carefully.

2.1.x to 2.2.0

  • The configuration syntax has changed.
  • The user interface has changed.
  • Removed support for old CGI.pm.

2.0.9 to 2.1.0

  • The configuration syntax has changed.

2.0.8 to 2.0.9

  • Support for new FPING.
  • Various bugfixes.

2.0.5 to 2.0.6

  • Added support for FPING.

2.0.4 to 2.0.5

  • The configuration syntax has changed.

2.0.1 to 2.0.2

  • The configuration syntax has changed.

1.40 to 2.0

  • The configuration syntax has changed significantly.
  • The new syntax is described in smokeping_config(5).

1.38 to 1.40

  • The configuration syntax has changed.

1.34 to 1.37

  • The configuration syntax has changed.
