SCRIPT(1) أوامر المستخدم SCRIPT(1)

الاسم

script - إنشاء نسخة من جلسة الطرفية

ملخص

script [خيارات] [ملف]

الوصف

يقوم script بإنشاء نسخة مطبوعة من كل شيء في جلسة الطرفية الخاصة بك. يتم تخزين بيانات الطرفية بشكل خام في ملف السجل والمعلومات المتعلقة بالتوقيت في ملف سجل منظم آخر (اختياري). ملف سجل التوقيت ضروري لإعادة تشغيل الجلسة لاحقًا باستخدام scriptreplay(1) وتخزين معلومات إضافية حول الجلسة.

منذ الإصدار 2.35، يدعم script تدفقات متعددة ويسمح بتسجيل المدخلات والمخرجات في ملفات منفصلة أو جميعها في ملف واحد. يدعم هذا الإصدار أيضًا ملف توقيت جديد يسجل معلومات إضافية. يوفر الأمر scriptreplay --summary بعد ذلك كل المعلومات.

إذا تم توفير الوسيط ملف أو الخيار --log-out ملف، يقوم script بحفظ الحوار في هذا الملف. إذا لم يتم تقديم اسم ملف، يتم حفظ الحوار في الملف typescript.

لاحظ أن تسجيل المدخلات باستخدام --log-in أو --log-io قد يسجل معلومات حساسة أمنيًا حيث يحتوي ملف السجل على جميع مدخلات جلسة الطرفية (مثل كلمات المرور) بشكل مستقل عن إعداد علامة صدى الطرفية.

الخيارات

أدناه، قد يتبع الوسيط size اللواحق المضاعفة KiB (=1024)، MiB (=1024*1024)، وهكذا لـ GiB، TiB، PiB، EiB، ZiB و YiB (الـ "iB" اختياري، على سبيل المثال، "K" لها نفس معنى "KiB")، أو اللواحق KB (=1000)، MB (=1000*1000)، وهكذا لـ GB، TB، PB، EB، ZB و YB.

-a, --append

إلحاق المخرجات بـ ملف أو بـ typescript، مع الاحتفاظ بالمحتويات السابقة.

-c, --command command

تشغيل الأمر بدلاً من shell تفاعلي. هذا يسهل على البرنامج النصي التقاط مخرجات برنامج يتصرف بشكل مختلف عندما لا يكون stdout الخاص به tty.

-E, --echo when

يتحكم هذا الخيار في علامة ECHO لنهاية العبد للطرفية الزائفة للجلسة. الأوضاع المدعومة هي always (دائمًا)، never (أبدًا)، أو auto (تلقائي).

الافتراضي هو auto (تلقائي) - في هذه الحالة، تم تمكين ECHO للعبد الطرفي الزائف؛ إذا كان الإدخال القياسي الحالي طرفية، يتم تعطيل ECHO لها لمنع الصدى المزدوج؛ إذا لم يكن الإدخال القياسي الحالي طرفية (على سبيل المثال، أنبوب: echo date | script) فإن الحفاظ على تمكين ECHO للعبد الطرفي الزائف يسمح بعرض بيانات الإدخال القياسي على الشاشة أثناء تسجيلها في سجل الجلسة في وقت واحد.

لاحظ أن وضع 'never' (أبدًا) يؤثر على محتوى سجل مخرجات الجلسة، لأن إدخال المستخدم لا يتكرر في المخرجات.

-e, --return

إرجاع حالة الخروج لعملية الابن. يستخدم نفس التنسيق مثل إنهاء bash عند الإنهاء بسبب إشارة (أي، حالة الخروج هي 128 + رقم الإشارة). يتم دائمًا تخزين حالة الخروج لعملية الابن في ملف script من النوع أيضًا.

-f, --flush

مسح المخرجات بعد كل كتابة. هذا جيد للتعاون عن بعد: يقوم شخص واحد بعمل mkfifo foo؛ script -f foo، ويمكن لشخص آخر الإشراف في الوقت الفعلي على ما يتم باستخدام cat foo. لاحظ أن المسح يؤثر على الأداء؛ يمكن استخدام SIGUSR1 لمسح السجلات عند الطلب.

--force

السماح لملف المخرجات الافتراضي typescript بأن يكون رابطًا ثابتًا أو رمزيًا. سيتبع الأمر رابطًا رمزيًا.

-B, --log-io file

تسجيل المدخلات والمخرجات في نفس الملف. لاحظ أن هذا الخيار له معنى فقط إذا تم تحديد --log-timing أيضًا، وإلا فإنه من المستحيل فصل تدفقات المخرجات والمدخلات من ملف السجل.

-I, --log-in file

تسجيل المدخلات في الملف. يتم تعطيل مخرجات السجل إذا تم تحديد --log-in فقط.

استخدم وظيفة التسجيل هذه بحذر لأنها تسجل جميع المدخلات، بما في ذلك المدخلات عند تعطيل صدى الطرفية (على سبيل المثال، إدخالات كلمات المرور).

-O, --log-out file

تسجيل المخرجات في الملف. الافتراضي هو تسجيل المخرجات في الملف المسمى typescript إذا لم يتم تقديم الخيار --log-out أو --log-in. يتم تعطيل مخرجات السجل إذا تم تحديد --log-in فقط.

-T, --log-timing file

تسجيل معلومات التوقيت في الملف. يتم الآن دعم تنسيقين لملف التوقيت. يتم استخدام التنسيق الكلاسيكي عند تمكين تسجيل تدفق واحد فقط (المدخلات أو المخرجات). يتم استخدام تنسيق التدفق المتعدد عند --log-io أو عند استخدام --log-in و --log-out معًا. انظر أيضًا --logging-format.

-m, --logging-format format

فرض استخدام تنسيق سجل التوقيت المتقدم أو الكلاسيكي. الافتراضي هو التنسيق الكلاسيكي لتسجيل المخرجات فقط والتنسيق المتقدم عند طلب تسجيل المدخلات وكذلك المخرجات.

التنسيق الكلاسيكي

يحتوي سجل التوقيت على حقلين، مفصولين بمسافة. يشير الحقل الأول إلى مقدار الوقت المنقضي منذ المخرجات السابقة. يشير الحقل الثاني إلى عدد الأحرف التي تم إخراجها في هذا الوقت.

التنسيق المتقدم (متعدد التدفقات)

الحقل الأول هو معرف نوع الإدخال ('I'nput, 'O'utput, 'H'eader, 'S'ignal). الحقل الثاني هو مقدار الوقت المنقضي منذ الإدخال السابق، وبقية الإدخال هي بيانات خاصة بالنوع.

-o, --output-limit size

تحديد حجم ملفات script وسجلات التوقيت بـ size وإيقاف عملية الابن بعد تجاوز هذا الحجم. لا يشمل حجم الملف المحسوب رسائل البداية والانتهاء التي يضيفها أمر script قبل وبعد مخرجات عملية الابن. بسبب التخزين المؤقت، قد يكون ملف المخرجات الناتج أكبر من القيمة المحددة.

-q, --quiet

كن هادئًا (لا تكتب رسائل البدء والانتهاء إلى المخرجات القياسية).

-t[file], --timing[=file]

إخراج بيانات التوقيت إلى الخطأ القياسي، أو إلى file عند تقديمه. هذا الخيار مهمل لصالح --log-timing حيث الوسيط file ليس اختياريًا.

-h, --help

عرض نص المساعدة والخروج.

-V, --version

عرض الإصدار والخروج.

الإشارات

عند تلقي SIGUSR1، يقوم script بمسح ملفات المخرجات على الفور.

البيئة

يتم استخدام متغير البيئة التالي بواسطة script:

SHELL

إذا كان المتغير SHELL موجودًا، فستكون shell التي يتم إنشاؤها بواسطة script هي تلك الـ shell. إذا لم يتم تعيين SHELL، فسيتم افتراض shell Bourne. (معظم الـ shells تقوم بتعيين هذا المتغير تلقائيًا).

ملاحظات

تنتهي الـ script عندما تخرج الـ shell المنشأة ( control-D لـ shell Bourne (sh(1p))، و exit، logout أو control-d (إذا لم يتم تعيين ignoreeof) لـ shell C، csh(1)).

بعض الأوامر التفاعلية، مثل vi(1)، تنشئ قمامة في ملف الـ script. يعمل script بشكل أفضل مع الأوامر التي لا تتلاعب بالشاشة، والنتائج المقصودة لمحاكاة طرفية نسخة مطبوعة.

لا يُنصح بتشغيل script في shells غير تفاعلية. الـ shell الداخلية لـ script هي تفاعلية دائمًا، وهذا قد يؤدي إلى نتائج غير متوقعة. إذا كنت تستخدم script في ملف تهيئة الـ shell، يجب عليك تجنب الدخول في حلقة لا نهائية. يمكنك استخدام، على سبيل المثال، ملف .profile، الذي تقرأه الـ shells المسجلة فقط:

if test -t 0 ; t

hen script exit fi

يجب عليك أيضًا تجنب استخدام script في أنابيب الأوامر، حيث يمكن لـ script قراءة المزيد من الإدخال مما تتوقعه.

التاريخ

ظهر أمر script في 3.0BSD.

الأخطاء

يضع script كل شيء في ملف السجل، بما في ذلك فواصل الأسطر ومحرفات الرجوع للخلف. هذا ليس ما يتوقعه المستخدم العادي.

تم تصميم script بشكل أساسي لجلسات الطرفية التفاعلية. عندما لا يكون المدخل القياسي طرفية (على سبيل المثال: echo foo | script)، يمكن أن تتعثر الجلسة، لأن الشل التفاعلي داخل جلسة script يفتقد EOF وليس لدى script أي فكرة متى يغلق الجلسة. راجع قسم NOTES لمزيد من المعلومات.

انظر أيضًا

csh(1) (لآلية history)، scriptreplay(1)، scriptlive(1)
