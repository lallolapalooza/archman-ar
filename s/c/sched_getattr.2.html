sched_setattr(2) دليل استدعاءات النظام sched_setattr(2)

الاسم

sched_setattr, sched_getattr - تعيين واسترجاع سياسة الجدولة وسماتها

المكتبة

مكتبة C القياسية (libc, -lc)

الملخص

#include <sched.h>            /* تعريف ثوابت SCHED_* */
#include <sys/syscall.h>      /* تعريف ثوابت SYS_* */
#include <unistd.h>
int syscall(SYS_sched_setattr, pid_t pid, struct sched_attr *attr,
            unsigned int flags);
int syscall(SYS_sched_getattr, pid_t pid, struct sched_attr *attr,
            unsigned int size, unsigned int flags);

ملاحظة: لا توفر glibc واجهات استدعاء لهذه الاستدعاءات النظامية، مما يستلزم استخدام syscall(2).

الوصف

sched_setattr()

يقوم استدعاء النظام sched_setattr() بتعيين سياسة الجدولة والسمات المرتبطة بها للخيط المحدد بالمعرف pid. إذا كانت pid تساوي صفرًا، فسيتم تعيين سياسة الجدولة وسمات الخيط المستدعي.

حاليًا، يدعم Linux سياسات الجدولة "العادية" التالية (أي، غير الوقت الفعلي) كقيم يمكن تحديدها في policy:

SCHED_OTHER
سياسة تبديل الأدوار القياسية؛
SCHED_BATCH
لتنفيذ العمليات بأسلوب "الدُفعات"؛ و
SCHED_IDLE
لتشغيل الوظائف الخلفية ذات الأولوية المنخفضة جدًا.

يتم أيضًا دعم سياسات "الوقت الفعلي" المختلفة، للتطبيقات ذات الأولوية الزمنية التي تحتاج إلى تحكم دقيق في كيفية اختيار الخيوط القابلة للتنفيذ للتنفيذ. لمعرفة القواعد التي تحكم متى يمكن للعملية استخدام هذه السياسات، راجع sched(7). سياسات الوقت الفعلي التي يمكن تحديدها في policy هي:

SCHED_FIFO
سياسة "الوصول أولاً، والخروج أولاً"؛ و
SCHED_RR
سياسة تبديل الأدوار.

يوفر Linux أيضًا السياسة التالية:

SCHED_DEADLINE
سياسة جدولة المواعيد النهائية؛ راجع sched(7) للتفاصيل.

الوسيط attr هو مؤشر إلى هيكل يحدد سياسة الجدولة الجديدة والسمات للخيط المحدد. يكون لهذا الهيكل الشكل التالي:


struct sched_attr {
    u32 size;              /* حجم هذا الهيكل */
    u32 sched_policy;      /* السياسة (SCHED_*) */
    u64 sched_flags;       /* الأعلام */
    s32 sched_nice;        /* قيمة nice (SCHED_OTHER,
                              SCHED_BATCH) */
    u32 sched_priority;    /* الأولوية الثابتة (SCHED_FIFO,
                              SCHED_RR) */
    /* لـ SCHED_DEADLINE */
    u64 sched_runtime;
    u64 sched_deadline;
    u64 sched_period;
    /* تلميحات الاستخدام */
    u32 sched_util_min;
    u32 sched_util_max;
};

الحقول في هيكل sched_attr هي كالتالي:

size
يجب تعيين هذا الحقل إلى حجم الهيكل بالبايت، كما في sizeof(struct sched_attr). إذا كان الهيكل المقدم أصغر من هيكل النواة، فسيتم افتراض أن أي حقول إضافية هي "0". إذا كان الهيكل المقدم أكبر من هيكل النواة، تتحقق النواة من أن جميع الحقول الإضافية هي 0؛ إذا لم تكن كذلك، يفشل sched_setattr() بالخطأ E2BIG ويحدث size ليحتوي على حجم هيكل النواة.
السلوك أعلاه عندما لا يتطابق حجم هيكل sched_attr في مساحة المستخدم مع حجم هيكل النواة يسمح بالتوسع المستقبلي للواجهة. التطبيقات المشوهة التي تمرر هياكل كبيرة الحجم لن تتعطل في المستقبل إذا تم زيادة حجم هيكل النواة sched_attr. في المستقبل، يمكن أن يسمح ذلك أيضًا للتطبيقات التي تعرف عن هيكل sched_attr أكبر في مساحة المستخدم بتحديد ما إذا كانت تعمل على نواة أقدم لا تدعم الهيكل الأكبر.
sched_policy
يحدد هذا الحقل سياسة الجدولة، كواحدة من قيم SCHED_* المذكورة أعلاه.
sched_flags
يحتوي هذا الحقل على صفر أو أكثر من الأعلام التالية التي تم دمجها معًا للتحكم في سلوك الجدولة:
SCHED_FLAG_RESET_ON_FORK
لا ترث الأطفال الذين تم إنشاؤهم بواسطة fork(2) سياسات الجدولة المميزة. انظر sched(7) للتفاصيل.
SCHED_FLAG_RECLAIM (منذ Linux 4.13)
يسمح هذا العلم لخيط SCHED_DEADLINE باستعادة النطاق الترددي غير المستخدم من قبل خيوط الوقت الفعلي الأخرى.
SCHED_FLAG_DL_OVERRUN (منذ Linux 4.16)
يسمح هذا العلم لتطبيق ما بالحصول على إعلام بتجاوزات وقت التشغيل في خيوط SCHED_DEADLINE. قد تنتج مثل هذه التجاوزات عن (على سبيل المثال) المحاسبة الخشنة لوقت التنفيذ أو تعيين المعلمات غير الصحيح. يأخذ الإعلام شكل إشارة SIGXCPU التي يتم توليدها عند كل تجاوز.
هذه الإشارة SIGXCPU هي موجهة للعملية (انظر signal(7)) بدلاً من كونها موجهة للخيط. هذا ربما يكون خطأ. من ناحية، يتم استخدام sched_setattr() لتعيين سمة لكل خيط. من ناحية أخرى، إذا تم تسليم الإشارة الموجهة للعملية إلى خيط داخل العملية بخلاف الخيط الذي تجاوز وقت التشغيل، فلا توجد طريقة للتطبيق لمعرفة أي خيط تجاوز.
SCHED_FLAG_UTIL_CLAMP_MIN
SCHED_FLAG_UTIL_CLAMP_MAX (كلاهما منذ Linux 5.3)
تشير هذه الأعلام إلى أن حقلي sched_util_min أو sched_util_max، على التوالي، موجودان، ويمثلان الحد الأدنى والأقصى المتوقع لاستخدام الخيط.
توفر سمات الاستخدام للمجدول حدودًا يجب عليه جدولة الخيط ضمنها، مما قد يوجه قراراته بشأن وضع المهام واختيار التردد.
sched_nice
يحدد هذا الحقل قيمة nice التي سيتم تعيينها عند تحديد sched_policy كـ SCHED_OTHER أو SCHED_BATCH. قيمة nice هي رقم في النطاق -20 (أولوية عالية) إلى +19 (أولوية منخفضة)؛ انظر sched(7).
sched_priority
يحدد هذا الحقل الأولوية الثابتة التي سيتم تعيينها عند تحديد sched_policy كـ SCHED_FIFO أو SCHED_RR. يمكن تحديد نطاق الأولويات المسموح به لهذه السياسات باستخدام sched_get_priority_min(2) و sched_get_priority_max(2). بالنسبة للسياسات الأخرى، يجب تعيين هذا الحقل على 0.
sched_runtime
يحدد هذا الحقل معلمة "وقت التشغيل" لجدولة المواعيد النهائية. يتم التعبير عن القيمة بالنانوثانية. يستخدم هذا الحقل والحقلين التاليين فقط لجدولة SCHED_DEADLINE؛ لمزيد من التفاصيل، انظر sched(7).
sched_deadline
يحدد هذا الحقل معلمة "الموعد النهائي" لجدولة المواعيد النهائية.

sched_getattr()

يسترجع استدعاء النظام sched_getattr() سياسة الجدولة الحالية والسمات المرتبطة بها للخيط المحدد بواسطة pid. إذا كانت pid تساوي صفرًا، فسيتم استرجاع سياسة الجدولة والسمات للخيط المستدعي.

يجب على المتصل تعيين الحقل attr->size إلى حجم هيكل sched_attr المتاح في مساحة المستخدم. يتم استرجاع سياسة الجدولة والسمات في هيكل attr.

يجب تعيين الحقل flags إلى 0.

إذا كان pid يشير إلى عملية لا تنتمي إلى نفس المستخدم الذي تم تنفيذه، أو إذا كانت العملية لا تملك صلاحيات الجذر، فلن يتمكن المستدعي من قراءة سمات جدولة الوقت الفعلي.

قيمة الإرجاع

عند النجاح، تُرجع كلتا الوظيفتين 0. عند الفشل، تُرجع -1، ويتم تعيين errno بشكل مناسب.

الأخطاء

EACCES
تم تحديد سياسة جدولة غير مسموح بها، أو حاول المستدعي تعيين سياسة جدولة مميزة بدون صلاحيات مناسبة.
EAGAIN
لم يتمكن المجدول من تخصيص مورد مطلوب.
EINVAL
قيمة pid غير صالحة، أو فشلت التحقق من صحة الحقول في attr (مثل sched_policy غير صالح، أو sched_priority خارج النطاق، أو sched_runtime > sched_period، أو sched_deadline > sched_period).
EPERM
حاول المستدعي تعيين سياسة جدولة مميزة (مثل SCHED_FIFO أو SCHED_RR أو SCHED_DEADLINE) دون صلاحيات كافية (عادةً، صلاحيات الجذر).
ESRCH
لم يتم العثور على العملية أو الخيط المحدد بواسطة pid.

المعايير

هذه الوظائف هي أجزاء من POSIX.1-2001 (وأحدث). تم تقديم SCHED_DEADLINE في Linux 3.14.

NAME

sched_setattr, sched_getattr - set and get scheduling attributes

LIBRARY

Linux, glibc

SYNOPSIS

#include <linux/sched.h>

int sched_setattr(pid_t pid, const struct sched_attr *attr, unsigned int flags);

int sched_getattr(pid_t pid, struct sched_attr *attr, unsigned int size, unsigned int flags);

DESCRIPTION

The sched_setattr() and sched_getattr() system calls provide an interface to set and get scheduling attributes for a thread. These system calls are a superset of the functionality provided by the older sched_setscheduler(2) and sched_setparam(2) system calls.

The thread whose attributes are to be manipulated is specified by pid. If pid is zero, then the calling thread is used.

The attr argument is a pointer to a structure of type sched_attr, which contains the scheduling attributes. The structure is defined as follows:

struct sched_attr {
    __u32 size;

    __u32 sched_policy;
    __u64 sched_flags;

    /* SCHED_NORMAL, SCHED_FIFO, SCHED_RR */
    __u32 sched_priority;

    /* SCHED_NORMAL */
    __u64 sched_nice;

    /* SCHED_DEADLINE */
    __u64 sched_runtime;
    __u64 sched_deadline;
    __u64 sched_period;

    /* SCHED_Core, SCHED_SPARSE */
    __u64 sched_util_min;
    __u64 sched_util_max;
};

The size argument to sched_getattr() should be set to the size of the sched_attr structure as known to user space. This allows the interface to be extended in the future without breaking existing applications.

The flags argument is for future extensions and must be zero in the current implementation.

The scheduling policies supported by the kernel are defined in <linux/sched.h>:

SCHED_NORMAL
This is the default policy for normal tasks. It is a fair-share scheduling policy. The sched_priority field is ignored. sched_nice can be used to adjust the priority, with lower values indicating higher priority (similar to the traditional nice value).
SCHED_FIFO
This is a real-time first-in, first-out scheduling policy. Threads with this policy are run in preference to any thread with a normal or SCHED_RR policy. Threads with the same priority are run in the order they were created. The sched_priority field determines the priority, with higher values indicating higher priority. Valid priorities are in the range [1, 99]. The sched_nice field is ignored.
SCHED_RR
This is a real-time round-robin scheduling policy. It is similar to SCHED_FIFO, but threads are given a fixed time slice. If a thread does not voluntarily yield the CPU, it will be preempted after its time slice expires. The sched_priority field determines the priority, with higher values indicating higher priority. Valid priorities are in the range [1, 99]. The sched_nice field is ignored.
SCHED_DEADLINE
This is a real-time scheduling policy based on runtime, deadline, and period. It is designed for tasks with periodic or sporadic real-time requirements. The sched_runtime, sched_deadline, and sched_period fields are used to specify the scheduling parameters. This policy is only available if the kernel is configured with CONFIG_SCHED_DEADLINE.
SCHED_CORE
This is a scheduling policy that allows tasks to specify their CPU utilization requirements. It is useful for tasks that need to run at a certain percentage of CPU time. The sched_util_min and sched_util_max fields are used to specify the minimum and maximum CPU utilization, respectively. This policy is only available if the kernel is configured with CONFIG_SCHED_CORE.
SCHED_SPARSE
This scheduling policy is similar to SCHED_CORE but is designed for tasks that do not require continuous CPU time. It allows tasks to specify their CPU utilization requirements and can be used to schedule tasks more efficiently on systems with heterogeneous CPU capacities. The sched_util_min and sched_util_max fields are used to specify the minimum and maximum CPU utilization, respectively. This policy is only available if the kernel is configured with CONFIG_SCHED_SPARSE.

sched_setattr()

The sched_setattr() system call sets the scheduling policy and attributes for the thread specified by pid.

The attr argument points to a sched_attr structure containing the desired scheduling attributes. The kernel checks that the values in the structure are valid for the specified policy.

The flags argument is provided to allow for future extensions to the interface; in the current implementation it must be specified as 0.

SCHED_FLAG_RESET_ON_FORK
If this flag is set in sched_flags, the scheduling attributes will be reset to the default values for the child thread after a fork(2) operation. This flag is only supported for the normal scheduling policy.
SCHED_FLAG_KEEP_POLICY
If this flag is set in sched_flags, the scheduling policy will be kept after a fork(2) operation. This flag is only supported for the normal scheduling policy.
SCHED_FLAG_UTIL_CLAMP_MIN
If this flag is set in sched_flags, the task's minimum CPU utilization is clamped to the value specified in sched_util_min. This flag is only supported for the SCHED_CORE and SCHED_SPARSE policies.
SCHED_FLAG_UTIL_CLAMP_MAX
If this flag is set in sched_flags, the task's maximum CPU utilization is clamped to the value specified in sched_util_max. This flag is only supported for the SCHED_CORE and SCHED_SPARSE policies.
SCHED_FLAG_UTIL_CLAMP
If this flag is set in sched_flags, the task's CPU utilization is clamped to the range specified by sched_util_min and sched_util_max. This flag is only supported for the SCHED_CORE and SCHED_SPARSE policies.
sched_runtime
This field specifies the "Runtime" parameter for deadline scheduling. The value is expressed in nanoseconds.
sched_deadline
This field specifies the "Deadline" parameter for deadline scheduling. The value is expressed in nanoseconds.
sched_period
This field specifies the "Period" parameter for deadline scheduling. The value is expressed in nanoseconds.
sched_util_min
sched_util_max (both since Linux 5.3)
These fields specify the expected minimum and maximum utilization, respectively. They are ignored unless their corresponding SCHED_FLAG_UTIL_CLAMP_MIN or SCHED_FLAG_UTIL_CLAMP_MAX is set in sched_flags.
Utilization is a value in the range [0, 1024], representing the percentage of CPU time used by a task when running at the maximum frequency on the highest capacity CPU of the system. This is a fixed point representation, where 1024 corresponds to 100%, and 0 corresponds to 0%. For example, a 20% utilization task is a task running for 2ms every 10ms at maximum frequency and is represented by a utilization value of 0.2 * 1024 = 205.
A task with a minimum utilization value larger than 0 is more likely scheduled on a CPU with a capacity big enough to fit the specified value. A task with a maximum utilization value smaller than 1024 is more likely scheduled on a CPU with no more capacity than the specified value.
A task utilization boundary can be reset by setting its field to UINT32_MAX (since Linux 5.11).

The flags argument is provided to allow for future extensions to the interface; in the current implementation it must be specified as 0.

sched_getattr()

The sched_getattr() system call fetches the scheduling policy and the associated attributes for the thread whose ID is specified in pid. If pid equals zero, the scheduling policy and attributes of the calling thread will be retrieved.

The size argument should be set to the size of the sched_attr structure as known to user space. The value must be at least as large as the size of the initially published sched_attr structure, or the call fails with the error EINVAL.

The retrieved scheduling attributes are placed in the fields of the sched_attr structure pointed to by attr. The kernel sets attr.size to the size of its sched_attr structure.

If the caller-provided attr buffer is larger than the kernel's sched_attr structure, the additional bytes in the user-space structure are not touched. If the caller-provided structure is smaller than the kernel sched_attr structure, the kernel will silently not return any values which would be stored outside the provided space. As with sched_setattr(), these semantics allow for future extensibility of the interface.

The flags argument is provided to allow for future extensions to the interface; in the current implementation it must be specified as 0.

RETURN VALUE

On success, sched_setattr() and sched_getattr() return 0. On error, -1 is returned, and errno is set to indicate the error.

ERRORS

sched_getattr() and sched_setattr() can both fail for the following reasons:

EINVAL
attr is NULL; or pid is negative; or flags is not zero.
ESRCH
The thread whose ID is pid could not be found.

In addition, sched_getattr() can fail for the following reasons:

E2BIG
The buffer specified by size and attr is too small.
EINVAL
size is invalid; that is, it is smaller than the initial version of the sched_attr structure (48 bytes) or larger than the system page size.

In addition, sched_setattr() can fail for the following reasons:

E2BIG
The buffer specified by size and attr is larger than the kernel structure, and one or more of the excess bytes is nonzero.
EBUSY
SCHED_DEADLINE admission control failure, see sched(7).
EINVAL
attr.sched_policy is not one of the recognized policies.
EINVAL
attr.sched_flags contains a flag other than SCHED_FLAG_RESET_ON_FORK.
EINVAL
attr.sched_priority is invalid.
EINVAL
attr.sched_policy is SCHED_DEADLINE, and the deadline scheduling parameters in attr are invalid.
EINVAL
attr.sched_flags contains SCHED_FLAG_UTIL_CLAMP_MIN or SCHED_FLAG_UTIL_CLAMP_MAX, and attr.sched_util_min or attr.sched_util_max are out of bounds.
EOPNOTSUPP
SCHED_FLAG_UTIL_CLAMP was provided, but the kernel was not built with CONFIG_UCLAMP_TASK support.
EPERM
The caller does not have appropriate privileges.
EPERM
The CPU affinity mask of the thread specified by pid does not include all CPUs in the system (see sched_setaffinity(2)).

STANDARDS

Linux.

HISTORY

Linux 3.14.

NOTES

glibc does not provide wrappers for these system calls; call them using syscall(2).

sched_setattr() provides a superset of the functionality of sched_setscheduler(2), sched_setparam(2), nice(2), and (other than the ability to set the priority of all processes belonging to a specified user or all processes in a specified group) setpriority(2). Analogously, sched_getattr() provides a superset of the functionality of sched_getscheduler(2), sched_getparam(2), and (partially) getpriority(2).

BUGS

In Linux versions up to 3.15, sched_setattr() failed with the error EFAULT instead of E2BIG for the case described in ERRORS.

Up to Linux 5.3, sched_getattr() failed with the error EFBIG if the in-kernel sched_attr structure was larger than the size passed by user space.
