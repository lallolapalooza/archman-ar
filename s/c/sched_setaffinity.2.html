sched_setaffinity(2) دليل استدعاءات النظام sched_setaffinity(2)

الاسم

sched_setaffinity, sched_getaffinity - تعيين واسترجاع قناع انتماء المعالج (CPU) للخيط (thread)

المكتبة

مكتبة C القياسية (libc، -lc)

الملخص

#define _GNU_SOURCE             /* انظر feature_test_macros(7) */
#include <sched.h>
int sched_setaffinity(pid_t pid, size_t cpusetsize,
                      const cpu_set_t *mask);
int sched_getaffinity(pid_t pid, size_t cpusetsize,
                      cpu_set_t *mask);

الوصف

يحدد قناع انتماء المعالج (CPU affinity mask) للخيط (thread) مجموعة المعالجات التي يحق له العمل عليها. على نظام متعدد المعالجات، يمكن استخدام تعيين قناع انتماء المعالج للحصول على فوائد أدائية. على سبيل المثال، من خلال تخصيص معالج واحد لخيط معين (أي، تعيين قناع انتماء ذلك الخيط لتحديد معالج واحد، وتعيين قناع انتماء جميع الخيوط الأخرى لاستبعاد ذلك المعالج)، يمكن تحقيق أقصى سرعة تنفيذ لذلك الخيط. كما أن تقييد خيط للعمل على معالج واحد يتجنب تكلفة الأداء الناتجة عن عدم صلاحية ذاكرة التخزين المؤقت (cache invalidation) التي تحدث عندما يتوقف خيط عن التنفيذ على معالج واحد ثم يستأنف التنفيذ على معالج مختلف.

يتم تمثيل قناع انتماء المعالج بواسطة البنية cpu_set_t، وهي "مجموعة معالجات" (CPU set)، يتم الإشارة إليها بواسطة mask. يتم وصف مجموعة من وحدات الماكرو لمعالجة مجموعات المعالجات في CPU_SET(3).

تقوم sched_setaffinity() بتعيين قناع انتماء المعالج للخيط الذي معرفه pid إلى القيمة المحددة بواسطة mask. إذا كان pid صفرًا، يتم استخدام الخيط المستدعي.

إذا لم يكن الخيط المحدد بواسطة pid يعمل حاليًا على أحد المعالجات المحددة في mask، فسيتم ترحيل هذا الخيط إلى أحد المعالجات المحددة في mask.

تقوم sched_getaffinity() بكتابة قناع انتماء الخيط الذي معرفه pid إلى بنية cpu_set_t التي يشير إليها mask. تحدد المعلمة cpusetsize حجم (بالبايت) mask. إذا كان pid صفرًا، يتم إرجاع قناع الخيط المستدعي.

قيمة الإرجاع

عند النجاح، تعيد sched_setaffinity() و sched_getaffinity() القيمة 0 (ولكن انظر "الاختلافات بين مكتبة C والنواة" أدناه، التي تشير إلى أن sched_getaffinity() الأساسية تختلف في قيمة إرجاعها). عند الفشل، يتم إرجاع -1، ويتم تعيين errno للإشارة إلى الخطأ.

الأخطاء

EFAULT
كان عنوان الذاكرة المقدم غير صالح.
EINVAL
قناع بت الانتماء mask لا يحتوي على معالجات موجودة حاليًا فعليًا على النظام ومسموح بها للخيط وفقًا لأي قيود قد تفرضها مجموعات cpuset cgroups أو آلية "cpuset" الموصوفة في cpuset(7).
EINVAL
(sched_getaffinity() وقبل Linux 2.6.9، sched_setaffinity()) cpusetsize أصغر من حجم قناع الانتماء الذي تستخدمه النواة.
EPERM
(sched_setaffinity()) الخيط المستدعي لا يمتلك الامتيازات المناسبة. يحتاج المستدعي إلى معرف مستخدم فعال (effective user ID) يساوي معرف المستخدم الحقيقي (real user ID) أو معرف المستخدم الفعال للخيط المحدد بواسطة pid، أو يجب أن يمتلك القدرة CAP_SYS_NICE في مساحة اسم المستخدم للخيط pid.
ESRCH
لم يتم العثور على الخيط الذي معرفه pid.

المعايير

Linux.

التاريخ

Linux 2.5.8، glibc 2.3.

في البداية، تضمنت واجهات glibc معلمة cpusetsize، تم تعريف نوعها كـ unsigned int. في glibc 2.3.3، تم إزالة المعلمة cpusetsize، ولكن تم إعادتها لاحقًا في glibc 2.3.4، مع نوع size_t.

ملاحظات

بعد استدعاء sched_setaffinity()، تكون مجموعة المعالجات التي سيعمل عليها الخيط فعليًا هي تقاطع المجموعة المحددة في المعلمة mask مع مجموعة المعالجات الموجودة فعليًا على النظام. قد يقوم النظام بتقييد مجموعة المعالجات التي يعمل عليها الخيط بشكل أكبر إذا كانت آلية "cpuset" الموضحة في cpuset(7) قيد الاستخدام. يتم فرض هذه القيود على مجموعة المعالجات الفعلية التي سيعمل عليها الخيط بصمت من قبل النواة.

هناك طرق مختلفة لتحديد عدد المعالجات المتاحة على النظام، بما في ذلك: فحص محتويات /proc/cpuinfo؛ استخدام sysconf(3) للحصول على قيم المعلمات _SC_NPROCESSORS_CONF و _SC_NPROCESSORS_ONLN؛ وفحص قائمة أدلة المعالجات تحت /sys/devices/system/cpu/.

sched(7) يحتوي على وصف لمخطط الجدولة في Linux.

قناع الانتماء هو سمة لكل خيط يمكن تعديله بشكل مستقل لكل من الخيوط في مجموعة خيوط. يمكن تمرير القيمة المسترجعة من استدعاء gettid(2) في المعلمة pid. تحديد pid كـ 0 سيقوم بتعيين السمة للخيط المستدعي، وتمرير القيمة المسترجعة من استدعاء getpid(2) سيقوم بتعيين السمة للخيط الرئيسي لمجموعة الخيوط. (إذا كنت تستخدم واجهة POSIX threads API، فاستخدم pthread_setaffinity_np(3) بدلاً من sched_setaffinity().)

يمكن استخدام خيار بدء التشغيل isolcpus لعزل معالج واحد أو أكثر عند بدء التشغيل، بحيث لا يتم جدولة أي عمليات على تلك المعالجات. بعد استخدام خيار بدء التشغيل هذا، فإن الطريقة الوحيدة لجدولة العمليات على المعالجات المعزولة هي عبر sched_setaffinity() أو آلية cpuset(7). لمزيد من المعلومات، راجع ملف مصدر النواة Documentation/admin-guide/kernel-parameters.txt. كما هو مذكور في هذا الملف، فإن isolcpus هي الآلية المفضلة لعزل المعالجات (مقابل البديل المتمثل في تعيين قناع انتماء المعالج يدويًا لجميع العمليات على النظام).

يرث الطفل الذي تم إنشاؤه عبر fork(2) قناع انتماء المعالج الخاص بوالده. يتم الحفاظ على قناع الانتماء عبر execve(2).

الاختلافات بين مكتبة C والنواة

تصف صفحة الدليل هذه واجهة glibc لاستدعاءات انتماء المعالج. واجهة استدعاء النظام الفعلية مختلفة قليلاً، حيث تم تعريف mask كـ unsigned long *، مما يعكس حقيقة أن التنفيذ الأساسي لمجموعات المعالجات هو قناع بت بسيط.

عند النجاح، تعيد استدعاء النظام الخام sched_getaffinity() عدد البايتات التي تم نسخها إلى المخزن المؤقت mask؛ سيكون هذا هو الحد الأدنى بين cpusetsize وحجم (بالبايت) نوع البيانات cpumask_t المستخدم داخليًا بواسطة النواة لتمثيل قناع بت مجموعة المعالج.

التعامل مع الأنظمة ذات أقنعة انتماء معالج كبيرة

تفرض استدعاءات النظام الأساسية (التي تمثل أقنعة المعالج كأقنعة بت من نوع unsigned long *) أي قيود على حجم قناع المعالج. ومع ذلك، فإن نوع البيانات cpu_set_t المستخدم بواسطة glibc له حجم ثابت يبلغ 128 بايت، مما يعني أن أقصى رقم معالج يمكن تمثيله هو 1023. إذا كان قناع انتماء المعالج الخاص بالنواة أكبر من 1024، فإن الاستدعاءات من النوع:


  sched_setaffinity(2) and sched_getaffinity(2)

using a cpu_set_t mask will fail with the error EINVAL.

To handle systems with more than 1024 CPUs, you need to use the lower-level system call interface directly, passing a buffer of unsigned long values and calculating the appropriate cpusetsize.

Consider the following:


    #include <sched.h>
    #include <errno.h>
    #include <stdio.h>
    #include <stdlib.h>
    #include <unistd.h>

    int main(void) {
        cpu_set_t cpuset;
        pid_t pid = 0; /* Calling thread */
        size_t cpusetsize = sizeof(cpu_set_t);
        int rc;

        rc = sched_getaffinity(pid, cpusetsize, &cpuset);
        if (rc == -1) {
            perror("sched_getaffinity");
            exit(EXIT_FAILURE);
        }

        printf("sched_getaffinity returned %d\n", rc);
        printf("Number of CPUs in mask: %d\n", CPU_COUNT(&cpuset));

        /* Example: Add CPU 1024 to the mask */
        CPU_SET(1024, &cpuset);
        rc = sched_setaffinity(pid, cpusetsize, &cpuset);
        if (rc == -1) {
            perror("sched_setaffinity");
            /* On systems with >1024 CPUs, this will likely fail with EINVAL */
            exit(EXIT_FAILURE);
        }

        printf("sched_setaffinity returned %d\n", rc);

        exit(EXIT_SUCCESS);
    }

When compiled and run on a system with more than 1024 CPUs, the example above will likely produce output similar to:


sched_getaffinity returned 0
Number of CPUs in mask: X  (where X is the number of CPUs in the default mask)
sched_setaffinity: Invalid argument

To correctly handle such systems, you would need to determine the actual size of the CPU affinity mask used by the kernel (e.g., by using `sysconf(_SC_ARG_MAX)` and then allocating a buffer dynamically, or by reading `/proc/self/status` and parsing the `Cpus_allowed_list` or `Cpus_allowed` fields). Then, you would need to use the raw system call interface, passing a pointer to your dynamically allocated buffer and the correct size.

For example, to get the affinity mask on a system with potentially more than 1024 CPUs, you might do something like this:


    #define _GNU_SOURCE
    #include <sched.h>
    #include <stdio.h>
    #include <stdlib.h>
    #include <unistd.h>
    #include <sys/syscall.h>

    /* This is the definition used by the kernel */
    typedef unsigned long cpumask_t;

    #ifndef __NR_sched_setaffinity
    #define __NR_sched_setaffinity SYS_sched_setaffinity
    #endif
    #ifndef __NR_sched_getaffinity
    #define __NR_sched_getaffinity SYS_sched_getaffinity
    #endif

    static inline int
    sched_getaffinity_raw(pid_t pid, unsigned int len, cpumask_t *cpuset)
    {
        return syscall(__NR_sched_getaffinity, pid, len, cpuset);
    }

    static inline int
    sched_setaffinity_raw(pid_t pid, unsigned int len, const cpumask_t *cpuset)
    {
        return syscall(__NR_sched_setaffinity, pid, len, cpuset);
    }

    int main(void) {
        pid_t pid = 0; /* Calling thread */
        unsigned int cpu_count;
        unsigned long max_cpusetsize;
        cpumask_t *cpuset_buf;
        int i, rc;

        cpu_count = sysconf(_SC_NPROCESSORS_CONF);
        if (cpu_count == (unsigned int)-1) {
            perror("sysconf(_SC_NPROCESSORS_CONF)");
            exit(EXIT_FAILURE);
        }

        /* The kernel uses sizeof(cpumask_t) * (number of CPUs / bits per mask + 1) */
        max_cpusetsize = (cpu_count / (sizeof(cpumask_t) * 8)) + 1;
        max_cpusetsize *= sizeof(cpumask_t);

        cpuset_buf = malloc(max_cpusetsize);
        if (cpuset_buf == NULL) {
            perror("malloc");
            exit(EXIT_FAILURE);
        }

        rc = sched_getaffinity_raw(pid, max_cpusetsize, cpuset_buf);
        if (rc == -1) {
            perror("sched_getaffinity_raw");
            free(cpuset_buf);
            exit(EXIT_FAILURE);
        }

        printf("Raw sched_getaffinity returned %d bytes\n", rc);
        /* Note: A more robust way would be to iterate through the mask */
        printf("CPU mask (first long): %016lx\n", cpuset_buf[0]);

        /* Example: Set affinity to CPU 1024 (requires careful calculation) */
        /* CPU 1024 is bit 0 of the 13th cpumask_t (index 12) */
        if (12 * sizeof(cpumask_t) < rc) {
             cpuset_buf[12] |= (1UL << 0);
             rc = sched_setaffinity_raw(pid, max_cpusetsize, cpuset_buf);
             if (rc == -1) {
                 perror("sched_setaffinity_raw");
             } else {
                 printf("sched_setaffinity_raw returned %d bytes\n", rc);
             }
        } else {
            printf("System does not support CPU 1024 with current mask size.\n");
        }


        free(cpuset_buf);
        exit(EXIT_SUCCESS);
    }

>sched_getaffinity(pid, sizeof(cpu_set_t), &mask);

تفشل مع الخطأ EINVAL، الخطأ الناتج عن استدعاء النظام الأساسي في الحالة التي يكون فيها حجم mask المحدد في cpusetsize أصغر من حجم قناع الارتباط الذي يستخدمه النواة. (اعتمادًا على طوبولوجيا وحدة المعالجة المركزية للنظام، يمكن أن يكون قناع ارتباط النواة أكبر بكثير من عدد وحدات المعالجة المركزية النشطة في النظام.)

عند العمل على أنظمة ذات أقنعة ارتباط لوحدة المعالجة المركزية كبيرة النواة، يجب تخصيص وسيطة mask ديناميكيًا (انظر CPU_ALLOC(3)). حاليًا، الطريقة الوحيدة للقيام بذلك هي عن طريق فحص حجم القناع المطلوب باستخدام استدعاءات sched_getaffinity() بأحجام أقنعة متزايدة (حتى يتوقف الاستدعاء عن الفشل مع الخطأ EINVAL).

كن على علم بأن CPU_ALLOC(3) قد تخصص مجموعة وحدات معالجة مركزية أكبر قليلاً مما هو مطلوب (لأن مجموعات وحدات المعالجة المركزية يتم تنفيذها كأقنعة بت مخصصة بوحدات sizeof(long)). نتيجة لذلك، يمكن لـ sched_getaffinity() تعيين بتات تتجاوز حجم التخصيص المطلوب، لأن النواة ترى بضع بتات إضافية. لذلك، يجب على المتصل التكرار فوق البتات في المجموعة المرتجعة، وعد البتات التي تم تعيينها، والتوقف عند الوصول إلى القيمة المرتجعة بواسطة CPU_COUNT(3) (بدلاً من التكرار فوق عدد البتات المطلوبة للتخصيص).

أمثلة

يقوم البرنامج أدناه بإنشاء عملية ابن. يقوم الوالد والابن بعد ذلك بتعيين أنفسهم لكل منهما إلى وحدة معالجة مركزية محددة وينفذان حلقات متطابقة تستهلك بعض وقت وحدة المعالجة المركزية. قبل الإنهاء، ينتظر الوالد اكتمال الابن. يأخذ البرنامج ثلاثة وسائط لسطر الأوامر: رقم وحدة المعالجة المركزية للأب، ورقم وحدة المعالجة المركزية للابن، وعدد تكرارات الحلقة التي يجب أن تقوم بها كلتا العمليتين.

كما توضح الأمثلة التشغيلية أدناه، فإن مقدار الوقت الفعلي ووقت وحدة المعالجة المركزية المستهلك عند تشغيل البرنامج سيعتمد على تأثيرات التخزين المؤقت داخل النواة وما إذا كانت العمليات تستخدم نفس وحدة المعالجة المركزية.

نستخدم أولاً lscpu(1) لتحديد أن هذا (x86) النظام يحتوي على نواتين، كل منهما بوحدتي معالجة مركزية:


$ lscpu | egrep -i 'core.*:|socket';
Thread(s) per core:    2
Core(s) per socket:    2
Socket(s):             1

نقوم بعد ذلك بتوقيت تشغيل البرنامج التجريبي لثلاث حالات: كلتا العمليتين تعملان على نفس وحدة المعالجة المركزية؛ كلتا العمليتين تعملان على وحدتي معالجة مركزية مختلفتين على نفس النواة؛ وكلتا العمليتين تعملان على وحدتي معالجة مركزية مختلفتين على نواتين مختلفتين.


$ time -p ./a.out 0 0 100000000;
real 14.75
user 3.02
sys 11.73
$ time -p ./a.out 0 1 100000000;
real 11.52
user 3.98
sys 19.06
$ time -p ./a.out 0 3 100000000;
real 7.89
user 3.29
sys 12.07

مصدر البرنامج

#define _GNU_SOURCE
#include <err.h>
#include <sched.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/wait.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    int           parentCPU, childCPU;
    cpu_set_t     set;
    unsigned int  nloops;
    if (argc != 4) {
        fprintf(stderr, "Usage: %s parent-cpu child-cpu num-loops\n",
                argv[0]);
        exit(EXIT_FAILURE);
    }
    parentCPU = atoi(argv[1]);
    childCPU = atoi(argv[2]);
    nloops = atoi(argv[3]);
    CPU_ZERO(&set);
    switch (fork()) {
    case -1:            /* Error */
        err(EXIT_FAILURE, "fork");
    case 0:             /* Child */
        CPU_SET(childCPU, &set);
        if (sched_setaffinity(0, sizeof(set), &set) == -1)
            err(EXIT_FAILURE, "sched_setaffinity");
        for (unsigned int j = 0; j < nloops; j++)
            getppid();
        exit(EXIT_SUCCESS);
    default:            /* Parent */
        CPU_SET(parentCPU, &set);
        if (sched_setaffinity(0, sizeof(set), &set) == -1)
            err(EXIT_FAILURE, "sched_setaffinity");
        for (unsigned int j = 0; j < nloops; j++)
            getppid();
        wait(NULL);     /* Wait for child to terminate */
        exit(EXIT_SUCCESS);
    }
}
