الحزمة: git

التراخيص: GPL-2.0-only

SCALAR(1) دليل Git SCALAR(1)

الاسم

scalar - أداة لإدارة مستودعات Git الكبيرة

الملخص

scalar clone [--single-branch] [--branch <main-branch>] [--full-clone]
        [--[no-]src] [--[no-]tags] [--[no-]maintenance] <url> [<enlistment>]
scalar list
scalar register [--[no-]maintenance] [<enlistment>]
scalar unregister [<enlistment>]
scalar run ( all | config | commit-graph | fetch | loose-objects | pack-files ) [<enlistment>]
scalar reconfigure [--maintenance=(enable|disable|keep)] [ --all | <enlistment> ]
scalar diagnose [<enlistment>]
scalar delete <enlistment>

الوصف

Scalar هي أداة لإدارة المستودعات تعمل على تحسين Git للاستخدام في المستودعات الكبيرة. تعمل Scalar على تحسين الأداء عن طريق تكوين إعدادات Git المتقدمة، وصيانة المستودعات في الخلفية، والمساعدة في تقليل البيانات المرسلة عبر الشبكة.

مفهوم مهم في Scalar هو "enlistment" (تجنيد): هذا هو الدليل العلوي للمشروع. يحتوي عادةً على الدليل الفرعي src/ وهو مساحة عمل Git. هذا يشجع على الفصل بين الملفات المتعقبة (داخل src/) والملفات غير المتعقبة، مثل نواتج البناء (خارج src/). عند تسجيل مساحة عمل Git موجودة مع Scalar باسم غير src، سيكون "enlistment" مطابقًا لمساحة العمل.

ينفذ الأمر scalar أوامر فرعية مختلفة، وخيارات مختلفة اعتمادًا على الأمر الفرعي. باستثناء clone و list و reconfigure --all، تتوقع جميع الأوامر الفرعية أن يتم تشغيلها داخل "enlistment".

يمكن تحديد الخيارات التالية قبل الأمر الفرعي:

-C <directory>

قبل تشغيل الأمر الفرعي، قم بتغيير دليل العمل. يحاكي هذا الخيار نفس الخيار في git(1).

-c <key>=<value>

طوال مدة تشغيل الأمر الفرعي المحدد، قم بتكوين هذا الإعداد. يحاكي هذا الخيار نفس الخيار في git(1).

الأوامر

Clone

clone [<options>] <url> [<enlistment>]

ينسخ المستودع المحدد، بشكل مشابه لـ git-clone(1). افتراضيًا، يتم نسخ كائنات الالتزام (commit) والشجرة (tree) فقط. عند الانتهاء، تكون مساحة العمل موجودة في <enlistment>/src.

يتم تمكين ميزة الاختيار المتفرق (sparse-checkout) (ما لم يتم تشغيلها مع --full-clone) والملفات الموجودة هي فقط تلك الموجودة في الدليل العلوي. استخدم git sparse-checkout set لتوسيع مجموعة الأدلة التي تريد رؤيتها، أو git sparse-checkout disable للتوسع إلى جميع الملفات (انظر git-sparse-checkout(1) لمزيد من التفاصيل). يمكنك استكشاف الأدلة الفرعية خارج الاختيار المتفرق الخاص بك باستخدام git ls-tree HEAD[:<directory>].

-b <name>, --branch <name>

بدلاً من سحب الفرع الذي يشير إليه HEAD في المستودع المستنسخ، اسحب الفرع <name> بدلاً من ذلك.

--single-branch, --no-single-branch

انسخ فقط السجل الذي يؤدي إلى طرف فرع واحد، إما المحدد بواسطة الخيار --branch أو الفرع الأساسي الذي يشير إليه HEAD في المستودع البعيد.

ستقوم عمليات السحب (fetch) المستقبلية في المستودع الناتج بتحديث فرع التتبع البعيد فقط للفرع الذي تم استخدام هذا الخيار من أجله في النسخ الأولي. إذا لم يكن HEAD في المستودع البعيد يشير إلى أي فرع عند إنشاء نسخة --single-branch، فلن يتم إنشاء فرع تتبع بعيد.

--src, --no-src

افتراضيًا، يضع scalar clone المستودع المستنسخ داخل دليل <entlistment>/src. استخدم --no-src لوضع المستودع المستنسخ مباشرة في دليل <enlistment>.

--tags, --no-tags

افتراضيًا، سيقوم scalar clone بسحب كائنات العلامات (tags) المعلن عنها من المستودع البعيد وستقوم أوامر git fetch المستقبلية بنفس الشيء. استخدم --no-tags لتجنب سحب العلامات في scalar clone ولتكوين المستودع لتجنب سحب العلامات في المستقبل. لسحب العلامات بعد النسخ باستخدام --no-tags، قم بتشغيل git fetch --tags.

--full-clone, --no-full-clone

يتم تهيئة الاختيار المتفرق افتراضيًا. يمكن تعطيل هذا السلوك عبر --full-clone.

--maintenance, --no-maintenance

افتراضيًا، يقوم scalar clone بتكوين "enlistment" لاستخدام ميزة صيانة Git الخلفية. استخدم --no-maintenance لتخطي هذا التكوين.

List

list

يسرد "enlistments" المسجلة حاليًا بواسطة Scalar. لا يحتاج هذا الأمر الفرعي إلى تشغيله داخل "enlistment".

Register

register [<enlistment>]

يضيف مستودع "enlistment" إلى قائمة المستودعات المسجلة ويبدأ الصيانة الخلفية. إذا لم يتم توفير <enlistment>، فإن "enlistment" المرتبط بدليل العمل الحالي هو الذي يتم تسجيله.

ملاحظة: عندما يتم استدعاء هذا الأمر الفرعي في مساحة عمل تسمى src/، يعتبر دليلها الأصلي هو "enlistment" الخاص بـ Scalar. إذا كانت مساحة العمل غير مسماة src/، فسيتم اعتبارها هي نفسها "enlistment" الخاص بـ Scalar.

--maintenance, --no-maintenance

افتراضيًا، يقوم scalar register بتكوين "enlistment" لاستخدام ميزة صيانة Git الخلفية. استخدم --no-maintenance لتخطي هذا التكوين. هذا لا يعطل أي صيانة قد تكون ممكّنة بالفعل بطرق أخرى.

Unregister

unregister [<enlistment>]

يزيل المستودع المحدد من قائمة المستودعات المسجلة لدى Scalar ويوقف الصيانة الخلفية المجدولة.

Run

scalar run ( all | config | commit-graph | fetch | loose-objects | pack-files ) [<enlistment>]

يشغل مهمة الصيانة المعطاة (أو جميع المهام، إذا تم تحديد all). باستثناء all و config، يقوم هذا الأمر الفرعي بتسليم المهمة إلى git-maintenance(1) (مع تعيين fetch إلى prefetch و pack-files إلى incremental-repack).

يتم تشغيل هذه المهام تلقائيًا كجزء من الصيانة المجدولة، بمجرد تسجيل المستودع لدى Scalar. لذلك، لا ينبغي أن يكون من الضروري تشغيل هذا الأمر الفرعي يدويًا.

المهمة config خاصة بـ Scalar وتقوم بتكوين جميع تلك الإعدادات الافتراضية المبنية على الآراء التي تجعل Git يعمل بكفاءة أكبر مع المستودعات الكبيرة. نظرًا لأن هذه المهمة يتم تشغيلها كجزء من scalar clone تلقائيًا، نادرًا ما تكون هناك حاجة إلى استدعاءات صريحة لهذه المهمة.

Reconfigure

بعد ترقية Scalar، أو عندما تم تلف تكوين "enlistment" الخاص بـ Scalar أو تغييره عن طريق الخطأ، يتيح هذا الأمر الفرعي إعادة تكوين "enlistment".

--all

عند تحديد --all، قم بإعادة تكوين جميع "enlistments" المسجلة حاليًا لدى Scalar عبر مفتاح التكوين scalar.repo. استخدم هذا الخيار بعد كل ترقية للحصول على أحدث الميزات.

--maintenance=(enable|disable|keep)

افتراضيًا، يقوم Scalar بتكوين "enlistment" لاستخدام ميزة صيانة Git الخلفية؛ هذا هو نفس استخدام القيمة `enable` لهذا الخيار. استخدم القيمة `disable` لإزالة كل "enlistment" تم النظر فيه من الصيانة الخلفية. استخدم `keep` لترك تكوين الصيانة الخلفية دون تغيير لهذه المستودعات.

Diagnose

diagnose [<enlistment>]

عند الإبلاغ عن مشاكل تتعلق بـ Scalar، غالبًا ما يكون من المفيد تقديم المعلومات التي تم جمعها بواسطة هذا الأمر، بما في ذلك السجلات وإحصائيات معينة تصف شكل البيانات لـ "enlistment" الحالي.

NAME

scalar

manage Git repositories

SYNOPSIS

scalar enlist [OPTIONS] <repository> <path>

scalar push <enlistment> <remote>

scalar delete <enlistment>

DESCRIPTION

This manual page describes the scalar command.

enlist

enlist <repository> <path>

This subcommand lets you clone a Git repository at the specified path. If the path is not empty, Scalar will attempt to recover the repository. Scalar will automatically register the repository for future use.

Example:

$ scalar enlist git://example.com/repo.git my/repo

push

push <enlistment> <remote>

This subcommand lets you push your local changes to a remote repository. The output of this command is a .zip file that is written into a directory adjacent to the worktree in the src directory.

Delete

delete <enlistment>

This subcommand lets you delete an existing Scalar enlistment from your local file system, unregistering the repository.

SEE ALSO

git-clone(1), git-maintenance(1).
