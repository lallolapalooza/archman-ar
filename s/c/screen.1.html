The following commands are bound to the Control-a prefix key:

C-a ^A (reset) Reset the virtual terminal to its power-on values.
C-a B (break) Reopen the terminal line and send a break.
C-a c, C-a C-c (screen) Create a new window with a shell and switch to that window.

C-a d, C-a C-d (detach) Detach screen from this terminal.

C-a F (fit) Resize the window to the current region size.
C-a C-g (vbell) Toggles screen's visual bell mode.
C-a h (hardcopy) Write a hardcopy of the current window to the file hardcopy.n.
C-a H (log) Begins/ends logging of the current window to the file screenlog.n.
C-a i, C-a C-i (info) Show info about this window.
C-a k, C-a C-k (kill) Destroy current window.
C-a l, C-a C-l (redisplay) Fully refresh current window.

C-a m, C-a C-m (lastmsg) Repeat the last message displayed in the message line.
C-a M (monitor) Toggles monitoring of the current window.
C-a space, C-a n, C-a C-n (next) Switch to the next window.

التخصيص

يحتوي دليل المقبس بشكل افتراضي إما على $HOME/.screen أو ببساطة على /tmp/screens أو يفضل /usr/local/screens الذي تم اختياره عند وقت الترجمة. إذا تم تثبيت screen مع صلاحيات root، فيجب على المسؤول ترجمة screen مع دليل مقبس مناسب (غير مثبت على NFS). إذا لم يكن screen قيد التشغيل بصلاحيات root، فيمكن للمستخدم تحديد أي دليل بوضع 700 في المتغير البيئي $SCREENDIR.

عند استدعاء screen، فإنه ينفذ أوامر التهيئة من الملفات /usr/local/etc/screenrc والافتراضيات التي يمكن تجاوزها بالطرق التالية: بالنسبة للملف screenrc العام، يبحث screen عن المتغير البيئي $SYSSCREENRC (قد يتم تعطيل ميزة التجاوز هذه عند وقت الترجمة). يتم البحث عن ملف screenrc الخاص بالمستخدم في $SCREENRC، ثم $HOME/.screenrc. الخيار -c في سطر الأوامر له الأسبقية على ملفات screenrc للمستخدم المذكورة أعلاه.

الأوامر في هذه الملفات تُستخدم لضبط الخيارات، ربط الوظائف بالمفاتيح، وإنشاء نافذة واحدة أو أكثر تلقائيًا في بداية جلسة screen الخاصة بك. الأوامر مدرجة سطرًا بسطر، مع تجاهل الأسطر الفارغة. يتم فصل وسائط الأمر بالعلامات (tabs) أو المسافات، ويمكن إحاطتها بعلامات اقتباس مفردة أو مزدوجة. علامة '#' تحول بقية السطر إلى تعليق، باستثناء ما بداخل علامات الاقتباس. يتم التحذير من الأسطر غير المفهومة ويتم تجاهلها. يمكن أن تحتوي الأوامر على إشارات إلى متغيرات البيئة. الصيغة هي مثل shell "$VAR" أو "${VAR}". لاحظ أن هذا يسبب عدم توافق مع إصدارات screen السابقة، حيث يجب الآن حماية حرف '$' بـ '\' إذا لم يكن سيتم إجراء استبدال للمتغير. السلسلة النصية بعلامات اقتباس مفردة محمية أيضًا من استبدال المتغيرات.

يتم شحن ملفي تكوين كمثال مع توزيع screen الخاص بك: etc/screenrc و etc/etcscreenrc. تحتوي هذه الملفات على عدد من الأمثلة المفيدة لمختلف الأوامر.

exec [[fdpat]newcommand [args ...]]

Run a unix subprocess (specified by an executable path newcommand and its optional arguments) in the current window. The flow of data between newcommands stdin/stdout/stderr, the process originally started in the window (let us call it "application-process") and screen itself (window) is controlled by the file descriptor pattern fdpat. This pattern is basically a three character sequence representing stdin, stdout and stderr of newcommand. A dot (.) connects the file descriptor to screen. An exclamation mark (!) causes the file descriptor to be connected to the application-process. A colon (:) combines both. User input will go to newcommand unless newcommand receives the application-process' output (fdpats first character is `!' or `:') or a pipe symbol (|) is added (as a fourth character) to the end of fdpat.

Invoking `exec' without arguments shows name and arguments of the currently running subprocess in this window. Only one subprocess a time can be running in each window.

When a subprocess is running the `kill' command will affect it instead of the windows process.

Refer to the postscript file `doc/fdpat.ps' for a confusing illustration of all 21 possible combinations. Each drawing shows the digits 2,1,0 representing the three file descriptors of newcommand. The box marked `W' is the usual pty that has the application-process on its slave side. The box marked `P' is the secondary pty that now has screen at its master side.

Abbreviations: Whitespace between the word `exec' and fdpat and the command can be omitted. Trailing dots and a fdpat consisting only of dots can be omitted. A simple `|' is synonymous for the pattern `!..|'; the word exec can be omitted here and can always be replaced by `!'.

Examples:

exec ... /bin/sh
exec /bin/sh
!/bin/sh

Creates another shell in the same window, while the original shell is still running. Output of both shells is displayed and user input is sent to the new /bin/sh.

exec !.. stty 19200
exec ! stty 19200
!!stty 19200

Set the speed of the window's tty. If your stty command operates on stdout, then add another `!'.

exec !..| less
|less

This adds a pager to the window output. The special character `|' is needed to give the user control over the pager although it gets its input from the window's process. This works, because less listens on stderr (a behavior that screen would not expect without the `|') when its stdin is not a tty. Less versions newer than 177 fail miserably here; good old pg still works.

!:sed -n s/.*Error.*/\007/p

Sends window output to both, the user and the sed command. The sed inserts an additional bell character (oct. 007) to the window output seen by screen. This will cause "Bell in window x" messages, whenever the string "Error" appears in the window.

Sets the flow-control mode for this window. Without parameters it cycles the current window's flow-control setting from "automatic" to "on" to "off". See the discussion on FLOW-CONTROL later on in this document for full details and note, that this is subject to change in future releases. Default is set by `defflow'.

focus [ next | prev | up | down | left | right | top | bottom ]

Move the input focus to the next region. This is done in a cyclic way so that the top left region is selected after the bottom right one. If no option is given it defaults to `next'. The next region to be selected is determined by how the regions are layered. Normally, the next region in the same layer would be selected. However, if that next region contains one or more layers, the first region in the highest layer is selected first. If you are at the last region of the current layer, `next' will move the focus to the next region in the lower layer (if there is a lower layer). `Prev' cycles in the opposite order. See split for more information about layers.

The rest of the options (`up', `down', `left', `right', `top', and `bottom') are more indifferent to layers. The option `up' will move the focus upward to the region that is touching the upper left corner of the current region. `Down' will move downward to the region that is touching the lower left corner of the current region. The option `left' will move the focus leftward to the region that is touching the upper left corner of the current region, while `right' will move rightward to the region that is touching the upper right corner of the current region. Moving left from a left most region or moving right from a right most region will result in no action.

يقوم هذا الأمر بتكوين استخدام ومحاكاة خط الحالة الصلبة (hardstatus line) للطرفية. الشكل الأول يبدل ما إذا كان screen سيستخدم خط الحالة الصلبة لعرض الرسائل. إذا تم تعيين العلامة على 'off'، فسيتم تراكب هذه الرسائل في وضع الفيديو المعكوس على سطر العرض. الإعداد الافتراضي هو 'on'.

يخبر الشكل الثاني screen بما يجب فعله إذا لم يكن للطرفية خط حالة صلبة (أي أن قدرات termcap/terminfo "hs"، "ts"، "fs"، و "ds" غير محددة). عند استخدام firstline/lastline، سيقوم screen بحجز السطر الأول/الأخير من العرض للحالة الصلبة. يستخدم message آلية الرسائل الخاصة بـ screen ويخبر ignore screen بعدم عرض الحالة الصلبة أبدًا. إذا قمت بوضع كلمة always قبل النوع (على سبيل المثال، alwayslastline)، فسيستخدم screen النوع حتى لو كانت الطرفية تدعم حالة صلبة.

يحدد الشكل الثالث محتويات سطر الحالة الصلبة. يتم استخدام '%h' كسلسلة افتراضية، أي يتم عرض الحالة الصلبة المخزنة للنافذة الحالية (قابلة للتعيين عبر ESC]0;<string>^G أو ESC_<string>ESC\). يمكنك تخصيص هذا إلى أي سلسلة تريدها بما في ذلك الهروب من قسم STRING ESCAPES. إذا تركت الوسيط string، فسيتم عرض السلسلة الحالية.

info

يستخدم سطر الرسائل لعرض بعض المعلومات حول النافذة الحالية: موضع المؤشر بالشكل (عمود، صف) بدءًا من (1,1)، عرض وارتفاع الطرفية بالإضافة إلى حجم مخزن التمرير بالأسطر، كما في (80,24)+50، يتم عرض الحالة الحالية للتحكم في تدفق XON/XOFF كما يلي (انظر أيضًا قسم FLOW CONTROL):

+flow تحكم تلقائي في التدفق، قيد التشغيل حاليًا.
-flow تحكم تلقائي في التدفق، متوقف حاليًا.
+(+)flow تم تمكين التحكم في التدفق. يتفق مع التحكم التلقائي.
-(+)flow تم تعطيل التحكم في التدفق. لا يتفق مع التحكم التلقائي.
+(-)flow تم تمكين التحكم في التدفق. لا يتفق مع التحكم التلقائي.
-(-)flow تم تعطيل التحكم في التدفق. يتفق مع التحكم التلقائي.

يتم أيضًا عرض إعداد التفاف الأسطر الحالي ('+wrap' يشير إلى ممكّن، '-wrap' غير ممكّن). يتم عرض العلامات 'ins'، 'org'، 'app'، 'log'، 'mon' أو 'nored' عندما تكون النافذة في وضع الإدراج، وضع الأصل، وضع لوحة المفاتيح التطبيقية، لديها تسجيل الإخراج، مراقبة النشاط، أو إعادة الرسم الجزئي ممكّن.

يتم عرض مجموعة الأحرف النشطة حاليًا (G0، G1، G2، أو G3) وفي أقواس مربعة مجموعات أحرف الطرفية المعينة حاليًا من G0 إلى G3. إذا كانت النافذة في وضع UTF-8، فسيتم عرض السلسلة UTF-8 بدلاً من ذلك.

يتم عرض الأوضاع الإضافية اعتمادًا على نوع النافذة في نهاية سطر الحالة (انظر أيضًا فصل أنواع النوافذ).

إذا كانت آلة الحالة لمحاكي الطرفية في حالة غير افتراضية، يبدأ سطر المعلومات بسلسلة تحدد الحالة الحالية.

للحصول على معلومات النظام، استخدم أمر time.

split[-v]

تقسيم المنطقة الحالية إلى اثنتين جديدتين. يتم تغيير حجم جميع المناطق على الشاشة لتوفير مساحة للمنطقة الجديدة. يتم عرض النافذة الفارغة في المنطقة الجديدة. الافتراضي هو إنشاء تقسيم أفقي، ووضع المناطق الجديدة فوق بعضها البعض. استخدام `-v' سيؤدي إلى إنشاء تقسيم عمودي، مما يؤدي إلى ظهور المناطق الجديدة جنبًا إلى جنب. استخدم الأمر remove أو only لحذف المناطق. استخدم focus للتبديل بين المناطق.

عند تقسيم منطقة بشكل معاكس لكيفية تقسيمها سابقًا (أي، عمودي ثم أفقي أو أفقي ثم عمودي)، يتم إنشاء طبقة جديدة. تستخدم الطبقة لتجميع المناطق التي تم تقسيمها بنفس الطريقة. بشكل عام، كمستخدم، لا ينبغي أن ترى أو تقلق بشأن الطبقات، ولكنها ستؤثر على كيفية عمل بعض الأوامر (focus و resize).

مع التنفيذ الحالي لـ screen، سيظهر تمرير البيانات أبطأ بكثير في منطقة مقسمة عموديًا مقارنة بمنطقة ليست كذلك. يجب أخذ ذلك في الاعتبار إذا كنت بحاجة إلى استخدام أوامر النظام مثل cat أو tail -f.

استبدال مستخدم العرض. يطلب الأمر جميع المعلمات التي تم حذفها. إذا تم تحديد كلمات المرور كمعلمات، فيجب تحديدها دون تشفير. تتم مطابقة كلمة المرور الأولى مع قاعدة بيانات passwd للنظام، وتتم مطابقة كلمة المرور الثانية مع كلمة مرور screen كما تم تعيينها باستخدام الأوامر acladd أو password. قد يكون Su مفيدًا لمسؤول screen لاختبار إعدادات المستخدمين المتعددين. عند فشل التعريف، يتمتع المستخدم بإمكانية الوصول إلى الأوامر المتاحة للمستخدم nobody. هذه هي detach، license، version، help، و displays.

تعليق screen. تكون النوافذ في حالة 'detached'، بينما screen معلق. هذه الميزة تعتمد على قدرة shell على التحكم في المهام.

term term

في بيئة كل نافذة يفتحها screen، يتم تعيين المتغير $TERM إلى screen افتراضيًا. ولكن عندما لا يكون هناك وصف لـ screen مثبتًا في قاعدة بيانات termcap أو terminfo المحلية، فإنك تقوم بتعيين $TERM إلى - على سبيل المثال - vt100. لن يسبب هذا ضررًا كبيرًا، حيث أن screen متوافق مع VT100/ANSI. يوصى بعدم استخدام أمر term لغرض غير افتراضي. أي، قد يرغب المرء في تحديد إعدادات $TERM خاصة (على سبيل المثال، vt100) لأمر rlogin othermachine التالي لـ screen. استخدم الأمر screen -T vt100 rlogin othermachine بدلاً من تعيين وإعادة تعيين الافتراضي.

termcap term terminal-tweaks[window-tweaks]
terminfo term terminal-tweaks[window-tweaks]
termcapinfo term terminal-tweaks[window-tweaks]

استخدم هذا الأمر لتعديل إدخال termcap الخاص بجهازك الطرفي دون المرور بكل المتاعب المتعلقة بإنشاء إدخال termcap مخصص. بالإضافة إلى ذلك، يمكنك اختياريًا تخصيص termcap الذي تم إنشاؤه للنوافذ. يجب عليك وضع هذه الأوامر في أحد ملفات بدء التشغيل screenrc، حيث أنها لا معنى لها بمجرد تشغيل محاكي الطرفية.

إذا كان نظامك يستخدم قاعدة بيانات terminfo بدلاً من termcap، فسيتمكن screen من فهم الأمر `terminfo'، والذي له نفس تأثيرات أمر `termcap'. يتم توفير أمرتين منفصلتين، حيث توجد اختلافات تركيبية دقيقة، على سبيل المثال عند الحاجة إلى استيفاء المعلمات (باستخدام '%'). لاحظ أنه يجب استخدام أسماء termcap للقدرات مع أمر `terminfo'.

في العديد من الحالات، حيث تكون الوسائط صالحة في بناء جملة terminfo و termcap، يمكنك استخدام الأمر `termcapinfo'، وهو مجرد اختصار لزوج من الأوامر `termcap' و `terminfo' مع وسائط متطابقة.

تحدد الوسيطة الأولى أي طرفيات يجب أن تتأثر بهذا التعريف. يمكنك تحديد أسماء طرفيات متعددة بفصلها بـ `|'s. استخدم `*' لمطابقة جميع الطرفيات واستخدم `vt*' لمطابقة جميع الطرفيات التي تبدأ بـ vt.

كل وسيطة tweak تحتوي على تعريف termcap واحد أو أكثر (مفصولة بـ `:'s) ليتم إدراجها في بداية إدخال termcap المناسب، وتعزيزها أو تجاوز القيم الموجودة. تقوم أول تعديل بتعديل termcap طرفيتك، وتحتوي على تعريفات تستخدمها طرفيتك لأداء وظائف معينة. حدد سلسلة فارغة لترك هذا دون تغيير (على سبيل المثال، ''). التعديل الثاني (اختياري) يعدل جميع termcaps النوافذ، ويجب أن يحتوي على تعريفات يفهمها screen (انظر قسم VIRTUAL TERMINAL).

بعض الأمثلة:

termcap xterm* LP:hs@

يبلغ screen بأن جميع الطرفيات التي تبدأ بـ 'xterm' لديها هوامش تلقائية ثابتة تسمح بتحديث الموضع الأخير على الشاشة (LP)، ولكن ليس لديها خط حالة فعليًا (ليس 'hs' - أضف '@' لإيقاف تشغيل الإدخالات). لاحظ أننا نفترض 'LP' لجميع أسماء الطرفيات التي تبدأ بـ vt، ولكن فقط إذا لم تحدد أمر termcap لتلك الطرفية.

termcap vt*  LP

termcap vt102|vt220 Z0=\E[?3h:Z1=\E[?3l

يحدد القدرة 'LP' ذات الهوامش الثابتة لجميع الطرفيات التي تبدأ بـ 'vt'، والسطر الثاني سيضيف أيضًا تسلسلات الهروب للتبديل إلى (Z0) والعودة من (Z1) وضع 132 حرفًا في السطر إذا كانت VT102 أو VT220. (يجب عليك تحديد Z0 و Z1 في termcap الخاص بك لاستخدام أوامر تغيير العرض.)

termcap vt100 "" l0=PF1:l1=PF2:l2=PF3:l3=PF4

هذا يترك termcap vt100 الخاص بك كما هو ويضيف تسميات مفاتيح الوظائف إلى إدخال termcap لكل نافذة.

termcap h19|z19 am@:im=\E@:ei=\EO dc=\E[P

يأخذ termcap h19 أو z19 ويطفئ الهوامش التلقائية (am@) ويمكّن وضع الإدراج (im) وإلغاء الإدراج (ei) (علامة '@' في سلسلة 'im' بعد '='، لذلك هي جزء من السلسلة). وجود تعريفات 'im' و 'ei' في termcap طرفيتك سيجعل screen يعلن تلقائيًا عن القدرة على إدراج الأحرف في termcap كل نافذة. ستحصل كل نافذة أيضًا على القدرة على حذف الأحرف (dc) مضافة إلى termcap الخاص بها، والتي سيقوم screen بترجمتها إلى تحديث سطر للطرفية (نتظاهر بأنها لا تدعم حذف الأحرف).

إذا كنت ترغب في تحديد إدخال termcap لكل نافذة بالكامل، فيجب عليك بدلاً من ذلك تعيين المتغير $SCREENCAP قبل تشغيل screen. انظر المناقشة حول VIRTUAL TERMINAL في هذا الدليل، والرجل termcap(5)
