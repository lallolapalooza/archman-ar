SCTP_NODELAY
\n
Turn on/off any Nagle-like algorithm. This means that packets are\n generally sent as soon as possible and no unnecessary delays are\n introduced, at the cost of more packets in the network.\n

The parameter type is int boolean, for reading and\n writing.

\n

Default: 0.

SCTP_AUTOCLOSE
\n
This socket option is applicable to the one-to-many style socket only.\n When set it will cause associations that are idle for more than the\n specified number of seconds to automatically close. An association being\n idle is defined an association that has NOT sent or received user data\n within a period.\n

The parameter type is int(seconds), for reading and writing. 0\n indicates that no automatic close of any associations should be\n performed.

\n

Default: sysctl_net.sctp.max_autoclose.

SCTP_DISABLE_FRAGMENTS
\n
If enabled no SCTP message fragmentation will be performed. Instead if a\n message being sent exceeds the current PMTU size, the message will NOT be\n sent and an error will be indicated to the user.\n

The parameter type is int boolean, for reading and\n writing.

\n

Default: 0.

SCTP_PEER_ADDR_PARAMS
\n
Using this option, applications can enable or disable heartbeats for any\n peer address of an association, modify an address's heartbeat interval, \n force a heartbeat to be sent immediately, and adjust the address's maximum\n number of retransmissions sent before an address is considered\n unreachable.\n

The parameter type is struct sctp_paddrparams, for reading and\n writing. spp_address is a specified transport address or 0, spp_assoc_id\n is a specified assoc_id or SCTP_FUTURE_ASSOC.

\n

Default: hbinterval=sysctl_net.sctp.hb_interval, \n pathmaxrxt=sysctl_net.sctp.path_max_retrans, pathmtu=dev/route's, \n sackdelay=sysctl_net.sctp.sack_timeout,\n param_flags=HB_ENABLE|PMTUD_ENABLE|SACKDELAY_ENABLE, flowlabel=0, \n dscp=0.

SCTP_I_WANT_MAPPED_V4_ADDR

SCTP_MAXSEG
\n
This socket option specifies the maximum size to put in any outgoing SCTP\n DATA chunk. If a message is larger than this size it will be fragmented by\n SCTP into the specified size. Note that the underlying SCTP implementation\n may fragment into smaller sized chunks when the PMTU of the underlying\n association is smaller than the value set by the user. 0 indicates the\n user is NOT limiting fragmentation and only the PMTU will effect SCTP's\n choice of DATA chunk size.\n

The parameter type is struct sctp_assoc_value, for reading and\n writing. assoc_id is a specified assoc_id or SCTP_FUTURE_ASSOC.
