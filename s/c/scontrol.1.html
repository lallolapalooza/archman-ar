scontrol(1) أوامر Slurm scontrol(1)

الاسم

scontrol - عرض أو تعديل تكوين وحالة Slurm.

الملخص

scontrol [خيارات...] [أمر...]

الوصف

يُستخدم scontrol لعرض أو تعديل تكوين Slurm بما في ذلك: مهام، خطوات المهام، العقد، الأقسام، التحفظات، وتكوين النظام العام. معظم الأوامر لا يمكن تنفيذها إلا بواسطة المستخدم الجذر (root) أو مسؤول (Administrator). إذا حاول مستخدم غير مصرح له عرض أو تعديل معلومات التكوين، فستتم طباعة رسالة خطأ ولن يتم تنفيذ الإجراء المطلوب. إذا لم يتم إدخال أي أمر على سطر التنفيذ، فسيعمل scontrol في وضع تفاعلي ويطلب الإدخال. سيستمر في طلب الإدخال وتنفيذ الأوامر حتى يتم إنهاؤه صراحةً. إذا تم إدخال أمر على سطر التنفيذ، فسوف ينفذه scontrol ويخرج. جميع الأوامر والخيارات غير حساسة لحالة الأحرف، على الرغم من أن أسماء العقد، وأسماء الأقسام، وأسماء التحفظات حساسة لحالة الأحرف (أسماء العقد "LX" و "lx" مميزة). يمكن اختصار جميع الأوامر والخيارات إلى الحد الذي يكون فيه التحديد فريدًا. يمكن كتابة تكوين Slurm المعدل إلى ملف باستخدام الأمر scontrol write config. سيتم تسمية الملف الناتج باستخدام الاصطلاح "slurm.conf.<datetime>" وسيقع في نفس الدليل الذي يحتوي على ملف "slurm.conf" الأصلي. يجب أن يكون الدليل الذي يحتوي على slurm.conf الأصلي قابلاً للكتابة ليحدث ذلك.

الخيارات

-a, --all
عند استخدام أمر show، قم بعرض جميع الأقسام، مهامها، وخطوات مهامها. هذا يؤدي إلى عرض معلومات حول الأقسام التي تم تكوينها على أنها مخفية والأقسام غير المتاحة لمجموعة المستخدم.
-M, --clusters=<سلسلة>
المجموعة التي يتم إصدار الأوامر إليها. يمكن تحديد اسم مجموعة واحدة فقط. لاحظ أنه يجب أن يكون slurmdbd قيد التشغيل لهذا الخيار ليعمل بشكل صحيح، ما لم تكن تعمل في اتحاد مع تكوين FederationParameters=fed_display أو تم تعيين خيار --federation. هذا الخيار يحدد ضمنيًا خيار --local.
-d, --details
يجعل أمر show يوفر تفاصيل إضافية حيثما تكون متاحة.
--federation
عرض المهام من الاتحاد إذا كنت عضوًا فيه.
-F, --future
عرض العقد في حالة FUTURE (مستقبلية).
-h, --help
طباعة رسالة مساعدة تصف استخدام scontrol.
--hide
عدم عرض معلومات حول الأقسام المخفية، ومهامها، وخطوات مهامها. افتراضيًا، لن يتم عرض الأقسام التي تم تكوينها على أنها مخفية ولا الأقسام غير المتاحة لمجموعة المستخدم (أي، هذا هو السلوك الافتراضي).
--json, --json=قائمة, --json=< محلل_بيانات>
تفريغ المعلومات بصيغة JSON باستخدام ملحق محلل البيانات الافتراضي أو محلل بيانات محدد مع معلمات. يتم تفريغ جميع المعلومات، حتى لو لم تكن كذلك عادةً. يتم تجاهل وسيطات الفرز والتنسيق الممررة إلى خيارات أخرى؛ ومع ذلك، لا تزال معظم وسيطات التصفية مستخدمة. هذا الخيار غير متاح لكل أمر. هذا الخيار يحدد ضمنيًا خيار --details.
--local
عرض المعلومات المحلية لهذه المجموعة فقط. تجاهل المجموعات الأخرى في الاتحاد إذا كنت عضوًا فيه. يتجاوز --federation.
-o, --oneliner
طباعة المعلومات بسطر واحد لكل سجل.
-Q, --quiet
عدم طباعة أي تحذيرات أو رسائل معلومات، فقط رسائل الخطأ القاتلة.
--sibling
عرض جميع المهام الشقيقة في مجموعة متحدة. يتضمن --federation.
-u, --uid=<معرف_المستخدم>
محاولة تحديث مهمة كمستخدم <معرف_المستخدم> بدلاً من معرف المستخدم المستدعي.
-v, --verbose
طباعة تسجيل الأحداث المفصل. سيؤدي استخدام "-v" متعددة إلى زيادة تفصيل التسجيل. افتراضيًا، سيتم عرض الأخطاء فقط.
-V , --version
طباعة معلومات الإصدار والخروج.
--yaml, --yaml=قائمة, --yaml=<محلل_بيانات>
تفريغ المعلومات بصيغة YAML باستخدام ملحق محلل البيانات الافتراضي أو محلل بيانات محدد مع معلمات. يتم تفريغ جميع المعلومات، حتى لو لم تكن كذلك عادةً. يتم تجاهل وسيطات الفرز والتنسيق الممررة إلى خيارات أخرى؛ ومع ذلك، لا تزال معظم وسيطات التصفية مستخدمة. هذا الخيار غير متاح لكل أمر. هذا الخيار يحدد ضمنيًا خيار --details.

الأوامر

cancel_reboot <قائمة_العقد>
إلغاء إعادة التشغيل المعلقة على العقد. سيتم إلغاء إفراغ العقدة ومسح السبب إذا تم إفراغ العقدة بواسطة إعادة تشغيل فورية.
create <مواصفات>
إنشاء عقدة، قسم، أو حجز جديد. انظر القائمة الكاملة للمعلمات أدناه.
completing
عرض جميع المهام في حالة COMPLETING (تكتمل) مع العقد المرتبطة بها في حالة COMPLETING أو DOWN (متوقفة).
delete <مواصفات>
حذف الإدخال بالمواصفات المحددة SPECIFICATION. خيارات SPECIFICATION المتاحة هي:
NodeName=<قائمة_العقد>
اسم العقدة أو قائمة أسماء العقد المراد حذفها. لا يمكن حذف إلا العقد الديناميكية التي لا تحتوي على مهام قيد التشغيل والتي ليست جزءًا من حجز.

يمكن تحديد أسماء عقد متعددة باستخدام تعبيرات نطاق عقد بسيطة (على سبيل المثال، "lx[10-20]"). يمكن أيضًا تحديد مجموعات العقد بمفردها أو مزجها مع تعبيرات نطاق العقد، باستخدام فاصلة كفاصل للقائمة. إذا تم تحديد الكلمة المفتاحية "ALL" بمفردها، فسيتم محاولة الحذف ضد جميع العقد في المجموعة المحلية (وسيفشل على العقد غير المؤهلة للحذف).

PartitionName=<الاسم>

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

reconfigure
يُصدر تعليمات لجميع وحدات slurmctld و slurmd بإعادة قراءة ملف التكوين. يمكن استخدام هذه الآلية لتعديل معلمات التكوين المحددة في slurm.conf(5) دون مقاطعة الوظائف قيد التشغيل. بدءًا من الإصدار 23.11، تعمل هذه الأوامر عن طريق إنشاء عمليات جديدة للوحدات، ثم تمرير التحكم إلى العمليات الجديدة عند بدء تشغيلها بنجاح أو إذا فشلت. هذا يسمح لها بالتقاط مشكلات التكوين بلطف والاستمرار في العمل بالتكوين السابق إذا كانت هناك مشكلة. لن يتمكن هذا من تغيير إعدادات منفذ TCP للاستماع للوحدات أو آلية المصادقة.
release <job_list>
يُصدر أمرًا لوظيفة محتجزة سابقًا للبدء في التنفيذ. الوسيط job_list هو قائمة مفصولة بفواصل بمعرفات الوظائف أو "jobname=" مع اسم الوظيفة، والذي سيحاول إصدار جميع الوظائف التي تحمل هذا الاسم. انظر أيضًا hold.
requeue [<option>] <job_list>
يُعيد وضع وظيفة Slurm دفعة قيد التشغيل أو معلقة أو مكتملة إلى حالة الانتظار. الوسيط job_list هو قائمة مفصولة بفواصل بمعرفات الوظائف. يقبل الأمر الخيار التالي:
Incomplete
يعمل فقط على الوظائف (أو مهام مصفوفة الوظائف) التي لم تكتمل. على وجه التحديد، سيتم إعادة وضع الوظائف التالية فقط في حالة الانتظار: CONFIGURING، RUNNING، STOPPED، أو SUSPENDED.
requeuehold [<option>] <job_list>
يعيد وضع وظيفة Slurm دفعة قيد التشغيل أو معلقة أو مكتملة إلى حالة الانتظار، علاوة على ذلك، يتم وضع الوظيفة في حالة الاحتجاز (أولوية صفر). الوسيط job_list هو قائمة مفصولة بفواصل بمعرفات الوظائف. يمكن إصدار وظيفة محتجزة باستخدام scontrol لإعادة تعيين أولويتها (مثل "scontrol release <job_id>"). يقبل الأمر الخيارات التالية:
Incomplete
يعمل فقط على الوظائف (أو مهام مصفوفة الوظائف) التي لم تكتمل. على وجه التحديد، سيتم إعادة وضع الوظائف التالية فقط في حالة الانتظار: CONFIGURING، RUNNING، STOPPED، أو SUSPENDED.
State=SpecialExit
تحدد الكلمة المفتاحية "SpecialExit" أن الوظيفة يجب أن توضع في حالة خاصة JOB_SPECIAL_EXIT. سيعرض أمر "scontrol show job" حالة الوظيفة كـ SPECIAL_EXIT، بينما يعرض أمر "squeue" كـ SE.
resume <job_list>
يستأنف وظيفة معلقة سابقًا. الوسيط job_list هو قائمة مفصولة بفواصل بمعرفات الوظائف. انظر أيضًا suspend.

ملاحظة: تقوم الوظيفة المعلقة بتحرير وحدات المعالجة المركزية الخاصة بها لتخصيصها لوظائف أخرى. قد يؤدي استئناف وظيفة معلقة سابقًا إلى تخصيص وحدات معالجة مركزية متطابقة لوظائف متعددة، مما قد يؤدي إلى تشغيل جدولة جماعية مع بعض التكوينات أو تدهور شديد في الأداء مع تكوينات أخرى. استخدام أمر scancel لإرسال إشارات SIGSTOP و SIGCONT سيوقف وظيفة دون تحرير وحدات المعالجة المركزية الخاصة بها لتخصيصها لوظائف أخرى وسيكون آلية مفضلة في العديد من الحالات. إذا كنت تقوم بصيانة النظام، فقد ترغب في استخدام suspend/resume بالطريقة التالية. قبل التعليق، اضبط جميع العقد على وضع الصرف (draining) أو اضبط جميع الأقسام على وضع التعطيل (down) بحيث لا يمكن جدولة وظائف جديدة. ثم قم بتعليق الوظائف. بمجرد الانتهاء من الصيانة، قم باستئناف الوظائف ثم استأنف العقد و/أو أعد ضبط جميع الأقسام إلى وضع التشغيل (up). استخدم بحذر. فقط منسق حساب، مشغل، مسؤول، مستخدم Slurm، أو root يمكنه استئناف الوظائف.

schedloglevel <LEVEL>
يتيح أو يعطل تسجيل المجدول. يمكن أن يكون LEVEL "0" أو "1" أو "disable" أو "enable". "0" له نفس تأثير "disable". "1" له نفس تأثير "enable". هذه القيمة مؤقتة وستتم الكتابة فوقها عندما تقرأ وحدة slurmctld ملف التكوين slurm.conf (على سبيل المثال، عند إعادة تشغيل الوحدة أو تنفيذ scontrol reconfigure) إذا كان المعلمة SlurmSchedLogLevel موجودة.
setdebug <LEVEL> [nodes=<NODES>]
يغير مستوى التصحيح لوحدة slurmctld لجميع قنوات التسجيل النشطة التي لم يتم تكوينها مسبقًا كـ (quiet). يمكن أن يكون LEVEL قيمة عددية صحيحة بين صفر وتسعة (باستخدام نفس القيم مثل SlurmctldDebug في ملف slurm.conf) أو اسم نوع الرسالة الأكثر تفصيلاً المطلوب طباعته: "quiet"، "fatal"، "error"، "info"، "verbose"، "debug"، "debug2"، "debug3"، "debug4"، أو "debug5". هذه القيمة مؤقتة، وسيتم الكتابة فوقها في كل مرة تقرأ فيها الوحدة ملف التكوين slurm.conf. (مثل عند إعادة تشغيل الوحدة أو تنفيذ scontrol reconfigure).
nodes=<NodeName>
إذا تم تعيينه، يتم إرسال طلب تغيير مستوى التصحيح إلى وحدات slurmd الموجودة على العقد بدلاً من slurmctld. يمكن استخدام تعبير نطاق العقدة لـ NodeName.
setdebugflags {+|-}<FLAG> [{+|-}<FLAG>] [nodes=<NODES>]
يضيف أو يزيل DebugFlags لوحدة slurmctld. انظر "man slurm.conf" للحصول على قائمة DebugFlags المدعومة.

ملاحظة: تغيير قيمة بعض DebugFlags لن يكون له تأثير بدون إعادة تشغيل وحدة slurmctld، والتي ستعين DebugFlags بناءً على محتويات ملف التكوين slurm.conf أو متغير البيئة SLURM_DEBUG_FLAGS. متغير البيئة له الأسبقية على الإعداد في slurm.conf.

nodes=<NodeName>
الوسيط اختياري وإذا تم استخدامه، يتم إرسال طلب تغيير مستوى التصحيح إلى slurmd بدلاً من slurmctld. يمكن استخدام تعبير نطاق العقدة لـ NodeName.
show <ENTITY>[=<ID>] أو <ENTITY> [<ID>]
يعرض حالة الكيان المحدد بالتعريف المحدد.
aliases
يعيد جميع قيم NodeName المرتبطة بـ NodeHostname معين (مفيد للحصول على قائمة العقد الافتراضية المرتبطة بعقدة حقيقية في تكوين حيث تعمل وحدات slurmd متعددة على عقدة حساب واحدة).
assoc_mgr
يعرض المحتويات الحالية لـ slurmctld's internal cache للمستخدمين، والارتباطات، و/أو qos. يمكن تصفية الإخراج حسب أنواع السجلات المختلفة:
users=<user1>[...,<userN>]
يحد من سجلات المستخدم المعروضة لتلك التي تحمل أسماء المستخدم (أسماء المستخدمين) المحددة.
accounts=<acct1>[...,<acctN>]
يحد من سجلات الارتباط المعروضة لتلك التي تحمل أسماء الحساب (أسماء الحسابات) المحددة.
qos=<qos1>[...,<qosN>]
يحد من سجلات QOS المعروضة لتلك التي تحمل أسماء QOS المحددة.
flags={users|assoc|qos}
يحدد نوع السجل المطلوب عرضه. إذا لم يتم تحديد أي أعلام، يتم عرض جميع أنواع السجلات.
bbstat
يعرض المخرجات من أداة حالة المكون الإضافي ذاكرة التخزين المؤقت المؤقت الحالية (slurm_bb_get_status لـ lua أو dwstat لـ datawarp). يتم تمرير الخيارات التي تلي bbstat مباشرة إلى أداة الحالة بواسطة وحدة slurmctld ويتم إرجاع الاستجابة للمستخدم. يعادل dwstat.
burstbuffer
يعرض الحالة الحالية للمكون الإضافي BurstBuffer.
config
يعرض أسماء المعلمات من ملفات التكوين بأحرف مختلطة (مثل SlurmdPort=7003) بينما تكون أسماء المعلمات المشتقة بأحرف كبيرة فقط (مثل SLURM_VERSION).
daemons
يبلغ عن الوحدات التي يجب أن تعمل على هذه العقدة.
dwstat
يعرض المخرجات من أداة حالة المكون الإضافي ذاكرة التخزين المؤقت المؤقت الحالية (slurm_bb_get_status لـ lua أو dwstat لـ datawarp). يتم تمرير الخيارات التي تلي

تنص على ما إذا كان يجب إعادة جدولة المهمة بعد فشل عقدة: 0 لـ لا، 1 لـ نعم.
ReservationName=<name>
تعيين حجز المهمة إلى القيمة المحددة. يمكن مسح القيمة بقيمة بيانات فارغة، "ReservationName=".
ResetAccrueTime
تعيين قيمة وقت تراكم المهمة إلى 'الآن' مما يعني أنها ستفقد أي وقت تم تجميعه مسبقًا للأولوية. مفيد إذا كان لديك قائمة انتظار كبيرة من المهام موجودة بالفعل في قائمة الانتظار وترغب في البدء في الحد من عدد المهام التي يمكنها تجميع الوقت دون انتظار تفريغ قائمة الانتظار.
SiteFactor=<account>
تحديد عامل الأولوية الإداري للمهمة في النطاق +/-2147483645. يمكن للمستخدمين المميزين فقط تعديل القيمة.
StdErr=<filepath>
تعيين مسار ملف stderr للمهمة الدفعية. يمكن إعادة تعيين القيمة إلى الإعداد الافتراضي للمهمة بقيمة بيانات فارغة، "StdErr=".

ملاحظة: افتراضيًا، سيتم دمج StdErr في StdOut.

StdIn=<filepath>
تعيين مسار ملف stdin للمهمة الدفعية. يمكن إعادة تعيين القيمة إلى الإعداد الافتراضي للمهمة بقيمة بيانات فارغة، "StdIn=".

ملاحظة: افتراضيًا، سيكون StdIn هو '/dev/null'.

StdOut=<filepath>
تعيين مسار ملف stdout للمهمة الدفعية. يمكن إعادة تعيين القيمة إلى الإعداد الافتراضي للمهمة بقيمة بيانات فارغة، "StdOut=".

ملاحظة: افتراضيًا، سيعتمد StdOut على JobId.

Shared={yes|no}
انظر خيار OverSubscribe أعلاه.
StartTime=<time_spec>
تعيين وقت بدء المهمة المبكر. يقبل أوقات بالشكل HH:MM:SS لتشغيل مهمة في وقت معين من اليوم (الثواني اختيارية). (إذا كان هذا الوقت قد مضى بالفعل، يتم افتراض اليوم التالي.) يمكنك أيضًا تحديد midnight (منتصف الليل)، noon (الظهيرة)، elevenses (11 صباحًا)، fika (3 مساءً) أو teatime (4 مساءً) ويمكنك الحصول على وقت من اليوم متبوعًا بـ AM أو PM للتشغيل في الصباح أو المساء. يمكنك أيضًا تحديد يوم تشغيل المهمة، عن طريق تحديد تاريخ بالشكل MMDDYY أو MM/DD/YY أو MM.DD.YY، أو تاريخ ووقت بالشكل YYYY-MM-DD[THH:MM[:SS]]. يمكنك أيضًا إعطاء أوقات مثل now + count time-units، حيث يمكن أن تكون time-units seconds (افتراضي)، minutes (دقائق)، hours (ساعات)، days (أيام)، أو weeks (أسابيع) ويمكنك إخبار Slurm بتشغيل المهمة اليوم باستخدام الكلمة المفتاحية today (اليوم) وتشغيل المهمة غدًا باستخدام الكلمة المفتاحية tomorrow (غدًا).

ملاحظات على مواصفات التاريخ/الوقت:
- على الرغم من أن حقل 'seconds' في مواصفات الوقت HH:MM:SS مسموح به من قبل الكود، لاحظ أن وقت استقصاء مجدول Slurm ليس دقيقًا بما يكفي لضمان إرسال المهمة في الثانية المحددة. ستكون المهمة مؤهلة للبدء في الاستقصاء التالي بعد الوقت المحدد. يعتمد فاصل الاستقصاء الدقيق على مجدول Slurm (على سبيل المثال، 60 ثانية مع المجدول الافتراضي sched/builtin).
- إذا لم يتم تحديد وقت (HH:MM:SS)، فإن الافتراضي هو (00:00:00).

NODES - PARAMETERS

DOWN
إيقاف جميع المهام قيد التشغيل والمعلقة وجعل العقدة غير متاحة للمهام الجديدة.
DRAIN
يشير إلى عدم إمكانية بدء مهام جديدة على هذه العقدة. يُسمح للمهام الحالية بالتشغيل حتى الاكتمال، تاركة العقدة في حالة DRAINED بمجرد اكتمال جميع المهام.
FAIL
مشابه لـ DRAIN باستثناء أن بعض التطبيقات ستسعى للتخلي عن تلك العقد قبل اكتمال المهمة.
FUTURE
يشير إلى أن العقدة ليست مكوّنة بالكامل، ولكن من المتوقع أن تكون متاحة في وقت ما في المستقبل.
IDLE
سيقوم بمسح حالات DOWN و DRAIN و FAIL. سيقوم بتعيين الحالة إلى IDLE و NoResp. سيحاول slurmctld بعد ذلك الاتصال بـ slurmd لطلب تسجيل العقدة لنفسها. بمجرد التسجيل، ستقوم حالة العقدة بإزالة علامة NoResp وستستأنف العمليات العادية.
NoResp
سيقوم هذا بتعيين علامة "عدم الاستجابة" لعقدة دون تغيير حالتها الأساسية.
RESUME
ليست حالة عقدة فعلية، ولكنها ستغير حالة العقدة من DRAIN و DRAINING و DOWN أو REBOOT إلى IDLE و NoResp. سيحاول slurmctld بعد ذلك الاتصال بـ slurmd لطلب تسجيل العقدة لنفسها. بمجرد التسجيل، ستقوم حالة العقدة بإزالة علامة NoResp وستستأنف العمليات العادية. كما أنها ستمسح حالة POWERING_DOWN للعقدة وتجعلها مؤهلة للتخصيص.
UNDRAIN
يمسح العقدة من كونها مستنزفة (مثل RESUME)، ولكنه لن يغير الحالة الأساسية للعقدة (على سبيل المثال، DOWN). يتطلب UNDRAIN تسجيلًا صحيحًا للعقدة قبل أن يمكن جدولة المهام الجديدة على العقدة. سيؤدي تعيين عقدة DOWN إلى إنهاء جميع المهام قيد التشغيل والمعلقة على تلك العقدة.

في حين أن جميع الحالات المذكورة أعلاه صالحة، إلا أن بعضها ليس حالات عقد جديدة صالحة بالنظر إلى حالتها السابقة.

ملاحظة: لا ينبغي استخدام الأمر scontrol لتغيير حالة العقدة على أنظمة Cray. استخدم أدوات Cray مثل xtprocadmin بدلاً من ذلك.

Topology=<topology_name>:<topology_unit>[,<topology_name>:<topology_unit>,...]
حيث <topology_unit> هو اسم الكتلة أو اسم مفتاح ورقي. يمكن توفير أسماء المفاتيح الوسيطة - مفصولة بنقطتين رأسيتين (':') - وسيتم إنشاؤها إذا لزم الأمر (على سبيل المثال، Topology=topo-tree:sw_root:s1:s2). يتجاوز هذا التكوين إعدادات انتماء طوبولوجيا العقدة من topology.conf و topology.yaml.
Weight=<weight>
تحديد الوزن المرتبط بالعقد المحددة. يتيح هذا التغييرات الديناميكية في الوزن المرتبط بالعقد، والتي سيتم استخدامها لقرارات تخصيص العقد اللاحقة. الوزن المعين عبر scontrol سيستمر فقط عبر إعادة تشغيل خادم slurmctld مع الخيار -R وملفات الحالة محفوظة أو عند تلقي slurmctld لإشارة SIGHUP. قم بتحديث slurm.conf بأي تغييرات يُقصد بها أن تكون دائمة عبر عمليات إعادة تشغيل slurmctld العادية أو تنفيذ scontrol reconfig.

NODES - SPECIFICATIONS FOR SHOW COMMAND

AllocMem
إجمالي الذاكرة، بالميجابايت، المخصصة حاليًا للمهام على العقدة.
CPULoad
حمل وحدة المعالجة المركزية للعقدة كما هو مبلغ عنه من قبل نظام التشغيل.
CPUSpecList
قائمة معرفات وحدة المعالجة المركزية المجردة لـ Slurm على هذه العقدة المحجوزة للاستخدام الحصري بواسطة عمليات Slurm الخاصة بعقدة الحوسبة (slurmd, slurmstepd).
FreeMem
إجمالي الذاكرة، بالميجابايت، المتاحة حاليًا على العقدة كما هو مبلغ عنه من قبل نظام التشغيل.
LastBusyTime
آخر مرة كانت فيها العقدة مشغولة (أي آخر مرة كانت بها مهام). يستخدم هذا الوقت في PowerSave لتحديد وقت إيقاف العقد (على سبيل المثال، الآن - LastBusy > SuspendTime).
MemSpecLimit
الحد الأقصى للذاكرة المجمعة، بالميجابايت، على هذه العقدة لعمليات Slurm الخاصة بعقدة الحوسبة (slurmd, slurmstepd).
RealMemory
إجمالي الذاكرة، بالميجابايت، على العقدة.
State
تحديد الحالة (الحالات) المعينة للعقدة مع علامات الحالة مفصولة بـ '+'.

الحالات:

ALLOCATED
يشير إلى أن العقدة لديها جميع وحدات المعالجة المركزية المخصصة للمهام قيد التشغيل على العقدة.
DOWN
لا تحتوي العقدة على أي مهام قيد التشغيل وهي غير متاحة للعمل الجديد.
ERROR
العقدة في حالة خطأ. استشر السجلات للحصول على مزيد من المعلومات حول سبب هذه الحالة.
FUTURE
العقدة ليست مكوّنة بالكامل حاليًا، ولكن من المتوقع أن تكون متاحة في وقت ما في المستقبل غير المحدد للاستخدام.
IDLE
يشير إلى أن العقدة متاحة للعمل ولكن لا توجد مهام مخصصة لها حاليًا.
MIXED
يشير إلى أن العقدة في حالات متعددة. على سبيل المثال، إذا كان جزء فقط من العقدة ALLOCATED والجزء الآخر IDLE، فستكون الحالة MIXED.
UNKNOWN
لم تسجل العقدة بعد مع المتحكم وحالتها غير معروفة.

علامات:

CLOUD
يشير إلى أن العقدة مكوّنة كعقدة سحابية، ليتم تشغيلها عند الطلب، ولكنها لا تعمل حاليًا.
COMPLETING
يشير إلى أن المهمة الوحيدة على العقدة أو أن جميع المهام على العقدة قيد إكمالها.
DRAIN
العقدة لا تقبل أي مهام جديدة وسيتم إكمال أي مهام قيد التشغيل حاليًا.
DYNAMIC
يسمح لك Slurm بتعريف أنواع متعددة من العقد في حالة مستقبلية. عند بدء slurmd على عقدة، يمكنك تحديد الخيار -F لجعل العقدة تطابق وتستخدم تعريفًا موجودًا في ملف slurm.conf الخاص بك. تشير حالة DYNAMIC إلى أن العقدة تم تشغيلها كعقدة مستقبلية ديناميكية.
INVALID_REG
لم تسجل العقدة بشكل صحيح مع المتحكم. يحدث هذا عندما تسجل عقدة بموارد أقل من تلك المحددة في ملف slurm.conf. ستتم إزالة العقدة من هذه الحالة بتسجيل صحيح (أي، يلزم إعادة تشغيل slurmd).
MAINTENANCE
العقدة حاليًا في حجز يتضمن علامة maintenance.
NOT_RESPONDING
العقدة لا تستجيب.
PERFCTRS
يشير إلى أن عدادات أداء الشبكة المرتبطة بهذه العقدة قيد الاستخدام، مما يجعل هذه العقدة غير قابلة للاستخدام لأي مهام أخرى.
POWER_DOWN
يشير إلى أن العقدة تخضع لعملية إيقاف التشغيل.
POWERING_DOWN
يشير إلى أن العقدة في طور إيقاف التشغيل، ولكن لم يتم إيقاف تشغيلها بالكامل.
PROLOG
يشير إلى أن بروتوكول العقدة قيد التشغيل.
REBOOT
يشير إلى أن العقدة تخضع لإعادة تشغيل.
RESUMING
يشير إلى أن العقدة قيد الاستئناف.
STARTING
يشير إلى أن العقدة قيد البدء.
STOPPED
يشير إلى أن العقدة قد توقفت.
SUSPENDED
يشير إلى أن العقدة معلقة.
SUSPENDING
يشير إلى أن العقدة قيد التعليق.
TIMEOUT
يشير إلى أن العقدة تجاوزت مهلة النظام.
UNAFFILIATED
يشير إلى أن العقدة ليست مرتبطة بأي بنية طوبولوجية.
UPDATING
يشير إلى أن العقدة يتم تحديثها.
WAITING_FOR_DRAIN
يشير إلى أن العقدة تنتظر أن يتم استنزافها.
ThreadsPerCore
عدد الخيوط لكل نواة على العقدة.
TotalCPUs
إجمالي عدد وحدات المعالجة المركزية على العقدة.
TotalNodes
إجمالي عدد العقد التي تفي بمعايير الاستعلام.
TRUECPUTime
الوقت الحقيقي لوحدة المعالجة المركزية، بالثواني، المستخدمة بواسطة المهام على العقدة.
UsedMemory
إجمالي الذاكرة، بالميجابايت، المستخدمة حاليًا على العقدة.
Version
إصدار برنامج Slurm الذي يعمل على العقدة.

NODE STATES

POWER_DOWN
العقدة قيد الإيقاف المؤقت للطاقة.
POWERED_DOWN
العقدة حاليًا في وضع إيقاف التشغيل وغير قادرة على تشغيل أي مهام.
POWERING_DOWN
العقدة قيد عملية إيقاف التشغيل.
POWERING_UP
العقدة قيد عملية التشغيل.
PLANNED
تم تخصيص العقدة لمهمة ستبدأ في المستقبل.
REBOOT_ISSUED
تم إرسال طلب إعادة تشغيل إلى الوكيل المُعد للتعامل مع هذا الطلب.
REBOOT_REQUESTED
تم تقديم طلب لإعادة تشغيل هذه العقدة، ولكنه لم يتم التعامل معه بعد.
RESERVED
يشير إلى أن العقدة في حجز مسبق وليست متاحة بشكل عام.
معنى معلومات الطاقة هو كما يلي:
CurrentWatts
الاستهلاك الفوري للطاقة للعقدة في وقت آخر عينة محاسبة طاقة للعقدة، بالواط.
LowestJoules
الطاقة المستهلكة بواسطة العقدة بين آخر مرة تم تشغيلها وآخر مرة تم تسجيلها بواسطة slurmd، بالجول.
ConsumedJoules
الطاقة المستهلكة بواسطة العقدة بين آخر مرة تم تسجيلها بواسطة خدمة slurmd وآخر عينة محاسبة طاقة للعقدة، بالجول.

إذا كانت القيمة المبلغ عنها هي "n/s" (غير مدعوم)، فإن العقدة لا تدعم المكون الإضافي AcctGatherEnergyType المُعد. إذا كانت القيمة المبلغ عنها صفرًا، فإن محاسبة الطاقة للعقد غير مفعلة.

الأقسام - مواصفات أوامر الإنشاء والتحديث

PartitionName=<name>
تحديد القسم المراد تحديثه. هذا التحديد مطلوب.
AllocNodes=<name>
قائمة مفصولة بفواصل للعقد التي يمكن للمستخدمين من خلالها تنفيذ مهام في القسم. يمكن تحديد أسماء العقد باستخدام صيغة تعبير نطاق العقد الموصوفة أعلاه. القيمة الافتراضية هي "ALL".
AllowAccounts=<name>
قائمة مفصولة بفواصل للحسابات التي قد تنفذ مهام في القسم. القيمة الافتراضية هي "ALL". هذه القائمة هرمية، مما يعني أن الحسابات الفرعية مدرجة تلقائيًا. **ملاحظة**: إذا تم استخدام AllowAccounts، فلن يتم تطبيق DenyAccounts. ارجع أيضًا إلى DenyAccounts.
AllowGroups=<name>
تحديد مجموعات المستخدمين التي قد تستخدم هذا القسم. يمكن تحديد مجموعات متعددة في قائمة مفصولة بفواصل. للسماح لجميع المجموعات باستخدام القسم، حدد "AllowGroups=ALL".
AllowQOS=<name>
تحديد خدمات الجودة (QOSs) التي قد تستخدم هذا القسم. يمكن تحديد خدمات جودة متعددة في قائمة مفصولة بفواصل. للسماح لجميع خدمات الجودة باستخدام القسم، حدد "AllowQOS=ALL".
Alternate=<partition name>
قسم بديل سيتم استخدامه إذا كانت حالة هذا القسم "DRAIN" أو "INACTIVE". القيمة "NONE" ستمسح قسمًا بديلاً تم تعيينه سابقًا.
CpuBind=<node>
تحديد وضع ربط المهمة الذي سيتم استخدامه افتراضيًا لهذا القسم. تشمل الخيارات المدعومة: "none"، "socket"، "ldom" (NUMA)، "core"، "thread" و "off" (إزالة وضع الربط السابق).
Default={yes|no}
تحديد ما إذا كان سيتم استخدام هذا القسم للمهام التي لا تحدد صراحةً قسمًا لاستخدامه. القيم المحتملة هي "YES" و "NO". لتغيير القسم الافتراضي لنظام قيد التشغيل، استخدم أمر scontrol update واضبط Default=yes للقسم الذي تريد أن يصبح القسم الافتراضي الجديد.
DefaultTime=<time>
حد وقت التشغيل المستخدم للمهام التي لا تحدد قيمة. إذا لم يتم تعيينه، فسيتم استخدام MaxTime. التنسيق هو نفس تنسيق MaxTime.
DefMemPerCPU=<MB>
تعيين حد الذاكرة الافتراضي الذي سيتم تخصيصه لكل وحدة معالجة مركزية للمهام في هذا القسم. يتم تحديد حجم الذاكرة بالميجابايت.
DefMemPerNode=<MB>
تعيين حد الذاكرة الافتراضي الذي سيتم تخصيصه لكل عقدة للمهام في هذا القسم. يتم تحديد حجم الذاكرة بالميجابايت.
DenyAccounts=<name>
قائمة مفصولة بفواصل للحسابات التي لا يُسمح لها بتنفيذ مهام في القسم. افتراضيًا، لا يتم رفض الوصول لأي حسابات. هذه القائمة هرمية، مما يعني أن الحسابات الفرعية مدرجة تلقائيًا. **ملاحظة**: إذا تم استخدام AllowAccounts، فلن يتم تطبيق DenyAccounts. ارجع أيضًا إلى AllowAccounts.
DenyQOS=<name>
تحديد خدمات الجودة (QOSs) التي يجب رفض الوصول إليها إلى هذا القسم. يمكن تحديد خدمات جودة متعددة في قائمة مفصولة بفواصل.
DisableRootJobs={yes|no}
تحديد ما إذا كان يمكن تنفيذ المهام كالمستخدم root. القيم الممكنة هي "YES" و "NO".
ExclusiveUser={yes|no}
عند التمكين، سيتم تخصيص العقد حصريًا للمستخدمين. يمكن تشغيل مهام متعددة في وقت واحد، ولكن يجب أن تكون تلك المهام من مستخدم واحد.

NAME

scontrol — view and modify Slurm configuration and state

SYNOPSIS

scontrol [OPTIONS] [COMMANDS]

DESCRIPTION

The scontrol command is used to view and modify the state of Slurm configuration parameters and objects. It can be used to view information about jobs, nodes, partitions, reservations, and other Slurm objects. It can also be used to modify the state of these objects, such as updating job priorities or changing the state of nodes.

scontrol can be run in interactive mode or can execute specific commands from the command line.

OPTIONS

-a, --all
Show all objects, including those that are not currently active or available.
-d, --delete
Delete the specified object. This option can be used with commands such as create, update, and delete.
-h, --help
Print a help message and exit.
-i, --interactive
Run scontrol in interactive mode.
-l, --long
Show detailed information about the specified object.
-M, --cluster cluster_name
Specifies the cluster with which to communicate. This is only relevant when the Slurm configuration has been configured to communicate with multiple clusters. This option must be used when communicating with a remote cluster.
-n, --noheader
Do not print the header line when listing objects.
-o, --oneline
Print all information about a single object on one line.
-s, --short
Show abbreviated information about the specified object.
-v, --verbose
Print verbose output, including debugging information.
-V, --version
Print version information and exit.

The Job ID of the step to update.
StepId
The Step ID of the step to update.
StepState
The new state of the step. Possible values include PENDING, RUNNING, COMPLETED, FAILED.
Priority
The new priority of the step.

NODES - SPECIFICATIONS FOR CREATE COMMAND

The scontrol create node command is used to add nodes to the Slurm configuration. This command is typically used during initial cluster setup and is not intended for regular use.

NODES - SPECIFICATIONS FOR UPDATE COMMAND

The following parameters can be modified for nodes using the scontrol update node command:

NodeName
The name of the node to update.
State
The new state of the node. Possible values include IDLE, ALLOCATED, DOWN, DRAIN, REBOOT, SUSPENDED.
Reason
The reason for the node's state.

NODES - SPECIFICATIONS FOR SHOW COMMAND

The scontrol show node command can display information about nodes. You can specify node names or states to filter the output.

NodeName=node_name
Show information about the specified node.
State=node_state
Show information about nodes in the specified state.

PARTITIONS - SPECIFICATIONS FOR CREATE AND UPDATE COMMANDS

The following parameters can be specified when creating or updating partitions using the scontrol create partition and scontrol update partition commands:

PartitionName
The name of the partition.
Nodes
A list of nodes that belong to the partition.
MaxTime
The maximum time limit for jobs in the partition. Format is [[DD:]HH:]MM:SS.
MaxNodes
The maximum number of nodes that can be allocated to a single job in the partition.
State
The state of the partition. Possible values include UP, DOWN, DRAIN.

RESERVATIONS - SPECIFICATIONS FOR CREATE AND UPDATE COMMANDS

The following parameters can be specified when creating or updating reservations using the scontrol create reservation and scontrol update reservation commands:

ReservationName
The name of the reservation.
StartTime
The start time of the reservation. Format is YYYY-MM-DD[THH:MM:SS].
Duration
The duration of the reservation. Format is [[[DD:]HH:]MM:]SS.
Users
A comma-separated list of users who are allowed to use the reservation.
NodeCnt
The number of nodes to reserve.

PERFORMANCE

The scontrol command can impact the performance of the Slurm controller. Avoid running it frequently or on a large number of objects, especially in a production environment.

ENVIRONMENT VARIABLES

SLURM_CONF
The path to the slurm.conf file. If not set, the default path is used.
SLURM_HOST
The hostname of the Slurm controller. If not set, the default hostname is used.
SLURM_TIME_FORMAT
A valid strftime() format can also be specified. For example, a value of "%a %T" will report the day of the week and a 24-hour time stamp (e.g. "Mon 12:34:56").
SLURM_TOPO_LEN
Specify the maximum size of the line when printing Topology. If not set, the default value is unlimited.
SLURM_YAML
Control YAML serialization:
compact Output YAML as compact as possible.
pretty Output YAML in pretty format to make it more readable.
