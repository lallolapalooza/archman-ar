Name

sco - Bluetooth SCO socket

SYNOPSIS

#include <sys/socket.h>
#include <bluetooth/bluetooth.h>
#include <bluetooth/sco.h>

int sock = socket(PF_BLUETOOTH, SOCK_SEQPACKET, BTPROTO_SCO);

int sock = socket(AF_BLUETOOTH, SOCK_SEQPACKET, BTPROTO_SCO);

DESCRIPTION

The Bluetooth Protocol Control Block (PCB) implements the SCO (Synchronous Connection-Oriented) links. This protocol is used for audio streaming, like voice calls, between Bluetooth devices.

The SCO socket type is SOCK_SEQPACKET, which means that data is exchanged in datagrams, and these datagrams are reliably delivered in order. Each datagram sent with a send call is received as a single datagram by the receiving application with a recv call.

The Bluetooth SCO socket can be connected to a specific Bluetooth device address, or it can be bound to a local Bluetooth adapter address and port, allowing it to listen for incoming SCO connections.

SCO sockets are connection-oriented. They support connect, bind, listen, accept, send, and recv operations.

To create a SCO socket, the address family must be AF_BLUETOOTH, the socket type must be SOCK_SEQPACKET, and the protocol must be BTPROTO_SCO.

SOCKET ADDRESS

The Bluetooth socket address structure is defined by struct bluetooth_addr.

struct bluetooth_addr {
    struct sockaddr_rc sa_rc;
};

The sockaddr_rc structure is used for SCO sockets. It contains the Bluetooth device address and the SCO connection channel. The channel for SCO is always set to BT_CHAN_SCO.

struct sockaddr_rc {
    sa_family_t     rc_family;  // AF_BLUETOOTH
    bdaddr_t        rc_bdaddr;  // Bluetooth device address
    uint8_t         rc_channel; // BT_CHAN_SCO
};

The bdaddr_t structure is defined as:

typedef struct {
    uint8_t addr[6];
} bdaddr_t;

The Bluetooth device address can be set to any manually set address or to the wildcard address BDADDR_ANY (all zeros) to allow the kernel to assign an address.

For SCO sockets, the rc_channel field must be set to BT_CHAN_SCO.

SOCKET OPTIONS (SOL_BLUETOOTH)

The following socket options are available for SCO sockets under the SOL_BLUETOOTH level.

BT_SECURITY

Set the security level for the connection. The possible values are:

Define Value Description
BT_SECURITY_LOW 0 No security (unencrypted and unauthenticated)
BT_SECURITY_MEDIUM 1 Authentication required, encryption optional
BT_SECURITY_HIGH 2 Authentication and encryption required
BT_SECURITY_FIPS 3 FIPS certified security (if supported)

BT_POWER

Set the transmit power level for the connection. The value is implementation-dependent and may be ignored by the hardware.

Possible values range from 0 to 9.

BT_VOICE

Set the voice setting for the connection. The possible values are:

Define Value Description
BT_VOICE_TRANSCODE 0x00 Use codec to transcode
BT_VOICE_CVSD 0x01 Use CVSD codec
BT_VOICE_MSBC 0x02 Use mSBC codec (Wideband Speech)
BT_VOICE_PCM 0x03 Use PCM codec (no transcoding)

BT_MAX_CONNECTIONS

Set the maximum number of concurrent SCO connections allowed. This option is only applicable for listening sockets.

The default value is 1.

BT_SNDMTU

Set the maximum transmit unit (MTU) for SCO sockets. This option is read-only and indicates the maximum size of a data packet that can be sent over the SCO link.

The default value is 255 bytes.

BT_RCVMTU

Set the maximum receive unit (MTU) for SCO sockets. This option is read-only and indicates the maximum size of a data packet that can be received over the SCO link.

The default value is 255 bytes.

BT_FLUSH

Flush any pending data in the transmit queue. This option is write-only.

Setting this option to 1 will discard all data in the transmit buffer and send an empty packet.

BT_RECV_FLUSH_TIMEOUT

Set the receive flush timeout for SCO sockets. This option is read-only.

The value represents the time in milliseconds that the controller will wait for a packet before discarding it. The default value is 0, which means no timeout.

BT_LINK_POLICY

Set the link policy for SCO connections. This option is read-only.

Possible values:

Define Value Description
BT_LINK_POLICY_RETRANSMISSION BIT(0) Enable retransmissions
BT_LINK_POLICY_ROBUST_BUFFER_ALLOCATION BIT(1) Use robust buffer allocation
BT_LINK_POLICY_HOLD_MODE BIT(2) Enable hold mode
BT_LINK_POLICY_SNIFF_MODE BIT(3) Enable sniff mode
BT_LINK_POLICY_PARK_MODE BIT(4) Enable park mode

BT_CONNINFO

Get connection information for SCO sockets. This option is read-only.

The information is returned in a struct bt_conninfo:

struct bt_conninfo {
    uint16_t        hci_handle;
    uint16_t        tx_interval;
    uint16_t        rx_interval;
    uint8_t         type;
    uint8_t         latency;
    uint8_t         voice_setting;
    uint8_t         class_of_device[3];
    struct timespec timestamp;
};

Possible values for the type field:

Define Value Description
BT_CONNINFO_INVALID 0x00 No data received
0x3 Data partially lost

BT_PHY (since Linux 5.10)

Transport supported PHY(s), read-only (no setsockopt support). Possible values:

Define Value Description
BT_PHY_BR_1M_1SLOT BIT 0 BR 1Mbps 1SLOT
BT_PHY_BR_1M_3SLOT BIT 1 BR 1Mbps 3SLOT
BT_PHY_BR_2M_1SLOT BIT 3 EDR 2Mbps 1SLOT
BT_PHY_BR_2M_3SLOT BIT 4 EDR 2Mbps 3SLOT
BT_PHY_BR_3M_1SLOT BIT 6 EDR 3Mbps 1SLOT
BT_PHY_BR_3M_3SLOT BIT 7 EDR 3Mbps 3SLOT

BT_CODEC (since Linux 5.14)

Transport codec offload, possible values:

struct bt_codec {
    uint8_t id;
    uint16_t cid;
    uint16_t vid;
    uint8_t data_path_id;
    uint8_t num_caps;
    struct codec_caps {
        uint8_t len;
        uint8_t data[];
    } caps[];
} __attribute__((packed));
struct bt_codecs {
    uint8_t num_codecs;
    struct bt_codec codecs[];
} __attribute__((packed));

Example:

char buffer[sizeof(struct bt_codecs) + sizeof(struct bt_codec)];
struct bt_codec *codecs = (void *)buffer;
memset(codecs, 0, sizeof(codecs));
codec->num_codecs = 1;
codecs->codecs[0].id = 0x05;
codecs->codecs[0].data_path_id = 1;
int err = setsockopt(sco_socket, SOL_BLUETOOTH, BT_CODEC, codecs,
                     sizeof(buffer));
if (err == -1) {
    perror("setsockopt");
    return 1;
}

SOCKET OPTIONS (SOL_SOCKET)

SOL_SOCKET level socket options that modify generic socket features (SO_SNDBUF, SO_RCVBUF, etc.) have their usual meaning, see socket(7).

The SOL_SOCKET level SCO socket options that have Bluetooth-specific handling in kernel are listed below.

SO_TIMESTAMPING, SO_TIMESTAMP, SO_TIMESTAMPNS

See https://docs.kernel.org/networking/timestamping.html

For SCO sockets, software RX timestamps are supported. Software TX timestamps (SOF_TIMESTAMPING_TX_SOFTWARE) are supported since Linux 6.15.

The software RX timestamp is the time when the kernel received the packet from the controller driver.

The SCM_TSTAMP_SND timestamp is emitted when packet is sent to the controller driver.

The SCM_TSTAMP_COMPLETION timestamp is emitted when controller reports the packet completed. Completion timestamps are only supported on controllers that have SCO flow control. Other TX timestamp types are not supported.

You can use SIOCETHTOOL to query supported flags.

The timestamps are in CLOCK_REALTIME time.

Example (Enable RX timestamping):

int flags = SOF_TIMESTAMPING_SOFTWARE |
    SOF_TIMESTAMPING_RX_SOFTWARE;
setsockopt(fd, SOL_SOCKET, SO_TIMESTAMPING, &flags, sizeof(flags));

Example (Read packet and its RX timestamp):

char data_buf[256];
union {
    char buf[CMSG_SPACE(sizeof(struct scm_timestamping))];
    struct cmsghdr align;
} control;
struct iovec data = {
    .iov_base = data_buf,
    .iov_len = sizeof(data_buf),
};
struct msghdr msg = {
    .msg_iov = &data,
    .msg_iovlen = 1,
    .msg_control = control.buf,
    .msg_controllen = sizeof(control.buf),
};
struct scm_timestamping tss;
res = recvmsg(fd, &msg, MSG_ERRQUEUE | MSG_DONTWAIT);
if (res < 0)
    goto error;
for (cmsg = CMSG_FIRSTHDR(&msg); cmsg; cmsg = CMSG_NXTHDR(&msg, cmsg)) {
    if (cmsg->cmsg_level == SOL_SOCKET && cmsg->cmsg_type == SCM_TIMESTAMPING)
        memcpy(&tss, CMSG_DATA(cmsg), sizeof(tss));
}
tstamp_clock_realtime = tss.ts[0];

Example (Enable TX timestamping):

int flags = SOF_TIMESTAMPING_SOFTWARE |
    SOF_TIMESTAMPING_TX_SOFTWARE |
    SOF_TIMESTAMPING_OPT_ID;
setsockopt(fd, SOL_SOCKET, SO_TIMESTAMPING, &flags, sizeof(flags));

Example (Read TX timestamps):

union {
    char buf[CMSG_SPACE(sizeof(struct scm_timestamping))];
    struct cmsghdr align;
} control;
struct iovec data = {
    .iov_base = NULL,
    .iov_len = 0
};
struct msghdr msg = {
    .msg_iov = &data,
    .msg_iovlen = 1,
    .msg_control = control.buf,
    .msg_controllen = sizeof(control.buf),
};
struct cmsghdr *cmsg;
struct scm_timestamping tss;
struct sock_extended_err serr;
int res;
res = recvmsg(fd, &msg, MSG_ERRQUEUE | MSG_DONTWAIT);
if (res < 0)
    goto error;
for (cmsg = CMSG_FIRSTHDR(&msg); cmsg; cmsg = CMSG_NXTHDR(&msg, cmsg)) {
    if (cmsg->cmsg_level == SOL_SOCKET && cmsg->cmsg_type == SCM_TIMESTAMPING)
        memcpy(&tss, CMSG_DATA(cmsg), sizeof(tss));
    else if (cmsg->cmsg_level == SOL_BLUETOOTH && cmsg->cmsg_type == BT_SCM_ERROR)
        memcpy(&serr, CMSG_DATA(cmsg), sizeof(serr));
}
tstamp_clock_realtime = tss.ts[0];
tstamp_type = serr->ee_info;      /* SCM_TSTAMP_SND or SCM_TSTAMP_COMPLETION */
tstamp_seqnum = serr->ee_data;

IOCTLS

The following ioctls with operation specific for SCO sockets are available.

SIOCETHTOOL (since Linux 6.16-rc1)

Supports only command ETHTOOL_GET_TS_INFO, which may be used to query supported SOF_TIMESTAMPING_* flags. The SOF_TIMESTAMPING_OPT_* flags are always available as applicable.

Example:

#include <linux/ethtool.h>
#include <linux/sockios.h>
#include <net/if.h>
#include <sys/socket.h>
#include <sys/ioctl.h>
...
struct ifreq ifr = {};
struct ethtool_ts_info cmd = {};
int sk;
snprintf(ifr.ifr_name, sizeof(ifr.ifr_name), "hci0");
ifr.ifr_data = (void *)&cmd;
cmd.cmd = ETHTOOL_GET_TS_INFO;
sk = socket(PF_BLUETOOTH, SOCK_SEQPACKET, BTPROTO_SCO);
if (sk < 0)
    goto error;
if (ioctl(sk, SIOCETHTOOL, &ifr))
    goto error;
sof_available = cmd.so_timestamping;
