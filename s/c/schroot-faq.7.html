الاسم

schroot - أسئلة متكررة

الوصف

تغطي صفحة الدليل هذه مجموعة متنوعة من الأسئلة المتكررة حول تهيئة واستخدام schroot.

التهيئة

لماذا يقوم schroot بالكتابة فوق ملفات التكوين في chroot؟

بشكل افتراضي، يقوم schroot بنسخ قواعد بيانات NSS للنظام ('passwd'، 'shadow'، 'group'، 'gshadow'، 'services'، 'protocols'، 'networks'، و 'hosts'، إلخ) إلى chroot. السبب وراء ذلك هو أن بيئة chroot ليست نظامًا منفصلاً تمامًا، ونسخها فوقها يحافظ على تزامنها. ومع ذلك، قد لا يكون هذا مرغوبًا دائمًا، خاصة إذا كان تثبيت حزمة في chroot ينشئ مستخدمين ومجموعات نظام غير موجودين على المضيف، حيث سيختفون في المرة التالية التي يتم فيها نسخ قواعد البيانات.

الحل البديل المقترح هنا هو تعطيل النسخ. يمكن تحقيق ذلك عن طريق تعيين مفتاح setup.nssdatabases ليكون فارغًا في schroot.conf. في إصدارات schroot السابقة، تم ذلك عن طريق التعليق على ملف NSSDATABASES لـ chroot (/etc/schroot/default/config بشكل افتراضي). يمكن أيضًا تخصيص قائمة قواعد البيانات عن طريق تحرير الملف الذي يحتوي على قائمة قواعد البيانات (/etc/schroot/default/nssdatabases بشكل افتراضي).

في المستقبل، سنعمل على مخطط أفضل للحفاظ على تزامن قواعد بيانات المضيف و chroot والذي يمكنه دمج الإدخالات بدلاً من الكتابة فوق قاعدة البيانات بأكملها، مما سيحافظ على التغييرات الخاصة بـ chroot.

هل يجب علي استخدام النوع البسيط أو النوع الدليلي لـ chroot؟

هذان النوعان من chroot متكافئان بشكل أساسي، حيث أنهما مجرد دليلين في نظام الملفات. النوع البسيط بسيط جدًا ولا يقوم بأي مهام إعداد؛ والسبب الوحيد الذي قد ترغب في استخدامه من أجله هو إذا كنت تقوم بالترقية من برنامج مثل dchroot(1) أو chroot(8) الذي لا يقوم بأي شيء سوى تشغيل أمر أو shell في دليل. من ناحية أخرى، تقوم chroot الدليلية بتشغيل نصوص الإعداد، والتي يمكنها تحميل أنظمة ملفات إضافية والقيام بمهام إعداد أخرى.

التهيئة المتقدمة

ما هي اللقطات والاتحادات؟

تدعم بعض أنواع chroot الاستنساخ. هذا يعني أنه عند بدء جلسة، تحصل على نسخة من chroot تستمر فقط طوال مدة الجلسة. هذا مفيد عندما تريد نسخة نظيفة مؤقتة لنظام لمهمة واحدة، والتي يتم حذفها تلقائيًا عند الانتهاء منها. على سبيل المثال، تقوم شياطين بناء حزم Debian بتشغيل sbuild(1) لبناء حزم Debian، وهذا البرنامج يستخدم schroot لإنشاء بيئة بناء نظيفة لكل حزمة. بدون أخذ لقطات، سيحتاج chroot إلى إعادة تعيينه إلى حالته الأولية في نهاية كل بناء لجعله جاهزًا للبناء التالي، وأي بقايا متبقية من إزالة الحزم أو عمليات البناء السابقة يمكن أن تتداخل مع البناء التالي.

الطريقة الأكثر استخدامًا لأخذ اللقطات هي استخدام لقطات LVM (نوع chroot 'lvm-snapshot'). في هذه الحالة، يجب أن يوجد chroot على حجم منطقي LVM (LV)؛ يمكن بعد ذلك أخذ لقطات لـ LV باستخدام lvcreate(8) أثناء إعداد جلسة chroot. ومع ذلك، فإن هذه تستهلك الكثير من مساحة القرص. طريقة أحدث هي استخدام لقطات Btrfs التي تستهلك مساحة قرص أقل بكثير (نوع chroot 'btrfs-snapshot')، وقد تكون أكثر موثوقية من لقطات LVM. ومع ذلك، لا يزال Btrfs تجريبيًا، ولكن من المأمول أن يصبح الطريقة الموصى بها مع نضجه.

الاتحادات هي بديل للقطات. في هذا الموقف، بدلاً من إنشاء نسخة من نظام ملفات chroot، نقوم بتركيب نظام ملفات مؤقت للقراءة والكتابة فوق نظام ملفات chroot بحيث يتم تخزين أي تعديلات في الطبقة العلوية، تاركًا نظام ملفات chroot الأصلي دون تغيير. لم يقم نواة Linux بدمج الدعم لأنظمة الملفات الاتحادية مثل aufs و unionfs، لذا لا تزال لقطات LVM هي الطريقة الموصى بها في الوقت الحالي.

الاستخدام

هل يمكنني تشغيل الشياطين (daemons) في chroot؟

المشكلة الشائعة هي محاولة تشغيل شيطان في chroot، وتجد أن هذا لا يعمل. عادةً، يتم قتل الشي atan بعد فترة وجيزة من بدء تشغيله.

عندما يعمل schroot، يبدأ جلسة، ويشغل الأمر أو shell المحدد، وينتظر خروج الأمر أو shell، ثم ينهي الجلسة. بالنسبة للأمر العادي أو shell، يعمل هذا بشكل جيد. ومع ذلك، تبدأ الشياطين عادةً بالعمل في الخلفية وفصلها عن الطرفية المتحكمة. تفعل ذلك عن طريق التفرع مرتين والسماح لعمليات الوالدين بالخروج. لسوء الحظ، هذا يعني أن schroot يكتشف أن البرنامج قد خرج (الشيطان هو سليل يتيم لهذه العملية) ويقوم بإنهاء الجلسة. جزء من إنهاء الجلسة هو قتل جميع العمليات التي تعمل داخل chroot، مما يعني أن الشي atan يتم قتله عند انتهاء الجلسة.

نتيجة لذلك، لا يمكن تشغيل شيطان مباشرة باستخدام schroot. ومع ذلك، يمكنك القيام بذلك إذا قمت بإنشاء جلسة باستخدام --begin-session ثم شغلت الشي atan باستخدام --run-session. تقع على عاتقك مسؤولية إنهاء الجلسة باستخدام --end-session عند انتهاء الشي atan أو عندما لا تعود بحاجة إليه.

كيف أقوم بتنظيف جلسة معطلة يدويًا؟

في بعض الأحيان، قد يكون من الضروري تنظيف الجلسات يدويًا. إذا تغير شيء ما في نظامك مما يتسبب في فشل نصوص الإعداد عند إنهاء الجلسة، على سبيل المثال، إزالة ملف أو دليل مطلوب، فقد لا يكون من الممكن لـ schroot تنظيف كل شيء تلقائيًا. لكل دليل جلسة مدرج في قسم "دليل الجلسة" في schroot(1)، يجب حذف أي ملفات باسم معرف الجلسة، ويجب إلغاء تحميل أي دلائل باسم معرف الجلسة (إذا كانت هناك أي أنظمة ملفات محملة تحتها)، ثم إزالتها أيضًا.

على سبيل المثال، لإزالة جلسة تسمى my-session يدويًا:

•
حذف ملف تكوين الجلسة 
% rm /var/lib/schroot/session/my-session↵
•
التحقق من أنظمة الملفات المحملة 
% /usr/lib/schroot/schroot-listmounts -m \
  /var/run/schroot/mount/my-session↵
•
إلغاء تحميل أي أنظمة ملفات محملة
•
إزالة /var/run/schroot/mount/my-session
•
التكرار للدلائل الأخرى مثل /var/lib/schroot/union/underlay، /var/lib/schroot/union/overlay و /var/lib/schroot/unpack

ملاحظة: لا تقم بإزالة أي دلائل دون التحقق مما إذا كانت هناك أي أنظمة ملفات محملة تحتها، حيث قد تظل أنظمة الملفات مثل /home محملة بربط. القيام بذلك قد يتسبب في فقدان بيانات لا يمكن استعادتها!

schroot-faq(7) — schroot — Arch Linux

DESCRIPTION

The schroot utility allows you to run commands and build packages in otherwise clean chroot environments.

This manual page provides a FAQ for schroot.

WHAT IS SCHROOT?

schroot stands for Secure CHRoot. It is a system that allows unprivileged users to run commands within a chroot environment.

This is achieved by running schroot as root, which sets up the chroot environment, then runs the specified command as the specified user within that chroot. The process is then marked as a child of the original schroot process which exits, leaving the command running as the specified user within the chroot environment.

Further details on schroot can be found in the schroot(1) man page.

WHAT IS A CHROOT?

A chroot is an operation that changes the perceived root directory for the current running process and its children. By changing the root directory, you can make a portion of the filesystem appear as the entire filesystem.

This is useful for testing software, building packages, or providing a restricted environment for users.

However, the standard chroot utility has several drawbacks:

  • It requires root privileges to set up.
  • It does not provide any isolation between the host system and the chroot environment.
  • It is difficult to manage multiple chroot environments.

schroot addresses these issues by providing a more secure and flexible chroot environment.

HOW DOES SCHROOT HANDLE MULTIPLE CHROOTS?

schroot uses configuration files to manage multiple chroot environments. The main configuration file is located at /etc/schroot/schroot.conf. This file defines the chroot environments, their locations, and their properties.

Each chroot environment can have its own configuration file, allowing for fine-grained control over its behavior.

WHAT IS A SESSION?

When schroot is invoked with a single command, such as:

% schroot -c squeeze -- command↵

the following steps are performed:

•
A session is created using the squeeze chroot. This is automatically assigned a unique name, such as squeeze-57a69547-e014-4f5d-a98b-f4f35a005307, although you don't usually need to know this.
•
Setup scripts are run to create the session chroot and configure it for you.
•
The command command is run inside the session chroot.
•
Setup scripts are run to clean up the session chroot.
•
The session is deleted.

Now, if you wanted to run more than one command, you could run a shell and run them interactively, or you could put them into shell script and run that instead. But you might want to do something in between, such as running arbitrary commands from a program or script where you don't know which commands to run in advance. You might also want to preseve the chroot state in between commands, where the normal automatic session creation would reset the state in between each command. This is what sessions are for: once created, the session is persistent and won't be automatically removed. With a session, you can run as many commands as you like, but you need to create and delete the session by hand since schroot can't know by itself when you're done with it unlike in the single command case above. This is quite easy:

% schroot --begin-session -c squeeze↵
squeeze-57a69547-e014-4f5d-a98b-f4f35a005307

This created a new session based upon the squeeze chroot. The unique name for the session, the session ID, was printed to standard output, so we could also save it as a shell variable at the same time like so:

% SESSION=$(schroot --begin-session -c squeeze)↵
% echo $SESSION↵
squeeze-57a69547-e014-4f5d-a98b-f4f35a005307

Now we have created the session and got the session ID, we can run commands in it using the session ID:

% schroot --run-session -c squeeze-57a69547-e014-4f5d-a98b-f4f35a005307 \
  -- command1↵

or

% schroot --run-session -c "$SESSION" -- command1↵

and then as many more commands as we like

% schroot --run-session -c "$SESSION" -- command2↵
% schroot --run-session -c "$SESSION" -- command3↵
% schroot --run-session -c "$SESSION" -- command4↵

etc.

When we are done with the session, we can remove it with --end-session:

% schroot --end-session -c squeeze-57a69547-e014-4f5d-a98b-f4f35a005307↵

or

% schroot --end-session -c "$SESSION"↵

Since the automatically generated session names can be long and unwieldy, the --session-name option allows you to provide you own name:

% schroot --begin-session -c squeeze --session-name my-name↵
my-name
