SCAN-BUILD(1) دليل الأوامر العامة SCAN-BUILD(1)

الاسم

scan-build — محلل Clang الثابت

الشكل العام

scan-build [-ohkvV] [-analyze-headers] [-enable-checker [اسم_المفحص]] [-disable-checker [اسم_المفحص]] [--help] [--help-checkers] [--html-title [=عنوان]] [--keep-going] [-plist] [-plist-html] [--status-bugs] [--use-c++ [=مسار_المترجم]] [--use-cc [=مسار_المترجم]] [--view] [-constraints [نموذج]] [-maxloop N] [-no-failure-reports] [-stats] [-store [نموذج]] أمر_البناء [خيارات_البناء]

الوصف

scan-build هو سكربت Perl يستدعي محلل Clang الثابت. الخيارات التي يستخدمها scan-build أو المحلل تظهر أولاً، تليها أمر_البناء وأي خيارات_البناء المستخدمة عادة لبناء النظام المستهدف.

يستخدم المحلل الثابت قائمة طويلة من خوارزميات الفحص، انظر CHECKERS. يمكن كتابة الإخراج بتنسيق .plist و/أو HTML القياسي.

الخيارات التالية مدعومة:

-analyze-headers
تحليل الدوال في الملفات التي تم تضمينها (#included) أيضًا.
-enable-checker اسم_المفحص, -disable-checker اسم_المفحص
تمكين/تعطيل اسم_المفحص. انظر CHECKERS.
-h, --help
عرض هذه الرسالة.
--help-checkers
قائمة المفحصات الافتراضية، انظر CHECKERS.
--html-title[=عنوان]
تحديد العنوان المستخدم في صفحات HTML التي تم إنشاؤها. يتم إنشاء عنوان افتراضي إذا لم يتم تحديد عنوان.
-k, --keep-going
إضافة خيار "المتابعة" إلى أمر_البناء. حاليًا يدعم make و xcodebuild. هذا خيار اختصار؛ يمكن للمستخدم تحديد هذا السلوك مباشرة باستخدام خيارات البناء.
-o
دليل الهدف لملفات تقرير HTML. سيتم إنشاء مجلدات فرعية حسب الحاجة لتمثيل استدعاءات منفصلة للمحلل. إذا لم يتم تحديد هذا الخيار، يتم إنشاء دليل في /tmp (TMPDIR على Mac OS X) لتخزين التقارير.
-plist
إخراج النتائج كمجموعة من ملفات .plist. (بشكل افتراضي، إخراج scan-build هو مجموعة من ملفات HTML.)
-plist-html
إخراج النتائج كمجموعة من ملفات HTML و .plist
--status-bugs
تعيين حالة الخروج إلى 1 إذا وجد أخطاء محتملة و 0 بخلاف ذلك. افتراضيًا، حالة الخروج لـ scan-build هي تلك التي يعيدها أمر_البناء.
--use-c++[=مسار_المترجم]
تخمين المترجم الافتراضي لتعليمات C++ و Objective-C++ البرمجية. استخدم هذا الخيار لتحديد مترجم بديل.
--use-cc[=مسار_المترجم]
تخمين المترجم الافتراضي لتعليمات C و Objective-C البرمجية. استخدم هذا الخيار لتحديد مترجم بديل.
-v
إخراج تفصيلي من scan-build والمحلل. زيادة v الثانية والثالثة تزيد من التفاصيل.
-V, --view
عرض نتائج التحليل في متصفح الويب عند اكتمال البناء.
-constraints [نموذج]
تحديد محرك القيود الذي يستخدمه المحلل. افتراضيًا، يتم استخدام نموذج ' range ' (النطاق). تحديد ' basic ' (أساسي) يستخدم نموذج قيود أبسط وأقل قوة يستخدم في checker-0.160 وما قبله.
-maxloop N
تحديد عدد المرات التي يمكن زيارة كتلة فيها قبل التخلي. الافتراضي هو 4. زيادة هذا العدد لتغطية أشمل على حساب السرعة.
-no-failure-reports
عدم إنشاء مجلد فرعي ' failures ' (فشل) يتضمن تقارير تعطل المحلل وملفات المصدر المعالجة مسبقًا.
-stats
إنشاء إحصائيات الزيارة للمشروع الذي يتم تحليله.
-store [نموذج]
تحديد نموذج التخزين الذي يستخدمه المحلل. افتراضيًا، يتم استخدام نموذج التخزين ' region ' (المنطقة). ' region ' يحدد نموذج تخزين حساس للحقل. يمكن للمستخدمين أيضًا تحديد ' basic ' (أساسي) وهو أقل دقة بكثير ولكنه يمكن أن يحلل التعليمات البرمجية بشكل أسرع. ' basic ' كان نموذج التخزين الافتراضي لـ checker-0.221 وما قبله.

حالة الخروج

scan-build يعيد القيمة التي يعيدها أمر_البناء إلا إذا تم استخدام --status-bugs أو --keep-going.

المفحصات

قد يتم تمكين/تعطيل المفحصات المدرجة أدناه باستخدام خيارات -enable-checker و -disable-checker. يتم تشغيل مجموعة افتراضية من المفحصات ما لم يتم تعطيلها صراحة. يعتمد تحديد المفحصات التي تشكل المجموعة الافتراضية على نظام التشغيل قيد الاستخدام؛ يتم سردها باستخدام --help-checkers.

core.AdjustedReturnValue
التحقق مما إذا كانت القيمة المرجعة لاستدعاء دالة تختلف عما يتوقعه المستدعي (على سبيل المثال، من الاستدعاءات عبر مؤشرات الدوال).
core.AttributeNonNull
التحقق من مؤشرات فارغة (null pointers) تم تمريرها كوسائط لدالة تم تمييز وسائطها بالسمة ' nonnull '.
core.CallAndMessage
التحقق من الأخطاء المنطقية لاستدعاءات الدوال وتعبيرات رسائل Objective-C (على سبيل المثال، وسائط غير مهيأة، مؤشرات دوال فارغة).
core.DivideZero
التحقق من القسمة على صفر.
core.NullDereference
التحقق من إلغاء إشارة مؤشر فارغ (null pointer dereferences).
core.StackAddressEscape
التحقق من أن عناوين الذاكرة المكدسة لا تتجاوز الدالة.
core.UndefinedBinaryOperatorResult
التحقق من النتائج غير المعرفة للمشغلات الثنائية.
core.VLASize
التحقق من تعريفات VLA (Variable Length Array) ذات حجم غير معرف أو صفر.
core.builtin.BuiltinFunctions
تقييم الدوال المدمجة للمترجم، على سبيل المثال alloca

NAME

scan-build

a tool for finding bugs in C, C++, and Objective-C code

SYNOPSIS

scan-build [options] command[arguments...]

DESCRIPTION

The scan-build utility is a tool for finding bugs in C, C++, and Objective-C code. It works by intercepting compiler invocations and running static analysis checks on the source code. These checks are performed by the Clang static analyzer.

The results of the analysis are printed to standard error and also saved as HTML reports in a subdirectory of the current working directory. These HTML reports provide a more detailed view of the bugs found, including source code annotations.

The scan-build tool can be used to analyze any build process that is invoked via compiler commands. This includes build systems like Make, CMake, and Autoconf, as well as direct calls to compilers like clang or gcc.

EXIT STATUS

The exit status of scan-build is the exit status of the command it executed. If scan-build itself encounters an error (e.g., unable to intercept compiler invocations), it will exit with a non-zero status.

Warn on using a floating point value as a loop counter.
core.Security.insecureAPI.DeprecatedOrUnsafe

core.Security.insecureAPI.getpw
Warn on uses of getpw().
core.Security.insecureAPI.gets
Warn on uses of gets().

Warn when mkstemp() is passed fewer than 6 X's in the format string.
core.Security.insecureAPI.mktemp
Warn on uses of mktemp().

EXAMPLE

scan-build -o /tmp/myhtmldir make -j4

The above example causes analysis reports to be deposited into a subdirectory of /tmp/myhtmldir and to run make with the -j4 option. A different subdirectory is created each time scan-build analyzes a project. The analyzer should support most parallel builds, but not distributed builds.
