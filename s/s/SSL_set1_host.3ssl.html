SSL_set1_host(3ssl)

الحزمة: openssl

التراخيص: Apache-2.0

SSL_SET1_HOST(3ssl) OpenSSL SSL_SET1_HOST(3ssl)

الاسم

SSL_set1_host, SSL_add1_host, SSL_set_hostflags, SSL_get0_peername - معلمات التحقق من خادم SSL

الملخص

#include <openssl/ssl.h>
int SSL_set1_host(SSL *s, const char *host);
int SSL_add1_host(SSL *s, const char *host);
void SSL_set_hostflags(SSL *s, unsigned int flags);
const char *SSL_get0_peername(SSL *s);

الوصف

تقوم هذه الدوال بتكوين فحوصات اسم المضيف للخادم في عميل SSL.

SSL_set1_host() تقوم بتعيين اسم DNS المتوقع أو عنوان IP المتوقع في معلمات التحقق من s إلى host، مع مسح أي عنوان IP وأسماء مضيفين محددة مسبقًا. إذا كان host هو NULL أو سلسلة فارغة، فلا يتم إجراء فحوصات عنوان IP واسم المضيف على شهادة النظير. عند تحديد host غير فارغ، تتحقق عملية التحقق من الشهادة تلقائيًا من اسم مضيف النظير عبر X509_check_host(3) باستخدام flags كما تم تحديده عبر SSL_set_hostflags(). يجب على العملاء الذين يقومون بتمكين مصادقة DANE TLSA عبر SSL_dane_enable(3) ترك الأمر لتلك الدالة لتعيين المعرف المرجعي الأساسي للنظير، ويجب ألا يستدعوا SSL_set1_host().

SSL_add1_host() تضيف host كمعرف مرجعي إضافي يمكن أن يتطابق مع شهادة النظير. يتم الاحتفاظ بأي أسماء مضيفين سابقة تم تعيينها عبر SSL_set1_host() أو SSL_add1_host(). إضافة عنوان IP مسموح بها فقط إذا لم يتم تعيين عنوان IP من قبل. لا يتم إجراء أي تغيير إذا كان host هو NULL أو فارغًا. عند تكوين عنوان IP و/أو أسماء مضيفين متعددة، يعتبر النظير موثقًا عندما يتطابق أي من هذه. هذه الدالة مطلوبة لـ DANE TLSA في وجود توجيه اسم الخدمة عبر سجلات CNAME أو MX أو SRV كما هو محدد في RFCs 7671 و 7672 و 7673.

يوصى لعملاء TLS باستخدام SSL_set1_host() أو SSL_add1_host() للتحقق من صحة اسم المضيف أو عنوان IP للخادم، بالإضافة إلى SSL_set_tlsext_host_name(3) لـ Server Name Indication (SNI)، والتي قد تكون حاسمة أيضًا للتوجيه الصحيح لطلب الاتصال.

SSL_set_hostflags() تعين flags التي سيتم تمريرها إلى X509_check_host(3) عندما تكون فحوصات الاسم قابلة للتطبيق، افتراضيًا تكون قيمة flags هي 0. انظر X509_check_host(3) للحصول على قائمة بالعلامات المتاحة ومعناها.

SSL_get0_peername() تعيد اسم DNS أو الاسم الشائع للموضوع من شهادة النظير التي تطابقت مع أحد المعرفات المرجعية. عندما لا يتم تعطيل مطابقة الأحرف البديلة (wildcard)، قد يكون الاسم المتطابق في شهادة النظير اسمًا بديلًا. عندما يبدأ أحد المعرفات المرجعية المكونة عبر SSL_set1_host() أو SSL_add1_host() بـ ".".، مما يشير إلى بادئة نطاق أصل بدلاً من اسم ثابت، قد يكون اسم النظير المتطابق نطاقًا فرعيًا للمعرف المرجعي. السلسلة المعادة مخصصة من قبل المكتبة ولم تعد صالحة بمجرد مسح مقبض ssl المرتبط أو تحريره، أو حدوث إعادة تفاوض. يجب على التطبيقات عدم تحرير القيمة المعادة.

ينصح عملاء SSL باستخدام هذه الدوال بدلاً من استدعاء X509_check_host(3) بشكل صريح. قد تكون فحوصات اسم المضيف خارج النطاق مع استخدام شهادة RFC 7671 DANE-EE(3)، وسيتم كبت الفحص الداخلي حسب الاقتضاء عند تمكين DANE.

قيم الإرجاع

SSL_set1_host() و SSL_add1_host() تعيدان 1 للنجاح و 0 للفشل.

SSL_set_hostflags() لا تعيد شيئًا على الإطلاق.

SSL_get0_peername() تعيد NULL إذا كان التحقق من اسم النظير غير قابل للتطبيق (كما هو الحال مع RFC 7671 DANE-EE(3))، أو لم يتم مطابقة اسم نظير موثوق. بخلاف ذلك، تعيد اسم النظير المتطابق. لتحديد ما إذا كان التحقق ناجحًا، استدعِ SSL_get_verify_result(3).

أمثلة

لنفترض أن "smtp.example.com" هو مضيف MX للنطاق "example.com". ستقوم الاستدعاءات أدناه بترتيب المطابقة إما لاسم مضيف MX أو اسم نطاق الوجهة في شهادة خادم SMTP. يتم دعم الأحرف البديلة، ولكن يجب أن تتطابق مع التسمية بأكملها. يتم استرداد الاسم الفعلي المتطابق في الشهادة (والذي قد يكون بديلًا)، ويجب نسخه بواسطة التطبيق إذا كان سيتم الاحتفاظ به بعد مدة اتصال SSL.

SSL_set_hostflags(ssl, X509_CHECK_FLAG_NO_PARTIAL_WILDCARDS);
if (!SSL_set1_host(ssl, "smtp.example.com"))
    /* خطأ */
if (!SSL_add1_host(ssl, "example.com"))
    /* خطأ */
/* XXX: قم بإجراء SSL_connect() handshake ومعالجة الأخطاء هنا */
if (SSL_get_verify_result(ssl) == X509_V_OK) {
    const char *peername = SSL_get0_peername(ssl);
    if (peername != NULL)
        /* كانت فحوصات الاسم ضمن النطاق وطابقت peername */
}
