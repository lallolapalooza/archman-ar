الوصف

SSL_CTX_set_alpn_protos() و SSL_set_alpn_protos() يستخدمان من قبل العميل لتحديد قائمة البروتوكولات المتاحة للتفاوض. يجب أن تكون protos بتنسيق قائمة البروتوكولات، الموضح أدناه. يتم تحديد طول protos في protos_len. يؤدي تعيين protos_len إلى 0 إلى مسح أي قائمة موجودة لبروتوكولات ALPN ولن يتم إرسال امتداد ALPN إلى الخادم.

SSL_CTX_set_alpn_select_cb() يحدد دالة الاستدعاء للتطبيق cb التي يستخدمها الخادم لتحديد البروتوكول الذي سيتم استخدامه للاتصال الوارد. عندما تكون cb هي NULL، لا يتم استخدام ALPN. القيمة arg هي مؤشر يتم تمريره إلى دالة استدعاء التطبيق.

cb هي دالة استدعاء معرفة من قبل التطبيق. معلمتا in و inlen هما متجه بتنسيق قائمة البروتوكولات. يجب تعيين قيمة المتجه out و outlen إلى قيمة بروتوكول واحد تم تحديده من المتجه in و inlen. قد يشير المخزن المؤقت out مباشرة إلى in، أو إلى مخزن مؤقت يتجاوز عمر المصافحة. المعلمة arg هي المؤشر الذي تم تعيينه عبر SSL_CTX_set_alpn_select_cb().

SSL_select_next_proto() هي دالة مساعدة تستخدم لتحديد البروتوكولات. إنها تنفذ الاختيار القياسي للبروتوكولات. من المتوقع استدعاء هذه الدالة من دالة استدعاء التطبيق cb. يجب أن تكون بيانات البروتوكول في server و server_len و client و client_len بتنسيق قائمة البروتوكولات الموضحة أدناه. يتم تحديد العنصر الأول في قائمة server و server_len الذي يتطابق مع عنصر في قائمة client و client_len، ويتم إرجاعه في out و outlen. ستشير القيمة out إما إلى server أو client، لذا يجب نسخها على الفور. يجب أن تتضمن قائمة العميل مدخل بروتوكول صالح واحد على الأقل (غير فارغ) في القائمة.

يمكن أن تكون الدالة المساعدة SSL_select_next_proto() مفيدة إما من دالة استدعاء ALPN أو دالة استدعاء NPN (الموضحة أدناه). إذا لم يتم العثور على تطابق، فسيتم إرجاع العنصر الأول في client و client_len في out و outlen، وسيتم إرجاع OPENSSL_NPN_NO_OVERLAP. يمكن أن يكون هذا مفيدًا عند تنفيذ دالة استدعاء NPN. في حالة ALPN، يجب تجاهل القيمة التي تم إرجاعها في out و outlen إذا تم إرجاع OPENSSL_NPN_NO_OVERLAP من SSL_select_next_proto().

SSL_CTX_set_next_proto_select_cb() يحدد دالة استدعاء cb التي يتم استدعاؤها عندما يحتاج العميل إلى تحديد بروتوكول من قائمة الخادم المقدمة، ومعلمة مؤشر معرفة من قبل المستخدم arg والتي سيتم تمريرها إلى دالة الاستدعاء هذه. بالنسبة لدالة الاستدعاء نفسها، يجب تعيين out للإشارة إلى البروتوكول المحدد (والذي قد يكون ضمن in). يجب كتابة طول اسم البروتوكول في outlen. يتم توفير بروتوكولات الخادم المعلنة في in و inlen. يمكن لدالة الاستدعاء افتراض أن in صحيح من الناحية التركيبية. يجب على العميل تحديد بروتوكول (على الرغم من أنه قد يكون بروتوكولًا فارغًا، بطول صفر). يعد ذلك فشلًا في الاتصال إذا أعادت دالة الاستدعاء هذه قيمة أخرى غير SSL_TLSEXT_ERR_OK أو إذا تم تحديد بروتوكول بطول صفر. المعلمة arg هي المؤشر الذي تم تعيينه عبر SSL_CTX_set_next_proto_select_cb().

SSL_CTX_set_next_protos_advertised_cb() يحدد دالة استدعاء cb التي يتم استدعاؤها عندما يحتاج خادم TLS إلى قائمة بالبروتوكولات المدعومة للتفاوض على البروتوكول التالي. يجب أن تكون القائمة المرجعة بتنسيق قائمة البروتوكولات، الموضح أدناه. يتم إرجاع القائمة عن طريق تعيين out للإشارة إليها و outlen لطولها. لن يتم تعديل هذه الذاكرة، ولكن SSL تحتفظ بمرجع لها. يجب أن تعيد دالة الاستدعاء SSL_TLSEXT_ERR_OK إذا كانت ترغب في الإعلان. وإلا، فلن يتم تضمين هذا الامتداد في ServerHello.

SSL_get0_alpn_selected() ترجع مؤشرًا إلى البروتوكول المحدد في data بطول len. لا ينتهي بحرف NULL. يتم تعيين data إلى NULL و len إلى 0 إذا لم يتم تحديد أي بروتوكول. لا يجب تحرير data.

SSL_get0_next_proto_negotiated() تعين data و len للإشارة إلى البروتوكول المطلوب من العميل لهذا الاتصال. إذا لم يطلب العميل أي بروتوكول أو لم يتم تمكين NPN، فسيتم تعيين data إلى NULL و len إلى 0. لاحظ أن العميل يمكنه طلب أي بروتوكول يختاره. القيمة المرجعة من هذه الدالة لا يلزم أن تكون عضوًا في قائمة البروتوكولات المدعومة المقدمة من دالة الاستدعاء.

لا يمكن استخدام وظيفة NPN مع كائنات QUIC SSL. استخدام ALPN إلزامي عند استخدام كائنات QUIC SSL. SSL_CTX_set_next_protos_advertised_cb() و SSL_CTX_set_next_proto_select_cb() ليس لها تأثير إذا تم استدعاؤها على سياق QUIC SSL.

ملاحظات

يجب أن تكون قوائم البروتوكولات بتنسيق الأسلاك، والتي تم تعريفها كمتجه من سلاسل بايت غير فارغة، مسبوقة بطول 8 بت. لا يتم تضمين بايت بادئة الطول في الطول. كل سلسلة محدودة بـ 255 بايت. طول سلسلة البايت 0 غير صالح. سلسلة البايت المقطوعة غير صالحة. طول المتجه ليس في المتجه نفسه، ولكن في متغير منفصل.

مثال:

unsigned char vector[] = {
    6, 's', 'p', 'd', 'y', '/', '1',
    8, 'h', 't', 't', 'p', '/', '1', '.', '1'
};
unsigned int length = sizeof(vector);

يتم تنفيذ دالة استدعاء ALPN بعد دالة استدعاء اسم الخادم؛ حيث قد تقوم دالة استدعاء اسم الخادم بتحديث SSL_CTX، وبالتالي، دالة استدعاء ALPN.

إذا لم يكن هناك ALPN مقترح في ClientHello، فلن يتم استدعاء دالة استدعاء ALPN.

SSL_CTX_set_alpn_select_cb(3ssl)

NAME

SSL_CTX_set_alpn_select_cb, SSL_CTX_set_alpn_protos - set ALPN callback

SYNOPSIS

#include <openssl/ssl.h>
typedef int (*alpn_select_cb)(SSL *ssl,
                              const unsigned char **out,
                              unsigned int *outlen,
                              const unsigned char *in,
                              unsigned int inlen,
                              void *arg);
int SSL_CTX_set_alpn_select_cb(SSL_CTX *ctx,
                               alpn_select_cb cb,
                               void *arg);
int SSL_CTX_set_alpn_protos(SSL_CTX *ctx,
                            const unsigned char *protos,
                            unsigned int protoslen);

DESCRIPTION

The ALPN (Application-Layer Protocol Negotiation) extension allows the client and server to negotiate which application protocol to use over the TLS connection. See RFC 7636 for more details.

A server can use the callback function set by SSL_CTX_set_alpn_select_cb() to select an application protocol from the list advertised by the client in the ALPN extension. The callback cb is invoked when the ALPN extension is processed.

The callback cb is called with the following arguments:

SSL *ssl
The SSL object.
const unsigned char **out
A pointer to a pointer where the selected protocol should be written. The memory pointed to must be valid for the lifetime of the connection. The callback is responsible for allocating this memory.
unsigned int *outlen
A pointer to the length of the selected protocol.
const unsigned char *in
A pointer to the buffer containing the list of protocols advertised by the client. The buffer is null-terminated.
unsigned int inlen
The length of the client's advertised protocols.
void *arg
The arbitrary argument passed to SSL_CTX_set_alpn_select_cb().

The server advertises the protocols it supports using SSL_CTX_set_alpn_protos(). This function takes a null-separated list of protocol strings in protos and its length protoslen. This list is included in the ALPN extension in the ServerHello message.

If SSL_CTX_set_alpn_protos() is not called, then no ALPN extension is sent by the server.

NOTES

The callback cb must select a protocol from the client's list and set *out and *outlen accordingly. The selected protocol must be present in the list set by SSL_CTX_set_alpn_protos(). If no protocol can be selected, the callback should indicate this by returning an appropriate error code.

The client can be configured to use ALPN by setting the ALPN extension using SSL_set_alpn_protos().

RETURN VALUES

SSL_CTX_set_alpn_select_cb() and SSL_CTX_set_alpn_protos() return 1 on success, and 0 on failure.

The ALPN select callback cb, must return one of the following:

SSL_TLSEXT_ERR_OK
ALPN protocol selected.
SSL_TLSEXT_ERR_ALERT_FATAL
There was no overlap between the client's supplied list and the server configuration.
SSL_TLSEXT_ERR_NOACK
ALPN protocol not selected, e.g., because no ALPN protocols are configured for this connection.

The callback set using SSL_CTX_set_next_proto_select_cb() should return SSL_TLSEXT_ERR_OK if successful. Any other value is fatal to the connection.

The callback set using SSL_CTX_set_next_protos_advertised_cb() should return SSL_TLSEXT_ERR_OK if it wishes to advertise. Otherwise, no such extension will be included in the ServerHello.

SEE ALSO

ssl(7), SSL_CTX_set_tlsext_servername_callback(3), SSL_CTX_set_tlsext_servername_arg(3)

الاسم

SSL_CTX_set_alpn_select_cb, SSL_CTX_set_alpn_protos - تعيين رد اتصال ALPN

الملخص

#include <openssl/ssl.h>
typedef int (*alpn_select_cb)(SSL *ssl,
                              const unsigned char **out,
                              unsigned int *outlen,
                              const unsigned char *in,
                              unsigned int inlen,
                              void *arg);
int SSL_CTX_set_alpn_select_cb(SSL_CTX *ctx,
                               alpn_select_cb cb,
                               void *arg);
int SSL_CTX_set_alpn_protos(SSL_CTX *ctx,
                            const unsigned char *protos,
                            unsigned int protoslen);

الوصف

تسمح امتداد ALPN (التفاوض على بروتوكول طبقة التطبيق) للعميل والخادم بالتفاوض على بروتوكول التطبيق الذي سيتم استخدامه عبر اتصال TLS. راجع RFC 7636 لمزيد من التفاصيل.

يمكن للخادم استخدام دالة رد الاتصال المعينة بواسطة SSL_CTX_set_alpn_select_cb() لاختيار بروتوكول تطبيق من القائمة المعلن عنها بواسطة العميل في امتداد ALPN. يتم استدعاء رد الاتصال cb عند معالجة امتداد ALPN.

يتم استدعاء رد الاتصال cb مع الوسائط التالية:

SSL *ssl
كائن SSL.
const unsigned char **out
مؤشر إلى مؤشر حيث يجب كتابة البروتوكول المحدد. يجب أن تكون الذاكرة المشار إليها صالحة طوال مدة الاتصال. يكون رد الاتصال مسؤولاً عن تخصيص هذه الذاكرة.
unsigned int *outlen
مؤشر إلى طول البروتوكول المحدد.
const unsigned char *in
مؤشر إلى المخزن المؤقت الذي يحتوي على قائمة البروتوكولات المعلنة بواسطة العميل. المخزن المؤقت ينتهي بـ null.
unsigned int inlen
طول بروتوكولات العميل المعلنة.
void *arg
الوسيط العشوائي الذي تم تمريره إلى SSL_CTX_set_alpn_select_cb().

يعلن الخادم عن البروتوكولات التي يدعمها باستخدام SSL_CTX_set_alpn_protos(). تأخذ هذه الدالة قائمة بفصلها عن طريق null لسلاسل البروتوكول في protos وطولها protoslen. يتم تضمين هذه القائمة في امتداد ALPN في رسالة ServerHello.

إذا لم يتم استدعاء SSL_CTX_set_alpn_protos()، فلن يتم إرسال امتداد ALPN بواسطة الخادم.

ملاحظات

يجب على رد الاتصال cb تحديد بروتوكول من قائمة العميل وتعيين *out و *outlen وفقًا لذلك. يجب أن يكون البروتوكول المحدد موجودًا في القائمة المعينة بواسطة SSL_CTX_set_alpn_protos(). إذا لم يكن من الممكن تحديد بروتوكول، فيجب على رد الاتصال الإشارة إلى ذلك عن طريق إرجاع رمز خطأ مناسب.

يمكن تكوين العميل لاستخدام ALPN عن طريق تعيين امتداد ALPN باستخدام SSL_set_alpn_protos().

قيم الإرجاع

SSL_CTX_set_alpn_select_cb() و SSL_CTX_set_alpn_protos() ترجع 1 عند النجاح، و 0 عند الفشل.

يجب أن يرجع رد اتصال ALPN select cb أحد القيم التالية:

SSL_TLSEXT_ERR_OK
تم تحديد بروتوكول ALPN.
SSL_TLSEXT_ERR_ALERT_FATAL
لم يكن هناك تداخل بين القائمة المقدمة من العميل وتكوين الخادم.
SSL_TLSEXT_ERR_NOACK
لم يتم تحديد بروتوكول ALPN، على سبيل المثال، لأنه لا توجد بروتوكولات ALPN مهيأة لهذا الاتصال.

يجب أن يرجع رد الاتصال المعين باستخدام SSL_CTX_set_next_proto_select_cb() SSL_TLSEXT_ERR_OK في حالة النجاح. أي قيمة أخرى ستكون قاتلة للاتصال.

يجب أن يرجع رد الاتصال المعين باستخدام SSL_CTX_set_next_protos_advertised_cb() SSL_TLSEXT_ERR_OK إذا رغب في الإعلان. بخلاف ذلك، لن يتم تضمين أي امتداد من هذا القبيل في ServerHello.
