الاسم

sshguard-setup - إعداد SSHGuard على نظامك

الوصف

لإعداد SSHGuard، اكتب sshguard.conf وأنشئ الواجهة الخلفية (backend) إذا لزم الأمر. خيارات التكوين موثقة في ملف التكوين النموذجي. نقطة انطلاق جيدة هي نسخه وإجراء التغييرات اللازمة:

1.
عيّن BACKEND. قد تحتاج أيضًا إلى إعداده للعمل مع SSHGuard (انظر BACKENDS).
2.
عيّن FILES، LOGREADER، أو كليهما. بدلاً من ذلك، امنح sshguard قائمة بالملفات لمراقبتها كمعاملات موضعية في سطر الأوامر.

استخدم FILES لتحديد قائمة مفصولة بمسافات من ملفات السجل لمراقبتها. استخدم LOGREADER لتحديد أمر shell ليتم تشغيله للحصول على السجلات. يتم تجاهل كلا الإعدادين إذا تم توفير الملفات في سطر الأوامر.

أوامر LOGREADER النموذجية لـ journalctl(1) و macOS 10.12+ متوفرة في ملف التكوين النموذجي.

سجلات أخرى

syslog-ng

بالنسبة لـ syslog-ng 2.x، أضف الأسطر التالية إلى syslog-ng.conf:

# تمرير الإدخالات فقط التي تحتوي على مرافق auth+authpriv من برامج غير sshguard
filter sshlogs { facility(auth, authpriv) and not match("sshguard"); };
# تمرير إلى هذه العملية بهذا القالب (يتجنب بادئات &lt;ID&gt;)
destination sshguardproc {
program("/usr/local/sbin/sshguard"
template("$DATE $FULLHOST $MESSAGE\n"));
};
log { source(src); filter(sshlogs); destination(sshguardproc); };

بالنسبة لـ syslog-ng 3.x، أضف الأسطر التالية إلى syslog-ng.conf:

# تمكين وضع 3.x
@version:3.0
# تمرير الإدخالات فقط التي تحتوي على مرافق auth+authpriv من برامج غير sshguard
filter f_sshguard { facility(auth, authpriv) and not program("sshguard"); };
# تمرير الإدخالات المبنية بهذا التنسيق
destination sshguard {
program("/usr/sbin/sshguard"
template("$DATE $FULLHOST $MSGHDR$MESSAGE\n")
);
};
log { source(src); filter(f_sshguard); destination(sshguard); };

بعد إعادة تشغيل syslog-ng، يجب أن يبدأ SSHGuard بمجرد وصول إدخال سجل بالمرفق auth أو authpriv. إذا كنت تراقب خدمات أخرى غير sshd، أضف مرافق السجل المناسبة إلى syslog-ng.conf.

metalog

أضف الأسطر التالية إلى metalog.conf:

Stuff to protect from brute force attacks :
    # for ssh
    facility = "*"
    program = "sshd"
    # other services ...
    # log to /var/log/sshguard directory
    logdir = "/var/log/sshguard"

بعد إعادة تشغيل metalog، ستظهر إدخالات السجل في /var/log/sshguard. استخدم log polling لمراقبة السجل الحالي.

الواجهات الخلفية

يمكن لـ SSHGuard حظر المهاجمين باستخدام إحدى واجهات جدار الحماية الخلفية المتعددة التي يتم اختيارها وقت الترجمة.

تحذير:

اقرأ وثائق جدار الحماية الخاص بك. تأكد من فهمك الكامل لكل قاعدة أو أمر في الأمثلة أدناه قبل استخدامها. قد تحتاج إلى تعديلها لتناسب تكوينك الخاص.

pf

يضيف SSHGuard المهاجمين إلى الجدول <sshguard>. قم بإنشاء الجدول وحظر المهاجمين عن طريق إضافة الأسطر التالية إلى نهاية pf.conf:

table <sshguard> persist
block in proto tcp from <sshguard>

بعد إعادة تحميل تكوين pf، يمكنك فحص محتويات الجدول باستخدام:

# pfctl -t sshguard -T show

ipfw

يقوم SSHGuard بإنشاء وإضافة المهاجمين إلى الجدول 22. يمكن استخدام الجدول لحظر المهاجمين في مجموعة القواعد الخاصة بك. على سبيل المثال:

# ipfw add 5000 reset ip from table\(22\) to me

يمكنك فحص محتويات الجدول باستخدام:

# ipfw table 22 list

firewalld

يتم إضافة المهاجمين المحظورين إلى مجموعتي ipsets باسم sshguard4 و sshguard6. يتم حظر الإدخالات في ipsets افتراضيًا في منطقة جدار الحماية الافتراضية. يمكن تكوين مناطق جدار حماية إضافية باستخدام:

# firewall-cmd --zone=zone-name --permanent \
    --add-rich-rule="rule source ipset=sshguard4 drop"
# firewall-cmd --zone=zone-name --permanent \
    --add-rich-rule="rule source ipset=sshguard6 drop"

يمكنك فحص الإدخالات في مجموعتي ipsets باستخدام:

# firewall-cmd --permanent --info-ipset=sshguard4
# firewall-cmd --permanent --info-ipset=sshguard6

ipset

يتم إضافة المهاجمين المحظورين إلى مجموعتي ipsets باسم sshguard4 و sshguard6. لا يتم حظر أي شيء افتراضيًا، ولكن يمكن استخدامه كمصدر لـ iptables وأدوات أخرى. مثال:

# iptables  -I INPUT -m set --match-set sshguard4 src -j DROP
# ip6tables -I INPUT -m set --match-set sshguard6 src -j DROP

netfilter/iptables

قم بإنشاء سلسلة لـ SSHGuard:

# iptables -N sshguard      # لـ IPv4
# ip6tables -N sshguard     # لـ IPv6

قم بتحديث سلسلة INPUT لتمرير حركة المرور أيضًا إلى سلسلة sshguard في نهاية معالجتها تمامًا. حدد في --dport جميع منافذ الخدمات التي يحميها sshguard. إذا كنت ترغب في منع المهاجمين من القيام بأي حركة مرور إلى المضيف، فقم بإزالة الخيار تمامًا:

# حظر أي حركة مرور من المسيئين
iptables -A INPUT -j sshguard
ip6tables -A INPUT -j sshguard

أو:

# حظر المسيئين فقط لخدمات SSH، FTP، POP، IMAP (استخدم وحدة "multiport")
iptables -A INPUT -m multiport -p tcp --destination-ports 21,22,110,143 -j sshguard
ip6tables -A INPUT -m multiport -p tcp --destination-ports 21,22,110,143 -j sshguard

تحقق من عدم وجود قاعدة سماح افتراضية تمرر كل حركة مرور SSH أعلى في السلسلة. تحقق من عدم وجود قاعدة حظر افتراضية تمنع كل حركة مرور SSH في جدار الحماية الخاص بك. في كلتا الحالتين، لديك بالفعل المهارة لتعديل إعداد جدار الحماية الخاص بك.

إليك مجموعة قواعد نموذجية منطقية:

iptables -N sshguard
# حظر ما يقوله SSHGuard أنه سيء ...
iptables -A INPUT -j sshguard
# تمكين SSH، DNS، HTTP، HTTPS
iptables -A INPUT -p tcp --dport 22 -j ACCEPT
iptables -A INPUT -p udp --dport 53 -j ACCEPT
iptables -A INPUT -p tcp --dport 80 -j ACCEPT
iptables -A INPUT -p tcp --dport 443 -j ACCEPT
# وحظر كل شيء آخر (رفض افتراضي)
iptables -P INPUT DROP

عند إعادة التشغيل، تقوم معظم الأنظمة بإعادة تعيين تكوين جدار الحماية افتراضيًا. للحفاظ على تكوينك، عادةً ما تستخدم الأدوات iptables-save و iptables-restore. ومع ذلك، كل توزيع Linux له "طريقته الصحيحة".

nftables

يقوم SSHGuard بإنشاء جداول ذات أولوية عالية ويضيف المهاجمين إلى مجموعة تلقائيًا.

يمكنك فحص محتويات المجموعات باستخدام:

# nft list set ip sshguard attackers
# nft list set ip6 sshguard attackers

علاوة على ذلك، يمكنك عرض جداول sshguard باستخدام:

# nft list table ip sshguard
# nft list table ip6 sshguard

استكشاف الأخطاء وإصلاحها

استكشاف الأخطاء وإصلاحها

هل تم تكوين SSHGuard بشكل صحيح؟

تحقق من أن FILES (أو LOGREADER) و BACKEND الصحيحين تم تعيينهما في sshguard.conf.

هل يعمل SSHGuard؟

يقوم SSHGuard بتشغيل سلسلة من العمليات المتعاونة. يمكنك التحقق من بدء تشغيل SSHGuard بشكل صحيح عن طريق عرض قائمة العمليات الخاصة بك باستخدام ps أو top. تُظهر هنا العمليات المرتبطة بتكوين مثال:

/bin/sh /opt/sshguard/sbin/sshguard
tail -F -n 0 /tmp/log.txt
/opt/sshguard/libexec/sshg-parser
/opt/sshguard/libexec/sshg-blocker -a 30 -p 120 -s 1800 -N 128 -n 32
/bin/sh /usr/local/libexec/sshg-fw-null

بالترتيب:

  • SSHGuard، المثبت في /opt/sshguard، يتم تفسيره بواسطة /bin/sh.
  • قام SSHGuard بتشغيل tail -F -n 0، والذي يراقب /tmp/log.txt.
  • محلل الهجمات الافتراضي sshg-parser يعمل.
  • برنامج الحظر يعمل بالخيارات -a 30 -p 120 -s 1800 -N 128 -n 32.
  • جدار الحماية sshg-fw-null يعمل. الواجهة الخلفية الفارغة (null backend) لا تمنع أي هجمات فعليًا.

هل يتعرف SSHGuard على الهجمات؟

يتعرف SSHGuard على الهجمات عن طريق تحليل رسائل السجل. يمكن أن يتغير تنسيق رسائل السجل بشكل عرضي. إذا كنت تستخدم محلل الهجمات الافتراضي المدمج، يمكنك التحقق مما إذا كان SSHGuard يتعرف على هجماتك عن طريق تشغيل:

$ cat /var/log/auth.log | %PREFIX%/libexec/sshg-parser -a

رسائل السجل التي يتم التعرف عليها كهجمات مسبوقة بعلامة '*' في بداية كل سطر. إذا لم يتم التعرف على رسالة سجل كان ينبغي التعرف عليها كهجوم، ففكر في الإبلاغ عنها.

أمثلة

تجاهل FILES وراقب هذه الملفات بدلاً من ذلك:

# sshguard /var/log/auth.log /var/log/maillog
