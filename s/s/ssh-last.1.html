ssh-last(1)

الحزمة: ssh-tools

التراخيص: GPL-3.0-only

SSH-LAST(1) أوامر المستخدم SSH-LAST(1)

الاسم

ssh-last - عرض آخر جلسات SSH

المُلَخَّص

           ssh-last [خيارات]
ssh_logs | ssh-last [خيارات]

خيارات

-a  عرض جميع الجلسات                           (عرض البيانات التي تم إخفاؤها بواسطة ملف 'ignored')
-c  إخراج ملون                               (تمييز جلسات SSH النشطة)
-d  تصحيح الأخطاء
-f  فرض عرض البصمات                          (لا يوجد تعيين من ملف 'known')
-h  عرض رسالة المساعدة هذه
-i  فرض عرض معرفات الشهادات                   (لا يوجد تعيين من ملف 'known'، ليس مع -f)
-l  محاولة استخدام ملفات السجل بدلاً من journalctl  (قد يكون أسرع على بعض الأنظمة)
-n  عرض المضيف/IP كنص عادي                     (لا يوجد تعيين من ملف 'known')
-w  عرض جلسات SSH النشطة فقط
-?  عرض الدليل الكامل بمعلومات أكثر تفصيلاً
    (عادة ما يتطلب تثبيت perl-doc ليعمل بشكل صحيح)
--version    عرض معلومات الإصدار

أمثلة

ssh-last
ssh-last -c | more
ssh-last -c | less -R   # يحافظ على الإخراج الملون في less
ssh-last -cw
# سجلات الأمس
LC_TIME=C journalctl _COMM=sshd -g 'Accepted|Disconnected' --since yesterday               | ssh-last
# سجلات قبل ثلاثة أيام
LC_TIME=C journalctl _COMM=sshd -g 'Accepted|Disconnected' --since -3d --until -2d         | ssh-last
# سجلات الساعة الأخيرة
LC_TIME=C journalctl _COMM=sshd -g 'Accepted|Disconnected' --since -1h                     | ssh-last
# سجلات حتى تاريخ محدد
LC_TIME=C journalctl _COMM=sshd -g 'Accepted|Disconnected' --until "2022-03-12 07:00:00"   | ssh-last
# من ملفات السجل (يجب أن يكون الترتيب من الأقدم إلى الأحدث)
zgrep -hE 'Accepted|Disconnected' auth.log.2.gz  auth.log.1  auth.log                      | ssh-last
zgrep -hE 'Accepted|Disconnected' $(ls /var/log/auth.log* --sort=time --reverse)           | ssh-last
zgrep -hE 'Accepted|Disconnected' $(ls /var/log/messages* --sort=time --reverse)           | ssh-last
zgrep -hE 'Accepted|Disconnected' $(ls /var/log/secure*   --sort=time --reverse)           | ssh-last

الوصف

ssh-last يشبه last ولكنه مخصص لجلسات SSH

علامات الإخراج

+--------------------------------------------------------------------------+
|                                                                          |
| AUTH_ID                                                                  |
|                                                                          |
| (C) تم المصادقة على تسجيل دخول sshd عبر (c)ertificate (شهادة)            |
| (K) تم المصادقة على تسجيل دخول sshd عبر المفتاح (k)ey العام              |
| (?) تم المصادقة على تسجيل دخول sshd عبر نوع آخر (كلمة مرور، pam)       |
|                                                                          |
+--------------------------------------------------------------------------+

الخوارزمية

التنقل عبر سجلات sshd بترتيب زمني:
1) البحث عن سطور تسجيل الدخول (Accepted) وتسجيل الخروج (Disconnected).
2) تخزين المعلومات من السطور مثل اسم المستخدم، نوع المصادقة، البصمة، ...
3) استخدام المنفذ الشبكي المستخدم للتحقق من الجلسات النشطة
   وتجميع الجلسات القديمة عن طريق تذكر منافذ الشبكة التي تم تسجيلها
4) استخدام /etc/os-release بشكل أساسي للتكيف مع الأنظمة المختلفة
   التي تختلف في أسماء ملفات السجل، وأنماط التسجيل، إلخ...

أخطاء وحدود

مضيفو القفز

استخدام مضيف قفز مع ProxyCommand أو ProxyJump،
غالباً ما يؤدي إلى قطع غير نظيف مع عدم تسجيل أي شيء،
لذلك لا يمكن عرض LOGOUT (تسجيل الخروج) و DURATION (المدة).

المستخدمون غير المميزين

إذا أمكن، قم بتشغيل ssh-last كـ root أو عبر sudo
1) عادةً لا يمكن للمستخدم العادي قراءة ملفات السجل ومجلة systemd
2) ssh-last -w يعمل بشكل موثوق فقط كـ root،
   لأن ss و netstat لا تعرضان معلومات العملية عند استدعائهما كمستخدم عادي
3) يحاول ssh-last تعيين البصمة من ملف authorized_keys الخاص بالمستخدم
   ولكن عادةً لا يُسمح للمستخدمين بالاطلاع على ملفات بعضهم البعض

ترقيات نظام التشغيل

إذا قمت بترقية في المكان مثل dist-upgrade على Debian/Ubuntu،
اعتمادًا على فرق الإصدار،
يمكن أن يحدث أن يسجل sshd بشكل مختلف من تلك النقطة فصاعدًا
وقد يكون لديك مزيج من السجلات بالتنسيق الجديد والقديم
مما يؤدي إلى عرض ssh-last للأحدث فقط بشكل صحيح

عدم اتساق السجلات

لقد رأيت حالات تم فيها فقدان بعض رسائل سجل "Disconnect" الخاصة بـ sshd
في مجلة systemd ولكنها موجودة في /var/log/auth.log.
لذلك، إذا لم يعرض ssh-last تسجيل الخروج والمدة
ولكن سطور السجل موجودة في ملف السجل، تحقق مما إذا كانت رسالة السجل
قد وصلت بالفعل إلى مجلة systemd نظرًا لأن ssh-last يستخدم journald افتراضيًا

SCRIPTS

For convenience you can create little wrapper scripts like the following which avoids parsing too many logs by limiting the data only to the last week

my-ssh-last
+--------------------------------------------------------------------------+
| #!/usr/bin/env bash                                                      |
|                                                                          |
| LC_TIME=C journalctl _COMM=sshd --since -1week \                         |
| | grep -E 'Accepted|Disconnected'              \                         |
| | ssh-last "$@"                                                          |
|                                                                          |
+--------------------------------------------------------------------------+
