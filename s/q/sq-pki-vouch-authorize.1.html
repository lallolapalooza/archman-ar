sq-pki-vouch-authorize(1)

الحزمة: sequoia-sq

التراخيص: LGPL-2.0-or-later

SQ(1) أوامر المستخدم SQ(1)

الاسم

sq-pki-vouch-authorize - ضع علامة على شهادة كمقدم موثوق

النبذة

sq pki vouch authorize [خيارات]

الوصف

ضع علامة على شهادة كمقدم موثوق.

ينشئ شهادة تقول إن المُصدر يعتبر الشهادة مقدمًا موثوقًا. مقدم موثوق هو مصطلح آخر للسلطة المانحة للشهادات (CA). عندما يعتمد مستخدم على مقدم موثوق، يعتبر المستخدم الشهادات التي أصدرتها السلطة المانحة للشهادات صالحة. يمكن لمقدم موثوق أيضًا تعيين مقدمين موثوقين إضافيين.

كما هي، تتمتع السلطة المانحة للشهادات بقدر كبير من السلطة. يمكن تقييد هذه السلطة بعدة طرق.


- يمكن تقييد القدرة على تحديد مقدمين إضافيين باستخدام المعلمة `--depth`.


- يمكن تغيير درجة الثقة في المقدم باستخدام المعلمة `--amount`.


- يمكن تقييد معرفات المستخدم التي يمكن للسلطة المانحة للشهادات التصديق عليها حسب المجال باستخدام المعلمة `--domain` أو باستخدام تعبير عادي باستخدام المعلمة `--regex`.

تسمح هذه الآليات لـ Alice بالقول إنها على استعداد للاعتماد على CA، على سبيل المثال، `example.org`، ولكن فقط لمعرفات المستخدم التي لديها عنوان بريد إلكتروني لـ `example.org`، على سبيل المثال.

افتراضيًا، تنتهي صلاحية التفويض بعد 10 سنوات. استخدم الوسيطة `--expiration` لتجاوز هذا.

هذا الأمر الفرعي يحترم الوقت المرجعي المحدد بواسطة الوسيطة العلنية `--time`. يقوم بتعيين وقت إنشاء الشهادة إلى الوقت المرجعي.

خيارات

خيارات الأمر الفرعي

--add-email=EMAIL
استخدم معرف مستخدم بعنوان البريد الإلكتروني المحدد
يتكون معرف المستخدم من عنوان البريد الإلكتروني فقط. لا يلزم أن يظهر عنوان البريد الإلكتروني في معرف مستخدم موقع ذاتيًا.
--add-userid=USERID
استخدم معرف المستخدم المحدد
لا يلزم أن يكون معرف المستخدم المحدد موقعًا ذاتيًا.
نظرًا لأن استخدام معرف مستخدم غير موقع ذاتيًا غالبًا ما يكون خطأ، فأنت بحاجة إلى استخدام هذا الخيار للموافقة الصريحة.
--all
استخدم جميع معرفات المستخدمين الموقعين ذاتيًا
--allow-non-canonical-userids
لا ترفض معرفات المستخدمين الجديدة التي ليست في شكل قياسي
معرفات المستخدم القياسية تكون على شكل `Name (Comment) <localpart@example.org>`.
--amount=AMOUNT
اضبط مقدار الثقة
القيم بين 1 و 120 لها معنى. 120 يعني ثقة كاملة. القيم الأقل من 120 تشير إلى درجة الثقة. عادة ما يتم استخدام 60 للثقة الجزئية.
[الافتراضي: full]
--cert=FINGERPRINT|KEYID
استخدم الشهادات ببصمة الإصبع أو معرف المفتاح المحدد
--cert-file=PATH
اقرأ الشهادات من المسار
--certifier=FINGERPRINT|KEYID
قم بإنشاء الشهادة باستخدام المفتاح ببصمة الإصبع أو معرف المفتاح المحدد
--certifier-email=EMAIL
قم بإنشاء الشهادة باستخدام المفتاح حيث يتضمن معرف المستخدم عنوان البريد الإلكتروني المحدد
--certifier-file=PATH
قم بإنشاء الشهادة باستخدام المفتاح المقروء من المسار
--certifier-self
قم بإنشاء الشهادة باستخدام مفتاح الشهادة الافتراضي الخاص بك
يستخدم هذا الشهادات المحددة في ملف التكوين تحت `pki.vouch.certifier-self` كمفتاح شهادة.
حاليًا، لا يوجد مفتاح شهادة افتراضي.
--certifier-userid=USERID
قم بإنشاء الشهادة باستخدام المفتاح بمعرف المستخدم المحدد
--depth=TRUST_DEPTH
اضبط عمق الثقة
يشار إلى هذا أحيانًا باسم مستوى الثقة. 1 يعني أن الشهادة هي مقدم موثوق (الافتراضي)، 2 يعني أن الشهادة هي مقدم موثوق ميتا ويمكنها التصديق على مقدم موثوق آخر، إلخ.
[الافتراضي: 1]
--domain=DOMAIN
أضف قيد مجال للمقدم
أضف مجالًا لتقييد الشهادات التي يتم الوثوق بها. لا يتم الوثوق بالشهادة الصادرة عن الشهادة إلا إذا كانت تتعلق بمعرف مستخدم بعنوان بريد إلكتروني في المجال المحدد. يمكن تحديد مجالات متعددة. في هذه الحالة، يجب أن يكون هناك تطابق واحد.
--email=EMAIL
استخدم معرف مستخدم يتكون فقط من عنوان البريد الإلكتروني، إذا كان عنوان البريد الإلكتروني يظهر في معرف مستخدم موقع ذاتيًا
--expiration=EXPIRATION
يحدد وقت انتهاء الصلاحية
EXPIRATION هو إما تاريخ بتنسيق ISO 8601 مع وقت اختياري أو مدة مخصصة. تأخذ المدة شكل `N[ymwds]`، حيث الأحرف تمثل السنوات والأشهر والأسابيع والأيام والثواني، على التوالي. بدلاً من ذلك، الكلمة المفتاحية `never` لا تحدد وقت انتهاء الصلاحية.
يمكن تغيير الإعداد الافتراضي في ملف التكوين باستخدام الإعداد `pki.vouch.expiration`.
[الافتراضي: 10y]
--local
اجعل الشهادة شهادة محلية
عادةً، لا يتم تصدير الشهادات المحلية.
--non-revocable
ضع علامة على الشهادة على أنها غير قابلة للإلغاء
وهذا يعني أنه لا يمكنك لاحقًا إلغاء هذه الشهادة. يجب عادةً استخدام هذا مع تاريخ انتهاء صلاحية.
--output=FILE
اكتب إلى الملف أو إلى الإخراج القياسي إذا تم حذفه
--regex=REGEX
أضف تعبيرًا عاديًا لتقييد المقدم
أضف تعبيرًا عاديًا لتقييد الشهادات التي يتم الوثوق بها. لا يتم الوثوق بالشهادة الصادرة عن الشهادة إلا إذا كانت تتعلق بمعرف مستخدم يتطابق مع أحد التعبيرات العادية المحددة. يمكن تحديد تعبيرات عادية متعددة. في هذه الحالة، يجب أن يكون هناك تطابق واحد على الأقل.
--signature-notation NAME VALUE
أضف ملاحظة إلى التوقيع
يجب أن يكون اسم الملاحظة المعرفة من قبل المستخدم على شكل `name@a.domain.you.control.org`. إذا كان اسم الملاحظة يبدأ بـ `!`, فعندئذ يتم تمييز الملاحظة على أنها حرجة. إذا لم يفهم المستهلك للتوقيع ملاحظة حرجة، فسيقوم بتجاهل التوقيع. يتم تمييز الملاحظة على أنها قابلة للقراءة من قبل الإنسان.
--unconstrained
لا تقيد المقدم
عادةً ما يتم تقييد المقدم بحيث لا يتم الوثوق إلا بمعرفات مستخدم معينة، على سبيل المثال، تلك التي لديها عنوان بريد إلكتروني لمجال معين. هذا الخيار يصرح لمقدم دون تقييده بهذه الطريقة. نظرًا لأن هذا يمنح المقدم قدرًا كبيرًا من السلطة، يجب عليك الموافقة صراحةً على هذا السلوك.
--userid=USERID
استخدم معرف المستخدم المحدد الموقع ذاتيًا

sq-pki-vouch-authorize(1) — Sequoia PGP

NAME

sq-pki-vouch-authorize - authorize a user ID as a trusted introducer

SYNOPSIS

sq pki vouch authorize [ --certifier=CERTIFIER ] [ --cert=CERT ] [ --domain=DOMAIN ] [ --user-id=USERID ] [ --all ] [ -h | --help ] [ -V | --version ]

DESCRIPTION

This subcommand creates a vouch for a user ID for a given domain. A vouch is an assertion that a user ID is a trusted introducer for a domain. A vouch is signed by the user ID of the certifier. The certifier must have the appropriate key in its keyring.

If --all is passed, then the vouch is valid for all domains listed in the certificates.

OPTIONS

--certifier=CERTIFIER
The fingerprint of the certifier's self-signed user ID.
--cert=CERT
The fingerprint of the user ID to be vouched for.
--domain=DOMAIN
The domain for which the user ID is a trusted introducer.
--user-id=USERID
The user ID of the certifier. This is used when the certifier has multiple user IDs. If not specified, the default user ID is used.
--all
Vouch for the user ID for all domains associated with the certificate.
-h, --help
Print help information and exit.
-V, --version
Print program version and exit.

The specified user ID must be self signed.

--userid-by-email=EMAIL
Use the self-signed user ID with the specified email address

Global options

See sq(1) for a description of the global options.

EXAMPLES

Certify that E7FC51AD886BBB5C4F44C3D7A9DA14F3E740F63F is a trusted introducer for example.org and example.com.

sq pki vouch authorize \
    --certifier=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
    --cert=E7FC51AD886BBB5C4F44C3D7A9DA14F3E740F63F \
    --domain=example.org --domain=example.com --all
