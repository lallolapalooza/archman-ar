sq-key-rotate(1)

الحزمة: sequoia-sq

التراخيص: LGPL-2.0-or-later

NAME

sq-key-rotate — rotate a secret key

SYNOPSIS

sq-key-rotate [‑]h

sq-key-rotate [‑]V

sq-key-rotate ‑o ‑p ‑e ‑k ‑n ‑t [‑]G ‑f ‑a ‑s ‑S

DESCRIPTION

This command generates a new secret key, using the given key OPTIONS, and signs it. The old key is signed by the new key. The resulting key bundle is written to stdout.

Note that this command is deprecated and is kept for compatibility. sq(1) may be used instead.

OPTIONS

The command requires the following arguments:

‑o old-key
Path to the old secret key.
‑p old-key-passphrase
Passphrase of the old secret key. If not given, it is prompted for.
‑e curve
Elliptic curve to use for the new key. Allowed values: ed25519 and secp256k1.
‑k key-size
Key size in bits for the new key. If the curve is ed25519 or secp256k1, this is ignored.
‑n new-key-passphrase
Passphrase for the new key. If not given, it is prompted for.
‑t new-key-type
Type of the new key. Allowed values: ed25519, nistp256, nistp384, and nistp521.
‑G old-key-subkey-id
The key ID of the subkey of the old key that should be signed.
‑f output-file
File to write the new key to. If not given, it is written to stdout.
‑a user-id
User ID to add to the new key.
‑s signature-expiration
Expiration date of the signature. This is a string that is parsed by date(1).
‑S signature-subpackets
A comma-separated list of signature subpacket settings.

Optional arguments:

‑h
Print help message and exit.
‑V
Print program version and exit.

EXAMPLES

Generate a new Ed25519 key and sign it with the old key:

$ sq-key-rotate -o old.key -p 123456 -e ed25519 -n 654321 -t ed25519 -a "Test User <test@example.com>" -f new.key

SEE ALSO

sq(1), sq-key-generate(1), sq-key-sign(1)

For the full documentation see https://book.sequoia-pgp.org/.

الاسم

sq-key-rotate — تدوير مفتاح سري

الملخص

sq-key-rotate [‑]h

sq-key-rotate [‑]V

sq-key-rotate ‑o ‑p ‑e ‑k ‑n ‑t [‑]G ‑f ‑a ‑s ‑S

الوصف

يقوم هذا الأمر بإنشاء مفتاح سري جديد، باستخدام خيارات المفتاح المعطاة، وتوقيعه. يتم توقيع المفتاح القديم بواسطة المفتاح الجديد. يتم كتابة حزمة المفاتيح الناتجة إلى الإخراج القياسي.

لاحظ أن هذا الأمر مهمل ويتم الاحتفاظ به للتوافق. يمكن استخدام sq(1) بدلاً منه.

خيارات

يتطلب الأمر الوسائط التالية:

‑o old-key
مسار المفتاح السري القديم.
‑p old-key-passphrase
عبارة مرور المفتاح السري القديم. إذا لم يتم تقديمها، فسيتم الاستعلام عنها.
‑e curve
المنحنى الإهليلجي لاستخدامه للمفتاح الجديد. القيم المسموح بها: ed25519 و secp256k1.
‑k key-size
حجم المفتاح بالبتات للمفتاح الجديد. إذا كان المنحنى ed25519 أو secp256k1، فسيتم تجاهل هذا.
‑n new-key-passphrase
عبارة مرور المفتاح الجديد. إذا لم يتم تقديمها، فسيتم الاستعلام عنها.
‑t new-key-type
نوع المفتاح الجديد. القيم المسموح بها: ed25519، nistp256، nistp384، و nistp521.
‑G old-key-subkey-id
معرف المفتاح الفرعي للمفتاح القديم الذي يجب توقيعه.
‑f output-file
الملف الذي سيتم كتابة المفتاح الجديد إليه. إذا لم يتم تقديمه، فسيتم كتابته إلى الإخراج القياسي.
‑a user-id
معرف المستخدم لإضافته إلى المفتاح الجديد.
‑s signature-expiration
تاريخ انتهاء صلاحية التوقيع. هذه سلسلة نصية يتم تحليلها بواسطة date(1).
‑S signature-subpackets
قائمة مفصولة بفواصل لإعدادات حزم التوقيع الفرعية.

الوسائط الاختيارية:

‑h
عرض رسالة المساعدة والخروج.
‑V
عرض إصدار البرنامج والخروج.

أمثلة

إنشاء مفتاح Ed25519 جديد وتوقيعه بالمفتاح القديم:

$ sq-key-rotate -o old.key -p 123456 -e ed25519 -n 654321 -t ed25519 -a "Test User <test@example.com>" -f new.key
