NAME

sq-pki-link-authorize - Make a certificate a trusted introducer

SYNOPSIS

sq pki link authorize [OPTIONS]

DESCRIPTION

Make a certificate a trusted introducer.

This causes `sq` to consider the certificate to be a be a trusted introducer. Trusted introducer is another word for certification authority (CA). When you link a trusted introducer, you consider certifications made by the trusted introducer to be valid. A trusted introducer can also designate further trusted introducers.

As is, a trusted introducer has a lot of power. This power can be limited in several ways.


- The ability to specify further introducers can be constrained using the `--depth` parameter.


- The degree to which an introducer is trusted can be changed using the `--amount` parameter.


- The user IDs that an introducer can certify can be constrained by domain using the `--domain` parameter or a regular expression using the `--regex` parameter.

These mechanisms allow you to say that you are willing to rely on the CA for example.org, but only for user IDs that have an email address for example.org, for instance.

A link can be retracted using `sq pki link retract`.

This command is similar to `sq pki vouch authorize`, but the certifications it makes are done using the certificate directory's trust root, not an arbitrary key. Further, the certificates are marked as non-exportable. The former makes it easier to manage certifications, especially when your certification key is offline. And the latter improves your privacy, by reducing the chance that parts of your social graph are leaked when a certificate is shared.

By default a link never expires. Using the `--expiration` argument specific validity periods may be defined. It allows for providing a point in time for validity to end or a validity duration.

`sq pki link authorize` respects the reference time set by the top-level `--time` argument. It sets the link's creation time to the reference time.

OPTIONS

Subcommand options

--add-email=EMAIL
Use a user ID with the specified email address
The user ID consists of just the email address. The email address does not have to appear in a self-signed user ID.
--add-userid=USERID
Use the specified user ID
The specified user ID does not need to be self signed.
Because using a user ID that is not self-signed is often a mistake, you need to use this option to explicitly opt in.
--all
Use all self-signed user IDs
--allow-non-canonical-userids
Don't reject new user IDs that are not in canonical form
Canonical user IDs are of the form `Name (Comment) <localpart@example.org>`.
--amount=AMOUNT
Set the amount of trust
Values between 1 and 120 are meaningful. 120 means fully trusted. Values less than 120 indicate the degree of trust. 60 is usually used for partially trusted.
[default: full]
--cert=FINGERPRINT|KEYID
Use certificates with the specified fingerprint or key ID
--cert-special=SPECIAL
Use certificates identified by the special name
[possible values: public-directories, keys.openpgp.org, keys.mailvelope.com, proton.me, wkd, dane, autocrypt, web]
--depth=TRUST_DEPTH
Set the trust depth
This is sometimes referred to as the trust level. 1 means CERTIFICATE is a trusted introducer (default), 2 means CERTIFICATE is a meta-trusted introducer and can authorize another trusted introducer, etc.
[default: 255]
--domain=DOMAIN
Add a domain constraint to the introducer
Add a domain to constrain what certifications are respected. A certification made by the certificate is only respected if it is over a user ID with an email address in the specified domain. Multiple domains may be specified. In that case, one must match.
--email=EMAIL
Use a user ID consisting of just the email address, if the email address occurs in a self-signed user ID
--expiration=EXPIRATION
Sets the expiration time
EXPIRATION is either an ISO 8601 formatted date with an optional time or a custom duration. A duration takes the form `N[ymwds]`, where the letters stand for years, months, weeks, days, and seconds, respectively. Alternatively, the keyword `never` does not set an expiration time.
[default: never]
--recreate
Recreate the signature even if the parameters did not change
If the link parameters did not change, and thus creating a signature should not be necessary, we omit the operation. This flag can be given to force the signature to be recreated anyway.
--regex=REGEX
Add a regular expression to constrain the introducer
Add a regular expression to constrain what certifications are respected. A certification made by the certificate is only respected if it is over a user ID that matches one of the specified regular expression. Multiple regular expressions may be specified. In that case, at least one must match.
--signature-notation NAME VALUE
Add a notation to the signature
A user-defined notation's name must be of the form `name@a.domain.you.control.org`. If the notation's name starts with a `!`, then the notation is marked as being critical. If a consumer of a signature doesn't understand a critical notation, then it will ignore the signature. The notation is marked as being human readable.
--unconstrained
Don't constrain the introducer
Normally an introducer is constrained so that only certain user IDs are respected, e.g., those that have an email address for a certain domain name. This option authorizes an introducer without constraining it in this way. Because this grants the introducer a lot of power, you have to opt in to this behavior explicitly.
--userid=USERID
Use the specified self-signed user ID
The specified user ID must be self signed.
--userid-by-email=EMAIL
Use the self-signed user ID with the specified email address

Global options

See sq(1) for a description of the global options.

EXAMPLES

Add an unconstrained trusted introducer.

$ sq pki link authorize --unconstrained --cert=62121F7D678B252D

Add a trusted introducer that is only trusted for user IDs in the `example.org` domain.

$ sq pki link authorize --domain=example.org --cert=D27E5B2856556750

Add a trusted introducer that is only trusted for user IDs that match the supplied regular expression.

$ sq pki link authorize --regex='.*<.*@example.org>' --cert=3BBF91AE5D92E44D

Add a trusted introducer that is trusted for 120 days.

$ sq pki link authorize --expiration=120d --cert=3BBF91AE5D92E44D

Add a trusted introducer that is trusted until the given date.

$ sq pki pki link authorize --expiration=2024-07-15T00:00:00 --cert=3BBF91AE5D92E44D

Add a trusted introducer with a specified amount of trust.

$ sq pki link authorize --amount=60 --cert=3BBF91AE5D92E44D

Add a trusted introducer with a specified trust depth.

$ sq pki link authorize --depth=2 --cert=3BBF91AE5D92E44D

الاسم

sq-pki-link-authorize - اجعل الشهادة مقدمة موثوقة

ملخص

sq pki link authorize [خيارات]

الوصف

اجعل الشهادة مقدمة موثوقة.

هذا يجعل `sq` يعتبر الشهادة مقدمة موثوقة. مقدم موثوق هو كلمة أخرى لسلطة التصديق (CA). عندما تربط مقدمًا موثوقًا، فإنك تعتبر الشهادات الصادرة عن المقدم الموثوق صالحة. يمكن للمقدم الموثوق أيضًا تحديد مقدمين إضافيين موثوقين.

كما هي، يمتلك المقدم الموثوق الكثير من القوة. يمكن تقييد هذه القوة بعدة طرق.


- يمكن تقييد القدرة على تحديد مقدمين إضافيين باستخدام المعامل `--depth`.


- يمكن تغيير درجة الثقة في المقدم باستخدام المعامل `--amount`.


- يمكن تقييد معرفات المستخدم التي يمكن للمقدم التصديق عليها حسب المجال باستخدام المعامل `--domain` أو حسب تعبير عادي باستخدام المعامل `--regex`.

تسمح لك هذه الآليات بالقول إنك على استعداد للاعتماد على CA لـ example.org، على سبيل المثال، ولكن فقط لمعرفات المستخدم التي لديها عنوان بريد إلكتروني لـ example.org، على سبيل المثال.

يمكن إلغاء الارتباط باستخدام `sq pki link retract`.

هذا الأمر مشابه لـ `sq pki vouch authorize`، ولكن الشهادات التي يصدرها تتم باستخدام جذر الثقة الخاص بدليل الشهادات، وليس مفتاحًا عشوائيًا. علاوة على ذلك، يتم تمييز الشهادات على أنها غير قابلة للتصدير. الأول يجعل إدارة الشهادات أسهل، خاصة عندما يكون مفتاح التصديق الخاص بك غير متصل بالإنترنت. والأخير يحسن خصوصيتك، عن طريق تقليل فرصة تسرب أجزاء من رسمك البياني الاجتماعي عند مشاركة شهادة.

افتراضيًا، لا ينتهي ارتباط أبدًا. باستخدام الوسيط `--expiration`، يمكن تحديد فترات صلاحية محددة. يسمح بتوفير نقطة زمنية لانتهاء الصلاحية أو مدة صلاحية.

يحترم `sq pki link authorize` وقت المرجع المحدد بواسطة الوسيط العلوي `--time`. يقوم بتعيين وقت إنشاء الارتباط إلى وقت المرجع.

خيارات

خيارات الأوامر الفرعية

--add-email=EMAIL
استخدم معرف مستخدم بعنوان البريد الإلكتروني المحدد
يتكون معرف المستخدم من عنوان البريد الإلكتروني فقط. لا يلزم أن يظهر عنوان البريد الإلكتروني في معرف مستخدم موقع ذاتيًا.
--add-userid=USERID
استخدم معرف المستخدم المحدد
لا يلزم أن يكون معرف المستخدم المحدد موقعًا ذاتيًا.
نظرًا لأن استخدام معرف مستخدم غير موقع ذاتيًا غالبًا ما يكون خطأ، تحتاج إلى استخدام هذا الخيار للاختيار صراحةً.
--all
استخدم جميع معرفات المستخدمين الموقعين ذاتيًا
--allow-non-canonical-userids
لا ترفض معرفات المستخدمين الجديدة التي ليست بالشكل القياسي
معرفات المستخدمين القياسية هي من الشكل `Name (Comment) <localpart@example.org>`.
--amount=AMOUNT
تعيين مقدار الثقة
القيم بين 1 و 120 ذات معنى. 120 تعني موثوق بالكامل. القيم الأقل من 120 تشير إلى درجة الثقة. 60 تستخدم عادة للثقة جزئيًا.
[الافتراضي: full]
--cert=FINGERPRINT|KEYID
استخدم الشهادات مع البصمة أو معرف المفتاح المحدد
--cert-special=SPECIAL
استخدم الشهادات المعرفة بالاسم الخاص
[القيم الممكنة: public-directories, keys.openpgp.org, keys.mailvelope.com, proton.me, wkd, dane, autocrypt, web]
--depth=TRUST_DEPTH
تعيين عمق الثقة
يشار إلى هذا أحيانًا بمستوى الثقة. 1 يعني أن الشهادة هي مقدم موثوق (الافتراضي)، 2 يعني أن الشهادة هي مقدم موثوق ميتا ويمكنها التفويض لمقدم موثوق آخر، وما إلى ذلك.
[الافتراضي: 255]
--domain=DOMAIN
إضافة قيد المجال للمقدم
أضف مجالًا لتقييد الشهادات التي يتم احترامها. لا يتم احترام الشهادة الصادرة عن الشهادة إلا إذا كانت فوق معرف مستخدم بعنوان بريد إلكتروني في المجال المحدد. يمكن تحديد مجالات متعددة. في هذه الحالة، يجب أن يتطابق أحدها.
--email=EMAIL
استخدم معرف مستخدم يتكون فقط من عنوان البريد الإلكتروني، إذا كان عنوان البريد الإلكتروني يظهر في معرف مستخدم موقع ذاتيًا
--expiration=EXPIRATION
يحدد وقت انتهاء الصلاحية
EXPIRATION هو إما تاريخ بتنسيق ISO 8601 مع وقت اختياري أو مدة مخصصة. تأخذ المدة الشكل `N[ymwds]`، حيث تمثل الأحرف السنوات والأشهر والأسابيع والأيام والثواني على التوالي. بدلاً من ذلك، الكلمة الرئيسية `never` لا تحدد وقت انتهاء الصلاحية.
[الافتراضي: never]
--recreate
إعادة إنشاء التوقيع حتى لو لم تتغير المعلمات
إذا لم تتغير معلمات الارتباط، وبالتالي لا ينبغي أن يكون إنشاء توقيع ضروريًا، فإننا نتجاوز العملية. يمكن إعطاء هذا العلم لإجبار إعادة إنشاء التوقيع على أي حال.
--regex=REGEX
إضافة تعبير عادي لتقييد المقدم
أضف تعبيرًا عاديًا لتقييد الشهادات التي يتم احترامها. لا يتم احترام الشهادة الصادرة عن الشهادة إلا إذا كانت فوق معرف مستخدم يتطابق مع أحد التعبيرات العادية المحددة. يمكن تحديد تعبيرات عادية متعددة. في هذه الحالة، يجب أن يتطابق واحد على الأقل.
--signature-notation NAME VALUE
إضافة ملاحظة إلى التوقيع
يجب أن يكون اسم ملاحظة محددة من قبل المستخدم من الشكل `name@a.domain.you.control.org`. إذا بدأ اسم الملاحظة بـ `!`، فسيتم تمييز الملاحظة على أنها حرجة. إذا كان مستهلك التوقيع لا يفهم ملاحظة حرجة، فسيقوم بتجاهل التوقيع. يتم تمييز الملاحظة على أنها قابلة للقراءة البشرية.
--unconstrained
لا تقيد المقدم
عادةً ما يتم تقييد المقدم بحيث يتم احترام معرفات مستخدم معينة فقط، على سبيل المثال، تلك التي لديها عنوان بريد إلكتروني لاسم مجال معين. يفوض هذا الخيار مقدمًا دون تقييده بهذه الطريقة. نظرًا لأن هذا يمنح المقدم الكثير من القوة، يجب عليك الاشتراك في هذا السلوك صراحةً.
--userid=USERID
استخدم معرف المستخدم المحدد الموقع ذاتيًا
يجب أن يكون معرف المستخدم المحدد موقعًا ذاتيًا.
--userid-by-email=EMAIL
استخدم معرف المستخدم الموقع ذاتيًا مع عنوان البريد الإلكتروني المحدد

خيارات عامة

انظر sq(1) لوصف الخيارات العامة.

أمثلة

إضافة مقدم موثوق غير مقيد.

$ sq pki link authorize --unconstrained --cert=62121F7D678B252D

إضافة مقدم موثوق موثوق به فقط لمعرفات المستخدمين في مجال `example.org`.

$ sq pki link authorize --domain=example.org --cert=D27E5B2856556750

إضافة مقدم موثوق موثوق به فقط لمعرفات المستخدمين التي تتطابق مع التعبير العادي المقدم.

$ sq pki link authorize --regex='.*<.*@example.org>' --cert=3BBF91AE5D92E44D

إضافة مقدم موثوق موثوق به لمدة 120 يومًا.

$ sq pki link authorize --expiration=120d --cert=3BBF91AE5D92E44D

إضافة مقدم موثوق موثوق به حتى التاريخ المحدد.

$ sq pki pki link authorize --expiration=2024-07-15T00:00:00 --cert=3BBF91AE5D92E44D

إضافة مقدم موثوق بمقدار ثقة محدد.

$ sq pki link authorize --amount=60 --cert=3BBF91AE5D92E44D

إضافة مقدم موثوق بعمق ثقة محدد.

$ sq pki link authorize --depth=2 --cert=3BBF91AE5D92E44D
