SQLITE_TABLE(5) دليل تنسيقات الملفات SQLITE_TABLE(5)

الاسم

sqlite_table - إعدادات Postfix SQLite

الملخص

postmap -q "سلسلة" sqlite:/etc/postfix/اسم_الملف
postmap -q - sqlite:/etc/postfix/اسم_الملف <ملف_الإدخال

الوصف


يستخدم نظام البريد Postfix جداول اختيارية لإعادة كتابة العناوين أو لتوجيه البريد. هذه الجداول تكون عادة بتنسيق dbm أو db.

بدلاً من ذلك، يمكن تحديد جداول البحث كقواعد بيانات SQLite. لاستخدام عمليات البحث في SQLite، حدد مصدر SQLite كجدول بحث في main.cf، على سبيل المثال:

    alias_maps = sqlite:/etc/postfix/sqlite-aliases.cf

الملف /etc/postfix/sqlite-aliases.cf له نفس تنسيق ملف main.cf الخاص بـ Postfix، ويمكن أن يحدد المعلمات الموضحة أدناه.

عضوية القائمة

عند استخدام SQL لتخزين قوائم مثل $mynetworks، $mydestination، $relay_domains، $local_recipient_maps، إلخ، من المهم فهم أن الجدول يجب أن يخزن كل عضو في القائمة كمفتاح منفصل. التحقق من الجدول يتحقق من *وجود* المفتاح. انظر "Postfix lists versus tables" في وثيقة DATABASE_README لمناقشة هذه المسألة.

لا تقم بإنشاء جداول تُرجع القائمة الكاملة للمجالات في $mydestination أو $relay_domains إلخ، أو عناوين IP في $mynetworks.

قم بإنشاء جداول يكون فيها كل عنصر مطابق مفتاحًا وقيمة اعتباطية. مع قواعد بيانات SQL، ليس من غير المألوف إرجاع المفتاح نفسه أو قيمة ثابتة.

معلمات SQLite

dbpath
موقع ملف قاعدة بيانات SQLite. مثال: 
    dbpath = customer_database
query
قالب استعلام SQL المستخدم للبحث في قاعدة البيانات، حيث %s هو بديل للعنوان الذي يحاول Postfix حله، على سبيل المثال: 
    query = SELECT replacement FROM aliases WHERE mailbox = '%s'

تدعم هذه المعلمة التوسعات التالية بعلامة '%':

%%
يتم استبداله بحرف '%' حرفي.
%s
يتم استبداله بالمفتاح المدخل. يتم استخدام اقتباس SQL للتأكد من أن المفتاح المدخل لا يضيف أحرفًا وصفية غير متوقعة.
%u
عندما يكون المفتاح المدخل عنوانًا بالصيغة user@domain، يتم استبدال %u بالجزء المحلي من العنوان مع اقتباس SQL. بخلاف ذلك، يتم استبدال %u بسلسلة البحث بأكملها. إذا كان الجزء المحلي فارغًا، يتم قمع الاستعلام ولا يتم إرجاع أي نتائج.
%d
عندما يكون المفتاح المدخل عنوانًا بالصيغة user@domain، يتم استبدال %d بالجزء الخاص بالنطاق من العنوان مع اقتباس SQL. بخلاف ذلك، يتم قمع الاستعلام ولا يتم إرجاع أي نتائج.
%[SUD]
المكافئات الكبيرة للأحرف الكبيرة للأحرف المذكورة أعلاه تعمل في معلمة query بنفس الطريقة التي تعمل بها نظيراتها الصغيرة. مع معلمة result_format (انظر أدناه)، تقوم بتوسيع المفتاح المدخل بدلاً من قيمة النتيجة.
%[1-9]
الأنماط %1، %2، ... %9 يتم استبدالها بالمكون الأكثر أهمية المقابل لنطاق المفتاح المدخل. إذا كان المفتاح المدخل هو user@mail.example.com، فإن %1 هو com، و %2 هو example، و %3 هو mail. إذا كان المفتاح المدخل غير مؤهل أو لا يحتوي على مكونات نطاق كافية لتلبية جميع الأنماط المحددة، يتم قمع الاستعلام ولا يتم إرجاع أي نتائج.
تحد معلمة domain الموضحة أدناه المفاتيح المدخلة إلى عناوين في النطاقات المطابقة. عندما تكون معلمة domain غير فارغة، يتم قمع استعلامات SQL للعناوين غير المؤهلة أو العناوين في النطاقات غير المطابقة ولا يتم إرجاع أي نتائج.

هذه المعلمة متاحة مع Postfix 2.2. في الإصدارات السابقة، تم بناء استعلام SQL من المعلمات المنفصلة: select_field، table، where_field، و additional_conditions. التعيين من المعلمات القديمة إلى الاستعلام المكافئ هو:

    SELECT [select_field]
    FROM [table]
    WHERE [where_field] = '%s'
          [additional_conditions]

يتم توسيع '%s' في جملة WHERE إلى سلسلة البحث المشفرة. مع Postfix 2.2، يتم استخدام هذه المعلمات القديمة إذا لم يتم تحديد معلمة query.

ملاحظة: لا تضع علامات اقتباس حول معلمة الاستعلام.

result_format (الافتراضي: %s)
قالب تنسيق يتم تطبيقه على سمات النتائج. الأكثر شيوعًا استخدامه لإلحاق (أو تقديم) نص بالنتيجة. تدعم هذه المعلمة التوسعات التالية بعلامة '%':
%%
يتم استبداله بحرف '%' حرفي.
%s
يتم استبداله بقيمة سمة النتيجة. عندما تكون النتيجة فارغة، يتم تخطيها.
%u
عندما تكون قيمة سمة النتيجة عنوانًا بالصيغة user@domain، يتم استبدال %u بالجزء المحلي من العنوان. عندما يكون للنتيجة جزء محلي فارغ، يتم تخطيها.
%d
عندما تكون قيمة سمة النتيجة عنوانًا بالصيغة user@domain، يتم استبدال %d بالجزء الخاص بالنطاق من قيمة السمة. عندما يكون للنتيجة غير مؤهل، يتم تخطيها.
%[SUD1-9]
التوسعات الكبيرة والأرقام العشرية تستبدل أجزاء المفتاح المدخل بدلاً من النتيجة. سلوكها مطابق للسلوك الموصوف مع query، وفي الواقع لأن المفتاح المدخل معروف مسبقًا، يتم قمع الاستعلامات التي لا يحتوي مفتاحها على جميع المعلومات المحددة في قالب النتيجة ولا يتم إرجاع أي نتائج.
على سبيل المثال، استخدام "result_format = smtp:[%s]" يسمح باستخدام سمة mailHost كأساس لجدول transport(5). بعد تطبيق تنسيق النتيجة، يتم دمج القيم المتعددة كسلاسل مفصولة بفواصل. يسمح limit_expansion والمعلمة الموضحة أدناه بتقييد عدد القيم في النتيجة، وهو مفيد بشكل خاص للخرائط التي يجب أن تُرجع قيمة واحدة على الأكثر.

القيمة الافتراضية %s تحدد أن كل قيمة نتيجة يجب استخدامها كما هي.

هذه المعلمة متاحة مع Postfix 2.2 والإصدارات الأحدث.

ملاحظة: لا تضع علامات اقتباس حول تنسيق النتيجة!

domain (الافتراضي: لا قائمة نطاقات)
هذه قائمة بأسماء النطاقات، أو مسارات للملفات، أو قواعد بيانات "type:table". عند تحديدها، تكون مفاتيح البحث المؤهلة بالكامل فقط مع جزء محلي *غير فارغ* ونطاق مطابق مؤهلة للبحث: عمليات البحث عن 'user'، وعمليات البحث عن نطاقات عارية، وعمليات البحث "@domain" لا يتم إجراؤها. يمكن أن يقلل هذا بشكل كبير من حمل الاستعلام على خادم SQLite. 
    domain = postfix.org, hash:/etc/postfix/searchdomains

من الأفضل عدم استخدام SQL لتخزين النطاقات المؤهلة لعمليات البحث في SQL.

هذه المعلمة متاحة مع Postfix 2.2 والإصدارات الأحدث.

ملاحظة: لا تحدد هذه المعلمة لـ local(8) aliases، لأن المفاتيح المدخلة غير مؤهلة دائمًا.

expansion_limit (الافتراضي: 0)
حد على إجمالي عدد عناصر النتيجة التي تم إرجاعها (كسلسلة مفصولة بفواصل) من بحث ضد الخريطة. الإعداد صفر يعطل الحد. تفشل عمليات البحث بخطأ مؤقت إذا تم تجاوز الحد. يضمن تعيين الحد إلى 1 أن عمليات البحث لا تُرجع قيمًا متعددة.

معلمات MAIN.CF المهملة

للتوافق مع جداول البحث الأخرى في Postfix، يمكن أيضًا تعريف معلمات SQLite في main.cf. للقيام بذلك، حدد كمصدر SQLite اسمًا لا يبدأ بشرطة مائلة أو نقطة. ستكون معلمات SQLite بعد ذلك متاحة باسم المصدر الذي حددته في تعريفه، تحته شرطة سفلية، واسم المعلمة. على سبيل المثال، إذا تم تحديد الخريطة كـ "sqlite:sqlitename"، فسيتم تعريف المعلمة "query" في main.cf كـ "sqlitename_query".

واجهة الاستعلام المهملة

OBSOLETE QUERY INTERFACE

This section describes an interface that is deprecated as of Postfix 2.2. It is replaced by the more general query interface described above. If the query parameter is defined, the legacy parameters described here ignored. Please migrate to the new interface as the legacy interface may be removed in a future release.

The following parameters can be used to fill in a SELECT template statement of the form:

    SELECT [select_field]
    FROM [table]
    WHERE [where_field] = '%s'
          [additional_conditions]

The specifier %s is replaced by the search string, and is escaped so if it contains single quotes or other odd characters, it will not cause a parse error, or worse, a security problem.

select_field
The SQL "select" parameter. Example: 
    select_field = forw_addr
table
The SQL "select .. from" table name. Example: 
    table = mxaliases
where_field
The SQL "select .. where" parameter. Example: 
    where_field = alias
additional_conditions
Additional conditions to the SQL query. Example: 
    additional_conditions = AND status = 'paid'
