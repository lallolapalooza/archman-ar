sq-pki-vouch-add(1)

الحزمة: sequoia-sq

التراخيص: LGPL-2.0-or-later

SQ(1) أوامر المستخدم SQ(1)

الاسم

sq-pki-vouch-add - التصديق على معرف مستخدم لشهادة

الملخص

sq pki vouch add [خيارات]

الوصف

التصديق على معرف مستخدم لشهادة.

باستخدام شهادة، قد يشهد حامل المفتاح على حقيقة أن شهادة أخرى تنتمي بشكل شرعي إلى معرف مستخدم. في سياق رسائل البريد الإلكتروني، هذا يعني أن نفس الكيان يتحكم في المفتاح وعنوان البريد الإلكتروني. تشكل هذه الأنواع من الشهادات أساس شبكة الثقة.

ينتج هذا الأمر الشهادة مع الشهادة الجديدة. يجب توزيع الشهادة المحدثة، ويفضل إرسالها إلى حامل الشهادة للموافقة. انظر أيضًا `sq key approvals`.

افتراضيًا، تنتهي صلاحية الشهادة بعد 10 سنوات. باستخدام الوسيطة `--expiration`، يمكن تحديد فترات صلاحية محددة. يسمح بتوفير نقطة زمنية لانتهاء الصلاحية أو مدة صلاحية.

يحترم `sq pki vouch add` الوقت المرجعي الذي حددته الوسيطة العليا `--time`. تحدد وقت إنشاء الشهادة إلى الوقت المرجعي.

الخيارات

خيارات الأمر الفرعي

--add-email=EMAIL
استخدم معرف مستخدم بعنوان البريد الإلكتروني المحدد
يتكون معرف المستخدم من عنوان البريد الإلكتروني فقط. لا يلزم أن يظهر عنوان البريد الإلكتروني في معرف مستخدم موقع ذاتيًا.
--add-userid=USERID
استخدم معرف المستخدم المحدد
لا يلزم أن يكون معرف المستخدم المحدد موقعًا ذاتيًا.
نظرًا لأن استخدام معرف مستخدم غير موقع ذاتيًا غالبًا ما يكون خطأ، تحتاج إلى استخدام هذه الوسيطة للاشتراك الصريح.
--all
استخدم جميع معرفات المستخدمين الموقع ذاتيًا
--allow-non-canonical-userids
لا ترفض معرفات المستخدمين الجديدة التي ليست في شكل قياسي
معرفات المستخدمين القياسية هي على شكل `الاسم (تعليق) <الجزء المحلي@مثال.org>`.
--amount=AMOUNT
اضبط مقدار الثقة
القيم بين 1 و 120 ذات مغزى. 120 تعني ثقة كاملة. القيم الأقل من 120 تشير إلى درجة الثقة. عادة ما يتم استخدام 60 للثقة الجزئية.
[افتراضي: full]
--cert=FINGERPRINT|KEYID
استخدم الشهادات ببصمة الإصبع أو معرف المفتاح المحدد
--cert-file=PATH
اقرأ الشهادات من المسار
--certifier=FINGERPRINT|KEYID
أنشئ الشهادة باستخدام المفتاح ببصمة الإصبع أو معرف المفتاح المحدد
--certifier-email=EMAIL
أنشئ الشهادة باستخدام المفتاح حيث يتضمن معرف مستخدم عنوان البريد الإلكتروني المحدد
--certifier-file=PATH
أنشئ الشهادة باستخدام المفتاح المقروء من المسار
--certifier-self
أنشئ الشهادة باستخدام مفتاح التصديق الافتراضي الخاص بك
يستخدم هذا الشهادات المحددة في ملف التكوين تحت `pki.vouch.certifier-self` كمفتاح تصديق.
حاليًا، لا يوجد مفتاح تصديق افتراضي.
--certifier-userid=USERID
أنشئ الشهادة باستخدام المفتاح بمعرف المستخدم المحدد
--email=EMAIL
استخدم معرف مستخدم يتكون فقط من عنوان البريد الإلكتروني، إذا ظهر عنوان البريد الإلكتروني في معرف مستخدم موقع ذاتيًا
--expiration=EXPIRATION
اضبط وقت الانتهاء
EXPIRATION هو إما تاريخ بتنسيق ISO 8601 مع وقت اختياري أو مدة مخصصة. مدة التأخذ شكل `N[ymwds]`، حيث تمثل الأحرف السنوات، الأشهر، الأسابيع، الأيام، والثواني، على التوالي. بدلاً من ذلك، الكلمة المفتاحية `never` لا تحدد وقت انتهاء الصلاحية.
يمكن تغيير الافتراضي في ملف التكوين باستخدام الإعداد `pki.vouch.expiration`.
[افتراضي: 10y]
--local
اجعل الشهادة شهادة محلية
عادة، لا يتم تصدير الشهادات المحلية.
--non-revocable
ضع علامة على الشهادة على أنها غير قابلة للإلغاء
أي، لا يمكنك إلغاء هذه الشهادة لاحقًا. يجب استخدام هذا عادةً مع انتهاء الصلاحية.
--output=FILE
اكتب إلى الملف أو إلى الخرج القياسي إذا تم حذفه
--signature-notation NAME VALUE
أضف تعليقًا توضيحيًا إلى التوقيع
يجب أن يكون اسم التعليق التوضيحي المعرف من قبل المستخدم على شكل `name@a.domain.you.control.org`. إذا بدأ اسم التعليق التوضيحي بـ `!`, فعندئذ يتم وضع علامة على التعليق التوضيحي على أنه حاسم. إذا لم يفهم المستهلك للتوقيع تعليقًا توضيحيًا حاسمًا، فسيقوم بتجاهل التوقيع. يتم وضع علامة على التعليق التوضيحي على أنه قابل للقراءة من قبل الإنسان.
--userid=USERID
استخدم معرف المستخدم الموقع ذاتيًا المحدد
يجب أن يكون معرف المستخدم المحدد موقعًا ذاتيًا.
--userid-by-email=EMAIL
استخدم معرف المستخدم الموقع ذاتيًا بعنوان البريد الإلكتروني المحدد

أمثلة

تصادق أليس على أن بوب يتحكم في 3F68CB84CE537C9A و bob@example.org.

sq pki vouch add \
--certifier=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
--cert=511257EBBF077B7AEDAE5D093F68CB84CE537C9A \
--email=bob@example.org

تصادق أليس على أن بوب يتحكم في 3F68CB84CE537C9A و bob@bobs.lair.net, وهو ليس معرف مستخدم موقع ذاتيًا.

sq pki vouch add \
--certifier=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
--cert=511257EBBF077B7AEDAE5D093F68CB84CE537C9A \
--add-email=bob@bobs.lair.net

NAME

sq-pki-vouch-add — Add a vouch to a certificate

SYNOPSIS

sq pki vouch add [OPTIONS] <cert> <key> <recipient> <cert_id> <key_id>

DESCRIPTION

This command adds a new vouch to a certificate. A vouch is a signature by one certificate holder on another certificate, asserting the identity of the second certificate holder. It is used to establish trust in certificates, especially when the primary trust path is not available or insufficient.

The command takes the following arguments:

  • <cert>: The path to the certificate file to which the vouch will be added.
  • <key>: The path to the private key file corresponding to the certificate used to sign the vouch.
  • <recipient>: The certificate ID of the recipient of the vouch (the certificate being vouched for).
  • <cert_id>: The certificate ID of the signer (the issuer of the vouch).
  • <key_id>: The key ID of the private key to use for signing the vouch.

OPTIONS

--output <output>, -o <output>
Specifies the output file for the modified certificate. If not provided, the output will be written to standard output.
--passphrase <passphrase>
The passphrase for the private key. If not provided, the command will prompt for the passphrase.
--debug
Enable debug logging.
--help
Show help message and exit.

EXAMPLES

Add a vouch to a certificate using a private key:

sq pki vouch add my_cert.pem my_private_key.pem recipient_cert_id signer_cert_id signer_key_id --output updated_cert.pem
