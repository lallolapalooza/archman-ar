SQFSTAR(1) User Commands SQFSTAR(1)

NAME

sqfstar - أداة لإنشاء نظام ملفات squashfs من أرشيف tar

SYNOPSIS


cat xxx.tar | sqfstar [OPTIONS] FILESYSTEM [exclude files]
zcat xxx.tgz | sqfstar [OPTIONS] FILESYSTEM [exclude files]
xzcat xxx.tar.xz | sqfstar [OPTIONS] FILESYSTEM [exclude files]
zstdcat xxx.tar.zst | sqfstar [OPTIONS] FILESYSTEM [exclude files]

DESCRIPTION

Squashfs هو نظام ملفات عالي الضغط للقراءة فقط لنظام Linux. يستخدم ضغط gzip/xz/lzo/lz4/zstd لضغط الملفات، inodes، والأدلة. العقد (Inodes) في النظام صغيرة جدًا وجميع الكتل مجمعة لتقليل الحمل الزائد للبيانات. أحجام الكتل الأكبر من 4K مدعومة حتى حد أقصى 1 ميجابايت (حجم الكتلة الافتراضي 128 كيلو بايت).

يهدف Squashfs إلى الاستخدام العام لنظام الملفات للقراءة فقط، ولأغراض الأرشفة (أي في الحالات التي يمكن فيها استخدام ملف .tar.gz)، وفي الأنظمة ذات القيود على الأجهزة (مثل الأنظمة المدمجة) حيث تكون الحاجة إلى حمل زائد منخفض.

OPTIONS

خيارات ضغط نظام الملفات:

-b BLOCK-SIZE
تعيين كتلة البيانات إلى BLOCK-SIZE. الافتراضي 128 كيلو بايت. اختياريًا، يمكن إعطاء لاحقة K أو KB أو Kbytes أو M أو MB أو Mbytes لتحديد كيلو بايت أو ميجابايت على التوالي.
-comp COMP
اختيار ضغط COMP. قم بتشغيل -help-comp COMP للحصول على خيارات الضغط لـ COMP، أو ALL لجميع الضواغط. الضواغط المتاحة: gzip (الافتراضي)، lzo، lz4، xz، zstd، lzma.
-noI
عدم ضغط جدول inode.
-noId
عدم ضغط جدول uid/gid (ضمنية بواسطة -noI).
-noD
عدم ضغط كتل البيانات.
-noF
عدم ضغط كتل الأجزاء (fragments).
-noX
عدم ضغط السمات الممتدة (extended attributes).
-no-compression
عدم ضغط أي من البيانات أو البيانات الوصفية. هذا يعادل تحديد -noI -noD -noF و -noX.

خيارات بناء نظام الملفات:

-exports
جعل نظام الملفات قابلاً للتصدير عبر NFS.
-no-sparse
عدم اكتشاف الملفات المتفرقة (sparse files).
-no-fragments
عدم استخدام الأجزاء (fragments).
-no-tailends
عدم تجميع نهايات الذيل (tail ends) في أجزاء.
-no-duplicates
عدم إجراء التحقق من التكرارات.
-no-hardlinks
عدم ربط الملفات الصلبة (hardlinks)، بل تخزين التكرارات.
-regex
السماح باستخدام تعابير POSIX العادية في الأدلة/الملفات المستبعدة.
-ignore-zeros
السماح بدمج ملفات tar معًا وتغذيتها إلى Sqfstar. عادةً ما يحتوي ملف tar على كتلتين متتاليتين بحجم 512 بايت مملوءتين بالأصفار، مما يعني نهاية الملف (EOF)، وسيتوقف Sqfstar عن القراءة بعد ملف tar الأول عند مواجهتها. هذا الخيار يجعل Sqfstar يتجاهل الكتل المملوءة بالأصفار.
-ef EXCLUDE-FILE
قائمة بالأدلة/الملفات المستبعدة. سطر واحد لكل منها.

خيارات وقت نظام الملفات:

-mkfs-time TIME
تعيين الطابع الزمني لإنشاء نظام الملفات إلى TIME. يمكن أن يكون TIME "inode"، مما يعني استخدام أحدث طابع زمني لـ inode، أو عدد صحيح غير موقع 32 بت يشير إلى الثواني منذ بداية الحقبة (1970-01-01)، أو قيمة نصية يتم تمريرها إلى أمر "date" لتحليلها. يمكن استخدام أي قيمة نصية يتعرف عليها أمر date مثل "now" أو "last week" أو "Wed Feb 15 21:02:39 GMT 2023".
-inode-time TIME
تعيين جميع الطوابع الزمنية للملفات والأدلة إلى TIME. يمكن أن يكون TIME "inode"، مما يعني استخدام أحدث طابع زمني لـ inode، أو عدد صحيح غير موقع 32 بت يشير إلى الثواني منذ بداية الحقبة (1970-01-01)، أو قيمة نصية يتم تمريرها إلى أمر "date" لتحليلها. يمكن استخدام أي قيمة نصية يتعرف عليها أمر date مثل "now" أو "last week" أو "Wed Feb 15 21:02:39 GMT 2025". هذا الخيار يعين ويتجاوز الخيار -root-time.
-root-time TIME
تعيين وقت الدليل الجذر إلى TIME. يمكن أن يكون TIME "inode"، مما يعني استخدام أحدث طابع زمني لـ inode، أو عدد صحيح غير موقع 32 بت يشير إلى الثواني منذ بداية الحقبة (1970-01-01)، أو قيمة نصية يتم تمريرها إلى أمر "date" لتحليلها. يمكن استخدام أي قيمة نصية يتعرف عليها أمر date مثل "now" أو "last week" أو "Wed Feb 15 21:02:39 GMT 2025".
-repro
بناء صورة نظام ملفات قابلة للتكرار. هذا يعادل -mkfs-time inode، والذي يحقق قابلية التكرار عن طريق تعيين وقت بناء نظام الملفات إلى أحدث طابع زمني لـ inode. من الواضح أن الصورة لن تكون قابلة للتكرار إذا تغيرت الطوابع الزمنية أو المحتوى.
-repro-time TIME
بناء صورة نظام ملفات قابلة للتكرار. هذا يعادل تحديد -mkfs-time TIME و -inode-time TIME، والذي يحقق قابلية التكرار عن طريق تعيين جميع الطوابع الزمنية إلى TIME. يمكن استخدام هذا الخيار في الحالات التي قد تتغير فيها الطوابع الزمنية، وحيث لا يمكن استخدام -repro لهذا السبب.

خيارات أذونات نظام الملفات:

-all-root
جعل جميع الملفات والأدلة مملوكة لـ root.
-root-mode MODE
تعيين أذونات الدليل الجذر إلى MODE. يمكن أن يكون MODE رمزيًا أو ثمانيًا (انظر قسم مواصفات الوضع الرمزي). الوضع الافتراضي للجذر هو ugo=rwx أو 0777 ثماني.
-root-uid USER
تعيين مالك الدليل الجذر إلى USER المحدد، يمكن أن يكون USER إما معرف uid رقمي أو اسم مستخدم.
-root-gid GROUP
تعيين مجموعة الدليل الجذر إلى GROUP المحدد، يمكن أن يكون GROUP إما معرف gid رقمي أو اسم مجموعة.
-force-file-mode MODE
تعيين جميع أذونات الملفات (غير الأدلة) إلى MODE. يمكن أن يكون MODE رمزيًا أو ثمانيًا (انظر قسم مواصفات الوضع الرمزي).
-force-dir-mode MODE
تعيين جميع أذونات الأدلة إلى MODE. يمكن أن يكون MODE رمزيًا أو ثمانيًا (انظر قسم مواصفات الوضع الرمزي).
-force-uid USER
تعيين جميع معرفات uid للملفات والأدلة إلى USER المحدد، يمكن أن يكون USER إما معرف uid رقمي أو اسم مستخدم.
-force-gid GROUP
تعيين جميع معرفات gid للملفات والأدلة إلى GROUP المحدد، يمكن أن يكون GROUP إما معرف gid رقمي أو اسم مجموعة.
-uid-gid-offset VALUE
إزاحة جميع معرفات uid و gid بالقيمة المحددة VALUE. يجب أن تكون VALUE عددًا صحيحًا موجبًا.
-default-mode MODE
غالبًا ما لا تخزن ملفات tar أذونات للأدلة الوسيطة. يحدد هذا الخيار الأذونات الافتراضية للدليل إلى MODE. يمكن أن يكون MODE رمزيًا أو ثمانيًا (انظر قسم مواصفات الوضع الرمزي). الوضع الافتراضي هو u=rwx,go=rx أو 0755 ثماني. هذا يعين أيضًا وضع الدليل الجذر.

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

-default-uid USER

-default-uid USER
غالباً ما لا تقوم ملفات tar بتخزين معرفات المستخدم (uids) للأدلة الوسيطة. تحدد هذه الخيار مالك الدليل الافتراضي ليكون USER، بدلاً من المستخدم الذي يشغل Sqfstar. يمكن أن يكون USER معرف مستخدم (uid) عددي أو اسم مستخدم. هذا يحدد أيضاً معرف المستخدم (uid) للدليل الجذر.
-default-gid GROUP
غالباً ما لا تقوم ملفات tar بتخزين معرفات المجموعة (gids) للأدلة الوسيطة. تحدد هذه الخيار مجموعة الدليل الافتراضية لتكون GROUP، بدلاً من مجموعة المستخدم الذي يشغل Sqfstar. يمكن أن يكون GROUP معرف مجموعة (gid) عددي أو اسم مجموعة. هذا يحدد أيضاً معرف المجموعة (gid) للدليل الجذر.

خيارات الملفات الزائفة (pseudo options):

-p PSEUDO-DEFINITION
إضافة تعريف ملف زائف. يجب أن يكون التعريف بين علامتي اقتباس. راجع القسم "صيغة تعريف الملف الزائف" (Pseudo file definition format) للحصول على تفاصيل الصيغة.
-pd "d mode uid gid"
تحديد دليل زائف افتراضي سيتم استخدامه في التعريفات الزائفة إذا لم يكن دليل موجود في مسار الملف. هذا يسمح أيضاً بتحديد التعريفات الزائفة دون الحاجة إلى تحديد جميع الأدلة في المسار. يجب أن يكون التعريف بين علامتي اقتباس.
-pd "D time mode uid gid"
تحديد دليل زائف افتراضي سيتم استخدامه في التعريفات الزائفة إذا لم يكن دليل موجود في مسار الملف. يسمح النوع D أيضاً بتحديد الطابع الزمني بالإضافة إلى الوضع (mode) ومعرف المستخدم (uid) ومعرف المجموعة (gid).
-pf PSEUDO-FILE
إضافة قائمة بتعريفات الملفات الزائفة. لا يجب أن تكون تعريفات الملفات الزائفة في الملفات الزائفة بين علامتي اقتباس.
-pseudo-override
جعل معرفات المستخدم (uids) ومعرفات المجموعة (gids) للملفات الزائفة تتجاوز خيارات -all-root، -force-uid، و -force-gid.

خيارات سمات الملفات الموسعة (xattrs):

-no-xattrs
عدم تخزين السمات الموسعة.
-xattrs
تخزين السمات الموسعة (افتراضي).
-xattrs-exclude REGEX
استبعاد أي أسماء سمات موسعة (xattr names) تطابق REGEX. REGEX هو تعبير نمطي POSIX، على سبيل المثال، -xattrs-exclude '^user.' يستبعد السمات الموسعة من مساحة اسم المستخدم.
-xattrs-include REGEX
تضمين أي أسماء سمات موسعة (xattr names) تطابق REGEX. REGEX هو تعبير نمطي POSIX، على سبيل المثال، -xattrs-include '^user.' يضم السمات الموسعة من مساحة اسم المستخدم.
-xattrs-add NAME=VAL
إضافة السمة الموسعة NAME بالقيمة VAL إلى الملفات. إذا كانت سمة مستخدم، فستتم إضافتها إلى الملفات العادية والأدلة (انظر man 7 xattr). بخلاف ذلك، ستتم إضافتها إلى جميع الملفات. القيمة VAL ستعامل افتراضياً على أنها ثنائية (أي تسلسل بايت غير مفسر)، ولكن يمكن أن تبدأ بـ 0، حيث سيتم التعامل معها على أنها مشفرة بـ base64، أو تبدأ بـ 0x، حيث ستعامل القيمة على أنها سداسية عشرية. بالإضافة إلى ذلك، يمكن أن تبدأ بـ 0t حيث يكون هذا الترميز مشابهاً للترميز الثنائي، باستثناء أن الشرطة المائلة العكسية (backslash) تعامل بشكل خاص، ويمكن استخدام شرطة مائلة عكسية متبوعة بـ 3 أرقام ثمانية لترميز أي حرف ASCII، مما يمكن استخدامه بالطبع لترميز رموز التحكم. يمكن تكرار الخيار عدة مرات لإضافة سمات موسعة متعددة.

خيارات وقت تشغيل Sqfstar:

-version
طباعة رسالة الإصدار والترخيص وحقوق النشر.
-force
إجبار Sqfstar على الكتابة إلى جهاز كتلة (block device) أو ملف.
-exit-on-error
معاملة الأخطاء التي يتم تجاهلها عادةً على أنها قاتلة.
-quiet
لا يوجد مخرجات مطولة.
-info
طباعة الملفات التي تم كتابتها إلى نظام الملفات إلى المخرجات القياسية. هذا يعطل شريط التقدم تلقائياً. راجع -info-file لإخراج إلى ملف دون تعطيل شريط التقدم.
-info-file FILE
طباعة الملفات التي تم كتابتها إلى نظام الملفات إلى الملف FILE. هذا لا يعطل شريط التقدم.
-no-progress
عدم عرض شريط التقدم.
-progress
عرض شريط التقدم عند استخدام الخيار -info.
-percentage
عرض نسبة مئوية بدلاً من شريط التقدم الكامل. يمكن استخدامه مع أدوات مثل dialog --gauge وما شابه.
-throttle PERCENTAGE
تقييد معدل إدخال الإدخال/الإخراج (I/O) بالنسبة المئوية المحددة. يمكن استخدام هذا لتقليل استهلاك الإدخال/الإخراج والمعالج (CPU) بواسطة Sqfstar.
-limit PERCENTAGE
تحديد معدل إدخال الإدخال/الإخراج (I/O) بالنسبة المئوية المحددة. يمكن استخدام هذا لتقليل استهلاك الإدخال/الإخراج والمعالج (CPU) بواسطة Sqfstar (بديل لـ -throttle).
-processors NUMBER
استخدام NUMBER من المعالجات. افتراضياً، سيتم استخدام عدد المعالجات المتاحة.
-mem SIZE
استخدام SIZE من الذاكرة الفعلية (physical memory) للتخزين المؤقت (caches). استخدم K أو M أو G لتحديد كيلوبايت أو ميجابايت أو جيجابايت على التوالي.
-mem-percent PERCENT
استخدام PERCENT من الذاكرة الفعلية (physical memory) للتخزين المؤقت (caches). الافتراضي هو 25%.
-mem-default
طباعة استخدام الذاكرة الافتراضي بالميجابايت (Mbytes).
-overcommit PERCENT
السماح بنسبة PERCENT إضافية من سلاسل العمليات (threads) للتشغيل بالتوازي مقارنة بالمعالجات المتاحة. قد يؤدي القيام بذلك إلى زيادة استخدام المعالج. الافتراضي هو 0%، لأنه عادةً ما يقلل الإفراط في التخصيص من الأداء بسبب التبديل (trashing). قيمة النسبة المئوية تكون على مقياس عدد المعالجات، على سبيل المثال، 4 معالجات لها مقياس نسبة مئوية 25%، و 20 معالجاً لها مقياس نسبة مئوية 5%.

خيارات الخبراء (قد تجعل نظام الملفات غير قابل للتحميل):

-stream
إخراج نظام الملفات إلى المخرجات القياسية (STDOUT) بدلاً من ملف. هذا يسمح بتوجيه المخرجات إلى برنامج آخر أو في مكان آخر باستخدام ssh. نظام الملفات Squashfs الموجه (streamed) الناتج لن يكون نظام ملفات Squashfs عاديًا لأن كتلة الإدارة (super block) ستكون في نهاية نظام الملفات. ولكن يمكن إصلاحه لاحقًا باستخدام الخيار -fix، ويمكن لـ Unsquashfs 4.7.3 والإصدارات الأحدث قراءة ملفات موجهة غير ثابتة مباشرة. يتم تعطيل اكتشاف التكرار باستخدام الخيار -stream.
-fix FILESYSTEM
إصلاح FILESYSTEM الذي تم إنشاؤه باستخدام الخيار -stream.
-nopad
عدم حشو نظام الملفات بمضاعفات 4K.
-offset OFFSET
تخطي OFFSET بايت في بداية FILESYSTEM. اختياريًا، يمكن إعطاء لاحقة K أو M أو G لتحديد كيلوبايت أو ميجابايت أو جيجابايت على التوالي. الافتراضي هو 0 بايت.
-o OFFSET
مرادف للخيار -offset.

خيارات المساعدة:

-help
طباعة ملخص معلومات المساعدة إلى عارض الصفحات (pager) (أو المخرجات القياسية إذا لم يكن جهاز طرفي).
-help-option REGEX
طباعة معلومات المساعدة للخيارات التي تطابق REGEX إلى عارض الصفحات (أو المخرجات القياسية إذا لم يكن جهاز طرفي).
-help-section SECTION
طباعة معلومات المساعدة للقسم SECTION إلى عارض الصفحات (أو المخرجات القياسية إذا لم يكن جهاز طرفي). إذا لم يطابق SECTION اسم قسم بشكل دقيق، فسيتم معاملته كتعبير نمطي، وسيتم عرض جميع أسماء الأقسام التي تطابق. استخدم "list" كاسم قسم للحصول على قائمة بالأقسام وأسمائها.
-help-comp COMP
طباعة خيارات ضغط ضاغط معين COMP. استخدم "list" للحصول على قائمة بالضواغط المتاحة، و "all" للحصول على خيارات الضغط لجميع الضواغط.
-help-all
طباعة معلومات المساعدة لجميع خيارات وأقسام Sqfstar إلى عارض الصفحات (أو المخرجات القياسية إذا لم يكن جهاز طرفي).
-Xhelp
طباعة خيارات الضغط للضاغط المحدد.
-h
اختصار بديل للخيار -help.
-ho REGEX
اختصار بديل للخيار -help-option.
-hs SECTION
اختصار بديل للخيار -help-section.
-ha
اختصار بديل للخيار -help-all.
-no-pager
عدم استخدام عارض صفحات (pager) لإخراج معلومات المساعدة.
-cols WIDTH
استخدام WIDTH من الأعمدة لإخراج معلومات المساعدة. مفيد إذا لم تكن المخرجات موجهة إلى جهاز طرفي.

خيارات متنوعة:

-fstime TIME
اسم بديل لـ mkfs-time.
-root-owned
اسم بديل للخيار -all-root.
-noInodeCompress

OPTIONS

-o options
Set of comma separated mount options. See mount(8) for possible options.
-t type
Set the filesystem type. If not specified, this defaults to the type specified by the libxxxfs library. This option is only useful when multiple filesystem types are supported by the library, and is unused at present.
-p prog
Use prog instead of the default program to extract files. This program must take the compressed file as standard input and write the uncompressed file to standard output.
-f filename
Use filename as the filesystem image to be read or written. If this is not specified, standard input is used to read and standard output is used to write.
-P
Display the filesystem structure to standard output.
-x prog
Use prog instead of the default program to extract files. This program must take the compressed file as standard input and write the uncompressed file to standard output.
-i file
Write out an info file describing the filesystem.
-d
Generate a filesystem definition file.
-a
Set the access time of the filesystem to the current time.

SYMBOLIC MODE SPECIFICATION

The symbolic mode is of the format [ugoa]*[[+-=]PERMS]+. PERMS = [rwxXst]+ or [ugo], and the sequence can be repeated separated with commas.

A combination of the letters ugoa specify which permission bits will be affected, u means user, g means group, o means other, and a means all or ugo.

The next letter is +, - or =. The letter + means add to the existing permission bits, - means remove the bits from the existing permission bits, and = means set the permission bits.

The permission bits (PERMS) are a combination of [rwxXst] which sets/adds/removes those bits for the specified ugoa combination, r means read, w means write and x means execute for files or search for directories. X has a special meaning, if the file is a directory it is equivalent to x or search, but if it is a non-directory, it only takes effect if execute is already set for user, group or other. The s flag sets user or group ID on execution, and the t flag on a directory sets restricted deletion, or historically made the file sticky if a non-directory.

The permission bits can also be u, g or o, which takes the permission bits from the user, group or other of the file respectively.

NAME

sqfstar - create a Squashfs filesystem from a tar archive

SYNOPSIS

sqfstar [-comp compressor] [-comp-busize size] [-comp-options options] [-force-uid uid] [-force-gid gid] [-force-file-mode mode] [-p pseudo-file-definition ...] [-root-owned] [-no-exports] [-no-xattrs] [-no-sparse] [-no-duplicates] [-no-progress] [-quiet] [-mkfs-options options] [-offset offset] [-b block-size] [-no-fragments] [-always-use-fragments] [-fragment-max-size size] [-fragment-min-size size] [-no-tail] [-le] [-be] [-valid-fs] [-no-valid-fs] [-root-dir dir] [-all-root] [-sort-file file] [squashfs-image] [tar-archive ...]

DESCRIPTION

sqfstar is a utility that takes one or more tar archives, processes them, and creates a Squashfs filesystem image. It is intended to be used in environments where raw Squashfs images cannot be directly created (e.g. when the root filesystem is read-only).

The utility is essentially a wrapper around mksquashfs(1) which extracts the contents of the provided tar archive(s) to a temporary directory, processes them, and then creates a Squashfs image from that directory. By default, the temporary directory is created in the current directory, but it can be specified using the TMPDIR environment variable.

The contents of the tar archive are extracted into the temporary directory. Then, any additional arguments are processed. These arguments can be used to modify the extracted files, create new files, or exclude files. Finally, a Squashfs image is created from the contents of the temporary directory.

OPTIONS

Most of the options are passed directly to mksquashfs(1). Please refer to the mksquashfs(1) man page for a full description of these options.

The following options are specific to sqfstar:

-p pseudo-file-definition
Create a pseudo-file in the filesystem. See PSEUDO FILE DEFINITION FORMAT below.
-root-owned
Make all files and directories in the filesystem owned by root.
-no-exports
Do not export the Squashfs filesystem. This is the default behaviour. This option is mainly for compatibility with older versions.
-no-xattrs
Do not preserve extended attributes. By default, extended attributes are preserved.
-no-sparse
Do not support sparse files. By default, sparse files are supported.
-no-duplicates
Do not remove duplicate file data. By default, duplicate file data is removed to save space.
-no-progress
Do not display a progress indicator.
-quiet
Suppress informational messages. Only error messages will be displayed.
-mkfs-options options
Pass the specified options to mksquashfs(1).
-offset offset
Set the offset for the Squashfs image. This is useful for creating filesystem images that can be directly appended to other files (e.g. kernel images).
-b block-size
Set the block size for the Squashfs image. The default is 131072 bytes.
-no-fragments
Do not use fragments. Fragments are small files (less than the block size) that are stored efficiently within the filesystem.
-always-use-fragments
Always use fragments, even if they are larger than the block size. This can improve compression by allowing larger fragments to be used.
-fragment-max-size size
Set the maximum size of a fragment. The default is the block size.
-fragment-min-size size
Set the minimum size of a fragment. The default is 4 bytes.
-no-tail
Do not store file tails separately. File tails are the last part of a file that is smaller than the block size.
-le
Use little-endian format for the filesystem image. This is the default on little-endian systems.
-be
Use big-endian format for the filesystem image. This is the default on big-endian systems.
-valid-fs
Perform validity checks on the created filesystem. This is the default behaviour.
-no-valid-fs
Do not perform validity checks on the created filesystem. This can speed up the creation process, but the resulting filesystem may not be valid.
-root-dir dir
Use the specified directory as the root of the filesystem. This option is useful when creating a Squashfs image from an existing directory structure, rather than from a tar archive.
-all-root
Make all files and directories owned by root. This is equivalent to using -force-uid 0 and -force-gid 0.
-sort-file file
Sort the files in the filesystem according to the specified file. This can improve compression by grouping similar files together.

PSEUDO FILE DEFINITION FORMAT

A pseudo file definition is a string that defines a file or directory to be created in the Squashfs filesystem. The format is as follows:

name type mode uid gid [data]

where:

name
The name of the file or directory.
type
The type of the entry. Can be f for a regular file, d for a directory, or l for a symbolic link.
mode
The file mode (permissions). Can be specified in octal or symbolic notation.
uid
The user ID of the owner. Can be a number or a username.
gid
The group ID of the owner. Can be a number or a username.
data
Optional data for the file. Can be a string, a filename, or a command to be executed.

The following examples illustrate the use of pseudo file definitions:

sqfstar -p "build_dir d 0755 0 0" IMAGE.SQFS < archive.tar
Create a directory named "build_dir" with permissions 0755, owned by root.
sqfstar -p "version.txt l 0644 0 0 /tmp/build/version" IMAGE.SQFS < archive.tar
Create a symbolic link named "version.txt" pointing to "/tmp/build/version", with permissions 0644, owned by root.
sqfstar -p "date.txt f 0644 0 0 date" IMAGE.SQFS < archive.tar
Create a file named "date.txt" containing the output of the "date" command, with permissions 0644, owned by root.
sqfstar -p "\"hello world\" f 0644 0 0 echo\"hello world\"" IMAGE.SQFS < archive.tar
Create a file named "hello world" (with a space in the name) containing the string "hello world", with permissions 0644, owned by root. Note that the filename and the command output are quoted and the inner quotes are escaped.
sqfstar -p "input f 0644 0 0 dd if=/dev/sda1 bs=1024" IMAGE.SQFS < archive.tar
Create a file named "input" containing the contents of "/dev/sda1", with permissions 0644, owned by root. This allows data from special device files to be captured.

SYMBOLIC MODE SPECIFICATION

Symbolic mode specifications are similar to those used by chmod(1). They consist of sequences of.

who
A character specifying who the permissions apply to: 'u' (user), 'g' (group), 'o' (others), or 'a' (all).
operator
A character specifying the type of operation: '+' (add), '-' (remove), or '=' (set).
perm
A sequence of one or more permission characters: 'r' (read), 'w' (write), 'x' (execute), 's' (setuid/setgid), 't' (sticky bit).

Multiple specifications can be separated by commas. For example:

sqfstar -force-file-mode u+x,go-w IMAGE.SQFS < archive.tar
Add execute permission for the user, and remove write permission for the group and others. All other permission bits are unaffected.

EXIT STATUS

sqfstar exits with a status of 0 if the filesystem was created successfully, and a non-zero status otherwise.

COMPRESSORS AVAILABLE AND COMPRESSOR SPECIFIC OPTIONS

The available compressors and their specific options depend on how Squashfs-tools was compiled. Typically, the following compressors are available:

gzip
Compression level (1-9).
lzma
Compression level (0-9).
lzo
xz
Compression level (0-9).
lz4
zstd
Compression level (1-22).

Use the -comp option to specify the compressor, and -comp-options to specify compressor-specific options. For example:

sqfstar -comp xz -comp-options 9 IMAGE.SQFS < archive.tar
Create a Squashfs image using xz compression with level 9.

ENVIRONMENT

TMPDIR: Specifies the directory in which to create the temporary directory for extracting the tar archive. If not set, the current directory is used.

EXAMPLES

sqfstar IMAGE.SQFS < archive.tar
Create a Squashfs image named IMAGE.SQFS from the tar archive archive.tar.
sqfstar -root-owned IMAGE.SQFS < archive.tar
Create a Squashfs image named IMAGE.SQFS from archive.tar, making all files and directories owned by root.
sqfstar -comp gzip -comp-options 6 IMAGE.SQFS < archive.tar
Create a Squashfs image named IMAGE.SQFS from archive.tar using gzip compression with level 6.
sqfstar -p "my_dir d 0755 0 0" -p "my_file f 0644 0 0 hello world" IMAGE.SQFS < archive.tar
Create a Squashfs image named IMAGE.SQFS from archive.tar, adding a directory named my_dir and a file named my_file containing "hello world".
sqfstar IMAGE.SQFS file1 file2 < archive.tar
Create a Squashfs image named IMAGE.SQFS from archive.tar, excluding file1 and file2.
sqfstar IMAGE.SQFS "*.gz" < archive.tar
Create a Squashfs image named IMAGE.SQFS from archive.tar, excluding any files in the top level directory matching the pattern "*.gz".
sqfstar IMAGE.SQFS "... *.gz" < archive.tar
Create a Squashfs image named IMAGE.SQFS from archive.tar, excluding any file matching the pattern "*.gz" anywhere within the tar archive. The initial "..." indicates that the wildcard pattern is non-anchored.
sqfstar -p "build_dir d 0644 0 0" IMAGE.SQFS < archive.tar
Create a directory called "build_dir" in the output filesystem.
sqfstar -p "version.txt l /tmp/build/version" IMAGE.SQFS < archive.tar
Create a reference called "version.txt" to a file not in the tar archive, which acts as if that file was in the tar archive.
sqfstar -p "date.txt f 0644 0 0 date" IMAGE.SQFS < archive.tar
Create a file called "date.txt" which holds the output (stdout) from running the "date" command.
sqfstar -p "\"hello world\" f 0644 0 0 date" IMAGE.SQFS < archive.tar
As above, but, showing that filenames can have spaces, if they are quoted. The quotes need to be blackslashed to protect them from the shell.
sqfstar -p "input f 0644 root root dd if=/dev/sda1 bs=1024" IMAGE.SQFS < archive.tar
Create a file containing the contents of partition /dev/sda1". The above allows input from these special files to be captured and placed in the Squashfs filesystem.

Note: when passing wildcarded names to Sqfstar, they should be quoted (as in the above examples), to ensure that they are not processed by the shell.
