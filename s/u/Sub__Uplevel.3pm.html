Sub__Uplevel(3pm)

الحزمة: perl-sub-uplevel

التراخيص: GPL, PerlArtistic

Sub::Uplevel(3) وثائق بيرل المقدمة من المستخدم Sub::Uplevel(3)

الاسم

Sub::Uplevel - يبدو أنه يقوم بتشغيل دالة في إطار مكدس أعلى

الإصدار

الإصدار 0.2800

ملخص

use Sub::Uplevel;
sub foo {
    print join " - ", caller;
}
sub bar {
    uplevel 1, \&foo;
}
#line 11
bar();    # main - foo.plx - 11

الوصف

مثل دالة uplevel() في Tcl، ولكن ليس بخطورة تامة. الفكرة هي فقط خداع caller(). يتم تجنب جميع الأجزاء الخبيثة حقًا في uplevel() الخاصة بـ Tcl.

هذا ليس النوع من الأشياء التي تريد القيام بها كل يوم

uplevel
uplevel $num_frames, \&func, @args;

يجعل الدالة المعطاة تعتقد أنها تُنفذ أعلى بـ $num_frames من مستوى المكدس الحالي. لذلك، عندما تستخدم caller($frames)، فإنها ستعطي فعليًا caller($frames + $num_frames) لهم.

"uplevel(1, \&some_func, @_)" يعادل فعليًا "goto &some_func" ولكنك لا تخرج مباشرة من الإجراء الفرعي الحالي. لذلك، بينما لا يمكنك القيام بما يلي:

sub wrapper {
    print "Before\n";
    goto &some_func;
    print "After\n";
}

يمكنك القيام بما يلي:

sub wrapper {
    print "Before\n";
    my @out = uplevel 1, &some_func;
    print "After\n";
    return @out;
}

"uplevel" لديها القدرة على إصدار تحذير إذا كان $num_frames أكثر من عمق مكدس الاستدعاء الحالي، على الرغم من أن هذا التحذير معطل ويتم تجميعه خارجًا بشكل افتراضي لأن التحقق مكلف نسبيًا.

لتمكين التحقق لأغراض التصحيح أو الاختبار، يجب عليك تعيين متغير $Sub::Uplevel::CHECK_FRAMES العام على true قبل تحميل Sub::Uplevel لأول مرة كما يلي:

#!/usr/bin/perl

BEGIN {
    $Sub::Uplevel::CHECK_FRAMES = 1;
}
use Sub::Uplevel;

لن يكون لتعيين أو تغيير المتغير العام بعد تحميل الوحدة أي تأثير.

مثال

السبب الرئيسي الذي جعلني أكتب هذه الوحدة هو حتى أتمكن من كتابة أغلفة حول الدوال ولا تكون على علم بأنها قد تم تغليفها.

use Sub::Uplevel;
my $original_foo = \&foo;
*foo = sub {
    my @output = uplevel 1, $original_foo;
    print "foo() returned:  @output";
    return @output;
};

إذا كان هذا الكود يخيفك، فلا يجب عليك استخدام هذه الوحدة.

الأخطاء والملاحظات

حسنًا، الخبر السيء هو أن uplevel() أبطأ بحوالي 5 مرات من استدعاء دالة عادي. هل يبحث أحد عن تنفيذ XS؟ كما أنه يبطئ كل استدعاء لـ caller()، بغض النظر عما إذا كان uplevel() ساري المفعول أم لا.

تقوم Sub::Uplevel بتجاوز CORE::GLOBAL::caller مؤقتًا لنطاق كل استدعاء uplevel. تبذل قصارى جهدها للعمل مع أي CORE::GLOBAL::caller موجود سابقًا (كل من عند تحميل Sub::Uplevel لأول مرة وداخل كل استدعاء uplevel) مثل تلك القادمة من Contextual::Return أو Hook::LexWrap.

ومع ذلك، إذا كنت تستخدم بشكل روتيني وحدات متعددة تتجاوز CORE::GLOBAL::caller، فمن المحتمل أنك تطلب المتاعب.

يجب عليك تحميل Sub::Uplevel في أقرب وقت ممكن داخل برنامجك. كما هو الحال مع جميع التحميلات الزائدة لـ CORE::GLOBAL، لن يؤثر التحميل الزائد على الوحدات التي تم تجميعها بالفعل قبل التحميل الزائد. وحدة واحدة غالبًا ما يتم تحميلها بشكل لا مفر منه قبل Sub::Uplevel هي Exporter. لإعادة تجميع Exporter (و Exporter::Heavy) بالقوة بعد تحميل Sub::Uplevel، استخدمها مع العلامة ":aggressive":

use Sub::Uplevel qw/:aggressive/;

قد يتم تمرير الدالة الخاصة Sub::Uplevel::_force_reload() قائمة بالوحدات الإضافية لإعادة تحميلها إذا لم تكن ":aggressive" عدوانية بما فيه الكفاية. قد يؤدي إعادة تحميل الوحدات إلى كسر الأشياء، لذا استخدم هذا كملاذ أخير فقط.

اعتبارًا من الإصدار 0.20، تتطلب Sub::Uplevel Perl 5.6 أو أعلى.
