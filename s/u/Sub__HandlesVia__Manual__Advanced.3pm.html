Sub__HandlesVia__Manual__Advanced(3pm)

الحزمة: perl-sub-handlesvia

التراخيص: PerlArtistic, GPL

Sub::HandlesVia::Manual::Advanced(3) وثائق Perl المساهمة من قبل المستخدم Sub::HandlesVia::Manual::Advanced(3)

الاسم

Sub::HandlesVia::Manual::Advanced - وثائق متقدمة متنوعة

دليل

تنطبق المعلومات التالية بغض النظر عن أي أدوات OO تستخدمها.

سلسلة الأساليب

لنفترض أن لديك ما يلي

handles_via => 'Array',
handles     => {
  'add_food'    => 'push',
  'find_food'   => 'grep',
  'remove_food' => 'pop',
},

الآن "$kitchen->remove_food" ستزيل آخر طعام في القائمة وتعيده. ولكن ماذا لو لم نهتم بالطعام الذي تمت إزالته؟ نريد فقط إزالة الطعام والتخلص منه. يمكنك القيام بذلك:

handles_via => 'Array',
handles     => {
  'add_food'    => 'push',
  'find_food'   => 'grep',
  'remove_food' => 'pop...',
},

الآن ستعيد الطريقة "remove_food" كائن المطبخ بدلاً من إعادة الطعام. هذا يجعلها مناسبة لسلسلة استدعاءات الطرق:

# قم بإزالة أحدث ثلاثة أطعمة
$kitchen->remove_food->remove_food->remove_food;

تفويض إلى مراجع الكود

يمكنك التفويض إلى مراجع الكود:

handles_via => 'Array',
handles    => {
  'find_healthiest' => sub { my $foods = shift; ... },
}

تفويض إلى طرق مسماة

تسمح لك مكتبة معالج Sub::HandlesVia::HandlerLibrary::Blessed بالتفويض إلى طرق مسماة لكائن مبارك.

isa         => InstanceOf['HTTP::Tiny'],
handles_via => 'Blessed',
handles     => {
  'http_get'   => 'get',
  'http_post'  => 'post',
},

ومع ذلك، في Moo، Moose، Mouse، و Mite، يتم تضمين هذا النوع من التفويض، لذلك لا تحتاج حتى إلى Sub::HandlesVia!

isa         => InstanceOf['HTTP::Tiny'],
handles     => {
  'http_get'   => 'get',
  'http_post'  => 'post',
},

ومع ذلك، قد تظل مكتبة معالج Sub::HandlesVia::HandlerLibrary::Blessed مفيدة إذا كنت ترغب في استخدام ميزات Sub::HandlesVia الأخرى مثل السلسلة، أو إذا كنت تستخدم مجموعة أدوات OO مختلفة.

مثال على الجمع بين التفويض إلى طرق مسماة والتفويض بأسلوب "السمة الأصلية"... لنفترض أن "FoodList" هي فئة حيث تكون المثيلات عبارة عن مراجع مصفوفات مباركة من السلاسل.

isa         => InstanceOf['FoodList'],
handles_via => 'Array', 'Blessed',
handles     => {
  'find_food'             => 'grep',
  'find_healthiest_food'  => 'find_healthiest',
},

الآن "$kitchen->find_food($coderef)" يفعل هذا (مما يكسر التغليف ):

my @result = grep $coderef->(), @{ $kitchen->food };

ولكن نظرًا لأن "find_healthiest" ليست إحدى الطرق التي تقدمها Sub::HandlesVia::HandlerList::Array، فإن Sub::HandlesVia تفترض أنك تريد استدعائها على المصفوفة كطريقة صحيحة، لذا "$kitchen->find_healthiest_food" يفعل هذا:

$kitchen->food->find_healthiest

قد يكون من المفيد أن تكون صريحًا بشأن الطرق التي ترغب في التفويض إليها مصفوفة بأسلوب "السمة الأصلية" وأيها هي طرق مسماة لاستدعائها على كائن مبارك:

isa         => InstanceOf['FoodList'],
handles_via => [ 'Array', 'Blessed' ],
handles     => {
  'find_food'             => 'Array->grep',
  'find_healthiest_food'  => 'Blessed->find_healthiest',
},

انظر "تفويض إلى مكتبات معالج متعددة".

الوسائط المكرونة

كل هذا الحديث عن الطعام يجعلني جائعًا، ولكن بقدر ما أحب تناول الكاري الآن، هذا ليس نوع الكرينج الذي نتحدث عنه.

handles_via => 'Array',
handles     => {
  'get_food'   => 'get',
},

"$kitchen->get_food(0)" ستعيد العنصر الأول في القائمة. "$kitchen->get_food(1)" ستعيد العنصر الثاني في القائمة. وهكذا.

handles_via => 'Array',
handles     => {
  'first_food'   => [ 'get' => 0 ],
  'second_food'  => [ 'get' => 1 ],
},

أعتقد أنك تعرف بالفعل ما يفعله هذا. صحيح؟

ونعم، الكرينج يعمل مع مراجع الكود.

handles_via => 'Array',
handles     => {
  'blargy'       => [ sub { ... }, @curried ],
},

فحص وسائط أوسع

يحاول Sub::HandlesVia أن يكون صارمًا بشكل افتراضي. على سبيل المثال، إذا حددت السمة الخاصة بك "isa => ArrayRef[Int]"، فستقوم طريقتك التي تفوض إلى "push" بالتحقق من أن وسائطها عبارة عن أعداد صحيحة.

يمكنك إخباره بأن يكون أقل صرامة في التحقق من وسائط الطريقة باستخدام البادئة "~":

handles_via => 'Array',
handles     => {
  'find_food'   => '~grep',
},

تفويض إلى مكتبات معالج متعددة

قد ترغب أحيانًا في اختيار طرق للتفويض إليها من مكتبات معالج متعددة. هذا ممكن عن طريق تعيين "handles_via" إلى مصفوفة.

isa         => ArrayRef|HashRef,
handles_via => [ 'Array', 'Hash' ],
handles     => {
  the_keys     => 'keys',
  ship_shape   => 'sort_in_place',
}

هنا لديك سمة قد تكون مصفوفة أو مفتاحًا. عندما تكون مصفوفة، "$object->ship_shape" ستعمل بشكل جيد، ولكن "$object->the_keys" ستفشل فشلاً ذريعًا.

ومع ذلك، يمكن أن يكون هذا النوع من الأشياء منطقيًا إذا كان لديك كائن يفرط في تحميل كل من "@{}" و "%{}".

على وجه الخصوص، غالبًا ما يكون لمكتبة Sub::HandlesVia::HandlerLibrary::Scalar معنى بالاقتران مع المكتبات الأخرى لأن السلاسل والأعداد الصحيحة والأرقام والقيم المنطقية وحتى مراجع المصفوفات ومراجع المفاتيح ومراجع الكود، كلها قيم.

في بعض الأحيان يكون اسم الطريقة غامضًا. على سبيل المثال، توجد طريقة "get" لكل من المفاتيح والمصفوفات. في هذه الحالة، ستفوز مصفوفة لأنك أدرجتها أولاً في "handles_via".

ولكن يمكنك أن تكون محددًا:

isa         => ArrayRef|HashRef,
handles_via => [ 'Array', 'Hash' ],
handles     => {
  get_by_index => 'Array->get',
  get_by_key   => 'Hash->get',
}
