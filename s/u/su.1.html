SU(1) أوامر المستخدم SU(1)

الاسم

su - تشغيل أمر بمعرف مستخدم ومجموعة بديلين

الملخص

su [خيارات] [-] [مستخدم [وسيطة...]]

الوصف

يسمح su بتشغيل الأوامر بمعرف مستخدم ومجموعة بديلين.

عند استدعائه بدون تحديد مستخدم، يقوم su افتراضيًا بتشغيل shell تفاعلي كـ root. عند تحديد مستخدم، يمكن توفير وسيطات إضافية، وفي هذه الحالة يتم تمريرها إلى shell.

للتوافق مع الإصدارات السابقة، يقوم su افتراضيًا بعدم تغيير الدليل الحالي وتعيين متغيرات البيئة فقط HOME و SHELL (بالإضافة إلى USER و LOGNAME إذا كان المستخدم الهدف ليس root). يوصى دائمًا باستخدام الخيار --login (بدلاً من اختصاره -) لتجنب الآثار الجانبية الناتجة عن خلط البيئات.

يستخدم هذا الإصدار من su نظام PAM للمصادقة وإدارة الحسابات والجلسات. يجب تكوين بعض خيارات التكوين الموجودة في تطبيقات su الأخرى، مثل دعم مجموعة العجلات (wheel group)، عبر PAM.

تم تصميم su بشكل أساسي للمستخدمين غير المميزين، والحل الموصى به للمستخدمين المميزين (مثل النصوص البرمجية التي ينفذها root) هو استخدام أمر runuser(1) غير set-user-ID الذي لا يتطلب المصادقة ويوفر تكوين PAM منفصل. إذا لم تكن جلسة PAM مطلوبة على الإطلاق، فإن الحل الموصى به هو استخدام أمر setpriv(1).

لاحظ أن su في جميع الحالات يستخدم PAM (pam_getenvlist(3)) لإجراء التعديل النهائي للبيئة. تؤثر خيارات سطر الأوامر مثل --login و --preserve-environment على البيئة قبل تعديلها بواسطة PAM.

منذ الإصدار 2.38، يقوم su بإعادة تعيين حدود موارد العملية RLIMIT_NICE، RLIMIT_RTPRIO، RLIMIT_FSIZE، RLIMIT_AS، و RLIMIT_NOFILE.

الخيارات

-c, --command أمر

يمرر الأمر إلى shell مع الخيار -c.

-f, --fast

يمرر -f إلى shell، والذي قد يكون مفيدًا أو لا، اعتمادًا على shell.

-g, --group مجموعة

تحديد المجموعة الأساسية. هذا الخيار متاح لمستخدم root فقط.

-G, --supp-group مجموعة

تحديد مجموعة إضافية. هذا الخيار متاح لمستخدم root فقط. يتم أيضًا استخدام المجموعة الإضافية الأولى المحددة كمجموعة أساسية إذا لم يتم تحديد الخيار --group.

-, -l, --login

بدء shell كـ login shell مع بيئة مشابهة لـ login حقيقي.

لاحظ أنه في الأنظمة المستندة إلى systemd، قد يتم تعريف جلسة جديدة كنقطة دخول حقيقية للنظام. ومع ذلك، لا يقوم su بإنشاء جلسة حقيقية (من وجهة نظر PAM). تحتاج إلى استخدام أدوات مثل systemd-run أو machinectl لبدء جلسة كاملة وحقيقية.

يقوم su بما يلي:

• مسح جميع متغيرات البيئة باستثناء TERM والمتغيرات المحددة بواسطة --whitelist-environment
• تهيئة متغيرات البيئة HOME، SHELL، USER، LOGNAME، و PATH
• التغيير إلى الدليل المنزلي للمستخدم الهدف
• تعيين argv[0] للـ shell إلى '-' لجعل الـ shell login shell

-m, -p, --preserve-environment

الحفاظ على البيئة بأكملها، أي عدم تعيين HOME، SHELL، USER أو LOGNAME. يتم تجاهل هذا الخيار إذا تم تحديد الخيار --login.

-P, --pty

إنشاء طرفية زائفة (pseudo-terminal) للجلسة. توفر الطرفية المستقلة أمانًا أفضل حيث لا يشارك المستخدم طرفية مع الجلسة الأصلية. يمكن استخدام هذا لتجنب حقن الأوامر في الطرفية عبر TIOCSTI ioctl وهجمات الأمان الأخرى على واصفات ملفات الطرفية. يمكن أيضًا نقل الجلسة بأكملها إلى الخلفية (على سبيل المثال، su --pty - مستخدم -c تطبيق &). إذا تم تمكين الطرفية الزائفة، فإن su يعمل كوكيل بين الجلسات (مزامنة الإدخال القياسي والإخراج القياسي).

هذه الميزة مصممة بشكل أساسي للجلسات التفاعلية. إذا لم يكن الإدخال القياسي طرفية، بل على سبيل المثال تدفق (pipe) (مثل echo "date" | su --pty)، فسيتم تعطيل علامة ECHO للطرفية الزائفة لتجنب إخراج مشوش.

-s, --shell shell

تشغيل shell المحدد بدلاً من الافتراضي. إذا كان للمستخدم الهدف shell مقيد (أي غير مدرج في /etc/shells)، فسيتم تجاهل الخيار --shell ومتغير البيئة SHELL ما لم يكن المستخدم المتصل هو root.

يتم اختيار shell المراد تشغيله وفقًا للقواعد التالية، بالترتيب:

• shell المحدد باستخدام --shell
• shell المحدد في متغير البيئة SHELL، إذا تم استخدام الخيار --preserve-environment
• shell المدرج في إدخال passwd للمستخدم الهدف
• /bin/sh

--session-command=أمر

نفس -c، ولكن لا ينشئ جلسة جديدة. (غير مستحسن.)

-T, --no-pty

لا تنشئ طرفية زائفة، عكس --pty و -P. لاحظ أن التشغيل بدون طرفية زائفة يفتح خطر أمني يتمثل في تصعيد الامتيازات من خلال حقن الأوامر ioctl TIOCSTI/TIOCLINUX.

-w, --whitelist-environment قائمة

لا تقم بإعادة تعيين متغيرات البيئة المحددة في القائمة المفصولة بفواصل عند مسح البيئة لـ --login. يتم تجاهل القائمة البيضاء لمتغيرات البيئة HOME، SHELL، USER، LOGNAME، و PATH.

-h, --help

عرض نص المساعدة والخروج.

-V, --version

عرض الإصدار والخروج.

الإشارات

عند تلقي SIGINT أو SIGQUIT أو SIGTERM، يقوم su بإنهاء ابنه وبعد ذلك ينهي نفسه بالإشارة المستلمة. يتم إنهاء الابن بواسطة SIGTERM، وبعد محاولة فاشلة وتأخير لمدة 2 ثانية، يتم قتل الابن بواسطة SIGKILL.

ملفات التكوين

يقرأ su ملفي التكوين /etc/default/su و /etc/login.defs. عناصر التكوين التالية ذات صلة بـ su:

FAIL_DELAY (رقم)

التأخير بالثواني في حالة فشل المصادقة. يجب أن يكون الرقم عددًا صحيحًا غير سالب.

ENV_PATH (سلسلة نصية)

يحدد متغير البيئة PATH لمستخدم عادي. القيمة الافتراضية هي /usr/local/bin:/bin:/usr/bin.

ENV_ROOTPATH (سلسلة نصية)، ENV_SUPATH (سلسلة نصية)

يحدد متغير البيئة PATH لـ root. ENV_SUPATH له الأولوية. القيمة الافتراضية هي /usr/local/sbin:/usr/local/bin:/sbin:/bin:/usr/sbin:/usr/bin.

ALWAYS_SET_PATH (قيمة منطقية)

إذا تم تعيينها على yes ولم يتم تحديد --login و --preserve-environment، يقوم su بتهيئة PATH.

قد يكون متغير البيئة PATH مختلفًا على الأنظمة حيث يتم دمج /bin و /sbin في /usr؛ يتأثر هذا المتغير أيضًا بخيار سطر الأوامر --login وإعداد نظام PAM (على سبيل المثال، pam_env(8)).

US

su normally returns the exit status of the command it executed. If the command was killed by a signal, su returns the number of the signal plus 128.

Exit status generated by su itself:

1

Generic error before executing the requested command

126

The requested command could not be executed

127

The requested command was not found

FILES

/etc/pam.d/su

default PAM configuration file

/etc/pam.d/su-l

PAM configuration file if --login is specified

/etc/default/su

command specific logindef config file

/etc/login.defs

global logindef config file

NOTES

For security reasons, su always logs failed log-in attempts to the btmp file, but it does not write to the lastlog file at all. This solution can be used to control su behavior by PAM configuration. If you want to use the pam_lastlog(8) module to print warning message about failed log-in attempts then pam_lastlog(8) has to be configured to update the lastlog file as well. For example by:

session required pam_lastlog.so nowtmp

HISTORY

This su command was derived from coreutils' su, which was based on an implementation by David MacKenzie. The util-linux version has been refactored by Karel Zak.

ملاحظات

لأسباب أمنية، يقوم su دائمًا بتسجيل محاولات تسجيل الدخول الفاشلة في ملف btmp، ولكنه لا يكتب إلى ملف lastlog على الإطلاق. يمكن استخدام هذا الحل للتحكم في سلوك su بواسطة تكوين PAM. إذا كنت ترغب في استخدام الوحدة النمطية pam_lastlog(8) لطباعة رسالة تحذير حول محاولات تسجيل الدخول الفاشلة، فيجب تكوين pam_lastlog(8) لتحديث ملف lastlog أيضًا. على سبيل المثال:
