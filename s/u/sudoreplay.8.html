sudoreplay(8)

الحزمة: sudo

التراخيص: custom

SUDOREPLAY(8) دليل مدير النظام SUDOREPLAY(8)

الاسم

sudoreplay — إعادة تشغيل سجلات جلسات sudo

الملخص

sudoreplay [-FhnRS] [-d dir] [-f filter] [-m num] [-s num] ID[@offset]

sudoreplay [-h] [-d dir] -l [بحث تعبير]

الوصف

sudoreplay يعيد تشغيل أو يسرد سجلات الإخراج التي أنشأتها sudo. عند إعادة التشغيل، يمكن لـ sudoreplay إعادة تشغيل الجلسة بالوقت الفعلي، أو قد يتم تعديل سرعة إعادة التشغيل (أسرع أو أبطأ) بناءً على خيارات سطر الأوامر.

يجب أن يكون ID إما تسلسلًا من ستة أحرف من الأرقام والأحرف الكبيرة، على سبيل المثال، "0100A5" أو اسم مسار. قد يتضمن ID لاحقة اختيارية @offset والتي يمكن استخدامها لبدء إعادة التشغيل عند إزاحة زمنية محددة. يتم تحديد @offset كرقم بالثواني منذ بداية الجلسة مع جزء عشري اختياري.

قد تكون أسماء المسارات نسبية إلى دليل سجل الإدخال/الإخراج /var/log/sudo-io (ما لم يتم تجاوزه بواسطة الخيار -d) أو مؤهلة بالكامل، تبدأ بحرف ''/''. عند تشغيل أمر عبر sudo مع تمكين log_output في ملف sudoers، يتم تسجيل سلسلة "TSID=ID" عبر syslog(3) أو إلى ملف سجل sudo. يمكن أيضًا تحديد ID باستخدام وضع القائمة في sudoreplay.

في وضع القائمة، يمكن استخدام sudoreplay للعثور على معرف الجلسة بناءً على عدد من المعايير مثل المستخدم، tty، أو الأمر الذي تم تشغيله.

في وضع إعادة التشغيل، إذا كان الإدخال والإخراج القياسيان متصلين بطرفية ولم يتم تحديد الخيار -n، فسيعمل sudoreplay بشكل تفاعلي. في الوضع التفاعلي، سيحاول sudoreplay تعديل حجم الطرفية لتتناسب مع حجم الجلسة والكتابة مباشرة إلى الطرفية (لا تدعم جميع الطرفيات هذا). بالإضافة إلى ذلك، سيقوم باستقصاء لوحة المفاتيح والتصرف بناءً على المفاتيح التالية:

''\n'' أو ''\r''
تجاوز الحدث التالي لإعادة التشغيل؛ مفيد للتوقفات الطويلة.
''“ ”'' (مسافة)
إيقاف الإخراج مؤقتًا؛ اضغط على أي مفتاح للاستئناف.
''<''
تقليل سرعة إعادة التشغيل إلى النصف.
''>''
مضاعفة سرعة إعادة التشغيل.

يمكن مقاطعة الجلسة عبر Ctrl-C. عند انتهاء الجلسة، يتم استعادة الطرفية إلى حجمها الأصلي إذا تم تغييرها أثناء إعادة التشغيل.

الخيارات هي كما يلي:

-d dir, --directory=dir
تخزين سجلات الجلسات في dir بدلاً من الافتراضي، /var/log/sudo-io.
-f filter, --filter=filter
تحديد أنواع الإدخال/الإخراج التي سيتم عرضها. افتراضيًا، sudoreplay سيعرض الإخراج القياسي، الخطأ القياسي، وإخراج tty للأمر. الوسيطة filter هي قائمة مفصولة بفواصل، تتكون من واحدة أو أكثر مما يلي: stdin، stdout، stderr، ttyin، و ttyout.
-F, --follow
تمكين وضع "المتابعة". عند إعادة تشغيل جلسة، سيقوم sudoreplay بتجاهل نهاية الملف وسيستمر في إعادة التشغيل حتى يكتمل السجل. يمكن استخدام هذا لإعادة تشغيل جلسة لا تزال قيد التقدم، مشابهة لـ "tail -f". تعتبر ملفات سجل الإدخال/الإخراج مكتملة عند إزالة بتات الكتابة من ملف توقيت الجلسة. الإصدارات من sudo قبل 1.9.1 لا تزيل بتات الكتابة عند الاكتمال.
-h, --help
عرض رسالة مساعدة قصيرة على الإخراج القياسي والخروج.
-l, --list [بحث تعبير]
تمكين وضع "القائمة". في هذا الوضع، سيقوم sudoreplay بسرد الجلسات المتاحة بتنسيق مشابه لتنسيق ملف سجل sudo، مرتبة حسب اسم الملف (أو رقم التسلسل). أي أحرف تحكم موجودة في بيانات السجل يتم تنسيقها في ثماني مع حرف '#' مقدمة. على سبيل المثال، يتم عرض علامة الجدولة الأفقية كـ ''#011'' ويتم عرض عودة العربة المضمنة كـ ''#015''. يتم أيضًا تنسيق المسافات في اسم الأمر والوسائط في ثماني.

إذا تم تحديد search expression، فسيتم استخدامه لتقييد المعرفات التي يتم عرضها. يتكون التعبير من المسندات التالية:

command pattern
يتم تقييمه إلى صحيح إذا كان الأمر الذي تم تشغيله يطابق تعبير نمط POSIX الممتد pattern.
cwd directory
يتم تقييمه إلى صحيح إذا تم تشغيل الأمر مع دليل العمل الحالي المحدد.
fromdate date
يتم تقييمه إلى صحيح إذا تم تشغيل الأمر في تاريخ date أو بعده. انظر تنسيق التاريخ والوقت لوصف تنسيقات التاريخ والوقت المدعومة.
group runas_group
يتم تقييمه إلى صحيح إذا تم تشغيل الأمر مع runas_group المحدد. ما لم يتم تحديد runas_group بشكل صريح عند تشغيل sudo، سيكون هذا الحقل فارغًا في السجل.
host hostname
يتم تقييمه إلى صحيح إذا تم تشغيل الأمر على hostname المحدد.
runas runas_user
يتم تقييمه إلى صحيح إذا تم تشغيل الأمر باسم runas_user المحدد. افتراضيًا، يقوم sudo بتشغيل الأوامر باسم المستخدم root.
todate date
يتم تقييمه إلى صحيح إذا تم تشغيل الأمر في تاريخ date أو قبله. انظر تنسيق التاريخ والوقت لوصف تنسيقات التاريخ والوقت المدعومة.
tty tty name
يتم تقييمه إلى صحيح إذا تم تشغيل الأمر على جهاز الطرفية المحدد. يجب تحديد tty name بدون البادئة /dev/، على سبيل المثال، tty01 بدلاً من /dev/tty01.
user user name
يتم تقييمه إلى صحيح إذا كان المعرف يطابق أمرًا قام بتشغيله user name.

يمكن اختصار المسندات إلى أقصر سلسلة فريدة.

يمكن دمج المسندات باستخدام عوامل التشغيل and، or، و ! بالإضافة إلى الأقواس '' sudo(8)

sudo(8)

NAME

sudo – enable a user to run commands as another user

SYNOPSIS

sudo [-Ab ] [- ] [-C filename] [-g group] [-h | -H] [-P] [-u user] [-s | -i] [- ] [command]

sudoreplay [-d | -F] [-k path] [file ...]

DESCRIPTION

sudo stands for "superuser do" or "substitute user do". It allows a permitted user to execute a command as the superuser or another user, as specified by the security policy.

The sudoers file (typically /etc/sudoers) specifies which users may run which commands on which machines and as which other users.

When sudo is run, it checks the sudoers file to see if the invoking user is allowed to run the command. If the user is allowed, sudo will prompt for the user's password (unless the NOPASSWD option is set in the sudoers file or the user has recently authenticated). If the password is correct, sudo executes the command specified.

The command may be a simple command, a shell built-in, or a command with arguments.

If no command is specified, sudo will run the user's default shell.

sudoreplay is used to replay a session logged by sudo with the log_output option.

FILES

/etc/sudoers
The security policy file.
/etc/sudoers.d/
Directory for additional sudoers files.
/var/log/auth.log
Default log file for sudo activity.

EXAMPLES

Run a command as root:
sudo apt update

Run a shell as root:
sudo -s

Run a command as another user:
sudo -u www-data ls /var/www
