الوصف

ما هو المصدر؟

عندما تقوم "use" بوحدة نمطية، يتم طلبها أولاً، ثم يتم استدعاء دالة "import" الخاصة بها. تخبرنا وثائق Perl أن السطرين التاليين متكافئان:

use Module LIST;
BEGIN { require Module; Module->import(LIST); }

الدالة المسماة "import" هي مصدر الوحدة النمطية، فهي تصدّر دوال ومتغيرات إلى مساحة أسماء المستدعي لها.

أساسيات Sub::Exporter

يقوم Sub::Exporter ببناء مصدر مخصص يمكن تثبيته بعد ذلك في وحدتك النمطية. يبني هذه الدالة بناءً على التكوين المقدم إلى دالة "setup_exporter" الخاصة به.

قد تبدو حالة استخدام بسيطة جدًا كالتالي:

package Addition;
use Sub::Exporter;
Sub::Exporter::setup_exporter({ exports => [ qw(plus) ]});
sub plus { my ($x, $y) = @_; return $x + $y; }

هذا يعني أنه عندما يستخدم شخص ما وحدة Addition الخاصة بك، يمكنه استيراد روتين "plus" الخاص بها إلى حزمته:

use Addition qw(plus);
my $z = plus(2, 2); # هذا يعمل، لأنه الآن plus موجود في الحزمة الرئيسية

هذه الصيغة لإعداد المصدر، أعلاه، verbose قليلاً، لذلك لحالة تسمية التصديرات فقط، يمكنك كتابة هذا:

use Sub::Exporter -setup => { exports => [ qw(plus) ] };

... وهو نفس المثال الأصلي -- باستثناء أن المصدر الآن تم بناؤه وتثبيته في وقت الترجمة. حسنًا، هذا، وأنك كتبت أقل.

استخدام مجموعات التصدير

يمكنك تحديد مجموعات كاملة من الأشياء التي يمكن تصديرها معًا. تسمى هذه المجموعات. يسميها المصدر علامات. لتحديد المجموعات، ما عليك سوى تمرير مفتاح "groups" في تكوين المصدر الخاص بك:

package Food;
use Sub::Exporter -setup => {
  exports => [ qw(apple banana beef fluff lox rabbit) ],
  groups  => {
    fauna  => [ qw(beef lox rabbit) ],
    flora  => [ qw(apple banana) ],
  }
};

الآن، لاستيراد كل هذا اللحم الأجنبي اللذيذ، يحتاج المستهلك فقط إلى الكتابة:

use Food qw(:fauna);
use Food qw(-fauna);

كلاهما مقبول. النقطتان أكثر تقليدية، ولكن لا يمكن اقتباس الكلمات المجردة ذات النقطتين البادئة بواسطة سهم سمين. سنرى لماذا هذا مهم لاحقًا.

يمكن للمجموعات أن تحتوي على مجموعات أخرى. إذا قمت بتضمين اسم مجموعة (مع الشرطة أو النقطتين البادئة) في تعريف مجموعة، فسيتم توسيعها بشكل متكرر عند استدعاء المصدر. لن يتكرر المصدر في نفس المجموعة مرتين أثناء توسيع المجموعات.

هناك مجموعتان خاصتان: "all" و "default". يتم تعريف المجموعة "all" لك وتحتوي على جميع الروتينات القابلة للتصدير. يمكنك إعادة تعريفها، إذا كنت ترغب في تصدير مجموعة فرعية فقط عند طلب جميع الصادرات. المجموعة "default" هي مجموعة الروتينات المراد تصديرها عندما لا يتم طلب شيء محدد. افتراضيًا، لا توجد مجموعة "default".

إعادة تسمية الواردات الخاصة بك

في بعض الأحيان تريد استيراد شيء ما، ولكنك لا تحب الاسم الذي يتم استيراده به. يمكن لـ Sub::Exporter إعادة تسمية الواردات الخاصة بك. إذا كنت ترغب في استيراد "lox" من حزمة Food، ولكنك لا تحب الاسم، يمكنك كتابة هذا:

use Food lox => { -as => 'salmon' };

الآن ستحصل على الروتين "lox"، ولكن سيتم استدعاؤه salmon في حزمتك. يمكنك أيضًا إعادة تسمية مجموعات كاملة باستخدام خيار "prefix":

use Food -fauna => { -prefix => 'cute_little_' };

الآن يمكنك استدعاء الروتين الخاص بك "cute_little_rabbit". (يمكنك أيضًا استدعاء "cute_little_beef"، ولكن هذا لا يبدو مغريًا بقدر ذلك.)

عندما تحدد المجموعات، يمكنك تضمين إعادة التسمية.

use Sub::Exporter -setup => {
  exports => [ qw(apple banana beef fluff lox rabbit) ],
  groups  => {
    fauna  => [ qw(beef lox), rabbit => { -as => 'coney' } ],
  }
};

تطبيق بادئة على مجموعة كهذه يقوم بالعمل الصحيح. هذا هو الوقت الذي يكون فيه من المفيد استخدام شرطة بدلاً من نقطتين للإشارة إلى مجموعة: يمكنك وضع سهم سمين بين المجموعة ووسائطها، بعد ذلك.

use Food -fauna => { -prefix => 'lovely_' };
eat( lovely_coney ); # هذا يعمل

تنطبق البادئات أيضًا بشكل متكرر. هذا يعني أن هذا الكود يعمل:

use Sub::Exporter -setup => {
  exports => [ qw(apple banana beef fluff lox rabbit) ],
  groups  => {
    fauna   => [ qw(beef lox), rabbit => { -as => 'coney' } ],
    allowed => [ -fauna => { -prefix => 'willing_' }, 'banana' ],
  }
};
...
use Food -allowed => { -prefix => 'any_' };
$dinner = any_willing_coney; # لذيذ!

يمكن للمجموعات أيضًا تمرير وسيطة "-suffix".

أخيرًا، إذا كانت الوسيطة "-as" لروتين تم تصديره هي مرجع لمتغير، فسيتم وضع مرجع للروتين في هذا المتغير.

بناء الروتينات حسب الطلب

في بعض الأحيان، تريد تصدير أشياء لا تملكها. قد ترغب في تقديم روتينات مخصصة مبنية وفقًا لمواصفات المستهلك الخاص بك؛ هذا مجرد عمل جيد! مع Sub::Exporter، هذا سهل.

لتقديم روتينات حسب الطلب، تحتاج إلى توفير مولد عند إعداد المصدر الخاص بك. المولد هو مجرد روتين يعيد روتينًا جديدًا. يتحدث Perlref عن هذه عندما يناقش الإغلاقات والقوالب الوظيفية. المثال النموذجي للمولد يبني مُزيدًا فريدًا؛ إليك كيف يمكنك القيام بذلك باستخدام Sub::Exporter؛

package Package::Counter;
use Sub::Exporter -setup => {
  exports => [ counter => sub { my $i = 0; sub { $i++ } } ],
  groups  => { default => [ qw(counter) ] },
};

الآن يمكن لأي شخص استخدام وحدة Package::Counter الخاصة بك وسيحصل على "counter" في حزمته. سيتم زيادته بمقدار واحد، ولن يتعارض أبدًا مع عداد أي شخص آخر.

هذا ليس مفيدًا جدًا، رغم ذلك، إلا إذا كان المستهلك يمكنه شرح ما يريده. يتم ذلك، جزئيًا، عن طريق توفير وسائط عند الاستيراد. يوضح المثال التالي كيف يمكن للمولد أن يأخذ ويستخدم الوسائط:

package Package::Counter;
sub _build_counter {
  my ($class, $name, $arg) = @_;
  $arg ||= {};
  my $i = $arg->{start} || 0;
  return sub { $i++ };
}
use Sub::Exporter -setup => {
  exports => [ counter => \'_build_counter' ],
  groups  => { default => [ qw(counter) ] },
};

الآن، يمكن للمستهلك (إذا أراد) تحديد قيمة بدء لعداده:

use Package::Counter counter => { start => 10 };

يتم تمرير الوسائط إلى مجموعة إلى مولدات الروتينات في تلك المجموعة، ولكن لا يتم تمرير وسائط Sub::Exporter أبدًا -- أي شيء يبدأ بشرطة. عند تداخل المجموعات، يتم دمج الوسائط عند توسيع المجموعات.

لاحظ أيضًا، في المثال أعلاه، أننا قدمنا مرجعًا إلى اسم طريقة method name بدلاً من تنفيذ طريقة method implementation. من خلال تقديم الاسم بدلاً من الروتين، نجعل من الممكن للفئات الفرعية لوحدة "Package::Counter" الخاصة بنا استبدال طريقة "_build_counter".

عند استدعاء مولد، يتم تمرير أربعة معلمات إليه:

  • المُستدعى الذي تم استدعاء المصدر عليه
  • اسم التصدير الذي يتم إنشاؤه (ليس الاسم الذي يتم تثبيته به)
  • الوسائط المقدمة للروتين
  • مجموعة الوسائط العامة

العنصر الرابع هو الميزة الرئيسية الأخيرة التي لم يتم تناولها.

package Menu::Airline
use Sub::Exporter -setup => {
  exports =>  ... ,
  groups  =>  ... ,
  collectors => [ qw(allergies ethics) ],
};

Collectors look like normal exports in the import call, but they don't do anything but collect data which can later be passed to generators. If the module was used like this:

use Menu::Airline allergies => [ qw(peanuts) ], ethics => [ qw(vegan) ];

...the consumer would get a salad. Also, all the generators would be passed, as their fourth argument, something like this:

{ allerges => [ qw(peanuts) ], ethics => [ qw(vegan) ] }

Generators may have arguments in their definition, as well. These must be code refs that perform validation of the collected values. They are passed the collection value and may return true or false. If they return false, the exporter will throw an exception.

Generating Many Routines in One Scope

Sometimes it's useful to have multiple routines generated in one scope. This way they can share lexical data which is otherwise unavailable. To do this, you can supply a generator for a group which returns a hashref of names and code references. This generator is passed all the usual data, and the group may receive the usual "-prefix" or "-suffix" arguments.

PERL VERSION

This library should run on perls released even a long time ago. It should work on any version of perl released in the last five years.

Although it may work on older versions of perl, no guarantee is made that the minimum required version will not be increased. The version may be increased for any reason, and there is no promise that patches will be accepted to lower the minimum required perl.
