Sub::Override(3) وثائق بيرل المقدمة من المستخدم Sub::Override(3)

الاسم

Sub::Override - امتداد بيرل لتجاوز الدوال الفرعية بسهولة

الإصدار

0.12

ملخص

use Sub::Override;
sub foo { 'original sub' };
print foo(); # يطبع 'original sub'
my $override = Sub::Override->new( foo => sub { 'overridden sub' } );
print foo(); # يطبع 'overridden sub'
$override->restore;
print foo(); # يطبع 'original sub'

الوصف

المشكلة

في بعض الأحيان، تحتاج الدوال الفرعية إلى التجاوز. في الواقع، يقوم مؤلفك بذلك بشكل متكرر للاختبار. خاصة عند الاختبار، قد يكون استخدام كائن وهمي (Mock Object) مبالغًا فيه عندما يكون كل ما تريده هو تجاوز وظيفة واحدة صغيرة جدًا.

غالبًا ما يتم تجاوز الدالة الفرعية باستخدام صيغة مشابهة لما يلي:

{
  local *Some::sub = sub {'some behavior'};
  # افعل شيئًا
}
# تم استعادة سلوك الدالة الفرعية الأصلي

لهذا بعض المشاكل.

{
  local *Get::some_feild = { 'some behavior' };
  # افعل شيئًا
}

في المثال أعلاه، لم نقم فقط بخطأ إملائي في اسم الدالة الفرعية، بل حتى لو كانت هناك دالة فرعية بهذا الاسم، فإننا لم نتجاوزها. يمكن أن تكون هاتان المشكلتان دقيقتين للكشف عنهما.

علاوة على ذلك، إذا كنا نحاول تقييد التأثير بوضع هذا الكود في كتلة، فإن البناء بأكمله مربك.

يسمح Hook::LexWrap أيضًا بتجاوز سلوك الدوال الفرعية، لكنني لا أتذكر أبدًا الصيغة الدقيقة.

طريقة أسهل لاستبدال الدوال الفرعية

بدلاً من ذلك، يسمح "Sub::Override" للمبرمج بتسمية الدالة الفرعية المراد استبدالها ببساطة وتوفير دالة فرعية لاستبدالها بها.

my $override = Sub::Override->new('Some::sub', sub {'new data'});
# وهو ما يعادل:
my $override = Sub::Override->new;
$override->replace('Some::sub', sub { 'new data' });

يمكنك استبدال دوال فرعية متعددة، إذا لزم الأمر:

$override->replace('Some::sub1', sub { 'new data1' });
$override->replace('Some::sub2', sub { 'new data2' });
$override->replace('Some::sub3', sub { 'new data3' });

إذا نجح استبدال الدالة الفرعية، يتم إرجاع الكائن. هذا يسمح للمبرمج بتسلسل الاستدعاءات، إذا كان هذا النمط من البرمجة مفضلاً:

$override->replace('Some::sub1', sub { 'new data1' })
         ->replace('Some::sub2', sub { 'new data2' })
         ->replace('Some::sub3', sub { 'new data3' });

إذا كانت الدالة الفرعية تحتوي على نموذج أولي (prototype)، فيجب تعريف الدالة الفرعية الجديدة بنفس النموذج الأولي للدالة الأصلية:

$override->replace('Some::sub_with_proto', sub ($$) { ($_[0], $_ [1]) });

يمكن استبدال الدالة الفرعية عدة مرات حسب الرغبة. هذا مفيد بشكل خاص عند اختبار سلوك الكود بشروط متعددة.

$override->replace('Some::thing', sub { 0 });
is($object->foo, 'wibble', 'wibble is returned if Some::thing is false');
$override->replace('Some::thing', sub { 1 });
is($object->foo, 'puppies', 'puppies are returned if Some::thing is true');

إدخال دالة فرعية

إذا كنت ترغب في إدخال دالة فرعية في حزمة (package)، يمكنك استخدام التابع inject(). هذا مطابق لـ replace()، باستثناء أنه يتطلب ألا توجد الدالة الفرعية:

$override->inject('Some::sub', sub {'new data'});

هذا مفيد إذا كنت ترغب في إضافة دالة فرعية إلى حزمة لا تحتوي عليها بالفعل.

إذا حاولت إدخال دالة فرعية موجودة بالفعل، فسيتم طرح استثناء (exception).

$override->inject('Some::sub', sub {'new data'}); # يعمل
$override->inject('Some::sub', sub {'new data'}); # يطرح استثناء

سيؤدي استدعاء restore() أو السماح لـ $override بالخروج من النطاق إلى إزالة الدالة الفرعية المدخلة.

$override->inject('Some::sub', sub {'new data'});
$override->restore('Some::sub'); # يزيل الدالة الفرعية المدخلة

وراثة دالة فرعية

على غرار 'inject'، يسمح 'inherit' فقط بإنشاء دالة فرعية جديدة في كائن فرعي يرث الدالة من الكائن الأصلي، ولا توجد في الكائن الفرعي:

package Parent;
sub foo {}
sub bar {}
package Child;
use parent 'Parent';
sub foo {}

سيسمح 'Inherit' بإعداد دالة فرعية جديدة 'Child::bar' نظرًا لأنها موروثة من Parent. محاولة 'inherit' لـ 'Child::foo' ستؤدي إلى طرح استثناء لأن 'foo' موجود بالفعل في Child. وبالمثل، فإن محاولة 'inherit' لدالة فرعية جديدة 'something' في Child ستؤدي أيضًا إلى طرح استثناء نظرًا لأنها غير موجودة في Parent ولن ترثها Child.

تغليف دالة فرعية

قد تكون هناك أوقات تريد فيها استبدال دالة فرعية 'بشكل شرطي' - على سبيل المثال، لتجاوز الدالة الفرعية الأصلية فقط إذا تم تمرير وسائط معينة. لهذا يمكنك تحديد "wrap" بدلاً من "replace". "wrap" مطابق لـ "replace"، باستثناء أن الدالة الفرعية الأصلية يتم تمريرها كوسيط أول إلى دالتك الجديدة. يمكنك استدعاء الدالة الفرعية الأصلية عبر 'shift->(@_)':

$override->wrap('Some::sub',
  sub {
    my ($old_sub, @args) = @_;
    return 1 if $args[0];
    return $old_sub->(@args);
  }
);

استعادة الدوال الفرعية

إذا خرج الكائن من النطاق، يتم استعادة الدوال الفرعية الأصلية. ومع ذلك، إذا كنت بحاجة إلى استعادة دالة فرعية مبكرًا، فاستخدم التابع restore():

my $override = Sub::Override->new('Some::sub', sub {'new data'});
# افعل أشياء
$override->restore;

وهو ما يعادل إلى حد ما:

{
  my $override = Sub::Override->new('Some::sub', sub {'new data'});
  # افعل أشياء
}

إذا قمت بتجاوز أكثر من دالة فرعية واحدة بكائن تجاوز، فسيتعين عليك تحديد اسم الدالة الفرعية التي ترغب في استعادتها صراحةً:

$override->restore('This::sub');

لاحظ أن restore() ستستعيد دائمًا السلوك الأصلي للدالة الفرعية بغض النظر عن عدد المرات التي قمت فيها بتجاوزها.

في أي حزمة توجد الدالة الفرعية؟

عادةً، تريد التأهيل الكامل للدالة الفرعية عن طريق تضمين اسم الحزمة. ومع ذلك، فإن الفشل في التأهيل الكامل لاسم الدالة الفرعية يفترض الحزمة الحالية.

package Foo;
use Sub::Override;
sub foo { 23 };
my $override = Sub::Override->new( foo => sub { 42 } ); # يفترض Foo::foo
print foo(); # يطبع 42
$override->restore;
print foo(); # يطبع 23

التوابع

new

my $sub = Sub::Override->new;
my $sub = Sub::Override->new($sub_name, $sub_ref);

ينشئ مثيلاً جديدًا لـ "Sub::Override". اختياريًا، يمكنك تجاوز دالة فرعية أثناء إنشاء كائن جديد.

replace

$sub->replace($sub_name, $sub_body);

يستبدل دالة فرعية مؤقتًا بدالة فرعية أخرى. يعيد المثيل، لذا فإن تسلسل التابع مسموح به:

$sub->replace($sub_name, $sub_body)
    ->replace($another_sub, $another_body);

هذا التابع سيقوم بـ "croak" (إصدار خطأ فادح) إذا كانت الدالة الفرعية المراد استبدالها غير موجودة.

override

my $sub = Sub::Override->new;
$sub->override($sub_name, $sub_body);

"override" هو اسم بديل لـ "replace". هما نفس التابع.

NAME

Sub::Override - Override subroutines safely

VERSION

0.12

SYNOPSIS

use Sub::Override;
my $sub = Sub::Override->new( 'Foo::bar' => sub { 'override' } );
# ... later, do something with Foo::bar ...
# $sub goes out of scope and Foo::bar is restored

DESCRIPTION

This module allows you to temporarily override subroutines in a package. You create a "Sub::Override" object, and it keeps track of your overrides. When the object goes out of scope, it automatically restores the original subroutines.

This is useful for testing, or for temporarily changing behavior within a specific context.

METHODS

new

my $sub = Sub::Override->new(
    'Package::name' => sub { ... },
    'Another::name' => sub { ... },
);

Creates a new "Sub::Override" object. It takes a hash of package names to subroutine bodies (coderefs). The keys are the full names of the subroutines (e.g., "MyClass::method"), and the values are the coderefs that will replace them.

replace

$sub->replace( 'Package::name' => sub { ... } );

Replaces an existing override with a new subroutine body. This is useful if you need to change the override behavior without creating a new "Sub::Override" object.

inject

$sub->inject($sub_name, $sub_body);

Temporarily injects a subroutine into a package. Returns the instance, so chaining the method is allowed:

$sub->inject($sub_name, $sub_body)
    ->inject($another_sub, $another_body);

inherit

$sub->inherit($sub_name, $sub_body);

Checks that the subroutine exists in a parent class, but not in the current class, and injects it into the current class to inherit the parent's version.

restore

$sub->restore($sub_name);

Restores the previous behavior of the subroutine. This will happen automatically if the "Sub::Override" object falls out of scope.

wrap

$sub->wrap($sub_name, $sub_body);

Temporarily wraps a subroutine with another subroutine. The original subroutine is passed as the first arg to the new subroutine.

EXPORT

None by default.

CAVEATS

If you need to override the same sub several times do not create a new "Sub::Override" object, but instead always reuse the existing one and call "replace" on it. Creating a new object to override the same sub will result in weird behavior.

# Do not do this!
my $sub_first = Sub::Override->new( 'Foo:bar' => sub { 'first' } );
my $sub_second = Sub::Override->new( 'Foo::bar' => sub { 'second' } );
# Do not do this either!
my $sub = Sub::Override->new( 'Foo::bar' => sub { 'first' } );
$sub = Sub::Override->new( 'Foo::bar' => sub { 'second' } );

Both of those usages could result in of your subs being lost, depending on the order in which you restore them.

Instead, call "replace" on the existing $sub.

my $sub = Sub::Override->new( 'Foo::bar' => sub { 'first' } );
$sub->replace( 'Foo::bar' => sub { 'second' } );
