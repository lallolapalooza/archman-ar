أمثلة

أحد أقوى الأوامر في s3cmd هو s3cmd sync المستخدم لمزامنة أشجار الدلائل الكاملة إلى أو من تخزين S3 البعيد. إلى حد ما s3cmd put و s3cmd get تشترك في سلوك مماثل مع sync.

الاستخدام الأساسي الشائع في سيناريوهات النسخ الاحتياطي بسيط مثل:

s3cmd sync /local/path/ s3://test-bucket/backup/

سيقوم هذا الأمر بالعثور على جميع الملفات تحت دليل /local/path و نسخها إلى المسارات المقابلة تحت s3://test-bucket/backup على الجانب البعيد. على سبيل المثال:

/local/path/file1.ext         ->  s3://bucket/backup/file1.ext
/local/path/dir123/file2.bin  ->  s3://bucket/backup/dir123/file2.bin

ولكن إذا كان المسار المحلي لا ينتهي بشرطة مائلة، فسيتم استخدام اسم الدليل الأخير على الجانب البعيد أيضًا. قارن هذه بالأمثلة السابقة:

s3cmd sync /local/path s3://test-bucket/backup/
سيقوم بمزامنة: 
/local/path/file1.ext         ->  s3://bucket/backup/path/file1.ext
/local/path/dir123/file2.bin  ->  s3://bucket/backup/path/dir123/file2.bin

لاستعادة الملفات من S3 استخدم الصيغة المعكوسة:

s3cmd sync s3://test-bucket/backup/ ~/restore/
سيقوم بتنزيل الملفات كـ: 
s3://bucket/backup/file1.ext         ->  ~/restore/file1.ext
s3://bucket/backup/dir123/file2.bin  ->  ~/restore/dir123/file2.bin

بدون الشرطة المائلة الختامية على المصدر، يكون السلوك مشابهًا لما تم توضيحه مع التحميل:

s3cmd sync s3://test-bucket/backup ~/restore/
سيقوم بتنزيل الملفات كـ: 
s3://bucket/backup/file1.ext         ->  ~/restore/backup/file1.ext
s3://bucket/backup/dir123/file2.bin  ->  ~/restore/backup/dir123/file2.bin

تتم مطابقة جميع أسماء ملفات المصدر، وهي الأسماء العريضة أعلاه، مع قواعد exclude ثم تتم إعادة فحصها مقابل قواعد include لمعرفة ما إذا كان يجب استبعادها أو الاحتفاظ بها في قائمة المصدر.

لغرض مطابقة --exclude و --include، يتم استخدام أسماء الملفات العريضة فقط أعلاه. على سبيل المثال، يتم اختبار /local/path/file1.ext فقط مقابل الأنماط، وليس /local/path/file1.ext

يعمل كل من --exclude و --include مع أنماط shell (المعروفة أيضًا باسم GLOB). لمزيد من المرونة، يوفر s3cmd إصدارات تعبير عادي لـ

OPTIONS

There are two exclude options named --rexclude and --rinclude. The options with ...-from suffix (eg --rinclude-from) expect a filename as an argument. Each line of such a file is treated as one pattern.

There is only one set of patterns built from all --(r)exclude(-from) options and similarly for include variant. Any file excluded with eg --exclude can be put back with a pattern found in --rinclude-from list.

Run s3cmd with --dry-run to verify that your rules work as expected. Use together with --debug get detailed information about matching file names against exclude and include rules.

For example to exclude all files with ".jpg" extension except those beginning with a number use:

--exclude '*.jpg' --rinclude '[0-9].*.jpg'

To exclude all files except "*.jpg" extension, use:

--exclude '*' --include '*.jpg'

To exclude local directory 'somedir', be sure to use a trailing forward slash, as such:

--exclude 'somedir/'
