Detailed Description

The SoVRMLCylinderSensor class maps pointer motion into rotations about the Y axis.

The detailed class description is taken verbatim from the VRML97 standard(ISO/IEC 14772-1:1997). It is copyrighted by the Web3D Consortium and used with the Consortium's permission: 

CylinderSensor {
  exposedField SFBool     autoOffset TRUE
  exposedField SFFloat    diskAngle  0.262       # (0,/2)
  exposedField SFBool     enabled    TRUE
  exposedField SFFloat    maxAngle   -1          # [-2,2]
  exposedField SFFloat    minAngle   0           # [-2,2]
  exposedField SFFloat    offset     0           # (-inf, inf)
  eventOut     SFBool     isActive
  eventOut     SFRotation rotation_changed
  eventOut     SFVec3f    trackPoint_changed
}

The CylinderSensor node maps pointing device motion (e.g., a mouse or pen) into a rotation within an invisible cylinder aligned with the local coordinate system's Y axis. The CylinderSensor uses the geometry descended from its parent node to determine if it is capable of generating events.

The enabled field enables and disables the CylinderSensor node. If TRUE, the sensor reacts appropriately to user events. If FALSE, the sensor does not track user input or send events. If the enabled event is FALSE and isActive is TRUE, the sensor is disabled and deactivated, emitting an isActive FALSE event. If the enabled event is TRUE, the sensor is enabled and ready for user activation.

A CylinderSensor node generates events when the pointing device is active while the pointer indicates any geometry descended from the sensor's geometry. See 4.6.7.5, Sensor activation and manipulation (http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.6.7.5), for details on using the pointing device to activate the CylinderSensor .

Once the pointing device is activated while indicating the sensor's geometry, an isActive TRUE event is sent. The acute angle between the track vector and the local Y axis of the CylinderSensor node determines whether the sides of the invisible cylinder or the ends (disks) are used for manipulation. If the initial angle is less than diskAngle , the geometry is treated as an infinitely large disk lying in the local Y=0 plane and coincident with the initial intersection point. Manipulation of pointer motion is mapped into a rotation about the +Y vector of the sensor's coordinate system. The vector perpendicular from the initial intersection point to the Y axis defines a zero rotation about the Y axis. For each subsequent track point, an rotation_changed event is sent which is the sum of the rotation about the +Y vector (from the initial intersection to the new intersection) plus the offset value. trackPoint_changed events reflect the unconstrained sliding position on the disk surface. When the pointing device is deactivated and autoOffset is TRUE, the offset value is set to the last rotation_changed value and an offset_changed event is sent. See 4.6.7.4, Drag sensors (http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.6.7.4), for a more general description of the autoOffset and offset fields.

If the acute angle between the track vector and the local Y axis of the CylinderSensor node is greater than or equal to diskAngle , the sensor behaves like a cylinder. The radius of an invisible cylinder is determined by the shortest distance between the intersection point (between the track and the sensor geometry) and the Y axis of the parent group's local coordinate system. This radius is used to map the pointing device motion and marks the zero rotation value. For each subsequent track point, an rotation_changed event is sent which is the sum of the right-hand rotation about the +Y vector (from the original intersection to the new intersection) plus the offset value. trackPoint_changed events reflect the unconstrained sliding position on the surface of the invisible cylinder. When the pointing device is deactivated and autoOffset is TRUE, the offset value is set to the last rotation angle and an offset_changed event is sent. More details are available in 4.6.7.4, Drag sensors (http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.6.7.4).

When the sensor generates an isActive TRUE event, it captures all subsequent pointing device motion events from the sensor's activation point.

وصف تفصيلي

يعمل هذا المستشعر على تتبع حركة جهاز التأشير عند تشغيله. يتم إخراج أحداث isActive TRUE عند بدء التفاعل مع المستشعر (مثل الضغط على زر الفأرة فوقه) و isActive FALSE عند الانتهاء. لا تقوم أجهزة التأشير الأخرى بإصدار أحداث أثناء فترة isActive TRUE. تسمى حركة جهاز التأشير أثناء isActive TRUE بـ "السحب" (drag). بالنسبة لجهاز تأشير ثنائي الأبعاد، عادةً ما تعكس أحداث isActive حالة الزر الأساسي (TRUE عند الضغط، FALSE عند الإفلات). بالنسبة لجهاز تأشير ثلاثي الأبعاد (مثل عصا التحكم)، قد تعكس isActive ما إذا كان المؤشر داخل أو ملامسًا لهندسة المستشعر.

أثناء تنشيط جهاز التأشير، يتم إخراج أحداث trackPoint_changed و rotation_changed، والتي تُفسر من حركة جهاز التأشير بناءً على نظام الإحداثيات المحلي للمستشعر وقت التنشيط. تمثل أحداث trackPoint_changed نقاط التقاطع غير المقيدة على سطح الأسطوانة أو القرص غير المرئي. إذا أدى الزاوية الأولية إلى دوران أسطواني (بدلاً من سلوك القرص) وتم سحب جهاز التأشير بعيدًا عن الأسطوانة أثناء التنشيط، فقد يفسر المتصفح ذلك بطرق مختلفة (مثل، قص جميع القيم إلى الأسطوانة والاستمرار في الدوران أثناء سحب النقطة بعيدًا عن الأسطوانة). كل حركة لجهاز التأشير أثناء isActive TRUE تولد أحداث trackPoint_changed و rotation_changed. تحدد حقلا minAngle و maxAngle نطاق أحداث rotation_changed. إذا كان minAngle أكبر من maxAngle، فلن يتم قص أحداث rotation_changed.

تقتصر حقلا minAngle و maxAngle على النطاق [-2، 2]. مزيد من المعلومات حول هذا السلوك موضحة في الأقسام 4.6.7.3، مستشعرات جهاز التأشير، 4.6.7.4، مستشعرات السحب (http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.6.7.4)، و 4.6.7.5 (http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.6.7.5)، تنشيط ومعالجة المستشعرات.
