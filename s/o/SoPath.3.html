الوصف المفصل

فئة SoPath هي فئة حاوية لوصف مسارات الاجتياز.

تحتوي كائنات SoPath على قائمة بمؤشرات SoNode وقائمة بفهارس الأبناء. الفهارس ضرورية لتمييز المواقف التي يستخدم فيها عقدة نفس العقدة كابن لها عدة مرات.

يمكن تصدير واستيراد المسارات من/إلى الملف، مثل الكائنات الأخرى المشتقة من SoBase. اقرأ التوثيق حول دالة write() لمعرفة شكل الملف.

من المهم معرفة الفرق بين هذه الفئة و SoFullPath عند العمل مع المسارات. ستعيد SoPath::getTail() أول عقدة في المسار التي لا ترث SoGroup، و getLength() تعيد عدد العقد حتى هذه العقدة.

إذا كنت بحاجة إلى طول المسار الفعلي، أو العقدة الذيل الفعلية، فأنت بحاجة إلى تحويل المسار إلى SoFullPath.

void SoPath::removeIndex (SoNode *const parent, const int oldindex)

يتم استدعاء هذه الدالة عندما تتم إزالة عقدة في سلسلة المسار، لتحديث فهرس طفلها.

oldindex كان فهرس الطفل الذي تمت إزالته. إذا كان oldindex أقل من أو يساوي قيمة الفهرس للعقدة الابنة المخزنة في المسار، يتم تحديث المسار وفقًا لذلك.

void SoPath::replaceIndex (SoNode *const parent, const int index, SoNode *const newchild)

يتم استدعاء هذه الدالة عندما تقوم عقدة newchild باستبدال عقدة في المسار. index هو موضع الطفل الذي تم استبداله.

SbBool SoPath::isRelevantNotification (SoNotList *const l) const

إرجاع TRUE إذا كانت سلسلة الإشعارات l ستؤثر على المسار. سيؤثر l على المسار إما إذا كان الإشعار في المسار (بدأ الإشعار في حقل في عقدة في المسار)، أو خارج المسار (بدأ الإشعار في عقدة غير فاصلة تقع يسار عقدة المسار).

void SoPath::write (SoWriteAction * action) [virtual]

تستخدم هذه الدالة لكتابة محتويات SoPath.

يتم كتابة المسار على النحو التالي:

Path {
  HEAD-NODE-OF-SUBGRAPH
  NUMBER-OF-INDICES
  INDEX0
  INDEX1
  ...
}

[يشرح بقية الوثائق لهذه الدالة فقط سبب حدوث اختلاف في السلوك بين Open Inventor الأصلي و Coin. لا تقرأها إذا لم تكن مهتمًا بشكل خاص. (ملخص قصير: نقوم بتصدير SoPath بطريقة أقل كفاءة إلى حد ما لتجنب احتمالية حدوث أخطاء).]

لاحظ أنه بخلاف Open Inventor، نقوم بكتابة الرسم البياني الفرعي الكامل أسفل العقدة الرأسية. كتابة أجزاء فقط من الرسم البياني الفرعي التي تؤثر على الحالة للعقد داخل المسار عرضة للخطأ إذا تم تصدير رسم بياني فرعي كجزء من مسار قبل تصديره "بشكل صحيح". ضع في اعتبارك تصدير رسم بياني للمشهد يبدو كالتالي (في الذاكرة):

DEF top_sep Separator {
  Cone { }
  DEF a_sphere Sphere { }
  Cube { }
}
DEF path_switch PathSwitch {
  path Path {
    ...path from "top_sep" to "a_sphere"...
  }
}

..إذا قمنا الآن بـ:

SoSeparator * root = new SoSeparator;
root->addChild([ptr to path_switch]);
root->addChild([ptr to top_sep]);
SoWriteAction wa;
wa.apply(root);

..سنحصل على الرسم البياني للمشهد المصدر هكذا:

Separator {
  DEF path_switch PathSwitch {
    path Path {
      DEF top_sep Separator {
        DEF a_sphere Sphere {
        }
      }
      1
      0
    }
  }
  USE top_sep
}

..وكما ترى، اختفت كل من عقدتي Cone و Cube، لأنهما لم تكونا مهمتين للجزء بحد ذاته، ولم يتم كتابتهما كجزء منه.

هذا هو السبب في أننا نقوم بتصدير رسم بياني فرعي كامل للعقد الرأسية في المسارات.
