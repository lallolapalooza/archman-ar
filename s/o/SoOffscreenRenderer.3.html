وصف تفصيلي

الفئة SoOffscreenRenderer تُستخدم لعرض المشاهد على مخازن مؤقتة خارج الشاشة.

إذا أردت العرض على مخزن مؤقت للذاكرة بدلاً من سياق OpenGL على الشاشة، استخدم هذه الفئة. يمكن استخدام العرض على مخزن مؤقت للذاكرة لتوليد خرائط نسيج ديناميكيًا، أو لحفظ لقطات من المشهد إلى ملفات (كصور نقطية أو كملفات PostScript لإرسالها إلى طابعة تدعم PostScript).

إليك مثال بسيط للاستخدام، فقط الكود المتعلق مباشرة بـ SoOffscreenRenderer:

SoOffscreenRenderer myRenderer(vpregion);
SoNode * root = myViewer->getSceneManager()->getSceneGraph();
SbBool ok = myRenderer.render(root);
unsigned char * imgbuffer = myRenderer.getBuffer();
// [ثم استخدم مخزن الصور في نسيج، أو اكتبه إلى ملف، أو أي شيء آخر]

وهنا مثال كامل مستقل مع كاميرا متحركة تحفظ إطارات متعددة إلى القرص كملفات JPG:

#include <Inventor/SoDB.h>
#include <Inventor/SoOffscreenRenderer.h>
#include <Inventor/engines/SoInterpolateVec3f.h>
#include <Inventor/nodes/SoCube.h>
#include <Inventor/nodes/SoDirectionalLight.h>
#include <Inventor/nodes/SoPerspectiveCamera.h>
#include <Inventor/nodes/SoSeparator.h>
#include <iostream>
int main()
{
  // تهيئة Coin
  SoDB::init();
  // العقدة الجذرية
  SoSeparator * root = new SoSeparator;
  root->ref();
  // من الضروري وجود ضوء واحد على الأقل للمُعرض خارج الشاشة
  SoDirectionalLight * light = new SoDirectionalLight;
  root->addChild(light);
  // من الضروري وجود كاميرا واحدة على الأقل للمُعرض خارج الشاشة
  SoPerspectiveCamera * camera = new SoPerspectiveCamera;
  SbRotation cameraRotation = SbRotation::identity();
  cameraRotation *= SbRotation(SbVec3f(1, 0, 0), -0.4f);
  cameraRotation *= SbRotation(SbVec3f(0, 1, 0), 0.4f);
  camera->orientation = cameraRotation;
  root->addChild(camera);
  // شيء للعرض... مكعب
  SoCube * cube = new SoCube;
  root->addChild(cube);
  // إعداد موضعي الكاميرا الموضعان اللذان نريد تحريك الكاميرا بينهما
  SoInterpolateVec3f * interpolate = new SoInterpolateVec3f;
  interpolate->input0 = SbVec3f(2, 2, 9);
  interpolate->input1 = SbVec3f(2, 2, 5);
  camera->position.connectFrom(&interpolate->output);
  // إعداد المُعرض خارج الشاشة
  SbViewportRegion vpRegion(400, 300);
  SoOffscreenRenderer offscreenRenderer(vpRegion);
  // عدد الإطارات التي سيتم عرضها للفيديو
  int frames = 5;
  std::cout << "Writing " << frames << " frames..." << std::endl;
  for (int i = 0; i < frames; i++) {
    // تحديث موضع الكاميرا
    interpolate->alpha = float(i) / (frames - 1);
    // عرض المشهد
    SbBool ok = offscreenRenderer.render(root);
    // حفظ الصورة إلى القرص
    SbString filename = SbString("coinvideo-") + (i + 1) + ".jpg";
    if (ok) {
      offscreenRenderer.writeToFile(filename.getString(), "jpg");
    } else {
      std::cout << "Error saving image: " << filename.getString() << std::endl;
      break;
    }
  }
  std::cout << "Done!" << std::endl;
  root->unref();
  return 0;
}

لاحظ أن SoOffscreenRenderer قد يخصص كمية كبيرة من الموارد، سواء موارد OpenGL أو موارد النظام العامة، لكل مثيل. لذلك، يُنصح بمحاولة إعادة استخدام مثيلات SoOffscreenRenderer، بدلاً من إنشاء وتدمير مثيل جديد لكل إطار عند إنشاء صور للفيديو.

يتم العرض خارج الشاشة داخليًا من خلال إما سياق GLX خارج الشاشة (أي OpenGL على X11)، أو WGL (أي OpenGL على Win32)، أو AGL (نمط OpenGL القديم على Mac OS X)، أو CGL (نمط Mac OS X الجديد).

إذا كانت تعريفات OpenGL تدعم امتداد pbuffer، فسيتم اكتشافها واستخدامها لتوفير عرض خارج الشاشة مسرّع بالأجهزة.

يتم جلب بيانات البكسل من مخزن OpenGL باستخدام glReadPixels()، مع تعيين وسيطات التنسيق والنوع إلى GL_RGBA و GL_UNSIGNED_BYTE، على التوالي. هذا يعني أن الحد الأقصى للدقة هو 32 بت، 8 بت لكل مكون من مكونات R/G/B/A.

أحد الاستخدامات الخاصة لـ SoOffscreenRenderer هو جعله يعرض إطارات لاستخدامها في إنشاء الأفلام. التقنية العامة للقيام بذلك هي التكرار على الإجراءات التالية:

  • نقل الكاميرا إلى الموضع الصحيح للإطار
  • تحديث الحقل العام realTime (انظر الشرح أدناه)
  • استدعاء SoOffscreenRenderer
  • تفريغ المشهد المعروض إلى ملف

.. ثم تستخدم أداة خارجية أو مكتبة لإنشاء ملف الفيلم، على سبيل المثال بتنسيق MPEG، من مجموعة الملفات التي تم تفريغها إلى القرص من العملية التكرارية أعلاه.

الكود سيكون شيئًا مثل ما يلي (بأسلوب الكود الزائف). أولاً، نحتاج إلى إيقاف مكتبة Coin نفسها من القيام بأي تحديثات تلقائية للحقل realTime، لذا يجب أن يبدو تهيئة التطبيق الخاص بك لـ Coin شيئًا كهذا:

[...] = SoQt::init([...]); // أو SoWin::init() أو SoDB::init()
// ..ثم مباشرة:
// التحكم في حقل realTime بأنفسنا، حتى تتبع الرسوم المتحركة داخل المشهد
// "وقت الفيلم" وليس "وقت ساعة الحائط".
SoDB::enableRealTimeSensor(FALSE);
SoSceneManager::enableRealTimeUpdate(FALSE);

Detailed Description

This class is a subclass of SoSensor and provides functionality for rendering a scene graph to an offscreen buffer. This is particularly useful for generating images of 3D scenes without needing to display them in a window on the screen. This can be used for generating thumbnails, rendering effects, or saving images in various formats.

The SoOffscreenRenderer uses OpenGL for rendering. It can utilize hardware acceleration features like pbuffers (Pixel Buffers) for improved performance.

The renderer maintains an internal buffer where the rendered scene is stored. This buffer can then be accessed or saved to a file.

Key functionalities include:

  • Initializing the renderer with a specified size.
  • Rendering a scene graph to the offscreen buffer.
  • Controlling stereo rendering capabilities.
  • Saving the rendered buffer to various file formats.
  • Optionally using pbuffers for hardware acceleration.

Constructor & Destructor Documentation

SoOffscreenRenderer::SoOffscreenRenderer (const SbVec2f & size = SbVec2f(1.0f,1.0f), SbBool = true, SbBool = true)

Constructs an offscreen renderer. The constructor takes the desired size of the offscreen buffer as an SbVec2f, and two boolean flags to control whether pbuffers and stereo rendering should be enabled, respectively.

The default size is 1.0x1.0. Pbuffers are enabled by default, and stereo rendering is disabled by default.

SoOffscreenRenderer::SoOffscreenRenderer (const SbVec2f & size = SbVec2f(1.0f,1.0f), const SbString & windowSystem = SbString())

Constructs an offscreen renderer with a specified size and an optional window system string. This constructor allows for more control over the underlying graphics context creation.

The windowSystem parameter can be used to specify hints for the windowing system, although its exact behavior may vary depending on the platform and Coin's internal implementation.

SbBool SoOffscreenRenderer::writeToFile (const SbString & filename, const SbName & filetypeextension) const

Saves the buffer to filename, in the file type specified by filetypeextensions.

Note that you must still specify the full filename for the first argument, i.e. the second argument will not automatically be attached to the filename -- it is only used to decide the file type.

This method is an extension versus the original SGI Open Inventor API.

void SoOffscreenRenderer::setPbufferEnable (SbBool enable)

Control whether or not SoOffscreenRenderer can use the "pbuffer" feature of OpenGL to render the scenes with hardware acceleration.

This is a dummy function in Coin, provided for API compatibility reasons, as it is really superfluous:

Coin has internal heuristics to figure out if pbuffers are available and can be allocated and used for the SoOffscreenRenderer. The SoOffscreenRenderer will also automatically fall back on "soft" buffers if it cannot use pbuffers (or any other hardware accelerated rendering technique).
