وصف تفصيلي

تستخدم الفئة SoGLImage للتعامل مع نسيج OpenGL ثنائي/ثلاثي الأبعاد.

يمكن تهيئة عدد من متغيرات البيئة للتحكم في كيفية إنشاء الأنسجة. هذا مفيد لضبط Coin لنظامك. على سبيل المثال، إذا كنت تستخدم كمبيوتر محمول، فقد يكون من الجيد تعطيل الترشيح الخطي و mipmaps.

•
COIN_TEX2_LINEAR_LIMIT: يتم تمكين الترشيح الخطي إذا كان جودة النسيج أكبر من أو تساوي هذه القيمة. القيمة الافتراضية: 0.2.
•
COIN_TEX2_MIPMAP_LIMIT: يتم إنشاء mipmaps إذا كانت جودة النسيج أكبر من أو تساوي هذه القيمة. القيمة الافتراضية: 0.5.
•
COIN_TEX2_LINEAR_MIPMAP_LIMIT: يتم تمكين الترشيح الخطي بين مستويات mipmap إذا كانت جودة النسيج أكبر من أو تساوي هذه القيمة. القيمة الافتراضية: 0.8.
•
COIN_TEX2_SCALEUP_LIMIT: يتم دائمًا توسيع الأنسجة التي يكون عرضها أو ارتفاعها غير قوة للعدد 2 إذا كانت جودة النسيج أكبر من أو تساوي هذه القيمة. القيمة الافتراضية: 0.7. إذا كانت الجودة أقل من هذه القيمة وكان العرض أو الارتفاع أكبر من 256 بكسل، فسيتم توسيع النسيج فقط إذا كان قريبًا نسبيًا من حجم قوة العدد 2 التالي. هذا يمكن أن يوفر الكثير من ذاكرة النسيج.
•
COIN_TEX2_USE_GLTEXSUBIMAGE: عند تعيينه، وعندما تحتوي بيانات النسيج الجديدة على نفس خصائص البيانات القديمة، سيتم استخدام glTexSubImage() لنسخ البيانات الجديدة إلى النسيج بدلاً من إعادة إنشائه. هذا غير ممكن افتراضيًا، لأنه يبدو أنه يسبب خطأ في برامج تشغيل NVIDIA لنظام Linux. يحدث فقط في حالات غير قابلة للتكرار. قد يكون خطأ في كود glTexSubImage() لدينا. :)
•
COIN_TEX2_USE_SGIS_GENERATE_MIPMAP: عند تعيينه، سيتم استخدام الامتداد GL_SGIS_generate_mipmap (إذا كان متاحًا) لإنشاء mipmaps، وإلا سيتم استخدام خوارزمية داخلية سريعة لإنشائها. لا يتم تمكين استخدام GL_SGIS_generate_mipmap افتراضيًا بسبب الاشتباه في أن بعض برامج تشغيل ATi تواجه مشاكل مع هذا الامتداد.
•
COIN_ENABLE_CONFORMANT_GL_CLAMP: عند تعيينه، سيتم استخدام GL_CLAMP عندما يكون وضع تقريب النسيج CLAMP. افتراضيًا، يتم استخدام GL_CLAMP_TO_EDGE، لأنه ما يريده المستخدمون عادةً. انظر http://www.opengl.org/discussion_boards/ubb/Forum3/HTML/007306.html لمناقشة حول GL_CLAMP و GL_CLAMP_TO_EDGE.
•
COIN_TEX2_ANISOTROPIC_LIMIT: يتم تمكين الترشيح المتباين إذا كانت جودة النسيج أكبر من هذه القيمة. القيمة الافتراضية: 0.85

لاحظ أن هذه الفئة هي امتداد لـ Coin وغير متاحة في واجهة برمجة التطبيقات الأصلية SGI Open Inventor v2.1.

توثيق تعداد الأعضاء

enum SoGLImage::Wrap

Used to specify how texture coordinates < 0.0 and > 1.0 should be handled. It can either be repeated (REPEAT), clamped (CLAMP) or clamped to edge (CLAMP_TO_EDGE), which is useful when tiling textures. Since 2002-11-18, CLAMP will be treated as CLAMP_TO_EDGE. The environment variable COIN_ENABLE_CONFORMANT_GL_CLAMP can be used to override this behaviour.

enum SoGLImage::ResizeReason

Sent as a parameter to SoGLImageResizeCB as a hint to why an image is being resized. IMAGE means that a whole image is being initially resized (e.g. a texture image). SUBIMAGE and MIPMAP are not in use and reserved for future use.

enum SoGLImage::Flags

Can be used to tune/optimize the GL texture handling. Normally the texture quality will be used to decide scaling and filtering, and the image data will be scanned to decide if the image is (partially) transparent, and if the texture can be rendered using the cheaper alpha test instead of blending if it does contain transparency. If you know the contents of your texture image, or if you have special requirements on how the texture should be rendered, you can set the flags using the SoGLImage::setFlags() method.

void SoGLImage::setData (const SbImage * image, const Wrap wraps, const Wrap wrapt, const Wrap wrapr, const float quality = 0.5f, const int border = 0, SoState * createinstate = NULL) [virtual]

Sets the data for this GL image. Should only be called when one of the parameters have changed, since this will cause the GL texture object to be recreated. Caller is responsible for sending legal wrap values. CLAMP_TO_EDGE is only supported on OpenGL v1.2 implementations, and as an extension on some earlier SGI implementations (GL_SGIS_texture_edge_clamp).

For now, if quality > 0.5 when created, we create mipmaps, otherwise a regular texture is created. Be aware, if you for instance create a texture with texture quality 0.4, and then later try to apply the texture with a texture quality greater than 0.5, the texture object will be recreated as a mipmap texture object. This will happen only once though, of course.

If border != 0, the OpenGL texture will be created with this border size. Be aware that this might be extremely slow on most PC hardware.

Normally, the OpenGL texture object isn't created until the first time it is needed, but if createinstate is != NULL, the texture object is created immediately. This is useful if you use a temporary buffer to hold the texture data. Be careful when using this feature, since the texture data might be needed at a later stage (for instance to create a texture object for another context). It will not be possible to create texture objects for other cache contexts when createinstate is != NULL.

Also if createinstate is supplied, and all the attributes are the same as the current data in the image, glTexSubImage() will be used to insert the image data instead of creating a new texture object. This is much faster on most OpenGL drivers, and is very useful, for instance when doing animated textures.

If you supply NULL for image, the instance will be reset, causing all display lists and memory to be freed.

Reimplemented in SoGLBigImage, and SoGLCubeMapImage.

DESCRIPTION

This class is a wrapper for the SbImage class. It handles the OpenGL-specific management of texture images, including the creation and management of GL display lists.

The SoGLImage class can be used to store and manage image data for use as OpenGL textures. It provides methods for setting and retrieving texture parameters, such as wrap modes, quality, and transparency information. It also manages the underlying OpenGL texture objects, including their creation, updating, and deletion, to optimize performance and resource usage.

The class implements a display list caching mechanism to avoid unnecessary OpenGL calls. Display lists are cached and reused as long as they are considered "young" (i.e., have been used recently). The age of a display list is determined by the number of frames since it was last used. The setDisplayListMaxAge() method allows you to control the maximum age of a display list before it is considered for deletion.

The static methods beginFrame(), tagImage(), and endFrame() provide a framework for managing the lifecycle of OpenGL texture resources. You should call beginFrame() at the beginning of each rendering frame, tagImage() whenever a texture image is used, and endFrame() after the scene has been rendered. This mechanism helps in efficiently managing and releasing unused texture resources.
