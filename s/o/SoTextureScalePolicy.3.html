Detailed Description

This node allows you to control how the Coin rendering engine will handle textures that are not powers of two (and thus not optimally supported by OpenGL).

The node has two fields:

  • policy: Controls the general behavior. With `USE_TEXTURE_QUALITY`, the node will consult SoComplexity's `textureQuality` field. Other values offer more direct control.

  • quality: Used when `policy` is set to `USE_TEXTURE_QUALITY`. A value of 0.5 or higher means high quality resizing, while a value below 0.5 means low quality resizing.

The default policy is `USE_TEXTURE_QUALITY`, and the default quality is 0.5.

Note: Textures smaller than 256 pixels are never scaled down by default, since this can lead to too much information loss.

Member Enumeration Documentation

enum SoTextureScalePolicy::Policy

Enumeration to control texture scaling behavior.

USE_TEXTURE_QUALITY
Use SoComplexity::textureQuality to decide if textures should be scaled up or down. A value of >= 0.7 scales up, while < 0.7 scales down. Textures smaller than 256 pixels are never scaled down.
ALWAYS_SCALE_UP
Always scale up textures that are smaller than the nearest power of two.
NEVER_SCALE_UP
Never scale up textures, even if they are smaller than the nearest power of two.
ALWAYS_SCALE_DOWN
Always scale down textures that are larger than the nearest power of two.
NEVER_SCALE_DOWN
Never scale down textures, even if they are larger than the nearest power of two.

Member Data Documentation

SoSFEnum SoTextureScalePolicy::policy

The policy setting. Default value is USE_TEXTURE_QUALITY.

USE_TEXTURE_QUALITY means that SoComplexity::textureQuality will be used to decide if the texture should be scaled up or down. SoComplexity::textureQuality >= 0.7 means scale up, while < 0.7 means scale down. Textures smaller than 256 pixels are never scaled down since you lose too much information.

SoSFFloat SoTextureScalePolicy::quality

The texture scale/resize quality. Default value is 0.5.

This field can be used to force Coin to use a lower quality (but much faster) image resize function. Currently, if you set this field to a value < 0.5, a low quality resize function will be used, otherwise a high quality (but slow) function will be used.
