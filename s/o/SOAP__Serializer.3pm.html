SOAP__Serializer(3pm)

الحزمة: perl-soap-lite

التراخيص: GPL-1.0-or-later, Artistic-1.0-Perl

SOAP::Serializer(3) وثائق Perl المقدمة من المستخدم SOAP::Serializer(3)

الاسم

SOAP::Serializer - الوسيلة التي تدير بها الأداة التعبير عن البيانات بصيغة XML

الوصف

الفئة SOAP::Serializer هي الوسيلة التي تدير بها الأداة التعبير عن البيانات بصيغة XML. الكائن الذي تستخدمه نسخة SOAP::Lite افتراضيًا يكون عادةً كافيًا للمهمة، دون الحاجة لأن يقوم التطبيق بإنشاء كائنه الخاص. الغرض الرئيسي لهذه الفئة هو توفير مكان للتطبيقات لتوسيع أداة التسلسل عن طريق تعريف أساليب إضافية لمعالجة أنواع بيانات جديدة.

الأساليب

new(أزواج مفتاح/قيمة اختيارية)
$serialize = SOAP::Serializer->new( );

هذا هو أسلوب المُنشئ لهذه الفئة. بالإضافة إلى إنشاء كائن أساسي وتهيئته بقيم افتراضية، يمكن للمُنشئ أيضًا أخذ أسماء وقيم لمعظم أساليب الوصول التي تدعمها الفئة.

envelope(method, وسائط البيانات)
$serialize->envelope(fault => $fault_obj);

يوفر الغرض الأساسي لفئة SOAP::Serializer. يقوم بإنشاء مظروف SOAP الكامل بناءً على المدخلات التي تم تمريرها إليه. يتم تقسيم وسائط البيانات التي تم تمريرها في قائمة المعاملات إلى قائمتين فرعيتين: أي معاملات هي كائنات SOAP::Header أو مشتقاتها تذهب إلى قائمة واحدة، بينما تذهب البقية إلى القائمة الأخرى. تُستخدم الكائنات غير الرأسية كمحتوى لجسم الرسالة، مع كون الجسم نفسه يعتمد إلى حد كبير على قيمة المعامل الأول في القائمة. يُتوقع أن يكون هذا المعامل سلسلة نصية ويجب أن يكون أحد ما يلي:

context
$serialize->context->packager();

يوفر هذا الوصول إلى سياق الاستدعاء لـ "SOAP::Serializer". في سياق جانب العميل، غالبًا ما يعني هذا مرجعًا لنسخة من SOAP::Lite. في سياق جانب الخادم، يعني هذا مرجعًا لنسخة من SOAP::Server.

method
يتم إنشاء المظروف لتغليف استدعاء طريقة من نمط RPC.
response
الرسالة التي يتم إنشاؤها هي استجابة ناتجة عن استدعاء طريقة من نمط RPC.
fault
لهذا المحدد، يتم إنشاء المظروف لنقل خطأ (fault).
freeform
يُستخدم هذا المعرف كأسلوب ترميز للحالة العامة للرسائل التي لا تتناسب مع أي من الحالات السابقة. يتم ترميز الوسائط في علامة Body الخاصة بالمظروف دون أي حساسية للسياق.

أي قيمة أخرى غير هذه الأربع تؤدي إلى خطأ.

envprefix(قيمة اختيارية)
$serialize->envprefix('env');

يحصل على أو يحدد البادئة التي تشير إلى مساحة اسم مظروف SOAP. القيمة الافتراضية هي SOAP-ENV.

encprefix(قيمة اختيارية)
$serialize->envprefix('enc');

يحصل على أو يحدد البادئة التي تشير إلى مساحة اسم ترميز SOAP. القيمة الافتراضية هي SOAP-ENC.

soapversion(قيمة اختيارية)
$serialize->soapversion('1.2');

إذا لم يتم تقديم معامل، فإنه يعيد الإصدار الحالي من SOAP الذي يتم استخدامه كأساس لتسلسل الرسائل. إذا تم تقديم معامل، فإنه يحاول تعيينه كإصدار SOAP المستخدم. يجب أن تكون القيمة إما 1.1 أو 1.2. عند تعيين إصدار SOAP، تختار الحزمة معرفات URN جديدة لمساحات المظروف والترميز، كما تستدعي أسلوب xmlschema لتعيين تعريف المخطط المناسب.

xmlschema(قيمة اختيارية)
$serialize->xmlschema($xml_schema_1999);

يحصل على أو يحدد معرف URN للمخطط المستخدم للتعبير عن بنية XML التي تم إنشاؤها بواسطة أداة التسلسل. عند تعيين القيمة، يجب أن يكون الإدخال هو معرف URN الكامل للمخطط الجديد ويتم التحقق منه مقابل قائمة مخططات SOAP المعروفة.

register_ns
تسمح الإجراء الفرعي register_ns للمستخدمين بتسجيل مساحة اسم عالمية مع مظروف SOAP. المعامل الأول هو مساحة الاسم، والمعامل الثاني لهذا الإجراء الفرعي هو بادئة اختيارية. إذا لم يتم توفير بادئة، فسيتم إنشاؤها تلقائيًا لك. يتم الإعلان عن جميع مساحات الأسماء المسجلة مع أداة التسلسل في العنصر <soap:Envelope />.
find_prefix
يأخذ الإجراء الفرعي find_prefix مساحة اسم كمعامل ويعيد البادئة المخصصة لتلك المساحة. هذا يلغي الحاجة إلى الإعلان وإعادة الإعلان عن مساحات الأسماء داخل المظروف. هذا الإجراء الفرعي مفيد بشكل خاص في تحديد البادئة المناسبة عند تعيين نوع لعنصر SOAP::Data. مثال جيد على كيفية استخدام هذا هو كما يلي: 
SOAP::Data->name("foo" => $inputParams{'foo'})
   ->type($client->serializer->find_prefix('urn:Foo').':Foo');

أنواع البيانات المخصصة

عند تسلسل كائن، أو مرجع تجزئة مبارك (blessed hash reference)، إلى XML، تتحقق "SOAP::Serializer" أولاً مما إذا كان هناك إجراء فرعي تم تعريفه لاسم الفئة المقابل. على سبيل المثال، في الكود أدناه، ستتحقق "SOAP::Serializer" مما إذا كان هناك إجراء فرعي يسمى "as_MyModule__MyPackage" قد تم تعريفه. إذا كان الأمر كذلك، فسيتم تمرير $foo إلى هذا الإجراء الفرعي مع بيانات أخرى معروفة حول عنصر "SOAP::Data" الذي يتم ترميزه.

$foo = MyModule::MyPackage->new;
my $client = SOAP::Lite
   ->uri($NS)
   ->proxy($HOST);
$som = $client->someMethod(SOAP::Data->name("foo" => $foo));

متطلبات إجراء as_TypeName الفرعي

اتفاقية التسمية
يجب دائمًا أن يسبق الإجراء الفرعي "as_" متبوعًا باسم النوع. يجب استبدال جميع النقطتين (':') في اسم النوع بشرطة سفلية ('_').
المدخلات
سيكون للمدخلات إلى "as_TypeName" معامل واحد على الأقل، وأربعة معاملات كحد أقصى. سيكون المعامل الأول دائمًا هو القيمة أو الكائن المراد ترميزه. تعتمد المعاملات الثلاثة التالية على سياق القيمة/الكائن الذي يتم ترميزه.

إذا كانت القيمة/الكائن الذي يتم ترميزه جزءًا من كائن "SOAP::Data" (كما في المثال أعلاه)، فإن المعامل الثاني والثالث والرابع ستكون اسم عنصر "SOAP::Data" ونوعه ومجموعة سماته على التوالي. إذا، من ناحية أخرى، القيمة/الكائن الذي يتم ترميزه *ليس* جزءًا من كائن "SOAP::Data"، كما في الكود أدناه:

$foo = MyModule::MyPackage->new;
my $client = SOAP::Lite
   ->uri($NS)
   ->proxy($HOST);
$som = $client->someMethod($foo);

إذن سيكون المعامل الثاني والثالث هما اسم الفئة للقيمة/الكائن الذي يتم ترميزه (على سبيل المثال، "MyModule::MyPackage" في المثال أعلاه)، وسيكون المعامل الرابع تجزئة فارغة.

المخرجات
يجب أن يعيد إجراء الترميز مصفوفة تحتوي على ثلاثة عناصر: 1) اسم عنصر XML، 2) تجزئة تحتوي على السمات التي سيتم وضعها في العنصر، و 3) قيمة العنصر.

SOAP::Serializer(3pm)

NAME

SOAP::Serializer - Base class for SOAP::Lite serializers

DESCRIPTION

The SOAP::Serializer class is responsible for the translation of Perl data structures into their corresponding XML representation, as specified by the SOAP specification. It achieves this by maintaining a list of data types that it can auto-detect, and by allowing developers to register their own custom data types for auto-detection and serialization.

METHODS

This class provides no public methods.

CUSTOM DATA TYPES

One of the most powerful features of SOAP::Lite is its ability to serialize custom data types into XML. This is achieved through the use of the SOAP::Serializer::typelookup hash and the requirement that custom data types must provide two specific subroutines: a test subroutine to detect the type and an encoding subroutine to serialize the type.

The following sections detail the requirements for these subroutines and how to register them with SOAP::Lite.

as_TypeName SUBROUTINE REQUIREMENTS

When SOAP::Serializer is asked to encode an object into XML, it first checks to see if a type has been explicitly stated for the current object. If a type has been provided, SOAP::Serializer checks to see if an as_TypeName subroutine has been defined for that type. If such a subroutine exists, then SOAP::Serializer passes the object to it to be encoded.

The encoding subroutine must accept four parameters:

The value to be encoded:
This is the actual Perl data that needs to be serialized.
The name of the element being encoded:
This is the name that should be given to the XML element.
The assumed type of the element being encoded:
This is the type name that SOAP::Serializer believes the element to be. This may or may not be the correct type.
A reference to a hash containing the attributes of the element being encoded:
This hash contains any attributes that should be associated with the XML element. This will be empty if no attributes are provided.

The encoding subroutine must return an array containing three elements:

  1. The name of the XML element.
  2. A hash containing the attributes to be placed into the element. This should include the xsi:type attribute, which specifies the XML Schema type of the element.
  3. The value of the element.

If a type has not been provided and no specific encoding subroutine is found, SOAP::Serializer must attempt to "guess" the type of the object being serialized.

AUTOTYPING

When a data type has not been declared explicitly, SOAP::Lite must "guess" at the object's type. That is due to the fact that the only form of introspection that Perl provides (through the use of the "ref" subroutine) does not provide enough information to SOAP::Serializer to allow SOAP::Lite to determine the exact type of an element being serialized.

To work around this limitation, the SOAP::Serializer::typelookup hash was created. This hash is populated with all the data types that the current SOAP::Serializer can auto detect. Users and developers are free to modify the contents of this hash allowing them to register new data types with the system.

When SOAP::Serializer is asked to encode an object into XML, it goes through the following steps. First, SOAP::Serializer checks to see if a type has been explicitly stated for the current object. If a type has been provided SOAP::Serializer checks to see if an as_TypeName subroutine has been defined for that type. If such a subroutine exists, then SOAP::Serializer passes the object to it to be encoded. If the subroutine does not exist, or the type has not been provided, then SOAP::Serializer must attempt to "guess" the type of the object being serialized.

To do so, SOAP::Serializer runs in sequence a set of tests stored in the SOAP::Serializer::typelookup hash. SOAP::Serializer continues to run each test until one of the tests returns true, indicating that the type of the object has been detected. When the type of the object has been detected, then SOAP::Serializer passes the object to the encoding subroutine that corresponds with the test that was passed. If all the tests fail, and the type was not determined, then SOAP::Serializer will as a last resort encode the object based on one of the four basic data types known to Perl: REF, SCALAR, ARRAY and HASH.

The following table contains the set of data types detectable by SOAP::Lite by default and the order in which their corresponding test subroutine will be run, according to their precedence value.

Table 1 - Autotyping Precedence
TYPENAME    PRECEDENCE VALUE
----------------------------
base64      10
int         20
long        25
float       30
gMonth      35
gDay        40
gYear       45
gMonthDay   50
gYearMonth  55
date        60
time        70
dateTime    75
duration    80
boolean     90
anyURI      95
string      100

REGISTERING A NEW DATA TYPE

To register a new data type that can be automatically detected by SOAP::Lite and then serialized into XML, the developer must provide the following four things:

  • The name of the new data type.
  • A subroutine that is capable of detecting whether a value passed to it is of the corresponding data type.
  • A number representing the test subroutine's precedence relative to all the other types' test subroutinestypes. See Table 1 - Autotyping Precedence.
  • A subroutine that is capable of providing SOAP::Serializer with the information necessary to serialize an object of the corresponding data type into XML.

EXAMPLE 1

If, for example, you wish to create a new datatype called "uriReference" for which you would like Perl values to be automatically detected and serialized into, then you follow these steps.

Step 1: Write a Test Subroutine

The test subroutine will have passed to it by SOAP::Serializer a value to be tested. The test subroutine must return 1 if the value passed to it is of the corresponding type, or else it must return 0.

sub SOAP::Serializer::uriReferenceTest {
  my ($value) = @_;
  return 1 if ($value =~ m!^http://!);
  return 0;
}

Step 2: Write an Encoding Subroutine

The encoding subroutine provides SOAP::Serializer with the data necessary to encode the value passed to it into XML. The encoding subroutine name's should be of the following format: "as_"<Type Name>.

The encoding subroutine will have passed to it by SOAP::Serializer four parameters: the value to be encoded, the name of the element being encoded, the assumed type of the element being encoded, and a reference to a hash containing the attributes of the element being encoded. The encoding subroutine must return an array representing the encoded datatype. SOAP::Serializer will use the contents of this array to generate the corresponding XML of the value being encoded, or serialized. This array contains the following 3 elements: the name of the XML element, a hash containing the attributes to be placed into the element, and the value of the element.

sub SOAP::Serializer::as_uriReference {
  my $self = shift;
  my($value, $name, $type, $attr) = @_;
  return [$name, {'xsi:type' => 'xsd:uriReference', %$attr}, $value];
}

Step 3: Register the New Data Type

To register the new data type, simply add the type to the SOAP::Serializer::typelookup hash using the type name as the key, and an array containing the precedence value, the test subroutine, and the encoding subroutine.

$s->typelookup->{uriReference}
    = [11, \&uriReferenceTest, 'as_uriReference'];

Tip: As a short hand, you could just as easily use an anonymous test subroutine when registering the new datatype in place of the "urlReferenceTest" subroutine above. For example:

$s->typelookup->{uriReference}
    = [11, sub { $_[0] =~ m!^http://! }, 'as_uriReference'];

Once complete, SOAP::Serializer will be able to serialize the following SOAP::Data object into XML:

$elem = SOAP::Data->name("someUri" => 'http://yahoo.com')->type('uriReference');

SOAP::Serializer will also be able to automatically determine and serialize the following untyped SOAP::Data object into XML:

$elem = SOAP::Data->name("someUri" => 'http://yahoo.com');
