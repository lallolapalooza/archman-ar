SOAP__Data(3pm)

الحزمة: perl-soap-lite

التراخيص: GPL-1.0-or-later, Artistic-1.0-Perl

SOAP::Data(3) وثائق Perl المساهمة من المستخدم SOAP::Data(3)

الاسم

SOAP::Data - توفر هذه الفئة الوسائل للتلاعب الصريح والتحكم في جميع جوانب كيفية تعبير بيانات Perl عن كيانات بيانات SOAP.

الوصف

توفر فئة SOAP::Data الوسائل للتلاعب الصريح والتحكم في جميع جوانب كيفية تعبير بيانات Perl عن كيانات بيانات SOAP. معظم الأساليب هي أدوات وصول، والتي، مثل تلك الموجودة في SOAP::Lite، مصممة لإرجاع القيمة الحالية إذا لم يتم تمرير قيمة جديدة، بينما ترجع مرجع الكائن بخلاف ذلك (مما يسمح باستدعاءات الأساليب المتسلسلة). لاحظ أن معظم أدوات الوصول (باستثناء القيمة) تقبل قيمة جديدة لكائن البيانات كوسيط ثانٍ.

الأساليب

new(أزواج المفتاح/القيمة اختيارية)
$obj = SOAP::Data->new(name => 'idx', value => 5);

هذا هو منشئ الفئة. يمكن تمرير جميع السمات المتعلقة بالفئة تقريبًا إلى المنشئ كأزواج مفتاح/قيمة. نادرًا ما يتم استخدام هذه الطريقة مباشرة لأن كائنات SOAP::Data يتم إنشاؤها بشكل عام للاستخدام المؤقت. وهي متاحة لتلك المواقف التي تتطلب ذلك.

name(اسم جديد، قيمة اختيارية)
$obj->name('index');

يحصل أو يحدد القيمة الحالية للاسم، كما يراه الكائن. الاسم هو ما سيستخدمه المحلل للاسم عند إنشاء XML لهذا الكائن. وهو ما سيصبح أداة الوصول لعنصر البيانات. اختياريًا، يمكن تحديث قيمة الكائن إذا تم تمريرها كوسيط ثانٍ.

type(نوع جديد، قيمة اختيارية)
$obj->type('int');

يحصل أو يحدد النوع المرتبط بالقيمة الحالية في الكائن. هذا مفيد في الحالات التي يتم فيها استخدام كائن SOAP::Data لتحديد نوع البيانات بشكل صريح والتي قد يتم تفسيرها على أنها نوع مختلف تمامًا (مثل إدراك السلسلة 123 كعدد صحيح، بدلاً من ذلك). يسمح بتعيين قيمة الكائن، إذا تم تمريرها كوسيط ثانٍ للطريقة.

uri(URI جديد، قيمة اختيارية)
$obj->uri('http://www.perl.com/SOAP');

يحصل أو يحدد URI الذي سيتم استخدامه كمسافة اسم للكيان XML الناتج، إذا كان مطلوبًا. هذا لا يحدد تسمية مسافة الاسم. إذا لم يتم توفير واحدة عن طريق طريقة البادئة، يتم إنشاؤها تلقائيًا عند الحاجة. يسمح أيضًا بتعيين قيمة الكائن، إذا تم تمريرها كوسيط ثانٍ للطريقة.

prefix(بادئة جديدة، قيمة اختيارية)
$obj->prefix('perl');

يوفر البادئة، أو التسمية، للاستخدام عند ربط كائن البيانات بمسافة اسم معينة. يسمح أيضًا بتعيين قيمة الكائن، إذا تم تمريرها كوسيط ثانٍ للطريقة.

attr(مرجع هاش للسمات، قيمة اختيارية)
$obj->attr({ attr1 => 'value' });

يسمح بتعيين سمات اعتباطية على كائن البيانات. ضع في اعتبارك المتطلب بأن أي سمات غير معروفة أصلاً لـ SOAP يجب أن تكون مؤهلة مسافة الاسم. يسمح أيضًا بتعيين قيمة الكائن، إذا تم تمريرها كوسيط ثانٍ للطريقة.

value(قيمة جديدة)
$obj->value(10);

يجلب القيمة الحالية التي يغلفها الكائن، أو يحددها بشكل صريح.

الأربع طرق الأخيرة هي اختصارات مريحة للسمات التي يدعمها SOAP نفسه. كل منها يسمح أيضًا بتضمين قيمة جديدة، كوسيط ثانٍ اختياري.

actor(ممثل جديد، قيمة اختيارية)
$obj->actor($new_actor_name);

يحصل أو يحدد قيمة السمة 'actor'؛ مفيد فقط عندما ينشئ الكائن كيانًا لرأس الرسالة.

mustUnderstand(منطقي، قيمة اختيارية)
$obj->mustUnderstand(0);

يتعامل مع السمة 'mustUnderstand'، التي تخبر معالج SOAP ما إذا كان مطلوبًا فهم الكيان المعني.

encodingStyle(رمز تشفير جديد، قيمة اختيارية)
$obj->encodingStyle($soap_11_encoding);

من المرجح استخدام هذه الطريقة في أماكن خارج إنشاء الرأس. تحدد 'encodingStyle'، التي تحدد ترميزًا يختلف عن الترميز الذي سيتم تحديده افتراضيًا.

root(منطقي، قيمة اختيارية)
$obj->root(1);

عندما يتعين على التطبيق تحديد عنصر البيانات الذي يجب اعتباره العنصر الجذري لإنشاء نموذج الكائن، توفر هذه الطريقة الوصول إلى السمة 'root'.

اكتشاف النوع

سيقوم محلل SOAP::Lite باكتشاف نوع أي قيمة عددية يتم تمريرها كقيمة لكائن SOAP::Data. نظرًا لأن Perl ذات أنواع فضفاضة، فإن المحلل قادر فقط على اكتشاف الأنواع بناءً على مجموعة محددة مسبقًا من التعبيرات المنتظمة. لذلك، فإن اكتشاف النوع ليس دقيقًا بنسبة 100% دائمًا. في مثل هذه الحالة، قد تحتاج إلى تعيين نوع العنصر الذي يتم ترميزه بشكل صريح. على سبيل المثال، افتراضيًا، سيتم تحليل الكود التالي كرقم صحيح:

$elem = SOAP::Data->name('idx')->value(5);

ولكن، إذا كنت بحاجة إلى تحليل هذا إلى رقم طويل، فسيقوم الكود التالي بذلك:

$elem = SOAP::Data->name('idx')->value(5)->type('long');

أمثلة

أنواع بسيطة

سيؤدي المثال التالي إلى إنشاء نفس XML:

$elem1 = SOAP::Data->new(name => 'idx', value => 5);
$elem2 = SOAP::Data->name('idx' => 5);
$elem3 = SOAP::Data->name('idx')->value(5);

أنواع معقدة

سؤال شائع هو كيف تقوم بإنشاء عناصر XML متداخلة باستخدام SOAP::Lite. يوضح المثال التالي كيف:

SOAP::Data->name('foo' => \SOAP::Data->value(
    SOAP::Data->name('bar' => '123')));

سيؤدي الكود أعلاه إلى إنشاء XML التالي:

<foo>
  <bar>123</bar>
</foo>

مصفوفات

الكود التالي:

$elem1 = SOAP::Data->name('item' => 123)->type('SomeObject');
$elem2 = SOAP::Data->name('item' => 456)->type('SomeObject');
push(@array,$elem1);
push(@array,$elem2);
my $client = SOAP::Lite
    ->readable(1)
    ->uri($NS)
    ->proxy($HOST);
$temp_elements = SOAP::Data
    ->name("CallDetails" => \SOAP::Data->value(
          SOAP::Data->name("elem1" => 'foo'),
          SOAP::Data->name("elem2" => 'baz'),
          SOAP::Data->name("someArray" => \SOAP::Data->value(
              SOAP::Data->name("someArrayItem" => @array)
                        ->type("SomeObject"))
                   )->type("ArrayOf_SomeObject") ))
->type("SomeObject");
$response = $client->someMethod($temp_elements);

سيؤدي إلى إنشاء XML التالي:

<?xml version="1.0" encoding="UTF-8"?>
<SOAP-ENV:Envelope
    xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
    xmlns:SOAP-ENC="http://schemas.xmlsoap.org/soap/encoding/"
    xmlns:SOAP-ENV="http://schemas.xmlsoap.org/soap/envelope/"
    xmlns:xsd="http://www.w3.org/2001/XMLSchema"
    xmlns:namesp2="http://namespaces.soaplite.com/perl"
    SOAP-ENV:encodingStyle="http://schemas.xmlsoap.org/soap/encoding/">
  <SOAP-ENV:Body>
    <namesp1:someMethod xmlns:namesp1="urn:TemperatureService">
      <CallDetails xsi:type="namesp2:SomeObject">
SOAP::Data(3pm)

NAME

SOAP::Data - A data element for SOAP::Lite

DESCRIPTION

This module provides a convenient way to create SOAP::Data objects, which represent elements within a SOAP message.

SOAP::Data objects can be used to represent simple values, arrays, complex types (elements with children), and attributes.

METHODS

  • SOAP::Data->new

    Constructor for SOAP::Data objects.

  • type

    Sets the data type of the element. For example, type('xsd:string') or type('xml' => $raw_xml).

  • name

    Sets the name of the element. Can be used to specify a namespace prefix, e.g., name('ns:elementName').

  • value

    Sets the value of the element.

  • attr

    Adds attributes to the element. Accepts a hash reference of attribute name-value pairs, e.g., attr({ 'xmlns:foo' => 'urn:bar' }).

  • uri

    Sets the namespace URI for the element's name.

  • prefix

    Sets the namespace prefix for the element's name.

TYPE DETECTION

SOAP::Lite attempts to automatically detect the type of data you are passing to it. For example, a Perl hash reference will be serialized as a complex type (an element with child elements), while a Perl scalar will be serialized as a simple type (an element with text content).

You can explicitly set the type using the type method.

COMPOSING MESSAGES USING ARRAYS

Arrays can be represented by passing a Perl array reference to the value method. SOAP::Lite will serialize this into a SOAP array.

For example:

        $array_ref = [ 1, 2, 3 ];
        $data = SOAP::Data->name('myArray')->value($array_ref);

This would produce XML similar to:

        <myArray>
            <item>1</item>
            <item>2</item>
            <item>3</item>
        </myArray>

If you need to encode an array of complex types, pass an array of other SOAP::Data objects.

        $complex_item1 = SOAP::Data->name('item')->type('xsd:string')->value('foo');
        $complex_item2 = SOAP::Data->name('item')->type('xsd:string')->value('bar');
        $array_ref = [ $complex_item1, $complex_item2 ];
        $data = SOAP::Data->name('myArray')->type('namesp2:ArrayOf_SomeObject')->value($array_ref);

COMPOSING MESSAGES USING RAW XML

In some circumstances you may need to encode a message using raw unserialized XML text. To instantiate a SOAP::Data object using raw XML, do the following:

        $xml_content = "<foo><bar>123</bar></foo>";
        $elem = SOAP::Data->type('xml' => $xml_content);

SOAP::Lite's serializer simply takes whatever text is passed to it, and inserts it into the encoded SOAP::Data element verbatim. The text input is NOT validated to ensure it is valid XML, nor is the resulting SOAP::Data element validated to ensure that it will produce valid XML. Therefore, it is incumbent upon the developer to ensure that any XML data used in this fashion is valid and will result in a valid XML document.

MULTIPLE NAMESPACES

When working with complex types it may be necessary to declare multiple namespaces. The following code demonstrates how to do so:

        $elem = SOAP::Data->name("myElement" => "myValue")
                ->attr( { 'xmlns:foo2' => 'urn:Foo2',
                                'xmlns:foo3' => 'urn:Foo3' } );

This will produce the following XML:

        <myElement xmlns:foo2="urn:Foo2" xmlns:foo3="urn:Foo3">myValue</myElement>
