الوصف التفصيلي

الفئة SoDelayQueueSensor هي الفئة الأساسية المجردة للمستشعرات ذات الأولوية.

يتم استدعاء مستشعرات قائمة التأخير عند حدوث أحداث متنوعة *غير* مرتبطة بالأحداث الزمنية. انظر إلى وثائق الأنواع الفرعية لمعرفة أنواع الأحداث التي يمكن مراقبتها بواسطة أنواع المستشعرات المدمجة.

يمكن استخدام قيم الأولوية لإعادة ترتيب الأحداث حسب أهميتها، بحيث يتم تشغيل المستشعرات بالترتيب المطلوب.

يتم معالجة قائمة انتظار مستشعرات التأخير (أي، مثيلات الأنواع الفرعية من SoDelayQueueSensor) بمجرد أن يكون نظام التوقيت خاملاً، أو إذا كان مشغولًا باستمرار، يتم معالجتها في غضون فترة زمنية ثابتة.

هذه الفترة الزمنية هي افتراضيًا 1/12 من الثانية، ولكن يمكن التحكم فيها باستخدام الواجهة SoSensorManager::setDelaySensorTimeout().

ملاحظة: يشير الرقم المنخفض إلى أولوية عالية. يتم تشغيل مستشعر ذي أولوية 5 قبل مستشعر ذي أولوية 6.

تمتلك المستشعرات ذات الأولوية 0 معنى خاصًا في Coin/Inventor. تسمى مستشعرات فورية ويتم تشغيلها فورًا بعد الانتهاء من سلسلة الإخطار الحالية. يجب استخدامها بحذر، لأنها قد تسبب أداءً سلبيًا إذا تم إجراء أي معالجة داخل رد اتصال المستشعر.

لا يؤثر هذا الضبط على استدعاءات SoDataSensor مع رد الاتصال بالإزالة، والتي تكون دائمًا فورية.

NAME

SoDelayQueueSensor — sensor that can be delayed

SYNOPSIS

Inherits from SoSensor.

Derived classes: SoDataSensor, SoFieldSensor.

Detailed Description

This class is a subclass of SoSensor and provides functionality for sensors that can be delayed. If a sensor is scheduled to be triggered, but the trigger condition is not met yet, it can be placed in a delay queue. The sensor will then be triggered later, when the condition is met, or if it is explicitly triggered or invalidated.

The purpose of a delay queue sensor is to postpone sensor triggering until some later time. This is useful in situations where triggering a sensor immediately might cause problems, such as infinite recursion or performance issues.

Delay queue sensors are managed by the Coin rendering engine. When a sensor is scheduled, it is placed in a queue. The sensor is triggered when its condition is met, or when the delay queue is processed.

The delay queue is processed at specific points in the rendering pipeline, such as before rendering a frame or after a scene graph traversal. This ensures that sensors are triggered at appropriate times, minimizing the risk of unexpected behavior.

Subclasses of SoDelayQueueSensor, such as SoDataSensor and SoFieldSensor, can provide more specific functionality for different types of sensors. For example, SoFieldSensor can be used to trigger a sensor when a field's value changes.

Member Data Documentation

SbBool SoDelayQueueSensor::scheduled [protected]

This protected member variable indicates whether the sensor is currently scheduled. It is a boolean value, where TRUE means the sensor is scheduled and FALSE means it is not.

This variable is managed internally by the Coin library and is typically not accessed directly by user code. It plays a role in determining the sensor's state and how it will be processed by the delay queue.
