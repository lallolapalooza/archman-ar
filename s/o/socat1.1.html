socat - مرحل متعدد الأغراض (SOcket CAT)

ملخص

filan

الوصف

Socat هو أداة سطر أوامر تنشئ تدفقات بايت ثنائية الاتجاه وتنقل البيانات بينها. نظرًا لأنه يمكن بناء التدفقات من مجموعة كبيرة من أنواع مختلفة من وجهات ومصادر البيانات (انظر أنواع العناوين)، ولأن العديد من خيارات العناوين يمكن تطبيقها على التدفقات، يمكن استخدام socat للعديد من الأغراض المختلفة.

Filan هي أداة تطبع معلومات حول واصفات الملفات النشطة إلى stdout. لقد تم كتابتها لتصحيح أخطاء socat، ولكن قد تكون مفيدة لأغراض أخرى أيضًا. استخدم الخيار -h للعثور على مزيد من المعلومات.

Procan هي أداة تطبع معلومات حول معلمات العملية إلى stdout. لقد تم كتابتها لفهم خصائص عملية UNIX بشكل أفضل ولتصحيح أخطاء socat، ولكن قد تكون مفيدة لأغراض أخرى أيضًا.

تتكون دورة حياة مثيل socat عادةً من أربع مراحل.

في مرحلة البداية، يتم تحليل خيارات سطر الأوامر ويتم تهيئة التسجيل.

خلال مرحلة الفتح، يفتح socat العنوان الأول وبعد ذلك العنوان الثاني. عادة ما تكون هذه الخطوات مانعة؛ وبالتالي، خاصة بالنسبة لأنواع العناوين المعقدة مثل socks، يجب إكمال طلبات الاتصال أو حوارات المصادقة قبل بدء الخطوة التالية.

في مرحلة النقل، يراقب socat واصفات الملفات للقراءة والكتابة لكلا التدفقين عبر select()، وعندما تكون البيانات متاحة على جانب واحد و يمكن كتابتها إلى الجانب الآخر، يقرأها socat، ويقوم بتحويلات أحرف نهاية السطر إذا لزم الأمر، ويكتب البيانات إلى واصف الملف للكتابة للتدفق الآخر، ثم يستمر في انتظار المزيد من البيانات في كلا الاتجاهين.

عندما يصل أحد التدفقات فعليًا إلى EOF، تبدأ مرحلة الإغلاق. يقوم socat بنقل حالة EOF إلى التدفق الآخر، أي يحاول إيقاف تشغيل تدفق الكتابة الخاص به فقط، مما يمنحه فرصة للإنهاء بشكل رشيق. لفترة محددة، يستمر socat في نقل البيانات في الاتجاه الآخر، ولكنه بعد ذلك يغلق جميع القنوات المتبقية وينتهي.

خيارات

يوفر Socat بعض خيارات سطر الأوامر التي تعدل سلوك البرنامج. ليس لها علاقة بما يسمى بخيارات العناوين التي تستخدم كأجزاء من مواصفات العنوان.

-V
طباعة معلومات الإصدار والميزات المتاحة إلى stdout، ثم الخروج.
-h | -?
طباعة نص مساعدة إلى stdout يصف خيارات سطر الأوامر وأنواع العناوين المتاحة، ثم الخروج.
-hh | -??
مثل -h، بالإضافة إلى قائمة بالأسماء المختصرة لجميع خيارات العناوين المتاحة. بعض الخيارات تعتمد على المنصة، لذا فإن هذه المخرجات مفيدة للتحقق من التطبيق المحدد.
-hhh | -???
مثل -hh، بالإضافة إلى قائمة بجميع أسماء خيارات العناوين المتاحة.
-d
بدون هذا الخيار، يتم طباعة رسائل الأخطاء القاتلة، والأخطاء، والتحذيرات فقط؛ تطبيق هذا الخيار يطبع أيضًا رسائل الإشعار. انظر التشخيصات لمزيد من المعلومات.
-d0
مع هذا الخيار، يتم طباعة رسائل الأخطاء القاتلة والأخطاء فقط؛ هذا يعيد سلوك socat حتى الإصدار 1.7.4.
-d -d | -dd | -d2
يطبع رسائل الأخطاء القاتلة، والأخطاء، والتحذيرات، والإشعارات.
-d -d -d | -ddd | -d3
يطبع رسائل الأخطاء القاتلة، والأخطاء، والتحذيرات، والإشعارات، والمعلومات.
-d -d -d -d | -dddd | -d4
يطبع رسائل الأخطاء القاتلة، والأخطاء، والتحذيرات، والإشعارات، والمعلومات، والتصحيح.
-D
يسجل معلومات حول واصفات الملفات قبل بدء مرحلة النقل.
--experimental
الميزات الجديدة التي لم يتم اختبارها جيدًا أو تخضع للتغيير في المستقبل يجب تمكينها صراحة باستخدام هذا الخيار.
-ly[<facility>]
يكتب الرسائل إلى syslog بدلاً من stderr؛ شدة كما هو محدد مع الخيار -d. مع <facility> الاختياري، يمكن تحديد نوع syslog، الافتراضي هو "daemon". قد لا تتبع المكتبات الخارجية هذا الخيار.
-lf <logfile>
يكتب الرسائل إلى <logfile> [اسم الملف] بدلاً من stderr. قد لا تتبع بعض المكتبات الخارجية، وخاصة libwrap، هذا الخيار.
-ls
يكتب الرسائل إلى stderr (هذا هو الافتراضي). قد لا تتبع بعض المكتبات الخارجية هذا الخيار، وخاصة libwrap يبدو أنها تسجل فقط إلى syslog.
-lp<progname>
يتجاوز اسم البرنامج المطبوع في رسائل الخطأ والمستخدم لإنشاء أسماء متغيرات البيئة.
-lu
يوسع الطابع الزمني لرسائل الخطأ إلى دقة الميكرو ثانية. لا يعمل عند التسجيل إلى syslog.
-lm[<facility>]
وضع تسجيل مختلط. أثناء بدء التشغيل، يتم طباعة الرسائل إلى stderr؛ عندما يبدأ socat حلقة نقل البيانات أو وضع الخادم (أي بعد فتح جميع التدفقات وقبل بدء نقل البيانات، أو، مع مقابس الاستماع مع خيار fork، قبل أول استدعاء accept)، فإنه يحول التسجيل إلى syslog. مع <facility> الاختياري، يمكن تحديد نوع syslog، الافتراضي هو "daemon".
-lh
يضيف اسم المضيف إلى رسائل السجل. يستخدم القيمة من متغير البيئة HOSTNAME أو القيمة المستردة باستخدام uname() إذا لم يتم تعيين HOSTNAME.
-v
يكتب البيانات المنقولة ليس فقط إلى تدفقاتها المستهدفة، ولكن أيضًا إلى stderr. تنسيق المخرجات هو نص مع بعض التحويلات للقراءة، ومسبوق بـ "> " أو "< " مما يشير إلى اتجاهات التدفق.
-x
يكتب البيانات المنقولة ليس فقط إلى تدفقاتها المستهدفة، ولكن أيضًا إلى stderr. تنسيق المخرجات سداسي عشري، مسبوق بـ "> " أو "< " مما يشير إلى اتجاهات التدفق. يمكن دمجه مع -v.
-r <file>
يقوم بتفريغ البيانات الأولية (الثنائية) المتدفقة من العنوان الأيسر إلى الأيمن إلى الملف المحدد. قد يحتوي اسم الملف على مراجع لمتغيرات البيئة و $$ (pid)، و $PROGNAME (انظر الخيار -lp)، و $TIMESTAMP (يستخدم التنسيق %Y%m%dT%H%M%S)، و MICROS (ميكرو ثانية من النهار). يجب حماية هذه المراجع من توسيع shell بالطبع.
DCCP4-LISTEN:<port> (DCCP4-L:<port>)
مثل DCCP-LISTEN، لكنه يدعم بروتوكول IPv4 فقط.
مجموعات الخيارات: FD، SOCKET، LISTEN، CHILD، RANGE، IP4، DCCP، RETRY
DCCP6-LISTEN:<port> (DCCP6-L:<port>)
مثل DCCP-LISTEN، لكنه يدعم بروتوكول IPv6 فقط.
مجموعات الخيارات: FD، SOCKET، LISTEN، CHILD، RANGE، IP6، DCCP، RETRY
EXEC:<command-line>
ينشئ عملية فرعية تقيم اتصالًا مع عمليتها الأم وتستدعي البرنامج المحدد باستخدام execvp(). <command-line> هو أمر بسيط مع وسائط مفصولة بمسافات مفردة. إذا كان اسم البرنامج يحتوي على '/'. يؤخذ الجزء بعد آخر '/' كـ ARGV[0]. إذا كان اسم البرنامج هو مسار نسبي، فإن دلالات execvp() لـ العثور على البرنامج عبر $PATH تنطبق. بعد بدء البرنامج بنجاح، يكتب socat بيانات إلى stdin للعملية ويقرأ من stdout الخاص بها باستخدام مقبس مجال UNIX يتم إنشاؤه بواسطة socketpair() بشكل افتراضي. (مثال)
مجموعات الخيارات: FD، SOCKET، EXEC، FORK، TERMIOS
خيارات مفيدة: path, fdin, fdout, chroot, su, su-d, nofork, socktype, pty, stderr, ctty, setsid, pipes, umask, login, sigint, sigquit, netns
انظر أيضًا: SYSTEM، SHELL
FD:<fdnum>
يستخدم واصف الملف <fdnum>. يجب أن يكون موجودًا بالفعل كوصف ملف UN*X صالح.
مجموعات الخيارات: FD (TERMIOS, REG, SOCKET)
انظر أيضًا: STDIO، STDIN، STDOUT، STDERR
GOPEN:<filename>
(فتح عام) يحاول نوع العنوان هذا التعامل مع أي إدخال في نظام الملفات باستثناء الدلائل بشكل مفيد. قد يكون <filename> مسارًا نسبيًا أو مطلقًا. إذا كان موجودًا بالفعل، يتم فحص نوعه. في حالة مقبس مجال UNIX، يتصل socat؛ إذا فشل الاتصال، يفترض socat أنه مقبس بيانات ويستخدم استدعاءات sendto(). إذا لم يكن الإدخال مقبسًا، يفتحه socat مع تطبيق علامة O_APPEND. إذا لم يكن موجودًا، يتم فتحه بالعلامة O_CREAT كملف عادي (مثال).
مجموعات الخيارات: FD، REG، SOCKET، NAMED، OPEN
انظر أيضًا: OPEN، CREATE، UNIX-CONNECT
IP-SENDTO:<host>:<protocol>
يفتح مقبس IP خام. اعتمادًا على مواصفات المضيف أو خيار pf، يتم استخدام إصدار بروتوكول IP 4 أو 6. يستخدم <protocol> لإرسال حزم إلى <host> [عنوان IP] ويستقبل حزمًا من المضيف، ويتجاهل الحزم من مضيفين آخرين. البروتوكول 255 يستخدم المقبس الخام مع كون رأس IP جزءًا من البيانات.
مجموعات الخيارات: FD، SOCKET، IP4، IP6
خيارات مفيدة: pf، ttl
انظر أيضًا: IP4-SENDTO، IP6-SENDTO، IP-RECVFROM، IP-RECV، UDP-SENDTO، UNIX-SENDTO
INTERFACE:<interface>
يتواصل مع شبكة متصلة على واجهة باستخدام حزم خام بما في ذلك بيانات مستوى الارتباط. <interface> هو اسم واجهة الشبكة. متاح حاليًا على Linux فقط.
مجموعات الخيارات: FD، SOCKET
خيارات مفيدة: pf، type
انظر أيضًا: ip-recv
IP4-SENDTO:<host>:<protocol>
مثل IP-SENDTO، ولكنه يستخدم IPv4 دائمًا.
مجموعات الخيارات: FD، SOCKET، IP4
IP6-SENDTO:<host>:<protocol>
مثل IP-SENDTO، ولكنه يستخدم IPv6 دائمًا.
مجموعات الخيارات: FD، SOCKET، IP6
IP-DATAGRAM:<address>:<protocol>
يرسل بيانات صادرة إلى العنوان المحدد الذي قد يكون، على وجه الخصوص، عنوان بث أو بث متعدد. يتم فحص الحزم التي تصل إلى المقبس المحلي لتحديد ما إذا كانت عناوين المصدر الخاصة بها تتطابق مع خيارات RANGE أو TCPWRAP. يمكن استخدام نوع العنوان هذا، على سبيل المثال، لتنفيذ اتصالات بث أو بث متعدد متماثلة أو غير متماثلة.
مجموعات الخيارات: FD، SOCKET، IP4، IP6، RANGE
خيارات مفيدة: bind, range, tcpwrap, broadcast, ip-multicast-loop, ip-multicast-ttl, ip-multicast-if, ip-add-membership, ip-add-source-membership, ipv6-join-group, ipv6-join-source-group, ttl, tos, pf
انظر أيضًا: IP4-DATAGRAM، IP6-DATAGRAM، IP-SENDTO، IP-RECVFROM، IP-RECV، UDP-DATAGRAM
IP4-DATAGRAM:<host>:<protocol>
مثل IP-DATAGRAM، ولكنه يستخدم IPv4 دائمًا. (مثال)
مجموعات الخيارات: FD، SOCKET، IP4، RANGE
IP6-DATAGRAM:<host>:<protocol>
مثل IP-DATAGRAM، ولكنه يستخدم IPv6 دائمًا. يرجى ملاحظة أن IPv6 لا يعرف البث.
مجموعات الخيارات: FD، SOCKET، IP6، RANGE
IP-RECVFROM:<protocol>
يفتح مقبس IP خام للبروتوكول <protocol>. اعتمادًا على الخيار pf، يتم استخدام إصدار بروتوكول IP 4 أو 6. يستقبل حزمة واحدة من نظير غير محدد وقد يرسل حزمة استجابة واحدة أو أكثر إلى هذا النظير. هذا الوضع مفيد بشكل خاص مع خيار fork حيث كل حزمة واردة - من نظراء عشوائيين - تتم معالجتها بواسطة عملية فرعية خاصة بها. هذا يسمح بسلوك مشابه للخوادم التقليدية المستندة إلى UDP مثل ntpd أو named.
يرجى ملاحظة أن حزم الرد قد يتم جلبها كحركة مرور واردة إذا كان عنوان IP للمرسل والمستقبل متطابقين لأنه لا يوجد رقم منفذ لتمييز المقابس.
يعمل هذا العنوان بشكل جيد مع نظراء عناوين IP-SENDTO (انظر أعلاه). البروتوكول 255 يستخدم المقبس الخام مع كون رأس IP جزءًا من البيانات.
انظر الملاحظة حول عناوين RECVFROM.
مجموعات الخيارات: FD، SOCKET، IP4، IP6، CHILD، RANGE
خيارات مفيدة: pf، fork، range، ttl، broadcast
انظر أيضًا: IP4-RECVFROM، IP6-RECVFROM، IP-SENDTO، IP-RECV، UDP-RECVFROM، UNIX-RECVFROM
IP4-RECVFROM:<protocol>
مثل IP-RECVFROM، ولكنه يستخدم IPv4 دائمًا.
مجموعات الخيارات: FD، SOCKET، IP4، CHILD، RANGE
IP6-RECVFROM:<protocol>
مثل IP-RECVFROM، ولكنه يستخدم IPv6 دائمًا.
مجموعات الخيارات: FD، SOCKET، IP6، CHILD، RANGE
IP-RECV:<protocol>
يفتح مقبس IP خام للبروتوكول <protocol>. اعتمادًا على الخيار pf، يتم استخدام إصدار بروتوكول IP 4 أو 6. يستقبل حزمًا من عدة نظراء غير محددين ويدمج البيانات. لا يمكن الرد، هذا هو عنوان للقراءة فقط، انظر الخيارات -u و -U، والعناوين المزدوجة. يمكن أن يكون، على سبيل المثال، موجهًا بواسطة نظراء عناوين socat IP-SENDTO. البروتوكول 255 يستخدم المقبس الخام مع كون رأس IP جزءًا من البيانات.
مجموعات الخيارات: FD، SOCKET، IP4، IP6، RANGE
خيارات مفيدة: pf, range
انظر أيضًا: IP4-RECV، IP6-RECV، IP-SENDTO، IP-RECVFROM، UDP-RECV، UNIX-RECV
IP4-RECV:<protocol>
مثل IP-RECV، ولكنه يستخدم IPv4 دائمًا.
مجموعات الخيارات: FD، SOCKET، IP4، RANGE
IP6-RECV:<protocol>
مثل IP-RECV، ولكنه يستخدم IPv6 دائمًا.
مجموعات الخيارات: FD، SOCKET، IP6، RANGE
OPEN:<filename>
يفتح <filename> باستخدام استدعاء النظام open() (مثال). تفشل هذه العملية على مقابس مجال UNIX.
ملاحظة: نوع العنوان هذا نادرًا ما يكون مفيدًا في الوضع ثنائي الاتجاه.
مجموعات الخيارات: FD، REG، NAMED، OPEN
خيارات مفيدة: creat, excl, noatime, nofollow, append, rdonly, wronly, lock, readbytes, ignoreeof
انظر أيضًا: CREATE، GOPEN، UNIX-CONNECT
OPENSSL:<host>:<port>
يحاول إنشاء اتصال SSL بمنفذ <port> [خدمة TCP] على المضيف <host> [عنوان IP] باستخدام TCP/IP الإصدار 4 أو 6 اعتمادًا على مواصفات العنوان، أو حل الاسم، أو خيار pf.
ملاحظة: حتى الإصدار 1.7.2.4، كان شهادة الخادم تُفحص فقط للصلاحية مقابل مخزن شهادات النظام أو cafile أو capath، ولكن ليس للمطابقة مع اسم الخادم أو عنوان IP الخاص به. منذ الإصدار 1.7.3.0، يفحص socat شهادة النظير للمطابقة مع المعلمة <host> أو قيمة خيار openssl-commonname. يحاول socat مطابقتها مع أسماء CommonName للخادم، وأسماء DNS في امتداد subjectAltName للشهادات. يتم دعم أحرف البدل في الشهادة.
مجموعات الخيارات: FD، SOCKET، IP4، IP6، TCP، OPENSSL، RETRY
خيارات مفيدة: min-proto-version، cipher، verify، commonname، cafile، capath، certificate، key، compress، bind، pf، connect-timeout، sourceport، retry
انظر أيضًا: OPENSSL-LISTEN، TCP
OPENSSL-LISTEN:<port>
يستمع على منفذ tcp <port> [خدمة TCP]. إصدار IP هو 4 أو الإصدار المحدد باستخدام pf. عند قبول اتصال، يتصرف هذا العنوان كمخدم SSL.
SOCKET-CONNECT:<domain>:<protocol>:<remote-address>
ينشئ مقبس تدفق باستخدام أول وثاني معلمة مقبس معطاة و SOCK_STREAM (انظر man socket(2)) ويتصل بالعنوان البعيد. يجب تحديد معلمتي المقبس بواسطة أرقام صحيحة. راجع وثائق نظام التشغيل وملفات التضمين الخاصة بك للعثور على القيم المناسبة. يجب أن يكون العنوان البعيد هو التمثيل البياني لهيكل sockaddr بدون مكونات sa_family و (BSD) sa_len.
يرجى ملاحظة أنه يمكنك - بالإضافة إلى خيارات المجموعات المحددة - أيضًا استخدام خيارات البروتوكولات ذات المستوى الأعلى عند تطبيق خيار socat -g.
مجموعات الخيارات: FD، SOCKET، CHILD، RETRY
خيارات مفيدة: bind، setsockopt،
انظر أيضًا: TCP، UDP-CONNECT، UNIX-CONNECT، SOCKET-LISTEN، SOCKET-SENDTO

SYSTEM:<shell-command>
يقوم بعمل fork لعملية فرعية تنشئ اتصالًا مع عمليتها الأم وتستدعي البرنامج المحدد مع system(). يرجى ملاحظة أن <shell-command> [string] يجب ألا يحتوي على ’،’ أو "!!"، وأن الأحرف الوصفية للصدفة قد تحتاج إلى حماية. بعد بدء البرنامج بنجاح، يكتب socat البيانات إلى stdin للعملية ويقرأ من stdout الخاصة بها.
مجموعات الخيارات: FD، SOCKET، EX معلمات استدعاءات النظام؛ على سبيل المثال، الخيار sync يضبط العلامة O_SYNC باستخدام استدعاء open(). تسبب خيارات أخرى استدعاء نظام أو مكتبة؛ على سبيل المثال، مع الخيار `ttl=value’ يتم تطبيق استدعاء setsockopt(fd, SOL_IP, IP_TTL, value, sizeof(int)). تضبط خيارات أخرى متغيرات socat داخلية تُستخدم أثناء نقل البيانات؛ على سبيل المثال، `crnl’ يسبب تحويلات أحرف صريحة. قليلة من الخيارات لها تطبيقات أكثر تعقيدًا؛ على سبيل المثال، su-d (substuser-delayed) يستعلم عن بعض معلومات المستخدم والمجموعة، ويخزنها، ويطبقها لاحقًا بعد استدعاء محتمل لـ chroot().

إذا تم إعطاء خيارات متعددة لعنوان، فإن تسلسلها في مواصفات العنوان له (تقريبًا) لا تأثير على تسلسل تنفيذها/تطبيقها. بدلاً من ذلك، يمتلك socat نموذجًا مدمجًا لـ مرحلة الخيارات يحاول ترتيب الخيارات بترتيب مفيد. بعض الخيارات موجودة بأشكال مختلفة (على سبيل المثال، unlink، unlink-early، unlink-late) للتحكم في وقت تنفيذها.

إذا تم تحديد نفس الخيار أكثر من مرة ضمن مواصفات عنوان واحد، بقيمه المتساوية أو المختلفة، يعتمد التأثير على نوع الخيار. الخيارات التي تؤدي إلى استدعاءات وظائف مثل setsockopt() تسبب استدعاءات متعددة. مع الخيارات التي تضبط معلمات لاستدعاء مطلوب مثل open() أو تضبط علامات داخلية، تكون قيمة آخر ظهور للخيار فعالة.

وجود أو دلالات العديد من الخيارات تعتمد على النظام. socat عادةً لا يحاول محاكاة ميزات libc أو النواة المفقودة، بل يوفر واجهة للنظام الأساسي. لذا، إذا كان نظام التشغيل يفتقر إلى ميزة، فإن الخيار المتعلق به ببساطة غير متاح على هذا النظام الأساسي.

الفقرات التالية تقدم فقط خيارات العنوان الأكثر شيوعًا. للحصول على مرجع أكثر شمولاً وللعثور على معلومات حول أسماء الخيارات القياسية، والأسماء المستعارة، ومراحل الخيارات، والأنظمة الأساسية، راجع الملف xio.help.

مجموعة خيارات FD

تحتوي مجموعة الخيارات هذه على خيارات يتم تطبيقها على واصف ملف بأسلوب UN*X، بغض النظر عن كيفية إنشائه. نظرًا لأن جميع أنواع عناوين socat الحالية تستند إلى واصفات ملفات، يمكن تطبيق هذه الخيارات على أي عنوان.
ملاحظة: بعض هذه الخيارات هي أيضًا عضو في مجموعة خيارات أخرى، توفر آلية مختلفة، غير قائمة على واصفات الملفات. بالنسبة لهذه الخيارات، يعتمد الأمر على نوع العنوان الفعلي ومجموعات خياراته أي آلية يتم استخدامها. يتم إعطاء الأولوية للآلية الثانية، غير القائمة على واصفات الملفات.

cloexec[=<bool>]
يضبط العلامة FD_CLOEXEC باستخدام استدعاء النظام fcntl() بالقيمة <bool>. إذا تم تعيينها، يتم إغلاق واصف الملف عند استدعاءات عائلة الوظائف exec(). يتعامل socat داخليًا مع هذه العلامة لواصفات الملفات التي يتحكم فيها، لذا في معظم الحالات لن تكون هناك حاجة لتطبيق هذا الخيار.
setlk[=<bool>]
يحاول تعيين قفل كتابة تقديري على الملف بالكامل باستخدام استدعاء النظام fcntl(fd, F_SETLK, ...). إذا كان الملف مقفلاً بالفعل، ينتج عن هذا الاستدعاء خطأ. على Linux، عندما تكون أذونات الملف للمجموعة هي "S" (g-x,g+s)، ويتم تحميل نظام الملفات محليًا بخيار "mand"، يكون القفل إلزاميًا، أي يمنع العمليات الأخرى من فتح الملف.
setlkw[=<bool>]
يحاول تعيين قفل كتابة تقديري منتظر على الملف بالكامل باستخدام استدعاء النظام fcntl(fd, F_SETLKW, ...). إذا كان الملف مقفلاً بالفعل، فإن هذا الاستدعاء يتم حظره. انظر خيار setlk للحصول على معلومات حول جعل هذا القفل إلزاميًا.

قد تتطلب هذه الاستدعاءات الملكية أو امتيازات الجذر.

مجموعة خيارات RANGE

تتحقق هذه الخيارات مما إذا كان يجب منح العميل المتصل حق الوصول. يمكن تطبيقها على مقابس الشبكة التي تستمع وتستقبل. تندرج خيارات tcp-wrappers ضمن هذه المجموعة.

allow-table=<filename>
يأخذ الملف المحدد بدلاً من /etc/hosts.allow.
deny-table=<filename>
يأخذ الملف المحدد بدلاً من /etc/hosts.deny.
tcpwrap-etc=<directoryname>
يبحث عن hosts.allow و hosts.deny في الدليل المحدد. يتم تجاوزه بواسطة خيارات hosts-allow و hosts-deny.

مجموعة خيارات FORK

تستدعي عناوين EXEC أو SYSTEM برنامجًا باستخدام عملية فرعية وتنقل البيانات بين socat والبرنامج. يمكن التأثير على آلية الاتصال بين العمليات باستخدام الخيارات التالية. افتراضيًا، يتم إنشاء `socketpair()` وتعيينه لـ stdin و stdout للعملية الفرعية، بينما يتم توريث stderr من عملية socat، وتستخدم العملية الفرعية واصفات الملفات 0 و 1 للتواصل مع عملية socat الرئيسية.

nofork
لا يقوم بإنشاء عملية فرعية لتنفيذ البرنامج، بدلاً من ذلك يستدعي execvp() أو system() مباشرة من مثيل socat الفعلي. هذا يتجنب تكلفة عملية إضافية بين البرنامج ونظيره، ولكنه يقدم الكثير من القيود:
o
لا يمكن تطبيق هذا الخيار إلا على عنوان socat الثاني.
o
لا يمكن تطبيقه على جزء من عنوان مزدوج.
o
لا يمكن أن يكون عنوان socat الأول OPENSSL أو READLINE.
o
تصبح خيارات socat -b، -t، -D، -l، -v، -x عديمة الفائدة.
o
لكلا العنوانين، تصبح خيارات ignoreeof، cr، و crnl عديمة الفائدة.
o
لكلا العنوانين، تصبح معالجة نهاية/إغلاق خاصة بالعنوان (مثل إغلاق المقبس بأمان) والخيارات ذات الصلة عديمة الفائدة.
o
بالنسبة للعنوان الثاني (الذي يحتوي على الخيار nofork)، لا يمكن تطبيق الخيارات append، cloexec، flock، user، group، mode، nonblock، perm-late، setlk، و setpgid. يمكن استخدام بعض هذه الخيارات على العنوان الأول.

ينشئ زوجًا من الأنابيب غير المسماة للاتصال بين العمليات بدلاً من زوج مقابس.

ينشئ اتصالًا بالعملية الفرعية باستخدام طرفية زائفة تم إنشاؤها باستخدام `openpty()` بدلاً من الافتراضي (socketpair أو ptmx).
ptmx
ينشئ اتصالًا بالعملية الفرعية باستخدام طرفية زائفة تم إنشاؤها عن طريق فتح `/dev/ptmx` أو `/dev/ptc` بدلاً من الافتراضي (socketpair).
pty
ينشئ اتصالًا بالعملية الفرعية باستخدام طرفية زائفة بدلاً من زوج مقابس. ينشئ pty بآلية متاحة. إذا كان كل من openpty و ptmx متاحين، فإنه يستخدم ptmx لأنه يلتزم بمعيار POSIX (مثال).

يجعل pty هو الطرفية المتحكمة للعملية الفرعية (مثال).

يوجه stderr للعملية الفرعية إلى قناة الإخراج الخاصة بها عن طريق جعل stderr `dup()` لـ stdout (مثال).

fdout=<fdnum>
يعين قناة الإخراج للعملية الفرعية إلى واصف الملف الخاص بها <fdnum> بدلاً من stdout (1). يجب على البرنامج الذي تم تشغيله من العملية الفرعية استخدام هذا الواصف للكتابة إلى socat (مثال).

مجموعة خيارات PTY

هذه الخيارات مخصصة للاستخدام مع نوع عنوان pty.

يمنع مرحلة الفتح حتى يفتح عملية ما الجانب التابع لجهاز pty. عادةً، تستمر socat بعد إنشاء pty بفتح العنوان التالي أو بالدخول في حلقة النقل. باستخدام خيار wait-slave، تنتظر socat حتى تفتح عملية ما الجانب التابع لجهاز pty قبل المتابعة. يعمل هذا الخيار فقط إذا كانت نظام التشغيل يوفر استدعاء النظام poll(). وهو يعتمد على سلوك غير موثق لأجهزة pty، لذا فهو لا يعمل على جميع أنظمة التشغيل. تم اختباره بنجاح على Linux و FreeBSD و NetBSD وعلى Tru64 مع openpty.
pty-interval=<seconds>
عند تعيين خيار wait-slave، تتحقق socat بشكل دوري من شرط HUP باستخدام poll() لمعرفة ما إذا كان جانب التابع لجهاز pty قد تم فتحه. متوسط ​​الفاصل الزمني للاستقصاء هو 1 ثانية. استخدم خيار pty-interval [timeval] لتغيير هذه القيمة.

verify[=<bool>]
يتحكم في فحص شهادة الطرف الآخر. القيمة الافتراضية هي 1 (صحيح). قد يؤدي تعطيل التحقق إلى فتح مقبسك للجميع، مما يجعل التشفير عديم الفائدة!
cert=<filename>
يحدد الملف الذي يحتوي على الشهادة والمفتاح الخاص للمصادقة. يجب أن تكون الشهادة بتنسيق OpenSSL (*.pem). مع openssl-listen، يوصى بشدة باستخدام هذا الخيار. باستثناء الخوارزمية aNULL، سيحدث خطأ "لا توجد خوارزميات تشفير مشتركة" عندما لا يتم توفير شهادة.
key=<filename>
يحدد الملف الذي يحتوي على المفتاح الخاص. قد يكون المفتاح الخاص في هذا الملف أو في الملف المحدد مع خيار cert. الطرف الذي يحتاج إلى إثبات أنه مالك شهادة يحتاج إلى المفتاح الخاص.

يحدد الملف الذي يحتوي على معلمات Diffie Hellman. قد تكون هذه المعلمات أيضًا في الملف المحدد مع خيار cert، وفي هذه الحالة لا يلزم خيار dhparams.

يحدد الملف الذي يحتوي على شهادات المرجع (الجذر) الموثوق بها. يجب أن يكون الملف بتنسيق PEM ويجب أن يحتوي على شهادة واحدة أو أكثر. الطرف الذي يتحقق من مصادقة نظيره يثق فقط بالشهادات الموجودة في هذا الملف.

بالنسبة لاتصالات العميل، قم بإجراء طلب تفاوض على أقصى طول للقطعة
للخادم لتحديد الحد الأقصى لحجم الجزء الذي سيرسله الخادم لنا. الأطوال المدعومة هي: 512، 1024، 2048، أو 4096. لاحظ أن هذا الخيار غير قابل للتطبيق على OPENSSL-LISTEN.

يحدد الحد الأقصى لحجم الجزء الذي سنرسله إلى الطرف الآخر. نطاق الطول المدعوم: 512 - 16384. لاحظ أنه في ظل OPENSSL-LISTEN، قد يتم تقييد الحد الأقصى لحجم الجزء بشكل أكبر بواسطة طلب تفاوض الحد الأقصى لطول الجزء الخاص بالعميل، إذا قام بإنشاء واحد.
pseudo
في الأنظمة التي لا يمكن فيها لـ openssl العثور على مصدر إنتروبي ولا يمكن فيها استخدام خادم جمع الإنتروبي، يقوم هذا الخيار بتنشيط آلية لتوفير إنتروبي زائف. يتم تحقيق ذلك عن طريق أخذ الوقت الحالي بالميكروثانية لتغذية مولد الأرقام العشوائية الزائفة الخاص بـ libc بقيمة أولية. ثم يتم تغذية openssl بمخرجات من استدعاءات random().
ملاحظة: هذه الآلية ليست كافية لتوليد مفاتيح آمنة!

تمكين أو تعطيل استخدام الضغط لاتصال. تعيين هذا على "none" يعطل الضغط، تعيينه على "auto" يسمح لـ OpenSSL باختيار أفضل خوارزمية متاحة مدعومة من قبل الطرفين. الافتراضي هو عدم المساس بأي إعدادات متعلقة بالضغط. ملاحظة: يتطلب OpenSSL 0.9.8 أو أعلى وتعطيل الضغط باستخدام OpenSSL 0.9.8 يؤثر على جميع الاتصالات الجديدة في العملية.
commonname=<string>
يحدد الاسم الشائع الذي يجب أن تتطابق معه شهادة الطرف المقابل. مع OPENSSL-CONNECT address، يتجاوز هذا اسم المضيف أو عنوان IP المستهدف المحدد؛ مع OPENSSL-LISTEN، يقوم بتشغيل فحص الاسم الشائع لشهادات الطرف المقابل. هذا الخيار له معنى فقط عندما لا يتم تعطيل خيار verify وتوفر خوارزمية التشفير المختارة شهادة طرف مقابل.
no-sni[=<bool>]
لا تستخدم ميزة Server Name Indication (SNI) من جانب العميل التي تحدد شهادة الخادم المطلوبة.
ملاحظة: يتم استخدام SNI تلقائيًا منذ الإصدار 1.7.4.0 من socat ويستخدم اسم المضيف الشائع أو اسم المضيف المحدد.
snihost=<string>
يحدد اسم مضيف Server Name Indication (SNI) من جانب العميل مختلفًا عن اسم الخادم المخاطب أو الاسم الشائع. قد يكون هذا مفيدًا عندما تحتوي شهادة الخادم على أسماء مضيفين متعددة أو أسماء أحرف بدل لأن اسم مضيف SNI يتم تمريره بوضوح إلى الخادم وقد يتم التنصت عليه؛ مع هذا الخيار، يمكن نقل اسم وهمي للشهادة المطلوبة.
fips
يمكّن وضع FIPS إذا تم تجميعه. للحصول على معلومات حول معيار تنفيذ تشفير FIPS، راجع http://oss-institute.org/fips-faq.html. قد يتطلب هذا الوضع أن يتم إنشاء الشهادات المتضمنة باستخدام إصدار FIPS من openssl. يؤثر تعيين أو مسح هذا الخيار على عنوان OpenSSL واحد على جميع عناوين OpenSSL الخاصة بهذه العملية.

uint32_t (رقم 32 بت غير مُشار إليه) يحدد منفذ VSOCK، يُقرأ باستخدام strtoul().

أمثلة

socat - TCP4:www.domain.org:80
ينقل البيانات بين STDIO (-) واتصال TCP4 بالمضيف www.domain.org على المنفذ 80. ينتج هذا المثال اتصالًا تفاعليًا مشابهًا لـ telnet أو netcat. لم يتم تغيير معلمات طرفية الإدخال القياسي، لذا قد تقوم بإغلاق المرحل باستخدام ^D أو إلغائه باستخدام ^C.
socat -d -d \
READLINE,history=$HOME/.http_history \ 
TCP4:www.domain.org:www,crnl
هذا مشابه للمثال السابق، ولكن يمكنك تحرير السطر الحالي بطريقة تشبه bash (READLINE) واستخدام ملف السجل .http_history؛ socat يطبع رسائل حول التقدم (-d -d). يتم تحديد المنفذ باسم الخدمة (www)، وتُستخدم أحرف إنهاء السطر الشبكية الصحيحة (crnl) بدلاً من NL.
socat \
TCP4-LISTEN:www \ 
TCP4:www.domain.org:www
يقوم بتثبيت موجه منفذ TCP بسيط. باستخدام TCP4-LISTEN، فإنه يستمع على المنفذ المحلي "www" حتى يأتي اتصال، يقبله، ثم يتصل بالمضيف البعيد (TCP4) ويبدأ نقل البيانات. لن يقبل اتصالًا ثانيًا.
socat -d -d -lmlocal2 \
TCP4-LISTEN:80,bind=myaddr1,reuseaddr,fork,su=nobody,range=10.0.0.0/8 \ 
TCP4:www.domain.org:80,bind=myaddr2
موجه منفذ TCP، كل جانب مرتبط بعنوان IP محلي مختلف (bind). هذا المثال يتعامل مع عدد شبه تعسفي من الاتصالات المتوازية أو المتتالية عن طريق إنشاء نسخة (fork) لعملية جديدة بعد كل accept(). يوفر بعض الأمان عن طريق التحويل إلى المستخدم nobody بعد النسخ؛ يسمح فقط بالاتصالات من الشبكة الخاصة 10 (range)؛ بسبب reuseaddr، يسمح بإعادة التشغيل الفوري بعد إنهاء العملية الرئيسية، حتى لو لم يتم إغلاق بعض مقابس الأطفال بالكامل. مع -lmlocal2، يسجل socat إلى stderr حتى الوصول بنجاح إلى حلقة القبول. المزيد من التسجيلات هو di

ENVIRONMENT

SOCAT_LISTEN_IP (input)
(Values 4 or 6) Sets the IP version to be used for listen, recv, and recvfrom addresses if no pf (protocol-family) option is given. Is overridden by socat options -4 or -6.
SOCAT_PREFERRED_RESOLVE_IP (input)
(Values 0, 4, or 6) Sets the IP version to be used when resolving target host names when version is not specified by address type, option pf (protocol-family), or address format. If name resolution does not return a matching entry, the first result (with differing IP version) is taken. With value 0, socat always selects the first record and its IP version.
SOCAT_MAIN_WAIT (input)
Specifies the time (seconds) to sleep the main process on begin of main\(). Useful for debugging.
SOCAT_TRANSFER_WAIT (input)
Specifies the time (seconds) to sleep the process after opening addresses before entering the transfer loop. Useful for debugging.
SOCAT_FORK_WAIT (input)
Specifies the time (seconds) to sleep the parent and child processes after successful fork(). Useful for debugging.
SOCAT_VERSION (output)
Socat sets this variable to its version string, e.g. "1.7.0.0" for released versions or e.g. "1.6.0.1+envvar" for temporary versions; can be used in scripts invoked by socat.
SOCAT_PID (output)
Socat sets this variable to its process id. In case of fork address option, SOCAT_PID gets the child processes id. Forking for exec, system, and SHELL does not change SOCAT_PID.
SOCAT_PPID (output)
Socat sets this variable to its process id. In case of fork, SOCAT_PPID keeps the pid of the master process.
SOCAT_PEERADDR (output)
With passive socket addresses (all LISTEN and RECVFROM addresses), this variable is set to a string describing the peers socket address. Port information is not included.
SOCAT_PEERPORT (output)
With appropriate passive socket addresses (TCP, UDP, and SCTP - LISTEN and RECVFROM), this variable is set to a string containing the number of the peer port.
SOCAT_SOCKADDR (output)
With all LISTEN addresses, this variable is set to a string describing the local socket address. Port information is not included example
SOCAT_SOCKPORT (output)
With TCP-LISTEN, UDP-LISTEN, and SCTP-LISTEN addresses, this variable is set to the local port.
SOCAT_TIMESTAMP (output)
With all RECVFROM addresses where address option so-timestamp is applied, socat sets this variable to the resulting timestamp.
SOCAT_IP_OPTIONS (output)
With all IPv4 based RECVFROM addresses where address option ip-recvopts is applied, socat fills this variable with the IP options of the received packet.
SOCAT_IP_DSTADDR (output)
With all IPv4 based RECVFROM addresses where address option ip-recvdstaddr (BSD) or ip-pktinfo (other platforms) is applied, socat sets this variable to the destination address of the received packet. This is particularly useful to identify broadcast and multicast addressed packets.
SOCAT_IP_IF (output)
With all IPv4 based RECVFROM addresses where address option ip-recvif (BSD) or ip-pktinfo (other platforms) is applied, socat sets this variable to the name of the interface where the packet was received.
SOCAT_IP_LOCADDR (output)
With all IPv4 based RECVFROM addresses where address option ip-pktinfo is applied, socat sets this variable to the address of the interface where the packet was received.
SOCAT_IP_TOS (output)
With all IPv4 based RECVFROM addresses where address option ip-recvtos is applied, socat sets this variable to the TOS (type of service) of the received packet.
SOCAT_IP_TTL (output)
With all IPv4 based RECVFROM addresses where address option ip-recvttl is applied, socat sets this variable to the TTL (time to live) of the received packet.
SOCAT_IPV6_HOPLIMIT (output)
With all IPv6 based RECVFROM addresses where address option ipv6-recvhoplimit is applied, socat sets this variable to the hoplimit value of the received packet.
SOCAT_IPV6_DSTADDR (output)
With all IPv6 based RECVFROM addresses where address option ipv6-recvpktinfo is applied, socat sets this variable to the destination address of the received packet.
SOCAT_IPV6_TCLASS (output)
With all IPv6 based RECVFROM addresses where address option ipv6-recvtclass is applied, socat sets this variable to the transfer class of the received packet.
SOCAT_OPENSSL_X509_ISSUER (output)
Issuer field from peer certificate
SOCAT_OPENSSL_X509_SUBJECT (output)
Subject field from peer certificate
SOCAT_OPENSSL_X509_COMMONNAME (output)
commonName entries from peer certificates subject. Multiple values are separated by " // ".
SOCAT_OPENSSL_X509_* (output)
all other entries from peer certificates subject
SOCAT_OPENSSL_X509V3_DNS (output)
DNS entries from peer certificates extensions - subjectAltName field. Multiple values are separated by " // ".
HOSTNAME (input)
Is used to determine the hostname for logging (see -lh).
LOGNAME (input)
Is used as name for the socks client user name if no socksuser is given.
With options su and su-d, LOGNAME is set to the given user name.
USER (input)
Is used as name for the socks client user name if no socksuser is given and LOGNAME is empty.
With options su and su-d, USER is set to the given user name.
SHELL (output)
With options su and su-d, SHELL is set to the login shell of the given user.
PATH (output)
Can be set with option path for exec, system, and SHELL addresses.
HOME (output)
With options su and su-d, HOME is set to the home directory of the given user.

BUGS

Addresses cannot be nested, so a single socat process cannot, e.g., drive ssl over socks.

Address option ftruncate without value uses default 1 instead of 0.

Verbose modes (-x and/or -v) display line termination characters inconsistently when address options cr or crnl are used: They show the data after conversion in either direction.

The data transfer blocksize setting (-b) is ignored with address readline.
