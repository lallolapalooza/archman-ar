وصف تفصيلي

الصنف SoVRMLImageTexture يستخدم لربط ملف نسيج بالهندسة.

توثيق الصنف التفصيلي مأخوذ حرفيًا من معيار VRML97 (ISO/IEC 14772-1:1997). وهو محمي بحقوق الطبع والنشر من قبل The Web3D Consortium، ويستخدم بإذن من المنظمة:

ImageTexture {
  exposedField MFString url     []
  field        SFBool   repeatS TRUE
  field        SFBool   repeatT TRUE
}

يعرف عقدة ImageTexture خريطة نسيج عن طريق تحديد ملف صورة ومعلمات عامة لربطها بالهندسة. يتم تعريف خرائط النسيج في نظام إحداثيات ثنائي الأبعاد (s, t) يتراوح من [0.0, 1.0] في كلا الاتجاهين. يتوافق الحافة السفلية للصورة مع محور S لخريطة النسيج، والحافة اليسرى للصورة تتوافق مع محور T لخريطة النسيج. البكسل السفلي الأيسر للصورة يتوافق مع s=0, t=0، والبكسل العلوي الأيمن للصورة يتوافق مع s=1, t=1. يتم توضيح هذه العلاقات في الشكل 6.9.


الشكل 6.9

يتم قراءة النسيج من عنوان URL المحدد بواسطة حقل url. عندما يحتوي حقل url على قيم فارغة ([]), يتم تعطيل النسيج. يجب أن تدعم المتصفحات تنسيقات ملفات الصور JPEG و PNG. بالإضافة إلى ذلك، قد تدعم المتصفحات تنسيقات صور أخرى (مثل CGM) والتي يمكن عرضها كصورة ثنائية الأبعاد. يوصى أيضًا بدعم تنسيق GIF (بما في ذلك الشفافية).

يمكن العثور على تفاصيل حول حقل url في 4.5، VRML والشبكة العنكبوتية العالمية.

انظر 4.6.11، خرائط النسيج (http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.6.11)، لوصف عام لخرائط النسيج.

انظر 4.14، نموذج الإضاءة (http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.14)، لوصف معادلات الإضاءة والتفاعل بين النسيج والمواد ومظهر الهندسة.

تحدد حقلا repeatS و repeatT كيفية التفاف النسيج في اتجاهي S و T. إذا كان repeatS صحيحًا (الافتراضي)، يتم تكرار خريطة النسيج خارج نطاق إحداثيات النسيج [0.0, 1.0] في اتجاه S لملء الشكل. إذا كان repeatS خاطئًا، يتم تقييد إحداثيات النسيج في اتجاه S لتكون ضمن النطاق [0.0, 1.0]. حقل repeatT مشابه لحقل repeatS.

بقية توثيق هذا الصنف *ليس* من وثائق معيار VRML97، بل تمت كتابته خصيصًا لوثائق واجهة برمجة تطبيقات Coin3D.


أحد العيوب الشائعة في العديد من البرامج التي تدعم تصدير ملفات VRML أو Inventor، هو تصدير نفس ملف النسيج عدة مرات، ولكن كعقد مختلفة. يمكن أن يؤدي ذلك إلى استهلاك مفرط لذاكرة النسيج وبطء في العرض. فيما يلي مثال لبرنامج يقوم بإصلاح ذلك عن طريق استبدال جميع مثيلات النسيج نفسه بمؤشر إلى العقدة الأولى:

#include <Inventor/actions/SoSearchAction.h>
#include <Inventor/actions/SoWriteAction.h>
#include <Inventor/VRMLnodes/SoVRMLGroup.h>
#include <Inventor/VRMLnodes/SoVRMLImageTexture.h>
#include <Inventor/VRMLnodes/SoVRMLAppearance.h>
#include <Inventor/SoDB.h>
#include <Inventor/SoInput.h>
#include <Inventor/SoOutput.h>
#include <cassert>
int main(int argc, char ** argv)
{
  if (argc < 2) return -1;
  SoDB::init();
  SoInput in;
  if (!in.openFile(argv[1])) return -1;
  if (!in.isFileVRML2()) return -1; // file is not a vrml2 file
  SoVRMLGroup * root = SoDB::readAllVRML(&in);
  if (!root) return -1;
  root->ref();
  SoSearchAction sa;
  sa.setType(SoVRMLImageTexture::getClassTypeId());
  sa.setInterest(SoSearchAction::ALL);
  sa.setSearchingAll(TRUE);
  sa.apply(root);
  SoPathList & pl = sa.getPaths();
  SbDict namedict;
  for (int i = 0; i < pl.getLength(); i++) {
    SoFullPath * p = (SoFullPath*) pl[i];
    if (p->getTail()->isOfType(SoVRMLImageTexture::getClassTypeId())) {
      SoVRMLImageTexture * tex = (SoVRMLImageTexture*) p->getTail();
      if (tex->url.getNum()) {
        // FIXME: we only check the first name here. Should really check all of them
        SbName name = tex->url[0].getString();
        unsigned long key = (unsigned long) ((void*) name.getString());
        void * tmp;
        if (!namedict.find(key, tmp)) {
          (void) namedict.enter(key, tex);
        }
        else if (tmp != (void*) tex) {
          SoNode * parent = p->getNodeFromTail(1);
          if (parent->isOfType(SoVRMLAppearance::getClassTypeId())) {
            ((SoVRMLAppearance*)parent)->texture = (SoNode*) tmp;
          }
          else {
            // not a valid VRML2 file. Print a warning or something.
          }
        }
      }
    }
  }
  sa.reset();
  SoOutput out;
  out.setHeaderString("#VRML V2.0 utf8");
  SoWriteAction wa(&out);
  wa.apply(root);
  root->unref();
}

Detailed Description

Image Texture node. This node defines a texture map which is specified by an Image node. VRML nodes like BaseColor, DiffuseColor, EmissiveColor, SpecularColor, and Shininess can use textures.

The image can be specified inline using the SbImage class or by a URL.

The field url is inherited from SoVRMLTexture. If this field is empty, the image is specified inline using the image field.
