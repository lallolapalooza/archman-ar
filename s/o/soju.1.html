الاسم

soju - جسر IRC

الملخص

soju [خيارات...]

الوصف

soju هو جسر IRC سهل الاستخدام. يتصل بخوادم IRC المنبع نيابة عن المستخدم لتوفير ميزات إضافية.

  • عدة مستخدمين منفصلين يتشاركون نفس الجسر، لكل منهم خوادمه المنبع الخاصة
  • إرسال سجل الرسائل (الرسائل المستلمة أثناء انقطاع اتصال المستخدم بالجسر)، مع مخازن مؤقتة لكل عميل

للاتصال بالجسر، استخدم اسم المستخدم وكلمة المرور الخاصين بالجسر. لاستخدام عميل لا يدعم امتداد IRC soju.im/bouncer-networks، قم بإعداد اتصال واحد لكل خادم تم تكوينه في soju، وقم بتحديد اسم الشبكة في اسم المستخدم: "<اسم المستخدم>/<اسم الشبكة>". عندها يمكن الانضمام والمغادرة من القنوات كما لو كنت متصلاً مباشرة بالخادم المنبع.

لكي تعمل سجلات كل عميل على العملاء الذين لا يدعمون امتداد IRCv3 chathistory، يحتاج العملاء إلى تحديد اسمهم. يمكن القيام بذلك عن طريق إضافة لاحقة "@<اسم العميل>" إلى اسم المستخدم.

عند الانضمام إلى قناة، سيتم حفظ القناة وسيتم الانضمام إليها تلقائيًا عند الاتصال التالي. عند التسجيل أو المصادقة مع NickServ، سيتم حفظ بيانات الاعتماد وسيتم استخدامها تلقائيًا عند الاتصال التالي إذا كان الخادم يدعم SASL. عند مغادرة قناة مع السبب "detach"، سيتم فصل القناة بدلاً من مغادرتها.

إذا كانت الشبكة المحددة في اسم المستخدم غير موجودة، وكان اسم الشبكة اسم مضيف صالح، فسيتم إضافة الشبكة تلقائيًا.

عندما تنقطع جميع العملاء عن الجسر، يتم تمييز المستخدم تلقائيًا على أنه غير موجود (away) بشكل افتراضي.

سيقوم soju بإعادة تحميل ملف التكوين، وشهادة/مفتاح TLS، وملف MOTD عند تلقي إشارة HUP. لا يمكن إعادة تحميل خيارات التكوين listen و db و log.

يمكن للمسؤولين بث رسالة إلى جميع مستخدمي الجسر عبر /notice $<اسم المضيف> <النص>، أو عبر /notice $* <النص> إذا لم يكن الاتصال مرتبطًا بشبكة معينة. سيتلقى جميع مستخدمي الجسر المتصلين حالياً الرسالة من الخدمة الخاصة BouncerServ.

خيارات

-h, -help

عرض رسالة المساعدة والخروج.

-config <مسار>

مسار ملف التكوين. إذا لم يتم تعيينه، يتم استخدام ملف تكوين افتراضي.

-debug

تمكين تسجيل التصحيح (سيؤدي هذا إلى تسريب معلومات حساسة مثل كلمات المرور). يمكن تجاوز ذلك في وقت التشغيل باستخدام أمر الخدمة server debug.

-listen <uri>

عنوان URI للاستماع (الافتراضي: ":6697"). يمكن تحديده عدة مرات.

ملف التكوين

يحتوي ملف التكوين على توجيه واحد لكل سطر.

مثال:

listen ircs://
tls cert.pem key.pem
hostname example.org

التوجيهات التالية مدعومة:

listen <uri>

عنوان URI للاستماع (الافتراضي: ":6697").

عناوين URI التالية مدعومة:

  • [ircs://][host][:port] تستمع باستخدام TLS عبر TCP (المنفذ الافتراضي إذا تم حذفه: 6697)
  • irc://localhost[:port] تستمع بنص عادي عبر TCP (المنفذ الافتراضي إذا تم حذفه: 6667، يجب أن يكون المضيف "localhost")
  • irc+insecure://[host][:port] تستمع بنص عادي عبر TCP (المنفذ الافتراضي إذا تم حذفه: 6667)
  • unix://<path> تستمع على مقبس نطاق Unix
  • https://[host][:port] تستمع لاتصالات HTTPS (المنفذ الافتراضي: 443) وتعالج الطلبات التالية:
  • /socket لـ WebSocket
  • /uploads (والدلائل الفرعية) لتحميل الملفات
  • http://localhost[:port] تستمع لاتصالات HTTP بنص عادي (المنفذ الافتراضي: 80، يجب أن يكون المضيف "localhost") وتعالج الطلبات مثل https://
  • http+insecure://[host][:port] تستمع لاتصالات HTTP بنص عادي (المنفذ الافتراضي: 80) وتعالج الطلبات مثل https://
  • http+unix://<path> تستمع لاتصالات HTTP بنص عادي على مقبس نطاق Unix وتعالج الطلبات مثل https://
  • wss://[host][:port] تستمع لاتصالات WebSocket عبر TLS (المنفذ الافتراضي: 443)
  • ws://localhost[:port] تستمع لاتصالات WebSocket بنص عادي (المنفذ الافتراضي: 80، يجب أن يكون المضيف "localhost")
  • ws+insecure://[host][:port] تستمع لاتصالات WebSocket بنص عادي (المنفذ الافتراضي: 80)
  • ws+unix://<path> تستمع لاتصالات WebSocket بنص عادي على مقبس نطاق Unix
  • ident://[host][:port] تستمع لاتصالات ident بنص عادي (المنفذ الافتراضي: 113)
  • http+prometheus://localhost:<port> تستمع لاتصالات HTTP بنص عادي وتقدم مقاييس Prometheus (يجب أن يكون المضيف "localhost")
  • http+pprof://localhost:<port> تستمع لاتصالات HTTP بنص عادي وتقدم بيانات تحليل وقت تشغيل pprof (يجب أن يكون المضيف "localhost"). لمزيد من المعلومات، انظر: https://pkg.go.dev/net/http/pprof.
  • unix+admin://[path] تستمع على مقبس نطاق Unix لاتصالات إدارية، مثل sojuctl (المسار الافتراضي: /run/soju/admin)

إذا تم حذف المخطط، فسيتم افتراض "ircs". إذا تم تحديد توجيهات listen متعددة، فسيستمع soju على كل منها.

hostname <اسم>

اسم مضيف الخادم (الافتراضي: اسم مضيف النظام).

يجب تعيين هذا إلى اسم مجال مؤهل بالكامل.

title <عنوان>

عنوان الخادم. سيتم إرسال هذا كقيمة ISUPPORT NETWORK عندما لا يحدد العملاء شبكة معينة.

tls <شهادة> <مفتاح>

تمكين دعم TLS. يجب أن تكون ملفات الشهادة والمفتاح بتنسيق PEM.

db <مشغل> <مصدر>

تعيين موقع قاعدة البيانات لتخزين المستخدمين والشبكات والقنوات. افتراضيًا، يتم فتح قاعدة بيانات sqlite3 في "./soju.db".

المشغلات المدعومة:

  • sqlite3 يتوقع أن يكون source مسارًا لملف SQLite
  • postgres يتوقع أن يكون source قائمة مفصولة بمسافات من معلمات key=value، على سبيل المثال db postgres "host=/run/postgresql dbname=soju". لاحظ أن sslmode يُفترض تلقائيًا أنه require. لمزيد من المعلومات حول سلاسل الاتصال، انظر: https://pkg.go.dev/github.com/lib/pq#hdr-Connection_String_Parameters.

message-store <مشغل> [مصدر]

تعيين موقع قاعدة البيانات لرسائل IRC. افتراضيًا، يتم استخدام db.

المشغلات المدعومة:

  • db يخزن الرسائل في قاعدة البيانات. يتم استخدام فهرس بحث نصي كامل لتسريع استعلامات البحث.
  • fs يخزن الرسائل على القرص، بنفس تنسيق ZNC. source مطلوب وهو المسار الدليلي الجذر لقاعدة البيانات. هذا التنسيق على القرص قابل للفقدان: يتم تجاهل بعض رسائل IRCv3 (مثل TAGMSG) وجميع علامات الرسائل.
  • memory يخزن الرسائل في الذاكرة. لكل قناة/مستخدم، يتم الاحتفاظ بآخر 4K رسالة فقط في الذاكرة، ويتم تجاهل الرسائل الأقدم. هذا المشغل أساسي جدًا ولا يدعم ميزات مثل امتداد chathistory والبحث.

(log هو اسم مستعار تم إيقافه لهذه التوجيهية.)

file-upload <مشغل> [مصدر]

تعيين موقع قاعدة البيانات للملفات التي تم تحميلها.

يتطلب تحميل الملف إعداد مستمع HTTP (راجع عناوين URI https:// و http+insecure:// في توجيه listen).

المشغلات المدعومة:

  • fs يخزن الملفات التي تم تحميلها على القرص. source مطلوب.
  • http يخزن الملفات التي تم تحميلها من خلال خدمة HTTP خارجية. source مطلوب ويجب أن يكون عنوان URL لـ HTTP. عند استلام ملف، سيرسل soju طلب POST HTTP إلى هذا العنوان، ويرسل الملف كما هو في نص طلب HTTP؛
