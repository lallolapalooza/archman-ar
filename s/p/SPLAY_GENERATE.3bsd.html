الوصف

تحدد هذه الماكرو هياكل البيانات لأنواع مختلفة من الأشجار: أشجار الانفراج (splay trees) وأشجار ثنائية متوازنة (red-black trees).

في تعريفات الماكرو، TYPE هو اسم علامة بنية معرفة من قبل المستخدم يجب أن تحتوي على حقل يسمى FIELD، من نوع SPLAY_ENTRY أو RB_ENTRY. الوسيط HEADNAME هو اسم علامة بنية معرفة من قبل المستخدم يجب الإعلان عنها باستخدام الماكرو SPLAY_HEAD() أو RB_HEAD(). الوسيط NAME يجب أن يكون بادئة اسم فريدة لكل شجرة تم تعريفها.

يتم الإعلان عن نماذج الدوال باستخدام SPLAY_PROTOTYPE أو RB_PROTOTYPE أو RB_PROTOTYPE_STATIC. يتم إنشاء أجسام الدوال باستخدام SPLAY_GENERATE أو RB_GENERATE أو RB_GENERATE_STATIC. انظر الأمثلة أدناه لمزيد من الشرح حول كيفية استخدام هذه الماكرو.

أشجار الانفراج

شجرة الانفراج هي بنية بيانات ذاتية التنظيم. كل عملية على الشجرة تسبب حدوث انفراج. ينقل الانفراج العقدة المطلوبة إلى جذر الشجرة ويعيد توازنها جزئيًا.

هذا له فائدة أن تفضيل الوصول يؤدي إلى عمليات بحث أسرع حيث تتحرك العقد المطلوبة إلى أعلى الشجرة. من ناحية أخرى، تسبب كل عملية بحث كتابات في الذاكرة.

يحدد نظرية التوازن الوقت الإجمالي للوصول لـ m عملية وإدخال n في شجرة فارغة مبدئيًا على أنه O((m + n)lg n). التكلفة المجمعة لسلسلة من m وصول إلى شجرة انفراج هي O(lg n).

تترأس شجرة الانفراج بنية معرفة بواسطة الماكرو SPLAY_HEAD(). يتم الإعلان عن بنية SPLAY_HEAD على النحو التالي:

SPLAY_HEAD(HEADNAME, TYPE) head;

حيث HEADNAME هو اسم البنية المراد تعريفها، وهيكل TYPE هو نوع العناصر المراد إدخالها في الشجرة.

الماكرو SPLAY_ENTRY() يعلن عن بنية تسمح بتوصيل العناصر في الشجرة.

لأجل استخدام الدوال التي تعالج بنية الشجرة، يجب الإعلان عن نماذجها باستخدام الماكرو SPLAY_PROTOTYPE()، حيث NAME هو معرف فريد لهذه الشجرة المعينة. الوسيط TYPE هو نوع البنية التي تتم إدارتها بواسطة الشجرة. الوسيط FIELD هو اسم العنصر المعرف بواسطة SPLAY_ENTRY().

يتم إنشاء أجسام الدوال باستخدام الماكرو SPLAY_GENERATE(). يأخذ نفس وسائط الماكرو SPLAY_PROTOTYPE()، ولكنه يجب استخدامه مرة واحدة فقط.

أخيرًا، الوسيط CMP هو اسم دالة تستخدم لمقارنة عقد الشجرة ببعضها البعض. تأخذ الدالة وسيطين من نوع struct TYPE *. إذا كان الوسيط الأول أصغر من الثاني، تعيد الدالة قيمة أصغر من الصفر. إذا كانا متساويين، تعيد الدالة صفرًا. خلاف ذلك، يجب أن تعيد قيمة أكبر من الصفر. تحدد دالة المقارنة ترتيب عناصر الشجرة.

الماكرو SPLAY_INIT() يقوم بتهيئة الشجرة المشار إليها بواسطة head.

يمكن أيضًا تهيئة شجرة الانفراج بشكل ثابت باستخدام الماكرو SPLAY_INITIALIZER() على النحو التالي:

SPLAY_HEAD(HEADNAME, TYPE) head = SPLAY_INITIALIZER(&head);

يقوم الماكرو SPLAY_INSERT() بإدراج العنصر الجديد elm في الشجرة. عند النجاح، يتم إرجاع NULL. إذا كان عنصر مطابق موجودًا بالفعل في الشجرة، يتم إيقاف الإدراج، ويتم إرجاع مؤشر إلى العنصر الموجود.

يقوم الماكرو SPLAY_REMOVE() بإزالة العنصر elm من الشجرة المشار إليها بواسطة head. عند النجاح، يتم إرجاع مؤشر إلى العنصر المحذوف. يتم إرجاع NULL إذا لم يكن elm موجودًا في الشجرة.

يمكن استخدام الماكرو SPLAY_FIND() للعثور على عنصر معين في الشجرة.

struct TYPE find, *res;
find.key = 30;
res = SPLAY_FIND(NAME, &head, &find);

يمكن استخدام الماكرو SPLAY_ROOT() و SPLAY_MIN() و SPLAY_MAX() و SPLAY_NEXT() للتنقل عبر الشجرة:

for (np = SPLAY_MIN(NAME, &head); np != NULL; np = SPLAY_NEXT(NAME, &head, np))

أو، للتبسيط، يمكن استخدام الماكرو SPLAY_FOREACH():

SPLAY_FOREACH(np, NAME, &head)

يجب استخدام الماكرو SPLAY_EMPTY() للتحقق مما إذا كانت شجرة الانفراج فارغة.

أشجار ثنائية متوازنة

شجرة ثنائية متوازنة هي شجرة بحث ثنائية مع لون العقدة كسمة إضافية. تفي بمجموعة من الشروط:

  1. كل مسار بحث من الجذر إلى ورقة يتكون من نفس العدد من العقد السوداء،
  2. كل عقدة حمراء (باستثناء الجذر) لها أب أسود،
  3. كل ورقة هي عقدة سوداء.

كل عملية على شجرة ثنائية متوازنة محدودة بـ O(lg n). أقصى ارتفاع لشجرة ثنائية متوازنة هو 2lg (n+1).

تترأس شجرة ثنائية متوازنة بنية معرفة بواسطة الماكرو RB_HEAD(). يتم الإعلان عن بنية RB_HEAD على النحو التالي:

RB_HEAD(HEADNAME, TYPE) head;

حيث HEADNAME هو اسم البنية المراد تعريفها، وهيكل TYPE هو نوع العناصر المراد إدخالها في الشجرة.

الماكرو RB_ENTRY() يعلن عن بنية تسمح بتوصيل العناصر في الشجرة.

لأجل استخدام الدوال التي تعالج بنية الشجرة، يجب الإعلان عن نماذجها باستخدام الماكرو RB_PROTOTYPE() أو RB_PROTOTYPE_STATIC()، حيث NAME هو معرف فريد لهذه الشجرة المعينة. الوسيط TYPE هو نوع البنية التي تتم إدارتها بواسطة الشجرة. الوسيط FIELD هو اسم العنصر المعرف بواسطة RB_ENTRY().

يتم إنشاء أجسام الدوال باستخدام الماكرو RB_GENERATE() أو RB_GENERATE_STATIC(). تأخذ هذه الماكرو نفس وسائط الماكرو RB_PROTOTYPE() و RB_

PROTOTYPE_STATIC() أو PROTOTYPE() ، ولكن يجب استخدامهما مرة واحدة فقط.

أخيرًا ، الوسيط CMP هو اسم دالة تستخدم لمقارنة عقد الأشجار ببعضها البعض. تأخذ الدالة وسيطين من النوع struct TYPE *. إذا كان الوسيط الأول أصغر من الثاني ، فترجع الدالة قيمة أصغر من الصفر. إذا كانا متساويين ، فترجع الدالة صفرًا. وإلا ، فيجب أن ترجع قيمة أكبر من الصفر. تحدد دالة المقارنة ترتيب عناصر الشجرة.

يقوم الماكرو RB_INIT() بتهيئة الشجرة المشار إليها بواسطة head.

يمكن أيضًا تهيئة شجرة red-black بشكل ثابت باستخدام الماكرو RB_INITIALIZER() على النحو التالي:

RB_HEAD(HEADNAME, TYPE) head = RB_INITIALIZER(&head);

يقوم الماكرو RB_INSERT() بإدراج العنصر الجديد elm في الشجرة. عند النجاح ، يتم إرجاع NULL. إذا كان عنصر مطابق موجودًا بالفعل في الشجرة ، يتم إلغاء عملية الإدراج ، ويتم إرجاع مؤشر إلى العنصر الموجود.

يقوم الماكرو RB_REMOVE() بإزالة العنصر elm من الشجرة المشار إليها بواسطة head. ترجع RB_REMOVE() القيمة elm.

يمكن استخدام الماكروين RB_FIND() و RB_NFIND() للعثور على عنصر معين في الشجرة. يبحث RB_FIND() عن العقدة التي لها نفس مفتاح elm. يبحث RB_NFIND() عن أول عقدة أكبر من أو تساوي مفتاح البحث.

struct TYPE find, *res;
find.key = 30;
res = RB_FIND(NAME, &head, &find);

يمكن استخدام الماكروات RB_ROOT()، RB_MIN()، RB_MAX()، RB_NEXT()، و RB_PREV() للتنقل في الشجرة:

for (np = RB_MIN(NAME, &head); np != NULL; np = RB_NEXT(NAME, &head, np))

أو ، للتبسيط ، يمكن استخدام الماكروين RB_FOREACH() أو RB_FOREACH_REVERSE():

RB_FOREACH(np, NAME, &head)

تقوم الماكروات RB_FOREACH_SAFE() و RB_FOREACH_REVERSE_SAFE() بالتنقل في الشجرة المشار إليها بواسطة head في اتجاه أمامي أو عكسي على التوالي ، وتعيين كل عنصر بدوره إلى np. ومع ذلك ، على عكس نظيراتها غير الآمنة ، فإنها تسمح بإزالة np وكذلك تحريره من داخل الحلقة بأمان دون التأثير على التنقل.

يجب استخدام الماكرو RB_EMPTY() للتحقق مما إذا كانت شجرة red-black فارغة.

أمثلة

يوضح المثال التالي كيفية تعريف شجرة red-black تحتفظ بالأعداد الصحيحة. يتم إدراج القيم فيها وطباعة محتويات الشجرة بالترتيب. أخيرًا ، تتم طباعة الهيكل الداخلي للشجرة.

#include <sys/tree.h>
#include <err.h>
#include <stdio.h>
#include <stdlib.h>

struct node {
	RB_ENTRY(node) entry;
	int i;
};

int	intcmp(struct node *, struct node *);
void	print_tree(struct node *);

int
intcmp(struct node *e1, struct node *e2)
{
	return (e1->i < e2->i ? -1 : e1->i > e2->i);
}

RB_HEAD(inttree, node) head = RB_INITIALIZER(&head);
RB_PROTOTYPE(inttree, node, entry, intcmp)
RB_GENERATE(inttree, node, entry, intcmp)

int testdata[] = {
	20, 16, 17, 13, 3, 6, 1, 8, 2, 4, 10, 19, 5, 9, 12, 15, 18,
	7, 11, 14
};

void
print_tree(struct node *n)
{
	struct node *left, *right;

	if (n == NULL) {
		printf("nil");
		return;
	}
	left = RB_LEFT(n, entry);
	right = RB_RIGHT(n, entry);
	if (left == NULL && right == NULL)
		printf("%d", n->i);
	else {
		printf("%d(", n->i);
		print_tree(left);
		printf(",");
		print_tree(right);
		printf(")");
	}
}

int
main(void)
{
	int i;
	struct node *n;

	for (i = 0; i < sizeof(testdata) / sizeof(testdata[0]); i++) {
		if ((n = malloc(sizeof(struct node))) == NULL)
			err(1, NULL);
		n->i = testdata[i];
		RB_INSERT(inttree, &head, n);
	}

	RB_FOREACH(n, inttree, &head) {
		printf("%d\n", n->i);
	}
	print_tree(RB_ROOT(&head));
	printf("\n");
	return (0);
}

ملاحظات

محاولة تحرير شجرة بالطريقة التالية هو خطأ شائع:

SPLAY_FOREACH(var, NAME, &head) {
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
free(head);

نظرًا لأنه تم تحرير var ، فإن الماكرو FOREACH() يشير إلى مؤشر قد تم إعادة تخصيصه بالفعل. الكود الصحيح يحتاج إلى متغير ثانٍ.

for (var = SPLAY_MIN(NAME, &head); var != NULL; var = nxt) {
	nxt = SPLAY_NEXT(NAME, &head, var);
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
