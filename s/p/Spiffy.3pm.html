Spiffy(3pm)

الحزمة: perl-spiffy

التراخيص: GPL, PerlArtistic

"AAA-DDD" و "AAA-CCC" هي الأسماء الحقيقية للفئات التي يتم إنشاؤها. ميزة هذا الأسلوب هي أن المزج في CCC لا يمحو أي وظائف من AAA، و DDD لا يتعارض مع AAA أو CCC. إذا قمت بدمج وظيفة في CCC موجودة أيضًا في AAA، فلا يزال بإمكانك الوصول إليها باستخدام "super".

عندما يقوم Spiffy بالمزج في CCC، يتم جلب جميع وظائف CCC التي لا تبدأ بشرطة سفلية. في الواقع، يذهب أبعد من ذلك: إذا كان CCC فئة مشتقة، فسيتم جلب جميع الوظائف التي يمكن لـ CCC "وراثتها". هذا قوي جدًا، ربما قوي جدًا.

لتقييد ما تقوم بدمجه، يقوم Spiffy بإلغاء مفهوم أدوار Perl6. يُستخدم مصطلح role بشكل أوسع في Spiffy، على الرغم من أنه مشابه لقائمة الاستيراد التي يستخدمها وحدة Exporter، ويمكنك استخدام مجموعات (علامات) ونفي. إذا كان العنصر الأول في قائمتك يستخدم النفي، فسيبدأ Spiffy بجميع الوظائف التي يمكن لفئة mixin الخاصة بك القيام بها.

use EEE -mixin => qw(:tools walk !run !:sharp_tools);

في هذا المثال، "walk" و "run" هما وظيفتان يمكن لـ EEE القيام بهما، و "tools" و "sharp_tools" هما أدوار فئة EEE. كيف تعرف EEE هذه الأدوار؟ ببساطة عن طريق تعريف وظائف تسمى "_role_tools" و "_role_sharp_tools" والتي تعيد قوائم بوظائف أعمق. (وربما أدوار أخرى!) الجزء المثير للاهتمام هنا هو أنه نظرًا لأن الأدوار هي مجرد وظائف، فيمكن أيضًا وراثتها. خذ ذلك يا Perl6!

التصفية

باستخدام علامة "-Base" بدلاً من "-base"، لن تحتاج أبدًا إلى كتابة السطر:

my $self = shift;

يتم إضافة هذا التوجيه إلى جميع الإجراءات الفرعية في فئتك بواسطة مرشح مصدر. الحيلة بسيطة وسريعة، لذلك لا توجد تكلفة أداء كبيرة لإنشاء رمز نظيف مثل Ruby و Python.

package Example;
use Spiffy -Base;
sub crazy {
    $self->nuts;
}
sub wacky { }
sub new() {
    bless [], shift;
}

هو بالضبط نفس:

package Example;
use Spiffy -base;
use strict;use warnings;
sub crazy {my $self = shift;
    $self->nuts;
}
sub wacky {my $self = shift; }
sub new {
    bless [], shift;
}
;1;

ملاحظة: الأقواس الفارغة بعد الوظيفة الفرعية "new" تمنع إضافة $self. لاحظ أيضًا أنه يتم إضافة الرمز الإضافي إلى الأسطر الموجودة لضمان عدم تغيير أرقام الأسطر.

"-Base" يقوم أيضًا بتنشيط الأوامر "strict" و "warnings"، ويضيف السطر الإضافي "1;" إلى وحدتك.

الوظائف الخاصة

يدعم Spiffy الآن الوظائف الخاصة عند استخدام آلية التصفية "-Base". تحتاج فقط إلى التصريح عن الإجراءات الفرعية باستخدام الكلمة المفتاحية "my" واستدعائها بعلامة '$' أمامها. على سبيل المثال:

package Keen;
use SomethingSpiffy -Base;
# وظيفة عامة عادية
sub swell {
    $self->$stinky;
}
# وظيفة خاصة بالقاموس. لا يمكن استدعاؤها من خارج هذا الملف.
my sub stinky {
    ...
}

تصحيح أخطاء Spiffy

وظيفة XXX مفيدة جدًا لتصحيح الأخطاء لأنك يمكنك إدراجها في أي مكان تقريبًا وستعرض محتويات بياناتك بتنسيق YAML نظيف. لنأخذ التوجيه التالي:

my @stuff = grep { /keen/ } $self->find($a, $b);

إذا كانت لديك مشكلة مع هذا التوجيه، يمكنك تصحيحه في أي من الطرق التالية:

XXX my @stuff = grep { /keen/ } $self->find($a, $b);
my @stuff = XXX grep { /keen/ } $self->find($a, $b);
my @stuff = grep { /keen/ } XXX $self->find($a, $b);
my @stuff = grep { /keen/ } $self->find(XXX $a, $b);

XXX سهل الإدراج والإزالة. من التقليدي أيضًا تمييز الأجزاء غير المؤكدة من الرمز بـ XXX. سيؤدي هذا إلى تسهيل العثور عليها من قبل مصححي الأخطاء إذا نسيت إزالتها.

WWW و YYY جيدان لأنهما يعرضان وسيطاتهما ثم يعيدان نفس الشيء. لذلك، يمكنك إدراجها في العديد من المواقع ولا يزال الرمز يعمل كما كان. استخدم ZZZ عندما تحتاج إلى التوقف مع تفريغ YAML وتتبع كامل للمكدس.

يتم عرض وظائف تصحيح الأخطاء افتراضيًا إذا استخدمت الخيار "-base"، ولكن فقط إذا كنت قد استخدمت بالفعل الخيار "-XXX". لتصدير جميع الوظائف الأربعة، استخدم العلامة export:

use SomeSpiffyModule ':XXX';

لإجبار وظائف تصحيح الأخطاء على استخدام Data::Dumper بدلاً من YAML:

use SomeSpiffyModule -dumper;

وظائف Spiffy

يصف هذا القسم الوظائف التي يكشف عنها Spiffy. يتم الكشف عن الوظائف "field" و "const" و "stub" و "super" فقط عند استخدام الخيارات "-base" أو "-Base".

field
تحدد وظائف الوصول لحقل في فئتك: 
package Example;
use Spiffy -Base;
field 'foo';
field bar => [];
sub lalala {
    $self->foo(42);
    push @{$self->{bar}}, $self->foo;
}

المعامل الأول الذي يتم تمريره إلى "field" هو اسم السمة التي يتم تعريفها. يمكن لوظائف الوصول أن تحتوي على قيمة افتراضية اختيارية. يتم إرجاع هذه القيمة إذا لم يتم تعيين قيمة للحقل في الكائن.

const
const bar => 42;

وظيفة "const" مشابهة لـ "field" باستثناء أنها غير قابلة للتغيير. كما أنها لا تخزن البيانات في الكائن. تأكد من تزويد "const" بقيمة افتراضية، وإلا فإن الوظيفة التي تم إنشاؤها ستكون عديمة الفائدة.

stub
stub 'cigar';

وظيفة "stub" تنشئ وظيفة تتوقف برسالة مناسبة. الفكرة هي أن الفئات الفرعية يجب أن تنفذ هذه الوظائف حتى لا يتم استدعاء وظائف stub.

super
إذا تم استدعاء هذه الوظيفة بدون معاملات، فستستدعي نفس الوظيفة التي يتم تنفيذها، أعلى في تسلسل ISA، مع تمرير جميع نفس المعاملات. إذا تم استدعاؤها بمعاملات، فستستخدم تلك المعاملات مع $self في المقدمة. بمعنى آخر، إنها تعمل ببساطة كما تتوقع. 
sub foo {
    super;             # نفس $self->SUPER::foo(@_);
    super('hello');    # نفس $self->SUPER::foo('hello');
    $self->bar(42);
}
sub new() {
    my $self = super;
    $self->init;
    return $self;
}

"super" لن تفعل شيئًا ببساطة إذا لم تكن هناك وظيفة super. أخيرًا، تقوم "super" بالعمل الصحيح في الإجراءات الفرعية AUTOLOAD.

الوظائف

يسرد هذا القسم جميع الوظائف التي ترثها أي فئة فرعية من Spiffy تلقائيًا.

mixin
وظيفة لدمج فئة في وقت التشغيل. تتلقى نفس المعاملات مثل "use mixin" ...". تجعل الفئة المستهدفة دمجا للمكالمة. 
$self->mixin('SomeClass');
$object->mixin('SomeOtherClass' => 'some_method');
parse_arguments
تأخذ هذه الوظيفة قائمة من المعاملات وتقوم بتجميعها في أزواج. تسمح بالمعاملات المنطقية التي قد تحتوي أو لا تحتوي على قيمة (القيمة الافتراضية هي 1). تعيد الوظيفة مرجعًا إلى تجزئة تحتوي على جميع الأزواج كمفاتيح وقيم في التجزئة. يتم إرجاع المعاملات التي لا يمكن تجميعها كقائمة. إليك مثال: 
sub boolean_arguments { qw(-has_spots -is_yummy) }
sub paired_arguments { qw(-name -size) }
my ($pairs, @others) = $self->parse_arguments(
    'red', 'white',
    -name => 'Ingy',
    -has_spots =>
    -size => 'large',
    'black',
    -is_yummy => 0,
);

بعد هذه المكالمة، ستحتوي $pairs على:

{
    -name => 'Ingy',
    -has_spots => 1,
    -size => 'large',
    -is_yummy => 0,
}

وستحتوي @others على 'red' و 'white' و 'black'.

boolean_arguments
تعيد قائمة المعاملات المعترف بها كمنطقية. قم بتجاوز هذه الوظيفة لتعريف قائمتك الخاصة.
paired_arguments
تعيد قائمة المعاملات المعترف بها كأزواج. قم بتجاوز هذه الوظيفة لتعريف قائمتك الخاصة.

المعاملات

عند استخدام وحدة Spiffy أو فئة فرعية منها، يمكنك تمرير قائمة من المعاملات إليها. تتم معالجة هذه المعاملات باستخدام وظيفة "parse_arguments" الموضحة أعلاه. يُستخدم المعامل الخاص "-base" لجعل الحزمة الحالية فئة فرعية لوحدة Spiffy قيد الاستخدام.

أي معامل غير مجمع يعمل كقائمة عادية؛ إنه مثل تلك المستخدمة مع وحدة Exporter.

استخدام Spiffy مع base.pm

الطريقة الصحيحة لاستخدام وحدة Spiffy كفئة أساسية هي مع المعامل "-base" في توجيه "use". يختلف هذا عن الوحدات النموذجية حيث ترغب في استخدام "use base".

package Something;
use Spiffy::Module -base;
use base 'NonSpiffy::Module';

قد يكون من الصعب الآن تتبع ما هو Spiffy وما ليس كذلك. لهذا السبب تم تصميم Spiffy حقًا للعمل مع base.

USING SPIFFY WITH BASE.PM

The base.pm module is used to specify the base classes for your class. It is used like this:

  package MyClass;
  use base qw(AnotherClass BaseClass);

Spiffy can be used with base.pm. In fact, it is the default behavior when Spiffy is used.

  package MyClass;
  use Spiffy;
  use base qw(Spiffy::Class);

In this case, Spiffy automatically makes "Spiffy::Class" a base class. You don't need to do anything special.

If you want to use Spiffy on a class that is not Spiffy, you can do this:

package Something;
use Spiffy -base;
use base 'NonSpiffy::Class';

Or even:

package Something;
use Spiffy -base;
use base qw(NonSpiffy::Class AnotherNonSpiffy::Class);

And if you want to use Spiffy on a class that is Spiffy, and also use non-Spiffy classes as base classes, you can do this:

package Something;
use Spiffy;
use base 'Spiffy::Class';
use base 'NonSpiffy::Class';

"use base" is also very useful when your class is not an actual module (a separate file) but just a package in some file that has already been loaded. "base" will work whether the class is a module or not, while the "-base" syntax cannot work that way, since "use" always tries to load a module.

base.pm Caveats

To make Spiffy work with base.pm, a dirty trick was played. Spiffy swaps "base::import" with its own version. If the base modules are not Spiffy, Spiffy calls the original base::import. If the base modules are Spiffy, then Spiffy does its own thing.

There are two caveats.

Spiffy must be loaded first.
If Spiffy is not loaded and "use base" is invoked on a Spiffy module, Spiffy will die with a useful message telling the author to read this documentation. That's because Spiffy needed to do the import swap beforehand.

If you get this error, simply put a statement like this up front in your code:

use Spiffy ();
No Mixing
"base.pm" can take multiple arguments. And this works with Spiffy as long as all the base classes are Spiffy, or they are all non-Spiffy. If they are mixed, Spiffy will die. In this case just use separate "use base" statements.
