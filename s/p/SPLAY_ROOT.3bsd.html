الوصف

تحدد هذه الماكرو هياكل بيانات لأنواع مختلفة من الأشجار: أشجار الانضغاط وأشجار الأحمر والأسود.

في تعريفات الماكرو، TYPE هو علامة لهيكل معرف من قبل المستخدم يجب أن يتضمن حقلاً بالاسم FIELD والنوع SPLAY_ENTRY أو RB_ENTRY. الوسيط HEADNAME هو علامة لهيكل معرف من قبل المستخدم يجب تعريفه باستخدام الماكرو SPLAY_HEAD() أو RB_HEAD(). يجب أن يكون الوسيط NAME اسم بادئة فريد لكل شجرة محددة.

يتم الإعلان عن نماذج الدوال باستخدام SPLAY_PROTOTYPE، RB_PROTOTYPE أو RB_PROTOTYPE_STATIC. يتم إنشاء سلاسل نصية لجسم الدوال باستخدام SPLAY_GENERATE، RB_GENERATE أو RB_GENERATE_STATIC. انظر الأمثلة أدناه لمزيد من الشرح حول كيفية استخدام هذه الماكرو.

أشجار الانضغاط

شجرة الانضغاط هي هيكل بيانات ذاتي التنظيم. كل عملية على الشجرة تسبب انضغاطًا. الانضغاط ينقل العقدة المطلوبة إلى جذر الشجرة ويعيد توازن الشجرة جزئيًا.

هذا له فائدة أن محلية الطلبات تؤدي إلى استعلامات أسرع حيث يتم نقل العقد المطلوبة إلى أعلى الشجرة. من ناحية أخرى، تتسبب كل استعلام في كتابة في الذاكرة.

يحد نظرية التوازن من إجمالي وقت الوصول لـ m عملية و n إدراج في شجرة فارغة مبدئيًا بـ O((m + n)lg n). التكلفة الموزونة لسلسلة من m استعلام على شجرة انضغاط هي O(lg n).

تدار شجرة الانضغاط بواسطة هيكل معرف بواسطة الماكرو SPLAY_HEAD(). يتم تعريف هيكل SPLAY_HEAD على النحو التالي:

SPLAY_HEAD(HEADNAME, TYPE) head;

حيث HEADNAME هو اسم الهيكل المراد تعريفه و TYPE هو نوع العناصر المراد إدراجها في الشجرة.

تعلن الماكرو SPLAY_ENTRY عن هيكل يسمح بربط العناصر في الشجرة.

لاستخدام الدوال التي تعالج هيكل الشجرة، يجب الإعلان عن نماذجها باستخدام الماكرو SPLAY_PROTOTYPE، حيث NAME هو معرف فريد لهذه الشجرة المعينة. الوسيط TYPE هو نوع الهيكل الذي يدير الشجرة. الوسيط FIELD هو اسم العنصر المعرف بواسطة SPLAY_ENTRY).

يتم إنشاء سلاسل نصية لجسم الدوال باستخدام الماكرو SPLAY_GENERATE. تأخذ نفس الوسائط التي تأخذها الماكرو SPLAY_PROTOTYPE()، ولكن يجب استخدامها مرة واحدة فقط.

أخيرًا، الوسيط CMP هو اسم دالة تستخدم لمقارنة عقد الأشجار مع بعضها البعض. تأخذ الدالة وسيطين من النوع struct TYPE *. إذا كان الوسيط الأول أصغر من الثاني، فإن الدالة ترجع قيمة أقل من الصفر. إذا كانا متساويين، ترجع صفرًا. خلاف ذلك، ترجع قيمة أكبر من الصفر. تحدد دالة المقارنة ترتيب عناصر الشجرة.

تهيئة الماكرو SPLAY_INIT الشجرة المشار إليها بواسطة head.

يمكن أيضًا تهيئة شجرة الانضغاط بشكل ثابت باستخدام الماكرو SPLAY_INITIALIZER كما يلي:

SPLAY_HEAD(HEADNAME, TYPE) head = SPLAY_INITIALIZER(&head);

تدرج الماكرو SPLAY_INSERT العنصر الجديد elm في الشجرة. بمجرد النجاح، يتم إرجاع NULL. إذا كان هناك بالفعل عنصر مطابق في الشجرة، يتم إيقاف الإدراج ويتم إرجاع مؤشر إلى العنصر الموجود.

تزيل الماكرو SPLAY_REMOVE العنصر elm من الشجرة التي يشير إليها head. بمجرد النجاح، يتم إرجاع مؤشر إلى العنصر الذي تمت إزالته. يتم إرجاع NULL إذا كان elm غير موجود في الشجرة.

يمكن استخدام الماكرو SPLAY_FIND للعثور على عنصر معين في الشجرة.

struct TYPE find, *res;
find.key = 30;
res = SPLAY_FIND(NAME, &head, &find);

يمكن استخدام الماكرو SPLAY_ROOT، SPLAY_MIN، SPLAY_MAX، و SPLAY_NEXT للتنقل في الشجرة:

for (np = SPLAY_MIN(NAME, &head); np != NULL; np = SPLAY_NEXT(NAME, &head, np))

أو، للتبسيط، يمكن استخدام الماكرو SPLAY_FOREACH:

SPLAY_FOREACH(np, NAME, &head)

يجب استخدام الماكرو SPLAY_EMPTY للتحقق مما إذا كانت شجرة الانضغاط فارغة.

أشجار الأحمر والأسود

شجرة الأحمر والأسود هي شجرة بحث ثنائية مع لون العقدة كخاصية إضافية. إنها تفي بمجموعة من الشروط:

  1. كل مسار من الجذر إلى عقدة ورقة يحتوي على نفس العدد من العقد السوداء،
  2. كل عقدة حمراء (باستثناء الجذر) لديها أب أسود،
  3. كل عقدة ورقة سوداء.

كل عملية على شجرة الأحمر والأسود محدودة بـ O(lg n). الحد الأقصى لارتفاع شجرة الأحمر والأسود هو 2lg(n+1).

تدار شجرة الأحمر والأسود بواسطة هيكل معرف بواسطة الماكرو RB_HEAD(). يتم تعريف هيكل RB_HEAD على النحو التالي:

RB_HEAD(HEADNAME, TYPE) head;

حيث HEADNAME هو اسم الهيكل المراد تعريفه و TYPE هو نوع العناصر المراد إدراجها في الشجرة.

تعلن الماكرو RB_ENTRY عن هيكل يسمح بربط العناصر في الشجرة.

لاستخدام الدوال التي تعالج هيكل الشجرة، يجب الإعلان عن نماذجها باستخدام الماكرو RB_PROTOTYPE أو RB_PROTOTYPE_STATIC، حيث NAME هو معرف فريد لهذه الشجرة المعينة. الوسيط TYPE هو نوع الهيكل الذي يدير الشجرة. الوسيط FIELD هو اسم العنصر المعرف بواسطة RB_ENTRY).

يتم إنشاء سلاسل نصية لجسم الدوال باستخدام الماكرو RB_GENERATE أو RB_GENERATE_STATIC. تأخذ هذه الماكرو نفس الوسائط التي تأخذها الماكرو RB_PROTOTYPE() و RB_PROT

SPLAY_ROOT(3bsd)

الحزمة: libbsd

التراخيص: custom

NAME

RB_INSERT, RB_REMOVE, RB_FIND, RB_NFIND, RB_ROOT, RB_MIN, RB_MAX, RB_NEXT, RB_PREV, RB_FOREACH, RB_FOREACH_REVERSE, RB_FOREACH_SAFE, RB_FOREACH_REVERSE_SAFE, RB_EMPTY, RB_INIT, RB_INITIALIZER —
macros for a red-black tree implementation

LIBRARY

libbsd (libbsd), or C standard library (libc)

SYNOPSIS

#include <sys/tree.h>

Macros for declaration:

RB_HEAD(NAME, TYPE);
RB_PROTOTYPE(NAME, TYPE, FIELD, CMP);
RB_GENERATE(NAME, TYPE, FIELD, CMP);

Macros for operations:

void RB_INIT(RB_HEAD(NAME, TYPE) head);
struct TYPE *RB_INSERT(NAME, RB_HEAD(NAME, TYPE) head, struct TYPE *elm);
struct TYPE *RB_REMOVE(NAME, RB_HEAD(NAME, TYPE) head, struct TYPE *elm);
struct TYPE *RB_FIND(NAME, RB_HEAD(NAME, TYPE) head, struct TYPE *elm);
struct TYPE *RB_NFIND(NAME, RB_HEAD(NAME, TYPE) head, struct TYPE *elm);
struct TYPE *RB_ROOT(RB_HEAD(NAME, TYPE) head);
struct TYPE *RB_MIN(NAME, RB_HEAD(NAME, TYPE) head);
struct TYPE *RB_MAX(NAME, RB_HEAD(NAME, TYPE) head);
struct TYPE *RB_NEXT(NAME, RB_HEAD(NAME, TYPE) head, struct TYPE *elm);
struct TYPE *RB_PREV(NAME, RB_HEAD(NAME, TYPE) head, struct TYPE *elm);
void RB_FOREACH(struct TYPE *var, NAME, RB_HEAD(NAME, TYPE) head);
void RB_FOREACH_REVERSE(struct TYPE *var, NAME, RB_HEAD(NAME, TYPE) head);
void RB_FOREACH_SAFE(struct TYPE *var, NAME, RB_HEAD(NAME, TYPE) head);
void RB_FOREACH_REVERSE_SAFE(struct TYPE *var, NAME, RB_HEAD(NAME, TYPE) head);
int RB_EMPTY(RB_HEAD(NAME, TYPE) head);

Macro for static initialization:

RB_INITIALIZER(head);

DESCRIPTION

These macros provide an implementation of red-black trees. Red-black trees are a type of self-balancing binary search tree. The balancing of the tree is made automatically upon insertion and deletion. Therefore, the operations are guaranteed to take O(log n) time, where n is the number of elements in the tree.

To use the tree macros, a structure must be defined that will hold the tree elements. This structure must contain a field of type RB_ENTRY(TYPE). This field will store the pointers to the parent, left child, and right child nodes, as well as the color of the node.

The tree itself is represented by a pointer to a structure that contains pointers to the root of the tree and to the tail of the tree. This structure is declared using the RB_HEAD() macro. The first argument is the name of the tree structure, and the second argument is the type of the elements stored in the tree.

struct mynode {
	RB_ENTRY(mynode) next;
	int data;
};
RB_HEAD(mytree, mynode) myhead;

The tree macros require a comparison function CMP to compare keys. The comparison function should take two pointers to elements of type struct TYPE * and return a value smaller than zero if the first element is smaller than the second, zero if they are equal, and a value greater than zero otherwise. The comparison function determines the order of elements in the tree. The comparison function must be consistent with the equality check, meaning that if CMP(a, b) returns 0, then a and b must be considered equal by the tree operations.

The RB_PROTOTYPE() macro is used to declare the comparison function. It is typically placed in a header file.

The RB_GENERATE() macro is used to define the tree data structure and the comparison function. It is typically placed in a source file. The first argument is the name of the tree, the second argument is the type of the elements, the third argument is the name of the field of type RB_ENTRY within the element structure, and the fourth argument is the name of the comparison function.

int compare_nodes(struct mynode *a, struct mynode *b);
RB_PROTOTYPE(mytree, mynode, next, compare_nodes)
RB_GENERATE(mytree, mynode, next, compare_nodes)

Note that the name of the tree, NAME, must be the same in all macros related to a particular tree. The TYPE argument is the structure name that holds the tree nodes, and the FIELD argument is the name of the RB_ENTRY structure within TYPE. The CMP argument is the name of a function used to compare nodes. The function takes two arguments of type struct TYPE *. If the first argument is smaller than the second, the function returns a value smaller than zero. If they are equal, the function returns zero. Otherwise, it should return a value greater than zero. The compare function defines the order of the tree elements.

The RB_INIT() macro initializes the tree referenced by head.

The red-black tree can also be initialized statically by using the RB_INITIALIZER() macro like this:

RB_HEAD(HEADNAME, TYPE) head = RB_INITIALIZER(&head);

The RB_INSERT() macro inserts the new element elm into the tree. Upon success, NULL is returned. If a matching element already exists in the tree, the insertion is aborted, and a pointer to the existing element is returned.

The RB_REMOVE() macro removes the element elm from the tree pointed by head. RB_REMOVE() returns elm.

The RB_FIND() and RB_NFIND() macros can be used to find a particular element in the tree. RB_FIND() finds the node with the same key as elm. RB_NFIND() finds the first node greater than or equal to the search key.

struct TYPE find, *res;
find.key = 30;
res = RB_FIND(NAME, &head, &find);

The RB_ROOT(), RB_MIN(), RB_MAX(), RB_NEXT(), and RB_PREV() macros can be used to traverse the tree:

for (np = RB_MIN(NAME, &head); np != NULL; np = RB_NEXT(NAME, &head, np))

Or, for simplicity, one can use the RB_FOREACH() or RB_FOREACH_REVERSE() macros:

RB_FOREACH(np, NAME, &head)

The macros RB_FOREACH_SAFE() and RB_FOREACH_REVERSE_SAFE() traverse the tree referenced by head in a forward or reverse direction respectively, assigning each element in turn to np. However, unlike their unsafe counterparts, they permit both the removal of np as well as freeing it from within the loop safely without interfering with the traversal.

The RB_EMPTY() macro should be used to check whether a red-black tree is empty.

EXAMPLES

The following example demonstrates how to declare a red-black tree holding integers. Values are inserted into it and the contents of the tree are printed in order. Lastly, the internal structure of the tree is printed.

#include <sys/tree.h>
#include <err.h>
#include <stdio.h>
#include <stdlib.h>

struct node {
	RB_ENTRY(node) entry;
	int i;
};

int	intcmp(struct node *, struct node *);
void	print_tree(struct node *);

int
intcmp(struct node *e1, struct node *e2)
{
	return (e1->i < e2->i ? -1 : e1->i > e2->i);
}

RB_HEAD(inttree, node) head = RB_INITIALIZER(&head);
RB_PROTOTYPE(inttree, node, entry, intcmp)
RB_GENERATE(inttree, node, entry, intcmp)

int testdata[] = {
	20, 16, 17, 13, 3, 6, 1, 8, 2, 4, 10, 19, 5, 9, 12, 15, 18,
	7, 11, 14
};

void
print_tree(struct node *n)
{
	struct node *left, *right;

	if (n == NULL) {
		printf("nil");
		return;
	}
	left = RB_LEFT(n, entry);
	right = RB_RIGHT(n, entry);
	if (left == NULL && right == NULL)
		printf("%d", n->i);
	else {
		printf("%d(", n->i);
		print_tree(left);
		printf(",");
		print_tree(right);
		printf(")");
	}
}

int
main(void)
{
	int i;
	struct node *n;

	for (i = 0; i < sizeof(testdata) / sizeof(testdata[0]); i++) {
		if ((n = malloc(sizeof(struct node))) == NULL)
			err(1, NULL);
		n->i = testdata[i];
		RB_INSERT(inttree, &head, n);
	}

	RB_FOREACH(n, inttree, &head) {
		printf("%d\n", n->i);
	}
	print_tree(RB_ROOT(&head));
	printf("\n");
	return (0);
}

HISTORY

NOTES

Trying to free a tree in the following way is a common error:

SPLAY_FOREACH(var, NAME, &head) {
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
free(head);

Since var is free'd, the FOREACH() macro refers to a pointer that may have been reallocated already. Proper code needs a second variable.

for (var = SPLAY_MIN(NAME, &head); var != NULL; var = nxt) {
	nxt = SPLAY_NEXT(NAME, &head, var);
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
