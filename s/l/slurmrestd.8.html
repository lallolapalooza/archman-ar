slurmrestd(8)

الحزمة: slurm-llnl

التراخيص: GPL-2.0-or-later

slurmrestd(8) خادم Slurm REST slurmrestd(8)

الاسم

slurmrestd - واجهة إلى Slurm عبر REST API.

الملخص

slurmrestd [خيارات...] <[مضيف]:منفذ|unix:/مسار/إلى/مقبس>...

الوصف

slurmrestd هي واجهة REST API لـ Slurm. يمكن استخدامها في وضعين:

وضع Inetd: سيقوم slurmrestd بالقراءة والكتابة إلى STDIO. إذا كان STDIN عبارة عن واصف ملف مقبس، فسيكتشف slurmrestd ذلك ويستخدم الوظائف ذات الصلة. تم تصميم هذا الوضع للعمل مع الإدخال الموجه، inetd، xinetd، أو تفعيل مقبس systemd.

وضع الاستماع: سيقوم slurmrestd بفتح مقبس استماع على كل زوج مضيف:منفذ مطلوب أو مقبس UNIX.

خيارات

[https://][مضيف]:منفذ
اسم المضيف والمنفذ للاستماع عليهما. قد يكون المضيف عنوان IP IPv4/IPv6 أو اسم مضيف قابل للحل. يتم البحث عن أسماء المضيفين فقط عند بدء التشغيل ولا تتغير طوال عمر العملية. المضيف اختياري؛ إذا لم يتم توفيره، فسيستمع slurmrestd على جميع واجهات الشبكة. https:// اختياري؛ إذا لم يتم توفيره، فسيستخدم slurmrestd تلقائيًا مكون TLS لتشفير حركة المرور عندما يكون ذلك ممكنًا. إذا تم تحديد https://؛ فسيتطلب slurmrestd من مكون TLS المهيأ تشفير حركة المرور.
unix:///مسار/إلى/مقبس
الاستماع على مقبس UNIX محلي. يجب أن يكون لديك إذن لإنشاء مقبس في نظام الملفات.
-a <مكون>[,مكون]...
قائمة مفصولة بفواصل لمكونات المصادقة لتحميلها. افتراضيًا، سيتم تحميل جميع مكونات المصادقة المتاحة.
list
عرض قائمة بالمكونات الممكنة للتحميل.
rest_auth/local
يسمح بالمصادقة عبر مقابس UNIX عندما يكون auth/munge نشطًا.
ملاحظة: يجب تشغيل slurmrestd وعملاء العمليات بنفس UID أو سيتم رفض طلبات العميل.
rest_auth/jwt
يسمح بالمصادقة عبر مقابس TCP و UNIX عندما يكون AuthAltTypes=auth/jwt نشطًا. يجب على المستخدم تحديد ملفات تعريف الارتباط HTTP التالية مع كل طلب:
X-SLURM-USER-NAME:<اسم المستخدم>
X-SLURM-USER-TOKEN:<JSON Web Token>
ملاحظة: يتم عادةً إنشاء الرموز المميزة عن طريق استدعاء "scontrol token".
-d <مكون>[,مكون]...
قائمة مفصولة بفواصل لمكونات data_parser، والتي ستحدد تنسيق الإخراج. قد تتضمن علامات اختيارية مميزة برمز '+'. افتراضيًا، سيتم تحميل جميع مكونات data_parser المتاحة دون أي علامات اختيارية. انظر أيضًا -s لمكونات OpenAPI التي تتحكم في المحتوى المتاح. الافتراضيات: جميع مكونات data_parser المدمجة المدعومة.
list[+flags]
عرض قائمة بالمكونات الممكنة للتحميل.
latest
يتم استبداله تلقائيًا بأحدث إصدار للمكون. انظر المكون ذي الصلة للحصول على الوصف والعلامات المحتملة.
[data_parser/]v0.0.40[+fast]
تحميل المكون data_parser/]v0.0.40 لتنسيق البيانات. متوافق فقط مع مكونات المحتوى openapi/slurmctld و openapi/slurmdbd.
+fast
تعطيل التحذيرات المدمجة والمنطق الآخر للتحقق بدقة من الطلبات الواردة. يجب استخدامه فقط في بيئة إنتاجية مع عملاء تم اختبارهم جيدًا وقد يتم قبول الطلبات ذات التنسيق الخاطئ كما هي ولن يتم إنشاء أي تحذيرات بشأن الحقول أو القيم التي تم تجاهلها أو غير الصحيحة.

SLURM_JWT
يجب تعيين هذا المتغير لاستخدام مصادقة رمز JWT.
SLURMRESTD_AUTH_TYPES
تحديد أنواع المصادقة المسموح بها. انظر -a
SLURMRESTD_DEBUG
تحديد مستوى التصحيح بشكل صريح. القيم الصالحة هي 0-9، أو نفس قيم السلسلة مثل SlurmctldDebug في slurm.conf(5). إذا تم اكتشاف TTY تحكم، فسيتم تنشيط الوضع التفاعلي تلقائيًا لتوفير معلومات تسجيل إضافية إلى stderr. إذا لم يتم اكتشاف TTY تحكم، فسترسل السجلات إلى syslog. يزداد إذا تم تمرير -v كوسيط أثناء الاستدعاء. يتم تجاهله إذا تم تعيين SLURMRESTD_DEBUG_STDERR أو SLURMRESTD_DEBUG_SYSLOG في البيئة.
SLURMRESTD_DEBUG_STDERR
تحديد مستوى التصحيح بشكل صريح للتسجيل إلى STDERR. القيم الصالحة هي 0-9، أو نفس قيم السلسلة مثل خيارات التصحيح مثل SlurmctldDebug في slurm.conf(5). يزداد إذا تم تمرير -v كوسيط أثناء الاستدعاء.
SLURMRESTD_DEBUG_SYSLOG
تحديد مستوى التصحيح بشكل صريح للتسجيل إلى syslog. القيم الصالحة هي 0-9، أو نفس قيم السلسلة مثل خيارات التصحيح مثل SlurmctldDebug في slurm.conf(5). يزداد إذا تم تمرير -v كوسيط أثناء الاستدعاء.
SLURMRESTD_DATA_PARSER_PLUGINS
قائمة مفصولة بفواصل لمكونات data_parser الإضافية التي سيتم تحميلها. انظر -d
SLURMRESTD_LISTEN
قائمة مفصولة بفواصل لأزواج المضيف:المنفذ أو مآخذ Unix للاستماع عليها.
SLURMRESTD_MAX_CONNECTIONS
تحديد الحد الأقصى لعدد الاتصالات التي سيتم معالجتها في أي وقت. انظر --max-connections
SLURMRESTD_OPENAPI_PLUGINS
قائمة مفصولة بفواصل لمكونات OpenAPI الإضافية التي سيتم تحميلها. انظر -s
SLURMRESTD_RESPONSE_STATUS_CODES
قائمة مفصولة بفواصل لاستجابات طرق OpenAPI التي سيتم إنشاؤها في مواصفات OpenAPI. الافتراضي: 200,default
SLURMRESTD_SECURITY
التحكم في وظائف أمان slurmrestd باستخدام القيم التالية المفصولة بفواصل:
become_user
يسمح بتشغيل slurmrestd كـ root ليصبح المستخدم الذي يطلب جميع الطلبات. عند دمجه مع rest_auth/local، عند اتصال مستخدم عبر مأخذ Unix مسمى، سيقوم slurmrestd بتعيين المستخدم/المجموعة باستخدام setuid()/setgid() ثم إكمال جميع الطلبات كمستخدم معين. هذا الوضع مخصص فقط لوضع inet حيث أن تغيير المستخدم دائم طوال مدة العملية. هذا الوضع غير متوافق مع rest_auth/jwt ويقترح بدء slurmrestd باستخدام الوسائط "-a rest_auth/local".
disable_unshare_files
يعطل مشاركة واصفات الملفات مع العملية الأصل.
disable_unshare_sysv
يعطل مشاركة مساحة الأسماء SYSV.
disable_user_check
يعطل التحقق من أن slurmrestd لا يعمل كـ root أو SlurmUser، أو بالمجموعة الرئيسية لـ root أو SlurmUser. سيسمح تعطيل هذا التحقق بتشغيل slurmrestd كـ root أو SlurmUser مما سيسمح لأي شخص يمكنه الاتصال بهذه الخدمة بتشغيل أي شيء كـ root على الكتلة.
SLURMRESTD_YAML أو SLURM_YAML
التحكم في تسلسل YAML:
compact
إخراج YAML بأكبر قدر ممكن من الضغط.
no_tag
إخراج YAML بدون علامات !! للأنواع.
pretty
إخراج YAML بتنسيق جميل لجعله أكثر قابلية للقراءة.

الإشارات

SIGINT
سيتم إيقاف slurmrestd بشكل نظيف.
SIGPIPE
يتم تجاهل هذه الإشارة بشكل صريح.
SIGPROF
تسجيل حالة مدير الاتصال عندما يكون مستوى التصحيح على الأقل هو info.

ملاحظات

مكونات SPANK و clifilter الإضافية غير مدعومة في slurmrestd بسبب افتقارها إلى السلامة على مستوى الخيوط. المكونات الإضافية النشطة لـ SPANK و JobSubmitPlugins في slurmctld مستقلة عن slurmrestd ويمكن استخدامها لفرض سياسة الموقع على تقديمات المهام.

أمثلة

إنشاء مخطط OpenAPI بدون تكوين

$ slurmrestd -f /dev/null  --generate-openapi-spec -s slurmdbd,slurmctld -d v0.0.42 > openapi.json

بدء slurmrestd بمأخذ Unix في وضع الاستماع:

$ export SLURMRESTD=/var/spool/slurm/restd/rest
$ slurmrestd -s slurmctld,slurmdbd -d v0.0.42 unix:$SLURMRESTD

التحقق من الاتصال بـ slurmctld باستخدام ping، مع تشغيل slurmrestd في وضع الاستماع:

$ export $(scontrol token)
$ curl --unix-socket "${SLURMRESTD}" -H "X-SLURM-USER-TOKEN:${SLURM_JWT}" 'http://ignored_with_unix_sockets/slurm/v0.0.42/ping' | jq '.pings'

]
