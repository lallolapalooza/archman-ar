slurmd(8) خادم Slurm slurmd(8)

الاسم

slurmd - خادم عقدة الحوسبة لـ Slurm.

الملخص

slurmd [خيارات...]

الوصف

slurmd هو خادم عقدة الحوسبة لـ Slurm. يقوم بمراقبة جميع المهام التي تعمل على عقدة الحوسبة، ويقبل العمل (المهام)، ويقوم بتشغيل المهام، ويقوم بإلغاء المهام قيد التشغيل عند الطلب.

الخيارات

--authinfo
يستخدم مع configless لتعيين معلمة AuthInfo بديلة لاستخدامها في إنشاء الاتصال مع slurmctld قبل استرداد ملف التكوين. (على سبيل المثال، لتحديد موقع مقبس MUNGE بديل).
-b
الإبلاغ عن إعادة تشغيل العقدة عند إعادة تشغيل الخادم. يستخدم لأغراض الاختبار.
-c
مسح أقفال النظام حسب الحاجة. قد يكون هذا مطلوبًا إذا تم إنهاء slurmd بشكل غير طبيعي.
-C
طباعة تكوين الأجهزة الفعلي (وليس التكوين من ملف slurm.conf) والخروج. تنسيق الإخراج هو نفس التنسيق المستخدم في slurm.conf لوصف تكوين العقدة بالإضافة إلى وقت تشغيلها. يمكنك استخدام --parameters لتحديد خيارات مثل 'l3cache_as_socket' التي قد تغير طوبولوجيا العقدة المبلغ عنها.
--ca-cert-file <file>
المسار المطلق لشهادة CA المستخدمة لجلب التكوين عند التشغيل بدون تكوين في مجموعة ممكّنة لـ TLS.
--conf <node parameters>
يستخدم بالاقتران مع الخيار -Z. يستخدم لتجاوز أو تعريف معلمات إضافية لعقدة ديناميكية باستخدام نفس بناء الجملة والمعلمات المستخدمة لتحديد العقد في slurm.conf. تحديد أي من CPUs أو Boards أو SocketsPerBoard أو CoresPerSocket أو ThreadsPerCore سيؤدي إلى تجاوز القيم الافتراضية التي حددها الخيار -C. NodeName و Port غير مدعومين. يمكن أيضًا استخدام هذا لتحديد طوبولوجيا عقدة سحابية، وفي هذه الحالة لا ينبغي استخدام العلامة -Z (على سبيل المثال، --conf="topology=topo-switch:s1")

على سبيل المثال، إذا أبلغ slurmd -C عن:

NodeName=node1 CPUs=16 Boards=1 SocketsPerBoard=1 CoresPerSocket=8 ThreadsPerCore=2 RealMemory=31848

ستقوم مواصفات --conf التالية بإنشاء تعريفات العقد المقابلة:

--conf "Gres=gpu:2"
NodeName=node1 CPUs=16 Boards=1 SocketsPerBoard=1 CoresPerSocket=8 ThreadsPerCore=2 RealMemory=31848 Gres=gpu:2
--conf "RealMemory=30000"
NodeName=node1 CPUs=16 Boards=1 SocketsPerBoard=1 CoresPerSocket=8 ThreadsPerCore=2 RealMemory=30000
--conf "CPUs=16"
NodeName=node1 CPUs=16 RealMemory=331848
--conf "CPUs=16 RealMemory=30000 Gres=gpu:2"
NodeName=node1 CPUs=16 RealMemory=30000 Gres=gpu:2"
--conf-server <host|ip address>[:<port>]
قائمة مفصولة بفواصل من وحدات التحكم، الأولى هي slurmctld الأساسي. يمكن (اختياريًا) تحديد منفذ لكل وحدة تحكم. هذه المضيفات هي التي سيجلب منها slurmd التكوين عند التشغيل في وضع "configless". ملاحظة: عند تحديد عنوان IPv6، قم بتغليف <ip address> بين [] لتمييز العنوان عن المنفذ. هذا مطلوب حتى لو لم يتم تحديد أي منفذ.
-d <file>
تحديد المسار الكامل لبرنامج slurmstepd المراد استخدامه لرعاية خطوات مهام المستخدم. قد يكون هذا مفيدًا لأغراض الاختبار.
-D
تشغيل slurmd في المقدمة مع نسخ السجلات إلى stderr.
--extra <arbitrary string>
تعيين بيانات "إضافية" عند بدء تشغيل العقدة. إذا كانت هذه سلسلة JSON وتم تعيين SchedulerParameters=extra_constraints في slurm.conf، فيمكن للأعمال استخدام الخيار --extra للتصفية بناءً على هذه البيانات "الإضافية".
-f <file>
قراءة التكوين من الملف المحدد. راجع ملاحظات أدناه.
-F[feature]
بدء هذه العقدة كعقدة Dynamic Future. ستحاول مطابقة تعريف عقدة بحالة FUTURE، مع استخدام الميزة المحددة اختياريًا لمطابقة تعريف العقدة.
-G
طباعة تكوين موارد GRES (المستندة إلى GRES في slurm.conf المدمجة مع محتويات gres.conf لهذه العقدة) والخروج.
-h
مساعدة؛ طباعة ملخص موجز لخيارات الأمر.
--instance-id <cloud instance id>
تعيين معرف مثيل السحابة عند بدء تشغيل العقدة.
--instance-type <cloud instance type>
تعيين نوع مثيل السحابة عند بدء تشغيل العقدة.
-L <file>
كتابة رسائل السجل إلى الملف المحدد.
-M
قفل صفحات slurmd في ذاكرة النظام باستخدام mlockall (2) لتعطيل التبديل لعملية slurmd. قد يساعد هذا في الحالات التي يتم فيها تمييز العقد كـ DOWN خلال فترات النشاط المكثف للتبديل. إذا لم يكن استدعاء النظام mlockall (2) متاحًا، فسيتم طباعة خطأ في السجل وسيستمر slurmd بشكل طبيعي.

يُقترح تعيين LaunchParameters=slurmstepd_memlock في slurm.conf(5) عند تعيين -M.

-n <value>
تعيين قيمة الأولوية (nice value) للخادم إلى القيمة المحددة، عادةً رقم سالب. لاحظ أيضًا المعلمة configuration PropagatePrioProcess.
-N <nodename>
تشغيل الخادم بالاسم المحدد للعقدة. يستخدم لمحاكاة نظام أكبر بأكثر من خادم slurmd واحد لكل عقدة. يتطلب أن يكون Slurm مبنيًا باستخدام خيار التكوين --enable-multiple-slurmd.
--parameters <slurmd parameters>
يسمح بإجراء تغييرات مؤقتة خاصة بالعقدة على SlurmdParameters. يمكن استخدامه بالاقتران مع -C لتحديد خيارات مثل 'l3cache_as_socket' التي قد تغير طوبولوجيا العقدة المبلغ عنها. تتم إضافة هذه المعلمات إلى أي معلمات خاصة بالعقدة محددة في slurm.conf.
-s
تغيير دليل العمل لـ slurmd إلى مسار SlurmdLogFile إذا أمكن، أو إلى SlurmdSpoolDir إذا لم يكن كذلك. إذا فشل كلاهما، فسيعود إلى /var/tmp.

NAME

slurmd — Slurm daemon

SYNOPSIS

slurmd [-a] [-c conf] [-d] [-f conf] [-h] [-i] [-k] [-l] [-M name] [-p] [-q] [-s] [-t] [-v] [-V] [-Z]

DESCRIPTION

The slurmd daemon is the Slurm node daemon. It is started on each compute node of the cluster. slurmd accepts connections from slurmctld and one or more slurm-wlm client commands. It is responsible for starting and terminating Slurm batch jobs, and for managing the node's state.

slurmd must be started as root to be able to manage jobs.

OPTIONS

-a
Run in the foreground. All logging is sent to standard output.
-c, --conf conf
Use configuration file conf. Only one configuration file can be used.
-d
Do not detach from the terminal and log all output to standard output. This is the same as the -a option.
-f, --conf conf
Use configuration file conf. Only one configuration file can be used.
-h, --help
Display help information and exit.
-i
Ignore all signals. This is used for debugging.
-k
Do not dump core file.
-l
Log all output to syslog.
-M, --conf-server name
Set the configuration server to name. This is normally set to the name of the machine running slurmctld.
-p
Run in the foreground and log all output to standard output.
-q
Do not daemonize. Log all output to standard output.
-s
Start slurmd as a daemon. This is the default behavior.
--systemd
Use when starting the daemon with systemd. This will allow slurmd to notify systemd of the new PID when using 'scontrol reconfigure'.
-v
Verbose operation. Multiple -v's increase verbosity.
-V, --version
Print version information and exit.
-Z
Start this node as a Dynamic Normal node. If no --conf is specified, then the slurmd will register with the same hardware configuration (except GRES) as defined by the -C option.

ENVIRONMENT VARIABLES

The following environment variables can be used to override settings compiled into slurmd.

ABORT_ON_FATAL
When a fatal error is detected, use abort() instead of exit() to terminate the process. This allows backtraces to be captured without recompiling Slurm.
SLURM_CONF
The location of the Slurm configuration file. This is overridden by explicitly naming a configuration file on the command line.
SLURM_DEBUG_FLAGS
Specify debug flags for slurmd to use. See DebugFlags in the slurm.conf(5) man page for a full list of flags. The environment variable takes precedence over the setting in the slurm.conf.

HTTP server

Unless disabled via CommunicationParameters=disable_http in slurm.conf, slurmd will accept incoming HTTP/1.1 compliant requests to any socket listening as configured by SlurmdPort in slurm.conf. Authentication of HTTP requests is not supported. TLS wrapping optionally supported without requiring TLSType in slurm.conf. The following endpoints are currently supported:

GET /
Get list of endpoints.
GET /healthz
Test if slurmd loaded successfully.
GET /livez
Test if slurmd loaded successfully.
GET /readyz
Test if slurmd is ready to accept incoming RPCs.

SIGNALS

SIGTERM SIGINT SIGQUIT
slurmd will shutdown cleanly.
SIGHUP
Reloads the slurm configuration files, similar to 'scontrol reconfigure'.
SIGUSR2
Reread the log level from the configs, and then reopen the log file. This should be used when setting up logrotate(8).
SIGPIPE
This signal is explicitly ignored.

CORE FILE LOCATION

If slurmd is started with the -D option then the core file will be written to the current working directory. Otherwise if SlurmdLogFile is a fully qualified path name (starting with a slash), the core file will be written to the same directory as the log file. Otherwise the core file will be written to the SlurmdSpoolDir directory, or "/var/tmp/" as a last resort. If none of the above directories can be written, no core file will be produced.

NOTES

It may be useful to experiment with different slurmd specific configuration parameters using a distinct configuration file (e.g. timeouts). However, this special configuration file will not be used by the slurmctld daemon or the Slurm programs, unless you specifically tell each of them to use it. If you desire changing communication ports, the location of the temporary file system, or other parameters used by other Slurm components, change the common configuration file, slurm.conf.

If you are using configless mode with a login node that runs a lot of client commands, you may consider running slurmd on that machine so it can manage a cached version of the configuration files. Otherwise, each client command will use the DNS record to contact the controller and get the configuration information, which could place additional load on the controller.
