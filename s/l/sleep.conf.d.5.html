NAME

sleep.conf.d — configuration files for systemd sleep states

SYNOPSIS

/etc/systemd/sleep.conf.d/, /run/systemd/sleep.conf.d/, /usr/lib/systemd/sleep.conf.d/

DESCRIPTION

Systemd's sleep dispatch logic, used by systemd-sleep(8), may be configured via the sleep configuration files. These are configured in a similar manner as systemd.conf(5). Specifically, they are split into several snippets which are merged according to the rules described in systemd.conf(5).

The configuration snippets are read from directories /etc/systemd/sleep.conf.d/, /run/systemd/sleep.conf.d/ and /usr/lib/systemd/sleep.conf.d/. Files are sorted lexicographically by name and merged.

The main configuration file is sleep.conf(5).

CONFIGURATION DIRECTORIES AND PRECEDENCE

The main configuration file is sleep.conf(5). Additionally, simple configuration snippets may be placed in /etc/systemd/sleep.conf.d/, /run/systemd/sleep.conf.d/ and /usr/lib/systemd/sleep.conf.d/. These files are read in lexicographical order. If multiple files specify the same option, the last one read wins.

System administrators may place their local configuration snippets in /etc/systemd/sleep.conf.d/. The package provided configuration snippets are placed in /usr/lib/systemd/sleep.conf.d/. Runtime configuration snippets, for example for system services, are placed in /run/systemd/sleep.conf.d/.

File names are önerilen to end in .conf. They are parsed in order of their names. For example, zz-local.conf will be read after 50-default.conf.conf.

If a configuration file is not sorted lexicographically, e.g. a symbolic link is involved, the order is arbitrary.

The configuration snippets are merged in the following order: snippets in /usr/lib/systemd/sleep.conf.d/ first are overridden by snippets in /run/systemd/sleep.conf.d/ which are finally overridden by snippets in /etc/systemd/sleep.conf.d/.

A more detailed description of the configuration file syntax and ordering rules is available in systemd.conf(5).

OPTIONS

The configuration files may specify options under the [Sleep] section header.

SuspendState=

A space-separated list of suspend states to try. The first state that works is used. Allowed values are "idle", "mem", "freeze", "hibernate", "hybrid-sleep", "suspend-then-hibernate". If none is given, defaults to "mem". Note that "hibernate", "hybrid-sleep", and "suspend-then-hibernate" require special setup and may not be available on all systems. On most systems, only "freeze" and "mem" (which is the standard ACPI S3 suspend) are available. See Basic sysfs Interfaces for System Suspend and Hibernation [2] for more details.

Added in version 256.

HibernateDelaySec=

The amount of time the system spends in suspend mode before the system is automatically put into hibernate mode. Only used by systemd-suspend-then-hibernate.service(8). Refer to suspend-then-hibernate for details on how this option interacts with other options/system battery state.

Added in version 239.

HibernateOnACPower=

Whether to allow hibernation when the system has AC power. Only used by systemd-suspend-then-hibernate.service(8) when HibernateDelaySec= is set.

If this option is disabled, the countdown of HibernateDelaySec= starts only after AC power is disconnected, keeping the system in the suspend state otherwise.

This option is only effective on systems with a battery.

Added in version 257.

SuspendEstimationSec=

The RTC alarm will wake the system after the specified timespan to measure the system battery capacity level and estimate battery discharging rate. Only used by systemd-suspend-then-hibernate.service(8). Refer to suspend-then-hibernate for details on how this option interacts with other options/system battery state.

Added in version 253.

EXAMPLE: FREEZE

Example: to exploit the “freeze” mode added in Linux 3.9, one can use systemctl suspend with

[Sleep]
SuspendState=freeze
