slirp4netns(1)

الحزمة: slirp4netns

التراخيص: GPL-2.0-or-later

SLIRP4NETNS(1) أوامر المستخدم SLIRP4NETNS(1)

الاسم

slirp4netns - شبكات في وضع المستخدم لمساحات الشبكة غير المميزة

الملخص

slirp4netns [خيار]... PID|مسار|FD [اسم_TAP]

الوصف

يوفر slirp4netns شبكات في وضع المستخدم ("slirp") لمساحات الشبكة.

على عكس veth(4)، لا يتطلب slirp4netns امتيازات الجذر على المضيف.

الإعداد الافتراضي:

  • MTU: 1500
  • CIDR: 10.0.2.0/24
  • البوابة/المضيف: 10.0.2.2 (عنوان الشبكة + 2)
  • DNS: 10.0.2.3 (عنوان الشبكة + 3)
  • بداية DHCP: 10.0.2.15 (عنوان الشبكة + 15)
  • نهاية DHCP: 10.0.2.30 (عنوان الشبكة + 30)
  • IPv6 CIDR: fd00::/64
  • IPv6 البوابة/المضيف: fd00::2
  • IPv6 DNS: fd00::3

خيارات

-c، --configure تشغيل واجهة TAP. سيتم تعيين IP إلى 10.0.2.100 (عنوان الشبكة + 100) افتراضيًا. سيتم تعيين IPv6 إلى عنوان عشوائي. بدءًا من v0.4.0، يتم تشغيل واجهة الاسترجاع (lo) أيضًا.

-e، --exit-fd=FD تحديد FD لإنهاء slirp4netns. عند تحديد FD، يخرج slirp4netns عند حدوث حدث poll(2) على FD.

-r، --ready-fd=FD تحديد FD للكتابة إليه عند الانتهاء من خطوات التهيئة. عند تحديد FD، يكتب slirp4netns "1" إلى FD ويغلق FD. قبل v0.4.0، تمت كتابة FD بعد تكوين الشبكة (-c) ولكن قبل تكوين مقبس API (-a).

-m، --mtu=MTU (منذ v0.2.0) تحديد MTU (الحد الأقصى=65521).

-6، --enable-ipv6 (منذ v0.2.0، تجريبي) تمكين IPv6

-a، --api-socket (منذ v0.3.0) مسار مقبس API

--cidr (منذ v0.3.0) تحديد CIDR، على سبيل المثال 10.0.2.0/24

--disable-host-loopback (منذ v0.3.0) منع الاتصال بـ 127.0.0.1:* في مساحة المضيف

--netns-type=TYPE (منذ v0.4.0) تحديد نوع مساحة الشبكة ([path|pid|tapfd]، افتراضي=pid)

إذا كان نوع مساحة الشبكة هو tapfd، فمن المتوقع أن يكون الوسيط الموضعي الأول واصف ملف موروث يتوافق مع اتصال /dev/net/tun. يتعارض هذا مع --configure ويتم تجاهل اسم_TAP.

--userns-path=PATH (منذ v0.4.0) تحديد مسار مساحة المستخدم

--enable-sandbox (منذ v0.4.0) الدخول إلى مساحة المستخدم وإنشاء مساحة تركيب جديدة يتم فيها تحميل /etc و /run فقط من المضيف.

يتطلب أن يكون /etc/resolv.conf ليس رابطًا رمزيًا لملف خارج /etc و /run.

عند التشغيل كجذر، لا تدخل العملية في مساحة المستخدم ولكن يتم إسقاط جميع القدرات باستثناء CAP_NET_BIND_SERVICE.

--enable-seccomp (منذ v0.4.0، تجريبي) تمكين seccomp(2) للحد من استدعاءات النظام. يستخدم عادةً بالاقتران مع --enable-sandbox.

--outbound-addr=IPv4 (منذ v1.1.0، تجريبي) تحديد عنوان IPv4 الصادر الذي يجب ربط slirp به

--outbound-addr=INTERFACE (منذ v1.1.0، تجريبي) تحديد واجهة الصادر التي يجب ربط slirp بها (حركة مرور IPv4 فقط)

--outbound-addr=IPv6 (منذ v1.1.0، تجريبي) تحديد عنوان IPv6 الصادر الذي يجب ربط slirp به

--outbound-addr6=INTERFACE (منذ v1.1.0، تجريبي) تحديد واجهة الصادر التي يجب ربط slirp بها (حركة مرور IPv6 فقط)

--disable-dns (منذ v1.1.0) تعطيل DNS المضمن (10.0.2.3 افتراضيًا)

--macaddress (منذ v1.1.9) تحديد عنوان MAC لواجهة TAP (صالح فقط مع -c)

--target-type=TYPE (منذ v1.2.0) تحديد نوع الهدف ([netns|bess]، افتراضي=netns).

من المتوقع استخدام وضع bess (منذ v1.2.0، تجريبي) مع User Mode Linux. يتعارض وضع bess مع --configure، --netns-type، و --userns-path.

-h، --help (منذ v0.2.0) عرض المساعدة والخروج

-v، --version (منذ v0.2.0) عرض الإصدار والخروج

مثال

الطرفية 1: إنشاء مساحات المستخدم/الشبكة/التركيب

(host)$ unshare --user --map-root-user --net --mount
(namespace)$ echo $$ > /tmp/pid

في هذه الوثائق، نستخدم (host)$ كطلب لصدفة المضيف، و (namespace)$ كطلب للصدفة التي تعمل في المساحات.

إذا فشل unshare، جرب الأوامر التالية (معروف أنها مطلوبة على Debian و Arch و CentOS 7.X القديم):

(host)$ sudo sh -c 'echo "user.max_user_namespaces=28633" >> /etc/sysctl.d/userns.conf'
(host)$ if [ -f /proc/sys/kernel/unprivileged_userns_clone ]; then sudo sh -c 'echo "kernel.unprivileged_userns_clone=1" >> /etc/sysctl.d/userns.conf'; fi
(host)$ sudo sysctl --system

الطرفية 2: بدء slirp4netns

(host)$ slirp4netns --configure --mtu=65520 $(cat /tmp/pid) tap0
starting slirp, MTU=65520

الطرفية 1: تأكد من تكوين tap0 واتصاله بالإنترنت

(namespace)$ ip a
1: lo: <LOOPBACK> mtu 65536 qdisc noop state DOWN group default qlen 1000
    link/loopback 00:00:00:00:00:00 brd 00:00:00:00:00:00
3: tap0: <BROADCAST,UP,LOWER_UP> mtu 65520 qdisc fq_codel state UNKNOWN group default qlen 1000
    link/ether c2:28:0c:0e:29:06 brd ff:ff:ff:ff:ff:ff
    inet 10.0.2.100/24 brd 10.0.2.255 scope global tap0
       valid_lft forever preferred_lft forever
    inet6 fe80::c028:cff:fe0e:2906/64 scope link 
       valid_lft forever preferred_lft forever
(namespace)$ echo "nameserver 10.0.2.3" > /tmp/resolv.conf
(namespace)$ mount --bind /tmp/resolv.conf /etc/resolv.conf
(namespace)$ curl https://example.com

ربط /etc/resolv.conf مطلوب فقط عندما يشير /etc/resolv.conf على المضيف إلى عناوين الاسترجاع (127.0.0.X، عادةً dnsmasq(8) أو systemd-resolved.service(8)) التي لا يمكن الوصول إليها من المساحة.

إذا كان /etc/resolv.conf الخاص بك على المضيف مُدارًا بواسطة networkmanager(8) أو systemd-resolved.service(8)، فقد تحتاج إلى تركيب نظام ملفات جديد على /etc بدلاً من ذلك، وذلك لمنع إلغاء تركيب /etc/resolv.conf الجديد بشكل غير متوقع عند إعادة إنشاء /etc/resolv.conf على المضيف.

(namespace)$ mkdir /tmp/a /tmp/b
(namespace)$ mount --rbind /etc /tmp/a
(namespace)$ mount --rbind /tmp/b /etc
(namespace)$ mkdir /etc/.ro
(namespace)$ mount --move /tmp/a /etc/.ro
(namespace)$ cd /etc
(namespace)$ for f in .ro/*; do ln -s $f $(basename $f); done
(namespace)$ rm resolv.conf
(namespace)$ echo "nameserver 10.0.2.3" > resolv.conf
(namespace)$ curl https://example.com

يمكن تبسيط هذه الخطوات باستخدام rootlesskit --copy-up=/etc إذا تم تثبيت rootlesskit:

(host)$ rootlesskit --net=slirp4netns --copy-up=/etc bash
(namespace)$ cat /etc/resolv.conf
nameserver 10.0.2.3

توجيه حزم Ping

لتوجيه حزم ping، قد تحتاج إلى إعداد net.ipv4.ping_group_range بشكل صحيح كجذر.

مثال.

(host)$ sudo sh -c 'echo "net.ipv4.ping_group_range=0   2147483647" > /etc/sysctl.d/ping_group_range.conf'
(host)$ sudo sysctl --system

تصفية الاتصالات

افتراضيًا، المنافذ التي تستمع على INADDR_LOOPBACK (127.0.0.1) على المضيف تكون متاحة من المساحة الفرعية عبر البوابة (الافتراضي: 10.0.2.2). يمكن استخدام --disable-host-loopback لمنع الاتصال بـ INADDR_LOOPBACK على المضيف.

ومع ذلك، قد لا يزال من الممكن الوصول إلى عنوان استرجاع المضيف عبر DNS المضمن (الافتراضي: 10.0.2.3) إذا كان /etc/resolv.conf على المضيف يشير إلى عنوان استرجاع. قد ترغب في إعداد iptables للحد من الوصول إلى DNS المضمن في مثل هذه الحالة.

(host)$ nsenter -t $(cat /tmp/pid) -U --p
