FILTER EXPRESSIONS

Each filter expression consists of a library pattern and a symbol pattern.

The library pattern can be:

  • A SONAME of a shared library.
  • A basename of a shared library.
  • A wildcard pattern.
  • A regular expression.

The symbol pattern can be:

  • A symbol name.
  • A wildcard pattern.
  • A regular expression.

If a library pattern is not explicitly given, it defaults to * (all libraries). If a symbol pattern is not explicitly given, it defaults to * (all symbols).

Here are some examples:

  • lib*: Matches any library whose SONAME starts with lib.
  • *libc.so*: Matches any library whose SONAME contains libc.so.
  • /ld-linux.*/: Matches any library whose SONAME is a regular expression like ld-linux.so.1, ld-linux.so.2, etc.
  • malloc: Matches the symbol malloc in any library.
  • libc.so:malloc: Matches the symbol malloc in the library libc.so.
  • lib*.so:mallo*: Matches any symbol starting with mallo in any library whose SONAME starts with lib and ends with .so.
  • /.*\.so\.[0-9]/: Matches any library whose SONAME matches the regular expression .*\.so\.[0-9].
  • /lib(?:\.so|\.a)$/:: Matches any library whose SONAME matches the regular expression lib.so or lib.a.
  • /glibc.*/:: Matches any library whose SONAME matches the regular expression glibc.*.
  • /foo.*\.so.*/: Matches any library whose SONAME matches the regular expression foo.*\.so.*.
  • foo: Matches the symbol foo in any library, and also matches any library whose SONAME is foo and any symbol in it.
  • @libc.*: Matches any symbol whose name starts with libc.. Note that this implicitly also means *:@libc.*.
  • ld-linux.*: Matches any library whose SONAME matches ld-linux.* and any symbol in it.

A rule can be prefixed by a plus sign (+) to include symbols, or a minus sign (-) to exclude symbols. If no prefix is given, (+) is assumed.

If the library pattern starts with a @ character, it is interpreted as a regular expression for the library SONAME. For example, @libc.* matches any library whose SONAME starts with libc..

A symbol pattern can also be prefixed by a @ character, in which case it is interpreted as a regular expression for the symbol name.

For example, the rule +@libc.* matches any symbol whose name starts with libc. in any library.

The rule -@libc.* excludes any symbol whose name starts with libc. in any library.

The rule @libc.* matches any symbol whose name starts with libc. in any library.

The rule @.*:@libc.* is equivalent to @libc.*.

The rule @.*:@.* is equivalent to *.*, i.e. all symbols in all libraries.

The rule @.*:@.* is equivalent to *.*, i.e. all symbols in all libraries.

The rule @.*:@.* is equivalent to *.*, i.e. all symbols in all libraries.

In libraries that don't have an explicit SONAME, basename is taken for SONAME. That holds for main binary as well: /bin/echo has an implicit SONAME of echo. In addition to that, special library pattern MAIN always matches symbols in the main binary and never a library with actual SONAME MAIN (use e.g. ^MAIN or [M]AIN for that).

If the symbol or library pattern is surrounded in slashes (/like this/), then it is considered a regular expression instead. As a shorthand, instead of writing /x/@/y/, you can write /x@y/.

If the library pattern starts with a slash, it is not a SONAME expression, but a path expression, and is matched against the library path name.

The first rule may lack a sign, in which case + is assumed. If, on the other hand, the first rule has a - sign, it is as if there was another rule @ in front of it, which has the effect of tracing complement of given rule.

The above rules are used to construct the set of traced symbols. Each candidate symbol is passed through the chain of above rules. Initially, the symbol is unmarked. If it matches a + rule, it becomes marked, if it matches a - rule, it becomes unmarked again. If, after applying all rules, the symbol is marked, it will be traced.

BUGS

It has most of the bugs stated in strace(1).

It only works on Linux and in a small subset of architectures.

If you would like to report a bug, send a message to the mailing list (ltrace-devel@lists.alioth.debian.org), or use the reportbug(1) program if you are under the Debian GNU/Linux distribution.
