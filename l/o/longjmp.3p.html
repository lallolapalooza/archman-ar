LONGJMP(3P) دليل مبرمج POSIX LONGJMP(3P)

مقدمة

هذه الصفحة الدليلية جزء من دليل مبرمج POSIX. قد يختلف تطبيق Linux لهذا الواجهة (استشر صفحة دليل Linux المقابلة لتفاصيل سلوك Linux)، أو قد لا تكون الواجهة مطبقة على Linux.

الاسم

longjmp — الانتقال غير المحلي

الملخص

#include <setjmp.h>
void longjmp(jmp_buf env, int val);

الوصف

تتوافق الوظائف الموضحة في صفحة المرجع هذه مع معيار ISO C. أي تعارض بين المتطلبات الموضحة هنا ومعيار ISO C هو غير مقصود. هذا المجلد من POSIX.1-2017 يحيل إلى معيار ISO C.

تقوم الدالة longjmp() باستعادة البيئة المحفوظة بواسطة أحدث استدعاء لـ setjmp() في نفس العملية، مع وسيط jmp_buf المقابل. إذا كان أحدث استدعاء لـ setjmp() مع jmp_buf المقابل قد حدث في خيط آخر، أو إذا لم يكن هناك مثل هذا الاستدعاء، أو إذا كانت الدالة التي تحتوي على استدعاء setjmp() قد أنهت التنفيذ مؤقتًا، أو إذا كان استدعاء setjmp() ضمن نطاق معرف بنوع معدل متغير وتم مغادرة هذا النطاق مؤقتًا، فإن السلوك غير محدد. من غير المحدد ما إذا كانت longjmp() تستعيد قناع الإشارة، أو تترك قناع الإشارة دون تغيير، أو تستعيده إلى قيمته وقت استدعاء setjmp().

لجميع الكائنات التي يمكن الوصول إليها قيم، ولجميع المكونات الأخرى للآلة المجردة حالة (على سبيل المثال، علامات حالة النقطة العائمة والملفات المفتوحة)، كما كانت وقت استدعاء longjmp()، باستثناء أن قيم الكائنات ذات مدة التخزين التلقائي غير محددة إذا كانت تلبي جميع الشروط التالية:

*
أنها محلية للدالة التي تحتوي على استدعاء setjmp() المقابل.
*
أنها لا تحتوي على نوع مؤهل بشكل متقلب (volatile-qualified).
*
تم تغييرها بين استدعاء setjmp() واستدعاء longjmp().

على الرغم من أن longjmp() هي دالة آمنة للإشارة غير المتزامنة (async-signal-safe)، إذا تم استدعاؤها من معالج إشارة اعترض دالة غير آمنة للإشارة غير المتزامنة أو ما يعادلها (مثل المعالجة المكافئة لـ exit() التي تتم بعد العودة من الاستدعاء الأولي لـ main())، فإن سلوك أي استدعاء لاحق لدالة غير آمنة للإشارة غير المتزامنة أو ما يعادلها غير محدد.

تأثير استدعاء longjmp() حيث لم يتم إجراء تهيئة بنية jmp_buf في الخيط المستدعي غير محدد.

قيمة الإرجاع

بعد اكتمال longjmp()، يستمر تنفيذ البرنامج كما لو أن استدعاء setjmp() المقابل قد عاد للتو بالقيمة المحددة بواسطة val. لا تتسبب الدالة longjmp() في إرجاع setjmp() للقيمة 0؛ إذا كانت val تساوي 0، فإن setjmp() ستعيد القيمة 1.

الأخطاء

لا توجد أخطاء محددة.

الأقسام التالية إعلامية.

أمثلة

لا يوجد.

استخدام التطبيق

التطبيقات التي يعتمد سلوكها على قيمة قناع الإشارة يجب ألا تستخدم longjmp() و setjmp()، حيث أن تأثيرهما على قناع الإشارة غير محدد، ولكن يجب بدلاً من ذلك استخدام الدوال siglongjmp() و sigsetjmp() (التي يمكنها حفظ واستعادة قناع الإشارة تحت سيطرة التطبيق).

يوصى بعدم استدعاء التطبيقات لـ longjmp() أو siglongjmp() من معالجات الإشارة. لتجنب السلوك غير المحدد عند استدعاء هذه الدوال من معالج إشارة، يحتاج التطبيق إلى ضمان أحد الأمرين التاليين:

1.
بعد استدعاء longjmp() أو siglongjmp()، لا يستدعي البرنامج سوى دوال آمنة للإشارة غير المتزامنة ولا يعود من الاستدعاء الأولي لـ main().
2.
يتم حظر أي إشارة يكون معالجها يستدعي longjmp() أو siglongjmp() أثناء *كل* استدعاء لدالة غير آمنة للإشارة غير المتزامنة، ولا تتم أي استدعاءات من هذا القبيل بعد العودة من الاستدعاء الأولي لـ main().

NAME

longjmp — non-local goto

LIBRARY

Standard C Library (libc, -lc)

SYNOPSIS

#include <setjmp.h>

int setjmp(jmp_buf env);
void longjmp(jmp_buf env, int val);

DESCRIPTION

The setjmp() function saves the current execution context (program counter, stack pointer, etc.) in the array env. The setjmp() function returns 0 if it is called directly, and a non-zero value if control is returned to the execution context saved by setjmp() using longjmp().

The longjmp() function restores the execution context saved in env by a previous call to setjmp(). Control is then transferred back to the point of the setjmp() call. The value val is used as the return value for the setjmp() call. If val is 0, setjmp() will return 1; otherwise, setjmp() will return val.

The behavior is undefined if env was not initialized by a call to setjmp(), or if longjmp() is called after the function containing the setjmp() call has returned.

It is unsafe to call longjmp() from inside a signal handler if the signal handler was invoked asynchronously, unless the signal handler is invoking longjmp() as the very last action before returning.

The use of setjmp() and longjmp() can make programs difficult to understand and debug. It is recommended to use standard control flow constructs whenever possible.

RETURN VALUE

Upon first call, setjmp() returns 0.

When returning from longjmp(), setjmp() returns the non-zero value specified in val to longjmp().

EXAMPLES

A common use case for setjmp() and longjmp() is to implement error handling or non-local exits from nested function calls.

#include <stdio.h>
#include <setjmp.h>

jmp_buf jump_buffer;

void function_that_might_fail() {
    printf("Entering function_that_might_fail...\n");
    // Simulate an error condition
    int error_code = 1;
    if (error_code) {
        printf("Error detected, longjmping...\n");
        longjmp(jump_buffer, error_code);
    }
    printf("Exiting function_that_might_fail normally.\n");
}

int main() {
    int ret = setjmp(jump_buffer);

    if (ret == 0) {
        printf("setjmp() returned 0, calling function_that_might_fail...\n");
        function_that_might_fail();
        printf("Returned from function_that_might_fail normally.\n");
    } else {
        printf("setjmp() returned non-zero: %d, handling error...\n", ret);
        // Handle the error based on the return value
    }

    printf("Program finished.\n");
    return 0;
}

NOTES

The setjmp() and longjmp() functions are not thread-safe. If used in a multi-threaded program, each thread should have its own jmp_buf.

The variables that are modified between the call to setjmp() and the call to longjmp() may have indeterminate values after the longjmp() call, especially if they are optimized by the compiler.

For safer and more portable error handling, consider using exceptions (if available in your language) or returning error codes from functions.

STANDARDS

The setjmp() and longjmp() functions are specified by the C standard.

الاسم

longjmp — قفزة غير محلية

المكتبة

مكتبة C القياسية (libc, -lc)

الشكل العام

#include <setjmp.h>

int setjmp(jmp_buf env);
void longjmp(jmp_buf env, int val);

الوصف

تقوم الدالة setjmp() بحفظ سياق التنفيذ الحالي (عداد البرنامج، مؤشر المكدس، إلخ) في المصفوفة env. تُرجع الدالة setjmp() القيمة 0 إذا تم استدعاؤها مباشرة، وقيمة غير صفرية إذا تم إرجاع التحكم إلى سياق التنفيذ الذي تم حفظه بواسطة setjmp() باستخدام longjmp().

تقوم الدالة longjmp() باستعادة سياق التنفيذ الذي تم حفظه في env بواسطة استدعاء سابق لـ setjmp(). يتم بعد ذلك نقل التحكم مرة أخرى إلى نقطة استدعاء setjmp(). تُستخدم القيمة val كقيمة إرجاع لاستدعاء setjmp(). إذا كانت val تساوي 0، سترجع setjmp() القيمة 1؛ وإلا، سترجع setjmp() القيمة val.

السلوك غير محدد إذا لم يتم تهيئة env بواسطة استدعاء لـ setjmp()، أو إذا تم استدعاء longjmp() بعد أن قامت الدالة التي تحتوي على استدعاء setjmp() بالإرجاع.

من غير الآمن استدعاء longjmp() من داخل معالج إشارة إذا تم استدعاء معالج الإشارة بشكل غير متزامن، إلا إذا كان معالج الإشارة يستدعي longjmp() كآخر إجراء له قبل الإرجاع.

يمكن أن يؤدي استخدام setjmp() و longjmp() إلى جعل البرامج صعبة الفهم والتصحيح. يُوصى باستخدام هياكل تدفق التحكم القياسية كلما أمكن ذلك.

قيمة الإرجاع

عند الاستدعاء الأول، تُرجع setjmp() القيمة 0.

عند الإرجاع من longjmp()، تُرجع setjmp() القيمة غير الصفرية المحددة في val إلى longjmp().

أمثلة

حالة استخدام شائعة لـ setjmp() و longjmp() هي تنفيذ معالجة الأخطاء أو الخروج غير المحلي من استدعاءات الدوال المتداخلة.

#include <stdio.h>
#include <setjmp.h>

jmp_buf jump_buffer;

void function_that_might_fail() {
    printf("Entering function_that_might_fail...\n");
    // Simulate an error condition
    int error_code = 1;
    if (error_code) {
        printf("Error detected, longjmping...\n");
        longjmp(jump_buffer, error_code);
    }
    printf("Exiting function_that_might_fail normally.\n");
}

int main() {
    int ret = setjmp(jump_buffer);

    if (ret == 0) {
        printf("setjmp() returned 0, calling function_that_might_fail...\n");
        function_that_might_fail();
        printf("Returned from function_that_might_fail normally.\n");
    } else {
        printf("setjmp() returned non-zero: %d, handling error...\n", ret);
        // Handle the error based on the return value
    }

    printf("Program finished.\n");
    return 0;
}

ملاحظات

الدالتان setjmp() و longjmp() ليستا آمنتين للعمل مع المواضيع (threads). إذا تم استخدامهما في برنامج متعدد المواضيع، يجب أن يكون لكل موضوع jmp_buf خاص به.

قد تكون للمتغيرات التي تم تعديلها بين استدعاء setjmp() واستدعاء longjmp() قيم غير محددة بعد استدعاء longjmp()، خاصة إذا قام المترجم بتحسينها.

للحصول على معالجة أخطاء أكثر أمانًا وقابلية للنقل، ضع في اعتبارك استخدام الاستثناءات (إذا كانت متاحة في لغتك) أو إرجاع رموز الأخطاء من الدوال.
