FUNCIONES EXPORTADAS

Todas las funciones tienen nombres bastante extraños con el propósito de que sean cortos, operadores y que no den conflictos con funciones existentes en tu espacio de nombres. Entenderás esto cuando internacionalices tu primer programa o módulo de Perl. Preparar un programa es más como marcar cadenas como traducibles que insertar llamadas a funciones. Aquí vamos:

__ MSGID
NOTA: ¡Este es un doble guion bajo!

La función básica y más utilizada. Es un atajo para una llamada a gettext() respectivamente dgettext(), y simplemente devuelve la traducción para MSGID. Si tu código antiguo se lee así:

print "permission denied";

A partir de ahora escribes:

print __"permission denied";

Eso es todo, la cadena se mostrará en el idioma preferido del usuario, siempre que hayas instalado una traducción para ella.

Obviamente puedes usar paréntesis:

print __("permission denied");

O incluso:

print (__("permission denied"));

En mi opinión, la primera versión sin paréntesis es la mejor.

__x MSGID, ID1 => VAL1, ID2 => VAL2, ...
Una de las mejores características de Perl es su capacidad de interpolar variables en cadenas: 
print "This is the $color $thing.\n";

Esta característica puede hacerte pensar que ahora puedas escribir:

print __"This is the $color $thing.\n";

Sin embargo, eso sería bonito pero no es posible. Recuerda que la función __() sirve tanto como un operador para traducir cadenas y como un marco para cadenas traducibles. Si la cadena anterior se extrae de tu código de Perl, la forma no interpolada se incluirá en el catálogo de mensajes porque al analizar tu código es impredecible qué valores tendrán las variables $thing y $color en tiempo de ejecución (esto es probablemente una de las razones por las que has escrito tu programa).

Sin embargo, en tiempo de ejecución, Perl intercalará los valores ya antes de que __() (respectivamente la función subsecuente gettext()) vea la cadena original. Por lo tanto, algo como "This is the red car.\n" se buscará en el catálogo de mensajes, no se encontrará (porque solo "This is the $color $thing.\n" está incluido en la base de datos), y se devolverá la cadena no traducida. Honestamente, porque esto es casi siempre un error, el programa xgettext(1) se detendrá con un error fatal cuando encuentre esa cadena en tu código.

Hay dos soluciones para ese problema:

printf __"This is the %s %s.\n", $color, $thing;

pero eso tiene varias desventajas: tu traductor solo verá la cadena aislada y sin el contexto completo es casi imposible interpretarla correctamente. De hecho, los software GNU emacs y otros con capacidad de edición de archivos de traducción PO permitirán que veas el contexto en el código fuente, pero es más probable que tu traductor busque un proyecto de traducción más sencillo cuando se encuentre con tales mensajes frecuentemente.

Y incluso si ella entiende el programa subyacente, ¿qué pasa si tiene que reordenar el color y el thing como en francés:

msgid "This is the red car.\n";
msgstr "Cela est la voiture rouge.\n"

¡Zut alors! Aunque es posible reordenar los argumentos de printf() y amigos, requiere una sintaxis que no quieres aprender.

¿Y qué? El backend de Perl para gettext del GNU ha definido un formato alternativo para cadenas interpolables:

"This is the {color} {thing}.\n";

En lugar de variables Perl, usas marcadores de posición entre corchetes, y luego llamas a:

print __x ("This is the {color} {thing}.\n",
           thing => $thang,
           color => $color);

La función __x() tomará el hash adicional y reemplazará todas las ocurrencias de las claves del hash entre corchetes con los valores correspondientes. ¿Simple, legible, entendible para traductores, qué más te gustaría? Y si el traductor olvida, escribe o daña alguna "variable", la función msgfmt(1), que se usa para compilar el archivo de traducción textual en su representación binaria, incluso se enfadará con estos errores y rechazará la compilación de la traducción.

__n MSGID, MSGID_PLURAL, COUNT
¡Uf! Aquello parece complicado... mejor lo explico con un ejemplo. Vamos a revisar de nuevo tu código antiguo: 
if ($files_deleted > 1) {
    print "All files have been deleted.\n";
} else {
    print "One file has been deleted.\n";
}

Tu intención es clara, quieres evitar el complicado "1 files deleted". Esto es correcto en inglés, pero en otros idiomas hay más de un plural. Por ejemplo, en ruso, se diferencia entre 1 archivo, 3 archivos o 6 archivos. Usarás tres formas diferentes del sustantivo "file" en cada caso. [Nota: Si lo sabes, también entenderás el resto, aunque esta simplificación sea un poco complicada...].

Esa es la razón por la que existe la función ngettext(), que __n() es un atajo para:

print __n"One file has been deleted.\n"
         "All files have been deleted.\n"
         $files_deleted;

Alternativamente:

print __n ("One file has been deleted.\n",
           "All files have been deleted.\n",
           $files_deleted);

El efecto es siempre el mismo: libintl-perl buscará la forma correcta para tu idioma de usuario y el texto se mostrará siempre bien.

__nx MSGID, MSGID_PLURAL, COUNT, VAR1 => VAL1, VAR2 => VAL2, ...
Uniendo todo lo anterior: 
print __nx ("One file has been deleted.\n",
            "{count} files have been deleted.\n",
            $num_files,
            count => $num_files);

La función __nx() elige la forma correcta de plural (también para inglés) y puede interpolar variables en cadenas.

Aunque quieras mirar el orden de los argumentos: el primero es la cadena en singular, el segundo es la cadena en plural. El tercer argumento es un entero que indica el número de elementos. Este tercer argumento se usa únicamente para elegir la forma correcta. Los argumentos opcionales siguientes forman el hash usado para interpolación. Inicialmente suele ser confuso que la variable que almacena el número de elementos suele aparecer repetida en el hash de interpolación.

__xn MSGID, MSGID_PLURAL, COUNT, VAR1 => VAL1, VAR2 => VAL2, ...
Hace exactamente lo mismo que __nx(). En realidad es un error tipográfico común promovido a una característica.
__p MSGCTXT, MSGID
Esta es mucho más como __. La "p" significa "particular" y MSGCTXT se usa para proporcionar contexto a los traductores. Esto puede ser necesario cuando tu cadena es corta y podría representar varios significados. Por ejemplo:

print __p"Verb, to view", "View";
print __p"Noun, a view", "View";

El ejemplo anterior puede ser "View" en un menú donde View->Source y File->View son formas diferentes de "View", que probablemente necesitan ser traducidas de manera diferente.

Un uso típico son programas de interfaz gráfica. Imagina un programa con un menú principal y la entrada notoria "Open" en el menú File. Imagina ahora otra entrada de menú Preferences->Advanced->Policy donde tienes una elección entre las alternativas "Open" y "Closed". En inglés, "Open" es el texto adecuado en ambos lugares. En otros idiomas, es muy probable que necesites dos traducciones distintas. Por lo tanto, ahora escribirías:

__p"File|", "Open";
__p"Preferences|Advanced|Policy", "Open";

En inglés, o si no existe traducción, se devuelve el segundo argumento (MSGID).

Esta función fue introducida en libintl-perl 1.17.

__px MSGCTXT, MSGID, VAR1 => VAL1, VAR2 => VAL2, ...
Como __p(), pero soporta reemplazo de variables en la cadena, como __x(). 
print __px("Verb, to view", "View {file}", file => $filename);

Ver __p() y __x() para más detalles.

Esta función fue introducida

Locale__TextDomain(3pm)

الحزمة: perl-libintl-perl

التراخيص: LGPL

NAME

Locale::TextDomain - Perl implementation of the gettext functions

SYNOPSIS

 use Locale::TextDomain;

 # Load message catalogs
 my $domain = Locale::TextDomain->import( 'MyTextDomain', 'AnotherDomain' );

 # Translate strings
 print $domain->gettext( 'Hello, world!' );
 print $domain->ngettext( 'There is %d item.', 'There are %d items.', $count, $count );

 # Translate strings with plural forms, but don't generate them
 print $domain->pgettext( 'Greeting', 'Hello, world!' );
 print $domain->npgettext( 'ItemCount', 'There is %d item.', 'There are %d items.', $count, $count );

 # Translate strings with context, but don't generate them
 print $domain->xgettext( 'Hello, world!', 'Greeting' );
 print $domain->nxgettext( 'There is %d item.', 'There are %d items.', $count, $count, 'ItemCount' );

 # Fallback to English if no translation is found
 print $domain->gettext( 'This string is not translated.' );

 # Get text domain object without loading catalogs
 my $domain = Locale::TextDomain->new( 'MyTextDomain' );
 $domain->load_catalog();

DESCRIPTION

This module provides Perl implementations of the gettext functions, which are used for internationalizing and localizing Perl programs. It supports the standard gettext functions like gettext, ngettext, pgettext, and xgettext.

The module can automatically load message catalogs from standard locations. It also supports different plural forms based on the locale.

USAGE

To use this module, you typically import it and specify the text domain(s) you want to use.

 use Locale::TextDomain;
 my $domain = Locale::TextDomain->import( 'MyTextDomain' );

This will load the message catalog for the text domain 'MyTextDomain' from the default locations (e.g., /usr/share/locale/<locale>/LC_MESSAGES/MyTextDomain.mo or share/locale/<locale>/LC_MESSAGES/MyTextDomain.mo relative to your installation).

You can then use the imported functions:

 my $greeting = $domain->gettext('Hello');
 my $count = 5;
 my $items_msg = $domain->ngettext('There is %d item.', 'There are %d items.', $count, $count);

EXPORTED FUNCTIONS

By default, Locale::TextDomain exports the following functions:

  • gettext
  • ngettext
  • pgettext
  • npgettext
  • xgettext
  • nxgettext

You can control which functions are exported using standard Perl import tags:

 use Locale::TextDomain qw(gettext ngettext);
 use Locale::TextDomain qw(:all); # Export all functions

When functions are imported directly, they act on the default text domain. If you need to work with multiple text domains, it is recommended to import the module without any arguments and then use the method calls on the domain object:

 use Locale::TextDomain;
 my $app_domain = Locale::TextDomain->import('MyApp');
 my $lib_domain = Locale::TextDomain->import('MyLibrary');

 print $app_domain->gettext('Application message');
 print $lib_domain->gettext('Library message');

EXPORTED VARIABLES

None.

CLASS METHODS

  • new( [ domain_name ] ): Creates a new Locale::TextDomain object. If domain_name is provided, it is used as the text domain. Otherwise, a default domain might be used or it will be set later.
  • import( [ domain_name, ... ] ): Imports the specified text domains. This is a convenient way to load catalogs and optionally export the translation functions. Returns the first imported Locale::TextDomain object.
  • find_domain( domain_name ): Returns the Locale::TextDomain object for the given domain_name if it has been loaded, or undef otherwise.
  • get_default_domain( ): Returns the currently active default text domain object.
  • set_default_domain( domain_object ): Sets the default text domain object.

INSTANCE METHODS

  • load_catalog( [ domain_name ] ): Loads the message catalog for the specified domain_name (or the object's domain if not specified).
  • gettext( msgid ): Translates the given msgid string.
  • ngettext( msgid_singular, msgid_plural, n, ... ): Translates a message string that depends on a number n. It chooses between msgid_singular and msgid_plural based on the plural form rules of the current locale and the value of n.
  • pgettext( context, msgid ): Translates the given msgid string, considering the given context. This is useful when the same message string can appear in different contexts and needs different translations.
  • npgettext( context, msgid_singular, msgid_plural, n, ... ): Similar to ngettext, but also takes a context argument.
  • xgettext( msgid, msgctxt ): Alias for pgettext. This is an older name for the function.
  • nxgettext( msgid_singular, msgid_plural, n, msgctxt, ... ): Alias for npgettext. This is an older name for the function.
  • set_language( lang_code ): Sets the language for this text domain.
  • get_language( ): Returns the currently set language for this text domain.
  • set_encoding( encoding ): Sets the expected encoding of the message catalog files.
  • get_encoding( ): Returns the current encoding.

PERFORMANCE

This module uses pure Perl implementations for flexibility and compatibility. For performance-critical applications, consider using the native C gettext library via bindings if available, or optimize your translation loading strategy.

Loading large message catalogs can incur overhead. If you are using many text domains, it might be beneficial to load them explicitly only when needed, or to consolidate them if possible.
