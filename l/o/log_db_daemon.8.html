log_db_daemon(8)

الحزمة: squid

التراخيص: GPL

LOG_DB_DAEMON(8) توثيق مساهم من مستخدمي Perl LOG_DB_DAEMON(8)

الاسم

log_db_daemon - خادم تسجيل قاعدة البيانات لـ Squid

الإصدار 0.5.

الملخص

log_db_daemon DSN [خيارات]

الوصف

يقوم هذا البرنامج بكتابة إدخالات Squid access.log إلى قاعدة بيانات. حاليًا يقبل فقط تنسيق السجل الأصلي لـ squid.

تم تطوير البرنامج واختباره في البيئة التالية:

squid-2.7 Squid-3.2
mysql 5.0.26 و 5.1
perl 5.8.8
OpenSUSE 10.2

الخيارات

DSN
DSN قاعدة البيانات مشفرة كمسار. يتم إرسالها كمسار ملف access_log.

مثال التكوين:
access_log daemon:/host/database/table/username/password squid

لترك معلمة غير محددة استخدم شرطة مائلة مزدوجة:
access_log daemon://database/table/username/password squid

القيمة الافتراضية "DBI:mysql:database=squid"

--debug
كتابة معلومات التصحيح إلى stderr.

التكوين

تكوين Squid

توجيه access_log

يُستخدم المسار إلى ملف سجل الوصول لتوفير معلمات اتصال قاعدة البيانات.

access_log daemon:/mysql_host:port/database/table/username/password squid

البادئة 'daemon' إلزامية وتخبر squid أنه سيتم استخدام مساعد logfile_daemon بدلاً من تسجيل الملف العادي.

المعلمة الأخيرة تخبر squid أي تنسيق سجل سيتم استخدامه عند كتابة الأسطر إلى خادم السجل. حاليًا يتم دعم تنسيق squid.

mysql_host:port
المضيف الذي يعمل عليه خادم mysql. إذا تم تركه فارغًا، يُفترض 'localhost'.
database
اسم قاعدة البيانات المراد الاتصال بها. إذا تم تركه فارغًا، يُفترض 'squid_log'.
table
اسم جدول قاعدة البيانات حيث يتم تخزين أسطر السجل. إذا تم تركه فارغًا، يُفترض 'access_log'.
username
اسم المستخدم المراد استخدامه عند الاتصال بقاعدة البيانات. إذا تم تركه فارغًا، يُفترض 'squid'.
password
كلمة المرور المراد استخدامها عند الاتصال بقاعدة البيانات. إذا تم تركها فارغة، فلن يتم استخدام كلمة مرور.

لترك جميع الحقول بقيمها الافتراضية، يمكنك استخدام شرطة مائلة واحدة:

access_log daemon:/ squid

لتحديد كلمة مرور قاعدة البيانات فقط، والتي تكون فارغة افتراضيًا، يجب عليك ترك جميع المعلمات الأخرى غير محددة باستخدام سلاسل فارغة:

access_log daemon://///password squid

توجيه logfile_daemon

هذه هي الطريقة الحالية لإخبار squid بمكان وجود خادم logfile.

logfile_daemon /path/to/squid/libexec/logfile-daemon_mysql.pl

يجب نسخ البرنامج النصي إلى الموقع المحدد في التوجيه.

تكوين قاعدة البيانات

لنسمي قاعدة البيانات 'squid_log' وجدول السجل 'access_log'. سيكون اسم المستخدم وكلمة المرور لاتصال قاعدة البيانات كلاهما 'squid'.

قاعدة البيانات

إنشاء قاعدة البيانات:

CREATE DATABASE squid_log;

المستخدم

إنشاء المستخدم:

GRANT INSERT,SELECT,CREATE ON squid_log.* TO 'squid'@'localhost' IDENTIFIED BY 'squid';
FLUSH PRIVILEGES;

لاحظ أنه يتم منح صلاحيات CREATE و INSERT و SELECT فقط للمستخدم 'squid'. هذا يضمن أن البرنامج النصي لخادم logfile لا يمكنه تغيير أو تعديل إدخالات السجل.

الجدول

سيحاول الخادم تهيئة هذا الجدول إذا لم يكن موجودًا عند بدء تشغيله.

يجب أن يبدو الجدول الذي تم إنشاؤه كما يلي:

CREATE TABLE access_log (
  id                   INTEGER NOT NULL AUTO_INCREMENT PRIMARY KEY,
  time_since_epoch     DECIMAL(15,3),
  time_response        INTEGER,
  ip_client            CHAR(15),
  ip_server            CHAR(15),
  http_status_code     VARCHAR(10),
  http_reply_size      INTEGER,
  http_method          VARCHAR(20),
  http_url             TEXT,
  http_username        VARCHAR(20),
  http_mime_type       VARCHAR(50),
  squid_hier_status    VARCHAR(20),
  squid_request_status VARCHAR(20)
);

استخراج البيانات

استعلامات نموذجية.

العملاء الذين يصلون إلى الذاكرة المؤقتة
SELECT DISTINCT ip_client FROM access_log;
عدد الطلبات في اليوم
SELECT
  DATE(FROM_UNIXTIME(time_since_epoch)) AS date_day,
  COUNT(*) AS num_of_requests
FROM access_log
GROUP BY 1
ORDER BY 1;
عدد حالات طلب HTTP
للحصول على العدد الخام لكل حالة طلب: 
SELECT squid_request_status, COUNT(*) AS n
FROM access_log
GROUP BY squid_request_status
ORDER BY 2 DESC;

لحساب نسبة كل حالة طلب:

SELECT
  squid_request_status,
  (COUNT(*)/(SELECT COUNT(*) FROM access_log)*100) AS percentage
FROM access_log
GROUP BY squid_request_status
ORDER BY 2 DESC;

للتمييز فقط بين HITs و MISSes:

SELECT
  'hits',
  (SELECT COUNT(*)
  FROM access_log
  WHERE squid_request_status LIKE '%HIT%')
  /
  (SELECT COUNT(*) FROM access_log)*100
  AS percentage
UNION
SELECT
  'misses',
  (SELECT COUNT(*)
  FROM access_log
  WHERE squid_request_status LIKE '%MISS%')
  /
  (SELECT COUNT(*) FROM access_log)*100
  AS percentage;
نطاقات زمن الاستجابة
SELECT
  '0..500',
  COUNT(*)/(SELECT COUNT(*) FROM access_log)*100 AS percentage
FROM access_log
WHERE time_response >= 0 AND time_response < 500
UNION
SELECT
  '500..1000',
  COUNT(*)/(SELECT COUNT(*) FROM access_log)*100 AS percentage
FROM access_log
WHERE time_response >= 500 AND time_response < 1000
UNION
SELECT
  '1000..2000',
  COUNT(*)/(SELECT COUNT(*) FROM access_log)*100 AS percentage
FROM access_log
WHERE time_response >= 1000 AND time_response < 2000
UNION
SELECT
  '>= 2000',
  COUNT(*)/(SELECT COUNT(*) FROM access_log)*100 AS percentage
FROM access_log
WHERE time_response >= 2000;
حركة المرور حسب نوع mime
SELECT
  http_mime_type,
  SUM(http_reply_size) as total_bytes
FROM access_log
GROUP BY http_mime_type
ORDER BY 2 DESC;
حركة المرور حسب العميل
SELECT
  ip_client,
  SUM(http_reply_size) AS total_bytes
FROM access_log
GROUP BY 1
ORDER BY 2 DESC;

NAME

log_db_daemon - Squid URL rewrite backend database daemon

SYNOPSIS

log_db_daemon [ -d ] [ -i ] [ -m ] [ -r ] [ -l ] [ -p ] [ -t ] [ -T ] [ -v ] [ --verbose ] [ --debug ] [ --foreground ] [ --log ] [ --no-rotate ] [ --pid-file ] [ --reload-interval ] [ --time-format ] [ -h ] [ --help ] [ -V ] [ --version ]

DESCRIPTION

The log_db_daemon program is a helper utility for Squid's URL rewrite backend feature. It maintains a database of URLs and their corresponding access details, allowing Squid to perform quick lookups against this database.

This utility is designed to be used by Squid's url_rewrite_program directive, or similarly by url_rewrite_access and url_rewrite_deny directives.

OPTIONS

-d, --debug
Enable debugging output. This will log a lot of information about the daemon's operation, which can be useful for troubleshooting.
-i, --foreground
Run the daemon in the foreground. By default, it forks into the background and detaches from the controlling terminal.
-m, --no-rotate
Disables log rotation. By default, the daemon will rotate its log file when it reaches a certain size or after a certain time period.
-r, --reload-interval
Specifies the interval in seconds for reloading configuration files. Not commonly used.
-l, --log
Specifies the log file to use. If not specified, a default log file is used.
-p, --pid-file
Specifies the PID file to use. The PID file stores the process ID of the running daemon, which can be used to stop or restart it.
-t, --time-format
Specifies the time format to use in log messages. This allows for customization of how timestamps are displayed.
-T, --cache-dir
Specifies the directory where the database cache files are stored. Directory must exist and be writable by the daemon.
-v, --verbose
Enable verbose output. Similar to debug, but typically less detailed.
-h, --help
Display a help message and exit.
-V, --version
Display program version and exit.

CONFIGURATION

The behavior of log_db_daemon is primarily controlled by a configuration file, typically located at /etc/squid/log_db_daemon.conf. This file specifies:

  • Database file location.
  • Database size limits.
  • Log rotation settings.
  • Network access controls (which clients are allowed to connect).
  • Database update policies.

Consult the example configuration file provided with the Squid distribution for detailed options.

DATA EXTRACTION

The daemon can extract data from Squid's access logs. This is typically done using a separate script or utility that parses the Squid access logs and feeds the relevant information to the log_db_daemon via its database interface.

The process of extracting and inserting data into the database can be resource-intensive, especially for busy Squid caches. Care must be taken to ensure that the extraction process does not negatively impact the performance of the Squid proxy or the database itself.

A common approach is to run an external script periodically that reads the latest entries from the Squid access log, processes them, and inserts the data into the log_db_daemon's database.

This approach has an obvious scalability problem.

One solution would be to implement e.g. the "rotate log" command in a way that would calculate some summary values, put them in a "summary table" and then delete the lines used to calculate those values.

Similar cleanup code could be implemented in an external script and run periodically independently from squid log commands.

Testing

This script has only been tested in low-volume scenarios (single client, less than 10 req/s). Tests in high volume environments could reveal performance bottlenecks and bugs.
