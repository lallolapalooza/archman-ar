LOGROTATE(8) دليل مسؤول النظام LOGROTATE(8)

الاسم

logrotate ‐ يقوم بتدوير، ضغط، وإرسال سجلات النظام بالبريد

ملخص

logrotate [--force] [--debug] [--state ملف] [--skip-state-lock] [--wait-for-state-lock] [--verbose] [--log ملف] [--mail أمر] ملف_التكوين [ملف_التكوين2 ...]

الوصف

تم تصميم logrotate لتسهيل إدارة الأنظمة التي تولد عددًا كبيرًا من ملفات السجل. يسمح بالتدوير التلقائي، والضغط، والإزالة، وإرسال ملفات السجل بالبريد. يمكن التعامل مع كل ملف سجل يوميًا، أسبوعيًا، شهريًا، أو عندما يصبح كبيرًا جدًا.

عادةً، يتم تشغيل logrotate كوظيفة cron يومية. لن يقوم بتعديل سجل أكثر من مرة في يوم واحد إلا إذا كان المعيار لذلك السجل يعتمد على حجم السجل ويتم تشغيل logrotate أكثر من مرة في اليوم، أو إذا تم استخدام الخيار -f أو --force.

يمكن تقديم أي عدد من ملفات التكوين في سطر الأوامر. قد تتجاوز ملفات التكوين اللاحقة الخيارات المعطاة في الملفات السابقة، لذلك فإن الترتيب الذي يتم به سرد ملفات تكوين logrotate مهم. عادةً، يجب استخدام ملف تكوين واحد يتضمن أي ملفات تكوين أخرى مطلوبة. انظر أدناه لمزيد من المعلومات حول كيفية استخدام التوجيه include لتحقيق ذلك. إذا تم توفير دليل في سطر الأوامر، يتم استخدام كل ملف في هذا الدليل كملف تكوين.

إذا لم يتم تقديم أي وسيطات سطر الأوامر، سيقوم logrotate بطباعة معلومات الإصدار وحقوق النشر، بالإضافة إلى ملخص استخدام موجز. إذا حدثت أي أخطاء أثناء تدوير السجلات، سيخرج logrotate بحالة غير صفرية، على الرغم من أن ملف الحالة سيتم تحديثه.

خيارات

-f, --force
يخبر logrotate بفرض التدوير، حتى لو لم يكن يعتقد أن ذلك ضروري. يكون هذا مفيدًا في بعض الأحيان بعد إضافة إدخالات جديدة إلى ملف تكوين logrotate، أو إذا تمت إزالة ملفات السجل القديمة يدويًا، حيث سيتم إنشاء ملفات جديدة، وسيستمر التسجيل بشكل صحيح.
-d, --debug
تشغيل وضع التصحيح، مما يعني عدم إجراء أي تغييرات على السجلات وعدم تحديث ملف حالة logrotate. يتم فقط طباعة رسائل التصحيح.
-s, --state ملف_الحالة
يخبر logrotate باستخدام ملف حالة بديل. هذا مفيد إذا كان logrotate يتم تشغيله كمستخدم مختلف لمجموعات مختلفة من ملفات السجل. لمنع التنفيذ المتوازي، يقوم logrotate افتراضيًا بالحصول على قفل على ملف الحالة، وإذا تعذر الحصول عليه، سيخرج logrotate بالقيمة 3. ملف الحالة الافتراضي هو /var/lib/logrotate.status. إذا تم توفير /dev/null كملف حالة، فلن يحاول logrotate قفل أو كتابة ملف الحالة.
--skip-state-lock
عدم قفل ملف الحالة، على سبيل المثال إذا كان القفل غير مدعوم أو محظور.
--wait-for-state-lock
الانتظار حتى يتم تحرير قفل ملف الحالة بواسطة عملية logrotate أخرى. قد يتسبب هذا الخيار في انتظار logrotate إلى أجل غير مسمى. استخدم بحذر.
-v, --verbose
تشغيل الوضع المطول، على سبيل المثال لعرض الرسائل أثناء التدوير.
-l, --log ملف
يخبر logrotate بتسجيل المخرجات المطولة في ملف السجل. المخرجات المطولة المسجلة في هذا الملف هي نفسها عند تشغيل logrotate باستخدام المفتاح -v. يتم الكتابة فوق ملف السجل في كل تنفيذ لـ logrotate.
-m, --mail أمر
يخبر logrotate بالأمر الذي يجب استخدامه عند إرسال السجلات بالبريد. يجب أن يقبل هذا الأمر الوسيطات التالية:
1) موضوع الرسالة المعطى مع '-s subject'
2) المستلم.
يجب على الأمر بعد ذلك قراءة رسالة من الإدخال القياسي وإرسالها بالبريد إلى المستلم. الأمر الافتراضي للبريد هو /usr/bin/mail.
--usage
يطبع رسالة استخدام موجزة.
-?, --help
يطبع رسالة مساعدة.
--version
عرض معلومات الإصدار.

ملف التكوين

يقرأ logrotate كل شيء عن ملفات السجل التي يجب أن يتعامل معها من سلسلة ملفات التكوين المحددة في سطر الأوامر. يمكن لكل ملف تكوين تعيين خيارات عامة (تتجاوز التعريفات المحلية التعريفات العامة، وتتجاوز التعريفات اللاحقة التعريفات السابقة) وتحديد ملفات السجل لتدويرها. لا تؤثر الخيارات العامة على توجيهات التضمين السابقة. ملف تكوين بسيط يبدو كالتالي:

# ملف تكوين logrotate نموذجي
compress
/var/log/messages {
    rotate 5
    weekly
    postrotate
        /usr/bin/killall -HUP syslogd
    endscript
}
"/var/log/httpd/access.log" /var/log/httpd/error.log {
    rotate 5
    mail recipient@example.org
    size 100k
    sharedscripts
    postrotate
        /usr/bin/killall -HUP httpd
    endscript
}
/var/log/news/* {
    monthly
    rotate 2
    olddir /var/log/news/old
    missingok
    sharedscripts
    postrotate
        kill -HUP $(cat /var/run/inn.pid)
    endscript
    nocompress
}
~/log/*.log {}

تحدد الأسطر القليلة الأولى خيارات عامة؛ في المثال، يتم ضغط السجلات بعد تدويرها. لاحظ أن التعليقات يمكن أن تظهر في أي مكان في ملف التكوين طالما أن الحرف الأول غير الأبيض في السطر هو #.

يتم فصل القيم عن التوجيهات بواسطة المسافات البيضاء و/أو علامة = اختيارية. يجب تحديد الأرقام بتنسيق يفهمه strtoul(3).

يحدد قسم ملف التكوين التالي كيفية التعامل مع ملف السجل /var/log/messages. سيتم تدوير السجل خمس مرات أسبوعيًا قبل إزالته. بعد تدوير ملف السجل (ولكن قبل ضغط النسخة القديمة من السجل)، سيتم تنفيذ الأمر /usr/bin/killall -HUP syslogd.

يحدد القسم التالي المعلمات لكلا من /var/log/httpd/access.log و /var/log/httpd/error.log. يتم تدوير كل منهما عندما ينمو حجمه فوق 100 كيلوبايت، ويتم إرسال ملفات السجل القديمة (غير المضغوطة) بالبريد إلى recipient@example.org بعد اجتياز 5 عمليات تدوير، بدلاً من إزالتها. يعني sharedscripts أن نص postrotate سيتم تشغيله مرة واحدة فقط لهذا القسم، وليس مرة واحدة لكل سجل يتم تدويره. لاحظ أنه يمكن إحاطة أسماء ملفات السجل بعلامات اقتباس (ويجب أن تكون علامات الاقتباس مطلوبة إذا كان الاسم يحتوي على مسافات). تنطبق قواعد الاقتباس العادية في shell، مع دعم أحرف ' و " و \.

يحدد القسم التالي المعلمات لجميع الملفات في /var/log/news. يتم تدوير كل ملف شهريًا.

يستخدم القسم الأخير توسيع الشرطة المائلة العكسية لتدوير ملفات السجل في الدليل الرئيسي للمستخدم الحالي. هذا متاح فقط إذا كانت مكتبة glob الخاصة بك تدعم توسيع الشرطة المائلة العكسية. يدعم GNU glob هذا.

يرجى استخدام أحرف البدل بحذر. إذا حددت *، فسيقوم logrotate بتدوير جميع الملفات، بما في ذلك الملفات التي تم تدويرها سابقًا. طريقة لتجاوز ذلك هي استخدام التوجيه olddir أو حرف بدل أكثر دقة (مثل *.log).

يرجى ملاحظة، افتراضيًا عند استخدام systemd(1)، يتم تعيين الخيار ProtectSystem=full في ملف logrotate.service. هذا يمنع logrotate من تعديل السجلات في /etc و /usr.

sharedscripts

Run prerotate and postrotate scripts only once for every set of log files which match the wildcarded pattern (this is the default, and overrides the nosharedscripts option). The scripts are run with the aforementioned options. The absolute path to the log file is passed as first argument to the script. The absolute path to the final rotated log file is passed as the second argument to the postrotate script. If the scripts exit with error, the remaining actions will not be executed for any logs. This option overrides the nosharedscripts option.
nosharedscripts
Run prerotate and postrotate scripts for every log file which is rotated (this is the default, and overrides the sharedscripts option). The absolute path to the log file is passed as first argument to the script. The absolute path to the final rotated log file is passed as the second argument to the postrotate script. If the scripts exit with error, the remaining actions will not be executed for the affected log only.
firstaction

    script

endscript
The script is executed once before all log files that match the wildcarded pattern are rotated, before the prerotate script is run and only if at least one log will actually be rotated. These directives may only appear inside a log file definition. The whole pattern is passed to the script as its first argument. If the script exits with an error, no further processing is done. See also lastaction and the SCRIPTS section.
lastaction

    script

endscript
The script is executed once after all log files that match the wildcarded pattern are rotated, after the postrotate script is run and only if at least one log is rotated. These directives may only appear inside a log file definition. The whole pattern is passed to the script as its first argument. If the script exits with an error, just an error message is shown (as this is the last action). See also firstaction and the SCRIPTS section.
prerotate

    script

endscript
The script is executed before the log file and its old logs are rotated and only if the log will actually be rotated. These directives may only appear inside a log file definition. Normally, the absolute path to the log file is passed as the first argument to the script. If sharedscripts is specified, the whole pattern is passed to the script. See also postrotate and the SCRIPTS section. See sharedscripts and nosharedscripts for error handling.
postrotate

    script

endscript
The script is executed after the log file is rotated and before the log file is being compressed. These directives may only appear inside a log file definition. Normally, the absolute path to the log file is passed as the first argument to the script and the absolute path to the final rotated log file is passed as the second argument to the script. If sharedscripts is specified, the whole pattern is passed as the first argument to the script, and the second argument is omitted. See also prerotate and the SCRIPTS section. See sharedscripts and nosharedscripts for error handling.
preremove

    script

endscript
The script is executed once just before removal of a log file. logrotate will pass the name of file which is soon to be removed as the first argument to the script. See also firstaction and the SCRIPTS section.

SCRIPTS

The lines between the starting keyword (e.g. prerotate) and endscript (both of which must appear on lines by themselves) are executed (using /bin/sh). The script inherits some traits from the logrotate process, including stderr, stdout, the current directory, the environment, and the umask. Scripts are run as the invoking user and group, irrespective of any su directive. If the --log flag was specified, file descriptor 3 is the log file. The current working directory is unspecified.

USER AND GROUP

User and group identifiers are resolved first by trying the textual representation and, in case it fails, afterwards by the numeric value.
