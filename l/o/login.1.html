NAME

login - log in the system

SYNOPSIS

login [-f] [-h host] [-p] [-s] [name]

DESCRIPTION

The login utility announces the user logged on the system and starts the user session.

When invoked without a name argument, login prompts for a username and then, if necessary, for a password.

The login utility handles both local and remote logins. For remote logins, it relies on the getty(8) and login(1) services.

Upon successful authentication, login determines the user's login shell, login directory, and environment variables.

login updates the user's last login time in the /var/log/lastlog file.

For more details on the login process, refer to the PAM documentation (e.g., pam.d(5)).

The following options are available:

OPTIONS

-f
Force login without checking the username/password validity. This is intended for use by virtual terminals and is not recommended for use on dialup or networked logins.
-h host
Specify the name of the host the user is logging in from. This is used for logging purposes.
-p
Preserve the existing environment variables. If this option is used, the PATH and HOME environment variables are not modified.
-s
Specify that the shell should be invoked as a login shell. This is the default behavior.

CONFIG FILE ITEMS

The login configuration can be influenced by the contents of the /etc/login.defs file.

DEFAULT_LOGIN_GROUP (string)

Specifies the default login group. If set, all newly created users are added to this group. The default value is users.

FAIL_DELAY (unsigned number)

Specifies the delay in seconds after a failed login attempt. This is intended to slow down brute-force attacks. The default value is 4 seconds.

DELAY_LOGIN_USERNAME (boolean)

Enable a delay when prompting for username. If set to yes, there is a short delay before the username prompt is displayed. The default value is no.

LOG_PER_LOGIN_SESSIONS (boolean)

Enable logging per login session. If set to yes, each login session is logged separately in the utmp file. The default value is yes.

LOG_UNKNOWN (boolean)

Indicate if login is allowed if we cannot change directory to the home directory. If set to yes, the user will login in the root (/) directory if it is not possible to change directory to their home. The default value is yes.

LASTLOG_UID_MAX (unsigned number)

Highest user ID number for which the lastlog entries should be updated. As higher user IDs are usually tracked by remote user identity and authentication services there is no need to create a huge sparse lastlog file for them. No LASTLOG_UID_MAX option present in the configuration means that there is no user ID limit for writing lastlog entries. The default value is ULONG_MAX.

LOG_UNKFAIL_ENAB (boolean)

Enable display of unknown usernames when login failures are recorded. The default value is no.

Note that logging unknown usernames may be a security issue if a user enters their password instead of their login name.

ENV_PATH (string)

If set, it will be used to define the PATH environment variable when a regular user logs in. The default value is /usr/local/bin:/bin:/usr/bin.

ENV_ROOTPATH (string), ENV_SUPATH (string)

If set, it will be used to define the PATH environment variable when the superuser logs in. ENV_ROOTPATH takes precedence. The default value is /usr/local/sbin:/usr/local/bin:/sbin:/bin:/usr/sbin:/usr/bin.

FILES

/var/run/utmp, /var/log/wtmp, /var/log/lastlog, /var/spool/mail/*, /etc/motd, /etc/passwd, /etc/nologin, /etc/pam.d/login, /etc/pam.d/remote, /etc/hushlogins, $HOME/.hushlogin

CREDENTIALS

login supports configuration via systemd credentials (see https://systemd.io/CREDENTIALS/). login reads the following systemd credentials:

login.noauth (boolean)

If set, configures login to skip login authentication, similarly to the -f option.

BUGS

The undocumented BSD -r option is not supported. This may be required by some rlogind(8) programs.

A recursive login, as used to be possible in the good old days, no longer works; for most purposes su(1) is a satisfactory substitute. Indeed, for security reasons, login does a vhangup(2) system call to remove any possible listening processes on the tty. This is to avoid password sniffing. If one uses the command login, then the surrounding shell gets killed by vhangup(2) because it’s no longer the true owner of the tty. This can be avoided by using exec login in a top-level shell or xterm.

الاسم

login - تسجيل الدخول إلى النظام

ملخص

login [-f] [-h host] [-p] [-s] [name]

الوصف

يقوم الأداة login بالإعلان عن المستخدم الذي تم تسجيل دخوله إلى النظام وبدء جلسة المستخدم.

عند استدعائها بدون وسيط name، تقوم login بطلب اسم مستخدم، ثم، إذا لزم الأمر، كلمة مرور.

تتعامل الأداة login مع عمليات تسجيل الدخول المحلية والبعيدة. بالنسبة لعمليات تسجيل الدخول البعيدة، فإنها تعتمد على خدمات getty(8) و login(1).

بعد المصادقة الناجحة، تحدد login قشرة تسجيل الدخول الخاصة بالمستخدم، ودليل تسجيل الدخول، ومتغيرات البيئة.

تقوم login بتحديث وقت آخر تسجيل دخول للمستخدم في ملف /var/log/lastlog.

لمزيد من التفاصيل حول عملية تسجيل الدخول، راجع وثائق PAM (على سبيل المثال، pam.d(5)).

الخيارات التالية متاحة:

الخيارات

-f
فرض تسجيل الدخول دون التحقق من صحة اسم المستخدم/كلمة المرور. هذا مخصص للاستخدام بواسطة المحطات الطرفية الافتراضية ولا يوصى باستخدامه في تسجيلات الاتصال الهاتفي أو الشبكة.
-h host
تحديد اسم المضيف الذي يسجل المستخدم الدخول منه. يستخدم هذا لأغراض التسجيل.
-p
الحفاظ على متغيرات البيئة الحالية. إذا تم استخدام هذا الخيار، فلن يتم تعديل متغيرات البيئة PATH و HOME.
-s
تحديد أن القشرة يجب أن يتم استدعاؤها كقشرة تسجيل دخول. هذا هو السلوك الافتراضي.

عناصر ملف التكوين

يمكن أن يتأثر تكوين login بمحتويات ملف /etc/login.defs.

DEFAULT_LOGIN_GROUP (string)

يحدد مجموعة تسجيل الدخول الافتراضية. إذا تم تعيينها، تتم إضافة جميع المستخدمين الذين تم إنشاؤهم حديثًا إلى هذه المجموعة. القيمة الافتراضية هي users.

FAIL_DELAY (unsigned number)

يحدد التأخير بالثواني بعد محاولة تسجيل دخول فاشلة. هذا مخصص لإبطاء هجمات القوة الغاشمة. القيمة الافتراضية هي 4 ثوانٍ.

DELAY_LOGIN_USERNAME (boolean)

تمكين التأخير عند المطالبة باسم المستخدم. إذا تم تعيينها على yes، يكون هناك تأخير قصير قبل عرض المطالبة باسم المستخدم. القيمة الافتراضية هي no.

LOG_PER_LOGIN_SESSIONS (boolean)

تمكين التسجيل لكل جلسة تسجيل دخول. إذا تم تعيينها على yes، يتم تسجيل كل جلسة تسجيل دخول بشكل منفصل في ملف utmp. القيمة الافتراضية هي yes.

LOG_UNKNOWN (boolean)

تشير إلى ما إذا كان تسجيل الدخول مسموحًا به إذا لم نتمكن من تغيير الدليل إلى الدليل الرئيسي. إذا تم تعيينها على yes، فسيسجل المستخدم الدخول في الدليل الجذر (/) إذا لم يكن من الممكن تغيير الدليل إلى دليله الرئيسي. القيمة الافتراضية هي yes.

LASTLOG_UID_MAX (unsigned number)

أعلى رقم معرف مستخدم يجب تحديث إدخالات lastlog له. نظرًا لأن معرفات المستخدمين الأعلى عادةً ما يتم تتبعها بواسطة خدمات هوية المستخدم والمصادقة عن بعد، فلا داعي لإنشاء ملف lastlog ضخم متفرق لها. يعني عدم وجود خيار LASTLOG_UID_MAX في التكوين أنه لا يوجد حد لمعرف المستخدم لكتابة إدخالات lastlog. القيمة الافتراضية هي ULONG_MAX.

LOG_UNKFAIL_ENAB (boolean)

تمكين عرض أسماء المستخدمين غير المعروفة عند تسجيل فشل تسجيل الدخول. القيمة الافتراضية هي no.

لاحظ أن تسجيل أسماء المستخدمين غير المعروفة قد يمثل مشكلة أمنية إذا أدخل المستخدم كلمة مروره بدلاً من اسم تسجيل الدخول الخاص به.

ENV_PATH (string)

إذا تم تعيينه، فسيتم استخدامه لتحديد متغير البيئة PATH عند تسجيل دخول مستخدم عادي. القيمة الافتراضية هي /usr/local/bin:/bin:/usr/bin.

ENV_ROOTPATH (string), ENV_SUPATH (string)

إذا تم تعيينه، فسيتم استخدامه لتحديد متغير البيئة PATH عند تسجيل دخول المستخدم الخارق. يأخذ ENV_ROOTPATH الأسبقية. القيمة الافتراضية هي /usr/local/sbin:/usr/local/bin:/sbin:/bin:/usr/sbin:/usr/bin.

الملفات

بيانات الاعتماد

يدعم login التكوين عبر بيانات اعتماد systemd (انظر https://systemd.io/CREDENTIALS/). يقرأ login بيانات اعتماد systemd التالية:

login.noauth (boolean)

إذا تم تعيينها، فإنها تقوم بتكوين login لتخطي مصادقة تسجيل الدخول، بشكل مشابه للخيار -f.

الأخطاء

الخيار -r الخاص بنظام BSD غير المدعوم. قد يكون هذا مطلوبًا بواسطة بعض برامج rlogind(8).

تسجيل الدخول المتكرر، كما كان ممكنًا في الأيام الخوالي، لم يعد يعمل؛ بالنسبة لمعظم الأغراض، يعد su(1) بديلاً مرضيًا. في الواقع، لأسباب أمنية، تقوم login باستدعاء نظام vhangup(2) لإزالة أي عمليات استماع محتملة على tty. هذا لتجنب التنصت على كلمات المرور. إذا استخدم أحد الأمر login، فسيتم إنهاء القشرة المحيطة بواسطة vhangup(2) لأنها لم تعد المالك الحقيقي لـ tty. يمكن تجنب ذلك باستخدام exec login في قشرة عليا أو xterm.
