libressl-SSL_read(3)

الحزمة: libressl

التراخيص: ISC, custom:OpenSSL

SSL_READ(3) دليل وظائف المكتبة SSL_READ(3)

الاسم

SSL_read_ex, SSL_read, SSL_peek_ex, SSL_peek — قراءة البايتات من اتصال TLS

الملخص

المكتبة “libssl” libcrypto
#include <openssl/ssl.h>

int
SSL_read_ex(SSL *ssl, void *buf, size_t num, size_t *readbytes);

int
SSL_read(SSL *ssl, void *buf, int num);

int
SSL_peek_ex(SSL *ssl, void *buf, size_t num, size_t *readbytes);

int
SSL_peek(SSL *ssl, void *buf, int num);

الوصف

SSL_read_ex() و SSL_read() تحاول قراءة num بايت من ssl المحدد إلى المخزن المؤقت buf. عند النجاح، تقوم SSL_read_ex() بتخزين عدد البايتات التي تم قراءتها فعليًا في *readbytes.

SSL_peek_ex() و SSL_peek() متماثلتان مع SSL_read_ex() و SSL_read()، على التوالي، باستثناء أنه لا تتم إزالة أي بايتات من BIO الأساسي أثناء القراءة، بحيث يمكن لنداء لاحق لـ SSL_read_ex() أو SSL_read() تقديم نفس البايتات مرة أخرى على الأقل.

فيما يلي، تسمى SSL_read_ex()، SSL_read()، SSL_peek_ex()، و SSL_peek() “وظائف القراءة”.

إذا لزم الأمر، ستقوم وظيفة القراءة بالتفاوض على جلسة TLS، إذا لم تكن قد تم إجراؤها بالفعل بشكل صريح بواسطة SSL_connect(3) أو SSL_accept(3). إذا طلب الطرف الآخر إعادة التفاوض، فسيتم إجراؤه بشفافية أثناء عملية وظيفة القراءة. يعتمد سلوك وظائف القراءة على BIO الأساسي.

لكي تنجح المفاوضات الشفافة، يجب أن يكون ssl قد تم تهيئته لوضع العميل أو الخادم. يتم ذلك عن طريق استدعاء SSL_set_connect_state(3) أو SSL_set_accept_state(3) قبل الاستدعاء الأول لوظيفة قراءة.

تعمل وظائف القراءة بناءً على سجلات TLS. يتم استلام البيانات في سجلات (بحد أقصى لحجم السجل يبلغ 16 كيلوبايت). فقط عند استلام سجل بالكامل، يمكن معالجته (فك تشفيره والتحقق من سلامته). لذلك، يمكن أن تظل البيانات التي لم يتم استردادها في استدعاء القراءة الأخير مخزنة مؤقتًا داخل طبقة TLS وسيتم استردادها في استدعاء القراءة التالي. إذا كان num أعلى من عدد البايتات المخزنة مؤقتًا، فسترجع وظائف القراءة مع البايتات المخزنة مؤقتًا. إذا لم تكن هناك بايتات أخرى في المخزن المؤقت، فستقوم وظائف القراءة بتشغيل معالجة السجل التالي. فقط عند استلام السجل ومعالجته بالكامل، سترجع وظائف القراءة مع الإبلاغ عن النجاح. سيتم إرجاع محتويات السجل على الأكثر. نظرًا لأن حجم سجل TLS قد يتجاوز الحد الأقصى لحجم الحزمة للنقل الأساسي (مثل TCP)، فقد يكون من الضروري قراءة عدة حزم من طبقة النقل قبل أن يكتمل السجل ويمكن أن ينجح استدعاء القراءة.

إذا كان BIO الأساسي يحظر، فلن ترجع وظيفة القراءة إلا بعد انتهاء عملية القراءة أو حدوث خطأ، باستثناء عندما يحدث إعادة تفاوض، وفي هذه الحالة قد يحدث SSL_ERROR_WANT_READ. يمكن التحكم في هذا السلوك باستخدام علامة SSL_MODE_AUTO_RETRY لنداء SSL_CTX_set_mode(3).

إذا كان BIO الأساسي غير مانع، فسترجع وظيفة القراءة أيضًا عندما لا يتمكن BIO الأساسي من تلبية احتياجات الوظيفة لمتابعة العملية. في هذه الحالة، سيؤدي استدعاء SSL_get_error(3) مع القيمة المرجعة لوظيفة القراءة إلى SSL_ERROR_WANT_READ أو SSL_ERROR_WANT_WRITE. نظرًا لأنه يمكن حدوث إعادة تفاوض في أي وقت، فقد تتسبب وظيفة القراءة أيضًا في عمليات كتابة. يجب على العملية المستدعية تكرار النداء بعد اتخاذ الإجراء المناسب لتلبية احتياجات وظيفة القراءة. يعتمد الإجراء على BIO الأساسي. عند استخدام مقبس غير مانع، لا يلزم القيام بأي شيء، ولكن يمكن استخدام select(2) للتحقق من الشرط المطلوب. عند استخدام BIO مخزن مؤقت، مثل زوج BIO، يجب كتابة البيانات إلى BIO أو استردادها منه قبل أن يتمكن من المتابعة.

SSL_pending(3) يمكن استخدامه لمعرفة ما إذا كانت هناك بايتات مخزنة مؤقتًا متاحة للاسترداد الفوري. في هذه الحالة، يمكن استدعاء وظيفة القراءة دون حظر أو استلام بيانات جديدة فعليًا من المقبس الأساسي.

عندما يلزم تكرار عملية وظيفة القراءة بسبب SSL_ERROR_WANT_READ أو SSL_ERROR_WANT_WRITE، يجب تكرارها بنفس الوسائط.

قيم الإرجاع

SSL_read_ex() و SSL_peek_ex() ترجع 1 للنجاح أو 0 للفشل. يعني النجاح أنه تم قراءة بايت واحد أو أكثر من بيانات التطبيق من اتصال SSL. يعني الفشل أنه لم يتم قراءة أي بايتات من اتصال SSL. قد تكون حالات الفشل قابلة للتكرار (على سبيل المثال، نحن ننتظر المزيد من البايتات ليتم تسليمها بواسطة الشبكة) أو غير قابلة للتكرار (على سبيل المثال، خطأ شبكة فادح). في حالة الفشل، قم باستدعاء SSL_get_error(3) لمعرفة السبب الذي يشير إلى ما إذا كان النداء قابلاً للتكرار أم لا.

بالنسبة لـ SSL_read() و SSL_peek()، يمكن أن تحدث القيم المرجعة التالية:

>0
كانت عملية القراءة ناجحة. القيمة المرجعة هي عدد البايتات التي تم قراءتها فعليًا من اتصال TLS.
0
لم تكن عملية القراءة ناجحة. قد يكون السبب إما إغلاق نظيف بسبب تنبيه “close notify” أرسله الطرف الآخر (في هذه الحالة يتم تعيين العلامة SSL_RECEIVED_SHUTDOWN في حالة إغلاق ssl (انظر SSL_shutdown(3) و SSL_set_shutdown(3)). من الممكن أيضًا أن الطرف الآخر أغلق النقل الأساسي ببساطة والإغلاق غير مكتمل. قم باستدعاء SSL_get_error(3) مع القيمة المرجعة لمعرفة ما إذا حدث خطأ أم تم إغلاق الاتصال بشكل نظيف (SSL_ERROR_ZERO_RETURN).
<0
لم تكن عملية القراءة ناجحة، إما بسبب حدوث خطأ أو لأنه يجب على العملية المستدعية اتخاذ إجراء. قم باستدعاء SSL_get_error(3) مع القيمة المرجعة لمعرفة السبب.

SSL_read(3) — LibreSSL 4.2.1

NAME

SSL_read, SSL_read_ex, SSL_peek, SSL_peek_ex — read data from an SSL/TLS connection

SYNOPSIS

#include <openssl/ssl.h>
int SSL_read(SSL *ssl, void *buf, int num);
int SSL_peek(SSL *ssl, void *buf, int num);
int SSL_read_ex(SSL *ssl, void *buf, int num, int *processed);
int SSL_peek_ex(SSL *ssl, void *buf, int num, int *processed);

DESCRIPTION

The SSL_read() function attempts to read up to num bytes from the SSL/TLS connection described by ssl into the buffer buf. It may return fewer bytes than requested, even if more data is available, due to buffering and protocol overhead.

The SSL_peek() function attempts to read up to num bytes from the SSL/TLS connection described by ssl into the buffer buf. Unlike SSL_read(), SSL_peek() does not consume the data from the connection. This means that subsequent calls to SSL_read() or SSL_peek() will return the same data.

The SSL_read_ex() and SSL_peek_ex() functions are enhanced versions that return the number of bytes actually processed (read or peeked) in the processed argument.

If the return value is positive, it indicates the number of bytes read or peeked.

If the return value is zero or negative, an SSL/TLS error has occurred. The error code can be retrieved using SSL_get_error(3).

When an error occurs, the application may need to call SSL_read() or SSL_peek() again. The specific error code returned by SSL_get_error(3) indicates whether the operation should be retried, or if a different action should be taken.

If SSL_get_error(3) returns SSL_ERROR_WANT_READ or SSL_ERROR_WANT_WRITE, the application must wait for the underlying transport layer to become readable or writable, respectively, and then retry the call to SSL_read() or SSL_peek().

If SSL_get_error(3) returns SSL_ERROR_ZERO_RETURN, the peer has closed the connection gracefully. The application should then close the connection as well.

Other error codes indicate fatal errors, and the application should close the connection.

The SSL_read() and SSL_peek() functions may perform handshake operations if required. This may involve reading data from or writing data to the underlying transport layer.

RETURN VALUES

The number of bytes successfully read or peeked, 0, or a negative value on error. If a negative value is returned, SSL_get_error(3) should be called to determine the cause of the error.

HISTORY

SSL_read() appeared in SSLeay 0.4 or earlier. SSL_peek() first appeared in SSLeay 0.6.6. Both functions have been available since OpenBSD 2.4.

SSL_read_ex() and SSL_peek_ex() first appeared in OpenSSL 1.1.1 and have been available since OpenBSD 7.1.
