libressl-EVP_DigestInit(3)

الحزمة: libressl

التراخيص: ISC, custom:OpenSSL

EVP_DigestInit, EVP_DigestUpdate, EVP_DigestFinal, EVP_Digest, EVP_DigestInit_ex, EVP_DigestFinal_ex, EVP_MD_CTX_new, EVP_MD_CTX_create, EVP_MD_CTX_free, EVP_MD_CTX_cleanup, EVP_MD_CTX_reset, EVP_MD_CTX_copy, EVP_MD_CTX_copy_ex, EVP_MD_CTX_md, EVP_sha224, EVP_sha256, EVP_sha384, EVP_sha512, EVP_sha512_224, EVP_sha512_256, EVP_ripemd160, EVP_md_null, EVP_get_digestbyname, EVP_get_digestbynid, EVP_get_digestbyobj - high level message digest functions

DESCRIPTION

The EVP high-level functions provide a unified interface to message digests. They use an EVP_MD_CTX structure to maintain state during a message digest operation. This structure is typically allocated using EVP_MD_CTX_new() or EVP_MD_CTX_create(), initialized with a digest algorithm using EVP_DigestInit_ex(), updated with data using EVP_DigestUpdate(), and finalized using EVP_DigestFinal_ex().

EVP_MD_CTX_new() and EVP_MD_CTX_create() allocate and initialize a new EVP_MD_CTX. EVP_MD_CTX_free() and EVP_MD_CTX_cleanup() free up the context. EVP_MD_CTX_init() initializes an already allocated EVP_MD_CTX. This is mostly useful for contexts allocated as static or global variables.

EVP_MD_CTX_reset() resets an existing EVP_MD_CTX to allow it to be reused. It clears the digest state but retains the digest algorithm. It can also be used to change the digest algorithm. It should be called before calling EVP_DigestInit_ex() for a context that has already been used. Note that EVP_MD_CTX_reset() implies calling EVP_MD_CTX_cleanup() first.

EVP_DigestInit_ex() initializes the digest operation with digest type type and an optional ENGINE. If type is NULL, the default digest is used. The ENGINE *engine argument is used to explicitly specify hardware acceleration or other implementation. If NULL is specified, then any available ENGINE implementation will be used. For digest operations where the digest is not explicitly known at compile time, the EVP_get_digestbyname(), EVP_get_digestbynid() or EVP_get_digestbyobj() functions can be used to retrieve the digest implementation.

EVP_DigestUpdate() hashes cnt bytes of data at d into the digest context ctx. This function may be called multiple times.

EVP_DigestFinal_ex() computes the digest and places it in md. md must point to at least EVP_MAX_MD_SIZE bytes of memory. The actual size of the digest is placed in s. The digest context ctx is preserved for possible future use.

EVP_Digest() is a simple wrapper function to hash cnt bytes of data at d using the digest type in a one-shot operation and place the digest value into md, and, unless s is NULL, the length of the digest in bytes into *s. This wrapper uses a temporary digest context and passes its arguments to EVP_DigestInit_ex(), EVP_DigestUpdate(), and EVP_DigestFinal_ex() internally. The ENGINE *engine argument is always ignored and passing NULL is recommended.

EVP_MD_CTX_copy_ex() can be used to copy the message digest state from in to out. This is useful if large amounts of data are to be hashed which only differ in the last few bytes.

The function EVP_DigestInit() is a deprecated function behaving like EVP_DigestInit_ex() except that it requires EVP_MD_CTX_reset() before it can be used on a context that was already used.

The function EVP_DigestFinal() is a deprecated function behaving like EVP_DigestFinal_ex() except that the digest context ctx is automatically cleaned up after use by calling EVP_MD_CTX_reset() internally.

The function EVP_MD_CTX_copy() is a deprecated function behaving like EVP_MD_CTX_copy_ex() except that it requires EVP_MD_CTX_reset() before a context that was already used can be passed as out.

EVP_sha224(), EVP_sha256(), EVP_sha384(), EVP_sha512(), and EVP_ripemd160() return EVP_MD structures for the SHA-224, SHA-256, SHA-384, SHA-512 and RIPEMD-160 digest algorithms respectively.

EVP_sha512_224() and EVP_sha512_256() return an EVP_MD structure that provides the truncated SHA-512 variants SHA-512/224 and SHA-512/256, respectively.

EVP_md_null() is a "null" message digest that does nothing: i.e. the hash it returns is of zero length.

EVP_get_digestbyname(), EVP_get_digestbynid(), and EVP_get_digestbyobj() return an EVP_MD structure when passed a digest name, a digest NID, or an ASN1_OBJECT structure respectively.

EVP_get_digestbynid() and EVP_get_digestbyobj() are implemented as macros.

The EVP interface to message digests should almost always be used in preference to the low-level interfaces. This is because the code then becomes transparent to the digest used and much more flexible.

The ENGINE *engine argument is always ignored and passing NULL is recommended.

The functions EVP_DigestInit(), EVP_DigestFinal(), and EVP_MD_CTX_copy() are obsolete but are retained to maintain compatibility with existing code. New applications should use EVP_DigestInit_ex(), EVP_DigestFinal_ex(), and EVP_MD_CTX_copy_ex() because they can efficiently reuse a digest context instead of initializing and cleaning it up on each call.

If digest contexts are not cleaned up after use, memory leaks will occur.

RETURN VALUES

EVP_MD_CTX_new() and EVP_MD_CTX_create() return the new EVP_MD_CTX object or NULL for failure.

EVP_MD_CTX_reset(), EVP_MD_CTX_init(), and EVP_MD_CTX_cleanup() always return 1.

EVP_DigestInit_ex(), EVP_DigestUpdate(), EVP_DigestFinal_ex(), EVP_Digest(), EVP_MD_CTX_copy_ex(), EVP_DigestInit(), EVP_DigestFinal(), and EVP_MD_CTX_copy() return 1 for success or 0 for failure.

EVP_MD_CTX_md() returns the EVP_MD object used by ctx, or NULL if ctx is NULL or does not have any message digest algorithm assigned yet.

EVP_md_null(), EVP_sha224(), EVP_sha256(), EVP_sha384(), EVP_sha512(), EVP_sha512_224(), EVP_sha512_256(), and EVP_ripemd160() return pointers to constant static objects owned by the library.

EVP_get_digestbyname(), EVP_get_digestbynid(), and EVP_get_digestbyobj() return either an EVP_MD structure or NULL if an error occurs.

EXAMPLES

This example digests the data "Test Message\n" and "Hello World\n", using the digest name passed on the command line.

#include <stdio.h>
#include <string.h>
#include <openssl/evp.h>

int
main(int argc, char *argv[])
{
	EVP_MD_CTX *mdctx;
	const EVP_MD *md;
	const char mess1[] = "Test Message\n";
	const char mess2[] = "Hello World\n";
	unsigned char md_value[EVP_MAX_MD_SIZE];
	unsigned int md_len, i;

	if (argc <= 1) {
		printf("Usage: mdtest digestname\n");
		exit(1);
	}

	md = EVP_get_digestbyname(argv[1]);
	if (md == NULL) {
		printf("Unknown message digest %s\n", argv[1]);
		exit(1);
	}

	mdctx = EVP_MD_CTX_new();
	EVP_DigestInit_ex(mdctx, md, NULL);
	EVP_DigestUpdate(mdctx, mess1, strlen(mess1));
	EVP_DigestUpdate(mdctx, mess2, strlen(mess2));
	EVP_DigestFinal_ex(mdctx, md_value, &md_len);
	EVP_MD_CTX_free(mdctx);

	printf("Digest is: ");
	for(i = 0; i < md_len; i++)
		printf("%02x", md_value[i]);
	printf("\n");

	return 0;
}

HISTORY

EVP_DigestInit(), EVP_DigestUpdate(), and EVP_DigestFinal() first appeared in SSLeay 0.5.1. EVP_md_null() and EVP_get_digestbyname() first appeared in SSLeay 0.8.0. EVP_get_digestbynid() and EVP_get_digestbyobj() first appeared in SSLeay 0.8.1. EVP_ripemd160() first appeared in SSLeay 0.9.0. All these functions have been available since OpenBSD 2.4.

EVP_MD_CTX_copy() first appeared in OpenSSL 0.9.2b and has been available since OpenBSD 2.6.

EVP_MD_CTX_md() first appeared in OpenSSL 0.9.5 and has been available since OpenBSD 2.7.

EVP_MD_CTX_init(), EVP_MD_CTX_create(), EVP_MD_CTX_cleanup(), EVP_MD_CTX_destroy(), EVP_DigestInit_ex(), EVP_DigestFinal_ex(), EVP_Digest(), and EVP_MD_CTX_copy_ex() first appeared in OpenSSL 0.9.7 and have been available since OpenBSD 3.2.

EVP_sha224(), EVP_sha256(), EVP_sha384(), EVP_sha512(), EVP_sha512_224(), EVP_sha512_256() were added in OpenSSL 1.0.0.

و EVP_sha512() ظهرت لأول مرة في OpenSSL 0.9.7h و 0.9.8a وكانت متاحة منذ OpenBSD 4.0.

EVP_MD_CTX_new()، EVP_MD_CTX_reset()، و EVP_MD_CTX_free() ظهرت لأول مرة في OpenSSL 1.1.0 وكانت متاحة منذ OpenBSD 6.3.

EVP_sha512_224() و EVP_sha512_256() ظهرت لأول مرة في OpenSSL 1.1.1 و كانت متاحة منذ OpenBSD 7.4.
