الاسم

limits.conf - ملف تكوين لوحدة pam_limits

الوصف

تطبق الوحدة pam_limits.so حدود ulimit، وأولوية nice، وحدود عدد جلسات تسجيل الدخول المتزامنة على جلسات تسجيل دخول المستخدم. ينطبق وصف بناء الجملة لملف التكوين هذا على ملف /etc/security/limits.conf وملفات *.conf في الدليل /etc/security/limits.d.

صيغة الأسطر هي كما يلي:

<domain> <type> <item> <value>

يجب ملء الحقول المذكورة أعلاه على النحو التالي:

<domain>

• اسم مستخدم
• اسم مجموعة، مع بناء الجملة @group. لا ينبغي الخلط بين هذا وبين مجموعات الشبكة (netgroups).
• حرف البدل *، للمدخل الافتراضي.
• حرف البدل %، لحد maxlogins فقط، يمكن استخدامه أيضًا مع بناء الجملة %group. إذا تم استخدام حرف البدل % بمفرده، فهو مطابق لاستخدام * مع حد maxsyslogins. مع تحديد مجموعة بعد %، فإنه يحد من العدد الإجمالي لتسجيلات دخول جميع المستخدمين الذين هم أعضاء في المجموعة.
• نطاق uid محدد كـ <min_uid>:<max_uid>. إذا تم حذف min_uid، فالمطابقة دقيقة لـ max_uid. إذا تم حذف max_uid، فإن جميع معرفات المستخدمين الأكبر من أو تساوي min_uid تتطابق.
• نطاق gid محدد كـ @<min_gid>:<max_gid>. إذا تم حذف min_gid، فالمطابقة دقيقة لـ max_gid. إذا تم حذف max_gid، فإن جميع معرفات المجموعة الأكبر من أو تساوي min_gid تتطابق. للمطابقة الدقيقة، يتم فحص جميع المجموعات بما في ذلك المجموعات الإضافية للمستخدم. بالنسبة لمطابقات النطاق، يتم فحص المجموعة الأساسية للمستخدم فقط.
• gid محدد كـ %:<gid> ينطبق على حد maxlogins فقط. يحد من العدد الإجمالي لتسجيلات دخول جميع المستخدمين الذين هم أعضاء في المجموعة بمعرف المجموعة المحدد.

<type>

hard

لتطبيق حدود الموارد hard. يتم تعيين هذه الحدود بواسطة المستخدم الخارق (superuser) وتفرضها النواة (Kernel). لا يمكن للمستخدمين زيادة متطلباتهم الخاصة من موارد النظام فوق هذه القيم.

soft

لتطبيق حدود الموارد soft. هذه الحدود هي تلك التي يمكن للمستخدم نقلها لأعلى أو لأسفل ضمن النطاق المسموح به بواسطة أي حدود hard قائمة بالفعل. يمكن اعتبار القيم المحددة بهذا الرمز بمثابة قيم افتراضية للاستخدام العادي للنظام.

-

لتطبيق حدود الموارد soft و hard معًا.

ملاحظة: إذا قمت بتحديد نوع '-' ولكن فشلت في توفير حقلي العنصر والقيمة، فلن تقوم الوحدة بفرض أي حدود على المستخدم/المجموعة المحدد وما إلى ذلك.

<item>

core

يحد من حجم ملف النواة (KB)

data

أقصى حجم بيانات (KB)

fsize

أقصى حجم ملف (KB)

memlock

أقصى مساحة عنوان ذاكرة مقفلة (KB)

nofile

الحد الأقصى لعدد واصفات الملفات المفتوحة

rss

أقصى حجم مجموعة مقيمة (KB) (تم تجاهله في Linux 2.4.30 والإصدارات الأعلى)

stack

أقصى حجم مكدس (KB)

cpu

أقصى وقت معالج (دقائق)

nproc

الحد الأقصى لعدد العمليات

as

حد مساحة العنوان (KB)

maxlogins

الحد الأقصى لعدد تسجيلات الدخول لهذا المستخدم (هذا الحد لا ينطبق على المستخدم ذي uid=0)

maxsyslogins

الحد الأقصى لعدد جميع تسجيلات الدخول على النظام؛ لا يُسمح للمستخدم بتسجيل الدخول إذا كان العدد الإجمالي لجميع تسجيلات دخول المستخدمين أكبر من العدد المحدد (هذا الحد لا ينطبق على المستخدم ذي uid=0)

nonewprivs

قيمة 0 أو 1؛ إذا تم تعيينها إلى 1، فإنها تعطّل اكتساب امتيازات جديدة عن طريق استدعاء prctl(PR_SET_NO_NEW_PRIVS)

priority

الأولوية لتشغيل عملية المستخدم (القيم السالبة تعزز أولوية العملية)

locks

أقصى عدد ملفات مقفلة (Linux 2.4 والإصدارات الأعلى)

sigpending

الحد الأقصى لعدد الإشارات المعلقة (Linux 2.6 والإصدارات الأعلى)

msgqueue

الحد الأقصى للذاكرة المستخدمة بواسطة قوائم انتظار رسائل POSIX (بايت) (Linux 2.6 والإصدارات الأعلى)

nice

أقصى أولوية nice مسموح بالرفع إليها (Linux 2.6.12 والإصدارات الأعلى) القيم: [-20,19]

rtprio

أقصى أولوية في الوقت الفعلي مسموح بها للعمليات غير المميزة (Linux 2.6.12 والإصدارات الأعلى)

rttime

مهلة لمهام الوقت الفعلي بالميكروثانية (Linux 2.6.25 والإصدارات الأعلى)

تدعم جميع العناصر القيم -1، unlimited أو infinity التي تشير إلى عدم وجود حد، باستثناء priority، nice، و nonewprivs. إذا تم تعيين nofile إلى أحد هذه القيم، فسيتم تعيينه إلى محتويات /proc/sys/fs/nr_open بدلاً من ذلك (انظر setrlimit(3)).

إذا تم تعيين حد صارم أو حد ناعم لمورد إلى قيمة صالحة، ولكن خارج النطاق المدعوم للنظام المحلي، فقد يرفض النظام الحد الجديد أو قد يحدث سلوك غير متوقع. إذا تم استخدام قيمة التحكم required، سترفض الوحدة تسجيل الدخول إذا تعذر تعيين حد.

بشكل عام، تتمتع الحدود الفردية بالأولوية على حدود المجموعة، لذا إذا لم تفرض أي حدود على مجموعة admin، ولكن أحد أعضاء هذه المجموعة لديه سطر حدود، فسيتم تعيين حدود المستخدم وفقًا لهذا السطر.

أيضًا، يرجى ملاحظة أن جميع إعدادات الحدود يتم تعيينها لكل تسجيل دخول. فهي ليست عامة، وليست دائمة؛ موجودة فقط لمدة الجلسة. الاستثناء الوحيد هو خيار maxlogin، هذا الخيار على مستوى النظام. ولكن هناك سباق، تسجيلات الدخول المتزامنة في نفس الوقت لن يتم اكتشافها دائمًا على هذا النحو ولكن سيتم عدها كواحدة فقط.

في ملف التكوين limits، يبدأ حرف '#' تعليقًا - بعده يتم تجاهل بقية السطر.

وحدة pam_limits تبلغ عن مشكلات التكوين الموجودة في ملف تكوينها والأخطاء عبر syslog(3).

أمثلة

هذه بعض الأسطر النموذجية التي قد يتم تحديدها في /etc/security/limits.conf.

*               soft    core            0
*               hard    nofile          512
@student        hard    nproc           20
@faculty        soft    nproc           20
@faculty        hard    nproc           50
ftp             hard    nproc           0
@student        -       maxlogins       4
@student        -       nonewprivs      1
:123            hard    cpu             5000
@500:           soft    cpu             10000
600:700         hard    locks           10

NAME

limits.conf — User resource limits configuration file

SYNOPSIS

/etc/security/limits.conf

DESCRIPTION

The limits.conf file allows administrators to specify resource limits for users and groups. These limits are enforced by the PAM (Pluggable Authentication Modules) system, specifically through the pam_limits.so module.

Each line in limits.conf defines a resource limit and applies to a specific user, group, or all users. The format of each line is:

                    <domain>      <type>       <item>      <value>

Where:

  • <domain>: Specifies the user, group, or wildcard to which the limit applies. It can be a username, a group name prefixed with '@', or '*' for all users.
  • <type>: Specifies the type of limit. 'hard' sets the maximum value that a user can set for themselves, while 'soft' sets the current limit.
  • <item>: Specifies the resource to be limited. Common items include:
    • `core`: Maximum size of core files.
    • `cpu`: Maximum CPU time (in minutes).
    • `data`: Maximum size of data segments.
    • `fsize`: Maximum file size.
    • `memlock`: Maximum locked-in-memory address space.
    • `nofile`: Maximum number of open files.
    • `nproc`: Maximum number of processes.
    • `rss`: Maximum resident set size.
    • `stack`: Maximum stack size.
  • <value>: The limit value. For some items, 'unlimited' can be used.

EXAMPLES

Limit the number of open files for user 'john' to 4096:

                    john            soft    nofile      4096
                    john            hard    nofile      8192

Limit the number of processes for all users in the 'developers' group to 1024:

                    @developers     hard    nproc       1024

Set the maximum core file size to unlimited for all users:

                    *               hard    core        unlimited
