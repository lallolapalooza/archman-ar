NAME

libnss_systemd.so.2.8 — systemd NSS user and group lookup

SYNOPSIS

libnss_systemd.so.2

DESCRIPTION

The libnss_systemd.so.2 library is a Network Service Switch (NSS) module that may be used to resolve users and groups dynamically. It is intended to complement the static user and group databases defined in /etc/passwd and /etc/group, and may be used in addition to other NSS modules like files, db, ldap, etc.

This module is primarily useful for dynamic user and group resolution, for instance, for container runtimes, virtual machines, or for systemd-homed(8) and systemd-userdbd(8) user databases.

To enable this module, add the following lines to /etc/nsswitch.conf:

passwd: files systemd
group: files systemd
user: files systemd
shadow: files systemd
gshadow: files systemd

The order of the entries determines the lookup order. If systemd is listed before files, systemd users/groups will be preferred. If it is listed after, traditional files will be preferred.

STATIC DROP-IN JSON USER/GROUP RECORDS

The module may look for static user and group records in JSON format in order to extend the user and group databases. These are placed in drop-in directories like /etc/userdb/ and /etc/groupdb/, or /run/userdb/ and /run/groupdb/, or /usr/lib/userdb/ and /usr/lib/groupdb/. The directories are scanned in the order listed above.

Within these directories, files ending in .json are parsed as JSON objects, defining a single user or group record. For details on the JSON format, see:

1.
User/Group API
https://systemd.io/USER_GROUP_API
2.
JSON User Records
https://systemd.io/USER_RECORD
3.
JSON Group Record
https://systemd.io/GROUP_RECORD

CONFIGURATION IN /ETC/NSSWITCH.CONF

The libnss_systemd.so.2 module reads its configuration from systemd-specific configuration files, or from the main systemd configuration directory (/etc/systemd/).

In addition to the primary configuration file /etc/systemd/nsswitch.conf, configuration may be overridden by drop-in files named *.conf in the directory /etc/systemd/nsswitch.conf.d/.

The configuration options are:

UserDatabase=
Specifies the primary user database to use. This can be systemd, files, or compat. The default is compat.
GroupDatabase=
Specifies the primary group database to use. This can be systemd, files, or compat. The default is compat.

For more details, see systemd.directives(7) and systemd.index(7).

EXAMPLE: MAPPINGS PROVIDED BY SYSTEMD-MACHINED.SERVICE

When systemd-machined.service(8) is running, it provides dynamic user and group mappings for containers and virtual machines. This module can leverage these mappings. For example, a user might be mapped to UID 10000 in a container, and this module will correctly resolve it as such.

SEE ALSO

nsswitch.conf(5), systemd-userdbd.service(8), systemd-homed.service(8), systemd-machined.service(8)

NOTES

This module is only available if compiled with the appropriate NSS support. In most cases, it is provided by the systemd package.
