NAME

X509_check_purpose — فحص الاستخدام المقصود لمفتاح عام

SYNOPSIS

مكتبة “libcrypto”
#include <openssl/x509v3.h>

int
X509_check_purpose(X509 *certificate, int purpose, int ca);

DESCRIPTION

إذا كانت الوسيطة purpose تساوي -1، تقوم X509_check_purpose() بتجاهل الوسيطة ca والتحقق من أن جميع الامتدادات للشهادة certificate يمكن تحليلها وتمرير فحوصات السلامة الدنيا، مما يضمن عدم تكرار أي امتداد. كما تتأكد من تخزين جميع الامتدادات مؤقتًا في كائن X509.

إذا لم تكن الوسيطة purpose تساوي -1 وكانت علامة ca تساوي 0، فإن X509_check_purpose() تتحقق أيضًا مما إذا كان المفتاح العام الموجود في الشهادة certificate مخصصًا للاستخدام للغرض المحدد purpose، والذي يمكن أن يكون أحد ثوابت الأعداد الصحيحة التالية. ينجح الفحص إذا لم يتم انتهاك أي من الشروط المذكورة في القائمة أدناه. يفشل دائمًا إذا فشل تحليل أي امتداد موجود في الشهادة certificate.

X509_PURPOSE_SSL_CLIENT
  • إذا كانت الشهادة certificate تحتوي على امتداد استخدام المفتاح الممتد، فيجب أن تحتوي على غرض RFC 5280 "مصادقة عميل TLS WWW" (NID_client_auth).
  • إذا كانت الشهادة certificate تحتوي على امتداد استخدام المفتاح، فيجب تعيين بت digitalSignature.
  • إذا كانت الشهادة certificate تحتوي على امتداد نوع الشهادة Netscape، فيجب تعيين بت "شهادة عميل SSL" (NS_SSL_CLIENT).
X509_PURPOSE_SSL_SERVER
  • إذا كانت الشهادة certificate تحتوي على امتداد استخدام المفتاح الممتد، فيجب أن تحتوي على غرض RFC 5280 "مصادقة خادم TLS WWW" (NID_server_auth) أو الغرض الخاص "Netscape Server Gated Crypto" (NID_ns_sgc) أو "Microsoft Server Gated Crypto" (NID_ms_sgc).
  • إذا كانت الشهادة certificate تحتوي على امتداد استخدام المفتاح، فيجب تعيين واحد على الأقل من بتات digitalSignature و keyEncipherment.
  • إذا كانت الشهادة certificate تحتوي على امتداد نوع الشهادة Netscape، فيجب تعيين بت "شهادة خادم SSL" (NS_SSL_SERVER)
X509_PURPOSE_NS_SSL_SERVER
يقوم هذا بنفس فحوصات X509_PURPOSE_SSL_SERVER ويتطلب بالإضافة إلى ذلك أن يكون بت keyEncipherment معينًا في امتداد استخدام المفتاح، إذا كان موجودًا.
X509_PURPOSE_SMIME_SIGN
  • إذا كانت الشهادة certificate تحتوي على امتداد استخدام المفتاح الممتد، فيجب أن تحتوي على غرض RFC 5280 "حماية البريد الإلكتروني" (NID_email_protect).
  • إذا كانت الشهادة certificate تحتوي على امتداد استخدام المفتاح، فيجب تعيين واحد على الأقل من بتات digitalSignature و nonRepudiation.
  • إذا كانت الشهادة certificate تحتوي على امتداد نوع الشهادة Netscape، فيجب تعيين بت "شهادة S/MIME". إذا تم تعيين بت "شهادة عميل SSL" ولكن لم يتم تعيين بت "شهادة S/MIME"، فلن يتم اتخاذ قرار.
X509_PURPOSE_SMIME_ENCRYPT
  • إذا كانت الشهادة certificate تحتوي على امتداد استخدام المفتاح الممتد، فيجب أن تحتوي على غرض RFC 5280 "حماية البريد الإلكتروني" (NID_email_protect).
  • إذا كانت الشهادة certificate تحتوي على امتداد استخدام المفتاح، فيجب تعيين بت keyEncipherment.
  • إذا كانت الشهادة certificate تحتوي على امتداد نوع الشهادة Netscape، فيجب تعيين بت "شهادة S/MIME". إذا تم تعيين بت "شهادة عميل SSL" ولكن لم يتم تعيين بت "شهادة S/MIME"، فلن يتم اتخاذ قرار.
X509_PURPOSE_CRL_SIGN
  • إذا كانت الشهادة certificate تحتوي على امتداد استخدام المفتاح، فيجب تعيين بت cRLSign.
X509_PURPOSE_ANY
لا يلزم شيء سوى أنه، إذا كانت هناك أي امتدادات، فيجب أن ينجح تحليلها.
X509_PURPOSE_OCSP_HELPER
لا يلزم شيء سوى أنه، إذا كانت هناك أي امتدادات، فيجب أن ينجح تحليلها. يتوقع من برنامج التطبيق إجراء الفحص الفعلي بوسائل أخرى.
X509_PURPOSE_TIMESTAMP_SIGN
  • تحتوي الشهادة certificate على امتداد استخدام المفتاح الممتد يحتوي على غرض RFC 5280 "التوقيع الزمني" ولا يحتوي على أي غرض آخر. يتم تمييز هذا الامتداد على أنه حرج.
  • إذا كانت الشهادة certificate تحتوي على امتداد استخدام المفتاح، فيجب تعيين واحد على الأقل من بتات digitalSignature و nonRepudiation، وعدم تعيين أي بتات أخرى.

إذا لم تكن الوسيطة purpose تساوي -1 وكانت علامة ca غير صفرية، فإن X509_check_purpose() بدلاً من ذلك تتحقق، بالإضافة إلى فحوصات السلامة الدنيا، مما إذا كان يمكن استخدام الشهادة certificate كشهادة سلطة شهادات في سياق الغرض المعطى purpose. للنجاح، يتطلب الفحص دائمًا عدم انتهاك أي من الشروط التالية:

  • إذا كانت الشهادة certificate تحتوي على أي امتدادات، فيجب أن ينجح تحليلها.
  • إذا كانت الشهادة certificate تحتوي على امتداد استخدام المفتاح، فيجب تعيين بت keyCertSign.
  • إذا كانت الشهادة certificate تحتوي على امتداد القيود الأساسية، فيجب تعيين حقل cA.
  • إذا كانت الشهادة certificate هي شهادة إصدار 1، فيجب أن يتطابق اسم الموضوع مع اسم المُصدر وأن تكون الشهادة موقعة ذاتيًا.

ينجح الفحص إذا لم يتم انتهاك أي من الشروط الإضافية المذكورة في القائمة أدناه.

X509_PURPOSE_SSL_CLIENT

X509_check_purpose(3) — libressl — Arch Linux

NAME

X509_check_purpose, X509_check_host — check certificate purpose and hostname

SYNOPSIS

#include <openssl/x509.h>

int
X509_check_purpose(X509 *x, int purpose, int ca);
int
X509_check_host(X509 *x, const char *host, size_t hlen, unsigned int flags,
    STACK_OF(X509_NAME) **);

DESCRIPTION

The X509_check_purpose() function checks if the certificate x can be used for the given purpose. The ca parameter determines how the certificate is to be used. If ca is 0, then x is checked as an end-entity certificate. If ca is non-zero, then x is checked as an intermediate or self-signed CA certificate.

The purpose is specified by one of the following constants:

X509_PURPOSE_SSL_AUTH or X509_PURPOSE_NS_SSL_SERVER
  • If the certificate contains an Extended Key Usage extension, it contains the RFC 5280 “TLS WWW server authentication” purpose (NID_server_auth) or the private “Netscape Server Gated Crypto” (NID_ns_sgc) or “Microsoft Server Gated Crypto” (NID_ms_sgc) purpose.
  • If the certificate is not a version 1 certificate and does not contain a Basic Constraints extension, it contains a Key Usage extension with the keyEncipherment or digitalSignature bits set or a Netscape Cert Type extension with the “SSL Client Certificate” or “SSL Server Certificate” bit set.
X509_PURPOSE_CODE_SIGN
  • If the certificate contains an Extended Key Usage extension, it contains the RFC 5280 “Code Signing” purpose (NID_code_sign).
  • If the certificate is not a version 1 certificate and does not contain a Basic Constraints extension, it contains a Key Usage extension with the keyCertSign bit set or a Netscape Cert Type extension with the “SSL CA certificate” bit set.
X509_PURPOSE_SSL_SERVER or X509_PURPOSE_NS_SSL_SERVER
  • If the certificate contains an Extended Key Usage extension, it contains the RFC 5280 “TLS WWW server authentication” purpose (NID_server_auth) or the private “Netscape Server Gated Crypto” (NID_ns_sgc) or “Microsoft Server Gated Crypto” (NID_ms_sgc) purpose.
  • If the certificate is not a version 1 certificate and does not contain a Basic Constraints extension, it contains a Key Usage extension with the keyCertSign bit set or a Netscape Cert Type extension with the “SSL CA certificate” bit set.
X509_PURPOSE_SMIME_SIGN or X509_PURPOSE_SMIME_ENCRYPT
  • If the certificate contains an Extended Key Usage extension, it contains the RFC 5280 “Email protection” purpose (NID_email_protect).
  • If the certificate is not a version 1 certificate and does not contain a Basic Constraints extension, it contains a Key Usage extension with the keyCertSign bit set or a Netscape Cert Type extension with the “S/MIME CA certificate” bit set.
X509_PURPOSE_CRL_SIGN, X509_PURPOSE_OCSP_HELPER, or X509_PURPOSE_TIMESTAMP_SIGN
  • If the certificate is not a version 1 certificate and does not contain a Basic Constraints extension, it contains a Key Usage extension with the keyCertSign bit set or a Netscape Cert Type extension with at least one of the “SSL CA certificate”, “S/MIME CA certificate”, or “Object-signing CA certificate” bits set.
X509_PURPOSE_ANY
Nothing is required except that, if any extensions are present, parsing them needs to succeed. The check even succeeds if the three other common conditions cited above this list are violated.

If the function X509_PURPOSE_add(3) was called before X509_check_purpose(), it may have installed different, user-supplied checking functions for some of the standard purposes listed above, or it may have installed additional, user-supplied checking functions for user-defined purpose identifiers not listed above.

The X509_check_host() function checks if the certificate x matches the given hostname host of length hlen. The flags parameter can be used to control the matching behavior. If the hostname matches the certificate, a pointer to a stack of matching subject names is stored in **name. Otherwise, **name is set to NULL. If the check is successful, X509_check_host() returns 1, and 0 otherwise.

The following flags are supported:

X509_CHECK_FLAG_NO_SUBJECT_ALT_NAME
Do not check the subject alternative name extension.
X509_CHECK_FLAG_NO_CANONICALIZE
Do not canonicalize the hostname before comparison.
X509_CHECK_FLAG_GLOBAL_LOOKUP
Perform a global lookup for the hostname.

RETURN VALUES

If the parsing of certificate extensions fails, sanity checks fail or the purpose is invalid, X509_check_purpose() returns -1 to indicate the error.

If the purpose argument is -1 and parsing and minimal sanity checks succeed, X509_check_purpose() returns 1 to indicate success.

Otherwise, it returns the following values:

If ca is 0:

0 Failure The certificate cannot be used for the purpose.
1 Success The certificate can be used for the purpose.
2 Unknown No decision can be made.

If ca is non-zero:

0 Failure The certificate cannot be used as a CA for the purpose.
1 Success The certificate can be used as a CA for the purpose.
3 Success The certificate is a version 1 CA.
4 Success The Key Usage allows keyCertSign.
5 Success A Netscape Cert Type allows usage as a CA.
