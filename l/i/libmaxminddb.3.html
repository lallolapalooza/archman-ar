الوصف

توفر مكتبة libmaxminddb وظائف للتعامل مع ملفات MaxMind DB. راجع https://maxmind.github.io/MaxMind-DB/ لمواصفات تنسيق MaxMind DB. يتم تمثيل قاعدة البيانات والنتائج بواسطة هياكل بيانات مختلفة. يتم فتح قواعد البيانات عن طريق استدعاء MMDB_open(). يمكنك البحث عن عناوين IP كسلسلة نصية باستخدام MMDB_lookup_string() أو كمؤشر إلى بنية sockaddr باستخدام MMDB_lookup_sockaddr().

إذا وجدت عملية البحث عنوان IP في قاعدة البيانات، فإنها تُرجع بنية MMDB_lookup_result_s. إذا أشارت هذه البنية إلى أن قاعدة البيانات تحتوي على بيانات لعنوان IP، فهناك عدد من الوظائف التي يمكن استخدامها لجلب هذه البيانات. تشمل هذه MMDB_get_value() و MMDB_get_entry_data_list(). راجع توثيق الوظائف أدناه لمزيد من التفاصيل.

عند الانتهاء من مقبض قاعدة البيانات، يجب عليك استدعاء MMDB_close().

جميع الوظائف والهياكل والقوالب المعروضة للعامة تبدأ بـ "MMDB_".

هياكل البيانات

جميع هياكل البيانات التي تصدرها ملفات الرأس maxminddb.h لهذه المكتبة معرفة باسم مستعار (typedef) بالشكل typedef struct foo_s { ... } foo_s بحيث يمكنك الإشارة إليها بدون البادئة struct.

توفر هذه المكتبة هياكل البيانات التالية:

MMDB_s

هذا هو المقبض الخاص بملف MaxMind DB. نوثق فقط بعض حقول هذا الهيكل المخصصة للاستخدام العام. جميع الحقول الأخرى عرضة للتغيير وهي مخصصة للاستخدام الداخلي فقط.

typedef struct MMDB_s {
    uint32_t flags;
    const char *filename;
    ...
    MMDB_metadata_s metadata;
} MMDB_s;
  • uint32_t flags - الأعلام التي تم فتح قاعدة البيانات بها. راجع توثيق MMDB_open() لمزيد من التفاصيل.
  • const char *filename - اسم الملف الذي تم فتحه، كما تم تمريره إلى MMDB_open().
  • MMDB_metadata_s metadata - البيانات الوصفية لقاعدة البيانات.

MMDB_metadata_s و MMDB_description_s

يمكن استرداد هذا الهيكل من الهيكل MMDB_s. يحتوي على البيانات الوصفية المقروءة من ملف قاعدة البيانات. لاحظ أنه قد تجد أنه من الأنسب الوصول إلى هذه البيانات الوصفية عن طريق استدعاء MMDB_get_metadata_as_entry_data_list() بدلاً من ذلك.

typedef struct MMDB_metadata_s {
    uint32_t node_count;
    uint16_t record_size;
    uint16_t ip_version;
    const char *database_type;
    struct {
        size_t count;
        const char **names;
    } languages;
    uint16_t binary_format_major_version;
    uint16_t binary_format_minor_version;
    uint64_t build_epoch;
    struct {
        size_t count;
        MMDB_description_s **descriptions;
    } description;
} MMDB_metadata_s;
typedef struct MMDB_description_s {
    const char *language;
    const char *description;
} MMDB_description_s;

يجب أن تكون هذه الهياكل واضحة في الغالب.

يجب أن يكون العضو ip_version دائمًا 4 أو 6. يجب أن يكون binary_format_major_version دائمًا 2.

لا يوجد شرط بأن تتضمن البيانات الوصفية لقاعدة البيانات لغات أو أوصافًا، لذلك يمكن أن يكون count لهذه الأجزاء من البيانات الوصفية صفرًا. يجب أن تكون جميع حقول MMDB_metadata_s الأخرى مملوءة.

MMDB_lookup_result_s

يتم إرجاع هذا الهيكل كنتيجة للبحث عن عنوان IP.

typedef struct MMDB_lookup_result_s {
    bool found_entry;
    MMDB_entry_s entry;
    uint16_t netmask;
} MMDB_lookup_result_s;

إذا كان العضو found_entry خاطئًا، فإن الأعضاء الآخرين في هذا الهيكل لا تحتوي على قيم ذات معنى. تحقق دائمًا من أن found_entry صحيح أولاً.

يُستخدم العضو entry للبحث عن البيانات المرتبطة بعنوان IP.

يخبرك العضو netmask بالشبكة الفرعية التي ينتمي إليها عنوان IP في قاعدة البيانات هذه. على سبيل المثال، إذا بحثت عن العنوان 1.1.1.1 في قاعدة بيانات IPv4 وكانت netmask المُرجعة 16، فإن العنوان جزء من الشبكة الفرعية 1.1.0.0/16.

إذا كانت قاعدة البيانات هي قاعدة بيانات IPv6، فإن قناع الشبكة المُرجع هو دائمًا طول بادئة IPv6 (من 0-128)، حتى لو كانت قاعدة البيانات هذه تحتوي *أيضًا* على شبكات IPv4. إذا بحثت عن عنوان IPv4 وترغب في تحويل قناع الشبكة إلى قيمة قناع شبكة IPv4، يمكنك ببساطة طرح 96 من القيمة.

MMDB_result_s

لست بحاجة حقًا إلى التعمق في هذا الهيكل. ستحصل على هذا من هيكل MMDB_lookup_result_s وتمرره إلى وظائف مختلفة.

MMDB_entry_data_s

يُستخدم هذا الهيكل لإرجاع إدخال قسم بيانات واحد لعنوان IP. يمكن أن تشير هذه الإدخالات بدورها إلى إدخالات أخرى، كما هو الحال بالنسبة لأشياء مثل الخرائط والمصفوفات. بعض أعضاء هذا الهيكل غير موثقة لأنها مخصصة للاستخدام الداخلي فقط.

typedef struct MMDB_entry_data_s {
    bool has_data;
    union {
        uint32_t pointer;
        const char *utf8_string;
        double double_value;
        const uint8_t *bytes;
        uint16_t uint16;
        uint32_t uint32;
        int32_t int32;
        uint64_t uint64;
        {mmdb_uint128_t or uint8_t[16]} uint128;
        bool boolean;
        float float_value;
    };
    ...
    uint32_t data_size;
    uint32_t type;
} MMDB_entry_data_s;

العضو has_data يكون صحيحًا إذا تم العثور على بيانات لعملية بحث معينة. راجع MMDB_get_value() لمزيد من التفاصيل. إذا كان هذا العضو خاطئًا، فإن أيًا من القيم الأخرى في الهيكل ليست ذات معنى.

الاتحاد في بداية الهيكل يحدد البيانات الفعلية. لتحديد عضو الاتحاد الذي يتم استخدامه

يجب عليك النظر إلى العضو type. يجب ألا يتم تعبئة عضو pointer في الاتحاد أبدًا في أي بيانات تم إرجاعها بواسطة واجهة برمجة التطبيقات. يجب دائمًا حل المؤشرات داخليًا.

العضو data_size ذو صلة فقط ببيانات utf8_string و bytes. سلسلة utf8_string غير منتهية بصفر ويجب استخدام data_size لتحديد طولها.

يمكن مقارنة العضو type بإحدى وحدات الماكرو MMDB_DATA_TYPE_*.

أعداد صحيحة 128 بت

يعتمد التعامل مع بيانات uint128 على كيفية دعم نظامك لأعداد صحيحة 128 بت، إذا كان يدعمها على الإطلاق. مع GCC 4.4 و 4.5 يمكننا كتابة unsigned int __attribute__ ((__mode__ (TI))). مع الإصدارات الأحدث من GCC (4.6+) و clang (3.2+) يمكننا ببساطة كتابة "unsigned __int128".

لتجاوز هذه الاختلافات، تحدد هذه المكتبة نوع mmdb_uint128_t. يتم تعريف هذا النوع في ملف الترويسة maxminddb.h حتى تتمكن من استخدامه في التعليمات البرمجية الخاصة بك.

مع المترجمات الأقدم، لا يمكننا استخدام عدد صحيح، لذلك نستخدم بدلاً من ذلك مصفوفة بحجم 16 بايت من قيم uint8_t. هذه هي البيانات الخام من قاعدة البيانات.

توفر هذه المكتبة ماكرو عام MMDB_UINT128_IS_BYTE_ARRAY. إذا كان هذا صحيحًا (1)، فإن قيم uint128 يتم إرجاعها كمصفوفة بايت، وإذا كان خطأً، فسيتم إرجاعها كعدد صحيح mmdb_uint128_t.

وحدات الماكرو لأنواع البيانات

توفر هذه المكتبة ماكرو لكل نوع بيانات تحدده مواصفات MaxMind DB.

  • MMDB_DATA_TYPE_UTF8_STRING
  • MMDB_DATA_TYPE_DOUBLE
  • MMDB_DATA_TYPE_BYTES
  • MMDB_DATA_TYPE_UINT16
  • MMDB_DATA_TYPE_UINT32
  • MMDB_DATA_TYPE_MAP
  • MMDB_DATA_TYPE_INT32
  • MMDB_DATA_TYPE_UINT64
  • MMDB_DATA_TYPE_UINT128
  • MMDB_DATA_TYPE_ARRAY
  • MMDB_DATA_TYPE_BOOLEAN
  • MMDB_DATA_TYPE_FLOAT

هناك أيضًا بعض الأنواع المخصصة للاستخدام الداخلي فقط:

  • MMDB_DATA_TYPE_EXTENDED
  • MMDB_DATA_TYPE_POINTER
  • MMDB_DATA_TYPE_CONTAINER
  • MMDB_DATA_TYPE_END_MARKER

إذا رأيت أحد هذه الرموز في البيانات المرجعة، فهذا يعني أن شيئًا ما قد حدث بشكل خاطئ جدًا. قاعدة البيانات تالفة أو تم إنشاؤها بشكل غير صحيح أو أن هناك خطأ في رمز libmaxminddb.

قيم المؤشر و MMDB_close()

أعضاء utf8_string و bytes و (ربما) uint128 في هذا الهيكل هي مؤشرات مباشرة إلى قسم بيانات قاعدة البيانات. يمكن أن يكون هذا كتلة ذاكرة مخصصة بواسطة calloc أو mmap. في كلتا الحالتين، ستصبح هذه المؤشرات غير صالحة بعد استدعاء MMDB_close().

إذا كنت بحاجة إلى الإشارة إلى هذه البيانات بعد ذلك الوقت، فيجب عليك نسخ البيانات باستخدام دالة مناسبة (مثل strdup، memcpy، إلخ).

MMDB_entry_data_list_s

يلخص هذا الهيكل قائمة مترابطة من هياكل MMDB_entry_data_s.

typedef struct MMDB_entry_data_list_s {
    MMDB_entry_data_s entry_data;
    struct MMDB_entry_data_list_s *next;
} MMDB_entry_data_list_s;

يسمح لك هذا الهيكل بالاطلاع على بيانات الخريطة أو المصفوفة بأكملها عن طريق التكرار فوق القائمة المترابطة.

MMDB_search_node_s

يلخص هذا الهيكل سجلين في عقدة بحث. هذا مفيد حقًا فقط إذا كنت ترغب في كتابة تعليمات برمجية تتكرر فوق شجرة البحث بأكملها بدلاً من البحث عن عنوان IP معين.

typedef struct MMDB_search_node_s {
    uint64_t left_record;
    uint64_t right_record;
    uint8_t left_record_type;
    uint8_t right_record_type;
    MMDB_entry_s left_record_entry;
    MMDB_entry_s right_record_entry;
} MMDB_search_node_s;

ستأخذ أنواع السجلات هذين القيمتين:

  • MMDB_RECORD_TYPE_SEARCH_NODE - يشير السجل إلى عقدة البحث التالية.
  • MMDB_RECORD_TYPE_EMPTY - السجل هو عنصر نائب يشير إلى عدم وجود بيانات لعنوان IP. يجب أن ينتهي البحث هنا.
  • MMDB_RECORD_TYPE_DATA - السجل مخصص للبيانات في قسم البيانات من قاعدة البيانات. استخدم الإدخال للسجل عند البحث عن البيانات للسجل.
  • MMDB_RECORD_TYPE_INVALID - السجل غير صالح. إما تم البحث عن عقدة غير صالحة أو أن قاعدة البيانات تالفة.

يكون MMDB_entry_s للسجل صالحًا فقط إذا كان النوع هو MMDB_RECORD_TYPE_DATA. ستؤدي محاولات استخدام إدخال لأنواع السجلات الأخرى إلى حدوث خطأ أو بيانات غير صالحة.

رموز الحالة

تُرجع هذه المكتبة (أو تملأ) رموز حالة للعديد من الوظائف. رموز الحالة هذه هي:

  • MMDB_SUCCESS - تم كل شيء بنجاح
  • MMDB_FILE_OPEN_ERROR - كان هناك خطأ أثناء محاولة فتح ملف MaxMind DB.
  • MMDB_IO_ERROR - فشلت عملية إدخال/إخراج. تحقق من errno لمزيد من التفاصيل.
  • MMDB_CORRUPT_SEARCH_TREE_ERROR - أدى البحث عن عنوان IP في شجرة البحث إلى نتيجة مستحيلة. قاعدة البيانات تالفة أو تم إنشاؤها بشكل غير صحيح أو أن هناك خطأ في رمز libmaxminddb.
  • MMDB_INVALID_METADATA_ERROR - شيء ما في قاعدة البيانات خاطئ. يشمل ذلك مفاتيح بيانات وصفية مفقودة بالإضافة إلى قيم مستحيلة (مثل ip_version يساوي 7).
  • MMDB_UNKNOWN_DATABASE_FORMAT_ERROR - تشير البيانات الوصفية لقاعدة البيانات إلى أن إصدارها الرئيسي ليس 2. يمكن لهذه المكتبة فقط التعامل مع الإصدار الرئيسي 2.
  • MMDB_OUT_OF_MEMORY_ERROR - فشل استدعاء تخصيص الذاكرة (مثل malloc، إلخ).
  • MMDB_INVALID_DATA_ERROR - يحتوي إدخال في قسم البيانات على بيانات غير صالحة. على سبيل المثال، يدعي حقل uint16 أنه أطول من بايتين. قاعدة البيانات على الأرجح تالفة أو تم إنشاؤها بشكل غير صحيح.
  • MMDB_INVALID_LOOKUP_PATH_ERROR - يحتوي المسار المُمرر إلى MMDB_get_value، MMDB_vget_value، أو MMDB_aget_value على إزاحة مصفوفة أكبر من LONGMAX أو أصغر من LONGMIN.
  • MMDB_LOOKUP_PATH_DOES_NOT_MATCH_DATA_ERROR - المسار المُمرر إلى MMDB_get_value،MMDB_vget_value، أو MMDB_aget_value لا يتطابق مع بنية البيانات للإدخال. هناك عدد من الأسباب التي يمكن أن تحدث بسببها. يمكن أن يتضمن مسار البحث مفتاحًا غير موجود في خريطة. يمكن أن يتضمن مسار البحث فهرس مصفوفة أكبر من مصفوفة أو أصغر من الحد الأدنى للإزاحة من نهاية المصفوفة. يمكن أن يحدث هذا أيضًا عندما يتوقع المسار العثور على خريطة أو مصفوفة حيث لا توجد أي منها.

يجب التعامل مع جميع رموز الحالة كقيم int.

MMDB_strerror()

const char *MMDB_strerror(int error_code)

تأخذ هذه الدالة رمز حالة وتعيد سلسلة نصية باللغة الإنجليزية تشرح الحالة.

الوظائف

توفر هذه المكتبة الوظائف المصدرة التالية:

MMDB_open()

int MMDB_open(
    const char *const filename,
    uint32_t flags,
    MMDB_s *const mmdb);

تفتح هذه الدالة مقبضًا لملف MaxMind DB. قيمة الإرجاع الخاصة بها هي رمز حالة كما هو محدد أعلاه. تحقق دائمًا من قيمة الإرجاع لهذا الاستدعاء.

MMDB_s mmdb;
int status =
    MMDB_open("/path/to/file.mmdb", MMDB_MODE_MMAP, &mmdb);
if (MMDB_SUCCESS != status) { ... }
...
MMDB_close(&mmdb);

filename يجب أن يتم ترميزه بنظام UTF-8 على نظام Windows.

يمكن أن يكون الهيكل MMDB_s الذي تمرره موجودًا على المكدس أو تم تخصيصه من الكومة. ومع ذلك، إذا نجح الفتح، فسيحتوي على بيانات مخصصة من الكومة، لذلك تحتاج إلى إغلاقه باستخدام MMDB_close(). إذا لم تكن الحالة المرجعة MMDB_SUCCESS، فإن هذه المكتبة تتأكد من تحرير جميع الذاكرة المخصصة قبل العودة.

الأعلام المتوفرة حاليًا هي:

•
MMDB_MODE_MMAP - افتح قاعدة البيانات باستخدام mmap().

قد يؤدي تمرير قيم أخرى للأعلام (flags) إلى نتائج غير متوقعة. في المستقبل، قد نضيف أعلامًا إضافية يمكنك دمجها مع الوضع باستخدام عملية OR الثنائية، بالإضافة إلى أوضاع إضافية.

يمكنك أيضًا تمرير 0 كقيمة للأعلام (flags) وفي هذه الحالة سيتم فتح قاعدة البيانات باستخدام الأعلام الافتراضية. ومع ذلك، قد تتغير هذه الافتراضيات في الإصدارات المستقبلية. الافتراضي الحالي هو MMDB_MODE_MMAP.

MMDB_close()

void MMDB_close(MMDB_s *const mmdb);

يقوم هذا بتحرير أي ذاكرة مخصصة أو مُمَثلة (mmap'd) يحتفظ بها الهيكل MMDB_s. * لا يقوم بتحرير الذاكرة المخصصة

Data Lookup Functions

There are three functions for looking up data associated with an IP address.

int MMDB_get_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    ...);
int MMDB_vget_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    va_list va_path);
int MMDB_aget_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    const char *const *const path);

The three functions allow three slightly different calling styles, but they all do the same thing.

The first parameter is an MMDB_entry_s value. In most cases this will come from the MMDB_lookup_result_s value returned by MMDB_lookup_string() or MMDB_lookup_sockaddr().

The second parameter is a reference to an MMDB_entry_data_s structure. This will be populated with the data that is being looked up, if any is found. If nothing is found, then the has_data member of this structure will be false. If has_data is true then you can look at the data_type member.

The final parameter is a lookup path. The path consists of a set of strings representing either map keys (e.g, "city") or array indexes (e.g., "0", "1", "-1") to use in the lookup.

Negative array indexes will be treated as an offset from the end of the array. For instance, "-1" refers to the last element of the array.

The lookup path allows you to navigate a complex data structure. For example, given this data:

{
    "names": {
        "en": "Germany",
        "de": "Deutschland"
    },
    "cities": [ "Berlin", "Frankfurt" ]
}

We could look up the English name with this code:

MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
MMDB_entry_data_s entry_data;
int status =
    MMDB_get_value(&result.entry, &entry_data,
                   "names", "en", NULL);
if (MMDB_SUCCESS != status) { ... }
if (entry_data.has_data) { ... }

If we wanted to find the first city the lookup path would be "cities", "0". If you don't provide a lookup path at all, you'll get the entry which corresponds to the top level map. The lookup path must always end with NULL, regardless of which function you call.

The MMDB_get_value function takes a variable number of arguments. All of the arguments after the MMDB_entry_data_s * structure pointer are the lookup path. The last argument must be NULL.

The MMDB_vget_value function accepts a va_list as the lookup path. The last element retrieved by va_arg() must be NULL.

Finally, the MMDB_aget_value accepts an array of strings as the lookup path. The last member of this array must be NULL.

If you want to get all of the entry data at once you can call MMDB_get_entry_data_list() instead.

For each of the three functions, the return value is a status code as defined above.

MMDB_get_entry_data_list()

int MMDB_get_entry_data_list(
    MMDB_entry_s *start,
    MMDB_entry_data_list_s **const entry_data_list);

This function allows you to get all of the data for a complex data structure at once, rather than looking up each piece using repeated calls to MMDB_get_value().

MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
MMDB_entry_data_list_s *entry_data_list, *first;
int status =
    MMDB_get_entry_data_list(&result.entry, &entry_data_list);
if (MMDB_SUCCESS != status) { ... }
// save this so we can free this data later
first = entry_data_list;
while (1) {
    MMDB_entry_data_list_s *next = entry_data_list = entry_data_list->next;
    if (NULL == next) {
        break;
    }
    switch (next->entry_data.type) {
        case MMDB_DATA_TYPE_MAP: { ... }
        case MMDB_DATA_TYPE_UTF8_STRING: { ... }
        ...
    }
}
MMDB_free_entry_data_list(first);

It's up to you to interpret the entry_data_list data structure. The list is linked in a depth-first traversal. Let's use this structure as an example:

{
    "names": {
        "en": "Germany",
        "de": "Deutschland"
    },
    "cities": [ "Berlin", "Frankfurt" ]
}

The list will consist of the following items:

1.
MAP - top level map
2.
UTF8_STRING - "names" key
3.
MAP - map for "names" key
4.
UTF8_STRING - "en" key
5.
UTF8_STRING - value for "en" key
6.
UTF8_STRING - "de" key
7.
UTF8_STRING - value for "de" key
8.
UTF8_STRING - "cities" key
9.
ARRAY - value for "cities" key
10.
UTF8_STRING - array[0]
11.
UTF8_STRING - array[1]

The return value of the function is a status code as defined above.

MMDB_free_entry_data_list()

void MMDB_free_entry_data_list(
    MMDB_entry_data_list_s *const entry_data_list);

The MMDB_get_entry_data_list() and MMDB_get_metadata_as_entry_data_list() functions will allocate the linked list structure from the heap. Call this function to free the MMDB_entry_data_list_s structure.

MMDB_get_metadata_as_entry_data_list()

int MMDB_get_metadata_as_entry_data_list(
    MMDB_s *const mmdb,
    MMDB_entry_data_list_s **const entry_data_list);

This function allows you to retrieve the database metadata as a linked list of MMDB_entry_data_list_s structures. This can be a more convenient way to deal with the metadata than using the metadata structure directly.

    MMDB_entry_data_list_s *entry_data_list, *first;
    int status =
        MMDB_get_metadata_as_entry_data_list(&mmdb, &entry_data_list);
    if (MMDB_SUCCESS != status) { ... }
    first = entry_data_list;
    ... // do something with the data
    MMDB_free_entry_data_list(first);

The return value of the function is a status code as defined above.

MMDB_dump_entry_data_list()

int MMDB_dump_entry_data_list(
    FILE *const stream,
    MMDB_entry_data_list_s *const entry_data_list,
    int indent);

This function takes a linked list of MMDB_entry_data_list_s structures and stringifies it to the given stream. The indent parameter is the starting indent level for the generated output. It is incremented for nested data structures (maps, array, etc.).

The stream must be a file handle (stdout, etc). If your platform provides something like the GNU open_memstream() you can use that to capture the output as a string.

The output is formatted in a JSON-ish fashion, but values are marked with their data type (except for maps and arrays which are shown with "{}" and "[]" respectively).
