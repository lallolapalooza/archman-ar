LIBZIP(3) Library Functions Manual LIBZIP(3)

NAME

libzip — مكتبة للتعامل مع أرشيفات zip

LIBRARY

libzip (-lzip)

SYNOPSIS

#include <zip.h>

DESCRIPTION

libzip هي مكتبة لقراءة وإنشاء وتعديل أرشيفات zip.

كانت معايير التصميم الرئيسية لـ libzip هي:

  • الحفاظ على واجهة برمجة تطبيقات مستقرة دون كسر التوافق الرجعي.
  • عدم إنشاء ملفات تالفة، حتى في حالة حدوث أخطاء.
  • عدم حذف البيانات.
  • أن تكون فعالة.

لهذا السبب، عند تعديل أرشيفات zip، تكتب libzip إلى ملف مؤقت وتحل محل أرشيف zip الأصلي بشكل ذري.

GENERAL NOTES

عند إضافة ملفات إلى أرشيف، يتم قراءة بيانات الملف فقط عند كتابة الأرشيف الجديد. لذلك يجب أن تظل جميع الملفات المضافة صالحة حتى يتم إغلاق الأرشيف باستخدام zip_close(3) أو zip_discard(3).

ما لم يتم توثيقه صراحة، لا ينبغي تمرير مؤشرات NULL كوسائط للدوال.

DATA TYPES

تتوافق أنواع البيانات هذه مع المفاهيم المركزية في libzip. معظمها خاص، مما يعني أنه لا يمكنك تخصيصها أو الوصول إلى أعضائها مباشرة. هذا يسمح بتوسيع الهياكل في المستقبل دون كسر التوافق.

zip_t

يمثل هذا النوع أرشيفًا مفتوحًا. انظر zip(5).

zip_file_t

يمثل هذا النوع ملفًا من أرشيف تم فتحه للقراءة. انظر zip_file(5).

zip_source_t

يمثل هذا النوع مصدرًا (أو وجهة) للبيانات. يُستخدم في libzip لتوفير البيانات عند إضافة أو استبدال الملفات، والوصول إلى البيانات من ملف داخل أرشيف، والبيانات الخاصة بالأرشيف ككل. انظر zip_source(5).

zip_error_t

يمثل هذا النوع معلومات حول خطأ. يمكن التحقق من نوعه مقابل ثوابت محددة مسبقًا ويمكن تحويله إلى سلسلة نصية قابلة للقراءة. انظر zip_error(5).

FILE NAMES

Encoding

يتوقع أن تكون أسماء الملفات في نظام الملفات المضيف مشفرة بـ UTF-8. على نظام Windows، تتوفر أيضًا متغيرات لـ ASCII و UTF-16.

افتراضيًا، يتوقع أن تكون أسماء الملفات داخل الأرشيفات مشفرة بـ UTF-8. يمكن طلب ترميزات أخرى باستخدام الأعلام ZIP_FL_ENC_CP437 و ZIP_FL_ENC_RAW.

للتفاصيل، راجع صفحات الدليل ذات الصلة.

Directory Separator

يتطلب تنسيق zip استخدام الشرطة المائلة للأمام (‘/’) كم فاصل للمجلدات. نظرًا لأن الشرطة المائلة العكسية (‘\’) يمكن أن تكون جزءًا من اسم ملف صالح على أنظمة Unix، فإن libzip لا تقوم بتحويلها تلقائيًا، حتى على نظام Windows. تقع على عاتق المبرمج مسؤولية التأكد من تمرير جميع فواصل المجلدات كشرطات مائلة للأمام إلى libzip.

THREAD SAFETY

بشكل عام، تختلف أرشيفات zip المختلفة المفتوحة بواسطة libzip عن بعضها البعض ويمكن استخدامها بواسطة خيوط متوازية دون الحاجة إلى قفل. إذا كنت ترغب في استخدام أرشيف من خيوط متعددة، فيجب عليك مزامنة الوصول إليه بنفسك. إذا كنت تستخدم أرشيفًا كمصدر لـ zip_file_add(3) أو zip_file_replace(3)، فيجب مزامنة الوصول إلى الأرشيف الهدف مع الوصول إلى الأرشيف المصدر أيضًا.

libzip(3) — libzip — Arch Linux

NAME

libzip - High level interface to manipulate zip archives

LIBRARY

libzip, -lzip

SYNOPSIS

#include <zip.h>

DESCRIPTION

The libzip library provides functions to create, read, modify, and extract zip archives.

GENERAL NOTES

All functions in libzip that operate on zip archives take a pointer to a zip_t structure as their first argument. This structure is obtained by calling zip_open(3) or zip_open_from_source(3).

When you are finished with a zip archive, you must call zip_close(3) or zip_discard(3) to free any resources associated with it.

Functions that modify zip archives (e.g., adding, renaming, deleting files) do not take effect until zip_close(3) is called. If you want to discard changes without saving them, call zip_discard(3) instead.

Error handling is done via the zip_error_t structure and related functions (see zip_error_strerror(3), zip_strerror(3), etc.).

DATA TYPES

zip_t: Represents an open zip archive.

zip_file_t: Represents a file within a zip archive.

zip_source_t: Represents a source of data for adding to or opening a zip archive.

zip_error_t: Structure for error reporting.

zip_uint8_t, zip_uint16_t, zip_uint32_t, zip_uint64_t: Unsigned integer types of specified sizes.

zip_int8_t, zip_int16_t, zip_int32_t, zip_int64_t: Signed integer types of specified sizes.

FILE NAMES

File names within a zip archive are treated as sequences of bytes. libzip does not perform any character set conversions or interpretations by default. It is up to the application to handle the character encoding of file names if necessary.

THREAD SAFETY

Except for functions that operate on zip_source_t objects created with zip_source_function(3) or zip_source_layered(3) (which require careful handling of shared state), libzip is generally thread-safe. However, multiple threads should not access the same zip_t structure concurrently. For finer-grained control, use the cancel and progress callback functions with state.
