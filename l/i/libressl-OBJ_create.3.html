libressl-OBJ_create(3)

الحزمة: libressl

التراخيص: ISC, custom:OpenSSL

OBJ_CREATE(3) دليل وظائف المكتبة OBJ_CREATE(3)

الاسم

OBJ_new_nid، OBJ_add_object، OBJ_create، OBJ_create_objects، OBJ_cleanup — تعديل جدول معرفات كائنات ASN.1

الملخص

مكتبة «libcrypto»
#include <openssl/objects.h>

int
OBJ_new_nid(int increment);

int
OBJ_add_object(const ASN1_OBJECT *object);

int
OBJ_create(const char *oid, const char *sn, const char *ln);

int
OBJ_create_objects(BIO *in_bio);

void
OBJ_cleanup(void);

الوصف

OBJ_new_nid() تعيد أصغر معرف كائن ASN.1 رقمي (NID) غير معين حاليًا وتحجز increment معرفات NIDs متتالية تبدأ منه. يوصى عادةً بتمرير قيمة 1. يمكن تعيين القيمة المرجعة لكائن جديد عن طريق تمريرها كوسيط nid إلى ASN1_OBJECT_CREATE(3) وتمرير الكائن الناتج إلى OBJ_add_object().

OBJ_add_object() تضيف نسخة من object إلى الجدول الداخلي لمعرفات كائنات ASN.1 للاستخدام بواسطة OBJ_nid2obj(3) والوظائف ذات الصلة.

OBJ_create() توفر طريقة أبسط لإضافة كائن جديد إلى الجدول الداخلي. oid هو الشكل الرقمي للكائن، sn هو الاسم المختصر، و ln هو الاسم الطويل. يتم تعيين NID جديد تلقائيًا باستخدام OBJ_new_nid().

OBJ_create_objects() تقرأ سطور نصية بالشكل

oid sn ln

من in_bio وتستدعي OBJ_create(oid, sn, ln) لكل سطر تتم قراءته. يتم فصل الحقول الثلاثة لأسطر الإدخال بمسافة بيضاء واحدة أو أكثر.

لكل الوظائف الثلاث، يتم تمييز الكائنات المضافة إلى الجدول الداخلي وجميع البيانات الموجودة فيها على أنها غير مخصصة ديناميكيًا. ونتيجة لذلك، فإن استردادها باستخدام OBJ_nid2obj(3) أو وظيفة مماثلة ثم استدعاء ASN1_OBJECT_FREE(3) على المؤشر المُعاد لن يكون له أي تأثير.

OBJ_cleanup() تعيد ضبط جدول الكائنات الداخلي إلى حالته الافتراضية، مع إزالة وتحرير جميع الكائنات التي تم إضافتها باستخدام OBJ_add_object()، OBJ_create()، أو OBJ_create_objects().

قيم الإرجاع

OBJ_new_nid() تعيد NID الجديد.

OBJ_add_object() تعيد NID الخاص بـ object المضاف أو NID_undef إذا لم تتم إضافة أي كائن لأن وسيط object كان NULL، أو لم يحتوِ على NID، أو فشل تخصيص الذاكرة.

OBJ_create() تعيد NID الجديد أو NID_undef إذا كان oid ليس تمثيلاً صحيحًا لمعرف كائن، أو إذا فشل تخصيص الذاكرة.

OBJ_create_objects() تعيد عدد الكائنات المضافة.

في بعض حالات الفشل لـ OBJ_add_object()، OBJ_create()، و OBJ_create_objects()، يمكن تحديد السبب باستخدام ERR_get_error(3).

أمثلة

إنشاء NID جديد وتهيئة كائن منه:

int new_nid;
ASN1_OBJECT *obj;

new_nid = OBJ_create("1.2.3.4", "NewOID", "New Object Identifier");
obj = OBJ_nid2obj(new_nid);

انظر أيضاً

ASN1_OBJECT_NEW(3)، OBJ_NID2OBJ(3)

التاريخ

OBJ_new_nid()، OBJ_add_object()، و OBJ_cleanup() ظهرت لأول مرة في SSLeay 0.8.0، و OBJ_create() في SSLeay 0.9.0. هذه الوظائف متاحة منذ OpenBSD 2.4.

تنبيهات

OBJ_add_object() تشير إلى النجاح حتى بعد إضافة كائن غير مكتمل تم إنشاؤه باستخدام ASN1_OBJECT_CREATE(3) ولكنه يفتقر إلى اسم مختصر، أو اسم طويل، أو OID.

حتى OBJ_create() تتسامح مع تمرير مؤشرات NULL للوسيطين sn و/أو ln، وفي هذه الحالة، لن تعمل OBJ_NID2SN(3) و OBJ_SN2NID(3) أو OBJ_NID2LN(3) و OBJ_LN2NID(3) على الكائن المضاف، على التوالي.

أخطاء

OBJ_new_nid() لا تحتجز أي قيمة إرجاع للإشارة إلى خطأ. ونتيجة لذلك، لتجنب تعارض تعيينات NID وفائض الأعداد الصحيحة، يجب توخي الحذر لعدم تمرير وسائط سالبة أو صفرية أو كبيرة إلى OBJ_new_nid().

OBJ_create_objects() لا تميز بين نهاية الملف، أو أخطاء الإدخال/الإخراج، أو عدم التوفر المؤقت للبيانات على BIO غير مانع، أو بناء جملة إدخال غير صالح، أو فشل تخصيص الذاكرة. في جميع هذه الحالات، يتم إيقاف القراءة ويتم إرجاع عدد الكائنات التي تمت إضافتها بالفعل.
