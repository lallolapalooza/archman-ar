libressl-CMS_add1_signer(3)

الحزمة: libressl

التراخيص: ISC, custom:OpenSSL

CMS_ADD1_SIGNER(3) دليل وظائف المكتبة CMS_ADD1_SIGNER(3)

الاسم

CMS_add1_signer، CMS_SignerInfo_sign — إضافة موقع إلى بنية CMS SignedData

المُلَخَّص

المكتبة "libcrypto"
#include <openssl/cms.h>

CMS_SignerInfo *
CMS_add1_signer(CMS_ContentInfo *cms, X509 *signcert, EVP_PKEY *pkey, const EVP_MD *md, unsigned int flags);

int
CMS_SignerInfo_sign(CMS_SignerInfo *si);

الوصف

CMS_add1_signer() تضيف موقِّعًا بشهادة signcert ومفتاح خاص pkey باستخدام هضم الرسالة md إلى حقل signerInfos في بنية SignedData cms، والتي يجب أن تكون قد حصلت عليها من استدعاء أولي لـ CMS_sign(3) مع تعيين العلامة CMS_PARTIAL، أو يمكن أن تكون بنية SignedData صالحة في حالة إعادة التوقيع.

إذا كان md هو NULL، يتم استخدام الهضم الافتراضي لخوارزمية المفتاح العام لـ pkey.

ما لم يتم تعيين العلامة CMS_REUSE_DIGEST، تظل بنية cms غير مكتملة ويجب إنهاؤها إما عن طريق التدفق (إذا كان ذلك ممكنًا) أو عن طريق استدعاء CMS_final(3).

الغرض الرئيسي من CMS_add1_signer() هو توفير تحكم أدق فوق بنية CMS SignedData حيث تكون الافتراضيات الأبسط لوظيفة CMS_sign(3) غير مناسبة، على سبيل المثال إذا كانت هناك حاجة إلى موقعين متعددين أو خوارزميات هضم غير افتراضية. يمكن أيضًا إضافة سمات جديدة باستخدام بنية CMS_SignerInfo المُرجعة ووظائف أداة سمات CMS أو وظائف طلب إيصال CMS الموقّع.

يمكن تمرير أي من العلامات التالية (مع OR) في المعامل flags:

CMS_REUSE_DIGEST
محاولة نسخ قيمة هضم المحتوى من إحدى هياكل CMS_SignerInfo الموجودة في cms عند إضافة موقِّع آخر. يحدث خطأ إذا تعذر العثور على قيمة هضم مطابقة لنسخها. ستكون بنية cms صالحة ومنهية عند تعيين هذه العلامة.
CMS_PARTIAL
إذا تم تعيين هذه العلامة بالإضافة إلى CMS_REUSE_DIGEST، فلن يتم إنهاء بنية CMS_SignerInfo المُرجعة، لذا يمكن إضافة سمات إضافية. في هذه الحالة، يلزم استدعاء صريح لـ CMS_SignerInfo_sign() لإنهاءها.
CMS_NOCERTS
لا تضف شهادة الموقِّع إلى حقل certificates في cms. لا يزال يتعين توفير شهادة الموقِّع في المعامل signcert. يمكن لهذه العلامة تقليل حجم التوقيع إذا كان يمكن الحصول على شهادة الموقِّع بوسائل أخرى، على سبيل المثال من رسالة موقّعة مسبقًا.
CMS_NOATTR
ترك حقل signedAttrs لبنية CMS_SignedData المُرجعة فارغًا. افتراضيًا، يتم إضافة العديد من سمات CMS SignedAttributes، بما في ذلك وقت التوقيع، ونوع محتوى CMS، وقائمة المدعومة من خوارزميات التشفير في سمة SMIMECapabilities.
CMS_NOSMIMECAP
تجاهل سمة SMIMECapabilities فقط.
CMS_USE_KEYID
استخدم معرف المفتاح الفريد لتحديد شهادات التوقيع. يحدث خطأ إذا كانت شهادة التوقيع لا تحتوي على امتداد معرف المفتاح الفريد. افتراضيًا، يتم استخدام اسم المُصدِر ورقمه التسلسلي بدلاً من ذلك.

إذا كانت سمة SMIMECapabilities موجودة، فإنها تشير إلى دعم الخوارزميات التالية بترتيب الأفضلية: AES 256 بت، AES 192 بت، AES 128 بت، DES ثلاثي، RC2 128 بت، RC2 64 بت، DES، و RC2 40 بت. إذا لم تكن أي من هذه الخوارزميات متاحة، فلن يتم تضمينها.

تقوم وظيفة CMS_SignerInfo_sign() بتوقيع si بشكل صريح. استخدامها الرئيسي هو عندما تم تعيين كلتا العلامتين CMS_REUSE_DIGEST و CMS_PARTIAL في الاستدعاء لـ CMS_add1_signer() التي أنشأت si.

قيم الإرجاع

CMS_add1_signer() تُرجع مؤشرًا داخليًا إلى بنية CMS_SignerInfo الجديدة التي تمت إضافتها للتو أو NULL إذا حدث خطأ.

NAME

CMS_add1_signer - Add a signer to a CMS structure.

SYNOPSIS

#include <openssl/cms.h>

int CMS_add1_signer(CMS_ContentInfo *cms, X509 *cert, EVP_PKEY *pk,
                    const EVP_MD *digest, unsigned int flags);

DESCRIPTION

The CMS_add1_signer() function adds a signer to the CMS structure pointed to by cms. The signer will use the certificate cert and the private key pk to sign the content. The digest algorithm to use is specified by digest. The flags parameter can be used to control the signing process. If flags is 0, default behaviour is used.

The cert and pk are added to the CMS structure using CMS_add_certificate() and CMS_add_recipient_info() respectively. The digest algorithm is set using CMS_set_digest_alg().

RETURN VALUES

Returns 1 on success, 0 on failure.

DIAGNOSTICS

The following errors can occur:

  • Invalid input parameters.
  • Failure to add the certificate to the CMS structure.
  • Failure to add the private key to the CMS structure.
  • Failure to set the digest algorithm.

EXAMPLES

The following example shows how to add a signer to a CMS structure:

CMS_ContentInfo *cms;
X509 *cert;
EVP_PKEY *pk;
const EVP_MD *digest;

cms = CMS_new();
cert = X509_new();
pk = EVP_PKEY_new();
digest = EVP_sha256();

if (CMS_add1_signer(cms, cert, pk, digest, 0) < 0) {
    // Handle error
}
