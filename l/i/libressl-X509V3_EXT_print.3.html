libressl-X509V3_EXT_print(3)

الحزمة: libressl

التراخيص: ISC, custom:OpenSSL

X509V3_EXT_PRINT(3) دليل وظائف المكتبة X509V3_EXT_PRINT(3)

الاسم

X509V3_EXT_print، X509V3_EXT_print_fp — طباعة واضحة لتوسيع X.509

ملخص

مكتبة "libcrypto"؛
#include <openssl/x509v3.h>

int
X509V3_EXT_print(BIO *bio, X509_EXTENSION *ext, unsigned long flags, int indent);

int
X509V3_EXT_print_fp(FILE *file, X509_EXTENSION *ext, int flags, int indent);

الوصف

X509V3_EXT_print() و X509V3_EXT_print_fp() تقوم بفك تشفير ext وطباعة البيانات الموجودة فيه إلى bio أو file، على التوالي، بتنسيق سهل القراءة مع هامش أيسر يتكون من indent حرف مسافة. تعتمد تفاصيل كل من فك التشفير والطباعة على نوع ext.

بالنسبة لمعظم أنواع الامتدادات، يتم فك التشفير بنفس الطريقة التي سيتم بها عن طريق وظيفة الواجهة العامة المناسبة، على سبيل المثال:

بعض وظائف الطباعة العامة ليست موثقة بعد.

إذا كان ext من نوع امتداد غير معروف أو إذا فشل فك التشفير عند استخدام وظيفة فك التشفير للنوع المعني، فإن الإجراء المتخذ يعتمد على الوسيط flags:

  • إذا تم تعيين البت X509V3_EXT_PARSE_UNKNOWN، يتم استدعاء ASN1_parse_dump(3) على البيانات المشفرة بصيغة BER للامتداد، مع تمرير -1 للوسيط dump. وبالتالي، يتم طباعة بعض المعلومات حول ترميز الامتداد وبعض المعلومات حول محتواه الذي تم فك تشفيره، مع الرجوع إلى BIO_dump_indent(3) للمحتوى الذي تم فك تشفيره ما لم تكن هناك طريقة طباعة مخصصة معروفة لأنواع البيانات المعنية. لاحظ أنه حتى إذا كان نوع الامتداد غير معروف، فإن نوع البيانات الذي يستخدمه الامتداد غير المعروف، أو إذا كان نوع البيانات هذا مكونًا، أو من القيم الموجودة فيه، فقد يكون معروفًا، مما قد يسمح بطباعة محتوى حتى الامتداد غير المعروف بشكل منظم أو منظم جزئيًا.
  • إذا تم تعيين البت X509V3_EXT_DUMP_UNKNOWN، يتم استدعاء BIO_dump_indent(3) على البيانات المشفرة بصيغة BER للامتداد دون فك تشفيرها أولاً، وهو عادةً أقل قابلية للقراءة من السابق ولكنه يشكل خطرًا أقل لتخطي أو تمثيل أجزاء من المعلومات بشكل غير صحيح.
  • إذا تم تعيين البت X509V3_EXT_ERROR_UNKNOWN، يتم طباعة السلسلة النصية الثابتة "<Not Supported>" فقط للامتداد غير المعروف أو السلسلة النصية الثابتة "<Parse Error>" فقط إذا فشلت وظائف التحليل، ولكن تعتبر الطباعة ناجحة على أي حال.
  • إذا تم تعيين أكثر من بت واحد من هذه البتات الثلاثة، أو إذا تم تعيين بت في X509V3_EXT_UNKNOWN_MASK غير مذكور أعلاه، فلن تتم طباعة أي شيء، ولكن تعتبر الطباعة ناجحة على أي حال.
  • إذا لم يتم تعيين أي من البتات في X509V3
X509V3_EXT_print(3) — libressl 4.2.1

NAME

X509V3_EXT_print, X509V3_EXT_print_fp — طباعة ملحق شهادة X509v3

SYNOPSIS

#include <openssl/x509v3.h>
int
X509V3_EXT_print(BIO *out, X509_EXTENSION *ext, unsigned long flag,
    int indent);
int
X509V3_EXT_print_fp(FILE *fp, X509_EXTENSION *ext, unsigned long flag,
    int indent);

DESCRIPTION

These functions print an X509 certificate extension to the specified output BIO X509V3_EXT_print() or file pointer X509V3_EXT_print_fp().

The ext argument is the extension to be printed.

The flag argument can be used to control printing. Currently, the following flags are supported:

  • : If the X509V3_EXT_PRINT_INLINE flag is set, then the value of the extension is printed. If this flag is not set, then the OID and the value are printed.

  • : If the X509V3_EXT_IGNORE_CRITICAL flag is set, then critical extensions that are not recognized are ignored. If this flag is not set, then an error message is printed for such extensions.

  • : If the X509V3_EXT_UNKNOWN_MASK flags are set, nothing is printed and printing is considered as failed.

RETURN VALUES

X509V3_EXT_print() and X509V3_EXT_print_fp() return 0 if failure was both detected and considered relevant. Otherwise, 1 is returned, and in general the user cannot tell whether failure simply went undetected, whether the function detected failure but regarded it as irrelevant, or whether printing did indeed succeed.

SEE ALSO

BIO_new(3), X509_EXTENSION_new(3), X509_get0_extensions(3), X509_get_ext(3), X509V3_extensions_print(3)

HISTORY

These functions first appeared in OpenSSL 0.9.2 and have been available since OpenBSD 2.6.

BUGS

These functions lack error handling throughout. When a write operation fails, they will usually ignore the fact that information was omitted from the output and report success to the caller anyway.
