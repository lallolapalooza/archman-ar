الوصف

تقوم هذه الوظائف بقراءة وكتابة الكائنات المشفرة بصيغة PEM، باستخدام نوع PEM name، وأي معلومات header إضافية، والبيانات الخام data بطول len.

PEM هو ترميز المحتوى الثنائي الذي تم تعريفه لأول مرة في IETF RFC 1421. يتكون المحتوى من سلسلة من الأسطر المشفرة بـ base64، محاطة بعلامات بداية/نهاية كل منها في سطر خاص بها. على سبيل المثال:

-----BEGIN PRIVATE KEY-----
MIICdg....
... bhTQ==
-----END PRIVATE KEY-----

قد تظهر سطور ترويسة اختيارية بعد سطر البداية، ويعتمد وجودها على نوع الكائن الذي يتم كتابته أو قراءته.

PEM_write() تكتب إلى الملف fp، بينما PEM_write_bio() تكتب إلى BIO bp. name هو الاسم الذي سيتم استخدامه في العلامة، header هي قيمة الترويسة أو NULL، و data و len تحددان البيانات وطولها.

عادةً ما يكون المخزن المؤقت data النهائي كائن ASN.1 يمكن فك ترميزه باستخدام وظيفة d2i_*() المناسبة للنوع name؛ انظر d2i_X509(3) للحصول على أمثلة.

PEM_read() تقرأ من الملف fp، بينما PEM_read_bio() تقرأ من BIO bp. كلاهما يتجاوزان أي بيانات غير PEM تسبق بداية كائن PEM التالي. عند استرداد كائن بنجاح، يتم إرجاع اسم النوع من "----BEGIN <type>-----" عبر الوسيط name، ويتم إرجاع أي ترويسات تغليف في header، ويتم إرجاع المحتوى الذي تم فك ترميزه بـ base64 وطوله عبر data و len على التوالي. يجب على المستدعي تحرير مؤشرات name و header و data عند عدم الحاجة إليها.

الوظائف المتبقية تم إهمالها لأن صيغة تشفير PEM الأساسية قديمة ويجب تجنبها. تستخدم صيغة تشفير مع وظيفة اشتقاق مفاتيح خاصة بـ OpenSSL، والتي تستخدم MD5 مع عدد تكرارات 1. بدلاً من ذلك، يجب تخزين المفاتيح الخاصة في شكل PKCS#8، مع PBE قوي PKCS#5 v2.0؛ انظر PEM_write_PrivateKey(3) و d2i_PKCS8PrivateKey_bio(3).

PEM_get_EVP_CIPHER_INFO() يمكن استخدامها لتحديد ما إذا كانت data التي تم إرجاعها بواسطة PEM_read() أو PEM_read_bio() مشفرة واسترداد الشفرة و IV المرتبطين. يمرر المستدعي مؤشرًا إلى هيكل من نوع EVP_CIPHER_INFO عبر الوسيط cinfo و header التي تم إرجاعها عبر PEM_read() أو PEM_read_bio(). إذا كان الاستدعاء ناجحًا، يتم إرجاع 1 وتخزين الشفرة و IV في العنوان المشار إليه بواسطة cinfo. عندما تكون الترويسة مشوهة أو غير مدعومة أو عندما تكون الشفرة غير معروفة أو يحدث خطأ داخلي، يتم إرجاع 0.

PEM_do_header() يمكن بعد ذلك استخدامها لفك تشفير البيانات إذا أشارت الترويسة إلى التشفير. الوسيط cinfo هو مؤشر إلى الهيكل الذي تم تهيئته بواسطة استدعاء سابق لـ PEM_get_EVP_CIPHER_INFO(). إذا أشار هذا الهيكل إلى غياب التشفير، فإن PEM_do_header() ترجع بنجاح دون اتخاذ أي إجراء. تُستخدم الوسائط data و len لتمرير البيانات المشفرة التي تم إرجاعها في نفس الوسائط من الاستدعاء السابق لـ PEM_read() أو PEM_read_bio() ولإخراج البيانات المفككة التشفير.

تُستخدم وظيفة الاستدعاء cb للحصول على password التشفير؛ إذا كان cb هو NULL، فسيتم استخدام PEM_def_callback() بدلاً من ذلك. يجب أن يكون المخزن المؤقت password بطول size على الأقل. ما لم يكن userdata هو NULL، تتجاهل PEM_def_callback() الوسيط verify وتنسخ السلسلة المنتهية بـ NUL userdata إلى password دون بايت NUL نهائي، وتقوم باختصار النسخ بصمت إلى size بايت كحد أقصى. إذا كان userdata هو NULL، فإن PEM_def_callback() تطالب المستخدم بكلمة المرور عن طريق إيقاف عرض الأحرف عن طريق استدعاء EVP_read_pw_string_min(3) داخليًا. في هذه الحالة، يتم تقليل size بصمت إلى BUFSIZ كحد أقصى و size بايت كحد أقصى - 1 يتم قبولها من المستخدم ونسخها إلى مخزن السلاسل المؤقت password. قد تستخدم وظيفة الاستدعاء cb التي يوفرها التطبيق userdata لغرض مختلف عن PEM_def_callback()، على سبيل المثال، كبيانات مساعدة لاستخدامها أثناء الحصول على كلمة المرور. على سبيل المثال، قد يمرر تطبيق واجهة رسومية مقبض نافذة. إذا كان علم verify غير صفري، تتم مطالبة المستخدم مرتين بكلمة المرور لتجنب الأخطاء المطبعية

libressl(7) — PEM_read — libressl 4.2.1

PEM_read

PEM_read, PEM_read_bio, PEM_get_EVP_CIPHER_INFO, PEM_do_header, PEM_def_callback - PEM file input

SYNOPSIS

#include <openssl/pem.h>

int PEM_read(FILE *fp, char **name, char **header, unsigned char **data,
    long *len);
int PEM_read_bio(BIO *bp, char **name, char **header, unsigned char **data,
    long *len);

int PEM_get_EVP_CIPHER_INFO(const char *header, const char *name,
    EVP_CIPHER_INFO *cipher_info);
int PEM_do_header(BIO *bp, char **name, char **header, unsigned char **data,
    long *len);

int PEM_def_callback(int operation, const char *fmt, ...);
int PEM_get_callback(void);
void PEM_set_callback(int (*cb)(int, const char *, ...));
int PEM_sign(BIO *bio, const char *name, const char *passwd,
    const unsigned char *sig, int siglen);
int PEM_Seal(BIO *bio, BIO *out, BIO *keyin, int size, char **nm, char **hdr,
    unsigned char **data, long *len);
int PEM_SealFinalize(BIO *bio, BIO *out, BIO *keyin, BIO *sigin,
    const unsigned char *sig, int siglen);
int PEM_cleanup_remove_all_empty_objects(void);
int PEM_cleanup_all_empty_objects(void);

DESCRIPTION

PEM_read() and PEM_read_bio() read the next PEM formatted object from the file pointer fp or the BIO bp respectively. If the PEM object is encrypted, it is decrypted using the supplied password. The password is obtained using the callback set by PEM_set_callback(3). If no callback is set, then the default callback function PEM_def_callback() is used.

The name of the PEM object (e.g. "ENCRYPTED PRIVATE KEY") is stored in the location pointed to by name. The PEM header lines are stored in the location pointed to by header. The PEM data is stored in the location pointed to by data, and its length is stored in len.

The caller is responsible for freeing the memory pointed to by name, header, and data using OPENSSL_free(3).

PEM_get_EVP_CIPHER_INFO() processes the PEM object header line and determines the encryption algorithm and key information. The header is the first header line, e.g. "DEK-Info: AES-128-CBC, ...". The name is the PEM object name, e.g. "ENCRYPTED PRIVATE KEY". The resulting cipher information is stored in cipher_info.

PEM_do_header() is a convenience function that calls PEM_get_EVP_CIPHER_INFO() and then decrypts the PEM object data. The decryption key is obtained using the password callback.

PEM_def_callback() is the default password callback function. It prompts the user for the password. The operation parameter is not used. The fmt parameter is used to print a prompt message. The password is read from standard input.

If userdata is not NULL, then it is passed to the user-provided callback. This is typically a pointer to an int containing the password. PEM_def_callback() will use this if available, otherwise it prompts the user.

The function PEM_get_callback() returns the current password callback function, and PEM_set_callback() sets a new password callback function.

The functions PEM_sign(), PEM_Seal(), PEM_SealFinalize(), PEM_cleanup_remove_all_empty_objects(), and PEM_cleanup_all_empty_objects() are not directly related to reading PEM objects, but are related to PEM file manipulation.

The flag `PEM_FLAG_SECURE` in the structure pointed to by cipher_info is set if the decryption key derivation process is considered secure. This typically means that the key is derived from a password using a key derivation function, and that it is checked that both inputs agree. This flag is not set by PEM_do_header() nor by other read functions, but it is typically set by write functions.

If the data is a priori known to not be encrypted, then neither PEM_get_EVP_CIPHER_INFO() nor PEM_do_header() need to be called.

RETURN VALUES

PEM_read() and PEM_read_bio() return 1 on success or 0 on failure. The latter includes the case when no more PEM objects remain in the input file. To distinguish end of file from more serious errors, the caller must peek at the error stack and check for PEM_R_NO_START_LINE, which indicates that no more PEM objects were found. See ERR_peek_last_error(3) and ERR_GET_REASON(3).

PEM_get_EVP_CIPHER_INFO() and PEM_do_header() return 1 on success or 0 on failure. The data is likely meaningless if these functions fail.

PEM_def_callback() returns the number of bytes stored into buf or a negative value on failure, and cb is expected to behave in the same way. If userdata is NULL, PEM_def_callback() fails if num is less than 5 or if an error occurs trying to prompt the user for the password. Otherwise, it fails when num is negative. The details of the circumstances that cause cb to fail may differ.

HISTORY

PEM_write(), PEM_read(), and PEM_do_header() appeared in SSLeay 0.4 or earlier. PEM_get_EVP_CIPHER_INFO() first appeared in SSLeay 0.5.1. PEM_write_bio() and PEM_read_bio() first appeared in SSLeay 0.6.0. These functions have been available since OpenBSD 2.4.

PEM_def_callback() first appeared in OpenSSL 0.9.7 and has been available since OpenBSD 3.2.
