الحزمة: libressl

التراخيص: ISC, custom:OpenSSL

SSL_CTX_SET_ALPN_SELECT_CB(3) دليل وظائف المكتبة SSL_CTX_SET_ALPN_SELECT_CB(3)

الاسم

SSL_CTX_set_alpn_protos، SSL_set_alpn_protos، SSL_CTX_set_alpn_select_cb، SSL_select_next_proto، SSL_get0_alpn_selected — معالجة التفاوض على بروتوكول طبقة التطبيق (ALPN)

الملخص

مكتبة “libssl” libcrypto
#include <openssl/ssl.h>

int
SSL_CTX_set_alpn_protos(SSL_CTX *ctx, const unsigned char *protos, unsigned int protos_len);

int
SSL_set_alpn_protos(SSL *ssl, const unsigned char *protos, unsigned int protos_len);

void
SSL_CTX_set_alpn_select_cb(SSL_CTX *ctx, int (*cb)(SSL *ssl, const unsigned char **out, unsigned char *outlen, const unsigned char *in, unsigned int inlen, void *arg), void *arg);

int
SSL_select_next_proto(unsigned char **out, unsigned char *outlen, const unsigned char *peer_list, unsigned int peer_list_len, const unsigned char *supported_list, unsigned int supported_list_len);

void
SSL_get0_alpn_selected(const SSL *ssl, const unsigned char **data, unsigned int *len);

الوصف

SSL_CTX_set_alpn_protos() و SSL_set_alpn_protos() يستخدمان بواسطة العميل لتعيين قائمة البروتوكولات المتاحة للتفاوض. يجب أن تكون protos بتنسيق قائمة البروتوكولات، الموضح أدناه. يتم تحديد طول protos في protos_len.

SSL_CTX_set_alpn_select_cb() يعين دالة الاستدعاء التطبيقية cb التي يستخدمها الخادم لاختيار البروتوكول الذي سيتم استخدامه للاتصال الوارد. عندما تكون cb NULL، لا يتم استخدام ALPN. القيمة arg هي مؤشر يتم تمريره إلى دالة استدعاء التطبيق.

cb هي دالة الاستدعاء التي يحددها التطبيق. المعلمات in، inlen هي متجه بتنسيق قائمة البروتوكولات. يجب تعيين قيمة المتجه out، outlen إلى قيمة بروتوكول واحد تم اختياره من المتجه in، inlen. قد يشير المخزن المؤقت out مباشرة إلى in، أو إلى مخزن مؤقت يدوم بعد المصافحة. المعلمة arg هي المؤشر الذي تم تعيينه عبر SSL_CTX_set_alpn_select_cb().

SSL_select_next_proto() هي دالة مساعدة تستخدم لاختيار البروتوكولات. من المتوقع استدعاء هذه الدالة من دالة استدعاء التطبيق cb. إذا أعادت SSL_select_next_proto() OPENSSL_NPN_NO_OVERLAP، فيجب على cb تجاهل out والفشل عن طريق إعادة SSL_TLSEXT_ERR_ALERT_FATAL. يجب أن تكون بيانات البروتوكول في peer_list، peer_list_len و supported_list، supported_list_len قائمتين غير فارغتين، مرمزة بشكل صحيح بتنسيق قائمة البروتوكولات الموضح أدناه. يتم تحديد العنصر الأول في peer_list الذي يتطابق مع عنصر في supported_list، ويتم إرجاعه في out، outlen. سيشير المتجه out إما إلى peer_list أو supported_list، لذا يجب عدم تعديله ونسخه فورًا. إذا لم يتم العثور على تطابق، يتم إرجاع العنصر الأول في supported_list في out، outlen.

SSL_get0_alpn_selected() يعيد مؤشرًا إلى البروتوكول المحدد في data بطول len. لا ينتهي بصفر (NUL-terminated). يتم تعيين data إلى NULL ويتم تعيين len إلى 0 إذا لم يتم تحديد أي بروتوكول. يجب عدم تحرير data.

يجب أن تكون قوائم البروتوكولات بتنسيق الأسلاك (wire-format)، والتي يتم تعريفها كمتجه من السلاسل النصية بايت غير فارغة، يسبقها بادئة طول 8 بت. البايت ذو البادئة الطول غير مدرج في الطول. كل سلسلة نصية محدودة بـ 255 بايت. طول السلسلة النصية 0 غير صالح. طول المتجه ليس في المتجه نفسه، بل في متغير منفصل.

على سبيل المثال:

const unsigned char *vector = "\x06" "spdy/1" "\x08" "http/1.1";
unsigned int length = strlen(vector);

يتم تنفيذ دالة استدعاء ALPN بعد دالة استدعاء اسم الخادم؛ حيث قد تقوم دالة استدعاء اسم الخادم بتحديث SSL_CTX، وبالتالي، دالة استدعاء ALPN.

إذا لم يتم اقتراح ALPN في ClientHello، فلن يتم استدعاء دالة استدعاء ALPN.

قيم الإرجاع

SSL_CTX_set_alpn_protos() و SSL_set_alpn_protos() تعيد 0 عند النجاح أو قيمة غير صفرية عند الفشل. تحذير: هذه الوظائف تعكس اصطلاح قيمة الإرجاع.

SSL_select_next_proto() تعيد أحد ما يلي:

OPENSSL_NPN_NEGOTIATED
تم العثور على تطابق ويتم إرجاعه في out، outlen.
OPENSSL_NPN_NO_OVERLAP
لم يتم العثور على تطابق. يتم إرجاع العنصر الأول في supported_list، supported_list_len في out، outlen.

يجب على دالة استدعاء اختيار ALPN cb إعادة أحد ما يلي:

SSL_TLSEXT_ERR_OK
تم تحديد بروتوكول ALPN.
SSL_TLSEXT_ERR_ALERT_FATAL
لم يكن هناك تداخل بين القائمة المقدمة من العميل وتكوين الخادم.
SSL_TLSEXT_ERR_NOACK
لم يتم تحديد بروتوكول ALPN، على سبيل المثال، لأنه لم يتم تكوين بروتوكولات ALPN لهذا الاتصال.

libressl-SSL_CTX_set_alpn_select_cb(3)

NAME

SSL_CTX_set_alpn_select_cb, SSL_CTX_set_alpn_protos, SSL_provide_server_hello_pipe, SSL_get0_alpn_selected - Application Layer Protocol Negotiation (ALPN)

SYNOPSIS

#include <openssl/ssl.h>

typedef int (*alpn_select_cb)(SSL *ssl, const unsigned char **out,
    unsigned char *outlen, const unsigned char *in, unsigned int inlen,
    void *arg);

int
SSL_CTX_set_alpn_select_cb(SSL_CTX *ctx, alpn_select_cb callback, void *arg);

int
SSL_CTX_set_alpn_protos(SSL_CTX *ctx, const unsigned char *protos,
    unsigned int protoslen);

int
SSL_provide_server_hello_pipe(SSL *ssl, const unsigned char *pipe,
    unsigned int pipelen);

int
SSL_get0_alpn_selected(SSL *ssl, const unsigned char **out, unsigned int *outlen);

DESCRIPTION

The Application Layer Protocol Negotiation (ALPN) extension for Transport Layer Security (TLS) allows a server to indicate which protocols it supports, and to select one of those protocols with the client. It is described in RFC 7301.

ALPN is implemented as a TLS extension. It is used during the TLS handshake. Both client and server must support ALPN for it to be used. A client indicates its supported protocols by sending an ALPN extension in its ClientHello message. A server responds by sending an ALPN extension in its ServerHello message, indicating the protocol selected from the client's list.

The selected protocol is then communicated to the application, which may use it to select the appropriate protocol handler.

ALPN is implemented using the following functions:

SSL_CTX_set_alpn_select_cb
Registers a callback function callback to be invoked when a ServerHello message is to be sent. This function is called on the server side. The arg parameter is an application-specific value that is passed to the callback.
SSL_CTX_set_alpn_protos
Sets the list of protocols supported by the server. This function should be called on the server side, typically before a connection is accepted. The protos parameter is a pointer to a list of protocols, where each protocol is prefixed by its length. For example, a list of "http/1.1" and "spdy/3.1" would be represented as "\x08http/1.1\x08spdy/3.1". The protoslen parameter is the total length of the protocol list.
SSL_provide_server_hello_pipe
Provides the ALPN extension data for the ServerHello message. This function should be called on the server side, after the ClientHello has been received and parsed, but before the ServerHello is sent. The pipe parameter is a pointer to the ALPN extension data, and pipelen is its length. This function is typically used internally by libssl when using SSL_CTX_set_alpn_select_cb.
SSL_get0_alpn_selected
Retrieves the selected ALPN protocol. This function can be called by both client and server after the handshake is complete. The selected protocol is returned in out and its length in outlen. The returned pointer is valid only as long as the ssl object is valid.

The alpn_select_cb callback function should iterate through the protocols provided by the client (in, inlen) and find the first protocol that matches one of the server's supported protocols. If a match is found, the callback should set out and outlen to point to the selected protocol and its length, and return SSL_TLSEXT_ERR_OK. If no match is found, or if the server does not support ALPN, the callback should return SSL_TLSEXT_ERR_NO_OVERLAP.

If the callback returns SSL_TLSEXT_ERR_NO_OVERLAP, the server will send an empty ALPN extension in the ServerHello, indicating that no protocol overlap was found. This will result in a handshake failure if ALPN was mandatory.

RETURN VALUES

SSL_CTX_set_alpn_select_cb, SSL_CTX_set_alpn_protos, and SSL_provide_server_hello_pipe return 1 on success, and 0 on failure.

SSL_get0_alpn_selected returns 1 if a protocol was selected, and 0 otherwise.

The alpn_select_cb callback should return one of the following values:

SSL_TLSEXT_ERR_OK
A protocol was successfully selected.
SSL_TLSEXT_ERR_NO_OVERLAP
No protocol overlap was found.
SSL_TLSEXT_ERR_ALERT_FATAL
A fatal alert should be sent.
SSL_TLSEXT_ERR_ALERT_WARNING
A warning alert should be sent.

SEE ALSO

SSL_CTX_new(3), SSL_new(3), SSL_set_accept_state(3), SSL_set_connect_state(3), SSL_use_certificate(3)

STANDARDS

RFC 7301: Application Layer Protocol Negotiation Extension for Transport Layer Security (TLS)

HISTORY

The ALPN API was added in OpenSSL 1.0.2. It has been available since OpenBSD 5.7.

CAVEATS

The fallback to the first supported protocol in SSL_select_next_proto() comes from the opportunistic fallback mechanism in the NPN extension. This behavior does not make sense for ALPN, where missing protocol overlap should result in a handshake failure. To avoid accidental selection of a protocol that the server does not support, it is recommended to pass the locally configured protocols as second pair of protocols in the ALPN callback.

BUGS

The out argument of SSL_select_next_proto() should have been const.
