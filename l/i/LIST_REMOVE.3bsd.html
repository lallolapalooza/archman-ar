HISTORY

The tail queue macros first appeared in 4.4BSD.

BUGS

The macro TAILQ_INSERT_HEAD takes a TAILQ_HEAD pointer as its first argument, while TAILQ_INSERT_TAIL, TAILQ_REMOVE, and TAILQ_SWAP take a TAILQ_HEAD pointer as their first argument. This inconsistency is intentional, but may be surprising. Similarly, TAILQ_INSERT_AFTER takes a TAILQ_HEAD pointer as its first argument, while TAILQ_INSERT_BEFORE takes a TYPE pointer as its first argument.

The TAILQ_PREV macro requires that HEADNAME be passed as the second argument. This is required because the macro is implemented using a forward declaration of the HEADNAME structure, and the compiler needs to know the size of the structure.

The TAILQ_SWAP macro requires that TYPE be passed as the third argument. This is required because the macro is implemented using a forward declaration of the TYPE structure, and the compiler needs to know the size of the structure.

DESCRIPTION

The TAILQ_HEAD, TAILQ_ENTRY, and TAILQ_HEAD_INITIALIZER macros define and declare the data structures used by the tail queue macros. The tail queue macros provide a mechanism for implementing tail queues, which are doubly-linked lists that can be traversed forwards and backwards, and provide constant time insertion and deletion at both ends of the list.

TAILQ_HEAD(HEADNAME, TYPE) declares a structure named HEADNAME which will contain a pointer to the first element in the tail queue, and a pointer to the last element in the tail queue. TYPE is the name of the data structure that will be used for the elements in the tail queue.

TAILQ_ENTRY(TYPE) declares a structure named TYPE whose name is concatenated with _entry. This structure contains two pointers, one to the next element in the tail queue, and one to the previous element in the tail queue.

TAILQ_HEAD_INITIALIZER returns an initializer for an empty tail queue.

TAILQ_INIT(TAILQ_HEAD *head) initializes the tail queue pointed to by head.

TAILQ_INSERT_AFTER(TAILQ_HEAD *head, TYPE *listelm, TYPE *elm, TAILQ_ENTRY NAME) inserts the new element elm after the existing element listelm in the tail queue pointed to by head. The TAILQ_ENTRY NAME argument is the name of the entry field within the TYPE structure.

TAILQ_INSERT_BEFORE(TYPE *listelm, TYPE *elm, TAILQ_ENTRY NAME) inserts the new element elm before the existing element listelm. The TAILQ_ENTRY NAME argument is the name of the entry field within the TYPE structure.

TAILQ_INSERT_HEAD(TAILQ_HEAD *head, TYPE *elm, TAILQ_ENTRY NAME) inserts the new element elm at the head of the tail queue pointed to by head. The TAILQ_ENTRY NAME argument is the name of the entry field within the TYPE structure.

TAILQ_INSERT_TAIL(TAILQ_HEAD *head, TYPE *elm, TAILQ_ENTRY NAME) inserts the new element elm at the tail of the tail queue pointed to by head. The TAILQ_ENTRY NAME argument is the name of the entry field within the TYPE structure.

TAILQ_LAST(TAILQ_HEAD *head, HEADNAME) returns a pointer to the last element in the tail queue pointed to by head. HEADNAME is the name of the structure that contains the tail queue.

TAILQ_NEXT(TYPE *elm, TAILQ_ENTRY NAME) returns a pointer to the next element in the tail queue after the element elm. The TAILQ_ENTRY NAME argument is the name of the entry field within the TYPE structure.

TAILQ_PREV(TYPE *elm, HEADNAME, TAILQ_ENTRY NAME) returns a pointer to the previous element in the tail queue before the element elm. HEADNAME is the name of the structure that contains the tail queue. The TAILQ_ENTRY NAME argument is the name of the entry field within the TYPE structure.

TAILQ_REMOVE(TAILQ_HEAD *head, TYPE *elm, TAILQ_ENTRY NAME) removes the element elm from the tail queue pointed to by head. The TAILQ_ENTRY NAME argument is the name of the entry field within the TYPE structure.

TAILQ_SWAP(TAILQ_HEAD *head1, TAILQ_HEAD *head2, TYPE, TAILQ_ENTRY NAME) swaps the contents of the tail queues pointed to by head1 and head2. TYPE is the name of the data structure used for the elements in the tail queue. The TAILQ_ENTRY NAME argument is the name of the entry field within the TYPE structure.

قوائم نهاية الذيل المرتبطة بشكل مفرد

يتم تعريف قائمة نهاية ذيل مرتبطة بشكل مفرد بواسطة الماكرو STAILQ_HEAD. تحتوي هذه البنية على مؤشرين: واحد للعنصر الأول في الطابور والآخر للعنصر الأخير في الطابور. ترتبط العناصر بشكل مفرد لتقليل المساحة وعبء معالجة المؤشرات، على الرغم من أن التكلفة هي O(n) للعناصر التعسفية. يمكن إضافة عناصر جديدة إلى طابور نهاية الذيل بعد عنصر موجود، أو إلى مقدمة طابور نهاية الذيل، أو إلى نهاية طابور نهاية الذيل. يتم تعريف بنية STAILQ_HEAD على النحو التالي:

STAILQ_HEAD(HEADNAME, TYPE) head;

حيث HEADNAME هو اسم البنية المراد تعريفها و TYPE هو نوع عناصر الطابور. يمكن لاحقًا الإعلان عن عنوان المؤشر إلى مقدمة الطابور كالتالي:

struct HEADNAME *headp;

(أسماء head و headp يمكن اختيارها من قبل المستخدم.)

الماكرو STAILQ_HEAD_INITIALIZER يقيم كمنهي للطابور head.

الماكرو STAILQ_CONCAT يربط طابور نهاية الذيل الموجه بواسطة head2 بنهاية طابور نهاية الذيل الموجه بواسطة head1، مع إزالة جميع العناصر من الطابور الأول.

الماكرو STAILQ_EMPTY يقيم بصحيح إذا لم تكن هناك عناصر في طابور نهاية الذيل.

الماكرو STAILQ_ENTRY يعرّف بنية تربط عناصر طابور نهاية الذيل.

الماكرو STAILQ_FIRST يعيد العنصر الأول في طابور نهاية الذيل أو NULL إذا كان الطابور فارغًا.

الماكرو STAILQ_FOREACH يجتاز طابور نهاية الذيل المشار إليه بواسطة head في الاتجاه الأمامي، مع تعيين كل عنصر إلى var.

الماكرو STAILQ_FOREACH_FROM يتصرف بنفس طريقة STAILQ_FOREACH عندما يكون var هو NULL، وإلا فإنه يعامل var كعنصر تم العثور عليه مسبقًا في طابور نهاية الذيل ويبدأ الحلقة من var بدلاً من العنصر الأول في طابور نهاية الذيل المشار إليه بواسطة head.

الماكرو STAILQ_FOREACH_SAFE يجتاز طابور نهاية الذيل المشار إليه بواسطة head في الاتجاه الأمامي، مع تعيين كل عنصر إلى var. ومع ذلك، على عكس STAILQ_FOREACH()، يُسمح هنا بحذف var وتحريره بأمان داخل الحلقة دون التدخل في مسار الاجتياز.

الماكرو STAILQ_FOREACH_FROM_SAFE يتصرف بنفس طريقة STAILQ_FOREACH_SAFE عندما يكون var هو NULL، وإلا فإنه يعامل var كعنصر تم العثور عليه مسبقًا في طابور نهاية الذيل ويبدأ الحلقة من var بدلاً من العنصر الأول في طابور نهاية الذيل المشار إليه بواسطة head.

الماكرو STAILQ_INIT يهيئ طابور نهاية الذيل المشار إليه بواسطة head.

الماكرو STAILQ_INSERT_HEAD يدرج العنصر الجديد elm في مقدمة طابور نهاية الذيل.

الماكرو STAILQ_INSERT_TAIL يدرج العنصر الجديد elm في نهاية طابور نهاية الذيل.

الماكرو STAILQ_INSERT_AFTER يدرج العنصر الجديد elm بعد العنصر listelm.

الماكرو STAILQ_LAST يعيد العنصر الأخير في طابور نهاية الذيل. إذا كان طابور نهاية الذيل فارغًا، فإن القيمة المعادة هي NULL.

الماكرو STAILQ_NEXT يعيد العنصر التالي في طابور نهاية الذيل، أو NULL إذا كان هذا العنصر هو الأخير.

الماكرو STAILQ_REMOVE_AFTER يزيل العنصر الذي يلي elm من طابور نهاية الذيل. على عكس STAILQ_REMOVE، فإن هذا الماكرو لا يجتاز الطابور بأكمله.

الماكرو STAILQ_REMOVE_HEAD يزيل العنصر الموجود في مقدمة طابور نهاية الذيل. لتحسين الكفاءة، يجب على العناصر التي سيتم إزالتها من طابور نهاية الذيل استخدام هذا الماكرو صراحةً بدلاً من الماكرو العام STAILQ_REMOVE.

الماكرو STAILQ_REMOVE يزيل العنصر elm من طابور نهاية الذيل. يجب تجنب استخدامه لأنه يجتاز القائمة بأكملها. يجب استخدام طابور نهاية ذيل مزدوج الارتباط إذا كان هذا الماكرو ضروريًا في مسارات التعليمات البرمجية ذات الاستخدام العالي أو للعمل على قوائم نهاية ذيل طويلة.

الماكرو STAILQ_SWAP يبادل محتويات head1 و head2.

					/* اجتياز إلى الأمام. */
SLIST_FOREACH(np, &head, entries)
	np-> ...
					/* اجتياز آمن إلى الأمام. */
SLIST_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	SLIST_REMOVE(&head, np, entry, entries);
	free(np);

					/* إفراغ طابور نهاية الذيل. */

	n1 = STAILQ_FIRST(&head);
	STAILQ_REMOVE_HEAD(&head, entries);
	free(n1);

					/* إفراغ أسرع لطابور نهاية الذيل. */
n1 = STAILQ_FIRST(&head);
while (n1 != NULL) {
	n2 = STAILQ_NEXT(n1, entries);
	free(n1);
	n1 = n2;
}

التشخيص

عند تصحيح أخطاء queue(3)، قد يكون من المفيد تتبع التغييرات في قائمة الانتظار. لتمكين التتبع، عرف الماكرو QUEUE_MACRO_DEBUG_TRACE في وقت الترجمة.

قد يكون من المفيد أيضًا إتلاف المؤشرات التي تم فصلها من قائمة انتظار، لاكتشاف الاستخدام بعد الإزالة. لتمكين إتلاف المؤشرات، عرف الماكرو QUEUE_MACRO_DEBUG_TRASH في وقت الترجمة. يعيد الماكرو QMD_IS_TRASHED(void *ptr) القيمة true إذا تم إتلاف ptr بواسطة الخيار QUEUE_MACRO_DEBUG_TRASH.
