الوصف

CMAC هو خوارزمية رمز مصادقة رسالة يمكنها استخدام تشفير كتلة اعتباطي باستخدام مفتاح متماثل.

صفحة الدليل الحالية تصف الدوال منخفضة المستوى التي تنفذ CMAC. بدلاً من استخدام هذه الدوال مباشرة، تقوم برامج التطبيق عادةً باستدعاء EVP_PKEY_new_CMAC_key(3) ثم تمرر كائن EVP_PKEY الناتج إلى EVP_DigestSignInit(3).

واجهة برمجة تطبيقات CMAC موجهة للكائنات. يتطلب حساب رمز مصادقة الرسالة كائن CMAC_CTX. عادةً، يجب استدعاء الدوال CMAC_CTX_new()، CMAC_Init()، CMAC_Update()، CMAC_Final()، و CMAC_CTX_free() بهذا الترتيب.

CMAC_CTX_new() يخصص كائن CMAC_CTX جديد، ويهيئ كائن EVP_CIPHER_CTX المضمن، ويضع علامة على الكائن نفسه بأنه غير مهيأ.

CMAC_Init() يختار تشفير الكتلة المحدد cipher للاستخدام بواسطة ctx. توجد الدوال للحصول على كائنات EVP_CIPHER مناسبة مدرجة في قسم قائمة التشفير في صفحة دليل EVP_EncryptInit(3). ما لم يكن key يساوي NULL، فإن CMAC_Init() يهيئ أيضًا ctx للاستخدام مع المفتاح المتماثل المحدد key الذي طوله key_len بايت. على وجه الخصوص، يقوم بحساب وتخزين المفاتيح الفرعية الاثنين داخليًا ويهيئ ctxCMAC_Update(). يتم تجاهل وسيطة engine. يوصى بتمرير NULL.

إذا كان ctxCMAC_Init() مرة أخرى مع تعيين كل من key و cipher إلى NULL وتعيين key_len إلى 0. في هذه الحالة، يتم تجاهل أي بيانات تم معالجتها بالفعل و إعادة تهيئة ctx

CMAC_Update() يعالج بايتات in_len من بيانات الإدخال المشار إليها بواسطة in_data. اعتمادًا على عدد بايتات الإدخال المخزنة مؤقتًا بالفعل في ctxin_len، وعلى حجم الكتلة، قد يقوم هذا بتشفير صفر أو أكثر من الكتل. ما لم يكن in_lenctx. يمكن استدعاء CMAC_Update() عدة مرات لربط عدة أجزاء من بيانات الإدخال بأحجام مختلفة.

CMAC_Final() يخزن طول رمز مصادقة الرسالة بالبايت، والذي يساوي حجم كتلة التشفير، في *out_len. ما لم يكن out_mac يساوي NULL، فإنه يقوم بتشفير الكتلة الأخيرة، مع حشوها إذا لزم الأمر، وينسخ رمز مصادقة الرسالة الناتج إلى out_mac. المتصل مسؤول عن توفير مخزن مؤقت بحجم كافٍ.

CMAC_CTX_copy() يقوم بنسخ عميق لـ in_ctx المهيأ بالفعل إلى out_ctx.

CMAC_CTX_cleanup() يصفر كلا المفتاحين الفرعيين وجميع البيانات المؤقتة في ctx وفي كائن EVP_CIPHER_CTX المضمن، ويزيل تخصيص كل الذاكرة المخصصة المرتبطة به، باستثناء ctxCMAC_Init() لاحقة.

CMAC_CTX_free() يستدعي CMAC_CTX_cleanup()، ثم يزيل تخصيص ctx نفسه. إذا كان ctxNULL، فلن يحدث شيء.

قيم الإرجاع

CMAC_CTX_new() ترجع كائن السياق الجديد أو NULL في حالة الفشل. تنجح ما لم تنفد الذاكرة.

CMAC_Init()، CMAC_Update()، CMAC_Final()، و CMAC_CTX_copy() ترجع 1 عند النجاح أو 0 عند الفشل. تفشل CMAC_Init() إذا فشلت تهيئة كائن EVP_CIPHER_CTX المضمن. تفشل الدوال الأخرى إذا كان in_ctx غير مهيأ. تفشل أيضًا CMAC_Update() و CMAC_Final() إذا فشل تشفير كتلة، و CMAC_CTX_copy() إذا فشل نسخ كائن EVP_CIPHER_CTX المضمن، مما قد يحدث على سبيل المثال عند نفاد الذاكرة.

CMAC_CTX_get0_cipher_ctx() ترجع مؤشرًا داخليًا إلى كائن EVP_CIPHER_CTX المضمن في ctx.

الأخطاء

رمز CMAC نفسه لا يستخدم إطار عمل <openssl/err.h>، لذلك بشكل عام، لا يمكن معرفة أسباب الفشل باستخدام ERR_get_error(3). ومع ذلك، نظرًا لأنه يتم استخدام دوال EVP_EncryptInit(3) داخليًا، فقد تظل هناك إدخالات تُضاف إلى مكدس الأخطاء في بعض حالات الفشل.

NAME

CMAC_Init, CMAC_Update, CMAC_Final, CMAC_OneShot, CMAC_CTX_new, CMAC_CTX_free, CMAC_CTX_cleanup, CMAC_digest, CMAC_get_key — CMAC message authentication code algorithm

SYNOPSIS

#include <openssl/cmac.h>

int CMAC_Init(CMAC_CTX *ctx, const unsigned char *key, EVP_CIPHER_CTX *cipher_ctx);
int CMAC_Update(CMAC_CTX *ctx, const unsigned char *data, size_t len);
int CMAC_Final(CMAC_CTX *ctx, unsigned char *md, unsigned int *len);
int CMAC_OneShot(EVP_CIPHER_CTX *cipher_ctx, const unsigned char *key, size_t keylen, const unsigned char *in, size_t inlen, unsigned char *out, unsigned int *outlen);
CMAC_CTX *CMAC_CTX_new(void);
void CMAC_CTX_free(CMAC_CTX *ctx);
int CMAC_CTX_cleanup(CMAC_CTX *ctx);
int CMAC_digest(CMAC_CTX *ctx, unsigned char *md, unsigned int *len);
const EVP_CIPHER *CMAC_get_key(CMAC_CTX *ctx);

DESCRIPTION

The CMAC algorithm, also known as the Cipher-based Message Authentication Code, is an algorithm for computing a message authentication code using a block cipher. It is a type of MAC (Message Authentication Code).

CMAC uses a block cipher such as AES to generate a MAC for a given message. The MAC can be used to verify the integrity and authenticity of the message. It can also be used for keyed hash functions.

The following functions are provided:

CMAC_Init
Initializes the CMAC_CTX structure. The key parameter is the secret key to be used for the CMAC calculation. The cipher_ctx parameter is an EVP_CIPHER_CTX structure that will be used by CMAC. It is recommended to initialize cipher_ctx using EVP_EncryptInit(3) before passing it to CMAC_Init.
CMAC_Update
Updates the CMAC calculation with the message data specified by data and len.
CMAC_Final
Calculates the CMAC and stores it in the buffer md. The maximum size of the buffer is specified by len. After the call, len is updated to the actual size of the CMAC.
CMAC_OneShot
This function performs a CMAC calculation in a single call. It takes the block cipher context cipher_ctx, the key key with length keylen, the message data in with length inlen, and an output buffer out with maximum size outlen. The actual size of the output is stored in outlen. This function internally uses EVP_EncryptInit, EVP_EncryptUpdate, and EVP_EncryptFinal_ex.
CMAC_CTX_new
Allocates and initializes a new CMAC_CTX structure.
CMAC_CTX_free
Frees the CMAC_CTX structure.
CMAC_CTX_cleanup
Cleans up the CMAC_CTX structure. This is equivalent to calling CMAC_Final and then clearing the context. It should be called before freeing the context with CMAC_CTX_free.
CMAC_digest
This function is deprecated. Use CMAC_Final instead.
CMAC_get_key
Returns the EVP_CIPHER used by the CMAC context.

RETURN VALUES

The functions CMAC_Init, CMAC_Update, and CMAC_Final return 1 on success, and 0 on failure.

The function CMAC_OneShot returns 1 on success, and 0 on failure.

The function CMAC_CTX_new returns a pointer to a new CMAC_CTX structure, or NULL if the allocation fails.

The function CMAC_CTX_cleanup returns 1 on success, and 0 on failure.

The function CMAC_digest returns 1 on success, and 0 on failure.

The function CMAC_get_key returns a pointer to the EVP_CIPHER structure, or NULL if an error occurs.

ERRORS

The cause of failure can be obtained from the error stack.

STANDARDS
