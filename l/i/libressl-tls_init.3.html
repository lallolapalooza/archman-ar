libressl-tls_init(3)

الحزمة: libressl

التراخيص: ISC, custom:OpenSSL

TLS_INIT(3) دليل وظائف المكتبة TLS_INIT(3)

الاسم

tls_init, tls_config_new, tls_config_free, tls_config_error — تهيئة واجهة برمجة تطبيقات عميل وخادم TLS

الملخص

مكتبة “libtls” libssl libcrypto
#include <tls.h>

int
tls_init(void);

struct tls_config *
tls_config_new(void);

void
tls_config_free(struct tls_config *config);

const char *
tls_config_error(struct tls_config *config);

الوصف

تقوم عائلة الوظائف tls بإنشاء قناة اتصال آمنة باستخدام بروتوكول مقبس TLS. يتم دعم كل من العملاء والخوادم.

تقوم الوظيفة tls_init() بتهيئة هياكل البيانات العامة. لم تعد هناك حاجة لاستدعاء هذه الوظيفة مباشرة، حيث يتم استدعاؤها داخليًا عند الحاجة. يمكن استدعاؤها أكثر من مرة، ويمكن استدعاؤها بشكل متزامن.

قبل إنشاء اتصال، يجب إنشاء تكوين. تقوم الوظيفة tls_config_new() بتخصيص وتهيئة وإرجاع كائن تكوين افتراضي جديد يمكن استخدامه للاتصالات المستقبلية. توجد العديد من الوظائف لتغيير خيارات التكوين؛ راجع tls_config_set_protocols(3)، tls_load_file(3)، tls_config_ocsp_require_stapling(3)، و tls_config_verify(3).

يمكن استخدام الوظيفة tls_config_error() لاسترداد سلسلة نصية تحتوي على مزيد من المعلومات حول آخر خطأ متعلق بتكوين ما.

يتم إنشاء كائن اتصال TLS بواسطة tls_client(3) أو tls_server(3) ويتم تكوينه باستخدام tls_configure(3).

يبدأ اتصال العميل بعد التكوين عن طريق استدعاء tls_connect(3). يمكن للخادم قبول اتصال عميل جديد عن طريق استدعاء tls_accept_socket(3) على اتصال مقبس تم إنشاؤه بالفعل.

تم توفير وظيفتين للإدخال والإخراج، tls_read(3) و tls_write(3). كلاهما يقوم تلقائيًا بإجراء tls_handshake(3) عند الحاجة.

يمكن فحص خصائص اتصالات TLS المنشأة باستخدام الوظائف الموضحة في tls_conn_version(3) و tls_ocsp_process_response(3).

بعد الاستخدام، يجب إغلاق اتصال TLS باستخدام tls_close(3) ثم تحريره عن طريق استدعاء tls_free(3).

عندما لا تكون هناك حاجة للمزيد من السياقات للتكوين، يجب تحرير كائن التكوين عن طريق استدعاء tls_config_free(). من الآمن استدعاء tls_config_free() بمجرد الانتهاء من الاستدعاء النهائي لـ tls_configure(). إذا كان config هو NULL، فلن يحدث أي إجراء.

قيم الإرجاع

tls_init() ترجع 0 عند النجاح أو -1 عند الخطأ.

tls_config_new() ترجع NULL عند الخطأ أو عند نفاد الذاكرة.

tls_config_error() ترجع NULL إذا لم يحدث أي خطأ مع config على الإطلاق، أو إذا فشل تخصيص الذاكرة أثناء محاولة تجميع السلسلة النصية التي تصف آخر خطأ متعلق بـ config.

انظر أيضًا

tls_accept_socket(3)، tls_client(3)، tls_config_ocsp_require_stapling(3)، tls_config_set_protocols(3)، tls_config_verify(3)، tls_conn_version(3)، tls_connect(3)، tls_load_file(3)، tls_ocsp_process_response(3)، tls_read(3)

التاريخ

ظهرت واجهة برمجة التطبيقات tls لأول مرة في OpenBSD 5.6 كرد فعل على التحديات غير الضرورية التي تقدمها واجهات برمجة التطبيقات الأخرى لاستخدامها بأمان.

تم تغيير أسماء جميع الوظائف من ressl_*() إلى tls_*() لـ OpenBSD 5.7.

ظهرت tls_config_error() في OpenBSD 6.0.

تنبيهات

ترجع الوظيفة tls_config_error() مؤشرًا داخليًا. لا يجب تحريره بواسطة التطبيق، وإلا فسيحدث خطأ تحرير مزدوج. سيصبح المؤشر غير صالح عند حدوث الخطأ التالي مع config. بالتالي، إذا قد يحتاج التطبيق إلى الرسالة في وقت لاحق، فيجب عليه نسخ السلسلة النصية قبل استدعاء وظيفة libtls التالية التي تتضمن config، أو قد ينتج عن ذلك خطأ تجاوز مساحة الذاكرة أو وصول قراءة لبيانات غير مقصودة.

tls_init(3)

LibreSSL — **tls_init**

NAME

tls_init — initialize the TLS library

SYNOPSIS

#include <tls.h>

int tls_init(void);

DESCRIPTION

The **tls_init**() function initializes the TLS library. It must be called once before any other TLS functions are used.

The function is thread-safe and can be called multiple times, although only the first call has any effect.

RETURN VALUES

On success, **tls_init**() returns 0. On failure, it returns -1 and sets the global errno variable appropriately.

SEE ALSO

tls_configure(3), tls_load_peer_cert_file(3), tls_open(3)

HISTORY

The **tls_init**() function first appeared in OpenBSD 5.3.

AUTHORS

The LibreSSL project <misc@libressl.org>

CAVEATS

The underlying C library's initialization routines might be called if they have not been already. This means that calling **tls_init**() can potentially call into functions that might themselves be thread-unsafe if they are not explicitly designed to be so. However, in practice, this is not an issue on most modern operating systems.

The function is not intended to be used to initialize multiple TLS contexts. For that purpose, use tls_configure(3).

tls_init(3)

LibreSSL — **tls_init**

الاسم

tls_init — تهيئة مكتبة TLS

الملخص

#include <tls.h>

int tls_init(void);

الوصف

تقوم الدالة **tls_init**() بتهيئة مكتبة TLS. يجب استدعاؤها مرة واحدة قبل استخدام أي دوال TLS أخرى.

الدالة آمنة للاستخدام المتعدد الخيوط (thread-safe) ويمكن استدعاؤها عدة مرات، على الرغم من أن الاستدعاء الأول فقط هو الذي له أي تأثير.

قيم الإرجاع

عند النجاح، تُرجع الدالة **tls_init**() القيمة 0. عند الفشل، تُرجع القيمة -1 وتضبط المتغير العام errno بشكل مناسب.

انظر أيضًا

tls_configure(3), tls_load_peer_cert_file(3), tls_open(3)

التاريخ

ظهرت الدالة **tls_init**() لأول مرة في OpenBSD 5.3.

المؤلفون

مشروع LibreSSL <misc@libressl.org>

ملاحظات

قد يتم استدعاء إجراءات التهيئة الخاصة بالمكتبة C الأساسية إذا لم يتم استدعاؤها بعد. هذا يعني أن استدعاء **tls_init**() يمكن أن يستدعي بشكل محتمل دوال قد تكون غير آمنة للاستخدام المتعدد الخيوط إذا لم تكن مصممة خصيصًا لذلك. ومع ذلك، من الناحية العملية، لا يمثل هذا مشكلة في معظم أنظمة التشغيل الحديثة.

الدالة غير مخصصة لتهيئة سياقات TLS متعددة. لهذا الغرض، استخدم tls_configure(3).
