libinput-record(1)

الحزمة: libinput

التراخيص: MIT

libinput-record(1) دليل الأوامر العام libinput-record(1)

الاسم

libinput-record - تسجيل أحداث النواة

الملخص

libinput record [خيارات] [/dev/input/event0 [/dev/input/event1 ...]]

الوصف

أداة libinput record تسجل أحداث النواة من جهاز وتطبعها بتنسيق يمكن لاحقًا إعادة تشغيله باستخدام أداة libinput replay(1). تحتاج هذه الأداة إلى التشغيل كـ root للقراءة من الجهاز.

ناتج هذه الأداة هو YAML، انظر تنسيق الملف لمزيد من التفاصيل. افتراضيًا، تطبع إلى stdout ما لم يتم توفير ملف إخراج. على سبيل المثال، هذه استدعاءات صالحة:

libinput record /dev/input/event3 touchpad.yml

libinput record recording.yml

libinput record --all all-devices.yml

libinput record /dev/input/event3 /dev/input/event4 tp-and-keyboard.yml

الأحداث المسجلة مستقلة عن libinput نفسها، وتحديث أو إزالة libinput لن يغير تدفق الأحداث.

الخيارات

إذا تم تقديم عقدة جهاز واحدة أو أكثر، تفتح هذه الأداة عقد عقد الجهاز هذه. بخلاف ذلك، يتم تقديم قائمة بالأجهزة ويمكن للمستخدم تحديد الجهاز المراد تسجيله. إذا كنت غير متأكد، قم بتشغيلها بدون أي وسائط.

--help
طباعة المساعدة
--all
تسجيل جميع أجهزة /dev/input/event* المتاحة على النظام. يجب استخدام هذا الخيار في حالات استثنائية فقط، فملف الإخراج غالبًا ما يكون صاخبًا جدًا وقد لا يكون من الممكن إعادة تشغيل التسجيل. يتطلب هذا الخيار --output-file ولا يجوز تقديم عقد أجهزة على سطر الأوامر.
--autorestart=s
إنهاء التسجيل الحالي بعد s ثانية من عدم نشاط الجهاز. يتطلب هذا الخيار تحديد --output-file. يتم استخدام اسم ملف الإخراج كبادئة، مع إضافة التاريخ والوقت للتسجيل. يجب أن يكون المهلة أكبر من 0.
-o filename.yml
--output-file=filename.yml
يحدد ملف الإخراج المراد استخدامه. إذا تم تقديم --autorestart، يتم استخدام اسم الملف كبادئة فقط. حيث لم يتم تقديم --output-file ولم يكن الوسيط الأول أو الأخير جهاز إدخال، فسيكون الوسيط الأول أو الأخير هو ملف الإخراج.
--grab
الاستحواذ الحصري على جميع الأجهزة المفتوحة. هذا سيمنع تسليم الأحداث إلى النظام المضيف.
--show-keycodes
عرض رموز المفاتيح كما هي في التسجيل. افتراضيًا، يتم إخفاء المفاتيح الشائعة وطباعتها كـ KEY_A لتجنب تسرب المعلومات.
--with-libinput
تسجيل أحداث libinput جنبًا إلى جنب مع أحداث الجهاز. هذه الميزة تجريبية. انظر قسم تسجيل أحداث libinput لمزيد من التفاصيل.
--with-hidraw
تسجيل أحداث hidraw جنبًا إلى جنب مع أحداث الجهاز. لا تكتب بيانات حساسة. انظر تسجيل تقارير HID لمزيد من التفاصيل.

تسجيل أجهزة متعددة

في بعض الأحيان يكون من الضروري تسجيل الأحداث من أجهزة متعددة في وقت واحد، على سبيل المثال عندما يتسبب تفاعل بين لوحة اللمس ولوحة المفاتيح في خلل. تسجل libinput record أجهزة متعددة بإزاحة زمنية متطابقة، مما يسمح بإعادة تشغيل صحيحة للتفاعل.

إذا تم تسجيل أجهزة متعددة، فيجب تقديم اسم ملف إخراج.

يجب تقديم جميع الأجهزة المراد تسجيلها على سطر الأوامر، استدعاء مثال هو:

libinput record -o tap-bug /dev/input/event3 /dev/input/event7

لاحظ أنه عند تسجيل أجهزة متعددة، يتم طباعة الجهاز الأول فقط على الفور، ويتم طباعة جميع الأجهزة الأخرى وأحداثها عند الخروج.

تسجيل أحداث libinput

عند تقديم خيار سطر الأوامر --with-libinput، تقوم libinput-record بتهيئة سياق libinput للأجهزة التي يتم تسجيلها. يتم طباعة الأحداث من هذه السياقات جنبًا إلى جنب مع أحداث evdev. هذه الميزة تجريبية.

الغرض الأساسي من هذه الميزة هو تصحيح الأخطاء وتحليل الأحداث، ولا يجوز لأي مستدعي الاعتماد على أي تنسيق معين للأحداث.

لاحظ أنه بينما ترى libinput و libinput-record نفس الأحداث من عقد الأجهزة، لا يمكن تقديم أي ضمان بشأن الترتيب الصحيح للأحداث. قد تأتي أحداث libinput في وقت مبكر أو متأخر عن الأحداث من عقد الأجهزة، وبالنسبة لبعض الأجهزة، قد تقوم libinput بتعديل تدفق الأحداث داخليًا قبل المعالجة.

لاحظ أن سياق libinput الذي تنشئه libinput-record لا يؤثر على جلسة سطح المكتب قيد التشغيل ولا ينسخ (لا يمكنه!) أي خيارات تكوين من تلك الجلسة.

تسجيل تقارير HID

عند تقديم خيار سطر الأوامر --with-hidraw، تبحث libinput-record عن عقدة hidraw (عقد) للأجهزة المحددة وتطبع أي تقارير HID واردة من تلك الأجهزة.

تقارير HID غير مشفرة ويمكن لشخص متحفز بما فيه الكفاية استعادة ضربات المفاتيح من السجلات. لا تكتب كلمات المرور أثناء تسجيل تقارير HID.

تنسيق الملف

Information about and events from the recorded device nodes

node: string
the device node recorded
evdev
A dictionary with the evdev device information.
hid
A list of integers representing the HID report descriptor bytes.
udev
A dictionary with the udev device information.
events
A list of dictionaries with the recorded events

evdev

name: string
The device name
id: [bustype, vendor, product, version]
The data from the struct input_id, bustype, vendor, product, version.
codes: {type: [a, b, c ], ...}
All evdev types and codes as nested dictionary. The evdev type is the key, the codes are a list.
absinfo: {code: [min, max, fuzz, flat, resolution], ...}
An array of arrays with 6 decimal elements each, denoting the contents of a struct input_absinfo. The first element is the code (e.g. ABS_X) in decimal format.
properties: [0, 1, ...]
Array with all INPUT_PROP_FOO constants. May be an empty array.

udev

properties: list of strings
A list of udev properties in the key=value format. This is not the complete list of properties assigned to the device but a subset that is relevant to libinput. These properties may include properties set on a parent device.
quirks: list of strings
A list of device quirks the key=value format.

events

A list of the recorded events. The list contains dictionaries Information about the events. The content is a list of dictionaries, with the string identifying the type of event sequence.

{ evdev: [ [sec, usec, type, code, value], ...] }
Each evdev dictionary contains the contents of a struct input_event in decimal format. The last item in the list is always the SYN_REPORT of this event frame. The next event frame starts a new evdev dictionary entry in the parent events list.
{ hid: hidrawX : [ 12, 34, 56 ], ...] }
The hid dictionary contains the hid reports in decimal format, with the hidraw node as key. The special key time denotes the current time when the report was read from the kernel.

Note that the kernel does not provide timestamps for hidraw events and the timestamps provided are from clock_gettime(3). They may be greater than a subsequent evdev event's timestamp.

NOTES

This tool records events from the kernel and is independent of libinput. In other words, updating or otherwise changing libinput will not alter the output from this tool. libinput itself does not need to be in use to record events.
