libpsx(3)

الحزمة: libcap

التراخيص: BSD-3-Clause OR GPL-2.0-only

LIBPSX(3) دليل مبرمج Linux LIBPSX(3)

الاسم

psx_syscall3, psx_syscall6, psx_set_sensitivity - دلالات POSIX لاستدعاءات النظام

الملخص

#include <sys/psx_syscall.h>
long int psx_syscall3(long int syscall_nr,
                      long int arg1, long int arg2, long int arg3);
long int psx_syscall6(long int syscall_nr,
                      long int arg1, long int arg2, long int arg3,
                      long int arg4, long int arg5, long int arg6);
int psx_set_sensitivity(psx_sensitivity_t sensitivity);
void psx_load_syscalls(long int (**syscall_fn)(long int,
                                    long int, long int, long int),
                       long int (**syscall6_fn)(long int,
                                    long int, long int, long int,
                                    long int, long int, long int));

يمكن ربط أي كود يستخدم أحد الوظائف أعلاه على النحو التالي:

ld ... -lpsx -lpthread

gcc ... -lpsx -lpthread

لاحظ أن الأعلام الخاصة مطلوبة لجعل -lcap تعمل مع قدرات العملية الكاملة عند ربطها مع -lpsx. على وجه التحديد، استخدم ملف خيارات pkg-config: gcc ... -lcap $(pkg-config --libs --cflags libpsx). المزيد من التفاصيل متاحة في صفحة الدليل cap_get_proc(3).

الوصف

تحاول مكتبة libpsx سد فجوة تركتها تطبيق pthreads(7) على Linux. لكي تكون خيوط POSIX متوافقة، عبر آلية setxid الخاصة بـ nptl(7)، تحتفظ glibc ببيانات اعتماد UID و GID متسقة بين جميع الخيوط المرتبطة بالعملية الحالية. ومع ذلك، فإن حالة الاعتماد الأخرى غير مدعومة بواسطة هذا التجريد. لدعم سمات الأمان الموسعة التي يديرها النواة، توفر libpsx زوجًا أكثر عمومية من وظائف استدعاء النظام الالتفافية: psx_syscall3() و psx_syscall6(). مثل آلية setxid، يتم تنسيق حالة الخيط بواسطة إشارة في الوقت الفعلي. بينما تستخدم آلية nptl:setxid الإشارة signo=33 (والتي تخفيها glibc خلف SIGRTMIN المعرفة بشكل خاطئ)، تدرج libpsx نفسها في مكدس معالج SIGSYS. تبذل جهدًا كبيرًا لتكون أول معالج من هذا القبيل ولكنها تعمل كمرور لاستخدامات SIGSYS الأخرى.

يدعم خدعة ماكرو غير فعالة الوظيفة الزائفة psx_syscall() التي تأخذ من 1 إلى 7 حجج، اعتمادًا على احتياجات المتصل. تقوم الماكرو (التي تستدعي في النهاية __psx_syscall()) بتعبئة الاستدعاء لاستخدام psx_syscall3() أو psx_syscall6() بالفعل مع ملء الأصفار للحجج المفقودة. بينما استخدام هذا في شفرة المصدر سيجعلها تبدو نظيفة، فإن بصمة الشفرة الفعلية أكبر. يتم تشجيعك على استخدام الوظائف الأكثر وضوحًا psx_syscall3() و psx_syscall6() حسب الحاجة.

تقوم psx_set_sensitivity() بتغيير سلوك استدعاءات النظام المعكوسة: PSX_IGNORE تضمن تجاهل الاختلافات (السلوك الافتراضي)؛ PSX_WARNING تطبع إشعارًا إلى stderr حول كيفية اختلاف النتائج؛ و PSX_ERROR تطبع تفاصيل الخطأ وتولد إشارة SIGSYS.

يمكن استخدام psx_load_syscalls() لتعيين مؤشرات وظائف محددة من قبل المتصل لاستدعاء استدعاءات النظام ذات 3 و 6 حجج. يمكن استخدام هذه الوظيفة لتكوين مكتبة، أو برنامج لتغيير السلوك عند ربطه بـ libpsx. في الواقع، تستخدم libcap هذه الوظيفة من libpsx لتجاوز واجهة برمجة التطبيقات الافتراضية لاستدعاء النظام الخاصة بها والمحددة للنطاق الخيطي. عند الربط بـ libpsx، يمكن لـ libcap العمل على جميع خيوط برنامج متعدد الخيوط للعمل بدلالات POSIX.

قيمة الإرجاع

قيمة الإرجاع لوظائف استدعاء النظام هي عمومًا القيمة التي تم إرجاعها بواسطة النواة، أو -1 في حالة حدوث خطأ. في مثل هذه الحالات، يتم تعيين errno(3) إلى قيمة الخطأ التفصيلية. تحاول وظائف psx_syscall3() و psx_syscall6() استدعاء نظام بخيط واحد والعودة فورًا في حالة حدوث خطأ. إذا نجح هذا الاستدعاء، فسيتم تنفيذ نفس استدعاءات النظام من معالج إشارة على كل من الخيوط الأخرى للعملية.

التوافق مع

احتياجات libcap(3) لدلالات POSIX لمعالجة القدرات. يمكنك قراءة المزيد حول سبب الحاجة إلى ذلك هنا:

https://sites.google.com/site/fullycapable/who-ordered-libpsx

الإصدارات من libpsx قبل 2.72 دعمت خيوط pthreads فقط. منذ libpsx-2.72، تعمل المكتبة مع جميع تطبيقات خيوط Linux لأنها تعمل على أدنى مستوى من تجريد الخيط، LWPs.
