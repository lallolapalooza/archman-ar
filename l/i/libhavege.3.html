الاسم

libhavege, havege_create, havege_run, havege_rng, havege_destroy, havege_status, havege_status_dump, havege_version - مولّد الأرقام العشوائية haveged

التركيب

#include <haveged/havege.h>
H_PARAMS params = {0};
h_status status;
char     status_buf[512];
if (NULL==havege_version(HAVEGE_PREP_VERSION)) exit(1);
H_PTR handle = havege_create(&params);
havege_status(handle, &status);
havege_run(handle);
rc = havege_rng(handle, handle->io_buf, handle->i_readSz/sizeof(H_UINT));
havege_status_dump(handle, H_SD_TOPIC_BUILD, status_buf, sizeof(status_buf));
havege_destroy(handle);

الوصف

توفر مكتبة libhavege مولّد الأرقام العشوائية haveged ومرافقه الخاصة بالضبط والاختبار في حزمة فرعية للتطوير. يتم الحفاظ على جميع ميزات البناء الشرطية لـ haveged وجميع خيارات haveged غير المرتبطة مباشرة بواجهات الخدمة أو نظام الملفات متاحة. وهذا يعني أن مكونات الضبط والاختبار نفسها الخاصة بـ haveged موجودة في المكتبة مع عناصر التحكم المكافئة التي يوفرها سطر أوامر haveged.

طرق واجهة برمجة التطبيقات

تستخدم مكتبة libhavege تقنية المقبض المعتم لإدارة مواردها المطلوبة. تُعاد الأخطاء في العضو "error" من المقبض. يجب استدعاء الدالة havege_destroy() للتخلص من أي موارد حصلت عليها havege_create().

H_PTR havege_create(H_PARAMS *params);

إنشاء مرساة. معظم أعضاء H_PARAMS المدخلة إلى هذا الاستدعاء تتوافق بشكل وثيق مع خيارات سطر أوامر haveged (انظر haveged(8) للتفاصيل). يجب على المستدعي التحقق من قيمة إرجاع غير فارغة بقيمة خطأ H_NOERR. أي قيمة إرجاع غير فارغة يجب التخلص منها باستدعاء havege_destroy() لتحرير أي موارد. قيم الأخطاء المحتملة: H_NOERR، H_NOTESTSPEC، H_NOBUF، H_NOTESTMEM، H_NOINIT

void havege_destroy(H_PTR hptr);

تحرير جميع موارد المرساة المخصصة. إذا تم استخدام خيار النواة المتعددة، يجب استدعاء هذه الدالة من معالج إشارة لمنع العمليات الزومبي. إذا تم استدعاؤها من العملية التي استدعت haveged_create()، فسيتم تحرير hptr عند إنهاء جميع العمليات الفرعية (إن وجدت). إذا تم استدعاؤها من عملية فرعية، فسيتم تعيين H_EXIT وإيقاظ جميع العمليات الفرعية للخروج.

int havege_rng(H_PTR hptr, H_UINT *buf, H_UINT sz);

قراءة بايتات عشوائية من مرساة نشطة. يجب أن يكون مولّد الأرقام العشوائية قد تم تجهيزه مسبقًا باستدعاء havege_run(). يجب أن تتم القراءة ضمن المخزن المؤقت المخصص، hptr->io_buf. النطاق المحدد هو عدد H_UINT المراد قراءتها. إذا تم استخدام خيار النواة المتعددة، فإن هذا المخزن المؤقت يكون معيّنًا في الذاكرة بين المجمعات. قيم الأخطاء المحتملة: H_NOERR، H_NOTESRUN، H_NOPOST، H_NODONE، H_NORQST، H_NOCOMP، H_EXIT

int havege_run(H_PTR hptr);

تسخين مولّد الأرقام العشوائية وتشغيل اختبارات بدء التشغيل. تنجح العملية إذا كان عضو الخطأ في المقبض هو H_NOERR. يجب التخلص من المقبض الفاشل باستدعاء havege_destroy(). قيم الأخطاء المحتملة: H_NOERR، H_NOCOLLECT، H_NOWALK، H_NOTESTMEM، H_NOTASK، H_NOTESTTOT، H_NOWAIT، H_NOTIMER، وأي خطأ من havege_rng().

void havege_status(H_PTR hptr, H_STATUS hsts);

يملأ بنية h_status بمعلومات للقراءة فقط تم جمعها من بناء الحزمة والضبط وقت التشغيل ومكونات الاختبار.

int havege_status_dump(H_PTR hptr, H_SD_TOPIC topic, char *buf, size_t len);

يستدعي havege_status() وينسّق العروض القياسية لحالة havege في المخزن المؤقت المقدم. التنسيقات القياسية هي:

H_SD_TOPIC_BUILD

ver: %s; arch: %s; vend: %s; build: (%s); collect: %dK

H_SD_TOPIC_TUNE

cpu: (%s); data: %dK (%s); inst: %dK (%s); idx: %d/%d; sz: %d/%d

H_SD_TOPIC_TEST

[tot tests(%s): A:%d/%d B: %d/%d;][continuous tests(%s): A:%d/%d B: %d/%d;][last entropy estimate %g]

H_SD_TOPIC_SUM

fills: %d, generated: %.4g %c bytes

const char *havege_version(const char *version);

إرجاع/التحقق من إصدار التحضير للمكتبة. إصدار التحضير هو إصدار الحزمة المستخدم لبناء المكتبة. تعيد الوسيطة الفارغة إصدار التحضير دون شرط. استخدام تعريف سلسلة التحضير في havege.h كمدخل يعيد إصدار التحضير إذا كان ملف الرأس متوافقًا مع المكتبة، أو NULL إذا لم يكن كذلك. يُقصد استدعاؤها قبل محاولة أي تهيئة.

ملاحظات

تُستخدم أحجام ذاكرات التخزين المؤقت من المستوى الأول للتعليمات والبيانات في المعالج لضبط خوارزمية HAVEGE لأقصى حساسية. إذا لم يتم تحديد هذه الأحجام، فسيحاول haveged تحديد الأحجام ديناميكيًا من sysfs في لينكس و/أو تعليمة cpuid مع الرجوع إلى قيمة افتراضية مُجمّعة إذا لم تتوفر معلومات أفضل.

يتضمن مولّد الأرقام العشوائية haveged مرفق اختبار وقت التشغيل استنادًا إلى مجموعة الاختبارات المحددة في مواصفة AIS-31 من المكتب الفيدرالي الألماني لأمن المعلومات (Bundesamt für Sicherheit in der Informationstechnik). تتكون مجموعة الاختبارات من 11 اختبارًا إحصائيًا مجمعة في مجموعتي اختبار ("A" و"B"). يمكن تشغيل الاختبارات عند التهيئة (المعروف أيضًا باسم اختبار "tot")، أو بشكل مستمر لمراقبة جميع المخرجات. سيؤدي فشل مجموعة إلى إحباط العملية ما لم يتم التنازل عن السلوك صراحةً في خيارات إعداد الاختبار.

يحتوي الإجراء A على 6 إجراءات اختبار مصممة لضمان سلوك غير لافت إحصائيًا. الاختبار الأول، "test0"، يتحقق من تفكك 65 ألف سلسلة من ستة بتات. يتكون باقي الإجراء من 257 تكرارًا لاختبارات FIPS140-1، "test1" حتى "test4"، واختبار الارتباط الذاتي، "test5". الحجم الثابت لمدخلات الإجراء A يجعله مثاليًا للاستخدام المستمر، لكن الإجراء بطيء ومستهلك للموارد. على وجه الخصوص، test5 أبطأ بعدة مراتب من أي اختبار AIS فردي آخر. كبديل لمن لا يستطيع تحمل هذا الحمل، يتم توفير متغيرات الإجراء A<n> التي تنفذ جميع الاختبارات المضمنة ولكن تنفذ test5 فقط كل 2^n تكرار. حتى مع هذا التسهيل، فإن الإجراء A أبطأ بكثير من الإجراء B.

يحتوي الإجراء B على 5 اختبارات، "test6a"، "test6b'، "test7a"، "test7b"، و"test8". تتحقق الاختبارات الأربعة الأولى من التكرارات المتوقعة للعينات 100,000 لانتقالات البتات بخطوة واحدة وخطوتين وثلاث خطوات وأربع خطوات. يوفر الاختبار الأخير تقديرًا تجريبيًا للإنتروبيا للمدخلات. المدخلات المطلوبة لإكمال هذه الاختبارات متغيرة، مما يؤدي إلى محاذاة بتات متغيرة باستمرار تحمي من آثار التخزين المؤقت.

يتطلب كل إجراء اختبار أكثر من 1 ميغابايت من البيانات. تتم إدارة مدخلات الاختبار بواسطة فهرس بتات في مخزن التجميع. يدير فهرس مستقل من أين يتم أخذ مخرجات الأعداد الصحيحة من نفس المخزن المؤقت. يتم تفعيل ملء المخزن المؤقت عندما يشير فهرس المخرجات إلى أن جميع البيانات قد تم استخراجها من المخزن المؤقت. يتم الاختبار عبر الإنترنت بعد إعادة ملء المخزن المؤقت ولكن قبل أن يسمح تحديث فهرس المخرجات باستئناف المخرجات. إذا فشل أي اختبار عبر الإنترنت أثناء معالجة المخزن المؤقت، فسيتم إعادة ملء المخزن المؤقت وإعادة معالجته حتى تكتمل أي إعادة محاولة ويحتوي المخزن المؤقت على اختبارات عبر الإنترنت غير فاشلة أو يفشل إجراء الاختبار عبر الإنترنت ويُعتبر مولّد الأرقام العشوائية معطوبًا.

يوصى بتشغيل كلا إجراءي اختبار AIS عند بدء التشغيل لضمان تهيئة مولّد الأرقام العشوائية بشكل صحيح. إذا كانت الموارد شحيحة، فإن حذف الإجراء A سيوفر الذاكرة والوقت، مع مخاطرة قليلة في الظروف التي يتم فيها خلط المخرجات مع مصادر أخرى في /dev/random أو csprng آخر. يُوصى أيضًا بالاختبار المستمر حيث تكون عقوبة الإنتاجية مقبولة. يظهر أحد التقييمات الحديثة لتكاليف إنتاجية الاختبار أدناه.

haveged -n0 -oc | pv > /dev/null
400MiB/s
haveged -n0 -ocb | pv > /dev/null
70MiB/s
haveged -n0 -oca8b | pv > /dev/null
13MiB/s
haveged -n0 -oca8 | pv > /dev/null
8MiB/s
haveged -n0 -oca | pv > /dev/null
100kiB/s

يكشف الاختبار المستمر أيضًا عن مأزق محتمل آخر. حتىan ideal RNG has a 10e-4 chance of failing either test procedure. The strict retry policy of AIS-31 is designed to guarantee an ideal RNG will "almost never" fail a test procedure. A single retry is mandated only to recover from a previous attempt that experienced a single individual test failure. The haveged implementation logs all retries and terminates on test procedure failures unless the procedure has been flagged as advisory by the "w" argument (see --onlinetest in haveged(8) ). Little evidence of the retry mechanism is seen unless large data sets are processed. Procedure A is too slow to be practical in these situations, so procedure B has been the best studied. Retries are observed at the approximate rate of 0.7-0.8 failures/GB, mostly in the test7 multi-step transition checks.

The probability that procedureB will fail two times in a row (in which case the program will be terminated unless w option was specified) is 4e-7 which is expected to happen at an approximate rate of once per 3,000 TB. When producing large amounts of data in order of TBs it's recommended to use -w option to make sure that program will not prematurely terminate because of a failed retry and carefully examine the stderr output for any problems.

EXAMPLE

The following minimal program writes the contents of 16 collection buffers of random data to stdout with continuous testing.

#include <stdio.h>
#include <haveged/havege.h>
int main(void)
{
H_PTR havege_state;
H_PARAMS havege_parameters = {0};
int i, rc;
if (NULL==havege_version(HAVEGE_PREP_VERSION)) {
  fprintf(stderr, "Incompatible library %s\n", havege_version(NULL));
  return 1;
  }
havege_parameters.testSpec="ta8bcb";
havege_state = havege_create(&havege_parameters);
rc = havege_state==NULL? H_NOHANDLE : havege_state->error;
if (H_NOERR==rc) {
  if (0==havege_run(havege_state)) {
    H_UINT *buf = havege_state->io_buf;
    int size = havege_state->i_readSz /sizeof(H_UINT);
    char info[256];
    for(i=0;i<16;i++) {
        rc = havege_rng(havege_state, buf, size);
        if (rc != size) {
            fprintf(stderr, "RNG read failed %d\n", havege_state->error);
            break;
            }
        rc = fwrite(buf, 1, size*sizeof(H_UINT), stdout);
        if ( rc < size ) {
            fprintf(stderr, "Write failed\n");
            break;
            }
        }
    i = havege_status_dump(havege_state, H_SD_TOPIC_TEST, info, sizeof(info));
    info[i++] = '\n';
    havege_status_dump(havege_state, H_SD_TOPIC_SUM, info+i, sizeof(info)-i);
    fprintf(stderr, "%s\n", info);
    }
  else fprintf(stderr, "Initialize failed %d\n", havege_state->error);
  havege_destroy(havege_state);
  }
else fprintf(stderr, "Create failed %d\n", rc);
return rc;
}

Defaults are provided for all inputs to havege_create() as documented in havege.h. In this case for example, (16*4kb=65kb) will be written to stdout because the default size for i_readsz in 4kb.
