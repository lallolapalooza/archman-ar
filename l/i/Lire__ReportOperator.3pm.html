Lire__ReportOperator(3pm)

الحزمة: lire

التراخيص: GPL-2.0-only

ReportOperator(3pm) وثائق Lire من LogReport ReportOperator(3pm)

الاسم

Lire::ReportOperator - الفئة الأساسية لجميع العمليات التي يمكن استخدامها لحساب التقارير

الملخص

print $op->name(), "\n";
print $op->op(), "\n";
print $op->label(), "\n";

الوصف

Lire::ReportOperator هي الفئة الأساسية لجميع العمليات التي يمكن استخدامها لحساب البيانات التي تظهر في تقارير Lire. توفر هذه الفئة فقط السلوك المشترك لجميع العمليات.

حاليًا، تنقسم العمليات المعرفة في Lire إلى نوعين رئيسيين: أولاً، هناك المجمعات (aggregators) وهي العمليات التي يمكنها تقسيم سجلات DLF إلى مجموعات متعددة، ثانيًا، هناك عمليات المجموعات (group operators) التي يمكنها حساب البيانات بناءً على مجموعة من سجلات DLF. المجمعات هي فئات فرعية من Lire::Aggregator وعمليات المجموعات هي فئات فرعية من Lire::Aggregate.

الأساليب

op()

ترجع اسم عنصر XML الذي يشير إلى هذه العملية.

report_spec()

ترجع كائن Lire::ReportSpec الذي توجد فيه هذه العملية.

parent()

ترجع الأب لهذه العملية. سيكون هذا غير معرف للمجمع ذي المستوى الأعلى في مواصفات التقرير. فقط Lire::Aggregator يمكن أن يكون لها أطفال وبالتالي تكون أبًا.

last_parent()

ترجع أبنا الأعلى مستوى لدينا.

name( [$new_name] )

ترجع اسم هذه العملية في مواصفات التقرير الحالية. اسم العملية هو معرف يجب أن يكون فريدًا في مواصفات تقرير معين. سيتم استخدام هذا الاسم لتحديد القيم التي تم إنشاؤها بواسطة هذه العملية في التقرير المُنشأ.

إذا تم تعيين $new_name، فسيتم تغيير اسم هذه العملية إلى هذا القيمة الجديدة.

has_label()

ترجع صحيحًا إذا كانت لهذه العملية تسمية صريحة معين.

label( [$new_label] )

ترجع ما يجب استخدامه كتسمية عمود للبيانات التي تم إنشاؤها بواسطة هذه العملية.

إذا تم تعيين الوسيط الثاني، فسيتم تعيين تسمية العمود إلى هذه القيمة الجديدة.

الأساليب للفئات الفرعية

يجب على الفئات الفرعية استخدام تجزئة (hash) لتمثيل بيانات مثيلاتها. يجب عليها استدعاء init() من طريقة المُنشئ (constructor) الخاصة بها.

init( %params )

Lire::Report هي فئة مجردة لا ينبغي إنشاؤها مباشرة. يجب على الفئات الفرعية استدعاء طريقة init() في المُنشئ الخاص بها. تقوم هذه الطريقة بتهيئة السمات المشتركة لجميع العمليات. مفاتيح %params التي يجب تحديدها هي:

op
نوع العملية. هذا هو اسم عنصر XML. إنه وسيط إلزامي.
parent
الأب لهذه العملية. يجب أن يكون هذا موجودًا ما لم يكن العنصر هو المجمع ذو المستوى الأعلى.
report_spec
مواصفات التقرير التي تضاف إليها هذه العملية.
label
تسمية هذه العملية. هذه معلومة اختيارية.

ترجع هذه الطريقة الكائن.

print( $fh, $prefix )

هذه هي الطريقة التي يتم استدعاؤها لكتابة تمثيل XML لهذه العملية.

$fh هو مقبض الملف الذي يجب إخراج تمثيل XML عليه. $indent هو عدد صحيح يعطي عدد المسافات التي يجب استخدامها كمسافة بادئة عند كتابة XML.

build_query( $query )

واجهة برمجة تطبيقات الدمج

يجب تنفيذ الأساليب لدعم دمج البيانات التي تم إنشاؤها بواسطة هذه العملية من تقريرين.

init_merge()

يتم استدعاء هذه الطريقة مرة واحدة قبل بدء دمج تقارير XML.

end_merge()

يتم استدعاء هذه الطريقة مرة واحدة بعد دمج جميع تقارير XML.

init_group_data()

يجب أن ترجع هذه الطريقة بنية بيانات سيتم تمريرها إلى استدعاء update_group_data() و merge_group_data(). سيكون هناك بنية بيانات واحدة لكل مجموعة موجودة في المجمع الذي يحتوي على هذه العملية.

هناك عدد قليل من القيود المفروضة على بنية البيانات هذه لضمان إمكانية فرزها بواسطة المجمعات التي تحتاج إلى فرز مدخلاتها. إذا كانت بنية البيانات

SCALAR
يمكن استخدام هذه القيمة لأغراض الفرز.
SCALAR REFERENCE
سيتم استخدام قيمة SCALAR كمفتاح فرز.
ARRAY REFERENCE
سيتم استخدام العنصر الأول في مرجع المصفوفة كمفتاح فرز.
HASH REFERENCE
سيتم استخدام العناصر "sort_value" في التجزئة كمفتاح فرز.
OBJECT REFERENCE
سيتم استخدام القيمة التي تم إرجاعها بواسطة طريقة sort_value() كمفتاح فرز.

يمكن استخدام دالة group_data_value() لاستخراج قيمة مفتاح الفرز وفقًا لهذه القواعد. يمكن استيرادها:

use Lire::ReportOperator qw/group_data_value/;
my $v = group_data_value( $data );

merge_group_data( $value, $data )

سيتم استدعاء هذه الطريقة مرة واحدة لكل قيمة تم إنشاؤها بواسطة هذه العملية في تقارير XML التي سيتم دمجها.

يمكن أن يكون الوسيط $value إما مرجع تجزئة (hash reference) أو كائن Lire::Report::Group. سيكون هو نفس الشيء الذي تم إنشاؤه بواسطة هذه العملية.

$data هي بنية بيانات المجموعة التي تم إرجاعها بواسطة init_group_data() للمجموعة التي يجب دمج $value فيها.

end_group_data( $data )

سيتم استدعاء هذه الطريقة مرة واحدة لكل مجموعة تم إنشاؤها بواسطة المجمع الذي يحتوي على هذه العملية. الوسيط $data هو بنية البيانات التي تم إرجاعها بواسطة init_group_data() للمجموعة الحالية.

أحد الاستخدامات الممكنة لهذه الطريقة يمكن أن يكون، على سبيل المثال، لطريقة المتوسط (avg) لحساب المتوسط الفعلي نظرًا لأنه لا يمكن القيام بذلك حتى تتم معالجة جميع السجلات.

add_entry_value( $entry, $data )

سيتم استدعاء هذه الطريقة مرة واحدة لكل مجموعة تم إنشاؤها بواسطة المجمع. في هذه الطريقة، يجب على العملية إضافة الاسم والقيمة المناسبين لهذه المدخل. $entry هو كائن Lire::Report::Entry الذي يجب إضافة الأسماء و/أو القيم إليه. $data هي بنية البيانات التي تم إرجاعها بواسطة init_group_data() المقابلة للمجموعة الحالية.

على سبيل المثال، في هذه الطريقة ستضيف عملية المجموع (sum) القيمة التي تحتوي على المجموع للمدخل الحالي.

group_data_value($data)

ترجع "القيمة" من عنصر بيانات واحد تم إنشاؤه بواسطة طريقة init_group_data(). هذه دالة وليست طريقة.

Lire::ReportOperator(3pm)

NAME

Lire::ReportOperator - Base class for report operators

SYNOPSIS

  use Lire::ReportOperator;
  
  # Inherit from Lire::ReportOperator
  package MyReportOperator;
  
  @ISA = qw(Lire::ReportOperator);
  
  sub new {
    my ($class, $report) = @_;
    my $self = $class->SUPER::new($report);
    # ... specific initialization ...
    return $self;
  }
  
  sub process {
    my ($self, $line) = @_;
    # ... process a log line ...
    return 1; # or 0 to skip
  }
  
  # ... other methods ...

DESCRIPTION

This module provides the base class for all report operators. A report operator is a Perl object that processes individual log lines from a log file to extract information or perform actions based on the content of the line.

Subclasses should override the METHODS as needed to implement specific processing logic.

METHODS

new
  my $operator = MyReportOperator->new($report);

Constructor for the report operator. It takes a reference to the report object as an argument. Subclasses should call the superclass constructor using $class->SUPER::new($report) and then perform their own initialization.

process
  my $keep_line = $operator->process($line);

This method is called for each line read from the log file. The $line argument contains the log line. The method should return a true value (e.g., 1) if the line should be kept for further processing or reporting, and a false value (e.g., 0) if the line should be skipped.

Subclasses must implement this method to define their specific processing logic.

finalize
  $operator->finalize();

This method is called after all lines have been processed. It can be used to perform any final calculations or cleanup operations. Subclasses can override this method.

report
  my $report_data = $operator->report();

This method is called to retrieve the results of the operator's processing. It should return data in a format suitable for reporting. Subclasses should override this method to return their collected or calculated data.

METHODS FOR SUBCLASSES

report_object
  my $report = $operator->report_object();

Returns the Lire::Report(3pm) object associated with this operator.

config
  my $config = $operator->config();

Returns the configuration hash for this operator.

set_config
  $operator->set_config($config_hashref);

Sets the configuration hash for this operator.

MERGING API

Report operators can be merged together. The following methods are used to facilitate this:

merge
  $operator1->merge($operator2);

Merges the data from $operator2 into $operator1. Subclasses should override this method if they have specific data structures that need to be merged.

SEE ALSO

Lire::ReportSpec(3pm), Lire::Aggregate(3pm), Lire::Aggregator(3pm).
