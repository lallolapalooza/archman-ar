الاسم

openssl.cnf — ملفات تكوين OpenSSL

الوصف

يمكن استخدام مكتبة OpenSSL CONF لقراءة ملفات التكوين؛ انظر CONF_modules_load_file(3). يتم استخدامها لملف التكوين الرئيسي لـ OpenSSL /etc/ssl/openssl.cnf وفي بعض الأماكن الأخرى مثل ملفات امتداد الشهادة للأداة openssl(1) x509. يمكن لتطبيقات OpenSSL أيضًا استخدام مكتبة CONF لأغراضها الخاصة.

ينقسم ملف التكوين إلى عدد من الأقسام. يبدأ كل قسم بسطر [اسم_القسم] وينتهي عند بدء قسم جديد أو الوصول إلى نهاية الملف. يمكن أن يتكون اسم القسم من أحرف أبجدية رقمية وشرطات سفلية.

القسم الأول في ملف التكوين مميز ويشار إليه باسم "القسم الافتراضي". عادة ما يكون غير مسمى ويمتد من بداية الملف إلى القسم المسمى الأول. عند البحث عن اسم، يتم البحث عنه أولاً في قسم مسمى (إن وجد) ثم في القسم الافتراضي.

يتم تعيين البيئة إلى قسم يسمى ENV.

يمكن تضمين التعليقات بإضافة الحرف ‘#’ قبلها.

يتكون كل قسم في ملف التكوين من عدد من أزواج الاسم والقيمة بالشكل اسم=قيمة.

يمكن أن يحتوي سلسلة الاسم على أي أحرف أبجدية رقمية بالإضافة إلى بعض رموز علامات الترقيم مثل ‘.’ ‘,’ ‘;’ و ‘_’.

تتكون سلسلة القيمة من السلسلة التي تلي الحرف ‘=’> حتى نهاية السطر مع إزالة أي مسافات بيضاء بادئة وزائدة.

تخضع سلسلة القيمة لتوسيع المتغيرات. يمكن القيام بذلك عن طريق تضمين سلاسل فرعية بالشكل $اسم أو ${اسم}: هذا سيستبدل قيمة المتغير المسمى في القسم الحالي. من الممكن أيضًا استبدال قيمة من قسم آخر باستخدام الصيغة $قسم::اسم أو ${قسم::اسم}. باستخدام الصيغة $ENV::اسم، يمكن استبدال متغيرات البيئة. من الممكن أيضًا تعيين قيم لمتغيرات البيئة باستخدام الاسم ENV::اسم. سيعمل هذا إذا كان البرنامج يبحث عن متغيرات البيئة باستخدام مكتبة CONF بدلاً من استدعاء getenv(3) مباشرة. يجب ألا يتجاوز طول سلسلة القيمة 64 ألف بعد توسيع المتغيرات وإلا سيحدث خطأ.

من الممكن تجاوز بعض الأحرف باستخدام أي نوع من علامات الاقتباس أو الحرف ‘\’>. بجعل الحرف الأخير من السطر ‘\’>، يمكن تمديد سلسلة القيمة عبر عدة أسطر. بالإضافة إلى ذلك، يتم التعرف على التسلسلات ‘\n’>، ‘\r’>، ‘\b’>، و ‘\t’>.

تكوين مكتبة OpenSSL

يمكن للتطبيقات تكوين جوانب معينة من OpenSSL تلقائيًا باستخدام ملف التكوين الرئيسي لـ OpenSSL، أو بشكل اختياري ملف تكوين بديل. تتضمن الأداة openssl(1) هذه الوظيفة: يستخدم أي أمر فرعي ملف التكوين الرئيسي لـ OpenSSL ما لم يتم استخدام خيار في الأمر الفرعي لاستخدام ملف تكوين بديل.

لتمكين تكوين المكتبة، يجب أن يحتوي القسم الافتراضي على سطر مناسب يشير إلى قسم التكوين الرئيسي. الاسم الافتراضي هو openssl_conf، والذي تستخدمه الأداة openssl(1). قد تستخدم التطبيقات الأخرى اسمًا بديلاً مثل myapplication_conf. تظهر جميع سطور تكوين المكتبة في القسم الافتراضي في بداية ملف التكوين.

يجب أن يتكون قسم التكوين من مجموعة من أزواج الاسم والقيمة التي تحتوي على معلومات تكوين الوحدة النمطية المحددة. يمثل الاسم اسم وحدة تكوين التكوين. معنى القيمة يعتمد على الوحدة النمطية: قد يمثل، على سبيل المثال، قسم تكوين إضافي يحتوي على معلومات خاصة بوحدة تكوين الوحدة النمطية. على سبيل المثال:

# يجب أن يكون السطر التالي في القسم الافتراضي.
openssl_conf = openssl_init

[openssl_init]
oid_section = new_oids

[new_oids]
... oids جديدة هنا ...

يتم وصف ميزات كل وحدة تكوين أدناه.

وحدة تكوين كائنات ASN.1

هذه الوحدة النمطية لها الاسم oid_section. تشير قيمة هذا المتغير إلى قسم يحتوي على أزواج الاسم والقيمة من OIDs: الاسم هو اسم OID المختصر والطويل، والقيمة هي الشكل الرقمي لـ OID. على الرغم من أن بعض الأوامر الفرعية للأداة openssl(1) لديها بالفعل وظائف قسم كائنات ASN1 الخاصة بها، إلا أن ليس جميعها كذلك. باستخدام وحدة تكوين كائنات ASN1، يمكن لجميع الأوامر الفرعية للأداة openssl(1) رؤية الكائنات الجديدة بالإضافة إلى أي تطبيقات متوافقة. على سبيل المثال:

[new_oids]
some_new_oid = 1.2.3.4
some_other_oid = 1.2.3.5

من الممكن أيضًا تعيين القيمة إلى الاسم الطويل متبوعًا بفاصلة وشكل OID الرقمي. على سبيل المثال:

shortName = some object long name, 1.2.3.4

أمثلة

هذا مثال لملف تكوين يستخدم بعض الميزات المذكورة أعلاه:

# هذا هو القسم الافتراضي.
HOME=/temp
RANDFILE= ${ENV::HOME}/.rnd
configdir=$ENV::HOME/config

[ section_one ]
# نحن الآن في القسم الأول.

# الاقتباسات تسمح بمسافات بيضاء بادئة وزائدة
any = " any variable name "

other = A string that can \
cover several lines \
by including \\ characters

message = Hello World\n

[ section_two ]
greeting = $section_one::message

يوضح المثال التالي كيفية توسيع متغيرات البيئة بأمان.

افترض أنك تريد متغيرًا يسمى tmpfile للإشارة إلى اسم ملف مؤقت. يمكن تحديد الدليل الذي يتم وضعه فيه بواسطة متغيرات البيئة TEMP أو TMP ولكن قد لا يتم تعيينها لأي قيمة على الإطلاق. إذا قمت فقط بتضمين أسماء متغيرات البيئة ولم يكن المتغير موجودًا، فسيتسبب هذا في حدوث خطأ عند محاولة تحميل ملف التكوين. بالاستفادة من القسم الافتراضي، يمكن البحث عن كلتا القيمتين مع إعطاء الأولوية لـ TEMP واستخدام /tmp إذا لم يتم تعريف أي منهما:

TMP=/tmp
# تُستخدم القيمة أعلاه إذا لم يكن TMP في البيئة
TEMP=$ENV::TMP
# تُستخدم القيمة أعلاه إذا لم يكن TEMP في البيئة
tmpfile=${ENV::TEMP}/tmp.filename

تكوين مكتبة OpenSSL أكثر تعقيدًا. إضافة OID:

# اسم التطبيق الافتراضي: يجب أن يتطابق مع معلمة "appname" (إن وجدت)
# المقدمة لـ CONF_modules_load_file وما شابه.
openssl_conf = openssl_conf_section

[openssl_conf_section]
# قائمة وحدات التكوين
oid_section = new_oids

[new_oids]
# OID جديد، اسم قصير فقط
newoid1 = 1.2.3.4.1
# OID جديد باسم قصير واسم طويل
newoid2 = New OID 2 long name, 1.2.3.4.2

يمكن استخدام الأمثلة أعلاه مع أي تطبيق يدعم تكوين المكتبة إذا تم تعديل "openssl_conf" لمطابقة "appname" المناسب.

openssl.cnf(5) - Arch Linux

NAME

openssl.cnf - OpenSSL library configuration file

DESCRIPTION

The OpenSSL library can be configured using the openssl.cnf file. This file uses a colon-separated hierarchy, where sections are named section.subsection.subsubsection. Sections can also be named using the dot-notation section.name. For example, openssl_conf uses the format openssl_conf = openssl_init, openssl_init = 0.0.0.0.

A configuration file consists of sections. Each section begins with a line containing the section name in square brackets, e.g. [ new_section ]. Within a section are zero or more configuration settings, which are name = value pairs. White space surrounding the name and value is ignored.

A '#' or ';' character at the beginning of a line indicates a comment. Comments can also appear after a value on the same line.

The openssl.cnf file supports variable expansion. The syntax is ${variable} or $variable. The search order for variables is: first the current section, then the .<section> section (if it exists), then the environment, and finally the default value (if specified).

A special section named .mail name is used for variables that are not found in the current section. The search order is the same as above, except that the default values are searched last.

A section name can be a number or a string. Numbers are treated as hexadecimal values. For example, 10000 is equivalent to 0x10000.

A variable can be defined in a section using the name=value syntax. The value can be a string, a number, or another variable expansion.

Empty lines are ignored.

OPENSSL LIBRARY CONFIGURATION

The OpenSSL library looks for configuration files in the following order:

  1. The file specified by the OPENSSL_CONF environment variable.
  2. The file openssl.cnf in the current directory.
  3. The system-wide configuration file, typically /etc/ssl/openssl.cnf.

The library can be instructed to load configuration files programmatically using the CONF_modules_load_file(3) function.

FILES

/etc/ssl/openssl.cnf

EXAMPLES

The following example shows how to define a new OID in a configuration file.

[ new_oids ]
1.2.3.4.1 = newoid1

For example if the second sample file above is saved to "example.cnf" then the command line:

OPENSSL_CONF=example.cnf openssl asn1parse -genstr OID:1.2.3.4.1

will output:

0:d=0 hl=2 l= 4 prim: OBJECT :newoid1

showing that the OID "newoid1" has been added as "1.2.3.4.1".

SEE ALSO

openssl(1), CONF_modules_load_file(3), OPENSSL_config(3), x509v3.cnf(5)

CAVEATS

If a configuration file attempts to expand a variable that doesn't exist, then an error is flagged and the file will not load. This can also happen if an attempt is made to expand an environment variable that doesn't exist. For example, in a previous version of OpenSSL the default OpenSSL master configuration file used the value of HOME which may not be defined on non Unix systems and would cause an error.

This can be worked around by including a default section to provide a default value: then if the environment lookup fails, the default value will be used instead. For this to work properly, the default value must be defined earlier in the configuration file than the expansion. See the EXAMPLES section for an example of how to do this.

If the same variable is defined more than once in the same section, then all but the last value will be silently ignored. In certain circumstances such as with DNs, the same field may occur multiple times. This is usually worked around by ignoring any characters before an initial ‘.’, for example:

1.OU="My first OU"
2.OU="My Second OU"

BUGS

Currently there is no way to include characters using the octal \nnn form. Strings are all NUL terminated, so NUL bytes cannot form part of the value.

The escaping isn't quite right: if you want to use sequences like ‘\n’, you can't use any quote escaping on the same line.

Files are loaded in a single pass. This means that a variable expansion will only work if the variables referenced are defined earlier in the file.
