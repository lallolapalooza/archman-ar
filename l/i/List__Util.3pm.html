NAME

List::Util - utilitarian functions for list processing

SYNOPSIS

  use List::Util qw(
      sum max min reduce
      shuffle sample pairmap
      first last none all any
      mesh_shortest mesh_longest
  );
  use List::Util qw(:all); # Import all functions

DESCRIPTION

This module provides a collection of useful, often-needed, functions for manipulating lists and scalars.

Many of these functions are implemented in C for speed, and are therefore faster than equivalent Perl implementations.

The module exports functions by default, but you can control which functions are exported using the standard Perl import mechanism.

For example:

  use List::Util qw(sum max min);
  use List::Util (); # Import nothing by default

Or you can import everything:

  use List::Util qw(:all);

LIST-REDUCTION FUNCTIONS

These functions take a list of values and reduce it to a single scalar value.

sum LIST
Returns the sum of the elements in LIST.
max LIST
Returns the maximum element in LIST.
min LIST
Returns the minimum element in LIST.
reduce BLOCK LIST
Reduces the list LIST by applying the BLOCK repeatedly. The BLOCK should take two arguments and return a single value. The BLOCK is first called with the first two elements of LIST. The result of that call is then called with the next element of LIST, and so on.

For example:

  my $sum = sum 1..100;
  my $max = max @array;
  my $min = min @array;
  my $product = reduce { $a * $b } @nums;

Note that reduce does not apply a prototype, so you must invoke it with references to arrays if you want to pass arrays.

  my $product = reduce { $a * $b } \@nums;

If the list is empty, sum, max, and min return undef. If the list has only one element, that element is returned.

reduce returns undef if the list is empty. If the list has only one element, that element is returned.

KEY/VALUE PAIR LIST FUNCTIONS

These functions operate on lists that are expected to contain key/value pairs.

pairmap BLOCK, LIST
Iterates over LIST assuming it contains key/value pairs. For each pair, the BLOCK is executed with the key as $a and the value as $b. The results of each BLOCK invocation are collected into a list and returned.

For example:

  my @values = pairmap { $a => $b*2 } one => 1, two => 2;

This will result in @values containing ( one => 2, two => 4 ).

pairmap does not apply a prototype. You must pass references to arrays if you wish to pass arrays.

  my @values = pairmap { $a => $b*2 } \%hash;

The BLOCK can be any valid Perl expression, including a list context expression.

pairmap also supports the :all import tag, allowing you to import all pairmap-related functions.

See also the "KNOWN BUGS" section regarding lexical variables in the BLOCK.

OTHER FUNCTIONS

first BLOCK, LIST
Returns the first element in LIST for which BLOCK returns true. Returns undef if no such element is found. 
  my $first_even = first { $_ % 2 == 0 } @numbers;
last BLOCK, LIST
Returns the last element in LIST for which BLOCK returns true. Returns undef if no such element is found. 
  my $last_odd = last { $_ % 2 != 0 } @numbers;
none BLOCK, LIST
Returns true if BLOCK returns false for all elements in LIST. Returns false otherwise.
all BLOCK, LIST
Returns true if BLOCK returns true for all elements in LIST. Returns false otherwise.
any BLOCK, LIST
Returns true if BLOCK returns true for at least one element in LIST. Returns false otherwise.
shuffle LIST
Returns a random permutation of LIST.
sample($n, LIST)
Returns a random sample of $n elements from LIST, without replacement.
mesh_shortest LIST
A list-based version of "zip". Returns a list of lists, where each inner list contains elements from the input lists at the same index. Stops when the shortest input list runs out of elements.
mesh_longest LIST
Similar to mesh_shortest, but continues until the longest input list runs out of elements. Missing elements are filled with undef.

All these functions take their list arguments in the normal Perl way (i.e. as a comma-separated list of values).

The predicate functions (first, last, none, all, any) do not apply a prototype. You must pass references to arrays if you wish to pass arrays.

  my @evens = first { $_ % 2 == 0 } \@numbers;

The shuffle and sample functions are intended to be used with the List::MoreUtils::zip function, or List::MoreUtils::mesh_shortest, or List::MoreUtils::mesh_longest (themselves aliases of each other). This function does not apply a prototype, so make sure to invoke it with references to arrays.

my @result = mesh_shortest ...
my @result = mesh_longest ...

These variations are similar to those of zip, in that they differ in behaviour when one of the input lists runs out of elements before the others.

CONFIGURATION VARIABLES

$RAND

local $List::Util::RAND = sub { ... };

Since version 1.54.

This package variable is used by code which needs to generate random numbers (such as the "shuffle" and "sample" functions). If set to a CODE reference it provides an alternative to perl's builtin rand() function. When a new random number is needed this function will be invoked with no arguments and is expected to return a floating-point value, of which only the fractional part will be used.

KNOWN BUGS

RT #95409

https://rt.cpan.org/Ticket/Display.html?id=95409

If the block of code given to "pairmap" contains lexical variables that are captured by a returned closure, and the closure is executed after the block has been re-used for the next iteration, these lexicals will not see the correct values. For example:

my @subs = pairmap {
   my $var = "$a is $b";
   sub { print "$var\n" };
} one => 1, two => 2, three => 3;
$_->() for @subs;

Will incorrectly print

three is 3
three is 3
three is 3

This is due to the performance optimisation of using "MULTICALL" for the code block, which means that fresh SVs do not get allocated for each call to the block. Instead, the same SV is re-assigned for each iteration, and all the closures will share the value seen on the final iteration.

To work around this bug, surround the code with a second set of braces. This creates an inner block that defeats the "MULTICALL" logic, and does get fresh SVs allocated each time:

my @subs = pairmap {
   {
      my $var = "$a is $b";
      sub { print "$var\n"; }
   }
} one => 1, two => 2, three => 3;

This bug only affects closures that are generated by the block but used afterwards. Lexical variables that are only used during the lifetime of the block's execution will take their individual values for each invocation, as normal.

uniqnum() on oversized bignums

Due to the way that uniqnum() compares numbers, it cannot distinguish differences between bignums (especially bigints) that are too large to fit in the native platform types. For example,

my $x = Math::BigInt->new( "1" x 100 );
my $y = $x + 1;
say for uniqnum( $x, $y );

Will print just the value of $x, believing that $y is a numerically- equivalent value. This bug does not affect uniqstr(), which will correctly observe that the two values stringify to different strings.
