NAME

Lire::ReportParser - Base class for report parser.

SYNOPSIS

   use Lire::ReportParser;

   my $parser = Lire::ReportParser->new($report);
   # ...
   $parser->parse();

DESCRIPTION

This is the base class for all report parser. You should not use it directly. You should use one of its subclasses.

USAGE

This class is not intended to be used directly. It is intended to be subclassed by other classes that will parse specific report formats.

The main method to use is parse(), which will process the report and generate the desired output.

WRITING AN XML REPORT PROCESSOR

To write a parser for an XML-based report format, you should subclass Lire::ReportParser and implement the following methods:

initialize()
This method is called when the parser is created. It should initialize any necessary data structures.
start_element($element, $attributes)
This method is called when an element starts in the XML document.
end_element($element)
This method is called when an element ends in the XML document.
character_data($data)
This method is called when character data is encountered in the XML document.
parse()
This method starts the parsing process. It should not be overridden unless you want to change the entire parsing logic.

CONTEXT METHODS

These methods are called by the parser to provide information about the current context. They are useful for conditional processing of report elements.

current_timespan( )

Useful in "subreport" context, it returns the timespan of the current subreport.

current_superservice( )

Useful in "subreport" context, it returns the superservice's of the current subreport.

current_type( )

Useful in "subreport" context, it returns the ID of the report specification that was used to generate the current subreport.

current_table_info()

Useful when processing "group" and "entry", this returns a Lire::Report;:TableInfo object which describes the layout of the current table.

current_group_entry_show( )

Useful in "table" and "group" context, it returns the maximum number of entries that should be displayed.

show_current_entry( )

Useful in "entry" context , this can be used to test whether or not the current "entry" should be displayed based on the current entry index and the parent's "show" attribute.

current_table_entry_count( )

Useful in "table" context, it returns the number of entries that were processed so far. This only reports the entries in the "table" element, not counting the one in the nested "group".
