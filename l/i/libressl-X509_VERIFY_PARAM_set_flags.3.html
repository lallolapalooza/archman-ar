">X509_VERIFY_PARAM_set_trust() يضبط إعداد الثقة في param إلى trust.

X509_VERIFY_PARAM_set_time() يضبط العلامة X509_V_FLAG_USE_CHECK_TIME في param بالإضافة إلى العلامات التي تم تعيينها بالفعل ويضبط وقت التحقق إلى t. إذا لم يتم استدعاء هذه الدالة، فسيتم استخدام الوقت الحالي بدلاً من ذلك، أو بداية حقبة يونكس (1 يناير 1970) إذا تم تعيين X509_V_FLAG_USE_CHECK_TIME يدويًا باستخدام X509_VERIFY_PARAM_set_flags().

X509_VERIFY_PARAM_add0_policy() تُمكّن التحقق من السياسات (وهو معطل بشكل افتراضي) وتضيف policy إلى مجموعة السياسات المقبولة.

X509_VERIFY_PARAM_set1_policies() تُمكّن التحقق من السياسات (وهو معطل بشكل افتراضي) وتضبط مجموعة السياسات المقبولة إلى policies. يتم مسح أي مجموعة سياسات موجودة. يمكن أن تكون المعلمة policies NULL لمسح مجموعة سياسات موجودة.

X509_VERIFY_PARAM_set_depth() تضبط الحد الأقصى لعمق التحقق إلى depth. وهذا هو الحد الأقصى لعدد شهادات CA غير الموثوق بها التي يمكن أن تظهر في سلسلة.

X509_VERIFY_PARAM_set_auth_level() تضبط مستوى الأمان كما هو محدد في SSL_CTX_set_security_level(3) لتحقق سلسلة الشهادات. لكي تتحقق سلسلة الشهادات، يجب أن تلبي المفاتيح العامة لجميع الشهادات مستوى الأمان المحدد. لا يتم فرض مستوى الأمان لخوارزمية التوقيع لشهادة مرساة الثقة في السلسلة، والتي إما أن تكون موثوقة بشكل مباشر أو تم التحقق منها بوسائل أخرى غير توقيعها.

من وجهة نظر مكتبة X.509، مستوى الأمان الافتراضي هو 0. ومع ذلك، تستخدم مكتبة SSL مستوى أمان افتراضي مختلف وهو 1 وتستدعي X509_VERIFY_PARAM_set_auth_level() بمستواها الخاص قبل التحقق من سلسلة الشهادات.

X509_VERIFY_PARAM_set1_host() تضبط اسم DNS المتوقع إلى name مع مسح أي اسم مضيف أو أسماء تم تحديدها مسبقًا. إذا كان name NULL أو فارغًا، يتم مسح قائمة أسماء المضيفين، ولا يتم إجراء فحوصات الاسم على شهادة الطرف المقابل. يجب تعيين namelen إلى طول name. للتوافق التاريخي، إذا كان name ينتهي بـ NUL، فيمكن تحديد namelen على أنه صفر. عند تحديد اسم مضيف، يقوم التحقق من الشهادة تلقائيًا باستدعاء X509_check_host(3) مع علامات تساوي الوسيط flags المقدمة إلى X509_VERIFY_PARAM_set_hostflags() (الافتراضي صفر). ستفشل X509_VERIFY_PARAM_set1_host() إذا كان name يحتوي على أي بايتات 0 مضمنة.

X509_VERIFY_PARAM_add1_host() تضيف name كمعرف مرجعي إضافي يمكن مطابقته مع شهادة الطرف المقابل. يتم الاحتفاظ بأي أسماء سابقة تم تعيينها عبر X509_VERIFY_PARAM_set1_host() و X509_VERIFY_PARAM_add1_host(). لا يتم إجراء أي تغيير إذا كان name NULL أو فارغًا. يجب تعيين namelen إلى طول name. للتوافق التاريخي، إذا كان name ينتهي بـ NUL، فيمكن تحديد namelen على أنه صفر. ستفشل X509_VERIFY_PARAM_add1_host() إذا كان name يحتوي على أي بايتات 0 مضمنة. عند تكوين أسماء متعددة، يعتبر الطرف المقابل موثقًا عندما تتطابق أي اسم.

X509_VERIFY_PARAM_get0_peername() تُرجع اسم DNS أو الاسم الشائع للموضوع من شهادة الطرف المقابل الذي تطابق مع أحد المعرفات المرجعية. عندما لا يتم تعطيل المطابقة ذات الأحرف البديلة، أو عندما يحدد معرف مرجعي نطاقًا فرعيًا (يبدأ بـ ".") بدلاً من اسم مضيف، قد يكون اسم الطرف المقابل اسمًا ذا أحرف بديلة أو نطاقًا فرعيًا للمعّرف المرجعي على التوالي.

X509_VERIFY_PARAM_set1_email() تضبط عنوان البريد الإلكتروني المتوقع بتنسيق RFC 822 إلى email. يجب تعيين emaillen إلى طول email. للتوافق التاريخي، إذا كان email ينتهي بـ NUL، فيمكن تعيين emaillen على أنه صفر، وستفشل X509_VERIFY_PARAM_set1_email() إذا كان email هو NULL أو سلسلة فارغة أو يحتوي على بايتات 0 مضمنة. عند تحديد عنوان بريد إلكتروني، يقوم التحقق من الشهادة تلقائيًا باستدعاء X509_check_email(3).

X509_VERIFY_PARAM_set1_ip() تضبط عنوان IP المتوقع إلى ip. الوسيط ip بتنسيق ثنائي، بترتيب بايتات الشبكة، ويجب تعيين iplen إلى 4 لـ IPv4 و 16 لـ IPv6. ستفشل X509_VERIFY_PARAM_set1_ip() إذا كان ip هو NULL أو إذا كان iplen ليس 4 أو 16. عند تحديد عنوان IP، يقوم التحقق من الشهادة تلقائيًا باستدعاء X509_check_ip(3).

X509_VERIFY_PARAM_set1_ip_asc() تضبط عنوان IP المتوقع إلى ipasc. الوسيط ipasc هو سلسلة ASCII تنتهي بـ NUL: نقطي عشري رباعي لـ IPv4 وسداسي عشري مفصول بنقطتين لـ IPv6. يتم دعم الترميز المختصر "::" لعناوين IPv6. ستفشل X509_VERIFY_PARAM_set1_ip_asc() إذا كان ipasc غير قابل للتحليل.

قيم الإرجاع

X509_VERIFY_PARAM_set1_name() و X509_VERIFY_PARAM_set_flags() و X509_VERIFY_PARAM_clear_flags() و X509_VERIFY_PARAM_set_purpose() و X509_VERIFY_PARAM_set_trust() و X509_VERIFY_PARAM_add0_policy() و X509_VERIFY_PARAM_set1_policies() تُرجع 1 للنجاح أو 0 للفشل.

X509_VERIFY_PARAM_set1_host() و X509_VERIFY_PARAM_add1_host() و X509_VERIFY_PARAM_set1_email() و X509_VERIFY_PARAM_set1_ip() و X509_VERIFY_PARAM_set1_ip_asc() تُرجع 1 للنجاح أو 0 للفشل. الفشل من هذه الروتينات سيؤدي إلى تسميم كائن X509_VERIFY_PARAM بحيث تفشل الاستدعاءات المستقبلية لـ X509_verify_cert(3) باستخدام الكائن المسموم.

X509_VERIFY_PARAM_get_flags() تُرجع علامات التحقق الحالية.

X509_VERIFY_PARAM_get_time() تُرجع دائمًا وقت التحقق المكون. تفعل ذلك حتى لو لم يتم استخدام الوقت المرجع لأن العلامة X509_V_FLAG_USE_CHECK_TIME غير محددة.

X509_VERIFY_PARAM_get_depth() تُرجع عمق التحقق الحالي.

X509_VERIFY_PARAM_get0_name() و X509_VERIFY_PARAM_get0_peername() تُرجع مؤشرات إلى سلاسل صالحة فقط خلال فترة حياة كائن param المحدد ويجب ألا يتم تحريرها بواسطة برنامج التطبيق.

علامات التحقق

تتكون علامات التحقق من صفر أو أكثر من العلامات التالية مدمجة معًا.

X509_V_FLAG_CRL_CHECK تُمكّن التحقق من CRL لشهادة ورقة سلسلة الشهادات. يحدث خطأ إذا لم يتم العثور على CRL مناسب.

X509_V_FLAG_CRL_CHECK_ALL تُمكّن التحقق من CRL لسلسلة الشهادات بأكملها.

X509_V_FLAG_IGNORE_CRITICAL تعطّل التحقق من الامتدادات الحرجة. افتراضيًا، أي امتدادات حرجة غير معالجة في الشهادات أو (إذا تم التحقق منها) CRLs تؤدي إلى خطأ فادح. إذا تم تعيين هذه العلامة، يتم تجاهل الامتدادات الحرجة غير المعالجة. تحذير: قد يكون تعيين هذا الخيار لأي شيء آخر غير أغراض التصحيح خطرًا أمنيًا. يمكن إجراء تحكم أدق في الامتدادات المدعومة في دالة الاستدعاء الخلفي للتحقق.

العلامة X509_V_FLAG_X509_STRICT تعطل الحلول البديلة لبعض الشهادات المعطلة وتجعل التحقق يطبق قواعد X509 بشكل صارم.

X509_V_FLAG_ALLOW_PROXY_CERTS علامة تم إهمالها كانت تمكّن التحقق من شهادات الوكيل. في LibreSSL، ليس لهذه العلامة أي تأثير.

X509_V_FLAG_POLICY_CHECK تُمكّن التحقق من سياسات الشهادة؛ افتراضيًا لا يتم إجراء أي فحص للسياسات. يتم إرسال معلومات إضافية إلى دالة الاستدعاء الخلفي للتحقق المتعلقة بفحص السياسات.

X509_V_FLAG_EXPLICIT_POLICY و X509_V_FLAG_INHIBIT_ANY و X509_V_FLAG_INHIBIT_MAP تضبط علامات "تتطلب سياسة صريحة" و "تمنع أي سياسة" و "تمنع تعيين السياسات" على التوالي، كما هو محدد في RFC 3280. يتم تجاهل هذه العلامات الثلاثة ما لم يتم تعيين X509_V_FLAG_POLICY_CHECK أيضًا.

libressl-X509_VERIFY_PARAM_set_flags(3)

الحزمة: libressl

التراخيص: ISC, custom:OpenSSL

NAME

X509_VERIFY_PARAM_set_flags, X509_VERIFY_PARAM_clear_flags, X509_VERIFY_PARAM_get_flags, X509_V_FLAG_CRL_CHECK, X509_V_FLAG_CRL_CHECK_LEAF, X509_V_FLAG_NEVER_CHECK_VALIDITY, X509_V_FLAG_NO_ALT_CHAINS, X509_V_FLAG_NO_CHECK_TIME, X509_V_FLAG_NOTIFY_POLICY, X509_V_FLAG_PARTIAL_CHAIN, X509_V_FLAG_POLICY_CHECK, X509_V_FLAG_SIGNATURE_EXTENDED, X509_V_FLAG_STRICT_RANK, X509_V_FLAG_TRUSTED_FIRST, X509_V_FLAG_USE_CHECK_TIME, X509_V_FLAG_USE_DELTAS, X509_V_FLAG_EXTENDED_CRL_SUPPORT, X509_V_FLAG_CHECK_SS_SIGNATURE, X509_V_FLAG_CB_ISSUER_CHECK, X509_V_FLAG_IGNORE_ Cromwell_POLICY, X509_V_FLAG_IGNORE_ Cromwell_UI - set and get verification flags

SYNOPSIS

#include <openssl/x509_vfy.h>

int X509_VERIFY_PARAM_set_flags(X509_VERIFY_PARAM *param, uint64_t flags);
int X509_VERIFY_PARAM_clear_flags(X509_VERIFY_PARAM *param, uint64_t flags);
uint64_t X509_VERIFY_PARAM_get_flags(const X509_VERIFY_PARAM *param);

/* Verification flags */
#define X509_V_FLAG_CRL_CHECK           0x00000001
#define X509_V_FLAG_CRL_CHECK_LEAF      0x00000002
#define X509_V_FLAG_NEVER_CHECK_VALIDITY 0x00000004
#define X509_V_FLAG_NO_ALT_CHAINS       0x00000008
#define X509_V_FLAG_NO_CHECK_TIME       0x00000010
#define X509_V_FLAG_NOTIFY_POLICY       0x00000020
#define X509_V_FLAG_PARTIAL_CHAIN       0x00000040
#define X509_V_FLAG_POLICY_CHECK        0x00000080
#define X509_V_FLAG_SIGNATURE_EXTENDED  0x00000100
#define X509_V_FLAG_STRICT_RANK         0x00000200
#define X509_V_FLAG_TRUSTED_FIRST       0x00000400
#define X509_V_FLAG_USE_CHECK_TIME      0x00000800
#define X509_V_FLAG_USE_DELTAS          0x00001000
#define X509_V_FLAG_EXTENDED_CRL_SUPPORT 0x00002000
#define X509_V_FLAG_CHECK_SS_SIGNATURE  0x00004000
#define X509_V_FLAG_CB_ISSUER_CHECK     0x00008000 /* deprecated */
#define X509_V_FLAG_IGNORE_ Cromwell_POLICY 0x00010000 /* deprecated */
#define X509_V_FLAG_IGNORE_ Cromwell_UI  0x00020000 /* deprecated */

DESCRIPTION

X509_VERIFY_PARAM_set_flags() sets the specified flags in the param verification parameters.

X509_VERIFY_PARAM_clear_flags() clears the specified flags in the param verification parameters.

X509_VERIFY_PARAM_get_flags() returns the current flags set in param.

The following flags can be set:

X509_V_FLAG_CRL_CHECK
Enables checking of certificate revocation lists (CRLs). If this flag is set, CRLs are checked for all certificates in the chain, except possibly the leaf certificate. See X509_V_FLAG_CRL_CHECK_LEAF.
X509_V_FLAG_CRL_CHECK_LEAF
Enables checking of CRLs for the leaf certificate as well. This is only meaningful if X509_V_FLAG_CRL_CHECK is also set.
X509_V_FLAG_NEVER_CHECK_VALIDITY
Disables checking of certificate and CRL validity periods. This flag is deprecated and has no effect. Use X509_V_FLAG_NO_CHECK_TIME instead.
X509_V_FLAG_NO_ALT_CHAINS
Suppresses checking for alternative chains. See X509_V_FLAG_TRUSTED_FIRST.
X509_V_FLAG_NO_CHECK_TIME
Disables checking of certificate and CRL validity periods. If this flag is set, the current time is not used for validation, and any time set using X509_VERIFY_PARAM_set_time() is ignored.
X509_V_FLAG_NOTIFY_POLICY
If X509_V_FLAG_NOTIFY_POLICY is set and policy checking is successful, a special status code is sent to the verification callback.
X509_V_FLAG_PARTIAL_CHAIN
Causes intermediate certificates in the trust store to be treated as trust-anchors, in the same way as the self-signed root CA certificates. This makes it possible to trust certificates issued by an intermediate CA without having to trust its ancestor root CA.
X509_V_FLAG_POLICY_CHECK
Enables policy checking. If this flag is set, the certificate policies extension is checked.
X509_V_FLAG_SIGNATURE_EXTENDED
This flag is currently unused.
X509_V_FLAG_STRICT_RANK
This flag is currently unused.
X509_V_FLAG_TRUSTED_FIRST
When constructing the certificate chain, search the trust store for issuer certificates before searching the provided untrusted certificates. Local issuer certificates are often more likely to satisfy local security requirements and lead to a locally trusted root. This is especially important when some certificates in the trust store have explicit trust settings.
X509_V_FLAG_USE_CHECK_TIME
If X509_V_FLAG_USE_CHECK_TIME is set, the validity period of certificates and CRLs is checked. In this case, X509_V_FLAG_NO_CHECK_TIME is ignored. If the validation time was set with X509_VERIFY_PARAM_set_time(), that time is used. If X509_VERIFY_PARAM_set_time() was not called, the UNIX Epoch (January 1, 1970) is used.
X509_V_FLAG_USE_DELTAS
If X509_V_FLAG_USE_DELTAS is set, delta CRLs (if present) are used to determine certificate status. If not set, deltas are ignored.
X509_V_FLAG_EXTENDED_CRL_SUPPORT
By default some additional features such as indirect CRLs and CRLs signed by different keys are disabled. If X509_V_FLAG_EXTENDED_CRL_SUPPORT is set, they are enabled.
X509_V_FLAG_CHECK_SS_SIGNATURE
Enables checking of the root CA self signed certificate signature. By default this check is disabled because it doesn't add any additional security but in some cases applications might want to check the signature anyway. A side effect of not checking the root CA signature is that disabled or unsupported message digests on the root CA are not treated as fatal errors.
X509_V_FLAG_CB_ISSUER_CHECK
The deprecated X509_V_FLAG_CB_ISSUER_CHECK flag used to enable debugging of certificate issuer checks. It is provided for binary backwards compatibility and has no effect.

If neither X509_V_FLAG_USE_CHECK_TIME nor X509_V_FLAG_NO_CHECK_TIME is set, the validity period of certificates and CRLs is checked using the current time. This is the default behaviour. In this case, if a validation time was set with X509_VERIFY_PARAM_set_time() but X509_V_FLAG_USE_CHECK_TIME was later cleared with X509_VERIFY_PARAM_clear_flags(), the configured validation time is ignored and the current time is used anyway.

If X509_V_FLAG_USE_CHECK_TIME is not set but X509_V_FLAG_NO_CHECK_TIME is set, the validity period of certificates and CRLs is not checked at all, and like in the previous case, any configured validation time is ignored.

RETURN VALUES

X509_VERIFY_PARAM_set_flags() and X509_VERIFY_PARAM_clear_flags() return 1 on success and 0 on failure. For valid flags, they never fail.

X509_VERIFY_PARAM_get_flags() returns the current flags.

VERIFICATION FLAGS

If X509_V_FLAG_NOTIFY_POLICY is set and policy checking is successful, a special status code is sent to the verification callback.

By default some additional features such as indirect CRLs and CRLs signed by different keys are disabled. If X509_V_FLAG_EXTENDED_CRL_SUPPORT is set, they are enabled.

If X509_V_FLAG_USE_DELTAS is set, delta CRLs (if present) are used to determine certificate status. If not set, deltas are ignored.

X509_V_FLAG_CHECK_SS_SIGNATURE enables checking of the root CA self signed certificate signature. By default this check is disabled because it doesn't add any additional security but in some cases applications might want to check the signature anyway. A side effect of not checking the root CA signature is that disabled or unsupported message digests on the root CA are not treated as fatal errors.

The deprecated X509_V_FLAG_CB_ISSUER_CHECK flag used to enable debugging of certificate issuer checks. It is provided for binary backwards compatibility and has no effect.

When X509_V_FLAG_TRUSTED_FIRST is set, construction of the certificate chain in X509_verify(3) will search the trust store for issuer certificates before searching the provided untrusted certificates. Local issuer certificates are often more likely to satisfy local security requirements and lead to a locally trusted root. This is especially important when some certificates in the trust store have explicit trust settings; see the trust settings options of the x509 command in openssl(1).

The X509_V_FLAG_NO_ALT_CHAINS flag suppresses checking for alternative chains. By default, unless X509_V_FLAG_TRUSTED_FIRST is set, when building a certificate chain, if the first certificate chain found is not trusted, then OpenSSL will attempt to replace untrusted certificates supplied by the peer with certificates from the trust store to see if an alternative chain can be found that is trusted.

The X509_V_FLAG_PARTIAL_CHAIN flag causes intermediate certificates in the trust store to be treated as trust-anchors, in the same way as the self-signed root CA certificates. This makes it possible to trust certificates issued by an intermediate CA without having to trust its ancestor root CA.

If X509_V_FLAG_USE_CHECK_TIME is set, the validity period of certificates and CRLs is checked. In this case, X509_V_FLAG_NO_CHECK_TIME is ignored. If the validation time was set with X509_VERIFY_PARAM_set_time(), that time is used. If X509_VERIFY_PARAM_set_time() was not called, the UNIX Epoch (January 1, 1970) is used.

If neither X509_V_FLAG_USE_CHECK_TIME nor X509_V_FLAG_NO_CHECK_TIME is set, the validity period of certificates and CRLs is checked using the current time. This is the default behaviour. In this case, if a validation time was set with X509_VERIFY_PARAM_set_time() but X509_V_FLAG_USE_CHECK_TIME was later cleared with X509_VERIFY_PARAM_clear_flags(), the configured validation time is ignored and the current time is used anyway.

If X509_V_FLAG_USE_CHECK_TIME is not set but X509_V_FLAG_NO_CHECK_TIME is set, the validity period of certificates and CRLs is not checked at all, and like in the previous case, any configured validation time is ignored.

EXAMPLES

Enable CRL checking when performing certificate verification during SSL connections associated with an SSL_CTX structure ctx:

X509_VERIFY_PARAM *param;

param = X509_VERIFY_PARAM_new();
X509_VERIFY_PARAM_set_flags(param, X509_V_FLAG_CRL_CHECK);
SSL_CTX_set1_param(ctx, param);
X509_VERIFY_PARAM_free(param);

BUGS

Delta CRL checking is currently primitive. Only a single delta can be used and (partly due to limitations of X509_STORE) constructed CRLs are not maintained.

If CRLs checking is enabled, CRLs are expected to be available in the corresponding X509_STORE structure. No attempt is made to download CRLs from the CRL distribution points extension.
