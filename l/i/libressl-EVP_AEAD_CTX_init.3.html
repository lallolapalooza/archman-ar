الوصف

AEAD (التشفير الموثق مع بيانات إضافية) يجمع بين السرية والتكامل في بدائي واحد. خوارزميات AEAD تأخذ مفتاحًا ويمكنها بعد ذلك ختم وفتح رسائل فردية. كل رسالة لديها غيرس (nonce) فريد لكل رسالة، اختياريًا، بيانات إضافية يتم توثيقها ولكن لا يتم تضمينها في المخرجات.

EVP_AEAD_CTX_new() تخصص سياقًا جديدًا للاستخدام مع EVP_AEAD_CTX_init(). يمكن تنظيفه لإعادة الاستخدام مع EVP_AEAD_CTX_cleanup() ويجب تحريره مع EVP_AEAD_CTX_free().

EVP_AEAD_CTX_free() تنظف ctx وتحرر المساحة المخصصة له.

EVP_AEAD_CTX_init() تهيئة السياق ctx لخوارزمية AEAD المحددة aead. يجب أن يكون الوسيط engine NULL للتنفيذ الافتراضي؛ القيم الأخرى غير مدعومة. قد يتم اقتطاع علامات المصادقة عن طريق تمرير طول العلامة. وسيط tag_len بقيمة EVP_AEAD_DEFAULT_TAG_LENGTH، والتي قيمتها 0، تسبب استخدام طول العلامة الافتراضي.

EVP_AEAD_CTX_cleanup() تحرر أي بيانات مخصصة للسياق ctx. بعد EVP_AEAD_CTX_cleanup()، يكون ctx في نفس حالة ما بعد EVP_AEAD_CTX_new().

EVP_AEAD_CTX_open() توثق المدخل in والبيانات الإضافية الاختيارية ad، وفك تشفير المدخل وكتابته كمخرج out. يمكن استدعاء هذه الدالة (مع نفس EVP_AEAD_CTX) بالتوازي مع نفسها أو مع EVP_AEAD_CTX_seal(). يتم كتابة عدد لا يزيد عن عدد بايتات المدخل كمخرج. لضمان النجاح، يجب أن يكون max_out_len مساويًا على الأقل لطول المدخل in_len. عند العودة بنجاح، يتم تعيين out_len إلى العدد الفعلي للبايتات المكتوبة. يجب أن يكون طول الـ nonce المحدد بـ nonce_len مساويًا لنتيجة EVP_AEAD_nonce_length لهذا AEAD. EVP_AEAD_CTX_open() لا تنتج مخرجات جزئية أبدًا. إذا كان max_out_len غير كافٍ، فسيتم إرجاع صفر و out_len سيتم تعيينه إلى صفر. إذا كان المدخل والمخرج متداخلين، فيجب أن يكون out <= in.

EVP_AEAD_CTX_seal() تشفير وتوثيق المدخل وتوثيق أي بيانات إضافية مقدمة في ad، مع كتابة المدخل المشفر وعلامة المصادقة كمخرج out. يمكن استدعاء هذه الدالة (مع نفس EVP_AEAD_CTX) بالتوازي مع نفسها أو مع EVP_AEAD_CTX_open(). يتم كتابة ما لا يزيد عن max_out_len بايت كمخرج، ولضمان النجاح، يجب أن تكون هذه القيمة هي in_len زائد نتيجة EVP_AEAD_max_overhead(). عند العودة بنجاح، يتم تعيين out_len إلى العدد الفعلي للبايتات المكتوبة. يجب أن يكون طول الـ nonce المحدد بـ nonce_len مساويًا لنتيجة EVP_AEAD_nonce_length() لهذا AEAD. EVP_AEAD_CTX_seal() لا تنتج مخرجات جزئية أبدًا. إذا كان max_out_len غير كافٍ، فسيتم إرجاع صفر و out_len سيتم تعيينه إلى صفر. إذا كان المدخل والمخرج متداخلين، فيجب أن يكون out <= in.

EVP_AEAD_key_length(), EVP_AEAD_max_overhead(), EVP_AEAD_max_tag_len(), و EVP_AEAD_nonce_length() توفر معلومات حول خوارزمية AEAD aead.

EVP_AEAD_max_tag_len() تعيد الحد الأقصى لطول العلامة الذي يمكن أن يكون

DESCRIPTION

The EVP_AEAD interface provides a unified interface to Authenticated Encryption with Associated Data (AEAD) ciphers. AEAD ciphers provide both confidentiality and integrity of data. They can also protect associated data (AAD) which is not encrypted but must have the same integrity protection.

The functions are:

EVP_AEAD_CTX_new(), EVP_AEAD_CTX_free()
Allocate and free an EVP_AEAD_CTX object. The latter must be called for every EVP_AEAD_CTX that is allocated with EVP_AEAD_CTX_new().
EVP_AEAD_CTX_init(), EVP_AEAD_CTX_init_with_direction()
Initialise the EVP_AEAD_CTX object. The aead parameter is a pointer to an EVP_AEAD object. The key parameter is the secret key. The key_len parameter is the length of the key in bytes. The tag_len parameter is the length of the authentication tag in bytes. If tag_len is EVP_AEAD_DEFAULT_TAG_LENGTH, then the default tag length for the given aead is used. The maximum value that can be passed for tag_len is EVP_AEAD_MAX_TAG_LENGTH. The EVP_AEAD_CTX_init_with_direction() function allows to specify the direction of operation, EVP_AEAD_ENCRYPT or EVP_AEAD_DECRYPT. If the direction is not specified, it is assumed to be EVP_AEAD_ENCRYPT.
EVP_AEAD_CTX_seal()
Seal (encrypt and authenticate) the plaintext in of length in_len using the nonce nonce of length nonce_len and optional associated data aad of length aad_len. The result is written to out, and the actual length is written to out_len. max_out_len is the maximum buffer size of out. The value of nonce_len must be equal to the nonce length returned by EVP_AEAD_nonce_length().
EVP_AEAD_CTX_open()
Open (decrypt and verify) the ciphertext in of length in_len using the nonce nonce of length nonce_len and optional associated data aad of length aad_len. The result is written to out, and the actual length is written to out_len. max_out_len is the maximum buffer size of out. The value of nonce_len must be equal to the nonce length returned by EVP_AEAD_nonce_length().
EVP_AEAD_CTX_export_key()
Export the key from the context. This is primarily useful for key derivation. The maximum key length is returned in key_len.
EVP_AEAD_CTX_get_tag_len()
Returns the tag length that was set during initialization of the context. This should be less than or equal to EVP_AEAD_MAX_TAG_LENGTH.
EVP_AEAD_CTX_get_iv_len()
Returns the IV length (nonce length) for the AEAD.
EVP_AEAD_CTX_get_encrypt_len()
Returns the maximum ciphertext length for a given plaintext length in_len. This includes the authentication tag.
EVP_AEAD_CTX_get_aad_len()
Returns the maximum length of associated data (AAD) that can be processed. This is typically the same as the maximum plaintext length.
EVP_AEAD_CTX_use_tag(), EVP_AEAD_CTX_get_tag()
These functions are used to handle the tag in a two-pass encryption/decryption process. EVP_AEAD_CTX_use_tag() is used during encryption to specify the tag to be appended to the ciphertext. EVP_AEAD_CTX_get_tag() is used during decryption to retrieve the tag from the ciphertext.
EVP_AEAD_CTX_set_nonce_length()
Sets the nonce length for the context. This is an alternative to passing the nonce length to EVP_AEAD_CTX_init().
EVP_AEAD_key_length()
Returns the key length for the AEAD.
EVP_AEAD_nonce_length()
Returns the nonce length for the AEAD.
EVP_AEAD_max_overhead()
Returns the maximum number of additional bytes added by the act of sealing data with the AEAD. This is typically the size of the authentication tag.
EVP_AEAD_max_tag_len()
Returns the maximum tag length that can be used with this AEAD.
EVP_aead_aes_128_gcm()
AES-128 in Galois/Counter Mode (GCM). This AEAD uses a key length of 16 bytes and a nonce length of 12 bytes. The default tag length is 16 bytes.
EVP_aead_aes_256_gcm()
AES-256 in GCM. This AEAD uses a key length of 32 bytes and a nonce length of 12 bytes. The default tag length is 16 bytes.
EVP_aead_chacha20_poly1305()
ChaCha20 combined with the Poly1305 message authenticator. This AEAD uses a key length of 32 bytes and a nonce length of 12 bytes. The default tag length is 16 bytes. The constant EVP_CHACHAPOLY_TLS_TAG_LEN is defined and has the value 16.
EVP_aead_xchacha20_poly1305()
XChaCha20 combined with the Poly1305 message authenticator. This AEAD uses a key length of 32 bytes and a nonce length of 24 bytes. The default tag length is 16 bytes.

The constant EVP_AEAD_MAX_TAG_LENGTH is defined as the largest value that can be passed as the tag_len argument to EVP_AEAD_CTX_init(). No built-in EVP_AEAD object has a maximum tag length larger than this constant.

All cipher algorithms have a fixed key length unless otherwise stated. The following ciphers are available:

EVP_aead_aes_128_gcm()
AES-128 in Galois Counter Mode, using a key_len of 16 bytes and a nonce_len of 12 bytes.
EVP_aead_aes_256_gcm()
AES-256 in Galois Counter Mode, using a key_len of 32 bytes and a nonce_len of 12 bytes.
EVP_aead_chacha20_poly1305()
ChaCha20 with a Poly1305 authenticator, using a key_len of 32 bytes and a nonce_len of 12 bytes. The constant EVP_CHACHAPOLY_TLS_TAG_LEN specifies the length of the authentication tag in bytes and has a value of 16.
EVP_aead_xchacha20_poly1305()
XChaCha20 with a Poly1305 authenticator, using a key_len of 32 bytes and a nonce_len of 24 bytes.

Unless compatibility with other implementations like OpenSSL or BoringSSL is required, using the EVP_AEAD interface to AEAD ciphers is recommended in preference to the functions documented in the EVP_EncryptInit(3), EVP_aes_256_gcm(3), and EVP_chacha20_poly1305(3) manual pages. The code then becomes transparent to the AEAD cipher used and much more flexible. It is also safer to use as it prevents common mistakes with the EVP APIs.

RETURN VALUES

EVP_AEAD_CTX_new() returns the new EVP_AEAD_CTX object on success; otherwise NULL is returned and errno is set to ENOMEM.

EVP_AEAD_CTX_init(), EVP_AEAD_CTX_open(), and EVP_AEAD_CTX_seal() return 1 for success or zero for failure.

EVP_AEAD_key_length() returns the length of the key used for this AEAD.

EVP_AEAD_max_overhead() returns the maximum number of additional bytes added by the act of sealing data with the AEAD.

EVP_AEAD_max_tag_len() returns the maximum tag length when using this AEAD.

EVP_AEAD_nonce_length() returns the length of the per-message nonce.

EXAMPLES

Encrypt a string using ChaCha20-Poly1305:

const EVP_AEAD *aead = EVP_aead_chacha20_poly1305();
static const unsigned char nonce[32] = {0};
size_t buf_len, nonce_len;
EVP_AEAD_CTX *ctx;

ctx = EVP_AEAD_CTX_new();
EVP_AEAD_CTX_init(ctx, aead, key32, EVP_AEAD_key_length(aead),
    EVP_AEAD_DEFAULT_TAG_LENGTH, NULL);
nonce_len = EVP_AEAD_nonce_length(aead);

EVP_AEAD_CTX_seal(ctx, out, &out_len, BUFSIZE, nonce,
    nonce_len, in, in_len, NULL, 0);

EVP_AEAD_CTX_free(ctx);

HISTORY

AEAD is based on the implementation by Adam Langley for Chromium/BoringSSL and first appeared in OpenBSD 5.6.

EVP_AEAD_CTX_new() and EVP_AEAD_CTX_free() first appeared in OpenBSD 7.1.

CAVEATS

The original publications and code by Adam Langley used a modified AEAD construction that is incompatible with the common style used by AEAD in TLS and incompatible with RFC 7905:

A. Langley and W. Chang, ChaCha20 and Poly1305 based Cipher Suites for TLS, draft-agl-tls-chacha20poly1305-04, November 2013.

Y. Nir and A. Langley, ChaCha20 and Poly1305 for IETF Protocols, RFC 8439, June 2018.

In particular, the original version used a nonce_len of 8 bytes.
