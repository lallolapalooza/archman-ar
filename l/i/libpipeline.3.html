void pipeline_connect(pipeline *source, pipeline *sink, ...)

ربط مدخل واحد أو أكثر من خطوط الأنابيب المغسلة بمخرج خط أنابيب مصدر. قد يبدأ خط أنابيب المصدر، ولكن في هذه الحالة يجب استدعاء pipeline_want_out() مع fd سالب؛ وإلا، يستدعي pipeline_want_out(source، -1). على أي حال، يستدعي pipeline_want_in(sink، -1) على جميع المغاسل، ولا يُسمح ببدء أي منها. إنهاء الوسائط بـ nullptr (قبل C23: (void *) 0).

هذا اتصال على مستوى التطبيق؛ قد يتم اعتراض البيانات بين خطوط الأنابيب بواسطة البرنامج قبل استدعاء pipeline_pump()، التي تبدأ تدفق البيانات من المصدر إلى المغاسل. تكون مفيدة بشكل أساسي عندما يكون هناك أكثر من مغسلة واحدة، وفي هذه الحالة لا يمكن ببساطة دمج خطوط الأنابيب في واحد.

النتيجة مشابهة لـ tee(1)، باستثناء أنه يمكن إرسال الإخراج إلى أكثر من مكانين ويمكن إرساله بسهولة إلى عمليات متعددة.

void pipeline_want_in(pipeline *p, int fd)
 
void pipeline_want_out(pipeline *p, int fd)

Set file descriptors to use as the input and output of the whole pipeline. If non-negative, fd is used directly as a file descriptor. If negative, pipeline_start() will create pipes and store the input writing half and the output reading half in the pipeline's infd or outfd field as appropriate. The default is to leave input and output as stdin and stdout unless pipeline_want_infile() or pipeline_want_outfile() respectively has been called.

Calling these functions supersedes any previous call to pipeline_want_infile() or pipeline_want_outfile() respectively.

void pipeline_want_infile(pipeline *p, const char *file)
 
void pipeline_want_outfile(pipeline *p, const char *file)

Set file names to open and use as the input and output of the whole pipeline. This may be more convenient than supplying file descriptors, and guarantees that the files are opened with the same privileges under which the pipeline is run.

Calling these functions (even with NULL, which returns to the default of leaving input and output as stdin and stdout) supersedes any previous call to pipeline_want_in() or pipeline_want_outfile() respectively.

The given files will be opened when the pipeline is started. If an output file does not already exist, it is created (with mode 0666 modified in the usual way by umask); if it does exist, then it is truncated.

void pipeline_ignore_signals(pipeline *p, int ignore_signals)

If ignore_signals is non-zero, ignore SIGINT and SIGQUIT in the calling process while the pipeline is running, like system(3). Otherwise, and by default, leave their dispositions unchanged.

معالجة الإشارات

libpipeline يقوم بتثبيت معالج إشارة لـ SIGCHLD، ويجمع حالة الخروج للعمليات الفرعية في pipeline_wait(). يجب على التطبيقات التي تستخدم هذه المكتبة إما الامتناع عن تغيير تصرف SIGCHLD (بمعنى آخر، يجب الاعتماد على libpipeline لجميع عمليات معالجة العمليات الفرعية) أو يجب عليها التأكد من استعادة معالج libpipeline لـ SIGCHLD قبل استدعاء أي من وظائفها.

إذا تم تعيين علامة ignore_signals في خط الأنابيب (وهو الافتراضي)، فسيتم تجاهل الإشارات SIGINT و SIGQUIT في العملية الأصلية أثناء تشغيل العمليات الفرعية. يعكس هذا سلوك system(3).

libpipeline يترك العمليات الفرعية بالتصرف الافتراضي لـ SIGPIPE، وهو إنهاء العملية. يتجاهل SIGPIPE في العملية الأصلية أثناء تشغيل pipeline_pump().

حصاد العمليات الفرعية

libpipeline يقوم بتثبيت معالج SIGCHLD الذي سيحاول حصاد العمليات الفرعية التي خرجت. هذا يستدعي waitpid(2) مع -1، لذا سيقوم بحصاد أي عملية فرعية، وليس فقط تلك التي تم إنشاؤها عبر هذه المكتبة. في الوقت الحالي، هذا يعني أنه إذا قامت البرنامج المتصل بتشعب عمليات فرعية أخرى قد تخرج أثناء تشغيل خط الأنابيب، فلا يضمن البرنامج القدرة على جمع حالات خروج تلك العمليات.

لا يجب الاعتماد على هذا السلوك، وقد يتم تعديله في المستقبل إما لحصاد العمليات الفرعية التي أنشأتها هذه المكتبة فقط أو لتوفير طريقة لإعادة الحالات الأجنبية إلى التطبيق. يرجى الاتصال بالمؤلف إذا كان لديك مثال تطبيقي وترغب في المساعدة في تصميم مثل هذه الواجهة.

البيئة

إذا تم تعيين متغير البيئة PIPELINE_DEBUG إلى "1"، فسوف تقوم libpipeline بإصدار رسائل تصحيح الأخطاء على الخطأ القياسي.

إذا تم تعيين متغير البيئة PIPELINE_QUIET إلى أي قيمة، فسوف تمتنع libpipeline عن طباعة رسالة خطأ عند إنهاء عملية فرعية بواسطة إشارة. تمت الإضافة في libpipeline 1.4.0.

أمثلة

في الأمثلة التالية، أسماء الوظائف التي تبدأ بـ pipecmd_ أو pipeline_ هي وظائف libpipeline حقيقية، بينما أي أسماء وظائف أخرى هي شيفرة زائفة. تستخدم هذه الأمثلة الكلمة المفتاحية nullptr بنمط C23 لإنهاء قوائم الوسيطات المتغيرة؛ في الإصدارات الأقدم من C، استخدم (void *) 0 بدلاً من ذلك.

الحالة الأبسط هي بسيطة. لتشغيل أمر واحد، مثل mv source dest:

pipeline *p = pipeline_new_command_args ("mv", source, dest, nullptr);
int status = pipeline_run (p);

غالبًا ما تستخدم libpipeline لمحاكاة خطوط أنابيب shell، مثل المثال التالي:

zsoelim < input-file | tbl | nroff -mandoc -Tutf8

الكود اللازم لإنشاء هذا سيكون:

pipeline *p;
int status;

p = pipeline_new ();
pipeline_want_infile (p, "input-file");
pipeline_command_args (p, "zsoelim", nullptr);
pipeline_command_args (p, "tbl", nullptr);
pipeline_command_args (p, "nroff", "-mandoc", "-Tutf8", nullptr);
status = pipeline_run (p);

قد ترغب في بناء أمر ديناميكيًا:

pipecmd *manconv = pipecmd_new_args ("manconv", "-f", from_code,
                                     "-t", "UTF-8", nullptr);
if (quiet)
        pipecmd_arg (manconv, "-q");
pipeline_command (p, manconv);

ربما تحتاج إلى تعيين متغير بيئة فقط أثناء تشغيل أمر معين:

pipecmd *less = pipecmd_new ("less");
pipecmd_setenv (less, "LESSCHARSET", lesscharset);

قد تجد نفسك بحاجة إلى تمرير مخرجات خط أنابيب واحد إلى عدة خطوط أنابيب أخرى، بترتيب "tee":

pipeline *source, *sink1, *sink2;

source = make_source ();
sink1 = make_sink1 ();
sink2 = make_sink2 ();
pipeline_connect (source, sink1, sink2, nullptr);
/* ضخ البيانات بين خطوط الأنابيب هذه حتى لا يتبقى شيء. */
pipeline_pump (source, sink1, sink2, nullptr);
pipeline_free (sink2);
pipeline_free (sink1);
pipeline_free (source);

ربما يكون أحد أوامرك في الواقع دالة داخل العملية، بدلاً من برنامج خارجي:

pipecmd *inproc = pipecmd_new_function ("in-process", &func,
                                        NULL, NULL);
pipeline_command (p, inproc);

في بعض الأحيان يحتاج برنامجك إلى استهلاك مخرجات خط أنابيب، بدلاً من إرسالها كلها إلى عملية فرعية أخرى:

pipeline *p = make_pipeline ();
const char *line;

pipeline_want_out (p, -1);
pip
