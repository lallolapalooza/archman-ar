عمليات حسابية مؤجلة.

type 'a t = 'a CamlinternalLazy.t

قيمة من النوع 'a Lazy.t هي عملية حسابية مؤجلة، تسمى تعليقاً، ولها نتيجة من النوع 'a . الصيغة التعبيرية الخاصة lazy (expr) تنشئ تعليقاً لعملية حساب expr ، دون حساب expr نفسه بعد. "إجبار" التعليق سيقوم بحساب expr وإرجاع نتيجته. مطابقة تعليق بصيغة النمط الخاصة lazy(pattern) تقوم أيضاً بحساب التعبير الأساسي ومحاولة ربطه بـ pattern :

      let lazy_option_map f x =
      match x with
      | lazy (Some x) -> Some (Lazy.force f x)
      | _ -> None

ملاحظة: إذا ظهرت أنماط lazy في حالات متعددة في مطابقة نمط، فقد يتم إجبار تعبيرات lazy حتى خارج الحالة المختارة في النهاية بواسطة مطابقة النمط. في المثال أعلاه، يتم دائمًا حساب التعليق x.

ملاحظة: lazy_t هو الباني النوعي المدمج الذي يستخدمه المترجم للكلمة المفتاحية lazy. يجب ألا تستخدمه مباشرة. استخدم دائمًا Lazy.t بدلاً من ذلك.

ملاحظة: Lazy.force ليست آمنة للتزامن. إذا كنت تستخدم هذه الوحدة مع ألياف متعددة، أو خيوط نظام، أو نطاقات، فستحتاج إلى إضافة بعض الأقفال. ومع ذلك، تضمن الوحدة سلامة الذاكرة، وبالتالي، فإن الوصول المتزامن إلى هذه الوحدة لن يؤدي إلى انهيار ولكن السلوك غير محدد.

ملاحظة: إذا تمت ترجمة البرنامج باستخدام الخيار -rectypes، فإن تعريفات تكرارية غير صحيحة من الشكل let rec x = lazy x أو let rec x = lazy(lazy(...(lazy x))) يتم قبولها بواسطة مدقق الأنواع وتؤدي، عند إجبارها، إلى قيم غير صحيحة تسبب حلقات لا نهائية في جامع القمامة وأجزاء أخرى من نظام التشغيل. بدون الخيار -rectypes، يتم رفض هذه التعريفات التكرارية غير الصحيحة بواسطة مدقق الأنواع.

exception Undefined

يتم رفعها عند إجبار تعليق بشكل متزامن من ألياف أو خيوط نظام أو نطاقات متعددة، أو عندما يحاول التعليق إجبار نفسه بشكل تكراري.

val force : 'a t -> 'a

force x تجبر التعليق x وترجع نتيجته. إذا تم إجبار x بالفعل، فإن Lazy.force x يرجع نفس القيمة مرة أخرى دون إعادة حسابها. إذا رفعت استثناءً، فسيتم رفع نفس الاستثناء مرة أخرى.

يرفع Undefined (انظر Lazy.Undefined).

المكررات

val map : ('a -> 'b) -> 'a t -> 'b t

map f x يرجع تعليقًا، عند إجباره، يجبر x ويطبق f على قيمته.

إنها مكافئة لـ lazy (f (Lazy.force x)).

منذ 4.13

التفكير في التعليقات المجبرة بالفعل

val is_val : 'a t -> bool

is_val x يرجع true إذا تم إجبار x بالفعل ولم يرفع استثناءً.

منذ 4.00

val from_val : 'a -> 'a t

from_val v يقوم بتقييم v أولاً (كما تفعل أي دالة) ويرجع تعليقًا مجبرًا بالفعل لنتيجته. إنه نفس الشيء مثل let x = v in lazy x ، ولكنه يستخدم اختبارات ديناميكية لتحسين إنشاء التعليق في بعض الحالات.

منذ 4.00

val map_val : ('a -> 'b) -> 'a t -> 'b t

map_val f x يطبق f مباشرة إذا تم إجبار x بالفعل، وإلا فإنه يتصرف مثل map f x.

عندما يتم إجبار x بالفعل، فإن هذا السلوك يوفر بناء تعليق، ولكنه من ناحية أخرى يقوم بعمل أكثر بشكل استباقي قد لا يكون مفيدًا إذا لم تقم أبدًا بإجبار نتيجة الدالة.

إذا رفعت f استثناءً، فسيتم رفعه فورًا عند is_val x ، أو يتم رفعه فقط عند إجبار الـ thunk بخلاف ذلك.

إذا لم يرفع map_val f x استثناءً، فإن is_val (map_val f x) يساوي is_val x.

منذ 4.13

متقدم

التعريفات التالية للاستخدامات المتقدمة فقط؛ تتطلب الإلمام بمخطط الترجمة الكسول لاستخدامها بشكل مناسب.

val from_fun : (unit -> 'a) -> 'a t

from_fun f هو نفس الشيء مثل lazy (f ()) ولكن أكثر كفاءة قليلاً.

يجب استخدامه فقط إذا كانت الدالة f معرفة بالفعل. على وجه الخصوص، من الأكثر كفاءة دائمًا كتابة from_fun (fun () -> expr) بدلاً من lazy expr.

منذ 4.00

val force_val : 'a t -> 'a

force_val x تجبر التعليق x وترجع نتيجته. إذا تم إجبار x بالفعل، فإن force_val x يرجع نفس القيمة مرة أخرى دون إعادة حسابها.

إذا أدى حساب x إلى رفع استثناء، فمن غير المحدد ما إذا كان force_val x يرفع نفس الاستثناء أو Lazy.Undefined.

يرفع Undefined إذا حاول إجبار x إجبار x نفسه بشكل تكراري.

يرفع Undefined (انظر Lazy.Undefined).
