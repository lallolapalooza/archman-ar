--alternate
ابدأ في وضع الماكرو البديل.
--compress-debug-sections
ضغط أقسام تصحيح DWARF باستخدام zlib مع SHF_COMPRESSED من ELF ABI. قد لا يكون ملف الكائن الناتج متوافقًا مع أدوات الربط والأدوات المساعدة القديمة لملفات الكائنات. لاحظ أنه إذا أدى الضغط إلى جعل قسم معين أكبر، فلن يتم ضغطه.
--compress-debug-sections=none
--compress-debug-sections=zlib
--compress-debug-sections=zlib-gnu
--compress-debug-sections=zlib-gabi
--compress-debug-sections=zstd
تتحكم هذه الخيارات في كيفية ضغط أقسام تصحيح DWARF. --compress-debug-sections=none يعادل --nocompress-debug-sections. --compress-debug-sections=zlib و --compress-debug-sections=zlib-gabi يعادلان --compress-debug-sections. --compress-debug-sections=zlib-gnu يضغط أقسام تصحيح DWARF باستخدام تنسيق zlib-gnu المهمل. يتم إعادة تسمية أقسام التصحيح لتبدأ بـ .zdebug. --compress-debug-sections=zstd يضغط أقسام تصحيح DWARF باستخدام zstd. ملاحظة - إذا أدى الضغط فعليًا إلى جعل القسم أكبر، فلن يتم ضغطه أو إعادة تسميته.
--nocompress-debug-sections
لا تضغط أقسام تصحيح DWARF. هذا عادة هو الافتراضي لجميع الأهداف باستثناء x86/x86_64، ولكن يمكن استخدام خيار التكوين لتجاوز هذا.
-D
تمكين التصحيح في الخلفيات الخاصة بالهدف، إذا كانت مدعومة. بخلاف ذلك يتم تجاهلها. حتى لو تم تجاهلها، يتم قبول هذا الخيار للتوافق مع البرامج النصية مع استدعاءات لأدوات تجميع أخرى.
--debug-prefix-map old=new
عند تجميع الملفات في الدليل old، سجل معلومات التصحيح التي تصفها على أنها في new بدلاً من ذلك.
--defsym sym=value
تعريف الرمز sym ليكون value قبل تجميع ملف الإدخال. value يجب أن يكون ثابتًا صحيحًا. كما في C، يشير البادئة 0x إلى قيمة سداسية عشرية، ويشير البادئة 0 إلى قيمة ثمانية. يمكن تجاوز قيمة الرمز داخل ملف مصدر عبر استخدام توجيه ".set".
--dump-config
يعرض كيفية تكوين المجمّع ثم يخرج.
--elf-stt-common=no
--elf-stt-common=yes
تتحكم هذه الخيارات فيما إذا كان مجمّع ELF يجب أن ينشئ رموزًا مشتركة بالنوع "STT_COMMON". يمكن التحكم في الافتراضي بواسطة خيار التكوين --enable-elf-stt-common.
--emulation=name
إذا تم تكوين المجمّع لدعم تكوينات هدف مختلفة متعددة، فيمكن استخدام هذا الخيار لتحديد الشكل المطلوب.
-f
"fast"---تخطي معالجة المسافات البيضاء والتعليقات (افترض أن المصدر هو إخراج المترجم).
-g
--gen-debug
إنشاء معلومات تصحيح لكل سطر مصدر للمجمّع باستخدام أي تنسيق تصحيح يفضله الهدف. هذا يعني حاليًا إما STABS أو ECOFF أو DWARF2. عندما يكون تنسيق التصحيح هو DWARF، يتم إصدار قسم ".debug_info" و ".debug_line" فقط عندما لا ينشئ ملف التجميع قسمًا بنفسه.
--gstabs
إنشاء معلومات تصحيح stabs لكل سطر للمجمّع. قد يساعد هذا في تصحيح أخطاء كود المجمّع، إذا كان المصحح يمكنه التعامل معه.
--gstabs+
إنشاء معلومات تصحيح stabs لكل سطر للمجمّع، مع امتدادات GNU التي ربما لا يمكن لـ gdb فقط التعامل معها، والتي يمكن أن تتسبب في تعطل مصححات أخرى أو رفض قراءة برنامجك. قد يساعد هذا في تصحيح أخطاء كود المجمّع. حاليًا، الامتداد الوحيد لـ GNU هو موقع دليل العمل الحالي وقت التجميع.
--gdwarf-2
إنشاء معلومات تصحيح DWARF2 لكل سطر للمجمّع. قد يساعد هذا في تصحيح أخطاء كود المجمّع، إذا كان المصحح يمكنه التعامل معه. ملاحظة --- هذا الخيار مدعوم فقط من قبل بعض الأهداف، وليس كلها.
--gdwarf-3
هذا الخيار هو نفسه الخيار --gdwarf-2، باستثناء أنه يسمح بإمكانية إنشاء معلومات تصحيح إضافية وفقًا للإصدار 3 من مواصفات DWARF. ملاحظة - تمكين هذا الخيار لا يضمن إنشاء أي معلومات إضافية، والاختيار للقيام بذلك يكون على أساس كل هدف.

--gdwarf-5
هذا الخيار هو نفسه الخيار --gdwarf-2، باستثناء أنه يسمح بإمكانية إنشاء معلومات تصحيح إضافية وفقًا للإصدار 5 من مواصفات DWARF. ملاحظة - تمكين هذا الخيار لا يضمن إنشاء أي معلومات إضافية، والاختيار للقيام بذلك يكون على أساس كل هدف.
--gdwarf-sections
بدلاً من إنشاء قسم .debug_line، قم بإنشاء سلسلة من أقسام .debug_line.foo حيث foo هو اسم قسم الكود المقابل. على سبيل المثال، قسم الكود المسمى .text.func سيتم وضع معلومات سطر الأوامر الخاص به في قسم يسمى .debug_line.text.func. إذا كان قسم الكود يسمى ببساطة .text، فسيظل قسم سطر الأوامر يسمى ببساطة .debug_line بدون أي لاحقة.
--gdwarf-cie-version=version
تحكم في إصدار مدخلات المعلومات المشتركة لـ DWARF (CIEs) التي يتم إنتاجها. عندما لا يتم تحديد هذا العلم، يكون الافتراضي هو الإصدار 1، على الرغم من أن بعض الأهداف يمكنها تعديل هذا الافتراضي. القيم الأخرى الممكنة لـ version هي 3 أو 4.
--generate-missing-build-notes=yes

الخيارات التالية متاحة عندما يتم تكوين as لمعالج i386.

--32 | --x32 | --64
يحدد حجم الكلمة، إما 32 بت أو 64 بت. --32 يعني بنية Intel i386، بينما --x32 و --64 يعنيان بنية AMD x86-64 بحجم كلمة 32 بت أو 64 بت على التوالي.

هذه الخيارات متاحة فقط مع تنسيق ملف الكائن ELF، وتتطلب أن يكون دعم BFD الضروري قد تم تضمينه (على منصة 32 بت يجب عليك إضافة --enable-64-bit-bfd إلى configure لتمكين الاستخدام 64 بت واستخدام x86-64 ك منصة هدف).

-n
بشكل افتراضي، تستبدل x86 GAS تعليمات nop المتعددة المستخدمة للمحاذاة داخل أقسام الكود بتعليمات nop متعددة البايت مثل leal 0(%esi,1),%esi. يقوم هذا المفتاح بتعطيل التحسين إذا تم تحديد nop ببايت واحد (0x90) بشكل صريح كبايت ملء للمحاذاة.

NAME

as - GNU assembler

SYNOPSIS

as [-cons] [-defsym sym=val] [-g[level]] [-I dir] [-L] [-mall] [-o file] [-R] [-s] [-S] [-t] [-V] [-v] [--help] [--target-help] [--version] [input-file]

TARGET

Xtensa, Z80

DESCRIPTION

The GNU assembler, `as', translates assembly language programs into object files.

This document describes the Xtensa and Z80 specific options for `as'.

Xtensa Dependent Features

The Xtensa processor architecture includes optional, configurable features. The assembler must know which features are configured for a particular processor configuration. This is typically done using the configuration file generated by the Xtensa tools, or by explicitly specifying the features on the command line. The assembler will reject any instruction that is not supported by the configured Xtensa features.

The command line options below allow for some manual overriding of assembler behavior. These options should generally not be needed if the assembler is configured correctly via a configuration file.

--longcalls | --no-longcalls
Enable or disable transformation of call instructions to allow calls across a greater range of addresses. This option should be used when call targets can potentially be out of range. It may degrade both code size and performance, but the linker can generally optimize away the unnecessary overhead when a call ends up within range. The default is --no-longcalls.
--transform | --no-transform
Enable or disable all assembler transformations of Xtensa instructions, including both relaxation and optimization. The default is --transform; --no-transform should only be used in the rare cases when the instructions must be exactly as specified in the assembly source. Using --no-transform causes out of range instruction operands to be errors.
--rename-section oldname=newname
Rename the oldname section to newname. This option can be used multiple times to rename multiple sections.
--trampolines | --no-trampolines
Enable or disable transformation of jump instructions to allow jumps across a greater range of addresses. This option should be used when jump targets can potentially be out of range. In the absence of such jumps this option does not affect code size or performance. The default is --trampolines.
--abi-windowed | --abi-call0
Choose ABI tag written to the ".xtensa.info" section. ABI tag indicates ABI of the assembly code. A warning is issued by the linker on an attempt to link object files with inconsistent ABI tags. Default ABI is chosen by the Xtensa core configuration.

The following options are available when as is configured for an Z80 processor.

@chapter Z80 Dependent Features

Command-line Options

-march=CPU[-EXT...][+EXT...]
This option specifies the target processor. The assembler will issue an error message if an attempt is made to assemble an instruction which will not execute on the target processor. The following processor names are recognized: "z80", "z180", "ez80", "gbz80", "z80n", "r800". In addition to the basic instruction set, the assembler can be told to accept some extension mnemonics. For example, "-march=z180+sli+infc" extends z180 with SLI instructions and IN F,(C). The following extensions are currently supported: "full" (all known instructions), "adl" (ADL CPU mode by default, eZ80 only), "sli" (instruction known as SLI, SLL or SL1), "xyhl" (instructions with halves of index registers: IXL, IXH, IYL, IYH), "xdcb" (instructions like RotOp (II+d),R and BitOp n,(II+d),R), "infc" (instruction IN F,(C) or IN (C)), "outc0" (instruction OUT (C),0). Note that rather than extending a basic instruction set, the extension mnemonics starting with "-" revoke the respective functionality: "-march=z80-full+xyhl" first removes all default extensions and adds support for index registers halves only.

If this option is not specified then "-march=z80+xyhl+infc" is assumed.

-local-prefix=prefix
Mark all labels with specified prefix as local. But such label can be marked global explicitly in the code. This option do not change default local label prefix ".L", it is just adds new one.
-colonless
Accept colonless labels. All symbols at line begin are treated as labels.
-sdcc
Accept assembler code produced by SDCC.
-fp-s=FORMAT
Single precision floating point numbers format. Default: ieee754 (32 bit).
-fp-d=FORMAT
Double precision floating point numbers format. Default: ieee754 (64 bit).
