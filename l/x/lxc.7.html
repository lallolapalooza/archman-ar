الاسم

lxc - حاويات لينكس

نظرة عامة

يتم دفع تقنية الحاويات بقوة نحو نواة لينكس الرئيسية. توفر إدارة الموارد من خلال مجموعات التحكم وعزل الموارد عبر مساحات الأسماء.

يهدف lxc إلى استخدام هذه الوظائف الجديدة لتوفير كائن حاوية في مساحة المستخدم والذي يوفر عزلًا كاملاً للموارد والتحكم في الموارد لتطبيق أو نظام كامل.

lxc صغير بما يكفي لإدارة حاوية بسهولة باستخدام أوامر بسيطة وكامل بما يكفي لاستخدامه لأغراض أخرى.

المتطلبات

إصدار النواة > = 3.10 المشحون مع التوزيعات، سيعمل مع lxc، هذا الأخير سيكون لديه وظائف أقل ولكن ما يكفي ليكون مثيرًا للاهتمام.

يعتمد lxc على مجموعة من الوظائف التي توفرها النواة. سيمنحك البرنامج النصي المساعد lxc-checkconfig معلومات حول تكوين النواة لديك، والميزات المطلوبة والمفقودة.

المواصفات الوظيفية

الحاوية هي كائن يعزل بعض موارد المضيف، للتطبيق أو النظام الذي يعمل فيها.

سيتم تشغيل التطبيق / النظام داخل حاوية محددة بتكوين تم إنشاؤه مبدئيًا أو تم تمريره كمعلمة للأوامر.

كيفية تشغيل تطبيق في حاوية

قبل تشغيل تطبيق، يجب أن تعرف الموارد التي تريد عزلها. التكوين الافتراضي هو عزل PIDs، و sysv IPC، ونقاط الربط. إذا كنت ترغب في تشغيل shell بسيط داخل حاوية، فإن تكوينًا أساسيًا مطلوب، خاصة إذا كنت تريد مشاركة rootfs. إذا كنت ترغب في تشغيل تطبيق مثل sshd، فيجب عليك توفير مكدس شبكة جديد واسم مضيف جديد. إذا كنت ترغب في تجنب التعارضات مع بعض الملفات مثل /var/run/httpd.pid، فيجب عليك إعادة ربط /var/run بدليل فارغ. إذا كنت تريد تجنب التعارضات في جميع الحالات، يمكنك تحديد rootfs للحاوية. يمكن أن يكون rootfs شجرة دليل، تم ربطها مسبقًا بـ rootfs الأولي، لذلك لا يزال بإمكانك استخدام التوزيعة الخاصة بك ولكن مع /etc و /home الخاصة بك

إليك مثال على شجرة دليل لـ sshd:

[root@lxc sshd]$ tree -d rootfs

rootfs	
|-- bin	
|-- dev	
|   |-- pts
|   `-- shm
|       `-- network
|-- etc	
|   `-- ssh
|-- lib	
|-- proc
|-- root
|-- sbin
|-- sys	
|-- usr	
`-- var	
    |-- empty
    |   `-- sshd
    |-- lib
    |   `-- empty
    |       `-- sshd
    `-- run
        `-- sshd

وملف نقاط الربط المرتبط به:

	[root@lxc sshd]$ cat fstab
	/lib /home/root/sshd/rootfs/lib none ro,bind 0 0
	/bin /home/root/sshd/rootfs/bin none ro,bind 0 0
	/usr /home/root/sshd/rootfs/usr none ro,bind 0 0
	/sbin /home/root/sshd/rootfs/sbin none ro,bind 0 0

كيفية تشغيل نظام في حاوية

تشغيل نظام داخل حاوية أسهل بشكل متناقض من تشغيل تطبيق. لماذا؟ لأنك لا تضطر إلى الاهتمام بالموارد التي يجب عزلها، كل شيء يحتاج إلى عزله، يتم تحديد الموارد الأخرى على أنها معزولة ولكن بدون تكوين لأن الحاوية ستقوم بإعدادها. على سبيل المثال، سيتم إعداد عنوان ipv4 بواسطة نصوص تهيئة نظام الحاوية. إليك مثال على ملف نقاط الربط:

	[root@lxc debian]$ cat fstab
	/dev	/home/root/debian/rootfs/dev none bind 0 0
	/dev/pts /home/root/debian/rootfs/dev/pts  none bind 0 0

دورة حياة الحاوية

عند إنشاء الحاوية، فإنها تحتوي على معلومات التكوين. عند تشغيل عملية، سيتم بدء تشغيل الحاوية وتشغيلها. عندما تنتهي آخر عملية تعمل داخل الحاوية، يتم إيقاف الحاوية.

في حالة الفشل عند تهيئة الحاوية، ستمر بحالة الإجهاض.

التكوين

يتم تكوين الحاوية من خلال ملف تكوين، يتم وصف تنسيق ملف التكوين في lxc.conf(5)

إنشاء / تدمير الحاويات

يمكن إنشاء كائن حاوية دائم عبر الأمر lxc-create. يأخذ اسم حاوية كمعلمة وملف تكوين اختياري وقالب. يستخدم الاسم بواسطة الأوامر المختلفة للإشارة إلى هذه الحاوية. سيقوم الأمر lxc-destroy بتدمير كائن الحاوية.

lxc-create -n foo
lxc-destroy -n foo

حاوية متطايرة

ليس من الإلزامي إنشاء كائن حاوية قبل تشغيله. يمكن بدء تشغيل الحاوية مباشرةً باستخدام ملف تكوين كمعلمة.

بدء / إيقاف الحاوية

عندما يتم إنشاء الحاوية، تكون جاهزة لتشغيل تطبيق / نظام. هذا هو الغرض من الأمرين lxc-execute و lxc-start. إذا لم يتم إنشاء الحاوية قبل بدء تشغيل التطبيق، فستستخدم الحاوية ملف التكوين الذي تم تمريره كمعلمة للأمر، وإذا لم تكن هناك معلمة، فستستخدم عزلًا افتراضيًا. إذا انتهى التطبيق، فسيتم إيقاف الحاوية، ولكن إذا لزم الأمر، يمكن استخدام الأمر lxc-stop لإيقاف الحاوية.

تشغيل تطبيق داخل حاوية ليس هو نفس تشغيل نظام تمامًا. لهذا السبب، هناك أمران مختلفان لتشغيل تطبيق داخل حاوية:

lxc-execute -n foo [-f config] /bin/bash
lxc-start -n foo [-f config] [/bin/bash]

سيقوم الأمر lxc-execute بتشغيل الأمر المحدد داخل حاوية عبر عملية وسيطة، lxc-init. سيقوم هذا lxc-init بعد تشغيل الأمر المحدد، بالانتظار حتى نهايته وجميع العمليات الأخرى التي تم إعادة توجيهها. (لدعم الشياطين في الحاوية). بعبارة أخرى، في الحاوية، lxc-init هو PID 1 والعملية الأولى للتطبيق هي PID 2.

سيقوم الأمر lxc-start بتشغيل الأمر المحدد مباشرة في الحاوية. PID للعملية الأولى هو 1. إذا لم يتم تحديد أمر، فسيقوم lxc-start بتشغيل الأمر المحدد في lxc.init.cmd أو إذا لم يتم تعيينه، /sbin/init.

لتلخيص ذلك، lxc-execute مخصص لتشغيل تطبيق و lxc-start مناسب لتشغيل نظام.

إذا كان التطبيق لا يستجيب، أو غير قابل للوصول، أو غير قادر على الانتهاء بنفسه، فإن أمر lxc-stop البري سيقتل جميع العمليات في الحاوية بلا رحمة.

lxc-stop -n foo -k

الاتصال بمحطة طرفية متاحة

إذا تم تكوين الحاوية باستخدام محطات طرفية، فمن الممكن الوصول إليها من خلالها. يعتمد الأمر على الحاوية لتوفير مجموعة من المحطات الطرفية المتاحة لاستخدامها بواسطة الأمر التالي. عندما يتم فقدان المحطة الطرفية، يمكن إعادة الاتصال بها دون تسجيل الدخول مرة أخرى.

lxc-console -n foo -t 3

تجميد / إلغاء تجميد الحاوية

في بعض الأحيان، يكون من المفيد إيقاف جميع العمليات التي تنتمي إلى حاوية، على سبيل المثال، لجدولة المهام. الأوامر:

lxc-freeze -n foo

ستضع جميع العمليات في حالة غير قابلة للإيقاف، و

lxc-unfreeze -n foo

ستستأنفها.

NAME

lxc - LXC container runtime environment

OVERVIEW

This man page gives an overview of the LXC runtime environment. It describes the state transitions and the commands which are used to manage containers.

LXC stands for Linux Containers. LXC provides an operating system-level virtualization for the Linux kernel. It allows you to create multiple isolated Linux systems (containers) on a single host Linux system. A container consists of a root filesystem, a set of configuration files, and a set of tunable parameters.

LXC containers are managed by a set of tools. The most basic ones are: lxc-create, lxc-destroy, lxc-start, lxc-stop, lxc-attach, lxc-execute, lxc-ls, lxc-info, lxc-monitor, lxc-wait, lxc-cgroup, lxc-freeze, lxc-unfreeze and lxc-copy.

The containers state model is composed of the following states:

NOT_CREATED
The container has not been created yet. This means that its root filesystem is not present.
STOPPED
The container is not running. Its root filesystem is present.
STARTING
The container is being started. The kernel is being configured, the namespace is being created etc.
RUNNING
The container is running. It is possible to execute processes inside the container.
STOPPING
The container is being stopped. The processes inside the container are being killed.
ABORTING
The container failed to start. Some error happened during the STARTING state.
FREEZING
The container is being frozen. The processes inside the container are being stopped and their state is being saved.
FROZEN
The container is frozen. Its processes are stopped and their state is saved.
THAWING
The container is being thawed. The processes inside the container are being resumed from their saved state.

REQUIREMENTS

LXC requires a Linux kernel with the following features enabled:

  • Namespaces (ipc, mnt, net, pid, user, uts)
  • Capabilities
  • Cgroups

For more details, please refer to the lxc.conf(5) man page.

FUNCTIONAL SPECIFICATION

FREEZING CONTAINERS

The freezer cgroup controller is used to freeze and unfreeze containers. This feature is enabled if the freezer cgroup v1 controller is enabled in the kernel.

GETTING INFORMATION ABOUT CONTAINER

When there are a lot of containers, it is hard to follow what has been created or destroyed, what is running or what are the PIDs running in a specific container. For this reason, the following commands may be useful:

lxc-ls -f
lxc-info -n foo

lxc-ls lists containers.

lxc-info gives information for a specific container.

Here is an example on how the combination of these commands allows one to list all the containers and retrieve their state.

for i in $(lxc-ls -1); do
  lxc-info -n $i
done

MONITORING CONTAINER

It is sometime useful to track the states of a container, for example to monitor it or just to wait for a specific state in a script.

lxc-monitor command will monitor one or several containers. The parameter of this command accepts a regular expression for example:

lxc-monitor -n "foo|bar"

will monitor the states of containers named 'foo' and 'bar', and:

lxc-monitor -n ".*"

will monitor all the containers.

For a container 'foo' starting, doing some work and exiting, the output will be in the form:

'foo' changed state to [STARTING]
'foo' changed state to [RUNNING]
'foo' changed state to [STOPPING]
'foo' changed state to [STOPPED]

lxc-wait command will wait for a specific state change and exit. This is useful for scripting to synchronize the launch of a container or the end. The parameter is an ORed combination of different states. The following example shows how to wait for a container if it successfully started as a daemon.

# launch lxc-wait in background
lxc-wait -n foo -s STOPPED &
LXC_WAIT_PID=$!
# this command goes in background
lxc-execute -n foo mydaemon &
# block until the lxc-wait exits
# and lxc-wait exits when the container
# is STOPPED
wait $LXC_WAIT_PID
echo "'foo' is finished"

CGROUP SETTINGS FOR CONTAINERS

The container is tied with the control groups, when a container is started a control group is created and associated with it. The control group properties can be read and modified when the container is running by using the lxc-cgroup command.

lxc-cgroup command is used to set or get a control group subsystem which is associated with a container. The subsystem name is handled by the user, the command won't do any syntax checking on the subsystem name, if the subsystem name does not exists, the command will fail.

lxc-cgroup -n foo cpuset.cpus

will display the content of this subsystem.

lxc-cgroup -n foo cpu.shares 512

will set the subsystem to the specified value.
