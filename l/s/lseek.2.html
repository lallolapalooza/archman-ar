lseek(2) دليل استدعاءات النظام lseek(2)

الاسم

lseek - إعادة تعيين موضع القراءة/الكتابة للملف

المكتبة

مكتبة C القياسية (libc، -lc)

ملخص

#include <unistd.h>
off_t lseek(int fd, off_t offset, int whence);

الوصف

تقوم lseek() بإعادة تعيين موضع الملف لوصف الملف المفتوح المرتبط بمُعرف الملف fd إلى الوسيط offset وفقًا للتوجيه whence على النحو التالي:

SEEK_SET
يتم تعيين موضع الملف إلى offset بايت.
SEEK_CUR
يتم تعيين موضع الملف إلى موقعه الحالي مضافًا إليه offset بايت.
SEEK_END
يتم تعيين موضع الملف إلى حجم الملف مضافًا إليه offset بايت.

تسمح lseek() بتعيين موضع الملف بما يتجاوز نهاية الملف (لكن هذا لا يغير حجم الملف). إذا تم كتابة بيانات لاحقًا في هذا الموضع، فإن القراءات اللاحقة للبيانات في الفجوة (a "hole") تُعيد بايتات فارغة ('\0') حتى يتم كتابة البيانات فعليًا في الفجوة.

البحث عن بيانات الملف والفجوات

منذ Linux 3.1، يدعم Linux القيم الإضافية التالية لـ whence:

SEEK_DATA
تعديل موضع الملف إلى الموقع التالي في الملف الأكبر من أو يساوي offset الذي يحتوي على بيانات. إذا كان offset يشير إلى بيانات، فسيتم تعيين موضع الملف إلى offset.
SEEK_HOLE
تعديل موضع الملف إلى الفجوة التالية في الملف الأكبر من أو يساوي offset. إذا كان offset يشير إلى منتصف فجوة، فسيتم تعيين موضع الملف إلى offset. إذا لم تكن هناك فجوة بعد offset، فسيتم تعديل موضع الملف إلى نهاية الملف (أي، هناك فجوة ضمنية في نهاية أي ملف).

في كلتا الحالتين أعلاه، تفشل lseek() إذا كان offset يشير إلى ما بعد نهاية الملف.

تسمح هذه العمليات للتطبيقات برسم خرائط للفجوات في ملف مخصص بشكل متناثر. يمكن أن يكون هذا مفيدًا لتطبيقات مثل أدوات النسخ الاحتياطي للملفات، والتي يمكنها توفير المساحة عند إنشاء النسخ الاحتياطية والحفاظ على الفجوات، إذا كان لديها آلية لاكتشاف الفجوات.

لأغراض هذه العمليات، الفجوة هي تسلسل من الأصفار لم يتم تخصيصه (عادةً) في تخزين الملف الأساسي. ومع ذلك، لا يُلزم نظام الملفات بالإبلاغ عن الفجوات، لذا فإن هذه العمليات ليست آلية مضمونة لرسم خرائط مساحة التخزين المخصصة فعليًا لملف. (علاوة على ذلك، قد لا يتم الإبلاغ عن تسلسل الأصفار الذي تم كتابته فعليًا في التخزين الأساسي كفجوة.) في أبسط تطبيق، يمكن لنظام الملفات دعم العمليات بجعل SEEK_HOLE تعيد دائمًا موضع نهاية الملف، وجعل SEEK_DATA تعيد دائمًا offset (أي، حتى لو كان الموضع المشار إليه بواسطة offset فجوة، يمكن اعتباره يتكون من بيانات هي تسلسل من الأصفار).

يجب تعريف ماكرو اختبار الميزة _GNU_SOURCE للحصول على تعريفات SEEK_DATA و SEEK_HOLE من <unistd.h>.

يتم دعم عمليتي SEEK_HOLE و SEEK_DATA لأنظمة الملفات التالية:

•
Btrfs (منذ Linux 3.1)
•
OCFS (منذ Linux 3.2)
•
XFS (منذ Linux 3.5)
•
ext4 (منذ Linux 3.8)
•
tmpfs(5) (منذ Linux 3.8)
•
NFS (منذ Linux 3.18)
•
FUSE (منذ Linux 4.5)
•
GFS2 (منذ Linux 4.15)

قيمة الإرجاع

عند الاكتمال بنجاح، تُعيد lseek() موقع الإزاحة الناتج مقاسًا بالبايت من بداية الملف. في حالة الخطأ، تُعاد القيمة (off_t) -1 ويتم تعيين errno للإشارة إلى الخطأ.

الأخطاء

EBADF
fd ليس مُعرف ملف مفتوح.
EINVAL
whence غير صالح. أو: موضع الملف الناتج سيكون سالبًا، أو يتجاوز نهاية جهاز قابل للبحث.
ENXIO
whence هو SEEK_DATA أو SEEK_HOLE، و offset يتجاوز نهاية الملف، أو whence هو SEEK_DATA و offset يقع داخل فجوة في نهاية الملف.
EOVERFLOW
لا يمكن تمثيل موضع الملف الناتج في off_t.
ESPIPE
fd مرتبط بأنبوب، أو مقبس، أو FIFO.

الإصدارات

في Linux، فشل استخدام lseek() على جهاز طرفي بخطأ ESPIPE.

NAME

lseek — set file offset

LIBRARY

Standard C library (libc, -lc)

SYNOPSIS

off_t lseek(int fd, off_t offset, int whence);

DESCRIPTION

The lseek() function repositions the file offset of the open file description referred to by the file descriptor fd to a new value determined by the argument offset. The new file offset is expressed in bytes from the beginning of the file. The argument whence determines how offset is interpreted:

SEEK_SET

The file offset shall be set to offset bytes from the beginning of the file.

SEEK_CUR

The file offset shall be set to its current location plus offset bytes from the beginning of the file.

SEEK_END

The file offset shall be set to the size of the file plus offset bytes from the beginning of the file.

SEEK_DATA

(Since Linux 3.11) The file offset shall be set to the offset of the end of the next valid data "hole" or the end of the file, whichever comes first. A "hole" is a region of the file that reads as zero bytes but does not consume physical storage. This option is intended to be used with block devices and other filesystems that may represent sparse files. If the file offset is already within a data region, this call will search for the next hole.

SEEK_HOLE

(Since Linux 3.11) The file offset shall be set to the offset of the beginning of the next hole or the end of the file, whichever comes first. If the file offset is already within a hole, this call will search for the next data region.

The lseek() function allows the file offset to be set beyond the end of existing data in the file. If the offset is beyond the end of the file, subsequent writes to the file shall extend the file. The characteristics of file offset extension are implementation-dependent.

SEEK_DATA and SEEK_HOLE are intended for use with block devices, but might also be useful for other types of files. They are not supported by all filesystem types.

RETURN VALUE

Upon successful completion, lseek() shall return the resulting file offset, expressed in bytes from the beginning of the file.

On error, lseek() shall return (off_t) -1 and set errno to indicate the error.

ERRORS

EBADF

fd is not an open file descriptor, or the file descriptor is not seekable.

EINVAL

The value of whence is not valid. Or, the resulting file offset would be negative, or before the end of the file if whence is SEEK_END and offset is negative.

ESPIPE

fd is associated with a pipe, socket, or FIFO. These types of files may not have a settable offset.

VERSIONS

SEEK_DATA and SEEK_HOLE were introduced in Linux kernel 3.11.

STANDARDS

POSIX.1-2008, SEEK_SET, SEEK_CUR, SEEK_END.

HISTORY

The lseek() function first appeared in Version 7 Unix.

SEEK_DATA and SEEK_HOLE are Linux-specific.

NOTES

The type off_t is defined in types.h(3type).

A successful call to lseek() with the SEEK_END flag and an offset of 0 will position the file offset at the end of the file.

If the file is opened with the O_APPEND flag, the file offset can only be modified in the kernel by opening the file without the O_APPEND flag. The lseek() calls will fail with ESPIPE if the file was opened with O_APPEND.

Note that seeking is not meaningful for pipes, sockets, or ttys.

The behavior of lseek() on a file that is being written to by another process or being truncated by another process is not specified.

The behavior of lseek() on an NFS file depends on the NFS server's implementation. The NFS protocol does not define a behavior for seeking. Some NFS servers implement lseek() by truncating the file to the current offset, others don't.

For most regular files, the lseek() call is unnecessary, since read (2) and write (2) automatically update the file offset. However, lseek() is useful for things like:

  • Seeking to a specific location in a file to read or write.
  • Determining the current file offset (using lseek(fd, 0, SEEK_CUR)).
  • Seeking to the end of a file (using lseek(fd, 0, SEEK_END)).

SEEK_DATA and SEEK_HOLE are useful for navigating sparse files. For example, to find the next data region after the current file offset, one could use:

off_t next_data_offset = lseek(fd, 0, SEEK_DATA);

If the call succeeds, next_data_offset will be the offset of the start of the next data region. If the end of the file is reached without finding a data region, lseek() will return the size of the file. If next_data_offset is greater than or equal to the current file offset, then a data region has been found. Otherwise, the end of the file has been reached.
