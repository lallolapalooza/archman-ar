llvm-symbolizer(1)

الحزمة: llvm

التراخيص: Apache-2.0 WITH LLVM-exception

LLVM-SYMBOLIZER(1) LLVM LLVM-SYMBOLIZER(1)

NAME

llvm-symbolizer - تحويل العناوين إلى مواقع الكود المصدري

SYNOPSIS

llvm-symbolizer [خيارات] [عناوين...]

DESCRIPTION

llvm-symbolizer يقرأ أسماء الإدخال والعناوين من سطر الأوامر ويطبع مواقع الكود المصدري المقابلة إلى المخرج القياسي. يمكنه أيضًا تحويل السجلات التي تحتوي على ترميز الرموز <> عبر --filter-markup. يمكن تحديد العناوين كأرقام أو أسماء رموز.

إذا لم يتم تحديد عنوان في سطر الأوامر، فإنه يقرأ العناوين من الإدخال القياسي. إذا لم يتم تحديد اسم إدخال في سطر الأوامر، ولكن تم تحديد عناوين، يتم تفسير قيمة العنوان الأولى كاسم إدخال. إذا لم يتم التعرف على قيمة إدخال، فإنه يبلغ عن عدم العثور على معلومات المصدر.

يمكن تحديد أسماء الإدخال مع العناوين إما في الإدخال القياسي أو كوسائط موضعية في سطر الأوامر. افتراضيًا، يتم تفسير أسماء الإدخال كمسارات لملفات الكائنات. ومع ذلك، فإن إضافة البادئة BUILDID: لاسم تشير إلى أنه معرف بناء سداسي عشري بدلاً من مسار. سيؤدي هذا إلى البحث عن ملف التصحيح المقابل. لضمان الاتساق، فإن إضافة البادئة FILE: لاسم تشير صراحةً إلى أنه مسار لملف كائن (الافتراضي).

يمكن مسبوقة وسيطة موضعية أو قيمة إدخال قياسية بـ "DATA" أو "CODE" للإشارة إلى أنه يجب تمثيل العنوان كبيانات أو كود قابل للتنفيذ على التوالي. إذا لم يتم تحديد أي منهما، فيفترض "CODE". يتم تمثيل البيانات كعنوان وحجم رمز بدلاً من رقم السطر.

يقوم llvm-symbolizer بتحليل الخيارات من متغير البيئة LLVM_SYMBOLIZER_OPTS بعد تحليل الخيارات من سطر الأوامر. LLVM_SYMBOLIZER_OPTS مفيد بشكل أساسي لتكملة خيارات سطر الأوامر عندما يتم استدعاء llvm-symbolizer بواسطة برنامج أو وقت تشغيل آخر.

EXAMPLES

تستخدم جميع الأمثلة التالية ملفين مصدريين كمدخلات. يستخدمون مزيجًا من الربط بأسلوب C و C ++ لتوضيح كيفية طباعة هذه الأسماء بشكل مختلف (انظر --demangle).

// test.h
extern "C" inline int foz() {
  return 1234;
}
// test.cpp
#include "test.h"
int bar=42;
int foo() {
  return bar;
}
int baz() {
  volatile int k = 42;
  return foz() + k;
}
int main() {
  return foo() + baz();
}

يتم بناء هذه الملفات على النحو التالي:

$ clang -g test.cpp -o test.elf
$ clang -g -O2 test.cpp -o inlined.elf

المثال 1 - العناوين والكائن على سطر الأوامر:

$ llvm-symbolizer --obj=test.elf 0x4004d0 0x400490
foz
/tmp/test.h:1:0
baz()
/tmp/test.cpp:11:0

المثال 2 - العناوين على الإدخال القياسي:

$ cat addr.txt
0x4004a0
0x400490
0x4004d0
$ llvm-symbolizer --obj=test.elf < addr.txt
main
/tmp/test.cpp:15:0
baz()
/tmp/test.cpp:11:0
foz
/tmp/./test.h:1:0

المثال 3 - الكائن المحدد مع العنوان:

$ llvm-symbolizer "test.elf 0x400490" "FILE:inlined.elf 0x400480"
baz()
/tmp/test.cpp:11:0
foo()
/tmp/test.cpp:8:10
$ cat addr2.txt
FILE:test.elf 0x4004a0
inlined.elf 0x400480
$ llvm-symbolizer < addr2.txt
main
/tmp/test.cpp:15:0
foo()
/tmp/test.cpp:8:10

المثال 4 - بادئات BUILDID و FILE:

$ llvm-symbolizer "FILE:test.elf 0x400490" "DATA BUILDID:123456789abcdef 0x601028"
baz()
/tmp/test.cpp:11:0
bar
6295592 4
$ cat addr3.txt
FILE:test.elf 0x400490
DATA BUILDID:123456789abcdef 0x601028
$ llvm-symbolizer < addr3.txt
baz()
/tmp/test.cpp:11:0
bar
6295592 4

المثال 5 - بادئات CODE و DATA:

$ llvm-symbolizer --obj=test.elf "CODE 0x400490" "DATA 0x601028"
baz()
/tmp/test.cpp:11:0
bar
6295592 4
$ cat addr4.txt
CODE test.elf 0x4004a0
DATA inlined.elf 0x601028
$ llvm-symbolizer < addr4.txt
main
/tmp/test.cpp:15:0
bar
6295592 4

المثال 6 - خيارات نمط المسار:

يستخدم هذا المثال نفس ملف المصدر أعلاه، ولكن المسار الكامل لملف المصدر هو /tmp/foo/test.cpp ويتم تجميعه على النحو التالي. تعرض الحالة الأولى المسار المطلق الافتراضي، والثانية --basenames، والثالثة تعرض --relativenames.

$ pwd
/tmp
$ clang -g foo/test.cpp -o test.elf
$ llvm-symbolizer --obj=test.elf 0x4004a0
main
/tmp/foo/test.cpp:15:0
$ llvm-symbolizer --obj=test.elf 0x4004a0 --basenames
main
test.cpp:15:0
$ llvm-symbolizer --obj=test.elf 0x4004a0 --relativenames
main
foo/test.cpp:15:0

المثال 7 - العناوين كأسماء رموز:

$ llvm-symbolizer --obj=test.elf main
main
/tmp/test.cpp:14:0
$ llvm-symbolizer --obj=test.elf "CODE foz"
foz
/tmp/test.h:1:0

المثال 8 - إخراج --skip-line-zero لعنوان بدون مراسلة سطر (عنوان مرتبط بالسطر صفر):

// test.c
int foo = 0;
int x = 1234;
int main() {
  if (x)
    return foo;
  else
    return x;
}

يتم بناء هذه الملفات على النحو التالي:

$ clang -g -S -o test.s test.c
$ llvm-mc -filetype=obj -triple=x86_64-unknown-linux  test.s -o test.o
$ llvm-symbolizer --obj=test.o --skip-line-zero 0xa
main
/tmp/test.c:5:7 (approximate)

OPTIONS

--adjust-vma <offset>
أضف الإزاحة المحددة إلى عناوين ملف الكائن عند إجراء عمليات البحث. يمكن استخدام هذا لإجراء عمليات البحث كما لو كان الكائن قد تم نقله بالإزاحة.
--skip-line-zero
إذا لم يكن للعنوان رقم سطر مرتبط، فاستخدم آخر رقم سطر من التسلسل الحالي في جدول الأسطر. يتم تسمية هذه الأسطر باسم "تقريبي" في المخرجات لأنها قد تكون مضللة.
--basenames, -s
اطبع اسم الملف فقط بدون أي أدلة، بدلاً من المسار المطلق.
--build-id
ابحث عن الكائن باستخدام معرف البناء المحدد، والمحدد كسلسلة سداسية عشرية. هذا الخيار حصري مع --obj.
--color [=<always|auto|never>]
حدد ما إذا كنت ستستخدم الألوان في وضع --filter-markup. الافتراضي هو auto، والذي يكتشف ما إذا كان المخرج القياسي يدعم الألوان. تحديد --color وحده يعادل --color=always.
--debug-file-directory <path>
قدم مسارًا إلى دليل يحتوي على دليل فرعي .build-id للبحث عن معلومات التصحيح للملفات الثنائية المقطوعة. يتم البحث عن مثيلات متعددة لهذا الوسيط بالترتيب المعطى.
--debuginfod, --no-debuginfod
ما إذا كان سيتم محاولة البحث في debuginfod عن ملفات التصحيح أم لا. ما لم يتم تحديده، يتم تمكين debuginfod فقط إذا تم تجميع libcurl (LLVM_ENABLE_CURL) وتم توفير عنوان URL واحد على الأقل للخادم بواسطة متغير البيئة DEBUGINFOD_URLS.
--demangle, -C
اطبع أسماء الوظائف غير المشفرة، إذا كانت الأسماء مشفرة (على سبيل المثال، الاسم المشفر _Z3bazv يصبح baz()، بينما الاسم غير المشفر foz يُطبع كما هو). الافتراضي هو true.
--dwp <path>
