llvm-remarkutil(1)

الحزمة: llvm

التراخيص: Apache-2.0 WITH LLVM-exception

LLVM-REMARKUTIL(1) LLVM LLVM-REMARKUTIL(1)

الاسم

llvm-remarkutil - أداة الملاحظات

موجز

llvm-remarkutil [أمر فرعي] [خيارات]

الوصف

أداة لعرض المعلومات من، والتحويل بين صيغ الملاحظات المختلفة https://llvm.org/docs/Remarks.html.

الأوامر الفرعية

  • bitstream2yaml - إعادة تسلسل ملاحظات bitstream إلى YAML.
  • yaml2bitstream - إعادة تسلسل ملاحظات YAML إلى bitstream.
  • instruction-count - إخراج عدد التعليمات للدوال.
  • annotation-count - إخراج عدد أنواع الملاحظات من ملاحظات الشرح.
  • size-diff - حساب الفرق في ملاحظات الحجم.

bitstream2yaml

الاستخدام: llvm-remarkutil bitstream2yaml <ملف الإدخال> -o <ملف الإخراج>

ملخص

تأخذ ملف ملاحظات bitstream كمدخل، وتعيد تسلسل هذا الملف بصيغة YAML.

yaml2bitstream

الاستخدام: llvm-remarkutil yaml2bitstream <ملف الإدخال> -o <ملف الإخراج>

ملخص

تأخذ ملف ملاحظات YAML كمدخل، وتعيد تسلسل هذا الملف بصيغة bitstream.

instruction-count

الاستخدام: llvm-remarkutil instruction-count <ملف الإدخال> --parser=<bitstream|yaml> [--use-debug-loc] -o <ملف الإخراج>

ملخص

تخرج ملاحظات عدد التعليمات لكل دالة. ملاحظات عدد التعليمات ترمّز عدد التعليمات في دالة في وقت طباعة التجميع.

تتطلب ملاحظات عدد التعليمات ملاحظات asm-printer.

صيغة CSV كالتالي:

Function,InstructionCount
foo,123

إذا تم تمرير --use-debug-loc، فسيتضمن CSV مسار المصدر، رقم السطر والعمود.

Source,Function,InstructionCount
path:line:column,foo,3

annotation-count

الاستخدام: llvm-remarkutil annotation-count <ملف الإدخال> --parser=<bitstream|yaml> --annotation-type=<type> [--use-debug-loc] -o <ملف الإخراج>

ملخص

تخرج عدًا لنوع الشرح <type> للملاحظات لكل دالة. يعبر العدد عن عدد فحوصات الملاحظات المدخلة في الدالة.

تتطلب ملاحظات عدد الشروحات ملاحظات AnnotationRemarksPass.

صيغة CSV كالتالي:

Function,Count
foo,123

إذا تم تمرير --use-debug-loc، فسيتضمن CSV مسار المصدر، رقم السطر والعمود.

Source,Function,Count
path:line:column,foo,3

count

الاستخدام: llvm-remarkutil count [خيارات] <ملف الإدخال>

ملخص

llvm-remarkutil count يحسب الملاحظات https://llvm.org/docs/Remarks.html بناءً على الخصائص المحددة. بشكل افتراضي، تقوم الأداة بحساب عدد الملاحظات بناءً على عدد مرات ظهورها في ملف مصدر أو دالة أو الإجمالي لملف الملاحظات المنشأ. تدعم الأداة أيضًا جمع العدد بناءً على وسيطات ملاحظات محددة. يجب أن تحتوي الوسيطات المحددة على قيمة عددية لتتمكن من الإبلاغ عن عدد.

تحتوي الأداة على أدوات لتصفية عدد الملاحظات بناءً على اسم الملاحظة، اسم الممر، قيمة الوسيط ونوع الملاحظة.

الخيارات

--parser=<yaml|bitstream>
اختر نوع محلل ملاحظات الإدخال. مطلوب.
  • yaml : ستقوم الأداة بتحليل ملاحظات YAML.
  • bitstream : ستقوم الأداة بتحليل ملاحظات bitstream.
--count-by=<value>
اختر خيارًا لجمع الملاحظات حسب.
  • remark-name : حساب عدد الملاحظات الفردية الموجودة.
  • arg : حساب الملاحظات بناءً على الوسيطات المحددة الممررة عبر --(r)args. يجب أن تكون قيمة الوسيط رقمًا.
--group-by=<value>
تجميع عدد الملاحظات حسب الخاصية.
  • source : سيتم جمع العدد لكل مسار مصدر. لن يتم احتساب الملاحظات التي لا تحتوي على موقع تصحيح.
  • function : يتم جمع العدد لكل دالة.
  • function-with-loc : يتم جمع العدد لكل دالة لكل مصدر. لن يتم احتساب الملاحظات التي لا تحتوي على موقع تصحيح.
  • Total : الإبلاغ عن عدد لملف الملاحظات المقدم.
--args[=arguments]
إذا تم تعيين count-by إلى arg، فيمكن استخدام هذا العلم للتجميع من وسيطات ملاحظات محددة ممثلة كسلسلة نصية مفصولة بفواصل. يجب أن تحتوي الوسيطات على قيمة رقمية لتتمكن من عد الملاحظات بواسطتها
--rargs[=arguments]
إذا تم تعيين count-by إلى arg، فيمكن استخدام هذا العلم للتجميع من وسيطات ملاحظات محددة باستخدام تعبير عادي. يجب أن تحتوي الوسيطات على قيمة رقمية لتتمكن من عد الملاحظات بواسطتها
--pass-name[=<string>]
تصفية العدد حسب اسم الممر.
--rpass-name[=<string>]
تصفية العدد حسب اسم الممر باستخدام تعبيرات عادية.
--remark-name[=<string>]
تصفية العدد حسب اسم الملاحظة.
--rremark-name[=<string>]
تصفية العدد حسب اسم الملاحظة باستخدام تعبيرات عادية.
--filter-arg-by[=<string>]
تصفية العدد حسب قيمة الوسيط.
--rfilter-arg-by[=<string>]
تصفية العدد حسب قيمة الوسيط باستخدام تعبيرات عادية.
--remark-type=<value>
تصفية الملاحظات حسب النوع بالخيارات التالية.
  • unknown
  • passed
  • missed
  • analysis
  • analysis-fp-commute
  • analysis-aliasing
  • failure

size-diff

الاستخدام: llvm-remarkutil size-diff [خيارات] file_a file_b --parser parser

NAME

llvm-remarkutil — utility to process LLVM remarks

SYNOPSIS

llvm-remarkutil [options] subcommand [subcommand-options]

DESCRIPTION

llvm-remarkutil is a utility that processes LLVM remarks. Currently, it supports the following subcommands:

size-diff
Compares the size information of two remark files.

SUBCOMMANDS

size-diff

llvm-remarkutil size-diff diffs size remarks https://llvm.org/docs/Remarks.html in two remark files: file_a and file_b.

llvm-remarkutil size-diff can be used to gain insight into which functions were impacted the most by code generation changes.

In most common use-cases file_a and file_b will be remarks output by compiling a fixed source with differing compilers or differing optimization settings.

llvm-remarkutil size-diff handles both YAML https://llvm.org/docs/Remarks.html#yaml-remarks and bitstream https://llvm.org/docs/Remarks.html#llvm-bitstream-remarks remarks.

Options

--parser=<yaml|bitstream>

Select the type of input remark parser. Required.

  • yaml : The tool will parse YAML remarks.
  • bitstream : The tool will parse bitstream remarks.
--report-style=<human|json>
Output style.
  • human : Human-readable textual report. Default option.
  • json : JSON report.
--pretty
Pretty-print JSON output. Optional.

If output is not set to JSON, this does nothing.

-o=<file>
Output file for the report. Outputs to stdout by default.

Human-Readable Output

The human-readable format for llvm-remarkutil size-diff is composed of two sections:

  • Per-function changes.
  • A high-level summary of all changes.

Changed Function Section

Suppose you are comparing two remark files OLD and NEW.

For each function with a changed instruction count in OLD and NEW, llvm-remarkutil size-diff will emit a line like below:

(++|--|==) (>|<) function_name, N instrs, M stack B

A breakdown of the format is below:

(++|--|==)
Which of OLD and NEW the function_name is present in.
  • ++: Only in NEW. ("Added")
  • --: Only in OLD. ("Removed")
  • ==: In both.
(>|<)
Denotes if function_name has more instructions or fewer instructions in the second file.
  • >: More instructions in second file than first file.
  • <: Fewer instructions in second file than in first file.
function_name
The name of the changed function.
N instrs
Second file instruction count - first file instruction count.
M stack B
Second file stack byte count - first file stack byte count.

Summary Section

llvm-remarkutil size-diff will output a high-level summary after printing all changed functions.

instruction count: N (inst_pct_change%)
stack byte usage: M (sb_pct_change%)
N
Sum of all instruction count changes between the second and first file.
inst_pct_change%
Percent increase or decrease in instruction count between the second and first file.
M
Sum of all stack byte count changes between the second and first file.
sb_pct_change%
Percent increase or decrease in stack byte usage between the second and first file.

JSON OUTPUT

High-Level view

Suppose we are comparing two files, OLD and NEW.

llvm-remarkutil size-diff will output JSON as follows.

"Files": [
  "A": "path/to/OLD",
  "B": "path/to/NEW"
]
"InBoth": [
  ...
],
"OnlyInA": [
  ...
],
"OnlyInB": [
  ...
]
Files
Original paths to remark files.
  • A: Path to the first file.
  • B: Path to the second file.
InBoth
Functions present in both files.
OnlyInA
Functions only present in the first file.
OnlyInB
Functions only present in the second file.

Function JSON

The InBoth, OnlyInA, and OnlyInB sections contain size information for each function in the input remark files.

{
  "FunctionName" : "function_name"
  "InstCount": [
      INST_COUNT_A,
      INST_COUNT_B
    ],
  "StackSize": [
      STACK_BYTES_A,
      STACK_BYTES_B
    ],
}
FunctionName
Name of the function.
InstCount
Instruction counts for the function.
  • INST_COUNT_A: Instruction count in OLD.
  • INST_COUNT_B: Instruction count in NEW.
StackSize
Stack byte counts for the function.
  • STACK_BYTES_A: Stack bytes in OLD.
  • STACK_BYTES_B: Stack bytes in NEW.

Computing Diffs From Function JSON

Function JSON does not contain the diffs. Tools consuming JSON output from llvm-remarkutil size-diff are responsible for computing the diffs separately.

To compute the diffs:

  • Instruction count diff: INST_COUNT_B - INST_COUNT_A
  • Stack byte count diff: STACK_BYTES_B - STACK_BYTES_A

EXIT STATUS

llvm-remarkutil size-diff returns 0 on success, and a non-zero value otherwise.
