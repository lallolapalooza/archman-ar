الوصف

تُستخدم هذه الإجراءات لتحليل تعريفات المخطط بالصيغة المحددة في RFC 4512 إلى هياكل ومعالجة هذه الهياكل. تتعامل هذه الإجراءات مع أربعة أنواع من التعريفات: الصيغ، وقواعد المطابقة، وأنواع السمات، وفئات الكائنات. لكل نوع تعريف، يتم توفير أربعة إجراءات.

ldap_str2xxx() تأخذ تعريفًا بتنسيق RFC 4512 في الوسيط s كسلسلة نصية منتهية بـ NUL وتعيد، إذا أمكن، مؤشرًا إلى هيكل تم تخصيصه حديثًا من النوع المناسب. يتحمل المتصل مسؤولية تحرير الهيكل عن طريق استدعاء ldap_xxx_free() عندما لم يعد مطلوبًا. تعيد الإجراء قيمة NULL إذا حدثت مشكلة. في هذه الحالة، سيحصل العدد الصحيح المشار إليه بواسطة الوسيط code على رمز خطأ (انظر أدناه وصف ldap_scherr2str() لشرح القيم) وسيتم وضع مؤشر إلى سلسلة نصية منتهية بـ NUL حيث طلب الوسيط errp ، مما يشير إلى مكان الخطأ في الوسيط s ، لذلك يجب ألا يقوم المتصل بتحريره. الوسيط flags هو قناع بت لخيارات التحليل التي تتحكم في استرخاء الصيغة المعترف بها. تم تعريف القيم التالية:

LDAP_SCHEMA_ALLOW_NONE
تحليل صارم وفقًا لـ RFC 4512.
LDAP_SCHEMA_ALLOW_NO_OID
السماح بالتعريفات التي لا تحتوي على OID أولي.
LDAP_SCHEMA_ALLOW_QUOTED
السماح بعلامات الاقتباس حول بعض العناصر التي لا ينبغي أن تحتوي عليها.
LDAP_SCHEMA_ALLOW_DESCR
السماح بـ descr بدلاً من OID رقمي في الأماكن التي تتوقع فيها الصيغة هذا الأخير.
LDAP_SCHEMA_ALLOW_DESCR_PREFIX
السماح بأن يحتوي OID الرقمي الأولي على بادئة بتنسيق descr.
LDAP_SCHEMA_ALLOW_ALL
كن ليبراليًا جدًا، وشمل جميع الخيارات.

الهياكل المعاد إرجاعها هي كما يلي:

typedef struct ldap_schema_extension_item {
	char *lsei_name;	/* اسم الامتداد */
	char **lsei_values;	/* قيم الامتداد */
} LDAPSchemaExtensionItem;
typedef struct ldap_syntax {
	char *syn_oid;		/* OID */
	char **syn_names;	/* الأسماء */
	char *syn_desc;		/* الوصف */
	LDAPSchemaExtensionItem **syn_extensions; /* الامتداد */
} LDAPSyntax;
typedef struct ldap_matchingrule {
	char *mr_oid;		/* OID */
	char **mr_names;	/* الأسماء */
	char *mr_desc;		/* الوصف */
	int  mr_obsolete;	/* هل هو مهمل؟ */
	char *mr_syntax_oid;	/* OID الصيغة للقيم المؤكدة */
	LDAPSchemaExtensionItem **mr_extensions; /* الامتدادات */
} LDAPMatchingRule;
typedef struct ldap_attributetype {
	char *at_oid;		/* OID */
	char **at_names;	/* الأسماء */
	char *at_desc;		/* الوصف */
	int  at_obsolete;	/* هل هو مهمل؟ */
	char *at_sup_oid;	/* OID للنوع الأعلى */
	char *at_equality_oid;	/* OID لقاعدة المطابقة المساواة */
	char *at_ordering_oid;	/* OID لقاعدة المطابقة الترتيبية */
	char *at_substr_oid;	/* OID لقاعدة مطابقة السلاسل الفرعية */
	char *at_syntax_oid;	/* OID للصيغة للقيم */
	int  at_syntax_len;	/* الحد الأقصى الأدنى المقترح للطول */
	int  at_single_value;	/* هل له قيمة واحدة؟ */
	int  at_collective;	/* هل هو جماعي؟ */
	int  at_no_user_mod;	/* هل التغييرات ممنوعة عبر LDAP؟ */
	int  at_usage;		/* الاستخدام، انظر أدناه */
	LDAPSchemaExtensionItem **at_extensions; /* الامتدادات */
} LDAPAttributeType;
typedef struct ldap_objectclass {
	char *oc_oid;		/* OID */
	char **oc_names;	/* الأسماء */
	char *oc_desc;		/* الوصف */
	int  oc_obsolete;	/* هل هو مهمل؟ */
	char **oc_sup_oids;	/* OIDs لفئات الكائنات العليا */
	int  oc_kind;		/* النوع، انظر أدناه */
	char **oc_at_oids_must;	/* OIDs لأنواع السمات المطلوبة */
	char **oc_at_oids_may;	/* OIDs لأنواع السمات الاختيارية */
	LDAPSchemaExtensionItem **oc_extensions; /* الامتدادات */
} LDAPObjectClass;

بعض الحقول العددية (تلك الموصوفة بعلامة استفهام) لها قيمة صحيحة، بالنسبة لهذه الحقول القيم الممكنة هي:

LDAP_SCHEMA_NO
الإجابة على السؤال لا.
LDAP_SCHEMA_YES
الإجابة على السؤال نعم.

بالنسبة لأنواع السمات، الاستخدامات التالية ممكنة:

LDAP_SCHEMA_USER_APPLICATIONS
نوع السمة غير تشغيلي.
LDAP_SCHEMA_DIRECTORY_OPERATION
نوع السمة تشغيلي ويتعلق بالدليل نفسه، أي أن له نفس القيمة على جميع الخوادم التي توفر الإدخال الذي يحتوي على نوع السمة هذا.
LDAP_SCHEMA_DISTRIBUTED_OPERATION
نوع السمة تشغيلي ويتعلق بالنسخ المتماثل، الظل، أو جوانب أخرى من الدليل الموزع. سيتم تحديده.
LDAP_SCHEMA_DSA_OPERATION
نوع السمة تشغيلي ويتعلق بخادم الدليل نفسه، أي أنه قد تكون له قيم مختلفة لنفس الإدخال عند استرجاعه من خوادم مختلفة توفر الإدخال.

يمكن أن تكون فئات الكائنات من ثلاثة أنواع:

LDAP_SCHEMA_ABSTRACT
فئة الكائن مجردة، أي أنه لا يمكن أن تكون هناك إدخالات من هذا النوع بمفردها.
LDAP_SCHEMA_STRUCTURAL
فئة الكائن هيكلية، أي أنها تصف الدور الرئيسي للإدخال. على بعض الخوادم، بمجرد إنشاء الإدخال، لا يمكن تغيير مجموعة فئات الكائنات الهيكلية المعينة: لا يمكن إزالة أي من الفئات الموجودة ولا يمكن إضافة فئات أخرى.
LDAP_SCHEMA_AUXILIARY
فئة الكائن مساعدة، أي أنها مخصصة

ldap_schema(3) — OpenLDAP 2.6.10

NAME

ldap_schema, ldap_schema_freeref, ldap_schema_dup, ldap_schema_search, ldap_schparse, ldap_scherr2str, ldap_xxx2name, ldap_xxx2str — LDAP schema management library

LIBRARY

ldap - LDAP library

SYNOPSIS

#include <ldap.h>
#include <ldap_schema.h>

LDAPSchema *ldap_schema_freeref(LDAPSchema *s);

LDAPSchema *ldap_schema_dup(LDAPSchema *s);

LDAPSchema *ldap_schema_search(LDAP *ld, const char *filter, const char *attrs[]);

int ldap_schparse(LDAP *ld, const char *s, LDAPSchema **sp, int options);

const char *ldap_scherr2str(int code);

char *ldap_xxx2name(LDAPObject classes);

char *ldap_xxx2str(LDAPObject classes);

DESCRIPTION

The routines described herein provide support for parsing and managing LDAP schema information. Schema information is stored in a LDAPSchema structure, which is a private structure used to maintain an in-memory representation of schema definitions.

ldap_schema_freeref() frees a referenced LDAPSchema structure. If the structure is not currently referenced, it is freed. The reference count is decremented. When the reference count reaches zero, the structure is freed and the memory is returned to the system.

ldap_schema_dup() duplicates an LDAPSchema structure. The reference count is incremented. The caller is responsible for freeing the duplicated structure using ldap_schema_freeref().

ldap_schema_search() searches the schema associated with the LDAP connection specified by ld using the provided filter and attrs. The filter specifies the object classes to search for, and attrs specifies the attributes to retrieve for matching entries. The function returns a pointer to a newly allocated LDAPSchema structure containing the search results. The caller is responsible for freeing the returned structure using ldap_schema_freeref().

ldap_schparse() parses a string containing schema definitions and populates an LDAPSchema structure. The string is specified by s. The parsed schema is returned in the structure pointed to by sp. The options argument specifies parsing options. This routine may return NULL if no memory can be allocated for the schema structure.

Routines ldap_xxx2name() return a canonical name for the definition.

Routines ldap_xxx2str() return a string representation in the format described by RFC 4512 of the struct passed in the argument. The string is a newly allocated string that must be freed by the caller. These routines may return NULL if no memory can be allocated for the string.

ldap_scherr2str() returns a NUL-terminated string with a text description of the error found. This is a pointer to a static area, so it must not be freed by the caller. The argument code comes from one of the parsing routines and can adopt the following values:

LDAP_SCHERR_OUTOFMEM
Out of memory.
LDAP_SCHERR_UNEXPTOKEN
Unexpected token.
LDAP_SCHERR_NOLEFTPAREN
Missing opening parenthesis.
LDAP_SCHERR_NORIGHTPAREN
Missing closing parenthesis.
LDAP_SCHERR_NODIGIT
Expecting digit.
LDAP_SCHERR_BADNAME
Expecting a name.
LDAP_SCHERR_BADDESC
Bad description.
LDAP_SCHERR_BADSUP
Bad superiors.
LDAP_SCHERR_DUPOPT
Duplicate option.
LDAP_SCHERR_EMPTY
Unexpected end of data.
