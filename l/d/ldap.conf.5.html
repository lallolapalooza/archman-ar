ldap.conf(5)

الحزمة: libldap

التراخيص: custom

LDAP.CONF(5) دليل صيغ الملفات LDAP.CONF(5)

الاسم

ldap.conf, .ldaprc - ملف الإعدادات LDAP/متغيرات البيئة

ملخص

ETCDIR/ldap.conf, ldaprc, .ldaprc, $LDAP<اسم-الخيار>

الوصف

إذا تم تعريف متغير البيئة LDAPNOINIT، فسيتم تعطيل جميع الإعدادات الافتراضية.

يُستخدم ملف الإعدادات ldap.conf لتعيين القيم الافتراضية على مستوى النظام التي سيتم تطبيقها عند تشغيل عملاء ldap.

يمكن للمستخدمين إنشاء ملف إعدادات اختياري، ldaprc أو .ldaprc، في دليلهم الرئيسي والذي سيتم استخدامه لتجاوز ملف الإعدادات الافتراضي للنظام. يتم أيضًا استخدام الملف ldaprc في الدليل الحالي.

يمكن تحديد ملفات إعدادات إضافية باستخدام متغيرات البيئة LDAPCONF و LDAPRC. يمكن تعيين LDAPCONF لمسار ملف الإعدادات. يمكن أن يكون هذا المسار مطلقًا أو نسبيًا بالنسبة للدليل الحالي. يجب أن يكون LDAPRC، إذا تم تعريفه، هو الاسم الأساسي لملف في الدليل الحالي أو في دليل المستخدم الرئيسي.

يمكن أيضًا استخدام متغيرات البيئة لتعزيز الإعدادات الافتراضية المستندة إلى الملف. اسم المتغير هو اسم الخيار مسبوقًا بـ LDAP. على سبيل المثال، لتعريف BASE عبر البيئة، قم بتعيين المتغير LDAPBASE إلى القيمة المطلوبة.

بعض الخيارات خاصة بالمستخدم فقط. يتم تجاهل هذه الخيارات إذا كانت موجودة في ldap.conf (أو الملف المحدد بواسطة LDAPCONF).

وبالتالي، يتم قراءة الملفات والمتغيرات التالية، بالترتيب:

    متغير     $LDAPNOINIT، وإذا لم يكن معينًا:
    ملف النظام  ETCDIR/ldap.conf,
    ملفات المستخدم  $HOME/ldaprc,  $HOME/.ldaprc,  ./ldaprc,
    ملف النظام  $LDAPCONF,
    ملفات المستخدم  $HOME/$LDAPRC, $HOME/.$LDAPRC, ./$LDAPRC,
    متغيرات    $LDAP<اسم الخيار بحروف كبيرة>.
تتجاوز الإعدادات اللاحقة الإعدادات السابقة.

الصيغة

خيارات الإعدادات غير حساسة لحالة الأحرف؛ قد تكون قيمها حساسة لحالة الأحرف، حسب كل حالة على حدة.

يتم تجاهل الأسطر الفارغة.
الأسطر التي تبدأ بعلامة هاش (`#') هي تعليقات، ويتم تجاهلها.

الأسطر الصالحة تتكون من اسم خيار (تسلسل من الأحرف غير الفارغة، يُكتب عادةً بأحرف كبيرة، على الرغم من أنه غير مطلوب)، متبوعًا بقيمة. تبدأ القيمة بأول حرف غير فارغ بعد اسم الخيار، وتنتهي بنهاية السطر، أو بآخر تسلسل من المسافات قبل نهاية السطر. يتم تفويض تقسيم القيمة، إن وجد، إلى المعالجات الخاصة بهذا الخيار، إن وجدت. قد يكون اقتباس القيم التي تحتوي على مسافات غير صحيح، حيث ستصبح علامات الاقتباس جزءًا من القيمة. على سبيل المثال،

# خطأ - علامات اقتباس خاطئة:
URI     "ldap:// ldaps://"
# صحيح - قائمة عناوين URI مفصولة بمسافات، بدون علامات اقتباس:
URI     ldap:// ldaps://
# صحيح - صيغة DN تحتاج إلى اقتباس لـ Example, Inc:
BASE    ou=IT staff,o="Example, Inc",c=US
# أو:
BASE    ou=IT staff,o=Example\2C Inc,c=US
# خطأ - تعليق في نفس السطر مع الخيار:
DEREF   never           # لا تتبع الأسماء المستعارة أبدًا

لا يمكن أن يكون طول السطر أطول من LINE_MAX، والذي يجب أن يكون أكثر من 2000 بايت على جميع الأنظمة الأساسية. لا توجد آلية لتقسيم سطر طويل على عدة أسطر، سواء للتحسين أو للتغلب على الحد أعلاه.

الخيارات

خيارات الإعدادات المختلفة هي:

URI <ldap[si]://[name[:port]] ...>
يحدد عنوان (عناوين) الخادم LDAP الذي يجب أن تتصل به مكتبة LDAP. يمكن أن يكون مخطط URI أيًا من ldap، ldaps أو ldapi، والتي تشير إلى LDAP عبر TCP، LDAP عبر SSL (TLS) و LDAP عبر IPC (مقابس مجال UNIX)، على التوالي. يمكن تحديد اسم كل خادم كاسم نمط نطاق أو حرفي عنوان IP. اختياريًا، يمكن أن يتبع اسم الخادم ':' ورقم المنفذ الذي يستمع إليه خادم LDAP. إذا لم يتم توفير رقم منفذ، فسيتم استخدام المنفذ الافتراضي للمخطط (389 لـ ldap://، 636 لـ ldaps://). بالنسبة لـ LDAP عبر IPC، name هو اسم المقبس، ولا يلزم وجود port، ولا يُسمح به؛ لاحظ أنه يجب ترميز فواصل الدلائل، مثل أي أحرف أخرى خاصة بعناوين URL؛ لذا فإن المقبس

/usr/local/var/ldapi

يجب تحديده كـ

ldapi://%2Fusr%2Flocal%2Fvar%2Fldapi

يمكن توفير قائمة بعناوين URI مفصولة بمسافات.

BASE <base>
يحدد اسم DN الأساسي الافتراضي الذي سيتم استخدامه عند إجراء عمليات ldap. يجب تحديد الأساس كاسم DN مميز بتنسيق LDAP.
BINDDN <dn>
يحدد اسم DN الربط الافتراضي الذي سيتم استخدامه عند إجراء عمليات ldap. يجب تحديد اسم DN الربط كاسم DN مميز بتنسيق LDAP. هذا خيار للمستخدم فقط.
DEREF <when>
يحدد كيفية إلغاء الإحالة للأسماء المستعارة عند إجراء بحث. يمكن تحديد <when> كواحد من الكلمات المفتاحية التالية:
never
لا يتم إلغاء الإحالة للأسماء المستعارة أبدًا. هذا هو الافتراضي.
searching
يتم إلغاء الإحالة للأسماء المستعارة في العناصر الفرعية للكائن الأساسي، ولكن ليس في تحديد موقع الكائن الأساسي للبحث.
finding
يتم إلغاء الإحالة للأسماء المستعارة فقط عند تحديد موقع الكائن الأساسي للبحث.
always
يتم إلغاء الإحالة للأسماء المستعارة في كل من البحث وتحديد موقع الكائن الأساسي للبحث.
HOST <name[:port] ...>
يحدد اسم (أسماء) خادم (خوادم) LDAP الذي يجب أن تتصل به مكتبة LDAP. يمكن تحديد اسم كل خادم كاسم نمط نطاق أو عنوان IP، واختياريًا متبوعًا بـ ':' ورقم المنفذ الذي يستمع إليه خادم ldap. يمكن توفير قائمة مضيفين مفصولة بمسافات. HOST مهمل لصالح URI.
KEEPALIVE_IDLE
يضبط/يحصل على عدد الثواني التي يجب أن يظل فيها الاتصال خاملاً قبل أن تبدأ TCP في إرسال استقصاءات الحفاظ على الاتصال. لينكس فقط.
KEEPALIVE_PROBES
يضبط/يحصل على الحد الأقصى لعدد استقصاءات الحفاظ على الاتصال التي يجب أن ترسلها TCP قبل إنهاء الاتصال. لينكس فقط.
KEEPALIVE_INTERVAL
يضبط/يحصل على الفترة الزمنية بالثواني بين استقصاءات الحفاظ على الاتصال الفردية. لينكس فقط.
NETWORK_TIMEOUT <integer>
يحدد المهلة الزمنية (بالثواني) التي بعدها يعود poll(2) / select(2) بعد connect(2) في حالة عدم وجود نشاط.
PORT <port>
يحدد المنفذ الافتراضي المستخدم عند الاتصال بخادم (خوادم) LDAP. يمكن تحديد المنفذ كرقم. PORT مهمل لصالح URI.
REFERRALS <on/true/yes/off/false/no>
يحدد ما إذا كان يجب على العميل متابعة الإحالات التي يتم إرجاعها بواسطة خوادم LDAP تلقائيًا. الافتراضي هو التشغيل. لاحظ أن أدوات سطر الأوامر مثل ldapsearch(1) &co تتجاوز دائمًا هذا الخيار.
SIZELIMIT <integer>
يحدد حد الحجم (عدد الإدخالات) الذي سيتم استخدامه عند إجراء عمليات البحث. يجب أن يكون الرقم عددًا صحيحًا غير سالب. يحدد SIZELIMIT بقيمة صفر (0) طلبًا لحد بحث غير محدود. يرجى ملاحظة أن الخادم قد يطبق أي حد من جانب الخادم على كمية الإدخالات التي يمكن إرجاعها بواسطة عملية بحث.
SOCKET_BIND_ADDRESSES <IP>
يحدد عنوان IP المصدر المستخدم للاتصال بخادم LDAP المستهدف. يجب فصل عناوين IP المتعددة بمسافات. يُسمح بعنوان IP صالح واحد IPv4 و/أو عنوان IPv6 واحد في القائمة.
TIMELIMIT <integer>
يحدد حد الوقت (بالثواني) الذي سيتم استخدامه عند إجراء عمليات البحث. يجب أن يكون الرقم عددًا صحيحًا غير سالب. قيمة صفر (0) تعني عدم وجود حد زمني.
TLS_CACERT <file>
يحدد مسار ملف يحتوي على شهادة (شهادات) CA الجذرية التي سيتم استخدامها للتحقق من شهادة الخادم. إذا لم يتم تحديد خيار TLS_REQCERT، فلن يتم إجراء أي تحقق.
TLS_CACERTDIR <directory>
يحدد مسار دليل يحتوي على شهادات CA الجذرية التي سيتم استخدامها للتحقق من شهادة الخادم. يجب أن تكون الشهادات موجودة في هذا الدليل بأسماء ملفات مناسبة (على سبيل المثال، نتائج osmocomputing). إذا لم يتم تحديد خيار TLS_REQCERT، فلن يتم إجراء أي تحقق.
TLS_CERT <file>
يحدد مسار ملف يحتوي على شهادة العميل لتوفيرها للخادم عند استخدام TLS. يستخدم هذا الخيار بشكل أساسي للربط للمصادقة.
TLS_CHECK_PEER <yes/no>
هذا خيار مهمل. تم استبداله بـ TLS_REQCERT.
TLS_CIPHER <ciphers>
يحدد قائمة تشفيرات SSL/TLS التي يجب استخدامها. يمكن أن تكون القائمة أي صيغة مقبولة بواسطة OpenSSL.
TLS_DIALOG
يطالب المستخدم بكلمة المرور في كل مرة يحاول فيها فتح اتصال TLS. هذا مفيد إذا كان مفتاح العميل الخاص محميًا بكلمة مرور.
TLS_KEY <file>
يحدد مسار ملف يحتوي على مفتاح العميل الخاص الذي سيتم استخدامه مع شهادة العميل. إذا لم يتم تحديد هذا الخيار، فسيتم البحث عن ملف المفتاح في نفس الدليل الذي توجد فيه الشهادة، مع وجود نفس اسم الملف ولكنه ينتهي بـ ".key".
TLS_LOW_START_TLS
يشير إلى أن الخادم قد لا يدعم STARTTLS بشكل صحيح. عند التمكين، ستحاول المكتبة إعادة محاولة STARTTLS باستخدام أمر LDAPv3 مباشرة.
TLS_NEGOCOTS
يشير إلى أنه يجب التفاوض على بروتوكولات TLS. تم تمكين هذا افتراضيًا.
TLS_PROTOCOL <protocol>
يحدد بروتوكول TLS الذي يجب استخدامه. القيم الممكنة هي TLSv1.0, TLSv1.1, TLSv1.2, TLSv1.3.
TLS_REQCERT <when>
يحدد متى يجب على العميل التحقق من شهادة الخادم. القيم الممكنة هي:
never
لا يتم التحقق من الشهادة مطلقًا.
allow
يتم التحقق من الشهادة إذا كانت متوفرة، ولكن لا يتم إرجاع خطأ إذا لم تكن موجودة أو غير صالحة.
try
يتم التحقق من الشهادة إذا كانت متوفرة. إذا لم تكن متوفرة أو غير صالحة، يتم إرجاع خطأ.
demand or true
يجب التحقق من الشهادة. سيتم إرجاع خطأ إذا لم تكن متوفرة أو غير صالحة. هذا هو الافتراضي.
never
لا يتم التحقق من الشهادة مطلقًا.
TLS_REQUIRE_SOFTWARE_UPDATE
يطالب المستخدم بتأكيد تحديث البرنامج إذا تم اكتشاف تجاوز تاريخ انتهاء صلاحية الشهادة. إذا لم يقم المستخدم بتأكيد التحديث، فسيتم رفض الاتصال.
TLS_SNIFF
يسمح بالاتصال بخادم LDAP غير آمن عبر TLS. سيتم إرجاع خطأ إلا إذا تم تمكين هذا الخيار.
TLS_VERIFY_DEPTH <depth>
يحدد عمق التحقق من سلسلة شهادة الخادم.
URGENT_PIDFILE <file>
يحدد ملف PID للتحقق من أن عميل ldap يعمل.
Version
يطبع رقم إصدار مكتبة ldap.

أمثلة

للبحث في الدليل o=Example, c=US باستخدام خادم LDAP في ldap.example.com:

URI     ldap://ldap.example.com
BASE    o=Example, c=US

للبحث في الدليل dc=example, dc=com باستخدام خادم LDAP في ldaps://ldap.example.com:636 مع التحقق من شهادة الخادم:

URI     ldaps://ldap.example.com:636
BASE    dc=example, dc=com
TLS_REQCERT demand

للبحث في الدليل ou=Users, dc=example, dc=com باستخدام خادم LDAP في ldap.example.com دون استخدام اسم DN الربط الافتراضي:

URI     ldap://ldap.example.com
BASE    ou=Users, dc=example, dc=com
SIZELIMIT       100
TIMELIMIT       300

لتعطيل متابعة الإحالات:

REFERRALS       off

OPTIONS

TLS_CACERTDIR <directory>
The directory containing trusted Certificate Authority (CA) certificates. The certificates must be named using the hash of the subject name, e.g. (using SHA-1) 3c1516d9.0. See openssl-verify(1) for more details. This parameter is ignored with GnuTLS.
TLS_CACERTFILE <filename>
The file containing trusted Certificate Authority (CA) certificates. This parameter is ignored with GnuTLS.
TLS_CERTFILE <filename>
The file containing the client certificate. This option is only used when the client needs to authenticate itself to the server.
TLS_CHECKPEERNAME <level>
Specifies how to check the peer's name against the certificate's Subject Alternative Name (SAN) and Subject Distinguished Name (DN). <level> can be specified as one of the following keywords:
never
The client will not check any SAN in the certificate.
allow
The SAN is checked against the specified hostname. If a SAN is present but none match the specified hostname, the SANs are ignored and the usual check against the certificate DN is used. This is the default setting.
try
The SAN is checked against the specified hostname. If no SAN is present in the server certificate, the usual check against the certificate DN is used. If a SAN is present but doesn't match the specified hostname, the session is immediately terminated. This setting may be preferred when a mix of certs with and without SANs are in use.
demand | hard
These keywords are equivalent. The SAN is checked against the specified hostname. If no SAN is present in the server certificate, or no SANs match, the session is immediately terminated. This setting should be used when only certificates with SANs are in use.
TLS_CRLCHECK <level>
Specifies if the Certificate Revocation List (CRL) of the CA should be used to verify if the server certificates have not been revoked. This requires TLS_CACERTDIR parameter to be set. This parameter is ignored with GnuTLS. <level> can be specified as one of the following keywords:
none
No CRL checks are performed
peer
Check the CRL of the peer certificate
all
Check the CRL for a whole certificate chain
TLS_CRLFILE <filename>
Specifies the file containing a Certificate Revocation List to be used to verify if the server certificates have not been revoked. This parameter is only supported with GnuTLS.

ENVIRONMENT VARIABLES

LDAPNOINIT
disable all defaulting

path of a configuration file

basename of ldaprc file in $HOME or $CWD
LDAP<option-name>
Set <option-name> as from ldap.conf
