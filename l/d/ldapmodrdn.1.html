ldapmodrdn(1)

الحزمة: openldap

التراخيص: custom

LDAPMODRDN(1) دليل الأوامر العامة LDAPMODRDN(1)

الاسم

ldapmodrdn - أداة تغيير اسم الإدخال في LDAP

الملخص

ldapmodrdn [-V[V]] [-d مستوى_التصحيح] [-n] [-v] [-r] [-s newsup] [-c] [-f ملف] [-M[M]] [-x] [-D binddn] [-W] [-w كلمة_مرور] [-y ملف_كلمة_مرور] [-H ldapuri] [-P {2|3}] [-e [!]ext[=معلمة_امتداد]] [-E [!]ext[=معلمة_امتداد]] [-o opt[=معلمة_الخيار]] [-O خصائص_الأمان] [-I] [-Q] [-N] [-U معرف_المصادقة] [-R نطاق] [-X معرف_الترخيص] [-Y آلية] [-Z[Z]] [dn rdn]

الوصف

ldapmodrdn هو واجهة متاحة من سطر الأوامر لاستدعاء مكتبة ldap_rename(3).

يقوم ldapmodrdn بفتح اتصال بخادم LDAP، وربطه، وتعديل RDN للإدخالات. تتم قراءة معلومات الإدخال من الإدخال القياسي، أو من ملف باستخدام الخيار -f، أو من زوج سطر الأوامر dn و rdn.

الخيارات

-V[V]
طباعة معلومات الإصدار. إذا تم تقديم -VV، تتم طباعة معلومات الإصدار فقط.
-d مستوى_التصحيح
تعيين مستوى تصحيح LDAP إلى مستوى_التصحيح. يجب أن يكون ldapmodrdn مجمّعًا مع تعريف LDAP_DEBUG حتى يكون لهذا الخيار أي تأثير.
-n
إظهار ما سيتم فعله، ولكن لا تقم بتغيير الإدخالات فعليًا. مفيد للتصحيح بالاقتران مع -v.
-v
استخدام وضع الإسهاب، مع كتابة العديد من التشخيصات إلى الإخراج القياسي.
-r
إزالة قيم RDN القديمة من الإدخال. الافتراضي هو الاحتفاظ بالقيم القديمة.
-s newsup
تحديد إدخال أب جديد. (أي، نقل الإدخال الهدف وجعله طفلاً للأب الجديد.) هذا الخيار غير مدعوم في LDAPv2.
-c
وضع التشغيل المستمر. يتم الإبلاغ عن الأخطاء، ولكن سيستمر ldapmodrdn في التعديلات. الافتراضي هو الخروج بعد الإبلاغ عن خطأ.
-f ملف
قراءة معلومات تعديل الإدخال من ملف بدلاً من الإدخال القياسي أو سطر الأوامر.
-M[M]
تمكين تحكم DSA IT للإدارة. -MM يجعل التحكم حاسمًا.
-x
استخدام المصادقة البسيطة بدلاً من SASL.
-D binddn
استخدام اسم التمييز binddn للربط بدليل LDAP. بالنسبة لعمليات ربط SASL، يُتوقع من الخادم تجاهل هذه القيمة.
-W
المطالبة بالمصادقة البسيطة. يتم استخدام هذا بدلاً من تحديد كلمة المرور في سطر الأوامر.
-w كلمة_مرور
استخدام كلمة_مرور ككلمة مرور للمصادقة البسيطة.
-y ملف_كلمة_مرور
استخدام المحتويات الكاملة لـ ملف_كلمة_مرور ككلمة مرور للمصادقة البسيطة.
-H ldapuri
تحديد URI (أو URI) التي تشير إلى خادم (خوادم) LDAP؛ يُسمح فقط بحقول البروتوكول/المضيف/المنفذ؛ يُتوقع قائمة من URI، مفصولة بمسافات بيضاء أو فواصل.
-P {2|3}
تحديد إصدار بروتوكول LDAP المراد استخدامه.
-e [!]ext[=معلمة_امتداد]
-E [!]ext[=معلمة_امتداد]

تحديد امتدادات عامة باستخدام -e وامتدادات modrdn باستخدام -E. تشير ´!´ إلى الأهمية.

امتدادات Modrdn:

  (none)
-o opt[=معلمة_الخيار]

تحديد أي خيار ldap.conf(5) أو أحد الخيارات التالية:

  nettimeout=<timeout>  (in seconds, or "none" or "max")
  ldif_wrap=<width>     (in columns, or "no" for no wrapping)
-O خصائص_الأمان
تحديد خصائص أمان SASL.
-I
تمكين وضع SASL التفاعلي. المطالبة دائمًا. الافتراضي هو المطالبة فقط عند الحاجة.
-Q
تمكين وضع SASL الهادئ. لا تطالب أبدًا.
-N
لا تستخدم DNS العكسي لتسوية اسم مضيف SASL.
-U معرف_المصادقة
تحديد معرف المصادقة لربط SASL. شكل المعرف يعتمد على آلية SASL الفعلية المستخدمة.
-R نطاق
تحديد نطاق معرف المصادقة لربط SASL. شكل النطاق يعتمد على آلية SASL الفعلية المستخدمة.
-X معرف_الترخيص
تحديد معرف الترخيص المطلوب لربط SASL. يجب أن يكون authzid أحد التنسيقات التالية: dn:<اسم_مميز> أو u:<اسم_مستخدم>
-Y آلية
تحديد آلية SASL المراد استخدامها للمصادقة. إذا لم يتم تحديدها، سيختار البرنامج أفضل آلية يعرفها الخادم.
-Z[Z]
إصدار عملية StartTLS (Transport Layer Security) الموسعة. إذا استخدمت -ZZ، فسيطلب الأمر نجاح العملية.

تنسيق الإدخال

إذا تم تقديم وسيطات سطر الأوامر dn و rdn، فسيقوم rdn باستبدال RDN للإدخال المحدد بواسطة DN، dn.

بخلاف ذلك، يجب أن تتكون محتويات ملف (أو الإدخال القياسي إذا لم يتم تقديم علامة -f) من إدخال واحد أو أكثر.

    اسم التمييز (DN)
    اسم التمييز النسبي (RDN)

يمكن استخدام سطر واحد أو أكثر من الأسطر الفارغة للفصل بين كل زوج DN/RDN.

مثال

بافتراض أن الملف /tmp/entrymods موجود ويحتوي على:

    cn=Modify Me,dc=example,dc=com
    cn=The New Me

الأمر:

    ldapmodrdn -r -f /tmp/entrymods

سيقوم بتغيير RDN للإدخال "Modify Me" من "Modify Me" إلى "The New Me" وسيتم إزالة cn القديم، "Modify Me".

التشخيصات

حالة الخروج هي 0 إذا لم تحدث أخطاء. تؤدي الأخطاء إلى حالة خروج غير صفرية وكتابة رسالة تشخيصية إلى الإخراج القياسي.

انظر أيضًا

ldapadd(1), NAME

ldapmodrdn — modify the RDN of an entry in an LDAP directory

SYNOPSIS

ldapmodrdn [-V] [-d level] [-n authzid] [-f ldif-file] [-H ldap-uri] [-h host] [-p port] [-D binddn] [-w passwd | -W] [-y passwdfile] [-b basedn] [-I] [-l ldif-in] [-o ldif-output-file] [-r newrdn] [-s newSuperior] [-R newParent] [-e extop] [-E extop-authz] [-t scope] [-L] [-Z] [-X authtype] [-Y mech] [-Q] [-N] [-M] [-O max-passive-senders] [-P max-senders] [-S sslpref] [-U uri] [-u] [-K keypath] [-k secretpath] [-F keycertpath] [-G proxyDN] [-g proxyAuthz] [-j sasl-param] [-i ldif-in] [-P ldif-out] [-S ldif-script] [dn ...]

DESCRIPTION

The ldapmodrdn utility is used to modify the Relative Distinguished Name (RDN) of one or more entries in an LDAP directory. This operation is also known as renaming an entry, although strictly speaking, only the RDN is changed, not the entire Distinguished Name (DN).

The utility can be used in two primary modes:

  • Interactive Mode: When no LDIF input is provided, ldapmodrdn prompts the user for the new RDN and optionally for a new parent entry for the modified entry.

  • Batch Mode: When an LDIF input file is specified using the -f option, ldapmodrdn processes the modifications described in the file. Each record in the LDIF file should describe an entry to be modified and specify the new RDN and optionally the new parent.

The modification is performed using the LDAP modify RDN operation.

OPTIONS

The options available to ldapmodrdn are extensive and mirror many of the options found in other LDAP utilities like ldapmodify and ldapsearch. Key options include:

-d level
Set LDAP protocol debugging level.
-n authzid
Specify the authorized identity for the operation.
-f ldif-file
Read modification requests from the specified LDIF file.
-H ldap-uri
Specify the LDAP server URI (e.g., ldap://ldap.example.com).
-h host
Specify the LDAP server host name.
-p port
Specify the LDAP server port.
-D binddn
Bind DN for authentication.
-w passwd | -W
Password for authentication. -W prompts for the password.
-y passwdfile
Read password from the specified file.
-b basedn
Base DN for the search or operation.
-I
Use referral chasing.
-l ldif-in
LDIF input file (alternative to -f).
-o ldif-output-file
Write LDIF output to the specified file.
-r newrdn
Specify the new RDN directly.
-s newSuperior
Specify a new parent for the entry.
-R newParent
Specify a new parent for the entry (alternative to -s).
-e extop
Use an extended operation.
-E extop-authz
Authorization for extended operation.
-t scope
Scope of the operation (base, one, sub).
-L
Use SSL/TLS.
-Z
Use StartTLS.
-X authtype
SASL authentication type.
-Y mech
SASL mechanism.
-Q
Do not prompt for SASL password.
-N
Do not use the default SASL realm.
-M
Use referral chasing (alternative to -I).
-O max-passive-senders
Maximum passive senders for replication.
-P max-senders
Maximum senders for replication.
-S sslpref
SSL/TLS preference.
-U uri
LDAP URI (alternative to -H).
-u
Use authenticated user (anonymous bind).
-K keypath
Path to client certificate key.
-k secretpath
Path to client secret.
-F keycertpath
Path to client certificate.
-G proxyDN
Proxy DN for proxied authorization.
-g proxyAuthz
Proxy authorization rule.
-j sasl-param
SASL parameter.
-i ldif-in
LDIF input file (alternative to -f and -l).
-P ldif-out
LDIF output file (alternative to -o).
-S ldif-script
LDIF script file.
dn ...
The distinguished name(s) of the entry or entries to modify.

INPUT FORMAT

When using the -f or -l options, the input file should be in LDIF (LDAP Data Interchange Format). Each entry in the LDIF file should contain the following information:

  • The Distinguished Name (DN) of the entry to be modified.
  • The new Relative Distinguished Name (RDN).
  • Optionally, the DN of the new parent entry if the entry is being moved to a different part of the directory tree.

A typical LDIF record for modifying an RDN might look like this:

dn: uid=olduser,ou=people,dc=example,dc=com
changetype: modify
replace: RDN
RDN: uid=newuser
-
add: parentDN
parentDN: ou=users,dc=example,dc=com

In this example, the RDN of the entry uid=olduser,ou=people,dc=example,dc=com is changed to uid=newuser, and its parent is changed to ou=users,dc=example,dc=com.

If the new parent is not specified, the entry will remain under its current parent.

EXAMPLE

Interactive mode:

$ ldapmodrdn -h ldap.example.com -D "cn=admin,dc=example,dc=com" -W "uid=olduser,ou=people,dc=example,dc=com"
Enter new RDN: uid=newuser
Enter new parent DN (leave blank to keep current parent): 
new RDN of entry uid=olduser,ou=people,dc=example,dc=com with new RDN uid=newuser? (true/false) true
adding new attribute "RDN"
adding new attribute "parentDN"
modifying RDN of entry uid=olduser,ou=people,dc=example,dc=com...
... success ...

Batch mode using an LDIF file:

Create a file named modify_rdn.ldif with the following content:

dn: uid=olduser,ou=people,dc=example,dc=com
changetype: modify
replace: RDN
RDN: uid=newuser
-
add: parentDN
parentDN: ou=users,dc=example,dc=com

Then run:

$ ldapmodrdn -h ldap.example.com -D "cn=admin,dc=example,dc=com" -W -f modify_rdn.ldif
modifying RDN of entry uid=olduser,ou=people,dc=example,dc=com...
... success ...

DIAGNOSTICS

Exit status is zero on success, and non-zero on failure. Errors are reported to standard error.
