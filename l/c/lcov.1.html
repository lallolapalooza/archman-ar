NAME

lcov - a graphical GCOV front-end

SYNOPSIS

Capture coverage data tracefile (from compiler-generated data).
The lcov tracefile (".info" file) format is described in man geninfo(1).

lcov -c|--capture

[-d|--directory directory] [-k|--kernel-directory directory]
[-o|--output-file tracefile] [-t|--test-name testname]
[-b|--base-directory directory]
[--build-directory directory]
[--source-directory directory]
[-i|--initial]
[--all]
[--gcov-tool tool]
[--branch-coverage]
[--mcdc-coverage]
[--demangle-cpp [param]]
[--checksum] [--no-checksum] [--no-recursion] [-f|--follow]
[--sort-input]
[--compat-libtool] [--no-compat-libtool]
[--msg-log [log_file_name]]
[--ignore-errors errors]
[--expect-message-count message_type=expr[,message_type=expr..]]
[--preserve] [--to-package package] [--from-package package] [--no-markers] [--external] [--no-external]
[--compat mode=on|off|auto]
[--context-script script_file]
[--criteria-script script_file]
[--resolve--script script_file]
[--version-script script_file]
[--comment comment_string]
[--large-file regexp]

Generate tracefile (from compiler-generated data) with all counter values set to zero:

lcov -z|--zerocounters

[-d|--directory directory] [--no-recursion] [-f|--follow]

Show coverage counts recorded in previously generated tracefile:

lcov -l|--list tracefile

[--list-full-path] [--no-list-full-path]

Aggregate multiple coverage tracefiles into one:

lcov -a|--add-tracefile tracefile_pattern

[-o|--output-file tracefile]
[--prune-tests]
[--forget-test-names]
[--map-functions]
[--branch-coverage]
[--mcdc-coverage]
[--checksum] [--no-checksum]
[--sort-input]

Depending on your use model, it may not be necessary to create aggregate coverage data files. For example, if your regression tests are split into multiple suites, you may want to keep separate suite data and to compare both per-suite and aggregate results over time. genhtml allows you specify tracefiles via one or more glob patterns - which enables you generate aggregate reports without explicitly generating aggregated trace files. See the genhtml man page.

Generate new tracefile from existing tracefile, keeping only data from files matching pattern:

lcov -e|--extract tracefile pattern

[-o|--output-file tracefile] [--checksum] [--no-checksum]

Generate new tracefile from existing tracefile, removing data from files matching pattern:

lcov -r|--remove tracefile pattern

[-o|--output-file tracefile] [--checksum] [--no-checksum]

Generate new tracefile from existing tracefiles by performing set operations on coverage data:

lcov --intersect rh_glob_pattern

[-o|--output-file tracefile]
lh_glob_pattern

The output will reflect

(union of files matching lh_glob_patterns) intersect (union of files matching rh_glob_patterns)
such that coverpoints found in both sets are merged (summed) whereas coverpoints found in only one set are dropped. Note that branch blocks are defined to be the same if and only if their block ID and the associated branch expressions list are identical. Functions are defined to be the same if their name and location are identical.
lcov --subtract rh_glob_pattern

[-o|--output-file tracefile]
lh_glob_pattern

The output will reflect

(union of files matching lh_glob_patterns) subtract (union of files matching rh_glob_patterns)
such that coverpoints found only in the set on the left will be retained and all others are dropped.

Summarize tracefile content:

lcov --summary tracefile

Print version or help message and exit:

lcov [-h|--help] [--version]

Common lcov options - supported by all the above use cases:

lcov [--keep-going]
[--filter type]
[-q|--quiet]
[-v|--verbose]
[--comment comment_string]
[--debug]
[--parallel|-j [integer]]
[--memory integer_num_Mb]
[--tempdir dirname]
[--branch-coverage]
[--mcdc-coverage]
[--config-file config-file] [--rc keyword=value]
[--profile [profile-file]]
[--include glob_pattern]
[--exclude glob_pattern]
[--erase-functions regexp_pattern]
[--substitute regexp_pattern]
[--omit-lines regexp_pattern]
[--fail-under-branches percentage]
[--fail-under-lines percentage]

DESCRIPTION

lcov is a graphical front-end for GCC's coverage testing tool gcov. It collects line, function and branch coverage data for multiple source files and creates HTML pages containing the source code annotated with coverage information. It also adds overview pages for easy navigation within the file structure.

Use lcov to collect coverage data and genhtml to create HTML pages. Coverage data can either be collected from the currently running Linux kernel or from a user space application. To do this, you have to complete the following preparation steps:

For Linux kernel coverage:

Follow the setup instructions for the gcov-kernel infrastructure: https://docs.kernel.org/dev-tools/gcov.html

For user space application coverage:

Compile the application with GCC using the options "-fprofile-arcs" and "-ftest-coverage" or "--coverage".

Please note that this man page refers to the output format of lcov as ".info file" or "tracefile" and that the output of GCOV is called ".da file".

Also note that when printing percentages, 0% and 100% are only printed when the values are exactly 0% and 100% respectively. Other values which would conventionally be rounded to 0% or 100% are instead printed as nearest non-boundary value. This behavior is in accordance with that of the gcov(1) tool.

By default, lcov and related tools generate and collect line and function coverage data. Branch data is not collected or displayed by default; all tools support the --branch-coverage and --mdcd-coverage options to enable branch and MC/DC coverage, respectively - or you can permanently enable branch coverage by adding the appropriate settings to your personal, group, or site lcov configuration file. See man lcovrc(5) for details.

OPTIONS

In general, (almost) all lcov options can also be specified in a configuration file - see man lcovrc(5) for details.

-a tracefile_pattern
--add-tracefile tracefile_pattern

Add contents of all files matching glob pattern

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

tracefile_pattern.

حدد عدة ملفات تتبع باستخدام المفتاح -a لدمج بيانات التغطية الموجودة في هذه الملفات عن طريق إضافة أعداد التنفيذ لتركيبات الاختبار واسم الملف المطابقة.

سيتم كتابة نتيجة عملية الجمع إلى المخرج القياسي (stdout) أو إلى ملف التتبع المحدد باستخدام -o.

يمكن تحديد واحد فقط من الخيارات التالية في كل مرة: -z، -c، -a، -e، -r، -l أو --summary.

-b directory
--base-directory directory

استخدم directory كدليل أساسي للمسارات النسبية.

استخدم هذا الخيار لتحديد الدليل الأساسي لبيئة بناء عندما ينتج lcov رسائل خطأ مثل:

ERROR: could not read source file /home/user/project/subdir1/subdir2/subdir1/subdir2/file.c

في هذا المثال، استخدم /home/user/project كدليل أساسي.

هذا الخيار مطلوب عند استخدام lcov على مشاريع تم بناؤها باستخدام libtool أو بيئات بناء مماثلة تعمل مع دليل أساسي، أي البيئات التي لا يكون فيها الدليل الحالي عند استدعاء المترجم هو نفس الدليل الذي يوجد فيه ملف الكود المصدري.

لاحظ أن هذا الخيار لن يعمل في البيئات التي تستخدم عدة أدلة أساسية. في هذه الحالة، استخدم إعداد ملف التكوين geninfo_auto_base=1 (انظر man lcovrc(5)).

--build-directory build_directory

ابحث عن ملفات بيانات .gcno من build_directory بدلاً من مجاورتها لملف .gcda المقابل.

انظر man geninfo(1)) للحصول على التفاصيل.

--source-directory dirname
أضف 'dirname' إلى قائمة الأماكن للبحث عن الملفات المصدر.

بالنسبة لمسارات الملفات المصدر النسبية المدرجة في، على سبيل المثال، المسارات الموجودة في tracefile، أو الموجودة في مخرجات gcov أثناء --capture - ربما بعد تطبيق البدائل - سيبحث lcov أولاً عن المسار من 'cwd' (حيث تم استدعاء genhtml) ثم من كل دليل بديل بالترتيب المحدد. يتم استخدام أول موقع مطابق.

يمكن تحديد هذا الخيار عدة مرات، لإضافة المزيد من الأدلة إلى مسار البحث عن المصدر.

-c
--capture
التقاط بيانات تغطية وقت التشغيل.

بشكل افتراضي، يلتقط أعداد تنفيذ النواة الحالية ويكتب بيانات التغطية الناتجة إلى المخرج القياسي. استخدم الخيار --directory لالتقاط الأعداد لبرنامج مساحة المستخدم.

سيتم كتابة نتيجة عملية الالتقاط إلى المخرج القياسي (stdout) أو إلى ملف التتبع المحدد باستخدام -o.

عند دمجه مع العلامة --all، سيتم استخراج كل من تغطية وقت التشغيل وتغطية وقت التجميع في خطوة واحدة. راجع وصف العلامة --initial، أدناه.

انظر man geninfo(1)) لمزيد من التفاصيل حول عملية الالتقاط والخيارات والمعلمات المتاحة.

يمكن تحديد واحد فقط من الخيارات التالية في كل مرة: -z، -c، -a، -e، -r، -l، --diff أو --summary.

--branch-coverage


اجمع أو احتفظ ببيانات تغطية الفروع.

هذا يعادل استخدام الخيار "--rc branch_coverage=1"؛ تمت إضافة الخيار لمطابقة واجهة genhml بشكل أفضل.

--mcdc-coverage


اجمع واحتفظ ببيانات MC/DC.

هذا يعادل استخدام الخيار "--rc mcdc_coverage=1"؛. يتم دعم تغطية MC/DC لإصدارات GCC 14.2 والإصدارات الأحدث، أو LLVM 18.1 والإصدارات الأحدث.
راجع llvm2lcov --help للحصول على تفاصيل حول التقاط بيانات MC/DC في LLVM.

راجع قسم MC/DC في man genhtml(1) لمزيد من التفاصيل

--checksum
--no-checksum

حدد ما إذا كنت تريد إنشاء بيانات checksum عند كتابة ملفات التتبع و/أو التحقق من تطابق checksums عند دمج ملفات التتبع.

استخدم --checksum لتمكين إنشاء checksum أو --no-checksum لتعطيله. يتم تعطيل إنشاء checksum افتراضيًا.

عند تمكين إنشاء checksum، سيتم إنشاء checksum لكل سطر كود مصدري وتخزينه مع بيانات التغطية. سيتم استخدام هذا checksum لمنع محاولات دمج بيانات التغطية من إصدارات مختلفة من الكود المصدري.

إذا كنت لا تعمل مع إصدارات مختلفة من الكود المصدري، فقم بتعطيل هذا الخيار لتسريع معالجة بيانات التغطية وتقليل حجم ملفات التتبع.

لاحظ أن هذا الخيار مستوعب إلى حد ما بواسطة الخيار --version-script - الذي يقوم بشيء مشابه، ولكن على مستوى 'الملف بالكامل'.

--compat mode=value[,mode=value,...]

تعيين وضع التوافق.

استخدم --compat لتحديد أن lcov يجب أن يمكّن وضع توافق واحد أو أكثر عند التقاط بيانات التغطية. يمكنك توفير قائمة مفصولة بفواصل من أزواج mode=value لتحديد القيم لأوضاع متعددة.

القيم values الصالحة هي:

on

تمكين وضع التوافق.
off
تعطيل وضع التوافق.
auto
تطبيق الكشف التلقائي لتحديد ما إذا كان وضع التوافق مطلوبًا. لاحظ أن الكشف التلقائي غير متاح لجميع أوضاع التوافق.

إذا لم يتم تحديد قيمة، فسيتم افتراض 'on' كقيمة افتراضية.

الأوضاع modes الصالحة هي:

libtool

قم بتمكين هذا الوضع إذا كنت تلتقط بيانات التغطية لمشروع تم بناؤه باستخدام آلية libtool. انظر أيضًا --compat-libtool.

القيمة الافتراضية لهذا الإعداد هي 'on'.

hammer
قم بتمكين هذا الوضع إذا كنت تلتقط بيانات التغطية لمشروع تم بناؤه باستخدام إصدار من GCC 3.3 يحتوي على تعديل (رقعة hammer) لإصدارات GCC اللاحقة. يمكنك التعرف على إصدار GCC 3.3 المعدل عن طريق التحقق من دليل البناء لمشروعك بحثًا عن الملفات التي تنتهي بالامتداد '.bbg'. الإصدارات غير المعدلة من GCC 3.3 تسمي هذه الملفات '.bb'.

القيمة الافتراضية لهذا الإعداد هي 'auto'.

split_crc
قم بتمكين هذا الوضع إذا كنت تلتقط بيانات التغطية لمشروع تم بناؤه باستخدام إصدار من GCC 4.6 يحتوي على تعديل (تجزئة checksums الوظائف) لإصدارات GCC اللاحقة. رسائل الخطأ النموذجية عند تشغيل lcov على بيانات التغطية التي تنتجها إصدارات GCC هذه هي ´out of memory' و 'reached unexpected end of file'.

القيمة الافتراضية لهذا الإعداد هي 'auto'

--compat-libtool
--no-compat-libtool

حدد ما إذا كنت تريد تمكين وضع توافق libtool.

استخدم --compat-libtool لتمكين وضع توافق libtool أو --no-compat-libtool لتعطيله. وضع توافق libtool ممكّن افتراضيًا.

عند تمكين وضع توافق libtool، سيفترض lcov أن الكود المصدري المتعلق بملف .da الموجود في دليل يسمى ".libs" يمكن العثور عليه في دليله الأصل.

إذا كانت لديك أدلة تسمى ".libs" في بيئة البناء الخاصة بك ولكنك لا تستخدم libtool، فقم بتعطيل هذا الخيار لمنع حدوث مشاكل عند التقاط بيانات التغطية.

--config-file config-file

حدد ملف تكوين لاستخدامه. انظر man lcovrc(5) للحصول على تفاصيل حول تنسيق الملف والخيارات. راجع أيضًا إدخال config_file في نفس صفحة man للحصول على تفاصيل حول كيفية تضمين ملف تكوين في ملف آخر.

عند تحديد هذا الخيار، لن يتم قراءة ملف التكوين الخاص بالنظام /etc/lcovrc، ولا ملف التكوين الخاص بالمستخدم ~/.lcovrc.

قد يكون هذا الخيار مفيدًا عندما تكون هناك حاجة لتشغيل عدة مثيلات من lcov بخيارات ملف تكوين مختلفة بالتوازي.

لاحظ أن هذا الخيار يجب تحديده بالكامل - الاختصارات غير مدعومة.

--profile [ profile-data-file ]

أخبر الأداة بتتبع بيانات الأداء وبيانات التكوين الأخرى. إذا لم يتم تحديد profile-data-file الاختياري، فسيتم كتابة بيانات الملف الشخصي إلى ملف بنفس الاسم الأساسي لـ --output-filename، مع إضافة اللاحقة .json.

يمكن تحديد واحد فقط من الخيارات التالية في كل مرة: -z، -c، -a، -e، -r، -l، --diff أو --summary.

-d directory
--directory directory

استخدم ملفات .da في directory بدلاً من النواة.

إذا كنت تريد العمل على بيانات تغطية لبرنامج مساحة المستخدم، فاستخدم هذا الخيار لتحديد الموقع الذي تم فيه تجميع البرنامج (حيث سيتم تخزين ملفات العداد التي تنتهي بـ .da).

لاحظ أنه يمكنك تحديد هذا الخيار أكثر من مرة.

--exclude pattern

استبعد الملفات المصدر المطابقة لـ pattern.

استخدم هذا المفتاح إذا كنت ترغب في استبعاد بيانات التغطية لمجموعة معينة من الملفات المصدر التي تطابق أيًا من الأنماط المحددة. يمكن تحديد أنماط متعددة باستخدام مفاتيح سطر الأوامر --exclude متعددة. سيتم تفسير patterns على أنها أنماط أحرف البدل للصدفة (لاحظ أنه قد يلزم الهروب منها بشكل مناسب لمنع الصدفة من توسيعها أولاً).

ملاحظة: يجب تحديد النمط لمطابقة المسار المطلق لكل ملف مصدر. إذا قمت بتحديد نمط لا يبدو أنه مطبق بشكل صحيح - لا تزال الملفات التي كنت تتوقع استبعادها تظهر في المخرجات - يمكنك البحث عن رسائل التحذير في ملف السجل. سيقوم lcov بإصدار تحذير لكل نمط لا يتم تطبيقه مرة واحدة على الأقل.

يمكن دمجه مع مفتاح سطر الأوامر --include. إذا تطابق ملف معين مع نمط التضمين ونمط الاستبعاد، فسيكون لنمط الاستبعاد الأسبقية.

--erase-functions regexp

استبعد بيانات التغطية من الأسطر التي تقع ضمن وظيفة يتطابق اسمها مع التعبير العادي (regexp) المقدم. لاحظ أن هذا اسم مشفر أو مفكوك تشفيره، اعتمادًا على ما إذا كان الخيار --demangle-cpp مستخدمًا أم لا.

لاحظ أن هذا الخيار يتطلب منك استخدام إصدار gcc جديد بما يكفي لدعم تقارير بداية/نهاية الوظيفة أو أن تقوم بتكوين الأداة لاستنتاج البيانات المطلوبة - انظر مناقشة derive_function_end_line في man lcovrc(5).

--substitute regexp_pattern
طبق تعبير Perl العادي regexp_pattern على أسماء الملفات المصدر التي تم العثور عليها أثناء المعالجة. هذا مفيد، على سبيل المثال، عندما لا يتطابق اسم المسار الذي أبلغ عنه gcov مع تخطيط المصدر الخاص بك ولا يتم العثور على الملف، أو في بيئات أكثر تعقيدًا حيث لا يتطابق هيكل دليل البناء مع تخطيط الكود المصدري أو التخطيط في نظام التحكم في إصدارات المشروع.
