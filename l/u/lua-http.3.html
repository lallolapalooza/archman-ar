مقدمة

lua-http هي مكتبة HTTP و WebSocket سريعة وقادرة لـ Lua 5.1، 5.2، 5.3 و LuaJIT. بعض ميزات المكتبة تشمل:

•
دعم إصدارات HTTP 1، 1.1 و 2 كما هو محدد بواسطة RFC 7230 (https://tools.ietf.org/html/rfc7230) و RFC 7540 (https://tools.ietf.org/html/rfc7540)
•
توفر واجهات برمجة تطبيقات للعميل والخادم
•
واجهة برمجة تطبيقات غير متزامنة بالكامل لا تمنع الخيط الحالي عند تنفيذ عمليات عادة ما تكون معطلة
•
دعم WebSockets كما هو محدد بواسطة RFC 6455 (https://tools.ietf.org/html/rfc6455) بما في ذلك ping/pong، نقل البيانات الثنائية وتشفير TLS
•
أمان طبقة النقل (TLS) - تدعم lua-http HTTPS و WSS عبر luaossl (https://github.com/wahern/luaossl).
•
تكامل سهل مع حلقات الأحداث أو النصوص البرمجية الأخرى

لماذا lua-http؟

تمت كتابة مكتبة lua-http لسد فجوة في نظام Lua البيئي من خلال توفير مكتبة HTTP و WebSocket بالسمات التالية:

•
غير متزامن وذو أداء عالٍ
•
يمكن استخدامه دون إجبار المطور على اتباع نمط معين. على العكس من ذلك، يمكن تكييف المكتبة مع العديد من الأنماط الشائعة.
•
يمكن استخدامه على مستوى عالٍ جدًا دون الحاجة إلى فهم نقل بيانات HTTP (بخلاف عناوين الاتصال).
•
يوفر واجهة برمجة تطبيقات غنية ومنخفضة المستوى، إذا رغبت في ذلك، لإنشاء أدوات قوية تعتمد على HTTP على مستوى البروتوكول.

نتيجة لهذه الأهداف التصميمية، فإن المكتبة بسيطة وغير مزعجة ويمكنها استيعاب عشرات الآلاف من الاتصالات على أجهزة تجارية.

lua-http هي مكتبة HTTP و WebSocket مرنة تسمح للمطورين بالتركيز على ميزات العمل الأساسية عند بناء التطبيقات المتصلة بالإنترنت. إذا كنت تبحث عن طريقة لتبسيط تطوير تطبيق متصل بالإنترنت، أو تمكين الشبكات HTTP في لعبتك، أو إنشاء نظام إنترنت الأشياء (IoT) جديد، أو كتابة خادم ويب مخصص عالي الأداء لحالة استخدام محددة، فإن lua-http لديها الأدوات التي تحتاجها.

قابلية النقل

lua-http هو رمز Lua نقي يعتمد على المكتبات الخارجية التالية:

•
cqueues (http://25thandclement.com/~william/projects/cqueues.html) - مكتبة واجهة برمجة تطبيقات Posix لـ Lua
•
luaossl (http://25thandclement.com/~william/projects/luaossl.html) - ربط Lua لـ TLS/SSL
•

يمكن تشغيل lua-http على أي نظام تشغيل مدعوم من cqueues و openssl، وهو في وقت الكتابة GNU/Linux، FreeBSD، NetBSD، OpenBSD، OSX و Solaris.

حالات الاستخدام الشائعة

فيما يلي عرضان توضيحيان بسيطان لكيفية استخدام مكتبة lua-http:

استرداد مستند

أعلى مستوى واجهة للعملاء هو http.request. عن طريق بناء كائن request من URI باستخدام new_from_uri وتقييمه فورًا، يمكنك بسهولة جلب مورد HTTP.

local http_request = require "http.request"
local headers, stream = assert(http_request.new_from_uri("http://example.com"):go())
local body = assert(stream:get_body_as_string())
if headers:get ":status" ~= "200" then
    error(body)
end
print(body)

اتصالات WebSocket

لطلب معلومات من خادم WebSocket، استخدم وحدة websocket لإنشاء عميل WebSocket جديد.

local websocket = require "http.websocket"
local ws = websocket.new_from_uri("wss://echo.websocket.org")
assert(ws:connect())
assert(ws:send("koo-eee!"))
local data = assert(ws:receive())
assert(data == "koo-eee!")
assert(ws:close())

العملية غير المتزامنة

تمت كتابة lua-http للعمل بشكل غير متزامن حتى يمكن استخدامه في تطبيقك أو خادمك أو لعبتك دون حظر حلقة التطبيق الرئيسية. يتم تحقيق العمليات غير المتزامنة عن طريق استخدام cqueues، وهي مكتبة Lua/C تدمج Yielding Lua وواجهات برمجة التطبيقات على مستوى النواة لتقليل استخدام وحدة المعالجة المركزية. لن تمنع جميع عمليات lua-http، بما في ذلك البحث عن DNS، والتفاوض على TLS، وعمليات القراءة/الكتابة، الخيط الرئيسي للتطبيق عند تشغيلها من داخل cqueue أو "حاوية" مدعومة بـ cqueue. بينما قد يكون من الضروري في بعض الأحيان حظر روتين (yield) وانتظار بيانات خارجية، فإن جميع استدعاءات واجهة برمجة التطبيقات المعطلة تأخذ مهلة اختيارية لضمان سلوك جيد للتطبيقات المتصلة بالشبكة وتجنب الروتينات غير المستجيبة أو "الميتة".

العمليات غير المتزامنة هي واحدة من أقوى ميزات lua-http ولا تتطلب أي جهد من المطور. على سبيل المثال، يمكن إنشاء خادم HTTP داخل أي حلقة رئيسية لـ Lua وتشغيله جنبًا إلى جنب مع كود التطبيق دون التأثير سلبًا على عملية التطبيق الرئيسية. إذا تم دمج مكونات أخرى مدعومة بـ cqueue داخل حلقة cqueue، فإن التطبيق يعتمد بالكامل على الأحداث من خلال واجهات برمجة تطبيقات الاقتراع على مستوى النواة.

يمكن استخدام cqueues بالاقتران مع lua-http لدمج ميزات أخرى في تطبيق Lua الخاص بك وإنشاء تطبيقات قوية وعالية الأداء ومتصلة بالويب. ستستخدم بعض الأمثلة في هذا الدليل cqueues لعروض توضيحية بسيطة. لمزيد من الموارد حول cqueues، يرجى الاطلاع على:

•
موقع cqueues (http://25thandclement.com/~william/projects/cqueues.html) لمزيد من المعلومات حول مكتبة cqueues.
•
يمكن العثور على أمثلة cqueues مع كود مصدر cqueues المتاح عبر git أو الأرشيفات (http://www.25thandclement.com/~william/projects/cqueues.html#download) أو الوصول إليها عبر الإنترنت هنا (https://github.com/wahern/cqueues/tree/master/examples).
•
لمزيد من المعلومات حول دمج cqueues مع مكتبات حلقات الأحداث الأخرى، يرجى الاطلاع على التكامل مع حلقات الأحداث الأخرى (https://github.com/wahern/cqueues/wiki/Integrations-with-other-main-loops).
•
للمكتبات الأخرى التي تستخدم cqueues، مثل واجهات برمجة التطبيقات غير المتزامنة لـ Redis و PostgreSQL، يرجى الاطلاع على إدخال wiki الخاص بـ cqueues هنا (https://github.com/wahern/cqueues/wiki/Libraries-that-use-cqueues).

Places str back on the incoming data buffer, allowing it to be returned again on a subsequent command (“un-gets” the data). Returns true on success. On error, returns nil, an error message and an error number.

stream:write_chunk(chunk, end_stream, timeout)

Writes the string chunk to the stream. If end_stream is true, the body will be finalized and the stream will be closed. write_chunk yields indefinitely, or until timeout is exceeded. On error, returns nil, an error message and an error number.

Deals with obtaining a connection to an HTTP server.

Negotiates the HTTP settings with the remote server. If TLS has been specified, this function instantiates the encryption tunnel. Parameters are as follows:

defaults to true

•
true indicates to copy the .host field as long as it is not an IP
•
false disables SNI
•

connect(options, timeout)

This function returns a new connection to an HTTP server. Once a connection has been opened, a stream can be created to start a request/response exchange. Please see h1_stream.new_stream and h2_stream.new_stream for more information about creating streams.

•
options is a table containing the options to http.client.negotiate, plus the following:

may be either a hostname or an IP address

new_store()

ينشئ مخزن ملفات تعريف ارتباط جديدة.

ملفات تعريف الارتباط فريدة بالنسبة لمجموعة من المجال والمسار والاسم؛ على الرغم من أنه قد توجد ملفات تعريف ارتباط متعددة بنفس الاسم في طلب واحد بسبب تداخل المسارات أو المجالات.

store.psl

كائن lua-psl (https://github.com/daurnimator/lua-psl) للاستخدام عند التحقق من قائمة النطاقات العامة (Public Suffix List). قم بتعيين الحقل إلى false لتخطي التحقق من قائمة النطاقات.

الافتراضي هو أحدث قائمة نطاقات عامة (https://rockdaboot.github.io/libpsl/libpsl-Public-Suffix-List-functions.html#psl-latest) على النظام. إذا لم يتم تثبيت lua-psl، فستكون القيمة nil.

store.time()

دالة تستخدمها store للحصول على الوقت الحالي للانتهاء وما إلى ذلك.

الافتراضي هو دالة تعتمد على os.time (https://www.lua.org/manual/5.3/manual.html#pdf-os.time).

store.max_cookie_length

الحد الأقصى للطول (بالبايت) لملفات تعريف الارتباط في المخزن؛ يتم استخدام هذه القيمة أيضًا كحد أقصى افتراضي لطول ملف تعريف الارتباط لـ :lookup(). سيؤدي تقليل هذه القيمة فقط إلى منع إضافة ملفات تعريف ارتباط جديدة، ولن يؤدي إلى إزالة ملفات تعريف الارتباط القديمة.

الافتراضي هو اللانهاية (لا يوجد حد أقصى للحجم).

store.max_cookies

الحد الأقصى لعدد ملفات تعريف الارتباط المسموح بها في store. سيؤدي تقليل هذه القيمة فقط إلى منع إضافة ملفات تعريف ارتباط جديدة، ولن يؤدي إلى إزالة ملفات تعريف الارتباط القديمة.

الافتراضي هو اللانهاية (يُسمح بأي عدد من ملفات تعريف الارتباط).

store.max_cookies_per_domain

الحد الأقصى لعدد ملفات تعريف الارتباط المسموح بها في store لكل مجال. سيؤدي تقليل هذه القيمة فقط إلى منع إضافة ملفات تعريف ارتباط جديدة، ولن يؤدي إلى إزالة ملفات تعريف الارتباط القديمة.

الافتراضي هو اللانهاية (يُسمح بأي عدد من ملفات تعريف الارتباط).

store:store(req_domain, req_path, req_is_http, req_is_secure, req_site_for_cookies, name, value, params)

يحاول إضافة ملف تعريف ارتباط إلى store.

•
req_domain هو المجال الذي تم الحصول على ملف تعريف الارتباط منه
•
req_path هو المسار الذي تم الحصول على ملف تعريف الارتباط منه
•
req_is_http هو علامة منطقية تشير إلى ما إذا كان ملف تعريف الارتباط قد تم الحصول عليه من واجهة برمجة تطبيقات "غير HTTP"
•
req_is_secure هو علامة منطقية تشير إلى ما إذا كان ملف تعريف الارتباط قد تم الحصول عليه من بروتوكول "آمن"
•
req_site_for_cookies هو سلسلة نصية تحتوي على المضيف الذي يجب اعتباره "الموقع لملفات تعريف الارتباط" (انظر RFC 6265bis-02 القسم 5.2 (https://tools.ietf.org/html/draft-ietf-httpbis-rfc6265bis-02#section-5.2))، يمكن أن يكون nil إذا كان غير معروف.
•
name هو سلسلة نصية تحتوي على اسم ملف تعريف الارتباط
•
value هو سلسلة نصية تحتوي على قيمة ملف تعريف الارتباط
•
params هي جدول حيث تكون المفاتيح هي أسماء سمات ملف تعريف الارتباط والقيم هي قيم سمات ملف تعريف الارتباط

يُرجع قيمة منطقية تشير إلى ما إذا تم تخزين ملف تعريف الارتباط.

store:store_from_request(req_headers, resp_headers, req_host, req_site_for_cookies)

يحاول تخزين أي ملفات تعريف ارتباط موجودة في رؤوس الاستجابة.

•
req_headers هو كائن http.headers للطلب الصادر
•
resp_headers هو كائن http.headers المستلم في الاستجابة
•
req_host هو المضيف الذي تم توجيه استعلامك إليه (يُستخدم فقط إذا كانت req_headers تفتقد رأس Host)
•
req_site_for_cookies هو سلسلة نصية تحتوي على المضيف الذي يجب اعتباره "الموقع لملفات تعريف الارتباط" (انظر RFC 6265bis-02 القسم 5.2 (https://tools.ietf.org/html/draft-ietf-httpbis-rfc6265bis-02#section-5.2))، يمكن أن يكون nil إذا كان غير معروف.

store:get(domain, path, name)

يُرجع قيمة ملف تعريف الارتباط للملف التعريفي المخزن للمجال والمسار والاسم الممررين.

store:remove(domain, path, name)

يحذف ملف تعريف الارتباط المخزن للمجال والمسار والاسم الممررين.

إذا كانت name هي nil أو لم يتم تمريرها، فسيتم إزالة جميع ملفات تعريف الارتباط للمجال والمسار.

إذا كانت path هي nil أو لم يتم تمريرها (بالإضافة إلى name)، فسيتم إزالة جميع ملفات تعريف الارتباط للمجال.

store:lookup(domain, path, is_http, is_secure, is_safe_method, site_for_cookies, is_top_level, max_cookie_length)

يعثر على ملفات تعريف الارتباط المرئية والمناسبة للتمرير إلى كيان.

•
domain هو المجال الذي سيتم إرسال ملف تعريف الارتباط إليه
•
path هو المسار الذي سيتم إرسال ملف تعريف الارتباط إليه
•
is_http هو علامة منطقية تشير إلى ما إذا كانت الوجهة هي واجهة برمجة تطبيقات "غير HTTP"
•
is_secure هو علامة منطقية تشير إلى ما إذا كانت الوجهة ستتواصل عبر بروتوكول "آمن"
•
is_safe_method هو علامة منطقية تشير إلى ما إذا كان ملف تعريف الارتباط سيتم إرساله عبر طريقة HTTP آمنة (انظر أيضًا http.util.is_safe_method)
•
site_for_cookies هو سلسلة نصية تحتوي على المضيف الذي يجب اعتباره "الموقع لملفات تعريف الارتباط" (انظر RFC 6265bis-02 القسم 5.2 (https://tools.ietf.org/html/draft-ietf-httpbis-rfc6265bis-02#section-5.2))، يمكن أن يكون nil إذا كان غير معروف.
•

http.headers

\n

An ordered list of header fields. Each field has a name, a\n value and a never_index flag that indicates if the header\n field is potentially sensitive data.

\n

Each headers object has an index by field name to efficiently\n retrieve values by key. Keep in mind that there can be multiple values for a\n given field name. (e.g. an HTTP server may send two\n Set-Cookie headers).

.max_concurrent (number): الحد الأقصى لعدد الاتصالات المسموح بها في نفس الوقت. الافتراضي هو لا نهائي.

listen(options)

ينشئ مقبسًا جديدًا ويعيد خادم HTTP سيقوم بـ accept() منه. المعلمات هي نفسها كما في new(options) باستثناء أنه بدلاً من .socket، يمكنك توفير ما يلي:

•
.host (string): عنوان IP المحلي في صيغة الأرقام العشرية أو تدوين IPV6. هذه القيمة مطلوبة إذا لم يتم تحديد .path.
•
.port (number): منفذ IP للمقبس المحلي. حدد 0 لاختيار منفذ تلقائي. المنافذ من 1 إلى 1024 تتطلب أن يمتلك التطبيق امتيازات الجذر للتشغيل. القيمة القصوى هي 65535. إذا كان .tls == nil، فإن هذه القيمة مطلوبة. وإلا، فإن القيم الافتراضية هي:
•
80 إذا كان .tls == false
•
443 إذا كان .tls == true
•
.path (string): المسار إلى مقبس UNIX. هذه القيمة مطلوبة إذا لم يتم تحديد .host.
•
.family (string): عائلة البروتوكول. الافتراضي هو "AF_INET"
•
.v6only (boolean): حدد true لتقييد جميع الاتصالات على IPv6 فقط (لا توجد IPv4-mapped-IPv6). الافتراضي هو false.
•
.mode (string): fchmod أو chmod المقبس بعد إنشاء مقبس نطاق UNIX.
•
.mask (boolean): تعيين واستعادة umask عند ربط مقبس نطاق UNIX.
•
.unlink (boolean): true يعني إلغاء ربط مسار المقبس قبل الربط.
•
.reuseaddr (boolean): تشغيل العلامة SO_REUSEADDR.
•
.reuseport (boolean): تشغيل العلامة SO_REUSEPORT.

server:onerror(new_handler)

إذا تم استدعاؤها مع وسائط، فإن الدالة تستبدل دالة معالج الأخطاء الحالية بـ new_handler وتعيد مرجعًا للدالة القديمة. استدعاء الدالة بدون وسائط يعيد معالج الأخطاء الحالي. المعالج الافتراضي يثير خطأ. يمكن تعيين دالة onerror للخادم أثناء الإنشاء من خلال جدول options الذي تم تمريره إلى الدالة server.listen(options).

server:listen(timeout)

يقوم بتهيئة مقبس الخادم و، إذا لزم الأمر، يحل اسم DNS. مطلوب server:listen() إذا تم استدعاء localname قبل step أو loop. عند حدوث خطأ، يتم إرجاع nil، ورسالة خطأ، ورقم خطأ.

server:localname()

يعيد معلومات الاتصال للمقبس المحلي. يعيد عائلة العنوان، وعنوان IP، والمنفذ لمقبس خارجي. بالنسبة لمقابس نطاق Unix، تعيد الدالة AF_UNIX والمسار. إذا لم يكن كائن الاتصال متصلاً، فإنه يعيد AF_UNSPEC (0). عند حدوث خطأ، يتم إرجاع nil، ورسالة خطأ، ورقم خطأ.

server:pause()

يوقف حلقة الخادم عن معالجة العملاء الجدد حتى يتم استدعاء resume. سيتم تشغيل اتصالات العملاء الموجودة حتى يتم إغلاقها.

server:resume()

يستأنف خادم متوقف مؤقتًا ويعالج طلبات العملاء الجديدة.

server:close()

يغلق الخادم ويغلق المقبس. لا يمكن إعادة استخدام خادم مغلق.

server:pollfd()

يعيد واصف ملف (كرقم صحيح) أو nil.

يمكن تمرير واصف الملف إلى واجهة برمجة تطبيقات النظام مثل select أو kqueue للانتظار على أي شيء يرغب كائن الخادم هذا في القيام به. تُستخدم هذه الطريقة للتكامل مع الحلقات الرئيسية الأخرى، ويجب استخدامها بالاقتران مع :events() و :timeout().

server:events()

يعيد سلسلة نصية تشير إلى نوع الأحداث التي ينتظرها الكائن: ستحتوي السلسلة على "r" إذا كان يريد أن يتم خطوته عندما يتم الإشارة إلى POLLIN على واصف الملف الذي تم إرجاعه بواسطة pollfd()؛ "w" لـ POLLOUT أو "p" لـ POLLPRI.

تُستخدم هذه الطريقة للتكامل مع الحلقات الرئيسية الأخرى، ويجب استخدامها بالاقتران مع :pollfd() و :timeout().

server:timeout()

الحد الأقصى للوقت (بالثواني) للانتظار قبل استدعاء server:step().

تُستخدم هذه الطريقة للتكامل مع الحلقات الرئيسية الأخرى، ويجب استخدامها بالاقتران مع :pollfd() و :events().

server:empty()

يعيد true إذا تم إغلاق مقبس الخادم الرئيسي وجميع اتصالات العملاء، و false بخلاف ذلك.

server:step(timeout)

يخطو خطوة واحدة عبر الحلقة الرئيسية للخادم: سيتم accept() أي عملاء ينتظرون، وسيتم بدء معالجة أي تيارات معلقة، وسيتم تشغيل كل معالج onstream مرة واحدة على الأكثر. ستتوقف هذه الطريقة عن العمل لمدة تصل إلى timeout ثانية. عند حدوث خطأ، يتم إرجاع nil، ورسالة خطأ، ورقم خطأ.

يمكن استخدام هذا للتكامل مع الحلقات الرئيسية الخارجية.

server:loop(timeout)

تشغيل الخادم كحلقة حظر لمدة تصل إلى timeout ثانية. سيستمر الخادم في الاستماع وقبول طلبات العملاء حتى يتم استدعاء :pause() أو :close()، أو تحدث خبرة.

server:add_socket(socket)

يضيف مقبس اتصال جديد إلى الخادم للمعالجة. سيستخدم الخادم معالج طلب onstream الحالي وجميع options المحددة حاليًا من خلال المنشئ server.listen(options). يمكن استخدام add_socket لمعالجة مقابس الاتصال التي تم الحصول عليها من مصدر خارجي مثل:

•
خيط cqueues آخر بمقبس رئيسي آخر.
•
من inetd لبدء تشغيل الخدمات عند الطلب.
•
مقبس Unix مع SCM_RIGHTS.

server:add_stream(stream)

أضف دفقًا موجودًا إلى الخادم للمعالجة.
