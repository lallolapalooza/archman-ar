LWP__Protocol__ldap(3pm)

الحزمة: perl-ldap

التراخيص: GPL

LWP::Protocol::ldap(3) توثيق Perl من مساهمة المستخدم LWP::Protocol::ldap(3)

الاسم

LWP::Protocol::ldap - توفير دعم LDAP لـ LWP::UserAgent

ملخص

use LWP::UserAgent;
$ua = LWP::UserAgent->new();
$res = $ua->get('ldap://ldap.example.com/' .
                'o=University%20of%20Michigan,c=US??sub?(cn=Babs%20Jensen)',
                 Accept => 'text/json'):

الوصف

توفر وحدة LWP::Protocol::ldap الدعم لاستخدام عناوين URL ذات المخطط ldap وفقًا لـ RFC 4516 مع LWP. هذه الوحدة هي ملحق لمعالجة بروتوكول LWP، لذلك لا تستخدمها مباشرة.

بالإضافة إلى استخدامها مع عناوين URL LDAP، تعمل LWP::Protocol::ldap أيضًا كفئة أساسية لوحداتها الشقيقة LWP::Protocol::ldaps و LWP::Protocol::ldapi.

الميزات

طرق HTTP المدعومة

تنفذ LWP::Protocol::ldap طريقتي HTTP GET و HEAD. يتم تعيينهما لعملية بحث LDAP،

صيغة الاستجابة

اعتمادًا على رأس Accept HTTP الذي يوفره وكيل المستخدم، يمكن لـ LWP::Protocol::ldap الإجابة على الطلبات بأحد التنسيقات التالية:

DSML
عندما يحتوي رأس Accept HTTP على نوع MIME "text/dsml"، يتم إرسال الاستجابة كـ DSMLv1.
JSON
عندما يحتوي رأس Accept HTTP على نوع MIME "text/json"، يتم إرسال الاستجابة كـ JSON. لإنجاح ذلك، يجب تثبيت وحدة Perl JSON.
LDIF
عندما يحتوي رأس Accept HTTP على نوع MIME "text/ldif"، يتم إرسال الاستجابة بصيغة LDIFv1.
HTML
في حالة عدم إرسال رأس Accept HTTP أو عدم اكتشاف أي من أنواع MIME المذكورة أعلاه، وعدم توفير امتداد x-format أيضًا، يتم إرسال الاستجابة باستخدام علامات HTML في تنسيق جدول من عمودين (تم تصميمه بشكل تقريبي على LDIF).

كبديل لإرسال رأس Accept HTTP، تقبل LWP::Protocol::ldap أيضًا الامتداد "x-format"

مثال:

ldap://ldap.example.com/o=University%20of%20Michigan,c=US??sub?(cn=Babs%20Jensen)?x-format=dsml

دعم TLS

بالنسبة لعناوين URL ldap و ldapi، تطبق الوحدة الامتداد "x-tls" الذي يبدل اتصال LDAP إلى TLS باستخدام استدعاء لطريقة start_tls.

مثال:

ldap://ldap.example.com/o=University%20of%20Michigan,c=US??sub?(cn=Babs%20Jensen)?x-tls=1

ملاحظة: في المثال أعلاه، من الناحية المثالية، يجب أن يكون إعطاء "x-tls" كافيًا، ولكن للأسف محلل URI::ldap به خلل بسيط.

المصادقة

عادةً ما يتم الاتصال بشكل مجهول، ولكن إذا تم توفير رأس Authorization HTTP مع بيانات الاعتماد للمصادقة الأساسية لـ HTTP، فسيتم استخدام بيانات الاعتماد المقدمة في هذا الرأس لإجراء ربط بسيط بخادم LDAP.
