NAME

lvresize — resize a logical volume

SYNOPSIS

lvresize [-A|--autobackup Bool] [-b|--backup] [-d|--debug] [-h|-?|--help] [-k|--shrink] [-l|--extents [+/-]LogicalExtents[%[VG|LV|PVS|VGS|PVSZ|VGSZ]] [-M|--monitor Bool] [-m|--contiguous Bool] [-n|--nounits] [-P|--partial] [-r|--resizefs] [-t|--test] [-T|--thinpool ThinPoolName] [-v|--verbose] [-y|--yes] [LogicalVolumePath] [PhysicalVolumePath[:PhysicalExtentRange]...

DESCRIPTION

Resize an existing logical volume. The size can be specified using number of logical extents, or using a percentage of the total size of the volume group, free space in the volume group, free space on the physical volume(s), or free space on all physical volumes in the volume group.

If -l is used with a percentage value, it can be specified as a percentage of the total size of the volume group (e.g. 100%VG), the total free space in the volume group (e.g. 100%FREE), the free space on the physical volume(s) (e.g. 100%PVS), the total size of the physical volume(s) (e.g. 100%PVSZ), the total size of the volume group (e.g. 100%VGSZ), or the total free space in the volume group (e.g. 100%FREE).

To shrink a logical volume, use the -L option with a size followed by the --shrink option. Shrinking an LV also shrinks the filesystem if -r is used. If the filesystem is not resized using -r, the filesystem becomes invalid.

When shrinking, the Logical Volume becomes smaller. The new size cannot be smaller than the size of the data on the LV. If the filesystem is not resized, the LV size becomes smaller than the filesystem size, and the filesystem becomes invalid. The LV size must be large enough for the filesystem.

For thin logical volumes, use -T to specify the thin pool. If this option is not specified, the LV will be resized directly.

To extend a thin logical volume, use -T and specify the thin pool name. The thin pool itself needs to have enough free space.

When extending, the Physical Volume Path can be specified to limit the space added to the LV to the specified Physical Extent Range on the Physical Volume.

USAGE

lvresize [options] {LogicalVolumePath | LogicalVolumePath[@SnaphotName]} [PhysicalVolumePath[:PhysicalExtentRange]...]

OPTIONS

-A | --autobackup Bool
Enable or disable the automatic metadata backup for this command. Metadata backup is described in lvm(8). Default is “yes”.
-b | --backup
Create a backup of the LV data before resizing. This option is only supported for LVM snapshots.
-d | --debug
Enable additional debugging output. Use in conjunction with -v for even more detailed output.
-h | -? | --help
Display the help message. This does not run the command.
-k | --shrink
Allow shrinking of the LV. This option is required to shrink an LV.
-l | --extents [+/-]LogicalExtents[%[VG|LV|PVS|VGS|PVSZ|VGSZ]]
Controls the size of the logical volume in logical extents (LEs). The value can be a number of LEs, or a percentage. The percentage can be based on: %VG total volume group size %FREE total free space in volume group %LV logical volume size %PVS free space on the specified physical volume(s) %S PVS free space on all physical volumes in the volume group %PVSZ physical volume size %S PVSZ physical volume size on all physical volumes in the volume group %VGSZ volume group size %100FREE = use all free space in the VG %100PVS = use all free space on the specified PVs Use a preceding + or - to add or subtract LEs from the current size. See Size argument format below.
-M | --monitor Bool
If Bool is y (yes), enable the volume monitoring. If Bool is n (no), disable volume monitoring. Monitoring is disabled by default.
-m | --contiguous Bool
Controls whether the logical extents are allocated contiguously. If Bool is y (yes), the LV is allocated contiguously. If Bool is n (no), contiguous allocation is not required. The default is to try to allocate contiguously. This option has no effect when extending or shrinking an LV.
-n | --nounits
Do not display units in the output. Use with --verbose.
-P | --partial
Allow operations on partial LVs. See lvm(8) for more information on partial logical volumes.
-r | --resizefs
Resize the filesystem residing on the logical volume together with the logical volume itself. The filesystem must be mounted. This option is supported only for the ext2, ext3, ext4, XFS, and Btrfs filesystems. For other filesystems, use fsadm(8) or other filesystem-specific tools to resize the filesystem after resizing the LV.
-t | --test
Perform a simulation of the command without making any changes. This can be used to verify that a command is valid and will produce the expected results.
-T | --thinpool ThinPoolName
Resize the thin logical volume in the specified thin pool. The thin pool itself must have enough free space to accommodate the resize. If this option is used, the LV is resized by creating a new thin logical volume of the specified size in the specified thin pool and copying the data from the old LV to the new LV, then replacing the old LV with the new one.
-v | --verbose
Enable verbose output, if supported by the command. For LVM commands, this option is used to increase the level of detail in messages that are sent to stdout and stderr.
--version
Display version information.
-y | --yes
Do not prompt for confirmation interactively but always assume the answer yes. Use with extreme caution. (For automatic no, see -qq.)

VARIABLES

LV
Logical Volume name. See lvm(8) for valid names. An LV positional arg generally includes the VG name and LV name, e.g. VG/LV. LV1 indicates the LV must have a specific type, where the accepted LV types are listed. (raid represents raid<N> type).
PV
Physical Volume name, a device path under /dev. For commands managing physical extents, a PV positional arg generally accepts a suffix indicating a range (or multiple ranges) of physical extents (PEs). When the first PE is omitted, it defaults to the start of the device, and when the last PE is omitted it defaults to end.
Start and end range (inclusive): PV[:PE-PE] ...
Start and length range (counting from 0): PV[:PE+PE] ...
String
See the option description for information about the string content.
Size[UNIT]
Size is an input number that accepts an optional unit. Input units are always treated as base two values, regardless of capitalization, e.g. 'k' and 'K' both refer to 1024. The default input unit is specified by letter, followed by |UNIT. UNIT represents other possible input units: b|B is bytes, s|S is sectors of 512 bytes, k|K is KiB, m|M is MiB, g|G is GiB, t|T is TiB, p|P is PiB, e|E is EiB. (This should not be confused with the output control --units, where capital letters mean multiple of 1000.)

ENVIRONMENT VARIABLES

See lvm(8) for information about environment variables used by lvm. For example, LVM_VG_NAME can generally be substituted for a required VG parameter.

EXAMPLES

Extend an LV by 16MB using specific physical extents.
lvresize -L+16M vg1/lv1 /dev/sda:0-1 /dev/sdb:0-1

Resize an LV to use 50% of the size volume group.
lvresize -l50%VG vg1/lv1
