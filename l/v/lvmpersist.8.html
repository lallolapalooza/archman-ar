الاسم

lvmpersist - إدارة الحجوزات المستمرة على مجموعة من أجهزة الكتلة

الوصف

توفر الحجوزات المستمرة (PRs) آلية للتحكم في الوصول إلى أجهزة التخزين المشتركة، عادةً لحماية الأجهزة من التعديل بواسطة مضيفين لا ينبغي لهم الكتابة إلى الأجهزة المشتركة. هذا عادة ما يكون مصدر قلق في بيئات SAN أو المجمعة، حيث يكون لدى العديد من المضيفين وصول إلى نفس أجهزة التخزين.

إذا كانت مجموعة وحدات التخزين LVM (VG) تحتوي على أجهزة قادرة على PR، فيمكن استخدام أوامر LVM لإدارة PR على مستوى VG، وتطبيق PR على كل حجم مادي (PV) في VG. (يجب أن تدعم جميع وحدات PV في VG خاصية PR.)

lvmpersist هي أداة منخفضة المستوى تستخدم لتنفيذ عمليات PR على أجهزة الكتلة الفردية. توفر LVM أيضًا واجهة إدارة PR عالية المستوى من خلال واجهة أوامر LVM قياسية:
vgchange --setpersist، vgchange --persist

lvmpersist هو برنامج نصي لا ينفذ خيارات سطر الأوامر الشائعة لـ LVM أو قدراتها. يستخدم البرنامج النصي أوامر sg_persist و mpathpersist و nvme لتنفيذ عمليات PR على أجهزة الكتلة. تنفذ أوامر LVM عالية المستوى (مثل vgchange) البرنامج النصي lvmpersist.

أنواع الأجهزة

تدعم أجهزة SCSI أو SCSI-المشابهة (مثل iSCSI، SAS، Fibre Channel) و dm-multipath و NVME. تم تقديم PRs مع معيار SCSI Primary Commands Version 3 (SPC-3).

عند استخدام أجهزة المسارات المتعددة، يجب تكوين multipath.conf باستخدام "reservation_key file". (قم بتشغيل mpathconf --option reservation_key:file، وأعد تشغيل multipathd.)

أنواع الحجوزات المستمرة

تستخدم LVM نوع PR "Write Exclusive" (WE) للأجهزة في VG محلي، و "Write Exclusive - all registrants" (WEAR) للأجهزة في VG مشترك. هناك استثناء واحد وهو أجهزة dm-multipath، التي تستخدم WEAR في كل من VGs المحلية والمشتركة (هذا ضروري للحفاظ على جميع المسارات قابلة للاستخدام.)

يحتوي أمر lvmpersist على خيارين لتحديد نوع PR:

--access ex|sh

قم بتعيين الوصول إلى "ex" (حصري) إذا كان يجب الوصول إلى الأجهزة بواسطة مضيف واحد فقط (أي أن الأجهزة جزء من VG محلي.) قم بتعيين الوصول إلى "sh" (مشترك) إذا كان من المفترض الوصول إلى الأجهزة بشكل متزامن بواسطة مضيفين متعددين (أي أن الأجهزة جزء من VG مشترك.) سيختار lvmpersist نوع PR المناسب لكل جهاز (عادةً WE لـ "ex"، و WEAR لـ "sh".)
--prtype PRTYPE
عند تحديد قيمة PRTYPE، سيستخدم lvmpersist هذا النوع فقط لجميع الأجهزة.

أنواع PR والاختصارات المستخدمة في الواجهات/الرسائل:

WE Write Exclusive (كتابة حصرية)
EA Exclusive Access (وصول حصري)
WERO Write Exclusive - registrants only (كتابة حصرية - المسجلون فقط)
EARO Exclusive Access - registrants only (وصول حصري - المسجلون فقط)
WEAR Write Exclusive - all registrants (كتابة حصرية - جميع المسجلين)
EAAR Exclusive Access - all registrants (وصول حصري - جميع المسجلين)

(لا يتم دعم أنواع WERO و EARO بعد.)

مفاتيح الحجز المستمر

يمكن أن يصل طول مفاتيح PR إلى 8 بايت، ويتم تمثيلها بما يصل إلى 16 حرفًا سداسي عشري مع بادئة "0x". لا يُسمح بالأصفار البادئة، على سبيل المثال، استخدم 0x1234abcd، وليس 0x000000001234abcd. يتم قبول قيمة مفتاح عشري (بدون بادئة 0x) كمدخل، ولكنها ستظهر كست عشري في المخرجات.

يجب أن يستخدم كل مضيف يستخدم أجهزة مشتركة مفتاح PR فريدًا.

يجب تكوين مفاتيح PR على كل مضيف في /etc/lvm/lvmlocal.conf (راجع الإعدادات المحلية أدناه.)

الاستخدام

مجموعة الأوامر الأساسية والخيارات لإدارة PR:

أداة PR على مستوى الجهاز:
lvmpersist start|stop|remove|clear|read [OPTIONS] DEST

تكوين VG PR:
vgchange --setpersist y|n VG

عمليات VG PR:
vgchange --persist start|stop|remove|clear|read|check VG

أوامر lvmpersist

lvmpersist start --ourkey KEY DEST

"start" يسجل المفتاح المحلي ويحجز الأجهزة. إذا كان مفتاح مختلف من نفس المضيف لا يزال مسجلاً، فسيتم استبداله بالمفتاح المحدد. عندما لا يتم تحديد --access أو --prtype، يتم استخدام الوصول "ex".

lvmpersist stop --ourkey KEY DEST

"stop" يلغي تسجيل المفتاح المحلي، مما يزيل أيضًا حجزًا محليًا.

lvmpersist remove --ourkey KEY --removekey REMKEY DEST

"remove" يزيل مفتاح مضيف مسجل آخر. يفقد المضيف ذو المفتاح الذي تمت إزالته القدرة على الكتابة إلى الأجهزة. (ينطبق هذا الأمر على VGs المشتركة، حيث يتم تشغيل مضيفين متعددين في وقت واحد.)

lvmpersist start --ourkey KEY --removekey REMKEY DEST

"start" مع removekey يسجل المفتاح المحلي ويستحوذ على الحجز من مضيف آخر (باستخدام preempt-abort). يفقد المضيف الآخر القدرة على الكتابة إلى الأجهزة. (ينطبق هذا الأمر على VGs المحلية، والتي يمكن تشغيل مضيف واحد فيها في وقت واحد.)

lvmpersist clear --ourkey KEY DEST

"clear" يزيل جميع المفاتيح والحجوزات من الأجهزة.

lvmpersist devtest|read|read-keys|read-reservation DEST

تستخدم هذه الأوامر لاختبار ما إذا كانت الأجهزة تدعم PR، وعرض مفاتيح PR والحجوزات الحالية.

lvmpersist check-key --key KEY DEST

تحقق مما إذا كان مفتاح معين مسجلًا.

OPTIONS:

--ourkey KEY

مفتاح PR المحلي، على سبيل المثال 0x123abc
--removekey REMKEY

مفتاح مضيف آخر.
--key KEY

أي مفتاح للتحقق منه.
--access ex|sh

استخدم نوع PR للوصول الحصري أو المشترك إلى الجهاز.
--prtype PRTYPE

استخدم نوع الحجز المحدد (بديل لـ --access.)
--ptpl

تمكين الاستمرار عبر فقدان الطاقة أثناء البدء (التسجيل.)

DEST:

--device PATH ...

جهاز واحد أو أكثر للعمل عليه.
--vg VGNAME

VG واحد للعمل عليه (جميع وحدات PV في VG.)
--vg VGNAME --device PATH ...

جهاز واحد أو أكثر للعمل عليه، واسم VG لاستخدامه كمعرف لمجموعة الأجهزة.

يتطلب lvmpersist إما أسماء أجهزة محددة، كل منها محدد كـ --device /dev/name، أو اسم VG، محدد مع --vg VGNAME. عند تحديد VG، بدون أجهزة كتلة فردية، يقوم lvmpersist بتشغيل أوامر PR على كل PV في VG. عند تحديد الأجهزة، ويتم توفير VG أيضًا مع --vg، فإن اسم VG يستخدم ببساطة في رسائل السجل لتحديد مجموعة الأجهزة ككل. عند تشغيل lvmpersist بواسطة أوامر LVM عالية المستوى، يتم تحديد كل جهاز باستخدام --device، واسم VG يتم تحديده باستخدام --vg.

أوامر بيانات VG الوصفية

يستخدم vgchange --setpersist لتكوين أتمتة وإنفاذ PR فيما يتعلق بالاستخدام الأوسع لـ VG

NAME

lvmpersist - Manage persistent reservations for LVM devices

DESCRIPTION

The lvmpersist utility allows you to manage persistent reservations on LVM devices. Persistent reservations are a feature that allows multiple hosts to share access to block devices while ensuring data integrity. This utility is part of the LVM (Logical Volume Manager) tools and is used to start, stop, and check the status of persistent reservations on LVM volume groups.

When a volume group is configured with persistent reservation support, it uses an underlying mechanism (like SCSI Persistent Reservations or other storage array specific features) to control access. Only the host that holds the reservation can modify the volume group's metadata or create/delete logical volumes.

The commands demonstrated in the examples typically involve:

  • Starting and stopping the persistent reservation service for a volume group.

  • Activating and deactivating logical volumes within a volume group.

  • Checking the status of persistent reservations, including which host holds the reservation.

  • Forcibly taking over the reservation from another host.

The use of persistent reservations is crucial in shared storage environments (like clusters or SANs) to prevent data corruption when multiple servers access the same LVM volume group.

USAGE

The following commands are demonstrated to illustrate the usage of lvmpersist and related LVM commands in managing persistent reservations:

vgchange --persist stop <vgname>
Stops the persistent reservation service for the specified volume group. This releases any reservations held by the current host.
vgchange -ay <vgname>
Activates all logical volumes in the specified volume group. This command may fail if persistent reservation is not started or if the host does not hold the reservation.
lvcreate -l <extents> -n <lname> <vgname>
Creates a new logical volume with the specified size and name within the volume group. This also requires the host to hold the persistent reservation.
vgchange --persist start <vgname>
Starts the persistent reservation service for the specified volume group. The host attempts to acquire the reservation.
lvmconfig local/host_id
Retrieves the unique host ID configured for the local system.
vgchange --persist check <vgname>
Checks the status of the persistent reservation for the volume group, indicating which host holds the reservation (if any) and the type of reservation.
vgchange --persist start --removekey <key> <vgname>
Starts the persistent reservation service and removes a specific reservation key. This is often used to forcibly take over the reservation from another host.
vgcreate --shared <vgname> <device1> <device2> ...
Creates a new shared volume group. The --shared option implies the use of a locking mechanism (like sanlock) and enables persistent reservation features.
vgchange --setpersist y <vgname>
Enables persistent reservation support for an existing volume group.
vgchange --lockstart <vgname>
Starts the locking mechanism for a shared volume group, which is necessary for persistent reservations to function correctly.
lvchange -ay <vgname>/<lname>
Activates a specific logical volume. If the LV is locked by another host, this operation will fail.
vgchange -an <vgname>
Deactivates all logical volumes in the specified volume group.
vgchange --lockstop <vgname>
Stops the locking mechanism for a shared volume group.

EXAMPLES

The following examples illustrate scenarios of managing persistent reservations:

Basic persistent reservation management

host1:
$ lvmconfig local/host_id
host_id=1
$ vgchange --persist stop vg
  lvmpersist: stopped vg with key 0x1000000000000001.
$ vgchange -ay vg
  persistent reservation is not started.
  Cannot access VG vg without persistent reservation.
$ lvcreate -l1 -n lvol1 vg
  persistent reservation is not started.
  Cannot access VG vg without persistent reservation.
$ vgchange --persist start vg
  lvmpersist: started vg with key 0x1000000000000001.
$ vgchange -ay vg
  1 logical volume(s) in volume group "vg" now active
$ lvcreate -l1 -n lvol1 vg
  Logical volume "lvol1" created.
host2 foricibly takes VG from host1:
$ lvmconfig local/host_id
host_id=2
$ vgchange -ay vg
  persistent reservation is not started.
  Cannot access VG vg without persistent reservation.
$ vgchange --persist start vg
  persistent reservation is not started by another host
$ vgchange --persist check vg
  key for local host is not registered (host_id 2)
  key for other host is registered: 0x1000000000000001
  reservation WE for other host
  PR is not started.
$ dd if=/dev/zero of=/dev/sda
dd: error writing '/dev/sda': Input/output error
$ vgchange --persist start --removekey 0x1000000000000001 vg
  lvmpersist: started vg with key 0x1000000000000002.
$ vgchange -ay vg
  2 logical volume(s) in volume group "vg" now active
$ vgchange --persist check vg
  key for local host is registered: 0x1000000000000002
  reservation WE for local host
  PR is started.
host1 can no longer write:
$ dd if=/dev/zero of=/dev/vg/lvol0
dd: error writing '/dev/vg/lvol0': Input/output error
$ lvcreate -l1 -n lvol1 vg
  persistent reservation is not started.
  Cannot access VG vg without persistent reservation.
$ vgchange --persist check vg
  key for local host is not registered (host_id 1)
  key for other host is registered: 0x1000000000000002
  reservation WE for other host
  PR is not started.

Shared VG usage

host1:
$ lvmconfig local/host_id
host_id=1
$ vgcreate --shared vg /dev/sda /dev/sdb
  Enabling sanlock global lock
  Physical volume "/dev/sda" successfully created.
  Physical volume "/dev/sdb" successfully created.
  Logical volume "lvmlock" created.
  Volume group "vg" successfully created
  VG vg starting sanlock lockspace
  Starting locking.  Waiting until locks are ready...
$ vgchange --setpersist y vg
  Volume group "vg" successfully changed.
$ vgchange --persist start vg
  lvmpersist: started vg with key 0x1000000000010001.
$ vgchange --persist check vg
  key for local host is registered: 0x1000000000010001
  keys for all registered hosts: 0x1000000000010001
  reservation WEAR for registered hosts
  PR is started.
$ lvcreate -l1 -n lvol0 vg
  Logical volume "lvol0" created.
host2:
$ lvmconfig local/host_id
host_id=2
$ vgchange --persist start vg
  lvmpersist: started vg with key 0x1000000000010002.
$ vgchange --lockstart vg
  VG vg starting sanlock lockspace
  Starting locking.  Waiting for sanlock...
$ vgchange --persist check vg
  key for local host is registered: 0x1000000000010002
  keys for all registered hosts: 0x1000000000010001 0x1000000000010002
  reservation WEAR for registered hosts
  PR is started.
$ lvcreate -l1 -n lvol1 vg
  Logical volume "lvol1" created.
$ lvchange -ay vg/lvol0
  LV locked by other host: vg/lvol0 (host_id 1)
  Failed to lock logical volume vg/lvol0.
$ vgchange -an vg
  0 logical volume(s) in volume group "vg" now active
$ vgchange --lockstop vg
$ vgchange --persist stop vg
  lvmpersist: stopped ee with key 0x1000000000010002.
$ vgchange --persist check vg
  key for local host is not registered (host_id 2)
  keys for all registered hosts: 0x1000000000010001
  reservation WEAR for registered hosts
  PR is not started.
$ dd if=/dev/zero of=/dev/sda
dd: error writing '/dev/sda': Input/output error
