NAME

lvmreport — LVM reporting and related features

DESCRIPTION

LVM uses a single reporting infrastructure that sets standard on LVM command's output and it provides wide range of configuration settings and command line options to customize report and filter the report's output.

USAGE

Categorization based on reporting facility

Based on functionality, commands which make use of the reporting infrastructure are divided into two groups:

Report-oriented commands
These commands inform about current LVM state and their primary role is to display this information in a concise way. To make a distinction, we will name this report as main report. The set of report-only commands include: pvs, vgs, lvs, pvdisplay, vgdisplay, lvdisplay, lvm devtypes, lvm fullreport. For further information about main report, see Main report specifics.
Processing-oriented commands
These commands are responsible for changing LVM state and they do not contain any main report as identified for report-oriented commands, they only perform some kind of processing. The set of processing-oriented commands includes: pvcreate, vgcreate, lvcreate, pvchange, vgchange, lvchange, pvremove, vgremove, lvremove, pvresize, vgextend, vgreduce, lvextend, lvreduce, lvresize, lvrename, pvscan, vgscan, lvscan, pvmove, vgcfgbackup, vgck, vgconvert, vgexport, vgimport, vgmknodes.

If enabled, so-called log report is either displayed solely (for processing-oriented commands) or in addition to main report (for report-oriented commands). The log report contains a log of operations, messages and per-object status with complete object identification collected during LVM command execution. See Log report specifics for more information about this report type.

Terms

When describing reporting functionality and features in this text, we will use terms row and column. By row we mean series of values reported for a single entity (for example single PV, VG or LV). Each value from the row then belongs to a column of certain type. The columns have column headings which are short descriptions for the columns. The columns are referenced by column names. Please note that this text is also using term field interchangeably with the term column. Most of the time the term columns is abbreviated as col in configuration.

Common report configuration settings and command line options

There are common configuration settings and command line options which apply to both main report and log report. The following lists contain all of them, separated into groups based on their use.

This document does not describe these settings in more detail – if you need detailed information, including values which are accepted for the settings, please run lvmconfig --type default --withcomments <setting>. There are more configuration settings in addition to the common set listed above, but they are specific to either main report or log report, see main report specifics and log report specifics for these settings. Besides configuring reports globally by using configuration settings, there are also command line options you can use to extend, override or further specify the report configuration.

Common command line options

Definition of the set of fields to use
-o|--options FieldSet
Field set to use. See main report specifics and log report specifics for information about field sets configured with global configuration settings that this option overrides.
-o|--options +FieldSet
Fields to include in current field set. See main report specifics and log report specifics for information about field sets configured with global configuration settings that this option extends.
-o|--options -FieldSet
Fields to exclude from current field set. See main report specifics and log report specifics for information about field sets configured with global configuration settings that this option reduces.
-o|--options #FieldSet
Compaction of unused fields. Overrides report/compact_output_cols configuration setting.
Sorting
-O|--sort +FieldSet
Fields to sort by in ascending order. See main report specifics and log report specifics for information about field sets configured with global configuration settings that this option overrides.
-O|--sort -FieldSet
Fields to sort by in descending order. See main report specifics and log report specifics for information about field sets configured with global configuration settings that this option overrides.
Selection
-S|--select Selection
Define selection criteria for report output. For log report, this also overrides log/command_log_selection configuration setting, see also log report specifics.

خصوصيات التقرير الرئيسي

يشمل التقرير الرئيسي حاليًا هذه الأنواع الفرعية المميزة، والتي يتم الرجوع إليها بأسمائها - اسم_التقرير كما هو مدرج أدناه. الأمر بين قوسين هو أمر تمثيلي يستخدم نوع التقرير الرئيسي الفرعي افتراضيًا. كل نوع فرعي له إعداد تكوين خاص به لتعريف مجموعة الحقول العامة وكذلك تعريف حقل الفرز (مدرج أسفل كل اسم_التقرير فردي):

pv
يمثل تقريرًا عن وحدات التخزين المادية (pvs)
– report/pvs_cols
– report/pvs_sort
pvseg
يمثل تقريرًا عن مقاطع وحدات التخزين المادية (pvs --segments)
– report/pvseg_cols
– report/pvseg_sort
vg
يمثل تقريرًا عن مجموعات وحدات التخزين (vgs)
– report/vgs_cols
– report/vgs_sort
lv
يمثل تقريرًا عن وحدات التخزين المنطقية (lvs)
– report/lvs_cols
– report/lvs_sort
seg
يمثل تقريرًا عن مقاطع وحدات التخزين المنطقية (lvs --segments)
– report/segs_cols
– report/segs_sort
full
يمثل تقريرًا يجمع كل ما سبق كوحدة واحدة (lvm fullreport)
– report/pvs_cols_full
– report/pvs_sort_full
– report/pvsegs_cols_full
– report/pvseg_sort_full
– report/vgs_cols_full
– report/vgs_sort_full
– report/lvs_cols_full
– report/lvs_sort_full
– report/segs_cols_full
– report/segs_sort_full
devtype
يمثل تقريرًا عن أنواع الأجهزة (lvm devtypes)
– report/devtypes_cols
– report/devtypes_sort

استخدم pvs, vgs, lvs -o help أو lvm devtypes -o help للحصول على قائمة كاملة بالحقول التي يمكنك استخدامها للتقرير الرئيسي. يتم فصل قائمة الحقول في خرج المساعدة إلى مجموعات بناءً على نوع التقرير الذي تنتمي إليه. لاحظ أن LVM يمكن أن يغير نوع التقرير النهائي المستخدم إذا تم تجميع حقول من مجموعات مختلفة معًا. بعض هذه التركيبات غير مسموح بها وفي هذه الحالة سيصدر LVM خطأ.

بالنسبة لجميع الأنواع الفرعية للتقارير الرئيسية باستثناء full، لا يلزم استخدام --configreport اسم_التقرير لتحديد التقرير الذي تنطبق عليه أي خيارات -o، -O أو -S لاحقة حيث أنها تنطبق دائمًا على نوع التقرير الرئيسي الوحيد. حاليًا، lvm fullreport هو الأمر الوحيد الذي يشمل أكثر من نوع تقرير رئيسي فرعي واحد. لذلك، فإن --configreport مناسب بشكل خاص للتقرير الكامل إذا كنت بحاجة إلى تكوين كل تقرير فرعي منه بطريقة مختلفة.

خصوصيات تقرير السجل

يمكنك تمكين تقرير السجل باستخدام إعداد التكوين log/report_command_log - هذه الوظيفة معطلة افتراضيًا. يحتوي تقرير السجل على سجل تم تجميعه أثناء تنفيذ أمر LVM ثم يتم عرض السجل تمامًا مثل أي تقرير آخر معروف من التقرير الرئيسي. يوجد نوع فرعي واحد فقط لتقرير السجل كما هو موضح أدناه جنبًا إلى جنب مع إعدادات التكوين ذات الصلة للحقول والفرز والاختيار:

log
يمثل تقرير السجل
– log/command_log_cols
– log/command_log_sort
– log/command_log_selection

تحتاج دائمًا إلى استخدام --configreport log مع -o|--options، -O|--sort أو -S|--selection لتجاوز إعدادات التكوين مباشرة على سطر الأوامر لـ تقرير السجل. عند مقارنتها بالتقرير الرئيسي، بالإضافة إلى إعدادات التكوين المعتادة لحقول التقرير والفرز، فإن تقرير السجل لديه أيضًا خيار تكوين للاختيار - report/command_log_selection. يتم توفير إعداد التكوين هذا للراحة، لذلك ليس من الضروري استخدام -S|--select في سطر الأوامر في كل مرة يتم فيها تنفيذ أمر LVM ونحتاج إلى تطبيق نفس معايير الاختيار لـ تقرير السجل. معايير الاختيار الافتراضية المستخدمة لـ تقرير السجل هي log/command_log_selection="!(log_type=status && message=success)". هذا يعني، افتراضيًا، أن تقرير السجل لا يعرض رسائل الحالة حول العملية الناجحة ويعرض فقط الصفوف التي تحتوي على أخطاء، تحذيرات، رسائل من نوع طباعة، ورسائل حول حالات الفشل. لرؤية سجل الأوامر غير المصفى، استخدم القيمة "all" للاختيار. لمزيد من المعلومات، انظر محتوى تقرير السجل أدناه.

تغطية تقرير السجل
حاليًا، عند تشغيل أوامر LVM مباشرة (ليس في shell LVM)، يغطي تقرير السجل مرحلة معالجة الأمر، وهي اللحظة التي يتم فيها تكرار كيانات LVM ومعالجتها واحدة تلو الأخرى. لا يغطي أي تهيئة للأوامر ولا مرحلة الإنهاء النهائية للأوامر. إذا تم إصدار أي رسالة خارج نطاق تغطية تقرير السجل، فإن هذه الرسالة تذهب مباشرة إلى الإخراج، متجاوزة تقرير السجل. افتراضيًا، يكون هذا هو إخراج الخطأ القياسي لرسائل الخطأ والتحذير، والإخراج القياسي لرسائل الطباعة الشائعة.

عند تشغيل أوامر LVM في shell LVM، يغطي تقرير السجل تنفيذ أمر LVM بالكامل، بما في ذلك معالجة الأمر بالإضافة إلى مرحلتي التهيئة والإنهاء النهائي. لذا من هذا المنظور، فإن تغطية تقرير السجل كاملة للأوامر LVM المنفذة. لاحظ أنه لا تزال هناك لحظات قليلة عندما يحتاج shell LVM إلى تهيئة نفسه قبل أن يدخل حتى الحلقة الرئيسية التي ينفذ فيها أوامر LVM. بالإضافة إلى ذلك، هناك لحظة عندما يحتاج shell LVM إلى إعداد تقرير السجل بشكل صحيح للأمر التالي الذي يتم تنفيذه في shell، ثم بعد تشغيل الأمر، يحتاج shell إلى عرض تقرير السجل لهذا الأمر الذي تم تنفيذه مؤخرًا. إذا حدث فشل أو أي رسالة أخرى أثناء هذه الفترة، فسيتجاوز LVM تقرير السجل ويعرض الرسائل على الإخراج مباشرة.

لهذه الأسباب وللإكمال، لا يمكن الاعتماد بالكامل على تقرير السجل كمؤشر وحيد لحالة أمر LVM والمكان الوحيد الذي يتم فيه جمع جميع الرسائل الصادرة أثناء تنفيذ أمر LVM. تحتاج دائمًا إلى التحقق مما إذا كان الأمر لم يفشل خارج نطاق تقرير السجل من خلال التحقق من الإخراج غير التقريري أيضًا.

للمساعدة في ذلك، يمكن لـ LVM فصل الإخراج الذي يمكنك بعد ذلك إعادة توجيهه إلى واصف ملف مخصص تقوم بإعداده قبل تشغيل أمر LVM أو shell LVM، ثم تجعل LVM يستخدم واصفات الملفات هذه لأنواع مختلفة من الإخراج عن طريق تحديد متغيرات البيئة بأرقام واصفات الملفات. راجع أيضًا وصف متغير البيئة LVM_OUT_FD وLVM_ERR_FD وLVM_REPORT_FD في صفحة الدليل lvm(8).

لاحظ أيضًا أنه افتراضيًا، تستخدم التقارير نفس واصف الملف مثل رسائل الطباعة الشائعة، وهي الإخراج القياسي. إذا كنت تخطط لاستخدام تقرير السجل في برامجك النصية أو أي أدوات خارجية، فيجب عليك استخدام LVM_OUT_FD وLVM_ERR_FD وLVM_REPORT_FD لفصل جميع أنواع الإخراج إلى واصفات ملفات مختلفة. على سبيل المثال، مع bash، سيكون ذلك:

LVM_OUT_FD=3 LVM_ERR_FD=4 LVM_REPORT_FD=5 <أمر_lvm> 3>ملف_الخارج 4>ملف_الخطأ 5>ملف_التقرير

حيث يكون <أمر_lvm> إما أمر LVM مباشر أو shell LVM. يمكنك بعد ذلك جمع جميع الأنواع الثلاثة من الإخراج في ملفات معينة.

الاختيار

يُستخدم الاختيار للتقرير لعرض الصفوف التي تطابق معايير الاختيار فقط. يتم عرض جميع الصفوف مع حقل selected الإضافي (-o selected) الذي يعرض 1 إذا كان الصف يطابق الاختيار و 0 بخلاف ذلك. معايير الاختيار هي مجموعة من البيانات مدمجة بواسطة عوامل تشغيل منطقية وتجميعية. تتكون البيانات من اسم حقل يتم تعريف مجموعة من القيم الصحيحة له باستخدام عوامل مقارنة. للحصول على القائمة الكاملة بأسماء الحقول التي يمكنك استخدامها في الاختيار، انظر إلى مخرجات lvm -S help. يحتوي الإخراج المساعد أيضًا على نوع القيم التي يعرضها كل حقل مغلفًا بأقواس.

نهاية مجموعة فرعية من القائمة

أنواع الحقول ومعاملات الاختيار

يقيد نوع الحقل مجموعة العوامل والقيم التي يمكنك استخدامها مع الحقل عند تحديد معايير الاختيار. يمكنك رؤية نوع الحقل لكل حقل إذا قمت بتشغيل lvm -S help حيث يمكنك العثور على اسم النوع مغلفًا بأقواس مربعة. حاليًا، يتعرف LVM على أنواع الحقول التالية في التقارير:

string
لمجموعة من الأحرف (لكل نوع حقل نصي، يمكنك استخدام إما نص أو تعبير عادي – تعبير عادي للقيمة المستخدمة في معايير الاختيار)
string list
لمجموعة من النصوص
number
لقيمة عدد صحيح
size
لرقم صحيح أو عشري مع لاحقة وحدة الحجم (انظر أيضًا صفحة الدليل lvcreate(8) ووصف الخيار "-L|--size" للحصول على قائمة باللواحق المعترف بها)
percent
لرقم عشري مع أو بدون لاحقة "%" (على سبيل المثال، 50 أو 50%)
time
لقيم الوقت

عند استخدام string list في معايير الاختيار، هناك عدة طرق يمكن لـ LVM من خلالها مطابقة حقول قائمة النصوص من التقرير، اعتمادًا على عامل تشغيل تجميع القائمة المستخدم و فاصل العناصر المستخدم ضمن هذه المجموعة من العناصر. لاحظ أيضًا أن ترتيب العناصر لا يهم هنا.

•
مطابقة جميع العناصر في حقل قائمة النصوص:
–
وجميع العناصر من الاختيار، استخدم [ ] مع "," (أو "&&")، على سبيل المثال، ["a","b","c"]،
–
وأي عنصر من الاختيار، استخدم [ ] مع "#" (أو "||")، على سبيل المثال، ["a"#"b"#"c"].
•
مطابقة مجموعة فرعية من العناصر في حقل قائمة النصوص:
–
وجميع العناصر من الاختيار، استخدم { } مع "," (أو "&&")، على سبيل المثال، {"a","b","c"}،
–
و أي عنصر من الاختيار، استخدم { } مع "#" (أو "||")، على سبيل المثال، {"a"#"b"#"c"}.

عند استخدام time في معايير الاختيار الخاصة بك، يمكن لـ LVM التعرف على تنسيقات وقت مختلفة باستخدام تعبيرات قياسية أو مطلقة أو حرة. للحصول على أمثلة توضح تعبيرات الوقت في معايير الاختيار، انظر قسم أمثلة.

•

YYYY-MM-DD
YYYY-MM، تلقائي DD=1
YYYY، تلقائي MM=01 و DD=01

Informal grammar specification

\n
\n
–
\n
STATEMENT = column cmp_op VALUE |\n STATEMENT log_op STATEMENT | (STATEMENT) |\n !(STATEMENT)
\n
–
\n
VALUE = [VALUE log_op VALUE]\n
\n For list-based types: string list. Matches all items in list. The log_op\n must always be of one type within the whole list value.
\n
–
\n
VALUE = {VALUE log_op VALUE}\n
\n For list-based types: string list. Matches a subset of items in list. The\n log_op must always be of one type within the whole list value.
\n
–
\n
VALUE = value\n
\n For scalar types: number, size, percent, string (or string regex). Also for\n list-based types: string list (in this case the value is a short form of\n {value}).

Basic usage

\n

We start our examples with default configuration –\n lvmconfig(8) is helpful command to display configuration settings\n which are currently used, including all configuration related to reporting. \n We will use it throughout examples below to display current\n configuration.

\n
# lvmconfig --type full global/units global/suffix \\\n   report/output_format  report/compact_output \\\n   report/compact_output_cols report/aligned \\\n   report/headings report/separator \\\n   report/list_item_separator report/prefixes \\\n   report/quoted report/columns_as_rows \\\n   report/binary_values_as_numeric report/time_format \\\n   report/mark_hidden_devices report/two_word_unknown_device \\\n   report/buffered\nunits="h"\nsuffix=1\noutput_format="basic"\ncompact_output=0\ncompact_output_cols=""\naligned=1\nheadings=1\nseparator=" "\nlist_item_separator=","\nprefixes=0\nquoted=1\ncolumns_as_rows=0\nbinary_values_as_numeric=0\ntime_format="%Y-%m-%d %T %z"\nmark_hidden_devices=1\ntwo_word_unknown_device=0\nbuffered=1
\n

Also, we start with simple LVM layout with two PVs (/dev/sda, \n /dev/sdb), VG (vg) and two LVs (lvol0 and lvol1) in the VG. We display all\n possible reports as single commands here, see also pvs(8),\n vgs(8), lvs(8) man pages for more information. The field set\n for each report type is configured with configuration settings as we already\n mentioned in main report specifics section in this man page.

\n
# lvmconfig --type full report/pvs_cols report/pvs_sort \\\n   report/pvsegs_cols report/pvsegs_sort report/vgs_cols \\\n   report/vgs_sort report/lvs_cols report/lvs_sort \\\n   report/segs_cols report/segs_sort\npvs_cols="pv_name,vg_name,pv_fmt,pv_attr,pv_size,pv_free"\npvs_sort="pv_name"\npvsegs_cols="pv_name,vg_name,pv_fmt,pv_attr,pv_size,pv_free,\n             pvseg_start,pvseg_size"\npvsegs_sort="pv_name,pvseg_start"\nvgs_cols="vg_name,pv_count,lv_count,snap_count,vg_attr,vg_size,vg_free"\nvgs_sort="vg_name"\nlvs_cols="lv_name,vg_name,lv_attr,lv_size,pool_lv,origin,move_pv,\n          mirror_log,copy_percent,convert_lv"\nlvs_sort="vg_name,lv_name"\nsegs_cols="lv_name,vg_name,lv_attr,stripes,segtype,seg_size"\nsegs_sort="vg_name,lv_name,seg_start"

We will use report/lvs_cols and report/lvs_sort\n configuration settings to define our own list of fields to use and to sort\n by that is different from defaults. You can do this for other reports in\n same manner with report/{pvs,pvseg,vgs,seg}_{cols,sort} configuration\n settings. Also note that in the example below, we don't display the\n "lv_time" field even though we're using it for sorting –\n this is allowed.

\n
# lvmconfig --type full report/lvs_cols report/lvs_sort\nlvs_cols="lv_name,lv_size,origin,pool_lv,copy_percent"\nlvs_sort="-lv_time"

# lvs\n  LV    LSize Origin Pool Cpy%Sync\n  lvol1 4.00m             100.00\n  lvol0 4.00m

You can use -o|--options command line option to\n override current configuration directly on command line.

\n
# lvs -o lv_name,lv_size\n  LV    LSize\n  lvol1 4.00m\n  lvol0 4.00m
\n
# lvs -o+lv_layout\n  LV    LSize Origin Pool Cpy%Sync Layout\n  lvol1 4.00m             100.00   raid,raid1\n  lvol0 4.00m                      linear
\n
# lvs -o-origin\n  LV    LSize Pool Cpy%Sync\n  lvol1 4.00m      100.00\n  lvol0 4.00m

You can obtain the same information with single command where all\n the information about PVs, PV segments, LVs and LV segments are obtained per\n VG under a single VG lock for consistency, see also lvm fullreport(8)\n man page for more information. This way, it's possible to configure different sets of fields to\n display and to sort by for individual reports as well as the full\n report.

Automatic output compaction

\n

If you look at the lvs output above, you can see that the report\n also contains fields for which there is no information to display (e.g. the\n columns under "Origin" and "Pool" heading – the\n "origin" and "pool_lv" fields). LVM can automatically\n compact report output so such fields are not included in final output. To\n enable this feature and to compact all fields, use\n report/compact_output=1 in your configuration.

\n
# lvmconfig --type full report/compact_output\ncompact_output=1
\n
# lvs\n  LV    LSize Cpy%Sync\n  lvol1 4.00m 100.00\n  lvol0 4.00m
\n
# lvs vg/lvol0\n  LV    LSize\n  lvol0 4.00m
\n

Alternatively, you can define which fields should be compacted by\n configuring report/compact_output_cols configuration setting (or\n -o|--options # command line option).

\n
# lvmconfig --type full report/compact_output report/compact_output_cols\ncompact_output=0\ncompact_output_cols="origin"
\n
# lvs\n  LV    LSize Pool Cpy%Sync\n  lvol1 4.00m      100.00\n  lvol0 4.00m
\n
# lvs vg/lvol0\n  LV    LSize Pool\n  lvol0 4.00m
\n
# lvs -o#pool_lv\n  LV    LSize Origin Cpy%Sync\n  lvol1 4.00m        100.00\n  lvol0 4.00m
\n

We will use report/compact_output=1 for subsequent\n examples.

سنستخدم إعدادات التكوين report/lvs_cols و report/lvs_sort\n لتحديد قائمتنا الخاصة بالحقول للاستخدام والفرز بشكل مختلف عن الافتراضيات. يمكنك القيام بذلك للتقارير الأخرى بنفس الطريقة باستخدام\n إعدادات التكوين report/{pvs,pvseg,vgs,seg}_{cols,sort}. لاحظ أيضاً أنه في المثال أدناه، لا نعرض\n حقل "lv_time" على الرغم من أننا نستخدمه للفرز –\n هذا مسموح به.

\n
# lvmconfig --type full report/lvs_cols report/lvs_sort\nlvs_cols="lv_name,lv_size,origin,pool_lv,copy_percent"\nlvs_sort="-lv_time"
\n
# lvs\n  LV    LSize Origin Pool Cpy%Sync\n  lvol1 4.00m             100.00\n  lvol0 4.00m
\n

يمكنك استخدام خيار سطر الأوامر -o|--options\n لتجاوز التكوين الحالي مباشرة على سطر الأوامر.

\n
# lvs -o lv_name,lv_size\n  LV    LSize\n  lvol1 4.00m\n  lvol0 4.00m
\n
# lvs -o+lv_layout\n  LV    LSize Origin Pool Cpy%Sync Layout\n  lvol1 4.00m             100.00   raid,raid1\n  lvol0 4.00m                      linear

# lvs -o-origin\n  LV    LSize Pool Cpy%Sync\n  lvol1 4.00m      100.00\n  lvol0 4.00m

# lvs -o lv_name,lv_size,origin -o+lv_layout -o-origin -O lv_name\n  LV    LSize Layout\n  lvol0 4.00m linear\n  lvol1 4.00m raid,raid1

يمكنك الحصول على نفس المعلومات بأمر واحد حيث يتم الحصول على جميع\n المعلومات حول وحدات التخزين المادية (PVs)، وشرائح وحدات التخزين المادية (PV segments)،\n ووحدات التخزين المنطقية (LVs)، وشرائح وحدات التخزين المنطقية (LV segments) لكل مجموعة تخزين (VG) تحت قفل واحد للمجموعة (VG lock)\n للاتساق، راجع أيضاً الصفحة اليدوية lvm fullreport(8) لمزيد من المعلومات.\n التقرير الكامل (fullreport) له إعدادات تكوين خاصة به لتحديد مجموعات الحقول للاستخدام،\n على غرار التقارير الفردية كما هو موضح أعلاه، ولكن إعدادات التكوين تحتوي على لاحقة\n "_full" الآن. بهذه الطريقة، من الممكن تكوين مجموعات مختلفة من الحقول للعرض\n والفرز للتقارير الفردية وكذلك للتقرير الكامل.

\n
# lvmconfig --type full report/pvs_cols_full \\\n   report/pvs_sort_full report/pvsegs_cols_full \\\n   report/pvsegs_sort_full report/vgs_cols_full \\\n   report/vgs_sort_full report/lvs_cols_full \\\n   report/lvs_sort_full report/segs_cols_full \\\n   report/segs_sort_full\npvs_cols_full="pv_name,vg_name"\npvs_sort_full="pv_name"\npvsegs_cols_full="pv_name,pvseg_start,pvseg_size"\npvsegs_sort_full="pv_uuid,pvseg_start"\nvgs_cols_full="vg_name"\nvgs_sort_full="vg_name"\nlvs_cols_full="lv_name,vg_name"\nlvs_sort_full="vg_name,lv_name"\nsegs_cols_full="lv_name,seg_start,seg_size"\nsegs_sort_full="lv_uuid,seg_start"

الضغط التلقائي للمخرجات

\n

إذا نظرت إلى مخرجات lvs أعلاه، يمكنك رؤية أن التقرير يحتوي أيضاً على حقول لا توجد معلومات لعرضها (على سبيل المثال، الأعمدة تحت عنوان\n "Origin" و "Pool" – حقلي\n "origin" و "pool_lv"). يمكن لـ LVM ضغط مخرجات التقرير تلقائياً بحيث لا يتم تضمين هذه الحقول في المخرجات النهائية. لتمكين هذه الميزة ولضغط جميع الحقول، استخدم\n report/compact_output=1 في تكوينك.

\n
# lvmconfig --type full report/compact_output\ncompact_output=1
\n
# lvs\n  LV    LSize Cpy%Sync\n  lvol1 4.00m 100.00\n  lvol0 4.00m
\n
# lvs vg/lvol0\n  LV    LSize\n  lvol0 4.00m
\n

بدلاً من ذلك، يمكنك تحديد الحقول التي يجب ضغطها عن طريق تكوين إعداد التكوين report/compact_output_cols (أو\n خيار سطر الأوامر -o|--options #).

\n
# lvmconfig --type full report/compact_output report/compact_output_cols\ncompact_output=0\ncompact_output_cols="origin"
\n
# lvs\n  LV    LSize Pool Cpy%Sync\n  lvol1 4.00m      100.00\n  lvol0 4.00m
\n
# lvs vg/lvol0\n  LV    LSize Pool\n  lvol0 4.00m
\n
# lvs -o#pool_lv\n  LV    LSize Origin Cpy%Sync\n  lvol1 4.00m        100.00\n  lvol0 4.00m
\n

سنستخدم report/compact_output=1 للأمثلة اللاحقة.
