الوصف

lvextend يزيد من حجم وحدة تخزين منطقية (LV). يتطلب هذا تخصيص نطاقات منطقية من النطاقات الفيزيائية الحرة لمجموعة وحدات التخزين (VG). إذا كان الامتداد يضيف جزءًا جديدًا لوحدة التخزين، فإن الجزء الجديد سيستخدم نوع الجزء الموجود لوحدة التخزين.

تمديد لقطة وحدة تخزين منطقية بنسخ عند الكتابة (copy-on-write snapshot LV) يضيف مساحة لكتل COW.

استخدم lvconvert(8) لتغيير عدد صور البيانات في وحدة تخزين RAID أو المرآة (mirrored LV).

في قسم الاستخدام أدناه، يمكن استبدال --size Size بـ --extents Number. انظر وصف كلا الخيارين في قسم الخيارات.

--alloc contiguous|cling|cling_by_tags|normal|anywhere|inherit
يحدد سياسة التخصيص عندما يحتاج الأمر إلى تخصيص نطاقات فيزيائية (PEs) من VG. لكل VG و LV سياسة تخصيص يمكن تغييرها باستخدام vgchange/lvchange، أو تجاوزها في سطر الأوامر. normal يطبق قواعد منطقية مثل عدم وضع شرائح متوازية على نفس PV. inherit يطبق سياسة VG على LV. contiguous يتطلب وضع PEs جديدة بجوار PEs الموجودة. cling يضع PEs جديدة على نفس PV الموجودة في نفس شريحة LV. إذا كانت هناك PEs كافية للتخصيص، ولكن normal لا يستخدمها، فإن anywhere سيستخدمها حتى لو قلل ذلك من الأداء، على سبيل المثال عن طريق وضع شريحتين على نفس PV. يمكن أيضًا استخدام وسيطات PV الموضعية الاختيارية في سطر الأوامر للحد من أي PVs سيستخدمها الأمر للتخصيص. انظر lvm(8) لمزيد من المعلومات حول التخصيص.

NAME

lvextend — Extend the size of a logical volume

SYNOPSIS

lvextend options LV PV ...

DESCRIPTION

Extends the size of one or more logical volumes.

The amount to extend can be specified in two main ways:

  • -L|--size LogicalVolume[+ size]
    Extend by an absolute size or by adding size.
  • -l|--extents LogicalVolume[+ extents]
    Extend by an absolute number of or by adding extents.

You can also extend to fill the remaining free space in the volume group using -l +100%FREE.

If the LV argument is a simple name (e.g. mylv), the command will search all volume groups for a logical volume with that name. If the name is qualified with a volume group name (e.g. myvg/mylv), the command will only search within that specific volume group.

A list of Physical Volumes can be provided to lvextend to specify where the additional space should be allocated. If no Physical Volumes are specified, the space will be allocated from the volume group's free extents.

If the filesystem is not of type xfs(7), and the filesystem is mounted, the filesystem size is not automatically grown. Use fsadm(8) or the specific filesystem resize command (e.g. resize2fs(8), xfs_growfs(8)) to grow the filesystem.

For xfs(7) filesystems, the fsadm(8) command will be used if the -r flag is specified.

USAGE

lvextend can be used to extend existing logical volumes. The size can be specified using -L (size in MB) or -l (number of extents).

OPTIONS

-a|--alloc AllocationPolicy
Specifies the allocation policy. See lvm.conf(5) for the list of policies with the parameter allocation/policy.
-A|--availableactpolicy Policy
Sets the space available to the Logical Volume manager. See lvm.conf(5). Default is inherit.
-b|--block
Forces the Logical Volume to be created with the block type. This is the default for non-thin LVs. See lvmthin(7).
-c|--contiguous
Try to allocate all the logical extents contiguously on each physical volume. See lvm.conf(5) for allocation/contiguous.
-d|--discard
Enable discard/trim for the LV. This requires that the underlying devices support discard/trim. For thin volumes, this option is ignored, and the discard setting of the thin pool is used.
-h|--help
Display help information.
-k|--keepactive
Do not deactivate the logical volume after the operation. This is the default.
-m|--metadatacopy Copy
Number of metadata copies to be written. Defaults to 1. A value of 2 provides a spare copy of the metadata in the VG.
-M|--monitor { y|n }
Sets the monitoring mode for the LV. Default is inherit.
-t|--type Type
The LV type, also known as "segment type" or "segtype". See usage descriptions for the specific ways to use these types. For more information about redundancy and performance (raid<N>, mirror, striped, linear) see lvmraid(7). For thin provisioning (thin, thin-pool) see lvmthin(7). For performance caching (cache, cache-pool) see lvmcache(7). For copy-on-write snapshots (snapshot) see usage definitions. For VDO (vdo) see lvmvdo(7). Several commands omit an explicit type option because the type is inferred from other options or shortcuts (e.g. --stripes, --mirrors, --snapshot, --virtualsize, --thin, --cache, --vdo). Use inferred types with care because it can lead to unexpected results.
-l|--extents LogicalVolume[+extents]
Extend the LV by the given number of extents. Use a leading + to add extents to the existing size. Use %FREE to extend to the maximum possible size using all free extents in the volume group. Use %लेषण to extend by a percentage of the volume group's free space. The + sign is optional if adding extents.
-L|--size LogicalVolume[+size[UNIT]]
Extend the LV by the given size. Use a leading + to add size to the existing size. The size can be specified in units of B, S, T, P, E, K, M, G, T, P, E (for bytes, sectors, tebibytes, pebibytes, exbibytes, kibibytes, mebibytes, gibibytes, tebibytes, pebibytes, exbibytes respectively).
Use %FREE to extend to the maximum possible size using all free space in the volume group. Use %लेषण to extend by a percentage of the volume group's free space. The + sign is optional if adding size.
-m|--stripes N
Number of stripes (default 1). If more than one stripe is specified, the LV is striped.
-r|--resizefs
Resize filesystem after extending the LV. This is only supported for some filesystem types (currently ext2, ext3, ext4, XFS, Btrfs, JFS, ReiserFS). For XFS, this option requires that the filesystem is mounted. For other types, the filesystem may be mounted or unmounted. The resize operation is attempted using fsadm(8) if possible, otherwise using the filesystem's native resize command. Use with caution.
-s|--snapshot
Creates an LV as a snapshot. See lvmthin(7).
-t|--thin
Creates an LV as a thin volume. See lvmthin(7).
-u|--stripeunit Size[UNIT]
Number of extents per stripe. The default is the value of stripeunit in lvm.conf(5), or 0 if not set. If set to 0, the stripe unit size is calculated from the number of stripes and the number of PEs per stripe. See lvm.conf(5) for allocation/stripeunit.
-U|--update
Update the LV metadata. See lvm.conf(5).
-w|--writecache { on|off|pool|cache-pool }
Enable or disable write cache for the LV. See lvmcache(7).
--usepolicies
Perform an operation according to the policy configured in lvm.conf(5) or a profile.
-v|--verbose ...
Set verbose level. Repeat from 1 to 4 times to increase the detail of messages sent to stdout and stderr.
--version
Display version information.
-y|--yes
Do not prompt for confirmation interactively but always assume the answer yes. Use with extreme caution. (For automatic no, see -qq.)

VARIABLES

LV
Logical Volume name. See lvm(8) for valid names. An LV positional arg generally includes the VG name and LV name, e.g. VG/LV. LV1 indicates the LV must have a specific type, where the accepted LV types are listed. (raid represents raid<N> type).
PV
Physical Volume name, a device path under /dev. For commands managing physical extents, a PV positional arg generally accepts a suffix indicating a range (or multiple ranges) of physical extents (PEs). When the first PE is omitted, it defaults to the start of the device, and when the last PE is omitted it defaults to end.
Start and end range (inclusive): PV[:PE-PE] ...
Start and length range (counting from 0): PV[:PE+PE] ...
String
See the option description for information about the string content.
Size[UNIT]
Size is an input number that accepts an optional unit. Input units are always treated as base two values, regardless of capitalization, e.g. 'k' and 'K' both refer to 1024. The default input unit is specified by letter, followed by |UNIT. UNIT represents other possible input units: b|B is bytes, s|S is sectors of 512 bytes, k|K is KiB, m|M is MiB, g|G is GiB, t|T is TiB, p|P is PiB, e|E is EiB. (This should not be confused with the output control --units, where capital letters mean multiple of 1000.)

ENVIRONMENT VARIABLES

See lvm(8) for information about environment variables used by lvm. For example, LVM_VG_NAME can generally be substituted for a required VG parameter.

EXAMPLES

Extend the size of an LV by 54MiB, using a specific PV.
lvextend -L +54 vg01/lvol10 /dev/sdk3

Extend the size of an LV by the amount of free space on PV /dev/sdk3. This is equivalent to specifying "-l +100%PVS" on the command line.
lvextend vg01/lvol01 /dev/sdk3

Extend an LV by 16MiB using specific physical extents.
lvextend -L+16m vg01/lvol01 /dev/sda:8-9 /dev/sdb:8-9

Extend an LV to use all remaining free space in volume group and all resize its filesystem with fsadm(8).
lvextend -l+100%FREE -r vg01/lvol01

``` ```html lvextend(8) — lvm.ar — مشروع صفحات دليل Arch Linux

الاسم

lvextend — توسيع حجم وحدة تخزين منطقية

الملخص

lvextend الخيارات LV PV ...

الوصف

يقوم بتوسيع حجم وحدة تخزين منطقية واحدة أو أكثر.

يمكن تحديد مقدار التوسيع بطريقتين رئيسيتين:

  • -L|--size LogicalVolume[+ size]
    قم بالتوسيع بحجم مطلق أو بإضافة حجم.
  • -l|--extents LogicalVolume[+ extents]
    قم بالتوسيع بعدد مطلق من أو بإضافة امتدادات.

يمكنك أيضًا التوسيع لملء المساحة الحرة المتبقية في مجموعة وحدات التخزين باستخدام -l +100%FREE.

إذا كان وسيط LV اسمًا بسيطًا (مثل mylv)، فسيقوم الأمر بالبحث في جميع مجموعات وحدات التخزين عن وحدة تخزين منطقية بهذا الاسم. إذا تم تأهيل الاسم باسم مجموعة وحدات تخزين (مثل myvg/mylv)، فسيقوم الأمر بالبحث فقط داخل مجموعة وحدات التخزين المحددة.

يمكن توفير قائمة بوحدات التخزين المادية (Physical Volumes) إلى lvextend لتحديد مكان تخصيص المساحة الإضافية. إذا لم يتم تحديد أي وحدات تخزين مادية، فسيتم تخصيص المساحة من الامتدادات الحرة لمجموعة وحدات التخزين.

إذا لم يكن نوع نظام الملفات هو xfs(7)، وكان نظام الملفات مثبتًا، فلن يتم تكبير حجم نظام الملفات تلقائيًا. استخدم fsadm(8) أو أمر تغيير حجم نظام الملفات المحدد (مثل resize2fs(8)، xfs_growfs(8)) لتكبير نظام الملفات.

بالنسبة لأنظمة الملفات xfs(7)، سيتم استخدام الأمر fsadm(8) إذا تم تحديد العلامة -r.

الاستخدام

lvextend يمكن استخدامه لتوسيع وحدات التخزين المنطقية الموجودة. يمكن تحديد الحجم باستخدام -L (حجم بالميجابايت) أو -l (عدد الامتدادات).

الخيارات

-a|--alloc AllocationPolicy
يحدد سياسة التخصيص. انظر lvm.conf(5) للحصول على قائمة السياسات مع المعامل allocation/policy.
-A|--availableactpolicy Policy
يضبط المساحة المتاحة لمدير وحدات التخزين المنطقية. انظر lvm.conf(5). الافتراضي هو inherit.
-b|--block
يجبر وحدة التخزين المنطقية على الإنشاء بنوع block. هذا هو الافتراضي لوحدات التخزين غير الرقيقة (non-thin). انظر lvmthin(7).
-c|--contiguous
محاولة تخصيص جميع الامتدادات المنطقية بشكل متجاور على كل وحدة تخزين مادية. انظر lvm.conf(5) لـ allocation/contiguous.
-d|--discard
تمكين الإهمال/الاقتطاع (discard/trim) لوحدة التخزين المنطقية. يتطلب هذا أن تدعم الأجهزة الأساسية الإهمال/الاقتطاع. بالنسبة لوحدات التخزين الرقيقة، يتم تجاهل هذا الخيار، ويتم استخدام إعداد الإهمال لمجمع الوحدات الرقيق.
-h|--help
عرض معلومات المساعدة.
-k|--keepactive
لا تقم بإلغاء تنشيط وحدة التخزين المنطقية بعد العملية. هذا هو الافتراضي.
-m|--metadatacopy Copy
عدد نسخ البيانات الوصفية (metadata) التي سيتم كتابتها. الافتراضي هو 1. يوفر الرقم 2 نسخة احتياطية من البيانات الوصفية في مجموعة وحدات التخزين.
-M|--monitor { y|n }
يضبط وضع المراقبة لوحدة التخزين المنطقية. الافتراضي هو inherit.
-t|--type Type
نوع وحدة التخزين المنطقية، المعروف أيضًا باسم "نوع الشريحة" أو "segtype". انظر أوصاف الاستخدام للطرق المحددة لاستخدام هذه الأنواع. لمزيد من المعلومات حول التكرار والأداء (raid<N>, mirror, striped, linear) انظر lvmraid(7). بالنسبة للتزويد الرقيق (thin provisioning) (thin, thin-pool) انظر lvmthin(7). بالنسبة للتخزين المؤقت للأداء (cache, cache-pool) انظر lvmcache(7). بالنسبة لللقطات النسخ عند الكتابة (copy-on-write snapshots) (snapshot) انظر تعريفات الاستخدام. بالنسبة لـ VDO (vdo) انظر lvmvdo(7). تتجاهل العديد من الأوامر خيار نوع صريح لأن النوع يتم استنتاجه من خيارات أخرى أو اختصارات (مثل --stripes، --mirrors، --snapshot، --virtualsize، --thin، --cache، --vdo). استخدم الأنواع المستنتجة بحذر لأنها قد تؤدي إلى نتائج غير متوقعة.
-l|--extents LogicalVolume[+extents]
قم بتوسيع وحدة التخزين المنطقية بالعدد المحدد من الامتدادات. استخدم '+' بادئة لإضافة امتدادات إلى الحجم الحالي. استخدم %FREE للتوسيع إلى أقصى حجم ممكن باستخدام جميع الامتدادات الحرة في مجموعة وحدات التخزين. استخدم %लेषण للتوسيع بنسبة مئوية من المساحة الحرة لمجموعة وحدات التخزين. علامة '+' اختيارية عند إضافة امتدادات.
-L|--size LogicalVolume[+size[UNIT]]
قم بتوسيع وحدة التخزين المنطقية بالحجم المحدد. استخدم '+' بادئة لإضافة حجم إلى الحجم الحالي. يمكن تحديد الحجم بوحدات B، S، T، P، E، K، M، G، T، P، E (للبايت، القطاعات، تبي بايت، بيبي بايت، إكسا بايت، كيبي بايت، ميبي بايت، جيبي بايت، تبي بايت، بيبي بايت، إكسا بايت على التوالي).
استخدم %FREE للتوسيع إلى أقصى حجم ممكن باستخدام كل المساحة الحرة في مجموعة وحدات التخزين. استخدم %लेषण للتوسيع بنسبة مئوية من المساحة الحرة لمجموعة وحدات التخزين. علامة '+' اختيارية عند إضافة حجم.
-m|--stripes N
عدد الشرائح (الافتراضي 1). إذا تم تحديد أكثر من شريحة واحدة، فإن وحدة التخزين المنطقية تكون مقسمة إلى شرائح.
-r|--resizefs
تغيير حجم نظام الملفات بعد توسيع وحدة التخزين المنطقية. هذا مدعوم فقط لبعض أنواع أنظمة الملفات (حالياً ext2، ext3، ext4، XFS، Btrfs، JFS، ReiserFS). بالنسبة لـ XFS، يتطلب هذا الخيار أن يكون نظام الملفات مثبتًا. بالنسبة للأنواع الأخرى، قد يكون نظام الملفات مثبتًا أو غير مثبت. يتم محاولة عملية تغيير الحجم باستخدام fsadm(8) إذا أمكن، وإلا باستخدام أمر تغيير حجم نظام الملفات الأصلي. استخدم بحذر.
-s|--snapshot
ينشئ وحدة تخزين منطقية كلقطة. انظر lvmthin(7).
-t|--thin
ينشئ وحدة تخزين منطقية كوحدة تخزين رقيقة. انظر lvmthin(7).
-u|--stripeunit Size[UNIT]
عدد الامتدادات لكل شريحة. الافتراضي هو قيمة stripeunit في lvm.conf(5)، أو 0 إذا لم يتم تعيينه. إذا تم تعيينه على 0، يتم حساب حجم وحدة الشريحة من عدد الشرائح وعدد وحدات التخزين المادية لكل شريحة. انظر lvm.conf(5) لـ allocation/stripeunit.
-U|--update
تحديث البيانات الوصفية لوحدة التخزين المنطقية. انظر lvm.conf(5).
-w|--writecache { on|off|pool|cache-pool }
تمكين أو تعطيل ذاكرة التخزين المؤقت للكتابة لوحدة التخزين المنطقية. انظر lvmcache(7).
--usepolicies
قم بإجراء عملية وفقًا للسياسة المكونة في lvm.conf(5) أو ملف تعريف.
-v|--verbose ...
ضبط مستوى التفصيل. كرر من مرة إلى 4 مرات لزيادة تفاصيل الرسائل المرسلة إلى الإخراج القياسي والإخراج القياسي للأخطاء.
--version
عرض معلومات الإصدار.
-y|--yes
لا تطلب التأكيد بشكل تفاعلي ولكن افترض دائمًا الإجابة بنعم. استخدم بحذر شديد. (للنفي التلقائي، انظر -qq.)

المتغيرات

LV
اسم وحدة التخزين المنطقية. انظر lvm(8) للأسماء الصالحة. عادةً ما يتضمن وسيط LV الموضعي اسم VG واسم LV، على سبيل المثال VG/LV. يشير LV1 إلى أنه يجب أن يكون لوحدة التخزين المنطقية نوع محدد، حيث يتم سرد أنواع وحدات التخزين المنطقية المقبولة. (يمثل raid نوع raid<N>).
PV
اسم وحدة التخزين المادية، وهو مسار جهاز تحت /dev. بالنسبة للأوامر التي تدير الامتدادات المادية، يقبل وسيط PV الموضعي عادةً لاحقة تشير إلى نطاق (أو نطاقات متعددة) من الامتدادات المادية (PEs). عندما يتم حذف أول PE، فإنه افتراضيًا يبدأ من بداية الجهاز، وعندما يتم حذف آخر PE، فإنه افتراضيًا ينتهي.
نطاق البداية والنهاية (شامل): PV[:PE-PE] ...
نطاق البداية والطول (العد من 0): PV[:PE+PE] ...
String
انظر وصف الخيار للحصول على معلومات حول محتوى السلسلة.
Size[UNIT]
الحجم هو رقم إدخال يقبل وحدة اختيارية. يتم دائمًا التعامل مع وحدات الإدخال على أنها قيم أساس ثنائي، بغض النظر عن حالة الأحرف، على سبيل المثال 'k' و 'K' كلاهما يشيران إلى 1024. يتم تحديد وحدة الإدخال الافتراضية بالحرف، يليه |UNIT. يمثل UNIT وحدات الإدخال الأخرى الممكنة: b|B هي بايت، s|S هي قطاعات بحجم 512 بايت، k|K هي KiB، m|M هي MiB، g|G هي GiB، t|T هي TiB، p|P هي PiB، e|E هي EiB. (لا ينبغي الخلط بين هذا وبين التحكم في الإخراج --units، حيث تعني الأحرف الكبيرة مضاعفات 1000.)

متغيرات البيئة

انظر lvm(8) للحصول على معلومات حول متغيرات البيئة المستخدمة بواسطة lvm. على سبيل المثال، يمكن استبدال LVM_VG_NAME بشكل عام بمعامل VG مطلوب.

أمثلة

توسيع حجم وحدة تخزين منطقية بمقدار 54MiB، باستخدام وحدة تخزين مادية محددة.
lvextend -L +54 vg01/lvol10 /dev/sdk3

توسيع حجم وحدة تخزين منطقية بمقدار المساحة الحرة على وحدة التخزين المادية /dev/sdk3. هذا يعادل تحديد "-l +100%PVS" على سطر الأوامر.
lvextend vg01/lvol01 /dev/sdk3

توسيع وحدة تخزين منطقية بمقدار 16MiB باستخدام امتدادات مادية محددة.
lvextend -L+16m vg01/lvol01 /dev/sda:8-9 /dev/sdb:8-9

توسيع وحدة تخزين منطقية لاستخدام كل المساحة الحرة المتبقية في مجموعة وحدات التخزين وتغيير حجم نظام الملفات الخاص بها باستخدام fsadm(8).
lvextend -l+100%FREE -r vg01/lvol01
