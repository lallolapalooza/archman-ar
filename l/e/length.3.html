تحذير

هذه أشياء متقدمة وصعبة. لا تحتاج إليها إلا إذا كنت تعرف حقًا ما تفعله. معظم التطبيقات لن تحتاج إليها.

تاريخياً، وفرت PhysicsFS الوصول إلى نظام الملفات الفعلي والأرشيفات داخل نظام الملفات هذا. ومع ذلك، أحيانًا تحتاج إلى قوة أكبر من هذا. ربما تحتاج إلى توفير أرشيف موجود بالكامل في الذاكرة، أو تحتاج إلى ربط واجهة برمجة تطبيقات إدخال/إخراج ملف أخرى بـ PhysicsFS، أو تحتاج إلى ترجمة البتات (ربما لديك ملف .zip قياسي مشفر، وتحتاج إلى فك تشفيره أثناء الطيران لأرشيف zip غير المتوقع).

PHYSFS_Io هي الواجهة التي تستخدمها الأرشيفات للحصول على بيانات الأرشيف. تاريخيًا، تم ربط هذا بإدخال/إخراج الملفات إلى نظام الملفات الفعلي، ولكن اعتبارًا من PhysicsFS 2.1، يمكن للتطبيقات توفير تطبيقات إدخال/إخراج خاصة بها وقت التشغيل.

هذه الواجهة ليست بالضرورة ملاءمة عالمية جيدة للإدخال/الإخراج. هناك عدد قليل من المتطلبات الجديرة بالملاحظة:

  • إنها تقوم فقط بإدخال/إخراج متزامن (على الأقل، في الوقت الحالي).
  • تحتاج إلى أن تكون قادرة على المضاعفة. إذا كان لديك مقبض ملف من fopen()، فأنت بحاجة إلى أن تكون قادرًا على إنشاء نسخة فريدة منه (بحيث يكون لدينا مقبضان لنفس الملف يمكن لكل منهما البحث/القراءة/إلخ دون التعارض مع الآخر).
  • تحتاج إلى معرفة حجم مجموعة البيانات بأكملها.
  • تحتاج إلى أن تكون قادرة على البحث والارتداد حسب الطلب.

... باختصار، ربما لن تقوم بتطبيق HTTP.

سلامة الخيوط: لا يُضمن أن تكون تطبيقات PHYSFS_Io آمنة للخيوط بحد ذاتها. في الخلفية حيث تستخدمها PhysicsFS، توفر المكتبة أقفالها الخاصة. إذا كنت تخطط لاستخدامها مباشرة من خيوط منفصلة، يجب عليك إما استخدام mutexes لحمايتها، أو عدم استخدام نفس PHYSFS_Io من خيطين في نفس الوقت.

توثيق الحقول

void(* PHYSFS_Io::destroy) (struct PHYSFS_Io *io)

تنظيف وتخصيص مثيل الإدخال/الإخراج. تحرير الموارد المرتبطة، بما في ذلك (opaque) إذا كان ذلك ممكنًا.

يجب أن تنجح هذه الوظيفة دائمًا: على هذا النحو، فهي تعيد void. قد يقوم النظام باستدعاء وظيفة flush() الخاصة بك قبل هذا. قد تبلغ عن فشل هناك إذا لزم الأمر. قد يتم استدعاء هذه الطريقة حتى إذا فشلت flush()، وفي هذه الحالة سيتعين عليك التخلي عن البيانات غير المفرغة والظروف الفاشلة الأخرى وتنظيفها.

بمجرد استدعاء هذه الطريقة لمثيل معين، سيفترض النظام أنه من غير الآمن لمس هذا المثيل مرة أخرى وسيتجاهل أي مراجع له.

المعلمات

s مثيل الإدخال/الإخراج المراد تدميره.

struct PHYSFS_Io *(* PHYSFS_Io::duplicate) (struct PHYSFS_Io *io)

مضاعفة مثيل الإدخال/الإخراج هذا. يجب أن يؤدي هذا إلى نسخة كاملة من PHYSFS_Io هذا، والتي يمكن أن تعيش بشكل مستقل تمامًا. تحتاج النسخة إلى أن تكون قادرة على أداء جميع عملياتها دون تغيير الأصل، بما في ذلك تدمير كل كائن بشكل منفصل (لذلك، على سبيل المثال: لا يمكنهما مشاركة مقبض ملف؛ يحتاج كل منهما إلى مقبضه الخاص).

إذا لم تتمكن من مضاعفة مقبض، فمن القانوني إرجاع NULL، ولكنك ستحتاج بالتأكيد إلى هذه الوظيفة إذا كنت ترغب في استخدام PHYSFS_Io هذا لدعم أرشيف.

المعلمات

io مثيل الإدخال/الإخراج المراد مضاعفته.

الإرجاع

قيمة جديدة لحقل (opaque) الدفق، أو NULL عند حدوث خطأ.

int(* PHYSFS_Io::flush) (struct PHYSFS_Io *io)

تفريغ الموارد إلى الوسائط، أو إلى أي مكان آخر. هذه هي الفرصة للإبلاغ عن فشل عمليات الكتابة التي ادعت النجاح سابقًا، ولكنها لا تزال لديها فرصة للفشل بالفعل. يمكن أن تكون هذه الطريقة NULL إذا لم يكن التفريغ ضروريًا.

قد يتم استدعاء هذه الوظيفة قبل destroy()، لأنها يمكن أن تبلغ عن فشل و destroy() لا يمكنها ذلك. قد يتم استدعاؤها في أوقات أخرى أيضًا.

المعلمات

io مثيل الإدخال/الإخراج المراد تفريغه.

الإرجاع

صفر عند حدوث خطأ، غير صفر عند النجاح.

PHYSFS_sint64(* PHYSFS_Io::length) (struct PHYSFS_Io *io)

تحديد حجم مجموعة بيانات مثيل الإدخال/الإخراج. إرجاع عدد البايتات المتاحة في الملف، أو -1 إذا لم تتمكن من التحديد. من شبه المؤكد أن يكون الفشل مميتًا لمزيد من استخدام هذا الدفق، لذلك لا يمكنك ترك هذا غير منفذ.

المعلمات

io مثيل الإدخال/الإخراج للاستعلام عنه.

الإرجاع

الحجم الإجمالي، بالبايت، لمجموعة البيانات.

void* PHYSFS_Io::opaque

بيانات المثيل لهذا الهيكل. كل مثيل لديه مؤشر مرتبط به يمكن استخدامه لتخزين أي شيء يريده. هذا المؤشر خاص بكل مثيل من الدفق، لذلك يُفترض أنه سيتغير عند استدعاء duplicate(). يمكن تخصيص هذا أثناء طريقة destroy().

PHYSFS_sint64(* PHYSFS_Io::read) (struct PHYSFS_Io *io, void *buf, PHYSFS_uint64 len)

قراءة المزيد من البيانات. اقرأ (len) بايت من الواجهة، عند موضع الإدخال/الإخراج الحالي، وخزنها في (buffer). يجب أن يتحرك موضع الإدخال/الإخراج الحالي للأمام بمقدار عدد البايتات التي تمت قراءتها بنجاح.

ليس عليك تنفيذ هذا؛ قم بتعيينه إلى NULL إذا لم يتم تنفيذه. سيتم استخدام هذا فقط إذا تم فتح الملف للقراءة. إذا تم تعيينه إلى NULL، فسيتم استخدام تطبيق افتراضي يبلغ عن فشل فوري.

المعلمات

io مثيل الإدخال/الإخراج للقراءة منه.
buf المخزن المؤقت لتخزين البيانات فيه. يجب أن يكون بطول (len) بايت على الأقل ولا يمكن أن يكون NULL.
len عدد البايتات المراد قراءتها من الواجهة.

الإرجاع

عدد البايتات التي تمت قراءتها من الملف، 0 عند نهاية الملف، -1 في حالة فشل كامل.

int(* PHYSFS_Io::seek) (struct PHYSFS_Io *io, PHYSFS_uint64 offset)

نقل موضع الإدخال/الإخراج إلى إزاحة بايت معينة من البداية. هذه الطريقة تنقل موضع الإدخال/الإخراج، لذلك ستكون القراءة/الكتابة التالية للبايت عند إزاحة (offset). يجب أن تتجاوز الإزاحات بعد نهاية الملف

NAME

PHYSFS_Io - I/O interface structure for PhysFS.

SYNOPSIS

#include <physfs.h>

struct PHYSFS_Io {
    PHYSFS_sint64 (*close)(struct PHYSFS_Io *io);
    PHYSFS_sint64 (*read)(struct PHYSFS_Io *io, void *buffer,
                            PHYSFS_uint64 len);
    PHYSFS_sint64 (*seek)(struct PHYSFS_Io *io, PHYSFS_uint64 offset);
    PHYSFS_sint64 (*tell)(struct PHYSFS_Io *io);
    PHYSFS_uint32 version;
    PHYSFS_sint64 (*write)(struct PHYSFS_Io *io, const void *buffer,
                             PHYSFS_uint64 len);
};

Detailed Description

This structure defines the interface for input/output operations within PhysFS. It allows PhysFS to abstract different storage mechanisms (like directories, zip files, etc.) into a unified I/O interface.

Each function pointer within this structure represents a specific I/O operation (close, read, seek, tell, write). When PhysFS needs to perform one of these operations on a specific archive or file, it calls the corresponding function pointer in the PHYSFS_Io structure associated with that archive or file.

The version field is used for binary compatibility and should be set to zero.

Field Documentation

PHYSFS_sint64(* PHYSFS_Io::close) (struct PHYSFS_Io *io)

Close the i/o interface. Free any memory associated with it. This must be implemented for any handle that is not NULL. A failure here will be treated as an error.

Parameters

io The i/o instance to close.

Returns

non-zero on success, zero on error.

PHYSFS_sint64(* PHYSFS_Io::read) (struct PHYSFS_Io *io, void *buffer, PHYSFS_uint64 len)

Read data. Read up to (len) bytes from the interface into the provided (buffer). The current i/o position should move ahead by the number of bytes successfully read.

You don't have to implement this; set it to NULL if not implemented. This will only be used if the file is opened for reading. If set to NULL, a default implementation that immediately reports failure will be used.

You are allowed to buffer; a read can succeed here and then later fail when flushing. Note that PHYSFS_setBuffer() may be operating a level above your i/o, so you should usually not implement your own buffering routines.

Parameters

io The i/o instance to read from.
buffer The buffer to read data into. It must be at least (len) bytes long and can't be NULL.
len The maximum number of bytes to read into (buffer).

Returns

number of bytes read, or -1 if there was a complete failure.

PHYSFS_sint64(* PHYSFS_Io::seek) (struct PHYSFS_Io *io, PHYSFS_uint64 offset)

Set the i/o position. Set the current i/o position to the byte offset specified by (offset). An offset of zero is the beginning of the file.

You don't have to implement this; set it to NULL if not implemented. This will only be used if the file is opened for reading. If set to NULL, a default implementation that immediately reports failure will be used.

Note that seeking past the end of the file is allowed.

Parameters

io The i/o instance to seek.
offset The new byte offset for the i/o position.

Returns

non-zero on success, zero on error.

PHYSFS_sint64(* PHYSFS_Io::tell) (struct PHYSFS_Io *io)

Report current i/o position. Return bytes offset, or -1 if you aren't able to determine. A failure will almost certainly be fatal to further use of this stream, so you may not leave this unimplemented.

Parameters

io The i/o instance to query.

Returns

The current byte offset for the i/o position, -1 if unknown.

PHYSFS_uint32 PHYSFS_Io::version

Binary compatibility information. This must be set to zero at this time. Future versions of this struct will increment this field, so we know what a given implementation supports. We'll presumably keep supporting older versions as we offer new features, though.

PHYSFS_sint64(* PHYSFS_Io::write) (struct PHYSFS_Io *io, const void *buffer, PHYSFS_uint64 len)

Write more data. Write (len) bytes from (buffer) to the interface at the current i/o position. The current i/o position should move ahead by the number of bytes successfully written.

You don't have to implement this; set it to NULL if not implemented. This will only be used if the file is opened for writing. If set to NULL, a default implementation that immediately reports failure will be used.

You are allowed to buffer; a write can succeed here and then later fail when flushing. Note that PHYSFS_setBuffer() may be operating a level above your i/o, so you should usually not implement your own buffering routines.

Parameters

io The i/o instance to write to.
buffer The buffer to read data from. It must be at least (len) bytes long and can't be NULL.
len The number of bytes to read from (buffer).

Returns

number of bytes written to file, -1 if complete failure.
