المكتبة التشغيلية للمحللات اللغوية التي تم إنشاؤها بواسطة ocamllex .

المواضع

type position = {
pos_fname : string ;
pos_lnum : int ;
pos_bol : int ;
pos_cnum : int ;
}

قيمة من النوع position تصف نقطة في ملف مصدر. pos_fname هو اسم الملف؛ pos_lnum هو رقم السطر؛ pos_bol هو إزاحة بداية السطر (عدد الأحرف بين بداية lexbuf وبداية السطر)؛ pos_cnum هو إزاحة الموضع (عدد الأحرف بين بداية lexbuf والموضع). الفرق بين pos_cnum و pos_bol هو إزاحة الحرف داخل السطر (أي، رقم العمود، بافتراض أن كل حرف بعرض عمود واحد).

راجع توثيق النوع lexbuf للحصول على معلومات حول كيفية إدارة المحلل اللغوي للمواضع.

val dummy_pos : position

قيمة من النوع position ، مضمون أن تكون مختلفة عن أي موضع صالح.

مخازن المحلل اللغوي

type lexbuf = {
refill_buff : lexbuf -> unit ;

mutable lex_buffer : bytes ;

mutable lex_buffer_len : int ;

mutable lex_abs_pos : int ;

mutable lex_start_pos : int ;

mutable lex_curr_pos : int ;

mutable lex_last_pos : int ;

mutable lex_last_action : int ;

mutable lex_eof_reached : bool ;

mutable lex_mem : int array ;

mutable lex_start_p : position ;

mutable lex_curr_p : position ;
}

نوع مخازن المحلل اللغوي. مخزن المحلل اللغوي هو الوسيط الذي يتم تمريره إلى وظائف المسح التي تحددها الماسحات الضوئية التي تم إنشاؤها. يحتفظ مخزن المحلل اللغوي بالحالة الحالية للمحلل اللغوي، بالإضافة إلى وظيفة لإعادة تعبئة المخزن من الإدخال.

يمكن للمحللات اللغوية اختيارية الحفاظ على حقول الموضع lex_curr_p و lex_start_p . هذا الوضع "تتبع المواضع" هو الوضع الافتراضي، ويتوافق مع تمرير ~with_position:true إلى الوظائف التي تنشئ مخازن المحلل اللغوي. في هذا الوضع، يتشارك محرك التحليل اللغوي وإجراءات المحلل اللغوي في تحديث حقول الموضع بشكل صحيح، كما هو موضح في الفقرة التالية. عندما يتم تعطيل الوضع صراحةً (مع ~with_position:false )، لن يقوم محرك التحليل اللغوي بلمس حقول المواضع ويجب أن تكون إجراءات المحلل اللغوي حذرة من عدم القيام بذلك أيضًا؛ ستحتفظ حقول lex_curr_p و lex_start_p حينئذٍ دائمًا بالموضع غير الصالح dummy_pos . تجنب تتبع المواضع التخصيصات وكتابة الذاكرة ويمكن أن يحسن بشكل كبير أداء المحلل اللغوي في السياقات التي لا تكون فيها lex_start_p و lex_curr_p مطلوبة.

يعمل وضع تتبع المواضع على النحو التالي. عند كل رمز، سيقوم محرك التحليل اللغوي بنسخ lex_curr_p إلى lex_start_p ، ثم تغيير حقل pos_cnum الخاص بـ lex_curr_p عن طريق تحديثه بعدد الأحرف التي تمت قراءتها منذ بداية lexbuf . يتم ترك الحقول الأخرى دون تغيير بواسطة محرك التحليل اللغوي. للحفاظ على دقتها، يجب تهيئتها قبل الاستخدام الأول لـ lexbuf، وتحديثها بواسطة إجراءات المحلل اللغوي ذات الصلة (أي عند كل نهاية سطر - انظر أيضًا new_line ).

val from_channel : ?with_positions:bool -> in_channel -> lexbuf

إنشاء مخزن محلل لغوي على قناة الإدخال المعطاة. Lexing.from_channel inchan يعيد مخزن محلل لغوي يقرأ من قناة الإدخال inchan ، عند موضع القراءة الحالي.

val from_string : ?with_positions:bool -> string -> lexbuf

إنشاء مخزن محلل لغوي يقرأ من السلسلة المعطاة. يبدأ القراءة من الحرف الأول في السلسلة. يتم إنشاء شرط نهاية الإدخال عند الوصول إلى نهاية السلسلة.

val from_function : ?with_positions:bool -> (bytes -> int -> int) -> lexbuf

إنشاء مخزن محلل لغوي مع الوظيفة المعطاة كطريقة قراءة لها. عندما يحتاج المحلل اللغوي إلى المزيد من الأحرف، سيقوم باستدعاء الوظيفة المعطاة، مما يمنحها تسلسل بايت s وعدد بايت n . يجب على الوظيفة وضع n بايت أو أقل في s ، بدءًا من الفهرس 0، وإرجاع عدد البايتات المقدمة. القيمة المرجعة 0 تعني نهاية الإدخال.

val set_position : lexbuf -> position -> unit

تعيين موضع الإدخال المتتبع الأولي لـ lexbuf إلى قيمة مخصصة. يتجاهل pos_fname . انظر Lexing.set_filename لتغيير هذا الحقل.

Since 4.11

val set_filename : lexbuf -> string -> unit

تعيين اسم الملف في الموضع المتتبع الأولي إلى file في lexbuf .

Since 4.11

val with_positions : lexbuf -> bool

إخبار ما إذا كان مخزن المحلل اللغوي يتتبع حقول المواضع lex_curr_p / lex_start_p ، كما تم تحديده بواسطة الوسيط الاختياري المقابل لوظائف إنشاء مخازن المحلل اللغوي (القيمة الافتراضية هي true ).

عندما يكون with_positions هو false ، يجب ألا تعدل إجراءات المحلل اللغوي حقول المواضع. القيام بذلك على أي حال يمكن أن يعيد تمكين وضع with_position ويقلل من الأداء.

وظائف لإجراءات المحلل اللغوي الدلالية

يمكن استدعاء الوظائف التالية من الإجراءات الدلالية لتعريفات المحلل اللغوي (كود ML المغلق بين أقواس معقوفة الذي يحسب القيمة التي تعيدها وظائف التحليل اللغوي). تمنح هذه الوظائف الوصول إلى سلسلة الأحرف التي تطابقها التعبير العادي المرتبط بالإجراء الدلالي. يجب تطبيق هذه الوظائف على الوسيط lexbuf ، والذي، في الكود الذي تم إنشاؤه بواسطة ocamllex ، يتم ربطه بمخزن المحلل اللغوي الذي تم تمريره إلى وظيفة التحليل.

val lexeme : lexbuf -> string

Lexing.lexeme lexbuf تعيد السلسلة التي تطابق التعبير العادي.

val lexeme_char : lexbuf -> int -> char

Lexing.lexeme_char lexbuf i تعيد الحرف رقم i في السلسلة المطابقة.

val lexeme_start : lexbuf -> int

Lexing.lexeme_start lexbuf تعيد الإزاحة في تيار الإدخال للحرف الأول من السلسلة المطابقة. الحرف الأول من التيار له إزاحة 0.

val lexeme_end : lexbuf -> int

Lexing.lexeme_end lexbuf تعيد الإزاحة في تيار الإدخال للحرف الذي يلي الحرف الأخير من السلسلة المطابقة. الحرف الأول من التيار له إزاحة 0.

val lexeme_start_p : lexbuf -> position

مثل lexeme_start ، ولكن تعيد position كاملة بدلاً من إزاحة. عندما يتم تعطيل تتبع المواضع، تعيد الوظيفة dummy_pos .

val lexeme_end_p : lexbuf -> position

مثل lexeme_end ، ولكن تعيد position كاملة بدلاً من إزاحة. عندما يتم تعطيل تتبع المواضع، تعيد الوظيفة dummy_pos .

val new_line : lexbuf -> unit

تحديث حقل lex_curr_p في lexbuf ليعكس بداية سطر جديد. يمكنك استدعاء هذه الوظيفة في الإجراء الدلالي للقاعدة التي تطابق حرف نهاية السطر. الوظيفة لا تفعل شيئًا عند تعطيل تتبع المواضع.

Since 3.11

وظائف متنوعة

val flush_input : lexbuf -> unit

تجاهل محتويات المخزن وإعادة تعيين الموضع الحالي إلى 0. سيؤدي الاستخدام التالي لـ lexbuf إلى تشغيل إعادة التعبئة.

NAME

Lexing - Interface to the lexical analyzer.

Module

Lexing

Documentation

This module provides access to the state of the lexical analyzer. It is primarily used for debugging lexical analyzers, for instance, to print the current position in the input stream.
