NAME

lev_comp - compiler for NetHack level files

SYNOPSIS

lev_comp [-v] [-w WxH] [-o O] [-i I] [-p P] [-t T] [-L L] [-F F] [-s S] [-d D] [-e E] [-C C] [-R R] [-M M] [-m m] [-N N] [-K K] [-A A] [-U U] [-V V] [-G G] [-H H] [-B B] [-Z Z] [-X X] [-Y Y] [-W W] [-T T] [-P P] [-Q Q] [-O O] [-I I] [-E E] [-U U] [-D D] [-S S] [-H H] [-R R] [-C C] [-M M] [-W W] [-F F] [-L L] [-K K] [-N N] [-G G] [-B B] [-Z Z] [-X X] [-Y Y] [-j J] [-k K] [-l L] [-f F] [-n N] [-g G] [-b B] [-z Z] [-x X] [-y Y] [-o O] [-i I] [-e E] [-u U] [-d D] [-s S] [-h H] [-r R] [-c C] [-m M] [-w W] [-f F] [-l L] [-k K] [-n N] [-g G] [-b B] [-z Z] [-x X] [-y Y] [-j J] [-v] level_file

DESCRIPTION

The file level_file is a text file that describes the contents and layout of a NetHack level. The lev_comp command reads this file, checks for errors, and compiles it into a binary format suitable for use by the NetHack game.

The following options are available:

-v
Verbose mode. Prints more information about the compilation process.
-w WxH
Specifies the width W and height H of the level. If not provided, the dimensions are inferred from the MAP statement.
-o O
Specifies the output file name. If not provided, the default is to overwrite the input file with the compiled version.
-i I
Specifies an include directory for referenced files.
-p P
Specifies a prefix for generated symbols.
-t T
Specifies a table file for object and monster data.
-L L
Specifies a log file for errors and warnings.
-F F
Specifies a format for the output file.
-s S
Specifies a script file for custom behaviors.
-d D
Specifies a directory for default settings.
-e E
Specifies an encoding for the input file.
-C C
Specifies a configuration file.
-R R
Specifies a region definition file.
-M M
Specifies a music file.
-m m
Specifies a map file.

GRAMMAR

The level file format is line-based. Each line represents a command or a definition. The following is a simplified overview of the grammar:

MAP
    [grid_definition]
    [object_definitions]
    [monster_definitions]
    [trap_definitions]
    [room_definitions]
    [corridor_definitions]
    [special_definitions]
ENDMAP

# Example definitions:
# A monster in the center of the map
MONSTER: 'd', "hell hound", (4,3)
# A chest on another random side
OBJECT: '(', "chest", (4,5)
# A sack on a random side, with a diamond and maybe a ruby in it
CONTAINER: '(', "sack", (3,4)
OBJECT: '*', "diamond", contained
OBJECT[50%]: '*', "ruby", contained
# A random dragon somewhere
MONSTER: 'D', random, random
# 3 out of 4 chance for a random trap in the EAST end
TRAP[75%]: random, (6,4)
# An electric eel below the SOUTH end
MONSTER: ';', "electric eel", (4,8)
# Make the walls non-diggable
NON_DIGGABLE: (0,0,8,8)
TELEPORT_REGION: levregion(0,0,79,20), (0,0,8,8)

Coordinates are given as (x,y), where (0,0) is the top-left corner.

Special keywords like random can be used to place objects or monsters at random locations.

Brackets [] can be used to specify a probability for placing an item (e.g., OBJECT[50%]).

Keywords like contained specify that the object should be placed inside another container.

The TELEPORT_REGION directive allows specifying areas for teleportation or other level transitions. The levregion prefix enables referring to any area of the level, irrespective of the current MAP block's position.

EXAMPLE

The following example describes a simple level named "fortress":

4,3), (4,5), (3,4), (5,4)
MONSTER: 'd', "hell hound", place[0]
# a chest on another random side
OBJECT: '(', "chest", place[1]
# a sack on a random side, with a diamond and maybe a ruby in it
CONTAINER: '(', "sack", place[2]
OBJECT: '*', "diamond", contained
OBJECT[50%]: '*', "ruby", contained
# a random dragon somewhere
MONSTER: 'D', random, random
# 3 out of 4 chance for a random trap in the EAST end
TRAP[75%]: random, (6,4)
# an electric eel below the SOUTH end
MONSTER: ';', "electric eel", (4,8)
# make the walls non-diggable
NON_DIGGABLE: (0,0,8,8)
TELEPORT_REGION: levregion(0,0,79,20), (0,0,8,8)

This example will produce a file named "fortress" that can be integrated into one of the numerous mazes of the game.

Note especially the final, TELEPORT_REGION specification. This says that level teleports or other non-stairway arrivals on this level can land anywhere on the level except the area of the map. This shows the use of the ``levregion'' prefix allowed in certain region specifications. Normally, regions apply only to the most recent MAP specification, but when prefixed with ``levregion'', one can refer to any area of the level, regardless of the placement of the current MAP in the level.
