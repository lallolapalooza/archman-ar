LEX(1P) دليل مبرمجي POSIX LEX(1P)

PROLOG

هذه الصفحة الدليلية هي جزء من دليل مبرمجي POSIX. قد يختلف تطبيق Linux لهذه الواجهة (راجع صفحة دليل Linux المقابلة لتفاصيل سلوك Linux)، أو قد لا تكون الواجهة مطبقة على Linux.

NAME

lex — إنشاء برامج للمهام المعجمية (DEVELOPMENT)

SYNOPSIS

lex [-t] [-n|-v] [file...]

DESCRIPTION

تقوم أداة lex بإنشاء برامج C لمعالجة الإدخال الحرفي، والتي يمكن استخدامها كواجهة لـ yacc. يتم إنشاء برامج C من شيفرة المصدر lex وتتوافق مع معيار ISO C، دون الاعتماد على أي سلوك غير محدد، أو غير محدد، أو محدد بالتنفيذ، باستثناء الحالات التي يتم فيها نسخ الشيفرة مباشرة من المصدر المقدم، أو في الحالات التي وثقتها التنفيذ. عادةً، تقوم أداة lex بكتابة البرنامج الذي تنشئه إلى الملف lex.yy.c؛ حالة هذا الملف غير محددة إذا خرج lex بحالة خروج غير صفرية. راجع قسم الوصف الموسع للحصول على وصف كامل للغة إدخال lex.

OPTIONS

تتوافق أداة lex مع مجلد التعريفات الأساسية لـ POSIX.1-2017، القسم 12.2، إرشادات بناء جملة الأداة المساعدة، باستثناء الإرشادات 9.

سيتم دعم الخيارات التالية:

-n
قم بقمع ملخص الإحصائيات الذي يُكتب عادةً مع الخيار -v. إذا لم يتم تحديد أحجام الجداول في شيفرة المصدر lex ولم يتم تحديد الخيار -v، فسيتم ضمنيًا استخدام -n.
-t
اكتب البرنامج الناتج إلى الإخراج القياسي بدلاً من lex.yy.c.
-v
اكتب ملخصًا لإحصائيات lex إلى الإخراج القياسي. (راجع مناقشة أحجام جداول lex في التعريفات في lex.) إذا تم تحديد الخيار -t ولم يتم تحديد -n، فسيتم كتابة هذا التقرير إلى الخطأ القياسي. إذا تم تحديد أحجام الجداول في شيفرة المصدر lex، وإذا لم يتم تحديد الخيار -n، فقد يتم تمكين الخيار -v.

OPERANDS

سيتم دعم المعامل التالي:

file
مسار ملف إدخال. إذا تم تحديد أكثر من file واحد، فسيتم دمج جميع الملفات لإنتاج برنامج lex واحد. إذا لم يتم تحديد أي معاملات file، أو إذا كان المعامل file هو '-'، فسيتم استخدام الإدخال القياسي.

STDIN

سيتم استخدام الإدخال القياسي إذا لم يتم تحديد أي معاملات file، أو إذا كان المعامل file هو '-'. راجع ملفات الإدخال.

INPUT FILES

ستكون ملفات الإدخال ملفات نصية تحتوي على شيفرة مصدر lex، كما هو موضح في قسم الوصف الموسع.

ENVIRONMENT VARIABLES

ستؤثر متغيرات البيئة التالية على تنفيذ lex:

LANG
قم بتوفير قيمة افتراضية لمتغيرات التدويل التي لم يتم تعيينها أو فارغة. (راجع مجلد التعريفات الأساسية لـ POSIX.1-2017، القسم 8.2، متغيرات التدويل لأسبقية متغيرات التدويل المستخدمة لتحديد قيم فئات المكان.)
LC_ALL
إذا تم تعيينه إلى قيمة سلسلة غير فارغة، فقم بالكتابة فوق قيم جميع متغيرات التدويل الأخرى.
LC_COLLATE

حدد المكان لسلوك النطاقات، وفئات التكافؤ، وعناصر التجميع متعددة الأحرف ضمن التعابير العادية. إذا لم يتم تعيين هذا المتغير إلى المكان POSIX، فإن النتائج غير محددة.
LC_CTYPE
حدد المكان لتفسير تسلسلات البايتات لبيانات النص كأحرف (على سبيل المثال، أحرف أحادية البايت مقابل متعددة البايتات في الوسائط وملفات الإدخال)، وسلوك فئات الأحرف ضمن التعابير العادية. إذا لم يتم تعيين هذا المتغير إلى المكان POSIX، فإن النتائج غير محددة.
LC_MESSAGES

حدد المكان الذي يجب استخدامه للتأثير على تنسيق ومحتويات الرسائل التشخيصية المكتوبة إلى الخطأ القياسي.
NLSPATH
حدد موقع كتالوجات الرسائل لمعالجة LC_MESSAGES.

ASYNCHRONOUS EVENTS

افتراضي.

STDOUT

إذا تم تحديد الخيار -t، فسيتم كتابة ملف النص لشيفرة مصدر C الناتجة من lex إلى الإخراج القياسي.

إذا لم يتم تحديد الخيار -t:

*
سيتم كتابة رسائل معلوماتية أو أخطاء أو تحذيرات محددة بالتنفيذ بشأن محتويات إدخال شيفرة المصدر lex إما إلى الإخراج القياسي أو الخطأ القياسي.
*
إذا تم تحديد الخيار -v ولم يتم تحديد الخيار -n، فستتم كتابة إحصائيات lex أيضًا إما إلى الإخراج القياسي أو الخطأ القياسي، بتنسيق محدد بالتنفيذ. قد يتم أيضًا إنشاء هذه الإحصائيات إذا تم تحديد أحجام الجداول باستخدام عامل '%' في قسم التعريفات، طالما لم يتم تحديد الخيار -n.

STDERR

إذا تم تحديد الخيار -t، فسيتم كتابة رسائل معلوماتية أو أخطاء أو تحذيرات محددة بالتنفيذ بشأن محتويات إدخال شيفرة المصدر lex إلى الخطأ القياسي.

إذا لم يتم تحديد الخيار -t:

1.
سيتم كتابة رسائل معلوماتية أو أخطاء أو تحذيرات محددة بالتنفيذ بشأن محتويات إدخال شيفرة المصدر lex إما إلى الإخراج القياسي أو الخطأ القياسي.
2.
إذا تم تحديد الخيار -v ولم يتم تحديد الخيار -n، فستتم كتابة إحصائيات lex أيضًا إما إلى الإخراج القياسي أو الخطأ القياسي، بتنسيق محدد بالتنفيذ. قد يتم أيضًا إنشاء هذه الإحصائيات إذا تم تحديد أحجام الجداول باستخدام عامل '%' في قسم التعريفات، طالما لم يتم تحديد الخيار -n.

OUTPUT FILES

سيتم كتابة ملف نصي يحتوي على شيفرة مصدر C إلى lex.yy.c، أو إلى الإخراج القياسي إذا كان الخيار -t موجودًا.

EXTENDED DESCRIPTION

يحتوي كل ملف إدخال على شيفرة مصدر lex، وهي جدول من التعابير العادية مع إجراءات مقابلة في شكل أجزاء برامج C.

عند تجميع lex.yy.c وربطه بمكتبة lex (باستخدام المعامل -l l مع c99)، سيقرأ البرنامج الناتج إدخال الأحرف من الإدخال القياسي وسيقسمه إلى سلاسل تتطابق مع التعابير المعطاة.

عند مطابقة تعبير، ستحدث هذه الإجراءات:

*
سيتم ترك سلسلة الإدخال التي تمت مطابقتها في yytext كسلسلة منتهية بـ null؛ سيكون yytext إما مصفوفة أحرف خارجية أو مؤشرًا إلى سلسلة أحرف. كما هو موضح في التعريفات في lex، يمكن تحديد النوع بشكل صريح
lex(1p) — POSIX Standard Manual

RATIONALE

The output of the lex utility goes to standard output by default. POSIX.1‐2008 allows this behavior, but leaves an opening for the more expected behavior of using standard error for diagnostics. Also, the System V behavior of writing the statistics when any table sizes are given is allowed, while BSD-derived systems can avoid it. The programmer can always precisely obtain the desired results by using either the -t or -n options.

The OPERANDS section does not mention the use of - as a synonym for standard input; not all historical implementations support such usage for any of the file operands.

A description of the translation table was deleted from early proposals because of its relatively low usage in historical applications.

The change to the definition of the input() function that allows buffering of input presents the opportunity for major performance gains in some applications.

The following examples clarify the differences between lex regular expressions and regular expressions appearing elsewhere in this volume of POSIX.1‐2017. For regular expressions of the form "r/x", the string matching r is always returned; confusion may arise when the beginning of x matches the trailing portion of r. For example, given the regular expression "a*b/cc" and the input "aaabcc", yytext would contain the string "aaab" on this match. But given the regular expression "x*/xy" and the input "xxxy", the token xxx, not xx, is returned by some implementations because xxx matches "x*".

In the rule "ab*/bc", the "b*" at the end of r extends r's match into the beginning of the trailing context, so the result is unspecified. If this rule were "ab/bc", however, the rule matches the text "ab" when it is followed by the text "bc". In this latter case, the matching of r cannot extend into the beginning of x, so the result is specified.
