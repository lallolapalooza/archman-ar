الاسم

tlmgr - مدير TeX Live الأصلي

الملخص

tlmgr [خيار...] إجراء [خيار...] [معامل...]

الوصف

tlmgr يدير تثبيت TeX Live الحالي، سواء الحزم أو خيارات التكوين. للحصول على معلومات حول تنزيل وتثبيت TeX Live مبدئيًا، راجع https://tug.org/texlive/acquire.html.

أحدث إصدار من هذا التوثيق (يتم تحديثه ليليًا من مصادر التطوير) متاح على https://tug.org/texlive/tlmgr.html، بالإضافة إلى إجراءات تحديث "tlmgr" نفسها ومعلومات حول إصدارات الاختبار.

منظمة TeX Live في بضع مخططات رئيسية، كل منها يتم تحديده كمجموعة مختلفة من المجموعات و الحزم، حيث المجموعة هي مجموعة من الحزم، والحزمة هي ما تحتوي على الملفات الفعلية. تحتوي المخططات عادةً على مزيج من المجموعات والحزم، ولكن كل حزمة مدرجة في مجموعة واحدة بالضبط، لا أكثر ولا أقل. يمكن تخصيص وإدارة تثبيت TeX Live على أي مستوى.

راجع https://tug.org/texlive/doc لجميع توثيقات TeX Live المتاحة.

أمثلة

بعد تثبيت TeX Live بنجاح، إليك بعض العمليات الشائعة مع "tlmgr":

"tlmgr option repository ctan"
"tlmgr option repository https://mirror.ctan.org/systems/texlive/tlnet"
أخبر "tlmgr" باستخدام مرآة CTAN قريبة للتحديثات المستقبلية؛ مفيد إذا قمت بتثبيت TeX Live من صورة DVD وتريد تحديثات مستمرة. الأمرين متكافئان؛ "ctan" هو مجرد اسم مستعار للعنوان المحدد.

تحذير: "mirror.ctan.org" يحل إلى العديد من المضيفين المختلفين، وهي ليست متزامنة تمامًا؛ نوصي بالتحديث مرة واحدة يوميًا (على الأكثر)، وليس أكثر. يمكنك اختيار مرآة معينة إذا واجهت مشاكل؛ قائمة جميع مرايا CTAN مع حالة كل منها متاحة على https://ctan.org/mirrors/mirmon.

"tlmgr update --list"
الإبلاغ عما سيتم تحديثه دون تحديث أي شيء فعليًا.
"tlmgr update --all"
اجعل تثبيت TeX المحلي الخاص بك مطابقًا لما هو موجود في مستودع الحزم (مفيد عادةً عند التحديث من CTAN).
"tlmgr info" ماذا
عرض معلومات مفصلة حول حزمة ماذا، مثل حالة التثبيت والوصف، أو البحث عن ماذا في جميع الحزم.
"tlmgr bug" ماذا
عرض معلومات الإبلاغ عن الأخطاء المتاحة لـ ماذا، وهو اسم حزمة أو ملف.

لجميع الإمكانيات والتفاصيل الخاصة بـ "tlmgr"، يرجى قراءة المعلومات الضخمة التالية.

خيارات

الخيارات التالية لـ "tlmgr" هي خيارات عامة، وليست خاصة بأي إجراء. يمكن إعطاء جميع الخيارات، سواء كانت عامة أو خاصة بالإجراء، في أي مكان في سطر الأوامر، وبأي ترتيب. سيكون أول وسيط غير خيار هو الإجراء الرئيسي. في جميع الحالات، "--"خيار و "-"خيار متكافئان، و "=" اختياري بين اسم الخيار وقيمته.

--repository عنوان_url|مسار
تحديد مستودع الحزم الذي يجب تثبيت الحزم منه أو تحديثها، سواء كان دليلًا محليًا أو موقعًا على الشبكة، كما هو موضح أدناه. هذا يتجاوز مستودع الحزم الافتراضي الموجود في قاعدة بيانات حزم TeX Live المثبتة (المعروفة أيضًا باسم TLPDB، والتي ترد بالكامل في الملف "tlpkg/texlive.tlpdb").

هذا الخيار "--repository" يغير الموقع فقط للتشغيل الحالي؛ لإجراء تغيير دائم، استخدم "option repository" (راجع إجراء "option").

كمثال، يمكنك اختيار مرآة CTAN معينة باستخدام شيء كهذا:

-repository http://ctan.example.org/its/ctan/dir/systems/texlive/tlnet

بالطبع، يجب تحديد اسم مضيف فعلي ودليل CTAN العلوي الخاص به. قائمة مرايا CTAN متاحة على https://ctan.org/mirrors/mirmon.

هذا مثال على استخدام دليل محلي:

-repository /local/TL/repository

للألفة الرجعية والراحة، "--location" و "--repo" مقبولان كأسماء مستعارة لهذا الخيار.

يمكن تحديد المواقع بأي من الطرق التالية:

"/some/local/dir"
"file:/some/local/dir"
طرق متكافئة لتحديد دليل محلي.
"ctan"
"https://mirror.ctan.org/systems/texlive/tlnet"
اختر مرآة CTAN تلقائيًا، مع محاولة اختيار مرآة قريبة وحديثة. تستخدم المرآة المختارة للتنزيل بأكمله. الاسم المستعار "ctan" الفارغ هو مجرد اسم مستعار للعنوان الكامل. (انظر https://ctan.org لمزيد من المعلومات حول CTAN ومراياه.)
"http://server/path/to/tlnet"
HTTP القياسي. إذا تم استخدام طريقة LWP (الافتراضية)، يتم دعم الاتصالات المستمرة. يمكن لـ TL أيضًا استخدام "curl" أو "wget" لإجراء التنزيلات، أو برنامج محدد بواسطة المستخدم، كما هو موضح في توثيق "tlmgr" (https://tug.org/texlive/doc/tlmgr.html#ENVIRONMENT-VARIABLES).
"https://server/path/to/tlnet"
مرة أخرى، إذا تم استخدام طريقة LWP (الافتراضية)، فهذا يدعم الاتصالات المستمرة. لسوء الحظ، بعض إصدارات "wget" و "curl" لا تدعم https، وحتى عندما يدعم "wget" https، قد يتم رفض الشهادات حتى عندما تكون الشهادة جيدة، بسبب عدم وجود جذور شهادات محلية. الحل الأبسط لهذه المشكلة هو استخدام http أو ftp.
"ftp://server/path/to/tlnet"
إذا تم استخدام طريقة LWP (الافتراضية)، يتم دعم الاتصالات المستمرة.
"user@machine:/path/to/tlnet"
"scp://user@machine/path/to/tlnet"
"ssh://user@machine/path/to/tlnet"
هذه الصيغ متكافئة؛ كلها تستخدم "scp" لنقل الملفات. يوصى باستخدام "ssh-agent". (معلومات: https://en.wikipedia.org/wiki/OpenSSH، https://en.wikipedia.org/wiki/Ssh-agent.)

إذا كان المستودع على الشبكة، يتم تجاهل أحرف "/" اللاحقة و/أو مكونات "/tlpkg" و/أو "/archive" اللاحقة.

--gui [إجراء]
واجهتان رسوميتان بارزتان لـ "tlmgr"، "tlshell" و "tlcockpit"، يتم تشغيلهما كبرنامجين منفصلين؛ راجع توثيقاتهما الخاصة.

"tlmgr" نفسه لديه واجهة رسومية بالإضافة إلى واجهة سطر الأوامر. يمكنك إعطاء الخيار لاستدعائه، "--gui"، مع إجراء ليتم إحضاره مباشرة إلى الشاشة المقابلة في الواجهة الرسومية. على سبيل المثال، تشغيل

tlmgr --gui update

NAME

tlmgr - TeX Live Package Manager

SYNOPSIS

tlmgr [option...] command [argument...]

DESCRIPTION

The tlmgr program is the TeX Live Package Manager. It is used to install, remove, update, and manage TeX and TeX-related packages from the TeX Live distribution. It can also be used to manage the TeX Live installation itself, for example, by generating configuration files.

COMMANDS

Here is a list of the available commands:

backup

Creates a backup of a package or all packages.

backup [--list] pkg...
Backs up the specified package(s). If the "--list" option is given, it lists all packages that would be backed up.
backup --all [--list]
Backs up all installed packages. If the "--list" option is given, it lists all packages that would be backed up.

Backup files are stored in the "TEXMFBACKUPS" directory.

candidates

Lists packages that are candidates for installation or update.

conflicts

Shows the conflict information for a package.

depends

Shows the dependency information for a package.

depends [-l|-r] [-c] [-w] pkg...
Show dependencies of pkg. The "-l" option lists only local dependencies, "-r" lists only remote dependencies (from the repository). The default is to list both.
dependents [-l|-r] [-c] [-w] pkg...
Show packages that depend on pkg. The options "-l" and "-r" are as above.

The options "-c" and "-w" restrict the output to packages that are currently installed ("-c" for collections, "-w" for worldwide/global packages).

dequeue

Removes a package from the queue for processing.

dump-formats

This command is obsolete. Use "generate fmtutil" instead.

dump-xml

Generates XML output of the installed package database.

enqueue

Adds a package to the queue for processing.

fmtutil

This command is obsolete. Use "generate fmtutil" instead.

freeze

Prevents a package from being updated.

freeze pkg...
Mark the specified package(s) as frozen. Frozen packages will not be updated by the "update --all" command. They can still be updated individually.
freeze --all
Mark all installed packages as frozen.
unfreeze pkg...
Unmark the specified package(s) as frozen.
unfreeze --all
Unmark all installed packages as frozen.

The current frozen status of packages is shown in the "info" command output.

generate

Generates various configuration and index files.

generate fmtutil
Regenerates the format files (e.g., "latex.fmt", "plain.fmt") and the Hyphenation files. This is usually done automatically when needed.
generate language.dat
Regenerates the "language.dat" file.
generate language.def
Regenerates the "language.def" file.
generate language.dat.lua
Regenerates the "language.dat.lua" file.
generate language
Regenerates all three language files: "language.dat", "language.def", and "language.dat.lua".

When generating language files, local overrides can be provided. For example, if you want to disable hyphenation for German, you can create a file named "language-local.dat" in the same directory as "language.dat" and add the line "--!german" to it.

The syntax for disabling items in the local files is as follows:

  • Lines starting with "%" are used for disabling entries in "language.def".

  • Lines starting with "--" are used for disabling entries in "language.dat" and "language.dat.lua".

In all cases, the name is the respective format name or hyphenation pattern identifier. Examples:

%!german
--!usenglishmax

(Of course, you're not likely to actually want to disable those particular items. They're just examples.)

After such a disabling line, the local file can include another entry for the same item, if a different definition is desired. In general, except for the special disabling lines, the local files follow the same syntax as the master files.

The form "generate language" recreates all three files "language.dat", "language.def", and "language.dat.lua", while the forms with an extension recreates only that given language file.

Options:

--dest output_file
specifies the output file (defaults to the respective location in "TEXMFSYSVAR"). If "--dest" is given to "generate language", it serves as a basename onto which ".dat" will be appended for the name of the "language.dat" output file, ".def" will be appended to the value for the name of the "language.def" output file, and ".dat.lua" to the name of the "language.dat.lua" file. (This is just to avoid overwriting; if you want a specific name for each output file, we recommend invoking "tlmgr" twice.)
--localcfg local_conf_file
specifies the (optional) local additions (defaults to the respective location in "TEXMFLOCAL").
--rebuild-sys
tells "tlmgr" to run necessary programs after config files have been regenerated. These are: "fmtutil-sys --all" after "generate fmtutil", "fmtutil-sys --byhyphen .../language.dat" after "generate language.dat", and "fmtutil-sys --byhyphen .../language.def" after "generate language.def".

These subsequent calls cause the newly-generated files to actually take effect. This is not done by default since those calls are lengthy processes and one might want to made several related changes in succession before invoking these programs.

The respective locations are as follows:

tex/generic/config/language.dat (and language-local.dat)
tex/generic/config/language.def (and language-local.def)
tex/generic/config/language.dat.lua (and language-local.dat.lua)

gui

Start the graphical user interface. See GUI below.

info

info [option...] pkg...
info [option...] collections
info [option...] schemes
With no argument, lists all packages available at the package repository, prefixing those already installed with "i".

With the single word "collections" or "schemes" as the argument, lists the request type instead of all packages.

With any other arguments, display information about pkg: the name, category, short and long description, sizes, installation status, and TeX Live revision number. If pkg is not locally installed, searches in the remote installation source.

For normal packages (not collections or schemes), the sizes of the four groups of files (run/src/doc/bin files) are shown separately. For collections, the cumulative size is shown, including all directly-dependent packages (but not dependent collections). For schemes, the cumulative size is also shown, including all directly-dependent collections and packages.

If pkg is not found locally or remotely, the search action is used and lists matching packages and files.

It also displays information taken from the TeX Catalogue, namely the package version, date, and license. Consider these, especially the package version, as approximations only, due to timing skew of the updates of the different pieces. By contrast, the "revision" value comes directly from TL and is reliable.

The former actions "show" and "list" are merged into this action, but are still supported for backward compatibility.

Options:

--list
If the option "--list" is given with a package, the list of contained files is also shown, including those for platform-specific dependencies. When given with schemes and collections, "--list" outputs their dependencies in a similar way.
--only-files
If this option is given, only the files for a given package are listed, no further information. If more than one package name is given, each file list is preceded by the package name.
--only-installed
If this option is given, the installation source will not be used; only locally installed packages, collections, or schemes are listed.
--only-remote
Only list packages from the remote repository. Useful when checking what is available in a remote repository using "tlmgr --repo ... --only-remote info". Note that "--only-installed" and "--only-remote" cannot both be specified.
--data "item1,item2,..."
If the option "--data" is given, its argument must be a comma or colon separated list of field names from: "name", "category", "localrev", "remoterev", "shortdesc", "longdesc", "installed", "size", "relocatable", "depends", "cat-version", "cat-date", "cat-license", plus various "cat-contact-*" fields (see below).

The "cat-*" fields all come from the TeX Catalogue (https://ctan.org/pkg/catalogue). For each, there are two more variants with prefix "l" and "r", e.g., "lcat-version" and "rcat-version", which indicate the local and remote information, respectively. The variants without "l" and "r" show the most current one, which is normally the remote value.

The requested packages' information is listed in CSV format, one package per line, and the column information is given by the "itemN". The "depends" column contains the names of all the dependencies separated by ":" characters.

At this writing, the "cat-contact-*" fields include: "home", "repository", "support", "bugs", "announce", "development". Each may be empty or a url value. A brief description is on the CTAN upload page for new packages: https://ctan.org/upload.

إذا تم تعيين "formats" (وهذا هو الافتراضي)، فسيتم إعادة إنشاء الصيغ عند تغيير المحرك أو ملفات الصيغة. قم بتعطيل هذا فقط عندما تعرف كيف وتريد إعادة إنشاء الصيغ بنفسك كلما لزم الأمر (وهو أمر متكرر، في الممارسة العملية).

يتحكم خيار "postcode" في تنفيذ كتل الإجراءات ما بعد التثبيت لكل حزمة. يتم تعيينه افتراضيًا، مرة أخرى، لا يُرجح أن يكون تعطيله ذا أهمية إلا للمطورين الذين يقومون بتصحيح الأخطاء.

تتحكم خيارات "docfiles" و "srcfiles" في تثبيت مجموعات الملفات المقابلة (التوثيق، المصادر؛ التقريب هو تقريبي) لكل حزمة. افتراضيًا، كلاهما مُمكّن (1). يمكن تعطيل أي منهما أو كليهما (تعيين إلى 0) إذا كانت مساحة القرص محدودة أو للتثبيتات التجريبية الدنيا، إلخ. عند تعطيلها، لا يتم تنزيل الملفات المقابلة على الإطلاق.

تحدد الخيارات "autobackup" و "backupdir" الإعدادات الافتراضية للإجراءات "update" و "backup" و "restore". تحتاج هذه الإجراءات الثلاثة إلى دليل للكتابة أو القراءة منه للنسخ الاحتياطي. إذا لم يتم تحديد "--backupdir" في سطر الأوامر، يتم استخدام قيمة خيار "backupdir" (إذا تم تعيينها). يقوم مثبت TL بتعيين "backupdir" إلى ".../tlpkg/backups"، تحت دليل تثبيت TL الرئيسي.

يقوم خيار "autobackup" (بتفعيل/تعطيل) الإنشاء التلقائي للنسخ الاحتياطية. قيمته عدد صحيح. إذا كانت قيمة "autobackup" هي -1، فلا يتم إزالة أي نسخ احتياطية. إذا كانت "autobackup" 0 أو أكثر، فإنها تحدد عدد النسخ الاحتياطية المراد الاحتفاظ بها. وبالتالي، يتم تعطيل النسخ الاحتياطية إذا كانت القيمة 0. في وضع "--clean" للإجراء "backup"، يحدد هذا الخيار أيضًا العدد المراد الاحتفاظ به. القيمة الافتراضية هي 1، بحيث يتم إجراء نسخ احتياطية، ولكن يتم الاحتفاظ بنسخة احتياطية واحدة فقط.

لإعداد "autobackup" إلى -1 في سطر الأوامر، استخدم:

tlmgr option -- autobackup -1

تجنب "--" أن يتم التعامل مع -1 كخيار. (يتوقف "--" عن التحليل للخيارات عند النقطة التي يظهر فيها؛ هذه ميزة عامة عبر معظم برامج Unix.)

تستخدم الخيارات "sys_bin" و "sys_man" و "sys_info" في أنظمة Unix للتحكم في إنشاء الروابط للملفات القابلة للتنفيذ وملفات Info وصفحات man. انظر إجراء "path" لمزيد من التفاصيل.

update [option...] [pkg...]

يقوم بتحديث الحزم المقدمة كوسائط إلى أحدث إصدار متاح في مصدر التثبيت. يجب تحديد إما "--all" أو اسم pkg واحد على الأقل.

--all
تحديث جميع الحزم المثبتة باستثناء "tlmgr" نفسها. إذا كانت هناك تحديثات لـ "tlmgr" نفسها، فسيؤدي ذلك إلى حدوث خطأ، إلا إذا تم أيضًا تقديم الخيار "--force" أو "--self". (انظر أدناه.)

بالإضافة إلى تحديث الحزم المثبتة، أثناء تحديث مجموعة، يتم مزامنة التثبيت المحلي (بشكل افتراضي) مع حالة المجموعة على الخادم، لكل من الإضافات والإزالات.

هذا يعني أنه إذا تمت إزالة حزمة على الخادم (وبالتالي تم حذفها أيضًا من المجموعة ذات الصلة)، فسيقوم "tlmgr" بإزالة الحزمة في التثبيت المحلي. يُطلق على هذا ``الإزالة التلقائية'' ويتم الإعلان عنه على هذا النحو عند استخدام الخيار "--list". يمكن منع هذه الإزالة التلقائية باستخدام الخيار "--no-auto-remove" (غير مستحسن، انظر وصف الخيار).

وبالمثل، إذا تمت إضافة حزمة إلى مجموعة على الخادم مثبتة محليًا أيضًا، فسيتم إضافتها إلى التثبيت المحلي. يُطلق على هذا ``التثبيت التلقائي'' ويتم الإعلان عنه على هذا النحو عند استخدام الخيار "--list". يمكن منع هذا التثبيت التلقائي باستخدام الخيار "--no-auto-install" (غير مستحسن أيضًا).

استثناء من فحوصات تبعيات المجموعة (بما في ذلك التثبيت التلقائي للحزم المذكورة للتو) هي تلك التي تم ``إزالتها بالقوة'' بواسطتك، أي أنك استدعيت "tlmgr remove --force" عليها. (انظر وثائق إجراء "remove".) لإعادة تثبيت أي حزم تم إزالتها بالقوة، استخدم "--reinstall-forcibly-removed".

للتأكيد: تتم إزالة الإضافات والإزالات التلقائية بالكامل بناءً على مقارنة المجموعات. وبالتالي، إذا قمت بتثبيت حزمة فردية يدويًا "foo" والتي تم حذفها لاحقًا من الخادم، فلن يلاحظها "tlmgr" ولن يقوم بإزالتها محليًا. (يجب أن يكون الأمر كذلك، بدون عمل إعادة هيكلة كبير، لأن tlpdb لا يسجل المستودع الذي تأتي منه الحزم.)

إذا كنت ترغب في استبعاد بعض الحزم من تشغيل التحديث الحالي (على سبيل المثال، بسبب اتصال بطيء)، انظر الخيار "--exclude" أدناه.

--self
تحديث "tlmgr" نفسها (أي، حزم البنية التحتية) إذا كانت هناك تحديثات متاحة لها. على نظام Windows، يتضمن ذلك تحديثات لمفسر Perl الخاص المشحون داخل TeX Live.

إذا تم تقديم هذا الخيار مع "--all" أو قائمة بالحزم، فسيتم تحديث "tlmgr" أولاً، وإذا نجح هذا التحديث، فسيتم إعادة تشغيل الإصدار الجديد لإكمال بقية التحديثات.

باختصار:

tlmgr update --self        # تحديث البنية التحتية فقط
tlmgr update --self --all  # تحديث البنية التحتية وجميع الحزم
tlmgr update --force --all # تحديث جميع الحزم ولكن *ليس* البنية التحتية
                           # ... هذا الأخير على مسؤوليتك الخاصة، غير مستحسن!
--dry-run
لن يتم تثبيت أي شيء فعليًا؛ بدلاً من ذلك، سيتم كتابة الإجراءات التي سيتم تنفيذها إلى الطرفية. هذا تقرير أكثر تفصيلاً من "--list".
--list [pkg]
يسرد بإيجاز الحزم التي سيتم تحديثها أو تثبيتها حديثًا أو إزالتها، دون تغيير أي شيء فعليًا. إذا تم تقديم "--all" أيضًا، فسيتم سرد جميع التحديثات المتاحة. إذا تم تقديم "--self"، ولكن ليس "--all"، فسيتم سرد التحديثات فقط للحزم الحيوية (tlmgr، بنية TeX Live التحتية، perl على Windows، إلخ). إذا لم يتم تقديم "--all" ولا "--self"، ولم يتم تقديم أي pkg بالإضافة إلى ذلك، فسيتم افتراض "--all" (وبالتالي، "tlmgr update --list" هو نفس "tlmgr update --list --all"). إذا لم يتم تقديم "--all" ولا "--self"، ولكن تم تقديم أسماء حزم محددة، فسيتم التحقق من تحديثات تلك الحزم.
--exclude pkg
استبعاد pkg من عملية التحديث. إذا تم تقديم هذا الخيار أكثر من مرة، فستتراكم وسائطه.

الوسيط pkg يستبعد كل من الحزمة pkg نفسها وجميع حزمها ذات الصلة الخاصة بالمنصة pkg.ARCH. على سبيل المثال،

tlmgr update --all --exclude a2ping

لن يقوم بتحديث "a2ping"، "a2ping.i386-linux"، أو أي حزمة أخرى "a2ping."ARCH.

إذا حدد هذا الخيار حزمة كانت ستكون مرشحة للتثبيت التلقائي، أو الإزالة التلقائية، أو إعادة تثبيت حزمة تمت إزالتها بالقوة، فسينتهي "tlmgr" برسالة خطأ. الاستثناءات غير مدعومة في هذه الظروف.

يمكن أيضًا تعيين هذا الخيار بشكل دائم في ملف تكوين tlmgr باستخدام المفتاح "update-exclude".

--no-auto-remove [pkg...]
بشكل افتراضي، يحاول "tlmgr" إزالة الحزم في مجموعة موجودة اختفت من الخادم، كما هو موضح أعلاه تحت "--all". يمنع هذا الخيار مثل هذه الإزالات، إما لجميع الحزم (مع "--all")، أو فقط لأسماء pkg المعطاة. يمكن أن يؤدي هذا إلى تثبيت TeX غير متناسق، حيث غالبًا ما يتم إعادة تسمية الحزم أو استبدالها من قبل مؤلفيها. لذلك لا يُنصح بهذا.
--no-auto-install [pkg...]
في الظروف العادية، سيقوم "tlmgr" بتثبيت الحزم الجديدة على الخادم، كما هو موضح أعلاه تحت "--all". يمنع هذا الخيار أي تثبيت تلقائي من هذا القبيل، إما لجميع الحزم (مع "--all")، أو أسماء pkg المعطاة.

علاوة على ذلك، بعد انتهاء تشغيل "tlmgr" باستخدام هذا، سيتم *اعتبار* الحزم التي كان سيتم تثبيتها تلقائيًا *مُزالَة بالقوة*. لذا، إذا كان "foobar" هو الحزمة الجديدة الوحيدة على الخادم، فإن

tlmgr update --all --no-auto-install

يعادل

tlmgr update --all
tlmgr remove --force foobar

مرة أخرى، نظرًا لأنه يتم أحيانًا إعادة تسمية الحزم أو استبدالها، فلا يُنصح باستخدام هذا الخيار.

--reinstall-forcibly-removed
في الظروف العادية، لن يقوم "tlmgr" بتثبيت الحزم التي تم إزالتها بالقوة من قبل المستخدم؛ أي، التي تمت إزالتها باستخدام "remove --force"، أو التي تم حظر تثبيتها بواسطة "--no-auto-install" خلال تحديث سابق.

يجعل هذا الخيار "tlmgr" يتجاهل عمليات الإزالة بالقوة ويعيد تثبيت جميع هذه الحزم. يمكن استخدام هذا لمزامنة التثبيت بالكامل مع ما هو متاح على الخادم:

tlmgr update --reinstall-forcibly-removed --all
--backup
--backupdir directory
يتحكم هذان الخياران في إنشاء نسخ احتياطية للحزم *قبل* التحديث؛ أي، نسخ الحزم المثبتة حاليًا احتياطيًا. إذا لم يتم تقديم أي من الخيارين، فلن يتم إجراء أي نسخ احتياطي. إذا تم تقديم "--backupdir" وحدد دليلاً قابلاً للكتابة، فسيتم إجراء نسخة احتياطية في هذا الموقع. إذا تم تقديم "--backup" فقط، فسيتم إجراء نسخة احتياطية في الدليل الذي تم تعيينه مسبقًا عبر إجراء "option" (انظر أدناه). إذا تم تقديم كليهما، فسيتم إجراء نسخة احتياطية في directory المحدد.

يمكنك أيضًا تعيين الخيارات عبر إجراء "option" لإنشاء نسخ احتياطية تلقائيًا لجميع الحزم، و/أو الاحتفاظ بعدد معين فقط من النسخ الاحتياطية.

يقوم "tlmgr" دائمًا بإنشاء نسخة احتياطية مؤقتة عند تحديث الحزم، في حالة حدوث فشل في التنزيل أو فشل آخر أثناء التحديث. في المقابل، الغرض من خيار "--backup" هذا هو حفظ نسخة احتياطية دائمة في حالة أن *محتوى* التحديث الفعلي يسبب مشاكل، على سبيل المثال، يقدم عدم توافق في TeX.

يوضح إجراء "restore" كيفية الاستعادة من نسخة احتياطية.

--no-depends
إذا طلبت تحديث حزمة بشكل طبيعي، فسيتم التحقق من جميع الحزم التابعة لها وتحديثها إذا لزم الأمر. يلغي هذا المفتاح هذا السلوك.
--no-depends-at-all
انظر أعلاه تحت install (وكن حذرًا).
--force
فرض تحديث الحزم العادية، دون تحديث "tlmgr" نفسها (ما لم يتم تقديم الخيار "--self" أيضًا). غير مستحسن.

أيضًا، لا يزال يتم تنفيذ "update --list" بغض النظر عن هذا الخيار.

/dl>

إذا كانت الحزمة الموجودة على الخادم أقدم من الحزمة المثبتة بالفعل (على سبيل المثال، إذا كان المستودع المحدد محدثًا)، فإن "tlmgr" لا يقوم بعملية التخفيض. أيضًا، لا يتم تثبيت حزم الأنظمة الأساسية غير المثبتة.

"tlmgr" يحفظ نسخة واحدة من الملف الرئيسي "texlive.tlpdb" المستخدم للتحديث، مع لاحقة تمثل عنوان URL للمستودع، كما في "tlpkg/texlive.tlpdb.main."سلسلة تجزئة طويلة. وبالتالي، حتى عند استخدام العديد من المستودعات، يتم الاحتفاظ بنسخة احتياطية واحدة فقط للملف الرئيسي "tlpdb". بالنسبة للمستودعات غير الرئيسية، والتي لا تحتوي عمومًا على العديد من المستودعات (أو أي منها)، لا يتم إجراء أي تنظيف للنسخ الاحتياطية.

هذا الإجراء لا يضيف أو يزيل تلقائيًا روابط رمزية جديدة في أدلة النظام؛ تحتاج إلى تشغيل "tlmgr" "path" بنفسك إذا كنت تستخدم هذه الميزة وتريد إضافة روابط رمزية جديدة.

ملف إعدادات TLMGR

"tlmgr" يقرأ ملفي إعدادات: أحدهما على مستوى النظام، في "TEXMFSYSCONFIG/tlmgr/config"، والآخر خاص بالمستخدم، في "TEXMFCONFIG/tlmgr/config". الملف الخاص بالمستخدم هو الافتراضي لإجراء "conf tlmgr". (قم بتشغيل "kpsewhich -var-value=TEXMFSYSCONFIG" أو "... TEXMFCONFIG ..." لرؤية أسماء الدلائل الفعلية.)

يمكن تعيين بعض الإعدادات الافتراضية المقابلة لخيار سطر الأوامر في ملفات الإعدادات هذه. بالإضافة إلى ذلك، يمكن للملف على مستوى النظام أن يحتوي على توجيه لتقييد الإجراءات المسموح بها.

في ملفات الإعدادات هذه، يتم تجاهل الأسطر الفارغة والأسطر التي تبدأ بالرمز #. يجب أن تبدو جميع الأسطر الأخرى كالتالي:

key = value

حيث أن المسافات اختيارية ولكن "=" مطلوبة.

المفاتيح المسموح بها هي:

"auto-remove =" 0 أو 1 (الافتراضي 1)، نفس خيار سطر الأوامر.
"gui-expertmode =" 0 أو 1 (الافتراضي 1). هذا يبدل بين الواجهة الرسومية الكاملة والواجهة الرسومية المبسطة مع الإعدادات الأكثر شيوعًا فقط.
"gui-lang =" llcode، مع قيمة رمز لغة كما في خيار سطر الأوامر.
"no-checksums =" 0 أو 1 (الافتراضي 0، انظر أدناه).
"persistent-downloads =" 0 أو 1 (الافتراضي 1)، نفس خيار سطر الأوامر.
"require-verification =" 0 أو 1 (الافتراضي 0)، نفس خيار سطر الأوامر.
"tkfontscale =" رقم عشري (الافتراضي 1.0)؛ عامل قياس للخطوط في الواجهات الأمامية المستندة إلى Tk.
"update-exclude =" قائمة حزم مفصولة بفواصل (لا يُسمح بالمسافات). نفس خيار سطر الأوامر "--exclude" لإجراء "update".
"verify-downloads =" 0 أو 1 (الافتراضي 1)، نفس خيار سطر الأوامر.

يمكن لملف إعدادات النظام أن يحتوي على مفتاح إضافي واحد:

"allowed-actions =" action1[,action2,...] القيمة هي قائمة مفصولة بفواصل (بدون مسافات) لإجراءات "tlmgr" التي يُسمح بتنفيذها عند استدعاء "tlmgr" في وضع النظام (أي، بدون "--usermode"). هذا يسمح للموزعين بتضمين "tlmgr" في حزمهم، ولكن السماح فقط بمجموعة مقيدة من الإجراءات التي لا تتداخل مع مدير حزم التوزيع الخاص بهم. بالنسبة لتثبيتات TeX Live الأصلية، لا معنى لتعيين هذا.

أخيرًا، يحتاج المفتاح "no-checksums" إلى مزيد من الشرح. افتراضيًا، تتم مقارنة مجاميع التحقق من الحزم التي تم حسابها وتخزينها على الخادم (في TLPDB) بمجاميع التحقق التي تم حسابها محليًا بعد التنزيل. "no-checksums" يعطل هذه العملية. خوارزمية مجموع التحقق هي SHA-512. يجب أن يحتوي نظامك على أحد (يتم البحث عنه بهذا الترتيب): وحدة Perl "Digest::SHA"، برنامج "openssl" (https://openssl.org)، برنامج "sha512sum" (من GNU Coreutils، https://www.gnu.org/software/coreutils)، أو أخيرًا برنامج "shasum" (فقط لدعم أجهزة Mac القديمة). إذا لم يكن أي من هذه البرامج متاحًا، يتم إصدار تحذير ويتابع "tlmgr" دون التحقق من مجاميع التحقق. "no-checksums" يتجنب التحذير. (بالمناسبة، تطبيقات SHA الأخرى، مثل وحدات Perl الخالصة و Lua الخالصة، بطيئة جدًا بحيث لا يمكن استخدامها في سياقنا.)

التحقق التشفيري

"tlmgr" و "install-tl" يقومان بالتحقق التشفيري إذا أمكن. إذا تم إجراء التحقق ونجح، فإن البرامج تسجل "(verified)" بعد تحميل TLPDB؛ وإلا، فإنها تسجل "(not verified)". ولكن في كلتا الحالتين، بشكل افتراضي، تستمر عملية التثبيت و/أو التحديثات بشكل طبيعي.

إذا كان برنامج اسمه "gpg" متاحًا (أي، تم العثور عليه في "PATH")، فسيتم التحقق افتراضيًا من التوقيعات التشفيرية: نحن نطلب أن يكون المستودع الرئيسي موقعًا، ولكن ليس أي مستودعات إضافية. إذا لم يكن "gpg" متاحًا، فلن يتم التحقق من التوقيعات بشكل افتراضي ولن يتم إجراء أي تحقق، لكن "tlmgr" سيستمر على أي حال.

يمكن التحكم في سلوك التحقق بواسطة سطر الأوامر وخيار ملف الإعدادات "verify-repo" الذي يأخذ إحدى القيم التالية: "none"، "main"، أو "all". مع "none"، لا يتم محاولة أي تحقق على الإطلاق. مع "main" (الافتراضي) يكون التحقق مطلوبًا فقط للمستودع الرئيسي، وفقط إذا كان "gpg" متاحًا؛ على الرغم من المحاولة لجميع المستودعات، فإن التوقيعات المفقودة للمستودعات الفرعية لن تؤدي إلى خطأ. أخيرًا، في حالة "all"، يجب أن يكون "gpg" متاحًا ويجب أن تكون جميع المستودعات موقعة.

في جميع الحالات، إذا تم فحص توقيع وفشل في التحقق، يتم رفع خطأ.

يتطلب التحقق التشفيري نجاح فحص مجاميع التحقق (الموصوف أعلاه) وبرنامج GnuPG عامل ( "gpg") (انظر أدناه لطريقة البحث). ثم، ما لم يتم تعطيل التحقق التشفيري، يتم تنزيل ملف توقيع ( "texlive.tlpdb.*.asc") لملف مجاميع التحقق والتحقق من التوقيع. يتم إنشاء التوقيع بواسطة مفتاح توزيع TeX Live GPG 0x0D5E5D9106BAB6BC، والذي بدوره موقع بواسطة مفتاح Karl Berry 0x0716748A30D155AD ومفتاح Norbert Preining 0x6CACA448860CDC13. يمكن الحصول على جميع هذه المفاتيح من خوادم المفاتيح القياسية.

يمكن إضافة مفاتيح موثوقة إضافية باستخدام إجراء "key".

إعداد استدعاء GnuPG

يتم البحث عن الملف التنفيذي لـ GnuPG على النحو التالي: إذا تم تعيين متغير البيئة "TL_GNUPG"، يتم اختباره واستخدامه؛ وإلا يتم فحص "gpg"؛ وأخيرًا يتم فحص "gpg2".

يمكن إجراء مزيد من التكيف لاستدعاء "gpg" باستخدام متغيرات البيئة "TL_GNUPGHOME"، والتي يتم تمريرها إلى "gpg" كقيمة لـ "--homedir"، و "TL_GNUPGARGS"، والتي تستبدل الخيارات الافتراضية "--no-secmem-warning --no-permission-warning".

وضع المستخدم

"tlmgr" يوفر طريقة مقيدة، تسمى "وضع المستخدم"، لإدارة أشجار texmf عشوائية بنفس طريقة التثبيت الرئيسي. على سبيل المثال، هذا يسمح للأشخاص الذين ليس لديهم أذونات كتابة على موقع التثبيت بتحديث/تثبيت الحزم في شجرة خاصة بهم.

يتم تبديل "tlmgr" إلى وضع المستخدم باستخدام خيار سطر الأوامر "--usermode". لا يقوم بالتبديل تلقائيًا، ولا يوجد إعداد ملف تكوين له. وبالتالي، يجب تقديم هذا الخيار صراحةً في كل مرة يتم فيها تنشيط وضع المستخدم.

يعمل هذا الوضع من "tlmgr" على شجرة المستخدم، افتراضيًا قيمة متغير "TEXMFHOME". يمكن تجاوز هذا باستخدام خيار سطر الأوامر "--usertree". في ما يلي، عندما نتحدث عن شجرة المستخدم، فإننا نعني إما "TEXMFHOME" أو تلك المحددة في سطر الأوامر.

ليست كل الإجراءات مسموح بها في وضع المستخدم؛ سيقوم "tlmgr" بتنبيهك ولن ينفذ أي إجراءات إشكالية. ما هو غير مدعوم حاليًا (ومن المحتمل ألا يتم دعمه أبدًا) هو إجراء "platform". إجراء "gui" غير مدعوم حاليًا، ولكن قد يكون كذلك في إصدار مستقبلي.

بعض إجراءات "tlmgr" لا تحتاج إلى أي أذونات كتابة وبالتالي تعمل بنفس الطريقة في وضع المستخدم والوضع العادي. حاليًا هذه هي: "check"، "help"، "list"، "print-platform"، "print-platform-info"، "search"، "show"، "version".

من ناحية أخرى، معظم الإجراءات المتعلقة بإدارة الحزم تحتاج إلى أذونات كتابة، وبالتالي تتصرف بشكل مختلف في وضع المستخدم، كما هو موضح أدناه: "install"، "update"، "remove"، "خيار", "ورقة", "إنشاء", "نسخ_احتياطي", "استعادة", "إلغاء_التثبيت", "روابط_رمزية".

قبل استخدام "tlmgr" في وضع المستخدم، يجب عليك إعداد شجرة المستخدم باستخدام إجراء "init-usertree". يقوم هذا بإنشاء usertree"/web2c" و usertree"/tlpkg/tlpobj"، وملف usertree"/tlpkg/texlive.tlpdb" صغير. عند هذه النقطة، يمكنك إخبار "tlmgr" بتنفيذ الإجراءات (المدعومة) عن طريق إضافة خيار سطر الأوامر "--usermode".

في وضع المستخدم، يحتوي الملف usertree"/tlpkg/texlive.tlpdb" فقط على الحزم التي تم تثبيتها في شجرة المستخدم باستخدام "tlmgr"، بالإضافة إلى خيارات إضافية من الحزمة ``الافتراضية'' "00texlive.installation" (على غرار "texlive.tlpdb" للتثبيت الرئيسي).

جميع الإجراءات على الحزم في وضع المستخدم لا يمكن تنفيذها إلا على الحزم المعروفة بأنها "قابلة للنقل". هذا يستثني جميع الحزم التي تحتوي على ملفات تنفيذية وعدد قليل من الحزم الأساسية الأخرى. من بين حوالي 2500 حزمة موجودة حاليًا في TeX Live، الغالبية العظمى قابلة للنقل ويمكن تثبيتها في شجرة المستخدم.

وصف التغييرات على الإجراءات في وضع المستخدم:

تثبيت وضع المستخدم

في وضع المستخدم، يتحقق إجراء "install" من أن الحزمة وجميع التبعيات إما قابلة للنقل أو مثبتة بالفعل في التثبيت الرئيسي للنظام. إذا كان الأمر كذلك، فإنه يقوم بفك ضغط جميع الحاويات التي سيتم تثبيتها في شجرة المستخدم (لتكرار، وهو إما "TEXMFHOME" أو قيمة "--usertree") ويضيف الحزم المعنية إلى "texlive.tlpdb" الخاصة بشجرة المستخدم (مع إنشائها إذا لزم الأمر).

حالياً، تثبيت مجموعة في وضع المستخدم يقوم بتثبيت جميع الحزم التابعة، ولكن على عكس الوضع العادي، فإنه *لا* يقوم بتثبيت المجموعات التابعة. على سبيل المثال، في الوضع العادي، سيقوم "tlmgr install collection-context" بتثبيت "collection-basic" ومجموعات أخرى، بينما في وضع المستخدم، يتم تثبيت الحزم المذكورة في "collection-context" *فقط*.

إذا تم تثبيت حزمة تحتوي على ملفات خرائط في وضع المستخدم، يتم عمل نسخة احتياطية من ملف "updmap.cfg" الخاص بالمستخدم في "USERTREE/web2c/"، ثم يتم إعادة إنشاء هذا الملف من قائمة الحزم المثبتة.

وضع المستخدم النسخ الاحتياطي، الاستعادة، الإزالة، التحديث

في وضع المستخدم، تتحقق هذه الإجراءات من أن جميع الحزم المراد معالجتها مثبتة في شجرة المستخدم قبل المتابعة؛ بخلاف ذلك، فإنها تتصرف تمامًا كما في الوضع العادي.

وضع المستخدم الإنشاء، الخيار، الورقة

في وضع المستخدم، تعمل هذه الإجراءات فقط على ملفات تكوين شجرة المستخدم و/أو "texlive.tlpdb".

سجلات وضع المستخدم

في وضع المستخدم، يتم كتابة "tlmgr.log" و "tlmgr-commands.log" في الدليل "TEXMFVAR/web2c/" بدلاً من "TEXMFSYSVAR/web2c/".

مستودعات متعددة

يحتوي مستودع TeX Live الرئيسي على مجموعة واسعة من الحزم. ومع ذلك، يمكن أن تكون المستودعات المحلية الإضافية مفيدة لتوفير الموارد المثبتة محليًا، مثل الخطوط الاحتكارية وأنماط الشركة. أيضًا، تقوم مستودعات الحزم البديلة بتوزيع الحزم التي لا يمكن أو لا ينبغي تضمينها في TeX Live، لأي سبب كان.

الطريقة الأبسط والأكثر موثوقية هي تعيين مصدر التثبيت مؤقتًا إلى أي مستودع (باستخدام خيارات سطر الأوامر "-repository" أو "option repository")، وتنفيذ عملياتك.

ومع ذلك، عند استخدام مستودعات متعددة لفترة طويلة، يصبح التبديل بينها صريحًا غير ملائم. وبالتالي، من الممكن إخبار "tlmgr" عن المستودعات الإضافية التي تريد استخدامها. الأمر الأساسي هو "tlmgr repository add". يشرح بقية هذا القسم المزيد.

عند استخدام مستودعات متعددة، يجب أن يكون أحدها هو المستودع الرئيسي، الذي يوزع معظم الحزم المثبتة. عندما تنتقل من تثبيت بمستودع واحد إلى تثبيت بمستودعات متعددة، سيتم تعيين المستودع السابق الوحيد كمستودع رئيسي.

افتراضيًا، حتى لو تم تكوين مستودعات متعددة، لا تزال الحزم تُثبت *فقط* من المستودع الرئيسي. وبالتالي، فإن مجرد إضافة مستودع ثانٍ لا يُمكّن فعليًا تثبيت أي شيء منه. تحتاج أيضًا إلى تحديد الحزم التي يجب أخذها من المستودع الجديد، عن طريق تحديد قواعد "تثبيت" (pinning) تسمى، سيتم شرحها لاحقًا.

التثبيت (Pinning)

عندما يتم تثبيت حزمة "foo" لمستودع، فإن حزمة "foo" في أي مستودع آخر، حتى لو كان لها رقم مراجعة أعلى، لن تعتبر مرشحًا للتثبيت.

كما ذكرنا أعلاه، افتراضيًا كل شيء مثبت للمستودع الرئيسي. دعنا نستعرض الآن مثالًا على إعداد مستودع ثانٍ وتمكين التحديثات لحزمة منه.

أولاً، تحقق من أن لدينا دعمًا لمستودعات متعددة، ولدينا مستودع واحد فقط ممكّن (كما هو الحال افتراضيًا):

$ tlmgr repository list
List of repositories (with tags if set):
  /var/www/norbert/tlnet

حسنًا. لنضف مستودع "tlcontrib" (هذا مستودع حقيقي مستضاف على http://contrib.texlive.info) مع العلامة "tlcontrib":

$ tlmgr repository add http://contrib.texlive.info/current tlcontrib

تحقق من قائمة المستودعات مرة أخرى:

$ tlmgr repository list
List of repositories (with tags if set):
   http://contrib.texlive.info/current (tlcontrib)
   /var/www/norbert/tlnet (main)

الآن نحدد إدخال تثبيت لأخذ الحزمة "classico" من "tlcontrib":

$ tlmgr pinning add tlcontrib classico

تحقق من أنه يمكننا العثور على "classico":

$ tlmgr show classico
package:     classico
...
shortdesc:   URW Classico fonts
...

- تثبيت "classico":

$ tlmgr install classico
tlmgr: package repositories:
...
[1/1,  ??:??/??:??] install: classico @tlcontrib [737k]

في الإخراج هنا، يمكنك رؤية أن حزمة "classico" تم تثبيتها من المستودع "tlcontrib" ( @tlcontrib).

أخيرًا، يدعم "tlmgr pinning" أيضًا إزالة حزم معينة أو كلها من مستودع معين:

$ tlmgr pinning remove tlcontrib classico # remove just classico
$ tlmgr pinning remove tlcontrib --all    # take nothing from tlcontrib

يتم تقديم ملخص لإجراءات "tlmgr pinning" أعلاه.

واجهة رسومية لـ TLMGR

تتطلب الواجهة الرسومية لـ "tlmgr" Perl/Tk https://search.cpan.org/search?query=perl%2Ftk. بالنسبة لأنظمة Unix، يجب تثبيت Perl/Tk (وكذلك Perl بالطبع) خارج TL. يحتوي https://tug.org/texlive/distro.html#perltk على قائمة للأوامر لبعض التوزيعات. بالنسبة لنظام Windows، لم تعد الوحدات اللازمة متوفرة ضمن TeX Live، لذا ستحتاج إلى توفير Perl خارجي يتضمنها.

نحن نتحدث هنا عن الواجهة الرسومية المدمجة في tlmgr نفسه، وليس عن واجهات tlmgr الرسومية الأخرى، وهي: tlshell (مبنية على Tcl/Tk)، tlcockpit (مبنية على Java)، وعلى أجهزة Mac فقط، TeX Live Utility. يتم استدعاؤها كبرامج منفصلة.

يتم بدء وضع الواجهة الرسومية لـ tlmgr بالاستدعاء "tlmgr gui"؛ بافتراض أن Tk يمكن تحميله، سيتم عرض الواجهة الرسومية. تحتوي النافذة الرئيسية على شريط قوائم، العرض الرئيسي، ومنطقة الحالة حيث يتم عرض الرسائل التي تظهر عادةً على وحدة التحكم.

ضمن العرض الرئيسي، توجد ثلاثة أجزاء رئيسية: منطقة "إعدادات العرض"، قائمة الحزم، وأزرار الإجراءات.

أيضًا، في الجزء العلوي الأيمن يتم عرض المستودع المحمل حاليًا؛ يعمل هذا أيضًا كزر وعند النقر عليه سيحاول تحميل المستودع الافتراضي. لتحميل مستودع مختلف، انظر عنصر القائمة "tlmgr".

أخيرًا، توفر منطقة الحالة في أسفل النافذة معلومات إضافية حول ما يجري.

منطقة قائمة الحزم

المنطقة الثانية من العرض الرئيسي تسرد جميع الحزم المثبتة. إذا تم تحميل مستودع، فسيتم أيضًا سرد تلك المتاحة ولكن غير المثبتة.

النقر المزدوج على سطر الحزمة يفتح نافذة معلومات بتفاصيل إضافية: الوصف الطويل، الملفات المتضمنة، إلخ.

يتكون كل سطر في قائمة الحزم من العناصر التالية:

خانة اختيار
تستخدم لتحديد حزم معينة؛ تعمل بعض أزرار الإجراءات (انظر أدناه) فقط على الحزم المحددة.
اسم الحزمة
اسم (معرف) الحزمة كما هو موضح في قاعدة البيانات.
المراجعة المحلية (والإصدار)
إذا كانت الحزمة مثبتة، فسيتم عرض رقم مراجعة TeX Live للحزمة المثبتة. إذا كان هناك إصدار كتالوج محدد في قاعدة البيانات لهذه الحزمة، فسيتم عرضه بين قوسين. ومع ذلك، فإن إصدار الكتالوج، على عكس مراجعة TL، غير مضمون ليعكس ما هو مثبت بالفعل.
المراجعة البعيدة (والإصدار)
إذا تم تحميل مستودع، فسيتم عرض مراجعة الحزمة في المستودع (إذا كانت موجودة). كما هو الحال مع العمود المحلي، إذا تم توفير إصدار كتالوج، فسيتم عرضه. وكما هو الحال مع العمود المحلي، قد يكون إصدار الكتالوج قديمًا.
وصف مختصر
الوصف المختصر للحزمة.

أزرار إجراءات العرض الرئيسي

أسفل قائمة الحزم توجد عدة أزرار:

تحديث الكل المثبت
هذا يستدعي "tlmgr update --all"، أي يحاول تحديث جميع الحزم المتاحة. أسفل هذا الزر يوجد تبديل للسماح بإعادة تثبيت الحزم التي تمت إزالتها سابقًا كجزء من هذا الإجراء.

الأزرار الأربعة الأخرى تعمل فقط على الحزم المحددة، أي تلك التي تم تحديد خانة الاختيار في بداية سطر الحزمة.

تحديث
تحديث الحزم المحددة فقط.
تثبيت
تثبيت الحزم المحددة؛ تعمل مثل "tlmgr install"، أي أنها تثبت أيضًا التبعيات. وبالتالي، فإن تثبيت مجموعة يثبت جميع حزمها المكونة.
إزالة
يزيل الحزم المحددة؛ تعمل مثل "tlmgr remove"، أي أنها ستزيل أيضًا تبعيات المجموعات (ولكن ليس تبعيات الحزم العادية).
نسخ احتياطي
يقوم بعمل نسخة احتياطية من الحزم المحددة؛ تعمل مثل "tlmgr backup". يتطلب هذا الإجراء تعيين الخيار "backupdir" (انظر "Options -" General>).

شريط القوائم

يمكن العثور على الإدخالات التالية في شريط القوائم:

قائمة "tlmgr"
تقوم العناصر هنا بتحميل مستودعات مختلفة: الافتراضية كما هو محدد في قاعدة بيانات TeX Live، مستودع الشبكة الافتراضي، المستودع المحدد في سطر الأوامر (إن وجد)، وواحد تم إدخاله يدويًا بشكل عشوائي. تحتوي أيضًا على عملية "quit" الضرورية.
قائمة "Options"
توفر الوصول إلى مجموعات متعددة من الخيارات: "Paper" (تكوين أحجام الورق الافتراضية)، "Platforms" (فقط على Unix، تكوين المنصات المدعومة/المثبتة)، "GUI Language" (تحديد اللغة المستخدمة في واجهة المستخدم الرسومية)، و "General" (كل شيء آخر).

هناك أيضًا العديد من التبديلات هنا. الأول هو "Expert options"، وهو محدد افتراضيًا. إذا قمت بإيقاف تشغيله، في المرة التالية التي تبدأ فيها واجهة المستخدم الرسومية، سيتم عرض شاشة مبسطة تعرض الوظائف الأكثر أهمية فقط. يتم حفظ هذا الإعداد في ملف تكوين "tlmgr"؛ انظر "ملف التكوين لـ TLMGR" للحصول على التفاصيل.

التبديلات الأخرى كلها معطلة افتراضيًا: لإخراج التصحيح، لتعطيل التثبيت التلقائي للحزم الجديدة، ولتعطيل الإزالة التلقائية للحزم المحذوفة من الخادم. قد يؤدي اللعب بالخيارات حول ما تم تثبيته أو لم يتم تثبيته إلى تثبيت TeX Live غير متناسق؛ على سبيل المثال، عندما يتم إعادة تسمية حزمة.

قائمة "Actions"
توفر الوصول إلى إجراءات متعددة: تحديث قاعدة بيانات أسماء الملفات (المعروفة أيضًا باسم "ls-R"، "mktexlsr"، "texhash")، إعادة بناء جميع التنسيقات ("fmtutil-sys --all")، تحديث قاعدة بيانات خرائط الخطوط ("updmap-sys")، استعادة من نسخة احتياطية لحزمة، واستخدام الروابط الرمزية في أدلة النظام (ليس على Windows).

الإجراء الأخير هو إزالة تثبيت TeX Live بالكامل (ليس على Windows أيضًا).

قائمة "Help"
توفر الوصول إلى دليل TeX Live (وأيضًا على الويب على https://tug.org/texlive/doc.html) وصندوق "حول" المعتاد.

تعيين لون المقدمة.
"-geometry" geomspec
تعيين هندسة X، على سبيل المثال، "tlmgr gui -geometry 1024x512-0+0" ينشئ النافذة بالحجم (تقريبًا) المحدد في الزاوية العلوية اليمنى للشاشة.
"-xrm" xresource
تمرير سلسلة موارد X التعسفية xresource.

يتم التعرف على عدد قليل من الخيارات الغامضة الأخرى ولكن لم يتم ذكرها هنا. راجع وثائق Perl/Tk (https://search.cpan.org/perldoc?Tk) للحصول على القائمة الكاملة، وأي وثائق X للحصول على معلومات عامة.

مخرجات قابلة للقراءة آليًا

مع الخيار "--machine-readable" ، تكتب "tlmgr" إلى stdout بتنسيق ثابت موجه بالأسطر موصوف هنا، وتكتب الرسائل المعلوماتية المعتادة للاستهلاك البشري إلى stderr (عادةً ما تكتب إلى stdout). الفكرة هي أن برنامجًا يمكنه الحصول على جميع المعلومات التي يحتاجها عن طريق قراءة stdout.

حاليا، ينطبق هذا الخيار فقط على إجراءات التحديث والتثبيت و "option".

مخرجات "update" و "install" القابلة للقراءة آليًا

تنسيق المخرجات هو كالتالي:

fieldname "\t" value
...
"end-of-header"
pkgname status localrev serverrev size runtime esttot
...
"end-of-updates"
other output from post actions, not in machine readable form

قسم العنوان حاليًا به حقلان: "location-url" (مصدر المستودع الذي يتم سحب التحديثات منه)، و "total-bytes" (إجمالي عدد البايتات التي سيتم تنزيلها).

حقلا localrev و serverrev لكل حزمة هما أرقام المراجعة في التثبيت المحلي والمستودع الخادم، على التوالي. حقل size هو عدد البايتات التي سيتم تنزيلها، أي حجم الملف المضغوط للتثبيت عبر الشبكة، وليس الحجم بعد فك الضغط. حقلا runtime و esttot موجودان فقط للحزم التي تم تحديثها أو تثبيتها تلقائيًا، ويحتويان على الوقت المنقضي الحالي منذ بدء التثبيت/التحديث والوقت الإجمالي المقدر.

قد تكون نهايات الأسطر إما LF أو CRLF اعتمادًا على النظام الأساسي الحالي.

"location-url" location
قد يكون location عنوان URL (بما في ذلك "file:///foo/bar/...")، أو اسم دليل ("/foo/bar"). إنه مستودع الحزم الذي تم سحب معلومات الحزمة الجديدة منه.
"total-bytes" count
count هو ببساطة رقم عشري، وهو مجموع أحجام جميع الحزم التي تحتاج إلى تحديث أو تثبيت (والتي يتم سردها لاحقًا).

ثم يأتي سطر يحتوي فقط على النص الحرفي "end-of-header".

كل سطر تالٍ حتى سطر يحتوي على النص الحرفي "end-of-updates" يبلغ عن حزمة واحدة. الحقول في كل سطر مفصولة بعلامة جدولة. إليك الحقول.

اسم الحزمة
معرف حزمة TeX Live، مع لاحقة نظام أساسي محتملة للملفات التنفيذية. على سبيل المثال، يتم تقديم "pdftex" و "pdftex.i386-linux" كحزمتين منفصلتين، واحدة في كل سطر.
الحالة
تمثل الحالة الحالية للحزمة. القيم الممكنة هي:
new
هذه حزمة جديدة سيتم تثبيتها.
upd
هذه حزمة موجودة سيتم تحديثها.
same
الحزمة موجودة بالفعل وهي محدثة.
obsolete
الحزمة غير موجودة في المستودع الحالي.
auto
تم تثبيت الحزمة تلقائيًا كاعتمادية.
localrev
رقم مراجعة الحزمة في تثبيتك المحلي.
serverrev
رقم مراجعة الحزمة في المستودع الذي يتم سحب التحديثات منه.
size
حجم الحزمة بالبايت التي سيتم تنزيلها (ملف مضغوط).
runtime
الوقت الذي استغرقه تحميل وتثبيت هذه الحزمة، بالثواني.
esttot
الوقت الإجمالي المقدر لتنزيل وتثبيت جميع الحزم المتبقية.

في نهاية المخرجات، تكون هناك رسالة إلى stderr (إذا تم استخدام "--machine-readable") تشير إلى إجمالي عدد البايتات التي تم تنزيلها، أو الإجمالي إذا لم تكن هناك تحديثات.

مخرجات "option" القابلة للقراءة آليًا

عند استخدام الخيار "--machine-readable" مع الأمر "option"، سيتم طباعة قائمة بتعيينات اسم الخيار إلى قيمته الحالية إلى stdout. على سبيل المثال:

optionname value
...
end-of-options

لا يتم طباعة أي شيء آخر. هذا يسمح لبرنامج خارجي بفحص جميع خيارات texlive-local configuration.

status

The status of the package update. One character, as follows:
"d"
The package was removed on the server.
"f"
The package was removed in the local installation, even though a collection depended on it. (E.g., the user ran "tlmgr remove --force".)
"u"
Normal update is needed.
"r"
Reversed non-update: the locally-installed version is newer than the version on the server.
"a"
Automatically-determined need for installation, the package is new on the server and is (most probably) part of an installed collection.
"i"
Package will be installed and isn't present in the local installation (action install).
"I"
Package is already present but will be reinstalled (action install).
localrev
The revision number of the installed package, or "-" if it is not present locally.
serverrev
The revision number of the package on the server, or "-" if it is not present on the server.
size
The size in bytes of the package on the server. The sum of all the package sizes is given in the "total-bytes" header field mentioned above.
runtime
The run time since start of installations or updates.
esttot
The estimated total time.

Machine-readable "option" output

The output format is as follows:

key "\t" value

If a value is not saved in the database the string "(not set)" is shown.

If you are developing a program that uses this output, and find that changes would be helpful, do not hesitate to write the mailing list.

ENVIRONMENT VARIABLES

"tlmgr" uses many of the standard TeX environment variables, as reported by, e.g., "tlmgr conf" ("conf").

In addition, for ease in scripting and debugging, "tlmgr" looks for the following environment variables. These are not of interest for normal user installations.

"TEXLIVE_COMPRESSOR"
This variable allows selecting a different compressor program for backups and intermediate rollback containers. The order of selection is:
1.
If the environment variable "TEXLIVE_COMPRESSOR" is defined, use it; abort if it doesn't work. Possible values: "lz4", "gzip", "xz". The necessary options are added internally.
2.
If lz4 is available (either from the system or TL) and working, use that.
3.
If gzip is available (from the system) and working, use that.
4.
If xz is available (either from the system or TL) and working, use that.

lz4 and gzip are faster in creating tlmgr's local backups, hence they are preferred. The unconditional use of xz for the tlnet containers is unaffected, to minimize download sizes.

"TEXLIVE_DOWNLOADER"
"TL_DOWNLOAD_PROGRAM"
"TL_DOWNLOAD_ARGS"
These options allow selecting different download programs then the ones automatically selected by the installer. The order of selection is:
1.
If the environment variable "TEXLIVE_DOWNLOADER" is defined, use it; abort if the specified program doesn't work. Possible values: "lwp", "curl", "wget". The necessary options are added internally.
2.
If the environment variable "TL_DOWNLOAD_PROGRAM" is defined (can be any value), use it together with "TL_DOWNLOAD_ARGS"; abort if it doesn't work.
3.
If LWP is available and working, use that (by far the most efficient method, as it supports persistent downloads).
4.
If curl is available (from the system) and working, use that.
5.
If wget is available (either from the system or TL) and working, use that.

TL provides "wget" binaries for platforms where necessary, so some download method should always be available.

"TEXLIVE_PREFER_OWN"
By default, compression and download programs provided by the system, i.e., found along "PATH" are preferred over those shipped with TeX Live.

This can create problems with systems that are too old, and so can be overridden by setting the environment variable "TEXLIVE_PREFER_OWN" to 1. In this case, executables shipped with TL will be preferred.

Extra compression/download programs not provided by TL, such as gzip, lwp, and curl, are still checked for on the system and used if available, per the above. "TEXLIVE_PREFER_OWN" only applies when the program being checked for is shipped with TL, namely the lz4 and xz compressors and wget downloader.

Exception: on Windows, the "tar.exe" shipped with TL is always used, regardless of any setting.
