Try__Tiny(3pm)

الحزمة: perl-try-tiny

التراخيص: MIT

Try::Tiny(3) توثيق Perl مقدم من المستخدم Try::Tiny(3)

الاسم

Try::Tiny - الحد الأدنى من try/catch مع الحفاظ السليم لـ $@

الإصدار

الإصدار 0.32

الملخص

يمكنك استخدام وظائفي "try" و "catch" من Try::Tiny لتوقع ومعالجة ظروف الخطأ، مع تجنب حيل Perl والأخطاء الشائعة:

# التعامل مع الأخطاء باستخدام معالج catch
try {
  die "foo";
}
catch {
  warn "caught error: $_"; # ليس $@
};

يمكنك أيضًا استخدامه كـ "eval" مستقل لالتقاط أي ظروف خطأ وتجاهلها. من الواضح أن هذا إجراء متطرف لا ينبغي اتخاذه بخفة:

# إسكات الأخطاء فقط
try {
  die "foo";
};

الوصف

توفر هذه الوحدة تعليمات try/catch بحد أدنى من التعليمات البرمجية التي تقلل من الأخطاء الشائعة مع كتل eval، ولا شيء آخر.

هذا على عكس TryCatch، الذي يقدم بناء جملة لطيف ويتجنب إضافة طبقة مكدس إضافية، ويدعم استدعاء "return" من كتلة "try" للإرجاع من الروتين الفرعي الأصلي. هذه الوظائف الإضافية لها تكلفة تبعيات، مثل Devel::Declare و Scope::Upper، والتي يمكن أن تكون مزعجة في بعض الأحيان، واستخدام عوامل تصفية catch يستخدم قيود أنواع Moose، والتي قد لا تكون مرغوبة.

التركيز الأساسي لهذه الوحدة هو توفير معالجة بسيطة وموثوقة للأخطاء لأولئك الذين يواجهون صعوبة في تثبيت TryCatch، ولكنهم ما زالوا يرغبون في كتابة كتل eval صحيحة دون الحاجة إلى كتابة 5 أسطر من التعليمات البرمجية في كل مرة.

تم تصميمه ليعمل بشكل صحيح مع مراعاة الحالات المتطرفة في حواف الأنماط (انظر "BACKGROUND") وليكون متوافقًا مع أي أسلوب لقيم الخطأ (سلاسل نصية بسيطة، مراجع، كائنات، كائنات معاد تعريفها، إلخ).

إذا انتهت كتلة "try" من التنفيذ، فإنها تُرجع قيمة آخر تعليمة تم تنفيذها في كتلة "catch"، إن وجدت. خلاف ذلك، تُرجع "undef" في سياق قياسي أو القائمة الفارغة في سياق قائمة. الأمثلة التالية تعين "bar" إلى $x:

my $x = try { die "foo" } catch { "bar" };
my $x = try { die "foo" } || "bar";
my $x = (try { die "foo" }) // "bar";
my $x = eval { die "foo" } || "bar";

يمكنك إضافة كتل "finally"، مما ينتج عنه ما يلي:

my $x;
try { die 'foo' } finally { $x = 'bar' };
try { die 'foo' } catch { warn "Got a die: $_" } finally { $x = 'bar' };

يتم تنفيذ كتل "finally" دائمًا، مما يجعلها مناسبة لتعليمات التنظيف التي لا يمكن إدارتها باستخدام local. يمكنك إضافة العديد من كتل "finally" كما تريد إلى كتلة "try".

ملاحظة: إضافة كتلة "finally" دون وجود كتلة "catch" سابقة تلغي أي أخطاء. هذه الميزة متوافقة مع استخدام "eval" مستقل، ولكنها ليست متوافقة مع أنماط "try"/"finally" الموجودة في لغات البرمجة الأخرى، مثل Java، Python، JavaScript أو C#. إذا تعلمت نمط "try"/"finally" من إحدى هذه اللغات، فكن على دراية بهذا الاختلاف.

تصدير

يتم تصدير جميع الوظائف افتراضيًا بواسطة Exporter.

إذا كنت بحاجة إلى إعادة تسمية "try" أو "catch" أو "finally"، ففكر في استخدام Sub::Import للحصول على مرونة Sub::Exporter.

try (&;@)
يأخذ روتينًا فرعيًا إلزاميًا "try"، وروتينًا فرعيًا اختياريًا "catch"، وروتينًا فرعيًا "finally".

يتم تقييم الروتين الفرعي الإلزامي في سياق كتلة "eval".

إذا لم يكن هناك خطأ، يتم إرجاع قيمة الروتين الفرعي الأول، مع الحفاظ على سياق القائمة/القياسي.

إذا كان هناك خطأ وتم تحديد الروتين الفرعي "catch"، فسيتم استدعاؤه مع الخطأ في $_ (موضعي) كوسيط أول ووحيد لهذه الكتلة.

لا يحتوي $@ على الخطأ. داخل كتلة "catch"، له نفس قيمة ما قبل تنفيذ كتلة "try".

ملاحظة: قد يكون الخطأ خاطئًا، ولكن إذا حدث، فسيتم استدعاء كتلة "catch" على أي حال.

بمجرد الانتهاء من التنفيذ، سيتم تنفيذ كتلة "finally"، إن وجدت.

catch (&;@)
مقصود للاستخدام كوسيط ثانٍ لـ "try".

تُرجع مرجعًا إلى الروتين الفرعي الذي تم تمريره، ولكنها تقوم بتغليفه كـ "Try::Tiny::Catch" مما يسمح لـ try بتحديد ما يجب فعله بهذه الكتلة المرجعية بشكل صحيح.

catch { ... }

في كتلة "catch"، يتم تخزين الخطأ الملتقط في $_، بينما تظل قيمة $@ السابقة متاحة للاستخدام. قد تكون هذه القيمة ذات مغزى أو لا، اعتمادًا على ما حدث قبل تنفيذ كتلة "try"، ولكن قد يكون من الجيد الاحتفاظ بها في مكدس الأخطاء.

لالتقاط $@ عند طرح أخطاء جديدة (أي Class::Throwable)، تحتاج إلى:

local $@ = $_;
finally (&;@)
try     { ... }
catch   { ... }
finally { ... };

أو

try     { ... }
finally { ... };

أو حتى

try     { ... }
finally { ... }
catch   { ... };

مقصود كوسيط ثانٍ أو ثالث لـ "try". تُنفذ كتل "finally" دائمًا في حالة نجاح "try" أو إذا تم تنفيذ "catch". هذا يسمح بتحديد تعليمات التنظيف التي لا يمكن تحقيقها باستخدام local()، على سبيل المثال، إغلاق معالج ملف.

عند استدعائها، يتم تمرير الخطأ الملتقط إلى كتلة "finally". إذا لم يتم التقاط أي خطأ، فلن يتم تمرير شيء. (لاحظ أن كتلة "finally" لا تضع $_ في سياق محلي مع الخطأ، لأنه في كتلة "catch" لا توجد طريقة لمعرفة ما إذا كان "$_ == undef" يعني عدم وجود أخطاء. بعبارة أخرى، الكود التالي يفعل ما تتوقعه:

try {
  die_sometimes();
} catch {
  # ... كود يتم تنفيذه في حالة وجود خطأ
} finally {
  if (@_) {
    print "The try block died with: @_\n";
  } else {
    print "The try block ran without error.\n";
  }
};

عليك القيام بمعالجة الأخطاء الخاصة بك في كتلة "finally". لن يقوم "Try::Tiny" بأي شيء تجاه الأخطاء التي تأتي من التعليمات البرمجية الموجودة في هذه الكتل.

علاوة على ذلك، لا يمكن التقاط الاستثناءات في كتل "finally" ولا يمكنها التأثير على تنفيذ برنامجك. هذا بسبب قيود حراس السياق المستندة إلى "DESTROY"، والتي يتم تنفيذ "finally" فوقها. قد يتغير هذا في الإصدارات المستقبلية من "Try::Tiny".

أيضًا، لا يمكن التقاط الاستثناءات في كتل "finally" ولا يمكنها التأثير على تنفيذ برنامجك. هذا بسبب قيود حراس السياق المستندة إلى "DESTROY"، والتي يتم تنفيذ "finally" فوقها. قد يتغير هذا في الإصدارات المستقبلية من "Try::Tiny".
