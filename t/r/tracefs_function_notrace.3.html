tracefs_function_notrace(3)

الحزمة: libtracefs

التراخيص: GPL-2.0-only, LGPL-2.1-only

LIBTRACEFS(3) دليل libtracefs LIBTRACEFS(3)

الاسم

tracefs_function_filter, tracefs_function_notrace, tracefs_filter_functions - وظائف لتعديل عوامل تصفية تتبع الوظائف

ملخص

#include <tracefs.h>
int tracefs_function_filter(struct tracefs_instance *instance, const char *filter, const char *module, int flags);
int tracefs_function_notrace(struct tracefs_instance *instance, const char *filter, const char *module, int flags);
int tracefs_filter_functions(const char *filter, const char *module, char ***list);

الوصف

يمكن استخدام tracefs_function_filter و tracefs_function_notrace لتحديد وظائف نواة Linux التي سيتم تتبعها بواسطة متتبعي الوظائف ورسم بياني للوظائف. تحدد tracefs_function_filter قائمة بالوظائف التي يمكن تتبعها. تحدد tracefs_function_notrace قائمة بالوظائف التي لن يتم تتبعها. إذا كانت الوظيفة موجودة في كلتا القائمتين، فلن يتم تتبعها.

تأخذ هذه الوظائف instance ، والتي يمكن أن تكون NULL للتتبع العلوي، filter ، وهي سلسلة تمثل عامل تصفية يجب تطبيقه لتحديد الوظائف التي سيتم تتبعها، module ، لتحديد عامل التصفية على وحدة نمطية معينة (أو NULL لتصفية جميع الوظائف)، flags التي تحمل مقابض تحكم حول كيفية التعامل مع عوامل التصفية (انظر القسم FLAGS أدناه).

تقوم tracefs_filter_functions بإرجاع قائمة بالوظائف التي يمكن تصفيتها عبر filter و module المقدمة. إذا كان كل من filter و module هما NULL، فسيتم إرجاع جميع الوظائف المتاحة التي يمكن تصفيتها. عند النجاح، يجب تحرير list باستخدام tracefs_list_free()(3).

قد يكون filter إما مطابقًا مباشرًا لوظيفة، أو نمطًا عامًا (glob)، أو تعبيرًا عاديًا (regex(3)). النمط العام هو حيث يطابق * صفرًا أو أكثر من الأحرف، و ? يطابق صفرًا أو حرفًا واحدًا، و . يطابق فترة فقط. إذا تم تحديد أن filter هو تعبير عادي (حيث يحتوي على أي شيء بخلاف الأحرف الأبجدية الرقمية، أو .، *، ?) فسيتم معالجة filter كتعبير عادي (regex(3)) باتباع قواعد regex(3)، و . ليس فترة، ولكنه سيطابق أي حرف واحد. لفرض تعبير عادي، قم إما بوضع بادئة لـ filter بـ ^ أو ألحقها بـ $ حيث أن filter يقوم بمطابقات كاملة للوظائف على أي حال.

إذا تم تعيين module وكان filter هو NULL، فسيشير هذا إلى نفس الشيء مثل filter يساوي "*". مما سيمكن جميع الوظائف لوحدة نمطية معينة module. بخلاف ذلك، قد يكون filter NULL إذا كان الاستدعاء السابق لـ tracefs_function_filter() مع نفس instance يحتوي على TRACEFS_FL_CONTINUE تم تعيينه وهذا الاستدعاء لا يفعل ذلك. هذا مفيد ببساطة لتثبيت عوامل التصفية السابقة. قد يكون أيضًا NULL إذا تم تعيين TRACEFS_FL_RESET ولم يكن الاستدعاء السابق يحتوي على نفس instance وتم تعيين TRACEFS_FL_CONTINUE. هذا مفيد لمجرد مسح عامل التصفية.

الأعلام

قد يحتوي المعامل flags على ما يلي، أو يكون صفرًا.

TRACEFS_FL_RESET : إذا كانت flags تحتوي على TRACEFS_FL_RESET، فسيؤدي ذلك إلى مسح عوامل التصفية التي تم تعيينها حاليًا قبل تطبيق filter. بخلاف ذلك، يتم إضافة filter إلى المجموعة الحالية من عوامل التصفية الممكّنة بالفعل. إذا تم تعيين هذا العلم وكان الاستدعاء السابق لـ tracefs_function_filter() يحتوي على نفس instance وتم تعيين علم TRACEFS_FL_CONTINUE، فستفشل الوظيفة بإرجاع -1 وتعيين errno على EBUSY.

TRACEFS_FL_CONTINUE : إذا كانت flags تحتوي على TRACEFS_FL_CONTINUE، فلن تسري filter بعد استدعاء ناجح لـ tracefs_function_filter(). هذا يسمح باستدعاءات متعددة لـ tracefs_function_filter() لتحديث وظيفة عامل التصفية ثم استدعاء واحد (بدون علم TRACEFS_FL_CONTINUE معين) لتثبيت جميع عوامل التصفية. يمكن استدعاؤه عدة مرات لإضافة المزيد من عوامل التصفية. سيؤدي الاستدعاء بدون تعيين هذا العلم إلى تثبيت التغييرات قبل الإرجاع (إذا تمت مطابقة filter المقدم بنجاح). سيفشل استدعاء tracefs_function_filter() بعد استدعاء كان يحتوي على علم TRACEFS_FL_CONTINUE لنفس المثيل إذا تم تعيين علم TRACEFS_FL_RESET، حيث أن علم إعادة التعيين قابل للتطبيق فقط على عامل التصفية الأول الذي سيتم إضافته قبل التثبيت.

TRACEFS_FL_FUTURE : إذا كانت flags تحتوي على TRACEFS_FL_FUTURE وكان module يحتوي على سلسلة نصية لوحدة نمطية، فإذا لم تكن الوحدة النمطية محملة، فستحاول كتابة عامل التصفية مع الوحدة النمطية في ملف عامل التصفية. بدءًا من Linux v4.13، يمكن إضافة وظائف الوحدات النمطية إلى عامل التصفية قبل تحميلها. سيتم تخزين عامل التصفية مؤقتًا، وعند تحميل الوحدة النمطية، سيتم تعيين عامل التصفية قبل تنفيذ الوحدة النمطية، مما يسمح بتتبع وظائف تهيئة الوحدة النمطية. سيعمل هذا فقط إذا لم يكن filter تعبيرًا عاديًا.

قيمة الإرجاع

بالنسبة لـ tracefs_function_filter() و tracefs_function_notrace()، يعني إرجاع 0 النجاح. إذا كان هناك خطأ ولكن لم يبدأ التصفية، فسيتم إرجاع 1. إذا بدأت التصفية ولكن حدث خطأ، فسيتم إرجاع -1. قد تكون حالة التصفية في حالة غير معروفة.

إذا تم تعيين TRACEFS_FL_CONTINUE، وتم إرجاع 0 أو -1، فيجب إجراء استدعاء آخر لـ tracefs_function_filter() بدون تعيين TRACEFS_FL_CONTINUE لتثبيت (وإغلاق) التصفية.

بالنسبة لـ tracefs_filter_functions()، يعني إرجاع 0 النجاح، ويتم ملء المعامل list بقائمة بأسماء الوظائف التي تطابقت مع filter و module. list هي مصفوفة سلاسل، حيث يكون مؤشر السلسلة الأخير في المصفوفة NULL. يجب تحرير list باستخدام tracefs_list_free(). عند الفشل، يتم إرجاع قيمة سالبة، ويتم تجاهل list.

الأخطاء

يمكن أن تفشل tracefs_function_filter() بالأخطاء التالية:

EINVAL عامل التصفية غير صالح أو لم يطابق أي وظائف.

EBUSY تم استدعاء الاستدعاء السابق لـ tracefs_function_filter() بنفس المثيل وتم تعيين TRACEFS_FL_CONTINUE وكان الاستدعاء الحالي يحتوي على TRACEFS_FL_RESET معين.

قد تحدث أخطاء أخرى ناتجة عن استدعاءات النظام الداخلية.
