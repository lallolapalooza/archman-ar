الوصف

الأحداث الاصطناعية هي أحداث ديناميكية يتم إنشاؤها عن طريق مطابقة حدثين آخرين يؤديان إلى حدث اصطناعي. أحد الأحداث هو حدث البداية الذي يتم تسجيل حقل منه، وعند تنفيذ الحدث الثاني، إذا كان يحتوي على حقل (أو حقول) يطابق حقل (أو حقول) حدث البداية، فسيؤدي ذلك إلى تشغيل الحدث الاصطناعي. قد يتم تمرير قيم الحقول بخلاف الحقول المطابقة من حدث البداية إلى حدث النهاية لإجراء حسابات عليها، أو ببساطة لتمريرها كمعامل للحدث الاصطناعي.

أحد حالات الاستخدام الشائعة هو تعيين "sched_waking" كحدث بداية. يتم تشغيل هذا الحدث عند إيقاظ عملية. ثم قم بتعيين "sched_switch" كحدث نهاية. يتم تشغيل هذا الحدث عند جدولة مهمة جديدة على وحدة المعالجة المركزية. من خلال تعيين "common_pid" لكلا الحدثين كحقول مطابقة، يعتبر الوقت بين الحدثين زمن تأخير إيقاظ تلك العملية. استخدم TRACEFS_TIMESTAMP كحقل لكلا الحدثين لحساب الفرق بالنانو ثانية، أو استخدم *TRACEFS_TIMESTAMP_USECS" كحقول مقارنة لكلا الحدثين لحساب الفرق بالميكرو ثانية. يستخدم هذا كالمثال أدناه.

tracefs_synth_alloc() يخصص ويهيئ حدثًا اصطناعيًا. لا يقوم بإنشاء الحدث الاصطناعي، ولكنه يوفر الحد الأدنى من المعلومات للقيام بذلك. انظر tracefs_synth_create(3) لكيفية إنشاء الحدث الاصطناعي في النظام. يتطلب معالج tep يمكن إنشاؤه بواسطة tracefs_local_events(3) لمزيد من المعلومات. يحتوي name على اسم الحدث الاصطناعي الذي سيتم إنشاؤه. start_system هو اسم النظام للحدث المبدئي. قد يكون NULL وسيتم اختيار الحدث الأول بالاسم start_event. end_system هو اسم النظام للحدث النهائي. قد يكون NULL وسيتم اختيار الحدث الأول بالاسم end_event كحدث نهائي. إذا تم توفير match_name، فسيكون هذا هو الحقل في الحدث الاصطناعي الذي تم إنشاؤه والذي يحتوي على المفاتيح المطابقة لـ start_match_field لحدث البداية و end_match_field لحدث النهاية. إذا كان match_name هو NULL، فلن يتم تسجيله في الحدث الاصطناعي الذي تم إنشاؤه.

tracefs_synth_add_match_field() سيضيف مفتاحًا ثانيًا للمطابقة بين حدث البداية وحدث النهاية. إذا تم توفير name، فسيتم حفظ محتوى الحقل المطابق بهذا name في الحدث الاصطناعي. start_match_field هو حقل حدث البداية للمطابقة مع end_match_field لحدث النهاية.

tracefs_synth_add_compare_field() يستخدم لمقارنة start_compare_field لحدث البداية مع end_compare_field لحدث النهاية. يجب توفير name حتى يتم حفظ النتيجة بواسطة الحدث الاصطناعي. لا معنى لعدم تمرير هذا إلى الحدث الاصطناعي بعد القيام بعمل الحقول المقارنة، لأنه لا يخدم أي غرض آخر. يمكن أن يكون المعامل calc أحد هذه الخيارات:

TRACEFS_SYNTH_DELTA_END - حساب الفرق بين المحتوى في end_compare_field والمحتوى في start_compare_field.

name = end_compare_field - start_compare_field

TRACEFS_SYNTH_DELTA_START - حساب الفرق بين المحتوى في start_compare_field والمحتوى في end_compare_field.

name = start_compare_field - end_compare_field

TRACEFS_SYNTH_ADD - إضافة محتوى start_compare_field إلى محتوى end_compare_field.

name = start_compare_field + end_compare_field

tracefs_synth_add_start_field() - يسجل start_field لحدث البداية كـ name في الحدث الاصطناعي. إذا كان name هو NULL، فسيكون الاسم المستخدم هو نفس اسم start_field.

tracefs_synth_add_end_field() - يسجل end_field لحدث النهاية كـ name في الحدث الاصطناعي. إذا كان name هو NULL، فسيكون الاسم المستخدم هو نفس اسم end_field.

tracefs_synth_append_start_filter() ينشئ مرشحًا أو يلحق به لحدث البداية. اعتمادًا على type، سيقوم ببناء سلسلة من الرموز للأقواس أو عبارات المنطق، أو قد يضيف مقارنة بين field و val بناءً على compare.

إذا كان type هو: TRACEFS_FILTER_COMPARE - انظر أدناه TRACEFS_FILTER_AND - إلحاق "&&" بالمرشح TRACEFS_FILTER_OR - إلحاق "||" بالمرشح TRACEFS_FILTER_NOT - إلحاق "!" بالمرشح TRACEFS_FILTER_OPEN_PAREN - إلحاق "(" بالمرشح TRACEFS_FILTER_CLOSE_PAREN - إلحاق ")" بالمرشح

يتم تجاهل field و compare و val إلا إذا كان type يساوي TRACEFS_FILTER_COMPARE، ثم سيتم استخدام _compare لما يلي:

TRACEFS_COMPARE_EQ - field == val

TRACEFS_COMPARE_NE - field != val

TRACEFS_COMPARE_GT - field > val

TRACEFS_COMPARE_GE - field >= val

TRACEFS_COMPARE_LT - field < val

TRACEFS_COMPARE_LE - field <= val

TRACEFS_COMPARE_RE - field ~ "val" : حيث field هو سلسلة نصية.

TRACEFS_COMPARE_AND - field & val : حيث field هو حقل علامات.

tracefs_synth_append_end_filter() هو نفس tracefs_synth_append_start_filter ولكنه يقوم بالتصفية على حدث النهاية.

tracefs_synth_free() يحرر الواصف المخصص الذي تم إرجاعه بواسطة tracefs_synth_alloc().

tracefs_synth_add_match_field.3 - صفحة الدليل

الاسم

tracefs_synth_add_match_field - إضافة حقل مطابقة لحدث اصطناعي.

الصيغة

#include <tracefs.h>

int tracefs_synth_add_match_field(struct tracefs_synth *synth,
                                  const char *field,
                                  const char *value);

الوصف

تقوم الدالة tracefs_synth_add_match_field بإضافة حقل مطابقة جديد إلى حدث اصطناعي معرف بواسطة synth.

يجب أن يتطابق field مع اسم حقل في الحدث الاصطناعي، ويجب أن تتطابق value مع القيمة المطلوبة لهذا الحقل.

يمكن استدعاء هذه الدالة عدة مرات لإضافة شروط مطابقة متعددة.

المعلمات

  • synth: مؤشر إلى بنية tracefs_synth التي تمثل الحدث الاصطناعي.
  • field: سلسلة نصية تحتوي على اسم الحقل المراد مطابقته.
  • value: سلسلة نصية تحتوي على القيمة التي يجب أن يطابقها الحقل.

القيمة المُرجعة

تُرجع الدالة 0 عند النجاح، ورقمًا سالبًا عند الفشل. قد يتم تعيين errno للإشارة إلى الخطأ.

أمثلة

#include <tracefs.h>
#include <stdio.h>
#include <stdlib.h>

int main() {
    struct tracefs_synth *synth;
    int ret;

    // إنشاء حدث اصطناعي
    synth = tracefs_synth_new("my_event");
    if (!synth) {
        perror("tracefs_synth_new");
        return 1;
    }

    // إضافة حقول مطابقة
    ret = tracefs_synth_add_match_field(synth, "pid", "1234");
    if (ret < 0) {
        fprintf(stderr, "Failed to add match field pid: %d\n", ret);
        tracefs_synth_free(synth);
        return 1;
    }

    ret = tracefs_synth_add_match_field(synth, "comm", "myapp");
    if (ret < 0) {
        fprintf(stderr, "Failed to add match field comm: %d\n", ret);
        tracefs_synth_free(synth);
        return 1;
    }

    // ... استخدام synth ...

    tracefs_synth_free(synth);
    return 0;
}
