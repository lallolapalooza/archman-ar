NAME

trustman — A DNSSEC Trust Anchor Management Utility

SYNOPSIS

        trustman [ -add ] [ -del ] [ -list ] [ -check ] [ -rotate ]
                [ -config <file> ] [ -conf <file> ]
                [ -debug <level> ] [ -domain <domain> ]
                [ -dryrun ] [ -file <file> ]
                [ -group <group> ] [ -help ] [ -key <key> ]
                [ -keyfile <file> ] [ -log <file> ] [ -mail <addr> ]
                [ -mailto <addr> ] [ -name <name> ] [ -newkey <file> ]
                [ -nsstat <file> ] [ -owner <name> ] [ -pidfile <file> ]
                [ -port <port> ] [ -private ] [ -q ] [ -quiet ]
                [ -resolv <file> ] [ -resolv_conf_file <file> ]
                [ -root_hints_file <file> ] [ -rootfile <file> ]
                [ -logfile <file> ] [ -sig_life <duration> ]
                [ -smtp_server <server> ] [ -syslog <facility> ]
                [ -tmp_dir <dir> ] [ -toptions <file> ]
                [ -tkey <key> ] [ -tkeyfile <file> ]
                [ -tnsstat <file> ] [ -trootfile <file> ]
                [ -tresolv <file> ] [ -tresolv_conf_file <file> ]
                [ -troot_hints_file <file> ] [ -tsmtpserver <server> ]
                [ -tatmpdir <dir> ] [ -verbose ] [ -version ]
                [ -whoami <name> ] [ -zsk <key> ] [ -zskfile <file> ]
                [ -zskrollover ]

DESCRIPTION

The trustman utility is a DNSSEC Trust Anchor Management Utility. It is designed to help automate the management of DNSSEC trust anchors. The utility can perform a variety of tasks, including adding, deleting, listing, checking, and rotating trust anchors. It can also be used to send email notifications for various events.

The trustman utility can be run in several modes, determined by the options provided. The default mode is to list all known trust anchors.

Configuration for trustman can be provided via a configuration file (specified with the -config or -conf option) or through command-line options. Command-line options override any settings in the configuration file.

OPTIONS

The following options are available:

-add
Add a new trust anchor. This option requires additional information, such as the key and domain name, to be provided either through command-line arguments or the configuration file.
-check
Check the status of existing trust anchors. This may involve verifying signatures, key validity periods, and other relevant information.
-config file
Specifies a configuration file to be used by trustman. See the CONFIGURATION section for more details.
-conf file
An alias for the -config option.
-debug level
Sets the debug level for trustman. Higher levels provide more detailed output, which can be useful for troubleshooting.
-del
Delete an existing trust anchor. Requires specifying which trust anchor to delete.
-domain domain
Specifies the domain name for which trust anchor operations should be performed.
-dryrun
Perform a dry run of the specified operation. No actual changes will be made to the trust anchor configuration or related files.
-file file
Specifies a file containing trust anchor information. The format of the file depends on the operation being performed.
-group group
Specifies a group of trust anchors to operate on.
-help
Display a help message summarizing the available options and their usage.
-key key
Specifies a public key string.
-keyfile file
Specifies a file containing a public key.
-list
List all known trust anchors and their associated information.
-log file
Specifies a file to which log messages should be written. This is an alias for the -logfile option.
-logfile file
Specifies a file to which log messages should be written.
-mail addr
Specifies an email address to which notifications should be sent. This is an alias for the -mailto option.
-mailto addr
Specifies an email address to which notifications should be sent.
-name name
Specifies a name for a trust anchor or related entity.
-newkey file
Specifies a file containing information about a new key to be added. This is often used in conjunction with the -add option.
-nsstat file
Specifies a file containing statistics about name servers. This is an alias for the -tnsstat option.
-owner name
Specifies the owner of a trust anchor.
-pidfile file
Specifies a file where the process ID (PID) of the trustman daemon should be written. This is typically used when running trustman in daemon mode.
-port port
Specifies the network port number to use for communication. The default port is 53.
-private
Indicates that the key being managed is a private key. This option is usually used internally by the DNSSEC-Tools package and not typically specified directly by the user.
-q
Alias for the -quiet option.
-quiet
Suppress informational messages. Only errors and critical warnings will be displayed.
-resolv file
Specifies a file containing resolver configuration settings. This is an alias for the -resolv_conf_file option.
-resolv_conf_file file
Specifies the resolver configuration file (e.g., /etc/resolv.conf) to be used by trustman for DNS queries.
-root_hints_file file
Specifies the root hints file to be used by trustman. This is an alias for the -troot_hints_file option.
-rootfile file
Specifies the root zone file to be used. This is an alias for the -trootfile option.
-rotate
Rotate trust anchors. This typically involves updating keys that are expiring or have expired.
-sig_life duration
Specifies the desired signature lifetime for newly generated keys or signatures.
-smtp_server server
Specifies the SMTP server to which email notifications will be sent. This is an alias for the -tsmtpserver option.
-syslog facility
Specifies the syslog facility to use for logging messages when logging to syslog is enabled.
-tmp_dir dir
Specifies the directory where temporary files should be created. This is used during operations that involve creating or modifying configuration files before they are moved into their final locations.
-toptions file
This specifies a file containing Trustman-specific options. This is equivalent to the -config flag.
-tkey key
This specifies a Trust Anchor key. This is equivalent to the -key flag.
-tkeyfile file
This specifies a file containing a Trust Anchor key. This is equivalent to the -keyfile flag.
-tnsstat file
This specifies a file containing Name Server statistics. This is equivalent to the -nsstat flag.
-trootfile file
This specifies the root zone file to use. This is equivalent to the -rootfile flag.
-tresolv file
This specifies a file containing resolver information. This is equivalent to the -resolv_conf_file flag.
-taroothintsfile file
This specifies the root.hints file to read. This is equivalent to the -root_hints_file flag.
-tasmtpserver servername
This is equivalent to the -smtp_server flag for specifying the SMTP server to which email notices will be sent.
-tatmpdir directory
This specifies where temporary files should be created. This is used when creating new versions of the dnsval.conf and named.conf files before they're moved into place.

See the note about renaming in the description of the -tmp_dir option.

-verbose
Enable verbose output. This option provides more detailed information about the operations being performed, similar to a higher debug level but focused on standard operational output rather than internal debugging.
-version
Display the version information for trustman and exit.
-whoami name
Specifies a name to identify the current instance or context of trustman. This might be used in logging or notifications.
-zsk key
Specifies a Zone Signing Key (ZSK). This is typically used when adding or managing keys for a zone.
-zskfile file
Specifies a file containing a Zone Signing Key (ZSK).
-zskrollover
Initiates a rollover process for the Zone Signing Key (ZSK). This may involve generating a new key and updating DNSSEC records.

CONFIGURATION

The trustman utility can be configured using a configuration file. The file path can be specified using the -config or -conf command-line options. If no configuration file is specified, trustman will look for a default configuration file, typically named dnssec-tools.conf or similar, in standard system locations.

The configuration file uses a simple key-value format, where each line typically contains an option name followed by its value. Comments can be started with a # character.

Example configuration file entries:

    log_level: 3
    mail_to: admin@example.com
    smtp_server: smtp.example.com
    resolv_conf_file: /etc/resolv.conf
    tmp_dir: /var/tmp

Options specified on the command line take precedence over those defined in the configuration file.

EXIT CODES

trustman may exit for the following reasons:

0 - Successful execution.  In daemon mode, this may just mean
    that the daemon was successfully started.  The daemon itself
    may exit with some other error.
1 - Invalid options were specified.
2 - No new-key file was specified.
3 - Unable to open the new-key file.
4 - Unable to determine a set of zones to check.
5 - Some form of file-management error was encountered.
