الوصف

Linux Trace Toolkit: الجيل التالي http://lttng.org/ هي حزمة برامج مفتوحة المصدر تستخدم للتتبع المترابط لنواة لينكس، تطبيقات المستخدم، والمكتبات.

LTTng-UST هو مكون تتبع مساحة المستخدم لمشروع LTTng. إنها نسخة لمساحة المستخدم من قدرات التتبع منخفضة الحمل لمُتتبّع نواة لينكس LTTng. تُستخدم مكتبة liblttng-ust لتتبع تطبيقات المستخدم والمكتبات.


ملاحظة

صفحة الدليل هذه حول مكتبة liblttng-ust. يوفر مشروع LTTng-UST أيضًا حزم Java و Python لتتبع التطبيقات المكتوبة بتلك اللغات. كيفية توثيق وتتبع تطبيقات Java و Python موثقة في وثائق LTTng عبر الإنترنت http://lttng.org/docs/.

هناك ثلاث طرق لاستخدام liblttng-ust:

•باستخدام واجهة برمجة التطبيقات lttng_ust_tracef(3)، وهي مشابهة لـ printf(3).
•باستخدام واجهة برمجة التطبيقات lttng_ust_tracelog(3)، وهي lttng_ust_tracef(3) مع معلمة مستوى السجل.
•تحديد نقاط التتبع الخاصة بك. انظر قسم إنشاء موفر لنقطة تتبع أدناه.

توضح هذه الصفحة الدليلية الجدول التالي الربط بين إصدارات LTTng-UST (حتى LTTng-UST 2.14.0) وإصدارات واجهات برمجة التطبيقات المتاحة:

إصدار LTTng-UST إصدارات واجهات برمجة التطبيقات المتاحة
2.0 إلى 2.12 0
2.13 0 و 1

هذه الصفحة الدليلية توثق فقط الإصدار 1 من واجهة برمجة التطبيقات.

إذا كنت ترغب في الوصول إلى الإصدار 0 من واجهة برمجة التطبيقات (على سبيل المثال، وحدات الماكرو tracepoint()، ctf_integer()، و TRACEPOINT_EVENT())، فإما لا تحدد LTTNG_UST_COMPAT_API_VERSION، أو حددها إلى 0 قبل تضمين أي رأس LTTng-UST.

إنشاء موفر لنقطة تتبع

يعد إنشاء موفر لنقطة تتبع هو الخطوة الأولى في استخدام liblttng-ust. الخطوات التالية هي:

•توثيق تطبيقك باستخدام استدعاءات lttng_ust_tracepoint()
•بناء تطبيقك بدعم LTTng-UST، إما بشكل ثابت أو بشكل ديناميكي.

موفر نقطة التتبع (tracepoint provider) هو كائن مجمّع يحتوي على مجسات الأحداث المقابلة لتعريفات نقاط التتبع المخصصة الخاصة بك. يحتوي موفر نقطة التتبع على الكود اللازم للحصول على حجم الحدث وتسلسله، من بين أمور أخرى.

لإنشاء موفر لنقطة تتبع، ابدأ بالنموذج التالي لرأس موفر نقطة التتبع:

#undef LTTNG_UST_TRACEPOINT_PROVIDER
#define LTTNG_UST_TRACEPOINT_PROVIDER my_provider
#undef LTTNG_UST_TRACEPOINT_INCLUDE
#define LTTNG_UST_TRACEPOINT_INCLUDE "./tp.h"
#if !defined(_TP_H) || \
    defined(LTTNG_UST_TRACEPOINT_HEADER_MULTI_READ)
#define _TP_H
#include <lttng/tracepoint.h>
/*
 * LTTNG_UST_TRACEPOINT_EVENT(), LTTNG_UST_TRACEPOINT_EVENT_CLASS(),
 * LTTNG_UST_TRACEPOINT_EVENT_INSTANCE(),
 * LTTNG_UST_TRACEPOINT_LOGLEVEL(), and `LTTNG_UST_TRACEPOINT_ENUM()`
 * are used here.
 */
#endif /* _TP_H */
#include <lttng/tracepoint-event.h>

في هذا النموذج، يتم تسمية موفر نقطة التتبع my_provider (تعريف LTTNG_UST_TRACEPOINT_PROVIDER). يجب أن يحمل الملف اسم تعريف LTTNG_UST_TRACEPOINT_INCLUDE (tp.h في هذه الحالة). بين #include <lttng/tracepoint.h> و #endif تذهب استدعاءات الماكرو LTTNG_UST_TRACEPOINT_EVENT()، LTTNG_UST_TRACEPOINT_EVENT_CLASS()، LTTNG_UST_TRACEPOINT_EVENT_INSTANCE()، LTTNG_UST_TRACEPOINT_LOGLEVEL()، و LTTNG_UST_TRACEPOINT_ENUM().


ملاحظة

يمكنك تجنب كتابة الكود التمهيدي والختامي في ملف النموذج أعلاه باستخدام الأداة lttng-gen-tp(1) المتوفرة مع LTTng-UST.

يجب تضمين ملف رأس موفر نقطة التتبع في ملف مصدر يبدو كالتالي:

#define LTTNG_UST_TRACEPOINT_CREATE_PROBES
#include "tp.h"

معًا، هذان الملفان (لنسميهما tp.h و tp.c) يشكلان مصادر موفر نقطة التتبع، الجاهزة للتجميع.

يمكنك إنشاء عدة موفرات لنقاط تتبع لاستخدامها في تطبيق واحد، ولكن يجب أن يكون لكل منها ملف رأس خاص به.

يوضح قسم الاستخدام LTTNG_UST_TRACEPOINT_EVENT() أدناه كيفية استخدام ماكرو LTTNG_UST_TRACEPOINT_EVENT() لتعريف نقاط التتبع الفعلية في ملف رأس موفر نقطة التتبع.

راجع قسم المثال أدناه لمثال كامل.

استخدام LTTNG_UST_TRACEPOINT_EVENT()

يُستخدم ماكرو LTTNG_UST_TRACEPOINT_EVENT() في ملف رأس نموذج للموفر (انظر قسم إنشاء موفر نقطة تتبع أعلاه) لتعريف نقاط تتبع LTTng-UST.

نموذج استخدام LTTNG_UST_TRACEPOINT_EVENT() هو كما يلي:

LTTNG_UST_TRACEPOINT_EVENT(
    /* اسم موفر نقطة التتبع */
    my_provider,
    /* اسم نقطة التتبع/الحدث */
    my_tracepoint,
    /* قائمة وسائط نقطة التتبع (إدخال) */
    LTTNG_UST_TP_ARGS(
        ...
    ),
    /* قائمة حقول الحدث المحتمل (إخراج) */
    LTTNG_UST_TP_FIELDS(
        ...
    )
)

يحتوي ماكرو LTTNG_UST_TP_ARGS() على وسائط الإدخال لنقطة التتبع. يمكن استخدام هذه الوسائط في تعبيرات الوسائط للحقول الإخراج المحددة في LTTNG_UST_TP_FIELDS().

تنسيق معلمات LTTNG_UST_TP_ARGS() هو: نوع C، ثم اسم الوسيط؛ كرر حسب الحاجة، حتى عشر مرات. على سبيل المثال:

LTTNG_UST_TP_ARGS(
    int, my_int,
    const char *, my_string,
    FILE *, my_file,
    double, my_float,
    struct my_data *, my_data
)

يحتوي ماكرو LTTNG_UST_TP_FIELDS() على حقول الإخراج لنقطة التتبع، أي البيانات الفعلية التي يمكن تسجيلها في حمولة حدث يتم إنشاؤه بواسطة نقطة التتبع هذه.

يحتوي ماكرو LTTNG_UST_TP_FIELDS() على قائمة بماكرو lttng_ust_field_*() غير مفصولة بفواصل. الماكرو المتاحة موثقة في قسم الماكرو المتاحة لأنواع الحقول lttng_ust_field_*() أدناه.

LTTNG_UST_TRACEPOINT_ENUM()، **LTTNG_UST_TRACEPOINT_EVENT_CLASS()**، **LTTNG_UST_TRACEPOINT_LOGLEVEL()** usage

LTTng-UST provides a mechanism for defining new tracepoint providers. A tracepoint provider is a collection of related tracepoints. Each provider must be declared with the LTTNG_UST_TRACEPOINT_PROVIDER() macro. A tracepoint is an event that can be emitted by an application. Each tracepoint has a name, and can optionally take arguments and define fields. Arguments are data passed to the tracepoint at emission time. Fields are data that are serialized into the trace buffer, and that can be accessed later during trace analysis.

The following macros are available for defining new tracepoint providers and tracepoints:

LTTNG_UST_TRACEPOINT_PROVIDER()

LTTNG_UST_TRACEPOINT_PROVIDER(
    /* Provider name */
    my_provider
)

Declares a tracepoint provider named my_provider. This macro must be called before any other tracepoint definition macro for this provider.

LTTNG_UST_TRACEPOINT_EVENT()

LTTNG_UST_TRACEPOINT_EVENT(
    /* Tracepoint provider name */
    my_provider,
    /* Event name */
    my_event,
    /* List of tracepoint arguments (input) */
    LTTNG_UST_TP_ARGS(
        ...
    ),
    /* List of fields of eventual event (output) */
    LTTNG_UST_TP_FIELDS(
        ...
    )
)

Declares a tracepoint event named my_event for the provider my_provider. The arguments defined within LTTNG_UST_TP_ARGS() are the inputs to the tracepoint. The fields defined within LTTNG_UST_TP_FIELDS() are the outputs of the tracepoint. They are serialized and stored in the trace. Fields can be derived from arguments or computed otherwise. Arguments that are not fields are ignored.

Arguments and fields are defined using the following macros:

lttng_ust_field_integer()

lttng_ust_field_integer(
    /* Field name */
    my_int_field,
    /* Data type (signed char, unsigned char, signed short, unsigned short,
       signed int, unsigned int, signed long, unsigned long, signed long
       long, unsigned long long, size_t, pid_t, uid_t, gid_t) */
    unsigned int,
    /* Argument name */
    my_arg
)

Defines an integer field named my_int_field of the specified data type. The value of this field will be the value of the argument named my_arg.

lttng_ust_field_string()

lttng_ust_field_string(
    /* Field name */
    my_string_field,
    /* Argument name */
    my_arg
)

Defines a string field named my_string_field. The value of this field will be the value of the argument named my_arg.

lttng_ust_field_float()

lttng_ust_field_float(
    /* Field name */
    my_float_field,
    /* Data type (float, double, long double) */
    double,
    /* Argument name */
    my_arg
)

Defines a floating point field named my_float_field of the specified data type. The value of this field will be the value of the argument named my_arg.

lttng_ust_field_array()

lttng_ust_field_array(
    /* Field name */
    my_array_field,
    /* Element data type (see lttng_ust_field_integer) */
    unsigned int,
    /* Size of the array */
    10,
    /* Argument name */
    my_arg
)

Defines an array field named my_array_field containing elements of the specified data type and size. The value of this field will be the value of the argument named my_arg, which must be a pointer to an array of the specified element type and size.

lttng_ust_field_structure()

lttng_ust_field_structure(
    /* Field name */
    my_struct_field,
    /* Structure definition */
    my_struct_def,
    /* Argument name */
    my_arg
)

Defines a structure field named my_struct_field. The structure definition is provided by a previously defined structure type (see LTTNG_UST_TRACEPOINT_STRUCT() below). The value of this field will be the value of the argument named my_arg, which must be a pointer to a structure of the defined type.

LTTNG_UST_TRACEPOINT_STRUCT()

LTTNG_UST_TRACEPOINT_STRUCT(
    /* Structure definition name */
    my_struct_def,
    /* List of structure members */
    LTTNG_UST_TP_STRUCT_MEMBERS(
        ...
    )
)

Defines a structure type named my_struct_def that can be used with lttng_ust_field_structure(). The members of the structure are defined using the same macros as fields (lttng_ust_field_integer(), lttng_ust_field_string(), etc.).

A structure can contain other structures. In such cases, the nested structure must be defined before being used.

The arguments passed to a tracepoint are available in the context of the LTTNG_UST_TP_FIELDS() macro. They are otherwise identical. Their primary purpose is to make some of the event context available to the event filters without having to commit the data to sub-buffers. See lttng-enable-event(1) to learn more about dynamic event filtering.

See the EXAMPLE section below for a complete example.

LTTNG_UST_TRACEPOINT_ENUM() usage

An enumeration field is a list of mappings between an integers, or a range of integers, and strings (sometimes called labels or enumerators). Enumeration fields can be used to have a more compact trace when the possible values for a field are limited.

An enumeration field is defined with the LTTNG_UST_TRACEPOINT_ENUM() macro:

LTTNG_UST_TRACEPOINT_ENUM(
    /* Tracepoint provider name */
    my_provider,
    /* Enumeration name (unique in the whole tracepoint provider) */
    my_enum,
    /* Enumeration mappings */
    LTTNG_UST_TP_ENUM_VALUES(
        ...
    )
)

LTTNG_UST_TP_ENUM_VALUES() contains a list of enumeration mappings, NOT separated by commas. Two macros can be used in the LTTNG_UST_TP_ENUM_VALUES(): lttng_ust_field_enum_value() and lttng_ust_field_enum_range().

lttng_ust_field_enum_value() is a single value mapping:

lttng_ust_field_enum_value(label, value)

This macro maps the given label string to the value value.

lttng_ust_field_enum_range() is a range mapping:

lttng_ust_field_enum_range(label, start, end)

This macro maps the given label string to the range of integers from start to end, inclusively. Range mappings may overlap, but the behaviour is implementation-defined: each trace reader handles overlapping ranges as it wishes.

See the EXAMPLE section below for a complete example.

LTTNG_UST_TRACEPOINT_EVENT_CLASS() usage

A tracepoint class is a class of tracepoints sharing the same field types and names. A tracepoint instance is one instance of such a declared tracepoint class, with its own event name.

LTTng-UST creates one event serialization function per tracepoint class. Using LTTNG_UST_TRACEPOINT_EVENT() creates one tracepoint class per tracepoint definition, whereas using LTTNG_UST_TRACEPOINT_EVENT_CLASS() and LTTNG_UST_TRACEPOINT_EVENT_INSTANCE() creates one tracepoint class, and one or more tracepoint instances of this class. In other words, many tracepoints can reuse the same serialization code. Reusing the same code, when possible, can reduce cache pollution, thus improve performance.

The LTTNG_UST_TRACEPOINT_EVENT_CLASS() macro accepts the same parameters as the LTTNG_UST_TRACEPOINT_EVENT() macro, except that instead of an event name, its second parameter is the tracepoint class name:

#define LTTNG_UST_TRACEPOINT_PROVIDER my_provider
/* ... */
LTTNG_UST_TRACEPOINT_EVENT_CLASS(
    /* Tracepoint class provider name */
    my_provider,
    /* Tracepoint class name */
    my_tracepoint_class,
    /* List of tracepoint arguments (input) */
    LTTNG_UST_TP_ARGS(
        ...
    ),
    /* List of fields of eventual event (output) */
    LTTNG_UST_TP_FIELDS(
        ...
    )
)

Once the tracepoint class is defined, you can create as many tracepoint instances as needed:

#define LTTNG_UST_TRACEPOINT_PROVIDER natality
/* ... */
LTTNG_UST_TRACEPOINT_EVENT_INSTANCE(
    /* Name of the tracepoint class provider */
    my_provider,
    /* Tracepoint class name */
    my_tracepoint_class,
    /* Name of the local (instance) tracepoint provider */
    natality,
    /* Tracepoint/event name */
    my_tracepoint,
    /* List of tracepoint arguments (input) */
    LTTNG_UST_TP_ARGS(
        ...
    )
)

As you can see, the LTTNG_UST_TRACEPOINT_EVENT_INSTANCE() does not contain the LTTNG_UST_TP_FIELDS() macro, because they are defined at the LTTNG_UST_TRACEPOINT_EVENT_CLASS() level.

Note that the LTTNG_UST_TRACEPOINT_EVENT_INSTANCE() macro requires two provider names:

•The name of the tracepoint class provider (my_provider in the example above).

This is the same as the first argument of the LTTNG_UST_TRACEPOINT_EVENT_CLASS() expansion to refer to.

•The name of the local, or instance, provider (natality in the example above).

This is the provider name which becomes the prefix part of the name of the events which such a tracepoint creates.

The two provider names may be different if the tracepoint class and the tracepoint instance macros are in two different translation units.

See the EXAMPLE section below for a complete example.

Instrumenting your application

Once the tracepoint provider is created (see the Creating a tracepoint provider section above), you can instrument your application with the defined tracepoints thanks to the lttng_ust_tracepoint() macro:

#define lttng_ust_tracepoint(prov_name, t_name, ...)

With:

prov_name

Tracepoint provider name.

t_name

Tracepoint/event name.

...

Tracepoint arguments, if any.

Make sure to include the tracepoint provider header file anywhere you use lttng_ust_tracepoint() for this provider.


Note

Even though LTTng-UST supports lttng_ust_tracepoint() call site duplicates having the same provider and tracepoint names, it is recommended to use a provider/tracepoint name pair only once within the application source code to help map events back to their call sites when analyzing the trace.

Sometimes, arguments to the tracepoint are expensive to compute (take call stack, for example). To avoid the computation when the tracepoint is disabled, you can use the lttng_ust_tracepoint_enabled() and lttng_ust_do_tracepoint() macros:

#define lttng_ust_tracepoint_enabled(prov_name, t_name)
#define lttng_ust_do_tracepoint(prov_name, t_name, ...)

lttng_ust_tracepoint_enabled() returns a non-zero value if the tracepoint named t_name from the provider named prov_name is enabled at run time.

lttng_ust_do_tracepoint() is like lttng_ust_tracepoint(), except that it doesn’t check if the tracepoint is enabled. Using lttng_ust_tracepoint() with lttng_ust_tracepoint_enabled() is dangerous since lttng_ust_tracepoint() also contains the lttng_ust_tracepoint_enabled() check, thus a race condition is possible in this situation:

if (lttng_ust_tracepoint_enabled(my_provider, my_tracepoint)) {
    stuff = prepare_stuff();
}
lttng_ust_tracepoint(my_provider, my_tracepoint, stuff);

If the tracepoint is enabled after the condition, then stuff is not prepared: the emitted event will either contain wrong data, or the whole application could crash (segmentation fault, for example).


Note

Neither lttng_ust_tracepoint_enabled() nor lttng_ust_do_tracepoint() have a STAP_PROBEV() call, so if you need it, you should emit this call yourself.

Tracing C/C++ applications

To instrument your C/C++ application, you will need to include the LTTng-UST header file, which is usually <lttng/ust.h>.

Then, you need to define your tracepoint provider and tracepoints. This is typically done in a dedicated header file (e.g., my_provider.h) which will be included in the source files where you need to emit tracepoints.

Here is a minimal example of such a header file:

#undef LTTNG_UST_TRACEPOINT_PROVIDER
#define LTTNG_UST_TRACEPOINT_PROVIDER my_provider

#include <lttng/tracepoint.h>

/* Define a simple tracepoint with no arguments and no fields */
LTTNG_UST_TRACEPOINT_EVENT(my_simple_tracepoint)

/* Define a tracepoint with one integer argument and one integer field */
LTTNG_UST_TRACEPOINT_EVENT(my_int_tracepoint,
    LTTNG_UST_TP_ARGS(
        int, my_arg
    ),
    LTTNG_UST_TP_FIELDS(
        lttng_ust_field_integer(my_field, int, my_arg)
    )
)

/* Define a tracepoint with a string argument and field, and a structure field */
struct my_complex_data {
    int id;
    char *name;
};

LTTNG_UST_TRACEPOINT_STRUCT(my_struct_def,
    LTTNG_UST_TP_STRUCT_MEMBERS(
        lttng_ust_field_integer(id, int, id)
        lttng_ust_field_string(name, name)
    )
)

LTTNG_UST_TRACEPOINT_EVENT(my_complex_tracepoint,
    LTTNG_UST_TP_ARGS(
        const char *, msg,
        struct my_complex_data *, data
    ),
    LTTNG_UST_TP_FIELDS(
        lttng_ust_field_string(message, msg)
        lttng_ust_field_structure(complex_data, my_struct_def, data)
    )
)

/* Define a tracepoint class and an instance of it */
LTTNG_UST_TRACEPOINT_EVENT_CLASS(my_provider, my_class,
    LTTNG_UST_TP_ARGS(
        int, value
    ),
    LTTNG_UST_TP_FIELDS(
        lttng_ust_field_integer(val, int, value)
    )
)

LTTNG_UST_TRACEPOINT_EVENT_INSTANCE(my_provider, my_class, other_provider, my_instance,
    LTTNG_UST_TP_ARGS(
        int, value
    )
)

/* Define a tracepoint with a log level */
LTTNG_UST_TRACEPOINT_EVENT(my_log_tracepoint,
    LTTNG_UST_TP_ARGS(
        int, level
    ),
    LTTNG_UST_TP_FIELDS(
        lttng_ust_field_integer(lvl, int, level)
    )
)
LTTNG_UST_TRACEPOINT_LOGLEVEL(my_provider, my_log_tracepoint, LTTNG_UST_TRACEPOINT_LOGLEVEL_INFO)

/* Include this header in your source files */
#undef LTTNG_UST_TRACEPOINT_PROVIDER

Then, in your C/C++ source files, you can include this header and emit tracepoints:

#include "my_provider.h"

int main(int argc, char **argv) {
    /* Emit the simple tracepoint */
    lttng_ust_tracepoint(my_provider, my_simple_tracepoint);

    /* Emit the integer tracepoint */
    int my_data = 42;
    lttng_ust_tracepoint(my_provider, my_int_tracepoint, my_data);

    /* Emit the complex tracepoint */
    struct my_complex_data data = {1, "example"};
    lttng_ust_tracepoint(my_provider, my_complex_tracepoint, "hello world", &data);

    /* Emit the tracepoint instance */
    lttng_ust_tracepoint(other_provider, my_instance, 100);

    /* Emit the log level tracepoint */
    lttng_ust_tracepoint(my_provider, my_log_tracepoint, 5);

    return 0;
}

After compiling and running your application, you can trace it using:

$ lttng create my_session --tracefile-size=10M --output=./traces
$ lttng enable-event -u my_provider:my_simple_tracepoint
$ lttng enable-event -u my_provider:my_int_tracepoint
$ lttng enable-event -u my_provider:my_complex_tracepoint
$ lttng enable-event -u other_provider:my_instance
$ lttng enable-event -u my_provider:my_log_tracepoint --loglevel=info
$ lttng start
$ ./your_application
$ lttng stop
$ lttng view

The tracepoints defined using LTTNG_UST_TRACEPOINT_EVENT_CLASS() will be emitted using the instance name (e.g. other_provider:my_instance).

Note that you need to include the header file defining the tracepoint provider in every source file where you use the tracepoints. You also need to define the provider using LTTNG_UST_TRACEPOINT_PROVIDER() before including the header file.

The example above shows how to define and use tracepoints. More complex examples can be found in the LTTng-UST source code tree.

Make sure to link your application with the LTTng-UST library (e.g. -llttng-ust).

NAME

lttng-ust-capture - LTTng user space tracer

SYNOPSIS

/usr/share/doc/lttng-ust/

DESCRIPTION

This document describes the LTTng user space tracer (liblttng-ust) API and configuration.

LTTng-UST allows you to trace user space applications with minimal performance overhead. It provides a set of macros that you can use to define tracepoints in your C/C++ source code. These tracepoints can then be enabled and observed using the LTTng tools.

The tracepoint provider

A tracepoint provider is a component that defines a set of tracepoints. It is implemented using C preprocessor macros defined in a header file. The same header file is included by the application source file(s) that use the tracepoints and by a source file that implements the provider.

The tracepoint provider header file must define the following macros:

LTTNG_UST_TRACEPOINT_PROVIDER
Defines the name of the tracepoint provider. This name is used to uniquely identify the provider and its tracepoints.
LTTNG_USTTRACEPOINT_INCLUDE
Specifies the path to the tracepoint provider header file itself. This is necessary to ensure that the tracepoint definitions are correctly processed when the provider source file is compiled.

Tracepoints are defined using the LTTNG_UST_TRACEPOINT_EVENT macro, which takes the provider name, event name, arguments, and fields as parameters.

The provider source file must define the following macros before including the tracepoint provider header file:

LTTNG_UST_TRACEPOINT_CREATE_PROBES
This macro tells liblttng-ust to create the actual probe functions for the tracepoints defined in the header file.
LTTNG_UST_TRACEPOINT_DEFINE
This macro is required to ensure that the tracepoint probes are defined and initialized.

Defining tracepoints

Tracepoints are defined using the following macros:

LTTNG_UST_TRACEPOINT_EVENT
Defines a tracepoint event. 
LTTNG_UST_TRACEPOINT_EVENT(provider, event_name,
                           LTTNG_UST_TP_ARGS(...),
                           LTTNG_UST_TP_FIELDS(...))

Arguments are defined using LTTNG_UST_TP_ARGS, and fields are defined using LTTNG_UST_TP_FIELDS.

LTTNG_UST_TRACEPOINT_EVENT_CLASS
Defines a tracepoint event class. Event classes are used to group related tracepoints.
LTTNG_UST_TRACEPOINT_EVENT_INSTANCE
Defines an instance of a tracepoint event class. This allows you to create multiple tracepoints with the same structure but different names.
LTTNG_UST_TRACEPOINT_LOGLEVEL
Sets the log level for a tracepoint event. This can be used to filter events based on their severity.
LTTNG_UST_TRACEPOINT_ENUM
Defines an enumeration type for tracepoint fields. This allows you to represent symbolic values for integer fields.

Using tracepoints in an application

To use tracepoints in an application, include the tracepoint provider header file and call the tracepoint macros. The tracepoint macros are typically wrapped in functions that are called from the application code.

For example:

#include "my_provider.h"
/* ... */
lttng_ust_tracepoint(my_provider, my_event, arg1, arg2);
/* ... */

The arguments passed to the tracepoint macro must match the arguments defined in the tracepoint definition.

The tracepoint definition can also specify fields to be recorded along with the event. These fields can be simple values, strings, arrays, or sequences.

LTTNG_UST_TRACEPOINT_EVENT(
    my_provider,
    my_event,
    LTTNG_UST_TP_ARGS(int, arg1, const char *, arg2),
    LTTNG_UST_TP_FIELDS(
        lttng_ust_field_integer(int, my_int_field, arg1)
        lttng_ust_field_string(my_string_field, arg2)
    )
)

Linker script for static linking

When statically linking your application with liblttng-ust, you may need to provide a linker script to ensure that the tracepoint probes are correctly initialized. This is typically done by defining a symbol in the linker script that references the `__lttng_usr_init` function.

Here is an example linker script:

GROUP ( /usr/lib/liblttng-ust.a )
*(@);

This script ensures that the liblttng-ust library is linked statically and that its initialization function is called.

When using this linker script, you should compile your application like this:

$ cc -c -I. tp.c
$ cc -c app.c
$ cc -o app tp.o app.o -Wl,-T your_linker_script.ld

Replace `your_linker_script.ld` with the actual name of your linker script file.

Note that using dynamic linking is generally simpler and does not require a custom linker script.

The debug link file name is defined in the linker script.

Detect if LTTng-UST is loaded

To detect if liblttng-ust is loaded from an application:

1.Define the lttng_ust_loaded weak symbol globally: 
int lttng_ust_loaded __attribute__((weak));

This weak symbol is set by the constructor of liblttng-ust.

2.Test lttng_ust_loaded where needed: 
/* ... */
if (lttng_ust_loaded) {
    /* LTTng-UST is loaded */
} else {
    /* LTTNG-UST is NOT loaded */
}
/* ... */

ENVIRONMENT VARIABLES

LTTNG_HOME

Alternative user’s home directory. This variable is useful when the user running the instrumented application has a non-writable home directory. This path is where Unix sockets for communication with the per-user session daemon are located.

LTTNG_UST_ABORT_ON_CRITICAL

If set, abort the instrumented application on a critical error message.

LTTNG_UST_ALLOW_BLOCKING

If set, allow the application to retry event tracing when there’s no space left for the event record in the sub-buffer, therefore effectively blocking the application until space is made available or the configured timeout is reached.

To allow an application to block during tracing, you also need to specify a blocking timeout when you create a channel with the --blocking-timeout option of the lttng-enable-channel(1) command.

This option can be useful in workloads generating very large trace data throughput, where blocking the application is an acceptable trade-off to prevent discarding event records.


Warning
Setting this environment variable may significantly affect application timings.

LTTNG_UST_APP_PATH

Path of the directory where to expect the LTTng session daemon to place the following files to receive instrumented application connection requests:
•The application registration Unix socket.
•The "wait" shared memory files to wake up instrumented applications that are waiting for a session daemon to start.
•The agent port file.

This file contains the TCP port the agents must connect to in order to enable LTTng tracing.

This directory must exist when you start the application for LTTng tracing to be enabled.

When LTTNG_UST_APP_PATH is set, liblttng-ust:

•Only considers this path to connect to a session daemon.
•Won’t connect to root and/or user session daemons as usual.

See the corresponding LTTNG_UST_CTL_PATH environment variable of lttng-sessiond(8).

LTTNG_UST_CLOCK_PLUGIN

Path to the shared object which acts as the clock override plugin. An example of such a plugin can be found in the LTTng-UST documentation under examples/clock-override https://github.com/lttng/lttng-ust/tree/stable-2.14/doc/examples/clock-override.

اسم

tracepoint_enabled - التحقق من تمكين نقطة تتبع LTTng-UST

نبذة

tracepoint_enabled

وصف

تسمح لك الوظيفة tracepoint_enabled بالتحقق مما إذا كانت نقطة تتبع معينة ممكّنة أو لا. هذا مفيد بشكل خاص عند استخدام نقاط التتبع التي تتطلب تحميل مكتبة ديناميكية.

هذه الوظيفة هي جزء من مكتبة liblttng-ust.

مثال

فيما يلي مثال بسيط يوضح كيفية استخدام tracepoint_enabled:

#include <lttng/tracepoint.h>
#include <stdio.h>

int main() {
    if (tracepoint_enabled(my_custom_tracepoint)) {
        printf("Tracepoint my_custom_tracepoint is enabled.\n");
        // قم باستدعاء نقطة التتبع هنا
        my_custom_tracepoint();
    } else {
        printf("Tracepoint my_custom_tracepoint is not enabled.\n");
    }
    return 0;
}

في هذا المثال، نتحقق أولاً مما إذا كانت نقطة التتبع my_custom_tracepoint ممكّنة. إذا كانت ممكّنة، نطبع رسالة ونستدعي نقطة التتبع. وإلا، نطبع رسالة تشير إلى أنها غير ممكّنة.

متغيرات البيئة

LTTNG_UST_DEBUG

إذا تم تعيينها، فسيتم تمكين إخراج تصحيح الأخطاء والأخطاء الخاص بـ liblttng-ust.

LTTNG_UST_GETCPU_PLUGIN

المسار إلى الكائن المشترك الذي يعمل كإضافة تجاوز getcpu(). يمكن العثور على مثال لهذه الإضافة في وثائق LTTng-UST ضمن examples/getcpu-override https://github.com/lttng/lttng-ust/tree/stable-2.14/doc/examples/getcpu-override.

LTTNG_UST_MAP_POPULATE_POLICY

إذا تم تعيينها، فسيتم تجاوز السياسة المستخدمة لملء صفحات الذاكرة المشتركة داخل التطبيق.

القيم الممكنة هي:

none (افتراضي)

لا تقم بملء أي صفحة مسبقًا: قم بأخذ الأخطاء الطفيفة عند الوصول الأول أثناء التتبع.

cpu_possible

قم بملء الصفحات مسبقًا لجميع وحدات المعالجة المركزية الممكنة في النظام، كما هو موضح في /sys/devices/system/cpu/possible.

LTTNG_UST_REGISTER_TIMEOUT

وقت الانتظار لأمر ذاكرة الجلسة registration done لـ daemon قبل المتابعة لتنفيذ البرنامج الرئيسي (بالمللي ثانية).

القيمة 0 تعني عدم الانتظار. القيمة -1 تعني الانتظار إلى الأبد. يوصى بتعيين متغير البيئة هذا إلى 0 للتطبيقات التي لديها قيود زمنية على وقت بدء تشغيل العملية.

الافتراضي: 3000.

LTTNG_UST_WITHOUT_BADDR_STATEDUMP

إذا تم تعيينها، فإنها تمنع liblttng-ust من أداء تفريغ حالة العنوان الأساسي (انظر قسم LTTng-UST state dump أعلاه).

LTTNG_UST_WITHOUT_PROCNAME_STATEDUMP

إذا تم تعيينها، فإنها تمنع liblttng-ust من أداء تفريغ حالة اسم العملية (انظر قسم LTTng-UST state dump أعلاه).
