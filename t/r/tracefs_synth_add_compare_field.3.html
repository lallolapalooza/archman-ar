الوصف

الأحداث الاصطناعية هي أحداث ديناميكية يتم إنشاؤها عن طريق مطابقة حدثين آخرين مما يؤدي إلى تشغيل حدث اصطناعي. أحد الأحداث هو حدث البدء الذي يتم تسجيل حقل معين فيه، وعندما يتم تنفيذ الحدث الثاني، إذا كان لديه حقل (أو حقول) يطابق حقل (أو حقول) حدث البدء، فسيؤدي ذلك إلى تشغيل الحدث الاصطناعي. قد يتم تمرير قيم الحقول بخلاف الحقول المطابقة من حدث البدء إلى حدث النهاية لإجراء حسابات عليها، أو لمجرد تمريرها كمعلمة للحدث الاصطناعي.

أحد حالات الاستخدام الشائعة هو تعيين "sched_waking" كحدث بدء. يتم تشغيل هذا الحدث عند إيقاظ عملية. ثم قم بتعيين "sched_switch" كحدث نهاية. يتم تشغيل هذا الحدث عند جدولة مهمة جديدة على وحدة المعالجة المركزية. من خلال تعيين "common_pid" لكلا الحدثين كمطابقة للحقول، يعتبر الوقت بين الحدثين هو زمن الاستيقاظ لتلك العملية. استخدم TRACEFS_TIMESTAMP كمجال لكلا الحدثين لحساب الفرق بالنانوثانية، أو استخدم *TRACEFS_TIMESTAMP_USECS" كمجالات مقارنة لكلا الحدثين لحساب الفرق بالميكروثانية. يستخدم هذا كمثال أدناه.

tracefs_synth_alloc() يقوم بتخصيص وتهيئة حدث اصطناعي. لا يقوم بإنشاء الحدث الاصطناعي، ولكنه يوفر الحد الأدنى من المعلومات للقيام بذلك. انظر tracefs_synth_create(3) لكيفية إنشاء الحدث الاصطناعي في النظام. يتطلب معالج tep الذي يمكن إنشاؤه بواسطة tracefs_local_events(3) لمزيد من المعلومات. يحتوي name على اسم الحدث الاصطناعي الذي سيتم إنشاؤه. start_system هو اسم النظام للحدث البدء. قد يكون NULL وسيتم اختيار أول حدث بالاسم start_event. end_system هو اسم النظام لحدث النهاية. قد يكون NULL وسيتم اختيار أول حدث بالاسم end_event كحدث نهاية. إذا تم تقديم match_name، فسيتم حفظ هذا في حقل الحدث الاصطناعي الذي تم إنشاؤه والذي يحمل مفاتيح المطابقة لـ start_match_field لحدث البدء و end_match_field لحدث النهاية. إذا كان match_name هو NULL، فلن يتم تسجيله في الحدث الاصطناعي الذي تم إنشاؤه.

tracefs_synth_add_match_field() سيضيف مفتاحًا ثانيًا للمطابقة بين حدث البدء وحدث النهاية. إذا تم تقديم name، فسيتم حفظ محتوى حقل المطابقة بهذا name في الحدث الاصطناعي. start_match_field هو حقل حدث البدء للمطابقة مع end_match_field لحدث النهاية.

tracefs_synth_add_compare_field() يستخدم لمقارنة start_compare_field لحدث البدء مع end_compare_field لحدث النهاية. يجب تقديم name حتى يتم حفظ النتيجة بواسطة الحدث الاصطناعي. لا معنى لعدم تمرير هذا إلى الحدث الاصطناعي بعد القيام بعمل الحقول المقارنة، حيث إنه لا يخدم أي غرض آخر. يمكن أن يكون المعلمة calc واحدة مما يلي:

TRACEFS_SYNTH_DELTA_END - حساب الفرق بين المحتوى في end_compare_field والمحتوى في start_compare_field.

name = end_compare_field - start_compare_field

TRACEFS_SYNTH_DELTA_START - حساب الفرق بين المحتوى في start_compare_field والمحتوى في end_compare_field.

name = start_compare_field - end_compare_field

TRACEFS_SYNTH_ADD - إضافة محتوى start_compare_field إلى محتوى end_compare_field.

name = start_compare_field + end_compare_field

tracefs_synth_add_start_field() - يسجل start_field لحدث البدء باسم name في الحدث الاصطناعي. إذا كان name هو NULL، فسيتم استخدام نفس الاسم مثل start_field.

tracefs_synth_add_end_field() - يسجل end_field لحدث النهاية باسم name في الحدث الاصطناعي. إذا كان name هو NULL، فسيتم استخدام نفس الاسم مثل end_field.

tracefs_synth_append_start_filter() ينشئ مرشحًا أو يلحق به لحدث البدء. اعتمادًا على type، سيبني سلسلة من الرموز للأقواس أو عبارات المنطق، أو قد يضيف مقارنة لـ field مع val بناءً على compare.

إذا كان type هو: TRACEFS_FILTER_COMPARE - انظر أدناه TRACEFS_FILTER_AND - إلحاق "&&" بالمرشح TRACEFS_FILTER_OR - إلحاق "||" بالمرشح TRACEFS_FILTER_NOT - إلحاق "!" بالمرشح TRACEFS_FILTER_OPEN_PAREN - إلحاق "(" بالمرشح TRACEFS_FILTER_CLOSE_PAREN - إلحاق ")" بالمرشح

يتم تجاهل field و compare و val ما لم يكن type يساوي TRACEFS_FILTER_COMPARE، ثم يتم استخدام _compare لما يلي:

TRACEFS_COMPARE_EQ - field == val

TRACEFS_COMPARE_NE - field != val

TRACEFS_COMPARE_GT - field > val

TRACEFS_COMPARE_GE - field >= val

TRACEFS_COMPARE_LT - field < val

TRACEFS_COMPARE_LE - field <= val

TRACEFS_COMPARE_RE - field ~ "val" : حيث field هو سلسلة نصية.

TRACEFS_COMPARE_AND - field & val : حيث field هو حقل علامات.

tracefs_synth_append_end_filter() هو نفس tracefs_synth_append_start_filter ولكنه يقوم بالترشيح على حدث النهاية.

tracefs_synth_free() يحرر الواصف المخصص الذي تم إرجاعه بواسطة tracefs_synth_alloc().

قيمة الإرجاع

tracefs_synth_add_compare_field.3

NAME

tracefs_synth_add_compare_field - Add a field to a synthetic event definition.

SYNOPSIS

#include <tracefs.h>

int tracefs_synth_add_compare_field(struct tracefs_synth_event *event,
                                   const char *name,
                                   enum tracefs_synth_field_type type,
                                   unsigned int size);

DESCRIPTION

tracefs_synth_add_compare_field adds a new field to the given synthetic event definition event. The field will have the specified name, type, and size. This function is intended to be used when defining synthetic events that involve comparing fields. The size parameter is only relevant for string and byte array fields.

RETURN VALUE

On success, 0 is returned. On failure, a negative error code is returned.

EXAMPLE

struct tracefs_synth_event *event;
int ret;

event = tracefs_synth_event_new("my_event");
if (!event) {
    // handle error
}

ret = tracefs_synth_add_compare_field(event, "field1", TRACEFS_SYNTH_FIELD_INT, 0);
if (ret < 0) {
    // handle error
    tracefs_synth_event_free(event);
    return ret;
}

ret = tracefs_synth_add_compare_field(event, "field2", TRACEFS_SYNTH_FIELD_STRING, 64);
if (ret < 0) {
    // handle error
    tracefs_synth_event_free(event);
    return ret;
}

// ... use event ...

tracefs_synth_event_free(event);
