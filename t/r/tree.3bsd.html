tree(3bsd)

الحزمة: libbsd

التراخيص: custom

NAME

tree - an interface to the tree, splay tree, and red-black tree data structures

LIBRARY

C library (libc)

SYNOPSIS

#include <sys/tree.h>

DESCRIPTION

The <sys/tree.h> header defines macros for manipulating binary search trees, splay trees, and red-black trees.

A tree is defined by a struct that contains a pointer to the root of the tree. Trees are typically declared as follows:

RB_HEAD(HEADNAME, TYPE) head;

where HEADNAME is the name of the tree head structure, and TYPE is the name of the structure that will be stored in the tree. The TYPE structure must contain a field of type RB_ENTRY(TYPE) (or SPLAY_ENTRY(TYPE), or T_ENTRY(TYPE) for generic trees). This field is used by the tree macros to link the nodes together.

The tree macros are based on the tree(3) implementation found in the 4.4BSD-Lite distribution.

SPLAY TREES

Splay trees are self-balancing binary search trees. Every time a node is accessed, it is splayed to the root of the tree. This improves locality of reference, as frequently accessed nodes are more likely to be near the root.

A splay tree is declared using the macros SPLAY_HEAD(), SPLAY_ENTRY(), SPLAY_PROTOTYPE(), and SPLAY_GENERATE().

SPLAY_HEAD(HEADNAME, TYPE) head;
SPLAY_PROTOTYPE(HEADNAME, TYPE, field, cmp);
SPLAY_GENERATE(HEADNAME, TYPE, field, cmp);

field is the name of the SPLAY_ENTRY() field in the TYPE structure. cmp is the name of a function used to compare nodes. The function takes two arguments of type struct TYPE *. If the first argument is smaller than the second, the function returns a value smaller than zero. If they are equal, the function returns zero. Otherwise, it returns a value greater than zero. The compare function defines the order of the tree elements.

The following macros are available for manipulating splay trees:

SPLAY_INIT(struct HEADNAME *head)
Initializes the tree referenced by head.
SPLAY_EMPTY(struct HEADNAME *head)
Checks if the tree is empty.
SPLAY_INSERT(HEADNAME, head, elm)
Inserts the element elm into the tree. If a matching element already exists, the insertion is aborted and a pointer to the existing element is returned. Otherwise, elm is returned.
SPLAY_REMOVE(HEADNAME, head, elm)
Removes the element elm from the tree.
SPLAY_FIND(HEADNAME, head, elm)
Finds an element in the tree that matches elm.
SPLAY_NEXT(HEADNAME, head, elm)
Returns a pointer to the next element in the tree after elm.
SPLAY_MIN(HEADNAME, head)
Returns a pointer to the smallest element in the tree.
SPLAY_MAX(HEADNAME, head)
Returns a pointer to the largest element in the tree.
SPLAY_ROOT(struct HEADNAME *head)
Returns a pointer to the root of the tree.
SPLAY_FOREACH(var, HEADNAME, head)
Iterates over all elements in the tree in ascending order.

RED-BLACK TREES

Red-black trees are a type of self-balancing binary search tree. They are typically more complex than splay trees, but offer more predictable performance characteristics.

A red-black tree is declared using the macros RB_HEAD(), RB_ENTRY(), RB_PROTOTYPE(), and RB_GENERATE().

RB_HEAD(HEADNAME, TYPE) head;
RB_PROTOTYPE(HEADNAME, TYPE, field, cmp);
RB_GENERATE(HEADNAME, TYPE, field, cmp);

field is the name of the RB_ENTRY() field in the TYPE structure. cmp is the name of a function used to compare nodes. The function takes two arguments of type struct TYPE *. If the first argument is smaller than the second, the function returns a value smaller than zero. If they are equal, the function returns zero. Otherwise, it returns a value greater than zero. The compare function defines the order of the tree elements.

The following macros are available for manipulating red-black trees:

RB_INIT(struct HEADNAME *head)
Initializes the tree referenced by head.
RB_INITIALIZER(struct HEADNAME *head)
The red-black tree can also be initialized statically by using the RB_INITIALIZER() macro like this:
RB_HEAD(HEADNAME, TYPE) head = RB_INITIALIZER(&head);
RB_INSERT(HEADNAME, head, elm)
Inserts the new element elm into the tree. Upon success, NULL is returned. If a matching element already exists in the tree, the insertion is aborted, and a pointer to the existing element is returned.
RB_REMOVE(HEADNAME, head, elm)
Removes the element elm from the tree pointed by head. RB_REMOVE() returns elm.
RB_FIND(HEADNAME, head, elm)
and RB_NFIND(HEADNAME, head, elm)
macros can be used to find a particular element in the tree. RB_FIND() finds the node with the same key as elm. RB_NFIND() finds the first node greater than or equal to the search key.
struct TYPE find, *res;
find.key = 30;
res = RB_FIND(NAME, &head, &find);
RB_ROOT(struct HEADNAME *head)
RB_MIN(HEADNAME, head)
RB_MAX(HEADNAME, head)
RB_NEXT(HEADNAME, head, elm)
RB_PREV(HEADNAME, head, elm)
macros can be used to traverse the tree:
for (np = RB_MIN(NAME, &head); np != NULL; np = RB_NEXT(NAME, &head, np))
RB_FOREACH(var, HEADNAME, head)
Or, for simplicity, one can use the RB_FOREACH() or RB_FOREACH_REVERSE(var, HEADNAME, head) macros:
RB_FOREACH(np, NAME, &head)
RB_FOREACH_SAFE(var, HEADNAME, head)
RB_FOREACH_REVERSE_SAFE(var, HEADNAME, head)
The macros RB_FOREACH_SAFE() and RB_FOREACH_REVERSE_SAFE() traverse the tree referenced by head in a forward or reverse direction respectively, assigning each element in turn to np. However, unlike their unsafe counterparts, they permit both the removal of np as well as freeing it from within the loop safely without interfering with the traversal.
RB_EMPTY(struct HEADNAME *head)
The RB_EMPTY() macro should be used to check whether a red-black tree is empty.

EXAMPLES

The following example demonstrates how to declare a red-black tree holding integers. Values are inserted into it and the contents of the tree are printed in order. Lastly, the internal structure of the tree is printed.

#include <sys/tree.h>
#include <err.h>
#include <stdio.h>
#include <stdlib.h>

struct node {
	RB_ENTRY(node) entry;
	int i;
};

int	intcmp(struct node *, struct node *);
void	print_tree(struct node *);

int
intcmp(struct node *e1, struct node *e2)
{
	return (e1->i < e2->i ? -1 : e1->i > e2->i);
}

RB_HEAD(inttree, node) head = RB_INITIALIZER(&head);
RB_PROTOTYPE(inttree, node, entry, intcmp)
RB_GENERATE(inttree, node, entry, intcmp)

int testdata[] = {
	20, 16, 17, 13, 3, 6, 1, 8, 2, 4, 10, 19, 5, 9, 12, 15, 18,
	7, 11, 14
};

void
print_tree(struct node *n)
{
	struct node *left, *right;

	if (n == NULL) {
		printf("nil");
		return;
	}
	left = RB_LEFT(n, entry);
	right = RB_RIGHT(n, entry);
	if (left == NULL && right == NULL)
		printf("%d", n->i);
	else {
		printf("%d(", n->i);
		print_tree(left);
		printf(",");
		print_tree(right);
		printf(")");
	}
}

int
main(void)
{
	int i;
	struct node *n;

	for (i = 0; i < sizeof(testdata) / sizeof(testdata[0]); i++) {
		if ((n = malloc(sizeof(struct node))) == NULL)
			err(1, NULL);
		n->i = testdata[i];
		RB_INSERT(inttree, &head, n);
	}

	RB_FOREACH(n, inttree, &head) {
		printf("%d\n", n->i);
	}
	print_tree(RB_ROOT(&head));
	printf("\n");
	return (0);
}

HISTORY

The tree macros first appeared in FreeBSD 4.6.

NOTES

Trying to free a tree in the following way is a common error:

SPLAY_FOREACH(var, NAME, &head) {
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
free(head);

Since var is free'd, the FOREACH() macro refers to a pointer that may have been reallocated already. Proper code needs a second variable.

for (var = SPLAY_MIN(NAME, &head); var != NULL; var = nxt) {
	nxt = SPLAY_NEXT(NAME, &head, var);
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
