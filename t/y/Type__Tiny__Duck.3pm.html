Type__Tiny__Duck(3pm)

الحزمة: perl-type-tiny

التراخيص: PerlArtistic, GPL

Type::Tiny::Duck(3) وثائق Perl مساهمة من المستخدم Type::Tiny::Duck(3)

الاسم

Type::Tiny::Duck - قيود النوع بناءً على الطريقة "can"

الملخص

الاستخدام عبر Types::Standard:

package Logger {
  use Moo;
  use Types::Standard qw( HasMethods Bool );

  has debugging => ( is => 'rw', isa => Bool, default => 0 );
  has output    => ( is => 'ro', isa => HasMethods[ 'print' ] );

  sub warn {
    my ( $self, $message ) = @_;
    $self->output->print( "[WARNING] $message\n" );
  }

  sub debug {
    my ( $self, $message ) = @_;
    $self->output->print( "[DEBUG] $message\n" ) if $self->debugging;
  }
}

الاستخدام عبر ميزة التصدير الخاصة بـ Type::Tiny::Duck:

package Logger {
  use Moo;
  use Types::Standard qw( Bool );
  use Type::Tiny::Duck Printable => [ 'print' ];

  has debugging => ( is => 'rw', isa => Bool, default => 0 );
  has output    => ( is => 'ro', isa => Printable );

  sub warn {
    my ( $self, $message ) = @_;
    $self->output->print( "[WARNING] $message\n" );
  }

  sub debug {
    my ( $self, $message ) = @_;
    $self->output->print( "[DEBUG] $message\n" ) if $self->debugging;
  }
}

الاستخدام عبر الواجهة الموجهة للكائنات في Type::Tiny::Duck:

package Logger {
  use Moo;
  use Types::Standard qw( Bool );
  use Type::Tiny::Duck;

  my $Printable = Type::Type::Duck->new(
    name    => 'Printable',
    methods => [ 'print' ],
  );

  has debugging => ( is => 'rw', isa => Bool, default => 0 );
  has output    => ( is => 'ro', isa => $Printable );

  sub warn {
    my ( $self, $message ) = @_;
    $self->output->print( "[WARNING] $message\n" );
  }

  sub debug {
    my ( $self, $message ) = @_;
    $self->output->print( "[DEBUG] $message\n" ) if $self->debugging;
  }
}

الحالة

هذه الوحدة مغطاة بسياسة استقرار Type-Tiny.

الوصف

قيود النوع من الشكل العام "{ $_->can("method") }".

يشير الاسم إلى القول المأثور: "إذا بدا كبطة، وسبح كبطة، وصاح كبطة، فهو على الأرجح بطة". يمكن أن يكون التنميط الكاذب طريقة أكثر مرونة لاختبار الكائنات من الاعتماد على "isa"، حيث يسمح للناس باستبدال الكائنات الوهمية بسهولة.

ترث هذه الحزمة من Type::Tiny؛ انظر تلك الوثائق لمعظم التوثيق. الاختلافات الرئيسية مدرجة أدناه:

البانيات

لا يزال الباني "new" من Type::Tiny يعمل، بالطبع. ولكن هناك أيضًا:

"new_intersection( type_constraints => \@ducklings, %opts )"
ينشئ قيد نوع بطة جديد يمثل تقاطع قيود نوع بطة موجودة. هذا يسمح بتقاطع "HasMethods['read']" و "HasMethods['write']" بأن يكون ببساطة "HasMethods['read', 'write']" بدلاً من قيد نوع مركب معقد مع قيود نوع بطة أخرى كأبناء له.

السمات

"methods"
مصفوفة بأسماء الطرق.
"constraint"
بخلاف Type::Tiny، لا يمكنك تمرير رمز تقييد إلى الباني. بدلاً من ذلك، اعتمد على الافتراضي.
"inlined"
بخلاف Type::Tiny، لا يمكنك تمرير رمز تضمين إلى الباني. بدلاً من ذلك، اعتمد على الافتراضي.
"parent"
الأصل هو دائمًا Types::Standard::Object، ولا يمكن تمريره إلى الباني.

الطرق

stringifies_to($constraint)
انظر Type::Tiny::ConstrainedObject.
numifies_to($constraint)
انظر Type::Tiny::ConstrainedObject.
"with_attribute_values($attr1 => $constraint1, ...)"
انظر Type::Tiny::ConstrainedObject.

التصديرات

يمكن استخدام Type::Tiny::Duck كمصدر.

use Type::Tiny::Duck HttpClient => [ 'get', 'post' ];

سيقوم هذا بتصدير الوظائف التالية إلى مساحة اسمك:

"HttpClient"
is_HttpClient( $value )
assert_HttpClient( $value )
to_HttpClient( $value )

يمكن تصدير أنواع متعددة في وقت واحد:

use Type::Tiny::Duck (
  HttpClient   => [ 'get', 'post' ],
  FtpClient    => [ 'upload', 'download' ],
);
