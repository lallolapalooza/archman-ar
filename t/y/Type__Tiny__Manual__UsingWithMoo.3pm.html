is => 'ro', isa => ArrayRef[ Tuple[ PositiveInt, NonEmptyStr, Optional[NonEmptyStr] ] ], default => sub { return [] }, );

العنصر الثالث سيتم التحقق منه إذا كان موجودًا، ولكن سيتم التسامح معه إذا كان غائبًا.

أو يمكننا ببساطة السماح للـ tuples بتضمين قائمة عشوائية من السلاسل النصية بعد السنة واسم السباق:

use Types::Standard qw( ArrayRef Tuple Str Slurpy );
use Types::Common::Numeric qw( PositiveInt );
use Types::Common::String qw( NonEmptyStr );

has wins => (
  is      => 'ro',
  isa     => ArrayRef[
    Tuple[ PositiveInt, NonEmptyStr, Slurpy[ ArrayRef[Str] ] ]
  ],
  default => sub { return [] },
);

سيقوم النوع Slurpy[ ArrayRef[Str] ] "بشفط" جميع العناصر المتبقية في الـ tuple إلى arrayref والتحقق منه مقابل ArrayRef[Str].

من الممكن حتى القيام بذلك:

use Types::Standard qw( ArrayRef Tuple Any Slurpy );
use Types::Common::Numeric qw( PositiveInt );
use Types::Common::String qw( NonEmptyStr );

has wins => (
  is      => 'ro',
  isa     => ArrayRef[
    Tuple[ PositiveInt, NonEmptyStr, Slurpy[Any] ]
  ],
  default => sub { return [] },
);

مع قيد النوع هذا، سيتم شفط أي عناصر بعد العنصرين الأولين إلى arrayref ولن نتحقق من هذا الـ arrayref على الإطلاق. (في الواقع، تنفيذ نوع Tuple ذكي بما يكفي لعدم إزعاج إنشاء الـ arrayref المؤقت للتحقق.)

Dict هو المكافئ لـ Tuple للتحقق من قيم الـ hashrefs.

use Types::Standard qw( ArrayRef Dict Optional );
use Types::Common::Numeric qw( PositiveInt );
use Types::Common::String qw( NonEmptyStr );

has wins => (
  is      => 'ro',
  isa     => ArrayRef[
    Dict[
      year    => PositiveInt,
      race    => NonEmptyStr,
      jockey  => Optional[NonEmptyStr],
    ],
  ],
  default => sub { return [] },
);

مثال على استخدامه:

my $br = Horse->new(
  name    => "Bold Ruler",
  wins    => [
    { year => 1956, race => "Futurity Stakes", jockey => "Eddie" },
    { year => 1956, race => "Juvenile Stakes" },
  ],
);

يعمل النوع Slurpy مع Dict أيضًا:

Dict[
  year    => PositiveInt,
  race    => NonEmptyStr,
  jockey  => Optional[NonEmptyStr],
  ()      => Slurpy[ HashRef[Str] ],  # تسمح بقيم Str أخرى
]

و "Slurpy[Any]" يعني ما تتوقعه على الأرجح:

Dict[
  year    => PositiveInt,
  race    => NonEmptyStr,
  jockey  => Optional[NonEmptyStr],
  ()      => Slurpy[Any], # تسمح للـ hashref باحتواء أي شيء آخر على الإطلاق
]

بالعودة إلى مثالنا الأول، هناك فرصة لتحسين قيد ArrayRef الخاص بنا:

package Horse {
  use Moo;
  use Types::Standard qw( Str Num ArrayRef );
  use namespace::autoclean;

  has name       => ( is => 'ro', isa => Str );
  has gender     => ( is => 'ro', isa => Str );
  has age        => ( is => 'rw', isa => Num );
  has children   => (
    is      => 'ro',
    isa     => ArrayRef[ InstanceOf["Horse"] ],
    default => sub { return [] },
  );
}

قيد النوع InstanceOf["Horse"] يتحقق من أن القيمة هي كائن مقدس في فئة Horse. لذا يجب أن يكون أطفال الحصان arrayref من كائنات Horse أخرى.

داخليًا، يتحقق فقط من "$_->isa("Horse")" على كل عنصر في الـ arrayref.

من المفيد أحيانًا بدلاً من ذلك التحقق من "$_->DOES($role)" أو "$_->can($method)" على كائن. على سبيل المثال:

package MyAPI::Client {
  use Moo;
  use Types::Standard qw( HasMethods );

  has ua => (is => 'ro', isa => HasMethods["get", "post"] );
}

تسمح أنواع ConsumerOf و HasMethods القابلة للمعلمات بالتحقق بسهولة من الأدوار والطرق للكائنات.

يسمح النوع القابل للمعلمات Enum بقبول مجموعة محدودة أكثر من قيم السلاسل النصية. على سبيل المثال:

use Types::Standard qw( Enum );
has gender => ( is => 'ro', isa => Enum["m","f"] );

أو إذا كنت تريد مزيدًا من المرونة، يمكنك استخدام StrMatch الذي يسمح لك باختبار السلاسل النصية مقابل تعبير عادي:

use Types::Standard qw( StrMatch );
has gender => ( is => 'ro', isa => StrMatch[qr/^[MF]/i] );

أو StrLength للتحقق من الحد الأقصى والأدنى لطول السلسلة النصية:

use Types::Common::String qw( StrLength );
has name => ( is => 'ro', isa => StrLength[3, 100] );

يمكن حذف الحد الأقصى.

وبالمثل، يمكن التعبير عن القيم القصوى والدنيا لنوع رقمي باستخدام IntRange و NumRange:

use Types::Common::Numeric qw( IntRange );
# القيم التي تزيد عن 200 قد تكون خطأ في الإدخال
has age => ( is => 'ro', isa => IntRange[0, 200] );

تعد قيود الأنواع القابلة للمعلمات واحدة من أقوى ميزات Type::Tiny، مما يسمح بدمج مجموعة صغيرة من القيود بطرق مفيدة.

تحويلات الأنواع (Type Coercions)

غالبًا ما تكون الممارسة الجيدة هي أن تكون ليبراليًا فيما تقبله.

package Horse {
  use Moo;
  use Types::Standard qw( Str Num ArrayRef Bool );
  use namespace::autoclean;

  ...;  # name, gender, age, children, wins
  has is_alive => ( is => 'rw', isa => Bool, coerce => 1 );
}

الخيار "coerce" يشير إلى أنه إذا تم تقديم قيمة لا تمر بقيد النوع Bool، فيجب تحويلها (تحويلها) إلى شيء يمر.

تعريف Bool يقول أنه لتحويل قيمة غير منطقية إلى قيمة منطقية، ما عليك سوى القيام بـ "!! $non_bool". لذا، كل ما يلي سيشير إلى أن الخيول على قيد الحياة:

Horse->new(is_alive => 42)
Horse->new(is_alive => [])
Horse->new(is_alive => "false") # في Perl، السلسلة النصية "false" صحيحة!

Bool هو قيد النوع الوحيد في Types::Standard الذي لديه تحويل معرف له. الأنواع NumericCode، UpperCaseStr، LowerCaseStr، UpperCaseSimpleStr، و LowerCaseSimpleStr من Types::Common::String لديها أيضًا تحويلات معرفة.

القيود المضمنة الأخرى لا تعرف أي تحويلات لأنه سيكون من الصعب الاتفاق على ما يعنيه التحويل من، على سبيل المثال، HashRef إلى ArrayRef. هل نحتفظ بالمفاتيح؟ القيم؟ كلاهما؟

ولكن من السهل جدًا إضافة تحويلاتك الخاصة!

use Types::Standard qw( ArrayRef HashRef Str );
has things => (
  is     => 'rw',
  isa    => ArrayRef->plus_coercions(
    HashRef,     sub { [ values %$_ ] },
    Str,         sub { [ split /;/, $_ ] },
  ),
  coerce => 1,
);

(لا تنسى أبدًا "coerce => 1"!)

إذا تم تقديم hashref، فسيتم استخدام القيم، وإذا تم تقديم سلسلة نصية، فسيتم تقسيمها على الفاصلة المنقوطة. بالطبع، إذا تم تقديم arrayref، فإنه يمر بالفعل بقيد النوع، لذا لا يلزم إجراء أي تحويل.

يجب أن تكون التحويلات أزواجًا من "أنواع من" ورموز لتحويل القيمة. يمكن أن يكون الرمز عبارة عن coderef (كما هو موضح أعلاه) أو مجرد سلسلة من رمز Perl (كما هو موضح أدناه). يمكن تحسين السلاسل النصية من رمز Perl عادةً بشكل أفضل بواسطة داخليات Type::Tiny، لذا فهي مفضلة بشكل عام. بفضل عامل التشغيل "q{...}" في Perl، يمكن أن تبدو نظيفة وجميلة مثل الـ coderefs.

use Types::Standard qw( ArrayRef HashRef Str );
has things => (
  is     => 'rw',
  isa    => ArrayRef->plus_coercions(
    HashRef,     q{ [ values %$_ ] },
    Str,         q{ [ split /;/, $_ ] },
  ),
  coerce => 1,
);

يتم تطبيق التحويلات بعمق تلقائيًا، لذا فإن ما يلي سيفعل ما تتوقعه.

has inputs => (
  is     => 'ro',
  isa    => ArrayRef->of(Bool),
  coerce => 1
);

أنا، بالطبع، أفترض أنك تتوقع شيئًا مثل:

my $coerced = [ map { !!$_ } @$orig ];

إذا كنت تفترض ذلك، تهانينا! نحن على نفس الموجة.

وبالطبع لا يزال بإمكانك إضافة المزيد من التحويلات إلى التحويلات الموروثة...

has inputs => (
  is     => 'ro',
  isa    => ArrayRef->of(Bool)->plus_coercions(Str, sub {...}),
  coerce => 1
);

الافتراضات للأنواع (Type Defaults)

شمل مثال سابق:

has children => (
  is      => 'ro',
  isa     => ArrayRef,
  default => sub { return [] },
);

إنه في الواقع شائع جدًا أنك سترغب في أن يرجع سمة arrayref افتراضيًا إلى أن يكون arrayref فارغًا، وسمة رقمية أن ترجع افتراضيًا إلى الصفر، وما إلى ذلك. يوفر Type::Tiny طريقة لذلك:

has children => (
  is      => 'ro',
  isa     => ArrayRef,
  default => ArrayRef->type_default,
);

العديد من الأنواع في Types::Standard لديها افتراضات أنواع معقولة معرفة.

معلمات الأساليب (Method Parameters)

حتى الآن ركزنا فقط على تعريف سمات الكائنات، ولكن قيود الأنواع مفيدة أيضًا للتحقق من معلمات الأساليب.

دعنا نتذكر السمة الخاصة بنا لتتبع انتصارات سباق الحصان:

use Types::Standard qw( ArrayRef Tuple Optional );
use Types::Common::Numeric qw( PositiveInt );
use Types::Common::String qw( NonEmptyStr );

has wins => (
  is      => 'ro',
  isa     => ArrayRef[
    Tuple[ PositiveInt, NonEmptyStr, Optional[NonEmptyStr] ]
  ],
  default => sub { return [] },
);

نظرًا لأننا لا نثق في الكود الخارجي لدفع إدخالات جديدة إلى هذه المصفوفة، دعنا نحدد طريقة في فئتنا للقيام بذلك.

package Horse {
  ...;

    my $win = [
      $year,
      $race,
      $jockey ? $jockey : (),

    push $self->wins->@*, $win;
    return $self;
  }
}
