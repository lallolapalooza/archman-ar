Type__Tiny__Bitfield(3pm)

الحزمة: perl-type-tiny

التراخيص: PerlArtistic, GPL

Type::Tiny::Bitfield(3) توثيق Perl من مساهمة المستخدم Type::Tiny::Bitfield(3)

الاسم

Type::Tiny::Bitfield - قيود نوع الحقل الثنائي/علم البت

الملخص

استخدام ميزة تصدير Type::Tiny::Bitfield:

package LightSource {
  use Moo;

  use Type::Tiny::Bitfield LedSet => {
    RED   => 1,
    GREEN => 2,
    BLUE  => 4,
  };

  has leds => ( is => 'ro', isa => LedSet, default => 0, coerce => 1 );

  sub new_red {
    my $class = shift;
    return $class->new( leds => LEDSET_RED );
  }

  sub new_green {
    my $class = shift;
    return $class->new( leds => LEDSET_GREEN );
  }

  sub new_yellow {
    my $class = shift;
    return $class->new( leds => LEDSET_RED | LEDSET_GREEN );
  }
}

استخدام الواجهة الشيئية لـ Type::Tiny::Bitfield:

package LightSource {
  use Moo;
  use Type::Tiny::Bitfield;

  my $LedSet = Type::Tiny::Bitfield->new(
    name   => 'LedSet',
    values => {
      RED   => 1,
      GREEN => 2,
      BLUE  => 4,
    },
    coercion => 1,
  );

  has leds => ( is => 'ro', isa => $LedSet, default => 0, coerce => 1 );

  sub new_red {
    my $class = shift;
    return $class->new( leds => $LedSet->RED );
  }

  sub new_green {
    my $class = shift;
    return $class->new( leds => $LedSet->GREEN );
  }

  sub new_yellow {
    my $class = shift;
    return $class->new( leds => $LedSet->coerce('red|green') );
  }
}

الحالة

تخضع هذه الوحدة لسياسة استقرار Type-Tiny.

الوصف

قيود نوع الحقل الثنائي.

هذه الحزمة ترث من Type::Tiny؛ راجع تلك لتوثيق معظم الأشياء. الاختلافات الرئيسية مدرجة أدناه:

السمات

"values"
هاشفريت للبتات المسموح بها في الحقل الثنائي. يجب أن تكون المفاتيح سلاسل UPPER_SNAKE_CASE. يجب أن تكون القيم أعدادًا صحيحة موجبة وهي قوى للعدد 2. لا يمكن استخدام نفس الرقم عدة مرات.
"constraint"
بخلاف Type::Tiny، لا يمكنك تمرير دالة قيد إلى المنشئ. اعتمد بدلاً من ذلك على الافتراضي.
"inlined"
بخلاف Type::Tiny، لا يمكنك تمرير دالة تضمين إلى المنشئ. اعتمد بدلاً من ذلك على الافتراضي.
"parent"
الأب دائمًا Types::Common::Numeric::PositiveOrZeroInt، ولا يمكن تمريره إلى المنشئ.
"coercion"
إذا تم تمرير "coercion => 1" إلى المنشئ، فسيكون لنوع النوع تحويل تلقائي من Str. ستتضمن الأنواع التي تم إنشاؤها بواسطة طريقة "import" دائمًا "coercion => 1".

في مثال الملخص، سيقبل التحويل من Str سلاسل مثل:

"RED"
"red"
"Red Green"
"Red+Blue"
"blue | GREEN"
"LEDSET_RED + LeDsEt_green"

الطرق

تستخدم هذه الفئة "AUTOLOAD" للسماح باستخدام أسماء كل بت في الحقل الثنائي كطرق. ستكون أسماء هذه الطرق دائمًا UPPER_SNAKE_CASE.

على سبيل المثال، في الملخص، "LedSet->GREEN" ستعيد 2.

طرق أخرى توفرها:

from_string( $str )
توفر التحويل القياسي من سلسلة نصية، حتى لو لم يكن لقيد النوع هذا تحويل.
to_string( $int )
يقوم بالتحويل العكسي.
constant_names()
هذه طريقة ملائمة للسماح بما يلي: 
use base 'Exporter::Tiny';
push our @EXPORT_OK, LineStyle->constant_names;

التصدير

يمكن استخدام Type::Tiny::Bitfield كمصدر.

use Type::Tiny::Bitfield LedSet => {
  RED    => 1,
  GREEN  => 2,
  BLUE   => 4,
};

سيقوم هذا بتصدير الوظائف التالية إلى مساحة الاسم الخاصة بك:

"LedSet"
is_LedSet( $value )
assert_LedSet( $value )
to_LedSet( $string )
LedSet_to_Str( $value )
"LEDSET_RED"
"LEDSET_GREEN"
"LEDSET_BLUE"

يمكن تصدير أنواع حقول ثنائية متعددة دفعة واحدة:

use Type::Tiny::Enum (
  LedSet     => { RED => 1, GREEN => 2, BLUE => 4 },
  LedPattern => { FLASHING => 1 },
);

التحميل الزائد

من الممكن دمج نوعي Bitfield باستخدام العامل "+".

use Type::Tiny::Enum (
  LedSet     => { RED => 1, GREEN => 2, BLUE => 4 },
  LedPattern => { FLASHING => 8 },
);

has leds => (
  is      => 'ro',
  isa     => LedSet + LedPattern,
  default => 0,
  coerce  => 1
);

سيسمح هذا بقيم مثل "11" (LEDSET_RED|LEDSET_GREEN|LEDPATTERN_FLASHING).

سيتم طرح استثناء إذا تعارضت أي من الأسماء في النوعين اللذين يتم دمجهما.
