NAME

Type::Tiny::Manual::UsingWithMoo2 - advanced use of Type::Tiny\n with Moo

MANUAL

\n
\n

What is a Type?

\n

So far all the examples have shown you how to work with types, but\n we haven't looked at what a type actually is.

\n
use Types::Standard qw( Int );\nmy $type = Int;
\n

"Int" in the above code is just\n a function called with zero arguments which returns a blessed Perl object.\n It is this object that defines what the Int type is and is\n responsible for checking values meet its definition.

\n
use Types::Standard qw( HashRef Int );\nmy $type = HashRef[Int];
\n

The "HashRef" function, if\n called with no parameters returns the object defining the HashRef\n type, just like the "Int" function did\n before. But the difference here is that it's called with a parameter, an\n arrayref containing the Int type object. It uses this to make the\n HashRef[Int] type and returns that.

\n

Like any object, you can call methods on it. The most important\n methods to know about are:

\n
# check the value and return a boolean\n#\n$type->check($value);\n\n# return an error message about $value failing the type check\n# but don't actually check the value\n#\n$type->get_message($value);\n\n# coerce the value\n#\nmy $coerced = $type->coerce($value);
\n

We've already seen some other methods earlier in the tutorial.

\n
# create a new type, same as the old type, but that has coercions\n#\nmy $new_type = $type->plus_coercions( ... );\n\n# different syntax for parameterized types\n#\nmy $href = HashRef;\nmy $int = Int;\nmy $href_of_int = $href->of($int);
\n

So now you should understand this:

\n
use Types::Standard qw( ArrayRef Dict Optional );\nuse Types::Common::Numeric qw( PositiveInt );\nuse Types::Common::String qw( NonEmptyStr );\n\nmy $RaceInfo = Dict[\n  year    => PositiveInt,\n  race    => NonEmptyStr,\n  jockey  => Optional[NonEmptyStr],\n];\n\nhas latest_event  => ( is => 'rw', isa => $RaceInfo );\nhas wins          => ( is => 'rw', isa => ArrayRef[$RaceInfo] );\nhas losses        => ( is => 'rw', isa => ArrayRef[$RaceInfo] );
\n

This can help you avoid repetition if you have a complex\n parameterized type that you need to reuse a few times.

\n
\n
\n

"where"

\n

One of the most useful methods you can call on a type object is\n "where".

\n
use Types::Standard qw( Int );\n\nhas lucky_number => (\n  is   => 'ro',\n  isa  => Int->where(sub { $_ != 13 }),\n);\n
\n

I think you already understand what it does. It creates a new type\n constraint on the fly, restricting the original type.

\n

Like with coercions, these restrictions can be expressed as a\n coderef or as a string of Perl code, operating on the\n $_ variable. And like with coercions, using a string\n of code will result in better performance.

\n
use Types::Standard qw( Int );\n\nhas lucky_number => (\n  is   => 'ro',\n  isa  => Int->where(q{ $_ != 13 }),\n);\n
\n

Let's coerce a hashref of strings from an even-sized arrayref of\n strings:

\n
use Types::Standard qw( HashRef ArrayRef Str );\n\nhas stringhash => (\n  is   => 'ro',\n  isa  => HashRef->of(Str)->plus_coercions(\n    ArrayRef->of(Str)->where(q{ @$_ % 2 == 0 }), q{\n      my %h = @$_;\n      \%h;\n    },\n  ),\n  coerce => 1,  # never forget!\n);\n
\n

If you understand that, you really are in the advanced class.\n Congratulations!

\n

\n

Unions

\n

Sometimes you want to accept one thing or another thing. This is\n pretty easy with Type::Tiny.

\n
use Types::Standard qw( HashRef ArrayRef Str );\n\nhas strings => (\n  is    => 'ro',\n  isa   => ArrayRef[Str] | HashRef[Str],\n);\n
\n

Type::Tiny overloads the bitwise or operator so stuff like this\n should "just work".

\n

That said, now any code that calls\n "$self->strings" will probably need to\n check if the value is an arrayref or a hashref before doing anything with\n it. So it may be simpler overall if you just choose one of the options and\n coerce the other one into it.

\n
\n
\n

Intersections

\n

Similar to a union is an intersection.

\n
package MyAPI::Client {\n  use Moo;\n  use Types::Standard qw( HasMethods InstanceOf );\n\n  has ua => (\n    is    => 'ro',\n    isa   => (InstanceOf["MyUA"]) & (HasMethods["store_cookie"]),\n  );\n}\n
\n

Here we are checking that the UA is an instance of the MyUA class\n and also offers the "store_cookie" method.\n Perhaps "store_cookie" isn't provided by\n the MyUA class itself, but several subclasses of MyUA provide it.

\n

Intersections are not useful as often as unions are. This is\n because they often make no sense. "(ArrayRef) &\n (HashRef)" would be a reference which was simultaneously\n pointing to an array and a hash, which is impossible.

\n

Note that when using intersections, it is good practice to put\n parentheses around each type. This is to disambiguate the meaning of\n "&" for Perl, because Perl uses it as\n the bitwise and operator but also as the sigil for subs.

\n
\n
\n

Complements

\n

For any type Foo there is a complementary type ~Foo\n (pronounced "not Foo").

\n
package My::Class {\n  use Moo;\n  use Types::Standard qw( ArrayRef CodeRef );\n\n  has things => ( is => 'ro', isa => ArrayRef[~CodeRef] );\n}\n
\n

"things" is now an arrayref of\n anything except coderefs.

\n

If you need a number that is not an integer:

\n
Num & ~Int
\n

Types::Standard includes two types which are complements of each\n other: Undef and Defined.

\n

NegativeInt might seem to be the complement of\n PositiveOrZeroInt but when you think about it, it is not. There are\n values that fall into neither category, such as non-integers, non-numeric\n strings, references, undef, etc.

"stringifies_to" and "numifies_to"

\n

The Object type constraint provides\n "stringifies_to" and\n "numifies_to" methods which are probably\n best explained by examples.

\n

"Object->numifies_to(Int)"\n means any object where "0 + $object" is an\n integer.

\n

"Object->stringifies_to(StrMatch[$re])"\n means any object where "$object" matches\n the regular expression.

\n

"Object->stringifies_to($re)"\n also works as a shortcut.

\n

"Object->numifies_to($coderef)"\n and "Object->stringifies_to($coderef)"\n also work, where the coderef checks $_ and returns a\n boolean.

\n

Other types which are also logically objects, such as\n parameterized HasMethods, InstanceOf, and ConsumerOf\n should also provide "stringifies_to" and\n "numifies_to" methods.

\n

"stringifies_to" and\n "numifies_to" work on unions if all\n of the type constraints in the union offer the method.

\n

"stringifies_to" and\n "numifies_to" work on intersections if\n at least one of of the type constraints in the intersection offers\n the method.
