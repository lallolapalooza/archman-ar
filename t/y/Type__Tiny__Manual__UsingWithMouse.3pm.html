Type::Tiny::Manual::UsingWithMouse(3) توثيق مساهمة المستخدم Type::Tiny::Manual::UsingWithMouse(3)

الاسم

Type::Tiny::Manual::UsingWithMouse - كيفية استخدام Type::Tiny مع Mouse

دليل

اقرأ أولاً Type::Tiny::Manual::UsingWithMoo, Type::Tiny::Manual::UsingWithMoo2, و Type::Tiny::Manual::UsingWithMoo3. كل شيء في هذه الأجزاء من الدليل يجب أن يعمل بنفس الطريقة تمامًا في Mouse.

هذا الجزء من الدليل سيركز على الأمور الخاصة بـ Mouse.

بشكل عام، Type::Tiny أقل اختبارًا مع Mouse مقارنة بـ Moose و Moo، ولكن لا يزال هناك عدد جيد من حالات الاختبار لاستخدام Type::Tiny مع Mouse، ولا توجد مشكلات رئيسية معروفة في دعم Type::Tiny لـ Mouse.

لماذا نستخدم Type::Tiny على الإطلاق؟

يمتلك Mouse نظام قيود النوع الخاص به المدمج وهو مناسب تمامًا للاستخدام، ولكن هناك عدة أسباب قد تدفعك للتفكير في استخدام Type::Tiny بدلاً منه.

  • يوفر Type::Tiny طرقًا مفيدة مثل "where" و "plus_coercions" التي تسمح بتعديل قيود النوع والتحويلات بسهولة لكل سمة على حدة.

    شيء كهذا أصعب بكثير مع أنواع Mouse العادية:

    has name => (
  is      => "ro",
  isa     => Str->plus_coercions(
    ArrayRef[Str], sub { join " ", @$_ },
  ),
  coerce  => 1,
);

    يميل Mouse إلى تشجيع تعريف التحويلات بشكل عام، لذلك إذا كنت تريد أن يتمكن سمة Str واحدة من التحويل من ArrayRef[Str]، فإن جميع سمات Str سيتم تحويلها من ArrayRef[Str]، وسيقومون جميعًا بهذا التحويل بنفس الطريقة. (حتى لو كان من المنطقي الانضمام بمسافة في بعض الأماكن، وفاصلة في أخرى، وفاصل سطر في أماكن أخرى!)

  • يوفر Type::Tiny تحويلات عميقة تلقائية، لذا إذا كان النوع Xyz يحتوي على تحويل، فيجب أن يعمل ما يلي "بشكل طبيعي": 
    has xyzlist => ( is => 'ro', isa => ArrayRef[Xyz], coerce => 1 );
  • يقدم Type::Tiny مجموعة أوسع من الأنواع المدمجة.
  • باستخدام Type::Tiny، يمكنك استخدام نفس قيود النوع والتحويلات للسمات ومعلمات التوابع، في كود Mouse وغير كود Mouse.

Type::Utils

إذا كنت قد استخدمت Mouse::Util::TypeConstraints، فقد تكون معتادًا على استخدام DSL (لغة خاصة بالمجال) لتحديد قيود النوع:

use Mouse::Util::TypeConstraints;

subtype 'Natural',
  as 'Int',
  where { $_ > 0 };

هناك وحدة تسمى Type::Utils توفر DSL مشابهًا جدًا لتحديد الأنواع في مكتبات الأنواع المستندة إلى Type::Library.

package My::Types {
  use Type::Library -base;
  use Type::Utils;
  use Types::Standard qw( Int );

  declare 'Natural',
    as Int,
    where { $_ > 0 };
}

شخصيًا، أفضل الطريقة الأكثر توجهًا نحو الكائنات لتحديد الأنواع.

في Mouse، قد تحدد الأنواع أيضًا بهذه الطريقة ضمن الفئات والأدوار أيضًا. على عكس Mouse، لا يحتفظ Type::Tiny بالأنواع في مساحة اسم مسطحة عالمية واحدة، لذلك لا يعمل هذا بنفس الطريقة تمامًا مع Type::Utils. لا يزال ينشئ النوع، ولكنه لا يخزنه في أي مكتبة أنواع؛ يتم إرجاع النوع.

package My::Class {
  use Mouse;
  use Type::Utils;
  use Types::Standard qw( Int );

  my $Natural =          # تخزين النوع في متغير
    declare 'Natural',
    as Int,
    where { $_ > 0 };

  has number => ( is => 'ro', isa => $Natural );
}

ولكن حقًا، أليست الطريقة الموجهة نحو الكائنات أكثر وضوحًا؟

package My::Class {
  use Mouse;
  use Types::Standard qw( Int );

  has number => (
    is   => 'ro',
    isa  => Int->where('$_ > 0'),
  );
}

Type::Tiny و MouseX::Types

يجب أن يكون Types::Standard بديلاً مباشرًا لـ MooseX::Types. ويجب أن تحل Types::Common::Numeric و Types::Common::String بسهولة محل MouseX::Types::Common::Numeric و MouseX::Types::Common::String.

ومع ذلك، إذا كنت ترغب في استخدام مزيج من Type::Tiny و MouseX::Types، فيجب أن تتناسب مع بعضها البعض بسلاسة.

use Types::Standard qw( ArrayRef );
use MouseX::Types::Mouse qw( Int );

# يجب أن يعمل هذا ببساطة
my $list_of_nums = ArrayRef[Int];

# وهذا أيضًا
my $list_or_num = ArrayRef | Int;

معلمة الاستيراد "-mouse"

إذا كنت قد قرأت حتى هذه النقطة في الدليل، فستعرف أن هذه هي الطريقة المعتادة لاستيراد قيود النوع:

use Types::Standard qw( Int );

و "Int" الذي تم استيراده هو وظيفة لا تأخذ أي وسائط وتعيد قيد النوع Int، وهو كائن مبارك في فئة Type::Tiny.

يقوم Type::Tiny بمحاكاة واجهة برمجة تطبيقات Mouse::Meta::TypeConstraint بشكل جيد لدرجة أن معظم كود Mouse و MouseX لن يتمكن من التمييز.

ولكن ماذا لو كنت بحاجة إلى كائن Mouse::Meta::TypeConstraint حقيقي؟

use Types::Standard -mouse, qw( Int );

الآن، الوظيفة "Int" التي تم استيرادها ستعيد قيد نوع Mouse أصليًا.

هذه العلامة هي في الغالب إشارة إلى الماضي عندما لم تعمل كائنات Mouse الأصلية في Type::Tiny مباشرة في Mouse. في 99.9٪ من الحالات، لا يوجد سبب لاستخدامه والعديد من الأسباب لعدم استخدامه. (قيود نوع Mouse الأصلية لا تقدم طرقًا مفيدة مثل "plus_coercions" و "where".)

طريقة "mouse_type"

طريقة أخرى سريعة للحصول على كائن قيد نوع Mouse أصلي من كائن Type::Tiny هي استدعاء طريقة "mouse_type":

use Types::Standard qw( Int );

my $tiny_type   = Int;
my $mouse_type  = $tiny_type->mouse_type;

داخليًا، هذا هو ما تفعله علامة "-mouse" للوظائف المستوردة.

أداء Type::Tiny

يجب أن يعمل Type::Tiny بنفس سرعة أنواع Mouse تقريبًا. هذا لأنه، عند الإمكان، سيستخدم تطبيقات XS الخاصة بـ Mouse لفحوصات الأنواع للقيام بالعمل الثقيل.

هناك عدد قليل من قيود النوع التي يفضل Type::Tiny القيام بها دون مساعدة Mouse، من أجل الاتساق والصحة. على سبيل المثال، تطبيق XS الخاص بـ Mouse لـ Bool غريب... فهو يقبل الكائنات المباركة التي تفرط في تحميل "bool"، ولكن فقط إذا أعادت قيمة خاطئة. إذا أعادت قيمة صحيحة، فهذا خطأ في قيد النوع.

استخدام Type::Tiny بدلاً من قيود النوع الخاصة بـ Mouse لا ينبغي أن يحدث فرقًا كبيرًا في أداء الكود الخاص بك.
