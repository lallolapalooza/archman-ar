Type__Tiny__Manual__Optimization(3pm)

الحزمة: perl-type-tiny

التراخيص: PerlArtistic, GPL

Type::Tiny::Manual::Optimization(3) وثائق Perl المساهمة من المستخدمين Type::Tiny::Manual::Optimization(3)

الاسم

Type::Tiny::Manual::Optimization - استخرج أقصى ما يمكن من وحدة المعالجة المركزية الخاصة بك

الدليل

كُتب Type::Tiny مع مراعاة الكفاءة، لكن هناك تقنيات يمكنك استخدامها للحصول على أفضل أداء منه.

XS

أبسط ما يمكنك فعله لزيادة أداء العديد من قيود الأنواع المدمجة هو تثبيت Type::Tiny::XS، وهي مجموعة من فحوصات قيود الأنواع فائقة السرعة المنفذة بلغة C.

سيحاول Type::Tiny تحميل Type::Tiny::XS واستخدام فحوصات الأنواع الخاصة به. إذا لم يكن Type::Tiny::XS متاحًا، فسيحاول بعد ذلك استخدام Mouse إذا كان محمّلًا بالفعل، لكن Type::Tiny لن يحاول تحميل Mouse نيابةً عنك.

يمكن أيضًا تسريع بعض قيود الأنواع إذا كان لديك Ref::Util::XS مثبتًا.

الأنواع التي يمكن تسريعها بواسطة Type::Tiny::XS

سيتم تسريع قيود الأنواع البسيطة التالية من Types::Standard بواسطة Type::Tiny::XS: Any وArrayRef وBool وClassName وCodeRef وDefined وFileHandle وGlobRef وHashRef وInt وItem وObject وMap وRef وScalarRef وStr وTuple وUndef وValue. (لاحظ أن Num وRegexpRef ليسا في تلك القائمة.)

لا يمكن تسريع الصيغة المُعاملة من Ref.

يمكن تسريع الصيغ المُعاملة من ArrayRef وHashRef وMap فقط إذا كانت معاملاتها قابلة للتسريع.

يمكن تسريع الصيغة المُعاملة من Tuple إذا كانت معاملاتها قابلة للتسريع، ولا تحتوي على مكونات Optional، ولا تستخدم Slurpy.

قد تستفيد بعض قيود الأنواع جزئيًا من Type::Tiny::XS. على سبيل المثال، يرث RoleName من ClassName، لذا سيُجرى جزء من فحص النوع بواسطة Type::Tiny::XS.

سيتم تسريع قيود الأنواع المُعاملة InstanceOf وHasMethods وEnum. وكذلك كائنات Type::Tiny::Class وType::Tiny::Duck وType::Tiny::Enum.

سيتم تسريع قيود الأنواع PositiveInt وPositiveOrZeroInt من Types::Common::Numeric، وكذلك قيد النوع NonEmptyStr من Types::Common::String.

سيتم تسريع الأنواع StringLike وCodeLike وHashLike وArrayLike من Types::TypeTiny، بما في ذلك الصيغ المُعاملة من HashLike وArrayLike.

سيتم أيضًا تسريع Type::Tiny::Union وType::Tiny::Intersection إذا كانت قيود الأنواع المكوّنة لهما قابلة للتسريع.

الأنواع التي يمكن تسريعها بواسطة Mouse

سيتم تسريع قيود الأنواع البسيطة التالية من Types::Standard بواسطة Type::Tiny::XS: Any وArrayRef وBool وClassName وCodeRef وDefined وFileHandle وGlobRef وHashRef وRef وScalarRef وStr وUndef وValue. (لاحظ أن Item وNum وInt وObject وRegexpRef ليست في تلك القائمة.)

لا يمكن تسريع الصيغة المُعاملة من Ref.

يمكن تسريع الصيغ المُعاملة من ArrayRef وHashRef فقط إذا كانت معاملاتها قابلة للتسريع.

قد تستفيد بعض قيود الأنواع جزئيًا من Mouse. على سبيل المثال، يرث RoleName من ClassName، لذا سيُجرى جزء من فحص النوع بواسطة Mouse.

سيتم تسريع قيود الأنواع المُعاملة InstanceOf وHasMethods. وكذلك كائنات Type::Tiny::Class وType::Tiny::Duck.

تضمين قيود الأنواع

في حالة قيد نوع كهذا:

my $type = Int->where( sub { $_ >= 0 } );

سيحتاج Type::Tiny إلى استدعاء دالة فرعية واحدة للتحقق من أن القيمة تستوفي قيد النوع Int، ودالتك المرجعية للتحقق من أن القيمة أكبر من الصفر.

استدعاءات الدوال الفرعية في Perl مكلفة نسبيًا من حيث الذاكرة واستخدام وحدة المعالجة المركزية، لذا سيكون من الجيد لو أمكن القيام بكل ذلك في استدعاء دالة فرعية واحد.

يعرف قيد النوع Int كيفية إنشاء سلسلة من كود Perl تتحقق من عدد صحيح. إنها شيء مثل ما يلي. (إنها في الواقع أكثر تعقيدًا، لكن هذا قريب بما يكفي كمثال.)

$_ =~ /^-?[0-9]+$/

إذا قدمت فحصك كسلسلة نصية بدلاً من دالة مرجعية، كهذا:

my $type = Int->where( q{ $_ >= 0 } );

فسيتمكن Type::Tiny من دمجهما في سلسلة واحدة:

( $_ =~ /^-?[0-9]+$/ ) && ( $_ >= 0 )

لذا سيتمكن Type::Tiny من فحص القيم في استدعاء دالة فرعية واحد. تقديم القيود كسلاسل نصية هو طريقة بسيطة وسهلة حقًا لتحسين فحوصات الأنواع.

لكن يمكن جعلها أكثر كفاءة. يحتاج Type::Tiny إلى توطين $_ ونسخ القيمة إليه للفحص أعلاه. إذا كنت تفحص ArrayRef[$type] فسيتم ذلك لكل عنصر من عناصر المصفوفة. يمكن جعل الأمور أكثر كفاءة إذا كان Type::Tiny قادرًا على الفحص مباشرة:

( $arrayref->[$i] =~ /^-?[0-9]+$/ ) && ( $arrayref->[$i] >= 0 )

يمكن القيام بذلك من خلال توفير دالة فرعية للتضمين. تُعطى الدالة الفرعية اسم متغير ويمكنها استخدامه في سلسلة الكود التي تولدها.

my $type = Type::Tiny->new(
  parent  => Int,
  inlined => sub ( $self, $varname ) {
    return sprintf(
      '(%s) && ( %s >= 0 )',
      $self->parent->inline_check( $varname ),
      $varname,
    );
  }
);

نظرًا لأنه من الشائع جدًا أن تريد استدعاء فحص التضمين الخاص بالوالد ودمج سلسلتك الخاصة معه باستخدام "&&"، يوفر Type::Tiny اختصارًا لذلك. فقط أعد قائمة من السلاسل النصية لدمجها معًا باستخدام "&&"، وإذا كانت الأولى "undef"، فسيملأ Type::Tiny الفراغ بفحص النوع الأب.

my $type = Type::Tiny->new(
  parent  => Int,
  inlined => sub ( $self, $varname ) {
    return ( undef, sprintf( '%s >= 0', $varname ) );
  },
);

هناك تحسين إضافي واحد يمكن تطبيقه على هذه الحالة بالذات. ستلاحظ أننا نتحقق من أن السلسلة تطابق "/^-?[0-9+]$/" ثم نتحقق من أنها أكبر من أو تساوي الصفر. لكن العدد الصحيح غير السالب لن يبدأ أبدًا بعلامة ناقص، لذا يمكننا تضمين الفحص إلى شيء مثل:

$_ =~ /^[0-9]+$/

بينما يمكن لفحص التضمين استدعاء فحص النوع الأب، إلا أنه غير مطلوب.

my $type = Type::Tiny->new(
  parent  => Int,
  inlined => sub ( $self, $varname ) {
    return sprintf( '%s =~ /^[0-9]+$/', $varname );
  }
);

إذا اخترت عدم استدعاء فحص النوع الأب، فيجب عليك التأكد من أن فحصك الخاص على الأقل بنفس الصرامة.

تضمين الإكراهات

Moo هي مجموعة أدوات البرمجة الكائنية الوحيدة التي تدعم بشكل كامل تضمين الإكراهات، لكن حتى بالنسبة لـ Moose وMouse، يمكن أن يساعد تقديم الإكراهات كسلاسل نصية Type::Tiny على تحسين ميزات الإكراه الخاصة به.

بالنسبة لـ Moo، إذا كنت تريد أن يكون إكراهك قابلًا للتضمين، فيجب أن تكون جميع الأنواع التي تُكره منها وإليها قابلة للتضمين، بالإضافة إلى أن الإكراه يجب أن يُعطى كسلسلة من كود Perl.

الحس السليم

من المحتمل أن يكون فحص قيد النوع HashRef[ArrayRef] أسرع من HashRef[ArrayRef[Num]]. إذا وجدت نفسك تستخدم قيود أنواع معقدة وبطيئة جدًا، فيجب أن تفكر في التبديل إلى قيود أبسط وأسرع. (رغم أن هذا يعني أنه عليك أن تضع ثقة أكبر قليلًا في المستدعي الخاص بك لعدم تزويدك ببيانات سيئة.)

(استثناء غير بديهي لذلك: على الرغم من أن Int أكثر تقييدًا من Num، إلا أن فحوصات Int ستعمل بشكل أسرع في معظم الظروف.)

Devel::StrictMode

أحد الاحتمالات هو استخدام فحوصات أنواع صارمة عند تشغيل اختبارات الإصدار الخاصة بك، وفحوصات أنواع أسرع وأكثر تسامحًا في أوقات أخرى. يمكن لـ Devel::StrictMode أن يجعل هذا أسهل.

يوفر هذا ثابتًا "STRICT" يشير إلى ما إذا كان كودك يعمل في "الوضع الصارم" بناءً على متغيرات بيئة معينة.

السمات

use Types::Standard qw( ArrayRef Num );
use Devel::StrictMode qw( STRICT );
has numbers => ( is => 'ro', isa => STRICT ? ArrayRef[Num] : ArrayRef, default => sub { [] }, );

من غير المستحسن القيام بذلك على السمات التي تحتوي على تحويلات لأن ذلك قد يؤدي إلى سلوك غير متسق وغير متوقع.

Type::Params

طريقة فعّالة جدًا تتجنب تجميع التوقيع تمامًا إذا كانت "STRICT" خاطئة:

use Types::Standard qw( Num Object );
use Type::Params qw( signature );
use Devel::StrictMode qw( STRICT );

sub add_number {
  state $check;
  STRICT and $check //= signature(
    method     => 1,
    positional => [ Num ],
  );

  my ( $self, $num ) = STRICT ? &$check : @_;

  push @{ $self->numbers }, $num;
  return $self;
}

مرة أخرى، عليك أن تكون حذرًا لضمان سلوك متسق إذا كنت تستخدم التحويلات أو القيم الافتراضية أو slurpies، إلخ.

طريقة أقل كفاءة، لكنها أكثر تصريحية وذكية بما يكفي لتعطيل الفحوصات التي يكون تعطيلها آمنًا (إلى حد ما) فقط، بينما ستستمر التحويلات والقيم الافتراضية و slurpies في العمل:

use Types::Standard qw( Num Object );
use Type::Params qw( signature_for );
use Devel::StrictMode qw( STRICT );

 signature_for add_number => (
   strictness => STRICT,
   method     => 1,
   positional => [ Num ],
 );

 sub add_number ( $self, $num ) {
   push @{ $self->numbers }, $num;
   return $self;
 }

فحوصات الأنواع المخصصة

...;
my $x = get_some_number();
assert_Int $x if STRICT;
return $x + 1;
...;

عامل الشرطة المائلة

يحتوي Type::Tiny على بعض المنطق نفسه المدمج في Devel::StrictMode. على وجه الخصوص، فإنه يحمّل عامل الشرطة المائلة (القسمة) بحيث يتم تقييم TypeA/TypeB إلى TypeB عادةً، ولكن إلى TypeA في الوضع الصارم.

مثال باستخدام هذه الميزة:

use Types::Standard -types;

has numbers => (
  is      => 'ro',
  isa     => ArrayRef[ Num / Any ],
  default => sub { [] },
);

في الوضع الصارم، ستتحقق هذه السمة من أن قيمتها هي مرجع مصفوفة من الأرقام (والتي قد تكون بطيئة إذا كانت تحتوي على الكثير من الأرقام). ولكن عادةً، ستتحقق فقط من أن القيمة هي مرجع مصفوفة.
