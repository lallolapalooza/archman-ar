Type__Params(3pm)

الحزمة: perl-type-tiny

التراخيص: PerlArtistic, GPL

ctMode qw( STRICT ); state $signature = signature( strictness => STRICT, positional => [ Int, ArrayRef ], ); ```

"multiple" ArrayRef|HashRef

يسمح هذا الخيار لتوقيعك بدعم اتفاقيات استدعاء متعددة. كل إدخال في المصفوفة هو توقيع بديل، كهش ريف:

signature_for my_func => (
  multiple => [
    {
      positional    => [ ArrayRef, Int ],
    },
    {
      named         => [ array => ArrayRef, index => Int ],
      named_to_list => true,
    },
  ],
);

sub my_func ( $aref, $int ) {
  ...;
}

سيسمح هذا التوقيع لدالتك بالاستدعاء كالتالي:

your_function( $arr, $ix );
your_function( array => $arr, index => $ix );
your_function( { array => $arr, index => $ix } );

في بعض الأحيان، ستعيد البدائل المعلمات بترتيب مختلف:

signature_for my_func => (
  multiple => [
    { positional => [ ArrayRef, Int ] },
    { positional => [ Int, ArrayRef ] },
  ],
);

إذًا، كيف تعرف الدالة الفرعية كيف تم استدعاؤها؟ أحد الخيارات هو استخدام المتغير العام "${^_TYPE_PARAMS_MULTISIG}" والذي سيتم تعيينه لفهرس التوقيع الذي تم استخدامه:

sub my_func {
  my ( $arr, $ix ) = ${^_TYPE_PARAMS_MULTISIG} == 1 ? reverse( @_ ) : @_;
  ...;
}

إذا كنت تفضل استخدام أسماء تعريفية بدلاً من فهرس رقمي، يمكنك تحديدها باستخدام "ID":

signature_for my_func => (
  multiple => [
    { ID => 'one', positional => [ ArrayRef, Int ] },
    { ID => 'two', positional => [ Int, ArrayRef ] },
  ],
);

أو باستخدام هش ريف:

signature_for my_func => (
  multiple => {
    one => { positional => [ ArrayRef, Int ] },
    two => { positional => [ Int, ArrayRef ] },
  },
);

الحل الأكثر أناقة هو استخدام دالة "next" لإعادة ترتيب نتائج التوقيعات البديلة إلى الترتيب المفضل لديك:

signature_for my_func => (
  multiple => [
    { positional => [ ArrayRef, Int ] },
    { positional => [ Int, ArrayRef ], next => sub { reverse @_ } },
  ],
);

sub my_func ( $arr, $ix ) {
  ...;
}

بينما من الناحية المفاهيمية "multiple" هو مصفوفة من هش ريفز، فمن الممكن أيضًا استخدام مصفوفات في المصفوفة.

multiple => [
  [ ArrayRef, Int ],
  [ Int, ArrayRef ],
]

عند استخدام مصفوفة بهذه الطريقة، فهي اختصار لتوقيع موضعي.

يمكن أيضًا استخدام دوال الكود إضافيًا:

signature_for my_func => (
  multiple => [
    [ ArrayRef, Int ],
    { positional => [ Int, ArrayRef ], next => sub { reverse @_ } },
    sub { ... },
    sub { ... },
  ],
);

يجب أن تكون دوال الكود دوالًا تُرجع قائمة بالمعلمات إذا نجحت وتُطلق استثناءً إذا فشلت.

التوقيعات التالية مكافئة:

signature_for my_func => (
  multiple => [
    { method => true, positional => [ ArrayRef, Int ] },
    { method => true, positional => [ Int, ArrayRef ] },
  ],
);

signature_for my_func => (
  method   => true,
  multiple => [
    { positional => [ ArrayRef, Int ] },
    { positional => [ Int, ArrayRef ] },
  ],
);

يمكن أيضًا اختصار الخيار "multiple" إلى "multi". لذا يمكن استخدام "signature( multi => [...] )" بدلاً من "signature( multiple => [...] )" الأطول. توفير ثلاث ضغطات مفاتيح كاملة!

(ملاحظة: في الإصدارات الأقدم من Type::Params، كان "${^_TYPE_PARAMS_MULTISIG}" يسمى "${^TYPE_PARAMS_MULTISIG}". الاسم الأخير لم يعد مدعومًا.)

"message" Str

يستخدم فقط بواسطة توقيعات "multiple". رسالة الخطأ التي يجب إطلاقها عندما لا تتطابق أي توقيعات.

"bless" Bool|ClassName، "class" ClassName|ArrayRef، و "constructor" Str

عادةً ما تُعاد المعلمات المسماة ككائن مبارك:

signature_for add_numbers => ( named => [ num1 => Num, num2 => Num ] );

sub add_numbers ( $arg ) {
  return $arg->num1 + $arg->num2;
}

الفئة التي تم مباركتها فيها هي فئة مبنية عند الطلب بواسطة Type::Params. ومع ذلك، تسمح لك هذه الخيارات الثلاثة للتوقيع بمزيد من التحكم في تلك العملية.

أولاً، إذا قمت بتعيين "bless => false" ولم تقم بتعيين "class" أو "constructor"، فسيصبح $arg مجرد هش ريف غير مبارك.

signature_for add_numbers => (
  named        => [ num1 => Num, num2 => Num ],
  bless        => false,
);

sub add_numbers ( $arg ) {
  return $arg->{num1} + $arg->{num2};
}

هذه زيادة سرعة جيدة، ولكن وجود طرق مناسبة لكل معلمة مسماة هو طريقة مفيدة لاكتشاف الأسماء المكتوبة بشكل خاطئ.

إذا كنت ترغب في إنشاء فئة يدويًا بدلاً من الاعتماد على Type::Params لإنشاء واحدة عند الطلب، يمكنك القيام بذلك:

package Params::For::AddNumbers {
  sub num1 ( $self ) {
    return $self->{num1};
  }
  sub num2 ( $self ) {
    return $self->{num2};
  }
  sub sum ( $self ) {
    return $self->num1 + $self->num2;
  }
}

signature_for add_numbers => (
  named        => [ num1 => Num, num2 => Num ],
  bless        => 'Params::For::AddNumbers',
);

sub add_numbers ( $arg ) {
  return $arg->sum;
}

لاحظ أن "Params::For::AddNumbers" هنا لا يتضمن طريقة "new" لأن Type::Params سيقوم مباشرة بتنفيذ "bless( $arg, $opts{bless} )".

إذا كنت تريد من Type::Params استخدام مُنشئ مناسب، يجب عليك استخدام الخيار "class" بدلاً من ذلك:

package Params::For::AddNumbers {
  use Moo;
  has [ 'num1', 'num2' ] => ( is => 'ro' );
  sub sum {
    my $self = shift;
    return $self->num1 + $self->num2;
  }
}

signature_for add_numbers => (
  named        => [ num1 => Num, num2 => Num ],
  class        => 'Params::For::AddNumbers',
);

sub add_numbers ( $arg ) {
  return $arg->sum;
}

إذا كنت ترغب في استخدام مُنشئ باسم غير "new"، فاستخدم:

signature_for add_numbers => (
  named        => [ num1 => Num, num2 => Num ],
  class        => 'Params::For::AddNumbers',
  constructor  => 'new_from_hashref',
);

أو كاختصار:

signature_for add_numbers => (
  named        => [ num1 => Num, num2 => Num ],
  class        => [ 'Params::For::AddNumbers' => 'new_from_hashref' ],
);

من غير المحتمل أن ترغب في استخدام أي من هذه الخيارات، باستثناء "bless => false".

"returns" TypeTiny، "returns_scalar" TypeTiny، و "returns_list" TypeTiny

يمكن استخدام هذه لتحديد نوع القيمة المرتجعة من دالتك.

signature_for round_number => (
  pos          => [ Num ],
  returns      => Int,
);

sub round_number ( $num ) {
  return int( $num );
}

إذا كانت دالتك تُرجع أنواعًا مختلفة في السياق القياسي والسياق القائم على القائمة، فيمكنك استخدام "returns_scalar" و "returns_list" للإشارة إلى أنواع إرجاع منفصلة في سياقات مختلفة.

signature_for my_func => (
  pos             => [ Int, Int ],
  returns_scalar  => Int,
  returns_list    => Tuple[ Int, Int, Int ],
);

يتم تعريف قيد "returns_list" باستخدام قيد نوع يشبه ArrayRef أو يشبه HashRef على الرغم من أنه يُرجع قائمة، وليس مرجعًا واحدًا.

إذا تم استدعاء دالتك في سياق فارغ (void context)، فإن قيمة الإرجاع غير مهمة ولا يجب التحقق من نوعها.

"allow_dash" Bool

لأي معلمات مسماة أو أسماء مستعارة تشبه "الكلمات"، يتم إنشاء اسم مستعار تلقائيًا مع شرطة بادئة.

signature_for withdraw_funds => (
  named      => [ amount => Num, account => Str ],
  allow_dash => true,
);

sub withdraw_funds ( $arg ) {
  ...;
}

withdraw_funds(  amount => 11.99,  account => 'ABC123' );
withdraw_funds( -amount => 11.99,  account => 'ABC123' );
withdraw_funds(  amount => 11.99, -account => 'ABC123' );
withdraw_funds( -amount => 11.99, -account => 'ABC123' );

ليس له تأثير على الأسماء التي ليست شبيهة بالكلمات. الأسماء الشبيهة بالكلمات هي تلك التي تطابق "/\A[^\W0-9]\w*\z/"؛ بشكل أساسي أي شيء تسمح به Perl كاسم متغير عادي غير مؤهل.

خيارات المعلمات

في قوائم المعلمات لخيارات التوقيع "positional" و "named"، يمكن أن تتبع كل معلمة بهش ريف من الخيارات الخاصة بتلك المعلمة:

signature_for my_func => (
  positional => [
    Int, \%options_for_first_parameter,
    Int, \%options_for_other_parameter,
  ],
  %more_options_for_signature,
);
signature_for my_func => (
  named => [
    foo => Int, \%options_for_foo,
    bar => Int, \%options_for_bar,
  ],
  %more_options_for_signature,
);

الخيارات التالية مدعومة للمعلمات.

"optional" Bool

خيار *مسمى* اختياري!

هذا يجعل المعلمة اختيارية:

signature_for add_nums => (
  positional => [
    Int,
    Int,
    Bool, { optional => true },
  ],
);

sub add_nums ( $num1, $num2, $debug ) {
  my $sum = $num1 + $num2;
  warn "$sum = $num1 + $num2" if $debug;
  return $sum;
}

add_nums( 2, 3, 1 );   # يطبع تحذيرا
add_nums( 2, 3, 0 );   # لا يوجد تحذير
add_nums( 2, 3    );   # لا يوجد تحذير

يوفر Types::Standard أيضًا نوع معلمة قابل للتحديث يسمى Optional والذي قد يكون طريقة أكثر أناقة للقيام بذلك:

signature_for add_nums => ( pos => [ Int, Int, Optional[Bool] ] );

في التوقيعات ذات المعلمات الموضعية، يجب تعريف أي معلمات اختيارية *بعد* المعلمات غير الاختيارية. يوفر خيار "tail" حلاً للمشكلات المتعلقة بالمعلمات المطلوبة في نهاية @_.

في التوقيعات ذات المعلمات المسماة، ترتيب المعلمات الاختيارية وغير الاختيارية غير مهم.

"slurpy" Bool

">

"wrap_subs( func1 => \@params1, func2 => \@params2, ... )"

Equivalent to:

signature_for func1 => ( positional => \@params1 );
signature_for func2 => ( positional => \@params2 );

One slight difference is that instead of arrayrefs, you can provide the output of one of the "compile" functions:

wrap_subs( func1 => compile_named( @params1 ) );

"wrap_subs" is not exported unless requested by name.

"wrap_methods( func1 => \@params1, func2 => \@params2, ... )"

Equivalent to:

signature_for func1 => ( method => 1, positional => \@params1 );
signature_for func2 => ( method => 1, positional => \@params2 );

One slight difference is that instead of arrayrefs, you can provide the output of one of the "compile" functions:

wrap_methods( func1 => compile_named( @params1 ) );

"wrap_methods" is not exported unless requested by name.

multisig( @alternatives )

Equivalent to:

signature( multiple => \@alternatives )

"multisig( \%spec, @alternatives )" is equivalent to "signature( %spec, multiple => \@alternatives )".

TYPE CONSTRAINTS

Although Type::Params is not a real type library, it exports two type constraints. Their use is no longer recommended.

Invocant

Type::Params exports a type Invocant on request. This gives you a type constraint which accepts classnames and blessed objects.

use Type::Params qw( compile Invocant );

signature_for my_method => (
  method     => Invocant,
  positional => [ ArrayRef, Int ],
);

sub my_method ($self_or_class, $arr, $ix) {
  return $arr->[ $ix ];
}

"Invocant" is not exported unless requested by name.

Recommendation: use Defined from Types::Standard instead.

ArgsObject

Type::Params exports a parameterizable type constraint ArgsObject. It accepts the kinds of objects returned by signature checks for named parameters.

use v5.36;

package Foo {
  use Moo;
  use Type::Params 'ArgsObject';

  has args => (
    is  => 'ro',
    isa => ArgsObject['Bar::bar'],
  );
}

package Bar {
  use Types::Standard -types;
  use Type::Params 'signature_for';

  signature_for bar => ( named => [ xxx => Int, yyy => ArrayRef ] );

  sub bar ( $got ) {
    return 'Foo'->new( args => $got );
  }
}

Bar::bar( xxx => 42, yyy => [] );

The parameter "Bar::bar" refers to the caller when the check is compiled, rather than when the parameters are checked.

"ArgsObject" is not exported unless requested by name.

Recommendation: use Object from Types::Standard instead.

ENVIRONMENT

"PERL_TYPE_PARAMS_XS"
Affects the building of accessors for $arg objects. If set to true, will use Class::XSAccessor. If set to false, will use pure Perl. If this environment variable does not exist, will use Class::XSAccessor.

If Class::XSAccessor is not installed or is too old, pure Perl will always be used as a fallback.
