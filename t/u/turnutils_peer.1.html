turnutils_peer(1)

الحزمة: coturn

التراخيص: BSD

TURN(1) TURN(1)

معلومات عامة

مجموعة من برامج turnutils_* توفر بعض وظائف الأدوات المساعدة للتجريب ولإعداد خادم TURN.

1.
turnutils_uclient: يحاكي عملاء UDP، TCP، TLS أو DTLS متعددين. (هذا البرنامج متاح لأغراض الاختبار فقط!) توجد الصورة الثنائية المجمعة لهذا البرنامج في الدليل الفرعي bin/.
2.
turnutils_peer: خادم "صدى" بسيط غير متصل بالشبكة ويعتمد على UDP فقط، يُستخدم كخادم نهائي في نمط الترحيل ("peer"). لكل حزمة UDP واردة، يقوم ببساطة بإعادتها. (هذا البرنامج متاح لأغراض الاختبار فقط!) عند تواصل عملاء الاختبار بطريقة العميل إلى العميل (عند استخدام برنامج "turnutils_uclient" مع الخيار "-y")، فإن turnutils_peer غير مطلوب.

توجد الصورة الثنائية المجمعة لهذا البرنامج في الدليل الفرعي bin/.

3.
turnutils_stunclient: مثال بسيط لعميل STUN. توجد الصورة الثنائية المجمعة لهذا البرنامج في الدليل الفرعي bin/.
4.
turnutils_rfc5769check: أداة تتحقق من صحة تطبيق بروتوكول STUN/TURN. تُستخدم هذه الأداة فقط لإجراء فحص التجميع، ولا يتم نسخها إلى وجهة التثبيت.

في الدليل الفرعي "examples/scripts"، ستجد أمثلة لأسطر الأوامر المستخدمة لتشغيل البرامج. البرامج النصية مخصصة للتشغيل من الدليل الفرعي examples/، على سبيل المثال:

$ cd examples

$ ./scripts/secure_relay.sh

5.
turnutils_natdiscovery: أداة توفر اكتشاف سلوك NAT وفقًا لـ RFC5780. تكتشف هذه الأداة تعيين NAT الفعلي وسلوك التصفية، إلخ. انتبه إلى أنه على جانب خادم TURN، يجب تكوين عنواني IP مختلفين للاستماع لكي يعمل بشكل صحيح!
6.
turnutils_oauth: أداة توفر **إنشاء** (تشفير AEAD) وتدقيق وفك تشفير access_token. تستقبل هذه الأداة جميع المفاتيح وفترات الصلاحية وأي معلومات ذات صلة مطلوبة لإنشاء وتدقيق access_token. تنتج ملف JSON بجميع معلمات OAuth PoP التي يجب تمريرها إلى العميل. يتم إنشاء الناتج وفقًا للملحق B، الشكل 8 في RFC7635.

لمزيد من التفاصيل، ولبنية access_token، اقرأ rfc7635، وانظر البرنامج النصي في examples/scripts/oauth.sh.

=====================================

الاسم

turnutils_uclient - تطبيق محاكاة العميل هذا متاح لأغراض الاختبار فقط.

ملخص

$ turnutils_uclient [-tTSvsyhcxg] [خيارات] <عنوان IP لخادم TURN>

الوصف

تم تصميمه لمحاكاة عملاء متعددين. يستخدم واجهة برمجة تطبيقات الإدخال/الإخراج غير المتزامنة في libevent للتعامل مع عملاء متعددين. يتصل العميل بالخادم المرحل، ويتفاوض على الجلسة، ويرسل حزمًا متعددة (عدد محدد) إلى الخادم (المرحل)، متوقعًا نفس العدد من الردود. طول الرسائل قابل للتكوين. الرسالة عبارة عن تيار ثماني عشوائي. عدد الرسائل المراد إرسالها قابل للتكوين.

علامات:

-t
استخدم TCP للاتصالات بين العميل وخادم TURN (الافتراضي هو UDP).
-b
استخدم SCTP للاتصالات بين العميل وخادم TURN (الافتراضي هو UDP).
-T
استخدم TCP للنقل المرحل (الافتراضي - UDP). يتضمن الخيارات -t، -y، -c، ويتجاهل العلامات والخيارات -s، -e، -r و -g. يمكن استخدامه مع -b.
-P
TCP سلبي (RFC6062 مع نظير نشط). يتضمن -T.
-S
اتصال SSL آمن: SSL/TLS لـ TCP، DTLS لـ UDP، TLS/SCTP لـ SCTP.
-U
اتصال آمن غير مشفر (مجموعة eNULL): SSL/TLS لـ TCP، DTLS لـ UDP.
-v
المطوّل.
-s
استخدم طريقة "إرسال" في TURN؛ افتراضيًا، تستخدم قنوات TURN.
-y
استخدم اتصالات من العميل إلى العميل: زوج قنوات RTP/RTCP إلى زوج قنوات RTP/RTCP آخر. مع هذا الخيار، لا يتم استخدام التطبيق turnutils_peer، حيث تتحدث نقاط نهاية الترحيل المخصصة مع بعضها البعض.
-h
البقاء معلقًا إلى أجل غير مسمى بعد آخر حزمة مرسلة.
-c
لا تنشئ اتصالات rtcp.
-x
طلب عنوان ترحيل IPv6 (RFC6156).
-X
تم طلب عنوان ترحيل IPv4 بشكل صريح.
-g
تعيين معلمة DONT_FRAGMENT في طلبات TURN.
-D
قم بحشو القنوات الإلزامي حتى لـ UDP (مثل pjnath).
-N
قم بإجراء اختبارات سلبية (بعض الحالات المحدودة فقط).
-R
قم بإجراء اختبارات بروتوكول سلبية.
-O
وضع هجوم DOS.
-M
استخدم تنقل TURN ICE.
-I
لا تقم بتعيين أذونات على نقاط نهاية الترحيل TURN (لاختبار وظيفة الترحيل غير القياسية للخادم).
-G
إنشاء طلبات إضافية (إنشاء أذونات، ربط قنوات).
-B
قطع الاتصال بشكل عشوائي بعد بضع حزم أولية.
-Z
تخصيص مزدوج (SSODA). يتضمن الخيار -c.
-J
استخدم oAuth مع مفتاح الاختبار الافتراضي kid='north'.

الخيارات التي تتطلب قيمًا:

-l
طول الرسالة (الافتراضي: 100 بايت).
-i
ملف الشهادة (للاتصالات الآمنة فقط، اختياري).
-k
ملف المفتاح الخاص (للاتصالات الآمنة فقط).
-E
ملف CA للتحقق من شهادة الخادم، إذا كان يجب التحقق من شهادة الخادم.
-p
منفذ خادم TURN (الافتراضي: 3478 غير آمن، 5349 آمن).
-n
عدد الرسائل المراد إرسالها (الافتراضي: 5).
-d
واجهة الجهاز المحلية (اختياري، Linux فقط).
-L
عنوان IP المحلي (اختياري).
-m
عدد العملاء (الافتراضي: 1، 2 أو 4، اعتمادًا على الخيارات).
-e
عنوان النظير.
-r
منفذ النظير (الافتراضي: 3480).
-z
فاصل الحزم لكل جلسة بالمللي ثانية (الافتراضي: 20).
-u
اسم مستخدم STUN/TURN.
-w
كلمة مرور مستخدم STUN/TURN.
-W
سر REST API الخاص بـ TURN. السر "النصي العادي" مثال "north" المخزن في عمود القيمة لـ turn_secret

timestamp in format 64 bit unsigned (Native format - Unix), so 48 bit for secs since epoch UTC + 16 bit for 1/64000 fractions of a second. e.g.: the actual unixtimestamp 16 bit left shifted. (Default: actual gmtime)
