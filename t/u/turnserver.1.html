الاسم

turnserver - تطبيق خادم ترحيل TURN.

الملخص

$ turnserver [-n | -c <ملف-التكوين> ] [علامات] [ --userdb=<ملف-قاعدة-بيانات-المستخدمين> | --psql-userdb=<سلسلة-اتصال-قاعدة-البيانات> | --mysql-userdb=<سلسلة-اتصال-قاعدة-البيانات>  | --mongo-userdb=<سلسلة-اتصال-قاعدة-البيانات>  | --redis-userdb=<سلسلة-اتصال-قاعدة-البيانات> ] [-z | --no-auth | -a | --lt-cred-mech ] [خيارات]
$ turnserver -h

الوصف

إعدادات ملف التكوين:

-n
لا تستخدم ملف التكوين، استخدم معلمات سطر الأوامر فقط.
-c
اسم ملف التكوين (الافتراضي - turnserver.conf). يمكن رؤية تنسيق ملف التكوين في ملف مثال examples/etc/turnserver.conf المقدم. تُستخدم الأسماء الطويلة لـ خيارات كأسماء عناصر التكوين في الملف. إذا لم يتم توفير مسار مطلق، فسيتم البحث عن الملف في الأدلة التالية:
  • الدليل الحالي
  • الدليل الحالي الدليل الفرعي etc/
  • الدليل العلوي etc/
  • /etc/
  • /usr/local/etc/
  • دليل التثبيت /etc

إعدادات قاعدة بيانات المستخدمين:

-b, --db, --userdb
اسم ملف قاعدة بيانات مستخدمي SQLite (الافتراضي - /var/db/turndb أو /usr/local/var/db/turndb أو /var/lib/turn/turndb).
-e, --psql-userdb
سلسلة اتصال قاعدة بيانات المستخدمين لـ PostgreSQL. يمكن استخدام قاعدة البيانات هذه لآلية بيانات الاعتماد طويلة الأجل، ويمكنها تخزين القيمة السرية للمصادقة المحددة بوقت والمستندة إلى السر في واجهة برمجة تطبيقات REST الخاصة بـ TURN. تنسيق سلسلة الاتصال هو كالتالي:

"host=<المضيف> dbname=<اسم-قاعدة-البيانات> user=<مستخدم-قاعدة-البيانات> password=<كلمة-مرور-مستخدم-قاعدة-البيانات> connect_timeout=<ثواني>" (لـ Postgres 8.x أو أحدث).

أو:

"postgresql://username:password@hostname:port/databasename" (لـ Postgres 9.x أو أحدث).

راجع ملف INSTALL لمزيد من الشروحات والأمثلة.

أيضًا، راجع http://www.PostgreSQL.org للحصول على وثائق PostgreSQL الكاملة.

-M, --mysql-userdb
سلسلة اتصال قاعدة بيانات المستخدمين لـ MySQL أو MariaDB. يمكن استخدام قاعدة البيانات هذه لآلية بيانات الاعتماد طويلة الأجل، ويمكنها تخزين القيمة السرية للمصادقة المحددة بوقت والمستندة إلى السر في واجهة برمجة تطبيقات REST الخاصة بـ TURN. تنسيق سلسلة الاتصال هو كالتالي:

"host=<المضيف> dbname=<اسم-قاعدة-البيانات> user=<مستخدم-قاعدة-البيانات> password=<كلمة-مرور-مستخدم-قاعدة-البيانات> connect_timeout=<ثواني> read_timeout=<ثواني>"

راجع ملف INSTALL لمزيد من الشروحات والأمثلة.

أيضًا، راجع http://www.mysql.org أو http://mariadb.org للحصول على وثائق MySQL الكاملة.

معلمات سلسلة اتصال اختيارية للاتصالات الآمنة (SSL): ca، capath، cert، key، cipher (راجع http://dev.mysql.com/doc/refman/5.1/en/ssl-options.html لوصف خيارات الأوامر).

--secret-key-file
هذا هو المسار إلى الملف الذي يحتوي على المفتاح السري للتشفير AES عند استخدام تشفير كلمة مرور MySQL. إذا كنت ترغب في استخدام كلمة المرور بتنسيق مشفر في سلسلة اتصال MySQL، فقم بتعيين مسار ملف المفتاح السري في هذا الخيار. المفتاح المستخدم لتشفير كلمة مرور MySQL. تحذير: إذا تم تعيين هذا الخيار، فيجب تعيين كلمة مرور MySQL في خيار "mysql-userdb" بتنسيق مشفر! إذا كنت ترغب في استخدام كلمة مرور واضحة، فلا تقم بتعيين هذا الخيار!
-J, --mongo-userdb
سلسلة اتصال قاعدة بيانات المستخدمين لـ MongoDB. يمكن استخدام قاعدة البيانات هذه لآلية بيانات الاعتماد طويلة الأجل، ويمكنها تخزين القيمة السرية للمصادقة المحددة بوقت والمستندة إلى السر في واجهة برمجة تطبيقات REST الخاصة بـ TURN. تنسيق سلسلة الاتصال هو كالتالي:

"mongodb://username:password@host:port/database?options"

راجع ملف INSTALL لمزيد من الشروحات والأمثلة.

أيضًا، راجع http://docs.mongodb.org/manual/ للحصول على وثائق MongoDB الكاملة.

-N, --redis-userdb
سلسلة اتصال قاعدة بيانات المستخدمين لـ Redis. يمكن استخدام قاعدة البيانات هذه لآلية بيانات الاعتماد طويلة الأجل، ويمكنها تخزين القيمة السرية للمصادقة المحددة بوقت والمستندة إلى السر في واجهة برمجة تطبيقات REST الخاصة بـ TURN. تنسيق سلسلة الاتصال هو كالتالي:

"ip=<عنوان-IP> dbname=<رقم-قاعدة-البيانات> password=<كلمة-مرور-قاعدة-البيانات> connect_timeout=<ثواني>"

راجع ملف INSTALL لمزيد من الشروحات والأمثلة.

أيضًا، راجع http://redis.io للحصول على وثائق Redis الكاملة.

--alt-tls-listening-port
منفذ استماع بديل لبروتوكولات TLS و DTLS. القيمة الافتراضية (أو صفر) تعني "منفذ استماع TLS زائد واحد".

--aux-server
نقطة نهاية استماع خادم STUN/TURN مساعد. للخوادم المساعدة وظائف TURN و STUN كاملة تقريبًا. القيود (الطفيفة) هي:
1)
لا تحتوي الخوادم المساعدة على منافذ بديلة ولا تدعم وظيفة CHANGE REQUEST الخاصة بـ STUN RFC 5780.
2)
لا تقوم الخوادم المساعدة أبدًا بإرجاع رد ALTERNATIVE-SERVER.

التنسيقات الصالحة هي 1.2.3.4:5555 لـ IPv4 و [1:2::3:4]:5555 لـ IPv6. قد تكون هناك خيارات aux-server متعددة، سيتم استخدام كل منها للاستماع إلى طلبات العميل.

-i, --relay-device
جهاز واجهة الترحيل لمقابس الترحيل (غير مستحسن. اختياري، لنظام Linux فقط).
-E, --relay-ip
عنوان الترحيل (عنوان IP المحلي الذي سيتم استخدامه لترحيل الحزم إلى النظير). يمكن استخدام عناوين ترحيل متعددة: -E ip1 -E ip2 -E ip3 يمكن استخدام نفس عنوان IP (عناوين IP) كـ عناوين IP للاستماع وعناوين IP للترحيل. إذا لم يتم تحديد عناوين IP للترحيل، فسيطبق خادم turnserver السياسة الافتراضية: سيقرر بنفسه عناوين الترحيل التي سيتم استخدامها، وسيقوم دائمًا باستخدام عنوان IP لمقبس العميل كعنوان IP للترحيل لجلسة TURN (إذا كان عنوان IP المطلوب للترحيل من نفس عائلة عنوان IP لمقبس العميل).
-X, --external-ip
TURN Server تعيين عنوان عام/خاص، إذا كان الخادم خلف NAT. في هذه الحالة، إذا تم استخدام -X بالشكل "<ip> -X" ، فسيتم الإبلاغ عن هذا الـ ip كعنوان IP للترحيل لجميع التخصيصات. هذه السيناريو تعمل فقط في حالة بسيطة عندما يتم استخدام عنوان IP واحد للترحيل، ولا يلزم وجود وظيفة CHANGE_REQUEST. يجب تعيين عنوان IP واحد للترحيل هذا بواسطة NAT إلى عنوان IP "الخارجي". سيتم إرجاع قيمة "external-ip"، إذا لم تكن فارغة، في حقل XOR-RELAYED-ADDRESS. بالنسبة لعنوان IP "الخارجي" هذا، يجب أن يقوم NAT بإعادة توجيه المنافذ مباشرة (يجب أن يتم تعيين منفذ الترحيل 12345 دائمًا إلى منفذ "خارجي" 12345). في حالة أكثر تعقيدًا عند مشاركة أكثر من عنوان IP واحد، يجب استخدام هذا الخيار عدة مرات، يجب أن يكون كل إدخال بالشكل "<public-ip/private-ip> -X" ، لتعيين جميع العناوين المشاركة. ستعمل وظيفة NAT discovery STUN CHANGE_REQUEST (RFC5780 أو RFC3489) بشكل صحيح، إذا تم تعيين العناوين بشكل صحيح، حتى عندما يكون خادم TURN نفسه خلف NAT. افتراضيًا، هذه القيمة فارغة، ولا يتم استخدام أي تعيين للعنوان.
-m, --relay-threads
عدد خيوط الترحيل لمعالجة الاتصالات المنشأة (بالإضافة إلى خيط المصادقة وخيط المستمع). إذا تم تعيينه صراحةً إلى 0، فسيعمل التطبيق عملية الترحيل في خيط واحد، في نفس الخيط مع عملية المستمع (سيظل خيط المصادقة خيطًا منفصلاً). إذا لم يتم تعيينه، فسيتم استخدام خوارزمية مثلى افتراضية (تعتمد على نظام التشغيل). في أنظمة Linux الأقدم (قبل نواة Linux 3.9)، يكون عدد خيوط UDP دائمًا خيطًا واحدًا لكل نقطة نهاية استماع شبكة - ما لم يتم تعيين "0 -m" أو "1 -m".
--min-port
الحد الأدنى لنطاق منفذ UDP لتخصيص نقاط نهاية الترحيل. القيمة الافتراضية هي 49152 ، وفقًا لـ RFC 5766.
--max-port
الحد الأقصى لنطاق منفذ UDP لتخصيص نقاط نهاية الترحيل. القيمة الافتراضية هي 65535 ، وفقًا لـ RFC 5766.
-u, --user
بيانات اعتماد آلية الأمان طويلة الأجل للمستخدم، في شكل عمود username:key. يمكن استخدام حسابات مستخدمين متعددة في سطر الأوامر. المفتاح هو إما كلمة مرور المستخدم، أو يتم إنشاء المفتاح بواسطة أمر turnadmin. في الحالة الثانية، يجب أن يسبق المفتاح رموز 0x. يتم حساب المفتاح فوق اسم المستخدم، والنطاق (realm) للمستخدم، وكلمة مرور المستخدم. قد لا يتم استخدام هذا الإعداد مع TURN REST API.
-r, --realm
النطاق الافتراضي الذي سيتم استخدامه للمستخدمين عندما لا يتم العثور على علاقة أصل/نطاق صريحة في قاعدة البيانات، أو إذا كان خادم TURN لا يستخدم أي قاعدة بيانات (فقط الإعدادات الموجودة في سطر الأوامر وملف userdb). يجب استخدامه مع آلية بيانات الاعتماد طويلة الأجل أو مع TURN REST API.
-C, --rest-api-separator
هذا هو رمز (حرف) فاصل الطابع الزمني/اسم المستخدم في TURN REST API. القيمة الافتراضية هي :.
-q, --user-quota
حصص التخصيص لكل مستخدم: عدد التخصيصات المتزامنة التي يمكن للمستخدم إنشاؤها. يمكن أيضًا تعيين هذا الخيار من خلال قاعدة البيانات، لنطاق معين.
-Q, --total-quota
حصص التخصيص الإجمالية: الحد العام للتخصيصات المتزامنة. يمكن أيضًا تعيين هذا الخيار من خلال قاعدة البيانات، لنطاق معين.
-s, --max-bps
الحد الأقصى للبايت في الثانية للنطاق الترددي الذي يُسمح لجلسة TURN بمعالجته (يتم التعامل مع تدفقات الشبكة الواردة والصادرة بشكل منفصل). أي شيء فوق هذا الحد سيتم إسقاطه أو قمعه مؤقتًا (ضمن حدود المخزن المؤقت المتاحة). يمكن أيضًا تعيين هذا الخيار من خلال قاعدة البيانات، لنطاق معين.
-B, --bps-capacity
الحد الأقصى لسعة الخادم. إجمالي البايت في الثانية للنطاق الترددي الذي يُسمح لخادم TURN بتخصيصه للجلسات، مجتمعًا (يتم التعامل مع تدفقات الشبكة الواردة والصادرة بشكل منفصل).
--static-auth-secret
قيمة سر المصادقة الثابت (سلسلة نصية) لـ TURN REST API فقط. إذا لم يتم تعيينها، فسيحاول خادم turn استخدام القيمة الديناميكية في جدول turn_secret في قاعدة بيانات المستخدم (إذا كانت موجودة). يمكن تغيير القيمة المخزنة في قاعدة البيانات فورًا بواسطة برنامج منفصل، وهذا هو سبب كون الوضع الآخر ديناميكيًا. يمكن استخدام أسرار مشتركة متعددة (في قاعدة البيانات وفي الشكل "static" على حد سواء).
--no-auth-pings
تعطيل فحوصات الصحة الدورية لجداول سر المصادقة "الديناميكية".
--no-dynamic-ip-list
لا تستخدم قائمة عناوين IP المسموح بها/المحظورة الديناميكية.
--no-dynamic-realms
لا تستخدم تعيين النطاقات والخيارات الديناميكية.
--server-name
اسم الخادم المستخدم لأغراض مصادقة oAuth. القيمة الافتراضية هي اسم النطاق.
--cert
ملف الشهادة، بتنسيق PEM. يتم تطبيق نفس قواعد البحث عن الملفات كما في ملف التكوين. إذا تم تحديد كل من الخيارين --no-tls و --no-dtls ، فلن تكون هذه المعلمة مطلوبة. القيمة الافتراضية هي turn_server_cert.pem.
--pkey
ملف المفتاح الخاص، بتنسيق PEM. يتم تطبيق نفس قواعد البحث عن الملفات كما في ملف التكوين. إذا تم تحديد كل من الخيارين --no-tls و --no-dtls ، فلن تكون هذه المعلمة مطلوبة. القيمة الافتراضية هي turn_server_pkey.pem.
--pkey-pwd
إذا كان ملف المفتاح الخاص مشفرًا، فستكون هذه هي كلمة المرور المراد استخدامها.
--cipher-list
قائمة تشفير OpenSSL المسموح بها لاتصالات TLS/DTLS. القيمة الافتراضية هي "DEFAULT" لإصدارات TLS/DTLS حتى TLSv1.2/DTLSv1.2، وتشفيرات المكتبة الافتراضية لإصدار TLSv1.3.
--CA-file
ملف CA بتنسيق OpenSSL. يجبر خادم TURN على التحقق من شهادات SSL للعميل. افتراضيًا، لا يتم تعيين أي CA ولا يتم إجراء أي فحص لشهادة العميل.
--ec-curve-name
اسم المنحنى لتشفيرات EC، إذا كان مدعومًا بواسطة مكتبة OpenSSL (TLS و DTLS). القيمة الافتراضية هي prime256v1.
--dh-file
استخدام مفتاح TLS DH مخصص، مخزن بتنسيق PEM في الملف. يتم تجاهل الأعلام --dh566 و --dh1066 عند أخذ مفتاح DH من ملف.
-l, --log-file
خيار لتعيين اسم المسار الكامل لملف السجل. افتراضيًا، يحاول turnserver فتح ملف سجل في /var/log/turnserver، /var/log، /var/tmp، /tmp و . (الدلائل الحالية) (أول عملية فتح ملف تنجح سيتم استخدام ملفها). مع هذا الخيار، يمكنك تعيين اسم ملف سجل محدد. الأسماء الخاصة هي "stdout" و "-" - سيجبران كل شيء على الإخراج القياسي. أيضًا، اسم "syslog" سيعيد توجيه كل شيء إلى سجل النظام (syslog)، كما لو تم تعيين الخيار "--syslog". في وقت التشغيل، يمكن إعادة تعيين ملف السجل عن طريق إشارة SIGHUP إلى عملية turnserver.
--alternate-server
خيار لتعيين وضع "إعادة التوجيه". ستكون قيمة هذا الخيار هي عنوان الخادم البديل لخدمة UDP و TCP بالشكل <ip>[:<port>]. سيرسل الخادم هذه القيمة في السمة ALTERNATE-SERVER، مع الخطأ 300، عند طلب ALLOCATE، إلى العميل. سيستقبل العميل فقط القيم التي لها نفس عائلة العنوان مثل عنوان عائلة نهاية شبكة العميل. انظر RFC 5389 و RFC 5766 لوصف وظيفة ALTERNATE-SERVER. يجب على العميل استخدام القيمة التي تم الحصول عليها لاتصالات TURN اللاحقة. إذا تم توفير أكثر من خيار --alternate-server واحد، فيمكن وصف الوظيفة بشكل أكثر دقة بأنها "موازنة تحميل" بدلاً من مجرد "إعادة توجيه". إذا تم حذف رقم المنفذ، فسيتم استخدام رقم المنفذ الافتراضي 3478 لبروتوكولات UDP/TCP. قد تتعارض أحرف النقطتين (:) في عناوين IPv6 مع بناء الجملة للخيارات. للتخفيف من هذا التعارض، يتم تضمين عناوين IPv6 الحرفية في أقواس مربعة في معرفات الموارد هذه، على سبيل المثال: [2001:db8:85a3:8d3:1319:8a2e:370:7348]:3478. يمكن تعيين خوادم بديلة متعددة. سيتم استخدامها بطريقة التوزيع العشوائي (round-robin). تعتبر جميع الخوادم في المجموعة ذات وزن متساوٍ وسيتم توزيع الحمل بالتساوي. على سبيل المثال، إذا كان لدينا 4 خوادم بديلة، فسيتلقى كل خادم 25٪ من جميع طلبات ALLOCATE. يمكن استخدام عنوان خادم TURN بديل أكثر من مرة مع خيار alternate-server، بحيث يمكن محاكاة "وزن" الخوادم.
--tls-alternate-server
خيار لتعيين خادم بديل لخدمات TLS و DTLS في شكل <ip>:<port>. إذا تم حذف رقم المنفذ، فسيتم استخدام رقم المنفذ الافتراضي 5349 لبروتوكولات TLS/DTLS. انظر الخيار السابق لوصف الوظيفة.
-O, --redis-statsdb
سلسلة اتصال قاعدة بيانات حالة وإحصائيات Redis، إذا تم استخدامها (الافتراضي - فارغ، لا توجد قاعدة بيانات إحصائيات Redis مستخدمة). تحتفظ قاعدة البيانات هذه بمعلومات حالة التخصيص، ويمكن استخدامها أيضًا لنشر وتسليم حركة المرور وإشعارات أحداث التخصيص. يمكن استخدام خيار قاعدة البيانات هذا بشكل مستقل عن خيار --redis-userdb، وفي الواقع يمكن استخدام Redis للحالة/الإحصائيات و SQLite أو MySQL أو MongoDB أو PostgreSQL لقاعدة بيانات المستخدم. سلسلة الاتصال لها نفس معلمات سلسلة اتصال redis-userdb.
--max-allocate-timeout
الحد الأقصى للوقت، بالثواني، المسموح به لإنشاء تخصيص كامل. الافتراضي هو 60 ثانية.

--denied-peer-ip=<IPaddr[-IPaddr]>

--allowed-peer-ip=<IPaddr[-IPaddr]> خيارات لحظر أو السماح لعناوين IP محددة أو نطاقات من عناوين IP. إذا تم تحديد عنوان IP كعنوان مسموح به ومحظور، فسيتم اعتبار عنوان IP مسموحًا به. هذا مفيد عندما ترغب في حظر نطاق من عناوين IP، باستثناء عدد قليل من عناوين IP المحددة ضمن هذا النطاق. يمكن استخدام هذا عندما لا تريد أن يتمكن المستخدمون من خادم turn من الوصول إلى الأجهزة التي يمكن الوصول إليها بواسطة خادم turn، ولكنها قد تكون غير قابلة للوصول بطريقة أخرى من الإنترنت (على سبيل المثال، عندما يكون خادم turn خلف NAT). يمكن أيضًا تغيير نطاقات IP الخاصة بالنظير "الأبيض" و "الأسود" ديناميكيًا في قاعدة البيانات. قواعد العناوين المسموح بها/المحظورة (القوائم البيضاء/السوداء) بسيطة جدًا:

1)
إذا لم تكن هناك قاعدة لهذا العنوان، فإنه مسموح به؛
2)
إذا كانت هناك قاعدة "مسموح بها" تناسب العنوان، فإنه مسموح به - بغض النظر عن أي شيء؛
3)
إذا لم تكن هناك قاعدة "مسموح بها" تناسب العنوان، وإذا كانت هناك قاعدة "محظورة" تناسب العنوان، فإنه محظور.
--pidfile
اسم الملف لتخزين معرف العملية (pid). الافتراضي هو /var/run/turnserver.pid (إذا تم استخدام حساب المستخدم الخارق) أو /var/tmp/turnserver.pid.
--acme-redirect
<URL> إعادة توجيه طلبات ACME/RFC8555 (مثل تحدي Let's Encrypt)، أي طلبات HTTP GET التي تطابق '^/.well-known/acme-challenge/(.*)' إلى <URL>$1 حيث $1 == (.*). لن يتم إجراء أي تحقق من <URL>، لذا تأكد من عدم نسيان الشرطة المائلة اللاحقة. إذا كانت <URL> عبارة عن سلسلة فارغة (القيمة الافتراضية)، فلن يتم إجراء أي معالجة خاصة لمثل هذه الطلبات.
--proc-user
اسم المستخدم لتشغيل العملية. بعد التهيئة، ستحاول عملية turnserver تغيير معرف المستخدم الحالي إلى هذا المستخدم.
--proc-group
اسم المجموعة لتشغيل العملية. بعد التهيئة، ستحاول عملية turnserver تغيير معرف المجموعة الحالي إلى هذه المجموعة.
-K, --keep-address-family
تم إيقافه وسيتم إزالته لصالح --allocation-default-address-family !! يقوم خادم TURN بتخصيص عائلة عنوان اتصال عميل TURN <=> الخادم. !! إنه ينتهك RFC6156 القسم-4.2 (ينتهك الافتراضي IPv4) !!
-A --allocation-default-address-family=<ipv4|ipv6|keep>
الافتراضي هو IPv4. يقوم خادم TURN بتخصيص عائلة عنوان وفقًا لعائلة العنوان التي طلبها عميل TURN. إذا لم يتم طلب عائلة العنوان صراحةً من قبل العميل، فإنه يعود إلى هذا الافتراضي. يحدد معيار RFC صراحةً أن هذا الافتراضي يجب أن يكون IPv4، لذا استخدم خيارات أخرى بحذر!
--cli-ip
عنوان IP للنظام المحلي الذي سيتم استخدامه لواجهة إدارة CLI. يمكن الوصول إلى عملية turnserver للإدارة باستخدام telnet، على عنوان IP هذا وعلى منفذ CLI (انظر المعلمة التالية). القيمة الافتراضية هي 127.0.0.1. يمكنك استخدام telnet أو putty (في وضع telnet) للوصول إلى واجهة إدارة CLI.
--cli-port
منفذ الاستماع لواجهة إدارة CLI. الافتراضي هو 5766.
--cli-password
كلمة مرور الوصول إلى CLI. الافتراضي هو فارغ (لا توجد كلمة مرور). لأسباب أمنية، يوصى باستخدام الشكل المشفر لكلمة المرور (انظر الأمر -P في الأداة المساعدة turnadmin). يجب إلغاء الهروب من علامات الدولار في الشكل المشفر.
--cli-max-output-sessions
الحد الأقصى لعدد جلسات الإخراج في أمر ps CLI. يمكن تغيير هذه القيمة أثناء التشغيل في CLI. القيمة الافتراضية هي 256.
--web-admin
تمكين دعم Turn Web-admin. بشكل افتراضي، يكون معطلاً.
--web-admin-ip=<IP>
عنوان IP للنظام المحلي الذي سيتم استخدامه لنقطة نهاية خادم Web-admin. القيمة الافتراضية هي 127.0.0.1.
--web-admin-port=<port>
منفذ خادم Web-admin. الافتراضي هو 8080.
--web-admin-listen-on-workers
تمكين خادم web-admin للاستماع على منافذ STUN/TURN الخاصة بالعاملين STUN/TURN. بشكل افتراضي، يكون معطلاً لأسباب أمنية! (كان هذا السلوك هو السلوك الافتراضي، وكان ممكنًا بشكل افتراضي.)
--ne=[1|2|3]
تعيين نوع محرك الشبكة للعملية (لأغراض داخلية).
--rfc5780
تمكين RFC5780 (اكتشاف سلوك NAT). في الأصل، إذا كان هناك أكثر من عنوان استماع واحد من نفس عائلة العنوان، فسيتم تمكين ميزة اكتشاف سلوك NAT افتراضيًا. يقوم هذا الخيار بتمكين هذا السلوك الأصلي (اكتشاف سلوك NAT) ويضيف سمات إلى الاستجابة، وهذا يزيد من احتمالية هجوم التضخيم. يُنصح بشدة بإبقاء هذا الخيار مغلقًا لتقليل عامل الكسب في استجابات ربط STUN.
--no-stun-backward-compatibility
تعطيل معالجة طلبات STUN القديمة وتعطيل سمة MAPPED-ADDRESS في استجابة الربط (استخدام XOR-MAPPED-ADDRESS فقط).
--response-origin-only-with-rfc5780
إرسال سمة RESPONSE-ORIGIN فقط في استجابة الربط إذا كان RFC5780 ممكّنًا.

معلومات عامة

The turnserver is a server implementing the STUN and TURN protocols. It can relay UDP, TCP, and TLS connections.

==================================

SYSTEMD

The turnserver package provides a systemd service file. You can enable and start the service using:

systemctl enable turnserver.service

systemctl start turnserver.service

The service configuration can be adjusted in /etc/turnserver.conf.

==================================

تشغيل خادم TURN

The turnserver can be run from the command line. The basic syntax is:

turnserver [options]

The configuration file is typically located at /etc/turnserver.conf. Options specified on the command line will override those in the configuration file.

For a full list of options, please refer to the man page:

man turnserver

==================================

موازنة الحمل وتحسين الأداء

For load balancing and performance tuning, consider the following:

  • Multiple instances: Run multiple instances of turnserver on the same or different machines.

  • Database backend: For high availability and scalability, use a database backend like PostgreSQL or MySQL instead of SQLite.

  • Configuration tuning: Adjust parameters such as the number of worker threads, allowed peer-reflexive addresses, and session timeouts in the configuration file.

  • Networking: Ensure proper network configuration, including firewall rules and port forwarding, to allow TURN traffic.

===================================

استخدام WebRTC

The turnserver is commonly used in WebRTC deployments to enable peer-to-peer communication between clients behind NATs or firewalls. The server relays media and control traffic, ensuring connectivity.

Key configuration parameters for WebRTC include:

  • Realm and users: Define realms and user credentials for authentication.

  • Listening ports: Specify the ports for UDP, TCP, and TLS traffic.

  • Relay addresses: Configure the IP addresses that the server will use for relaying traffic.

===================================

واجهة برمجة تطبيقات REST للـ TURN

The turnserver can be managed remotely via a REST API. This allows for dynamic configuration updates, user management, and retrieving server statistics without restarting the server.

The REST API is typically enabled and configured in the /etc/turnserver.conf file. Refer to the official documentation for detailed API endpoints and usage.

===================================

قواعد البيانات

The turnserver supports multiple database backends for storing configuration and runtime data. Supported databases include:

  • SQLite: A simple, file-based database suitable for smaller deployments or testing.

  • MySQL/MariaDB: A robust relational database for larger deployments.

  • PostgreSQL: Another powerful relational database option.

The database can be initialized using the turnadmin utility or automatically when the turnserver starts for the first time with an empty database.

If you are using SQLite, you do not have to do even that - just run turnadmin and it will set the users for you (see the turnadmin manuals). If you are using SQLite, then the turnserver or turnadmin will initialize the empty database, for you, when started. The TURN server installation process creates an empty initialized SQLite database in the default location (/var/db/turndb or /usr/local/var/db/turndb or /var/lib/turn/turndb, depending on the system).

=================================

ALPN

The server supports ALPNs "stun.turn" and "stun.nat-discovery". If the server receives a TLS/DTLS ClientHello message that contains one or both of those ALPNs, then the server chooses the first stun.* label and sends it back (in the ServerHello) in the ALPN extension field. If no stun.* label is found, then the server does not include the ALPN information into the ServerHello.

السجلات

When the TURN Server starts, it makes efforts to create a log file turn_<pid>.log in the following directories:

  • /var/log
  • /log/
  • /var/tmp
  • /tmp
  • current directory

If all efforts failed (due to the system permission settings) then all log messages are sent only to the standard output of the process.

This behavior can be controlled by --log-file, --syslog and --no-stdout-log options.

=================================

واجهة الإدارة عبر HTTPS

The turnserver process provides an HTTPS Web access as statistics and basic management interface. The turnserver listens to incoming HTTPS admin connections on the same ports as the main TURN/STUN listener. The Web admin pages are basic and self-explanatory.

To make the HTTPS interface active, the database table admin_user must be populated with the admin user account(s). An admin user can be a superuser (if not assigned to a particular realm) or a restricted user (if assigned to a realm). The restricted admin users can perform only limited actions, within their corresponding realms.

=================================

واجهة سطر الأوامر عبر Telnet

The turnserver process provides a telnet CLI access as statistics and basic management interface. By default, the turnserver starts a telnet CLI listener on IP 127.0.0.1 and port 5766. That can be changed by the command-cline options of the turnserver process (see --cli-ip and --cli-port options). The full list of telnet CLI commands is provided in "help" command output in the telnet CLI.

=================================

المجموعات (Clusters)

TURN Server can be a part of the cluster installation. But, to support the "even port" functionality (RTP/RTCP streams pairs) the client requests from a particular IP must be delivered to the same TURN Server instance, so it requires some networking setup massaging for the cluster. The reason is that the RTP and RTCP relaying endpoints must be allocated on the same relay IP. It would be possible to design a scheme with the application-level requests forwarding (and we may do that later) but it would affect the performance.

    turnserver(8)

    NAME

    turnserver - GNU turnserver

    =================================

    SYNOPSIS

    ==================================

    DESCRIPTION

    The GNU TURN Server (turnserver) implements the Session Traversal Utilities for NAT (STUN) and Traversal Using Relays around NAT (TURN) protocols as specified in RFC 5766. It can be used to relay network traffic between peers that cannot directly communicate due to NAT or firewall restrictions.

    =================================_2

    OPTIONS

    The turnserver program accepts the following options:

    -h, --help
    Display a help message and exit.
    -v, --version
    Display version information and exit.
    -c, --config=FILE
    Use configuration file FILE. If not specified, defaults to /etc/turnserver.conf.
    -L, --local=IP
    Listen on local IP address IP. Can be specified multiple times for multiple addresses.
    -d, --daemon
    Run as a daemon in the background.
    -K, --secure-logins
    Use secure logins (TLS) for the management interface.
    -t, --threads=NUM
    Use NUM worker threads. Defaults to the number of CPU cores.
    -T, --log-file=FILE
    Log to FILE instead of syslog.
    -V, --verbose
    Increase logging verbosity.

    =================================_3

    ALPN

    The server supports the Application-Layer Protocol Negotiation (ALPN) extension for TLS, allowing clients to specify the desired protocol (e.g., "stun", "turn") over a single TLS connection.

    =================================_4

    LIBRARIES

    This server relies on the libturnutils library for its core functionality.

    =================================_5

    DOCS

    More detailed documentation can be found in the docs/ directory of the source distribution.

    =================================_6

    LOGS

    Logs are typically sent to syslog. The path to the log file can be configured using the --log-file option or in the configuration file.

    =================================_7

    HTTPS MANAGEMENT INTERFACE

    The server provides an optional HTTPS management interface for monitoring and configuration. It can be enabled and configured in the configuration file.

    =================================_8

    TELNET CLI

    A Telnet Command Line Interface (CLI) can be enabled for administrative tasks. It allows interactive control and monitoring of the server.

    =================================_9
