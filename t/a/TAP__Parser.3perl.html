TAP::Parser(3perl) دليل مرجع مطوري Perl TAP::Parser(3perl)

الاسم

TAP::Parser - تحليل ناتج TAP

الإصدار

الإصدار 3.50

الملخص

use TAP::Parser;
my $parser = TAP::Parser->new( { source => $source } );
while ( my $result = $parser->next ) {
    print $result->as_string;
}

الوصف

"TAP::Parser" مصمم لإنتاج تحليل صحيح لنتائج TAP. لمثال على كيفية تشغيل الاختبارات باستخدام هذه الوحدة، انظر إلى الموجهات البسيطة في "examples/".

يوجد ويكي مخصص لبروتوكول اختبار TAP:

http://testanything.org

يتضمن كتيب TAP::Parser:

http://testanything.org/testing-with-tap/perl/tap::parser-cookbook.html

الطرق

طرق الفئة

"new"

my $parser = TAP::Parser->new(\%args);

يعيد كائن "TAP::Parser" جديد.

يجب أن تكون الوسائط عبارة عن hashref مع أحد المفاتيح التالية:

  • "source"

    تغير في 3.18

    هذه هي الطريقة المفضلة لتمرير الإدخال إلى المنشئ.

    يتم استخدام "source" لإنشاء كائن TAP::Parser::Source الذي يتم تمريره إلى iterador_factory_class، والذي بدوره يكتشف كيفية التعامل مع المصدر وينشئ TAP::Parser::Iterator له. يتم استخدام المكرر بواسطة المحلل لقراءة دفق TAP.

    لتهيئة IteratorFactory استخدم المعلمة "sources" أدناه.

    ملاحظة: "source" و "tap" و "exec" متنافية متبادلة.

  • "tap"

    تغير في 3.18

    يجب أن تكون القيمة هي ناتج TAP الكامل.

    يتم استخدام tap لإنشاء كائن TAP::Parser::Source الذي يتم تمريره إلى iterador_factory_class، والذي بدوره يكتشف كيفية التعامل مع المصدر وينشئ TAP::Parser::Iterator له. يتم استخدام المكرر بواسطة المحلل لقراءة دفق TAP.

    لتهيئة IteratorFactory استخدم المعلمة "sources" أدناه.

    ملاحظة: "source" و "tap" و "exec" متنافية متبادلة.

  • "exec"

    يجب تمرير مرجع مصفوفة.

    يتم استخدام مرجع مصفوفة exec لإنشاء كائن TAP::Parser::Source الذي يتم تمريره إلى iterador_factory_class، والذي بدوره يكتشف كيفية التعامل مع المصدر وينشئ TAP::Parser::Iterator له. يتم استخدام المكرر بواسطة المحلل لقراءة دفق TAP.

    بشكل افتراضي، ينشئ TAP::Parser::SourceHandler::Executable كائن TAP::Parser::Iterator::Process للتعامل مع المصدر. يقوم هذا بتمرير مرجع المصفوفة كسلسلة من الوسائط إلى IPC::Open3::open3:

    exec => [ '/usr/bin/ruby', 't/my_test.rb' ]

    إذا تم تقديم بعض "test_args"، فسيتم إلحاقها بنهاية قائمة وسائط الأمر.

    لتهيئة IteratorFactory استخدم المعلمة "sources" أدناه.

    ملاحظة: "source" و "tap" و "exec" متنافية متبادلة.

المفاتيح التالية اختيارية.

  • "sources"

    جديد في 3.18.

    إذا تم تعيينه، يجب أن يكون "sources" عبارة عن hashref يحتوي على أسماء TAP::Parser::SourceHandler لتحميلها و/أو تهيئتها. القيم عبارة عن hash من التكوين الذي يمكن الوصول إليه عبر "config_for" في TAP::Parser::Source.

    مثال:

    sources => {
  Perl => { exec => '/path/to/custom/perl' },
  File => { extensions => [ '.tap', '.txt' ] },
  MyCustom => { some => 'config' },
}

    سيؤدي هذا إلى جعل "TAP::Parser" يمرر التكوين المخصص إلى اثنين من المعالجات المثبتة مسبقًا - TAP::Parser::SourceHandler::Perl و TAP::Parser::SourceHandler::File - وسيُحاول تحميل الفئة "MyCustom". انظر "load_handlers" في TAP::Parser::IteratorFactory لمزيد من التفاصيل.

    تؤثر المعلمة "sources" على كيفية التعامل مع معلمات "source" و "tap" و "exec".

    انظر TAP::Parser::IteratorFactory و TAP::Parser::SourceHandler والفئات الفرعية الخاصة بهم لمزيد من التفاصيل.

  • "callback"

    إذا تم تقديمه، فسيتم استدعاء كل رد اتصال مقابل نوع معين من النتائج مع النتيجة كوسيط إذا تم استخدام طريقة "run":

    my %callbacks = (
    test    => \&test_callback,
    plan    => \&plan_callback,
    comment => \&comment_callback,
    bailout => \&bailout_callback,
    unknown => \&unknown_callback,
);
my $aggregator = TAP::Parser::Aggregator->new;
for my $file ( @test_files ) {
    my $parser = TAP::Parser->new(
        {
            source    => $file,
            callbacks => \%callbacks,
        }
    );
    $parser->run;
    $aggregator->add( $file, $parser );
}
  • "switches"

    إذا تم استخدام ملف Perl كمصدر، يمكنك تمرير مفاتيح اختيارية سيتم استخدامها عند استدعاء منفذ Perl.

    my $parser = TAP::Parser->new( {
    source   => $test_file,
    switches => [ '-Ilib' ],
} );
  • "test_args"

    تستخدم مع معلمات "source" و "exec" لتوفير مرجع لمصفوفة وسائط نمط @ARGV لبرنامج الاختبار.

  • "spool"

    إذا تم تمرير مقبض ملف، فسيتم كتابة نسخة من كل TAP تم تحليله إلى هذا المقبض.

  • "merge"

    إذا كان خطأ (false)، فلن يتم التقاط STDERR (على الرغم من إرساله إلى STDOUT للحفاظ على التزامن).

    إذا كان صحيحًا، فإن STDERR و STDOUT عبارة عن نفس مقبض الملف. قد يتسبب هذا في مشاكل إذا كان STDERR يحتوي على شيء مشابه لنمط TAP، ولكنه يسمح بالتزامن الدقيق.

    قد تعتمد تفاصيل هذا السلوك على النظام وقد تتغير في المستقبل.

  • "grammar_class"

    تم تقديم هذا الخيار للسماح لك بتخصيص فئة القواعد التي يجب على المحلل استخدامها بسهولة. القيمة الافتراضية هي TAP::Parser::Grammar.

    انظر أيضًا "make_grammar".

  • "result_factory_class"

    تم تقديم هذا الخيار للسماح لك بتخصيص فئة النتائج factory التي يجب على المحلل استخدامها بسهولة. القيمة الافتراضية هي TAP::Parser::ResultFactory.

    انظر أيضًا "make_result".

  • "iterator_factory_class"

    تغيير في 3.18

    تم تقديم هذا الخيار للسماح لك بتخصيص فئة المكرر factory التي يجب على المحلل استخدامها بسهولة. القيمة الافتراضية هي TAP::Parser::IteratorFactory.

طرق النسخة

"next""is_unplanned"

if ( $test->is_unplanned ) { ... }

إذا كان رقم الاختبار أكبر من عدد الاختبارات المخطط لها، فسوف تقوم هذه الطريقة بإرجاع القيمة true. ستُرجع الاختبارات غير المخطط لها دائمًا القيمة false لـ "is_ok"، بغض النظر عما إذا كان الاختبار "has_todo" أم لا (راجع TAP::Parser::Result::Test لمزيد من المعلومات حول هذا).

"has_skip"

if ( $result->has_skip ) { ... }

تُرجع قيمة منطقية تشير إلى ما إذا كان هذا الاختبار يحتوي على توجيه SKIP أم لا.

"has_todo"

if ( $result->has_todo ) { ... }

تُرجع قيمة منطقية تشير إلى ما إذا كان هذا الاختبار يحتوي على توجيه TODO أم لا.

لاحظ أن اختبارات TODO تمر دائمًا. إذا كنت بحاجة إلى معرفة ما إذا كانت قد مرت بالفعل أم لا، فتحقق من الطريقة "is_actual_ok".

"in_todo"

if ( $parser->in_todo ) { ... }

صحيح أثناء أن النتيجة الأخيرة كانت TODO. تصبح صحيحة قبل إرجاع نتيجة TODO وتظل صحيحة حتى قبل إرجاع اختبار غير TODO التالي.

نتائج إجمالية

بعد تحليل TAP، تتوفر العديد من الطرق لتتيح لك الغوص في النتائج وتحديد ما هو مهم بالنسبة لك.

نتائج فردية

تشير هذه النتائج إلى الاختبارات الفردية التي تم تشغيلها.

"passed"

my @passed = $parser->passed; # أرقام الاختبارات التي مرت
my $passed = $parser->passed; # عدد الاختبارات التي مرت

تتيح لك هذه الطريقة معرفة الاختبارات التي مرت (أو عددها). إذا فشل اختبار ولكن كان لديه توجيه TODO، فسيتم احتسابه كاختبار ناجح.

"failed"

my @failed = $parser->failed; # أرقام الاختبارات التي فشلت
my $failed = $parser->failed; # عدد الاختبارات التي فشلت

تتيح لك هذه الطريقة معرفة الاختبارات التي فشلت (أو عددها). إذا نجح اختبار ولكن كان لديه توجيه TODO، فلن يتم احتسابه كاختبار فاشل.

"actual_passed"

# أرقام الاختبارات التي مرت بالفعل
my @actual_passed = $parser->actual_passed;
# عدد الاختبارات التي مرت بالفعل
my $actual_passed = $parser->actual_passed;

تتيح لك هذه الطريقة معرفة الاختبارات التي مرت بالفعل (أو عددها)، بغض النظر عما إذا تم العثور على توجيه TODO أم لا.

"actual_ok"

هذه الطريقة هي مرادف لـ "actual_passed".

"actual_failed"

# أرقام الاختبارات التي فشلت بالفعل
my @actual_failed = $parser->actual_failed;
# عدد الاختبارات التي فشلت بالفعل
my $actual_failed = $parser->actual_failed;

تتيح لك هذه الطريقة معرفة الاختبارات التي فشلت بالفعل (أو عددها)، بغض النظر عما إذا تم العثور على توجيه TODO أم لا.

"todo"

my @todo = $parser->todo; # أرقام الاختبارات مع توجيهات todo
my $todo = $parser->todo; # عدد الاختبارات مع توجيهات todo

تتيح لك هذه الطريقة معرفة الاختبارات التي تحتوي على توجيهات TODO (أو عددها).

"todo_passed"

# أرقام الاختبارات التي نجحت بشكل غير متوقع
my @todo_passed = $parser->todo_passed;
# عدد الاختبارات التي نجحت بشكل غير متوقع
my $todo_passed = $parser->todo_passed;

تتيح لك هذه الطريقة معرفة الاختبارات التي مرت بالفعل ولكن تم الإعلان عنها كاختبارات "TODO" (أو عددها).

"todo_failed"

# تم إيقاف استخدامها لصالح 'todo_passed'. كانت هذه الطريقة ذات تسمية خاطئة بشكل فظيع.

كانت هذه الطريقة ذات تسمية خاطئة. تشير إلى اختبارات TODO التي نجحت بشكل غير متوقع. ستصدر الآن تحذيرًا وتستدعي "todo_passed".

"skipped"

my @skipped = $parser->skipped; # أرقام الاختبارات مع توجيهات SKIP
my $skipped = $parser->skipped; # عدد الاختبارات مع توجيهات SKIP

تتيح لك هذه الطريقة معرفة الاختبارات التي تحتوي على توجيهات SKIP (أو عددها).

الأوامر

"pragma"

الحصول على أمر أو تعيينه. للحصول على حالة الأمر:

if ( $p->pragma('strict') ) {
    # كن صارمًا
}

لتعيين حالة الأمر:

$p->pragma('strict', 1); # تمكين الوضع الصارم

"pragmas"

الحصول على قائمة بجميع الأوامر التي تم تمكينها حاليًا:

my @pragmas_enabled = $p->pragmas;

نتائج ملخصة

هذه النتائج هي معلومات "meta" حول النتائج الإجمالية لبرنامج اختبار فردي.

"plan"

my $plan = $parser->plan;

تُرجع خطة الاختبار، إذا تم العثور عليها.

"good_plan"

تم إيقاف استخدامه. استخدم "is_good_plan" بدلاً من ذلك.

"is_good_plan"

if ( $parser->is_good_plan ) { ... }

تُرجع قيمة منطقية تشير إلى ما إذا كان عدد الاختبارات المخطط لها يتطابق مع عدد الاختبارات التي تم تشغيلها أم لا.

ملاحظة: كان هذا سابقًا "good_plan". تم إيقاف استخدام الطريقة الأخيرة وسيتم إصدار تحذير.

وبما أننا نتحدث عن هذا الموضوع...

"tests_planned"

print $parser->tests_planned;

تُرجع عدد الاختبارات المخطط لها، وفقًا للخطة. على سبيل المثال، تعني الخطة '1..17' أنه تم التخطيط لـ 17 اختبارًا.

"tests_run"

print $parser->tests_run;

تُرجع عدد الاختبارات التي تم تشغيلها فعليًا. نأمل أن يتطابق هذا مع عدد "$parser->tests_planned".

"skip_all"

تُرجع قيمة صحيحة (السبب الفعلي للتخطي) إذا تم تخطي جميع الاختبارات.

"start_time"

تُرجع وقت ساعة الحائط عند إنشاء المحلل.

"end_time"

تُرجع وقت ساعة الحائط عند رؤية نهاية إدخال TAP.

"start_times"

تُرجع أوقات وحدة المعالجة المركزية (مثل "times" في perlfunc عند إنشاء المحلل).

"end_times"

تُرجع أوقات وحدة المعالجة المركزية (مثل "times" في perlfunc عند رؤية نهاية إدخال TAP.

"has_problems"

if ( $parser->has_problems ) {
    ...
}

هذه طريقة "التقاط الكل" التي تُرجع true إذا فشلت أي اختبارات حاليًا، أو نجحت اختبارات TODO بشكل غير متوقع، أو حدثت أي أخطاء في التحليل.

"version"

$parser->version;

بمجرد انتهاء المحلل، ستُرجع هذه الطريقة رقم إصدار TAP الذي تم تحليله. تم تقديم أرقام الإصدارات مع TAP الإصدار 13، لذلك إذا لم يتم العثور على رقم إصدار، فسيتم افتراض الإصدار 12.

"exit"

$parser->exit;

بمجرد انتهاء المحلل، ستُرجع هذه الطريقة حالة الخروج. إذا قام المحلل بتشغيل قابل للتنفيذ، فإنه يُرجع حالة خروج القابل للتنفيذ.

"wait"

$parser->wait;

بمجرد انتهاء المحلل، ستُرجع هذه الطريقة حالة الانتظار. إذا قام المحلل بتشغيل قابل للتنفيذ، فإنه يُرجع حالة انتظار القابل للتنفيذ. بخلاف ذلك، فإن هذه الطريقة تُرجع ببساطة حالة "exit".

"ignore_exit"

$parser->ignore_exit(1);

أخبر المحلل بتجاهل حالة الخروج من الاختبار عند تحديد ما إذا كان الاختبار قد نجح. عادةً ما تعتبر الاختبارات ذات حالة الخروج غير الصفرية قد فشلت حتى لو نجحت جميع الاختبارات الفردية. في الحالات التي لا يمكن فيها التحكم في قيمة الخروج لبرنامج نصي للاختبار، استخدم هذا الخيار لتجاهله.

"parse_errors"

my @errors = $parser->parse_errors; # أخطاء المحلل
my $errors = $parser->parse_errors; # عدد أخطاء المحلل_

لحسن الحظ، جميع مخرجات TAP مثالية. في حالة عدم كونها كذلك، ستُرجع هذه الطريقة أخطاء المحلل. لاحظ أن سطرًا غير مرغوب فيه لا يتعرف عليه المحلل ليس خطأ. هذا يسمح لهذا المحلل بمعالجة الإصدارات المستقبلية من TAP. ما يلي هي جميع أخطاء TAP التي أبلغ عنها المحلل:

  • خطة في غير محلها

    يجب أن تأتي الخطة (على سبيل المثال، '1..5') فقط في بداية أو نهاية مخرجات TAP.

  • لا توجد خطة

    يجب أن تكون هناك خطة!

  • أكثر من خطة واحدة 
    1..3
ok 1 - تم فتح ملف الإدخال
not ok 2 - السطر الأول من الإدخال صالح # todo بعض البيانات
ok 3 قراءة بقية الملف
1..3

    حسنًا. مضحك جدًا. لا تفعل ذلك.

  • أرقام الاختبارات خارج التسلسل 
    1..3
ok 1 - تم فتح ملف الإدخال
not ok 2 - السطر الأول من الإدخال صالح # todo بعض البيانات
ok 2 قراءة بقية الملف

    يجب أن يحتوي سطر الاختبار الأخير أعلاه على الرقم '3' بدلاً من '2'.

    لاحظ أنه من المقبول تمامًا أن تحتوي بعض الأسطر على أرقام اختبارات والبعض الآخر لا يحتوي عليها. ومع ذلك، عندما يتم العثور على رقم اختبار، يجب أن يكون بالتسلسل. ما يلي هو أيضًا خطأ:

    1..3
ok 1 - تم فتح ملف الإدخال
not ok - السطر الأول من الإدخال صالح # todo بعض البيانات
ok 2 قراءة بقية الملف

    لكن هذا ليس كذلك:

    1..3
ok - تم فتح ملف الإدخال
not ok - السطر الأول من الإدخال صالح # todo بعض البيانات
ok 3 قراءة بقية الملف

TAP::Parser::Grammar - Perl 5.42.0 Documentation

TAP::PARSER::GRAMMAR

TAP::Parser::Grammar is the heart of the parser. It tokenizes the TAP input stream and produces results. If you need to customize its behaviour you should probably familiarize yourself with the source first. Enough lecturing.

Subclass TAP::Parser::Grammar and customize your parser by setting the "grammar_class" parameter. See "new" for more details.

If you need to customize the objects on creation, subclass TAP::Parser and override "make_result".

يرجى الإبلاغ عن أي أخطاء أو طلبات ميزات إلى "bug-test-harness@rt.cpan.org"، أو عبر واجهة الويب على http://rt.cpan.org/NoAuth/ReportBug.html?Queue=Test-Harness. سيتم إخطارنا، وبعد ذلك سيتم إخطارك تلقائيًا بتقدم خطأك أثناء إجراء التغييرات.

من الواضح أن الأخطاء التي تتضمن تصحيحات هي الأفضل. إذا كنت تفضل ذلك، يمكنك تطبيق تصحيحات على الإصدار الأحدث عن طريق سحب مجهول لأحدث إصدار:

git clone git://github.com/Perl-Toolchain-Gang/Test-Harness.git
