task <filter> count
يُرجع عدد المهام التي تطابق المرشح.
task <filter> export [type]
تصدير المهام المطابقة للمرشح. إذا لم يتم تحديد نوع، فسيتم تصديرها بتنسيق JSON. التنسيقات المدعومة هي: JSON، CSV، XML، YAML، Ical، TSV. يمكنك العثور على هذه البرامج النصية النموذجية عبر الإنترنت على https://taskwarrior.org/tools/: 
  export-csv.pl
  export-sql.py
  export-xml.py
  export-yaml.pl
  export-html.pl
  export-tsv.pl
  export-xml.rb
  export-ical.pl
  export-xml.pl
  export-yad.pl
task <filter> ghistory.annual
يعرض تقريرًا رسوميًا لحالة المهام حسب السنة.
task <filter> ghistory.monthly
يعرض تقريرًا رسوميًا لحالة المهام حسب الشهر. لاحظ أن 'ghistory' هو اسم مستعار لـ 'ghistory.monthly'.
task <filter> ghistory.weekly
يعرض تقريرًا رسوميًا لحالة المهام حسب الأسبوع.
task <filter> ghistory.daily
يعرض تقريرًا رسوميًا لحالة المهام حسب اليوم.
task help
يعرض نص الاستخدام المطول.
task <filter> history.annual
يعرض تقريرًا لتاريخ المهام حسب السنة. يتأثر بالسياق.
task <filter> history.monthly
يعرض تقريرًا لتاريخ المهام حسب الشهر. لاحظ أن 'history' هو اسم مستعار لـ 'history.monthly'. يتأثر بالسياق.
task <filter> history.weekly
يعرض تقريرًا لتاريخ المهام حسب الأسبوع. يتأثر بالسياق.
task <filter> history.daily
يعرض تقريرًا لتاريخ المهام حسب اليوم. يتأثر بالسياق.
task <filter> ids
يطبق المرشح ثم يستخرج فقط معرفات المهام ويعرضها كقائمة مفصولة بمسافات. هذا مفيد كمدخل لأمر task، لتحقيق ما يلي: 
  task $(task project:Home ids) modify priority:H

هذا المثال يستخرج أولاً معرفات المرشح project:Home، ثم يضبط الأولوية إلى H لكل تلك المهام. يمكن تحقيق ذلك أيضًا مباشرة:

  task project:Home modify priority:H

هذا الأمر مفيد بشكل أساسي للبرامج النصية الخارجية.

task <filter> uuids
يطبق المرشح على جميع المهام (حتى المهام المحذوفة والمكتملة) ثم يستخرج فقط المعرفات الفريدة للمهام (UUIDs) ويعرضها كقائمة مفصولة بمسافات. هذا مفيد كمدخل لأمر task، لتحقيق ما يلي: 
  task $(task project:Home status:completed uuids) modify status:pending

هذا المثال يستخرج أولاً المعرفات الفريدة للمرشحين project:Home و status:completed، ثم يعيد كل تلك المهام إلى حالة 'pending'.

هذا الأمر مفيد بشكل أساسي للبرامج النصية الخارجية.

task udas
يعرض قائمة بالسمات المعرفة من قبل المستخدم (UDAs)، بما في ذلك اسمها ونوعها والتسمية والقيم المسموح بها. يعرض أيضًا استخدام UDAs وأي UDAs يتيمة.
task <filter> information
يعرض جميع البيانات والبيانات الوصفية للمهام المحددة. هذه هي الوسيلة الوحيدة لعرض جميع جوانب مهمة معينة، بما في ذلك سجل التغييرات.
task <filter> list
يوفر قائمة قياسية بالمهام المطابقة للمرشح.
task <filter> long
يوفر قائمة مفصلة للغاية بالمهام المطابقة للمرشح.
task <filter> ls
يوفر قائمة مختصرة بالمهام المطابقة للمرشح.
task <filter> minimal
يوفر قائمة بسيطة بالمهام المطابقة للمرشح.
task <filter> newest
يعرض أحدث المهام المطابقة للمرشح.
task <filter> next
يعرض صفحة من المهام الأكثر إلحاحًا، مرتبة حسب الأولوية، وهي قيمة محسوبة.
task <filter> ready
يعرض صفحة من المهام الجاهزة الأكثر إلحاحًا، مرتبة حسب الأولوية مع بدء المهام أولاً. المهمة الجاهزة هي مهمة إما غير مجدولة، أو لديها تاريخ جدولة قد مضى وليست في حالة انتظار.
task <filter> oldest
يعرض أقدم المهام المطابقة للمرشح.
task <filter> overdue
يعرض جميع المهام غير المكتملة المطابقة للمرشح التي تجاوزت تاريخ استحقاقها.
task <filter> projects
يسرد جميع أسماء المشاريع المستخدمة حاليًا من قبل المهام المعلقة، وعدد المهام لكل منها. يتأثر بالسياق.
task <filter> recurring
يعرض جميع المهام المتكررة المطابقة للمرشح.
task <filter> unblocked
يعرض جميع المهام التي لا تعتمد حاليًا على مهام أخرى، وتطابق المرشح.
task <filter> waiting
يعرض جميع المهام المعلقة المطابقة للمرشح.

أوامر الكتابة

task add <mods>
يضيف مهمة جديدة معلقة إلى قائمة المهام. يتأثر بالسياق المحدد حاليًا.
task <filter> annotate <mods>
يضيف تعليقًا إلى مهمة موجودة.
task <filter> append <mods>
يضيف نص وصف إلى نهاية مهمة موجودة.
task <filter> delete <mods>
يحذف المهمة المحددة من قائمة المهام. يتأثر بالسياق.
task <filter> denotate <mods>
يحذف تعليقًا من المهمة المحددة. إذا كان الوصف المقدم يطابق تعليقًا تمامًا، يتم حذف التعليق المقابل. إذا كان الوصف المقدم يطابق التعليقات جزئيًا، يتم حذف أول تعليق مطابق جزئيًا. يتأثر بالسياق.
task <filter> done <mods>
يضع علامة "تم" على المهمة المحددة. يتأثر بالسياق.
task <filter> duplicate <mods>
ينسخ المهمة المحددة ويسمح بإجراء تعديلات. يتأثر بالسياق.
task <filter> edit
يشغل محرر نصوص للسماح لك بتعديل جميع جوانب المهمة مباشرة. بشكل عام، هذه ليست الطريقة الموصى بها لتعديل المهام، ولكنها متوفرة للظروف الاستثنائية. استخدم بحذر. يتأثر بالسياق.
task import [<file> ...]
يستورد المهام بتنسيق JSON. يمكن استخدامه لإضافة مهام جديدة، أو تحديث مهام موجودة. يتم التعرف على المهام بواسطة المعرفات الفريدة (UUIDs) الخاصة بها.

إذا لم يتم تحديد ملف أو "-"، فسيتم استيراد المهام من STDIN.

يوصى بضبط rc.recurrence.confirmation إلى مستوى مناسب إذا كان سيتم استخدام الاستيراد في مسارات عمل مؤتمتة. انظر taskrc(5).

لاستيراد تنسيقات ملفات أخرى، يأتي الإصدار القياسي من task مع بعض البرامج النصية النموذجية، مثل:

  import-todo.sh.pl
  import-yaml.pl
task import-v2
يستورد المهام من تنسيق Taskwarrior v2.x. يستخدم هذا عند الترقية من الإصدار 2.x إلى الإصدار 3.x.
task log <mods>
يضيف مهمة جديدة مكتملة بالفعل إلى قائمة المهام. يتأثر بالسياق المحدد حاليًا.
task <filter> modify <mods>
يعدل المهمة الموجودة بالمعلومات المقدمة.
task <filter> prepend <mods>
يضيف نص وصف إلى بداية مهمة موجودة. يتأثر بالسياق.
task <filter> purge
يزيل المهام المحددة بشكل دائم من ملفات البيانات. فقط المهام التي تم حذفها بالفعل يمكن مسحها. هذا الأمر له تأثير محلي فقط ولا تتم مزامنة التغييرات التي تم إجراؤها بواسطته. يتأثر بالسياق.

تحذير: يسبب فقدانًا دائمًا وغير قابل للتراجع للبيانات.

task <filter> start <mods>
يضع علامة "بدء" على المهام المحددة. يتأثر بالسياق.
task <filter> stop <mods>
يزيل وقت البدء من المهمة المحددة. يتأثر بالسياق.

TAGS

You can specify tags to control how rules are applied.

+tagname
Adds the specified tag to the task. If the tag is prefixed with a tilde (~), it is removed. The "tag" attribute value is set to 1.
-tagname
Removes the specified tag from the task. If the tag is prefixed with a tilde (~), it is added. The "tag" attribute value is set to 0.

The following tags are special and can be used to override default behavior and skip processing of rules:

    +nocolor     Disable color rules processing for this task
    +nonag       Completion of this task suppresses all nag messages
    +nocal       This task will not appear on the calendar
    +next        Elevates task so it appears on 'next' report

There are also virtual tags, which represent task metadata in tag form. These tags do not exist, but can be used to filter tasks. The supported virtual tags are:

    ACTIVE       Matches if the task is started
    ANNOTATED    Matches if the task has annotations
    BLOCKED      Matches if the task is blocked
    BLOCKING     Matches if the task is blocking
    CHILD        Matches if the task has a parent (deprecated in 2.6.0)
    COMPLETED    Matches if the task has completed status
    DELETED      Matches if the task has deleted status
    DUE          Matches if the task is due within the next 7 days (See rc.due)
    INSTANCE     Matches if the task is a recurrent instance
    LATEST       Matches if the task is the newest added task
    MONTH        Matches if the task is due this month
    ORPHAN       Matches if the task has any orphaned UDA values
    OVERDUE      Matches if the task is overdue
    PARENT       Matches if the task is a parent (deprecated in 2.6.0)
    PENDING      Matches if the task has pending status
    PRIORITY     Matches if the task has a priority
    PROJECT      Matches if the task has a project
    QUARTER      Matches if the task is due this quarter
    READY        Matches if the task is actionable
    SCHEDULED    Matches if the task is scheduled
    TAGGED       Matches if the task has tags
    TEMPLATE     Matches if the task is a recurrence template
    TODAY        Matches if the task is due today
    TOMORROW     Matches if the task is due sometime tomorrow
    UDA          Matches if the task has any UDA values
    UNBLOCKED    Matches if the task is not blocked
    UNTIL        Matches if the task expires
    WAITING      Matches if the task is waiting
    WEEK         Matches if the task is due this week
    YEAR         Matches if the task is due this year
    YESTERDAY    Matches if the task was due sometime yesterday

You can use +BLOCKED to filter blocked tasks, or -BLOCKED for unblocked tasks. Similarly, -BLOCKED is equivalent to +UNBLOCKED. It is an error to attempt to add or remove a virtual tag.

project:<project-name>
Specifies the project to which a task is related to.
status:pending|deleted|completed|waiting|recurring
Specifies the state of the task.
priority:H|M|L or priority:
Specifies High, Medium, Low and no priority for a task.
due:<due-date>
Specifies the due-date of a task.
recur:<frequency>
Specifies the frequency of a recurrence of a task.
scheduled:<ready-date>
Specifies the date after which a task can be accomplished.
until:<expiration date of task>
Specifies the expiration date of a task, after which it will be deleted.
limit:<number-of-rows>
Specifies the desired number of tasks a report should show, if a positive integer is given. The value 'page' may also be used, and will limit the report output to as many lines of text as will fit on screen. This defaults to 25 lines.
wait:<wait-date>
When a task is given a wait date, it is hidden from most built-in reports, which exclude +WAITING. When the date is in the past, the task is not considered +WAITING, and again becomes visible. Note that, for compatibilty, such tasks are shown as having status "waiting", but this will change in a future release.
depends:<id1,id2 ...>
Declares this task to be dependent on id1 and id2. This means that the tasks id1 and id2 should be completed before this task. Consequently, this task will then show up on the 'blocked' report. It accepts a comma-separated list of ID numbers, UUID numbers and ID ranges. When prefixing any element of this list by '-', the specified tasks are removed from the dependency list.
entry:<entry-date>
For report purposes, specifies the date that a task was created.
modified:<modified-date>
Specifies the most recent modification date.

ATTRIBUTE MODIFIERS

Attribute modifiers improve filters. Supported modifiers are:

before (synonyms under, below)
after (synonyms over, above)
by
none
any
is (synonym equals)
isnt (synonym not)
has (synonym contains)
hasnt
startswith (synonym left)
endswith (synonym right)
word
noword

They can be applied to all regular attributes (see above) and the following calculated attributes:

urgency (or short urg)

For example:

    task due.before:eom priority.not:L list

The before modifier is used to compare values, preserving semantics, so project.before:B list all projects that begin with 'A'. Priority 'L' is before 'M', and due:2011-01-01 is before due:2011-01-02. The synonyms 'under' and 'below' are included to allow filters that read more naturally.

The after modifier is the inverse of the before modifier.

The by modifier is the same as 'before', except it also includes the moment in question. For example:

    task add test due:eoy

will be found when using the inclusive filter 'by':

    task due.by:eoy

but not when the non-inclusive filter 'before' is used:

    task due.before:eoy

this applies equally to other named dates such as 'eom', 'eod', etc; the modifier compares using '<=' rather than '<' like 'before' does.

The none modifier requires that the attribute does not have a value. For example:

    task priority:      list
    task priority.none: list

are equivalent, and list tasks that do not have a priority.

The any modifier requires that the attribute has a value, but any value will suffice.

The is modifier requires an exact match with the value.

The isnt modifier is the inverse of the is modifier.

The has modifier is used to search for a substring, such as:

    task description.has:foo list
    task foo                 list

These are equivalent and will return any task that has 'foo' in the description or annotations.

The hasnt modifier is the inverse of the has modifier.

The startswith modifier matches against the left, or beginning of an attribute, such that:

    task project.startswith:H list
    task project:H            list

are equivalent and will match any project starting with 'H'. Matching all projects not starting with 'H' is done with:

    task project.not:H         list

The endswith modifier matches against the right, or end of an attribute.

The word modifier requires that the attribute contain the whole word specified, such that this:

    task description.word:foo list

Will match the description 'foo bar baz' but does not match 'dog food'.

The noword modifier is the inverse of the word modifier.

EXPRESSIONS AND OPERATORS

You can use the following operators in filter expressions:

  and  or  xor  !               Logical operators
  <  <=  =  ==  !=  !==  >=  >  Relational operators
  (  )                          Precedence

For example:

  task due.before:eom priority.not:L list
  task '( due < eom or priority != L )' list
  task '! ( project:Home or project:Garden )' list

The = operator tests for approximate equality. Dates compare equal if they are on the same day (hour and minutes are ignored). Strings compare equal if the left operand starts with the right operand. The == operator tests for exact equality. The != and !== operators are the negation of = and == respectively. The negation operator is !.

Note that the parentheses are required when using a logical operator other than the 'and' operator. The reason is that some reports contain filters that must be combined with the command line. Consider this example:

  task project:Home or project:Garden list

While this looks correct, it is not. The 'list' report contains a filter of:

  task show report.list.filter
  Config Variable    Value
  -----------------  --------------
  report.list.filter status:pending

Which means the example is really:

  task status:pending project:Home or project:Garden list

The implied 'and' operator makes it:

  task status:pending and project:Home or project:Garden list

This is a precedence error - the 'and' and 'or' need to be grouped using parentheses, like this:

  task status:pending and ( project:Home or project:Garden ) list

The original example therefore must be entered as:

  task '( project:Home or project:Garden )' list

This includes quotes to escape the parentheses, so that the shell doesn't interpret them and hide them from Taskwarrior.

There is redundancy between operators, attribute modifiers and other syntactic sugar. For example, the following are all equivalent:

  task foo                      list
  task /foo/                    list
  task description.contains:foo list
  task description.has:foo      list
  task 'description ~ foo'

MODIFICATIONS

The modify command modifies tasks. This can be the same as adding or subtracting values.

  $ task 123 add project:Future due:tomorrow

The modification of a task can be done by specifying any attribute, and the value will be set to the new value.

  $ task 123 modify project:Home due:20160101

If the value is empty, the attribute is deleted:

  $ task 123 modify project:

Some attributes are numbers, and can be increased or decreased. For example, to add 10 to the priority:

  $ task 123 modify priority+10

To subtract 5 from the priority:

  $ task 123 modify priority-5

The attribute name can be abbreviated:

  $ task 123 mod prio+10

And so can the command itself:

  $ task 123 mo prio+10

It is possible to change multiple attributes at once:

  $ task 123 modify due:nextweek priority+1 project:Work

The description can be modified, or appended to. To modify the description:

  $ task 123 modify description:New description for task 123

To append to the description:

  $ task 123 modify description+New text to append

In order to modify a value containing spaces, you must quote it:

  $ task 123 modify description="A task with spaces in the description"

Here the description is modified to be exactly "A task with spaces in the description". If you wanted to append to the description, you would write:

  $ task 123 modify description+"Appending this text."

The task specification can be a filter, and the modification will be applied to all matching tasks.

  $ task due:today modify project:Urgent

The command specification may also use quoted arguments:

  $ task 123 modify "from this/to that"

The following modification syntax is broken up into several arguments, which is corrected with quotes:

  $ task 123 modify "/from this/to that/"

It is sometimes necessary to force the shell to pass quotes to Taskwarrior intact, so you can use:

  $ task add project:\'Three Word Project\' description

Taskwarrior supports Unicode using only the UTF8 encoding.

CONFIGURATION FILE AND OVERRIDE OPTIONS

Taskwarrior stores its configuration in a file in the user's home directory: ~/.taskrc. The default configuration file can be overridden with:

task rc:<path-to-alternate-file> ...
Specifies an alternate configuration file with highest priority.
TASKRC=<path-to-alternate-file> task ..
The environment variable specifies an alternate configuration file to use.
XDG_CONFIG_HOME=<path-to-alternate-config-home> task ..
The environment variable specifies an alternate configuration file to use.
task rc.<name>:<value> ...
task rc.<name>=<value> ... Specifies individual configuration file overrides.
TASKDATA=/tmp/.task task ...
The environment variable overrides the default, and the 'data.location' configuration setting of the task data directory.
