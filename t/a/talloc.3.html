talloc(3)

الحزمة: talloc

التراخيص: GPL-3.0-or-later

TALLOC(3) أدوات إدارة النظام TALLOC(3)

الاسم

talloc - نظام تجميع ذاكرة مرجعية متسلسل مع أجهزة تدمير

الملخص

#include <talloc.h>

الوصف

إذا كنت معتادًا على talloc من Samba3، فيرجى قراءة هذا بعناية، حيث تغير talloc كثيرًا.

talloc الجديد هو نظام تجميع ذاكرة مرجعية متسلسل مع أجهزة تدمير. هذا مصطلح طويل حقًا، ولكنه ليس سيئًا جدًا بمجرد أن تعتاد عليه.

ربما يكون التغيير الأكبر عن Samba3 هو أنه لا يوجد تمييز بين "سياق talloc" و "مؤشر talloc". أي مؤشر تم إرجاعه من talloc() هو بحد ذاته سياق talloc صالح. هذا يعني أنه يمكنك فعل هذا:

    struct foo *X = talloc(mem_ctx, struct foo);
    X->name = talloc_strdup(X, "foo");

وسيكون المؤشر X->name "ابنًا" لسياق talloc X الذي هو بحد ذاته ابن لـ mem_ctx. لذلك إذا قمت بعمل talloc_free(mem_ctx) فسيتم تدمير كل شيء، بينما إذا قمت بعمل talloc_free(X) فسيتم تدمير X و X->name فقط، وإذا قمت بعمل talloc_free(X->name) فسيتم تدمير عنصر الاسم فقط في X.

إذا فكرت في هذا، فإن ما يمنحك إياه هذا فعليًا هو شجرة N-ary، حيث يمكنك تحرير أي جزء من الشجرة باستخدام talloc_free().

إذا وجدت هذا مربكًا، أقترح عليك تشغيل برنامج testsuite لمشاهدة talloc أثناء العمل. قد ترغب أيضًا في إضافة اختباراتك الخاصة إلى testsuite.c لتوضيح كيفية التعامل مع موقف معين.

واجهة برمجة تطبيقات TALLOC

الدليل التالي هو دليل كامل لواجهة برمجة تطبيقات talloc. اقرأه كله مرتين على الأقل.

(type *)talloc(const void *ctx, type);

ماكرو talloc() هو جوهر مكتبة talloc. يأخذ ذاكرة ctx و type، ويرجع مؤشرًا إلى منطقة ذاكرة جديدة من النوع المحدد type.

المؤشر المرجع هو بحد ذاته سياق talloc، لذلك يمكنك استخدامه كوسيط ctx لمزيد من استدعاءات talloc() إذا أردت.

المؤشر المرجع هو "ابن" للسياق المقدم. هذا يعني أنه إذا قمت بعمل talloc_free() للسياق ctx، فإن الابن الجديد يختفي أيضًا. بدلاً من ذلك، يمكنك تحرير الابن فقط.

يمكن أن يكون الوسيط ctx لـ talloc() هو NULL، وفي هذه الحالة يتم إنشاء سياق مستوى أعلى جديد.

void *talloc_size(const void *ctx, size_t size);

يجب استخدام الدالة talloc_size() عندما لا يكون لديك نوع مناسب لتمريره إلى talloc(). على عكس talloc()، فهي ليست آمنة من حيث النوع (حيث أنها ترجع void *)، لذلك أنت مسؤول عن التحقق من النوع.

(typeof(ptr)) talloc_ptrtype(const void *ctx, ptr);

يجب استخدام الماكرو talloc_ptrtype() عندما يكون لديك مؤشر وترغب في تخصيص ذاكرة للإشارة إليها بهذا المؤشر. عند الترجمة باستخدام gcc >= 3، تكون آمنة من حيث النوع. لاحظ أن هذا غلاف لـ talloc_size() و talloc_get_name() سيرجع الموقع الحالي في ملف المصدر، وليس النوع.

int talloc_free(void *ptr);

الدالة talloc_free() تحرر قطعة من ذاكرة talloc، وجميع أبنائها. يمكنك استدعاء talloc_free() على أي مؤشر تم إرجاعه بواسطة talloc().

قيمة الإرجاع للدالة talloc_free() تشير إلى النجاح أو الفشل، حيث يتم إرجاع 0 للنجاح و -1 للفشل. الشرط الوحيد الممكن للفشل هو إذا كان للمؤشر ptr جهاز تدمير مرفق به والجهاز قد أعاد -1. انظر “talloc_set_destructor()” للحصول على تفاصيل حول أجهزة التدمير.

إذا كان لهذا المؤشر أب إضافي عند استدعاء talloc_free()، فلن يتم تحرير الذاكرة فعليًا، بل سيتم تدمير الأب المنشأ مؤخرًا. انظر “talloc_reference()” للحصول على تفاصيل حول إنشاء آباء إضافيين.

لمزيد من التحكم في أي أب يجب إزالته، انظر “talloc_unlink()”.

تعمل talloc_free() بشكل تكراري على أبنائها.

من الإصدار 2.0 من talloc، كحالة خاصة، يتم رفض talloc_free() على المؤشرات التي لها أكثر من أب واحد، حيث لن يكون لدى talloc أي طريقة لمعرفة أي أب يجب إزالته. لتحرير مؤشر له أكثر من أب واحد، يرجى استخدام talloc_unlink().

لمساعدتك في العثور على مشاكل في الكود الخاص بك ناتجة عن هذا السلوك، إذا حاولت تحرير مؤشر له أكثر من أب واحد، فسيتم استدعاء دالة تسجيل talloc لتقديم مخرجات مثل هذه:

    ERROR: talloc_free with references at some_dir/source/foo.c:123
	reference at some_dir/source/other.c:325
	reference at some_dir/source/third.c:121

يرجى الاطلاع على الوثائق الخاصة بـ talloc_set_log_fn() و talloc_set_log_stderr() لمزيد من المعلومات حول دوال تسجيل talloc.

void *talloc_reference(const void *ctx, const void *ptr);

الدالة talloc_reference() تجعل ctx أبًا إضافيًا لـ ptr.

قيمة الإرجاع للدالة talloc_reference() هي دائمًا المؤشر الأصلي ptr، إلا إذا نفدت ذاكرة talloc عند إنشاء المرجع، وفي هذه الحالة سترجع NULL (كل مرجع إضافي يستهلك حوالي 48 بايت من الذاكرة على منصات Intel x86).

إذا كان ptr هو NULL، فإن الدالة لا تقوم بأي شيء، وترجع NULL ببساطة.

بعد إنشاء مرجع، يمكنك تحريره بإحدى الطرق التالية:

•يمكنك استخدام talloc_free() لأي أب للمؤشر الأصلي. سيؤدي ذلك إلى تقليل عدد الآباء لهذا المؤشر بمقدار 1، وسيؤدي إلى تحرير هذا المؤشر إذا نفد منه الآباء.
•يمكنك استخدام talloc_free() للمؤشر نفسه إذا كان له أب واحد على الأكثر. تم تغيير هذا السلوك منذ إصدار 2.0. مزيد من المعلومات في وصف "talloc_free".

لمزيد من التحكم في أي أب يجب إزالته، انظر “talloc_unlink()”.

int talloc_unlink(const void *ctx, void *ptr);

الدالة talloc_unlink() تزيل أبًا محددًا من ptr. يجب أن يكون ctx المقدم إما سياقًا مستخدمًا في talloc_reference() مع هذا المؤشر، أو يجب أن يكون أبًا مباشرًا لـ ptr.

لاحظ أنه إذا تمت إزالة الأب بالفعل باستخدام talloc_free()، فإن هذه الدالة ستفشل وترجع -1. وبالمثل، إذا كان ptr هو NULL، فلن تقوم الدالة بأي تعديلات وترجع -1.

عادةً يمكنك فقط استخدام talloc_free() بدلاً من talloc_unlink()، ولكن في بعض الأحيان يكون من المفيد الحصول على تحكم إضافي في أي أب تتم إزالته.

void talloc_set_destructor(const void *ptr, int (*destructor)(void *));

تحدد الدالة talloc_set_destructor() جهاز التدمير للمؤشر ptr. جهاز التدمير هو دالة يتم استدعاؤها عندما يتم وشيكًا تحرير الذاكرة المستخدمة بواسطة المؤشر. يتلقى جهاز التدمير ptr كوسيط، ويجب أن يرجع 0 للنجاح و -1 للفشل.

يمكن لـ جهاز التدمير فعل أي شيء يريده، بما في ذلك تحرير قطع أخرى من الذاكرة. الاستخدام الشائع لأجهزة التدمير هو تنظيف موارد نظام التشغيل (مثل واصفات الملفات المفتوحة) الموجودة في الهيكل الذي يتم وضع جهاز التدمير عليه.

يمكنك وضع جهاز تدمير واحد فقط على مؤشر. إذا احتجت إلى أكثر من جهاز تدمير واحد، يمكنك إنشاء ابن بطول صفر للمؤشر ووضع جهاز تدمير إضافي عليه.

لإزالة جهاز تدمير، استدعِ talloc_set_destructor() باستخدام NULL لجهاز التدمير.

NAME

talloc - hierarchical memory allocator

SYNOPSIS

#include <talloc.h>

void *talloc_realloc_fn(const void *ctx, void *ptr, size_t size);

void *talloc_autofree_context(void);

void *talloc_check_name(const void *ptr, const char *name);

(type *)talloc_get_type(const void *ptr, type);

talloc_set_type(const void *ptr, type);

talloc_set_log_fn(void (*log_fn)(const char *message));

talloc_set_log_stderr(void);

DESCRIPTION

talloc is a general-purpose memory allocator that allows you to allocate memory that will be automatically freed. This is done by allocating objects within a hierarchy. When a parent object is freed, all its children are automatically freed. This is useful for complex data structures where you might otherwise have to traverse the structure manually to free all the memory.

The primary benefit of talloc is that it simplifies the memory management of complex data structures. Instead of manually tracking and freeing each piece of memory, you can rely on talloc's hierarchical freeing mechanism.

TALLOC API

void *talloc_realloc_fn(const void *ctx, void *ptr, size_t size);

This is a non-macro version of talloc_realloc(), which is useful as libraries sometimes want a realloc function pointer. A realloc(3) implementation encapsulates the functionality of malloc(3), free(3) and realloc(3) in one call, which is why it is useful to be able to pass around a single function pointer.

void *talloc_autofree_context(void);

This is a handy utility function that returns a talloc context which will be automatically freed on program exit. This can be used to reduce the noise in memory leak reports.

void *talloc_check_name(const void *ptr, const char *name);

This function checks if a pointer has the specified name. If it does then the pointer is returned. It it doesn't then NULL is returned.

(type *)talloc_get_type(const void *ptr, type);

This macro allows you to do type checking on talloc pointers. It is particularly useful for void* private pointers. It is equivalent to this:

(type *)talloc_check_name(ptr, #type)

talloc_set_type(const void *ptr, type);

This macro allows you to force the name of a pointer to be a particular type. This can be used in conjunction with talloc_get_type() to do type checking on void* pointers.

It is equivalent to this:

talloc_set_name_const(ptr, #type)

talloc_set_log_fn(void (*log_fn)(const char *message));

This function sets a logging function that talloc will use for warnings and errors. By default talloc will not print any warnings or errors.

talloc_set_log_stderr(void);

This sets the talloc log function to write log messages to stderr

PERFORMANCE

All the additional features of talloc(3) over malloc(3) do come at a price. We have a performance test in Samba that measures talloc() versus malloc() performance, and it seems that talloc() is about 50% slower than malloc() (AMD Ryzen 9 3900X). For Samba, the great reduction in code complexity that we get by using talloc makes this worthwhile, especially as the total overhead of talloc/malloc in Samba is already quite small.
