table-mysql(5)

TABLE_MYSQL(5) دليل تنسيق الملفات TABLE_MYSQL(5)

الاسم

table_mysql — وصف تنسيق جداول MySQL أو MariaDB

الوصف

توثق صفحة الدليل هذه تنسيق جداول MySQL أو MariaDB التي يستخدمها daemon البريد smtpd(8).

ينطبق التنسيق الموصوف هنا على الجداول كما هو محدد في smtpd.conf(5).

جدول MySQL

يسمح جدول MySQL بتخزين أسماء المستخدمين وكلمات المرور والأسماء المستعارة والنطاقات في تنسيق يمكن مشاركته عبر أجهزة مختلفة تدعم mysql(1).

يستخدم الجدول بواسطة smtpd(8) عند المصادقة على مستخدم، عندما تكون معلومات المستخدم مثل معرف المستخدم و/أو الدليل الرئيسي مطلوبة للتسليم، عندما قد يكون البحث عن نطاق مطلوبًا، و/أو عند البحث عن اسم مستعار.

يتكون جدول MySQL من قاعدة بيانات mysql(1) واحدة أو أكثر مع جدول واحد أو أكثر.

إذا تم استخدام الجدول للمصادقة، فيجب تشفير كلمة المرور باستخدام الدالة crypt(3). يمكن إنشاء كلمات المرور هذه باستخدام الأداة المساعدة encrypt(1) أو أمر smtpctl(8) encrypt.

ملف تكوين جدول MySQL

خيارات التكوين التالية متاحة:

host hostname
هذا هو الخادم الذي يعمل عليه MySQL أو MariaDB. على سبيل المثال: 
host db.example.com
username username
اسم المستخدم المطلوب للتواصل مع قاعدة بيانات MySQL أو MariaDB. على سبيل المثال: 
username maildba
password password
كلمة المرور المطلوبة للتواصل مع قاعدة بيانات MySQL أو MariaDB. على سبيل المثال: 
password OpenSMTPDRules!
database databse
اسم قاعدة بيانات MySQL أو MariaDB. على سبيل المثال: 
databse opensmtpdb
query_alias SQL statement
يستخدم هذا لتوفير استعلام للبحث عن الأسماء المستعارة. يتم استبدال علامة الاستفهام بالبيانات المناسبة. بالنسبة للأسماء المستعارة، يكون هذا هو الجانب الأيسر من عنوان SMTP. يتوقع أن يتم إرجاع VARCHAR واحد مع اسم المستخدم الذي يؤول إليه الاسم المستعار.
query_credentials SQL statement
يستخدم هذا لتوفير استعلام للبحث عن بيانات اعتماد المستخدم. يتم استبدال علامة الاستفهام بالبيانات المناسبة. بالنسبة لبيانات الاعتماد، يكون هذا هو الجانب الأيسر من عنوان SMTP. يتوقع الاستعلام أن يتم إرجاع VARCHARs، أحدهما يحتوي على اسم مستخدم والآخر يحتوي على كلمة مرور بتنسيق crypt(3).
query_domain SQL statement
يستخدم هذا لتوفير استعلام للبحث عن نطاق. يتم استبدال علامة الاستفهام بالبيانات المناسبة. بالنسبة للنطاق، سيكون هذا هو الجانب الأيمن من عنوان SMTP. يتوقع أن يتم إرجاع VARCHAR واحد مع اسم نطاق مطابق.
query_mailaddrmap SQL statement
يستخدم هذا لتوفير استعلام للبحث عن المرسلين. يتم استبدال علامة الاستفهام بالبيانات المناسبة. يتوقع أن يتم إرجاع VARCHAR واحد مع العنوان المسموح للمرسل بإرسال رسائل منه.

بيان SQL عام سيكون شيئًا مثل:

query_ SELECT value FROM table WHERE key=?;

أمثلة

مثال عام

مثال مستوحى من الأسئلة الشائعة لـ OpenSMTPD: بناء خادم بريد. يتم استبعاد جزء التصفية في هذا المثال.

التكوين أدناه هو لخادم بريد متوسط الحجم يتعامل مع نطاقات متعددة مع مستخدمين افتراضيين متعددين ويستند إلى عدة افتراضات. أحدها هو أنه يتم استخدام مستخدم نظام واحد يسمى vmail لجميع المستخدمين الافتراضيين. يجب إنشاء هذا المستخدم:

# useradd -g =uid -c "Virtual Mail" -d /var/vmail -s /sbin/nologin vmail
# mkdir /var/vmail
# chown vmail:vmail /var/vmail

مخطط MySQL

CREATE TABLE domains (
  id INT NOT NULL AUTO_INCREMENT PRIMARY KEY,
  domain VARCHAR(255) NOT NULL DEFAULT ''
);
CREATE TABLE virtuals (
    id INT AUTO_INCREMENT PRIMARY KEY,
    email VARCHAR(255) NOT NULL DEFAULT '',
    destination VARCHAR(255) NOT NULL DEFAULT ''
);
CREATE TABLE credentials (
    id INT AUTO_INCREMENT PRIMARY KEY,
    email VARCHAR(255) NOT NULL DEFAULT '',
    password VARCHAR(255) NOT NULL DEFAULT ''
);
INSERT INTO domains VALUES (1, "example.com");
INSERT INTO domains VALUES (2, "example.net");
INSERT INTO domains VALUES (3, "example.org");

INSERT INTO virtuals VALUES (1, "abuse@example.com", "bob@example.com");
INSERT INTO virtuals VALUES (2, "postmaster@example.com", "bob@example.com");
INSERT INTO virtuals VALUES (3, "webmaster@example.com", "bob@example.com");
INSERT INTO virtuals VALUES (4, "bob@example.com", "vmail");
INSERT INTO virtuals VALUES (5, "abuse@example.net", "alice@example.net");
INSERT INTO virtuals VALUES (6, "postmaster@example.net", "alice@example.net");
INSERT INTO virtuals VALUES (7, "webmaster@example.net", "alice@example.net");
INSERT INTO virtuals VALUES (8, "alice@example.net", "vmail");

INSERT INTO credentials VALUES (1, "bob@example.com", "$2b$08$ANGFKBL.BnDLL0bUl7I6aumTCLRJSQluSQLuueWRG.xceworWrUIu");
INSERT INTO credentials VALUES (2, "alice@example.net", "$2b$08$AkHdB37kaj2NEoTcISHSYOCEBA5vyW1RcD8H1HG.XX0P/G1KIYwii");

/etc/mail/mysql.conf

host db.example.com
username maildba
password OpenSMTPDRules!
database opensmtpdb
query_alias SELECT destination FROM virtuals WHERE email=?;
query_credentials SELECT email, password FROM credentials WHERE email=?;
query_domain SELECT domain FROM domains WHERE domain=?;

/etc/mail/smtpd.conf

table domains mysql:/etc/mail/mysql.conf
table virtuals mysql:/etc/mail/mysql.conf
table credentials mysql:/etc/mail/mysql.conf
listen on egress port 25 tls pki mail.example.com
listen on egress port 587 tls-require pki mail.example.com auth <credentials>
accept from any for domain <domains> virtual <virtuals> deliver to mbox

\n                
NAME
\n                
table-mysql \u2013 OpenSMTPD mysql table
\n            
\n            
\n                
DESCRIPTION
\n                
The mysql table delivery agent is \n                    used in smtpd.conf(5) \n                    to perform lookups in a remote MySQL database.
\n                
It allows OpenSMTPD to query a MySQL database for information \n                    such as recipient addresses, aliases, or anything else that might be \n                    useful for mail routing or filtering.
\n            
\n            
\n                
MYSQL TABLE
\n                
The mysql table is configured \n                    within the smtpd.conf file.
\n                
A typical configuration line looks like:
\n                
table mysql \"mysql:host=localhost;dbname=opensmtpd;option=value;...\"\n
\n                
The string following mysql: \n                    is a database connection string composed of key-value pairs separated \n                    by semicolons.
\n                
Supported keys include:
\n                
\n                    
host
\n                    
The hostname or IP address of the MySQL server.
\n                    
port
\n                    
The port number of the MySQL server (default is 3306).
\n                    
dbname
\n                    
The name of the database to connect to.
\n                    
user
\n                    
The username for authentication.
\n                    
password
\n                    
The password for authentication.
\n                    
option
\n                    
MySQL client options. See mysql_options(3) for a list of valid options.
\n                
\n            
\n            
\n                
MYSQL TABLE CONFIG FILE
\n                
Instead of providing the connection string directly in \n                    smtpd.conf, it is possible to specify a \n                    configuration file. This is done by prefixing the connection string \n                    with file:.
\n                
table mysql \"mysql:file:/path/to/mysql.conf\"\n
\n                
The configuration file should contain the connection parameters \n                    in the same key-value format as the connection string, with each parameter \n                    on a new line.
\n                
# /path/to/mysql.conf\nhost=localhost\nport=3306\ndbname=opensmtpd\nuser=user\npassword=password\n
\n            
\n            
\n                
EXAMPLES
\n                
The following example shows how to use the mysql \n                    table to resolve mail aliases:
\n                
table mysql \"mysql:host=db.example.com;dbname=mail;user=opensmtpd;password=secret\"\n\ncredentials db.example.com \"opensmtpd:secret\"\n\nlisten on smtpd\n    match for local alias  rcpt-to && deliver to maildir\n
\n                
In this example, the mysql table \n                    is configured to connect to the MySQL server at db.example.com. \n                    The credentials directive is used to provide \n                    the authentication details separately, which is generally recommended \n                    for security reasons. The match rule then uses \n                    this table to check if a recipient address is an alias in the \n                    MySQL database. If it is, the email is delivered to the user's \n                    maildir.
\n                
The query executed against the MySQL database will depend \n                    on the context in which the table is used. For example, when used \n                    for recipient verification, the query might look like:
\n                
SELECT destination FROM aliases WHERE source = ?\n
\n                
Where ? is a placeholder for \n                    the recipient address being checked. The table will automatically \n                    construct the appropriate SQL query based on the context. The following \n                    predefined keys can be used in your SQL query:\n                    query_source, query_mailaddr, \n                    query_addrname.
\n
