tabs(1) أوامر المستخدم tabs(1)

الاسم

tabs - تعيين مواضع علامات الجدولة في الطرفية

الملخص

tabs [خيارات] [قائمة مواضع علامات الجدولة]

الوصف

يقوم برنامج tabs بمسح وتعيين مواضع علامات الجدولة في الطرفية. يستخدم هذا القدرات clear_all_tabs و set_tab من terminfo. إذا كان أي منهما غير موجود، فلن يتمكن tabs من مسح/تعيين علامات الجدولة. يجب تكوين الطرفية لاستخدام علامات الجدولة الصلبة، على سبيل المثال:

stty tab0

مثل clear(1)، يكتب tabs إلى المخرج القياسي. يمكنك إعادة توجيه المخرج القياسي إلى ملف (مما يمنع tabs من تغيير مواضع علامات الجدولة فعليًا)، وفي وقت لاحق يمكنك استخدام cat للملف لعرضه على الشاشة، مما يؤدي إلى تعيين علامات الجدولة في تلك اللحظة.

هذه علامات جدولة بالأجهزة، لا يمكن للتطبيقات التي تعمل في الطرفية الاستعلام عنها بسرعة، إن كان ذلك ممكنًا على الإطلاق. قد تستخدم Curses والتطبيقات الأخرى كاملة الشاشة علامات الجدولة بالأجهزة في تحسين مخرجاتها إلى الطرفية. إذا اختلفت علامات الجدولة بالأجهزة عن المعلومات الموجودة في قاعدة بيانات الطرفية، تكون النتيجة غير متوقعة. قبل تشغيل برامج Curses، يجب إما إعادة تعيين علامات الجدولة إلى الفاصل القياسي

tabs -8

أو استخدام برنامج reset، حيث أن تسلسلات التهيئة العادية لا تضمن إعادة تعيين علامات الجدولة.

الخيارات

خيارات عامة

-Tاسم
تخبر tabs بنوع الطرفية المراد استخدامه. إذا لم يتم تقديم هذا الخيار، سيستخدم tabs متغير البيئة $TERM. إذا لم يتم تعيينه، فسيستخدم الإدخال ansi+tabs.
-d
يُظهر خيار التصحيح خط مسطرة، متبوعًا بسطرين من البيانات. يُظهر السطر الأول من البيانات مواضع علامات الجدولة المتوقعة معلمة بعلامات النجمة. يُظهر السطر الثاني من البيانات مواضع علامات الجدولة الفعلية، معلمة بعلامات النجمة.
-n
يخبر هذا الخيار tabs بفحص الخيارات وتشغيل أي خيار تصحيح، ولكن دون تعديل إعدادات الطرفية.
-V
يبلغ عن إصدار ncurses الذي تم استخدامه في هذا البرنامج، ثم يخرج.

يعالج برنامج tabs قائمة واحدة لمواضع علامات الجدولة. آخر خيار تم معالجته والذي يحدد قائمة هو الذي يحدد القائمة المراد معالجتها.

قوائم ضمنية

استخدم رقمًا واحدًا كخيار، على سبيل المثال، "-5" لتعيين علامات الجدولة بفاصل زمني معين (في هذه الحالة 1، 6، 11، 16، 21، إلخ). تتكرر علامات الجدولة حتى الهامش الأيمن للشاشة.

استخدم "-0" لمسح جميع علامات الجدولة.

استخدم "-8" لتعيين علامات الجدولة إلى الفاصل القياسي.

قوائم صريحة

يمكن تحديد قائمة صريحة بعد الخيارات (لا تستخدم "-"). يجب أن تكون القيم في القائمة بترتيب رقمي متزايد، وأن تكون أكبر من الصفر. يتم فصلها بفاصلة أو مسافة، على سبيل المثال:

tabs 1,6,11,16,21
tabs 1 6 11 16 21

استخدم "+" لمعاملة الرقم كزيادة بالنسبة للقيمة السابقة، على سبيل المثال:

tabs 1,+5,+5,+5,+5

وهو ما يعادل مثال 1,6,11,16,21.

الهوامش

تكشف بعض الطرفيات عن وسيلة لتغيير هوامشها اليسرى واليمنى. tabs تدعم هذه الميزة بخيار.

+m هامش
يعتمد التأثير على ما إذا كانت الطرفية توفر إمكانيات الهامش:
  • إذا كانت الطرفية توفر القدرة على تعيين الهامش الأيسر، فسيستخدم tabs ذلك، ويعدل عروض مواضع علامات الجدولة المتاحة.
  • إذا كانت الطرفية لا توفر إمكانيات الهامش، فإن tabs يحاكي تأثيرها، واضعًا علامات جدولة في أماكن مناسبة في كل سطر. لا يتم تعديل الهامش الأيسر لل طرفية.
إذا تم حذف معامل margin، يكون الافتراضي هو 10. استخدم +m0 لإعادة تعيين الهامش الأيسر، أي جعله الحافة اليسرى لشاشة الطرفية. قبل تعيين هامش أيسر، يقوم tabs بإعادة تعيين الهامش لتقليل المشكلات التي قد تنشأ عن نقل المؤشر إلى يسار الهامش الأيسر الحالي.

عند تعيين أو إعادة تعيين الهامش الأيسر، قد يقوم tabs أيضًا بإعادة تعيين الهامش الأيمن.

/usr/share/tabset
قاعدة بيانات تهيئة مواضع علامات الجدولة

قابلية النقل

يصف IEEE Std 1003.1/The Open Group Base Specifications Issue 7 (POSIX.1-2008) أداة tabs. ومع ذلك،

  • يصف هذا المعيار خيار +m لتعيين هامش الطرفية الأيسر. عدد قليل جدًا من الإدخالات في قاعدة بيانات الطرفية توفر قدرات set_left_margin (smgl) أو set_left_margin_parm (smglp) اللازمة لدعم هذه الميزة.
  • لا يوجد مقابل في X/Open Curses Issue 7 لهذه الأداة، على عكس tput(1).

خيارات -d (تصحيح) و -n (لا إجراء) هي امتدادات ncurses لا توفرها التطبيقات الأخرى.

التاريخ

ظهرت أداة tabs في PWB/Unix 1.0 (1977). تم شحن نسخة مخفضة في Seventh Edition Unix (أوائل 1979) وفي 3BSD (لاحقًا في نفس العام)؛ دعمت خيار "-n" لتعيين علامة الجدولة الأولى عند الهامش الأيسر. هذا الخيار غير محدد بواسطة POSIX.

عادت أداة tabs الخاصة بـ PWB/Unix في System III (1980)، واستخدمت جداول مدمجة لدعم نصف دزينة من أنواع الطرفيات (الطابعات) ذات الخطوط الثابتة. كانت لديها أيضًا منطق لدعم تعيين الهامش الأيسر، بالإضافة إلى ميزة لنسخ إعدادات علامات الجدولة من ملف.

أضافت إصدارات البرنامج في الإصدارات اللاحقة من AT&T Unix، مثل SVr4، دعمًا لقاعدة بيانات الطرفية، ولكنها احتفظت بالجداول لدعم الطابعات. بحلول هذا الوقت، قام tput الخاص بـ System V بدمج ميزة تهيئة مواضع علامات الجدولة الخاصة بـ tset الخاصة بـ BSD من عام 1982، ولكنه استخدم قاعدة بيانات terminfo للقيام بذلك.

تم توثيق خيار +m في POSIX Base Specifications Issue 5 (Unix98، 1997)، ثم تم حذفه في Issue 6 (Unix03، 2004) دون دافع صريح، على الرغم من أن تعليقًا تمهيديًا "ويعدل الهامش اختياريًا" لا يزال موجودًا، وقد تم تجاهله في عملية الحذف. يختلف خيار +m في tabs الخاص بـ ncurses عن ميزة SVr4 باستخدامه لقدرات الطرفية بدلاً من

PORTABILITY

This utility is the POSIX standard utility.

HISTORY

A tabs command was first provided by AT&T Unix. It was improved in later versions of AT&T Unix.

The POSIX standard for tabs (IEEE Std 1002.1-2001) specifies that the utility should be able to set arbitrary tab stops. This is done by passing a list of tab-stop columns to the utility. If no list is given, it defaults to the standard 8-column tab stops.

The POSIX standard for tabs does not specify the order of tab stops in the list. However, the implementation in ncurses requires them to be in increasing order. If they are not, the behavior is undefined.

The POSIX standard for tabs does not specify any constraints on the number of tab stops that can be set. However, some implementations may impose limits. For example, PWB/Unix's tabs utility imposes a limit of 20 tab stops. The ncurses implementation attempts to set tab stops up to the right margin if the list thereof is sufficiently long, although some terminals may not support an arbitrary number of tab stops.

The POSIX Issue 6 documentation for tabs mentions that the committee considered redesigning the tabs and tput utilities but did not settle on an improved solution. It also claims that "no known historical version of tabs supports the capability of setting arbitrary tab stops." This statement is contradicted by the implementation of the feature in PWB/Unix, which permitted the setting of arbitrary tab stops.

The ncurses implementation of tabs conforms to the POSIX standard. It supports setting arbitrary tab stops by allowing a list of tab-stop columns to be passed as an argument. If no list is provided, it defaults to the standard 8-column tab stops. The implementation also attempts to set tab stops up to the right margin if the list is long enough, though terminal limitations may apply.

The POSIX standard specifies that the default behavior for tab stops is every 8 columns. This implementation adheres to that default when no explicit list of tab stops is provided.

The POSIX standard does not specify the behavior when the list of tab stops is not in increasing order. This implementation requires the tab stops to be in increasing order. Providing a list that is not sorted may lead to undefined behavior.

The POSIX standard does not impose a limit on the number of tab stops that can be set. This implementation attempts to set as many tab stops as requested, up to the terminal's right margin. However, actual terminal capabilities may limit the number of tab stops that can be effectively set.

The POSIX standard documentation notes that historical versions of tabs did not support arbitrary tab stops. However, PWB/Unix's implementation did provide this functionality, demonstrating that it was possible even before the POSIX standard formalized it.
