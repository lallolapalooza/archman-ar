DESCRIPTION

These macros define and operate on four types of data structures that can be used in both C and C++.

  1. List
  2. Doubly linked list
  3. Doubly linked tail queue
  4. Tail queue
All four structures support the following functionality:
  1. Insertion of a new element at the beginning of the list.
  2. Insertion of a new element after any element in the list.
  3. Removal of an element at the beginning of the list in O(1).
  4. Forward traversal of the list.
  5. Swapping the contents of two lists.

Doubly linked lists are the simplest of the four data structures and support only the functionality above. Doubly linked lists are ideal for applications with large datasets and few or no removals, or for implementing a LIFO stack. Doubly linked lists add the following functionality:

  1. Removal of any element in the list in O(n).
  2. Concatenation of two lists in O(n).

Doubly linked tail queues add the following functionality:

  1. Insertion of a new element at the end of a list.
  2. Removal of any element in the list in O(n).
  3. They can be concatenated.

However:

  1. All insertions into the lists must specify the list head.
  2. Each head entry requires two pointers instead of one.
  3. The code size is approximately 15% larger and operations execute approximately 20% slower than doubly linked lists.

Doubly linked tail queues are ideal for applications with large datasets and few or no removals, or for implementing a FIFO queue.

All doubly linked data structures (lists and tail queues) also permit:

  1. Insertion of a new element before any element in the list.
  2. Removal of any element in the list in O(1).

However:

  1. Each element requires two pointers instead of one.
  2. The code size and the execution time of operations (except for removal) is approximately double that of singly linked data structures.

Doubly linked lists are the simplest of the doubly linked data structures. They add the following functionality over the preceding ones:

  1. Concatenation of two lists in O(n).
  2. They can be traversed in reverse.

However:

  1. To traverse in reverse, a starting element and the list it belongs to must be specified.

Tail queues add the following functionality:

  1. Insertion of an element at the end of a list.
  2. They can be traversed in reverse, from tail to head.
  3. They can be concatenated.

However:

  1. All insertions and removals in the lists must specify the list head.
  2. Each head entry requires two pointers instead of one.
  3. The code size is approximately 15% larger and operations execute approximately 20% slower than doubly linked lists.

In the macro definitions, TYPE is the name of a user-defined structure. The structure must contain a field named NAME of type SLIST_ENTRY, STAILQ_ENTRY, LIST_ENTRY, or TAILQ_ENTRY. In the macro definitions, CLASSTYPE is the name of a user-defined class. The class must contain a field named NAME of type SLIST_CLASS_ENTRY, STAILQ_CLASS_ENTRY, LIST_CLASS_ENTRY, or TAILQ_CLASS_ENTRY. The HEADNAME argument is the name of a user-defined structure that must be declared using the SLIST_HEAD, SLIST_CLASS_HEAD, STAILQ_HEAD, STAILQ_CLASS_HEAD, LIST_HEAD, LIST_CLASS_HEAD, TAILQ_HEAD, or TAILQ_CLASS_HEAD macros. See the examples below for a more detailed explanation of how these macros are used.

SINGLY-LINKED LISTS

A singly linked list is headed by a structure defined by the SLIST_HEAD macro. This structure contains a single pointer to the first element in the list. The elements are singly linked to minimize space and pointer manipulation overhead, even though access to arbitrary elements has O(n) time. New elements can be added to the list either after an existing element or at the beginning of the list. An SLIST_HEAD structure is declared as follows:

SLIST_HEAD(HEADNAME, TYPE) head;

where HEADNAME is the name of the structure to be defined and TYPE is the type of the elements to be linked into the list. A pointer to the list head can then be declared as follows:

struct HEADNAME *headp;

(The names head and headp are user-selectable.)

The SLIST_HEAD_INITIALIZER macro evaluates to an initializer for the head list.

The SLIST_CONCAT macro will concatenate the list headed by head2 to the end of the list headed by head1, emptying the former. Use of this macro should be avoided, as it completely traverses the head1 list. A doubly linked tail queue should be used if this macro is needed in high-usage code paths or to operate on long lists.

The SLIST_EMPTY macro evaluates to true if there are no elements in the list.

The SLIST_ENTRY macro declares a structure that links the list elements.

The SLIST_FIRST macro returns the first element in the list, or NULL if the list is empty.

The SLIST_FOREACH macro traverses the list referred to by head in the forward direction, assigning each element in order to var.

The SLIST_FOREACH_FROM macro behaves similarly to SLIST_FOREACH when var is NULL, otherwise it treats var as a previously found element in an SLIST list and starts the loop from var instead of the first element in the list referred to by head.

The SLIST_FOREACH_SAFE macro traverses the list referred to by head in the forward direction, assigning each element in order to var. However, unlike SLIST_FOREACH(), here it is permitted to both delete var and safely free it from within the loop without interfering with the traversal.

The SLIST_FOREACH_FROM_SAFE macro behaves similarly to SLIST_FOREACH_SAFE when var is NULL, otherwise it treats var as a previously found element in an SLIST list and starts the loop from var instead of the first element in the list referred to by head.

The SLIST_INIT macro initializes the list referred to by head.

The SLIST_INSERT_HEAD macro inserts the new element elm at the beginning of the list.

The SLIST_INSERT_AFTER macro inserts the new element elm after the element

طوابير الذيل المرتبطة أحادية الاتجاه

طابور الذيل المرتبط أحادي الاتجاه يتم رأسه بهيكل يتم تعريفه بواسطة الماكرو STAILQ_HEAD. يحتوي هذا الهيكل على زوج من المؤشرات، أحدهما يشير إلى العنصر الأول في طابور الذيل والآخر إلى العنصر الأخير في طابور الذيل. العناصر مرتبطة أحادية الاتجاه لتقليل استهلاك المساحة والتعامل مع المؤشرات على حساب تعقيد زمني O(n) للحذف العشوائي للعناصر. يمكن إضافة عناصر جديدة إلى طابور الذيل بعد عنصر موجود، أو في رأس طابور الذيل، أو في نهاية طابور الذيل. يتم تعريف هيكل STAILQ_HEAD على النحو التالي:

STAILQ_HEAD(HEADNAME, TYPE) head;

حيث HEADNAME هو اسم الهيكل الذي سيتم تعريفه، و TYPE هو نوع العناصر التي سيتم ربطها في طابور الذيل. يمكن لاحقًا تعريف مؤشر إلى رأس طابور الذيل على النحو التالي:

struct HEADNAME *headp;

(الأسماء head و headp قابلة للاختيار من قبل المستخدم.)

الماكرو STAILQ_HEAD_INITIALIZER يعطي قيمة أولية لرأس طابور الذيل head.

الماكرو STAILQ_CONCAT يربط طابور الذيل الذي رأسه head2 بنهاية طابور الذيل الذي رأسه head1، مما يؤدي إلى إزالة جميع الإدخالات من الأول.

الماكرو STAILQ_EMPTY يعطي قيمة صحيحة إذا لم تكن هناك عناصر في طابور الذيل.

الماكرو STAILQ_ENTRY يعرّف هيكلًا يربط العناصر في طابور الذيل.

الماكرو STAILQ_FIRST يعيد العنصر الأول في طابور الذيل أو NULL إذا كان طابور الذيل فارغًا.

الماكرو STAILQ_FOREACH يجتاز طابور الذيل المشار إليه بواسطة head في الاتجاه الأمامي، ويعين كل عنصر بالتتابع إلى var.

الماكرو STAILQ_FOREACH_FROM يتصرف بشكل متطابق مع STAILQ_FOREACH عندما يكون var هو NULL، وإلا فإنه يعامل var كعنصر STAILQ تم العثور عليه سابقًا ويبدأ الحلقة عند var بدلاً من العنصر الأول في STAILQ المشار إليه بواسطة head.

الماكرو STAILQ_FOREACH_SAFE يجتاز طابور الذيل المشار إليه بواسطة head في الاتجاه الأمامي، ويعين كل عنصر بالتتابع إلى var. ومع ذلك، على عكس STAILQ_FOREACH()، يُسمح هنا بإزالة var وكذلك تحريره من داخل الحلقة بأمان دون التدخل في الاجتياز.

الماكرو STAILQ_FOREACH_FROM_SAFE يتصرف بشكل متطابق مع STAILQ_FOREACH_SAFE عندما يكون var هو NULL، وإلا فإنه يعامل var كعنصر STAILQ تم العثور عليه سابقًا ويبدأ الحلقة عند var بدلاً من العنصر الأول في STAILQ المشار إليه بواسطة head.

الماكرو STAILQ_INIT يهيئ طابور الذيل المشار إليه بواسطة head.

الماكرو STAILQ_INSERT_HEAD يدرج العنصر الجديد elm في رأس طابور الذيل.

الماكرو STAILQ_INSERT_TAIL يدرج العنصر الجديد elm في نهاية طابور الذيل.

الماكرو STAILQ_INSERT_AFTER يدرج العنصر الجديد elm بعد العنصر listelm.

الماكرو STAILQ_LAST يعيد العنصر الأخير في طابور الذيل. إذا كان طابور الذيل فارغًا، فإن القيمة المعادة هي NULL.

الماكرو STAILQ_NEXT يعيد العنصر التالي في طابور الذيل، أو NULL إذا كان هذا العنصر هو الأخير.

الماكرو STAILQ_REMOVE_AFTER يزيل العنصر الذي يلي elm من طابور الذيل. على عكس STAILQ_REMOVE، لا يجتاز هذا الماكرو طابور الذيل بأكمله.

الماكرو STAILQ_REMOVE_HEAD يزيل العنصر الموجود في رأس طابور الذيل. لتحقيق أقصى قدر من الكفاءة، يجب على العناصر التي يتم إزالتها من رأس طابور الذيل استخدام هذا الماكرو بشكل صريح بدلاً من الماكرو العام STAILQ_REMOVE.

الماكرو STAILQ_REMOVE يزيل العنصر elm من طابور الذيل. يجب تجنب استخدام هذا الماكرو لأنه يجتاز القائمة بأكملها. يجب استخدام طابور ذيل مزدوج الارتباط إذا كان هذا الماكرو مطلوبًا في مسارات التعليمات البرمجية ذات الاستخدام العالي أو للعمل على طوابير ذيل طويلة.

الماكرو STAILQ_SWAP يتبادل محتويات head1 و head2.

مثال على طابور الذيل المرتبط أحادي الاتجاه

STAILQ_HEAD(stailhead, entry) head =
    STAILQ_HEAD_INITIALIZER(head);
struct stailhead *headp;		/* رأس طابور الذيل المرتبط أحادي الاتجاه. */
struct entry {
	...
	STAILQ_ENTRY(entry) entries;	/* طابور الذيل. */
	...
} *n1, *n2, *n3, *np;

STAILQ_INIT(&head);			/* تهيئة الطابور. */

n1 = malloc(sizeof(struct entry));	/* إدراج في الرأس. */
STAILQ_INSERT_HEAD(&head, n1, entries);

n1 = malloc(sizeof(struct entry));	/* إدراج في الذيل. */
STAILQ_INSERT_TAIL(&head, n1, entries);

n2 = malloc(sizeof(struct entry));	/* إدراج بعد. */
STAILQ_INSERT_AFTER(&head, n1, n2, entries);
					/* حذف. */
STAILQ_REMOVE(&head, n2, entry, entries);
free(n2);
					/* حذف من الرأس. */
n3 = STAILQ_FIRST(&head);
STAILQ_REMOVE_HEAD(&head, entries);
free(n3);
					/* اجتياز أمامي. */
STAILQ_FOREACH(np, &head, entries)
	np-> ...
					/* اجتياز أمامي آمن. */
STAILQ_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	STAILQ_REMOVE(&head, np, entry, entries);
	free(np);
}
					/* حذف طابور الذيل. */
while (!STAILQ_EMPTY(&head)) {
	n1 = STAILQ_FIRST(&head);
	STAILQ_REMOVE_HEAD(&head, entries);
	free(n1);
}
					/* حذف أسرع لطابور الذيل. */
n1 = STAILQ_FIRST(&head);
while (n1 != NULL) {
	n2 = STAILQ_NEXT(n1, entries);
	free(n1);
	n1 = n2;
}
STAILQ_INIT(&head);

القوائم

تُصاغ القائمة بهيكل يتم تعريفه بواسطة الماكرو LIST_HEAD. يحتوي هذا الهيكل على مؤشر واحد إلى العنصر الأول في القائمة. العناصر مرتبطة بشكل مزدوج بحيث يمكن إزالة عنصر عشوائي دون اجتياز القائمة. يمكن إضافة عناصر جديدة إلى القائمة بعد عنصر موجود، أو قبل عنصر موجود، أو في رأس القائمة. يتم تعريف هيكل LIST_HEAD على النحو التالي:

LIST_HEAD(HEADNAME, TYPE) head;

حيث HEADNAME هو اسم الهيكل الذي سيتم تعريفه، و TYPE هو نوع العناصر التي سيتم ربطها في القائمة. يمكن لاحقًا تعريف مؤشر إلى رأس القائمة على النحو التالي:

struct HEADNAME *headp;

(الأسماء head و headp قابلة للاختيار من قبل المستخدم.)

الماكرو LIST_HEAD_INITIALIZER يعطي قيمة أولية لرأس القائمة head.

الماكرو LIST_CONCAT يربط القائمة التي رأسه head2 بنهاية القائمة التي رأسه head1، مما يؤدي إلى إزالة جميع الإدخالات من الأولى. يجب تجنب استخدام هذا الماكرو لأنه يجتاز القائمة head1 بأكملها. يجب استخدام طابور الذيل إذا كان هذا الماكرو مطلوبًا في مسارات التعليمات البرمجية ذات الاستخدام العالي أو للعمل على قوائم طويلة.

الماكرو LIST_EMPTY يعطي قيمة صحيحة إذا لم تكن هناك عناصر في القائمة.

الماكرو LIST_ENTRY يعرّف هيكلًا يربط العناصر في القائمة.

الماكرو LIST_FIRST يعيد العنصر الأول في القائمة أو NULL إذا كانت القائمة فارغة.

الماكرو LIST_FOREACH يجتاز القائمة المشار إليها بواسطة head في الاتجاه الأمامي، ويعين كل عنصر بالتتابع إلى var.

الماكرو LIST_FOREACH_SAFE يجتاز القائمة المشار إليها بواسطة head في الاتجاه الأمامي، ويعين كل عنصر بالتتابع إلى var. ومع ذلك، على عكس LIST_FOREACH()، يُسمح هنا بإزالة var وكذلك تحريره من داخل الحلقة بأمان دون التدخل في الاجتياز.

الماكرو LIST_FOREACH_FROM يتصرف بشكل متطابق مع LIST_FOREACH عندما يكون var هو NULL، وإلا فإنه يعامل var كعنصر قائمة تم العثور عليه سابقًا ويبدأ الحلقة عند var بدلاً من العنصر الأول في القائمة المشار إليها بواسطة head.

في الاتجاه الأمامي، مع تعيين كل عنصر بدوره إلى var.

الماكرو LIST_FOREACH_FROM يتصرف بشكل مطابق لـ LIST_FOREACH عندما يكون var هو NULL، وإلا فإنه يعامل var كعنصر قائمة تم العثور عليه مسبقًا ويبدأ الحلقة عند var بدلاً من العنصر الأول في القائمة المشار إليها بواسطة head.

يتنقل الماكرو LIST_FOREACH_SAFE في القائمة المشار إليها بواسطة head في الاتجاه الأمامي، مع تعيين كل عنصر بدوره إلى var. ومع ذلك، على عكس LIST_FOREACH() هنا يُسمح بإزالة var وكذلك تحريره من داخل الحلقة بأمان دون التدخل في الاجتياز.

الماكرو LIST_FOREACH_FROM_SAFE يتصرف بشكل مطابق لـ LIST_FOREACH_SAFE عندما يكون var هو NULL، وإلا فإنه يعامل var كعنصر قائمة تم العثور عليه مسبقًا ويبدأ الحلقة عند var بدلاً من العنصر الأول في القائمة المشار إليها بواسطة head.

الماكرو LIST_INIT يقوم بتهيئة القائمة المشار إليها بواسطة head.

الماكرو LIST_INSERT_HEAD يدرج العنصر الجديد elm في رأس القائمة.

الماكرو LIST_INSERT_AFTER يدرج العنصر الجديد elm بعد العنصر listelm.

الماكرو LIST_INSERT_BEFORE يدرج العنصر الجديد elm قبل العنصر listelm.

الماكرو LIST_NEXT يعيد العنصر التالي في القائمة، أو NULL إذا كان هذا هو الأخير.

الماكرو LIST_PREV يعيد العنصر السابق في القائمة، أو NULL إذا كان هذا هو الأول. يجب أن تحتوي قائمة head على العنصر elm.

الماكرو LIST_REMOVE يزيل العنصر elm من القائمة.

الماكرو LIST_SWAP يبادل محتويات head1 و head2.

مثال على القائمة (LIST EXAMPLE)

LIST_HEAD(listhead, entry) head =
    LIST_HEAD_INITIALIZER(head);
struct listhead *headp;			/* رأس القائمة. */
struct entry {
	...
	LIST_ENTRY(entry) entries;	/* القائمة. */
	...
} *n1, *n2, *n3, *np, *np_temp;

LIST_INIT(&head);			/* تهيئة القائمة. */

n1 = malloc(sizeof(struct entry));	/* الإدراج في الرأس. */
LIST_INSERT_HEAD(&head, n1, entries);

n2 = malloc(sizeof(struct entry));	/* الإدراج بعد. */
LIST_INSERT_AFTER(n1, n2, entries);

n3 = malloc(sizeof(struct entry));	/* الإدراج قبل. */
LIST_INSERT_BEFORE(n2, n3, entries);

LIST_REMOVE(n2, entries);		/* الحذف. */
free(n2);
					/* الاجتياز الأمامي. */
LIST_FOREACH(np, &head, entries)
	np-> ...

					/* الاجتياز الأمامي الآمن. */
LIST_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	LIST_REMOVE(np, entries);
	free(np);
}

while (!LIST_EMPTY(&head)) {		/* حذف القائمة. */
	n1 = LIST_FIRST(&head);
	LIST_REMOVE(n1, entries);
	free(n1);
}

n1 = LIST_FIRST(&head);			/* حذف القائمة بشكل أسرع. */
while (n1 != NULL) {
	n2 = LIST_NEXT(n1, entries);
	free(n1);
	n1 = n2;
}
LIST_INIT(&head);

قوائم الذيل (TAIL QUEUES)

قائمة الذيل يتم ترأسها بواسطة بنية يتم تعريفها بواسطة الماكرو TAILQ_HEAD. تحتوي هذه البنية على زوج من المؤشرات، واحد إلى العنصر الأول في قائمة الذيل والآخر إلى العنصر الأخير في قائمة الذيل. العناصر مرتبطة بروابط مزدوجة بحيث يمكن إزالة عنصر اعتباطي دون اجتياز قائمة الذيل. يمكن إضافة عناصر جديدة إلى قائمة الذيل بعد عنصر موجود، قبل عنصر موجود، في رأس قائمة الذيل، أو في نهاية قائمة الذيل. يتم تعريف بنية TAILQ_HEAD على النحو التالي:

TAILQ_HEAD(HEADNAME, TYPE) head;

حيث HEADNAME هو اسم البنية التي سيتم تعريفها، و TYPE هو نوع العناصر التي سيتم ربطها في قائمة الذيل. يمكن بعد ذلك الإعلان عن مؤشر إلى رأس قائمة الذيل على النحو التالي:

struct HEADNAME *headp;

(الأسماء head و headp قابلة للاختيار من قبل المستخدم.)

الماكرو TAILQ_HEAD_INITIALIZER يقيم إلى مُهيئ لقائمة الذيل head.

الماكرو TAILQ_CONCAT يقوم بدمج قائمة الذيل التي يرأسها head2 في نهاية قائمة الذيل التي يرأسها head1، مزيلًا جميع الإدخالات من القائمة الأولى.

الماكرو TAILQ_EMPTY يقيم إلى صحيح إذا لم تكن هناك عناصر في قائمة الذيل.

الماكرو TAILQ_ENTRY يعلن عن بنية تربط العناصر في قائمة الذيل.

الماكرو TAILQ_FIRST يعيد العنصر الأول في قائمة الذيل أو NULL إذا كانت قائمة الذيل فارغة.

الماكرو TAILQ_FOREACH يجتاز قائمة الذيل المشار إليها بواسطة head في الاتجاه الأمامي، مع تعيين كل عنصر بدوره إلى var. يتم تعيين var إلى NULL إذا اكتملت الحلقة بشكل طبيعي، أو إذا لم تكن هناك عناصر.

الماكرو TAILQ_FOREACH_FROM يتصرف بشكل مطابق لـ TAILQ_FOREACH عندما يكون var هو NULL، وإلا فإنه يعامل var كعنصر TAILQ تم العثور عليه مسبقًا ويبدأ الحلقة عند var بدلاً من العنصر الأول في TAILQ المشار إليها بواسطة head.

الماكرو TAILQ_FOREACH_REVERSE يجتاز قائمة الذيل المشار إليها بواسطة head في الاتجاه العكسي، مع تعيين كل عنصر بدوره إلى var.

الماكرو TAILQ_FOREACH_REVERSE_FROM يتصرف بشكل مطابق لـ TAILQ_FOREACH_REVERSE عندما يكون var هو NULL، وإلا فإنه يعامل var كعنصر TAILQ تم العثور عليه مسبقًا ويبدأ الحلقة العكسية عند var بدلاً من العنصر الأخير في TAILQ المشار إليها بواسطة head.

الماكرو TAILQ_FOREACH_SAFE والماكرو TAILQ_FOREACH_REVERSE_SAFE يجتازان القائمة المشار إليها بواسطة head في الاتجاه الأمامي أو العكسي على التوالي، مع تعيين كل عنصر بدوره إلى var. ومع ذلك، على عكس نظيراتها غير الآمنة، TAILQ_FOREACH و TAILQ_FOREACH_REVERSE تجعل من الممكن إزالة var وكذلك تحريره من داخل الحلقة بأمان دون التدخل في الاجتياز.

الماكرو TAILQ_FOREACH_FROM_SAFE يتصرف بشكل مطابق لـ TAILQ_FOREACH_SAFE عندما يكون var هو NULL، وإلا فإنه يعامل var كعنصر TAILQ تم العثور عليه مسبقًا ويبدأ الحلقة عند var بدلاً من العنصر الأول في TAILQ المشار إليها بواسطة head.

الماكرو TAILQ_FOREACH_REVERSE_FROM_SAFE يتصرف بشكل مطابق لـ TAILQ_FOREACH_REVERSE_SAFE عندما يكون var هو NULL، وإلا فإنه يعامل var كعنصر TAILQ تم العثور عليه مسبقًا ويبدأ الحلقة العكسية عند var بدلاً من العنصر الأخير في TAILQ المشار إليها بواسطة head.

الماكرو TAILQ_INIT يقوم بتهيئة قائمة الذيل المشار إليها بواسطة head.

الماكرو TAILQ_INSERT_HEAD يدرج العنصر الجديد elm في رأس قائمة الذيل.

الماكرو TAILQ_INSERT_TAIL يدرج العنصر الجديد elm في نهاية قائمة الذيل.

الماكرو TAILQ_INSERT_AFTER يدرج العنصر الجديد elm بعد العنصر listelm.

الماكرو TAILQ_INSERT_BEFORE يدرج العنصر الجديد elm قبل العنصر listelm.

الماكرو TAILQ_LAST يعيد العنصر الأخير في قائمة الذيل. إذا كانت قائمة الذيل فارغة، فإن القيمة المعادة هي NULL.

الماكرو TAILQ_NEXT يعيد العنصر التالي في قائمة الذيل، أو NULL إذا كان هذا العنصر هو الأخير.

الماكرو TAILQ_PREV يعيد العنصر السابق في قائمة الذيل، أو NULL إذا كان هذا العنصر هو الأول.

الماكرو TAILQ_REMOVE يزيل العنصر elm من قائمة الذيل.

الماكرو TAILQ_SWAP يبادل محتويات head1 و head2.

التشخيص

عند تصحيح الأخطاء في queue(3)، قد يكون من المفيد تتبع التغييرات في الصف. لتمكين التتبع، قم بتعريف الماكرو QUEUE_MACRO_DEBUG_TRACE وقت الترجمة.

قد يكون من المفيد أيضًا إتلاف المؤشرات التي تم فصلها من صف، للكشف عن الاستخدام بعد الإزالة. لتمكين إتلاف المؤشرات، قم بتعريف الماكرو QUEUE_MACRO_DEBUG_TRASH وقت الترجمة. يعيد الماكرو QMD_IS_TRASHED(void *ptr) القيمة true إذا تم إتلاف ptr بواسطة الخيار QUEUE_MACRO_DEBUG_TRASH.
