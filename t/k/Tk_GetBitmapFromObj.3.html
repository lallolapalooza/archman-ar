الوصف

تدير هذه الإجراءات مجموعة من الرسومات النقطية (pixmaps أحادية المستوى) التي تستخدمها التطبيقات. تسمح الإجراءات بإعادة استخدام الرسومات النقطية بكفاءة، مما يتجنب الحمل الزائد على الخادم، كما تسمح بتسمية الرسومات النقطية بسلاسل نصية.

Tk_AllocBitmapFromObj ترجع معرف رسم نقطي لرسم نقطي يطابق الوصف في objPtr وهو مناسب للاستخدام في tkwin. تعيد استخدام رسم نقطي موجود، إن أمكن، وتنشئ واحدًا جديدًا بخلاف ذلك. يجب أن يكون قيمة ObjPtr بأحد الأشكال التالية:

@fileName
يجب أن يكون FileName اسم ملف يحتوي على وصف رسم نقطي بتنسيق X11 القياسي.
name
يجب أن يكون Name اسم رسم نقطي تم تعريفه مسبقًا باستدعاء Tk_DefineBitmap. الأسماء التالية محددة مسبقًا بواسطة Tk:

في الظروف العادية، ترجع Tk_AllocBitmapFromObj معرفًا للرسم النقطي المطلوب. إذا حدث خطأ في إنشاء الرسم النقطي، مثل عندما يشير objPtr إلى ملف غير موجود، فسيتم إرجاع None وسيتم ترك رسالة خطأ في نتيجة interp إذا لم يكن interp NULL. تقوم Tk_AllocBitmapFromObj بتخزين المعلومات حول القيمة المرجعة مؤقتًا في objPtr، مما يسرع الاستدعاءات المستقبلية للإجراءات مثل Tk_AllocBitmapFromObj و Tk_GetBitmapFromObj.

Tk_GetBitmap مطابق لـ Tk_AllocBitmapFromObj باستثناء أن وصف الرسم النقطي يتم تحديده بسلسلة نصية بدلاً من كائن. هذا يمنع Tk_GetBitmap من تخزين القيمة المرجعة مؤقتًا، لذا فإن Tk_GetBitmap أقل كفاءة من Tk_AllocBitmapFromObj.

Tk_GetBitmapFromObj ترجع الرمز لرسم نقطي موجود، بالنظر إلى النافذة والوصف المستخدمين لإنشاء الرسم النقطي. لا تقوم Tk_GetBitmapFromObj بإنشاء الرسم النقطي فعليًا؛ يجب أن يكون الرسم النقطي قد تم إنشاؤه بالفعل باستدعاء سابق لـ Tk_AllocBitmapFromObj أو Tk_GetBitmap. يتم تخزين القيمة المرجعة مؤقتًا في objPtr، مما يسرع الاستدعاءات المستقبلية لـ Tk_GetBitmapFromObj بنفس objPtr و tkwin.

Tk_DefineBitmap يربط اسمًا ببيانات الرسم النقطي الموجودة في الذاكرة بحيث يمكن استخدام الاسم في الاستدعاءات اللاحقة لـ Tk_AllocBitmapFromObj أو Tk_GetBitmap. الوسيط nameId يعطي اسمًا للرسم النقطي؛ يجب ألا يكون قد تم استخدامه مسبقًا في استدعاء لـ Tk_DefineBitmap. الوسائط source و width و height تصف الرسم النقطي. تعيد Tk_DefineBitmap عادةً TCL_OK؛ إذا حدث خطأ (على سبيل المثال، تم تعريف رسم نقطي باسم nameId بالفعل) فسيتم إرجاع TCL_ERROR وسيتم ترك رسالة خطأ في نتيجة المفسر interp. ملاحظة: تتوقع Tk_DefineBitmap أن تكون الذاكرة المشار إليها بواسطة source ثابتة: لا تنشئ Tk_DefineBitmap نسخة خاصة من هذه الذاكرة، بل تستخدم البايتات المشار إليها بواسطة source لاحقًا في استدعاءات لـ Tk_AllocBitmapFromObj أو Tk_GetBitmap.

ARGUMENTS

Tcl_Interp *interp
Interpreter to use for error reporting and for accessing the bitmap database.
Tcl_Obj *objPtr
The string representation of the bitmap is in this object. Possible values are described in the TEXT REPRESENTATIONS section below.
Tk_Window tkwin
Window associated with the desired bitmap. This is needed to determine screen and display. If NULL, the default screen and display are used.
const char *string
A string identifying the desired bitmap. See TEXT REPRESENTATIONS.
Pixmap bitmap
A bitmap previously returned by Tk_GetBitmapFromObj or Tk_GetBitmap.
int *widthPtr
If not NULL, points to integer storage where the width of the bitmap will be written.
int *heightPtr
If not NULL, points to integer storage where the height of the bitmap will be written.

DESCRIPTION

These procedures manage bitmaps for Tk applications. A bitmap is a monochromatic image that can be used for drawing or as a pattern.

A bitmap can be specified in several ways:

@filename
The bitmap is read from the file named filename. The file should be in the standard X11 XBM format. The file is searched for in the current directory, or in directories specified by the Tk_FindBitmap search path.
name
The bitmap is looked up in Tk's internal database by the name name. This is typically used for bitmaps that have been defined using Tk_DefineBitmap.

The procedure Tk_GetBitmapFromObj is the preferred modern way to get a bitmap. It takes a Tcl_Obj pointer as input, which can represent the bitmap name as either a string (as described above) or as a pre-defined bitmap object. It returns the desired bitmap, creating it if necessary. If the bitmap already exists in the database and is in use, Tk_GetBitmapFromObj will simply return a pointer to the existing bitmap, avoiding redundant work.

The procedure Tk_AllocBitmapFromObj is similar to Tk_GetBitmapFromObj, but it also takes a Tk_Window argument which is used to determine the screen and display to use for the bitmap. It is typically used when you need to create a bitmap for a specific window, e.g. for a widget.

The procedure Tk_GetBitmap is the older, C-style interface. It takes a null-terminated string as input and returns the desired bitmap. It is functionally equivalent to Tk_GetBitmapFromObj with the string representation of the object used as input.

The following code uses Tk_DefineBitmap to define a new bitmap named foo:

Pixmap bitmap;
#include "stip.bitmap"
Tk_DefineBitmap(interp, "foo", stip_bits,
    stip_width, stip_height);
...
bitmap = Tk_GetBitmap(interp, tkwin, "foo");

This code causes the bitmap file to be read at compile-time and incorporates the bitmap information into the program's executable image. The same bitmap file could be read at run-time using Tk_GetBitmap:

Pixmap bitmap;
bitmap = Tk_GetBitmap(interp, tkwin, "@stip.bitmap");

The second form is a bit more flexible (the file could be modified after the program has been compiled, or a different string could be provided to read a different file), but it is a little slower and requires the bitmap file to exist separately from the program.

Tk maintains a database of all the bitmaps that are currently in use. Whenever possible, it will return an existing bitmap rather than creating a new one. When a bitmap is no longer used, Tk will release it automatically. This approach can substantially reduce server overhead, so Tk_AllocBitmapFromObj and Tk_GetBitmap should generally be used in preference to Xlib procedures like XReadBitmapFile.

The bitmaps returned by Tk_AllocBitmapFromObj and Tk_GetBitmap are shared, so callers should never modify them. If a bitmap must be modified dynamically, then it should be created by calling Xlib procedures such as XReadBitmapFile or XCreatePixmap directly.

The procedure Tk_NameOfBitmap is roughly the inverse of Tk_GetBitmap. Given an X Pixmap argument, it returns the textual description that was passed to Tk_GetBitmap when the bitmap was created. Bitmap must have been the return value from a previous call to Tk_AllocBitmapFromObj or Tk_GetBitmap.

Tk_SizeOfBitmap returns the dimensions of its bitmap argument in the words pointed to by the widthPtr and heightPtr arguments. As with Tk_NameOfBitmap, bitmap must have been created by Tk_AllocBitmapFromObj or Tk_GetBitmap.

When a bitmap is no longer needed, Tk_FreeBitmapFromObj or Tk_FreeBitmap should be called to release it. For Tk_FreeBitmapFromObj the bitmap to release is specified with the same information used to create it; for Tk_FreeBitmap the bitmap to release is specified with its Pixmap token. There should be exactly one call to Tk_FreeBitmapFromObj or Tk_FreeBitmap for each call to Tk_AllocBitmapFromObj or Tk_GetBitmap.

BUGS

In determining whether an existing bitmap can be used to satisfy a new request, Tk_AllocBitmapFromObj and Tk_GetBitmap consider only the immediate value of the string description. For example, when a file name is passed to Tk_GetBitmap, Tk_GetBitmap will assume it is safe to re-use an existing bitmap created from the same file name: it will not check to see whether the file itself has changed, or whether the current directory has changed, thereby causing the name to refer to a different file.

KEYWORDS

bitmap, pixmap
