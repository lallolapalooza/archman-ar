Tk__option(3pm)

الحزمة: perl-tk

التراخيص: PerlArtistic, GPL, custom

DESCRIPTION

The option method is used to query or set Tk resource values. It is used extensively by Tk widgets to retrieve configuration options from resource databases. The option method has the following general form:

    $widget->option($optionName, $value)
    $widget->option($optionName)

If value is provided, the option named optionName is set to that value. If value is omitted, then the current value of the option is returned. The optionName is a string such as "background" or "font".

The value returned by option is an X resource string. Tk does some translation to allow certain shortcuts, for example, a value of "red" might be translated to something like "#ff0000".

The value of an option is determined by a lookup process. The process searches for the option in a set of predefined priority levels. The first value found is the one used. The priority levels, from lowest to highest, are:

startupFile
Level 40. Used for options specified in application-specific startup files.
userDefault
Level 60. Used for options specified in user-specific defaults files, such as .Xdefaults, resource databases loaded into the X server, or user-specific startup files.
interactive
Level 80. Used for options specified interactively after the application starts running. If priority isn't specified, it defaults to this level.

Any of the above keywords may be abbreviated. In addition, priorities may be specified numerically using integers between 0 and 100, inclusive. The numeric form is probably a bad idea except for new priority levels other than the ones given above.

BUGS

The priority scheme used by core Tk is not the same as used by normal Xlib routines. In particular is assumes that the order of the entries is defined, but user commands like xrdb -merge can change the order.

الوصف

يُستخدم التابع option للاستعلام عن قيم موارد Tk أو تعيينها. تستخدمه عناصر واجهة المستخدم الرسومية (widgets) الخاصة بـ Tk بشكل مكثف لاسترداد خيارات التكوين من قواعد بيانات الموارد. يمتلك التابع option الشكل العام التالي:

    $widget->option($optionName, $value)
    $widget->option($optionName)

إذا تم توفير value، فسيتم تعيين الخيار المسمى optionName إلى هذا value. إذا تم حذف value، فسيتم إرجاع القيمة الحالية للخيار. optionName هو سلسلة نصية مثل "background" أو "font".

القيمة التي يتم إرجاعها بواسطة option هي سلسلة مورد X. يقوم Tk بإجراء بعض الترجمات للسماح بالاختصارات، على سبيل المثال، قد يتم ترجمة قيمة مثل "red" إلى شيء مثل "#ff0000".

يتم تحديد قيمة الخيار من خلال عملية بحث. تبحث العملية عن الخيار في مجموعة من مستويات الأولوية المحددة مسبقًا. أول قيمة يتم العثور عليها هي التي يتم استخدامها. مستويات الأولوية، من الأدنى إلى الأعلى، هي:

startupFile
المستوى 40. يستخدم للخيارات المحددة في ملفات بدء تشغيل خاصة بالتطبيق.
userDefault
المستوى 60. يستخدم للخيارات المحددة في ملفات الإعدادات الخاصة بالمستخدم، مثل .Xdefaults، أو قواعد بيانات الموارد المحملة في خادم X، أو ملفات بدء التشغيل الخاصة بالمستخدم.
interactive
المستوى 80. يستخدم للخيارات المحددة تفاعليًا بعد بدء تشغيل التطبيق. إذا لم يتم تحديد priority، فسيتم افتراض هذا المستوى.

يمكن اختصار أي من الكلمات المفتاحية المذكورة أعلاه. بالإضافة إلى ذلك، يمكن تحديد الأولويات رقميًا باستخدام أعداد صحيحة بين 0 و 100، شاملة. الشكل الرقمي قد يكون فكرة سيئة باستثناء مستويات الأولوية الجديدة بخلاف تلك المذكورة أعلاه.

الأخطاء

نظام الأولوية الذي تستخدمه Tk الأساسي ليس هو نفس المستخدم في إجراءات Xlib العادية. على وجه الخصوص، يفترض أن ترتيب الإدخالات محدد، ولكن الأوامر الخاصة بالمستخدم مثل xrdb -merge يمكن أن تغير الترتيب.
