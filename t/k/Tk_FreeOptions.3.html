الوصف

ملاحظة: يجب استبدال Tk_ConfigureWidget بواجهة Tcl_Obj الجديدة Tk_SetOptions. الواجهة القديمة محفوظة للتوافق مع الإصدارات السابقة.

يتم استدعاء Tk_ConfigureWidget لتكوين جوانب مختلفة للأداة، مثل الألوان والخطوط وعرض الحدود وما إلى ذلك. وهي تهدف إلى أن تكون إجراءً مساعدًا لتقليل كمية التعليمات البرمجية التي يجب كتابتها في مديري الأدوات الفرديين لمعالجة معلومات التكوين. يتم استدعاؤها عادةً عند إنشاء الأدوات، ومرة أخرى عند استدعاء الأمر configure لأداة. على الرغم من أنها مخصصة بشكل أساسي للأدوات، يمكن استخدام Tk_ConfigureWidget في مواقف أخرى حيث يتم استخدام معلومات argc-argv لملء بنية سجل، مثل تكوين العناصر الرسومية لأداة canvas أو إدخالات قائمة.

تقوم Tk_ConfigureWidget بمعالجة جدول يحدد خيارات التكوين المدعومة (specs) ومجموعة من وسائط سطر الأوامر (argc و argv) لملء حقول سجل (widgRec). تستخدم قاعدة بيانات الخيارات والقيم الافتراضية المحددة في specs لملء حقول widgRec غير المحددة في argv. تعيد Tk_ConfigureWidget عادةً القيمة TCL_OK؛ في هذه الحالة، لا تعدل interp. إذا حدث خطأ، تُرجع TCL_ERROR وستترك Tk_ConfigureWidget رسالة خطأ في نتيجة المفسر interp بالطريقة القياسية لـ Tcl. في حالة إرجاع خطأ، قد تكون بعض حقول widgRec قد تم تعيينها بالفعل، إذا تم معالجة معلومات التكوين الخاصة بها بنجاح قبل حدوث الخطأ. سيتم تعيين الحقول الأخرى إلى قيم أولية معقولة بحيث يمكن استدعاء Tk_FreeOptions للتنظيف.

يحدد مصفوفة specs أنواع خيارات التكوين التي تدعمها الأداة. كل إدخال منها يحدد خيار تكوين واحد وله البنية التالية:

typedef struct {
    int type;
    const char *argvName;
    const char *dbName;
    const char *dbClass;
    const char *defValue;
    int offset;
    int specFlags;
    const Tk_CustomOption *customPtr;
} Tk_ConfigSpec;
يحدد الحقل type نوع خيار التكوين (مثل TK_CONFIG_COLOR لقيمة اللون، أو TK_CONFIG_INT لقيمة عدد صحيح). يحدد الحقل type كيفية استخدام قيمة الخيار (المزيد حول هذا أدناه). الحقل argvName هو سلسلة نصية مثل " -font " أو " -bg "، والتي تتم مقارنتها بالقيم في argv (إذا كان argvName NULL فهذا يعني أنه إدخال مجمع؛ انظر الإدخالات المجمعة أدناه). تستخدم الحقول dbName و dbClass للبحث عن قيمة لهذا الخيار في قاعدة بيانات الخيارات. يحدد الحقل defValue قيمة افتراضية لخيـار التكوين هذا إذا لم يتم تحديد قيمة في argv أو قاعدة بيانات الخيارات. Offset يشير إلى مكان التخزين في widgRec لمعلومات حول هذا الخيار، ويحتوي specFlags على معلومات إضافية للتحكم في معالجة خيار التكوين هذا (انظر الأعلام أدناه). الحقل الأخير، customPtr، يستخدم فقط إذا كان type هو TK_CONFIG_CUSTOM؛ انظر أنواع الخيارات المخصصة أدناه.

تقوم Tk_ConfigureWidget أولاً بمعالجة argv لمعرفة أي (إن وجد) خيارات التكوين محددة هناك. يجب أن يحتوي argv على عدد زوجي من الحقول؛ يجب أن يتطابق الأول من كل زوج من الحقول مع argvName لإدخال ما في specs (الاختصارات الفريدة مقبولة)، والحقل الثاني من الزوج يحتوي على قيمة خيار التكوين هذا. إذا كانت هناك إدخالات في spec لم تكن لها إدخالات مطابقة في argv، تستخدم Tk_ConfigureWidget الحقول dbName و dbClass لإدخال specs للاستعلام عن قاعدة بيانات الخيارات؛ إذا تم العثور على قيمة، فسيتم استخدامها كقيمة للخيار. أخيرًا، إذا لم يتم العثور على إدخال في قاعدة بيانات الخيارات، يتم استخدام الحقل defValue لإدخال specs كقيمة لخيار التكوين. إذا كان defValue هو NULL، أو إذا تم تعيين البت TK_CONFIG_DONT_SET_DEFAULT في flags، فلا توجد قيمة افتراضية وسيتم تجاهل إدخال specs هذا إذا لم يتم تحديد قيمة في argv أو قاعدة بيانات الخيارات.

بمجرد تحديد قيمة سلسلة نصية لخيار تكوين، تقوم Tk_ConfigureWidget بترجمة قيمة السلسلة النصية إلى شكل أكثر فائدة، مثل لون إذا كان type هو TK_CONFIG_COLOR أو عدد صحيح إذا كان type هو TK_CONFIG_INT. يتم بعد ذلك تخزين هذه القيمة في السجل المشار إليه بواسطة widgRec. يُفترض أن يحتوي هذا السجل على معلومات ذات صلة بمدير الأداة؛ نوعه الدقيق غير معروف لـ Tk_ConfigureWidget. يشير الحقل offset لكل إدخال specs إلى مكان التخزين في widgRec للمعلومات حول هذا الخيار. يجب عليك استخدام ماكرو Tk_Offset لإنشاء قيم offset (انظر أدناه لوصف Tk_Offset). سيشار إلى الموقع المشار إليه بواسطة widgRec و offset باسم "الهدف" في الأوصاف أدناه.

يحدد الحقل type لكل إدخال في specs ما يجب فعله بقيمة السلسلة النصية لهذا الخيار. القيم القانونية لـ type، والإجراءات المقابلة، هي:

TK_CONFIG_ACTIVE_CURSOR
يجب أن تكون القيمة سلسلة نصية ASCII تحدد مؤشرًا بتنسيق مناسب لتمريره إلى Tk_GetCursor. تتم ترجمة القيمة إلى Tk_Cursor عن طريق استدعاء Tk_GetCursor ويتم تخزين النتيجة في الهدف. بالإضافة إلى ذلك، يتم تعيين المؤشر الناتج ليكون المؤشر النشط لـ tkwin عن طريق استدعاء XDefineCursor. إذا تم تحديد TK_CONFIG_NULL_OK في specFlags، فيمكن أن تكون القيمة سلسلة نصية فارغة، وفي هذه الحالة سيتم تعيين الهدف والمؤشر النشط لـ tkwin إلى None. إذا لم تكن القيمة السابقة للهدف None، فسيتم تحريرها عن طريق تمريرها إلى Tk_FreeCursor.
TK_CONFIG_ANCHOR
يجب أن تكون القيمة سلسلة نصية ASCII تحدد نقطة تثبيت بإحدى الطرق التي تقبلها Tk_GetAnchor. تتم ترجمة السلسلة النصية إلى Tk_Anchor بواسطة

TK_CONFIG_ANCHOR
يجب أن تكون القيمة عبارة عن سلسلة نصية ASCII تحدد نقطة الارتكاز بصيغة مناسبة لتمريرها إلى Tk_GetAnchor. يتم تحويل القيمة عن طريق استدعاء Tk_GetAnchor ويتم تخزين النتيجة في الهدف.
TK_CONFIG_BITMAP
يجب أن تكون القيمة عبارة عن سلسلة نصية ASCII تحدد صورة نقطية (bitmap) بصيغة مناسبة لتمريرها إلى Tk_GetBitmap. يتم تحويل القيمة إلى Pixmap عن طريق استدعاء Tk_GetBitmap ويتم تخزين النتيجة في الهدف. إذا تم تحديد TK_CONFIG_NULL_OK في specFlags فيمكن أن تكون القيمة سلسلة نصية فارغة، وفي هذه الحالة يتم تعيين الهدف إلى None. إذا لم تكن القيمة السابقة للهدف None، فسيتم تحريرها عن طريق تمريرها إلى Tk_FreeBitmap.
TK_CONFIG_BOOLEAN
يجب أن تكون القيمة عبارة عن سلسلة نصية ASCII تحدد قيمة منطقية. أي من القيم "true" أو "yes" أو "on" أو "1" ، أو اختصار لإحدى هذه القيم، يعني صحيح؛ وأي من القيم "false" أو "no" أو "off" أو "0"، أو اختصار لإحدى هذه القيم، يعني خاطئ. يُتوقع أن يكون الهدف عددًا صحيحًا؛ بالنسبة للقيم الصحيحة سيتم تعيينه إلى 1 وبالنسبة للقيم الخاطئة سيتم تعيينه إلى 0.
TK_CONFIG_BORDER
يجب أن تكون القيمة عبارة عن سلسلة نصية ASCII تحدد لون الحدود بصيغة مناسبة لتمريرها إلى Tk_Get3DBorder. يتم تحويل القيمة إلى (Tk_3DBorder *) عن طريق استدعاء Tk_Get3DBorder ويتم تخزين النتيجة في الهدف. إذا تم تحديد TK_CONFIG_NULL_OK في specFlags فيمكن أن تكون القيمة سلسلة نصية فارغة، وفي هذه الحالة سيتم تعيين الهدف إلى NULL. إذا لم تكن القيمة السابقة للهدف NULL، فسيتم تحريرها عن طريق تمريرها إلى Tk_Free3DBorder.
TK_CONFIG_CAP_STYLE
يجب أن تكون القيمة عبارة عن سلسلة نصية ASCII تحدد نمط النهاية (cap style) بإحدى الطرق التي تقبلها Tk_GetCapStyle. يتم تحويل السلسلة إلى قيمة عدد صحيح تقابل نمط النهاية عن طريق استدعاء Tk_GetCapStyle ويتم تخزين النتيجة في الهدف.
TK_CONFIG_COLOR
يجب أن تكون القيمة عبارة عن سلسلة نصية ASCII تحدد لونًا بصيغة مناسبة لتمريرها إلى Tk_GetColor. يتم تحويل القيمة إلى (XColor *) عن طريق استدعاء Tk_GetColor ويتم تخزين النتيجة في الهدف. إذا تم تحديد TK_CONFIG_NULL_OK في specFlags فيمكن أن تكون القيمة سلسلة نصية فارغة، وفي هذه الحالة سيتم تعيين الهدف إلى None. إذا لم تكن القيمة السابقة للهدف NULL، فسيتم تحريرها عن طريق تمريرها إلى Tk_FreeColor.
TK_CONFIG_CURSOR
هذا الخيار مطابق لـ TK_CONFIG_ACTIVE_CURSOR باستثناء أن المؤشر الجديد لا يتم جعله المؤشر النشط لـ tkwin.
TK_CONFIG_CUSTOM
يتيح هذا الخيار للتطبيقات تعريف أنواع خيارات جديدة. يشير الحقل customPtr في المدخل إلى بنية تحدد نوع الخيار الجديد. انظر القسم أنواع الخيارات المخصصة أدناه للحصول على التفاصيل.
TK_CONFIG_DOUBLE
يجب أن تكون القيمة عبارة عن رقم عشري بفاصلة عائمة بصيغة ASCII بالشكل الذي تقبله strtol. يتم تحويل السلسلة إلى قيمة double، ويتم تخزين القيمة في الهدف.
TK_CONFIG_END
يمثل نهاية الجدول. يجب أن يكون الإدخال الأخير في specs بهذا النوع؛ سيتم تجاهل جميع حقوله الأخرى ولن يتطابق أبدًا مع أي وسيطات.
TK_CONFIG_FONT
يجب أن تكون القيمة عبارة عن سلسلة نصية ASCII تحدد خطًا بصيغة مناسبة لتمريرها إلى Tk_GetFont. يتم تحويل القيمة إلى Tk_Font عن طريق استدعاء Tk_GetFont ويتم تخزين النتيجة في الهدف. إذا تم تحديد TK_CONFIG_NULL_OK في specFlags فيمكن أن تكون القيمة سلسلة نصية فارغة، وفي هذه الحالة سيتم تعيين الهدف إلى NULL. إذا لم تكن القيمة السابقة للهدف NULL، فسيتم تحريرها عن طريق تمريرها إلى Tk_FreeFont.
TK_CONFIG_INT
يجب أن تكون القيمة عبارة عن سلسلة نصية عددية صحيحة بصيغة ASCII بالشكل الذي تقبله strtol (على سبيل المثال، يمكن استخدام البادئات "0" و "0x" لتحديد الأرقام الثمانية أو الستة عشرية، على التوالي). يتم تحويل السلسلة إلى قيمة عدد صحيح ويتم تخزين العدد الصحيح في الهدف.
TK_CONFIG_JOIN_STYLE
يجب أن تكون القيمة عبارة عن سلسلة نصية ASCII تحدد نمط الوصل (join style) بإحدى الطرق التي تقبلها Tk_GetJoinStyle. يتم تحويل السلسلة إلى قيمة عدد صحيح تقابل نمط الوصل عن طريق استدعاء Tk_GetJoinStyle ويتم تخزين النتيجة في الهدف.
TK_CONFIG_JUSTIFY
يجب أن تكون القيمة عبارة عن سلسلة نصية ASCII تحدد طريقة المحاذاة (justification) بإحدى الطرق التي تقبلها Tk_GetJustify. يتم تحويل السلسلة إلى Tk_Justify عن طريق استدعاء Tk_GetJustify ويتم تخزين النتيجة في الهدف.
TK_CONFIG_MM
يجب أن تحدد القيمة مسافة على الشاشة بإحدى الصيغ المقبولة بواسطة Tk_GetScreenMM. يتم تحويل السلسلة إلى مسافة بفاصلة عائمة مزدوجة الدقة بالملليمتر ويتم تخزين القيمة في الهدف.
TK_CONFIG_PIXELS
يجب أن تحدد القيمة وحدات على الشاشة بإحدى الصيغ المقبولة بواسطة Tk_GetPixels. يتم تحويل السلسلة إلى مسافة عدد صحيح بالبكسل ويتم تخزين القيمة في الهدف.
TK_CONFIG_RELIEF
يجب أن تكون القيمة عبارة عن سلسلة نصية ASCII تحدد تخفيفًا (relief) بصيغة مناسبة لتمريرها إلى Tk_GetRelief. يتم تحويل القيمة إلى قيمة عدد صحيح للتخفيف عن طريق استدعاء Tk_GetRelief ويتم تخزين النتيجة في الهدف.
TK_CONFIG_STRING
يتم إنشاء نسخة من القيمة عن طريق تخصيص مساحة ذاكرة باستخدام Tcl_Alloc ونسخ القيمة إلى المساحة المخصصة ديناميكيًا. يتم تخزين مؤشر إلى السلسلة الجديدة في الهدف. إذا تم تحديد TK_CONFIG_NULL_OK في specFlags فيمكن أن تكون القيمة سلسلة نصية فارغة، وفي هذه الحالة سيتم تعيين الهدف إلى NULL. إذا لم تكن القيمة السابقة للهدف NULL، فسيتم تحريرها عن طريق تمريرها إلى Tcl_Free.
TK_CONFIG_SYNONYM
يحدد هذا النوع الخاص من type مداخل خاصة في specs وهي مرادفات لمداخل أخرى. إذا تطابقت قيمة argv مع argvName لإدخال TK_CONFIG_SYNONYM، فلن يتم استخدام الإدخال مباشرة. بدلاً من ذلك، يبحث Tk_ConfigureWidget في specs عن إدخال آخر يكون argvName الخاص به هو نفسه حقل dbName في إدخال TK_CONFIG_SYNONYM؛ سيتم استخدام هذا الإدخال الجديد كما لو كان argvName الخاص به قد تطابق مع قيمة argv. تسمح آلية المرادفات باستخدام قيم argv متعددة لخيار تكوين واحد، مثل "-background" و "-bg".
TK_CONFIG_UID
يتم ترجمة القيمة إلى Tk_Uid (عن طريق تمريرها إلى Tk_GetUid). يتم تخزين القيمة الناتجة في الهدف. إذا تم تحديد TK_CONFIG_NULL_OK في specFlags وكانت القيمة سلسلة نصية فارغة، فسيتم تعيين الهدف إلى NULL.
TK_CONFIG_WINDOW
يجب أن تكون القيمة اسم مسار نافذة. يتم ترجمتها إلى رمز Tk_Window ويتم تخزين الرمز في الهدف.

المداخل المجمعة

في بعض الحالات يكون من المفيد إنشاء موارد متعددة من قيمة تكوين واحدة. على سبيل المثال، يمكن استخدام اسم لون لتوليد لون الخلفية للأداة (باستخدام TK_CONFIG_COLOR) ولتوليد حد ثلاثي الأبعاد لرسمه حول الأداة (باستخدام TK_CONFIG_BORDER). في حالات مثل هذه، من الممكن تحديد أن عدة مداخل متتالية في specs يجب التعامل معها كمجموعة. يتم استخدام الإدخال الأول لتحديد قيمة (باستخدام حقول argvName و dbName و dbClass و defValue). سيتم معالجة القيمة عدة مرات (مرة لكل إدخال في المجموعة)، مما يؤدي إلى إنشاء موارد مختلفة متعددة وتعديل أهداف متعددة داخل widgRec. يجب أن يكون لكل إدخال بعد الأول قيمة NULL في حقله argvName؛ يشير هذا إلى أن الإدخال سيتم تجميعه مع الإدخال الذي يسبقه. يتم استخدام حقلي type و offset فقط من هذه الإدخالات اللاحقة.

الأعلام

يتم استخدام الوسيط flags الممرر إلى Tk_ConfigureWidget بالاقتران مع حقول specFlags في مداخل specs لتوفير تحكم إضافي في معالجة خيارات التكوين. تُستخدم هذه القيم بثلاث طرق مختلفة كما هو موضح أدناه.

أولاً، إذا كان الوسيط flags لـ Tk_ConfigureWidget يحتوي على البت TK_CONFIG_ARGV_ONLY معين (أي، flags | TK_CONFIG_ARGV_ONLY != 0)، فلن يتم استخدام قاعدة بيانات الخيارات وحقول defValue. في هذه الحالة، إذا لم يتطابق إدخال في specs مع حقل في argv، فلن يحدث شيء: لن يتم تعديل الهدف المقابل. هذه الميزة مفيدة عندما يكون الهدف هو تعديل خيارات تكوين معينة مع ترك خيارات أخرى في حالتها الحالية، مثل عند معالجة أمر configure للأداة.

ثانياً، يمكن استخدام حقل specFlags للإدخال في specs للتحكم في معالجة هذا الإدخال. قد يتكون كل حقل specFlags من مجموعة OR للأقيم التالية:

TK_CONFIG_COLOR_ONLY
إذا تم تعيين هذا البت، فسيتم النظر في الإدخال فقط إذا كانت الشاشة لـ tkwin تحتوي على أكثر من مستوى بت واحد. إذا كانت الشاشة أحادية اللون، فسيتم تجاهل إدخال specs هذا.

The offset, in bytes, from the beginning of the widget record to the field that holds the option value.
int objc
The number of elements in the objv array.
Tcl_Obj *const objv[]
Array of new-style Tcl command arguments.
int flags
A bitmask of flags that control the behavior of the configuration routines. See the description of Tk_ConfigSpec for more information.
Tk_FreeProc *freeProc
A pointer to a procedure that will be called to free any dynamic memory allocated by the parseProc. If the parseProc does not allocate dynamic memory, then freeProc should be NULL.
Tk_OptionParseProc *parseProc
A pointer to a procedure that will be called to parse the string value of an option. If the option type is not TK_CONFIG_CUSTOM, this argument is ignored.
Tk_OptionPrintProc *printProc
A pointer to a procedure that will be called to convert the internal representation of an option value to a string. If the option type is not TK_CONFIG_CUSTOM, this argument is ignored.

DESCRIPTION

The Tk_ConfigureWidget function is the primary mechanism for configuring Tk widgets. It takes an array of Tk_ConfigSpec structures, which describe the configuration options for a widget, and a list of option specifications (in objc and objv) and applies them to the widget record pointed to by recordPtr.

The Tk_ConfigSpec structure has the following fields:

    int type;
    int offset;
    const char *optionName;
    const char *defValue;
    unsigned int specFlags;
    ClientData clientData;

The type field specifies the type of the option. The possible values are:

TK_CONFIG_SYNONYM
Specifies that this option is a synonym for another option. The optionName field should be the name of the option it is a synonym for. The clientData field should be unused.
TK_CONFIG_STRING
Specifies a string option. The offset field should be the offset of a char * field in the widget record. The defValue field should be the default string value. If the option is not specified, the defValue will be copied into the widget record. If the option is specified, the new string value will be copied into the widget record. The memory for the string will be dynamically allocated.
TK_CONFIG_BOOLEAN
Specifies a boolean option. The offset field should be the offset of an int field in the widget record. The defValue field should be the default value ("true" or "false").
TK_CONFIG_INT
Specifies an integer option. The offset field should be the offset of an int field in the widget record. The defValue field should be the default integer value.
TK_CONFIG_DOUBLE
Specifies a double-precision floating-point option. The offset field should be the offset of a double field in the widget record. The defValue field should be the default double value.
TK_CONFIG_COLOR
Specifies a color option. The offset field should be the offset of a Tk_Color structure in the widget record. The defValue field should be the default color string.
TK_CONFIG_FONT
Specifies a font option. The offset field should be the offset of a Tk_Font structure in the widget record. The defValue field should be the default font string.
TK_CONFIG_BITMAP
Specifies a bitmap option. The offset field should be the offset of a Tk_Bitmap structure in the widget record. The defValue field should be the default bitmap string.
TK_CONFIG_RELIEF
Specifies a relief option. The offset field should be the offset of an int field in the widget record. The defValue field should be the default relief string ("raised", "sunken", "flat", etc.).
TK_CONFIG_ANCHOR
Specifies an anchor option. The offset field should be the offset of an int field in the widget record. The defValue field should be the default anchor string ("n", "s", "e", "w", "center", etc.).
TK_CONFIG_JUSTIFY
Specifies a justification option. The offset field should be the offset of an int field in the widget record. The defValue field should be the default justification string ("left", "center", "right").
TK_CONFIG_CAP_STYLE
Specifies a line cap style option. The offset field should be the offset of an int field in the widget record. The defValue field should be the default cap style string ("butt", "round", "projecting").
TK_CONFIG_JOIN_STYLE
Specifies a line join style option. The offset field should be the offset of an int field in the widget record. The defValue field should be the default join style string ("miter", "round", "bevel").
TK_CONFIG_PIXELS
Specifies a pixel-based distance option. The offset field should be the offset of an int field in the widget record. The defValue field should be the default distance string (e.g., "5", "10p").
TK_CONFIG_MM
Specifies a millimeter-based distance option. The offset field should be the offset of an int field in the widget record. The defValue field should be the default distance string (e.g., "5m").
TK_CONFIG_ACTIVE_BUTTON_BG
Specifies the background color for active buttons. The offset field should be the offset of a Tk_Color structure in the widget record. The defValue field should be the default color string.
TK_CONFIG_ACTIVE_BUTTON_FG
Specifies the foreground color for active buttons. The offset field should be the offset of a Tk_Color structure in the widget record. The defValue field should be the default color string.
TK_CONFIG_ACTIVE_BUTTON_TEXT
Specifies the text color for active buttons. The offset field should be the offset of a Tk_Color structure in the widget record. The defValue field should be the default color string.
TK_CONFIG_TEXT_BG
Specifies the background color for text widgets. The offset field should be the offset of a Tk_Color structure in the widget record. The defValue field should be the default color string.
TK_CONFIG_TEXT_FG
Specifies the foreground color for text widgets. The offset field should be the offset of a Tk_Color structure in the widget record. The defValue field should be the default color string.
TK_CONFIG_TEXT_INSERTION_BG
Specifies the background color for the text insertion cursor. The offset field should be the offset of a Tk_Color structure in the widget record. The defValue field should be the default color string.
TK_CONFIG_TEXT_SELECT_BG
Specifies the background color for selected text. The offset field should be the offset of a Tk_Color structure in the widget record. The defValue field should be the default color string.
TK_CONFIG_TEXT_SELECT_FG
Specifies the foreground color for selected text. The offset field should be the offset of a Tk_Color structure in the widget record. The defValue field should be the default color string.
TK_CONFIG_TEXT_BORDER
Specifies the border color for text widgets. The offset field should be the offset of a Tk_Color structure in the widget record. The defValue field should be the default color string.
TK_CONFIG_TEXT_BG_MONO
Specifies the background color for monochrome text widgets. The offset field should be the offset of a Tk_Color structure in the widget record. The defValue field should be the default color string.
TK_CONFIG_TEXT_FG_MONO
Specifies the foreground color for monochrome text widgets. The offset field should be the offset of a Tk_Color structure in the widget record. The defValue field should be the default color string.
TK_CONFIG_CUSTOM
Specifies a custom option type. The clientData field should point to a Tk_CustomOption structure that describes how to parse and print the option. The offset field is unused. The defValue field is unused.
TK_CONFIG_END
Marks the end of the configuration table.

The optionName field specifies the name of the option (e.g., "background", "foreground"). The defValue field specifies the default value for the option if it is not provided by the user. The specFlags field is a bitmask that can be used to modify the behavior of the option. The following flags are currently supported:

TK_CONFIG_OPTION_IS_TABLE
This flag is used with TK_CONFIG_CUSTOM to indicate that the clientData field points to a Tk_CustomOption structure that is itself an array of Tk_ConfigSpec structures.
TK_CONFIG_USER_BIT
This flag and higher bits can be used for application-specific purposes.

The Tk_FreeOptions function is called to free any memory allocated by the parseProc for the options described by specPtr. It is typically called when a widget is destroyed.

The Tk_ConfigureInfo function is used to get information about the configuration options for a widget. It is typically called by the widget's cget subcommand.

The Tk_ConfigureValue function is used to get the value of a single configuration option. It is typically called by the widget's cget subcommand.

The Tk_SetOptions function is used to register custom option parsing and printing procedures for a given interpreter. This is typically called once during the initialization of a Tk application.

The Tk_ConvertDistanceToPixels function converts a distance string (e.g., "5m", "10p") into a pixel value. The screenWidth and screenHeight arguments are used to determine the screen dimensions for relative units.

GROUPED ENTRIES

Some Tk configuration options are grouped together. For example, the `text` widget has options like `textBackground`, `textForeground`, `textInsertionBackground`, `textSelectBackground`, and `textSelectForeground`. These options are all related to the appearance of text within the widget.

When using TK_CONFIG_CUSTOM, you can define a custom option type that handles a group of related options. The clientData field of the Tk_ConfigSpec structure should point to a Tk_CustomOption structure. The Tk_CustomOption structure contains pointers to a parseProc and a printProc that handle the custom option type.

FLAGS

The specFlags field of the Tk_ConfigSpec structure can be used to modify the behavior of the configuration routines. The following flags are currently supported:

TK_CONFIG_OPTION_IS_TABLE
This flag is used with TK_CONFIG_CUSTOM to indicate that the clientData field points to a Tk_CustomOption structure that is itself an array of Tk_ConfigSpec structures.
TK_CONFIG_USER_BIT
This flag and higher bits can be used for application-specific purposes.

TK_OFFSET

The Tk_Offset macro can be used to calculate the offset of a field within a structure. For example, to get the offset of the background field within a widget record:

    Tk_Offset(WidgetRec, background)

TK_CONFIGUREINFO

The Tk_ConfigureInfo function is used to get information about the configuration options for a widget. It is typically called by the widget's cget subcommand.

The parseProc and printProc arguments are used for custom option types. If the option type is not TK_CONFIG_CUSTOM, these arguments are ignored.

The clientData argument is passed to the custom option's parseProc and printProc procedures.

The flags argument is a bitmask that can be used to control the behavior of the configuration routines. See the description of Tk_ConfigSpec for more information.

TK_CONFIGUREVALUE

The Tk_ConfigureValue function is used to get the value of a single configuration option. It is typically called by the widget's cget subcommand.

The parseProc and printProc arguments are used for custom option types. If the option type is not TK_CONFIG_CUSTOM, these arguments are ignored.

The clientData argument is passed to the custom option's parseProc and printProc procedures.

The flags argument is a bitmask that can be used to control the behavior of the configuration routines. See the description of Tk_ConfigSpec for more information.

TK_FREEOPTIONS

The Tk_FreeOptions function is called to free any memory allocated by the parseProc for the options described by specPtr. It is typically called when a widget is destroyed.

The freeProc argument is a pointer to a procedure that will be called to free any dynamic memory allocated by the parseProc. If the parseProc does not allocate dynamic memory, then freeProc should be NULL.

The recordPtr argument points to the widget record where the option values are stored.

The specPtr argument points to the first element of an array of Tk_ConfigSpec structures, which describes the configuration options for a widget.

CUSTOM OPTION TYPES

For custom option types (TK_CONFIG_CUSTOM), you need to provide two procedures: a parseProc and a printProc.

The parseProc is responsible for converting a string value into an internal representation and storing it in the widget record. It should return TCL_OK on success and TCL_ERROR on failure.

The printProc is responsible for converting an internal representation back into a string. It should return a pointer to the string representation of the option value.

If the parseProc allocates dynamic memory for the option value, then the freeProcPtr argument to Tk_ConfigureWidget should point to a procedure that will free that memory. If the result string is stored in static memory then printProc need not do anything with the freeProcPtr argument.

Once parseProc and printProc have been defined and a Tk_CustomOption structure has been created for them, options of this new type may be manipulated with Tk_ConfigSpec entries whose type fields are TK_CONFIG_CUSTOM and whose customPtr fields point to the Tk_CustomOption structure.

EXAMPLES

Although the explanation of Tk_ConfigureWidget is fairly complicated, its actual use is pretty straightforward. The easiest way to get started is to copy the code from an existing widget. The library implementation of frames (tkFrame.c) has a simple configuration table, and the library implementation of buttons (tkButton.c) has a much more complex table that uses many of the fancy specFlags mechanisms.
