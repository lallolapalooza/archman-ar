Tk__Balloon(3pm)

الحزمة: perl-tk

التراخيص: PerlArtistic, GPL, custom

Balloon(3) توثيق مساهمي Perl Balloon(3)

الاسم

Tk::Balloon - بالونات المساعدة.

الملخص

use Tk::Balloon;
...
$b = $top->Balloon(-statusbar => $status_bar_widget);
# بالون عادي:
$b->attach($widget,
           -balloonmsg => "رسالة مساعدة",
           -statusmsg => "رسالة حالة");
# بالون مرتبط بعنصر واجهة مستخدم لقائمة:
$b->attach($menu, -state => 'status',
                  -msg => ['أول عنصر قائمة',
                           'ثاني عنصر قائمة',
                           ...
                          ],
          );
# بالون مرتبط بعنصر فردي لعنصر واجهة مستخدم شبكي:
$b->attach($canvas, -balloonposition => 'mouse',
                    -msg => {'item1' => 'message1',
                             'tag2'  => 'message2',
                              ...
                            },
          );
# بالون مرتبط بعناصر عنصر واجهة مستخدم لقائمة:
$b->attach($listbox, -balloonposition => 'mouse',
                     -msg => ['أول عنصر قائمة',
                              'ثاني عنصر قائمة',
                              ...
                             ],
          );

الوصف

توفر Balloon الإطار اللازم لإنشاء بالونات المساعدة وربطها بعناصر واجهة المستخدم المختلفة، بالإضافة إلى عرض رسالة عند توقف مؤشر الفأرة فوق عنصر واجهة المستخدم لفترة زمنية معينة.

البالونات والقوائم أو مربعات القائمة

إذا تم ربط البالون بعنصر واجهة مستخدم من نوع menu أو listbox وكانت وسائط الرسالة عبارة عن مراجع مصفوفة، فإن كل عنصر في المصفوفة يقابل رسالة لإدخال قائمة أو عنصر في مربع القائمة. ستُعرض رسالة البالون للإدخال الذي توقف مؤشر الفأرة فوقه. بخلاف ذلك، يُفترض أن البالون مرتبط بكامل عنصر واجهة المستخدم menu أو listbox. يمكنك الحصول على رسائل حالة وبالونات منفصلة، كما هو الحال في البالونات العادية.

البالونات ولوحات الرسم

إذا تم ربط البالون بعنصر واجهة مستخدم من نوع canvas وكانت وسائط الرسالة عبارة عن مراجع تجزئة، فإن كل مفتاح في التجزئة يجب أن يقابل معرفًا أو علامة لعنصر في لوحة الرسم، والقيمة المرتبطة تقابل الرسالة الخاصة بذلك العنصر. ستُعرض رسالة البالون للعنصر الحالي (الموجود في مكان مؤشر الفأرة). بخلاف ذلك، يُفترض أن البالون مرتبط بكامل عنصر واجهة المستخدم canvas. يمكنك الحصول على رسائل حالة وبالونات منفصلة، كما هو الحال في البالونات العادية.

البالونات والقوائم الأفقية

إذا تم ربط البالون بعنصر واجهة مستخدم من نوع HList وكانت وسائط الرسالة عبارة عن مراجع تجزئة، فإن كل مفتاح في التجزئة يجب أن يقابل مسار HList، والقيمة المرتبطة تقابل الرسالة الخاصة بذلك العنصر في HList. ستُعرض رسالة البالون للعنصر الحالي (الموجود في مكان مؤشر الفأرة). بخلاف ذلك، يُفترض أن البالون مرتبط بكامل عنصر واجهة المستخدم HList. يمكنك الحصول على رسائل حالة وبالونات منفصلة، كما هو الحال في البالونات العادية.

موضع البالون

افتراضيًا، يتم عرض البالون في الجانب السفلي الأيمن من العميل. إذا كان سيمتد خارج الحدود السفلية للشاشة، فسيتم نقله إلى الجانب العلوي الأيسر. إذا كان سيمتد خارج الحدود اليمنى، فسيتم عرضه في الجانب السفلي الأيسر من العميل. إذا كان سيمتد خارج كلتا الحدود، فسيتم نقله إلى الجانب العلوي الأيسر من العميل. لذلك، فإن المؤشر الصغير يشير دائمًا إلى العميل المرتبط به.

خيارات

تقبل Balloon جميع الخيارات التي يقبلها عنصر واجهة المستخدم Frame. بالإضافة إلى ذلك، يتم التعرف على الخيارات التالية أيضًا:

-initwait
يحدد المدة الزمنية التي يتم انتظارها بدون نشاط قبل عرض رسالة مساعدة. يتم تحديدها بالمللي ثانية. القيمة الافتراضية هي 350 مللي ثانية. ينطبق هذا على كل من البالون المعروض ورسالة الحالة.
-state
يمكن أن تكون واحدة من 'balloon' أو 'status' أو 'both' أو 'none'، مشيرة إلى ما إذا كان يجب تفعيل بالون المساعدة، أو رسالة الحالة، أو كليهما، أو عدم تفعيل أي منهما عند توقف مؤشر الفأرة فوق عنصر واجهة المستخدم. القيمة الافتراضية هي 'both'.
-statusbar
يحدد عنصر واجهة المستخدم الذي سيتم استخدامه لعرض رسالة الحالة. يجب أن يقبل عنصر واجهة المستخدم هذا خيار -text وعادة ما يكون Label. إذا قبل عنصر واجهة المستخدم الخيار -textvariable وتم تحديد هذا الخيار، فسيتم استخدام هذا الخيار بدلاً من -text.
-balloonposition
يمكن أن تكون واحدة من 'widget' أو 'mouse'. يتحكم في الموضع الذي سيتم فيه عرض البالون. 'widget' تجعل البالون يظهر في الجانب السفلي الأيمن من عنصر واجهة المستخدم المرتبط به (القيمة الافتراضية)، و 'mouse' تجعل البالون يظهر أسفل يمين موضع مؤشر الفأرة.
-postcommand
يقبل هذا الخيار مرجعًا إلى CODE سيتم تنفيذه قبل عرض رسالة البالون ورسالة الحالة، ويجب أن يعيد قيمة صحيحة أو خاطئة للإشارة إلى ما إذا كنت تريد عرض بالون المساعدة أم لا. يسمح هذا أيضًا بالتحكم في موضع بالون المساعدة من خلال القيمة المعادة، والتي يجب أن تكون قيمة صحيحة تبدو كـ X,Y (تطابق هذا النمط المنتظم: "/^(\d+),(\d+)$/"). إذا كانت القيمة المعادة من postcommand تتطابق مع هذا النمط، فسيتم استخدام تلك الإحداثيات كموضع لعرض البالون. ملاحظة: يمكن عرض بالون جديد بعد فترة -initwait، ولكن يمكن التحكم فيه باستخدام الخيار -postcommand. تحذير: يجب أن تعيد هذه الوظيفة الفرعية بسرعة وإلا فإن استجابة بالون المساعدة ستظهر بطيئة وسيتم استهلاك وقت معالجة كبير لوحدة المعالجة المركزية (يتم تنفيذها في كل مرة يتحرك فيها مؤشر الفأرة فوق عناصر واجهة المستخدم المرتبطة بها).
-cancelcommand
يقبل هذا الخيار مرجعًا إلى CODE سيتم تنفيذه قبل إلغاء رسالة البالون ورسالة الحالة، ويجب أن يعيد قيمة صحيحة أو خاطئة للإشارة إلى ما إذا كنت تريد إلغاء بالون المساعدة أم لا. تحذير: يجب أن تعيد هذه الوظيفة الفرعية بسرعة وإلا فإن استجابة بالون المساعدة ستظهر بطيئة وسيتم استهلاك وقت معالجة كبير لوحدة المعالجة المركزية (يتم تنفيذها في كل مرة يتحرك فيها مؤشر الفأرة فوق عناصر واجهة المستخدم المرتبطة بها).
-motioncommand
يقبل هذا الخيار مرجعًا إلى CODE سيتم تنفيذه لأي حدث حركة مؤشر الفأرة ويجب أن يعيد قيمة صحيحة أو خاطئة للإشارة إلى ما إذا كان يجب إلغاء البالون الحالي (تعطيله). إذا أعاد قيمة صحيحة، فسيتم إلغاء البالون بالتأكيد؛ إذا أعاد قيمة خاطئة، فقد يتم إلغاؤه وفقًا للقواعد الداخلية. ملاحظة: يمكن عرض بالون جديد بعد فترة -initwait، ولكن يمكن التحكم فيه باستخدام الخيار -postcommand. تحذير: يجب أن تكون الوظيفة الفرعية سريعة للغاية وإلا فإن استجابة بالون المساعدة ستظهر بطيئة وتستهلك وقت معالجة كبير لوحدة المعالجة المركزية (يتم تنفيذها في كل مرة يتحرك فيها مؤشر الفأرة فوق عناصر واجهة المستخدم المرتبطة بها).
-numscreens
يقبل هذا الخيار عددًا صحيحًا 1 أو أكبر. يجب استخدام هذا الخيار لتجنب البالونات غير المحاذية على شاشات متعددة في وضع الشاشة الواحدة (SLS). يعمل هذا فقط في الاتجاه الأفقي. مثال: إذا كنت في وضع SLS مع شاشتين، فعيّن هذه القيمة إلى 2. القيمة الافتراضية هي 1.

الطرق

عنصر واجهة المستخدم Balloon يدعم ثلاث طرق غير قياسية فقط:

attach(widget, options)

يربط عنصر واجهة المستخدم المشار إليه بواسطة widget بنظام البالونات. الخيارات المسموح بها هي:

-statusmsg
الوسيط هو الرسالة التي ستظهر في رسالة الحالة عند توقف مؤشر الفأرة فوق هذا العميل. إذا لم يتم تحديد هذا، ولكن تم تحديد -msg، فإن الرسالة التي ستظهر في رسالة الحالة هي نفسها الوسيط الخاص بـ -msg. إذا قدمت مرجعًا إلى قيمة قابلة للفك، فسيتم فكها قبل عرضها. مفيد إذا كنت تستخدم -postcommand لتغيير الرسالة.
-state
يمكن أن تكون واحدة من 'balloon' أو 'status' أو 'both' أو 'none'، مشيرة إلى ما إذا كان يجب تفعيل بالون المساعدة، أو رسالة الحالة، أو كليهما، أو عدم تفعيل أي منهما عند توقف مؤشر الفأرة فوق هذا العميل. القيمة الافتراضية هي 'both'. هذا الخيار له نفس وظيفة خيار -state الخاص بـ Balloon، ولكنه خاص بعميل attach.

detach(widget)

يقوم بإلغاء ربط عنصر واجهة المستخدم المشار إليه بواسطة widget من نظام البالونات.

configure(options)

يقوم بتكوين Balloon. يمكنك تغيير الخيارات التي تم تعيينها عند إنشاء Balloon.

 $b->configure(-initwait => 500, -state => 'status');

مثال

#!/usr/bin/perl
use strict;
use warnings;
use Tk;
use Tk::Balloon;
my $mw = MainWindow->new;
my $b = $mw->Balloon(-statusbar => 1, -initwait => 200);
my $btn1 = $mw->Button(-text => 'Button 1', -command => sub { print "Button 1 clicked\n" });
$b->attach($btn1, -balloonmsg => 'This is button 1.', -statusmsg => 'Click for option 1');
my $btn2 = $mw->Button(-text => 'Button 2', -command => sub { print "Button 2 clicked\n" });
$b->attach($btn2, -balloonmsg => 'This is button 2.', -statusmsg => 'Click for option 2');
$btn1->pack(-side => 'left');
$btn2->pack(-side => 'left');
$mw->MainLoop;

NAME

Tk::Balloon - provide balloon help for widgets

SYNOPSIS

use Tk;
use Tk::Balloon;

my $balloon = $mw->Balloon(-initwait => 200);
$balloon->attach($widget,
                 -balloonmsg => 'This is the balloon message',
                 -statusmsg  => 'This is the status bar message',
                 -msg        => 'This is both',
                 -state      => 'active', # or 'disabled'
                 -postcommand => sub { ... },
                 -cancelcommand => sub { ... },
                 -motioncommand => sub { ... },
                );

# If you want to use different messages for balloon and statusbar
$balloon->configure(-balloonmsg => 'Balloon only message');
$balloon->configure(-statusmsg => 'Status bar only message');

# To detach a widget from the balloon
$balloon->detach($widget);

# To destroy the balloon
$balloon->destroy;

DESCRIPTION

The Tk::Balloon widget is a subclass of Tk widget which is used to provide help for other widgets. It pops up a small window containing a message when the mouse pointer pauses over a widget that has been associated with the balloon.

The balloon window itself is automatically managed. You create it once, and then you attach widgets to it. When the mouse pointer pauses over an attached widget, the balloon window appears near the pointer displaying whatever message you've associated with that widget.

The balloon window is automatically destroyed when the application exits. You can also destroy it manually using the destroy method.

There is also support for menus. Menus are treated as widgets.

It also supports canvas items and listbox entries.

OPTIONS

The Tk::Balloon widget supports the following options:

-balloonautoandcancel
A boolean value. If true, the balloon will be automatically destroyed when a button is pressed. This is the default value.
-balloonautoanddestroy
A boolean value. If true, the balloon will be automatically destroyed when the widget it is attached to is destroyed. This is the default value.
-balloonborderwidth
Specifies the border width for the balloon window. Defaults to 1.
-ballooncursor
Specifies the cursor for the balloon window. Defaults to "arrowhead".
-balloonfont
Specifies the font for the text in the balloon window. Defaults to the system's default font.
-balloonfore
Specifies the foreground color for the text in the balloon window. Defaults to the system's default foreground color.
-balloongeometry
Specifies the geometry for the balloon window. Defaults to "+0+0".
-balloonheight
Specifies the height of the balloon window. Defaults to 0 (automatic).
-balloonpadx
Specifies the padding along the x-axis within the balloon window. Defaults to 4.
-balloonpady
Specifies the padding along the y-axis within the balloon window. Defaults to 4.
-balloonrelief
Specifies the relief for the balloon window. Defaults to "raised".
-balloonwidth
Specifies the width of the balloon window. Defaults to 0 (automatic).
-initwait
The initial wait time in milliseconds before the balloon appears. Defaults to 500.
-state
Specifies whether the balloon is "active" or "disabled". Defaults to "active".
-statusbar
A boolean value. If true, the message will also be displayed in the status bar. Defaults to false.
-balloonposition
A list of preferred positions for the balloon relative to the mouse pointer. Defaults to "bottomright topright bottomleft topleft".
-postcommand
A callback command to be executed just before the balloon is displayed. The balloon message is passed to the callback.
-cancelcommand
A callback command to be executed when the balloon is cancelled (e.g., by pressing a button). The balloon message is passed to the callback.
-motioncommand
A callback command to be executed when the mouse pointer moves while the balloon is displayed. The balloon message is passed to the callback.

METHODS

attach(widget, -option => value, ...)
Attaches the specified widget to the balloon. The following options can be used to configure the balloon for this specific widget:
-balloonmsg
The argument is the message to be displayed in the balloon that will be popped up when the mouse pauses over this client. As with -statusmsg if this is not specified, then it takes its value from the -msg specification if any. If neither -balloonmsg nor -msg are specified, or they are the empty string then no balloon is popped up instead of an empty balloon. If you give it a scalar reference then it is dereferenced before being displayed. Useful if the postcommand is used to change the message.
-msg
The catch-all for -statusmsg and -balloonmsg. This is a convenient way of specifying the same message to be displayed in both the balloon and the status bar for the client.
-initwait
-state
-statusbar
-balloonposition
-postcommand
-cancelcommand
-motioncommand
These options allow you to override the balloon's default value for those option for some of the widgets it is attached to. It accepts the same values as above and will default to the Balloon's value.

detach(widget)

Detaches the specified widget from the help system.

destroy

Destroys the specified balloon.

ADVERTISED SUBWIDGETS

The balloon label is advertised as "message".

EXAMPLES

See the balloon demo included with the widget demo script that came with the distribution for examples on various ways to use balloons.

NOTES

Because of the overhead associated with each balloon you create (from tracking the mouse movement to know when to activate and deactivate them) you will see the best performance (low CPU consumption) if you create as few balloons as possible and attach them to as many widgets as you can. In other words, don't create a balloon for each widget you want to attach one to.

CAVEATS

Pressing any button will deactivate (cancel) the current balloon, if one exists. You can usually make the balloon reappear by moving the mouse a little. Creative use of the 3 command options can help you out also. If the mouse is over the balloon when a menu is unposted then the balloon will remain until you move off of it.

BUGS

If using balloons attached to listbox entries or canvas items in a scrolled widget, then the subwidget have to be used:

$balloon->attach($w->Subwidget("scrolled"), -msg => ...);
