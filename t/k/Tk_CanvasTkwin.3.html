الوصف

يتم استدعاء هذه الإجراءات من قبل مديري أنواع الـ canvas لأداء وظائف مساعدة مختلفة.

Tk_CanvasTkwin ترجع النافذة Tk_Window المرتبطة بـ canvas معين.

Tk_CanvasGetCoord تحول مواصفات سلسلة نصية للإحداثيات (مثل 2p أو 1.6c) إلى إحداثيات canvas ذات فاصلة عائمة مزدوجة. إذا كانت string وصفًا صالحًا للإحداثيات، فتقوم Tk_CanvasGetCoord بتخزين الإحداثيات المقابلة للـ canvas في *doublePtr وترجع TCL_OK. وإلا، فإنها تخزن رسالة خطأ في نتيجة المفسر وترجع TCL_ERROR.

يتم استدعاء Tk_CanvasDrawableCoords من قبل مديري الأنواع أثناء إعادة الرسم لحساب مكان رسم الأشياء. بالنظر إلى إحداثيات x و y في مساحة الـ canvas، تقوم Tk_CanvasDrawableCoords بحساب البكسل المقابل في الرسم الذي يتم استخدامه حاليًا لإعادة الرسم؛ وترجع تلك الإحداثيات في *drawableXPtr و *drawableYPtr. لا ينبغي استدعاء هذا الإجراء إلا أثناء إعادة الرسم.

يتم استخدام Tk_CanvasSetStippleOrigin أيضًا أثناء إعادة الرسم. يقوم بتعيين أصل التعبئة (stipple origin) في gc بحيث تكون التعبئات المرسومة باستخدام gc في خريطة البكسل (pixmap) خارج الشاشة الحالية متوافقة مع التعبئات المرسومة مع الأصل (0,0) في نافذة الـ canvas الفعلية. يلزم وجود Tk_CanvasSetStippleOrigin لضمان محاذاة أنماط التعبئة بشكل صحيح عند إعادة رسم الـ canvas على أجزاء صغيرة. يتم تنفيذ إعادة الرسم بطريقة التخزين المؤقت المزدوج حيث يتم إعادة رسم جزء من الـ canvas في خريطة بكسل خارج الشاشة ثم نسخه مرة أخرى إلى الشاشة. في هذا النهج، يجب تعديل أصول التعبئة في سياقات الرسم (graphics contexts) أثناء كل عملية إعادة رسم لتعويض موضع خريطة البكسل خارج الشاشة بالنسبة للنافذة. إذا كان العنصر يتم رسمه بالتعبئات، فعادةً ما يستدعي مدير النوع الخاص به Tk_CanvasSetStippleOrigin قبل استخدام gc لرسم شيء ما؛ بعد الانتهاء من الرسم، يستدعي مدير النوع XSetTSOrigin لاستعادة الأصل في gc مرة أخرى إلى (0,0) (الاستعادة مطلوبة لأن سياقات الرسم مشتركة، لذا لا يمكن تعديلها بشكل دائم).

Tk_CanvasWindowCoords مشابه لـ Tk_CanvasDrawableCoords باستثناء أنه يرجع إحداثيات في نافذة الـ canvas على الشاشة، بدلاً من إحداثيات في خريطة بكسل خارج الشاشة.

يمكن استدعاء Tk_CanvasEventuallyRedraw من قبل مدير النوع لإبلاغ Tk بأن جزءًا من الـ canvas يحتاج إلى إعادة رسم. تحدد الوسائط x1، y1، x2، و y2 المنطقة التي تحتاج إلى إعادة رسم، بإحداثيات الـ canvas. نادرًا ما يحتاج مديرو الأنواع إلى استدعاء Tk_CanvasEventuallyRedraw، حيث يمكن لـ Tk عادةً تحديد متى يتغير عنصر ما ويقوم بطلب إعادة الرسم نيابة عنه (يحدث هذا، على سبيل المثال، كلما استدعى Tk إجراء configureProc أو scaleProc). الوقت الوحيد الذي يحتاج فيه مدير النوع إلى استدعاء Tk_CanvasEventuallyRedraw هو إذا تغير عنصر ما من تلقاء نفسه دون استدعائه من خلال أحد الإجراءات في Tk_ItemType الخاص به؛ قد يحدث هذا، على سبيل المثال، في عنصر صورة إذا تم تعديل الصورة باستخدام أوامر الصور.

Tk_CanvasTagsParseProc و Tk_CanvasTagsPrintProc هي إجراءات تتعامل مع الخيار -tags لعناصر الـ canvas. لن يستدعي رمز مدير نوع الـ canvas هذه الإجراءات مباشرة، ولكنه سيستخدم عناوينها لإنشاء هيكل Tk_CustomOption للخيار -tags. عادةً ما يبدو الرمز كما يلي:

static const Tk_CustomOption tagsOption = {Tk_CanvasTagsParseProc,
    Tk_CanvasTagsPrintProc, NULL
};
static const Tk_ConfigSpec configSpecs[] = {
    ...
    {TK_CONFIG_CUSTOM, "-tags", NULL, NULL,
        NULL, 0, TK_CONFIG_NULL_OK, &tagsOption},
    ...
};

تزيين حزمة Arch Linux

ما هو تزيين الحزمة؟

تزيين الحزمة (Package Decorating) في Arch Linux هو مفهوم مفيد لتخصيص طريقة بناء الحزم ودمج التعديلات أو الإعدادات الإضافية دون الحاجة إلى تعديل ملف PKGBUILD الأصلي مباشرة. بدلاً من ذلك، تقوم بإنشاء ملف PKGBUILD جديد يقوم بتزيين الحزمة الأصلية.

لماذا قد تحتاج إلى تزيين حزمة؟

  • إضافة ميزات مخصصة: قد ترغب في تمكين ميزات غير ممكّنة افتراضيًا في الحزمة الأصلية.
  • تغيير خيارات البناء: قد تحتاج إلى تغيير خيارات الترجمة (compilation flags) أو الاعتماديات (dependencies).
  • تطبيق تعديلات (Patches): يمكنك تطبيق تعديلات خاصة بك على الكود قبل البناء.
  • تثبيت ملفات إضافية: قد ترغب في تضمين ملفات تكوين أو نصوص برمجية إضافية مع الحزمة.
  • فصل التخصيص عن الحزمة الأصلية: هذا يسهل تحديث الحزمة الأصلية دون فقدان التخصيصات الخاصة بك.

كيفية تزيين حزمة

الخطوة 1: الحصول على ملف PKGBUILD الأصلي

أولاً، تحتاج إلى الحصول على ملف PKGBUILD للحزمة التي تريد تزيينها. يمكنك القيام بذلك باستخدام `asp` أو بتحميله من مستودعات Arch Linux.

مثال باستخدام `asp`: 


# قم بتثبيت asp إذا لم يكن مثبتًا:
# sudo pacman -S asp

# استيراد ملف PKGBUILD للحزمة (مثال: firefox):
asp checkout firefox
cd firefox

الخطوة 2: إنشاء ملف PKGBUILD جديد للتزيين

داخل الدليل الذي يحتوي على ملف PKGBUILD الأصلي، قم بإنشاء ملف PKGBUILD جديد. سنفترض أن اسم الحزمة الأصلي هو `original-package` وأن ملف PKGBUILD الجديد الخاص بك سيكون `PKGBUILD.custom`.

محتوى `PKGBUILD.custom` (مثال): 


# اسم الحزمة المزيّنة
pkgname=original-package-custom
pkgver=X.Y.Z # استخدم نفس إصدار الحزمة الأصلية
pkgrel=1
pkgdesc="A custom decorated version of original-package"
arch=('x86_64') # أو حسب بنية الحزمة الأصلية
url="http://example.com/original-package"
license=('GPL') # أو حسب ترخيص الحزمة الأصلية
depends=('original-package') # اعتمد على الحزمة الأصلية المثبتة

# ملف PKGBUILD الأصلي الذي سنستخرجه منه
source=("${pkgname%-custom}-${pkgver}.tar.gz::https://www.archlinux.org/packages/community/x86_64/${pkgname%-custom}/download/")
# أو يمكنك سحب المصدر مباشرة من PKGBUILD الأصلي إذا كان متاحًا

# استخراج المصدر (هذه الخطوة قد تحتاج تعديل حسب كيفية بناء الحزمة الأصلية)
# يمكنك أن تجعلها تعتمد على تثبيت الحزمة الأصلية واستخدام ملفاتها

build() {
  cd "${srcdir}/${pkgname%-custom}-${pkgver}"

  # هنا يمكنك إضافة أو تعديل خيارات البناء
  # مثال: تفعيل ميزة معينة
  # ./configure --enable-my-feature ${LDFLAGS} ${CPPFLAGS}

  # إذا كنت تعتمد على الحزمة الأصلية المثبتة، قد لا تحتاج إلى إعادة البناء من المصدر
  # بدلاً من ذلك، يمكنك نسخ الملفات المعدلة إلى مكانها الصحيح
}

package() {
  # هذه هي أهم خطوة للتزيين
  # قم بتثبيت الحزمة الأصلية أولاً (إذا لم تكن مثبتة بالفعل)
  # يمكنك استخدام 'pacman -U' لتثبيت الحزمة الأصلية كاعتمادية في بيئة البناء
  # أو يمكنك استخدام 'make DESTDIR=${pkgdir} install' إذا كانت الحزمة تدعم ذلك

  # مثال: تثبيت الحزمة الأصلية ثم تعديلها
  # pacman -U --noconfirm --nodeps /path/to/original-package.pkg.tar.zst
  # cp -r "${srcdir}/my-custom-files" "${pkgdir}/usr/share/original-package/"

  # مثال آخر: نسخ ملفات معدلة
  # install -Dm755 "${srcdir}/my-custom-script.sh" "${pkgdir}/usr/bin/my-custom-script.sh"
  # install -Dm644 "${srcdir}/my-custom-config.conf" "${pkgdir}/etc/original-package/config.conf"
}

# قد تحتاج إلى تعديل قائمة الملفات إذا كنت تقوم بتغيير هيكل التثبيت
# package_original-package-custom() {
#   # ...
# }

# لإعادة استخدام وظائف البناء من PKGBUILD الأصلي:
# يمكنك استدعاء الوظائف مباشرة أو نسخها وتعديلها.
# طريقة أخرى هي استخلاص الحزمة الأصلية واستخدام ملفاتها.
# مثال:
# source=(
#   'https://www.archlinux.org/packages/community/x86_64/firefox/download/'
# )
# pkgdesc="Firefox with custom patches"
# pkgver=...
# _pkgver=${pkgver%%-*}
# _pkgrel=${pkgver#*-}
#
# build() {
#   tar xf "${srcdir}/${pkgname}-${pkgver}.pkg.tar.zst" -C "${srcdir}"
#   cd "${srcdir}/${pkgname}-${pkgver}"
#   # قم بتطبيق تعديلاتك هنا
#   patch -p1 < "${srcdir}/my-custom-patch.patch"
#   # إعادة بناء الحزمة (قد يكون معقدًا)
# }
#
# package() {
#   # قم بتثبيت الملفات من الدليل الذي قمت بتعديله
#   # ...
# }

شرح موجز للـ `PKGBUILD.custom`

  • pkgname: اسم الحزمة الجديدة (عادةً ما يضاف له لاحقة مثل `-custom`).
  • depends: يجب أن تعتمد هذه الحزمة على الحزمة الأصلية المثبتة.
  • source: هنا يمكنك تحديد مصدر الحزمة الأصلية أو الملفات الإضافية التي تريد تضمينها.
  • build(): هنا يتم تجميع الكود. يمكنك إضافة تعديلات (`patch`) أو تغيير خيارات البناء.
  • package(): هنا يتم تثبيت الملفات في الدليل النهائي للحزمة. هذه هي الخطوة الأساسية للتزيين، حيث يمكنك نسخ ملفات معدلة أو إضافة ملفات جديدة.

الخطوة 3: بناء الحزمة المزينة

بعد إنشاء `PKGBUILD.custom`، يمكنك بناء الحزمة باستخدام `makepkg`: 


makepkg -si

سيقوم هذا الأمر ببناء الحزمة وتثبيتها إذا نجح.

نصائح إضافية

  • استخدم `debtree` أو `pactree` لفهم الاعتماديات.
  • اختبر جيدًا بعد بناء الحزمة للتأكد من أن كل شيء يعمل كما هو متوقع.
  • انتبه إلى تحديثات الحزمة الأصلية. عندما يتم تحديث الحزمة الأصلية، قد تحتاج إلى تحديث ملف PKGBUILD المزخرف الخاص بك أيضًا.
  • احتفظ بملفات التزيين (مثل ملفات التعديل) في نفس الدليل الذي يحتوي على `PKGBUILD.custom`.
  • فكر في استخدام `build()` و `package()` بشكل منفصل. قد يكون من الأسهل نسخ الملفات من الحزمة الأصلية المثبتة بدلاً من إعادة بنائها من المصدر.

تزيين الحزمة يوفر مرونة كبيرة لمستخدمي Arch Linux لتخصيص نظامهم حسب احتياجاتهم.
