Tk_CreatePhotoImageFormat(3) إجراءات مكتبة Tk Tk_CreatePhotoImageFormat(3)

الاسم

Tk_CreatePhotoImageFormat - تعريف تنسيق ملف جديد للصور النقطية

الملخص

#include <tk.h>

Tk_CreatePhotoImageFormat(formatPtr)

المعاملات

const Tk_PhotoImageFormat *formatPtr (في)
بنية تحدد تنسيق الملف الجديد.

الوصف

يتم استدعاء Tk_CreatePhotoImageFormat لتحديد تنسيق ملف جديد لبيانات الصور للصور النقطية. يُطلق على الكود الذي ينفذ تنسيق ملف صور اسم معالج تنسيق ملف الصور، أو معالج للاختصار. تحتفظ شيفرة الصور النقطية بقائمة بالمعالجات التي يمكن استخدامها لقراءة وكتابة البيانات من أو إلى ملف. قد تدعم بعض المعالجات أيضًا قراءة بيانات الصور من سلسلة نصية أو تحويل بيانات الصور إلى تنسيق سلسلة نصية. يمكن للمستخدم تحديد المعالج الذي سيتم استخدامه باستخدام خيار تكوين الصورة -format أو الخيار -format إلى الأوامر الفرعية للصورة النقطية read و write.

يتكون معالج تنسيق ملف الصور من مجموعة من الإجراءات بالإضافة إلى بنية Tk_PhotoImageFormat، والتي تحتوي على اسم تنسيق ملف الصورة ومؤشرات إلى ستة إجراءات توفرها المعالج للتعامل مع الملفات والسلاسل النصية بهذا التنسيق. تحتوي بنية Tk_PhotoImageFormat على المجالات التالية:

typedef struct Tk_PhotoImageFormat {
    const char *name;
    Tk_ImageFileMatchProc *fileMatchProc;
    Tk_ImageStringMatchProc *stringMatchProc;
    Tk_ImageFileReadProc *fileReadProc;
    Tk_ImageStringReadProc *stringReadProc;
    Tk_ImageFileWriteProc *fileWriteProc;
    Tk_ImageStringWriteProc *stringWriteProc;
} Tk_PhotoImageFormat;

ليس من الضروري أن يوفر المعالج تطبيقات لجميع الإجراءات الستة. على سبيل المثال، لن يتم توفير الإجراءات التي تعالج بيانات السلاسل النصية لتنسيق يتم فيه تخزين بيانات الصورة في صيغة ثنائية، وقد تحتوي بالتالي على أحرف فارغة. إذا لم يتم تنفيذ أي إجراء، فيجب تعيين المؤشر المقابل في بنية Tk_PhotoImageFormat إلى NULL. يجب على المعالج توفير إجراء fileMatchProc إذا كان يوفر إجراء fileReadProc، وإجراء stringMatchProc إذا كان يوفر إجراء stringReadProc.

الاسم

formatPtr->name يوفر اسمًا لنوع الصورة. بمجرد أن تقوم Tk_CreatePhotoImageFormat بالإرجاع، يمكن استخدام هذا الاسم في خيار تكوين الصورة النقطية و خيار الأمر الفرعي -format. تصف صفحة الدليل للصورة النقطية (photo(n)) كيف يتم اختيار تنسيقات ملفات الصور بناءً على أسمائها والقيمة المعطاة للخيار -format. يجب ألا يكون الحرف الأول من formatPtr->name حرفًا أبجديًا كبيرًا من مجموعة أحرف ASCII (أي، أحد الأحرف A-Z). تُستخدم هذه الأسماء فقط لدعم الواجهة القديمة (انظر أدناه).

FILEMATCHPROC

formatPtr->fileMatchProc يوفر عنوان إجراء لاستدعائه بواسطة Tk عند البحث عن معالج تنسيق ملف صور مناسب لقراءة البيانات في ملف معين. يجب أن يتوافق formatPtr->fileMatchProc مع النموذج الأولي التالي:

typedef int Tk_ImageFileMatchProc(
        Tcl_Channel chan,
        const char *fileName,
        Tcl_Obj *format,
        int *widthPtr,
        int *heightPtr,
        Tcl_Interp *interp);
المعامل fileName هو اسم الملف الذي يحتوي على بيانات الصورة، والذي تم فتحه للقراءة كـ chan. يحتوي المعامل format على القيمة المعطاة للخيار -format، أو NULL إذا لم يتم تحديد الخيار. إذا بدت البيانات في الملف في التنسيق الذي يدعمه هذا المعالج، فيجب على إجراء formatPtr->fileMatchProc تخزين عرض وارتفاع الصورة في *widthPtr و *heightPtr على التوالي، وإرجاع 1. وإلا فيجب إرجاع 0.

STRINGMATCHPROC

formatPtr->stringMatchProc يوفر عنوان إجراء لاستدعائه بواسطة Tk عند البحث عن معالج تنسيق ملف صور مناسب لقراءة البيانات من سلسلة نصية معينة. يجب أن يتوافق formatPtr->stringMatchProc مع النموذج الأولي التالي:

typedef int Tk_ImageStringMatchProc(
        Tcl_Obj *data,
        Tcl_Obj *format,
        int *widthPtr,
        int *heightPtr,
        Tcl_Interp *interp);
يشير المعامل data إلى الكائن الذي يحتوي على بيانات الصورة. يحتوي المعامل format على القيمة المعطاة للخيار -format، أو NULL إذا لم يتم تحديد الخيار. إذا بدت البيانات في السلسلة النصية في التنسيق الذي يدعمه هذا المعالج، فيجب على إجراء formatPtr->stringMatchProc تخزين عرض وارتفاع الصورة في *widthPtr و *heightPtr على التوالي، وإرجاع 1. وإلا فيجب إرجاع 0.

FILEREADPROC

formatPtr->fileReadProc يوفر عنوان إجراء لاستدعائه بواسطة Tk لقراءة البيانات من ملف صورة إلى صورة نقطية. يجب أن يتوافق formatPtr->fileReadProc مع النموذج الأولي التالي:

typedef int Tk_ImageFileReadProc(
        Tcl_Interp *interp,
        Tcl_Channel chan,
        const char *fileName,
        Tcl_Obj *format,
        PhotoHandle imageHandle,
        int destX, int destY,
        int width, int height,
        int srcX, int srcY);
المعامل interp هو المفسر الذي تم فيه استدعاء الأمر لقراءة الصورة؛ ويجب استخدامه للإبلاغ عن الأخطاء. بيانات الصورة موجودة في الملف المسمى fileName، والذي تم فتحه للقراءة كـ chan. يحتوي المعامل format على القيمة المعطاة للخيار -format، أو NULL إذا لم يتم تحديد الخيار. يجب قراءة بيانات الصورة في الملف، أو صورة فرعية منها، إلى الصورة النقطية المحددة بواسطة المعالج imageHandle. الصورة الفرعية للبيانات في الملف هي بأبعاد width x height ولها الزاوية العلوية اليسرى عند الإحداثيات (srcX,srcY). يجب تخزينها في الصورة النقطية مع الزاوية العلوية اليسرى عند الإحداثيات (destX,destY) باستخدام الإجراء Tk_PhotoPutBlock. القيمة المرجعة هي قيمة إرجاع Tcl قياسية.

STRINGREADPROC

formatPtr->stringReadProc يوفر عنوان إجراء لاستدعائه بواسطة Tk لقراءة البيانات من سلسلة نصية إلى صورة نقطية. يجب أن يتوافق formatPtr->stringReadProc مع النموذج الأولي التالي:

typedef int Tk_ImageStringReadProc(
        Tcl_Interp *interp,
        Tcl_Obj *data,
        Tcl_Obj *format,
        PhotoHandle imageHandle,
        int destX, int destY,
        int width, int height,
        int srcX, int srcY);
المعامل interp هو المفسر الذي تم فيه استدعاء الأمر لقراءة الصورة؛ ويجب استخدامه للإبلاغ عن الأخطاء. يشير المعامل data إلى بيانات الصورة في شكل كائن. يحتوي المعامل format على القيمة المعطاة للخيار -format، أو NULL إذا لم يتم تحديد الخيار. يجب قراءة بيانات الصورة في السلسلة النصية، أو صورة فرعية منها، إلى الصورة النقطية المحددة بواسطة المعالج imageHandle. الصورة الفرعية للبيانات في السلسلة النصية هي بأبعاد width x height ولها الزاوية العلوية اليسرى عند الإحداثيات (srcX,srcY). يجب تخزينها في الصورة النقطية مع الزاوية العلوية اليسرى عند الإحداثيات (destX,destY) باستخدام الإجراء Tk_PhotoPutBlock. القيمة المرجعة هي قيمة إرجاع Tcl قياسية.

FILEWRITEPROC

formatPtr->fileWriteProc يوفر عنوان إجراء لاستدعائه بواسطة Tk لكتابة البيانات من صورة نقطية إلى ملف. يجب أن يتوافق formatPtr->fileWriteProc مع النموذج الأولي التالي:

typedef int Tk_ImageFileWriteProc(
        Tcl_Interp *interp,
        const char *fileName,
        Tcl_Obj *format,
        Tk_PhotoImageBlock *blockPtr);

Tk_CreatePhotoImageFormat(3) — Tk

NAME

Tk_CreatePhotoImageFormat — register a new image format

SYNOPSIS

#include <tk.h>
int
Tk_CreatePhotoImageFormat(
        Tk_PhotoImageFormat *formatPtr);

ARGUMENTS

Tk_PhotoImageFormat * formatPtr
Pointer to a structure describing the new image format. This structure must be filled in before calling this function.

DESCRIPTION

The Tk_CreatePhotoImageFormat function is used to register a new image format with the Tk photo image facility. Tk applications can then use this format to read and write images. The formatPtr argument points to a Tk_PhotoImageFormat structure that describes the new format. This structure must be filled in before calling this function.

The Tk_PhotoImageFormat structure has the following definition:

typedef struct Tk_PhotoImageFormat {
    const char *name;
    Tk_ImageFileMatchProc *fileMatchProc;
    Tk_ImageFileReadProc *fileReadProc;
    Tk_ImageStringWriteProc *stringWriteProc;
    Tk_ImageCmdProc *imageCmdProc;
    ClientData clientData;
    Tk_ImageFreeProc *freeProc;
} Tk_PhotoImageFormat;
name
The name of the image format, e.g. "gif" or "jpeg". This is the value that will be used with the -format option of the image create photo command.
fileMatchProc
Procedure to call to determine if a file matches this format. The prototype is:
typedef int Tk_ImageFileMatchProc(
        Tcl_Interp *interp,
        const char *fileName,
        const unsigned char *data,
        size_t dataSize);
This procedure is given a file name and the first dataSize bytes from the file. It should return 1 if the file is likely to be of this format, and 0 otherwise. The interp argument is the interpreter in which the command was invoked, and can be used for reporting errors.
fileReadProc
Procedure to call to read an image from a file. The prototype is:
typedef int Tk_ImageFileReadProc(
        Tcl_Interp *interp,
        const char *fileName,
        const Tk_PhotoImageFormat *formatPtr,
        Tk_PhotoImageBlock *blockPtr);
This procedure is given the name of the file to read, the format structure for this format, and a pointer to a Tk_PhotoImageBlock structure. It should fill the Tk_PhotoImageBlock structure with information about the image, including its width, height, pixels, and the number of bits per pixel. It should allocate memory for the pixel data itself and return a pointer to it via blockPtr->pixelData. The caller is responsible for freeing this memory later. The return value is a standard Tcl return value. See the manual page FindPhoto(3) for details on Tk_PhotoImageBlock.
stringWriteProc
Procedure to call to write an image to a string. The prototype is:
typedef int Tk_ImageStringWriteProc(
        Tcl_Interp *interp,
        Tcl_Obj *format,
        Tk_PhotoImageBlock *blockPtr);
This procedure is given the interpreter, the format string from the -format option, and a pointer to a Tk_PhotoImageBlock structure. It should write the image data to the interpreter result in the specified format. The return value is a standard Tcl return value.
imageCmdProc
Procedure to call to handle commands related to this image format. This is only used for image types that are implemented as Tcl commands, not for file-based image formats. The prototype is:
typedef int Tk_ImageCmdProc(
        ClientData clientData,
        Tcl_Interp *interp,
        int argc,
        const char *argv[]);
This procedure is called when a command is invoked for an image of this type. The clientData is the value from the clientData field of the Tk_PhotoImageFormat structure. The remaining arguments are similar to those for a Tcl command procedure.
clientData
Arbitrary client data to be passed to the imageCmdProc. Usually used to pass a pointer to the image data structure.
freeProc
Procedure to call to free the clientData when the image is destroyed. The prototype is:
typedef void Tk_ImageFreeProc(
        ClientData clientData);

The Tk_CreatePhotoImageFormat function returns a standard Tcl return value. If the format is successfully registered, it returns TCL_OK. If there is an error (e.g., the name is already registered), it returns TCL_ERROR and leaves an error message in the interpreter's result.

Note that the fileReadProc and stringWriteProc pointers within the Tk_PhotoImageFormat structure can be NULL if the format does not support reading from files or writing to strings, respectively. Similarly, fileMatchProc and imageCmdProc can be NULL.

The Tk_PhotoImageFormat structure is copied by Tk, so the caller does not need to keep it around after this function returns.

FILEMATCHPROC

formatPtr->fileMatchProc provides the address of a procedure for Tk to call to determine if a given file is of this image format. See the description of the Tk_PhotoImageFormat structure above for the prototype.

FILEREADPROC

formatPtr->fileReadProc provides the address of a procedure for Tk to call to read an image from a file. See the description of the Tk_PhotoImageFormat structure above for the prototype.

The interp argument is the interpreter in which the command was invoked to read the image; it should be used for reporting errors. The image data to be read are in memory and are described by the Tk_PhotoImageBlock structure pointed to by blockPtr; see the manual page FindPhoto(3) for details. The fileName argument points to the string giving the name of the file to read. The formatPtr argument points to the format structure for this image type. The return value is a standard Tcl return value.

STRINGWRITEPROC

formatPtr->stringWriteProc provides the address of a procedure for Tk to call to translate image data from a photo image into a string. See the description of the Tk_PhotoImageFormat structure above for the prototype.

The interp argument is the interpreter in which the command was invoked to convert the image; it should be used for reporting errors. The image data to be converted are in memory and are described by the Tk_PhotoImageBlock structure pointed to by blockPtr; see the manual page FindPhoto(3) for details. The data for the string should be put in the interpreter interp result. The format argument contains the value given for the -format option, or NULL if the option was not specified. The format string can contain extra characters after the name of the format. If appropriate, the formatPtr->stringWriteProc procedure may interpret these characters to specify further details about the image file. The return value is a standard Tcl return value.

FILEWRITEPROC

The Tk_PhotoImageFormat structure also contains a fileWriteProc field for writing images to files. This field is not documented here, as it is not part of the public interface.

typedef int Tk_ImageFileWriteProc(
        Tcl_Interp *interp,
        const char *fileName,
        const Tk_PhotoImageFormat *formatPtr,
        Tk_PhotoImageBlock *blockPtr);

The interp argument is the interpreter in which the command was invoked to write the image; it should be used for reporting errors. The image data to be written are in memory and are described by the Tk_PhotoImageBlock structure pointed to by blockPtr; see the manual page FindPhoto(3) for details. The fileName argument points to the string giving the name of the file in which to write the image data. The format argument contains the value given for the -format option, or NULL if the option was not specified. The format string can contain extra characters after the name of the format. If appropriate, the formatPtr->fileWriteProc procedure may interpret these characters to specify further details about the image file. The return value is a standard Tcl return value.

LEGACY INTERFACE SUPPORT

In Tk 8.2 and earlier, the definition of all the function pointer types stored in fields of a Tk_PhotoImageFormat struct were incompatibly different. Legacy programs and libraries dating from those days may still contain code that defines extended Tk photo image formats using the old interface. The Tk header file will still support this legacy interface if the code is compiled with the macro USE_OLD_IMAGE defined. Alternatively, the legacy interfaces are used if the first character of formatPtr->name is an uppercase ASCII character (A-Z), and explicit casts are used to forgive the type mismatch. For example,

static Tk_PhotoImageFormat myFormat = {
    "MyFormat",
    (Tk_ImageFileMatchProc *) FileMatch,
    NULL,
    (Tk_ImageFileReadProc *) FileRead,
    NULL,
    NULL,
    NULL
};

would define a minimal Tk_PhotoImageFormat that operates provide only file reading capability, where FileMatch and FileRead are written according to the legacy interfaces of Tk 8.2 or earlier.

Any stub-enabled extension providing an extended photo image format via the legacy interface enabled by the USE_OLD_IMAGE macro that is compiled against Tk 8.5 headers and linked against the Tk 8.5 stub library will produce a file that can be loaded only into interps with Tk 8.5 or later; that is, the normal stub-compatibility rules. If a developer needs to generate from such code a file that is loadable into interps with Tk 8.4 or earlier, they must use Tk 8.4 headers and stub libraries to do so.

Any new code written today should not make use of the legacy interfaces. Expect their support to go away in Tk 9.
