Toplevel(3) توثيق Perl المساهم به من قبل المستخدم Toplevel(3)

الاسم

Tk::Toplevel - إنشاء ومعالجة أدوات Toplevel

الملخص

    $toplevel = $parent->Toplevel(?خيارات?);

الخيارات القياسية

-borderwidth -highlightbackground -highlightthickness -takefocus -class -highlightcolor -relief -cursor

راجع Tk::options لتفاصيل الخيارات القياسية.

الخيارات الخاصة بالأداة

الاسم: background
الفئة: Background
المفتاح: -background
هذا الخيار هو نفس الخيار القياسي background باستثناء أنه يمكن تحديد قيمته أيضًا على أنها قيمة غير معرفة. في هذه الحالة، لن تعرض الأداة أي خلفية أو حدود، ولن يتم استهلاك أي ألوان من خريطة الألوان الخاصة بها للخلفية والحدود.
الاسم: colormap
الفئة: Colormap
المفتاح: -colormap
يحدد خريطة ألوان لاستخدامها في النافذة. يمكن أن تكون القيمة إما new، وفي هذه الحالة يتم إنشاء خريطة ألوان جديدة للنافذة وأبنائها، أو اسم نافذة أخرى (يجب أن تكون على نفس الشاشة ولها نفس العرض مثل $widget)، وفي هذه الحالة ستستخدم النافذة الجديدة خريطة الألوان من النافذة المحددة. إذا لم يتم تحديد خيار colormap، فستستخدم النافذة الجديدة خريطة الألوان الافتراضية للشاشة الخاصة بها. لا يمكن تغيير هذا الخيار باستخدام طريقة configure.
الاسم: container
الفئة: Container
المفتاح: -container
يجب أن تكون القيمة منطقية. إذا كانت صحيحة، فهذا يعني أن هذه النافذة سيتم استخدامها كحاوية سيتم فيها تضمين تطبيق آخر (على سبيل المثال، يمكن تضمين Tk toplevel باستخدام الخيار -use). ستدعم النافذة بروتوكولات مدير النوافذ المناسبة لأشياء مثل طلبات الهندسة. لا يجب أن يكون للنافذة أي أبناء خاصة بها في هذا التطبيق. لا يمكن تغيير هذا الخيار باستخدام طريقة configure.
الاسم: height
الفئة: Height
المفتاح: -height
يحدد الارتفاع المطلوب للنافذة بأي شكل من الأشكال المقبولة بواسطة Tk_GetPixels. إذا كان هذا الخيار أقل من أو يساوي الصفر، فلن تطلب النافذة أي حجم على الإطلاق.
الاسم: menu
الفئة: Menu
المفتاح: -menu
يحدد أداة قائمة لاستخدامها كشريط قوائم. في ماكنتوش، سيتم عرض شريط القوائم عبر الجزء العلوي من الشاشة الرئيسية. على أنظمة Microsoft Windows وجميع منصات UNIX، ستظهر القائمة عبر نافذة toplevel كجزء من تزيين النافذة الذي يحتفظ به مدير النوافذ.
الاسم: ""
الفئة: ""
المفتاح: -screen
يحدد الشاشة التي سيتم وضع النافذة الجديدة عليها. يمكن استخدام أي اسم شاشة صالح، حتى اسم مرتبط بشاشة مختلفة. الافتراضي هو نفس الشاشة مثل الأصل. هذا الخيار خاص لأنه لا يمكن تحديده من خلال قاعدة بيانات الخيارات، ولا يمكن تعديله باستخدام طريقة configure.
المفتاح: -title
يحدد عنوان نافذة toplevel.
الاسم: use
الفئة: Use
المفتاح: -use
يستخدم هذا الخيار للتضمين. إذا لم تكن القيمة سلسلة فارغة، فيجب أن تكون معرف النافذة لنافذة حاوية، محددة كسلسلة سداسية عشرية مثل تلك التي يتم إرجاعها بواسطة الأمر winfo id. سيتم إنشاء أداة toplevel كابن للحاوية المحددة بدلاً من النافذة الجذر للشاشة. إذا كانت النافذة الحاوية في تطبيق Tk، فيجب أن تكون إطارًا أو أداة toplevel تم تحديد الخيار -container لها. لا يمكن تغيير هذا الخيار باستخدام طريقة configure.
الاسم: visual
الفئة: Visual
المفتاح: -visual
يحدد معلومات مرئية للنافذة الجديدة بأي من الأشكال التي تقبلها Tk_GetVisual. إذا لم يتم تحديد هذا الخيار، فستستخدم النافذة الجديدة العرض الافتراضي لشاشتها. لا يمكن تعديل خيار visual باستخدام طريقة configure.
الاسم: width
الفئة: Width
المفتاح: -width
يحدد العرض المطلوب للنافذة بأي شكل من الأشكال المقبولة بواسطة Tk_GetPixels. إذا كان هذا الخيار أقل من أو يساوي الصفر، فلن تطلب النافذة أي حجم على الإطلاق.

الوصف

تقوم طريقة Toplevel بإنشاء أداة toplevel جديدة (المحددة بواسطة الوسيط $widget). يمكن تحديد خيارات إضافية، موضحة أعلاه، في سطر الأوامر أو في قاعدة بيانات الخيارات لتكوين جوانب من toplevel مثل لون الخلفية والتخفيف. تعيد طريقة toplevel اسم المسار للنافذة الجديدة.

تتشابه toplevel مع الإطار باستثناء أنه يتم إنشاؤها كنافذة top-level: الأصل X الخاص بها هو النافذة الجذر للشاشة بدلاً من الأصل المنطقي من مسارها. الغرض الرئيسي من toplevel هو أن تكون بمثابة حاوية لصناديق الحوار ومجموعات الأدوات الأخرى. الميزات المرئية الوحيدة لـ toplevel هي لون خلفيتها وحد حدود اختياري ثلاثي الأبعاد لجعل toplevel يبدو مرتفعًا أو غائرًا.

طرق الأدوات

تقوم طريقة Toplevel بإنشاء كائن أداة. يدعم هذا الكائن طريقتي configure و cget الموصوفتين في Tk::options، والتي يمكن استخدامها للاستعلام عن الخيارات الموصوفة أعلاه وتعديلها. ترث الأداة أيضًا جميع الطرق التي توفرها الفئة العامة Tk::Widget، والفئة Tk::Wm.

الربط

عند إنشاء toplevel جديد، لا يحتوي على ربطات أحداث افتراضية: لا يُقصد أن تكون toplevels تفاعلية.

NAME

Tk::Toplevel - create and manage a toplevel window

SYNOPSIS

use Tk;
use Tk::Toplevel;

my $mw = MainWindow->new;
my $tl = $mw->Toplevel;
$tl->title("My Toplevel Window");
$tl->geometry("+50+100");

# ... add widgets to $tl ...

MainLoop;

STANDARD OPTIONS

Toplevel supports the standard Tk options.

WIDGET-SPECIFIC OPTIONS

-borderwidth, -bd
Specifies the width of the border around the toplevel window. Default is 0.
-colormap
Specifies the colormap to use for the window. Default is the colormap of the parent window.
-container
Specifies whether the toplevel window should act as a container for other windows. If true, it prevents the window manager from drawing decorations around the window.
-cursor
Specifies the cursor to display when the mouse is over the toplevel window.
-height
Specifies the height of the toplevel window in screen units.
-highlightbackground
Specifies the color of the highlight rectangle when the toplevel window does not have focus.
-highlightcolor
Specifies the color of the highlight rectangle when the toplevel window has focus.
-highlightthickness
Specifies the thickness of the highlight rectangle. Default is 0.
-menu
Specifies the menu bar to be associated with the toplevel window.
-relief
Specifies the relief style of the border. Can be flat, groove, raised, ridge, or sunken. Default is flat.
-screen
Specifies the screen on which to create the toplevel window.
-use
Specifies the window ID of an existing window to use as the toplevel window.
-width
Specifies the width of the toplevel window in screen units.

DESCRIPTION

The Toplevel command creates a new toplevel window. Toplevel windows are independent windows that can be used to create dialog boxes, pop-up menus, and other secondary windows.

The new toplevel window is created as a child of the specified parent window. If no parent is specified, it is created as a child of the main window.

The Toplevel command returns a reference to the newly created toplevel window object.

WIDGET METHODS

The following methods are supported for Toplevel widgets:

  • <widget>->Withdraw: Hides the toplevel window without destroying it.
  • <widget>->Deiconify: Makes a withdrawn toplevel window visible again.
  • <widget>->Iconify: Requests the window manager to iconify the toplevel window.
  • <widget>->State: Returns the current state of the toplevel window (normal, iconified, or withdrawn).
  • <widget>->TransientFor(otherWindow): Specifies that this toplevel window is transient for otherWindow. This is typically used for dialog boxes.

BINDINGS

Toplevel windows support the following bindings:

  • <Destroy>: Triggered when the toplevel window is destroyed.
