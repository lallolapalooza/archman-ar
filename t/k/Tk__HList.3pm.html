الوصف

تقوم الطريقة HList بإنشاء نافذة جديدة (يحددها الوسيط $widget) وتحويلها إلى عنصر HList. قد يتم تحديد خيارات إضافية، موصوفة أعلاه، في سطر الأوامر أو في قاعدة بيانات الخيارات لتكوين جوانب عنصر HList مثل المؤشر والإغاثة.

يمكن استخدام عنصر HList لعرض أي بيانات لها هيكل هرمي، على سبيل المثال، أشجار دليل نظام الملفات. يتم ضبط إدخالات القائمة وتوصيلها بخطوط فروع وفقًا لمكانها في الهرمية.

يتم تحديد كل إدخال قائمة بواسطة entryPath. entryPath هي سلسلة من أسماء الإدخالات مفصولة بحرف الفاصل (يحدده الخيار -separator). يمكن أن يكون اسم الإدخال أي سلسلة لا تحتوي على حرف الفاصل، أو يمكن أن تكون سلسلة تحتوي على حرف فاصل واحد فقط.

على سبيل المثال، عند استخدام "." كحرف فاصل، فإن "one.two.three" هو entryPath لإدخال قائمة يكون الوالد له هو "one.two"، والذي يكون الوالد له هو "one"، وهو إدخال مستوى علوي (ليس له آباء).

أمثلة أخرى: ".two.three" هو entryPath لإدخال قائمة يكون الوالد له هو ".two"، والذي يكون الوالد له هو "."، وهو إدخال مستوى علوي.

عناصر العرض

يرتبط كل إدخال قائمة في عنصر HList بعنصر عرض. يحدد عنصر العرض المعلومات المرئية التي يجب عرضها لهذا الإدخال القائمة. يرجى الاطلاع على Tk::DItem للحصول على قائمة بجميع عناصر العرض. عندما يتم إنشاء إدخال قائمة بواسطة طرق العنصر itemCreate أو add أو addchild، يتم تحديد نوع عنصر العرض الخاص به بواسطة الخيار -itemtype الذي تم تمريره إلى هذه الطرق. إذا تم حذف -itemtype، فسيتم استخدام نوع عنصر HList المحدد بواسطة خيار -itemtype لهذا العنصر افتراضيًا.

طرق العناصر

تقوم الطريقة HList بإنشاء كائن عنصر. يدعم هذا الكائن طريقتي configure و cget الموصوفتين في Tk::options، والتي يمكن استخدامها للاستفسار عن الخيارات الموصوفة أعلاه وتعديلها. يرث العنصر أيضًا جميع الطرق التي توفرها فئة Tk::Widget العامة.

تتوفر الطرق الإضافية التالية لعناصر HList:

$hlist->add($entryPath ?,option=>value, ...?)
ينشئ إدخال قائمة جديدًا بالمسار $entryPath. يجب إنشاء إدخال قائمة بعد إنشاء والده (ما لم يكن هذا الإدخال إدخالاً على مستوى أعلى، والذي ليس له والد). انظر أيضًا "BUGS" أدناه. تُرجع هذه الطريقة entryPath لإدخال القائمة الذي تم إنشاؤه حديثًا. يمكن تقديم خيارات التكوين التالية لتكوين إدخال القائمة:
-at => position
إدراج القائمة الجديدة في الموضع المحدد بواسطة position. يجب أن يكون position عددًا صحيحًا صالحًا. يشير الموضع 0 إلى الموضع الأول، ويشير 1 إلى الموضع الثاني، وهكذا.
-after => afterWhich
إدراج إدخال القائمة الجديد بعد الإدخال المحدد بواسطة afterWhich. يجب أن يكون afterWhich إدخال قائمة صالحًا ويجب أن يكون له نفس والد إدخال القائمة الجديد.
-before => beforeWhich
إدراج إدخال القائمة الجديد قبل الإدخال المحدد بواسطة beforeWhich. يجب أن يكون beforeWhich إدخال قائمة صالحًا ويجب أن يكون له نفس والد إدخال القائمة الجديد.
-data => string
يحدد سلسلة لربطها بهذا الإدخال القائمة. يمكن الاستعلام عن هذه السلسلة بواسطة الطريقة info. يمكن لبرنامج التطبيق استخدام الخيار -data لربط إدخال القائمة بالبيانات التي يمثلها.
-itemtype => type
يحدد نوع عنصر العرض الذي سيتم عرضه لإدخال القائمة الجديد. يجب أن يكون type نوع عنصر عرض صالحًا. حاليًا، أنواع عناصر العرض المتاحة هي imagetext، text، و $widget. إذا لم يتم تحديد هذا الخيار، فسيتم استخدام النوع المحدد بواسطة خيار -itemtype لعنصر HList هذا افتراضيًا.
-state => state
يحدد ما إذا كان يمكن تحديد هذا الإدخال أو استدعاؤه بواسطة المستخدم. يجب أن يكون إما normal أو disabled.

تقبل الطريقة add خيارات تكوين إضافية لتكوين عنصر العرض المرتبط بهذا الإدخال القائمة. تعتمد مجموعة خيارات التكوين الإضافية على نوع عنصر العرض المحدد بواسطة الخيار -itemtype. يرجى الاطلاع على Tk::DItem للحصول على قائمة بخيارات التكوين لكل نوع من أنواع عناصر العرض.

$hlist->addchild($parentPath, ?option, value, ..., ?)
يضيف إدخال ابن جديد إلى قائمة الأبناء لإدخال القائمة المحدد بواسطة $parentPath. أو، إذا تم تعيين $parentPath لتكون سلسلة فارغة، فإنه ينشئ إدخالاً جديدًا على مستوى أعلى. سيكون اسم إدخال القائمة الجديد اسمًا فريدًا يتم إنشاؤه تلقائيًا بواسطة عنصر HList. عادةً، إذا كان $parentPath هو foo، فإن entryPath للإدخال الجديد سيكون foo.0، foo.1، ... إلخ. تُرجع هذه الطريقة entryPath لإدخال القائمة الذي تم إنشاؤه حديثًا. يمكن أن يكون option أي خيار للطريقة add. انظر أيضًا "BUGS" أدناه.
$hlist->anchorSet($entryPath)
يضبط المرسى على إدخال القائمة المحدد بواسطة $entryPath. المرسى هو نهاية التحديد الذي يتم تثبيته أثناء قيام المستخدم بسحب تحديد بالفأرة.
$hlist->anchorClear
يزيل المرسى، إن وجد، من عنصر HList هذا. هذا يزيل فقط التمييزات المحيطة بإدخال المرسى ولا يؤثر على حالة تحديده.
$hlist->columnWidth($col?, -char?, ?width?)
يستعلم عن عرض العمود $col في عنصر HList أو يضبطه. قيمة $col تبدأ من الصفر: 0 يمثل العمود الأول، 1 يمثل العمود الثاني، وهكذا. إذا لم يتم تقديم معلمات إضافية، فستُرجع العرض الحالي لهذا العمود (بالبكسل). يمكن تقديم معلمات إضافية لضبط عرض هذا العمود:
$hlist->columnWidth($col, '')
تشير سلسلة فارغة إلى أن عرض العمود يجب أن يكون واسعًا بما يكفي لعرض أوسع عنصر في هذا العمود. في هذه الحالة، قد يتغير عرض هذا العمود نتيجة لتغير أحجام العناصر في هذا العمود.
$hlist->columnWidth($col, width)
يجب أن يكون width بتنسيق مقبول بواسطة Tk_GetPixels.
$hlist->columnWidth($col, -char, nChars)
يتم ضبط العرض ليكون متوسط العرض الذي تشغله nChars رمزًا من الخط المحدد بواسطة خيار -font لعنصر HList هذا.
$hlist->delete(option, $entryPath)
حذف إدخال قائمة واحد أو أكثر. قد يكون option أحد الخيارات التالية:
all
حذف جميع الإدخالات في HList. في هذه الحالة، لا يلزم تحديد $entryPath.
entry
حذف الإدخال المحدد بواسطة $entryPath وجميع ذرياته، إن وجدت.
offsprings
حذف جميع الذريات، إن وجدت، للإدخال المحدد بواسطة $entryPath. ومع ذلك، فإن $entryPath نفسه لا يتم حذفه.
siblings
حذف جميع إدخالات القائمة التي تشترك في نفس الوالد مع الإدخال المحدد بواسطة $entryPath. ومع ذلك، فإن $entryPath نفسه لا يتم حذفه.
$hlist->dragsiteSet($entryPath)
يضبط موقع السحب على إدخال القائمة المحدد بواسطة $entryPath. يستخدم موقع السحب للإشارة إلى مصدر إجراء السحب والإفلات. حاليًا، لم يتم تنفيذ وظيفة السحب والإفلات في Tix بعد.
$hlist->dragsiteClear
إزالة موقع السحب، إن وجد، من عنصر HList هذا. هذا يزيل فقط التمييزات المحيطة بإدخال موقع السحب ولا يؤثر على حالة تحديده.
$hlist->dropsiteSet($entryPath)

STANDARD OPTIONS

The Tk::HList widget supports the standard Tk options: -background, -borderwidth, -cursor, -disabledforeground, -font, -foreground, -height, -highlightbackground, -highlightcolor, -highlightthickness, -label, -padx, -pady, -relief, -takefocus, -width, and the standard Tk bindings.

WIDGET-SPECIFIC OPTIONS

-browsecmd ?command?
Specifies a command to be called whenever the highlighted item(s) change. The command is called with one argument, the path of the highlighted item. This is only called if the -selectmode is "browse" or "single". For other select modes, see the BINDINGS section.
-command ?command?
Specifies a command to be called whenever the user double-clicks on an item. The command is called with one argument, the path of the item double-clicked.
-columns ?number?
Specifies the number of columns in the HList. Defaults to 1.
-decrement ?boolean?
If true, the numbering of the list entries starts from 1. Otherwise, it starts from 0. Defaults to false.
-itemtype ?type?
Specifies the type of items in the listbox. Defaults to "text".
-padx ?amount?
Specifies the amount of extra padding to add to the left and right of each item. Defaults to 0.
-pady ?amount?
Specifies the amount of extra padding to add to the top and bottom of each item. Defaults to 0.
-postcmd ?command?
Specifies a command to be called when an item is about to be expanded. The command is called with one argument, the path of the item to be expanded.
-selectbackground ?color?
Specifies the background color to use for selected items. Defaults to the system default.
-selectborderwidth ?amount?
Specifies the borderwidth for selected items. Defaults to 0.
-selectforeground ?color?
Specifies the foreground color to use for selected items. Defaults to the system default.
-selectmode ?mode?
Specifies how items can be selected. Defaults to "browse". Possible values are:
browse
Only one item can be selected at a time. Selecting a new item automatically deselects the previously selected item. The -browsecmd is called when the selection changes.
single
Only one item can be selected at a time. Selecting a new item automatically deselects the previously selected item. The -browsecmd is called when the selection changes. The item is only highlighted when the mouse button is released.
multiple
Multiple items can be selected. The -browsecmd is called whenever the selection changes.
extended
Multiple items can be selected, and the user can select ranges of items using the Shift key. The -browsecmd is called whenever the selection changes.
-separator ?char?
Specifies the separator character to use for creating hierarchical paths. Defaults to ".".
-show ?boolean?
If true, all items are initially shown. Otherwise, only top-level items are shown. Defaults to false.
-state ?state?
Specifies the state of the widget, which can be normal or disabled.
- ?data?
An arbitrary scalar value that can be associated with the widget.
- ?tags?
A list of tags associated with the widget.

DESCRIPTION

The Tk::HList widget displays a list of items, each of which can have children, forming a hierarchical structure. The widget supports multiple columns, allowing for the display of related information for each item.

DISPLAY ITEMS

Each item in the HList is identified by a unique path. Paths are strings that specify the item's position in the hierarchy. For example, if the separator character is ".", then "1.2.3" refers to the third item in the second child list of the first top-level item.

Items can be added using the add, addchild, and addgroup methods. The add method adds an item at the top level or as a child of an existing item. The addchild method is a shortcut for adding a child item. The addgroup method is similar to addchild but creates a group item that can be expanded or collapsed.

Items can display text, bitmaps, or images. They can also have different colors, fonts, and padding settings.

-text

-data

-state

-open

-tags

$hlist->entryconfigure($path, %options)
Modifies the options for the item specified by $path.
$hlist->exists($path)

$hlist->focus($path)

$hlist->get($path)

$hlist->index($path)
Returns the numerical index of the item specified by $path.

$hlist->move($path, $newParentPath)
Moves the item specified by $path to become a child of $newParentPath.

Forces the expansion of the item specified by $path. The -postcmd callback is called.

Scrolls the list so that the item specified by $path is visible.
$hlist->selection($option, $path, ...)
Manages the selection of items. $option can be:

Clears the selection.
exists

Returns true if the specified item is selected.

$hlist->yview()
Returns a list containing two elements, both of which are real fractions between 0 and 1. The first element gives the position of the list element at the top of the window, relative to the HList as a whole (0.5 means it is halfway through the HList, for example). The second element gives the position of the list entry just after the last one in the window, relative to the HList as a whole. These are the same values passed to scrollbars via the -yscrollcommand option.

Adjusts the view in the window so that the list entry given by $entryPath is displayed at the top of the window.
$hlist->yview(moveto => fraction)
Adjusts the view in the window so that the list entry given by fraction appears at the top of the window. Fraction is a fraction between 0 and 1; 0 indicates the first entry in the HList, 0.33 indicates the entry one-third the way through the HList, and so on.

This method adjust the view in the window up or down according to number and what. Number must be an integer. What must be either units or pages. If what is units, the view adjusts up or down by number lines; if it is pages then the view adjusts by number screenfuls. If number is negative then earlier entries become visible; if it is positive then later entries become visible.

BINDINGS

[1]
If the -selectmode is "browse", when the user drags the mouse pointer over the list entries, the entry under the pointer will be highlighted and the -browsecmd callback will be called with one parameter, the entryPath of the highlighted entry. Only one entry can be highlighted at a time. The -command callback will be called when the user double-clicks on a list entry.
[2]
If the -selectmode is "single", the entries will only be highlighted by mouse <ButtonRelease-1> events. When a new list entry is highlighted, the -browsecmd callback will be called with one parameter indicating the highlighted list entry. The -command callback will be called when the user double-clicks on a list entry.
[3]
If the -selectmode is "multiple", when the user drags the mouse pointer over the list entries, all the entries under the pointer will be highlighted. However, only a contiguous region of list entries can be selected. When the highlighted area is changed, the -browsecmd callback will be called with an undefined parameter. It is the responsibility of the -browsecmd callback to find out the exact highlighted selection in the HList. The -command callback will be called when the user double-clicks on a list entry.
[4]
If the -selectmode is "extended", when the user drags the mouse pointer over the list entries, all the entries under the pointer will be highlighted. The user can also make disjointed selections using <Control-ButtonPress-1>. When the highlighted area is changed, the -browsecmd callback will be called with an undefined parameter. It is the responsibility of the -browsecmd callback to find out the exact highlighted selection in the HList. The -command callback will be called when the user double-clicks on a list entry.
[5]
Arrow key bindings: <Up> arrow key moves the anchor point to the item right on top of the current anchor item. <Down> arrow key moves the anchor point to the item right below the current anchor item. <Left> arrow key moves the anchor to the parent item of the current anchor item. <Right> moves the anchor to the first child of the current anchor item. If the current anchor item does not have any children, moves the anchor to the item right below the current anchor item.

EXAMPLE

This example demonstrates how to use an HList to store a file directory structure and respond to the user's browse events:

use strict;
use Tk;
use Tk::Label;
use Tk::HList;
my $mw = MainWindow->new();
my $label = $mw->Label(-width=>15);
my $hlist = $mw->HList(
                    -itemtype   => 'text',
                    -separator  => '/',
                    -selectmode => 'single',
                    -browsecmd  => sub {
                              my $file = shift;
                              $label->configure(-text=>$file);
                           }
                    );
foreach ( qw(/ /home /home/ioi /home/foo /usr /usr/lib) ) {
    $hlist->add($_, -text=>$_);
}
$hlist->pack;
$label->pack;
MainLoop;

BUGS

The fact that the display item at column 0 is implicitly associated with the whole entry is probably a design bug. This was done for backward compatibility purposes. The result is that there is a large overlap between the item method and the add, addchild, entrycget and entryconfigure methods. Whenever multiple columns exist, the programmer should use ONLY the item method to create and configure the display items in each column; the add, addchild, entrycget and entryconfigure should be used ONLY to create and configure entries.
