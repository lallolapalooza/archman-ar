Tk_ConfigureWidget(3)

الحزمة: tk

التراخيص: TCL

Tk_ConfigureWidget(3) إجراءات مكتبة Tk Tk_ConfigureWidget(3)

الاسم

Tk_ConfigureWidget, Tk_ConfigureInfo, Tk_ConfigureValue, Tk_FreeOptions - معالجة خيارات التهيئة للأدوات (widgets)

الملخص

#include <tk.h>

int
Tk_ConfigureWidget(interp, tkwin, specs, argc, argv, widgRec, flags)

int
Tk_ConfigureInfo(interp, tkwin, specs, widgRec, argvName, flags)

int
Tk_ConfigureValue(interp, tkwin, specs, widgRec, argvName, flags)

Tk_FreeOptions(specs, widgRec, display, flags)

الوسائط

المفسر (interpreter) المراد استخدامه لإرجاع رسائل الخطأ.
Tk_Window tkwin (in)
النافذة التي تمثل الأداة (widget) (مطلوبة لتهيئة موارد X).
const Tk_ConfigSpec *specs (in)
مؤشر إلى الجدول الذي يحدد خيارات التهيئة الصالحة لهذه الأداة.
int argc (in)
عدد الوسائط في argv.

خيارات سطر الأوامر لتهيئة الأداة.

يشير إلى هيكل سجل الأداة. يتم تعديل حقول هذا الهيكل بواسطة Tk_ConfigureWidget لتخزين معلومات التهيئة.
int flags (in)
إذا لم يكن صفرًا، فإنه يحدد مزيج OR من الأعلام التي تتحكم في معالجة معلومات التهيئة. TK_CONFIG_ARGV_ONLY يتجاهل قاعدة بيانات الخيارات والقيم الافتراضية، ويتم استخدام البتات TK_CONFIG_USER_BIT وما فوق لتعطيل الإدخالات في specs.

اسم نوع سجل الأداة.
field name field (in)
اسم خاصية لسجل من النوع type.
const char *argvName (in)

Display *display (in)
الشاشة التي تحتوي على الأداة التي يتم تحرير سجلها؛ مطلوب لتحرير الموارد.

الوصف

ملاحظة: يجب استبدال Tk_ConfigureWidget بواجهة برمجة التطبيقات الجديدة المستندة إلى Tcl_Obj وهي Tk_SetOptions. الواجهة القديمة محفوظة للتوافق.

يُستخدم Tk_ConfigureWidget لتهيئة جوانب مختلفة من الأداة، مثل الألوان والخطوط وعرض الحدود وما إلى ذلك. إنها أداة مساعدة لتقليل كمية التعليمات البرمجية التي يجب كتابتها في مديري الأدوات للتعامل مع معلومات التهيئة. عادةً ما يتم استدعاؤه عند إنشاء الأدوات، ومرة أخرى عند استدعاء الأمر configure لأداة. على الرغم من أنه مصمم بشكل أساسي للأدوات، يمكن استخدام Tk_ConfigureWidget في سياقات أخرى حيث يتم استخدام معلومات سطر الأوامر argc-argv لملء هيكل سجل، مثل تهيئة العناصر الرسومية في أداة canvas أو إدخالات القائمة.

يقوم Tk_ConfigureWidget بمعالجة جدول يحدد خيارات التهيئة المدعومة (specs) ومجموعة من وسائط سطر الأوامر (argc و argv) لملء حقول هيكل سجل (widgRec). يستخدم قاعدة بيانات الخيارات والقيم الافتراضية المحددة في specs لملء حقول widgRec التي لم يتم تحديدها في argv. يعيد Tk_ConfigureWidget عادةً TCL_OK؛ في هذه الحالة، لا يقوم بتعديل interp. في حالة حدوث خطأ، يتم إرجاع TCL_ERROR ويتم ترك رسالة خطأ في interp بأسلوب Tcl القياسي. في حالة حدوث خطأ، قد تكون بعض حقول widgRec قد تم تعيينها بالفعل، إذا تمت معالجة معلومات التهيئة الخاصة بها بشكل صحيح قبل حدوث الخطأ. يتم تعيين الحقول الأخرى إلى قيم أولية معقولة بحيث يمكن استدعاء Tk_FreeOptions للتنظيف.

يحدد المصفوفة specs أنواع خيارات التهيئة التي تتوقعها الأداة. يحدد كل إدخال في هذه المصفوفة خيار تهيئة ويحتوي على الهيكل التالي:

typedef struct {
    int type;
    const char *argvName;
    const char *dbName;
    const char *dbClass;
    const char *defValue;
    int offset;
    int specFlags;
    const Tk_CustomOption *customPtr;
} Tk_ConfigSpec;
يشير الحقل type إلى نوع خيار التهيئة (على سبيل المثال، TK_CONFIG_COLOR لقيمة اللون، أو TK_CONFIG_INT لقيمة عدد صحيح). يحدد الحقل type كيفية استخدام قيمة الخيار (مزيد من المعلومات في الفقرة التالية). الحقل argvName هو سلسلة نصية مثل -font أو -bg، والتي تتم مقارنتها مع القيم في argv (إذا كان argvName هو NULL، فهذا يعني أنها إدخالات مجمعة؛ انظر GROUPED ENTRIES أدناه). تُستخدم الحقول dbName و dbClass للبحث عن قيمة لهذا الخيار في قاعدة بيانات الخيارات. يحدد الحقل defValue قيمة افتراضية لهذا الخيار إذا لم يتم تحديد أي قيمة في argv أو في قاعدة بيانات الخيارات. يحدد الحقل offset مكان تخزين المعلومات حول هذا الخيار في widgRec، ويحتوي specFlags على معلومات إضافية للتحكم في معالجة هذا الخيار (انظر FLAGS أدناه). يتم استخدام الحقل الأخير، customPtr، فقط إذا كان type هو TK_CONFIG_CUSTOM؛ انظر CUSTOM OPTION TYPES أدناه.

يقوم Tk_ConfigureWidget بمعالجة وسائط argv أولاً لمعرفة أي منها (إن وجدت) هي خيارات التهيئة المحددة هناك. يجب أن تحتوي Argv على عدد زوجي من الحقول؛ يجب أن يتطابق الحقل الأول من كل زوج مع argvName لإدخال ما في specs (الاختصارات الفريدة مقبولة)، ويحتوي الحقل الثاني من الزوج على القيمة لخيارات التهيئة تلك. إذا كانت هناك إدخالات في spec لا تتوافق مع argv، يستخدم Tk_ConfigureWidget الحقول dbName و dbClass من إدخال specs لاستكشاف قاعدة بيانات الخيارات؛ إذا تم العثور على قيمة، يتم استخدامها كقيمة للخيار. أخيرًا، إذا لم يتم العثور على تطابق في قاعدة بيانات الخيارات، يتم استخدام الحقل defValue من إدخال specs كقيمة لخيارات التهيئة. إذا كان defValue هو NULL، أو إذا تم تمكين البت TK_CONFIG_DONT_SET_DEFAULT في flags، فلن يتم تعيين قيمة افتراضية وسيتم تجاهل إدخال specs هذا إذا لم يتم تحديد قيمة في argv أو في قاعدة بيانات الخيارات.

بمجرد تحديد قيمة لخيارات التهيئة، يقوم Tk_ConfigureWidget بترجمة قيمة السلسلة النصية إلى تنسيق أكثر فائدة، على سبيل المثال، لون إذا كان type هو TK_CONFIG_COLOR أو عدد صحيح إذا كان type هو TK_CONFIG_INT. يتم تخزين هذه القيمة في سجل هيكل widgRec. يُفترض أن يحتوي هذا السجل على معلومات ذات صلة بمدير الأداة؛ نوعه الدقيق غير معروف لـ Tk_ConfigureWidget. يشير الحقل offset لكل إدخال في specs إلى مكان تخزين المعلومات حول خيارات التهيئة هذه في widgRec. يجب عليك استخدام الماكرو Tk_Offset لتوليد قيم offset (انظر وصف Tk_Offset أدناه). سيشار إلى الموقع المحدد بواسطة widgRec و offset باسم "الهدف" في الأوصاف التالية.

يحدد الحقل type لكل إدخال في specs ما يجب فعله بقيمة سلسلة الخيار هذه. القيم القانونية لـ type، والإجراءات المقابلة، هي:

TK_CONFIG_ACTIVE_CURSOR
يجب أن تكون القيمة سلسلة ASCII تحدد مؤشرًا (cursor) مناسبًا لتمريره إلى Tk_GetCursor. يتم تحويل القيمة إلى Tk_Cursor عن طريق استدعاء Tk_GetCursor ويتم تخزين النتيجة في الهدف. بالإضافة إلى ذلك، يتم تعيين المؤشر الناتج كمؤشر نشط للنافذة tkwin عن طريق استدعاء XDefineCursor. إذا تم تمكين البت TK_CONFIG_NULL_OK في specFlags، يمكن أن تكون القيمة سلسلة فارغة، وفي هذه الحالة يتم تعيين الهدف والمؤشر النشط للنافذة tkwin إلى None. إذا لم يكن قيمة الهدف السابقة None، يتم تحريرها عن طريق تمرير القيمة إلى Tk_FreeCursor.
TK_CONFIG_ANCHOR
يجب أن تكون القيمة سلسلة ASCII تحدد نقطة تثبيت (anchor point) في أحد الأشكال التي تقبلها Tk_GetAnchor. يتم تحويل السلسلة إلى Tk_Anchor.

DESCRIPTION

The Tk_ConfigureWidget command provides a standard mechanism for configuring Tk widgets. It is used by most Tk widgets to process configuration options specified by the application.

The configuration options for a widget are described by an array of Tk_ConfigSpec structures. Each structure describes a single option, including its name (e.g., "background"), the type of the option (e.g., integer, color, font), and the offset within the widget's internal structure where the option's value should be stored. The specFlags field can be used to control the behavior of the configuration options. Some of the most common flags are:

TK_CONFIG_OPTION_SPECIFIED
The option was specified in the configuration command.
TK_CONFIG_USER_BIT
The option is a user-defined option.
TK_CONFIG_COLOR_USER_BIT
The option is a user-defined color option.
TK_CONFIG_FONT_USER_BIT
The option is a user-defined font option.
TK_CONFIG_MONOCHROME
The option should be set to black and white only.
TK_CONFIG_ADHOC
The option is an ad hoc option that can be specified multiple times.
TK_CONFIG_NULL_OK
The option can be set to null.
TK_CONFIG_NODEFAULT
The option has no default value.
TK_CONFIG_DERIVATIVE
The option is derived from another option.
TK_CONFIG_JAPANESE
The option is for Japanese characters.
TK_CONFIG_COMBOBOX
The option is for combobox widgets.

The Tk_ConfigureWidget function processes a list of options specified in the specPtr array. For each option, it parses the value given in the valuePtr array, converts it to the appropriate type, and stores it in the widget's internal structure at the offset specified by the Tk_ConfigSpec structure. The mask argument is used to specify which options should be configured. If an error occurs, Tk_ConfigureWidget returns an error code and sets the interp->result to an error message.

The Tk_ConfigureInfo function is similar to Tk_ConfigureWidget, but instead of configuring the widget, it returns information about the configuration options. The infoPtr argument is used to specify the type of information to be returned.

The Tk_ConfigureValue function is used to get the value of a single configuration option.

The Tk_ParseConfig function parses a list of configuration options without actually applying them to a widget. This can be useful for validating configuration options before applying them.

The Tk_PrintConfig function converts a list of configuration options into a string representation. This can be useful for debugging or for displaying the current configuration of a widget.

The Tk_SetOptions function is a lower-level function that applies configuration options to a widget. It is typically called by Tk_ConfigureWidget.

The Tk_OptionValue function returns the value of a single configuration option.

The Tk_OptionSpec function returns a pointer to the Tk_ConfigSpec structure for a given option name.

The Tk_OptionTraceInfo function is a callback function that is called when an option is changed. It can be used to perform custom actions when an option is modified.

The Tk_FreeOptions function frees any memory that was allocated by Tk_ConfigureWidget or Tk_SetOptions.

The Tk_InitOptions function initializes the configuration options for a widget. It is typically called by the widget's creation procedure.

The Tk_InitCustomOptions function initializes a table of custom option types. Custom option types allow widgets to define their own option types beyond the standard ones provided by Tk.

The Tk_FreeConfigInfo function frees any memory that was allocated by Tk_ConfigureInfo.

The Tk_NameOfColor, Tk_NameOfFont, Tk_NameOf relief, Tk_NameOfCursor, and Tk_NameOfImage functions return the string name corresponding to a given color, font, relief style, cursor, or image, respectively.

The Tk_AllocColor, Tk_AllocFont, Tk_AllocCursor, and Tk_AllocBitmap functions allocate and return resources corresponding to the given string names. If the resources cannot be allocated or the name is invalid, an error is returned.

The Tk_FindColor, Tk_FindFont, Tk_FindCursor, and Tk_FindBitmap functions find existing resources corresponding to the given string names. If the resources do not exist, they are allocated using the corresponding Tk_Alloc function. This is useful for ensuring that resources are shared and not duplicated.

The Tk_OptionTypes function returns a pointer to a table of option type descriptors. This can be used to dynamically query the types of configuration options.

The Tk_Offset macro calculates the offset of a field within a structure. This is used in Tk_ConfigSpec structures to specify where option values should be stored.

The Tk_NameOfUid function returns the string name associated with a Tk_Uid identifier.

The Tk_SetClass and Tk_GetClass functions allow you to set and get the widget class for a widget. The Tk_NameOfClass function returns the string name of a widget class.

The Tk_Std...Option functions are standard procedures for handling common option types. They are typically used in conjunction with custom option types.

The Tk_ConfigModified function checks if a particular option has been modified based on a mask.

CUSTOM OPTION TYPES

Tk supports custom option types, which allow you to define your own option types beyond the standard ones. This is done by creating a Tk_CustomOption structure that specifies the name of the custom option type, a pointer to a procedure that parses values of this type (parseProc), and a pointer to a procedure that prints values of this type (printProc).

The parseProc procedure is responsible for converting a string representation of the option's value into the internal representation used by the widget. It should return a status code indicating success or failure. If the result string is stored in static memory then printProc need not do anything with the freeProcPtr argument.

Once parseProc and printProc have been defined and a Tk_CustomOption structure has been created for them, options of this new type may be manipulated with Tk_ConfigSpec entries whose type fields are TK_CONFIG_CUSTOM and whose customPtr fields point to the Tk_CustomOption structure.

EXAMPLES

Although the explanation of Tk_ConfigureWidget is fairly complicated, its actual use is pretty straightforward. The easiest way to get started is to copy the code from an existing widget. The library implementation of frames (tkFrame.c) has a simple configuration table, and the library implementation of buttons (tkButton.c) has a much more complex table that uses many of the fancy specFlags mechanisms.
