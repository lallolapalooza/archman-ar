Tk__Adjuster(3pm)

Adjuster(3) وثائق Perl من مساهمي المستخدم Adjuster(3)

الاسم

Tk::Adjuster - السماح بتعديل حجم الأدوات المعبأة بواسطة المستخدم

الملخص

use Tk::Adjuster;

$adjuster = $widget->Adjuster(?خيارات؟);

خيارات خاصة بالأداة

الاسم: restore
الفئة: Restore
المفتاح: -restore
يحدد قيمة منطقية تحدد ما إذا كان يجب على المضبط (Adjuster) محاولة إفساح المجال لنفسه بالقوة (عن طريق تقليل حجم الأداة التي يديرها) عند إلغاء تعيينه (على سبيل المثال، بسبب تغيير في حجم نافذة علوية). القيمة الافتراضية هي 1.
الاسم: side
الفئة: Side
المفتاح: -side
يحدد الجانب الذي تقع عليه الأداة المُدارة بالنسبة للمضبط. بالاقتران مع مدير الهندسة pack، يتعلق هذا بجانب السيد الذي يتم تعبئة الأداة المُدارة والمضبط مقابله. يجب أن يكون left، right، top، أو bottom. الافتراضي هو top.
الاسم: widget
الفئة: Widget
المفتاح: -widget
يحدد الأداة التي سيتم إدارتها بواسطة المضبط.

الوصف

Tk::Adjuster هو إطار يحتوي على "خط" و "فقاعة".

السحب باستخدام زر الماوس-1 يؤدي إلى سحب خط للإشارة إلى الحجم الجديد. يؤدي تحرير الزر-1 إلى إرسال طلبات الهندسة (GeometryRequests) نيابة عن الأداة المُدارة مما سيؤدي إلى تغيير مدير التعبئة لحجم الأداة.

إذا تم السحب مع الضغط على زر Shift، يتم إرسال طلبات الهندسة في "الوقت الفعلي" بحيث يمكن رؤية تأثيرات تدفق النص، ولكن نظرًا لأن هناك المزيد من العمل الذي يتم إجراؤه، فقد يكون السلوك بطيئًا.

إذا تم تعبئة الأداة باستخدام -side => left أو -side => right، يتم تعديل العرض. إذا تم تعبئتها -side => top أو -side => bottom، يتم تعديل الارتفاع.

يتم إيقاف packPropagate للنافذة الرئيسية لمنع التعديل من تغيير حجم النافذة الإجمالي. وبالمثل، يتم إيقاف packPropagate للأداة المُدارة إذا كان لديها عناصر معبأة بداخلها. هذا لمنع طلبات الهندسة التي تم إجراؤها بواسطة Tk::Adjuster من تجاوزها بواسطة pack.

بالإضافة إلى ذلك، يتم جعل الأداة المُدارة غير قابلة للتوسيع لمنع مدير الهندسة من إعادة تخصيص المساحة المحررة في السيد إلى الأداة المُدارة. لاحظ مع ذلك أنه يتم إيقاف التوسيع فقط بعد تعيين المضبط، مما يسمح للأداة المُدارة بالتوسع بشكل طبيعي عند إنشاء النافذة.

تقوم طريقة أداة Tk، packAdjust، باستدعاء pack على الأداة، ثم تنشئ مثيلاً من Tk::Adjuster، وتقوم بتعبئة تلك "بعد" الأداة. ومع ذلك، فإن استخدامها له عيبان: لا تتوفر أداة المضبط للمتصل، ولا يمكن تعيين الخيارات على المضبط. لهذه الأسباب، يُفضل طريقة Tk::Adjuster، packAfter، ولكن يتم الاحتفاظ بـ packAdjust للتوافق مع الإصدارات السابقة.

طرق الأدوات

$adjuster->packAfter(managed_widget, ?pack_options?)
يقوم هذا الأمر بتكوين خيارات -widget و -side الخاصة بالمضبط على التوالي إلى managed_widget وقيمة -side المحددة في pack_options (top إذا لم يتم تحديدها). ثم يقوم بتعبئة المضبط بعد managed_widget، مع ضبط -fill على x أو y حسب الاقتضاء.
$adjuster->packForget?(boolean)?
يستدعي هذا الأمر Tk::Widget::packForget على المضبط. إذا تم توفير معلمة ولها قيمة منطقية صحيحة، فسيتم أيضًا استدعاء packForget على الأداة المُدارة.
$adjuster->slave
يقوم هذا الأمر بإرجاع القيمة $adjuster->cget('-widget')، أي مرجع إلى الأداة المُدارة.

أمثلة

استخدام مضبط للفصل بين أداتين، حيث تتم إدارة الأداة اليسرى، وتتمدد الأداة اليمنى لملء المساحة عند تغيير حجم النافذة

أ) استخدام packAfter (الواجهة المفضلة)

use Tk;
use Tk::Adjuster;
my $f = MainWindow->new;
my $lst1 = $f->Listbox();
my $adj1 = $f->Adjuster();
my $lst2 = $f->Listbox();
my $side = 'left';
$lst1->pack(-side => $side, -fill => 'both', -expand => 1);
$adj1->packAfter($lst1, -side => $side);
$lst2->pack(-side => $side, -fill => 'both', -expand => 1);
MainLoop;

ب) استخدام packAdjust

use Tk;
use Tk::Adjuster;
my $f = MainWindow->new;
my $lst1 = $f->Listbox();
my $lst2 = $f->Listbox();
my $side = 'left';
$lst1->packAdjust(-side => $side, -fill => 'both');
$lst2->pack      (-side => $side, -fill => 'both', -expand => 1);
MainLoop;

ج) استخدام Tk::Widget::pack القياسي

use Tk;
use Tk::Adjuster;
my $f = MainWindow->new;
my $side = 'left';
my $lst1 = $f->Listbox();
my $adj  = $f->Adjuster(-widget => $lst1, -side => $side);
my $lst2 = $f->Listbox();
$lst1->pack(-side => $side, -fill => 'both', -expand => 1);
$adj->pack (-side => $side, -fill => 'y');
$lst2->pack(-side => $side, -fill => 'both', -expand => 1);
MainLoop;

تغيير الأمثلة أعلاه بحيث تكون قيمة $side هي 'right' يعني أن الأداة اليسرى تتمدد لملء المساحة عند تغيير حجم النافذة.

تغيير الأمثلة أعلاه بحيث تكون قيمة $side هي 'top' ينتج عنه حالة اختبار مع مضبط أفقي. هنا تتمدد الأداة السفلية لملء المساحة عند تغيير حجم النافذة. التعبئة إلى 'bottom' تجعل الأداة العلوية تتمدد لملء المساحة عند تغيير حجم النافذة.

استخدام -restore => 0 لأعمدة متعددة

في حالة وجود أعمدة (أو صفوف) متعددة، يمكن أن تكون وظيفة "الاستعادة" للمضبط غير مريحة. عندما يقوم المستخدم بتعديل عرض عمود واحد ويدفع بالتالي مضبط عمود آخر خارج النافذة، يحاول هذا المضبط استعادة نفسه عن طريق تقليل حجم أداته المُدارة. هذا يؤدي إلى تقلص عرض الأعمدة؛ ولا يتم استعادة الحجم الأصلي عندما يعكس المستخدم التغيير الأصلي. يمكن استخدام الخيار -restore لإيقاف هذه الوظيفة. (ومع ذلك، يبدو من المنطقي ترك -restore قيد التشغيل للمضبط الذي تم تعبئته أولاً، بحيث يظل مضبط واحد على الأقل مرئيًا دائمًا.)

use Tk;
use Tk::Adjuster;
my $f = MainWindow->new;
my $lst1 = $f->Listbox();
my $adj1 = $f->Adjuster();
my $lst2 = $f->Listbox();
my $adj2 = $f->Adjuster(-restore => 0);
my $lst3 = $f->Listbox();
my $side = 'left';
$lst1->pack(-side => $side, -fill => 'both', -expand => 1);
$adj1->packAfter($lst1, -side => $side);
$lst2->pack(-side => $side, -fill => 'both', -expand => 1);
$adj2->packAfter($lst2, -side => $side);
$lst3->pack(-side => $side, -fill => 'both', -expand => 1);
MainLoop;

أخطاء

لا يمكن حاليًا تكوين مظهر المضبط. سيكون من الجيد أن نتمكن من تعيين عرض وتخفيف "خط" المضبط ووجود/عدم وجود "الفقاعة" على المضبط.

يعمل Tk::Adjuster نظريًا مع مدير الهندسة grid ولكن هناك حاليًا بعض المشاكل التي تبدو بسبب أخطاء في grid:

a) لا يوجد حدث Unmap للمضبط أبدًا، لذلك لا يكون لوظيفة "الاستعادة" أي تأثير.
b) بعد التعديل، تبرز الأدوات في حدود السيد.
c) لا يكون لـ grid('Propagate', 0) على MainWindow أي تأثير - تتقلص/تنمو النافذة عند تعديل الأدوات.
d) تتنقل الأدوات إلى الموضع الصحيح عند بدء التشغيل
