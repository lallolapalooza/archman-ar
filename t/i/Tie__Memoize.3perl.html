Tie::Memoize(3perl) دليل مبرمجي Perl Tie::Memoize(3perl)

الاسم

Tie::Memoize - إضافة بيانات إلى الهاش عند الحاجة

الملخص

require Tie::Memoize;
tie %hash, 'Tie::Memoize',
    \&fetch,                  # الباقي اختياري
    $DATA, \&exists,
    {%ini_value}, {%ini_existence};

الوصف

تسمح هذه الحزمة لهاش مرتبط بتحميل قيمه تلقائيًا عند الوصول الأول، واستخدام القيمة المخزنة مؤقتًا في الوصول اللاحق.

الوصول للقراءة فقط (عبر جلب القيمة أو "exists") يؤدي إلى استدعاءات للدوال؛ ويتم تنفيذ عمليات التعديل كما في الهاش العادي.

الوسائط المطلوبة أثناء "tie" هي الهاش، الحزمة، ومرجع لدالة "FETCH". الوسائط الاختيارية هي قيمة قياسية اعتباطية $data، ومرجع لدالة "EXISTS"، وقيم أولية للهاش ولمخزن الوجود المؤقت.

كل من دالتي "FETCH" و "EXISTS" لهما نفس التوقيع: الوسائط هي "$key, $data"؛ $data هي نفس القيمة المعطاة كوسيط أثناء ربط tie(). يجب أن تعيد كلتا الدالتين قائمة فارغة إذا لم تكن القيمة موجودة. إذا كانت دالة "EXISTS" مختلفة عن دالة "FETCH"، فيجب أن تعيد قيمة TRUE عند النجاح. يجب أن تعيد دالة "FETCH" القيمة المقصودة إذا كان المفتاح صالحًا.

الوراثة من Tie::Memoize

هيكل بيانات tied() هو مرجع لمصفوفة بعناصر

0:  مخزن القيم المعروفة
1:  مخزن الوجود المعروف للمفاتيح
2:  دالة FETCH
3:  دالة EXISTS
4:  $data

الباقي مخصص للاستخدام الداخلي لهذه الحزمة. على وجه الخصوص، إذا تمت إعادة كتابة TIEHASH، فيجب استدعاء SUPER::TIEHASH.

مثال

sub slurp {
  my ($key, $dir) = shift;
  open my $h, '<', "$dir/$key" or return;
  local $/; <$h>                      # اقرأه بالكامل
}
sub exists { my ($key, $dir) = shift; return -f "$dir/$key" }
tie %hash, 'Tie::Memoize', \&slurp, $directory, \&exists,
    { fake_file1 => $content1, fake_file2 => $content2 },
    { pretend_does_not_exists => 0, known_to_exist => 1 };

يعالج هذا المثال محتويات معدلة قليلاً ل $directory كهاش. التعديلات هي أن المفاتيح fake_file1 و fake_file2 تجلب القيم $content1 و $content2، ولن يتم الوصول أبدًا إلى pretend_does_not_exists. بالإضافة إلى ذلك، لا يتم التحقق أبدًا من وجود known_to_exist (لذا إذا لم يكن موجودًا عند الحاجة إلى محتواه، فقد يكون المستخدم ل %hash مرتبكًا).

أخطاء

تتجاوز الأساليب FIRSTKEY و NEXTKEY المفاتيح التي تمت قراءتها بالفعل، وليس كل المفاتيح الممكنة للهاش.
