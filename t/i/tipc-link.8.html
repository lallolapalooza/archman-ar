الاسم

tipc-link - عرض الروابط أو تعديل خصائص الرابط

ملخص


tipc link set
[ { priority الأولوية | tolerance التسامح | window النافذة } link الرابط ] |
[ { broadcast [ البث | التكرار | الاختيار_التلقائي [ ratio الحجم ] ] } ]

tipc link get
[ { priority | tolerance | window } link الرابط ] |
[ { broadcast } ]

tipc link statistics { show [ link الرابط ] | reset link الرابط }

tipc link list

tipc link monitor set { threshold }

tipc link monitor get { threshold }

tipc link monitor summary

tipc link monitor list
[ media { eth | ib } device الجهاز ] |
[ media udp name الاسم ]

خيارات

الخيارات (الأعلام) التي يمكن تمريرها في أي مكان في سلسلة الأوامر.

-h, --help
عرض المساعدة حول آخر أمر صالح. على سبيل المثال tipc link --help سيعرض مساعدة الرابط و tipc --help سيعرض مساعدة عامة. موقع الخيار في السلسلة غير ذي صلة.
-j, -json
إخراج النتائج بصيغة JavaScript Object Notation (JSON).
-p, -pretty
صيغة JSON الافتراضية مدمجة وأكثر كفاءة في التحليل ولكنها صعبة القراءة لمعظم المستخدمين. هذا العلم يضيف مسافة بادئة لقابلية القراءة.

الوصف

إحصائيات الرابط

حالة الرابط ACTIVE

الرابط ACTIVE يخدم المرور. يمكن لرابطين إلى نفس العقدة أن يصبحا ACTIVE إذا كان لهما نفس priority الرابط. إذا كان هناك أكثر من رابطين بنفس الأولوية، فسيتم وضع الروابط الإضافية في حالة STANDBY.
حالة الرابط STANDBY

الرابط STANDBY له أولوية رابط أقل من الرابط ACTIVE. الرابط STANDBY لديه حركة مرور تحكم جارية وهو جاهز لتولي المسؤولية إذا تعطل الرابط (الروابط) ACTIVE.
MTU

وحدة النقل القصوى. يعلن طرفا الاتصال عن MTU الافتراضية أو المعدلة عند إعداد الرابط الأولي وسيتفقان على استخدام القيمة الأقل بينهما إذا اختلفت .
الحزم

إجمالي عدد حزم TIPC المرسلة أو المستلمة على رابط. بما في ذلك الحزم المجزأة و المجمعة.
التجزئات

ممثلة بالشكل fragments/fragmented. حيث fragmented هو مقدار رسائل البيانات التي تم تقسيمها إلى fragments. بالتالي fragments هي إجمالي عدد الحزم التي تم تقسيم رسائل fragmented إليها.
التجميعات

ممثلة بالشكل bundles/bundled. إذا أصبح الرابط مزدحمًا، سيحاول الرابط تجميع البيانات من حزم bundled الصغيرة إلى حزم bundles بحجم MTU الكامل قبل إرسالها.
الملف الشخصي

يعرض حجم الحزمة المتوسط بالبايت لـ عينة من الحزم. كما يعرض توزيع حجم الحزمة للحزم المأخوذة ضمن الفواصل:

0-64 بايت
64-256 بايت
256-1024 بايت
1024-4096 بايت
4096-16384 بايت
16384-32768 بايت
32768-66000 بايت

عدادات الرسائل

states - عدد رسائل حالة الرابط

probes - رسائل حالة الرابط مع تعيين علم الفحص. يتم إرسالها عادةً عندما يكون الرابط خاملاً

nacks - عدد حزم الإقرار السلبي (NACK) المرسلة والمستلمة بواسطة الرابط

defs - عدد الحزم المستلمة خارج الترتيب

dups - عدد الحزم المكررة المستلمة

ازدحام الرابط
عدد المرات التي حاولت فيها تطبيق إرسال بيانات عندما كان رابط TIPC مزدحمًا
قائمة الانتظار للإرسال
Max هو الحد الأقصى لعدد الرسائل التي كانت موجودة في قائمة الانتظار الخارجية خلال فترة جمع الإحصائيات لرابط معين.

Avg هو متوسط حجم قائمة الانتظار الخارجية خلال عمر الرابط.

خصائص الرابط

priority

الأولوية بين روابط TIPC المنطقية إلى عقدة معينة. يمكن أن تتراوح أولوية الرابط من 0 (الأدنى) إلى 31 (الأعلى).
tolerance

يحدد تسامح الرابط الحد الأقصى للوقت بالمللي ثانية الذي ستسمح به TIPC بوجود مشكلة في الاتصال قبل إيقاف الرابط. القيمة الافتراضية هي 1500 مللي ثانية.
window

تتحكم نافذة الرابط في عدد الرسائل غير المؤكدة التي يمكن أن يمتلكها طرف اتصال في قائمة الانتظار للإرسال قبل تفعيل آلية التحكم في الازدحام في TIPC.

خصائص المراقبة

threshold

يحدد الحد الأقصى لحجم المجموعة الذي سيبدأ عنده خوارزمية مراقبة الرابط في التبديل من "شبكة كاملة" (full-mesh) إلى "حلقة متداخلة" (overlapping-ring). إذا تم تعيينه على 0، تكون المراقبة بالحلقة المتداخلة قيد التشغيل دائمًا، وإذا تم تعيينه على قيمة أكبر من حجم المجموعة المتوقع، يتم تعطيل الحلقة المتداخلة. القيمة الافتراضية هي 32.

معلومات المراقبة

table_generation

يمثل عدد الأحداث في قائمة المراقبة المحلية للعقدة. يزداد كلما حدث تغيير في قائمة المراقبة المحلية، بما في ذلك التغييرات في المجال المحلي.
cluster_size

يمثل العدد الحالي لأعضاء المجموعة.
algorithm

خوارزمية الإشراف الحالية المستخدمة لمراقبة الجيران للمحمول. القيم الممكنة هي شبكة كاملة (full-mesh) أو حلقة متداخلة (overlapping-ring).
status

حالة العقدة المستمدة من العقدة المحلية. الحالات الممكنة هي قيد التشغيل (up) أو متوقفة (down).
monitored

يمثل نوع المراقبة الذي اختارته العقدة المحلية. القيم الممكنة هي مباشرة (direct) أو غير مباشرة (indirect).
generation

يمثل جيل المجال، وهو عدد الأحداث في مجال العقدة المحلي. في كل مرة يحدث فيها تغيير (إضافة/إزالة/تشغيل/إيقاف نظير)، يتم زيادة جيل المجال وإرسال نسخة جديدة من سجل العقدة لإعلام الجيران بهذا التغيير. يساعد جيل المجال المستلم لسجل المجال على معرفة ما إذا كان يجب عليه تجاهل السجل أو معالجته.
applied_node_status

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

monitor TIPC link state

OPTIONS

all
Shows all link monitoring information.
stats
Shows link monitoring statistics.
summary
Shows a summary of link monitoring information.
name
Shows link monitoring name information.
list
Shows the link monitoring list.
routes
Shows link monitoring route information.
broadcast
Shows link monitoring broadcast information.
bearer
Shows link monitoring bearer information.
peer
Shows link monitoring peer information.
node
Shows link monitoring node information.
config
Shows link monitoring configuration information.
counters
Shows link monitoring counter information.
topology
Shows link monitoring topology information.
port
Shows link monitoring port information.

DESCRIPTION

The tipc link command is used to monitor the state of TIPC links. It can display a variety of information about the links, including their status, statistics, names, routes, broadcast settings, bearer information, peer information, node information, configuration, counters, topology, and port information.

The command can also be used to set the attributes of a link. The help command displays all available commands and options.

The following options are available:

Link monitoring information

applied_node:status

The node status reported by the peer node for the succeeding peers in the node list. The Node list is a circular list of ascending addresses starting with the local node. Possible status are: U or D. The status U implies up and D down.
non_applied_node:status

Represents the nodes and their status as reported by the peer node. These nodes were not applied to the monitoring list for this peer node. They are usually transient and occur during the cluster startup phase or network reconfiguration. Possible status are: U or D. The status U implies up and D down.

Broadcast properties

BROADCAST

Forces all multicast traffic to be transmitted via broadcast only, irrespective of cluster size and number of destinations.
REPLICAST

Forces all multicast traffic to be transmitted via replicast only, irrespective of cluster size and number of destinations.
AUTOSELECT

Auto switching to broadcast or replicast depending on cluster size and destination node number.
ratio SIZE

Set the AUTOSELECT criteria, percentage of destination nodes vs cluster size.

EXAMPLES

tipc link monitor list

Shows the link monitoring information for cluster members on device data0.

tipc link monitor summary

The monitor summary command prints the basic attributes.

EXIT STATUS

Exit status is 0 if command was successful or a positive integer upon failure.

الوصف

يُستخدم الأمر tipc link لمراقبة حالة روابط TIPC. يمكنه عرض مجموعة متنوعة من المعلومات حول الروابط، بما في ذلك حالتها، وإحصائياتها، وأسمائها، ومساراتها، وإعدادات البث، ومعلومات الحامل، ومعلومات الأقران، ومعلومات العقد، والإعدادات، والعدادات، والطوبولوجيا، ومعلومات المنافذ.

يمكن استخدام الأمر أيضًا لتعيين سمات الرابط. يعرض الأمر help جميع الأوامر والخيارات المتاحة.

الخيارات التالية متاحة:

معلومات مراقبة الرابط

applied_node:status

حالة العقدة التي أبلغت عنها العقدة المجاورة للعقد المجاورة التالية في قائمة العقد. قائمة العقد هي قائمة دائرية للعناوين المتزايدة التي تبدأ بالعقدة المحلية. الحالات الممكنة هي: U أو D. تشير الحالة U إلى قيد التشغيل (up) و D إلى متوقف (down).
non_applied_node:status

تمثل العقد وحالتها كما أبلغت عنها العقدة المجاورة. لم يتم تطبيق هذه العقد على قائمة المراقبة لهذه العقدة المجاورة. عادة ما تكون مؤقتة وتحدث أثناء مرحلة بدء تشغيل الكتلة أو إعادة تكوين الشبكة. الحالات الممكنة هي: U أو D. تشير الحالة U إلى قيد التشغيل (up) و D إلى متوقف (down).

خصائص البث

BROADCAST

يجبر جميع حركة مرور البث المتعدد على الإرسال عبر البث فقط، بغض النظر عن حجم الكتلة وعدد الوجهات.
REPLICAST

يجبر جميع حركة مرور البث المتعدد على الإرسال عبر replicast فقط، بغض النظر عن حجم الكتلة وعدد الوجهات.
AUTOSELECT

التبديل التلقائي إلى البث أو replicast اعتمادًا على حجم الكتلة وعدد عقد الوجهة.
ratio SIZE

قم بتعيين معيار AUTOSELECT، وهي نسبة عقد الوجهة مقابل حجم الكتلة.

أمثلة

tipc link monitor list

يعرض معلومات مراقبة الرابط لأعضاء الكتلة على الجهاز data0.

tipc link monitor summary

يطبع أمر المراقبة الملخصة السمات الأساسية.

حالة الخروج

حالة الخروج هي 0 إذا كان الأمر ناجحًا أو رقمًا صحيحًا موجبًا عند الفشل.
