الوصف

تنشئ استدعاءات النظام هذه وتعمل على مؤقت يوصل إشعارات انتهاء صلاحية المؤقت عبر واصف ملف. توفر بديلاً لاستخدام setitimer(2) أو timer_create(2)، مع ميزة أن واصف الملف يمكن مراقبته بواسطة select(2)، poll(2)، و epoll(7).

استخدام استدعاءات النظام الثلاثة هذه مشابه لاستخدام timer_create(2)، timer_settime(2)، و timer_gettime(2). (لا يوجد نظير لـ timer_getoverrun(2)، حيث يتم توفير هذه الوظيفة بواسطة read(2)، كما هو موضح أدناه.)

timerfd_create()

يقوم timerfd_create() بإنشاء كائن مؤقت جديد، ويعيد واصف ملف يشير إلى هذا المؤقت. تحدد الوسيطة clockid الساعة التي يتم استخدامها لتحديد تقدم المؤقت، ويجب أن تكون واحدة مما يلي:

CLOCK_REALTIME
ساعة زمن حقيقي قابلة للضبط على مستوى النظام.
CLOCK_MONOTONIC
ساعة متزايدة بشكل رتيب غير قابلة للضبط تقيس الوقت من نقطة غير محددة في الماضي لا تتغير بعد بدء تشغيل النظام.
CLOCK_BOOTTIME (منذ Linux 3.15)
مثل CLOCK_MONOTONIC، هذه ساعة متزايدة بشكل رتيب. ومع ذلك، في حين أن ساعة CLOCK_MONOTONIC لا تقيس الوقت أثناء تعليق النظام، فإن ساعة CLOCK_BOOTTIME تشمل الوقت الذي يكون فيه النظام معلقًا. هذا مفيد للتطبيقات التي تحتاج إلى أن تكون مدركة لتعليق النظام. CLOCK_REALTIME غير مناسبة لمثل هذه التطبيقات، حيث تتأثر هذه الساعة بالتغييرات غير المتواصلة في ساعة النظام.
CLOCK_REALTIME_ALARM (منذ Linux 3.11)
هذه الساعة تشبه CLOCK_REALTIME، ولكنها ستوقظ النظام إذا كان معلقًا. يجب أن يمتلك المتصل القدرة CAP_WAKE_ALARM لتعيين مؤقت ضد هذه الساعة.
CLOCK_BOOTTIME_ALARM (منذ Linux 3.11)
هذه الساعة تشبه CLOCK_BOOTTIME، ولكنها ستوقظ النظام إذا كان معلقًا. يجب أن يمتلك المتصل القدرة CAP_WAKE_ALARM لتعيين مؤقت ضد هذه الساعة.

راجع clock_getres(2) لبعض التفاصيل الإضافية حول الساعات المذكورة أعلاه.

يمكن استرداد القيمة الحالية لكل من هذه الساعات باستخدام clock_gettime(2).

بدءًا من Linux 2.6.27، يمكن تشغيل القيم التالية بتطبيق OR منطقي في flags لتغيير سلوك timerfd_create():

TFD_NONBLOCK
تعيين علامة حالة الملف O_NONBLOCK في وصف الملف المفتوح (انظر open(2)) الذي يشير إليه واصف الملف الجديد. استخدام هذه العلامة يوفر استدعاءات إضافية لـ fcntl(2) لتحقيق نفس النتيجة.
TFD_CLOEXEC
تعيين علامة الإغلاق عند التنفيذ (FD_CLOEXEC) على واصف الملف الجديد. انظر وصف العلامة O_CLOEXEC في open(2) لمعرفة الأسباب التي قد تجعل هذا مفيدًا.

في إصدارات Linux حتى 2.6.26 بما في ذلك، يجب تحديد flags على أنها صفر.

timerfd_settime()

يقوم timerfd_settime() بتفعيل (بدء) أو تعطيل (إيقاف) المؤقت المشار إليه بواسطة واصف الملف fd.

تحدد الوسيطة new_value وقت انتهاء الصلاحية الأولي والفاصل الزمني للمؤقت. يتم وصف هيكل itimerspec المستخدم لهذه الوسيطة في itimerspec(3type).

تحدد new_value.it_value وقت انتهاء الصلاحية الأولي للمؤقت، بالثواني وأجزاء النانو. تعيين أي من الحقول في new_value.it_value إلى قيمة غير صفرية يقوم بتفعيل المؤقت. تعيين كلا الحقلين في new_value.it_value إلى صفر يقوم بتعطيل المؤقت.

تعيين واحد أو كلا الحقلين في new_value.it_interval إلى قيم غير صفرية يحدد الفترة، بالثواني وأجزاء النانو، لانتهاء صلاحية المؤقت بشكل متكرر بعد انتهاء الصلاحية الأولي. إذا كان كلا الحقلين في new_value.it_interval صفرًا، فإن المؤقت ينتهي صلاحيته مرة واحدة فقط، في الوقت المحدد بواسطة new_value.it_value.

بشكل افتراضي، يتم تفسير وقت انتهاء الصلاحية الأولي المحدد في new_value بالنسبة للوقت الحالي على ساعة المؤقت في وقت الاستدعاء (أي، تحدد new_value.it_value وقتًا نسبيًا للقيمة الحالية للساعة المحددة بواسطة clockid). يمكن تحديد وقت انتهاء صلاحية مطلق عبر الوسيطة flags.

يمكن للوسيطة flags أن تكون قناع بت يمكن أن يشمل القيم التالية:

TFD_TIMER_ABSTIME
تفسير new_value.it_value كقيمة مطلقة على ساعة المؤقت. سينتهي المؤقت عندما تصل قيمة ساعة المؤقت إلى القيمة المحددة في new_value.it_value.
TFD_TIMER_CANCEL_ON_SET
إذا تم تحديد هذه العلامة جنبًا إلى جنب مع TFD_TIMER_ABSTIME وكانت الساعة الخاصة بهذا المؤقت هي CLOCK_REALTIME أو CLOCK_REALTIME_ALARM، فقم بتمييز هذا المؤقت على أنه قابل للإلغاء إذا تعرضت ساعة الوقت الفعلي لتغيير غير متواصل (settimeofday(2)، clock_settime(2)، أو ما شابه). عند حدوث مثل هذه التغييرات، سيفشل استدعاء read(2) الحالي أو المستقبلي من واصف الملف مع الخطأ ECANCELED.

إذا كانت الوسيطة old_value ليست NULL، فإن هيكل itimerspec الذي تشير إليه تستخدم لإرجاع إعداد المؤقت الذي كان ساريًا في وقت الاستدعاء؛ انظر وصف timerfd_gettime() التالي.

timerfd_gettime()

يقوم timerfd_gettime() بإرجاع، في curr_value، هيكل itimerspec يحتوي على الإعداد الحالي للمؤقت المشار إليه بواسطة واصف الملف fd.

يرجع الحقل it_value مقدار الوقت المتبقي حتى تنتهي صلاحية المؤقت في المرة القادمة. إذا كان كلا الحقلين من هذا الهيكل صفرًا، فإن المؤقت معطل حاليًا. يحتوي هذا الحقل دائمًا على قيمة نسبية، بغض النظر عما إذا تم تحديد العلامة TFD_TIMER_ABSTIME عند تعيين المؤقت.

يرجع الحقل it_interval فاصل المؤقت. إذا كان كلا الحقلين من هذا الهيكل صفرًا، يتم تعيين المؤقت لانتهاء صلاحيته مرة واحدة فقط، في الوقت المحدد بواسطة curr_value.it_value.

NAME

timerfd_create, timerfd_gettime, timerfd_settime - timers that integrate with the event model

LIBRARY

realtime library (librt)

SYNOPSIS

#include <sys/timerfd.h>


int timerfd_create(int clockid, int flags);


int timerfd_gettime(int fd, struct itimerspec *curr_value);


int timerfd_settime(int fd, int flags, const struct
    itimerspec *new_value, struct itimerspec *old_value);

DESCRIPTION

A timer managed by timerfd_create() is associated with the specified clockid (see clock_gettime(3)). The timer is created in an unsalted state.

The flags argument specifies characteristics of the new file description. Currently, the only supported flag is TFD_CLOEXEC, which sets the close-on-exec flag on the new file descriptor. If this flag is set, the file descriptor will be closed by any of the exec* family of functions (execve(2), execv(3), etc.).

The file descriptor returned by timerfd_create() is used for the subsequent calls to timerfd_gettime() and timerfd_settime().

timerfd_gettime() returns the time remaining until the next expiration of the timer specified by the file descriptor fd in the structure pointed to by curr_value. The time is returned as an absolute time (i.e., a time relative to the specified clock's epoch).

timerfd_settime() programs the timer associated with the file descriptor fd. The new_value argument points to a structure that specifies the time until the next expiration and the interval between expirations. The flags argument specifies how the time values in new_value are interpreted.

If flags is 0, then the times in new_value are relative (i.e., they specify a duration from the time that the timer is set). This is the behavior of setitimer(2).

If flags is TFD_TIMER_ABSTIME, then the times in new_value are absolute (i.e., they specify a time relative to the clock's epoch). This is the behavior of timer_settime(2).

The old_value argument, if not NULL, points to a structure that is set to the time remaining until the next expiration and the interval for the timer before timerfd_settime() is called.

The structure struct itimerspec is defined as:

struct timespec {
        time_t   tv_sec;     /* seconds */
        long     tv_nsec;    /* nanoseconds */
    };

    struct itimerspec {
        struct timespec it_interval;  /* Interval for periodic timer */
        struct timespec it_value;     /* Next expiration time */
    };

A timer interval of {0, 0} means that the timer is disarmed.

When a timer expires, a number of bytes equal to the size of uint64_t is made available to be read from the timer file descriptor. The value read is the number of timer expirations that have occurred since the last read operation. When reading from the timer file descriptor, if the value is greater than 1, it means the timer has expired one or more times while the process was busy doing something else, for example, handling a signal or during a long system call.

The timer FD is a blocking file descriptor by default. If the caller attempts to read from the FD when no data is available (i.e., the timer has not expired), the call will block until data is available.

The timer FD supports the following system calls:

  • poll(2), select(2), epoll(7): The timer FD indicates readiness for reading when at least one timer expiration has occurred. The result is returned in the revents field of the struct pollfd.
  • read(2): Reads the number of timer expirations from the FD.
  • close(2): Closes the FD and destroys the associated timer.

TFD_NONBLOCK flag: If this flag is set during the creation of the timerfd, then reads from the timerfd will be non-blocking. If a read is attempted and no data is available, read() returns -1 and sets errno to EAGAIN.

RETURN VALUE

On success, timerfd_create() returns a new file descriptor. On failure, -1 is returned, and errno is set appropriately.

On success, timerfd_gettime() and timerfd_settime() return 0. On failure, -1 is returned, and errno is set appropriately.

ERRORS

The following errors can occur:

  • EINVAL The clockid is not supported, or an unknown flag was specified in flags.
  • EMFILE The process has reached its limit for open file descriptors.
  • ENFILE The system has reached its limit for open files.
  • ENODEV Clock source is gone.
  • ENOMEM Not enough memory to create timer FD.
  • EFAULT curr_value or new_value points to an invalid address.
  • EBADF fd is not a valid file descriptor.
  • EINVAL flags has an invalid value.
  • ETIMEDOUT The timer specified by fd has expired and has already been disarmed.

STANDARDS

These system calls are Linux-specific.

HISTORY

Support for timerfd_create, timerfd_gettime, and timerfd_settime first appeared in Linux kernel 2.6.25.

NOTES

The struct itimerspec members tv_sec and tv_nsec can be used to specify very large time values. The maximum value is limited by the range of time_t and long, and also by the kernel's timer resolution and maximum timer values.

The timer FD is a multishot timer, meaning it will continue to fire periodically until explicitly disarmed or the FD is closed. A timer created with an interval of {0, 0} in it_interval is disarmed.

The value read from the timer FD is the number of timer expirations that have occurred since the last read. If the timer expires while the process is busy or asleep, the count can be greater than 1.

The clock used can be specified using the clockid parameter. For example, CLOCK_REALTIME is the system-wide real-time clock, and CLOCK_MONOTONIC is a monotonically increasing clock that is not affected by system time changes.

A common use case is to create a timer that fires periodically, and then use poll(2) or select(2) to wait for timer expirations. This allows a process to perform periodic tasks without busy-waiting.

Example usage of timerfd_create:

    int fd;
    struct itimerspec ts;

    fd = timerfd_create(CLOCK_MONOTONIC, 0);
    if (fd == -1)
        perror(\"timerfd_create\");

    ts.it_interval.tv_sec = 1;
    ts.it_interval.tv_nsec = 0;
    ts.it_value.tv_sec = 5;
    ts.it_value.tv_nsec = 0;

    if (timerfd_settime(fd, 0, &ts, NULL) == -1)
        perror(\"timerfd_settime\");

    /* Now wait for the timer to expire */

The program in the EXAMPLE section demonstrates how to use these system calls.

BUGS

The TFD_TIMER_ABSTIME flag is not supported by timerfd_settime in older kernel versions.

EXAMPLES

The following program demonstrates the usage of timerfd_create, timerfd_settime, and reading from the timer file descriptor.

The program takes an initial expiration time in seconds as the first argument. Optionally, it can take an interval in seconds and the maximum number of expirations as the second and third arguments, respectively.

#include <err.h>
#include <errno.h>
#include <fcntl.h>
#include <inttypes.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/timerfd.h>
#include <time.h>
#include <unistd.h>

#define CLOCKID CLOCK_REALTIME
#define TIMER_ABSTIME TFD_TIMER_ABSTIME

static void
print_elapsed_time(void)
{
    static struct timespec start = {0, 0};
    struct timespec     curr;
    long long           secs, nsecs;

    if (clock_gettime(CLOCKID, &curr) == -1)
        err(EXIT_FAILURE, "clock_gettime");

    if (start.tv_sec == 0 && start.tv_nsec == 0) {
        start = curr;
    }

    secs = curr.tv_sec - start.tv_sec;
    nsecs = curr.tv_nsec - start.tv_nsec;
    if (nsecs < 0) {
        secs--;
        nsecs += 1000000000;
    }

    /*
     * Print elapsed time in seconds and milliseconds.
     * The expression (nsecs + 500000) / 1000000 rounds to the nearest
     * millisecond.
     */
    printf("%lld.%03lld:\t", (long long)secs, (long long)((nsecs + 500000) / 1000000));
}

int
main(int argc, char *argv[])
{
    int                fd;
    ssize_t            s;
    uint64_t           expir, tot_expir, max_expir;
    struct timespec    now;
    struct itimerspec  new_value;

    /* Check command-line arguments */
    if (argc != 2 && argc != 4) {
        fprintf(stderr, "%s init-secs [interval-secs max-num-expir]\n",
                argv[0]);
        exit(EXIT_FAILURE);
    }

    /* Get the current time */
    if (clock_gettime(CLOCKID, &now) == -1)
        err(EXIT_FAILURE, "clock_gettime");

    /* Create a CLOCK_REALTIME absolute timer with initial
       expiration and interval as specified in command line.  */
    new_value.it_value.tv_sec = now.tv_sec + atoi(argv[1]);
    new_value.it_value.tv_nsec = now.tv_nsec;

    if (argc == 2) {
        /* Timer expires just once */
        new_value.it_interval.tv_sec = 0;
        max_expir = 1;
    } else {
        /* Timer expires periodically */
        new_value.it_interval.tv_sec = atoi(argv[2]);
        max_expir = atoi(argv[3]);
    }
    new_value.it_interval.tv_nsec = 0;

    /* Create a timerfd file descriptor */
    fd = timerfd_create(CLOCKID, 0);
    if (fd == -1)
        err(EXIT_FAILURE, "timerfd_create");

    /* Set the timer */
    if (timerfd_settime(fd, TIMER_ABSTIME, &new_value, NULL) == -1)
        err(EXIT_FAILURE, "timerfd_settime");

    print_elapsed_time();
    printf("timer started\n");

    /* Loop, reading from the timerfd */
    for (tot_expir = 0; tot_expir < max_expir;) {
        s = read(fd, &expir, sizeof(uint64_t));
        if (s != sizeof(uint64_t))
            err(EXIT_FAILURE, "read");

        tot_expir += expir;
        print_elapsed_time();
        printf("read: %" PRIu64 "; total=%" PRIu64 "\n",
               expir, tot_expir);
    }

    exit(EXIT_SUCCESS);
}
