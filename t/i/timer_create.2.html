timer_create(2) دليل استدعاءات النظام timer_create(2)

الاسم

timer_create - إنشاء مؤقت POSIX لكل عملية

المكتبة

مكتبة الوقت الحقيقي (librt, -lrt)

الملخص

#include <signal.h>           /* تعريف ثوابت SIGEV_* */
#include <time.h>
int timer_create(clockid_t clockid,
                 struct sigevent *_Nullable restrict sevp,
                 timer_t *restrict timerid);
متطلبات ماكرو اختبار الميزات لـ glibc (انظر feature_test_macros(7)):

timer_create():

    _POSIX_C_SOURCE >= 199309L

الوصف

يقوم timer_create() بإنشاء مؤقت فاصل جديد لكل عملية. يتم إرجاع معرف المؤقت الجديد في المخزن المؤقت المشار إليه بواسطة timerid، والذي يجب أن يكون مؤشرًا غير فارغ. هذا المعرف فريد ضمن العملية، حتى يتم حذف المؤقت. يكون المؤقت الجديد غير مفعل مبدئيًا.

يحدد الوسيط clockid الساعة التي يستخدمها المؤقت الجديد لقياس الوقت. يمكن تحديده كأحد القيم التالية:

CLOCK_REALTIME
ساعة حقيقية قابلة للضبط على مستوى النظام.
CLOCK_MONOTONIC
ساعة تزايدية بشكل رتيب غير قابلة للضبط تقيس الوقت من نقطة غير محددة في الماضي لا تتغير بعد بدء تشغيل النظام.
CLOCK_PROCESS_CPUTIME_ID (منذ Linux 2.6.12)
ساعة تقيس وقت وحدة المعالجة المركزية (المستخدم والنظام) الذي تستهلكه (جميع خيوط) العملية المتصلة.
CLOCK_THREAD_CPUTIME_ID (منذ Linux 2.6.12)
ساعة تقيس وقت وحدة المعالجة المركزية (المستخدم والنظام) الذي تستهلكه الخيط المتصل.
CLOCK_BOOTTIME (منذ Linux 2.6.39)
مثل CLOCK_MONOTONIC، هذه ساعة تزايدية بشكل رتيب. ومع ذلك، بينما لا تقيس ساعة CLOCK_MONOTONIC الوقت أثناء تعليق النظام، تتضمن ساعة CLOCK_BOOTTIME الوقت الذي يكون فيه النظام معلقًا. هذا مفيد للتطبيقات التي تحتاج إلى أن تكون مدركة للتعليق. CLOCK_REALTIME غير مناسب لمثل هذه التطبيقات، حيث تتأثر تلك الساعة بالتغييرات غير المتصلة في ساعة النظام.
CLOCK_REALTIME_ALARM (منذ Linux 3.0)
هذه الساعة تشبه CLOCK_REALTIME، لكنها ستوقظ النظام إذا كان معلقًا. يجب أن يمتلك المتصل صلاحية CAP_WAKE_ALARM لضبط مؤقت ضد هذه الساعة.
CLOCK_BOOTTIME_ALARM (منذ Linux 3.0)
هذه الساعة تشبه CLOCK_BOOTTIME، لكنها ستوقظ النظام إذا كان معلقًا. يجب أن يمتلك المتصل صلاحية CAP_WAKE_ALARM لضبط مؤقت ضد هذه الساعة.
CLOCK_TAI (منذ Linux 3.10)
ساعة على مستوى النظام مشتقة من وقت الساعة الحالية ولكن مع احتساب الثواني الكبيسة.

انظر clock_getres(2) لبعض التفاصيل الإضافية حول الساعات المذكورة أعلاه.

بالإضافة إلى القيم أعلاه، يمكن تحديد clockid كـ clockid الذي تم إرجاعه بواسطة استدعاء لـ clock_getcpuclockid(3) أو pthread_getcpuclockid(3).

يشير الوسيط sevp إلى بنية sigevent تحدد كيفية إعلام المتصل عند انتهاء صلاحية المؤقت. لتعريف وتفاصيل عامة لهذه البنية، انظر sigevent(3type).

يمكن أن يأخذ الحقل sevp.sigev_notify القيم التالية:

SIGEV_NONE
لا تقم بإعلام غير متزامن عند انتهاء صلاحية المؤقت. يمكن مراقبة تقدم المؤقت باستخدام timer_gettime(2).
SIGEV_SIGNAL
عند انتهاء صلاحية المؤقت، قم بتوليد الإشارة sigev_signo للعملية. انظر sigevent(3type) للتفاصيل العامة. سيتم تعيين الحقل si_code للبنية siginfo_t إلى SI_TIMER. في أي وقت، يتم إدراج إشارة واحدة على الأكثر للعملية لإشارة معينة؛ انظر timer_getoverrun(2) لمزيد من التفاصيل.
SIGEV_THREAD
عند انتهاء صلاحية المؤقت، استدعِ sigev_notify_function كما لو كانت دالة البداية لخيط جديد. انظر sigevent(3type) للتفاصيل.
SIGEV_THREAD_ID (خاص بـ Linux)
كما هو الحال مع SIGEV_SIGNAL، ولكن يتم استهداف الإشارة للخيط الذي يعرفه sigev_notify_thread_id، والذي يجب أن يكون خيطًا في نفس العملية مثل المتصل. يحدد الحقل sigev_notify_thread_id معرف خيط نواة، أي القيمة التي تم إرجاعها بواسطة clone(2) أو gettid(2). هذا العلم مخصص فقط لاستخدام مكتبات الخيوط.

تحديد sevp على أنه NULL يكافئ تحديد مؤشر إلى بنية sigevent يكون فيها sigev_notify هو SIGEV_SIGNAL، sigev_signo هو SIGALRM، و sigev_value.sival_int هو معرف المؤقت.

قيمة الإرجاع

عند النجاح، يعيد timer_create() القيمة 0، ويتم وضع معرف المؤقت الجديد في *timerid. عند الفشل، يتم إرجاع -1، ويتم تعيين errno للإشارة إلى الخطأ.

الأخطاء

EAGAIN
خطأ مؤقت أثناء تخصيص بنى المؤقت في النواة.
EINVAL
معرف الساعة، sigev_notify، sigev_signo، أو sigev_notify_thread_id غير صالح.
ENOMEM
لم يتمكن من تخصيص الذاكرة.
ENOTSUP
النواة لا تدعم إنشاء مؤقت ضد clockid هذا.
EPERM
كان clockid هو CLOCK_REALTIME_ALARM أو CLOCK_BOOTTIME_ALARM ولكن المتصل لم يكن لديه صلاحية CAP_WAKE_ALARM.

الإصدارات

الاختلافات بين مكتبة C والنواة

يتم توفير جزء من وظائف واجهة مؤقتات POSIX بواسطة glibc. على وجه الخصوص:

•
تم تنفيذ الكثير من الوظائف لـ SIGEV_THREAD داخل glibc، بدلاً من النواة. (هذا ضروري، نظرًا لأن الخيط المشارك في معالجة الإشعار هو خيط يجب أن تديره مكتبة C لتطبيق خيوط POSIX). على الرغم من أن الإشعار الذي يتم تسليمه إلى العملية يكون عبر خيط، إلا أن تنفيذ NPTL داخليًا يستخدم قيمة sigev_notify SIGEV_THREAD_ID جنبًا إلى جنب مع إشارة في الوقت الحقيقي محجوزة من قبل التنفيذ (انظر nptl(7)).
•
يتم تنفيذ الحالة الافتراضية حيث evp هو NULL داخل glibc، والتي تستدعي استدعاء النظام الأساسي مع بنية sigevent مملوءة بشكل مناسب.
•
تتم صيانة معرفات المؤقتات المقدمة على مستوى المستخدم بواسطة glibc، والتي تربط هذه المعرفات بمعرفات المؤقتات المستخدمة من قبل النواة.

التاريخ

Linux 2.6. POSIX.1-2001.

قبل Linux 2.6، وفرت glibc تطبيقًا غير كامل لمساحة المستخدم (مؤقتات CLOCK_REALTIME فقط) باستخدام خيوط POSIX، وقبل glibc 2.17، يعود التطبيق إلى هذه التقنية على الأنظمة التي تشغل نواة أقدم من Linux 2.6.

ملاحظات

قد يقوم برنامج بإنشاء مؤقتات فاصلة متعددة باستخدام timer_create().

لا يتم وراثة المؤقتات بواسطة الابن لـ fork(2)، ويتم تعطيلها وحذفها أثناء execve(2).

تقوم النواة بتخصيص مسبق لـ "إشارة وقت حقيقي معلقة" لكل مؤقت يتم إنشاؤه باستخدام timer_create(). نتيجة لذلك، يقتصر عدد المؤقتات على حد المورد RLIMIT_SIGPENDING (انظر setrlimit(2)).

تُعرف المؤقتات التي تم إنشاؤها بواسطة timer_create() عادةً باسم "مؤقتات POSIX (الفاصلة)". تتكون واجهة برمجة تطبيقات مؤقتات POSIX من الواجهات التالية:

timer_create()
إنشاء مؤقت.
timer_settime(2)
تفعيل (بدء) أو تعطيل (إيقاف) مؤقت.
timer_gettime(2)
جلب الوقت المتبقي حتى انتهاء صلاحية المؤقت التالي، إلى جانب إعداد الفاصلة للمؤقت.
timer_getoverrun(2)
إرجاع عدد مرات تجاوز انتهاء صلاحية المؤقت الأخير.
timer_delete(2)
تعطيل وحذف مؤقت.

منذ Linux 3.10، يمكن استخدام الملف /proc/pid/timers لسرد مؤقتات POSIX للعملية ذات PID pid. انظر proc(5) لمزيد من المعلومات.

منذ Linux 4.10، يعد دعم مؤقتات POSIX خيارًا قابلاً للتكوين يتم تمكينه افتراضيًا. يمكن تعطيل دعم النواة عبر الخيار CONFIG_POSIX_TIMERS.

أمثلة

يأخذ البرنامج التالي وسيطتين: فترة نوم بالثواني، وتردد مؤقت بالنانوثواني. يقوم البرنامج بإنشاء معالج للإشارة التي يستخدمها للمؤقت، يحظر هذه الإشارة، وينشئ ويفعل مؤقتًا تنتهي صلاحيته بالتردد المحدد، وينام لعدد الثواني المحدد، ثم يزيل حظر إشارة المؤقت. بافتراض أن المؤقت انتهت صلاحيته مرة واحدة على الأقل أثناء نوم البرنامج، سيتم استدعاء معالج الإشارة، ويعرض المعالج بعض المعلومات حول إشعار المؤقت. ينتهي البرنامج بعد استدعاء واحد لمعالج الإشارة.

في تشغيل المثال التالي، ينام البرنامج لمدة ثانية واحدة، بعد إنشاء مؤقت بتردد 100 نانوثانية. بحلول الوقت الذي تمت فيه إزالة حظر الإشارة وتسليمها، كان هناك حوالي عشرة ملايين تجاوز.


$ ./a.out 1 100;
إنشاء معالج للإشارة 34
حظر الإشارة 34
معرف المؤقت هو 0x804c008
النوم لمدة 1 ثانية
إزالة حظر الإشارة 34
تم التقاط الإشارة 34
    sival_ptr = 0xbfb174f4;     *sival_ptr = 0x804c008
    عدد مرات تجاوز انتهاء الصلاحية = 10004886

مصدر البرنامج

#include <err.h>
#include <signal.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <time.h>
#include <unistd.h>
#define CLOCKID CLOCK_REALTIME
#define SIG SIGRTMIN
static void
print_siginfo(siginfo_t *si)
{
    int      or;
    timer_t  *tidp;
    tidp = si->si_value.sival_ptr;
    printf("    sival_ptr = %p; ", si->si_value.sival_ptr);
    printf("    *sival_ptr = %#jx\n", (uintmax_t) *tidp);
    or = timer_getoverrun(*tidp);
    if (or == -1)
        err(EXIT_FAILURE, "timer_getoverrun");
    printf("    عدد مرات تجاوز انتهاء الصلاحية = %d\n", or);
}
static void
handler(int sig, siginfo_t *si, void *uc)
{
    /* ملاحظة: استدعاء printf() من معالج إشارة ليس آمنًا
       (ولا ينبغي القيام به في برامج الإنتاج)، لأن
       printf() ليس آمنًا مع الإشارات غير المتزامنة؛ انظر signal-safety(7).
       ومع ذلك، نستخدم printf() هنا كطريقة بسيطة لـ
       إظهار أنه تم استدعاء المعالج.  */
    printf("تم التقاط الإشارة %d\n", sig);
    print_siginfo(si);
    signal(sig, SIG_IGN);
}
int
main(int argc, char *argv[])
{
    timer_t            timerid;
    sigset_t           mask;
    long long          freq_nanosecs;
    struct sigevent    sev;
    struct sigaction   sa;
    struct itimerspec  its;
    if (argc != 3) {
        fprintf(stderr, "الاستخدام: %s <sleep-secs> <freq-nanosecs>\n",
                argv[0]);
        exit(EXIT_FAILURE);
    }
    /* إنشاء معالج لإشارة المؤقت.  */
    printf("إنشاء معالج للإشارة %d\n", SIG);
    sa.sa_flags = SA_SIGINFO;
    sa.sa_sigaction = handler;
    sigemptyset(&sa.sa_mask);
    if (sigaction(SIG, &sa, NULL) == -1)
        err(EXIT_FAILURE, "sigaction");
    /* حظر إشارة المؤقت مؤقتًا.  */
    printf("حظر الإشارة %d\n", SIG);
    sigemptyset(&mask);
    sigaddset(&mask, SIG);
    if (sigprocmask(SIG_SETMASK, &mask, NULL) == -1)
        err(EXIT_FAILURE, "sigprocmask");
    /* إنشاء المؤقت.  */
    sev.sigev_notify = SIGEV_SIGNAL;
    sev.sigev_signo = SIG;
    sev.sigev_value.sival_ptr = &timerid;
    if (timer_create(CLOCKID, &sev, &timerid) == -1)
        err(EXIT_FAILURE, "timer_create");
    printf("معرف المؤقت هو %#jx\n", (uintmax_t) timerid);
    /* بدء المؤقت.  */
    freq_nanosecs = atoll(argv[2]);
    its.it_value.tv_sec = freq_nanosecs / 1000000000;
    its.it_value.tv_nsec = freq_nanosecs % 1000000000;
    its.it_interval.tv_sec = its.it_value.tv_sec;
    its.it_interval.tv_nsec = its.it_value.tv_nsec;
    if (timer_settime(timerid, 0, &its, NULL) == -1)
         err(EXIT_FAILURE, "timer_settime");
    /* النوم لفترة؛ في هذه الأثناء، قد تنتهي صلاحية المؤقت
       مرات متعددة.  */
    printf("النوم لمدة %d ثوانٍ\n", atoi(argv[1]));
    sleep(atoi(argv[1]));
    /* فتح قفل إشارة المؤقت، حتى يمكن تسليم إشعار المؤقت.  */
    printf("إزالة حظر الإشارة %d\n", SIG);
    if (sigprocmask(SIG_UNBLOCK, &mask, NULL) == -1)
        err(EXIT_FAILURE, "sigprocmask");
    exit(EXIT_SUCCESS);
}
