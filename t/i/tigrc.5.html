tigrc(5)

الحزمة: tig

التراخيص: GPL

TIGRC(5) يدوي Tig TIGRC(5)

الاسم

tigrc - ملف تكوين Tig

الملخص

set   متغير = قيمة
bind  خريطة مفاتيح مفتاح إجراء
color منطقة لون أمامي لون خلفي [سمات]
source مسار

الوصف

يمكنك تعيين خيار بشكل دائم عن طريق وضعه في ملف ~/.tigrc. يتكون الملف من سلسلة من الأوامر. قد يحتوي كل سطر في الملف على أمر واحد فقط. يمكن أن تمتد الأوامر عبر عدة أسطر إذا كان كل سطر ينتهي بحرف الشرطة المائلة العكسية (\).

يُستخدم رمز الهاش (#) كحرف تعليق. يتم تجاهل كل النص بعد رمز التعليق حتى نهاية السطر. يمكنك استخدام التعليقات لشرح ملف التهيئة الخاص بك.

يمكن التلاعب ببعض الخيارات في وقت التشغيل عبر قائمة الخيارات. بالإضافة إلى ذلك، يمكن أيضًا تبديل الخيارات باستخدام أمر المطالبة :toggle أو عن طريق إدخال أمر التكوين في المطالبة.

في بعض البيئات، سيتم تخزين تكوين المستخدم في الموقع البديل $XDG_CONFIG_HOME/tig/config. للاختصار، سيشير هذا المستند فقط إلى ~/.tigrc.

تكوين Git

بدلاً من استخدام ~/.tigrc، يمكن تعيين خيارات Tig عن طريق وضعها في أحد ملفات تكوين Git، والتي يقرأها Tig عند بدء التشغيل. انظر git-config(1) لمعرفة الملفات التي يجب استخدامها. توضح الأمثلة التالية بناء الجملة الأساسي لاستخدامه في الإعدادات والربط والألوان.

[tig] show-changes = true
[tig "color"] cursor = yellow red bold
[tig "bind"] generic = P parent

بالإضافة إلى الخيارات الخاصة بـ tig، يتم قراءة خيارات Git التالية من تكوين Git:

color.*

ألوان لأنواع واجهة المستخدم المختلفة. يمكن تكوينها عبر الإعداد git-colors.

core.abbrev

عرض معرف الالتزام (commit ID). انظر أيضًا الخيار id-width.

core.editor

أمر المحرر. يمكن تجاوزه عن طريق تعيين TIG_EDITOR أو GIT_EDITOR.

core.worktree

مسار جذر شجرة العمل.

gui.encoding

الترميز المستخدم لعرض محتوى الملف.

i18n.commitencoding

الترميز المستخدم للالتزامات (commits). الافتراضي هو UTF-8.

أمر SET

يمكن تكوين عدد قليل من المتغيرات الانتقائية باستخدام أمر set. الصيغة هي:

set متغيرات = قيمة

أمثلة:

set commit-order = topo         # ترتيب الالتزامات بشكل طوبولوجي
set git-colors = no             # عدم قراءة إعدادات ألوان Git.
set horizontal-scroll = 33%     # تمرير 33% من عرض العرض
set blame-options = -C -C -C    # ألقِ باللوم على أسطر من ملفات أخرى
# لف أسماء الفروع بين قوسين () والعلامات بين <>
set reference-format = (branch) <tag>
# تكوين أعمدة عرض التتبع باستخدام أمر يمتد عبر عدة أسطر.
set blame-view = \
        date:default \
        author:abbreviated \
        committer:abbreviated \
        file-name:auto \
        id:yes,color \
        line-number:yes,interval=5 text

أو في ملفات تكوين Git:

[tig]
        line-graphics = no      # تعطيل أحرف الرسوم
        tab-size = 8            # عدد المسافات لكل علامة جدولة

نوع المتغيرات هو إما bool (قيمة منطقية)، int (عدد صحيح)، string (سلسلة نصية)، أو mixed (مختلط)..

قيم bool صالحة

لتعيين متغير منطقي إلى true، استخدم إما "1" أو "true" أو "yes". أي قيمة أخرى ستعين المتغير إلى false.

قيم int صالحة

عدد صحيح غير سالب.

قيم string صالحة

سلسلة من الأحرف. اختياريًا، استخدم ' أو " كفواصل.

قيم مختلطة صالحة

هذه القيم هي مجموعات من الأنواع المذكورة أعلاه. القيم الصالحة محددة في الوصف.

المتغيرات

يمكن تعيين المتغيرات التالية:

diff-options (string)

سلسلة مفصولة بمسافات من خيارات diff لاستخدامها في عرض diff. يتم استخدام git-show(1) للتنسيق ويمرر دائمًا --patch-with-stat. يمكن التحكم في عرض البيانات الوصفية لرأس الالتزام (commit header)، عن طريق تمرير الخيار --format. يتجاوز هذا الخيار أي خيارات محددة في متغير البيئة TIG_DIFF_OPTS (الموصوف في tig(1))، ولكنه يتجاوز بدوره خيارات diff المقدمة في استدعاء سطر الأوامر.

blame-options (string)

سلسلة مفصولة بمسافات من خيارات blame الافتراضية. يمكن استخدامها لإخبار git-blame(1) بكيفية اكتشاف مصدر الأسطر. يتم تجاهل الخيارات عند بدء Tig في وضع blame وتمرير خيارات blame في سطر الأوامر.

log-options (string)

سلسلة مفصولة بمسافات من الخيارات الافتراضية التي يجب تمريرها إلى أمر git-log(1) المستخدم بواسطة عرض السجل (log view). يمكن تجاوز الخيارات بواسطة خيارات سطر الأوامر. تستخدم داخليًا لتجاوز إعدادات ‘pretty.format’ المخصصة التي تكسر عرض السجل.

main-options (string)

سلسلة مفصولة بمسافات من الخيارات الافتراضية التي يجب تمريرها إلى أمر git-log(1) المستخدم بواسطة العرض الرئيسي (main view). يمكن تجاوز الخيارات بواسطة خيارات سطر الأوامر.

reference-format (string)

سلسلة مفصولة بمسافات من سلاسل التنسيق المستخدمة لتنسيق أسماء المراجع. قم بلف اسم نوع المرجع بالأحرف التي ترغب في استخدامها للتنسيق، على سبيل المثال [tag] و <remote>. إذا لم يتم تحديد تنسيق لـ local-tag، يتم استخدام تنسيق tag. وبالمثل، إذا لم يتم تحديد تنسيق لـ tracked-remote، يتم استخدام تنسيق remote، وإذا لم يتم تحديد تنسيق لأي نوع مرجع آخر، يتم استخدام تنسيق branch. قم بالبادئة بـ hide: لعدم إظهار نوع المرجع هذا، على سبيل المثال hide:remote. أنواع المراجع المدعومة هي:
•head : رأس الالتزام الحالي (HEAD).
•tag : علامة مشروحة (annotated tag).
•local-tag : علامة خفيفة (lightweight tag).
•remote : مرجع بعيد (remote reference).
•tracked-remote : المرجع البعيد الذي يتتبعه الرأس الحالي.
•replace : مرجع مستبدل.
•branch : فرع.
•stash : مخزن الـ stash.
•note : ملاحظات.
•prefetch : مراجع تم جلبها مسبقًا بواسطة صيانة git.
•other : أي مرجع آخر.

line-graphics (mixed) [ascii|default|utf-8|auto|]

نوع الرسومات الحرفية للرسم الخطي. "auto" تعني "utf-8" إذا كانت اللغة المحلية UTF-8، و "default" بخلاف ذلك.

truncation-delimiter (mixed) [utf-8|]

حرف واحد للرسم حيث يتم اقتطاع الأعمدة. الافتراضي هو "~". تشير القيمة الخاصة "utf-8" إلى الحرف "..." ("Midline Horizontal Ellipsis").

horizontal-scroll (mixed)

فاصل زمني للتمرير أفقيًا في كل خطوة. يمكن تحديده إما كرقم أعمدة، على سبيل المثال 5، أو كنسبة مئوية من عرض العرض، على سبيل المثال 33%، حيث الحد الأقصى هو 100%. بالنسبة للنسب المئوية، يتم دائمًا ضمان تمرير عمود واحد على الأقل. الافتراضي هو التمرير 50% من عرض العرض.

git-colors (list)

قائمة مفصولة بمسافات من أزواج "key=value" حيث يكون المفتاح اسم لون Git والقيمة اسم لون Tig، على سبيل المثال "branch.current=main-head" و "grep.filename=grep.file". اضبطه على "no" لتعطيله.

show-notes (mixed) [|]

ما إذا كان سيتم عرض ملاحظات لالتزام معين. عند تعيينه إلى مرجع ملاحظات، يتم تمرير المرجع إلى git show --notes=. الملاحظات ممكّنة بشكل افتراضي.

show-changes (bool)

ما إذا كان سيتم عرض التغييرات المعدة (staged) وغير المعدة (unstaged) في العرض الرئيسي.

show-untracked (bool)

ما إذا كان سيتم عرض التغييرات غير المتتبعة أيضًا في العرض الرئيسي.

vertical-split (mixed) [auto|]

ما إذا كان سيتم تقسيم العرض أفقيًا أو رأسيًا

ما لم يُذكر خلاف ذلك، يتم تشغيل الأوامر في الواجهة الأمامية مع عرض مخرجات وحدة التحكم الخاصة بها (كما لو تم تحديد !). عندما يتم تحديد خيارات أوامر متعددة، يتم دمج سلوكها، على سبيل المثال، "?<git commit" سيطالب المستخدم عما إذا كان سيتم تنفيذ الأمر وسيتم إنهاء Tig بعد الانتهاء.

لاحظ أنه إذا كنت ترغب في استخدام الأنابيب أو إعادة التوجيه في أوامرك، فيجب عليك تشغيلها في صدفة فرعية، أي تضمين أوامرك في sh -c '<commands>'.

تصفح متغيرات الحالة

يمكن للأوامر المعرفة من قبل المستخدم أن تشير اختياريًا إلى الحالة الداخلية لـ Tig باستخدام أسماء المتغيرات التالية، والتي يتم استبدالها قبل تشغيل الأوامر:

%(head) معرف الرأس الحالي المعروض. الافتراضي هو HEAD
%(commit) معرف الالتزام المحدد حاليًا.
%(blob) معرف الـ blob المحدد حاليًا.
%(branch) اسم الفرع المحدد حاليًا.
%(remote) اسم المستودع البعيد المحدد حاليًا. بالنسبة للفروع البعيدة، سيحتوي %(branch) على اسم الفرع.
%(tag) اسم العلامة المحددة حاليًا.
%(refname) اسم المرجع المحدد حاليًا بما في ذلك اسم المستودع البعيد للفروع البعيدة.
%(stash) اسم الـ stash المحدد حاليًا.
%(directory) مسار الدليل الحالي في عرض الشجرة أو "." إذا لم يكن محددًا.
%(file) الملف المحدد حاليًا.
%(file_old) اسم الملف القديم للملف المحدد حاليًا.
%(lineno) رقم السطر المحدد حاليًا. الافتراضي هو 0.
%(lineno_old) رقم السطر المحدد حاليًا، قبل تطبيق الفرق. الافتراضي هو 0.
%(ref) المرجع المحدد لـ blame أو HEAD إذا لم يكن محددًا.
%(revargs) وسيطات المراجعة التي تم تمريرها في سطر الأوامر.
%(fileargs) وسيطات الملف التي تم تمريرها في سطر الأوامر.
%(cmdlineargs) جميع الخيارات الأخرى التي تم تمريرها في سطر الأوامر.
%(diffargs) خيارات من diff-options أو TIG_DIFF_OPTS المستخدمة في عرض الفرق والتثبيت.
%(blameargs) خيارات من blame-options المستخدمة في عرض blame.
%(logargs) خيارات من log-options المستخدمة في عرض log.
%(mainargs) خيارات من main-options المستخدمة في العرض الرئيسي.
%(prompt) مطالبة بقيمة الوسيطة. يمكنك تحديد مطالبة مخصصة اختياريًا باستخدام "%(prompt Enter branch name: )"
%(text) عمود النص للسطر المحدد حاليًا.
%(repo:head) اسم الفرع الذي تم سحبه، على سبيل المثال، master
%(repo:head-id) معرف الالتزام للفرع الذي تم سحبه.
%(repo:remote) اسم المستودع البعيد المرتبط بالفرع الذي تم سحبه، على سبيل المثال، origin.
%(repo:upstream) فرع المنبع المرتبط بالفرع الذي تم سحبه، على سبيل المثال، origin/master.
%(repo:cdup) مسار لتغيير الدليل إلى جذر المستودع، على سبيل المثال، ../
%(repo:prefix) بادئة المسار للدليل العامل الحالي، على سبيل المثال subdir/.
%(repo:git-dir) مسار دليل Git، على سبيل المثال، /src/repo/.git.
%(repo:worktree) مسار شجرة العمل، إذا تم تعريفه.
%(repo:is-inside-work-tree) ما إذا كان Tig يعمل داخل شجرة عمل، إما true أو false.

أمثلة:

# حفظ الالتزام الحالي كملف تصحيح عند تحديد المستخدم لالتزام
# في العرض الرئيسي ويضغط على 'S'.
bind main S !git format-patch -1 %(commit)
# إنشاء فرع جديد وسحبه؛ تحديد مطالبة مخصصة
bind main B ?git checkout -b "%(prompt Enter new branch name: )"
# عرض إحصائيات الالتزام للمؤلف تحت المؤشر
bind main U +sh -c 'git --no-pager shortlog -s --author="$(git show -s --format=%aE %(commit))" </dev/tty'

أوامر شبيهة بالصدفة متقدمة

إذا كان أمرك يتطلب استخدام ميزات ديناميكية، مثل الصدف الفرعية، وتوسيع متغيرات البيئة، والتحكم في العمليات، يمكن تحقيق ذلك باستخدام أمر صدفة:

مثال 1. تكوين ربط لنسخ معرف الالتزام الحالي إلى الحافظة.

bind generic I @sh -c "echo -n %(commit) | xclip -selection c"

أو باستخدام مزيج من أسماء مستعارة لـ Git وأوامر Tig الخارجية. يمكن وضع الأمثلة التالية في ملف .gitconfig أو .git/config:

مثال 2. تكوين Git يربط مفاتيح Tig بأسماء مستعارة لأوامر Git.

[alias]
        gitk-bg = !"gitk HEAD --not $(git rev-parse --remotes) &"
        publish = !"for i in origin public; do git push $i; done"
[tig "bind"]
        generic = V @git gitk-bg
        generic = > !git publish

أوامر داخلية معرفة من قبل المستخدم

سيتم تشغيل الإجراءات التي تبدأ بـ : وتفسيرها كأوامر داخلية وستتصرف بشكل مشابه للأوامر التي يتم تشغيلها عبر مطالبة Tig. الأوامر الداخلية الصالحة هي خيارات ملف التكوين (كما هو موضح في هذه الوثيقة) وأوامر عرض المُنقح. أمثلة:

# إعادة تحميل ~/.tigrc عند الضغط على 'S'
bind generic S :source .tigrc
# تغيير عرض الفرق لإظهار جميع تغييرات الالتزام بغض النظر عن قيود الملف
bind diff F :set diff-options = --full-diff
# عرض مخرجات git-reflog(1) في عرض المُنقح
bind generic W :!git reflog
# البحث عن كتلة فرق (c) سابقة ورأس فرق تالي
bind stage 2 :?^@@
bind stage D :/^diff --(git|cc)
bind main I :toggle id                          # إظهار/إخفاء عمود المعرف
bind diff D :toggle diff-options --minimal      # استخدام خوارزمية فرق الحد الأدنى
bind diff [ :toggle diff-context -3             # تقليل السياق (-U arg)
bind diff ] :toggle diff-context +3             # زيادة السياق
bind generic V :toggle split-view-height -10%   # تقليل ارتفاع التقسيم

على غرار الأوامر الخارجية، يمكن لأوامر عرض المُنقح أن تحتوي على أسماء متغيرات سيتم استبدالها قبل تشغيل الأمر.

COLOR COMMAND

Color commands control highlighting and the user interface styles. If your terminal supports color, these commands can be used to assign foreground and background combinations to certain areas. Optionally, an attribute can be given as the last parameter. The syntax is:

color area fgcolor bgcolor [attributes]

Examples:

# Override the default terminal colors to white on black.
color default           white   black
# Diff colors
color diff-header       yellow  default
color diff-index        blue    default
color diff-chunk        magenta default
color "Reported-by:"    green   default
# View-specific color
color tree.date         black   cyan    bold
# Custom color
color "/(note|warning|error):/" yellow  default bold

Or in the Git configuration files:

[tig "color"]
        # A strange looking cursor line
        cursor          = red   default underline
        # UI colors
        title-blur      = white blue
        title-focus     = white blue    bold
# View-specific color
[tig "color.tree"]
        date            = cyan  default bold

Area names

Can be either a built-in area name or a custom quoted string. The latter allows custom color rules to be added for lines matching a quoted string. Strings of the form "/.../" are interpreted as regular expressions. Valid built-in area names are described below. Note, all names are case-insensitive, and you may use -, and _ interchangeably, e.g. "Diff-Header" and "DIFF_HEADER" are the same. View-specific colors can be defined by prefixing the view name to the area name, e.g. "stage.diff-chunk" and "diff.diff-chunk".

Color names

Valid colors include: white, black, green, magenta, blue, cyan, yellow, red, default. Use default to refer to the default terminal colors, for example, to keep the background transparent when you are using a terminal with a transparent background.

Colors can also be specified using the keywords color0, color1, ..., colorN-1 (where N is the number of colors supported by your terminal). This is useful when you remap the colors for your display or want to enable colors supported by 88-color and 256-color terminals. Note that the color prefix is optional. If you prefer, you can specify colors directly by their numbers 0, 1, ..., N-1 instead, just like in the configuration file of Git.

Attribute names

Valid attributes include: normal, blink, bold, dim, reverse, standout, and underline. Note, not all attributes may be supported by the terminal.

UI colors

The colors and attributes to be used for the text that is not highlighted or that specify the use of the default terminal colors can be controlled by setting the default color option.
