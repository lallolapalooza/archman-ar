tig - واجهة وضع النص لـ Git

الموجز

الوصف

Tig هي واجهة وضع نص تستند إلى ncurses لـ git(1). تعمل بشكل أساسي كمتصفح لمستودع Git، ولكن يمكنها أيضًا المساعدة في مرحلة التغييرات للالتزام على مستوى القطعة وتعمل كـ pager لمخرجات أوامر Git المختلفة.

الخيارات

تشمل خيارات سطر الأوامر التي يتعرف عليها Tig جميع خيارات git-log(1) و git-diff(1) الصالحة، بالإضافة إلى الأوامر الفرعية التالية وخيارات Tig الخاصة. يُفسر المعامل الأول لسطر الأوامر الذي لا يبدأ بـ "-" على أنه مواصفات مراجعة أو مسار وينتهي بتحليل الخيارات. سيتم تمرير جميع الخيارات الإضافية إلى أمر Git الأساسي.

لاحظ أن هذا يعني أنه يجب تحديد أي معاملات للخيارات معًا. على سبيل المثال، قم بتشغيل tig -Sfoo بدلاً من tig -S foo، و tig --grep=foo بدلاً من tig --grep foo، وإلا فسيتم تفسير foo على أنها مراجعة وليست معاملًا.

show

افتح عرض الاختلاف باستخدام خيارات git-show(1) المحددة.

blame

عرض الملف المحدد مع تعليقات توضيحية بواسطة الالتزامات. يأخذ صفرًا أو أكثر من خيارات git-blame(1). قد يكون مقيدًا اختياريًا من المراجعة المحددة.

status

ابدأ في وضع العرض.

log

ابدأ في وضع السجل، وعرض مخرجات git-log(1).

reflog

ابدأ في وضع reflog.

refs

ابدأ في وضع refs. يتم عرض جميع المراجع ما لم يتم تحديدها باستخدام أحد المعاملات --branches أو --remotes أو --tags.

stash

ابدأ في وضع stash.

grep

افتح عرض grep. يدعم نفس خيارات git-grep(1).

+<number>

اعرض العرض الأول مع ظهور السطر <number> وتحديده.

-v, --version

عرض الإصدار والخروج.

-h, --help

عرض رسالة المساعدة والخروج.

-C <path>

قم بالتشغيل كما لو تم تشغيل Tig في <path> بدلاً من الدليل الحالي.

وضع PAGER

يدخل Tig في وضع Pager عند توفير الإدخال عبر stdin ويدعم الأوامر الفرعية والخيارات التالية:

•؛ عند تحديد الأمر الفرعي show وإعطاء الخيار --stdin، يُفترض أن stdin هي قائمة بمعرفات الالتزام وسيتم توجيهها إلى أمر git-show(1) الأساسي لعرض الاختلاف. على سبيل المثال:

$ git rev-list --author=vivien HEAD | tig show --stdin
•؛ عند إعطاء --stdin، يُفترض أن stdin هي قائمة بمعرفات الالتزام وسيتم توجيهها إلى أمر git-log(1) الأساسي للعرض الرئيسي. على سبيل المثال:

$ tig --no-walk --stdin < cherry-picks.txt
•؛ عند إعطاء --pretty=raw، يُفترض أن stdin هي مخرجات بتنسيق "pretty=raw" مشابهة لمخرجات git-log(1). على سبيل المثال:

$ git reflog --pretty=raw | tig --pretty=raw

عند عدم وجود أوامر فرعية أو خيارات، سيتم استخدام عرض Pager لعرض إدخال أمر Git المعطى على stdin. يفترض عرض Pager أن الإدخال إما من git-log(1) أو git-diff(1) وسيقوم بتمييزه بشكل مشابه لعرضي log و diff. على سبيل المثال:

$ git log -Schange -p --raw | tig

أمثلة

عرض قائمة الالتزامات للفرع الحالي:

$ tig

عرض الالتزامات من فرع واحد أو أكثر:

$ tig test master

تظاهر كما لو كانت جميع المراجع في refs/ مدرجة على سطر الأوامر:

$ tig --all

عرض الاختلافات بين فرعين:

$ tig test..master

عرض التغييرات لإصدارات الوحدات الفرعية:

$ tig --submodule

عرض التغييرات لملف واحد:

$ tig -- README

عرض محتويات ملف README في مراجعة معينة:

$ tig show tig-0.8:README

عرض المراجعات بين تاريخين لملف معين:

$ tig --after="2004-01-01" --before="2006-05-16" -- README

ملف Blame مع تمكين اكتشاف النسخ:

$ tig blame -C README

عرض قائمة الـ stashes:

$ tig stash

البحث عن جميع الملفات عن الأسطر التي تحتوي على DEFINE_ENUM:

$ tig grep -p DEFINE_ENUM

عرض المراجع (الفروع، المراجع عن بعد، والعلامات):

$ tig refs

استخدام diff الكلمات في عرض diff:

$ tig --word-diff=plain

متغيرات البيئة

بالإضافة إلى متغيرات البيئة التي تستخدمها Git (مثل GIT_DIR)، يحدد Tig المتغيرات أدناه. متغيرات البيئة المتعلقة بالأوامر لديها وصول إلى الحالة الداخلية لـ Tig عبر متغيرات الاستبدال، مثل %(commit) و %(blob). راجع tigrc(5) للحصول على قائمة كاملة.

TIGRC_USER

مسار ملف تكوين المستخدم (افتراضيًا ~/.tigrc أو $XDG_CONFIG_HOME/tig/config).

TIGRC_SYSTEM

مسار ملف تكوين النظام (افتراضيًا {sysconfdir}/tigrc). قم بتعيينه إلى سلسلة فارغة لاستخدام التكوين المضمن.

TIG_LS_REMOTE

أمر استرداد جميع مراجع المستودع. يجب أن ينتج الأمر بيانات بنفس تنسيق git-ls-remote(1).

TIG_DIFF_OPTS

خيارات diff لاستخدامها في عرض diff. يستخدم عرض diff الأمر git-show(1) للتنسيق ويمرر دائمًا --patch-with-stat. يمكنك أيضًا تعيين إعداد diff-options في ملف التكوين.

TIG_TRACE

مسار ملف التتبع حيث يتم تسجيل معلومات حول أوامر Git.

TIG_SCRIPT

مسار النص البرمجي الذي يجب تنفيذه تلقائيًا عند بدء التشغيل. إذا تم تعريف متغير البيئة هذا إلى سلسلة فارغة، فسيتم قراءة النص البرمجي من stdin. يتم تفسير النص البرمجي سطرًا بسطر ويمكن أن يحتوي على أوامر موجه وتعيينات مفاتيح. لاحظ أنه يجب ترميز الحرف < كـ <LT> داخل النص البرمجي. 
E.g. TIG_SCRIPT=<(echo :set main-view-commit-title-graph = no) tig

TIG_NO_DISPLAY

افتح Tig دون عرض أي شيء على الطرفية. هذا يجبر Ncurses على الكتابة إلى /dev/null. الاستخدام الرئيسي هو للاختبار الآلي لـ Tig.

TIG_EDITOR

أمر المحرر للاستخدام عند زيارة الملفات. يتجاوز متغير البيئة هذا (حسب ترتيب الأسبقية) $GIT_EDITOR، و core.editor configuration، و $VISUAL، و $EDITOR، لذا يسمح باستخدام محرر مختلف عن الذي تستخدمه Git. القيمة مخصصة للتفسير بواسطة shell عند استخدامها.

الملفات

$XDG_CONFIG_HOME/tig/config، ~/.config/tig/config، ~/.tigrc

يتم تحميل ملف تكوين المستخدم Tig بالطريقة التالية. إذا تم تعيين $XDG_CONFIG_HOME، فاقرأ تكوين المستخدم من $XDG_CONFIG_HOME/tig/config. إذا كان $XDG_CONFIG_HOME فارغًا أو غير معرف، فاقرأ تكوين المستخدم من ~/.config/tig/config إذا كان موجودًا ثم ارجع إلى ~/.tigrc إذا لم يكن موجودًا. راجع tigrc(5) للحصول على أمثلة.

/etc/tigrc

ملف تكوين على مستوى النظام.

$GIT_DIR/config، ~/.gitconfig، /etc/gitconfig

ملفات تكوين Git

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

les. اقرأ عند بدء التشغيل بمساعدة git-config(1).

$XDG_DATA_HOME/tig/history، ~/.local/share/tig/history، ~/.tig_history

عند الترجمة بدعم readline، يكتب Tig سجل الأوامر والبحث المستمر. يتم تحديد موقع ملف السجل على النحو التالي. إذا تم تعيين $XDG_DATA_HOME و $XDG_DATA_HOME/ موجود، فأنشئ $XDG_DATA_HOME/tig/ إذا لزم الأمر وخزن السجل في $XDG_DATA_HOME/tig/history. إذا كان $XDG_DATA_HOME فارغًا أو غير معرف، فخزن السجل في ~/.local/share/tig/history إذا كان الدليل ~/.local/share/tig/ موجودًا، وإلا فارجع إلى ~/.tig_history إذا لم يكن موجودًا.
