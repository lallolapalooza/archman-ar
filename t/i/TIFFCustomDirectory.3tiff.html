TIFFCUSTOMDIRECTORY(3tiff) LibTIFF TIFFCUSTOMDIRECTORY(3tiff)

الاسم

TIFFCustomDirectory - روتينات لإنشاء دليل مخصص

الموجز

#include <tiffio.h>
int TIFFCreateCustomDirectory(TIFF *tif, const TIFFFieldArray *infoarray)
int TIFFCreateEXIFDirectory(TIFF *tif)
int TIFFCreateGPSDirectory(TIFF *tif)
int TIFFWriteCustomDirectory(TIFF *tif, uint64 *pdiroff)
int TIFFReadCustomDirectory(TIFF *tif, toff_t diroff, const TIFFFieldArray *infoarray)
int TIFFReadEXIFDirectory(TIFF *tif, toff_t diroff)
int TIFFReadGPSDirectory(TIFF *tif, toff_t diroff)
const TIFFFieldArray *_TIFFGetExifFields(void)
const TIFFFieldArray *_TIFFGetGpsFields(void)

الوصف

تقوم الروتينات التالية بإنشاء دليل مخصص واسترداد معلومات حول الأدلة في ملف TIFF مفتوح.

TIFFCreateCustomDirectory()، TIFFCreateEXIFDirectory()، TIFFCreateGPSDirectory() ستقوم بإعداد دليل مخصص أو أحد الأدلة المحددة مسبقًا EXIF أو GPS وتعيين سياق المقبض TIFF tif إلى ذلك الدليل المخصص لوظائف مثل TIFFSetField().

TIFFWriteCustomDirectory() ستقوم بكتابة محتويات الدليل المخصص الحالي إلى الملف وإرجاع الإزاحة إلى ذلك الدليل في pdiroff. يجب كتابة تلك الإزاحة إلى IFD الرئيسي:

 /* العودة إلى الدليل الأول، وإضافة مؤشر EXIFIFD. */
TIFFSetDirectory(tif, 0);
TIFFSetField(tif, TIFFTAG_EXIFIFD, pdiroff);

TIFFReadCustomDirectory() ستقوم بقراءة الدليل المخصص من الإزاحة العشوائية إلى infoarray وتعيين سياق المقبض TIFF tif إلى ذلك الدليل المخصص لوظائف مثل TIFFReadField(). يجب أن يكون TIFFFieldArray infoarray متوافقًا مع تخطيط الدليل المخصص. بالنسبة لأدلة EXIF و GPS المحددة مسبقًا، يتم إخفاء تعريفات TIFFFieldArray ذات الصلة داخل وظائف TIFFReadEXIFDirectory() و TIFFReadGPSDirectory(). الكود مشابه جدًا لـ TIFFReadDirectory(). يجب قراءة الإزاحة إلى diroff الدليل المخصص من علامة TIFF النسبية أولاً.

_TIFFGetExifFields() و _TIFFGetGpsFields() ستعيد مؤشرًا إلى قائمة تعريفات العلامات الداخلية لـ EXIF و GPS من libtiff، على التوالي.

ملاحظات

كن على علم

  • أنه حتى يتم كتابة دليل إلى ملف وقراءته مرة أخرى، فإن وظائف الاستعلام لن تسترجع المعلومات الصحيحة!
  • أن الدليل الذي تم إنشاؤه حديثًا لن يكون موجودًا في الملف حتى يتم استدعاء TIFFWriteDirectory()، TIFFCheckpointDirectory()، TIFFFlush() أو TIFFClose().
  • أن TIFFCreateDirectory() و TIFFWriteDirectory() تنشئ دليلًا جديدًا، وتفرج عن بنية *tif وتنشئ واحدة جديدة.
  • أنه على عكس TIFFWriteDirectory()، فإن TIFFCheckpointDirectory() لا تفرج عن هياكل بيانات الدليل في الذاكرة.
  • أن LibTiff لا يدعم سلاسل الدلائل المخصصة (NextIFD يشير إلى IFD آخر). NextIFD للأدلة المخصصة دائمًا صفر ويجب أن يكون صفرًا عند القراءة.

للأسف، لإنشاء أو قراءة أدلة مخصصة ذات حقول محددة مسبقًا، من الضروري تضمين الملف الخاص tif_dir.h. ومع ذلك، بالنسبة لأدلة EXIF و GPS، التي لها مخطط محدد مسبقًا داخل libtiff، هذا ليس ضروريًا. هناك بعض برامج الاختبار التي توضح بإيجاز إنشاء وقراءة أدلة EXIF و GPS والأدلة المخصصة. انظر test/custom_dir.c و test/custom_dir_EXIF_231.c

تلميحات وتعليمات مفصلة

كتابة ملفات TIFF بأكثر من دليل واحد (IFD) ليست سهلة لأن بعض الآثار الجانبية تحتاج إلى معرفتها.

النقطة الرئيسية هنا هي أنه لا يمكن أن يكون هناك سوى بنية tif واحدة في الذاكرة الرئيسية للملف، والتي يمكنها فقط الاحتفاظ بعلامات دليل واحد في كل مرة. لا فائدة من العمل بمؤشرين مختلفين tiffOut1، tiffOut2، لأنه لا يوجد سوى كائن TIFF واحد (دليل TIFF) داخل libtiff. إذا كنت تريد معالجة دليل ثانٍ في الملف، فيجب أولاً حفظ علامات الدليل الحالي في الملف، وإلا فسيتم فقدانها (الكتابة فوقها أو خلطها). بعد ذلك، يجب تنظيف بنية tif في الذاكرة الرئيسية، وإلا فسيتم تضمين العلامات القديمة في الدليل الجديد. يمكن القيام بذلك إما عن طريق إنشاء بنية tif جديدة وفارغة أو عن طريق قراءة دليل تم حفظه مسبقًا في الملف.

التسلسل لمعالجة دليل TIFF ثانٍ (أو ثالث) - في هذه الحالة، GPS IFD - هو كما يلي:

1.
إنشاء ملف TIFF
2.
إكمال البيانات الوصفية "العادية"
3.
تعيين علامة الدليل المخصص بقيمة "وهمية" للحصول على العلامة محجوزة. سيتم إدراج القيمة النهائية لاحقًا. هذا يمنع الدليل الرئيسي من الكتابة إلى الملف مرة أخرى في منطقة إضافية، مع ترك منطقة الذاكرة الأولى غير مستخدمة:
TIFFSetField(tiffOut, TIFFTAG_GPSIFD, dir_offset);
4.
حفظ دليل TIFF الحالي إلى الملف. وإلا، سيتم فقده. تذكر أيضًا رقم الدليل الحالي:
TIFFWriteDirectory(tiffOut);
dirNum = TIFFCurrentDirectory(tiffOut);
5.
إنشاء دليل TIFF الثاني (مثل الدليل المخصص) وتعيين حقوله. يجب تحديد `TIFFFieldArray infoarray` مسبقًا في مكان ما في ملفات التضمين الخاصة بك. يتم تقديم مثال لدليل EXIF في tif_dirinfo.c
TIFFCreateCustomDirectory(tiffOut, infoarray);        /* لدليل مخصص حقيقي */
/* أو بدلاً من ذلك، استخدم GPS أو EXIF مع بنية حقل IFD TIFFFieldArray محددة مسبقًا */
TIFFCreateGPSDirectory(tiffOut);
TIFFSetField(tiffOut, GPSTAG_VERSIONID, gpsVersion);  /* تعيين حقول الدليل المخصص */

كن على علم أن كل TIFFCreateDirectory() أو TIFFWriteDirectory() تقوم على ما يبدو بإلغاء تخصيص بنية *tif وإعداد واحدة جديدة!

6.
كتابة الدليل المخصص إلى الملف. يتم إرجاع الإزاحة إلى ذلك الدليل في الملف في dir_offset.
TIFFWriteCustomDirectory(tiffOut, &dir_offset);
7.
إعادة تحميل الدليل الأول (أي دليل TIFF الأصلي). على ما يبدو، هذا يقرأ البيانات مرة أخرى من الملف.
TIFFSetDirectory(tiffOut, dirNum);
8.
تعيين قيمة الإزاحة الصحيحة لعلامة IFD للدليل المخصص وحفظ تلك التغييرات في الملف.
TIFFSetField(tiffOut, TIFFTAG_GPSIFD, dir_offset);
TIFFWriteDirectory(tiffOut);

قيم الإرجاع

TIFFCustomDirectory(3tiff) — libtiff — Arch Linux

NAME

TIFFCustomDirectory, TIFFWriteDirectory, TIFFWriteDirectorySec, TIFFWriteDirectorySubifd, TIFFWriteCustomDirectory — write TIFF directory to an open TIFF file

SYNOPSIS

#include <tiffio.h>

int
TIFFWriteDirectory(thandle_t fd, tdata_t dirbase, uint32_t nextdiroff);
int
TIFFWriteDirectorySec(thandle_t fd, tdata_t dirbase, uint32_t nextdiroff,
    uint32_t* next_subifd_offset);
int
TIFFWriteDirectorySubifd(thandle_t fd, tdata_t dirbase, uint32_t nextdiroff,
    uint32_t* next_subifd_offset);
int
TIFFWriteCustomDirectory(thandle_t fd, tdata_t dirbase, uint32_t nextdiroff,
    uint32_t* next_subifd_offset);

DESCRIPTION

The function TIFFWriteDirectory is used to write an image directory (also known as an Image File Directory or IFD) to the file associated with the open TIFF file descriptor fd. The directory contents are located in memory starting at the address dirbase. The nextdiroff parameter is the byte offset where the next directory should be written. This parameter is usually set to 0 when writing the first directory, or the offset of the previous directory when writing subsequent directories.

The TIFFWriteDirectorySec, TIFFWriteDirectorySubifd, and TIFFWriteCustomDirectory functions are variants of TIFFWriteDirectory that handle the writing of sub-IFDs.

The TIFF library maintains a list of directories associated with an open TIFF file. The TIFFWriteDirectory function writes the directory that is currently pointed to by the internal file state. This is typically the directory most recently created or set using TIFFCreateDirectory or TIFFSetDirectory.

The TIFFWriteDirectory function writes the directory structure, including all associated tag data, to the file at the current file offset. It then updates the file to point to the location of the next directory (if one exists) or the end of the file. The offset of the next directory is returned in nextdiroff.

TIFFWriteDirectorySec, TIFFWriteDirectorySubifd, and TIFFWriteCustomDirectory are used when dealing with specific types of TIFF structures, such as multi-page documents or image pyramids, where sub-IFDs are employed. The next_subifd_offset parameter is used to manage the offsets of these sub-IFDs.

NOTES

These functions are typically called internally by the TIFF library during the process of writing an image to a file. Direct use of these functions by application developers is generally not required unless they are working with specialized TIFF structures or custom directory formats.

HINTS AND DETAILED INSTRUCTIONS

When writing a TIFF file, the process usually involves creating a TIFF structure, setting up tags and data for each directory (image), and then writing these directories to the file. The TIFF library handles the details of calculating offsets and writing the directory structures.

The dirbase parameter should point to a memory buffer containing the prepared TIFF directory structure. This structure includes the directory entry count, the directory entries (tag, type, value offset), and any associated data. The TIFF library typically manages the allocation and population of this buffer.

The nextdiroff parameter is crucial for linking directories together. When writing the first directory, nextdiroff is often set to 0. The library then writes the first directory and returns the offset where the *next* directory should begin. This returned offset is then used as the nextdiroff parameter when writing the subsequent directory.

RETURN VALUES

1 is returned when the contents are successfully written to the file. Otherwise, 0 is returned if an error was encountered when writing the directory contents.

DIAGNOSTICS

All error messages are directed to the TIFFErrorExtR() routine. Likewise, warning messages are directed to the TIFFWarningExtR() routine.
