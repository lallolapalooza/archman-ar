إنشاء الخيوط وإنهاؤها

val create : ('a -> 'b) -> 'a -> t

Thread.create funct arg ينشئ خيط تحكم جديد، يتم فيه تنفيذ تطبيق الدالة funct arg بشكل متزامن مع الخيوط الأخرى في النطاق. تطبيق Thread.create يعيد مقبض الخيط المنشأ حديثًا. ينتهي الخيط الجديد عندما يعيد تطبيق funct arg، سواء بشكل طبيعي أو عن طريق إطلاق استثناء Thread.Exit أو عن طريق إطلاق أي استثناء آخر لم يتم التقاطه. في الحالة الأخيرة، يتم طباعة الاستثناء الذي لم يتم التقاطه على الخطأ القياسي، ولكنه لا ينتشر إلى الخيط الأصل. وبالمثل، يتم تجاهل نتيجة تطبيق funct arg ولا يمكن الوصول إليها مباشرة من قبل الخيط الأصل.

انظر أيضًا Domain.spawn إذا كنت تريد تنفيذًا متوازيًا بدلاً من ذلك.

val self : unit -> t

يعيد مقبض الخيط الحالي قيد التنفيذ.

val id : t -> int

يعيد معرف الخيط المعطى. معرف الخيط هو عدد صحيح يحدد الخيط بشكل فريد. يمكن استخدامه لبناء هياكل بيانات مفهرسة بالخيوط.

val set_current_thread_name : string -> unit

تعيين اسم الخيط. يجب استدعاء هذا من داخل دالة الخيط. تعيين اسم الخيط متاح على معظم الأنظمة.

هذا لا يفعل شيئًا إذا لم تكن الوظيفة مطبقة ولكنه سيطبع تحذيرًا على الخطأ القياسي إذا تم تمكينه.

وبالمثل، يتم طباعة تحذير إذا فشلت العملية.

منذ 5.4

exception Exit

استثناء يتم إطلاقه بواسطة كود المستخدم لبدء إنهاء الخيط الحالي. في خيط تم إنشاؤه بواسطة Thread.create funct arg، إذا وصل استثناء Thread.Exit إلى أعلى تطبيق funct arg، فإنه يؤدي إلى إنهاء الخيط الحالي بصمت. في سياقات أخرى، لا يوجد معالجة ضمنية لاستثناء Thread.Exit.

val exit : unit -> unit

مهمل. استخدم 'raise Thread.Exit' بدلاً من ذلك.

يطلق استثناء Thread.Exit. في خيط تم إنشاؤه بواسطة Thread.create، سيؤدي هذا إلى إنهاء الخيط مبكرًا، ما لم تعالج دالة الخيط الاستثناء بنفسها. سيتم تنفيذ النهائية والتعامل مع الاستثناءات الشاملة لـ Fun.protect.

لتوضيح أن استثناءً ما يتم إطلاقه وسيؤدي إلى تشغيل النهائيات ومعالجات الاستثناءات الشاملة، يوصى بكتابة raise Thread.Exit بدلاً من Thread.exit ().

قبل 5.0 تم استخدام تطبيق مختلف، ليس قائمًا على إطلاق استثناء، ولا يقوم بتشغيل النهائيات ومعالجات الاستثناءات الشاملة. كان للتطبيق السابق سلوك مختلف عند استدعائه خارج خيط تم إنشاؤه بواسطة Thread.create.

تعليق الخيوط

val delay : float -> unit

delay d يعلق تنفيذ الخيط المستدعي لمدة d ثانية. تستمر خيوط البرنامج الأخرى في العمل خلال هذا الوقت.

val join : t -> unit

join th يعلق تنفيذ الخيط المستدعي حتى ينتهي الخيط th.

val yield : unit -> unit

إعادة جدولة الخيط المستدعي دون تعليقه. يمكن استخدام هذه الدالة لإعطاء تلميحات جدولة، تخبر المجدول أن الوقت الحالي مناسب للتبديل إلى خيوط أخرى.

الانتظار لواصفات الملفات أو العمليات

الوظائف أدناه هي بقايا من نظام خيوط سابق يعتمد على الآلة الافتراضية. توفر وحدة Unix وظائف مماثلة، بطريقة أكثر عمومية وأكثر توافقًا مع المعايير. يوصى باستخدام وظائف Unix مباشرة.

val wait_timed_read : Unix.file_descr -> float -> bool

مهمل. استخدم Unix.select بدلاً من ذلك.

انظر Thread.wait_timed_write.

val wait_timed_write : Unix.file_descr -> float -> bool

مهمل. استخدم Unix.select بدلاً من ذلك.

يعلق تنفيذ الخيط المستدعي حتى يتوفر حرف واحد على الأقل أو EOF للقراءة ( wait_timed_read ) أو يمكن كتابة حرف واحد دون حظر ( wait_timed_write ) على واصف الملف Unix المحدد. انتظر لمدة أقصاها الوقت المحدد كمتوسط ثانٍ (بالثواني). يعيد true إذا كان واصف الملف جاهزًا للإدخال/الإخراج و false إذا انتهت المهلة. يمكن تحقيق نفس الوظائف باستخدام Unix.select.

val select : Unix.file_descr list -> Unix.file_descr list -> Unix.file_descr list -> float -> Unix.file_descr list * Unix.file_descr list * Unix.file_descr list

مهمل. استخدم Unix.select بدلاً من ذلك.

نفس وظيفة Unix.select. يعلق تنفيذ الخيط المستدعي حتى تصبح الإدخال/الإخراج ممكنة على واصفات الملفات Unix المحددة. الوسائط والنتائج لها نفس المعنى كما هو الحال بالنسبة لـ Unix.select.

val wait_pid : int -> int * Unix.process_status

مهمل. استخدم Unix.waitpid بدلاً من ذلك.

نفس وظيفة Unix.waitpid. wait_pid p يعلق تنفيذ الخيط المستدعي حتى تنتهي العملية المحددة بمعرف العملية p. يعيد معرّف الطفل الذي تم التقاطه وحالة إنهائه، وفقًا لـ Unix.wait.

إدارة الإشارات

تتبع معالجة الإشارات نموذج خيط POSIX: يتم تسليم الإشارات التي يولدها خيط إلى هذا الخيط؛ يتم تسليم الإشارات المولدة خارجيًا إلى أحد الخيوط التي لا تحظرها. يمتلك كل خيط مجموعة من الإشارات المحظورة، والتي يمكن تعديلها باستخدام Thread.sigmask. يتم وراثة هذه المجموعة عند إنشاء الخيط. يتم دعم أقنعة الإشارات لكل خيط فقط بواسطة مكتبة خيوط النظام تحت Unix، ولكن ليس تحت Win32، ولا بواسطة مكتبة خيوط الآلة الافتراضية.

val sigmask : Unix.sigprocmask_command -> int list -> int list

نفس وظيفة Unix.sigprocmask. sigmask cmd sigs يغير مجموعة الإشارات المحظورة للخيط المستدعي. إذا كان cmd هو SIG_SETMASK، يتم تعيين الإشارات المحظورة إلى تلك الموجودة في القائمة sigs. إذا كان cmd هو SIG_BLOCK، تتم إضافة الإشارات في sigs إلى مجموعة الإشارات المحظورة. إذا كان cmd هو SIG_UNBLOCK، تتم إزالة الإشارات في sigs من مجموعة الإشارات المحظورة. sigmask يعيد مجموعة الإشارات المحظورة سابقًا للخيط.

val wait_signal : int list -> int

نفس وظيفة Unix.sigwait. wait_signal sigs يعلق تنفيذ الخيط المستدعي حتى تتلقى العملية إحدى الإشارات المحددة في القائمة sigs. ثم يعيد رقم الإشارة المستلمة. لن يتم استدعاء معالجات الإشارات المرفقة بالإشارات في sigs. من المتوقع أن يتم حظر الإشارات sigs قبل استدعاء wait_signal.

الاستثناءات التي لم يتم التقاطها

val default_uncaught_exception_handler : exn -> unit

سيطبع Thread.default_uncaught_exception_handler معرف الخيط، والاستثناء، والتتبع الخلفي (إذا كان متاحًا).

val set_uncaught_exception_handler : (exn -> unit) -> unit

Thread.set_uncaught_exception_handler fn يسجل fn كمعالج للاستثناءات التي لم يتم التقاطها.

إذا أطلق معالج الاستثناء الذي تم تعيينه حديثًا استثناءً، فسيتم استدعاء Thread.default_uncaught_exception_handler.
