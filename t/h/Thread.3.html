مقدمة

بدءًا من الإصدار 8.1، أصبح جوهر Tcl آمنًا للسلاسل، مما يسمح لك بدمج Tcl في التطبيقات متعددة السلاسل دون تخصيص جوهر Tcl.

بدءًا من الإصدار 8.6، يكون دعم سلاسل Tcl متعددة السلاسل قيد التشغيل افتراضيًا. لتعطيل دعم سلاسل Tcl متعددة السلاسل، يجب عليك تضمين الخيار --disable-threads في configure عند تهيئة وتجميع جوهر Tcl الخاص بك.

قيود مهمة لتنفيذ سلاسل Tcl هي أن السلسلة التي أنشأت مترجم Tcl فقط يمكنها استخدام هذا المترجم. بمعنى آخر، لا يمكن لسلاسل متعددة الوصول إلى نفس مترجم Tcl. (ومع ذلك، يمكن لسلسلة واحدة إنشاء واستخدام مترجمات متعددة بأمان.)

الوصف

يوفر Tcl Tcl_CreateThread لإنشاء السلاسل. يمكن للمتصل تحديد حجم المكدس المعطى للسلسلة الجديدة وتعديل السلوك من خلال flags المحددة. القيمة TCL_THREAD_STACK_DEFAULT لـ stackSize تشير إلى أنه سيتم استخدام الحجم الافتراضي كما هو محدد بواسطة نظام التشغيل للسلسلة الجديدة. أما بالنسبة للعلامات، حاليًا فقط القيمتان TCL_THREAD_NOFLAGS و TCL_THREAD_JOINABLE محددتان. الأول يستدعي السلوك الافتراضي دون أي إعدادات خاصة. استخدام القيمة الثانية يضع علامة joinable على السلسلة الجديدة. هذا يعني أن سلسلة أخرى يمكنها الانتظار حتى تنتهي هذه السلسلة المميزة والانضمام إليها.

القيود: على بعض أنظمة UNIX، لا تحتوي مكتبة pthread على الوظيفة لتحديد حجم مكدس السلسلة. يتم تجاهل القيمة المحددة لحجم المكدس على هذه الأنظمة. لا تدعم Windows حاليًا السلاسل القابلة للانضمام. لذلك يتم تجاهل قيمة العلامة هذه على هذا النظام.

يوفر Tcl دالتي Tcl_ExitThread و Tcl_FinalizeThread لإنهاء السلاسل واستدعاء معالجات خروج اختيارية لكل سلسلة. راجع صفحة Tcl_Exit لمزيد من المعلومات حول هذه الإجراءات.

يتم توفير الدالة Tcl_JoinThread للسماح للسلاسل بالانتظار حتى خروج سلسلة أخرى، والتي يجب أن تكون قد تم وضع علامة قابلة للانضمام عليها من خلال استخدام علامة TCL_THREAD_JOINABLE أثناء إنشائها عبر Tcl_CreateThread.

محاولة الانتظار حتى خروج سلسلة غير قابلة للانضمام أو سلسلة يتم الانتظار عليها بالفعل ستؤدي إلى خطأ. من الممكن الانتظار لسلسلة قابلة للانضمام وقد خرجت بالفعل، سيحتفظ النظام بالمعلومات اللازمة حتى بعد استدعاء Tcl_JoinThread. هذا يعني أن عدم استدعاء Tcl_JoinThread لسلسلة قابلة للانضمام سيؤدي إلى تسرب في الذاكرة.

يُرجع استدعاء Tcl_GetThreadData مؤشرًا إلى كتلة بيانات خاصة بالسلسلة. وسيطتها هي مفتاح مشترك بين جميع السلاسل وحجم لكتلة التخزين. يتم تخصيص التخزين تلقائيًا وتهيئته إلى جميع الأصفار في المرة الأولى التي تطلبه فيها كل سلسلة. يتم إلغاء تخصيص التخزين تلقائيًا بواسطة Tcl_FinalizeThread.

المزامنة والاتصال

يوفر Tcl Tcl_ThreadQueueEvent و Tcl_ThreadAlert لمعالجة طوابير الأحداث في التطبيقات متعددة السلاسل. راجع صفحة دليل Notifier لمزيد من المعلومات حول هذه الإجراءات.

Mutex هو قفل يستخدم لتسلسل جميع السلاسل عبر جزء من التعليمات البرمجية عن طريق استدعاء Tcl_MutexLock و Tcl_MutexUnlock. إذا كانت سلسلة ما تحتفظ بقفل mutex، فإن أي سلسلة أخرى تستدعي Tcl_MutexLock سيتم حظرها حتى يتم استدعاء Tcl_MutexUnlock. يمكن تدمير قفل mutex بعد استخدامه عن طريق استدعاء Tcl_MutexFinalize. نتيجة قفل قفل mutex مرتين من نفس السلسلة غير محددة. على بعض الأنظمة، سيؤدي ذلك إلى توقف تام. يتم تعريف الإجراءات Tcl_MutexLock و Tcl_MutexUnlock و Tcl_MutexFinalize على أنها وحدات ماكرو فارغة إذا لم يتم التجميع مع تمكين السلاسل. للإعلان عن mutexes، يجب استخدام الماكرو TCL_DECLARE_MUTEX. يضمن هذا الماكرو معالجة mutex صحيحة حتى عندما يتم تجميع النواة بدون تمكين السلاسل.

متغير الشرط هو آلية إشارة: يمكن لسلسلة قفل mutex ثم الانتظار على متغير شرط باستخدام Tcl_ConditionWait. هذا يحرر قفل mutex بشكل ذري ويمنع السلسلة المنتظرة حتى تستدعي سلسلة أخرى Tcl_ConditionNotify. يجب أن يكون لدى مستدعي Tcl_ConditionNotify قفل mutex المرتبط به محفوظًا عن طريق استدعاء Tcl_MutexLock مسبقًا، ولكن هذا غير مفروض. إعلام متغير الشرط يوقف جميع السلاسل المنتظرة على متغير الشرط، لكنها لا تستمر حتى يتم تحرير قفل mutex باستخدام Tcl_MutexUnlock. آلية Tcl_ConditionWait تقوم تلقائيًا بقفل mutex قبل العودة.

يجب أن يكون مستدعي Tcl_ConditionWait مستعدًا للإشعارات الزائفة عن طريق استدعاء Tcl_ConditionWait داخل حلقة while تختبر بعض الخاصية الثابتة.

يمكن تدمير متغير الشرط بعد استخدامه عن طريق استدعاء Tcl_ConditionFinalize.

يتم تعريف الإجراءات Tcl_ConditionNotify و Tcl_ConditionWait و Tcl_ConditionFinalize على أنها وحدات ماكرو فارغة إذا لم يتم التجميع مع تمكين السلاسل.

التهيئة

جميع كائنات المزامنة هذه ذاتية التهيئة. يتم تنفيذها كمؤشرات مبهمة يجب أن تكون NULL عند الاستخدام الأول. يتم تنظيف mutexes ومتغيرات الشرط تلقائيًا بواسطة معالجات خروج العملية (إذا عاشت طويلاً) أو صراحةً عن طريق استدعاء Tcl_MutexFinalize أو Tcl_ConditionFinalize. يتم استرداد تخزين بيانات السلسلة المحلي أثناء Tcl_FinalizeThread.

الوصول على مستوى البرنامج النصي إلى السلاسل

لا يوفر Tcl أوامر مدمجة للبرامج النصية لاستخدامها لإنشاء السلاسل أو إدارتها أو الانضمام إليها، ولا أي وصول على مستوى البرنامج النصي إلى mutex أو متغيرات الشرط. يوفر مثل هذه المرافق فقط عبر واجهات C، ويترك الأمر للحزم لكشفها.

ARGUMENTS

Tcl_ThreadId threadId
Identifier for a thread. This is an opaque type used to refer to a thread. If threadId is NULL, it refers to the current thread.
Tcl_ThreadCreateProc *startProc
Pointer to the function that will be executed by the new thread.
ClientData clientData
Arbitrary one-word value to be passed to the thread's start procedure.
int stackSize
The desired stack size for the new thread in bytes. TCL_THREAD_STACK_DEFAULT can be used to let the system choose a default size.
int joinable
A flag indicating whether the thread should be joinable. TCL_THREAD_JOINABLE means the thread can be joined using Tcl_JoinThread. TCL_THREAD_DETACHED means the thread cannot be joined, and its resources will be freed automatically when it terminates.
threadIdPtr
On return from Tcl_CreateThread, this points to the identifier of the newly created thread. This is only valid if the function returns TCL_OK.
result
On return from Tcl_JoinThread, this points to the integer return value from the thread's start procedure. This is only valid if the function returns TCL_OK.
int seconds
The number of seconds to sleep.
int microseconds
The number of microseconds to delay.
int status
The status value to return from the thread.
keyPtr
A pointer to a Tcl_ThreadDataKey structure. This is used to manage thread-local data.
data
A pointer to the thread-specific data to be stored.
mutexPtr
Pointer to a Tcl_Mutex structure, used for mutual exclusion.
condPtr
Pointer to a Tcl_Condition structure, used for condition variables.

INTRODUCTION

Tcl provides a powerful and portable mechanism for creating and managing threads. This allows you to write applications that can perform multiple tasks concurrently, improving responsiveness and performance.

DESCRIPTION

The Tcl_CreateThread function creates a new thread that begins execution in the procedure specified by startProc. The clientData argument is passed as the sole argument to startProc. The stackSize argument allows you to specify the stack size for the new thread. If joinable is set to TCL_THREAD_JOINABLE, the thread can be joined later using Tcl_JoinThread. If it's TCL_THREAD_DETACHED, the thread cannot be joined, and its resources will be automatically reclaimed upon termination.

The Tcl_GetCurrentThread function returns the thread identifier for the calling thread. Tcl_IsMainThread returns true if the calling thread is the main Tcl thread.

When a thread is created with the TCL_THREAD_JOINABLE flag, the parent thread can wait for the child thread to complete its execution using Tcl_JoinThread. This function blocks until the specified thread terminates and retrieves its return value.

The Tcl_Sleep and Tcl_Delay functions allow a thread to pause its execution for a specified duration.

Tcl_ExitThread causes the current thread to terminate. The status argument is the exit status of the thread.

Tcl_CancelThread attempts to cancel the execution of the specified thread. This is a potentially dangerous operation and should be used with caution.

Tcl_GetJoinableThreads returns the identifier of the thread from which all other joinable threads were created.

The functions Tcl_SetThreadData and Tcl_GetThreadData allow for the management of thread-local storage. A key is used to associate data with the current thread. This data is private to each thread.

Tcl also provides basic support for mutexes and condition variables for synchronization between threads:

Tcl_MutexLock
Acquires a lock on a mutex. If the mutex is already locked, the calling thread will block until the mutex is released.
Tcl_MutexTryLock
Attempts to acquire a lock on a mutex. If the mutex is already locked, it returns immediately without blocking.
Tcl_MutexUnlock
Releases a previously acquired lock on a mutex.
Tcl_ConditionWait
Blocks the calling thread until the condition variable is signaled. This function must be called with the associated mutex locked. The mutex is atomically unlocked before blocking and re-locked before returning.
Tcl_ConditionSignal
Wakes up one of the threads (if any) that are waiting on the condition variable.
Tcl_ConditionBroadcast
Wakes up all threads that are waiting on the condition variable.

SCRIPT-LEVEL ACCESS TO THREADS

While the C API provides direct control over threads, Tcl also offers a scripting interface for thread management. The Thread package, when loaded into a Tcl interpreter, provides commands like thread create, thread join, thread id, and thread sleep. This allows Tcl scripts to create, manage, and synchronize threads without writing C code.

Accessing thread-related features at the script level is crucial for many Tcl applications that require concurrency. The Thread package is a prime example of how advanced features can be exposed to Tcl programmers. This package, like others, is loaded into the interpreter and makes its functionality available through Tcl commands. This approach abstracts away the complexities of the underlying C API, making thread management more accessible.

EXAMPLE

To create a thread with portable code, its implementation function should be declared as follows:

static Tcl_ThreadCreateProc MyThreadImplFunc;

It should then be defined like this example, which just counts up to a given value and then finishes.

static Tcl_ThreadCreateType
MyThreadImplFunc(
    ClientData clientData)
{
    int i, limit = (int) clientData;
    for (i=0 ; i<limit ; i++) {
        /* doing nothing at all here */
    }
    TCL_THREAD_CREATE_RETURN;
}

To create the above thread, make it execute, and wait for it to finish, we would do this:

int limit = 1000000000;
ClientData limitData = (void*)((intptr_t) limit);
Tcl_ThreadId id;    /* holds identity of thread created */
int result;
if (Tcl_CreateThread(&id, MyThreadImplFunc, limitData,
        TCL_THREAD_STACK_DEFAULT,
        TCL_THREAD_JOINABLE) != TCL_OK) {
    /* Thread did not create correctly */
    return;
}
/* Do something else for a while here */
if (Tcl_JoinThread(id, &result) != TCL_OK) {
    /* Thread did not finish properly */
    return;
}
/* All cleaned up nicely */
