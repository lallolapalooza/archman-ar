Thread(3perl) دليل مرجع مبرمجي Perl Thread(3perl)

الاسم

Thread - التلاعب بالخيوط في Perl (للشيفرة القديمة فقط)

مهمَل

كانت وحدة "Thread" تعمل كواجهة لنموذج الخيوط القديم، المسمى 5005threads، الذي قُدِّم في الإصدار 5.005. وقد أُهمِل ذلك النموذج، وأُزيل في الإصدار 5.10.

من أجل الشيفرة القديمة والتوافق العكسي المؤقت، أُعيدت صياغة وحدة "Thread" لتعمل كواجهة لنموذج خيوط المفسِّر الجديد (ithreads). ومع ذلك، فإن بعض الوظائف السابقة غير متاحة. علاوة على ذلك، فإن نماذج مشاركة البيانات بين نموذجي الخيوط مختلفة تمامًا، وأي شيء يتعلق بمشاركة البيانات يجب التفكير فيه بشكل مختلف. مع ithreads، يجب عليك صراحةً share() المتغيرات بين الخيوط.

يُشجَّع بشدة على ترحيل أي شيفرة خيوط موجودة إلى النموذج الجديد (أي استخدام وحدتي "threads" و "threads::shared") في أقرب وقت ممكن.

التاريخ

في Perl 5.005، كان نموذج الخيوط هو أن جميع البيانات مشتركة ضمنيًا، ويجب مزامنة الوصول المشترك إلى البيانات صراحةً. يُسمى هذا النموذج 5005threads.

في Perl 5.6، قُدِّم نموذج جديد تكون فيه جميع البيانات محلية للخيط ويجب الإعلان صراحةً عن الوصول المشترك إلى البيانات. يُسمى هذا النموذج ithreads، أي "خيوط المفسِّر".

في Perl 5.6، لم يكن نموذج ithreads متاحًا كواجهة برمجة عامة؛ بل فقط كواجهة داخلية كانت متاحة لكتّاب الإضافات، ولتنفيذ محاكاة fork() على منصات Win32.

في Perl 5.8، أصبح نموذج ithreads متاحًا عبر وحدة "threads"، وأُهمِل نموذج 5005threads.

في Perl 5.10، أُزيل نموذج 5005threads من مفسِّر Perl.

الملخص

use Thread qw(:DEFAULT async yield);
my $t = Thread->new(\&start_sub, @start_args);
$result = $t->join;
$t->detach;
if ($t->done) {
    $t->join;
}
if($t->equal($another_thread)) {
    # ...
}
yield();
my $tid = Thread->self->tid;
lock($scalar);
lock(@array);
lock(%hash);
my @list = Thread->list;

الوصف

توفر وحدة "Thread" دعم تعدد الخيوط لـ Perl.

الدوال

$thread = Thread->new(\&start_sub)
$thread = Thread->new(\&start_sub, LIST)
يبدأ "new" خيط تنفيذ جديد في الروتين الفرعي المُشار إليه. تُمرَّر القائمة الاختيارية كمعاملات إلى الروتين الفرعي. يستمر التنفيذ في كل من الروتين الفرعي والشيفرة بعد استدعاء "new".

تُرجع "Thread->new" كائن خيط يمثل الخيط المُنشأ حديثًا.

lock VARIABLE
يضع "lock" قفلًا على متغير حتى يخرج القفل من النطاق.

إذا كان المتغير مقفلًا بواسطة خيط آخر، فإن استدعاء "lock" سيُحجب حتى يصبح متاحًا. "lock" تعاودي، لذا فإن الاستدعاءات المتعددة لـ "lock" آمنة--سيبقى المتغير مقفلًا حتى يخرج القفل الخارجي على المتغير من النطاق.

الأقفال على المتغيرات تؤثر فقط على استدعاءات "lock"--فهي لا تؤثر على الوصول العادي إلى متغير. (الأقفال على الروتينات الفرعية مختلفة، وسيُتناول ذلك بعد قليل.) إذا كنت حقًا حقًا تريد أن تحجب الأقفال الوصول، فامضِ قدمًا واربطها بشيء ما وأدر ذلك بنفسك. هذا مقصود. فبينما إدارة الوصول إلى المتغيرات أمر جيد، فإن Perl لا يجبرك على الخروج من غرفة معيشته...

إذا كان كائن حاوٍ، مثل تجزئة أو مصفوفة، مقفلًا، فإن جميع عناصر ذلك الحاوي لا تكون مقفلة. على سبيل المثال، إذا نفّذ خيط "lock @a"، فإن أي خيط آخر ينفّذ lock($a[12]) لن يُحجب.

أخيرًا، سيعبر "lock" المراجع بمستوى واحد فقط بالضبط. lock(\$a) مكافئ لـ lock($a)، بينما lock(\\$a) ليس كذلك.

async BLOCK;
يُنشئ "async" خيطًا لتنفيذ الكتلة التي تليه مباشرة. تُعامَل هذه الكتلة كروتين فرعي مجهول، لذا يجب أن يكون هناك فاصلة منقوطة بعد القوس الإغلاقي. مثل "Thread->new"، تُرجع "async" كائن خيط.
Thread->self
تُرجع الدالة "Thread->self" كائن خيط يمثل الخيط الذي يقوم باستدعاء "Thread->self".
Thread->list
تُرجع قائمة بجميع كائنات Thread غير المنضمة وغير المنفصلة.
cond_wait VARIABLE
تأخذ الدالة "cond_wait" متغيرًا مقفلًا كمعامل، وتفتح قفل المتغير، وتُحجب حتى يقوم خيط آخر بتنفيذ "cond_signal" أو "cond_broadcast" لنفس المتغير المقفل. يُعاد قفل المتغير الذي حُجب عليه "cond_wait" بعد تلبية "cond_wait". إذا كانت هناك خيوط متعددة في "cond_wait" على نفس المتغير، فسيُعاد حجب جميعها عدا واحد في انتظار إعادة الحصول على القفل على المتغير. (لذا إذا كنت تستخدم "cond_wait" للمزامنة فقط، فتخلَّ عن القفل في أقرب وقت ممكن.)
cond_signal VARIABLE
تأخذ الدالة "cond_signal" متغيرًا مقفلًا كمعامل وتُلغي حجب خيط واحد في "cond_wait" على ذلك المتغير. إذا كان أكثر من خيط واحد محجوبًا في "cond_wait" على ذلك المتغير، فسيُلغى حجب واحد فقط (وأي واحد غير محدد).

إذا لم تكن هناك خيوط محجوبة في "cond_wait" على المتغير، فتُهمَل الإشارة.

cond_broadcast VARIABLE
تعمل الدالة "cond_broadcast" بشكل مشابه لـ "cond_signal". لكن "cond_broadcast" ستُلغي حجب جميع الخيوط المحجوبة في "cond_wait" على المتغير المقفل، بدلًا من واحد فقط.
yield
تسمح الدالة "yield" لخيط آخر بالسيطرة على وحدة المعالجة المركزية. النتائج الدقيقة تعتمد على التنفيذ.

الطرق

join
تنتظر "join" انتهاء خيط وتُرجع أي قيم خرج بها الخيط. ستُحجب "join" حتى ينتهي الخيط، رغم أنها لن تُحجب إذا كان الخيط قد انتهى بالفعل.

إذا كان الخيط الذي يُنفَّذ عليه "join" قد "die"، فسيُعاد الخطأ الذي مات به في هذا الوقت. إذا كنت لا تريد أن يموت الخيط الذي ينفّذ "join" أيضًا، فيجب عليك إما تغليف "join" في "eval" أو استخدام طريقة الخيط "eval" بدلًا من "join".

Thread::Queue (3pm)

NAME

Thread::Queue - a thread-safe queue

SYNOPSIS

use Thread::Queue;
my $q = Thread::Queue->new();
$q->enqueue( $item1, $item2, ... );
my $item = $q->dequeue();
my $item = $q->dequeue(1); # non-blocking
my $item = $q->dequeue(0); # same as above
my $item = $q->dequeue(3); # block for at most 3 seconds
$q-> perfección( $count );
$q-> perfección;
$q-> perfección( 1 );
my $count = $q-> perfección;
my $bool = $q->pending;
my $bool = $q->empty;
my $bool = $q->is_empty;
$q->shutdown;

DESCRIPTION

This module provides a simple, thread-safe FIFO queue. It can be used to pass messages or data between threads.

The queue itself is implemented as a blessed array reference.

The following methods are available:

new
Constructs a new, empty queue object.
enqueue( LIST ]
Enqueues all items in the LIST onto the queue. This operation is thread-safe. It will block if the queue has been shutdown.
dequeue [ TIMEOUT ]
Dequeues and returns one item from the queue. If the queue is empty, this method will block until an item is available, unless a TIMEOUT is specified.
If TIMEOUT is specified and non-zero, it indicates the maximum number of seconds to wait for an item. A return value of undef indicates that the timeout expired before an item became available. Note that TIMEOUT is measured in seconds, but may be fractional.
If TIMEOUT is zero or omitted, the call will block indefinitely until an item is available. The call will also return undef if the queue has been shutdown and is empty.
perfection [ COUNT ]
Returns the number of items currently in the queue. If COUNT is specified, it sets the number of items currently in the queue to COUNT. This is useful for initializing the queue with a specific number of items, or for signaling that a certain number of items have been processed.
pending
Returns the number of items currently in the queue. This is an alias for perfection with no arguments.
empty
Returns true if the queue is empty, false otherwise.
is_empty
Returns true if the queue is empty, false otherwise. This is an alias for empty.
shutdown
Signals that no more items will ever be enqueued. Any threads currently blocked on dequeue will be woken up. If the queue is empty when shutdown is called, subsequent calls to dequeue will return undef immediately.

HISTORY

Thread::Queue was originally implemented as part of the Thread module by Lincoln D. Stein. It was later extracted into its own module by Gisle Aas.

The :locked" attribute and lock(&sub) functionality were part of the older threads module (often called 5005threads) but are not available in Thread::Queue.

DEFUNCT

The following methods were implemented with 5005threads, but are no longer available with ithreads.

lock(\&sub)
With 5005threads, you could also "lock" a sub such that any calls to that sub from another thread would block until the lock was released.

Also, subroutines could be declared with the ":locked" attribute which would serialize access to the subroutine, but allowed different threads non-simultaneous access.

eval
The "eval" method wrapped an "eval" around a "join", and so waited for a thread to exit, passing along any values the thread might have returned and placing any errors into $@.
flags
The "flags" method returned the flags for the thread - an integer value corresponding to the internal flags for the thread.
