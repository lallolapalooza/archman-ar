NAME

Thread::Queue

a thread-safe, non-blocking queue for Perl

VERSION

1.08

SYNOPSIS

 use Thread::Queue;

 my $q = Thread::Queue->new;

 # Basic usage
 $q->enqueue('item 1');
 $q->enqueue('item 2');
 my $item = $q->dequeue; # item is 'item 1'

 # Non-blocking
 my $item_nb = $q->dequeue_nb; # returns undef if empty
 $q->enqueue_nb('item 3');     # returns undef if full (if bound)

 # Indexed access
 $q->insert(1, 'item 0');    # Queue: item 0, item 2
 my @items = $q->extract(0, 2); # @items is ('item 0', 'item 2'); Queue: empty

DESCRIPTION

This module provides a thread-safe, FIFO queue that can be used for communication between threads. It is designed to be easy to use and provides both blocking and non-blocking methods for accessing the queue. It also provides methods for inserting and extracting items at specific index positions.

QUEUE CREATION

new()

Creates a new, empty queue.

Options can be passed to the constructor to set limits on the queue size:

 my $bounded_q = Thread::Queue->new( 10 ); # Max 10 items
 my $bounded_q = Thread::Queue->new( -max_size => 10 );
 my $unbounded_q = Thread::Queue->new( -max_size => 0 ); # Default is unbounded

Setting a maximum size will cause enqueue and enqueue_nb to block or fail, respectively, when the queue is full.

BASIC METHODS

->enqueue( LIST )
Adds the elements in LIST to the end of the queue. This method will block if the queue has a maximum size and is currently full, until space becomes available.
->dequeue()
Removes and returns the first element from the queue. This method will block if the queue is empty, until an element becomes available.
->dequeue_nb()
Removes and returns the first element from the queue. Returns undef if the queue is empty. This is the non-blocking version of dequeue.
->enqueue_nb( LIST )
Adds the elements in LIST to the end of the queue. Returns the number of items successfully enqueued, or undef if the queue has a maximum size and is currently full. This is the non-blocking version of enqueue.
->pending()
Returns the number of items currently in the queue.
->is_content_shared()
Returns true if the queue is set up to share its contents between threads (default). Returns false if the queue is set up to pass copies of its contents between threads.
->set_content_sharing( BOOLEAN )
Sets whether the queue shares its content between threads. By default, content sharing is enabled. Disabling content sharing requires the use of threads::shared and will pass copies of data instead of references.

ADVANCED METHODS

->insert( INDEX, LIST )
Inserts the elements in LIST into the queue at the specified INDEX. The first element of the queue is at index 0. This method will block if the queue has a maximum size and is currently full, until space becomes available.

If the index is greater than or equal to the number of items currently in the queue, the list is added to the end of the queue.

Negative index positions are supported. If a negative index position is specified such that it is less than the beginning of the queue, the list is added to the head of the queue.

 my $q = Thread::Queue->new;
 $q->enqueue(1, 2, 3, 4);
 # Queue: 1, 2, 3, 4
 $q->insert(2, qw/foo bar/);
 # Queue: 1, 2, foo, bar, 3, 4
 $q->insert(0, 0);
 # Queue: 0, 1, 2, foo, bar, 3, 4
 $q->insert(-1, 5);
 # Queue: 0, 1, 2, foo, bar, 3, 4, 5
 $q->insert(-10, -1);
 # Queue: -1, 0, 1, 2, foo, bar, 3, 4, 5

Specifying a negative index position greater than the number of items in the queue just adds the list to the end.

$q->enqueue(1, 2, 3, 4);
$q->insert(-2, qw/foo bar/);
# Queue now contains:  1, 2, foo, bar, 3, 4

Negative index positions are supported: Specifying a negative index position greater than the number of items in the queue adds the list to the head of the queue.

->extract()
->extract(INDEX)
->extract(INDEX, COUNT)
Removes and returns the specified number of items (defaults to 1) from the specified index position in the queue (0 is the head of the queue). When called with no arguments, "extract" operates the same as "dequeue_nb".

This method is non-blocking, and will return only as many items as are available to fulfill the request:

$q->enqueue(1, 2, 3, 4);
my $item  = $q->extract(2)     # Returns 3
                               # Queue now contains:  1, 2, 4
my @items = $q->extract(1, 3)  # Returns (2, 4)
                               # Queue now contains:  1

Specifying an index position greater than the number of items in the queue results in "undef" or an empty list being returned.

$q->enqueue('foo');
my $nada = $q->extract(3)      # Returns undef
my @nada = $q->extract(1, 3)   # Returns ()

Negative index positions are supported. Specifying a negative index position greater than the number of items in the queue may return items from the head of the queue (similar to "dequeue_nb") if the count overlaps the head of the queue from the specified position (i.e. if queue size + index + count is greater than zero):

$q->enqueue(qw/foo bar baz/);
my @nada = $q->extract(-6, 2);  # Returns ()      - (3+(-6)+2) <= 0
my @some = $q->extract(-6, 4);  # Returns (foo)   - (3+(-6)+4) > 0
                                # Queue now contains:  bar, baz
my @rest = $q->extract(-3, 4);  # Returns (bar, baz) -
                                #                   (2+(-3)+4) > 0

NOTES

Queues created by Thread::Queue can be used in both threaded and non-threaded applications.

LIMITATIONS

Passing objects on queues may not work if the objects' classes do not support sharing. See "BUGS AND LIMITATIONS" in threads::shared for more.

Passing array/hash refs that contain objects may not work for Perl prior to 5.10.0.
