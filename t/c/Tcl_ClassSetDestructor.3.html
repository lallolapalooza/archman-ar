الوصف

الطريقة هي عملية يتم تنفيذها على كائن مرتبط بهذا الكائن. يجب ربط كل طريقة إما بكائن أو بفئة؛ الطرق المرتبطة بفئة ترتبط بجميع مثيلات تلك الفئة (المباشرة وغير المباشرة).

بالنظر إلى طريقة، يمكن العثور على الكيان الذي أعلنها باستخدام Tcl_MethodDeclarerClass الذي يعيد الفئة التي تم ربط الطريقة بها (أو NULL إذا لم تكن الطريقة مرتبطة بأي فئة) و Tcl_MethodDeclarerObject الذي يعيد الكائن الذي تم ربط الطريقة به (أو NULL إذا لم تكن الطريقة مرتبطة بكائن). يمكن استرداد اسم الطريقة باستخدام Tcl_MethodName وما إذا كانت الطريقة مصدّرة يتم استردادها باستخدام Tcl_MethodIsPublic. يمكن أيضًا فحص نوع الطريقة إلى درجة محدودة؛ تعيد الدالة Tcl_MethodIsType ما إذا كانت الطريقة من نوع معين، وتعيين clientData لكل طريقة للمتغير الذي يشير إليه clientDataPtr (إذا كان غير NULL) إذا تمت مطابقة النوع.

إنشاء الطرق

يتم إنشاء الطرق بواسطة Tcl_NewMethod و Tcl_NewInstanceMethod، والتي تنشئ طريقة مرتبطة بفئة أو كائن على التوالي. في كلتا الحالتين، يوفر الوسيط nameObj اسم الطريقة المراد إنشاؤها، ويحدد الوسيط isPublic ما إذا كان يجب تصدير الطريقة مبدئيًا، ويصف الوسيط methodTypePtr تنفيذ الطريقة (انظر قسم أنواع الطرق أدناه)، ويوفر الوسيط clientData بعض البيانات الخاصة بالتنفيذ التي يتم تمريرها إلى تنفيذ الطريقة عند استدعائها.

عندما يكون الوسيط nameObj لـ Tcl_NewMethod هو NULL، يتم إنشاء طريقة غير مسماة، والتي تستخدم للمنشئات والمدمرات. يجب تثبيت المنشئات في فئتها باستخدام الدالة Tcl_ClassSetConstructor، ويجب تثبيت المدمرات (التي يجب ألا تتطلب أي وسائط) في فئتها باستخدام الدالة Tcl_ClassSetDestructor. يجب عدم استخدام الطرق غير المسماة لأي غرض آخر، ويجب عدم استخدام الطرق المسماة كمنشئات أو مدمرات. لاحظ أيضًا أن methodTypePtr NULL يستخدم لتوفير إشارات داخلية، ولا يجب استخدامه في كود العميل.

سياقات استدعاء الطرق

عند استدعاء طريقة، يتم تمرير مرجع سياق استدعاء الطريقة كوسيطة واحدة إلى دالة التنفيذ. يمكن فحص هذا السياق لتوفير معلومات حول المستدعي، ولكن لا يجب الاحتفاظ به بعد انتهاء استدعاء الطريقة.

يمكن استرداد الطريقة التي يتم استدعاؤها من السياق باستخدام Tcl_ObjectContextMethod، ويمكن استرداد الكائن الذي تسبب في استدعاء الطريقة باستخدام Tcl_ObjectContextObject. يتم قراءة عدد الوسائط التي يجب تخطيها (على سبيل المثال، اسم الكائن واسم الطريقة في استدعاء طريقة عادي) باستخدام Tcl_ObjectContextSkippedArgs، ويمكن للسياق أيضًا الإبلاغ عما إذا كان يعمل كمرشح لطريقة أخرى من خلال Tcl_ObjectContextIsFiltering.

خلال تنفيذ الطريقة، قد يختار تنفيذ الطريقة استدعاء المراحل اللاحقة لسلسلة استدعاء الطريقة التي تأتي بعد تنفيذ الطريقة الحالية. يتم ذلك (جوهر أمر next) باستخدام Tcl_ObjectContextInvokeNext. لاحظ أن هذه الدالة لا تتلاعب بمكدس إطارات الاستدعاء، على عكس أمر next؛ إذا دفع تنفيذ الطريقة إطارًا واحدًا أو أكثر إلى المكدس كجزء من تنفيذه، فهو مسؤول أيضًا عن إزالة تلك الإطارات مؤقتًا من المكدس أثناء تنفيذ الدالة Tcl_ObjectContextInvokeNext. لاحظ أيضًا أنه لا يتم حذف سياق استدعاء الطريقة أبدًا أثناء تنفيذ هذه الدالة.

أنواع الطرق

يتم وصف أنواع الطرق بمؤشر إلى بنية Tcl_MethodType، والتي يتم تعريفها كالتالي:

typedef struct {
    int version;
    const char *name;
    Tcl_MethodCallProc *callProc;
    Tcl_MethodDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_MethodType;

يسمح الحقل version بالتوسع المستقبلي للبنية، ويجب دائمًا تعريفه على أنه يساوي TCL_OO_METHOD_VERSION_CURRENT. يوفر الحقل name اسمًا للقراءة البشرية للنوع، وهو القيمة التي يتم كشفها عبر أوامر Tcl info class methodtype و info object methodtype.

يعطي الحقل callProc دالة يتم استدعاؤها عند استدعاء الطريقة؛ يجب ألا تكون NULL أبدًا.

يعطي الحقل deleteProc دالة تستخدم لحذف طريقة معينة، ويتم استدعاؤها عند استبدال الطريقة أو إزالتها؛ إذا كان الحقل NULL، فمن المفترض أن clientData الطريقة لا يحتاج إلى إجراء خاص لحذفه.

الحقل cloneProc هو إما دالة تستخدم لنسخ clientData الطريقة (كجزء من Tcl_CopyObjectInstance) أو NULL للإشارة إلى أنه يمكن نسخ clientData مباشرة.
