المعاملات

Tcl_Interp *interp (in)
المترجم لتخزين البيانات المضغوطة أو غير المضغوطة الناتجة فيه. أيضًا حيث يتم كتابة أي رسائل خطأ. بالنسبة لـ Tcl_ZlibStreamInit، يمكن أن يكون NULL لإنشاء دفق غير مرتبط بأمر.
int format (in)
ما هو تنسيق البيانات المضغوطة للعمل معه. يجب أن يكون أحد TCL_ZLIB_FORMAT_ZLIB للبيانات بتنسيق zlib، TCL_ZLIB_FORMAT_GZIP للبيانات بتنسيق gzip، أو TCL_ZLIB_FORMAT_RAW للبيانات المضغوطة الخام. بالإضافة إلى ذلك، لفك الضغط فقط، يمكن أيضًا اختيار TCL_ZLIB_FORMAT_AUTO والذي يمكنه اكتشاف تلقائيًا ما إذا كانت البيانات المضغوطة بتنسيق zlib أو gzip.
Tcl_Obj *dataObj (in/out)
قيمة مصفوفة بايت تحتوي على البيانات المراد ضغطها أو فك ضغطها، أو التي يتم إلحاق البيانات المستخرجة من الدفق بها عند تمريرها إلى Tcl_ZlibStreamGet.
int level (in)
مستوى الضغط المراد استخدامه. يجب أن يكون رقمًا من 0 إلى 9 أو أحد القيم التالية: TCL_ZLIB_COMPRESS_NONE لعدم الضغط، TCL_ZLIB_COMPRESS_FAST للضغط السريع ولكن غير الفعال، TCL_ZLIB_COMPRESS_BEST للضغط البطيء والأقصى، أو TCL_ZLIB_COMPRESS_DEFAULT للمستوى الموصى به من قبل مكتبة zlib.
Tcl_Obj *dictObj (in/out)
قاموس يحتوي، أو سيتم تحديثه ليحتوي، على وصف لرأس gzip المرتبط بالبيانات المضغوطة. مفيد فقط عندما يكون format هو TCL_ZLIB_FORMAT_GZIP أو TCL_ZLIB_FORMAT_AUTO. إذا تم تمرير NULL، فسيتم استخدام رأس افتراضي عند الضغط وسيتم تجاهل الرأس (باستثناء فحوصات التكامل) عند فك الضغط. انظر القسم قاموس خيارات GZIP لمزيد من التفاصيل حول محتويات هذا القاموس.
unsigned int initValue (in)
القيمة الأولية لخوارزمية التحقق.
int bufferSize (in)
تلميح لحجم المخزن المؤقت المراد استخدامه لاستقبال البيانات. استخدم 0 لتقدير عام بناءً على بيانات الإدخال.
unsigned char *bytes (in)
مصفوفة بايت لتشغيل خوارزمية التحقق عليها، أو NULL للحصول على القيمة الأولية الموصى بها لخوارزمية التحقق.
int length (in)
عدد البايتات في المصفوفة.
int mode (in)
الوضع الذي سيتم تشغيل الدفق به. يجب أن يكون إما TCL_ZLIB_STREAM_DEFLATE لدفق ضاغط أو TCL_ZLIB_STREAM_INFLATE لدفق مفكك الضغط.
Tcl_ZlibStream *zshandlePtr (out)
مؤشر إلى متغير لكتابة الرمز المجرد للدفق عند الإنشاء بنجاح.
Tcl_ZlibStream zshandle (in)
الرمز المجرد للدفق المراد العمل عليه.
int flush (in)
ما إذا كان سيتم تفريغ الدفق بعد كتابة البيانات إليه وكيف. يجب أن يكون أحد: TCL_ZLIB_NO_FLUSH إذا لم يتم إجراء أي تفريغ، TCL_ZLIB_FLUSH إذا يجب جعل البيانات المضغوطة الحالية متاحة للوصول إليها باستخدام Tcl_ZlibStreamGet، TCL_ZLIB_FULLFLUSH إذا يجب وضع الدفق في حالة يمكن لمفكك الضغط الاسترداد منها عند حدوث تلف، أو TCL_ZLIB_FINALIZE لضمان انتهاء الدفق وكتابة أي تذييل مطلوب بواسطة التنسيق.
int count (in)
الحد الأقصى لعدد البايتات التي سيتم الحصول عليها من الدفق، أو -1 للحصول على جميع البايتات المتبقية من مخازن الدفق المؤقتة.
Tcl_Obj *compDict (in)
قيمة مصفوفة بايت وهي قاموس الضغط المراد استخدامه مع الدفق. لاحظ أن هذا ليس قاموس Tcl، ويوصى باستخدامه فقط مع التدفقات التي تم إنشاؤها مع تعيين format الخاص بها إلى TCL_ZLIB_FORMAT_ZLIB لأن التنسيقات الأخرى ليس لديها آلية للإشارة إلى ما إذا كان قاموس الضغط موجودًا بخلاف الفشل عند فك الضغط.

الوصف

تشكل هذه الوظائف الواجهة من مكتبة Tcl إلى مكتبة Zlib بواسطة Jean-loup Gailly و Mark Adler.

Tcl_ZlibDeflate و Tcl_ZlibInflate تقوم بضغط وفك ضغط البيانات الموجودة في المعامل dataObj على التوالي، وفقًا للمعاملات format و، للضغط، level. يتم استخدام القاموس في المعامل dictObj لنقل معلومات رأس إضافية حول البيانات المضغوطة عندما يدعم تنسيق الضغط ذلك؛ حاليا، يتم استخدام القاموس فقط عندما يكون المعامل format هو TCL_ZLIB_FORMAT_GZIP أو TCL_ZLIB_FORMAT_AUTO. لمزيد من التفاصيل حول محتويات القاموس، انظر القسم قاموس خيارات GZIP أدناه. عند النجاح، تترك كلتا الوظيفتين البيانات المضغوطة أو غير المضغوطة الناتجة في قيمة مصفوفة بايت وهي نتيجة مترجم Tcl؛ القيمة المرجعة هي رمز نتيجة Tcl قياسي.

Tcl_ZlibAdler32 و Tcl_ZlibCRC32 تحسبان قيم التحقق على مصفوفات من البايتات، وترجعان قيمة التحقق المحسوبة. يتم حساب قيم التحقق بشكل تدريجي، مما يسمح بمعالجة البيانات في كتل واحدة، ولكن هذا يتطلب من المتصل الاحتفاظ بقيمة التحقق الحالية وتمريرها كمعامل initValue؛ يمكن الحصول على القيمة الأولية لاستخدامها لهذا عن طريق استخدام NULL للمعامل bytes بدلاً من مؤشر إلى مصفوفة البايتات لحساب قيمة التحقق. وبالتالي، فإن الاستخدام النموذجي في حالة كتلة البيانات الواحدة يكون كالتالي:

checksum = Tcl_ZlibCRC32(Tcl_ZlibCRC32(0,NULL,0), data, length);

لاحظ أن خوارزمية Adler-32 ليست قيمة تحقق حقيقية، بل هي نوع من التجزئة ذات الصلة تعمل بشكل أفضل على البيانات الأطول.

تدفقات ZLIB

Tcl_ZlibStreamInit تنشئ دفقًا ضاغطًا أو مفكك الضغط مرتبطًا بأمر Tcl، وفقًا لمعاملاته، وتوفر رمزًا مجردًا للدفق وتعيد رمز نتيجة Tcl عادي؛ Tcl_ZlibStreamGetCommandName تعيد اسم ذلك الأمر بالنظر إلى رمز الدفق، أو NULL إذا لم يكن للدفق أمر. التدفقات ليست مصممة لتكون آمنة للخيوط؛ يجب استخدام كل دفق فقط من الخيط الذي أنشأه. عند العمل مع تدفقات gzip، يمكن توفير قاموس (الحقول كما هو موضح في قسم قاموس خيارات GZIP أدناه) عبر المعامل dictObj والذي يسمح عند الضغط بالتحكم في الرؤوس التي تم إنشاؤها، وعند فك الضغط يسمح باكتشاف الرؤوس الموجودة. لاحظ أن القاموس سيتم الكتابة إليه عند فك الضغط بمجرد قراءة بيانات كافية للحصول على رأس كامل. هذا يعني أن القاموس يجب أن يكون قيمة غير مشتركة في هذه الحالة؛ يُقترح قيمة فارغة تم إنشاؤها باستخدام Tcl_NewObj.

بمجرد بناء دفق، يتم استخدام Tcl_ZlibStreamPut لإضافة بيانات إلى الدفق ويتم استخدام Tcl_ZlibStreamGet لاسترداد البيانات من الدفق بعد المعالجة. كلتاهما تعيدان رموز نتيجة Tcl عادية وتتركان رسالة خطأ في نتيجة المترجم الذي تم تسجيل الدفق معه في حالة الخطأ (إذا تم إجراء مثل هذا التسجيل). مع Tcl_ZlibStreamPut، يجب عدم تعديل قيمة مخزن البيانات المؤقت الذي تم تمريره إليها بعد ذلك. مع Tcl_ZlibStreamGet، سيتم إلحاق بايتات البيانات بقيمة مخزن البيانات المؤقت الذي تم تمريره إليها. داخليًا للدفق، يتم الاحتفاظ بالبيانات مضغوطة لتقليل تكلفة مساحة المخزن المؤقت.

Tcl_ZlibStreamChecksum تعيد قيمة التحقق المحسوبة على البيانات غير المضغوطة وفقًا للتنسيق، و Tcl_ZlibStream

DESCRIPTION

\n

These procedures provide interfaces to the zlib compression and\ndecompression library. There are two styles of interface: a simple one-shot\ninterface and a streaming interface.

\n

The one-shot interfaces are Tcl_ZlibInflate and\nTcl_ZlibDeflate. Tcl_ZlibInflate decompresses the data in\ndataObj and returns the result as a new Tcl object. Tcl_ZlibDeflate}\ncompresses the data in dataObj and returns the result as a new Tcl\nobject. If dictObj is not NULL, it is used as a dictionary of\noptions; see GZIP OPTIONS DICTIONARY\nbelow.

\n

The streaming interface involves creating a stream object with\nTcl_ZlibStreamInit. This procedure returns an integer index which is\nused to refer to the stream in subsequent calls. The stream index is placed\nin the interpreter's result object. If dictObj is not NULL, it is\nused as a dictionary of options; see GZIP\nOPTIONS DICTIONARY below. A stream is initialized for either compression or\ndecompression based on the options given.

\n

Tcl_ZlibStreamPut is used to feed data into the stream. The\nstreamIndex identifies the stream and dataObj holds the data to\nbe compressed or decompressed. This procedure may return early, with more\ndata waiting to be processed.

\n

Tcl_ZlibStreamGet is used to retrieve data from the stream.\nIt fills the Tcl object pointed to by dataObj with the decompressed or\ndecompressed data. If the stream is not yet finished, it may return early\nwith no data.

\n

Tcl_ZlibStreamEof returns a boolean value indicating whether\nthe end of the uncompressed data has been reached.

\n

Tcl_ZlibStreamSetCompressionDictionary is used to control\nthe compression dictionary used with the stream, a compression dictionary\nbeing an array of bytes (such as might be created with\nTcl_NewByteArrayObj) that is used to initialize the compression\nengine rather than leaving it to create it on the fly from the data being\ncompressed. Setting a compression dictionary allows for more efficient\ncompression in the case where the start of the data is highly regular, but\nit does require both the compressor and the decompressor to agree on the\nvalue to use. Compression dictionaries are only fully supported for\nzlib-format data; on compression, they must be set before any data is sent\nin with Tcl_ZlibStreamPut, and on decompression they should be set\nwhen Tcl_ZlibStreamGet produces an error with its\n-errorcode set to “ZLIB NEED_DICT code”;\nthe code will be the Adler-32 checksum (see Tcl_ZlibAdler32) of\nthe compression dictionary sought. (Note that this is only true for\nzlib-format streams; gzip streams ignore compression dictionaries as the\nformat specification doesn't permit them, and raw streams just produce a\ndata error if the compression dictionary is missing or incorrect.)

\n

If you wish to clear a stream and reuse it for a new compression\nor decompression action, Tcl_ZlibStreamReset will do this and return\na normal Tcl result code to indicate whether it was successful; if the\nstream is registered with an interpreter, an error message will be left in\nthe interpreter result when this function returns TCL_ERROR.
