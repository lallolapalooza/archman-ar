الوصف

Tcl_CreateObjCommand يعرّف أمرًا جديدًا في interp ويربطه بالإجراء proc بحيث كلما تم استدعاء name كأمر Tcl (على سبيل المثال، عبر استدعاء Tcl_EvalObjEx)، سيقوم مترجم Tcl باستدعاء proc لمعالجة الأمر.

Tcl_CreateObjCommand يحذف أي أمر name موجود بالفعل مرتبط بالمترجم (ومع ذلك، انظر أدناه للحالة الاستثنائية حيث لا يتم حذف الأمر الموجود). يعيد رمزًا يمكن استخدامه للإشارة إلى الأمر في استدعاءات لاحقة لـ Tcl_GetCommandName. إذا كان name يحتوي على أي مؤهلات للمساحة الاسمية ::، فسيتم إضافة الأمر إلى المساحة الاسمية المحددة؛ بخلاف ذلك، يتم إضافة الأمر إلى المساحة الاسمية العامة. إذا تم استدعاء Tcl_CreateObjCommand لمترجم قيد الحذف، فإنه لا ينشئ أمرًا جديدًا ويعيد NULL. يجب أن تحتوي proc على وسائط ونتائج تطابق النوع Tcl_ObjCmdProc:

typedef int Tcl_ObjCmdProc(
        ClientData clientData,
        Tcl_Interp *interp,
        int objc,
        Tcl_Obj *const objv[]);

عند استدعاء proc، ستكون الوسائط clientData و interp نسخًا من الوسائط clientData و interp التي تم تمريرها إلى Tcl_CreateObjCommand. عادةً، يشير clientData إلى هيكل بيانات خاص بالتطبيق يصف ما يجب فعله عند استدعاء إجراء الأمر. تصف objc و objv وسائط الأمر، حيث تعطي objc عدد قيم الوسائط (بما في ذلك اسم الأمر) وتعطي objv قيم الوسائط. ستحتوي مصفوفة objv على objc قيم، تشير إلى قيم الوسائط. على عكس argv[argv] المستخدمة في إجراء أمر قائم على السلاسل، لن تحتوي objv[objc] على NULL.

بالإضافة إلى ذلك، عند استدعاء proc، يجب ألا تعدل محتويات مصفوفة objv عن طريق تعيين قيم مؤشر جديدة لأي عنصر في المصفوفة (على سبيل المثال، objv[2] = NULL) لأن هذا سيؤدي إلى فقدان الذاكرة وإتلاف المكدس الزمني. سيؤدي const في تعريف objv إلى إبلاغ المترجمات المتوافقة مع ANSI بأي محاولة تعيين من هذا القبيل كخطأ. ومع ذلك، من المقبول تعديل التمثيل الداخلي لأي قيمة وسيطة فردية. على سبيل المثال، قد يستدعي المستخدم Tcl_GetIntFromObj على objv[2] للحصول على التمثيل العددي لتلك القيمة؛ قد يغير هذا الاستدعاء نوع القيمة التي يشير إليها objv[2]، ولكنه لن يغير المكان الذي يشير إليه objv[2].

يجب أن تعيد proc رمزًا عدديًا يكون إما TCL_OK، TCL_ERROR، TCL_RETURN، TCL_BREAK، أو TCL_CONTINUE. انظر صفحة دليل نظرة عامة على Tcl للحصول على تفاصيل حول ما تعنيه هذه الرموز. معظم الأوامر العادية ستعيد فقط TCL_OK أو TCL_ERROR. بالإضافة إلى ذلك، إذا احتاجت proc إلى إعادة نتيجة غير فارغة، يمكنها استدعاء Tcl_SetObjResult لتعيين نتيجة المترجم. في حالة رمز الإرجاع TCL_OK، هذه هي نتيجة الأمر، وفي حالة TCL_ERROR، هذه هي رسالة خطأ. قبل استدعاء إجراء الأمر، تقوم Tcl_EvalObjEx بتعيين نتيجة المترجم للإشارة إلى قيمة تمثل سلسلة فارغة، لذا يمكن للأوامر البسيطة إعادة نتيجة فارغة عن طريق عدم فعل شيء على الإطلاق.

تنتمي محتويات مصفوفة objv إلى Tcl وليست مضمونة للبقاء بمجرد عودة proc: يجب ألا تعدلها proc. استدعاء Tcl_SetObjResult إذا كنت ترغب في إعادة شيء ما من مصفوفة objv.

عادةً، يحذف Tcl_CreateObjCommand أي أمر name موجود بالفعل مرتبط بالمترجم. ومع ذلك، إذا تم إنشاء الأمر الموجود بواسطة استدعاء سابق لـ Tcl_CreateCommand، فإن Tcl_CreateObjCommand لا يحذف الأمر ولكنه بدلاً من ذلك يرتب للمترجم Tcl لاستدعاء Tcl_ObjCmdProc proc في المستقبل. يتم الاحتفاظ بـ Tcl_CmdProc القديم القائم على السلاسل المرتبط بالأمر ويمكن الحصول على عنوانه بواسطة استدعاءات Tcl_GetCommandInfo اللاحقة. يتم ذلك للتوافق مع الإصدارات السابقة.

سيتم استدعاء DeleteProc عند (إذا) تم حذف name. يمكن أن يحدث هذا من خلال استدعاء لـ Tcl_DeleteCommand، Tcl_DeleteCommandFromToken، أو Tcl_DeleteInterp، أو عن طريق استبدال name في استدعاء آخر لـ Tcl_CreateObjCommand. يتم استدعاء DeleteProc قبل حذف الأمر، ويعطي التطبيق فرصة لتحرير أي هياكل مرتبطة بالأمر. يجب أن تحتوي DeleteProc على وسائط ونتائج تتطابق مع النوع Tcl_CmdDeleteProc:

typedef void Tcl_CmdDeleteProc(
        ClientData clientData);

ستكون الوسيطة clientData هي نفسها الوسيطة clientData التي تم تمريرها إلى Tcl_CreateObjCommand.

Tcl_DeleteCommand يحذف أمرًا من مترجم أوامر. بمجرد اكتمال الاستدعاء، فإن محاولات استدعاء cmdName في interp ستؤدي إلى أخطاء. إذا لم يكن cmdName مرتبطًا كأمر في interp، فإن Tcl_DeleteCommand لا يفعل شيئًا ويعيد -1؛ بخلاف ذلك، يعيد 0. لا توجد قيود على cmdName: يمكن أن يشير إلى أمر مدمج، أو أمر خاص بالتطبيق، أو إجراء Tcl. إذا كان name يحتوي على أي مؤهلات للمساحة الاسمية ::، فسيتم حذف الأمر من المساحة الاسمية المحددة.

بالنظر إلى رمز تم إرجاعه بواسطة Tcl_CreateObjCommand، يقوم Tcl_DeleteCommandFromToken بحذف الأمر من مترجم أوامر. سيحذف الأمر حتى لو تم إعادة تسميته. بمجرد اكتمال الاستدعاء، فإن محاولات استدعاء الأمر في interp ستؤدي إلى أخطاء. إذا تم بالفعل حذف الأمر المقابل لـ token من interp، فإن Tcl_DeleteCommand لا يفعل شيئًا ويعيد -1؛ بخلاف ذلك، يعيد 0.

يتحقق Tcl_GetCommandInfo لمعرفة ما إذا كان وسيطه cmdName موجودًا كأمر في interp. قد يتضمن cmdName مؤهلات للمساحة الاسمية :: لتحديد أمر في مساحة اسمية معينة. إذا لم يتم العثور على الأمر، فإنه يعيد 0. بخلاف ذلك، يضع معلومات حول الأمر في البنية Tcl_CmdInfo التي يشير إليها infoPtr ويعيد 1. تحتوي بنية Tcl_CmdInfo على الحقول التالية:

DESCRIPTION

\n

These procedures provide a mechanism for obtaining and modifying\ninformation about commands registered in a Tcl interpreter. They are useful\nprimarily for implementing Tcl extensions that need to introspect Tcl code.\nFor example, they can be used to implement the proc command, or to\nimplement the rename command.

\n

The structure Tcl_CmdInfo is defined as follows:\n

typedef struct Tcl_CmdInfo {\n    int isNativeObjectProc;\n    Tcl_ObjCmdProc *objProc;\n    ClientData objClientData;\n    Tcl_CmdProc *proc;\n    ClientData clientData;\n    Tcl_CmdDeleteProc *deleteProc;\n    ClientData deleteData;\n    Tcl_Namespace *namespacePtr;\n} Tcl_CmdInfo;
\n

\n

The isNativeObjectProc field has the value 1 if\nTcl_CreateObjCommand was called to register the command; it is 0 if\nonly Tcl_CreateCommand was called. It allows a program to determine\nwhether it is faster to call objProc or proc: objProc\nis normally faster if isNativeObjectProc has the value 1. The fields\nobjProc and objClientData have the same meaning as the\nproc and clientData arguments to Tcl_CreateObjCommand; they hold information about the value-based command procedure that the Tcl\ninterpreter calls to implement the command. The fields proc and\nclientData hold information about the string-based command procedure\nthat implements the command. If Tcl_CreateCommand was called for this\ncommand, this is the procedure passed to it; otherwise, this is a\ncompatibility procedure registered by Tcl_CreateObjCommand that\nsimply calls the command's value-based procedure after converting its string\narguments to Tcl values. The field deleteData is the ClientData value\nto pass to deleteProc; it is normally the same as clientData but may be set independently using the Tcl_SetCommandInfo procedure.\nThe field namespacePtr holds a pointer to the Tcl_Namespace that\ncontains the command.

\n

Tcl_GetCommandInfoFromToken is identical to\nTcl_GetCommandInfo except that it uses a command token returned from\nTcl_CreateObjCommand in place of the command name. If the\ntoken parameter is NULL, it returns 0; otherwise, it returns 1 and\nfills in the structure designated by infoPtr.

\n

Tcl_SetCommandInfo is used to modify the procedures and\nClientData values associated with a command. Its cmdName argument is\nthe name of a command in interp. cmdName may include ::\nnamespace qualifiers to identify a command in a particular namespace. If\nthis command does not exist then Tcl_SetCommandInfo returns 0.\nOtherwise, it copies the information from *infoPtr to Tcl's internal\nstructure for the command and returns 1.

\n

Tcl_SetCommandInfoFromToken is identical to\nTcl_SetCommandInfo except that it takes a command token as returned\nby Tcl_CreateObjCommand instead of the command name. If the\ntoken parameter is NULL, it returns 0. Otherwise, it copies the\ninformation from *infoPtr to Tcl's internal structure for the command\nand returns 1.

\n

Note that Tcl_SetCommandInfo and\nTcl_SetCommandInfoFromToken both allow the ClientData for a command's\ndeletion procedure to be given a different value than the ClientData for its\ncommand procedure.

\n

Note that neither Tcl_SetCommandInfo nor\nTcl_SetCommandInfoFromToken will change a command's namespace. Use\nTcl_Eval to call the rename command to do that.

\n

Tcl_GetCommandName provides a mechanism for tracking\ncommands that have been renamed. Given a token returned by\nTcl_CreateObjCommand when the command was created,\nTcl_GetCommandName returns the string name of the command. If the\ncommand has been renamed since it was created, then\nTcl_GetCommandName returns the current name. This name does not\ninclude any :: namespace qualifiers. The command corresponding to\ntoken must not have been deleted. The string returned by\nTcl_GetCommandName is in dynamic memory owned by Tcl and is only\nguaranteed to retain its value as long as the command is not deleted or\nrenamed; callers should copy the string if they need to keep it for a long\ntime.

\n

Tcl_GetCommandFullName produces the fully qualified name of\na command from a command token. The name, including all namespace prefixes, is appended to the value specified by objPtr.

\n

Tcl_GetCommandFromObj returns a token for the command\nspecified by the name in a Tcl_Obj. The command name is resolved\nrelative to the current namespace. Returns NULL if the command is not\nfound.
