الوسائط

Tcl_Interp *interp (in)
يُستخدم للإبلاغ عن الأخطاء وللبحث عن قناة مسجلة فيه.
const char *fileName (in)
اسم ملف محلي أو شبكي.
const char *mode (in)
يحدد كيفية الوصول إلى الملف. قد يأخذ أيًا من القيم المسموح بها لوسيط mode في أمر Tcl open.
int permissions (in)
علامات الأذونات بأسلوب POSIX مثل 0644. إذا تم إنشاء ملف جديد، فسيتم تعيين هذه الأذونات على الملف المنشأ.
int argc (in)
عدد العناصر في argv.
const char **argv (in)
وسائط لإنشاء خط أنابيب أوامر. هذه القيم لها نفس معنى الوسائط غير المفتاحية لأمر Tcl exec.
int flags (in)
يحدد تصرف المقابض القياسية للإدخال/الإخراج في خط الأنابيب: مزيج بأسلوب OR لـ TCL_STDIN، TCL_STDOUT، TCL_STDERR، و TCL_ENFORCE_MODE. إذا تم تعيين TCL_STDIN، فإن الإدخال القياسي للطفل الأول في الأنبوب هو قناة الأنبوب، وإلا فإنه يماثل الإدخال القياسي للعملية المستدعاة؛ وينطبق الشيء نفسه على TCL_STDOUT و TCL_STDERR. إذا لم يتم تعيين TCL_ENFORCE_MODE، فيمكن للأنبوب إعادة توجيه المقابض القياسية للإدخال/الإخراج لتجاوز المقابض القياسية التي تم تعيين TCL_STDIN و TCL_STDOUT و TCL_STDERR لها. إذا تم تعيينها، فإن هذه التوجيهات تسبب خطأ.
ClientData handle (in)
مقبض خاص بنظام التشغيل للإدخال/الإخراج إلى ملف. بالنسبة لـ Unix، هذا هو واصف ملف، بالنسبة لـ Windows، هذا هو مقبض HANDLE.
int readOrWrite (in)
مزيج بأسلوب OR لـ TCL_READABLE و TCL_WRITABLE للإشارة إلى العمليات الصالحة على handle.
const char *channelName (in)
اسم القناة.
int *modePtr (out)
يشير إلى متغير عدد صحيح سيستقبل مزيجًا بأسلوب OR لـ TCL_READABLE و TCL_WRITABLE الذي يشير إلى ما إذا كانت القناة مفتوحة للقراءة والكتابة.
const char *pattern (in)
النمط للمطابقة، يتم تمريره إلى Tcl_StringMatch، أو NULL.
Tcl_Channel channel (in)
قناة Tcl للإدخال أو الإخراج. يجب أن تكون القيمة المرجعة من إجراء مثل Tcl_OpenFileChannel.
Tcl_Obj *readObjPtr (in/out)
مؤشر إلى قيمة Tcl سيتم تخزين الأحرف المقروءة من القناة فيها.
int charsToRead (in)
عدد الأحرف المراد قراءتها من القناة. إذا كان ترميز القناة هو binary، فهذا يعادل عدد البايتات المراد قراءتها من القناة.
int appendFlag (in)
إذا كانت القيمة غير صفرية، فسيتم إلحاق البيانات المقروءة من القناة بالقيمة. بخلاف ذلك، ستحل البيانات محل المحتويات الحالية للقيمة.
char *readBuf (out)
مخزن مؤقت لتخزين البايتات المقروءة من القناة.
int bytesToRead (in)
عدد البايتات المراد قراءتها من القناة. يجب أن يكون المخزن المؤقت readBuf كبيرًا بما يكفي لاستيعاب هذا العدد من البايتات.
Tcl_Obj *lineObjPtr (in/out)
مؤشر إلى قيمة Tcl سيتم تخزين السطر المقروء من القناة فيها. سيتم إلحاق السطر المقروء بالقيمة الحالية للقيمة.
Tcl_DString *lineRead (in/out)
مؤشر إلى سلسلة Tcl ديناميكية سيتم تخزين السطر المقروء من القناة فيها. يجب أن يكون قد تم تهيئته بواسطة المتصل. سيتم إلحاق السطر المقروء بأي بيانات موجودة بالفعل في السلسلة الديناميكية.
const char *input (in)
الإدخال المراد إضافته إلى مخزن مؤقت للقناة.
int inputLen (in)
طول الإدخال
int addAtEnd (in)
علامة تشير إلى ما إذا كان يجب إضافة الإدخال إلى نهاية أو بداية المخزن المؤقت للقناة.
Tcl_Obj *writeObjPtr (in)
مؤشر إلى قيمة Tcl سيتم إخراج محتوياتها إلى القناة.
const char *charBuf (in)
مخزن مؤقت يحتوي على الأحرف المراد إخراجها إلى القناة.
const char *byteBuf (in)
مخزن مؤقت يحتوي على البايتات المراد إخراجها إلى القناة.
int bytesToWrite (in)
عدد البايتات المراد استهلاكها من charBuf أو byteBuf وإخراجها إلى القناة.
Tcl_WideInt offset (in)
مدى تحريك نقطة الوصول في القناة التي سيتم تطبيق عملية الإدخال أو الإخراج التالية عليها، مقاسة بالبايتات من الموضع المحدد بواسطة seekMode. قد تكون موجبة أو سالبة.
int seekMode (in)
نسبة إلى أي نقطة سيتم البحث؛ تستخدم مع offset لحساب نقطة الوصول الجديدة للقناة. القيم القانونية هي SEEK_SET، SEEK_CUR، و SEEK_END.
Tcl_WideInt length (in)
الطول (غير السالب) الذي سيتم اقتطاع القناة إليه.
const char *optionName (in)
اسم خيار ينطبق على هذه القناة، مثل -blocking. قد يأخذ أيًا من القيم التي يقبلها أمر fconfigure.
Tcl_DString *optionValue (in)
المكان الذي سيتم فيه تخزين قيمة خيار أو قائمة بجميع الخيارات وقيمها. يجب أن يكون قد تم تهيئته بواسطة المتصل.
const char *newValue (in)
القيمة الجديدة للخيار المحدد بواسطة optionName.

الوصف

توفر آلية قنوات Tcl آلية مستقلة عن الجهاز ومستقلة عن المنصة لإجراء عمليات الإدخال والإخراج المؤقتة على مجموعة متنوعة من أنواع الملفات والمقابس والأجهزة. آلية القنوات قابلة للتوسيع لأنواع قنوات جديدة، عن طريق توفير مشغل قناة منخفض المستوى للنوع الجديد؛ وصف واجهة مشغل القناة في إدخال الدليل لـ Tcl_CreateChannel. توفر آلية القنوات مخطط تخزين مؤقت مستوحى من الإدخال/الإخراج القياسي لـ Unix، وتسمح أيضًا بالإدخال/الإخراج غير الحاجب على القنوات.

تشمل الإجراءات الموصوفة في إدخال الدليل هذا واجهات برمجة التطبيقات C للطبقة العامة لبنية القناة. لوصف بنية مشغل القناة وكيفية تنفيذ مشغلات القنوات لأنواع القنوات الجديدة، انظر إدخال الدليل لـ Tcl_CreateChannel.

TCL_OPENFILECHANNEL

يفتح fileName للقراءة و/أو الكتابة. إذا كان mode "r"، تتم إضافة قناة قراءة. إذا كان mode "w"، تتم إضافة قناة كتابة (سيتم إنشاء الملف إذا لم يكن موجودًا، وسيتم اقتطاعه إذا كان موجودًا). إذا كان mode "a"، فسيتم إنشاء قناة كتابة (سيتم إنشاء الملف إذا لم يكن موجودًا، وسيتم إضافة البيانات إلى نهايته إذا كان موجودًا). إذا كان mode "+"، فسيتم إضافة كل من قناة القراءة والكتابة. يمكن دمج هذه الأوضاع مع "b" (لـ binary) أو "t" (لـ text). سيتم استخدام permissions لتعيين أذونات الملف إذا تم إنشاؤه.

تُرجع القناة المفتوحة أو NULL إذا حدث خطأ.

TCL_OPENCOMMANDCHANNEL

يفتح خط أنابيب لأوامر Tcl. يتم تشغيل الأوامر المحددة في argv (يجب أن يكون هناك اثنان على الأقل: أمر بدء وأمر نهاية) ويتم ربطها ببعضها البعض. يتم تحديد تصرف المقابض القياسية للإدخال/الإخراج للعملية الأولى في الأنبوب بواسطة flags.

تُرجع القناة المفتوحة أو NULL إذا حدث خطأ.

TCL_MAKEFILECHANNEL

يُنشئ قناة Tcl بناءً على مقبض نظام تشغيل موجود (مثل واصف ملف Unix أو مقبض Windows). يجب أن تحدد readOrWrite ما إذا كان المقبض قابلاً للقراءة و/أو الكتابة.

تُرجع القناة التي تم إنشاؤها أو NULL إذا حدث خطأ.

TCL_GETCHANNEL

يسترجع قناة Tcl المسجلة بالاسم channelName. إذا تم توفير modePtr، فسيتم تعيينه ليشير إلى حالة القناة (قابلة للقراءة/الكتابة).

تُرجع القناة أو NULL إذا لم يتم العثور على القناة أو حدث خطأ.

TCL_GETCHANNELNAMES

يُسجل القنوات المتاحة في المفسر. سيتم تعيين قيمة الخاصية channels للمفسر إلى قائمة بأسماء القنوات المتاحة.

تُرجع عدد القنوات المسجلة أو -1 في حالة حدوث خطأ.

TCL_GETCHANNELNAMESEX

مشابه لـ Tcl_GetChannelNames، ولكنه يقوم بتصفية القنوات المسجلة بناءً على pattern. يتم استخدام Tcl_StringMatch لمطابقة الأنماط.

تُرجع عدد القنوات المطابقة أو -1 في حالة حدوث خطأ.

TCL_REGISTERCHANNEL

يسجل قناة Tcl مع المفسر المحدد، مما يجعلها متاحة لعمليات Tcl اللاحقة.

TCL_UNREGISTERCHANNEL

يزيل قناة Tcl من التسجيل في المفسر المحدد. لن تكون القناة متاحة بعد ذلك لعمليات Tcl.

تُرجع 0 عند النجاح، و -1 عند الفشل.

TCL_DETACHCHANNEL

يزيل قناة Tcl من المفسر المحدد، ولكنه لا يغلق القناة. يسمح هذا للتطبيق بإدارة القناة يدويًا.

تُرجع 0 عند النجاح، و -1 عند الفشل.

TCL_ISSTANDARDCHANNEL

تُرجع قيمة غير صفرية إذا كانت القناة هي إحدى القنوات القياسية (stdin، stdout، stderr) وتُرجع 0 بخلاف ذلك.

TCL_CLOSE

يغلق قناة Tcl. يقوم هذا بتنفيذ أي مخازن مؤقتة معلقة قبل إغلاق القناة الأساسية.

تُرجع 0 عند النجاح، و -1 عند الفشل.

TCL_READCHARS

يقرأ ما يصل إلى charsToRead من الأحرف من القناة ويضعها في readObjPtr. إذا كان appendFlag غير صفري، يتم إلحاق البيانات المقروءة بالقيمة الحالية لـ readObjPtr. خلاف ذلك، يتم استبدال المحتويات الحالية.

تُرجع عدد الأحرف المقروءة، أو -1 إذا حدث خطأ أو تم الوصول إلى نهاية الملف.

TCL_READ

يقرأ ما يصل إلى bytesToRead من البايتات من القناة ويضعها في readBuf.

تُرجع عدد البايتات المقروءة، أو -1 إذا حدث خطأ أو تم الوصول إلى نهاية الملف.

TCL_GETSOBJ

يقرأ سطرًا من القناة، بما في ذلك أي حرف سطر جديد، ويخزنه في lineObjPtr. يتم إلحاق السطر المقروء بالقيمة الحالية لـ lineObjPtr. يحدد Tcl_Encoding في القناة كيفية تفسير الأحرف (مثل نهايات الأسطر).

تُرجع 1 عند النجاح، و 0 إذا تم الوصول إلى نهاية الملف دون قراءة أي أحرف، و -1 إذا حدث خطأ.

TCL_GETS

مشابه لـ Tcl_GetsObj، ولكنه يكتب السطر المقروء في سلسلة Tcl ديناميكية (lineRead).

تُرجع 1 عند النجاح، و 0 إذا تم الوصول إلى نهاية الملف دون قراءة أي أحرف، و -1 إذا حدث خطأ.

TCL_UNGETS

يضع السلسلة input في المخزن المؤقت للإدخال للقناة. إذا كان addAtEnd غير صفري، فسيتم إضافة البيانات إلى نهاية المخزن المؤقت، وإلا فسيتم إضافتها إلى البداية.

لا تُرجع أي قيمة.

TCL_WRITEOBJ

يكتب محتويات كائن Tcl writeObjPtr إلى القناة.

تُرجع عدد البايتات المكتوبة، أو -1 إذا حدث خطأ.

TCL_WRITECHARS

يكتب bytesToWrite من الأحرف من charBuf إلى القناة.

تُرجع عدد البايتات المكتوبة، أو -1 إذا حدث خطأ.

TCL_WRITE

يكتب bytesToWrite من البايتات من byteBuf إلى القناة.

تُرجع عدد البايتات المكتوبة، أو -1 إذا حدث خطأ.

TCL_READRAW

يقرأ ما يصل إلى bytesToRead من البايتات من القناة (بدون أي تحويل للترميز) ويضعها في readBuf.

تُرجع عدد البايتات المقروءة، أو -1 إذا حدث خطأ أو تم الوصول إلى نهاية الملف.

TCL_WRITERAW

يكتب bytesToWrite من البايتات من byteBuf إلى القناة (بدون أي تحويل للترميز).

تُرجع عدد البايتات المكتوبة، أو -1 إذا حدث خطأ.

TCL_EOF

تُرجع قيمة غير صفرية إذا تم الوصول إلى نهاية ملف القناة (EOF) وتمت قراءة جميع البيانات من المخزن المؤقت للقراءة. تُرجع 0 بخلاف ذلك.

TCL_FLUSH

يقوم بإخراج أي بيانات مؤقتة للقناة (مثل البيانات في المخزن المؤقت للكتابة) إلى الجهاز الأساسي.

تُرجع 0 عند النجاح، و -1 عند الفشل.

TCL_INPUTBLOCKED

تُرجع قيمة غير صفرية إذا كانت عملية القراءة التالية على القناة ستحجب (أي، لن تتوفر بيانات كافية على الفور). تُرجع 0 بخلاف ذلك.

TCL_INPUTBUFFERED

تُرجع عدد البايتات الموجودة حاليًا في المخزن المؤقت للقراءة للقناة.

TCL_OUTPUTBUFFERED

تُرجع عدد البايتات الموجودة حاليًا في المخزن المؤقت للكتابة للقناة والتي لم يتم إخراجها بعد إلى الجهاز الأساسي.

TCL_SEEK

يغير نقطة الوصول الحالية للقناة. يتم تحديد الموضع الجديد بواسطة offset و seekMode (SEEK_SET، SEEK_CUR، SEEK_END).

تُرجع الموضع الجديد للقناة بالبايتات، أو -1 إذا حدث خطأ.

TCL_TELL

تُرجع الموضع الحالي لنقطة الوصول في القناة بالبايتات.

تُرجع الموضع الحالي، أو -1 إذا حدث خطأ.

TCL_TRUNCATECHANNEL

يقوم باقتطاع القناة إلى الطول المحدد length. إذا كان length أكبر من الطول الحالي، فسيتم تمديد القناة (عادةً بما يكفي من بايتات NULL). إذا كانت القناة غير قابلة للاقتطاع، فسيحدث خطأ.

تُرجع 0 عند النجاح، و -1 عند الفشل.

TCL_GETCHANNELOPTION

يحصل على قيمة الخيار المحدد optionName للقناة channel ويخزنها في optionValue (سلسلة Tcl ديناميكية).

تُرجع 0 عند النجاح، و -1 عند الفشل.

TCL_SETCHANNELOPTION

يقوم بتعيين الخيار المحدد optionName للقناة channel إلى القيمة newValue.

تُرجع 0 عند النجاح، و -1 عند الفشل.

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel يفتح ملفًا محددًا بواسطة fileName ويعيد مقبض قناة يمكن استخدامه لإجراء عمليات الإدخال والإخراج على الملف. تم تصميم واجهة برمجة التطبيقات هذه على غرار إجراء fopen في مكتبة الإدخال والإخراج القياسية Unix. بناء الجملة ومعنى جميع الوسائط مشابه لتلك المعطاة في أمر Tcl open عند فتح ملف. إذا حدث خطأ أثناء فتح القناة، تعيد Tcl_OpenFileChannel القيمة NULL وتسجل رمز خطأ POSIX يمكن استرداده باستخدام Tcl_GetErrno. بالإضافة إلى ذلك، إذا كان interp ليس NULL، فإن Tcl_OpenFileChannel تترك رسالة خطأ في نتيجة interp بعد أي خطأ. اعتبارًا من Tcl 8.4، يجب استخدام القيمة المستندة إلى واجهة برمجة التطبيقات Tcl_FSOpenFileChannel بدلاً من Tcl_OpenFileChannel حيثما أمكن.

القناة التي تم إنشاؤها حديثًا لا يتم تسجيلها في المفسر المقدم؛ لتسجيلها، يجب استخدام Tcl_RegisterChannel، الموضحة أدناه. إذا تم إغلاق إحدى القنوات القياسية، stdin، stdout، أو stderr مسبقًا، فإن إجراء إنشاء القناة الجديدة يقوم أيضًا بتعيينها كبديل للقناة القياسية.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel يوفر واجهة على مستوى C لوظائف الأوامر exec و open. يقوم بإنشاء سلسلة من العمليات اللاحقة المحددة بواسطة الوسائط argv و argc ويعيد قناة يمكن استخدامها للتواصل مع هذه العمليات اللاحقة. يشير الوسيط flags إلى نوع الاتصال الذي سيتم إجراؤه مع سلسلة الأوامر.

إذا تم تعيين علامة TCL_STDIN، يتم ربط الإدخال القياسي للعملية الأولى بالقناة: الكتابة في القناة توفر الإدخال للعملية اللاحقة. إذا لم يتم تعيين علامة TCL_STDIN، فإن الإدخال القياسي للعملية الأولى سيكون هو نفسه الإدخال القياسي لهذا التطبيق. إذا تم تعيين علامة TCL_STDOUT، يمكن قراءة الإخراج القياسي لآخر عملية لاحقة من القناة؛ بخلاف ذلك، يتم توجيهه إلى الإخراج القياسي لهذا التطبيق. إذا تم تعيين علامة TCL_STDERR، يتم إرجاع خطأ الإخراج القياسي لجميع العمليات اللاحقة إلى القناة وتسبب خطأ عند إغلاق القناة؛ بخلاف ذلك، يتم توجيهه إلى خطأ الإخراج القياسي لهذا التطبيق. إذا لم يتم تعيين علامة TCL_ENFORCE_MODE، يمكن للوسائط argc و argv إعادة توجيه المقابض القياسية لتجاوز TCL_STDIN و TCL_STDOUT و TCL_STDERR؛ إذا تم تعيينها، فإنه يمثل خطأ بالنسبة لـ argc و argv التي تعيد توجيه القنوات القياسية التي تم تعيين TCL_STDIN و TCL_STDOUT و TCL_STDERR لها.

إذا حدث خطأ أثناء فتح القناة، تعيد Tcl_OpenCommandChannel القيمة NULL وتسجل رمز خطأ POSIX يمكن استرداده باستخدام Tcl_GetErrno. بالإضافة إلى ذلك، تترك Tcl_OpenCommandChannel رسالة خطأ في نتيجة المفسر. لا يمكن أن يكون interp NULL.

القناة التي تم إنشاؤها حديثًا لا يتم تسجيلها في المفسر المقدم؛ لتسجيلها، يجب استخدام Tcl_RegisterChannel، الموضحة أدناه. إذا تم إغلاق إحدى القنوات القياسية، stdin، stdout، أو stderr مسبقًا، فإن إجراء إنشاء القناة الجديدة يقوم أيضًا بتعيينها كبديل للقناة القياسية.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel ينشئ Tcl_Channel من مقبض ملف موجود وعلى وجه التحديد من نظام التشغيل. القناة التي تم إنشاؤها حديثًا لا يتم تسجيلها في المفسر المقدم؛ لتسجيلها، يجب استخدام Tcl_RegisterChannel، الموضحة أدناه. إذا تم إغلاق إحدى القنوات القياسية، stdin، stdout، أو stderr مسبقًا، فإن إجراء إنشاء القناة الجديدة يقوم أيضًا بتعيينها كبديل للقناة القياسية.

TCL_GETCHANNEL

Tcl_GetChannel تعيد قناة بالنظر إلى channelName المستخدم لإنشائها باستخدام Tcl_CreateChannel ومؤشر إلى المفسر في interp. إذا لم يتم تسجيل قناة بهذا الاسم في هذا المفسر، فإن الإجراء يعيد NULL. إذا كان الوسيط modePtr ليس NULL، فإنه يشير إلى متغير صحيح سيستقبل OR مشفرًا من TCL_READABLE و TCL_WRITABLE للإشارة إلى ما إذا كانت القناة مفتوحة للقراءة والكتابة.

Tcl_GetChannelNames و Tcl_GetChannelNamesEx تكتب أسماء القنوات المسجلة في نتيجة المفسر كقيمة قائمة. ستقوم Tcl_GetChannelNamesEx بتصفية هذه الأسماء وفقًا لـ pattern. إذا كان pattern NULL، فلن تقوم بالتصفية. القيمة المرجعة هي TCL_OK إذا لم تكن هناك أخطاء في الكتابة إلى النتيجة، وإلا فإنها TCL_ERROR وتترك رسالة الخطأ في نتيجة المفسر.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel تضيف قناة إلى مجموعة القنوات التي يمكن الوصول إليها في interp. بعد هذا الاستدعاء، يمكن لبرامج Tcl التي تم تنفيذها في هذا المفسر الرجوع إلى القناة بالاسم المقدم في استدعاء Tcl_CreateChannel. بعد هذا الاستدعاء، تصبح القناة ملكًا للمفسر ويجب على المستخدم تجنب استدعاء Tcl_Close للقناة؛ يتم إغلاق القناة تلقائيًا عند إلغاء تسجيلها من المفسر.

يمكن للرمز الذي يتم تنفيذه خارج أي مفسر استدعاء Tcl_RegisterChannel مع interp كـ NULL، للإشارة إلى أنك ترغب في الاحتفاظ بمرجع لهذه القناة. لاحقًا، يمكن تسجيل القناة في مفسر Tcl ولن يتم إغلاقها إلا عند إجراء عدد مكافئ من استدعاءات Tcl_UnregisterChannel. هذا يسمح للرمز الذي يتم تنفيذه خارج أي مفسر بالاحتفاظ بمرجع آمن لقناة مسجلة أيضًا في مفسر Tcl.

يتفاعل هذا الإجراء مع الرمز الذي يدير القنوات القياسية. إذا لم يتم تهيئة أي قنوات قياسية قبل الاستدعاء الأول لـ Tcl_RegisterChannel، فسيتم تهيئتها بواسطة هذا الاستدعاء. راجع Tcl_StandardChannels للحصول على نظرة عامة على القنوات القياسية وسلوك مكتبة Tcl فيما يتعلق بها.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel تزيل قناة من مجموعة القنوات التي يمكن الوصول إليها في interp. بعد هذا الاستدعاء، لن تتمكن برامج Tcl من استخدام اسم القناة للإشارة إلى القناة في هذا المفسر. إذا أزال هذا الإجراء آخر تسجيل للقناة في أي مفسر، فسيتم إغلاق القناة وتدميرها أيضًا.

يمكن للرمز غير المرتبط بأي مفسر استدعاء Tcl_UnregisterChannel مع interp كـ NULL، للإشارة إلى Tcl أنك لم تعد تحتفظ بمرجع لهذه القناة. إذا كان هذا هو المرجع الأخير للقناة، فسيتم إغلاقها الآن. Tcl_UnregisterChannel مشابه جدًا لـ Tcl_DetachChannel باستثناء أنه يغلق القناة أيضًا إذا لم تكن هناك مراجع متبقية.

TCL_DETACHCHANNEL

Tcl_DetachChannel تزيل قناة من مجموعة القنوات التي يمكن الوصول إليها في interp. بعد هذا الاستدعاء، لن تتمكن برامج Tcl من استخدام اسم القناة للإشارة إلى القناة في هذا المفسر. بخلاف ذلك، لا يكون لهذا الأمر أي تأثير إضافي. لا يمكن استخدامه على القنوات القياسية (stdout، stderr، stdin) وسيعيد TCL_ERROR إذا تم تمريره إحدى هذه القنوات.

يمكن للرمز غير المرتبط بأي مفسر استدعاء Tcl_DetachChannel مع interp كـ NULL، للإشارة إلى Tcl أنك لم تعد تحتفظ بمرجع لهذه القناة. إذا كان هذا هو المرجع الأخير للقناة، كما في Tcl_UnregisterChannel، فلن يتم إغلاقها.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel تختبر ما إذا كانت قناة هي إحدى القنوات القياسية الثلاث، stdin، stdout، أو stderr. إذا كان الأمر كذلك، فستعيد 1، وإلا فستعيد 0.

لا يتم إجراء أي محاولة للتحقق مما إذا كانت القناة المعطاة أو القنوات القياسية مهيأة أو صالحة.

TCL_CLOSE

Tcl_Close تدمر القناة channel، والتي يجب أن تشير إلى قناة مفتوحة حاليًا. يجب ألا تكون القناة مسجلة في أي مفسر عند استدعاء Tcl_Close. يتم إفراغ مخزن الإخراج المؤقت قبل تدمير القناة، ويتم إزالة أي إدخال مخزن مؤقت. إذا كانت القناة مانعة، فإن الاستدعاء لا يعود حتى يتم إرسال جميع البيانات المخزنة مؤقتًا إلى جهاز الإخراج للقناة. إذا كانت القناة غير مانعة وهناك بيانات مخزنة مؤقتًا لا يمكن كتابتها دون حظر، فإن الاستدعاء يعود على الفور؛ يتم إفراغ الإخراج في الخلفية ويتم إغلاق القناة عند إخراج جميع البيانات المخزنة مؤقتًا. في هذه الحالة، لا يتم الإبلاغ عن الأخطاء أثناء الإفراغ.

إذا تم إغلاق القناة بنجاح، فإن Tcl_Close تعيد TCL_OK. إذا حدث خطأ، فإن Tcl_Close تعيد TCL_ERROR وتسجل رمز خطأ POSIX يمكن استرداده باستخدام Tcl_GetErrno. إذا تم إغلاق القناة بشكل متزامن وحدث خطأ أثناء الإغلاق وكان interp ليس NULL، فسيتم ترك رسالة خطأ في نتيجة المفسر.

ملاحظة: ليس من الآمن استدعاء Tcl_Close على قناة تم تسجيلها باستخدام Tcl_RegisterChannel؛ راجع الوثائق الخاصة بـ Tcl_RegisterChannel، أعلاه، للحصول على التفاصيل. إذا تم تمرير القناة كوسيط chan في أي استدعاء لـ Tcl_RegisterChannel، فيجب عليك استخدام Tcl_UnregisterChannel، الذي يستدعي داخليًا Tcl_Close عند الانتهاء من جميع استدعاءات Tcl_RegisterChannel باستدعاءات مقابلة لـ Tcl_UnregisterChannel

TCL_READCHARS AND TCL_READ

Tcl_ReadChars تستهلك بايتات من channel، وتحولها إلى UTF-8 وفقًا لترميز القناة وتخزن البيانات المنتجة في تمثيل readObjPtr. القيمة المرجعة لـ Tcl_ReadChars هي عدد الأحرف، حتى charsToRead، التي تم تخزينها في readObjPtr. إذا حدث خطأ أثناء القراءة، فإن القيمة المرجعة هي -1 و Tcl_ReadChars تسجل رمز خطأ POSIX يمكن استرداده باستخدام Tcl_GetErrno.

القيمة المرجعة لـ Tcl_ReadChars هي عدد الأحرف، حتى charsToRead، التي تم تخزينها في readObjPtr. إذا حدث خطأ أثناء القراءة، فإن القيمة المرجعة هي -1 و Tcl_ReadChars تسجل رمز خطأ POSIX يمكن استرداده باستخدام Tcl_GetErrno.

عن طريق تعيين char

TCL_READCHARS, TCL_READOBJ, AND TCL_READ

When called with charsToRead set to -1, the command will read all characters currently available (mode non-blocking) or everything until eof (mode blocking).

The return value may be smaller than the value to read, indicating that less data than requested was available. This is called a short read. In blocking mode, this can only happen on an end-of-file. In nonblocking mode, a short read can also occur if there is not enough input currently available: Tcl_ReadChars returns a short count rather than waiting for more data.

If the channel is in blocking mode, a return value of zero indicates an end-of-file condition. If the channel is in nonblocking mode, a return value of zero indicates either that no input is currently available or an end-of-file condition. Use Tcl_Eof and Tcl_InputBlocked to tell which of these conditions actually occurred.

Tcl_ReadChars translates the various end-of-line representations into the canonical \n internal representation according to the current end-of-line recognition mode. End-of-line recognition and the various platform-specific modes are described in the manual entry for the Tcl fconfigure command.

As a performance optimization, when reading from a channel with the encoding binary, the bytes are not converted to UTF-8 as they are read. Instead, they are stored in readObjPtr's internal representation as a byte-array value. The string representation of this value will only be constructed if it is needed (e.g., because of a call to Tcl_GetStringFromObj). In this way, byte-oriented data can be read from a channel, manipulated by calling Tcl_GetByteArrayFromObj and related functions, and then written to a channel without the expense of ever converting to or from UTF-8.

Tcl_Read is similar to Tcl_ReadChars, except that it does not do encoding conversions, regardless of the channel's encoding. It is deprecated and exists for backwards compatibility with non-internationalized Tcl extensions. It consumes bytes from channel and stores them in readBuf, performing end-of-line translations on the way. The return value of Tcl_Read is the number of bytes, up to bytesToRead, written in readBuf. The buffer produced by Tcl_Read is not null-terminated. Its contents are valid from the zeroth position up to and excluding the position indicated by the return value.

Tcl_ReadRaw is the same as Tcl_Read but does not compensate for stacking. While Tcl_Read (and the other functions in the API) always get their data from the topmost channel in the stack the supplied channel is part of, Tcl_ReadRaw does not. Thus this function is only usable for transformational channel drivers, i.e. drivers used in the middle of a stack of channels, to move data from the channel below into the transformation.

TCL_GETSOBJ AND TCL_GETS

Tcl_GetsObj consumes bytes from channel, converting the bytes to UTF-8 based on the channel's encoding, until a full line of input has been seen. If the channel's encoding is binary, each byte read from the channel is treated as an individual Unicode character. All of the characters of the line except for the terminating end-of-line character(s) are appended to lineObjPtr's string representation. The end-of-line character(s) are read and discarded.

If a line was successfully read, the return value is greater than or equal to zero and indicates the number of bytes stored in lineObjPtr. If an error occurs, Tcl_GetsObj returns -1 and records a POSIX error code that can be retrieved with Tcl_GetErrno. Tcl_GetsObj also returns -1 if the end of the file is reached; the Tcl_Eof procedure can be used to distinguish an error from an end-of-file condition.

If the channel is in nonblocking mode, the return value can also be -1 if no data was available or the data that was available did not contain an end-of-line character. When -1 is returned, the Tcl_InputBlocked procedure may be invoked to determine if the channel is blocked because of input unavailability.

Tcl_Gets is the same as Tcl_GetsObj except the resulting characters are appended to the dynamic string given by lineRead rather than a Tcl value.

TCL_UNGETS

Tcl_Ungets is used to add data to the input queue of a channel, at either the head or tail of the queue. The pointer input points to the data that is to be added. The length of the input to add is given by inputLen. A non-zero value of addAtEnd indicates that the data is to be added at the end of queue; otherwise it will be added at the head of the queue. If channel has a “sticky” EOF set, no data will be added to the input queue. Tcl_Ungets returns inputLen or -1 if an error occurs.

TCL_WRITECHARS, TCL_WRITEOBJ, AND TCL_WRITE

Tcl_WriteChars accepts bytesToWrite bytes of character data at charBuf. The UTF-8 characters in the buffer are converted to the channel's encoding and queued for output to channel. If bytesToWrite is negative, Tcl_WriteChars expects charBuf to be null-terminated and it outputs everything up to the null.

Data queued for output may not appear on the output device immediately, due to internal buffering. If the data should appear immediately, call Tcl_Flush after the call to Tcl_WriteChars, or set the -buffering option on the channel to none. If you wish the data to appear as soon as a complete line is accepted for output, set the -buffering option on the channel to line mode.

The return value of Tcl_WriteChars is a count of how many bytes were accepted for output to the channel. This is either greater than zero to indicate success or -1 to indicate that an error occurred. If an error occurs, Tcl_WriteChars records a POSIX error code that may be retrieved with Tcl_GetErrno.

Newline characters in the output data are translated to platform-specific end-of-line sequences according to the -translation option for the channel. This is done even if the channel has no encoding.

Tcl_WriteObj is similar to Tcl_WriteChars except it accepts a Tcl value whose contents will be output to the channel. The UTF-8 characters in writeObjPtr's string representation are converted to the channel's encoding and queued for output to channel. As a performance optimization, when writing to a channel with the encoding binary, UTF-8 characters are not converted as they are written. Instead, the bytes in writeObjPtr's internal representation as a byte-array value are written to the channel. The byte-array representation of the value will be constructed if it is needed. In this way, byte-oriented data can be read from a channel, manipulated by calling Tcl_GetByteArrayFromObj and related functions, and then written to a channel without the expense of ever converting to or from UTF-8.

Tcl_Write is similar to Tcl_WriteChars except that it does not do encoding conversions, regardless of the channel's encoding. It is deprecated and exists for backwards compatibility with non-internationalized Tcl extensions. It accepts bytesToWrite bytes of data at byteBuf and queues them for output to channel. If bytesToWrite is negative, Tcl_Write expects byteBuf to be null-terminated and it outputs everything up to the null.

Tcl_WriteRaw is the same as Tcl_Write but does not compensate for stacking. While Tcl_Write (and the other functions in the API) always feed their input to the topmost channel in the stack the supplied channel is part of, Tcl_WriteRaw does not. Thus this function is only usable for transformational channel drivers, i.e. drivers used in the middle of a stack of channels, to move data from the transformation into the channel below it.

TCL_FLUSH

Tcl_Flush causes all of the buffered output data for channel to be written to its underlying file or device as soon as possible. If the channel is in blocking mode, the call does not return until all the buffered data has been sent to the channel or some error occurred. The call returns immediately if the channel is nonblocking; it starts a background flush that will write the buffered data to the channel eventually, as fast as the channel is able to absorb it.

The return value is normally TCL_OK. If an error occurs, Tcl_Flush returns TCL_ERROR and records a POSIX error code that can be retrieved with Tcl_GetErrno.

TCL_SEEK

Tcl_Seek moves the access point in channel where subsequent data will be read or written. Buffered output is flushed to the channel and buffered input is discarded, prior to the seek operation.

Tcl_Seek normally returns the new access point. If an error occurs, Tcl_Seek returns -1 and records a POSIX error code that can be retrieved with Tcl_GetErrno. After an error, the access point may or may not have been moved.

TCL_TELL

Tcl_Tell returns the current access point for a channel. The returned value is -1 if the channel does not support seeking.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel truncates the file underlying channel to a given length of bytes. It returns TCL_OK if the operation succeeded, and TCL_ERROR otherwise.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption retrieves, in optionValue, the value of one of the options currently in effect for a channel, or a list of all options and their values. The channel argument identifies the channel for which to query an option or retrieve all options and their values. If optionName is not NULL, it is the name of the option to query; the option's value is copied to the Tcl dynamic string denoted by optionValue.
