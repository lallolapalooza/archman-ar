Tcl_TraceVar(3) Tcl Library Procedures Tcl_TraceVar(3)

NAME

Tcl_TraceVar, Tcl_TraceVar2, Tcl_UntraceVar, Tcl_UntraceVar2, Tcl_VarTraceInfo, Tcl_VarTraceInfo2 - monitor accesses to a variable

SYNOPSIS

#include <tcl.h>

int
Tcl_TraceVar(interp, varName, flags, proc, clientData)

int
Tcl_TraceVar2(interp, name1, name2, flags, proc, clientData)

Tcl_UntraceVar(interp, varName, flags, proc, clientData)

Tcl_UntraceVar2(interp, name1, name2, flags, proc, clientData)

ClientData
Tcl_VarTraceInfo(interp, varName, flags, proc, prevClientData)

ClientData
Tcl_VarTraceInfo2(interp, name1, name2, flags, proc, prevClientData)

ARGUMENTS

Tcl_Interp *interp (in)
Interpreter containing variable.
const char *varName (in)
Name of variable. May refer to a scalar variable, to an array variable with no index, or to an array variable with a parenthesized index.
int flags (in)
OR-ed combination of the values TCL_TRACE_READS, TCL_TRACE_WRITES, TCL_TRACE_UNSETS, TCL_TRACE_ARRAY, TCL_GLOBAL_ONLY, TCL_NAMESPACE_ONLY, TCL_TRACE_RESULT_DYNAMIC and TCL_TRACE_RESULT_OBJECT. Not all flags are used by all procedures. See below for more information.
Tcl_VarTraceProc *proc (in)
Procedure to invoke whenever one of the traced operations occurs.
ClientData clientData (in)
Arbitrary one-word value to pass to proc.
const char *name1 (in)
Name of scalar or array variable (without array index).
const char *name2 (in)
For a trace on an element of an array, gives the index of the element. For traces on scalar variables or on whole arrays, is NULL.
ClientData prevClientData (in)
If non-NULL, gives last value returned by Tcl_VarTraceInfo or Tcl_VarTraceInfo2, so this call will return information about next trace. If NULL, this call will return information about first trace.

DESCRIPTION

Tcl_TraceVar allows a C procedure to monitor and control access to a Tcl variable, so that the C procedure is invoked whenever the variable is read or written or unset. If the trace is created successfully then Tcl_TraceVar returns TCL_OK. If an error occurred (e.g. varName specifies an element of an array, but the actual variable is not an array) then TCL_ERROR is returned and an error message is left in the interpreter's result.

The flags argument to Tcl_TraceVar indicates when the trace procedure is to be invoked and provides information for setting up the trace. It consists of an OR-ed combination of any of the following values:

TCL_GLOBAL_ONLY
Normally, the variable will be looked up at the current level of procedure call; if this bit is set then the variable will be looked up at global level, ignoring any active procedures.
TCL_NAMESPACE_ONLY
Normally, the variable will be looked up at the current level of procedure call; if this bit is set then the variable will be looked up in the current namespace, ignoring any active procedures.
TCL_TRACE_READS
Invoke proc whenever an attempt is made to read the variable.
TCL_TRACE_WRITES
Invoke proc whenever an attempt is made to modify the variable.
TCL_TRACE_UNSETS
Invoke proc whenever the variable is unset. A variable may be unset either explicitly by an unset command, or implicitly when a procedure returns (its local variables are automatically unset) or when the interpreter is deleted (all variables are automatically unset).
TCL_TRACE_ARRAY
Invoke proc whenever the array command is invoked. This gives the trace procedure a chance to update the array before array names or array get is called. Note that this is called before an array set, but that will trigger write traces.
TCL_TRACE_RESULT_DYNAMIC
The result of invoking the proc is a dynamically allocated string that will be released by the Tcl library via a call to ckfree. Must not be specified at the same time as TCL_TRACE_RESULT_OBJECT.
TCL_TRACE_RESULT_OBJECT
The result of invoking the proc is a Tcl_Obj* (cast to a char*) with a reference count of at least one. The ownership of that reference will be transferred to the Tcl core for release (when the core has finished with it) via a call to Tcl_DecrRefCount. Must not be specified at the same time as TCL_TRACE_RESULT_DYNAMIC.

Whenever one of the specified operations occurs on the variable, proc will be invoked. It should have arguments and result that match the type Tcl_VarTraceProc:

typedef char *Tcl_VarTraceProc(
        ClientData clientData,
        Tcl_Interp *interp,
        const char *name1,
        const char *name2,
        int flags);

The clientData and interp parameters will have the same values as those passed to Tcl_TraceVar when the trace was created. ClientData typically points to an application-specific data structure that describes what to do when proc is invoked. Name1 and name2 give the name of the traced variable in the normal two-part form (see the description of Tcl_TraceVar2 below for details). Flags is an OR-ed combination of bits providing several pieces of information. One of the bits TCL_TRACE_READS, TCL_TRACE_WRITES, TCL_TRACE_ARRAY, or TCL_TRACE_UNSETS will be set in flags to indicate which operation is being performed on the variable. The bit TCL_GLOBAL_ONLY will be set whenever the variable being accessed is a global one not accessible from the current level of procedure call: the trace procedure will need to pass this flag back to variable-related procedures like Tcl_GetVar if it attempts to access the variable. The bit TCL_NAMESPACE_ONLY will be set whenever the variable being accessed is a namespace one not accessible from the current level of procedure call: the trace procedure will need to pass this flag back to variable-related procedures like Tcl_GetVar if it attempts to access the variable. The bit TCL_TRACE_DESTROYED will be set in flags if the trace is about to be destroyed; this information may be useful to proc so that it can clean up its own internal data structures (see the section TCL_TRACE_DESTROYED below for more details). Lastly, the bit TCL_INTERP_DESTROYED will be set if the entire interpreter is being destroyed. When this bit is set, proc must be especially careful in the things it does (see the section TCL_INTERP_DESTROYED below). The trace procedure's return value should normally be NULL; see ERROR RETURNS below for information on other possibilities.

Tcl_UntraceVar may be used to remove a trace. If the variable specified by interp, varName, and flags has a trace set with flags, proc, and clientData, then the corresponding trace is removed. If no such trace exists, then the call to Tcl_UntraceVar has no effect. The same bits are valid for flags as for calls to Tcl_TraceVar.

Tcl_VarTraceInfo may be used to retrieve information about traces set on a given variable. The return value from Tcl_VarTraceInfo is the clientData associated with a particular trace. The trace must be on the variable specified by the interp, varName, and flags arguments (only the TCL_GLOBAL_ONLY and TCL_NAMESPACE_ONLY bits from flags is used; other bits are ignored) and its trace procedure must the same as the proc argument. TCL_VARTRACEINFO

يُستخدم هذا الإجراء لاسترداد معلومات حول متعقبات المتغيرات. يُرجع الإجراء مؤشرًا إلى هيكل Tcl_TraceVarInfo يصف متعقبًا واحدًا للمتغير. إذا كان الوسيط prevClientData ليس NULL، فيجب أن يكون نتيجة استدعاء سابق لـ Tcl_VarTraceInfo. في هذه الحالة، ستتوافق النتيجة الجديدة مع المتعقب المطابق التالي بعد المتعقب الذي يتطابق فيه clientData مع prevClientData، أو NULL إذا لم يتطابق أي متعقب مع prevClientData أو إذا لم تكن هناك متعقبات مطابقة بعده. تجعل هذه الآلية من الممكن المرور عبر جميع متعقبات متغير معين التي لها نفس proc.

أسماء ذات جزأين

الإجراءات Tcl_TraceVar2 و Tcl_UntraceVar2 و Tcl_VarTraceInfo2 متطابقة مع Tcl_TraceVar و Tcl_UntraceVar و Tcl_VarTraceInfo على التوالي، باستثناء أن اسم المتغير يتكون من جزأين. يوفر Name1 اسم متغير قياسي أو مصفوفة، ويوفر name2 اسم عنصر داخل مصفوفة. عندما يكون name2 هو NULL، يمكن أن يحتوي name1 على اسم مصفوفة واسم عنصر: إذا كان الاسم يحتوي على قوس مفتوح وينتهي بقوس مغلق، فإن القيمة بين الأقواس تُعامل كاسم عنصر (والذي يمكن أن يكون له أي قيمة نصية) والأحرف قبل القوس المفتوح الأول تُعامل كاسم متغير مصفوفة. إذا كان name2 هو NULL و name1 لا يشير إلى عنصر مصفوفة، فهذا يعني إما أن المتغير قياسي أو أن المتعقب سيتم تعيينه على المصفوفة بأكملها بدلاً من عنصر فردي (انظر متعقبات المصفوفة الكاملة أدناه لمزيد من المعلومات).

الوصول إلى المتغيرات أثناء المتعقبات

خلال متعقبات القراءة والكتابة والمصفوفات، يمكن لإجراء المتعقب قراءة أو كتابة أو إلغاء تعيين المتغير المتعقب باستخدام Tcl_GetVar2 و Tcl_SetVar2 وإجراءات أخرى. أثناء تنفيذ proc، يتم تعطيل المتعقبات مؤقتًا للمتغير، بحيث أن استدعاءات Tcl_GetVar2 و Tcl_SetVar2 لن تتسبب في استدعاء proc أو إجراءات متعقبة أخرى مرة أخرى. يحدث التعطيل فقط للمتغير الذي يكون إجراء المتعقب الخاص به نشطًا؛ ستظل عمليات الوصول إلى المتغيرات الأخرى متعقبة. ومع ذلك، إذا تم إلغاء تعيين متغير أثناء متعقب قراءة أو كتابة، فسيتم استدعاء متعقبات الإلغاء.

خلال متعقبات الإلغاء، تم بالفعل حذف المتغير بالكامل. من الممكن لإجراء المتعقب قراءة أو كتابة المتغير، ولكن هذه ستكون نسخة جديدة من المتغير. لا يتم تعطيل المتعقبات أثناء متعقبات الإلغاء كما هو الحال بالنسبة لمتعقبات القراءة والكتابة، ولكن تم إزالة المتعقبات الموجودة من المتغير قبل استدعاء أي إجراءات متعقبة. إذا تم تعيين متعقبات جديدة بواسطة إجراءات متعقبات الإلغاء، فسيتم استدعاء هذه المتعقبات عند الوصول إلى المتغير بواسطة إجراءات المتعقبات.

توقيت الاستدعاءات الراجعة

عند تحديد متعقب قراءة لمتغير، سيتم استدعاء إجراء المتعقب في كل مرة تتم فيها قراءة قيمة المتغير. يتضمن هذا أوامر Tcl set، وتدوين $ في أوامر Tcl، واستدعاء إجراءات Tcl_GetVar و Tcl_GetVar2. يتم استدعاء Proc مباشرة قبل إرجاع قيمة المتغير. يمكنه تعديل قيمة المتغير للتأثير على ما يرجعه الوصول المتعقب. إذا قام بإلغاء تعيين المتغير، فسيرجع الوصول خطأ كما لو كان المتغير غير موجود أبدًا.

عند تحديد متعقب كتابة لمتغير، سيتم استدعاء إجراء المتعقب في كل مرة يتم فيها تعديل قيمة المتغير. يتضمن هذا أوامر set، والأوامر التي تعدل المتغيرات كآثار جانبية (مثل catch و scan)، واستدعاءات إجراءات Tcl_SetVar و Tcl_SetVar2). سيتم استدعاء Proc بعد تعديل قيمة المتغير، ولكن قبل إرجاع القيمة الجديدة للمتغير. يمكنه تعديل قيمة المتغير لتجاوز التغيير ولتحديد القيمة التي يتم إرجاعها فعليًا بواسطة الوصول المتعقب. إذا قام بحذف المتغير، فسيرجع الوصول المتعقب سلسلة فارغة.

عند تحديد متعقب مصفوفة، سيتم استدعاء إجراء المتعقب في بداية تنفيذ أمر المصفوفة، قبل استدعاء أي من العمليات مثل الحصول أو التعيين أو الأسماء. يمكن لإجراء المتعقب تعديل عناصر المصفوفة باستخدام Tcl_SetVar و Tcl_SetVar2.

عند تحديد متعقب إلغاء، سيتم استدعاء إجراء المتعقب في كل مرة يتم فيها تدمير المتغير. سيتم استدعاء المتعقبات بعد إلغاء تعيين المتغير بالكامل.

متعقبات المصفوفة الكاملة

إذا حدد استدعاء لـ Tcl_TraceVar أو Tcl_TraceVar2 اسم متغير مصفوفة بدون فهرس في المصفوفة، فسيتم تعيين المتعقب على المصفوفة بأكملها. هذا يعني أنه سيتم استدعاء proc كلما تم الوصول إلى أي عنصر في المصفوفة بالطرق المحددة بواسطة flags. عند إلغاء تعيين مصفوفة، سيتم استدعاء متعقب مصفوفة كامل مرة واحدة فقط، مع كون name1 مساوياً لاسم المصفوفة و name2 هو NULL؛ لن يتم استدعاؤه مرة واحدة لكل عنصر.

متعقبات متعددة

من الممكن وجود متعقبات متعددة على نفس المتغير. عندما يحدث هذا، سيتم استدعاء جميع إجراءات المتعقبات عند كل وصول، بالترتيب من الأحدث إنشاءً إلى الأقدم إنشاءً. عندما توجد متعقبات مصفوفة كاملة لمصفوفة بالإضافة إلى متعقبات على عناصر فردية، يتم استدعاء متعقبات المصفوفة الكاملة قبل متعقبات العناصر الفردية. إذا قام متعقب قراءة أو كتابة بإلغاء تعيين المتغير، فسيتم استدعاء جميع متعقبات الإلغاء ولكن سيتم تخطي باقي متعقبات القراءة والكتابة.

إرجاع الأخطاء

في الظروف العادية، يجب أن تعيد إجراءات المتعقبات NULL، مشيرة إلى اكتمال ناجح. إذا أعاد proc قيمة غير NULL، فهذا يعني حدوث خطأ. يجب أن تكون القيمة المرتجعة مؤشرًا إلى سلسلة أحرف ثابتة تحتوي على رسالة خطأ، ما لم يتم تعيين (علم واحد فقط) من العلامتين TCL_TRACE_RESULT_DYNAMIC و TCL_TRACE_RESULT_OBJECT، والتي تحدد أن النتيجة هي إما سلسلة ديناميكية (سيتم تحريرها باستخدام ckfree) أو Tcl_Obj* (محولة إلى char* وسيتم تحريرها باستخدام Tcl_DecrRefCount) تحتوي على رسالة الخطأ. إذا أعادت إجراءات المتعقبات خطأ، فلن يتم استدعاء أي متعقبات إضافية للوصول وسيتم إلغاء الوصول المتعقب بالرسالة المعطاة. يمكن لإجراءات المتعقبات استخدام هذه الميزة لجعل المتغيرات للقراءة فقط، على سبيل المثال (ولكن لاحظ أنه قد تم تعديل قيمة المتغير بالفعل قبل استدعاء إجراء المتعقب، لذلك سيتعين على إجراء المتعقب استعادة القيمة الصحيحة).

يتم استخدام القيمة المرتجعة من proc فقط أثناء متعقبات القراءة والكتابة. أثناء متعقبات الإلغاء، يتم تجاهل القيمة المرتجعة وسيتم استدعاء جميع إجراءات المتعقبات ذات الصلة دائمًا.

قيود

يمكن استدعاء إجراء المتعقب في أي وقت، حتى عندما تكون هناك نتائج مشكلة جزئيًا مخزنة في المفسر. إذا قام إجراء المتعقب بأي شيء قد يضر بهذه النتيجة (مثل استدعاء Tcl_Eval) فيجب عليه استخدام الروتينات Tcl_SaveInterpState والروتينات ذات الصلة لحفظ واستعادة الحالة الأصلية للمفسر قبل أن يعود.

المتغيرات غير المعرفة

من القانوني تعيين متعقب لمتغير غير معرف. سيظل المتغير يبدو غير معرف حتى المرة الأولى التي يتم فيها تعيين قيمته. إذا تم تتبع متغير غير معرف ثم تم إلغاء تعيينه، فسيفشل إلغاء التعيين بخطأ ("لا يوجد مثل هذا المتغير")، ولكن سيظل إجراء المتعقب مستدعى.

علم TCL_TRACE_DESTROYED

في استدعاء إلغاء إلى proc، يتم تعيين بت TCL_TRACE_DESTROYED في flags إذا كان المتعقب تتم إزالته كجزء من الحذف. تتم دائمًا إزالة المتعقبات على متغير عند حذف المتغير؛ الوقت الوحيد الذي لا يتم فيه تعيين TCL_TRACE_DESTROYED هو لمتعقب مصفوفة كاملة تم استدعاؤه عندما يتم إلغاء تعيين عنصر واحد فقط من مصفوفة.

TCL_INTERP_DESTROYED

عند تدمير مفسر، يتم استدعاء متعقبات الإلغاء لجميع متغيراته. سيتم تعيين بت TCL_INTERP_DESTROYED في الوسيط flags الذي تم تمريره إلى إجراءات المتعقبات. يجب أن تكون إجراءات المتعقبات حذرة للغاية فيما تفعله إذا تم تعيين بت TCL_INTERP_DESTROYED. لا يجوز للإجراءات استدعاء أي إجراءات Tcl على المفسر، نظرًا لأن حالته محذوفة جزئيًا. كل ما يجب أن تفعله إجراءات المتعقبات في ظل هذه الظروف هو تنظيف وتحرير هياكل بياناتها الداخلية الخاصة.

الأخطاء

لا يقوم Tcl بأي فحص للأخطاء لمنع إجراءات المتعقبات من إساءة استخدام المفسر أثناء المتعقبات مع تعيين TCL_INTERP_DESTROYED.

لم يتم دمج متعقبات المصفوفات بعد مع أمر Tcl info exists، ولا يوجد وصول على مستوى Tcl لمتعقبات المصفوفات.
