الوصف

تم تصميم هذه الإجراءات للوصول إلى مرفق المفسرات المتعددة من داخل برامج C. إنها تمكّن من إدارة مفسرات متعددة في علاقة هرمية، وإدارة الأسماء المستعارة، والأوامر التي عند استدعائها في مفسر واحد تنفذ أمرًا في مفسر آخر. القيمة المرجعة لهذه الإجراءات التي تعيد int هي إما TCL_OK أو TCL_ERROR. إذا تم إرجاع TCL_ERROR، فإن نتيجة المفسر تحتوي على رسالة خطأ.

Tcl_CreateSlave ينشئ مفسرًا جديدًا كابن لـ interp. كما أنه ينشئ أمرًا فرعيًا يسمى childName في interp يسمح لـ interp بمعالجة الابن الجديد. إذا كان isSafe صفراً، فإن الأمر ينشئ ابنًا موثوقًا به لديه وصول Tcl إلى جميع أوامر Tcl. إذا كان 1، فإن الأمر ينشئ ابنًا "آمنًا" لديه وصول Tcl فقط إلى مجموعة أوامر Tcl المعرفة باسم "Safe Tcl"؛ راجع صفحة الدليل لأمر interp في Tcl للتفاصيل. إذا فشل إنشاء المفسر الفرعي الجديد، يتم إرجاع NULL.

Tcl_CreateChild هو مرادف لـ Tcl_CreateSlave.

Tcl_IsSafe يعيد 1 إذا كان interp "آمنًا" (تم إنشاؤه مع العلم TCL_SAFE_INTERPRETER محددًا)، و 0 بخلاف ذلك.

Tcl_MakeSafe يميز interp على أنه "آمن"، بحيث تعيد الاستدعاءات المستقبلية لـ Tcl_IsSafe القيمة 1. كما أنه يزيل جميع وظائف النواة الأساسية المحتملة الخطورة المعروفة (الأوامر والمتغيرات) من interp. ومع ذلك، لا يمكنه معرفة الأجزاء الآمنة من امتداد أو تطبيق ولا يحاول إزالة تلك الأجزاء، لذا فإن الأمان غير مضمون بعد استدعاء Tcl_MakeSafe. يجب على المستدعين توخي الحذر في استخدامهم لـ Tcl_MakeSafe لتجنب الادعاءات الزائفة بالأمان. في العديد من الحالات، قد يكون Tcl_CreateSlave خيارًا أفضل، لأنه ينشئ مفسرات في حالة آمنة معروفة.

Tcl_GetSlave يعيد مؤشرًا إلى مفسر فرعي لـ interp. يتم تحديد المفسر الفرعي بواسطة childName. إذا لم يكن هناك مفسر فرعي كهذا، يتم إرجاع NULL.

Tcl_GetChild هو مرادف لـ Tcl_GetSlave.

Tcl_GetMaster يعيد مؤشرًا إلى المفسر الرئيسي لـ interp. إذا كان interp ليس له سيد (إنه مفسر مستوى أعلى) فيعاد NULL.

Tcl_GetParent هو مرادف لـ Tcl_GetMaster.

Tcl_GetInterpPath يخزن في نتيجة interp المسار النسبي بين interp و childInterp؛ يجب أن يكون childInterp ابنًا لـ interp. إذا نجح حساب المسار النسبي، يتم إرجاع TCL_OK، وإلا يتم إرجاع TCL_ERROR ويتم تخزين رسالة خطأ كنتيجة لـ interp.

Tcl_CreateAlias ينشئ أمرًا باسم childCmd في childInterp والذي عند استدعائه، سيؤدي إلى استدعاء الأمر targetCmd في targetInterp. يتم دائمًا إضافة المعاملات المحددة بالسلاسل الموجودة في argv قبل أي معاملات مقدمة في استدعاء childCmd وتمريرها إلى targetCmd. تعيد هذه العملية TCL_OK إذا نجحت، أو TCL_ERROR إذا فشلت؛ في هذه الحالة، يتم ترك رسالة خطأ في النتيجة القيمة لـ childInterp. لاحظ أنه لا توجد قيود على علاقة النسب (كما تم إنشاؤها بواسطة Tcl_CreateSlave) بين childInterp و targetInterp. يمكن استخدام أي مفسرين، دون أي قيود على كيفية ارتباطهما.

Tcl_CreateAliasObj مشابه لـ Tcl_CreateAlias باستثناء أنه يأخذ متجهًا من القيم لتمريرها كمعاملات إضافية بدلاً من متجه من السلاسل.

Tcl_GetAliasObj يعيد معلومات في شكل مؤشر إلى متجه من هياكل Tcl_Obj حول اسم مستعار aliasName في interp. يمكن أن يكون أي من حقول النتيجة NULL، وفي هذه الحالة لا يتم إرجاع البيانات المقابلة. إذا كان حقل النتيجة غير NULL، يتم تعيين العنوان المشار إليه إلى البيانات المقابلة. على سبيل المثال، إذا كان targetCmdPtr غير NULL، فإنه يتم تعيينه إلى مؤشر للسلسلة التي تحتوي على اسم الأمر الهدف.

Tcl_ExposeCommand

NAME

Tcl_ExposeCommand, Tcl_HideCommand - expose or hide Tcl commands

SYNOPSIS

#include <tcl.h>

int
Tcl_ExposeCommand(
    Tcl_Interp *interp,
    const char *hiddenCmdName,
    const char *cmdName);
int
Tcl_HideCommand(
    Tcl_Interp *interp,
    const char *cmdName,
    const char *hiddenCmdName);

ARGUMENTS

Tcl_Interp *interp
Interpreter to modify.
const char *hiddenCmdName
Name for the command in the hidden set.
const char *cmdName
Name for the command in the exposed set.

DESCRIPTION

Commands in Tcl can be placed in one of two sets: the set of exposed commands, or the set of hidden commands. Commands in the exposed set are visible and callable by scripts. Commands in the hidden set are not visible to scripts and cannot be called directly. Commands are placed in the hidden set by default when they are created.

Tcl_ExposeCommand moves the command named hiddenCmdName from the set of hidden commands to the set of exposed commands, putting it under the name cmdName. HiddenCmdName must be the name of an existing hidden command, or the operation will return TCL_ERROR and leave an error message as the result of interp. If an exposed command named cmdName already exists, the operation returns TCL_ERROR and leaves an error message as the result of interp. If the operation succeeds, it returns TCL_OK. After executing this command, attempts to use cmdName in any script evaluation mechanism will again succeed.

Tcl_HideCommand moves the command named cmdName from the set of exposed commands to the set of hidden commands, under the name hiddenCmdName. CmdName must be the name of an existing exposed command, or the operation will return TCL_ERROR and leave an error message as the result of interp. Currently both cmdName and hiddenCmdName must not contain namespace qualifiers, or the operation will return TCL_ERROR and leave an error message as the result of interp. The CmdName will be looked up in the global namespace, and not relative to the current namespace, even if the current namespace is not the global one. If a hidden command whose name is hiddenCmdName already exists, the operation also returns TCL_ERROR and an error message is left as the result of interp. If the operation succeeds, it returns TCL_OK. After executing this command, attempts to use cmdName in any script evaluation mechanism will fail.

For a description of the Tcl interface to multiple interpreters, see interp(n).
