الإجراء الذي سيتم استدعاؤه بواسطة Tcl_DoOneEvent بعد انتظار الأحداث. يتحقق مما إذا كانت أي أحداث قد وقعت، وإذا كان الأمر كذلك، يقوم بوضعها في قائمة الانتظار.

يشير إلى الحد الأقصى للوقت الذي سيتم انتظاره لوقوع حدث. يتم تحديد هذا كفترة زمنية (مدة الانتظار)، وليس كوقت مطلق (متى سيتم الاستيقاظ). إذا كان المؤشر الممرر إلى Tcl_WaitForEvent هو NULL، فهذا يعني أنه لا يوجد وقت أقصى للانتظار: انتظر إلى الأبد إذا لزم الأمر.

مقدمة

تُستخدم الواجهات الموضحة هنا لتخصيص حلقة أحداث Tcl. أكثر التخصيصات شيوعًا هما إضافة مصادر أحداث جديدة ودمج حلقة أحداث Tcl مع حلقة أحداث أخرى، مثل تلك التي يوفرها تطبيق يتم تضمين Tcl فيه. يتم وصف كل من هذه المهام في قسم منفصل أدناه.

الإجراءات الموجودة في إدخال الدليل هذا هي اللبنات الأساسية التي يتكون منها مُخبِر أحداث Tcl. مُخبِر الأحداث هو أدنى طبقة في آلية أحداث Tcl. تتكون من ثلاثة أشياء:

[1]
مصادر الأحداث: تمثل هذه الطرق التي يمكن بها إنشاء الأحداث. على سبيل المثال، يوجد مصدر أحداث مؤقت ينفذ الإجراء Tcl_CreateTimerHandler والأمر after، ويوجد مصدر أحداث ملف ينفذ الإجراء Tcl_CreateFileHandler على أنظمة Unix. يجب على مصدر الحدث العمل مع المُخبِر للكشف عن الأحداث في الأوقات المناسبة، وتسجيلها في قائمة انتظار الأحداث، وإخطار البرنامج الأعلى مستوى بحدوثها في النهاية. تُستخدم الإجراءات Tcl_CreateEventSource، Tcl_DeleteEventSource، و Tcl_SetMaxBlockTime، Tcl_QueueEvent، و Tcl_DeleteEvents بشكل أساسي بواسطة مصادر الأحداث.
[2]
قائمة انتظار الأحداث: للتطبيقات غير الخيطية، توجد قائمة انتظار واحدة للتطبيق بأكمله، تحتوي على الأحداث التي تم اكتشافها ولكن لم تتم معالجتها بعد. تضع مصادر الأحداث الأحداث في قائمة الانتظار حتى يمكن معالجتها بالترتيب في أوقات مناسبة أثناء حلقة الأحداث. تضمن قائمة انتظار الأحداث انضباطًا عادلاً لمعالجة الأحداث، بحيث لا يستطيع أي مصدر أحداث تجويع الآخرين. كما تسمح بحفظ الأحداث لمعالجتها في وقت لاحق. تعمل التطبيقات الخيطية بطريقة مماثلة، باستثناء وجود قائمة انتظار أحداث منفصلة لكل خيط يحتوي على مترجم Tcl. يتم استخدام Tcl_QueueEvent (بشكل أساسي بواسطة مصادر الأحداث) لإضافة الأحداث إلى قائمة انتظار الأحداث، ويتم استخدام Tcl_DeleteEvents لإزالة الأحداث من القائمة دون معالجتها. في تطبيق خيطي، تضيف Tcl_QueueEvent حدثًا إلى قائمة انتظار الخيط الحالي، وتضيف Tcl_ThreadQueueEvent حدثًا إلى قائمة انتظار في خيط معين.
[3]
حلقة الأحداث: للكشف عن الأحداث ومعالجتها، يدخل التطبيق في حلقة تنتظر وقوع الأحداث، ويضعها في قائمة انتظار الأحداث، ثم يعالجها. ستفعل معظم التطبيقات ذلك عن طريق استدعاء الإجراء Tcl_DoOneEvent، والذي تم وصفه في إدخال دليل منفصل.

لا تحتاج معظم تطبيقات Tcl إلى القلق بشأن أي من التفاصيل الداخلية لمُخبِر Tcl. ومع ذلك، يتمتع المُخبِر الآن بمرونة كافية لإعادة توجيهه إما لمنصة جديدة أو لاستخدام حلقة أحداث خارجية (مثل حلقة أحداث Motif، عندما يتم تضمين Tcl في تطبيق Motif). يتم تنفيذ الإجراءات Tcl_WaitForEvent و Tcl_SetTimer عادةً بواسطة Tcl، ولكن يمكن استبدالها بإصدارات جديدة لإعادة توجيه المُخبِر (يجب أيضًا استبدال Tcl_InitNotifier، و Tcl_AlertNotifier، و Tcl_FinalizeNotifier، و Tcl_Sleep، و Tcl_CreateFileHandler، و Tcl_DeleteFileHandler؛ انظر إنشاء مُخبِر جديد أدناه للحصول على التفاصيل). تم توفير الإجراءات Tcl_ServiceAll، Tcl_ServiceEvent، Tcl_GetServiceMode، و Tcl_SetServiceMode للمساعدة في ربط حلقة أحداث Tcl بحلقة أحداث خارجية مثل حلقة Motif.

أساسيات المُخبِر

أسهل طريقة لفهم كيفية عمل المُخبِر هي النظر في ما يحدث عند استدعاء Tcl_DoOneEvent. يتم تمرير وسيط flags إلى Tcl_DoOneEvent والذي يشير إلى نوع الأحداث التي يمكن معالجتها وأيضًا ما إذا كان سيتم حظر أو لا إذا لم تكن هناك أحداث جاهزة. يقوم Tcl_DoOneEvent بما يلي:

[1]
تحقق من قائمة انتظار الأحداث لمعرفة ما إذا كانت تحتوي على أي أحداث يمكن معالجتها. إذا كان الأمر كذلك، قم بمعالجة أول حدث ممكن، وأزله من القائمة، ثم أعد. يقوم بذلك عن طريق استدعاء Tcl_ServiceEvent وتمرير وسيط flags.
[2]
الاستعداد للحظر لوقوع حدث. للقيام بذلك، يقوم Tcl_DoOneEvent باستدعاء إجراء إعداد في كل مصدر حدث. سيقوم مصدر الحدث بإجراء تهيئة خاصة بمصدر الحدث وربما يستدعي Tcl_SetMaxBlockTime لتحديد المدة التي سيتم فيها حظر Tcl_WaitForEvent إذا لم تحدث أحداث جديدة.
[3]
استدعاء Tcl_WaitForEvent. يتم تنفيذ هذا الإجراء بشكل مختلف على منصات مختلفة؛ إنه ينتظر وقوع حدث، بناءً على المعلومات المقدمة من مصادر الأحداث. قد يتسبب في حظر التطبيق إذا كان timePtr يحدد فترة زمنية بخلاف 0. يعود Tcl_WaitForEvent عندما يحدث شيء ما، مثل أن يصبح الملف قابلاً للقراءة أو تنتهي الفترة الزمنية المحددة بواسطة timePtr. إذا لم تكن هناك أحداث ينتظرها Tcl_WaitForEvent، بحيث سيتم حظره إلى الأبد، فإنه يعود فورًا ويعود Tcl_DoOneEvent بالقيمة 0.
[4]
استدعاء إجراء تحقق في كل مصدر حدث. يحدد إجراء التحقق ما إذا كانت أي أحداث تهم هذا المصدر قد وقعت. إذا كان الأمر كذلك، يتم إضافة الأحداث إلى قائمة انتظار الأحداث.
[5]

INTRODUCTION

The Tcl event loop is responsible for processing events from various sources, such as file descriptors, timers, and idle handlers. The event loop can be in one of three modes: TCL_SERVICE_ALL (process all events), TCL_SERVICE_NONE (process no events), or TCL_SERVICE_MARK (process events until a mark is reached).

The Tcl event loop can be extended by creating new event sources. An event source consists of a callback procedure that is called when an event is ready to be processed. The event loop can also be driven by external code by calling Tcl_ServiceEvent or Tcl_ServiceIdle.

Tcl also provides support for multithreading. Threads can be created using Tcl_CreateThread and joined using Tcl_JoinThread. Thread-local data can be managed using Tcl_GetThreadData and Tcl_SetThreadData.

The Tcl channel mechanism provides a high-level interface for I/O operations. Channels can be created using Tcl_CreateChannel and manipulated using various channel-related procedures.

NOTIFIER BASICS

The notifier is responsible for managing the event queue and dispatching events to their respective handlers. The notifier can be accessed and manipulated through a set of Tcl C API functions.

Tcl_SetServiceMode sets the service mode of the notifier. Tcl_GetServiceMode returns the current service mode.

Tcl_CreateEventSource creates a new event source, which is a mechanism for Tcl to receive events from external sources. Tcl_DeleteEventSource deletes an event source.

Tcl_QueueEvent adds an event to the event queue. Events are processed in order of priority. Tcl_DeleteQueueBinding removes an event from the queue.

Tcl_SetTimer sets a timer that will trigger a callback procedure after a specified time. Tcl_Time returns the current time.

Tcl_ServiceMode returns the current service mode of the notifier.

Tcl_ServiceEvent processes a single event from the event queue.

Tcl_ServiceIdle processes all events that are currently ready to be processed, up to the current service mode's limit.

CREATING A NEW EVENT SOURCE

To create a new event source, you need to define an event procedure that will be called when an event is ready. This procedure should handle the event and potentially re-register itself for future events. You then use Tcl_CreateEventSource to register this procedure with the Tcl event loop.

The `clientData` argument allows you to pass arbitrary data to your event procedure, which is useful for maintaining state.

CREATING A NEW NOTIFIER

You can create a new notifier by implementing a `Tcl_NotifierProcs` structure and registering it with Tcl_SetNotifier. This allows you to customize how Tcl handles events.

REPLACING THE NOTIFIER

The default notifier can be replaced by calling Tcl_SetNotifier with your custom notifier procedures. This is typically done during Tcl initialization.

EXTERNAL EVENT LOOPS

You can integrate Tcl into an external event loop by using Tcl_ServiceEvent and Tcl_ServiceIdle. Your external loop would be responsible for managing file descriptors, timers, and other event sources, and calling the Tcl procedures when appropriate.
