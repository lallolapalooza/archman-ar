الوسائط

Tcl_Interp *interp (in)
المفسر المستخدم للإبلاغ عن الأخطاء، أو NULL إذا لم يكن الإبلاغ عن الأخطاء مطلوبًا.
const char *name (in)
اسم الترميز المراد تحميله.
Tcl_Encoding encoding (in)
الترميز المراد الاستعلام عنه أو تحريره أو استخدامه لتحويل النص. إذا كان encoding هو NULL، يتم استخدام ترميز النظام الحالي.
Tcl_Obj *objPtr (in)
اسم الترميز للحصول على رمز له.
Tcl_Encoding *encodingPtr (out)
يشير إلى مساحة التخزين حيث سيتم كتابة رمز الترميز.
const char *src (in)
بالنسبة لدوال Tcl_ExternalToUtf، مصفوفة من البايتات في الترميز المحدد المراد تحويلها إلى UTF-8. بالنسبة لدوال Tcl_UtfToExternal وTcl_WinUtfToTChar، مصفوفة من أحرف UTF-8 المراد تحويلها إلى الترميز المحدد.
const TCHAR *tsrc (in)
مصفوفة من أحرف TCHAR الخاصة بـ Windows المراد تحويلها إلى UTF-8.
int srcLen (in)
طول src أو tsrc بالبايت. إذا كان الطول سالبًا، يتم استخدام الطول الخاص بالترميز للسلسلة.
Tcl_DString *dstPtr (out)
مؤشر إلى Tcl_DString غير مهيأ أو حر حيث سيتم تخزين النتيجة المحولة.
int flags (in)
بتات علم متنوعة مجمعة معًا باستخدام OR. TCL_ENCODING_START تعني أن المخزن المصدر هو الكتلة الأولى في تدفق إدخال (قد يكون متعدد الكتل)، مما يخبر روتين التحويل بإعادة التعيين إلى حالة أولية وإجراء أي تهيئة يجب أن تحدث قبل تحويل البايت الأول. TCL_ENCODING_END تعني أن المخزن المصدر هو الكتلة الأخيرة في تدفق إدخال (قد يكون متعدد الكتل)، مما يخبر روتين التحويل بإجراء أي إنهاء يجب أن يحدث بعد تحويل البايت الأخير ثم إعادة التعيين إلى حالة أولية. TCL_ENCODING_STOPONERROR تعني أن روتين التحويل يجب أن يعود فورًا عند قراءة حرف مصدر غير موجود في الترميز الهدف؛ وإلا فسيتم استبدال حرف احتياطي افتراضي تلقائيًا.
Tcl_EncodingState *statePtr (in/out)
يُستخدم عند تحويل تدفق بايتات (طويل أو غير محدد الطول عمومًا) بطريقة قطعة بقطعة. يخزن روتين التحويل حالته الحالية في *statePtr بعد تحويل src (المخزن الذي يحتوي على القطعة الحالية)؛ يجب تمرير معلومات الحالة تلك مرة أخرى عند تحويل القطعة التالية من التدفق حتى يعرف روتين التحويل الحالة التي كان عليها عندما توقف عند نهاية القطعة الأخيرة. قد يكون NULL، وفي هذه الحالة يتم تجاهل القيمة المحددة لـ flags ويُفترض أن المخزن المصدر يحتوي على السلسلة الكاملة المراد تحويلها.
char *dst (out)
المخزن الذي سيتم تخزين النتيجة المحولة فيه. لن يتم تخزين أكثر من dstLen بايت في dst.
int dstLen (in)
الحد الأقصى لطول مخزن الإخراج dst بالبايت.
int *srcReadPtr (out)
يُملأ بعدد البايتات من src التي تم تحويلها فعليًا. قد يكون هذا أقل من طول المصدر الأصلي إذا كانت هناك مشكلة في تحويل بعض أحرف المصدر. قد يكون NULL.
int *dstWrotePtr (out)
يُملأ بعدد البايتات التي تم تخزينها فعليًا في مخزن الإخراج نتيجة للتحويل. قد يكون NULL.
int *dstCharsPtr (out)
يُملأ بعدد الأحرف التي تتوافق مع عدد البايتات المخزنة في مخزن الإخراج. قد يكون NULL.
Tcl_DString *bufPtr (out)
مساحة تخزين لاسم ترميز النظام المحدد.
const Tcl_EncodingType *typePtr (in)
بنية تحدد نوعًا جديدًا من الترميز.
Tcl_Obj *searchPath (in)
قائمة بأدلة نظام الملفات للبحث فيها عن ملفات بيانات الترميز.
const char *path (in)
مسار إلى موقع ملف الترميز.

مقدمة

تحوّل هذه الروتينات بين تمثيل الأحرف الداخلي لـ Tcl، وهو UTF-8، وتمثيلات الأحرف المستخدمة من قبل أنظمة التشغيل أو أنظمة الملفات المختلفة، مثل Unicode أو ASCII أو Shift-JIS. عند التعامل مع السلاسل، مثل الحصول على أسماء الملفات أو عرض الأحرف باستخدام خطوط دولية، يجب ترجمة السلاسل إلى تنسيق واحد أو ربما عدة تنسيقات يمكن لنداءات النظام المختلفة استخدامها. على سبيل المثال، على محطة عمل Unix يابانية، قد يحصل المستخدم على اسم ملف ممثل بترميز ملف EUC-JP ثم يترجم الأحرف إلى ترميز خط jisx0208 لعرض اسم الملف في أداة Tk. الغرض من حزمة الترميز هو المساعدة في سد فجوة الترجمة. يوفر UTF-8 أرضية وسيطة لجميع الترميزات المختلفة. في المثال أعلاه، سيتم ترجمة النص إلى UTF-8 من أي ترميز ملف يستخدمه نظام التشغيل. ثم سيتم ترجمته من UTF-8 إلى أي ترميز خط تتطلبه روتينات العرض.

بعض الترميزات الأساسية مضمنة في Tcl. يمكن تعريف أخرى من قبل المستخدم أو تحميلها ديناميكيًا من ملفات الترميز بطريقة مستقلة عن المنصة.

الوصف

يعثر Tcl_GetEncoding على ترميز بالنظر إلى name الخاص به. قد يشير الاسم إلى ترميز Tcl مدمج، أو ترميز معرّف من قبل المستخدم مسجل عن طريق استدعاء Tcl_CreateEncoding، أو ملف ترميز قابل للتحميل ديناميكيًا. القيمة المعادة هي رمز يمثل الترميز ويمكن استخدامه في الاستدعاءات اللاحقة لإجراءات مثل Tcl_GetEncodingName وTcl_FreeEncoding وTcl_UtfToExternal. إذا لم يشير الاسم إلى أي ترميز معروف أو قابل للتحميل، يتم إرجاع NULL ويتم إرجاع رسالة خطأ في interp.

تحتفظ حزمة الترميز بقاعدة بيانات لجميع الترميزات المستخدمة حاليًا. في المرة الأولى التي يُرى فيها name، يعيد Tcl_GetEncoding ترميزًا بعدد مراجع 1. إذا تم طلب نفس name مرات أخرى، فسيتم زيادة عدد المراجع لذلك الترميز دون عبء تخصيص ترميز جديد وجميع هياكل البيانات المرتبطة به.

عندما لا يكون encoding مطلوبًا بعد الآن، يجب استدعاء Tcl_FreeEncoding لتحريره. عندما لا يكون encoding قيد الاستخدام في أي مكان بعد الآن (أي أنه تم تحريره بقدر ما تم الحصول عليه) فسيقوم Tcl_FreeEncoding بتحرير جميع مساحات التخزين التي كان الترميز يستخدمها وحذفه من قاعدة البيانات.

يعامل Tcl_GetEncodingFromObj تمثيل السلسلة لـ objPtr كاسم ترميز، ويعثر على ترميز بذلك الاسم، تمامًا كما يفعل Tcl_GetEncoding. عند العثور على ترميز، يتم تخزينه مؤقتًا داخل قيمة objPtr للرجوع إليه في المستقبل، ويتم كتابة رمز Tcl_Encoding إلى مساحة التخزين

حافظ على بنية الملف بالكامل. يتم إرجاع القيمة TCL_OK عند الإشارة إلى encodingPtr المحدد. إذا لم يكن هناك أي نوع ترميز موجود، يتم إرجاع TCL_ERROR ولا يتم إجراء أي كتابة في *encodingPtr. هذا مشابه لحالة Tcl_GetEncoding، ويجب على المستخدم استدعاء Tcl_FreeEncoding على رمز الترميز الناتج عندما لا يعود يستخدمه.

Tcl_ExternalToUtfDString يحوّل مخزنًا مصدريًا src من الترميز المحدد إلى UTF-8. يتم تخزين البايتات المحوّلة في dstPtr، والذي يتم إنهاؤه بعد ذلك بقيمة null المناسبة للترميز. يجب على المستخدم استدعاء Tcl_DStringFree في النهاية لتحرير أي معلومات مخزنة في dstPtr. عند التحويل، إذا تعذّر تمثيل أي حرف في المخزن المصدر في الترميز الهدف، يتم استخدام حرف بديل افتراضي. القيمة المُرجعة هي مؤشر إلى القيمة المخزنة في DString.

Tcl_ExternalToUtf يحوّل مخزنًا مصدريًا src من الترميز المحدد إلى UTF-8. يتم تحويل حتى srcLen بايت من المخزن المصدر وتخزين حتى dstLen بايت في dst. في جميع الأحوال، يتم ملء *srcReadPtr بعدد البايتات المحوّلة من src و*dstWrotePtr بعدد البايتات المخزنة في dst. القيمة المُرجعة هي واحدة مما يلي:

TCL_OK
تم تحويل كل محتوى src.
TCL_CONVERT_NOSPACE
لم يكن المخزن الهدف كافيًا لتخزين جميع البيانات المحوّلة؛ تم تحويل الأحرف التي أمكن احتواؤها وإن لم يكن الجميع.
TCL_CONVERT_MULTIBYTE
كانت البايتات الأخيرة من المخزن المصدر بداية تسلسل متعدد البايتات، لكن كانت هناك حاجة إلى مزيد من البايتات لإكماله. يجب أن يمرر استدعاء لاحق للمحوّل مخزنًا يحتوي على البايتات غير المحوّلة المتبقية في src بالإضافة إلى بعض البايتات من المصدر لإكمال التسلسل المنقسم سابقًا.
TCL_CONVERT_SYNTAX
احتوى المخزن المصدر على تسلسل أحرف غير صالح. يمكن أن يحدث هذا إذا كان تدفق الإدخال قد تلف أو إذا تم تحديد طريقة الترميز بشكل خاطئ.
TCL_CONVERT_UNKNOWN
احتوى المخزن المصدر على حرف تعذّر تمثيله في الترميز الهدف وتم تحديد TCL_ENCODING_STOPONERROR.

Tcl_UtfToExternalDString يحوّل مخزنًا مصدريًا src من UTF-8 إلى الترميز المحدد. يتم تخزين البايتات المحوّلة في dstPtr، والذي يتم إنهاؤه بعد ذلك بقيمة null المناسبة للترميز. يجب على المستخدم استدعاء Tcl_DStringFree في النهاية لتحرير أي معلومات مخزنة في dstPtr. عند التحويل، إذا تعذّر تمثيل أي حرف في المخزن المصدر في الترميز الهدف، يتم استخدام حرف بديل افتراضي. القيمة المُرجعة هي مؤشر إلى القيمة المخزنة في DString.

Tcl_UtfToExternal يحوّل مخزنًا مصدريًا src من UTF-8 إلى الترميز المحدد. يتم تحويل حتى srcLen بايت من المخزن المصدر وتخزين حتى dstLen بايت في dst. في جميع الأحوال، يتم ملء *srcReadPtr بعدد البايتات المحوّلة من src و*dstWrotePtr بعدد البايتات المخزنة في dst. القيم المُرجعة هي نفسها الخاصة بـ Tcl_ExternalToUtf.

Tcl_WinUtfToTChar وTcl_WinTCharToUtf هما دالتا دعم للتحويل بين UTF-8 وسلاسل Windows القائمة على نوع TCHAR، والذي هو عمومًا حرف Unicode في Windows NT.

Tcl_GetEncodingName هو تقريبًا عكس Tcl_GetEncoding. بالنظر إلى encoding، القيمة المُرجعة هي الوسيط name المستخدم لإنشاء الترميز. السلسلة التي تُرجعها Tcl_GetEncodingName مضمونة فقط بالاستمرار حتى يتم حذف encoding. يجب على المستخدم عدم تعديل هذه السلسلة.

Tcl_SetSystemEncoding يضبط الترميز الافتراضي الذي سيُستخدم عندما يمرر المستخدم قيمة null للوسيط encoding إلى أي دالة ترميز. إذا كان name فارغًا، يُعاد ضبط ترميز النظام إلى الترميز الافتراضي للنظام، binary. إذا لم يشِر الاسم إلى أي ترميز معروف أو قابل للتحميل، يتم إرجاع TCL_ERROR وتُترك رسالة خطأ في interp. بخلاف ذلك، يزيد هذا الإجراء عداد مراجع ترميز النظام الجديد، ويُنقص عداد مراجع النظام القديم، ويُرجع TCL_OK.

Tcl_GetEncodingNameFromEnvironment يوفر وسيلة لمكتبة Tcl للإبلاغ عن اسم الترميز الذي تعتقد أنه الصحيح لاستخدامه كترميز للنظام، بناءً على استدعاءات النظام وفحص البيئة المناسب للمنصة. يستقبل bufPtr، وهو مؤشر إلى Tcl_DString غير مهيأ أو محرر، ويكتب اسم الترميز فيه. القيمة المُرجعة هي Tcl_DStringValue.

Tcl_GetEncodingNames يضبط نتيجة interp إلى قائمة تحتوي على أسماء جميع الترميزات المعرّفة أو القابلة للتحميل ديناميكيًا، بالبحث في مسار الترميزات المحدد بواسطة Tcl_SetDefaultEncodingDir. لا يضمن هذا الإجراء أن الملفات القابلة للتحميل ديناميكيًا تحتوي على بيانات صالحة، بل يضمن فقط أنها موجودة.

Tcl_CreateEncoding يعرّف ترميزًا جديدًا ويسجّل الإجراءات C التي تُستدعى للتحويل بين الترميز وUTF-8. الترميزات المنشأة بـ Tcl_CreateEncoding مرئية في قاعدة البيانات المستخدمة بواسطة Tcl_GetEncoding. كما هو الحال مع Tcl_GetEncoding، القيمة المُرجعة هي رمز يمثل الترميز ويمكن استخدامه في استدعاءات لاحقة لدوال ترميز أخرى. يُرجع Tcl_CreateEncoding ترميزًا بعداد مراجع يساوي 1. إذا كان هناك بالفعل إدخال في قاعدة البيانات بالاسم المحدد، يتم استبدال إدخاله بالترميز الجديد؛ سيظل رمز النظام القديم صالحًا وسيستمر في التصرف كما كان من قبل، لكن مستخدمي الرمز الجديد سيستدعون الآن إجراءات الترميز الجديد.

يحتوي الوسيط typePtr الخاص بـ Tcl_CreateEncoding على معلومات حول اسم الترميز والإجراءات التي تُستدعى للتحويل بين هذا الترميز وUTF-8. وهو معرّف كما يلي:

typedef struct Tcl_EncodingType {
    const char *encodingName;
    Tcl_EncodingConvertProc *toUtfProc;
    Tcl_EncodingConvertProc *fromUtfProc;
    Tcl_EncodingFreeProc *freeProc;
    ClientData clientData;
    int nullSize;
} Tcl_EncodingType;

يوفر encodingName اسمًا للترميز، يمكن من خلاله الإشارة إليه في إجراءات أخرى مثل Tcl_GetEncoding. يشير toUtfProc إلى إجراء استدعاء عكسي لتحويل النص من هذا الترميز إلى UTF-8. يشير fromUtfProc إلى إجراء استدعاء عكسي لتحويل النص من UTF-8 إلى هذا الترميز. يشير freeProc إلى إجراء استدعاء عكسي لاستدعائه عند حذف الترميز. يمكن أن يكون حقل freeProc فارغًا. يحتوي clientData على قيمة عشوائية من كلمة واحدة تستخدمها toUtfProc وfromUtfProc وfreeProc عند استدعائها. عمومًا، هو مؤشر إلى بنية تحتوي على معلومات خاصة بالترميز يمكن استخدامها بواسطة إجراءات الاستدعاء العكسي. على سبيل المثال، يمكن لترميزين متشابهين جدًا مثل ascii وmacRoman استخدام نفس إجراء الاستدعاء العكسي، لكنهما يستخدمان قيمًا مختلفة من clientData للتحكم في سلوكهما. يحدد nullSize عدد الأصفار التي تعني نهاية السلسلة في هذا الترميز. يجب أن يكون 1 (لترميزات البايت الواحد أو متعددة البايتات مثل ASCII أو Shift-JIS) أو 2 (لترميزات البايتين مثل Unicode). الترميزات التي تحتوي على 3 بايتات أو أكثر لكل حرف (مثل CNS11643) غير مقبولة.

يجب أن تتطابق إجراءات الاستدعاء العكسي toUtfProc وfromUtfProc مع النوع Tcl_EncodingConvertProc:

typedef int Tcl_EncodingConvertProc(
        ClientData clientData,
        const char *src,
        int srcLen,
        int flags,
        Tcl_EncodingState *statePtr,
        char *dst,
        int dstLen,
        int *srcReadPtr,
        int *dstWrotePtr,
        int *dstCharsPtr);

تُستدعى إجراءات الاستدعاء العكسي toUtfProc وfromUtfProc بواسطة Tcl_ExternalToUtf أو Tcl_UtfToExternal لإجراء التحويل الفعلي. المعامل clientData لهذه الإجراءات هو نفسه clientData المحدد في Tcl_CreateEncoding عند إنشاء الترميز. الوسائط المتبقية لإجراءات الاستدعاء العكسي هي نفس الوسائط، الموثقة أعلاه، الخاصة بـ Tcl_ExternalToUtf أو Tcl_UtfToExternal، مع الاستثناءات التالية. إذا كان الوسيط srcLen لإحدى هذه الدوال عالية المستوى سالبًا، فستكون القيمة الممررة إلى إجراء الاستدعاء العكسي هي الطول المناسب لترميز src. إذا كان أي من الوسائط srcReadPtr أو dstWrotePtr أو dstCharsPtr لإحدى هذه الدوال عالية المستوى فارغًا، فستكون القيمة الممررة إلى إجراء الاستدعاء العكسي موقعًا غير فارغ.

إجراء الاستدعاء العكسي freeProc، إذا لم يكن فارغًا، يجب أن يتطابق مع النوع Tcl_EncodingFreeProc:

typedef void Tcl_EncodingFreeProc(

NAME

utf, encoding, convert

SYNOPSIS

Tcl_GetDefaultEncodingDir, Tcl_GetEncodingSearchPath

ARGUMENTS

name, searchPath

INTRODUCTION

The Tcl_GetDefaultEncodingDir and Tcl_GetEncodingSearchPath are obsolete interfaces best replaced with calls to Tcl_GetDefaultEncodingDir and Tcl_GetEncodingSearchPath. They are called to access and set the first element of the searchPath list. Since Tcl searches searchPath for encoding data files in list order, these routines establish the "default" directory in which to find encoding data files.

DESCRIPTION

Space would prohibit precompiling into Tcl every possible encoding algorithm, so many encodings are stored on disk as dynamically-loadable encoding files. This behavior also allows the user to create additional encoding files that can be loaded using the same mechanism. These encoding files contain information about the tables and/or escape sequences used to map between an external encoding and Unicode. The external encoding may consist of single-byte, multi-byte, or double-byte characters.

Each dynamically-loadable encoding is represented as a text file. The initial line of the file, beginning with a # symbol, is a comment that provides a human-readable description of the file. The next line identifies the type of encoding file. It can be one of the following letters:

[1] S
A single-byte encoding, where one character is always one byte long in the encoding. An example is iso8859-1, used by many European languages.
[2] D
A double-byte encoding, where one character is always two bytes long in the encoding. An example is big5, used for Chinese text.
[3] M
A multi-byte encoding, where one character may be either one or two bytes long. Certain bytes are lead bytes, indicating that another byte must follow and that together the two bytes represent one character. Other bytes are not lead bytes and represent themselves. An example is shiftjis, used by many Japanese computers.
[4] E
An escape-sequence encoding, specifying that certain sequences of bytes do not represent characters, but commands that describe how following bytes should be interpreted.

The rest of the lines in the file depend on the type.

The third line of the file is three numbers. The first number is the fallback character (in base 16) to use when converting from UTF-8 to this encoding. The second number is a 1 if this file represents the encoding for a symbol font, or 0 otherwise. The last number (in base 10) is how many pages of data follow.

Subsequent lines in the example above are pages that describe how to map from the encoding into 2-byte Unicode. The first line in a page identifies the page number. Following it are 256 double-byte numbers, arranged as 16 rows of 16 numbers. Given a character in the encoding, the high byte of that character is used to select which page, and the low byte of that character is used as an index to select one of the double-byte numbers in that page - the value obtained being the corresponding Unicode character. By examination of the example above, one can see that the characters 0x7E and 0x8163 in shiftjis map to 203E and 2026 in Unicode, respectively.

Following the first page will be all the other pages, each in the same format as the first: one number identifying the page followed by 256 double-byte Unicode characters. If a character in the encoding maps to the Unicode character 0000, it means that the character does not actually exist. If all characters on a page would map to 0000, that page can be omitted.
