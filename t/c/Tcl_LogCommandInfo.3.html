الوصف

تُعرض الروتينات Tcl_SetReturnOptions و Tcl_GetReturnOptions نفس القدرات التي توفرها الأوامر return و catch، على التوالي، في شكل واجهة C.

تقوم Tcl_GetReturnOptions باسترداد قاموس خيارات الإرجاع من مفسر بعد تقييم نص برمجي. يتم استدعاء روتينات مثل Tcl_Eval لتقييم نص برمجي في مفسر. تُرجع هذه الروتينات رمز إكمال عددي. تترك هذه الروتينات أيضًا في المفسر كلاً من النتيجة وقاموس خيارات الإرجاع التي تم إنشاؤها بواسطة تقييم النص البرمجي. تمامًا كما تسترد Tcl_GetObjResult النتيجة، تسترد Tcl_GetReturnOptions قاموس خيارات الإرجاع. يجب تمرير رمز الإكمال العددي كوسيط code إلى Tcl_GetReturnOptions بحيث تكون جميع الخيارات المطلوبة موجودة في القاموس. على وجه التحديد، سيضمن قيمة code بقيمة TCL_ERROR ظهور الإدخالات للمفاتيح -errorinfo و -errorcode و -errorline في القاموس. أيضًا، سيتم تعديل الإدخالات للمفاتيح -code و -level إذا لزم الأمر لتتوافق مع قيمة code. يشير (Tcl_Obj *) الذي يتم إرجاعه بواسطة Tcl_GetReturnOptions إلى Tcl_Obj غير مشترك مع عدد مراجع صفر. يمكن تعديل القاموس، سواء بإضافة أو إزالة أو الكتابة فوق أي إدخالات فيه، دون الحاجة إلى التحقق من وجود قيمة مشتركة. كما هو الحال مع أي Tcl_Obj بعدد مراجع صفر، يقع على عاتق المتصل ترتيب التخلص منه باستخدام Tcl_DecrRefCount أو الإشارة إليه عبر Tcl_IncrRefCount (أو إحدى الوظائف العديدة التي تستدعي ذلك، وأبرزها Tcl_SetObjResult و Tcl_SetVar2Ex).

الاستخدام النموذجي لـ Tcl_GetReturnOptions هو استرداد تتبع المكدس عند إرجاع تقييم النص البرمجي TCL_ERROR، كالتالي:

int code = Tcl_Eval(interp, script);
if (code == TCL_ERROR) {
    Tcl_Obj *options = Tcl_GetReturnOptions(interp, code);
    Tcl_Obj *key = Tcl_NewStringObj("-errorinfo", -1);
    Tcl_Obj *stackTrace;
    Tcl_IncrRefCount(key);
    Tcl_DictObjGet(NULL, options, key, &stackTrace);
    Tcl_DecrRefCount(key);
    /* افعل شيئًا مع stackTrace */
    Tcl_DecrRefCount(options);
}

تقوم Tcl_SetReturnOptions بتعيين خيارات الإرجاع لـ interp لتكون options. إذا كان options يحتوي على أي قيمة غير صالحة لأي مفتاح، فسيتم إرجاع TCL_ERROR، وسيتم تعيين نتيجة المفسر إلى رسالة خطأ مناسبة. خلاف ذلك، سيتم إرجاع رمز إكمال يتوافق مع مفتاحي -code و -level في options.

على سبيل المثال، يمكن تنفيذ أمر Tcl return نفسه باستخدام Tcl_SetReturnOptions كالتالي:

if ((objc % 2) == 0) { /* وسيط نتيجة صريح */
    objc--;
    Tcl_SetObjResult(interp, objv[objc]);
}
return Tcl_SetReturnOptions(interp, Tcl_NewListObj(objc-1, objv+1));

(لم يتم تنفيذه بهذه الطريقة حقًا. تتيح امتيازات الوصول الداخلية بديلاً أكثر كفاءة يتناسب بشكل أفضل مع مترجم البايت كود.)

لاحظ أنه يمكن تمرير Tcl_Obj تم إنشاؤه حديثًا كوسيط options دون الحاجة إلى التعامل مع أي عد مراجع. هذا مشابه لـ Tcl_SetObjResult.

بينما توفر Tcl_SetReturnOptions واجهة عامة لتعيين أي مجموعة من خيارات الإرجاع، هناك عدد قليل من خيارات الإرجاع المستخدمة بشكل متكرر. وأبرزها، يجب تعيين خياري -errorinfo و -errorcode بشكل صحيح عندما تُرجع إجراءات الأمر TCL_ERROR. يتم أيضًا قراءة خيار -errorline بواسطة الأوامر التي تقيّم نصوصًا برمجية وترغب في توفير معلومات مفصلة عن موقع الخطأ في نص تتبع المكدس الذي تلحقه بخيار -errorinfo. توفر Tcl العديد من الواجهات الأبسط لتعيين هذه الخيارات بشكل مباشر.

يحتوي خيار -errorinfo على تتبع مكدس للعمليات التي كانت قيد التنفيذ عند حدوث خطأ، وهو مخصص ليكون قابلاً للقراءة البشرية. يحتوي خيار -errorcode على قائمة Tcl بعناصر مخصصة لتكون قابلة للقراءة آليًا. يحدد العنصر الأول في قيمة -errorcode فئة الخطأ الذي حدث (على سبيل المثال، POSIX يعني حدوث خطأ في استدعاء نظام POSIX) وتحتوي العناصر الإضافية على قطع إضافية من المعلومات تعتمد على الفئة. راجع دليل المتغير errorCode للحصول على تفاصيل حول التنسيقات المختلفة لخيار -errorcode التي تستخدمها أوامر Tcl المضمنة.

يتم تجميع قيمة خيار -errorinfo تدريجياً أثناء تفكك الخطأ عبر العمليات المتداخلة. في كل مرة يتم فيها إرجاع رمز خطأ إلى Tcl_Eval، أو أي من الروتينات التي تقوم بتقييم النص البرمجي، يتم استدعاء الإجراء Tcl_AddErrorInfo لإضافة نص إضافي إلى قيمة -errorinfo يصف الأمر الذي كان قيد التنفيذ عند حدوث الخطأ. بحلول الوقت الذي تم فيه تمرير الخطأ بالكامل إلى التطبيق، سيحتوي على تتبع كامل للنشاط الذي كان قيد التنفيذ عند حدوث الخطأ.

يكون مفيدًا أحيانًا إضافة معلومات إضافية إلى قيمة -errorinfo بما يتجاوز ما يمكن توفيره تلقائيًا بواسطة روتينات تقييم النص البرمجي. يمكن استخدام Tcl_AddErrorInfo لهذا الغرض: وسيطها message هو سلسلة إضافية ليتم إلحاقها بخيار -errorinfo. على سبيل المثال، عندما ينشأ خطأ أثناء الأمر source، يتم استدعاء الإجراء Tcl_AddErrorInfo لتسجيل اسم الملف الذي تتم معالجته ورقم السطر الذي حدث فيه الخطأ. وبالمثل، عندما ينشأ خطأ أثناء تقييم
