CLASSLESS QDISCS

The following qdiscs are not structured by the scheduler and can therefore only be attached directly to a device's root qdisc.

bfifo
A FIFO queue limited to 64 packets (a parameter, see below). The configuration is similar to RED.
codel
CoDel (pronounced "coddle") is an adaptive "no-knobs" active queue management algorithm (AQM) scheme that was developed to address the shortcomings of RED and its variants.
[p|b]fifo
Simplest usable qdisc, pure First In, First Out behaviour. Limited in packets or in bytes.
fq
Fair Queue Scheduler realises TCP pacing and scales to millions of concurrent flows per qdisc.
fq_codel
Fair Queuing Controlled Delay is queuing discipline that combines Fair Queuing with the CoDel AQM scheme. FQ_Codel uses a stochastic model to classify incoming packets into different flows and is used to provide a fair share of the bandwidth to all the flows using the queue. Each such flow is managed by the CoDel queuing discipline. Reordering within a flow is avoided since Codel internally uses a FIFO queue.
fq_pie
FQ-PIE (Flow Queuing with Proportional Integral controller Enhanced) is a queuing discipline that combines Flow Queuing with the PIE AQM scheme. FQ-PIE uses a Jenkins hash function to classify incoming packets into different flows and is used to provide a fair share of the bandwidth to all the flows using the qdisc. Each such flow is managed by the PIE algorithm.
gred
Generalized Random Early Detection combines multiple RED queues in order to achieve multiple drop priorities. This is required to realize Assured Forwarding (RFC 2597).
hhf
Heavy-Hitter Filter differentiates between small flows and the opposite, heavy-hitters. The goal is to catch the heavy-hitters and move them to a separate queue with less priority so that bulk traffic does not affect the latency of critical traffic.
ingress
This is a special qdisc as it applies to incoming traffic on an interface, allowing for it to be filtered and policed.
mqprio
The Multiqueue Priority Qdisc is a simple queuing discipline that allows mapping traffic flows to hardware queue ranges using priorities and a configurable priority to traffic class mapping. A traffic class in this context is a set of contiguous qdisc classes which map 1:1 to a set of hardware exposed queues.
multiq
Multiqueue is a qdisc optimized for devices with multiple Tx queues. It has been added for hardware that wishes to avoid head-of-line blocking. It will cycle though the bands and verify that the hardware queue associated with the band is not stopped prior to dequeuing a packet.
netem
Network Emulator is an enhancement of the Linux traffic control facilities that allow one to add delay, packet loss, duplication and more other characteristics to packets outgoing from a selected network interface.
pfifo_fast
Standard qdisc for 'Advanced Router' enabled kernels. Consists of a three-band queue which honors Type of Service flags, as well as the priority that may be assigned to a packet.
pie
Proportional Integral controller-Enhanced (PIE) is a control theoretic active queue management scheme. It is based on the proportional integral controller but aims to control delay.
red
Random Early Detection simulates physical congestion by randomly dropping packets when nearing configured bandwidth allocation. Well suited to very large bandwidth applications.
sfb
Stochastic Fair Blue is a classless qdisc to manage congestion based on packet loss and link utilization history while trying to prevent non-responsive flows (i.e. flows that do not react to congestion marking or dropped packets) from impacting performance of responsive flows. Unlike RED, where the marking probability has to be configured, BLUE tries to determine the ideal marking probability automatically.
sfq
Stochastic Fairness Queueing reorders queued traffic so each 'session' gets to send a packet in turn.
tbf
The Token Bucket Filter is suited for slowing traffic down to a precisely configured rate. Scales well to large bandwidths.

تكوين قوائم الانتظار عديمة الفئات

في غياب قوائم الانتظار المصنفة، لا يمكن ربط قوائم الانتظار عديمة الفئات إلا بالجذر الخاص بالجهاز. الصيغة الكاملة:

tc qdisc add dev DEV root QDISC QDISC-PARAMETERS

لإزالة، قم بتنفيذ

tc qdisc del dev DEV root

قائمة الانتظار pfifo_fast هي الافتراضية التلقائية في غياب قائمة انتظار مهيأة.

قوائم الانتظار المصنفة

قوائم الانتظار المصنفة هي:

ATM
ربط التدفقات بالدوائر الافتراضية لجهاز نقل الوضع غير المتزامن الأساسي.
DRR
مجدول Deficit Round Robin هو بديل أكثر مرونة لمقاربة الإنصاف العشوائي. على عكس SFQ، لا توجد قوائم انتظار مدمجة - تحتاج إلى إضافة فئات وإعداد عوامل تصفية لتصنيف الحزم وفقًا لذلك. يمكن أن يكون هذا مفيدًا على سبيل المثال لاستخدام قوائم انتظار RED بإعدادات مختلفة لحركة مرور معينة. لا توجد فئة افتراضية - إذا لم يتم تصنيف حزمة، فسيتم إسقاطها.
ETS
قائمة انتظار ETS هي تخصص طابور يدمج وظائف قوائم انتظار PRIO و DRR في مجدول واحد. تجعل ETS من السهل تكوين مجموعة من النطاقات الصارمة ومشاركة النطاق الترددي لتنفيذ اختيار الإرسال الموضح في 802.1Qaz.
HFSC
تضمن منحنيات الخدمة العادلة الهرمية تخصيصًا دقيقًا للنطاق الترددي ووقت الاستجابة للفئات الطرفية وتخصص النطاق الترددي الزائد بشكل عادل. على عكس HTB، فإنه يستخدم إسقاط الحزم لتحقيق أوقات استجابة تستفيد منها الجلسات التفاعلية.
HTB
تطبق Hierarchy Token Bucket تسلسلًا هرميًا غنيًا لمشاركة الارتباط للفئات مع التركيز على الامتثال للممارسات الحالية. تسهل HTB ضمان النطاق الترددي للفئات، مع السماح أيضًا بتحديد الحدود العليا لمشاركة ما بين الفئات. تحتوي على عناصر تشكيل، تستند إلى TBF ويمكنها تحديد أولويات الفئات.
PRIO
قائمة انتظار PRIO هي حاوية غير مشكلة لعدد قابل للتكوين من الفئات التي يتم إخراجها بالترتيب. هذا يسمح بتحديد أولويات سهلة لحركة المرور، حيث لا يمكن للفئات الأدنى الإرسال إلا إذا لم تكن للفئات الأعلى أي حزم متاحة. لتسهيل التكوين، يتم احترام بتات نوع الخدمة افتراضيًا.
QFQ
Quick Fair Queueing هو مجدول O(1) يوفر ضمانات شبه مثالية، وهو الأول الذي يحقق هذا الهدف بتكلفة ثابتة أيضًا فيما يتعلق بعدد المجموعات وطول الحزمة. خوارزمية QFQ لا تحتوي على حلقات، وتستخدم تعليمات وهياكل بيانات بسيطة جدًا تجعلها مناسبة جدًا للتنفيذ في الأجهزة.

نظرية التشغيل

تشكل الفئات شجرة، حيث يكون لكل فئة والد واحد. قد يكون للفئة أطفال متعددون. تسمح بعض قوائم الانتظار بإضافة فئات في وقت التشغيل (HTB) بينما يتم إنشاء أخرى (PRIO) بعدد ثابت من الأطفال.

قوائم الانتظار التي تسمح بالإضافة الديناميكية للفئات يمكن أن تحتوي على صفر أو أكثر من الفئات الفرعية التي يمكن إدخال حركة المرور إليها.

علاوة على ذلك، تحتوي كل فئة على قائمة انتظار طرفية يكون سلوكها افتراضيًا هو pfifo، على الرغم من أنه يمكن ربط قائمة انتظار أخرى بدلاً منها. قد تحتوي هذه القائمة مرة أخرى على فئات، ولكن يمكن لكل فئة أن تحتوي على قائمة انتظار طرفية واحدة فقط.

عندما تدخل حزمة إلى قائمة انتظار مصنفة، يمكن تصنيفها إلى إحدى الفئات بداخلها. تتوفر ثلاثة معايير، على الرغم من أن قوائم الانتظار ليست كلها ستستخدم الثلاثة:

عوامل تصفية tc
إذا تم إرفاق عوامل تصفية tc بفئة، يتم استشارتها أولاً للحصول على تعليمات ذات صلة. يمكن لعوامل التصفية المطابقة لجميع حقول رأس الحزمة، وكذلك لعلامة جدار الحماية التي تم تطبيقها بواسطة iptables.
نوع الخدمة
تحتوي بعض قوائم الانتظار على قواعد مدمجة لتصنيف الحزم بناءً على حقل TOS.
skb->priority
يمكن لبرامج مساحة المستخدم تشفير معرف الفئة في حقل 'skb->priority' باستخدام الخيار SO_PRIORITY.

كل عقدة داخل الشجرة يمكن أن يكون لها عوامل تصفية خاصة بها ولكن عوامل التصفية الأعلى مستوى قد تشير أيضًا مباشرة إلى فئات أقل.

إذا لم ينجح التصنيف، يتم إدخال الحزم في قائمة الانتظار الطرفية المرفقة بتلك الفئة. تحقق من صفحات الدليل الخاصة بقائمة الانتظار للحصول على التفاصيل، ومع ذلك.

التسمية

جميع قوائم الانتظار والفئات وعوامل التصفية لها معرفات، والتي يمكن تحديدها أو تعيينها تلقائيًا.

تتكون المعرفات من رقم رئيسي ورقم فرعي، مفصولين بنقطتين - رئيسي:فرعي. كل من الرئيسي و الفرعي هي أرقام ست عشرية ومحدودة بـ 16 بت. هناك قيمتان خاصتان: يتم تمثيل الجذر بواسطة رئيسي و فرعي من كل الوحدات، ويتم تحديد غير المحدد بالأصفار.

QDISCS
يتم تعيين رقم رئيسي، يسمى 'مقبض'، لقائمة انتظار، والتي يمكن أن تحتوي على أطفال، تاركة مساحة أسماء الرقم الفرعي متاحة للفئات. يتم التعبير عن المقبض كـ '10:'. من المعتاد تحديد مقبض صريحًا لقوائم الانتظار المتوقع أن يكون لها أطفال.
الفئات
تشارك الفئات الموجودة تحت قائمة انتظار نفس الرقم الرئيسي لقائمة الانتظار، ولكن كل منها لها رقم فرعي منفصل يسمى 'معرف الفئة' لا علاقة له بالفئات الأصل، فقط بقائمة الانتظار الأصل. نفس عادة التسمية كما هو الحال بالنسبة لقوائم الانتظار تنطبق.

TC COMMANDS

الأوامر التالية متاحة لأقنعة Qdisc، والفئات، والفلاتر:

add
إضافة قناع Qdisc أو فئة أو فلتر إلى عقدة. لجميع الكيانات، يجب تمرير parent، إما بتمرير معرفه أو عن طريق الارتباط مباشرة بالجذر الخاص بالجهاز. عند إنشاء قناع Qdisc أو فلتر، يمكن تسميته بالمعلمة handle. تُسمى الفئة بالمعلمة classid.
delete
يمكن حذف قناع Qdisc عن طريق تحديد معرّفه، والذي يمكن أن يكون أيضًا "root". يتم حذف جميع الفئات الفرعية وأقنعة Qdisc الخاصة بها تلقائيًا، بالإضافة إلى أي فلاتر مرتبطة بها.
change
يمكن تعديل بعض الكيانات "في مكانها". تشترك في بناء الجملة الخاص بـ "add"، باستثناء أنه لا يمكن تغيير المعرف ولا يمكن تغيير الأصل. بعبارة أخرى، لا يمكن لـ change نقل عقدة.
replace
يجري إزالة / إضافة شبه ذرية لعقدة موجودة. إذا لم تكن العقدة موجودة بعد، يتم إنشاؤها.
get
يعرض فلترًا واحدًا بالنظر إلى الواجهة DEV، qdisc-id، priority، protocol و filter-id.
show
يعرض جميع الفلاتر المرتبطة بالواجهة المعطاة. يجب تمرير معرف أصل صالح.
link
متاح فقط لأقنعة Qdisc ويجري استبدالًا حيث يجب أن تكون العقدة موجودة بالفعل.

MONITOR

يمكن لأداة tc مراقبة الأحداث التي تنشئها النواة مثل إضافة / حذف أقنعة Qdisc أو الفلاتر أو الإجراءات، أو تعديل القائمة.

الأمر التالي متاح لـ monitor :

file
إذا تم تقديم خيار الملف، فإن tc لا يستمع إلى أحداث النواة، ولكنه يفتح الملف المحدد ويدمر محتوياته. يجب أن يكون الملف بتنسيق ثنائي وأن يحتوي على رسائل netlink.

OPTIONS

-b, -b filename, -batch, -batch filename
قراءة الأوامر من الملف المقدم أو الإدخال القياسي واستدعاؤها. سيؤدي أول فشل إلى إنهاء tc.
-force
لا تنهي tc عند حدوث أخطاء في وضع الدُفعات. إذا كانت هناك أي أخطاء أثناء تنفيذ الأوامر، فسيكون رمز إرجاع التطبيق غير صفري.
-o, -oneline
إخراج كل سجل في سطر واحد، واستبدال أحرف الأسطر بـ '\'. هذا مناسب عندما تريد عد السجلات باستخدام wc(1) أو لـ grep(1) الإخراج.
-n, -net, -netns <NETNS>
يقوم بالتبديل tc إلى مساحة اسم الشبكة المحددة NETNS. في الواقع، إنه يبسط تنفيذ:

ip netns exec NETNS tc [ OPTIONS ] OBJECT { COMMAND | help }

إلى

tc -n[etns] NETNS [ OPTIONS ] OBJECT { COMMAND | help }

-N, -Numeric
طباعة رقم البروتوكول، والنطاق، وdsfield، إلخ مباشرة بدلاً من تحويله إلى اسم قابل للقراءة.
-cf, -conf <FILENAME>
يحدد المسار إلى ملف التكوين. يُستخدم هذا الخيار بالاقتران مع خيارات أخرى (على سبيل المثال، -nm).
-t, -timestamp
عند تشغيل tc monitor ، اطبع طابعًا زمنيًا قبل رسالة الحدث بالتنسيق:
Timestamp: <Day> <Month> <DD> <hh:mm:ss> <YYYY> <usecs> usec
-ts, -tshort
عند تشغيل tc monitor ، يطبع طابعًا زمنيًا قصيرًا قبل رسالة الحدث بالتنسيق:
[<YYYY>-<MM>-<DD>T<hh:mm:ss>.<ms>]
-echo
طلب من النواة إرسال التكوين المطبق مرة أخرى.

FORMAT

يحتوي أمر العرض على خيارات تنسيق إضافية:

-s, -stats, -statistics
إخراج المزيد من الإحصائيات حول استخدام الحزم.
-d, -details
إخراج معلومات أكثر تفصيلاً حول المعدلات وأحجام الخلايا.
-r, -raw
إخراج قيم سداسية عشرية خام للمعّرفات.
-p, -pretty
بالنسبة لفلتر u32، قم بفك تشفير قيم الإزاحة والقناع إلى أوامر فلتر مكافئة بناءً على TCP / IP. في إخراج JSON، أضف مسافات لتحسين سهولة القراءة.
-iec
طباعة المعدلات بوحدات IEC (أي 1K = 1024).
-g, -graph
يعرض الفئات كرسم بياني ASCII. يطبع معلومات إحصائية عامة تحت كل فئة إذا تم تحديد الخيار -s. يمكن تصفية الفئات فقط بواسطة خيار dev.
-c[color][={always|auto|never}
تكوين إخراج الألوان. إذا تم حذف المعلمة أو كانت always، يتم تمكين إخراج الألوان بغض النظر عن حالة الإخراج القياسي. إذا كانت المعلمة auto، يتم التحقق من أن الإخراج القياسي هو طرفية قبل تمكين إخراج الألوان. إذا كانت المعلمة never، يتم تعطيل إخراج الألوان. إذا تم تحديده عدة مرات، فإن الأخير له الأسبقية. يتم تجاهل هذا العلم إذا تم إعطاء -json أيضًا.
-j, -json
عرض النتائج بتنسيق JSON.
-nm, -name
حل اسم الفئة من الملف /etc/iproute2/tc_cls أو من الملف المحدد بواسطة الخيار -cf. هذا الملف هو مجرد تعيين لـ classid إلى اسم الفئة.

Query and manipulate the ingress qdisc.

DESCRIPTION

tc is a utility for configuring traffic control primitives in the Linux kernel. These primitives include queueing disciplines (qdiscs), classes, and filters.

Traffic control is implemented as a tree, where the root is attached to a network device. Each node in the tree is either a queueing discipline or a filter. Qdiscs are responsible for scheduling packets for transmission. Filters are responsible for directing packets to appropriate qdiscs.

The tree structure allows for complex traffic shaping and prioritization policies to be implemented. For example, you can configure a root qdisc that uses a classful scheduler, and then create classes under that scheduler to represent different traffic types (e.g., VoIP, web, FTP). You can then use filters to direct packets of each type to their corresponding class.

The tc utility allows you to view and modify these traffic control structures.

QDISCS

Queueing disciplines (qdiscs) are responsible for managing the queue of packets waiting to be transmitted. They determine which packet is sent next, and when.

There are two main types of qdiscs: classless and classful.

CLASSES

Classes are used in conjunction with classful qdiscs to divide traffic into different categories. Each class can have its own queueing discipline and its own set of child classes or filters.

FILTERS

Filters are used to inspect incoming packets and direct them to the appropriate qdisc or class. Filters can be based on various criteria, such as source or destination IP address, port number, or packet protocol.

QEVENTS

The tc monitor command can be used to stream events from the kernel related to traffic control. This can be useful for debugging and monitoring traffic shaping behavior.

CLASSLESS QDISCS

Classless qdiscs do not support classification. All traffic is treated the same way.

Examples of classless qdiscs include:

pfifo
First-In, First-Out (FIFO) queueing discipline.
bfifo
Bucket-based FIFO queueing discipline.
red
Random Early Detection qdisc.
tbf
Token Bucket Filter qdisc.
sfq
Stochastic Fairness Queuing qdisc.

CONFIGURING CLASSLESS QDISCS

To configure a classless qdisc, you typically specify the qdisc type and any associated parameters. For example, to replace the default qdisc on eth0 with a pfifo qdisc:

tc qdisc add dev eth0 root pfifo limit 1000

CLASSFUL QDISCS

Classful qdiscs allow for more complex traffic management by dividing traffic into different classes. Each class can have its own characteristics and policies.

Examples of classful qdiscs include:

htb
Hierarchical Token Bucket qdisc.
hfsc
Hierarchical Fair Service Curve qdisc.
prio
Priority qdisc.

THEORY OF OPERATION

The tc command manipulates a tree of traffic control objects. The root of the tree is attached to a network device. Each node in the tree is either a qdisc or a filter.

Qdiscs are responsible for scheduling packets for transmission. Filters are responsible for directing packets to appropriate qdiscs.

The tree structure allows for complex traffic shaping and prioritization policies to be implemented. For example, you can configure a root qdisc that uses a classful scheduler, and then create classes under that scheduler to represent different traffic types (e.g., VoIP, web, FTP). You can then use filters to direct packets of each type to their corresponding class.

NAMING

The tc utility uses a hierarchical naming scheme for its objects. Each object is identified by its type (qdisc, class, or filter) and its parent. The root object is attached to a network device.

For example, the root qdisc on the eth0 interface might be named eth0. A class under that root qdisc might be named 1:1, and a filter associated with that class might be named 1:1.

The -n (or -names) option can be used to display numeric handles instead of names, which can be useful when dealing with complex configurations.

The following names are reserved for special purposes:
  • 0: The root of the tree.
  • ffff: Used internally by the kernel.
# Here is comment
1:40 voip # Here is another comment
1:50 web
1:60 ftp
1:2 home
tc will not fail if -nm was specified without -cf option but /etc/iproute2/tc_cls file does not exist, which makes it possible to pass -nm option for creating tc alias.
-br, -brief
Print only essential data needed to identify the filter and action (handle, cookie, etc.) and stats. This option is currently only supported by tc filter show and tc actions ls commands.

PARAMETERS

Many tc commands take parameters that configure the behavior of qdiscs, classes, and filters. These parameters vary depending on the type of object being configured.

Some common parameters include:

dev DEVICE
Specifies the network device to operate on.
parent X:
Specifies the parent qdisc or class for the object being created.
protocol PROTO
Specifies the protocol to use for the qdisc, class, or filter.
prio PRIO
Specifies the priority of a filter.
handle X:
Specifies the handle for a qdisc or class.
classid X:Y
Specifies the class ID for a class.
limit BYTES
Specifies the maximum queue size in bytes.
burst BYTES
Specifies the maximum burst size in bytes.
rate RATE
Specifies the desired bandwidth rate.

TC COMMANDS

The tc utility provides several commands for managing traffic control objects:

add
Add a new qdisc, class, or filter.
change
Modify an existing qdisc, class, or filter.
replace
Replace an existing qdisc, class, or filter. If it does not exist, it is added.
delete
Delete a qdisc, class, or filter.
show
Display existing qdiscs, classes, or filters.
get
Display a single qdisc, class, or filter.

MONITOR

The tc monitor command streams events from the kernel related to traffic control. This can be useful for debugging and monitoring traffic shaping behavior.

tc monitor

OPTIONS

The tc utility accepts various options that modify its behavior:

-d, --details

Display output in raw format.
-n, --names
Display numeric handles instead of names.
-i, --ifindex
Display interface index instead of name.
-c, --comment

-b, --batch
Read commands from standard input.
-e, --explain
Explain the command being executed.
-o, --output FILE

Show all objects, even those without statistics.
-v, --verbose

FORMAT

The output format of tc commands can be controlled using various options. The default format provides a human-readable representation of the traffic control configuration.

The -r (raw) option displays the output in a machine-readable format, which can be useful for scripting.

The -s (statistics) option shows statistics for each object, such as the number of packets and bytes transmitted.

The -d (details) option provides more in-depth information about each object, including its parameters and configuration.

EXAMPLE FORMAT

Here is an example of the default output format for a qdisc:

qdisc pfifo 8001: dev eth0 root refcnt 2
 link/ether 00:11:22:33:44:55 brd ff:ff:ff:ff:ff:ff
       RX: bytes  packets  errors  dropped netif_rx: bytes  packets
       TX: bytes  packets  errors  dropped
    123456      100        0       0      123456      100        0       0

Here is an example of the same output with the -s and -d options:

qdisc pfifo 8001: dev eth0 root refcnt 2 <stats>
 link/ether 00:11:22:33:44:55 brd ff:ff:ff:ff:ff:ff
       RX: bytes  packets  errors  dropped netif_rx: bytes  packets
       TX: bytes  packets  errors  dropped
    123456      100        0       0      123456      100        0       0
   Sent 100 pkts 123456 bytes 50 pkts 60000 bytes

EXAMPLES

tc -g class show dev eth0

Shows classes as ASCII graph on eth0 interface.

tc -g -s class show dev eth0

Shows classes as ASCII graph with stats info under each class.
