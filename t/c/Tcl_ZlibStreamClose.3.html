الوصف

تشكل هذه الوظائف الواجهة من مكتبة Tcl إلى مكتبة Zlib بواسطة Jean-loup Gailly و Mark Adler.

Tcl_ZlibDeflate و Tcl_ZlibInflate تضغط وتفك ضغط البيانات الموجودة في الوسيط dataObj على التوالي، وفقًا للوسيطين format، وللضغط، level. يتم استخدام القاموس في الوسيط dictObj لنقل معلومات رأس إضافية حول البيانات المضغوطة عندما يدعم تنسيق الضغط ذلك؛ حاليًا، يتم استخدام القاموس فقط عندما يكون الوسيط format هو TCL_ZLIB_FORMAT_GZIP أو TCL_ZLIB_FORMAT_AUTO. لمزيد من التفاصيل حول محتويات القاموس، انظر القسم قاموس خيارات GZIP أدناه. عند النجاح، تترك كلتا الوظيفتين البيانات المضغوطة أو غير المضغوطة الناتجة في قيمة مصفوفة بايت هي نتيجة مفسر Tcl؛ القيمة المرجعة هي رمز نتيجة Tcl قياسي.

Tcl_ZlibAdler32 و Tcl_ZlibCRC32 تحسب التحققات على مصفوفات البايت، وتعيد التحقق المحسوب. يتم حساب التحققات بشكل متزايد، مما يسمح بمعالجة البيانات في كتل، ولكن هذا يتطلب من المتصل الاحتفاظ بالتحقق الحالي وتمريره كوسيط initValue؛ يمكن الحصول على القيمة الأولية لاستخدامها لهذا عن طريق استخدام NULL للوسيط bytes بدلاً من مؤشر إلى مصفوفة البايتات لحساب التحقق. وبالتالي، فإن الاستخدام النموذجي في حالة الكتلة الواحدة من البيانات يكون كالتالي:

checksum = Tcl_ZlibCRC32(Tcl_ZlibCRC32(0,NULL,0), data, length);

لاحظ أن خوارزمية Adler-32 ليست تحققًا حقيقيًا، بل هي نوع مرتبط من التجزئة يعمل بشكل أفضل على البيانات الطويلة.

تدفقات ZLIB

Tcl_ZlibStreamInit ينشئ دفق ضغط أو فك ضغط مرتبط بأمر Tcl، وفقًا لوسائطه، ويوفر رمزًا مجردًا للدفق ويعيد رمز نتيجة Tcl عادي؛ Tcl_ZlibStreamGetCommandName يعيد اسم هذا الأمر بالنظر إلى رمز الدفق، أو NULL إذا كان الدفق لا يحتوي على أمر. التدفقات ليست مصممة لتكون آمنة للخيوط؛ يجب استخدام كل دفق فقط من الخيط الذي أنشأه. عند العمل مع تدفقات gzip، يمكن توفير قاموس (حقول كما هو موضح في قسم قاموس خيارات GZIP أدناه) عبر الوسيط dictObj الذي يسمح عند الضغط بالتحكم في الرؤوس التي تم إنشاؤها، وعند فك الضغط يسمح باكتشاف الرؤوس الموجودة. لاحظ أنه سيتم الكتابة إلى القاموس عند فك الضغط بمجرد قراءة بيانات كافية للحصول على رأس كامل. هذا يعني أن القاموس يجب أن يكون قيمة غير مشتركة في تلك الحالة؛ يُقترح استخدام قيمة فارغة تم إنشاؤها باستخدام Tcl_NewObj.

بمجرد إنشاء دفق، يتم استخدام Tcl_ZlibStreamPut لإضافة البيانات إلى الدفق ويتم استخدام Tcl_ZlibStreamGet لاسترداد البيانات من الدفق بعد المعالجة. كلتاهما تعيدان رموز نتيجة Tcl عادية وتتركان رسالة خطأ في نتيجة المفسر المسجل به الدفق في حالة الخطأ (إذا تم إجراء هذا التسجيل). مع Tcl_ZlibStreamPut، يجب عدم تعديل قيمة المخزن المؤقت للبيانات التي تم تمريرها إليه بعد ذلك. مع Tcl_ZlibStreamGet، سيتم إلحاق بايتات البيانات بقيمة المخزن المؤقت للبيانات التي تم تمريرها إليه. داخليًا في الدفق، يتم الاحتفاظ بالبيانات مضغوطة لتقليل تكلفة مساحة المخزن المؤقت.

DESCRIPTION

These functions provide a Tcl interface to the zlib compression library. The functions work with a stream which is initialized by Tcl_ZlibStreamInit, fed data with Tcl_ZlibStreamPut, and from which compressed data is retrieved with Tcl_ZlibStreamGet. The state of the stream can be queried using Tcl_ZlibStreamDataAvailable and Tcl_ZlibStreamEof, and the stream can be reset for reuse with Tcl_ZlibStreamReset. The stream is finally cleaned up using Tcl_ZlibStreamClose.

Tcl_ZlibStreamInit initializes a zlib stream. The arguments are the interpreter in which the stream will be used, the name of the command that will be used to control the stream, a value indicating whether the stream is to be used for compression or decompression, a value indicating the format of the compressed data (zlib, gzip, or raw), and a dictionary object containing options for the stream initialization.

Tcl_ZlibStreamPut is used to feed data into the stream. DataObj is a Tcl value containing the data to be compressed or decompressed. If flush is true, the output buffer is flushed. The function returns a normal Tcl result code. The data that is output by the compression or decompression engine is returned as the result of the command that controls the stream.

Tcl_ZlibStreamGet retrieves data from the stream. If the stream is set up for decompression, this call attempts to decompress and return the uncompressed data. If the stream is set up for compression, this call returns any data that has been compressed and is available in the output buffer. BytesToRead specifies the maximum number of bytes to return. If bytesToRead is negative, then all available compressed data is returned. The function returns a normal Tcl result code. The data retrieved is returned as the result of the command that controls the stream.

Tcl_ZlibStreamDataAvailable returns the number of bytes of compressed data that are available for retrieval using Tcl_ZlibStreamGet.

Tcl_ZlibStreamEof returns a boolean value indicating whether the end of the uncompressed data has been reached.

Tcl_ZlibStreamSetCompressionDictionary is used to control the compression dictionary used with the stream, a compression dictionary being an array of bytes (such as might be created with Tcl_NewByteArrayObj) that is used to initialize the compression engine rather than leaving it to create it on the fly from the data being compressed. Setting a compression dictionary allows for more efficient compression in the case where the start of the data is highly regular, but it does require both the compressor and the decompressor to agreee on the value to use. Compression dictionaries are only fully supported for zlib-format data; on compression, they must be set before any data is sent in with Tcl_ZlibStreamPut, and on decompression they should be set when Tcl_ZlibStreamGet produces an error with its -errorcode set to “ZLIB NEED_DICT code”; the code will be the Adler-32 checksum (see Tcl_ZlibAdler32) of the compression dictionary sought. (Note that this is only true for zlib-format streams; gzip streams ignore compression dictionaries as the format specification doesn't permit them, and raw streams just produce a data error if the compression dictionary is missing or incorrect.)

If you wish to clear a stream and reuse it for a new compression or decompression action, Tcl_ZlibStreamReset will do this and return a normal Tcl result code to indicate whether it was successful; if the stream is registered with an interpreter, an error message will be left in the interpreter result when this function returns TCL_ERROR. Finally, Tcl_ZlibStreamClose will clean up the stream and delete the associated command: using Tcl_DeleteCommand on the stream's command is equivalent (when such a command exists).

GZIP OPTIONS DICTIONARY

The dictObj parameter to Tcl_ZlibDeflate, Tcl_ZlibInflate and Tcl_ZlibStreamInit is used to pass a dictionary of options about that is used to describe the gzip header in the compressed data. When creating compressed data, the dictionary is read and when unpacking compressed data the dictionary is written (in which case the dictObj parameter must refer to an unshared dictionary value).

The following fields in the dictionary value are understood. All other fields are ignored. No field is required when creating a gzip-format stream.

comment
This holds the comment field of the header, if present. If absent, no comment was supplied (on decompression) or will be created (on compression).
crc
A boolean value describing whether a CRC of the header is computed. Note that the gzip program does not use or allow a CRC on the header.
filename
The name of the file that held the uncompressed data. This should not contain any directory separators, and should be sanitized before use on decompression with file tail.
os
The operating system type code field from the header (if not the “unknown” value). See RFC 1952 for the meaning of these codes. On compression, if this is absent then the field will be set to the “unknown” value.
size
The size of the uncompressed data. This is ignored on compression; the size of the data compressed depends on how much data is supplied to the compression engine.
time
The time field from the header if non-zero, expected to be the time that the file named by the filename field was modified. Suitable for use with clock format. On creation, the right value to use is that from clock seconds or file mtime.
type
The type of the uncompressed data (either binary or text) if known.

PORTABILITY NOTES

These functions will fail gracefully if Tcl is not linked with the zlib library.
