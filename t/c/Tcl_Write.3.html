الوصف

توفر آلية قنوات Tcl آلية مستقلة عن الجهاز ومستقلة عن المنصة لتنفيذ عمليات الإدخال والإخراج المخزنة مؤقتًا على مجموعة متنوعة من أنواع الملفات والمقابس والأجهزة. آلية القنوات قابلة للتوسيع إلى أنواع قنوات جديدة، عن طريق توفير برنامج تشغيل قناة منخفض المستوى للنوع الجديد؛ وصف واجهة برنامج تشغيل القناة موجود في صفحة الدليل الخاصة بـ Tcl_CreateChannel. توفر آلية القنوات نظام تخزين مؤقت يعتمد على الإدخال/الإخراج القياسي في Unix، كما أنها تسمح بالإدخال/الإخراج غير المتزامن على القنوات.

تتكون الإجراءات الموصوفة في صفحة الدليل هذه من واجهات برمجة التطبيقات C للطبقة العامة لهندسة القنوات. لوصف هندسة برنامج تشغيل القناة وكيفية تنفيذ برامج تشغيل القنوات لأنواع جديدة من القنوات، راجع صفحة الدليل الخاصة بـ Tcl_CreateChannel.

TCL_OPENFILECHANNEL

تفتح Tcl_OpenFileChannel قناة لملف محلي أو شبكة. يجب أن يكون fileName هو اسم الملف، و mode هو سلسلة تصف كيفية فتح الملف (مثل "r" للقراءة، "w" للكتابة، "r+" للقراءة والكتابة، "rb" للقراءة الثنائية، إلخ). يجب أن تكون permissions علامات صلاحيات POSIX (مثل 0644) يتم استخدامها فقط إذا تم إنشاء ملف جديد. إذا نجحت العملية، فسيتم إرجاع واصف قناة Tcl. إذا فشلت، فسيتم تعيين خطأ في interp وسترجع الدالة NULL.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel يفتح ملفًا محددًا بواسطة fileName ويعيد مقبض قناة يمكن استخدامه لإجراء إدخال وإخراج إلى الملف. تم تصميم واجهة برمجة التطبيقات هذه على غرار إجراء fopen الخاص بمكتبة الإدخال/الإخراج القياسية لنظام Unix. يتشابه بناء الجملة ومعنى جميع الوسائط مع تلك المقدمة في أمر Tcl open عند فتح ملف. إذا حدث خطأ أثناء فتح القناة، فإن Tcl_OpenFileChannel تعيد NULL وتسجل رمز خطأ POSIX يمكن استعادته باستخدام Tcl_GetErrno. بالإضافة إلى ذلك، إذا كانت interp غير NULL، فإن Tcl_OpenFileChannel تترك رسالة خطأ في نتيجة interp بعد أي خطأ. كجزء من Tcl 8.4، يجب استخدام القيمة المستندة إلى واجهة برمجة التطبيقات Tcl_FSOpenFileChannel بدلاً من Tcl_OpenFileChannel حيثما أمكن.

القناة المنشأة حديثًا غير مسجلة في المفسر المقدم؛ لتسجيلها، يجب استخدام Tcl_RegisterChannel، الموضح أدناه. إذا تم إغلاق إحدى القنوات القياسية، stdin أو stdout أو stderr سابقًا، فإن إجراء إنشاء القناة الجديدة يقوم أيضًا بتعيينها كبديل للقناة القياسية.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel يوفر واجهة مستوى C لوظائف أوامر exec و open. يقوم بإنشاء سلسلة من العمليات المتسلسلة المحددة بواسطة الوسائط argv و argc ويعيد قناة يمكن استخدامها للتواصل مع هذه العمليات المتسلسلة. تشير الوسيطة flags إلى نوع الاتصال الذي سيتم إجراؤه مع سلسلة العمليات.

إذا تم تعيين علامة TCL_STDIN، فسيتم ربط الإدخال القياسي للعملية الأولى في السلسلة بالقناة: الكتابة إلى القناة ستوفر الإدخال لتلك العملية. إذا لم يتم تعيين علامة TCL_STDIN، فسيكون الإدخال القياسي للعملية الأولى في السلسلة هو نفسه الإدخال القياسي لهذا التطبيق. إذا تم تعيين علامة TCL_STDOUT، فيمكن قراءة الإخراج القياسي لآخر عملية في السلسلة من القناة؛ وإلا، فسيتم توجيهه إلى الإخراج القياسي لهذا التطبيق. إذا تم تعيين علامة TCL_STDERR، فسيتم إرجاع إخراج الخطأ القياسي لجميع العمليات في السلسلة إلى القناة ويولد خطأ عند إغلاق القناة؛ وإلا، فسيتم توجيهه إلى الخطأ القياسي لهذا التطبيق. إذا لم يتم تعيين علامة TCL_ENFORCE_MODE، فيمكن للوسائط argc و argv إعادة توجيه المقابض القياسية لاستبدال TCL_STDIN و TCL_STDOUT و TCL_STDERR؛ إذا تم تعيينها، فسيكون خطأ إذا حاولت argc و argv استبدال القنوات القياسية التي تم تعيين TCL_STDIN و TCL_STDOUT و TCL_STDERR لها.

إذا حدث خطأ أثناء فتح القناة، فإن Tcl_OpenCommandChannel تعيد NULL وتسجل رمز خطأ POSIX يمكن استعادته باستخدام Tcl_GetErrno. بالإضافة إلى ذلك، تترك Tcl_OpenCommandChannel رسالة خطأ في نتيجة المفسر. لا يمكن أن تكون interp NULL.

القناة المنشأة حديثًا غير مسجلة في المفسر المقدم؛ لتسجيلها، يجب استخدام Tcl_RegisterChannel، الموضح أدناه. إذا تم إغلاق إحدى القنوات القياسية، stdin أو stdout أو stderr سابقًا، فإن إجراء إنشاء القناة الجديدة يقوم أيضًا بتعيينها كبديل للقناة القياسية.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel ينشئ Tcl_Channel من مقبض ملف موجود ومخصص للمنصة. القناة المنشأة حديثًا غير مسجلة في المفسر المقدم؛ لتسجيلها، يجب استخدام Tcl_RegisterChannel، الموضح أدناه. إذا تم إغلاق إحدى القنوات القياسية، stdin أو stdout أو stderr سابقًا، فإن إجراء إنشاء القناة الجديدة يقوم أيضًا بتعيينها كبديل للقناة القياسية.

TCL_GETCHANNEL

Tcl_GetChannel يعيد قناة معطاة باسم channelName المستخدم لإنشائها باستخدام Tcl_CreateChannel ومؤشر إلى مفسر في interp. إذا لم يتم العثور على القناة بهذا الاسم في المفسر، فإن الإجراء يعيد NULL. إذا كانت الوسيطة modePtr غير NULL، فإنها تشير إلى متغير عدد صحيح سيحصل على OR منطقي لـ TCL_READABLE و TCL_WRITABLE للإشارة إلى ما إذا كانت القناة مفتوحة للقراءة والكتابة.

Tcl_GetChannelNames و Tcl_GetChannelNamesEx يكتبان أسماء القنوات المسجلة في نتيجة المفسر كقيمة قائمة. ستقوم Tcl_GetChannelNamesEx بتصفية هذه الأسماء بناءً على pattern. إذا كانت pattern NULL، فلن تجري أي تصفية. قيمة الإرجاع هي TCL_OK إذا لم تكن هناك أخطاء في الكتابة إلى النتيجة، وإلا فهي TCL_ERROR، وتترك رسالة الخطأ في نتيجة المفسر.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel يضيف قناة إلى مجموعة القنوات التي يمكن الوصول إليها في interp. بعد هذا الاستدعاء، يمكن لبرامج Tcl التي تعمل في هذا المفسر الإشارة إلى القناة بالاسم المقدم في استدعاء Tcl_CreateChannel. بعد هذا الاستدعاء، تصبح القناة ملكًا للمفسر، ولا يجب على المتصل استدعاء Tcl_Close للقناة؛ يتم إغلاق القناة تلقائيًا عند إلغاء تسجيلها من المفسر.

يمكن للكود الذي يعمل خارج أي مفسر استدعاء Tcl_RegisterChannel مع interp كـ NULL، مما يشير إلى أنه يريد الاحتفاظ بمرجع لهذه القناة. بعد ذلك، يمكن تسجيل القناة في مفسر Tcl ولا يتم إغلاقها إلا عندما يتم إجراء عدد متساوٍ من استدعاءات Tcl_UnregisterChannel. هذا يسمح للكود الذي يعمل خارج أي مفسر بالاحتفاظ بمرجع آمن للقناة المسجلة في مفسر Tcl.

يتفاعل هذا الإجراء مع الكود الذي يدير القنوات القياسية. إذا لم يتم تهيئة أي قنوات قياسية قبل الاستدعاء الأول لـ Tcl_RegisterChannel، فسيتم تهيئتها بواسطة هذا الاستدعاء. انظر Tcl_StandardChannels لمعالجة عامة للقنوات القياسية وسلوك مكتبة Tcl فيما يتعلق بها.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel يزيل قناة من مجموعة القنوات التي يمكن الوصول إليها في interp. بعد هذا الاستدعاء، لن تتمكن برامج Tcl من استخدام اسم القناة للإشارة إلى القناة في هذا المفسر. إذا أزال هذا الإجراء آخر تسجيل للقناة في أي مفسر، فسيتم أيضًا إغلاق القناة وتدميرها.

يمكن للكود غير المرتبط بأي مفسر استدعاء Tcl_UnregisterChannel مع interp كـ NULL، مما يشير إلى Tcl أنه لم يعد يحتفظ بمرجع لتلك القناة. إذا كان هذا هو المرجع الأخير للقناة، فسيتم إغلاقها الآن. Tcl_UnregisterChannel مشابه جدًا لـ Tcl_DetachChannel، باستثناء أنه يغلق القناة أيضًا إذا لم تعد هناك مراجع لها.

TCL_DETACHCHANNEL

Tcl_DetachChannel يزيل قناة من مجموعة القنوات التي يمكن الوصول إليها في interp. بعد هذا الاستدعاء، لن تتمكن برامج Tcl من استخدام اسم القناة للإشارة إلى القناة في هذا المفسر. بالإضافة إلى ذلك، لا يكون لهذا الأمر أي تأثير إضافي. لا يمكن استخدامه على القنوات القياسية (stdout و stderr و stdin)، وسيعيد TCL_ERROR إذا تم تمرير إحدى هذه القنوات إليه.

يمكن للكود غير المرتبط بأي مفسر استدعاء Tcl_DetachChannel مع interp كـ NULL، مما يشير إلى Tcl أنه لم يعد يحتفظ بمرجع لتلك القناة. إذا كان هذا هو المرجع الأخير للقناة، فبخلاف Tcl_UnregisterChannel، لن يتم إغلاقها.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel يتحقق مما إذا كانت القناة هي واحدة من القنوات القياسية الثلاث، stdin أو stdout أو stderr. إذا كانت كذلك، فإنها تعيد 1، وإلا تعيد 0.

لا يتم محاولة التحقق مما إذا كانت القناة المعطاة أو القنوات القياسية قد تم تهيئتها أو كانت صالحة.

TCL_CLOSE

Tcl_Close يدمر القناة channel، والتي يجب أن تشير إلى قناة مفتوحة حاليًا. لا يجب أن تكون القناة مسجلة في أي مفسر عند استدعاء Tcl_Close. يتم إفراغ مخزن الإخراج المؤقت قبل تدمير القناة، ويتم تجاهل أي مخزن إدخال مؤقت. إذا كانت هذه قناة مانعة، فلن يعود الاستدعاء حتى يتم إرسال جميع البيانات المخزنة مؤقتًا إلى جهاز الإخراج الخاص بالقناة. إذا كانت هذه قناة غير مانعة وهناك بيانات مخزنة مؤقتًا لا يمكن كتابتها دون حظر، فسيعود الاستدعاء فورًا؛ يتم إفراغ الإخراج في الخلفية ويتم إغلاق القناة عندما يتم إخراج جميع البيانات المخزنة مؤقتًا. في هذه الحالة، لا يتم الإبلاغ عن الأخطاء أثناء الإفراغ.

إذا تم إغلاق القناة بنجاح، فإن Tcl_Close تعيد TCL_OK. إذا حدث خطأ، فإن Tcl_Close تعيد TCL_ERROR وتسجل رمز خطأ POSIX يمكن استعادته باستخدام Tcl_GetErrno. إذا تم إغلاق القناة بشكل متزامن وحدث خطأ أثناء إغلاق القناة و interp ليست NULL، فسيتم ترك رسالة خطأ في نتيجة المفسر.

ملاحظة: ليس من الآمن استدعاء Tcl_Close على قناة تم تسجيلها باستخدام Tcl_RegisterChannel؛ انظر الوثائق الخاصة بـ Tcl_RegisterChannel، أعلاه، للتفاصيل. إذا تم تمرير القناة كوسيطة chan في استدعاء لـ Tcl_RegisterChannel، فيجب عليك استخدام Tcl_UnregisterChannel، الذي يستدعي داخليًا Tcl_Close عندما تقابل جميع استدعاءات Tcl_RegisterChannel استدعاءات مقابلة لـ Tcl_UnregisterChannel.

TCL_READCHARS_AND_TCL_READ

Tcl_ReadChars تستهلك بايتات من channel، وتحولها إلى UTF-8 وفقًا لترميز القناة وتخزين البيانات الناتجة في تمثيل readObjPtr. القيمة التي تعيدها Tcl_ReadChars هي عدد الأحرف، حتى charsToRead، التي تم تخزينها في readObjPtr. إذا حدث خطأ أثناء القراءة، فإن القيمة المعادة هي -1 وتقوم Tcl_ReadChars بتسجيل رمز خطأ POSIX يمكن استعادته باستخدام Tcl_GetErrno.

TCL_GETSOBJ_Y_TCL_GETS

Tcl_Getsobj يستهلك بايتات من channel، ويحول البايتات إلى UTF-8 بناءً على ترميز القناة، حتى يتم رؤية سطر كامل من الإدخال. إذا كان ترميز القناة binary، يتم التعامل مع كل بايت مقروء من القناة كحرف يونيكود فردي. يتم إلحاق جميع أحرف السطر باستثناء أحرف نهاية السطر، بتمثيل سلسلة lineObjPtr. يتم قراءة أحرف نهاية السطر وتجاهلها.

إذا تم قراءة سطر بنجاح، فإن القيمة المرجعة تكون أكبر من أو تساوي الصفر وتشير إلى عدد البايتات المخزنة في lineObjPtr. في حالة حدوث خطأ، تعيد Tcl_Getsobj القيمة -1 وتسجل رمز خطأ POSIX يمكن استرداده باستخدام Tcl_GetErrno. تعيد Tcl_Getsobj أيضًا القيمة -1 إذا تم الوصول إلى نهاية الملف؛ يمكن استخدام الإجراء Tcl_Eof للتمييز بين خطأ وحالة نهاية الملف.

إذا كانت القناة في وضع عدم الحظر، يمكن أن تكون القيمة المرجعة أيضًا -1 إذا لم تكن هناك بيانات متاحة أو البيانات المتاحة لم تحتوي على حرف نهاية السطر. عند إرجاع -1، يمكن استدعاء الإجراء Tcl_InputBlocked لتحديد ما إذا كانت القناة محظورة بسبب عدم توفر الإدخال.

Tcl_Get هي نفسها Tcl_Getsobj باستثناء أن الأحرف الناتجة يتم إلحاقها بالسلسلة الديناميكية المعطاة بواسطة lineRead بدلاً من قيمة Tcl.

TCL_UNGETS

يتم استخدام Tcl_Ungets لإضافة بيانات إلى طابور الإدخال لقناة، سواء في رأس الطابور أو ذيله. يشير المؤشر input إلى البيانات المراد إضافتها. يتم إعطاء طول الإدخال المراد إضافته بواسطة inputLen. تشير القيمة غير الصفرية لـ addAtEnd إلى أنه سيتم إضافة البيانات في نهاية الطابور؛ وإلا سيتم إضافتها في رأس الطابور. إذا كانت القناة تحتوي على علامة EOF "لاصقة"، فلن تتم إضافة أي بيانات إلى طابور الإدخال. تعيد Tcl_Ungets القيمة inputLen أو -1 في حالة حدوث خطأ.

TCL_WRITECHARS, TCL_WRITEOBJ, AND TCL_WRITE

يقبل Tcl_WriteChars بايتات bytesToWrite من بيانات الأحرف في charBuf. يتم تحويل أحرف UTF-8 في المخزن المؤقت إلى ترميز القناة وتجميعها للإخراج إلى channel. إذا كانت bytesToWrite سالبة، تتوقع Tcl_WriteChars أن تكون charBuf منتهية بحرف null وتقوم بإخراج كل شيء حتى حرف null.

قد لا تظهر البيانات المجمعة للإخراج على جهاز الإخراج فورًا، بسبب التخزين المؤقت الداخلي. إذا كان يجب أن تظهر البيانات فورًا، استدعِ Tcl_Flush بعد استدعاء Tcl_WriteChars، أو قم بتعيين خيار -buffering على القناة إلى none. إذا كنت ترغب في ظهور البيانات فور قبول سطر كامل للإخراج، قم بتعيين خيار -buffering على القناة إلى وضع line.

القيمة المرجعة لـ Tcl_WriteChars هي عدد البايتات التي تم قبولها للإخراج إلى القناة. هذه إما أكبر من الصفر للإشارة إلى النجاح أو -1 للإشارة إلى حدوث خطأ. في حالة حدوث خطأ، تسجل Tcl_WriteChars رمز خطأ POSIX يمكن استرداده باستخدام Tcl_GetErrno.

يتم تحويل أحرف نهاية السطر في بيانات الإخراج إلى تسلسلات نهاية سطر خاصة بالمنصة وفقًا للخيار -translation للقناة. يتم ذلك حتى لو لم يكن للقناة ترميز.

Tcl_WriteObj تشبه Tcl_WriteChars باستثناء أنها تقبل قيمة Tcl سيتم إخراج محتوياتها إلى القناة. يتم تحويل أحرف UTF-8 في تمثيل سلسلة writeObjPtr إلى ترميز القناة وتجميعها للإخراج إلى channel. كتحسين للأداء، عند الكتابة إلى قناة ذات ترميز binary، لا يتم تحويل أحرف UTF-8 عند كتابتها. بدلاً من ذلك، يتم كتابة البايتات في التمثيل الداخلي لـ writeObjPtr كقيمة مصفوفة بايتات إلى القناة. سيتم بناء تمثيل مصفوفة البايتات للقيمة إذا لزم الأمر. بهذه الطريقة، يمكن قراءة البيانات الموجهة بالبايت من قناة، ومعالجتها عن طريق استدعاء Tcl_GetByteArrayFromObj ووظائف ذات صلة، ثم كتابتها إلى قناة دون تكلفة التحويل من أو إلى UTF-8.

Tcl_Write تشبه Tcl_WriteChars باستثناء أنها لا تقوم بتحويلات الترميز، بغض النظر عن ترميز القناة. إنها مهملة وتوجد للتوافق مع الإصدارات السابقة مع ملحقات Tcl غير الدولية. إنها تقبل بايتات bytesToWrite من البيانات في byteBuf وتقوم بتجميعها للإخراج إلى channel. إذا كانت bytesToWrite سالبة، تتوقع Tcl_Write أن تكون byteBuf منتهية بحرف null وتقوم بإخراج كل شيء حتى حرف null.

Tcl_WriteRaw هي نفسها Tcl_Write ولكنها لا تعوض عن التكديس. بينما تقوم Tcl_Write (والوظائف الأخرى في API) دائمًا بتغذية مدخلاتها إلى أعلى قناة في المكدس الذي تنتمي إليه القناة المقدمة، فإن Tcl_WriteRaw لا تفعل ذلك. وبالتالي فإن هذه الوظيفة قابلة للاستخدام فقط لبرامج تشغيل القنوات التحويلية، أي برامج التشغيل المستخدمة في منتصف مكدس من القنوات، لنقل البيانات من التحويل إلى القناة التي تحتها.

TCL_FLUSH

يتسبب Tcl_Flush في كتابة جميع بيانات الإخراج المخزنة مؤقتًا للقناة channel إلى ملفها أو جهازها الأساسي في أقرب وقت ممكن. إذا كانت القناة في وضع الحظر، فإن الاستدعاء لا يعود حتى يتم إرسال جميع البيانات المخزنة مؤقتًا إلى القناة أو حدوث خطأ ما. يعود الاستدعاء فورًا إذا كانت القناة غير حاجزة؛ يبدأ عملية مسح في الخلفية ستكتب البيانات المخزنة مؤقتًا إلى القناة في النهاية، بأسرع ما يمكن للقناة امتصاصها.

القيمة المرجعة هي عادةً TCL_OK. في حالة حدوث خطأ، تعيد Tcl_Flush القيمة TCL_ERROR وتسجل رمز خطأ POSIX يمكن استرداده باستخدام Tcl_GetErrno.

TCL_SEEK

ينقل Tcl_Seek نقطة الوصول في channel حيث سيتم قراءة أو كتابة البيانات اللاحقة. يتم مسح الإخراج المخزن مؤقتًا إلى القناة ويتم تجاهل الإدخال المخزن مؤقتًا، قبل عملية البحث.

يعيد Tcl_Seek عادةً نقطة الوصول الجديدة. في حالة حدوث خطأ، يعيد Tcl_Seek القيمة -1 ويسجل رمز خطأ POSIX يمكن استرداده باستخدام Tcl_GetErrno. بعد حدوث خطأ، قد تكون نقطة الوصول قد تم نقلها أو لم يتم نقلها.

TCL_TELL

يعيد Tcl_Tell نقطة الوصول الحالية لقناة. القيمة المرجعة هي -1 إذا كانت القناة لا تدعم البحث.

TCL_TRUNCATECHANNEL

يقوم Tcl_TruncateChannel بقص الملف الأساسي للقناة channel إلى طول length معين من البايتات. يعيد TCL_OK إذا نجحت العملية، و TCL_ERROR إذا لم تنجح.

TCL_GETCHANNELOPTION

TCL_GETCHANNELOPTION

The Tcl_GetChannelOption procedure retrieves the value of an option optionName on channel. The value is stored in the buffer pointed to by value, and the size of the buffer is given by len. The actual length of the value is returned. If the buffer is too small, Tcl_GetChannelOption returns the required size, and the contents of value are undefined. If an error occurs, it returns -1. If interp is non-NULL, Tcl_GetChannelOption leaves an error message in the interpreter's result. The options that can be retrieved are those that can be set with a series of calls to Tcl_DStringAppendElement. The various preexisting options and their possible values are described in the manual entry for the Tcl fconfigure command. Other options can be added by each channel type. These channel type specific options are described in the manual entry for the Tcl command that creates a channel of that type; for example, the additional options for TCP-based channels are described in the manual entry for the Tcl socket command. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR and calls Tcl_SetErrno to store an appropriate POSIX error code.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption sets a new value newValue for an option optionName on channel. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR; in addition, if interp is non-NULL, Tcl_SetChannelOption leaves an error message in the interpreter's result.

TCL_EOF

Tcl_Eof returns a nonzero value if channel encountered an end of file during the last input operation.

TCL_INPUTBLOCKED

Tcl_InputBlocked returns a nonzero value if channel is in nonblocking mode and the last input operation returned less data than requested because there was insufficient data available. The call always returns zero if the channel is in blocking mode.

TCL_INPUTBUFFERED

Tcl_InputBuffered returns the number of bytes of input currently buffered in the internal buffers for a channel. If the channel is not open for reading, this function always returns zero.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered returns the number of bytes of output currently buffered in the internal buffers for a channel. If the channel is not open for writing, this function always returns zero.

PLATFORM ISSUES

The handles returned from Tcl_GetChannelHandle depend on the platform and the channel type. On Unix platforms, the handle is always a Unix file descriptor as returned from the open system call. On Windows platforms, the handle is a file HANDLE when the channel was created with Tcl_OpenFileChannel, Tcl_OpenCommandChannel, or Tcl_MakeFileChannel. Other channel types may return a different type of handle on Windows platforms.
