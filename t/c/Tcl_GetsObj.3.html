الوصف

توفر آلية قنوات Tcl آلية مستقلة عن الأجهزة ومستقلة عن المنصة لإجراء عمليات الإدخال والإخراج المؤقتة على مجموعة متنوعة من أنواع الملفات والمقابس والأجهزة. آلية القنوات قابلة للتوسيع إلى أنواع قنوات جديدة، عن طريق توفير مشغل قنوات منخفض المستوى للنوع الجديد؛ تم وصف واجهة مشغل القنوات في مدخل الدليل الخاص بـ Tcl_CreateChannel. توفر آلية القنوات نظام تخزين مؤقت مصمم على غرار الإدخال/الإخراج القياسي في Unix، كما تسمح بالإدخال/الإخراج غير الحاجب على القنوات.

الإجراءات الموصوفة في هذا الدليل تتكون من واجهات برمجة التطبيقات C للطبقة العامة من بنية القناة. لوصف بنية مشغل القنوات وكيفية تنفيذ مشغلات القنوات لأنواع جديدة من القنوات، انظر مدخل الدليل الخاص بـ Tcl_CreateChannel.

TCL_GETSOBJ_Y_TCL_GETS

Tcl_Getsobj تستهلك بايتات من channel، محولة البايتات إلى UTF-8 بناءً على ترميز القناة، حتى يتم رؤية سطر كامل من المدخلات. إذا كان ترميز القناة binary، يتم التعامل مع كل بايت مقروء من القناة كحرف يونيكود فردي. يتم إلحاق جميع أحرف السطر باستثناء حرف (أو أحرف) نهاية السطر بتمثيل السلسلة الخاص بـ lineobjptr. يتم قراءة أحرف نهاية السطر والتخلص منها.

إذا تمت قراءة سطر بنجاح، فإن قيمة الإرجاع تكون أكبر من أو تساوي صفرًا وتشير إلى عدد البايتات المخزنة في lineobjptr. في حالة حدوث خطأ، تعيد Tcl_Getsobj القيمة -1 وتسجل رمز خطأ POSIX يمكن استرداده باستخدام Tcl_Geterrno. تعيد Tcl_Getsobj أيضًا القيمة -1 إذا تم الوصول إلى نهاية الملف؛ يمكن استخدام الإجراء Tcl_Eof للتمييز بين خطأ وحالة نهاية الملف.

إذا كانت القناة في وضع عدم الحظر، يمكن أن تكون قيمة الإرجاع -1 أيضًا إذا لم تكن هناك بيانات متاحة أو إذا كانت البيانات المتاحة لا تحتوي على حرف نهاية السطر. عند إرجاع -1، يمكن استدعاء الإجراء Tcl_InputBlocked لتحديد ما إذا كانت القناة محظورة بسبب عدم توفر المدخلات.

Tcl_Get مماثلة لـ Tcl_Getsobj باستثناء أنه يتم إلحاق الأحرف الناتجة بالسلسلة الديناميكية المعطاة بواسطة lineread بدلاً من قيمة Tcl.

TCL_UNGETS

تُستخدم Tcl_Ungets لإضافة بيانات إلى طابور الإدخال لقناة، إما في رأس الطابور أو في ذيله. يشير المؤشر input إلى البيانات المراد إضافتها. يتم إعطاء طول المدخلات المراد إضافتها بواسطة inputlen. تشير القيمة غير الصفرية لـ addatend إلى أنه سيتم إضافة البيانات في نهاية الطابور؛ وإلا سيتم إضافتها في رأس الطابور. إذا كانت القناة تحتوي على إشارة EOF "لاصقة" (sticky)، فلن تتم إضافة أي بيانات إلى طابور الإدخال. تعيد Tcl_Ungets القيمة inputlen أو -1 في حالة حدوث خطأ.

TCL_WRITECHARS_Y_TCL_WRITEOBJ_Y_TCL_WRITE

تستقبل Tcl_Writechars عدد bytesToWrite من بايتات بيانات الأحرف في charbuf. يتم تحويل أحرف UTF-8 في المخزن المؤقت إلى ترميز القناة وإدراجها في قائمة انتظار للإخراج إلى channel. إذا كانت bytesToWrite سالبة، تتوقع Tcl_Writechars أن يكون charbuf مختتمًا بحرف NULL وتقوم بإخراج كل شيء حتى حرف NULL.

قد لا تظهر البيانات المدرجة في قائمة الانتظار للإخراج على جهاز الإخراج على الفور، نظرًا للتخزين المؤقت الداخلي. إذا كان ينبغي أن تظهر البيانات على الفور، استدعِ Tcl_Flush بعد استدعاء Tcl_Writechars، أو قم بتعيين خيار -buffering على القناة إلى none. إذا كنت ترغب في ظهور البيانات فور قبول سطر كامل للإخراج، قم بتعيين خيار -buffering على القناة إلى وضع line.

قيمة الإرجاع لـ Tcl_Writechars هي عدد البايتات التي تم قبولها للإخراج إلى القناة. تكون إما أكبر من الصفر للإشارة إلى النجاح أو -1 للإشارة إلى حدوث خطأ. في حالة حدوث خطأ، تسجل Tcl_Writechars رمز خطأ POSIX يمكن استرداده باستخدام Tcl_Geterrno.

تتم ترجمة أحرف السطر الجديد في بيانات الإخراج إلى تسلسلات نهاية سطر خاصة بالمنصة وفقًا للخيار -translation للقناة. يتم ذلك حتى لو كانت القناة ليس لها ترميز.

Tcl_Writeobj مشابه لـ Tcl_Writechars باستثناء أنها تقبل قيمة Tcl التي سيتم إخراج محتوياتها إلى القناة. يتم تحويل أحرف UTF-8 في تمثيل السلسلة الخاص بـ writeobjptr إلى ترميز القناة وإدراجها في قائمة انتظار للإخراج إلى channel. كتحسين للأداء، عند الكتابة إلى قناة ذات ترميز binary، لا يتم تحويل أحرف UTF-8 أثناء كتابتها. بدلاً من ذلك، يتم كتابة البايتات في التمثيل الداخلي لـ writeobjptr كقيمة مصفوفة بايتات إلى القناة. سيتم إنشاء تمثيل مصفوفة البايتات للقيمة إذا لزم الأمر. بهذه الطريقة، يمكن قراءة البيانات الموجهة بالبايت من قناة، ومعالجتها عن طريق استدعاء Tcl_Getbytearrayfromobj والوظائف ذات الصلة، ثم كتابتها إلى قناة دون تكلفة التحويل من أو إلى UTF-8.

Tcl_Write مشابه لـ Tcl_Writechars باستثناء أنها لا تقوم بتحويلات الترميز، بغض النظر عن ترميز القناة. تم إيقاف استخدامها وتوجد للتوافق مع الإصدارات السابقة مع امتدادات Tcl غير الدولية. تقبل عدد bytesToWrite من بايتات البيانات في bytebuf وتضعها في قائمة انتظار للإخراج إلى channel. إذا كانت bytesToWrite سالبة، تتوقع Tcl_Write أن يكون bytebuf مختتمًا بحرف NULL وتقوم بإخراج كل شيء حتى حرف NULL.

Tcl_Writeraw مماثلة لـ Tcl_Write ولكنها لا تعوض عن التراص. بينما تقوم Tcl_Write (والوظائف الأخرى في واجهة برمجة التطبيقات) دائمًا بتغذية مدخلاتها إلى أعلى قناة في المكدس الذي تنتمي إليه القناة، فإن Tcl_Writeraw لا تفعل ذلك. وبالتالي، لا يمكن استخدام هذه الوظيفة إلا لدوافع القنوات التحويلية، أي الدوافع المستخدمة في منتصف مكدس القنوات، لنقل البيانات من التحويل إلى القناة التي تحتها.

TCL_FLUSH

تتسبب Tcl_Flush في كتابة جميع بيانات الإخراج المخزنة مؤقتًا لـ channel إلى ملفها الأساسي أو جهازها في أقرب وقت ممكن. إذا كانت القناة في وضع الحظر، لا تعود المكالمة حتى يتم إرسال جميع البيانات المخزنة مؤقتًا إلى القناة أو حدوث خطأ ما. تعود المكالمة فورًا إذا كانت القناة غير حاظرة؛ تبدأ عملية دفع في الخلفية ستكتب البيانات المخزنة مؤقتًا إلى القناة في النهاية، بأسرع ما يمكن للقناة استيعابها.

قيمة الإرجاع هي عادةً TCL_OK. في حالة حدوث خطأ، تعيد Tcl_Flush القيمة TCL_ERROR وتسجل رمز خطأ POSIX يمكن استرداده باستخدام Tcl_Geterrno.

TCL_SEEK

تنقل Tcl_Seek نقطة الوصول في channel حيث سيتم قراءة أو كتابة البيانات اللاحقة. يتم دفع الإخراج المخزن مؤقتًا إلى القناة ويتم تجاهل الإدخال المخزن مؤقتًا، قبل عملية البحث. Tcl_Seek تعيد عادةً نقطة الوصول الجديدة. في حالة حدوث خطأ، تعيد Tcl_Seek القيمة -1 وتسجل رمز خطأ POSIX يمكن استرداده باستخدام Tcl_Geterrno. بعد حدوث خطأ، قد تكون نقطة الوصول قد تم نقلها أو لم يتم نقلها.

TCL_TELL

تعيد Tcl_Tell نقطة الوصول الحالية لقناة. القيمة المرجعة هي -1 إذا كانت القناة لا تدعم البحث.

TCL_TRUNCATECHANNEL

تقوم Tcl_TruncateChannel بتقصير الملف الأساسي للقناة channel إلى طول معين يبلغ length من البايتات. تعيد TCL_OK إذا نجحت العملية، و TCL_ERROR بخلاف ذلك.

TCL_GETCHANNELOPTION

تقوم Tcl_Getchanneloption باسترداد، في optionvalue، قيمة أحد الخيارات السارية حاليًا لقناة، أو قائمة بجميع الخيارات وقيمها. يحدد الوسيط channel القناة التي سيتم الاستعلام عن خيارها أو استرداد جميع الخيارات وقيمها. إذا لم يكن optionname NULL، فهو اسم الخيار المراد الاستعلام عنه؛ يتم نسخ قيمة الخيار إلى السلسلة الديناميكية Tcl المشار إليها بواسطة optionvalue. إذا كان optionname NULL، تخزن الدالة قائمة متناوبة من أسماء الخيارات وقيمها في optionvalue، باستخدام

TCL_GETCHANNELOPTION

Tcl_GetChannelOption returns the current value for an option optionName on channel. The value is returned as a Tcl object in valuePtr. If the option is not supported by the channel driver, Tcl_GetChannelOption returns TCL_ERROR and leaves an error message in the interpreter's result if interp is non-NULL. Otherwise, it returns TCL_OK.

The existing options and their possible values are described in the manual entry for the Tcl fconfigure command. Other options may be added by each channel type. These channel type specific options are described in the manual entry for the Tcl command that creates a channel of that type; for example, the additional options for TCP-based channels are described in the manual entry for the Tcl socket command.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption sets a new value newValue for an option optionName on channel. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR; in addition, if interp is non-NULL, Tcl_SetChannelOption leaves an error message in the interpreter's result.

TCL_EOF

Tcl_Eof returns a nonzero value if channel encountered an end of file during the last input operation.

TCL_INPUTBLOCKED

Tcl_InputBlocked returns a nonzero value if channel is in nonblocking mode and the last input operation returned less data than requested because there was insufficient data available. The call always returns zero if the channel is in blocking mode.

TCL_INPUTBUFFERED

Tcl_InputBuffered returns the number of bytes of input currently buffered in the internal buffers for a channel. If the channel is not open for reading, this function always returns zero.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered returns the number of bytes of output currently buffered in the internal buffers for a channel. If the channel is not open for writing, this function always returns zero.

PLATFORM ISSUES

The handles returned from Tcl_GetChannelHandle depend on the platform and the channel type. On Unix platforms, the handle is always a Unix file descriptor as returned from the open system call. On Windows platforms, the handle is a file HANDLE when the channel was created with Tcl_OpenFileChannel, Tcl_OpenCommandChannel, or Tcl_MakeFileChannel. Other channel types may return a different type of handle on Windows platforms.
