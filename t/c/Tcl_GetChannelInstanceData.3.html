الوصف

تستخدم Tcl بنية قناة من طبقتين. توفر طبقة عليا عامة لتمكين برامج C و Tcl من إجراء عمليات الإدخال والإخراج باستخدام نفس واجهات برمجة التطبيقات لمجموعة متنوعة من الملفات والأجهزة والمقابس وما إلى ذلك. يتم وصف واجهات برمجة تطبيقات C العامة في إدخال الدليل لـ Tcl_OpenFileChannel.

توفر الطبقة السفلية برامج تشغيل قنوات محددة النوع لكل نوع جهاز مدعوم على كل منصة. يصف إدخال الدليل هذا واجهات برمجة تطبيقات C المستخدمة للتواصل بين الطبقة العامة وبرامج تشغيل القنوات المحددة النوع. كما يشرح كيفية إضافة أنواع قنوات جديدة عن طريق توفير برامج تشغيل قنوات جديدة.

تتكون برامج تشغيل القنوات من عدد من المكونات: أولاً، يوفر كل برنامج تشغيل قناة بنية Tcl_ChannelType تحتوي على مؤشرات إلى الإجراءات التي تنفذ العمليات المختلفة التي تستخدمها الطبقة العامة للتواصل مع برنامج تشغيل القناة. يتم وصف بنية Tcl_ChannelType والإجراءات المشار إليها بها في قسم TCL_CHANNELTYPE، أدناه.

ثانياً، توفر برامج تشغيل القنوات عادةً أمر Tcl لإنشاء مثيلات من هذا النوع من القنوات. على سبيل المثال، ينشئ أمر Tcl open قنوات تستخدم برامج تشغيل القنوات والملفات، وينشئ أمر Tcl socket قنوات تستخدم مقابس TCP للاتصال الشبكي.

ثالثاً، يوفر برنامج تشغيل القناة اختيارياً إجراء C لفتح مثيلات قنوات من هذا النوع. على سبيل المثال، يفتح Tcl_OpenFileChannel قناة تستخدم برنامج تشغيل القناة، ويفتح Tcl_OpenTcpClient قناة تستخدم بروتوكول شبكة TCP. تستخدم دوال الإنشاء هذه عادةً Tcl_CreateChannel داخليًا لفتح القناة.

لإضافة نوع قناة جديد، يجب عليك تنفيذ واجهة برمجة تطبيقات C أو أمر Tcl يفتح قناة عن طريق استدعاء Tcl_CreateChannel. عند استدعاء برنامج التشغيل الخاص بك لـ Tcl_CreateChannel، فإنه يمرر بنية Tcl_ChannelType تصف إجراءات الإدخال/الإخراج الخاصة ببرنامج التشغيل. ستقوم الطبقة العامة بعد ذلك باستدعاء الإجراءات المشار إليها في تلك البنية لإجراء عمليات على القناة.

Tcl_CreateChannel يفتح قناة جديدة ويربط typePtr و instanceData المقدمين بها. يتم فتح القناة في الوضع المحدد بواسطة mask. لمناقشة برامج تشغيل القنوات، وعملياتها، وبنية Tcl_ChannelType، راجع قسم TCL_CHANNELTYPE، أدناه.

Tcl_CreateChannel يتفاعل مع الكود الذي يدير القنوات القياسية. بمجرد تهيئة قناة قياسية إما من خلال استدعاء لـ Tcl_GetStdChannel أو استدعاء لـ Tcl_SetStdChannel، فإن إغلاق هذه القناة القياسية سيؤدي إلى أن الاستدعاء التالي لـ Tcl_CreateChannel سيجعل القناة الجديدة هي القناة القياسية الجديدة أيضًا. راجع Tcl_StandardChannels لمعالجة عامة حول القنوات القياسية وسلوك مكتبة Tcl فيما يتعلق بها.

Tcl_GetChannelInstanceData يعيد البيانات المثيل المرتبطة بالقناة في channel. هذا هو نفس الوسيط instanceData في استدعاء Tcl_CreateChannel الذي أنشأ هذه القناة.

Tcl_GetChannelType يعيد مؤشراً إلى بنية Tcl_ChannelType المستخدمة بواسطة القناة في الوسيط channel. هذا هو نفس الوسيط typePtr في استدعاء Tcl_CreateChannel الذي أنشأ هذه القناة.

Tcl_GetChannelName يعيد سلسلة نصية تحتوي على الاسم المرتبط بالقناة، أو NULL إذا كان الوسيط channelName لـ Tcl_CreateChannel هو NULL.

Tcl_GetChannelHandle يضع مقبض الجهاز الخاص بنظام التشغيل المرتبط بـ channel للاتجاه direction المحدد في t

TCL_GETCHANNELHANDLE

Tcl_GetChannelHandle returns the low-level handle for the specified channel and direction. The handle is specified by handlePtr and returns TCL_OK. If the channel does not have a device handle for the specified direction, then TCL_ERROR is returned instead. Different channel drivers will return different types of handle. Refer to the manual entries for each driver to determine what type of handle is returned.

Tcl_GetChannelThread returns the id of the thread currently managing the specified channel. This allows channel drivers to send their file events to the correct event queue even for a multi-threaded core.

Tcl_GetChannelMode returns an OR-ed combination of TCL_READABLE and TCL_WRITABLE, indicating whether the channel is open for input and output.

Tcl_GetChannelBufferSize returns the size, in bytes, of buffers allocated to store input or output in channel. If the value was not set by a previous call to Tcl_SetChannelBufferSize, described below, then the default value of 4096 is returned.

Tcl_SetChannelBufferSize sets the size, in bytes, of buffers that will be allocated in subsequent operations on the channel to store input or output. The size argument should be between one and one million, allowing buffers of one byte to one million bytes. If size is outside this range, Tcl_SetChannelBufferSize sets the buffer size to 4096.

Tcl_NotifyChannel is called by a channel driver to indicate to the generic layer that the events specified by mask have occurred on the channel. Channel drivers are responsible for invoking this function whenever the channel handlers need to be called for the channel (or other pending tasks like a write flush should be performed). See WATCHPROC below for more details.

Tcl_BadChannelOption is called from driver specific setOptionProc or getOptionProc to generate a complete error message.

Tcl_ChannelBuffered returns the number of bytes of input currently buffered in the internal buffer (push back area) of the channel itself. It does not report about the data in the overall buffers for the stack of channels the supplied channel is part of.

Tcl_IsChannelShared checks the refcount of the specified channel and returns whether the channel was shared among multiple interpreters (result == 1) or not (result == 0).

Tcl_IsChannelRegistered checks whether the specified channel is registered in the given interpreter (result == 1) or not (result == 0).

Tcl_IsChannelExisting checks whether a channel with the specified name is registered in the (thread)-global list of all channels (result == 1) or not (result == 0).

Tcl_CutChannel removes the specified channel from the (thread)global list of all channels (of the current thread). Application to a channel still registered in some interpreter is not allowed. Also notifies the driver if the Tcl_ChannelType version is TCL_CHANNEL_VERSION_4 (or higher), and Tcl_DriverThreadActionProc is defined for it.

Tcl_SpliceChannel adds the specified channel to the (thread)global list of all channels (of the current thread). Application to a channel registered in some interpreter is not allowed. Also notifies the driver if the Tcl_ChannelType version is TCL_CHANNEL_VERSION_4 (or higher), and Tcl_DriverThreadActionProc is defined for it.

Tcl_ClearChannelHandlers removes all channel handlers and event scripts associated with the specified channel, thus shutting down all event processing for this channel.

TCL_CHANNELTYPE

A channel driver provides a Tcl_ChannelType structure that contains pointers to functions that implement the various operations on a channel; these operations are invoked as needed by the generic layer. The structure was versioned starting in Tcl 8.3.2/8.4 to correct a problem with stacked channel drivers. See the OLD CHANNEL TYPES section below for details about the old structure.

The Tcl_ChannelType structure contains the following fields:

typedef struct Tcl_ChannelType {
        const char *typeName;
        Tcl_ChannelTypeVersion version;
        Tcl_DriverCloseProc *closeProc;
        Tcl_DriverInputProc *inputProc;
        Tcl_DriverOutputProc *outputProc;
        Tcl_DriverSeekProc *seekProc;
        Tcl_DriverSetOptionProc *setOptionProc;
        Tcl_DriverGetOptionProc *getOptionProc;
        Tcl_DriverWatchProc *watchProc;
        Tcl_DriverGetHandleProc *getHandleProc;
        Tcl_DriverClose2Proc *close2Proc;
        Tcl_DriverBlockModeProc *blockModeProc;
        Tcl_DriverFlushProc *flushProc;
        Tcl_DriverHandlerProc *handlerProc;
        Tcl_DriverWideSeekProc *wideSeekProc;
        Tcl_DriverThreadActionProc *threadActionProc;
        Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

It is not necessary to provide implementations for all channel operations. Those which are not necessary may be set to NULL in the struct: blockModeProc, seekProc, setOptionProc, getOptionProc, getHandleProc, and close2Proc, in addition to flushProc, handlerProc, threadActionProc, and truncateProc. Other functions that cannot be implemented in a meaningful way should return EINVAL when called, to indicate that the operations they represent are not available. Also note that wideSeekProc can be NULL if seekProc is.

The user should only use the above structure for Tcl_ChannelType instantiation. When referencing fields in a Tcl_ChannelType structure, the following functions should be used to obtain the values: Tcl_ChannelName, Tcl_ChannelVersion, Tcl_ChannelBlockModeProc, Tcl_ChannelCloseProc, Tcl_ChannelClose2Proc, Tcl_ChannelInputProc, Tcl_ChannelOutputProc, Tcl_ChannelSeekProc, Tcl_ChannelWideSeekProc, Tcl_ChannelThreadActionProc, Tcl_ChannelTruncateProc, Tcl_ChannelSetOptionProc, Tcl_ChannelGetOptionProc, Tcl_ChannelWatchProc, Tcl_ChannelGetHandleProc, Tcl_ChannelFlushProc, or Tcl_ChannelHandlerProc.

The change to the structures was made in such a way that standard channel types are binary compatible. However, channel types that use stacked channels (i.e. TLS, Trf) have new versions to correspond to the above change since the previous code for stacked channels had problems.

TYPENAME

The typeName field contains a null-terminated string that identifies the type of the device implemented by this driver, e.g. file or socket.

This value can be retrieved with Tcl_ChannelName, which returns a pointer to the string.

VERSION

The version field should be set to the version of the structure that you require. TCL_CHANNEL_VERSION_2 is the minimum recommended. TCL_CHANNEL_VERSION_3 must be set to specify the wideSeekProc member. TCL_CHANNEL_VERSION_4 must be set to specify the threadActionProc member (includes wideSeekProc). TCL_CHANNEL_VERSION_5 must be set to specify the truncateProc members (includes wideSeekProc and threadActionProc). If it is not set to any of these, then this Tcl_ChannelType is assumed to have the original structure. See OLD CHANNEL TYPES for more details. While Tcl will recognize and function with either structures, stacked channels must be of at least TCL_CHANNEL_VERSION_2 to function correctly.

This value can be retrieved with Tcl_ChannelVersion, which returns one of TCL_CHANNEL_VERSION_5, TCL_CHANNEL_VERSION_4, TCL_CHANNEL_VERSION_3, TCL_CHANNEL_VERSION_2 or TCL_CHANNEL_VERSION_1.

BLOCKMODEPROC

The blockModeProc field contains the address of a function called by the generic layer to set blocking and nonblocking mode on the device. BlockModeProc should match the following prototype:

typedef int Tcl_DriverBlockModeProc(
        ClientData instanceData,
        int mode);

The instanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The mode argument is either TCL_MODE_BLOCKING or TCL_MODE_NONBLOCKING to set the device into blocking or nonblocking mode. The function should return zero if the operation was successful, or a nonzero POSIX error code if the operation failed.

If the operation is successful, the function can modify the supplied instanceData to record that the channel entered blocking or nonblocking mode and to implement the blocking or nonblocking behavior. For some device types, the blocking and nonblocking behavior can be implemented by the underlying operating system; for other device types, the behavior must be emulated in the channel driver.

This value can be retrieved with Tcl_ChannelBlockModeProc, which returns a pointer to the function.

A channel driver not supplying a blockModeProc has to be very, very careful. It has to tell the generic layer exactly which blocking mode is acceptable to it, and should this also document for the user so that the blocking mode of the channel is not changed to an unacceptable value. Any confusion here may lead the interpreter into a (spurious and difficult to find) deadlock.

INPUTPROC

يحتوي الحقل inputProc على عنوان دالة يتم استدعاؤها بواسطة الطبقة العامة لقراءة البيانات من الجهاز أو الملف وتخزينها في مخزن مؤقت داخلي. يجب أن يتوافق InputProc مع البروتوكول التالي:

typedef int Tcl_DriverInputProc(
        ClientData instanceData,
        char *buf,
        int bufSize,
        int *errorCodePtr);

InstanceData هو نفس القيمة التي تم تمريرها إلى Tcl_CreateChannel عند إنشاء القناة. يشير الوسيط buf إلى مصفوفة بايت سيتم تخزين بيانات الإدخال من الجهاز فيها، ويشير الوسيط bufSize إلى عدد البايتات المتاحة في buf.

يشير الوسيط errorCodePtr إلى متغير عدد صحيح توفره الطبقة العامة. إذا حدث خطأ، يجب على الدالة تعيين هذا المتغير إلى رمز خطأ POSIX يحدد الخطأ.

يجب على الدالة قراءة البيانات من الجهاز المغلف بواسطة القناة وتخزينها في buf. في حالة النجاح، يجب أن تُرجع عددًا صحيحًا غير سالب يشير إلى عدد البايتات التي تم قراءتها من الجهاز وتخزينها في buf. في حالة حدوث خطأ، يجب أن تُرجع -1. إذا حدث خطأ بعد قراءة أي بيانات من الجهاز، فسيتم فقدان تلك البيانات.

إذا كان بإمكان inputProc تحديد أن الجهاز لديه بيانات متاحة ولكن أقل من المطلوب بواسطة الوسيط bufSize، فيجب على الدالة محاولة قراءة المتاح فقط وإرجاعها دون حظر. إذا لم يكن هناك بيانات متاحة وأن القناة في وضع عدم الحظر، فيجب على الدالة إرجاع خطأ EAGAIN. إذا لم يكن هناك بيانات متاحة وأن القناة في وضع الحظر، فيجب على الدالة الحظر لأقصر فترة ممكنة حتى يمكن قراءة بايت واحد على الأقل من الجهاز، ثم إرجاع جميع البيانات التي يمكن قراءتها دون حظر.

يمكن استرداد هذه القيمة باستخدام Tcl_ChannelInputProc، والتي تُرجع عنوان الدالة.

OUTPUTPROC

يحتوي الحقل outputProc على عنوان دالة يتم استدعاؤها بواسطة الطبقة العامة لنقل البيانات من المخزن المؤقت الداخلي إلى جهاز الإخراج. يجب أن يتوافق OutputProc مع البروتوكول التالي:

typedef int Tcl_DriverOutputProc(
        ClientData instanceData,
        const char *buf,
        int toWrite,
        int *errorCodePtr);

InstanceData هو نفس القيمة التي تم تمريرها إلى Tcl_CreateChannel عند إنشاء القناة. يحتوي الوسيط buf على مصفوفة بايت سيتم كتابتها إلى الجهاز، ويشير الوسيط toWrite إلى عدد البايتات التي سيتم كتابتها من الوسيط buf.

يشير الوسيط errorCodePtr إلى متغير عدد صحيح توفره الطبقة العامة لإرجاع قيم errno للدالة. يجب على الدالة تعيين هذا المتغير إلى رمز خطأ POSIX إذا حدث خطأ. إذا لم يقم نوع القناة بتنفيذ التقدم في الموضع، فيجب على الدالة تعيين رمز الخطأ EINVAL.

يجب على الدالة كتابة البيانات في buf إلى جهاز الإخراج المغلف بواسطة القناة. في حالة النجاح، يجب أن تُرجع عددًا صحيحًا غير سالب يشير إلى عدد البايتات التي تم كتابتها إلى جهاز الإخراج. عادةً ما تكون القيمة المرجعة هي نفسها toWrite، ولكنها قد تكون أقل في بعض الحالات مثل عندما يتم مقاطعة عملية الإخراج بإشارة. إذا حدث خطأ، يجب أن تُرجع الدالة -1. في حالة حدوث خطأ، قد تكون بعض البيانات قد تم كتابتها إلى الجهاز.

إذا كانت القناة في وضع عدم الحظر ولا يمكن لجهاز الإخراج استيعاب أي بيانات، فيجب على الدالة إرجاع -1 مع خطأ EAGAIN دون كتابة أي بيانات.

يمكن استرداد هذه القيمة باستخدام Tcl_ChannelOutputProc، والتي تُرجع عنوان الدالة.

SEEKPROC AND WIDESEEKPROC

يحتوي الحقل seekProc على عنوان دالة يتم استدعاؤها بواسطة الطبقة العامة لنقل نقطة الوصول التي سيتم تطبيق عمليات الإدخال أو الإخراج اللاحقة عليها. يجب أن يتوافق SeekProc مع البروتوكول التالي:

typedef int Tcl_DriverSeekProc(
        ClientData instanceData,
        long offset,
        int seekMode,
        int *errorCodePtr);

الوسيط instanceData هو نفس القيمة التي تم إعطاؤها لـ Tcl_CreateChannel عند إنشاء هذه القناة. Offset و seekMode لهما نفس المعنى كما في الدالة Tcl_Seek (المذكورة في دليل Tcl_OpenFileChannel).

يشير الوسيط errorCodePtr إلى متغير عدد صحيح توفره الطبقة العامة لإرجاع قيم errno للدالة. يجب على الدالة تعيين هذا المتغير إلى رمز خطأ POSIX إذا حدث خطأ. إذا لم يقم نوع القناة بتنفيذ التقدم في الموضع، فيجب على الدالة تعيين رمز الخطأ EINVAL.

القيمة المرجعة هي نقطة الوصول الجديدة أو -1 في حالة حدوث خطأ. في حالة حدوث خطأ، يجب ألا تنقل الدالة نقطة الوصول.

إذا كان هناك seekProc غير فارغ، فقد يحتوي الحقل wideSeekProc على عنوان دالة بديلة تعالج إزاحات الموضع (أي أكبر من 32 بت)، مما يسمح بالتقدم في الملفات الأكبر من 2 جيجابايت. يتم استدعاء الدالة wideSeekProc تفضيليًا على seekProc، ولكن يجب تعريف كليهما إذا تم تعريف wideSeekProc. يجب أن يتوافق WideSeekProc مع البروتوكول التالي:

typedef Tcl_WideInt Tcl_DriverWideSeekProc(
        ClientData instanceData,
        Tcl_WideInt offset,
        int seekMode,
        int *errorCodePtr);

الوسطاء والقيم المرجعة هي نفسها كما في seekProc، باستثناء أن نوع الإزاحة ونوع الإرجاع مختلفان.

يمكن استرداد الحقل seekProc باستخدام Tcl_ChannelSeekProc، والتي تُرجع عنوان الدالة، ويمكن استرداد الحقل wideSeekProc باستخدام Tcl_ChannelWideSeekProc.

SETOPTIONPROC

يحتوي الحقل setOptionProc على عنوان دالة يتم استدعاؤها بواسطة الطبقة العامة لتعيين خيار محدد لنوع القناة في قناة. يجب أن يتوافق setOptionProc مع البروتوكول التالي:

typedef int Tcl_DriverSetOptionProc(
        ClientData instanceData,
        Tcl_Interp *interp,
        const char *optionName,
        const char *newValue);

optionName هو اسم خيار ليتم تعيينه، و newValue هو القيمة الجديدة لهذا الخيار، كسلسلة نصية. instanceData هو نفس القيمة التي تم إعطاؤها لـ Tcl_CreateChannel عند إنشاء هذه القناة. يجب على الدالة تنفيذ الإجراء المحدد لتطبيق القيمة الجديدة للخيار.

يتم التعامل مع بعض الخيارات بواسطة الكود العام ولا يتم استدعاء هذه الدالة أبدًا لتعيينها، على سبيل المثال -blockmode. يتم التعامل مع الخيارات الأخرى بشكل فردي لكل نوع قناة ويتم استدعاء دالة setOptionProc الخاصة ببرنامج تشغيل القناة لتنفيذها. قد يكون الحقل setOptionProc فارغًا، مما يشير إلى أن نوع القناة هذا لا يدعم خيارات محددة.

إذا تم تعديل قيمة الخيار بنجاح إلى القيمة الجديدة، تُرجع الدالة TCL_OK. يجب عليها استدعاء Tcl_BadChannelOption، والتي تُرجع TCL_ERROR إذا لم يتم التعرف على optionName. إذا حدد newValue قيمة غير مدعومة أو إذا حدث خطأ في استدعاء نظام، فيجب على الدالة تخزين رسالة خطأ في نتيجة interp إذا لم يكن interp فارغًا. يجب على الدالة أيضًا استدعاء Tcl_SetErrno لتخزين رمز خطأ POSIX مناسب.

يمكن استرداد هذه القيمة باستخدام Tcl_ChannelSetOptionProc، والتي تُرجع عنوان الدالة.

GETOPTIONPROC

يحتوي الحقل getOptionProc على عنوان دالة يتم استدعاؤها بواسطة الطبقة العامة للحصول على قيمة خيار محدد لنوع القناة في قناة. يجب أن يتوافق getOptionProc مع البروتوكول التالي:

typedef int Tcl_DriverGetOptionProc(
        ClientData instanceData,
        Tcl_Interp *interp,
        const char *optionName,
        Tcl_DString *optionValue);

optionName هو اسم خيار مدعوم من قبل هذا النوع من القنوات. إذا لم يكن اسم الخيار فارغًا، فستقوم الدالة بتخزين قيمته الحالية، كسلسلة نصية، في سلسلة Tcl الديناميكية optionValue. إذا كان optionName فارغًا، فستقوم الدالة بتخزين قائمة بديلة بجميع الخيارات المدعومة وقيمها الحالية في optionValue. في حالة النجاح، تُرجع الدالة TCL_OK. يجب عليها استدعاء Tcl_BadChannelOption، والتي تُرجع TCL_ERROR إذا لم يتم التعرف على optionName. إذا حدد newValue قيمة غير مدعومة أو إذا حدث خطأ في استدعاء نظام، فيجب على الدالة تخزين رسالة خطأ في نتيجة interp إذا لم يكن interp فارغًا. يجب على الدالة أيضًا استدعاء Tcl_SetErrno لتخزين رمز خطأ POSIX مناسب.

يمكن استرداد هذه القيمة باستخدام Tcl_ChannelGetOptionProc، والتي تُرجع عنوان الدالة.

WATCHPROC

يحتوي الحقل watchProc على عنوان دالة تستدعيها الطبقة العامة لتهيئة آلية الإخطار بالأحداث ذات الأهمية في هذه القناة. يجب أن يتطابق WatchProc مع النموذج الأولي التالي:

typedef void Tcl_DriverWatchProc(
        ClientData instanceData,
        int mask);

instanceData هو نفس القيمة التي تم تمريرها إلى Tcl_CreateChannel عند إنشاء هذه القناة. mask هو مزيج OR من TCL_READABLE و TCL_WRITABLE و TCL_EXCEPTION؛ وهو يشير إلى الأحداث التي يهتم المستخدم بالإبلاغ عنها في هذه القناة.

يجب أن تقوم الدالة بتهيئة آليات خاصة بنوع الجهاز للإبلاغ عند وجود حدث ذي أهمية في القناة. عندما يحدث حدث ذي أهمية في القناة، يجب على المشغل استدعاء Tcl_NotifyChannel لإبلاغ وحدة القناة العامة. يجب على المشغل تجنب تشغيل Tcl_NotifyChannel بشكل متكرر جدًا، مما قد يؤدي إلى حظر مشغلات القناة الأخرى أو مصادر الاستدعاءات. يمكن ضمان العدالة باستخدام قائمة انتظار الأحداث في Tcl لجدولة حدث القناة بالتتابع مع الأحداث الأخرى. راجع وصف Tcl_QueueEvent للحصول على تفاصيل حول جدولة حدث.

يمكن استرداد هذه القيمة باستخدام Tcl_ChannelWatchProc، والتي تُرجع مؤشرًا إلى الدالة.

GETHANDLEPROC

يحتوي الحقل getHandleProc على عنوان دالة تستدعيها الطبقة العامة لاسترداد مقبض خاص بالقناة. يجب أن يتطابق GetHandleProc مع النموذج الأولي التالي:

typedef int Tcl_DriverGetHandleProc(
        ClientData instanceData,
        int direction,
        ClientData *handlePtr);

instanceData هو نفس القيمة التي تم تمريرها إلى Tcl_CreateChannel عند إنشاء هذه القناة. direction هو إما TCL_READABLE لاسترداد المقبض المستخدم للإدخال، أو TCL_WRITABLE لاسترداد المقبض المستخدم للإخراج.

إذا كان لتطبيق القناة مقبضات محددة، فيجب على الدالة استرداد المقبض المناسب وفقًا للوسيط direction. يجب تخزين المقبض في الموقع المشار إليه بواسطة handlePtr، ويجب إرجاع TCL_OK. إذا لم تكن القناة مفتوحة للاتجاه المحدد أو إذا كان تطبيق القناة لا يستخدم مقبضات محددة، فيجب على الدالة إرجاع TCL_ERROR.

يمكن استرداد هذه القيمة باستخدام Tcl_ChannelGetHandleProc، والتي تُرجع مؤشرًا إلى الدالة.

FLUSHPROC

الحقل flushProc محجوز حاليًا للاستخدامات المستقبلية. يجب تعيينه إلى NULL. يجب أن يتطابق FlushProc مع النموذج الأولي التالي:

typedef int Tcl_DriverFlushProc(
        ClientData instanceData);

يمكن استرداد هذه القيمة باستخدام Tcl_ChannelFlushProc، والتي تُرجع مؤشرًا إلى الدالة.

HANDLERPROC

يحتوي الحقل handlerProc على عنوان دالة تستدعيها الطبقة العامة لإبلاغ القناة بحدوث حدث. يجب تعريفه لمشغلات القنوات المكدسة التي ترغب في تلقي إشعارات بالأحداث التي تحدث في القناة الأساسية (القناة المكدسة). يجب أن يتطابق HandlerProc مع النموذج الأولي التالي:

typedef int Tcl_DriverHandlerProc(
        ClientData instanceData,
        int interestMask);

instanceData هو نفس القيمة التي تم تمريرها إلى Tcl_CreateChannel عند إنشاء هذه القناة. interestMask هو مزيج OR من TCL_READABLE أو TCL_WRITABLE؛ وهو يشير إلى نوع الحدث الذي حدث في هذه القناة.

يمكن استرداد هذه القيمة باستخدام Tcl_ChannelHandlerProc، والتي تُرجع مؤشرًا إلى الدالة.

THREADACTIONPROC

يحتوي الحقل threadActionProc على عنوان الدالة التي تستدعيها الطبقة العامة عند إنشاء قناة، أو إغلاقها، أو نقلها إلى مؤشر ترابط مختلف، أي عند الحاجة إلى تهيئة أو تحديث حالة مؤشر الترابط الخاصة بالمشغل. قد يكون NULL. يتم استخدام الإجراء TCL_CHANNEL_THREAD_REMOVE لإبلاغ المشغل بأنه يجب عليه تحديث أو إزالة أي بيانات خاصة بمؤشر الترابط قد يحتفظ بها للقناة.

يتم استخدام الإجراء TCL_CHANNEL_THREAD_INSERT لإبلاغ المشغل بأنه يجب عليه تحديث أو تهيئة أي بيانات خاصة بمؤشر الترابط قد يحتفظ بها باستخدام مؤشر الترابط المستدعي كمرتبط. راجع Tcl_CutChannel و Tcl_SpliceChannel لمزيد من التفاصيل.

typedef void Tcl_DriverThreadActionProc(
        ClientData instanceData,
        int action);

instanceData هو نفس القيمة التي تم تمريرها إلى Tcl_CreateChannel عند إنشاء هذه القناة.

يمكن استرداد هذه القيم باستخدام Tcl_ChannelThreadActionProc، والتي تُرجع مؤشرًا إلى الدالة.

TRUNCATEPROC

يحتوي الحقل truncateProc على عنوان الدالة التي تستدعيها الطبقة العامة عند اقتطاع قناة إلى طول معين. قد يكون NULL.

typedef int Tcl_DriverTruncateProc(
        ClientData instanceData,
        Tcl_WideInt length);

instanceData هو نفس القيمة التي تم تمريرها إلى Tcl_CreateChannel عند إنشاء هذه القناة، و length هو الطول الجديد للملف الأساسي، والذي يجب ألا يكون سالبًا. يجب أن تكون النتيجة 0 في حالة النجاح أو رمز خطأ (مناسب للاستخدام مع Tcl_SetErrno) في حالة الفشل.

يمكن استرداد هذه القيم باستخدام Tcl_ChannelTruncateProc، والتي تُرجع مؤشرًا إلى الدالة.

TCL_BADCHANNELOPTION

ينشئ هذا الإجراء رسالة خطأ "خيار سيء" في مترجم (اختياري). تستخدمه مشغلات القنوات عند طلب خيار غير صالح. هدفه هو دمج قائمة الخيارات العامة مع القائمة المحددة وتشكيل رسالة خطأ الخيارات العامة.

يعيد دائمًا TCL_ERROR.

يتم إنشاء رسالة خطأ في قيمة نتيجة interp للإشارة إلى أنه تم استدعاء أمر بخيار غير صالح. يكون تنسيق الرسالة:

    bad option "blah": should be one of
    <...generic options...>+<...specific options...>
وبالتالي، يتم الحصول على، على سبيل المثال: 
    bad option "-blah": should be one of -blocking,
    -buffering, -buffersize, -eofchar, -translation,
    -peername, or -sockname
عند الاستدعاء مع optionList مساوٍ لـ "peername sockname".

"blah" هو الوسيط optionName و "<specific options>" هي قائمة بكلمات محددة مفصولة بمسافات. تتولى الدالة مهمة إدراج شرطات (-) قبل كل خيار، وفاصلات (,) بعده، و "or" قبل الخيار الأخير.

OLD CHANNEL TYPES

يحتوي الهيكل الأصلي (Tcl_ChannelType لـ 8.3.1 والإصدارات الأقدم) على الحقول التالية:

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverClose2Proc *close2Proc;
} Tcl_ChannelType;

من الممكن إنشاء قناة باستخدام الهيكل المذكور أعلاه. سيحدد الكود الداخلي للقناة الإصدار. من الضروري استخدام الهيكل الجديد Tcl_ChannelType إذا تم إنشاء مشغل قنوات مكدسة، نظرًا للمشكلات الموجودة في التنفيذ السابق للقنوات المكدسة (8.2.0 إلى 8.3.1).

قبل 8.4.0 (أي، خلال الإصدارات الأحدث من 8.3 وجزء مبكر من دورة تطوير 8.4)، احتوى الهيكل Tcl_ChannelType على الحقول التالية:

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_ChannelTypeVersion version;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverClose2Proc *close2Proc;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverFlushProc *flushProc;
    Tcl_DriverHandlerProc *handlerProc;
    Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

عند تسجيل الهيكل السابق كنوع قناة، يجب أن يكون الحقل version دائمًا TCL_CHANNEL_VERSION_2.

DESCRIPTION

The Tcl channel driver interface is a core part of Tcl input/output operations. It allows Tcl to interact with various I/O devices and protocols through a unified interface. The functions described here provide the building blocks for creating and managing these channels.

The channel driver interface is composed of several key concepts:

CHANNEL
A channel represents a connection to an I/O device or resource. Tcl provides a generic channel interface that abstracts the details of the underlying I/O mechanism.
CHANNELTYPE
A channel type defines the behavior and operations that can be performed on a specific kind of channel. It is implemented as a structure containing pointers to functions that handle various channel operations (e.g., reading, writing, closing).
CHANNELINSTANCE
This is the actual instance of a channel. It contains the instance-specific data and information needed to manage the channel.

The functions provided in this section allow for:

  • Retrieving instance-specific data for a channel.
  • Getting the type of a channel.
  • Registering and unregistering channel drivers with the Tcl interpreter.
  • Creating and deleting channels.
  • Accessing the underlying file handle or other I/O resources associated with a channel.
  • Getting and setting channel options such as blocking mode, buffer size, and specific options for the channel type.
  • Managing standard channels (stdin, stdout, stderr).
  • Creating channels from existing file descriptors, pipes, or server sockets.
  • Associating arbitrary data with channels.
  • Executing Tcl commands in the context of a channel.
  • Defining new channel types and their associated procedures.
  • Handling channel events and metadata.
  • Controlling blocking and non-blocking modes for channels.
  • Retrieving and setting various error-related information for a channel.

TCL_CHANNELTYPE

The Tcl_ChannelType structure is central to defining channel behavior. It is defined as:

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_ChannelProc *openProc;
    Tcl_ChannelProc *closeProc;
    Tcl_ChannelProc *inputProc;
    Tcl_ChannelProc *outputProc;
    Tcl_ChannelProc *seekProc;
    Tcl_ChannelProc *setOptionProc;
    Tcl_ChannelProc *getOptionProc;
    Tcl_ChannelProc *watchProc;
    Tcl_ChannelProc *getHandleProc;
    Tcl_ChannelProc *threadSafeProc;
    Tcl_ChannelProc *truncateProc;
    Tcl_ChannelProc *convertProc;
    Tcl_ChannelProc *flagsProc;
} Tcl_ChannelType;

This structure contains function pointers that the Tcl interpreter calls to perform various operations on channels of this type. For example, inputProc is called to read data from the channel, and outputProc is called to write data to the channel.

TCL_BADCHANNELOPTION

This constant is returned by Tcl_GetChannelOption and Tcl_SetChannelOption when an invalid channel option name is provided.

OLD CHANNEL TYPES

Older versions of Tcl used a different mechanism for defining channel types. While the newer interface is preferred, compatibility may be maintained for some older channel types.
