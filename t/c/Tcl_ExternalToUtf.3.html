ARGUMENTS

Tcl_Interp *interp (in)
Interpreter to use for error reporting, or NULL if no error reporting is desired.
const char *name (in)
Name of encoding to load.
Tcl_Encoding encoding (in)
The encoding to query, free, or use for converting text. If encoding is NULL, the current system encoding is used.
Tcl_Obj *objPtr (in)
Name of encoding to get token for.
Tcl_Encoding *encodingPtr (out)
Points to storage where encoding token is to be written.
const char *src (in)
For the Tcl_ExternalToUtf functions, an array of bytes in the specified encoding that are to be converted to UTF-8. For the Tcl_UtfToExternal and Tcl_WinUtfToTChar functions, an array of UTF-8 characters to be converted to the specified encoding.
const TCHAR *tsrc (in)
An array of Windows TCHAR characters to convert to UTF-8.
int srcLen (in)
Length of src or tsrc in bytes. If the length is negative, the encoding-specific length of the string is used.
Tcl_DString *dstPtr (out)
Pointer to an uninitialized or free Tcl_DString in which the converted result will be stored.
int flags (in)
Various flag bits OR-ed together. TCL_ENCODING_START signifies that the source buffer is the first block in a (potentially multi-block) input stream, telling the conversion routine to reset to an initial state and perform any initialization that needs to occur before the first byte is converted. TCL_ENCODING_END signifies that the source buffer is the last block in a (potentially multi-block) input stream, telling the conversion routine to perform any finalization that needs to occur after the last byte is converted and then to reset to an initial state. TCL_ENCODING_STOPONERROR signifies that the conversion routine should return immediately upon reading a source character that does not exist in the target encoding; otherwise a default fallback character will automatically be substituted.
Tcl_EncodingState *statePtr (in/out)
Used when converting a (generally long or indefinite length) byte stream in a piece-by-piece fashion. The conversion routine stores its current state in *statePtr after src (the buffer containing the current piece) has been converted; that state information must be passed back when converting the next piece of the stream so the conversion routine knows what state it was in when it left off at the end of the last piece. May be NULL, in which case the value specified for flags is ignored and the source buffer is assumed to contain the complete string to convert.
char *dst (out)
Buffer in which the converted result will be stored. No more than dstLen bytes will be stored in dst.
int dstLen (in)
The maximum length of the output buffer dst in bytes.
int *srcReadPtr (out)
Filled with the number of bytes from src that were actually converted. This may be less than the original source length if there was a problem converting some source characters. May be NULL.
int *dstWrotePtr (out)
Filled with the number of bytes that were actually stored in the output buffer as a result of the conversion. May be NULL.
int *dstCharsPtr (out)
Filled with the number of characters that correspond to the number of bytes stored in the output buffer. May be NULL.
Tcl_DString *bufPtr (out)
Storage for the prescribed system encoding name.
const Tcl_EncodingType *typePtr (in)
Structure that defines a new type of encoding.
Tcl_Obj *searchPath (in)
List of filesystem directories in which to search for encoding data files.
const char *path (in)
A path to the location of the encoding file.

INTRODUCTION

These routines convert between Tcl's internal character representation, UTF-8, and character representations used by various operating systems or file systems, such as Unicode, ASCII, or Shift-JIS. When operating on strings, such as such as obtaining the names of files or displaying characters using international fonts, the strings must be translated into one or possibly multiple formats that the various system calls can use. For instance, on a Japanese Unix workstation, a user might obtain a filename represented in the EUC-JP file encoding and then translate the characters to the jisx0208 font encoding in order to display the filename in a Tk widget. The purpose of the encoding package is to help bridge the translation gap. UTF-8 provides an intermediate staging ground for all the various encodings. In the example above, text would be translated into UTF-8 from whatever file encoding the operating system is using. Then it would be translated from UTF-8 into whatever font encoding the display routines require.

Some basic encodings are compiled into Tcl. Others can be defined by the user or dynamically loaded from encoding files in a platform-independent manner.

DESCRIPTION

Tcl_GetEncoding finds an encoding given its name. The name may refer to a built-in Tcl encoding, a user-defined encoding registered by calling Tcl_CreateEncoding, or a dynamically-loadable encoding file. The return value is a token that represents the encoding and can be used in subsequent calls to procedures such as Tcl_GetEncodingName, Tcl_FreeEncoding, and Tcl_UtfToExternal. If the name did not refer to any known or loadable encoding, NULL is returned and an error message is returned in interp.

The encoding package maintains a database of all encodings currently in use. The first time name is seen, Tcl_GetEncoding returns an encoding with a reference count of 1. If the same name is requested further times, then the reference count for that encoding is incremented without the overhead of allocating a new encoding and all its associated data structures.

When an encoding is no longer needed, Tcl_FreeEncoding should be called to release it. When an encoding is no longer in use anywhere (i.e., it has been freed as many times as it has been gotten) Tcl_FreeEncoding will release all storage the encoding was using and delete it from the database.

تقوم Tcl_ExternalToUtfDString بتحويل المخزن المؤقت المصدر src من الترميز المحدد encoding إلى UTF-8. يتم تخزين البايتات المحولة في dstPtr، والتي يتم بعد ذلك إنهاؤها بـ NULL. يجب على المتصل استدعاء Tcl_DStringFree في النهاية لتحرير أي معلومات مخزنة في dstPtr. عند التحويل، إذا لم يكن من الممكن تمثيل أي من الأحرف في المخزن المؤقت المصدر في الترميز الهدف، فسيتم استخدام حرف افتراضي بديل. القيمة المرجعة هي مؤشر إلى القيمة المخزنة في DString.

تقوم Tcl_ExternalToUtf بتحويل المخزن المؤقت المصدر src من الترميز المحدد encoding إلى UTF-8. يتم تحويل ما يصل إلى srcLen بايت من المخزن المؤقت المصدر ويتم تخزين ما يصل إلى dstLen بايت محولة في dst. في جميع الحالات، يتم ملء *srcReadPtr بعدد البايتات التي تم تحويلها بنجاح من src ويتم ملء *dstWrotePtr بعدد البايتات المقابل الذي تم تخزينه في dst. القيمة المرجعة هي واحدة مما يلي:

TCL_OK
تم تحويل جميع بايتات src.
TCL_CONVERT_NOSPACE
لم يكن المخزن المؤقت الوجهة كبيرًا بما يكفي لجميع البيانات المحولة؛ تم تحويل أكبر عدد ممكن من الأحرف التي يمكن أن تتناسب.
TCL_CONVERT_MULTIBYTE
كانت البايتات القليلة الأخيرة في المخزن المؤقت المصدر بداية لتسلسل متعدد البايتات، ولكن كانت هناك حاجة إلى المزيد من البايتات لإكمال هذا التسلسل. يجب أن تمر استدعاء لاحق لروتين التحويل بمخزن مؤقت يحتوي على البايتات غير المحولة التي بقيت في src بالإضافة إلى بعض البايتات الإضافية من تدفق المصدر لتحويل تسلسل متعدد البايتات المقسم سابقًا بشكل صحيح.
TCL_CONVERT_SYNTAX
احتوى المخزن المؤقت المصدر على تسلسل أحرف غير صالح. قد يحدث هذا إذا تعرض تدفق الإدخال للتلف أو إذا تم تحديد طريقة ترميز الإدخال بشكل خاطئ.
TCL_CONVERT_UNKNOWN
احتوى المخزن المؤقت المصدر على حرف لم يكن من الممكن تمثيله في الترميز الهدف وتم تحديد TCL_ENCODING_STOPONERROR.

تقوم Tcl_UtfToExternalDString بتحويل المخزن المؤقت المصدر src من UTF-8 إلى الترميز المحدد encoding. يتم تخزين البايتات المحولة في dstPtr، والتي يتم بعد ذلك إنهاؤها بـ NULL المناسب الخاص بالترميز. يجب على المتصل استدعاء Tcl_DStringFree في النهاية لتحرير أي معلومات مخزنة في dstPtr. عند التحويل، إذا لم يكن من الممكن تمثيل أي من الأحرف في المخزن المؤقت المصدر في الترميز الهدف، فسيتم استخدام حرف افتراضي بديل. القيمة المرجعة هي مؤشر إلى القيمة المخزنة في DString.

تقوم Tcl_UtfToExternal بتحويل المخزن المؤقت المصدر src من UTF-8 إلى الترميز المحدد encoding. يتم تحويل ما يصل إلى srcLen بايت من المخزن المؤقت المصدر ويتم تخزين ما يصل إلى dstLen بايت محولة في dst. في جميع الحالات، يتم ملء *srcReadPtr بعدد البايتات التي تم تحويلها بنجاح من src ويتم ملء *dstWrotePtr بعدد البايتات المقابل الذي تم تخزينه في dst. القيم المرجعة هي نفسها القيم المرجعة لـ Tcl_ExternalToUtf.

Tcl_WinUtfToTChar و Tcl_WinTCharToUtf هما وظيفتان ملائمتان خاصتان بنظام Windows للتحويل بين UTF-8 وسلاسل Windows بناءً على نوع TCHAR الذي هو بالاتفاق حرف Unicode على نظام Windows NT.

Tcl_GetEncodingName هي عكس Tcl_GetEncoding تقريبًا. بالنظر إلى encoding، تكون القيمة المرجعة هي وسيطة name التي تم استخدامها لإنشاء الترميز. لا يُضمن أن يظل السلسلة النصية المرجعة بواسطة Tcl_GetEncodingName صالحة إلا حتى يتم حذف encoding. يجب على المتصل عدم تعديل هذه السلسلة النصية.

تقوم Tcl_SetSystemEncoding بتعيين الترميز الافتراضي الذي يجب استخدامه كلما مرر المستخدم قيمة NULL للوسيط encoding إلى أي من وظائف الترميز الأخرى. إذا كان name هو NULL، يتم إعادة تعيين ترميز النظام إلى ترميز النظام الافتراضي، binary. إذا لم يشير الاسم إلى أي ترميز معروف أو قابل للتحميل، فسيتم إرجاع TCL_ERROR ويتم ترك رسالة خطأ في interp. خلاف ذلك، تقوم هذه الإجراءات بزيادة عدد المراجع للترميز الجديد للنظام، وتقليل عدد المراجع للترميز القديم للنظام، وتعيد TCL_OK.

توفر Tcl_GetEncodingNameFromEnvironment وسيلة لمكتبة Tcl للإبلاغ عن اسم الترميز الذي تعتقد أنه الصحيح لاستخدامه كترميز نظام، بناءً على استدعاءات النظام وفحص البيئة المناسبة للمنصة. تقبل bufPtr، وهو مؤشر إلى Tcl_DString غير مهيأ أو تم تحريره، وتكتب اسم الترميز إليه. يتم إرجاع Tcl_DStringValue.

تقوم Tcl_GetEncodingNames بتعيين نتيجة interp إلى قائمة تتكون من أسماء جميع الترميزات المعرفة حاليًا أو التي يمكن تحميلها ديناميكيًا، مع البحث في مسار الترميز المحدد بواسطة Tcl_SetDefaultEncodingDir. لا يضمن هذا الإجراء أن تحتوي ملفات الترميز القابلة للتحميل ديناميكيًا على بيانات صالحة، بل مجرد وجودها.

تقوم Tcl_CreateEncoding بتعريف ترميز جديد وتسجيل إجراءات C التي يتم استدعاؤها للتحويل بين الترميز و UTF-8. تصبح الترميزات التي تم إنشاؤها بواسطة Tcl_CreateEncoding مرئية بعد ذلك في قاعدة البيانات التي تستخدمها Tcl_GetEncoding. تمامًا مثل إجراء Tcl_GetEncoding، القيمة المرجعة هي رمز يمثل الترميز ويمكن استخدامه في استدعاءات لاحقة لوظائف الترميز الأخرى. تعيد Tcl_CreateEncoding ترميزًا بعدد مراجع 1. إذا كان الترميز بالاسم المحدد name موجودًا بالفعل، فسيتم استبدال إدخاله في قاعدة البيانات بالترميز الجديد؛ سيظل الرمز الخاص بالترميز القديم صالحًا وسيستمر في التصرف كما كان من قبل، ولكن مستخدمي الرمز الجديد سيستدعون الآن إجراءات الترميز الجديدة.

تحتوي الوسيطة typePtr لـ Tcl_CreateEncoding على معلومات حول اسم الترميز والإجراءات التي سيتم استدعاؤها للتحويل بين هذا الترميز و UTF-8. يتم تعريفه على النحو التالي:

typedef struct Tcl_EncodingType {
    const char *encodingName;
    Tcl_EncodingConvertProc *toUtfProc;
    Tcl_EncodingConvertProc *fromUtfProc;
    Tcl_EncodingFreeProc *freeProc;
    ClientData clientData;
    int nullSize;
} Tcl_EncodingType;

يوفر encodingName اسمًا سلسليًا للترميز، والذي يمكن الإشارة إليه به في الإجراءات الأخرى مثل Tcl_GetEncoding. يشير toUtfProc إلى إجراء رد اتصال ليتم استدعاؤه لتحويل النص من هذا الترميز إلى UTF-8. يشير fromUtfProc إلى إجراء رد اتصال ليتم استدعاؤه لتحويل النص من UTF-8 إلى هذا الترميز. يشير freeProc إلى إجراء رد اتصال ليتم استدعاؤه عند حذف هذا الترميز. قد يكون حقل freeProc NULL. يحتوي clientData على قيمة كلمة واحدة عشوائية يتم تمريرها إلى toUtfProc و fromUtfProc و freeProc كلما تم استدعاؤها. عادةً، يكون هذا مؤشرًا إلى بنية بيانات تحتوي على معلومات خاصة بالترميز يمكن استخدامها بواسطة إجراءات رد الاتصال. على سبيل المثال، قد يستخدم ترميزان متشابهان جدًا مثل ascii و macRoman نفس إجراء رد الاتصال، ولكن يستخدمان قيمًا مختلفة لـ clientData للتحكم في سلوكه. يحدد nullSize عدد البايتات الصفرية التي تمثل نهاية السلسلة في هذا الترميز. يجب أن يكون 1 (لترميزات البايت الفردي أو متعدد البايتات مثل ASCII أو Shift-JIS) أو 2 (للترميزات مزدوجة البايت مثل Unicode). الترميزات ذات الحجم الثابت مع 3 بايتات أو أكثر لكل حرف (مثل CNS11643) غير مقبولة.

يجب أن تتطابق إجراءات رد الاتصال toUtfProc و fromUtfProc مع النوع Tcl_EncodingConvertProc:

typedef int Tcl_EncodingConvertProc(
        ClientData clientData,
        const char *src,
        int srcLen,
        int flags,
        Tcl_EncodingState *statePtr,
        char *dst,
        int dstLen,
        int *srcReadPtr,
        int *dstWrotePtr,
        int *dstCharsPtr);

يتم استدعاء إجراءات toUtfProc و fromUtfProc بواسطة عائلة وظائف Tcl_ExternalToUtf أو Tcl_UtfToExternal لإجراء التحويل الفعلي. وسيطة clientData لهذه الإجراءات هي نفسها الحقل clientData المحدد لـ Tcl_CreateEncoding عند إنشاء الترميز. الوسيطات المتبقية لإجراءات رد الاتصال هي نفسها الوسيطات، الموثقة في الأعلى، لـ Tcl_ExternalToUtf أو Tcl_UtfToExternal، مع الاستثناءات التالية. إذا كانت وسيطة srcLen لواحدة من هذه الوظائف عالية المستوى سالبة، فستكون القيمة الممررة إلى إجراء رد الاتصال هي طول السلسلة المناسب للترميز الخاص بـ src. إذا كان أي من الوسائط srcReadPtr أو dstWrotePtr أو dstCharsPtr لواحدة من الوظائف عالية المستوى NULL، فستكون القيمة الممررة إلى إجراء رد الاتصال موقعًا غير NULL.

يجب أن يتطابق إجراء رد الاتصال freeProc، إذا لم يكن NULL، مع النوع Tcl_EncodingFreeProc:

typedef void Tcl_EncodingFreeProc(
        ClientData clientData);

يتم استدعاء وظيفة freeProc هذه عند حذف الترميز. وسيطة clientData هي نفسها الحقل clientData المحدد لـ Tcl_CreateEncoding عند إنشاء الترميز.

يتم استدعاء Tcl_GetEncodingSearchPath و Tcl_SetEncodingSearchPath للوصول إلى قائمة الدلائل التي يتم البحث فيها عن ملفات بيانات الترميز وتعيينها.

القيمة التي تعيدها Tcl_GetEncodingSearchPath هي القيمة التي تم تخزينها بواسطة آخر استدعاء ناجح لـ Tcl_SetEncodingSearchPath. إذا لم تحدث استدعاءات لـ Tcl_SetEncodingSearchPath، فسيقوم Tcl بحساب قيمة أولية بناءً على البيئة. يوجد مسار بحث ترميز واحد للعملية بأكملها، مشترك بين جميع الخيوط في العملية.
