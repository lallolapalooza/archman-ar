الوصف

تُعرّض إجراءات Tcl_SetReturnOptions و Tcl_GetReturnOptions نفس القدرات التي توفرها أوامر return و catch، على التوالي، في شكل واجهة C.

تقوم Tcl_GetReturnOptions باسترداد قاموس خيارات الإرجاع من مفسر بعد تقييم نص برمجي. يتم استدعاء إجراءات مثل Tcl_Eval لتقييم نص برمجي في مفسر. تُرجع هذه الإجراءات رمز إكمال عدد صحيح. تترك هذه الإجراءات أيضًا في المفسر كلاً من نتيجة وقاموس خيارات الإرجاع التي تم إنشاؤها بواسطة تقييم النص البرمجي. تمامًا كما يسترد Tcl_GetObjResult النتيجة، تسترد Tcl_GetReturnOptions قاموس خيارات الإرجاع. يجب تمرير رمز الإكمال العددي كمعامل code إلى Tcl_GetReturnOptions بحيث تكون جميع الخيارات المطلوبة موجودة في القاموس. على وجه التحديد، يضمن قيمة code TCL_ERROR ظهور إدخالات للمفاتيح -errorinfo و -errorcode و -errorline في القاموس. أيضًا، سيتم تعديل إدخالات المفاتيح -code و -level إذا لزم الأمر لتتوافق مع قيمة code. يشير (Tcl_Obj *) الذي تم إرجاعه بواسطة Tcl_GetReturnOptions إلى Tcl_Obj غير مشترك مع عدد مرجعي صفر. يمكن الكتابة فوق القاموس، سواء بإضافة أو إزالة أو استبدال أي إدخالات فيه، دون الحاجة إلى التحقق من قيمة مشتركة. كما هو الحال مع أي Tcl_Obj مع عدد مرجعي صفر، فإن الأمر متروك للمتصل لترتيب التخلص منه باستخدام Tcl_DecrRefCount أو إلى مرجع إليه عبر Tcl_IncrRefCount (أو أحد العديد من الوظائف التي تستدعي ذلك، بما في ذلك بشكل خاص Tcl_SetObjResult و Tcl_SetVar2Ex).

الاستخدام النموذجي لـ Tcl_GetReturnOptions هو استرداد تتبع المكدس عند إرجاع تقييم النص البرمجي TCL_ERROR، كالتالي:

int code = Tcl_Eval(interp, script);
if (code == TCL_ERROR) {
    Tcl_Obj *options = Tcl_GetReturnOptions(interp, code);
    Tcl_Obj *key = Tcl_NewStringObj("-errorinfo", -1);
    Tcl_Obj *stackTrace;
    Tcl_IncrRefCount(key);
    Tcl_DictObjGet(NULL, options, key, &stackTrace);
    Tcl_DecrRefCount(key);
    /* قم بشيء ما باستخدام stackTrace */
    Tcl_DecrRefCount(options);
}

تقوم Tcl_SetReturnOptions بتعيين خيارات الإرجاع للمفسر interp لتكون options. إذا احتوى options على أي قيمة غير صالحة لأي مفتاح، فسيتم إرجاع TCL_ERROR، وسيتم تعيين نتيجة المفسر إلى رسالة خطأ مناسبة. بخلاف ذلك، سيتم إرجاع رمز إكمال يتفق مع مفاتيح -code و -level في options.

كمثال، يمكن تنفيذ أمر Tcl return نفسه باستخدام Tcl_SetReturnOptions كالتالي:

if ((objc % 2) == 0) { /* معامل نتيجة صريح */
    objc--;
    Tcl_SetObjResult(interp, objv[objc]);
}
return Tcl_SetReturnOptions(interp, Tcl_NewListObj(objc-1, objv+1));

(لم يتم تنفيذه بهذه الطريقة حقًا. تمنح امتيازات الوصول الداخلية بديلًا أكثر كفاءة يتناسب بشكل أفضل مع مترجم البايت كود.)

لاحظ أنه يمكن تمرير Tcl_Obj تم إنشاؤه حديثًا كمعامل options دون الحاجة إلى التعامل مع أي عد مراجع. هذا مشابه لـ Tcl_SetObjResult.

بينما توفر Tcl_SetReturnOptions واجهة عامة لتعيين أي مجموعة من خيارات الإرجاع، هناك عدد قليل من خيارات الإرجاع المستخدمة بشكل متكرر جدًا. أهمها، يجب تعيين خيارات الإرجاع -errorinfo و -errorcode بشكل صحيح عندما تُرجع إجراءات الأوامر رمز TCL_ERROR. يتم أيضًا قراءة خيار الإرجاع -errorline بواسطة الأوامر التي تقوم بتقييم النصوص البرمجية وترغب في توفير معلومات مفصلة عن موقع الخطأ في نص تتبع المكدس الذي تلحقه بخيار -errorinfo. توفر Tcl عدة واجهات أبسط لتعيين خيارات الإرجاع هذه بشكل مباشر.

يحتوي خيار -errorinfo على تتبع مكدس للعمليات التي كانت قيد التنفيذ عند حدوث خطأ، وهو مخصص للقراءة من قبل الإنسان. يحتوي خيار -errorcode على قائمة Tcl بالعناصر المخصصة للقراءة من قبل الآلة. يحدد العنصر الأول في قيمة -errorcode فئة الخطأ الذي حدث (على سبيل المثال، POSIX يعني حدوث خطأ في استدعاء نظام POSIX) وتحتوي العناصر الإضافية على قطع إضافية من المعلومات تعتمد على الفئة. راجع صفحة الدليل الخاصة بالمتغير errorCode للحصول على تفاصيل حول التنسيقات المختلفة لخيار -errorcode التي تستخدمها أوامر Tcl المضمنة.

يتم بناء قيمة خيار -errorinfo تدريجيًا أثناء تلاشي خطأ عبر العمليات المتداخلة. في كل مرة يتم فيها إرجاع رمز خطأ إلى Tcl_Eval، أو أي من الإجراءات التي تقوم بتقييم النص البرمجي، يتم استدعاء الإجراء Tcl_AddErrorInfo لإضافة نص إضافي إلى قيمة -errorinfo يصف الأمر الذي كان قيد التنفيذ عند حدوث الخطأ. بحلول الوقت الذي تم فيه تمرير الخطأ بالكامل مرة أخرى إلى التطبيق، سيحتوي على تتبع كامل للنشاط الذي كان قيد التنفيذ عند حدوث الخطأ.

من المفيد أحيانًا إضافة معلومات إضافية إلى قيمة -errorinfo أبعد مما يمكن توفيره تلقائيًا بواسطة إجراءات تقييم النص البرمجي. يمكن استخدام Tcl_AddErrorInfo لهذا الغرض: معاملها message هو سلسلة إضافية سيتم إلحاقها بخيار -errorinfo. على سبيل المثال، عند حدوث خطأ أثناء أمر source، يتم استدعاء الإجراء Tcl_AddErrorInfo لتسجيل اسم الملف الذي يتم معالجته ورقم السطر الذي وقع فيه الخطأ. وبالمثل، عند حدوث خطأ أثناء تقييم
