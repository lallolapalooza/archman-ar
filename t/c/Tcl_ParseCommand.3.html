Tcl_ParseCommand(3) Tcl Library Procedures Tcl_ParseCommand(3)

NAME

Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString, Tcl_ParseVarName, Tcl_ParseVar, Tcl_FreeParse, Tcl_EvalTokens, Tcl_EvalTokensStandard - parse Tcl scripts and expressions

#include <tcl.h>

int
Tcl_ParseCommand(interp, start, numBytes, nested, parsePtr)

int
Tcl_ParseExpr(interp, start, numBytes, parsePtr)

int
Tcl_ParseBraces(interp, start, numBytes, parsePtr, append, termPtr)

int
Tcl_ParseQuotedString(interp, start, numBytes, parsePtr, append, termPtr)

int
Tcl_ParseVarName(interp, start, numBytes, parsePtr, append)

const char *
Tcl_ParseVar(interp, start, termPtr)

Tcl_FreeParse(usedParsePtr)

Tcl_Obj *
Tcl_EvalTokens(interp, tokenPtr, numTokens)

int
Tcl_EvalTokensStandard(interp, tokenPtr, numTokens)

ARGUMENTS

Tcl_Interp *interp (out)
For procedures other than Tcl_FreeParse, Tcl_EvalTokens and Tcl_EvalTokensStandard, used only for error reporting; if NULL, then no error messages are left after errors. For Tcl_EvalTokens and Tcl_EvalTokensStandard, determines the context for evaluating the script and also is used for error reporting; must not be NULL.
const char *start (in)
Pointer to first character in string to parse.
int numBytes (in)
Number of bytes in string to parse, not including any terminating null character. If less than 0 then the script consists of all characters following start up to the first null character.
int nested (in)
Non-zero means that the script is part of a command substitution so an unquoted close bracket should be treated as a command terminator. If zero, close brackets have no special meaning.
int append (in)
Non-zero means that *parsePtr already contains valid tokens; the new tokens should be appended to those already present. Zero means that *parsePtr is uninitialized; any information in it is ignored. This argument is normally 0.
Tcl_Parse *parsePtr (out)
Points to structure to fill in with information about the parsed command, expression, variable name, etc. Any previous information in this structure is ignored, unless append is non-zero in a call to Tcl_ParseBraces, Tcl_ParseQuotedString, or Tcl_ParseVarName.
const char **termPtr (out)
If not NULL, points to a location where Tcl_ParseBraces, Tcl_ParseQuotedString, and Tcl_ParseVar will store a pointer to the character just after the terminating character (the close-brace, the last character of the variable name, or the close-quote (respectively)) if the parse was successful.
Tcl_Parse *usedParsePtr (in)
Points to structure that was filled in by a previous call to Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseVarName, etc.

DESCRIPTION

These procedures parse Tcl commands or portions of Tcl commands such as expressions or references to variables. Each procedure takes a pointer to a script (or portion thereof) and fills in the structure pointed to by parsePtr with a collection of tokens describing the information that was parsed. The procedures normally return TCL_OK. However, if an error occurs then they return TCL_ERROR, leave an error message in interp's result (if interp is not NULL), and leave nothing in parsePtr.

Tcl_ParseCommand is a procedure that parses Tcl scripts. Given a pointer to a script, it parses the first command from the script. If the command was parsed successfully, Tcl_ParseCommand returns TCL_OK and fills in the structure pointed to by parsePtr with information about the structure of the command (see below for details). If an error occurred in parsing the command then TCL_ERROR is returned, an error message is left in interp's result, and no information is left at *parsePtr.

Tcl_ParseExpr parses Tcl expressions. Given a pointer to a script containing an expression, Tcl_ParseExpr parses the expression. If the expression was parsed successfully, Tcl_ParseExpr returns TCL_OK and fills in the structure pointed to by parsePtr with information about the structure of the expression (see below for details). If an error occurred in parsing the command then TCL_ERROR is returned, an error message is left in interp's result, and no information is left at *parsePtr.

Tcl_ParseBraces parses a string or command argument enclosed in braces such as {hello} or {string \t with \t tabs} from the beginning of its argument start. The first character of start must be {. If the braced string was parsed successfully, Tcl_ParseBraces returns TCL_OK, fills in the structure pointed to by parsePtr with information about the structure of the string (see below for details), and stores a pointer to the character just after the terminating } in the location given by *termPtr. If an error occurs while parsing the string then TCL_ERROR is returned, an error message is left in interp's result, and no information is left at *parsePtr or *termPtr.

Tcl_ParseQuotedString parses a double-quoted string such as "sum is [expr {$a+$b}]" from the beginning of the argument start. The first character of start must be ". If the double-quoted string was parsed successfully, Tcl_ParseQuotedString returns TCL_OK, fills in the structure pointed to by parsePtr with information about the structure of the string (see below for details), and stores a pointer to the character just after the terminating " in the location given by *termPtr. If an error occurs while parsing the string then TCL_ERROR is returned, an error message is left in interp's result, and no information is left at *parsePtr or *termPtr.

Tcl_ParseVarName parses a Tcl variable reference such as $abc or $x([expr {$index + 1}]) from the beginning of its start argument. The first character of start must be $. If a variable name was parsed successfully, Tcl_ParseVarName returns TCL_OK and fills in the structure pointed to by parsePtr with information about the structure of the variable name (see below for details). If an error occurs while parsing the command then TCL_ERROR is returned, an error message is left in interp's result (if interp is not NULL), and no information is left at *parsePtr.

Tcl_ParseVar parses a Tcl variable reference such as $abc or $x([expr {$index + 1}]) from the beginning of its start argument. The first character of start must be $. If the variable name is parsed successfully, Tcl_ParseVar returns a pointer to the string value of the variable. If an error occurs while parsing, then NULL is returned and an error message is left in interp's result.

The information left at *parsePtr by Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString, and Tcl_ParseVarName may include dynamically allocated memory. If these five parsing procedures return TCL_OK then the caller must invoke Tcl_FreeParse to release the storage at *parsePtr. These procedures ignore any existing information in *parsePtr (unless append is non-zero), so if repeated calls are being made to any of them then Tcl_FreeParse must be invoked once after each call.

Tcl_EvalTokensStandard evaluates a sequence of parse tokens from a Tcl_Parse structure. The tokens typically consist of all the tokens in a word or all the tokens that make up the index for a reference to an array variable. Tcl_EvalTokensStandard performs the substitutions requested by the tokens and concatenates the resulting values. The return value from Tcl_EvalTokensStandard is a Tcl completion code with one of the values TCL_OK, TCL_ERROR, TCL_RETURN, TCL_BREAK, or TCL_CONTINUE, or possibly some other integer value originating in an extension. In addition, a result value or error message is left in interp's result; it can be retrieved using Tcl_GetObjResult.

TCL_EVAL_TOKENS

Tcl_EvalTokens evaluates a sequence of tokens that have been previously parsed and returns the result as a Tcl value. This is useful for implementing commands that generate Tcl commands or expressions dynamically. The function signature is:

Tcl_Obj * Tcl_EvalTokens(Tcl_Interp *interp, Tcl_Token *tokenPtr, int numTokens);

The interp argument is the Tcl interpreter in which the tokens are to be evaluated. The tokenPtr argument points to the first token in the array of tokens to be evaluated, and numTokens is the number of tokens in the array. The function returns a pointer to a new Tcl_Obj representing the result of evaluating the tokens. The reference count of the value returned as a result has been incremented, so the caller must invoke Tcl_DecrRefCount when it is finished with the value. If an error or other exception occurs while evaluating the tokens (such as a reference to a non-existent variable) then the return value is NULL and an error message is left in interp's result. The use of Tcl_EvalTokens is deprecated.

بنية التحليل (TCL_PARSE STRUCTURE)

Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString, and Tcl_ParseVarName تُرجع معلومات التحليل في هيكلين بيانات، Tcl_Parse و Tcl_Token:

typedef struct Tcl_Parse {
    const char *commentStart;
    int commentSize;
    const char *commandStart;
    int commandSize;
    int numWords;
    Tcl_Token *tokenPtr;
    int numTokens;
    ...
} Tcl_Parse;
typedef struct Tcl_Token {
    int type;
    const char *start;
    int size;
    int numComponents;
} Tcl_Token;

الحقول الخمسة الأولى لهيكل Tcl_Parse يتم ملؤها فقط بواسطة Tcl_ParseCommand. هذه الحقول لا تُستخدم بواسطة إجراءات التحليل الأخرى.

يملأ Tcl_ParseCommand هيكل Tcl_Parse بمعلومات تصف أمر Tcl واحد وأي تعليقات تسبق الأمر. إذا كانت هناك تعليقات، فإن الحقل commentStart يشير إلى الحرف # الذي يبدأ أول تعليق، ويشير commentSize إلى عدد البايتات في كل التعليقات التي تسبق الأمر، بما في ذلك حرف السطر الجديد الذي ينهي آخر تعليق. إذا لم يسبق الأمر أي تعليقات، فإن commentSize تكون 0. يقوم Tcl_ParseCommand أيضًا بتعيين الحقل commandStart للإشارة إلى الحرف الأول من الكلمة الأولى في الأمر (مع تجاوز أي تعليقات ومساحات بادئة)، ويعطي commandSize العدد الإجمالي للبايتات في الأمر، بما في ذلك الحرف الذي يشير إليه commandStart حتى الحرف الذي ينهي الأمر، بما في ذلك حرف السطر الجديد، أو القوس المغلق، أو الفاصلة المنقوطة. يعطي الحقل numWords العدد الإجمالي للكلمات في الأمر.

جميع إجراءات التحليل تقوم بتعيين الحقول المتبقية، tokenPtr و numTokens. يشير الحقل tokenPtr إلى أول هيكل في مصفوفة هياكل Tcl_Token التي تصف مكونات الكيان الذي يتم تحليله. يعطي الحقل numTokens العدد الإجمالي للرموز المميزة الموجودة في المصفوفة. يحتوي كل رمز مميز على أربعة حقول. يختار الحقل type أحد أنواع الرموز المميزة العديدة التي توصف أدناه. يشير الحقل start إلى الحرف الأول في الرمز المميز، ويعطي الحقل size العدد الإجمالي للأحرف في الرمز المميز. بعض أنواع الرموز المميزة، مثل TCL_TOKEN_WORD و TCL_TOKEN_VARIABLE، تتكون من عدة رموز مميزة فرعية، والتي تتبع الرمز المميز الأصل مباشرة؛ يصف الحقل numComponents عدد هذه الرموز. يأخذ الحقل type إحدى القيم التالية:

TCL_TOKEN_WORD
هذا الرمز المميز يصف عادةً كلمة واحدة من أمر، ولكنه قد يصف أيضًا سلسلة نصية محاطة بعلامات اقتباس أو أقواس معقوفة في تعبير. يصف الرمز المميز مكونًا من النص النصي الذي هو نتيجة دمج سلسلة من المكونات الفرعية، يصف كل منها رمز مميز فرعي منفصل. يبدأ الرمز المميز بالحرف الأول غير المسافة البيضاء للمكون (الذي قد يكون علامة اقتباس مزدوجة أو قوسًا معقوفًا مفتوحًا) ويتضمن جميع الأحرف في المكون حتى، ولكن ليس بما في ذلك، المسافة، الفاصلة المنقوطة، القوس المغلق، علامة الاقتباس المغلقة، أو القوس المعقوف المغلق الذي ينهي المكون. يحسب الحقل numComponents العدد الإجمالي للرموز الفرعية التي تشكل الكلمة، بما في ذلك الرموز الفرعية لرموز TCL_TOKEN_VARIABLE و TCL_TOKEN_BS.
TCL_TOKEN_SIMPLE_WORD
هذا الرمز المميز له نفس معنى TCL_TOKEN_WORD، باستثناء أن الكلمة مضمونة لتتكون من رمز فرعي واحد من نوع TCL_TOKEN_TEXT. الحقل numComponents دائمًا يساوي 1.
TCL_TOKEN_EXPAND_WORD
هذا الرمز المميز له نفس معنى TCL_TOKEN_WORD، باستثناء أن محلل الأوامر يلاحظ أن هذه الكلمة بدأت ببادئة التوسيع {*}، مما يشير إلى أنه بعد الاستبدال، يجب توسيع قيمة القائمة لهذه الكلمة لتكوين وسائط متعددة في تقييم الأمر. يمكن إنشاء هذا النوع من الرموز المميزة فقط بواسطة Tcl_ParseCommand.
TCL_TOKEN_TEXT
يصف الرمز المميز نطاقًا من النص الحرفي الذي هو جزء من كلمة. الحقل numComponents دائمًا يساوي 0.
TCL_TOKEN_BS
يصف الرمز المميز تسلسل شرطة مائلة للخلف مثل \n أو \0xA3. الحقل numComponents دائمًا يساوي 0.
TCL_TOKEN_COMMAND
يصف الرمز المميز أمرًا يجب استبدال نتيجته في الكلمة. يشمل الرمز المميز الأقواس المربعة التي تحيط بالأمر. الحقل numComponents دائمًا يساوي 0 (الأمر المتداخل لا يتم تحليله؛ اتصل بـ Tcl_ParseCommand بشكل متكرر إذا كنت تريد رؤية رموزه).
TCL_TOKEN_VARIABLE
يصف الرمز المميز استبدال متغير، بما في ذلك $، اسم المتغير، وفهرس المصفوفة (إذا كان موجودًا) حتى القوس المغلق الذي ينهي الفهرس. يتبع هذا الرمز المميز رمز واحد أو أكثر من الرموز الإضافية التي تصف اسم المتغير وفهرس المصفوفة. إذا كان numComponents يساوي 1، فإن المتغير هو كمي (scalar) والرمز المميز التالي هو رمز TCL_TOKEN_TEXT الذي يعطي اسم المتغير. إذا كان numComponents أكبر من 1، فإن المتغير هو مصفوفة: الرمز المميز الفرعي الأول هو رمز TCL_TOKEN_TEXT يعطي اسم المصفوفة، والرموز الفرعية المتبقية هي رموز TCL_TOKEN_TEXT، TCL_TOKEN_BS، TCL_TOKEN_COMMAND، و TCL_TOKEN_VARIABLE التي يجب دمجها لإنتاج فهرس المصفوفة. يتضمن الحقل numComponents الرموز الفرعية المتداخلة التي تعد جزءًا من رموز TCL_TOKEN_VARIABLE في فهرس المصفوفة.
TCL_TOKEN_SUB_EXPR
يصف الرمز المميز تعبيرًا فرعيًا واحدًا لتعبير (أو تعبيرًا كاملاً). قد يتكون التعبير الفرعي من قيمة مثل ثابت صحيح، استبدال متغير، أو تعبير فرعي محاط بأقواس؛ قد يتكون أيضًا من عامل وعوامل التشغيل الخاصة به. يبدأ الرمز المميز بالحرف الأول غير المسافة البيضاء من التعبير الفرعي حتى، ولكن ليس بما في ذلك، المسافة، القوس المعقوف، القوس المغلق، أو القوس المربع الذي ينهي التعبير الفرعي. يتبع هذا الرمز المميز رمز واحد أو أكثر من الرموز الإضافية التي تصف التعبير الفرعي. إذا كان أول رمز فرعي بعد رمز TCL_TOKEN_SUB_EXPR هو رمز TCL_TOKEN_OPERATOR، فإن التعبير الفرعي يتكون من عامل ورموزه التشغيلية. إذا كان العامل لا يحتوي على عوامل تشغيل، فإن التعبير الفرعي يتكون فقط من رمز TCL_TOKEN_OPERATOR. يتم وصف كل عامل تشغيل بواسطة رمز TCL_TOKEN_SUB_EXPR. بخلاف ذلك، فإن التعبير الفرعي هو قيمة وصفها أحد أنواع الرموز المميزة: TCL_TOKEN_WORD، TCL_TOKEN_TEXT، TCL_TOKEN_BS، TCL_TOKEN_COMMAND، TCL_TOKEN_VARIABLE، و TCL_TOKEN_SUB_EXPR. يحسب الحقل numComponents العدد الإجمالي للرموز الفرعية التي تشكل التعبير الفرعي؛ يشمل هذا الرموز الفرعية لأي رموز متداخلة من نوع TCL_TOKEN_SUB_EXPR.
TCL_TOKEN_OPERATOR
يصف الرمز المميز عامل تشغيل واحد لتعبير مثل && أو hypot. يسبق رمز TCL_TOKEN_OPERATOR دائمًا رمز TCL_TOKEN_SUB_EXPR الذي يصف العامل وعوامل التشغيل الخاصة به؛ يمكن استخدام الحقل numComponents لرمز TCL_TOKEN_SUB_EXPR لتحديد عدد عوامل التشغيل. يتبع عامل تشغيل ثنائي مثل * رمزان من نوع TCL_TOKEN_SUB_EXPR يصفان عوامل التشغيل الخاصة به. يتبع عامل تشغيل أحادي مثل - رمز واحد من نوع TCL_TOKEN_SUB_EXPR لعامل التشغيل الخاص به. إذا كان العامل دالة رياضية مثل log10، فإن رمز TCL_TOKEN_OPERATOR سيعطي اسمه، والرموز التالية من نوع TCL_TOKEN_SUB_EXPR ستصف عوامل التشغيل الخاصة به؛ إذا لم تكن هناك عوامل تشغيل (كما هو الحال مع rand)، فلن تتبع أي رموز من نوع TCL_TOKEN_SUB_EXPR. هناك عامل تشغيل ثلاثي واحد، وهو ?، يظهر في التعبيرات الفرعية الشرطية مثل x?y:z؛ في هذه الحالة، يتبع رمز TCL_TOKEN_OPERATOR الخاص بـ ? ثلاثة رموز من نوع TCL_TOKEN_SUB_EXPR لعوامل التشغيل x، y، و z. الحقل numComponents لرمز TCL_TOKEN_OPERATOR يساوي دائمًا 0.

بعد عودة Tcl_ParseCommand، يكون أول رمز مميز يشير إليه الحقل tokenPtr في هيكل Tcl_Parse دائمًا من نوع TCL_TOKEN_WORD أو TCL_TOKEN_SIMPLE_WORD أو TCL_TOKEN_EXPAND_WORD. يتبعه الرموز الفرعية التي يجب دمجها لإنتاج قيمة تلك الكلمة. الرمز المميز التالي هو رمز TCL_TOKEN_WORD أو TCL_TOKEN_SIMPLE_WORD أو TCL_TOKEN_EXPAND_WORD للكلمة الثانية، متبوعًا بالرموز الفرعية لتلك الكلمة، وهكذا حتى يتم حساب جميع numWords.

بعد عودة Tcl_ParseExpr، يكون أول رمز مميز يشير إليه الحقل tokenPtr في هيكل Tcl_Parse دائمًا من نوع TCL_TOKEN_SUB_EXPR. يتبعه الرموز الفرعية التي يجب تقييمها لإنتاج قيمة التعبير. يتم تعديل معلومات الرموز المميزة فقط في هيكل Tcl_Parse: لا يتم تعديل الحقول commentStart، commentSize، commandStart، و commandSize بواسطة Tcl_ParseExpr.
