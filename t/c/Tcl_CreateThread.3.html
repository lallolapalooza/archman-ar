مقدمة

منذ الإصدار 8.1، أصبح نواة Tcl آمنة للخيوط، مما يسمح بتضمين Tcl في تطبيقات متعددة الخيوط دون الحاجة إلى تخصيص نواة Tcl. منذ الإصدار 8.6، تم تمكين دعم الخيوط في Tcl افتراضيًا. لتعطيل دعم الخيوط في Tcl، يجب عليك تضمين الخيار --disable-threads لـ configure عند تكوين وتجميع نواة Tcl الخاصة بك.

أحد القيود الهامة لتنفيذ الخيوط في Tcl هو أن الخيط الذي ينشئ مفسر Tcl هو الوحيد الذي يمكنه استخدام هذا المفسر. بعبارة أخرى، لا يمكن لعدة خيوط الوصول إلى نفس مفسر Tcl. (ومع ذلك، يمكن لخيط واحد إنشاء واستخدام عدة مفسرات بأمان.)

الوصف

توفر Tcl Tcl_CreateThread لإنشاء خيوط. يمكن للمتصل تحديد حجم المكدس المعطى للخيط الجديد وتعديل السلوك باستخدام قيمة flags. تشير القيمة TCL_THREAD_STACK_DEFAULT لـ stackSize إلى أن الحجم الافتراضي هو الحجم الذي يحدده نظام التشغيل للخيط الجديد. فيما يتعلق بالأعلام، يتم حاليًا تحديد القيمتين TCL_THREAD_NOFLAGS و TCL_THREAD_JOINABLE فقط. الأول يستدعي السلوك الافتراضي دون أي تعديلات خاصة. استخدام الثاني يميز الخيط الجديد على أنه joinable (قابل للانضمام). هذا يعني أن خيطًا آخر يمكنه انتظار الخيط المحدد كـ joinable والانضمام إليه.

القيود: في بعض أنظمة UNIX، لا تحتوي مكتبة pthread على وظيفة لتحديد حجم مكدس الخيط. يتم تجاهل القيمة المحددة لحجم المكدس في هذه الأنظمة. لا تدعم Windows حاليًا الخيوط القابلة للانضمام. يتم تجاهل قيمة العلم هذه على هذه المنصة.

توفر Tcl وظيفتي Tcl_ExitThread و Tcl_FinalizeThread لإنهاء الخيوط واستدعاء معالجات الخروج الافتراضية لكل خيط. راجع صفحة Tcl_Exit لمزيد من المعلومات حول هذه الإجراءات.

تسمح دالة Tcl_JoinThread للخيوط بالانتظار حتى يغلق خيط آخر، والذي يجب أن يكون قد تم تمييزه على أنه joinable باستخدام العلم TCL_THREAD_JOINABLE أثناء إنشائه باستخدام Tcl_CreateThread.

محاولة الانتظار حتى يغلق خيط غير joinable أو خيط تم انتظاره بالفعل ستؤدي إلى خطأ. الانتظار لخيط joinable تم إغلاقه بالفعل ممكن، وسيحافظ النظام على المعلومات اللازمة حتى بعد استدعاء Tcl_JoinThread. هذا يعني أن عدم استدعاء Tcl_JoinThread لخيط joinable سيؤدي إلى تسرب في الذاكرة.

تُرجع استدعاء Tcl_GetThreadData مؤشرًا إلى كتلة بيانات خاصة بالخيط. معاملها هو مفتاح مشترك بين جميع الخيوط وحجم لكتلة التخزين. يتم تخصيص التخزين تلقائيًا وتهيئته إلى الصفر عند أول استخدام لكل خيط. يتم تحرير التخزين تلقائيًا بواسطة Tcl_FinalizeThread.

التركيب والتواصل

توفر Tcl Tcl_ThreadQueueEvent و Tcl_ThreadAlert للتعامل مع قائمة انتظار الأحداث في التطبيقات متعددة الخيوط. راجع صفحة Notifier لمزيد من المعلومات حول هذه الإجراءات.

الـ Mutex هو كتلة تحكم تُستخدم لتسلسل جميع الخيوط عبر كتلة من التعليمات البرمجية التي تستدعي Tcl_MutexLock و Tcl_MutexUnlock. إذا كان لدى خيط mutex، فإن أي خيط آخر يستدعي Tcl_MutexLock سيتم حظره حتى يتم استدعاء Tcl_MutexUnlock. يمكن تدمير mutex في نهاية استخدامه عن طريق استدعاء Tcl_MutexFinalize. نتيجة قفل mutex مرتين من نفس الخيط غير محددة. في بعض الحالات، قد يؤدي ذلك إلى قفل deadlock. تتصرف الإجراءات Tcl_MutexLock و Tcl_MutexUnlock و Tcl_MutexFinalize كماكروات فارغة إذا لم يتم تجميعها مع دعم الخيوط. لتعريف mutexes، يجب استخدام الماكرو TCL_DECLARE_MUTEX. يضمن هذا الماكرو الإدارة الصحيحة للـ mutexes حتى عندما لا يتم تجميع النواة مع دعم الخيوط.

يُستخدم المتغير الشرطي كآلية إشارة: يمكن لخيط قفل mutex والانتظار في Tcl_ConditionWait. هذا يحرر قفل mutex ويحظر الخيط المنتظر حتى يقوم خيط آخر باستدعاء Tcl_ConditionNotify. يجب أن يكون المستدعي لـ Tcl_ConditionNotify قد قفل mutex المرتبط مسبقًا عن طريق استدعاء Tcl_MutexLock، ولكن هذا لا يتم فرضه. إعلام المتغير الشرطي يفتح جميع الخيوط المنتظرة على المتغير الشرطي، ولكن هذه الخيوط لا تتقدم حتى يتم تحرير mutex عن طريق Tcl_MutexUnlock. يقوم تنفيذ Tcl_ConditionWait بتحرير mutex تلقائيًا قبل العودة.

يجب على مستدعي Tcl_ConditionWait الاستعداد للإشعارات الكاذبة عن طريق استدعاء Tcl_ConditionWait داخل حلقة while تختبر خاصية ثابتة.

يمكن تدمير متغير شرطي في نهاية استخدامه عن طريق استدعاء Tcl_ConditionFinalize.

تتصرف الإجراءات Tcl_ConditionNotify و Tcl_ConditionWait و Tcl_ConditionFinalize كماكروات فارغة إذا لم يتم تجميعها مع دعم الخيوط.

التهيئة

جميع كائنات المزامنة هذه ذاتية التهيئة. يتم تنفيذها كمؤشرات غير شفافة يجب أن تكون فارغة عند الاستخدام الأول. يتم حذف الـ mutexes والمتغيرات الشرطية بواسطة معالجات إغلاق العملية (إذا كانت قيد التشغيل) أو عن طريق استدعاء Tcl_MutexFinalize أو Tcl_ConditionFinalize صراحةً. يتم تحرير تخزين البيانات المحلية للخيوط أثناء Tcl_FinalizeThread.

الوصول على مستوى السكربت للخيوط

لا توفر Tcl أي أوامر سكربت لإنشاء وإدارة أو دمج الخيوط، أو الوصول على مستوى السكربت إلى mutexes أو المتغيرات الشرطية. إنها توفر هذه الخدمات فقط من خلال واجهات C، وتترك الأمر للحزم للقيام بذلك.

الملخص

لإنشاء خيط باستخدام كود قابل للنقل، يجب الإعلان عن دالة التنفيذ الخاصة به على النحو التالي:

static Tcl_ThreadCreateProc MyThreadImplFunc;

يجب بعد ذلك تعريفه على النحو التالي، والذي يقوم فقط بالعد حتى قيمة معينة ثم ينتهي.

static Tcl_ThreadCreateType
MyThreadImplFunc(
    ClientData clientData)
{
    int i, limit = (int) clientData;
    for (i=0 ; i<limit ; i++) {
        /* لا تفعل شيئا هنا */
    }
    TCL_THREAD_CREATE_RETURN;
}

لإنشاء الخيط أعلاه، وتشغيله، والانتظار حتى ينتهي، سنفعل هذا:

int limit = 1000000000;
ClientData limitData = (void*)((intptr_t) limit);
Tcl_ThreadId id;    /* تخزين هوية الخيط المنشأ */
int result;
if (Tcl_CreateThread(&id, MyThreadImplFunc, limitData,
        TCL_THREAD_STACK_DEFAULT,
        TCL_THREAD_JOINABLE) != TCL_OK) {
    /* لم يتم إنشاء الخيط بشكل صحيح */
    return;
}
/* افعل شيئا ما لبعض الوقت هنا */
if (Tcl_JoinThread(id, &result) != TCL_OK) {
    /* لم ينته الخيط بشكل صحيح */
    return;
}
/* كل شيء تم تنظيفه بشكل جيد */
