مقدمة

بدءًا من الإصدار 8.1، أصبح جوهر Tcl آمنًا للخيوط، مما يسمح لك بدمج Tcl في تطبيقات متعددة الخيوط دون تخصيص جوهر Tcl. بدءًا من الإصدار 8.6، يكون دعم تعدد خيوط Tcl ممكّنًا افتراضيًا. لتعطيل دعم تعدد خيوط Tcl، يجب عليك تضمين الخيار --disable-threads عند configure عند تكوين وتجميع جوهر Tcl الخاص بك.

قيد مهم لتنفيذ خيوط Tcl هو أن الخيط الذي أنشأ مفسر Tcl هو الوحيد الذي يمكنه استخدام هذا المفسر. بمعنى آخر، لا يمكن لعدة خيوط الوصول إلى نفس مفسر Tcl. (ومع ذلك، يمكن لخيط واحد إنشاء واستخدام مفسرات متعددة بأمان.)

الوصف

يوفر Tcl Tcl_CreateThread لإنشاء الخيوط. يمكن للمستدعي تحديد حجم المكدس المعطى للخيط الجديد وتعديل السلوك من خلال flags المقدمة. تشير القيمة TCL_THREAD_STACK_DEFAULT لـ stackSize إلى أنه سيتم استخدام الحجم الافتراضي كما هو محدد بواسطة نظام التشغيل للخيط الجديد. أما بالنسبة للعلامات، فحالياً تم تعريف القيمتين فقط TCL_THREAD_NOFLAGS و TCL_THREAD_JOINABLE. الأول يستدعي السلوك الافتراضي دون إعدادات خاصة. استخدام القيمة الثانية يحدد الخيط الجديد على أنه قابل للانضمام. هذا يعني أنه يمكن لخيط آخر انتظار هذا الخيط المحدد للخروج والانضمام إليه.

القيود: على بعض أنظمة UNIX، لا تحتوي مكتبة pthread على وظيفة لتحديد حجم المكدس للخيط. يتم تجاهل القيمة المحددة لحجم المكدس على هذه الأنظمة. لا يدعم Windows حاليًا الخيوط القابلة للانضمام. لذلك يتم تجاهل قيمة هذه العلامة على هذه المنصة.

يوفر Tcl وظيفتي Tcl_ExitThread و Tcl_FinalizeThread لإنهاء الخيوط واستدعاء معالجات خروج اختيارية لكل خيط. انظر صفحة Tcl_Exit لمزيد من المعلومات حول هذه الإجراءات.

تم توفير وظيفة Tcl_JoinThread للسماح للخيوط بالانتظار حتى خروج خيط آخر، والذي يجب أن يكون قد تم تحديده كـ قابل للانضمام من خلال استخدام علامة TCL_THREAD_JOINABLE أثناء إنشائه عبر Tcl_CreateThread.

محاولة انتظار خروج خيط غير قابل للانضمام أو خيط يتم انتظاره بالفعل ستؤدي إلى خطأ. لا يزال من الممكن انتظار خيط قابل للانضمام قد خرج بالفعل، وسيحتفظ النظام بالمعلومات اللازمة حتى بعد استدعاء Tcl_JoinThread. هذا يعني أن عدم استدعاء Tcl_JoinThread لخيط قابل للانضمام سيؤدي إلى تسرب في الذاكرة.

تقوم استدعاء Tcl_GetThreadData بإرجاع مؤشر إلى كتلة من بيانات الخيط الخاصة. وسيطتها هي مفتاح مشترك بين جميع الخيوط وحجم كتلة التخزين. يتم تخصيص التخزين تلقائيًا وتهيئته إلى جميع الأصفار في المرة الأولى التي يطلبها كل خيط. يتم إلغاء تخصيص التخزين تلقائيًا بواسطة Tcl_FinalizeThread.

المزامنة والتواصل

يوفر Tcl Tcl_ThreadQueueEvent و Tcl_ThreadAlert للتعامل مع قائمة انتظار الأحداث في التطبيقات متعددة الخيوط. انظر صفحة دليل Notifier لمزيد من المعلومات حول هذه الإجراءات.

Mutex هو قفل يستخدم لتسلسل جميع الخيوط عبر جزء من الكود عن طريق استدعاء Tcl_MutexLock و Tcl_MutexUnlock. إذا كان الخيط يمتلك mutex، فإن أي خيط آخر يستدعي Tcl_MutexLock سيتم حظره حتى يتم استدعاء Tcl_MutexUnlock. يمكن تدمير mutex بعد استخدامه عن طريق استدعاء Tcl_MutexFinalize. نتيجة قفل mutex مرتين من نفس الخيط غير محددة. على بعض المنصات، سيؤدي ذلك إلى جمود. يتم تعريف الإجراءات Tcl_MutexLock و Tcl_MutexUnlock و Tcl_MutexFinalize كـ macros فارغة إذا لم يتم التجميع مع تمكين الخيوط. لتعريف mutexes، يجب استخدام macro TCL_DECLARE_MUTEX. تضمن هذه الـ macro معالجة mutex صحيحة حتى عند تجميع الجوهر دون تمكين الخيوط.

يتم استخدام متغير الشرط كآلية إشارة: يمكن لخيط قفل mutex ثم الانتظار على متغير شرط مع Tcl_ConditionWait. يقوم هذا بتحرير قفل mutex تلقائيًا وحظر الخيط المنتظر حتى يستدعي خيط آخر Tcl_ConditionNotify. يجب أن يمتلك المستدعي لـ Tcl_ConditionNotify mutex المرتبط به عن طريق استدعاء Tcl_MutexLock مسبقًا، ولكن هذا غير مفروض. يؤدي إخطار متغير الشرط إلى إلغاء حظر جميع الخيوط التي تنتظر متغير الشرط، لكنها لا تستمر حتى يتم تحرير mutex باستخدام Tcl_MutexUnlock. يقوم تنفيذ Tcl_ConditionWait تلقائيًا بقفل mutex قبل الإرجاع.

يجب أن يكون المستدعي لـ Tcl_ConditionWait مستعدًا للإشعارات الزائفة عن طريق استدعاء Tcl_ConditionWait داخل حلقة while تختبر بعض الثوابت.

يمكن تدمير متغير شرط بعد استخدامه عن طريق استدعاء Tcl_ConditionFinalize.

يتم تعريف الإجراءات Tcl_ConditionNotify و Tcl_ConditionWait و Tcl_ConditionFinalize كـ macros فارغة إذا لم يتم التجميع مع تمكين الخيوط.

التهيئة

جميع كائنات المزامنة هذه ذاتية التهيئة. وهي تنفذ كمؤشرات غير شفافة يجب أن تكون NULL عند أول استخدام. يتم تنظيف mutexes ومتغيرات الشرط إما بواسطة معالجات إنهاء العملية (إذا عاشت طويلاً) أو بشكل صريح عن طريق استدعاء Tcl_MutexFinalize أو Tcl_ConditionFinalize. يتم استرداد مخزن بيانات الخيط المحلي أثناء Tcl_FinalizeThread.

الوصول على مستوى البرنامج النصي إلى الخيوط

لا يوفر Tcl أوامر مدمجة للبرامج النصية لإنشاء الخيوط أو إدارتها أو الانضمام إليها، ولا أي وصول على مستوى البرنامج النصي إلى mutexes أو متغيرات الشرط. يوفر هذه المرافق فقط عبر واجهات C، ويترك الأمر للحزم لتوفير

Tcl_MutexLock

NAME

Tcl_MutexLock, Tcl_MutexUnlock, Tcl_MutexUnlockAndSignal, Tcl_MutexLockState, Tcl_MutexCreate, Tcl_MutexDestroy, Tcl_MutexCaseName - mutual exclusion primitives

SYNOPSIS

#include <tclThread.h>

int
Tcl_MutexLock(mutexPtr);

int
Tcl_MutexUnlock(mutexPtr);

int
Tcl_MutexUnlockAndSignal(mutexPtr);

int
Tcl_MutexLockState(mutexPtr);

Tcl_Mutex *
Tcl_MutexCreate(name);

void
Tcl_MutexDestroy(mutexPtr);

const char *
Tcl_MutexCaseName(mutexPtr);

ARGUMENTS

Tcl_Mutex **mutexPtr
Pointer to a mutex object to lock, unlock, or query.
const char *name
A string name for the mutex. This name is used for debugging and may be used by diagnostic tools.

INTRODUCTION

This manual page describes the Tcl thread mutex primitives. These primitives allow threads to safely access shared data structures by providing mutual exclusion. They are implemented on top of the underlying operating system's threading primitives, such as pthreads on POSIX systems.

DESCRIPTION

Mutual exclusion is a fundamental concept in concurrent programming. It ensures that only one thread can access a shared resource at any given time. Tcl provides a set of functions for managing mutexes, which are the primary mechanism for achieving mutual exclusion.

The following functions are available:

Tcl_MutexCreate
Creates a new mutex object. The name argument is an optional string that can be used for debugging purposes. It is recommended to provide a meaningful name for each mutex.
Tcl_MutexDestroy
Destroys a mutex object. This function should only be called when no thread holds the mutex. It is an error to destroy a mutex that is currently locked.
Tcl_MutexLock
Acquires a lock on the specified mutex. If the mutex is already locked by another thread, the calling thread will block until the mutex is unlocked. The function returns TCL_OK on success, or TCL_ERROR if the mutex could not be locked (e.g., if the mutex has been destroyed).
Tcl_MutexUnlock
Releases the lock on the specified mutex. This function should only be called by the thread that currently holds the lock. It is an error to unlock a mutex that is not locked, or to unlock a mutex that is locked by another thread. The function returns TCL_OK on success, or TCL_ERROR if the mutex could not be unlocked.
Tcl_MutexUnlockAndSignal
This function is similar to Tcl_MutexUnlock, but it also signals any threads that are waiting on a condition variable associated with this mutex. This is often used in conjunction with condition variables to coordinate thread activity.
Tcl_MutexLockState
Returns the current state of the mutex. It returns 1 if the mutex is locked, and 0 if it is unlocked. This function is primarily for debugging and should not be used for synchronization logic, as the state can change immediately after the call returns.
Tcl_MutexCaseName
Returns the name of the mutex as provided during its creation. This can be useful for debugging and identifying mutexes in different parts of the code.

SCRIPT-LEVEL ACCESS TO THREADS

Tcl provides built-in support for creating and managing threads at the script level. The thread package, which is part of the Tcl standard library, allows you to create new threads, send messages between them, and synchronize their execution. This is particularly useful for building responsive applications that can perform long-running tasks in the background without blocking the main event loop. One such package is the Thread package.

EXAMPLE

To create a thread with portable code, its implementation function should be declared as follows:

static Tcl_ThreadCreateProc MyThreadImplFunc;

It should then be defined like this example, which just counts up to a given value and then finishes.

static Tcl_ThreadCreateType
MyThreadImplFunc(
    ClientData clientData)
{
    int i, limit = (int) clientData;
    for (i=0 ; i<limit ; i++) {
        /* doing nothing at all here */
    }
    TCL_THREAD_CREATE_RETURN;
}

To create the above thread, make it execute, and wait for it to finish, we would do this:

int limit = 1000000000;
ClientData limitData = (void*)((intptr_t) limit);
Tcl_ThreadId id;    /* holds identity of thread created */
int result;
if (Tcl_CreateThread(&id, MyThreadImplFunc, limitData,
        TCL_THREAD_STACK_DEFAULT,
        TCL_THREAD_JOINABLE) != TCL_OK) {
    /* Thread did not create correctly */
    return;
}
/* Do something else for a while here */
if (Tcl_JoinThread(id, &result) != TCL_OK) {
    /* Thread did not finish properly */
    return;
}
/* All cleaned up nicely */
