ARGUMENTS

const Tcl_ChannelType *typePtr (in)
Points to a structure containing the addresses of procedures that can be called to perform I/O and other functions on the channel.
const char *channelName (in)
The name of this channel, such as file3; must not be in use by any other channel. Can be NULL, in which case the channel is created without a name. If the created channel is assigned to one of the standard channels (stdin, stdout or stderr), the assigned channel name will be the name of the standard channel.
ClientData instanceData (in)
Arbitrary one-word value to be associated with this channel. This value is passed to procedures in typePtr when they are invoked.
int mask (in)
OR-ed combination of TCL_READABLE and TCL_WRITABLE to indicate whether a channel is readable and writable.
Tcl_Channel channel (in)
The channel to operate on.
int direction (in)
TCL_READABLE means the input handle is wanted; TCL_WRITABLE means the output handle is wanted.
ClientData *handlePtr (out)
Points to the location where the desired OS-specific handle should be stored.
int size (in)
The size, in bytes, of buffers to allocate in this channel.
int mask (in)
An OR-ed combination of TCL_READABLE, TCL_WRITABLE and TCL_EXCEPTION that indicates events that have occurred on this channel.
Tcl_Interp *interp (in)
Current interpreter. (can be NULL)
const char *optionName (in)
Name of the invalid option.
const char *optionList (in)
Specific options list (space separated words, without “-”) to append to the standard generic options list. Can be NULL for generic options error message only.

DESCRIPTION

Tcl uses a two-layered channel architecture. It provides a generic upper layer to enable C and Tcl programs to perform input and output using the same APIs for a variety of files, devices, sockets etc. The generic C APIs are described in the manual entry for Tcl_OpenFileChannel.

The lower layer provides type-specific channel drivers for each type of device supported on each platform. This manual entry describes the C APIs used to communicate between the generic layer and the type-specific channel drivers. It also explains how new types of channels can be added by providing new channel drivers.

Channel drivers consist of a number of components: First, each channel driver provides a Tcl_ChannelType structure containing pointers to functions implementing the various operations used by the generic layer to communicate with the channel driver. The Tcl_ChannelType structure and the functions referenced by it are described in the section TCL_CHANNELTYPE, below.

Second, channel drivers usually provide a Tcl command to create instances of that type of channel. For example, the Tcl open command creates channels that use the file and command channel drivers, and the Tcl socket command creates channels that use TCP sockets for network communication.

Third, a channel driver optionally provides a C function to open channel instances of that type. For example, Tcl_OpenFileChannel opens a channel that uses the file channel driver, and Tcl_OpenTcpClient opens a channel that uses the TCP network protocol. These creation functions typically use Tcl_CreateChannel internally to open the channel.

To add a new type of channel you must implement a C API or a Tcl command that opens a channel by invoking Tcl_CreateChannel. When your driver calls Tcl_CreateChannel it passes in a Tcl_ChannelType structure describing the driver's I/O procedures. The generic layer will then invoke the functions referenced in that structure to perform operations on the channel.

Tcl_CreateChannel opens a new channel and associates the supplied typePtr and instanceData with it. The channel is opened in the mode indicated by mask. For a discussion of channel drivers, their operations and the Tcl_ChannelType structure, see the section TCL_CHANNELTYPE, below.

Tcl_CreateChannel interacts with the code managing the standard channels. Once a standard channel was initialized either through a call to Tcl_GetStdChannel or a call to Tcl_SetStdChannel closing this standard channel will cause the next call to Tcl_CreateChannel to make the new channel the new standard channel too. See Tcl_StandardChannels for a general treatise about standard channels and the behavior of the Tcl library with regard to them.

Tcl_GetChannelInstanceData returns the instance data associated with the channel in channel. This is the same as the instanceData argument in the call to Tcl_CreateChannel that created this channel.

Tcl_GetChannelType returns a pointer to the Tcl_ChannelType structure used by the channel in the channel argument. This is the same as the typePtr argument in the call to Tcl_CreateChannel that created this channel.

Tcl_GetChannelName returns a string containing the name associated with the channel, or NULL if the channelName argument to Tcl_CreateChannel was NULL.

Tcl_GetChannelHandle places the OS-specific device handle associated with channel for the given direction in the *handlePtr location.

Tcl_GetChannelThread returns the thread ID of the thread that owns the channel.

Tcl_GetChannelMode returns the channel mode, which is an OR-ed combination of TCL_READABLE and TCL_WRITABLE.

Tcl_GetChannelBufferSize returns the size of the internal buffers used by the channel.

Tcl_SetChannelBufferSize sets the size of the internal buffers used by the channel to size bytes.

Tcl_NotifyChannel is called by Tcl to indicate that an event specified by mask has occurred on the channel. The channel driver can use this to perform any necessary processing. For example, if the channel is not currently readable but becomes readable, Tcl calls this function with TCL_READABLE set in the mask. The channel driver can then use this information to update its internal state or to trigger further actions.

Tcl_BadChannelOption is a utility procedure that may be called by a channel driver's option setting or getting procedures to report an error. It sets the interpreter's error string to an appropriate message indicating that optionName is not a valid option for the channel, and appends optionList if it is not NULL. It returns TCL_ERROR.

Tcl_IsChannelShared returns true if the channel is shared between multiple threads, false otherwise.

Tcl_IsChannelRegistered returns true if the channel is registered with the interpreter, false otherwise.

Tcl_IsChannelExisting returns true if a channel with the name channelName currently exists, false otherwise.

Tcl_CutChannel is called to detach a channel from its associated Tcl interpreter and delete it. The channel will no longer be accessible via Tcl commands. The underlying OS handle is not closed, but the Tcl channel structure is freed.

Tcl_SpliceChannel is called to attach a channel that has been previously cut to another Tcl interpreter. The channel becomes accessible via Tcl commands in the new interpreter.

Tcl_ClearChannelHandlers removes all input, output and exception handlers associated with the channel.

Tcl_ChannelBuffered returns the number of bytes currently in the output buffer for the channel.

The functions Tcl_ChannelName, Tcl_ChannelVersion, etc. are accessors used to retrieve information about the procedures in a Tcl_ChannelType structure.

TCL_CHANNELTYPE

A channel driver uses the Tcl_ChannelType structure to provide the generic channel code with a set of procedures to handle channel operations. The structure has the following definition:

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverFlushProc *flushProc;
    Tcl_DriverHandlerProc *handlerProc;
    Tcl_DriverThreadActionProc *threadActionProc;
    Tcl_DriverTruncateProc *truncateProc;
    Tcl_DriverWideSeekProc *wideSeekProc;
    Tcl_ChannelTypeVersion version;
    Tcl_DriverClose2Proc *close2Proc;
} Tcl_ChannelType;

The fields of the structure are:

typeName
A string name for this channel type, used for error messages.
blockModeProc
Procedure called to set the blocking mode of the channel. It should have the following signature: 
int blockModeProc(ClientData instanceData, int mode)
The mode argument is either TCL_BLOCKING or TCL_NONBLOCKING. The procedure should return TCL_OK on success, or TCL_ERROR on failure.
closeProc
Procedure called when the channel is closed. It should have the following signature: 
int closeProc(ClientData instanceData, Tcl_Interp *interp)
The procedure should close the underlying OS handle and free any associated resources. It should return TCL_OK on success, or TCL_ERROR on failure.
inputProc
Procedure called to read data from the channel. It should have the following signature: 
int inputProc(ClientData instanceData, char *buf, int toRead, Tcl_ErrnoInfo *ErrorInfo)
It should read at most toRead bytes from the channel into buf. It should return the number of bytes actually read. If an error occurs, it should fill in ErrorInfo and return -1.
outputProc
Procedure called to write data to the channel. It should have the following signature: 
int outputProc(ClientData instanceData, char *buf, int toWrite, Tcl_ErrnoInfo *ErrorInfo)
It should write at most toWrite bytes from buf to the channel. It should return the number of bytes actually written. If an error occurs, it should fill in ErrorInfo and return -1.
seekProc
Procedure called to seek to a position in the channel. It should have the following signature: 
int seekProc(ClientData instanceData, int offset, int mode)
It should seek to the position specified by offset relative to the beginning of the file (if mode is SEEK_SET), the current position (if mode is SEEK_CUR), or the end of the file (if mode is SEEK_END). It should return the new offset from the beginning of the file, or -1 on error.
setOptionProc
Procedure called to set channel options. It should have the following signature: 
int setOptionProc(ClientData instanceData, Tcl_Interp *interp, const char *optionName, const char *value)
It should set the option specified by optionName to value. It should return TCL_OK on success, or TCL_ERROR on failure.
getOptionProc
Procedure called to get channel options. It should have the following signature: 
int getOptionProc(ClientData instanceData, Tcl_Interp *interp, const char *optionName, const char *value)
It should set the interpreter's result to the value of the option specified by optionName. It should return TCL_OK on success, or TCL_ERROR on failure.
watchProc
Procedure called when the channel's readability or writability changes. It should have the following signature: 
void watchProc(ClientData instanceData, int mask)
The mask argument is an OR-ed combination of TCL_READABLE and TCL_WRITABLE, indicating the new state of the channel.
getHandleProc
Procedure called to get the OS-specific handle for the channel. It should have the following signature: 
int getHandleProc(ClientData instanceData, int direction, ClientData *handlePtr)
It should place the handle in handlePtr. It should return TCL_OK on success, or TCL_ERROR on failure.
flushProc
Procedure called to flush the channel's output buffer. It should have the following signature: 
int flushProc(ClientData instanceData, Tcl_Interp *interp)
It should flush any buffered output to the underlying channel. It should return TCL_OK on success, or TCL_ERROR on failure.
handlerProc
Procedure called when a channel event occurs. It should have the following signature: 
void handlerProc(ClientData instanceData, int mask)
The mask argument is an OR-ed combination of TCL_READABLE, TCL_WRITABLE, and TCL_EXCEPTION, indicating the event that occurred.
threadActionProc
Procedure called when a channel is moved to a different thread. It should have the following signature: 
void threadActionProc(ClientData instanceData, Tcl_ThreadId prevThread, Tcl_ThreadId newThread)
It should perform any necessary cleanup in the old thread and setup for the new thread.
truncateProc
Procedure called to truncate the channel at the current position. It should have the following signature: 
int truncateProc(ClientData instanceData, Tcl_WideInt length)
It should truncate the channel at the specified length. It should return TCL_OK on success, or TCL_ERROR on failure.
wideSeekProc
Procedure called to seek to a position in the channel using a 64-bit offset. It should have the following signature: 
Tcl_WideInt wideSeekProc(ClientData instanceData, Tcl_WideInt offset, int mode)
It should seek to the position specified by offset relative to the beginning of the file (if mode is SEEK_SET), the current position (if mode is SEEK_CUR), or the end of the file (if mode is SEEK_END). It should return the new offset from the beginning of the file, or -1 on error.
version
The version of the channel type. Currently, this should be TCL_CHANNEL_VERSION_1.
close2Proc
Procedure called when the channel is closed. It should have the following signature: 
void close2Proc(ClientData instanceData, Tcl_Interp *interp, int flags)
The flags argument is an OR-ed combination of flags such as TCL_CLOSE_READ, TCL_CLOSE_WRITE, and TCL_CLOSE_DETACH. The procedure should close the underlying OS handle and free any associated resources. Unlike closeProc, this procedure does not return an error code.

Deben devolver cero; de lo contrario, deben devolver un código de error POSIX no cero. Además, si ocurre un error y interp no es NULL, la procedencia debe almacenar un mensaje de error en el resultado del interp.

O bien, los canales que soporten cerrar ambos lados independientemente pueden establecer closeProc a TCL_CLOSE2PROC y establecer close2Proc a la dirección de una función que coincida con el siguiente esquema de prototipo:

typedef int Tcl_DriverClose2Proc(
        ClientData instanceData,
        Tcl_Interp *interp,
        int flags);

La close2Proc se llamará con flags establecida a una combinación OR de TCL_CLOSE_READ o TCL_CLOSE_WRITE para indicar que el driver debe cerrar el lado de lectura y/o de escritura del canal. El driver del canal puede llamarse para realizar operaciones adicionales en el canal después de que close2Proc haya cerrado una o ambas partes del canal. Si flags es 0 (cero), el driver debe cerrar el canal según la descripción anterior para closeProc. No se invocarán más operaciones en este instancio después de que close2Proc se haya llamado con todos los flags claros. En todos los casos, la close2Proc debe devolver cero si la operación de cierre fue exitosa; de lo contrario, debe devolver un código de error POSIX no cero. Además, si ocurre un error y interp no es NULL, la procedencia debe almacenar un mensaje de error en el resultado del interp.

Los valores de closeProc y close2Proc pueden obtenerse con Tcl_ChannelCloseProc o Tcl_ChannelClose2Proc, que devuelven un puntero a la función correspondiente.

INPUTPROC

El campo inputProc contiene la dirección de una función llamada por la capa genérica para leer datos de un dispositivo o archivo y almacenarlos en un búfer interno. InputProc debe corresponder al siguiente esquema de prototipo:

typedef int Tcl_DriverInputProc(
        ClientData instanceData,
        char *buf,
        int bufSize,
        int *errorCodePtr);

El instanceData es el mismo que el valor pasado a Tcl_CreateChannel cuando el canal fue creado. El argumento buf apunta a un arreglo de bytes en el cual se almacenará los datos de entrada del dispositivo, y el argumento bufSize indica cuántos bytes están disponibles en buf.

El argumento errorCodePtr apunta a una variable entera proporcionada por la capa genérica. Si ocurre un error, la función debe establecer esta variable a un código de error POSIX que identifique el error ocurrido.

La función debe leer los datos del dispositivo encapsulado por el canal y almacenarlos en buf. En caso de éxito, la función debe devolver un número no negativo indicando cuántos bytes se leyeron del dispositivo y almacenados en buf. En caso de error, la función debe devolver -1. Si ocurre un error después de haber leído algunos datos del dispositivo, esos datos se pierden.

Si inputProc puede determinar que el dispositivo de entrada tiene datos disponibles pero menos de lo solicitado por el argumento bufSize, la función debe intentar leer solo lo disponible y devolver sin bloquear. Si el dispositivo de entrada no tiene datos disponibles y el canal está en modo no bloqueante, la función debe devolver un error EAGAIN. Si el dispositivo de entrada no tiene datos disponibles y el canal está en modo bloqueante, la función debe bloquear por el tiempo más corto posible hasta que al menos un byte de datos pueda ser leído del dispositivo; luego, debe devolver todo el dato que pueda leer sin bloquear.

Este valor puede obtenerse con Tcl_ChannelInputProc, que devuelve un puntero a la función.

OUTPUTPROC

El campo outputProc contiene la dirección de una función llamada por la capa genérica para transferir datos del búfer interno al dispositivo de salida. OutputProc debe corresponder al siguiente esquema de prototipo:

typedef int Tcl_DriverOutputProc(
        ClientData instanceData,
        const char *buf,
        int toWrite,
        int *errorCodePtr);

El instanceData es el mismo que el valor pasado a Tcl_CreateChannel cuando el canal fue creado. El argumento buf contiene un arreglo de bytes a escribir en el dispositivo, y el argumento toWrite indica cuántos bytes se escribirán desde el argumento buf.

El argumento errorCodePtr apunta a una variable entera proporcionada por la capa genérica para devolver valores de errno desde la función. Si ocurre un error, la función debe establecer esta variable a un código de error POSIX que identifique el error. La función debe escribir los datos en buf en el dispositivo de salida encapsulado por el canal. En caso de éxito, la función debe devolver un número no negativo indicando cuántos bytes se escribieron en el dispositivo de salida. El valor de retorno es normally el mismo que toWrite, pero puede ser menor en algunos casos, como si la operación de salida es interrumpida por un señal. Si ocurre un error, la función debe devolver -1. En caso de error, algunos datos podrían haber sido escritos en el dispositivo.

Si el canal está en modo no bloqueante y el dispositivo de salida no puede absorber ningún dato, la función debe devolver -1 con un error EAGAIN sin escribir ningún dato.

Este valor puede obtenerse con Tcl_ChannelOutputProc, que devuelve un puntero a la función.

SEEKPROC AND WIDESEEKPROC

El campo seekProc contiene la dirección de una función llamada por la capa genérica para mover el punto de acceso en el cual se aplicarán las operaciones posteriores de entrada o salida. SeekProc debe corresponder al siguiente esquema de prototipo:

typedef int Tcl_DriverSeekProc(
        ClientData instanceData,
        long offset,
        int seekMode,
        int *errorCodePtr);

El instanceData es el mismo que el valor dado a Tcl_CreateChannel cuando este canal fue creado. Offset y seekMode tienen el mismo significado que en el procedimiento Tcl_Seek (descripto en el manual de Tcl_OpenFileChannel).

El errorCodePtr apunta a una variable entera proporcionada por la capa genérica para devolver los valores de errno de la función. La función debe establecer esta variable a un código de error POSIX si ocurre un error. La función debe almacenar un código de EINVAL si el tipo de canal no implementa el posicionamiento.

El valor de retorno es el nuevo punto de acceso o -1 en caso de error. Si ocurre un error, la función no debe mover el punto de acceso.

Si hay un campo no nulo de seekProc, el campo wideSeekProc puede contener la dirección de una función alternativa que maneje desplazamientos (es decir, mayores que 32 bits), permitiendo posiciones de archivo mayores que 2 GB. El wideSeekProc se llama en preferencia al seekProc, pero ambos deben estar definidos si el wideSeekProc está definido. El wideSeekProc debe corresponder al siguiente esquema de prototipo:

typedef Tcl_WideInt Tcl_DriverWideSeekProc(
        ClientData instanceData,
        Tcl_WideInt offset,
        int seekMode,
        int *errorCodePtr);

Los argumentos y los valores de retorno son lo mismo que con seekProc, excepto que el tipo de offset y el tipo de retorno son diferentes.

El campo seekProc puede obtenerse con Tcl_ChannelSeekProc, que devuelve un puntero a la función, y el campo wideSeekProc puede obtenerse con Tcl_ChannelWideSeekProc.

SETOPTIONPROC

El campo setOptionProc contiene la dirección de una función llamada por la capa genérica para establecer una opción específica del tipo de canal en un canal. setOptionProc debe corresponder al siguiente esquema de prototipo:

typedef int Tcl_DriverSetOptionProc(
        ClientData instanceData,
        Tcl_Interp *interp,
        const char *optionName,
        const char *newValue);

El optionName es el nombre de una opción a establecer, y newValue es el nuevo valor de esa opción, como una cadena. El instanceData es el mismo que el valor dado a Tcl_CreateChannel cuando este canal fue creado. La función debe realizar la acción específica para implementar el nuevo valor de la opción.

Algunas opciones son gestionadas por el código genérico y esta función nunca se llama para establecerlas, por ejemplo, -blockmode. Otras opciones son específicas a cada tipo de canal y la función setOptionProc del driver del canal se llama para implementarlas. El campo setOptionProc puede ser NULL, indicando que este tipo de canal no soporta opciones específicas.

Si el valor de la opción se modifica correctamente a la nueva valor, la función devuelve TCL_OK. Debe llamar a Tcl_BadChannelOption, que devuelve TCL_ERROR si el optionName no es reconocido. Si newValue especifica un valor no soportado o si ocurre un error en una llamada de sistema, la función debe dejar un mensaje de error en el resultado del interp si interp no es NULL. La función debe también llamar a Tcl_SetErrno para almacenar un código de error POSIX adecuado.

Este valor puede obtenerse con Tcl_ChannelSetOptionProc, que devuelve un puntero a la función.

GETOPTIONPROC

El campo getOptionProc contiene la dirección de una función llamada por la capa genérica para obtener el valor de una opción específica del tipo de canal en un canal. getOptionProc debe corresponder al siguiente esquema de prototipo:

typedef int Tcl_DriverGetOptionProc(
        ClientData instanceData,
        Tcl_Interp *interp,
        const char *optionName,
        Tcl_DString *optionValue);

El optionName es el nombre de una opción soportada por este tipo de canal. Si el nombre de la opción no es NULL, la función almacena el valor actual de la opción como una cadena en el Tcl dynamic string optionValue. Si optionName es NULL, la función almacena en optionValue una lista alternativa de todas las opciones soportadas y sus valores actuales. En caso de éxito, la función devuelve TCL_OK. Debe llamar a Tcl_BadChannelOption, que devuelve TCL_ERROR si el optionName no es reconocido. Si newValue especifica un valor no soportado o si ocurre un error en una llamada de sistema, la función debe dejar un mensaje de error en el resultado del interp si interp no es NULL. La función debe también llamar a Tcl_SetErrno para almacenar un código de error POSIX adecuado.

Este valor puede obtenerse con Tcl_ChannelGetOptionProc, que devuelve un puntero a la función.
