يُستخدم للإبلاغ عن الأخطاء وللبحث عن قناة مسجلة فيه.

اسم ملف محلي أو شبكة.
const char *mode (in)
يحدد كيفية الوصول إلى الملف. يمكن أن يكون له أي من القيم المسموح بها لوسيط mode لأمر Tcl open.

علامات صلاحيات POSIX مثل 0644. إذا تم إنشاء ملف جديد، فسيتم تعيين هذه الصلاحيات على الملف الذي تم إنشاؤه.
int argc (in)
عدد العناصر في argv.

int flags (in)
يحدد تصرف مقابض stdio في خط الأنابيب: مزيج تم إنشاؤه بواسطة OR من TCL_STDIN، TCL_STDOUT، TCL_STDERR، و TCL_ENFORCE_MODE. إذا تم تعيين TCL_STDIN، فإن الإدخال القياسي للطفل الأول في الأنبوب هو قناة الأنبوب، وإلا فهو نفس الإدخال القياسي للعملية المستدعية؛ وكذلك بالنسبة لـ TCL_STDOUT و TCL_STDERR. إذا لم يتم تعيين TCL_ENFORCE_MODE، فيمكن للأنبوب إعادة توجيه مقابض stdio لتجاوز مقابض stdio التي تم تعيين TCL_STDIN، TCL_STDOUT و TCL_STDERR لها. إذا تم تعيينه، فإن مثل هذه التوجيهات تسبب خطأ.
ClientData handle (in)
مقبض خاص بنظام التشغيل للإدخال/الإخراج إلى ملف. بالنسبة لنظام Unix، هذا هو واصف ملف، وبالنسبة لنظام Windows، هذا هو مقبض.

مزيج تم إنشاؤه بواسطة OR من TCL_READABLE و TCL_WRITABLE للإشارة إلى العمليات الصالحة على handle.

النقطة التي سيتم البحث بالنسبة إليها؛ تُستخدم مع offset لحساب نقطة الوصول الجديدة للقناة. القيم القانونية هي SEEK_SET، SEEK_CUR، و SEEK_END.

الوصف

توفر آلية قنوات Tcl آلية مستقلة عن الجهاز ومستقلة عن المنصة لإجراء عمليات الإدخال والإخراج المؤقت على مجموعة متنوعة من أنواع الملفات والمقابس والأجهزة. آلية القنوات قابلة للتوسيع إلى أنواع قنوات جديدة، عن طريق توفير برنامج تشغيل قناة منخفض المستوى للنوع الجديد؛ وصف واجهة برنامج تشغيل القناة موجود في إدخال الدليل لـ Tcl_CreateChannel. توفر آلية القنوات مخطط تخزين مؤقت مستوحى من الإدخال/الإخراج القياسي لنظام Unix، كما أنها تسمح بالإدخال/الإخراج غير المعيق على القنوات.

تتكون الإجراءات الموصوفة في دليل الدخول هذا من واجهات برمجة التطبيقات C للطبقة العامة لهيكلية القنوات. لوصف هيكلية برنامج تشغيل القنوات وكيفية تنفيذ برامج تشغيل القنوات لأنواع جديدة من القنوات، انظر إدخال الدليل لـ Tcl_CreateChannel.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel يفتح ملفًا محددًا بواسطة fileName ويعيد مقبض قناة يمكن استخدامه لإجراء عمليات إدخال وإخراج على الملف. هذه الواجهة مبنية على غرار إجراء fopen لمكتبة الإدخال / الإخراج القياسية في Unix. يشبه تركيب ومعنى جميع الوسائط تلك المقدمة في أمر Tcl open عند فتح ملف. إذا حدث خطأ أثناء فتح القناة، فإن Tcl_OpenFileChannel يعيد NULL ويسجل رمز خطأ POSIX يمكن استرجاعه باستخدام Tcl_GetErrno. بالإضافة إلى ذلك، إذا كان interp غير NULL، فإن Tcl_OpenFileChannel يترك رسالة خطأ في نتيجة interp بعد أي خطأ. اعتبارًا من Tcl 8.4، يجب استخدام واجهة القيمة Tcl_FSOpenFileChannel بدلاً من Tcl_OpenFileChannel حيثما أمكن.

القناة التي تم إنشاؤها حديثًا لا يتم تسجيلها في المفسر المزود؛ لتسجيلها، استخدم Tcl_RegisterChannel، الموصوفة أدناه. إذا تم إغلاق إحدى القنوات القياسية، stdin، stdout أو stderr سابقًا، فإن عملية إنشاء القناة الجديدة تقوم أيضًا بتعيينها كبديل للقناة القياسية.

TCL_OPENCOMMANDCHANNEL

يوفر Tcl_OpenCommandChannel واجهة على مستوى C لوظائف الأوامر exec و open. يقوم بإنشاء سلسلة من العمليات الفرعية المحددة بواسطة الوسائط argv و argc ويعيد قناة يمكن استخدامها للتواصل مع هذه العمليات الفرعية. يشير الوسيط flags إلى نوع الاتصال الذي سيكون موجودًا مع خط أنابيب الأوامر.

إذا تم تعيين العلامة TCL_STDIN، فإن الإدخال القياسي للعملية الفرعية الأولى سيتم ربطه بالقناة: الكتابة إلى القناة ستوفر مدخلات للعملية الفرعية. إذا لم يتم تعيين TCL_STDIN، فإن الإدخال القياسي للعملية الفرعية الأولى سيكون هو نفسه الإدخال القياسي لهذا التطبيق. إذا تم تعيين TCL_STDOUT، يمكن قراءة الإخراج القياسي من آخر عملية فرعية من القناة؛ وإلا فإنه يذهب إلى الإخراج القياسي لهذا التطبيق. إذا تم تعيين TCL_STDERR، يتم إرجاع مخرجات الخطأ القياسية لجميع العمليات الفرعية إلى القناة وتؤدي إلى حدوث خطأ عند إغلاق القناة؛ وإلا فإنها تذهب إلى الخطأ القياسي لهذا التطبيق. إذا لم يتم تعيين TCL_ENFORCE_MODE، فيمكن لـ argc و argv إعادة توجيه مقابض stdio لتجاوز TCL_STDIN و TCL_STDOUT و TCL_STDERR؛ إذا تم تعيينه، فإنه يعد خطأ لـ argc و argv لتجاوز قنوات stdio التي تم تعيين TCL_STDIN و TCL_STDOUT و TCL_STDERR لها.

إذا حدث خطأ أثناء فتح القناة، فإن Tcl_OpenCommandChannel يعيد NULL ويسجل رمز خطأ POSIX يمكن استرجاعه باستخدام Tcl_GetErrno. بالإضافة إلى ذلك، يترك Tcl_OpenCommandChannel رسالة خطأ في نتيجة المفسر. لا يمكن أن يكون interp NULL.

القناة التي تم إنشاؤها حديثًا لا يتم تسجيلها في المفسر المزود؛ لتسجيلها، استخدم Tcl_RegisterChannel، الموصوفة أدناه. إذا تم إغلاق إحدى القنوات القياسية، stdin، stdout أو stderr سابقًا، فإن عملية إنشاء القناة الجديدة تقوم أيضًا بتعيينها كبديل للقناة القياسية.

TCL_MAKEFILECHANNEL

تقوم Tcl_MakeFileChannel بإنشاء Tcl_Channel من مقبض ملف موجود خاص بالنظام الأساسي. القناة التي تم إنشاؤها حديثًا لا يتم تسجيلها في المفسر المزود؛ لتسجيلها، استخدم Tcl_RegisterChannel، الموصوفة أدناه. إذا تم إغلاق إحدى القنوات القياسية، stdin، stdout أو stderr سابقًا، فإن عملية إنشاء القناة الجديدة تقوم أيضًا بتعيينها كبديل للقناة القياسية.

TCL_GETCHANNEL

يعيد Tcl_GetChannel قناة بالاسم channelName المستخدم لإنشائها باستخدام Tcl_CreateChannel ومؤشر إلى مترجم Tcl في interp. إذا لم يتم تسجيل قناة بهذا الاسم في هذا المفسر، فإن الإجراء يعيد NULL. إذا كان الوسيط modePtr ليس NULL، فإنه يشير إلى متغير صحيح سيستقبل تركيبة ORed من TCL_READABLE و TCL_WRITABLE تصف ما إذا كانت القناة مفتوحة للقراءة والكتابة.

Tcl_GetChannelNames و Tcl_GetChannelNamesEx يكتبان أسماء القنوات المسجلة إلى نتيجة المفسر كقائمة. Tcl_GetChannelNamesEx سيقوم بتصفية هذه الأسماء وفقًا للنمط pattern. إذا كان pattern NULL، فلن يقوم بأي تصفية. القيمة المعادة هي TCL_OK إذا لم تحدث أخطاء أثناء الكتابة إلى النتيجة، وإلا فهي TCL_ERROR، ويتم ترك رسالة الخطأ في نتيجة المفسر.

TCL_REGISTERCHANNEL

تضيف Tcl_RegisterChannel قناة إلى مجموعة القنوات التي يمكن الوصول إليها في interp. بعد هذا الاستدعاء، يمكن لبرامج Tcl التي يتم تنفيذها في هذا المفسر الرجوع إلى القناة في عمليات الإدخال أو الإخراج باستخدام الاسم المقدم في استدعاء Tcl_CreateChannel. بعد هذا الاستدعاء، تصبح القناة ملكًا للمفسر، ولا يجب على المتصل استدعاء Tcl_Close للقناة؛ سيتم إغلاق القناة تلقائيًا عند إلغاء تسجيلها من المفسر.

يمكن للكود الذي يتم تنفيذه خارج أي مفسر Tcl استدعاء Tcl_RegisterChannel مع interp كـ NULL، للإشارة إلى أنه يرغب في الاحتفاظ بمرجع لهذه القناة. لاحقًا، يمكن تسجيل القناة في مفسر Tcl وسيتم إغلاقها فقط عندما يتم إجراء العدد المطابق من استدعاءات Tcl_UnregisterChannel. هذا يسمح للكود الذي يتم تنفيذه خارج أي مفسر بالاحتفاظ بمرجع آمن لقناة مسجلة أيضًا في مفسر Tcl.

يتفاعل هذا الإجراء مع الكود الذي يدير القنوات القياسية. إذا لم يتم تهيئة أي قنوات قياسية قبل الاستدعاء الأول لـ Tcl_RegisterChannel، فسيتم تهيئتها بواسطة هذا الاستدعاء. انظر Tcl_StandardChannels للحصول على معالجة عامة للقنوات القياسية وسلوك مكتبة Tcl فيما يتعلق بها.

TCL_UNREGISTERCHANNEL

يزيل Tcl_UnregisterChannel قناة من مجموعة القنوات التي يمكن الوصول إليها في interp. بعد هذا الاستدعاء، لن تتمكن برامج Tcl من استخدام اسم القناة للإشارة إلى القناة في هذا المفسر. إذا أزال هذا العمل آخر تسجيل للقناة في أي مفسر، يتم أيضًا إغلاق القناة وتدميرها.

يمكن للكود غير المرتبط بمفسر Tcl استدعاء Tcl_UnregisterChannel مع interp كـ NULL، للإشارة إلى Tcl بأنه لم يعد يحتفظ بمرجع لهذه القناة. إذا كان هذا هو المرجع الأخير للقناة، فسيتم إغلاقها الآن. Tcl_UnregisterChannel مشابه جدًا لـ Tcl_DetachChannel باستثناء أنه سيقوم أيضًا بإغلاق القناة إذا لم تعد هناك مراجع لها.

TCL_DETACHCHANNEL

يزيل Tcl_DetachChannel قناة من مجموعة القنوات التي يمكن الوصول إليها في interp. بعد هذا الاستدعاء، لن تتمكن برامج Tcl من استخدام اسم القناة للإشارة إلى القناة في هذا المفسر. بالإضافة إلى ذلك، لا يكون لهذا الأمر أي تأثير آخر. لا يمكن استخدامه على القنوات القياسية (stdout، stderr، stdin)، وسيعيد TCL_ERROR إذا تم تمرير إحدى هذه القنوات.

يمكن للكود غير المرتبط بمفسر Tcl استدعاء Tcl_DetachChannel مع interp كـ NULL، للإشارة إلى Tcl بأنه لم يعد يحتفظ بمرجع لهذه القناة. إذا كان هذا هو المرجع الأخير للقناة، بخلاف Tcl_UnregisterChannel، فلن يتم إغلاقه.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel تختبر ما إذا كانت القناة هي إحدى القنوات القياسية الثلاث، stdin، stdout أو stderr. إذا كان الأمر كذلك، فإنها تعيد 1، وإلا 0.

لا يتم بذل أي محاولة للتحقق مما إذا كانت القناة المعطاة أو القنوات القياسية مهيأة أو صالحة بأي شكل آخر.

TCL_CLOSE

Tcl_Close تدمر القناة channel، والتي يجب أن تشير إلى قناة مفتوحة حاليًا. يجب ألا تكون القناة مسجلة في أي مفسر عند استدعاء Tcl_Close. يتم مسح الإخراج المخزن مؤقتًا إلى جهاز الإخراج للقناة قبل تدمير القناة، ويتم تجاهل أي إدخال مخزن مؤقتًا. إذا كانت هذه قناة مانعة، فإن الاستدعاء لا يعود حتى يتم إرسال جميع البيانات المخزنة مؤقتًا بنجاح إلى جهاز الإخراج للقناة. إذا كانت هذه قناة غير مانعة وهناك إخراج مخزن مؤقتًا لا يمكن كتابته دون حظر، فإن الاستدعاء يعود فورًا؛ يتم مسح الإخراج في الخلفية وسيتم إغلاق القناة بمجرد إخراج جميع البيانات المخزنة مؤقتًا. في هذه الحالة، لا يتم الإبلاغ عن أخطاء أثناء المسح.

إذا تم إغلاق القناة بنجاح، فإن Tcl_Close يعيد TCL_OK. إذا حدث خطأ، فإن Tcl_Close يعيد TCL_ERROR ويسجل رمز خطأ POSIX يمكن استرجاعه باستخدام Tcl_GetErrno. إذا تم إغلاق القناة بشكل متزامن وحدث خطأ أثناء إغلاق القناة وكان interp غير NULL، يتم ترك رسالة خطأ في نتيجة المفسر.

ملاحظة: ليس من الآمن استدعاء Tcl_Close على قناة تم تسجيلها باستخدام Tcl_RegisterChannel؛ انظر وثائق Tcl_RegisterChannel، أعلاه، للتفاصيل. إذا تم تقديم القناة على الإطلاق كوسيط chan في استدعاء لـ Tcl_RegisterChannel، يجب عليك بدلاً من ذلك استخدام Tcl_UnregisterChannel، والذي سيستدعي داخليًا Tcl_Close عندما تتم مطابقة جميع استدعاءات Tcl_RegisterChannel باستدعاءات مطابقة لـ Tcl_UnregisterChannel.

TCL_GETCHANNELOPTION

The Tcl_GetChannelOption procedure retrieves the value of the option named optionName for the channel channel. The value is placed in the interpreter's result using Tcl_DStringAppend. If optionName is not recognized, Tcl_GetChannelOption returns TCL_ERROR and leaves an error message in the interpreter's result; otherwise, it returns TCL_OK. The valid option names and their meanings are described in the manual entry for the Tcl fconfigure command. Other options may be added by individual channel types. These channel-specific options are described in the manual entry for the Tcl command that creates a channel of that type; for example, the additional options for TCP-based channels are described in the manual entry for the Tcl socket command.

The options are retrieved by the channel driver for the channel. The channel driver should implement the option retrieval using a series of calls to Tcl_DStringAppendElement. The various preexisting options and their possible values are described in the manual entry for the Tcl fconfigure command. Other options can be added by each channel type. These channel type specific options are described in the manual entry for the Tcl command that creates a channel of that type; for example, the additional options for TCP-based channels are described in the manual entry for the Tcl socket command. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR and calls Tcl_SetErrno to store an appropriate POSIX error code.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption sets a new value newValue for an option optionName on channel. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR; in addition, if interp is non-NULL, Tcl_SetChannelOption leaves an error message in the interpreter's result.

TCL_EOF

Tcl_Eof returns a nonzero value if channel encountered an end of file during the last input operation.

TCL_INPUTBLOCKED

Tcl_InputBlocked returns a nonzero value if channel is in nonblocking mode and the last input operation returned less data than requested because there was insufficient data available. The call always returns zero if the channel is in blocking mode.

TCL_INPUTBUFFERED

Tcl_InputBuffered returns the number of bytes of input currently buffered in the internal buffers for a channel. If the channel is not open for reading, this function always returns zero.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered returns the number of bytes of output currently buffered in the internal buffers for a channel. If the channel is not open for writing, this function always returns zero.

PLATFORM ISSUES

The handles returned from Tcl_GetChannelHandle depend on the platform and the channel type. On Unix platforms, the handle is always a Unix file descriptor as returned from the open system call. On Windows platforms, the handle is a file HANDLE when the channel was created with Tcl_OpenFileChannel, Tcl_OpenCommandChannel, or Tcl_MakeFileChannel. Other channel types may return a different type of handle on Windows platforms.
