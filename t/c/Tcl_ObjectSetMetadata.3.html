الوصف

الكائنات هي كيانات مصنفة لها مجموعة من العمليات ("الطرق") مرتبطة بها. الفئات هي كائنات يمكنها تصنيع كائنات. يمكن عرض كل فئة ككائن بحد ذاتها؛ يمكن استرجاع عرض الكائن باستخدام Tcl_GetClassAsObject التي تعيد دائمًا الكائن عند تطبيقها على فئة غير مدمرة، ويمكن عرض كائن كفئة بمساعدة Tcl_GetObjectAsClass (التي تعيد إما الفئة، أو NULL إذا كان الكائن ليس فئة). يمكن البحث عن كائن باستخدام الدالة Tcl_GetObjectFromObj، التي تعيد إما كائنًا أو NULL (مع رسالة خطأ في نتيجة المفسر) إذا لم يمكن العثور على الكائن. الطريقة الصحيحة للبحث عن فئة بالاسم هي البحث عن الكائن بهذا الاسم، ثم استخدام Tcl_GetObjectAsClass.

كل كائن له أمر ومساحة اسم خاصة به مرتبطة به. يمكن استرجاع الأمر باستخدام الدالة Tcl_GetObjectCommand، واسم الكائن (وبالتالي اسم الأمر) باستخدام Tcl_GetObjectName، ويمكن استرجاع مساحة الاسم باستخدام الدالة Tcl_GetObjectNamespace. لاحظ أن مرجع Tcl_Obj الذي تعيده Tcl_GetObjectName هو مرجع مشترك. يمكنك أيضًا الحصول على ما إذا كان الكائن قد تم وضع علامة عليه للحذف باستخدام Tcl_ObjectDeleted (يعيد صحيحًا إذا بدأ حذف الكائن)؛ يمكن أن يكون هذا مفيدًا أثناء معالجة الطرق.

يتم إنشاء مثيلات للفئات باستخدام Tcl_NewObjectInstance، التي تنشئ كائنًا من أي فئة (والتي يتم استدعاؤها داخليًا بواسطة كل من طرق create و new لفئة oo::class). تأخذ معلمات تحدد اختياريًا اسم الكائن ومساحة الاسم لإنشائهما، والتي تصف الحجج التي سيتم تمريرها إلى المنشئ (constructor) الخاص بالفئة (إن وجد). ستكون نتيجة الدالة إما مرجعًا للكائن الذي تم إنشاؤه حديثًا، أو NULL إذا فشل الإنشاء (عندما سيتم ترك رسالة خطأ في نتيجة المفسر). بالإضافة إلى ذلك، يمكن نسخ الكائنات باستخدام Tcl_CopyObjectInstance التي تنشئ نسخة من كائن دون تشغيل أي منشئات.

لاحظ أن إدارة دورة حياة الكائنات تتم داخليًا ضمن TclOO، ولا تستخدم Tcl_Preserve. *لا يجوز وضع مقبض Tcl_Object في بنية C بعمر افتراضي مختلف عن عمر الكائن؛* يجب عليك استخدام اسم أمر الكائن (كما تم استرجاعه باستخدام Tcl_GetObjectName) بدلاً من ذلك. من الآمن استخدام مقبض Tcl_Object طوال فترة استدعاء طريقة على هذا الكائن؛ لا تصبح المقابض غير صالحة طالما أن هناك استدعاءً بارزًا على كائنها (حتى لو كانت العملية الوحيدة المضمونة لتكون آمنة عليها هي Tcl_ObjectDeleted؛ العمليات الأخرى مضمونة فقط للعمل على الكائنات غير المدمرة).

بيانات وصفية للكائنات والفئات

يمكن أن يكون لكل كائن وكل فئة كميات عشوائية من البيانات الوصفية المرفقة بها، والتي لا يرفق بها الكائن أو الفئة أي معنى بخلاف ما هو موصوف في مثيل بنية Tcl_ObjectMetadataType. يتم وصف البيانات الوصفية المراد إرفاقها بنوع البيانات الوصفية (المعطاة في المعامل metaTypePtr) ومؤشر عشوائي (المعامل metadata) التي يتم تمريرها إلى Tcl_ObjectSetMetadata و Tcl_ClassSetMetadata، ويمكن استرجاع قطعة معينة من البيانات الوصفية بالنظر إلى نوعها باستخدام Tcl_ObjectGetMetadata و Tcl_ClassGetMetadata. إذا كان المعامل metadata إلى Tcl_ObjectSetMetadata أو Tcl_ClassSetMetadata هو NULL، فسيتم إزالة البيانات الوصفية إذا كانت مرفقة، وستكون نتائج Tcl_ObjectGetMetadata و Tcl_ClassGetMetadata هي NULL إذا لم تكن البيانات الوصفية من النوع المعطى مرفقة. ليس خطأً طلب أو إزالة قطعة من البيانات الوصفية لم تكن مرفقة.

بنية TCL_OBJECTMETADATATYPE

محتويات بنية Tcl_ObjectMetadataType هي كما يلي:

typedef const struct {
    int version;
    const char *name;
    Tcl_ObjectMetadataDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_ObjectMetadataType;

يسمح حقل version بالتوسع المستقبلي للبنية، ويجب دائمًا تعريفه على أنه مساوٍ لـ TCL_OO_METADATA_VERSION_CURRENT. يوفر حقل name اسمًا قابلاً للقراءة من قبل الإنسان للنوع، وهو مخصص لتصحيح الأخطاء.

يعطي حقل deleteProc دالة من نوع Tcl_ObjectMetadataDeleteProc تستخدم لحذف قطعة بيانات وصفية معينة، ويتم استدعاؤها عند استبدال البيانات الوصفية المرفقة أو إزالتها؛ يجب ألا يكون الحقل NULL.

يعطي حقل cloneProc دالة تستخدم لنسخ قطعة بيانات وصفية (تستخدم عند إنشاء نسخة من كائن باستخدام Tcl_CopyObjectInstance)؛ إذا كانت NULL، فسيتم نسخ البيانات الوصفية مباشرة.

Tcl_ObjectSetMetadata, Tcl_ObjectGetMetadata, Tcl_ObjectDeleteMetadata, Tcl_CloneProc, Tcl_ObjectMapMethodNameProc

NAME

Tcl_ObjectSetMetadata, Tcl_ObjectGetMetadata, Tcl_ObjectDeleteMetadata, Tcl_CloneProc, Tcl_ObjectMapMethodNameProc - manage arbitrary data associated with TclOO objects and classes

SYNOPSIS

#include <tclOO.h>

int
Tcl_ObjectSetMetadata(
        Tcl_Interp *interp,
        Tcl_Object object,
        const char *key,
        Tcl_Obj *value);

Tcl_Obj *
Tcl_ObjectGetMetadata(
        Tcl_Object object,
        const char *key);

int
Tcl_ObjectDeleteMetadata(
        Tcl_Object object,
        const char *key);

typedef int
Tcl_CloneProc(
        Tcl_Interp *interp,
        ClientData srcMetadata,
        ClientData *dstMetadataPtr);

typedef int
Tcl_ObjectMapMethodNameProc(
        Tcl_Interp *interp,
        Tcl_Object object,
        Tcl_Class *startClsPtr,
        Tcl_Obj *methodNameObj);

ARGUMENTS

Tcl_Interp *interp
Interpreter to use for error reporting.
Tcl_Object object
The object to query, modify or manage.
const char *key
A string key identifying the metadata.
Tcl_Obj *value
An object representing the value of the metadata.
ClientData srcMetadata
Metadata to be cloned.
ClientData *dstMetadataPtr
Pointer to where the cloned metadata should be written.
Tcl_Class *startClsPtr
The class to start method lookup from.
Tcl_Obj *methodNameObj
The name of the method being looked up.

DESCRIPTION

These procedures provide a mechanism for associating arbitrary metadata with TclOO objects and classes. Metadata is stored as key-value pairs, where the key is a string and the value is a Tcl object.

Tcl_ObjectSetMetadata associates the given value object with the given key string in the specified object. If metadata with the same key already exists, it is overwritten.

Tcl_ObjectGetMetadata retrieves the Tcl object associated with the given key string in the specified object. If no metadata with that key exists, it returns NULL.

Tcl_ObjectDeleteMetadata removes the metadata associated with the given key string from the specified object. If no metadata with that key exists, the call has no effect.

These functions are primarily intended for use by TclOO's internal mechanisms, such as object cloning and method lookup.

OBJECT AND CLASS METADATA

TclOO allows arbitrary metadata to be associated with objects and classes. This metadata can be used to control various aspects of object behavior, such as cloning and method dispatch.

The metadata is stored as key-value pairs, where the key is a string and the value is a Tcl object.

Tcl_ObjectSetMetadata associates the given value object with the given key string in the specified object. If metadata with the same key already exists, it is overwritten.

Tcl_ObjectGetMetadata retrieves the Tcl object associated with the given key string in the specified object. If no metadata with that key exists, it returns NULL.

Tcl_ObjectDeleteMetadata removes the metadata associated with the given key string from the specified object. If no metadata with that key exists, the call has no effect.

TCL_OBJECTDELETEPROC FUNCTION SIGNATURE

The Tcl_ObjectDeleteProc callback is used to free any resources associated with object metadata when the object is destroyed.

typedef void Tcl_ObjectDeleteProc(
        ClientData metadata);

The metadata argument gives the address of the metadata to be deleted.

TCL_CLONEPROC FUNCTION SIGNATURE

Functions matching this signature are used to create copies of metadata associated with a class or object.

typedef int Tcl_CloneProc(
        Tcl_Interp *interp,
        ClientData srcMetadata,
        ClientData *dstMetadataPtr);

The interp argument gives a place to write an error message when the attempt to clone the object is to fail, in which case the clone procedure must also return TCL_ERROR; it should return TCL_OK otherwise. The srcMetadata argument gives the address of the metadata to be cloned, and the cloned metadata should be written into the variable pointed to by dstMetadataPtr; a NULL should be written if the metadata is to not be cloned but the overall object copy operation is still to succeed.

OBJECT METHOD NAME MAPPING

It is possible to control, on a per-object basis, what methods are invoked when a particular method is invoked. Normally this is done by looking up the method name in the object and then in the class hierarchy, but fine control of exactly what the value used to perform the look up is afforded through the ability to set a method name mapper callback via Tcl_ObjectSetMethodNameMapper (and its introspection counterpart, Tcl_ObjectGetMethodNameMapper, which returns the current mapper). The current mapper (if any) is invoked immediately before looking up what chain of method implementations is to be used.

TCL_OBJECTMAPMETHODNAMEPROC FUNCTION SIGNATURE

The Tcl_ObjectMapMethodNameProc callback is defined as follows:

typedef int Tcl_ObjectMapMethodNameProc(
        Tcl_Interp *interp,
        Tcl_Object object,
        Tcl_Class *startClsPtr,
        Tcl_Obj *methodNameObj);

If the result is TCL_OK, the remapping is assumed to have been done. If the result is TCL_ERROR, an error message will have been left in interp and the method call will fail. If the result is TCL_BREAK, the standard method name lookup rules will be used; the behavior of other result codes is currently undefined. The object parameter says which object is being processed. The startClsPtr parameter points to a variable that contains the first class to provide a definition in the method chain to process, or NULL if the whole chain is to be processed (the argument itself is never NULL); this variable may be updated by the callback. The methodNameObj parameter gives an unshared object containing the name of the method being invoked, as provided by the user; this object may be updated by the callback.
