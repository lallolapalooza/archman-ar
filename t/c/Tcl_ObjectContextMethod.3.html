الوصف

الطريقة هي عملية يتم تنفيذها على كائن وهي مرتبطة بهذا الكائن. يجب ربط كل طريقة إما بكائن أو بفئة؛ ترتبط الطرق المرتبطة بفئة بجميع مثيلات تلك الفئة (المباشرة وغير المباشرة).

بالنظر إلى طريقة، يمكن العثور على الكيان الذي أعلن عنها باستخدام Tcl_MethodDeclarerClass الذي يعيد الفئة التي ترتبط بها الطريقة (أو NULL إذا لم تكن الطريقة مرتبطة بأي فئة) و Tcl_MethodDeclarerObject الذي يعيد الكائن الذي ترتبط به الطريقة (أو NULL إذا لم تكن الطريقة مرتبطة بكائن). يمكن استرداد اسم الطريقة باستخدام Tcl_MethodName وما إذا كانت الطريقة مُصدّرة يتم استردادها باستخدام Tcl_MethodIsPublic. يمكن أيضًا فحص نوع الطريقة بدرجة محدودة؛ تعيد الدالة Tcl_MethodIsType ما إذا كانت الطريقة من نوع معين، وتعيين clientData لكل طريقة للمتغير المشار إليه بواسطة clientDataPtr (إذا كان غير NULL) إذا تطابق النوع.

إنشاء الطريقة

يتم إنشاء الطرق بواسطة Tcl_NewMethod و Tcl_NewInstanceMethod، اللتان تنشئان طريقة مرتبطة بفئة أو كائن على التوالي. في كلتا الحالتين، يعطي المعامل nameObj اسم الطريقة المراد إنشاؤها، وتشير العلامة isPublic إلى ما إذا كان ينبغي تصدير الطريقة مبدئيًا، ويصف المعامل methodTypePtr تطبيق الطريقة (راجع قسم أنواع الطرق أدناه) ويعطي المعامل clientData بعض البيانات الخاصة بالتطبيق والتي يتم تمريرها إلى تطبيق الطريقة عند استدعائها.

عندما يكون المعامل nameObj لـ Tcl_NewMethod هو NULL، يتم إنشاء طريقة بدون اسم، والتي تستخدم للمنشئات والمدمرات. يجب تثبيت المنشئات في فئتها باستخدام الدالة Tcl_ClassSetConstructor، ويجب تثبيت المدمرات (التي يجب ألا تتطلب أي وسائط) في فئتها باستخدام الدالة Tcl_ClassSetDestructor. لا ينبغي استخدام الطرق بدون أسماء لأي غرض آخر، ويجب عدم استخدام الطرق المسماة كمنشئات أو مدمرات. لاحظ أيضًا أن methodTypePtr NULL يستخدم لتوفير إشارة داخلية، ولا ينبغي استخدامه في رمز العميل.

سياقات استدعاء الطريقة

عند استدعاء طريقة، يتم تمرير مرجع سياق استدعاء الطريقة كوسيطة للدالة التطبيق. يمكن فحص هذا السياق لتوفير معلومات حول المستدعي، ولكن لا ينبغي الاحتفاظ به بعد انتهاء استدعاء الطريقة.

يمكن استرداد الطريقة التي يتم استدعاؤها من السياق باستخدام Tcl_ObjectContextMethod، ويمكن استرداد الكائن الذي تسبب في استدعاء الطريقة باستخدام Tcl_ObjectContextObject. يتم قراءة عدد الوسائط التي يجب تخطيها (مثل اسم الكائن واسم الطريقة في استدعاء طريقة عادي) باستخدام Tcl_ObjectContextSkippedArgs، ويمكن للسياق أيضًا الإبلاغ عما إذا كان يعمل كمرشح لطريقة أخرى من خلال Tcl_ObjectContextIsFiltering.

أثناء تنفيذ طريقة، قد يختار تطبيق الطريقة استدعاء مراحل سلسلة استدعاءات الطريقة التي تأتي بعد تطبيق الطريقة الحالي. يتم ذلك (جوهريًا للأمر next) باستخدام Tcl_ObjectContextInvokeNext. لاحظ أن هذه الدالة لا تعالج مكدس إطار الاستدعاء، على عكس الأمر next؛ إذا دفع تطبيق الطريقة إطارًا واحدًا أو أكثر إلى المكدس كجزء من تطبيقه، فهو مسؤول أيضًا عن إزالة هذه الإطارات مؤقتًا من المكدس أثناء تنفيذ الدالة Tcl_ObjectContextInvokeNext. لاحظ أيضًا أن سياق استدعاء الطريقة لا يتم حذفه مطلقًا أثناء تنفيذ هذه الدالة.

أنواع الطرق

يتم وصف أنواع الطرق بواسطة مؤشر إلى هيكل Tcl_MethodType، والذي يتم تعريفه كالتالي:

typedef struct {
    int version;
    const char *name;
    Tcl_MethodCallProc *callProc;
    Tcl_MethodDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_MethodType;

يسمح مجال version بالتوسع المستقبلي للهيكل، ويجب دائمًا تعريفه بنفس قيمة TCL_OO_METHOD_VERSION_CURRENT. يوفر مجال name اسمًا سهل القراءة للنوع، وهو القيمة التي يتم كشفها عبر أوامر Tcl info class methodtype و info object methodtype.

يعطي مجال callProc دالة يتم استدعاؤها عند استدعاء الطريقة؛ يجب ألا تكون NULL مطلقًا.

يعطي مجال deleteProc دالة تستخدم لحذف طريقة معينة، ويتم استدعاؤها عند استبدال الطريقة أو إزالتها؛ إذا كان المجال NULL، فمن المفترض أن clientData الخاصة بالطريقة لا تحتاج إلى إجراء خاص للحذف.

مجال cloneProc هو إما دالة تستخدم لنسخ clientData الخاصة بالطريقة (كجزء من Tcl_CopyObjectInstance) أو NULL للإشارة إلى أنه يمكن نسخ clientData مباشرة.

TCL_METHODCALLPROC FUNCTION SIGNATURE

Functions matching this signature are called when the method is invoked.

typedef int Tcl_MethodCallProc(
        ClientData clientData,
        Tcl_Interp *interp,
        Tcl_ObjectContext objectContext,
        int objc,
        Tcl_Obj *const *objv);

The clientData argument to a Tcl_MethodCallProc is the value that was given when the method was created, the interp is a place in which to execute scripts and access variables as well as being where to put the result of the method, and the objc and objv fields give the parameter objects to the method. The calling context of the method can be discovered through the objectContext argument, and the return value from a Tcl_MethodCallProc is any Tcl return code (e.g. TCL_OK, TCL_ERROR).

TCL_METHODDELETEPROC FUNCTION SIGNATURE

Functions matching this signature are used when a method is deleted, whether through a new method being created or because the object or class is deleted.

typedef void Tcl_MethodDeleteProc(
        ClientData clientData);

The clientData argument to a Tcl_MethodDeleteProc will be the same as the value passed to the clientData argument to Tcl_NewMethod or Tcl_NewInstanceMethod when the method was created.

TCL_CLONEPROC FUNCTION SIGNATURE

Functions matching this signature are used to copy a method when the object or class is copied using Tcl_CopyObjectInstance (or oo::copy).

typedef int Tcl_CloneProc(
        Tcl_Interp *interp,
        ClientData oldClientData,
        ClientData *newClientDataPtr);

The interp argument gives a place to write an error message when the attempt to clone the object is to fail, in which case the clone procedure must also return TCL_ERROR; it should return TCL_OK otherwise. The oldClientData field to a Tcl_CloneProc gives the value from the method being copied from, and the newClientDataPtr field will point to a variable in which to write the value for the method being copied to.
