الوصف

الطريقة هي عملية تُجرى على كائن وهي مرتبطة بالكائن. يجب ربط كل طريقة إما بكائن أو بفئة؛ ترتبط الطرق المرتبطة بفئة بجميع مثيلات تلك الفئة (المباشرة وغير المباشرة).

بالنظر إلى طريقة، يمكن العثور على الكيان الذي أعلن عنها باستخدام Tcl_MethodDeclarerClass الذي يُرجع الفئة التي ترتبط بها الطريقة (أو NULL إذا لم ترتبط الطريقة بأي فئة) و Tcl_MethodDeclarerObject الذي يُرجع الكائن الذي ترتبط به الطريقة (أو NULL إذا لم ترتبط الطريقة بكائن). يمكن استرداد اسم الطريقة باستخدام Tcl_MethodName وما إذا كانت الطريقة مُصدَّرة يتم استردادها باستخدام Tcl_MethodIsPublic. يمكن أيضًا فحص نوع الطريقة إلى درجة محدودة؛ تُرجع الدالة Tcl_MethodIsType ما إذا كانت الطريقة من نوع معين، وتُعين clientData لكل طريقة إلى المتغير الذي يشير إليه clientDataPtr إذا (كان غير NULL) إذا تمت مطابقة النوع.

إنشاء الطرق

يتم إنشاء الطرق بواسطة Tcl_NewMethod و Tcl_NewInstanceMethod، والتي تنشئ طريقة مرتبطة بفئة أو كائن على التوالي. في كلتا الحالتين، يعطي الوسيط nameObj اسم الطريقة المراد إنشاؤها، ويذكر الوسيط isPublic ما إذا كان يجب تصدير الطريقة مبدئيًا، ويصف الوسيط methodTypePtr تنفيذ الطريقة (راجع قسم أنواع الطرق أدناه) ويوفر الوسيط clientData بعض البيانات الخاصة بالتنفيذ التي يتم تمريرها إلى تنفيذ الطريقة عند استدعائها.

عندما يكون الوسيط nameObj للدالة Tcl_NewMethod هو NULL، يتم إنشاء طريقة غير مسماة، والتي تُستخدم للمنشئات والمدمرات. يجب تثبيت المنشئات في فئتها باستخدام الدالة Tcl_ClassSetConstructor، ويجب تثبيت المدمرات (التي يجب ألا تتطلب أي وسائط) في فئتها باستخدام الدالة Tcl_ClassSetDestructor. لا يجب استخدام الطرق غير المسماة لأي غرض آخر، ويجب عدم استخدام الطرق المسماة كمنشئات أو مدمرات. لاحظ أيضًا أن methodTypePtr NULL يُستخدم لتوفير إشارة داخلية، ويجب عدم استخدامه في كود العميل.

سياقات استدعاء الطرق

عند استدعاء طريقة، يتم تمرير مرجع لسياق استدعاء الطريقة كوسيطة واحدة لوظيفة التنفيذ. يمكن فحص هذا السياق لتوفير معلومات حول المتصل، ولكن لا ينبغي الاحتفاظ به بعد انتهاء استدعاء الطريقة.

يمكن استرداد الطريقة التي يتم استدعاؤها من السياق باستخدام Tcl_ObjectContextMethod، ويمكن استرداد الكائن الذي تسبب في استدعاء الطريقة باستخدام Tcl_ObjectContextObject. يتم قراءة عدد الوسائط التي يجب تخطيها (مثل اسم الكائن واسم الطريقة في استدعاء طريقة عادي) باستخدام Tcl_ObjectContextSkippedArgs، ويمكن للسياق أيضًا الإبلاغ عما إذا كان يعمل كمرشح لطريقة أخرى من خلال Tcl_ObjectContextIsFiltering.

خلال تنفيذ طريقة، قد يختار تنفيذ الطريقة استدعاء مراحل سلسلة استدعاء الطريقة التي تأتي بعد تنفيذ الطريقة الحالية. يتم ذلك (وهو جوهر الأمر next) باستخدام Tcl_ObjectContextInvokeNext. لاحظ أن هذه الدالة لا تعالج مكدس إطارات الاستدعاء، على عكس الأمر next؛ إذا كان تنفيذ الطريقة قد دفع إطارًا أو أكثر من الإطارات الإضافية إلى المكدس كجزء من تنفيذه، فإنه يكون مسؤولاً أيضًا عن إزالة تلك الإطارات مؤقتًا من المكدس أثناء تنفيذ الدالة Tcl_ObjectContextInvokeNext. لاحظ أيضًا أن سياق استدعاء الطريقة لا يتم حذفه مطلقًا أثناء تنفيذ هذه الدالة.

أنواع الطرق

يتم وصف أنواع الطرق بواسطة مؤشر إلى بنية Tcl_MethodType، والتي يتم تعريفها على النحو التالي:

typedef struct {
    int version;
    const char *name;
    Tcl_MethodCallProc *callProc;
    Tcl_MethodDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_MethodType;

يوفر حقل version للتوسع المستقبلي للبنية، ويجب دائمًا تعريفه على أنه مساوٍ لـ TCL_OO_METHOD_VERSION_CURRENT. يوفر حقل name اسمًا قابلاً للقراءة البشرية للنوع، وهو القيمة التي يتم كشفها عبر أوامر Tcl info class methodtype و info object methodtype.

يعطي حقل callProc دالة يتم استدعاؤها عند استدعاء الطريقة؛ يجب ألا تكون NULL أبدًا.

يعطي حقل deleteProc دالة تُستخدم لحذف طريقة معينة، ويتم استدعاؤها عند استبدال الطريقة أو إزالتها؛ إذا كان الحقل NULL، فمن المفترض أن clientData للطريقة لا يحتاج إلى إجراء خاص للحذف.

حقل cloneProc إما دالة تُستخدم لنسخ clientData للطريقة (كجزء من Tcl_CopyObjectInstance) أو NULL للإشارة إلى أنه يمكن نسخ clientData مباشرة.

توقيع دالة Tcl_MethodCallProc

يجب أن يكون لتنفيذ الطريقة التوقيع التالي:

typedef int (*Tcl_MethodCallProc)(ClientData clientData, Tcl_Interp *interp,
    Tcl_ObjectContext context, int objc, Tcl_Obj *const objv[]);

الوسيط clientData هو القيمة التي تم توفيرها عند إنشاء الطريقة.

الوسيط interp هو المفسر الذي يتم فيه استدعاء الطريقة.

الوسيط context هو السياق الخاص باستدعاء الطريقة.

الوسيط objc هو عدد الوسائط التي تم تمريرها إلى الطريقة.

الوسيط objv هو مصفوفة من الوسائط التي تم تمريرها إلى الطريقة. يتم استخدام الوسيط skip الذي تم تمريره إلى Tcl_ObjectContextInvokeNext لتحديد عدد الوسائط التي يجب تخطيها من بداية objv. بالنسبة لاستدعاءات الطرق العادية، سيكون هذا عادةً 2 (اسم الكائن واسم الطريقة)؛ بالنسبة للطرق التي يتم استدعاؤها من خلال الأوامر object و class، قد يكون 0.

يجب أن تُرجع تنفيذ الطريقة TCL_OK أو TCL_ERROR. في حالة النجاح، يجب أن تكون نتيجة الطريقة هي الكائن الموجود في interp->result. في حالة الخطأ، يجب أن تحتوي interp->result على رسالة خطأ.

توقيع دالة Tcl_MethodDeleteProc

يجب أن يكون للدالة الاختيارية لحذف الطريقة التوقيع التالي:

typedef void (*Tcl_MethodDeleteProc)(ClientData clientData);

يتم استدعاء هذه الدالة عند إزالة الطريقة من فئتها أو كائنها.

توقيع دالة Tcl_CloneProc

يجب أن يكون للدالة الاختيارية لنسخ الطريقة التوقيع التالي:

typedef ClientData (*Tcl_CloneProc)(ClientData clientData);

يتم استدعاء هذه الدالة عند نسخ كائن يحتوي على هذه الطريقة.

NAME

Tcl_NewMethod, Tcl_NewInstanceMethod, Tcl_NewConstructor, Tcl_MethodCallProc, Tcl_MethodDeleteProc, Tcl_CloneProc - create new methods and constructors for TclOO objects

SYNOPSIS

#include <tclOO.h>

int

int
Tcl_NewConstructor(Tcl_Interp *interp, Tcl_Object object, Tcl_MethodCallProc *callProc, ClientData clientData, Tcl_MethodDeleteProc *deleteProc);
typedef int Tcl_MethodCallProc(ClientData clientData, Tcl_Interp *interp, Tcl_ObjectContext objectContext, int objc, Tcl_Obj *const *objv);

typedef int Tcl_CloneProc(Tcl_Interp *interp, ClientData oldClientData, ClientData *newClientDataPtr);

ARGUMENTS

ClientData clientData (input)
Arbitrary data associated with the method or constructor.
Tcl_Interp *interp (input)
The Tcl interpreter.
Tcl_Object object (input)
The object to which the method or constructor is to be added.
const char *methodName (input)
The name of the method to be added.
Tcl_MethodCallProc *callProc (input)
The C procedure to be called when the method or constructor is invoked.
Tcl_MethodDeleteProc *deleteProc (input)
The C procedure to be called when the method or constructor is deleted.
Tcl_ObjectContext objectContext (input)
The context of the method invocation.
int objc (input)
The number of arguments to the method.
Tcl_Obj *const *objv (input)
The arguments to the method.
ClientData oldClientData (input)
The client data of the method being copied.
ClientData *newClientDataPtr (output)
A pointer to where the client data for the new method should be stored.

DESCRIPTION

These functions are used to add methods and constructors to TclOO objects and classes. A method is a procedure that can be called on an object, while a constructor is a special method that is called when an object is created.

Tcl_NewMethod adds a new method to the specified object. The method is called methodName, and it is implemented by the C procedure callProc. The clientData argument is arbitrary data that is passed to the callProc and deleteProc. The deleteProc is called when the method is deleted.

Tcl_NewInstanceMethod is similar to Tcl_NewMethod, but it adds the method to the instance configuration of the object, meaning that the method will be inherited by any objects created from this object. If the object is a class, the method will be added to the class configuration, and thus inherited by all instances of the class.

Tcl_NewConstructor adds a new constructor to the specified object. A constructor is a special method that is called when an object is created. It is implemented by the C procedure callProc.

TCL_METHODCALLPROC FUNCTION SIGNATURE

Functions matching this signature are called when the method is invoked.

typedef int Tcl_MethodCallProc(
        ClientData clientData,
        Tcl_Interp *interp,
        Tcl_ObjectContext objectContext,
        int objc,
        Tcl_Obj *const *objv);

The clientData argument to a Tcl_MethodCallProc is the value that was given when the method was created, the interp is a place in which to execute scripts and access variables as well as being where to put the result of the method, and the objc and objv fields give the parameter objects to the method. The calling context of the method can be discovered through the objectContext argument, and the return value from a Tcl_MethodCallProc is any Tcl return code (e.g. TCL_OK, TCL_ERROR).

TCL_METHODDELETEPROC FUNCTION SIGNATURE

Functions matching this signature are used when a method is deleted, whether through a new method being created or because the object or class is deleted.

typedef void Tcl_MethodDeleteProc(
        ClientData clientData);

The clientData argument to a Tcl_MethodDeleteProc will be the same as the value passed to the clientData argument to Tcl_NewMethod or Tcl_NewInstanceMethod when the method was created.

TCL_CLONEPROC FUNCTION SIGNATURE

Functions matching this signature are used to copy a method when the object or class is copied using Tcl_CopyObjectInstance (or oo::copy).

typedef int Tcl_CloneProc(
        Tcl_Interp *interp,
        ClientData oldClientData,
        ClientData *newClientDataPtr);

The interp argument gives a place to write an error message when the attempt to clone the object is to fail, in which case the clone procedure must also return TCL_ERROR; it should return TCL_OK otherwise. The oldClientData field to a Tcl_CloneProc gives the value from the method being copied from, and the newClientDataPtr field will point to a variable in which to write the value for the method being copied to.
