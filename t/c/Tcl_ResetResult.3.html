الوصف

الإجراءات الموصوفة هنا هي أدوات مساعدة للتلاعب بقيمة نتيجة Tcl في مفسر Tcl. قد تكون نتيجة المفسر إما قيمة Tcl أو سلسلة نصية. على سبيل المثال، تقوم Tcl_SetObjResult و Tcl_SetResult بتعيين نتيجة المفسر إلى قيمة وسلسلة نصية على التوالي. وبالمثل، تقوم Tcl_GetObjResult و Tcl_GetStringResult بإرجاع نتيجة المفسر كقيمة وكـ سلسلة نصية. تحافظ الإجراءات دائمًا على اتساق شكلي السلسلة النصية والقيمة لنتيجة المفسر. على سبيل المثال، إذا تم استدعاء Tcl_SetObjResult لتعيين النتيجة إلى قيمة، ثم تم استدعاء Tcl_GetStringResult، فسوف ترجع التمثيل النصي للقيمة.

تقوم Tcl_SetObjResult بترتيب objPtr لتكون النتيجة لـ interp، لتحل محل أي نتيجة موجودة. تظل النتيجة تشير إلى القيمة التي يشير إليها objPtr. يتم زيادة عدد مراجع objPtr نظرًا لوجود مرجع جديد لها من interp. يتم تقليل عدد مراجع أي قيمة نتيجة قديمة وتحرير القيمة النتيجة القديمة إذا لم تعد هناك مراجع لها.

تقوم Tcl_GetObjResult بإرجاع نتيجة interp كقيمة. لا يتم زيادة عدد مراجع القيمة؛ إذا احتاج المستدعي إلى الاحتفاظ بمؤشر طويل الأجل للقيمة، فيجب عليه استخدام Tcl_IncrRefCount لزيادة عدد مراجعها للحفاظ عليها من التحرير المبكر أو التغيير العرضي.

تقوم Tcl_SetResult بترتيب result لتكون النتيجة للأمر Tcl الحالي في interp، لتحل محل أي نتيجة موجودة. يحدد المعامل freeProc كيفية إدارة مساحة التخزين للمعامل result؛ تتم مناقشته في القسم معامل TCL_FREEPROC لـ TCL_SETRESULT أدناه. إذا كانت result تساوي NULL، فيتم تجاهل freeProc وتقوم Tcl_SetResult بإعادة تهيئة نتيجة interp للإشارة إلى سلسلة نصية فارغة.

تقوم Tcl_GetStringResult بإرجاع نتيجة interp كسلسلة نصية. إذا تم تعيين النتيجة إلى قيمة عن طريق استدعاء Tcl_SetObjResult، فسيتم تحويل شكل القيمة إلى سلسلة نصية وإرجاعه. إذا كان التمثيل النصي للقيمة يحتوي على بايتات فارغة، فإن هذا التحويل سيؤدي إلى فقدان المعلومات. لهذا السبب، يتم تشجيع المبرمجين على كتابة أجهزتهم لاستخدام إجراءات واجهة برمجة التطبيقات (API) الجديدة واستدعاء Tcl_GetObjResult بدلاً من ذلك.

تقوم Tcl_ResetResult بمسح نتيجة interp وترك النتيجة في حالتها الطبيعية الفارغة المهيأة. إذا كانت النتيجة قيمة، فسيتم تقليل عدد مراجعها وستظل النتيجة تشير إلى قيمة غير مشتركة تمثل سلسلة فارغة. إذا كانت النتيجة سلسلة نصية مخصصة ديناميكيًا، فسيتم تحرير ذاكرتها وستبقى النتيجة كسلسلة فارغة. تقوم Tcl_ResetResult أيضًا بمسح حالة الخطأ التي تديرها Tcl_AddErrorInfo، Tcl_AddObjErrorInfo، و Tcl_SetErrorCode.

تجعل Tcl_AppendResult من السهل بناء نتائج Tcl على أجزاء. تأخذ كل من معاملاتها result وتقوم بإلحاقها بالترتيب إلى النتيجة الحالية المرتبطة بـ interp. إذا كانت النتيجة في حالتها الفارغة المهيأة (على سبيل المثال، تم استدعاء إجراء أمر للتو أو تم استدعاء Tcl_ResetResult للتو)، فإن Tcl_AppendResult تعين النتيجة إلى تسلسل معاملاتها result. قد يتم استدعاء Tcl_AppendResult بشكل متكرر مع إنتاج قطع إضافية من النتيجة. تهتم Tcl_AppendResult بجميع قضايا إدارة مساحة التخزين المتعلقة بإدارة نتيجة interp، مثل تخصيص منطقة نتيجة أكبر إذا لزم الأمر. كما أنها تدير التحويل من وإلى حقل result لـ interp للتعامل مع التوافق مع الإصدارات السابقة مع الامتدادات القديمة. يمكن تمرير أي عدد من معاملات result في استدعاء واحد؛ يجب أن يكون آخر معامل في القائمة هو (char *)NULL.

Tcl_AppendResultVA هي نفس Tcl_AppendResult باستثناء أنها تأخذ قائمة معاملات بدلاً من أخذ عدد متغير من المعاملات.

تقوم Tcl_TransferResult بنقل حالة المفسر من sourceInterp إلى targetInterp. يجب أن يكون قد تم إنشاء المفسرين في نفس الخيط. إذا كان sourceInterp و targetInterp متساويين، فلن يتم فعل شيء. بخلاف ذلك، تقوم Tcl_TransferResult بنقل النتيجة من sourceInterp إلى targetInterp، وتعيد تعيين النتيجة في sourceInterp. كما أنها تنقل قاموس خيارات الإرجاع كما يتم التحكم فيه بواسطة رمز الإرجاع code بنفس الطريقة التي تقوم بها Tcl_GetReturnOptions.

الواجهات المهملة

إجراءات السلسلة النصية القديمة

يتم إهمال استخدام الإجراءات التالية لأنها تتلاعب بنتيجة Tcl كسلسلة نصية. الإجراءات مثل Tcl_SetObjResult التي تتلاعب بالنتيجة كقيمة يمكن أن تكون أكثر كفاءة.

Tcl_AppendElement مشابه لـ Tcl_AppendResult من حيث أنها تسمح ببناء النتائج على أجزاء. ومع ذلك، تأخذ Tcl_AppendElement معامل element واحد فقط وتقوم بإلحاق هذا المعامل بالنتيجة الحالية كعنصر قائمة Tcl صحيح. تضيف Tcl_AppendElement شرطات خلفية أو أقواس معقوفة إذا لزم الأمر لضمان أنه يمكن تحليل نتيجة interp كقائمة وأن element سيتم استخراجه كعنصر واحد. في ظل الظروف العادية، تضيف Tcl_AppendElement حرف مسافة إلى نتيجة interp قبل إضافة عنصر القائمة الجديد مباشرة، بحيث تكون عناصر القائمة في النتيجة مفصولة بشكل صحيح. ومع ذلك، إذا كان عنصر القائمة الجديد هو الأول في قائمة أو قائمة فرعية (أي أن النتيجة الحالية لـ interp فارغة، أو تتكون من الحرف الواحد “{”، أو تنتهي بالأحرف “ {”) فلن يتم إضافة مسافة.

تقوم Tcl_FreeResult بتنفيذ جزء من عمل Tcl_ResetResult. تقوم بتحرير الذاكرة المرتبطة بنتيجة interp. كما أنها تعين interp->freeProc إلى صفر، ولكنها لا تغير interp->result أو تمسح حالة الخطأ. يتم استخدام Tcl_FreeResult بشكل شائع عندما يكون الإجراء على وشك استبدال قيمة نتيجة بأخرى.

الوصول المباشر إلى INTERP->RESULT

كان مسموحًا في السابق للبرامج بقراءة وكتابة interp->result مباشرة للتلاعب بنتيجة المفسر. لم تعد رؤوس Tcl تسمح بهذا الوصول افتراضيًا، ويجب تحديث كود C الذي لا يزال يفعل ذلك لاستخدام su

char *
Tcl_GetStringResult(interp);

ARGUMENTS

Tcl_Interp *interp (in) Interpreter to which the result should be attached.
const char *string (in) String to set or append.
Tcl_FreeProc *freeProc (in) Procedure to call to free string when it's no longer needed.
const char *format (in) A printf-style format string.
Tcl_Obj *objPtr (in) The object to set as the result.

DESCRIPTION

These procedures are used by Tcl command implementations to manage the result returned to the Tcl interpreter. In the Tcl object-based results model, Tcl_SetObjResult and Tcl_GetObjResult are preferred. Older code that uses string-based results may still use Tcl_SetResult, Tcl_AppendResult, Tcl_AppendPrintf, and Tcl_GetStringResult.

Tcl_ResetResult clears the existing result for the interpreter. The storage for the old result is released using the freeProc that was specified when the result was last set. This is typically called at the beginning of a command's execution, before setting a new result.

Tcl_SetResult sets the result of the interpreter to string. The freeProc argument specifies how Tcl should manage the storage for string. If string is no longer needed, Tcl will call freeProc with string as its argument. If freeProc is TCL_STATIC, it means string refers to static storage that will not be modified until the next call to Tcl_Eval. If freeProc is TCL_DYNAMIC, it means string was allocated using Tcl_Alloc and Tcl will free it using Tcl_Free when it is no longer needed. If freeProc is TCL_VOLATILE, it means string points to memory that might be overwritten when Tcl_SetResult returns; Tcl will make a copy of the string. If freeProc is any other value, it is the address of a procedure that Tcl will call to free the storage. If Tcl_SetResult is called when the interpreter already has a string result, the old result is disposed of according to its freeProc. Tcl_SetResult returns TCL_OK if the result was set successfully, and TCL_ERROR otherwise.

Tcl_AppendResult appends one or more null-terminated strings to the interpreter's result. The strings are appended in the order they are given, separated by null characters internally. This means that the final result is a single string. If the interpreter has no result currently, Tcl_AppendResult acts like Tcl_SetResult, using Tcl_Static as the freeProc. If interp already has a result, the new strings are appended to it. The storage for the new strings is managed using TCL_STATIC. If the existing result was dynamically allocated, Tcl_AppendResult will reallocate its storage to hold the appended strings. It returns TCL_OK if the result was appended successfully, and TCL_ERROR otherwise.

Tcl_AppendPrintf is similar to Tcl_AppendResult, but it takes a printf-style format string and variable arguments. It formats the arguments according to format and appends the resulting string to the interpreter's result. The internal management of the result string is handled by Tcl.

Tcl_SetObjResult sets the interpreter's result to the object specified by objPtr. This is the preferred method for setting results in modern Tcl code. The object's reference count is incremented.

Tcl_GetObjResult returns a pointer to the interpreter's result object. The caller should not modify the returned object directly; instead, they should use Tcl object manipulation procedures. The reference count of the returned object is not affected.

Tcl_GetStringResult returns the interpreter's result as a null-terminated string. If the result is not already a string, it will be converted to one. Note that this may involve memory allocation if the result is not already a string or cannot be represented efficiently as one. This function returns a pointer to the string representation of the result. The caller should not modify the string, as it may be shared or managed by Tcl. This function is primarily for compatibility with older code.

DEPRECATED INTERFACES

The following interfaces are deprecated and should be avoided in new code. They are mentioned here for the benefit of maintaining older code. These interfaces access the interpreter's internal result string buffer. Modern code should use the object-based interfaces: Tcl_GetObjResult, Tcl_GetStringResult, Tcl_SetObjResult, and Tcl_SetResult. As a migration aid, access can be restored with the compiler directive

#define USE_INTERP_RESULT

but this is meant only to offer life support to otherwise dead code.

THE TCL_FREEPROC ARGUMENT TO TCL_SETRESULT

Tcl_SetResult's freeProc argument specifies how the Tcl system is to manage the storage for the result argument. If Tcl_SetResult or Tcl_SetObjResult are called at a time when interp holds a string result, they do whatever is necessary to dispose of the old string result (see the Tcl_Interp manual entry for details on this).

If freeProc is TCL_STATIC it means that result refers to an area of static storage that is guaranteed not to be modified until at least the next call to Tcl_Eval. If freeProc is TCL_DYNAMIC it means that result was allocated with a call to Tcl_Alloc and is now the property of the Tcl system. Tcl_SetResult will arrange for the string's storage to be released by calling Tcl_Free when it is no longer needed. If freeProc is TCL_VOLATILE it means that result points to an area of memory that is likely to be overwritten when Tcl_SetResult returns (e.g. it points to something in a stack frame). In this case Tcl_SetResult will make a copy of the string in dynamically allocated storage and arrange for the copy to be the result for the current Tcl command.

If freeProc is not one of the values TCL_STATIC, TCL_DYNAMIC, and TCL_VOLATILE, then it is the address of a procedure that Tcl should call to free the string. This allows applications to use non-standard storage allocators. When Tcl no longer needs the storage for the string, it will call freeProc. FreeProc should have arguments and result that match the type Tcl_FreeProc:

typedef void Tcl_FreeProc(
        char *blockPtr);

When freeProc is called, its blockPtr will be set to the value of result passed to Tcl_SetResult.
