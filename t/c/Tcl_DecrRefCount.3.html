Tcl_DecrRefCount(3)

الحزمة: tcl

التراخيص: TCL

NAME

Tcl_DecrRefCount, Tcl_IncrRefCount, Tcl_IsShared, Tcl_DuplicateObj - manage reference counts for Tcl values

SYNOPSIS

#include <tcl.h>

void
Tcl_IncrRefCount(objPtr)
void
Tcl_DecrRefCount(objPtr)
int
Tcl_IsShared(objPtr)
Tcl_Obj *
Tcl_DuplicateObj(objPtr)

ARGUMENTS

Tcl_Obj *objPtr (in)
Pointer to the Tcl value object.

DESCRIPTION

Tcl values are mutable objects that contain internal representations of their data. For example, a value might have an internal representation as a string and also as an integer. Tcl manages these values using reference counting to ensure that storage for a value is not freed until it is no longer in use. The Tcl_IncrRefCount and Tcl_DecrRefCount macros manage these reference counts. The Tcl_IsShared function and Tcl_DuplicateObj procedure are used to handle shared values.

When a Tcl value object is first created using functions like Tcl_NewObj or Tcl_NewStringObj, its reference count is initialized to 0. The reference count is incremented by Tcl_IncrRefCount whenever a new reference to the value is created. This typically happens when a value is stored in a variable, passed as an argument to a procedure, or stored in a data structure that needs to maintain a reference to it.

When a reference to a Tcl value is no longer needed, Tcl_DecrRefCount should be called. This macro decrements the reference count. If the reference count drops to zero as a result of this call, the storage for the value object (including any internal representations) is freed. It is crucial to call Tcl_DecrRefCount exactly once for every time Tcl_IncrRefCount was called for a given value to prevent memory leaks or premature freeing of the value.

A value is considered "shared" if its reference count is greater than 1. The Tcl_IsShared function returns true (1) if the reference count of the value pointed to by objPtr is greater than 1, and false (0) otherwise.

When a command procedure needs to modify a Tcl value that might be shared, it must first ensure that it has its own private copy of the value. Modifying a shared value directly would affect all other references to that value. To obtain a private copy, the procedure should first call Tcl_IsShared. If the value is shared, the procedure should then call Tcl_DuplicateObj. Tcl_DuplicateObj creates a new Tcl value object that is a copy of the original object pointed to by objPtr. The new object is returned and has a reference count of 0. The caller is then responsible for managing the reference count of this new object (typically by calling Tcl_IncrRefCount if it intends to keep a reference to it).

If Tcl_IsShared returns false, it means the value is not currently shared, and the command procedure can safely modify it directly without needing to duplicate it. In this case, the procedure effectively "owns" the value and is responsible for managing its reference count appropriately (e.g., decrementing it when it's no longer needed).

The internal representation of a Tcl object can change over time. For instance, when a value is first created as a string, it may later be converted to an integer if operations requiring an integer representation are performed on it. The Tcl_GetIntFromObj procedure can be used to obtain an integer representation of a value. If the value does not already have an integer representation, Tcl will attempt to convert it. This conversion process might involve creating a new internal representation and updating the object's type pointer. Procedures that modify values, such as list manipulation commands, may need to invalidate the string representation of a value after changing its internal representation. This is typically done using Tcl_InvalidateStringRep. A list element can be extracted using Tcl_ListObjIndex. The same value holding the same string value can have several different internal representations at different times. Extension writers can also force a value to be converted from one type to another using the Tcl_ConvertToType procedure. Only programmers that create new value types need to be concerned about how this is done. A procedure defined as part of the value type's implementation creates a new internal representation for a value and changes its typePtr. See the man page for Tcl_RegisterObjType to see how to create a new value type.

EXAMPLE OF THE LIFETIME OF A VALUE

As an example of the lifetime of a value, consider the following sequence of commands:

set x 123

This assigns to x an untyped value whose bytes member points to 123 and length member contains 3. The value's typePtr member is NULL.

puts "x is $x"

x's string representation is valid (since bytes is non-NULL) and is fetched for the command.

incr x

The incr command first gets an integer from x's value by calling Tcl_GetIntFromObj. This procedure checks whether the value is already an integer value. Since it is not, it converts the value by setting the value's internal representation to the integer 123 and setting the value's typePtr to point to the integer Tcl_ObjType structure. Both representations are now valid. incr increments the value's integer internal representation then invalidates its string representation (by calling Tcl_InvalidateStringRep) since the string representation no longer corresponds to the internal representation.

puts "x is now $x"

The string representation of x's value is needed and is recomputed. The string representation is now 124 and both representations are again valid.

STORAGE MANAGEMENT OF VALUES

Tcl values are allocated on the heap and are shared as much as possible to reduce storage requirements. Reference counting is used to determine when a value is no longer needed and can safely be freed. A value just created by Tcl_NewObj or Tcl_NewStringObj has refCount 0. The macro Tcl_IncrRefCount increments the reference count when a new reference to the value is created. The macro Tcl_DecrRefCount decrements the count when a reference is no longer needed and, if the value's reference count drops to zero, frees its storage. A value shared by different code or data structures has refCount greater than 1. Incrementing a value's reference count ensures that it will not be freed too early or have its value change accidentally.

As an example, the bytecode interpreter shares argument values between calling and called Tcl procedures to avoid having to copy values. It assigns the call's argument values to the procedure's formal parameter variables. In doing so, it calls Tcl_IncrRefCount to increment the reference count of each argument since there is now a new reference to it from the formal parameter. When the called procedure returns, the interpreter calls Tcl_DecrRefCount to decrement each argument's reference count. When a value's reference count drops less than or equal to zero, Tcl_DecrRefCount reclaims its storage. Most command procedures do not have to be concerned about reference counting since they use a value's value immediately and do not retain a pointer to the value after they return. However, if they do retain a pointer to a value in a data structure, they must be careful to increment its reference count since the retained pointer is a new reference.

Command procedures that directly modify values such as those for lappend and linsert must be careful to copy a shared value before changing it. They must first check whether the value is shared by calling Tcl_IsShared. If the value is shared they must copy the value by using Tcl_DuplicateObj; this returns a new duplicate of the original value that has refCount 0. If the value is not shared, the command procedure “owns” the value and can safely modify it directly. For example, the following code appears in the command procedure that implements linsert. This procedure modifies the list value passed to it in objv[1] by inserting objc-3 new elements before index.

listPtr = objv[1];
if (Tcl_IsShared(listPtr)) {
    listPtr = Tcl_DuplicateObj(listPtr);
}
result = Tcl_ListObjReplace(interp, listPtr, index, 0,
        (objc-3), &(objv[3]));

As another example, incr's command procedure must check whether the variable's value is shared before incrementing the integer in its internal representation. If it is shared, it needs to duplicate the value in order to avoid accidentally changing values in other data structures.

إدارة تخزين القيم

يتم تخصيص قيم Tcl في الذاكرة العشوائية ويتم مشاركتها قدر الإمكان لتقليل متطلبات التخزين. يتم استخدام عد المراجع لتحديد متى لم تعد القيمة مطلوبة ويمكن تحريرها بأمان. قيمة تم إنشاؤها للتو بواسطة Tcl_NewObj أو Tcl_NewStringObj لديها refCount 0. يقوم الماكرو Tcl_IncrRefCount بزيادة عد المراجع عند إنشاء مرجع جديد للقيمة. يقوم الماكرو Tcl_DecrRefCount بتقليل العد عند عدم الحاجة إلى مرجع، وإذا انخفض عد المراجع للقيمة إلى الصفر، فإنه يحرر تخزينها. قيمة مشتركة بين هياكل بيانات أو رموز مختلفة لديها refCount أكبر من 1. زيادة عد المراجع للقيمة تضمن أنها لن تُحرر مبكرًا أو تتغير قيمتها عن طريق الخطأ.

كمثال، يقوم مفسر البايت كود بمشاركة قيم الوسيطات بين إجراءات Tcl التي تستدعي وتُستدعى لتجنب نسخ القيم. يقوم بتعيين قيم وسيطات الاستدعاء للمتغيرات الرسمية للإجراء. عند القيام بذلك، يستدعي Tcl_IncrRefCount لزيادة عد المراجع لكل وسيطة نظرًا لوجود مرجع جديد لها الآن من المعلمة الرسمية. عند عودة الإجراء المستدعى، يستدعي المفسر Tcl_DecrRefCount لتقليل عد المراجع لكل وسيطة. عندما ينخفض عد المراجع للقيمة إلى أقل من أو يساوي الصفر، يقوم Tcl_DecrRefCount باستعادة تخزينها. لا تحتاج معظم إجراءات الأوامر إلى الاهتمام بعد المراجع لأنها تستخدم قيمة القيمة فورًا ولا تحتفظ بمؤشر للقيمة بعد عودتها. ومع ذلك، إذا احتفظت بمؤشر لقيمة في هيكل بيانات، فيجب عليها توخي الحذر لزيادة عد المراجع الخاص بها نظرًا لأن المؤشر المحتفظ به هو مرجع جديد.

يجب على إجراءات الأوامر التي تعدل القيم مباشرة مثل تلك الخاصة بـ lappend و linsert توخي الحذر لنسخ قيمة مشتركة قبل تغييرها. يجب عليها أولاً التحقق مما إذا كانت القيمة مشتركة عن طريق استدعاء Tcl_IsShared. إذا كانت القيمة مشتركة، فيجب عليها نسخ القيمة باستخدام Tcl_DuplicateObj ؛ هذا يعيد نسخة جديدة من القيمة الأصلية التي لديها refCount 0. إذا لم تكن القيمة مشتركة، فإن إجراء الأمر "يملك" القيمة ويمكنه تعديلها بأمان مباشرة. على سبيل المثال، الكود التالي يظهر في إجراء الأمر الذي ينفذ linsert. هذا الإجراء يعدل قيمة القائمة الممررة إليه في objv[1] عن طريق إدراج objc-3 عناصر جديدة قبل index.

listPtr = objv[1];
if (Tcl_IsShared(listPtr)) {
    listPtr = Tcl_DuplicateObj(listPtr);
}
result = Tcl_ListObjReplace(interp, listPtr, index, 0,
        (objc-3), &(objv[3]));

كمثال آخر، يجب على إجراء أمر incr التحقق مما إذا كانت قيمة المتغير مشتركة قبل زيادة العدد الصحيح في تمثيلها الداخلي. إذا كانت مشتركة، فيجب عليها تكرار القيمة لتجنب تغيير القيم في هياكل البيانات الأخرى عن طريق الخطأ.
