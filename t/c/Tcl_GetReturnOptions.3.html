DESCRIPTION

تكشف الإجراءات Tcl_SetReturnOptions و Tcl_GetReturnOptions عن نفس القدرات التي توفرها أوامر return و catch في شكل واجهة C.

تقوم الإجراء Tcl_GetReturnOptions باسترداد قاموس خيارات الإرجاع للمفسر بعد تقييم نص برمجي. يتم استدعاء إجراءات مثل Tcl_Eval لتقييم نص برمجي في مفسر. تُرجع هذه الإجراءات رمز اكتمال صحيح. تحتفظ هذه الإجراءات أيضًا بالنتيجة في المفسر وقاموس خيارات الإرجاع الناتج عن تقييم النص البرمجي. بشكل مشابه لـ Tcl_GetObjResult، تسترد Tcl_GetReturnOptions قاموس خيارات الإرجاع. يجب تمرير رمز الاكتمال الصحيح كوسيط code إلى Tcl_GetReturnOptions حتى تكون جميع الوسائط المطلوبة موجودة في القاموس. على وجه التحديد، سيضمن قيمة code لـ TCL_ERROR وجود الإدخالات للمفاتيح -errorinfo و -errorcode و -errorline في القاموس. كما سيتم ضبط الإدخالات للمفاتيح -code و -level إذا لزم الأمر لمطابقة قيمة code. يشير (Tcl_Obj *) الذي تم إرجاعه بواسطة Tcl_GetReturnOptions إلى Tcl_Obj غير مشترك مع عداد مراجع صفر. يمكن كتابة القاموس، بإضافة أو حذف أو استبدال أي إدخالات فيه، دون الحاجة إلى التحقق من قيمة مشتركة. كما هو الحال مع أي Tcl_Obj مع عداد مراجع صفر، يجب على المستخدم إدارة تصرفها باستخدام Tcl_DecrRefCount أو عن طريق الإشارة إليه باستخدام Tcl_IncrRefCount (أو إحدى الوظائف العديدة التي تستدعيها، مثل Tcl_SetObjResult و Tcl_SetVar2Ex).

الاستخدام النموذجي لـ Tcl_GetReturnOptions هو استرداد مكدس الاستدعاءات عندما يكون إرجاع النص البرمجي هو TCL_ERROR، كما هو موضح هنا:

int code = Tcl_Eval(interp, script);
if (code == TCL_ERROR) {
    Tcl_Obj *options = Tcl_GetReturnOptions(interp, code);
    Tcl_Obj *key = Tcl_NewStringObj("-errorinfo", -1);
    Tcl_Obj *stackTrace;
    Tcl_IncrRefCount(key);
    Tcl_DictObjGet(NULL, options, key, &stackTrace);
    Tcl_DecrRefCount(key);
    /* افعل شيئًا ما مع stackTrace */
    Tcl_DecrRefCount(options);
}

تقوم الإجراء Tcl_SetReturnOptions بتعيين خيارات الإرجاع للمفسر إلى options. إذا كان options يحتوي على أي قيم غير صالحة لأي مفتاح، فسيتم إرجاع TCL_ERROR وسيتم تعيين نتيجة المفسر إلى رسالة خطأ مناسبة. وإلا، سيتم إرجاع رمز اكتمال وفقًا لقيم المفاتيح -code و -level في options.

كمثال، يمكن تنفيذ أمر return في Tcl باستخدام Tcl_SetReturnOptions على النحو التالي:

if ((objc % 2) == 0) { /* وسيط صريح */
    objc--;
    Tcl_SetObjResult(interp, objv[objc]);
}
return Tcl_SetReturnOptions(interp, Tcl_NewListObj(objc-1, objv+1));

(لم يتم تنفيذه حقًا بهذه الطريقة. تتيح الامتيازات الداخلية بديلاً أكثر كفاءة يتناسب بشكل أفضل مع مترجم الشفرة الثنائية.)

ملاحظة: يمكن تمرير كائن Tcl_Obj تم إنشاؤه حديثًا كوسيط options دون الحاجة إلى إدارة أي عدادات مراجع. هذا مشابه لـ Tcl_SetObjResult.

على الرغم من أن Tcl_SetReturnOptions توفر واجهة عامة لتعيين أي مجموعة من خيارات الإرجاع، إلا أن هناك عددًا صغيرًا من خيارات الإرجاع شائعة الاستخدام للغاية. أبرزها هي خيارات -errorinfo و -errorcode التي يجب تعيينها بشكل مناسب عندما تعيد إجراءات الأوامر TCL_ERROR. يتم أيضًا قراءة خيار -errorline بواسطة الأوامر التي تقيم النصوص البرمجية وتريد تقديم معلومات موقع مفصلة في مكدس الاستدعاءات الذي تضيفه إلى خيار -errorinfo. توفر Tcl واجهات أبسط متعددة لتعيين خيارات الإرجاع هذه بشكل مباشر.

يحتوي خيار -errorinfo على مكدس استدعاءات للعمليات التي تم تنفيذها عند حدوث خطأ، وهو مقروء عمدًا للمستخدم. يحتوي خيار -errorcode على قائمة بعناصر Tcl التي يمكن قراءتها عمدًا بتنسيق آلة. يحدد العنصر الأول من خيار -errorcode نوع الخطأ الذي حدث (على سبيل المثال، POSIX يعني أن خطأ حدث في استدعاء نظام POSIX). تحتوي العناصر الإضافية على معلومات إضافية تعتمد على نوع الخطأ. راجع إدخال الدليل حول المتغير errorCode للحصول على مزيد من التفاصيل حول التنسيقات المختلفة المستخدمة في خيار -errorcode بواسطة أوامر Tcl الداخلية.

يتم بناء خيار -errorinfo تدريجيًا أثناء انتشار الأخطاء عبر العمليات المتداخلة. في كل مرة يتم فيها إرجاع رمز خطأ إلى Tcl_Eval أو أي إجراء يقوم بتقييم النصوص البرمجية، يتم استدعاء الإجراء Tcl_AddErrorInfo لإضافة المزيد من النص إلى خيار -errorinfo لوصف أمر الأمر الذي كان قيد التنفيذ عند حدوث الخطأ. عندما يتم إرجاع الخطأ إلى التطبيق، سيكون تتبع النشاط الكامل في وقت حدوث الخطأ يحتوي على مكدس كامل.

قد يكون من المفيد أحيانًا إضافة معلومات إضافية إلى خيار -errorinfo تتجاوز ما يمكن أن توفره إجراءات تقييم النص البرمجي. يمكن استخدام الإجراء Tcl_AddErrorInfo لهذا الغرض: الوسيط الخاص بها message هو نص إضافي لإلحاقه بخيار -errorinfo. على سبيل المثال، عند حدوث خطأ أثناء تنفيذ الأمر source، يتم استدعاء الإجراء Tcl_AddErrorInfo لتسجيل اسم الملف الذي يتم معالجته والسطر الذي حدث فيه الخطأ. وبالمثل، عند حدوث خطأ أثناء تقييم أمر، يتم استدعاء الإجراء Tcl_AddErrorInfo لتسجيل معلومات الملف وسطر الخطأ.
