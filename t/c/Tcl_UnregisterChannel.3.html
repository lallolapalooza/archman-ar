DESCRIPTION

The Tcl channel mechanism provides a device-independent and platform-independent mechanism for performing buffered input and output operations on a variety of file, socket, and device types. The channel mechanism is extensible to new channel types, by providing a low-level channel driver for the new type; the channel driver interface is described in the manual entry for Tcl_CreateChannel. The channel mechanism provides a buffering scheme modeled after Unix's standard I/O, and it also allows for nonblocking I/O on channels.

The procedures described in this manual entry comprise the C APIs of the generic layer of the channel architecture. For a description of the channel driver architecture and how to implement channel drivers for new types of channels, see the manual entry for Tcl_CreateChannel.

TCL_OPENFILECHANNEL

This procedure opens the file named fileName and returns a new Tcl channel for it. The file is opened with the mode specified by mode and permissions. The mode string has the same syntax as the mode for the Tcl open command. If the file is created, its permissions are set to permissions. Returns the channel handle if successful, or NULL otherwise. If an error occurs, a message is left in the interpreter's result.

Possible values for mode are:

r
Read access.
w
Write access. Creates the file if it does not exist; truncates to zero length if it does exist.
a
Append access. Creates the file if it does not exist. Data written will be added to the end of the file.
r+
Read and write access. The file must exist.
w+
Read and write access. Creates the file if it does not exist; truncates to zero length if it does exist.
a+
Append and read access. Creates the file if it does not exist. Data written will be added to the end of the file. Reads occur from the current position.

The mode may also include b to specify binary transfer (default is text mode, where certain characters may be translated). These modes are the same as the modes for the Tcl open command.

The permissions argument is a Unix-style mode triplet, e.g., 0644. It is only used when a file is created.

On Unix systems, the handle argument is a file descriptor. On Windows systems, it is a HANDLE value.

The readOrWrite argument is an OR-ed combination of TCL_READABLE and TCL_WRITABLE to indicate what operations are valid on handle.

This procedure may be used to create a channel from an existing file descriptor or handle. The procedure determines the channel type based on the underlying file descriptor or handle.

This procedure is used to create a channel that represents a pipe to a child process spawned by Tcl_Exec. argc and argv specify the command to execute and its arguments. flags specify which stdio handles (stdin, stdout, stderr) of the child process should be connected to the returned channel. It is also possible to specify that the child process should inherit the parent's stdio handles, or that stdio handles should be redirected using the <, >, or 2> redirection operators in the command string. See the manual entry for the Tcl exec command for more details.

The flags argument is an OR-ed combination of the following bits:

TCL_STDIN
Connects the child's standard input to the pipe.
TCL_STDOUT
Connects the child's standard output to the pipe.
TCL_STDERR
Connects the child's standard error to the pipe.
TCL_ENFORCE_MODE
If this bit is set, then the parent process's stdio handles are used for any stdio handles for which TCL_STDIN, TCL_STDOUT, or TCL_STDERR have been specified. If this bit is not set, then the child process can redirect these stdio handles as desired.

This procedure is used to get a Tcl channel corresponding to channelName. If modePtr is not NULL, it points to an integer variable that receives an OR-ed combination of TCL_READABLE and TCL_WRITABLE denoting whether the channel is open for reading and writing.

This procedure returns a list of all currently registered channel names in the interpreter's result.

This procedure returns a list of channel names that match the given pattern in the interpreter's result.

This procedure registers channel with interp, making it available via its name.

This procedure unregisters channel from interp. The channel should not be used after this call. Returns TCL_OK on success, or TCL_ERROR if the channel was not registered.

This procedure detaches the channel from the interpreter. The channel can still be used, but it will not be automatically closed when the interpreter is destroyed. It is the caller's responsibility to close the channel. Returns TCL_OK on success, or TCL_ERROR if the channel was not registered.

This procedure returns true if channel is one of the standard channels (stdin, stdout, stderr), false otherwise.

This procedure closes the channel channel. If the channel is registered with interp, it is unregistered. If the channel was opened by Tcl (e.g., via Tcl_OpenFileChannel), the underlying file descriptor or handle is closed. Returns TCL_OK on success, or TCL_ERROR if an error occurred.

Reads up to charsToRead characters from channel and stores them in the Tcl object referenced by readObjPtr. If appendFlag is non-zero, the characters are appended to the object's value; otherwise, the object's value is replaced. If the channel is not open for reading, or if an error occurs, an error is signaled. Returns the number of characters actually read, or -1 if an error occurs. If the end of file is reached before reading any characters, 0 is returned.

Reads up to bytesToRead bytes from channel and stores them in the buffer readBuf. The buffer must be large enough to hold bytesToRead bytes. If the channel is not open for reading, or if an error occurs, an error is signaled. Returns the number of bytes actually read, or -1 if an error occurs. If the end of file is reached before reading any bytes, 0 is returned.

Reads characters from channel until a newline character is encountered, or end-of-file is reached. The characters read (excluding the newline, if any) are stored in the Tcl object referenced by lineObjPtr. The object's value is replaced by the characters read. If the channel is not open for reading, or if an error occurs, an error is signaled. Returns the number of characters read, or -1 if an error occurs. If end-of-file is reached before any characters are read, 0 is returned.

Reads characters from channel until a newline character is encountered, or end-of-file is reached. The characters read (including the newline, if any) are appended to the Tcl dynamic string lineRead. If the channel is not open for reading, or if an error occurs, an error is signaled. Returns the number of characters read, or -1 if an error occurs. If end-of-file is reached before any characters are read, 0 is returned.

Pushes the characters in input back onto the channel's input buffer. inputLen specifies the length of the input. If addAtEnd is non-zero, the input is added to the end of the buffer; otherwise, it is added to the beginning. This is typically used to handle input that has been peeked at but not consumed.

Writes the contents of the Tcl object writeObjPtr to channel. If the channel is not open for writing, or if an error occurs, an error is signaled. Returns the number of bytes written, or -1 if an error occurs.

Writes the characters in charBuf to channel. The procedure will write up to bytesToWrite characters from the buffer. If the channel is not open for writing, or if an error occurs, an error is signaled. Returns the number of characters written, or -1 if an error occurs.

Writes the bytes in byteBuf to channel. The procedure will write up to bytesToWrite bytes from the buffer. If the channel is not open for writing, or if an error occurs, an error is signaled. Returns the number of bytes written, or -1 if an error occurs.

Reads up to bytesToRead bytes from channel and stores them in the buffer readBuf. This is a raw read; no character encoding translation is performed. The buffer must be large enough to hold bytesToRead bytes. If the channel is not open for reading, or if an error occurs, an error is signaled. Returns the number of bytes actually read, or -1 if an error occurs. If the end of file is reached before reading any bytes, 0 is returned.

Writes up to bytesToWrite bytes from byteBuf to channel. This is a raw write; no character encoding translation is performed. If the channel is not open for writing, or if an error occurs, an error is signaled. Returns the number of bytes written, or -1 if an error occurs.

Flushes any buffered output for channel to the underlying device. Returns TCL_OK on success, or TCL_ERROR if an error occurred.

Returns the number of bytes currently in the input buffer for channel.

Returns the number of bytes currently in the output buffer for channel.

If addAtEnd is non-zero, the input is added to the end of the buffer; otherwise, it is added to the beginning. This is typically used to handle input that has been peeked at but not consumed.

Repositions the access point in the channel channel. The new access point is offset bytes from the beginning of the file (if seekMode is SEEK_SET), from the current access point (if seekMode is SEEK_CUR), or from the end of the file (if seekMode is SEEK_END). On success, returns the new access point in bytes from the beginning of the file. On error, returns -1. This procedure only works on channels that support seeking.

Returns the current access point in bytes from the beginning of the file for channel channel. On error, returns -1. This procedure only works on channels that support seeking.

Truncates the file associated with channel to be at most length bytes. Only supported on channels that support seeking and writing. Returns TCL_OK on success, or TCL_ERROR on failure.

Retrieves the value of the option optionName for channel channel and stores it in the Tcl object pointed to by optionValue. If optionName is NULL, it retrieves a list of all options and their values. Returns TCL_OK on success, or TCL_ERROR if an error occurs.

Sets the option optionName for channel channel to newValue. Returns TCL_OK on success, or TCL_ERROR if an error occurs.

TCL_READCHARS, TCL_READOBJ, AND TCL_READ

The arsToRead value of -1 سيجعل الأمر يقرأ جميع الأحرف المتاحة حاليًا (غير مانع) أو كل شيء حتى نهاية الملف (وضع مانع).

قد تكون القيمة المرجعة أصغر من القيمة المطلوب قراءتها، مما يشير إلى أن كمية بيانات أقل من المطلوب كانت متاحة. يُطلق على هذا اسم قراءة قصيرة. في الوضع المانع، يمكن أن يحدث هذا فقط عند نهاية الملف. في الوضع غير المانع، يمكن أن تحدث قراءة قصيرة أيضًا إذا لم يكن هناك مدخلات كافية متاحة حاليًا: تُرجع Tcl_ReadChars عددًا صغيرًا بدلاً من انتظار المزيد من البيانات.

إذا كانت القناة في وضع مانع، فإن القيمة المرجعة صفر تشير إلى شرط نهاية الملف. إذا كانت القناة في وضع غير مانع، فإن القيمة المرجعة صفر تشير إما إلى عدم توفر مدخلات حاليًا أو شرط نهاية ملف. استخدم Tcl_Eof و Tcl_InputBlocked لمعرفة أي من هذه الشروط حدث بالفعل.

تقوم Tcl_ReadChars بترجمة تمثيلات نهاية السطر المختلفة إلى التمثيل الداخلي القياسي \n وفقًا لوضع التعرف على نهاية السطر الحالي. يتم وصف التعرف على نهاية السطر والأوضاع المختلفة الخاصة بالنظام الأساسي في إدخال الدليل لأمر Tcl fconfigure.

كتفضيء للأداء، عند القراءة من قناة بالتشفير binary، لا يتم تحويل البايتات إلى UTF-8 أثناء قراءتها. بدلاً من ذلك، يتم تخزينها في التمثيل الداخلي لـ readObjPtr كقيمة مصفوفة بايت. لن يتم إنشاء التمثيل النصي لهذه القيمة إلا إذا كان مطلوبًا (على سبيل المثال، بسبب استدعاء Tcl_GetStringFromObj). بهذه الطريقة، يمكن قراءة البيانات الموجهة بالبايت من قناة، ومعالجتها عن طريق استدعاء Tcl_GetByteArrayFromObj والدالات ذات الصلة، ثم كتابتها إلى قناة دون تكلفة التحويل إلى أو من UTF-8.

Tcl_Read مشابه لـ Tcl_ReadChars، باستثناء أنه لا يقوم بتحويلات التشفير، بغض النظر عن تشفير القناة. تم إهماله وهو موجود للتوافق مع الإصدارات السابقة مع امتدادات Tcl غير المترجمة. يستهلك بايتات من channel ويخزنها في readBuf، مع إجراء ترجمات نهاية السطر أثناء ذلك. القيمة المرجعة لـ Tcl_Read هي عدد البايتات، حتى bytesToRead، المكتوبة في readBuf. المخزن المؤقت الذي تنتجه Tcl_Read ليس منتهيًا بصفر. محتوياته صالحة من الموضع الصفري وحتى الموضع المشار إليه بالقيمة المرجعة باستثناء.

Tcl_ReadRaw هو نفس Tcl_Read ولكنه لا يعوض عن التكديس. بينما تحصل Tcl_Read (والدالات الأخرى في واجهة برمجة التطبيقات) دائمًا على بياناتها من القناة العلوية في المكدس الذي تشكل القناة الموفرة جزءًا منه، فإن Tcl_ReadRaw لا تفعل ذلك. وبالتالي فإن هذه الدالة قابلة للاستخدام فقط لسائقي القنوات التحويلية، أي السائقين المستخدمين في منتصف مكدس من القنوات، لنقل البيانات من القناة أدناه إلى التحويل.

TCL_GETSOBJ AND TCL_GETS

تستهلك Tcl_GetsObj بايتات من channel، وتحول البايتات إلى UTF-8 بناءً على تشفير القناة، حتى تتم رؤية سطر إدخال كامل. إذا كان تشفير القناة binary، يتم التعامل مع كل بايت مقروء من القناة كحرف يونيكود فردي. يتم إلحاق جميع أحرف السطر باستثناء حرف (أو أحرف) نهاية السطر الختامي بتمثيل النص لـ lineObjPtr. تتم قراءة حرف (أو أحرف) نهاية السطر والتخلص منها.

إذا تمت قراءة سطر بنجاح، فإن القيمة المرجعة أكبر من أو تساوي صفر وتشير إلى عدد البايتات المخزنة في lineObjPtr. إذا حدث خطأ، تُرجع Tcl_GetsObj -1 وتسجل رمز خطأ POSIX يمكن استرداده باستخدام Tcl_GetErrno. تُرجع Tcl_GetsObj أيضًا -1 إذا تم الوصول إلى نهاية الملف؛ يمكن استخدام الإجراء Tcl_Eof للتمييز بين خطأ وشرط نهاية ملف.

إذا كانت القناة في وضع غير مانع، يمكن أن تكون القيمة المرجعة أيضًا -1 إذا لم تتوفر بيانات أو لم تحتوِ البيانات المتاحة على حرف نهاية سطر. عند إرجاع -1، قد يتم استدعاء الإجراء Tcl_InputBlocked لتحديد ما إذا كانت القناة محظورة بسبب عدم توفر المدخلات.

Tcl_Gets هو نفس Tcl_GetsObj باستثناء أنه يتم إلحاق الأحرف الناتجة بالسلسلة الديناميكية التي يوفرها lineRead بدلاً من قيمة Tcl.

TCL_UNGETS

يُستخدم Tcl_Ungets لإضافة بيانات إلى قائمة انتظار الإدخال لقناة، إما في رأس أو ذيل القائمة. يشير المؤشر input إلى البيانات التي سيتم إضافتها. يتم إعطاء طول الإدخال للإضافة بواسطة inputLen. تشير القيمة غير الصفرية لـ addAtEnd إلى أنه سيتم إضافة البيانات في نهاية القائمة؛ بخلاف ذلك، سيتم إضافتها في رأس القائمة. إذا كانت القناة تحتوي على علامة نهاية ملف "ملتصقة" (sticky)، فلن تتم إضافة أي بيانات إلى قائمة انتظار الإدخال. تُرجع Tcl_Ungets inputLen أو -1 في حالة حدوث خطأ.

TCL_WRITECHARS, TCL_WRITEOBJ, AND TCL_WRITE

تقبل Tcl_WriteChars عدد bytesToWrite من بايتات بيانات الأحرف في charBuf. يتم تحويل أحرف UTF-8 في المخزن المؤقت إلى تشفير القناة وتجميعها للإخراج إلى channel. إذا كانت bytesToWrite سالبة، تتوقع Tcl_WriteChars أن يكون charBuf منتهيًا بصفر وتخرج كل شيء حتى الصفر.

قد لا تظهر البيانات المجمعة للإخراج على جهاز الإخراج فورًا، بسبب التخزين المؤقت الداخلي. إذا كان يجب أن تظهر البيانات فورًا، قم باستدعاء Tcl_Flush بعد استدعاء Tcl_WriteChars، أو قم بتعيين خيار -buffering على القناة إلى none. إذا كنت ترغب في ظهور البيانات فور قبول سطر كامل للإخراج، قم بتعيين خيار -buffering على القناة إلى وضع line.

القيمة المرجعة لـ Tcl_WriteChars هي عدد البايتات التي تم قبولها للإخراج إلى القناة. هذا إما أكبر من صفر للإشارة إلى النجاح أو -1 للإشارة إلى حدوث خطأ. في حالة حدوث خطأ، تسجل Tcl_WriteChars رمز خطأ POSIX يمكن استرداده باستخدام Tcl_GetErrno.

يتم ترجمة أحرف نهاية السطر في بيانات الإخراج إلى تسلسلات نهاية سطر خاصة بالنظام الأساسي وفقًا لخيار -translation للقناة. يتم ذلك حتى لو لم يكن للقناة تشفير.

Tcl_WriteObj مشابه لـ Tcl_WriteChars باستثناء أنه يقبل قيمة Tcl سيتم إخراج محتوياتها إلى القناة. يتم تحويل أحرف UTF-8 في تمثيل النص لـ writeObjPtr إلى تشفير القناة وتجميعها للإخراج إلى channel. كتفضيء للأداء، عند الكتابة إلى قناة بالتشفير binary، لا يتم تحويل أحرف UTF-8 أثناء كتابتها. بدلاً من ذلك، يتم كتابة البايتات في التمثيل الداخلي لـ writeObjPtr كمصفوفة بايت إلى القناة. سيتم إنشاء تمثيل مصفوفة البايت للقيمة إذا كان مطلوبًا. بهذه الطريقة، يمكن قراءة البيانات الموجهة بالبايت من قناة، ومعالجتها عن طريق استدعاء Tcl_GetByteArrayFromObj والدالات ذات الصلة، ثم كتابتها إلى قناة دون تكلفة التحويل إلى أو من UTF-8.

Tcl_Write مشابه لـ Tcl_WriteChars باستثناء أنه لا يقوم بتحويلات التشفير، بغض النظر عن تشفير القناة. تم إهماله وهو موجود للتوافق مع الإصدارات السابقة مع امتدادات Tcl غير المترجمة. يقبل عدد bytesToWrite من البايتات من byteBuf ويجمعها للإخراج إلى channel. إذا كانت bytesToWrite سالبة، تتوقع Tcl_Write أن يكون byteBuf منتهيًا بصفر وتخرج كل شيء حتى الصفر.

Tcl_WriteRaw هو نفس Tcl_Write ولكنه لا يعوض عن التكديس. بينما تغذي Tcl_Write (والدالات الأخرى في واجهة برمجة التطبيقات) دائمًا مدخلاتها إلى القناة العلوية في المكدس الذي تشكل القناة الموفرة جزءًا منه، فإن Tcl_WriteRaw لا تفعل ذلك. وبالتالي فإن هذه الدالة قابلة للاستخدام فقط لسائقي القنوات التحويلية، أي السائقين المستخدمين في منتصف مكدس من القنوات، لنقل البيانات من التحويل إلى القناة تحتها.

TCL_FLUSH

تتسبب Tcl_Flush في كتابة جميع بيانات الإخراج المخزنة مؤقتًا لـ channel إلى ملفها الأساسي أو جهازها في أقرب وقت ممكن. إذا كانت القناة في وضع مانع، فإن الاستدعاء لا يعود حتى يتم إرسال جميع البيانات المخزنة مؤقتًا إلى القناة أو حدوث خطأ ما. يعود الاستدعاء على الفور إذا كانت القناة غير مانعة؛ يبدأ تدفقًا في الخلفية يقوم بكتابة البيانات المخزنة مؤقتًا إلى القناة في النهاية، بأسرع ما يمكن للقناة استيعابها.

القيمة المرجعة هي عادةً TCL_OK. في حالة حدوث خطأ، تُرجع Tcl_Flush قيمة TCL_ERROR وتسجل رمز خطأ POSIX يمكن استرداده باستخدام Tcl_GetErrno.

TCL_SEEK

تنقل Tcl_Seek نقطة الوصول في channel حيث سيتم قراءة أو كتابة البيانات اللاحقة. يتم مسح الإخراج المخزن مؤقتًا إلى القناة وإلغاء تخزين المدخلات مؤقتًا، قبل عملية البحث.

تعيد Tcl_Seek عادةً نقطة الوصول الجديدة. في حالة حدوث خطأ، تُرجع Tcl_Seek القيمة -1 وتسجل رمز خطأ POSIX يمكن استرداده باستخدام Tcl_GetErrno. بعد حدوث خطأ، قد تكون نقطة الوصول قد تم نقلها أو لم تكن كذلك.

TCL_TELL

تُرجع Tcl_Tell نقطة الوصول الحالية لقناة. القيمة المرجعة هي -1 إذا كانت القناة لا تدعم البحث.

TCL_TRUNCATECHANNEL

تقوم Tcl_TruncateChannel بقص الملف الأساسي لـ channel إلى طول length معين من البايتات. تُرجع TCL_OK إذا نجحت العملية، و TCL_ERROR بخلاف ذلك.

TCL_GETCHANNELOPTION

تقوم Tcl_GetChannelOption باسترداد، في optionValue، قيمة أحد الخيارات السارية حاليًا لقناة، أو قائمة بجميع الخيارات وقيمها. يمثل الوسيط channel القناة التي سيتم الاستعلام عن خيارها أو استرداد جميع الخيارات وقيمها. إذا لم يكن optionName فارغًا (NULL)، فهو اسم الخيار للاستعلام؛ يتم نسخ قيمة الخيار إلى سلسلة Tcl الديناميكية التي يشير إليها optionValue. إذا كان optionName فارغًا (NULL)، تقوم الدالة بتخزين قائمة متناوبة بأسماء الخيارات وقيمها في optionValue
