الوصف

يتكون جدول التجزئة من صفر أو أكثر من الإدخالات، كل منها يحتوي على مفتاح وقيمة. نظرًا لمفتاح الإدخال، يمكن لروتينات التجزئة تحديد موقع الإدخال بسرعة، وبالتالي قيمته. يمكن أن يكون هناك إدخال واحد على الأكثر في جدول تجزئة بمفتاح معين، ولكن يمكن أن يكون هناك العديد من الإدخالات بنفس القيمة. يمكن أن تأخذ المفاتيح أحد الأشكال الأربعة: سلاسل نصية، قيم كلمة واحدة، مصفوفات من الأعداد الصحيحة، أو مفاتيح محددة بواسطة بنية Tcl_HashKeyType (انظر القسم THE TCL_HASHKEYTYPE STRUCTURE أدناه). جميع المفاتيح في جدول تجزئة لها نفس الشكل، والذي يتم تحديده عند تهيئة الجدول.

يمكن أن تكون قيمة إدخال جدول التجزئة أي شيء يشغل نفس المساحة مثل مؤشر إلى سلسلة نصية. تتم إدارة قيم إدخالات جدول التجزئة بالكامل بواسطة العملاء، وليس بواسطة وحدة التجزئة نفسها. بشكل عام، كل قيمة إدخال هي مؤشر إلى كائن بيانات تديره شيفرة العميل.

تنمو جداول التجزئة بسلاسة مع زيادة عدد الإدخالات، بحيث يكون هناك دائمًا أقل من ثلاثة إدخالات لكل دلو في المتوسط. هذا يسمح بالاستعلامات السريعة بغض النظر عن عدد الإدخالات في الجدول.

يقدم النواة ثلاث وظائف لتهيئة جداول التجزئة، Tcl_InitHashTable، Tcl_InitObjHashTable، و Tcl_InitCustomHashTable.

Tcl_InitHashTable يقوم بتهيئة بنية تصف جدول تجزئة جديد. يتم توفير المساحة للبنية بواسطة العميل، وليس بواسطة وحدة التجزئة. قيمة keyType تشير إلى أنواع المفاتيح التي سيتم استخدامها لجميع إدخالات الجدول. جميع أنواع المفاتيح الموضحة لاحقًا مسموح بها، باستثناء TCL_CUSTOM_TYPE_KEYS و TCL_CUSTOM_PTR_KEYS.

Tcl_InitObjHashTable هو غلاف لـ Tcl_InitCustomHashTable ويقوم بتهيئة جدول تجزئة تكون مفاتيحه Tcl_Obj *.

Tcl_InitCustomHashTable يقوم بتهيئة بنية تصف جدول تجزئة جديد. يتم توفير المساحة للبنية بواسطة العميل، وليس بواسطة وحدة التجزئة. قيمة keyType تشير إلى أنواع المفاتيح التي سيتم استخدامها لجميع إدخالات الجدول. يجب أن تأخذ KeyType أحد القيم التالية:

TCL_STRING_KEYS
المفاتيح هي سلاسل نصية منتهية بصفر. يتم تمريرها إلى روتينات التجزئة باستخدام عنوان الحرف الأول من السلسلة.
TCL_ONE_WORD_KEYS
المفاتيح هي قيم كلمة واحدة؛ يتم تمريرها إلى روتينات التجزئة وتخزينها في إدخالات الجدول كقيم char *. قيمة المؤشر هي المفتاح؛ لا يلزم (وبشكل عام غير مطلوب) أن تشير فعليًا إلى سلسلة نصية.
TCL_CUSTOM_TYPE_KEYS
المفاتيح هي من نوع اعتباطي ويتم تخزينها في الإدخالات. يتم تحديد التجزئة والمقارنة بواسطة typePtr. يتم وصف بنية Tcl_HashKeyType في القسم THE TCL_HASHKEYTYPE STRUCTURE أدناه.
TCL_CUSTOM_PTR_KEYS
المفاتيح هي مؤشرات إلى نوع اعتباطي ويتم تخزينها في الإدخالات. يتم تحديد التجزئة والمقارنة بواسطة typePtr. يتم وصف بنية Tcl_HashKeyType في القسم THE TCL_HASHKEYTYPE STRUCTURE أدناه.
other
إذا لم يكن keyType أحد ما سبق، فيجب أن يكون قيمة عددية أكبر من 1. في هذه الحالة، ستكون المفاتيح عبارة عن مصفوفات من قيم int، حيث يحدد keyType عدد الأعداد الصحيحة في كل مفتاح. هذا يسمح باستخدام الهياكل كمفاتيح. يجب أن يكون لجميع المفاتيح نفس الحجم. يتم تمرير مفاتيح المصفوفة إلى وظائف التجزئة باستخدام عنوان أول عدد صحيح في المصفوفة.

Tcl_DeleteHashTable تزيل جميع الإدخالات من جدول التجزئة وتحرر المساحة المرتبطة بمصفوفة الدلاء والإدخالات. لا تحرر بنية الجدول نفسها (المشار إليها بواسطة tablePtr)، حيث يتم افتراض المساحة بواسطة العميل. Tcl_DeleteHashTable أيضًا لا تحرر أو تتلاعب بقيم إدخالات جدول التجزئة. إذا كانت قيم الإدخالات تشير إلى ذاكرة ديناميكية، فإن مسؤولية تحرير هذه الهياكل تقع على عاتق العميل قبل حذف الجدول.

Tcl_CreateHashEntry تحدد موقع الإدخال المقابل لمفتاح معين، وتقوم بإنشاء إدخال جديد في الجدول إذا لم يكن هناك إدخال بالمفتاح المحدد. إذا كان هناك بالفعل إدخال بنفس المفتاح، فسيتم تعيين *newPtr إلى 0. إذا تم إنشاء إدخال جديد، فسيتم تعيين *newPtr إلى قيمة غير فارغة وسيتم تعيين قيمة الإدخال الجديد إلى 0. القيمة التي ترجعها Tcl_CreateHashEntry هي مؤشر إلى الإدخال، والتي يمكن استخدامها للحصول على قيمة الإدخال وتعديلها أو حذفها من الجدول.

Tcl_DeleteHashEntry تزيل إدخالًا موجودًا من جدول. يتم تحرير الذاكرة المرتبطة بالإدخال نفسه، ولكن العميل مسؤول عن أي تنظيف مرتبط بقيمة الإدخال، مثل تحرير كائن يشير إليه.

Tcl_FindHashEntry تشبه Tcl_CreateHashEntry باستثناء أنها لا تنشئ إدخالًا جديدًا إذا كان المفتاح غير موجود؛ بدلاً من ذلك، ترجع NULL كنتيجة.

Tcl_GetHashValue و Tcl_SetHashValue تستخدم لقراءة وكتابة قيمة إدخال، على التوالي. يتم تخزين القيم واسترجاعها كنوع ClientData، وهو ما يكفي لاحتواء قيمة المؤشر. في معظم الآلات، هذا يكفي لاحتواء قيمة عدد صحيح أيضًا.

Tcl_GetHashKey ترجع المفتاح لإدخال معين في جدول التجزئة، سواء كسلسلة نصية، مفتاح كلمة واحدة (char *)، أو كمؤشر إلى الكلمة الأولى لمصفوفة من الأعداد الصحيحة، اعتمادًا على keyType المستخدم لإنشاء جدول التجزئة. في جميع الحالات، ترجع Tcl_GetHashKey نتيجة من نوع char *. عندما يكون المفتاح سلسلة نصية أو مصفوفة، فإن نتيجة Tcl_GetHashKey تشير إلى معلومات في إدخال الجدول؛ ستظل هذه المعلومات صالحة حتى يتم حذف الإدخال أو حذف جدوله.

Tcl_FirstHashEntry و Tcl_NextHashEntry يمكن استخدامهما للمرور عبر جميع إدخالات جدول التجزئة.

tablePtr
The hash table to operate on. For Tcl_InitHashTable and Tcl_InitCustomHashTable, this is a pointer to an uninitialized hash table structure.
hashKeyType
Specifies the type of keys used in the hash table. This may be one of the predefined types: TCL_STRING_KEYS, TCL_INT_KEYS, TCL_WIDE_INT_KEYS, TCL_DOUBLE_KEYS, or TCL_CUSTOM_KEYS. If it is TCL_CUSTOM_KEYS then keyTypePtr must also be provided. Legal values for hashKeyType are defined in <tcl.h>.
keyPtr
A pointer to the key to be used for an operation. For Tcl_CreateHashEntry and Tcl_FindHashEntry, the type of *keyPtr must match the key type specified in Tcl_InitHashTable or Tcl_InitCustomHashTable. For custom key types, the type of *keyPtr is determined by the custom key type's structure.
newValuePtr
If not NULL, this is a pointer to an integer. If the entry was newly created, the integer will be set to 1. If the entry already existed, the integer will be set to 0.
hPtr
A pointer to a hash table entry. This may be obtained from a previous call to Tcl_CreateHashEntry or Tcl_FindHashEntry.
searchPtr
A pointer to a structure of type Tcl_HashSearch. This structure is used to keep track of progress through the hash table during a search.
keyTypePtr
A pointer to a structure describing a custom hash key type. This is only used when hashKeyType is set to TCL_CUSTOM_KEYS.

Tcl provides a general-purpose hash table implementation that is used internally for many Tcl commands and data structures. These procedures allow C code to create, access, and manage hash tables.

A hash table is a data structure that maps keys to values. The main operations are inserting a key-value pair, looking up the value associated with a key, and deleting a key-value pair. Hash tables provide expected O(1) average time complexity for these operations.

The hash table implementation supports several built-in key types: strings (TCL_STRING_KEYS), integers (TCL_INT_KEYS), 64-bit integers (TCL_WIDE_INT_KEYS), and doubles (TCL_DOUBLE_KEYS). It also supports custom key types through the TCL_CUSTOM_KEYS type and the Tcl_InitCustomHashTable procedure.

Tcl_InitHashTable initializes a hash table structure pointed to by tablePtr to manage entries with keys of type hashKeyType. The hash table is initially empty. This procedure should be called before any other hash table operations are performed on the table.

Tcl_DeleteHashTable destroys the hash table pointed to by tablePtr, freeing all associated storage. All entries must be deleted before calling this procedure, or use Tcl_DeleteHashEntry in conjunction with a loop through the table.

Tcl_CreateHashEntry creates a new hash table entry for the key pointed to by keyPtr in the table pointed to by tablePtr. If an entry with this key already exists, then the existing entry is returned. If the entry is new, then the integer pointed to by newValuePtr is set to 1 (or ignored if newValuePtr is NULL). If the entry already existed, then newValuePtr is set to 0. The procedure returns a pointer to the new or existing hash table entry. The value associated with the entry is initially NULL. Use Tcl_SetHashValue to set the value.

Tcl_FindHashEntry returns a pointer to the hash table entry associated with the key pointed to by keyPtr in the table pointed to by tablePtr. If no entry exists with that key, then NULL is returned. The value associated with the entry can be retrieved using Tcl_GetHashValue or set using Tcl_SetHashValue.

Tcl_DeleteHashEntry deletes the entry pointed to by hPtr from the hash table pointed to by tablePtr. The memory for the entry is then freed.

Tcl_GetHashKey returns a pointer to the key associated with the hash table entry pointed to by hPtr. The type of the key is determined by the type specified in Tcl_InitHashTable or Tcl_InitCustomHashTable.

Tcl_GetHashValue returns the value associated with the hash table entry pointed to by hPtr.

Tcl_SetHashValue sets the value associated with the hash table entry pointed to by hPtr to value.

Tcl_FirstHashEntry and Tcl_NextHashEntry can be used to iterate through all the entries in a hash table. A structure of type "Tcl_HashSearch", provided by the client, is used to keep track of progress through the table. Tcl_FirstHashEntry initializes the search record and returns the first entry in the table (or NULL if the table is empty). Each subsequent call to Tcl_NextHashEntry returns the next entry in the table or NULL if the end of the table has been reached. A call to Tcl_FirstHashEntry followed by calls to Tcl_NextHashEntry will return each of the entries in the table exactly once, in an arbitrary order. It is inadvisable to modify the structure of the table, e.g. by creating or deleting entries, while the search is in progress, with the exception of deleting the entry returned by Tcl_FirstHashEntry or Tcl_NextHashEntry.

Tcl_HashStats returns a dynamically-allocated string with overall information about a hash table, such as the number of entries it contains, the number of buckets in its hash array, and the utilization of the buckets. It is the caller's responsibility to free the result string by passing it to ckfree.

The header file tcl.h defines the actual data structures used to implement hash tables. This is necessary so that clients can allocate Tcl_HashTable structures and so that macros can be used to read and write the values of entries. However, users of the hashing routines should never refer directly to any of the fields of any of the hash-related data structures; use the procedures and macros defined here.

THE TCL_HASHKEYTYPE STRUCTURE

Extension writers can define new hash key types by defining four procedures, initializing a Tcl_HashKeyType structure to describe the type, and calling Tcl_InitCustomHashTable. The Tcl_HashKeyType structure is defined as follows:

typedef struct Tcl_HashKeyType {
    int version;
    int flags;
    Tcl_HashKeyProc *hashKeyProc;
    Tcl_CompareHashKeysProc *compareKeysProc;
    Tcl_AllocHashEntryProc *allocEntryProc;
    Tcl_FreeHashEntryProc *freeEntryProc;
} Tcl_HashKeyType;

The version member is the version of the table. If this structure is extended in future then the version can be used to distinguish between different structures. It should be set to TCL_HASH_KEY_TYPE_VERSION.

The flags member is 0 or one or more of the following values OR'ed together:

TCL_HASH_KEY_RANDOMIZE_HASH
There are some things, pointers for example which do not hash well because they do not use the lower bits. If this flag is set then the hash table will attempt to rectify this by randomizing the bits and then using the upper N bits as the index into the table.
TCL_HASH_KEY_SYSTEM_HASH
This flag forces Tcl to use the memory allocation procedures provided by the operating system when allocating and freeing memory used to store the hash table data structures, and not any of Tcl's own customized memory allocation routines. This is important if the hash table is to be used in the implementation of a custom set of allocation routines, or something that a custom set of allocation routines might depend on, in order to avoid any circular dependency.

The hashKeyProc member contains the address of a function called to calculate a hash value for the key.

typedef unsigned int Tcl_HashKeyProc(
        Tcl_HashTable *tablePtr,
        void *keyPtr);

If this is NULL then keyPtr is used and TCL_HASH_KEY_RANDOMIZE_HASH is assumed.

The compareKeysProc member contains the address of a function called to compare two keys.

typedef int Tcl_CompareHashKeysProc(
        void *keyPtr,
        Tcl_HashEntry *hPtr);

If this is NULL then the keyPtr pointers are compared. If the keys do not match then the function returns 0, otherwise it returns 1.

The allocEntryProc member contains the address of a function called to allocate space for an entry and initialize the key and clientData.

typedef Tcl_HashEntry *Tcl_AllocHashEntryProc(
        Tcl_HashTable *tablePtr,
        void *keyPtr);

If this is NULL then Tcl_Alloc is used to allocate enough space for a Tcl_HashEntry, the key pointer is assigned to key.oneWordValue and the clientData is set to NULL. String keys and array keys use this function to allocate enough space for the entry and the key in one block, rather than doing it in two blocks. This saves space for a pointer to the key from the entry and another memory allocation. Tcl_Obj* keys use this function to allocate enough space for an entry and increment the reference count on the value.

The freeEntryProc member contains the address of a function called to free space for an entry.

typedef void Tcl_FreeHashEntryProc(
        Tcl_HashEntry *hPtr);

If this is NULL then Tcl_Free is used to free the space for the entry. Tcl_Obj* keys use this function to decrement the reference count on the value.
