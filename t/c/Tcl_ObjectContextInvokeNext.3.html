الوصف

الطريقة هي عملية تتم على كائن مرتبط بهذا الكائن. يجب ربط كل طريقة إما بكائن أو بفئة؛ ترتبط الطرق المرفقة بفئة بجميع مثيلات تلك الفئة (المباشرة وغير المباشرة).

نظرًا لطريقة، يمكن العثور على الكيان الذي أعلنها باستخدام Tcl_MethodDeclarerClass الذي يعيد الفئة التي تم ربط الطريقة بها (أو NULL إذا لم تكن الطريقة مرتبطة بأي فئة) و Tcl_MethodDeclarerObject الذي يعيد الكائن الذي تم ربط الطريقة به (أو NULL إذا لم تكن الطريقة مرتبطة بكائن). يمكن استرداد اسم الطريقة باستخدام Tcl_MethodName وما إذا كانت الطريقة مصدرة يتم استردادها باستخدام Tcl_MethodIsPublic. يمكن أيضًا فحص نوع الطريقة إلى درجة محدودة؛ تعيد الدالة Tcl_MethodIsType ما إذا كانت الطريقة من نوع معين، وتعين clientData لكل طريقة إلى المتغير المشار إليه بواسطة clientDataPtr إذا (كان غير NULL) إذا تطابق النوع.

إنشاء الطرق

يتم إنشاء الطرق بواسطة Tcl_NewMethod و Tcl_NewInstanceMethod، اللتين تنشئان طريقة مرفقة بفئة أو بكائن على التوالي. في كلتا الحالتين، يحدد الوسيط nameObj اسم الطريقة المراد إنشاؤها، ويحدد الوسيط isPublic ما إذا كان يجب تصدير الطريقة مبدئيًا، ويصف الوسيط methodTypePtr تنفيذ الطريقة (انظر قسم أنواع الطرق أدناه) ويقدم الوسيط clientData بعض البيانات الخاصة بالتنفيذ التي يتم تمريرها إلى تنفيذ الطريقة عند استدعائها.

عندما يكون الوسيط nameObj لـ Tcl_NewMethod هو NULL، يتم إنشاء طريقة غير مسماة، والتي تستخدم للمنشئات والمدمرات. يجب تثبيت المنشئات في فئتها باستخدام الدالة Tcl_ClassSetConstructor، ويجب تثبيت المدمرات (التي لا تتطلب أي وسائط) في فئتها باستخدام الدالة Tcl_ClassSetDestructor. لا ينبغي استخدام الطرق غير المسماة لأي غرض آخر، ولا ينبغي استخدام الطرق المسماة كمنشئات أو مدمرات. لاحظ أيضًا أن methodTypePtr NULL يستخدم لتوفير إشارة داخلية، ولا ينبغي استخدامه في الشفرة العميل.

سياقات استدعاء الطرق

عند استدعاء طريقة، يتم تمرير مرجع سياق استدعاء الطريقة كوسيطة واحدة إلى دالة التنفيذ. يمكن فحص هذا السياق لتوفير معلومات حول المتصل، ولكن يجب عدم الاحتفاظ به بعد لحظة انتهاء استدعاء الطريقة.

يمكن استرداد الطريقة التي يتم استدعاؤها من السياق باستخدام Tcl_ObjectContextMethod، ويمكن استرداد الكائن الذي تسبب في استدعاء الطريقة باستخدام Tcl_ObjectContextObject. يتم قراءة عدد الوسائط التي يجب تخطيها (على سبيل المثال، اسم الكائن واسم الطريقة في استدعاء طريقة عادي) باستخدام Tcl_ObjectContextSkippedArgs، ويمكن للسياق أيضًا الإبلاغ عما إذا كان يعمل كمرشح لطريقة أخرى من خلال Tcl_ObjectContextIsFiltering.

أثناء تنفيذ طريقة، قد يختار تنفيذ الطريقة استدعاء المراحل في سلسلة استدعاء الطريقة التي تأتي بعد تنفيذ الطريقة الحالي. يتم ذلك (جوهر أمر next) باستخدام Tcl_ObjectContextInvokeNext. لاحظ أن هذه الدالة لا تعالج مكدس إطار الاستدعاء، على عكس أمر next؛ إذا دفع تنفيذ الطريقة إطارًا أو أكثر على المكدس كجزء من تنفيذه، فإنه يكون مسؤولًا أيضًا عن إزالة هذه الإطارات مؤقتًا من المكدس أثناء تنفيذ الدالة Tcl_ObjectContextInvokeNext. لاحظ أيضًا أنه لا يتم حذف سياق استدعاء الطريقة أبدًا أثناء تنفيذ هذه الدالة.

أنواع الطرق

يتم وصف أنواع الطرق بواسطة مؤشر إلى بنية Tcl_MethodType، والتي تم تعريفها كالتالي:

typedef struct {
    int version;
    const char *name;
    Tcl_MethodCallProc *callProc;
    Tcl_MethodDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_MethodType;

يسمح حقل version بالتوسع المستقبلي للبنية، ويجب دائمًا تعريفه على أنه مساوٍ لـ TCL_OO_METHOD_VERSION_CURRENT. يوفر حقل name اسمًا يمكن قراءته بواسطة الإنسان للنوع، وهو القيمة التي يتم كشفها عبر أوامر Tcl info class methodtype و info object methodtype.

يحدد حقل callProc دالة يتم استدعاؤها عند استدعاء الطريقة؛ يجب ألا يكون NULL أبدًا.

يحدد حقل deleteProc دالة تستخدم لحذف طريقة معينة، ويتم استدعاؤها عند استبدال الطريقة أو إزالتها؛ إذا كان الحقل NULL، فمن المفترض أن clientData للطريقة لا يحتاج إلى إجراء خاص لحذفه.

حقل cloneProc هو إما دالة تستخدم لنسخ clientData للطريقة (كجزء من Tcl_CopyObjectInstance) أو NULL للإشارة إلى أنه يمكن نسخ clientData مباشرة.

توقيع دالة Tcl_MethodCallProc

يجب أن تتوافق دالة callProc المحددة في بنية Tcl_MethodType مع التوقيع التالي:

typedef int
Tcl_MethodCallProc(
    ClientData clientData,
    Tcl_Interp *interp,
    int objc,
    Tcl_Obj *const objv[]
);

يحتوي clientData على القيمة التي تم تمريرها إلى Tcl_NewMethod أو Tcl_NewInstanceMethod عند إنشاء الطريقة. يحتوي interp على المترجم الذي يتم فيه استدعاء الطريقة، ويحتوي objc و objv على الوسائط التي تم تمريرها إلى الطريقة.

تتلقى الطريقة دائمًا وسيطتين افتراضيتين إضافيتين قبل الوسائط الفعلية التي يتم تمريرها من سطر الأوامر. هذه الوسائط هي:

Tcl_ObjectContext context
سياق الاستدعاء الذي تم إنشاؤه لهذه الطريقة.
Tcl_Method method
الطريقة التي يتم استدعاؤها.

بالإضافة إلى ذلك، قد يتم تمرير عدد من الوسائط الإضافية إلى تنفيذ الطريقة، والتي يحددها حقل skip في Tcl_ObjectContextInvokeNext. يتم تمرير هذه الوسائط مباشرة بعد الوسيط method.

يجب على تنفيذ الطريقة إرجاع TCL_OK في حالة النجاح، أو TCL_ERROR في حالة فشل. سيتم استخدام أي قيمة أخرى كخطأ.

توقيع دالة Tcl_MethodDeleteProc

يجب أن تتوافق دالة deleteProc المحددة في بنية Tcl_MethodType مع التوقيع التالي:

typedef void
Tcl_MethodDeleteProc(
    ClientData clientData
);

يحتوي clientData على القيمة التي تم تمريرها إلى Tcl_NewMethod أو Tcl_NewInstanceMethod عند إنشاء الطريقة.

توقيع دالة Tcl_CloneProc

يجب أن تتوافق دالة cloneProc المحددة في بنية Tcl_MethodType مع التوقيع التالي:

typedef ClientData
Tcl_CloneProc(
    ClientData clientData
);

يحتوي clientData على القيمة التي تم تمريرها إلى Tcl_NewMethod أو Tcl_NewInstanceMethod عند إنشاء الطريقة. يجب أن تعيد النسخة المنسوخة من clientData.

NAME

Tcl_ObjectContextInvokeNext — invoke the next method in the method resolution chain

SYNOPSIS

#include <tclOO.h>
TCL_METHODCALLPROC FUNCTION SIGNATURE

Functions matching this signature are called when the method is invoked.

typedef int Tcl_MethodCallProc(
        ClientData clientData,
        Tcl_Interp *interp,
        Tcl_ObjectContext objectContext,
        int objc,
        Tcl_Obj *const *objv);
TCL_METHODDELETEPROC FUNCTION SIGNATURE

Functions matching this signature are used when a method is deleted, whether through a new method being created or because the object or class is deleted.

typedef void Tcl_MethodDeleteProc(
        ClientData clientData);
TCL_CLONEPROC FUNCTION SIGNATURE

Functions matching this signature are used to copy a method when the object or class is copied using Tcl_CopyObjectInstance (or oo::copy).

typedef int Tcl_CloneProc(
        Tcl_Interp *interp,
        ClientData oldClientData,
        ClientData *newClientDataPtr);

ARGUMENTS

ClientData clientData (input)
The value associated with the method when it was created.
Tcl_Interp *interp (input)
The current interpreter.
Tcl_ObjectContext objectContext (input)
The context in which the method was invoked.
int objc (input)
The number of arguments to the method.
Tcl_Obj *const *objv (input)
The arguments to the method, as Tcl objects.
ClientData clientData (input)
The value associated with the method when it was created.
Tcl_Interp *interp (input)
The current interpreter. Used to write error messages if cloning fails.
ClientData oldClientData (input)
The client data for the method being copied.
ClientData *newClientDataPtr (output)
Pointer to where the client data for the newly created method should be stored.

DESCRIPTION

The Tcl_ObjectContextInvokeNext function is used to call the next method in the method resolution chain. This is typically done within a Tcl_MethodCallProc to implement method overriding or to chain method invocations.

The function takes the current interpreter, the object context, the number of arguments, and the arguments themselves. It returns the result of the invoked method.

The function should only be called when the method context is valid. If the method context is invalid or if there is no next method in the chain, the behavior is undefined.

TCL_METHODCALLPROC FUNCTION SIGNATURE

Functions matching this signature are called when the method is invoked.

typedef int Tcl_MethodCallProc(
        ClientData clientData,
        Tcl_Interp *interp,
        Tcl_ObjectContext objectContext,
        int objc,
        Tcl_Obj *const *objv);

The clientData argument to a Tcl_MethodCallProc is the value that was given when the method was created, the interp is a place in which to execute scripts and access variables as well as being where to put the result of the method, and the objc and objv fields give the parameter objects to the method. The calling context of the method can be discovered through the objectContext argument, and the return value from a Tcl_MethodCallProc is any Tcl return code (e.g. TCL_OK, TCL_ERROR).

TCL_METHODDELETEPROC FUNCTION SIGNATURE

Functions matching this signature are used when a method is deleted, whether through a new method being created or because the object or class is deleted.

typedef void Tcl_MethodDeleteProc(
        ClientData clientData);

The clientData argument to a Tcl_MethodDeleteProc will be the same as the value passed to the clientData argument to Tcl_NewMethod or Tcl_NewInstanceMethod when the method was created.

TCL_CLONEPROC FUNCTION SIGNATURE

Functions matching this signature are used to copy a method when the object or class is copied using Tcl_CopyObjectInstance (or oo::copy).

typedef int Tcl_CloneProc(
        Tcl_Interp *interp,
        ClientData oldClientData,
        ClientData *newClientDataPtr);

The interp argument gives a place to write an error message when the attempt to clone the object is to fail, in which case the clone procedure must also return TCL_ERROR; it should return TCL_OK otherwise. The oldClientData field to a Tcl_CloneProc gives the value from the method being copied from, and the newClientDataPtr field will point to a variable in which to write the value for the method being copied to.
