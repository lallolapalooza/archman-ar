tc-fq(8)

الحزمة: iproute2

التراخيص: GPL-2.0-or-later

FQ(8) Linux FQ(8)

الاسم

FQ - تحديد معدل حركة مرور البيانات بشكل عادل (Fair Queue)

الملخص

tc qdisc ... fq [ limit PACKETS ] [ flow_limit PACKETS ] [ quantum BYTES ] [ initial_quantum BYTES ] [ maxrate RATE ] [ buckets NUMBER ] [ orphan_mask NUMBER ] [ pacing | nopacing ] [ ce_threshold TIME ]

الوصف

FQ (Fair Queue) هو مجدول حزم غير مصنف مخصص بشكل أساسي لحركة المرور المولدة محليًا. تم تصميمه لتحقيق تحديد معدل لكل تدفق. يقوم FQ بفصل التدفقات، وهو قادر على احترام متطلبات تحديد المعدل التي يحددها مكدس TCP. تعتبر جميع الحزم التي تنتمي إلى مقبس 'تدفقًا'. بالنسبة للحزم غير المحلية (عبء عمل الموجه)، يتم استخدام تجزئة الحزمة كبديل.

يمكن للتطبيق تحديد معدل تحديد معدل أقصى باستخدام استدعاء SO_MAX_PACING_RATE setsockopt. يضيف مجدول الحزمة هذا تأخيرًا بين الحزم لاحترام الحد المحدد لكل مقبس. لاحظ أنه بعد linux-4.20، اعتمد لينكس EDT (Earliest Departure Time) ويحدد TCP مباشرة وقت المغادرة المناسب لكل skb.

يحدث إلغاء التجميع بترتيب دائري. يتم تخصيص طابور FIFO خاص للحزم ذات الأولوية العالية (ذات الأولوية TC_PRIO_CONTROL)، ويتم إلغاء تجميع هذه الحزم دائمًا أولاً.

FQ غير محافظ على العمل (non-work-conserving).

يعد تحديد معدل TCP مفيدًا للتدفقات التي لديها فترات خمول، حيث يسمح نافذة الازدحام لمكدس TCP بوضع عدد كبير محتمل من الحزم في الطابور. هذا يلغي خيار 'البداية البطيئة بعد الخمول'، والذي يؤثر بشدة على التدفقات ذات BDP الكبيرة والتطبيقات التي تقدم أجزاء من البيانات مثل بث الفيديو.

المعلمات

limit

حد أقصى لحجم الطابور الفعلي. عند الوصول إلى هذا الحد، يتم إسقاط الحزم الجديدة. إذا تم خفض القيمة، يتم إسقاط الحزم بحيث يتم تلبية الحد الجديد. الافتراضي هو 10000 حزمة.

flow_limit

حد أقصى لعدد الحزم الموجودة في الطابور لكل تدفق. القيمة الافتراضية هي 100.

quantum

الرصيد لكل جولة تجميع دائرية، أي كمية البايتات المسموح بها للتدفق للخروج دفعة واحدة. قيمة أكبر تعني فترة زمنية أطول قبل خدمة التدفق التالي. الافتراضي هو 2 * MTU الواجهة بالبايت.

initial_quantum

رصيد معدل الإرسال الأولي، أي كمية البايتات المسموح بها لتدفق جديد للخروج مبدئيًا. هذا مخصص بشكل خاص للسماح باستخدام IW10 بدون تأخير إضافي. الافتراضي هو 10 * MTU الواجهة، أي 15140 لشبكة الإيثرنت "القياسية".

maxrate

معدل الإرسال الأقصى للتدفق. الافتراضي غير محدود. يتم تجاهل الإعداد الخاص بالتطبيق عبر SO_MAX_PACING_RATE فقط إذا كان أكبر من هذه القيمة.

buckets

حجم جدول التجزئة المستخدم للبحث عن التدفقات. يتم تخصيص شجرة حمراء-سوداء لكل دلو لفرز التصادمات بكفاءة. الافتراضي: 1024.

orphan_mask

بالنسبة للحزم التي لا تنتمي إلى مقبس، يمكن لـ fq إخفاء جزء من skb->hash وتقليل عدد الدلاء المرتبطة بحركة المرور. هذه آلية لمنع هجمات DDOS، والافتراضي هو 1023 (مما يعني عدم تخصيص أكثر من 1024 تدفقًا لهذه الحزم)

[no]pacing

تمكين أو تعطيل تحديد معدل التدفق. الافتراضي هو ممكّن.

ce_threshold

يحدد عتبة يتم عندها تمييز جميع الحزم بعلامة ECN (تجربة الازدحام). هذا مفيد لخوارزميات التحكم في الازدحام من نوع DCTCP التي تتطلب التمييز عند عتبات طوابير ضحلة جدًا.

أمثلة

#tc qdisc add dev eth0 root fq ce_threshold 4ms
#tc -s -d qdisc show dev eth0
qdisc fq 8001: dev eth0 root refcnt 2 limit 10000p flow_limit 100p buckets 1024 orphan_mask 1023 quantum 3028b initial_quantum 15140b low_rate_threshold 550Kbit refill_delay 40.0ms ce_threshold 4.0ms
Sent 72149092 bytes 48062 pkt (dropped 2176, overlimits 0 requeues 0)
backlog 1937920b 1280p requeues 0
flows 34 (inactive 17 throttled 0)
gc 0 highprio 0 throttled 0 ce_mark 47622 flows_plimit 2176
