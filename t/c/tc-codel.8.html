tc-codel(8)

الحزمة: iproute2

التراخيص: GPL-2.0-or-later

CoDel(8) Linux CoDel(8)

الاسم

CoDel - خوارزمية إدارة قائمة الانتظار النشطة (AQM) للتحكم في التأخير

الملخص

tc qdisc ... codel [ limit PACKETS ] [ target TIME ] [ interval TIME ] [ ecn | noecn ] [ ce_threshold TIME ]

الوصف

CoDel (تُنطق "coddle") هي آلية تكيفية "بدون مقاييس" لإدارة قائمة الانتظار النشطة (AQM) تم تطويرها لمعالجة أوجه القصور في RED ومتغيراتها. تم تطويرها مع الأهداف التالية في الاعتبار:

  • يجب أن تكون بدون معلمات.
  • يجب أن تحافظ على انخفاض التأخيرات مع السماح بتدفقات حركة المرور المتدفقة.
  • يجب أن تتحكم في التأخير.
  • يجب أن تتكيف ديناميكيًا مع معدلات الارتباط المتغيرة دون التأثير على الاستخدام.
  • يجب أن تكون بسيطة وفعالة ويجب أن تتوسع من أجهزة التوجيه البسيطة إلى المعقدة.

الخوارزمية

تأتي CoDel بثلاثة ابتكارات رئيسية. بدلاً من استخدام حجم قائمة الانتظار أو متوسط قائمة الانتظار، تستخدم الحد الأدنى لقائمة الانتظار المحلية كمقياس لقائمة الانتظار الدائمة/المستمرة. ثانيًا، تستخدم متغير تتبع حالة واحد للتأخير الأدنى لمعرفة مكانها مقارنة بتأخير قائمة الانتظار الدائمة. ثالثًا، بدلاً من قياس حجم قائمة الانتظار بالبايت أو الحزم، يتم قياسها بوقت بقاء الحزمة في قائمة الانتظار.

تقوم CoDel بقياس الحد الأدنى لتأخير قائمة الانتظار المحلية (أي، تأخير قائمة الانتظار الدائمة) وتقارنه بقيمة target التأخير المقبول لقائمة الانتظار. طالما أن الحد الأدنى لتأخير قائمة الانتظار أقل من target أو يحتوي المخزن المؤقت على أقل من MTU من البايت، فلن يتم إسقاط الحزم. تدخل Codel في وضع إسقاط عندما يتجاوز الحد الأدنى لتأخير قائمة الانتظار target لفترة زمنية أكبر من interval. في هذا الوضع، يتم إسقاط الحزم في أوقات إسقاط مختلفة يتم تحديدها بواسطة قانون تحكم. يضمن قانون التحكم أن تؤدي عمليات إسقاط الحزم إلى تغيير خطي في الإنتاجية. بمجرد أن يصبح الحد الأدنى للتأخير أقل من target، لن يتم إسقاط الحزم بعد الآن.

يمكن العثور على تفاصيل إضافية في الورقة البحثية المشار إليها أدناه.

المعلمات

limit

هو الحد الأقصى لحجم قائمة الانتظار الحقيقي. عند الوصول إلى هذا الحد، يتم إسقاط الحزم الواردة. إذا تم خفض القيمة، يتم إسقاط الحزم بحيث يتم تلبية الحد الجديد. القيمة الافتراضية هي 1000 حزمة.

target

هو الحد الأدنى المقبول لتأخير قائمة الانتظار الدائمة/المستمرة. يتم تحديد هذا التأخير الأدنى عن طريق تتبع الحد الأدنى المحلي لتأخير قائمة الانتظار الذي تواجهه الحزم. القيمة الافتراضية والموصى بها هي 5 مللي ثانية.

interval

يُستخدم لضمان عدم تقادم التأخير الأدنى المقاس. يجب أن يتم تجربة التأخير الأدنى في الحقبة الأخيرة بطول interval. يجب تعيينه على مقياس أسوأ حالة لدورة الذهاب والإياب (RTT) عبر الاختناق لمنح نقاط النهاية وقتًا كافيًا للتفاعل. القيمة الافتراضية هي 100 مللي ثانية.

ecn | noecn

يمكن استخدامه لتمييز الحزم بدلاً من إسقاطها. إذا تم تمكين ecn، يمكن استخدام noecn لإيقافه والعكس صحيح. بشكل افتراضي، يتم إيقاف تشغيل ecn.

ce_threshold

يحدد حدًا يتم فوقه تمييز جميع الحزم بـ ECN Congestion Experienced. هذا مفيد لخوارزميات التحكم في الازدحام من نوع DCTCP التي تتطلب التمييز عند حدود طوابير ضحلة جدًا.

أمثلة


# tc qdisc add dev eth0 root codel
# tc -s qdisc show
qdisc codel 801b: dev eth0 root refcnt 2 limit 1000p target 5.0ms interval 100.0ms
Sent 245801662 bytes 275853 pkt (dropped 0, overlimits 0 requeues 24)
backlog 0b 0p requeues 24
count 0 lastcount 0 ldelay 2us drop_next 0us
maxpacket 7306 ecn_mark 0 drop_overlimit 0


# tc qdisc add dev eth0 root codel limit 100 target 4ms interval 30ms ecn
# tc -s qdisc show
qdisc codel 801c: dev eth0 root refcnt 2 limit 100p target 4.0ms interval 30.0ms ecn
Sent 237573074 bytes 268561 pkt (dropped 0, overlimits 0 requeues 5)
backlog 0b 0p requeues 5
count 0 lastcount 0 ldelay 76us drop_next 0us
maxpacket 2962 ecn_mark 0 drop_overlimit 0
