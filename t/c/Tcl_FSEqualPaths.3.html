Tcl_FSNewNativePath performs something like the reverse of the usual obj->path->nativerep conversions. If some code retrieves a path in native form (from, e.g. readlink or a native dialog), and that path is to be used at the Tcl level, then calling this function is an efficient way of creating the appropriate path value type.

The resulting value is a pure “path” value, which will only receive a UTF-8 string representation if that is required by some Tcl code.

Tcl_FSGetNativePath is for use by the Win/Unix native filesystems, so that they can easily retrieve the native (char* or TCHAR*) representation of a path. This function is a convenience wrapper around Tcl_FSGetInternalRep. It may be desirable in the future to have non-string-based native representations (for example, on macOS, a representation using a fileSpec of FSRef structure would probably be more efficient). On Windows a full Unicode representation would allow for paths of unlimited length. Currently the representation is simply a character string which may contain either the relative path or a complete, absolute normalized path in the native encoding (complex conditions dictate which of these will be provided, so neither can be relied upon, unless the path is known to be absolute). If you need a native path which must be absolute, then you should ask for the native version of a normalized path. If for some reason a non-absolute, non-normalized version of the path is needed, that must be constructed separately (e.g. using Tcl_FSGetTranslatedPath).

The native representation is cached so that repeated calls to this function will not require additional conversions. The return value is owned by Tcl and has a lifetime equivalent to that of the pathPtr passed in (unless that is a relative path, in which case the native representation may be freed any time the cwd changes).

Tcl_FSFileSystemInfo returns a list of two elements. The first element is the name of the filesystem (e.g. “native”, “vfs”, “zip”, or “prowrap”, perhaps), and the second is the particular type of the given path within that filesystem (which is filesystem dependent). The second element may be empty if the filesystem does not provide a further categorization of files.

A valid list value is returned, unless the path value is not recognized, when NULL will be returned.

Tcl_FSGetFileSystemForPath returns a pointer to the Tcl_Filesystem which accepts this path as valid.

If no filesystem will accept the path, NULL is returned.

Tcl_FSGetPathType determines whether the given path is relative to the current directory, relative to the current volume, or absolute.

It returns one of TCL_PATH_ABSOLUTE, TCL_PATH_RELATIVE, or TCL_PATH_VOLUME_RELATIVE

واجهة برمجة تطبيقات نظام الملفات الافتراضية

A filesystem provides a Tcl_Filesystem structure that contains pointers to functions that implement the various operations on a filesystem; these operations are invoked as needed by the generic layer, which generally occurs through the functions listed above.

The Tcl_Filesystem structures are manipulated using the following methods.

Tcl_FSRegister takes a pointer to a filesystem structure and an optional piece of data to associated with that filesystem. On calling this function, Tcl will attach the filesystem to the list of known filesystems, and it will become fully functional immediately. Tcl does not check if the same filesystem is registered multiple times (and in general that is not a good thing to do). TCL_OK will be returned.

Tcl_FSUnregister removes the given filesystem structure from the list of known filesystems, if it is known, and returns TCL_OK. If the filesystem is not currently registered, TCL_ERROR is returned.

Tcl_FSData will return the clientData associated with the given filesystem, if that filesystem is registered. Otherwise it will return NULL.

Tcl_FSMountsChanged is used to inform the Tcl's core that the set of mount points for the given (already registered) filesystem have changed, and that cached file representations may therefore no longer be correct.

بنية Tcl_Filesystem

The Tcl_Filesystem structure contains the following fields:

typedef struct Tcl_Filesystem {
    const char *typeName;
    int structureLength;
    Tcl_FSVersion version;
    Tcl_FSPathInFilesystemProc *pathInFilesystemProc;
    Tcl_FSDupInternalRepProc *dupInternalRepProc;
    Tcl_FSFreeInternalRepProc *freeInternalRepProc;
    Tcl_FSInternalToNormalizedProc *internalToNormalizedProc;
    Tcl_FSCreateInternalRepProc *createInternalRepProc;
    Tcl_FSNormalizePathProc *normalizePathProc;
    Tcl_FSFilesystemPathTypeProc *filesystemPathTypeProc;
    Tcl_FSFilesystemSeparatorProc *filesystemSeparatorProc;
    Tcl_FSStatProc *statProc;
    Tcl_FSAccessProc *accessProc;
    Tcl_FSOpenFileChannelProc *openFileChannelProc;
    Tcl_FSMatchInDirectoryProc *matchInDirectoryProc;
    Tcl_FSUtimeProc *utimeProc;
    Tcl_FSLinkProc *linkProc;
    Tcl_FSListVolumesProc *listVolumesProc;
    Tcl_FSFileAttrStringsProc *fileAttrStringsProc;
    Tcl_FSFileAttrsGetProc *fileAttrsGetProc;
    Tcl_FSFileAttrsSetProc *fileAttrsSetProc;
    Tcl_FSCreateDirectoryProc *createDirectoryProc;
    Tcl_FSRemoveDirectoryProc *removeDirectoryProc;
    Tcl_FSDeleteFileProc *deleteFileProc;
    Tcl_FSCopyFileProc *copyFileProc;
    Tcl_FSRenameFileProc *renameFileProc;
    Tcl_FSCopyDirectoryProc *copyDirectoryProc;
    Tcl_FSLstatProc *lstatProc;
    Tcl_FSLoadFileProc *loadFileProc;
    Tcl_FSGetCwdProc *getCwdProc;
    Tcl_FSChdirProc *chdirProc;
} Tcl_Filesystem;

Except for the first three fields in this structure which contain simple data elements, all entries contain addresses of functions called by the generic filesystem layer to perform the complete range of filesystem related actions.

The many functions in this structure are broken down into three categories: infrastructure functions (almost all of which must be implemented), operational functions (which must be implemented if a complete filesystem is provided), and efficiency functions (which need only be implemented if they can be done so efficiently, or if they have side-effects which are required by the filesystem; Tcl has less efficient emulations it can fall back on). It is important to note that, in the current version of Tcl, most of these fallbacks are only used to handle commands initiated in Tcl, not in C. What this means is, that if a file rename command is issued in Tcl, and the relevant filesystem(s) do not implement their Tcl_FSRenameFileProc, Tcl's core will instead fallback on a combination of other filesystem functions (it will use Tcl_FSCopyFileProc followed by Tcl_FSDeleteFileProc, and if Tcl_FSCopyFileProc is not implemented there is a further fallback). However, if a Tcl_FSRenameFileProc command is issued at the C level, no such fallbacks occur. This is true except for the last four entries in the filesystem table (lstat, load, getcwd and chdir) for which fallbacks do in fact occur at the C level.

Any functions which take path names in Tcl_Obj form take those names in UTF-8 form. The filesystem infrastructure API is designed to support efficient, cached conversion of these UTF-8 paths to other native representations.

بنية نظام الملفات

تحتوي هذه الحقول على معلومات أساسية حول بنية نظام الملفات وعناوين الوظائف المستخدمة لربط نظام ملفات معين بقيمة مسار، ومعالجة التمثيل الداخلي للمسارات، على سبيل المثال، نسخ هذه التمثيلات وتحريرها.

اسم النوع

يحتوي الحقل typeName على سلسلة منتهية بـ NULL تحدد نوع نظام الملفات الذي تم تنفيذه، على سبيل المثال، "native" أو "zip" أو "vfs".

طول البنية

يتم تنفيذ الحقل structureLength عمومًا كـ sizeof(Tcl_Filesystem)، وهو موجود للسماح بتوافق ثنائي أسهل إذا تغير حجم البنية في إصدار مستقبلي من Tcl.

الإصدار

يجب تعيين الحقل version إلى TCL_FILESYSTEM_VERSION_1.

يحتوي الحقل pathInFilesystemProc على عنوان وظيفة يتم استدعاؤها لتحديد ما إذا كانت قيمة المسار المعطاة تنتمي إلى نظام الملفات هذا أم لا. ستستدعي Tcl فقط وظائف نظام الملفات الأخرى بمسار أعادت هذه الوظيفة TCL_OK له. إذا لم يكن المسار ينتمي، فيجب إرجاع -1 (سلوك Tcl لأي قيمة إرجاع أخرى غير محدد). إذا تم إرجاع TCL_OK، فيمكن استخدام معلمة الإخراج الاختيارية clientDataPtr لإرجاع تمثيل داخلي (خاص بنظام الملفات) للمسار، والذي سيتم تخزينه مؤقتًا داخل قيمة المسار، ويمكن استعادته بكفاءة بواسطة وظائف نظام الملفات الأخرى. ستقوم Tcl بتخزين ما يدل على أن هذا المسار ينتمي إلى نظام الملفات هذا بشكل متزامن. يتم إبطال صلاحية مثل هذه المخازن المؤقتة عند إضافة هياكل نظام الملفات أو إزالتها من قائمة أنظمة الملفات المعروفة داخليًا لـ Tcl.

typedef int Tcl_FSPathInFilesystemProc(

وظيفة تسوية المسار

وظيفة لتسوية المسار. يجب تنفيذها لجميع أنظمة الملفات التي يمكن أن يكون لها تمثيلات سلسلة متعددة لنفس قيمة المسار. في Tcl، يجب أن يكون لكل "مسار" تمثيل "عادي" فريد. اعتمادًا على نظام الملفات، قد يكون هناك أكثر من تمثيل واحد غير عادي يشير إلى نفس المسار (على سبيل المثال، مسار نسبي، مسار بحالة مختلفة إذا كان نظام الملفات غير حساس لحالة الأحرف، مسار يحتوي على إشارة إلى مجلد المنزل مثل ~، مسار يحتوي على روابط رمزية، وما إلى ذلك). إذا كان المكون الأخير للمسار رابطًا رمزيًا، فلا يجب تحويله إلى القيمة التي يشير إليها (ولكن يجب أن تكون حالته أو جوانبه الأخرى فريدة). يجب تحويل جميع المكونات الأخرى للمسار من الروابط الرمزية. هذا الاستثناء مطلوب للتوافق مع سلوك Tcl في استخدام file delete و file rename و file copy مع الروابط الرمزية. قد يتم استدعاء هذه الوظيفة مع nextCheckpoint في بداية المسار (أي صفر)، أو في نهاية المسار، أو في أي نقطة فاصلة للملف في المسار. لن تشير أبدًا إلى أي موضع عشوائي في المسار. في الحالة الأخيرة من الحالات الثلاث الصالحة، يمكن للتنفيذ افتراض أن المسار حتى وفاصل الملف مضمن ومعروف وعادي.

typedef int Tcl_FSNormalizePathProc(
        Tcl_Interp *interp,
        Tcl_Obj *pathPtr,
        int nextCheckpoint);

عمليات نظام الملفات

تحتوي حقول هذا القسم من البنية على عناوين وظائف يتم استدعاؤها لتنفيذ عمليات نظام الملفات الأساسية. يجب على نظام الملفات الذي يتوقع استخدامه مع مجموعة أوامر Tcl الكاملة تنفيذ كل هذه. إذا لم يتم تنفيذ بعضها، فقد تفشل أوامر Tcl معينة عند العمل على المسارات داخل نظام الملفات هذا. ومع ذلك، في بعض الحالات قد يكون هذا مرغوبًا (على سبيل المثال، نظام ملفات للقراءة فقط لا ينبغي له تنفيذ الوظائف الأربع الأخيرة، ونظام ملفات لا يدعم الروابط الرمزية لا ينبغي له تنفيذ وظيفة readlink، وما إلى ذلك). تتوقع بنية Tcl أن تتصرف أنظمة الملفات بهذه الطريقة.

typedef Tcl_Obj *Tcl_FSFilesystemSeparatorProc(

وظيفة STAT

وظيفة لمعالجة استدعاء Tcl_FSStat. يجب تنفيذها لأي نظام ملفات معقول، حيث تعتمد العديد من أوامر Tcl عالية المستوى بشكل حاسم عليها (على سبيل المثال، file atime و file isdirectory و file size و glob).

typedef int Tcl_FSStatProc(
        Tcl_Obj *pathPtr,
        Tcl_StatBuf *statPtr);

تملأ الوظيفة Tcl_FSStatProc المخزن المؤقت للإحصائيات statPtr بمعلومات حول الملف المحدد. لا تحتاج إلى حقوق وصول للملف للحصول على هذه المعلومات، ولكنك تحتاج إلى حقوق بحث لجميع الدلائل المذكورة في المسار الذي يؤدي إلى هذا الملف. يتضمن المخزن المؤقت للإحصائيات معلومات حول الجهاز، و i-node (دائمًا 0 في Windows)، ووضع الامتياز، و nlink (دائمًا 1 في Windows)، ومعرف المستخدم (دائمًا 0 في Windows)، ومعرف المجموعة (دائمًا 0 في Windows)، و rdev (نفس الجهاز في Windows)، والحجم، ووقت الوصول الأخير، ووقت التعديل الأخير، ووقت آخر تعديل للبيانات.

إذا كان الملف الممثل بـ pathPtr موجودًا، فسترجع Tcl_FSStatProc 0 ويتم ملء المخزن المؤقت للإحصائيات بالبيانات. بخلاف ذلك، يتم إرجاع -1 ولا يتم تقديم معلومات الإحصائيات.

وظيفة الوصول

وظيفة لمعالجة استدعاء Tcl_FSAccess. يجب تنفيذها لأي نظام ملفات معقول، حيث تعتمد العديد من أوامر Tcl عالية المستوى بشكل حاسم عليها (على سبيل المثال، file exists و file readable).

typedef int Tcl_FSAccessProc(
        Tcl_Obj *pathPtr,
        int mode);

تتحقق الوظيفة Tcl_FSAccessProc مما إذا كانت العملية ستسمح بقراءة الملف (أو كائن نظام ملفات آخر) أو كتابته أو اختبار وجوده (الاسم في pathPtr). إذا كان المسار يشير إلى رابط رمزي، فيجب اختبار أذونات الملف الذي يشير إليه هذا الرابط الرمزي.

في حالة النجاح (تم منح جميع الأذونات المطلوبة)، يتم إرجاع 0. في حالة حدوث خطأ (تم رفض بت واحد على الأقل في الوضع المطلوب أو حدث خطأ آخر)، يتم إرجاع -1.

وظيفة لفتح قناة لملف. يجب تنفيذها لأي نظام ملفات معقول، حيث أن أوامر Tcl مثل puts و gets و read تعتمد عليها بشكل حاسم. يجب إرجاع مؤشر إلى كائن Tcl_Channel.

typedef Tcl_Channel Tcl_FSOpenFileChannelProc(

OPENFILECHANNELPROC

وظيفة لمعالجة استدعاء Tcl_FSOpenFileChannel. يجب تنفيذها لأي نظام ملفات معقول، حيث ستستخدمها جميع العمليات التي تتطلب فتح أو الوصول إلى محتويات ملف (مثل open و encoding والعديد من أوامر Tk).

typedef Tcl_Channel Tcl_FSOpenFileChannelProc(
        Tcl_Interp *interp,
        Tcl_Obj *pathPtr,
        int mode,
        int permissions);

تقوم Tcl_FSOpenFileChannelProc بفتح ملف محدد بواسطة pathPtr وتعيد مقبض قناة يمكن استخدامه لإجراء عمليات الإدخال والإخراج على الملف. تمت نمذجة واجهة برمجة التطبيقات هذه بعد إجراء fopen لمكتبة الإدخال والإخراج القياسية في Unix. يتشابه بناء و معنى جميع الوسائط مع تلك المعطاة في أمر Tcl open عند فتح ملف، حيث يكون الوسيط mode مزيجًا من علامات POSIX O_RDONLY و O_WRONLY وما إلى ذلك. إذا حدث خطأ أثناء فتح القناة، فإن Tcl_FSOpenFileChannelProc تعيد NULL وتسجل رمز خطأ POSIX يمكن استرجاعه باستخدام Tcl_GetErrno. بالإضافة إلى ذلك، إذا كان interp غير NULL، فإن Tcl_FSOpenFileChannelProc تترك رسالة خطأ في نتيجة interp بعد أي خطأ.

يجب ألا يتم تسجيل القناة التي تم إنشاؤها حديثًا في المترجم المقدم بواسطة Tcl_FSOpenFileChannelProc؛ هذه المهمة تقع على عاتق المتصل بـ Tcl_FSOpenFileChannel (إذا لزم الأمر). إذا تم إغلاق إحدى القنوات القياسية، stdin أو stdout أو stderr، في السابق، فإن عملية إنشاء القناة الجديدة تقوم أيضًا بتعيينها كبديل للقناة القياسية.

MATCHINDIRECTORYPROC

وظيفة لمعالجة استدعاء Tcl_FSMatchInDirectory. إذا لم يتم تنفيذها، فستكون وظائف glob والنسخ المتكرر غير متوفرة في نظام الملفات (وقد يؤثر ذلك على أوامر مثل encoding names التي تستخدم وظائف glob داخليًا).

typedef int Tcl_FSMatchInDirectoryProc(
        Tcl_Interp *interp,
        Tcl_Obj *resultPtr,
        Tcl_Obj *pathPtr,
        const char *pattern,
        Tcl_GlobTypeData *types);

يجب أن تعيد الوظيفة جميع الملفات أو الدلائل (أو كائنات نظام الملفات الأخرى) التي تطابق النمط المحدد وتتوافق مع مواصفات types المقدمة. هناك طريقتان يمكن استدعاء هذه الوظيفة بهما. إذا كان pattern NULL، فإن pathPtr هو مواصفات مسار كامل لملف أو دليل واحد يجب التحقق من وجوده ونوعه الصحيح. بخلاف ذلك، فإن pathPtr هو دليل، ويجب على الوظيفة البحث في محتوياته عن الملفات أو الدلائل ذات النوع الصحيح. في كلتا الحالتين، يمكن افتراض أن pathPtr غير NULL وغير فارغ. لا تزال غير موثقة ما إذا كان pathPtr سيحتوي على فاصل ملف في نهايته أم لا، لذا يجب أن يكون الكود مرنًا لكلا الاحتمالين.

القيمة المعادة هي نتيجة Tcl قياسية تشير إلى ما إذا كان قد حدث خطأ أثناء عملية المطابقة. يتم وضع رسائل الخطأ في interp، ما لم يكن interp NULL في هذه الحالة لا حاجة لتوليد رسالة خطأ؛ عند نتيجة TCL_OK، يجب إضافة النتائج إلى قيمة resultPtr المقدمة (والتي يمكن افتراض أنها قائمة Tcl صالحة وغير مشتركة). يجب أن تتضمن التطابقات المضافة إلى resultPtr أي بادئة مسار معطاة في pathPtr (وهذا يعني عادةً أنها ستكون مواصفات مسار مطلق). لاحظ أنه إذا لم يتم العثور على أي تطابقات، فإن ذلك يؤدي ببساطة إلى نتيجة فارغة؛ يتم الإشارة إلى الأخطاء فقط للمشاكل الفعلية في الملفات أو نظام الملفات التي قد تحدث أثناء عملية المطابقة.

يحتوي هيكل Tcl_GlobTypeData الذي يتم تمريره في الوسيط types على الحقول التالية:

typedef struct Tcl_GlobTypeData {
    /* يتوافق مع bcdpfls كما في 'find -t' */
    int type;
    /* يتوافق مع أذونات الملف */
    int perm;
    /* نوع Mac مقبول */
    Tcl_Obj *macType;
    /* منشئ Mac مقبول */
    Tcl_Obj *macCreator;
} Tcl_GlobTypeData;

هناك حالتان مهمتان يجب التعامل معهما بشكل صحيح، وكلاهما عندما يكون types غير NULL. الحالتان هما عندما يكون types->types & TCL_GLOB_TYPE_DIR أو types->types & TCL_GLOB_TYPE_MOUNT صحيحين (وبشكل خاص عندما تكون الأعلام الأخرى خاطئة). في الحالة الأولى، يجب على الوظيفة سرد الدلائل المحتواة. تستخدم Tcl هذا لتنفيذ glob متكرر، لذا من الضروري أن تقوم أنظمة الملفات بتنفيذ مطابقة الدلائل بشكل صحيح. في الحالة الثانية، مع TCL_GLOB_TYPE_MOUNT، يجب على نظام الملفات سرد نقاط التحميل الموجودة داخل pathPtr المحدد (وفي هذه الحالة، قد لا يقع pathPtr ضمن نفس نظام الملفات - يختلف عن جميع الحالات الأخرى التي يتم فيها استدعاء هذه الوظيفة). يعد الدعم لهذا الأمر بالغ الأهمية إذا أرادت Tcl أن يكون لديها انتقالات سلسة بين نظام ملفات وآخر.

UTIMEPROC

وظيفة لمعالجة استدعاء Tcl_FSUtime. مطلوب للسماح بضبط (وليس قراءة) الأوقات باستخدام file mtime و file atime وتنفيذ open-r/open-w/fcopy لأمر file copy.

typedef int Tcl_FSUtimeProc(
        Tcl_Obj *pathPtr,
        struct utimbuf *tval);

يجب تغيير أوقات الوصول والتعديل للملف المحدد بواسطة pathPtr إلى القيم المعطاة في هيكل tval.

يجب أن تكون القيمة المعادة 0 عند النجاح و -1 عند حدوث خطأ، كما هو الحال مع utime في النظام.

LINKPROC

وظيفة لمعالجة استدعاء Tcl_FSLink. يجب تنفيذها فقط إذا كان نظام الملفات يدعم الروابط، ويمكن أن تكون NULL بخلاف ذلك.

typedef Tcl_Obj *Tcl_FSLinkProc(
        Tcl_Obj *linkNamePtr,
        Tcl_Obj *toPtr,
        int linkAction);

إذا كان toPtr NULL، فسيتم سؤال الوظيفة عن قراءة محتويات رابط. النتيجة هي Tcl_Obj يحدد محتويات الرابط المعطى بواسطة linkNamePtr، أو NULL إذا تعذر قراءة الرابط. المالك للنتيجة هو المتصل (ويجب بالتالي زيادة عدد المراجع الخاصة بها قبل إعادتها). يجب على أي متصلين استدعاء Tcl_DecrRefCount لهذه النتيجة عندما لم تعد مطلوبة. إذا كان toPtr غير NULL، فيجب على الوظيفة محاولة إنشاء رابط. يجب أن تكون النتيجة في هذه الحالة هي toPtr إذا نجح الرابط و NULL بخلاف ذلك. في هذه الحالة، النتيجة ليست مملوكة للمتصل (أي لا يلزم إجراء أي تعديلات على عدد المراجع من أي طرف). راجع وثائق Tcl_FSLink لتفسير صحيح لأعلام linkAction.

LISTVOLUMESPROC

وظيفة لسرد أي وحدات تخزين نظام ملفات تم إضافتها بواسطة نظام الملفات هذا. يجب تنفيذها فقط إذا قام نظام الملفات بإضافة وحدات تخزين في مقدمة نظام الملفات، بحيث يمكن إعادتها بواسطة file volumes.

typedef Tcl_Obj *Tcl_FSListVolumesProc(void);

يجب أن تكون النتيجة قائمة بوحدات التخزين التي أضافها نظام الملفات هذا، أو NULL (أو قائمة فارغة) إذا لم يتم توفير أي وحدات تخزين. تعتبر قيمة النتيجة مملوكة لنظام الملفات (وليس لنواة Tcl)، ولكن يجب إعطاؤها عدد مراجع لـ Tcl. ستستخدم Tcl محتويات القائمة ثم تقلل عدد المراجع هذا. هذا يسمح لأنظمة الملفات بالاختيار ما إذا كانت تريد فعليًا الاحتفاظ بقائمة "عامة" لوحدات التخزين أم لا (إذا لم يكن الأمر كذلك، فإنها تولد القائمة ديناميكيًا وتمررها إلى Tcl مع عدد مراجع 1 ثم تنسى القائمة، وإذا كان الأمر كذلك، فإنها ببساطة تزيد عدد مراجع قائمتها العامة وتمررها إلى Tcl التي ستنسخ المحتويات ثم تقلل العدد مرة أخرى إلى ما كان عليه).

لذلك، تعتبر Tcl القيم المعادة من هذه الوظيفة للقراءة فقط.

FILEATTRSTRINGSPROC

وظيفة لسرد جميع سلاسل السمات التي تكون صالحة لنظام الملفات هذا. إذا لم يتم تنفيذها، فلن يدعم نظام الملفات أمر file attributes. هذا يسمح بإرفاق معلومات إضافية عشوائية بالملفات في نظام الملفات. إذا لم يتم تنفيذها، فلا حاجة لتنفيذ طرق get و set.

typedef const char *const *Tcl_FSFileAttrStringsProc(
        Tcl_Obj *pathPtr,
        Tcl_Obj **objPtrRef);

قد تعيد الوظيفة المستدعاة مصفوفة من السلاسل، أو قد تعيد NULL بدلاً من ذلك وتضع قائمة Tcl في objPtrRef المقدم. ستأخذ Tcl هذه القائمة وتزيد عدد مراجعها أولاً قبل استخدامها. عند الانتهاء من هذا الاستخدام، ستقلل Tcl عدد المراجع الخاص بها. وبالتالي، إذا كان يجب التخلص من القائمة بواسطة Tcl عند الانتهاء، فيجب أن يكون عدد مراجعها صفرًا، وإذا كان يجب عدم التخلص من القائمة، فيجب على نظام الملفات التأكد من أنه يعيد قيمة بعدد مراجع لا يقل عن واحد.

FILEATTRSGETPROC

وظيفة لمعالجة استدعاء Tcl_FSFileAttrsGet، يستخدم بواسطة file attributes.

typedef int Tcl_FSFileAttrsGetProc(
        Tcl_Interp *interp,
        int index,
        Tcl_Obj *pathPtr,
        Tcl_Obj **objPtrRef);

يعيد رمز نتيجة Tcl قياسي. قيمة السمة المسترجعة، والتي تتوافق مع العنصر ذي المؤشر index في القائمة التي تم إعادتها بواسطة Tcl_FSFileAttrStringsProc، هي Tcl_Obj تم وضعه في objPtrRef (إذا تم إرجاع TCL_OK) ومن المحتمل أن يكون عدد مراجعها صفرًا. في كلتا الحالتين، يجب علينا إما تخزينه في مكان ما (مثل نتيجة Tcl)، أو زيادة/تقليل عدد مراجعها لضمان تحريرها بشكل صحيح.

FILEATTRSSETPROC

وظيفة لمعالجة استدعاء Tcl_FSFileAttrsSet، يستخدم بواسطة file attributes. إذا كان نظام الملفات للقراءة فقط، فلا حاجة لتنفيذ هذا.

typedef int Tcl_FSFileAttrsSetProc(
        Tcl_Interp *interp,
        int index,
        Tcl_Obj *pathPtr,
        Tcl_Obj *objPtr);

يجب تعيين قيمة السمة للعنصر ذي المؤشر index في القائمة التي تم إعادتها بواسطة Tcl_FSFileAttrStringsProc إلى objPtr المقدم.
