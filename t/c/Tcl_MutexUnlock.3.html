ARGUMENTS

threadIdPtr (out)
A pointer to a Tcl_ThreadId that will hold the identity of the newly created thread.
proc (in)
The procedure to execute in the new thread. It should have the signature Tcl_ThreadCreateType and take a ClientData argument.
clientData (in)
A value to pass to the new thread's procedure.
stackSize (in)
The desired stack size for the new thread. Use TCL_THREAD_STACK_DEFAULT for the system default.
joinable (in)
A boolean flag indicating whether the thread should be joinable. Use TCL_THREAD_JOINABLE for joinable threads, TCL_THREAD_DETACHED for detached threads.
mutexPtr (in)
A pointer to a Tcl_Mutex object.
mutexes (in)
An array of Tcl_Mutex objects.
keyPtr (in)
A pointer to a Tcl_ThreadKey object.
newKey (in)
A boolean flag. If true, a new key will be created if the key does not exist.
data (in)
The thread-specific data to associate with the key.

INTRODUCTION

Tcl 8.5 introduces support for creating and managing native threads within a Tcl application. This functionality is exposed through a set of Tcl C API functions that allow Tcl applications to create threads, create and manage mutexes, and manage thread-local data.

The Tcl threading model is based on the POSIX Threads standard, but provides a portable interface across different operating systems.

DESCRIPTION

The Tcl threading API provides the following functions:

Tcl_CreateThread creates a new thread and starts its execution. The new thread will execute the procedure specified by proc, passing it the clientData argument. The stack size and joinability of the new thread can be specified.

Tcl_MutexCreate creates a new mutex object. A mutex (mutual exclusion) is a synchronization primitive that can be used to protect shared data from concurrent access by multiple threads.

Tcl_MutexLock locks a mutex. If the mutex is already locked by another thread, the current thread will block until the mutex is unlocked. Recursive locking is supported.

Tcl_MutexUnlock unlocks a mutex. If other threads are waiting to acquire the mutex, one of them will be woken up and allowed to acquire the mutex.

Tcl_MutexUnlockAll unlocks all mutexes in the given array. This is useful in situations where a thread needs to release all held mutexes before blocking or performing an operation that might deadlock.

Tcl_MutexInvestigate checks the state of a mutex. It returns one of the following values:

  • TCL_MUTEX_BAD: The mutex is not valid.
  • TCL_MUTEX_ERROR: An error occurred while accessing the mutex.
  • TCL_MUTEX_DEADLOCK: The mutex is currently locked by the calling thread (recursive lock) or a deadlock is detected.
  • TCL_MUTEX_RECURSIVE: The mutex is currently locked by the calling thread (recursive lock).

Tcl_MutexSustain ensures that a mutex remains locked. This is useful for preventing other threads from acquiring the mutex while a thread is performing a critical operation.

Tcl_MutexRelease releases a mutex without unlocking it. This is useful in scenarios where a thread needs to transfer ownership of a mutex to another thread.

Tcl_MutexDestroy destroys a mutex object. The mutex must not be locked when it is destroyed.

Tcl_GetThreadData retrieves thread-specific data associated with a key. If the key does not exist for the current thread, and newKey is true, a new key will be created and initialized to NULL.

Tcl_SetThreadData associates data with a thread-specific key for the current thread.

SCRIPT-LEVEL ACCESS TO THREADS

Tcl also provides script-level access to its threading primitives through the following commands:

thread
Creates a new thread, runs a script in it, and optionally waits for it to complete. Provides access to thread-local storage.
mutex
Creates, locks, unlocks, and destroys mutexes. Supports recursive locking.

The thread command is the primary way to create and manage threads from Tcl scripts. It provides a high-level interface to the underlying C API. The mutex command provides script-level access to mutexes, allowing for synchronization between threads.

For more information on using Tcl threads and mutexes from Tcl scripts, refer to the documentation for the thread and mutex commands. The Thread package provides this functionality.

EXAMPLE

To create a thread with portable code, its implementation function should be declared as follows:

static Tcl_ThreadCreateProc MyThreadImplFunc;

It should then be defined like this example, which just counts up to a given value and then finishes.

static Tcl_ThreadCreateType
MyThreadImplFunc(
    ClientData clientData)
{
    int i, limit = (int) clientData;
    for (i=0 ; i<limit ; i++) {
        /* doing nothing at all here */
    }
    TCL_THREAD_CREATE_RETURN;
}

To create the above thread, make it execute, and wait for it to finish, we would do this:

int limit = 1000000000;
ClientData limitData = (void*)((intptr_t) limit);
Tcl_ThreadId id;    /* holds identity of thread created */
int result;
if (Tcl_CreateThread(&id, MyThreadImplFunc, limitData,
        TCL_THREAD_STACK_DEFAULT,
        TCL_THREAD_JOINABLE) != TCL_OK) {
    /* Thread did not create correctly */
    return;
}
/* Do something else for a while here */
if (Tcl_JoinThread(id, &result) != TCL_OK) {
    /* Thread did not finish properly */
    return;
}
/* All cleaned up nicely */
