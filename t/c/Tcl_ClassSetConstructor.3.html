الوصف

الطريقة هي عملية يتم تنفيذها على كائن مرتبط بهذا الكائن. يجب أن ترتبط كل طريقة إما بكائن أو بفئة؛ الطرق المرتبطة بفئة ترتبط بجميع النسخ (المباشرة وغير المباشرة) لتلك الفئة.

بالنظر إلى طريقة، يمكن العثور على الكيان الذي أعلنها باستخدام Tcl_MethodDeclarerClass الذي يعيد الفئة التي ترتبط بها الطريقة (أو NULL إذا لم تكن الطريقة مرتبطة بأي فئة) و Tcl_MethodDeclarerObject الذي يعيد الكائن الذي ترتبط به الطريقة (أو NULL إذا لم تكن الطريقة مرتبطة بكائن). يمكن استرداد اسم الطريقة باستخدام Tcl_MethodName ومعرفة ما إذا كانت الطريقة مُصدرة باستخدام Tcl_MethodIsPublic. يمكن أيضًا فحص نوع الطريقة بدرجة محدودة؛ تعيد الدالة Tcl_MethodIsType ما إذا كانت الطريقة من نوع معين، وتعيين clientData الخاص بكل طريقة للمتغير المشار إليه بواسطة clientDataPtr إذا (كان غير NULL) إذا تطابق النوع.

إنشاء الطرق

يتم إنشاء الطرق بواسطة Tcl_NewMethod و Tcl_NewInstanceMethod، التي تنشئ طريقة مرتبطة بفئة أو بكائن على التوالي. في كلتا الحالتين، يعطي الوسيط nameObj اسم الطريقة المراد إنشاؤها، ويحدد الوسيط isPublic ما إذا كان يجب تصدير الطريقة مبدئيًا، ويصف الوسيط methodTypePtr تنفيذ الطريقة (انظر قسم أنواع الطرق أدناه) ويعطي الوسيط clientData بعض البيانات الخاصة بالتنفيذ التي يتم تمريرها إلى تنفيذ الطريقة عند استدعائها.

عندما يكون الوسيط nameObj لـ Tcl_NewMethod هو NULL، يتم إنشاء طريقة بدون اسم، والتي تستخدم للمنشئات والمدمرات. يجب تثبيت المنشئات في فئتها باستخدام الدالة Tcl_ClassSetConstructor، ويجب تثبيت المدمرات (التي لا يجب أن تتطلب أي وسائط) في فئتها باستخدام الدالة Tcl_ClassSetDestructor. يجب عدم استخدام الطرق بدون اسم لأي غرض آخر، ويجب عدم استخدام الطرق المسماة كمنشئات أو مدمرات. لاحظ أيضًا أن methodTypePtr NULL يستخدم لتوفير إشارة داخلية، ولا يجب استخدامه في كود العميل.

سياقات استدعاء الطرق

عند استدعاء طريقة، يتم تمرير مرجع لسياق استدعاء الطريقة كوسيط إلى دالة التنفيذ. يمكن فحص هذا السياق لتوفير معلومات حول المستدعي، ولكن لا ينبغي الاحتفاظ به بعد انتهاء استدعاء الطريقة.

يمكن استرداد الطريقة التي يتم استدعاؤها من السياق باستخدام Tcl_ObjectContextMethod، ويمكن استرداد الكائن الذي تسبب في استدعاء الطريقة باستخدام Tcl_ObjectContextObject. يتم قراءة عدد الوسائط التي يجب تخطيها (مثل اسم الكائن واسم الطريقة في استدعاء طريقة عادي) باستخدام Tcl_ObjectContextSkippedArgs، ويمكن للسياق أيضًا الإبلاغ عما إذا كان يعمل كمرشح لطريقة أخرى من خلال Tcl_ObjectContextIsFiltering.

أثناء تنفيذ الطريقة، قد يختار تنفيذ الطريقة استدعاء مراحل سلسلة استدعاء الطريقة التي تأتي بعد تنفيذ الطريقة الحالي. يتم ذلك (جوهر الأمر next) باستخدام Tcl_ObjectContextInvokeNext. لاحظ أن هذه الدالة لا تتلاعب بمكدس إطارات الاستدعاء، على عكس الأمر next؛ إذا دفع تنفيذ الطريقة إطارًا أو أكثر على المكدس كجزء من تنفيذه، فهو مسؤول أيضًا عن إزالة تلك الإطارات مؤقتًا من المكدس أثناء تنفيذ الدالة Tcl_ObjectContextInvokeNext. لاحظ أيضًا أنه لا يتم حذف سياق استدعاء الطريقة أبدًا أثناء تنفيذ هذه الدالة.

أنواع الطرق

يتم وصف أنواع الطرق بواسطة مؤشر إلى هيكل Tcl_MethodType، والذي يتم تعريفه على النحو التالي:

typedef struct {
    int version;
    const char *name;
    Tcl_MethodCallProc *callProc;
    Tcl_MethodDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_MethodType;

يسمح حقل version بالتوسع المستقبلي للهيكل، ويجب دائمًا تعريفه على أنه يساوي TCL_OO_METHOD_VERSION_CURRENT. يوفر حقل name اسمًا يمكن قراءته من قبل الإنسان للنوع، وهو القيمة التي يتم كشفها عبر أوامر Tcl info class methodtype و info object methodtype.

يعطي حقل callProc دالة يتم استدعاؤها عند استدعاء الطريقة؛ يجب ألا يكون NULL أبدًا.

يعطي حقل deleteProc دالة تستخدم لحذف طريقة معينة، ويتم استدعاؤها عند استبدال الطريقة أو إزالتها؛ إذا كان الحقل NULL، فمن المفترض أن clientData الخاص بالطريقة لا يحتاج إلى أي إجراء خاص للحذف.

حقل cloneProc هو إما دالة تستخدم لنسخ clientData الخاص بالطريقة (كجزء من Tcl_CopyObjectInstance) أو NULL للإشارة إلى أنه يمكن نسخ clientData مباشرة.

        Tcl_Obj *argsPtr);

DESCRIPTION

TclOO provides a powerful object-oriented programming model in Tcl. The TclOO API allows you to define classes, objects, methods, and constructors programmatically. This section describes the core functions for managing methods and constructors.

TCL_METHODCALLPROC FUNCTION SIGNATURE

Functions matching this signature are called when the method is invoked.

typedef int Tcl_MethodCallProc(
        ClientData clientData,
        Tcl_Interp *interp,
        Tcl_ObjectContext objectContext,
        int objc,
        Tcl_Obj *const *objv);

The clientData argument to a Tcl_MethodCallProc is the value that was given when the method was created, the interp is a place in which to execute scripts and access variables as well as being where to put the result of the method, and the objc and objv fields give the parameter objects to the method. The calling context of the method can be discovered through the objectContext argument, and the return value from a Tcl_MethodCallProc is any Tcl return code (e.g. TCL_OK, TCL_ERROR).

TCL_METHODDELETEPROC FUNCTION SIGNATURE

Functions matching this signature are used when a method is deleted, whether through a new method being created or because the object or class is deleted.

typedef void Tcl_MethodDeleteProc(
        ClientData clientData);

The clientData argument to a Tcl_MethodDeleteProc will be the same as the value passed to the clientData argument to Tcl_NewMethod or Tcl_NewInstanceMethod when the method was created.

TCL_CLONEPROC FUNCTION SIGNATURE

Functions matching this signature are used to copy a method when the object or class is copied using Tcl_CopyObjectInstance (or oo::copy).

typedef int Tcl_CloneProc(
        Tcl_Interp *interp,
        ClientData oldClientData,
        ClientData *newClientDataPtr);

The interp argument gives a place to write an error message when the attempt to clone the object is to fail, in which case the clone procedure must also return TCL_ERROR; it should return TCL_OK otherwise. The oldClientData field to a Tcl_CloneProc gives the value from the method being copied from, and the newClientDataPtr field will point to a variable in which to write the value for the method being copied to.
