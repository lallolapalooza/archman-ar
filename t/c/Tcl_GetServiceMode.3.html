INTRODUCTION

The Tcl event loop is responsible for dispatching events to the application. The Tcl library provides a default event loop implementation that handles file, timer, and idle events. The service mode and notifier management functions allow you to control and extend this event loop.

NOTIFIER BASICS

A notifier is a set of procedures that are called by the Tcl event loop to handle specific types of events. The default notifier handles file, timer, and idle events. You can create your own notifiers to handle additional event types or to customize the behavior of the default event loop.

A notifier is represented by a Tcl_Notifier structure, which contains a procedure pointer (notifierProc) and client data (clientData). The notifierProc is called by the Tcl event loop when an event occurs. The notifierProc should handle the event and return a value indicating whether the event was handled.

CREATING A NEW EVENT SOURCE

To create a new event source, you need to define a notifierProc that handles the new event type. The notifierProc should register the new event source with the Tcl event loop. The Tcl event loop will then call the notifierProc when the event source becomes ready.

CREATING A NEW NOTIFIER

To create a new notifier, you need to define a notifierProc that handles the events you want to manage. Then, call Tcl_CreateNotifier to create a new notifier and associate it with the interpreter. The new notifier will be added to the list of notifiers that the Tcl event loop checks.

REPLACING THE NOTIFIER

You can replace the default notifier with your own custom notifier by calling Tcl_SetNotifier. This will cause the Tcl event loop to use your notifier instead of the default one. To restore the default notifier, you can call Tcl_SetNotifier with the default notifier handle.

EXTERNAL EVENT LOOPS

Tcl can be integrated into an existing event loop. In this case, Tcl will not start its own event loop. Instead, it will rely on the external event loop to call Tcl_DoOneEvent when events are available. This allows Tcl to be used in applications that already have an event loop, such as GUI toolkits.
