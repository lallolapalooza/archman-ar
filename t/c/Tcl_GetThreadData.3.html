مقدمة

منذ الإصدار 8.1، أصبح نواة Tcl آمنة للخيوط، مما يسمح بتضمين Tcl في تطبيقات متعددة الخيوط دون الحاجة إلى تخصيص نواة Tcl. منذ الإصدار 8.6، تم تفعيل دعم الخيوط في Tcl افتراضيًا. لتعطيل دعم الخيوط في Tcl، يجب عليك تضمين الخيار --disable-threads في configure عند تكوين وتجميع نواة Tcl الخاصة بك.

قيد مهم لتطبيق الخيوط في Tcl هو أن الخيط الذي أنشأ المفسر فقط يمكنه استخدام هذا المفسر. بعبارة أخرى، لا يمكن للخيوط المتعددة الوصول إلى نفس المفسر. (ومع ذلك، يمكن لخيط واحد إنشاء واستخدام مفسرات متعددة بأمان.)

الوصف

يوفر Tcl Tcl_CreateThread لإنشاء الخيوط. يمكن للمستدعي تحديد حجم المكدس المعطى للخيط الجديد وتعديل السلوك باستخدام قيمة flags. القيمة TCL_THREAD_STACK_DEFAULT لـ stackSize تشير إلى استخدام الحجم الافتراضي وفقًا لنظام التشغيل. بالنسبة للأعلام، يتم حاليًا تعريف القيم TCL_THREAD_NOFLAGS و TCL_THREAD_JOINABLE فقط. الأول يستدعي السلوك الافتراضي بدون تعديلات خاصة. استخدام الثاني يضع علامة على الخيط الجديد على أنه قابل للانضمام. هذا يعني أن خيطًا آخر يمكنه انتظار تنفيذ الخيط المحدد والانضمام إليه.

القيود: في بعض أنظمة UNIX، لا تحتوي مكتبة pthread على وظيفة لتحديد حجم مكدس الخيط. يتم تجاهل القيمة المحددة لحجم المكدس على هذه الأنظمة. لا يدعم Windows حاليًا الخيوط القابلة للانضمام. يتم تجاهل قيمة العلم هذه على هذه المنصة.

يوفر Tcl وظيفتي Tcl_ExitThread و Tcl_FinalizeThread لإنهاء الخيوط واستدعاء معالجات خروج اختيارية لكل خيط. انظر صفحة Tcl_Exit لمزيد من المعلومات حول هذه الإجراءات.

تسمح وظيفة Tcl_JoinThread للخيوط بالانتظار لإنهاء خيط آخر، والذي يجب أن يكون قد تم تمييزه كقابل للانضمام باستخدام علامة TCL_THREAD_JOINABLE أثناء إنشائه باستخدام Tcl_CreateThread.

محاولة انتظار إنهاء خيط غير قابل للانضمام أو خيط تم انتظاره بالفعل ستؤدي إلى خطأ. يمكن انتظار خيط قابل للانضمام تم إنهاؤه بالفعل، وسيحافظ النظام على المعلومات اللازمة حتى بعد استدعاء Tcl_JoinThread. هذا يعني أن عدم استدعاء Tcl_JoinThread لخيط قابل للانضمام سيؤدي إلى تسرب في الذاكرة.

تُرجع استدعاء Tcl_GetThreadData مؤشرًا إلى كتلة بيانات خاصة بالخيط. وسيطها هو مفتاح مشترك بين جميع الخيوط وحجم لكتلة التخزين. يتم تلقائيًا حجز التخزين وتهيئته إلى الصفر في المرة الأولى التي يطلبه فيها خيط. يتم تحرير التخزين تلقائيًا بواسطة Tcl_FinalizeThread.

المزامنة والتواصل

يوفر Tcl Tcl_ThreadQueueEvent و Tcl_ThreadAlert لمعالجة طابور الأحداث في التطبيقات متعددة الخيوط. انظر صفحة Notifier لمزيد من المعلومات حول هذه الإجراءات.

Mutex هو قفل يستخدم لمزامنة جميع الخيوط من خلال تأمين جزء من التعليمات البرمجية يسمى Tcl_MutexLock و Tcl_MutexUnlock. إذا تم قفل خيط على mutex، فإن أي خيط آخر يستدعي Tcl_MutexLock سيتم قفله حتى يتم تنفيذ Tcl_MutexUnlock. يمكن تدمير mutex بعد استخدامه عن طريق استدعاء Tcl_MutexFinalize. نتيجة قفل mutex مرتين من نفس الخيط غير محددة. في بعض الأنظمة، قد يؤدي ذلك إلى قفل deadlock. يتم تعريف وظائف Tcl_MutexLock و Tcl_MutexUnlock و Tcl_MutexFinalize كـ macros فارغة إذا لم يتم تجميعها مع الخيوط. للإعلان عن mutexes، يجب استخدام macro TCL_DECLARE_MUTEX. تضمن هذه macro التعامل الصحيح مع mutexes حتى عندما لا يتم تجميع النواة مع الخيوط.

يُستخدم متغير الشرط كآلية إشعار: يمكن للخيط قفل mutex والانتظار عند متغير شرط باستخدام Tcl_ConditionWait. هذا يحرر تلقائيًا قفل mutex ويقفل الخيط المنتظر حتى يستدعي خيط آخر Tcl_ConditionNotify. يجب أن يكون المستدعي لـ Tcl_ConditionNotify قد قام بقفل mutex المرتبط بالفعل قبل استدعاء Tcl_MutexLock، ولكن هذا غير مطلوب. إشعار متغير الشرط يفتح جميع الخيوط المنتظرة عند متغير الشرط، لكنها لن تتقدم حتى يتم تحرير mutex بواسطة Tcl_MutexUnlock. يقوم تنفيذ Tcl_ConditionWait تلقائيًا بقفل mutex قبل إعادة التحكم.

يجب أن يكون المستدعي لـ Tcl_ConditionWait مستعدًا للإشعارات الوهمية عن طريق استدعاء Tcl_ConditionWait داخل حلقة while تختبر ثباتًا.

يمكن تدمير متغير الشرط بعد استخدامه عن طريق استدعاء Tcl_ConditionFinalize.

يتم تعريف وظائف Tcl_ConditionNotify و Tcl_ConditionWait و Tcl_ConditionFinalize كـ macros فارغة إذا لم يتم تجميعها مع الخيوط.

التهيئة

يتم تهيئة جميع كائنات المزامنة هذه تلقائيًا. يتم تنفيذها كمؤشرات غير شفافة يجب أن تكون NULL عند استخدامها لأول مرة. يتم تنظيف mutexes ومتغيرات الشرط بواسطة معالجات إغلاق العمليات (إذا عاشت طويلاً) أو صراحةً عن طريق استدعاء Tcl_MutexFinalize أو Tcl_ConditionFinalize. يتم تحرير تخزين بيانات الخيط المحلي أثناء Tcl_FinalizeThread.

الوصول إلى مستوى النص البرمجي للخيوط

لا يوفر Tcl أوامر داخلية للنصوص البرمجية لإنشاء الخيوط أو إدارتها أو الانضمام إليها، أو الوصول إلى مستوى النص البرمجي إلى mutexes أو متغيرات الشرط. إنه يوفر هذه الخدمات فقط من خلال واجهات C، ويتركها للحزم التي تحتاج إليها.

INTRODUCTION

Tcl provides a set of primitives for creating and managing threads, and for synchronizing access to shared resources. This package is intended to provide a portable interface to the underlying operating system's threading facilities.

DESCRIPTION

This section describes the thread and synchronization primitives provided by the Tcl Threading extension.

The Thread package is loaded automatically when you call any of its functions. You do not need to explicitly load it.

The following functions are available:

Tcl_MutexCreate, Tcl_MutexDestroy, Tcl_MutexLock, Tcl_MutexTryLock, Tcl_MutexUnlock, Tcl_MutexIsLocked
These functions provide mutex (mutual exclusion) locks. A mutex is a primitive synchronization object that is owned by at most one thread at a time. If a thread attempts to lock a mutex that is already locked, the thread will block until the mutex is unlocked. Tcl_MutexTryLock is a non-blocking version that returns immediately if the mutex is already locked.
Tcl_CondCreate, Tcl_CondDestroy, Tcl_CondWait, Tcl_CondSignal, Tcl_CondBroadcast
These functions provide condition variables. A condition variable is a primitive synchronization object that allows threads to wait for certain conditions to become true. A thread typically locks a mutex, checks a condition, and if the condition is not true, it calls Tcl_CondWait. This atomically unlocks the mutex and puts the thread to sleep. When another thread makes the condition true, it calls Tcl_CondSignal (to wake up one waiting thread) or Tcl_CondBroadcast (to wake up all waiting threads). The waiting thread then re-acquires the mutex and re-checks the condition.
Tcl_GetCurrentThread, Tcl_IsMainThread
Return the identifier of the current thread, and a boolean indicating if the current thread is the main thread.
Tcl_CreateThread, Tcl_ExitThread, Tcl_JoinThread
These functions are used to create, terminate, and join threads. Tcl_CreateThread creates a new thread that starts execution at the given function. The stackSize argument specifies the desired stack size for the new thread, or TCL_THREAD_STACK_DEFAULT for the default size. The joinable argument determines if the thread can be joined; use TCL_THREAD_JOINABLE or TCL_THREAD_DETACHED. Tcl_ExitThread terminates the calling thread. Tcl_JoinThread waits for a specific thread to terminate.
Tcl_SetThreadExitHook, Tcl_GetThreadExitHook
These functions allow you to register a hook that will be called when a thread exits. The hook will be called with the thread's exit status as an argument. Only one exit hook can be registered at a time.
Tcl_CreateThreadExitHandler, Tcl_DeleteThreadExitHandler
These functions allow you to register and unregister handlers that will be called when a thread exits. Multiple handlers can be registered, and they will be called in the reverse order of their registration.
Tcl_SetThreadLocal, Tcl_GetThreadLocal, Tcl_DeleteThreadLocal
These functions provide thread-local storage. Each thread has its own copy of the data associated with a given name. This is useful for storing data that should not be shared between threads.
Tcl_Sleep
Suspends the calling thread for the specified number of milliseconds.
Tcl_QueueEvent, Tcl_ThreadQueueEvent
These functions queue an event to be processed by the Tcl event loop. Tcl_ThreadQueueEvent allows you to queue an event to a specific thread.
Tcl_ThreadAlert
Wakes up a thread that is currently blocked in an event loop, for example, waiting for events.
Tcl_SetThreadData, Tcl_GetThreadData
These functions allow you to associate arbitrary data with a thread, identified by a key. This is similar to thread-local storage but more general, as it allows data to be associated with any thread, not just the current one. A freeProc can be specified to free the data when the thread exits.
Tcl_FinalizeThread
This function is called automatically when a thread exits. It should not be called directly by the user.

SCRIPT-LEVEL ACCESS TO THREADS

Tcl scripts can access these primitives through the Thread package. The Thread package provides a higher-level interface to the underlying threading primitives, making it easier to use them from Tcl scripts.

For example, to create a new thread from a Tcl script:

set threadId [thread::create {
    # Code to run in the new thread
    puts "Hello from a new thread!"
    # You can access thread-specific data here
    set myData [thread::getdata myKey]
    puts "My data is: $myData"
}]

The Thread package also provides commands for synchronization primitives like mutexes and condition variables, as well as thread-local storage.

For more information, see the documentation for the Thread package.

One such package is the Thread package.

EXAMPLE

To create a thread with portable code, its implementation function should be declared as follows:

static Tcl_ThreadCreateProc MyThreadImplFunc;

It should then be defined like this example, which just counts up to a given value and then finishes.

static Tcl_ThreadCreateType
MyThreadImplFunc(
    ClientData clientData)
{
    int i, limit = (int) clientData;
    for (i=0 ; i<limit ; i++) {
        /* doing nothing at all here */
    }
    TCL_THREAD_CREATE_RETURN;
}

To create the above thread, make it execute, and wait for it to finish, we would do this:

int limit = 1000000000;
ClientData limitData = (void*)((intptr_t) limit);
Tcl_ThreadId id;    /* holds identity of thread created */
int result;
if (Tcl_CreateThread(&id, MyThreadImplFunc, limitData,
        TCL_THREAD_STACK_DEFAULT,
        TCL_THREAD_JOINABLE) != TCL_OK) {
    /* Thread did not create correctly */
    return;
}
/* Do something else for a while here */
if (Tcl_JoinThread(id, &result) != TCL_OK) {
    /* Thread did not finish properly */
    return;
}
/* All cleaned up nicely */
