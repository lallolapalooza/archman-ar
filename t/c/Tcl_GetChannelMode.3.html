Tcl_GetChannelMode(3)

الحزمة: tcl

التراخيص: TCL

TCL_GETCHANNELHANDLE

Tcl_GetChannelHandle returns the device handle associated with the channel channelPtr for the specified direction direction. The handle is of the type that the channel driver returns. If the channel does not have a device handle for the specified direction, then TCL_ERROR is returned instead. Different channel drivers will return different types of handle. Refer to the manual entries for each driver to determine what type of handle is returned.

Tcl_GetChannelThread returns the id of the thread currently managing the specified channel. This allows channel drivers to send their file events to the correct event queue even for a multi-threaded core.

Tcl_GetChannelMode returns an OR-ed combination of TCL_READABLE and TCL_WRITABLE, indicating whether the channel is open for input and output.

Tcl_GetChannelBufferSize returns the size, in bytes, of buffers allocated to store input or output in channel. If the value was not set by a previous call to Tcl_SetChannelBufferSize, described below, then the default value of 4096 is returned.

Tcl_SetChannelBufferSize sets the size, in bytes, of buffers that will be allocated in subsequent operations on the channel to store input or output. The size argument should be between one and one million, allowing buffers of one byte to one million bytes. If size is outside this range, Tcl_SetChannelBufferSize sets the buffer size to 4096.

Tcl_NotifyChannel is called by a channel driver to indicate to the generic layer that the events specified by mask have occurred on the channel. Channel drivers are responsible for invoking this function whenever the channel handlers need to be called for the channel (or other pending tasks like a write flush should be performed). See WATCHPROC below for more details.

Tcl_BadChannelOption is called from driver specific setOptionProc or getOptionProc to generate a complete error message.

Tcl_ChannelBuffered returns the number of bytes of input currently buffered in the internal buffer (push back area) of the channel itself. It does not report about the data in the overall buffers for the stack of channels the supplied channel is part of.

Tcl_IsChannelShared checks the refcount of the specified channel and returns whether the channel was shared among multiple interpreters (result == 1) or not (result == 0).

Tcl_IsChannelRegistered checks whether the specified channel is registered in the given interpreter (result == 1) or not (result == 0).

Tcl_IsChannelExisting checks whether a channel with the specified name is registered in the (thread)-global list of all channels (result == 1) or not (result == 0).

Tcl_CutChannel removes the specified channel from the (thread)global list of all channels (of the current thread). Application to a channel still registered in some interpreter is not allowed. Also notifies the driver if the Tcl_ChannelType version is TCL_CHANNEL_VERSION_4 (or higher), and Tcl_DriverThreadActionProc is defined for it.

Tcl_SpliceChannel adds the specified channel to the (thread)global list of all channels (of the current thread). Application to a channel registered in some interpreter is not allowed. Also notifies the driver if the Tcl_ChannelType version is TCL_CHANNEL_VERSION_4 (or higher), and Tcl_DriverThreadActionProc is defined for it.

Tcl_ClearChannelHandlers removes all channel handlers and event scripts associated with the specified channel, thus shutting down all event processing for this channel.

TCL_CHANNELTYPE

A channel driver provides a Tcl_ChannelType structure that contains pointers to functions that implement the various operations on a channel; these operations are invoked as needed by the generic layer. The structure was versioned starting in Tcl 8.3.2/8.4 to correct a problem with stacked channel drivers. See the OLD CHANNEL TYPES section below for details about the old structure.

The Tcl_ChannelType structure contains the following fields:

typedef struct Tcl_ChannelType {
        const char *typeName;
        Tcl_ChannelTypeVersion version;
        Tcl_DriverCloseProc *closeProc;
        Tcl_DriverInputProc *inputProc;
        Tcl_DriverOutputProc *outputProc;
        Tcl_DriverSeekProc *seekProc;
        Tcl_DriverSetOptionProc *setOptionProc;
        Tcl_DriverGetOptionProc *getOptionProc;
        Tcl_DriverWatchProc *watchProc;
        Tcl_DriverGetHandleProc *getHandleProc;
        Tcl_DriverClose2Proc *close2Proc;
        Tcl_DriverBlockModeProc *blockModeProc;
        Tcl_DriverFlushProc *flushProc;
        Tcl_DriverHandlerProc *handlerProc;
        Tcl_DriverWideSeekProc *wideSeekProc;
        Tcl_DriverThreadActionProc *threadActionProc;
        Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

It is not necessary to provide implementations for all channel operations. Those which are not necessary may be set to NULL in the struct: blockModeProc, seekProc, setOptionProc, getOptionProc, getHandleProc, and close2Proc, in addition to flushProc, handlerProc, threadActionProc, and truncateProc. Other functions that cannot be implemented in a meaningful way should return EINVAL when called, to indicate that the operations they represent are not available. Also note that wideSeekProc can be NULL if seekProc is.

The user should only use the above structure for Tcl_ChannelType instantiation. When referencing fields in a Tcl_ChannelType structure, the following functions should be used to obtain the values: Tcl_ChannelName, Tcl_ChannelVersion, Tcl_ChannelBlockModeProc, Tcl_ChannelCloseProc, Tcl_ChannelClose2Proc, Tcl_ChannelInputProc, Tcl_ChannelOutputProc, Tcl_ChannelSeekProc, Tcl_ChannelWideSeekProc, Tcl_ChannelThreadActionProc, Tcl_ChannelTruncateProc, Tcl_ChannelSetOptionProc, Tcl_ChannelGetOptionProc, Tcl_ChannelWatchProc, Tcl_ChannelGetHandleProc, Tcl_ChannelFlushProc, or Tcl_ChannelHandlerProc.

The change to the structures was made in such a way that standard channel types are binary compatible. However, channel types that use stacked channels (i.e. TLS, Trf) have new versions to correspond to the above change since the previous code for stacked channels had problems.

TYPENAME

The typeName field contains a null-terminated string that identifies the type of the device implemented by this driver, e.g. file or socket.

This value can be retrieved with Tcl_ChannelName, which returns a pointer to the string.

VERSION

The version field should be set to the version of the structure that you require. TCL_CHANNEL_VERSION_2 is the minimum recommended. TCL_CHANNEL_VERSION_3 must be set to specify the wideSeekProc member. TCL_CHANNEL_VERSION_4 must be set to specify the threadActionProc member (includes wideSeekProc). TCL_CHANNEL_VERSION_5 must be set to specify the truncateProc members (includes wideSeekProc and threadActionProc). If it is not set to any of these, then this Tcl_ChannelType is assumed to have the original structure. See OLD CHANNEL TYPES for more details. While Tcl will recognize and function with either structures, stacked channels must be of at least TCL_CHANNEL_VERSION_2 to function correctly.

This value can be retrieved with Tcl_ChannelVersion, which returns one of TCL_CHANNEL_VERSION_5, TCL_CHANNEL_VERSION_4, TCL_CHANNEL_VERSION_3, TCL_CHANNEL_VERSION_2 or TCL_CHANNEL_VERSION_1.

BLOCKMODEPROC

The blockModeProc field contains the address of a function called by the generic layer to set blocking and nonblocking mode on the device. BlockModeProc should match the following prototype:

typedef int Tcl_DriverBlockModeProc(
        ClientData instanceData,
        int mode);

The instanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The mode argument is either TCL_MODE_BLOCKING or TCL_MODE_NONBLOCKING to set the device into blocking or nonblocking mode. The function should return zero if the operation was successful, or a nonzero POSIX error code if the operation failed.

If the operation is successful, the function can modify the supplied instanceData to record that the channel entered blocking or nonblocking mode and to implement the blocking or nonblocking behavior. For some device types, the blocking and nonblocking behavior can be implemented by the underlying operating system; for other device types, the behavior must be emulated in the channel driver.

This value can be retrieved with Tcl_ChannelBlockModeProc, which returns a pointer to the function.

A channel driver not supplying a blockModeProc has to be very, very careful. It has to tell the generic layer exactly which blocking mode is acceptable to it, and should this also document for the user so that the blocking mode of the channel is not changed to an unacceptable value. Any confusion here may lead the interpreter into a (spurious and difficult to find) deadlock.

CLOSEPROC AND CLOSE2PROC

The closeProc field contains the address of a function called by the generic layer to clean up driver-related information when the channel is closed. CloseProc must match the following prototype:

typedef int Tcl_DriverCloseProc(
        ClientData instanceData,
        Tcl_Interp *interp);

The instanceData argument is the same as the value provided to Tcl_CreateChannel when the channel was created. The function should release any storage maintained by the channel driver for this channel, and close the input and output devices encapsulated by this channel. يمكن الحصول على قيم closeProc و close2Proc باستخدام Tcl_ChannelCloseProc أو Tcl_ChannelClose2Proc، والتي تعيد مؤشرًا إلى الدالة المقابلة.

INPUTPROC

يحتوي الحقل inputProc على عنوان دالة تستدعيها الطبقة العامة لقراءة البيانات من ملف أو جهاز وتخزينها في مخزن مؤقت داخلي. يجب أن يتطابق InputProc مع النموذج الأولي التالي:

typedef int Tcl_DriverInputProc(
        ClientData instanceData,
        char *buf,
        int bufSize,
        int *errorCodePtr);

instanceData هو نفس القيمة التي تم تمريرها إلى Tcl_CreateChannel عند إنشاء القناة. يشير الوسيط buf إلى مصفوفة بايت سيتم تخزين بيانات الإدخال من الجهاز فيها، ويشير الوسيط bufSize إلى عدد البايتات المتاحة في buf.

يشير الوسيط errorCodePtr إلى متغير صحيح توفره الطبقة العامة. إذا حدث خطأ، فيجب على الدالة تعيين هذا المتغير إلى رمز خطأ POSIX يحدد الخطأ.

يجب على الدالة قراءة البيانات من الجهاز الذي تغلفه القناة وتخزينها في buf. في حالة النجاح، يجب على الدالة إرجاع رقم غير سالب يشير إلى عدد البايتات التي تم قراءتها من الجهاز وتخزينها في buf. في حالة حدوث خطأ، يجب على الدالة إرجاع -1. إذا حدث خطأ بعد قراءة بعض البيانات من الجهاز، فسيتم فقدان البيانات.

إذا كان بإمكان inputProc تحديد أن جهاز الإدخال يحتوي على بعض البيانات المتاحة ولكن أقل مما هو مطلوب بواسطة الوسيط bufSize، فستحاول الدالة فقط قراءة كمية البيانات المتاحة والعودة دون حظر. إذا لم تكن هناك بيانات متاحة في جهاز الإدخال وكانت القناة في وضع غير حاظر، فيجب على الدالة إرجاع الخطأ EAGAIN. إذا لم تكن هناك بيانات متاحة في جهاز الإدخال وكانت القناة في وضع حاظر، فيجب على الدالة حظر أقصر وقت ممكن حتى يمكن قراءة بايت واحد على الأقل من البيانات من الجهاز؛ ثم، ستعيد أقصى قدر من البيانات التي يمكنها قراءتها دون حظر.

يمكن الحصول على هذه القيمة باستخدام Tcl_ChannelInputProc، والتي تعيد مؤشرًا إلى الدالة.

OUTPUTPROC

يحتوي الحقل outputProc على عنوان دالة تستدعيها الطبقة العامة لنقل البيانات من المخزن المؤقت الداخلي إلى جهاز الإخراج. يجب أن يتطابق OutputProc مع النموذج الأولي التالي:

typedef int Tcl_DriverOutputProc(
        ClientData instanceData,
        const char *buf,
        int toWrite,
        int *errorCodePtr);

instanceData هو نفس القيمة التي تم تمريرها إلى Tcl_CreateChannel عند إنشاء القناة. الوسيط buf يحتوي على مصفوفة بايت لكتابتها في الجهاز، ويشير الوسيط toWrite إلى عدد البايتات التي سيتم كتابتها من الوسيط buf.

يشير الوسيط errorCodePtr إلى متغير صحيح توفره الطبقة العامة. إذا حدث خطأ، فيجب على الدالة تعيين هذا المتغير إلى رمز خطأ POSIX يحدد الخطأ.

يجب على الدالة كتابة البيانات في buf في جهاز الإخراج الذي تغلفه القناة. في حالة النجاح، يجب على الدالة إرجاع رقم غير سالب يشير إلى عدد البايتات التي تم كتابتها في جهاز الإخراج. عادة ما تكون قيمة الإرجاع هي نفسها toWrite، ولكنها قد تكون أقل في مواقف معينة، مثل عندما يتم مقاطعة عملية الإخراج بواسطة إشارة. إذا حدث خطأ، يجب على الدالة إرجاع -1. في حالة حدوث خطأ، قد تكون بعض البيانات قد تمت كتابتها في الجهاز.

إذا كانت القناة في وضع غير حاظر ولم يتمكن جهاز الإخراج من استيعاب أي بيانات، فيجب على الدالة إرجاع -1 مع الخطأ EAGAIN دون كتابة أي بيانات.

يمكن الحصول على هذه القيمة باستخدام Tcl_ChannelOutputProc، والتي تعيد مؤشرًا إلى الدالة.

SEEKPROC AND WIDESEEKPROC

يحتوي الحقل seekProc على عنوان دالة تستدعيها الطبقة العامة لنقل نقطة الوصول التي سيتم تطبيق عمليات الإدخال أو الإخراج اللاحقة عليها. يجب أن يتطابق SeekProc مع النموذج الأولي التالي:

typedef int Tcl_DriverSeekProc(
        ClientData instanceData,
        long offset,
        int seekMode,
        int *errorCodePtr);

instanceData هو نفس القيمة التي تم إعطاؤها لـ Tcl_CreateChannel عند إنشاء هذه القناة. Offset و seekMode لهما نفس المعنى كما في الإجراء Tcl_Seek (الموصوف في دليل Tcl_OpenFileChannel).

يشير errorCodePtr إلى متغير صحيح توفره الطبقة العامة لإرجاع قيمة errno للدالة. يجب على الدالة تعيين هذا المتغير إلى رمز خطأ POSIX إذا حدث خطأ. يجب على الدالة تخزين الرمز EINVAL إذا كان نوع القناة لا ينفذ البحث.

قيمة الإرجاع هي نقطة الوصول الجديدة أو -1 في حالة حدوث خطأ. إذا حدث خطأ، لا يجب على الدالة نقل نقطة الوصول.

إذا كان هناك حقل غير فارغ لـ seekProc، فقد يحتوي الحقل wideSeekProc على عنوان دالة بديلة تتعامل مع الإزاحات الواسعة (أي، أكبر من 32 بت)، مما يسمح بالبحث في ملفات أكبر من 2 جيجابايت. يتم استدعاء wideSeekProc مع تفضيل seekProc، ولكن يجب تعريف كليهما إذا تم تعريف wideSeekProc. يجب أن يتطابق WideSeekProc مع النموذج الأولي التالي:

typedef Tcl_WideInt Tcl_DriverWideSeekProc(
        ClientData instanceData,
        Tcl_WideInt offset,
        int seekMode,
        int *errorCodePtr);

الوسائط وقيم الإرجاع هي نفسها كما هو الحال مع seekProc، إلا إذا كان نوع الإزاحة ونوع الإرجاع مختلفين.

يمكن الحصول على الحقل seekProc باستخدام Tcl_ChannelSeekProc، والذي يعيد مؤشرًا إلى الدالة، ويمكن الحصول على الحقل wideSeekProc باستخدام Tcl_ChannelWideSeekProc.

SETOPTIONPROC

يحتوي الحقل setOptionProc على عنوان دالة تستدعيها الطبقة العامة لتعيين خيار محدد لنوع القناة في قناة. يجب أن يتطابق setOptionProc مع النموذج الأولي التالي:

typedef int Tcl_DriverSetOptionProc(
        ClientData instanceData,
        Tcl_Interp *interp,
        const char *optionName,
        const char *newValue);

optionName هو اسم خيار ليتم تعيينه، و newValue هو القيمة الجديدة لهذا الخيار، كسلسلة. instanceData هو نفس القيمة التي تم إعطاؤها لـ Tcl_CreateChannel عند إنشاء هذه القناة. يجب على الدالة تنفيذ أي إجراءات خاصة بنوع القناة مطلوبة لتنفيذ القيمة الجديدة للخيار.

يتم التعامل مع بعض الخيارات بواسطة الكود العام ولن يتم استدعاء هذه الدالة أبدًا لتعيينها، مثل -blockmode. خيارات أخرى خاصة بنوع القناة وسيتم استدعاء الدالة setOptionProc لمحرك القناة لتنفيذها. يمكن أن يكون الحقل setOptionProc NULL، مما يشير إلى أن هذا النوع من القنوات لا يدعم خيارات محددة.

إذا تم تعديل قيمة الخيار بنجاح للقيمة الجديدة، تعيد الدالة TCL_OK. يجب عليها استدعاء Tcl_BadChannelOption، والتي تعيد TCL_ERROR إذا لم يتم التعرف على optionName. إذا كان newValue يحدد قيمة غير مدعومة أو إذا حدث خطأ في استدعاء نظام، فيجب على الدالة ترك رسالة خطأ في نتيجة interp إذا لم يكن interp NULL. يجب على الدالة أيضًا استدعاء Tcl_SetErrno لتخزين رمز خطأ POSIX مناسب.

يمكن الحصول على هذه القيمة باستخدام Tcl_ChannelSetOptionProc، والتي تعيد مؤشرًا إلى الدالة.

GETOPTIONPROC

يحتوي الحقل getOptionProc على عنوان دالة تستدعيها الطبقة العامة للحصول على قيمة خيار محدد لنوع القناة في قناة. يجب أن يتطابق getOptionProc مع النموذج الأولي التالي:

typedef int Tcl_DriverGetOptionProc(
        ClientData instanceData,
        Tcl_Interp *interp,
        const char *optionName,
        Tcl_DString *optionValue);

optionName هو اسم خيار مدعوم من قبل هذا النوع من القنوات. إذا لم يكن اسم الخيار NULL، تقوم الدالة بتخزين قيمته الحالية، كسلسلة، في سلسلة Tcl الديناميكية optionValue. إذا كان optionName NULL، تقوم الدالة بتخزين قائمة بديلة بجميع الخيارات المدعومة وقيمها الحالية في optionValue. في حالة النجاح، تعيد الدالة TCL_OK. يجب عليها استدعاء Tcl_BadChannelOption، والتي تعيد TCL_ERROR إذا لم يتم التعرف على optionName. إذا كان newValue يحدد قيمة غير مدعومة أو إذا حدث خطأ في استدعاء نظام، فيجب على الدالة ترك رسالة خطأ في نتيجة interp إذا لم يكن interp NULL. يجب على الدالة أيضًا استدعاء Tcl_SetErrno لتخزين رمز خطأ POSIX مناسب.

يمكن الحصول على هذه القيمة باستخدام Tcl_ChannelGetOptionProc، والتي تعيد مؤشرًا إلى الدالة.

interp غير معروف. إذا حدث خطأ في استدعاء النظام، يجب أن تترك الدالة رسالة خطأ في نتيجة interp إذا كان interp ليس NULL. يجب على الدالة أيضًا استدعاء Tcl_SetErrno لتخزين رمز خطأ POSIX مناسب.

بعض الخيارات يتم التعامل معها بواسطة الكود العام ولا يتم استدعاء هذه الدالة أبدًا لاسترداد قيمتها، على سبيل المثال، -blockmode. الخيارات الأخرى خاصة بكل نوع قناة وسيتم استدعاء إجراء getOptionProc الخاص بمشغل القناة لتنفيذها. يمكن أن يكون الحقل getOptionProc NULL، مما يشير إلى أن نوع القناة هذا لا يدعم خيارات محددة النوع.

يمكن استرداد هذه القيمة باستخدام Tcl_ChannelGetOptionProc، التي تُرجع مؤشرًا إلى الدالة.

WATCHPROC

يحتوي الحقل watchProc على عنوان دالة يتم استدعاؤها بواسطة الطبقة العامة لتهيئة آلية إشعار الأحداث لملاحظة الأحداث ذات الأهمية على هذه القناة. يجب أن يتطابق WatchProc مع النموذج التالي:

typedef void Tcl_DriverWatchProc(
        ClientData instanceData,
        int mask);

instanceData هو نفس القيمة التي تم تمريرها إلى Tcl_CreateChannel عند إنشاء هذه القناة. الوسيط mask هو مزيج ORed من TCL_READABLE و TCL_WRITABLE و TCL_EXCEPTION؛ وهو يشير إلى الأحداث التي يهتم المتصل بملاحظتها على هذه القناة.

يجب على الدالة تهيئة آليات محددة لنوع الجهاز لملاحظة عندما يكون حدث ذو أهمية موجودًا على القناة. عندما يحدث حدث واحد أو أكثر من الأحداث المعينة على القناة، يكون مشغل القناة مسؤولاً عن استدعاء Tcl_NotifyChannel لإبلاغ وحدة القناة العامة. يجب على المشغل توخي الحذر لعدم تجويع مشغلي القنوات الآخرين أو مصادر الاستدعاءات عن طريق استدعاء Tcl_NotifyChannel بشكل متكرر جدًا. يمكن ضمان العدالة باستخدام طابور أحداث Tcl للسماح بجدولة حدث القناة بالتسلسل مع الأحداث الأخرى. انظر وصف Tcl_QueueEvent للحصول على تفاصيل حول كيفية وضع حدث في الطابور.

يمكن استرداد هذه القيمة باستخدام Tcl_ChannelWatchProc، التي تُرجع مؤشرًا إلى الدالة.

GETHANDLEPROC

يحتوي الحقل getHandleProc على عنوان دالة يتم استدعاؤها بواسطة الطبقة العامة لاسترداد مقبض خاص بنوع الجهاز من القناة. يجب أن يتطابق GetHandleProc مع النموذج التالي:

typedef int Tcl_DriverGetHandleProc(
        ClientData instanceData,
        int direction,
        ClientData *handlePtr);

InstanceData هو نفس القيمة التي تم تمريرها إلى Tcl_CreateChannel عند إنشاء هذه القناة. الوسيط direction هو إما TCL_READABLE لاسترداد المقبض المستخدم للإدخال، أو TCL_WRITABLE لاسترداد المقبض المستخدم للإخراج.

إذا كان تنفيذ القناة يحتوي على مقابض خاصة بالجهاز، فيجب على الدالة استرداد المقبض المناسب المرتبط بالقناة، وفقًا للوسيط direction. يجب تخزين المقبض في الموقع المشار إليه بواسطة handlePtr، ويجب إرجاع TCL_OK. إذا لم تكن القناة مفتوحة للاتجاه المحدد، أو إذا كان تنفيذ القناة لا يستخدم مقابض الجهاز، فيجب على الدالة إرجاع TCL_ERROR.

يمكن استرداد هذه القيمة باستخدام Tcl_ChannelGetHandleProc، التي تُرجع مؤشرًا إلى الدالة.

FLUSHPROC

الحقل flushProc محجوز حاليًا للاستخدام المستقبلي. يجب تعيينه إلى NULL. يجب أن يتطابق FlushProc مع النموذج التالي:

typedef int Tcl_DriverFlushProc(
        ClientData instanceData);

يمكن استرداد هذه القيمة باستخدام Tcl_ChannelFlushProc، التي تُرجع مؤشرًا إلى الدالة.

HANDLERPROC

يحتوي الحقل handlerProc على عنوان دالة يتم استدعاؤها بواسطة الطبقة العامة لإبلاغ القناة بحدوث حدث. يجب تعريفه لمشغلي القنوات المكدسة الذين يرغبون في تلقي إشعارات بالأحداث التي تحدث على القناة الأساسية (المكدسة). يجب أن يتطابق HandlerProc مع النموذج التالي:

typedef int Tcl_DriverHandlerProc(
        ClientData instanceData,
        int interestMask);

InstanceData هو نفس القيمة التي تم تمريرها إلى Tcl_CreateChannel عند إنشاء هذه القناة. interestMask هو مزيج ORed من TCL_READABLE أو TCL_WRITABLE؛ وهو يشير إلى نوع الحدث الذي حدث على هذه القناة.

يمكن استرداد هذه القيمة باستخدام Tcl_ChannelHandlerProc، التي تُرجع مؤشرًا إلى الدالة.

THREADACTIONPROC

يحتوي الحقل threadActionProc على عنوان الدالة التي يتم استدعاؤها بواسطة الطبقة العامة عند إنشاء قناة، أو إغلاقها، أو نقلها إلى خيط مختلف، أي كلما قد تحتاج حالة المشغل الخاصة بالخيط إلى تهيئتها أو تحديثها. يمكن أن تكون NULL. يتم استخدام الإجراء TCL_CHANNEL_THREAD_REMOVE لإبلاغ المشغل بأنه يجب عليه تحديث أو إزالة أي بيانات خاصة بالخيط قد يحتفظ بها للقناة.

يتم استخدام الإجراء TCL_CHANNEL_THREAD_INSERT لإبلاغ المشغل بأنه يجب عليه تحديث أو تهيئة أي بيانات خاصة بالخيط قد يحتفظ بها باستخدام الخيط المتصل كخيط مرتبط. انظر Tcl_CutChannel و Tcl_SpliceChannel لمزيد من التفاصيل.

typedef void Tcl_DriverThreadActionProc(
        ClientData instanceData,
        int action);

InstanceData هو نفس القيمة التي تم تمريرها إلى Tcl_CreateChannel عند إنشاء هذه القناة.

يمكن استرداد هذه القيم باستخدام Tcl_ChannelThreadActionProc، التي تُرجع مؤشرًا إلى الدالة.

TRUNCATEPROC

يحتوي الحقل truncateProc على عنوان الدالة التي يتم استدعاؤها بواسطة الطبقة العامة عند اقتطاع قناة إلى طول معين. يمكن أن تكون NULL.

typedef int Tcl_DriverTruncateProc(
        ClientData instanceData,
        Tcl_WideInt length);

InstanceData هو نفس القيمة التي تم تمريرها إلى Tcl_CreateChannel عند إنشاء هذه القناة، و length هو الطول الجديد للملف الأساسي، والذي يجب ألا يكون سالبًا. يجب أن تكون النتيجة 0 عند النجاح أو رمز errno (مناسب للاستخدام مع Tcl_SetErrno) عند الفشل.

يمكن استرداد هذه القيم باستخدام Tcl_ChannelTruncateProc، التي تُرجع مؤشرًا إلى الدالة.

TCL_BADCHANNELOPTION

تنشئ هذه الإجراءات رسالة خطأ "خيار سيء" في مترجم (اختياري). يتم استخدامها بواسطة مشغلي القنوات عند طلب خيار تعيين/الحصول غير صالح. الغرض منها هو ربط قائمة الخيارات العامة بالخيارات المحددة وتجميع سلسلة رسالة خطأ الخيارات العامة.

تعود دائمًا بالقيمة TCL_ERROR

يتم إنشاء رسالة خطأ في قيمة نتيجة interp للإشارة إلى أنه تم استدعاء أمر بخيار سيء. الرسالة لها الشكل

    bad option "blah": should be one of
    <...generic options...>+<...specific options...>
لذلك تحصل على على سبيل المثال: 
    bad option "-blah": should be one of -blocking,
    -buffering, -buffersize, -eofchar, -translation,
    -peername, or -sockname
عند استدعائها مع optionList يساوي "peername sockname"

"blah" هو الوسيط optionName و "<specific options>" هي قائمة مفصولة بمسافات من الكلمات الخاصة بالخيارات. تتخذ الدالة عناية جيدة بإدراج علامات الطرح قبل كل خيار، وفواصل بعده، و "or" قبل الخيار الأخير.

OLD CHANNEL TYPES

يحتوي هيكل Tcl_ChannelType الأصلي (8.3.1 وما دون) على الحقول التالية:

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverClose2Proc *close2Proc;
} Tcl_ChannelType;

لا يزال من الممكن إنشاء قنوات بالهيكل أعلاه. سيحدد الكود الداخلي للقناة الإصدار. من الضروري استخدام هيكل Tcl_ChannelType الجديد إذا كنت تقوم بإنشاء مشغل قناة مكدسة، بسبب مشاكل في تنفيذ القناة المكدسة السابقة (في 8.2.0 إلى 8.3.1).

قبل 8.4.0 (أي خلال الإصدارات الأخيرة من 8.3 والجزء المبكر من دورة تطوير 8.4) احتوى هيكل Tcl_ChannelType على الحقول التالية:

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_ChannelTypeVersion version;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverClose2Proc *close2Proc;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverFlushProc *flushProc;
    Tcl_DriverHandlerProc *handlerProc;
    Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

عند تسجيل الهيكل أعلاه كنوع قناة، يجب أن يكون الحقل version دائمًا TCL_CHANNEL_VERSION_2.
