DESCRIPTION

The Tcl channel mechanism provides a device-independent and platform-independent mechanism for performing buffered input and output operations on a variety of file, socket, and device types. The channel mechanism is extensible to new channel types, by providing a low-level channel driver for the new type; the channel driver interface is described in the manual entry for Tcl_CreateChannel. The channel mechanism provides a buffering scheme modeled after Unix's standard I/O, and it also allows for nonblocking I/O on channels.

The procedures described in this manual entry comprise the C APIs of the generic layer of the channel architecture. For a description of the channel driver architecture and how to implement channel drivers for new types of channels, see the manual entry for Tcl_CreateChannel.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel opens the file named fileName for I/O. The mode argument specifies how the file is to be accessed and has the same syntax as the mode argument to the Tcl open command (e.g., "r", "w", "r+", "w+", "a"). The permissions argument specifies the POSIX-style file permissions (e.g., 0644) to use if the file is created; it is ignored if the file already exists.

If successful, this procedure returns a handle for a new Tcl channel. The channel is opened in the Tcl interpreter interp and is associated with the interpreter. If an error occurs, the procedure returns an empty channel handle (TCL_BAD_CHANNEL) and leaves an error message in the interpreter's result.

The channel created by Tcl_OpenFileChannel is automatically registered with the interpreter. It can be retrieved later using Tcl_GetChannel, and it will be closed automatically when the interpreter is destroyed. The caller is responsible for closing the channel explicitly using Tcl_Close if it is no longer needed.

Channels are opened in Tcl 8.4 in nonblocking mode by default. Whether a channel is blocking or non-blocking can be changed using Tcl_SetChannelOption with the -blocking option.

The standard channels stdin, stdout, and stderr are pre-registered in each interpreter. The procedure Tcl_IsStandardChannel can be used to test if a channel is one of these standard channels.

Opening a channel in Tcl 8.4 is not automatic. You must register it with the interpreter using Tcl_RegisterChannel. Otherwise, commands like puts will not be able to find it.

The flags argument to Tcl_OpenCommandChannel is a bitmask composed of OR-ed combinations of the following flags:

TCL_STDIN
Use the pipe channel as the standard input for the first child in the pipeline. Otherwise, the first child inherits the standard input of the invoking process.
TCL_STDOUT
Use the pipe channel as the standard output for the last child in the pipeline. Otherwise, the last child inherits the standard output of the invoking process.
TCL_STDERR
Use the pipe channel as the standard error for the last child in the pipeline. Otherwise, the last child inherits the standard error of the invoking process.
TCL_ENFORCE_MODE
If this flag is set, then redirects specified by TCL_STDIN, TCL_STDOUT, or TCL_STDERR must be exclusively used. If any stdio handles are inherited from the invoking process, this causes an error.

The argument modePtr points to an integer that will receive an OR-ed combination of TCL_READABLE and TCL_WRITABLE to indicate the access modes of the channel.

The argument readOrWrite is an OR-ed combination of TCL_READABLE and TCL_WRITABLE to indicate what operations are valid on the handle.

The argument charsToRead specifies the number of characters to read. If the channel is in binary mode, this is the number of bytes to read.

The argument appendFlag is used by Tcl_ReadChars. If it is non-zero, data read from the channel will be appended to the value. Otherwise, the data will overwrite the existing contents of the value.

The argument bytesToRead specifies the number of bytes to read.

The argument lineObjPtr is a pointer to a Tcl object in which to store the line read from the channel. The line read will be appended to the current value of the object.

The argument lineRead is a pointer to a Tcl dynamic string in which to store the line read from the channel. It must have been initialized by the caller. The line read will be appended to any data already in the dynamic string.

The argument input is the string to be pushed back onto the channel buffer. The argument inputLen is the length of the input string. The argument addAtEnd determines whether the input should be added to the end or beginning of the buffer.

The argument writeObjPtr is a pointer to a Tcl object whose contents will be written to the channel.

The argument charBuf is a buffer containing characters to be written to the channel.

The argument byteBuf is a buffer containing bytes to be written to the channel.

The argument bytesToWrite specifies the number of bytes to write from the buffer to the channel.

The argument offset specifies how far to move the access point in the channel. The argument seekMode specifies whether the offset is relative to the beginning (SEEK_SET), current position (SEEK_CUR), or end (SEEK_END) of the channel.

The argument length specifies the new size of the channel to truncate to.

The argument optionName is the name of the channel option to get or set. The argument optionValue is a Tcl_DString used to return the value of the option or a list of all options and their values. The argument newValue is the new value for the option.

Tcl_OpenCommandChannel creates a channel that is connected to the standard input, output, and error of a command pipeline. The pipeline is specified by argc and argv, which have the same meaning as the arguments to the Tcl exec command. The flags specify how the standard handles of the children in the pipeline relate to the standard handles of the invoking process.

Tcl_MakeFileChannel creates a Tcl channel from an existing operating system specific handle (e.g. a file descriptor on Unix, a HANDLE on Windows). The readOrWrite argument indicates whether the handle is readable and/or writable.

Tcl_GetChannel retrieves a channel associated with the name channelName from the interpreter interp. If modePtr is not NULL, it points to an integer that will receive an OR-ed combination of TCL_READABLE and TCL_WRITABLE, indicating the access modes of the channel.

Tcl_GetChannelNames returns a Tcl list of all channel names currently registered in the interpreter interp. If the pattern argument is not NULL, only channel names matching the pattern are returned. The pattern is matched using Tcl_StringMatch.

Tcl_RegisterChannel registers the channel with the interpreter interp, making it available for use by Tcl commands. If the channel is already registered, this procedure does nothing.

Tcl_UnregisterChannel unregisters the channel from the interpreter interp. The channel handle remains valid, but it can no longer be accessed by Tcl commands using its name. The caller is responsible for closing the channel using Tcl_Close.

Tcl_DetachChannel removes the channel from the interpreter's management, but leaves the channel open. The caller is responsible for closing the channel using Tcl_Close.

Tcl_IsStandardChannel returns true if channel is one of the standard channels (stdin, stdout, stderr) for the interpreter.

Tcl_Close closes the channel. If the channel is not already closed, this procedure will flush any buffered output, free any internal buffers, and close the underlying operating system file descriptor or handle. If an error occurs during closing, an error message is left in the interpreter's result.

Tcl_ReadChars reads characters from the channel into the Tcl object pointed to by readObjPtr. The maximum number of characters to read is specified by charsToRead. If appendFlag is non-zero, the characters read are appended to the object's current value; otherwise, they replace the current value. This procedure may block if the channel is in blocking mode and no data is available. It returns the number of characters actually read, or -1 if an error occurs.

Tcl_Read reads bytes from the channel into the buffer pointed to by readBuf. The maximum number of bytes to read is specified by bytesToRead. This procedure may block if the channel is in blocking mode and no data is available. It returns the number of bytes actually read, or -1 if an error occurs.

Tcl_GetsObj reads characters from the channel until a newline is encountered, or end-of-file is reached. The characters read (up to, but not including, the newline) are stored in the Tcl object pointed to by lineObjPtr. If end-of-file is reached before any characters are read, the object's value remains unchanged. If end-of-file is reached after reading some characters, the newline is not included in the result. This procedure may block if the channel is in blocking mode and no data is available. It returns the number of characters read, or -1 if an error occurs.

Tcl_Gets reads characters from the channel until a newline is encountered, or end-of-file is reached. The characters read (including the newline, if present) are stored in the Tcl dynamic string pointed to by lineRead. If end-of-file is reached before any characters are read, the dynamic string remains unchanged. This procedure may block if the channel is in blocking mode and no data is available. It returns the number of characters read, or -1 if an error occurs.

Tcl_Ungets pushes the contents of input back onto the channel's read buffer. If addAtEnd is true, the input is added to the end of the buffer; otherwise, it is added to the beginning. This is typically used after reading some data and deciding to put it back for later processing.

Tcl_WriteObj writes the contents of the Tcl object pointed to by writeObjPtr to the channel. This procedure may block if the channel is in blocking mode and the output buffer is full. It returns the number of bytes actually written, or -1 if an error occurs.

Tcl_WriteChars writes characters from the buffer pointed to by charBuf to the channel. The number of characters to write is specified by bytesToWrite. This procedure may block if the channel is in blocking mode and the output buffer is full. It returns the number of bytes actually written, or -1 if an error occurs.

Tcl_Write writes bytes from the buffer pointed to by byteBuf to the channel. The number of bytes to write is specified by bytesToWrite. This procedure may block if the channel is in blocking mode and the output buffer is full. It returns the number of bytes actually written, or -1 if an error occurs.

Tcl_ReadRaw and Tcl_WriteRaw are similar to Tcl_Read and Tcl_Write, respectively, but they operate on raw bytes without any character encoding conversion. They are useful for dealing with binary data.

Tcl_Eof returns true if end-of-file has been reached on the channel, false otherwise.

Tcl_Flush forces any buffered output to be written to the channel. This is useful to ensure that data is sent immediately, especially for interactive channels. It returns 0 on success and -1 if an error occurs.

Tcl_InputBlocked returns true if a non-blocking read on the channel would block, false otherwise.

Tcl_InputBuffered returns the number of characters currently in the channel's input buffer.

Tcl_OutputBuffered returns the number of bytes currently in the channel's output buffer.

Tcl_Seek changes the current position in the channel by offset bytes, relative to the position specified by seekMode. SEEK_SET means relative to the beginning of the file, SEEK_CUR means relative to the current position, and SEEK_END means relative to the end of the file. It returns the new position in the channel, or -1 if an error occurs. Note that seeking is only supported on channels that support random access, such as files. Attempting to seek on a socket or pipe will result in an error.

Tcl_Tell returns the current position in the channel, measured in bytes from the beginning of the channel. It returns -1 if an error occurs or if the channel does not support seeking.

Tcl_TruncateChannel truncates the channel to the specified length. This operation is only supported on files opened for writing. It returns 0 on success and -1 if an error occurs.

Tcl_GetChannelOption retrieves the value of the channel option specified by optionName and stores it in the Tcl_DString pointed to by optionValue. If optionName is NULL, it retrieves a list of all options and their values.

Tcl_SetChannelOption sets the channel option specified by optionName to the value newValue.

RETURN VALUE

Most procedures return an integer status code: 0 for success, -1 for failure. For procedures that return channel handles, an empty handle (TCL_BAD_CHANNEL) is returned on error. Procedures that return data (e.g., Tcl_Read, Tcl_Gets) return the amount of data read, or -1 on error. Procedures that return channel positions (e.g., Tcl_Seek, Tcl_Tell) return the position or -1 on error. Tcl channel procedures leave error messages in the interpreter's result on failure.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel يفتح ملفًا محددًا بواسطة fileName ويعيد مقبض قناة يمكن استخدامه لإجراء عمليات الإدخال والإخراج على الملف. تم تصميم واجهة برمجة التطبيقات هذه على غرار الإجراء fopen لمكتبة الإدخال/الإخراج القياسية في Unix. يتشابه بناء الجملة ومعنى جميع الوسائط مع تلك الواردة في أمر Tcl open عند فتح ملف. إذا حدث خطأ أثناء فتح القناة، فتعيد Tcl_OpenFileChannel القيمة NULL وتسجل رمز خطأ POSIX الذي يمكن استرداده باستخدام Tcl_GetErrno. بالإضافة إلى ذلك، إذا كان interp غير NULL، فستترك Tcl_OpenFileChannel رسالة خطأ في نتيجة interp بعد أي خطأ. اعتبارًا من Tcl 8.4، يجب استخدام واجهة برمجة التطبيقات المستندة إلى القيمة Tcl_FSOpenFileChannel بدلاً من Tcl_OpenFileChannel حيثما أمكن.

القناة التي تم إنشاؤها حديثًا لا يتم تسجيلها في المفسر المقدم؛ لتسجيلها، استخدم Tcl_RegisterChannel، الموضحة أدناه. إذا تم إغلاق إحدى القنوات القياسية، stdin أو stdout أو stderr، في وقت سابق، فإن فعل إنشاء القناة الجديدة يعينها أيضًا كبديل للقناة القياسية.

TCL_OPENCOMMANDCHANNEL

يوفر Tcl_OpenCommandChannel واجهة على مستوى C لوظائف أوامر exec و open. يقوم بإنشاء تسلسل من العمليات الفرعية المحددة بواسطة الوسائط argv و argc ويعيد قناة يمكن استخدامها للتواصل مع هذه العمليات الفرعية. يشير الوسيط flags إلى نوع الاتصال الذي سيوجد مع خط أنابيب الأوامر.

إذا تم تعيين العلامة TCL_STDIN، فسيتم ربط الإدخال القياسي للعملية الفرعية الأولى بالقناة: الكتابة إلى القناة ستوفر مدخلات للعملية الفرعية. إذا لم يتم تعيين TCL_STDIN، فسيكون الإدخال القياسي للعملية الفرعية الأولى هو نفسه الإدخال القياسي لهذا التطبيق. إذا تم تعيين TCL_STDOUT، فيمكن قراءة الإخراج القياسي من آخر عملية فرعية من القناة؛ بخلاف ذلك، ينتقل إلى الإخراج القياسي لهذا التطبيق. إذا تم تعيين TCL_STDERR، يتم إرجاع مخرجات الخطأ القياسية لجميع العمليات الفرعية إلى القناة وتؤدي إلى حدوث خطأ عند إغلاق القناة؛ بخلاف ذلك، ينتقل إلى الخطأ القياسي لهذا التطبيق. إذا لم يتم تعيين TCL_ENFORCE_MODE، فيمكن لـ argc و argv إعادة توجيه مقابض stdio لتجاوز TCL_STDIN و TCL_STDOUT و TCL_STDERR؛ إذا تم تعيينها، فهو خطأ لـ argc و argv لتجاوز قنوات stdio التي تم تعيين TCL_STDIN و TCL_STDOUT و TCL_STDERR لها.

إذا حدث خطأ أثناء فتح القناة، فتعيد Tcl_OpenCommandChannel القيمة NULL وتسجل رمز خطأ POSIX الذي يمكن استرداده باستخدام Tcl_GetErrno. بالإضافة إلى ذلك، تترك Tcl_OpenCommandChannel رسالة خطأ في نتيجة المفسر. لا يمكن أن يكون interp NULL.

القناة التي تم إنشاؤها حديثًا لا يتم تسجيلها في المفسر المقدم؛ لتسجيلها، استخدم Tcl_RegisterChannel، الموضحة أدناه. إذا تم إغلاق إحدى القنوات القياسية، stdin أو stdout أو stderr، في وقت سابق، فإن فعل إنشاء القناة الجديدة يعينها أيضًا كبديل للقناة القياسية.

TCL_MAKEFILECHANNEL

ينشئ Tcl_MakeFileChannel Tcl_Channel من مقبض ملف موجود خاص بالمنصة. القناة التي تم إنشاؤها حديثًا لا يتم تسجيلها في المفسر المقدم؛ لتسجيلها، استخدم Tcl_RegisterChannel، الموضحة أدناه. إذا تم إغلاق إحدى القنوات القياسية، stdin أو stdout أو stderr، في وقت سابق، فإن فعل إنشاء القناة الجديدة يعينها أيضًا كبديل للقناة القياسية.

TCL_GETCHANNEL

يعيد Tcl_GetChannel قناة بالاسم channelName المستخدم لإنشائها باستخدام Tcl_CreateChannel ومؤشر إلى مفسر Tcl في interp. إذا لم يتم تسجيل قناة بهذا الاسم في هذا المفسر، فإن الإجراء يعيد القيمة NULL. إذا كان الوسيط modePtr غير NULL، فإنه يشير إلى متغير عدد صحيح سيستقبل تركيبة OR-ed من TCL_READABLE و TCL_WRITABLE تصف ما إذا كانت القناة مفتوحة للقراءة والكتابة.

Tcl_GetChannelNames و Tcl_GetChannelNamesEx يكتبان أسماء القنوات المسجلة إلى نتيجة المفسر كقائمة قيم. ستقوم Tcl_GetChannelNamesEx بتصفية هذه الأسماء وفقًا لـ pattern. إذا كان pattern NULL، فلن تقوم بأي تصفية. القيمة المرجعة هي TCL_OK إذا لم تحدث أخطاء أثناء الكتابة إلى النتيجة، وإلا فهي TCL_ERROR، ويتم ترك رسالة الخطأ في نتيجة المفسر.

TCL_REGISTERCHANNEL

تضيف Tcl_RegisterChannel قناة إلى مجموعة القنوات التي يمكن الوصول إليها في interp. بعد هذا الاستدعاء، يمكن لبرامج Tcl التي يتم تنفيذها في هذا المفسر الإشارة إلى القناة في عمليات الإدخال أو الإخراج باستخدام الاسم المحدد في استدعاء Tcl_CreateChannel. بعد هذا الاستدعاء، تصبح القناة ملكًا للمفسر، ويجب على المتصل عدم استدعاء Tcl_Close للقناة؛ سيتم إغلاق القناة تلقائيًا عند إلغاء تسجيلها من المفسر.

يمكن للكود الذي يتم تنفيذه خارج أي مفسر Tcl استدعاء Tcl_RegisterChannel مع interp على أنه NULL، للإشارة إلى أنه يرغب في الاحتفاظ بمرجع لهذه القناة. لاحقًا، يمكن تسجيل القناة في مفسر Tcl وستغلق فقط عند إجراء العدد المطابق من استدعاءات Tcl_UnregisterChannel. هذا يسمح للكود الذي يتم تنفيذه خارج أي مفسر بالاحتفاظ بمرجع آمن لقناة مسجلة أيضًا في مفسر Tcl.

يتفاعل هذا الإجراء مع الكود الذي يدير القنوات القياسية. إذا لم يتم تهيئة أي قنوات قياسية قبل الاستدعاء الأول لـ Tcl_RegisterChannel، فسيتم تهيئتها بواسطة هذا الاستدعاء. انظر Tcl_StandardChannels لمناقشة عامة حول القنوات القياسية وسلوك مكتبة Tcl فيما يتعلق بها.

TCL_UNREGISTERCHANNEL

يزيل Tcl_UnregisterChannel قناة من مجموعة القنوات التي يمكن الوصول إليها في interp. بعد هذا الاستدعاء، لن يتمكن برامج Tcl من استخدام اسم القناة للإشارة إلى القناة في هذا المفسر. إذا أزال هذا التشغيل آخر تسجيل للقناة في أي مفسر، فسيتم أيضًا إغلاق القناة وتدميرها.

يمكن للكود غير المرتبط بمفسر Tcl استدعاء Tcl_UnregisterChannel مع interp على أنه NULL، للإشارة إلى Tcl أنه لم يعد يحتفظ بمرجع لهذه القناة. إذا كان هذا هو المرجع الأخير للقناة، فسيتم إغلاقها الآن. Tcl_UnregisterChannel مشابه جدًا لـ Tcl_DetachChannel باستثناء أنه سيغلق القناة أيضًا إذا لم تعد هناك مراجع أخرى لها.

TCL_DETACHCHANNEL

يزيل Tcl_DetachChannel قناة من مجموعة القنوات التي يمكن الوصول إليها في interp. بعد هذا الاستدعاء، لن يتمكن برامج Tcl من استخدام اسم القناة للإشارة إلى القناة في هذا المفسر. بخلاف ذلك، لا يكون لهذا الأمر أي تأثير إضافي. لا يمكن استخدامه على القنوات القياسية (stdout و stderr و stdin)، وسيعيد TCL_ERROR إذا تم تمرير إحدى هذه القنوات.

يمكن للكود غير المرتبط بمفسر Tcl استدعاء Tcl_DetachChannel مع interp على أنه NULL، للإشارة إلى Tcl أنه لم يعد يحتفظ بمرجع لهذه القناة. إذا كان هذا هو المرجع الأخير للقناة، على عكس Tcl_UnregisterChannel، فلن يتم إغلاقه.

TCL_ISSTANDARDCHANNEL

تختبر Tcl_IsStandardChannel ما إذا كانت القناة هي إحدى القنوات القياسية الثلاث، stdin أو stdout أو stderr. إذا كانت كذلك، فإنها تعيد 1، وإلا تعيد 0.

لا يتم بذل أي محاولة للتحقق مما إذا كانت القناة المعطاة أو القنوات القياسية مهيأة أو صالحة بأي شكل آخر.

TCL_CLOSE

تدمر Tcl_Close القناة channel، والتي يجب أن تشير إلى قناة مفتوحة حاليًا. يجب ألا تكون القناة مسجلة في أي مفسر عند استدعاء Tcl_Close. يتم مسح البيانات المخزنة مؤقتًا للإخراج إلى جهاز إخراج القناة قبل تدمير القناة، ويتم تجاهل أي بيانات مدخلة مخزنة مؤقتًا. إذا كانت هذه قناة مانعة، فإن الاستدعاء لا يعود حتى يتم إرسال جميع البيانات المخزنة مؤقتًا بنجاح إلى جهاز إخراج القناة. إذا كانت هذه قناة غير مانعة وهناك إخراج مخزن مؤقتًا لا يمكن كتابته دون منع، يعود الاستدعاء فورًا؛ يتم مسح الإخراج في الخلفية وسيتم إغلاق القناة بمجرد إخراج جميع البيانات المخزنة مؤقتًا. في هذه الحالة، لا يتم الإبلاغ عن الأخطاء أثناء المسح.

إذا تم إغلاق القناة بنجاح، تعيد Tcl_Close القيمة TCL_OK. إذا حدث خطأ، تعيد Tcl_Close القيمة TCL_ERROR وتسجل رمز خطأ POSIX الذي يمكن استرداده باستخدام Tcl_GetErrno. إذا تم إغلاق القناة بشكل متزامن وحدث خطأ أثناء إغلاق القناة وكان interp غير NULL، فسيتم ترك رسالة خطأ في نتيجة المفسر.

ملاحظة: لا يجوز استدعاء Tcl_Close على قناة تم تسجيلها باستخدام Tcl_RegisterChannel؛ انظر الوثائق الخاصة بـ Tcl_RegisterChannel، أعلاه، للحصول على التفاصيل. إذا تم تمرير القناة على الإطلاق كوسيط chan في استدعاء لـ Tcl_RegisterChannel، فيجب عليك بدلاً من ذلك استخدام Tcl_UnregisterChannel، والتي ستستدعي داخليًا Tcl_Close عند مطابقة جميع استدعاءات Tcl_RegisterChannel بالاستدعاءات المقابلة لـ Tcl_UnregisterChannel.

TCL_READCHARS AND TCL_READ

تستهلك Tcl_ReadChars بايتات من channel، وتحول البايتات إلى UTF-8 بناءً على ترميز القناة وتخزن البيانات المنتجة في التمثيل النصي لـ readObjPtr. القيمة المرجعة لـ Tcl_ReadChars هي عدد الأحرف، حتى charsToRead، التي تم تخزينها في readObjPtr. إذا حدث خطأ أثناء القراءة، فإن القيمة المرجعة هي -1 وتسجل Tcl_ReadChars رمز خطأ POSIX يمكن استرداده باستخدام Tcl_GetErrno.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption retrieves the value of an option optionName on channel. The value is returned as a Tcl object. Interp must be non-NULL. Tcl_GetChannelOption returns the option's value in the interpreter's result if the option is found. Otherwise, it leaves an error message in the interpreter's result and returns an empty Tcl object.

The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR.

The various preexisting options and their possible values are described in the manual entry for the Tcl fconfigure command. Other options can be added by each channel type. These channel type specific options are described in the manual entry for the Tcl command that creates a channel of that type; for example, the additional options for TCP-based channels are described in the manual entry for the Tcl socket command.

The list of valid options for a channel is returned by Tcl_GetChannelOptions. This is done by adding each option name as a separate element to the Tcl DString passed in as optionList, using a series of calls to Tcl_DStringAppendElement. The various preexisting options and their possible values are described in the manual entry for the Tcl fconfigure command. Other options can be added by each channel type. These channel type specific options are described in the manual entry for the Tcl command that creates a channel of that type; for example, the additional options for TCP-based channels are described in the manual entry for the Tcl socket command. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR and calls Tcl_SetErrno to store an appropriate POSIX error code.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption sets a new value newValue for an option optionName on channel. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR; in addition, if interp is non-NULL, Tcl_SetChannelOption leaves an error message in the interpreter's result.

TCL_EOF

Tcl_Eof returns a nonzero value if channel encountered an end of file during the last input operation.

TCL_INPUTBLOCKED

Tcl_InputBlocked returns a nonzero value if channel is in nonblocking mode and the last input operation returned less data than requested because there was insufficient data available. The call always returns zero if the channel is in blocking mode.

TCL_INPUTBUFFERED

Tcl_InputBuffered returns the number of bytes of input currently buffered in the internal buffers for a channel. If the channel is not open for reading, this function always returns zero.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered returns the number of bytes of output currently buffered in the internal buffers for a channel. If the channel is not open for writing, this function always returns zero.

PLATFORM ISSUES

The handles returned from Tcl_GetChannelHandle depend on the platform and the channel type. On Unix platforms, the handle is always a Unix file descriptor as returned from the open system call. On Windows platforms, the handle is a file HANDLE when the channel was created with Tcl_OpenFileChannel, Tcl_OpenCommandChannel, or Tcl_MakeFileChannel. Other channel types may return a different type of handle on Windows platforms.
