يحدد تصرف مقابض stdio في خط الأنابيب: مزيج OR من TCL_STDIN، TCL_STDOUT، TCL_STDERR، و TCL_ENFORCE_MODE. إذا تم تعيين TCL_STDIN، فإن الإدخال القياسي للطفل الأول في الأنبوب هو قناة الأنبوب، وإلا فهو نفس الإدخال القياسي للعملية المستدعية؛ وينطبق الشيء نفسه على TCL_STDOUT و TCL_STDERR. إذا لم يتم تعيين TCL_ENFORCE_MODE، فيمكن للأنبوب إعادة توجيه مقابض stdio لتجاوز مقابض stdio التي تم تعيين TCL_STDIN و TCL_STDOUT و TCL_STDERR لها. إذا تم تعيينه، فإن مثل هذه عمليات إعادة التوجيه تسبب خطأ.

مقبض خاص بنظام التشغيل للإدخال/الإخراج إلى ملف. بالنسبة لنظام Unix، هذا هو واصف ملف، وبالنسبة لنظام Windows، فهو مقبض HANDLE.

مؤشر إلى قيمة Tcl سيتم تخزين الأحرف المقروءة من القناة فيها.
int charsToRead (in)
عدد الأحرف المراد قراءتها من القناة. إذا كان ترميز القناة هو binary، فهذا يعادل عدد البايتات المراد قراءتها من القناة.

الوصف

توفر آلية قنوات Tcl آلية مستقلة عن الجهاز ومستقلة عن النظام الأساسي لإجراء عمليات الإدخال والإخراج المخزنة مؤقتًا على مجموعة متنوعة من أنواع الملفات والمقابس والأجهزة. آلية القنوات قابلة للتوسيع لتشمل أنواع قنوات جديدة، عن طريق توفير برنامج تشغيل قنوات منخفض المستوى للنوع الجديد؛ يتم وصف واجهة برنامج تشغيل القنوات في صفحة الدليل الخاصة بـ Tcl_CreateChannel. توفر آلية القنوات مخطط تخزين مؤقت مستوحى من الإدخال/الإخراج القياسي لنظام Unix، كما أنها تسمح بالإدخال/الإخراج غير الحاجب على القنوات.

تتضمن الإجراءات الموضحة في صفحة الدليل هذه واجهات برمجة التطبيقات C للواجهة العامة لهندسة القنوات. لوصف هندسة برامج تشغيل القنوات وكيفية تنفيذ برامج تشغيل القنوات لأنواع القنوات الجديدة، راجع صفحة الدليل الخاصة بـ Tcl_CreateChannel.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel يفتح ملفًا محددًا بواسطة fileName ويعيد مقبض قناة يمكن استخدامه لإجراء الإدخال والإخراج على الملف. تم تصميم واجهة برمجة التطبيقات هذه على غرار إجراء fopen الخاص بمكتبة الإدخال/الإخراج القياسية في Unix. بناء الجملة ومعنى جميع الوسائط مشابه لتلك الموجودة في الأمر Tcl open عند فتح ملف. إذا حدث خطأ أثناء فتح القناة، فإن Tcl_OpenFileChannel يعيد NULL ويسجل رمز خطأ POSIX يمكن استرداده باستخدام Tcl_GetErrno. بالإضافة إلى ذلك، إذا كان interp غير NULL، فإن Tcl_OpenFileChannel يترك رسالة خطأ في نتيجة interp بعد أي خطأ. اعتبارًا من Tcl 8.4، يجب استخدام واجهة برمجة التطبيقات المستندة إلى القيم Tcl_FSOpenFileChannel مفضلة على Tcl_OpenFileChannel كلما أمكن ذلك.

القناة المنشأة حديثًا غير مسجلة في المفسر المقدم؛ لتسجيلها، استخدم Tcl_RegisterChannel، الموصوف أدناه. إذا تم إغلاق إحدى القنوات القياسية، stdin أو stdout أو stderr سابقًا، فإن عملية إنشاء القناة الجديدة تعينها أيضًا كبديل للقناة القياسية.

TCL_OPENCOMMANDCHANNEL

توفر Tcl_OpenCommandChannel واجهة مستوى C لوظائف أوامر exec و open. تنشئ تسلسلًا من العمليات الفرعية المحددة بواسطة الوسيطين argv و argc وتعيد قناة يمكن استخدامها للتواصل مع هذه العمليات الفرعية. يشير الوسيط flags إلى نوع الاتصال الذي سيكون موجودًا مع خط أنابيب الأوامر.

إذا تم تعيين علامة TCL_STDIN، فسيتم ربط الإدخال القياسي للعملية الفرعية الأولى بالقناة: الكتابة إلى القناة ستوفر مدخلات للعملية الفرعية. إذا لم يتم تعيين TCL_STDIN، فسيكون الإدخال القياسي للعملية الفرعية الأولى هو نفس الإدخال القياسي لهذا التطبيق. إذا تم تعيين TCL_STDOUT، فيمكن قراءة الإخراج القياسي من العملية الفرعية الأخيرة من القناة؛ بخلاف ذلك، يذهب إلى الإخراج القياسي لهذا التطبيق. إذا تم تعيين TCL_STDERR، فسيتم إرجاع إخراج الخطأ القياسي لجميع العمليات الفرعية إلى القناة وينتج عنه خطأ عند إغلاق القناة؛ بخلاف ذلك، يذهب إلى الخطأ القياسي لهذا التطبيق. إذا لم يتم تعيين TCL_ENFORCE_MODE، فيمكن لـ argc و argv إعادة توجيه مقابض stdio لتجاوز TCL_STDIN و TCL_STDOUT و TCL_STDERR؛ إذا تم تعيينها، فإنه يعد خطأ لـ argc و argv لتجاوز قنوات stdio التي تم تعيين TCL_STDIN و TCL_STDOUT و TCL_STDERR لها.

إذا حدث خطأ أثناء فتح القناة، فإن Tcl_OpenCommandChannel يعيد NULL ويسجل رمز خطأ POSIX يمكن استرداده باستخدام Tcl_GetErrno. بالإضافة إلى ذلك، تترك Tcl_OpenCommandChannel رسالة خطأ في نتيجة المفسر. لا يمكن أن يكون interp NULL.

القناة المنشأة حديثًا غير مسجلة في المفسر المقدم؛ لتسجيلها، استخدم Tcl_RegisterChannel، الموصوف أدناه. إذا تم إغلاق إحدى القنوات القياسية، stdin أو stdout أو stderr سابقًا، فإن عملية إنشاء القناة الجديدة تعينها أيضًا كبديل للقناة القياسية.

TCL_MAKEFILECHANNEL

ينشئ Tcl_MakeFileChannel Tcl_Channel من مقبض ملف موجود خاص بالمنصة. القناة المنشأة حديثًا غير مسجلة في المفسر المقدم؛ لتسجيلها، استخدم Tcl_RegisterChannel، الموصوف أدناه. إذا تم إغلاق إحدى القنوات القياسية، stdin أو stdout أو stderr سابقًا، فإن عملية إنشاء القناة الجديدة تعينها أيضًا كبديل للقناة القياسية.

TCL_GETCHANNEL

يعيد Tcl_GetChannel قناة بالاسم channelName المستخدم لإنشائها باستخدام Tcl_CreateChannel ومؤشر إلى مفسر Tcl في interp. إذا لم يتم تسجيل قناة بهذا الاسم في هذا المفسر، فإن الإجراء يعيد NULL. إذا كان الوسيط modePtr ليس NULL، فهو يشير إلى متغير صحيح سيتلقى تركيبة ORed من TCL_READABLE و TCL_WRITABLE تصف ما إذا كانت القناة مفتوحة للقراءة والكتابة.

Tcl_GetChannelNames و Tcl_GetChannelNamesEx يكتب أسماء القنوات المسجلة إلى نتيجة المفسر كقيمة قائمة. ستقوم Tcl_GetChannelNamesEx بتصفية هذه الأسماء وفقًا لـ pattern. إذا كان pattern NULL، فلن تقوم بأي تصفية. القيمة المعادة هي TCL_OK إذا لم تحدث أخطاء أثناء الكتابة إلى النتيجة، وإلا فإنها TCL_ERROR، ويتم ترك رسالة الخطأ في نتيجة المفسر.

TCL_REGISTERCHANNEL

تضيف Tcl_RegisterChannel قناة إلى مجموعة القنوات التي يمكن الوصول إليها في interp. بعد هذا الاستدعاء، يمكن لبرامج Tcl التي تنفذ في هذا المفسر الإشارة إلى القناة في عمليات الإدخال أو الإخراج باستخدام الاسم المقدم في استدعاء Tcl_CreateChannel. بعد هذا الاستدعاء، تصبح القناة ملكًا للمفسر، ولا يجب على المتصل استدعاء Tcl_Close للقناة؛ سيتم إغلاق القناة تلقائيًا عند إلغاء تسجيلها من المفسر.

يمكن للتعليمات البرمجية التي تعمل خارج أي مفسر Tcl استدعاء Tcl_RegisterChannel مع interp كـ NULL، للإشارة إلى أنها ترغب في الاحتفاظ بمرجع لهذه القناة. لاحقًا، يمكن تسجيل القناة في مفسر Tcl وسيتم إغلاقها فقط عند إجراء العدد المطابق من استدعاءات Tcl_UnregisterChannel. يتيح ذلك للتعليمات البرمجية التي تعمل خارج أي مفسر الاحتفاظ بمرجع آمن لقناة مسجلة أيضًا في مفسر Tcl.

يتفاعل هذا الإجراء مع التعليمات البرمجية التي تدير القنوات القياسية. إذا لم يتم تهيئة أي قنوات قياسية قبل الاستدعاء الأول لـ Tcl_RegisterChannel، فسيتم تهيئتها بواسطة هذا الاستدعاء. راجع Tcl_StandardChannels لمناقشة عامة حول القنوات القياسية وسلوك مكتبة Tcl فيما يتعلق بها.

TCL_UNREGISTERCHANNEL

تزيل Tcl_UnregisterChannel قناة من مجموعة القنوات التي يمكن الوصول إليها في interp. بعد هذا الاستدعاء، لن تتمكن برامج Tcl من استخدام اسم القناة للإشارة إلى القناة في هذا المفسر. إذا قامت هذه العملية بإزالة آخر تسجيل للقناة في أي مفسر، فسيتم أيضًا إغلاق القناة وتدميرها.

يمكن للتعليمات البرمجية غير المرتبطة بمفسر Tcl استدعاء Tcl_UnregisterChannel مع interp كـ NULL، للإشارة إلى Tcl أنها لم تعد تحتفظ بمرجع لهذه القناة. إذا كان هذا هو المرجع الأخير للقناة، فسيتم إغلاقها الآن. Tcl_UnregisterChannel مشابه جدًا لـ Tcl_DetachChannel باستثناء أنه سيغلق القناة أيضًا إذا لم تعد هناك مراجع أخرى لها.

TCL_DETACHCHANNEL

تزيل Tcl_DetachChannel قناة من مجموعة القنوات التي يمكن الوصول إليها في interp. بعد هذا الاستدعاء، لن تتمكن برامج Tcl من استخدام اسم القناة للإشارة إلى القناة في هذا المفسر. بخلاف ذلك، ليس لهذا الأمر أي تأثير إضافي. لا يمكن استخدامه على القنوات القياسية (stdout و stderr و stdin)، وسيعيد TCL_ERROR إذا تم تمرير إحدى هذه القنوات إليه.

يمكن للتعليمات البرمجية غير المرتبطة بمفسر Tcl استدعاء Tcl_DetachChannel مع interp كـ NULL، للإشارة إلى Tcl أنها لم تعد تحتفظ بمرجع لهذه القناة. إذا كان هذا هو المرجع الأخير للقناة، على عكس Tcl_UnregisterChannel، فلن يتم إغلاقها.

TCL_ISSTANDARDCHANNEL

يختبر Tcl_IsStandardChannel ما إذا كانت قناة ما هي إحدى القنوات القياسية الثلاث، stdin أو stdout أو stderr. إذا كان الأمر كذلك، فإنها تعيد 1، وإلا 0.

لا يتم بذل أي محاولة للتحقق مما إذا كانت القناة المحددة أو القنوات القياسية مهيأة أو صالحة بأي شكل آخر.

TCL_CLOSE

يقوم Tcl_Close بتدمير القناة channel، والتي يجب أن تشير إلى قناة مفتوحة حاليًا. يجب ألا تكون القناة مسجلة في أي مفسر عند استدعاء Tcl_Close. يتم مسح الإخراج المخزن مؤقتًا إلى جهاز الإخراج الخاص بالقناة قبل تدمير القناة، ويتم تجاهل أي إدخال مخزن مؤقتًا. إذا كانت هذه قناة مانعة، فلن يعود الاستدعاء حتى يتم إرسال جميع البيانات المخزنة مؤقتًا بنجاح إلى جهاز الإخراج الخاص بالقناة. إذا كانت هذه قناة غير مانعة وهناك إخراج مخزن مؤقتًا لا يمكن كتابته دون منع، فإن الاستدعاء يعود فورًا؛ يتم مسح الإخراج في الخلفية وسيتم إغلاق القناة بمجرد إخراج جميع البيانات المخزنة مؤقتًا. في هذه الحالة، لا يتم الإبلاغ عن أخطاء أثناء المسح.

إذا تم إغلاق القناة بنجاح، فإن Tcl_Close يعيد TCL_OK. إذا حدث خطأ، فإن Tcl_Close يعيد TCL_ERROR ويسجل رمز خطأ POSIX يمكن استرداده باستخدام Tcl_GetErrno. إذا تم إغلاق القناة بشكل متزامن وحدث خطأ أثناء إغلاق القناة وكان interp غير NULL، يتم ترك رسالة خطأ في نتيجة المفسر.

ملاحظة: ليس من الآمن استدعاء Tcl_Close على قناة تم تسجيلها باستخدام Tcl_RegisterChannel؛ راجع وثائق Tcl_RegisterChannel، أعلاه، للحصول على التفاصيل. إذا تم تقديم القناة على الإطلاق كوسيط chan في استدعاء لـ Tcl_RegisterChannel، فيجب عليك بدلاً من ذلك استخدام Tcl_UnregisterChannel، والذي سيستدعي داخليًا Tcl_Close عندما تتم مطابقة جميع استدعاءات Tcl_RegisterChannel مع استدعاءات مقابلة لـ Tcl_UnregisterChannel.

TCL_READCHARS AND TCL_READ

تستهلك Tcl_ReadChars بايتات من channel، محولة البايتات إلى UTF-8 بناءً على ترميز القناة وتخزين البيانات المنتجة في التمثيل النصي لـ readObjPtr. القيمة المعادة لـ Tcl_ReadChars هي عدد الأحرف، حتى charsToRead، التي تم تخزينها في readObjPtr. إذا حدث خطأ أثناء القراءة، فإن القيمة المعادة هي -1 وتقوم Tcl_ReadChars بتسجيل رمز خطأ POSIX يمكن استرداده باستخدام Tcl_GetErrno.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption returns the current value for an option optionName on channel. The value is returned as a Tcl value in valuePtr. The procedure returns TCL_OK if the option exists and has a value, otherwise it returns TCL_ERROR and leaves an error message in the interpreter's result. The valid options for any given channel depend on the channel's type. The available options and their possible values are described in the manual entry for the Tcl fconfigure command. Additional options may be supported by individual channel drivers; these are described in the manual entry for the command that creates the channel (e.g., the manual entry for the Tcl socket command describes the options specific to TCP sockets).

The value for optionName is retrieved using a series of calls to Tcl_DStringAppendElement. The various preexisting options and their possible values are described in the manual entry for the Tcl fconfigure command. Other options can be added by each channel type. These channel type specific options are described in the manual entry for the Tcl command that creates a channel of that type; for example, the additional options for TCP-based channels are described in the manual entry for the Tcl socket command. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR and calls Tcl_SetErrno to store an appropriate POSIX error code.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption sets a new value newValue for an option optionName on channel. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR; in addition, if interp is non-NULL, Tcl_SetChannelOption leaves an error message in the interpreter's result.

TCL_EOF

Tcl_Eof returns a nonzero value if channel encountered an end of file during the last input operation.

TCL_INPUTBLOCKED

Tcl_InputBlocked returns a nonzero value if channel is in nonblocking mode and the last input operation returned less data than requested because there was insufficient data available. The call always returns zero if the channel is in blocking mode.

TCL_INPUTBUFFERED

Tcl_InputBuffered returns the number of bytes of input currently buffered in the internal buffers for a channel. If the channel is not open for reading, this function always returns zero.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered returns the number of bytes of output currently buffered in the internal buffers for a channel. If the channel is not open for writing, this function always returns zero.

PLATFORM ISSUES

The handles returned from Tcl_GetChannelHandle depend on the platform and the channel type. On Unix platforms, the handle is always a Unix file descriptor as returned from the open system call. On Windows platforms, the handle is a file HANDLE when the channel was created with Tcl_OpenFileChannel, Tcl_OpenCommandChannel, or Tcl_MakeFileChannel. Other channel types may return a different type of handle on Windows platforms.
