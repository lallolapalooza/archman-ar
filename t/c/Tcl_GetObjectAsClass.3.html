الوصف

الكائنات هي كيانات مصنفة لها مجموعة من العمليات ("الطرق") مرتبطة بها. الفئات هي كائنات يمكنها تصنيع كائنات. يمكن النظر إلى كل فئة ككائن؛ يمكن الحصول على طريقة عرض الفئة باستخدام Tcl_GetClassAsObject، والتي تعيد دائمًا الكائن عند تطبيقها على فئة غير مدمرة، ويمكن النظر إلى كائن كفئة بمساعدة Tcl_GetObjectAsClass (التي تعيد الفئة، أو NULL إذا كان الكائن ليس فئة). يمكن البحث عن كائن باستخدام الدالة Tcl_GetObjectFromObj، والتي تعيد كائنًا أو NULL (مع رسالة خطأ في نتيجة المفسر) إذا تعذر العثور على الكائن. الطريقة الصحيحة للبحث عن فئة بالاسم هي البحث عن الكائن بهذا الاسم ثم استخدام Tcl_GetObjectAsClass.

لكل كائن أمر ومساحة أسماء خاصة به مرتبطة به. يمكن الحصول على الأمر باستخدام الدالة Tcl_GetObjectCommand، واسم الكائن (وبالتالي اسم الأمر) باستخدام Tcl_GetObjectName، ويمكن الحصول على مساحة الأسماء باستخدام الدالة Tcl_GetObjectNamespace. لاحظ أن مرجع الكائن الذي تعيده Tcl_GetObjectName هو مرجع مشترك. يمكنك أيضًا معرفة ما إذا كان الكائن قد تم وضع علامة عليه للحذف باستخدام Tcl_ObjectDeleted (يعيد صحيحًا إذا بدأ حذف الكائن)؛ قد يكون هذا مفيدًا أثناء معالجة الطرق.

يتم إنشاء كائنات الفئات باستخدام Tcl_NewObjectInstance، والتي تنشئ كائنًا من أي فئة (ويتم استدعاؤها داخليًا بواسطة كل من الطريقتين create و new لـ oo::class). المعاملات التي تقدم اختياريًا اسم الكائن ومساحة الأسماء التي سيتم إنشاؤها، وتصف الوسائط التي سيتم تمريرها إلى مُنشئ الفئة (إن وجدت). ستكون نتيجة الدالة مرجعًا إلى الكائن الذي تم إنشاؤه حديثًا، أو NULL إذا فشل الإنشاء (عندما سيتم ترك رسالة خطأ في نتيجة المفسر). بالإضافة إلى ذلك، يمكن نسخ الكائنات باستخدام Tcl_CopyObjectInstance، والتي تنشئ نسخة من كائن دون تنفيذ أي مُنشئ.

لاحظ أن إدارة دورة حياة الكائنات تتم داخليًا في TclOO ولا تستخدم Tcl_Preserve. ليس من الآمن وضع مقبض Tcl_Object في هيكل C بدورة حياة مختلفة عن دورة حياة الكائن؛ يجب استخدام اسم أمر الكائن (الذي تم الحصول عليه باستخدام Tcl_GetObjectName) بدلاً من المقابض. من الآمن استخدام مقبض Tcl_Object أثناء دورة حياة استدعاء طريقة على هذا الكائن؛ لا تصبح المقابض غير صالحة طالما أن هناك استدعاءً معلقًا على كائنها (حتى لو كانت العملية الآمنة الوحيدة عليها هي Tcl_ObjectDeleted؛ تضمن العمليات الأخرى فقط أنها تعمل على كائنات غير مدمرة).

بيانات وصفية للكائنات والفئات

يمكن أن يكون لكل كائن وفئة كمية اعتباطية من البيانات الوصفية المرتبطة بها، والتي يكون معنى الكائن أو الفئة فقط كما هو موصوف في نسخة من هيكل Tcl_ObjectMetadataType. يتم وصف البيانات الوصفية المراد ربطها بنوع البيانات الوصفية (المقدمة في المعامل metaTypePtr) ومؤشر اعتباطي (المعامل metadata) التي يتم تمريرها إلى Tcl_ObjectSetMetadata و Tcl_ClassSetMetadata، ويمكن الحصول على بيانات وصفية معينة حسب نوعها باستخدام Tcl_ObjectGetMetadata و Tcl_ClassGetMetadata. إذا كان المعامل metadata لـ Tcl_ObjectSetMetadata أو Tcl_ClassSetMetadata هو NULL، يتم إزالة البيانات الوصفية إذا تم ربطها، وتكون نتائج Tcl_ObjectGetMetadata و Tcl_ClassGetMetadata هي NULL إذا لم يتم ربط نوع البيانات الوصفية المحدد. ليس خطأً طلب أو إزالة بيانات وصفية لم يتم ربطها.

هيكل TCL_OBJECTMETADATATYPE

محتويات هيكل Tcl_ObjectMetadataType هي كما يلي:

typedef const struct {
    int version;
    const char *name;
    Tcl_ObjectMetadataDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_ObjectMetadataType;

يسمح الحقل version بالتوسع المستقبلي للهيكل، ويجب دائمًا تعريفه بنفس قيمة TCL_OO_METADATA_VERSION_CURRENT. يوفر الحقل name اسمًا قابلاً للقراءة البشرية للنوع، وهو محجوز للفحص.

يوفر الحقل deleteProc دالة من نوع Tcl_ObjectMetadataDeleteProc تُستخدم لإزالة كتلة بيانات وصفية معينة، ويتم استدعاؤها عند استبدال البيانات الوصفية المرتبطة أو إزالتها؛ يجب ألا يكون الحقل NULL.

يوفر الحقل cloneProc دالة تُستخدم لنسخ كتلة بيانات وصفية (يتم استخدامها عند إنشاء نسخة من كائن باستخدام Tcl_CopyObjectInstance)؛ إذا كانت NULL، فسيتم نسخ البيانات الوصفية مباشرة.

DESCRIPTION

The TclOO C API provides a rich set of functions for manipulating and querying the internal state of TclOO objects and classes. This man page details the functions for inspecting and modifying an object's class, constructor, destructor, and associated metadata.

OBJECT AND CLASS METADATA

TclOO objects and classes can have arbitrary, named metadata associated with them. This metadata is accessed via string keys. It is intended for use by Tcl code and extensions that need to associate custom data with objects and classes.

Tcl_ObjectMetadataDeleteProc FUNCTION SIGNATURE

Functions matching this signature are used to free metadata associated with an object.

typedef void Tcl_ObjectMetadataDeleteProc(
        ClientData metadata);

The metadata argument gives the address of the metadata to be deleted.

Tcl_CloneProc FUNCTION SIGNATURE

Functions matching this signature are used to create copies of metadata associated with a class or object.

typedef int Tcl_CloneProc(
        Tcl_Interp *interp,
        ClientData srcMetadata,
        ClientData *dstMetadataPtr);

The interp argument gives a place to write an error message when the attempt to clone the object is to fail, in which case the clone procedure must also return TCL_ERROR; it should return TCL_OK otherwise. The srcMetadata argument gives the address of the metadata to be cloned, and the cloned metadata should be written into the variable pointed to by dstMetadataPtr; a NULL should be written if the metadata is to not be cloned but the overall object copy operation is still to succeed.

OBJECT METHOD NAME MAPPING

It is possible to control, on a per-object basis, what methods are invoked when a particular method is invoked. Normally this is done by looking up the method name in the object and then in the class hierarchy, but fine control of exactly what the value used to perform the look up is afforded through the ability to set a method name mapper callback via Tcl_ObjectSetMethodNameMapper (and its introspection counterpart, Tcl_ObjectGetMethodNameMapper, which returns the current mapper). The current mapper (if any) is invoked immediately before looking up what chain of method implementations is to be used.

Tcl_ObjectMapMethodNameProc FUNCTION SIGNATURE

The Tcl_ObjectMapMethodNameProc callback is defined as follows:

typedef int Tcl_ObjectMapMethodNameProc(
        Tcl_Interp *interp,
        Tcl_Object object,
        Tcl_Class *startClsPtr,
        Tcl_Obj *methodNameObj);

If the result is TCL_OK, the remapping is assumed to have been done. If the result is TCL_ERROR, an error message will have been left in interp and the method call will fail. If the result is TCL_BREAK, the standard method name lookup rules will be used; the behavior of other result codes is currently undefined. The object parameter says which object is being processed. The startClsPtr parameter points to a variable that contains the first class to provide a definition in the method chain to process, or NULL if the whole chain is to be processed (the argument itself is never NULL); this variable may be updated by the callback. The methodNameObj parameter gives an unshared object containing the name of the method being invoked, as provided by the user; this object may be updated by the callback.
