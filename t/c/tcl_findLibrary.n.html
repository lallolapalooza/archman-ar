مقدمة

تتضمن Tcl مكتبة من إجراءات Tcl للوظائف المطلوبة بشكل شائع. الإجراءات المعرفة في مكتبة Tcl هي إجراءات عامة مناسبة للاستخدام من قبل العديد من التطبيقات المختلفة. موقع مكتبة Tcl يتم إرجاعه بواسطة الأمر info library. بالإضافة إلى مكتبة Tcl، عادة ما يكون لكل تطبيق مكتبته الخاصة من إجراءات الدعم؛ وعادة ما يتم إعطاء موقع هذه المكتبة بواسطة قيمة متغير app_library العام، حيث app هو اسم التطبيق. على سبيل المثال، يتم الاحتفاظ بموقع مكتبة Tk في المتغير tk_library.

للوصول إلى الإجراءات في مكتبة Tcl، يجب على التطبيق استدعاء الملف init.tcl في المكتبة، على سبيل المثال باستخدام أمر Tcl

source [file join [info library] init.tcl]

إذا تم استدعاء إجراء المكتبة Tcl_Init من إجراء Tcl_AppInit للتطبيق، يحدث هذا تلقائيًا. يقوم الكود الموجود في init.tcl بتعريف الإجراء unknown وترتيب تحميل الإجراءات الأخرى عند الطلب باستخدام آلية التحميل التلقائي المعرفة أدناه.

إجراءات الأوامر

الإجراءات التالية متوفرة في مكتبة Tcl:

auto_execok cmd
يحدد ما إذا كان هناك ملف قابل للتنفيذ أو أمر مضمن في سطر الأوامر بالاسم cmd. إذا كان الأمر كذلك، فإنه يرجع قائمة بالوسائط التي سيتم تمريرها إلى exec لتنفيذ الملف القابل للتنفيذ أو الأمر المضمن المسمى بواسطة cmd. إذا لم يكن الأمر كذلك، فإنه يرجع سلسلة فارغة. يفحص هذا الأمر الدلائل الموجودة في مسار البحث الحالي (المعطى بواسطة متغير البيئة PATH) في بحثه عن ملف قابل للتنفيذ يسمى cmd. على منصات Windows، يتم توسيع البحث بنفس الدلائل وامتدادات الملفات التي تستخدمها exec. تتذكر auto_execok معلومات حول عمليات البحث السابقة في مصفوفة تسمى auto_execs؛ هذا يتجنب البحث في المسار في المكالمات المستقبلية لنفس cmd. يمكن استخدام الأمر auto_reset لإجبار auto_execok على نسيان معلوماته المخزنة مؤقتًا.
auto_import pattern
يتم استدعاء auto_import أثناء namespace import لمعرفة ما إذا كانت الأوامر المستوردة المحددة بواسطة pattern موجودة في مكتبة تم تحميلها تلقائيًا. إذا كان الأمر كذلك، يتم تحميل الأوامر لتكون متاحة للمفسر لإنشاء روابط الاستيراد. إذا لم تكن الأوامر موجودة في مكتبة تم تحميلها تلقائيًا، فإن auto_import لا تفعل شيئًا. تتم مطابقة الأنماط وفقًا لقواعد المطابقة الخاصة بـ namespace import.
auto_load cmd
يحاول هذا الأمر تحميل تعريف لأمر Tcl يسمى cmd. للقيام بذلك، فإنه يبحث في مسار التحميل التلقائي، وهو قائمة بدليل واحد أو أكثر. يتم إعطاء مسار التحميل التلقائي بواسطة المتغير العام auto_path إذا كان موجودًا. إذا لم يكن هناك متغير auto_path، يتم استخدام متغير البيئة TCLLIBPATH، إذا كان موجودًا. خلاف ذلك، يتكون مسار التحميل التلقائي من دليل مكتبة Tcl فقط. يجب أن يحتوي كل دليل في مسار التحميل التلقائي على ملف tclIndex يصف أمرًا واحدًا أو أكثر معرفًا في هذا الدليل ونصًا برمجيًا لتقييم تحميل كل أمر. يجب إنشاء ملف tclIndex باستخدام الأمر auto_mkindex. إذا تم العثور على cmd في ملف فهرس، يتم تقييم النص البرمجي المناسب لإنشاء الأمر. يرجع الأمر auto_load القيمة 1 إذا تم إنشاء cmd بنجاح. يرجع الأمر 0 إذا لم يكن هناك إدخال فهرس لـ cmd أو إذا لم يحدد النص البرمجي cmd فعليًا (على سبيل المثال، لأن معلومات الفهرس قديمة). إذا حدث خطأ أثناء معالجة النص البرمجي، فسيتم إرجاع هذا الخطأ. يقرأ auto_load معلومات الفهرس مرة واحدة فقط ويحفظها في المصفوفة auto_index؛ المكالمات المستقبلية لـ auto_load تبحث عن cmd في المصفوفة بدلاً من إعادة قراءة ملفات الفهرس. يمكن حذف معلومات الفهرس المخزنة مؤقتًا باستخدام الأمر auto_reset. سيؤدي هذا إلى إجبار الأمر auto_load التالي على إعادة تحميل قاعدة بيانات الفهرس من القرص.
auto_mkindex dir pattern pattern ...
ينشئ فهرسًا مناسبًا للاستخدام بواسطة auto_load. يبحث الأمر في dir عن جميع الملفات التي تتطابق أسماؤها مع أي من وسائط pattern (تتم المطابقة باستخدام أمر glob)، وينشئ فهرسًا لجميع إجراءات أوامر Tcl المعرفة في جميع الملفات المتطابقة، ويخزن معلومات الفهرس في ملف يسمى tclIndex في dir. إذا لم يتم إعطاء نمط، فسيتم افتراض نمط *.tcl. على سبيل المثال، الأمر
auto_mkindex foo *.tcl

سيقرأ جميع ملفات .tcl في الدليل الفرعي foo وينشئ ملف فهرس جديد foo/tclIndex.

يقوم auto_mkindex بتحليل نصوص Tcl البرمجية عن طريق استدعائها في مفسر فرعي ومراقبة أوامر proc و namespace التي يتم تنفيذها. يمكن للإضافات استخدام حزمة auto_mkindex_parser (غير موثقة) لتسجيل أوامر أخرى يمكن أن تساهم في فهرس التحميل التلقائي. سيتعين عليك قراءة auto.tcl لمعرفة كيفية عمل هذا.

يقوم auto_mkindex_old (والذي له نفس بناء الجملة مثل auto_mkindex) بتحليل نصوص Tcl البرمجية بطريقة غير متطورة نسبيًا: إذا احتوى أي سطر على الكلمة “proc” كأحرفها الأولى، فسيتم اعتباره تعريف إجراء وسيتم أخذ الكلمة التالية في السطر كاسم الإجراء. تعريفات الإجراءات التي لا تظهر بهذه الطريقة (على سبيل المثال، تحتوي على مسافات قبل proc) لن يتم فهرستها. إذا كان النص البرمجي الخاص بك يحتوي على تعليمات برمجية “خطيرة”، مثل كود التهيئة العام أو أسماء الإجراءات ذات الأحرف الخاصة مثل $، *، [ أو ]، فأنت أكثر أمانًا باستخدام auto_mkindex_old.

auto_reset
يدمر جميع المعلومات المخزنة مؤقتًا بواسطة auto_execok و auto_load. سيتم إعادة قراءة هذه المعلومات من القرص في المرة التالية التي تكون فيها مطلوبة. يقوم auto_reset أيضًا بحذف أي إجراءات مدرجة في فهرس التحميل التلقائي، بحيث سيتم تحميل نسخ جديدة منها في المرة التالية التي يتم استخدامها فيها.
auto_qualify command namespace
يحسب قائمة بالأسماء المؤهلة بالكامل لـ command. تعكس هذه القائمة المسار الذي يتبعه مفسر Tcl القياسي للبحث عن الأوامر: أولاً يبحث عن الأمر في مساحة الاسم الحالية، ثم في مساحة الاسم العامة. وفقًا لذلك، إذا كان command نسبيًا و namespace ليس ::، فإن القائمة المرجعة تحتوي على عنصرين: command مقيد بـ namespace، كما لو كان أمرًا في مساحة الاسم namespace؛ و command كما لو كان أمرًا في مساحة الاسم العامة. بخلاف ذلك، إذا كان command مطلقًا (يبدأ بـ ::)، أو إذا كان namespace هو ::، فإن القائمة تحتوي فقط على command كما لو كان أمرًا في مساحة الاسم العامة.

يتم استخدام auto_qualify بواسطة مرافق التحميل التلقائي في Tcl، سواء لإنتاج فهارس التحميل التلقائي مثل pkgIndex.tcl، أو لتنفيذ التحميل التلقائي الفعلي للوظائف في وقت التشغيل.

NAME

tcl_findLibrary — procedure to search for Tcl library files

SYNOPSIS

tcl_findLibrary initScript varName enVarName ?basenameversion?

INTRODUCTION

This is a standard search procedure for use by extensions during their initialization. They call this procedure to look for their script library in several standard directories. The last component of the name of the library directory is normally basenameversion (e.g., tk8.0), but it might be “library” when in the build hierarchies. The initScript file will be sourced into the interpreter once it is found. The directory in which this file is found is stored into the global variable varName. If this variable is already defined (e.g. by C code during application initialization) then no searching is done. Otherwise the search looks in these directories: the directory named by the environment variable enVarName; relative to the Tcl library directory; relative to the executable file in the standard installation bin or bin/arch directory; relative to the executable file in the current build tree; relative to the executable file in a parallel build tree.

COMMAND PROCEDURES

parray arrayName ?pattern?
Prints on standard output the names and values of all the elements in the array arrayName, or just the names that match pattern (using the matching rules of string match) and their values if pattern is given. ArrayName must be an array accessible to the caller of parray. It may be either local or global.

WORD BOUNDARY HELPERS

These procedures are mainly used internally by Tk.

tcl_endOfWord str start
Returns the index of the first end-of-word location that occurs after a starting index start in the string str. An end-of-word location is defined to be the first non-word character following the first word character after the starting point. Returns -1 if there are no more end-of-word locations after the starting point. See the description of tcl_wordchars and tcl_nonwordchars below for more details on how Tcl determines which characters are word characters.
tcl_startOfNextWord str start
Returns the index of the first start-of-word location that occurs after a starting index start in the string str. A start-of-word location is defined to be the first word character following a non-word character. Returns -1 if there are no more start-of-word locations after the starting point.
tcl_startOfPreviousWord str start
Returns the index of the first start-of-word location that occurs before a starting index start in the string str. Returns -1 if there are no more start-of-word locations before the starting point.
tcl_wordBreakAfter str start
Returns the index of the first word boundary after the starting index start in the string str. Returns -1 if there are no more boundaries after the starting point in the given string. The index returned refers to the second character of the pair that comprises a boundary.
tcl_wordBreakBefore str start
Returns the index of the first word boundary before the starting index start in the string str. Returns -1 if there are no more boundaries before the starting point in the given string. The index returned refers to the second character of the pair that comprises a boundary.

VARIABLES

The following global variables are defined or used by the procedures in the Tcl library. They fall into two broad classes, handling unknown commands and packages, and determining what are words.

AUTOLOADING AND PACKAGE MANAGEMENT VARIABLES

auto_execs
Used by auto_execok to record information about whether particular commands exist as executable files.
auto_index
Used by auto_load to save the index information read from disk.
auto_noexec
If set to any value, then unknown will not attempt to auto-exec any commands.
auto_noload
If set to any value, then unknown will not attempt to auto-load any commands.
auto_path
If set, then it must contain a valid Tcl list giving directories to search during auto-load operations (including for package index files when using the default package unknown handler). This variable is initialized during startup to contain, in order: the directories listed in the TCLLIBPATH environment variable, the directory named by the tcl_library global variable, the parent directory of tcl_library, the directories listed in the tcl_pkgPath variable. Additional locations to look for files and package indices should normally be added to this variable using lappend.
env(TCL_LIBRARY)
If set, then it specifies the location of the directory containing library scripts (the value of this variable will be assigned to the tcl_library variable and therefore returned by the command info library). If this variable is not set then a default value is used.
env(TCLLIBPATH)
If set, then it must contain a valid Tcl list giving directories to search during auto-load operations. Directories must be specified in Tcl format, using “/” as the path separator, regardless of platform. This variable is only used when initializing the auto_path variable.

WORD BOUNDARY DETERMINATION VARIABLES

These variables are only used in the tcl_endOfWord, tcl_startOfNextWord, tcl_startOfPreviousWord, tcl_wordBreakAfter, and tcl_wordBreakBefore commands.

tcl_nonwordchars
This variable contains a regular expression that is used by routines like tcl_endOfWord to identify whether a character is part of a word or not. If the pattern matches a character, the character is considered to be a non-word character. On Windows platforms, spaces, tabs, and newlines are considered non-word characters. Under Unix, everything but numbers, letters and underscores are considered non-word characters.
tcl_wordchars
This variable contains a regular expression that is used by routines like tcl_endOfWord to identify whether a character is part of a word or not. If the pattern matches a character, the character is considered to be a word character. On Windows platforms, words are comprised of any character that is not a space, tab, or newline. Under Unix, words are comprised of numbers, letters or underscores.
