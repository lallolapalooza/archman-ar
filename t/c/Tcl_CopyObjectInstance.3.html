الوصف

الكائنات هي كيانات ذات أنواع لها مجموعة من العمليات ("الأساليب") المرتبطة بها. الفئات هي كائنات يمكنها تصنيع كائنات. يمكن النظر إلى كل فئة ككائن بحد ذاته؛ يمكن استرجاع عرض الكائن باستخدام Tcl_GetClassAsObject الذي يعيد دائمًا الكائن عند تطبيقه على فئة غير مدمرة، ويمكن النظر إلى كائن كفئة بمساعدة Tcl_GetObjectAsClass (الذي يعيد الفئة، أو NULL إذا لم يكن الكائن فئة). يمكن البحث عن كائن باستخدام وظيفة Tcl_GetObjectFromObj، التي تعيد كائنًا أو NULL (مع رسالة خطأ في نتيجة المترجم) إذا تعذر العثور على الكائن. الطريقة الصحيحة للبحث عن فئة بالاسم هي البحث عن الكائن بهذا الاسم، ثم استخدام Tcl_GetObjectAsClass.

كل كائن له أمر ومساحة اسم خاصة به مرتبطة به. يمكن استرجاع الأمر باستخدام وظيفة Tcl_GetObjectCommand، اسم الكائن (وبالتالي اسم الأمر) باستخدام Tcl_GetObjectName، ويمكن استرجاع مساحة الاسم باستخدام وظيفة Tcl_GetObjectNamespace. لاحظ أن مرجع Tcl_Obj الذي تم إرجاعه بواسطة Tcl_GetObjectName هو مرجع مشترك. يمكنك أيضًا الحصول على ما إذا كان الكائن قد تم تمييزه للحذف باستخدام Tcl_ObjectDeleted (يعيد صحيحًا إذا بدأ حذف الكائن)؛ يمكن أن يكون هذا مفيدًا أثناء معالجة الأساليب.

يتم إنشاء مثيلات الفئات باستخدام Tcl_NewObjectInstance، التي تنشئ كائنًا من أي فئة (والتي يتم استدعاؤها داخليًا بواسطة كلا الأسلوبين create و new للفئة oo::class). تأخذ معاملات تسمح اختياريًا باسم الكائن ومساحة الاسم المراد إنشاؤهما، والتي تصف الوسائط التي سيتم تمريرها إلى المنشئ (constructor) الخاص بالفئة (إن وجد). ستكون نتيجة الوظيفة إما مرجعًا للكائن الذي تم إنشاؤه حديثًا، أو NULL إذا فشل الإنشاء (عندما تترك رسالة خطأ في نتيجة المترجم). بالإضافة إلى ذلك، يمكن نسخ الكائنات باستخدام Tcl_CopyObjectInstance التي تنشئ نسخة من كائن دون تشغيل أي منشئات.

لاحظ أن إدارة دورة حياة الكائنات تتم داخليًا ضمن TclOO، ولا تستخدم Tcl_Preserve. *ليس من الآمن وضع مقبض* *Tcl_Object* *في هيكل C بعمر مختلف عن عمر الكائن؛* يجب عليك استخدام اسم أمر الكائن (كما تم استرجاعه باستخدام Tcl_GetObjectName) بدلاً من ذلك. من الآمن استخدام مقبض Tcl_Object لمدة مكالمة أسلوب على هذا الكائن؛ لا تصبح المقابض غير صالحة طالما أن هناك مكالمة مستحقة على الكائن الخاص بهم (حتى لو كانت العملية الوحيدة المضمونة بأنها آمنة عليها هي Tcl_ObjectDeleted؛ العمليات الأخرى مضمونة فقط للعمل على الكائنات غير المدمرة).

بيانات وصفية للكائنات والفئات

قد يكون لكل كائن وكل فئة كميات عشوائية من البيانات الوصفية الملحقة بها، والتي لا ينسب إليها الكائن أو الفئة أي معنى أبعد مما هو موصوف في مثيل بنية Tcl_ObjectMetadataType. يتم وصف البيانات الوصفية المراد إرفاقها بنوع البيانات الوصفية (المعطاة في المعامل metaTypePtr) ومؤشر عشوائي (المعامل metadata) التي يتم تمريرها إلى Tcl_ObjectSetMetadata و Tcl_ClassSetMetadata، ويمكن استرجاع قطعة معينة من البيانات الوصفية معطاة نوعها باستخدام Tcl_ObjectGetMetadata و Tcl_ClassGetMetadata. إذا كان المعامل metadata لكل من Tcl_ObjectSetMetadata أو Tcl_ClassSetMetadata هو NULL، فسيتم إزالة البيانات الوصفية إذا كانت ملحقة، وستكون نتائج Tcl_ObjectGetMetadata و Tcl_ClassGetMetadata هي NULL إذا لم تكن البيانات الوصفية من النوع المعطى ملحقة. ليس خطأً طلب أو إزالة قطعة من البيانات الوصفية لم تكن ملحقة.

بنية TCL_OBJECTMETADATATYPE

محتويات بنية Tcl_ObjectMetadataType هي كما يلي:

typedef const struct {
    int version;
    const char *name;
    Tcl_ObjectMetadataDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_ObjectMetadataType;

المجال version يسمح بالتوسع المستقبلي للبنية، ويجب دائمًا تعريفه مساويًا لـ TCL_OO_METADATA_VERSION_CURRENT. يوفر المجال name اسمًا يمكن قراءته من قبل الإنسان للنوع، وهو محجوز لتصحيح الأخطاء.

المجال deleteProc يعطي دالة من النوع Tcl_ObjectMetadataDeleteProc التي تستخدم لحذف قطعة معينة من البيانات الوصفية، ويتم استدعاؤها عند استبدال البيانات الوصفية الملحقة أو إزالتها؛ يجب ألا يكون المجال NULL.

المجال cloneProc يعطي دالة تستخدم لنسخ قطعة من البيانات الوصفية (تستخدم عند إنشاء نسخة من كائن باستخدام Tcl_CopyObjectInstance)؛ إذا كانت NULL، فسيتم نسخ البيانات الوصفية مباشرة.

توقيع دالة TCL_OBJECTMETADATADELETEPROC

تستخدم الدوال التي تطابق هذا التوقيع لحذف البيانات الوصفية المرتبطة بفئة أو كائن.

typedef void Tcl_ObjectMetadataDeleteProc(ClientData clientData);

توقيع دالة TCL_CLONEPROC

تستخدم الدوال التي تطابق هذا التوقيع لنسخ البيانات الوصفية المرتبطة بفئة أو كائن.

typedef ClientData Tcl_CloneProc(ClientData clientData);

NAME

Tcl_CopyObjectInstance — Copy an object instance

SYNOPSIS

#include <tclOO.h>

int
Tcl_CopyObjectInstance(
        Tcl_Interp *interp,
        Tcl_Object src,
        Tcl_Object *dstPtr);

ARGUMENTS

Tcl_Interp *interp
Interpreter to use for error reporting.
Tcl_Object src
The object instance to copy.
Tcl_Object *dstPtr
Pointer to where the new object instance should be stored.

DESCRIPTION

The Tcl_CopyObjectInstance function makes a copy of the object instance referred to by src. The copy is made by first invoking the object's copy method, if it has one, and then invoking the copy method of its class. The result of the copy operation, if successful, is stored in the location referred to by dstPtr. If the copy fails for any reason, an error message is written to the interpreter's result, and TCL_ERROR is returned.

If the object instance src has no associated metadata, or if its metadata has no copy procedure registered, then the class hierarchy is searched for a class that does have a copy procedure registered. If found, that copy procedure is invoked. If no copy procedure is found anywhere in the hierarchy, the object is copied by value (meaning that only the object's instance data is copied, not any shared state).

The result of this function is TCL_OK on success, and TCL_ERROR on failure.

OBJECT AND CLASS METADATA

Objects and classes can have arbitrary C data associated with them, called metadata. This metadata is managed through a set of callback procedures that are registered with the object or class. These callbacks allow for custom initialization, deletion, and copying of the metadata.

TCL_OBJECTMETADATACREATEPROC FUNCTION SIGNATURE

Functions matching this signature are used to create new metadata associated with an object or class.

typedef int Tcl_ObjectCreateProc(
        Tcl_Interp *interp,
        ClientData instanceData,
        ClientData *metadataPtr);

The interp argument gives a place to write an error message if the creation fails. The instanceData argument gives the object or class data that the new metadata is to be associated with. The new metadata should be written into the location pointed to by metadataPtr. The procedure should return TCL_OK on success, and TCL_ERROR on failure.

TCL_OBJECTMETADATADELETEPROC FUNCTION SIGNATURE

Functions matching this signature are used to destroy metadata associated with an object or class.

typedef void Tcl_ObjectDeleteProc(
        ClientData metadata);

The metadata argument gives the address of the metadata to be deleted.

TCL_CLONEPROC FUNCTION SIGNATURE

Functions matching this signature are used to create copies of metadata associated with a class or object.

typedef int Tcl_CloneProc(
        Tcl_Interp *interp,
        ClientData srcMetadata,
        ClientData *dstMetadataPtr);

The interp argument gives a place to write an error message when the attempt to clone the object is to fail, in which case the clone procedure must also return TCL_ERROR; it should return TCL_OK otherwise. The srcMetadata argument gives the address of the metadata to be cloned, and the cloned metadata should be written into the variable pointed to by dstMetadataPtr; a NULL should be written if the metadata is to not be cloned but the overall object copy operation is still to succeed.

OBJECT METHOD NAME MAPPING

It is possible to control, on a per-object basis, what methods are invoked when a particular method is invoked. Normally this is done by looking up the method name in the object and then in the class hierarchy, but fine control of exactly what the value used to perform the look up is afforded through the ability to set a method name mapper callback via Tcl_ObjectSetMethodNameMapper (and its introspection counterpart, Tcl_ObjectGetMethodNameMapper, which returns the current mapper). The current mapper (if any) is invoked immediately before looking up what chain of method implementations is to be used.

TCL_OBJECTMAPMETHODNAMEPROC FUNCTION SIGNATURE

The Tcl_ObjectMapMethodNameProc callback is defined as follows:

typedef int Tcl_ObjectMapMethodNameProc(
        Tcl_Interp *interp,
        Tcl_Object object,
        Tcl_Class *startClsPtr,
        Tcl_Obj *methodNameObj);

If the result is TCL_OK, the remapping is assumed to have been done. If the result is TCL_ERROR, an error message will have been left in interp and the method call will fail. If the result is TCL_BREAK, the standard method name lookup rules will be used; the behavior of other result codes is currently undefined. The object parameter says which object is being processed. The startClsPtr parameter points to a variable that contains the first class to provide a definition in the method chain to process, or NULL if the whole chain is to be processed (the argument itself is never NULL); this variable may be updated by the callback. The methodNameObj parameter gives an unshared object containing the name of the method being invoked, as provided by the user; this object may be updated by the callback.
