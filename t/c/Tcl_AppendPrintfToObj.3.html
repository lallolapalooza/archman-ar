الوصف

تسمح الإجراءات الموضحة في إدخال الدليل هذا بمعالجة قيم Tcl كسلاسل نصية. تستخدم التمثيل الداخلي للقيمة لتخزين معلومات إضافية لجعل عمليات السلسلة النصية أكثر كفاءة. على وجه الخصوص، فإنها تجعل سلسلة من عمليات الإلحاق فعالة عن طريق تخصيص مساحة تخزين إضافية للسلسلة النصية بحيث لا تحتاج إلى نسخها لكل عملية إلحاق. أيضًا، يتم تحسين عمليات الفهرسة وحسابات الطول لأن تمثيل سلسلة Unicode يتم حسابه وتخزينه مؤقتًا حسب الحاجة. عند استخدام عائلة إجراءات Tcl_Append* حيث تكون نتيجة المفسر هي القيمة التي يتم إلحاقها، من المهم استدعاء Tcl_ResetResult أولاً للتأكد من أنك لا تلحق عن غير قصد بالبيانات الموجودة في قيمة النتيجة.

Tcl_NewStringObj و Tcl_SetStringObj تنشئ قيمة جديدة أو تعدل قيمة موجودة لاحتواء نسخة من السلسلة النصية المعطاة بواسطة bytes و length. Tcl_NewUnicodeObj و Tcl_SetUnicodeObj تنشئ قيمة جديدة أو تعدل قيمة موجودة لاحتواء نسخة من سلسلة Unicode المعطاة بواسطة unicode و numChars. Tcl_NewStringObj و Tcl_NewUnicodeObj ترجع مؤشرًا إلى قيمة تم إنشاؤها حديثًا بعدد مراجع صفر. جميع الإجراءات الأربعة تعين القيمة لاحتواء نسخة من السلسلة النصية المحددة. Tcl_SetStringObj و Tcl_SetUnicodeObj تحرران أي تمثيل سلسلة نصية قديم وكذلك أي تمثيل داخلي قديم للقيمة.

Tcl_GetStringFromObj و Tcl_GetString ترجع التمثيل النصي للقيمة. يتم توفير هذا بواسطة مؤشر البايت المرجع و (لـ Tcl_GetStringFromObj) الطول، والذي يتم تخزينه في lengthPtr إذا لم يكن NULL. إذا كان تمثيل سلسلة UTF للقيمة غير صالح (مؤشر البايت الخاص به NULL)، فسيتم إعادة إنشاء التمثيل النصي من التمثيل الداخلي للقيمة. التخزين المشار إليه بواسطة مؤشر البايت المرجع مملوك لمدير القيمة. يتم تمريره كمؤشر قابل للكتابة حتى يتمكن مؤلف الملحق الذي ينشئ Tcl_ObjType الخاص به من تعديل التمثيل النصي داخل Tcl_UpdateStringProc الخاص بـ Tcl_ObjType الخاص به. باستثناء هذا الغرض المحدود، يجب التعامل مع المؤشر الذي تم إرجاعه بواسطة Tcl_GetStringFromObj أو Tcl_GetString على أنه للقراءة فقط. يوصى بتعيين هذا المؤشر لمتغير (const char *). حتى في الحالات المحدودة حيث يكون الكتابة إلى هذا المؤشر مقبولة، يجب توخي الحذر لاحترام دلالات النسخ عند الكتابة المطلوبة بواسطة Tcl_Obj، مع استدعاءات مناسبة لـ Tcl_IsShared و Tcl_DuplicateObj قبل أي تعديل في المكان للتمثيل النصي. يتم استخدام الإجراء Tcl_GetString في الحالة الشائعة حيث لا يحتاج المستدعي إلى طول التمثيل النصي.

Tcl_GetUnicodeFromObj و Tcl_GetUnicode ترجع القيمة كـ سلسلة Unicode. يتم توفير هذا بواسطة المؤشر المرجع و (لـ Tcl_GetUnicodeFromObj) الطول، والذي يتم تخزينه في lengthPtr إذا لم يكن NULL. التخزين المشار إليه بواسطة مؤشر البايت المرجع مملوك لمدير القيمة ويجب ألا يعدله المستدعي. يتم استخدام الإجراء Tcl_GetUnicode في الحالة الشائعة حيث لا يحتاج المستدعي إلى طول تمثيل سلسلة Unicode.

Tcl_GetUniChar ترجع الحرف ذو الفهرس index في تمثيل Unicode للقيمة. يفترض أن الفهرس ضمن النطاق المناسب.

Tcl_GetRange ترجع قيمة تم إنشاؤها حديثًا تتكون من الأحرف بين first و last (شاملة) في تمثيل Unicode للقيمة. إذا كان تمثيل Unicode للقيمة غير صالح، فسيتم إعادة إنشاء تمثيل Unicode من التمثيل النصي للقيمة. إذا كان first < 0، فستبدأ السلسلة النصية المرجعة من بداية القيمة. إذا كان last < 0، فستنتهي السلسلة النصية المرجعة في نهاية القيمة.

DESCRIPTION

These functions manipulate the string representation of Tcl objects. Many of these functions are designed to be efficient, reducing the number of memory allocations and copies required when building up string values.

Tcl_SetObjLength changes the length of the string value of its objPtr argument. If newLength is greater than the current string length, the string space is reallocated to accommodate the new length. The bytes between the old length and the new length are uninitialized. If newLength is less than the current string length, the string length is truncated. In all cases, a null character is stored at index newLength. The length returned by Tcl_ObjLength(3) reflects the value of newLength.

Tcl_AttemptSetObjLength is identical to Tcl_SetObjLength except that it will not cause the Tcl interpreter to panic if memory allocation fails. Instead, it returns 0 to indicate failure and leaves the object unchanged. If memory allocation succeeds, it returns 1.

Tcl_AppendToObj appends the bytes given by bytes and length to the string representation of the value specified by objPtr. If the object does not have a valid string representation, it attempts to convert bytes to Unicode. If successful, the converted Unicode is appended. Otherwise, the object's Unicode representation is invalidated, converted to UTF, and bytes is appended to the new string representation. Memory is reallocated as needed, with large allocations made to optimize multiple calls.

Tcl_AppendUnicodeToObj appends the Unicode string given by unicode and numChars to the value specified by objPtr. If the value does not have a valid Unicode representation, unicode is converted to UTF and appended to the string representation. Appends are optimized to avoid repeated reallocations by over-allocating space.

Tcl_AppendObjToObj appends the string or Unicode value (whichever exists and is best suited) of appendObjPtr to objPtr.

Tcl_AppendStringsToObj is similar to Tcl_AppendToObj but accepts multiple null-terminated strings. The last argument must be (char *)NULL.

Tcl_AppendStringsToObjVA is the same as Tcl_AppendStringsToObj but takes a va_list argument.

Tcl_AppendLimitedToObj appends at most limit bytes from bytes to objPtr. If the limit prevents all length bytes from being appended, the string ellipsis (or "..." if NULL) is appended instead of the truncated portion. This is useful for constructing bounded strings like error messages. If length is -1, bytes are appended up to the first null byte, subject to the limit. Appending may be adjusted to ensure only whole multi-byte characters are appended.

Tcl_Format is the C-level interface to the Tcl format command. It formats the objects in objv according to the format string and returns a new Tcl_Obj containing the result. If an error occurs, it returns NULL and sets an error message in interp (if not NULL).

Tcl_AppendFormatToObj is an appending version of Tcl_Format. It formats the objects and appends the result to objPtr.

Tcl_ObjPrintf provides a safe alternative to sprintf. It formats arguments according to format and returns a new Tcl_Obj containing the result. It handles buffer allocation automatically. The formatting engine is similar to that of Tcl's format command, but precision specifiers are interpreted as byte counts, like in sprintf. It does not support C99 format specifiers like "hh", "ll", etc. Mismatches between the format string and arguments can lead to runtime errors or be caught by compilers.

Tcl_AppendPrintfToObj is an appending version of Tcl_ObjPrintf. It formats arguments and appends the result to objPtr.

Tcl_ConcatObj returns a new Tcl_Obj whose value is the space-separated concatenation of the string representations of the objects in objv. Leading and trailing whitespace is removed from each object's string representation before concatenation. Objects containing only whitespace are ignored.
