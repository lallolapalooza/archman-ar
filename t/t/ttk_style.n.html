ttk_style(n)

الحزمة: tk

التراخيص: TCL

ttk::style(n) Tk Widget ذو السمات ttk::style(n)

الاسم

ttk::style - التعامل مع قاعدة بيانات الأنماط

ملخص

ttk::style option ?args?

ملاحظات

انظر أيضًا عرض مؤتمر Tcl'2004، متاح على https://tktable.sourceforge.net/tile/tile-tcl2004.pdf

تعريفات

يتم تعيين نمط لكل عنصر واجهة مستخدم، والذي يحدد مجموعة العناصر التي تتكون منها واجهة المستخدم وكيفية ترتيبها، بالإضافة إلى الإعدادات الديناميكية والافتراضية لخيارات العناصر. بشكل افتراضي، اسم النمط هو نفس اسم فئة عنصر واجهة المستخدم؛ يمكن تجاوز هذا بواسطة الخيار -style.

سمة (theme) هي مجموعة من العناصر والأنماط التي تتحكم في المظهر العام للتطبيق.

الوصف

يقبل الأمر ttk::style الوسائط التالية:

ttk::style configure style ?-option ?value option value...? ?
يضبط القيمة الافتراضية للخيارات المحددة في style.
ttk::style element args
ttk::style element create elementName type ?args...?
ينشئ عنصرًا جديدًا في السمة الحالية من النوع type. نوع العنصر المدمج الوحيد الذي يعمل عبر الأنظمة الأساسية هو image (انظر ttk_image(n)) ولكن السمات قد تعرف أنواع عناصر أخرى (انظر Ttk_RegisterElementFactory). على الإصدارات المناسبة من Windows، يتم تسجيل مصنع عناصر لإنشاء عناصر سمة Windows (انظر ttk_vsapi(n)).
ttk::style element names
يعيد قائمة بالعناصر المعرفة في السمة الحالية.
ttk::style element options element
يعيد قائمة بخيارات element.
ttk::style layout style ?layoutSpec?
يحدد تخطيط عنصر واجهة المستخدم للنمط style. انظر LAYOUTS أدناه لتنسيق layoutSpec. إذا تم حذف layoutSpec، يعيد مواصفات التخطيط للنمط style.
ttk::style lookup style -option ?state ?default??
يعيد القيمة المحددة للخيار -option في النمط style في الحالة state، باستخدام قواعد البحث القياسية لخيارات العناصر. state هي قائمة بأسماء الحالات؛ إذا تم حذفها، فإنها تكون افتراضية لجميع الحالات (حالة "عادية"). إذا كان الوسيط default موجودًا، فسيتم استخدامه كقيمة احتياطية في حالة عدم العثور على مواصفات للخيار -option.
ttk::style map style ?-option { statespec value... }?
يضبط القيم الديناميكية للخيارات المحددة في style. يتم فحص كل زوج statespec / value بالترتيب؛ يتم استخدام القيمة المقابلة لأول statespec مطابق.
ttk::style theme args
ttk::style theme create themeName ?-parent basedon? ?-settings script... ?
ينشئ سمة جديدة. يعد خطأ إذا كانت themeName موجودة بالفعل. إذا تم تحديد -parent، فإن السمة الجديدة سترث الأنماط والعناصر والتخطيطات من السمة الأم basedon. إذا كان -settings موجودًا، فسيتم تقييم script في سياق السمة الجديدة كما في ttk::style theme settings.
ttk::style theme names
يعيد قائمة بجميع السمات المعروفة.
ttk::style theme settings themeName script
يضبط مؤقتًا السمة الحالية على themeName، ويقوم بتقييم script، ثم يستعيد السمة السابقة. عادةً ما يقوم script بتعريف الأنماط والعناصر ببساطة، على الرغم من أنه يمكن أن يحتوي على تعليمات Tcl عشوائية.
ttk::style theme use ?themeName?
بدون وسيط، تكون النتيجة اسم السمة الحالية. بخلاف ذلك، يقوم هذا الأمر بتعيين السمة الحالية إلى themeName، ويعيد تهيئة جميع عناصر واجهة المستخدم.

التخطيطات (LAYOUTS)

التخطيط يحدد قائمة بالعناصر، يتبعها خيار واحد أو أكثر يحدد كيفية ترتيب العنصر. تستخدم آلية التخطيط نسخة مبسطة من مدير هندسة pack: نظرًا لتجويف أولي، يتم تعيين جزء لكل عنصر. ثم يتم تعديل الجزء المستخدم فعليًا بواسطة العنصر داخل الجزء المخصص. الخيارات الصالحة هي:

-children { sublayout... }
يحدد قائمة بالعناصر لوضعها داخل العنصر.
-expand boolean
يحدد ما إذا كان الجزء المخصص هو التجويف بأكمله. إذا كان الأمر كذلك، يتم تجاهل التحديد المتزامن لـ -side. الافتراضي هو 0.
-side side
يحدد الجانب الذي يجب وضع العنصر فيه من التجويف؛ أحد الخيارات: left، right، top، أو bottom. على سبيل المثال، -side top يخصص الجزء على طول الجزء العلوي من التجويف بعرض وارتفاع على التوالي بعرض التجويف وارتفاع العنصر. إذا تم حذفه، فإن الجزء المخصص هو التجويف بأكمله (نفس تأثير -expand 1).
-sticky [nswe]
يحدد الموضع والحجم الفعليين للجزء داخل الجزء المخصص. إذا تم تحديده كسلسلة فارغة، يتم توسيط الجزء الفعلي في الجزء المخصص. الافتراضي هو nswe.

على سبيل المثال:

ttk::style layout Horizontal.TScrollbar {
    Scrollbar.trough -children {
        Scrollbar.leftarrow -side left
        Scrollbar.rightarrow -side right
        Horizontal.Scrollbar.thumb -side left -sticky ew
    }
}
