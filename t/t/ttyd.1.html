ttyd(1)

الحزمة: ttyd

التراخيص: MIT

ttyd(1) دليل المستخدم ttyd(1)

الاسم

ttyd - مشاركة طرفيتك عبر الويب

ملخص

ttyd [خيارات] <أمر> [<وسيطات...>]

الوصف

ttyd هي أداة سطر أوامر لمشاركة الطرفية عبر الويب تعمل على أنظمة *nix وويندوز، مع الميزات التالية:

  • مبنية فوق Libwebsockets مع libuv للسرعة
  • طرفية كاملة الميزات تعتمد على Xterm.js مع دعم CJK (الصينية واليابانية والكورية) ودعم IME
  • تكامل ZMODEM الرسومي مع دعم lrzsz
  • دعم إخراج صور Sixel
  • دعم SSL يعتمد على OpenSSL
  • تشغيل أي أمر مخصص مع خيارات
  • دعم المصادقة الأساسية والعديد من الخيارات المخصصة الأخرى
  • متعدد المنصات: macOS، Linux، FreeBSD/OpenBSD، OpenWrt/LEDE، Windows

الخيارات

-p, --port
المنفذ للاستماع (الافتراضي: 7681، استخدم 0 لمنفذ عشوائي)

-i, --interface
واجهة الشبكة للربط (مثل: eth0)، أو مسار مقبس مجال UNIX (مثل: /var/run/ttyd.sock)

-U, --socket-owner
مالك المستخدم لملف مقبس مجال UNIX، عند تمكينه (مثل: user:group)

-c, --credential USER[:PASSWORD]
بيانات الاعتماد للمصادقة الأساسية (التنسيق: اسم المستخدم: كلمة المرور)

-H, --auth-header
اسم رأس HTTP لوكيل المصادقة، سيؤدي هذا إلى تكوين ttyd للسماح لوكيل عكسي HTTP بمعالجة المصادقة

-u, --uid
معرف المستخدم للتشغيل به

-g, --gid
معرف المجموعة للتشغيل بها

-s, --signal
الإشارة لإرسالها إلى الأمر عند الخروج منه (الافتراضي: 1، SIGHUP)

-w, --cwd
دليل العمل ليتم تعيينه للبرنامج التابع

-a, --url-arg
السماح للعميل بإرسال وسيطات سطر الأوامر في عنوان URL (مثل: http://localhost:7681?arg=foo&arg=bar)

-W, --writable
السماح للعملاء بالكتابة إلى TTY (للقراءة فقط افتراضيًا)

-t, --client-option
إرسال خيار إلى العميل (التنسيق: key=value)، كرر لإضافة المزيد من الخيارات، انظر خيارات العميل للتفاصيل

-T, --terminal-type
نوع الطرفية للإبلاغ عنه، الافتراضي: xterm-256color

-O, --check-origin
عدم السماح باتصال websocket من أصل مختلف

-m, --max-clients
الحد الأقصى للعملاء المدعومين (الافتراضي: 0، بدون حد)

-o, --once
قبول عميل واحد فقط والخروج عند قطع الاتصال

-q, --exit-no-conn
الخروج عند قطع اتصال جميع العملاء

-B, --browser
فتح الطرفية باستخدام المتصفح الافتراضي للنظام

-I, --index
مسار مخصص لـ index.html

-b, --base-path
المسار الأساسي المتوقع للطلبات الواردة من وكيل عكسي (مثل: /mounted/here، الحد الأقصى للطول: 128)

-P, --ping-interval
فاصل زمني لوقت استجابة websocket (بالثواني) (الافتراضي: 5)

-6, --ipv6
تمكين دعم IPv6

-S, --ssl
تمكين SSL

-C, --ssl-cert
مسار ملف شهادة SSL

-K, --ssl-key
مسار مفتاح SSL

-A, --ssl-ca
مسار ملف CA SSL للتحقق من شهادة العميل

-d, --debug
تعيين مستوى السجل (الافتراضي: 7)

-v, --version
طباعة الإصدار والخروج

-h, --help
طباعة هذا النص والخروج

خيارات العميل

يحتوي ttyd على آلية لتمرير وسيطات سطر الأوامر من جانب الخادم إلى صفحة المتصفح، والتي تسمى **خيارات العميل**:

-t, --client-option     إرسال خيار إلى العميل (التنسيق: key=value)، كرر لإضافة المزيد من الخيارات

الاستخدام الأساسي

  • -t rendererType=canvas: استخدام العارض **canvas** لـ xterm.js (الافتراضي: **webgl**)
  • -t disableLeaveAlert=true: تعطيل تنبيه مغادرة الصفحة
  • -t disableResizeOverlay=true: تعطيل تراكب تغيير حجم الطرفية
  • -t disableReconnect=true: منع الطرفية من إعادة الاتصال عند خطأ/إغلاق الاتصال
  • -t enableZmodem=true: تمكين دعم نقل الملفات ZMODEM ⟨https://en.wikipedia.org/wiki/ZMODEM⟩ / lrzsz ⟨https://ohse.de/uwe/software/lrzsz.html⟩
  • -t enableTrzsz=true: تمكين دعم نقل الملفات trzsz ⟨https://trzsz.github.io⟩
  • -t enableSixel=true: تمكين دعم إخراج صور Sixel ⟨https://en.wikipedia.org/wiki/Sixel⟩ (الاستخدام ⟨https://saitoha.github.io/libsixel/⟩)
  • -t titleFixed=hello: تعيين عنوان ثابت لنافذة المتصفح
  • -t fontSize=20: تغيير حجم خط الطرفية

الاستخدام المتقدم

يمكنك استخدام خيار العميل لتغيير جميع إعدادات xterm المعرفة في ITerminalOptions ⟨https://xtermjs.org/docs/api/terminal/interfaces/iterminaloptions/⟩، على سبيل المثال:

  • -t cursorStyle=bar: تعيين نمط المؤشر إلى bar
  • -t lineHeight=1.5: تعيين ارتفاع السطر إلى 1.5
  • -t 'theme={"background": "green"}': تعيين لون الخلفية إلى green

لتجربة خيارات المثال أعلاه، قم بتشغيل:

ttyd -t cursorStyle=bar -t lineHeight=1.5 -t 'theme={"background": "green"}' bash

أمثلة

يبدأ ttyd خادم الويب على المنفذ 7681 افتراضيًا، يمكنك استخدام الخيار -p لتغييره، وسيتم بدء الأمر بالوسيطات كخيارات. على سبيل المثال، قم بتشغيل:

ttyd -p 8080 bash -x

ثم افتح http://localhost:8080 باستخدام المتصفح، ستحصل على طرفية bash مع تمكين وضع التصحيح. المزيد من الأمثلة:

  • إذا كنت ترغب في تسجيل الدخول باستخدام حسابات النظام الخاصة بك على متصفح الويب، قم بتشغيل ttyd login.
  • يمكنك حتى تشغيل أمر ليس طرفية مثل vim، جرب: ttyd vim، سيعرض متصفح الويب لك محرر vim.
  • مشاركة عملية واحدة مع عدة عملاء: ttyd tmux new -A -s ttyd vim، قم بتشغيل tmux new -A -s ttyd للاتصال بجلسة tmux من الطرفية.

كيفية استخدام SSL

قم بإنشاء شهادات CA وشهادات خادم/عميل موقعة ذاتيًا:

# شهادة CA (يجب أن يكون FQDN مختلفًا عن الخادم/العميل)
openssl genrsa -out ca.key 2048
openssl req -new -x509 -days 365 -key ca.key -subj "/C=CN/ST=GD/L=SZ/O=Acme, Inc./CN=Acme Root CA" -out ca.crt
# شهادة الخادم (للنطاقات المتعددة، قم بتغيير subjectAltName إلى: DNS:example.com,DNS:www.example.com)
openssl req -newkey rsa:2048 -nodes -keyout server.key -subj "/C=CN/ST=GD/L=SZ/O=Acme, Inc./CN=localhost" -out server.csr
openssl x509 -sha256 -req -extfile <(printf "subjectAltName=DNS:localhost") -days 365 -in server.csr -CA ca.crt -CAkey ca.key -CAcreateserial -out server.crt
# شهادة العميل (قد يكون تنسيق p12/pem مفيدًا لبعض العملاء)
openssl req -newkey rsa:2048 -nodes -keyout client.key -subj "/C=CN/ST=GD/L=SZ/O=Acme, Inc./CN=client" -out client.csr
openssl x509 -req -days 365 -in client.csr -CA ca.crt -CAkey ca.key -CAcreateserial -out client.crt
openssl pkcs12 -export -clcerts -in client.crt -inkey client.key -out client.p12
openssl pkcs12 -in client.p12 -out client.pem -clcerts

ثم ابدأ ttyd:

ttyd --ssl --ssl-cert server.crt --ssl-key server.key --ssl-ca ca.crt bash

قد ترغب في اختبار التحقق من شهادة العميل باستخدام curl(1):

curl --insecure --cert client.p12[:password] -v https://localhost:7681

إذا كنت لا ترغب في تمكين التحقق من شهادة العميل، قم بإزالة الخيار --ssl-ca.

Docker و ttyd

حاويات Docker هي بيئات معزولة أكثر أمانًا، وهذا مفيد لحماية النظام المضيف، يمكنك استخدام ttyd مع docker بهذا الشكل:

  • مشاركة حاوية docker واحدة مع عدة عملاء: docker run -it --rm -p 7681:7681 tsl0922/ttyd.
  • إنشاء حاوية docker جديدة لكل عميل: ttyd docker run -it --rm ubuntu.

Nginx وكيل عكسي

نموذج إعداد لعمل وكيل عكسي لـ ttyd تحت المسار /ttyd:

location ~ ^/ttyd(.*)$ {
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_pass http://127.0.0.1:7681/$1;
}
