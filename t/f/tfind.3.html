الاسم

tsearch، tfind، tdelete، twalk، twalk_r، tdestroy - إدارة شجرة بحث ثنائية

المكتبة

مكتبة C القياسية (libc، -lc)

الملخص

#include <search.h>
typedef enum { preorder, postorder, endorder, leaf } VISIT;
void *tfind(const void *key, void *const *rootp,
            typeof(int (const void *, const void *)) *compar);
void *tsearch(const void *key, void **rootp,
            typeof(int (const void *, const void *)) *compar);
void *tdelete(const void *restrict key, void **restrict rootp,
            typeof(int (const void *, const void *)) *compar);
void twalk(const void *root,
            typeof(void (const void *nodep, VISIT which, int depth))
                *action);
#define _GNU_SOURCE         /* انظر feature_test_macros(7) */
#include <search.h>
void twalk_r(const void *root,
            typeof(void (const void *nodep, VISIT which, void *closure))
                *action,
            void *closure);
void tdestroy(void *root,
            typeof(void (void *nodep)) *free_node);

الوصف

تدير الوظائف tsearch() و tfind() و twalk() و tdelete() شجرة بحث ثنائية. تم تعميمها من الخوارزمية T في Knuth (6.2.2). الحقل الأول في كل عقدة من عقد الشجرة هو مؤشر إلى عنصر البيانات المقابل. (يجب على البرنامج المستدعي تخزين البيانات الفعلية.) يشير compar إلى روتين مقارنة، يأخذ مؤشرات إلى عنصرين. يجب أن يعيد عددًا صحيحًا يكون سالبًا أو صفرًا أو موجبًا، اعتمادًا على ما إذا كان العنصر الأول أصغر من أو يساوي أو أكبر من الثاني.

تبحث tsearch() في الشجرة عن عنصر. يشير key إلى العنصر المراد البحث عنه. يشير rootp إلى متغير يشير إلى جذر الشجرة. إذا كانت الشجرة فارغة، فيجب تعيين المتغير الذي يشير إليه rootp إلى NULL. إذا تم العثور على العنصر في الشجرة، فإن tsearch() تعيد مؤشرًا إلى عقدة الشجرة المقابلة. (بعبارة أخرى، تعيد tsearch() مؤشرًا إلى مؤشر إلى عنصر البيانات.) إذا لم يتم العثور على العنصر، فإن tsearch() تضيفه، وتعيد مؤشرًا إلى عقدة الشجرة المقابلة.

tfind() تشبه tsearch()، باستثناء أنه إذا لم يتم العثور على العنصر، فإن tfind() تعيد NULL.

تحذف tdelete() عنصرًا من الشجرة. حججها هي نفسها كما في tsearch().

تقوم twalk() بإجراء مسح عمقي، من اليسار إلى اليمين، لشجرة ثنائية. يشير root إلى عقدة البداية للمسح. إذا لم تكن هذه العقدة هي الجذر، فسيتم زيارة جزء فقط من الشجرة. تستدعي twalk() الدالة المستخدمة action في كل مرة يتم فيها زيارة عقدة (أي ثلاث مرات لعقدة داخلية، ومرة واحدة لعقدة طرفية). تأخذ action بدورها ثلاثة وسائط. الوسيط الأول هو مؤشر إلى العقدة التي يتم زيارتها. هيكل العقدة غير محدد، ولكن من الممكن تحويل المؤشر إلى مؤشر إلى مؤشر إلى عنصر للوصول إلى العنصر المخزن داخل العقدة. يجب على التطبيق عدم تعديل الهيكل المشار إليه بواسطة هذا الوسيط. الوسيط الثاني هو عدد صحيح يأخذ إحدى القيم preorder أو postorder أو endorder اعتمادًا على ما إذا كانت هذه هي الزيارة الأولى أو الثانية أو الثالثة لعقدة داخلية، أو القيمة leaf إذا كانت هذه هي الزيارة الوحيدة لعقدة طرفية. (تم تعريف هذه الرموز في <search.h>.) الوسيط الثالث هو عمق العقدة؛ عقدة الجذر لها عمق صفر.

(بشكل أكثر شيوعًا، تُعرف preorder و postorder و endorder باسم preorder و inorder و postorder: قبل زيارة الأبناء، وبعد الأول وقبل الثاني، وبعد زيارة الأبناء. وبالتالي، فإن اختيار الاسم postorder مربك إلى حد ما.)

twalk_r() تشبه twalk()، ولكن بدلاً من وسيط depth، يتم تمرير المؤشر closure إلى كل استدعاء لدالة الإجراء الخاصة، دون تغيير. يمكن استخدام هذا المؤشر لتمرير المعلومات إلى ومن الدالة الخاصة بطريقة آمنة للخيوط، دون اللجوء إلى المتغيرات العامة.

تقوم tdestroy() بإزالة الشجرة بأكملها المشار إليها بواسطة root، وتحرير جميع الموارد التي تم تخصيصها بواسطة الدالة tsearch(). بالنسبة للبيانات في كل عقدة من عقد الشجرة، يتم استدعاء الدالة free_node. يتم تمرير مؤشر إلى البيانات كوسيط للدالة. إذا لم تكن هناك حاجة لمثل هذا العمل، فيجب أن يشير free_node إلى دالة لا تفعل شيئًا.

قيمة الإرجاع

تعيد tsearch() مؤشرًا إلى عقدة مطابقة في الشجرة، أو إلى العقدة المضافة حديثًا، أو NULL إذا كانت الذاكرة غير كافية لإضافة العنصر. تعيد tfind() مؤشرًا إلى العقدة، أو NULL إذا لم يتم العثور على تطابق. إذا كانت هناك عناصر متعددة تتطابق مع المفتاح، فإن العنصر الذي يتم إرجاع عقدته غير محدد.

تعيد tdelete() مؤشرًا إلى والد العقدة المحذوفة، أو NULL إذا لم يتم العثور على العنصر. إذا كانت العقدة المحذوفة هي عقدة الجذر، فإن tdelete() تعيد مؤشرًا متدليًا يجب عدم الوصول إليه.

تعيد tsearch() و tfind() و tdelete() أيضًا NULL إذا كان rootp هو NULL عند الدخول.

ملاحظات

تأخذ twalk() مؤشرًا إلى الجذر، بينما تأخذ الوظائف الأخرى مؤشرًا إلى متغير يشير إلى الجذر.

تقوم tdelete() بتحرير الذاكرة المطلوبة للعقدة في الشجرة. المستخدم مسؤول عن تحرير الذاكرة للبيانات المقابلة.

يعتمد البرنامج التجريبي على حقيقة أن twalk() لا يقوم بأي إشارة أخرى إلى عقدة بعد استدعاء الدالة المستخدمة بالوسيط "endorder" أو "leaf". يعمل هذا مع تنفيذ مكتبة GNU، ولكنه ليس في وثائق System V.

NAME

tsearch, tfind, tdelete, twalk, tdestroy - manage a binary search tree

LIBRARY

Standard C Library (libc, -lc)

SYNOPSIS

#include <search.h>
void *tsearch(const void *key, void **rootp, int (compar(const void *, const void *));
void *tfind(const void *key, void *root, int (compar(const void *, const void *));
void *tdelete(const void *key, void **rootp, int (compar(const void *, const void *));
voidtwalk(void *root, void (action(const void *, VISIT, int));
voidtdestroy(void *root, void (free_node(void *));

DESCRIPTION

The functions tsearch, tfind, tdelete, twalk, and tdestroy manipulate binary search trees.

The data structure used for the tree is not described in the header file. It is a pointer to a pointer to a node, where the node itself contains a pointer to the data, and pointers to the left and right children. However, the structure is opaque; you should only manipulate it via the functions described here. The root of the tree is passed as a pointer to a pointer, so that the functions can modify the root pointer if necessary (e.g., when inserting into an empty tree).

The compar function is a comparison function that is used to order the keys in the tree. It takes two pointers to data items, and returns:

  • A negative value if the first item is less than the second.
  • Zero if the items are equal.
  • A positive value if the first item is greater than the second.

tsearch inserts a new node into the tree if the key is not found. It returns a pointer to the node containing the key. If the key was not found and a new node was inserted, the pointer returned will point to the newly inserted node. If the key was found, the pointer returned will point to the existing node. If the tree is empty and memory cannot be allocated for the new node, tsearch returns NULL.

tfind searches the tree for the specified key. It returns a pointer to the node containing the key if found, and NULL otherwise. It does not modify the tree.

tdelete deletes a node from the tree. It returns a pointer to the node containing the key if found and deleted, and NULL otherwise. The node itself is not freed; the caller is responsible for freeing the memory associated with the deleted node.

twalk traverses the tree in preorder, postorder, or endorder. The action function is called for each node in the tree. The action function receives a pointer to a pointer to the node's data, a VISIT code indicating the type of traversal, and the depth of the node in the tree. The VISIT codes are:

preorder
The node is visited before its children.
postorder
The node is visited after its children.
endorder
The node is visited after its children (same as postorder).
leaf
The node is a leaf node.

tdestroy destroys the tree and frees all the memory associated with it. The free_node function is called for each node in the tree to free the memory associated with the node's data. The caller is responsible for providing a suitable function to free the data.

RETURN VALUE

tsearch returns a pointer to the node containing the key, or NULL if the key was not found and memory could not be allocated for a new node. The returned pointer points to the data stored in the node.

tfind returns a pointer to the data stored in the node if the key is found, and NULL otherwise.

tdelete returns a pointer to the deleted node if the key was found and the node was deleted, and NULL otherwise.

ATTRIBUTES

For an explanation of the terms used in this section, see attributes(7).

? ? ?

STANDARDS

These functions first appeared in BSD-2.11. They are not specified by any POSIX or ISO C standards.

HISTORY

The binary search tree functions appeared in 4.3BSD.

NOTES

The tsearch function allocates memory using malloc(3). The caller is responsible for freeing the memory associated with the nodes when the tree is no longer needed, typically by calling tdestroy.

The tdelete function does not free the memory associated with the deleted node. The caller must free the memory pointed to by the returned pointer if necessary.

The twalk function traverses the tree in a specific order, but the exact order (preorder, postorder, endorder) depends on the implementation. The leaf code is also provided, which is called for leaf nodes.

The tdestroy function traverses the tree and calls the provided free_node function for each node. This is useful for freeing the memory allocated for the data stored in the tree.

EXAMPLES

The following example demonstrates how to use the tsearch, twalk, and tdestroy functions to build and traverse a binary search tree of integers:

#include <search.h>
#include <stddef.h>
#include <stdio.h>
#include <stdlib.h>
#include <time.h>

static void *root = NULL;

static void *
xmalloc(size_t n)
{
	void *p;

	p = malloc(n);
	if (p)
		return p;

	fprintf(stderr, "insufficient memory\n");
	exit(EXIT_FAILURE);
}

static int
compare(const void *pa, const void *pb)
{
	if (*(int *) pa < *(int *) pb)
		return -1;
	if (*(int *) pa > *(int *) pb)
		return 1;
	return 0;
}

static void
action(const void *nodep, VISIT which, int depth)
{
	int *datap;

	switch (which) {
	case preorder:
		break;
	case postorder:
		datap = *(int **) nodep;
		printf("%6d\n", *datap);
		break;
	case endorder:
		break;
	case leaf:
		datap = *(int **) nodep;
		printf("%6d\n", *datap);
		break;
	}
}

int
main(void)
{
	int *ptr;
	int **val;

	srand(time(NULL));

	for (unsigned int i = 0; i < 12; i++) {
		ptr = xmalloc(sizeof(*ptr));
		*ptr = rand() & 0xff;
		val = tsearch(ptr, &root, compare);
		if (val == NULL)
			exit(EXIT_FAILURE);
		if (*val != ptr)
			free(ptr);
	}

	twalk(root, action);
	tdestroy(root, free);

	exit(EXIT_SUCCESS);
}
