الاسم

Text::CSV_PP - وحدة Perl خالصة متوافقة مع Text::CSV_XS

الملخص

هذا القسم مأخوذ من Text::CSV_XS.

# واجهة وظيفية
use Text::CSV_PP qw( csv );
# قراءة الملف بالكامل في الذاكرة
my $aoa = csv (in => "data.csv");    # كمصفوفة من المصفوفات
my $aoh = csv (in => "data.csv",
               headers => "auto");   # كمصفوفة من الهاش
# كتابة مصفوفة من المصفوفات كملف CSV
csv (in => $aoa, out => "file.csv", sep_char => ";");
# عرض الأسطر فقط حيث يكون "code" فرديًا
csv (in => "data.csv", filter => { code => sub { $_ % 2 }});
# واجهة الكائن
use Text::CSV_PP;
my @rows;
# قراءة/تحليل CSV
my $csv = Text::CSV_PP->new ({ binary => 1, auto_diag => 1 });
open my $fh, "<:encoding(utf8)", "test.csv" or die "test.csv: $!";
while (my $row = $csv->getline ($fh)) {
    $row->[2] =~ m/pattern/ or next; # يجب أن يتطابق الحقل الثالث
    push @rows, $row;
    }
close $fh;
# وكتابة كـ CSV
open $fh, ">:encoding(utf8)", "new.csv" or die "new.csv: $!";
$csv->say ($fh, $_) for @rows;
close $fh or die "new.csv: $!";

الوصف

Text::CSV_PP هي وحدة Perl خالصة توفر تسهيلات لتكوين وتحليل قيم مفصولة بفواصل. هذه الوحدة متوافقة (تقريبًا) مع Text::CSV_XS الأسرع بكثير، وتستخدم بشكل أساسي كبديل لوحدة Text::CSV عندما تستخدم الوحدة Text::CSV دون تثبيت Text::CSV_XS. إذا لم يكن لديك أي سبب لاستخدام هذه الوحدة مباشرة، استخدم Text::CSV لتحسين السرعة وقابلية النقل (أو ربما Text::CSV_XS عند كتابة نص برمجي لمرة واحدة ولا تحتاج إلى الاهتمام بقابلية النقل).

المحاذير التالية مأخوذة من وثائق Text::CSV_XS.

الأسطر الجديدة المضمنة

ملاحظة هامة: السلوك الافتراضي هو قبول الأحرف ASCII فقط في النطاق من 0x20 (مسافة) إلى 0x7E (العلامة المائلة). هذا يعني أن الحقول لا يمكن أن تحتوي على أسطر جديدة. إذا كانت بياناتك تحتوي على أسطر جديدة مضمنة في الحقول، أو أحرف أعلى من 0x7E (العلامة المائلة)، أو بيانات ثنائية، فيجب عليك تعيين "binary => 1" في استدعاء "new". لتغطية أوسع نطاق من خيارات التحليل، سترغب دائمًا في تعيين binary.

لكنك لا تزال تواجه مشكلة أنك بحاجة إلى تمرير سطر صحيح إلى الطريقة "parse"، وهو أمر أكثر تعقيدًا من نقطة الاستخدام المعتادة:

my $csv = Text::CSV_PP->new ({ binary => 1, eol => $/ });
while (<>) {           #  خاطئ!
    $csv->parse ($_);
    my @fields = $csv->fields ();
    }

سيتعطل هذا، لأن "while" قد يقرأ أسطرًا مكسورة: فهي لا تهتم بالاقتباس. إذا كنت بحاجة إلى دعم الأسطر الجديدة المضمنة، فالطريقة الصحيحة هي عدم تمرير "eol" في المحلل (يقبل "\n"، "\r"، و "\r\n" افتراضيًا) ثم

my $csv = Text::CSV_PP->new ({ binary => 1 });
open my $fh, "<", $file or die "$file: $!";
while (my $row = $csv->getline ($fh)) {
    my @fields = @$row;
    }

الطريقة القديمة (الأقدم) لاستخدام مقابض الملفات العامة لا تزال مدعومة

while (my $row = $csv->getline (*ARGV)) { ... }

يونيكود

تم اختبار يونيكود ليعمل فقط مع perl-5.8.2 وما فوق.

انظر أيضًا "BOM".

أسهل طريقة لضمان استخدام الترميز الصحيح للإدخال والإخراج هي إما بتعيين طبقات على مقابض الملفات، أو بتعيين الوسيط "encoding" لـ "csv".

 open my $fh, "<:encoding(UTF-8)", "in.csv"  or die "in.csv: $!";
أو
 my $aoa = csv (in => "in.csv",     encoding => "UTF-8");
 open my $fh, ">:encoding(UTF-8)", "out.csv" or die "out.csv: $!";
أو
 csv (in => $aoa, out => "out.csv", encoding => "UTF-8");

عند التحليل (لكل من "getline" و "parse")، إذا تم تمييز المصدر بأنه UTF8، فسيتم تمييز جميع الحقول التي تم تمييزها كـ binary كـ UTF8 أيضًا.

عند التجميع ("print" و "combine"): إذا تم تمييز أي من الحقول المجمعة كـ UTF8، فسيتم تمييز السلسلة الناتجة كـ UTF8. لاحظ مع ذلك أن جميع الحقول قبل أول حقل تم تمييزه كـ UTF8 واحتوت على أحرف 8 بت لم يتم ترقيتها إلى UTF8، فستكون هذه "bytes" في السلسلة الناتجة أيضًا، مما قد يتسبب في أخطاء غير متوقعة. إذا قمت بتمرير بيانات ذات ترميز مختلف، أو كنت لا تعرف ما إذا كان هناك ترميز مختلف، فقم بفرضه ليتم ترقيته قبل تمريره:

$csv->print ($fh, [ map { utf8::upgrade (my $x = $_); $x } @data ]);

للتحكم الكامل في الترميز، يرجى استخدام Text::CSV::Encoded:

use Text::CSV::Encoded;
my $csv = Text::CSV::Encoded->new ({
    encoding_in  => "iso-8859-1", # الترميز يدخل إلى Perl
    encoding_out => "cp1252",     # الترميز يخرج من Perl
    });
$csv = Text::CSV::Encoded->new ({ encoding  => "utf8" });
# combine () و print () تقبل بيانات مرمزة بـ utf8 *حرفيًا*
# parse () و getline () تعيد بيانات مرمزة بـ utf8 *حرفيًا*
$csv = Text::CSV::Encoded->new ({ encoding  => undef }); # افتراضي
# combine () و print () تقبل بيانات معلمة بـ UTF8
# parse () و getline () تعيد بيانات معلمة بـ UTF8

BOM

معالجة BOM (أو علامة ترتيب البايتات) متاحة فقط داخل الطريقة "header". تدعم هذه الطريقة الترميزات التالية: "utf-8"، "utf-1"، "utf-32be"، "utf-32le"، "utf-16be"، "utf-16le"، "utf-ebcdic"، "scsu"، "bocu-1"، و "gb-18030". انظر ويكيبيديا https://en.wikipedia.org/wiki/Byte_order_mark.

إذا كان للملف BOM، فإن أسهل طريقة للتعامل مع ذلك هي

my $aoh = csv (in => $file, detect_bom => 1);

سيتم ترميز جميع السجلات بناءً على BOM المكتشف.

هذا يعني استدعاء للطريقة "header"، والتي تقوم افتراضيًا بتعيين "column_names" أيضًا. لذا فهذا ليس نفس

my $aoh = csv (in => $file, headers => "auto");

الذي يقرأ السجل الأول فقط لتعيين "column_names" ولكنه يتجاهل أي معنى لـ BOM قد يكون موجودًا.

سلسلة نهاية السطر التي يجب إضافتها إلى الصفوف لـ "print" أو فاصل السجلات لـ "getline".

ny: for the opposite, the default is true for safety. You can exclude the space from this trigger by setting this attribute to 0.

quote_empty

my $csv = Text::CSV_PP->new ({ quote_empty => 1 });
        $csv->quote_empty (0);
my $f = $csv->quote_empty;

By default the generated fields are quoted only if they need to be. An empty (defined) field does not need quotation. If you set this attribute to 1 then empty defined fields will be quoted. ("undef" fields are not quoted, see "blank_is_undef"). See also "always_quote".

quote_binary

my $csv = Text::CSV_PP->new ({ quote_binary => 1 });
        $csv->quote_binary (0);
my $f = $csv->quote_binary;

By default, all "unsafe" bytes inside a string cause the combined field to be quoted. By setting this attribute to 0, you can disable that trigger for bytes ">= 0x7F".

escape_null

my $csv = Text::CSV_PP->new ({ escape_null => 1 });
        $csv->escape_null (0);
my $f = $csv->escape_null;

By default, a "NULL" byte in a field would be escaped. This option enables you to treat the "NULL" byte as a simple binary character in binary mode (the "{ binary => 1 }" is set). The default is true. You can prevent "NULL" escapes by setting this attribute to 0.

When the "escape_char" attribute is set to undefined, this attribute will be set to false.

The default setting will encode "=\x00=" as

"="0="

With "escape_null" set, this will result in

"=\x00="

The default when using the "csv" function is "false".

For backward compatibility reasons, the deprecated old name "quote_null" is still recognized.

keep_meta_info

my $csv = Text::CSV_PP->new ({ keep_meta_info => 1 });
        $csv->keep_meta_info (0);
my $f = $csv->keep_meta_info;

By default, the parsing of input records is as simple and fast as possible. However, some parsing information - like quotation of the original field - is lost in that process. Setting this flag to true enables retrieving that information after parsing with the methods "meta_info", "is_quoted", and "is_binary" described below. Default is false for performance.

If you set this attribute to a value greater than 9, then you can control output quotation style like it was used in the input of the the last parsed record (unless quotation was added because of other reasons).

my $csv = Text::CSV_PP->new ({
   binary         => 1,
   keep_meta_info => 1,
   quote_space    => 0,
   });
my $row = $csv->parse (q{1,,"", ," ",f,"g","h""h",help,"help"});
$csv->print (*STDOUT, \@row);
# 1,,, , ,f,g,"h""h",help,help
$csv->keep_meta_info (11);
$csv->print (*STDOUT, \@row);
# 1,,"", ," ",f,"g","h""h",help,"help"

undef_str

my $csv = Text::CSV_PP->new ({ undef_str => "\\N" });
        $csv->undef_str (undef);
my $s = $csv->undef_str;

This attribute optionally defines the output of undefined fields. The value passed is not changed at all, so if it needs quotation, the quotation needs to be included in the value of the attribute. Use with caution, as passing a value like ",",,,,""" will for sure mess up your output. The default for this attribute is "undef", meaning no special treatment.

This attribute is useful when exporting CSV data to be imported in custom loaders, like for MySQL, that recognize special sequences for "NULL" data.

This attribute has no meaning when parsing CSV data.

comment_str

my $csv = Text::CSV_PP->new ({ comment_str => "#" });
        $csv->comment_str (undef);
my $s = $csv->comment_str;

This attribute optionally defines a string to be recognized as comment. If this attribute is defined, all lines starting with this sequence will not be parsed as CSV but skipped as comment.

This attribute has no meaning when generating CSV.

Comment strings that start with any of the special characters/sequences are not supported (so it cannot start with any of "sep_char", "quote_char", "escape_char", "sep", "quote", or "eol").

For convenience, "comment" is an alias for "comment_str".

verbatim

my $csv = Text::CSV_PP->new ({ verbatim => 1 });
        $csv->verbatim (0);
my $f = $csv->verbatim;

This is a quite controversial attribute to set, but makes some hard things possible.

The rationale behind this attribute is to tell the parser that the normally special characters newline ("NL") and Carriage Return ("CR") will not be special when this flag is set, and be dealt with as being ordinary binary characters. This will ease working with data with embedded newlines.

When "verbatim" is used with "getline", "getline" auto-"chomp"'s every line.

Imagine a file format like

M^^Hans^Janssen^Klas 2\n2A^Ja^11-06-2007#\r\n

where, the line ending is a very specific "#\r\n", and the sep_char is a "^" (caret). None of the fields is quoted, but embedded binary data is likely to be present. With the specific line ending, this should not be too hard to detect.

By default, Text::CSV_PP' parse function is instructed to only know about "\n" and "\r" to be legal line endings, and so has to deal with the embedded newline as a real "end-of-line", so it can scan the next line if binary is true, and the newline is inside a quoted field. With this option, we tell "parse" to parse the line as if "\n" is just nothing more than a binary character.

For "parse" this means that the parser has no more idea about line ending and "getline" "chomp"s line endings on reading.

For all of the above mentioned flags, an accessor method is available where you can inquire the current value, or change the value

my $quote = $csv->quote_char;
$csv->binary (1);

It is not wise to change these settings halfway through writing "CSV" data to a stream. If however you want to create a new stream using the available "CSV" object, there is no harm in changing them.

If the "new" constructor call fails, it returns "undef", and makes the fail reason available through the "error_diag" method.

$csv = Text::CSV_PP->new ({ ecs_char => 1 }) or
    die "".Text::CSV_PP->error_diag ();

"error_diag" will return a string like

"INI - Unknown attribute 'ecs_char'"

known_attributes

@attr = Text::CSV_PP->known_attributes;
@attr = Text::CSV_PP::known_attributes;
@attr = $csv->known_attributes;

This method will return an ordered list of all the supported attributes as described above. This can be useful for knowing what attributes are valid in classes that use or extend Text::CSV_PP.

print

$status = $csv->print ($fh, $colref);

Similar to "combine" + "string" + "print", but much more efficient. It expects an array ref as input (not an array!) and the resulting string is not really created, but immediately written to the $fh object, typically an IO handle or any other object that offers a "print" method.

For performance reasons "print" does not create a result string, so all "string", "status", "fields", and "error_input" methods will return undefined information after executing this method.

If $colref is "undef" (explicit, not through a variable argument) and "bind_columns" was used to specify fields to be printed, it is possible to make performance improvements, as otherwise data would have to be copied as arguments to the method call:

$csv->bind_columns (\($foo, $bar));
$status = $csv->print ($fh, undef);

getline

$colref = $csv->getline ($fh);

هذا هو المقابل لـ "print"، بنفس الطريقة التي يعد بها "parse" المقابل لـ "combine": يقوم بتحليل صف من المقبض $fh باستخدام الطريقة "getline" المرتبطة بالمقبض $fh ويقوم بتحليل هذا الصف إلى مرجع مصفوفة. يتم إرجاع مرجع المصفوفة هذا بواسطة الدالة أو كـ "undef" في حالة الفشل. عندما لا يدعم $fh "getline"، فمن المحتمل حدوث أخطاء.

عند ربط الأعمدة بواسطة "bind_columns"، تكون القيمة المرجعة مرجعًا إلى قائمة فارغة.

الطرق "string" و "fields" و "status" لم تعد ذات مغزى.

parse

$status = $csv->parse ($line);

تقوم هذه الطريقة بتفكيك نص "CSV" إلى حقول، وتعيد النجاح أو الفشل. قد يحدث الفشل بسبب عدم وجود وسيط أو نص "CSV" بتنسيق غير صحيح. بمجرد النجاح، يمكنك استدعاء "fields" لاستعادة الحقول المفككة. عند استدعاء "fields" عند الفشل، يتم إرجاع بيانات غير محددة، ويمكن استدعاء "error_input" لاستعادة الوسيط غير الصالح.

يمكنك استخدام الطريقة "types" لتحديد أنواع الأعمدة. راجع وصف "types" أدناه.

يفترض أن الوسيط $line هو قيمة عددية بسيطة. يفترض أن كل شيء آخر يؤدي إلى خطأ ويضبط الخطأ 1500.

fragment

تحاول هذه الدالة تنفيذ RFC7111 (معرفات الأجزاء النصية لنوع الوسائط text/csv) - https://datatracker.ietf.org/doc/html/rfc7111

my $AoA = $csv->fragment ($fh, $spec);

في المواصفات، يتم استخدام "*" لتحديد العنصر *الأخير*، وشرطة ("-") للإشارة إلى نطاق. جميع الفهارس هي 1-based: السطر أو العمود الأول له فهرس 1. يمكن دمج التحديدات بواسطة الفاصلة المنقوطة (";").

عند استخدام هذه الطريقة بالاشتراك مع "column_names"، سيشير المرجع المرجع إلى قائمة تجزئة بدلاً من قائمة قوائم. قد يؤدي التحديد المستند إلى خلايا إلى إرجاع صفوف بأعداد مختلفة من الأعمدة، مما يجعل استخدام التجزئات غير متوقع.

$csv->column_names ("Name", "Age");
my $AoH = $csv->fragment ($fh, "col=3;8");

إذا كان رد الاتصال "after_parse" نشطًا، فسيتم أيضًا استدعاء كل سطر تم تحليله وتجاوزه قبل الجزء.

row
row=4
row=5-7
row=6-*
row=1-2;4;6-*
col
col=2
col=1-3
col=4-*
col=1-2;4;7-*
cell
في التحديد المستند إلى خلايا، يتم استخدام الفاصلة (",") لأزواج الصف والعمود 
cell=4,1

يمكن استخدام عامل تشغيل النطاق ("-") باستخدام "cell" لتحديد موقع الخلية العلوية اليسرى والسفلية اليمنى 

cell=3,1-4,6

يُسمح فقط بـ "*" في الجزء الثاني من الزوج 

cell=3,2-*,2    # الصف 3 حتى النهاية، العمود 2 فقط
cell=3,2-3,*    # العمود 2 حتى النهاية، الصف 3 فقط
cell=3,2-*,*    # استبعاد الصف 1 و 2، والعمود 1

يمكن دمج الخلايا ونطاقات الخلايا بواسطة ";"، مما قد يؤدي إلى صفوف بأعداد مختلفة من الأعمدة 

cell=1,1-2,2;3,3-4,4;1,4;4,1

ستعيد التحديدات المنفصلة الخلايا المحددة فقط. لن يتم تضمين الخلايا غير المحددة في المجموعة المرجعة، حتى كـ "undef". على سبيل المثال، بالنظر إلى ملف CSV مثل 

11,12,13,...19
21,22,...28,29
:            :
91,...97,98,99

مع "cell=1,1-2,2;3,3-4,4;1,4;4,1" ستعيد:

11,12,14
21,22
33,34
41,43,44

ستعيد التحديدات المتداخلة الخلايا مرة واحدة فقط، لذا "cell=1,1-3,3;2,2-4,4;2,3;4,2" ستعيد:

11,12,13
21,22,23,24
31,32,33,34
42,43,44

لا تسمح RFC7111 https://datatracker.ietf.org/doc/html/rfc7111 بدمج أنواع مختلفة من المواصفات (إما "row" *أو* "col" *أو* "cell"). سيؤدي تمرير مواصفات جزء غير صالحة إلى إثارة خطأ وضبط الخطأ 2013.

column_names

يحدد المفاتيح التي سيتم استخدامها في استدعاءات "getline_hr". إذا لم يتم تمرير مفاتيح (أسماء أعمدة)، فسيعيد القيمة الحالية كقائمة.

"column_names" تقبل قائمة من القيم العددية (أسماء الأعمدة) أو مرجع مصفوفة واحد، لذلك يمكنك تمرير القيمة المرجعة من "getline":

$csv->column_names ($csv->getl
ine ($fh));

"column_names" لا يقوم بأي تحقق على التكرارات على الإطلاق، مما قد يؤدي إلى نتائج غير متوقعة. سيتم استبدال الإدخالات غير المحددة بالسلسلة "\cAUNDEF\cA"، لذا

$csv->column_names (undef, "", "name", "name");
$hr = $csv->getline_hr ($fh);

سيتم تعيين "$hr->{"\cAUNDEF\cA"}" إلى الحقل الأول، و "$hr->{""}" إلى الحقل الثاني، و "$hr->{name}" إلى الحقل الرابع، مع تجاهل الحقل الثالث.

"column_names" تتعطل مع الوسائط غير الصالحة.

header

هذه الطريقة لا تعمل في perl-5.6.x

قم بتحليل رأس CSV وتعيين "sep" وأسماء الأعمدة والترميز.

my @hdr = $csv->header ($fh);
$csv->header ($fh, { sep_set => [ ";", ",", "|", "\t" ] });
$csv->header ($fh, { detect_bom => 1, munge_column_names => "lc" });

يجب أن يكون الوسيط الأول مقبض ملف.

تعيد هذه الطريقة تعيين بعض خصائص الكائن، حيث يُفترض استدعاؤها مرة واحدة فقط لكل ملف أو تدفق. ستترك السمات "column_names" و "bound_columns" كما هي إذا تم تعطيل تعيين أسماء الأعمدة. قد تفشل قراءة الرؤوس على الكائنات التي تمت معالجتها سابقًا على perl-5.8.0 والإصدارات الأقدم.

بافتراض أن الملف المفتوح للتحليل يحتوي على رأس، وأن الرأس لا يحتوي على أحرف إشكالية مثل الأسطر الجديدة المضمنة، اقرأ السطر الأول من المقبض المفتوح ثم اكتشف تلقائيًا ما إذا كان الرأس يفصل أسماء الأعمدة بحرف من قائمة المحددات المسموح بها.

إذا تطابق أي من المحددات المسموح بها، ولم يتطابق أي من المحددات المسموح بها * الأخرى *، قم بتعيين "sep" إلى هذا المحدد لمثيل CSV_PP الحالي واستخدمه لتحليل السطر الأول، وقم بتعيينها إلى الأحرف الصغيرة، واستخدم ذلك لتعيين "column_names" للمثيل:

my $csv = Text::CSV_PP->new ({ binary => 1, auto_diag => 1 });
open my $fh, "<", "file.csv";
binmode $fh; # for Windows
$csv->header ($fh);
while (my $row = $csv->getline_hr ($fh)) {
    ...
    }

إذا كان الرأس فارغًا، أو يحتوي على أكثر من محدد فريد واحد من المجموعة المسموح بها، أو يحتوي على حقول فارغة، أو يحتوي على حقول متطابقة (بعد الطي)، فسوف تتعطل مع الخطأ 1010، 1011، 1012، أو 1013 على التوالي.

إذا كان الرأس يحتوي على أسطر جديدة مضمنة أو لم يكن CSV صالحًا بأي شكل آخر، فسوف تتعطل هذه الطريقة وتترك خطأ التحليل دون تغيير.

سيقوم استدعاء ناجح لـ "header" دائمًا بتعيين "sep" لكائن $csv. لا يمكن تعطيل هذا السلوك.

قيمة الإرجاع

عند حدوث خطأ، ستتعطل هذه الطريقة.

في سياق القائمة، سيتم إرجاع الرؤوس سواء تم استخدامها لتعيين "column_names" أم لا.

في سياق القياسي، يتم إرجاع المثيل نفسه. ** ملاحظة: ** سيتم * فقدان * القيم الموجودة في الرأس بشكل فعال إذا كان "set_column_names" غير صحيح.

الخيارات

sep_set
$csv->header ($fh, { sep_set => [ ";", ",", "|", "\t" ] });

القائمة الافتراضية للمحددات القانونية هي "[ ";", "," ]" ويمكن تغييرها بواسطة هذا الخيار. نظرًا لأن هذا هو الخيار الأكثر استخدامًا على الأرجح، يمكن تمريره بمفرده كوسيط غير مسمى:

$csv->header ($fh, [ ";", ",", "|", "\t", "::", "\x{2063}" ]);

يُسمح بتسلسلات متعددة البايتات، سواء كانت متعددة الأحرف أو Unicode. انظر "sep".

detect_bom
$csv->header ($fh, { detect_bom => 1 });

السلوك الافتراضي هو اكتشاف ما إذا كان سطر الرأس يبدأ بـ BOM. إذا كان للرأس BOM، فاستخدمه لتعيين ترميز $fh. يمكن تعطيل هذا السلوك الافتراضي بتمرير قيمة خاطئة إلى "detect_bom".

الترميزات المدعومة من BOM هي: UTF-8، UTF-16BE، UTF-16LE، UTF-32BE، و UTF-32LE. يدعم BOM أيضًا UTF-1، UTF-EBCDIC، SCSU، BOCU-1، و GB-18030 ولكن Encode لا يدعمها (حتى الآن). UTF-7 غير مدعوم.

إذا تم اكتشاف BOM مدعوم كبداية للتدفق، فسيتم تخزينه في سمة الكائن "ENCODING".

my $enc = $csv->{ENCODING};

يتم استخدام الترميز مع "binmode" على $fh.

إذا تم فتح المقبض بترميز (صحيح)، فلن تقوم هذه الطريقة بتغيير الترميز، حيث إنها تتحقق من البايتات الرائدة للسطر الأول. في حالة بدء التدفق بـ BOM مفكوك التشفير ("U+FEFF")، سيكون "{ENCODING}" "" (فارغ) بدلاً من القيمة الافتراضية "undef".

munge_column_names
يوفر هذا الخيار الوسيلة لتعديل أسماء الأعمدة إلى شيء مفيد للتطبيق. الافتراضي هو تعيين جميع أسماء الأعمدة إلى الأحرف الصغيرة. 
$csv->header ($fh, { munge_column_names => "lc" });

القيم التالية متاحة:

lc     - lower case
uc     - upper case
db     - valid DB field names
none   - do not change
\%hash - supply a mapping
\&cb   - supply a callback
Lower case
$csv->header ($fh, { munge_column_names => "lc" });

يتم تغيير الرأس إلى جميع الأحرف الصغيرة

$_ = lc;
Upper case
$csv->header ($fh, { munge_column_names => "uc" });

يتم تغيير الرأس إلى جميع الأحرف الكبيرة

$_ = uc;
Literal
$csv->header ($fh, { munge_column_names => "none" });
Hash
$csv->header ($fh, { munge_column_names => { foo => "sombrero" });

إذا كانت القيمة غير موجودة، يتم استخدام القيمة الأصلية دون تغيير

Database
$csv->header ($fh, { munge_column_names => "db" });
  • أحرف صغيرة
  • جميع تسلسلات الأحرف غير الكلمية يتم استبدالها بشرطة سفلية
  • جميع الشرطات السفلية البادئة يتم إزالتها
$_ = lc (s/\W+/_/gr =~ s/^_+//r);
Callback
$csv->header ($fh, { munge_column_names => sub { fc } });
$csv->header ($fh, { munge_column_names => sub { "column_".$col++ } });
$csv->header ($fh, { munge_column_names => sub { lc (s/\W+/_/gr) } });

نظرًا لأن هذا الاستدعاء يتم في "map"، يمكنك استخدام $_ مباشرة.

set_column_names
$csv->header ($fh, { set_column_names => 1 });

الافتراضي هو تعيين أسماء أعمدة المثيلات باستخدام "column_names" إذا نجحت الطريقة، بحيث يمكن لاستدعاءات "getline_hr" اللاحقة إرجاع تجزئة. يمكن فرض تعطيل تعيين الرأس باستخدام قيمة خاطئة لهذا الخيار.

كما هو موضح في "قيمة الإرجاع" أعلاه، يتم فقدان المحتوى في سياق القياسي.

التحقق من الصحة

عند تلقي ملفات CSV من مصادر خارجية، يمكن استخدام هذه الطريقة للحماية من التغييرات في التخطيط عن طريق التقييد إلى رؤوس معروفة (والأخطاء الإملائية في حقول الرأس).

my %known = (
    "record key" => "c_rec",
    "rec id"     => "c_rec",
    "id_rec"     => "c_rec",
    "kode"       => "code",
    "code"       => "code",
    "vaule"      => "value",
    "value"      => "value",
    );
my $csv = Text::CSV_PP->new ({ binary => 1, auto_diag => 1 });
open my $fh, "<", "file.csv" or die "$source: $!";
$csv->header ($fh, { munge_column_names => sub {
    s/\s+$//;
    s/^\s+//;
    $known{lc $_} or die "Unknown column '$_' in $source";
    }});
while (my $row = $csv->getline_hr ($fh)) {
    say join "\t", $row->{c_rec}, $row->{code}, $row->{value};
    }

bind_columns

يأخذ قائمة بمراجع قياسية لاستخدامها للإخراج مع "print" أو لتخزينها في الحقول التي تم جلبها بواسطة "getline". عندما لا تمرر مراجع كافية لتخزين الحقول التي تم جلبها فيها، ستفشل "getline" بالخطأ 3006. إذا قمت بتمرير أكثر مما هو موجود من حقول للإرجاع، فسيتم ترك محتوى المراجع المتبقية دون تغيير. تحت "strict" يجب أن يتطابق الاثنان، وإلا فإن "getline" ستفشل بالخطأ 2014.

$csv->bind_columns (\$code, \$name, \$price, \$description);
while ($csv->getline ($fh)) {
    print "The price of a $name is \x{20ac} $price\n";
    }

لإعادة تعيين أو مسح جميع ربط الأعمدة، قم باستدعاء "bind_columns" مع الوسيط الواحد "undef". سيؤدي ذلك أيضًا إلى مسح أسماء الأعمدة.

$csv->bind_columns (undef);

إذا لم يتم تمرير أي وسائط على الإطلاق، فإن "bind_columns" سترجع قائمة بالربطات الحالية أو "undef" إذا لم تكن هناك ربطات نشطة.

لاحظ أنه في التحليل باستخدام "bind_columns"، يتم تعيين الحقول في الوقت المناسب. هذا يعني أنه إذا تسبب الحقل الثالث للصف في خطأ (أو أن هذا الصف به

{ "error_message": "خطأ: تعذر قراءة محتوى الملف: [Errno 2] لا يوجد مثل هذا الملف أو الدليل: '/home/asdf/Documents/split_file_parts/split_file_parts_split_1/Text__CSV_PP.3pm_part7.en'" } ag (0);

استخدم لإعادة تعيين التشخيصات إذا كنت تتعامل مع أخطاء.

الوظائف

هذا القسم مأخوذ أيضًا من Text::CSV_XS.

csv

هذه الوظيفة لا يتم تصديرها بشكل افتراضي ويجب طلبها صراحةً:

use Text::CSV_PP qw( csv );

هذه وظيفة عالية المستوى تهدف إلى واجهات مستخدم بسيطة. يمكن استخدامها لقراءة/تحليل ملف أو تيار "CSV" (السلوك الافتراضي) أو لإنتاج ملف أو الكتابة إلى تيار (حدد السمة "out"). إنها تُرجع مرجعًا لمصفوفة أو تجزئة عند التحليل (أو "undef" عند الفشل) أو القيمة الرقمية لـ "error_diag" عند الكتابة. عندما تفشل هذه الوظيفة، يمكنك الحصول على الخطأ باستخدام استدعاء الفئة إلى "error_diag"

my $aoa = csv (in => "test.csv") or
    die Text::CSV_PP->error_diag;

لاحظ أن الفشل هنا هو عدم القدرة على بدء المحلل، مثل عندما يكون الإدخال غير موجود أو تكون الوسيطات غير معروفة أو متعارضة. ستُرجع أخطاء التحليل وقت التشغيل مرجعًا صالحًا، والذي يمكن أن يكون فارغًا، ولكنه لا يزال يحتوي على جميع النتائج حتى الخطأ. انظر "on_error".

تأخذ هذه الوظيفة الوسيطات كأزواج مفتاح-قيمة. يمكن تمريرها كقائمة أو ك تجزئة مجهولة:

my $aoa = csv (  in => "test.csv", sep_char => ";");
my $aoh = csv ({ in => $fh, headers => "auto" });

تتكون الوسيطات الممررة من جزأين: الوسيطات إلى "csv" نفسها والسمات الاختيارية للكائن "CSV" المستخدم داخل الوظيفة كما هو موضح ومشروح في "new".

إذا لم يتم تجاوزها، فإن الخيار الافتراضي المستخدم لـ CSV هو

auto_diag   => 1
escape_null => 0
strict_eol  => 1

الخيار الذي يتم تعيينه دائمًا ولا يمكن تغييره هو

binary      => 1

نظرًا لأن هذه الوظيفة من المحتمل استخدامها في سطر أوامر واحد، فإنها تسمح باختصار "quote" إلى "quo"، و "escape_char" إلى "esc" أو "escape".

استدعاءات بديلة:

my $aoa = Text::CSV_PP::csv (in => "file.csv");
my $csv = Text::CSV_PP->new ();
my $aoa = $csv->csv (in => "file.csv");

في الحالة الأخيرة، تُستخدم سمات الكائن من الكائن الحالي ويتم تجاهل وسيطات السمة في استدعاء الوظيفة:

my $csv = Text::CSV_PP->new ({ sep_char => ";" });
my $aoh = $csv->csv (in => "file.csv", bom => 1);

سيقوم بالتحليل باستخدام ";" كـ "sep_char"، وليس ",".

in

تستخدم لتحديد المصدر. يمكن أن يكون "in" اسم ملف (مثل "file.csv")، والذي سيتم فتحه للقراءة وإغلاقه عند الانتهاء، أو مقبض ملف (مثل $fh أو "FH")، أو مرجع إلى glob (مثل "\*ARGV")، أو glob نفسه (مثل *STDIN)، أو مرجع إلى متغير (مثل "\q{1,2,"csv"}").

عند استخدامها مع "out"، يجب أن يكون "in" مرجعًا لهيكل CSV (AoA أو AoH) أو مرجع CODE يُرجع مرجع مصفوفة أو مرجع تجزئة. سيتم استدعاء ref الكود بدون وسيطات.

my $aoa = csv (in => "file.csv");
open my $fh, "<", "file.csv";
my $aoa = csv (in => $fh);
my $csv = [ [qw( Foo Bar )], [ 1, 2 ], [ 2, 3 ]];
my $err = csv (in => $csv, out => "file.csv");

إذا تم استدعاؤها في سياق فارغ بدون السمة "out"، فسيتم استخدام المرجع الناتج كإدخال لاستدعاء لاحق لـ csv:

csv (in => "file.csv", filter => { 2 => sub { length > 2 }})

سيكون اختصارًا لـ

csv (in => csv (in => "file.csv", filter => { 2 => sub { length > 2 }}))

حيث، في غياب السمة "out"، يكون هذا اختصارًا لـ

csv (in  => csv (in => "file.csv", filter => { 2 => sub { length > 2 }}),
     out => *STDOUT)

out

csv (in => $aoa,  out => "file.csv");
csv (in => $aoa,  out => $fh);
csv (in => $aoa,  out =>   STDOUT);
csv (in => $aoa,  out =>  *STDOUT);
csv (in => $aoa,  out => \*STDOUT);
csv (in => $aoa,  out => \my $data);
csv (in => $aoa,  out =>  undef);
csv (in => $aoa,  out => \"skip");
csv (in => $fh,   out => \@aoa);
csv (in => $fh,   out => \@aoh, bom => 1);
csv (in => $fh,   out => \%hsh, key => "key");
csv (in => $file, out => $file);
csv (in => $file, out => $fh);
csv (in => $fh,   out => $file);
csv (in => $fh,   out => $fh);

في وضع الإخراج، الخيارات الافتراضية لـ CSV عند إنتاج CSV هي

eol       => "\r\n"

يتم تجاهل السمة "fragment" في وضع الإخراج.

"out" يمكن أن يكون اسم ملف (مثل "file.csv")، والذي سيتم فتحه للكتابة وإغلاقه عند الانتهاء، أو مقبض ملف (مثل $fh أو "FH")، أو مرجع إلى glob (مثل "\*STDOUT")، أو glob نفسه (مثل *STDOUT)، أو مرجع إلى متغير (مثل "\my $data").

csv (in => sub { $sth->fetch },            out => "dump.csv");
csv (in => sub { $sth->fetchrow_hashref }, out => "dump.csv",
     headers => $sth->{NAME_lc});

عند استخدام ref كود لـ "in"، يتم إنشاء الإخراج لكل استدعاء، لذلك لا يتم استخدام التخزين المؤقت. هذا يعني أنه لا يوجد حد لحجم عدد السجلات. تنتهي الوظيفة "csv" عندما يُرجع ref الكود قيمة زائفة.

إذا تم تعيين "out" إلى مرجع للسلسلة الحرفية "skip"، فسيتم قمع الإخراج بالكامل، والذي قد يكون مفيدًا بالاقتران مع مرشح للتأثيرات الجانبية فقط.

my %cache;
csv (in    => "dump.csv",
     out   => \"skip",
     on_in => sub { $cache{$_[1][1]}++ });

حاليًا، تعيين "out" إلى أي قيمة زائفة ( "undef"، ""، 0) سيعادل "\"skip"".

إذا كانت الوسيطة "in" تشير إلى شيء للتحليل، وتم تعيين "out" إلى مرجع لـ "ARRAY" أو "HASH"، فسيتم إلحاق الإخراج بالبيانات الموجودة في المرجع الحالي. يجب أن يتطابق ناتج التحليل مع ما هو موجود في المرجع الممرر. قد يكون هذا مفيدًا عندما تحتاج إلى تحليل مجموعة من الملفات ذات المحتوى المماثل (مثل البيانات المخزنة حسب الفترة) وتريد جمعها في بنية بيانات واحدة:

my %hash;
csv (in => $_, out => \%hash, key => "id") for sort glob "foo-[0-9]*.csv";
my @list; # List of arrays
csv (in => $_, out => \@list)              for sort glob "foo-[0-9]*.csv";
my @list; # List of hashes
csv (in => $_, out => \@list, bom => 1)    for sort glob "foo-[0-9]*.csv";

التيارات

إذا كان كل من "in" و "out" ملفات أو مقابض ملفات أو globs، فسيتم فرض التدفق عن طريق حقن رد استدعاء "after_parse" الذي يستخدم على الفور طريقة "say ()" لنفس المثيل لإخراج النتيجة ثم يرفض السجل.

إذا تم تمرير "after_parse" بالفعل كوسيطة، فسيتم تضمينه في الاستدعاء المحقون. إذا تم تمرير "on_in" ولم يتم تمرير "after_parse"، فسيتم استخدامه بدلاً من ذلك. إذا تم تمرير كليهما، فسيتم تجاهل "on_in".

يتم استخدام EOL للسجل الأول لمصدر "in" باستمرار كـ EOL لجميع السجلات في وجهة "out".

السمة "filter" غير متاحة.

تتم مشاركة جميع السمات الأخرى لـ "in" و "out"، لذا لا يمكنك تحديد ترميزات مختلفة لـ "in" و "out". تحتاج إلى تمرير $fh، حيث تم استخدام "binmode" لتطبيق طبقات الترميز.

after_in
This callback is invoked for each record after all records have been parsed but before returning the reference to the caller. The hook is invoked with two arguments: the current "CSV" parser object and a reference to the record. The reference can be a reference to a HASH or a reference to an ARRAY as determined by the arguments.

This callback can also be passed as an attribute without the "callbacks" wrapper.

before_out
This callback is invoked for each record before the record is printed. The hook is invoked with two arguments: the current "CSV" parser object and a reference to the record. The reference can be a reference to a HASH or a reference to an ARRAY as determined by the arguments.

This callback can also be passed as an attribute without the "callbacks" wrapper.

This callback makes the row available in %_ if the row is a hashref. In this case %_ is writable and will change the original row.

on_in
This callback acts exactly as the "after_in" or the "before_out" hooks.

This callback can also be passed as an attribute without the "callbacks" wrapper.

This callback makes the row available in %_ if the row is a hashref. In this case %_ is writable and will change the original row. So e.g. with

my $aoh = csv (
    in      => \"foo\n1\n2\n",
    headers => "auto",
    on_in   => sub { $_{bar} = 2; },
    );

$aoh will be:

[ { foo => 1,
    bar => 2,
    }
  { foo => 2,
    bar => 2,
    }
  ]
on_error
This callback acts exactly as the "error" hook. 
my @err;
my $aoa = csv (in => $fh, on_error => sub { @err = @_ });

is identical to

my $aoa = csv (in => $fh, callbacks => {
    error => sub { @err = @_ },
    });

It can be used for ignoring errors as well as for just keeping the error in case of analysis after the "csv ()" function has returned.

my @err;
my $aoa = csv (in => "bad.csv, on_error => sub { @err = @_ });
die Text::CSV_PP->error_diag if @err or !$aoa;

If an error occurs, "$csv->error_diag" can be used to get information on the cause of the failure. Note that for speed reasons the internal value is never cleared on success, so using the value returned by "error_diag" in normal cases - when no error occurred - may cause unexpected results.

If the constructor failed, the cause can be found using "error_diag" as a class method, like "Text::CSV_PP->error_diag".

The "$csv->error_diag" method is automatically invoked upon error when the contractor was called with "auto_diag" set to 1 or 2, or when autodie is in effect. When set to 1, this will cause a "warn" with the error message, when set to 2, it will "die". "2012 - EOF" is excluded from "auto_diag" reports.

Errors can be (individually) caught using the "error" callback.

The errors as described below are available. I have tried to make the error itself explanatory enough, but more descriptions will be added. For most of these errors, the first three capitals describe the error category:

  • INI

    Initialization error or option conflict.

  • ECR

    Carriage-Return related parse error.

  • EOF

    End-Of-File related parse error.

  • EIQ

    Parse error inside quotation.

  • EIF

    Parse error inside field.

  • ECB

    Combine error.

  • EHR

    HashRef parse related error.

And below should be the complete list of error codes that can be returned:

  • 1001 "INI - sep_char is equal to quote_char or escape_char"

    The separation character cannot be equal to the quotation character or to the escape character, as this would invalidate all parsing rules.

  • 1002 "INI - allow_whitespace with escape_char or quote_char SP or TAB"

    Using the "allow_whitespace" attribute when either "quote_char" or "escape_char" is equal to "SPACE" or "TAB" is too ambiguous to allow.

  • 1003 "INI - \r or \n in main attr not allowed"

    Using default "eol" characters in either "sep_char", "quote_char", or "escape_char" is not allowed.

  • 1004 "INI - callbacks should be undef or a hashref"

    The "callbacks" attribute only allows one to be "undef" or a hash reference.

  • 1005 "INI - EOL too long"

    The value passed for EOL is exceeding its maximum length (16).

  • 1006 "INI - SEP too long"

    The value passed for SEP is exceeding its maximum length (16).

  • 1007 "INI - QUOTE too long"

    The value passed for QUOTE is exceeding its maximum length (16).

  • 1008 "INI - SEP undefined"

    The value passed for SEP should be defined and not empty.

  • 1010 "INI - the header is empty"

    The header line parsed in the "header" is empty.

  • 1011 "INI - the header contains more than one valid separator"

    The header line parsed in the "header" contains more than one (unique) separator character out of the allowed set of separators.

  • 1012 "INI - the header contains an empty field"

    The header line parsed in the "header" contains an empty field.

  • 1013 "INI - the header contains nun-unique fields"

    The header line parsed in the "header" contains at least two identical fields.

  • 1014 "INI - header called on undefined stream"

    The header line cannot be parsed from an undefined source.

  • 1500 "PRM - Invalid/unsupported argument(s)"

    Function or method called with invalid argument(s) or parameter(s).

  • 1501 "PRM - The key attribute is passed as an unsupported type"

    The "key" attribute is of an unsupported type.

  • 1502 "PRM - The value attribute is passed without the key attribute"

    The "value" attribute is only allowed when a valid key is given.

  • 1503 "PRM - The value attribute is passed as an unsupported type"

    The "value" attribute is of an unsupported type.

  • 2010 "ECR - QUO char inside quotes followed by CR not part of EOL"

    When "eol" has been set to anything but the default, like "\r\t\n", and the "\r" is following the second (closing) "quote_char", where the characters following the "\r" do not make up the "eol" sequence, this is an error.

  • 2011 "ECR - Characters after end of quoted field"

    Sequences like "1,foo,"bar"baz,22,1" are not allowed. "bar" is a quoted field and after the closing double-quote, there should be either a new-line sequence or a separation character.

  • 2012 "EOF - End of data in parsing input stream"

    Self-explaining. End-of-file while inside parsing a stream. Can happen only when reading from streams with "getline", as using "parse" is done on strings that are not required to have a trailing "eol".

  • 2013 "INI - Specification error for fragments RFC7111"

    Invalid specification for URI "fragment" specification.

  • 2014 "ENF - Inconsistent number of fields"

    Inconsistent number of fields under strict parsing.

  • 2015 "ERW - Empty row"

    An empty row was not allowed.

  • 2016 "EOL - Inconsistent EOL"

    Inconsistent End-Of-Line detected under strict_eol parsing.

  • 2021 "EIQ - NL char inside quotes, binary off"

    Sequences like "1,"foo\nbar",22,1" are allowed only when the binary option has been selected with the constructor.

  • 2022 " EIQ - CR char inside quotes, binary off"

    Sequences like "1,"foo\rbar",22,1" are allowed only when the binary option has been selected with the constructor.

  • 2023 "EIQ - QUO character not allowed"

    Sequences like ""foo "bar" baz",qu" and "2023,",2008-04-05,"Foo, Bar",\n" will cause this error.

  • 2024 "EIQ - EOF cannot be escaped, not even inside quotes"

    The escape character is not allowed as last character in an input stream.

  • 2025 "EIQ - Loose unescaped escape"

    An escape character should escape only characters that need escaping.

    Allowing the escape for other characters is possible with the attribute "allow_loose_escapes".

  • 2026 "EIQ - Binary character inside quoted field, binary off"

    Binary characters are not allowed by default. Exceptions are fields that contain valid UTF-8, that will automatically be upgraded if the content is valid UTF-8. Set "binary" to 1 to accept binary data.

  • 2027 "EIQ - Quoted field not terminated"

    When parsing a field that started with a quotation character, the field is expected to be closed with a quotation character. When the parsed line is exhausted before the quote is found, that field is not terminated.

  • 2030 "EIF - NL char inside unquoted verbatim, binary off"
  • 2031 "EIF - CR char is first char of field, not part of EOL"
  • 2032 "EIF - CR char inside unquoted, not part of EOL"
  • 2034 "EIF - Loose unescaped quote"
  • 2035 "EIF - Escaped EOF in unquoted field"
  • 2036 "EIF - ESC error"
  • 2037 "EIF - Binary character in unquoted field, binary off"
  • 2110 "ECB - Binary character in Combine, binary off"
  • 2200 "EIO - print to IO failed. See errno"
  • 3001 "EHR - Unsupported syntax for column_names ()"
  • 3002 "EHR - getline_hr () called before column_names ()"
  • 3003 "EHR - bind_columns () and column_names () fields count mismatch"
  • 3004 "EHR - bind_columns () only accepts refs to scalars"
  • 3006 "EHR - bind_columns () did not pass enough refs for parsed fields"
  • 3007 "EHR - bind_columns needs refs to writable scalars"
  • 3008 "EHR - unexpected error in bound fields"
  • 3009 "EHR - print_hr () called before column_names ()"
  • 3010 "EHR - print_hr () called with invalid arguments"
