الاسم

Template::Tutorial::Web - توليد محتوى الويب باستخدام Template Toolkit

نظرة عامة

يقدم هذا المستند التعليمي مقدمة إلى Template Toolkit ويوضح بعض الطرق النموذجية التي يمكن استخدامه بها لتوليد محتوى الويب. يغطي توليد الصفحات الثابتة من القوالب باستخدام نصوص tpage و ttree، ثم ينتقل إلى عرض توليد المحتوى الديناميكي باستخدام نصوص CGI ومعالجات Apache/mod_perl.

سيتم تقديم ووصف ميزات مختلفة لـ Template Toolkit بإيجاز وشرحها باستخدام أمثلة. لمزيد من المعلومات، راجع Template و Template::Manual والأقسام المختلفة فيها. على سبيل المثال:

perldoc Template                    # استخدام وحدة Template.pm
perldoc Template::Manual            # فهرس الدليل
perldoc Template::Manual::Config    # على سبيل المثال، خيارات التكوين

الوثائق متاحة أيضًا بتنسيق HTML للقراءة عبر الإنترنت، أو يمكن تنزيلها من موقع Template Toolkit على الويب:

http://template-toolkit.org/docs/

مقدمة

Template Toolkit هي مجموعة من وحدات Perl التي تنفذ مجتمعة نظام معالجة القوالب.

القالب هو مستند نصي يتضمن علامات ترميز خاصة. بشكل افتراضي، يستخدم Template Toolkit '"[%"' و '"%]"' لتحديد بداية ونهاية العلامة. إليك مثال:

[% INCLUDE header %]

People of [% planet %], your attention please.

This is [% captain %] of the
Galactic Hyperspace Planning Council.

As you will no doubt be aware, the plans
for development of the outlying regions
of the Galaxy require the building of a
hyperspatial express route through your
star system, and regrettably your planet
is one of those scheduled for destruction.

The process will take slightly less than
[% time %].

Thank you.

[% INCLUDE footer %]

يمكن أن تحتوي العلامات على متغيرات بسيطة (مثل "planet" و "captain") و توجيهات أكثر تعقيدًا تبدأ بكلمة مفتاحية بحرف كبير (مثل "INCLUDE"). التوجيه هو أمر يخبر معالج القالب بتنفيذ إجراء ما، مثل معالجة قالب آخر ( "header" و "footer" في هذا المثال) وإدراج المخرجات في القالب الحالي. في الواقع، المتغيرات البسيطة التي ذكرناها هي في الواقع توجيهات "GET"، ولكن الكلمة المفتاحية "GET" اختيارية.

People of [% planet %], your attention please.      # short form
People of [% GET planet %], your attention please.  # long form

تشمل التوجيهات الأخرى "SET" لتعيين قيمة متغير (الكلمة المفتاحية "SET" اختيارية أيضًا)، "FOREACH" للتكرار عبر قائمة قيم، "IF" و "UNLESS" و "ELSIF" و "ELSE" لتحديد كتل شرطية.

يعالج Template Toolkit جميع ملفات النص بالتساوي، بغض النظر عن نوع المحتوى الذي تحتويه. لذلك يمكنك استخدام TT لتوليد HTML، XML، CSS، Javascript، Perl، RTF، LaTeX، أو أي تنسيق نصي آخر. في هذا البرنامج التعليمي، سنركز على توليد HTML لصفحات الويب.

توليد محتوى الويب الثابت

إليك مثال لقالب يستخدم لتوليد مستند HTML.

[%  INCLUDE header
      title = 'This is an HTML example';

    pages = [
      { url   = 'http://foo.org'
        title = 'The Foo Organisation'
      }
      { url   = 'http://bar.org'
        title = 'The Bar Organisation'
      }
    ]
%]
   <h1>Some Interesting Links</h1>
   <ul>
[%  FOREACH page IN pages %]
     <li><a href="[% page.url %]">[% page.title %]</a>
[%  END %]
   </ul>

[% INCLUDE footer %]

يوضح هذا المثال كيفية استخدام التوجيه "INCLUDE" لتحميل ومعالجة ملفات القوالب المنفصلة '"header"' و '"footer"'، بما في ذلك المخرجات في المستند الحالي. قد تبدو هذه الملفات شيئًا كهذا:

header:

<html>
  <head>
    <title>[% title %]</title>
  </head>
  <body>

footer:

    <div class="copyright">
      &copy; Copyright 2007 Arthur Dent
    </div>
  </body>
</html>

يستخدم المثال أيضًا التوجيه "FOREACH" للتكرار عبر قائمة '"pages"' لبناء جدول من الروابط. في هذا المثال، قمنا بتعريف هذه القائمة لاحتواء عدد من مراجع الهاش، كل منها يحتوي على عضو '"url"' و '"title"'. يتكرر التوجيه "FOREACH" عبر القائمة، ويشير إلى '"page"' لكل عنصر (في هذه الحالة، مراجع مصفوفة الهاش). تقوم التوجيهات "[% page.url %]" و "[% page.title %]" بعد ذلك بالوصول إلى القيم الفردية في مصفوفات الهاش وإدراجها في المستند.

استخدام tpage

بعد إنشاء ملف قالب، يمكننا الآن معالجته لتوليد بعض المخرجات الحقيقية. أسرع وأسهل طريقة للقيام بذلك هي استخدام نص tpage. يتم توفير هذا كجزء من Template Toolkit ويجب تثبيته في دليل bin الخاص بـ Perl.

بافتراض أنك حفظت ملف القالب الخاص بك باسم example.html، ستقوم بتشغيل الأمر:

$ tpage example.html

سيقوم هذا بمعالجة ملف القالب، وإرسال المخرجات إلى "STDOUT" (أي، يمر بسرعة أمامك على الشاشة). قد ترغب في إعادة توجيه المخرجات إلى ملف ولكن كن حذرًا من عدم تحديد نفس اسم ملف القالب، وإلا فسوف تتجاوزه. قد ترغب في استخدام بادئة واحدة لقوالبك (مثل '".tt"') وأخرى (مثل '".html"') لملفات المخرجات.

$ tpage example.tt > example.html

أو يمكنك إعادة توجيه المخرجات إلى دليل آخر. على سبيل المثال:

$ tpage templates/example.tt > html/example.html

ستبدو المخرجات المولدة كالتالي:

<html>
  <head>
    <title>This is an HTML example</title>
  </head>
  <body>
    <h1>Some Interesting Links</h1>
    <ul>
      <li><a href="http://foo.org">The Foo Organsiation</a>
      <li><a href="http://bar.org">The Bar Organsiation</a>
    </ul>
    <div class="copyright">
      &copy; Copyright 2007 Arthur Dent
    </div>
  </body>
</html>

تم تضمين ملفات القوالب header و footer (بافتراض أنك قمت بإنشائها وهي في الدليل الحالي) وتم بناء بيانات الارتباط في قائمة HTML.

استخدام ttree

يوفر لك نص tpage طريقة بسيطة وسهلة لمعالجة قالب واحد دون الحاجة إلى كتابة أي كود Perl. النص <ttree:Template::Tools::ttree>، والذي يتم توزيعه أيضًا كجزء من Template Toolkit، يوفر طريقة أكثر مرونة لمعالجة عدد من مستندات القوالب دفعة واحدة.

في المرة الأولى التي تقوم فيها بتشغيل النص، سيسألك عما إذا كان يجب عليه إنشاء ملف تكوين (.ttreerc) في دليل المنزل الخاص بك. أجب "y" لجعله ينشئ الملف.

توثيق <ttree:Template::Tools::ttree> يصف كيف يمكنك تغيير موقع هذا الملف ويشرح أيضًا بناء ومعنى الخيارات المختلفة في الملف. يتم كتابة التعليقات في ملف التكوين النموذجي والتي يجب أن تساعد أيضًا.

باختصار، يصف ملف التكوين الأدلة التي يجب البحث فيها عن ملفات القوالب ("src")، وأين يجب كتابة المخرجات المقابلة إليها ("dest")، وأي أدلة أخرى ("lib") قد تحتوي على ملفات قوالب تخطط لـ "I

حافظ على هيكل الملف بأكمله. عناصر مثل الرؤوس والتذييلات، من بين أمور أخرى. عند استخدام قالب لإنشاء مخرجات نصوص CGI الخاصة بك، يمكنك منحها نفس الاتساق الذي تتمتع به الصفحات الثابتة التي تم إنشاؤها باستخدام ttree أو وسائل أخرى. علاوة على ذلك، يمكننا تعديل برنامجنا النصي لمعالجة أي واحد من سلسلة من القوالب المختلفة بناءً على شرط معين. على سبيل المثال، قد يقوم برنامج نصي CGI لإدارة قاعدة بيانات للمستخدمين بمعالجة قالب لعرض نموذج فارغ للمستخدمين الجدد، ونفس النموذج مع بعض القيم الافتراضية لتحديث سجل مستخدم موجود، وقالب آخر لسرد جميع المستخدمين في النظام، وهكذا. يمكنك استخدام أي وظيفة Perl تكتبها لتنفيذ منطق التطبيق الخاص بك ثم اختيار قالب واحد أو أكثر لإنشاء المخرجات المطلوبة بناءً على حالة التطبيق. ### إنشاء محتوى ديناميكي عبر Apache/Mod_Perl Handler **ملاحظة:** الوحدة النمطية Apache::Template متاحة في CPAN وتقدم واجهة بسيطة وسهلة الاستخدام لـ Template Toolkit الخاص بـ Apache/mod_perl. على الرغم من أنها أساسية، إلا أنها تنفذ كل ما تم وصفه أدناه تقريبًا، مما يلغي الحاجة إلى كتابة معالج خاص بك. ومع ذلك، في كثير من الحالات، ستتخلى عن كتابة معالج خاص بك لتخصيص المعالجة حسب احتياجاتك، وسيوضح هذا القسم كيفية البدء. يمكن استخدام الوحدة النمطية Template من معالج Apache/mod_perl. إليك مثال لملف تكوين Apache نموذجي: ```perl PerlModule CGI; PerlModule Template PerlModule MyOrg::Apache::User PerlSetVar websrc_root /home/abw/websrc SetHandler perl-script PerlHandler MyOrg::Apache::User ``` يحدد هذا موقعًا يسمى `/user/bin` يتم توجيه جميع الطلبات إليه إلى الطريقة `handler()` للفئة `MyOrg::Apache::User`. قد تبدو هذه الفئة كالتالي: ```perl package MyOrg::Apache::User; use strict; use Apache::Constants qw( :common ); use Template; use CGI; our $VERSION = 1.59; sub handler { my $r = shift; my $websrc = $r->dir_config('websrc_root') or return fail($r, SERVER_ERROR, '"'websrc_root' not specified'); my $template = Template->new({ INCLUDE_PATH => "$websrc/src/user:$websrc/lib", PRE_PROCESS => 'config', OUTPUT => $r, # direct output to Apache request }); my $params = { uri => $r->uri, cgi => CGI->new, }; # use the path_info to determine which template file to process my $file = $r->path_info; $file =~ s[^/][]; $r->content_type('text/html'); $r->send_http_header; $template->process($file, $params) || return fail($r, SERVER_ERROR, $template->error()); return OK; } sub fail { my ($r, $status, $message) = @_; $r->log_reason($message, $r->filename); return $status; } ``` يقبل المعالج الطلب ويستخدمه لتحديد قيمة `$websrc_root` من ملف التكوين. ثم يتم استخدام هذه القيمة لتعريف `INCLUDE_PATH` لكائن Template جديد. يتم استخراج URI من الطلب ويتم إنشاء كائن CGI. يتم تعريف كلاهما كمتغيرات قالب. يتم أخذ اسم ملف القالب نفسه من جزء عنوان URL الذي يقع بعد عنصر `PATH_INFO` في الطلب. في هذه الحالة، سيكون جزء عنوان URL بعد `/user/bin`، على سبيل المثال، لـ `/user/bin/edit`، سيكون ملف القالب `edit` الموجود في `$websrc/src/user`. يتم إرسال الرؤوس ويتم معالجة ملف القالب. يتم إرسال جميع المخرجات مباشرة إلى الطريقة `print()` لكائن طلب Apache. ### استخدام الإضافات لتوسيع الوظائف كما أظهرنا بالفعل، من الممكن ربط بيانات ووظائف Perl بمتغيرات القالب عند إنشاء محتوى ديناميكي عبر برنامج نصي CGI أو عملية Apache/mod_perl. يدعم Template Toolkit أيضًا واجهة إضافات تسمح بتعريف بيانات إضافية و/أو وظائف في وحدة منفصلة ثم تحميلها واستخدامها مع التوجيه `USE`. الميزة الرئيسية لهذا النهج هي أنه يمكنك تحميل الامتداد في أي مستند قالب، حتى تلك التي تتم معالجتها بشكل ثابت بواسطة `tpage` أو `ttree`. لست بحاجة إلى كتابة غلاف Perl لتحميل الوحدة بشكل صريح وجعلها متاحة في المخزن المؤقت. سنوضح هذه المبادئ باستخدام إضافة `DBI` التي كتبها Simon Matthews (متوفرة في CPAN). يمكنك إنشاء هذا القالب في دليل `src` الخاص بك ومعالجته باستخدام `ttree` لرؤية النتائج. بالطبع، يعتمد هذا المثال على وجود قاعدة بيانات SQL مناسبة، ولكن يجب أن تكون قادرًا على تكييفه مع مواردك، أو على الأقل استخدامه كمثال لما هو ممكن. ```perl [% INCLUDE header title = 'User Info' %] [% USE DBI('dbi:mSQL:mydbname') %] <table border=0 width="100%"> <tr> <th>User ID</th> <th>Name</th> <th>Email</th> </tr> [% FOREACH user IN DBI.query('SELECT * FROM user ORDER BY id') %] <tr> <td>[% user.id %]</td> <td>[% user.name %]</td> <td>[% user.email %]</td> </tr> [% END %] </table> [% INCLUDE footer %] ``` الإضافة هي ببساطة وحدة Perl في موقع معروف تتبع معيارًا معروفًا، مما يسمح لـ Template Toolkit بالعثور عليها وتحميلها تلقائيًا. يمكنك إنشاء إضافاتك الخاصة عن طريق الوراثة من الفئة `Template::Plugin`. إليك مثال يحدد بعض البيانات (`foo` و `people`) وكذلك طريقة كائن (`bar`). سنسمي الإضافة `FooBar` لعدم وجود اسم أفضل وسننشئها في الفئة `MyOrg::Template::Plugin::FooBar`. نضيف `MyOrg` إلى الفئة `Template::Plugin::*` لتجنب التعارض مع الإضافات الموجودة. ```perl package MyOrg::Template::Plugin::FooBar; use base 'Template::Plugin' our $VERSION = 1.23; sub new { my ($class, $context, @params) = @_; bless { _CONTEXT => $context, foo => 25, people => [ 'tom', 'dick', 'harry' ], }, $class; } sub bar { my ($self, @params) = @_; # ...do something... return $some_value; } ``` يستقبل مُنشئ الإضافة `new()` اسم الفئة كمعلمة أولى، وهو أمر معتاد في Perl، متبوعًا بإشارة إلى كائن `Template::Context`. لا تقلق كثيرًا بشأن هذا، ولكن اعلم أنه الكائن الرئيسي لمعالجة Template Toolkit. يوفر الوصول إلى وظائف المعالج وقد تحتاج بعض الإضافات إلى التواصل معه. لن نفعل ذلك الآن، لكننا سنحفظه في العضو `_CONTEXT`. يشير الشرطة السفلية الأولية إلى أن هذا العنصر خاص ولن يحاول Template Toolkit الوصول إليه. الأعضاء الآخرون المحددين، `foo` و `people`، هي بيانات عادية سيتم تقديمها للقوالب باستخدام هذه الإضافة. بعد الإشارة إلى السياق، يتم تمرير أي معلمات إضافية محددة بالتوجيه `USE`، مثل معلمات المصدر، `dbi:mSQL:mydbname`، التي استخدمناها في المثال السابق. إذا لم تتمكن من تثبيته أو لم تتمكن من تثبيته في موقعه المعتاد لوحدات Perl الخاصة بك (على الأرجح بسبب عدم امتلاكك الأذونات اللازمة)، فيمكنك تعيين متغير البيئة `PERL5LIB` لتحديد موقع آخر. إذا كنت تستخدم `ttree`، يمكنك إضافة السطر التالي إلى ملف التكوين الخاص بك: ```perl $HOME/.ttreerc: perl5lib = /path/to/modules ``` يجب إضافة تكوين إضافي للإشارة إلى الأداة اسم الحزمة الجديد الذي نستخدمه لإضافاتنا: ```perl $HOME/.ttreerc: plugin_base = 'MyOrg::Template::Plugin' ``` إذا كنت تكتب كود Perl للتحكم في وحدات Template مباشرة، فيمكن تمرير هذه القيمة كمعلمة تكوين عند إنشاء الوحدة. ```perl use Template; my $template = Template->new({ PLUGIN_BASE => 'MyOrg::Template::Plugin' }); ``` الآن يمكننا إنشاء قالب يستخدم هذه الإضافة: ```perl [% INCLUDE header title = 'FooBar Plugin Test' %] [% USE FooBar %] Values available from this plugin: [% FooBar.foo %] [% FooBar.bar %] Users defined in the 'people' list: [% FOREACH uid = FooBar.people %] * [% uid %] [% END %] [% INCLUDE footer %] ``` يتم حل العناصر `foo` و `bar` و `people` للإضافة `FooBar` تلقائيًا إلى البيانات المقابلة أو استدعاءات الطرق للكائن الأساسي. باستخدام هذا النهج، من الممكن إنشاء وظائف تطبيق في وحدة واحدة يمكن بعد ذلك تحميلها واستخدامها في أي قالب. تسمح الواجهة البسيطة بين توجيهات القالب وكائنات الإضافات ببناء محتوى ديناميكي معقد من عدد قليل من مستندات القوالب البسيطة دون معرفة أي شيء عن التنفيذ الأساسي. ### المؤلف آندي واردي http://wardley.org/ ### حقوق النشر حقوق النشر (C) 1996-2007 آندي واردي. جميع الحقوق NAME

Template::Tutorial::Web - Web CGI and SSI tutorial

Overview

This tutorial demonstrates how to use the Template Toolkit to generate dynamic web content, primarily focusing on CGI scripts and server-side includes (SSI).

Introduction

The Template Toolkit is a powerful and flexible templating system for Perl. It's well-suited for web development, allowing you to separate presentation logic from application logic.

Generating Static Web Content

Even for static content, the Template Toolkit can be useful for managing HTML structure and reducing repetition. You can define templates and then render them with basic variables.

Dynamic Content Generation Via CGI Script

This section explains how to use Template Toolkit within a CGI script. The script will typically:

  • Receive input (e.g., from GET or POST requests).
  • Fetch data from a database or other sources.
  • Define variables to pass to the template.
  • Instantiate a Template Toolkit processor.
  • Process the template file with the defined variables.
  • Print the resulting HTML output to the browser.

Dynamic Content Generation Via Apache/Mod_Perl Handler

For better performance, you can integrate Template Toolkit with Apache using mod_perl. This allows templates to be compiled and cached in memory, speeding up subsequent requests. The setup involves configuring Apache to use a mod_perl handler that processes templates.

Using Plugins to Extend Functionality

The Template Toolkit supports plugins, which can add custom directives and functionality. For web development, plugins might handle tasks like:

  • Including other template files (like header/footer).
  • URL manipulation.
  • Form processing.
  • Database interaction.
