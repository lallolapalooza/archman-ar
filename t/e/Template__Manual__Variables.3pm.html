الاسم

Template::Manual::Variables - متغيرات القالب وربط الكود

متغيرات القالب

يمكن تمرير مصفوفة ارتباطية كحجة ثانية إلى الدالة process()، تحتوي على تعريفات لمتغيرات القالب. يمكن أيضًا استخدام الخيار "VARIABLES" (المعروف أيضًا باسم "PRE_DEFINE") لتعريف مسبق للمتغيرات لجميع القوالب التي تتم معالجتها بواسطة الكائن.

my $tt = Template->new({
    VARIABLES => {
        version => 3.14,
        release => 'Sahara',
    },
});
my $vars = {
    serial_no => 271828,
};
$tt->process('myfile', $vars);

القالب myfile:

This is version [% version %] ([% release %]).
Serial number: [% serial_no %]

النتيجة المولدة:

This is version 3.14 (Sahara)
Serial number: 271828

يمكن أن تحتوي أسماء المتغيرات على أي حرف أبجدي رقمي أو شرطة. يمكن أن تكون بأحرف صغيرة أو كبيرة أو مختلطة، على الرغم من أن العرف المعتاد هو استخدام الأحرف الصغيرة. حالة الأحرف *مهمة*، و"foo" و"Foo" و"FOO" كلها متغيرات مختلفة. يُسمح بأسماء المتغيرات الكبيرة، على الرغم من أنه لا يُنصح بها بسبب تعارض محتمل مع كلمة محجوزة موجودة أو مستقبلية. منذ الإصدار 2.00، هذه هي:

GET CALL SET DEFAULT INSERT INCLUDE PROCESS WRAPPER
IF UNLESS ELSE ELSIF FOR FOREACH WHILE SWITCH CASE
USE PLUGIN FILTER MACRO PERL RAWPERL BLOCK META
TRY THROW CATCH FINAL NEXT LAST BREAK RETURN STOP
CLEAR TO STEP AND OR NOT MOD DIV END

يمكن أن تكون قيم المتغيرات من أي نوع Perl، بما في ذلك القيم البسيطة، مراجع القوائم، مصفوفات الارتباط، الإجراءات الفرعية أو الكائنات. سيقوم Toolkit القالب بتطبيق الإجراء المناسب بشكل صحيح عند الوصول إلى هذه القيم عند استخدامها في القالب.

مثال على البيانات:

my $vars = {
    article => 'The Third Shoe',
    person  => {
        id    => 314,
        name  => 'Mr. Blue',
        email => 'blue@nowhere.org',
    },
    primes  => [ 2, 3, 5, 7, 11, 13 ],
    wizard  => sub { return join(' ', 'Abracadabra!', @_) },
    cgi     => CGI->new('mode=submit&debug=1'),
};

مثال على القالب:

[% article %]
[% person.id %]: [% person.name %] <[% person.email %]>
[% primes.first %] - [% primes.last %], including [% primes.3 %]
[% primes.size %] prime numbers: [% primes.join(', ') %]
[% wizard %]
[% wizard('Hocus Pocus!') %]
[% cgi.param('mode') %]

النتيجة المولدة:

The Third Shoe
314: Mr. Blue <blue@nowhere.org>
2 - 13, including 7
6 prime numbers: 2, 3, 5, 7, 11, 13
Abracadabra!
Abracadabra! Hocus Pocus!
submit

قيم القياس

يتم الوصول إلى متغيرات القياس ببساطة عن طريق تحديد اسمها. نظرًا لأن هذه مجرد إدخالات في تجزئة مساحة الأسماء الرئيسية، يمكن اعتبارها حالات خاصة لمراجع مصفوفات الارتباط، مع تضمين مساحة الأسماء الرئيسية ضمنيًا.

[% article %]

مراجع مصفوفة الارتباط

يتم الوصول إلى عناصر مصفوفة الارتباط عن طريق تحديد مرجع التجزئة والمفتاح مفصولين بالمعامل ".".

مثال على البيانات:

my $vars = {
    'home' => 'http://www.myserver.com/homepage.html',
    'page' => {
        'this' => 'mypage.html',
        'next' => 'nextpage.html',
        'prev' => 'prevpage.html',
    },
};

مثال على القالب:

<a href="[% home %]">Home</a>
<a href="[% page.prev %]">Previous Page</a>
<a href="[% page.next %]">Next Page</a>

النتيجة المولدة:

<a href="http://www.myserver.com/homepage.html">Home</a>
<a href="prevpage.html">Previous Page</a>
<a href="nextpage.html">Next Page</a>

سيتم اعتبار أي مفتاح في تجزئة يبدأ بالحرف "_" أو "." خاصًا ولا يمكن تقييمه أو تحديثه من القالب. سيتم إرجاع القيمة غير المعرفة لأي متغير تم الوصول إليه في هذه الحالة، وسيتجاهل Toolkit القالب تلقائيًا (ما لم يتم تمكين الخيار "DEBUG").

مثال على البيانات:

my $vars = {
    message => 'Hello World!',
    _secret => "On the Internet, no-one knows you're a dog",
    thing   => {
        public    => 123,
        _private  => 456,
        '.hidden' => 789,
    },
};

مثال على القالب:

[% message %]           # outputs "Hello World!"
[% _secret %]           # no output
[% thing.public %]      # outputs "123"
[% thing._private %]    # no output
[% thing..hidden %]     # ERROR: unexpected token (..)

يمكنك تعطيل هذه الميزة عن طريق تعيين متغير الحزمة $Template::Stash::PRIVATE إلى قيمة زائفة.

$Template::Stash::PRIVATE = undef;   # الآن يمكنك الوصول إلى thing._private

للوصول إلى إدخال تجزئة باستخدام مفتاح مخزن في متغير آخر، قم بتصيقه بـ "$" ليتم استيفاؤه قبل استخدامه (راجع "استيفاء المتغيرات").

[% pagename = 'next' %]
[% page.$pagename %]       # نفس الشيء مثل [% page.next %]

يمكنك أيضًا الوصول إلى إدخال تجزئة باستخدام الدالة item(). قد يكون هذا مفيدًا إذا كان لديك اسم مفتاح معقد.

<pre>
[% files.item('example.txt').content %]
</pre>

انظر Template::Manual::VMethods لمزيد من المعلومات.

عندما تقوم بتعيين قيمة لمتغير يحتوي على عناصر مساحة أسماء متعددة (أي، يحتوي على حرف واحد أو أكثر من "." في الاسم)، سيتم إنشاء أي تجزئة مطلوبة لتمثيل مساحات الأسماء الوسيطة تلقائيًا. في المثال التالي، سيتم إنشاء المتغير "product" تلقائيًا كمصفوفة ارتباطية إذا لم يتم تعريفه بطريقة أخرى.

[% product.id    = 'XYZ-2000'
   product.desc  = 'Bogon Generator'
   product.price = 666
%]
El [% product.id %] [% product.desc %]
cuesta $[% product.price %].00

النتيجة المولدة:

The XYZ-2000 Bogon Generator
costs $666.00

يمكنك استخدام البناء المألوف في Perl "{}" لإنشاء مصفوفة ارتباطية بشكل صريح وتعيينها لمتغير. ملاحظة: الفواصل بين أزواج المفتاح/القيمة اختيارية ويمكن استخدام "=" بدلاً من "=>".

# الحد الأدنى لنمط TT
[% product = {
     id    = 'XYZ-2000'
     desc  = 'Bogon Generator'
     price = 666
   }
%]
# نمط Perl
[% product = {
     id    => 'XYZ-2000',
     desc  => 'Bogon Generator',
     price => 666,
   }
%]

مراجع القوائم

يتم الوصول إلى عناصر القوائم أيضًا باستخدام معامل النقطة.

مثال على البيانات:

my $vars = {
    people => [ 'Tom', 'Dick', 'Larry' ],
};

مثال على القالب:

[% people.0 %]          # Tom
[% people.1 %]          # Dick
[% people.2 %]          # Larry

يمكن استخدام التوجيه "FOREACH" للتكرار على عناصر القائمة.

[% FOREACH person IN people %]
Hello [% person %]
[% END %]

النتيجة المولدة:

Hello Tom
Hello Dick
Hello Larry

يمكن بناء القوائم في وقت التشغيل باستخدام بناء القائمة المجهول "[]" العادي. الفواصل بين العناصر اختيارية.

[% cols = [ 'red', 'green', 'blue' ] %]
[% FOREACH c IN cols %]
   [% c %]
[% END %]

أو:

[% FOREACH c IN [ 'red', 'green', 'blue' ] %]
   [% c %]
[% END %]

يمكنك أيضًا إنشاء تسلسلات رقمية بسيطة باستخدام معامل النطاق "..":

[% n = [ 1 .. 4 ] %]    # n هو [ 1, 2, 3, 4 ]
[% x = 4
   y = 8
   z = [x..y]           # z هو [ 4, 5, 6, 7, 8 ]
%]

الإجراءات الفرعية

يمكن أن تحتوي متغيرات القالب على مراجع للإجراءات الفرعية في Perl. عند استخدام المتغير، سيقوم Toolkit القالب تلقائيًا باستدعاء الإجراء الفرعي، مع تمرير أي حجج إضافية محددة. سيتم استخدام القيمة التي تم إرجاعها بواسطة الإجراء الفرعي كقيمة للمتغير وسيتم إدخالها في مستند الإخراج.

الكائنات

يمكن أن تحتوي متغيرات القالب أيضًا على مراجع لكائنات Perl. يتم استدعاء الأساليب باستخدام عامل التشغيل النقطة لتحديد الأسلوب مقابل متغير الكائن. يمكن تحديد وسائط إضافية كما هو الحال مع الإجراءات الفرعية.

use CGI;
my $vars = {
    # hard coded CGI params for purpose of example
    cgi  => CGI->new('mode=submit&debug=1'),
};

قالب مثال:

[% FOREACH p IN cgi.param %]     # returns list of param keys
[% p %] => [% cgi.param(p) %]   # fetch each param value
[% END %]

الناتج المنشأ:

mode => submit
debug => 1

يمكن أيضًا استدعاء أساليب الكائنات كقيم يسارية. أي، يمكن أن تظهر على الجانب الأيسر من التعيين. سيتم استدعاء الأسلوب مع تمرير القيمة المعينة كوسيط.

[% myobj.method = 10 %]

مكافئ ل:

[% myobj.method(10) %]

تمرير المعلمات وإرجاع القيم

سيتم تمرير أي وسائط محددة في القالب إلى الإجراءات الفرعية والأساليب. سيتم تقييم أي متغيرات قالب في قائمة الوسائط أولاً وسيتم تمرير القيم الناتجة إلى الكود.

my $vars = {
    mycode => sub { return 'received ' . join(', ', @_) },
};

قالب:

[% foo = 10 %]
[% mycode(foo, 20) %]       # received 10, 20

يمكن أيضًا تحديد الوسائط المسماة. يتم تجميع هذه تلقائيًا في مصفوفة تجزئة واحدة يتم تمريرها بالمرجع كـ الوسيط الأخير إلى الإجراء الفرعي. يمكن تحديد الوسائط المسماة باستخدام "=>" أو "=" ويمكن أن تظهر في أي مكان في قائمة الوسائط.

my $vars = {
    myjoin => \&myjoin,
};
sub myjoin {
    # look for hash ref as last argument
    my $params = ref $_[-1] eq 'HASH' ? pop : { };
    return join($params->{ joint } || ' + ', @_);
}

قالب مثال:

[% myjoin(10, 20, 30) %]
[% myjoin(10, 20, 30, joint = ' - ') %]
[% myjoin(joint => ' * ', 10, 20, 30) %]

الناتج المنشأ:

10 + 20 + 30
10 - 20 - 30
10 * 20 * 30

يمكن إضافة الوسائط المحاطة بأقواس إلى أي عنصر من عناصر المتغير، وليس فقط تلك المرتبطة بالكود أو أساليب الكائنات. في الوقت الحالي، سيتم تجاهل الوسائط إذا لم يكن المتغير "قابلًا للاستدعاء" ولكنه مدعوم للتوسعات المستقبلية. فكر فيها على أنها "تلميحات" لهذا المتغير، بدلاً من مجرد وسائط يتم تمريرها إلى دالة.

[% r = 'Romeo' %]
[% r(100, 99, s, t, v) %]       # outputs "Romeo"

يجب أن يعيد الكود المستخدم قيمة للمتغير الذي يمثله. يمكن أن يكون هذا أيًا من أنواع بيانات Perl الموصوفة أعلاه: قيمة واحدة، أو مرجع لقائمة، أو تجزئة، أو إجراء فرعي، أو كائن. حيث يعيد الكود قائمة من قيم متعددة، سيتم طي العناصر تلقائيًا في مرجع قائمة يمكن الوصول إليه كالمعتاد.

my $vars = {
    # either is OK, first is recommended
    items1 => sub { return [ 'foo', 'bar', 'baz' ] },
    items2 => sub { return ( 'foo', 'bar', 'baz' ) },
};

قالب مثال:

[% FOREACH i IN items1 %]
   ...
[% END %]
[% FOREACH i IN items2 %]
   ...
[% END %]

معالجة الأخطاء

يمكن الإبلاغ عن الأخطاء من كود المستخدم عن طريق استدعاء die(). يتم التقاط الأخطاء التي تم رفعها بهذه الطريقة بواسطة Template Toolkit وتحويلها إلى استثناءات منظمة يمكن معالجتها من داخل القالب. يصبح مرجع كائن الاستثناء متاحًا كمتغير "error".

my $vars = {
    barf => sub {
        die "a sick error has occurred\n";
    },
};

قالب مثال:

[% TRY %]
   [% barf %]       # calls sub which throws error via die()
[% CATCH %]
   [% error.info %]     # outputs "a sick error has occurred\n"
[% END %]

يتم تحويل رسائل الخطأ التي يتم رفعها عبر die() إلى استثناءات من النوع "undef" (العبارة الحرفية "undef" بدلاً من القيمة غير المعرفة). يمكن رفع استثناءات من الأنواع المعرفة من قبل المستخدم عن طريق استدعاء die() مع مرجع لكائن Template::Exception.

use Template::Exception;
my $vars = {
    login => sub {
        ...do something...
        die Template::Exception->new( badpwd => 'password too silly' );
    },
};

قالب مثال:

[% TRY %]
   [% login %]
[% CATCH badpwd %]
   Bad password: [% error.info %]
[% CATCH %]
   Some other '[% error.type %]' error: [% error.info %]
[% END %]

تُستخدم أنواع الاستثناء "stop" و "return" لتنفيذ التوجيهات "STOP" و "RETURN". رفع استثناء كـ:

die (Template::Exception->new('stop'));

له نفس تأثير التوجيه:

[% STOP %]

الأساليب الافتراضية

تنفذ Template Toolkit عددًا من "الأساليب الافتراضية" التي يمكن تطبيقها على القيم المفردة، أو التجزئات، أو القوائم. على سبيل المثال:

[% mylist = [ 'foo', 'bar', 'baz' ] %]
[% newlist = mylist.sort %]

هنا "mylist" هو مرجع عادي لقائمة، و 'sort' هو أسلوب افتراضي يعيد قائمة جديدة من العناصر بترتيب مرتب. يمكنك ربط أساليب افتراضية متعددة معًا. على سبيل المثال:

[% mylist.sort.join(', ') %]

هنا يتم استدعاء الأسلوب الافتراضي "join" لربط القائمة المرتبة في سلسلة واحدة، مما ينشئ الناتج التالي:

bar, baz, foo

راجع Template::Manual::VMethods للحصول على تفاصيل حول جميع الأساليب الافتراضية المتاحة.

استيفاء المتغيرات

يستخدم Template Toolkit '$' باستمرار للإشارة إلى أنه يجب استيفاء متغير في الموضع. في معظم الأحيان، تراها في السلاسل النصية المزدوجة الاقتباس:

[% fullname = "$honorific $firstname $surname" %]

أو مضمنة في نص عادي عندما يكون الخيار "INTERPOLATE" مضبوطًا:

Dear $honorific $firstname $surname,

تنطبق نفس القواعد داخل التوجيهات. إذا كان المتغير مسبوقًا بـ '$' فسيتم استبداله بقيمته قبل استخدامه. الاستخدام الأكثر شيوعًا هو استرداد عنصر من تجزئة حيث يتم تخزين المفتاح في متغير.

[% uid = 'abw' %]
[% users.$uid %]         # same as 'users.abw'

يمكن استخدام الأقواس المعقوفة لتحديد أسماء المتغيرات المستوفاة عند الضرورة.

[% users.${me.id}.name %]

التوجيهات مثل "INCLUDE" و "PROCESS" وما إلى ذلك، والتي تقبل اسم قالب كوسيط أول، ستقوم تلقائيًا باقتباسه لتسهيل الأمر.

[% INCLUDE foo/bar.txt %]

المثال أعلاه مكافئ لـ:

[% INCLUDE "foo/bar.txt" %]

لتضمين قالب اسمُه مخزن في متغير، ما عليك سوى إضافة بادئة اسم المتغير بـ '$' لاستيفائه.

[% myfile = 'header' %]
[% INCLUDE $myfile %]

هذا مكافئ لـ:

[% INCLUDE header %]

لاحظ أيضًا أنه يمكن معالجة متغير يحتوي على مرجع لكائن Template::Document بهذه الطريقة.

my $vars = {
    header => Template::Document->new({ ... }),
};

قالب مثال:

[% INCLUDE $header %]

المتغيرات المحلية والعالمية

أي متغيرات بسيطة تنشئها، أو أي تغييرات تجريها على المتغيرات الموجودة، ستستمر فقط أثناء معالجة القالب. يتم نسخ تجزئة المتغيرات على مستوى أعلى قبل بدء المعالجة وتتم إجراء أي تغييرات على المتغيرات في هذه النسخة، مع ترك الأصل سليماً.

يحدث نفس الشيء عندما تقوم بتضمين قالب آخر. يتم نسخ تجزئة مساحة الأسماء الحالية لمنع أي تغييرات في المتغيرات التي تتم في القالب المضمن من التداخل مع المتغيرات الموجودة. يتجاوز خيار "PROCESS" خطوة العزل تمامًا مما يجعله أسرع قليلاً، ولكنه يتطلب اهتمامًا أكبر بإمكانية الآثار الجانبية الناتجة عن إنشاء أو تغيير أي متغيرات داخل القالب المعالج.

[% BLOCK change_name %]
   [% name = 'bar' %]
[% END %]
[% name = 'foo' %]
[% INCLUDE change_name %]
[% name %]              # foo
[% PROCESS change_name %]
[% name %]              # bar

تتصرف المتغيرات المركبة ذات النقاط بشكل مختلف قليلاً لأن عملية العزل سطحية فقط. يتم نسخ تجزئة مساحة الأسماء الحالية، ولكن لا يتم بذل أي محاولة للقيام بنسخ عميق لهياكل أخرى بداخلها (تجزئات، مصفوفات، كائنات، إلخ). متغير يشير إلى تجزئة، على سبيل المثال، سيتم نسخه لإنشاء مرجع جديد ولكنه يشير إلى نفس التجزئة. وبالتالي، فإن القاعدة العامة هي أن المتغيرات البسيطة (المتغيرات غير المنقوطة) يتم عزلها، ولكن الهياكل المعقدة الموجودة (المتغيرات المنقوطة) ليست كذلك.

[% BLOCK all_change %]
   [% x = 20 %]         # changes copy

NAME

Template::Manual::Variables - Variables and namespaces in Template Toolkit

Template Variables

Variables are at the heart of any templating system and the Template Toolkit provides a flexible and powerful way to handle them.

All variables are defined within a particular namespace. By default, all variables defined via the "VARS" or "LOAD" constructor options are placed into the top-level namespace. When processing a template, the toolkit will search for a variable name through a list of namespaces in order of priority: first within the current namespace, then in any parent namespaces, and finally in the top-level namespace.

The following example demonstrates the default behaviour:

my $tt = Template->new({
    VARS => {
        foo => 'Hello',
        bar => 'World',
    }
});

$tt->process(\"[% foo %] [% bar %]\n");

# Output: Hello World

You can also define variables within specific namespaces:

my $tt = Template->new({
    VARS => {
        hello => {
            world => 'Hello World!',
        }
    }
});

$tt->process(\"[% hello.world %]\n");

# Output: Hello World!

When processing templates, you can dynamically define and undefine variables within the current namespace using the "VARS" directive.

[% VARS %]
    name = 'Fred'
    type = 'Human'
[% END %]

Name: [% name %] Type: [% type %]

This defines two variables, "name" and "type", within the current namespace. Any previously defined variables with the same name in this namespace will be overwritten. Variables defined in parent namespaces remain unaffected.

Variables defined using the "VARS" directive are local to the template (or block) in which they are defined. They are discarded when the template (or block) processing is complete.

The "UNDEF" directive can be used to remove variables from the current namespace.

[% name = 'Fred' %]
[% name %]  # Output: Fred
[% UNDEF name %]
[% IF name %]
   ...
[% ELSE %]
   Variable 'name' is now undefined.
[% END %]

Virtual Methods

One of the more powerful features of the Template Toolkit is its support for virtual methods. This allows you to call methods on variables that do not natively support them.

For example, if you have a scalar variable containing a string like "hello world", you can call the "upper" method on it directly:

[% myvar = "hello world" %]
[% myvar.upper %]  # Output: HELLO WORLD

This works by the toolkit searching for a method named "upper" in the scalar's class (e.g., "String" or equivalent). If no such method exists, it then checks for a virtual method handler configured via the "VIRTUAL" constructor option.

my $tt = Template->new({
    VIRTUAL => [qw( upper title )],
});

In this example, the toolkit is instructed to look for virtual methods named "upper" and "title". It will first try to find these as subroutines in the top-level namespace (e.g., "VIRTUAL::upper"). If found, the subroutine will be called with the variable as its first argument.

sub VIRTUAL::upper {
    my ($value) = @_;
    return uc($value);
}

sub VIRTUAL::title {
    my ($value) = @_;
    return titlecase($value);
}

my $tt = Template->new({
    VIRTUAL => [qw( upper title )],
});

$tt->process( q{
    [% myvar = "hello world" %]
    [% myvar.upper %]
    [% myvar.title %]
} );

Output:

HELLO WORLD
Hello World

You can also specify a specific package to search for virtual methods:

my $tt = Template->new({
    VIRTUAL => [ 'My::Formatter', qw( upper title ) ],
});

This tells the toolkit to first look for methods named "upper" and "title" within the "My::Formatter" package. If not found there, it will fall back to searching the top-level namespace.

Arguments can be passed to virtual methods just like regular methods:

[% mylist = [ 1, 2, 3 ] %]
[% mylist.join(', ') %]

The "join" method is not a built-in method for arrays, so the toolkit will search for a virtual method handler. In this case, it would call the subroutine "VIRTUAL::join" (or one specified via "VIRTUAL") with "mylist" as the first argument and ", " as the second.

Note that virtual methods are only called when a method is invoked on a variable that doesn't already have that method defined in its class. Existing methods always take precedence.

Variable Interpolation

When a variable is referenced in a template, its value is typically interpolated directly into the output stream. For example:

[% name = "World" %]
Hello [% name %]!

Output:

Hello World!

This behaviour can be modified using the "ENCODING" and "OUTPUT_PATH" constructor options, along with virtual methods like "escape".

Local and Global Variables

Variables defined within a template are local to that template by default. This means they are only visible within the template where they are defined and any subsequently included templates or blocks.

If you need a variable to be accessible across all templates, regardless of include or inheritance hierarchies, you can define it in the top-level namespace. This can be done by passing the variable to the "VARS" or "LOAD" constructor options when creating the "Template" object.

my $tt = Template->new({
    VARS => {
        sitename => 'My Awesome Website',
    }
});

This variable, "sitename", will be available in all templates processed by this "Template" object.

It is generally **discouraged** that you don't update elements of complex variables from within blocks or templates included by another.

If you want to create or update truly global variables then you can use the 'global' namespace. This is a hash array automatically created in the top-level namespace which all templates, localised or otherwise see the same reference to. Changes made to variables within this hash are visible across all templates.

[% global.version = 123 %]

Compile Time Constant Folding

In addition to variables that get resolved each time a template is processed, you can also define variables that get resolved just once when the template is compiled. This generally results in templates processing faster because there is less work to be done.

To define compile-time constants, specify a "CONSTANTS" hash as a constructor item as per "VARIABLES". The "CONSTANTS" hash can contain any kind of complex, nested, or dynamic data structures, just like regular variables.

my $tt = Template->new({
    CONSTANTS => {
        version => 3.14,
        release => 'skyrocket',
        col     => {
            back => '#ffffff',
            fore => '#000000',
        },
        myobj => My::Object->new(),
        mysub => sub { ... },
        joint => ', ',
    },
});

Within a template, you access these variables using the "constants" namespace prefix.

Version [% constants.version %] ([% constants.release %])
Background: [% constants.col.back %]

When the template is compiled, these variable references are replaced with the corresponding value. No further variable lookup is then required when the template is processed.

You can call subroutines, object methods, and even virtual methods on constant variables.

[% constants.mysub(10, 20) %]
[% constants.myobj(30, 40) %]
[% constants.col.keys.sort.join(', ') %]

One important proviso is that any arguments you pass to subroutines or methods must also be literal values or compile time constants.

For example, these are both fine:

# literal argument
[% constants.col.keys.sort.join(', ') %]
# constant argument
[% constants.col.keys.sort.join(constants.joint) %]

But this next example will raise an error at parse time because "joint" is a runtime variable and cannot be determined at compile time.

# ERROR: runtime variable argument!
[% constants.col.keys.sort.join(joint) %]

The "CONSTANTS_NAMESPACE" option can be used to provide a different namespace prefix for constant variables. For example:

my $tt = Template->new({
    CONSTANTS => {
        version => 3.14,
        # ...etc...
    },
    CONSTANTS_NAMESPACE => 'const',
});

Constants would then be referenced in templates as:

[% const.version %]

Special Variables

A number of special variables are automatically defined by the Template Toolkit.

template

The "template" variable contains a reference to the main template being processed, in the form of a Template::Document object. This variable is correctly defined within "PRE_PROCESS", "PROCESS" and "POST_PROCESS" templates, allowing standard headers, footers, etc., to access metadata items from the main template. The "name" and "modtime" metadata items are automatically provided, giving the template name and modification time in seconds since the epoch.

Note that the "template" variable always references the top-level template, even when processing other template components via "INCLUDE", "PROCESS", etc.

component

The "component" variable is like "template" but always contains a reference to the current, innermost template component being processed. In the main template, the "template" and "component" variable will reference the same Template::Document object. In any other template component called from the main template, the "template" variable will remain unchanged, but "component" will contain a new reference to the current component.

This example should demonstrate the difference:

$template->process('foo')
    || die $template->error(), "\n";

foo template:

[% template.name %]         # foo
[% component.name %]        # foo
[% PROCESS footer %]

footer template:

[% template.name %]         # foo
[% component.name %]        # footer

Additionally, the "component" variable has two special fields: "caller" and "callers". "caller" contains the name of the template that called the current template (or undef if the values of "template" and "component" are the same). "callers" contains a reference to a list of all the templates that have been called on the road to calling the current component template (like a call stack), with the outer-most template first.

Here's an example:

outer.tt2 template:

[% component.name %]        # 'outer.tt2'
[% component.caller %]      # undef
[% component.callers %]     # undef
[% PROCESS 'middle.tt2' %]

middle.tt2 template:

[% component.name %]        # 'middle.tt2'
[% component.caller %]      # 'outer.tt2'
[% component.callers %]     # [ 'outer.tt2' ]
[% PROCESS 'inner.tt2' %]

inner.tt2 template:

[% component.name %]        # 'inner.tt2'
[% component.caller %]      # 'middle.tt2'
[% component.callers %]     # [ 'outer.tt2', 'middle.tt2' ]

loop

Within a "FOREACH" loop, the "loop" variable references the Template::Iterator object responsible for controlling the loop.

[% FOREACH item = [ 'foo', 'bar', 'baz' ] -%]
   [% "Items:\n" IF loop.first -%]
   [% loop.count %]/[% loop.size %]: [% item %]
[% END %]

error

Within a "CATCH" block, the "error" variable contains a reference to the Template::Exception object thrown from within the "TRY" block. The "type" and "info" methods can be called or the variable itself can be printed for automatic stringification into a message of the form ""$type error - $info"". See Template::Exception for further details.

[% TRY %]
   ...
[% CATCH %]
   [% error %]
[% END %]

content

The "WRAPPER" method captures the output from a template block and then includes a named template, passing the captured output as the 'content' variable.

[% WRAPPER box %]
Be not afeard; the isle is full of noises,
Sounds and sweet airs, that give delight and hurt not.
[% END %]
[% BLOCK box %]
<blockquote class="prose">
  [% content %]
</blockquote>
[% END %]

Compound Variables

Compound 'dotted' variables may contain any number of separate elements. Each element may evaluate to any of the permitted variable types and the processor will then correctly use this value to evaluate the rest of the variable. Arguments may be passed to any of the intermediate elements.

[% myorg.people.sort('surname').first.fullname %]

Intermediate variables may be used and will behave entirely as expected.

[% sorted = myorg.people.sort('surname') %]
[% sorted.first.fullname %]

This simplified dotted notation has the benefit of hiding the implementation details of your data. For example, you could implement a data structure as a hash array one day and then change it to an object the next without requiring any change to the templates.

This document describes the variables used in the Template Toolkit.

Variables

Variables are used to store and retrieve data within templates. They can be simple values like strings, numbers, or booleans, or complex data structures like arrays and hashes.

You can access a variable by its name. For example, if you have a variable named name, you can print its value using: 

Hello, [% name %]!

Compound Variables

Compound variables allow you to access elements within arrays and hashes.

For arrays, you can use numerical indices (starting from 0): 

The first item is: [% my_array.0 %]

For hashes, you can use keys: 

The user's email is: [% user.email %]

You can also chain these accesses together: 

The first user's email is: [% users.0.email %]
