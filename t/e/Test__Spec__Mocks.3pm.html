Test__Spec__Mocks(3pm)

الحزمة: perl-test-spec

التراخيص: PerlArtistic, GPL

Test::Spec::Mocks(3) وثائق Perl المساهمة من قبل المستخدم Test::Spec::Mocks(3)

الاسم

Test::Spec::Mocks - مكون إضافي لمحاكاة الكائنات لـ Test::Spec

الملخص

use Test::Spec;
use base qw(Test::Spec);
use My::RSS::Tool;    # هذا هو ما نختبره
use LWP::UserAgent;
describe "RSS tool" => sub {
  it "should fetch and parse an RSS feed" => sub {
    my $xml = load_rss_fixture();
    LWP::Simple->expects('get')->returns($xml);
    # يستدعي LWP::Simple::get، ولكنه يعيد $xml بدلاً من ذلك
    my @stories = My::RSS::Tool->run;
    is_deeply(\@stories, load_stories_fixture());
  };
};

الوصف

Test::Spec::Mocks هو مكون إضافي لـ Test::Spec يوفر محاكاة واستبدال للكائنات، والطرق الفردية، والروتينات الفرعية العادية على كل من مثيلات الكائنات والفئات. تم استلهام هذه الوحدة واقتبس منها بشكل كبير من Mocha، وهي مكتبة للغة البرمجة Ruby. Mocha نفسها مستوحاة من JMock.

توفر الكائنات الوهمية طريقة لمحاكاة سلوك الكائنات الحقيقية، مع توفير نتائج متسقة وقابلة للتكرار. هذا مفيد جدًا عندما تحتاج إلى اختبار وظيفة تعتمد نتائجها على عامل خارجي لا يمكن التحكم فيه عادةً (مثل الوقت من اليوم). تسمح لك الكائنات الوهمية أيضًا باختبار الكود الخاص بك بمعزل عن غيره، وهو مبدأ أساسي في اختبار الوحدة.

هناك العديد من الأسباب الأخرى التي قد تكون الكائنات الوهمية مفيدة من أجلها. راجع مقالة كائنات Mock http://en.wikipedia.org/wiki/Mock_object في ويكيبيديا للحصول على المزيد من الأمثلة وتغطية أعمق لفلسفة محاكاة الكائنات.

النظام البيئي

Test::Spec::Mocks قابلة للاستخدام حاليًا فقط من داخل الاختبارات المبنية باستخدام إطار عمل BDD الخاص بـ Test::Spec.

المصطلحات

تعرف على هذه المصطلحات:

  • كائن بديل (Stub object)

    كائن بديل هو كائن تم إنشاؤه خصيصًا لإرجاع استجابات جاهزة لمجموعة محددة من الطرق. يتم إنشاؤها باستخدام الدالة stub.

  • كائن وهمي (Mock object)

    تشبه الكائنات الوهمية الكائنات البديلة، ولكنها مبرمجة باستجابات جاهزة وتوقعات لكيفية استدعائها. إذا لم يتم استيفاء التوقعات، فإنها تثير استثناء للإشارة إلى فشل الاختبار. يتم إنشاء الكائنات الوهمية باستخدام الدالة mock.

  • طريقة مستبدلة (Stubbed method)

    تحل الطرق المستبدلة مؤقتًا محل الطرق الموجودة في فئة أو مثيل كائن. هذا مفيد عندما تريد فقط تجاوز جزء من سلوك الكائن أو الفئة. على سبيل المثال، قد ترغب في تجاوز طريقة "do" لمقبض DBI حتى لا تجري تغييرات على قاعدة بياناتك، ولكنك لا تزال بحاجة إلى أن يستجيب المقبض كالمعتاد لطريقة "quote". ستقوم باستبدال الطرق باستخدام طريقة stubs.

  • طريقة وهمية (Mocked method)

    إذا كنت قد قرأت حتى هذه النقطة، فلن يكون هذا مفاجأة. الطرق الوهمية تشبه الطرق المستبدلة، ولكنها تأتي مع توقعات ستثير استثناء إذا لم يتم استيفائها. على سبيل المثال، يمكنك إجراء محاكاة لطريقة "save" على كائن للتأكد من استدعائها بواسطة الكود الذي تختبره، مع منع البيانات من الالتزام الفعلي بالقرص في اختبارك. استخدم طريقة expects لإنشاء طرق وهمية.

  • "stub", "mock"

    اعتمادًا على السياق، يمكن أن تشير هذه إلى الكائنات والطرق المستبدلة، أو الكائنات والطرق الوهمية، على التوالي.

استخدام الكائنات البديلة (البدائل المجهولة)

في بعض الأحيان يتطلب الكود الذي تختبره تمرير كائن يلتزم بواجهة محددة. على سبيل المثال، أنت تختبر مكتبة موجهات للموجه، ولكنك لا تريد أن يتطلب شخصًا حقيقيًا بالوقوف، ينتظر كتابة الإجابات في الموجه. تتطلب المكتبة كائنًا يعيد سلسلة نصية عند استدعاء طريقة "read_line".

يمكنك إنشاء فئة خصيصًا لإرجاع إدخال الموجه للاختبار. ولكن لماذا تفعل ذلك؟ يمكنك إنشاء كائن بديل في سطر واحد:

describe "An Asker" => sub {
  my $asker = Asker->new;
  it "returns true when a yes_or_no question is answered 'yes'" => sub {
    my $console_stub = stub(read_line => "yes");
    # $console_stub->read_line يعيد "yes"
    ok( $asker->yes_or_no($console_stub, "Am I awesome?") );
  };
  it "returns false when a yes_or_no question is answered 'no'" => sub {
    my $console_stub = stub(read_line => "no");
    ok( ! $asker->yes_or_no($console_stub, "Am I second best?") );
  };
};

يمكن للبدائل أيضًا أخذ مراجع الروتينات الفرعية. هذا مفيد عندما يكون السلوك الذي تحتاج إلى محاكاته أكثر تعقيدًا قليلاً.

it "keeps asking until it gets an answer" => sub {
  my @answers = (undef, "yes");
  my $console_stub = stub(read_line => sub { shift @answers });
  # عندما يتم استدعاء console_stub للمرة الأولى، فإنه يعيد undef
  # المرة الثانية يعيد "yes"
  ok( $asker->yes_or_no($console_stub, "Do I smell nice?") );
};

استخدام الكائنات الوهمية

إذا كنت ترغب في الارتقاء باختباراتك خطوة أخرى، يمكنك استخدام الكائنات الوهمية بدلاً من الكائنات البديلة. تضمن الكائنات الوهمية استدعاء الطرق التي تتوقع استدعاءها بالفعل. إذا لم يتم استدعاءها، فإن الكائن الوهمي سيثير استثناء مما يؤدي إلى فشل اختبارك.

في هذا المثال، نختبر أن "read_line" يتم استدعاؤها مرة واحدة وفقط مرة واحدة (الافتراضي للكائنات الوهمية).

it "returns true when a yes_or_no question is answered 'yes'" => sub {
  my $console_mock = mock();
  $console_mock->expects('read_line')
               ->returns("yes");
  # $console_mock->read_line يعيد "yes"
  ok( $asker->yes_or_no($console_mock, "Am I awesome?") );
};

إذا لم تستدعِ طريقة "yes_or_no" الخاصة بـ Asker "read_line" على الكائن الوهمي الخاص بنا مرة واحدة بالضبط، سيفشل الاختبار برسالة مثل:

expected read_line to be called exactly 1 time, but it was called 0 times

يمكنك تحديد عدد المرات التي يجب استدعاء الكائن الوهمي الخاص بك بها باستخدام "exactly":

it "keeps asking until it gets an answer" => sub {
  my @answers = (undef, "yes");
  my $console_mock = mock();
  $console_mock->expects('read_line')
               ->returns(sub { shift @answers })
               ->exactly(2);
  # عندما يتم استدعاء console_mock للمرة الأولى، فإنه يعيد undef
  # المرة الثانية يعيد "yes"
  ok( $asker->yes_or_no($console_mock, "Do I smell nice?") );
};

إذا كنت تريد شيئًا أكثر مرونة من "exactly"، يمكنك الاختيار من بين "at_least"، "at_most"، "any_number" وغيرها. راجع "EXPECTATION ADJUSTMENT METHODS".

استبدال الطرق

في بعض الأحيان تريد تجاوز مجموعة صغيرة فقط من سلوك الكائن.

describe "The old audit system" => sub {
  my $dbh;
  before sub { $dbh = SomeExternalClass->get_dbh };
  it "executes the expected sql" => sub {
    my $sql;
    $dbh->stubs(do => sub { $sql = shift; return 1 });
    # $dbh->do("foo") الآن يضبط $sql على "foo"
    # $dbh->quote لا يزال يفعل ما يفعله عادةً
    audit_event($dbh, "server crash, oh noes!!");
    like( $sql, qr/insert into audit_event.*'server crash, oh noes!!!'/ );
  };
};

يمكنك أيضًا استبدال طرق الفئات:

# 1977-05-26T14:11:55
my $event_datetime = DateTime->new(from_epoch => 0xdeafcab);
it "should tag each audit event with the current time" => sub {
  DateTime->stubs('now' => sub { $event_datetime });
  is( audit_timestamp(), '19770526.141155' );
};

Test::Spec::Mocks - Test::Spec Mocks

NOMBRE

Test::Spec::Mocks - Mocks para Test::Spec

SINOPSIS

  use Test::Spec;
  use Test::Spec::Mocks;

  describe 'SomeClass' => sub {
    it 'should do something' => sub {
      my $dbh = stub();
      # Expect the do method to be called exactly once with a specific query.
      $dbh->expects('do')->with('insert into audit_event (message) values (?)')->exactly(1);

      # Simulate the action that should trigger the database call.
      some_function_that_logs_a_crash($dbh, 'server crash, oh noes!!');

      # The expectation will be verified automatically at the end of the example.
      # Or you can manually call verify($dbh);
    };

    it 'should do something else' => sub {
      my $dbh = mock(); # Use mock() to check expectations later
      $dbh->expects('do')->once;

      some_function_that_logs_a_crash($dbh, 'server crash, oh noes!!!');

      verify($dbh); # Explicitly verify expectations
    };
  };

DESCRIPCIÓN

Este módulo provee un sistema de mocking simple y dulce para Test::Spec.

A diferencia de otros sistemas de mocking, esto se integra directamente en la ejecución de Test::Spec, lo que significa que las expectativas se verifican automáticamente al final de cada ejemplo.

server crash, oh noes!!);
  like( $sql, qr/insert into audit_event.*'server crash, oh noes!!!'/ );
  # if audit_event doesn't call $dbh->do exactly once, KABOOM!
};

CONSTRUCTORES

stub()
stub($method_name => $result, ...)
stub($method_name => sub { $result }, ...)
stub({ $method_name => $result, ... })
Devuelve un nuevo objeto stub anónimo. Toma una lista de pares $method_name/$result o una referencia a un hash que contenga lo mismo. Cada $method_name listado es "stubbed" para devolver el valor asociado ($result); o si el valor es una referencia a una subrutina, se "stubbea" en el lugar (la subrutina se convierte en el método).

Ejemplos:

# Un objeto en blanco sin métodos.
# Devuelve una respuesta verdadera a ref() y blessed().
my $blank = stub();
# Respuestas estáticas a width() y height():
my $rect = stub(width => 5, height => 5);
# Respuesta dinámica a area():
my $radius = 1.0;
my $circle_stub = stub(area => sub { PI * $radius * $radius });

También puedes hacer "stub" a más métodos, al igual que con cualquier otro objeto:

my $rect = stub(width => 5, height => 5);
$rect->stubs(area => sub { my $self = shift; $self->width * $self->height });
$thing->stubs($method_name)
$thing->stubs($method_name => $result)
$thing->stubs($method_name => sub { $result })
$thing->stubs({ $method_name => $result })
Hace "stub" a uno o más métodos en una clase o instancia existente, $thing.

Si se pasa solo un argumento (que no sea hash), se interpreta como un nombre de método. El valor de retorno del método "stubbeado" será "undef".

De lo contrario, los argumentos son una lista de pares $method_name y $result, ya sea como una lista plana o como una referencia a hash. Cada método se instala en $thing y devuelve el resultado especificado. Si el resultado es una referencia a subrutina, se llamará para cada invocación del método.

mock()
Devuelve un nuevo objeto mock anónimo y en blanco, adecuado para hacer mocking de métodos con expects(). 
my $rect = mock();
$rect->expects('area')->returns(100);
$thing->expects($method)
Instala un método mock llamado $method en la clase o objeto $thing y devuelve un objeto Test::Spec::Mocks::Expectation, que puedes usar para establecer el valor de retorno con returns() y otras expectativas. Por defecto, se espera que el método se llame at_least_once.

Si la expectativa no se cumple antes de que el ejemplo que la contiene se complete, el método mockeará lanzará una excepción que se verá algo así como:

expected foo to be called exactly 1 time, but it was called 0 times

MÉTODOS DE AJUSTE DE EXPECTATIVAS

Estos son métodos de la clase Test::Spec::Mocks::Expectation, que recibirás llamando a expects() en una clase o instancia de objeto.

returns( $result )
returns( @result )
returns( \&callback )
Configura el método mock para que devuelva el resultado especificado cuando se llame. Si se pasa una referencia a subrutina, la subrutina se ejecutará cuando se llame al método, y el resultado es el valor de retorno. 
$rect->expects('height')->returns(5);
# $rect->height ==> 5
@points = ( [0,0], [1,0], [1,1], [1,0] );
$rect->expects('points')->returns(@points);
# (@p = $rect->points) ==> ( [0,0], [1,0], [1,1], [1,0] )
# ($p = $rect->points) ==> 4
@points = ( [0,0], [1,0], [1,1], [1,0] );
$rect->expects('next_point')->returns(sub { shift @points });
# $rect->next_point ==> [0,0]
# $rect->next_point ==> [1,0]
# ...
exactly($N)
Configura el método mock para que deba llamarse exactamente $N veces.
never
Configura el método mock para que nunca deba llamarse.
once
Configura el método mock para que deba llamarse exactamente una vez.
at_least($N)
Configura el método mock para que deba llamarse al menos $N veces.
at_least_once
Configura el método mock para que deba llamarse al menos 1 vez. Esto es solo azúcar sintáctico para at_least(1).
at_most($N)
Configura el método mock para que no deba llamarse más de $N veces.
at_most_once
Configura el método mock para que deba llamarse cero o 1 vez.
maybe
Un alias para "at_most_once".
any_number
Configura el método mock para que pueda llamarse cero o más veces.
times
Un no-op de azúcar sintáctico: 
$io->expects('print')->exactly(3)->times;

Este método es alfa y probablemente cambiará en una versión futura.

with(@arguments) / with_eq(@arguments)
Configura el método mock para que deba llamarse con los argumentos especificados. Los argumentos se compararán usando el operador "eq", por lo que funciona para la mayoría de los valores escalares sin problemas. Si deseas verificar objetos aquí, deben ser la instancia exacta o debes sobrecargar el operador "eq" para proporcionar el comportamiento que deseas.
with_deep(@arguments)
Similar a "with_eq" excepto que los argumentos se comparan usando Test::Deep: los escalares se comparan por valor, los arrays y hashes deben tener los mismos elementos y las referencias deben estar "blessed" en la misma clase. 
$cache->expects('set')
      ->with_deep($customer_id, { name => $customer_name });

Usa las funciones de comparación de Test::Deep para mayor flexibilidad:

use Test::Deep::NoTest ();
$s3->expects('put')
   ->with_deep('test-bucket', 'my-doc', Test::Deep::ignore());
raises($exception)
Configura el método mock para que lance $exception cuando se llame.

OTROS MÉTODOS DE EXPECTATIVA

verify
Permite verificar manualmente que la expectativa se cumplió. Si la expectativa no se cumplió, el método muere con un mensaje de error que contiene detalles del fallo. Devuelve verdadero en caso contrario.
problems
Si la expectativa no se cumplió, devuelve una lista de cadenas de descripción de problemas. De lo contrario, devuelve una lista vacía.

PROBLEMAS CONOCIDOS

Fugas de memoria
Debido a la forma en que los objetos mock ("stubs", "stub", "expects", y "mock") se integran en el tiempo de ejecución de Test::Spec, filtrarán memoria. No se recomienda usar los mocks de Test::Spec en ningún programa de larga duración.

Parches bienvenidos.

VER TAMBIÉN

Existen otros sistemas de mocking menos "azucarados" para Perl, incluyendo Test::MockObject y Test::MockObject::Extends.
