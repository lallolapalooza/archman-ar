الحزمة: perl

التراخيص: Artistic-1.0-Perl OR GPL-1.0-or-later

Test2::Tools::Spec(3perl) دليل مبرمجي بيرل Test2::Tools::Spec(3perl)

الاسم

Test2::Tools::Spec - تطبيق RSPEC فوق Test2::Workflow

الوصف

هذا يستخدم Test2::Workflow لتطبيق صيغة RSPEC. هذه الصيغة تدعم العزل و/أو التوازي عبر التشعب أو المواضيع.

الملخص

use Test2::Bundle::Extended;
use Test2::Tools::Spec;
describe foo => sub {
    before_all  once => sub { ... };
    before_each many => sub { ... };
    after_all  once => sub { ... };
    after_each many => sub { ... };
    case condition_a => sub { ... };
    case condition_b => sub { ... };
    tests foo => sub { ... };
    tests bar => sub { ... };
};
done_testing;

التصدير

كل هذه تستخدم نفس نمط الوسائط. الوسيط الأول يجب أن يكون دائمًا اسمًا للكتلة. الوسيط الأخير يجب أن يكون دائمًا مرجعًا للكود.

FUNCTION "name" => sub { ... };
FUNCTION "name" => {...}, sub { ... };
الاسم
الوسيط الأول لدالة Test2::Tools::Spec يجب أن يكون اسمًا. لا يحتاج الاسم إلى أن يكون فريدًا.
الوسائط
هذا الوسيط اختياري. إذا كان موجودًا، فيجب أن يكون hash-ref.

هنا المفاتيح الصالحة لـ hash-ref:

flat => $bool
إذا تم تعيين هذا إلى صحيح، فلن يتم تقديم الكتلة كاختبار فرعي، بدلاً من ذلك، ستكون الأحداث ضمن الاختبار الفرعي الأم (أو الاختبار الرئيسي).
async => $bool
قم بتعيين هذا إلى صحيح لتمييز كتلة على أنها قادرة على التشغيل بشكل متزامن مع كتل الاختبار الأخرى. هذا لا يعني أن الكتلة سيتم تشغيلها بشكل متزامن، بل فقط أنها يمكن أن تكون كذلك.
iso => $bool
قم بتعيين هذا إلى صحيح إذا كان يجب تشغيل الكتلة بشكل معزول. إذا كان هذا صحيحًا، فسيتم تشغيل الكتلة في عمليتها المتشعبة الخاصة.

سيتم تخطي هذه الاختبارات على أي منصة لا تحتوي على تشعب حقيقي، أو مواضيع عاملة/ممكنة.

سيتم استخدام المواضيع فقط إذا تم تعيين متغير البيئة T2_WORKFLOW_USE_THREADS. سيتم تشغيل اختبارات المواضيع فقط إذا تم تعيين متغير البيئة T2_DO_THREAD_TESTS.

todo => $reason
استخدم هذا لتمييز كتلة كاملة على أنها TODO (قيد العمل).
skip => $reason
استخدم هذا لمنع كتلة من التشغيل على الإطلاق.
مرجع الكود
هذا الوسيط مطلوب. يجب أن يكون مرجعًا للكود سيقوم بتشغيل بعض التأكيدات.

الأساسيات

tests NAME => sub { ... }
tests NAME => \%params, sub { ... }
tests($NAME, \%PARAMS, \&CODE)
it NAME => sub { ... }
it NAME => \%params, sub { ... }
it($NAME, \%PARAMS, \&CODE)
هذا يعرف كتلة اختبار. كتل الاختبار هي في الأساس اختبارات فرعية. سيتم تشغيل جميع كتل الاختبار، ويُتوقع منها إنتاج أحداث. يمكن تشغيل كتل الاختبار عدة مرات إذا تم استخدام دالة case() أيضًا.

it() هو اسم مستعار لـ tests().

هذه لا يتم توريثها بواسطة كتل describe المتداخلة.

case NAME => sub { ... }
case NAME => \%params, sub { ... }
case($NAME, \%PARAMS, \&CODE)
هذا يسمح لك بتحديد شروط متعددة يتم فيها تشغيل كتل الاختبار. سيتم تشغيل كل كتلة اختبار داخل نفس المجموعة ("describe") مرة واحدة لكل حالة.

هذه لا يتم توريثها بواسطة كتل describe المتداخلة، ولكن سيتم تنفيذ كتل describe المتداخلة مرة واحدة لكل حالة.

before_each NAME => sub { ... }
before_each NAME => \%params, sub { ... }
before_each($NAME, \%PARAMS, \&CODE)
حدد كتلة كود يجب تشغيلها عدة مرات، مرة قبل تشغيل كل كتلة tests(). سيتم تشغيل هذه بعد كتل case() ولكن قبل كتل tests().

هذه يتم توريثها بواسطة كتل describe المتداخلة.

before_case NAME => sub { ... }
before_case NAME => \%params, sub { ... }
before_case($NAME, \%PARAMS, \&CODE)
نفس before_each()، باستثناء أن هذه الكتل تعمل قبل كتل case().

هذه لا يتم توريثها بواسطة كتل describe المتداخلة.

before_all NAME => sub { ... }
before_all NAME => \%params, sub { ... }
before_all($NAME, \%PARAMS, \&CODE)
حدد كتلة كود يجب تشغيلها مرة واحدة، قبل تشغيل جميع كتل الاختبار.

هذه لا يتم توريثها بواسطة كتل describe المتداخلة.

around_each NAME => sub { ... }
around_each NAME => \%params, sub { ... }
around_each($NAME, \%PARAMS, \&CODE)
حدد كتلة كود يجب أن تحيط بكل كتلة اختبار. تعمل هذه الكتل بعد كتل case، ولكن قبل كتل الاختبار. 
around_each wrapit => sub {
    my $cont = shift;
    local %ENV = ( ... );
    $cont->();
    ...
};

الوسيط الأول لكتلة الكود سيكون استدعاء يجب استدعاؤه في مكان ما داخل الدالة الفرعية للسماح بتشغيل العناصر المتداخلة.

هذه يتم توريثها بواسطة كتل describe المتداخلة.

around_case NAME => sub { ... }
around_case NAME => \%params, sub { ... }
around_case($NAME, \%PARAMS, \&CODE)
نفس "around_each" باستثناء أن هذه تعمل قبل كتل case.

هذه لا يتم توريثها بواسطة كتل describe المتداخلة.

around_all NAME => sub { ... }
around_all NAME => \%params, sub { ... }
around_all($NAME, \%PARAMS, \&CODE)
نفس "around_each" باستثناء أنها تعمل مرة واحدة فقط لتغليف جميع كتل الاختبار.

هذه لا يتم توريثها بواسطة كتل describe المتداخلة.

after_each NAME => sub { ... }
after_each NAME => \%params, sub { ... }
after_each($NAME, \%PARAMS, \&CODE)

اختصارات

هذه اختصارات. كل منها يعادل tests() إلا أن بعض المعلمات تُضاف لك تلقائيًا.

هذه ليست مُصدَّرة بشكل افتراضي.

mini NAME => sub { ... }
يعادل: 
tests NAME => { flat => 1 }, sub { ... }
iso NAME => sub { ... }
يعادل: 
tests NAME => { iso => 1 }, sub { ... }
miso NAME => sub { ... }
يعادل: 
tests NAME => { mini => 1, iso => 1 }, sub { ... }
async NAME => sub { ... }
يعادل: 
tests NAME => { async => 1 }, sub { ... }

ملاحظة: يتعارض هذا مع async() المُصدَّر من threads. لا تستورد كلاهما.

masync NAME => sub { ... }
يعادل: 
tests NAME => { minit => 1, async => 1 }, sub { ... }

افتراضات سمات مخصصة

أحيانًا تريد تطبيق سمات افتراضية على جميع كتل tests() أو case(). يمكن القيام بذلك، وهو مخصص لنطاق descibe أو حزمة الجذر!

use Test2::Bundle::Extended;
use Test2::Tools::Spec ':ALL';
# سيتم تعيين جميع كتل 'tests' بعد هذا الإعلان على C<<iso => 1>> افتراضيًا
spec_defaults tests => (iso => 1);
tests foo => sub { ... }; # معزولة
tests foo, {iso => 0}, sub { ... }; # غير معزولة
spec_defaults tests => (iso => 0); # إيقافها مرة أخرى

تُورَّث الافتراضات من كتل descibe المتداخلة. يمكنك أيضًا تجاوز الافتراضات لنطاق descibe:

spec_defaults tests => (iso => 1);
describe foo => sub {
    spec_defaults tests => (async => 1); # مُقيدة بهذا descibe وأي descibe فرعية
    tests bar => sub { ... }; # iso و async
};
tests baz => sub { ... }; # iso فقط، لا يوجد async.

يمكنك تطبيق الافتراضات على أي نوع من الكتل:

spec_defaults case => (iso => 1); # جميع الحالات 'iso'؛

لا تُورَّث الافتراضات عندما يتم التقاط نتيجة مُنشئ.

spec_defaults tests => (iso => 1);
# لاحظ أننا لا نستدعي هذا في سياق void، هذا هو المفتاح.
my $d = describe foo => {
    tests bar => sub { ... }; # ليس iso
};

ترتيب التنفيذ

عند مواجهة كل دالة، يتم تنفيذها، تمامًا مثل أي دالة أخرى. ستقوم دالة describe() بتنفيذ كتلة التعليمات البرمجية التي تُعطى لها على الفور. ستقوم جميع الدوال الأخرى بتخزين كتل التعليمات البرمجية الخاصة بها لتشغيلها لاحقًا. عندما يتم تشغيل done_testing()، سيتم تجميع سير العمل، وعند هذه النقطة سيتم تشغيل جميع الكتل الأخرى.

هذا نظرة عامة على الترتيب الذي تُستدعى به الكتل بعد تجميعها (عند done_testing()).

before_all
    for-each-case {
        before_case
            case
        after_case
        # و/أو descibe متداخلة
        before_each
            tests
        after_each
    }
after_all
