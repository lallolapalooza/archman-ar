Test2::API(3perl) دليل مبرمجي Perl Test2::API(3perl)

الاسم

Test2::API - الواجهة الرئيسية لكتابة أدوات اختبار تستند إلى Test2.

***ملاحظة حول التفاصيل الداخلية***

التفاصيل الداخلية لهذه الحزمة عرضة للتغيير في أي وقت! لن تتغير الطرق العامة المقدمة بطرق تتعارض مع التوافق السابق (بمجرد وجود إصدار مستقر)، ولكن قد تتغير تفاصيل التنفيذ الأساسية. لا تخرق التغليف هنا!

حاليًا، يتمثل التنفيذ في إنشاء مثيل واحد لكائن Test2::API::Instance. جميع طرق الفئة تحيل إلى المثيل الوحيد. لا يوجد وصول عام إلى المفرد، وهذا متعمد. توفر طرق الفئة التي توفرها هذه الحزمة الوظائف الوحيدة المكشوفة علنًا.

يتم ذلك بشكل أساسي لتجنب المشاكل التي واجهتها Test::Builder من خلال الكشف عن مفرداتها. لا نريد لأحد استبدال هذا المفرد، أو إعادة ربطه، أو العبث مباشرة بتفاصيله الداخلية. إذا كنت بحاجة إلى القيام بشيء ولا يمكنك القيام به بسبب القيود المفروضة هنا، فيرجى الإبلاغ عنه كمسألة. إذا أمكن، سنقوم بإنشاء طريقة لك لتنفيذ وظائفك دون الكشف عن الأشياء التي لا ينبغي الكشف عنها.

الوصف

تُصدّر هذه الحزمة جميع الوظائف اللازمة لكتابة و/أو التحقق من أدوات الاختبار. باستخدام هذه اللبنات الأساسية، يمكنك البدء في كتابة أدوات اختبار بسرعة كبيرة. كما يتم تزويدك بأدوات تساعدك على اختبار الأدوات التي تكتبها.

الملخص

كتابة أداة

طريقة context() هي واجهتك الرئيسية في إطار عمل Test2.

package My::Ok;
use Test2::API qw/context/;
our @EXPORT = qw/my_ok/;
use base 'Exporter';
# تمامًا مثل ok() من Test::More
sub my_ok($;$) {
    my ($bool, $name) = @_;
    my $ctx = context(); # الحصول على سياق
    $ctx->ok($bool, $name);
    $ctx->release; # تحرير السياق
    return $bool;
}

راجع Test2::API::Context للحصول على قائمة بالطرق المتاحة على كائن السياق.

اختبار أدواتك

الأداة "intercept { ... }" تتيح لك اعتراض جميع الأحداث التي يولدها نظام الاختبار مؤقتًا:

use Test2::API qw/intercept/;
use My::Ok qw/my_ok/;
my $events = intercept {
    # هذه الأحداث لا تظهر
    my_ok(1, "pass");
    my_ok(0, "fail");
};

اعتبارًا من الإصدار 1.302178، تعود هذه الآن بمصفوفة وهي أيضًا مثيل لـ Test2::API::InterceptResult. راجع توثيق Test2::API::InterceptResult للحصول على تفاصيل حول كيفية استخدامها على أفضل وجه.

متغيرات البيئة

راجع Test2::Env للحصول على قائمة بمتغيرات البيئة الهامة.

تصديرات API الرئيسية

جميع الصادرات اختيارية. يجب عليك تحديد الوظائف المراد استيرادها.

use Test2::API qw/context intercept run_subtest/;

هذه هي قائمة الصادرات الأكثر شيوعًا. إذا كنت تكتب أداة ببساطة، فهذا على الأرجح كل ما تحتاجه. إذا احتجت شيئًا ولم تتمكن من العثور عليه هنا، يمكنك أيضًا البحث في "تصديرات API أخرى".

تفتقر هذه الصادرات إلى البادئة 'test2_' بسبب أهميتها/شيوعها. الصادرات في قسم "تصديرات API أخرى" لها البادئة 'test2_' لضمان بروزها.

context(...)

الاستخدام:

$ctx = context()
$ctx = context(%params)

ستقوم وظيفة context() دائمًا بإرجاع السياق الحالي. إذا كان هناك سياق نشط بالفعل، فسيتم إرجاعه. إذا لم يكن هناك سياق نشط، فسيتم إنشاء واحد. عند إنشاء سياق، فإنه سيستخدم افتراضيًا الملف ورقم السطر حيث تم استدعاء الوظيفة قيد التشغيل حاليًا.

يرجى الرجوع إلى "تفاصيل حرجة" في Test2::API::Context للحصول على قواعد هامة حول ما يمكنك وما لا يمكنك فعله بسياق بمجرد الحصول عليه.

ملاحظة ستلقي هذه الوظيفة استثناءً إذا تجاهلت كائن السياق الذي تعيده.

ملاحظة على إصدارات Perl 5.14+، يتم استخدام فحص العمق لضمان عدم وجود تسريبات للسياق. لا يمكن القيام بذلك بأمان على إصدارات Perl الأقدم بسبب https://rt.perl.org/Public/Bug/Display.html?id=127774 يمكنك تمكينه بالقوة إما عن طريق تعيين "$ENV{T2_CHECK_DEPTH} = 1" أو "$Test2::API::DO_DEPTH_CHECK = 1" قبل تحميل Test2::API.

معلمات اختيارية

جميع معلمات "context" اختيارية.

level = > $int
إذا كان عليك الحصول على سياق في وظيفة أعمق من نقطة الدخول الخاصة بك، يمكنك استخدام هذا لإخباره بعدد إضافي من إطارات المكدس للبحث للخلف. إذا لم يتم توفير هذه المعلمة، يتم استخدام القيمة الافتراضية 0. 
sub third_party_tool {
    my $sub = shift;
    ... # لا يحصل على سياق
    $sub->();
    ...
}
third_party_tool(sub {
    my $ctx = context(level => 1);
    ...
    $ctx->release;
});
wrapped = > $int
استخدم هذا إذا كنت بحاجة إلى كتابة أداتك الخاصة التي تغلف استدعاءً لـ context() بنية إرجاع كائن سياق. 
sub my_context {
    my %params = ( wrapped => 0, @_ );
    $params{wrapped}++;
    my $ctx = context(%params);
    ...
    return $ctx;
}
sub my_tool {
    my $ctx = my_context();
    ...
    $ctx->release;
}

إذا لم تقم بذلك، فإن الأدوات التي تستدعيها والتي تتحقق أيضًا من وجود سياق ستلاحظ أن السياق الذي حصلت عليه تم إنشاؤه بنفس عمق المكدس، مما سيؤدي إلى تشغيل إجراءات حماية تنبهك وتدمر السياق الموجود.

stack = > $stack
عادةً ما تبحث context() في مكدس التوجيه العالمي. إذا كنت تحتفظ بمثيل Test2::API::Stack الخاص بك، فقد تمرره ليتم استخدامه بدلاً من المكدس العالمي.
hub = > $hub
استخدم هذه المعلمة إذا كنت ترغب في الحصول على السياق لموجه محدد بدلاً من أي موجه يوجد في قمة المكدس.
on_init = > sub { ... }
يتيح لك هذا توفير وظيفة استدعاء سيتم استدعاؤها فقط إذا قام استدعاؤك لـ context() بإنشاء سياق جديد. لن يتم استدعاء وظيفة الاستدعاء إذا كانت context() تعيد سياقًا موجودًا. الوسيطة الوحيدة التي تم تمريرها إلى وظيفة الاستدعاء ستكون كائن السياق نفسه. 
sub foo {
    my $ctx = context(on_init => sub { 'will run' });
    my $inner = sub {
        # لا يتم تشغيل وظيفة الاستدعاء هذه لأننا نحصل على السياق الحالي
        # من الوظيفة الأصلية.
        my $ctx = context(on_init => sub { 'will NOT run' });
        $ctx->release;
    }
    $inner->();
    $ctx->release;
}
on_release = > sub { ... }
يتيح لك هذا توفير وظيفة استدعاء سيتم استدعاؤها عند تحرير مثيل السياق. ستتم إضافة وظيفة الاستدعاء هذه إلى السياق المُعاد حتى لو تم إرجاع سياق موجود. إذا قامت استدعاءات متعددة لـ context بإضافة وظائف استدعاء، فسيتم استدعاء جميعها بترتيب عكسي عند تحرير السياق في النهاية. 
sub foo {
    my $ctx = context(on_release => sub { 'will run second' });
    my $inner = sub {
        my $ctx = context(on_release => sub { 'will run first' });
        # لا يتم تشغيل أي من وظيفتي الاستدعاء عند هذا التحرير

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

$SIG{__WARN__} = sub { my ($warning) = @_; if (test2_is_testing_done()) { warn @_; } else { my $ctx = context(); ... $ctx->release } };
test2_ipc_disable
تعطيل IPC.
$bool = test2_ipc_disabled
التحقق مما إذا كان IPC معطلاً.
test2_ipc_wait_enable()
test2_ipc_wait_disable()
$bool = test2_ipc_wait_enabled()
يمكن استخدام هذه لتشغيل أو إيقاف تشغيل انتظار IPC، أو التحقق من القيمة الحالية للعلم.

الانتظار معطل افتراضيًا. سيؤدي الانتظار إلى توقف العملية الأصل/الخيط حتى تنتهي جميع العمليات/الأخيطة الفرعية قبل الخروج. نادرًا ما تريد تعطيل هذه الميزة.

$bool = test2_no_wait()
test2_no_wait($bool)
غير مستحسن: هذه الواجهة مربكة، من الأفضل استخدام test2_ipc_wait_enable() و test2_ipc_wait_disable() و test2_ipc_wait_enabled().

يمكن استخدام هذا للحصول على / تعيين حالة عدم الانتظار. الانتظار ممكّن افتراضيًا. سيؤدي الانتظار إلى توقف العملية الأصل/الخيط حتى تنتهي جميع العمليات/الأخيطة الفرعية قبل الخروج. نادرًا ما تريد تعطيل هذه الميزة.

$fh = test2_stdout()
$fh = test2_stderr()
تقوم هذه الدوال بإرجاع مقابض الملفات التي يجب أن يُكتب إليها خرج الاختبارات. وهي مفيدة بشكل أساسي عند كتابة منسق مخصص وكود يحول الأحداث إلى إخراج (TAP، وما إلى ذلك). ستعيد نسخة من الأصل، بغض النظر عن حالة الاختبار قيد التشغيل، سيكون STDOUT و STDERR متماثلين.
test2_reset_io()
إعادة إنشاء مقابض الملفات الداخلية التي تم إرجاعها بواسطة test2_stdout() و test2_stderr() من STDOUT و STDERR الحاليين. لا ينبغي أن تكون هناك حاجة إليها إلا في مواقف غريبة جدًا (على سبيل المثال، عند اختبار منسق جديد وتريد التحكم في مكان إرسال إخراج المنسق).

خطافات السلوك

هذه هي إدخالات الخطافات التي تسمح بإضافة سلوك مخصص إلى الإجراءات التي تتخذها Test2 والأدوات المبنية عليها.

test2_add_callback_exit(sub { ... })
يمكن استخدام هذا لإضافة دالة استدعاء يتم استدعاؤها بعد انتهاء جميع الاختبارات. فات الأوان لإضافة نتائج جديدة، الاستخدام الرئيسي لدالة الاستدعاء هذه هو تعيين رمز الخروج. 
test2_add_callback_exit(
    sub {
        my ($context, $exit, \$new_exit) = @_;
        ...
    }
);

سيكون $context الذي تم تمريره مثيلًا لـ Test2::API::Context. ستكون الوسيطة $exit هي رمز الخروج الأصلي قبل تعديله. $$new_exit هو مرجع لرمز الخروج الجديد. يمكنك تعديله لتغيير رمز الخروج. يرجى ملاحظة أن $$new_exit قد يكون بالفعل مختلفًا عن $exit

test2_add_callback_post_load(sub { ... })
إضافة دالة استدعاء يتم تشغيلها عند انتهاء Test2 من التحميل. هذا يعني أنه سيتم تشغيل دالة الاستدعاء مرة واحدة، في المرة الأولى التي يتم فيها الحصول على سياق. إذا انتهى Test2 بالفعل من التحميل، فسيتم تشغيل دالة الاستدعاء على الفور.
test2_add_callback_testing_done(sub { ... })
يضيف هذا مرجع الكود الخاص بك كمتابع للمحور الجذر بعد انتهاء Test2 من التحميل.

هذه في الأساس مساعد للقيام بما يلي:

test2_add_callback_post_load(sub {
    my $stack = test2_stack();
    $stack->top; # تأكد من حصولك على محور
    my ($hub) = Test2::API::test2_stack->all;
    $hub->set_active(1);
    $hub->follow_up(sub { ... }); # <-- مرجع الكود الخاص بك هنا
});
test2_add_callback_context_acquire(sub { ... })
إضافة دالة استدعاء يتم تشغيلها في كل مرة يحاول فيها شخص ما الحصول على سياق. سيتم تشغيل هذا في كل استدعاء لـ context(). سيتم استلام وسيطة واحدة، مرجع إلى المعلمات المستخدمة لإنشاء السياق. هذه فرصتك لتغيير المعلمات عن طريق تعديل الهاش مباشرة. 
test2_add_callback_context_acquire(sub {
    my $params = shift;
    $params->{level}++;
});

هذه وظيفة API خطيرة للغاية. يرجى عدم استخدام هذا إلا إذا كنت بحاجة ماسة إليه. إنه موجود هنا لـ Test::Builder والتوافق مع الإصدارات السابقة. يقوم هذا بتعديل الهاش مباشرة بدلاً من إرجاع واحد جديد لأسباب تتعلق بالأداء.

test2_add_callback_context_init(sub { ... })
إضافة دالة استدعاء يتم تشغيلها في كل مرة يتم فيها إنشاء سياق جديد. ستستلم دالة الاستدعاء السياق الجديد كوسيطة وحيدة.
test2_add_callback_context_release(sub { ... })
إضافة دالة استدعاء يتم تشغيلها في كل مرة يتم فيها تحرير سياق. ستستلم دالة الاستدعاء السياق المحرر كوسيطة وحيدة.
test2_add_callback_pre_subtest(sub { ... })
إضافة دالة استدعاء يتم تشغيلها في كل مرة على وشك تشغيل اختبار فرعي. ستستلم دالة الاستدعاء اسم الاختبار الفرعي، ومرجع الكود، وأي وسيطات.
@list = test2_list_context_acquire_callbacks()
إرجاع جميع مراجع استدعاءات الحصول على السياق.
@list = test2_list_context_init_callbacks()
إرجاع جميع مراجع استدعاءات تهيئة السياق.
@list = test2_list_context_release_callbacks()
إرجاع جميع مراجع استدعاءات تحرير السياق.
@list = test2_list_exit_callbacks()
إرجاع جميع مراجع استدعاءات الخروج.
@list = test2_list_post_load_callbacks()
إرجاع جميع مراجع استدعاءات ما بعد التحميل.
@list = test2_list_pre_subtest_callbacks()
إرجاع جميع مراجع استدعاءات ما قبل الاختبار الفرعي.
test2_add_uuid_via(sub { ... })
$sub = test2_add_uuid_via()
يسمح هذا بتوفير مولد UUID. إذا تم توفير معرفات UUID، فسيتم إضافتها إلى جميع الأحداث والمحاور والسياقات. هذا مفيد لتخزين وتتبع وربط هذه الكائنات.

يجب أن تعيد الدالة الفرعية التي تقدمها دائمًا معرّفًا فريدًا. تتوقع معظم الكائنات سلسلة UUID، على الرغم من أن Test2::API لا تفرض أي شيء.

ستستلم الدالة الفرعية وسيطة واحدة بالضبط، وهو نوع الكائن الذي سيتم وضع علامة عليه "context" أو "hub" أو "event". في المستقبل، قد يتم وضع علامة على المزيد من الكائنات، وفي هذه الحالة سيتم تمرير سلاسل جديدة. هذه إعلامية، يمكنك تجاهلها (ويجب عليك تقريبًا دائمًا).

test2_add_pending_diag($diag)
test2_add_pending_diag($diag1, $diag2)
إضافة رسالة تشخيص سيتم إصدارها في المرة التالية التي يتم فيها تحرير سياق حدث فيه فشل.

يمكن أيضًا التفكير في هذا على أنه: "إذا تسبب الجزء التالي في فشل تأكيد، فأضف رسالة التشخيص هذه".

@diags = test2_get_pending_diags()
الحصول على جميع رسائل التشخيص المعلقة الحالية.
@diags = test2_clear_pending_diags()
مسح أي رسائل تشخيص معلقة، وإعادتها.

IPC والتزامن

تسمح هذه بالوصول إلى، أو تحديد، الأنظمة الداخلية لـ IPC.

$bool = test2_has_ipc()
التحقق مما إذا كان IPC نشطًا.
$ipc = test2_ipc()
ستعيد هذه النسخة العامة من Test2::IPC::Driver. إذا لم يتم تهيئتها بعد، فستقوم بتهيئتها الآن.
test2_ipc_add_driver($DRIVER)
إضافة مشغل IPC إلى القائمة. سيضيف هذا المشغل إلى بداية القائمة.
@drivers = test2_ipc_drivers()
الحصول على قائمة مشغلات IPC.
$bool = test2_ipc_polling()
التحقق مما إذا كان الاستقصاء نشطًا.
test2_ipc_enable_polling()
تمكين الاستقصاء. في كل مرة يتم فيها إنشاء سياق، سيتم إزالة الأحداث من العمليات والخيوط الأخرى.
test2_ipc_disable_polling()
تعطيل استقصاء IPC.
test2_ipc_enable_shm()
قديم، هذا حاليًا لا يفعل شيئًا ويعيد 0؛
test2_ipc_set_pending($uniq_val)
إخبار العمليات والأحداث الأخرى بأن هناك حدثًا معلقًا. $uniq_val يجب أن يكون قيمة فريدة غير مولدة بواسطة خيوط / عمليات أخرى.

ملاحظة: بعد استدعاء test2_ipc_get_pending()، ستعيد 1. هذا مقصود ولا يمكن تجنبه.

$pending = test2_ipc_get_pending()
يعيد -1 إذا لم تكن هناك طريقة للتحقق (نفترض أن هناك).

يعيد 0 إذا لم تكن هناك (على الأرجح) أحداث معلقة.

يعيد 1 إذا كانت هناك (على الأرجح) أحداث معلقة. عند الإرجاع، يعيد الضبط، لا يمكن لأحد آخر رؤية أن هناك أحداثًا معلقة.

$timeout = test2_ipc_get_timeout()
