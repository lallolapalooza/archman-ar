NAME

texfot - filter output from TeX to show only messages that might require action

SYNOPSIS

texfot [--no-something] [--only-something] [--version] [--help] [file ...]

DESCRIPTION

This script filters the standard output of tex(1) and its relatives (latex(1), pdftex(1), etc.) to show only messages which might require action by the user. The point is to suppress the long lists of style files and fonts being read, and to show only the warnings, errors, and other messages that are worth paying attention to.

The filtering is done by consulting a list of messages which typically need no action. These are primarily the messages given when style files, packages, or fonts are loaded.

The script works by reading the standard output of the TeX program and writing a filtered version to its own standard output. If arguments are given, they are treated as filenames, and texfot will read them one by one and process them. If no arguments are given, texfot reads from its standard input.

The typical usage is:

tex ... | texfot

or

tex ... > output.log
texfot output.log

The latter usage is more useful if you want to keep the log file for other purposes.

FLOW OF OPERATION

The script operates in two passes. In the first pass, it reads the entire input, looking for messages that it knows are ignorable. The messages are identified by matching patterns on the input lines. The typical ignorable messages are those related to loading files ("\input ...", "This is pdfTeX, Version ...", "entering extended mode", etc.) and those related to font loading ("Using font ...", "{", etc.).

In the second pass, the script writes out all lines that were not identified as ignorable in the first pass. In this way, it guarantees that all potentially interesting messages are shown, and nothing else.

OPTIONS

--no-something
Suppress messages of the given type. For example, --no-input suppresses messages about files being read. See the --help output for a full list of options.
--only-something
Show only messages of the given type. For example, --only-warning shows only warning messages. This option overrides --no- options. See the --help output for a full list of options.

RATIONALE

I wrote this because, in my work as a TUGboat editor (https://tug.org/TUGboat, article submissions always welcome!), I run and rerun many documents, many times each. It was easy to lose warnings I needed to see in the mass of unvarying and uninteresting output from TeX, such as style files being read and fonts being used. I wanted to see all and only those messages which needed some action by me.

I found some other programs of a similar nature, the LaTeX package "silence", and plenty of other (La)TeX wrappers, but it seemed none of them did what I wanted. Either they read the log file (I wanted to look at only the online output), or they output more, or less, than I wanted, or they required invoking TeX differently (I wanted to keep my build process exactly the same, most critically the TeX invocation, which can get complicated). Hence I wrote this little script.

Here are some keywords if you want to explore other options: texloganalyser, pydflatex, logfilter, latexmk, rubber, arara, and searching for "log" at https://ctan.org/search.

"texfot" is written in Perl, and runs on Unix. It may work on Windows if Perl and other software is installed, but I don't use Windows and don't support "texfot" there.

The name comes from the "trip.fot" and "trap.fot" files that are part of Knuth's trip and trap torture tests, which record the online output from the programs. I am not sure what "fot" stands for in trip and trap, but I can pretend that it stands for "filter online transcript" in the present case :).
