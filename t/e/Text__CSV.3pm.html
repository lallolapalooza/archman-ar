الحزمة: perl-text-csv

التراخيص: Artistic-1.0-Perl OR GPL-1.0-or-later

Mantén toda la estructura del archivo.

Los siguientes atributos están disponibles:

eol

my $csv = Text::CSV->new ({ eol => $/ });
          $csv->eol (undef);
my $eol = $csv->eol;

La cadena de fin de línea a agregar a las filas para "print" o el separador de registro para "getline".

Cuando no se pasa en un parser instancia, el comportamiento por defecto es aceptar "\n", "\r" y "\r\n", así que es probable que sea más seguro no especificar "eol" en absoluto. Pasar "undef" o la cadena vacía comporta lo mismo.

Cuando no se pasa en un generating instancia, las filas no se terminan en absoluto, así que es probable que sea útil pasar algo que se espera. Una opción segura para "eol" en salida es either "$/" o "\r\n".

Valores comunes para "eol" son "\012" ( "\n" o Line Feed), "\015\012" ( "\r\n" o Carriage Return, Line Feed), y "\015" ( "\r" o Carriage Return). El atributo "eol" no puede exceder 7 (ASCII) caracteres.

Si ambos "$/" y "eol" son "\015", se considerará correcto el parsing de líneas que terminan solo en Carriage Return sin Line Feed.

eol_type

my $eol = $csv->eol_type;

Este método de solo lectura devuelve el estado interna de lo que se considera el fin de línea válido para el parsing.

sep_char

my $csv = Text::CSV->new ({ sep_char => ";" });
        $csv->sep_char (";");
my $c = $csv->sep_char;

La chara usada para separar campos, por defecto una coma. ( ","). Limitada a un carácter único, normalmente en el rango de "0x20" (espacio) a "0x7E" (tildé). Cuando se requieren secuencias más largas, use "sep".

La chara de separación no puede ser igual a la chara de comillas o a la chara de escape.

sep

my $csv = Text::CSV->new ({ sep => "\N{FULLWIDTH COMMA}" });
          $csv->sep (";");
my $sep = $csv->sep;

Los chars usados para separar campos, por defecto undefined. Limitado a 8 bytes.

Cuando se establece, reemplaza "sep_char". Si su longitud es una byte, actúa como alias a "sep_char".

quote_char

my $csv = Text::CSV->new ({ quote_char => "'" });
        $csv->quote_char (undef);
my $c = $csv->quote_char;

La chara a usar para comilar campos con espacios o datos binarios, por defecto la chara de comillas ( """). Una valor de undef suprime las comillas (solo para casos simples). Limitada a un carácter único, normally en el rango de "0x20" (espacio) a "0x7E" (tildé). Cuando se requieren secuencias más largas, use "quote".

"quote_char" no puede ser igual a "sep_char".

quote

my $csv = Text::CSV->new ({ quote => "\N{FULLWIDTH QUOTATION MARK}" });
            $csv->quote ("'");
my $quote = $csv->quote;

Los chars usados para comilar campos, por defecto undefined. Limitado a 8 bytes.

Cuando se establece, reemplaza "quote_char". Si su longitud es una byte, actúa como alias a "quote_char".

Este método no soporta "undef". Use "quote_char" para desactivar la comilla.

escape_char

my $csv = Text::CSV->new ({ escape_char => "\\" });
        $csv->escape_char (":");
my $c = $csv->escape_char;

La chara a usar para escapar ciertas charas dentro de campos comilados. Esto es limitado a un carácter único, normalmente en el rango de "0x20" (espacio) a "0x7E" (tildé).

El "escape_char" por defecto es la chara de comillas ( """). En otras palabras, el mismo que el por defecto "quote_char". Esto significa que duplicar la chara de comillas en un campo escapa ella:

"foo","bar","Escape ""quote mark"" with two ""quote marks""","baz"

Si cambias "quote_char" sin cambiar "escape_char", "escape_char" seguirá siendo la chara de comillas ( """). Si quieres escalar la chara de comillas mediante duplicarla, tendrás que cambiar también "escape_char" para que sea lo mismo que has cambiado "quote_char" a.

Aunque "escape_char" sea "undef" o "", se desactivará completamente y se recomienda mucho. Esto también desactivará "escape_null".

La chara de escape no puede ser igual a la chara de separación.

binary

my $csv = Text::CSV->new ({ binary => 1 });
        $csv->binary (0);
my $f = $csv->binary;

Si este atributo es 1, puedes usar caracteres binarios en campos comilados, incluyendo line feeds, carriages returns y "NULL" bytes. (El último podría ser escapado como ""0".) Por defecto, esta función está desactivada.

Si un string se marca como UTF8, "binary" se activará automáticamente cuando se encuentren caracteres binarios no siendo "CR" o "NL". Nota que un string simple como "\x{00a0}" podría aún ser binario, pero no marcado como UTF8, así que establecer "{ binary => 1 }" es aún una buena opción.

strict

my $csv = Text::CSV->new ({ strict => 1 });
        $csv->strict (0);
my $f = $csv->strict;

Si este atributo es 1, cualquier fila que parsee a un número distinto de campos que la anterior causará al parser que de error 2014.

Filas vacías o filas que resulten en ningún campo (como líneas de comentario) están eximidas de estos checks.

strict_eol

my $csv = Text::CSV->new ({ strict_eol => 1 });
        $csv->strict_eol (0);
my $f = $csv->strict_eol;

Si este atributo es 0, no se realizan chequeos de consistencia de EOL.

Si este atributo es 1, cualquier fila que se parsee con un EOL diferente del EOL del primer fila causará un aviso. La error será ignorada y la parsing continua. Esta aviso se lanza solo una vez. Nota que en datos con diversos finales de línea, "\r\r" aún lanzará un error que no se puede ignorar.

Si este atributo es 2 o más, cualquier fila que se parsee con un EOL diferente del EOL del primer fila causará error 2016. La línea que se está parseando a este error podría no estar almacenada en el resultado.

skip_empty_rows

my $csv = Text::CSV->new ({ skip_empty_rows => 1 });
        $csv->skip_empty_rows ("eof");
my $f = $csv->skip_empty_rows;

Este atributo define el comportamiento para filas vacías: una "eol" inmediatamente después del comienzo de la línea. El comportamiento por defecto es devolver una sola campo vacío.

Este atributo es solo usado en parsing. Este atributo es inefectivo cuando se use "parse" y "fields".

Valores posibles para este atributo son:

0 | undef
my $csv = Text::CSV->new ({ skip_empty_rows => 0 });
$csv->skip_empty_rows (undef);

No se realiza ninguna acción especial. El resultado será una sola campo vacía.

1 | "skip"
my $csv = Text::CSV->new ({ skip_empty_rows => 1 });
$csv->skip_empty_rows ("skip");

La fila se saltará.

2 | "eof" | "stop"
my $csv = Text::CSV->new ({ skip_empty_rows => 2 });
$csv->skip_empty_rows ("eof");

La parsing se detendrá como si hubiera detectado "eof".

3 | "die"
my $csv = Text::CSV->new ({ skip_empty_rows => 3 });
$csv->skip_empty_rows ("die");

La parsing se detendrá. El código de error interno se establecerá a 2015 y el parser se detendrá con "die".

4 | "croak"
my $csv = Text::CSV->new ({ skip_empty_rows => 4 });
$csv->skip_empty_rows ("croak");

La parsing se detendrá. El código de error interno se establecerá a 2015 y el parser se detendrá con "croak".

5 | "error"
my $csv = Text::CSV->new ({ skip_empty_rows => 5 });
$csv->skip_empty_rows ("error");

La parsing fallará. El código de error interno se establecerá a 2015.

callback
my $csv = Text::CSV->new ({ skip_empty_rows => sub { [] } });
$csv->skip_empty_rows (sub { [ 42, $., undef, "empty" ] });

La callback se invoca y su resultado se usa en lugar. Si quieres que la parsing se detenga después de la callback, asegúrate de devolver un valor falso.

El valor devuelto de la callback debe ser un array-ref. Cualquier otro tipo causará que la parsing se detenga, así que estos tipos son equivalentes en comportamiento:

csv (in => $fh, skip_empty_rows => "stop");
csv (in => $fh. skip_empty_rows => sub { 0; });

known_attributes

@attr = Text::CSV->known_attributes;
@attr = Text::CSV::known_attributes;
@attr = $csv->known_attributes;

هذه الطريقة ستعيد قائمة مرتبة بجميع السمات المدعومة، كما هو موضح أعلاه. قد يكون هذا مفيدًا لمعرفة السمات الصالحة في الفئات التي تستخدم أو توسع Text::CSV.

<

NAME

Text::CSV - Objects for comma-separated values

SYNOPSIS

 use Text::CSV;
 my $csv = Text::CSV->new ({ binary => 1, auto_diag => 1 });
 my $fh;
 # ... open $fh ...
 # open, read, and parse a CSV file
 while (my $row = $csv->getline ($fh)) {
     my ($col1, $col2, $col3) = @$row;
     # ... process $col1, $col2, $col3 ...
     #
     # Note: if you are using bind_columns, the elements of $row
     # will be references to the variables you passed to bind_columns.
     print "The price of a $name is \x{20ac} $price\n";
 }
 if (my $err = $csv->error_diag ()) {
     warn "CSV Error: $err at line ", $csv->lines_read ();
 }
 $csv->eof or $csv->error_diag ();
 # ...
 # open, read, and parse a CSV file with column names
 $csv->column_names (@header_fields);
 while (my $hr = $csv->getline_hr ($fh)) {
     # ... process $hr->{col1}, $hr->{col2}, etc. ...
 }
 # ...
 # combine fields into a CSV record
 my $row = [ 'value1', 'value2', 'value3' ];
 my $csv_string = $csv->combine ($row);
 # ...

DESCRIPTION

This module implements RFC 2046, RFC 4180, and RFC 7111.

The API is designed to be easy to use, and yet it is powerful enough to handle all the quirks of CSV files.

Please see the full documentation in Text::CSV::FAQ and Text::CSV::Table.

constructor

$csv = Text::CSV->new ( [ NAME => VALUE, ... ] );
$csv = Text::CSV->new ( \%args );

Creates a new Text::CSV object. The following arguments are supported:

binary
If set to true, Text::CSV will not try to decode the input (which is assumed to be UTF-8). This is useful for handling arbitrary binary data. Default is false.
sep
The separator character (default is comma).
sep_char
Same as sep.
eol
The end-of-line character(s). Defaults to \n. Can be set to "\r\n" for DOS/Windows files.
quote
The quote character (default is double quote).
quote_char
Same as quote.
escape
The escape character (default is the same as quote). If set to false, escape characters are disabled.
escape_char
Same as escape.
allow_loose_quotes
If set to true, this allows for unescaped quotes within quoted fields. Default is false.
allow_loose_escapes
If set to true, this allows for unescaped escape characters within unquoted fields. Default is false.
skip_bom
If set to true, skip the UTF-8 Byte Order Mark (BOM) if present at the beginning of the input. Default is false.
auto_diag
If set to true, errors will automatically trigger a warning. Also, error diagnostics will be available via error_diag(). Default is false.
diag_verbose
If set to true, and auto_diag is true, error diagnostics will include the location in the XS code where the error occurred. Default is false.
empty_is_error
If set to true, an empty line will be treated as an error. Default is false.
blank_is_good
If set to true, an empty line is a valid CSV line, consisting of a single empty field. Default is false.
keep_meta_info
If set to true, information about whether fields were quoted, binary, or missing will be kept. Default is false.
fields_sep_trim
If set to true, whitespace around the separator will be trimmed. Default is false.
allow_cr_in_quote
If set to true, allows CR characters within quoted fields. Default is false.
parse_default
If set to true, the parse() method will try to guess the column types. This is not recommended for production use. Default is false.

parse

$rv = $csv->parse ($fh);

Reads from the given IO::Handle $fh until end of file or until an error occurs. It parses the content as CSV data.

Returns true on success, false on failure. Use error_diag to get details about the error.

The parsed fields are available via the fields method.

$csv->parse ($fh);
my @fields = $csv->fields ();

If you are using bind_columns, the bound variables will be populated here. See the example in the bind_columns section.

getline

@fields = $csv->getline ($fh);
$row_ref = $csv->getline ($fh);

Reads and parses one line from the given IO::Handle $fh. If successful, it returns a reference to an array of fields. If an error occurs, it returns undef. If end-of-file is reached without error, it returns an empty list in the first call, and undef in subsequent calls.

The behavior in case of errors depends on the auto_diag setting.

If auto_diag is false (the default), getline returns undef on error. You can check the error status with error_diag().

If auto_diag is true, getline will warn about the error and return undef.

If you are using bind_columns, the bound variables will be populated here instead of returning an array reference.

$csv->bind_columns (\$code, \$name, \$price, \$description);
while ($csv->getline ($fh)) {
    # $code, $name, $price, $description are now populated
    print "The price of a $name is \x{20ac} $price\n";
    }

getline_hr

$hash_ref = $csv->getline_hr ($fh);

Reads and parses one line from the given IO::Handle $fh. If successful, it returns a reference to a hash where the keys are the column names (set by column_names()) and the values are the corresponding fields. If an error occurs, it returns undef. If end-of-file is reached without error, it returns an empty hash reference in the first call, and undef in subsequent calls.

The behavior in case of errors depends on the auto_diag setting.

$csv->column_names ("code", "name", "price", "description");
while (my $hr = $csv->getline_hr ($fh)) {
    print "The price of a $hr->{name} is \x{20ac} $hr->{price}\n";
    }

bind_columns

$csv->bind_columns (\$col1, \$col2, ...);
$csv->bind_columns ($col1, $col2, ...); # scalar references are autodetected

This method allows you to bind variables to the columns of the CSV file. When you call parse or getline, these variables will be automatically populated with the values from the corresponding columns.

The number of arguments passed to bind_columns determines the number of columns to be parsed. If you pass more arguments than there are fields in a row, the remaining variables will be left untouched.

If the "strict" attribute is set (see strict()), then the number of bound columns must exactly match the number of fields in each row, otherwise getline will fail with error 2014. If "strict" is not set, getline will return error 3006 if you pass more arguments than there are fields to return. The content of the remaining references is left untouched.

$csv->bind_columns (\$code, \$name, \$price, \$description);
while ($csv->getline ($fh)) {
    print "The price of a $name is \x{20ac} $price\n";
    }

To reset or clear all column binding, call bind_columns with the single argument undef. This will also clear column names.

$csv->bind_columns (undef);

If no arguments are passed at all, bind_columns will return the list of current bindings or undef if no binds are active.

Note that in parsing with bind_columns, the fields are set on the fly. That implies that if the third field of a row causes an error (or this row has just two fields where the previous row had more), the first two fields already have been assigned the values of the current row, while the rest of the fields will still hold the values of the previous row. If you want the parser to fail in these cases, use the strict attribute.

eof

$eof = $csv->eof ();

If parse or getline was used with an IO stream, this method will return true (1) if the last call hit end of file, otherwise it will return false (''). This is useful to see the difference between a failure and end of file.

Note that if the parsing of the last line caused an error, eof is still true. That means that if you are not using auto_diag, an idiom like

while (my $row = $csv->getline ($fh)) {
    # ...
    }
$csv->eof or $csv->error_diag;

will not report the error. You would have to change that to

while (my $row = $csv->getline ($fh)) {
    # ...
    }
+$csv->error_diag and $csv->error_diag;

types

$csv->types (\@tref);

This method is used to force that (all) columns are of a given type. For example, if you have an integer column, two columns with doubles and a string column, then you might do a

$csv->types ([Text::CSV::IV (),
              Text::CSV::NV (),
              Text::CSV::NV (),
              Text::CSV::PV ()]);

Column types are used only for decoding columns while parsing, in other words by the parse and getline methods.

You can unset column types by doing a

$csv->types (undef);

or fetch the current type settings with

$types = $csv->types ();
IV
CSV_TYPE_IV
Set field type to integer.
NV
CSV_TYPE_NV
Set field type to numeric/float.
PV
CSV_TYPE_PV
Set field type to string.

fields

@columns = $csv->fields ();

This method returns the input to combine or the resultant decomposed fields of a successful parse, whichever was called more recently.

Note that the return value is undefined after using getline, which does not fill the data structures returned by parse.

meta_info

@flags = $csv->meta_info ();

This method returns the "flags" of the input to combine or the flags of the resultant decomposed fields of parse, whichever was called more recently.

For each field, a meta_info field will hold flags that inform something about the field returned by the fields method or passed to the combine method. The flags are bit-wise-"or"'d like:

0x0001
"CSV_FLAGS_IS_QUOTED"
The field was quoted.
0x0002
"CSV_FLAGS_IS_BINARY"
The field was binary.
0x0004
"CSV_FLAGS_ERROR_IN_FIELD"
The field was invalid.

Currently only used when allow_loose_quotes is active.

0x0010
"CSV_FLAGS_IS_MISSING"
The field was missing.

See the is_*** methods below.

is_quoted

my $quoted = $csv->is_quoted ($column_idx);

where $column_idx is the (zero-based) index of the column in the last result of parse.

This returns a true value if the data in the indicated column was enclosed in quote_char quotes. This might be important for fields where content is to be treated as a numeric value, and where This method is only valid when keep_meta_info is set to a true value.

is_binary

my $binary = $csv->is_binary ($column_idx);

where $column_idx is the (zero-based) index of the column in the last result of parse.

This returns a true value if the data in the indicated column contained any byte in the range .

This method is only valid when keep_meta_info is set to a true value.

is_missing

my $missing = $csv->is_missing ($column_idx);

where $column_idx is the (zero-based) index of the column in the last result of getline_hr.

$csv->keep_meta_info (1);
while (my $hr = $csv->getline_hr ($fh)) {
    $csv->is_missing (0) and next; # This was an empty line
    }

When using getline_hr, it is impossible to tell if the parsed fields are undef because they where not filled in the CSV stream or because they were not read at all, as all the fields defined by column_names are set in the hash-ref. If you still need to know if all fields in each row are provided, you should enable keep_meta_info so you can check the flags.

If keep_meta_info is false, is_missing will always return undef, regardless of $column_idx being valid or not. If this attribute is true it will return either 0 (the field is present) or 1 (the field is missing).

A special case is the empty line. If the line is completely empty - after dealing with the flags - this is still a valid CSV line: it is a record of just one single empty field. However, if keep_meta_info is set, invoking is_missing with index 0 will now return true.

status

$status = $csv->status ();

This method returns the status of the last invoked combine or parse call. Status is success (true: 1) or failure (false: undef or 0).

Note that as this only keeps track of the status of above mentioned methods, you are probably looking for error_diag instead.

error_input

$bad_argument = $csv->error_input ();

This method returns the erroneous argument (if it exists) of combine or parse, whichever was called more recently. If the last invocation was successful, error_input will return undef.

Depending on the type of error, it might also hold the data for the last error-input of getline.

error_diag

Text::CSV->error_diag ();
$csv->error_diag ();
$error_code               = 0  + $csv->error_diag ();
$error_str                = "" . $csv->error_diag ();
($cde, $str, $pos, $rec, $fld, $xs) = $csv->error_diag ();

If (and only if) an error occurred, this function returns the diagnostics of that error.

If called in void context, this will print the internal error code and the associated error message to STDERR.

If called in list context, this will return the error code and the error message in that order. If the last error was from parsing, the rest of the values returned are a best guess at the location within the line that was being parsed. Their values are 1-based. The position currently is index of the byte at which the parsing failed in the current record. It might change to be the index of the current character in a later release. The records is the index of the record parsed by the csv instance. The field number is the index of the field the parser thinks it is currently trying to parse. See examples/csv-check for how this can be used. If $xs is set, it is the line number in XS where the error was triggered (for debugging). "XS" will show in void context only when diag_verbose is set.

If called in scalar context, it will return the diagnostics in a single scalar, a-la $!.

دالات

تم أخذ هذا القسم أيضًا من Text::CSV_XS.

csv

لم يتم تصدير هذه الدالة افتراضيًا ويجب طلبها بشكل صريح:

use Text::CSV qw( csv );

هذه دالة عالية المستوى تهدف إلى واجهات بسيطة (للمستخدم). يمكن استخدامها لقراءة/تحليل ملف أو تدفق "CSV" (السلوك الافتراضي) أو لإنتاج ملف أو الكتابة إلى تدفق (تحديد السمة "out"). تُرجع مرجع مصفوفة أو هاش عند التحليل (أو "undef" عند الفشل) أو القيمة الرقمية لـ "error_diag" عند الكتابة. عندما تفشل هذه الدالة، يمكنك الوصول إلى الخطأ باستخدام استدعاء الفئة لـ "error_diag"

my $aoa = csv (in => "test.csv") or
    die Text::CSV->error_diag;

لاحظ أن الفشل هنا هو عدم القدرة على بدء المحلل، كما هو الحال عندما لا يكون الإدخال موجودًا أو تكون الوسيطات غير معروفة أو متعارضة. تُرجع أخطاء التحليل في وقت التشغيل مرجعًا صالحًا، والذي يمكن أن يكون فارغًا، ولكنه لا يزال يحتوي على جميع النتائج حتى الخطأ. راجع "on_error".

تأخذ هذه الدالة الوسيطات كأزواج مفتاح-قيمة. يمكن تمريرها كقائمة أو كهاش مجهول:

my $aoa = csv (  in => "test.csv", sep_char => ";");
my $aoh = csv ({ in => $fh, headers => "auto" });

تتكون الوسيطات التي تم تمريرها من جزأين: وسيطات "csv" نفسها والسمات الاختيارية لكائن "CSV" المستخدم داخل الدالة كما تم تعدادها وشرحها في "new".

إذا لم يتم تجاوزها، فإن الخيار الافتراضي المستخدم لـ CSV هو

auto_diag   => 1
escape_null => 0
strict_eol  => 1

الخيار الذي يتم تعيينه دائمًا ولا يمكن تغييره هو

binary      => 1

نظرًا لأنه من المحتمل استخدام هذه الدالة في وحدات نصية واحدة، فإنها تسمح باختصار "quote" إلى "quo"، واختصار "escape_char" إلى "esc" أو "escape".

استدعاءات بديلة:

my $aoa = Text::CSV::csv (in => "file.csv");
my $csv = Text::CSV->new ();
my $aoa = $csv->csv (in => "file.csv");

في الحالة الأخيرة، يتم استخدام سمات الكائن من الكائن الموجود ويتم تجاهل وسيطات السمة في استدعاء الدالة:

my $csv = Text::CSV->new ({ sep_char => ";" });
my $aoh = $csv->csv (in => "file.csv", bom => 1);

سيتم التحليل باستخدام ";" كـ "sep_char"، وليس ",".

in

تستخدم لتحديد المصدر. يمكن أن يكون "in" اسم ملف (مثل "file.csv")، والذي سيتم فتحه للقراءة وإغلاقه عند الانتهاء، أو مقبض ملف (مثل $fh أو "FH")، أو مرجع إلى glob (مثل "\*ARGV")، أو glob نفسه (مثل *STDIN)، أو مرجع إلى قيمة قابلة للقياس (مثل "\q{1,2,"csv"}").

عند استخدامه مع "out"، يجب أن يكون "in" مرجعًا لهيكل CSV (AoA أو AoH) أو مرجع CODE يُرجع مرجع مصفوفة أو مرجع هاش. سيتم استدعاء مرجع CODE بدون وسيطات.

my $aoa = csv (in => "file.csv");
open my $fh, "<", "file.csv";
my $aoa = csv (in => $fh);
my $csv = [ [qw( Foo Bar )], [ 1, 2 ], [ 2, 3 ]];
my $err = csv (in => $csv, out => "file.csv");

إذا تم استدعاؤه في سياق فارغ بدون السمة "out"، فسيتم استخدام المرجع الناتج كمدخل لاستدعاء لاحق لـ csv:

csv (in => "file.csv", filter => { 2 => sub { length > 2 }})

سيكون اختصارًا لـ

csv (in => csv (in => "file.csv", filter => { 2 => sub { length > 2 }}))

حيث، في غياب السمة "out"، يعد هذا اختصارًا لـ

csv (in  => csv (in => "file.csv", filter => { 2 => sub { length > 2 }}),
     out => *STDOUT)

out

csv (in => $aoa,  out => "file.csv");
csv (in => $aoa,  out => $fh);
csv (in => $aoa,  out =>   STDOUT);
csv (in => $aoa,  out =>  *STDOUT);
csv (in => $aoa,  out => \*STDOUT);
csv (in => $aoa,  out => \my $data);
csv (in => $aoa,  out =>  undef);
csv (in => $aoa,  out => \"skip");
csv (in => $fh,   out => \@aoa);
csv (in => $fh,   out => \@aoh, bom => 1);
csv (in => $fh,   out => \%hsh, key => "key");
csv (in => $file, out => $file);
csv (in => $file, out => $fh);
csv (in => $fh,   out => $file);
csv (in => $fh,   out => $fh);

في وضع الإخراج، تكون خيارات CSV الافتراضية عند إنتاج CSV هي

eol       => "\r\n"

يتم تجاهل السمة "fragment" في وضع الإخراج.

"out" يمكن أن يكون اسم ملف (مثل "file.csv")، والذي سيتم فتحه للكتابة وإغلاقه عند الانتهاء، أو مقبض ملف (مثل $fh أو "FH")، أو مرجع إلى glob (مثل "\*STDOUT")، أو glob نفسه (مثل *STDOUT)، أو مرجع إلى قيمة قابلة للقياس (مثل "\my $data").

csv (in => sub { $sth->fetch },            out => "dump.csv");
csv (in => sub { $sth->fetchrow_hashref }, out => "dump.csv",
     headers => $sth->{NAME_lc});

عند استخدام مرجع CODE للإدخال "in"، يتم إنشاء الإخراج لكل استدعاء، لذلك لا يوجد تخزين مؤقت. هذا يعني أنه لا يوجد حد لحجم عدد السجلات. تنتهي الدالة "csv" عندما يُرجع مرجع CODE قيمة خاطئة.

إذا تم تعيين "out" إلى مرجع للسلسلة الحرفية "skip"، فسيتم قمع الإخراج تمامًا، مما قد يكون مفيدًا بالاقتران مع مرشح للتأثيرات الجانبية فقط.

my %cache;
csv (in    => "dump.csv",
     out   => \"skip",
     on_in => sub { $cache{$_[1][1]}++ });

حالياً، سيتم تعيين "out" إلى أي قيمة خاطئة ("undef"، ""، 0) ما يعادل "\"skip"".

إذا كان الوسيط "in" يشير إلى شيء ما لتحليله، وتم تعيين "out" إلى مرجع لـ "ARRAY" أو "HASH"، فسيتم إلحاق الإخراج بالبيانات الموجودة في المرجع الحالي. يجب أن يتطابق ناتج التحليل مع ما هو موجود في المرجع الذي تم تمريره. قد يكون هذا مفيدًا عندما تحتاج إلى تحليل مجموعة من الملفات ذات المحتوى المتشابه (مثل البيانات المخزنة حسب الفترة) وتريد جمعها في بنية بيانات واحدة:

my %hash;
csv (in => $_, out => \%hash, key => "id") for sort glob "foo-[0-9]*.csv";
my @list; # List of arrays
csv (in => $_, out => \@list)              for sort glob "foo-[0-9]*.csv";
my @list; # List of hashes
csv (in => $_, out => \@list, bom => 1)    for sort glob "foo-[0-9]*.csv";

تدفق

إذا كان كل من "in" و "out" ملفات أو مقابض ملفات أو globs، يتم فرض التدفق عن طريق حقن رد استدعاء "after_parse" الذي يستخدم على الفور طريقة "say ()" لنفس المثيل لإخراج النتيجة ثم يرفض السجل.

إذا تم تمرير "after_parse" بالفعل كوسيط، فسيتم تضمينه في الاستدعاء المحقون. إذا تم تمرير "on_in" ولم يتم تمرير "after_parse"، فسيتم استخدامه بدلاً من ذلك. إذا تم تمرير كليهما، فسيتم تجاهل "on_in".

يتم استخدام EOL للسجل الأول لمصدر "in" بشكل ثابت كـ EOL لجميع السجلات في الوجهة "out".

السمة "filter" غير متوفرة.

تتم مشاركة جميع السمات الأخرى لـ "in" و "out"، لذلك لا يمكنك تحديد ترميزات مختلفة لـ "in" و "out". تحتاج إلى تمرير $fh، حيث

not_blank
تصفية الأسطر الفارغة

هذه التصفية هي اختصار لـ

filter => { 0 => sub { @{$_[1]} > 1 or
    defined $_[1][0] && $_[1][0] ne "" } }

بسبب التنفيذ، من المستحيل حاليًا تصفية الأسطر التي تتكون فقط من حقل فارغ مقتبس. تعتبر هذه الأسطر أيضًا أسطرًا فارغة.

مع المثال المعطى، سيتم تخطي السطرين 2 و 4.

not_empty
تصفية الأسطر التي تكون فيها جميع الحقول فارغة.

هذه التصفية هي اختصار لـ

filter => { 0 => sub { grep { defined && $_ ne "" } @{$_[1]} } }

لا يُعتبر المسافة فارغة، لذلك مع بيانات المثال المعطاة، يتم تخطي الأسطر 2، 3، 4، 5، و 7.

filled
تصفية الأسطر التي لا تحتوي على بيانات مرئية

هذه التصفية هي اختصار لـ

filter => { 0 => sub { grep { defined && m/\S/ } @{$_[1]} } }

ترفض هذه التصفية جميع الأسطر التي *لا* تحتوي على حقل واحد على الأقل لا يقيم إلى سلسلة فارغة.

مع بيانات المثال المعطاة، ستتخطى هذه التصفية الأسطر من 2 إلى 8.

يمكن أيضًا استخدام وحدات مثل Types::Standard:

use Types::Standard -types;
my $type   = Tuple[Str, Str, Int, Bool, Optional[Num]];
my $check  = $type->compiled_check;
# filter with compiled check and warnings
my $aoa = csv (
   in     => \$data,
   filter => {
       0 => sub {
           my $ok = $check->($_[1]) or
               warn $type->get_message ($_[1]), "\n";
           return $ok;
           },
       },
   );
after_in
يتم استدعاء رد الاتصال هذا لكل سجل بعد تحليل جميع السجلات ولكن قبل إرجاع المرجع إلى المتصل. يتم استدعاء الخطاف بوسيطين: كائن "CSV" الحالي ومرجع إلى السجل. يمكن أن يكون المرجع مرجعًا إلى HASH أو مرجعًا إلى ARRAY كما يحدده الوسيطات.

يمكن أيضًا تمرير رد الاتصال هذا كسمة بدون الغلاف "callbacks".

before_out
يتم استدعاء رد الاتصال هذا لكل سجل قبل طباعة السجل. يتم استدعاء الخطاف بوسيطين: كائن "CSV" الحالي ومرجع إلى السجل. يمكن أن يكون المرجع مرجعًا إلى HASH أو مرجعًا إلى ARRAY كما يحدده الوسيطات.

يمكن أيضًا تمرير رد الاتصال هذا كسمة بدون الغلاف "callbacks".

يجعل رد الاتصال هذا الصف متاحًا في %_ إذا كان الصف عبارة عن hashref. في هذه الحالة، يمكن كتابة %_ وسيغير الصف الأصلي.

on_in
يعمل رد الاتصال هذا تمامًا مثل خطافات "after_in" أو "before_out".

يمكن أيضًا تمرير رد الاتصال هذا كسمة بدون الغلاف "callbacks".

يجعل رد الاتصال هذا الصف متاحًا في %_ إذا كان الصف عبارة عن hashref. في هذه الحالة، يمكن كتابة %_ وسيغير الصف الأصلي. على سبيل المثال مع

my $aoh = csv (
    in      => \"foo\n1\n2\n",
    headers => "auto",
    on_in   => sub { $_{bar} = 2; },
    );

سيكون $aoh:

[ { foo => 1,
    bar => 2,
    }
  { foo => 2,
    bar => 2,
    }
  ]
on_error
يعمل رد الاتصال هذا تمامًا مثل خطاف "error". 
my @err;
my $aoa = csv (in => $fh, on_error => sub { @err = @_ });

هو مطابق لـ

my $aoa = csv (in => $fh, callbacks => {
    error => sub { @err = @_ },
    });

يمكن استخدامه لتجاهل الأخطاء وكذلك للاحتفاظ بالخطأ في حالة التحليل بعد إرجاع الدالة "csv ()".

my @err;
my $aoa = csv (in => "bad.csv, on_error => sub { @err = @_ });
die Text::CSV->error_diag if @err or !$aoa;

التشخيصات

يتم أخذ هذا القسم أيضًا من Text::CSV_XS.

لا يزال قيد الإنشاء ...

إذا حدث خطأ، يمكن استخدام "$csv->error_diag" للحصول على معلومات حول سبب الفشل. لاحظ أنه لأسباب السرعة، لا يتم مسح القيمة الداخلية أبدًا عند النجاح، لذا فإن استخدام القيمة التي تم إرجاعها بواسطة "error_diag" في الحالات العادية - عندما لم يحدث خطأ - قد يتسبب في نتائج غير متوقعة.

إذا فشل المنشئ، يمكن العثور على السبب باستخدام "error_diag" كطريقة فئة، مثل "Text::CSV->error_diag".

يتم استدعاء طريقة "$csv->error_diag" تلقائيًا عند حدوث خطأ عندما تم استدعاء المنشئ مع تعيين "auto_diag" إلى 1 أو 2، أو عندما يكون autodie ساري المفعول. عند التعيين على 1، سيؤدي ذلك إلى "warn" مع رسالة الخطأ، عند التعيين على 2، سيؤدي ذلك إلى "die". يتم استبعاد "2012 - EOF" من تقارير "auto_diag".

يمكن التقاط الأخطاء (بشكل فردي) باستخدام رد الاتصال "error".

الأخطاء كما هو موضح أدناه متاحة. لقد حاولت جعل الخطأ نفسه توضيحيًا بما فيه الكفاية، ولكن سيتم إضافة المزيد من الأوصاف. بالنسبة لمعظم هذه الأخطاء، تصف الأحرف الكبيرة الثلاثة الأولى فئة الخطأ:

  • INI

    خطأ تهيئة أو تعارض في الخيارات.

  • ECR

    خطأ في تحليل يتعلق بعودة المحرف.

  • EOF

    خطأ في تحليل يتعلق بنهاية الملف.

  • EIQ

    خطأ في التحليل داخل الاقتباس.

  • EIF

    خطأ في التحليل داخل الحقل.

  • ECB

    خطأ في الدمج.

  • EHR

    خطأ متعلق بتحليل HashRef.

وفيما يلي يجب أن تكون القائمة الكاملة لرموز الخطأ التي يمكن إرجاعها:

  • 1001 "INI - sep_char يساوي quote_char أو escape_char"

    لا يمكن أن يكون حرف الفصل مساويًا لحرف الاقتباس أو حرف الهروب، حيث سيؤدي ذلك إلى إبطال جميع قواعد التحليل.

  • 1002 "INI - allow_whitespace مع escape_char أو quote_char SP أو TAB"

    استخدام السمة "allow_whitespace" عندما يكون "quote_char" أو "escape_char" مساويًا لـ "SPACE" أو "TAB" غامض للغاية للسماح به.

  • 1003 "INI - \r أو \n في السمة الرئيسية غير مسموح بها"

    استخدام أحرف "eol" الافتراضية في "sep_char" أو "quote_char" أو "escape_char" غير مسموح به.

  • 1004 "INI - يجب أن تكون ردود الاتصال غير محددة أو مرجع هاش"

    تسمح سمة "callbacks" فقط بأن تكون واحدة "undef" أو مرجع هاش.

  • 1005 "INI - EOL طويل جدًا"

    القيمة المقدمة لـ EOL تتجاوز الحد الأقصى لطولها (16).

  • 1006 "INI - SEP طويل جدًا"

    القيمة المقدمة لـ SEP تتجاوز الحد الأقصى لطولها (16).

  • 1007 "INI - QUOTE طويل جدًا"

    القيمة المقدمة لـ QUOTE تتجاوز الحد الأقصى لطولها (16).

  • 1008 "INI - SEP غير محدد"

    يجب أن تكون القيمة المقدمة لـ SEP محددة وغير فارغة.

  • 1010 "INI - رأس الملف فارغ"

    سطر رأس الملف الذي تم تحليله في "header" فارغ.

  • 1011 "INI - يحتوي رأس الملف على أكثر من فاصل صالح واحد"

    يحتوي سطر رأس الملف الذي تم تحليله في "header" على أكثر من حرف فاصل واحد (فريد) من مجموعة الفواصل المسموح بها.

  • 1012 "INI - يحتوي رأس الملف على حقل فارغ"

    يحتوي سطر رأس الملف الذي تم تحليله في "header" على حقل فارغ.

  • 1013 "INI - يحتوي رأس الملف على حقول غير فريدة"

    يحتوي سطر رأس الملف الذي تم تحليله في "header" على حقلين متطابقين على الأقل.

  • 1014 "INI - استدعاء header على دفق غير محدد"

    لا يمكن تحليل سطر رأس الملف من مصدر غير محدد.

  • 1500 "PRM - وسيطات غير صالحة/غير مدعومة"

    تم استدعاء الدالة أو الطريقة بوسيطات أو معاملات غير صالحة.

  • 1501 "PRM - يتم تمرير السمة key بنوع غير مدعوم"

    السمة "key" من نوع غير مدعوم.

  • 1502 "PRM - يتم تمرير السمة value بدون السمة key"

    السمة "value" مسموح بها فقط عندما يتم توفير مفتاح صالح.

  • 1503 "PRM - يتم تمرير السمة value بنوع غير مدعوم"

    السمة "value" من نوع غير مدعوم.

  • 2010 "ECR - حرف QUO داخل علامات الاقتباس متبوعًا بـ CR ليس جزءًا من EOL"
