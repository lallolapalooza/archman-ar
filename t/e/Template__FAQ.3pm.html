Template::FAQ - أسئلة متكررة حول لغة Template Toolkit

لغة Template Toolkit

لماذا لا يعمل [% a = b IF c %] كما هو متوقع؟

هناك قيد في محلل TT2 يعني أن الكود التالي لا يعمل كما هو متوقع:

[% a = b IF c %]

يفسر المحلل هذا على أنه محاولة لتعيين "a" إلى نتيجة "b IF c"، هكذا:

[% a = (b IF c) %]

إذا كنت ترغب في تعيين "a = b" فقط إذا كانت "c" صحيحة، فافعل ما يلي:

[% SET a = b IF c %]

الكلمة المفتاحية "SET" تعطي المحلل المفتاح اللازم للقيام بالشيء الصحيح.

ملاحظة: سيتم إصلاح هذه المشكلة في TT3.

إذا كنت أستخدم TT لكتابة قالب TT، فهل هناك طريقة جيدة للهروب من [% و %]؟

يمكنك القيام بشيء كهذا:

[% stag = "[\%"
   etag = "%\]"
%]

ثم:

[% stag; 'hello'; etag %]

أو يمكنك استخدام التوجيه "TAGS"، هكذا:

[% TAGS [- -] %]
[- INCLUDE foo -]   # هو توجيه
[% INCLUDE foo %]   # ليس توجيهاً

كيف أتكرر فوق جدول هاش؟

تتم معالجة هذا الموضوع في قسم Template::Manual::VMethods من الوثائق. يمكن الحصول على قائمة بجميع المفاتيح الموجودة في الجدول باستخدام الطريقة الافتراضية "keys". ثم يمكن المرور فوق هذه القائمة والبحث عن كل مفتاح بالترتيب للحصول على القيمة.

[% FOREACH key = product.keys %]
   [% key %] => [% product.$key %]
[% END %]

الإضافات

كيف أجعل إضافة Table ترتب البيانات أفقياً بدلاً من عمودياً؟

قم بترتيب البيانات في صفوف:

Steve     Karen     Jeff
Brooklyn  Nantucket Fairfax
NY        MA        VA
[% USE table(data, rows=3) %]

ثم، اطلب كل عمود:

[% FOREACH column = table.cols %]

ثم اطبع كل عنصر في العمود، مروراً بصفوف الإخراج:

[% FOREACH item = column %]
    <td>[% item %]</td>
[% END %]

<p>القيمة هي [% CGI.cookie('cookie_name') | html %]

توسيع Template Toolkit

هل يمكنني تقديم قوالب من قاعدة بيانات؟

إجابة قصيرة: نعم، قام Chris Nandor بذلك لـ Slash. تحتاج إلى وراثة Template::Provider. انظر تصحيحات القوائم في البريد الإلكتروني للقوائم لمزيد من المعلومات.

هل يمكنني جلب القوالب عبر HTTP؟

لإنجاز العمل بشكل صحيح، يجب عليك وراثة Template::Provider لـ "Template::Provider::HTTP" واستخدام خيار "PREFIX_MAP" لربط البادئة "http" بهذا المزود المحدد (قد ترغب في البحث في ملف *Changes* حول الإصدار 2.01 لمزيد من المعلومات حول "PREFIX_MAP" - قد لا يكون موثقًا جيدًا بطريقة أخرى... بعد!). على سبيل المثال:

use Template::Provider::HTTP;
my $file = Template::Provider( INCLUDE_PATH => [...] );
my $http = Template::Provider::HTTP->new(...);
my $tt2  = Template->new({
    LOAD_TEMPLATES => [ $file, $http ],
    PREFIX_MAP => {
        file    => '0',     # file:foo.html
        http    => '1',     # http:foo.html
        default => '0',     # foo.html => file:foo.html
    }
});

الآن قالب محدد كـ:

[% INCLUDE foo %]

سيتم تقديمه بواسطة مزود "file" (الافتراضي). إذا لم تحدده، يمكنك إضافة بادئة بشكل صريح:

[% INCLUDE file:foo.html %]
[% INCLUDE http:foo.html %]
[% INCLUDE http://www.xyz.com/tt2/header.tt2 %]

يمكن استخدام نفس المبدأ هذا لإنشاء مزود DBI. على سبيل المثال:

[% INCLUDE dbi:foo.html %]

لكننا لا نملك بعد مزود DBI كجزء من مكتبة Toolkit للقوالب. تمت مناقشة جهود تطوير مزودات DBI و/أو HTTP في القائمة البريدية، ولكن لم يتقدم أحد بعد لتولي هذا التحدي...

في غضون ذلك، تحتوي ورقة Craig Barrat في القائمة البريدية على بعض النقاط المفيدة حول كيفية تحقيق ذلك باستخدام وحدات موجودة. انظر http://tt2.org/pipermail/templates/2001-May/000954.html

متفرقات

كيف يمكنني معرفة اسم القالب الرئيسي الذي تتم معالجته؟

تحتوي المتغير "template" على مرجع لكائن Template::Document للقالب الرئيسي الذي تعالجه (أي، الذي يتم تمريره كوسيط أول لدالة Template::process()). ترجع المتغير "name" اسمه.

[% template.name %]     # مثال: index.html

كيف يمكنني معرفة اسم القالب الحالي الذي تتم معالجته؟

يشير المتغير "template" دائمًا إلى القالب الرئيسي الذي تتم معالجته. لذلك حتى إذا قمت باستدعاء [% INCLUDE header %] وهذا الاستدعاء [% INCLUDE menu %]، فلن يتغير المتغير "template".

index.html:

[% template.name %]     # index.html
[% INCLUDE header %]

header:

[% template.name %]     # index.html
[% INCLUDE menu   %]

menu:

[% template.name %]     # index.html

على النقيض من ذلك، يشير المتغير "component" دائمًا إلى القالب الحالي الذي تتم معالجته.

index.html

[% component.name %]     # index.html
[% INCLUDE header %]

header:

[% component.name %]     # header
[% INCLUDE menu   %]

menu:

[% component.name %]     # menu

كيف أطبع وقت تعديل القالب أو المكون؟

يشير المتغيران "template" و "component" إلى القالب الرئيسي والقالب الحالي الذي تتم معالجته (انظر الأسئلة السابقة). تقوم الطريقة "modtime" بإرجاع وقت تعديل الملف المقابل كرقم ثوانٍ منذ عصر Unix (00:00:00 GMT 1 يناير 1970).

هذا الرقم ليس ذا معنى كبير لأي شخص (ما لم يكن خبيرًا في Unix جادًا)، لذلك ربما ترغب في استخدام إضافة Date لتنسيقه للاستهلاك البشري.

[% USE Date %]
[% template.name %] last modified [% Date.format(template.modtime) %]

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.
