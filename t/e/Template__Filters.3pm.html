Template__Filters(3pm)

الحزمة: perl-template-toolkit

التراخيص: PerlArtistic

Template::Filters(3) وثائق Perl المساهمة من المستخدم Template::Filters(3)

الاسم

Template::Filters - مرشحات ما بعد المعالجة لكتل القوالب

الملخص

use Template::Filters;
$filters = Template::Filters->new(\%config);
($filter, $error) = $filters->fetch($name, \@args, $context);
if ($filter) {
    print &$filter("some text");
}
else {
    print "Could not fetch $name filter: $error\n";
}

الوصف

تنفيذ الوحدة "Template::Filters" موفرًا لإنشاء دوال فرعية تنفذ المرشحات القياسية. يمكن توفير مرشحات مخصصة إضافية عبر خيار التهيئة FILTERS.

الأساليب

new(\%params)

طريقة البناء التي تنشئ وتعيد مرجعًا لكائن "Template::Filters". يمكن تمرير مرجع إلى مصفوفة تجزئة من عناصر التهيئة كمعامل. يتم وصف هذه العناصر أدناه.

my $filters = Template::Filters->new({
    FILTERS => { ... },
});
my $template = Template->new({
    LOAD_FILTERS => [ $filters ],
});

يتم إنشاء وحدة "Template::Filters" افتراضية بواسطة الوحدة Template إذا لم يتم تحديد خيار LOAD_FILTERS. يتم تمرير جميع معلمات التهيئة إلى الباني.

$template = Template->new({
    FILTERS => { ... },
});

fetch($name, \@args, $context)

يتم استدعاؤها لطلب توفير مرشح باسم معين. يجب تحديد اسم المرشح كمعامل أول. يجب أن يكون هذا أحد المرشحات القياسية أو واحدًا تم تحديده في تجزئة تهيئة FILTERS. يجب أن يكون المعامل الثاني مرجعًا لمصفوفة تحتوي على معلمات التهيئة للمرشح. يمكن تحديده كـ 0، أو undef حيث لا توجد معلمات. يجب أن يكون المعامل الثالث مرجعًا لكائن Template::Context الحالي.

تعيد الطريقة مرجعًا إلى دالة فرعية للمرشح عند النجاح. قد تعيد أيضًا "(undef, STATUS_DECLINE)" لرفض الطلب، للسماح بالوفد إلى موفري مرشحات آخرين في سلسلة المسؤولية LOAD_FILTERS. عند حدوث خطأ، يتم إعادة "($error, STATUS_ERROR)" حيث $error هو رسالة خطأ أو كائن Template::Exception يشير إلى الخطأ الذي حدث.

عند تعيين الخيار "TOLERANT"، يتم تخفيض الأخطاء تلقائيًا إلى استجابة "STATUS_DECLINE".

use_html_entities()

يمكن استدعاء طريقة الفئة هذه لتهيئة مرشح "html_entity" لاستخدام الوحدة HTML::Entities. سيتم رفع خطأ إذا لم تكن مثبتة على نظامك.

use Template::Filters;
Template::Filters->use_html_entities();

use_apache_util()

يمكن استدعاء طريقة الفئة هذه لتهيئة مرشح "html_entity" لاستخدام الوحدة Apache::Util. سيتم رفع خطأ إذا لم تكن مثبتة على نظامك.

use Template::Filters;
Template::Filters->use_apache_util();

use_rfc2732()

يمكن استدعاء طريقة الفئة هذه لتهيئة المرشحات "uri" و "url" لاستخدام معيار RFC2732 القديم لمطابقة الأحرف غير الآمنة.

use_rfc3986()

يمكن استدعاء طريقة الفئة هذه لتهيئة المرشحات "uri" و "url" لاستخدام معيار RFC3986 الجديد لمطابقة الأحرف غير الآمنة.

خيارات التهيئة

تلخص القائمة التالية خيارات التهيئة التي يمكن توفيرها لمنشئ "Template::Filters" new(). يرجى الرجوع إلى Template::Manual::Config لمزيد من المعلومات حول كل خيار.

FILTERS

يمكن استخدام خيار FILTERS لتحديد مرشحات مخصصة يمكن استخدامها بعد ذلك مع توجيه FILTER مثل أي مرشح آخر. تتم إضافتها إلى المرشحات القياسية المتاحة افتراضيًا.

$filters = Template::Filters->new({
    FILTERS => {
        'sfilt1' =>   \&static_filter,
        'dfilt1' => [ \&dyanamic_filter_factory, 1 ],
    },
});

TOLERANT

يمكن تعيين علامة TOLERANT للإشارة إلى أن الوحدة "Template::Filters" يجب أن تتجاهل أي أخطاء وتعيد بدلاً من ذلك "STATUS_DECLINED".

DEBUG

يمكن استخدام خيار DEBUG لتمكين رسائل التصحيح للوحدة Template::Filters عن طريق تعيينها لتشمل القيمة "DEBUG_FILTERS".

use Template::Constants qw( :debug );
my $template = Template->new({
    DEBUG => DEBUG_FILTERS | DEBUG_PLUGINS,
});

المرشحات القياسية

يرجى الرجوع إلى Template::Manual::Filters للحصول على قائمة بالمرشحات المتوفرة مع Template Toolkit، كاملة بأمثلة على الاستخدام.
