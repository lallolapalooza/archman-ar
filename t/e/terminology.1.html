TERMINOLOGY(1) صفحة دليل Terminology TERMINOLOGY(1)

الاسم

Terminology - محاكي طرفي مكتوب باستخدام EFL (مكتبات مؤسسة التنوير).

الملخص

terminology [خيارات]

الوصف

هذا محاكي طرفي EFL مع بعض الميزات الإضافية. يتميز بالعديد من الميزات بما في ذلك دعم الطرفيات المقسمة، ودعم علامات التبويب، وأيقونات معاينة للملفات وما إلى ذلك...

الخيارات

-e, --exec <الأمر>
تحديد الأمر المراد تنفيذه. الافتراضي هو $SHELL (أو shell المرور أو /bin/sh). عند استخدامه مع -S/--split، يتم استخدام كل وسيطة كأمر للقسم، مع تجاهل الوسائط الإضافية. مع 3 أقسام، قسم رأسي واحد، أمر على اليمين، قسم أفقي على اليسار مع أمر سفلي فقط، الوسائط التالية يجب استخدامها: --split v-h-- -e command1 $SHELL command2
-d=الدليل_الحالي, --current-directory=الدليل_الحالي
تغيير الدليل لتنفيذ أمر الطرفية. النوع: STR.
-t=السمة, --theme=السمة
استخدام سمة edje المسماة أو المسار إلى ملف السمة. النوع: STR.
-b=الخلفية, --background=الخلفية
استخدام الملف المسمى كخلفية شاشة لـ terminology. النوع: STR.
-g=الهندسة, --geometry=الهندسة
هندسة الطرفية المراد استخدامها (مثل 80x24 أو 80x24+50+20 إلخ). النوع: STR.
-n=الاسم, --name=الاسم
تعيين اسم النافذة. النوع: STR.
-r=الدور, --role=الدور
تعيين دور النافذة. النوع: STR.
-S=vh-, --split=vh-
يمكن لـ Terminology البدء بأقسام مفتوحة كما هو موضح أدناه. الوسائط هي سلسلة أحرف مع الأحرف التالية:
-S v يقسم الطرفية رأسيًا
-S h يقسم أفقيًا
- يحدد عنصرًا نائبًا لـ shell أو أمر عند استخدامه مع
--exec/-e
أمثلة:
______
| | |
$ terminology -S v |__|__|


______
|_____|
$ terminology -S h |_____|


______
|__| |
$ terminology -S vh |__|__|


______
| |__|
$ terminology -S v-h |__|__|


______
$ terminology -S vh--h |__|__|
hv--v |__|__|
النوع: STR.

-T=العنوان, --title=العنوان
تعيين عنوان النافذة. النوع: STR.
-i=اسم_الأيقونة, --icon-name=اسم_الأيقونة
تعيين اسم الأيقونة. النوع: STR.
-f=الخط, --font=الخط
تعيين الخط (اسم/حجم للخطوط القابلة للتغيير، اسم للخطوط النقطية). النوع: STR.
-l=تسجيل_الدخول, --login=تسجيل_الدخول
تشغيل shell كـ shell تسجيل دخول. النوع: BOOL.
-m=كتم_الفيديو, --video-mute=كتم_الفيديو
تعيين وضع الكتم لتشغيل الفيديو. النوع: BOOL.
-c=وميض_المؤشر, --cursor-blink=وميض_المؤشر
تعيين وضع وميض المؤشر. النوع: BOOL.
-G=جرس_مرئي, --visual-bell=جرس_مرئي
تعيين وضع الجرس المرئي. النوع: BOOL.
-F, --fullscreen
الدخول إلى وضع ملء الشاشة من البداية.
-I, --iconic
الدخول إلى حالة أيقونية من البداية.
-B, --borderless
أن تصبح نافذة مدارة بلا حدود.
-O, --override
أن تصبح نافذة تجاوز-إعادة توجيه.
-M, --maximized
أن تصبح مكبرة من البداية.
-W, --nowm
يتم تشغيل Terminology بدون مدير نوافذ (wm).
-H, --hold
لا تخرج عند انتهاء عملية الأمر.
-s, --single
فرض تنفيذ واحد إذا كان التعدد ممكّنًا.
-2, --256color
تعيين TERM إلى xterm-256color بدلاً من xterm.
--active-links=تنشيط_الروابط
ما إذا كان سيتم تمييز الروابط. النوع: BOOL.
--no-wizard
لا تعرض المعالج عند بدء التشغيل. النوع: BOOL.
--scale=الحجم
عامل تغيير الحجم المراد استخدامه على واجهة المستخدم. النوع: DOUBLE.
--colorscheme=مخطط_الألوان
استخدام مخطط الألوان المسماة. النوع: STR.
-V, --version
إظهار إصدار البرنامج.
-C, --copyright
إظهار حقوق النشر.
-L, --license
إظهار الترخيص.
-h, --help
إظهار هذه الرسالة.

COMMAND MODE COMMANDS

In command mode, you can invoke a number of commands that will either directly affect the terminal emulator, or more complex objects like images, videos, edje objects, or raw file transfers.

i[CW;H;FULL-PATH-OR-URL]
insert media (cell area). Otherwise parameters are identical to the is command, but uses media generation to make a fast to load but low resolution version (cached) of the media.
i[CW;H;FULL-PATH-OR-URL]
insert THUMB media (thumbnail cell area). Otherwise parameters are identical to the is command, but uses thumbnail generation to make a fast to load but low resolution version (cached) of the media.
i[CW;H;LINK\nFULL-PATH-OR-URL]
insert THUMB media with link (thumbnail cell area). Otherwise parameters are identical to the is command, but uses thumbnail generation to make a fast to load but low resolution version (cached) of the media. LINK is a path (or url) to open _when_ the thumb is clicked on by the user.
ij[CW;H;FULL-PATH\nGROUP][\n][cmd1][\r\n][cmd2]...
insert EDJE object with file path given, and the group name given. The command list (and the \n whitespace delimiter before the list) is optional, but is executed/parsed before display of the actual object to do things like initialize its initial state. See `iC` command for more details on the command list.

Be aware that once you have an object with an assigned channel id, it can send back signals and messages via escapes on stdin. These escapes will follow terminology extended escape format (ESC + } ... 00), and the content will be one of:

;CHID\ndrag\nPART NAME\nVAL1\nVAL2
;CHID\ndrag,start\nPART NAME\nVAL1\nVAL2
;CHID\ndrag,stop\nPART NAME\nVAL1\nVAL2
;CHID\ndrag,step\nPART NAME\nVAL1\nVAL2
;CHID\drag,set\nPART NAME\nVAL1\nVAL2
signal;CHID\nSIGNAL STRING\nSOURCE STRING
message;CHID\nOPCODE ID\nstring\nSTRING1
message;CHID\nOPCODE ID\nint\nINT1
message;CHID\nOPCODE ID\nfloat\nFLOAT1
message;CHID\nOPCODE ID\nstring_set\nSTRING1\nSTRING2\nSTRING3...
message;CHID\nOPCODE ID\nint_set\nINT1\nINT2\nINT3...
message;CHID\nOPCODE ID\nfloat_set\nFLOAT1\nFLOAT2\nFLOAT3...
message;CHID\nOPCODE ID\nstring_int\nSTRING1\nINT1
message;CHID\nOPCODE ID\nstring_float\nSTRING1\nFLOAT1
message;CHID\nOPCODE ID\nstring_int_set\nSTRING1\nINT1\nINT2\nINT3...
message;CHID\nOPCODE ID\nstring_float_set\nSTRING1\nFLOAT1\nFLOAT2\nFLOAT3...
iC[CHID]\n[cmd1][\r\n][cmd2][\r\n][cmd3]...
send a COMMAND (cmd1, cmd2, cmd3 etc.) to an existing named channel id CHID. this can be a list of 1 or more command strings, with each string broken by a continuous sequence of 1 or more \r and/or \n characters. e.g. "\n", "\r", "\r\n", "\n\r", "\n\r\n\n\n", etc.

commands understood are:

text\nPART NAME\nTEXT STRING
set the text of "PART NAME" to string "TEXT STRING"

emit\nSIGNAL STRING\nSOURCE STRING
emit signal "SIGNAL STRING" "SOURCE STRING"

drag\nPART NAME\n[value|size|step|page]\nVAL1\nVAL2
manipulate dragable of name "PART NAME" and either set "value", "size", "step" or "page" properties to "VAL1" and "VAL2" for x and y, where VAL1 and VAL2 are floating point values

chid\nCHANNEL ID
set the channel id of a given edje object (only valid in setup commands for the inline edje object) to "CHANNEL ID" so it can be addressed later.

message\nOPCODE ID\n[string|int|float|string_set|int_set|...
float_set|string|int|string_float|string_int_set|...
string_float_set]\n[message data]
send a message with opcode (integer) id "OPCODE ID" of one of the given types supported ("string", "int", "float", etc.) and then with the given "message data" at the end. message data format depends on message type:
string: STRING1
int: INT1
float: FLOAT1
string_set: STRING1\nSTRING2\nSTRING3...
int_set: INT1\nINT2\nINT3...
float_set: FLOAT1\nFLOAT2\nFLOAT3...
string_int: STRING1\nINT1
string_float: STRING1\nFLOAT1
string_int_set: STRING1\nINT1\nINT2\nINT3...
string_float_set: STRING1\nFLOAT1\nFLOAT2\nFLOAT3...
ib
begin media replace sequence run.
ie
end media replace sequence run.
fr[PATH/FILE]
begin file send for a file named PATH / FILE
fs[SIZE_BYTES]
set the size in bytes of a file send started with the above fr escape
fd[CHECKSUM DATA]
block of data for the current file transfer with checksum as a string decimal which is the sum of every byte when taken as an unsigned char per byte. the checksum is a signed 32bit integer. the checksum is the sum of the data after escaping. 4 bits at a time per data byte, encoded with high bits in one byte then low bits, with the bits encoded as 4 bit value being 0x40 + 4 bit value per byte. (@ == 0x0, A == 0x1, B == 0x2, ... N == 0xe, O == 0xf). so to rebuild a byte will be (((bytes[0] - 0x40) & 0xf) << 4) | ((bytes[1] - 0x40) & 0xf) per byte pair in the data block.
fx
exit file send mode (normally at the end of the file or when it's complete)
