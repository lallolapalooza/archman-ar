Term::Table::HashBase(3perl) دليل مبرمجي بيرل Term::Table::HashBase(3perl)

الاسم

Term::Table::HashBase - بناء فئات تعتمد على الهاش.

الملخص

فئة:

package My::Class;
use strict;
use warnings;
# توليد 3 محددات
use Term::Table::HashBase qw/foo -bar ^baz <bat >ban +boo/;
# فرصة لتهيئة القيم الافتراضية
sub init {
    my $self = shift;    # لا توجد وسائط أخرى
    $self->{+FOO} ||= "foo";
    $self->{+BAR} ||= "bar";
    $self->{+BAZ} ||= "baz";
    $self->{+BAT} ||= "bat";
    $self->{+BAN} ||= "ban";
    $self->{+BOO} ||= "boo";
}
sub print {
    print join ", " => map { $self->{$_} } FOO, BAR, BAZ, BAT, BAN, BOO;
}

فئة فرعية

package My::Subclass;
use strict;
use warnings;
# ملاحظة، يجب عليك إنشاء فئة فرعية قبل تحميل HashBase.
use base 'My::Class';
use Term::Table::HashBase qw/bub/;
sub init {
    my $self = shift;
    # نحصل على الثوابت من الفئة الأساسية مجانًا.
    $self->{+FOO} ||= 'SubFoo';
    $self->{+BUB} ||= 'bub';
    $self->SUPER::init();
}

استخدامها:

package main;
use strict;
use warnings;
use My::Class;
# هذه كلها متطابقة وظيفياً
my $one   = My::Class->new(foo => 'MyFoo', bar => 'MyBar');
my $two   = My::Class->new({foo => 'MyFoo', bar => 'MyBar'});
my $three = My::Class->new(['MyFoo', 'MyBar']);
# قارئات!
my $foo = $one->foo;    # 'MyFoo'
my $bar = $one->bar;    # 'MyBar'
my $baz = $one->baz;    # قيمة افتراضية: 'baz'
my $bat = $one->bat;    # قيمة افتراضية: 'bat'
# '>ban' يعني كاتب فقط، لا يوجد قارئ
# '+boo' يعني لا يوجد كاتب أو قارئ، فقط الثابت BOO
# كتاب!
$one->set_foo('A Foo');
#'-bar' يعني للقراءة فقط، لذا سيثير الكاتب استثناء (لكنه معرف).
$one->set_bar('A bar');
# '^baz' يعني كاتب مهمل، سيحذر هذا بشأن إهمال الكاتب.
$one->set_baz('A Baz');
# '<bat' يعني عدم وجود كاتب معرف على الإطلاق
# '+boo' يعني لا يوجد كاتب أو قارئ، فقط الثابت BOO
$one->{+FOO} = 'xxx';

الوصف

تُستخدم هذه الحزمة لتوليد فئات تستند إلى الهاش. سيمنحك استخدام هذه الفئة طريقة new()، بالإضافة إلى توليد المحددات التي تطلبها. ستكون المحددات التي تم إنشاؤها قراء (getters)، وسيتم أيضًا إنشاء كتاب (setters) باسم "set_ACCESSOR" لك. تحصل أيضًا على ثوابت لكل محدد (جميعها بأحرف كبيرة) والتي تُرجع المفتاح في الهاش لهذا المحدد. يتم أيضًا دعم الوراثة الأحادية.

هذه نسخة مجمعة من HASHBASE

هذه نسخة مجمعة من Object::HashBase. تم إنشاء هذا الملف باستخدام البرنامج النصي "/home/exodist/perl5/perlbrew/perls/main/bin/hashbase_inc.pl".

الطرق

مقدمة بواسطة HASH BASE

$it = $class->new(%PAIRS)
$it = $class->new(\%PAIRS)
$it = $class->new(\@ORDERED_VALUES)
إنشاء مثيل جديد.

لن يقوم HashBase بتصدير new() إذا كان هناك بالفعل طريقة new() في سلسلة وراثة حزمك.

إذا كنت لا تريد هذه الطريقة، يمكنك تعريف طريقتك الخاصة عليك فقط الإعلان عنها قبل تحميل Term::Table::HashBase.

package My::Package;
# تعريف جديد() مسبقًا حتى لا يمنحنا HashBase واحدة.
sub new;
use Term::Table::HashBase qw/foo bar baz/;
# الآن نحدد طريقة new الخاصة بنا.
sub new { ... }

هذا يجعل HashBase يرى أن لديك طريقة new() الخاصة بك. بدلاً من ذلك، يمكنك تعريف الطريقة قبل تحميل HashBase بدلاً من مجرد الإعلان عنها، ولكن هذا يبعثر عبارات الاستخدام الخاصة بك.

الطريقة الأكثر شيوعًا لإنشاء كائن هي تمرير أزواج مفتاح/قيمة حيث يكون كل مفتاح سمة وكل قيمة هي ما تريد تعيينه لتلك السمة. لا يتم إجراء أي فحص للتحقق من صحة السمات أو القيم، يمكنك القيام بذلك في init() إذا رغبت في ذلك.

إذا أردت، يمكنك تمرير هاشريف بدلاً من الأزواج. عند القيام بذلك، سيتم نسخ الهاشريف، وسيتم إرجاع النسخة مباركة ككائن. لا توجد طريقة للسؤال HashBase عن مباركة هاشريف معين.

في بعض الحالات، قد يحتوي الكائن على سمة أو اثنتين فقط، وفي هذه الحالات قد يكون الهاشريف طويلاً جدًا حسب رغبتك. في هذه الحالات، يمكنك تمرير مصفوفة تحتوي على قيم فقط. سيتم تعيين القيم للسمات بالترتيب الذي تم به سرد السمات. عند وجود وراثة، ستأتي سمات الفئات الأصلية قبل الفئات الفرعية.

خطافات

$self->init()
يمنحك هذا الفرصة لتعيين بعض القيم الافتراضية لحقولك. الوسيط الوحيد هو $self مع تعيين فهارسه بالفعل من المنشئ.

ملاحظة: يتحقق Term::Table::HashBase من وجود init باستخدام "$class->can('init')" أثناء البناء. لا يستدعي can() على الكائن الذي تم إنشاؤه. لاحظ أيضًا أن نتيجة الفحص يتم تخزينها مؤقتًا، ويتم فحصها مرة واحدة فقط، في المرة الأولى التي يتم فيها إنشاء مثيل لفئتك. هذا يعني أن إضافة طريقة init() بعد البناء الأول سيؤدي إلى تجاهلها.

المحددات

قراءة/كتابة

لتوليد المحددات، سردها عند استخدام الوحدة:

use Term::Table::HashBase qw/foo/;

سيؤدي هذا إلى توليد الدوال التالية في مساحة الاسم الخاصة بك:

foo()
قارئ (Getter)، يستخدم للحصول على قيمة حقل "foo".
set_foo()
كاتب (Setter)، يستخدم لتعيين قيمة حقل "foo".
FOO()
ثابت، يُرجع مفتاح حقل "foo" في هاش الفئة. ستحصل الفئات الفرعية أيضًا على هذه الوظيفة كثابت، وليس مجرد طريقة، مما يعني أنها تُنسخ إلى مساحة اسم الفئة الفرعية.

السبب الرئيسي لاستخدام هذه الثوابت هو المساعدة في تجنب أخطاء الإملاء والأخطاء المطبعية المماثلة. لن تساعدك إذا نسيت إضافة البادئة '+' مع ذلك.

للقراءة فقط

use Term::Table::HashBase qw/-foo/;
set_foo()
يثير استثناء يخبرك بأن السمة للقراءة فقط. يتم تصدير هذا لتجاوز أي كتاب نشطين للسمة في فئة أصل.

كاتب مهمل

use Term::Table::HashBase qw/^foo/;
set_foo()
سيقوم هذا بتعيين القيمة، ولكنه سيحذرك أيضًا من أن الطريقة مهملة.

لا يوجد كاتب

use Term::Table::HashBase qw/<foo/;

يوفر لك فقط قارئًا، ولا يتم تعريف طريقة "set_foo" على الإطلاق.

لا يوجد قارئ

use Term::Table::HashBase qw/>foo/;

فقط يوفر لك كاتبًا ("set_foo")، ولا يتم تعريف طريقة "foo" على الإطلاق.

ثابت فقط

use Term::Table::HashBase qw/+foo/;

هذا لا ينشئ أي طرق لك، بل يضيف فقط الثابت "FOO".
