الاختبار ليس شيئًا يجب التعامل معه باستخفاف، ولا تستخدمه كعذر للتهرب من العمل.

اختبار الكثير من القيم

سنرغب في اختبار الكثير من التواريخ هنا، محاولين خداع الكود بالكثير من الحالات الحدية المختلفة. هل يعمل قبل عام 1970؟ بعد عام 2038؟ قبل عام 1904؟ هل تسبب السنوات التي تتجاوز 10000 مشكلة؟ هل يتعامل مع السنوات الكبيسة بشكل صحيح؟ يمكننا الاستمرار في تكرار الكود أعلاه، أو يمكننا إعداد حلقة try/expect صغيرة.

use Test::More tests => 32;
use Date::ICal;
my %ICal_Dates = (
        # سلسلة ICal    والسنة والشهر واليوم
        #                    الساعة والدقيقة والثانية التي نتوقعها.
        '19971024T120000' =>    # من الوثائق.
                            [ 1997, 10, 24, 12,  0,  0 ],
        '20390123T232832' =>    # بعد حقبة يونكس
                            [ 2039,  1, 23, 23, 28, 32 ],
        '19671225T000000' =>    # قبل حقبة يونكس
                            [ 1967, 12, 25,  0,  0,  0 ],
        '18990505T232323' =>    # قبل حقبة ماك أو إس
                            [ 1899,  5,  5, 23, 23, 23 ],
);
while( my($ical_str, $expect) = each %ICal_Dates ) {
    my $ical = Date::ICal->new( ical => $ical_str );
    ok( defined $ical,            "new(ical => '$ical_str')" );
    ok( $ical->isa('Date::ICal'), "  وهي الفئة الصحيحة" );
    is( $ical->year,    $expect->[0],     '  year()'  );
    is( $ical->month,   $expect->[1],     '  month()' );
    is( $ical->day,     $expect->[2],     '  day()'   );
    is( $ical->hour,    $expect->[3],     '  hour()'  );
    is( $ical->min,     $expect->[4],     '  min()'   );
    is( $ical->sec,     $expect->[5],     '  sec()'   );
}

الآن يمكننا اختبار مجموعات من التواريخ بمجرد إضافتها إلى %ICal_Dates. الآن بعد أن أصبح اختبار المزيد من التواريخ أقل عبئًا، ستميل إلى مجرد إضافة المزيد منها كلما خطرت لك. المشكلة الوحيدة هي أنه في كل مرة نضيف فيها، يجب علينا الاستمرار في تعديل سطر "use Test::More tests => ##". يمكن أن يصبح هذا مزعجًا بسرعة. هناك طرق لجعل هذا يعمل بشكل أفضل.

أولاً، يمكننا حساب الخطة ديناميكيًا باستخدام الدالة plan().

use Test::More;
use Date::ICal;
my %ICal_Dates = (
    ...نفس السابق...
);
# لكل مفتاح في الهاش، نجري 8 اختبارات.
plan tests => keys(%ICal_Dates) * 8;
...ثم اختباراتك...

لزيادة المرونة، استخدم "done_testing". هذا يعني أننا نجري بعض الاختبارات، ولا نعرف عددها. [6]

use Test::More;   # بدلاً من tests => 32
... # اختبارات هنا
done_testing();   # تم الوصول إلى النهاية بأمان

إذا لم تحدد خطة، تتوقع Test::More رؤية done_testing() قبل خروج برنامجك. ستحذرك إذا نسيتها. يمكنك إعطاء done_testing() عددًا اختياريًا من الاختبارات التي توقعت تشغيلها، وإذا اختلف العدد الذي تم تشغيله، فسوف تعطيك Test::More نوعًا آخر من التحذيرات.

أسماء وصفية

ألق نظرة على السطر:

ok( defined $ical,            "new(ical => '$ical_str')" );

لقد أضفنا المزيد من التفاصيل حول ما نختبره وسلسلة ICal نفسها التي نجربها إلى الاسم. لذا تحصل على نتائج مثل:

ok 25 - new(ical => '19971024T120000')
ok 26 -   وهي الفئة الصحيحة
ok 27 -   year()
ok 28 -   month()
ok 29 -   day()
ok 30 -   hour()
ok 31 -   min()
ok 32 -   sec()

إذا فشل شيء ما هناك، ستعرف أي واحد كان، وسيؤدي ذلك إلى تسهيل تتبع المشكلة. حاول وضع القليل من معلومات التصحيح في أسماء الاختبارات.

صف ما تختبره الاختبارات، لجعل تصحيح اختبار فاشل أسهل لك أو للشخص التالي الذي يشغل اختبارك.

تخطي الاختبارات

بالبحث في اختبارات Date::ICal الحالية، وجدت هذا في t/01sanity.t [7]

#!/usr/bin/perl -w
use Test::More tests => 7;
use Date::ICal;
# تأكد من التعامل مع وقت الحقبة بشكل معقول.
my $t1 = Date::ICal->new( epoch => 0 );
is( $t1->epoch, 0,          "وقت الحقبة 0" );
# XXX سيعمل هذا فقط على أنظمة يونكس.
is( $t1->ical, '19700101Z', "  حقبة إلى ICal" );
is( $t1->year,  1970,       "  year()"  );
is( $t1->month, 1,          "  month()" );
is( $t1->day,   1,          "  day()"   );
# مثل الاختبارات أعلاه، ولكن بدءًا من ICal بدلاً من الحقبة
my $t2 = Date::ICal->new( ical => '19700101Z' );
is( $t2->ical, '19700101Z', "بداية الحقبة بتدوين ICal" );
is( $t2->epoch, 0,          "  والعودة إلى ICal" );

بداية الحقبة مختلفة على معظم أنظمة التشغيل غير Unix [8]. حتى لو قامت Perl بتلطيف الفروق إلى حد كبير، فإن بعض المنافذ تقوم بذلك بشكل مختلف. MacPerl هو أحدها الذي يتبادر إلى الذهن. [9] بدلاً من وضع تعليق في الاختبار والأمل في أن يقرأ شخص ما الاختبار أثناء تصحيح الفشل، يمكننا أن نقول صراحةً إنه لن يعمل أبدًا وتخطي الاختبار.

use Test::More tests => 7;
use Date::ICal;
# تأكد من التعامل مع وقت الحقبة بشكل معقول.
my $t1 = Date::ICal->new( epoch => 0 );
is( $t1->epoch, 0,          "وقت الحقبة 0" );
SKIP: {
    skip('epoch to ICal not working on Mac OS', 6)
        if $^O eq 'MacOS';
    is( $t1->ical, '19700101Z', "  حقبة إلى ICal" );
    is( $t1->year,  1970,       "  year()"  );
    is( $t1->month, 1,          "  month()" );
    is( $t1->day,   1,          "  day()"   );
    # مثل الاختبارات أعلاه، ولكن بدءًا من ICal بدلاً من الحقبة
    my $t2 = Date::ICal->new( ical => '19700101Z' );
    is( $t2->ical, '19700101Z', "بداية الحقبة بتدوين ICal" );
    is( $t2->epoch, 0,          "  والعودة إلى ICal" );
}

يحدث القليل من السحر هنا. عند التشغيل على أي شيء باستثناء MacOS، تعمل جميع الاختبارات بشكل طبيعي. ولكن عند التشغيل على MacOS، تتسبب skip() في تخطي المحتويات بأكملها لكتلة SKIP. إنها لا تعمل أبدًا. بدلاً من ذلك، تطبع skip() إخراجًا خاصًا يخبر Test::Harness أنه تم تخطي الاختبارات.

1..7
ok 1 - Epoch time of 0
ok 2 # skip epoch to ICal not working on MacOS
ok 3 # skip epoch to ICal not working on MacOS
ok 4 # skip epoch to ICal not working on MacOS
ok 5 # skip epoch to ICal not working on MacOS
ok 6 # skip epoch to ICal not working on MacOS
ok 7 # skip epoch to ICal not working on MacOS

هذا يعني أن اختباراتك لن تفشل على MacOS. هذا يعني عددًا أقل من رسائل البريد الإلكتروني من مستخدمي MacPerl الذين يخبرونك عن اختبارات فاشلة تعرف أنها لن تعمل أبدًا. يجب أن تكون حذرًا مع اختبارات التخطي. هذه للاختبارات التي لا تعمل ولن تعمل أبدًا. إنها ليست لتخطي الأخطاء الحقيقية (سنصل إلى ذلك بعد قليل).

يتم تخطي الاختبارات بالكامل وبشكل كامل. [10] سينجح هذا.

SKIP: {
    skip("I don't wanna die!");
    die, die, die, die, die;
}

اختبارات لم يتم إنجازها (Todo)

أثناء تصفح صفحة دليل Date::ICal، صادفت هذا:

ical
    $ical_string = $ical->ical;
يسترجع، أو يعيّن، التاريخ في الكائن، باستخدام أي سلسلة ICal date/time صالحة.

"يسترجع أو يعيّن". هممم. لم أر اختبارًا لاستخدام ical() لتعيين التاريخ في مجموعة اختبارات Date::ICal. لذلك كتبت واحدًا:

use Test::More tests => 1;
use Date::ICal;
my $ical = Date::ICal->new;
$ical->ical('20201231Z');
is( $ical->ical, '20201231Z',   'Setting via ical()' );

قم بتشغيل ذلك. رأيت:

1..1
not ok 1 - Setting via ical()
#     Failed test (- at line 6)
#          got: '20010814T233649Z'
#     expected: '20201231Z'
# Looks like you failed 1 tests of 1.

عفوًا! يبدو أنه غير منفذ. افترض أنك لا تملك الوقت لإصلاح هذا. [11] في العادة، كنت ستعلق الاختبار ببساطة وتضع ملاحظة في قائمة مهام أو شيء من هذا القبيل. بدلاً من ذلك، اذكر صراحةً "سيجتاز هذا الاختبار" عن طريق لفه في كتلة "TODO":

use Test::More tests => 1;
TODO: {
    local $TODO = 'ical($ical) not yet implemented';
    my $ical = Date::ICal->new;
    $ical->ical('20201231Z');
    is( $ical->ical, '20201231Z',   'Setting via ical()' );
}

الآن عندما تقوم بالتشغيل، يكون الأمر مختلفًا قليلاً:

1..1
not ok 1 - Setting via ical() # TODO ical($ical) not yet implemented
#          got: '20010822T201551Z'
#     expected: '20201231Z'

لا تقول Test::More "Looks like you failed 1 tests of 1". هذا '# TODO' يخبر Test::Harness "من المفترض أن يفشل هذا" ويعامله على أنه اختبار ناجح. يمكنك كتابة اختبارات حتى قبل إصلاح الكود الأساسي.

إذا نجح اختبار TODO، فسوف يبلغ Test::Harness عنه "UNEXPECTEDLY SUCCEEDED" (نجاح غير متوقع). عندما يحدث ذلك، قم بإزالة كتلة TODO باستخدام "local $TODO" وحولها إلى اختبار حقيقي.

الاختبار مع وضع التلوث (taint mode).

وضع التلوث شيء غريب. إنه أعم وأشمل من أي ميزة عامة. بمجرد تشغيله، يؤثر على جميع الأكواد في برنامجك وجميع الوحدات المستخدمة (وجميع الوحدات التي تستخدمها). إذا كان جزء واحد من الكود غير نظيف من حيث التلوث، فسينفجر الكل. مع أخذ ذلك في الاعتبار، من المهم جدًا التأكد من أن وحدتك تعمل في وضع التلوث.

من السهل جدًا تشغيل اختباراتك في وضع التلوث. فقط أضف "-T" إلى سطر "#!". ستقرأ Test::Harness المفاتيح في "#!" وتستخدمها لتشغيل اختباراتك.

#!/usr/bin/perl -Tw
...اختبر بشكل طبيعي هنا...

عندما تقول "make test"، سيتم التشغيل مع تفعيل وضع التلوث.
