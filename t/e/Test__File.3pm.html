file_readable_ok( FILENAME [, NAME ] )
جيد إذا كان الملف موجودًا وقابلًا للقراءة، وغير جيد إذا كان الملف غير موجود أو غير قابل للقراءة.
file_not_readable_ok( FILENAME [, NAME ] )
جيد إذا كان الملف موجودًا وغير قابل للقراءة، وغير جيد إذا كان الملف غير موجود أو قابل للقراءة.
file_writable_ok( FILENAME [, NAME ] )
file_writeable_ok( FILENAME [, NAME ] )
جيد إذا كان الملف موجودًا وقابلًا للكتابة، وغير جيد إذا كان الملف غير موجود أو غير قابل للكتابة.

الاسم الأصلي هو "file_writeable_ok" مع حرف e الإضافي. هذا لا يزال يعمل ولكن هناك دالة بالتهجئة الصحيحة أيضًا.

الاسم الأصلي هو "file_not_writeable_ok" مع حرف e الإضافي. هذا لا يزال يعمل ولكن هناك دالة بالتهجئة الصحيحة أيضًا.

file_executable_ok( FILENAME [, NAME ] )
جيد إذا كان الملف موجودًا وقابلًا للتنفيذ، وغير جيد إذا كان الملف غير موجود أو غير قابل للتنفيذ.

يتم تخطي هذا الاختبار تلقائيًا إذا كان يعتقد أنه على نظام ويندوز.

يتم تخطي هذا الاختبار تلقائيًا إذا كان يعتقد أنه على نظام ويندوز.

file_mode_is( FILENAME, MODE [, NAME ] )
جيد إذا كان الملف موجودًا وكانت الأوضاع متطابقة، وغير جيد إذا كان الملف غير موجود أو كانت الأوضاع غير متطابقة.

يتم تخطي هذا الاختبار تلقائيًا إذا كان يعتقد أنه على نظام ويندوز.

مساهمة من Shawn Sorichetti "<ssoriche@coloredblocks.net>"

file_mode_isnt( FILENAME, MODE [, NAME ] )
جيد إذا كان الملف موجودًا وكانت الأوضاع غير متطابقة، وغير جيد إذا كان الملف غير موجود أو كانت الأوضاع متطابقة.

يتم تخطي هذا الاختبار تلقائيًا إذا كان يعتقد أنه على نظام ويندوز.

مساهمة من Shawn Sorichetti "<ssoriche@coloredblocks.net>"

file_mode_has( FILENAME, MODE [, NAME ] )
جيد إذا كان الملف موجودًا وكانت جميع البتات في MODE مفعلة، وغير جيد إذا كان الملف غير موجود أو لم تتطابق الأوضاع. أي، يجب أن يكون "FILEMODE & MODE == MODE" صحيحًا.

يتم تخطي هذا الاختبار تلقائيًا إذا كان يعتقد أنه على نظام ويندوز.

مساهمة من Ricardo Signes "<rjbs@cpan.org>"

file_mode_hasnt( FILENAME, MODE [, NAME ] )
جيد إذا كان الملف موجودًا وكانت جميع البتات في MODE غير مفعلة، وغير جيد إذا كان الملف غير موجود أو لم تتطابق الأوضاع. أي، يجب أن يكون "FILEMODE & MODE == 0" صحيحًا.

يتم تخطي هذا الاختبار تلقائيًا إذا كان يعتقد أنه على نظام ويندوز.

مساهمة من Ricardo Signes "<rjbs@cpan.org>"

file_is_symlink_ok( FILENAME [, NAME ] )
جيد إذا كان FILENAME رابطًا رمزيًا، حتى لو كان يشير إلى ملف غير موجود. يتم تخطي هذا الاختبار تلقائيًا إذا كان نظام التشغيل لا يدعم الروابط الرمزية.
file_is_not_symlink_ok( FILENAME [, NAME ] )
جيد إذا كان FILENAME ليس رابطًا رمزيًا. يتم تخطي هذا الاختبار تلقائيًا إذا كان نظام التشغيل لا يدعم الروابط الرمزية. إذا كان الملف غير موجود، يفشل الاختبار.
symlink_target_exists_ok( SYMLINK [, TARGET] [, NAME ] )
جيد إذا كان FILENAME رابطًا رمزيًا وكان يشير إلى ملف موجود. مع الوسيط TARGET الاختياري، يفشل الاختبار إذا لم يكن هدف SYMLINK هو TARGET. يتم تخطي هذا الاختبار تلقائيًا إذا كان نظام التشغيل لا يدعم الروابط الرمزية. إذا كان الملف غير موجود، يفشل الاختبار.
symlink_target_dangles_ok( SYMLINK [, NAME ] )
جيد إذا كان FILENAME رابطًا رمزيًا وإذا كان لا يشير إلى ملف موجود. يتم تخطي هذا الاختبار تلقائيًا إذا كان نظام التشغيل لا يدعم الروابط الرمزية. إذا كان الملف غير موجود، يفشل الاختبار.
symlink_target_is( SYMLINK, TARGET [, NAME ] )
جيد إذا كان FILENAME رابطًا رمزيًا وإذا كان يشير إلى TARGET. يتم تخطي هذا الاختبار تلقائيًا إذا كان نظام التشغيل لا يدعم الروابط الرمزية. إذا كان الملف غير موجود، يفشل الاختبار.
symlink_target_is_absolute_ok( SYMLINK [, NAME ] )
جيد إذا كان FILENAME رابطًا رمزيًا وإذا كان هدفه مسارًا مطلقًا. يتم تخطي هذا الاختبار تلقائيًا إذا كان نظام التشغيل لا يدعم الروابط الرمزية. إذا كان الملف غير موجود، يفشل الاختبار.
dir_exists_ok( DIRECTORYNAME [, NAME ] )
جيد إذا كان الملف موجودًا وهو دليل، وغير جيد إذا كان الملف غير موجود، أو موجود ولكنه ليس دليلًا.

مساهمة من Buddy Burden "<barefoot@cpan.org>".

dir_contains_ok( DIRECTORYNAME, FILENAME [, NAME ] )
جيد إذا كان الدليل موجودًا ويحتوي على الملف، وغير جيد إذا كان الدليل غير موجود، أو موجود ولكنه لا يحتوي على الملف.

مساهمة من Buddy Burden "<barefoot@cpan.org>".

link_count_is_ok( FILE, LINK_COUNT [, NAME ] )
جيد إذا كان عدد الروابط للملف FILE هو LINK_COUNT. يتم تفسير LINK_COUNT كرقم صحيح. إذا كان LINK_COUNT يقيم إلى 0، فإنه يعود بجيد إذا كان الملف غير موجود.
link_count_gt_ok( FILE, LINK_COUNT [, NAME ] )
جيد إذا كان عدد الروابط للملف FILE أكبر من LINK_COUNT. يتم تفسير LINK_COUNT كرقم صحيح. إذا كان LINK_COUNT يقيم إلى 0، فإنه يعود بجيد إذا كان الملف لديه رابط واحد على الأقل.
link_count_lt_ok( FILE, LINK_COUNT [, NAME ] )
جيد إذا كان عدد الروابط للملف FILE أقل من LINK_COUNT. يتم تفسير LINK_COUNT كرقم صحيح. إذا كان LINK_COUNT يقيم إلى 0، فإنه يعود بجيد إذا كان الملف لديه رابط واحد على الأقل.
owner_is( FILE , OWNER [, NAME ] )
جيد إذا كان مالك الملف FILE هو نفسه OWNER. يمكن أن يكون OWNER اسم مستخدم نصي أو معرف مستخدم رقمي. يتم تخطي الاختبار على Dos، و Mac OS <= 9. إذا كان الملف غير موجود، يفشل الاختبار.

مساهمة من Dylan Martin

الملخص

use Test::File;

الوصف

Test::File هي وحدة Perl توفر مجموعة من وظائف الاختبار للتحقق من خصائص الملفات وسلوكياتها.

مهام قيد الإنجاز

* التحقق من الخصائص للمستخدمين الآخرين (مثل root_readable)

* التحقق من الأوقات

* التحقق من عدد الروابط لملف

* التحقق من أجزاء المسار (الدليل، اسم الملف، الامتداد)

انظر أيضًا

Test::Builder, Test::More

إذا كنت تستخدم "Test2" الجديد (Test2::Tools::File)، فراجع Test2::Tools::File (https://github.com/torbjorn/Test2-Tools-File).
