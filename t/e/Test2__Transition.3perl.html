TRANSITIONING

This document is for the transition from Test::Builder to Test2. It should also serve as a rough guide to transitioning Test::Builder based modules to use Test2.

It is important to note that Test2 is not a drop-in replacement for Test::Builder. The APIs are different, and the philosophies are different.

TESTING A MODULE FOR TEST2 COMPATIBILITY

The easiest way to ensure that your module works with Test2 is to run it through a Test2 harness. Test2 provides it's own harness, and it is capable of running Test::Builder based tests.

The Test2::Harness module is available on CPAN.

You can also use Test::Builder::Tester.

The following modules have been tested and have been found to be compatible with Test2:

Most Test::Builder based modules
Test2 is designed to be compatible with the vast majority of Test::Builder based modules. If your module uses only the public API of Test::Builder, then it should work out of the box.
Test::Builder::Tiny
This module provides a clean API for Test::Builder, that is also compatible with Test2. It has been fixed to work with Test2.

TESTING A MODULE FOR TEST_BUILDER COMPATIBILITY

If you are porting a module to Test2, you should also ensure that it still works with Test::Builder. This is important for users who have not yet upgraded to Test2.

The best way to do this is to use the Test::Builder::Tester module, which is available on CPAN.

You can also use the Test2::Harness module, which is capable of running Test::Builder based tests.
