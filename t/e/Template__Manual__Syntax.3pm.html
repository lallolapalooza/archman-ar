Template::Manual::Syntax - بناء جملة التوجيهات، الهيكل والمعاني

أنماط العلامات

تُضمن توجيهات القالب بين علامات البدء والانتهاء. افتراضياً، تكون علامات العلامات هذه "[%" و "%]".

[% PROCESS header %]
<h1>مرحباً بالعالم!</h1>
<a href="[% page.next %]"><img src="[% icon.next %].gif"></a>
[% PROCESS footer %]

يمكنك تغيير أحرف العلامات باستخدام خيارات التكوين "START_TAG" و "END_TAG" و "TAG_STYLE". يمكنك أيضاً استخدام التوجيه "TAGS" لتعريف نمط علامة جديد لملف القالب الحالي.

يمكنك أيضاً تعيين الخيار "INTERPOLATE" للسماح بتضمين مراجع المتغيرات البسيطة مباشرة في القوالب، مسبوقة بالرمز "$".

# INTERPOLATE = 0
<td>[% name %]</td>
<td>[% email %]</td>
# INTERPOLATE = 1
<td>$name</td>
<td>$email</td>

يمكن تضمين التوجيهات في أي مكان في سطر نصي ويمكن تقسيمها على عدة أسطر. يتم تجاهل المسافات البيضاء غير المهمة عمومًا داخل التوجيه.

[% INCLUDE header
     title = 'Hello World'
     bgcol = '#ffffff'
%]
[%INCLUDE menu align='right'%]
Name: [% name %]  ([%id%])

علامات المخطط التفصيلي

اعتبارًا من الإصدار 2.26، يدعم Template Toolkit علامات "المخطط التفصيلي". تحتوي هذه العلامات على علامة مخصصة في بداية السطر ( "%%" افتراضيًا) وتستمر حتى نهاية السطر. يتم تجاهل حرف السطر الجديد في نهاية السطر (يُعرف أيضًا بـ "التشذيب").

بدلاً من كتابة شيء كهذا:

[% IF some.list.size -%]
  <ul>
[%   FOREACH item IN some.list -%]
    <li>[% item.html %]</li>
[%   END -%]
  </ul>
[% END -%]

يمكنك كتابته هكذا بدلاً من ذلك:

%% IF some.list.size
  <ul>
%%   FOREACH item IN some.list
    <li>[% item.html %]</li>
%%   END
  </ul>
%% END

علامات المخطط التفصيلي ليست ممكّنة افتراضيًا. هناك عدد من الطرق لتمكينها. الأولى هي استخدام التوجيه "TAGS" لتعيين نمط العلامة إلى "outline" في أي قوالب تريد استخدامها فيها. سيؤدي هذا إلى تمكين علامات المخطط التفصيلي من تلك النقطة فصاعدًا.

[% TAGS outline -%]
%% INCLUDE header

يمكنك إعادة تعيين "TAGS" إلى القيمة "default" في وقت لاحق من القالب إذا كنت ترغب في تعطيلها:

[% TAGS default -%]

يمكنك تعيين خيار التكوين "TAG_STYLE" إذا كنت تريد تمكينها في جميع القوالب افتراضيًا. يمكنك دائمًا استخدام التوجيه "[% TAGS default %]" لتعطيلها في أي قوالب أو أجزاء من القوالب إذا لزم الأمر.

my $tt = Template->new({
    TAG_STYLE => 'outline',
});

يسمح لك الخيار "OUTLINE_TAG" بتعيين علامة المخطط التفصيلي إلى شيء آخر إذا لم تكن من محبي علامات النسبة المئوية. سيؤدي تعيين هذا الخيار إلى تمكين علامات المخطط التفصيلي تلقائيًا.

my $tt = Template->new({
    OUTLINE_TAG => '>>',
});

يمكنك أيضًا استخدام التوجيه "TAGS" لتحديد علاماتك المخصصة (البدء، الانتهاء، والآن اختياريًا، المخطط التفصيلي) لقالب أو جزء من قالب.

[% TAGS <* *> >> %]
>> INCLUDE header       # علامة المخطط التفصيلي
Hello <* name *>        # علامة مضمنة

إذا حددت علامة بداية ونهاية فقط، فسيتم تعطيل علامات المخطط التفصيلي.

[% TAGS <* *> %]        # لا توجد علامات للمخطط التفصيلي

التعليقات

يُستخدم الحرف "#" للإشارة إلى التعليقات داخل التوجيه. عندما يتم وضعه مباشرة داخل علامة التوجيه الافتتاحية، فإنه يتسبب في تجاهل التوجيه بأكمله.

[%# يتم تجاهل هذا التوجيه بالكامل
    مهما كان عدد الأسطر التي يمتد عليها
%]

في أي موضع آخر، يتسبب في معاملة ما تبقى من السطر الحالي كتعليق.

[% # هذا تعليق
   theta = 20      # وهذا أيضاً
   rho   = 30      # <aol>وأنا أيضاً!</aol>
%]

تشذيب المسافات البيضاء

يمكنك إضافة "-" أو "+" إلى بداية أو نهاية علامة التوجيه للتحكم في خيارات تشذيب المسافات البيضاء. انظر خيارات "PRE_CHOMP" و "POST_CHOMP" لمزيد من التفاصيل.

[% BLOCK foo -%]    # إزالة السطر الجديد اللاحق
This is block foo
[%- END %]          # إزالة السطر الجديد السابق

التوجيهات الضمنية: GET و SET

أبسط التوجيهات هي "GET" و "SET" والتي تسترجع وتحدث قيم المتغيرات على التوالي. الكلمتان المفتاحيتان "GET" و "SET" اختياريتان في الواقع لأن المحلل ذكي بما يكفي لرؤيتهما لما هما عليه حقًا (ولكن لاحظ التحذير أدناه بشأن استخدام تدوين التأثير الجانبي). وبالتالي، سترى عمومًا:

[% SET foo = 10 %]
[% GET foo %]

مكتوبًا كـ:

[% foo = 10 %]
[% foo %]

يمكنك أيضًا التعبير عن العبارات المنطقية البسيطة كتوجيهات "GET" ضمنية:

[% title or template.title or 'Default Title' %]
[% mode == 'graphics' ? "Graphics Mode Enabled" : "Text Mode" %]

يجب أن تبدأ جميع التوجيهات الأخرى بكلمة مفتاحية محددة بالأحرف الكبيرة (ولكن انظر الخيار "ANYCASE"). جميع الكلمات المفتاحية للتوجيهات مكتوبة بأحرف كبيرة لجعلها مميزة بصريًا وللتمييز بينها وبين المتغيرات ذات نفس الاسم ولكن بحالة مختلفة. من الصحيح تمامًا، على سبيل المثال، تعريف متغير يسمى "stop" وهو منفصل تمامًا عن توجيه "STOP".

[% stop = 'Clackett Lane Bus Depot' %]
The bus will next stop at [% stop %]    # متغير
[% STOP %]                              # توجيه

توجيهات الكتل

تحدد التوجيهات مثل "FOREACH" و "WHILE" و "BLOCK" و "FILTER" وما إلى ذلك، بداية كتلة قد تحتوي على نص أو توجيهات أخرى حتى توجيه "END" المطابق. يمكن تداخل الكتل بشكل غير محدود. تحدد توجيهات "IF" و "UNLESS" و "ELSIF" و "ELSE" أيضًا كتلًا ويمكن تجميعها بالطريقة المعتادة.

[% FOREACH item = [ 'foo' 'bar' 'baz' ] %]
   * Item: [% item %]
[% END %]
[% BLOCK footer %]
   Copyright 2000 [% me %]
   [% INCLUDE company/logo %]
[% END %]
[% IF foo %]
   [% FOREACH thing = foo.things %]
      [% thing %]
   [% END %]
[% ELSIF bar %]
   [% INCLUDE barinfo %]
[% ELSE %]
   do nothing...
[% END %]

يمكن أيضًا استخدام توجيهات الكتل في تدوين تآثير جانبي مناسب.

[% INCLUDE userinfo FOREACH user = userlist %]
[% INCLUDE debugtxt msg="file: $error.info"
     IF debugging %]
[% "Danger Will Robinson" IF atrisk %]

مقابل:

[% FOREACH user = userlist %]
   [% INCLUDE userinfo %]
[% END %]
[% IF debugging %]
   [% INCLUDE debugtxt msg="file: $error.info" %]
[% END %]
[% IF atrisk %]
Danger Will Robinson
[% END %]

التقاط مخرجات الكتلة

يمكن التقاط مخرجات التوجيه ببساطة عن طريق تعيين التوجيه لمتغير.

[% headtext = PROCESS header title="Hello World" %]
[% people = PROCESS userinfo FOREACH user = userlist %]

NAME

Template::Manual::Syntax - Template Toolkit syntax details

Tag Styles

The Template Toolkit uses tags to delimit directives and template variables. The default styles are:

   [% ... %]  # Directive tags
   [% ... %]  # Variable tags
   [% ... %]  # Text tags

However, these can be configured to use other styles, such as:

   <% ... %>   # Directive tags
   <:= ... =:; # Variable tags
   <% ... %>   # Text tags

A full list of supported tag styles can be found in the Template::Manual::Tags documentation.

Outline Tags

A less common but still supported tag style is the "outline" style.

   <%directive%>
       ... template ...
   <%/directive%>

This style is particularly useful for directives that define blocks of content, such as IF, WHILE, FOREACH, and INCLUDE.

   <% IF user %>
      Hello <%= user.name %>!
   <% ELSE %>
      Hello, guest!
   <% END %>

The "BLOCK" directive (see below) also supports this style.

Comments

Comments can be inserted into templates using the "COMMENT" directive:

[% COMMENT %]
   This is a comment and will be ignored by the template processor.
   It can span multiple lines.
[% END %]

Or, for single-line comments:

[% COMMENT text %]

There is also a shorthand syntax for comments:

   [%# This is a single-line comment %]

Chomping Whitespace

By default, the Template Toolkit outputs all text within the template, including whitespace. Sometimes, you may want to suppress this output. This can be achieved by "chomping" whitespace from the beginning or end of tags.

The "%" character appended to the start or end of a tag will cause leading or trailing whitespace, respectively, to be chomped.

   Leading whitespace chomped: [%% myvariable %]
   Trailing whitespace chomped: [% myvariable %]%]
   Both:                       [%% myvariable %]%]

A directive may have both leading and trailing whitespace chompers. For example:

   [%- PROCESS header %]
   [% END -%]

The "TRIM" directive can also be used to chomp whitespace from the output of a block of template code.

[% TRIM %]
    This text, and all whitespace surrounding it within this tag,
    will be chomped from the final output.
[% END %]

Implicit Directives: GET and SET

The Template Toolkit provides implicit "GET" and "SET" directives for retrieving and assigning values to template variables.

"GET" is implied when a variable name is used without any preceding directive.

[% name %]

This is equivalent to:

[% GET name %]

"SET" is implied when a variable name is followed by an equals sign ("=") and a value.

[% name = value %]

This is equivalent to:

[% SET name = value %]

The "SET" directive can also be used with a `IF` clause:

[% SET name = 'value' IF some_condition %]

Block Directives

Several directives, including "IF", "WHILE", "FOREACH", "TRY", and "TAGS", define blocks of template code. These blocks are typically delimited by an opening tag and a closing "END" tag.

[% IF condition %]
   ... template ...
[% ELSE IF another_condition %]
   ... template ...
[% ELSE %]
   ... template ...
[% END %]

The "BLOCK" directive is used for defining reusable blocks of template code or capturing large blocks of text or other content.

[% poem = BLOCK %]
   The boy stood on the burning deck,
   His fleece was white as snow.
   A rolling stone gathers no moss,
   And Keith is sure to follow.
[% END %]

Note one important caveat of using this syntax in conjunction with side-effect notation. The following directive does not behave as might be expected:

[% var = 'value' IF some_condition %]   # does not work

In this case, the directive is interpreted as (spacing added for clarity)

[% var = IF some_condition %]
   value
[% END %]

rather than

[% IF some_condition %]
   [% var = 'value' %]
[% END %]

The variable is assigned the output of the "IF" block which returns 'value' if true, but nothing if false. In other words, the following directive will always cause 'var' to be cleared.

[% var = 'value' IF 0 %]

To achieve the expected behaviour, the directive should be written as:

[% SET var = 'value' IF some_condition %]

Chaining Filters

Multiple "FILTER" directives can be chained together in sequence. They are called in the order defined, piping the output of one into the input of the next.

[% PROCESS somefile FILTER truncate(100) FILTER html %]

The pipe character, "|", can also be used as an alias for "FILTER".

[% PROCESS somefile | truncate(100) | html %]

Multiple Directive Blocks

Multiple directives can be included within a single tag when delimited by semi-colons. Note however that the "TAGS" directive must always be specified in a tag by itself.

[% IF title;
      INCLUDE header;
   ELSE;
      INCLUDE other/header  title="Some Other Title";
   END
%]

versus

[% IF title %]
   [% INCLUDE header %]
[% ELSE %]
   [% INCLUDE other/header  title="Some Other Title" %]
[% END %]
