Test__Deep(3pm)

Test::Deep(3) وثائق Perl المساهمة من المستخدم Test::Deep(3)

الاسم

Test::Deep - مقارنة عميقة مرنة للغاية

الإصدار

الإصدار 1.205

الملخص

use Test::More tests => $Num_Tests;
use Test::Deep;
cmp_deeply(
  $actual_horrible_nested_data_structure,
  $expected_horrible_nested_data_structure,
  "got the right horrible nested data structure"
);
cmp_deeply(
  $object,
  methods(name => "John", phone => "55378008"),
  "object methods ok"
);
cmp_deeply(
  \@array,
  [$hash1, $hash2, ignore()],
  "first 2 elements are as expected, ignoring 3"
);
cmp_deeply(
  $object,
  noclass({value => 5}),
  "object looks ok, not checking its class"
);
cmp_deeply(
  \@result,
  bag('a', 'b', {key => [1, 2]}),
  "array has the 3 things we wanted in some order"
);

الوصف

إذا لم تكن تعرف شيئًا عن الاختبار الآلي في Perl، فيجب عليك على الأرجح قراءة Test::Simple و Test::More قبل المتابعة. Test::Deep يستخدم إطار عمل Test::Builder.

يوفر لك Test::Deep طرقًا مرنة للغاية للتحقق من أن النتيجة التي حصلت عليها هي النتيجة التي كنت تتوقعها. في أبسط صوره، يقوم بمقارنة بنيتين عن طريق المرور عبر كل مستوى، والتأكد من تطابق القيم، وأن المصفوفات والأشياء لها نفس العناصر، وأن المراجع مُمنوحة للفئة الصحيحة. كما أنه يتعامل مع هياكل البيانات الدائرية دون الوقوع في حلقة لا نهائية.

حيث يصبح الأمر أكثر إثارة للاهتمام هو السماح لك بفعل شيء آخر بخلاف المقارنات الدقيقة البسيطة. مع السلاسل النصية، يقوم المعامل "eq" بالتحقق من أن سلسلتين نصيتين متساويتان تمامًا، ولكن في بعض الأحيان هذا ليس ما تريده. عندما لا تعرف بالضبط كيف يجب أن تكون السلسلة النصية ولكنك تعرف بعض الأشياء حول كيف يجب أن تبدو، فإن "eq" غير مفيد ويجب عليك استخدام مطابقة النمط بدلاً من ذلك. يوفر Test::Deep مطابقة النمط لهياكل البيانات المعقدة.

يحتوي Test::Deep على **الكثير** من التصديرات. انظر "EXPORTS" أدناه.

إصدار Perl

يجب أن تعمل هذه المكتبة على إصدارات Perl التي تم إصدارها منذ فترة طويلة. يجب أن تعمل على أي إصدار من Perl تم إصداره في السنوات الخمس الماضية.

على الرغم من أنها قد تعمل على إصدارات أقدم من Perl، لا يتم تقديم أي ضمان بأن الحد الأدنى للإصدار المطلوب لن يتم زيادته. يمكن زيادة الإصدار لأي سبب، ولا يوجد وعد بقبول التصحيحات لخفض الحد الأدنى المطلوب من Perl.

أمثلة

كيف يعمل Test::Deep أسهل بكثير في الفهم من خلال رؤية بعض الأمثلة.

بدون Test::Deep

لنفترض أنك تريد اختبار دالة تُرجع سلسلة نصية. أنت تعلم أن سلسلتك النصية يجب أن تكون رقمًا مكونًا من 7 أرقام يبدأ بـ 0، و "eq" غير مفيد في هذا الموقف، فأنت بحاجة إلى تعبير عادي. لذلك يمكنك استخدام دالة like() الخاصة بـ Test::More:

like($string, qr/^0[0-9]{6}$/, "number looks good");

وبالمثل، للتحقق من أن سلسلة نصية تبدو كاسم، يمكنك القيام بما يلي:

like($string, qr/^(Mr|Mrs|Miss) \w+ \w+$/,
  "got title, first and last name");

الآن تخيل أن دالتك تنتج أشياء (hash) تحتوي على بعض التفاصيل الشخصية. تريد التأكد من وجود مفتاحين، Name و Phone، وأن الاسم يبدو كاسم ورقم الهاتف يبدو كرقم هاتف. يمكنك القيام بما يلي:

$hash = make_person();
like($hash->{Name}, qr/^(Mr|Mrs|Miss) \w+ \w+$/, "name ok");
like($hash->{Phone}, qr/^0[0-9]{6}$/, "phone ok");
is(scalar keys %$hash, 2, "correct number of keys");

لكن هذا ليس صحيحًا تمامًا، ماذا لو كان make_person يواجه مشكلة خطيرة ولم يُرجع حتى أشياء (hash)؟ نحتاج حقًا إلى كتابة:

if (ref($hash) eq "HASH")
{
  like($hash->{Name}, qr/^(Mr|Mrs|Miss) \w+ \w+$/, "name ok");
  like($hash->{Phone}, qr/^0[0-9]{6}$/, "phone ok");
  is(scalar keys %$hash, 2, "correct number of keys");
}
else
{
  fail("person not a hash");
  fail("person not a hash");
  fail("person not a hash"); # need 3 to keep the plan correct
}

بالفعل أصبح هذا فوضويًا، والآن تخيل إدخالًا آخر في الأشياء (hash)، وهو مصفوفة من أسماء الأطفال. هذا سيتطلب:

if (ref($hash) eq "HASH")
{
  like($hash->{Name}, $name_pat, "name ok");
  like($hash->{Phone}, '/^0d{6}$/', "phone ok");
  my $cn = $hash->{ChildNames};
  if (ref($cn) eq "ARRAY")
  {
    foreach my $child (@$cn)
    {
      like($child, $name_pat);
    }
  }
  else
  {
      fail("child names not an array")
  }
}
else
{
  fail("person not a hash");
}

هذه فوضى مروعة ولأننا لا نعرف مقدمًا عدد أسماء الأطفال، لا يمكننا وضع خطة لاختبارنا بعد الآن (في الواقع، يمكننا ذلك ولكنه سيجعل الأمور أكثر تعقيدًا).

Test::Deep للإنقاذ.

مع Test::Deep

my $name_re = re('^(Mr|Mrs|Miss) \w+ \w+$');
cmp_deeply(
  $person,
  {
    Name => $name_re,
    Phone => re('^0d{6}$'),
    ChildNames => array_each($name_re)
  },
  "person ok"
);

سيؤدي هذا إلى القيام بكل ما تفعله الشفرة الفوضوية أعلاه وسيُقدم رسالة معقولة تخبرك بالضبط بما حدث خطأ إذا وجد جزءًا من $person لا يتطابق مع النمط. re() و array_each() هما دالتان خاصتان مستوردتان من Test::Deep. تنشئان علامة تخبر Test::Deep أن شيئًا مختلفًا يحدث هنا. بدلاً من مجرد إجراء مقارنة بسيطة والتحقق مما إذا كان شيئان متساويين تمامًا، يجب عليه القيام بشيء آخر.

إذا طُلب من شخص ما التحقق من أن شيئين متساويين، فيمكنه طباعتهما معًا ومقارنتهما سطرًا بسطر. العلامات أعلاه تشبه كتابة ملاحظة باللون الأحمر على إحدى المطبوعات تخبر الشخص أنه بالنسبة لهذا الجزء من البنية، يجب عليه التوقف عن إجراء مقارنة سطر بسطر بسيطة والقيام بشيء آخر.

re($regex) يعني أن Test::Deep يجب أن يتحقق من أن جزء البيانات الحالي يتطابق مع التعبير العادي في $regex. array_each($struct) يعني أن Test::Deep يجب أن يتوقع أن يكون جزء البيانات الحالي مصفوفة ويجب عليه التحقق من أن كل عنصر في تلك المصفوفة يتطابق مع $struct. في هذه الحالة، يجب أن يبدو كل عنصر من "$person->{ChildNames}" كاسم. إذا كان العنصر الثالث مثلاً لا يبدو كذلك، فستحصل على رسالة خطأ مثل

Using Regexp on $data->{ChildNames}[3]
   got    : 'Queen John Paul Sartre'
   expect : /^(Mr|Mrs|Miss) \w+ \w+$/

هناك العديد من المقارنات الخاصة الأخرى المتاحة، انظر "SPECIAL COMPARISONS PROVIDED" أدناه للحصول على القائمة الكاملة.

إعادة استخدام الهياكل

Test::Deep جيد لإعادة استخدام هياكل الاختبار حتى تتمكن من القيام بما يلي

my $name_re = re('^(Mr|Mrs|Miss) \w+ \w+$');
my $person_cmp = {
  Name => $name_re,
  Phone => re('^0d{6}$'),
  ChildNames => array_each($name_re)
};
cmp_deeply($person1, $person_cmp, "person ok");
cmp_deeply($person2, $person_cmp, "person ok");
cmp_deeply($person3, $person_cmp, "person ok");

يمكنك حتى وضع $person_cmp في وحدة والسماح للآخرين باستخدامه عند كتابة نصوص اختبار لوحدات تستخدم وحداتك.

لجعل الأمور أصعب قليلاً، دعنا نغير بنية بيانات الشخص بحيث بدلاً من قائمة ChildNames، تحتوي على قائمة من الأشياء (hash)، واحدة لكل طفل. لذلك في الواقع، ستحتوي بنية الشخص لدينا على هياكل شخص أخرى قد تحتوي على هياكل شخص أخرى وهكذا. هذا سهل التعامل معه مع Test::Deep لأن هياكل Test::Deep يمكن أن تتضمن نفسها. فقط افعل

my $name_re = re('^(Mr|Mrs|Miss) \w+ \w+$');
my $person_cmp = {
  Name => $name_re,
  Phone => re('^0d{6}$'),
  # note no mention of Children here
};
$person_cmp->{Children} = array_each($person_cmp);
cmp_deeply($person, $person_cmp, "person ok");

سيتحقق هذا الآن من أن $person->{Children} هي مصفوفة وأن كل عنصر في تلك المصفوفة أيضاً

DESCRIPTION

The Test::Deep distribution provides a framework for testing deep structures. It allows you to test that, for example, a hash contains a certain key, and that the value associated with that key is itself a hash which contains another key, and so on.

The main function provided is cmp_deeply(), which allows you to compare two Perl data structures for equality.

You can also use Test::Deep to check that a structure matches a particular pattern, rather than being exactly equal to it. For example, you could check that a hash contains a 'name' key, and that the value associated with that key is a string that matches a regular expression.

It also provides functions for generating detailed diagnostic output when tests fail, which can be invaluable when debugging complex data structures.

USING TEST::DEEP

The primary way to use Test::Deep is via the cmp_deeply() function.

use Test::Deep;
cmp_deeply($got, $expected, $name);

$got is the actual data structure that you are testing. $expected is the structure that you expect $got to be equal to. $name is the name of the test.

cmp_deeply() works recursively. It will compare the elements of $got and $expected one by one. If $got and $expected are hashes, it will compare the keys and values of the hashes. If they are arrays, it will compare the elements of the arrays. This process continues until the entire structure has been compared.

The following example shows how to use cmp_deeply() to test a simple hash:

my $person = {
  name => 'John Doe',
  age  => 30,
};
my $expected_person = {
  name => 'John Doe',
  age  => 30,
};
cmp_deeply($person, $expected_person, 'person hash');

In this example, cmp_deeply() will compare the keys and values of $person with those of $expected_person. If they are identical, the test will pass.

You can also use regular expressions to match values within the structure:

my $person = {
  name => 'John Doe',
  phone => '555-1234',
};
my $expected_person = {
  name => re('^\w+ \w+$'),
  phone => re('^\d{3}-\d{4}$'),
};
cmp_deeply($person, $expected_person, 'person hash with regex');

In this case, cmp_deeply() will check that the value of 'name' matches the regular expression /^\w+ \w+$/ and that the value of 'phone' matches the regular expression /^\d{3}-\d{4}$/.

Deep comparison

cmp_deeply will compare structures recursively. This means that if it encounters a hash or array reference in the expected structure, it will descend into that structure and compare its contents with the corresponding contents of the actual structure.

For example, consider the following structure:

my $person = {
  name => 'John Doe',
  address => {
    street => '123 Main St',
    city => 'Anytown',
    zip => '12345',
  },
};
my $expected_person = {
  name => 'John Doe',
  address => {
    street => '123 Main St',
    city => 'Anytown',
    zip => '12345',
  },
};
cmp_deeply($person, $expected_person, 'person with address');

In this case, cmp_deeply() will first compare the 'name' fields. Then, it will see that the 'address' field is a hash reference in both structures. It will then descend into these hash references and compare their contents recursively.

This recursive comparison means that cmp_deeply can handle arbitrarily nested data structures.

Circular data structures

A circular data structure is one which loops back on itself, you can make one easily by doing

my @b;
my @a = (1, 2, 3, \@b);
push(@b, \@a);

now @a contains a reference to be @b and @b contains a reference to @a. This causes problems if you have a program that wants to look inside @a and keep looking deeper and deeper at every level, it could get caught in an infinite loop looking into @a then @b then @a then @b and so on.

Test::Deep avoids this problem so we can extend our example further by saying that a person should also list their parents.

my $name_re = re('^(Mr|Mrs|Miss) \w+ \w+$');
my $person_cmp = {
  Name => $name_re,
  Phone => re('^0d{6}$'),
  # note no mention of Children here
};
$person_cmp->{Children} = each_array($person_cmp);
$person_cmp->{Parents} = each_array($person_cmp);
cmp_deeply($person, $person_cmp, "person ok");

So this will check that for each child $child in "$person->{Children}" that the "$child->{Parents}" matches $person_cmp however it is smart enough not to get caught in an infinite loop where it keeps bouncing between the same Parent and Child.

TERMINOLOGY

"cmp_deeply($got, $expected, $name)" takes 3 arguments. $got is the structure that you are checking, you must not include any special comparisons in this structure or you will get a fatal error. $expected describes what Test::Deep will be looking for in $got. You can put special comparisons in $expected if you want to.

As Test::Deep descends through the 2 structures, it compares them one piece at a time, so at any point in the process, Test::Deep is thinking about 2 things - the current value from $got and the current value from $expected. In the documentation, I call them $got_v and "exp_v" respectively.

COMPARISON FUNCTIONS

cmp_deeply

my $ok = cmp_deeply($got, $expected, $name)

$got is the result to be checked. $expected is the structure against which $got will be check. $name is the test name.

This is the main comparison function, the others are just wrappers around this. $got and $expected are compared recursively. Each value in $expected defines what's expected at the corresponding location in $got. Simple scalars are compared with "eq". References to structures like hashes and arrays are compared recursively.

Items in $expected, though, can also represent complex tests that check for numbers in a given range, hashes with at least a certain set of keys, a string matching a regex, or many other things.

See "WHAT ARE SPECIAL COMPARISONS" for details.

cmp_bag

my $ok = cmp_bag(\@got, \@bag, $name)

Is shorthand for cmp_deeply(\@got, bag(@bag), $name)

n.b.: Both arguments must be array refs. If they aren't an exception will be thrown.

cmp_set

my $ok = cmp_set(\@got, \@set, $name)

Is shorthand for cmp_deeply(\@got, set(@set), $name)

cmp_methods

my $ok = cmp_methods(\@got, \@methods, $name)

Is shorthand for cmp_deeply(\@got, methods(@methods), $name)

eq_deeply

my $ok = eq_deeply($got, $expected)

This is the same as cmp_deeply() except it just returns true or false. It does not create diagnostics or talk to Test::Builder, but if you want to use it in a non-testing environment then you should import it through Test::Deep::NoTest. For example

use Test::Deep::NoTest;
print "a equals b" unless eq_deeply($a, $b);

otherwise the Test::Builder framework will be loaded and testing messages will be output when your program ends.

cmp_details

($ok, $stack) = cmp_details($got, $expected)

This behaves much like eq_deeply, but it additionally allows you to produce diagnostics in case of failure by passing the value in $stack to "deep_diag".

Do not make assumptions about the structure or content of $stack and do not use it if $ok contains a true value.

See "USING TEST::DEEP WITH TEST::BUILDER" for example uses.

SPECIAL COMPARISONS PROVIDED

In the documentation below, $got_v is used to indicate any given value within the $got structure.

ignore

cmp_deeply( $got, ignore() );

This makes Test::Deep skip tests on $got_v. No matter what value $got_v has, Test::Deep will think it's correct. This is useful if some part of the structure you are testing is very complicated and already tested elsewhere, or if it is unpredictable.

cmp_deeply(
  $got,
  {
    name    => 'John',
    random  => ignore(),
    address => [ '5 A street', 'a town', 'a country' ],
  }
);

is the equivalent of checking

$got->{name} eq 'John';
exists $got->{random};
cmp_deeply($got->{address}, ['5 A street', 'a town', 'a country']);

methods

cmp_deeply( $got, methods(%hash) );

%hash is a hash of method call => expected value pairs.

This lets you call methods on an object and check the result of each call. The methods will be called in the order supplied. If you want to pass arguments to the method you should wrap the method name and arguments in an array reference.

cmp_deeply(
  $obj,
  methods(name => "John", ["favourite", "food"] => "taco")
);

is roughly the equivalent of checking that

$obj->name eq "John"
$obj->favourite("food") eq "taco"

The methods will be called in the order you supply them and will be called in scalar context. If you need to test methods called in list context then you should use listmethods().

NOTE Just as in a normal test script, you need to be careful if the methods you call have side effects like changing the object or other objects in the structure. Although the order of the methods is fixed, the order of some other tests is not so if $expected is

{
  manager => methods(@manager_methods),
  coder => methods(@coder_methods)
}

there is no way to know which if manager and coder will be tested first. If the methods you are testing depend on and alter global variables or if manager and coder are the same object then you may run into problems.

listmethods

cmp_deeply( $got, listmethods(%hash) );

%hash is a hash of pairs mapping method names to expected return values.

This is almost identical to methods() except the methods are called in list context instead of scalar context. This means that the expected return values supplied must be in array references.

cmp_deeply(
  $obj,
  listmethods(
    name => [ "John" ],
    ["favourites", "food"] => ["Mapo tofu", "Gongbao chicken"]
  )
);

is the equivalent of checking that

cmp_deeply([$obj->name], ["John"]);
cmp_deeply([$obj->favourites("food")], ["Mapo tofu", "Gongbao chicken"]);

The methods will be called in the order you supply them.

NOTE The same caveats apply as for methods().

shallow

cmp_deeply( $got, shallow($thing) );

$thing is a ref.

This prevents Test::Deep from looking inside $thing. It allows you to check that $got_v and $thing are references to the same variable. So

my @a = @b = (1, 2, 3);
cmp_deeply(\@a, \@b);

will pass because @a and @b have the same elements however

cmp_deeply(\@a, shallow(\@b))

will fail because although "\@a" and "\@b" both contain "1, 2, 3" they are references to different arrays.

noclass

cmp_deeply( $got, noclass($thing) );

$thing is a structure to be compared against.

This makes Test::Deep ignore the class of objects, so it just looks at the data they contain. Class checking will be turned off until Test::Deep is finished comparing $got_v against $thing. Once Test::Deep comes out of $thing it will go back to its previous setting for checking class.

This can be useful when you want to check that objects have been constructed correctly but you don't want to write lots of "bless"es. If @people is an array of Person objects then

cmp_deeply(\@people, [
  bless {name => 'John', phone => '555-5555'}, "Person",
  bless {name => 'Anne', phone => '444-4444'}, "Person",
]);

can be replaced with

cmp_deeply(\@people, noclass([
  {name => 'John', phone => '555-5555'},
  {name => 'Anne', phone => '444-4444'}
]));

However, this is testing so you should also check that the objects are blesse

d بشكل صحيح. يمكنك استخدام خريطة لمباركة كل تلك التجزئات أو يمكنك القيام باختبار ثانٍ مثل

cmp_deeply(\@people, array_each(isa("Person"));

useclass

cmp_deeply( $got, useclass($thing) );

هذا يعيد تشغيل مقارنة الفئة أثناء وجودك داخل noclass().

cmp_deeply(
  $got,
  noclass(
    [
      useclass( $object )
    ]
  )
)

في هذا المثال، يتم تجاهل فئة مرجع المصفوفة في $got ولكن يتم التحقق من فئة $object، وكذلك فئة كل شيء داخل $object.

re

cmp_deeply( $got, re($regexp, $capture_data, $flags) );

$regexp هو إما مرجع تعبير عادي تم إنتاجه باستخدام "qr/.../" أو سلسلة سيتم استخدامها لإنشاء تعبير عادي.

$capture_data اختياري ويستخدم للتحقق من السلاسل التي تم التقاطها بواسطة تعبير عادي. يمكن أن يكون هذا مرجع مصفوفة أو مقارن Test::Deep يعمل على مراجع المصفوفات.

$flags هي سلسلة اختيارية تتحكم فيما إذا كان التعبير العادي يعمل ك مطابقة شاملة. إذا كان $flags هو "g"، فسيعمل التعبير العادي كـ "m/$regexp/g".

بدون $capture_data، يقوم هذا ببساطة بمقارنة $got_v بالتعبير العادي المقدم. لذا

cmp_deeply($got, [ re("ferg") ])

يعادل

$got->[0] =~ /ferg/

مع $capture_data،

cmp_deeply($got, [re($regex, $capture_data)])

يعادل

my @data = $got->[0] =~ /$regex/;
cmp_deeply(\@data, $capture_data);

لذلك يمكنك القيام بشيء بسيط مثل

cmp_deeply($got, re(qr/(\d\d)(\w\w)/, [25, "ab" ]))

للتحقق من أن "(\d\d)" كان 25 وأن "(\w\w)" كان "ab" ولكن يمكنك أيضًا استخدام كائنات Test::Deep لإجراء اختبارات أكثر تعقيدًا للقيم الملتقطة

cmp_deeply(
  "cat=2,dog=67,sheep=3,goat=2,dog=5",
  re(
    qr/(\D+)=\d+,?/,
    set(qw( cat sheep dog )),
    "g"
  ),
);

هنا، سيتطابق التعبير العادي مع السلسلة ويلتقط أسماء الحيوانات ويتحقق من مطابقتها للمجموعة المحددة، وفي هذه الحالة ستفشل، معلنة أن "goat" ليس في المجموعة.

all

cmp_deeply( $got, all(@expecteds) );

@expecteds هي مصفوفة من الهياكل المتوقعة.

يتيح لك هذا مقارنة البيانات بنتائج متوقعة متعددة والتأكد من مطابقتها جميعًا.

cmp_deeply($got, all(isa("Person"), methods(name => 'John')))

يعادل

$got->isa("Person")
$got->name eq 'John'

إذا فشل أي من الاختبارين، فسيتم اعتبار الكل فاشلاً. هذا اختبار قصير الدائرة، يتوقف الاختبار بعد الفشل الأول، على الرغم من أنه في المستقبل قد يكمل جميع الاختبارات حتى يمكن إخراج التشخيصات لجميع حالات الفشل. عند الإبلاغ عن الفشل، يتم عد الأجزاء من 1.

بفضل سحر التحميل الزائد، يمكنك الكتابة

any( re("^wi"), all(isa("Person"), methods(name => 'John')) )

كـ

re("^wi") | isa("Person") & methods(name => 'John')

لاحظ "|" **واحد** وليس مزدوجًا، حيث لا يمكن تحميل "||" بشكل زائد. سيعمل هذا فقط عندما يكون هناك مقارنة خاصة متضمنة. إذا كتبت

"john" | "anne" | "robert"

سيقوم Perl بتحويل هذا إلى

"{onort"

وهو ما يفترض أنه ليس ما أردته. هذا لأن Perl يقوم بدمجها كسلاسل قبل أن تتاح لـ Test::Deep فرصة للقيام بأي حيل تحميل زائد.

any

cmp_deeply( $got, any(@expecteds) );

@expecteds هي مصفوفة من الهياكل المتوقعة.

يمكن استخدام هذا لمقارنة البيانات بنتائج متوقعة متعددة والتأكد من أن واحدة منها على الأقل تتطابق. هذا اختبار قصير الدائرة، لذا إذا نجح اختبار، فلن يتم محاولة أي اختبارات بعد ذلك.

يمكنك أيضًا استخدام التحميل الزائد مع "|" بشكل مشابه لـ all().

Isa

cmp_deeply( $got, Isa($class) );

isa

cmp_deeply( $got, isa($class) );

$class هو اسم فئة.

يستخدم هذا UNIVERSAL::isa() للتحقق من أن $got_v مباركة في الفئة $class.

**ملاحظة:** Isa() يفعل تمامًا كما هو موثق هنا، ولكن isa() مختلف قليلاً. إذا تم استدعاء isa() بحجة واحدة، فإنه ينتقل إلى Isa(). إذا تم استدعاء isa() بحجتين، فإنه ينتقل إلى "UNIVERSAL::isa". هذا لمنع الأعطال عند استيراد isa() إلى حزمة تستخدم كفئة. بدون هذا، أي شخص يستدعي "Class->isa($other_class)" سيحصل على إجابة خاطئة. هذه خدعة لتصحيح حقيقة أن "isa" يتم تصديرها افتراضيًا.

obj_isa

cmp_deeply( $got, obj_isa($class) );

يقبل هذا الاختبار فقط الكائنات التي هي مثيلات لـ $class أو فئة فرعية. على عكس اختبار "Isa"، لن يقبل هذا الاختبار أسماء الفئات أبدًا.

array_each

cmp_deeply( \@got, array_each($thing) );

$thing هو هيكل للمقارنة ضده.

<$got_v> يجب أن يكون مرجع مصفوفة. سيتم مقارنة كل عنصر منه بـ $thing. هذا مفيد عندما يكون لديك مصفوفة من الأشياء المماثلة، على سبيل المثال كائنات من نوع معروف ولا تريد تكرار نفس الاختبار لكل منها.

my $common_tests = all(
   isa("MyFile"),
   methods(
     handle => isa("IO::Handle")
     filename => re("^/home/ted/tmp"),
  )
);
cmp_deeply($got, array_each($common_tests));

مشابه لـ

foreach my $got_v (@$got) {
  cmp_deeply($got_v, $common_tests)
}

باستثناء أنه لن ينفجر إذا لم يكن $got مرجع مصفوفة. سيتحقق من أن كل كائن في @$got هو MyFile وأن كل واحد منهم يعطي النتائج الصحيحة لطرق عمله.

يمكنك الذهاب أبعد من ذلك، على سبيل المثال إذا كان هناك 3 ملفات وكنت تعرف حجم كل منها، يمكنك القيام بذلك

cmp_deeply(
  $got,
  all(
    array_each($common_tests),
    [
      methods(size => 1000),
      methods(size => 200),
      methods(size => 20)
    ]
  )
)
cmp_deeply($got, array_each($structure));

hash_each

cmp_deeply( \%got, hash_each($thing) );

يختبر هذا الاختبار مثل "array_each" (انظر أعلاه) ولكنه يختبر أن كل قيمة في الجدول تجتاز اختباراتها.

str

cmp_deeply( $got, str($string) );

$string هي سلسلة.

سيقوم هذا بتحويل $got_v إلى سلسلة ومقارنتها بـ $string باستخدام "eq"، حتى لو كان $got_v مرجعًا. إنه مفيد للتحقق من القيمة المحولة إلى سلسلة لمرجع محمل بشكل زائد.

num

cmp_deeply( $got, num($number, $tolerance) );

$number هو رقم.

$tolerance هو رقم اختياري.

سيقوم هذا بإضافة 0 إلى $got_v والتحقق مما إذا كان مساويًا رقميًا لـ $number، حتى لو كان $got_v مرجعًا. إنه مفيد للتحقق من القيمة الرقمية لمرجع محمل بشكل زائد. إذا تم توفير $tolerance، فسيتحقق هذا من أن $got_v و $exp_v أقل من $tolerance. هذا مفيد عند مقارنة أرقام الفاصلة العائمة حيث يمكن أن تؤدي أخطاء التقريب إلى صعوبة أو استحالة أن يكون $got_v مساويًا تمامًا لـ $exp_v. عندما يتم توفير $tolerance، ينجح الاختبار إذا كان "abs($got_v - $exp_v) <= $tolerance".

**ملاحظة** في Perl، ""12blah" == 12" لأن Perl سيكون ذكيًا ويحول "12blah" إلى 12. قد لا ترغب في ذلك. كان هناك وضع صارم ولكنه ذهب الآن. سيحل محل "يشبه الرقم" قريباً. حتى ذلك الحين، يمكنك عادةً استخدام مقارنة string() لتكون أكثر صرامة. سيعمل هذا بشكل جيد لمعظم المواقف، ولكنه لن يعمل عندما يكون <$got_v> قيمة محملة بشكل زائد تختلف قيمتها كسلسلة وقيمتها الرقمية.

bool, true, false

cmp_deeply( $got, bool($value) );
cmp_deeply( $got, true );
cmp_deeply( $got, false );

$value هو أي شيء تريده ولكن من الأفضل على الأرجح استخدام 0 أو 1

سيتحقق هذا من أن $got_v و $value لهما نفس القيمة المنطقية، أي أنهما سيعطيان نفس النتيجة عند استخدامهما في سياق منطقي، مثل جملة if().

**ملاحظة:** "true" و "false" يتم استيرادهما فقط بطلب خاص.

code

cmp_deeply( $got, code(\&subref) );

"\&subref" هو مرجع لروتين فرعي سيتم تمرير وسيطة واحدة إليه، ثم يجب أن يعيد قيمة صحيحة أو خاطئة وربما سلسلة.

سيقوم هذا بتمرير $got_v إلى الروتين الفرعي الذي يعيد قيمة صحيحة أو خاطئة للإشارة إلى نجاح أو فشل. يمكن أن تكون حالات الفشل مصحوبة بسلسلة تشخيصية توضح سبب فشلها.

sub check_name
{
  my $name = shift;
  if ($boss->likes($name))
  {
    return 1;
  }
  else
  {
    return (0, "the boss doesn't like your name");
  }
}
cmp_deeply("Brian", code(\&check_name));

NAME

Test::Deep - Deep comparison of Perl data structures

VERSION

1.205

SYNOPSIS

  use Test::Deep;
  use Test::More tests => 2;

  cmp_deeply(
      [ 1, { name => 'foo', age => 30 }, [ 'a', 'b' ] ],
      [ 1, { name => 'foo', age => 30 }, [ 'a', 'b' ] ],
      'simple deep comparison',
  );

  cmp_deeply(
      [ 1, { name => 'foo', age => 30 }, [ 'a', 'b' ] ],
      [ 1, { name => 'foo', age => 30 }, [ 'a', re('^b') ] ],
      'using special comparators',
  );

DESCRIPTION

This module provides a way to do deep comparisons of Perl data structures. It's like Test::More's is_deeply, but more flexible. It allows you to use special comparators for parts of the data structure.

PERL_VERSION

  This module requires Perl 5.008001 or later.

EXAMPLES

See SYNOPSIS.

TERMINOLOGY

A deep comparison is a recursive comparison of two data structures. It works like this:

  • If the two data structures are identical (using == for numbers, eq for strings, etc.), they are deeply equal.
  • If they are both arrays, compare their elements recursively.
  • If they are both hashes, compare their keys and values recursively.
  • Otherwise, they are not deeply equal.

A special comparison (SC) is an object that knows how to compare itself to a value. They are used to make deep comparisons more flexible. For example, instead of requiring a value to be exactly 'foo', you could use re('foo') to check if it matches the regular expression /foo/.

COMPARISON FUNCTIONS

The main comparison function is cmp_deeply. It takes three arguments:

  cmp_deeply($got, $expected, $test_name)
  • $got: The data structure you want to test.
  • $expected: The data structure you expect. This can contain special comparisons.
  • $test_name: The name of the test.

It returns true if the comparison succeeds, false otherwise. It also automatically generates diagnostic output if the comparison fails.

There are also convenience functions for comparing specific data structures:

  cmp_bag( $got, $expected, $test_name )
  cmp_set( $got, $expected, $test_name )
  cmp_hash( $got, $expected, $test_name )
  cmp_array( $got, $expected, $test_name )

These work like cmp_deeply, but they expect the top-level data structure to be a bag, set, hash, or array respectively.

SPECIAL COMPARISONS PROVIDED

Test::Deep provides a variety of special comparisons:

"all($val1, $val2, ...)"
All values must match.
"any($val1, $val2, ...)"
At least one value must match.
"none($val1, $val2, ...)"
No values must match.
"noneof($val1, $val2, ...)"
Synonym for none.
"array(@elems)"
Matches an array ref with exactly the given elements in the given order.
"array_each($matcher)"
Matches an array ref where each element matches the matcher.
"bag(@elems)"
Matches an array ref containing exactly the given elements, in any order. Duplicate elements are allowed.
"bag( {foo => 1}, {bar => 2} )"
Matches a hash ref containing exactly the given key/value pairs, in any order. Note that the keys are compared by value, not by reference.
"bool($val)"
Matches a value that is true or false (1 or undef).
"code(...)"
Matches a code reference. You can provide a regex to match the source code.
"eq_deeply($got, $expected)"
Same as cmp_deeply.
"hash(@pairs)"
Matches a hash ref with exactly the given key/value pairs. The order of pairs does not matter.
"hash_each($matcher)"
Matches a hash ref where each value matches the matcher.
"hashkeys($matcher)"
Matches a hash ref where each key matches the matcher.
"ignore()"
Always matches. Useful for ignoring specific fields.
"isa($class)"
Matches a value that is an instance of the given class.
"methods(%methods)"
Matches an object that has the given methods, with the given return values.
"noneof(...)"
See none.
"num($num)"
Matches a number.
"obj_isa($class)"
Same as isa.
"re($regex)"
Matches a string that matches the given regular expression.
"regexponly($regex)"
Matches a string that matches the given regular expression. Only the regex is compared.
"regexpref($regex)"
Matches a string that matches the given regular expression. The regex itself is compared.
"regexprefonly($regex)"
Matches a string that matches the given regular expression. Only the regex is compared.
"scalarrefonly()"
Matches a scalar reference.
"set(@elems)"
Matches an array ref containing exactly the given elements, in any order. Duplicate elements are not allowed.
"set( {foo => 1}, {bar => 2} )"
Matches a hash ref containing exactly the given key/value pairs, in any order. Note that the keys are compared by value, not by reference.
"str($str)"
Matches a string.

DIAGNOSTIC FUNCTIONS

cmp_details and deep_diag are provided for use within Test::Builder subclasses.

cmp_details($got, $expected) returns a two-element list: ($ok, $stack).

$ok is true if the comparison succeeded, false otherwise.

$stack is a data structure representing the differences between $got and $expected. This is used by deep_diag to generate a diagnostic message.

deep_diag($stack) takes the stack produced by cmp_details and returns a nicely formatted string suitable for use with diag.

ANOTHER EXAMPLE

This example shows how to use bag to check if an array contains certain elements, regardless of order.

  use Test::Deep;
  use Test::More tests => 1;

  my @items = ( { name => 'apple',  color => 'red'  },
                  { name => 'banana', color => 'yellow' },
                  { name => 'orange', color => 'orange' } );

  cmp_deeply(
      \@items,
      bag(
          { name => 'apple',  color => 'red'  },
          { name => 'banana', color => 'yellow' },
          { name => 'orange', color => 'orange' }
      ),
      'all fruits are present',
  );

This test will pass even if the elements in @items are in a different order.

USING TEST::DEEP WITH TEST::BUILDER

Combining "cmp_details" and "deep_diag" makes it possible to use Test::Deep in your own test classes.

In a Test::Builder subclass, create a test method in the following form:

sub behaves_ok {
  my $self = shift;
  my $expected = shift;
  my $test_name = shift;
  my $got = do_the_important_work_here();
  my ($ok, $stack) = cmp_details($got, $expected);
  unless ($Test->ok($ok, $test_name)) {
    my $diag = deep_diag($stack);
    $Test->diag($diag);
  }
}

As the subclass defines a test class, not tests themselves, make sure it uses Test::Deep::NoTest, not "Test::Deep" itself.

LIMITATIONS

Currently any CODE, GLOB or IO refs will be compared using shallow(), which means only their memory addresses are compared.

BUGS

There is a bug in set and bag compare to do with competing SCs. It only occurs when you put certain special comparisons inside bag or set comparisons you don't need to worry about it. The full details are in the bag() docs. It will be fixed in an upcoming version.

CAVEATS

SPECIAL CARE WITH SPECIAL COMPARISONS IN SETS AND BAGS

If you use certain special comparisons within a bag or set comparison there is a danger that a test will fail when it should have passed. It can only happen if two or more special comparisons in the bag are competing to match elements. Consider this comparison

cmp_deeply(['furry', 'furball'], bag(re("^fur"), re("furb")))

There are two things that could happen, hopefully re("^fur") is paired with "furry" and re("^furb") is paired with "furball" and everything is fine but it could happen that re("^fur") is paired with "furball" and then re("^furb") cannot find a match and so the test fails. Examples of other competing comparisons are "bag(1, 2, 2)" vs "set(1, 2)" and "methods(m1 => "v1", m2 => "v2")" vs "methods(m1 => "v1")"

This problem is could be solved by using a slower and more complicated algorithm for set and bag matching. Something for the future...

WHAT ARE SPECIAL COMPARISONS?

A special comparison (SC) is simply an object that inherits from Test::Deep::Cmp. Whenever $expected_v is an SC then instead of checking "$got_v eq $expected_v", we pass control over to the SC and let it do its thing.

Test::Deep exports lots of SC constructors, to make it easy for you to use them in your test scripts. For example is re("hello") is just a handy way of creating a Test::Deep::Regexp object that will match any string containing "hello". So

cmp_deeply([ 'a', 'b', 'hello world'], ['a', 'b', re("^hello")]);

will check 'a' eq 'a', 'b' eq 'b' but when it comes to comparing 'hello world' and re("^hello") it will see that $expected_v is an SC and so will pass control to the Test::Deep::Regexp class by do something like "$expected_v->descend($got_v)". The descend() method should just return true or false.

This gives you enough to write your own SCs but I haven't documented how diagnostics works because it's about to get an overhaul (theoretically).

EXPORTS

By default, Test::Deep will export everything in its "v0" tag, as if you had written:

use Test::Deep ':v0';

Those things are:

all any array array_each arrayelementsonly arraylength arraylengthonly bag
blessed bool cmp_bag cmp_deeply cmp_methods cmp_set code eq_deeply hash
hash_each hashkeys hashkeysonly ignore Isa isa listmethods methods noclass
none noneof num obj_isa re reftype regexpmatches regexponly regexpref
regexprefonly scalarrefonly scalref set shallow str subbagof subhashof
subsetof superbagof superhashof supersetof useclass

A slightly better set of exports is the "v1" set. It's all the same things, with the exception of "Isa" and "blessed". If you want to import "everything", you probably want to "use Test::Deep ':V1';".

There's another magic export group: ":preload". If that is specified, all of the Test::Deep plugins will be loaded immediately instead of lazily.
