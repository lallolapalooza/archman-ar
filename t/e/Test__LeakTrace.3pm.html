Test__LeakTrace(3pm)

الحزمة: perl-test-leaktrace

التراخيص: PerlArtistic, GPL

Test::LeakTrace(3) توثيق مساهمات Perl Test::LeakTrace(3)

الاسم

Test::LeakTrace - تتبع تسرب الذاكرة

الإصدار

يصف هذا المستند Test::LeakTrace الإصدار 0.17.

الملخص

use Test::LeakTrace;
# تقرير بسيط
leaktrace{
    # ...
};
# إخراج مفصل
leaktrace{
    # ...
} -verbose;
# مع رد اتصال
leaktrace{
    # ...
} sub {
    my($ref, $file, $line) = @_;
    warn "leaked $ref from $file line\n";
};
my @refs = leaked_refs{
    # ...
};
my @info = leaked_info{
    # ...
};
my $count = leaked_count{
    # ...
};
# واجهة اختبار قياسية
use Test::LeakTrace;
no_leaks_ok{
    # ...
} 'no memory leaks';
leaks_cmp_ok{
    # ...
} '<', 10;

الوصف

"Test::LeakTrace" يوفر العديد من الوظائف التي تتتبع تسرب الذاكرة. تقوم هذه الوحدة بفحص المساحات (arenas)، نظام تخصيص الذاكرة، لذلك يمكنها اكتشاف أي SV تم تحريره في كتل معينة.

SVs المحررة هي SVs التي لا يتم تحريرها بعد نهاية النطاق الذي تم إنشاؤها فيه. تشمل هذه SVs المتغيرات العامة والتخزينات المؤقتة الداخلية. على سبيل المثال، إذا قمت باستدعاء طريقة داخل كتلة تتبع، فقد يقوم Perl بإعداد ذاكرة تخزين مؤقت للطريقة. لتتبع التسرب الحقيقي، يتم استدعاء no_leaks_ok() و leaks_cmp_ok() للكتلة أكثر من مرة.

الواجهة

الوظائف المصدرة

"leaked_info { BLOCK }"

ينفذ BLOCK ويعيد قائمة من SVs المحررة وأين تأتي هذه SVs، أي "[$ref, $file, $line]".

"leaked_refs { BLOCK }"

ينفذ BLOCK ويعيد قائمة من SVs المحررة.

"leaked_count { BLOCK }"

ينفذ BLOCK ويعيد عدد SVs المحررة.

"leaktrace { BLOCK } ?($mode | \&callback)"

ينفذ BLOCK ويبلغ عن SVs المحررة إلى *STDERR.

القيم $mode المعرفة هي:

-simple
افتراضي. يبلغ عن هوية SVs المحررة (النوع والعنوان)، اسم الملف ورقم السطر.
-sv_dump
بالإضافة إلى -simple، يطبع محتويات SV باستخدام sv_dump()، والذي ينفذ أيضًا Devel::Peek::Dump().
-lines
بالإضافة إلى -simple، يطبع الأسطر المشبوهة.
-verbose
كل من -sv_dump و -lines.

"no_leaks_ok { BLOCK } ?$description"

يختبر أن BLOCK لا يحرر SVs. هذه وظيفة اختبار باستخدام "Test::Builder".

ملاحظة: يتم استدعاء BLOCK أكثر من مرة. هذا لأن BLOCK قد يقوم بإعداد ذاكرة تخزين مؤقت ليست تسربًا للذاكرة.

"leaks_cmp_ok { BLOCK } $cmp_op, $number, ?$description"

يختبر أن BLOCK يحرر عددًا محددًا من SVs. هذه وظيفة اختبار باستخدام "Test::Builder".

ملاحظة: يتم استدعاء BLOCK أكثر من مرة. هذا لأن BLOCK قد يقوم بإعداد ذاكرة تخزين مؤقت ليست تسربًا للذاكرة.

count_sv()

يعد جميع SVs في المساحة.

واجهة البرنامج النصي

يتم توفير "Devel::LeakTrace" و "Test::LeakTrace::Script" لبرامج نصية كاملة.

وسيطات "use Test::LeakTrace::Script" هي نفسها كما في leaktrace().

$ TEST_LEAKTRACE=-sv_dump perl -MTest::LeakTrace::Script script.pl
$ perl -MTest::LeakTrace::Script=-verbose script.pl
#!perl
# ...
use Test::LeakTrace::Script sub{
    my($ref, $file, $line) = @_;
    # ...
};
# ...

أمثلة

اختبار الوحدات

إليك مثال لبرنامج نصي اختباري يتحقق من تسرب الذاكرة.

#!perl -w
use strict;
use constant HAS_LEAKTRACE => eval{ require Test::LeakTrace };
use Test::More HAS_LEAKTRACE ? (tests => 1) : (skip_all => 'require Test::LeakTrace');
use Test::LeakTrace;
use Some::Module;
leaks_cmp_ok{
    my $o = Some::Module->new();
    $o->something();
    $o->something_else();
} '<', 1;

التبعيات

Perl 5.8.1 أو أحدث، ومترجم C.

ملاحظات

"Test::LeakTrace" لا يعمل مع "Devel::Cover" والوحدات التي تثبت إجراءات "runops" الخاصة بها أو منفذ Perl. إذا اكتشفت وظائف الاختبار في هذه الوحدة إجراءات "runops" غريبة، فإنها لا تفعل شيئًا وتبلغ "ok".
