Text__Template(3pm)

الحزمة: perl-text-template

التراخيص: PerlArtistic, GPL

Text::Template(3) توثيق Perl من مساهمة المستخدم Text::Template(3)

الاسم

Text::Template - توسيع نص القالب مع Perl مضمن

الإصدار

الإصدار 1.61

الملخص

use Text::Template;
$template = Text::Template->new(TYPE => 'FILE',  SOURCE => 'filename.tmpl');
$template = Text::Template->new(TYPE => 'ARRAY', SOURCE => [ ... ] );
$template = Text::Template->new(TYPE => 'FILEHANDLE', SOURCE => $fh );
$template = Text::Template->new(TYPE => 'STRING', SOURCE => '...' );
$template = Text::Template->new(PREPEND => q{use strict;}, ...);
# استخدام صيغة مختلفة لملف القالب:
$template = Text::Template->new(DELIMITERS => [$open, $close], ...);
$recipient = 'King';
$text = $template->fill_in();  # يستبدل `{$recipient}' بـ `King'
print $text;
$T::recipient = 'Josh';
$text = $template->fill_in(PACKAGE => T);
# تمرير العديد من المتغيرات بشكل صريح
$hash = { recipient => 'Abed-Nego',
          friends => [ 'me', 'you' ],
          enemies => { loathsome => 'Saruman',
                       fearsome => 'Sauron' },
        };
$text = $template->fill_in(HASH => $hash, ...);
# $recipient هو Abed-Nego،
# @friends هو ( 'me', 'you' )،
# %enemies هو ( loathsome => ..., fearsome => ... )
# استدعاء &callback في حالة حدوث أخطاء برمجية في القالب
$text = $template->fill_in(BROKEN => \&callback, BROKEN_ARG => $ref, ...);
# تقييم أجزاء البرنامج في حاوية آمنة مع صلاحيات مقيدة
$text = $template->fill_in(SAFE => $compartment, ...);
# طباعة نص النتيجة بدلاً من إرجاعه
$success = $template->fill_in(OUTPUT => \*FILEHANDLE, ...);
# تحليل القالب بصيغة ملف قالب مختلفة:
$text = $template->fill_in(DELIMITERS => [$open, $close], ...);
# لاحظ أن هذا *أسرع* من استخدام المحددات الافتراضية
# إضافة كود Perl محدد مسبقًا إلى كل جزء قبل تقييمه:
$text = $template->fill_in(PREPEND => q{use strict 'vars';}, ...);
use Text::Template 'fill_in_string';
$text = fill_in_string( <<'EOM', PACKAGE => 'T', ...);
Dear {$recipient},
Pay me at once.
       Love, 
        G.V.
EOM
use Text::Template 'fill_in_file';
$text = fill_in_file($filename, ...);
# جميع القوالب سيكون لها دائمًا `use strict vars` ملحقة بجميع الأجزاء
Text::Template->always_prepend(q{use strict 'vars';});

الوصف

هذه مكتبة لإنشاء رسائل نموذجية، وبناء صفحات HTML، أو ملء قوالب بشكل عام. `القالب' هو قطعة نصية تحتوي على برامج Perl صغيرة مضمنة هنا وهناك. عندما `تملأ' قالبًا، فإنك تقوم بتقييم البرامج الصغيرة واستبدالها بقيمها.

يمكنك تخزين القالب في ملف خارج برنامجك. يمكن للأشخاص تعديل القالب دون تعديل البرنامج. يمكنك فصل تفاصيل التنسيق عن الكود الرئيسي، ووضع أجزاء التنسيق من البرنامج في القالب. هذا يمنع تضخم الكود ويشجع الفصل الوظيفي.

مثال

هذا مثال لقالب، سنفترض أنه مخزن في الملف "formletter.tmpl":

Dear {$title} {$lastname},
It has come to our attention that you are delinquent in your
{$monthname[$last_paid_month]} payment.  Please remit
${sprintf("%.2f", $amount)} immediately, or your patellae may
be needlessly endangered.
                Love,
                Mark "Vizopteryx" Dominus

نتيجة ملء هذا القالب هي سلسلة نصية، قد تبدو شيئًا مثل هذا:

Dear Mr. Smith,
It has come to our attention that you are delinquent in your
February payment.  Please remit
$392.12 immediately, or your patellae may
be needlessly endangered.
                Love,
                Mark "Vizopteryx" Dominus

هذا برنامج كامل يحول القالب المثال إلى النتيجة المثال، ويطبعها:

use Text::Template;
my $template = Text::Template->new(SOURCE => 'formletter.tmpl')
  or die "Couldn't construct template: $Text::Template::ERROR";
my @monthname = qw(January February March April May June
                   July August September October November December);
my %vars = (title           => 'Mr.',
            firstname       => 'John',
            lastname        => 'Smith',
            last_paid_month => 1,   # February
            amount          => 392.12,
            monthname       => \@monthname);
my $result = $template->fill_in(HASH => \%vars);
if (defined $result) { print $result }
else { die "Couldn't fill in template: $Text::Template::ERROR" }

فلسفة

عندما ينشئ الأشخاص وحدة قوالب مثل هذه، فإنهم يبدأون دائمًا باختراع صيغة خاصة للتعويضات. على سبيل المثال، يبنونها بحيث يتم استبدال سلسلة مثل "%%VAR%%" بقيمة $VAR. ثم يدركون الحاجة إلى تنسيق إضافي، لذا يضعون صيغة خاصة للتنسيق. ثم يحتاجون إلى حلقة، لذا يبتكرون صيغة للحلقة. سرعان ما يصبح لديهم لغة قوالب صغيرة جديدة.

هذا النهج له مشكلتان: أولاً، لغتهم الصغيرة معيبة. إذا كنت بحاجة إلى فعل شيء لم يفكر فيه المؤلف، فإنك تخسر. ثانيًا: من يريد تعلم لغة أخرى؟ أنت تعرف بالفعل Perl، فلماذا لا تستخدمها؟

قوالب "Text::Template" مبرمجة بـ Perl. تقوم بتضمين كود Perl في قالبك، مع "{" في البداية و "}" في النهاية. إذا كنت تريد استبدال متغير، فإنك تكتبه بالطريقة التي تكتبها في Perl. إذا كنت بحاجة إلى إنشاء حلقة، فيمكنك استخدام أي من تراكيب الحلقات في Perl. جميع الدوال المضمنة في Perl متاحة.

التفاصيل

تحليل القالب

تقوم وحدة "Text::Template" بفحص مصدر القالب. تبدأ القوس الأيسر "{" بجزء برنامج، والذي يستمر حتى القوس الأيمن المطابق "}". عند ملء القالب، يتم تقييم أجزاء البرنامج، ويتم استبدال كل منها بالقيمة الناتجة لإنتاج النص الذي يتم إرجاعه.

يشير شرطة مائلة عكسية "\" قبل قوس (أو شرطة مائلة عكسية أخرى أمام قوس) إلى الهروب من معناه الخاص. نتيجة الانتهاء من هذا القالب:

\{ The sum of 1 and 2 is {1+2}  \}

هو

{ The sum of 1 and 2 is 3  }

إذا كان لديك قوس غير متطابق، فإن "Text::Template" سترجع رمز فشل وتحذيرًا حول مكان المشكلة. يتم تمرير الشرطات المائلة العكسية التي لا تسبق قوسًا دون تغيير. إذا كان لديك قالب مثل هذا:

{ "String that ends in a newline.\n" }

يتم تمرير الشرطة المائلة العكسية داخل السلسلة إلى Perl دون تغيير، لذلك يتحول "\n" حقًا إلى سطر جديد. انظر الملاحظة في النهاية للحصول على تفاصيل حول طريقة عمل الشرطات المائلة العكسية. لا يتم إجراء معالجة الشرطة المائلة العكسية عند تحديد محددات بديلة باستخدام الخيار "DELIMITERS". (انظر "المحددات البديلة"، أدناه.)

يجب أن يكون كل جزء برنامج تسلسلاً من عبارات Perl، والتي يتم تقييمها بالطريقة المعتادة. سيتم تقييم نتيجة العبارة الأخيرة المنفذة في سياق عددي؛ نتيجة هذه العبارة هي سلسلة نصية، يتم استبدالها في القالب مكان جزء البرنامج نفسه.

يتم تقييم الأجزاء بترتيبها، وستبقى الآثار الجانبية من الأجزاء السابقة في الأجزاء اللاحقة:

{$x = @things; ''}The Lord High Chamberlain has gotten {$x}
things for me this year.
{ $diff = $x - 17;
  $more = 'more'
  if ($diff == 0) {
    $diff = 'no';
  } elsif ($diff < 0) {
    $more = 'fewer';
  }
  '';
}
That is {$diff} {$more} than he gave me last year.

ستبقى قيمة $x المعينة في السطر الأول في الجزء التالي الذي يبدأ في السطر الثالث، وستبقى قيم $diff و $more المعينة في الجزء الثاني ويتم استبدالها في السطر الأخير. ستبدو النتيجة شيئًا مثل هذا:

The Lord High Chamberlain has gotten 42
things for me this year.
That is 25 more than he gave me last year.

هذه هي كل الصيغة الموجودة.

المتغير $OUT

هناك متغير خاص، $OUT، متاح لك في كل جزء من أجزاء البرنامج. يبدأ $OUT كسلسلة نصية فارغة، وفي كل مرة يتم فيها تقييم جزء من البرنامج، تتم إضافة نتيجة هذا الجزء إلى نهاية $OUT. عند الانتهاء من ملء القالب، يتم إرجاع القيمة النهائية لـ $OUT.

هذا يعني أنك قد كتبت قالبًا بهذا الشكل:

There are { scalar(@ARGV) } arguments.
{ foreach $arg (@ARGV) { print "  $arg\n" } }
Done.

عندما يكون @ARGV هو ('file1', 'file2')، فإن النتيجة هي:

There are 2 arguments.
  file1
  file2
Done.

يمكنك أيضًا استخدام $OUT لتهيئة أو معالجة الناتج الوسيط. على سبيل المثال، يمكنك تعيين قيم لمتغيرات في نطاقك الخاص، وإنشاء تلك المتغيرات بشكل صريح (لأن القالب قد يكون برنامج Perl كاملًا) ثم طباعتها.

أو يمكنك استخدام $OUT لإنشاء مخرجات متعددة الأجزاء.

الحزمة T

عندما تقوم باستدعاء fill_in، يتم إنشاء حزمة تسمى T (ما لم تحدد حزمة أخرى باستخدام خيار PACKAGE). يتم وضع جميع المتغيرات التي تم تمريرها باستخدام خيار HASH أو LIST في هذه الحزمة. وبالتالي، إذا كان لديك HASH مثل { name => 'Fred' }، يمكنك الوصول إلى المتغير $name في قالبك.

إذا كنت تريد تحديد حزمة أخرى، يمكنك القيام بذلك. على سبيل المثال، إذا كنت تريد استخدام حزمة MyVars، فستكتب:

$template->fill_in(PACKAGE => MyVars, HASH => \%my_vars);

يتم دائمًا تضمين "use strict 'vars';" في بداية كل جزء برنامج. هذا يعني أنه إذا لم يتم تعريف متغير، فسيتم طرح خطأ. إذا كنت لا تريد هذا، يمكنك استخدام always_prepend:

Text::Template->always_prepend('');

على سبيل المثال، يمكن أن تستخدم always_prepend لتعيين حزمة افتراضية:

Text::Template->always_prepend(q{use MyPackage;});

أو لتعيين حزمة بشكل صحيح، يجب أن تقوم بما يلي:

Text::Template->always_prepend(q{package MyPackage; use strict 'vars';});

عند استخدام fill_in_string أو fill_in_file، يتم إنشاء الحزمة T بشكل افتراضي. إذا كنت تريد استخدام حزمة أخرى، يجب عليك تمريرها باستخدام خيار PACKAGE.

خيارات الباني

عند استدعاء Text::Template->new(...)، يمكنك تحديد العديد من الخيارات.

TYPE

يحدد نوع مصدر القالب.

  • FILE: المصدر هو اسم ملف.

  • STRING: المصدر هو سلسلة نصية.

  • ARRAY: المصدر عبارة عن مصفوفة من السلاسل النصية.

  • FILEHANDLE: المصدر عبارة عن مقبض ملف.

إذا لم يتم تحديد TYPE، فسيتم تخمين النوع بناءً على ما إذا كان SOURCE يبدو مثل اسم ملف، أو سلسلة نصية، أو مصفوفة، أو مقبض ملف.

SOURCE

اسم الملف، السلسلة النصية، المصفوفة، أو مقبض الملف الذي يحتوي على القالب.

PREPEND

كود Perl يتم إلحاقه بكل جزء من أجزاء البرنامج قبل تقييمه. مفيد لإعلان المتغيرات التي تريد مشاركتها بين جميع الأجزاء.

DELIMITERS

مصفوفة تحتوي على سلسلتين نصيتين: القوس الافتتاحي والقوس الختامي. الافتراضي هو ['{', '}'].

على سبيل المثال:

$template = Text::Template->new(
    SOURCE    => 'my_template.txt',
    DELIMITERS => ['<%','%>'],
)

ملاحظة: عند استخدام محددات مخصصة، لن يتم إجراء معالجة الهروب بواسطة الشرطة المائلة العكسية.

خيارات fill_in

عند استدعاء $template->fill_in(...)، يمكنك تحديد العديد من الخيارات.

PACKAGE

الحزمة التي سيتم فيها تعريف المتغيرات. الافتراضي هو T.

HASH

مرجع إلى جدول هاش سيتم فك حزمته في الحزمة المحددة. كل مفتاح في الهاش يصبح اسم متغير، ويصبح قيمته هي قيمة المتغير.

LIST

قائمة من أزواج (اسم المتغير، قيمته). سيتم تعريف المتغيرات في الحزمة المحددة.

على سبيل المثال:

$template->fill_in(LIST => [ name => 'Fred', age => 30 ]);

BROKEN

يجب أن يكون مرجعًا إلى إجراء فرعي. سيتم استدعاء هذا الإجراء الفرعي إذا تعذر تقييم جزء من البرنامج. سيتم تمرير جزأين كوسيطين:

  • نص الخطأ الذي تم إرجاعه بواسطة Perl.
  • جزء البرنامج الذي فشل.

يجب أن يرجع الإجراء الفرعي سلسلة نصية، والتي سيتم استخدامها بدلاً من جزء البرنامج الفاشل.

BROKEN_ARG

إذا تم توفير هذا، فسيتم تمريره كوسيط إضافي إلى الإجراء الفرعي المحدد في BROKEN.

SAFE

إذا تم تعيين هذا على مرجع إلى كائن `Safe', فسيتم تنفيذ أجزاء البرنامج داخل هذا السياق الآمن.

OUTPUT

إذا تم تعيين هذا على مقبض ملف، فسيتم كتابة الناتج إليه بدلاً من إرجاعه. ستكون القيمة التي تم إرجاعها هي قيمة منطقية تشير إلى النجاح.

DELIMITERS

مصفوفة تحتوي على سلسلتين نصيتين: القوس الافتتاحي والقوس الختامي. يتم استخدام هذه المحددات لتحليل القالب الحالي فقط.

PREPEND

كود Perl يتم إلحاقه بكل جزء من أجزاء البرنامج قبل تقييمه. يتم تطبيق هذا لمرة واحدة فقط لكل استدعاء fill_in.

دوال

بالإضافة إلى إنشاء كائنات Text::Template، توفر الوحدة أيضًا دالتين:

  • fill_in_string(TEMPLATE, PACKAGE => undef, ...)
  • fill_in_file(FILENAME, PACKAGE => undef, ...)

تعمل هاتان الدالتان تمامًا مثل استدعاء Text::Template->new(...) متبوعًا بـ $template->fill_in(...)، ولكنهما أسهل في الاستخدام عند التعامل مع قوالب بسيطة.

يمكن تمرير جميع خيارات fill_in إلى هاتين الدالتين.

الشرطات المائلة العكسية

تتم معالجة الشرطات المائلة العكسية بطريقة خاصة. كل شرطة مائلة عكسية تسبق حرفًا آخر غير الشرطة المائلة العكسية أو القوس يتم تمريرها إلى Perl. يتم تجاهل الشرطة المائلة العكسية التي تسبق شرطة مائلة عكسية أخرى.

وبالتالي، فإن:

  • \\{ تصبح {
  • \\\\ تصبح \\
  • \n تصبح n (ملاحظة: هذا هو *نص* n، وليس حرف سطر جديد.)

إذا كنت تريد إدخال شرطة مائلة عكسية في القالب، فيجب عليك كتابة \\\\. إذا كنت تريد إدخال قوس، فيجب عليك كتابة \\{ أو \\}.

هذا السلوك يمكن أن يكون محيرًا بعض الشيء، ولكنه ضروري للسماح بمثل هذه الأشياء مثل:

The path is {$path = 'C:\\Program Files'; $path =~ s/\\/\//g; $path}

يتم تحويل المسار أعلاه إلى

C:/Program Files

تذكر أن هذا السلوك خاص فقط عند استخدام المحددات الافتراضية {...}. إذا كنت تستخدم محددات مخصصة، فلا يتم إجراء أي معالجة للشرطة المائلة العكسية.

متغير $OUT

هناك حيلة خاصة يمكنك القيام بها في قالب. هذا هو الدافع: افترض أنك تمرر مصفوفة، @items، إلى القالب، وتريد أن ينشئ القالب قائمة مع عنوان، على النحو التالي:

Here is a list of the things I have got for you since 1907:
  * Ivory
  * Apes
  * Peacocks
  * ...

إحدى الطرق للقيام بذلك هي باستخدام قالب مثل هذا:

Here is a list of the things I have got for you since 1907:
{ my $blist = '';
  foreach $i (@items) {
      $blist .= qq{  * $i\n};
  }
  $blist;
}

هنا نقوم ببناء القائمة في متغير يسمى $blist، والذي نعيده في النهاية. هذا يبدو مربكًا بعض الشيء. هناك اختصار.

داخل القوالب، يوجد متغير خاص يسمى $OUT. ما تضيفه إلى هذا المتغير سيظهر في إخراج القالب. أيضًا، إذا كنت تستخدم $OUT في جزء برنامج، فسيتم تعطيل السلوك العادي، وهو استبدال الجزء بقيمته المرجعة؛ بدلاً من ذلك، يتم استبدال الجزء بقيمة $OUT. هذا يعني أنه يمكنك كتابة القالب السابق على النحو التالي:

Here is a list of the things I have got for you since 1907:
{ foreach $i (@items) {
    $OUT .= "  * $i\n";
  }
}

$OUT يتم إعادة تعيينه إلى سلسلة فارغة عند بدء كل جزء من أجزاء البرنامج. إنه خاص بـ "Text::Template"، لذلك لا يمكنك استخدام متغير يسمى $OUT في قالبك دون استدعاء السلوك الخاص.

ملاحظات عامة

جميع وظائف "Text::Template" ترجع "undef" في حالة حدوث خطأ وتعيين المتغير $Text::Template::ERROR لشرح ما حدث. على سبيل المثال، إذا حاولت إنشاء قالب من ملف غير موجود، فسيحتوي $Text::Template::ERROR على شيء مثل:

Couldn't open file xyz.tmpl: No such file or directory

"new"

$template = Text::Template->new( TYPE => ..., SOURCE => ... );

يقوم هذا بإنشاء وإرجاع كائن قالب جديد. ترجع "new" "undef" وتعيين $Text::Template::ERROR إذا لم يتمكن من إنشاء كائن القالب. "SOURCE" يخبر من أين سيأتي كود القالب. "TYPE" يخبر ما هو نوع كود القالب.

النوع الأكثر شيوعًا لكود القالب هو ملف:

Text::Template->new( TYPE => 'FILE', SOURCE => $filename );

يقرأ هذا كود القالب من الملف المحدد. يتم فتح اسم الملف باستخدام أمر Perl "open"، لذلك يمكن أن يكون أنبوبًا أو أي شيء منطقي مع "open".

"TYPE" يمكن أن يكون أيضًا "STRING"، وفي هذه الحالة يجب أن يكون "SOURCE" سلسلة نصية:

Text::Template->new( TYPE => 'STRING',
                     SOURCE => "This is the actual template!" );

يمكن أن يكون "TYPE" "ARRAY"، وفي هذه الحالة يجب أن يكون كود القالب عبارة عن مرجع لمصفوفة من السلاسل النصية. دمج هذه السلاسل هو القالب:

Text::Template->new( TYPE => 'ARRAY',
                         SOURCE => [ "This is ", "the actual",
                                     " template!",
                                   ]
                   );

يمكن أن يكون "TYPE" "FILEHANDLE"، وفي هذه الحالة يجب أن يكون كود القالب عبارة عن مقبض ملف مفتوح (كما حصلت عليه من حزم "FileHandle" أو "IO::*"، أو مقبض ملف، أو مرجع لمقبض ملف). في هذه الحالة، سيقرأ "Text::Template" النص من الملف حتى نهاية الملف ويكون هذا النص هو القالب:

# Read template code from STDIN:
Text::Template->new ( TYPE => 'FILEHANDLE',
                      SOURCE => \*STDIN  );

إذا حذفت السمة "TYPE"، فسيتم اعتبارها "FILE". "SOURCE" إلزامي. إذا حذفته، سيتوقف البرنامج.

يمكن كتابة مصطلحات "TYPE" و "SOURCE" بأي شكل ممكن:

TYPE     SOURCE
Type     Source
type     source
-TYPE    -SOURCE
-Type    -Source
-type    -source

اختر أسلوبًا يعجبك والتزم به.

"DELIMITERS"
بالإضافة إلى ذلك، يمكنك تضمين خيار "DELIMITERS". إذا كان هذا الخيار موجودًا، فيجب أن تكون قيمته مرجعًا لمصفوفة من سلسلتين. تشير السلسلة الأولى إلى بداية كل جزء من أجزاء البرنامج، وتشير السلسلة الثانية إلى نهاية كل جزء من أجزاء البرنامج. انظر "Alternative Delimiters"، أدناه.
"ENCODING"
بالإضافة إلى ذلك، يمكنك تضمين خيار "ENCODING". إذا كان هذا الخيار موجودًا وكان "SOURCE" عبارة عن "FILE"، فسيتم فك تشفير البيانات من الترميز المعطى باستخدام الوحدة النمطية Encode. يمكنك استخدام أي ترميز تتعرف عليه Encode. على سبيل المثال: 
Text::Template->new(
    TYPE     => 'FILE',
    ENCODING => 'UTF-8',
    SOURCE   => 'xyz.tmpl');
"UNTAINT"
إذا كان برنامجك في وضع التعتيم، فقد تواجه مشاكل إذا تم تخزين القوالب الخاصة بك في ملفات. تعتبر البيانات المقروءة من الملفات "غير موثوقة"، ولا يسمح لك وضع التعتيم بتقييم كود Perl في الملف. (من المخيف أن شخصًا خبيثًا قد يكون قد عدل الملف.)

في بعض البيئات، ومع ذلك، تعتبر الملفات المحلية موثوقة. يمكنك إخبار "Text::Template" بأن ملفًا معينًا موثوق به عن طريق توفير "UNTAINT => 1" في استدعاء "new". هذا يخبر "Text::Template" بتعطيل فحوصات التعتيم على كود القالب الذي جاء من ملف، طالما أن اسم الملف نفسه يعتبر موثوقًا به. كما أنه يعطل فحوصات التعتيم على كود القالب الذي جاء من ملف. عند استخدامه مع "TYPE => 'string'" أو "TYPE" => "array"، فإنه لا يكون له أي تأثير.

"PREPEND"
يتم تمرير هذا الخيار إلى استدعاء "fill_in" ولكنه سيتم تجاوزه في وسيطات "fill_in". انظر "PREPEND" و "strict" في القوالب> أدناه.
"BROKEN"
يتم تمرير هذا الخيار إلى استدعاء "fill_in" ولكنه سيتم تجاوزه في وسيطات "fill_in". انظر "BROKEN" أدناه.

"compile"

$template->compile()

يقوم بتحميل نص القالب من مصدر القالب، وتحليله، وتجميع النص. إذا نجح، فإنه يرجع صحيحًا؛ وإلا، فإنه يرجع خطأ ويعين $Text::Template::ERROR. إذا كان القالب مجمعًا بالفعل، فإنه يرجع صحيحًا ولا يفعل شيئًا.

لا تحتاج عادةً إلى استدعاء هذه الوظيفة، لأن "fill_in" (انظر أدناه) يقوم بتجميع القالب إذا لم يكن مجمعًا بالفعل.

إذا كان هناك وسيط لهذه الوظيفة، فيجب أن يكون مرجعًا لمصفوفة بسلاسل محددة بديلة. انظر "Alternative Delimiters"، أدناه.

"fill_in"

$template->fill_in(OPTIONS);

يملأ قالبًا. يرجع النص الناتج إذا نجح. وإلا، فإنه يرجع "undef" ويعين $Text::Template::ERROR.

OPTIONS عبارة عن جدول، أو قائمة أزواج مفتاح-قيمة. يمكنك كتابة أسماء المفاتيح بأي من الأشكال الستة العادية كما هو مذكور؛ هذا يعني أنه حيثما يقول هذا الدليل "PACKAGE" (على سبيل المثال)، يمكنك استخدام أي من:

PACKAGE Package package -PACKAGE -Package -package

اختر أسلوبًا يعجبك والتزم به. قد تؤدي الإصدارات ذات الأحرف الصغيرة إلى تحذيرات زائفة حول:

Ambiguous use of package => resolved to "package"

لذلك يمكنك تجنبها واستخدام الإصدارات ذات الأحرف الكبيرة.

حاليًا، هناك ثمانية خيارات قانونية: "PACKAGE"، "BROKEN"، "BROKEN_ARG"، "FILENAME"، "SAFE"، "HASH"، "OUTPUT"، و "DELIMITERS".

"PACKAGE"
"PACKAGE" يحدد اسم فئة يجب تقييم أجزاء البرنامج ضمنها. القيمة الافتراضية هي استخدام الفئة التي تم استدعاء "fill_in" منها. على سبيل المثال، ضع في اعتبارك هذا القالب: 
The value of the variable x is {$x}.

إذا استخدمت $template->fill_in(PACKAGE => 'R')"، فسيتم استبدال $x في القالب بقيمة $R::x. إذا حذفت "PACKAGE"، فسيتم استبدال $x بقيمة المتغير $x في الحزمة التي استدعت بالفعل "fill_in".

معلومات حول ما حدث بشكل خاطئ.

يمكن للدالة "BROKEN" أيضًا استخدام "BROKEN_ARG" كمرجع لتخزين رسالة خطأ أو أي معلومات أخرى ترغب في توصيلها مرة أخرى إلى المتصل. على سبيل المثال:

$error = '';
sub my_broken {
   my %args = @_;
   my $err_ref = $args{arg};
   ...
   $$err_ref = "Some error message";
   return undef;
}
$template->fill_in(
    BROKEN     => \&my_broken,
    BROKEN_ARG => \$error
);
if ($error) {
  die "It didn't work: $error";
}

إذا فشل أحد أجزاء البرنامج في القالب، فسوف يستدعي الدالة "BROKEN"، أي "my_broken"، وسيمرر لها "BROKEN_ARG"، وهو مرجع إلى $error. يمكن لـ "my_broken" تخزين رسالة خطأ في $error بهذه الطريقة. بعد ذلك، يمكن للدالة التي استدعت "fill_in" رؤية ما إذا كانت "my_broken" قد تركت رسالة خطأ لتجدها، والمتابعة وفقًا لذلك.

"FILENAME"
إذا أعطيت "fill_in" خيار "FILENAME"، فهذا هو اسم الملف الذي قمت بتحميل مصدر القالب منه. هذا يؤثر فقط على رسالة الخطأ التي يتم تقديمها لأخطاء القالب. إذا قمت بتحميل القالب من "foo.txt" على سبيل المثال، وقمت بتمرير "foo.txt" كمعامل "FILENAME"، فستبدو الأخطاء مثل "... at foo.txt line N" بدلاً من "... at template line N".

لاحظ أن هذا ليس له علاقة بتحميل قالب من الملف المحدد. انظر fill_in_file() لهذا الغرض.

على سبيل المثال:

my $template = Text::Template->new(
    TYPE   => 'string',
    SOURCE => 'The value is {1/0}');
$template->fill_in(FILENAME => 'foo.txt') or die $Text::Template::ERROR;

سيموت بخطأ يحتوي على

Illegal division by zero at at foo.txt line 1
"SAFE"
إذا أعطيت "fill_in" خيار "SAFE"، فيجب أن تكون قيمته كائن حاوية آمن من حزمة "Safe". سيتم إجراء جميع تقييمات أجزاء البرنامج في هذه الحاوية. انظر Safe للحصول على تفاصيل كاملة حول هذه الحاويات وكيفية تقييد العمليات التي يمكن إجراؤها فيها.

إذا استخدمت خيار "PACKAGE" مع "SAFE"، فسيتم وضع الحزمة التي تحددها في الحاوية الآمنة وسيتم إجراء التقييم في تلك الحزمة كالمعتاد.

إذا لم يكن الأمر كذلك، فإن عملية "SAFE" تختلف قليلاً عن الافتراضية. عادةً، إذا لم تحدد حزمة، يحدث تقييم أجزاء البرنامج في الحزمة التي تم استدعاء القالب منها. ولكن في وضع "SAFE"، يحدث التقييم داخل الحاوية الآمنة ولا يمكن أن يؤثر على الحزمة المتصلة. عادةً، إذا استخدمت "HASH" بدون "PACKAGE"، فسيتم استيراد متغيرات الهاش إلى حزمة خاصة، تستخدم لمرة واحدة. ولكن إذا استخدمت "HASH" و "SAFE" معًا بدون "PACKAGE"، فسيتم تحميل متغيرات الهاش فقط في مساحة الاسم الجذر للحاوية "Safe".

"OUTPUT"
إذا كان قالبك سيولد الكثير من النصوص التي ستطبعها مرة أخرى على أي حال، يمكنك توفير الذاكرة عن طريق جعل "Text::Template" تطبع النص أثناء إنشائه بدلاً من تحويله إلى سلسلة نصية كبيرة وإرجاع السلسلة. إذا قدمت خيار "OUTPUT" لـ "fill_in"، فيجب أن تكون القيمة مقبض ملف. سيتم طباعة النص الذي تم إنشاؤه إلى مقبض الملف هذا أثناء بنائه. على سبيل المثال: 
$template->fill_in(OUTPUT => \*STDOUT, ...);

يملأ $template كالمعتاد، ولكن يتم طباعة النتائج فورًا إلى STDOUT. قد يؤدي هذا إلى ظهور الإخراج بشكل أسرع مما كان يمكن أن يحدث بخلاف ذلك.

إذا استخدمت "OUTPUT"، فإن القيمة المرجعة من "fill_in" لا تزال صحيحة عند النجاح وخاطئة عند الفشل، ولكن لا يتم إرجاع النص الكامل إلى المتصل.

"PREPEND"
يمكنك الحصول على بعض أكواد Perl التي يتم إلحاقها تلقائيًا ببداية كل جزء برنامج. انظر "ميزة "PREPEND" واستخدام "strict" في القوالب" أدناه.
"DELIMITERS"
إذا كان هذا الخيار موجودًا، فيجب أن تكون قيمته مرجعًا إلى قائمة من سلسلتين. السلسلة الأولى هي السلسلة التي تشير إلى بداية كل جزء برنامج، والسلسلة الثانية هي السلسلة التي تشير إلى نهاية كل جزء برنامج. انظر "بدائل الفواصل"، أدناه.

إذا قمت بتحديد "DELIMITERS" في استدعاء "fill_in"، فإنها تتجاوز أي فواصل قمت بتعيينها عند إنشاء كائن القالب باستخدام "new".

وظائف ملائمة

"fill_this_in"

الطريقة الأساسية لملء قالب هي إنشاء كائن قالب ثم استدعاء "fill_in" عليه. هذا مفيد إذا كنت ترغب في ملء نفس القالب أكثر من مرة.

في بعض البرامج، يمكن أن يكون هذا مرهقًا. تقبل "fill_this_in" سلسلة نصية، تحتوي على القالب، وقائمة خيارات، والتي يتم تمريرها إلى "fill_in" كما هو مذكور أعلاه. تقوم بإنشاء كائن القالب لك، وتملأه كما هو محدد، وتعيد النتائج. تعيد "undef" وتعين $Text::Template::ERROR إذا لم تتمكن من إنشاء أي نتائج.

مثال:

$Q::name = 'Donald';
$Q::amount = 141.61;
$Q::part = 'hyoid bone';
$text = Text::Template->fill_this_in( <<'EOM', PACKAGE => Q);
Dear {$name},
You owe me \\${sprintf('%.2f', $amount)}.
Pay or I will break your {$part}.
    Love,
    Grand Vizopteryx of Irkutsk.
EOM

لاحظ كيف قمنا بتضمين القالب مباشرة في البرنامج باستخدام "مستند هنا" مع التدوين "<<".

"fill_this_in" هي ميزة مهملة. إنها موجودة فقط للتوافق مع الإصدارات السابقة، وقد تتم إزالتها في إصدار مستقبلي بعيد في "Text::Template". يجب عليك استخدام "fill_in_string" بدلاً من ذلك. يتم وصفها في القسم التالي.

"fill_in_string"

من الغباء أن تكون "fill_this_in" طريقة فئة. كان ينبغي أن تكون مجرد دالة مستوردة، بحيث يمكنك حذف "Text::Template->" في المثال أعلاه. لكنني ارتكبت الخطأ قبل أربع سنوات ومن المستحيل تغييره الآن.

"fill_in_string" هي بالضبط مثل "fill_this_in" باستثناء أنها ليست طريقة ويمكنك حذف "Text::Template->" وتقول ببساطة

print fill_in_string(<<'EOM', ...);
Dear {$name},
  ...
EOM

لاستخدام "fill_in_string"، تحتاج إلى قول

use Text::Template 'fill_in_string';

في بداية برنامجك. يجب عليك على الأرجح استخدام "fill_in_string" بدلاً من "fill_this_in".

"fill_in_file"

إذا قمت باستيراد "fill_in_file"، يمكنك قول

$text = fill_in_file(filename, ...);

يتم تمرير "..." إلى "fill_in" كما هو موضح أعلاه. اسم الملف هو اسم الملف الذي يحتوي على القالب الذي تريد ملؤه. يعيد النص الناتج. أو "undef"، كالمعتاد.

إذا كنت ستقوم بملء نفس الملف أكثر من مرة في نفس البرنامج، فيجب عليك استخدام التسلسل الأطول "new" / "fill_in" بدلاً من ذلك. سيكون أسرع بكثير لأنه يحتاج فقط إلى قراءة وتحليل الملف مرة واحدة.

تضمين الملفات في القوالب

يطلب الناس دائمًا ذلك. "لماذا ليس لديك وظيفة تضمين؟" يسألون. الجواب القصير هو أن هذا هو Perl، و Perl لديها بالفعل وظيفة تضمين. إذا كنت تريدها، يمكنك ببساطة وضع

{qx{cat filename}}

في قالبك. ها أنت ذا.

إذا كنت لا تريد استخدام "cat"، يمكنك كتابة دالة صغيرة من أربعة أسطر تفتح ملفًا وتفرغ محتوياته، واستدعائها من القالب. لقد كتبت واحدة لك. في القالب، يمكنك قول

{Text::Template::_load_text(filename)}

إذا كان هذا كثيرًا، فإليك خدعة. افترض أن حزمة القالب التي ستذكرها في استدعاء "fill_in" هي الحزمة "Q". ثم في البرنامج الرئيسي، اكتب

*Q::include = \&Text::Template::_load_text;

متفرقات

متغيرات "my"

عادة ما يصاب المستخدمون بالدهشة عندما لا يعمل هذا:

my $recipient = 'The King';
my $text = fill_in_file('formletter.tmpl');

النص "The King" غير مدرج في النموذج. لماذا لا؟ لأن $recipient هو متغير "my" والغرض من متغيرات "my" هو أن تكون خاصة ولا يمكن الوصول إليها إلا في النطاق الذي تم الإعلان عنها فيه. القالب ليس ضمن هذا النطاق، لذلك لا يمكن للقالب رؤية $recipient.

إذا لم يكن هذا هو السلوك الذي تريده، فلا تستخدم "my". "my" تعني متغيرًا خاصًا، وفي هذه الحالة لا تريد أن يكون المتغير خاصًا. ضع المتغيرات في متغيرات الحزمة في حزمة أخرى، واستخدم خيار "PACKAGE" الخاص بـ "fill_in":

$Q::recipient = $recipient;
my $text = fill_in_file('formletter.tmpl', PACKAGE => 'Q');

أو قم بتمرير الأسماء والقيم في تجزئة باستخدام خيار "HASH":

my $text = fill_in_file('formletter.tmpl', HASH => { recipient => $recipient });

مسائل أمنية

يتم تقييم جميع المتغيرات في الحزمة التي تحددها باستخدام خيار "PACKAGE" الخاص بـ "fill_in". إذا استخدمت هذا الخيار وإذا لم تقم قوالبك بأي شيء فظيع، فلن تقلق بشأن تنفيذ الأكواد الصغيرة في بقية برنامجك وتدمير شيء ما.

ومع ذلك، لا توجد طريقة حقًا (ما لم تستخدم "Safe") للحماية من قالب يقول:

{ $Important::Secret::Security::Enable = 0;
  # تعطيل الضوابط الأمنية في هذا البرنامج
}

أو

{ $/ = "ho ho ho";   # بدء استخدام <FH>.
  # $/ هو دائما متغير عام
}

أو حتى

{ system("rm -rf /") }

لذلك، لا يجب عليك ملء القوالب إلا إذا كنت تعرف ما تحتويه. إذا كنت قلقًا أو لا يمكنك الوثوق بمن كتب القالب، فاستخدم خيار "SAFE".

كلمة تحذير أخيرة: هناك خطر ضئيل في أجزاء البرنامج من الكتابة فوق المتغيرات المحلية في دالة "fill_in". تحمل هذه المتغيرات أسماء تبدأ بـ "$fi_"، لذا إذا ابتعدت عن هذه الأسماء فستكون آمنًا. (على الرغم من أنه إذا كنت ساحرًا حقيقيًا يمكنك تغييرها عمدًا لتأثيرات مثيرة للاهتمام؛ هذه هي طريقة عمل $OUT.) يمكنني إصلاح ذلك، لكنه سيجعل الحزمة بطيئة، لذا أفضل عدم القيام بذلك. إذا كنت قلقًا، أرسل لي رسالة وسأوضح لك ما يجب عليك فعله.

محددات بديلة

أشار لورنزو فالديتارو إلى أنه إذا كنت تستخدم "Text::Template" لإنشاء مخرجات TeX، فإن اختيار الأقواس كـ محددات لأجزاء التعليمات البرمجية يجعلك تعاني. منذ الإصدار 1.20، يمكنك تغيير اختيار المحددات إلى شيء غير الأقواس.

في هذه الأثناء، يتيح لك خيار "DELIMITERS" الخاص باستدعاء "new()" أو "fill_in()" تحديد مجموعة بديلة من المحددات. على سبيل المثال، إذا كنت تريد أن تكون أجزاء التعليمات البرمجية محددة بواسطة "[@--" و "--@]" بدلاً من "{" و "}"، استخدم:

... DELIMITERS => [ '[@--', '--@]' ], ...

ملاحظة: هذه المحددات هي سلاسل حرفية، وليست تعابير نمطية. (لقد حاولت مع التعابير النمطية، لكنها عقدت التحليل المعجمي كثيرًا.) لاحظ أيضًا أن "DELIMITERS" يعطل المعنى الخاص للشرطة المائلة العكسية، لذلك إذا كنت تريد تضمين المحددات في النص الحرفي لملف القالب الخاص بك، فأنت في وضع سيء — يجب عليك اختيار محددات لا تتعارض مع ما تفعله. يمكن أن تظهر سلاسل المحددات داخل أجزاء التعليمات البرمجية طالما أنها متداخلة بشكل صحيح. هذا يعني أنه إذا كان يجب عليك لسبب ما أن يكون لديك جزء تعليمات برمجية يذكر أحد المحددات، مثل هذا:

[@--
    print "Oh no, a delimiter: --@]\n"
--@]

يمكنك جعله يعمل باستخدام هذا:

[@--
    # محدد وهمي في تعليق: [@--
    print "Oh no, a delimiter: --@]\n"
--@]

قد يكون من الأسلم اختيار محددات تبدأ بحرف سطر جديد.

نظرًا لأن تحليل القوالب يتم تبسيطه بدون هروب الشرطة المائلة العكسية، فإن استخدام محددات بديلة يمكن أن يسرع عملية التحليل بنسبة 20-25٪. هذا يوضح أن اختياري الأصلي لـ "{" و "}" كان سيئًا للغاية.

ميزة "PREPEND" واستخدام "strict" في القوالب

لنفترض أنك تريد استخدام "strict" في قوالبك لاكتشاف المتغيرات غير المعلنة وحالات أخرى. لكن كل جزء من التعليمات البرمجية هو نطاق معجمي مختلف، لذلك عليك تمكين "strict" في بداية كل منها:

{ use strict;
  use vars '$foo';
  $foo = 14;
  ...
}
...
{ # نسيت وضع `use strict` هنا
  my $result = $boo + 12;    # $boo مكتوبة بشكل خاطئ ويجب أن تكون $foo
  # لا يتم إنشاء أي خطأ بخصوص `$boo`
}

لأنك لم تضع "use strict" في بداية الجزء الثاني، فقد كان نشطًا فقط في الأول ولم يتم إنشاء أي فحص "strict" في الجزء الثاني. ثم، كتبت $foo بشكل خاطئ ولم يتم التقاط الخطأ.

يحتوي "Text::Template" الإصدار 1.22 وما بعده على ميزة جديدة لتسهيل ذلك. يمكنك تحديد أن أي نص سيتم إضافته تلقائيًا إلى بداية كل جزء من التعليمات البرمجية.

عند إجراء استدعاء لـ "fill_in"، يمكنك تحديد الخيار:

PREPEND => 'some perl statements here'

تتم إضافة العبارات إلى بداية كل جزء من التعليمات البرمجية لهذا الاستدعاء. لنفترض أن استدعاء "fill_in" تضمن:

PREPEND => 'use strict;'

ويبددو القالب كالتالي:

{ use vars '$foo';
  $foo = 14;
  ...
}
...
{ my $result = $boo + 12;    # $boo مكتوبة بشكل خاطئ ويجب أن تكون $foo
  ...
}

سيفشل الكود في الجزء الثاني، لأن $boo لم يتم الإعلان عنه. تم فرض "use strict" ضمنيًا، حتى لو لم تكتبه صراحةً، لأن خيار "PREPEND" أضاف الكود لك.

هناك ثلاث طرق أخرى للقيام بذلك. عند إنشاء كائن القالب باستخدام "new"، يمكنك أيضًا تحديد خيار "PREPEND"، حيث تتم إضافة العبارات إلى بداية كل استدعاء لـ "fill_in". إذا كان استدعاء "fill_in" يحتوي على خيار "PREPEND" خاص به، فإنه يلغي الخيار المحدد عند إنشاء الكائن. أخيرًا، يمكنك استدعاء طريقة الفئة:

Text::Template->always_prepend('perl statements');

إذا قمت بذلك، فإن أي استدعاء لـ "fill_in" لأي قالب سيضيف العبارات إلى بداية كل جزء من التعليمات البرمجية، باستثناء الحالات التي يتم فيها تجاوزها بخيارات "PREPEND" من "new" أو "fill_in".

بديل لإضافة "use strict;" إلى خيار "PREPEND" هو تمرير STRICT => 1 عند استدعاء "fill_in" جنبًا إلى جنب مع خيار "HASH".

لنفترض أن استدعاء "fill_in" تضمن كلا الخيارين:

HASH   => {$foo => ''} و
STRICT => 1

ويبددو القالب كالتالي:

{
  $foo = 14;
  ...
}
...
{ my $result = $boo + 12;    # $boo مكتوبة بشكل خاطئ ويجب أن تكون $foo
  ...
}

سيفشل الكود في الجزء الثاني، لأن $boo لم يتم الإعلان عنه. تم فرض "use strict" ضمنيًا، حتى لو لم تكتبه صراحةً، لأن خيار "STRICT" أضاف الكود لك. أي متغير مشار إليه في القالب غير موجود في خيار "HASH" سيكون خطأ.

إلحاق في الفئات المشتقة

هذا القسم تقني ويجب عليك تخطيه في القراءات الأولى.

عادة ما تكون هناك ثلاثة أماكن يمكن أن يأتي منها النص السابق. قد يأتي من خيار "PREPEND" لاستدعاء "fill_in"، أو من خيار "PREPEND" لاستدعاء "new" الذي أنشأ كائن القالب، أو من الوسيطة لاستدعاء "always_prepend". يمكن استخدام خيار "PREPEND" لاستدعاء "fill_in" لمنع إضافة النص السابق إلى جزء التعليمات البرمجية. يمكن استخدام خيار "PREPEND" لاستدعاء "new" لمنع إضافة النص السابق إلى جزء التعليمات البرمجية. يمكن استخدام الوسيطة لاستدعاء "always_prepend" لمنع إضافة النص السابق إلى جزء التعليمات البرمجية.
