NAME

libtecla — Curses-based line editing library

DESCRIPTION

The libtecla library provides interactive line editing capabilities similar to those found in the GNU Readline library and the vi editor. It allows users to enter commands and other text with sophisticated editing features.

The library supports two primary editing modes: Emacs mode and Vi mode. The user can switch between these modes, and the behavior of keys can be customized.

Key bindings can be configured using a configuration file or directly in the code.

KEY SEQUENCE NOTATION

The following notation is used to describe key sequences:

^char
Control key combination. For example, ^H is Control-H.
M-char
Meta key combination. This is often equivalent to Alt+char or Escape followed by char.
\r
Carriage return (Enter key).
\n
Newline.

THE TECLA CONFIGURATION FILE

Tecla reads its configuration from the file ~/.teclarc. This file allows users to customize key bindings, editing modes, and other library behavior.

The format of the configuration file is typically a series of lines, where each line specifies a key binding or a setting.

FILENAME AND TILDE COMPLETION

Tecla provides automatic completion for filenames and tilde (user) expansion. When the user presses the completion key (e.g., Tab), Tecla attempts to complete the word at the current cursor position.

If multiple matches are found, Tecla may list the possible completions. The list-glob function is often associated with displaying these possibilities.

FILENAME EXPANSION

The expand-filename function expands filenames according to shell globbing rules. This is typically triggered by a specific key sequence, like ^X*.

RECALLING PREVIOUSLY TYPED LINES

Tecla maintains a history of previously entered lines. Users can navigate this history using cursor keys or dedicated history navigation commands.

In Emacs mode, ^P (up-history) and ^N (down-history) are commonly used.

In Vi mode, commands like j (down-history) and k (up-history) might be used, often after entering command mode.

HISTORY FILES

Tecla can optionally save command history to a file, typically named ~/.tecla_history. This allows the history to persist across different shell sessions.

The `read-init-files` function, often bound to `^X^R`, can be used to load history from files.

INTERNATIONAL CHARACTER SETS

Tecla generally supports international character sets, provided the underlying terminal and environment are configured correctly. Key bindings involving meta characters might interact with multi-byte character input.

THE AVAILABLE KEY BINDING FUNCTIONS

Tecla provides a rich set of functions that can be bound to key sequences. These functions cover editing, history navigation, completion, and more.

Key bindings are defined separately for Emacs mode and Vi mode.

KEY SEQUENCE NOTATION

The cursor keys are refered to by name, as follows. This is necessary because different types of terminals generate different key sequences when their cursor keys are pressed.


right -> cursor-right
left -> cursor-left
up -> up-history
down -> down-history

The cursor keys normally generate a keysequence that start with an escape character, so beware that using the arrow keys will put you into command mode (if you aren't already in command mode).

ENTERING REPEAT COUNTS

Many of the key binding functions described previously, take an optional count, typed in before the target keysequence. This is interpreted as a repeat count by most bindings. A notable exception is the goto-column binding, which interprets the count as a column number.

By default you can specify this count argument by pressing the meta key while typing in the numeric count. This relies on the digit-argument action being bound to Meta-0, Meta-1 etc. Once any one of these bindings has been activated, you can optionally take your finger off the meta key to type in the rest of the number, since every numeric digit thereafter is treated as part of the number, unless it is preceded by the literal-next binding. As soon as a non-digit, or literal digit key is pressed the repeat count is terminated and either causes the just typed character to be added to the line that many times, or causes the next key-binding function to be given that argument.

For example, in emacs mode, typing:

  M-12a

causes the letter 'a' to be added to the line 12 times, whereas

  M-4M-c

Capitalizes the next 4 words.

In vi command mode the Meta modifier is automatically added to all characters typed in, so to enter a count in vi command-mode, just involves typing in the number, just as it does in the vi editor itself. So for example, in vi command mode, typing:

  4w2x

moves the cursor four words to the right, then deletes two characters.

You can also bind digit-argument to other key sequences. If these end in a numeric digit, that digit gets appended to the current repeat count. If it doesn't end in a numeric digit, a new repeat count is started with a value of zero, and can be completed by typing in the number, after letting go of the key which triggered the digit-argument action.
