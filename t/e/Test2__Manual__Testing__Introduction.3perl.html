الاسم

Test2::Manual::Testing::Introduction - مقدمة في الاختبار باستخدام Test2.

الوصف

هذا الدليل هو مقدمة للمبتدئين في مجال الاختبار. سيأخذك هذا الدليل خلال كتابة ملف اختبار، وتقديم التأكيدات، وتشغيل الاختبار الخاص بك.

النماذج الأولية

ملف الاختبار

عادةً ما توضع ملفات الاختبار داخل الدليل "t/"، وتنتهي بامتداد الملف ".t".

"t/example.t":

use Test2::V0;
# Assertions will go here
done_testing;

هذا هو كل النماذج الأولية التي تحتاجها.

use Test2::V0;
يقوم هذا بتحميل مجموعة من أدوات الاختبار التي سيتم وصفها لاحقًا في البرنامج التعليمي. سيقوم هذا أيضًا بتفعيل "strict" و "warnings" لك.
done_testing;
يجب أن يكون هذا دائمًا في نهاية ملفات الاختبار الخاصة بك. هذا يخبر Test2 بأنك انتهيت من تقديم التأكيدات. هذا مهم حيث سيفترض "test2" أن الاختبار لم يكتمل بنجاح بدون هذا، أو أي شكل آخر من أشكال "خطة" الاختبار.

إعداد التوزيع

يجب عليك دائمًا إدراج الحزم والأدوات مباشرة. لا يجب عليك ببساطة إدراج Test2::Suite واعتبار الأمر منتهياً، فقد يتم نقل الحزم والأدوات خارج Test2::Suite إلى موزعات خاصة بها في أي وقت.

Dist::Zilla

[Prereqs / TestRequires]
Test2::V0 = 0.000060

ExtUtils::MakeMaker

my %WriteMakefileArgs = (
  ...,
  "TEST_REQUIRES" => {
    "Test2::V0" => "0.000060"
  },
  ...
);

Module::Install

test_requires 'Test2::V0' => '0.000060';

Module::Build

my $build = Module::Build->new(
    ...,
    test_requires => {
        "Test2::V0" => "0.000060",
    },
    ...
);

تقديم التأكيدات

الأداة الأبسط لتقديم التأكيدات هي ok(). تتيح لك ok() التأكيد على أن الشرط صحيح.

ok($CONDITION, "Description of the condition");

إليك ملف "t/example.t" كامل:

use Test2::V0;
ok(1, "1 is true, so this will pass");
done_testing;

تشغيل الاختبار

ملفات الاختبار هي ببساطة نصوص برمجية. مثل أي نص برمجي آخر، يمكنك تشغيل الاختبار مباشرة باستخدام perl. خيار آخر هو استخدام "جهاز" اختبار يقوم بتشغيل الاختبار نيابة عنك، ويوفر معلومات إضافية ويتحقق من قيمة الخروج للنص البرمجي الخاص بك.

التشغيل المباشر

$ perl -Ilib t/example.t

والذي يجب أن ينتج عنه مخرجات مشابهة لهذه:

# Seeded srand with seed '20161028' from local date.
ok 1 - 1 is true, so this will pass
1..1

إذا فشل الاختبار ("ok(0, ...)") سيبدو الأمر كما يلي:

# Seeded srand with seed '20161028' from local date.
not ok 1 - 0 is false, so this will fail
1..1

سيقوم Test2 أيضًا بتعيين قيمة الخروج للنص البرمجي، سيكون تشغيل ناجح له قيمة خروج 0، وسيكون تشغيل فاشل له قيمة خروج غير صفرية.

استخدام YATH

الأداة سطر الأوامر "yath" مقدمة من Test2::Harness والتي قد تحتاج إلى تثبيتها بنفسك من cpan. "yath" هو الجهاز المكتوب خصيصًا لـ Test2.

$ yath -Ilib t/example.t

سينتج عن هذا مخرجات مشابهة لهذه:

( PASSED )  job  1    t/example.t
================================================================================
Run ID: 1508027909
All tests were successful!

يمكنك أيضًا طلب مخرجات مفصلة باستخدام علامة "-v":

$ yath -Ilib -v t/example.t

والتي تنتج:

( LAUNCH )  job  1    example.t
(  NOTE  )  job  1    Seeded srand with seed '20171014' from local date.
[  PASS  ]  job  1  + 1 is true, so this will pass
[  PLAN  ]  job  1    Expected asserions: 1
( PASSED )  job  1    example.t
================================================================================
Run ID: 1508028002
All tests were successful!

استخدام PROVE

الأداة سطر الأوامر "prove" مقدمة من وحدة Test::Harness التي تأتي مع معظم إصدارات perl. Test::Harness له عمر مزدوج، مما يعني أنه يمكنك أيضًا تثبيت أحدث إصدار من cpan.

$ prove -Ilib t/example.t

سينتج عن هذا مخرجات مشابهة لهذه:

example.t .. ok
All tests successful.
Files=1, Tests=1,  0 wallclock secs ( 0.01 usr  0.00 sys +  0.05 cusr  0.00 csys =  0.06 CPU)
Result: PASS

يمكنك أيضًا طلب مخرجات مفصلة باستخدام علامة "-v":

$ prove -Ilib -v t/example.t

تبدو المخرجات المفصلة كما يلي:

example.t ..
# Seeded srand with seed '20161028' from local date.
ok 1 - 1 is true, so this will pass
1..1
ok
All tests successful.
Files=1, Tests=1,  0 wallclock secs ( 0.02 usr  0.00 sys +  0.06 cusr  0.00 csys =  0.08 CPU)
Result: PASS

"خطة" الاختبار

تحتاج جميع الاختبارات إلى "خطة". وظيفة الخطة هي التأكد من أنك قمت بتشغيل جميع الاختبارات التي توقعتها. تمنع الخطة نتيجة ناجحة من اختبار يخرج قبل تشغيل جميع الاختبارات.

هناك طريقتان رئيسيتان لتعيين الخطة:

done_testing()
الطريقة الأكثر شيوعًا والموصى بها لتعيين خطة هي إضافة "done_testing" في نهاية ملف الاختبار الخاص بك. سيقوم هذا تلقائيًا بحساب الخطة لك في نهاية الاختبار. إذا خرج الاختبار مبكرًا، فلن يتم تشغيل "done_testing" ولن يتم العثور على خطة، مما يجبر على الفشل.
plan($COUNT)
تسمح لك الدالة plan() بتحديد عدد دقيق من التأكيدات التي تريد تشغيلها. إذا قمت بتشغيل عدد قليل جدًا من التأكيدات أو عدد كبير جدًا، فلن تتطابق الخطة وسيتم احتسابها كفشل. المشكلة الرئيسية مع هذه الطريقة في التخطيط هي أنك بحاجة إلى جمع عدد التأكيدات، وتعديل العد عند تحديث ملف الاختبار.

plan() يجب استخدامه قبل جميع التأكيدات، أو بعد جميع التأكيدات، لا يمكن القيام بذلك في منتصف تقديم التأكيدات.

أدوات تأكيد إضافية

توفر حزمة Test2::V0 أكثر بكثير من ok()، و plan()، و done_testing(). أهم الأدوات التي يجب ملاحظتها هي:

is($a, $b, $description)
is() يسمح لك بمقارنة هيكلين والتأكد من أنهما متطابقان. يمكنك استخدامه لمقارنات السلاسل النصية البسيطة، أو حتى مقارنات هياكل البيانات العميقة. 
is("foo", "foo", "Both strings are identical");
is(["foo", 1], ["foo", 1], "Both arrays contain the same elements");
like($a, $b, $description)
like() يشبه is() باستثناء أنه يتحقق فقط من العناصر المدرجة على اليمين، ويتجاهل أي قيم إضافية موجودة على اليسار. 
like([1, 2, 3, 4], [1, 2, 3], "Passes, the extra element on
