قم بتثبيت testinfra باستخدام pip:

def test_passwd_file(host):
    passwd = host.file("/etc/passwd")
    assert passwd.contains("root")
    assert passwd.user == "root"
    assert passwd.group == "root"
    assert passwd.mode == 0o644
def test_nginx_is_installed(host):
    nginx = host.package("nginx")
    assert nginx.is_installed
    assert nginx.version.startswith("1.2")
def test_nginx_running_and_enabled(host):
    nginx = host.service("nginx")
    assert nginx.is_running
    assert nginx.is_enabled

وشغّله:

واجهات الاتصال

تأتي Testinfra مع العديد من واجهات الاتصال لتنفيذ الأوامر عن بُعد.

عند التثبيت، يجب عليك تحديد الواجهات التي تحتاجها كـ extras للتأكد من تلبية تبعيات Python (لاحظ أنه قد لا تزال هناك حاجة لأدوات مختلفة مُغلفة بالنظام). على سبيل المثال:

$ pip install pytest-testinfra[ansible,salt]

لجميع الواجهات، يمكن تشغيل الأوامر كمستخدم خارق باستخدام الخيار --sudo أو كمستخدم معين باستخدام الخيار --sudo-user.

تحديد المضيف العام

يُستخدم المعلمة --hosts في Testinfra لتحديد المضيفين المستهدفين للاختبارات.

يمكنك تحديد مضيفين متعددين عن طريق فصل كل هدف بفاصلة، مما يسمح لك بتشغيل الاختبارات باستخدام واجهات مختلفة عبر بيئات أو أجهزة مختلفة.

تُعد حقول المستخدم وكلمة المرور والمنفذ اختيارية، مما يوفر مرونة اعتمادًا على متطلبات المصادقة والاتصال الخاصة بك.

يرجى أيضًا قراءة التفاصيل الخاصة بالواجهات الفردية، حيث يتم التعامل مع مواصفات المضيف بشكل مختلف قليلاً من واجهة إلى أخرى.

الصيغة:

--hosts=<backend>://<user>:<password>@<host>:<port>

المكونات:

  • <backend>: نوع الواجهة المستخدمة (مثل: ssh، docker، paramiko، local)
  • <user>: اسم المستخدم للمصادقة (اختياري)
  • <password>: كلمة المرور للمصادقة (اختياري)
  • <host>: اسم المضيف الهدف أو عنوان IP
  • <port>: رقم المنفذ الهدف (اختياري)

تحتاج الأحرف الخاصة (مثل ":") في حقلي المستخدم وكلمة المرور إلى ترميز النسبة المئوية وفقًا لـ RFC 3986. يمكن القيام بذلك باستخدام urllib.parse.quote() في Python.

على سبيل المثال:

import urllib.parse
user = urllib.parse.quote('user:name')
password = urllib.parse.quote('p@ssw:rd')
host = 'hostname'
port = 22
host_spec = f"ssh://{user}:{password}@{host}:{port}"
print(host_spec)

سيضمن هذا ترميز أي أحرف خاصة بشكل صحيح، مما يجعل سلسلة الاتصال صالحة.

أمثلة:

واجهة SSH مع مواصفات كاملة:

testinfra --hosts=ssh://user:password@hostname:22

واجهة Docker:

testinfra --hosts=docker://container_id

واجهات مختلطة:

testinfra --hosts=ssh://user:password@hostname:22,docker://container_id,local://

هذه هي الواجهة الافتراضية عندما لا يتم توفير أي مضيفين (إما عبر --hosts أو في الوحدات). يتم تشغيل الأوامر محليًا في عملية فرعية تحت المستخدم الحالي:

يمكنك توفير ملف ssh-config بديل:

$ pytest --hosts='docker://[user@]container_id_or_name'

ssh

هذه واجهة SSH نقية تستخدم الأمر ssh. مثال:

$ pytest --hosts='ssh://server'
$ pytest --ssh-config=/path/to/ssh_config --hosts='ssh://server'
$ pytest --ssh-identity-file=/path/to/key --hosts='ssh://server'
$ pytest --hosts='ssh://server?timeout=60&controlpersist=120'
$ pytest --hosts='ssh://server' --ssh-extra-args='-o StrictHostKeyChecking=no'

بشكل افتراضي، يتم تعيين المهلة إلى 10 ثوانٍ و ControlPersist إلى 60 ثانية. يمكنك تعطيل الاتصال المستمر عن طريق تمرير controlpersist=0 إلى الخيارات.

salt

$ pytest --hosts='salt://*'
$ pytest --hosts='salt://minion1,salt://minion2'
$ pytest --hosts='salt://web*'
$ pytest --hosts='salt://G@os:Debian'

سيستخدم Testinfra قناة اتصال salt لتشغيل الأوامر.

ansible

قد تُستخدم قوائم جرد Ansible لوصف المضيفين التي يجب أن تستخدمها Testinfra وكيفية الاتصال بهم، باستخدام واجهة Ansible الخاصة بـ Testinfra.

لاستخدام واجهة Ansible، قم ببادئة الخيار --hosts بـ ansible://، على سبيل المثال:

$ pytest --hosts='ansible://all' # يختبر جميع مضيفي قائمة الجرد
$ pytest --hosts='ansible://host1,ansible://host2'
$ pytest --hosts='ansible://web*'

يمكن تحديد قائمة جرد باستخدام الخيار --ansible-inventory، وإلا يتم استخدام القائمة الافتراضية (/etc/ansible/hosts).

سيتم استخدام قيمة ansible_connection في قائمة الجرد الخاصة بك لتحديد الواجهة التي يجب استخدامها لكل مضيف: local، ssh، paramiko، و docker هي قيم مدعومة. الاتصالات الأخرى (أو إذا كنت تستخدم الخيار --force-ansible) ستؤدي إلى تشغيل Testinfra لجميع الأوامر عبر Ansible نفسها، وهو أبطأ بكثير من الواجهات الأخرى:

$ pytest --force-ansible --hosts='ansible://all'
$ pytest --hosts='ansible://host?force_ansible=True'

بشكل افتراضي، ستحاول واجهة اتصال Ansible أولاً استخدام ansible_ssh_private_key_file و ansible_private_key_file للمصادقة، ثم تعود إلى ansible_user مع متغيرات ansible_ssh_pass (كلاهما مطلوب)، قبل العودة أخيرًا إلى إعداد SSH الخاص بجهازك.

قد يتم تجاوز هذا السلوك عن طريق تحديد إما الخيار --ssh-identity-file أو الخيار --ssh-config.

أخيرًا، يتم دعم متغيرات البيئة التالية وسيتم تمريرها إلى متغير Ansible المقابل لها (راجع وثائق Ansible):

  • ANSIBLE_REMOTE_USER
  • ANSIBLE_SSH_EXTRA_ARGS
  • ANSIBLE_SSH_COMMON_ARGS
  • ANSIBLE_REMOTE_PORT
  • ANSIBLE_BECOME_USER
  • ANSIBLE_BECOME

Docker

Allows you to inspect your docker containers.

get_containers()

Return a list of containers

By default return list of all containers, including non-running containers.

Multiple filters for a given key is handled by giving a list of string as value.

>>> host.docker.get_containers()
[<docker nginx>, <docker redis>, <docker app>]
# Get all running containers
>>> host.docker.get_containers(status="running")
[<docker app>]
# Get containers named "nginx"
>>> host.docker.get_containers(name="nginx")
[<docker nginx>]
# Get containers named "nginx" or "redis"
>>> host.docker.get_containers(name=["nginx", "redis"])
[<docker nginx>, <docker redis>]

testinfra(1) — Arch manual pages

NAME

testinfra — Run tests against your infrastructure.

ABOUT

Testinfra provides a set of Pytest fixtures and functions to help you test your infrastructure code.

LICENSE

Testinfra is released under the terms of the Apache License, Version 2.0.

QUICK START

Install testinfra:

$ pip install pytest-testinfra

Then create a test.py file:

import testinfra

def test_file_exists():
    host = testinfra.get_host("paramiko://user@host")
    assert host.file("/etc/hosts").exists

def test_package_installed():
    host = testinfra.get_host("paramiko://user@host")
    assert host.package("nginx").is_installed

def test_nginx_running():
    host = testinfra.get_host("paramiko://user@host")
    assert host.service("nginx").is_running

Then run pytest:

When your Vagrant machine is up and running, you can easily run your testinfra test suite on it:

If your Jenkins slave can run Vagrant, your build scripts can be like:

pip install pytest-testinfra paramiko
vagrant up
vagrant ssh-config > .vagrant/ssh-config
pytest --hosts=default --ssh-config=.vagrant/ssh-config --junit-xml junit.xml tests.py

Then configure Jenkins to get tests results from the junit.xml file.

Integration with KitchenCI

KitchenCI (aka Test Kitchen) can use testinfra via its shell verifier. Add the following to your .kitchen.yml, this requires installing paramiko additionally (on your host machine, not in the VM handled by kitchen)

verifier:
  name: shell
  command: pytest --hosts="paramiko://${KITCHEN_USERNAME}@${KITCHEN_HOSTNAME}:${KITCHEN_PORT}?ssh_identity_file=${KITCHEN_SSH_KEY}" --junit-xml "junit-${KITCHEN_INSTANCE}.xml" "test/integration/${KITCHEN_SUITE}"

Test Docker images

Docker is a handy way to test your infrastructure code. This recipe shows how to build and run Docker containers with Testinfra by overloading the host fixture.

import pytest
import subprocess
import testinfra
# scope='session' uses the same container for all the tests;
# scope='function' uses a new container per test function.
@pytest.fixture(scope='session')
def host(request):
    # build local ./Dockerfile
    subprocess.check_call(['docker', 'build', '-t', 'myimage', '.'])
    # run a container
    docker_id = subprocess.check_output(
        ['docker', 'run', '-d', 'myimage']).decode().strip()
    # return a testinfra connection to the container
    yield testinfra.get_host("docker://" + docker_id)
    # at the end of the test suite, destroy the container
    subprocess.check_call(['docker', 'rm', '-f', docker_id])
def test_myimage(host):
    # 'host' now binds to the container
    assert host.check_output('myapp -v') == 'Myapp 1.0'
