Test2::Manual::Testing::Migrating(3perl) دليل مبرمجي Perl Test2::Manual::Testing::Migrating(3perl)

الاسم

Test2::Manual::Testing::Migrating - كيفية ترحيل الاختبارات الحالية من Test::More إلى Test2.

الوصف

يغطي هذا الدليل تحويل اختبار موجود. يفترض هذا الدليل أن لديك اختبارًا مكتوبًا باستخدام Test::More.

الاختبار القديم

سيقوم هذا الدليل بتحويل الاختبار التجريبي هذا قسمًا تلو الآخر:

"t/example.t":

#####################
# Boilerplate
use strict;
use warnings;
use Test::More tests => 14;
use_ok 'Scalar::Util';
require_ok 'Exporter';
#####################
# Simple assertions (no changes)
ok(1, "pass");
is("apple", "apple", "Simple string compare");
like("foo bar baz", qr/bar/, "Regex match");
#####################
# Todo
{
    local $TODO = "These are todo";
    ok(0, "oops");
}
#####################
# Deep comparisons
is_deeply([1, 2, 3], [1, 2, 3], "Deep comparison");
#####################
# Comparing references
my $ref = [1];
is($ref, $ref, "Check that we have the same ref both times");
#####################
# Things that are gone
ok(eq_array([1], [1]), "array comparison");
ok(eq_hash({a => 1}, {a => 1}), "hash comparison");
ok(eq_set([1, 3, 2], [1, 2, 3]), "set comparison");
note explain([1, 2, 3]);
{
    package THING;
    sub new { bless({}, shift) }
}
my $thing = new_ok('THING');
#####################
# Tools that changed
isa_ok($thing, 'THING', '$thing');
can_ok(__PACKAGE__, qw/ok is/);

البرمجة الأساسية

قبل:

use strict;
use warnings;
use Test::More tests => 14;
use_ok 'Scalar::Util';
require_ok 'Exporter';

بعد:

use Test2::V0;
plan(11);
use Scalar::Util;
require Exporter;
استبدل Test::More بـ Test2::V0
Test2::V0 هي الحزمة الموصى بها. في عملية ترحيل كاملة، سترغب في استبدال Test::More بحزمة Test2::V0.

ملاحظة: يجب عليك دائمًا التحقق مرة أخرى من أحدث إصدار من Test2 لمعرفة ما إذا كانت هناك حزمة جديدة موصى بها. عند كتابة اختبار جديد، يجب عليك دائمًا استخدام أحدث وحدة Test::V#. الأرقام الأعلى هي أحدث إصدار.

ملاحظة: srand
عند تشغيل srand (افتراضي) يمكن أن يسبب مشاكل مع أشياء مثل File::Temp التي ستنتهي بمحاولة نفس أسماء الملفات "العشوائية" لكل عملية اختبار تبدأ في يوم معين (أو مشاركة نفس البذرة).

إذا كانت هذه مشكلة بالنسبة لك، فيرجى تعطيل srand عند تحميل Test2::V0:

use Test2::V0 -no_srand => 1;
توقف عن استخدام use_ok()
تمت إزالة use_ok(). عبارة "use MODULE" ستلقي استثناءً عند الفشل على أي حال، مما يمنع الاختبار من النجاح.

إذا كنت تريد/تحتاج حقًا إلى التأكيد على تحميل الملف، يمكنك استخدام وحدة ok:

use ok 'Scalar::Util';

الاختلاف الرئيسي هنا هو وجود مسافة بدلاً من شرطة سفلية.

توقف عن استخدام require_ok()
تمت إزالة "require_ok" تمامًا مثل "use_ok". لا يوجد ما يعادل وحدة ok هنا. فقط استخدم "require".
إزالة strict/warnings (اختياري)
حزمة Test2::V0 تقوم بتشغيل strict و warnings لك.
تغيير مكان تعيين الخطة
لا تسمح Test2 لك بتعيين الخطة عند الاستيراد. في الكود القديم، كنت تمرر "tests => 11" كوسيطة استيراد. في Test2، تحتاج إما إلى استخدام الدالة plan() لتعيين الخطة، أو استخدام done_testing() في نهاية الاختبار.

إذا كان اختبارك يستخدم بالفعل done_testing()، فيمكنك الاحتفاظ به ولا يلزم إجراء تغييرات على الخطة.

ملاحظة: نقوم أيضًا بتغيير الخطة من 14 إلى 11، وذلك لأننا أسقطنا "use_ok" و "require_ok"، وسنسقط شيئًا آخر لاحقًا. هذا هو سبب التوصية بـ done_testing() بدلاً من خطة محددة.

تأكيدات بسيطة

لن تحتاج غالبية التأكيدات إلى أي تغييرات:

#####################
# Simple assertions (no changes)
ok(1, "pass");
is("apple", "apple", "Simple string compare");
like("foo bar baz", qr/bar/, "Regex match");

قيد التنفيذ

{
    local $TODO = "These are todo";
    ok(0, "oops");
}

تم حذف متغير الحزمة $TODO. لديك الآن وظيفة todo().

هناك طريقتان لاستخدام هذا:

todo $reason => sub { ... }
todo "These are todo" => sub {
    ok(0, "oops");
};

هذه هي الطريقة الأنظف لعمل todo. سيجعل هذا جميع التأكيدات داخل كتلة الكود تأكيدات قيد التنفيذ.

{ my $TODO = todo $reason; ... }
{
    my $TODO = todo "These are todo";
    ok(0, "oops");
}

هذا نظام يحاكي الطريقة القديمة. بدلاً من تعديل متغير $TODO عام، تقوم بإنشاء كائن todo باستخدام الدالة todo() وتعيينه إلى متغير عددي. بمجرد خروج كائن todo من النطاق، ينتهي TODO.

مقارنات عميقة

is_deeply([1, 2, 3], [1, 2, 3], "Deep comparison");

المقارنات العميقة سهلة، فقط استبدل is_deeply() بـ is().

is([1, 2, 3], [1, 2, 3], "Deep comparison");

مقارنة المراجع

my $ref = [1];
is($ref, $ref, "Check that we have the same ref both times");

تقوم الدالة is() التي توفرها Test::More بتحويل كلا الوسيطين إلى سلاسل نصية، مما يجعل هذا مقارنة لعناوين المراجع. دالة is() الخاصة بـ Test2 هي مقارنة عميقة، لذلك سيظل هذا ينجح، ولكنه يفشل في اختبار ما نريده حقًا (وهو أن كلا المرجعين هما نفس المرجع بالضبط، وليس فقط هياكل متطابقة.)

لدينا الآن الدالة ref_is() التي تفعل ما نريده حقًا، إنها تضمن أن كلا المرجعين هما نفس المرجع. هذه الدالة تؤدي المهمة بشكل أفضل من الأصلية، والتي يمكن أن تنحرف بسبب التحميل الزائد للسلاسل النصية.

my $ref = [1];
ref_is($ref, $ref, "Check that we have the same ref both times");

الأدوات التي تم حذفها

ok(eq_array([1], [1]), "array comparison");
ok(eq_hash({a => 1}, {a => 1}), "hash comparison");
ok(eq_set([1, 3, 2], [1, 2, 3]), "set comparison");
note explain([1, 2, 3]);
{
    package THING;
    sub new { bless({}, shift) }
}
my $thing = new_ok('THING');

تم اعتبار "eq_array" و "eq_hash" و "eq_set" مهملة منذ فترة طويلة، Test2 لا يوفرها على الإطلاق. بدلاً من ذلك، يمكنك ببساطة استخدام is():

is([1], [1], "array comparison");
is({a => 1}, {a => 1}, "hash comparison");

"eq_set" أكثر تعقيدًا قليلاً، راجع Test2::Tools::Compare للحصول على شرح:

is([1, 3, 2], bag { item 1; item 2; item 3; end }, "set comparison");

تاريخ explain() مضطرب. كانت هناك حجج حول كيف يجب أن تعمل.

Test2::Manual::Testing::Migrating(3perl)

NAME

Test2::Manual::Testing::Migrating - Migrating from Test::More to Test2

DESCRIPTION

This document will go over the changes made between Test::More and Test2, with a focus on how to migrate your existing test suite from one to the other.

LEGACY TEST

The Test::More API is not stable. It is not stable because it is badly designed. The Test2 API IS stable. This document will show you how to migrate your tests to Test2.

This document assumes you are familiar with Test::More.

BOILERPLATE

The old boilerplate:

use Test::More tests => 10;
# or
use Test::More;

The new boilerplate:

use Test2::V0;
plan(10);
# or
use Test2::V0;

Note that use Test2::V0 will import everything you need, and will also set up your plan to auto-detect the number of tests. This means you do not need to specify the number of tests, unless you want to.

SIMPLE ASSERTIONS

The simple assertions remain the same:

ok(1, "this is ok");
is($a, $b, "this is same");
like($a, $b, "this is like");
unlike($a, $b, "this is unlike");
# and so on...

TODO

The TODO block has been changed.

# Old way
BEGIN { plan(tests => 3) }
sub test {
    ok(0, 'this will fail');
    pass('this will pass');
}
todo_skip("this is a todo test" => 2, sub { test() });
# or
todo_skip("this is a todo test", 2);
ok(0, 'this will fail');
pass('this will pass');
# New way
todo "this is a todo test" => sub {
    ok(0, 'this will fail');
    pass('this will pass');
};

Note that todo now takes a block. This block will be run, and any tests within it will be marked as todo. The number of tests is now auto-detected.

DEEP COMPARISONS

The way deep comparisons are done has not changed:

is([1, 2, 3], [1, 2, 3], "array comparison");
is({a => 1}, {a => 1}, "hash comparison");

However, the bag function has been removed.

# Old way
is([1, 3, 2], bag { item 1; item 2; item 3; end }, "set comparison");
# New way
is([1, 3, 2], [1, 2, 3], "set comparison");

If you need to compare arrays/hashes without regard to order, then you should sort them first.

COMPARING REFERENCES

ref_is() has been added to Test2.

my $ref = [1];
ref_is($ref, $ref, "Check that we have the same ref both times");

ref_is checks that the two arguments are the exact same reference, not just that they are equal.

TOOLS THAT ARE GONE

Some tools have been removed from Test2 that were present in Test::More.

The explain() function is gone. Instead, you can use Data::Dumper directly. Test2 captures STDERR, so you can just use note with the output of Dumper.

Test2 decided to simply not include explain() to avoid the arguments. You can instead directly use Data::Dumper:

use Data::Dumper;
note Dumper([1, 2, 3]);

new_ok() is gone. The implementation was complicated, and did not add much value:

{
    package THING;
    sub new { bless({}, shift) }
}
my $thing = THING->new;
ok($thing, "made a new thing");

The complete section after the conversion is:

is([1], [1], "array comparison");
is({a => 1}, {a => 1}, "hash comparison");
is([1, 3, 2], bag { item 1; item 2; item 3; end }, "set comparison");
use Data::Dumper;
note Dumper([1, 2, 3]);
{
    package THING;
    sub new { bless({}, shift) }
}
my $thing = THING->new;
ok($thing, "made a new thing");

TOOLS THAT HAVE CHANGED

isa_ok($thing, 'THING', '$thing');
can_ok(__PACKAGE__, qw/ok is/);

In Test::More these functions are very confusing, and most people use them wrong!

isa_ok() from Test::More takes a thing, a class/reftype to check, and then uses the third argument as an alternative display name for the first argument (NOT a test name!).

can_ok() from Test::More is not consistent with "isa_ok" as all arguments after the first are subroutine names.

Test2 fixes this by making both functions consistent and obvious:

isa_ok($thing, ['THING'], 'got a THING');
can_ok(__PACKAGE__, [qw/ok is/], "have expected subs");

You will note that both functions take a thing, an arrayref as the second argument, then a test name as the third argument.

FINAL VERSION

# Boilerplate
use Test2::V0;

#####################

#####################

    ok(0, "oops");

#####################

#####################

my $ref = [1];

#####################
