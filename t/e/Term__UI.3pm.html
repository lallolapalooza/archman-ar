Term__UI(3pm)

الحزمة: perl-term-ui

التراخيص: PerlArtistic, GPL

راحة اللف حول "Term::UI::History->history_as_string".

راجع صفحة الدليل "Term::UI::History" للتفاصيل.

المتغيرات العامة

يمكن تعديل سلوك Term::UI عن طريق تغيير المتغيرات العامة التالية:

$Term::UI::VERBOSE

يتحكم هذا فيما إذا كان Term::UI سيصدر تحذيرات وتفسيرات حول سبب فشل بعض الأشياء. إذا تم تعيينه على 0، فلن يصدر Term::UI أي تحذيرات. القيمة الافتراضية هي 1؛

$Term::UI::AUTOREPLY

سيؤدي هذا إلى الإجابة على كل سؤال افتراضيًا، وإعلامك إذا لم يتم توفير قيمة افتراضية. هذا مفيد بشكل خاص إذا كان برنامجك يعمل في وضع غير تفاعلي. القيمة الافتراضية هي 0؛

$Term::UI::INVALID

يخزن هذا السلسلة النصية التي سيتم طباعتها عندما يقوم المستخدم بإجراء اختيار غير صالح. يمكنك تجاوز هذه السلسلة من برنامجك إذا، على سبيل المثال، كنت ترغب في إجراء ترجمة. القيمة الافتراضية هي "Invalid selection, please try again: "

$Term::UI::History::HISTORY_FH

هذا هو مقبض الملف الذي يتم إرسال جميع التعليمات إليه من هذه الوحدة. يرجى الرجوع إلى صفحة الدليل "Term::UI::History" للتفاصيل.

هذا افتراضيًا هو *STDOUT.

أمثلة

مثال أساسي لـ get_reply

### ask a user (with an open question) for their favourite colour
$reply = $term->get_reply( prompt => 'Your favourite colour? );

والذي سيبدو كالتالي:

Your favourite colour?

وسيحتوي $reply على النص الذي كتبه المستخدم.

get_reply مع خيارات

### now provide a list of choices, so the user has to pick one
$reply = $term->get_reply(
            prompt  => 'Your favourite colour?',
            choices => [qw|red green blue|] );

والذي سيبدو كالتالي:

  1> red
  2> green
  3> blue
Your favourite colour?

$reply سيحتوي على أحد الخيارات المقدمة. "Term::UI" سيعيد طرح السؤال إذا حاول المستخدم إدخال قيمة غير موجودة في قائمة الخيارات. السلسلة النصية المعروضة مخزنة في المتغير $Term::UI::INVALID (راجع قسم "GLOBAL VARIABLES" للتفاصيل.

get_reply مع خيارات وقيمة افتراضية

### provide a sensible default option -- everyone loves blue!
$reply = $term->get_reply(
            prompt  => 'Your favourite colour?',
            choices => [qw|red green blue|],
            default => 'blue' );

والذي سيبدو كالتالي:

  1> red
  2> green
  3> blue
Your favourite colour? [3]:

لاحظ الاستجابة الافتراضية بعد الرسالة. يمكن للمستخدم الآن ببساطة الضغط على "enter" (أو تعيين $Term::UI::AUTOREPLY -- راجع قسم "GLOBAL VARIABLES") وسيتم إرجاع الاستجابة المناسبة 'blue'.

get_reply باستخدام print_me و multi

### allow the user to pick more than one colour and add an
### introduction text
@reply = $term->get_reply(
            print_me    => 'Tell us what colours you like',
            prompt      => 'Your favourite colours?',
            choices     => [qw|red green blue|],
            multi       => 1 );

والذي سيبدو كالتالي:

Tell us what colours you like
  1> red
  2> green
  3> blue
Your favourite colours?

استجابة مثل "3 2 1" ستملأ @reply بـ "blue green red"

get_reply و allow

### pose an open question, but do a custom verification on
### the answer, which will only exit the question loop, if
### the answer matches the allow handler.
$reply = $term->get_reply(
            prompt  => "What is the magic number?",
            allow   => 42 );

لا يهم الآن ما إذا كان المستخدم يدخل 42، سيعاد طرح السؤال بشكل متكرر. يمكنك استخدام معالجات أكثر تعقيدًا لـ "allow" (يمكن استخدام حتى الإجراءات الفرعية). يتم تنفيذ "allow" باستخدام وظيفة "allow" من "Params::Check". راجع صفحة الدليل الخاصة بها للتفاصيل.

مثال مفصل لـ ask_yn

### ask a user if he likes cookies. Default to a sensible 'yes'
### and inform him first what cookies are.
$bool = $term->ask_yn( prompt   => 'Do you like cookies?',
                       default  => 'y',
                       print_me => 'Cookies are LOVELY!!!' );

سيقوم بالطباعة:

Cookies are LOVELY!!!
Do you like cookies? [Y/n]:

إذا ضغط المستخدم لاحقًا ببساطة على "enter"، موافقًا على القيمة الافتراضية، فسيتم تعيين $bool إلى "true". (الضغط على 'y' ببساطة يعيد أيضًا "true". الضغط على 'n' يعيد "false")

يمكننا بعد ذلك استرداد هذا التبادل عن طريق طباعة سجل الأسئلة والأجوبة هكذا:

print $term->history_as_string;

والذي سيطبع:

Cookies are LOVELY!!!
Do you like cookies? [Y/n]:  y

هناك خطر من أننا نفعل هذا بطريقة غير تفاعلية، لأن هناك وحدة تحكم مفقودة، أشار المستخدم إلى أنه يريد فقط القيم الافتراضية، إلخ.

في هذه الحالة، بمجرد تعيين $Term::UI::AUTOREPLY إلى true، سيتم الإرجاع من كل سؤال بالرد الافتراضي للسؤال. يجب أن تلاحظ أنه إذا كان "AUTOREPLY" صحيحًا ولم يتم تعيين قيمة افتراضية، فسيقوم "Term::UI" بالإبلاغ عن ذلك وإرجاع "undef".
