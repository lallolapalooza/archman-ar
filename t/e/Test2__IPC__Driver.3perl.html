الاسم

Test2::IPC::Driver - الفئة الأساسية لبرامج تشغيل Test2 IPC.

الملخص

package Test2::IPC::Driver::MyDriver;
use base 'Test2::IPC::Driver';
...

الأساليب

$self->abort($msg)
إذا واجهت أداة IPC خطأً فادحًا، فيجب عليها استخدام هذا. سيؤدي ذلك إلى طباعة الرسالة إلى STDERR مع بادئة 'IPC Fatal Error: '، ثم سيتم إنهاء البرنامج فورًا برمز الخروج 255. قد تحدث أخطاء IPC في خيوط أو عمليات أخرى غير العملية الرئيسية، يوفر هذا الأسلوب أفضل فرصة للحزمة لاكتشاف الخطأ.
$self->abort_trace($msg)
هذا هو نفس "$ipc->abort($msg)" باستثناء أنه يستخدم "Carp::longmess" لإضافة تتبع المكدس إلى الرسالة.

تحميل برامج التشغيل

لدى Test2::IPC::Driver أسلوب import(). جميع برامج التشغيل ترث أسلوب الاستيراد هذا. يقوم أسلوب الاستيراد هذا بتسجيل برنامج التشغيل.

في معظم الحالات، ما عليك سوى تحميل برنامج تشغيل IPC المطلوب لجعله يعمل. يجب عليك تحميل برنامج التشغيل هذا في أقرب وقت ممكن. سيتم إصدار تحذير إذا قمت بتحميله متأخرًا جدًا ليكون فعالاً.

use Test2::IPC::Driver::MyDriver;
...

كتابة برامج التشغيل

package Test2::IPC::Driver::MyDriver;
use strict;
use warnings;
use base 'Test2::IPC::Driver';
sub is_viable {
    return 0 if $^O eq 'win32'; # لن يعمل على ويندوز.
    return 1;
}
sub add_hub {
    my $self = shift;
    my ($hid) = @_;
    ... # اجعل من الممكن الاتصال بالمركز
}
sub drop_hub {
    my $self = shift;
    my ($hid) = @_;
    ... # لا ينبغي لأحد محاولة الاتصال بالمركز بعد الآن.
}
sub send {
    my $self = shift;
    my ($hid, $e, $global) = @_;
    ... # إرسال الحدث إلى المركز المناسب.
    # قد يؤدي هذا إلى إخطار العمليات / الخيوط الأخرى بأن هناك حدثًا معلقًا.
    Test2::API::test2_ipc_set_pending($uniq_val);
}
sub cull {
    my $self = shift;
    my ($hid) = @_;
    my @events = ...; # هنا تحصل على الأحداث الخاصة بالمركز
    return @events;
}
sub waiting {
    my $self = shift;
    ... # إخطار جميع العمليات والخيوط المستمعة بأن العملية الرئيسية
    ... # تنتظرها لإنهاء العمل.
}
1;

الأساليب التي يجب على الفئات الفرعية تنفيذها

$ipc->is_viable
يجب أن يعيد هذا قيمة صحيحة إذا كان برنامج التشغيل يعمل في البيئة الحالية. يجب أن يعيد هذا قيمة خاطئة إذا لم يكن كذلك. هذا أسلوب CLASS.
$ipc->add_hub($hid)
يستخدم هذا لتنبيه برنامج التشغيل بأن مركزًا جديدًا يتوقع أحداثًا. يجب على برنامج التشغيل تتبع معرفات العمليات والخيوط، يجب إسقاط المركز فقط بواسطة العملية + الخيط الذي بدأه. 
sub add_hub {
    my $self = shift;
    my ($hid) = @_;
    ... # اجعل من الممكن الاتصال بالمركز
}
$ipc->drop_hub($hid)
يستخدم هذا لتنبيه برنامج التشغيل بأن مركزًا لم يعد يقبل الأحداث. يجب على برنامج التشغيل تتبع معرفات العمليات والخيوط، يجب إسقاط المركز فقط بواسطة العملية + الخيط الذي بدأه (هذه مسؤولية برنامج التشغيل لفرضها). 
sub drop_hub {
    my $self = shift;
    my ($hid) = @_;
    ... # لا ينبغي لأحد محاولة الاتصال بالمركز بعد الآن.
}
$ipc->send($hid, $event);
$ipc->send($hid, $event, $global);
يستخدم لإرسال الأحداث من العملية/الخيط الحالي إلى المركز المحدد في عمليته/خيطه. 
sub send {
    my $self = shift;
    my ($hid, $e) = @_;
    ... # إرسال الحدث إلى المركز المناسب.
    # قد يؤدي هذا إلى إخطار العمليات / الخيوط الأخرى بأن هناك حدثًا معلقًا.
    Test2::API::test2_ipc_set_pending($uniq_val);
}

إذا كانت $global صحيحة، فيجب على برنامج التشغيل إرسال الحدث إلى جميع المراكز في جميع العمليات والخيوط.

@events = $ipc->cull($hid)
يستخدم لجمع الأحداث التي تم إرسالها إلى المركز المحدد. 
sub cull {
    my $self = shift;
    my ($hid) = @_;
    my @events = ...; # هنا تحصل على الأحداث الخاصة بالمركز
    return @events;
}
$ipc->waiting()
يتم استدعاء هذا في العملية الأصلية عندما تكون مكتملة وتنتظر لإكمال جميع العمليات والخيوط الفرعية. 
sub waiting {
    my $self = shift;
    ... # إخطار جميع العمليات والخيوط المستمعة بأن العملية الرئيسية
    ... # تنتظرها لإنهاء العمل.
}

الأساليب التي قد تنفذها أو تتجاوزها الفئات الفرعية

$ipc->driver_abort($msg)
هذه خطاف (hook) يتم استدعاؤه بواسطة "Test2::IPC::Driver->abort()". هذه فرصتك للتنظيف عند حدوث إلغاء. لا يمكنك منع الإلغاء، ولكن يمكنك قبوله بأمان.
