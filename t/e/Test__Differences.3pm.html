NAME

Test::Differences - A module for testing differences

SYNOPSIS

    use Test::More tests => 1;
    use Test::Differences;

    my $got = "foo\nbar\nbaz\n";
    my $expected = "foo\nbaz\nbub\n";

    my $sub = sub {
        eq_or_diff($got, $expected);
    };
    $sub->();

    # or, for automatic diffing of all tests in the file:
    all_eq_or_diff();

    # or, for diffing only specific tests:
    sub my_ok {
        my ($got, $expected, $diag) = @_;
        $diag = "test $diag" unless defined $diag;
        return unless ok($got eq $expected, $diag);
        diff($got, $expected);
    };
    my_ok($got, $expected, 1);

EXPORT

Exports 3 functions by default: eq_or_diff, diff, and all_eq_or_diff.

Use use Test::Differences (); to prevent this.

DESCRIPTION

This module compares two strings and reports the difference if they are not identical. It uses the standard Test::Builder API, so it should interoperate nicely with Test::More, Test::Simple, etc.

The function eq_or_diff returns true if the strings are identical, false otherwise. If they are not identical, it prints a diagnostic message showing the differences.

The function diff is a lower-level function that simply prints the differences between two strings without checking for equality. It's useful for custom test harnesses.

The function all_eq_or_diff is a convenience function that turns on automatic diffing for all tests in the file. It uses Test::Builder's register_always_diag feature.

OPTIONS

The module accepts the following options:

$Test::Differences::diff_method
Specifies the diffing algorithm to use. Defaults to 'difflib'. Other options include 'diff' (requires external diff utility) and 'inline' (simple inline diff).
$Test::Differences::NoDeparse
If true, disables deparsing of code references. Defaults to false.
$Test::Differences::ShowCode
If true, displays code references in a more readable format. Defaults to false.

DIFF STYLES

The module supports different diff styles. The default style is a context diff. You can change the style by setting $Test::Differences::diff_style.

Available styles:

context
Standard context diff.
unified
Unified diff.
sidebyside
Side-by-side diff.

UNICODE

The module handles unicode strings correctly, provided you are using a perl version that supports unicode.

Unknown::Values

Test::Differences uses Unknown::Values to represent values that cannot be compared directly. This is an experimental feature and may change in future versions. If Unknown::Values is not available or fails, Test::Differences will likely die when it encounters such values.

LIMITATIONS

"Test" or "Test::More"

This module hooks into Test.pm or Test::Builder-based test libraries. If neither is found in %INC, it will issue a warning and disable test numbering.

Exporting

All functions are exported by default. To avoid this, use use Test::Differences ();.

This module does not override core test functions like ok(), is(), or is_deeply(). If you want automatic upgrading, you need to implement it yourself, for example:

    use Test::Differences qw(is_deeply);
    sub my_is_deeply {
        my ($got, $expected, $diag) = @_;
        return unless ok($got eq $expected, $diag);
        diff($got, $expected);
    };

Booleans

In Perl versions before 5.38, boolean values (true represented as 1, false as the empty string) were not properly distinguished from numeric or string values. Test::Differences, which relies on Data::Dumper, will reflect this behavior. In Perl 5.38 and later, booleans are true distinct values, and comparisons involving them may yield different results.

Unicode

Comparisons involving unicode characters may produce unexpected results in Perl versions prior to 5.6.0, as these versions have limited or buggy unicode support.

"Data::Dumper" and older Perls.

Prior to Perl 5.8, Data::Dumper did not guarantee consistent ordering of hash keys. While $Data::Dumper::Sortkeys is set to 1, this may still lead to spurious differences in tests involving hashes. This issue is generally resolved in newer versions of Data::Dumper.

Data::Dumper also has limitations in representing circular references. Test::Differences relies on Data::Dumper's representation, so complex structures with circular references might not be compared accurately.

    not ok 5
    #     Failed test (t/ctrl/05-home.t at line 51)
    # +----+------------------------+----+------------------------+
    # | Elt|Got                     | Elt|Expected                |
    # +----+------------------------+----+------------------------+
    # |   0|{                       |   0|{                       |
    # |   1|  'password' => '',     |   1|  'password' => '',     |
    # *   2|  'method' => 'login',  *    |                        |
    # |   3|  'ctrl' => 'home',     |   2|  'ctrl' => 'home',     |
    # |    |                        *   3|  'method' => 'login',  *
    # |   4|  'email' => 'test'     |   4|  'email' => 'test'     |
    # |   5|}                       |   5|}                       |
    # +----+------------------------+----+------------------------+

Code-refs

Test::Differences uses $Data::Dumper::Deparse to represent code references as text for comparison. This deparsing is done using B::Deparse, and the resulting text may not always match your original source code exactly, but it should be consistent for comparison purposes.

To disable this behavior, set $Test::Differences::NoDeparse to true.
