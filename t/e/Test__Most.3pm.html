Test__Most(3pm)

الحزمة: perl-test-most

التراخيص: GPL, PerlArtistic

Test::Most(3) وثائق الحزم المساهمة في Perl Test::Most(3)

الاسم

Test::Most - الدوال والميزات الأكثر شيوعًا للاختبارات.

الإصدار

الإصدار 0.38

ملخص

بدلاً من هذا:

use strict;
use warnings;
use Test::Exception 0.88;
use Test::Differences 0.500;
use Test::Deep 0.106;
use Test::Warn 0.11;
use Test::More tests => 42;

اكتب هذا:

use Test::Most tests => 42;

الوصف

Test::Most موجود لتقليل الكود المتكرر وجعل حياة الاختبارات أسهل. نقدم "متجرًا واحدًا" لوظائف وحدات الاختبار الأكثر شيوعًا. في الواقع، نحن غالبًا ما نحتاج إلى أحدث الإصدارات حتى تحصل على إصلاحات الأخطاء عبر Test::Most ولا تضطر إلى تحديث هذه الوحدات بشكل منفصل.

توفر لك هذه الوحدة الوظائف الأكثر شيوعًا للاختبار، مع تفعيل strict و warnings تلقائيًا، وتمنحك المزيد من التحكم في مجموعة الاختبارات الخاصة بك.

use Test::Most tests => 4, 'die';
ok 1, 'Normal calls to ok() should succeed';
is 2, 2, '... as should all passing tests';
eq_or_diff [3], [4], '... but failing tests should die';
ok 4, '... will never get to here';

كما ترى، سيفشل اختبار "eq_or_diff". نظرًا لأن "die" موجود في قائمة الاستيراد، فإن برنامج الاختبار سيتوقف عند هذه النقطة.

إذا كنت لا تريد تفعيل strict و warnings، فيجب عليك تعطيلهما صراحةً. لذلك، يجب أن تكون صريحًا بشأن ما تريد ولا تقلق بشأن نسيانه عن طريق الخطأ.

use Test::Most tests => 4;
no strict;
no warnings;

تصدير

سيتم تصدير جميع الدوال من الوحدات التالية تلقائيًا إلى مساحة الاسم الخاصة بك:

  • Test::More
  • Test::Exception
  • Test::Differences
  • Test::Deep
  • Test::Warn

يجب الإشارة إلى الدوال التي يتم تصديرها اختياريًا من أي من هذه الوحدات باسمها الكامل:

Test::Deep::render_stack( $var, $stack );

الدوال

يتم أيضًا تصدير دوال أخرى تلقائيًا:

"die_on_fail"

die_on_fail;
is_deeply $foo, bar, '... we throw an exception if this fails';

هذه الدالة، إذا تم استدعاؤها، ستتسبب في أن يرمي برنامج الاختبار استثناءً من Test::Most::Exception، مما يوقف الاختبار.

"bail_on_fail"

bail_on_fail;
is_deeply $foo, bar, '... we bail out if this fails';

هذه الدالة، إذا تم استدعاؤها، ستتسبب في أن تقوم مجموعة الاختبارات بإطلاق BAIL_OUT() إذا فشل أي اختبار بعدها.

"restore_fail"

die_on_fail;
is_deeply $foo, bar, '... we throw an exception if this fails';
restore_fail;
cmp_bag(\@got, \@bag, '... we will not throw an exception if this fails';

هذه الدالة ستعيد سلوك الفشل الأصلي، لذلك لن ترمي الاختبارات اللاحقة استثناءً أو BAIL_OUT().

"set_failure_handler"

إذا كنت تفضل سلوكًا آخر غير 'die_on_fail' أو 'bail_on_fail'، يمكنك تعيين معالج الفشل الخاص بك:

set_failure_handler( sub {
    my $builder = shift;
    if ( $builder && $builder->{Test_Results}[-1] =~ /critical/ ) {
       send_admin_email("critical failure in tests");
    }
} );

تستقبل كائن "Test::Builder" كوسيطها الوحيد.

هام: تأكد من أنه إذا كان الاختبار الفاشل هو آخر اختبار يتم تنفيذه، فقد يكون $builder غير معرف. هذا نتيجة غير متوقعة لكيفية تصميم "Test::Builder".

"explain"

على غرار "note"، سيتم عرض الإخراج للمستخدم فقط إذا استخدم الوسيط "-v" مع "prove" أو قرأ TAP مباشرة.

على عكس "note"، يتم توسيع أي مرجع في قائمة الوسائط تلقائيًا باستخدام "Data::Dumper". لذلك، بدلاً من هذا:

my $self = Some::Object->new($id);
use Data::Dumper;
explain 'I was just created', Dumper($self);

يمكنك الآن فقط فعل:

my $self = Some::Object->new($id);
explain 'I was just created:  ', $self;

سيكون الإخراج مشابهًا لـ:

I was just created: bless( {
  'id' => 2,
  'stack' => []
}, 'Some::Object' )

لاحظ أن الإخراج "dumpered" لديه المتغيرات "Data::Dumper" "$Indent" و "$Sortkeys" و "$Terse" معينة جميعها للقيمة "1". هذا يسمح بإخراج تشخيصي أنظف، وفي الوقت الحالي، لا يمكن تجاوزه.

لاحظ أن "explain" في Test::More يعمل بشكل مختلف. هذا "explain" يعادل "note explain" في Test::More.

"show"

تجريبي. على غرار "explain"، ولكنه يحاول أيضًا عرض أسماء المتغيرات الرمزية:

my $var   = 3;
my @array = qw/ foo bar /;
show $var, \@array;
__END__
$var = 3;
@array = [
    'foo',
    'bar'
];

سيظهر "$VAR1"، "$VAR2" ... "$VAR_N" لكل متغير لا يمكنه تحديد اسم المتغير:

my @array = qw/ foo bar /;
show @array;
__END__
$VAR1 = 'foo';
$VAR2 = 'bar';

لاحظ أن هذا يعتمد على إصدار "Data::Dumper::Names" 0.03 أو أعلى. إذا لم يكن موجودًا، فسوف يلاحظ ويستدعي explain بدلاً من ذلك. كما أنه سيعرض فقط أسماء المتغيرات الرمزية. المتغيرات العامة مثل "%ENV" أو "%@" لا يمكن الوصول إليها عبر PadWalker وبالتالي لا يمكن عرضها. سيكون من الرائع إيجاد حل لهذا.

"always_explain" و "always_show"

هذه متطابقة مع "explain" و "show"، ولكن مثل دالة "diag" في Test::More، هذه دائمًا ما تصدر إخراجًا، بغض النظر عما إذا كنت في وضع الإسهاب.

"all_done"

مهمل. استخدم "done_testing()" الجديد (تمت إضافته في Test::More منذ 0.87_01). بدلاً من ذلك. نترك هذا في المكان لفترة طويلة من التوقف. بعد فترة، قد نبدأ حتى في التحذير.

إذا تم تحديد الخطة على أنها "defer_plan"، يمكنك استدعاء "all_done" في نهاية الاختبار برقم اختبار اختياري. هذا يسمح لك بتعيين الخطة دون معرفتها قبل تشغيل الاختبارات.

إذا قمت باستدعائها بدون رقم اختبار، فستظل الاختبارات تفشل إذا لم تصل إلى نهاية الاختبار. هذا مفيد إذا كنت لا تريد تحديد خطة ولكن الاختبارات تغلق بشكل غير متوقع. على سبيل المثال، التالي سيكون ناجحًا مع "no_plan" ولكنه سيفشل مع "all_done".

use Test::More 'defer_plan';
ok 1;
exit;
ok 2;
all_done;

انظر "خطة مؤجلة" لمزيد من المعلومات.

تصدير عند الطلب

هذه متطابقة مع "explain" و "show"، ولكن مثل دالة "diag" في Test::More، هذه دائمًا ما تصدر إخراجًا، بغض النظر عما إذا كنت في وضع الإسهاب.

MISCELLANEOUS

Sometimes you don't know the number of tests you will run when you use "Test::More". The plan() function allows you to delay specifying the plan, but you must still call it before the tests are run. This is an error:

use Test::More;
my $tests = 0;
foreach my $test (
    my $count = run($test); # assumes tests are being run
    $tests += $count;
}
plan($tests);

The way around this is typically to use 'no_plan' and when the tests are done, "Test::Builder" merely sets the plan to the number of tests run. We'd like for the programmer to specify this number instead of letting "Test::Builder" do it. However, "Test::Builder" internals are a bit difficult to work with, so we're delaying this feature.

Cleaner skip()

if ( $some_condition ) {
    skip $message, $num_tests;
}
else {
    # run those tests
}

That would be cleaner and I might add it if enough people want it.

CAVEATS

Because of how Perl handles arguments, and because diagnostics are not really part of the Test Anything Protocol, what actually happens internally is that we note that a test has failed and we throw an exception or bail out as soon as the next test is called (but before it runs). This means that its arguments are automatically evaluated before we can take action:

use Test::Most qw<no_plan die>;
ok $foo, 'Die if this fails';
ok factorial(123456),
  '... but wait a loooong time before you throw an exception';
