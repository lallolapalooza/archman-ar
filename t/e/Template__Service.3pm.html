Template__Service(3pm)

الحزمة: perl-template-toolkit

التراخيص: PerlArtistic

Template::Service(3) توثيق مستخدم مساهم في Perl Template::Service(3)

الاسم

Template::Service - خدمة معالجة قوالب للأغراض العامة

الملخص

use Template::Service;
my $service = Template::Service->new({
    PRE_PROCESS  => [ 'config', 'header' ],
    POST_PROCESS => 'footer',
    ERROR        => {
        user     => 'user/index.html',
        dbi      => 'error/database',
        default  => 'error/default',
    },
});
my $output = $service->process($template_name, \%replace)
    || die $service->error(), "\n";

الوصف

الوحدة "Template::Service" تنفذ فئة كائن لتوفير خدمة معالجة قوالب متسقة.

يمكن تحديد قوالب الرأس (PRE_PROCESS) والتذييل (POST_PROCESS) القياسية والتي يتم إلحاقها وإضافتها إلى جميع القوالب التي تعالجها الخدمة (ولكن ليس إلى أي قوالب أخرى أو كتل يتم تضمينها أو معالجتها من الداخل). يمكن تحديد تجزئة خطأ (ERROR) تعيد توجيه الخدمة إلى ملف قالب بديل في حالة إلقاء استثناءات لم يتم التقاطها. هذا يسمح بمعالجة الأخطاء تلقائيًا بواسطة الخدمة وإنشاء استجابة صالحة مضمونة بغض النظر عن أي مشاكل معالجة تم مواجهتها.

يتم إنشاء كائن "Template::Service" افتراضي بواسطة وحدة Template. يمكن تمرير أي خيارات "Template::Service" إلى طريقة الباني new() في Template وسيتم تمريرها إلى مُنشئ Template::Service.

use Template;
my $template = Template->new({
    PRE_PROCESS  => 'header',
    POST_PROCESS => 'footer',
});

بالمثل، سيقوم مُنشئ "Template::Service" بتمرير جميع معلمات التكوين إلى الكائنات الافتراضية الأخرى (مثل Template::Context) التي قد يحتاج إلى إنشائها.

يمكن تهيئة كائن "Template::Service" (أو فئة فرعية) بشكل صريح وتمريره إلى طريقة الباني new() في Template كعنصر SERVICE.

use Template;
use Template::Service;
my $service = Template::Service->new({
    PRE_PROCESS  => 'header',
    POST_PROCESS => 'footer',
});
my $template = Template->new({
    SERVICE => $service,
});

يمكن جعل الوحدة "Template::Service" فئة فرعية لإنشاء معالجات خدمة مخصصة.

use Template;
use MyOrg::Template::Service;
my $service = MyOrg::Template::Service->new({
    PRE_PROCESS  => 'header',
    POST_PROCESS => 'footer',
    COOL_OPTION  => 'enabled in spades',
});
my $template = Template->new({
    SERVICE => $service,
});

تستخدم وحدة Template طريقة المصنع service() في Template::Config لإنشاء كائن خدمة افتراضي عند الحاجة. يمكن تعيين متغير الحزمة $Template::Config::SERVICE لتحديد وحدة خدمة بديلة. سيتم تحميل هذه الوحدة تلقائيًا وسيتم استدعاء طريقة الباني new() الخاصة بها بواسطة طريقة المصنع service() عند الحاجة إلى كائن خدمة افتراضي. وبالتالي يمكن كتابة المثال السابق على النحو التالي:

use Template;
$Template::Config::SERVICE = 'MyOrg::Template::Service';
my $template = Template->new({
    PRE_PROCESS  => 'header',
    POST_PROCESS => 'footer',
    COOL_OPTION  => 'enabled in spades',
});

الأساليب

new(\%config)

يتم استدعاء طريقة الباني new() لتهيئة كائن "Template::Service". يمكن تحديد معلمات التكوين كـ HASH مرجعي أو كقائمة من أزواج "name => value".

my $service1 = Template::Service->new({
    PRE_PROCESS  => 'header',
    POST_PROCESS => 'footer',
});
my $service2 = Template::Service->new( ERROR => 'error.html' );

الطريقة new() تُرجع كائن "Template::Service" أو "undef" عند حدوث خطأ. في الحالة الأخيرة، يمكن استرداد رسالة خطأ ذات صلة بواسطة طريقة الفئة error() أو مباشرة من متغير الحزمة $Template::Service::ERROR.

my $service = Template::Service->new(\%config)
    || die Template::Service->error();
my $service = Template::Service->new(\%config)
    || die $Template::Service::ERROR;

process($input, \%replace)

يتم استدعاء الطريقة process() لمعالجة قالب محدد كالمعلمة الأولى، $input. يمكن أن يكون هذا اسم ملف، مقبض ملف (مثل "GLOB" أو "IO::Handle") أو مرجع لنص يحتوي على نص القالب. يمكن تمرير مرجع تجزئة إضافي يحتوي على تعريفات متغيرات القالب.

تعالج الطريقة القالب، مضيفة أي قوالب PRE_PROCESS أو POST_PROCESS محددة، وتُرجع نص الإخراج. سيتم معالجة أي استثناء لم يتم التقاطه يتم إلقاؤه بواسطة القالب بواسطة معالج خطأ مناسب إذا تم تحديده. الأخطاء التي تحدث في قوالب PRE_PROCESS أو POST_PROCESS، أو تلك التي تحدث في قالب الإدخال الرئيسي ولا يتم التعامل معها، تتسبب في أن تُرجع الطريقة "undef" للإشارة إلى الفشل. يمكن استرداد رسالة الخطأ المناسبة عبر الطريقة error().

$service->process('myfile.html', { title => 'My Test File' })
    || die $service->error();

context()

تُرجع مرجعًا للكائن السياق الداخلي، والذي يكون افتراضيًا، مثيلًا لفئة Template::Context.

خيارات التكوين

يلخص السرد التالي خيارات التكوين التي يمكن توفيرها لمنشئ "Template::Service" new(). يرجى الرجوع إلى Template::Manual::Config للحصول على مزيد من التفاصيل والأمثلة لكل خيار تكوين قيد الاستخدام.

PRE_PROCESS، POST_PROCESS

يمكن تعيين خيارات PRE_PROCESS و POST_PROCESS لتتضمن اسم (أسماء) ملفات القوالب التي يجب معالجتها فورًا قبل و/أو بعد كل قالب. لا تتم إضافتها إلى القوالب التي تتم معالجتها في مستند عبر توجيهات مثل "INCLUDE" "PROCESS"، "WRAPPER"، إلخ.

my $service = Template::Service->new({
    PRE_PROCESS  => 'header',
    POST_PROCESS => 'footer',
};

يمكن تحديد قوالب متعددة كمرجع لقائمة. تتم معالجة كل منها بالترتيب المحدد.

my $service = Template::Service->new({
    PRE_PROCESS  => [ 'config', 'header' ],
    POST_PROCESS => 'footer',
};

PROCESS

يمكن تعيين خيار PROCESS لتضمين اسم (أسماء) ملفات القوالب التي يجب معالجتها بدلاً من القالب الرئيسي الذي تم تمريره إلى الطريقة "Template::Service" process(). يمكن استخدام هذا لتطبيق أغلفة متسقة حول جميع القوالب، على غرار استخدام قوالب PRE_PROCESS و POST_PROCESS.

my $service = Template::Service->new({
    PROCESS  => 'content',
};
# تعالج 'content' بدلاً من 'foo.html'
$service->process('foo.html');

مرجع إلى القالب الأصلي متاح في المتغير "template". يمكن فحص عناصر البيانات الوصفية ومعالجة القالب عن طريق تحديده كمرجع متغير (أي مسبوق بـ '"$"') إلى توجيه "INCLUDE"، "PROCESS" أو "WRAPPER".

مثال قالب "PROCESS":

<html>
  <head>
    <title>[% template.title %]</title>
  </head>
  <body>
  [% PROCESS $template %]
  </body>
</html>
