- package: testssl.sh version: "3.2" section: "OPTIONS" content: | -U, --update Enables/disables automatic updates of testssl.sh. "y" enables updates, "n" disables them. "a" asks for confirmation. If disabled, testssl.sh will not check for updates. If enabled, testssl.sh will check for updates and offer to download and install them. The environment variable UPDATE can be used instead. --disable-check Disables a specific check. The check name is the name of the test which you can find in the output of testssl.sh or in the `--help` output. This option can be used multiple times. The environment variable DISABLE_CHECK can be used instead. -E, --enable Enables a specific check. The check name is the name of the test which you can find in the output of testssl.sh or in the `--help` output. This option can be used multiple times. The environment variable ENABLE_CHECK can be used instead. -q, --quiet Quiet mode. Suppresses most output, only shows errors and the final scan result. --no-server-prints Suppresses the printing of the server's output. This can be useful when dealing with servers that produce a lot of output. --no-msie-padding Disables the workaround for MSIE padding issues. This is generally not recommended unless you are sure that the server does not suffer from these issues. --no-compression Disables the use of compression in TLS/SSL. This can be useful for testing servers that do not support compression or are vulnerable to CRIME attacks. --no-fallback Disables the fallback to older TLS/SSL versions. This is generally not recommended unless you are sure that the server does not need to fall back to older versions. --no-session-tickets Disables the use of session tickets. This can be useful for testing servers that do not support session tickets or are vulnerable to weak session resumption attacks. --no-ticket-bleed Disables the check for the Ticketbleed vulnerability. This is generally not recommended unless you are sure that the server is not vulnerable to this attack. --no-heartbleed Disables the check for the Heartbleed vulnerability. This is generally not recommended unless you are sure that the server is not vulnerable to this attack. --no-ccs Disables the check for the CCS injection vulnerability. This is generally not recommended unless you are sure that the server is not vulnerable to this attack. --no-robot Disables the check for the ROBOT vulnerability. This is generally not recommended unless you are sure that the server is not vulnerable to this attack. --no-sslv2 Disables the check for SSLv2 support. This is generally recommended as SSLv2 is considered insecure. --no-sslv3 Disables the check for SSLv3 support. This is generally recommended as SSLv3 is considered insecure. --no-tlsv1 Disables the check for TLSv1.0 support. This is generally recommended as TLSv1.0 is considered insecure. --no-tlsv1_1 Disables the check for TLSv1.1 support. This is generally recommended as TLSv1.1 is considered insecure. -O, --off Turns off the prompt for confirmation for some checks. This is automatically chosen for mass testing (--file). "off" just skips the warning, the confirmation but continues the scan, independent whether it makes sense or not. Please note that there are conflicts where testssl.sh will still ask for confirmation which are the ones which otherwise would have a drastic impact on the results. Almost any other decision will be made in the future as a best guess by testssl.sh. The same can be achieved by setting the environment variable WARNINGS. --connect-timeout This is useful for socket TCP connections to a node. If the node does not complete a TCP handshake (e.g. because it is down or behind a firewall or there's an IDS or a tarpit) testssl.sh may usually hang for around 2 minutes or even much more. This parameter instructs testssl.sh to wait at most seconds for the handshake to complete before giving up. This option only works if your OS has a timeout binary installed. CONNECT_TIMEOUT is the corresponding environment variable. --openssl-timeout This is especially useful for all connects using openssl and practically useful for mass testing. It avoids the openssl connect to hang for ~2 minutes. The expected parameter seconds instructs testssl.sh to wait before the openssl connect will be terminated. The option is only available if your OS has a timeout binary installed. As there are different implementations of timeout: It automatically calls the binary with the right parameters. OPENSSL_TIMEOUT is the equivalent environment variable. --basicauth This can be set to provide HTTP basic auth credentials which are used during checks for security headers. BASICAUTH is the ENV variable you can use instead. --reqheader
