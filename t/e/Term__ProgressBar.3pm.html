Term__ProgressBar(3pm)

الحزمة: perl-term-progressbar

التراخيص: GPL, PerlArtistic

Term::ProgressBar(3) توثيق Perl المساهم به من قبل المستخدم Term::ProgressBar(3)

الاسم

Term::ProgressBar - توفير شريط تقدم على طرفية قياسية

الإصدار

الإصدار 2.23

الملخص

use Term::ProgressBar;
my $progress = Term::ProgressBar->new ({count => 10_000});
$progress->update(5_000);

الوصف

يوفر Term::ProgressBar شريط تقدم بسيط على الطرفية، لإعلام المستخدم بأن شيئًا ما يحدث، وبشكل تقريبي كم تم إنجازه، وربما تقديرًا للمدة المتبقية.

الاستخدام النموذجي يقوم بإعداد شريط التقدم مع عدد العناصر المراد معالجتها، ثم يستدعي update لتحديث الشريط كلما تم معالجة عنصر.

في كثير من الأحيان، قد يتضمن ذلك تحديث شريط التقدم عدة مرات دون أي تغيير مرئي للمستخدم. لتجنب العمل غير الضروري، تعيد طريقة update قيمة، وهي قيمة التحديث التي سيشاهد عندها المستخدم تغييرًا. عن طريق استدعاء update فقط عندما تتجاوز القيمة الحالية قيمة التحديث التالية، يتم تقليل حمل استدعاء الدالة.

تذكر استدعاء "$progress->update($max_value)" عند اكتمال المهمة للحصول على شريط مكتمل بنسبة 100٪.

شريط التقدم افتراضيًا بسيط؛ إنه يتحرك فقط من اليسار إلى اليمين، مملوءًا بأحرف '='. تسمى هذه الأحرف رئيسية. بالنسبة للمهام الطويلة، قد يكون هذا بطيئًا جدًا، لذا تتوفر ميزتان إضافيتان: مقدّر وقت اكتمال خطي، و/أو حرف ثانوي: وهو حرف يتحرك من اليسار إلى اليمين على شريط التقدم (لا يملأه مثل الحرف الرئيسي)، ويتنقل مرة واحدة لكل حرف رئيسي مضاف. هذا يزيد بشكل أسي من دقة الشريط بنفس العرض.

أمثلة

استخدام بسيط جدًا

#!/usr/bin/perl
use Term::ProgressBar 2.00;
use constant MAX => 100_000;
my $progress = Term::ProgressBar->new(MAX);
for (0..MAX) {
    my $is_power = 0;
    for (my $i = 0; 2**$i <= $_; $i++) {
        $is_power = 1 if 2**$i == $_;
    }
    if ($is_power) {
        $progress->update($_);
    }
}

انظر eg/simle_use.pl

هذا مثال بسيط. تعالج العملية جميع الأرقام بين 0 و MAX، وتقوم بتحديث شريط التقدم كلما وجدت واحدًا. لاحظ أن تحديث شريط التقدم سيكون متقطعًا جدًا. انظر أدناه لمثال أكثر سلاسة. لاحظ أيضًا أن شريط التقدم لن يكتمل أبدًا؛ انظر أدناه لحل هذه المشكلة.

النص الكامل لهذا المثال موجود في examples/powers في مجموعة التوزيع (لا يتم تثبيته كجزء من الوحدة).

تحديث شريط أكثر سلاسة

my $progress = Term::ProgressBar->new($max);
for (0..$max) {
    my $is_power = 0;
    for (my $i = 0; 2**$i <= $_; $i++) {
        $is_power = 1 if 2**$i == $_;
    }
    $progress->update($_)
}

انظر eg/smooth_bar.pl

يستدعي هذا المثال update لكل قيمة تم النظر فيها. سيؤدي هذا إلى تحديث تقدم أكثر سلاسة بكثير، ولكن سيتم قضاء المزيد من وقت البرنامج في تحديث الشريط بدلاً من العمل "الحقيقي". انظر أدناه لمعالجة هذا. هذا المثال لا يستدعي "$progress->update($max);" في النهاية، حيث أنه غير ضروري، وسيقوم ProgressBar بإطلاق استثناء عند محاولة تحديث شريط مكتمل.

النص الكامل لهذا المثال موجود في examples/powers2 في مجموعة التوزيع (لا يتم تثبيته كجزء من الوحدة.

تحديث أكثر كفاءة (بكثير)

my $progress = Term::ProgressBar->new({name => 'Powers', count => $max, remove => 1});
$progress->minor(0);
my $next_update = 0;
for (0..$max) {
    my $is_power = 0;
    for (my $i = 0; 2**$i <= $_; $i++) {
        $is_power = 1 if 2**$i == $_;
    }
    $next_update = $progress->update($_) if $_ >= $next_update;
}
$progress->update($max) if $max >= $next_update;

يقوم هذا المثال بأمرين لتحسين الكفاءة: أولاً، يستخدم القيمة التي تعيدها update لاستدعائها مرة أخرى فقط عند الحاجة؛ ثانيًا، يقوم بتعطيل استخدام الأحرف الثانوية لتحديث أقل تكرارًا ("$progress->minor(0);". استخدام القيمة التي تعيدها update يعني أن استدعاء "$progress->update($max);" في النهاية مطلوب لضمان انتهاء الشريط عند 100٪، مما يمنح المستخدم شعورًا لطيفًا.

يوضح هذا المثال أيضًا استخدام علامة 'remove'، التي تزيل شريط التقدم من الطرفية عند الانتهاء.

النص الكامل لهذا المثال موجود في examples/powers3 في مجموعة التوزيع (لا يتم تثبيته كجزء من الوحدة.

عندما يكون الحد الأقصى لعدد العناصر غير معروف أحيانًا

في بعض الأحيان قد ترغب في استخدام شريط التقدم عندما قد يكون عدد العناصر معروفًا أو غير معروف. أحد الأمثلة الشائعة هو عندما تكتب برنامجًا نصيًا يمكنه أخذ مدخلات ممررة من إخراج أمر آخر، ثم تمرير الإخراج إلى أمر آخر. على سبيل المثال:

some_command --arg value | my_script.pl | some_other_command

أو ...

my_script.pl input_file output_file

يوضح هذا المثال كيف يمكنك التكرار على ملف محدد في سطر الأوامر باستخدام شريط التقدم. نظرًا لأنه يمكن قراءة ملف الإدخال من STDIN، فقد لا يكون عدد الأسطر معروفًا. يتعامل Term::ProgressBar مع هذا عن طريق أخذ '-1' كقيمة عد بدون تغييرات إضافية على الكود. عن طريق استدعاء update بنفس القيمة، تضمن إزالة شريط التقدم بعد ذلك.

my $input_file = shift;
my $output_file = shift;
my $in_fh = \*STDIN;
my $out_fh = \*STDOUT;
my $message_fh = \*STDERR;
my $num_lines = -1;
if (defined($input_file) and $input_file ne '-') {
    open($in_fh, $input_file) or die "Couldn't open file, '$input_file': $!";
    my $wc_output = `wc -l $input_file`;
    chomp($wc_output);
    $wc_output =~ /^\s*(\d+)(\D.*)?/ or die "Couldn't parse wc output: $wc_output";
    $num_lines = $1;
}
if(defined($output_file)) {
    !-f $output_file or die "Specified output file, '$output_file', already exists";
    open($out_fh, '>', $output_file) or die "Couldn't open output file, '$output_file': $!";
}
my $progress = Term::ProgressBar->new({
    name   => 'file processor',
    count  => $num_lines,
    remove => 1,
    fh     => $message_fh,
});
while (my $line = <$in_fh>) {
    chomp($line);
    print $out_fh "I found a line: $line\n";
    $progress->message("Found 10000!") if($line =~ /10000/);
    $progress->update();
}
$progress->update($num_lines);
print $message_fh "Finished\n";

عندما يتم تحديد الملف بشكل صريح، يعرض شريط التقدم تقدمًا سطريًا عبر الملف. نظرًا لأن شريط التقدم يقوم بطباعة الإخراج افتراضيًا إلى stderr، فلن تتأثر مخرجات نصوصك إلى STDOUT.

استخدام تقدير وقت الاكتمال

  my $progress = Term::ProgressBar->new({
      name  => 'Powers',
      count => $max,
      ETA   => 'linear',
  });
  $progress->max_update_rate(1);
  my $next_update = 0;
  for (0..$max) {
      my $is_power = 0;
      for (my $i = 0; 2**$i <= $_; $i++) {
      if ( 2**$i == $_ ) {
          $is_power = 1;
          $progress->message(sprintf "Found %8d to be 2 ** %2d", $_, $i);
      }
  }
  $next_update = $progress->update($_)
    if $_ > $next_update;
}
$progress->update($max)
    if $max >= $next_update;

يستخدم هذا المثال خيار ETA لتشغيل تقدير الاكتمال. أيضًا، يتم ضبط إعادة التحديث لمحاولة تحديث الشريط مرة واحدة تقريبًا كل ثانية، مع استدعاء max_update_rate. انظر الوثائق لطريقة new للحصول على تفاصيل حول التنسيقات المستخدمة.

يقدم هذا المثال أيضًا مثالًا لاستخدام دالة message لإخراج الرسائل إلى نفس مقبض الملف مع الحفاظ على شريط التقدم سليمًا

النص الكامل لهذا المثال موجود في examples/powers5 في مجموعة التوزيع (لا يتم تثبيته كجزء من الوحدة.

مثال الإنشاء

جديد

إنشاء وطباعة مثيل جديد من Term::ProgressBar.

وسائط
إذا تم توفير وسيط واحد وكان عبارة عن hashref، فسيتم التعامل معه كأزواج مفتاح-قيمة، مع المفاتيح التالية؛ بخلاف ذلك، يتم التعامل معه كرقم، وهو ما يعادل المفتاح "count".
عدد
عدد العناصر. سيتم وضع علامة على شريط التقدم بنسبة 100% عند استدعاء update بالقيمة count، وسيتم عرضه بشكل متناسب حتى ذلك الحين.

إذا تم تحديد قيمة count أقل من الصفر، فسيتم عرض الاسم فقط (إذا تم تحديده)، وإذا تم تمكين علامة remove، فسيتم إزالته عند تحديث شريط التقدم بقيمة أقل من الصفر. وهذا يسمح باستخدام شريط التقدم حتى عندما يكون حجم count معروفًا في بعض الأحيان وغير معروف في أحيان أخرى، دون الحاجة إلى إجراء تعديلات متعددة في جميع أنحاء الكود.

اسم
اسم سيتم تقديمه قبل شريط التقدم.
ملف
ملف الإخراج. افتراضيًا، يكون stderr. لا يُنصح باستخدام تنسيق *foo{THING} إذا كنت تريد الحصول على إمكانيات Term؛ يجب تمرير متغير عام.
عرض_الطرفية
في بعض الأحيان لا يمكن تحديد عرض الطرفية بشكل صحيح. يمكن استخدام هذا الخيار لفرض عرض طرفية معين. يرجى استخدام قيمة موجبة.
صامت
إذا تم تمرير قيمة صحيحة، فلن يقوم Term::ProgressBar بإجراء أي تغييرات. يمكن استخدامه في البرامج النصية حيث يكون شريط التقدم اختياريًا (أو ببساطة لا يعمل بسبب مشاكل في الوحدات التابعة).

بدلاً من ذلك، أخبر المنشئ أنك تريد أن تكون صامتًا ولا تحتاج إلى تغيير بقية البرنامج:

my $progress = Term::ProgressBar->new( { count => $count, silent => $silent } );
# لاحقًا
$progress->update; # لا يفعل شيئًا
الوقت_المتوقع_للانتهاء
تقدير إجمالي للوقت. إذا تم تمكينه، فسيتم طباعة تقدير لوقت الانتهاء على الجانب الأيمن (بمجرد إجراء تحديثات كافية لإجراء مثل هذا التقدير).

ملاحظة: تم تصميم تنسيق التقدير ليكون مدمجًا قدر الإمكان مع توفير المعلومات ذات الصلة. اعتمادًا على الوقت المتبقي، يتم اختيار التنسيق لتوفير بعض الدقة مع البقاء مدمجًا. مع انخفاض الوقت المتبقي، يتغير التنسيق تدريجيًا.

عند الاقتراب من الوقت المتوقع للانتهاء، سيشير التنسيق إلى الدقائق والثواني المتبقية. يمكن التعرف على ذلك من خلال الكلمة 'Left' على الجانب الأيمن من السطر. إذا كان الوقت المتوقع للانتهاء أبعد من ذلك، فسيتم عرض تقدير للانتهاء (بدلاً من الوقت المتبقي) ويمكن التعرف عليه من خلال 'ETA' على الجانب الأيسر من مربع الوقت المتوقع للانتهاء (على الجانب الأيمن من شريط التقدم). يمكن عرض وقت أو تاريخ؛ هذه بتنسيق ساعة 24 ساعة، على سبيل المثال، '13:33'، أو وقت مع أيام (مثل ' 7PM+3' لحوالي 3 أيام) أو تاريخ، على سبيل المثال، ' 1Jan' أو '27Feb').

إذا كان الوقت المتوقع للانتهاء نشطًا، فإن القيمة التي تم إرجاعها من update تتأثر أيضًا: الهدف هو أنه إذا بدا شريط التقدم يتحرك بشكل أسرع مما يمكن للعين العادية أن تهتم به (وبالتالي يقضي وقتًا طويلاً في التحديثات التي ليست عملًا "حقيقيًا")، فإن القيمة التالية تزداد لجعلها أبطأ. يمكن تعديل الحد الأقصى لمعدل التحديث المطلوب باستخدام المكون max_update_rate.

القيم المتاحة لهذا هي:

غير_معرف
لا تقم بإجراء تقدير. القيمة الافتراضية.
خطي
قم بإجراء تقدير خطي. ببساطة، الوقت بين إنشاء شريط التقدم والوقت الحالي مقسومًا على عدد المهام المكتملة، ويتم إجراء التقدير خطيًا.
أمثلة
my $progress = Term::ProgressBar->new(100); # عد إلى 100
my $progress = Term::ProgressBar->new({ count => 100 }); # نفس الشيء
# عد إلى 200 شيء، الإخراج إلى stdout بدلاً من stderr، تقديم شريط بـ 'thingy'
my $progress = Term::ProgressBar->new({ count => 200,
                                        fh    => \*STDOUT,
                                        name  => 'thingy' });

مكونات المثيل

مكونات قياسية.

انظر get_set في Class::MethodMaker للاستخدام.

هدف
الهدف النهائي. يتم قياس التحديثات بناءً على هذا. لن يكون للتغييرات تأثير حتى التحديث التالي، ولكن يجب أن تكون القيمة التالية نسبية للهدف الجديد. لذا، 
$p = Term::ProgressBar({count => 20});
# منتصف الطريق
$p->update(10);
# مضاعفة الهدف
$p->target(40)
$p->update(21);

سينتج شريط تقدم سيتم تحديثه إلى 52.5٪

أقصى_معدل_تحديث
تُعتبر هذه القيمة الحد الأقصى للسرعة بين التحديثات للمحاذاة. مفيدة فقط إذا كان الوقت المتوقع للانتهاء نشطًا. افتراضيًا، هو 0.5، وهو عدد الثواني بين التحديثات.

مكونات منطقية.

انظر get_set في Class::MethodMaker للاستخدام.

صغير
الافتراضي: تعيين. إذا لم يتم تعريفه، فلن يتم حساب خطوة صغيرة أو تحديثها. تُستخدم الأحرف الصغيرة في شريط التقدم لمنح المستخدم فكرة عن التقدم حتى عندما تكون هناك مهام كثيرة جدًا بحيث يكون عرض الطرفية صغيرًا جدًا. افتراضيًا، يتخذ Term::ProgressBar حكمًا حول متى تكون الأحرف الصغيرة مفيدة، ولكن قد لا يكون ذلك دائمًا صحيحًا، لذلك يمكنك استدعاء هذه الطريقة لفرضها بطريقة أو بأخرى. من الواضح أن توفير الكفاءة ضئيل، ما لم يكن العميل يستخدم القيمة المرجعة من update.

انظر examples/powers4 و examples/powers3 لمعرفة كيفية عمل الأحرف الصغيرة في العمل وبدون عمل، على التوالي.

حتى_الآن
