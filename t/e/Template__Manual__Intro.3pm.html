الاسم

Template::Manual::Intro - مقدمة إلى Template Toolkit

مقدمة

Template Toolkit هو مجموعة من وحدات Perl التي تنفذ نظام معالجة قوالب سريع ومرن وقوي وقابل للتوسيع. غالباً ما يستخدم لتوليد محتوى ويب ديناميكي، على الرغم من أنه يمكن استخدامه بنفس القدر لمعالجة أي نوع من مستندات النص.

على أبسط المستويات، يوفر طريقة سهلة لمعالجة ملفات القوالب، وملء مراجع المتغيرات المضمنة بقيمها المكافئة. إليك مثال على قالب.

عزيزي [% name %]،
لقد لفت انتباهنا أن حسابك متأخر بمبلغ [% debt %].
يرجى تسوية حسابك قبل [% deadline %] وإلا سنضطر إلى إلغاء رخصة الإثارة الخاصة بك.
الإدارة.

بشكل افتراضي، يتم تضمين توجيهات القالب ضمن تسلسلات الأحرف "[%" ... "%]" ولكن يمكنك تغيير هذه الخيارات وخيارات أخرى مختلفة لتكوين كيفية مظهر Template Toolkit وعمله. يمكنك تعيين خيار "INTERPOLATE"، على سبيل المثال، إذا كنت تفضل تضمين متغيراتك بأسلوب Perl:

عزيزي $name،
لقد لفت انتباهنا أن حسابك متأخر بمبلغ $debt.
...إلخ...

وحدة Perl للقوالب

وحدة Perl للقوالب هي الواجهة الأمامية لـ Template Toolkit لمبرمجي Perl، توفر الوصول إلى النطاق الكامل للوظائف من خلال وحدة واحدة بواجهة بسيطة. تقوم بتحميل الوحدات الأخرى حسب الحاجة وتنشئ مجموعة افتراضية من الكائنات للتعامل مع طلبات معالجة القوالب اللاحقة. يمكن تمرير معلمات التكوين إلى طريقة المنشئ للقالب، new()، والتي تستخدم بعد ذلك لتكوين الكائن المولد.

use Template;
my $tt = Template->new({
    INCLUDE_PATH => '/usr/local/templates',
    INTERPOLATE  => 1,
}) || die "$Template::ERROR\n";

تنفيذ الكائن Template طريقة process() لمعالجة ملفات القوالب أو النصوص. يتم تمرير اسم القالب المدخل (أو مصادر أخرى مختلفة) كوسيط أول، يليه مرجع إلى مصفوفة تجزئة لتعريفات المتغيرات للاستبدال في القالب.

my $vars = {
    name     => 'Count Edward van Halen',
    debt     => '3 riffs and a solo',
    deadline => 'the next chorus',
};
$tt->process('letters/overdrawn', $vars)
    || die $tt->error(), "\n";

ترجع طريقة process() قيمة صحيحة ( 1) عند النجاح وتطبع إخراج القالب إلى "STDOUT"، افتراضياً. عند حدوث خطأ، ترجع طريقة process() قيمة خاطئة ( "undef"). يمكن بعد ذلك استدعاء طريقة error() لاسترداد تفاصيل الخطأ.

بناء المحتوى المعتمد على المكونات

يتم توفير عدد من التوجيهات الخاصة، مثل "INSERT" و "INCLUDE" و "PROCESS"، والتي تسمح ببناء المحتوى من مكونات قوالب أصغر. هذا يسمح بنهج معياري لبناء موقع ويب أو مستودع محتوى آخر، مما يعزز قابلية إعادة الاستخدام، والاتساق عبر المواقع، وسهولة الإنشاء والصيانة اللاحقة. يمكن إنشاء العناصر المشتركة مثل الرؤوس والتذييلات وقوائم التنقل والجداول وما إلى ذلك كملفات قوالب منفصلة يمكن بعد ذلك معالجتها في مستندات أخرى حسب الحاجة. يتم توريث جميع المتغيرات المعرفة بواسطة هذه القوالب جنباً إلى جنب مع أي قيم "محلية" إضافية محددة.

[% PROCESS header
     title = "The Cat Sat on the Mat"
%]
[% PROCESS menu %]
لقد تم تحديد مكان القط المفقود الآن.
شكرا لمساعدتك.
[% INSERT legal/disclaimer %]
[% PROCESS footer %]

يمكنك أيضاً تعريف قالب كـ BLOCK داخل نفس الملف ومعالجته تماماً مثل أي ملف قالب آخر. يمكن أن يكون هذا لا يقدر بثمن لبناء العناصر المتكررة مثل الجداول والقوائم وما إلى ذلك.

[% BLOCK tabrow %]
   <tr><td>[% name %]</td><td>[% email %]</td></tr>
[% END %]
<table>
[% PROCESS tabrow name="tom"   email="tom@here.org"    %]
[% PROCESS tabrow name="dick"  email="disk@there.org"  %]
[% PROCESS tabrow name="larry" email="larry@where.org" %]
</table>

ربط البيانات والكود

إحدى الميزات الرئيسية التي تميز Template Toolkit عن معالجات القوالب الأخرى هي القدرة على ربط متغيرات القالب بأي نوع من بيانات Perl: القيم العددية، القوائم، مصفوفات التجزئة، الإجراءات الفرعية، والكائنات.

my $vars = {
    root   => 'http://here.com/there',
    menu   => [ 'modules', 'authors', 'scripts' ],
    client => {
        name => 'Doctor Joseph von Satriani',
        id   => 'JVSAT',
    },
    checkout => sub { my $total = shift; ...; return $something },
    shopcart => My::Cool::Shopping::Cart->new(),
};

سيقوم Template Toolkit تلقائياً بالقيام بالشيء الصحيح للوصول إلى البيانات بطريقة مناسبة لإرجاع قيمة يمكن بعد ذلك إخراجها. يتم استخدام عامل النقطة '"."' للدخول إلى القوائم والمصفوفات أو لاستدعاء طرق الكائنات. يتم توفير التوجيه "FOREACH" للتكرار عبر القوائم، وتتوفر اختبارات منطقية مختلفة باستخدام توجيهات مثل "IF" و "UNLESS" و "ELSIF" و "ELSE" و "SWITCH" و "CASE"، إلخ.

[% FOREACH section = menu %]
   <a href="[% root %]/[% section %]/index.html">[% section %]</a>
[% END %]
<b>Client</b>: [% client.name %] (id: [% client.id %])
[% IF shopcart.nitems %]
   Your shopping cart contains the following items:
   <ul>
   [% FOREACH item = shopcart.contents %]
     <li>[% item.name %] : [% item.qty %] @ [% item.price %]
   [% END %]
   </ul>
   [% checkout(shopcart.total) %]
[% ELSE %]
   No items currently in shopping cart.
[% END %]

ميزات متقدمة: المرشحات، وحدات الماكرو، الاستثناءات، الإضافات

يوفر Template Toolkit أيضاً عدداً من التوجيهات الإضافية للمعالجة المتقدمة والوظائف البرمجية. يدعم مرشحات الإخراج (FILTER)، ويسمح بتعريف وحدات ماكرو مخصصة (MACRO)، ولديه نظام كامل لمعالجة الاستثناءات (TRY، THROW، CATCH، FINAL) ويدعم بنية إضافات (USE) والتي تسمح بتحميل واستخدام وحدات إضافات خاصة وحتى وحدات Perl عادية بأقل قدر من المتاعب. Template Toolkit هو "فقط" معالج قوالب ولكن يمكنك توسيعه بسهولة لدمج وظائف أي وحدة Perl يمكنك الحصول عليها. وبالتالي، فهو أيضاً إطار عمل قوالب قابل للتطوير والتوسع، مناسب تماماً لإدارة طبقة العرض لخوادم التطبيقات وأنظمة إدارة المحتوى وتطبيقات الويب الأخرى.

فصل منطق العرض والتطبيق

بدلاً من تضمين كود Perl أو أي لغة برمجة نصية أخرى مباشرة في مستندات القوالب، فإنه يشجعك على إبقاء المكونات الوظيفية (أي كود Perl) منفصلة عن مكونات العرض (على سبيل المثال، قوالب HTML). توفر متغيرات القالب الواجهة بين الطبقتين، مما يسمح بتوليد البيانات في الكود ثم تمريرها إلى مكون قالب للعرض (نموذج خط الأنابيب) أو ربط مراجع الإجراءات الفرعية أو الكائنات بالمتغيرات التي يمكن بعد ذلك استدعاؤها من القالب عند الحاجة (نموذج الاستدعاء).

التوجيهات التي توفرها Template Toolkit تنفذ لغة برمجة صغيرة خاصة بها، لكنها ليست مصممة حقاً للبرمجة الجادة للأغراض العامة. Perl هي لغة أنسب بكثير لذلك. إذا قمت بتضمين منطق التطبيق (على سبيل المثال، أجزاء من Perl أو لغات برمجة نصية أخرى) في قوالب HTML، فإنك تخاطر بفقدان الفصل الواضح للمسؤوليات بين الوظائف والعرض. يصبح من الصعب صيانة العنصرين بشكل منفصل وأكثر صعوبة، إن لم يكن مستحيلاً، إعادة استخدام الكود أو العرض.

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

Template::Manual::Intro (3pm)

NAME

Template::Manual::Intro - Introduction to the Template Toolkit

Introduction

The Template Toolkit is a powerful, flexible, and extensible template processing system written in Perl. It is designed to be used for generating all kinds of text output, from HTML web pages and XML documents to email messages and configuration files. It is particularly well-suited for use in dynamic web content generation systems.

The core of the system is a template engine that accepts templates containing a mix of static text and template directives. When processed, the engine evaluates the directives, substitutes variables, and inserts data to generate the final output.

The Template Perl Module

The Template Toolkit is distributed as a Perl module, Template. This module provides a simple, Perl-based interface for processing templates. You can use it to load templates from files, strings, or other sources, and to process them with a given set of variables.

Component Based Content Construction

The Template Toolkit encourages a component-based approach to content construction. Templates can be broken down into smaller, reusable components or "includes". This allows for better organization and maintainability of complex templates.

This approach promotes the separation of concerns, where different components can be responsible for different parts of the content, making the overall system easier to manage and update.

Data and Code Binding

The Template Toolkit allows for flexible binding of data and code. Data can be passed into templates as variables, and these variables can be manipulated using filters and other directives. Complex logic can be handled either within the template (using Perl code blocks, if enabled) or, more preferably, in the application code that generates the data.

Advanced Features: Filters, Macros, Exceptions, Plugins

The Template Toolkit offers a rich set of advanced features:

Filters:
Allow you to modify or format data before it is outputted. Examples include HTML escaping, lowercasing, or date formatting.
Macros:
Reusable blocks of template code that can be defined and called like functions, accepting arguments.
Exceptions:
Mechanisms for handling errors and unexpected situations gracefully within the template processing.
Plugins:
Allow extension of the template engine's functionality with custom modules, enabling integration with external systems or complex data processing.

Separating Presentation and Application Logic

A key principle of the Template Toolkit is the separation of presentation logic from application logic. While the toolkit is flexible enough to embed Perl code for calculations, it is strongly recommended to keep complex data manipulation and business logic in your application code (Perl modules, libraries, or scripts). Templates should primarily focus on defining the structure and presentation of the output, using the data provided by the application.

This separation makes applications easier to maintain, test, and allows designers and developers to work more effectively. Think of the template language as a set of layout directives for displaying data, not for calculating it.

Having said that, the Template Toolkit doesn't force you into one approach or the other. It attempts to be pragmatic rather than dogmatic in allowing you to do whatever best gets the job done. Thus, if you enable the EVAL_PERL option then you can happily embed real Perl code in your templates within PERL ... END directives.

Performance

The Template Toolkit uses a fast YACC-like parser which compiles templates into Perl code for maximum runtime efficiency. It also has an advanced caching mechanism which manages in-memory and on-disk (i.e. persistent) versions of compiled templates. The modules that comprise the toolkit are highly configurable and the architecture around which they're built is designed to be extensible. The Template Toolkit provides a powerful framework around which content creation and delivery systems can be built while also providing a simple interface through the Template front-end module for general use.
