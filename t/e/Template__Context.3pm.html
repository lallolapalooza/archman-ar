NAME

Template::Context - The Template Toolkit context object

SYNOPSIS

    use Template::Context;

    # Create a context object
    my $context = Template::Context->new( ... );

    # Access configuration items
    my $stash = $context->stash;
    my $vars  = $stash->get_global;

    # Process a template
    my $template = Template::Document->new( ... );
    $template->process( $context, \@args, \$output );

    # Add or retrieve a plugin
    $context->plugin( 'Text' );
    my $text_plugin = $context->plugin( 'Text' );

    # Add or retrieve a filter
    $context->filter( 'upper' );
    my $upper_filter = $context->filter( 'upper' );

    # Define and use a block
    $context->define_block( 'MY_BLOCK', $template );
    my $block_template = $context->fetch_block( 'MY_BLOCK' );

    # Control debugging output
    $context->debugging( 'on' );
    $context->debugging( format => '## $file line $line: $text' );
    $context->debugging( msg => { file => 'foo.tt', line => 10, text => 'Hello' } );

DESCRIPTION

The Template::Context class defines the context within which templates are processed. It holds references to the Stash, Provider, Filters, Plugins and other configuration items that dictate how templates are parsed, compiled and processed.

A context object is created internally by the Template engine object when it is instantiated, or it can be created and configured explicitly if you wish to manage the process more directly.

The context is passed as the first argument to the process() method of a compiled Template::Document object.

METHODS

A number of methods are available for accessing and manipulating the context's configuration.

new(%args)

Creates and returns a new Template::Context object. The following configuration items may be passed as arguments:

stash
A Template::Stash object (or one that behaves like it).
provider
A Template::Provider object.
filters
A Template::Filters object.
plugins
A Template::Plugins object.
blocks
A hash reference containing block definitions. These are compiled into Template::Document objects and stored internally for retrieval via the fetch_block() method.
encoding
The default input encoding for template files and data. Defaults to UTF-8.
default_encoding
An alias for encoding.
output_encoding
The default output encoding for template rendering. Defaults to UTF-8.
die_on_error
If true, errors thrown during template processing will cause the script to die(). Defaults to false.
trim
If true, leading/trailing whitespace is automatically trimmed from template blocks. Defaults to false.
evaluate_php
If true, template blocks written in PHP syntax will be evaluated. Defaults to false.
regex_module
The regular expression module to use. Defaults to Perl's built-in regex engine.
error_mode
Specifies how to handle errors. Can be 'die', 'warn' or 'return'. Defaults to 'warn'.

stash()

Returns the Template::Stash object associated with the context.

provider()

Returns the Template::Provider object associated with the context.

filters()

Returns the Template::Filters object associated with the context.

plugins()

Returns the Template::Plugins object associated with the context.

plugin($name, %args)

Loads and returns a plugin instance. If the plugin is already loaded, it is simply returned. The $name argument is the name of the plugin (e.g. 'Text', 'Date'). Any additional arguments are passed to the plugin's constructor when it is first loaded.

filter($name)

Returns a filter subroutine reference. If the filter is not already loaded, it is loaded and registered internally.

define_block($name, $template)

Defines a named block. The $template argument should be a compiled Template::Document object or a string containing template code which will be compiled into one.

fetch_block($name)

Retrieves a compiled block definition by its name. Returns undef if the block is not found.

import_blocks($package)

Imports all blocks defined within a specific Perl package.

process($context, \@args, \$output)

Processes a Template::Document object according to the rules defined by the context. This method is generally called internally by the Template engine object when it calls the process() method of a Template::Document object.

error($message, %args)

Logs an error message. The behaviour depends on the value of the error_mode configuration item.

warn($message, %args)

Logs a warning message.

debug($message, %args)

Logs a debug message. Debugging must be explicitly enabled for output to be generated. See the debugging() method.

config($name)

Returns the value of a configuration item.

clear()

Clears the context of all cached objects, such as plugins and filters. This forces them to be re-loaded the next time they are requested. Note that this does not affect the Stash or Provider objects.

clone()

Creates and returns a copy of the context object. The copy is a shallow copy, meaning that the Stash, Provider, Filters and Plugins objects are shared between the original and the copy.

set_context(\@args)

Sets the context for the current block or template processing. This is primarily used internally to manage the call stack when processing nested templates or blocks, although it can be used to implement custom logic for handling variable scope.

The @args are the arguments passed to the template or block. These are pushed onto the stash as local variables.

get_context()

Returns the current context stack, which is an array reference containing the arguments passed to the templates and blocks currently being processed.

clear_context()

Clears the context stack, popping all saved contexts. This is generally called when a template or block finishes processing.

trim_mode($flag)

Sets or returns the trim mode flag.

eval_perl($flag)

Sets or returns the evaluate_perl mode flag.

encoding($encoding)

Sets or returns the default input encoding.

output_encoding($encoding)

Sets or returns the default output_encoding.

process_document($doc, \@args, \$output)

This method is called internally to process a compiled Template::Document object. It manages the context stack and calls the document's own process() method. It returns true on success or false on failure.

process_string($string, \@args, \$output)

Compiles and processes a template string. This is a convenience method that wraps calls to Template::Document->new() and process_document(). It returns true on success or false on failure.

$context->process_string( 'Hello, [% name %]!', [ name => 'World' ], \$output );

include($filename, \@args, \$output)

Finds, compiles and processes a template file specified by $filename. This method uses the context's provider to locate the file. It returns true on success or false on failure.

$context->include( 'header.tt', \%header_vars, \$output );

call($plugin, $method, \@args, \$output)

Calls a method on a plugin instance. This is used internally by the compiler to generate code for plugin calls.

load_plugin($name, %args)

Loads a plugin and returns an instance. This method is called by plugin() and also used internally by the compiler.

load_filter($name)

Loads a filter and returns a subroutine reference. This method is called by filter() and also used internally by the compiler.

add_block($name, $template)

Adds a compiled block definition to the context's internal cache. This is used by define_block().

get_block($name)

Retrieves a compiled block definition from the cache. This is used by fetch_block().

clear_blocks()

Clears all cached block definitions. This is used by reset().

debugging($flag, @args)

Controls the generation of debugging output. This method can be called in several ways:

debugging('on')
Enables debugging output.
debugging('off')
Disables debugging output.
debugging( 0 )
Equivalent to debugging('off').
debugging( 1 )
Equivalent to debugging('on').
debugging( format => $format )
Sets the format string for debug messages. The format string can include variables like $file, $line, and $text, which will be replaced with the relevant values when a debug message is generated.
debugging( msg => { file => ..., line => ..., text => ... } )
Generates and outputs a debug message. The hash reference provides values for the variables defined in the debug format string.

The debugging() method is used internally to implement the DEBUG directive.

    # Enable debugging
    $context->debugging('on');

    # Define a custom debug message format
    $context->debugging( format => '[DEBUG] at line $line in $file: $text' );

    # Output a debug message
    $context->debugging( msg => {
        file => 'example.tt',
        line => 42,
        text => 'Processing user data',
    } );

    # Disable debugging
    $context->debugging('off');

AUTOLOAD()

The AUTOLOAD method provides convenient access to configuration items and sub-objects. For example, you can access the stash via $context->stash() or directly via $context->stash (though the latter is not recommended as it bypasses any accessor methods).

The following are common examples of AUTOLOAD access:

    my $stash     = $context->stash();     # Returns Template::Stash object
    my $provider  = $context->provider();  # Returns Template::Provider object
    my $filters   = $context->filters();   # Returns Template::Filters object
    my $plugins   = $context->plugins();   # Returns Template::Plugins object
    my $trim      = $context->trim();      # Returns value of 'trim' config item
    my $eval_perl = $context->eval_perl(); # Returns value of 'evaluate_perl' config item

Note that AUTOLOAD is generally used internally by the Template Toolkit. Explicitly calling accessor methods like $context->stash() is usually preferred.
