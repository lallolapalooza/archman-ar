-f <capture filter>

Set the capture filter expression.

This option can occur multiple times. If used before the first occurrence of the -i option, it sets the default capture filter expression. If used after an -i option, it sets the capture filter expression for the interface specified by the last -i option occurring before this option. If the capture filter expression is not set specifically, the default capture filter expression is used if provided.

Pre-defined capture filter names, as shown in the GUI menu item Capture→Capture Filters, can be used by prefixing the argument with "predef:". Example: tshark -f "predef:MyPredefinedHostOnlyFilter"

-F <file format>

Set the file format of the output capture file written using the -w option. The output written with the -w option is raw packet data, not text, so there is no -F option to request text output. The option -F without a value will list the available formats. The default is the pcapng format (unless the default has been changed in preferences.) .

-g

This option causes the output file(s) to be created with group-read permission (meaning that the output file(s) can be read by other members of the calling user’s group).

-G <report type>

The -G option will cause TShark to dump one of several types of glossaries and then exit. The glossary type is now mandatory; previous versions generated the fields report by default when no type was given. With one exception, the reports reflect the current configuration, including that given by a -C option or as modified by other command line options. Using the report type of help lists all the current report types.

The available report types include:

column-formats Dumps the column formats understood by TShark. There is one record per line. The fields are tab-delimited.

Field 1

format string (e.g. "%rD")

Field 2

text description of format string (e.g. "Dest port (resolved)")

Field 3

field abbreviation used for the column text (e.g. "_ws.col.res_dst_port")

This report is followed by a usage example that demonstrates how to change the columns by overriding the gui.column.format preference value with -o.

currentprefs Dumps a copy of the current preferences file to stdout.

decodes Dumps the "layer type"/"decode as" associations to stdout. There is one record per line. The fields are tab-delimited.

Field 1

layer type, e.g. "tcp.port"

Field 2

Field 3

"decode as" name, e.g. "http"

Field 1

Field 2

filter is an optional list of comma separated protocol filter names that limits the generated mapping file to the specified protocols, to avoid a huge mapping file that can choke some software (such as Kibana). E.g.,

-i option، فإنه يحدد نوع الارتباط الافتراضي للاستيعاب. إذا تم استخدامه بعد خيار -i، فإنه يحدد نوع الارتباط للاستيعاب للواجهة المحددة بواسطة آخر خيار -i يظهر قبل هذا الخيار. إذا لم يتم تحديد نوع الارتباط للاستيعاب بشكل خاص، يتم استخدام نوع الارتباط الافتراضي للاستيعاب إذا تم توفيره.

-Y|--display-filter <displaY filter>

يجعل الفلتر المحدد (الذي يستخدم صيغة فلاتر القراءة/العرض، بدلاً من صيغة فلاتر الالتقاط) يتم تطبيقه قبل طباعة شكل مفكك للحزم أو كتابة الحزم إلى ملف. الحزم التي تطابق الفلتر يتم طباعتها أو كتابتها إلى الملف؛ الحزم التي تعتمد عليها الحزم المطابقة (مثل الأجزاء)، لا يتم طباعتها ولكن يتم كتابتها إلى الملف؛ الحزم التي لا تطابق الفلتر ولا تعتمد عليها يتم تجاهلها بدلاً من طباعتها أو كتابتها.

استخدم هذا بدلاً من -R للتصفية باستخدام التحليل أحادي المرور. إذا كنت تقوم بتحليل ثنائي المرور (انظر -2) فسيتم التحقق فقط من الحزم المطابقة لفلتر القراءة (إذا كان هناك واحد) مقابل هذا الفلتر.

-M <auto session reset>

إعادة تعيين جلسة العمل الداخلية تلقائيًا عند الوصول إلى عدد محدد من الحزم. على سبيل المثال،

tshark -M 100000

سيؤدي إلى إعادة تعيين الجلسة كل 100000 حزمة.

هذه الميزة لا تدعم التحليل ثنائي المرور -2

-z <statistics>

يجعل TShark يجمع أنواعًا مختلفة من الإحصائيات ويعرض النتيجة بعد الانتهاء من قراءة ملف الالتقاط. استخدم خيار -q إذا كنت تقرأ ملف التقاط وتريد فقط طباعة الإحصائيات، وليس أي معلومات لكل حزمة.

يتم حساب الإحصائيات بشكل مستقل عن مخرجات الحزم العادية، ولا تتأثر بفلتر العرض الرئيسي. ومع ذلك، فإن معظمها لديه معامل filter اختياري خاص به، وسيتم استخدام الحزم التي تطابق هذا الفلتر فقط (وأي فلتر التقاط أو فلتر قراءة) في الحسابات.

لاحظ أن خيار -z proto مختلف - فهو لا يؤدي إلى تجميع وطباعة الإحصائيات عند اكتمال الالتقاط، بل يقوم بتعديل مخرجات ملخص الحزم العادية لإدراج قيم الحقول المحددة بالخيار. لذلك يجب ألا تستخدم خيار -q، لأن هذا الخيار سيمنع طباعة مخرجات ملخص الحزم العادية، ويجب ألا تستخدم خيار -V أيضًا، لأن ذلك سيؤدي إلى طباعة معلومات تفصيلية عن الحزم بدلاً من معلومات ملخص الحزم.

يمكن استخدام هذا الخيار عدة مرات في سطر الأوامر.

مثال: -z "rlc-3gpp،stat،rlc-nr.ueid>3000" سيجمع الإحصائيات فقط لـ NR UEs بمعرف UE يزيد عن 3000.

-z rpc،programs

جمع بيانات SRT للمكالمات/الردود لجميع برامج/إصدارات ONC-RPC المعروفة. البيانات التي تم جمعها هي عدد المكالمات لكل بروتوكول/إصدار، MinSRT، MaxSRT، و AvgSRT. يمكن استخدام هذا الخيار مرة واحدة فقط في سطر الأوامر.

-z rpc،srt،program،version[,filter]

جمع بيانات SRT (زمن استجابة الخدمة) للمكالمات/الردود لـ program/version. البيانات التي تم جمعها هي عدد المكالمات لكل إجراء، MinSRT، MaxSRT، AvgSRT، والوقت الإجمالي المستغرق لكل إجراء.

مثال: tshark -z rpc،srt،100003،3 سيجمع البيانات لـ NFS v3.

يمكن استخدام هذا الخيار عدة مرات في سطر الأوامر.

مثال: -z rpc،srt،100003،3،nfs.fh.hash==0x12345678 سيجمع إحصائيات NFS v3 SRT لملف معين.

-z rtp،streams

جمع الإحصائيات لجميع تدفقات RTP وحساب أقصى. دلتا، وأقصى. ومتوسط نسبة فقدان الارتجاج وحزم البيانات.

-z rtsp،stat[,filter]

عد رموز حالة استجابة RTSP وطرق طلب RSTP.

-z rtsp،tree[,filter]

حساب توزيع حزم RTSP. القيم المعروضة هي رموز حالة الاستجابة وطرق الطلب.

-z sametime،tree[,filter]

حساب الإحصائيات حول رسائل SAMETIME. القيم المعروضة هي نوع الرسائل، نوع الإرسال، وحالة المستخدم.

-z scsi،srt،cmdset[,filter]

جمع بيانات SRT (زمن استجابة الخدمة) للمكالمات/الردود لمجموعة أوامر SCSI cmdset.

مجموعات الأوامر هي 0:SBC 1:SSC 5:MMC

البيانات التي تم جمعها هي عدد المكالمات لكل إجراء، MinSRT، MaxSRT، و AvgSRT.

مثال: -z scsi،srt،0 سيجمع البيانات لأوامر SCSI BLOCK (SBC).

يمكن استخدام هذا الخيار عدة مرات في سطر الأوامر.

مثال: -z scsi،srt،0،ip.addr==1.2.3.4 سيجمع إحصائيات SCSI SBC SRT لمضيف iscsi/ifcp/fcip معين.

-z sctp،stat

تنشيط عداد لأجزاء SCTP. بالإضافة إلى العدد الإجمالي لحزم SCTP، لكل تركيبة عنوان ومنفذ مصدر ووجهة، يتم عرض عدد الأجزاء من الأنواع الأكثر شيوعًا (DATA، SACK، HEARTBEAT، HEARTBEAT ACK، INIT، INIT ACK، COOKIE ECHO، COOKIE ACK، ABORT، و ERROR).

-z sip،stat[,filter]

سيؤدي هذا الخيار إلى تنشيط عداد لرسائل SIP. ستحصل على عدد مرات ظهور كل طريقة SIP وكل رمز حالة SIP. بالإضافة إلى ذلك، ستحصل أيضًا على عدد رسائل SIP المعاد إرسالها (فقط لـ SIP عبر UDP).

مثال: -z sip،stat.

يمكن استخدام هذا الخيار عدة مرات في سطر الأوامر.

مثال: -z "sip،stat،ip.addr==1.2.3.4" سيجمع الإحصائيات فقط لحزم SIP التي تم تبادلها بواسطة المضيف الموجود في عنوان IP 1.2.3.4.

-z smb،sids

عند استخدام هذه الميزة، سيقوم TShark بطباعة تقرير بجميع تعيينات SID واسم الحساب المكتشفة. سيتم عرض SID التي يكون اسم الحساب الخاص بها معروفًا فقط في الجدول.

لكي تعمل هذه الميزة، ستحتاج إما إلى تمكين "Edit/Preferences/Protocols/SMB/Snoop SID to name mappings" في التفضيلات أو يمكنك تجاوز التفضيلات عن طريق تحديد -o "smb.sid_name_snooping:TRUE" في سطر أوامر TShark.

الطريقة الحالية التي يستخدمها TShark للعثور على تعيين SID ← الاسم مقيدة نسبيًا مع أمل في التوسع المستقبلي.

-z smb،srt[,filter]

جمع بيانات SRT (زمن استجابة الخدمة) للمكالمات/الردود لـ SMB. البيانات التي تم جمعها هي عدد المكالمات لكل أمر SMB، MinSRT، MaxSRT، و AvgSRT.

مثال: -z smb،srt

سيتم عرض البيانات كجداول منفصلة لجميع أوامر SMB العادية، وجميع أوامر Transaction2، وجميع أوامر NT Transaction. سيتم عرض إحصائيات الأوامر التي تم رؤيتها في الالتقاط فقط. سيتم استخدام الأمر الأول فقط في سلسلة أوامر xAndX في الحساب. لذلك بالنسبة لسلاسل SessionSetupAndX + TreeConnectAndX الشائعة، سيتم استخدام مكالمة SessionSetupAndX فقط في الإحصائيات. هذا عيب قد يتم إصلاحه في المستقبل.

يمكن استخدام هذا الخيار عدة مرات في سطر الأوامر.

مثال: -z "smb،srt،ip.addr==1.2.3.4" سيجمع الإحصائيات فقط لحزم SMB التي تم تبادلها بواسطة المضيف الموجود في عنوان IP 1.2.3.4.

-z smb2،srt[,filter]

جمع بيانات SRT (زمن استجابة الخدمة) للمكالمات/الردود لإصدارات SMB 2 و 3. البيانات التي تم جمعها لكل نوع أمر عادي هي عدد المكالمات، MinSRT، MaxSRT، AvgSRT، و SumSRT. لا يتم جمع أي بيانات عن طلبات الإلغاء أو كسر الـ oplock، أو عن الأوامر غير المزدوجة. يتم استخدام الاستجابة الأولى فقط لطلب معين؛ لا يتم تضمين إعادة الإرسال في الحساب.

-z smpp_commands،tree[,filter]

حساب توزيع أوامر SMPP. القيم المعروضة هي معرفات الأوامر لكل من الطلبات والاستجابات، والحالة للاستجابات.

-z snmp،srt[,filter]

جمع بيانات SRT (زمن استجابة الخدمة) للمكالمات/الردود لـ SNMP. البيانات التي تم جمعها لكل نوع PDU هي عدد أزواج الطلبات/الاستجابات، MinSRT، MaxSRT، AvgSRT، و SumSRT. لا يتم جمع أي بيانات عن الرسائل غير المزدوجة.

-z someip_messages،tree[,filter]

إنشاء إحصائيات لرسائل SOME/IP. يتم عد الرسائل وعرضها كرسائل مجمعة حسب المرسل/المستقبل.

-z someipsd_entries،tree[,filter]

إنشاء إحصائيات لإدخالات SOME/IP-SD. يتم عد الإدخالات وعرضها كإدخالات مجمعة حسب المرسل/المستقبل.

-z sv

طباعة الوقت منذ بداية الالتقاط وعدد العينات لكل حزمة IEC 61850 Sampled Values.

-z ucp_messages،tree[,filter]

حساب توزيع الرسائل لحزم UCP. القيم المعروضة هي أنواع العمليات لكل من العمليات والنتائج، وما إذا كانت النتائج إيجابية أو سلبية، مع عرض رموز الأخطاء للنتائج السلبية.

-z wsp،stat[,filter]

عد أنواع PDU ورموز حالة حزم الرد لحزم WSP.

--capture-comment <comment>

إضافة تعليق التقاط إلى ملف الإخراج، إذا كان مدعومًا من قبل تنسيق ملف الإخراج.

يمكن تحديد هذا الخيار عدة مرات. لاحظ أن Wireshark يعرض حاليًا التعليق الأول لملف الالتقاط فقط.

--list-time-stamp-types

قائمة أنواع الطوابع الزمنية المدعومة للواجهة. إذا لم يتم تعيين أي نوع طابع زمني، فلن يتم سرد أي أنواع طوابع زمنية.

--time-stamp-type <type>

تغيير طريقة الطابع الزمني للواجهة.

--update-interval <interval>

تعيين طول الوقت بالمللي ثانية بين تقارير الحزم الجديدة أثناء الالتقاط. كما أنه يحدد دقة شروط مدة الملف. القيمة الافتراضية هي 100 مللي ثانية.

--color

تمكين تلوين الحزم وفقًا لقواعد تصفية الألوان القياسية لـ Wireshark. على أنظمة Windows، تقتصر الألوان على ألوان سمات الأحرف القياسية لوحدة التحكم. تتطلب الأنظمة الأساسية الأخرى طرفًا يدعم تسلسلات الهروب الطرفية "true color" بدقة 24 بت. انظر https://wiki.wireshark.org/ColoringRules لمزيد من المعلومات حول تكوين قواعد الألوان.

--no-duplicate-keys

إذا ظهر مفتاح عدة مرات في كائن، اكتبه مرة واحدة فقط مع قيمة عبارة عن مصفوفة JSON تحتوي على جميع القيم المنفصلة. (يعمل فقط مع -T json)

--elastic-mapping-filter <protocol>,<protocol>,...

عند إنشاء ملف تعيين ElasticSearch، ضع البروتوكولات المحددة فقط فيه، لتجنب ملف تعيين ضخم قد يتسبب في تعطل بعض البرامج (مثل Kibana). يأخذ الخيار قائمة بالاختصارات المطلوبة للبروتوكولات، مفصولة بفاصلة.

مثال: ip,udp,dns يضع هذه البروتوكولات الثلاثة فقط في ملف التعيين.

--export-objects <protocol>,<destdir>

تصدير جميع الكائنات ضمن بروتوكول إلى الدليل destdir. يمكن سرد القيم المتاحة لـ protocol باستخدام --export-objects help.

يتم حفظ الكائنات مباشرة في الدليل المحدد. تعتمد أسماء الملفات على الماسح الضوئي، ولكن عادةً ما يتم تسميتها باسم الملف الأساسي. لا يتم الكتابة فوق الملفات المكررة، بل يتم إلحاق رقم متزايد قبل امتداد الملف.

هذه الواجهة خاضعة للتغيير، مع إضافة إمكانية التصفية حسب الملفات.

--print-timers

إخراج JSON يحتوي على الأوقات المنقضية لكل مرحلة يقوم tshark بها لمعالجة ملف التقاط والوقت الإجمالي المنقضي لجميع المراحل. يحتوي الإخراج لكل مرحلة على الوقت الإجمالي المنقضي والعدادات المجمعة لعمليات كل حزمة (التشخيص والتصفية).

--compress <type>

ضغط ملف الإخراج باستخدام نوع تنسيق الضغط. يوفر --compress بدون وسيطة قائمة بتنسيقات الضغط المدعومة للكتابة. يأخذ النوع المحدد الأسبقية على امتداد outfile.

خيارات التشخيص

-d <layer type>==<selector>,<decode-as protocol>

مثل ميزة Decode As... في Wireshark، تسمح لك هذه الخيار بتحديد كيفية تشخيص نوع طبقة. إذا كان نوع الطبقة المعني (على سبيل المثال، tcp.port أو udp.port لرقم منفذ TCP أو UDP) يحتوي على قيمة المحدد المحددة، فيجب تشخيص الحزم على أنها البروتوكول المحدد.

المثال 1. فك التشفير حسب المنفذ

-d tcp.port==8888,http سيقوم بفك تشفير أي حركة مرور تعمل عبر منفذ TCP 8888 على أنها HTTP.

المثال 2. فك التشفير حسب نطاق المنافذ

-d tcp.port==8888-8890,http سيقوم بفك تشفير أي حركة مرور تعمل عبر منافذ TCP 8888 أو 8889 أو 8890 على أنها HTTP.

المثال 3. فك التشفير حسب نطاق المنافذ عبر الطول

-d tcp.port==8888:3,http سيقوم بفك تشفير أي حركة مرور تعمل عبر منافذ TCP الثلاثة 8888 أو 8889 أو 8890 على أنها HTTP.

سيؤدي استخدام محدد غير صالح أو بروتوكول غير صالح إلى عرض قائمة بالمحددات الصالحة وأسماء البروتوكولات، على التوالي.

المثال 4. فك التشفير حسب قائمة المحددات

-d . هي طريقة سريعة للحصول على قائمة بالمحددات الصحيحة.

المثال 5. فك التشفير حسب قائمة القيم لمحدد

-d ethertype==0x0800,. هي طريقة سريعة للحصول على قائمة بالبروتوكولات التي يمكن تحديدها باستخدام نوع الإيثرنت.

--disable-all-protocols

تعطيل تشخيص جميع البروتوكولات.

--disable-protocol <proto_name>[,<proto_name>,...]

تعطيل تشخيص proto_name. استخدم proto_name بقيمة ALL لتجاوز قائمة البروتوكولات الافتراضية الممكّنة لملفك الشخصي وتعطيل جميع البروتوكولات مؤقتًا.

--disable-heuristic <short_name>

تعطيل تشخيص البروتوكول الاستدلالي.

--enable-protocol <proto_name>[,<proto_name>,...]

تمكين تشخيص proto_name. استخدم proto_name بقيمة ALL لتجاوز قائمة البروتوكولات المعطلة الافتراضية لملفك الشخصي وتمكين جميع البروتوكولات التي تم تمكينها افتراضيًا مؤقتًا.

إذا كان بروتوكول متضمنًا في كل من --disable-protocol و --enable-protocol، فسيتم تمكين البروتوكول. يسمح لك هذا بتعطيل جميع البروتوكولات مؤقتًا باستثناء قائمة بالاستثناءات. مثال: --disable-protocol ALL --enable-protocol eth,ip

--enable-heuristic <short_name>

تمكين تشخيص البروتوكول الاستدلالي.

-K <keytab>

تحميل مفاتيح تشفير Kerberos من ملف keytab المحدد. يمكن استخدام هذا الخيار عدة مرات لتحميل المفاتيح من ملفات متعددة.

مثال: -K krb5.keytab

-n

تعطيل تحليل أسماء الكائنات الشبكية (مثل اسم المضيف، وأسماء منافذ TCP و UDP)؛ قد يتجاوز الخيار -N هذا الخيار.

-N <name resolving flags>

تشغيل تحليل الأسماء فقط لأنواع معينة من العناوين وأرقام المنافذ، مع تعطيل تحليل الأسماء لأنواع أخرى من العناوين وأرقام المنافذ. يمكن تحديد هذا الخيار (جنبًا إلى جنب مع -n) عدة مرات؛ القيمة الأخيرة المعطاة تتجاوز القيم السابقة. يتجاوز هذا الخيار و -n الخيارات من التفضيلات، بما في ذلك التفضيلات التي تم تعيينها عبر الخيار -o. إذا لم يتم تقديم كل من خيار -N وخيار -n، يتم استخدام القيم من التفضيلات، والتي تكون افتراضيًا -N dmN.

الوسيطة عبارة عن سلسلة يمكن أن تحتوي على الأحرف:

d لتمكين التحليل من حزم DNS الملتقطة

g لتمكين البحث عن معلومات تحديد الموقع الجغرافي لعناوين IP من قواعد بيانات MaxMind المهيأة

m لتمكين تحليل عناوين MAC

n لتمكين تحليل عناوين الشبكة

N لتمكين استخدام محللات خارجية (مثل DNS) لتحليل عناوين الشبكة؛ لا تأثير بدون تمكين n أيضًا.

s لتمكين تحليل العناوين باستخدام معلومات SNI الموجودة في حزم المصافحة الملتقطة

t لتمكين تحليل أرقام منافذ طبقة النقل

v لتمكين تحليل معرفات VLAN إلى أسماء


تحذير

في وضع tshark أحادي المراحل، يتم إجراء التحليل الخارجي
والبحث الجغرافي بشكل متزامن. بالنسبة للالتقاطات المباشرة، والتي تكون دائمًا في وضع أحادي المراحل، هذا يجعل من الصعب على التشخيص مواكبة شبكة مزدحمة، مما قد يؤدي إلى إسقاط الحزم.

--only-protocols <protocols>

قم بتمكين تشخيص هذه البروتوكولات فقط، مفصولة بفاصلة. عطّل كل شيء آخر.

-t (a|ad|adoy|d|dd|e|r|u|ud|udoy)[.[N]]|.[N]

قم بتعيين تنسيق الطابع الزمني للحزمة المعروض في العمود الزمني الافتراضي. يمكن أن يكون التنسيق واحدًا مما يلي:

a مطلق: الوقت المطلق، بالوقت المحلي في منطقتك الزمنية، هو الوقت الفعلي الذي تم فيه التقاط الحزمة، بدون عرض التاريخ

ad مطلق مع التاريخ: التاريخ المطلق، معروض بتنسيق YYYY-MM-DD، والوقت، بالوقت المحلي في منطقتك الزمنية، هو الوقت والتاريخ الفعليان اللذان تم فيهما التقاط الحزمة

adoy مطلق مع التاريخ باستخدام يوم السنة: التاريخ المطلق، معروض بتنسيق YYYY/DOY، والوقت، بالوقت المحلي في منطقتك الزمنية، هو الوقت والتاريخ الفعليان اللذان تم فيهما التقاط الحزمة

d دلتا: وقت الدلتا هو الوقت منذ التقاط الحزمة السابقة

dd دلتا_المعروضة: وقت الدلتا_المعروضة هو الوقت منذ عرض الحزمة السابقة

e حقبة: الوقت بالثواني منذ حقبة (1 يناير 1970 00:00:00)

r نسبي: الوقت النسبي هو الوقت المنقضي بين الحزمة الأولى والحزمة الحالية

u UTC: الوقت المطلق، بصيغة UTC مع لاحقة "Z"، هو الوقت الفعلي الذي تم فيه التقاط الحزمة، بدون عرض التاريخ

ud UTC مع التاريخ: التاريخ المطلق، معروض بتنسيق YYYY-MM-DD، والوقت، بصيغة UTC مع لاحقة "Z"، هو الوقت والتاريخ الفعليان اللذان تم فيهما التقاط الحزمة

udoy UTC مع التاريخ باستخدام يوم السنة: التاريخ المطلق، معروض بتنسيق YYYY/DOY، والوقت، بصيغة UTC مع لاحقة "Z"، هو الوقت والتاريخ الفعليان اللذان تم فيهما التقاط الحزمة

.[N] تعيين الدقة: N هو عدد المنازل العشرية (من 0 إلى 9). إذا تم استخدام "." بدون N، يتم تحديد الدقة تلقائيًا من المسار.

التنسيق الافتراضي هو نسبي مع دقة تعتمد على تنسيق التقاط.

-u <s|hms>

يحدد كيفية عرض تنسيقات الطابع الزمني للحزم في -t التي هي أوقات نسبية (أي، نسبي، دلتا، ودلتا_معروضة). الخيارات الصالحة هي:

s للثواني

hms للساعات والدقائق والثواني

التنسيق الافتراضي هو الثواني.

خيارات التشخيص

--log-level <level>

قم بتعيين مستوى التسجيل النشط. المستويات المدعومة بترتيب من الأدنى إلى الأعلى هي "noisy"، "debug"، "info"، "message"، "warning"، "critical"، و "error". سيتم طباعة الرسائل عند كل مستوى وما فوق، على سبيل المثال "warning" تطبع رسائل "warning"، "critical"، و "error"، و "noisy" تطبع جميع الرسائل. المستويات غير حساسة لحالة الأحرف.

--log-fatal <level>

قم بإنهاء البرنامج إذا تم تسجيل أي رسائل بالمستوى المحدد أو أعلى. على سبيل المثال، "warning" ينهي عند أي رسائل "warning" أو "critical" أو "error".

--log-domains <list>

طباعة الرسائل فقط لمجالات السجل المحددة، على سبيل المثال "GUI,Epan,sshdump". يجب أن تكون قائمة المجالات مفصولة بفاصلة. يمكن نفيها بالحرف "!" كأول حرف (يعكس المطابقة).

--log-debug <list>

فرض على المجالات المحددة لتسجيل مستوى "debug". يجب أن تكون قائمة المجالات مفصولة بفاصلة. يمكن نفيها بالحرف "!" كأول حرف (يعكس المطابقة).

--log-noisy <list>

فرض على المجالات المحددة لتسجيل مستوى "noisy". يجب أن تكون قائمة المجالات مفصولة بفاصلة. يمكن نفيها بالحرف "!" كأول حرف (يعكس المطابقة).

--log-fatal-domains <list>

قم بإنهاء البرنامج إذا تم تسجيل أي رسائل لمجالات السجل المحددة. يجب أن تكون قائمة المجالات مفصولة بفاصلة.

ملفات ipxnets)

تُستخدم ملفات ipxnets لربط أرقام شبكات IPX المكونة من 4 بايت بالأسماء. أولاً، تتم محاولة البحث في ملف ipxnets العام، وإذا لم يتم العثور على العنوان هناك، فسيتم محاولة البحث في الملف الشخصي.

التنسيق هو نفسه ملف ethers، باستثناء أن كل عنوان هو أربعة بايت بدلاً من ستة. بالإضافة إلى ذلك، يمكن تمثيل العنوان كرقم سداسي عشري واحد، وهو أمر شائع في عالم IPX، بدلاً من أربعة ثمانيات سداسية عشرية. على سبيل المثال، هذه الأسطر الأربعة هي أسطر صالحة لملف ipxnets:

C0.A8.2C.00              HR
c0-a8-1c-00              CEO
00:00:BE:EF              IT_Server1
110f                     FileServer3

يتم البحث عن ملف ipxnets العام في الدليل /etc على الأنظمة المتوافقة مع UNIX، مثل Linux و macOS و \*BSD و Solaris و AIX، وفي دليل التثبيت الرئيسي (على سبيل المثال، C:\Program Files\Wireshark) على أنظمة Windows.

يتم البحث عن ملف ipxnets الشخصي في نفس الدليل الموجود به ملف التفضيلات الشخصي.

ترجمة الأسماء (ss7pcs)

يُستخدم ملف ss7pcs لترجمة رموز نقاط SS7 إلى أسماء. يتم قراءته من دليل التكوين الشخصي.

يتكون كل سطر في هذا الملف من مؤشر شبكة واحد متبوعًا بشرطة متبوعة برمز نقطة بالنظام العشري واسم عقدة مفصولة بمسافات بيضاء. مثال:

2-1234 MyPointCode1

ترجمة الأسماء (vlans)

يُستخدم ملف vlans لترجمة معرفات علامات VLAN إلى أسماء. يتم قراءته من دليل التكوين الشخصي.

يتكون كل سطر في هذا الملف من معرف علامة VLAN واحد مفصول بمسافات بيضاء عن اسم. مثال:

123    Server-Lan
2049   HR-Client-LAN

مرشحات الألوان (قواعد التلوين)

تحتوي ملفات colorfilters على مرشحات ألوان على مستوى النظام والمرشحات الشخصية. يحتوي كل سطر على مرشح واحد، يبدأ بالسلسلة النصية المعروضة في مربع الحوار، متبوعًا بمرشح العرض المقابل. ثم يتم إضافة ألوان الخلفية والمقدمة:

# تعليق
@tcp@tcp@[59345,58980,65534][0,0,0]
@udp@udp@[28834,57427,65533][0,0,0]

يستخدم ملف colorfilters العام نفس دليل ملف التفضيلات العام.

يستخدم ملف colorfilters الشخصي نفس دليل ملف التفضيلات الشخصي. يتم كتابته من خلال مربع الحوار View:Coloring Rules.

إذا كان ملف colorfilters العام موجودًا، فسيتم استخدامه فقط إذا لم يكن ملف colorfilters الشخصي موجودًا؛ لا يتم دمج مرشحات الألوان العامة والشخصية.

الإضافات (Plugins)

يبحث Wireshark عن الإضافات في مجلد إضافة شخصي ومجلد إضافة عام.

على الأنظمة المتوافقة مع UNIX، مثل Linux و macOS و \*BSD و Solaris و AIX، يكون دليل الإضافات العام هو lib/wireshark/plugins/ (في بعض الأنظمة يتم استبدال lib64 بـ lib) تحت دليل التثبيت الرئيسي (على سبيل المثال، /usr/local/lib/wireshark/plugins/). دليل الإضافات الشخصي هو $HOME/.local/lib/wireshark/plugins.

على macOS، إذا تم تثبيت Wireshark كحزمة تطبيق، يكون مجلد الإضافات العام بدلاً من ذلك %APPDIR%/Contents/PlugIns/wireshark.

على Windows، يكون مجلد الإضافات العام هو plugins/ تحت دليل التثبيت الرئيسي (على سبيل المثال، C:\Program Files\Wireshark\plugins\). مجلد الإضافات الشخصي هو %APPDATA%\Wireshark\plugins (أو، إذا لم يكن %APPDATA% محددًا، %USERPROFILE%\Application Data\Wireshark\plugins).

يتم تخزين إضافات Lua في مجلدات الإضافات؛ يتم تخزين الإضافات المترجمة في مجلدات فرعية من مجلدات الإضافات، واسم المجلد الفرعي هو رقم الإصدار الثانوي لـ Wireshark (X.Y). يوجد مستوى هرمي آخر لكل نوع من أنواع إضافات Wireshark (libwireshark، libwiretap، و codecs). على سبيل المثال، سيكون موقع إضافة libwireshark foo.so (foo.dll على Windows) هو PLUGINDIR/X.Y/epan (كان libwireshark يسمى libepan؛ المجلدات الأخرى هي codecs و wiretap).


ملاحظة

على الأنظمة المتوافقة مع UNIX، يمكن أيضًا وضع إضافات Lua (ولكن ليس الإضافات الثنائية) في $XDG_CONFIG_HOME/wireshark/plugins، (أو، إذا لم يكن $XDG_CONFIG_HOME/wireshark موجودًا بينما $HOME/.wireshark موجودًا، $HOME/.wireshark/plugins.)

لاحظ أن وحدة إضافة محلل قد تدعم أكثر من بروتوكول واحد؛ لا يوجد بالضرورة تطابق واحد لواحد بين وحدات إضافة المحلل والبروتوكولات. يتم تمكين وتعطيل البروتوكولات التي تدعمها وحدة إضافة المحلل بنفس الطريقة التي يتم بها تمكين وتعطيل البروتوكولات المدمجة في Wireshark.

الإخراج

يستخدم TShark UTF-8 لتمثيل السلاسل النصية داخليًا. في بعض الحالات، قد لا يكون الإخراج صالحًا. على سبيل المثال، قد يقوم محلل بإنشاء تسلسلات أحرف UTF-8 غير صالحة. يجب أن تتوقع البرامج التي تقرأ إخراج TShark UTF-8 وأن تكون مستعدة للإخراج غير الصالح.

إذا اكتشف TShark أنه يكتب إلى TTY على نظام متوافق مع UNIX، مثل Linux و macOS و \*BSD و Solaris و AIX، ولا يدعم الإعداد المحلي UTF-8، فسيتم إعادة ترميز الإخراج ليتناسب مع الإعداد المحلي الحالي.

إذا اكتشف TShark أنه يكتب إلى وحدة التحكم على Windows، فسيتم ترميز إخراج التحليل كـ UTF-16LE. ستكون المخرجات الأخرى UTF-8. إذا لم يتم عرض الأحرف الممتدة بشكل صحيح في طرفيتك، فقد تحاول تعيين صفحة رمز وحدة التحكم الخاصة بك إلى UTF-8 (chcp 65001) واستخدام تطبيق طرفية حديث إن أمكن.

متغيرات البيئة

WIRESHARK_CONFIG_DIR

يتجاوز متغير البيئة هذا موقع ملفات التكوين الشخصية. على الأنظمة المتوافقة مع UNIX، مثل Linux و macOS و \*BSD و Solaris و AIX، يكون الافتراضي هو $XDG_CONFIG_HOME/wireshark (أو، إذا لم يكن هذا الدليل موجودًا ولكن $HOME/.wireshark موجودًا، $HOME/.wireshark)؛ عادةً ما يكون هذا $HOME/.config/wireshark. على Windows، يكون الافتراضي هو %APPDATA%\Wireshark (أو، إذا لم يكن %APPDATA% محددًا، %USERPROFILE%\Application Data\Wireshark). متاح منذ Wireshark 3.0.

WIRESHARK_DEBUG_WMEM_OVERRIDE

يجبر تعيين متغير البيئة هذا إطار عمل wmem على استخدام مخصص المخصص المحدد لـ جميع التخصيصات، بغض النظر عن المخصص الذي يتم تحديده عادةً بواسطة الكود. هذا مفيد بشكل أساسي للمطورين عند الاختبار أو التصحيح. راجع README.wmem في توزيع المصدر للحصول على التفاصيل.

WIRESHARK_RUN_FROM_BUILD_DIRECTORY

يتسبب متغير البيئة هذا في تحميل الإضافات وملفات البيانات الأخرى من دليل البناء (حيث تم تجميع البرنامج) بدلاً من المواقع القياسية. ليس له أي تأثير عندما يعمل البرنامج المعني بأذونات الجذر (أو setuid) على الأنظمة المتوافقة مع UNIX، مثل Linux و macOS و \*BSD و Solaris و AIX.

WIRESHARK_DATA_DIR

يتسبب متغير البيئة هذا في تحميل ملفات البيانات المختلفة من دليل مختلف عن المواقع القياسية. ليس له أي تأثير عندما يعمل البرنامج المعني بأذونات الجذر (أو setuid) على الأنظمة المتوافقة مع UNIX.

WIRESHARK_EXTCAP_DIR

يتسبب متغير البيئة هذا في تشغيل برامج ونصوص extcap المختلفة من دليل مختلف عن المواقع القياسية. ليس له أي تأثير عندما يعمل البرنامج المعني بأذونات الجذر (أو setuid) على الأنظمة المتوافقة مع UNIX.

WIRESHARK_PLUGIN_DIR

يتسبب متغير البيئة هذا في تحميل الإضافات المختلفة من دليل مختلف عن المواقع القياسية. ليس له أي تأثير عندما يعمل البرنامج المعني بأذونات الجذر (أو setuid) على الأنظمة المتوافقة مع UNIX.

ERF_RECORDS_TO_CHECK

يتحكم متغير البيئة هذا في عدد سجلات ERF التي يتم فحصها عند تحديد ما إذا كان الملف هو بتنسيق ERF حقًا. سيؤدي تعيين متغير البيئة هذا إلى رقم أعلى من الافتراضي (20) إلى تقليل احتمالية الإيجابيات الخاطئة.

IPFIX_RECORDS_TO_CHECK

يتحكم متغير البيئة هذا في عدد سجلات IPFIX التي يتم فحصها عند تحديد ما إذا كان الملف هو بتنسيق IPFIX حقًا. سيؤدي تعيين متغير البيئة هذا إلى رقم أعلى من الافتراضي (20) إلى تقليل احتمالية الإيجابيات الخاطئة.

WIRESHARK_ABORT_ON_DISSECTOR_BUG

NAME

tshark - TShark is the command-line version of Wireshark

SYNOPSIS

tshark [-i interface] [-f capture_filter] [-F capture_format] [-r file] [-w file] [-V] [-T pdml|psml|json|text|fields] [-P] [-x] [display_filter]

DESCRIPTION

TShark is a network protocol analyzer. It lets you capture live packet data from a live network, or read packets from a previously saved capture file, and displays that packet data in a detailed way that includes protocol information. The TShark executable is part of the Wireshark distribution.

The primary purpose of TShark is to allow filtering and displaying packets on systems where Wireshark cannot be run, or where command-line operation is preferred.

TShark can read packet data from a live network interface or from a saved packet file. The packet display can be controlled by a display filter expression. Packet capture can be controlled by a capture filter expression.

The packet data can be written to a file in various formats.

OPTIONS

The full set of command line options is available by running tshark -h.

-i interface

Set the network interface to listen on. This option can be repeated to listen on multiple interfaces.

-f capture_filter

Set the capture filter expression. This uses the same syntax as tcpdump(8) and pcap-filter(7).

-F capture_format

Set the capture file format. The default is "pcap". Other formats include "pcapng", "snoop", "erf", "ipfix", "netmon", and "pcap-ng".

-r file

Read packets from file instead of a live network interface.

-w file

Write the raw packet data, not filtered by capture or display filters, to file instead of dissecting and displaying them. This is useful for saving capture data for later analysis.

-V

In addition to the default output, print a detailed dissection of the packet.

-T pdml|psml|json|text|fields

Set the output format of the packet listing. Default is "psml".

-P

Print packet lengths and timestamps in the default output. Implies "-T psml" if no output format is specified.

-x

In addition to the default output, print a detailed dissection of the packet in both hex and ASCII.

DISSECTION OPTIONS

-d [protocol=value,...]

Enable or disable dissectors. For example, -d ip.addr=1.2.3.4 enables the IP dissector for packets with the source or destination IP address 1.2.3.4. -d ip.addr!=1.2.3.4 disables the IP dissector for packets with the source or destination IP address 1.2.3.4. A list of dissectors can be obtained by running tshark -G dissectors.

-g [filter,...]

Set the capture filter. This uses the same syntax as tcpdump(8) and pcap-filter(7).

-j [filter,...]

Set the read filter. This uses the same syntax as pcap-filter(7).

-J [filter,...]

Set the display filter. This uses the same syntax as pcap-filter(7).

DIAGNOSTIC OPTIONS

-v

Print the version information and exit.

-h

Print the command-line options and exit.

CAPTURE FILTER SYNTAX

See pcap-filter(7) for a description of the capture filter syntax.

READ FILTER SYNTAX

See pcap-filter(7) for a description of the read filter syntax.

OUTPUT

The output format can be one of the following:

pdml
Packet Data Markup Language. An XML format for packet data.
psml
Packet Summary Markup Language. An XML format for packet summaries.
json
JavaScript Object Notation. A text format for packet data.
text
Plain text format.
fields
A comma-separated list of fields.

ENVIRONMENT VARIABLES

The behavior of TShark can be affected by the following environment variables:

WIRESHARK_LOG_MASK

A list of domains to enable for logging. If set, only the included domains will be enabled. The default domain is always considered to be enabled. Domain filter lists can be preceded by '!' to invert the sense of the match.

WIRESHARK_LOG_DEBUG

List of domains with debug log level. This sets the level of the provided log domains and takes precedence over the active domains filter. If preceded by '!' this disables the debug level instead.

WIRESHARK_LOG_NOISY

Same as above but for noisy log level instead.
