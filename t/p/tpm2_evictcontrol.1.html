tpm2_evictcontrol(1) دليل الأوامر العامة tpm2_evictcontrol(1)

الاسم

tpm2_evictcontrol(1) - اجعل كائنًا عابرًا دائمًا أو قم بإلغاء الكائن الدائم.

الملخص

tpm2_evictcontrol [خيارات] [وسيط]

الوصف

tpm2_evictcontrol(1) - يسمح بجعل الكائن العابر دائمًا أو إلغاء الكائن الدائم. يتحكم الوسيط HANDLE في الفهرس الذي سيتم تعيينه للمقبض. إذا كان الكائن المحدد عبر -c عابرًا، وتم تحديد HANDLE دائم، فسيتم جعل الكائن دائمًا عند HANDLE. إذا كان HANDLE هو -، فسيتم جعل الكائن دائمًا في أول موقع مقبض دائم متاح. إذا كان الكائن المحدد عبر -c مقبضًا دائمًا، فسيتم إلغاء الكائن من موقع المقبض الدائم الخاص به.

الخيارات

•
-C, --hierarchy=OBJECT:

التسلسل الهرمي للتفويض المستخدم لتفويض الأوامر. الافتراضي هو تسلسل المالك الهرمي. الخيارات المدعومة هي:

•
o لـ TPM_RH_OWNER
•
p لـ TPM_RH_PLATFORM
•
<رقم> حيث يمكن استخدام رقم خام.
•
-c, --object-context=OBJECT:

محدد سياق كائن، سواء كان مقبضًا أو اسم ملف. إذا كان OBJECT كائنًا عابرًا، فسيتم جعله دائمًا، إما في المقبض المحدد بالوسيط أو في أول مقبض دائم شاغر متاح. إذا كان OBJECT لكائن دائم، فسيتم إلغاء الكائن من الذاكرة غير المتطايرة.

•
-P, --auth=AUTH:

قيمة التفويض للتسلسل الهرمي المحدد مع -C.

•
-o, --output=FILE:

اختياريًا، قم بإخراج كائن متسلسل يمثل المقبض الدائم. إذا لم يتم العبث بها، فإن هذه الملفات أكثر أمانًا للاستخدام من المقابض الدائمة الخام. يجب التحقق من المقبض الدائم الخام للتأكد من أن الكائن الذي يشير إليه هو كما هو متوقع.

•
--cphash=FILE

مسار الملف لتسجيل تجزئة معلمات الأمر. يُطلق على هذا عادةً اسم cpHash. ملاحظة: عند تحديد هذا الخيار، لن يقوم الأداة بتنفيذ الأمر فعليًا، بل ستعيد ببساطة cpHash.

•
ARGUMENT يحدد وسيط سطر الأوامر المقبض الدائم لحفظ الكائن العابر إليه.

الإخراج

يخرج الأداة قاموسًا متوافقًا مع YAML مع الحقول: persistent-handle: action: evicted|persisted

حيث persistent-handle هو المقبض الذي حدث فيه الإجراء. حيث action يمكن أن يكون إما evicted (تم إلغاؤه) أو persisted (تم جعله دائمًا). إذا تم evicted (إلغاء) كائن، فلن يكون الكائن موجودًا بعد الآن في عنوان persistent-handle داخل TPM. إذا تم persisted (جعله دائمًا) كائن، فسيتم توطين الكائن في عنوان persistent-handle داخل TPM.

المراجع

صيغة كائن السياق

يتم تحديد نوع كائن السياق، سواء كان مقبضًا أو اسم ملف، وفقًا للمنطق التالي بالترتيب:

•
إذا كان الوسيط مسار ملف، فسيتم تحميل الملف ككائن TPM عابر مستعاد.
•
إذا كان الوسيط تطابقًا بادئة لأحد:
•
owner: التسلسل الهرمي للمالك
•
platform: التسلسل الهرمي للمنصة
•
endorsement: التسلسل الهرمي للمصادقة
•
lockout: الكائن الدائم للتحكم في القفل
•
إذا كان الوسيط يمكن تحميله كرقم، فسيتم اعتباره مقبضًا، مثل 0x81010013 وسيتم استخدامه مباشرة._OBJECT_.

صيغة التفويض

يمكن أن يأتي التفويض لاستخدام كائن في TPM2.0 في 3 أشكال مختلفة: 1. كلمة المرور 2. HMAC 3. الجلسات

ملاحظة: "تكون التفويضات افتراضية إلى كلمة المرور الفارغة عند عدم تحديدها."

كلمات المرور

يتم تفسير كلمات المرور في الأشكال التالية أدناه باستخدام معرفات بادئة.

ملاحظة: افتراضيًا، يُفترض أن تكون كلمات المرور في شكل سلسلة نصية عندما لا تحتوي على بادئة.

سلسلة نصية

كلمة مرور كسلسلة نصية، محددة بالبادئة "str:" أو عدم وجودها (سلسلة خام بدون بادئة) لا يتم تفسيرها، ويتم استخدامها مباشرة للتفويض.

أمثلة

foobar
str:foobar

سلسلة سداسية عشرية

كلمة مرور كسلسلة سداسية عشرية، محددة بالبادئة "hex:" يتم تحويلها من شكل سداسي عشري إلى شكل مصفوفة بايت، مما يسمح بكلمات مرور تحتوي على أحرف غير قابلة للطباعة و/أو غير ودية للطرفية.

مثال

hex:1122334455667788

ملف

كلمة مرور مستندة إلى ملف، محددة بالبادئة "file:" يجب أن تكون مسار ملف يحتوي على كلمة المرور التي سيقرأها الأداة أو "-" لاستخدام stdin. يمنع تخزين كلمات المرور في الملفات تسرب المعلومات، وكلمات المرور المقدمة كخيارات يمكن قراءتها من قائمة العمليات أو ميزات سجل الأوامر الشائعة.

أمثلة

# لاستخدام stdin والمطالبة
file:-
# لاستخدام ملف من مسار
file:path/to/password/file
# لإرسال كلمة مرور عبر stdin:
echo foobar | tpm2_tool -p file:-
# لاستخدام bash here-string عبر stdin:
tpm2_tool -p file:- <<< foobar

الجلسات

عند استخدام جلسة سياسة لتفويض استخدام كائن، قم بإنهاء الوسيط الخيار بالكلمة المفتاحية session. ثم حدد مسارًا لملف جلسة تم إنشاؤه باستخدام tpm2_startauthsession(1). اختياريًا، إذا كانت الجلسة تتطلب قيمة auth ليتم إرسالها مع مقبض الجلسة (مثل كلمة مرور سياسة)، فقم بإلحاق + وسلسلة نصية كما هو موضح في قسم كلمات المرور.

أمثلة

لاستخدام ملف سياق جلسة يسمى session.ctx.

session:session.ctx

لاستخدام ملف سياق جلسة يسمى session.ctx و إرسال قيمة المصادقة mypassword.

session:session.ctx+mypassword

لاستخدام ملف سياق جلسة يسمى session.ctx و إرسال قيمة المصادقة السداسية العشرية 0x11223344.

session:session.ctx+hex:11223344

تفويضات PCR

يمكنك تلبية سياسة PCR باستخدام البادئة "pcr:" واللغة المصغرة لـ PCR. اللغة المصغرة لـ PCR هي كما يلي: <pcr-spec>=<raw-pcr-file>

tpm2_evictcontrol(8) — tpm2-tools — Arch Linux

NAME

tpm2_evictcontrol — make a PCR bank volatile and clear it.

SYNOPSIS

tpm2_evictcontrol [OPTIONS] [ARGUMENTS]

DESCRIPTION

The tpm2_evictcontrol command is used to make a PCR bank volatile and clear it. This command is part of the TPM2 Access Broker (TAB) protocol and is used to manage persistent storage of TPM objects.

The TPM specification defines PCRs (Platform Configuration Registers) that are used to store platform state information. PCR banks are used to group PCRs, typically by hashing algorithm. This command can be used to evict (remove) a persistent handle, effectively making it non-persistent and clearing its associated data.

PCR bank specifiers

PCR bank specifiers are used to identify the PCR banks that the command should operate on. The PCR spec is documented in the section “PCR bank specifiers”.

The raw-pcr-file is an optional argument that contains the output of the raw PCR contents as returned by tpm2_pcrread(1).

PCR bank specifiers

Examples

To satisfy a PCR policy of sha256 on banks 0, 1, 2 and 3 use a specifier of:

pcr:sha256:0,1,2,3

specifying AUTH.

TCTI Configuration

The TCTI or “Transmission Interface” is the communication mechanism with the TPM. TCTIs can be changed for communication with TPMs across different mediums.

To control the TCTI, the tools respect:

1.
The command line option -T or --tcti
2.
The environment variable: TPM2TOOLS_TCTI.

Note: The command line option always overrides the environment variable.

The current known TCTIs are:

•
tabrmd - The resource manager, called tabrmd. Note that tabrmd and abrmd as a tcti name are synonymous.
•
mssim - Typically used for communicating to the TPM software simulator.
•
device - Used when talking directly to a TPM device file.
•
none - Do not initalize a connection with the TPM. Some tools allow for off-tpm options and thus support not using a TCTI. Tools that do not support it will error when attempted to be used without a TCTI connection. Does not support ANY options and MUST BE presented as the exact text of “none”.

The arguments to either the command line option or the environment variable are in the form:

<tcti-name>:<tcti-option-config>

Specifying an empty string for either the <tcti-name> or <tcti-option-config> results in the default being used for that portion respectively.

TCTI Defaults

When a TCTI is not specified, the default TCTI is searched for using dlopen(3) semantics. The tools will search for tabrmd, device and mssim TCTIs IN THAT ORDER and USE THE FIRST ONE FOUND. You can query what TCTI will be chosen as the default by using the -v option to print the version information. The “default-tcti” key-value pair will indicate which of the aforementioned TCTIs is the default.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

EXAMPLES

To make a transient handle persistent at address 0x81010002

tpm2_changeauth -c o ownerauth
tpm2_createprimary -c primary.ctx -P ownerauth
tpm2_evictcontrol -C o -c primary.ctx 0x81010002 -P ownerauth

To evict a persistent handle

tpm2_evictcontrol -C o -c 0x81010002 -P ownerauth

To make a transient handle persistent and output a serialized persistent handle.

tpm2_evictcontrol -C o -c primary.ctx -o primary.handle -P ownerauth
