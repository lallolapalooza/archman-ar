الحزمة: tpm2-tools

tpm2_policyauthorize(1) دليل الأوامر العامة tpm2_policyauthorize(1)

الاسم

tpm2_policyauthorize(1) - يسمح بسياسات قابلة للتعديل عن طريق الربط بسلطة توقيع.

ملخص

tpm2_policyauthorize [خيارات]

الوصف

tpm2_policyauthorize(1) - هذا الأمر يسمح بتغيير السياسات عن طريق ربط السياسة بسلطة توقيع والسماح بتغيير محتويات السياسة.

1.
إذا كانت الجلسة المدخلة جلسة تجريبية، فإن هذه الأداة تولد هضم سياسة يربط اسم المفتاح العام لسلطة التوقيع بالسياسة التي يتم تفويضها.
2.
إذا كانت الجلسة المدخلة جلسة سياسة حقيقية، فإن tpm2_policyauthorize(1) يبحث عن تذكرة تحقق من TPM للتأكيد على أن TPM قد تحقق من التوقيع على هضم السياسة قبل تفويض السياسة في هضم السياسة.

خيارات

•
-L, --policy=ملف:

ملف لحفظ هضم السياسة.

•
-S, --session=ملف:

ملف جلسة السياسة الذي تم إنشاؤه عبر الخيار -S لـ tpm2_startauthsession(1).

•
-i, --input=ملف:

هضم السياسة الذي يجب تفويضه.

•
-q, --qualification=ملف_أو_ست عشري:

بيانات مؤهلات السياسة التي تم توقيعها بالاقتران مع هضم السياسة المدخلة. هذه بيانات فريدة يمكن للموقّع اختيار تضمينها في التوقيع ويمكن أن تكون إما مسارًا أو سلسلة ست عشرية.

•
-n, --name=ملف:

ملف يحتوي على اسم مفتاح التحقق العام. هذا يربط هضم السياسة النهائي بالموّقع. يمكن استرداد هذا باستخدام tpm2_readpublic(1)

•
-t, --ticket=ملف:

ملف التذكرة لتسجيل هيكل التحقق. يتم إنشاء هذا باستخدام tpm2_verifysignature(1).

•
--cphash=ملف

مسار الملف لتسجيل تجزئة معلمات الأمر. يُطلق على هذا غالبًا اسم cpHash. ملاحظة: عند تحديد هذا الخيار، لن تنفذ الأداة الأمر فعليًا، بل ستعيد ببساطة cpHash.

مراجع

خيارات مشتركة

هذه المجموعة من الخيارات شائعة في العديد من البرامج وتوفر معلومات قد يتوقعها العديد من المستخدمين.

•
-h, --help=[man|no-man]: عرض صفحة الدليل للأداة. افتراضيًا، تحاول استدعاء مستعرض الدليل للأداة، ولكن في حالة الفشل، ستعرض ملخصًا قصيرًا للأداة. هذا هو نفس السلوك إذا تم تحديد الوسيطة "man"، ومع ذلك، إذا تم طلب "man" صراحة، فستوفر الأداة أخطاء من man على stderr. إذا تم تحديد الخيار "no-man"، أو فشل مستعرض الدليل، فسيتم إخراج الخيارات القصيرة إلى stdout.

للاستخدام الناجح لميزة صفحات الدليل، يلزم تثبيت صفحات الدليل أو وجودها في MANPATH. راجع man(1) لمزيد من التفاصيل.

•
-v, --version: عرض معلومات الإصدار لهذه الأداة، و tctis المدعومة، والخروج.
•
-V, --verbose: زيادة المعلومات التي تطبعها الأداة على وحدة التحكم أثناء تنفيذها. عند استخدام هذا الخيار، تتم طباعة رقم الملف والسطر.
•
-Q, --quiet: كتم الإخراج العادي للأداة إلى stdout.
•
-Z, --enable-errata: تمكين تطبيق إصلاحات الأخطاء. مفيد إذا احتاجت إصلاحات الأخطاء إلى تطبيقها على الأوامر المرسلة إلى TPM. تحديد متغير البيئة TPM2TOOLS_ENABLE_ERRATA يعادل هذا.
•
-R, --autoflush: تمكين التفريغ التلقائي للكائنات المؤقتة التي أنشأتها الأداة. إذا تم تحميل كائن أب من ملف سياق، فسيتم أيضًا تفريغ الكائن الأب المؤقت. يمكن أيضًا تنشيط التفريغ التلقائي إذا كان متغير البيئة TPM2TOOLS_AUTOFLUSH مضبوطًا على yes أو true. معلومات قد يتوقعها العديد من المستخدمين.

تكوين TCTI

TCTI أو "واجهة النقل" هي آلية الاتصال بـ TPM. يمكن تغيير TCTIs للتواصل مع TPMs عبر وسائط مختلفة.

للتحكم في TCTI، تحترم الأدوات:

1.
خيار سطر الأوامر -T أو --tcti
2.
متغير البيئة: TPM2TOOLS_TCTI.

ملاحظة: يتجاوز خيار سطر الأوامر دائمًا متغير البيئة.

TCTIs المعروفة حاليًا هي:

•
tabrmd - مدير الموارد، يسمى tabrmd. لاحظ أن tabrmd و abrmd كاسم tcti مترادفان.
•
mssim - يستخدم عادة للتواصل مع محاكي برنامج TPM.
•
device - يستخدم عند التحدث مباشرة إلى ملف جهاز TPM.
•
none - لا تقم بتهيئة اتصال بـ TPM. تسمح بعض الأدوات بخيارات خارج TPM وبالتالي تدعم عدم استخدام TCTI. الأدوات التي لا تدعمها ستظهر خطأ عند محاولة استخدامها بدون اتصال TCTI. لا يدعم *أي* خيارات *ويجب* تقديمه كنص مطابق لـ "none".

الحجج إما لخيار سطر الأوامر أو لمتغير البيئة تكون بالشكل:

<اسم_tcti>:<تكوين_خيار_tcti>

تحديد سلسلة فارغة إما لـ <اسم_tcti> أو لـ <تكوين_خيار_tcti> يؤدي إلى استخدام الإعداد الافتراضي لكل جزء على التوالي.

إعدادات TCTI الافتراضية

عند عدم تحديد TCTI، يتم البحث عن TCTI الافتراضي باستخدام دلالات dlopen(3). ستبحث الأدوات عن TCTIs tabrmd و device و mssim بهذا الترتيب وتستخدم أول واحد تم العثور عليه. يمكنك الاستعلام عن TCTI الذي سيتم اختياره افتراضيًا باستخدام الخيار -v لطباعة معلومات الإصدار. سيشير زوج المفتاح والقيمة "default-tcti" إلى أي من TCTIs المذكورة أعلاه هو الافتراضي.

TCTIs المخصصة

يمكن تحميل أي TCTI يطبق واجهة TCTI الديناميكية. تستخدم الأدوات داخليًا dlopen(3)، ويتم استخدام قيمة اسم_tcti الخام للبحث. وبالتالي، يمكن أن يكون هذا مسارًا إلى المكتبة المشتركة، أو اسم مكتبة كما تفهمه دلالات dlopen(3).

خيارات TCTI

تُستخدم هذه المجموعة من الخيارات لتكوين وحدات TCTI المختلفة المتاحة:

•
device: بالنسبة لوحدة TCTI للجهاز، يمكن تحديد ملف جهاز TPM لاستخدامه بواسطة وحدة TCTI للجهاز. الافتراضي هو /dev/tpm0.

مثال: -T device:/dev/tpm0 أو export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: بالنسبة لوحدة TCTI mssim، يمكن تحديد اسم المجال أو عنوان IP ورقم المنفذ الذي يستخدمه المحاكي. الافتراضيات هي 127.0.0.1 و 2321.

مثال: -T mssim:host=localhost,port=2321 أو <

tpm2_policyauthorize(1) — tpm2-tools — Manual Pages

SYNOPSIS

tpm2_policyauthorize [OPTIONS] -S SESSION -L POLICY_FILE -n NAME [-t TICKET_FILE] [-i POLICY_DIGEST]

DESCRIPTION

The tpm2_policyauthorize command extends the current policy session by extending the policy digest with the digest of the authorization policy associated with a named object.

This command is used to create policies that require specific authorization values to be met. An example use-case for this command is to create a policy that requires the user to present a valid signature from a specific key. The command tpm2_policyauthorize(1) allows you to define what that authorization policy is.

The command can be used to create a policy digest that may be used as an input to other policy commands. For example, tpm2_policyauthorize(1) can be used to set the policy digest in a session that is later used to create an object. When that object is used, the policy digest must be satisfied.

The digest of the policy, associated with the specified name (a TPM2_RH_AUTH_POLICY or similar object) will be added to the policy session. The TPM will check this when the session is used.

The command can also be used to produce a ticket which can be used to authorize the policy session. A ticket is a signed data structure that proves that a certain policy has been met.

OPTIONS

-S, --session=SESSION

Policy session context. This can be a file path to the session context file, or the tag `-` to read from stdin.

-L, --policy-file=POLICY_FILE

Path to a file where the policy digest will be written.

-n, --name=NAME

The Name of the object that the policy is associated with. The name is a hexadecimal string representation of the TPM Name structure.

-t, --ticket-file=TICKET_FILE

Path to a file where the ticket will be written.

-i, --policy-digest=POLICY_DIGEST

Input policy digest. This is the digest of the policy that is being authorized. If this option is not provided, the digest will be read from stdin.

-f, --format=FMT

The format of the policy digest, default is `raw`.

-g, --hash-algorithm=ALG

The hash algorithm for the policy digest. Default: `sha256`.

--auth-session

Auth session. This option is used to indicate that the session is an authorization session. This means that the session is not a policy session.

-h, --help

Help information.

-v, --version

Print program version and exit.

COMMON OPTIONS

See tpm2_options(7) for common options that can be used with this command.

TCTI Configuration

The TPM Communication Interface (TCTI) is used to communicate with the TPM. The following TCTI modules are available:

  • mssim: simulator TCTI
  • tabrmd: resource manager TCTI
  • abrmd: resource manager TCTI

The TCTI can be specified using the TPM2TOOLS_TCTI environment variable or the -t, --tcti option. If both are specified, the command line option will take precedence.

•
TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

abrmd

For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,` character. Each key and value string are separated by a `=` character.

•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

EXAMPLES

Starts a trial session, builds a PCR policy. This PCR policy digest is then an input to the tpm2_policyauthorize(1) along with policy qualifier data and a signer public. The resultant policy digest is then used in creation of objects.

Subsequently when the PCR change and so does the PCR policy digest, the actual policy digest from the tpm2_policyauthorize(1) used in creation of the object will not change. At runtime the new PCR policy needs to be satisfied along with verification of the signature on the PCR policy digest using tpm2_policyauthorize(1)

Create a signing authority

openssl genrsa -out signing_key_private.pem 2048
openssl rsa -in signing_key_private.pem -out signing_key_public.pem -pubout
tpm2_loadexternal -G rsa -C o -u signing_key_public.pem -c signing_key.ctx -n signing_key.name

Create the authorize policy digest

tpm2_startauthsession -S session.ctx
tpm2_policyauthorize -S session.ctx -L authorized.policy -n signing_key.name
tpm2_flushcontext session.ctx

Create a policy to be authorized like a PCR policy

tpm2_pcrread -opcr0.sha256 sha256:0
tpm2_startauthsession -S session.ctx
tpm2_policypcr -S session.ctx -l sha256:0 -f pcr0.sha256 -L pcr.policy_desired
tpm2_flushcontext session.ctx

Sign the policy

openssl dgst -sha256 -sign signing_key_private.pem -out pcr.signature pcr.policy_desired

Create a TPM object like a sealing object with the authorized policy based authentication

tpm2_createprimary -C o -g sha256 -G rsa -c prim.ctx
tpm2_create -g sha256 -u sealing_pubkey.pub -r sealing_prikey.pub -i- -C prim.ctx -L authorized.policy <<< "secret to seal"

Verify the desired policy digest comes from the signing authority, read the actual value of PCR and check that read policy and desired policy are equal.

tpm2_verifysignature -c signing_key.ctx -g sha256 -m  pcr.policy_desired -s pcr.signature -t verification.tkt -f rsassa
tpm2_startauthsession \--policy-session -S session.ctx
tpm2_policypcr -S session.ctx -l sha256:0 -L pcr.policy_read
tpm2_policyauthorize -S session.ctx -L authorized.policy -i pcr.policy_desired -n signing_key.name -t verification.tkt
tpm2_load -C prim.ctx -u sealing_pubkey.pub -r sealing_prikey.pub -c sealing_key.ctx
unsealed=$(tpm2_unseal -p"session:session.ctx" -c sealing_key.ctx)
echo $unsealed
tpm2_flushcontext session.ctx

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.

Limitations

It expects a session to be already established via tpm2_startauthsession(1) and requires one of the following:

•
direct device access
•
extended session support with tpm2-abrmd.

Without it, most resource managers will not save session state between command invocations.
