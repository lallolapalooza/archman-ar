tpm2_policypassword(1) دليل الأوامر العام tpm2_policypassword(1)

الاسم

tpm2_policypassword(1) - تمكين ربط سياسة بقيمة التفويض لكائن TPM المصرح به.

الملخص

tpm2_policypassword [خيارات]

الوصف

tpm2_policypassword(1) - يمكّن سياسة تتطلب توفير عبارة مرور المصادقة الخاصة بالكائن. هذا يعادل المصادقة باستخدام عبارة مرور الكائن كنص عادي، فقط هذا يفرضها كسياسة. يوفر آلية للسماح بالمصادقة بكلمة المرور عندما يسمح الكائن فقط بتفويض قائم على السياسة، أي السمة الخاصة بالكائن "userwithauth" هي 0.

الخيارات

•
-L, --policy=FILE:

ملف لحفظ هضم السياسة المركب.

•
-S, --session=FILE:

ملف جلسة السياسة الذي تم إنشاؤه عبر الخيار -S لـ tpm2_startauthsession(1).

•
--cphash=FILE

مسار الملف لتسجيل تجزئة معلمات الأمر. هذا يسمى عادةً cpHash. ملاحظة: عند تحديد هذا الخيار، لن يقوم الأداة بتنفيذ الأمر فعليًا، بل سيعيد فقط cpHash.

-h, --help=[man|no-man]: عرض صفحة دليل الأداة. افتراضيًا، تحاول استدعاء عارض صفحات الدليل للأداة، ولكن عند الفشل، ستعرض ملخصًا قصيرًا للأداة. هذا هو نفس السلوك إذا تم تحديد الوسيطة "man" للخيار، ومع ذلك، إذا تم طلب "man" صراحةً، فستقدم الأداة أخطاء من man على stderr. إذا تم تحديد الوسيطة "no-man"، أو فشل عارض صفحات الدليل، فسيتم إخراج الخيارات القصيرة إلى stdout.

لاستخدام ميزة صفحات الدليل بنجاح، يلزم تثبيت صفحات الدليل أو وضعها في MANPATH. راجع man(1) لمزيد من التفاصيل.

•
-v, --version: عرض معلومات الإصدار لهذه الأداة، و tctis المدعومة والخروج.
•
-V, --verbose: زيادة المعلومات التي تطبعها الأداة إلى وحدة التحكم أثناء تنفيذها. عند استخدام هذا الخيار، يتم طباعة اسم الملف ورقم السطر.
•
-Q, --quiet: كتم الإخراج العادي للأداة إلى stdout.
•
-Z, --enable-errata: تمكين تطبيق إصلاحات الأخطاء. مفيد إذا احتاج إصلاح خطأ إلى تطبيقه على الأوامر المرسلة إلى TPM. تعريف متغير البيئة TPM2TOOLS_ENABLE_ERRATA يعادل ذلك.
•
-R, --autoflush: تمكين المسح التلقائي للكائنات المؤقتة التي تم إنشاؤها بواسطة الأمر. إذا تم تحميل كائن أصلي من ملف سياق، فسيتم أيضًا مسح الكائن الأصلي الوالد. يمكن أيضًا تنشيط المسح التلقائي إذا تم تعيين متغير البيئة TPM2TOOLS_AUTOFLUSH على "yes" أو "true".

تكوين TCTI

TCTI أو "واجهة النقل" هي آلية الاتصال مع TPM. يمكن تغيير TCTIs للاتصال بأجهزة TPM عبر وسائط مختلفة.

للتحكم في TCTI، تحترم الأدوات:

1.
خيار سطر الأوامر -T أو --tcti
2.
متغير البيئة: TPM2TOOLS_TCTI.

ملاحظة: يتجاوز خيار سطر الأوامر دائمًا متغير البيئة.

TCTIs المعروفة حاليًا هي:

•
tabrmd - مدير الموارد، المسمى tabrmd. ملاحظة أن tabrmd و abrmd كاسم tcti مترادفان.
•
mssim - يستخدم عادةً للاتصال بمحاكي برنامج TPM.
•
device - يستخدم عند التحدث مباشرة إلى ملف جهاز TPM.
•
none - لا تقم بتهيئة اتصال مع TPM. تسمح بعض الأدوات بخيارات خارج TPM وبالتالي تدعم عدم استخدام TCTI. الأدوات التي لا تدعمها ستعرض خطأ عند محاولة استخدامها بدون اتصال TCTI. لا تدعم أي خيارات ويجب تقديمها كنص "none" بالضبط.

تأتي وسائط إما خيار سطر الأوامر أو متغير البيئة بالشكل:

<tcti-name>:<tcti-option-config>

تحديد سلسلة فارغة إما لـ <tcti-name> أو <tcti-option-config> يؤدي إلى استخدام الافتراضي لذلك الجزء على التوالي.

افتراضات TCTI

عند عدم تحديد TCTI، يتم البحث عن TCTI الافتراضي باستخدام دلالات dlopen(3). ستبحث الأدوات عن TCTIs tabrmd، device، و mssim بهذا الترتيب وتستخدم أول واحد تم العثور عليه. يمكنك الاستعلام عن TCTI الذي سيتم اختياره كافتراضي باستخدام الخيار -v لعرض معلومات الإصدار. سيشير زوج المفتاح والقيمة "default-tcti" إلى أي من TCTIs المذكورة أعلاه هو الافتراضي.

TCTIs مخصصة

يمكن تحميل أي TCTI ينفذ واجهة TCTI الديناميكية. تستخدم الأدوات داخليًا dlopen(3)، ويتم استخدام قيمة tcti-name الخام للبحث. وبالتالي، يمكن أن يكون هذا مسارًا إلى المكتبة المشتركة، أو اسم مكتبة كما تفهمها دلالات dlopen(3).

خيارات TCTI

تُستخدم هذه المجموعة من الخيارات لتكوين وحدات TCTI المختلفة المتاحة:

•
device: بالنسبة لـ device TCTI، يمكن تحديد ملف جهاز TPM لاستخدامه بواسطة device TCTI. الافتراضي هو /dev/tpm0.

مثال: -T device:/dev/tpm0 أو export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: بالنسبة لـ mssim TCTI، يمكن تحديد اسم النطاق أو عنوان IP ورقم المنفذ الذي يستخدمه المحاكي. الافتراضي هو 127.0.0.1 و 2321.

مثال: -T mssim:host=localhost,port=2321 أو export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: بالنسبة لـ abrmd TCTI، يكون تنسيق سلسلة التكوين عبارة عن سلسلة من أزواج المفاتيح والقيم البسيطة مفصولة بحرف `,'. يتم فصل كل مفتاح وقيمة بسلسلة بحرف `= '.
•
يدعم TCTI abrmd مفتاحين:
1.
`bus_name': اسم خدمة tabrmd على الناقل (سلسلة).
2.
`bus_type': نوع مثيل dbus (سلسلة) محدود بـ `session' و `system'.

حدد اسم tcti tabrmd وسلسلة تكوين bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

حدد tcti الافتراضي (abrmd) وسلسلة تكوين bus_type=session:

\--tcti:bus_type=session

ملاحظة: abrmd و tabrmd مترادفان. وحدات TCTI المعروفة المختلفة.

tpm2_policypassword(1) — tpm2-tools documentation

NAME

tpm2_policypassword - Create a policy digest that requires a passphrase to be presented.

SYNOPSIS

tpm2_policypassword [OPTIONS]

DESCRIPTION

tpm2_policypassword is used to create a policy digest that requires a password (or a structure of passwords, as it is the case in this example) to be presented.

This command can be used in two ways:

  • Create a policy that requires a password: 
    tpm2_startauthsession -S session.dat
tpm2_policypassword -S session.dat -L policy.dat
tpm2_flushcontext session.dat
    This will create a policy digest in policy.dat. This policy can then be used with tpm2_create or tpm2_createprimary to create an object that is tied to this policy.
  • Authenticate with a password and a policy: 
    tpm2_startauthsession --policy-session -S session.dat
tpm2_policypassword -S session.dat -L policy.dat
tpm2_encryptdecrypt -c key.ctx -o encrypt.out \
  -p session:session.dat+testpswd plain.txt
tpm2_flushcontext session.dat
    This will load the policy, take the password and attach the policy session to the command. The command will then succeed if the password matches the one provided by the policy.

The policy digest for a password is a hash of the password, which can be obtained using the tpm2_hash command.

The password can be fed to the command using the -p option. The password can be specified directly or by reading it from a file.

The policy session is created using tpm2_startauthsession. The policy digest is created using tpm2_policypassword. The policy digest is then associated with the object using the -L option when creating the object. Finally, the object can be used for operations that require authentication, such as encryption or decryption.

To authenticate with the object, a session must be started again, the policy must be applied to the session, and then the password must be provided.

This example will show how to create an object with a passphrase and then authenticate with the object using the passphrase.

Create the password policy

tpm2_startauthsession -S session.dat
tpm2_policypassword -S session.dat -L policy.dat
tpm2_flushcontext session.dat

Create the object with a passphrase and the password policy

tpm2_createprimary -C o -c prim.ctx
tpm2_create -g sha256 -G aes -u key.pub -r key.priv -C prim.ctx -L policy.dat \
  -p testpswd

Authenticate with plaintext passphrase input

This example demonstrates how to authenticate using the TPM objects plaintext authentication value. While we could authenticate with an ephemeral password session, in this example we will authenticate with the plaintext passphrase in a policy session instead using the tpm2_policypassword(1) tool.

tpm2_load -C prim.ctx -u key.pub -r key.priv -n key.name -c key.ctx
echo "plaintext" > plain.txt
tpm2_encryptdecrypt -c key.ctx -o encrypt.out plain.txt -p testpswd plain.txt

Authenticate with password and the policy

tpm2_startauthsession \--policy-session -S session.dat
tpm2_policypassword -S session.dat -L policy.dat
tpm2_encryptdecrypt -c key.ctx -o encrypt.out \
  -p session:session.dat+testpswd plain.txt
tpm2_flushcontext session.dat

OPTIONS

The following options are available:

-S, --session=SESSION

The session file used to store the TPM session context. This is usually created using tpm2_startauthsession.

-L, --policy=POLICY

The file to store the policy digest.

-p, --password=PASSWORD

The password to be used in the policy. If the password is prefixed with `file:`, the password will be read from the specified file.

-q, --quiet

Suppresses output messages.

-Q, --very-quiet

Suppresses all output messages.

-V, --version

Prints the version number of the tool.

-h, --help

Prints the help message and exits.

COMMON OPTIONS

-c, --context=CONTEXT

Used to specify the TPM context file. This file is created by tools like tpm2_createprimary, tpm2_create, or tpm2_load.

-f, --force

Forces the operation to continue even if errors are encountered. This option should be used with caution.

-n, --name=NAME

The name of the object. This is typically generated by tpm2_createprimary or tpm2_create.

TCTI Configuration

The TPM Communication Interface (TCTI) is used to communicate with the TPM device. The default TCTI is usually the `mssim` TCTI, which is used for simulators. For actual hardware interaction, you might need to specify a different TCTI.

The TCTI can be configured using the environment variable TPM20_TCTI_CONFIG or via command-line options.

Example of setting the TCTI via environment variable:

export TPM20_TCTI_CONFIG=device

Or, using command-line options (if supported by the tool):

tpm2_policypassword --tcti=device ...

TCTI OPTIONS

The following TCTI options may be available, depending on the TCTI used:

--tcti-device=DEVICE

Specifies the TPM device path (e.g., `/dev/tpm0`).

--tcti-mssim=HOST:PORT

Specifies the host and port for the TPM simulator.

EXAMPLES

This section provides examples of how to use the tpm2_policypassword command.

Create the password policy

This command sequence creates a policy digest that requires a passphrase to be presented. The policy is stored in policy.dat.

tpm2_startauthsession -S session.dat
tpm2_policypassword -S session.dat -L policy.dat
tpm2_flushcontext session.dat

Create the object with a passphrase and the password policy

This sequence creates a primary key and then creates a new key under that primary key, which is associated with the policy created in the previous step. The passphrase used is testpswd.

tpm2_createprimary -C o -c prim.ctx
tpm2_create -g sha256 -G aes -u key.pub -r key.priv -C prim.ctx -L policy.dat \
  -p testpswd

Authenticate with plaintext passphrase input

This example demonstrates authenticating using the TPM objects plaintext authentication value. While we could authenticate with an ephemeral password session, in this example we will authenticate with the plaintext passphrase in a policy session instead using the tpm2_policypassword(1) tool.

First, load the key:

tpm2_load -C prim.ctx -u key.pub -r key.priv -n key.name -c key.ctx
echo "plaintext" > plain.txt

Then, encrypt data using the key, providing the passphrase testpswd.

tpm2_encryptdecrypt -c key.ctx -o encrypt.out plain.txt -p testpswd plain.txt

Authenticate with password and the policy

This sequence demonstrates authenticating using a password and a policy session. First, a policy session is started and the password policy is applied. Then, the tpm2_encryptdecrypt command is used with the policy session and the password.

tpm2_startauthsession \--policy-session -S session.dat
tpm2_policypassword -S session.dat -L policy.dat
tpm2_encryptdecrypt -c key.ctx -o encrypt.out \
  -p session:session.dat+testpswd plain.txt
tpm2_flushcontext session.dat

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.

Limitations

It expects a session to be already established via tpm2_startauthsession(1) and requires one of the following:

•
direct device access
•
extended session support with tpm2-abrmd.

Without it, most resource managers will not save session state between command invocations.
