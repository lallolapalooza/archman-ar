tpm2_certify(1) دليل الأوامر العامة tpm2_certify(1)

الاسم

tpm2_certify(1) - إثبات أن كائنًا ما محمل في TPM.

المُلَخَّص

tpm2_certify [خيارات]

الوصف

tpm2_certify(1) - يثبت أن كائنًا له اسم محدد محمل في TPM. من خلال التصديق على تحميل الكائن، فإن TPM يضمن أن المساحة العامة ذات الاسم المعطى متسقة داخليًا وترتبط بمساحة حساسة صالحة.

إذا كان لدى الطرف المعتمد مساحة عامة لها نفس الاسم مثل الاسم الذي تم التصديق عليه بهذا الأمر، فإن القيم الموجودة في تلك المساحة العامة تكون صحيحة. لا يمكن التصديق على كائن لا يحتوي إلا على مساحته العامة.

الخيارات

هذه الخيارات تتحكم في عملية التصديق:

•
-c, --certifiedkey-context=OBJECT:

الكائن المراد التصديق عليه.

•
-C, --signingkey-context=OBJECT:

المفتاح المستخدم لتوقيع بنية المصادقة.

•
-P, --certifiedkey-auth=AUTH:

قيمة المصادقة المقدمة للكائن المحدد باستخدام -c.

•
-g, --hash-algorithm=ALGORITHM:

خوارزمية التجزئة المستخدمة في إنشاء التوقيع.

•
--scheme=ALGORITHM:

نظام التوقيع المستخدم لتوقيع الرسالة. اختياري. يجب أن تتبع أنظمة التوقيع "معايير التنسيق"، راجع القسم "محدِّدات الخوارزميات". أيضًا، راجع القسم "أنظمة التوقيع المدعومة" للحصول على قائمة بأنظمة التوقيع المدعومة. إذا تم تحديده، يجب أن يتطابق نظام التوقيع مع نوع المفتاح. إذا تُرك غير محدد، فسيتم استخدام نظام توقيع افتراضي لنوع المفتاح.

•
-p, --signingkey-auth=AUTH:

قيمة المصادقة للمفتاح الموقع المحدد باستخدام -C.

•
-o, --attestation=FILE:

اسم ملف الإخراج لبيانات المصادقة.

•
-s, --signature=FILE:

اسم ملف الإخراج لبيانات التوقيع.

•
-f, --format=FORMAT:

اختيار التنسيق لملف إخراج التوقيع.

•
--cphash=FILE

مسار الملف لتسجيل تجزئة معلمات الأمر. هذا يُعرف عادةً بـ cpHash. ملاحظة: عند تحديد هذا الخيار، لن يقوم الأداة بتنفيذ الأمر فعليًا، بل ستعيد فقط cpHash، ما لم يكن rphash مطلوبًا أيضًا.

•
--rphash=FILE

مسار الملف لتسجيل تجزئة معلمات الاستجابة. هذا يُعرف عادةً بـ rpHash.

•
-S, --session=FILE:

الجلسة التي تم إنشاؤها باستخدام tpm2_startauthsession. يمكن استخدام هذا لتحديد جلسة مساعدة للتدقيق و/أو تشفير/فك تشفير المعلمات.

مراجع

تنسيق كائن السياق

يتم تحديد نوع كائن السياق، سواء كان مقبضًا أو اسم ملف، وفقًا للمنطق التالي *بالترتيب*:

•
إذا كان الوسيط مسار ملف، فسيتم تحميل الملف ككائن TPM مؤقت تم استعادته.
•
إذا كان الوسيط مطابقًا *بادئة* لأحد:
•
owner: التسلسل الهرمي للمالك
•
platform: التسلسل الهرمي للمنصة
•
endorsement: التسلسل الهرمي للمصادقة
•
lockout: الكائن المستمر للتحكم في قفل
•
إذا كان الوسيط يمكن تحميله كرقم، فسيتم التعامل معه كمقبض، على سبيل المثال: 0x81010013 ويستخدم مباشرة._OBJECT_.

تنسيق المصادقة

يمكن أن تأتي المصادقة لاستخدام كائن في TPM2.0 في 3 أشكال مختلفة: 1. كلمة مرور 2. HMAC 3. جلسات

ملاحظة: "تكون المصادقات افتراضيًا على كلمة المرور الفارغة عندما لا يتم تحديدها."

كلمات المرور

يتم تفسير كلمات المرور في الأشكال التالية باستخدام معرفات البادئة.

ملاحظة: افتراضيًا، تُفترض كلمات المرور أن تكون في شكل سلسلة نصية عندما لا تحتوي على بادئة.

سلسلة نصية

كلمة مرور نصية، محددة بالبادئة "str:" أو عدم وجودها (سلسلة نصية خام بدون بادئة) لا يتم تفسيرها، ويتم استخدامها مباشرة للمصادقة.

أمثلة

foobar
str:foobar

سلسلة سداسية عشرية

كلمة مرور بسلسلة سداسية عشرية، محددة بالبادئة "hex:" يتم تحويلها من شكل سداسي عشري إلى شكل مصفوفة بايت، مما يسمح بكلمات مرور تحتوي على أحرف غير قابلة للطباعة و/أو غير ودية للطرفية.

مثال

hex:1122334455667788

ملف

كلمة مرور مستندة إلى ملف، محددة بالبادئة "file:" يجب أن تكون مسار ملف يحتوي على كلمة المرور ليتم قراءتها بواسطة الأداة أو "-" لاستخدام الإدخال القياسي. تخزين كلمات المرور في ملفات يمنع تسرب المعلومات، وكلمات المرور المقدمة كخيارات يمكن قراءتها من قائمة العمليات وميزات سجل الأوامر الشائعة.

أمثلة

# لاستخدام الإدخال القياسي والمطالبة به
file:-
# لاستخدام ملف من مسار
file:path/to/password/file
# لبث كلمة مرور عبر الإدخال القياسي:
echo foobar | tpm2_tool -p file:-
# لاستخدام سلسلة bash هنا عبر الإدخال القياسي:
tpm2_tool -p file:- <<< foobar

الجلسات

عند استخدام جلسة سياسة للمصادقة على استخدام كائن، قم بوضع البادئة "session" على وسيط الخيار. ثم قم بتحديد مسار لملف جلسة تم إنشاؤه باستخدام tpm2_startauthsession(1). اختياريًا، إذا كانت الجلسة تتطلب قيمة مصادقة لإرسالها مع مقبض الجلسة (على سبيل المثال، كلمة مرور سياسة)، فألحق "+" وسلسلة نصية كما هو موضح في قسم كلمات المرور.

أمثلة

لاستخدام ملف سياق جلسة يسمى session.ctx.

session:session.ctx

لاستخدام ملف سياق جلسة يسمى session.ctx و إرسال قيمة المصادقة mypassword.

session:session.ctx+mypassword

لاستخدام ملف سياق جلسة يسمى session.ctx و إرسال قيمة المصادقة السداسية العشرية 0x11223344.

session:session.ctx+hex:11223344

NAME

tpm2_certify - Certify a piece of data using a TPM’s identity.

SYNOPSIS

tpm2_certify [OPTIONS] [ARGUMENTS]

DESCRIPTION

The tpm2_certify command is used to generate a signed attestation quote over a piece of data. The TPM must be provisioned with a signing key (typically an endorsement key (EK) or a platform key (PK) created and signed by the manufacturer, or a user-created signing key). The TPM generates a signature over the data digest, which can be used to prove that the TPM possesses the corresponding private key.

The command takes an input data digest, a primary context object (to obtain the PCRs), a signing key context object, and outputs the attestation data and a signature.

OPTIONS

The following are the options available for the tpm2_certify command:

-c, --context=context_object
Specifies the context object to load the signing key. The context object can be a file path or a TPM2_Load context. The context object must be a key previously created or loaded. The signing key context object may be a primary key context object (if the primary key is also the signing key).
-C, --parent-context=context_object
Specifies the parent context object. This is required if the signing key is not a primary key. The parent context object is the context of the primary key under which the signing key was created or loaded. This is needed to obtain the PCRs that are associated with the signing key.
-g, --hash-algorithm=algorithm
Specifies the hash algorithm to use for calculating the digest of the input data. Supported algorithms include:
sha1, sha256, sha384, sha512, sm3_256
-G, --signing-key-algorithm=algorithm
Specifies the signing key algorithm. This option is only needed when using a primary key as the signing key. Supported algorithms include:
rsa, ecc
-f, --format=format
Specifies the output format for the signature. Supported formats include:
raw, pem, pkcs7
-o, --output=file
Specifies the output file for the attestation data. This file will contain the signed digest.
-s, --signature=file
Specifies the output file for the signature. This file will contain the signature generated by the TPM.
-p, --policy=policy_file
Specifies a policy file to use for authorization. The policy file should contain the policy digest calculated by tpm2_policysize or related commands.
-P, --password=password
Specifies the password for the signing key. If the signing key is a primary key, this option is not needed.
-q, --quiet
Suppress normal tool output to stdout.
-v, --verbose
Enable verbose output.

Context Object Format

The context object can be specified in two ways:

1.
A file path to a context file. This file contains the saved context of an object (e.g., a key, a policy, etc.).
2.
A TPM2_Load context string. This string is of the form:

<handle>:<filename>

Where <handle> is the handle of the object in the TPM, and <filename> is the path to the file containing the object's data (e.g., the private key blob).

The primary context object argument should be specified using the -C or --parent-context option. The signing key context object should be specified using the -c or --context option.

Authorization Formatting

The authorization for the signing key can be provided using either a password or a policy. The password can be specified using the -P or --password option. The policy can be specified using the -p or --policy option, which takes a file path to the policy digest.

Algorithm Specifiers

The hash algorithm for input data digest is specified using the -g or --hash-algorithm option. The signing key algorithm is specified using the -G or --signing-key-algorithm option.

Signature Format Specifiers

The output signature format is specified using the -f or --format option. Supported formats include raw, pem, and pkcs7.

COMMON OPTIONS

•
-h, --help: Print help information.
•
-v, --version: Print version information.
•
-Q, --quiet: Silence normal tool output to stdout.
•
-Z, --enable-errata: Enable the application of errata fixups. Useful if an errata fixup needs to be applied to commands sent to the TPM. Defining the environment TPM2TOOLS_ENABLE_ERRATA is equivalent.
•

Autoflush can also be activated if the environment variable TPM2TOOLS_AUTOFLUSH is is set to yes or true. information many users may expect.

TCTI Configuration

The TCTI or “Transmission Interface” is the communication mechanism with the TPM. TCTIs can be changed for communication with TPMs across different mediums.

To control the TCTI, the tools respect:

1.
The command line option -T or --tcti
2.
The environment variable: TPM2TOOLS_TCTI.

Note: The command line option always overrides the environment variable.

The current known TCTIs are:

•
tabrmd - The resource manager, called tabrmd. Note that tabrmd and abrmd as a tcti name are synonymous.
•
mssim - Typically used for communicating to the TPM software simulator.
•
device - Used when talking directly to a TPM device file.
•
none - Do not initalize a connection with the TPM. Some tools allow for off-tpm options and thus support not using a TCTI. Tools that do not support it will error when attempted to be used without a TCTI connection. Does not support ANY options and MUST BE presented as the exact text of “none”.

The arguments to either the command line option or the environment variable are in the form:

<tcti-name>:<tcti-option-config>

Specifying an empty string for either the <tcti-name> or <tcti-option-config> results in the default being used for that portion respectively.

TCTI Defaults

When a TCTI is not specified, the default TCTI is searched for using dlopen(3) semantics. The tools will search for tabrmd, device and mssim TCTIs IN THAT ORDER and USE THE FIRST ONE FOUND. You can query what TCTI will be chosen as the default by using the -v option to print the version information. The “default-tcti” key-value pair will indicate which of the aforementioned TCTIs is the default.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

EXAMPLES

Create a primary key and certify it with a signing key.

tpm2_createprimary -Q -C e -g sha256 -G rsa -c primary.ctx
tpm2_create -Q -g sha256 -G rsa -u certify.pub -r certify.priv -C primary.ctx
tpm2_load -Q -C primary.ctx -u certify.pub -r certify.priv -n certify.name \
-c certify.ctx
tpm2_certify -Q -c primary.ctx -C certify.ctx -g sha256 -o attest.out -s sig.out

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.
