tpm2_geteccparameters(1) - استرداد معلمات منحنى ECC المحدد بواسطة معرّف المنحنى المعين من TCG.

الملخص

tpm2_geteccparameters [خيارات]

tpm2_geteccparameters(1) - استرداد معلمات منحنى ECC المحدد بواسطة معرّف المنحنى المعين من TCG.

الخيارات

•
ARGUMENT=ALGORITHM:

تحديد منحنى ECC. مثال ecc521.

•
-o, --output=FILE

تحديد مسار الملف لحفظ معلمات ECC.

•

مسار الملف لتسجيل تجزئة معلمات الأمر. يُطلق على هذا عادةً اسم cpHash. ملاحظة: عند تحديد هذا الخيار، لن يقوم الأداة بتنفيذ الأمر فعليًا، بل ستعيد فقط cpHash.

NAME

tpm2_create

create a primary or storage key

SYNOPSIS

tpm2_create [OPTIONS] [-C context] [-G algSpec] [-P auth] [-u public] [-r private] [-p policy] [-U usage] [-L policyFile] [-a authValue] [-I inData] [-o outData]

DESCRIPTION

tpm2_create is used to create a primary key or a storage key. These keys can be used for various cryptographic operations like signing, encrypting, or deriving keys.

A primary key is the root of a key hierarchy within the TPM. It is created using the -C null option. A storage key is created under an existing primary or storage key.

The command can generate asymmetric keys (RSA, ECC) or symmetric keys (AES).

Algorithm Specifiers

The algorithm specifier used with the -G option has the following format:

<alg>[:<keyType>][:<attrs>]

The possible values for <alg> are:

•
rsa - RSA keys
•
ecc - ECC keys
•
aes - AES keys

The possible values for <keyType> depend on the chosen algorithm:

•
For rsa: rsa2048, rsa3072, rsa4096. The default is rsa2048.
•
For ecc: ecc256, ecc384. The default is ecc256.
•
For aes: aes128, aes256. The default is aes128.

The optional <attrs> are algorithm-specific and denote usage attributes:

•
Asymmetric algorithm attributes:
•
fixed - for fixed TPM or policy.
•
user - for user or policy.
•
admin - for admin or policy.
•
fixedtpm - synonym for fixed.
•
fixedparent - key is bound to parent.
•
sensitivedata - key has sensitive data.
•
adminwithpolicy - admin auth is a policy.
•
userwithpolicy - user auth is a policy.
•
ek - key is an endorsement key.
•
hv_rootkey - key is an HV rootkey.
•
restricted - the key is restricted.
•
decrypt - the key can be used for decryption.
•
sign - the key can be used for signing.
•
no-da - Disables the use of DA for key generation.
•
scheme - specifies the signing or encryption scheme. For signing, valid options are rsassa, rsaes, ecdsa, ecsch, null. For encryption, valid options are rsaes, oaep, null. The scheme can also take a hash algorithm, e.g., rsassa-sha256. If no scheme is specified for signing keys, it defaults to rsassa or ecdsa based on the key type. If no scheme is specified for encryption keys, it defaults to rsaes.
•
Symmetric algorithm attributes:
•
cfb - Use Cipher Feedback (CFB) mode. This is the default mode for symmetric keys.
•
cbc - Use Cipher Block Chaining (CBC) mode.
•
ecb - Use Electronic Codebook (ECB) mode.

The attributes can be combined using a comma separator. For example, rsa2048:fixed:rsassa-sha256 creates a 2048-bit RSA key that is bound to the TPM and can be used for signing with SHA-256.

If an asymmetric key is created without specifying a scheme, the default scheme depends on the key type and its intended use (signing or encryption). For signing keys, it defaults to rsassa (for RSA) or ecdsa (for ECC). For encryption keys, it defaults to rsaes. If a symmetric key is created without specifying a mode, it defaults to CFB.

If the key is a symmetric object, a scheme must be specified. For example, aes128:cfb or aes128:rsasig .

If the key is an asymmetric object, symmetric details can be specified using the keyword. For example, rsa2048:aes128cfb .

If not specified, an asymmetric objects symmetric details defaults to aes128cfb.

Examples

Create an rsa2048 key with an rsaes asymmetric encryption scheme

tpm2_create -C parent.ctx -G rsa2048:rsaes -u key.pub -r key.priv

Create an ecc256 key with an ecdaa signing scheme with a count of 4 and sha384 hash

/tpm2_create -C parent.ctx -G ecc256:ecdaa4-sha384 -u key.pub -r key.priv cryptographic algorithms ALGORITHM.

TCTI Configuration

The TCTI or “Transmission Interface” is the communication mechanism with the TPM. TCTIs can be changed for communication with TPMs across different mediums.

To control the TCTI, the tools respect:

1.
The command line option -T or --tcti
2.
The environment variable: TPM2TOOLS_TCTI.

Note: The command line option always overrides the environment variable.

The current known TCTIs are:

•
tabrmd - The resource manager, called tabrmd. Note that tabrmd and abrmd as a tcti name are synonymous.
•
mssim - Typically used for communicating to the TPM software simulator.
•
device - Used when talking directly to a TPM device file.
•
none - Do not initalize a connection with the TPM. Some tools allow for off-tpm options and thus support not using a TCTI. Tools that do not support it will error when attempted to be used without a TCTI connection. Does not support ANY options and MUST BE presented as the exact text of “none”.

The arguments to either the command line option or the environment variable are in the form:

<tcti-name>:<tcti-option-config>

Specifying an empty string for either the <tcti-name> or <tcti-option-config> results in the default being used for that portion respectively.

TCTI Defaults

When a TCTI is not specified, the default TCTI is searched for using dlopen(3) semantics. The tools will search for tabrmd, device and mssim TCTIs IN THAT ORDER and USE THE FIRST ONE FOUND. You can query what TCTI will be chosen as the default by using the -v option to print the version information. The “default-tcti” key-value pair will indicate which of the aforementioned TCTIs is the default.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.
