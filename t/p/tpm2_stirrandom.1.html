tpm2_stirrandom(1)

الحزمة: tpm2-tools

التراخيص: BSD-3-Clause

tpm2_stirrandom(1) دليل الأوامر العامة tpm2_stirrandom(1)

الاسم

tpm2_stirrandom(1) - إضافة "معلومات إضافية" إلى حالة مولد الأرقام العشوائي الخاص بالـ TPM.

الملخص

tpm2_stirrandom [خيارات] [وسيط]

الوصف

tpm2_stirrandom(1) - حقن "معلومات إضافية" كبايتات في مجمع القدرات المحمية للـ TPM.

يمكن استخراج "المعلومات الإضافية" من ملف محدد كوسيط أو قراءتها من STDIN إذا لم يتم تحديد وسيط.

يمكن حقن ما يصل إلى 128 بايت في المرة الواحدة عبر الإدخال القياسي إلى tpm2_stirrandom(1).

إذا كان ملف الإدخال أكبر من 128 بايت، فسيفشل tpm2_stirrandom(1).

إن إضافة بيانات عبر tpm2_stirrandom(1) ستؤدي إلى إعادة توليد مولد الأرقام العشوائي (DRBG) للقدرة المحمية للـ TPM. يتم استخدامه عند إجراء أي إجراء حساس على موقع محمي مثل تحميل مفتاح دائم أو التصرف على قدرة محمية مثل تحديث البرامج الثابتة للـ TPM.

الخيارات

لا يحتوي هذا الأمر على خيارات.

مراجع

خيارات مشتركة

هذه المجموعة من الخيارات مشتركة بين العديد من البرامج وتوفر معلومات قد يتوقعها العديد من المستخدمين.

•
-h, --help=[man|no-man]: عرض دليل الأداة. افتراضيًا، تحاول استدعاء عارض الدليل للأداة، ولكن عند الفشل، سيتم عرض ملخص قصير للأداة. هذا هو نفس السلوك إذا تم تحديد وسيط الخيار "man"، ولكن إذا تم طلب "man" بشكل صريح، فإن الأداة ستوفر الأخطاء من الدليل على stderr. إذا تم تحديد الخيار "no-man" أو فشل عارض الدليل، فسيتم إخراج الخيارات القصيرة إلى stdout.

للاستفادة بنجاح من ميزة الدليل، يتطلب تثبيت أدلة الدليل أو وجودها في MANPATH، راجع man(1) لمزيد من التفاصيل.

•
-v, --version: عرض معلومات الإصدار لهذه الأداة، و tctis المدعومة والخروج.
•
-V, --verbose: زيادة المعلومات التي تطبعها الأداة إلى وحدة التحكم أثناء تنفيذها. عند استخدام هذا الخيار، يتم طباعة اسم الملف ورقم السطر.
•
-Q, --quiet: كتم الإخراج الطبيعي للأداة إلى stdout.
•
-Z, --enable-errata: تمكين تطبيق تصحيحات الأخطاء. مفيد إذا كان يجب تطبيق تصحيح خطأ على الأوامر المرسلة إلى TPM. تعريف متغير البيئة TPM2TOOLS_ENABLE_ERRATA يعادل ذلك.
•
-R, --autoflush: تمكين التفريغ التلقائي للكائنات المؤقتة التي تم إنشاؤها بواسطة الأمر. إذا تم تحميل كائن أب من ملف سياق، فسيتم أيضًا تفريغ كائن الأب المؤقت. يمكن أيضًا تفعيل التفريغ التلقائي إذا تم تعيين متغير البيئة TPM2TOOLS_AUTOFLUSH على "yes" أو "true". معلومات قد يتوقعها العديد من المستخدمين.

تكوين TCTI

TCTI أو "واجهة الإرسال" هي آلية الاتصال بالـ TPM. يمكن تغيير TCTIs للاتصال بـ TPMs عبر وسائط مختلفة.

للتحكم في TCTI، تحترم الأدوات:

1.
خيار سطر الأوامر -T أو --tcti
2.
متغير البيئة: TPM2TOOLS_TCTI.

ملاحظة: خيار سطر الأوامر يتجاوز دائمًا متغير البيئة.

TCTIs المعروفة حاليًا هي:

•
tabrmd - مدير الموارد، المسمى tabrmd. لاحظ أن tabrmd و abrmd كاسم tcti مترادفان.
•
mssim - يستخدم عادة للاتصال بمحاكي برامج TPM.
•
device - يستخدم عند التحدث مباشرة إلى ملف جهاز TPM.
•
none - لا تقم بتهيئة اتصال مع TPM. تسمح بعض الأدوات بخيارات خارج TPM وبالتالي تدعم عدم استخدام TCTI. الأدوات التي لا تدعمها ستحدث خطأ عند محاولة استخدامها بدون اتصال TCTI. لا تدعم أي خيارات ويجب تقديمها كنص دقيق "none".

تكون وسائط خيار سطر الأوامر أو متغير البيئة بالشكل:

<اسم_tcti>:<تكوين_خيارات_tcti>

تحديد سلسلة فارغة لأي من <اسم_tcti> أو <تكوين_خيارات_tcti> يؤدي إلى استخدام الإعداد الافتراضي لكل منهما.

الإعدادات الافتراضية لـ TCTI

عند عدم تحديد TCTI، يتم البحث عن TCTI الافتراضي باستخدام دلالات dlopen(3). ستبحث الأدوات عن TCTIs tabrmd و device و mssim بهذا الترتيب وتستخدم أول واحد يتم العثور عليه. يمكنك الاستعلام عن TCTI الذي سيتم اختياره كافتراضي باستخدام الخيار -v لطباعة معلومات الإصدار. سيشير زوج المفتاح والقيمة "default-tcti" إلى أي من TCTIs المذكورة أعلاه هو الافتراضي.

TCTIs المخصصة

يمكن تحميل أي TCTI ينفذ واجهة TCTI الديناميكية. تستخدم الأدوات داخليًا dlopen(3)، ويتم استخدام اسم TCTI الخام للبحث. وبالتالي، يمكن أن يكون هذا مسارًا إلى المكتبة المشتركة، أو اسم مكتبة كما هو مفهوم بواسطة دلالات dlopen(3).

خيارات TCTI

هذه المجموعة من الخيارات تستخدم لتكوين وحدات TCTI المعروفة المختلفة المتاحة:

•
device: بالنسبة لوحدة TCTI الخاصة بالجهاز، يمكن تحديد ملف جهاز TPM لاستخدامه بواسطة وحدة TCTI الخاصة بالجهاز. الافتراضي هو /dev/tpm0.

مثال: -T device:/dev/tpm0 أو export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: بالنسبة لوحدة TCTI الخاصة بـ mssim، يمكن تحديد اسم النطاق أو عنوان IP ورقم المنفذ الذي يستخدمه المحاكي. الافتراضي هو 127.0.0.1 و 2321.

مثال: -T mssim:host=localhost,port=2321 أو export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: بالنسبة لوحدة TCTI الخاصة بـ abrmd، يكون تنسيق سلسلة التكوين عبارة عن سلسلة من أزواج المفاتيح والقيم البسيطة مفصولة بفاصلة (`,`). يتم فصل كل مفتاح وسلسلة قيمة بـ (`=`).
•
يدعم TCTI abrmd مفتاحين:
1.
`bus_name`: اسم خدمة tabrmd على الناقل (سلسلة).
2.
`bus_type`: نوع مثيل dbus (سلسلة) محدود بـ `session` و `system`.

تحديد اسم tcti tabrmd وسلسلة تكوين bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

تحديد tcti الافتراضي (abrmd) وسلسلة تكوين bus_type=session:

\--tcti:bus_type=session

ملاحظة: abrmd و tabrmd مترادفان. وحدات TCTI المعروفة المختلفة.)

أمثلة

الحقن من stdin باستخدام echo

echo -n "myrandomdata" | tpm2_stirrandom

SYNOPSIS

tpm2_stirrandom [OPTIONS] [input_file]

DESCRIPTION

The tpm2_stirrandom command is used to add entropy to the TPM's random number generator (RNG). This is done by providing random bytes that the TPM will incorporate into its internal state.

The primary use case for this command is to seed the TPM's RNG with a sufficient amount of entropy before using cryptographic operations that rely on randomness, such as key generation.

The random bytes can be provided either from standard input or from a file.

OPTIONS

A list of options is available with the tpm2_stirrandom command.

-i, --input input_file
Specifies the input file containing the random bytes. If this option is not provided, the command will read from standard input.
-n, --num-bytes num_bytes
Specifies the number of random bytes to inject. The default is 64 bytes. The TPM supports a maximum of 128 bytes of additional entropy per call to TPM2_StirRandom.
-S, --session session_file
Optional session file. For more details on sessions, see tpm2_session(5).

COMMON OPTIONS

These options are common to many tpm2_tools commands and are used to configure the connection to the TPM.

-c, --clear
Clear the TPM session and close the connection.
-f, --force
Forces the operation to continue even if errors are encountered.
-h, --help
Prints the help message for the command.
-l, --log log_level
Set the tpm2_tools logging level.
-m, --module module_path
Path to the TCTI module to load.
-p, --password password
The password for the TPM owner or object.
-q, --quiet
Suppress output to stdout.
-t, --tcti tcti_spec
TPM Command Transmission Interface Specification.
-u, --unixstr
Use the Unix socket transport.
-v, --verbose
Enable verbose output.
-z, --take-ownership
Take ownership of the TPM.

TCTI Configuration

The TPM Command Transmission Interface (TCTI) is responsible for communicating with the TPM device. The following TCTIs are commonly used:

device
Connects to a TPM device via a character device (e.g., /dev/tpm0).
socket
Connects to a TPM emulator via a TCP socket.
none
Does not use a TCTI, useful for testing or when the TCTI is configured externally.

The TCTI can be specified using the -t or --tcti option. For example:

tpm2_stirrandom -t device:/dev/tpm0
tpm2_stirrandom -t socket:host=localhost,port=2321

TCTI OPTIONS

Some TCTIs accept additional options. For example, the socket TCTI supports specifying the host and port:

--tcti socket:host=127.0.0.1,port=2321

Refer to the tpm2-tss documentation for a complete list of TCTI options.

EXAMPLES

Inject 64 bytes from stdin using a file

dd if=/dev/urandom bs=1 count=64 > myrandom.bin
tpm2_stirrandom < ./myrandom.bin

Inject bytes from a file and reading up to 128 bytes

dd if=/dev/urandom of=./myrandom.bin bs=1 count=42
tpm2_stirrandom ./myrandom.bin

NOTES

Please be aware that even if the “additional information” added by tpm2_stirrandom(1) can be entropy gathered from other DRBG sources, the TPM has no way of determining if the value has any entropy or not. As a consequence, it will just be considered as “additional input”.

The “additional input” is as defined in https://nvlpubs.nist.gov/nistpubs/Legacy/SP/nistspecialpublication800-90.pdf NIST SP800-90A

Returns

Tools can return any of the following codes:

•
0 - Success.
•

•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.
