الحزمة: tpm2-tools

tpm2_load(1) دليل الأوامر العامة tpm2_load(1)

الاسم

tpm2_load(1) - تحميل كائن في TPM.

ملخص

tpm2_load [خيارات]

الوصف

tpm2_load(1) - تحميل الجزء الخاص والجزء العام لكائن في TPM أو تحميل الكائن بتنسيق PEM لمفتاح TSS2-Private-Key. يمكن القيام بذلك عن طريق تحديد الجزء الخاص وكذلك الجزء العام أو عبر ملف pem باستخدام الخيار -r.

تقوم الأداة بإخراج اسم الكائن المحمل بتنسيق قاموس YAML مع المفتاح name حيث القيمة لهذا المفتاح هي اسم الكائن بتنسيق سداسي عشري، على سبيل المثال:

name: 000bac25cb8743111c8e1f52f2ee7279d05d3902a18dd1af694db5d1afa7adf1c8b3

كما أنها تحفظ ملف سياق للتفاعلات المستقبلية مع الكائن.

ملاحظة: يجب تحديد كلا الجزأين الخاص والعام لمفتاح tpm. الاستثناء من ذلك هو إذا كان سيتم تحميل كائن PEM بتنسيق TSS2-Private-Key والذي لا يحتاج إلى تحديد الجزء العام.

الخيارات

•
-C, --parent-context=OBJECT:

الكائن الأصل.

•
-P, --auth=AUTH:

قيمة المصادقة للكائن الأصل المحدد بواسطة -C.

•
-u, --public=FILE:

ملف يحتوي على الجزء العام للكائن.

•
-r, --private=FILE:

ملف يحتوي على الجزء الحساس للكائن.

•
-n, --name=FILE:

ملف اختياري لحفظ بنية اسم الكائن.

•
-c, --key-context=FILE:

اسم ملف سياق الكائن المحفوظ، مطلوب.

•
--cphash=FILE

مسار الملف لتسجيل تجزئة معلمات الأمر. يُشار إلى هذا عادةً باسم cpHash. ملاحظة: عند تحديد هذا الخيار، لن تقوم الأداة بتنفيذ الأمر فعليًا، بل تعيد فقط cpHash.

المراجع

تنسيق كائن السياق

يتم تحديد نوع كائن السياق، سواء كان مقبضًا أو اسم ملف، وفقًا للمنطق التالي بالترتيب:

•
إذا كان الوسيط مسار ملف، فسيتم تحميل الملف ككائن TPM انتقالي مستعاد.
•
إذا كان الوسيط يطابق بادئة لأحد:
•
owner: هرم المالك
•
platform: هرم المنصة
•
endorsement: هرم المصادقة
•
lockout: كائن القفل المستمر للتحكم
•
إذا كان الوسيط يمكن تحميله كرقم، فسيتم اعتباره مقبضًا، على سبيل المثال 0x81010013 وسيتم استخدامه مباشرة.

تنسيق المصادقة

يمكن أن تأتي المصادقة لاستخدام كائن في TPM2.0 في 3 أشكال مختلفة: 1. كلمة مرور 2. HMAC 3. جلسات

ملاحظة: "تكون المصادقات افتراضية إلى كلمة المرور الفارغة عند عدم تحديدها."

كلمات المرور

يتم تفسير كلمات المرور في الأشكال التالية أدناه باستخدام معرفات البادئة.

ملاحظة: افتراضيًا، تُفترض كلمات المرور أنها في شكل سلسلة نصية عندما لا تحتوي على بادئة.

سلسلة نصية

كلمة مرور نصية، محددة بالبادئة "str:" أو غيابها (سلسلة نصية خام بدون بادئة) لا يتم تفسيرها، وتستخدم مباشرة للمصادقة.

أمثلة

foobar
str:foobar

سلسلة سداسية عشرية

كلمة مرور سداسية عشرية، محددة بالبادئة "hex:"، يتم تحويلها من شكل سداسي عشري إلى شكل مصفوفة بايت، مما يسمح بكلمات مرور تحتوي على أحرف غير قابلة للطباعة و/أو غير ودية للطرفية.

مثال

hex:1122334455667788

ملف

كلمة مرور قائمة على ملف، محددة بالبادئة "file:" يجب أن تكون مسار ملف يحتوي على كلمة المرور التي ستقوم الأداة بقراءتها أو "-" لاستخدام stdin. تخزين كلمات المرور في ملفات يمنع تسرب المعلومات، كلمات المرور المقدمة كخيارات يمكن قراءتها من قائمة العمليات أو ميزات سجل الأوامر الشائعة.

أمثلة

# لاستخدام stdin وسيطلب منك إدخال كلمة المرور
file:-
# لاستخدام ملف من مسار
file:path/to/password/file
# لإرسال كلمة مرور عبر stdin:
echo foobar | tpm2_tool -p file:-
# لاستخدام bash here-string عبر stdin:
tpm2_tool -p file:- <<< foobar

جلسات

عند استخدام جلسة سياسة لمصادقة استخدام كائن، قم بوضع بادئة للوسيط بالكلمة المفتاحية session. ثم حدد مسارًا لملف جلسة تم إنشاؤه بواسطة tpm2_startauthsession(1). اختياريًا، إذا كانت الجلسة تتطلب قيمة مصادقة لإرسالها مع مقبض الجلسة (مثل كلمة مرور سياسة)، فقم بإلحاق '+' وسلسلة نصية كما هو موضح في قسم كلمات المرور.

أمثلة

لاستخدام ملف سياق جلسة يسمى session.ctx.

session:session.ctx

لاستخدام ملف سياق جلسة يسمى session.ctx **و** إرسال قيمة المصادقة mypassword.

session:session.ctx+mypassword

لاستخدام ملف سياق جلسة يسمى session.ctx **و** إرسال قيمة المصادقة السداسية العشرية 0x11223344.

session:session.ctx+hex:11223344

مصادقات PCR

يمكنك تلبية سياسة PCR باستخدام البادئة "pcr:" ولغة PCR المصغرة. لغة PCR المصغرة هي كما يلي: <pcr-spec>=<raw-pcr-file>

مواصفات PCR موثقة في قسم "محددات بنك PCR".

الـ raw-pcr-file هو وسيط اختياري يحتوي على مخرجات محتويات PCR الأولية كما تم إرجاعها بواسطة tpm2_pcrread(1).

محددات بنك PCR

أمثلة

لتلبية سياسة PCR لـ sha256 على البنوك 0، 1، 2، و 3 استخدم المحدد:

pcr:sha256:0,1,2,3

إعداد TCTI

The TCTI or "Transmission Interface" is the communication mechanism with the TPM. TCTIs can be changed for communication with TPMs across different mediums.

To control the TCTI, the tools respect:

1.
The command line option -T or --tcti
2.
The environment variable: TPM2TOOLS_TCTI.

Note: The command line option always overrides the environment variable.

The current known TCTIs are:

•
tabrmd - The resource manager, called tabrmd. Note that tabrmd and abrmd as a tcti name are synonymous.
•
mssim - Typically used for communicating to the TPM software simulator.
•
device - Used when talking directly to a TPM device file.
•
none - Do not initalize a connection with the TPM. Some tools allow for off-tpm options and thus support not using a TCTI. Tools that do not support it will error when attempted to be used without a TCTI connection. Does not support ANY options and MUST BE presented as the exact text of "none".

The arguments to either the command line option or the environment variable are in the form:

<tcti-name>:<tcti-option-config>

Specifying an empty string for either the <tcti-name> or <tcti-option-config> results in the default being used for that portion respectively.

افتراضيات TCTI

When a TCTI is not specified, the default TCTI is searched for using dlopen(3) semantics. The tools will search for tabrmd, device and mssim TCTIs IN THAT ORDER and USE THE FIRST ONE FOUND. You can query what TCTI will be chosen as the default by using the -v option to print the version information. The "default-tcti" key-value pair will indicate which of the aforementioned TCTIs is the default.

TCTIs المخصصة

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

خيارات TCTI

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI="device:/dev/tpm0"

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI="mssim:host=localhost,port=2321"

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

إعداد

To load an object you first must create an object under a primary object. So the first step is to create the primary object.

tpm2_createprimary -c primary.ctx

Step 2 is to create an object under the primary object.

tpm2_create -C primary.ctx -u key.pub -r key.priv

This creates the private and public portions of the TPM object. With these object portions, it is now possible to load that object into the TPM for subsequent use.

تحميل كائن في TPM

The final step, is loading the public and private portions of the object into the TPM.

tpm2_load  -C primary.ctx -u key.pub -r key.priv -c key.ctx
name: 000bac25cb8743111c8e1f52f2ee7279d05d3902a18dd1af694db5d1afa7adf1c8b3

•

•

•
3 - Authentication error.
•
4 - TCTI related error.

5 - Non supported scheme. Applicable to tpm2_testparams.
