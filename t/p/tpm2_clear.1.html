tpm2_clear(1) دليل الأوامر العامة tpm2_clear(1)

الاسم

tpm2_clear(1) - يمسح قيم الترخيص الخاصة بقفل، تفويض، ومالك التسلسل الهرمي، وبيانات TPM أخرى.

الملخص

tpm2_clear [خيارات] [وسيط]

الوصف

tpm2_clear(1) - يرسل أمر مسح إلى TPM لمسح قيم الترخيص الثلاثة للتسلسل الهرمي. يأخذ كوسيط قيمة الترخيص الخاصة بالتسلسل الهرمي للمنصة أو للقفل. يمكن العثور على تفاصيل التغييرات التي تم إجراؤها على TPM في الجزء 3، "الأوامر"، القسم من مواصفات مكتبة TPM الموجودة على الرابط أدناه. - https://trustedcomputinggroup.org/resource/tpm-library-specification

يرجى البحث عن الإصدار الذي يتوافق مع إصدار مواصفات دعم TPM الخاص بك وأمر TPM2_Clear. يمكن العثور على إصدار مواصفات TPM المدعوم عن طريق إصدار tpm2_getcap properties-fixed في خاصية TPM_PT_REVISION.

ملاحظة: يتم فقدان جميع الكائنات التي تم إنشاؤها تحت التسلسلات الهرمية المعنية.

الخيارات

•
-c, --auth-hierarchy=OBJECT:

يحدد التسلسل الهرمي الذي يجب أن تعمل عليه الأدوات. افتراضيًا، تعمل على تسلسل القفل الهرمي.

ملاحظة: العمل على تسلسل المنصة الهرمي يتطلب ترخيص المنصة.

•
--cphash=FILE

مسار الملف لتسجيل تجزئة معلمات الأمر. يُعرف هذا عادةً باسم cpHash. ملاحظة: عند تحديد هذا الخيار، لن يقوم الأداة بتنفيذ الأمر فعليًا، بل سيعيد فقط cpHash.

•
ARGUMENT يحدد وسيط سطر الأوامر AUTH الذي سيتم تعيينه للكائن المحدد باستخدام -c.

المراجع

تنسيق كائن السياق

يتم تحديد نوع كائن السياق، سواء كان مقبضًا أو اسم ملف، وفقًا للمنطق التالي حسب الأولوية:

•
إذا كان الوسيط مسار ملف، فسيتم تحميل الملف ككائن TPM مؤقت مستعاد.
•
إذا كان الوسيط يطابق بادئة لأحد:
•
owner: تسلسل المالك الهرمي
•
platform: تسلسل المنصة الهرمي
•
endorsement: تسلسل التفويض الهرمي
•
lockout: كائن التحكم في القفل الدائم
•
إذا كان يمكن تحميل الوسيط كرقم، فسيعامل كمقبض، على سبيل المثال 0x81010013 ويستخدم مباشرة. _OBJECT_.

تنسيق الترخيص

يمكن أن يأتي ترخيص استخدام كائن في TPM2.0 في 3 أشكال مختلفة: 1. كلمة مرور 2. HMAC 3. جلسات

ملاحظة: "تكون كلمات المرور افتراضيًا على كلمة المرور الفارغة عند عدم تحديدها."

كلمات المرور

يتم تفسير كلمات المرور في الأشكال التالية أدناه باستخدام معرفات البادئة.

ملاحظة: افتراضيًا، يُفترض أن تكون كلمات المرور بتنسيق السلسلة عندما لا تحتوي على بادئة.

سلسلة

كلمة مرور سلسلة، محددة بالبادئة "str:" أو غيابها (سلسلة خام بدون بادئة) لا يتم تفسيرها، ويتم استخدامها مباشرة للترخيص.

أمثلة

foobar
str:foobar

سلسلة سداسية عشرية

كلمة مرور سلسلة سداسية عشرية، محددة بالبادئة "hex:"، يتم تحويلها من شكل سداسي عشري إلى شكل مصفوفة بايت، مما يسمح بكلمات المرور التي تحتوي على أحرف غير قابلة للطباعة و/أو غير ودية للطرفية.

مثال

hex:1122334455667788

ملف

كلمة مرور تعتمد على الملف، محددة بالبادئة "file:"، يجب أن تكون المسار إلى ملف يحتوي على كلمة المرور ليتم قراءتها بواسطة الأداة أو "-" لاستخدام stdin. يخزن كلمات المرور في الملفات يمنع تسرب المعلومات، وكلمات المرور التي تم تمريرها كخيارات يمكن قراءتها من قائمة العمليات أو ميزات سجل الأوامر الشائعة.

أمثلة

# لاستخدام stdin والمطالبة
file:-
# لاستخدام ملف من مسار
file:path/to/password/file
# لطباعة كلمة مرور عبر stdin:
echo foobar | tpm2_tool -p file:-
# لاستخدام سلسلة echo bash عبر stdin:
tpm2_tool -p file:- <<< foobar

جلسات

عند استخدام جلسة سياسة لترخيص استخدام كائن، قم بوضع البادئة لوسيط الخيار بكلمة session. ثم حدد مسارًا لملف جلسة تم إنشاؤه باستخدام tpm2_startauthsession(1). اختياريًا، إذا كانت الجلسة تتطلب قيمة ترخيص ليتم إرسالها مع مقبض الجلسة (على سبيل المثال، كلمة مرور السياسة)، فأضف "+"" وسلسلة كما هو موضح في قسم كلمات المرور.

أمثلة

لاستخدام ملف سياق جلسة يسمى session.ctx.

session:session.ctx

لاستخدام ملف سياق جلسة يسمى session.ctx و إرسال قيمة الترخيص mypassword.

session:session.ctx+mypassword

لاستخدام ملف سياق جلسة يسمى session.ctx و إرسال قيمة الترخيص السداسية العشرية 0x11223344.

session:session.ctx+hex:11223344

تراخيص PCR

يمكنك تلبية سياسة PCR باستخدام البادئة "pcr:" ولغة PCR المصغرة. لغة PCR المصغرة هي كما يلي: <pcr-spec>=<raw-pcr-file>

يتم توثيق مواصفات PCR في القسم "محدِّدات بنك PCR".

يعد raw-pcr-file وسيطًا اختياريًا يحتوي على إخراج محتويات PCR الخام كما تم إرجاعها بواسطة tpm2_pcrread(1).

محدِّدات بنك PCR

أمثلة

لتلبية سياسة PCR لـ sha256 على البنوك 0، 1، 2، و 3 استخدم محددًا:

pcr:sha256:0,1,2,3

تحديد AUTH.

tpm2_clear(1) — tpm2-tools

NAME

tpm2_clear — Clear the TPM. This command can be used to clear owner, endorsement and lockout authorizations. This command is not guaranteed to work on all TPMs. Some TPMs do not have the functionality to clear these values.

SYNOPSIS

tpm2_clear [OPTIONS] [auth-phrase]

DESCRIPTION

The tpm2_clear command is used to clear the TPM. This command can be used to clear owner, endorsement and lockout authorizations. This command is not guaranteed to work on all TPMs. Some TPMs do not have the functionality to clear these values.

The command can take an optional argument, auth-phrase, which is a hex string representing the authorization policy. If this is not provided, the command will attempt to use an empty authorization policy.

OPTIONS

The TPM2 tools follow the usual GNU command line syntax. Long options, which must appear before short options, are also supported.

Context Object Format

The context object format for loading TPM context objects is:

•
filename: A file containing a marshalled TPM context object. These files are generated by commands like tpm2_create, tpm2_createprimary, tpm2_load and tpm2_loadexternal.
•
handle: An integer or hex representation of a TPM handle. These handles are session, object, or dictionary attack counter handles.
•
type:handle: A string representation of a TPM handle type and value. The allowed types are:
•
p for the Platform hierarchy
•
o for the Owner hierarchy
•
e for the Endorsement hierarchy
•
l for the Lockout hierarchy
•
null for an empty TPM context object

For example, p:0x12345 or o:4321.

Authorization Formatting

Authorizations can be specified in the following ways:

•
As a plaintext password string.
•
As a hex string. Hex strings must be prefixed with 0x.
•
As a file containing the authorization string or hex string. Files must be prefixed with @.

For example, --auth-session=my_session.ctx, --password=0x12345678, --password=@auth.txt.

COMMON OPTIONS

These options are common to most TPM2 tools. They are documented in the tpm2_options(7) manual page.

For example, the following options are available:

•
-c, --context: Load a TPM context object from the specified file or handle.
•
-P, --platform-auth: The authorization value for the platform hierarchy.
•
-o, --owner-auth: The authorization value for the owner hierarchy.
•
-e, --endorsement-auth: The authorization value for the endorsement hierarchy.
•
-l, --lockout-auth: The authorization value for the lockout hierarchy.
•
-S, --session: The authorization session to use.
•
-T, --tcti: Specify the TCTI to use.

See also tpm2_options(7) for more details.

TCTI Configuration

The TCTI or “Transmission Interface” is the communication mechanism with the TPM. TCTIs can be changed for communication with TPMs across different mediums.

To control the TCTI, the tools respect:

1.
The command line option -T or --tcti
2.
The environment variable: TPM2TOOLS_TCTI.

Note: The command line option always overrides the environment variable.

The current known TCTIs are:

•
tabrmd - The resource manager, called tabrmd. Note that tabrmd and abrmd as a tcti name are synonymous.
•
mssim - Typically used for communicating to the TPM software simulator.
•
device - Used when talking directly to a TPM device file.
•
none - Do not initalize a connection with the TPM. Some tools allow for off-tpm options and thus support not using a TCTI. Tools that do not support it will error when attempted to be used without a TCTI connection. Does not support ANY options and MUST BE presented as the exact text of “none”.

The arguments to either the command line option or the environment variable are in the form:

<tcti-name>:<tcti-option-config>

Specifying an empty string for either the <tcti-name> or <tcti-option-config> results in the default being used for that portion respectively.

TCTI Defaults

When a TCTI is not specified, the default TCTI is searched for using dlopen(3) semantics. The tools will search for tabrmd, device and mssim TCTIs IN THAT ORDER and USE THE FIRST ONE FOUND. You can query what TCTI will be chosen as the default by using the -v option to print the version information. The “default-tcti” key-value pair will indicate which of the aforementioned TCTIs is the default.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

EXAMPLES

Set owner, endorsement and lockout authorizations to an empty value

tpm2_clear lockoutpasswd

Clear the authorization values on the platform hierarchy

tpm2_clear -c p

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.
