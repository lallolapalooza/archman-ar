tpm2_policyrestart(1) دليل الأوامر العامة tpm2_policyrestart(1)

الاسم

tpm2_policyrestart(1) - إعادة تشغيل جلسة موجودة مع TPM.

الملخص

tpm2_policyrestart [خيارات]

الوصف

tpm2_policyrestart(1) - يعيد تشغيل جلسة مع TPM إلى حالتها الأولية. هذا مفيد عندما يعطي TPM رمز خطأ TPM_RC_PCR_CHANGED (0x00000128) عند استخدام جلسة سياسة PCR.

سيتم إرجاع هذا إذا تم تغيير حالة PCR التي تؤثر على السياسة أثناء الجلسة. يمكن للمرء إعادة تشغيل الجلسة والمحاولة مرة أخرى، ومع ذلك، لا تزال حالة PCR بحاجة إلى تلبية السياسة.

الخيارات

•
-S, --session=ملف:

اختياري، ملف جلسة من خيار -S الخاص بـ tpm2_startauthsession(1). تستخدم هذه الجلسة بدلاً من بدء جلسة واستخدام خيارات سياسة PCR.

•
--cphash=ملف

مسار الملف لتسجيل تجزئة معلمات الأمر. هذا ما يسمى عادةً بـ cpHash. ملاحظة: عند تحديد هذا الخيار، لن يقوم الأداة بتنفيذ الأمر فعليًا، بل يعيد فقط cpHash.

المراجع

خيارات شائعة

تعتبر هذه المجموعة من الخيارات مشتركة بين العديد من البرامج وتوفر معلومات قد يتوقعها العديد من المستخدمين.

•
-h, --help=[man|no-man]: عرض دليل الأداة. افتراضيًا، تحاول استدعاء عارض الدليل للأداة، ولكن عند الفشل، تعرض ملخصًا قصيرًا للأداة. هذا هو نفس السلوك إذا تم تحديد وسيطة خيار "man"، ولكن إذا تم طلب "man" بشكل صريح، فستعرض الأداة أخطاء من man على stderr. إذا تم تحديد خيار "no-man"، أو فشل عارض الدليل، فسيتم إخراج الخيارات القصيرة إلى stdout.

يتطلب استخدام ميزة الدليل بنجاح تثبيت الدلائل أو وجودها في MANPATH، انظر man(1) لمزيد من التفاصيل.

•
-v, --version: عرض معلومات الإصدار لهذه الأداة، و tctis المدعومة والخروج.
•
-V, --verbose: زيادة المعلومات التي تطبعها الأداة إلى وحدة التحكم أثناء تنفيذها. عند استخدام هذا الخيار، تتم طباعة اسم الملف ورقم السطر.
•
-Q, --quiet: كتم إخراج الأداة العادي إلى stdout.
•
-Z, --enable-errata: تمكين تطبيق إصلاحات الأخطاء. مفيد إذا كان هناك حاجة لتطبيق إصلاح خطأ على الأوامر المرسلة إلى TPM. تعريف متغير البيئة TPM2TOOLS_ENABLE_ERRATA يعادل هذا.
•
-R, --autoflush: تمكين التفريغ التلقائي للكائنات المؤقتة التي تم إنشاؤها بواسطة الأمر. إذا تم تحميل كائن أب من ملف سياق، فسيتم أيضًا تفريغ كائن الأب المؤقت. يمكن أيضًا تنشيط التفريغ التلقائي إذا تم تعيين متغير البيئة TPM2TOOLS_AUTOFLUSH على yes أو true. معلومات قد يتوقعها العديد من المستخدمين.

تكوين TCTI

TCTI أو "واجهة الإرسال" هي آلية الاتصال مع TPM. يمكن تغيير TCTIs للاتصال بوحدات TPM عبر وسائط مختلفة.

للتحكم في TCTI، تحترم الأدوات:

1.
خيار سطر الأوامر -T أو --tcti
2.
متغير البيئة: TPM2TOOLS_TCTI.

ملاحظة: يتجاوز خيار سطر الأوامر دائمًا متغير البيئة.

TCTIs المعروفة حاليًا هي:

•
tabrmd - مدير الموارد، يسمى tabrmd. لاحظ أن tabrmd و abrmd كاسم tcti مترادفان.
•
mssim - يستخدم عادة للتواصل مع محاكي برامج TPM.
•
device - يستخدم عند التحدث مباشرة إلى ملف جهاز TPM.
•
none - لا تقم بتهيئة اتصال بـ TPM. تسمح بعض الأدوات بخيارات خارج TPM وتدعم بالتالي عدم استخدام TCTI. الأدوات التي لا تدعمها ستخطئ عند محاولة استخدامها بدون اتصال TCTI. لا تدعم أي خيارات ويجب تقديمها كنص دقيق "none".

تكون وسائط خيار سطر الأوامر أو متغير البيئة بالشكل:

<tcti-name>:<tcti-option-config>

تحديد سلسلة فارغة إما لـ <tcti-name> أو <tcti-option-config> يؤدي إلى استخدام الافتراضي لكل جزء على التوالي.

افتراضيات TCTI

عند عدم تحديد TCTI، يتم البحث عن TCTI الافتراضي باستخدام دلالات dlopen(3). ستبحث الأدوات عن TCTIs tabrmd و device و mssim بهذا الترتيب و تستخدم أول واحد تم العثور عليه. يمكنك الاستعلام عن TCTI الذي سيتم اختياره كافتراضي باستخدام الخيار -v لطباعة معلومات الإصدار. سيشير زوج المفتاح والقيمة "default-tcti" إلى أي من TCTIs المذكورة أعلاه هو الافتراضي.

TCTIs مخصصة

يمكن تحميل أي TCTI يطبق واجهة TCTI الديناميكية. تستخدم الأدوات داخليًا dlopen(3)، ويتم استخدام قيمة tcti-name الخام للبحث. وبالتالي، يمكن أن يكون هذا مسارًا إلى المكتبة المشتركة، أو اسم مكتبة كما تفهمه دلالات dlopen(3).

خيارات TCTI

تستخدم هذه المجموعة من الخيارات لتكوين وحدات TCTI المعروفة المختلفة المتاحة:

•
device: بالنسبة لـ device TCTI، يمكن تحديد ملف جهاز TPM لاستخدامه بواسطة device TCTI. الافتراضي هو /dev/tpm0.

مثال: -T device:/dev/tpm0 أو export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: بالنسبة لـ mssim TCTI، يمكن تحديد اسم النطاق أو عنوان IP ورقم المنفذ الذي يستخدمه المحاكي. الافتراضي هو 127.0.0.1 و 2321.

مثال: -T mssim:host=localhost,port=2321 أو export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: بالنسبة لـ abrmd TCTI، يكون تنسيق سلسلة التكوين عبارة عن سلسلة من أزواج المفاتيح والقيمة البسيطة مفصولة بفاصلة `,'. يتم فصل كل مفتاح وسلسلة قيمة بـ `=`.
•
يدعم TCTI abrmd مفتاحين:
1.
`bus_name': اسم خدمة tabrmd على الناقل (سلسلة).
2.
`bus_type': نوع مثيل dbus (سلسلة) محدود بـ `session' و `system'.

حدد اسم tcti tabrmd وسلسلة تكوين bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

حدد tcti الافتراضي (abrmd) وسلسلة تكوين bus_type=session:

\--tcti:bus_type=session

ملاحظة: abrmd و tabrmd مترادفان. وحدات TCTI المعروفة المختلفة.

ابدأ جلسة سياسة وأعد تشغيلها، وافتح بعض البيانات.

NAME

tpm2_policyrestart

reset the policy digest to its initial state

SYNOPSIS

tpm2_policyrestart -S <session> [-h] [-v]

DESCRIPTION

The tpm2_policyrestart command restarts the policy session by resetting the policy digest to its initial state. This command is useful when a policy check fails and you want to retry the policy check, or when you want to cancel the current policy checks and start over.

This command should be used after a policy check fails. The failure is typically indicated by a non-zero return code from the TPM.

It expects a session to be already established via tpm2_startauthsession(1) and requires one of the following:

  • direct device access
  • extended session support with tpm2-abrmd.

Without it, most resource managers will not save session state between command invocations.

OPTIONS

-S

The session file created by tpm2_startauthsession or a session capability string from tpm2_getcap. This option is mandatory.

-h
Help information.
-v
Verbosity verbosity.

COMMON OPTIONS

These options are common to most of the TPM tools. They are explained in the tpm2_tool_options(1) manual page.

TCTI CONFIGURATION

The TPM communication channel (TCTI) can be configured using environment variables or options. For more details, see the tpm2_tcti(7) manual page.

TCTI OPTIONS

These options are specific to the TCTI configuration and are explained in the tpm2_tcti(7) manual page.

EXAMPLES

The following example shows how to use tpm2_policyrestart to reset a policy session after a failed unseal operation.

First, create a policy session and bind it to an object:

# create a policy and bind it to an object
tpm2_startauthsession -S session.dat
tpm2_policypcr -S session.dat -l "sha1:0,1,2,3" -L policy.dat
tpm2_createprimary -c primary.ctx
tpm2_create -Cprimary.ctx -u key.pub -r key.priv -L policy.dat -i- <<< "secret"
tpm2_load -C primary.ctx -c key.ctx -u key.pub -r key.priv
tpm2_flushcontext session.dat

Next, satisfy the policy and attempt to unseal the object:

# satisfy the policy and use the object
tpm2_startauthsession --policy -S session.dat
tpm2_policypcr -S session.dat -l "sha1:0,1,2,3"
# PCR event occurs here causing unseal to fail
tpm2_pcrevent 0 <<< "event data"
tpm2_unseal -psession:session.dat -c key.ct

The unseal operation will fail because the PCRs have changed:

ERROR: Esys_Unseal(0x128) - tpm:error(2.0): PCR have changed since checked

Now, clear the policy digest to its initial state using tpm2_policyrestart:

# Clear the policy digest to initial state, note access to object no longer allowed by
# policy so policyor would be useful here.
tpm2_policyrestart -S session.dat

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.

Limitations

It expects a session to be already established via tpm2_startauthsession(1) and requires one of the following:

•
direct device access
•
extended session support with tpm2-abrmd.

Without it, most resource managers will not save session state between command invocations.
