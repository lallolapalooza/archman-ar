tpm2_hmac(1)

الحزمة: tpm2-tools

التراخيص: BSD-3-Clause

NAME

tpm2_hmac - Perform an HMAC operation

SYNOPSIS

tpm2_hmac [OPTION]... DATA_FILE

DESCRIPTION

tpm2_hmac is used to perform an HMAC operation. An HMAC (keyed-hash message authentication code) is a specific type of message authentication code involving a cryptographic hash function in combination with a secret cryptographic key. It can also be used as a pseudo-random number generator.

This command requires a key that was created with a signing capability and an associated HMAC scheme. For example, using tpm2_create with the -G hmac option.

OPTIONS

The behavior of tpm2_hmac is controlled by TCTI selection and common options. TCTI selection is done via the tpm2_tool.conf(5) configuration file or the command line options.

The following are options to generate a key:
-C context object
the context object for the primary or parent key.
-G algorithm
the HMAC algorithm. Supported values are sha1, sha256, sha384, sha512.
-c context file
path to load the context object from.
--hex
output the digest in hexidecimal format.

Context Object Format

The context object can be a file path, or a handle[:password] that represents a loaded object in the TPM. The handle can be one of the following:

0x8001
TPM_RH_OWNER
0x8002
TPM_RH_ENDORSEMENT
0x8003
TPM_RH_PLATFORM
0x8004
TPM_RH_NULL
0x8005
TPM_RH_LOCKOUT
0x8006
TPM_RH_RESERVED1
0x8007
TPM_RH_NA

If the key object is not persistent, it can be specified as handle:password. If the password is not specified, it defaults to empty.

COMMON OPTIONS

See tpm2_tool.conf(5) for common options.

TCTI Configuration

The TPM communication channel (TCTI) can be configured in multiple ways:

TCTI OPTIONS

-z tcti-list
a list of TCTI specifications separated by colons.
Supported TCTIs include:
mssim
The `mssim` TCTI connects to a TPM simulator via TCP/IP.
device
The `device` TCTI connects to a device like `/dev/tpm0`.
socket
The `socket` TCTI connects to a remote TPM via TCP/IP.
libtss
The `libtss` TCTI uses libtss to connect to the TPM.
file
The `file` TCTI reads TPM commands from a file.
The device TCTI may be configured using environment variables like:
TPM2_DEVICE_FILE
Path to the TPM device node (default: /dev/tpm0).
TPM2_DEVICE_GRANULARITY
Granularity of the device (default: auto).
TPM2_DEVICE_NUMBER_RETRYS
Number of retries for device access (default: 3).
The socket TCTI may be configured using environment variables like:
TPM2_SOCKET_ADDRESS
The IP address or hostname of the remote TPM (default: 127.0.0.1).
TPM2_SOCKET_PORT
The port number of the remote TPM (default: 2321).
The mssim TCTI is functionally identical to socket TCTI.

You can also use the tcti-device, tcti-socket, and tcti-mssim options to directly configure TCTI parameters. See tpm2_tool.conf(5) for more details on how to specify TCTI options.

The tool will attempt to use the default TCTI if no TCTI options are specified. The default TCTI is determined by the build configuration and may prioritize device over socket or mssim.

The tpm2_hmac command uses the tpm2-abrmd resource manager by default if available. You can disable it by passing the tcti=device option.

See tpm2_tool.conf(5) for more details on TCTI configuration and supported TCTIs known to us known TCTI modules.

EXAMPLES

Setup

# create a primary object
tpm2_createprimary -c primary.ctx
# create an hmac key
tpm2_create -C primary.ctx -G hmac -c hmac.key

Perform an HMAC with Default Hash Algorithm

Perform an hmac using the key’s default scheme (hash algorithm) and output to stdout in hexidecimal format.

tpm2_hmac -c hmac.key --hex data.in
e6eda48a53a9ddbb92f788f6d98e0372d63a408afb11aca43f522a2475a32805
