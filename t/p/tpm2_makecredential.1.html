tpm2_makecredential(1) دليل الأوامر العامة tpm2_makecredential(1)

الاسم

tpm2_makecredential(1) - إنشاء البيانات-المشفرة-المختارة-من-قبل-المستخدم والبيانات-الملفوفة-لمفتاح-تشفير-البيانات السرية لعملية إصدار الشهادات الحساسة للخصوصية لكائن TPM.

الملخص

tpm2_makecredential [خيارات]

الوصف

tpm2_makecredential(1) - يدعم TPM بروتوكولًا يحافظ على الخصوصية لتوزيع الشهادات لمفاتيح على TPM. تضمن العملية أن كائن-TPM-المُصدق (AIK) محمل على نفس TPM مثل كائن-المفتاح-العام-المعروف (EK) دون معرفة الخصائص العامة المحددة لكائن-TPM-المُصدق (AIK). الخصوصية مضمونة نظرًا لحقيقة أنه تتم مشاركة اسم كائن-TPM-المُصدق (AIK) فقط وليس المفتاح العام لكائن-TPM-المُصدق نفسه.

Make-credential هي الخطوة الأولى في هذه العملية حيث، بعد تلقي المفتاح العام لكائن-المفتاح-العام (EK) الخاص بـ TPM واسم كائن-TPM-المُصدق (AIK)، يتم إنشاء بيانات-مشفرة-مختارة-من-قبل-المستخدم ويتم إنشاء مفتاح-تشفير-البيانات السرية ولفه باستخدام عمليات تشفير خاصة بتنشيط الشهادات التي تضمن تحميل كائن-TPM-المُصدق (AIK) على TPM مع كائن-المفتاح-العام-المعروف (EK).

يمكن استخدام tpm2_makecredential لإنشاء البيانات-المشفرة-المختارة-من-قبل-المستخدم ومفتاح-تشفير-البيانات السرية الملفوف بدون TPM باستخدام خيار TCTI none.

خيارات

•
-e, --encryption-key=ملف:

مهمل، استخدم -u أو --public بدلاً من ذلك.

•
-u, --public=ملف:

مفتاح TPM عام تم استخدامه لتغليف البذرة. ملاحظة: هذا الخيار هو نفسه -e وتمت إضافته لجعله مشابهًا للأدوات الأخرى التي تحدد المفتاح العام. تم الاحتفاظ بالخيار القديم للتوافق مع الإصدارات السابقة.

•
-G, --key-algorithm=خوارزمية:

خوارزمية المفتاح المرتبطة بمفتاح TPM العام. حدد RSA أو ECC. عند استخدام هذا الخيار، يُتوقع أن يكون المفتاح العام المدخل بتنسيق PEM ويتم استخدام قالب TCG EK الافتراضي لخصائص المفتاح.

•
-s, --secret=ملف أو STDIN:

السر الذي سيتم حمايته بواسطة المفتاح المشتق من البذرة العشوائية. يمكن تحديده كملف أو تمريره من stdin.

•
-n, --name=ملف:

اسم المفتاح الذي سيتم إنشاء شهادة له.

•
-o, --credential-blob=ملف:

مسار ملف الإخراج، لتسجيل البيانات-المشفرة-المختارة-من-قبل-المستخدم ومفتاح-تشفير-البيانات السرية الملفوف.

خيارات مشتركة

هذه المجموعة من الخيارات مشتركة بين العديد من البرامج وتوفر معلومات قد يتوقعها العديد من المستخدمين.

•
-h, --help=[man|no-man]: عرض دليل الأداة. افتراضيًا، تحاول استدعاء مدير الدليل للأداة، ولكن عند الفشل ستخرج ملخصًا قصيرًا للأداة. هذا هو نفس السلوك إذا تم تحديد وسيطة الخيار "man"، ولكن إذا تم طلب "man" صراحةً، فستوفر الأداة أخطاء من man على stderr. إذا تم تحديد الخيار "no-man" صراحةً، أو فشل مدير الدليل، فسيتم إخراج الخيارات القصيرة إلى stdout.

للاستخدام الناجح لميزة الدليل، يتطلب تثبيت الدليل أو أن يكون على MANPATH، انظر man(1) لمزيد من التفاصيل.

•
-v, --version: عرض معلومات الإصدار لهذه الأداة، و TCTIs المدعومة والخروج.
•
-V, --verbose: زيادة المعلومات التي تطبعها الأداة إلى وحدة التحكم أثناء تنفيذها. عند استخدام هذا الخيار، تتم طباعة رقم الملف والسطر.
•
-Q, --quiet: إسكات الإخراج العادي للأداة إلى stdout.
•
-Z, --enable-errata: تمكين تطبيق إصلاحات الأخطاء. مفيد إذا كان هناك حاجة لتطبيق إصلاح خطأ على الأوامر المرسلة إلى TPM. التعريف البيئي TPM2TOOLS_ENABLE_ERRATA يعادل ذلك.
•
-R, --autoflush: تمكين التفريغ التلقائي للكائنات المؤقتة التي تم إنشاؤها بواسطة الأمر. إذا تم تحميل كائن أب من ملف سياق، فسيتم أيضًا تفريغ الكائن الأب المؤقت. يمكن أيضًا تنشيط التفريغ التلقائي إذا تم تعيين متغير البيئة TPM2TOOLS_AUTOFLUSH إلى yes أو true.

تكوين TCTI

TCTI أو "واجهة النقل" هي آلية الاتصال مع TPM. يمكن تغيير TCTIs للاتصال بـ TPMs عبر وسائط مختلفة.

للتحكم في TCTI، تحترم الأدوات:

1.
خيار سطر الأوامر -T أو --tcti
2.
متغير البيئة: TPM2TOOLS_TCTI.

ملاحظة: يتجاوز خيار سطر الأوامر دائمًا متغير البيئة.

TCTIs المعروفة حاليًا هي:

•
tabrmd - مدير الموارد، يسمى tabrmd. لاحظ أن tabrmd و abrmd كاسم tcti مترادفان.
•
mssim - يستخدم عادةً للاتصال بمحاكي برنامج TPM.
•
device - يستخدم عند التحدث مباشرة إلى ملف جهاز TPM.
•
none - لا تهيئ الاتصال بـ TPM. تسمح بعض الأدوات بخيارات خارج TPM وبالتالي تدعم عدم استخدام TCTI. الأدوات التي لا تدعمها ستعرض خطأ عند محاولة استخدامها بدون اتصال TCTI. لا تدعم أي خيارات ويجب تقديمها كنص دقيق "none".

الوسائط لأي من خيار سطر الأوامر أو متغير البيئة تكون بالشكل:

<tcti-name>:<tcti-option-config>

تحديد سلسلة فارغة لأي من <tcti-name> أو <tcti-option-config> ينتج عنه استخدام القيمة الافتراضية لتلك الجزء على التوالي.

الافتراضات TCTI

عند عدم تحديد TCTI، يتم البحث عن TCTI الافتراضي باستخدام دلالات dlopen(3). ستبحث الأدوات عن TCTIs tabrmd و device و mssim بهذا الترتيب و تستخدم أول واحد تم العثور عليه. يمكنك الاستعلام عن TCTI الذي سيتم اختياره كافتراضي باستخدام الخيار -v لطباعة معلومات الإصدار. سيشير زوج المفتاح والقيمة "default-tcti" إلى أي من TCTIs المذكورة أعلاه هو الافتراضي.

TCTIs المخصصة

يمكن تحميل أي TCTI ينفذ واجهة TCTI الديناميكية. تستخدم الأدوات داخليًا dlopen(3)، ويتم استخدام القيمة الخام tcti-name للبحث. وبالتالي، يمكن أن يكون هذا مسارًا للمكتبة المشتركة، أو اسم مكتبة كما تفهمها دلالات dlopen(3).

خيارات TCTI

تُستخدم هذه المجموعة من الخيارات لتكوين وحدات TCTI المختلفة المعروفة المتاحة:

•
device: بالنسبة لـ device TCTI، يمكن تحديد ملف جهاز TPM للاستخدام بواسطة device TCTI. الافتراضي هو /dev/tpm0.

مثال: -T device:/dev/tpm0 أو export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: بالنسبة لـ mssim TCTI، اسم النطاق أو عنوان IP ورقم المنفذ المستخدم بواسطة th

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

tpm2_makecredential(1)

NAME

tpm2_makecredential

-- create a credential blob

SYNOPSIS

tpm2_makecredential [OPTIONS] [ARGUMENTS]

DESCRIPTION

The tpm2_makecredential tool is used to create a credential blob.

A credential blob is a data structure that contains arbitrary data, encrypted with the public key of an Endorsement Key (EK) or Attestation Key (AK). The TPM will decrypt this blob if the correct key is used, and return the decrypted data.

The credential blob is created by the host using the public key of the EK or AK, and is then sent to the TPM. The TPM will then use the corresponding private key to decrypt the blob.

The credential blob contains the following fields:

  • credential: A JSON object containing the credential data. The data can be any valid JSON data.
  • policy: A JSON object containing the policy data. The policy data can be any valid JSON data.
  • extraData: A string containing extra data. This data is not encrypted by the TPM.

The credential blob is signed by the host using the private key of the EK or AK. The signature is then verified by the TPM.

OPTIONS

tpm2_makecredential accepts the following options:

-C <handle>, --child-context=<handle>
Load the child context of a primary key or other key object. This is required if you are creating a credential for an AK that was created under a primary key.
-u <file>, --public=<file>
The path to the file containing the public key of the EK or AK. This file can be in PEM or DER format.
-p <password>, --password=<password>
The password for the primary key or other key object. This is required if the key is password protected.
-s, --sign
Sign the credential blob with the private key of the EK or AK. This is required if you want to verify the credential blob on the TPM.
-n <name>, --name=<name>
The name of the EK or AK. This is required if you are signing the credential blob.
-o <file>, --output=<file>
The path to the file where the credential blob will be saved. If not specified, the credential blob will be printed to stdout.
-G <type>, --key-alg=<type>
The algorithm of the EK or AK. This is required if you are signing the credential blob.
-l, --pem
Read the public key in PEM format.
-r, --raw
Read the public key in raw format.
-f <format>, --format=<format>
The format of the public key. Can be pem or raw.
-Q, --quiet
Suppress output.
-v, --version
Print program version and exit.
-h, --help
Print program help and exit.

COMMON OPTIONS

See tpm2_tool(1) for common options.

TCTI Configuration

The TPM Communication Transport Interface (TCTI) can be specified using the -T option or the TPM2TOOLS_TCTI environment variable. The TCTI is used to communicate with the TPM.

The following TCTIs are supported:

mssim: For the mssim TCTI, the configuration string is a comma separated list of key-value pairs. The supported keys are host and port. The default values for host and port are 127.0.0.1 and 2321 respectively. The simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous.

EXAMPLES

tpm2 createek -Q -c 0x81010009 -G rsa -u ek.pub
tpm2 createak -C 0x81010009 -c ak.ctx -G rsa -g sha256 -s rsassa -u ak.pub \
-n ak.name -p akpass> ak.out
file_size=`ls -l ak.name | awk {'print $5'}`
loaded_key_name=`cat ak.name | xxd -p -c $file_size`
tpm2 readpublic -c 0x81010009 -o ek.pem -f pem -Q
echo "12345678" | tpm2 makecredential -Q -u ek.pem -s - -n $loaded_key_name \
-o mkcred.out -G rsa

Returns

Tools can return any of the following codes:

0 - Success.
1 - General non-specific error.
2 - Options handling error.
3 - Authentication error.
4 - TCTI related error.
5 - Non supported scheme. Applicable to tpm2_testparams.
