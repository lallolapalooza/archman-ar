الاسم

tpm2_nvwritelock(1) - قفل فهرس الذاكرة غير المتطايرة (NV) للكتابة لاحقة.

الملخص

tpm2_nvwritelock [خيارات] [وسيط]

الوصف

tpm2_nvwritelock(1) - قفل فهرس الذاكرة غير المتطايرة (NV) للكتابة لاحقة. يتم فتح القفل على فهرس NV عند إعادة تشغيل TPM ويصبح فهرس NV قابلاً للكتابة مرة أخرى. يمكن تحديد الفهرس كمعالج خام أو قيمة إزاحة لنطاق معالج nv "TPM2_HR_NV_INDEX".

الخيارات

•
-C, --hierarchy=OBJECT:

يحدد الهيكل المستخدم للتفويض. الخيارات المدعومة هي:

•
o لـ TPM_RH_OWNER
•
p لـ TPM_RH_PLATFORM
•
<num> حيث يمكن استخدام معالج هيكل أو فهرس nv.

عندما لا يتم تمرير -C صراحةً، سيتم استخدام معالج الفهرس للتفويض ضد الفهرس. يتم تعيين قيمة المصادقة للفهرس عبر الخيار -p إلى tpm2_nvdefine(1).

•
-P, --auth=AUTH:

يحدد قيمة المصادقة للهيكل.

•
--global:

يقفل جميع فهارس NV مع سمة TPMA_NV_GLOBALLOCK. لا يتطلب هذا الخيار فهرس NV أو إزاحة كوسيط.

•
--cphash=FILE

مسار الملف لتسجيل تجزئة معلمات الأمر. يُشار إلى هذا عادةً باسم cpHash. ملاحظة: عند تحديد هذا الخيار، لن يقوم الأداة بتنفيذ الأمر فعليًا، بل سيعيد ببساطة cpHash ما لم يكن rphash مطلوبًا أيضًا.

•
--rphash=FILE

مسار الملف لتسجيل تجزئة معلمات الاستجابة. يُشار إلى هذا عادةً باسم rpHash.

•
-S, --session=FILE:

الجلسة التي تم إنشاؤها باستخدام tpm2_startauthsession. يمكن استخدام هذا لتحديد جلسة مساعدة للتدقيق و/أو تشفير/فك تشفير المعلمات.

•
-n, --name=FILE:

اسم فهرس NV الذي يجب تقديمه عند حساب cpHash فقط دون إرسال الأمر فعليًا إلى TPM.

•
ARGUMENT يحدد وسيط سطر الأوامر فهرس NV أو رقم الإزاحة.

المراجع

تنسيق كائن السياق

يتم تحديد نوع كائن السياق، سواء كان معالجًا أو اسم ملف، وفقًا للمنطق التالي *بالترتيب*:

•
إذا كان الوسيط مسار ملف، فسيتم تحميل الملف ككائن TPM عابر مستعاد.
•
إذا كان الوسيط يطابق *بادئة* لأحد:
•
owner: الهيكل المالك
•
platform: هيكل المنصة
•
endorsement: هيكل المصادقة
•
lockout: الكائن المستمر للتحكم في القفل
•
إذا كان الوسيط يمكن تحميله كرقم، فسيتم التعامل معه كمعالج، على سبيل المثال 0x81010013 وسيتم استخدامه مباشرة. *OBJECT*.

تنسيق المصادقة

يمكن أن تأتي المصادقة لاستخدام كائن في TPM2.0 في 3 أشكال مختلفة: 1. كلمة مرور 2. HMAC 3. جلسات

ملاحظة: "كلمات المرور افتراضيًا إلى كلمة المرور الفارغة عند عدم تحديدها."

كلمات المرور

يتم تفسير كلمات المرور في الأشكال التالية أدناه باستخدام معرفات البادئة.

ملاحظة: افتراضيًا، يُفترض أن تكون كلمات المرور في شكل سلسلة عندما لا تحتوي على بادئة.

سلسلة نصية

كلمة مرور كسلسلة نصية، محددة بالبادئة "str:" أو غيابها (سلسلة خام بدون بادئة) لا يتم تفسيرها، وتستخدم مباشرة للمصادقة.

أمثلة

foobar
str:foobar

سلسلة سداسية عشرية

كلمة مرور كسلسلة سداسية عشرية، محددة بالبادئة "hex:"، يتم تحويلها من شكل سداسي عشري إلى شكل مصفوفة بايت، وبالتالي السماح بكلمات المرور التي تحتوي على أحرف غير قابلة للطباعة و/أو غير ودية للطرفية.

مثال

hex:1122334455667788

ملف

كلمة مرور تستند إلى ملف، محددة بالبادئة "file:"، يجب أن تكون مسار ملف يحتوي على كلمة المرور ليتم قراءتها بواسطة الأداة أو "-" لاستخدام الإدخال القياسي. يؤدي تخزين كلمات المرور في ملفات إلى منع تسرب المعلومات، ويمكن قراءة كلمات المرور المقدمة كخيارات من قائمة العمليات أو ميزات سجل الأوامر الشائعة.

أمثلة

# لاستخدام الإدخال القياسي والمطالبة به
file:-
# لاستخدام ملف من مسار
file:path/to/password/file
# لإرسال كلمة مرور عبر الإدخال القياسي:
echo foobar | tpm2_tool -p file:-
# لاستخدام سلسلة Bash هنا عبر الإدخال القياسي:
tpm2_tool -p file:- <<< foobar

الجلسات

عند استخدام جلسة سياسة لتفويض استخدام كائن، قم ببادئة وسيط الخيار بكلمة session. ثم قم بتحديد مسار لملف جلسة تم إنشاؤه باستخدام tpm2_startauthsession(1). اختياريًا، إذا كانت الجلسة تتطلب قيمة مصادقة لإرسالها مع معالج الجلسة (مثل كلمة مرور السياسة)، فقم بإلحاق + وسلسلة كما هو موضح في قسم كلمات المرور.

أمثلة

لاستخدام ملف سياق جلسة يسمى session.ctx.

session:session.ctx

لاستخدام ملف سياق جلسة يسمى session.ctx *و* إرسال قيمة المصادقة mypassword.

session:session.ctx+mypassword

لاستخدام ملف سياق جلسة يسمى session.ctx *و* إرسال قيمة المصادقة السداسية العشرية 0x11223344.

session:session.ctx+hex:11223344

مصادقات PCR

يمكنك تلبية سياسة PCR باستخدام البادئة "pcr:" ولغة PCR المصغرة. لغة PCR المصغرة هي كما يلي: <pcr-spec>=<raw-pcr-file>

مواصفات PCR موثقة في القسم "محدِّدات بنك PCR".

الملف raw-pcr-file هو وسيط *اختياري* يحتوي على إخراج محتويات PCR الخام كما تم إرجاعها بواسطة tpm2_pcrread(1).

NAME

tpm2_nvwritelock - write lock an index of NV memory

SYNOPSIS

tpm2_nvwritelock [-h|--help] [-V|--version] [-v|--verbose] [-Q|--quiet] [-T TCTI|--tcti=TCTI] [-c context|--context=context] [-f|--force] [-s size|--size=size] [-p policy|--policy=policy] [-P auth|--auth=auth] [-l policy|--policy-file=policy] [-I filename|--input-file=filename] [-r policy|--policy-digest=policy] [-i index|--index=index] [--global]

DESCRIPTION

The tpm2_nvwritelock command is used to write lock an index of NV memory. This is a permanent change and cannot be undone. The write lock prevents any further modifications to the NV index, including writing new data or changing its attributes.

To use this command, you must have the necessary authorization to modify the NV index. This typically involves providing the owner authorization value or a policy that grants write access.

Context Object Format

The context object is used to specify the loaded objects and state associated with the command. The format of the context object depends on the command that uses it. For NV index manipulation, the context object is typically specified by the owner authorization value.

owner:authValue

Where authValue is the authorization value for the owner.

Authorization Formatting

Authorization values can be specified in several ways:

•
As a string: e.g., -P secretsauce
•
As a file path containing the authorization string: e.g., -P file:auth.txt
•
As a policy digest: e.g., -r policy.digest
pcr:sha256:0,1,2,3
specifying AUTH.

TCTI Configuration

The TCTI or “Transmission Interface” is the communication mechanism with the TPM. TCTIs can be changed for communication with TPMs across different mediums.

To control the TCTI, the tools respect:

1.
The command line option -T or --tcti
2.
The environment variable: TPM2TOOLS_TCTI.

Note: The command line option always overrides the environment variable.

The current known TCTIs are:

•
tabrmd - The resource manager, called tabrmd. Note that tabrmd and abrmd as a tcti name are synonymous.
•
mssim - Typically used for communicating to the TPM software simulator.
•
device - Used when talking directly to a TPM device file.
•
none - Do not initalize a connection with the TPM. Some tools allow for off-tpm options and thus support not using a TCTI. Tools that do not support it will error when attempted to be used without a TCTI connection. Does not support ANY options and MUST BE presented as the exact text of “none”.

The arguments to either the command line option or the environment variable are in the form:

<tcti-name>:<tcti-option-config>

Specifying an empty string for either the <tcti-name> or <tcti-option-config> results in the default being used for that portion respectively.

TCTI Defaults

When a TCTI is not specified, the default TCTI is searched for using dlopen(3) semantics. The tools will search for tabrmd, device and mssim TCTIs IN THAT ORDER and USE THE FIRST ONE FOUND. You can query what TCTI will be chosen as the default by using the -v option to print the version information. The “default-tcti” key-value pair will indicate which of the aforementioned TCTIs is the default.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

EXAMPLES

Lock an index

tpm2_nvdefine -C o -s 32 \
  -a "ownerread|policywrite|ownerwrite" 1
echo "foobar" > nv.writelock
tpm2_nvwrite -C o -i nv.writelock 1
tpm2_nvwritelock -C o 1
# fails with "NV access locked"
tpm2_nvwrite -C o -i nv.writelock 1

Global Lock

tpm2_nvdefine -C o -s 32 \
  -a "ownerread|policywrite|ownerwrite|globallock" 1
tpm2_nvwritelock -C o --global
# this command fails with "NV access locked".
echo foo | tpm2_nvwrite -C o -i- 1
