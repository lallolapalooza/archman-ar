tpm2_policyauthorizenv(1) دليل الأوامر العام tpm2_policyauthorizenv(1)

الاسم

tpm2_policyauthorizenv(1) - يسمح بالسياسات القابلة للتغيير عن طريق الإشارة إلى سياسة من مؤشر NV.

الملخص

tpm2_policyauthorizenv [خيارات] [وسيط]

الوصف

tpm2_policyauthorizenv(1) - يسمح هذا الأمر بتغيير السياسات عن طريق الإشارة إلى سياسة التفويض المكتوبة في مؤشر NV. يجب أن يظل المؤشر الذي يحتوي على سياسة التفويض قابلاً للقراءة حتى لجلسة التجربة. يمكن تحديد المؤشر كمقبض خام أو قيمة إزاحة لنطاق مؤشر nv “TPM2_HR_NV_INDEX”.

الخيارات

•
-C, --hierarchy=OBJECT:

يحدد التسلسل الهرمي المستخدم للتفويض. الخيارات المدعومة هي:

•
o لـ TPM_RH_OWNER
•
p لـ TPM_RH_PLATFORM
•
<رقم> حيث يمكن استخدام مقبض التسلسل الهرمي أو مؤشر nv.

عندما لا يتم تمرير -C بشكل صريح، سيتم استخدام مقبض المؤشر للتفويض مقابل المؤشر. يتم تعيين قيمة تفويض المؤشر عبر الخيار -p لـ tpm2_nvdefine(1).

•
-P, --auth=AUTH:

يحدد قيمة التفويض للتسلسل الهرمي.

•
-L, --policy=FILE:

الملف لحفظ هضم السياسة.

•
-S, --session=FILE:

ملف جلسة السياسة الذي تم إنشاؤه عبر الخيار -S لـ tpm2_startauthsession(1).

•
--cphash=FILE

مسار الملف لتسجيل هضم معلمات الأمر. يُشار إلى هذا عادةً باسم cpHash. ملاحظة: عند تحديد هذا الخيار، لن يقوم الأداة بتنفيذ الأمر فعليًا، بل ستعيد فقط cpHash.

المراجع

خيارات شائعة

تُستخدم هذه المجموعة من الخيارات في العديد من البرامج وتوفر معلومات قد يتوقعها العديد من المستخدمين.

•
-h, --help=[man|no-man]: عرض دليل الأداة. افتراضيًا، تحاول استدعاء عارض الدليل للأداة، ولكن عند الفشل، ستعرض ملخصًا قصيرًا للأداة. هذا هو نفس السلوك إذا تم تحديد الوسيط "man"، ولكن إذا تم طلب "man" صريحًا، فستعرض الأداة الأخطاء من man على stderr. إذا تم تحديد الخيار "no-man"، أو فشل عارض الدليل، فسيتم إخراج الخيارات القصيرة إلى stdout.

يتطلب استخدام ميزة الدليل بنجاح تثبيت الدلائل أو وجودها في MANPATH. راجع man(1) لمزيد من التفاصيل.

•
-v, --version: عرض معلومات الإصدار لهذه الأداة، tctis المدعومة والخروج.
•
-V, --verbose: زيادة المعلومات التي تطبعها الأداة إلى وحدة التحكم أثناء تنفيذها. عند استخدام هذا الخيار، يتم طباعة رقم الملف والسطر.
•
-Q, --quiet: إسكات الإخراج العادي للأداة إلى stdout.
•
-Z, --enable-errata: تمكين تطبيق تصحيحات الأخطاء. مفيد إذا كان يجب تطبيق تصحيح خطأ على الأوامر المرسلة إلى TPM. التعريف البيئي TPM2TOOLS_ENABLE_ERRATA يعادل ذلك.
•
-R, --autoflush: تمكين التفريغ التلقائي للكائنات المؤقتة التي تم إنشاؤها بواسطة الأمر. إذا تم تحميل كائن أب من ملف سياق، فسيتم أيضًا تفريغ الكائن الأب المؤقت. يمكن أيضًا تنشيط التفريغ التلقائي إذا كان متغير البيئة TPM2TOOLS_AUTOFLUSH مضبوطًا على "yes" أو "true".

تهيئة TCTI

TCTI أو "واجهة النقل" هي آلية الاتصال مع TPM. يمكن تغيير TCTIs للاتصال بـ TPMs عبر وسائط مختلفة.

للتحكم في TCTI، تحترم الأدوات:

1.
خيار سطر الأوامر -T أو --tcti
2.
متغير البيئة: TPM2TOOLS_TCTI.

ملاحظة: يتجاوز خيار سطر الأوامر دائمًا متغير البيئة.

TCTIs المعروفة حاليًا هي:

•
tabrmd - مدير الموارد، يسمى tabrmd. لاحظ أن tabrmd و abrmd كاسم tcti مترادفان.
•
mssim - يستخدم عادةً للتواصل مع محاكي برامج TPM.
•
device - يستخدم عند التحدث مباشرة إلى ملف جهاز TPM.
•
none - لا تقم بتهيئة اتصال مع TPM. تسمح بعض الأدوات بخيارات خارج TPM وتدعم بذلك عدم استخدام TCTI. الأدوات التي لا تدعمها ستعرض خطأ عند محاولة استخدامها بدون اتصال TCTI. لا تدعم أي خيارات ويجب تقديمها كنص حرفي "none".

تكون وسائط الخيار سطر الأوامر أو متغير البيئة بالشكل:

<اسم-tcti>:<تهيئة-خيارات-tcti>

يشير تحديد سلسلة فارغة لـ <اسم-tcti> أو <تهيئة-خيارات-tcti> إلى استخدام الافتراضي لتلك الجزء على التوالي.

افتراضيات TCTI

عند عدم تحديد TCTI، يتم البحث عن TCTI الافتراضي باستخدام دلالات dlopen(3). ستبحث الأدوات عن TCTIs tabrmd، device و mssim بهذا الترتيب وتستخدم أول واحدة يتم العثور عليها. يمكنك الاستعلام عن TCTI الذي سيتم اختياره كافتراضي باستخدام الخيار -v لعرض معلومات الإصدار. سيشير زوج المفتاح والقيمة "default-tcti" إلى أي من TCTIs المذكورة أعلاه هو الافتراضي.

TCTIs مخصصة

يمكن تحميل أي TCTI يطبق واجهة TCTI الديناميكية. تستخدم الأدوات داخليًا dlopen(3)، ويتم استخدام قيمة tcti-name الخام للبحث. وبالتالي، يمكن أن يكون هذا مسارًا إلى المكتبة المشتركة، أو اسم مكتبة كما تفهمها دلالات dlopen(3).

خيارات TCTI

تُستخدم هذه المجموعة من الخيارات لتهيئة وحدات TCTI المختلفة المعروفة المتاحة:

•
device: بالنسبة لـ device TCTI، يمكن تحديد ملف جهاز TPM لاستخدامه بواسطة device TCTI. الافتراضي هو /dev/tpm0.

مثال: -T device:/dev/tpm0 أو export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: بالنسبة لـ mssim TCTI، يمكن تحديد اسم النطاق أو عنوان IP ورقم المنفذ الذي يستخدمه المحاكي. الافتراضي هو 127.0.0.1 و 2321.

مثال: -T mssim:host=localhost,port=2321 أو export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: بالنسبة لـ abrmd TCTI، يكون تنسيق سلسلة التهيئة عبارة عن سلسلة من أزواج المفتاح والقيمة البسيطة مفصولة بحرف `,`. يتم فصل كل مفتاح وسلسلة قيمة بحرف `=`.
•
يدعم TCTI abrmd مفتاحين:
1.
port: المنفذ الذي يستخدمه abrmd. القيمة الافتراضية هي 2321.
2.
host: اسم المضيف أو عنوان IP الذي يستخدمه abrmd. القيمة الافتراضية هي 127.0.0.1.
tpm2_policyauthorizenv(1) — tpm2-tools

NAME

tpm2_policyauthorizenv - Set up a policy for authorization using NV Index.

SYNOPSIS

tpm2_policyauthorizenv [OPTIONS] [nvIndex]

DESCRIPTION

The tpm2_policyauthorizenv command is used to set up a policy for authorization using NV Index. This policy requires that the user provides the correct authorization for the specified NV Index. The authorization can be provided via a password or a policy session.

The command supports the following TCTI ( TPM Command Transmission Interface) modules:

tcti-device: Uses the TPM device node directly.
tcti-mssim: Uses the mssim simulator.
tcti-tabrmd: Uses the tabrmd daemon.

OPTIONS

-C
authValue or handle
The authorization value or handle for the NV Index. If not provided, the default authorization value is used.
-P
password
The authorization password for the NV Index. If not provided, the default authorization password is used.
-S
session
The session context file to use for the policy. If not provided, a new session is created.
-L
policy_file
The file to store the policy digest. If not provided, the policy digest is not stored.
-l
log_file
The file to log the policy operations. If not provided, no logging is performed.
-V
verbose
Enable verbose output.
-q
quiet
Disable all output.
--help
Print a help message and exit.
--version
Print version information and exit.

COMMON OPTIONS

See tpm2_options(7) for options common to all commands.

TCTI Configuration

The TCTI can be specified using the --tcti option. The default TCTI is tcti-device.

The TCTI configuration string can include the following parameters:

bus_name
The name of the tabrmd service on the bus (a string).
2.
bus_type: The type of the dbus instance (a string) limited to session and system.

TCTI OPTIONS

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

EXAMPLES

Create a policypassword and write the policy digest to an NV Index. Build a policyauthorizenv policy referencing the NV index in a trial session. The resultant policy digest is then used in creation of objects.

In a policy authorization session, first satisfy the policy written to the NV index. Then run the policyauthorizenv which satisfies the authorization for the object.

Define the test NV Index to store the auth policy

nv_test_index=0x01500001
tpm2_nvdefine -C o -p nvpass $nv_test_index -a "authread|authwrite" -s 34

Define the auth policy

tpm2_startauthsession -S session.ctx
tpm2_policypassword -S session.ctx -L policy.pass
tpm2_flushcontext session.ctx

Write the auth policy to the NV Index

echo "000b" | xxd -p -r | cat - policy.pass | \
tpm2_nvwrite -C $nv_test_index -P nvpass $nv_test_index -i-

Define the policyauthorizenv

tpm2_startauthsession -S session.ctx
tpm2_policyauthorizenv -S session.ctx -C $nv_test_index -P nvpass \
-L policyauthorizenv.1500001 $nv_test_index
tpm2_flushcontext session.ctx

Create and load a sealing object with auth policy = policyauthorizenv

tpm2_createprimary -C o -c prim.ctx
echo "secretdata" | \
tpm2_create -C prim.ctx -u key.pub -r key.priv \
-a "fixedtpm|fixedparent|adminwithpolicy" -L policyauthorizenv.1500001 -i-
tpm2_load -C prim.ctx -u key.pub -r key.priv -c key.ctx

Satisfy the auth policy stored in the NV Index and thus policyauthorizenv

tpm2_startauthsession -S session.ctx --policy-session
tpm2_policypassword -S session.ctx
tpm2_policyauthorizenv -S session.ctx -C $nv_test_index -P nvpass $nv_test_index
tpm2_unseal -c key.ctx -p session:session.ctx
tpm2_flushcontext session.ctx

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.

Limitations

It expects a session to be already established via tpm2_startauthsession(1) and requires one of the following:

•
direct device access
•
extended session support with tpm2-abrmd.

Without it, most resource managers will not save session state between command invocations.
