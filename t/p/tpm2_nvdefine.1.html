tpm2_nvdefine(1)

الحزمة: tpm2-tools

التراخيص: BSD-3-Clause

tpm2_nvdefine(1) دليل الأوامر العامة tpm2_nvdefine(1)

الاسم

tpm2_nvdefine(1) - تعريف فهرس TPM غير متطاير (NV).

ملخص

tpm2_nvdefine [خيارات] [وسيط]

الوصف

tpm2_nvdefine(1) - تعريف فهرس NV بقيمة مصادقة معطاة. يتم تحديد الفهرس كوسيط. يمكن تحديده كمقبض خام أو قيمة إزاحة لنطاق مقبض nv "TPM2_HR_NV_INDEX". إذا لم يتم تحديد فهرس، فإن الأداة تستخدم أول فهرس مجاني. تقوم الأداة بإخراج فهرس nv المعرف عند النجاح.

خيارات

•
-C, --hierarchy=OBJECT:

يحدد المقبض المستخدم للمصادقة. افتراضيًا إلى o، TPM_RH_OWNER، عند عدم تحديد قيمة. الخيارات المدعومة هي:

•
o لـ TPM_RH_OWNER
•
p لـ TPM_RH_PLATFORM
•
<num> حيث يمكن استخدام مقبض هرمي أو فهرس nv.
•
-s, --size=NATURAL_NUMBER:

يحدد حجم منطقة البيانات بالبايت. الافتراضي هو MAX_NV_INDEX_SIZE وهو عادة 2048.

•
-g, --hash-algorithm=ALGORITHM:

خوارزمية التجزئة المستخدمة لحساب اسم الفهرس والمستخدمة لسياسة المصادقة. إذا كان الفهرس فهرس امتداد، يتم استخدام خوارزمية التجزئة للامتداد.

•
-a, --attributes=ATTRIBUTES

يحدد قيم السمات لمنطقة nv المستخدمة عند إنشاء الكيان. يمكن استخدام قناع البت الخام أو "الأسماء اللطيفة". انظر القسم "سمات NV" لمزيد من التفاصيل. إذا لم يتم تحديدها، فإن السمات الافتراضية هي اختيارات مختلفة بناءً على الهرم الذي تم تعريف الفهرس فيه.

بالنسبة للهرم المالك الافتراضيات هي:

•
TPMA_NV_OWNERWRITE
•
TPMA_NV_OWNERREAD

بالنسبة لهرم المنصة، الافتراضيات هي:

•
TPMA_NV_PPWRITE
•
TPMA_NV_PPREAD

إذا تم تحديد ملف سياسة، فإن السمات الافتراضية المختارة للهرم يتم دمجها بالعمليات المنطقية (bitwise or) مع:

•
TPMA_NV_POLICYWRITE
•
TPMA_NV_POLICYREAD

إذا لم يتم تحديد ملف سياسة، فإن السمات الافتراضية المختارة للهرم يتم دمجها بالعمليات المنطقية (bitwise or) مع:

•
TPMA_NV_AUTHWRITE
•
TPMA_NV_AUTHREAD
•
-P, --hierarchy-auth=AUTH:

يحدد قيمة المصادقة للهرم. يجب أن تتبع قيم المصادقة "معايير تنسيق المصادقة"، انظر القسم "تنسيق المصادقة".

•
-p, --index-auth=AUTH:

يحدد كلمة مرور فهرس NV عند إنشائه. يجب أن تتبع قيم مصادقة HMAC وكلمة المرور "معايير تنسيق المصادقة"، انظر القسم "تنسيق المصادقة".

•
-L, --policy=FILE:

يحدد ملف ملخص السياسة لمصادقات السياسة.

•
--cphash=FILE

مسار الملف لتسجيل تجزئة معلمات الأمر. يُطلق على هذا عادةً cpHash. ملاحظة: عند تحديد هذا الخيار، لن تقوم الأداة بتنفيذ الأمر فعليًا، بل ستعيد ببساطة cpHash، ما لم يكن rphash مطلوبًا أيضًا.

•
--rphash=FILE

مسار الملف لتسجيل تجزئة معلمات الاستجابة. يُطلق على هذا عادةً rpHash.

•
-S, --session=FILE:

الجلسة التي تم إنشاؤها باستخدام tpm2_startauthsession. يمكن تحديد عدة من هذه. على سبيل المثال، يمكنك الحصول على جلسة واحدة للتدقيق وجلسة أخرى لتشفير/فك تشفير المعلمات.

•
ARGUMENT الوسيط في سطر الأوامر يحدد فهرس NV أو رقم الإزاحة.

المراجع

تنسيق كائن السياق

يتم تحديد نوع كائن السياق، سواء كان مقبضًا أو اسم ملف، وفقًا للمنطق التالي *بالترتيب*:

•
إذا كان الوسيط مسار ملف، يتم تحميل الملف ككائن TPM مؤقت مستعاد.
•
إذا كان الوسيط مطابقًا *بادئة* لأحد:
•
owner: الهرم المالك
•
platform: هرم المنصة
•
endorsement: هرم المصادقة
•
lockout: الكائن الثابت للتحكم في القفل
•
إذا كان يمكن تحميل الوسيط كرقم، فسيعتبر كمقبض، على سبيل المثال 0x81010013 وسيتم استخدامه مباشرة._OBJECT_.

تنسيق المصادقة

يمكن أن تأتي المصادقة لاستخدام كائن في TPM2.0 في 3 أشكال مختلفة: 1. كلمة مرور 2. HMAC 3. جلسات

ملاحظة: "تكون المصادقات افتراضيًا بكلمة المرور الفارغة عندما لا يتم تحديدها".

كلمات المرور

يتم تفسير كلمات المرور في الأشكال التالية أدناه باستخدام معرفات البادئة.

ملاحظة: افتراضيًا، يُفترض أن تكون كلمات المرور بتنسيق السلسلة عندما لا تحتوي على بادئة.

سلسلة

كلمة مرور سلسلة، محددة بالبادئة "str:" أو غيابها (سلسلة خام بدون بادئة) لا يتم تفسيرها، ويتم استخدامها مباشرة للمصادقة.

أمثلة

foobar
str:foobar

سلسلة سداسية عشرية

كلمة مرور سلسلة سداسية عشرية، محددة بالبادئة "hex:" يتم تحويلها من شكل سداسي عشري إلى شكل مصفوفة بايت، مما يسمح بكلمات المرور التي تحتوي على أحرف غير قابلة للطباعة و/أو غير ودية للطرفية.

مثال

hex:1122334455667788

ملف

كلمة مرور تستند إلى ملف، محددة بالبادئة "file:" يجب أن تكون المسار إلى ملف يحتوي على كلمة المرور ليتم قراءتها بواسطة الأداة أو "-" لاستخدام الإدخال القياسي. يؤدي تخزين كلمات المرور في الملفات إلى منع تسرب المعلومات، حيث يمكن قراءة كلمات المرور المقدمة كخيارات من قائمة العمليات أو ميزات سجل الأوامر الشائعة.

أمثلة

# لاستخدام الإدخال القياسي والمطالبة به
file:-
# لاستخدام ملف من مسار
file:path/to/password/file
# لإرسال كلمة مرور عبر الإدخال القياسي:
echo foobar | tpm2_tool -p file:-
# لاستخدام سلسلة bash عبر الإدخال القياسي:
tpm2_tool -p file:- <<< foobar

جلسات

عند استخدام جلسة سياسة لمصادقة استخدام o

tpm2_nvdefine(1) - Linux man manual page

NAME

tpm2_nvdefine - define NV index

SYNOPSIS 

    tpm2_nvdefine [-C context] [-u usage_policy] [-p auth_policy] [-r policy_session] [-S session] [-L pcr_policy] [-I index_attrs] index [size]

DESCRIPTION

tpm2_nvdefine is used to define a new NV index. NV indices are storage locations within the TPM that can be used for persistent storage. NV indices can be defined with different attributes related to their persistence, write/read policies, and authorization.

The NV index is a 32 bit value that is associated with a NV index. For example, 0x1000000 is the first index that can be defined.

The NV index size is also a parameter, which defines the maximum size in bytes that can be written to the index.

The NV index can be defined with various policies. These can either be loaded from a file or specified inline.

NV indices can be defined with various attributes. These attributes control the behavior of the NV index, such as whether it is permanent or temporary, and whether it can be written to or read from.

NV indices can also be defined with various authorization mechanisms. These mechanisms are used to control access to the NV index, and can include passwords, PCR values, and session policies.

OPTIONS

A list of options are available:

-C, --context=context

The context of the primary seed to use. This can be either the TPM_RH_OWNER, TPM_RH_ENDORSEMENT, TPM_RH_PLATFORM, or TPM_RH_NULL.

This option is used to specify the parent object that the NV index will be associated with. This allows for finer-grained control over the NV index's lifecycle and authorization.

-u, --usage=policy

The policy that dictates how the NV index can be used. This can be either a path to a policy file or an inline policy.

The policy can be a combination of:

ownerread
ownerwrite
policyread
policywrite
DefaultForbidden
no_write_locked
no_da
no_owner
-p, --password=password

The password for authorization of the NV index. This is used to authenticate the user or process attempting to access the NV index.

The password can be specified as a string or a hex value. If a hex value is specified, it must be prefixed with 'hex:'.

-r, --policy_session=policy_session

A policy session that will be used to authorize the use of the NV index. This is used in conjunction with the -p option to provide a more secure authorization mechanism.

The policy session is created using the tpm2_startauthsession command.

-S, --session=session

The session context for the TPM session. This is used to specify the session that will be used to authorize the command. The session is created using the tpm2_startauthsession command.

The session argument is prefixed with the session keyword. Then indicate a path to a session file that was created with tpm2_startauthsession(1). Optionally, if the session requires an auth value to be sent with the session handle (eg policy password), then append a + and a string as described in the Passwords section.

-L, --pcr_policy=pcr_policy

The PCR policy that will be used to authorize the use of the NV index. This is used in conjunction with the -p option to provide a more secure authorization mechanism.

The PCR policy is specified using the PCR minilanguage. The PCR minilanguage is as follows: <pcr-spec>=<raw-pcr-file>

The PCR spec is documented in in the section “PCR bank specifiers”.

The raw-pcr-file is an optional argument that contains the output of the raw PCR contents as returned by tpm2_pcrread(1).

PCR bank specifiers

-I, --index_attrs=index_attrs

Object Attributes are used to control various properties of created objects. When specified as an option, either the raw bitfield mask or “nice-names” may be used. The values can be found in Table 31 Part 2 of the TPM2.0 specification, which can be found here:

https://trustedcomputinggroup.org/wp-content/uploads/TPM-Rev-2.0-Part-2-Structures-01.38.pdf

Nice names are calculated by taking the name field of table 31 and removing the prefix TPMA_OBJECT_ and lowercasing the result. Thus, TPMA_OBJECT_FIXEDTPM becomes fixedtpm. Nice names can be joined using the bitwise or “|” symbol.

For instance, to set The fields TPMA_OBJECT_FIXEDTPM, TPMA_OBJECT_NODA, and TPMA_OBJECT_SIGN_ENCRYPT, the argument would be:

fixedtpm|noda|sign specifying the nv attributes ATTRIBUTES.

Session Formatting

To specify an authorization session, prefix the option argument with the session keyword. Then indicate a path to a session file that was created with tpm2_startauthsession(1). Optionally, if the session requires an auth value to be sent with the session handle (eg policy password), then append a + and a string as described in the Passwords section.

Examples

To use a session context file called session.ctx.

session:session.ctx

To use a session context file called session.ctx AND send the authvalue mypassword.

session:session.ctx+mypassword

To use a session context file called session.ctx AND send the HEX authvalue 0x11223344.

session:session.ctx+hex:11223344

PCR Authorizations

You can satisfy a PCR policy using the “pcr:” prefix and the PCR minilanguage. The PCR minilanguage is as follows: <pcr-spec>=<raw-pcr-file>

The PCR spec is documented in in the section “PCR bank specifiers”.

The raw-pcr-file is an optional argument that contains the output of the raw PCR contents as returned by tpm2_pcrread(1).

PCR bank specifiers

Examples

To satisfy a PCR policy of sha256 on banks 0, 1, 2 and 3 use a specifier of:

pcr:sha256:0,1,2,3

specifying AUTH.

Object Attributes

Object Attributes are used to control various properties of created objects. When specified as an option, either the raw bitfield mask or “nice-names” may be used. The values can be found in Table 31 Part 2 of the TPM2.0 specification, which can be found here:

https://trustedcomputinggroup.org/wp-content/uploads/TPM-Rev-2.0-Part-2-Structures-01.38.pdf

Nice names are calculated by taking the name field of table 31 and removing the prefix TPMA_OBJECT_ and lowercasing the result. Thus, TPMA_OBJECT_FIXEDTPM becomes fixedtpm. Nice names can be joined using the bitwise or “|” symbol.

For instance, to set The fields TPMA_OBJECT_FIXEDTPM, TPMA_OBJECT_NODA, and TPMA_OBJECT_SIGN_ENCRYPT, the argument would be:

fixedtpm|noda|sign specifying the nv attributes ATTRIBUTES.

TCTI Configuration

The TCTI or “Transmission Interface” is the communication mechanism with the TPM. TCTIs can be changed for communication with TPMs across different mediums.

To control the TCTI, the tools respect:

1.
The command line option -T or --tcti
2.
The environment variable: TPM2TOOLS_TCTI.

Note: The command line option always overrides the environment variable.

The current known TCTIs are:

•
tabrmd - The resource manager, called tabrmd. Note that tabrmd and abrmd as a tcti name are synonymous.
•
mssim - Typically used for communicating to the TPM software simulator.
•
device - Used when talking directly to a TPM device file.
•
none - Do not initalize a connection with the TPM. Some tools allow for off-tpm options and thus support not using a TCTI. Tools that do not support it will error when attempted to be used without a TCTI connection. Does not support ANY options and MUST BE presented as the exact text of “none”.

The arguments to either the command line option or the environment variable are in the form:

<tcti-name>:<tcti-option-config>

Specifying an empty string for either the <tcti-name> or <tcti-option-config> results in the default being used for that portion respectively.

TCTI Defaults

When a TCTI is not specified, the default TCTI is searched for using dlopen(3) semantics. The tools will search for tabrmd, device and mssim TCTIs IN THAT ORDER and USE THE FIRST ONE FOUND. You can query what TCTI will be chosen as the default by using the -v option to print the version information. The “default-tcti” key-value pair will indicate which of the aforementioned TCTIs is the default.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

EXAMPLES 

tpm2_nvdefine   0x1500016 -C o -s 32 -a 0x2000A
tpm2_nvdefine   0x1500016 -C o -s 32 -a ownerread|ownerwrite|policywrite -p 1a1b

tpm2_nvdefine(1) - Arch Linux

NAME

tpm2_nvdefine ― Define a TPM2 NV Index.

SYNOPSIS

tpm2_nvdefine [-C auth SESSION] [-i index] [-s size] [-p policy] [-r policy_rules] [-a attributes] [-l policy_list] [-P password] [-u password] [-U password] [-t password] [-o password] [-O password] [-n name] [-x policy] [-X policy] [-f file] [-f policy_file] [-t policy_file] [-T policy_file] [-p policy_file] [-r policy_file] [-l policy_file] [-x policy_file] [-X policy_file] [-F filename] [-S filename] [-L filename] [-P filename] [-R filename] [-I filename]

DESCRIPTION

The tpm2_nvdefine command is used to define a TPM2 NV index. NV indices are persistent memory locations within the TPM that can be used to store arbitrary data. NV indices can be defined with various attributes, such as size, policy requirements, and access permissions.

This command allows you to specify the NV index number, the size of the data to be stored, access policies, and other attributes. It is a fundamental tool for managing persistent data within the TPM.

OPTIONS

The following options are available:

  • -C auth SESSION: Specifies the authorization session to use for the command. This can be a session handle or a session file.
  • -i index: The NV index to define. This is a unique identifier for the NV index.
  • -s size: The size of the NV data in bytes.
  • -p policy: Specifies a policy that must be met to access the NV index. This can be a policy digest or a policy file.
  • -r policy_rules: Specifies policy rules for the NV index.
  • -a attributes: Bitmask of attributes for the NV index. Common attributes include:
    • 0x0001: TPM_NT_DEFINED
    • 0x0002: TPM_NT_PRIVACY_SECRET
    • 0x0004: TPM_NT_HW_AUTH
    • 0x0008: TPM_NT_USE_ORDERLY
    • 0x0010: TPM_NT_CHANGE_Repeated
    • 0x0020: TPM_NT_LOCKOUT
    • 0x0040: TPM_NT_OWNER
    • 0x0080: TPM_NT_AUTH_POLICY
    • 0x0100: TPM_NT_PLATFORM
    • 0x0200: TPM_NT_REMOTE_CONTROL
    • 0x0400: TPM_NT_ORDERLY
  • -l policy_list: A list of policies to be applied to the NV index.
  • -P password: The authorization password for the NV index.
  • -u password: The update password for the NV index.
  • -U password: The unbinding password for the NV index.
  • -t password: The transport password for the NV index.
  • -o password: The owner password for the NV index.
  • -O password: The primary owner password for the NV index.
  • -n name: The name of the NV index.
  • -x policy: Specifies a policy for read access.
  • -X policy: Specifies a policy for write access.
  • -f file: Reads NV data from a file.
  • -f policy_file: Reads policy data from a file.
  • -t policy_file: Reads policy data from a file.
  • -T policy_file: Reads policy data from a file.
  • -p policy_file: Reads policy data from a file.
  • -r policy_file: Reads policy data from a file.
  • -l policy_file: Reads policy data from a file.
  • -x policy_file: Reads policy data from a file.
  • -X policy_file: Reads policy data from a file.
  • -F filename: Specifies a file containing NV index definitions.
  • -S filename: Specifies a file containing session data.
  • -L filename: Specifies a file containing policy list data.
  • -P filename: Specifies a file containing password data.
  • -R filename: Specifies a file containing policy rules.
  • -I filename: Specifies a file containing NV index information.

Context Object Format

The context object format is a string that specifies the TPM context object to use. It can be a handle, a file path, or a string representation of the object.

Authorization Formatting

Authorization can be specified using a password, a policy digest, or a session. The format depends on the specific authorization method used.

Object Attributes

Object attributes are a set of flags that define the behavior and access permissions of an NV index. These attributes are specified using a bitmask.

COMMON OPTIONS

This command shares common options with other tpm2-tools commands, such as:

  • -h, --help: Display help information.
  • -v, --version: Display version information.
  • -T, --tcti: Specify the TPM communication interface (TCTI).
  • -d, --debug: Enable debug output.

TCTI Configuration

The TCTI (Tabernacle Configuration and Transport Interface) determines how the tool communicates with the TPM device. Common TCTIs include:

  • mssim: Software simulator.
  • device: Direct access to the TPM device.
  • socket: Communication over a network socket.

TCTI OPTIONS

TCTI-specific options can be passed using the -T flag followed by the TCTI name and its options.

EXAMPLES

Define an NV index with index 0x1000, size 16 bytes, and owner authorization:

tpm2_nvdefine -i 0x1000 -s 16 -a 0x0004 -P mysecretpassword

Define an NV index with a policy that requires a specific policy digest:

tpm2_nvdefine -i 0x1001 -s 32 -p policy_digest_hex -a 0x0080

Returns

Returns 0 on success, non-zero on failure.

BUGS

No known bugs.

الاسم

tpm2_nvdefine ― تعريف فهرس NV لـ TPM2.

ملخص

tpm2_nvdefine [-C جلسة مصادقة] [-i فهرس] [-s حجم] [-p سياسة] [-r قواعد السياسة] [-a سمات] [-l قائمة السياسات] [-P كلمة مرور] [-u كلمة مرور] [-U كلمة مرور] [-t كلمة مرور] [-o كلمة مرور] [-O كلمة مرور] [-n اسم] [-x سياسة] [-X سياسة] [-f ملف] [-f ملف السياسة] [-t ملف السياسة] [-T ملف السياسة] [-p ملف السياسة] [-r ملف السياسة] [-l ملف السياسة] [-x ملف السياسة] [-X ملف السياسة] [-F اسم الملف] [-S اسم الملف] [-L اسم الملف] [-P اسم الملف] [-R اسم الملف] [-I اسم الملف]

الوصف

يُستخدم الأمر tpm2_nvdefine لتعريف فهرس NV لـ TPM2. فهارس NV هي مواقع ذاكرة دائمة داخل TPM يمكن استخدامها لتخزين بيانات عشوائية. يمكن تعريف فهارس NV بسمات مختلفة، مثل الحجم، ومتطلبات السياسة، وأذونات الوصول.

يسمح لك هذا الأمر بتحديد رقم فهرس NV، وحجم البيانات المراد تخزينها، وسياسات الوصول، وسمات أخرى. إنه أداة أساسية لإدارة البيانات الدائمة داخل TPM.

خيارات

الخيارات التالية متاحة:

  • -C جلسة مصادقة: يحدد جلسة المصادقة المراد استخدامها للأمر. يمكن أن تكون مقبض جلسة أو ملف جلسة.
  • -i فهرس: فهرس NV المراد تعريفه. هذا معرف فريد لفهرس NV.
  • -s حجم: حجم بيانات NV بالبايت.
  • -p سياسة: يحدد سياسة يجب تلبيتها للوصول إلى فهرس NV. يمكن أن يكون هذا هضم سياسة أو ملف سياسة.
  • -r قواعد السياسة: يحدد قواعد السياسة لفهرس NV.
  • -a سمات: قناع بت لسمات فهرس NV. السمات الشائعة تشمل:
    • 0x0001: TPM_NT_DEFINED
    • 0x0002: TPM_NT_PRIVACY_SECRET
    • 0x0004: TPM_NT_HW_AUTH
    • 0x0008: TPM_NT_USE_ORDERLY
    • 0x0010: TPM_NT_CHANGE_Repeated
    • 0x0020: TPM_NT_LOCKOUT
    • 0x0040: TPM_NT_OWNER
    • 0x0080: TPM_NT_AUTH_POLICY
    • 0x0100: TPM_NT_PLATFORM
    • 0x0200: TPM_NT_REMOTE_CONTROL
    • 0x0400: TPM_NT_ORDERLY
  • -l قائمة السياسات: قائمة بالسياسات التي سيتم تطبيقها على فهرس NV.
  • -P كلمة مرور: كلمة مرور المصادقة لفهرس NV.
  • -u كلمة مرور: كلمة مرور التحديث لفهرس NV.
  • -U كلمة مرور: كلمة مرور إلغاء الربط لفهرس NV.
  • -t كلمة مرور: كلمة مرور النقل لفهرس NV.
  • -o كلمة مرور: كلمة مرور المالك لفهرس NV.
  • -O كلمة مرور: كلمة مرور المالك الأساسي لفهرس NV.
  • -n اسم: اسم فهرس NV.
  • -x سياسة: يحدد سياسة للقراءة.
  • -X سياسة: يحدد سياسة للكتابة.
  • -f ملف: يقرأ بيانات NV من ملف.
  • -f ملف السياسة: يقرأ بيانات السياسة من ملف.
  • -t ملف السياسة: يقرأ بيانات السياسة من ملف.
  • -T ملف السياسة: يقرأ بيانات السياسة من ملف.
  • -p ملف السياسة: يقرأ بيانات السياسة من ملف.
  • -r ملف السياسة: يقرأ بيانات السياسة من ملف.
  • -l ملف السياسة: يقرأ بيانات السياسة من ملف.
  • -x ملف السياسة: يقرأ بيانات السياسة من ملف.
  • -X ملف السياسة: يقرأ بيانات السياسة من ملف.
  • -F اسم الملف: يحدد ملفًا يحتوي على تعريفات فهارس NV.
  • -S اسم الملف: يحدد ملفًا يحتوي على بيانات الجلسة.
  • -L اسم الملف: يحدد ملفًا يحتوي على بيانات قائمة السياسات.
  • -P اسم الملف: يحدد ملفًا يحتوي على بيانات كلمة المرور.
  • -R اسم الملف: يحدد ملفًا يحتوي على قواعد السياسة.
  • -I اسم الملف: يحدد ملفًا يحتوي على معلومات فهرس NV.

صيغة كائن السياق

صيغة كائن السياق هي سلسلة تحدد كائن سياق TPM المراد استخدامه. يمكن أن تكون مقبضًا، أو مسار ملف، أو تمثيلاً نصيًا للكائن.

صيغة المصادقة

يمكن تحديد المصادقة باستخدام كلمة مرور، أو هضم سياسة، أو جلسة. تعتمد الصيغة على طريقة المصادقة المحددة المستخدمة.

سمات الكائن

سمات الكائن هي مجموعة من العلامات التي تحدد سلوك وأذونات الوصول لفهرس NV. يتم تحديد هذه السمات باستخدام قناع بت.

خيارات شائعة

يتشارك هذا الأمر في خيارات مشتركة مع أوامر tpm2-tools أخرى، مثل:

  • -h, --help: عرض معلومات المساعدة.
  • -v, --version: عرض معلومات الإصدار.
  • -T, --tcti: تحديد واجهة اتصال TPM (TCTI).
  • -d, --debug: تمكين مخرجات التصحيح.

تكوين TCTI

يحدد TCTI (واجهة تكوين ونقل Tabernacle) كيفية تواصل الأداة مع جهاز TPM. تشمل TCTIs الشائعة:

  • mssim: محاكي برمجيات.
  • device: وصول مباشر إلى جهاز TPM.
  • socket: اتصال عبر مقبس شبكة.

خيارات TCTI

يمكن تمرير خيارات خاصة بـ TCTI باستخدام العلم -T متبوعًا باسم TCTI وخياراته.

أمثلة

تعريف فهرس NV بفهرس 0x1000، حجم 16 بايت، ومصادقة مالك:

tpm2_nvdefine -i 0x1000 -s 16 -a 0x0004 -P كلمةمرورسرية

تعريف فهرس NV بسياسة تتطلب هضم سياسة محدد:

tpm2_nvdefine -i 0x1001 -s 32 -p هضم_سياسة_سداسي_عشري -a 0x0080

يعيد

يعيد 0 عند النجاح، وقيمة غير صفرية عند الفشل.

أخطاء

لا توجد أخطاء معروفة.
