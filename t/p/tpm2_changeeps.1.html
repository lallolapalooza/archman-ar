tpm2_changeeps(1) دليل الأوامر العامة tpm2_changeeps(1)

اسم

tpm2_changeeps(1) - يستبدل بذرة التزويد النشطة (endorsement primary seed) بواحدة جديدة تم إنشاؤها من مولد الأرقام العشوائية الخاص بـ TPM2.

الملخص

tpm2_changeeps [خيارات]

الوصف

tpm2_changeeps(1) - يستبدل بذرة التزويد النشطة (endorsement primary seed) بواحدة جديدة تم إنشاؤها من مولد الأرقام العشوائية الخاص بـ TPM2. يتم فقدان الكائنات العابرة (Transient) والدائمة (Persistent) الموجودة تحت هرمية التزويد. يتطلب هذا الأمر مصادقة المنصة (platform auth).

الخيارات

•
-p, --auth=AUTH

يحدد AUTH لمصادقة هرمية المنصة (platform hierarchy).

•
--cphash=FILE

مسار الملف لتسجيل تجزئة (hash) معاملات الأمر. يُعرف هذا غالبًا باسم cpHash. ملاحظة: عند تحديد هذا الخيار، لن يقوم الأداة بتنفيذ الأمر فعليًا، بل ستعيد فقط cpHash، ما لم يكن rphash مطلوبًا أيضًا.

•
--rphash=FILE

مسار الملف لتسجيل تجزئة (hash) معاملات الاستجابة. يُعرف هذا غالبًا باسم rpHash.

•
-S, --session=FILE:

الجلسة التي تم إنشاؤها باستخدام tpm2_startauthsession. يمكن استخدام هذا لتحديد جلسة مساعدة للتدقيق و/أو التشفير/فك التشفير للمعاملات.

المراجع

تنسيق المصادقة

يمكن أن تأتي المصادقة لاستخدام كائن في TPM2.0 في 3 أشكال مختلفة: 1. كلمة مرور 2. HMAC 3. جلسات

ملاحظة: "المصادقات افتراضيًا تكون بـ كلمة مرور فارغة عند عدم تحديدها."

كلمات المرور

يتم تفسير كلمات المرور بالأشكال التالية باستخدام معرفات بادئة.

ملاحظة: بشكل افتراضي، تُعتبر كلمات المرور في شكل سلسلة نصية عندما لا تحتوي على بادئة.

سلسلة نصية

كلمة مرور كسلسلة نصية، يتم تحديدها بالبادئة "str:" أو بغيابها (سلسلة نصية خام بدون بادئة) ولا يتم تفسيرها، وتُستخدم مباشرة للمصادقة.

أمثلة

foobar
str:foobar

سلسلة سداسية عشرية

كلمة مرور كسلسلة سداسية عشرية، يتم تحديدها بالبادئة "hex:" يتم تحويلها من صيغة ست عشرية إلى صيغة مصفوفة بايت، مما يسمح بكلمات مرور تحتوي على أحرف غير قابلة للطباعة و/أو غير ودية للطرفية.

مثال

hex:1122334455667788

ملف

كلمة مرور تعتمد على ملف، يتم تحديدها بالبادئة "file:" يجب أن تكون مسار ملف يحتوي على كلمة المرور ليتم قراءتها بواسطة الأداة أو "-" لاستخدام الإدخال القياسي. تخزين كلمات المرور في الملفات يمنع تسرب المعلومات، حيث يمكن قراءة كلمات المرور التي يتم تمريرها كخيارات من قائمة العمليات أو ميزات سجل الأوامر الشائعة.

أمثلة

# لاستخدام الإدخال القياسي والمطالبة بكلمة المرور
file:-
# لاستخدام ملف من مسار
file:path/to/password/file
# لإرسال كلمة مرور عبر الإدخال القياسي:
echo foobar | tpm2_tool -p file:-
# لاستخدام سلسلة هنا (here-string) من bash عبر الإدخال القياسي:
tpm2_tool -p file:- <<< foobar

جلسات

عند استخدام جلسة سياسة (policy session) لمصادقة استخدام كائن، قم بوضع البادئة "session" على وسيطة الخيار. ثم قم بتحديد مسار لملف جلسة تم إنشاؤه باستخدام tpm2_startauthsession(1). اختياريًا، إذا كانت الجلسة تتطلب قيمة مصادقة (auth value) لإرسالها مع مقبض الجلسة (على سبيل المثال، كلمة مرور السياسة)، قم بإلحاق "+" وسلسلة نصية كما هو موضح في قسم كلمات المرور.

أمثلة

لاستخدام ملف سياق جلسة يسمى session.ctx.

session:session.ctx

لاستخدام ملف سياق جلسة يسمى session.ctx و إرسال قيمة المصادقة mypassword.

session:session.ctx+mypassword

لاستخدام ملف سياق جلسة يسمى session.ctx و إرسال قيمة المصادقة السداسية عشرية 0x11223344.

session:session.ctx+hex:11223344

مصادقات PCR

يمكنك تلبية سياسة PCR باستخدام البادئة "pcr:" ولغة PCR المصغرة. لغة PCR المصغرة كالتالي: <pcr-spec>=<raw-pcr-file>

تم توثيق مواصفات PCR في قسم "محدِّدات بنك PCR".

يُعد raw-pcr-file وسيطة اختيارية تحتوي على مخرجات محتويات PCR الخام كما تم إرجاعها بواسطة tpm2_pcrread(1).

محدِّدات بنك PCR

أمثلة

لتلبية سياسة PCR لـ sha256 على البنوك 0، 1، 2، و 3 استخدم محددًا:

pcr:sha256:0,1,2,3

تحديد AUTH.

تكوين TCTI

TCTI أو "واجهة النقل" (Transmission Interface) هي آلية الاتصال مع TPM. يمكن تغيير TCTI للاتصال بأجهزة TPM عبر وسائط مختلفة.

للتحكم في TCTI، تحترم الأدوات:

1.
خيار سطر الأوامر -T أو --tcti
2.
متغير البيئة: TPM2TOOLS_TCTI.

ملاحظة: يتجاوز خيار سطر الأوامر دائمًا متغير البيئة.

TCTIs المعروفة حاليًا هي:

•
tabrmd - مدير الموارد، يسمى tabrmd. ملاحظة أن tabrmd و abrmd كاسم tcti مترادفين.
•
mssim - يستخدم عادةً للاتصال بمحاكي برنامج TPM.
•
device - يستخدم عند التحدث مباشرة إلى ملف جهاز TPM.
•
none - لا تبدأ اتصالًا بـ TPM. تسمح بعض الأدوات بخيارات خارج TPM وبالتالي تدعم عدم استخدام TCTI. الأدوات التي لا تدعمها ستُظهر خطأ عند محاولة استخدامها بدون اتصال TCTI. لا تدعم أي خيارات ويجب تقديمها كنص مطابق لـ "none".

الوسائط لأي من خيار سطر الأوامر أو متغير البيئة تكون بالشكل:

<tcti-name>:<tcti-option-config>

تحديد سلسلة فارغة لأي من <tcti-name> أو <tcti-option-config> يؤدي إلى استخدام القيمة الافتراضية لتلك الجزئية على التوالي.

القيم الافتراضية لـ TCTI

عند عدم تحديد TCTI، يتم البحث عن TCTI الافتراضي باستخدام دلالات dlopen(3). ستبحث الأدوات عن TCTIs tabrmd و device و mssim بهذا الترتيب وتستخدم أول واحد يتم العثور عليه. يمكنك الاستعلام عن TCTI الذي سيتم اختياره كقيمة افتراضية باستخدام الخيار -v لـ

NAME

tpm2_changeeps - Change the endorsement primary seed (EPS)

SYNOPSIS

tpm2_changeeps [-c SESSION] [-f] [-P auth] [-S session_file] [-t tcti]

DESCRIPTION

The tpm2_changeeps command is used to change the Endorsement Primary Seed (EPS). The EPS is a secret value that is used to generate the Endorsement Hierarchy (EH) seeds. The EPS is provisioned by the platform manufacturer and should ideally never be changed. However, in cases where the EPS has been lost or compromised, this command can be used to change the EPS. Changing the EPS will effectively reset the Endorsement Hierarchy, rendering any objects created within it (such as Endorsement Keys) unusable.

The command requires the authorization for the Endorsement Primary Seed (e.g. platform authorization).

Authorization Formatting

The authorization value for the Endorsement Primary Seed is a password. The password can be provided in several ways:

A plain text password. Ex: -P mypassword
A hex string representing the password. Ex: -P 12345678
The path to a file containing the password. Ex: -P file:/path/to/password/file
The special value NULL. Ex: -P NULL

TCTI Configuration

The TPM Base Services (TBS) TCTI can be configured using the TPM2TOOLS_TCTI environment variable or the -t command line option. The following TCTIs are supported:

•
device: Use the TPM device file. The default is /dev/tpm0. Example: -t device:/dev/tpm0
•
mssim: Use the mssim simulator. Example: -t mssim:host=localhost,port=2321
•
abrmd: Use the tpm2-abrmd daemon. Example: -t abrmd:bus_name=com.example.Tpm2_abrmd

If no TCTI is specified, the tools will attempt to use the default TCTI configuration. The print-version command can be used to print the version information. The "default-tcti" key-value pair will indicate which of the aforementioned TCTIs is the default.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

EXAMPLES

Change the endorsement primary seed where the platform auth is NULL.

tpm2_changeeps

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.

Limitations

It expects a session to be already established via tpm2_startauthsession(1) and requires one of the following:

•
direct device access
•
extended session support with tpm2-abrmd.

Without it, most resource managers will not save session state between command invocations.
