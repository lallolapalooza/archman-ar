الحزمة: tpm2-tools

التراخيص: BSD-3-Clause

tpm2_createprimary(1) دليل الأوامر العامة tpm2_createprimary(1)

الاسم

tpm2_createprimary(1) - إنشاء مفتاح أساسي.

ملخص

tpm2_createprimary [خيارات]

الوصف

tpm2_createprimary(1) - يُستخدم هذا الأمر لإنشاء كائن أساسي تحت إحدى التسلسلات الهرمية: المالك، المنصة، المصادقة، أو الفارغة. سيقوم الأمر بإنشاء وتحميل كائن أساسي. الأجزاء الحساسة والعامة لن يتم إرجاعها. سيتم حفظ ملف سياق لمعرّف الكائن الذي تم إنشاؤه كملف للتفاعلات المستقبلية مع الأساسي الذي تم إنشاؤه.

الخيارات

•
-C, --hierarchy=OBJECT:

التسلسل الهرمي الذي يتم إنشاء الكائن تحته. سيحدد هذا أيضًا أي سر مصادقة (إن وجد) يجب تقديمه. الافتراضي هو TPM_RH_OWNER، عند عدم تحديد قيمة. الخيارات المدعومة هي:

•
o لـ TPM_RH_OWNER
•
p لـ TPM_RH_PLATFORM
•
e لـ TPM_RH_ENDORSEMENT
•
n لـ TPM_RH_NULL
•
<num> حيث يمكن استخدام رقم خام.
•
-P, --hierarchy-auth=AUTH:

قيمة المصادقة للتسلسل الهرمي المحدد بواسطة -C.

•
-p, --key-auth=AUTH:

قيمة المصادقة للكائن الأساسي الذي تم إنشاؤه.

•
-g, --hash-algorithm=ALGORITHM:

خوارزمية التجزئة المستخدمة لتوليد اسم الكائنات. الافتراضي هو sha256 إذا لم يتم تحديده.

•
-G, --key-algorithm=ALGORITHM:

نوع الخوارزمية للمفتاح الأساسي الذي تم إنشاؤه. الافتراضي هو rsa2048:null:aes128cfb.

•
-c, --key-context=FILE:

مسار الملف لحفظ سياق الكائن للكائن الأساسي الذي تم إنشاؤه.

•
-L, --policy=FILE OR HEX_STRING:

ملف اختياري أو سلسلة سداسية عشرية تحتوي على ملخص السياسة للمصادقة المستندة إلى السياسة للكائن.

•
-a, --attributes=ATTRIBUTES:

سمات الكائن، اختيارية. الافتراضي هو: TPMA_OBJECT_RESTRICTED|TPMA_OBJECT_DECRYPT|TPMA_OBJECT_FIXEDTPM| TPMA_OBJECT_FIXEDPARENT|TPMA_OBJECT_SENSITIVEDATAORIGIN| TPMA_OBJECT_USERWITHAUTH

•
-u, --unique-data=FILE OR STDIN:

ملف إدخال اختياري يحتوي على الحقل الفريد لـ TPMT_PUBLIC بتنسيقendian صغير. قد يقوم منشئ المفتاح الأساسي بوضع معلومات تتسبب في أن يقوم نظام إنشاء المفتاح الأساسي الداخلي لـ TPM بتوليد قيم فريدة إحصائيًا. تحدد مواصفات TPM v2.0 هذا الحقل بـ "فريد" وتقوم بتحميله بحيث يحتوي على قيمة واحدة عندما يقدم التطبيق هذا الهيكل كإدخال وقيمة أخرى عندما يستقبل التطبيق هذا الهيكل كمخرج (مثل الجزء العام لمفتاح rsa).

إذا تم تحديد البيانات كملف، فإن المستخدم مسؤول عن ضمان تنسيق هذا المخزن المؤقت وفقًا لاتحاد TPMU_PUBLIC_ID.

يمكن أيضًا استرداد البيانات الفريدة من مخزن مؤقت stdin عن طريق تحديد " - " كقيمة للخيار --unique-data وسيقوم الأداة بتحليل نوع المفتاح وربط بيانات الإدخال بالبيانات الفريدة المرتبطة بنوع المفتاح.

ملاحظة:

1.
الحد الأقصى للبايتات المسموح بها يعتمد على نوع المفتاح وتنفيذ TPM. على سبيل المثال، بينما تسمح TSS بقيمة تصل إلى 512 لـ MAX_RSA_KEY_BYTES، ومع ذلك، يدعم تنفيذ ibmSwTPM قيمة تصل إلى 256 بايت.
2.
يتم تقسيم بيانات الإدخال الفريدة المحددة في stdin لـ ECC لتحديد مخازن X و Y الإحداثية.
•
--creation-data=FILE:

ملف إخراج اختياري يحفظ بيانات الإنشاء للشهادة.

•
--template-data=FILE:

ملف إخراج اختياري يحفظ بيانات قالب المفتاح (TPM2B_PUBLIC) لاستخدامها في tpm2_policytemplate.

•
-t, --creation-ticket=FILE:

ملف إخراج اختياري يحفظ تذكرة الإنشاء للشهادة.

•
-d, --creation-hash=FILE:

ملف إخراج اختياري يحفظ تجزئة الإنشاء للشهادة.

•
-q, --outside-info=FILE_OR_HEX:

ملف أو سلسلة سداسية عشرية اختيارية لإضافة بيانات فريدة إلى بيانات الإنشاء. لاحظ أنها لا تساهم في إنشاء كائن فريد إحصائيًا.

•
-l, --pcr-list=PCR:

قائمة بنوك PCR ومعرفات PCRs المختارة لكل بنك ليتم تضمينها في بيانات الإنشاء للشهادة.

•
--cphash=FILE

مسار الملف لتسجيل تجزئة معلمات الأمر. يُطلق على هذا عادةً باسم cpHash. ملاحظة: عند تحديد هذا الخيار، لن يقوم الأداة بتنفيذ الأمر فعليًا، بل سيعيد فقط cpHash.

•
-f, --format:

اختيار التنسيق لملف إخراج المفتاح العام. `tss' (الافتراضي) سيخرج كتلة ثنائية وفقًا لمواصفات TPM 2.0. `pem' سيخرج مفتاحًا عامًا مشفرًا بتنسيق PEM متوافق مع OpenSSL. `der' سيخرج مفتاحًا عامًا مشفرًا بتنسيق DER متوافق مع OpenSSL. `tpmt' سيخرج كتلة ثنائية لهيكل TPMT_PUBLIC المشار إليه في مواصفات TPM 2.0.

تنسيق المفتاح العام.

•
-o, --output=FILE:

مسار ملف الإخراج، الذي يسجل الجزء العام من الكائن.

المراجع

تنسيق كائن السياق

يتم تحديد نوع كائن السياق، سواء كان معرّفًا أو اسم ملف، وفقًا للمنطق التالي بالترتيب:

•
إذا كان الوسيط مسار ملف، فسيتم تحميل الملف ككائن TPM مؤقت مستعاد.
•
إذا كان الوسيط تطابقًا بادئة لأحد:
•
owner: التسلسل الهرمي للمالك
•
platform: التسلسل الهرمي للمنصة
•
endorsement: التسلسل الهرمي للمصادقة
•
lockout: الكائن الثابت للتحكم في القفل
•
إذا كان الوسيط يمكن تحميله كرقم، فسيتم اعتباره معرّفًا، على سبيل المثال 0x81010013 ويتم استخدامه مباشرة._OBJECT_.

تنسيق المصادقة

يمكن أن تأتي المصادقة لاستخدام كائن في TPM2.0 في 3 أشكال مختلفة: 1. كلمة مرور 2. HMAC 3. جلسات

ملاحظة: "تكون المصادقات افتراضيًا لكلمة المرور الفارغة عند عدم تحديدها".

كلمات المرور

يتم تفسير كلمات المرور بالأشكال التالية أدناه باستخدام معرفات بادئة.

ملاحظة: بشكل افتراضي، فإن كلمات المرور

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

tpm2_tool
TPM2 SOFTWARE STACK
tpm2_tool(1)

Name

tpm2_tool - TPM2 Tool command line utility

Synopsis

tpm2_tool [OPTIONS] [COMMAND]

tpm2_tool [OPTIONS] COMMAND [COMMAND OPTIONS]

Description

The tpm2_tool utility is a command line tool that provides access to the TPM2 functionality by providing a uniform interface to the underlying TPM2 Software Stack (TSS) libraries.

The tool supports a hierarchical menu driven interface, which makes it easier to discover and use the TPM2 commands.

The tpm2_tool utility supports commands defined by the TPM2 specification.

Note: Some commands are implemented in separate utilities (e.g. tpm2_getrandom(1)). In these cases, calling the separate utility is preferred over calling the tool via tpm2_tool.

Options

The following options are available for all commands.

-p, --password Specify the password to be used for authorization. This option supports multiple formats:

The format of the password argument is a string prefixed by how the password should be interpreted. The prefixes are:

The following password types are supported:

String

A string password, specified by prefix “str:” or it’s absence (raw string without prefix) is not interpreted, and is directly used for authorization.

Examples

foobar
str:foobar

Hex-string

A hex-string password, specified by prefix “hex:” is converted from a hexidecimal form into a byte array form, thus allowing passwords with non-printable and/or terminal un-friendly characters.

Example

hex:1122334455667788

File

A file based password, specified be prefix “file:” should be the path of a file containing the password to be read by the tool or a “-” to use stdin. Storing passwords in files prevents information leakage, passwords passed as options can be read from the process list or common shell history features.

Examples

# to use stdin and be prompted
file:-
# to use a file from a path
file:path/to/password/file
# to echo a password via stdin:
echo foobar | tpm2_tool -p file:-
# to use a bash here-string via stdin:
tpm2_tool -p file:- <<< foobar

Sessions

When using a policy session to authorize the use of an object, prefix the option argument with the session keyword. Then indicate a path to a session file that was created with tpm2_startauthsession(1). Optionally, if the session requires an auth value to be sent with the session handle (eg policy password), then append a + and a string as described in the Passwords section.

Examples

To use a session context file called session.ctx.

session:session.ctx

To use a session context file called session.ctx AND send the authvalue mypassword.

session:session.ctx+mypassword

To use a session context file called session.ctx AND send the HEX authvalue 0x11223344.

session:session.ctx+hex:11223344

PCR Authorizations

You can satisfy a PCR policy using the “pcr:” prefix and the PCR minilanguage. The PCR minilanguage is as follows: <pcr-spec>=<raw-pcr-file>

The PCR spec is documented in in the section “PCR bank specifiers”.

The raw-pcr-file is an optional argument that contains the output of the raw PCR contents as returned by tpm2_pcrread(1).

PCR bank specifiers

Examples

To satisfy a PCR policy of sha256 on banks 0, 1, 2 and 3 use a specifier of:

pcr:sha256:0,1,2,3

specifying AUTH.

Complex Specifiers

Objects, when specified for creation by the TPM, have numerous algorithms to populate in the public data. Things like type, scheme and asymmetric details, key size, etc. Below is the general format for specifying this data: <type>:<scheme>:<symmetric-details>

Type Specifiers

This portion of the complex algorithm specifier is required. The remaining scheme and symmetric details will default based on the type specified and the type of the object being created.

•
aes - Default AES: aes128
•
aes128<mode> - 128 bit AES with optional mode (ctr|ofb|cbc|cfb|ecb). If mode is not specified, defaults to null.
•
aes192<mode> - Same as aes128<mode>, except for a 192 bit key size.
•
aes256<mode> - Same as aes128<mode>, except for a 256 bit key size.
•
sm4 - Default SM4: sm4128
•
sm4128 or sm4_128 <mode> - 128 bit SM4 with optional mode (ctr|ofb|cbc|cfb|ecb). If mode is not specified, defaults to null.
•
ecc - Elliptical Curve, defaults to ecc256.
•
ecc192 or ecc_nist_p192 - 192 bit ECC NIST curve
•
ecc224 or ecc_nist_p224 - 224 bit ECC NIST curve
•
ecc256 or ecc_nist_p256 - 256 bit ECC NIST curve
•
ecc384 or ecc_nist_p384 - 384 bit ECC NIST curve
•
ecc521 or ecc_nist_p521 - 521 bit ECC NIST curve
•
ecc_sm2 or ecc_sm2_p256 - 256 bit SM2 curve
•
rsa - Default RSA: rsa2048
•
rsa1024 - RSA with 1024 bit keysize.
•
rsa2048 - RSA with 2048 bit keysize.
•
rsa3072 - RSA with 3072 bit keysize.
•
rsa4096 - RSA with 4096 bit keysize.

Scheme Specifiers

Next, is an optional field, it can be skipped.

Schemes are usually Signing Schemes or Asymmetric Encryption Schemes. Most signing schemes take a hash algorithm directly following the signing scheme. If the hash algorithm is missing, it defaults to sha256. Some take no arguments, and some take multiple arguments.

Hash Optional Scheme Specifiers

These scheme specifiers are followed by a dash and a valid hash algorithm, For example: oaep-sha256.

•

Multiple Option Scheme Specifiers

This scheme specifier is followed by a count (max size UINT16) then followed by a dash(-) and a valid hash algorithm. * ecdaa For example, ecdaa4-sha256. If no count is specified, it defaults to 4.

No Option Scheme Specifiers

The following scheme specifiers do not take any arguments.

•
hmac
•
null

Symmetric Encryption Schemes

These are symmetric encryption schemes and do not take arguments for the scheme.

•

Specifiers

The tpm2_tool utility supports various specifiers for options. These specifiers allow for flexible specification of TPM objects and parameters.

Password Specifiers

Words are assumed to be in the string form when they do not have a prefix.

String

A string password, specified by prefix “str:” or it’s absence (raw string without prefix) is not interpreted, and is directly used for authorization.

Examples

foobar
str:foobar

Hex-string

A hex-string password, specified by prefix “hex:” is converted from a hexidecimal form into a byte array form, thus allowing passwords with non-printable and/or terminal un-friendly characters.

Example

hex:1122334455667788

File

A file based password, specified be prefix “file:” should be the path of a file containing the password to be read by the tool or a “-” to use stdin. Storing passwords in files prevents information leakage, passwords passed as options can be read from the process list or common shell history features.

Examples

# to use stdin and be prompted
file:-
# to use a file from a path
file:path/to/password/file
# to echo a password via stdin:
echo foobar | tpm2_tool -p file:-
# to use a bash here-string via stdin:
tpm2_tool -p file:- <<< foobar

Sessions

When using a policy session to authorize the use of an object, prefix the option argument with the session keyword. Then indicate a path to a session file that was created with tpm2_startauthsession(1). Optionally, if the session requires an auth value to be sent with the session handle (eg policy password), then append a + and a string as described in the Passwords section.

Examples

To use a session context file called session.ctx.

session:session.ctx

To use a session context file called session.ctx AND send the authvalue mypassword.

session:session.ctx+mypassword

To use a session context file called session.ctx AND send the HEX authvalue 0x11223344.

session:session.ctx+hex:11223344

PCR Authorizations

You can satisfy a PCR policy using the “pcr:” prefix and the PCR minilanguage. The PCR minilanguage is as follows: <pcr-spec>=<raw-pcr-file>

The PCR spec is documented in in the section “PCR bank specifiers”.

The raw-pcr-file is an optional argument that contains the output of the raw PCR contents as returned by tpm2_pcrread(1).

PCR bank specifiers

Examples

To satisfy a PCR policy of sha256 on banks 0, 1, 2 and 3 use a specifier of:

pcr:sha256:0,1,2,3

specifying AUTH.

Complex Specifiers

Objects, when specified for creation by the TPM, have numerous algorithms to populate in the public data. Things like type, scheme and asymmetric details, key size, etc. Below is the general format for specifying this data: <type>:<scheme>:<symmetric-details>

Type Specifiers

This portion of the complex algorithm specifier is required. The remaining scheme and symmetric details will default based on the type specified and the type of the object being created.

†
aes - Default AES: aes128
†
aes128<mode> - 128 bit AES with optional mode (ctr|ofb|cbc|cfb|ecb). If mode is not specified, defaults to null.
†
aes192<mode> - Same as aes128<mode>, except for a 192 bit key size.
†
aes256<mode> - Same as aes128<mode>, except for a 256 bit key size.
†
sm4 - Default SM4: sm4128
†
sm4128 or sm4_128 <mode> - 128 bit SM4 with optional mode (ctr|ofb|cbc|cfb|ecb). If mode is not specified, defaults to null.
†
