NAME

\n

tpm2_hierarchycontrol(1) - Enable and disable use of a\n hierarchy and its associated NV storage.

\n
\n
\n

SYNOPSIS

\n

tpm2_hierarchycontrol [OPTIONS] VARIABLE\n OPERATION

\n
\n
\n

DESCRIPTION

\n

tpm2_hierarchycontrol(1) - Allows user change phEnable, \n phEnableNV, shEnable and ehEnable when the proper authorization is provided. \n Authorization should be one out of owner hierarchy auth, endorsement\n hierarchy auth and platform hierarchy auth. As an argument the tool takes\n the VARIABLE as\n TPMA_STARTUP_CLEAR bit and _OPERATION_ as string\n clear|set to clear or set the VARIABLE\n bit.

\n

Note: If password option is missing, assume NULL.

\n
\n
\n

OPTIONS

\n
\n
•
\n
-C, --hierarchy=OBJECT:
\n
\n
\n

Specifies the handle used to authorize. Defaults to the\n “platform” hierarchy. Supported options are:

\n
\n
•
\n
o for TPM_RH_OWNER
\n
•
\n
p for TPM_RH_PLATFORM
\n
•
\n
<num> where a raw\n number can be used.
\n
\n
\n
\n
•
\n
-P, --hierarchy-auth=AUTH:
\n
\n
\n

Specifies the authorization value for the hierarchy.

\n
\n
\n
•
\n
--cphash=FILE
\n
\n
\n

File path to record the hash of the command parameters. This is\n commonly termed as cpHash. NOTE: When this option is selected, The tool will\n not actually execute the command, it simply returns a cpHash.

\n
\n
\n

References

\n
\n
\n

Context Object Format

\n

The type of a context object, whether it is a handle or file name, \n is determined according to the following logic in-order:

\n
\n
•
\n
If the argument is a file path, then the file is loaded as a restored TPM\n transient object.
\n
•
\n
If the argument is a prefix match on one of:
\n
\n
\n
\n
•
\n
owner: the owner hierarchy
\n
•
\n
platform: the platform hierarchy
\n
•
\n
endorsement: the endorsement hierarchy
\n
•
\n
lockout: the lockout control persistent object
\n
\n
\n
\n
•
\n
If the argument argument can be loaded as a number it will be treat as a\n handle, e.g. 0x81010013 and used directly._OBJECT_.
\n
\n
\n
\n

Authorization Formatting

\n

Authorization for use of an object in TPM2.0 can come in 3\n different forms: 1. Password 2. HMAC \n 3. Sessions

\n

NOTE: “Authorizations default to the EMPTY\n PASSWORD when not specified”.

\n
\n

Passwords

\n

Passwords are interpreted in the following forms below using\n prefix identifiers.

\n

Note: By default passwords are assumed to be in the string\n form when they do not have a prefix.

\n
\n
\n

String

\n

A string password, specified by prefix “str:” or\n it’s absence (raw string without prefix) is not interpreted, and is\n directly used for authorization.

\n
\n
\n

Examples

\n
\n
\n
\n 
foobar\nstr:foobar\n
\n
\n
\n
\n
\n

Hex-string

\n

A hex-string password, specified by prefix “hex:” is\n converted from a hexidecimal form into a byte array form, thus allowing\n passwords with non-printable and/or terminal un-friendly characters.

\n
\n
\n

Example

\n
\n
\n
\n 
hex:1122334455667788\n
\n
\n
\n
\n
\n

File

\n

A file based password, specified be prefix “file:”\n should be the path of a file containing the password to be read by the tool\n or a “-” to use stdin. Storing passwords in files prevents\n information leakage, passwords passed as options can be read from the\n process list or common shell history features.

\n
\n
\n

Examples

\n
\n
\n
\n 
# to use stdin and be prompted\nfile:-\n# to use a file from a path\nfile:path/to/password/file\n# to echo a password via stdin:\necho foobar | tpm2_tool -p file:-\n# to use a bash here-string via stdin:\ntpm2_tool -p file:- <<< foobar\n
\n
\n
\n
\n
\n

Sessions

\n

When using a policy session to authorize the use of an object, \n prefix the option argument with the session keyword. Then indicate a\n path to a session file that was created with tpm2_startauthsession(1). \n Optionally, if the session requires an auth value to be sent with the\n session handle (eg policy password), then append a + and a string as\n described in the Passwords section.

\n
\n
\n

Examples

\n

To use a session context file called session.ctx.

\n
\n
\n
\n 
session:session.ctx\n
\n
\n
\n

To use a session context file called session.ctx AND\n send the authvalue mypassword.

\n
\n
\n
\n 
session:session.ctx+mypassword\n
\n
\n
\n

To use a session context file called session.ctx AND\n send the HEX authvalue 0x11223344.

\n
\n
\n
\n 
session:session.ctx+hex:11223344\n
\n
\n
\n
\n
\n

PCR Authorizations

\n

You can satisfy a PCR policy using the “pcr:” prefix\n and the PCR minilanguage. The PCR minilanguage is as follows:\n <pcr-spec>=<raw-pcr-file>

\n

The PCR spec is documented in in the section “PCR bank\n specifiers”.

\n

The raw-pcr-file is an optional\n argument that contains the output of the raw PCR contents as returned by\n tpm2_pcrread(1).

\n

PCR bank specifiers

\n
\n
\n

Examples

\n

To satisfy a PCR policy of sha256 on banks 0, 1, 2 and 3 use a\n specifier of:

\n
\n
\n
\n 
pcr:sha256:0,1,2,3\n
\n
\n
\n

specifying AUTH.

إعداد TCTI

TCTI أو "واجهة النقل" هي آلية الاتصال بـ TPM. يمكن تغيير TCTIs للاتصال بـ TPMs عبر وسائط مختلفة.

للتحكم في TCTI، تحترم الأدوات:

1.
خيار سطر الأوامر -T أو --tcti
2.
متغير البيئة: TPM2TOOLS_TCTI.

ملاحظة: يتجاوز خيار سطر الأوامر دائمًا متغير البيئة.

TCTIs المعروفة حاليًا هي:

•
tabrmd - مدير الموارد، يسمى tabrmd. لاحظ أن tabrmd و abrmd كاسم tcti مرادفان.
•
mssim - يستخدم عادة للاتصال بمحاكي برنامج TPM.
•
device - يستخدم عند التحدث مباشرة إلى ملف جهاز TPM.
•
none - لا تقم بتهيئة اتصال بـ TPM. تسمح بعض الأدوات بخيارات خارج TPM وبالتالي تدعم عدم استخدام TCTI. الأدوات التي لا تدعمه ستخطئ عند محاولة استخدامها بدون اتصال TCTI. لا يدعم *أي* خيارات *ويجب* تقديمه كنص دقيق "none".

الوسائط لأي من خيار سطر الأوامر أو متغير البيئة تكون بالشكل:

<tcti-name>:<tcti-option-config>

تحديد سلسلة فارغة لأي من <tcti-name> أو <tcti-option-config> يؤدي إلى استخدام الإعداد الافتراضي لهذا الجزء على التوالي.

إعدادات TCTI الافتراضية

عندما لا يتم تحديد TCTI، يتم البحث عن TCTI الافتراضي باستخدام دلالات dlopen(3). ستبحث الأدوات عن TCTIs tabrmd و device و mssim بهذا الترتيب و تستخدم أول واحدة يتم العثور عليها. يمكنك الاستعلام عن TCTI الذي سيتم اختياره كإعداد افتراضي باستخدام الخيار -v لطباعة معلومات الإصدار. يشير زوج المفتاح والقيمة "default-tcti" إلى أي من TCTIs المذكورة أعلاه هو الإعداد الافتراضي.

TCTIs مخصصة

يمكن تحميل أي TCTI ينفذ واجهة TCTI الديناميكية. تستخدم الأدوات داخليًا dlopen(3)، ويتم استخدام قيمة tcti-name الخام للبحث. وبالتالي، يمكن أن يكون هذا مسارًا إلى مكتبة مشتركة، أو اسم مكتبة كما تفهمه دلالات dlopen(3).

خيارات TCTI

تُستخدم هذه المجموعة من الخيارات لتكوين وحدات TCTI المختلفة المعروفة المتاحة:

•
device: بالنسبة لـ device TCTI، يمكن تحديد ملف جهاز TPM للاستخدام بواسطة device TCTI. الإعداد الافتراضي هو /dev/tpm0.

مثال: -T device:/dev/tpm0 أو export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: بالنسبة لـ mssim TCTI، يمكن تحديد اسم النطاق أو عنوان IP ورقم المنفذ المستخدم بواسطة المحاكي. الإعدادات الافتراضية هي 127.0.0.1 و 2321.

مثال: -T mssim:host=localhost,port=2321 أو export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: بالنسبة لـ abrmd TCTI، يكون تنسيق سلسلة التكوين عبارة عن سلسلة من أزواج المفاتيح والقيم البسيطة مفصولة بحرف `,'. يتم فصل كل مفتاح وقيمة بسلسلة `='.
•
يدعم TCTI abrmd مفتاحين:
1.
`bus_name' : اسم خدمة tabrmd على الناقل (سلسلة).
2.
`bus_type' : نوع مثيل dbus (سلسلة) محدود بـ `session' و `system'.

حدد اسم tcti tabrmd وسلسلة تكوين bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

حدد tcti الافتراضي (abrmd) وسلسلة تكوين bus_type=session:

\--tcti:bus_type=session

ملاحظة: abrmd و tabrmd مرادفان. وحدات TCTI المختلفة المعروفة.

أمثلة

تعيين phEnableNV مع التسلسل الهرمي للمنصة وترخيصه

tpm2_hierarchycontrol -C p phEnableNV set -P pass

مسح phEnableNV مع التسلسل الهرمي للمنصة

tpm2_hierarchycontrol -C p phEnableNV clear

تعيين shEnable مع التسلسل الهرمي للمنصة

tpm2_hierarchycontrol -C p shEnable set

تعيين shEnable مع التسلسل الهرمي للمالك

tpm2_hierarchycontrol -C o shEnable set

التحقق من بتات TPMA_STARTUP_CLEAR الحالية

tpm2_getcap properties-variable

القيم المعادة

يمكن أن تعيد الأدوات أيًا من الرموز التالية:

•
0 - نجاح.
•
1 - خطأ عام غير محدد.
•
2 - خطأ في معالجة الخيارات.
•
3 - خطأ في المصادقة.
•
4 - خطأ متعلق بـ TCTI.
•
5 - مخطط غير مدعوم. ينطبق على tpm2_testparams.
