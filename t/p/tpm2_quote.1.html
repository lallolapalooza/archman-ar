tpm2_quote(1) دليل الأوامر العامة tpm2_quote(1)

الاسم

tpm2_quote(1) - توفير اقتباس وتوقيع من TPM.

الملخص

tpm2_quote [خيارات]

الوصف

tpm2_quote(1) - توفير اقتباس وتوقيع لقائمة PCR المحددة في الخوارزمية/البنوك المحددة.

الخيارات

•
-c, --key-context=OBJECT:

كائن السياق لمفتاح توقيع الاقتباس.

•
-p, --auth=AUTH:

يحدد قيمة التفويض لـ AK المحدد بواسطة الخيار -C.

•
-l, --pcr-list=PCR:

قائمة بنوك PCR ومعرفات PCR المحددة لكل بنك. راجع أيضًا قسم ملاحظات أدناه.

•
-m, --message=FILE:

ملف إخراج الرسالة، يسجل رسالة الاقتباس التي تشكل البيانات التي تم توقيعها بواسطة TPM.

•
-s, --signature=FILE:

ملف إخراج التوقيع، يسجل التوقيع بالتنسيق المحدد عبر الخيار -f.

•
-f, --format=FORMAT:

اختيار تنسيق ملف إخراج التوقيع.

•
-o, --pcr=FILE.

ملف إخراج PCR، اختياري، يسجل قائمة قيم PCR كما تم تعريفها بواسطة -l.

•
-F, --pcrs_format=FORMAT:

اختيار تنسيق الكتلة الثنائية في ملف إخراج PCR. 'values' سيخرج كتلة ثنائية من قيم PCR. 'serialized' سيخرج كتلة ثنائية من قيم PCR في شكل هيكل بيانات متسلسل بتنسيق Little Endian. اختياري. الافتراضي هو 'serialized'.

•
-q, --qualification=HEX_STRING_OR_PATH:

بيانات مقدمة كسلسلة سداسية عشرية أو ملف ثنائي لتأهيل الاقتباس، اختياري. يستخدم هذا عادة لإضافة nonce ضد هجمات إعادة التشغيل.

•
-g, --hash-algorithm:

خوارزمية التجزئة للتوقيع. الافتراضي هو sha256.

•
--scheme=ALGORITHM:

مخطط التوقيع المستخدم لتوقيع الرسالة. اختياري. يجب أن تتبع مخططات التوقيع "معايير التنسيق"، انظر قسم "محدِّدات الخوارزمية". انظر أيضًا قسم "مخططات التوقيع المدعومة" للحصول على قائمة بمخططات التوقيع المدعومة. إذا تم تحديده، يجب أن يتطابق مخطط التوقيع مع نوع المفتاح. إذا تُرك غير محدد، فسيتم استخدام مخطط توقيع افتراضي لنوع المفتاح.

•
--cphash=FILE

مسار الملف لتسجيل تجزئة معلمات الأمر. يُشار إلى هذا عادةً باسم cpHash. ملاحظة: عند تحديد هذا الخيار، لن يقوم الأداة بتنفيذ الأمر فعليًا، بل سيعيد ببساطة cpHash.

المراجع

تنسيق كائن السياق

يتم تحديد نوع كائن السياق، سواء كان مقبضًا أو اسم ملف، وفقًا للمنطق التالي بالترتيب:

•
إذا كان الوسيط مسار ملف، فسيتم تحميل الملف ككائن TPM عابر تم استعادته.
•
إذا كان الوسيط مطابقًا بادئة لأحد:
•
owner: التسلسل الهرمي للمالك
•
platform: التسلسل الهرمي للمنصة
•
endorsement: التسلسل الهرمي للمصادقة
•
lockout: كائن التحكم في القفل الدائم
•
إذا كان الوسيط يمكن تحميله كرقم، فسيتم التعامل معه كمقبض، على سبيل المثال 0x81010013 وسيتم استخدامه مباشرة._OBJECT_.

تنسيق التفويض

يمكن أن يأتي التفويض لاستخدام كائن في TPM2.0 في 3 أشكال مختلفة: 1. كلمة مرور 2. HMAC 3. جلسات

ملاحظة: "تكون التفويضات افتراضية إلى كلمة المرور الفارغة عندما لا يتم تحديدها."

كلمات المرور

يتم تفسير كلمات المرور بالأشكال التالية أدناه باستخدام معرفات بادئة.

ملاحظة: بشكل افتراضي، يُفترض أن كلمات المرور في شكل سلسلة عندما لا تحتوي على بادئة.

سلسلة نصية

كلمة مرور سلسلة نصية، يتم تحديدها بالبادئة "str:" أو بغيابها (سلسلة خام بدون بادئة) لا يتم تفسيرها، ويتم استخدامها مباشرة للتفويض.

أمثلة

foobar
str:foobar

سلسلة سداسية عشرية

كلمة مرور سلسلة سداسية عشرية، يتم تحديدها بالبادئة "hex:"، يتم تحويلها من شكل سداسي عشري إلى شكل مصفوفة بايت، مما يسمح بكلمات المرور التي تحتوي على أحرف غير قابلة للطباعة و/أو غير ودية للطرفية.

مثال

hex:1122334455667788

ملف

كلمة مرور مستندة إلى ملف، يتم تحديدها بالبادئة "file:" يجب أن تكون مسار ملف يحتوي على كلمة المرور ليتم قراءتها بواسطة الأداة أو "-" لاستخدام الإدخال القياسي. تخزين كلمات المرور في الملفات يمنع تسرب المعلومات، وكلمات المرور المقدمة كخيارات يمكن قراءتها من قائمة العمليات أو ميزات سجل الأوامر الشائعة.

أمثلة

# لاستخدام الإدخال القياسي وسيُطلب منك إدخال كلمة المرور
file:-
# لاستخدام ملف من مسار
file:path/to/password/file
# لإرسال كلمة مرور عبر الإدخال القياسي:
echo foobar | tpm2_tool -p file:-
# لاستخدام سلسلة هنا من bash عبر الإدخال القياسي:
tpm2_tool -p file:- <<< foobar

جلسات

عند استخدام جلسة سياسة لتفويض استخدام كائن، قم بوضع البادئة "session" على وسيط الخيار. ثم حدد مسارًا لملف جلسة تم إنشاؤه باستخدام tpm2_startauthsession(1). اختياريًا، إذا كانت الجلسة تتطلب قيمة تفويض ليتم إرسالها مع مقبض الجلسة (مثل كلمة مرور السياسة)، فألحق "+" وسلسلة كما هو موضح في قسم كلمات المرور.

أمثلة

لاستخدام ملف سياق جلسة يسمى session.ctx.

session:session.ctx

لاستخدام ملف سياق جلسة يسمى session.ctx و إرسال قيمة التفويض mypassword.

session:session.ctx+mypassword

لاستخدام ملف سياق جلسة يسمى session.ctx و إرسال قيمة التفويض السداسية العشرية 0x11223344.

session:session.ctx+hex:11223344

تفويضات PCR

يمكنك تلبية سياسة PCR باستخدام البادئة "pcr:" ولغة PCR المصغرة. لغة PCR المصغرة هي كما يلي: <pcr-spec>=<raw-pcr-file><

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

NAME

tpm2_quote – quotes contents of PCRs

SYNOPSIS

tpm2_quote
[-c AUTH_SESSION] [-p PCR_DIGEST] [-s SIGNATURE] [-u TPM_QUOTE_HASH_ALGO] [-r PCR_VALUE] [-l PCR_LIST] [-o OUTPUT_FILE] [TPM2_UTILITY_OPTIONS] [TPM2_COMMAND_OPTIONS]

DESCRIPTION

The tpm2_quote command is used to quote the contents of PCRs (Platform Configuration Registers). This command is typically used to attest to the state of the platform by signing the PCR values. The TPM can be configured to create a quote that is signed by a specific key.

OPTIONS

A list of options are provided below. Note that some options are specific to the TPM or the operation being performed.

-c AUTH_SESSION
--auth-session=AUTH_SESSION
The authorization session to use for the command. This can be a session created using tpm2_startauthsession. The format is a string that represents the session handle and attributes. For example, "12345678:0x00000001" would represent a session with handle 0x12345678 and attributes 0x00000001.
-p PCR_DIGEST
--pcr-digest=PCR_DIGEST
The PCR digest to quote. This is a hexadecimal string representing the digest of the PCR values.
-s SIGNATURE
--signature=SIGNATURE
The signature of the PCR digest. This is a hexadecimal string representing the signature created by the TPM. The format of the signature depends on the signing algorithm and the TPM's capabilities.
-u TPM_QUOTE_HASH_ALGO
--tpm-quote-hash-algo=TPM_QUOTE_HASH_ALGO
The hash algorithm to use for the quote. This can be a numeric value or a string representation of the algorithm. For example, "0x0004" or "sha256".
-r PCR_VALUE
--pcr-value=PCR_VALUE
The PCR value to quote. This is a hexadecimal string representing the value of the PCR.
-l PCR_LIST
--pcr-list=PCR_LIST
A list of PCRs to quote. This is a comma-separated list of PCR indices. For example, "0,1,2".
-o OUTPUT_FILE
--output-file=OUTPUT_FILE
The file to write the quoted data to.

Context Object Format

The context object format is a string that specifies how to load a TPM context object. The format is typically a hexadecimal representation of the object's name, followed by a colon, and then the object's type. For example, "0x12345678:0x0001" would represent an object with name 0x12345678 and type 0x0001 (e.g., a key).

Authorization Formatting

Authorization can be provided in several ways:

  • Password: A plain text password string.
  • Policy Session: A session handle and policy digest, e.g., "12345678:abcdef1234567890".
  • HMAC Session: A session handle and HMAC value, e.g., "12345678:abcdef1234567890".

Signature Format Specifiers

The signature format specifiers define the structure of the signature generated by the TPM. Common specifiers include:

  • rsassa: RSA signature with SHA-1, SHA-256, SHA-384, or SHA-512.
  • ecdsa: ECDSA signature with SHA-1, SHA-256, SHA-384, or SHA-512.
  • padding: Padding scheme used for the signature.

PCR Bank Specifiers

PCR bank specifiers indicate which PCR bank(s) should be used for the quote. Common specifiers include:

  • sha1
  • sha256
  • sha384
  • sha512

COMMON OPTIONS

The following options are common to most tpm2 utility commands:

-z TRANSCRIPT_FILE
--tpm-state-file=TRANSCRIPT_FILE
Specifies a file to store the TPM state transcript. This can be used for debugging or replaying commands.
-I INTERFACE_TYPE
--interface-type=INTERFACE_TYPE
Specifies the interface type to use for communicating with the TPM. Supported types include "dib", "ftdi", "libusb", "msssi", "spidev", "tpmdd", "uart".
-f DEVICE_PATH
--device-path=DEVICE_PATH
Specifies the device path for the TPM communication interface.
-p PORT_NUMBER
--port=PORT_NUMBER
Specifies the port number for communication with the TPM.
-S SOCKET_ADDRESS
--socket=SOCKET_ADDRESS
Specifies the socket address for communication with the TPM (e.g., for remote TPMs).
-X KEY_INDEX
--key-index=KEY_INDEX
Specifies the key index to use for communication with the TPM.
-P PASSWORD
--password=PASSWORD
Specifies the password for TPM authentication.
-e ENCRYPTION_KEY
--encryption-key=ENCRYPTION_KEY
Specifies the encryption key for TPM communication.
-t TIMEOUT
--timeout=TIMEOUT
Specifies the timeout in seconds for TPM communication.
-T THREADS
--threads=THREADS
Specifies the number of threads to use for parallel operations.
-V
--verbose
Enable verbose output.
-h
--help
Display help information and exit.
-v
--version
Display version information and exit.

TCTI Configuration

The TPM Communication Transport Interface (TCTI) is responsible for communicating with the TPM device. The TCTI can be configured using environment variables or command-line options.

TCTI OPTIONS

The following options can be used to configure the TCTI:

-d DEVICE_PATH
--tcti-device=DEVICE_PATH
Specifies the device path for the TCTI. This is typically used for serial or USB TCTIs.
-k SOCKET_ADDRESS
--tcti-socket=SOCKET_ADDRESS
Specifies the socket address for the TCTI. This is used for network-based TPMs.
-m MQ_CONFIG
--tcti-mq=MQ_CONFIG
Specifies the configuration for the Message Queue TCTI.

EXAMPLES

Quote PCR 0 and 1 using the SHA-256 algorithm and save the quote to a file: 

  $ tpm2_quote -l 0,1 -u sha256 -o quote.bin

Quote PCR 0 using a specific authorization session and save the quote to a file: 

  $ tpm2_quote -c session.ctx -l 0 -o quote.bin

NOTES

The tpm2_quote command requires access to a TPM device. The specific options and configurations may vary depending on the TPM hardware and software environment.

Returns

The command returns 0 on success, and a non-zero value on failure.

BUGS

Report bugs to the tpm2-software mailing list or issue tracker.

HELP

For more detailed help, use the --help option.
