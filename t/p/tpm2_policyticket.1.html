الاسم

tpm2_policyticket(1) - تمكين التفويض بالسياسة عن طريق التحقق من تذكرة تمثل تفويضًا مصادقًا عليه كان له وقت انتهاء صلاحية مرتبط به.

الملخص

tpm2_policyticket [خيارات]

الوصف

tpm2_policyticket(1) - تمكين التفويض بالسياسة عن طريق التحقق من تذكرة تمثل تفويضًا مصادقًا عليه كان له وقت انتهاء صلاحية مرتبط به.

الخيارات

•
-L, --policy=ملف:

ملف لحفظ ملخص السياسة المركب.

•
-S, --session=ملف:

ملف الجلسة السياسية الذي تم إنشاؤه عبر الخيار -S لـ tpm2_startauthsession(1).

•
-n, --name=ملف:

اسم الكائن الذي صادق على التفويض.

•
--ticket=ملف:

ملف التذكرة لتسجيل بنية تذكرة التفويض.

•
--timeout=ملف:

مسار الملف لتسجيل بنية انتهاء الصلاحية التي تم إرجاعها.

•
-q, --qualification=ملف_أو_سلسلة_سداسية:

اختياري، بيانات تأهيل السياسة التي يمكن للموقّع اختيار تضمينها في التوقيع. يمكن أن تكون سلسلة سداسية أو مسارًا.

مراجع

خيارات شائعة

هذه المجموعة من الخيارات مشتركة بين العديد من البرامج وتوفر معلومات قد يتوقعها العديد من المستخدمين.

•
-h, --help=[man|no-man]: عرض صفحة دليل الأداة. افتراضيًا، تحاول استدعاء عارض الدليل الخاص بالأداة، ولكن عند الفشل، ستقوم بإخراج ملخص قصير للأداة. هذا هو نفس السلوك إذا تم تحديد وسيطة الخيار "man"، ولكن إذا تم طلب "man" صراحةً، فستقدم الأداة أخطاء من الدليل على stderr. إذا تم تحديد خيار "no-man"، أو فشل عارض الدليل، فسيتم إخراج الخيارات القصيرة إلى stdout.

للاستخدام الناجح لميزة صفحات الدليل، يتطلب تثبيت صفحات الدليل أو وجودها في MANPATH. انظر man(1) لمزيد من التفاصيل.

•
-v, --version: عرض معلومات الإصدار لهذه الأداة، و tctis المدعومة، والخروج.
•
-V, --verbose: زيادة المعلومات التي تطبعها الأداة إلى وحدة التحكم أثناء تنفيذها. عند استخدام هذا الخيار، تتم طباعة رقم الملف والسطر.
•
-Q, --quiet: إسكات الإخراج العادي للأداة إلى stdout.
•
-Z, --enable-errata: تمكين تطبيق إصلاحات الأخطاء. مفيد إذا كان هناك حاجة لتطبيق إصلاح خطأ على الأوامر المرسلة إلى TPM. تحديد متغير البيئة TPM2TOOLS_ENABLE_ERRATA يكافئ هذا.
•
-R, --autoflush: تمكين التفريغ التلقائي للكائنات المؤقتة التي تم إنشاؤها بواسطة الأمر. إذا تم تحميل كائن أصل من ملف سياق، فسيتم أيضًا تفريغ كائن الأصل المؤقت. يمكن أيضًا تنشيط التفريغ التلقائي إذا تم تعيين متغير البيئة TPM2TOOLS_AUTOFLUSH على yes أو true. معلومات قد يتوقعها العديد من المستخدمين.

تكوين TCTI

TCTI أو "واجهة النقل" هي آلية الاتصال بـ TPM. يمكن تغيير TCTIs للتواصل مع TPMs عبر وسائط مختلفة.

للتحكم في TCTI، تحترم الأدوات:

1.
خيار سطر الأوامر -T أو --tcti
2.
متغير البيئة: TPM2TOOLS_TCTI.

ملاحظة: خيار سطر الأوامر يتجاوز دائمًا متغير البيئة.

TCTIs المعروفة حاليًا هي:

•
tabrmd - مدير الموارد، يسمى tabrmd. لاحظ أن tabrmd و abrmd كاسم tcti مترادفان.
•
mssim - يستخدم عادة للتواصل مع محاكي برامج TPM.
•
device - يستخدم عند التحدث مباشرة إلى ملف جهاز TPM.
•
none - لا تقم بتهيئة اتصال بـ TPM. تسمح بعض الأدوات بخيارات خارج TPM وبالتالي تدعم عدم استخدام TCTI. الأدوات التي لا تدعمها ستحدث أخطاء عند محاولة استخدامها بدون اتصال TCTI. لا تدعم أي خيارات و يجب تقديمها كنص مطابق لـ "none".

الوسائط لأي من خيار سطر الأوامر أو متغير البيئة تكون بالشكل:

<tcti-name>:<tcti-option-config>

تحديد سلسلة فارغة لأي من <tcti-name> أو <tcti-option-config> يؤدي إلى استخدام الافتراضي لهذا الجزء على التوالي.

افتراضيات TCTI

عند عدم تحديد TCTI، يتم البحث عن TCTI الافتراضي باستخدام دلالات dlopen(3). ستبحث الأدوات عن TCTIs tabrmd، device و mssim بهذا الترتيب وتستخدم أول واحدة يتم العثور عليها. يمكنك الاستعلام عن TCTI الذي سيتم اختياره كافتراضي باستخدام الخيار -v لطباعة معلومات الإصدار. سيشير زوج المفتاح والقيمة "default-tcti" إلى أي من TCTIs المذكورة أعلاه هو الافتراضي.

TCTIs مخصصة

يمكن تحميل أي TCTI يطبق واجهة TCTI الديناميكية. تستخدم الأدوات داخليًا dlopen(3)، ويتم استخدام قيمة tcti-name الخام للبحث. وبالتالي، يمكن أن يكون هذا مسارًا إلى المكتبة المشتركة، أو اسم مكتبة كما هو مفهوم بواسطة دلالات dlopen(3).

خيارات TCTI

تستخدم هذه المجموعة من الخيارات لتكوين وحدات TCTI المعروفة المتوفرة:

•
device: بالنسبة لـ TCTI الجهاز، يمكن تحديد ملف جهاز TPM لاستخدامه بواسطة TCTI الجهاز. الافتراضي هو /dev/tpm0.

مثال: -T device:/dev/tpm0 أو export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: بالنسبة لـ TCTI mssim، يمكن تحديد اسم المجال أو عنوان IP ورقم المنفذ الذي يستخدمه المحاكي. الافتراضيات هي 127.0.0.1 و 2321.

مثال: -T mssim:host=localhost,port=2321 أو export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: بالنسبة لـ TCTI abrmd، يكون تنسيق سلسلة التكوين عبارة عن سلسلة من أزواج المفاتيح والقيم البسيطة مفصولة بحرف `,`. يتم فصل كل سلسلة مفتاح وقيمة بحرف `=`.
•
يدعم TCTI abrmd مفتاحين:
1.
`bus_name': اسم خدمة tabrmd على الناقل (سلسلة).
2.
`bus_type': نوع نسخة dbus (سلسلة) محدودة بـ `session` و `system`.

تحديد اسم tcti tabrmd وسلسلة تكوين bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

تحديد tcti الافتراضي (abrmd) وسلسلة تكوين bus_type=session:

\--tcti=session

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

tpm2_policyticket(1) — tpm2-tools documentation

NAME

tpm2_policyticket(1)

Create a ticket-able policy

SYNOPSIS

tpm2_policyticket
    [-S session_path]
    [-n signing_key_name]
    [-g hash_alg]
    [-f signature_alg]
    [-s signature_path]
    [-c signing_key_context]
    [-L policy_file]
    [-x ticket_path]
    [-t timeout]
    [-Q]

DESCRIPTION

The tpm2_policyticket command is used to set a policy for a TPM2 object that requires a ticket to authorize its use. A ticket is a data structure generated by the TPM that vouches for certain conditions being met. In this case, the ticket is used to prove that a specific signing key was used to sign a message that includes a nonce and an expiry time.

This command is typically used in conjunction with tpm2_startauthsession and tpm2_policysigned or tpm2_policyticket itself to create a policy digest. This policy digest can then be used as the policy for a TPM2 object, such as a sealed object, which can only be unsealed if the policy is met.

The policy created by this command requires that a valid signature is provided for a message composed of the session nonce, a TPM-provided nonce (if available), and an expiry time. The signature must be created using a signing key (specified by -c) and a hashing algorithm (specified by -g) and a signing scheme (specified by -f).

The ticket itself, generated by tpm2_policyticket, is a proof that the signature was valid and that the conditions (nonce, expiry time) were met. This ticket can then be used in subsequent TPM2 operations, such as unsealing a sealed object.

OPTIONS

A list of options are provided below.

--auth AUTH Authorization for the session.
-c AUTH_CONTEXT An authorization context for the signing key. This can be a TPM2 object context, a loaded key handle, or a policy digest.
-f SIGNATURE_ALG The signature algorithm used to create the signature. Supported algorithms include: rsa, ecdsa, eccnorr.
-g HASH_ALG The hash algorithm used to create the signature. Supported algorithms include: sha1, sha256, sha384, sha512.
-L POLICY_FILE Path to a file where the policy digest will be written.
-n SIGNING_KEY_NAME The name of the signing key. This is used to verify the signature.
-Q Quiet mode. Do not print anything to stdout.
-S SESSION_PATH Path to the session context file created by tpm2_startauthsession.
-s SIGNATURE_PATH Path to the file containing the signature.
--ticket TICKET_PATH Path to the file where the generated ticket will be written.
--timeout TIMEOUT The expiry time for the ticket. This is a hexadecimal value representing seconds since the epoch.

TCTI Configuration

The TPM Communication Transport Interface (TCTI) is used to specify how the tpm2-tools communicate with the TPM. This can be configured via the command line options or environment variables.

The following TCTI configurations are supported:

•
mssim: Use the simulator TCTI.
•
tcti-device: Use the device TCTI to communicate directly with the TPM device.
•
tcti-socket: Use the socket TCTI to communicate with a remote TPM.
•
tcti-armdoc-dev: Use the ARM Doc device TCTI.
•
tcti-abrmd: Use the access broker resource manager daemon TCTI.

The TCTI can be specified using the --tcti-name option or the TPM2_TCTI_NAME environment variable. For example:

TPM2_TCTI_NAME=tcti-device tpm2_command ...
tpm2_command --tcti-name=tcti-socket --socket-connect=localhost:8080 ...

The following TCTI options are available:

•
--tcti-name=NAME: Set the TCTI name.
•
--tcti-device-path=PATH: Path to the TPM device.
•
--tcti-socket-connect=HOST:PORT: Connect to a remote TPM via socket.
•
--tcti-socket-listen=PORT: Listen for incoming TPM connections on a socket.

The tcti-abrmd TCTI is configured using the following option:

•
--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

EXAMPLES

Authorize a TPM operation on an object whose authorization is bound to specific signing authority.

Create the signing authority and load the verification key

openssl genrsa -out private.pem 2048
openssl rsa -in private.pem -outform PEM -pubout -out public.pem
tpm2_loadexternal -C o -G rsa -u public.pem -c signing_key.ctx \
-n signing_key.name

Generate signature with the expiry time

EXPIRYTIME="FFFFFE0C"
echo $EXPIRYTIME | xxd -r -p | \
openssl dgst -sha256 -sign private.pem -out signature.dat

Create the policy

tpm2_startauthsession -S session.ctx
tpm2_policysigned -S session.ctx -g sha256 -s signature.dat -f rsassa \
-c signing_key.ctx -L policy.signed
tpm2_flushcontext session.ctx

Create a sealing object

tpm2_createprimary -C o -c prim.ctx -Q
echo "plaintext" > secret.dat
tpm2_create -u sealing_key.pub -r sealing_key.priv -c sealing_key.ctx \
-C prim.ctx -i secret.dat -L policy.signed -Q

Create ticket-able policy

tpm2_startauthsession -S session.ctx --nonce-tpm=nonce.test --policy-session
{ cat nonce.test & echo $EXPIRYTIME | xxd -r -p; } | \
openssl dgst -sha256 -sign private.pem -out signature.dat
tpm2_policyticket -S session.ctx -g sha256 -s signature.dat -f rsassa \
-c signing_key.ctx -x nonce.test --ticket tic.ket --timeout time.out \
-t 0xFFFFFE0C
tpm2_flushcontext session.ctx

##Test with policyticket instead of policysigned

tpm2_startauthsession -S session.ctx --policy-session
tpm2_policyticket -S session.ctx -n signing_key.name --ticket tic.ket \
--timeout time.out
tpm2_unseal -p session:session.ctx -c sealing_key.ctx

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.

Limitations

It expects a session to be already established via tpm2_startauthsession(1) and requires one of the following:

•
direct device access
•
extended session support with tpm2-abrmd.

Without it, most resource managers will not save session state between command invocations.
