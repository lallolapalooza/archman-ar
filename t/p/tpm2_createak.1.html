tpm2_createak(1)

tpm2_createak(1) دليل الأوامر العامة tpm2_createak(1)

الاسم

tpm2_createak(1) - إنشاء مفتاح مصادقة بالخوارزمية المحددة تحت تسلسل المصادقة.

الملخص

tpm2_createak [خيارات]

الوصف

tpm2_createak(1) - إنشاء مفتاح مصادقة (AK) بالخوارزمية المحددة تحت تسلسل المصادقة. يتم تحديد سياق مفتاح المصادقة عبر -c.

تخرج الأداة إلى الإخراج القياسي تمثيل YAML لاسم المفتاح المحمل، على سبيل المثال:

loaded-key:
  name: 000bac149518baa05540a0678bd9b624f8a98d042e46c60f4d098ba394d36fc49268

الخيارات

•
-P, --eh-auth=AUTH:

قيمة التفويض لتسلسل المصادقة.

•
-p, --ak-auth=AUTH

قيمة التفويض لكائن مفتاح المصادقة الذي تم إنشاؤه.

•
-C, --ek-context=OBJECT:

كائن مفتاح المصادقة.

•
-c, --ak-context=FILE:

مسار الملف لحفظ سياق كائن مفتاح المصادقة.

•
-G, --key-algorithm=ALGORITHM:

يحدد خوارزمية مفتاح المصادقة. يدعم:

•
ecc - مفتاح NIST_P256 افتراضيًا. يمكن تحديد منحنيات بديلة باستخدام محددات الخوارزمية (مثل ecc384 أو ecc_nist_p384).
•
rsa - مفتاح RSA2048.
•
keyedhash - مفتاح HMAC.
•
-g, --hash-algorithm=ALGORITHM:

يحدد خوارزمية التجزئة المستخدمة للتوقيع.

•
-s, --signing-algorithm=ALGORITHM:

خوارزمية التوقيع.

•
-u, --public=FILE:

الملف لحفظ الجزء العام من مفتاح المصادقة.

•
-n, --ak-name=FILE:

الملف لحفظ اسم مفتاح المصادقة، اختياري.

•
-r, --private=FILE:

الملف الناتج الذي يحتوي على الجزء الحساس من الكائن، اختياري. # تفاصيل الحماية

تحتاج الكائنات التي يمكن نقلها خارج TPM إلى حماية (السرية والنزاهة). على سبيل المثال، تتطلب الكائنات المؤقتة تخزين بيانات TPM المحمية (مفتاح أو مادة ختم) خارج TPM. يُرى هذا في أدوات مثل tpm2_create(1)، حيث يخرج الخيار -r هذه البيانات المحمية. يحتوي هذا الملف على الأجزاء الحساسة للكائن. يتم حماية الأجزاء الحساسة للكائن بواسطة الكائن الأصل، باستخدام تفاصيل التشفير المتماثل للكائن الأصل لتشفير البيانات الحساسة و HMAC لها.

يمكن العثور على تفاصيل معمقة في الأقسام 23 من:

•
https://trustedcomputinggroup.org/wp-content/uploads/TPM-Rev-2.0-Part-1-Architecture-01.38.pdf

خاصة الشكل 20، ذو صلة، على الرغم من أنه يشير على وجه التحديد إلى أزواج التكرار، إلا أن العملية متطابقة.

إذا كان الإخراج من tpm2_duplicate(1)، فسيكون الإخراج مختلفًا قليلاً، كما هو موضح بالكامل في القسم 23.

•
-f, --format:

اختيار تنسيق ملف الإخراج للمفتاح العام. `tss' (الافتراضي) سيخرج ملفًا ثنائيًا وفقًا لمواصفات TPM 2.0. `pem' سيخرج مفتاحًا عامًا مشفرًا متوافقًا مع OpenSSL. `der' سيخرج مفتاحًا عامًا مشفرًا متوافقًا مع OpenSSL. `tpmt' سيخرج ملفًا ثنائيًا لـ TPMT_PUBLIC المشار إليه في مواصفات TPM 2.0.

اختيار تنسيق ملف الإخراج للتوقيع.

•
-q, --ak-qualified-name=FILE:

الاسم المؤهل لكائن مفتاح المصادقة. الاسم المؤهل هو الاسم المؤهل للكائن الأصل (EK في هذه الحالة) واسم الكائن نفسه. وبالتالي، فإن الاسم المؤهل لكائن يربطه بكائناته الأصل.

المراجع

تنسيق كائن السياق

يتم تحديد نوع كائن السياق، سواء كان مقبضًا أو اسم ملف، وفقًا للمنطق التالي *بالترتيب*:

•
إذا كان الوسيط مسار ملف، فسيتم تحميل الملف ككائن TPM مؤقت مستعاد.
•
إذا كان الوسيط تطابقًا *بادئًا* مع أحد:
•
owner: تسلسل المالك
•
platform: تسلسل المنصة
•
endorsement: تسلسل المصادقة
•
lockout: الكائن الثابت للتحكم في القفل
•
إذا كان الوسيط يمكن تحميله كرقم، فسيتم التعامل معه كمقبض، على سبيل المثال 0x81010013 ويتم استخدامه مباشرة.

تنسيق التفويض

يمكن أن يأتي التفويض لاستخدام كائن في TPM2.0 في 3 أشكال مختلفة: 1. كلمة مرور 2. HMAC 3. جلسات

ملاحظة: "كلمات المرور افتراضية إلى كلمة مرور فارغة عندما لا يتم تحديدها."

كلمات المرور

يتم تفسير كلمات المرور في الأشكال التالية أدناه باستخدام معرفات البادئة.

ملاحظة: افتراضيًا، يُفترض أن تكون كلمات المرور في شكل سلسلة نصية عندما لا تحتوي على بادئة.

سلسلة نصية

كلمة مرور كسلسلة نصية، يتم تحديدها بالبادئة "str:" أو عدم وجودها (سلسلة نصية خام بدون بادئة) لا يتم تفسيرها، ويتم استخدامها مباشرة للتفويض.

أمثلة

foobar
str:foobar

سلسلة ست عشرية

كلمة مرور كسلسلة ست عشرية، يتم تحديدها بالبادئة "hex:" يتم تحويلها من شكل ست عشري إلى شكل مصفوفة بايت، مما يسمح بكلمات مرور تحتوي على أحرف غير قابلة للطباعة و/أو غير ودية للطرفية.

مثال

hex:1122334455667788

ملف

كلمة مرور مستندة إلى ملف، يتم تحديدها بالبادئة "file:" يجب أن تكون مسار ملف يحتوي على كلمة المرور ليتم قراءتها بواسطة الأداة أو "-" لاستخدام الإدخال القياسي. منع تخزين كلمات المرور في الملفات من تسرب المعلومات، وكلمات المرور التي تم تمريرها كخيارات يمكن قراءتها من قائمة العمليات وميزات سجلات الأوامر الشائعة.

أمثلة

# لاستخدام الإدخال القياسي والطلب
file:-
# لاستخدام ملف من مسار
file:path/to/password/file
# لترحيل كلمة مرور عبر الإدخال القياسي:
echo foobar | tpm2_tool -p file:-
# لاستخدام سلسلة bash هنا عبر الإدخال القياسي:
tpm2_tool -p file:- <<< foobar

جلسات

سياسات جلسات التفويض

عند استخدام جلسة سياسة لتفويض استخدام كائن، قم بوضع بادئة الوسيطة مع الكلمة المفتاحية session. ثم حدد مسارًا لملف جلسة تم إنشاؤه باستخدام tpm2_startauthsession(1). اختياريًا، إذا كانت الجلسة تتطلب قيمة مصادقة ليتم إرسالها مع معالج الجلسة (مثل كلمة مرور السياسة)، قم بإلحاق "+" وسلسلة نصية كما هو موضح في قسم كلمات المرور.

أمثلة

لاستخدام ملف سياق جلسة يسمى session.ctx.

session:session.ctx

لاستخدام ملف سياق جلسة يسمى session.ctx **و** إرسال قيمة المصادقة mypassword.

session:session.ctx+mypassword

لاستخدام ملف سياق جلسة يسمى session.ctx **و** إرسال قيمة المصادقة السداسية عشرية HEX 0x11223344.

session:session.ctx+hex:11223344

تفويضات PCR

يمكنك تلبية سياسة PCR باستخدام البادئة "pcr:" ولغة PCR المصغرة. لغة PCR المصغرة هي كالتالي: <pcr-spec>=<raw-pcr-file>

مواصفات PCR موثقة في قسم "محددات بنك PCR".

الـ raw-pcr-file هو وسيطة **اختيارية** تحتوي على مخرجات محتويات PCR الخام كما تم إرجاعها بواسطة tpm2_pcrread(1).

محددات بنك PCR

أمثلة

لتلبية سياسة PCR لـ sha256 على البنوك 0، 1، 2، و 3 استخدم محددًا من:

pcr:sha256:0,1,2,3

تحديد AUTH.

NAME

tpm2_createak - Create an attestation key (AK)

SYNOPSIS

tpm2_createak [OPTIONS] [%<KEY_NAME%>]

DESCRIPTION

tpm2_createak is used to create an attestation key (AK) for the TPM. The AK is typically generated under the endorsement hierarchy (EH) and is used for attestation purposes, allowing the TPM to prove its identity and capabilities.

This tool will create an AK and save its private key context (associated with the primary seed) and public key context (associated with the primary seed) to files specified by the caller. The caller can also specify a key name to create the AK under, which can be used to reference the AK later.

The created AK will be created in the endorsement hierarchy, and it will be created as a permanent key. If the caller would like to make it a temporary key, the caller should use the -Q or --temporary option.

The AK will be created as a signing key (as opposed to an encryption key) by default. If the caller would like to make it an encryption key, the caller should use the -G or --key-gen option and specify the desired key algorithm.

OPTIONS

-C, --parent-context=parent-context
Specifies the parent key context to create the AK under. The parent key must be in the endorsement hierarchy. Common parents are the primary endorsement key (e.g., -C e or -C 0x81010001) or a primary seed (e.g., -C -c primary.ctx).
-u, --public=public-key-file
The file to store the public key context of the AK. The public key context is used to check the signature of the AK.
-n, --name=name-file
The file to store the calculated name of the AK. The name of the AK is used to reference the AK in subsequent operations.
-p, --pem=pem-file
The file to store the public key of the AK in PEM format. This is useful for interfacing with other tools and applications that expect keys in PEM format.
-r, --private=private-key-file
The file to store the private key context of the AK. The private key context is used to sign data with the AK.
-G, --key-gen=algorithm
The algorithm to use for generating the AK. Supported algorithms include rsa, ecc. The default is rsa.
-P, --policy=policy-file
The file containing the policy digest for the AK. This is used to set the policy for the AK, which can be used to control access to the AK.
-Q, --temporary
Create the AK as a temporary key. Temporary keys are not persistent and will be lost when the TPM is reset. If this option is not specified, the AK will be created as a permanent key.
-I, --credential-paths
This option enables the creation of credential files for the AK. Credential files contain information that can be used to attest to the identity of the AK and the TPM.
-f, --force
Overwrite the output files if they already exist.
-t, --tcti=tcti-name
Specify the Tagged Connection Transport Interface (TCTI) to use. The TCTI determines how the tool communicates with the TPM. Examples include device, mssim, and tabrmd.

Context Object Format

The context object format for specifying parent keys and storing output keys is generally in the form of a path to a file that stores the key's context blob. This context blob is opaque and may be specific to the tool that generated it.

The context object can also be specified in the form of a handle that is associated with a key that has been loaded into the TPM. Handles are typically represented as hex integers prefixed with 0x.

For example, the primary endorsement key (PEK) handle is 0x81010001.

Authorization Formatting

The TPM has a concept of authorization values which are typically used for authorizing operations on keys. These authorization values can be specified in several ways:

•
As a hex string representing the authorization value. For example: 0x1234567890abcdef.
•
As a string representing a password. For example: mypassword.
•
As a policy digest. For example: -P policy.digest.
•
The default authorization value for the primary seed is empty, effectively meaning no authorization is required. However, the primary seed itself may be protected by authorization.

Algorithm Specifiers

The TPM supports various cryptographic algorithms. These algorithms can be specified by name, such as:

rsa
ecc
hmac
sha1
sha256
sha384
sha512

The supported algorithms may vary depending on the TPM version and configuration.

Signature Format Specifiers

When signing data, the output signature can be in various formats. The common formats are:

pkcs1
      ecdsa
      der
      raw

The default format is typically pkcs1 for RSA keys and ecdsa for ECC keys.

TCTI Configuration

The TCTI or “Transmission Interface” is the communication mechanism with the TPM. TCTIs can be changed for communication with TPMs across different mediums.

To control the TCTI, the tools respect:

1.
The command line option -T or --tcti
2.
The environment variable: TPM2TOOLS_TCTI.

Note: The command line option always overrides the environment variable.

The current known TCTIs are:

•
tabrmd - The resource manager, called tabrmd. Note that tabrmd and abrmd as a tcti name are synonymous.
•
mssim - Typically used for communicating to the TPM software simulator.
•
device - Used when talking directly to a TPM device file.
•
none - Do not initalize a connection with the TPM. Some tools allow for off-tpm options and thus support not using a TCTI. Tools that do not support it will error when attempted to be used without a TCTI connection. Does not support ANY options and MUST BE presented as the exact text of “none”.

The arguments to either the command line option or the environment variable are in the form:

<tcti-name>:<tcti-option-config>

Specifying an empty string for either the <tcti-name> or <tcti-option-config> results in the default being used for that portion respectively.

TCTI Defaults

When a TCTI is not specified, the default TCTI is searched for using dlopen(3) semantics. The tools will search for tabrmd, device and mssim TCTIs IN THAT ORDER and USE THE FIRST ONE FOUND. You can query what TCTI will be chosen as the default by using the -v option to print the version information. The “default-tcti” key-value pair will indicate which of the aforementioned TCTIs is the default.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

Create an Attestation Key and make it persistent

tpm2_createek -c ek.handle -G rsa -u ek.pub

tpm2_evictcontrol -C o -c ak.ctx 0x81010002

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.
