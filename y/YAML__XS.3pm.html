الحزمة: perl-yaml-libyaml

التراخيص: PerlArtistic, GPL

YAML::XS(3) توثيق Perl المساهم به YAML::XS(3)

الاسم

YAML::XS - تسلسل YAML في Perl باستخدام XS و libyaml

الملخص

use YAML::XS;
# واجهة وظيفية كلاسيكية
my $yaml = Dump [ 1..4 ];
my $array = Load $yaml;
# تجريبي: واجهة موجهة للكائنات لـ YAML 1.2
# غير متوافقة مع الواجهة الوظيفية!
my $xs = YAML::XS->new;
my $yaml = $xs->dump([ 1..4 ]);
my $array = $xs->load($yaml);

الوصف

تعتبر "libyaml" لكيريل سيمونوف ربما أفضل تطبيق YAML. تم كتابة مكتبة C بدقة لمواصفات YAML 1.1. تم ربطها في الأصل ببايثون وتم ربطها لاحقًا بـ Ruby.

هذه الوحدة هي ربط Perl XS لـ libyaml والتي توفر لـ Perl أفضل دعم YAML حتى الآن.

تُصدّر هذه الوحدة الدوال "Dump"، "Load"، "DumpFile" و "LoadFile". هذه الدوال مخصصة للعمل تمامًا مثل دوال "YAML.pm" المقابلة. يتم تصدير "Load" و "Dump" فقط افتراضيًا.

التكوين

الواجهة الموجهة للكائنات موصوفة أدناه: "الواجهة الموجهة للكائنات"

  • $YAML::XS::LoadBlessed (منذ v0.69)

    الافتراضي: خاطئ.

    تم تغيير الافتراضي في الإصدار 0.81.

    عند ضبطها على خطأ، لن تقوم بـ "bless" البيانات إلى كائنات، مما قد يمثل مشكلة أمنية عند تحميل YAML من مصدر غير موثوق به. ستتجاهل العلامة بصمت وتحمل البيانات غير "blessed" فقط.

    في PyYAML، يُطلق على هذا SafeLoad.

    إذا تم ضبطها على صحيح، فستقوم بتحميل YAML التالي ككائنات:

    ---
local: !Foo::Bar [a]
perl: !!perl/hash:Foo::Bar { a: 1 }
regex: !!perl/regexp:Foo::Bar pattern

    يمكنك إنشاء أي نوع من الكائنات باستخدام YAML. الإنشاء بحد ذاته ليس الجزء الحرج. إذا كان للفئة طريقة "DESTROY"، فسيتم استدعاؤها بمجرد حذف الكائن. مثال مع File::Temp لإزالة الملفات يمكن العثور عليه في https://bugs.debian.org/cgi-bin/bugreport.cgi?bug=862373.

  • $YAML::XS::ForbidDuplicateKeys (منذ 0.84)

    الافتراضي: خطأ

    عند ضبطها على صحيح، ستفشل "Load" عند مواجهة مفتاح مكرر في جدول هاش، على سبيل المثال:

    key: value
key: another value

    يمكن أن يكون هذا مفيدًا للمستندات YAML الأكبر حيث يكون الأمر أقل وضوحًا، ويوصى بضبطه على صحيح. هذا هو ما يجب أن يقوم به محمل YAML افتراضيًا وفقًا لمواصفات YAML.

  • $YAML::XS::UseCode
  • $YAML::XS::DumpCode
  • $YAML::XS::LoadCode

    إذا تم تمكينه، يدعم فك التشفير وتقييم كتل التعليمات البرمجية.

    لاحظ أنه تم إضافة دعم لتحميل التعليمات البرمجية في الإصدار 0.75، على الرغم من أن $LoadCode تم توثيقه بالفعل في الإصدارات السابقة.

  • $YAML::XS::QuoteNumericStrings

    عندما تكون صحيحًا (الافتراضي)، سيتم اقتباس السلاسل التي تبدو كرقم ولكن لم يتم تحويلها إلى رقم عند التفريغ.

    يضمن هذا الاحتفاظ بالتنسيق مثل الأصفار البادئة وغيرها.

  • $YAML::XS::Boolean (منذ v0.67)

    الافتراضي: غير محدد

    منذ YAML::XS 0.89: عند الاستخدام مع perl 5.36 أو أحدث، ستعمل القيم المنطقية المدمجة مباشرة. سيتم إنشاؤها بواسطة "Load" وسيتم التعرف عليها بواسطة "Dump" تلقائيًا (منذ YAML::XS 0.89).

    say Dump({ truth => builtin::true });
# truth: true

    منذ YAML::XS v0.902: القيم المنطقية المحملة لم تعد للقراءة فقط.

    بالنسبة لإصدارات perl الأقدم، يمكنك استخدام التكوين التالي لتحويل البيانات إلى قيم منطقية YAML:

    عند ضبطها على "JSON::PP" أو "boolean"، سيتم تحميل السلاسل النصية (غير المقتبسة) "true" و "false" ككائنات "JSON::PP::Boolean" أو "boolean.pm". سيتم تفريغ هذه الكائنات مرة أخرى كسلاسل نصية عادية "true" أو "false".

    سيحاول تحميل [JSON::PP] أو [boolean] وسيفشل إذا لم يكن يمكن تحميله.

    مع ذلك، من الممكن إضافة قيم منطقية "حقيقية" جديدة إلى هيكل بيانات:

    local $YAML::XS::Boolean = "JSON::PP"; # أو "boolean"
my $data = Load("booltrue: true");
$data->{boolfalse} = JSON::PP::false;
my $yaml = Dump($data);
# boolfalse: false
# booltrue: true

    كما أنها تسمح للقيم المنطقية بالبقاء عند تحميل YAML عبر YAML::XS وتشفيرها بتنسيق JSON عبر أحد مشفرات JSON المختلفة، والتي تدعم في الغالب قيم JSON::PP المنطقية.

    يرجى ملاحظة أن JSON::PP::Boolean و boolean.pm يتصرفان بشكل مختلف قليلاً. من الناحية المثالية، يجب عليك استخدامهما فقط في سياق منطقي.

    إذا لم يتم ضبطها، يتم تحميل القيم المنطقية كمتغيرات perl خاصة "PL_sv_yes" و "PL_sv_no"، والتي لها عيب أنها للقراءة فقط، ولا يمكنك إضافتها إلى هيكل بيانات موجود باستخدام perl النقي.

    إذا كنت تحتاج ببساطة إلى تحميل "القيم المنطقية لـ perl" التي تكون صحيحة أو خاطئة في سياق منطقي، فستكون راضيًا عن الإعداد الافتراضي.

  • $YAML::XS::Indent (منذ v0.76)

    الافتراضي هو 2.

    يحدد عدد المسافات للمسافة البادئة لـ "Dump".

استخدام YAML::XS مع Unicode

التعامل مع unicode بشكل صحيح في Perl يمكن أن يكون مؤلمًا. YAML::XS يتعامل فقط مع تيارات من وحدات octets utf8. فقط تذكر هذا:

$perl = Load($utf8_octets);
$utf8_octets = Dump($perl);

هناك العديد والعديد من الأماكن التي يمكن أن تحدث فيها مشاكل مع unicode. إذا كنت تواجه مشاكل، استخدم Devel::Peek على جميع نقاط البيانات المحتملة.

منذ الإصدار v0.904.0، تجريبي

+++ملاحظة: هذا غير متوافق مع الواجهة الوظيفية وسيتعامل مع قيم YAML بطريقة مختلفة.+++

هناك فرقان رئيسيان عن الواجهة الوظيفية القديمة:

كائن مع خيارات
يوفر هذا واجهة تنشئ فيها كائن YAML::XS مع خيارات (بدلاً من الواجهة القديمة مع المتغيرات العامة).
مخطط YAML 1.2 الأساسي
يطبق مخطط YAML 1.2 الأساسي.

(لاحظ أن الواجهة الوظيفية لا تطبق YAML 1.1، عندما يتعلق الأمر بتحميل الأرقام والقيم المنطقية والمفتاح الفارغ وما إلى ذلك. إنها تطبق مجموعتها الخاصة من القواعد.)

إليك مثال (غير مكتمل!) للقيم التي يتم التعامل معها بشكل مختلف مقارنة بالواجهة الوظيفية. قيم YAML التي تطابق نمطًا معينًا، لا يتم تحميلها كسلاسل نصية، بل كأنواع أخرى:

# الواجهة الوظيفية: قيم خاصة (غير متوافقة مع وحدات YAML الأخرى)
- [true, false]                             # قيم منطقية
- [null, ~]                                 # غير محدد
- [inf, INF, iNf, iNF, InF, INf, -inf, ...] # Inf (لا نهائي)
- [100_000]                                 # 100000
- # anything that looks_like_number()       # رقم
# كائنات YAML 1.2 الخاصة
- [true, True, TRUE, false, False, FALSE]   # قيم منطقية
- [null, Null, NULL, ~]                     # غير محدد
- [.inf, .Inf, .INF, -.inf, -.Inf, -.INF]   # Inf (لا نهائي)
- [.nan, .NAN, .NaN]                        # nan (ليس رقمًا)
- [42, 0x10, 0o10]                          # عشري 42، سداسي عشري 16، ثماني 8

للحصول على اختلافات أكثر دقة فيما يتعلق بالأرقام، تحقق من البيانات الشاملة هنا:

تعريفات YAML 1.1 / 1.2: <https://perlpunk.github.io/

NAME

YAML::XS - YAML support for Perl, implemented in C

SYNOPSIS

use YAML::XS;
my $xs = YAML::XS->new;
my $yaml = "foo: bar";
# Load single (first) document:
my $data = $xs->load($yaml);
$yaml = $xs->dump($data);
# Or to load all documents:
my @data = $xs->load($yaml);
$yaml = $xs->dump(@data);

DESCRIPTION

This module implements the YAML 1.2 specification using the libyaml C library.

The intent is to provide a fast, reliable YAML parser and emitter for Perl.

It provides an object-oriented interface, which is compatible with YAML::PP, and a functional interface which is compatible with YAML::Syck.

The functional interface will dump the arguments in the order they are given, and load will return all documents found in the YAML string.

YAML 1.2 support
The module implements the YAML 1.2 specification.
Test data: <https://perlpunk.github.io/yaml-test-schema/data.html>
Schema: <https://perlpunk.github.io/yaml-test-schema/schemas.html>

This way the OOP interface is compatible to YAML::PP and YAML processors in other languages supporting YAML 1.2.

"load" will return the first document in scalar context
The functional interface returns the last.
Numbers don't have string flags
Booleans currently are only preserved for the new builtin booleans
Adding a JSON::PP boolean option for older perls is planned
References, objects, globs, regexes and coderefs cannot be loaded or dumped
This is planned.

Usage

use YAML::XS ();
my $xs = YAML::XS->new;
my $yaml = "foo: bar";
# Load single (first) document:
my $data = $xs->load($yaml);
$yaml = $xs->dump($data);
# Or to load all documents:
my @data = $xs->load($yaml);
$yaml = $xs->dump(@data);

METHODS

new

use YAML::XS;
my $xs = YAML::XS->new(
    # load options
    # require_footer => 0,
    # dump options
    # indent => 2,
    # header => 1,
    # footer => 0,
    # width => 80,
    # anchor_prefix => '',
    # load and dump options
    # utf8 => 0,
);

Options:

indent
Default: 2

Sets the number of spaces for indentation for dumping.

utf8
Default: false

When false, the loader will accept unencoded character strings, and the dumper returns unencoded character strings.

When true, the loader accepts a UTF-8 encoded string of bytes, and the dumper returns a UTF-8 encoded string of bytes. This typically makes sense when you read from / write to a file directly.

header
Default: 1

Writes a "---" before every document

footer
Default: 0

Writes a "..." at the end of every document.

width
Set the maximum number of colums for dumping. If a value has too many characters, it will be split into multiple lines.
require_footer
Default: 0

Can be useful in a use case where you want to make sure you received the complete document from the sender.

anchor_prefix
Default: ''

If set to a string like "ANCHOR", anchors and aliases will be prefixed with this instead of just being numbers:

# my $xs = YAML::XS->new( anchor_prefix => 'ANCHOR' );
# my $hash = { some => "mapping" };
# say $xs->dump([$hash, $hash]);
- &ANCHOR1
  some: mapping
- *ANCHOR1

load

my $yaml = <<'EOM';
---
- 23
---
some: mapping
EOM
my $array = $xs->load($yaml);
# [23]
my @documents = $xs->load($yaml);
# (
#   [23],
#   { some => "mapping" }
# )

In scalar context, if the YAML string contains more than one document, it will return the first document.

dump

$yaml = $xs->dump($data);
$yaml = $xs->dump($data1, $data2, $data3);
$yaml = $xs->dump(@data);

CONFIGURATION

The YAML::XS OO interface uses the following options:

indent
Sets the number of spaces for indentation for dumping. Default is 2.
utf8
If set to 1, the loader accepts a UTF-8 encoded string of bytes, and the dumper returns a UTF-8 encoded string of bytes. This typically makes sense when you read from / write to a file directly. Default is 0.
header
If set to 1, writes a "---" before every document. Default is 1.
footer
If set to 1, writes a "..." at the end of every document. Default is 0.
width
Set the maximum number of columns for dumping. If a value has too many characters, it will be split into multiple lines. Default is 80.
anchor_prefix
If set to a string like "ANCHOR", anchors and aliases will be prefixed with this instead of just being numbers.
require_footer
If set to 1, the loader will require a trailing "..." at the end of the document. Default is 0.

USING YAML::XS WITH UNICODE

By default, YAML::XS operates in bytes mode. This means that when you load YAML, it returns Perl strings that might contain non-ASCII characters as sequences of bytes. When you dump Perl strings, it outputs those bytes as-is.

If you want to work with Unicode strings (Perl's internal character representation), you need to enable UTF-8 mode by passing utf8 => 1 to the new method:

my $xs = YAML::XS->new( utf8 => 1 );

In this mode:

  • The loader accepts a UTF-8 encoded string of bytes. It decodes this into Perl's internal representation of Unicode characters.
  • The dumper returns a UTF-8 encoded string of bytes. It encodes Perl's internal representation of Unicode characters into UTF-8.

This mode is typically what you want when reading from/writing to files directly, or when communicating with other systems that expect UTF-8 encoded data.

OBJECT ORIENTED INTERFACE

The object-oriented interface is provided by the YAML::XS class.

You create an instance like this:

my $xs = YAML::XS->new;

And then use the load and dump methods:

my $data = $xs->load($yaml_string);
my $yaml_string = $xs->dump($perl_data);

The load method returns the first document in scalar context, and all documents in list context.

The dump method can take one or more arguments, each of which will be dumped as a separate YAML document.

LIBYAML

You can find out (since v.079) which libyaml version this module was built with:

my $libyaml_version = YAML::XS::LibYAML::libyaml_version();
