SYNOPSIS

#include <rpc/rpc.h>

See DESCRIPTION for function declarations.

DESCRIPTION

The svc_*() and clnt_*() functions described in this page are the old, TS-RPC interface to the XDR and RPC library, and exist for backward compatibility. The new interface is described in the pages referenced from rpc(3).

These routines allow C programs to make procedure calls on other machines across the network. First, the client calls a procedure to send a data packet to the server. Upon receipt of the packet, the server calls a dispatch routine to perform the requested service, and then sends back a reply. Finally, the procedure call returns to the client.

Routines that are used for Secure RPC (DES authentication) are described in rpc_secure(3). Secure RPC can be used only if DES encryption is available.

void
 
auth_destroy(AUTH *auth)

A macro that destroys the authentication information associated with auth. Destruction usually involves deallocation of private data structures. The use of auth is undefined after calling auth_destroy().

AUTH *
 
authnone_create()

Create and return an RPC authentication handle that passes nonusable authentication information with each remote procedure call. This is the default authentication used by RPC.

AUTH *
 
authunix_create(char *host, int uid, int gid, int len, int *aup_gids)

Create and return an RPC authentication handle that contains UNIX authentication information. The host argument is the name of the machine on which the information was created; uid is the user's user ID; gid is the user's current group ID; len and aup_gids refer to a counted array of groups to which the user belongs. It is easy to impersonate a user.

AUTH *
 
authunix_create_default()

Calls authunix_create() with the appropriate arguments.

int callrpc(char *host, u_long prognum, u_long versnum, u_long procnum, xdrproc_t inproc, void *in, xdrproc_t outproc, void *out);

Call the remote procedure associated with prognum, versnum, and procnum on the machine host. The in argument is the address of the procedure's argument(s), and out is the address of where to place the result(s); inproc is used to encode the procedure's arguments, and outproc is used to decode the procedure's results. This routine returns zero if it succeeds, or the value of enum clnt_stat cast to an integer if it fails. The routine clnt_perrno() is handy for translating failure statuses into messages.

Warning: calling remote procedures with this routine uses UDP/IP as a transport; see clntudp_create() for restrictions. You do not have control of timeouts or authentication using this routine.

enum clnt_stat
 
clnt_broadcast(u_long prognum, u_long versnum, u_long procnum, xdrproc_t inproc, char *in, xdrproc_t outproc, char *out, bool_t (*eachresult)(caddr_t, struct sockaddr_in *));

Like callrpc(), except the call message is broadcast to all locally connected broadcast nets. Each time it receives a response, this routine calls eachresult(), whose form is:

bool_t eachresult(caddr_t out, struct sockaddr_in *addr)

where out is the same as out passed to clnt_broadcast() and addr is the address of the machine that sent the response. If eachresult() returns true, clnt_broadcast() continues to listen for more responses. If it returns false, clnt_broadcast() gives up and returns.

enum clnt_stat
 
clnt_call(CLIENT *clnt, u_long procnum, xdrproc_t inproc, char *in, xdrproc_t outproc, char *out);

Make a remote procedure call using the transport handle clnt. The arguments and results are encoded/decoded using inproc and outproc respectively. The values of procnum are determined by the specific RPC service being called. The values for procnum are typically defined in the header file that corresponds to the RPC service's interface definition.

bool_t
 
clnt_control(CLIENT *clnt, int request, char *arg);

The clnt_control() function is used to control a client handle. The request parameter specifies the control operation, and arg is a pointer to a parameter for the operation. The possible requests are:

CLGET_timeouts
If arg is non-null, it points to a structure that is filled with the current retry timeout values.
CLSET_timeouts
If arg is non-null, it points to a structure containing the new retry timeout values. This is used for TCP transports and for UDP transports that specify a buffer size.
CLGET_SERVER_ADDR
If arg is non-null, it points to a struct sockaddr_in that is filled with the server's address.

Create a client handle for making remote procedure calls to the specified RPC prognum and versnum on the specified host. The nettype parameter specifies the network, which can be "udp" or "tcp". clnt_create() returns a CLIENT handle, or NULL on failure.

bool_t svc_destroy(SVCXPRT * xprt)

يربط prognum و versnum بإجراء توزيع الخدمة، dispatch(). إذا كانت protocol صفرًا، فلا يتم تسجيل الخدمة مع خدمة rpcbind(8). إذا كانت protocol غير صفرية، فسيتم إنشاء تعيين للثلاثي (prognum، versnum، protocol) إلى xprt->xp_port مع خدمة rpcbind(8) المحلية (بشكل عام protocol هو صفر، IPPROTO_UDP، أو IPPROTO_TCP). يكون للإجراء dispatch() الشكل التالي:

تعيد الدالة svc_register() واحدًا إذا نجحت، وصفرًا بخلاف ذلك.

svc_run()

هذه الدالة لا تعود أبدًا. تنتظر وصول طلبات RPC، وتستدعي إجراء الخدمة المناسب باستخدام svc_getreq() عند وصول واحد. عادة ما تنتظر هذه الإجراءات استدعاء نظام select(2) ليعود.

SVCXPRT *
 
svcraw_create(void)

تنشئ هذه الروتينية نقلاً لخدمة RPC وهمية، وتعيد مؤشرًا إليها. النقل هو في الواقع مخزن مؤقت داخل مساحة عنوان العملية، لذلك يجب أن يعيش عميل RPC المقابل في نفس مساحة العنوان؛ انظر clntraw_create(). تسمح هذه الروتينية بمحاكاة RPC واكتساب نفقات RPC (مثل أوقات الذهاب والعودة)، دون أي تدخل من النواة. تعيد هذه الروتينية NULL إذا فشلت.

SVCXPRT *
 
svctcp_create(int sock, u_int send_buf_size, u_int recv_buf_size)

تنشئ هذه الروتينية نقلاً لخدمة RPC يعتمد على TCP/IP، وتعيد مؤشرًا إليه. يرتبط النقل بالمقبس sock، والذي يمكن أن يكون RPC_ANYSOCK، وفي هذه الحالة يتم إنشاء مقبس جديد. إذا لم يكن المقبس مرتبطًا بمنفذ TCP محلي، فإن هذه الروتينية تربطه بمنفذ عشوائي. عند الانتهاء، يكون xprt->xp_fd هو واصف مقبس النقل، و xprt->xp_port هو رقم منفذ النقل. تعيد هذه الروتينية NULL إذا فشلت. نظرًا لأن RPC المعتمد على TCP يستخدم عمليات الإدخال/الإخراج المخزنة مؤقتًا، يمكن للمستخدمين تحديد حجم المخازن المؤقتة؛ القيم الصفرية تختار افتراضيات مناسبة.

SVCXPRT *
 
svcunix_create(int sock, u_int send_buf_size, u_int recv_buf_size, char *path)

تنشئ هذه الروتينية نقلاً لخدمة RPC يعتمد على UNIX، وتعيد مؤشرًا إليه. يرتبط النقل بالمقبس sock، والذي يمكن أن يكون RPC_ANYSOCK، وفي هذه الحالة يتم إنشاء مقبس جديد. الوسيط *path هو مسار اسم نظام ملفات متغير الطول بحد أقصى 104 أحرف. لا تتم إزالة هذا الملف عند إغلاق المقبس. يجب استخدام استدعاء النظام unlink(2) لإزالة الملف. عند الانتهاء، يكون xprt->xp_fd هو واصف مقبس النقل. تعيد هذه الروتينية NULL إذا فشلت. نظرًا لأن RPC المعتمد على UNIX يستخدم عمليات الإدخال/الإخراج المخزنة مؤقتًا، يمكن للمستخدمين تحديد حجم المخازن المؤقتة؛ القيم الصفرية تختار افتراضيات مناسبة.
