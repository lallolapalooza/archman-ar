NAME

recvmsg - receive a message from a socket

SYNOPSIS

#include <sys/socket.h>
ssize_t recvmsg(int sockfd, struct msghdr *msg, int flags);

DESCRIPTION

The recvmsg() function is used to receive messages from a socket, and may be used to receive data, control information, and the sender's address.

The msg argument points to a msghdr structure, which contains information about the message to be received.

struct msghdr {
    void         *msg_name;       /* optional address to report sender */
    socklen_t     msg_namelen;    /* size of address to store */
    struct iovec *msg_iov;        /* scatter/gather array of buffers */
    msg_iovlen_t  msg_iovlen;     /* number of elements in msg_iov */
    void         *msg_control;    /* ancillary data */
    socklen_t     msg_controllen; /* buffer length for ancillary data */
    int           msg_flags;      /* flags filled in by the kernel */
};

The msg_name and msg_namelen fields specify the buffer and length, respectively, that will hold the sender's address. If the socket is of a connection-oriented type (e.g., SOCK_STREAM), or if the peer address is not required, these fields can be set to NULL and 0, respectively.

The msg_iov and msg_iovlen fields specify an array of iovec structures, which are used to hold the message data. Each iovec structure specifies a buffer and its size:

struct iovec {
    void  *iov_base;    /* Starting address of buffer */
    size_t iov_len;     /* Length of buffer */
};

The kernel will scatter the received data across the buffers specified by the msg_iov array. The msg_iovlen field specifies the number of iovec structures in the array.

The msg_control and msg_controllen fields specify the buffer and length, respectively, for receiving ancillary data (also known as control information or "control messages"). Ancillary data is used to transmit information other than the normal message data, such as access control information or other protocol-specific data. If no ancillary data is expected or desired, these fields can be set to NULL and 0, respectively.

The msg_flags field is used by the kernel to return message flags. It may be used to return flags such as MSG_TRUNC, MSG_CTRUNC, and MSG_PEEK.

The flags argument specifies options that control the behavior of the recvmsg() function. The following flags are supported:

  • MSG_CMSG_CLOEXEC
    If this flag is set, the close-on-exec flag is set for the file descriptor associated with the socket. This means that the file descriptor will be closed automatically when an execve() is performed. (Introduced in POSIX.1-2008.)
  • MSG_DONTWAIT
    (The same effect as the SO_DONTWAIT socket option.) Non-blocking operation; if the operation would block, the function returns an error of EAGAIN.
  • MSG_ERRQUEUE
    Requests delivery of messages from the socket error queue. For certain protocol errors, a protocol control message (see IP_RECVERROR in ip(7)) is placed in the receive error queue. This flag allows receiving such error messages. The received message will have a protocol specific error code as its associated ancillary data.
  • MSG_PEEK
    Leave the data in the input queue as a result of the read. This is useful to examine incoming data without consuming it.
  • MSG_TRUNC
    If the message is larger than the buffer size specified by the msg_iovlen and msg_iov fields, the data is truncated. If MSG_TRUNC is set, the caller may be able to retrieve the rest of the data by calling recvmsg() again.
  • MSG_WAITALL
    Wait for all of the requested data to be received. The call will return only when the requested data size has been received or an error occurs.

RETURN VALUE

On success, recvmsg() returns the number of bytes received. On error, -1 is returned, and errno is set to indicate the error.

If the connection has been gracefully closed, 0 may be returned.

ERRORS

EBADF
Invalid file descriptor.
ECONNRESET
Connection reset by peer.
EFAULT
An invalid user pointer was given.
EINTR
The operation was interrupted by a signal.
EINVAL
Invalid argument value.
EISCONN
The socket is connection-mode and already connected.
ENOTCONN
The socket is connection-mode and is not connected.
ENOTSOCK
The file descriptor does not refer to a socket.
EOPNOTSUPP
The operation is not supported on the socket.
EWOULDBLOCK, EAGAIN
The socket is marked non-blocking and the receive operation would block.

EXAMPLES

The following example shows how to receive a datagram from a UDP socket:

    struct sockaddr_in addr;
    char buffer[1024];
    struct iovec iov[1];
    struct msghdr msg;

    iov[0].iov_base = buffer;
    iov[0].iov_len = sizeof(buffer);

    msg.msg_name = &addr;
    msg.msg_namelen = sizeof(addr);
    msg.msg_iov = iov;
    msg.msg_iovlen = 1;
    msg.msg_control = NULL;
    msg.msg_controllen = 0;
    msg.msg_flags = 0;

    ssize_t numbytes = recvmsg(sockfd, &msg, 0);
    if (numbytes < 0) {
        perror("recvmsg");
    } else {
        printf("Received %zd bytes from %s:%d\n",
               numbytes,
               inet_ntoa(addr.sin_addr),
               ntohs(addr.sin_port));
        // Process the received data in buffer
    }

APPLICATION USAGE

The select() and poll() functions can be used to determine when data is available to be received.

الاسم

recvmsg - استقبال رسالة من مقبس

ملخص

#include <sys/socket.h>
ssize_t recvmsg(int sockfd, struct msghdr *msg, int flags);

الوصف

تُستخدم الدالة recvmsg() لاستقبال الرسائل من المقبس، وقد تُستخدم لاستقبال البيانات ومعلومات التحكم وعنوان المرسل.

يشير الوسيط msg إلى بنية msghdr، والتي تحتوي على معلومات حول الرسالة المراد استقبالها.

struct msghdr {
    void         *msg_name;       /* عنوان اختياري للإبلاغ عن المرسل */
    socklen_t     msg_namelen;    /* حجم العنوان المراد تخزينه */
    struct iovec *msg_iov;        /* مصفوفة تشتيت/تجميع للمخازن المؤقتة */
    msg_iovlen_t  msg_iovlen;     /* عدد العناصر في msg_iov */
    void         *msg_control;    /* بيانات مساعدة */
    socklen_t     msg_controllen; /* طول المخزن المؤقت للبيانات المساعدة */
    int           msg_flags;      /* العلامات التي يملأها النواة */
};

تحدد الحقول msg_name و msg_namelen المخزن المؤقت وطوله، على التوالي، اللذين سيحتويان على عنوان المرسل. إذا كان المقبس من نوع موجه بالاتصال (على سبيل المثال، SOCK_STREAM)، أو إذا لم يكن عنوان النظير مطلوبًا، فيمكن تعيين هذه الحقول إلى NULL و 0، على التوالي.

تحدد الحقول msg_iov و msg_iovlen مصفوفة من بنى iovec، والتي تُستخدم للاحتفاظ ببيانات الرسالة. تحدد كل بنية iovec مخزنًا مؤقتًا وحجمه:

struct iovec {
    void  *iov_base;    /* عنوان بداية المخزن المؤقت */
    size_t iov_len;     /* طول المخزن المؤقت */
};

ستقوم النواة بتشتيت البيانات المستلمة عبر المخازن المؤقتة المحددة بواسطة مصفوفة msg_iov. يحدد حقل msg_iovlen عدد بنى iovec في المصفوفة.

تحدد الحقول msg_control و msg_controllen المخزن المؤقت وطوله، على التوالي، لاستقبال البيانات المساعدة (المعروفة أيضًا باسم معلومات التحكم أو "رسائل التحكم"). تُستخدم البيانات المساعدة لنقل معلومات بخلاف بيانات الرسالة العادية، مثل معلومات التحكم في الوصول أو بيانات أخرى خاصة بالبروتوكول. إذا لم يكن من المتوقع أو الرغبة في الحصول على بيانات مساعدة، فيمكن تعيين هذه الحقول إلى NULL و 0، على التوالي.

يُستخدم الحقل msg_flags بواسطة النواة لإرجاع علامات الرسالة. قد يُستخدم لإرجاع علامات مثل MSG_TRUNC و MSG_CTRUNC و MSG_PEEK.

يحدد الوسيط flags خيارات تتحكم في سلوك الدالة recvmsg(). تُدعم العلامات التالية:

  • MSG_CMSG_CLOEXEC
    إذا تم تعيين هذه العلامة، يتم تعيين علامة الإغلاق عند التنفيذ لوصف الملف المرتبط بالمقبس. هذا يعني أنه سيتم إغلاق وصف الملف تلقائيًا عند إجراء execve(). (تم تقديمه في POSIX.1-2008).
  • MSG_DONTWAIT
    (نفس تأثير خيار المقبس SO_DONTWAIT). عملية غير مانعة؛ إذا كانت العملية ستؤدي إلى حظر، فإن الدالة تُرجع خطأ EAGAIN.
  • MSG_ERRQUEUE
    يطلب تسليم الرسائل من قائمة انتظار أخطاء المقبس. بالنسبة لأخطاء بروتوكول معينة، يتم وضع رسالة تحكم بروتوكول (انظر IP_RECVERROR في ip(7)) في قائمة انتظار أخطاء الاستقبال. تسمح هذه العلامة باستقبال مثل هذه الرسائل الخطأ. ستحتوي الرسالة المستلمة على رمز خطأ خاص بالبروتوكول كبيانات مساعدة مرتبطة بها.
  • MSG_PEEK
    ترك البيانات في قائمة الإدخال نتيجة للقراءة. هذا مفيد لفحص البيانات الواردة دون استهلاكها.
  • MSG_TRUNC
    إذا كانت الرسالة أكبر من حجم المخزن المؤقت المحدد بواسطة الحقول msg_iovlen و msg_iov، فسيتم اقتطاع البيانات. إذا تم تعيين MSG_TRUNC، فقد يتمكن المتصل من استرداد بقية البيانات عن طريق استدعاء recvmsg() مرة أخرى.
  • MSG_WAITALL
    الانتظار حتى يتم استلام كل البيانات المطلوبة. ستعود المكالمة فقط عندما يتم استلام حجم البيانات المطلوب أو يحدث خطأ.

قيمة الإرجاع

عند النجاح، تُرجع recvmsg() عدد البايتات المستلمة. عند حدوث خطأ، يتم إرجاع -1، ويتم تعيين errno للإشارة إلى الخطأ.

إذا تم إغلاق الاتصال بشكل طبيعي، فقد يتم إرجاع 0.

الأخطاء

EBADF
وصف ملف غير صالح.
ECONNRESET
تمت إعادة تعيين الاتصال بواسطة النظير.
EFAULT
تم تقديم مؤشر مستخدم غير صالح.
EINTR
تمت مقاطعة العملية بواسطة إشارة.
EINVAL
قيمة وسيط غير صالحة.
EISCONN
المقبس من نوع اتصال وموصل بالفعل.
ENOTCONN
المقبس من نوع اتصال وغير متصل.
ENOTSOCK
لا يشير وصف الملف إلى مقبس.
EOPNOTSUPP
العملية غير مدعومة على المقبس.
EWOULDBLOCK, EAGAIN
تم تمييز المقبس على أنه غير مانع وعملية الاستقبال ستؤدي إلى حظر.

    struct sockaddr_in addr;

    }

يمكن استخدام الدالتين select() و poll() لتحديد متى تكون البيانات متاحة للاستقبال.
