اسم

re2hs - إنشاء محللات معجمية سريعة لـ Haskell

ملخص

re2hs [ خيارات ] [ تحذيرات ] المدخل

يمكن أن يكون المدخل إما ملفًا أو - لـ stdin.

مقدمة

يعمل re2hs كمعالج مسبق. يقرأ ملف الإدخال (وهو عادةً برنامج بلغة Haskell، ولكن يمكن أن يكون أي شيء) ويبحث عن كتل التعليمات البرمجية المغلفة بعلامات بدء/نهاية خاصة الشكل. يتم نسخ النص خارج هذه الكتل حرفيًا إلى ملف الإخراج. تتم معالجة محتويات الكتل بواسطة re2hs. يقوم بترجمتها إلى شفرة بلغة Haskell ويخرج الشفرة المولدة في مكان الكتلة.

إليك مثال لبرنامج صغير يتحقق مما إذا كان سلسلة معينة تحتوي على رقم عشري:

-- re2hs $INPUT -o $OUTPUT -i
{-# LANGUAGE OverloadedStrings #-}
{-# OPTIONS_GHC -Wno-unused-record-wildcards #-}
import Data.ByteString (ByteString, index)
data State = State {
    _yyinput :: ByteString,
    _yycursor :: Int
}
%{
    re2c:YYFN = ["lexer;Bool", "State{..};State"];
    re2c:yyfill:enable = 0;
    [1-9][0-9]* { True }
    *           { False }
%}
main :: IO ()
main = case lexer State{_yyinput = "1234\0", _yycursor = 0} of
    True -> return ()
    False -> error "lexer failed!"

في الإخراج، استبدل re2hs الكتلة في المنتصف بالشفرة المولدة:

-- تم الإنشاء بواسطة re2hs
{-# LANGUAGE RecordWildCards #-}
-- re2hs $INPUT -o $OUTPUT -i
{-# LANGUAGE OverloadedStrings #-}
{-# OPTIONS_GHC -Wno-unused-record-wildcards #-}
import Data.ByteString (ByteString, index)
data State = State {
    _yyinput :: ByteString,
    _yycursor :: Int
}
yy0 :: State -> Bool
yy0 State{..} =
    let yych = index _yyinput _yycursor in
    let __ = _yycursor + 1 in let _yycursor = __ in
    case yych of
        _c | 0x31 <= _c && _c <= 0x39 ->
            yy2 State{..}
        _c | True ->
            yy1 State{..}
yy1 :: State -> Bool
yy1 State{..} =
    False
yy2 :: State -> Bool
yy2 State{..} =
    let yych = index _yyinput _yycursor in
    case yych of
        _c | 0x30 <= _c && _c <= 0x39 ->
            let __ = _yycursor + 1 in let _yycursor = __ in
            yy2 State{..}
        _c | True ->
            yy3 State{..}
yy3 :: State -> Bool
yy3 State{..} =
    True
lexer :: State -> Bool
lexer State{..} =
    yy0 State{..}
main :: IO ()
main = case lexer State{_yyinput = "1234\0", _yycursor = 0} of
    True -> return ()
    False -> error "lexer failed!"

أساسيات

يتكون برنامج re2hs من سلسلة من الكتل المتناوبة مع شفرة في اللغة المستهدفة. قد تحتوي الكتلة على تعريفات، تكوينات، قواعد، إجراءات و توجيهات بأي ترتيب:

الاسم = تعبير-عادي ;
التعريف يربط الاسم بـ التعبير-العادي. يمكن أن تحتوي الأسماء على أحرف أبجدية رقمية وشرطة سفلية. يقدم قسم التعبيرات العادية نظرة عامة على صيغة re2hs للتعبيرات العادية. بمجرد تعريفه، يمكن استخدام الاسم في تعبيرات عادية أخرى وفي القواعد. لا يُسمح بالتكرار في التعريفات المسماة، ويجب تعريف كل اسم قبل استخدامه. ترث الكتلة التعريفات المسماة من النطاق العام. إعادة تعريف اسم موجود في النطاق الحالي هو خطأ.
تكوين = قيمة ;
التكوين يسمح للمرء بتغيير سلوك re2hs وتخصيص الشفرة المولدة. للحصول على قائمة كاملة بالتكوينات التي يدعمها re2hs، راجع قسم التكوينات. اعتمادًا على تكوين معين، يمكن أن تكون القيمة كلمة مفتاحية، أو رقم صحيح غير سالب، أو سلسلة نصية من سطر واحد يجب أن تكون محاطة بعلامات اقتباس مزدوجة أو فردية ما لم تتكون من أحرف أبجدية رقمية. ترث الكتلة التكوينات من النطاق العام ويمكنها إعادة تعريفها أو إضافة تكوينات جديدة. التكوينات المعرفة داخل كتلة تؤثر على الكتلة بأكملها، حتى لو ظهرت في نهايتها.
تعبير-عادي شفرة
القاعدة تربط التعبير-العادي بإجراءها الدلالي (كتلة شفرة بأقواس متعرجة، أو كتلة شفرة تبدأ بـ := وتنتهي بسطر جديد متبوعًا بأي حرف غير مسافة بيضاء). إذا تطابق التعبير-العادي، يتم تنفيذ الشفرة المرتبطة به. إذا تطابقت عدة قواعد، فإن أطول تطابق له الأسبقية. إذا تطابقت عدة قواعد مع نفس السلسلة، فإن أقدمها له الأسبقية. هناك قاعدتان خاصتان: القاعدة الافتراضية * وقاعدة نهاية الإدخال $. يجب تعريف القاعدة الافتراضية دائمًا، ولها أقل أولوية بغض النظر عن مكانها في الكتلة، وتتطابق مع أي وحدة رمز (ليس بالضرورة حرفًا صالحًا، انظر قسم دعم الترميز). يجب تعريف قاعدة نهاية الإدخال إذا تم استخدام طريقة معالجة نهاية الإدخال المقابلة. مع حالات البدء، تكون للقواعد صيغة أكثر تعقيدًا.
!إجراء شفرة
الإجراء يربط كتلة شفرة معرفة من قبل المستخدم بمكان معين في آلة الحالة المحدودة المولدة (بنفس طريقة ربط الإجراءات الدلالية بالشفرة في الحالات النهائية). راجع قسم الإجراءات للحصول على قائمة كاملة بالإجراءات المعرفة مسبقًا.
!توجيه ;
التوجيه هو أحد البيانات الخاصة المعرفة مسبقًا. لكل توجيه غرض فريد. راجع قسم التوجيهات للحصول على التفاصيل.

الكتل

علامات بدء وانتهاء الكتلة هي إما /*!re2c و */، أو %{ و %} (يتم دعم كلا الأسلوبين). بدءًا من الإصدار 2.2، يمكن أن تحتوي الكتل على أسماء اختيارية تسمح بالإشارة إليها في كتل أخرى. هناك أنواع مختلفة من الكتل:

/*!re2c[:<name>] ... */ أو %{[:<name>] ... %}
تحتوي الكتلة العامة على تعريفات وتكوينات وقواعد وتوجيهات. يقوم re2hs بتجميع التعبيرات العادية المرتبطة بكل قاعدة في آلة حالة محدودة حتمية، ويقوم بترميزها في شكل قفزات شرطية في اللغة المستهدفة ويستبدل الكتلة بالشفرة المولدة. تضاف الأسماء والتكوينات المعرفة في كتلة عامة إلى النطاق العام وتصبح مرئية للكتل اللاحقة. في بداية البرنامج، يتم تهيئة النطاق العام بـ خيارات سطر الأوامر.
/*!local:re2c[:<name>] ... */ أو %{local[:<name>] ... %}
الكتلة المحلية تشبه الكتلة العامة، ولكن الأسماء والتكوينات فيها لها نطاق محلي (لا تؤثر على الكتل الأخرى).
/*!rules:re2c[:<name>] ... */ أو %{rules[:<name>] ... %}
كتلة القواعد تشبه الكتلة المحلية، لكنها لا تولد أي شفرة بنفسها، ولا تضيف أي تعريفات إلى النطاق العام -- إنها مخصصة لإعادة استخدامها في كتل أخرى. هذه طريقة لمشاركة الشفرة (مزيد من التفاصيل في قسم الكتل القابلة لإعادة الاستخدام). قبل الإصدار 2.2 من re2hs، كانت كتل القواعد تتطلب الخيار -r --reusable.
/*!use:re2c[:<name>] ... */ أو %{use[:<name>] ... %}
كتلة استخدام تشير إلى كتلة قواعد معرفة مسبقًا. إذا تم تحديد الاسم، يبحث re2hs عن كتل قواعد بهذا الاسم. بخلاف ذلك، يتم استخدام أحدث كتلة قواعد (سواء كانت مسماة أو غير مسماة). يمكن لكتلة الاستخدام إضافة تعريفات وتكوينات وقواعد خاصة بها، والتي تضاف إلى تلك الموجودة في كتلة القواعد المشار إليها. قبل الإصدار 2.2 من re2hs، كانت كتل الاستخدام تتطلب الخيار -r --reusable.
/*!max:re2c[:<name1>[:<name2>...]] ... */ أو %{max[:<name1>[:<name2>...]] ... %}
كتلة تولد تعريف YYMAXFILL. تحدد قائمة اختيارية بأسماء الكتل أي الكتل يجب تضمينها عند حساب قيمة YYMAXFILL (إذا كانت القائمة فارغة، يتم تضمين جميع الكتل). بشكل افتراضي، الشفرة المولدة هي تعريف ماكرو لـ C (#define YYMAXFILL <n>)، أو متغير عام لـ Go (var YYMAXFILL int = <n>). يمكن تخصيصها بتكوين اختياري format يحدد سلسلة قالب حيث يتم استبدال @@{max} (أو @@ باختصار) بالقيمة الرقمية لـ YYMAXFILL.
/*!maxnmatch:re2c[:<name1>[:<name2>...]] ... */ أو %{m

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

/*!maxnmatch[:<name1>[:<name2>...]] ... %}
كتلة تقوم بإنشاء تعريف YYMAXNMATCH (تتطلب خيار -P --posix-captures). تحدد قائمة اختيارية بأسماء الكتل أي الكتل يجب تضمينها عند حساب قيمة YYMAXNMATCH (إذا كانت القائمة فارغة، يتم تضمين جميع الكتل). افتراضيًا، يكون الرمز الذي تم إنشاؤه هو تعريف ماكرو لـ C (#define YYMAXNMATCH <n>)، أو متغير عام لـ Go (var YYMAXNMATCH int = <n>). يمكن تخصيصه بتكوين اختياري format يحدد سلسلة قالب حيث يتم استبدال @@{max} (أو @@ اختصارًا) بالقيمة الرقمية لـ YYMAXNMATCH.
/*!stags:re2c[:<name1>[:<name2>...]] ... */, /*!mtags:re2c[:<name1>[:<name2>...]] ... */ أو %{stags[:<name1>[:<name2>...]] ... %}, %{mtags[:<name1>[:<name2>...]] ... %{
كتل تحدد جزءًا اختياريًا من الرمز يتم توسيعه لكل متغير علامة s/m تم إنشاؤه بواسطة re2hs. تحدد قائمة اختيارية بأسماء الكتل أي الكتل يجب تضمينها عند حساب مجموعة متغيرات العلامات (إذا كانت القائمة فارغة، يتم تضمين جميع الكتل). هناك تكوينات اختيارية: format و separator. يحدد التكوين format سلسلة قالب حيث يتم استبدال @@{tag} (أو @@ اختصارًا) باسم كل متغير علامة. يحدد التكوين separator جزءًا من الرمز يستخدم لربط أجزاء format التي تم إنشاؤها لمتغيرات علامات مختلفة.
/*!svars:re2c[:<name1>[:<name2>...]] ... */, /*!mvars:re2c[:<name1>[:<name2>...]] ... */ أو %{svars[:<name1>[:<name2>...]] ... %}, %{mvars[:<name1>[:<name2>...]] ... %{
كتل تحدد جزءًا اختياريًا من الرمز يتم توسيعه لكل علامة s/m تم ذكرها صراحةً بواسطة القواعد (مع الخيار --tags) أو تم إنشاؤها ضمنيًا بواسطة re2hs (مع الخيارات --captvars أو --posix-captvars). تحدد قائمة اختيارية بأسماء الكتل أي الكتل يجب تضمينها عند حساب مجموعة العلامات (إذا كانت القائمة فارغة، يتم تضمين جميع الكتل). هناك تكوينات اختيارية: format و separator. يحدد التكوين format سلسلة قالب حيث يتم استبدال @@{tag} (أو @@ اختصارًا) باسم كل علامة. يحدد التكوين separator جزءًا من الرمز يستخدم لربط أجزاء format التي تم إنشاؤها لعلامات مختلفة.
/*!getstate:re2c[:<name1>[:<name2>...]] ... */ أو %{getstate[:<name1>[:<name2>...]] ... %}
كتلة تقوم بإنشاء إرسال شرطي لحالة الم محلل (تتطلب الخيار --storable-state). تحدد قائمة اختيارية بأسماء الكتل أي الكتل يجب تضمينها في إرسال الحالة. ينتقل الانتقال الافتراضي إلى تسمية البداية للكتلة الأولى في القائمة. إذا كانت القائمة فارغة، يتم تضمين جميع الكتل، وينتقل الانتقال الافتراضي إلى الكتلة الأولى في الملف التي تحتوي على تسمية بداية. هذه الكتلة غير متوافقة مع الخيار --loop-switch، لأنها تتطلب انتقالات عبر الكتل غير مدعومة بدون goto أو استدعاءات الدوال.
/*!conditions:re2c[:<name1>[:<name2>...]] ... */, /*!types:re2c... */ أو %{conditions[:<name1>[:<name2>...]] ... %}, %{types... %}
كتلة تقوم بإنشاء تعداد للشروط (تتطلب الخيار --conditions). تحدد قائمة اختيارية بأسماء الكتل أي الكتل يجب تضمينها عند حساب مجموعة الشروط (إذا كانت القائمة فارغة، يتم تضمين جميع الكتل). افتراضيًا، يكون الرمز الذي تم إنشاؤه هو تعداد YYCONDTYPE. يمكن تخصيصه بتكوينات اختيارية format و separator. يحدد التكوين format سلسلة قالب حيث يتم استبدال @@{cond} (أو @@ اختصارًا) باسم كل شرط، و @@{num} يتم استبدالها بفهرس رقمي لذلك الشرط. يحدد التكوين separator جزءًا من الرمز يستخدم لربط أجزاء format التي تم إنشاؤها لشروط مختلفة.
/*!include:re2c <file> */ أو %{include <file> %}
تسمح هذه الكتلة بتضمين <file>، والتي يجب أن تكون مسار ملف محاط بعلامات اقتباس مزدوجة. يتم استبدال محتويات الملف حرفيًا مكان الكتلة، بنفس طريقة عمل #include في C/C++. يمكن استخدام هذه الكتلة مع الخيار --depfile لإنشاء تبعيات نظام البناء على الملفات المضمنة.
/*!header:re2c:on*/ أو %{header:on %}
تحدد هذه الكتلة بداية ملف الرأس. يتم معالجة كل شيء بعدها وحتى كتلة header:off التالية بواسطة re2hs ويكتب إلى ملف الرأس المحدد بالخيار -t --type-header.
/*!header:re2c:off*/ أو %{header:off %}
تحدد هذه الكتلة نهاية ملف الرأس الذي بدأ بكتلة header:on*/.
/*!ignore:re2c ... */ أو %{ignore ... %}
كتلة يتم تجاهل محتوياتها وإزالتها من ملف الإخراج.

Configurations

هذه قائمة كاملة بالتكوينات التي يدعمها re2hs:

re2c:api, re2c:input
نفس الخيار --api.
re2c:api:sigil
تحديد العلامة ("sigil") المستخدمة لمحددات الوسيطات في بدائيات API. الافتراضي هو @@. تبدأ المحددات بالـ sigil متبوعًا باسم الوسيطة بين قوسين معقوفين. على سبيل المثال، إذا تم تعيين sigil إلى $، فستكون المحددات بالشكل ${name}. قد تستخدم واجهات برمجة التطبيقات ذات الوسيطة الواحدة صيغة مختصرة بدون الاسم بين قوسين. يمكن تجاوز هذا الخيار بواسطة خيارات لواجهات برمجة التطبيقات الفردية، على سبيل المثال re2c:YYFILL@len لـ YYFILL.
re2c:api:style
تحديد نمط API. القيم الممكنة هي functions (الافتراضي لـ C) و free-form (الافتراضي لـ Go و Rust). في نمط functions، يتم إنشاء بدائيات API مع قائمة وسيطات بين قوسين بعد اسم البديهية. يتم توفير الوسيطات فقط للمعلمات التي تم إنشاؤها تلقائيًا (مثل عدد الأحرف التي تم تمريرها إلى YYFILL)، ولكن ليس لسياق الم محلل العام، لذا تتصرف البدائيات بشكل أشبه بالماكرو في C/C++ أو الإغلاقات في Go و Rust. في نمط free-form، لا تحتوي بدائيات API على شكل ثابت: يجب تعريفها كسلاسل تحتوي على أجزاء رمز حرة مع متغيرات مستبدلة بالشكل @@{var} أو @@ (تتوافق مع الوسيطات في النمط الشبيه بالدالة). يمكن تجاوز هذا التكوين لواجهات برمجة التطبيقات الفردية، انظر على سبيل المثال تكوين re2c:YYFILL:naked لـ YYFILL.
re2c:bit-vectors, re2c:flags:bit-vectors, re2c:flags:b
نفس الخيار --bit-vectors، ولكن يمكن تكوينه على أساس كل كتلة.
re2c:captures, re2c:leftmost-captures
نفس الخيار --leftmost-captures، ولكن يمكن تكوينه على أساس كل كتلة.
re2c:captvars, re2c:leftmost-captvars
نفس الخيار --leftmost-captvars، ولكن يمكن تكوينه على أساس كل كتلة.
re2c:case-insensitive, re2c:flags:case-insensitive
نفس الخيار --case-insensitive، ولكن يمكن تكوينه على أساس كل كتلة.
re2c:case-inverted, re2c:flags:case-inverted
نفس الخيار --case-inverted، ولكن يمكن تكوينه على أساس كل كتلة.
re2c:case-ranges, re2c:flags:case-ranges
نفس الخيار --case-ranges، ولكن يمكن تكوينه على أساس كل كتلة.
re2c:computed-gotos, re2c:flags:computed-gotos, re2c:flags:g
نفس الخيار --computed-gotos، ولكن يمكن تكوينه على أساس كل كتلة.
re2c:computed-gotos:relative, re2c:cgoto:relative
نفس الخيار --computed-gotos-relative، ولكن يمكن تكوينه على أساس كل كتلة.
re2c:computed-gotos:threshold, re2c:cgoto:threshold
إذا تم استخدام goto المحسوب، فإن هذا التكوين يحدد عتبة التعقيد التي تؤدي إلى إنشاء جداول قفز بدلاً من عبارات if متداخلة وخرائط بت. القيمة الافتراضية هي 9.
re2c:cond:abort
إذا تم تعيينها إلى قيمة عدد صحيح موجبة، فإن الحالة الافتراضية في إرسال الشرط الذي تم إنشاؤه تقوم بإيقاف تنفيذ البرنامج.
re2c:cond:goto
يحدد جزءًا من الرمز يستخدم للقواعد المختصرة التي تم إنشاؤها تلقائيًا :=> في الشروط. الافتراضي هو goto @@;. يتم استبدال محدد @@ باسم الشرط (انظر التكوينات re2c:api:sigil و re2c:cond:goto@cond).
re2c:cond:goto@cond

A generic API primitive that should restore the current input position to the value saved by YYBACKUP.
YYBACKUPCTX
A generic API primitive that should save the current input position as the position of the trailing context (to be restored with YYRESTORECTX later).
YYRESTORECTX
A generic API primitive that should restore the trailing context position saved with YYBACKUPCTX.
YYRESTORETAG
A generic API primitive with one variable tag that should restore the trailing context position to the value of tag.
YYSTAGP
A generic API primitive with one variable tag, where tag can be a pointer or an offset in YYINPUT (see submatch extraction section for details). YYSTAGP should set tag to the current input position.
YYSTAGN
A generic API primitive with one variable tag, where tag can be a pointer or an offset in YYINPUT (see submatch extraction section for details). YYSTAGN should to set tag to a value that represents non-existent input position.
YYMTAGP
A generic API primitive with one variable tag. YYMTAGP should append the current position to the submatch history of tag (see the submatch extraction section for details.)
YYMTAGN
A generic API primitive with one variable tag. YYMTAGN should append a value that represents non-existent input position position to the submatch history of tag (see the submatch extraction section for details.)
YYSHIFT
A generic API primitive with one variable shift that should shift the current input position by shift characters (the shift value may be negative).
YYCOPYSTAG
A generic API primitive with two variables, lhs and rhs that should copy right-hand-side s-tag variable rhs to the left-hand-side s-tag variable lhs. For most languages this primitive has a default definition that assigns lhs to rhs.
YYCOPYMTAG
A generic API primitive with two variables, lhs and rhs that should copy right-hand-side m-tag variable rhs to the left-hand-side m-tag variable lhs. For most languages this primitive has a default definition that assigns lhs to rhs.
YYSHIFTSTAG
A generic API primitive with two variables, tag and shift that should shift tag by shift code units (the shift value may be negative).
YYSHIFTMTAG
A generic API primitive with two variables, tag and shift that should shift the latest value in the history of tag by shift code units (the shift value may be negative).
YYMAXNMATCH
An integral constant equal to the maximal number of POSIX capturing groups in a rule. It is generated with a maxnmatch block.
YYCONDTYPE
The type of the condition enum. It can be generated either with conditions block or --header option.
YYGETACCEPT
A primitive with one variable var that stores numeric selector of the accepted rule. For most languages this primitive has a default definition that reads from var.
YYSETACCEPT
A primitive with two variables: var (an l-value that stores numeric selector of the accepted rule), and val (the value of selector). For most languages this primitive has a default definition that assigns var to val.
YYGETCOND
An r-value of type YYCONDTYPE that is equal to the current condition identifier.
YYSETCOND
A primitive with one variable cond that should set the current condition identifier to cond.
YYGETSTATE
An r-value of integer type that is equal to the current lexer state. It should be initialized to -1.
YYSETSTATE
A primitive with one variable state that should set the current lexer state to state.
YYDEBUG
This primitive is generated only with -d, --debug-output option. Its purpose is to add logging to the generated code (typical YYDEBUG definition is a print statement). YYDEBUG statements are generated in every state and have two variables: state (either a DFA state index or -1) and symbol (the current input symbol).
yyaccept
An l-value of unsigned integral type that stores the number of the latest matched rule. User definition is necessary only with --storable-state option.
yybm
A table containing compressed bitmaps for up to 8 transitions (used with the --bitmaps option). The table contains 256 elements and is indexed by 1-byte code units. Each 8-bit element combines boolean values for up to 8 transitions. k-Th bit of n-th element is true iff n-th code unit is in the range of k-th transition. The idea of this bitmap is to replace many if branches or switch cases with one check of a single bit in the table.
yych
An l-value of type YYCTYPE that stores the current input character. User definition is necessary only with -f --storable-state option.
yyctable
Jump table generated for the initial condition dispatch (enabled with the combination of --conditions and --computed-gotos options).
yyfill
An l-value that stores the result of YYFILL call (this may be necessary for pure functional languages, where YYFILL is a monadic function with complex return value).
yynmatch
An l-value of unsigned integral type that stores the number of POSIX capturing groups in the matched rule. Used only with -P --posix-captures option.
yypmatch
An array of l-values that are used to hold the tag values corresponding to the capturing parentheses in the matching rule. Array length must be at least yynmatch * 2 (usually YYMAXNMATCH * 2 is a good choice). Used only with -P --posix-captures option.
yystable
Deprecated.
yystate
An l-value used with the --loop-switch option to store the current DFA state.
yytarget
Jump table that contains jump targets (label addresses) for all transitions from a state. This table is local to each state. Generation of yytarget tables is enabled with --computed-gotos option.

OPTIONS

Options are grouped into several categories.

--continue
Continue lexing when there is not enough input, and then resumed when more input becomes available. In this mode users should additionally define YYGETSTATE and YYSETSTATE primitives, and variables yych, yyaccept and state should be part of the stored lexer state.
--syntax FILE
Load configurations from the specified FILE and apply them on top of the default syntax file. Note that FILE can define only a few configurations (if it's used to amend the default syntax file), or it can define a whole new language backend (in the latter case it is recommended to use --lang none option).
--tags -T
Enable submatch extraction with tags.
--ucs2 --wide-chars -w
Generate a lexer that reads UCS2-encoded input. re2hs assumes that the character range is 0 -- 0xFFFF and character size is 2 bytes. This option implies --nested-ifs.
--utf8 --utf-8 -8
Generate a lexer that reads input in UTF-8 encoding. re2hs assumes that the character range is 0 -- 0x10FFFF and character size is 1 byte.
--utf16 --utf-16 -x
Generate a lexer that reads UTF16-encoded input. re2hs assumes that the character range is 0 -- 0x10FFFF and character size is 2 bytes. This option implies --nested-ifs.
--utf32 --unicode -u
Generate a lexer that reads UTF32-encoded input. re2hs assumes that the character range is 0 -- 0x10FFFF and character size is 4 bytes. This option implies --nested-ifs.
--verbose
Output a short message in case of success.
--vernum -V
Show version information in MMmmpp format (major, minor, patch).
--version -v
Show version information.
--single-pass -1
Deprecated. Does nothing (single pass is the default now).
--debug-output -d
Emit YYDEBUG invocations in the generated code. This is useful to trace lexer execution.
--dump-adfa
Debug option: output DFA after tunneling (in .dot format).
--dump-cfg
Debug option: output control flow graph of tag variables (in .dot format).
--dump-closure-stats
Debug option: output statistics on the number of states in closure.
--dump-dfa-det
Debug option: output DFA immediately after determinization (in .dot format).
--dump-dfa-min
Debug option: output DFA after minimization (in .dot format).
--dump-dfa-tagopt
Debug option: output DFA after tag optimizations (in .dot format).
--dump-dfa-tree
Debug option: output DFA under construction with states represented as tag history trees (in .dot format).
--dump-dfa-raw
Debug option: output DFA under construction with expanded state-sets (in .dot format).
--dump-interf
Debug option: output interference table produced by liveness analysis of tag variables.
--dump-nfa
Debug option: output NFA (in .dot format).
--emit-dot -D
Instead of normal output generate lexer graph in .dot format. The output can be converted to an image with the help of Graphviz (e.g. something like dot -Tpng -odfa.png dfa.dot).
--dfa-minimization <moore | table>
Internal option: DFA minimization algorithm used by re2hs. The moore option is the Moore algorithm (it is the default). The table option is the "table filling" algorithm. Both algorithms should produce the same DFA up to states relabeling; table filling is simpler and much slower and serves as a reference implementation.
--eager-skip
Internal option: make the generated lexer advance the input position eagerly -- immediately after reading the input symbol. This changes the default behavior when the input position is advanced lazily -- after transition to the next state.
--no-lookahead
Internal option, deprecated. It used to enable TDFA(0) algorithm. Unlike TDFA(1), TDFA(0) algorithm does not use one-symbol lookahead. It applies register operations to the incoming transitions rather than the outgoing ones. Benchmarks showed that TDFA(0) algorithm is less efficient than TDFA(1).
--no-optimize-tags
Internal option: suppress optimization of tag variables (useful for debugging).
--posix-closure <gor1 | gtop>
Internal option: specify shortest-path algorithm used for the construction of epsilon-closure with POSIX disambiguation semantics: gor1 (the default) stands for Goldberg-Radzik algorithm, and gtop stands for "global topological order" algorithm.
--posix-prectable <complex | naive>
Internal option: specify the algorithm used to compute POSIX precedence table. The complex algorithm computes precedence table in one traversal of tag history tree and has quadratic complexity in the number of TNFA states; it is the default. The naive algorithm has worst-case cubic complexity in the number of TNFA states, but it is much simpler than complex and may be slightly faster in non-pathological cases.
--stadfa
Internal option, deprecated. It used to enable staDFA algorithm, which differs from TDFA in that register operations are placed in states rather than on transitions. Benchmarks showed that staDFA algorithm is less efficient than TDFA.
--fixed-tags <none | toplevel | all>
Internal option: specify whether the fixed-tag optimization should be applied to all tags (all), none of them (none), or only those in toplevel concatenation (toplevel). The default is all. "Fixed" tags are those that are located within a fixed distance to some other tag (called "base"). In such cases only the base tag needs to be tracked, and the value of the fixed tag can be computed as the value of the base tag plus a static offset. For tags that are under alternative or repetition it is also necessary to check if the base tag has a no-match value (in that case fixed tag should also be set to no-match, disregarding the offset). For tags in top-level concatenation the check is not needed, because they always match.

Warnings

Warnings can be invividually enabled, disabled and turned into an error.

-W
Turn on all warnings.
-Werror
Turn warnings into errors. Note that this option alone doesn't turn on any warnings; it only affects those warnings that have been turned on so far or will be turned on later.
-W<warning>
Turn on warning.
-Wno-<warning>
Turn off warning.
-Werror-<warning>
Turn on warning and treat it as an error (this implies -W<warning>).
-Wno-error-<warning>
Don't treat this particular warning as an error. This doesn't turn off the warning itself.
-Wcondition-order
Warn if the generated program makes implicit assumptions about condition numbering. One should use either --header option or conditions block to generate a mapping of condition names to numbers and then use the autogenerated condition names.
-Wempty-character-class
Warn if a regular expression contains an empty character class. Trying to match an empty character class makes no sense: it should always fail. However, for backwards compatibility reasons re2hs permits empty character classes and treats them as empty strings. Use the --empty-class option to change the default behavior.
-Wmatch-empty-string
Warn if a rule is nullable (matches an empty string). If the lexer runs in a loop and the empty match is unintentional, the lexer may unexpectedly hang in an infinite loop.
-Wswapped-range
Warn if the lower bound of a range is greater than its upper bound. The default behavior is to silently swap the range bounds.

تحذير بشأن قواعد نهاية الإدخال المستقلة $ التي ستتعطل بسبب التغييرات المستقبلية وتتطلب الإصلاح. في الوقت الحالي، تتفوق هذه القواعد عند التعارض مع قواعد أخرى، ولكن بعد إدخال رمز نهاية الإدخال المعمم $، سيتغير ترتيب الأسبقية وستصبح هذه القواعد محجوبة بواسطة قواعد أخرى.
-Wuseless-escape
تحذير إذا تم الهروب من رمز لم يكن ينبغي ذلك. بشكل افتراضي، يتجاهل re2hs عمليات الهروب هذه بصمت، ولكن قد يشير ذلك أيضًا إلى خطأ مطبعي أو خطأ في تسلسل الهروب.
-Wnondeterministic-tags
تحذير إذا كان للعلامة درجة n من عدم التحديد، حيث n أكبر من 1.
-Wsentinel-in-midrule
تحذير إذا كان رمز الحارس يظهر في منتصف قاعدة - قد يتسبب هذا في قراءات تتجاوز نهاية المخزن المؤقت، أو تعطل، أو تلف في الذاكرة في المحلل اللغوي المولد. هذا التحذير ينطبق فقط إذا تم استخدام طريقة الحارس للتحقق من نهاية الإدخال. تم تعيينه كخطأ إذا تم استخدام إعداد re2c:sentinel.
-Wundefined-syntax-config
تحذير إذا كان ملف الصيغة المحدد بالخيار --syntax يفتقر إلى تعريفات لبعض الإعدادات. هذا يساعد في الحفاظ على ملفات الصيغة المعرفة من قبل المستخدم: إذا أضاف إصدار جديد إعدادات، فسيرفع ملف الصيغة القديم تحذيرًا، وسيتم إعلام المستخدم. إذا كانت بعض الإعدادات غير مستخدمة ولا تحتاج إلى تعريف، فيجب تعيينها صراحةً إلى <undefined>.

ملفات الصيغة

يعتمد دعم اللغات المختلفة في re2c على فكرة ملفات الصيغة. ملف الصيغة هو ملف إعداد يحدد صيغة اللغة المستهدفة - وليس اللغة بأكملها، ولكن جزءًا صغيرًا منها يستخدمه الرمز المولد. تجعل ملفات الصيغة re2c مرنة للغاية، ولكن لا ينبغي استخدامها كبديل لإعدادات re2c:: الغرض منها هو تحديد صيغة اللغة المستهدفة، وليس تخصيص محلل لغوي معين. جميع اللغات المدعومة لديها ملفات صيغة افتراضية هي جزء من التوزيع (انظر الدليل الفرعي include/syntax)؛ وهي مدمجة أيضًا في الثنائي re2hs. قد يوفر المستخدمون ملف صيغة مخصصًا يتجاوز بعض الإعدادات للغة مدعومة، أو قد يختارون إعادة تعريف جميع الإعدادات (في هذه الحالة يجب استخدام الخيار --lang none). تحتوي ملفات الصيغة على إعدادات من أربعة أنواع مختلفة: قوائم الميزات، إعدادات اللغة، إعدادات الموضع، ونماذج التعليمات البرمجية.

نماذج التعليمات البرمجية

تحدد نماذج التعليمات البرمجية صيغة اللغة المستهدفة. وهي مكتوبة بلغة بسيطة خاصة بالمجال مع القواعد الرسمية التالية: 
code-template ::
      name '=' code-exprs ';'
    | CODE_TEMPLATE ';'
    | '<undefined>' ';'
code-exprs ::
      <EMPTY>
    | code-exprs code-expr
code-expr ::
      STRING
    | VARIABLE
    | optional
    | list
optional ::
      '(' CONDITIONAL '?' code-exprs ')'
    | '(' CONDITIONAL '?' code-exprs ':' code-exprs ')'
list ::
      '[' VARIABLE ':' code-exprs ']'
    | '[' VARIABLE '{' NUMBER '}' ':' code-exprs ']'
    | '[' VARIABLE '{' NUMBER ',' NUMBER '}' ':' code-exprs ']'.

نموذج التعليمات البرمجية هو تسلسل من السلاسل النصية، والمتغيرات، والعناصر الاختيارية، والقوائم، أو إشارة إلى نموذج تعليمات برمجية آخر، أو قيمة خاصة <undefined>. المتغيرات هي عناصر نائبة يتم استبدالها أثناء مرحلة توليد التعليمات البرمجية. متغيرات القائمة خاصة: عند توسيع نماذج القائمة، يكرر re2hs التعبيرات الموجودة على الجانب الأيمن من العمود عدة مرات، ويستبدل في كل مرة تكرارات متغير القائمة بقيمة خاصة بهذه التكرارات. تحتوي القوائم على حدود اختيارية (يتم حساب القيم السالبة من النهاية، على سبيل المثال، -1 تعني العنصر الأخير). تبدأ أسماء الشروط بنقطة. قد تكون الشروط والمتغيرات محلية (خاصة بنموذج التعليمات البرمجية المعطى) أو عامة (مسموح بها في جميع نماذج التعليمات البرمجية). عندما يقرأ re2hs ملف الصيغة، فإنه يتحقق من أن كل نموذج تعليمات برمجية يستخدم فقط المتغيرات والشروط المسموح بها فيه.

على سبيل المثال، يحدد نموذج التعليمات البرمجية التالي بنية if-then-else للغة شبيهة بلغة C:

code:if_then_else =

        indent [stmt: stmt] dedent]
    [branch{1:-1}: topindent "} else" (.cond ? " if " cond) " {" nl
        indent [stmt: stmt] dedent]
    topindent "}" nl.

هنا branch هو متغير قائمة: branch{0} يتوسع إلى الفرع الأول (وهو خاص، حيث لا يوجد جزء else)، branch{1:-1} يتوسع إلى جميع الفروع المتبقية (إن وجدت). stmt هو أيضًا متغير قائمة: [stmt: stmt] هي قائمة متداخلة تتوسع إلى قائمة بالعبارات في جسم الفرع الحالي. topindent، indent، dedent، و nl هي متغيرات عامة، و .cond هو شرط محلي (معانيها موصوفة أدناه). قد ينتج نموذج التعليمات البرمجية هذا التعليمات البرمجية التالية:

} else if y {

الكتل القابلة لإعادة الاستخدام

يمكن إعادة استخدام الكتل القابلة لإعادة الاستخدام من النوع /*!rules:re2c[:<name>] ... */ أو %{rules[:<name>] ... %} أي عدد من المرات ودمجها مع كتل re2hs أخرى. <name> اختياري. يمكن استخدام كتلة القواعد في كتلة use أو توجيه. يتم إنشاء الكود الخاص بكتلة القواعد في كل نقطة استخدام.

يتم تعريف كتل الاستخدام باستخدام /*!use:re2c[:<name>] ... */ أو %{use[:<name>] ... %}. <name> اختياري: إذا لم يتم تحديده، فإن كتلة القواعد المرتبطة بها هي الأحدث (سواء كانت مسماة أو غير مسماة). يمكن لكتلة الاستخدام إضافة تعريفات وتكوينات وقواعد مسماة خاصة بها. أحد حالات الاستخدام المهمة للكتل المستخدمة هو محلل الأكواد الذي يدعم تشفيرات إدخال متعددة: يتم إعادة استخدام نفس كتلة القواعد عدة مرات مع تكوينات خاصة بتشفير معين (انظر المثال أدناه).

يمكن استخدام توجيه الاستخدام داخل الكتلة !use:<name>; من داخل كتلة re2hs. يقوم بدمج الكتلة المشار إليها <name> في الكتلة الحالية. إذا تداخلت بعض القواعد والتكوينات المدمجة مع تلك المعرفة مسبقًا، يتم حل التعارضات بالطريقة المعتادة: الأولوية للقاعدة الأقدم، والتكوين الأحدث يلغي ما سبقه. الاستثناء الوحيد هو القواعد الخاصة * و $ و (في وضع الشرط) <!>، حيث يلغي التعريف المحلي للكتلة أي تعريفات موروثة. يسمح توجيه الاستخدام بدمج كتل re2hs مختلفة معًا في كتلة واحدة (انظر المثال أدناه).

تمت إضافة الكتل المسماة وتوجيه الاستخدام داخل الكتلة في الإصدار 2.2 من re2hs. منذ ذلك الحين، يُسمح بالكتل القابلة لإعادة الاستخدام بشكل افتراضي (لا حاجة لخيار خاص). قبل الإصدار 2.2، تم تمكين وضع إعادة الاستخدام باستخدام الخيار -r --reusable. قبل الإصدار 1.2، لم يكن من الممكن دمج الكتل القابلة لإعادة الاستخدام مع الكتل العادية.

استخراج المطابقات الفرعية

يحتوي re2hs على خيارين لاستخراج المطابقات الفرعية.

العلامات (Tags)
الخيار الأول هو استخدام علامات مستقلة من النوع @stag أو #mtag، حيث stag و mtag هما أسماء عشوائية يحددها المستخدم. يتم تمكين العلامات باستخدام الخيار -T --tags أو التكوين re2c:tags = 1. من الناحية الدلالية، العلامات هي علامات مواضع: يمكن إدراجها في أي مكان في تعبير عادي، وترتبط بالموضع المقابل (أو المواضع المتعددة) في سلسلة الإدخال. علامات s-tags ترتبط بآخر موضع مطابق، وعلامات m-tags ترتبط بقائمة من المواضع (يمكن استخدامها في تعبيرات التكرار الفرعية، حيث يتوافق موضع واحد في تعبير عادي مع مواضع متعددة في سلسلة الإدخال). يجب تعريف جميع العلامات من قبل المستخدم، إما يدويًا أو بمساعدة كتل svars و mvars. إذا كان هناك أكثر من طريقة لمطابقة العلامات مع الإدخال، يتم حل الغموض باستخدام استراتيجية إزالة الغموض الجشعة من اليسار إلى اليمين.
المجموعات الملتقطة (Captures)
الخيار الثاني هو استخدام مجموعات التقاط. يتم تمكينها باستخدام الخيار --captures أو التكوين re2c:captures = 1. هناك نوعان لسياسات إزالة الغموض المختلفة، --leftmost-captures (الافتراضي) للسياسة الجشعة من اليسار إلى اليمين، و --posix-captures لسياسة أطول مطابقة POSIX. في هذا الوضع، تعتبر جميع التعبيرات الفرعية الموضوعة بين قوسين مجموعات التقاط، ويمكن استخدام علامة تعجب لتحديد المجموعات غير الملتقطة: (! ... ). مع الخيار --invert-captures أو التكوين re2c:invert-captures = 1، يتم عكس معنى علامة التعجب. يتم تخزين عدد المجموعات للقاعدة المطابقة في المتغير yynmatch (يُعتبر التعبير العادي بأكمله المجموعة رقم صفر)، ويتم تخزين نتائج المطابقة الفرعية في المصفوفة yypmatch. يجب تعريف كل من yynmatch و yypmatch من قبل المستخدم، ويجب أن يكون حجم yypmatch على الأقل [yynmatch * 2]. استخدم كتلة maxnmatch لتحديد YYMAXNMATCH، وهو ثابت يساوي القيمة القصوى لـ yynmatch بين جميع القواعد.
متغيرات الالتقاط (Captvars)
طريقة أخرى لاستخدام مجموعات الالتقاط هي الخيار --captvars أو التكوين re2c:captvars = 1. الفرق الوحيد مع --captures هو في طريقة تخزين re2hs لنتائج المطابقات الفرعية: بدلاً من yynmatch و yypmatch، ينشئ re2hs المتغيرات yytl<k> و yytr<k> للمجموعة الملتقطة k (يجب على المستخدم الإعلان عن هذه باستخدام كتلة svars). تدعم متغيّرات الالتقاط سياسات إزالة غموض مختلفة: --leftmost-captvars أو re2c:leftmost-captvars = 1 للسياسة الجشعة من اليسار إلى اليمين (السياسة الافتراضية) و --posix-captvars أو re2c:posix-captvars لسياسة أطول مطابقة POSIX.

تحت الغطاء، تترجم جميع هذه الخيارات إلى العلامات و آلات الحالات المحددة المحددة بالعلامات مع التطلع (TDFA). الفكرة الأساسية لـ TDFA هي تقليل النفقات العامة لاستخراج المطابقات الفرعية. في أقصى حد، إذا لم تكن هناك علامات أو مجموعات التقاط في تعبير عادي، فإن TDFA هو مجرد DFA عادي. إذا كان عدد العلامات معتدلاً، فإن النفقات تكاد لا تكون ملحوظة. تستخدم TDFA الذي تم إنشاؤه عددًا من متغيرات العلامات التي لا تتطابق مباشرة مع العلامات: قد يُستخدم متغير واحد لعلامات مختلفة، وقد تتطلب العلامة متغيرات متعددة لتخزين جميع قيمها الممكنة. في النهاية، يتم حل الغموض، ويبقى متغير واحد نهائي لكل علامة. يجب تعريف متغيرات العلامات باستخدام كتل stags أو mtags. إذا تم تخزين حالة محلل الأكواد، فيجب أن تكون متغيرات العلامات جزءًا منها. كما تحتاج إلى تحديثها بواسطة YYFILL.

تدعم علامات s-tags العمليات التالية:

  • حفظ موضع الإدخال إلى علامة s: t = YYCURSOR باستخدام واجهة برمجة تطبيقات مؤشر C أو عملية معرفة من قبل المستخدم YYSTAGP(t) باستخدام واجهة برمجة التطبيقات العامة
  • حفظ القيمة الافتراضية إلى علامة s: t = NULL باستخدام واجهة برمجة تطبيقات مؤشر C أو عملية معرفة من قبل المستخدم YYSTAGN(t) باستخدام واجهة برمجة التطبيقات العامة
  • نسخ علامة s إلى أخرى: t1 = t2

تدعم علامات m-tags العمليات التالية:

  • إلحاق موضع الإدخال بعلامة m: عملية معرفة من قبل المستخدم YYMTAGP(t) باستخدام واجهة برمجة التطبيقات الافتراضية والعامة
  • إلحاق القيمة الافتراضية بعلامة m: عملية معرفة من قبل المستخدم YYMTAGN(t) باستخدام واجهة برمجة التطبيقات الافتراضية والعامة
  • نسخ علامة m إلى أخرى: t1 = t2

يمكن تنفيذ علامات s-tags كقيم قياسية (مؤشرات أو إزاحات). تحتاج علامات m-tags إلى تمثيل أكثر تعقيدًا، حيث تحتاج إلى تخزين تسلسل من قيم العلامات. التمثيل الأكثر بدائية وغير فعال لعلامة m هو قائمة (مصفوفة، متجه) من قيم العلامات؛ تمثيل أكثر كفاءة هو تخزين جميع علامات m في شجرة بادئة ممثلة بمصفوفة من العقد (v, p)، حيث v هي قيمة العلامة و p هو مؤشر إلى العقدة الأصل.

Include files

re2hs allows one to include other files using a block of the form /*!include:re2c FILE */ or %{include FILE %}, or an in-block directive !include FILE ;, where FILE is a path to the file to be included. re2hs looks for include files in the directory of the including file and in include locations, which can be specified with the -I option. Include blocks/directives in re2hs work in the same way as C/C++ #include: FILE contents are copy-pasted verbatim in place of the block/directive. Include files may have further includes of their own. Use --depfile option to track build dependencies of the output file on include files. re2hs provides some predefined include files that can be found in the include/ subdirectory of the project. These files contain definitions that may be useful to other projects (such as Unicode categories) and form something like a standard library for re2hs. Below is an example of using include files.

Header files

re2hs allows one to generate header file from the input .re file using --header option or re2c:header configuration and block pairs of the form /*!header:re2c:on*/ and /*!header:re2c:off*/, or %{header:on%} and %{header:off%}. The first block marks the beginning of header file, and the second block marks the end of it. Everything between these blocks is processed by re2hs, and the generated code is written to the file specified with --header option or re2c:header configuration (or stdout if neither option nor configuration is used). Autogenerated header file may be needed in cases when re2hs is used to generate definitions that must be visible from other translation units.

Skeleton programs

With the -S, --skeleton option, re2hs ignores all non-re2hs code and generates a self-contained C program that can be further compiled and executed. The program consists of lexer code and input data. For each constructed DFA (block or condition) re2hs generates a standalone lexer and two files: an .input file with strings derived from the DFA and a .keys file with expected match results. The program runs each lexer on the corresponding .input file and compares results with the expectations. Skeleton programs are very useful for a number of reasons:

  • They can check correctness of various re2hs optimizations (the data is generated early in the process, before any DFA transformations have taken place).
  • Generating a set of input data with good coverage may be useful for both testing and benchmarking.
  • Generating self-contained executable programs allows one to get minimized test cases (the original code may be large or have a lot of dependencies).

The difficulty with generating input data is that for all but the most trivial cases the number of possible input strings is too large (even if the string length is limited). re2hs solves this difficulty by generating sufficiently many strings to cover almost all DFA transitions. It uses the following algorithm. First, it constructs a skeleton of the DFA. For encodings with 1-byte code unit size (such as ASCII, UTF-8 and EBCDIC) skeleton is just an exact copy of the original DFA. For encodings with multibyte code units skeleton is a copy of DFA with certain transitions omitted: namely, re2hs takes at most 256 code units for each disjoint continuous range that corresponds to a DFA transition. The chosen values are evenly distributed and include range bounds. Instead of trying to cover all possible paths in the skeleton (which is infeasible) re2hs generates sufficiently many paths to cover all skeleton transitions, and thus trigger the corresponding conditional jumps in the lexer. The algorithm implementation is limited by ~1Gb of transitions and consumes constant amount of memory (re2hs writes data to file as soon as it is generated).

Visualization and debug

With the -D, --emit-dot option, re2hs does not generate code. Instead, it dumps the generated DFA in DOT format. One can convert this dump to an image of the DFA using Graphviz or another library. Note that this option shows the final DFA after it has gone through a number of optimizations and transformations. Earlier stages can be dumped with various debug options, such as --dump-nfa, --dump-dfa-raw etc. (see the full list of options).
