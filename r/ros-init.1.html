ros-init - إنشاء سكربت roswell (اختياريًا بناءً على قالب)

الملخص

ros init [TEMPLATE] NAME [ARGS...]]

TEMPLATE
يحدد اسم القالب، افتراضيًا القالب default. ومع ذلك، إذا لم يتم تحديد TEMPLATE وكان FILENAME يطابق أحد القوالب المخزنة، فإنه يستخدم القالب تلقائيًا. لقمع هذا السلوك، يجب عليك تحديد TEMPLATE بشكل صريح كـ default.

لذلك يتم تحذيرك عند استخدام هذا الأمر من سكربت شل. لتحقيق سلوك متسق ومرغوب فيه، يُنصح دائمًا بتحديد اسم القالب بشكل صريح.

NAME
يحدد اسم ملف الإخراج، أو “-” للإشارة إلى stdout. عندما يكون TEMPLATE هو default، فإنه يضيف تلقائيًا امتداد نوع الملف “.ros”.

الوصف

يقوم بتهيئة ملف roswell بناءً على قالب. يمكن إضافة قوالب محددة من قبل المستخدم بواسطة ros-template(1).

القالب الافتراضي هو شيء مثل:

#!/bin/sh
#|-*- mode:lisp -*-|#
#| <ضع وصفًا من سطر واحد هنا>
exec ros -Q -- $0 "$@"
|#
(progn ;;init forms
  (ros:ensure-asdf)
  ;;#+quicklisp (ql:quickload '() :silent t)
  )
(defpackage :ros.script.test.3703600390
  (:use :cl))
(in-package :ros.script.test.3703600390)
(defun main (&rest argv)
  (declare (ignorable argv)))
;;; vim: set ft=lisp lisp:

هذا في الأساس سكربت شل يستدعي Roswell فورًا عبر exec (انظر sh(1)). يقوم Roswell بتحميل نفس السكربت كمدخل، ويتخطى التعليقات متعددة الأسطر، ويقرأ بقية الملف كبرنامج Common Lisp، وأخيرًا يستدعي الدالة main مع وسائط سطر الأوامر.
