READDIR(3P) دليل مبرمج POSIX READDIR(3P)

تمهيد

هذه الصفحة من الدليل هي جزء من دليل مبرمج POSIX. قد يختلف تطبيق Linux لهذه الواجهة (استشر صفحة دليل Linux المقابلة لتفاصيل سلوك Linux)، أو قد لا تكون الواجهة مطبقة على Linux.

الاسم

readdir, readdir_r — قراءة دليل

الملخص

#include <dirent.h>
struct dirent *readdir(DIR *dirp);
int readdir_r(DIR *restrict dirp, struct dirent *restrict entry,
    struct dirent **restrict result);

الوصف

يمثل النوع DIR، المعرف في رأس <dirent.h>، تيار دليل، وهو تسلسل مرتب لجميع إدخالات الدليل في دليل معين. تمثل إدخالات الدليل الملفات؛ يمكن إزالة الملفات من الدليل أو إضافتها إلى دليل بشكل غير متزامن مع عملية readdir().

تقوم الدالة readdir() بإرجاع مؤشر إلى بنية تمثل إدخال الدليل في الموضع الحالي في تيار الدليل المحدد بواسطة الوسيط dirp، وتعيين تيار الدليل إلى الإدخال التالي. تقوم بإرجاع مؤشر فارغ عند الوصول إلى نهاية تيار الدليل. تصف البنية dirent المعرفة في رأس <dirent.h> إدخال الدليل. سيتم تعيين قيمة العضو d_ino في البنية إلى رقم التسلسل الخاص بالملف المسمى بواسطة العضو d_name. إذا كان العضو d_name يشير إلى رابط رمزي، فسيتم تعيين قيمة العضو d_ino إلى رقم التسلسل الخاص بالرابط الرمزي نفسه.

لن ترجع الدالة readdir() إدخالات دليل تحتوي على أسماء فارغة. إذا كانت الإدخالات الخاصة بنقطة (.) أو نقطتين (..) موجودة، فسيتم إرجاع إدخال واحد للنقطة وإدخال واحد للنقطتين؛ وإلا، فلن يتم إرجاعها.

لا يجب على التطبيق تعديل البنية التي يشير إليها القيمة المرجعة من readdir()، ولا مساحات التخزين التي تشير إليها المؤشرات داخل البنية. قد تصبح المؤشرات المرجعة، والمؤشرات داخل البنية، غير صالحة أو قد يتم الكتابة فوق البنية أو مساحات التخزين بواسطة استدعاء لاحق لـ readdir() على نفس تيار الدليل. لن تتأثر باستدعاء readdir() على تيار دليل مختلف. قد تصبح المؤشرات المرجعة، والمؤشرات داخل البنية، غير صالحة أيضًا إذا تم إنهاء خيط الاستدعاء.

إذا تم إزالة ملف من الدليل أو إضافته إليه بعد آخر استدعاء لـ opendir() أو rewinddir()، فإن ما إذا كانت استدعاءات readdir() اللاحقة ستعيد إدخالًا لهذا الملف غير محدد.

قد تقوم الدالة readdir() بتخزين إدخالات دليل متعددة لكل عملية قراءة فعلية؛ ستقوم readdir() بوضع علامة على آخر طابع زمني للوصول إلى البيانات للدليل ليتم تحديثه في كل مرة تتم فيها قراءة الدليل فعليًا.

بعد استدعاء fork()، يجوز إما للعملية الأم أو الابنة (وليس كليهما) متابعة معالجة تيار الدليل باستخدام readdir() أو rewinddir() أو seekdir(). إذا استخدمت كلتا العمليتين الأم والابنة هذه الدوال، فإن النتيجة غير محددة.

ليست هناك حاجة لأن تكون الدالة readdir() آمنة للاستخدام المتوازي.

يجب على التطبيقات التي ترغب في التحقق من حالات الخطأ تعيين errno إلى 0 قبل استدعاء readdir(). إذا تم تعيين errno إلى قيمة غير صفرية عند العودة، فقد حدث خطأ.

ستقوم الدالة readdir_r() بتهيئة البنية dirent المشار إليها بواسطة entry لتمثيل إدخال الدليل في الموضع الحالي في تيار الدليل المشار إليه بواسطة dirp، وتخزين مؤشر إلى هذه البنية في الموقع المشار إليه بواسطة result، وتعيين تيار الدليل إلى الإدخال التالي.

يجب أن تكون المساحة المشار إليها بواسطة entry كبيرة بما يكفي لـ dirent مع مصفوفة من أعضاء char d_name تحتوي على {NAME_MAX}+1 عنصر على الأقل.

عند العودة بنجاح، سيكون المؤشر المرجع في *result مساويًا لقيمة الوسيط entry. عند الوصول إلى نهاية تيار الدليل، سيكون هذا المؤشر NULL.

لن تقوم الدالة readdir_r() بإرجاع إدخالات دليل تحتوي على أسماء فارغة.

إذا تم إزالة ملف من الدليل أو إضافته إليه بعد آخر استدعاء لـ opendir() أو rewinddir()، فإن ما إذا كانت استدعاءات readdir_r() اللاحقة ستعيد إدخالًا لهذا الملف غير محدد.

قد تقوم الدالة readdir_r() بتخزين إدخالات دليل متعددة لكل عملية قراءة فعلية؛ ستقوم readdir_r() بوضع علامة على آخر طابع زمني للوصول إلى البيانات للدليل ليتم تحديثه في كل مرة تتم فيها قراءة الدليل فعليًا.

قيمة الإرجاع

عند الانتهاء بنجاح، تعيد الدالة readdir() مؤشرًا إلى كائن من النوع struct dirent. عند مواجهة خطأ، يتم إرجاع مؤشر فارغ ويتم تعيين errno للإشارة إلى الخطأ. عند الوصول إلى نهاية الدليل، يتم إرجاع مؤشر فارغ ولا يتغير errno.

إذا نجحت، تعيد الدالة readdir_r() القيمة صفر؛ وإلا، يتم إرجاع رقم خطأ للإشارة إلى الخطأ.

الأخطاء

ستفشل هذه الدوال إذا:

EOVERFLOW
لا يمكن تمثيل إحدى القيم في البنية التي سيتم إرجاعها بشكل صحيح.

قد تفشل هذه الدوال إذا:

EBADF
الوسيط dirp لا يشير إلى تيار دليل مفتوح.
ENOENT
الموضع الحالي لتيار الدليل غير صالح.

الأقسام التالية إعلامية.

أمثلة

يقوم برنامج العينة التالي بالبحث في الدليل الحالي لكل وسيط تم توفيره في سطر الأوامر.

#include <dirent.h>
#include <errno.h>
#include <stdio.h>
#include <string.h>
static void lookup(const char *arg)
{
    DIR *dirp;
    struct dirent *dp;
    if ((dirp = opendir(".")) == NULL) {
        perror("couldn't open '.'");
        return;
    }
    do {
        errno = 0;
        if ((dp = readdir(dirp)) != NULL) {
            if (strcmp(dp->d_name, arg) != 0)
                continue;
            (void) printf("found %s\n", arg);
            (void) closedir(dirp);
                return;
        }
    } while (dp != NULL);
    if (errno != 0)
        perror("error reading directory");
    else
        (void) printf("failed to find %s\n", arg);
    (void) closedir(dirp);
    return;
}
int main(int argc, char *argv[])
{
    int i;
    for (i = 1; i < argc; i++)
        lookup(argv[i]);
    return (0);
}

استخدام التطبيق

يجب استخدام الدالة readdir() بالاقتران مع opendir() و closedir() و rewinddir() لفحص محتويات الدليل.

الدالة readdir_r() آمنة للاستخدام المتوازي وتعيد القيم في مخزن مؤقت يوفره المستخدم بدلاً من استخدام منطقة بيانات ثابتة قد تتم الكتابة فوقها في كل استدعاء.

التعليل

القيمة المرجعة من readdir() تمثل ببساطة إدخال دليل. لا ينبغي استنتاج أي تكافؤ.

تطبيقات readdir() التاريخية تحصل على إدخالات دليل متعددة في عملية قراءة واحدة، مما يسمح لعمليات readdir() اللاحقة بالعمل من المعلومات المخزنة مؤقتًا. أي صياغة تتطلب أن تضع كل عملية readdir() ناجحة علامة على آخر طابع زمني للوصول إلى البيانات للدليل ليتم تحديثه ستمنع مثل هذه التطبيقات التاريخية الموجهة نحو الأداء.

عند إعادة إدخال دليل لجذر نظام ملفات محمل، أعادت بعض تطبيقات readdir() التاريخية رقم التسلسل الخاص بالملف لنقطة التحميل الأساسية، بدلاً من جذر نظام الملفات المحمل. يعتبر هذا السلوك خطأ، نظرًا لأن الملف الأساسي

man 3p readdir

PROLOG

This manual page is part of the POSIX standard. The original author of this page is the IEEE and The Open Group. The readdir() function is described in the Base Definitions volume of POSIX.1-2017, Section 3.218, Directory Entries.

NAME

readdir, readdir_r - read a directory entry

SYNOPSIS

#include <dirent.h>

                    struct dirent *readdir(DIR *dirp);

                    int readdir_r(DIR *dirp, struct dirent *entry, struct dirent **entry_ptr);

DESCRIPTION

The readdir() function shall return successive entries in the directory referenced by the argument dirp. The argument dirp is a directory stream pointer returned by opendir().

The readdir() function shall return a pointer to a structure which contains the next directory entry. The d_name member of this structure shall contain the character string for the corresponding file name.

When the end of the directory is encountered, readdir() shall return a NULL pointer. If a read error occurs, readdir() shall return a NULL pointer and set errno to indicate the error.

The information in the returned structure may be overwritten by a subsequent call to readdir() on the same directory stream dirp, or by a call to closedir() or rewinddir().

The readdir_r() function shall be equivalent to readdir(), except that the directory entry is copied into the buffer supplied by the caller in the entry argument, and a pointer to this buffer is returned in entry_ptr. The caller must allocate sufficient space for entry. The size of the structure pointed to by entry must be at least the value returned by pathconf (path, _PC_NAME_MAX) plus the size of a struct dirent minus the size of its d_name member.

When the end of the directory is encountered, readdir_r() shall set entry_ptr to NULL and return zero. If a read error occurs, readdir_r() shall return an error number greater than zero and set entry_ptr to NULL. If readdir_r() succeeds, it shall set entry_ptr to point to the buffer entry and return zero.

RETURN VALUE

The readdir() function returns a pointer to a struct dirent, or a NULL pointer if the end of the directory is encountered or an error occurs. If an error occurs, errno is set to indicate the error.

The readdir_r() function returns zero on success, or an error number greater than zero on error or end-of-directory.

ERRORS

The readdir() and readdir_r() functions shall fail if:

EBADF
The dirp argument does not refer to an opened directory stream.
EINTR
A signal was caught during the read operation.
EIO
An I/O error has occurred.
ENOTDIR
The file descriptor associated with dirp refers to a file that is not a directory.

EXAMPLES

#include <stdio.h>
#include <stdlib.h>
#include <dirent.h>
#include <string.h>
#include <errno.h>

int
main(int argc, char *argv[])
{
    DIR *dp;
    struct dirent *ep;
    char *path;
    long name_max;
    size_t buf_size;
    struct dirent entry;
    struct dirent *entry_ptr;
    int err_val;

    if (argc != 2) {
        fprintf(stderr, "Usage: %s directory_path\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    path = argv[1];

    dp = opendir(path);
    if (dp == NULL) {
        perror("Couldn't open directory");
        exit(EXIT_FAILURE);
    }

    // Example using readdir()
    errno = 0; // Reset errno before calling readdir()
    while ((ep = readdir(dp)) != NULL) {
        printf("readdir: %s\n", ep->d_name);
    }

    if (errno != 0) {
        perror("Error reading directory with readdir");
    }

    // Example using readdir_r()
    // Determine buffer size needed for readdir_r()
    name_max = pathconf(path, _PC_NAME_MAX);
    if (name_max == -1) {
        perror("pathconf");
        // Use a reasonable default if pathconf fails
        name_max = 255;
    }
    buf_size = sizeof(struct dirent) + name_max;
    // Note: In a real application, you might want to use dynamic allocation
    // or ensure 'entry' has sufficient stack space if it's a local variable.
    // For simplicity, we'll assume 'entry' is large enough or on the stack.

    // Rewind the directory stream to read again with readdir_r
    rewinddir(dp);

    while (1) {
        err_val = readdir_r(dp, &entry, &entry_ptr);
        if (err_val != 0) {
            if (err_val > 0) { // Error occurred
                errno = err_val;
                perror("Error reading directory with readdir_r");
            } else { // End of directory
                break;
            }
        }

        if (entry_ptr == NULL) { // End of directory
            break;
        }
        printf("readdir_r: %s\n", entry_ptr->d_name);
    }

    closedir(dp);
    exit(EXIT_SUCCESS);
}

APPLICATION USAGE

The serial number has no significance to applications.

Since readdir() returns NULL when it detects an error and when the end of the directory is encountered, an application that needs to tell the difference must set errno to zero before the call and check it if NULL is returned. Since the function must not change errno in the second case and must set it to a non-zero value in the first case, a zero errno after a call returning NULL indicates end-of-directory; otherwise, an error.

Routines to deal with this problem more directly were proposed:

int derror (DIR *dirp);
void clearderr (DIR *dirp);

The first would indicate whether an error had occurred, and the second would clear the error indication. The simpler method involving errno was adopted instead by requiring that readdir() not change errno when end-of-directory is encountered.

An error or signal indicating that a directory has changed while open was considered but rejected.

The thread-safe version of the directory reading function returns values in a user-supplied buffer instead of possibly using a static data area that may be overwritten by each call. Either the {NAME_MAX} compile-time constant or the corresponding pathconf() option can be used to determine the maximum sizes of returned pathnames.
