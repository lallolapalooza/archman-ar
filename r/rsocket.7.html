NAME

rsocket - Linux Socket Filter Bytecode

SYNOPSIS

A Linux socket filter (LSF) is a small program written in a restricted C-like language that gets interpreted by the kernel. LSF programs are used to filter network packets. They are attached to a socket using setsockopt(2) with the SO_ATTACH_FILTER or SO_DETACH_FILTER option.

DESCRIPTION

LSF is a stack machine. Each instruction takes arguments from the stack, performs an operation, and pushes the result back onto the stack. The stack size is limited to 16 32-bit words. LSF programs must terminate with a RET instruction.

The interpreter starts execution at the first instruction. Most instructions push a value onto the stack. The LD and LDX instructions load values from the packet data into registers. The ST and STX instructions store values from registers into the stack.

The following registers are available:

  • A: accumulator register
  • X: index register
  • M[]: 16 32-bit words for temporary storage.

The LD instruction loads data from the packet into the accumulator register A. The offset into the packet is specified by the instruction's second operand.

The LDX instruction loads data from the packet into the index register X. The offset into the packet is specified by the instruction's second operand.

The ST instruction stores the value of the accumulator register A into the M array at the specified index.

The STX instruction stores the value of the index register X into the M array at the specified index.

The RET instruction terminates the program and returns a value. The return value is used to determine whether to accept or reject the packet.

The following instructions are available:

  • LD (uint32 | uint16 | uint8 | be32 | be16 | be8 | le32 | le16 | le8) offset, size: Load data from packet at offset with size into accumulator A. Endianness conversion is performed if specified.
  • LDX (uint32 | uint16 | uint8 | be32 | be16 | be8 | le32 | le16 | le8) offset, size: Load data from packet at offset with size into index register X. Endianness conversion is performed if specified.
  • LD [[-]]imm, size: Load immediate value imm into accumulator A.
  • ST [M+imm], size: Store accumulator A into M array at offset imm.
  • STX [M+imm], size: Store index register X into M array at offset imm.
  • LD [M+imm], size: Load M array at offset imm into accumulator A.
  • LDX [M+imm], size: Load M array at offset imm into index register X.
  • RET size: Terminate program and return A if size is non-zero, otherwise return 0.
  • ALU32 op src: Perform 32-bit arithmetic operation op with src and store result in A. src can be an immediate value or register X.
  • ALU op src: Perform 16-bit arithmetic operation op with src and store result in A. src can be an immediate value or register X.
  • JMP offset: Unconditional jump to offset.
  • JA offset: Unconditional jump to offset.
  • COND op jump_offset: Conditional jump based on comparison between A and X. op can be EQ, GT, GE, LT, LE, NE.
  • CALL func_offset: Call function at func_offset.
  • TAX: Copy A to X.
  • TXA: Copy X to A.
  • MISC op dst src: Miscellaneous operations.
  • PUSH: Push accumulator A onto the stack.
  • POP A: Pop value from stack into accumulator A.
  • POP X: Pop value from stack into index register X.

The following operations are available for ALU32 and ALU:

  • add: Addition
  • sub: Subtraction
  • mul: Multiplication
  • div: Division
  • mod: Modulo
  • and: Bitwise AND
  • or: Bitwise OR
  • xor: Bitwise XOR
  • lsh: Left shift
  • rsh: Right shift
  • neg: Negate
  • not: Bitwise NOT

The following operations are available for COND:

  • EQ: Equal
  • GT: Greater than
  • GE: Greater than or equal to
  • LT: Less than
  • LE: Less than or equal to
  • NE: Not equal

The following operations are available for MISC:

  • WICH: Set A to the current network device name.

A return value of 0 means the packet is rejected. A non-zero value means the packet is accepted.

The maximum packet size is 1500 bytes. Offsets are relative to the start of the packet.

The interpreter checks for stack overflows and attempts to prevent infinite loops. The maximum program size is 4096 instructions.

NOTES

The SO_ATTACH_FILTER socket option expects a structure of type struct sock_filter, which is an array of struct sock_fprog. The sock_fprog structure contains the program length and a pointer to the program instructions.

Example program to accept only TCP packets:


    struct sock_filter filter[] = {
        BPF_STMT(BPF_LD+BPF_B+BPF_ABS, 23), /* Load L3 protocol */
        BPF_JUMP(BPF_JMP+BPF_JEQ+BPF_K, ETH_P_IP, 0, 1), /* If not IP, jump */
        BPF_STMT(BPF_LD+BPF_W+BPF_ABS, 14), /* Load TCP source port */
        BPF_JUMP(BPF_JMP+BPF_JEQ+BPF_K, htons(22), 0, 1), /* If not port 22, jump */
        BPF_STMT(BPF_RET+BPF_K, 65535), /* Accept */
        BPF_STMT(BPF_RET+BPF_K, 0), /* Reject */
    };
    struct sock_fprog prog = {
        .len = sizeof(filter) / sizeof(filter[0]),
        .filter = filter,
    };
    setsockopt(sk, SOL_SOCKET, SO_ATTACH_FILTER, &prog, sizeof(prog));

The SO_DETACH_FILTER socket option removes any previously attached filter.
