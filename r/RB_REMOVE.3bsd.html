الوصف

تحدد هذه الماكرو هياكل بيانات لأنواع مختلفة من الأشجار: أشجار الاعتكاف والأشجار الحمراء والسوداء.

في تعريفات الماكرو، TYPE هو وسم اسم بنية معرفة من قبل المستخدم يجب أن تحتوي على حقل يسمى FIELD، من نوع SPLAY_ENTRY أو RB_ENTRY. الوسيط HEADNAME هو وسم اسم بنية معرفة من قبل المستخدم يجب الإعلان عنها باستخدام الماكرو SPLAY_HEAD() أو RB_HEAD(). الوسيط NAME يجب أن يكون بادئة اسم فريدة لكل شجرة يتم تعريفها.

تُعلن نماذج الدوال الأولية باستخدام SPLAY_PROTOTYPE، RB_PROTOTYPE، أو RB_PROTOTYPE_STATIC. تُنشأ أجسام الدوال باستخدام SPLAY_GENERATE، RB_GENERATE، أو RB_GENERATE_STATIC. انظر الأمثلة أدناه لمزيد من الشرح حول كيفية استخدام هذه الماكرو.

أشجار الاعتكاف

شجرة الاعتكاف هي هيكل بيانات ذاتي التنظيم. كل عملية على الشجرة تسبب اعترافًا. ينقل الاعتكاف العقدة المطلوبة إلى جذر الشجرة ويعيد توازنها جزئيًا.

هذا له فائدة أن محلية الطلب تسبب عمليات بحث أسرع لأن العقد المطلوبة تنتقل إلى أعلى الشجرة. من ناحية أخرى، كل عملية بحث تسبب كتابة في الذاكرة.

يحد نظرية التوازن من إجمالي وقت الوصول لـ m عملية وإدراج n في شجرة فارغة مبدئيًا كـ O((m + n)lg n). التكلفة المتوسطة لتسلسل m وصول إلى شجرة اعتكاف هي O(lg n).

تترأس شجرة الاعتكاف بنية معرفة بواسطة الماكرو SPLAY_HEAD(). تُعلن بنية SPLAY_HEAD كما يلي:

SPLAY_HEAD(HEADNAME, TYPE) head;

حيث HEADNAME هو اسم البنية التي سيتم تعريفها، و struct TYPE هو نوع العناصر التي سيتم إدراجها في الشجرة.

الماكرو SPLAY_ENTRY() يعلن عن بنية تسمح بتوصيل العناصر في الشجرة.

لاستخدام الدوال التي تعالج بنية الشجرة، يجب الإعلان عن نماذجها الأولية باستخدام الماكرو SPLAY_PROTOTYPE()، حيث NAME هو معرف فريد لهذه الشجرة المحددة. الوسيط TYPE هو نوع البنية التي تتم إدارتها بواسطة الشجرة. الوسيط FIELD هو اسم العنصر المعرف بواسطة SPLAY_ENTRY().

تُنشأ أجسام الدوال باستخدام الماكرو SPLAY_GENERATE(). يأخذ نفس وسائط الماكرو SPLAY_PROTOTYPE()، ولكن يجب استخدامه مرة واحدة فقط.

أخيرًا، الوسيط CMP هو اسم دالة تستخدم لمقارنة عقد الأشجار ببعضها البعض. تأخذ الدالة وسيطين من نوع struct TYPE *. إذا كان الوسيط الأول أصغر من الثاني، تُرجع الدالة قيمة أصغر من الصفر. إذا كانا متساويين، تُرجع الدالة صفرًا. بخلاف ذلك، يجب أن تُرجع قيمة أكبر من الصفر. تحدد دالة المقارنة ترتيب عناصر الشجرة.

الماكرو SPLAY_INIT() يقوم بتهيئة الشجرة المشار إليها بواسطة head.

يمكن أيضًا تهيئة شجرة الاعتكاف بشكل ثابت باستخدام الماكرو SPLAY_INITIALIZER() كما يلي:

SPLAY_HEAD(HEADNAME, TYPE) head = SPLAY_INITIALIZER(&head);

الماكرو SPLAY_INSERT() يدرج العنصر الجديد elm في الشجرة. عند النجاح، يُرجع NULL. إذا كان عنصر مطابق موجودًا بالفعل في الشجرة، يتم إلغاء الإدراج، ويُرجع مؤشر إلى العنصر الموجود.

الماكرو SPLAY_REMOVE() يزيل العنصر elm من الشجرة المشار إليها بواسطة head. عند النجاح، يُرجع مؤشر إلى العنصر الذي تمت إزالته. يُرجع NULL إذا لم يكن elm موجودًا في الشجرة.

يمكن استخدام الماكرو SPLAY_FIND() للعثور على عنصر معين في الشجرة.

struct TYPE find, *res;
find.key = 30;
res = SPLAY_FIND(NAME, &head, &find);

يمكن استخدام الماكرو SPLAY_ROOT() و SPLAY_MIN() و SPLAY_MAX() و SPLAY_NEXT() للتنقل في الشجرة:

for (np = SPLAY_MIN(NAME, &head); np != NULL; np = SPLAY_NEXT(NAME, &head, np))

أو، للتبسيط، يمكن استخدام الماكرو SPLAY_FOREACH():

SPLAY_FOREACH(np, NAME, &head)

يجب استخدام الماكرو SPLAY_EMPTY() للتحقق مما إذا كانت شجرة الاعتكاف فارغة.

الأشجار الحمراء والسوداء

الشجرة الحمراء والسوداء هي شجرة بحث ثنائية مع لون العقدة كسمة إضافية. تفي بمجموعة من الشروط:

  1. كل مسار بحث من الجذر إلى ورقة يتكون من نفس العدد من العقد السوداء،
  2. كل عقدة حمراء (باستثناء الجذر) لها أب أسود،
  3. كل عقدة ورقة سوداء.

كل عملية على شجرة حمراء وسوداء محدودة بـ O(lg n). أقصى ارتفاع لشجرة حمراء وسوداء هو 2lg (n+1).

تترأس الشجرة الحمراء والسوداء بنية معرفة بواسطة الماكرو RB_HEAD(). تُعلن بنية RB_HEAD كما يلي:

RB_HEAD(HEADNAME, TYPE) head;

حيث HEADNAME هو اسم البنية التي سيتم تعريفها، و struct TYPE هو نوع العناصر التي سيتم إدراجها في الشجرة.

الماكرو RB_ENTRY() يعلن عن بنية تسمح بتوصيل العناصر في الشجرة.

لاستخدام الدوال التي تعالج بنية الشجرة، يجب الإعلان عن نماذجها الأولية باستخدام الماكرو RB_PROTOTYPE() أو RB_PROTOTYPE_STATIC()، حيث NAME هو معرف فريد لهذه الشجرة المحددة. الوسيط TYPE هو نوع البنية التي تتم إدارتها بواسطة الشجرة. الوسيط FIELD هو اسم العنصر المعرف بواسطة RB_ENTRY().

تُنشأ أجسام الدوال باستخدام الماكرو RB_GENERATE() أو RB_GENERATE_STATIC(). تأخذ هذه الماكرو نفس وسائط الماكرو RB_PROTOTYPE() و RB_PROTO

DESCRIPTION

The tree family of macros provides a generic implementation of red-black trees. They allow the programmer to easily implement a red-black tree, using any data structure as the node type, as long as it contains a field of type struct RB_ENTRY. The red-black tree implementation is based on the algorithm described in chapter 13 of Introduction to Algorithms by Cormen, Leiserson, Rivest, and Stein.

The macros are used in conjunction with the RB_HEAD, RB_ENTRY, RB_PROTOTYPE and RB_GENERATE macros.

The RB_HEAD macro declares the head of the tree. It should be used once for each tree that is implemented.

struct RB_ENTRY(type) { \
...
};

The RB_ENTRY macro defines the structure that holds the pointers needed for the red-black tree. It should be embedded into the user-defined node structure. For example:

struct my_node {
    int data;
    struct RB_ENTRY(my_node) next;
};

The RB_PROTOTYPE macro declares the tree functions. It should be used once in the header file, where the tree is defined.

The RB_GENERATE macro defines the tree functions. It should be used once in the source file, where the tree is defined.

The RB_GENERATE_INSERT_H, RB_GENERATE_REMOVE_H, RB_GENERATE_FIND_H, RB_GENERATE_INORDER_H, and RB_GENERATE_REMOVE_BY_POINTER_H macros may be used instead of RB_GENERATE, for cases where you only need a subset of the generated functions.

The RB_HEAD macro declares the structure that holds the root of the tree. For example:

RB_HEAD(my_tree_head, struct my_node) my_tree;

This declares a tree head named my_tree which contains nodes of type struct my_node.

The RB_PROTOTYPE macro declares the function prototypes for the tree operations. For example:

RB_PROTOTYPE(my_tree_head, struct my_node, next, my_cmp);

This declares the prototypes for the red-black tree operations for a tree named my_tree_head, where the nodes are of type struct my_node, the tree node field is named next, and the comparison function is named my_cmp.

The RB_GENERATE macro defines the actual functions for the red-black tree operations. For example:

RB_GENERATE(my_tree_head, struct my_node, next, my_cmp);

This defines the red-black tree operations for a tree named my_tree_head, where the nodes are of type struct my_node, the tree node field is named next, and the comparison function is named my_cmp.

The comparison function cmp takes two arguments of type struct TYPE *. If the first argument is smaller than the second, the function returns a value smaller than zero. If they are equal, the function returns zero. Otherwise, it should return a value greater than zero. The compare function defines the order of the tree elements.

The RB_INSERT macro inserts the new element elm into the tree. Upon success, NULL is returned. If a matching element already exists in the tree, the insertion is aborted, and a pointer to the existing element is returned.

The RB_REMOVE macro removes the element elm from the tree pointed by head. RB_REMOVE() returns elm.

The RB_FIND and RB_NFIND macros can be used to find a particular element in the tree. RB_FIND() finds the node with the same key as elm. RB_NFIND() finds the first node greater than or equal to the search key.

struct TYPE find, *res;
find.key = 30;
res = RB_FIND(NAME, &head, &find);

The RB_ROOT(), RB_MIN(), RB_MAX(), RB_NEXT(), and RB_PREV() macros can be used to traverse the tree:

for (np = RB_MIN(NAME, &head); np != NULL; np = RB_NEXT(NAME, &head, np))

Or, for simplicity, one can use the RB_FOREACH() or RB_FOREACH_REVERSE() macros:

RB_FOREACH(np, NAME, &head)

The macros RB_FOREACH_SAFE() and RB_FOREACH_REVERSE_SAFE() traverse the tree referenced by head in a forward or reverse direction respectively, assigning each element in turn to np. However, unlike their unsafe counterparts, they permit both the removal of np as well as freeing it from within the loop safely without interfering with the traversal.

The RB_EMPTY() macro should be used to check whether a red-black tree is empty.

EXAMPLES

The following example demonstrates how to declare a red-black tree holding integers. Values are inserted into it and the contents of the tree are printed in order. Lastly, the internal structure of the tree is printed.

#include <sys/tree.h>
#include <err.h>
#include <stdio.h>
#include <stdlib.h>

struct node {
	RB_ENTRY(node) entry;
	int i;
};

int	intcmp(struct node *, struct node *);
void	print_tree(struct node *);

int
intcmp(struct node *e1, struct node *e2)
{
	return (e1->i < e2->i ? -1 : e1->i > e2->i);
}

RB_HEAD(inttree, node) head = RB_INITIALIZER(&head);
RB_PROTOTYPE(inttree, node, entry, intcmp)
RB_GENERATE(inttree, node, entry, intcmp)

int testdata[] = {
	20, 16, 17, 13, 3, 6, 1, 8, 2, 4, 10, 19, 5, 9, 12, 15, 18,
	7, 11, 14
};

void
print_tree(struct node *n)
{
	struct node *left, *right;

	if (n == NULL) {
		printf("nil");
		return;
	}
	left = RB_LEFT(n, entry);
	right = RB_RIGHT(n, entry);
	if (left == NULL && right == NULL)
		printf("%d", n->i);
	else {
		printf("%d(", n->i);
		print_tree(left);
		printf(",");
		print_tree(right);
		printf(")");
	}
}

int
main(void)
{
	int i;
	struct node *n;

	for (i = 0; i < sizeof(testdata) / sizeof(testdata[0]); i++) {
		if ((n = malloc(sizeof(struct node))) == NULL)
			err(1, NULL);
		n->i = testdata[i];
		RB_INSERT(inttree, &head, n);
	}

	RB_FOREACH(n, inttree, &head) {
		printf("%d\n", n->i);
	}
	print_tree(RB_ROOT(&head));
	printf("\n");
	return (0);
}

The tree macros first appeared in FreeBSD 4.6.

NOTES

Trying to free a tree in the following way is a common error:

SPLAY_FOREACH(var, NAME, &head) {
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}

The macro RB_FOREACH is generally unsafe when used for removal of elements, as the loop variable var will point to memory that has been freed.

for (var = SPLAY_MIN(NAME, &head); var != NULL; var = nxt) {
	nxt = SPLAY_NEXT(NAME, &head, var);
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}

This loop structure avoids the problem, by using a temporary variable nxt to store the next element before the current element is removed and freed.
