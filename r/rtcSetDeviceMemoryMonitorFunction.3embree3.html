الحزمة: embree3

التراخيص: Apache

rtcSetDeviceMemoryMonitorFunction(3) Embree Ray Tracing Kernels 3 rtcSetDeviceMemoryMonitorFunction(3)

الاسم

rtcSetDeviceMemoryMonitorFunction - تسجيل دالة رد اتصال لتتبع استهلاك الذاكرة

الملخص

#include <embree3/rtcore.h>
typedef bool (*RTCMemoryMonitorFunction)(
  void* userPtr,
  ssize_t bytes,
  bool post
);
void rtcSetDeviceMemoryMonitorFunction(
  RTCDevice device,
  RTCMemoryMonitorFunction memoryMonitor,
  void* userPtr
);

الوصف

باستخدام استدعاء rtcSetDeviceMemoryMonitorFunction، من الممكن تسجيل دالة رد اتصال (الوسيط memoryMonitor) مع حمولة (الوسيط userPtr) لجهاز (الوسيط device) يتم استدعاؤها كلما تم تخصيص أو إلغاء تخصيص الذاكرة الداخلية بواسطة كائنات هذا الجهاز. باستخدام آلية رد اتصال مراقب الذاكرة هذه، يمكن للتطبيق تتبع استهلاك الذاكرة لجهاز Embree، واختياريًا إنهاء استدعاءات API التي تستهلك الكثير من الذاكرة.

يمكن تسجيل دالة رد اتصال واحدة فقط لكل جهاز، وستؤدي الاستدعاءات اللاحقة إلى الكتابة فوق دالة رد الاتصال التي تم تعيينها سابقًا. يدي تعيين NULL كمؤشر دالة لتعطيل دالة رد الاتصال المسجلة.

بمجرد التسجيل، سيقوم جهاز Embree باستدعاء دالة مراقب الذاكرة قبل أو بعد تخصيص أو تحرير كتل الذاكرة المهمة. يتم تمرير حمولة المستخدم كما هو محدد عند التسجيل (الوسيط userPtr)، وعدد البايتات التي تم تخصيصها أو إلغاء تخصيصها (الوسيط bytes)، وما إذا كان رد الاتصال يتم استدعاؤه بعد حدوث التخصيص أو إلغاء التخصيص (الوسيط post). قد يتم استدعاء دالة رد الاتصال من عدة مؤشرات ترابط بشكل متزامن.

يمكن للتطبيق تتبع استخدام الذاكرة الحالي لجهاز Embree عن طريق تجميع قيمة معلمة البايتات التي يتم تمريرها إلى دالة رد الاتصال بشكل ذري. ستكون هذه المعلمة > 0 للتخصيصات و < 0 لإلغاء التخصيصات.

سيستمر Embree في عمله بشكل طبيعي عند إرجاع true من دالة رد الاتصال. إذا تم إرجاع false، فسيقوم Embree بإلغاء العملية الحالية برمز الخطأ RTC_ERROR_OUT_OF_MEMORY. يُسمح بإصدار طلبات إلغاء متعددة من مؤشرات ترابط مختلفة. سيحدث الإلغاء فقط عندما تم استدعاء رد الاتصال للتخصيصات (bytes > 0)، وإلا فسيتم تجاهل طلب الإلغاء.

إذا تم استدعاء رد اتصال للإلغاء قبل حدوث التخصيص (post == false)، فلا ينبغي تجميع معلمة البايتات، حيث لن يحدث التخصيص أبدًا. إذا تم استدعاء رد اتصال للإلغاء بعد حدوث التخصيص (post == true)، فيجب تجميع معلمة البايتات، حيث حدث التخصيص بشكل صحيح وسيؤدي إلغاء التخصيص لاحقًا إلى تحرير كتلة البيانات تلك.
