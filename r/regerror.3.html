الوصف

الترجمة

تُستخدم regcomp() لترجمة تعبير نمطي إلى تنسيق مناسب لعمليات البحث اللاحقة باستخدام regexec().

عند النجاح، يتم تهيئة مخزن الأنماط في *preg. regex هو سلسلة نصية منتهية بصفر. يجب أن يكون الإعداد المحلي هو نفسه عند تشغيل regexec().

بعد نجاح regcomp()، يحتوي preg->re_nsub على عدد التعبيرات الفرعية في regex. وبالتالي، فإن القيمة preg->re_nsub + 1 التي يتم تمريرها كـ n إلى regexec() كافية لالتقاط جميع التطابقات.

cflags هو OR الثنائي لصفر أو أكثر من الأعلام التالية:

REG_EXTENDED
استخدم صيغة تعبير نمطي قياسية POSIX الموسعة عند تفسير regex. إذا لم يتم تعيينه، يتم استخدام صيغة تعبير نمطي أساسية POSIX.
REG_ICASE
لا تفرق بين حالة الأحرف. عمليات البحث اللاحقة باستخدام regexec() التي تستخدم مخزن الأنماط هذا ستكون غير حساسة لحالة الأحرف.
REG_NOSUB
الإبلاغ عن النجاح العام فقط. ستستخدم regexec() فقط pmatch لـ REG_STARTEND، متجاهلة n.
REG_NEWLINE
عوامل تشغيل مطابقة أي حرف لا تطابق حرف سطر جديد.
قائمة غير مطابقة ([^...]) لا تحتوي على حرف سطر جديد لا تطابق حرف سطر جديد.
عامل تشغيل بداية السطر (^) يطابق السلسلة الفارغة فورًا بعد حرف سطر جديد، بغض النظر عما إذا كان eflags، أعلام التنفيذ لـ regexec()، يحتوي على REG_NOTBOL.
عامل تشغيل نهاية السطر ($) يطابق السلسلة الفارغة فورًا قبل حرف سطر جديد، بغض النظر عما إذا كان eflags يحتوي على REG_NOTEOL.

المطابقة

تُستخدم regexec() لمطابقة سلسلة نصية منتهية بصفر مع مخزن الأنماط المترجم في *preg، والذي يجب أن يكون قد تم تهيئته باستخدام regcomp(). eflags هو OR الثنائي لصفر أو أكثر من الأعلام التالية:

REG_NOTBOL
يفشل عامل تشغيل بداية السطر دائمًا في المطابقة (لكن انظر علم الترجمة REG_NEWLINE أعلاه). قد يتم استخدام هذا العلم عند تمرير أجزاء مختلفة من سلسلة نصية إلى regexec() ويجب عدم تفسير بداية السلسلة كنهاية سطر.
REG_NOTEOL
يفشل عامل تشغيل نهاية السطر دائمًا في المطابقة (لكن انظر علم الترجمة REG_NEWLINE أعلاه).
REG_STARTEND
يطابق [string + pmatch[0].rm_so, string + pmatch[0].rm_eo) بدلاً من [string, string + strlen(string)). يسمح هذا بمطابقة بايتات NUL المضمنة وتجنب strlen(3) على سلاسل نصية ذات طول معروف. إذا تم إرجاع أي مطابقات (لم يتم تمرير REG_NOSUB إلى regcomp()، ونجحت المطابقة، و n > 0)، فإنها تقوم بالكتابة فوق pmatch كالمعتاد، وتظل أوفسيتات المطابقة نسبية إلى string (وليس string + pmatch[0].rm_so). هذا العلم هو امتداد BSD، غير موجود في POSIX.

أوفسيتات المطابقة

ما لم يتم تمرير REG_NOSUB إلى regcomp()، فمن الممكن الحصول على مواقع المطابقات داخل string: تقوم regexec() بملء n عناصر من pmatch بالنتائج: pmatch[0] يتوافق مع المطابقة الكاملة، pmatch[1] مع التعبير الفرعي الأول، وهكذا. إذا كانت هناك مطابقات أكثر من n، يتم تجاهلها؛ إذا كانت أقل، يتم ملء العناصر غير المستخدمة من pmatch بـ -1.

كل مطابقة صالحة (غير -1) تم إرجاعها تتوافق مع النطاق [string + rm_so, string + rm_eo).

regoff_t هو نوع عدد صحيح موقع قادر على تخزين أكبر قيمة يمكن تخزينها في أحد أنواع ptrdiff_t أو ssize_t.

الإبلاغ عن الأخطاء

تُستخدم regerror() لتحويل رموز الخطأ التي يمكن إرجاعها من كل من regcomp() و regexec() إلى سلاسل رسائل خطأ.

إذا لم يكن preg مؤشرًا فارغًا، فيجب أن يكون errcode هو أحدث خطأ تم إرجاعه من عملية على preg.

إذا لم يكن errbuf_size يساوي 0، يتم نسخ ما يصل إلى errbuf_size بايت إلى errbuf؛ تكون سلسلة الخطأ دائمًا منتهية بصفر، ويتم اقتطاعها لتناسب.

التحرير

تقوم regfree() بإلغاء تهيئة مخزن الأنماط في *preg، وتحرير أي ذاكرة مرتبطة به؛ يجب أن يكون *preg قد تم تهيئته عبر regcomp().

قيمة الإرجاع

تُرجع regcomp() صفرًا للترجمة الناجحة أو رمز خطأ للفشل.

تُرجع regexec() صفرًا للمطابقة الناجحة أو REG_NOMATCH للفشل.

تُرجع regerror() حجم المخزن المؤقت المطلوب للاحتفاظ بالسلسلة.

الأخطاء

يمكن إرجاع الأخطاء التالية بواسطة regcomp():

REG_BADBR
استخدام غير صالح لمراجع مرجعية.
REG_BADPAT
استخدام غير صالح لعوامل الأنماط مثل المجموعات أو القوائم.
REG_BADRPT
استخدام غير صالح لعوامل التكرار مثل استخدام '*' كأول حرف.
REG_EBRACE
عوامل فواصل زمنية غير متطابقة.
REG_EBRACK
عوامل قائمة أقواس غير متطابقة.
REG_ECOLLATE
عنصر تجميع غير صالح.
REG_ECTYPE
اسم فئة أحرف غير معروف.
REG_EEND
خطأ غير محدد. هذا غير معرف بواسطة POSIX.
REG_EESCAPE
شرطة مائلة لاحقة.
REG_EPAREN
عوامل مجموعات الأقواس غير المتطابقة.
REG_ERANGE
استخدام غير صالح لعامل النطاق؛ على سبيل المثال، تقع نقطة نهاية النطاق قبل نقطة البداية.

regerror(3) — Linux manual pages

NAME

regerror, regcomp, regexec, regfree — regular expression matching

LIBRARY

Support library (libregex, -lregex)

SYNOPSIS

#include <regex.h>

size_t regerror(int errcode, const regex_t *restrict preg, char *restrict errbuf, size_t errbuf_size);
int regcomp(regex_t *restrict preg, const char *restrict regex, int cflags);
int regexec(const regex_t *restrict preg, const char *restrict string, size_t nmatch, regmatch_t pmatch[restrict], int eflags);
void regfree(regex_t *preg);

DESCRIPTION

The regcomp, regexec, regerror, and regfree functions implement POSIX.1 regular expression matching.

The regcomp function compiles the regular expression given by the string regex and stores the compiled form in the structure pointed to by preg. The cflags argument is the bitwise OR of zero or more of the following compilation flags:

REG_BASIC
Use Basic Regular Expressions (BRE) syntax. This is the default if no syntax flag is specified.
REG_NOSUB
Report only whether the pattern matches, not the start and end of the subexpressions. This can improve performance.
REG_EXTENDED
Use Extended Regular Expressions (ERE) syntax. POSIX.1 specifies that this flag should be supported. GNU Emacs regular expressions are also supported with this flag.
REG_ICASE
Ignore case during matching.
REG_NEWLINE
Causes the characters `‘' and `’' to match the greatest number of characters possible within the string, excluding the newline character at the end of the string. Normally, `‘' and `’' match the longest possible string, including a trailing newline character. If REG_NEWLINE is in effect, a regular expression starting with `^' matches at the beginning of the string. A regular expression ending with `$' matches at the end of the string. The expression `^$' matches an empty string at the beginning of the string. A trailing newline is matched by `.$' if REG_NEWLINE is in effect.
REG_DONT_CARE_LOOSE
This flag is specific to glibc and not part of POSIX.1. It relaxes the matching of bracket expressions to not require exact matching of characters within the brackets.
REG_ENHANCEMODE
This flag is specific to glibc and not part of POSIX.1. It enables some extensions to ERE syntax, such as character classes like `[:alnum:]' and POSIX character sets.
REG_NOCOLLATE
Do not use locale-specific collation order when comparing characters. This can speed up matching.
REG_NOSUB
Report only whether the pattern matches, not the start and end of the subexpressions. This can improve performance.

The regexec function executes the compiled regular expression stored in preg against the character string string. If nmatch is non-zero, the array pmatch is used to store information about the start and end of the matched regular expression and any captured subexpressions. pmatch[0] describes the entire match, and pmatch[i] for i > 0 describes the i-th captured subexpression. The elements of pmatch are regmatch_t structures, each containing rm_so (start offset) and rm_eo (end offset) members.

The eflags argument is the bitwise OR of zero or more of the following execution flags:

REG_NOTBOL
The string string does not start with a beginning-of-line. The default is that it does.
REG_NOTEOL
The string string does not end with an end-of-line. The default is that it does.
REG_TRACE
Trace execution (for debugging).
REG_FUNCTIONS
Report function calls (for debugging).
REG_IRREGULAR
Report use of an irregular grammar (for debugging).
REG_NOMATCH
This flag is not used in POSIX.1.

The regfree function frees any memory that was allocated by regcomp.

The regerror function returns a string describing an error code returned by regcomp or regexec. errcode is the error code, preg is a pointer to the regex_t structure, errbuf is a pointer to a buffer where the error string will be stored, and errbuf_size is the size of the buffer.

The regex_t structure contains at least the following members:

re_nsub
The number of capturing subexpressions.
re_endp
Pointer to the end of the compiled regular expression.

The regmatch_t structure contains at least the following members:

rm_so
Start offset of the match.
rm_eo
End offset of the match.

RETURN VALUE

On success, regcomp returns 0. On failure, it returns an error code. regexec returns 0 on a successful match, and REG_NOMATCH if no match is found. On other errors, it returns a positive error code.

The regerror function returns the number of characters that should have been written to errbuf to fully accommodate the error message (including the null terminator). If errbuf_size is 0, it returns the required size without writing anything to the buffer.

The regfree function returns void.

ERRORS

The regcomp and regexec functions can fail for the following reasons:

REG_ASSERT
An internal error occurred. This should not happen.
REG_BADBR
Invalid use of bracketing expression (e.g., `{1` or `{1,2,3}`).
REG_BADPAT
The regular expression is invalid.
REG_BADECHAR
The regular expression contains a likely escape sequence that is invalid.
REG_ECOLLATE
The regular expression tried to use an invalid collating element.
REG_ECTL_INS
The regular expression contained invalid control characters.
REG_ECTYPE
The regular expression contained invalid character class specifiers.
REG_EEND
The regular expression ended unexpectedly.
REG_EESCAPE
The regular expression ended with a backslash.
REG_ESIZE
Compiled regular expression requires a pattern buffer larger than 64 kB. This is not defined by POSIX.
REG_ESPACE
The regex routines ran out of memory.
REG_ESUBREG
Invalid back reference to a subexpression.

ATTRIBUTES

For an explanation of the terms used in this section, see attributes(7).

Interface Attribute Value
regcomp (), regexec () Thread safety MT-Safe locale
regerror () Thread safety MT-Safe env
regfree () Thread safety MT-Safe

STANDARDS

POSIX.1-2008.

HISTORY

POSIX.1-2001.

Prior to POSIX.1-2008, regoff_t was required to be capable of storing the largest value that can be stored in either an off_t type or a ssize_t type.

CAVEATS

re_nsub is only required to be initialized if REG_NOSUB wasn't specified, but all known implementations initialize it regardless.

Both regex_t and regmatch_t may (and do) have more members, in any order. Always reference them by name.

EXAMPLES

#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <regex.h>
#define NITEMS(arr)  (sizeof((arr)) / sizeof((arr)[0]))
static const char *const str =
        "1) John Driverhacker;\n2) John Doe;\n3) John Foo;\n";
static const char *const re = "John.*o";
int main(void)
{
    static const char *s = str;
    regex_t     regex;
    regmatch_t  pmatch[1];
    regoff_t    off, len;
    if (regcomp(&regex, re, REG_NEWLINE))
        exit(EXIT_FAILURE);
    printf("String = \"%s\"\n", str);
    printf("Matches:\n");
    for (unsigned int i = 0; ; i++) {
        if (regexec(&regex, s, NITEMS(pmatch), pmatch, 0))
            break;
        off = pmatch[0].rm_so + (s - str);
        len = pmatch[0].rm_eo - pmatch[0].rm_so;
        printf("#%u:\n", i);
        printf("offset = %jd; length = %jd\n", (intmax_t) off,
                (intmax_t) len);
        printf("substring = \"%.*s\"\n", len, s + pmatch[0].rm_so);
        s += pmatch[0].rm_eo;
    }
    exit(EXIT_SUCCESS);
}
