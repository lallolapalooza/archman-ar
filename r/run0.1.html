run0(1)

الحزمة: systemd

التراخيص: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later, MIT-0

RUN0(1) run0 RUN0(1)

الاسم

run0 - رفع الامتيازات

الملخص

run0 [خيارات...] [أمر...]

الوصف

يمكن استخدام run0 لاكتساب امتيازات مرفوعة أو مختلفة بشكل مؤقت وتفاعلي. الغرض منها مشابه لـ sudo(8)، ولكنها تعمل بشكل مختلف في بعض المجالات الرئيسية:

•لا يتم وراثة أي بيانات اعتماد للسياق التنفيذي أو الأمني من المستدعي إلى الأوامر المستدعاة، حيث يتم استدعاؤها من خدمة جديدة معزولة يتم إنشاؤها بواسطة مدير الخدمة.
•يتم إجراء المصادقة عبر polkit[1]، وبالتالي عزل موجه المصادقة عن الطرفية (إذا كان ذلك ممكنًا).
•يتم تخصيص طرفية وهمية مستقلة للأمر المستدعى، مما يفصل دورة حياته ويعزله من أجل الأمان.
•لا يتم استخدام وظيفة بت الوصول لملف SetUID/SetGID للتنفيذ.

بشكل عام، يجب أن يوفر هذا بديلاً أكثر أمانًا وقوة لآلية sudo، خاصة في بيئات نظام التشغيل حيث لا يتوفر دعم SetUID/SetGID (على سبيل المثال عن طريق تعيين المتغير NoNewPrivileges= في systemd-system.conf(5)).

سيتم تشغيل أي جلسة مستدعاة عبر run0 من خلال مكدس PAM "systemd-run0".

لاحظ أن run0 تم تنفيذه كاستدعاء متعدد بديل لـ systemd-run(1). أي أن run0 هو رابط رمزي لملف قابل للتنفيذ systemd-run، ويتصرف كـ run0 إذا تم استدعاؤه من خلال الرابط الرمزي، وإلا يتصرف كـ systemd-run.

الخيارات

الخيارات التالية مفهومة:

--unit=

استخدم اسم الوحدة هذا بدلاً من اسم تم إنشاؤه تلقائيًا.

تمت الإضافة في الإصدار 256.

--property=

يحدد خاصية لوحدة الخدمة التي يتم إنشاؤها. يأخذ هذا الخيار تعيينًا بنفس تنسيق أمر set-property في systemctl(1).

تمت الإضافة في الإصدار 256.

--description=

قدم وصفًا لوحدة الخدمة التي يتم استدعاؤها. إذا لم يتم تحديده، فسيتم استخدام الأمر نفسه كوصف. انظر Description= في systemd.unit(5).

تمت الإضافة في الإصدار 256.

--slice=

اجعل وحدة .service الجديدة جزءًا من الشريحة المحددة، بدلاً من user.slice.

تمت الإضافة في الإصدار 256.

--slice-inherit

اجعل وحدة .service الجديدة جزءًا من الشريحة التي تم استدعاء run0 نفسه فيها. يمكن دمج هذا الخيار مع --slice=، وفي هذه الحالة، يتم وضع الشريحة المحددة عبر --slice= داخل الشريحة التي تم استدعاء الأمر run0 فيها.

مثال: بالنظر إلى استدعاء run0 في الشريحة foo.slice، ويكون الوسيط --slice= هو bar. ستوضع الوحدة بعد ذلك تحت foo-bar.slice.

تمت الإضافة في الإصدار 256.

--user=، -u، --group=، -g

ينتقل إلى المستخدم/المجموعة المحددة. إذا لم يتم تحديده، فالافتراضي هو "root"، ما لم يتم استخدام --area= (انظر أدناه)، في هذه الحالة يكون الافتراضي هو المستخدم المستدعي.

تمت الإضافة في الإصدار 256.

--nice=

يشغل الجلسة المستدعاة بمستوى الاستمتاع المحدد.

تمت الإضافة في الإصدار 256.

--chdir=، -D

يشغل الجلسة المستدعاة بدليل العمل المحدد. إذا لم يتم تحديده، فإن الافتراضي هو دليل العمل الحالي للعميل إذا تم الانتقال إلى المستخدم الجذر، أو الدليل الرئيسي للمستخدم المستهدف بخلاف ذلك.

تمت الإضافة في الإصدار 256.

--via-shell

يستدعي shell تسجيل دخول المستخدم المستهدف ويشغل الأمر المحدد (إن وجد) من خلاله.

تمت الإضافة في الإصدار 258.

-i

اختصار لـ --via-shell --chdir='~'.

تمت الإضافة في الإصدار 258.

--setenv=NAME[=VALUE]

يشغل الجلسة المستدعاة مع تعيين متغير البيئة المحدد. يمكن استخدام هذا الوسيط أكثر من مرة لتعيين متغيرات متعددة. عندما يتم حذف "=" و VALUE، سيتم استخدام قيمة المتغير بنفس الاسم في بيئة الاستدعاء.

تمت الإضافة في الإصدار 256.

--background=COLOR

غيّر لون خلفية الطرفية إلى لون ANSI المحدد طالما استمرت الجلسة. إذا لم يتم تحديده، فسيتم تلوين الخلفية بنغمة حمراء عند العمل كجذر، وبنغمة صفراء عند العمل تحت معرف مستخدم آخر، كتذكير بالامتيازات المتغيرة. يجب أن يكون اللون المحدد لون خلفية ANSI X3.64 SGR، أي سلاسل مثل "40"، "41"، ...، "47"، "48;2؛..."، "48;5؛...". انظر ANSI Escape Code (ويكيبيديا)[2] للحصول على التفاصيل. عيّن إلى سلسلة فارغة لتعطيلها.

مثال: "--background=44" لخلفية زرقاء.

تمت الإضافة في الإصدار 256.

--pty، --pty-late، --pipe

اطلب تخصيص طرفية وهمية لجلسة run0 (في حالة --pty أو --pty-late)، أو اطلب تمرير واصفات ملفات الإدخال/الإخراج/الخطأ القياسية للمستدعي مباشرة (في حالة --pipe). --pty-late مشابه جدًا لـ --pty ولكنه يبدأ معالجة TTY فقط بمجرد اكتمال بدء تشغيل الوحدة، تاركًا الإدخال لأي كلمات مرور/وكلاء polkit حتى ذلك الوقت. إذا لم يتم تحديد أي من هذين الخيارين، أو إذا تم تحديد كل من --pipe وأحد --pty/--pty-late، فسيتم اختيار الوضع تلقائيًا: إذا كان الإدخال القياسي والإخراج القياسي والإخراج الخطأ القياسي متصلين جميعًا بـ TTY، فسيتم تخصيص طرفية وهمية (في وضع --pty-late ما لم يتم تحديد --no-ask-password في هذه الحالة يتم اختيار --pty)، وإلا سيتم تمرير واصفات الملفات ذات الصلة مباشرة.

تمت إضافة --pty و --pipe في الإصدار 257.

تمت إضافة --pty-late في الإصدار 258.

--shell-prompt-prefix=STRING

قم بتعيين سلسلة بادئة لـ shell prompt. هذا يتحكم في النهاية في متغير البيئة $SHELL_PROMPT_PREFIX للبرنامج المستدعى، والذي يتم استيراده عادةً إلى shell prompt. بشكل افتراضي – إذا كانت الرموز التعبيرية مدعومة – يتم عرض رمز تعبيري بطل خارق (🦸). يمكن أيضًا تغيير هذا الافتراضي (أو تعطيله) عن طريق تمرير متغير البيئة $SYSTEMD_RUN_SHELL_PROMPT_PREFIX إلى run0، انظر أدناه. عيّن إلى سلسلة فارغة لتعطيل بادئة shell prompt.

تمت الإضافة في الإصدار 257.

--lightweight=BOOLEAN

يتحكم فيما إذا كان سيتم تنشيط مدير الخدمة لكل مستخدم للمستخدم المستهدف. بشكل افتراضي، إذا كان المستخدم المستهدف هو "root" أو مستخدم نظام، فلن يتم تنشيط مدير الخدمة لكل مستخدم نتيجة لاستدعاء run0، وإلا فسيتم تنشيطه.

هذا يتحكم في النهاية في متغير البيئة $XDG_SESSION_CLASS الذي يحترمه pam_systemd(8).

تمت الإضافة في الإصدار 258.

--area=AREA

يتحكم في "منطقة" حساب المستخدم المستهدف لتسجيل الدخول إليها. المناطق هي أدلة منزل ثانوية داخل الدليل الرئيسي للمستخدم المستهدف، أي تسجيل الدخول إلى منطقة "foobar" لحساب ما يترجم إلى تعيين $HOME إلى ~/Areas/foobar عند تسجيل الدخول.

إذا تم استخدام هذا الخيار، يتغير المستخدم الافتراضي للانتقال إليه من الجذر إلى المستخدم المستدعي (ولكن --user= له الأسبقية، انظر أعلاه). أو بعبارة أخرى، مجرد تحديد منطقة بدون مستخدم هو آلية لإنشاء جلسة جديدة للمستخدم المستدعي، فقط بمنطقة مختلفة.

هذا يتحكم في النهاية في متغير البيئة $XDG_AREA الذي يحترمه pam_systemd(8).

للحصول على تفاصيل حول مفهوم المنطقة، انظر pam_systemd_home(8).

تمت الإضافة في الإصدار 258.

--machine=

نفذ العملية في حاوية محلية. حدد اسم حاوية للاتصال بها.

تمت الإضافة في الإصدار 256.

-h, --help

Print a short help text and exit.

--version

Print a short version string and exit.

All command line arguments after the first non-option argument become part of the command line of the launched process. If no command line is specified an interactive shell is invoked. The shell to invoke may be controlled through --via-shell - when specified the target user's shell is used - or --setenv=SHELL=.... By default, the originating user's shell is executed if operating locally, or /bin/sh when operating with --machine=.

Note that unlike sudo, run0 always spawns shells with login shell semantics, regardless of -i.

EXIT STATUS

On success, 0 is returned. If run0 failed to start the session or the specified command fails, a non-zero return value will be returned.

ENVIRONMENT VARIABLES

As with systemd-run, the session will inherit the system environment from the service manager. In addition, the following environment variables will be set:

$TERM

Copied from the $TERM of the caller. Can be overridden with --setenv=

Added in version 256.

$SUDO_USER

Set to the username of the originating user.

Added in version 256.

$SUDO_UID

Set to the numeric UNIX user id of the originating user.

Added in version 256.

$SUDO_GID

Set to the primary numeric UNIX group id of the originating session.

Added in version 256.

$SHELL_PROMPT_PREFIX

By default, set to the superhero emoji (if supported), but may be overridden with the $SYSTEMD_RUN_SHELL_PROMPT_PREFIX environment variable (see below), or the --shell-prompt-prefix= switch (see above).

Added in version 257.

The following variables may be passed to run0:

$SYSTEMD_RUN_SHELL_PROMPT_PREFIX

If set, overrides the default shell prompt prefix that run0 sets for the invoked shell (the superhero emoji). Set to an empty string to disable shell prompt prefixing.

Added in version 257.
