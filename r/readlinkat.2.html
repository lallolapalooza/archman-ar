readlink(2) دليل استدعاءات النظام readlink(2)

الاسم

readlink, readlinkat - قراءة قيمة رابط رمزي

المكتبة

مكتبة C القياسية (libc, -lc)

ملخص

#include <unistd.h>
ssize_t readlink(size_t bufsiz;
                 const char *restrict path,
                 char buf[restrict bufsiz], size_t bufsiz);
#include <fcntl.h>            /* تعريف ثوابت AT_* */
#include <unistd.h>
ssize_t readlinkat(size_t bufsiz;
                 int dirfd, const char *restrict path,
                 char buf[restrict bufsiz], size_t bufsiz);
متطلبات ميزة الاختبار (Feature Test Macro Requirements) لـ glibc (انظر feature_test_macros(7)):

readlink():

    _XOPEN_SOURCE >= 500 || _POSIX_C_SOURCE >= 200112L
        || /* glibc <= 2.19: */ _BSD_SOURCE

readlinkat():

    منذ glibc 2.10:
        _POSIX_C_SOURCE >= 200809L
    قبل glibc 2.10:
        _ATFILE_SOURCE

الوصف

تقوم readlink() بوضع محتويات الرابط الرمزي path في المخزن المؤقت buf، والذي حجمه bufsiz. readlink() لا تضيف بايت إنهاء فارغ (null byte) إلى buf. ستقوم (بصمت) بتقصير المحتويات (إلى طول bufsiz حرفًا)، في حال كان المخزن المؤقت صغيرًا جدًا لاستيعاب كل المحتويات.

readlinkat()

تعمل استدعاءات نظام readlinkat() بنفس الطريقة تمامًا مثل readlink()، باستثناء الاختلافات الموضحة هنا.

إذا كان path نسبيًا، فسيتم تفسيره بالنسبة للدليل المشار إليه بواسطة واصف الملف dirfd (بدلاً من كونه نسبيًا لمجلد العمل الحالي للعملية المتصلة، كما تفعل readlink() للمسارات النسبية).

إذا كان path نسبيًا و dirfd هي القيمة الخاصة AT_FDCWD، فسيتم تفسير path بالنسبة لمجلد العمل الحالي للعملية المتصلة (مثل readlink()).

إذا كان path مطلقًا، فسيتم تجاهل dirfd.

منذ Linux 2.6.39، يمكن أن يكون path سلسلة فارغة، وفي هذه الحالة تعمل المكالمة على الرابط الرمزي المشار إليه بواسطة dirfd (والذي يجب الحصول عليه باستخدام open(2) مع العلامات O_PATH و O_NOFOLLOW).

انظر openat(2) لشرح الحاجة إلى readlinkat().

قيمة الإرجاع

عند النجاح، تقوم هذه الاستدعاءات بإرجاع عدد البايتات التي تم وضعها في buf. (إذا كانت القيمة المرجعة تساوي bufsiz، فقد يكون هناك اقتطاع.) عند الخطأ، يتم إرجاع -1 ويتم تعيين errno للإشارة إلى الخطأ.

الأخطاء

EACCES
تم رفض إذن البحث لمكون من بادئة المسار. (انظر أيضًا path_resolution(7).)
EBADF
(readlinkat()) path نسبي ولكن dirfd ليس AT_FDCWD ولا واصف ملف صالح.
EFAULT
يمتد buf خارج مساحة العنوان المخصصة للعملية.
EINVAL
bufsiz ليس موجبًا.
EINVAL
الملف المسمى (أي، آخر مكون اسم الملف لـ path) ليس رابطًا رمزيًا.
EIO
حدث خطأ في الإدخال/الإخراج أثناء القراءة من نظام الملفات.
ELOOP
تم العثور على عدد كبير جدًا من الروابط الرمزية أثناء ترجمة اسم المسار.
ENAMETOOLONG
كان اسم المسار، أو مكون من اسم المسار، طويلاً جدًا.
ENOENT
الملف المسمى غير موجود.
ENOMEM
كانت ذاكرة النواة غير كافية.
ENOTDIR
مكون من بادئة المسار ليس دليلاً.
ENOTDIR
(readlinkat()) path نسبي و dirfd هو واصف ملف يشير إلى ملف غير دليل.

المعايير

POSIX.1-2024.

التاريخ

readlink()
4.4BSD (ظهرت لأول مرة في 4.2BSD)، POSIX.1-2001، POSIX.1-2008.
readlinkat()
POSIX.1-2008. Linux 2.6.16، glibc 2.4.

حتى glibc 2.4 وما بعدها، كان نوع الإرجاع لـ readlink() يُعلن كـ int. في الوقت الحاضر، يُعلن نوع الإرجاع كـ ssize_t، كما هو مطلوب (حديثًا) في POSIX.1-2001.

glibc

على النوى الأقدم حيث readlinkat() غير متاحة، تعتمد وظيفة التغليف glibc على استخدام readlink(). عندما يكون path نسبيًا، تقوم glibc بإنشاء اسم مسار بناءً على الرابط الرمزي في /proc/self/fd الذي يتوافق مع الوسيط dirfd.

ملاحظات

قد لا يوفر استخدام مخزن مؤقت بحجم ثابت مساحة كافية لمحتويات الرابط الرمزي. يمكن الحصول على الحجم المطلوب للمخزن المؤقت من قيمة stat.st_size التي تم إرجاعها بواسطة مكالمة إلى lstat(2) على الرابط. ومع ذلك، يجب التحقق من عدد البايتات التي تم كتابتها بواسطة readlink() و readlinkat() للتأكد من أن حجم الرابط الرمزي لم يزد بين المكالمات. كما أن تخصيص المخزن المؤقت ديناميكيًا لـ readlink() و readlinkat() يعالج مشكلة قابلية نقل شائعة عند استخدام PATH_MAX لحجم المخزن المؤقت، حيث أن هذا الثابت غير مضمون ليكون معرفًا حسب POSIX إذا لم يكن للنظام مثل هذا الحد.

أمثلة

يقوم البرنامج التالي بتخصيص المخزن المؤقت المطلوب بواسطة readlink() ديناميكيًا من المعلومات المقدمة بواسطة lstat(2)، مع العودة إلى مخزن مؤقت بحجم PATH_MAX في الحالات التي يبلغ فيها lstat(2) عن حجم صفر.

#include <limits.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/stat.h>
#include <sys/types.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    char         *buf;
    ssize_t      nbytes, bufsiz;
    struct stat  sb;
    if (argc != 2) {
        fprintf(stderr, "Usage: %s <path>\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    if (lstat(argv[1], &sb) == -1) {
        perror("lstat");
        exit(EXIT_FAILURE);
    }
    /* إضافة واحد إلى حجم الرابط، حتى نتمكن من تحديد ما إذا كان
       المخزن المؤقت الذي تم إرجاعه بواسطة readlink() قد تم اقتطاعه.  */
    bufsiz = sb.st_size + 1;
    /* بعض الروابط السحرية تحت (على سبيل المثال) /proc و /sys
       تبلغ عن 'st_size' كصفر. في هذه الحالة، خذ PATH_MAX كتقدير
       "جيد بما فيه الكفاية".  */
    if (sb.st_size == 0)
        bufsiz = PATH_MAX;
    buf = malloc(bufsiz);
    if (buf == NULL) {
        perror("malloc");
        exit(EXIT_FAILURE);
    }
    nbytes = readlink(argv[1], buf, bufsiz);
    if (nbytes == -1) {
        perror("readlink");
        exit(EXIT_FAILURE);
    }
    /* طباعة 'nbytes' فقط من 'buf'، لأنه لا يحتوي على بايت إنهاء
       فارغ ('\0').  */
    printf("'%s' يشير إلى '%.*s'\n", argv[1], (int) nbytes, buf);
    /* إذا كانت القيمة المرجعة تساوي حجم المخزن المؤقت، فإن
       الوجهة الرابطة كانت أكبر من المتوقع (ربما لأن
    */
    /* The rest of the example program is omitted due to length constraints. */
    exit(EXIT_SUCCESS);
}
