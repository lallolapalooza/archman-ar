الاسم

re2v - توليد محللات معجمية سريعة لـ V

الخلاصة

re2v [ خيارات ] [ تحذيرات ] مدخل

يمكن أن يكون المدخل ملفًا أو - للمدخل القياسي.

مقدمة

يعمل re2v كمعالج مسبق. يقرأ ملف الإدخال (وهو عادةً برنامج بلغة V، ولكن يمكن أن يكون أي شيء) ويبحث عن كتل من التعليمات البرمجية محاطة بعلامات بداية/نهاية ذات شكل خاص. يتم نسخ النص خارج هذه الكتل حرفيًا إلى ملف الإخراج. تتم معالجة محتويات الكتل بواسطة re2v. يقوم بترجمتها إلى تعليمات برمجية بلغة V ويخرج التعليمات البرمجية المولدة بدلاً من الكتلة.

إليك مثال لبرنامج صغير يتحقق مما إذا كانت سلسلة معينة تحتوي على رقم عشري:

// re2v $INPUT -o $OUTPUT -i
fn lex(yyinput string) {
    mut yycursor := 0
    /*!re2c
        re2c:yyfill:enable = 0;
        [1-9][0-9]* { return }
        *           { panic("error!") }
    */
}
fn main() {
    lex("1234\x00")
}

في الإخراج، استبدل re2v الكتلة في المنتصف بالتعليمات البرمجية المولدة:

// Code generated by re2v, DO NOT EDIT.
// re2v $INPUT -o $OUTPUT -i
fn lex(yyinput string) {
    mut yycursor := 0
    mut yych := 0
    yych = yyinput[yycursor]
    match yych {
        0x31...0x39 { unsafe { goto yy2 } }
        else { unsafe { goto yy1 } }
    }
yy1:
    yycursor += 1
    panic("error!")
yy2:
    yycursor += 1
    yych = yyinput[yycursor]
    match yych {
        0x30...0x39 { unsafe { goto yy2 } }
        else { unsafe { goto yy3 } }
    }
yy3:
    return
}
fn main() {
    lex("1234\x00")
}

الأساسيات

يتكون برنامج re2v من تسلسل من الكتل تتداخل مع التعليمات البرمجية بلغة الهدف. قد تحتوي الكتلة على تعريفات، تكوينات، قواعد، إجراءات وتوجيهات بأي ترتيب:

الاسم = تعبير-نمطي ;
تعريف يربط الاسم بـ تعبير-نمطي. يمكن أن تحتوي الأسماء على أحرف أبجدية رقمية وشرطة سفلية. يقدم قسم التعبيرات النمطية نظرة عامة على بناء جمل re2v للتعبيرات النمطية. بمجرد تعريفه، يمكن استخدام الاسم في تعبيرات نمطية أخرى وفي القواعد. لا يُسمح بالتكرار في التعريفات المسماة، ويجب تعريف كل اسم قبل استخدامه. ترث الكتلة التعريفات المسماة من النطاق العام. إعادة تعريف اسم موجود في النطاق الحالي يعد خطأ.
تكوين = قيمة ;
تكوين يسمح بتغيير سلوك re2v وتخصيص التعليمات البرمجية المولدة. للحصول على قائمة كاملة بالتكوينات التي يدعمها re2v، راجع قسم التكوينات. اعتمادًا على تكوين معين، يمكن أن تكون القيمة كلمة مفتاحية، أو رقمًا صحيحًا غير سالب، أو سلسلة نصية من سطر واحد يجب أن تكون محاطة بعلامات اقتباس مزدوجة أو مفردة ما لم تكن تتكون من أحرف أبجدية رقمية. ترث الكتلة التكوينات من النطاق العام وقد تعيد تعريفها أو تضيف تكوينات جديدة. التكوينات المعرفة داخل كتلة تؤثر على الكتلة بأكملها، حتى لو ظهرت في نهايتها.
تعبير-نمطي تعليمات برمجية
قاعدة تربط تعبير-نمطي بإجراءاتها الدلالية (كتلة تعليمات برمجية بين أقواس معقوفة، أو كتلة تعليمات برمجية تبدأ بـ := وتنتهي بسطر جديد متبوعًا بأي حرف غير مسافة بيضاء). إذا تطابق تعبير-نمطي، يتم تنفيذ التعليمات البرمجية المرتبطة به. إذا تطابقت قواعد متعددة، فإن أطول تطابق له الأولوية. إذا تطابقت قواعد متعددة مع نفس السلسلة، فإن الأقدم له الأولوية. هناك قاعدتان خاصتان: القاعدة الافتراضية * وقاعدة نهاية الإدخال $. يجب تعريف القاعدة الافتراضية دائمًا، ولها أقل أولوية بغض النظر عن مكانها في الكتلة، وتتطابق مع أي وحدة رمز (ليس بالضرورة حرفًا صالحًا، انظر قسم دعم الترميز). يجب تعريف قاعدة نهاية الإدخال إذا تم استخدام الطريقة المقابلة لـ معالجة نهاية الإدخال. مع شروط البدء، تكون للقواعد بناء جملة أكثر تعقيدًا.
!إجراء تعليمات برمجية
إجراء يربط كتلة تعليمات برمجية معرفة من قبل المستخدم بمكان معين في الآلة الحتمية المحدودة المولدة (بنفس الطريقة التي تربط بها الإجراءات الدلالية التعليمات البرمجية بالحالات النهائية). راجع قسم الإجراءات للحصول على قائمة كاملة بالإجراءات المعرفة مسبقًا.
!توجيه ;
توجيه هو أحد البيانات المعرفة مسبقًا الخاصة. كل توجيه له غرض فريد. راجع قسم التوجيهات للحصول على التفاصيل.

الكتل

علامات بداية ونهاية الكتلة هي إما /*!re2c و */، أو %{ و %} (كلا النمطين مدعومان). بدءًا من الإصدار 2.2، يمكن أن يكون للكتل أسماء اختيارية تسمح بالإشارة إليها في كتل أخرى. هناك أنواع مختلفة من الكتل:

/*!re2c[:<name>] ... */ أو %{[:<name>] ... %}
تحتوي الكتلة العامة على تعريفات وتكوينات وقواعد وتوجيهات. يقوم re2v بتجميع التعبيرات النمطية المرتبطة بكل قاعدة في آلة حالات محدودة حتمية، ويقوم بتشفيرها في شكل قفزات شرطية بلغة الهدف ويستبدل الكتلة بالتعليمات البرمجية المولدة. تصبح الأسماء والتكوينات المعرفة في كتلة عامة جزءًا من النطاق العام وتصبح مرئية للكتل اللاحقة. في بداية البرنامج، يتم تهيئة النطاق العام بالخيارات الموجودة في سطر الأوامر.
/*!local:re2c[:<name>] ... */ أو %{local[:<name>] ... %}
الكتلة المحلية تشبه الكتلة العامة، ولكن الأسماء والتكوينات فيها لها نطاق محلي (لا تؤثر على الكتل الأخرى).
/*!rules:re2c[:<name>] ... */ أو %{rules[:<name>] ... %}
كتلة القواعد تشبه الكتلة المحلية، ولكنها لا تولد أي تعليمات برمجية بنفسها، ولا تضيف أي تعريفات إلى النطاق العام - فهي مخصصة لإعادة استخدامها في كتل أخرى. هذه طريقة لمشاركة التعليمات البرمجية (مزيد من التفاصيل في قسم الكتل القابلة لإعادة الاستخدام). قبل الإصدار 2.2 من re2v، كانت كتل القواعد تتطلب خيار -r --reusable.
/*!use:re2c[:<name>] ... */ أو %{use[:<name>] ... %}
كتلة استخدام تشير إلى كتلة قواعد معرفة مسبقًا. إذا تم تحديد الاسم، يبحث re2v عن كتل قواعد بهذا الاسم. بخلاف ذلك، يتم استخدام أحدث كتلة قواعد (سواء كانت مسماة أو غير مسماة). يمكن لكتلة الاستخدام إضافة تعريفات وتكوينات وقواعد خاصة بها، والتي تضاف إلى تلك الخاصة بكتلة القواعد المشار إليها. قبل الإصدار 2.2 من re2v، كانت كتل الاستخدام تتطلب خيار -r --reusable.
/*!max:re2c[:<name1>[:<name2>...]] ... */ أو %{max[:<name1>[:<name2>...]] ... %}
كتلة تولد تعريف YYMAXFILL. تحدد قائمة اختيارية من أسماء الكتل أي الكتل يجب تضمينها عند حساب قيمة YYMAXFILL (إذا كانت القائمة فارغة، يتم تضمين جميع الكتل). افتراضيًا، تكون التعليمات البرمجية المولدة عبارة عن تعريف ماكرو لـ C (#define YYMAXFILL <n>)، أو متغير عام لـ Go (var YYMAXFILL int = <n>). يمكن تخصيصها بتكوين اختياري format يحدد قالب سلسلة نصية حيث يتم استبدال @@{max} (أو @@ باختصار) بالقيمة الرقمية لـ YYMAXFILL.

الإجراءات

Here is a list of predefined actions supported by re2v:

!entry code
Entry action binds a user-defined block of code to the start state of the current finite state machine. If start conditions are used, the entry action can be set individually for each condition. This action may be used to perform initialization, e.g. to save start location of a lexeme.
!pre_rule code
Pre-rule action prepends a user-defined block of code to semantic actions of all rules in the current block (or condition, if start conditions are used). This action may be used to factor out the common part of all semantic actions (e.g. saving the end location of a lexeme).
!post_rule code
Post-rule action appends a user-defined block of code to semantic actions of all rules in the current block (or condition, if start conditions are used). This action may be used to emit trap statements that guard against unintended control flow.

التوجيهات

Here is a full list of directives supported by re2v:

!use:name ;
An in-block use directive that merges a previously defined rules block with the specified name into the current block. Named definitions, configurations and rules of the referenced block are added to the current ones. Conflicts between overlapping rules and configurations are resolved in the usual way: the first rule takes priority, and the latest configuration overrides the preceding ones. One exception is the special rules *, $ and <!> for which a block-local definition always takes priority. A use directive can be placed anywhere inside of a block, and multiple use directives are allowed.
!include file ;
This directive is the same as include block: it inserts file contents verbatim in place of the directive.

واجهة البرنامج

The generated code interfaces with the outer program with the help of primitives, collectively referred to as the API. Which primitives should be defined for a particular program depends on multiple factors, including the complexity of regular expressions, input representation, buffering and the use of various features. All the necessary primitives should be defined by the user in the form of macros, functions, variables or any other suitable form that makes the generated code syntactically and semantically correct. re2v does not (and cannot) check the definitions, so if anything is missing or defined incorrectly, the generated program may have compile-time or run-time errors. This manual provides examples of API definitions in the most common cases.

re2v has three API flavors that define the core set of primitives used by a program:

Simple API
This is the default API for the V backend. It consists of the following primitives: YYINPUT (which should be defined as a sequence of code units, e.g. a string) and YYCURSOR, YYMARKER, YYCTXMARKER, YYLIMIT (which should be defined as indices in YYINPUT).
Record API
Record API is useful in cases when lexer state must be stored in a struct. It is enabled with --api record option or re2c:api = record configuration. This API consists of a variable yyrecord (the name can be overridden with re2c:yyrecord) that should be defined as a struct with fields yyinput, yycursor, yymarker, yyctxmarker, yylimit (only the fields used by the generated code need to be defined, and their names can be configured).
Generic API
This is the most flexible API. It is enabled with --api generic option or re2c:api = generic configuration. It contains primitives for generic operations: YYPEEK, YYSKIP, YYBACKUP, YYBACKUPCTX, YYSTAGP, YYSTAGN, YYMTAGP, YYMTAGN, YYRESTORE, YYRESTORECTX, YYRESTORETAG, YYSHIFT, YYSHIFTSTAG, YYSHIFTMTAG, YYLESSTHAN.

Here is a full list of API primitives that may be used by the generated code in order to interface with the outer program.

YYCTYPE
The type of the input characters (code units). For ASCII, EBCDIC and UTF-8 encodings it should be 1-byte unsigned integer. For UTF-16 or UCS-2 it should be 2-byte unsigned integer. For UTF-32 it should be 4-byte unsigned integer.
YYCURSOR
An l-value that stores the current input position (a pointer or an integer offset in YYINPUT). Initially YYCURSOR should point to the first input character, and later it is advanced by the generated code. When a rule matches, YYCURSOR position is the one after the last matched character.
YYLIMIT
An r-value that stores the end of input position (a pointer or an integer offset in YYINPUT). Initially YYLIMIT should point to the position after the last available input character. It is not changed by the generated code. The lexer compares YYCURSOR to YYLIMIT in order to determine if there are enough input characters left.
YYMARKER
An l-value that stores the position of the latest matched rule (a pointer or an integer offset in YYINPUT). It is used to restore the YYCURSOR position if the longer match fails and the lexer needs to rollback. Initialization is not needed.
YYCTXMARKER
An l-value that stores the position of the trailing context (a pointer or an integer offset in YYINPUT). No initialization is needed. YYCTXMARKER is needed only if the lookahead operator / is used.
YYFILL
A generic API primitive with one variable len. YYFILL should provide at least len more input characters or fail. If re2c:eof is used, then len is always 1 and YYFILL should always return to the calling function; zero return value indicates success. If re2c:eof is not used, then YYFILL return value is ignored and it should not return on failure. The maximum value of len is YYMAXFILL.
YYFN
A primitive that defines function prototype in --recursive-functions code model. Its value should be an array of one or more strings, where each string contains two or three components separated by the string specified in re2c:fn:sep configuration (typically a semicolon). The first array element defines function name and return type (empty for a void function). Subsequent elements define function arguments: first, the expression for the argument used in function body (usually just a name); second, argument type; third, an optional formal parameter (it defaults to the first component - usually both the argument and the parameter are the same identifier).
YYINPUT
An r-value that stores the current input character sequence (string, buffer, etc.).
YYMAXFILL
An integral constant equal to the maximum value of the argument to YYFILL. It can be generated with a max block.
YYLESSTHAN
A generic API primitive with one variable len. It should be
defined على أنها قيمة r من النوع المنطقي تساوي true إذا وفقط إذا كان هناك أقل من len أحرف إدخال متبقية.
YYPEEK
بدائية واجهة برمجة تطبيقات عامة بدون متغيرات. يجب تعريفها على أنها قيمة r من النوع YYCTYPE تساوي الحرف الموجود في موضع الإدخال الحالي.
YYSKIP
بدائية واجهة برمجة تطبيقات عامة يجب أن تقدم موضع الإدخال الحالي بمقدار وحدة كود واحدة.
YYBACKUP
بدائية واجهة برمجة تطبيقات عامة يجب أن تحفظ موضع الإدخال الحالي (ليتم استعادته باستخدام YYRESTORE لاحقًا).
YYRESTORE
بدائية واجهة برمجة تطبيقات عامة يجب أن تستعيد موضع الإدخال الحالي إلى القيمة المحفوظة بواسطة YYBACKUP.
YYBACKUPCTX
بدائية واجهة برمجة تطبيقات عامة يجب أن تحفظ موضع الإدخال الحالي كموضع للسياق اللاحق (ليتم استعادته باستخدام YYRESTORECTX لاحقًا).
YYRESTORECTX
بدائية واجهة برمجة تطبيقات عامة يجب أن تستعيد موضع السياق اللاحق المحفوظ بواسطة YYBACKUPCTX.
YYRESTORETAG
بدائية واجهة برمجة تطبيقات عامة مع متغير واحد tag يجب أن تستعيد موضع السياق اللاحق إلى قيمة tag.
YYSTAGP
بدائية واجهة برمجة تطبيقات عامة مع متغير واحد tag، حيث يمكن أن يكون tag مؤشرًا أو إزاحة في YYINPUT (راجع قسم استخراج المطابقة الفرعية للتفاصيل). يجب أن تقوم YYSTAGP بتعيين tag إلى موضع الإدخال الحالي.
YYSTAGN
بدائية واجهة برمجة تطبيقات عامة مع متغير واحد tag، حيث يمكن أن يكون tag مؤشرًا أو إزاحة في YYINPUT (راجع قسم استخراج المطابقة الفرعية للتفاصيل). يجب أن تقوم YYSTAGN بتعيين tag إلى قيمة تمثل موضع إدخال غير موجود.
YYMTAGP
بدائية واجهة برمجة تطبيقات عامة مع متغير واحد tag. يجب أن تقوم YYMTAGP بإلحاق الموضع الحالي بسجل المطابقة الفرعية لـ tag (راجع قسم استخراج المطابقة الفرعية للتفاصيل).
YYMTAGN
بدائية واجهة برمجة تطبيقات عامة مع متغير واحد tag. يجب أن تقوم YYMTAGN بإلحاق قيمة تمثل موضع إدخال غير موجود بسجل المطابقة الفرعية لـ tag (راجع قسم استخراج المطابقة الفرعية للتفاصيل).
YYSHIFT
بدائية واجهة برمجة تطبيقات عامة مع متغير واحد shift يجب أن تقوم بإزاحة موضع الإدخال الحالي بمقدار shift حرف (قد تكون قيمة الإزاحة سالبة).
YYCOPYSTAG
بدائية واجهة برمجة تطبيقات عامة مع متغيرين، lhs و rhs، يجب أن تقوم بنسخ متغير العلامة s الأيمن rhs إلى متغير العلامة s الأيسر lhs. بالنسبة لمعظم اللغات، تحتوي هذه البدائية على تعريف افتراضي يعين lhs إلى rhs.
YYCOPYMTAG
بدائية واجهة برمجة تطبيقات عامة مع متغيرين، lhs و rhs، يجب أن تقوم بنسخ متغير العلامة m الأيمن rhs إلى متغير العلامة m الأيسر lhs. بالنسبة لمعظم اللغات، تحتوي هذه البدائية على تعريف افتراضي يعين lhs إلى rhs.
YYSHIFTSTAG
بدائية واجهة برمجة تطبيقات عامة مع متغيرين، tag و shift، يجب أن تقوم بإزاحة tag بمقدار shift وحدة كود (قد تكون قيمة الإزاحة سالبة).
YYSHIFTMTAG
بدائية واجهة برمجة تطبيقات عامة مع متغيرين، tag و shift، يجب أن تقوم بإزاحة أحدث قيمة في سجل tag بمقدار shift وحدة كود (قد تكون قيمة الإزاحة سالبة).
YYMAXNMATCH
ثابت صحيح يساوي العدد الأقصى لمجموعات الالتقاط POSIX في قاعدة. يتم إنشاؤه باستخدام كتلة maxnmatch.
YYCONDTYPE
نوع تعداد الشرط. يمكن إنشاؤه إما باستخدام كتلة conditions أو خيار --header.
YYGETACCEPT
بدائية مع متغير واحد var يخزن المحدد الرقمي للقاعدة المقبولة. بالنسبة لمعظم اللغات، تحتوي هذه البدائية على تعريف افتراضي يقرأ من var.
YYSETACCEPT
بدائية مع متغيرين: var (قيمة l تخزن المحدد الرقمي للقاعدة المقبولة)، و val (قيمة المحدد). بالنسبة لمعظم اللغات، تحتوي هذه البدائية على تعريف افتراضي يعين var إلى val.
YYGETCOND
قيمة r من النوع YYCONDTYPE تساوي معرف الشرط الحالي.
YYSETCOND
بدائية مع متغير واحد cond يجب أن تقوم بتعيين معرف الشرط الحالي إلى cond.
YYGETSTATE
قيمة r من نوع صحيح تساوي حالة المحلل اللغوي الحالية. يجب تهيئتها إلى -1.
YYSETSTATE
بدائية مع متغير واحد state يجب أن تقوم بتعيين حالة المحلل اللغوي الحالية إلى state.
YYDEBUG
يتم إنشاء هذه البدائية فقط باستخدام الخيار -d، --debug-output. الغرض منها هو إضافة تسجيل إلى الكود المنشأ (عادةً ما يكون تعريف YYDEBUG عبارة عن طباعة). يتم إنشاء عبارات YYDEBUG في كل حالة ولها متغيران: state (إما فهرس حالة DFA أو -1) و symbol (رمز الإدخال الحالي).
yyaccept
قيمة l من نوع صحيح غير موقع يخزن رقم آخر قاعدة تمت مطابقتها. لا يلزم تعريف المستخدم إلا مع خيار --storable-state.
yybm
جدول يحتوي على خرائط بت مضغوطة لما يصل إلى 8 انتقالات (تستخدم مع خيار --bitmaps). يحتوي الجدول على 256 عنصرًا ويتم فهرسته بواسطة وحدات كود بحجم 1 بايت. كل عنصر مكون من 8 بت يجمع القيم المنطقية لما يصل إلى 8 انتقالات. يكون البت k للعنصر n صحيحًا إذا كان وحدة الكود n في نطاق الانتقال k. الفكرة وراء خريطة البت هذه هي استبدال العديد من فروع if أو حالات switch بفحص واحد لبت واحد في الجدول.
yych
قيمة l من النوع YYCTYPE تخزن حرف الإدخال الحالي. لا يلزم تعريف المستخدم إلا مع خيار -f --storable-state.
yyctable
جدول قفز تم إنشاؤه للتوزيع المبدئي للحالة (تم تمكينه باستخدام مزيج من خيارات --conditions و --computed-gotos).
yyfill
قيمة l تخزن نتيجة استدعاء YYFILL (قد يكون هذا ضروريًا للغات الوظيفية النقية، حيث YYFILL عبارة عن دالة رتيبة ذات قيمة إرجاع معقدة).
yynmatch
قيمة l من نوع صحيح غير موقع تخزن عدد مجموعات الالتقاط POSIX في القاعدة المطابقة. تستخدم فقط مع خيار -P --posix-captures.
yypmatch
مصفوفة من قيم l تستخدم للاحتفاظ بقيم العلامات المقابلة لأقواس الالتقاط في القاعدة المطابقة. يجب أن يكون طول المصفوفة على الأقل yynmatch * 2 (عادةً ما يكون YYMAXNMATCH * 2 خيارًا جيدًا). تستخدم فقط مع خيار -P --posix-captures.
yystable
تم إيقافه.
yystate
قيمة l تستخدم مع خيار --loop-switch لتخزين حالة DFA الحالية.
yytarget
جدول قفز يحتوي على أهداف القفز (عناوين الملصقات) لجميع الانتقالات من حالة. هذا الجدول خاص بكل حالة. تم تمكين إنشاء جداول yytarget باستخدام خيار --computed-gotos.

خيارات

بعض الخيارات لها تكوينات مقابلة، بينما البعض الآخر عام ولا يمكن تغييره بعد بدء re2c في قراءة ملف الإدخال. تتطلب خيارات التصحيح عادةً بناء re2c في تكوين تصحيح. الخيارات الداخلية مفيدة لتجربة الخوارزميات المستخدمة في re2c.

-? --help -h
عرض رسالة المساعدة.
--api <simple | record | generic>
تحديد واجهة برمجة التطبيقات المستخدمة بواسطة الكود المنشأ للتفاعل مع الكود المحدد من قبل المستخدم. يجب استخدام خيار simple في الحالات البسيطة عندما لا تكون هناك حاجة لإعادة تعبئة المخزن المؤقت وتخزين حالة المحلل اللغوي. يجب استخدام خيار record عندما تحتاج حالة المحلل اللغوي إلى تخزينها في سجل (هيكل، فئة، إلخ). يجب استخدام خيار generic في الحالات المعقدة عندما لا تكون واجهات برمجة التطبيقات الأخرى مرنة بما فيه الكفاية.
--bit-vectors -b
تحسين القفزات الشرطية باستخدام أقنعة البت. يتضمن هذا الخيار --nested-ifs.
--captures, --leftmost-captures
تمكين استخراج المطابقة الفرعية مع مجموعات الالتقاط اليمنى الأكثر يسارًا. يتم تجميع النتيجة في مصفوفة yybmatch بسعة 2 * YYMAXNMATCH، ويتم تعيين yynmatch لعدد المجموعات للقاعدة المطابقة.
--captvars< e التعارض مع القواعد الأخرى، ولكن بعد إدخال رمز نهاية الإدخال العام $ سيتغير ترتيب الأسبقية وستصبح هذه القواعد مموهة بواسطة قواعد أخرى.
-Wuseless-escape
تحذير إذا تم الهروب من رمز عندما لا ينبغي. افتراضيًا، يتجاهل re2v مثل هذه الهروب بصمت، ولكن هذا قد يشير أيضًا إلى خطأ إملائي أو خطأ في تسلسل الهروب.
-Wnondeterministic-tags
تحذير إذا كان للعلامة درجة n من عدم الحتمية، حيث n أكبر من 1.
-Wsentinel-in-midrule
تحذير إذا ظهر رمز الحارس في منتصف القاعدة --- قد يتسبب ذلك في قراءات تتجاوز نهاية المخزن المؤقت، أو تعطل، أو تلف في الذاكرة في المحلل اللغوي الذي تم إنشاؤه. هذا التحذير ينطبق فقط إذا تم استخدام طريقة الحارس للتحقق من نهاية الإدخال. يتم تعيينه كخطأ إذا تم استخدام تهيئة re2c:sentinel.
-Wundefined-syntax-config
تحذير إذا كان ملف الصيغة المحدد بالخيار --syntax يفتقر إلى تعريفات لبعض التكوينات. هذا يساعد في صيانة ملفات الصيغة المعرفة من قبل المستخدم: إذا أضاف إصدار جديد تكوينات، فسيرفع ملف الصيغة القديم تحذيرًا، وسيتم إخطار المستخدم. إذا كانت بعض التكوينات غير مستخدمة ولا تحتاج إلى تعريف، فيجب تعيينها صراحةً على <undefined>.

ملفات الصيغة

يعتمد دعم اللغات المختلفة في re2c على فكرة ملفات الصيغة. ملف الصيغة هو ملف تهيئة يحدد صيغة اللغة المستهدفة -- وليس اللغة بأكملها، بل جزء صغير منها يستخدمه الرمز الذي تم إنشاؤه. تجعل ملفات الصيغة re2c مرنة للغاية، ولكن لا ينبغي استخدامها كبديل لتهيئة re2c: : الغرض منها هو تحديد صيغة اللغة المستهدفة، وليس تخصيص محلل لغوي واحد معين. جميع اللغات المدعومة لديها ملفات صيغة افتراضية تشكل جزءًا من التوزيع (انظر الدليل الفرعي include/syntax)؛ وهي مضمنة أيضًا في الثنائي re2v. يمكن للمستخدمين تقديم ملف صيغة مخصص يتجاوز عددًا قليلاً من التهيئة للغة واحدة مدعومة، أو قد يختارون إعادة تعريف جميع التهيئة (في هذه الحالة، يجب استخدام الخيار --lang none). تحتوي ملفات الصيغة على تهيئةات من أربعة أنواع مختلفة: قوائم الميزات، وتهيئةات اللغة، وتهيئةات موضعية، وقوالب الكود.

قوائم الميزات

تحدد عدد قليل من تهيئةات القوائم ميزات مختلفة تدعمها الواجهة الخلفية المعطاة، حتى يتمكن re2v من إعطاء خطأ واضح إذا حاول المستخدم تمكين ميزة غير مدعومة:
supported_apis
قائمة بواجهات برمجة التطبيقات المدعومة مع عناصر محتملة simple، record، generic.
supported_api_styles
قائمة بأنماط واجهات برمجة التطبيقات المدعومة مع عناصر محتملة functions، free-form.
supported_code_models
قائمة بنماذج الكود المدعومة مع عناصر محتملة goto-label، loop-switch، recursive-functions.
supported_targets
قائمة بأهداف توليد الكود المدعومة مع عناصر محتملة code، dot، skeleton.
supported_features
قائمة بالميزات المدعومة مع عناصر محتملة nested-ifs، bitmaps، computed-gotos، case-ranges، monadic، unsafe، tags، captures، captvars.

تهيئةات موضعية

تحدد ملفات الصيغة القيم الأولية لجميع تهيئةات re2c: ، حيث يمكن أن تختلف بالنسبة للغات المختلفة. انظر قسم التهيئةات للحصول على قائمة كاملة بجميع التهيئةات الموضعية ومعناها.

قوالب الكود

تحدد قوالب الكود صيغة اللغة المستهدفة. وهي مكتوبة بلغة بسيطة خاصة بالمجال بالنحو الرسمي التالي: 
code-template ::
      name '=' code-exprs ';'
    | CODE_TEMPLATE ';'
    | '<undefined>' ';'
code-exprs ::
      <EMPTY>
    | code-exprs code-expr
code-expr ::
      STRING
    | VARIABLE
    | optional
    | list
optional ::
      '(' CONDITIONAL '?' code-exprs ')'
    | '(' CONDITIONAL '?' code-exprs ':' code-exprs ')'
list ::
      '[' VARIABLE ':' code-exprs ']'
    | '[' VARIABLE '{' NUMBER '}' ':' code-exprs ']'
    | '[' VARIABLE '{' NUMBER ',' NUMBER '}' ':' code-exprs ']'

قالب الكود هو تسلسل من السلاسل الحرفية، والمتغيرات، والعناصر الاختيارية والقوائم، أو إشارة إلى قالب كود آخر، أو القيمة الخاصة <undefined>. المتغيرات هي عناصر نائبة يتم استبدالها أثناء مرحلة توليد الكود. متغيرات القائمة خاصة: عند توسيع قوالب القائمة، يكرر re2v تعبيرات الجانب الأيمن من العمود عدة مرات، في كل مرة يستبدل فيها تكرارات متغير القائمة بقيمة خاصة بهذه التكرارات. تحتوي القوائم على حدود اختيارية (القيم السالبة يتم عدها من النهاية، على سبيل المثال، -1 يعني العنصر الأخير). تبدأ أسماء الشروط بنقطة. يمكن أن تكون كل من الشروط والمتغيرات محلية (خاصة بقالب الكود المحدد) أو عامة (مسموح بها في جميع قوالب الكود). عند قراءة re2v لملف الصيغة، فإنه يتحقق من أن كل قالب كود يستخدم فقط المتغيرات والشروط المسموح بها فيه.

على سبيل المثال، يحدد قالب الكود التالي بنية if-then-else للغة شبيهة بلغة C:

code:if_then_else =
    [branch{0}: topindent "if " cond " {" nl
        indent [stmt: stmt] dedent]
    [branch{1:-1}: topindent "} else" (.cond ? " if " cond) " {" nl
        indent [stmt: stmt] dedent]
    topindent "}" nl;

هنا branch هو متغير قائمة: branch{0} يتوسع إلى الفرع الأول (وهو خاص، لأنه لا يوجد جزء else)، branch{1:-1} يتوسع إلى جميع الفروع المتبقية (إن وجدت). stmt هو أيضًا متغير قائمة: [stmt: stmt] هي قائمة متداخلة تتوسع إلى قائمة عبارات في جسم الفرع الحالي. topindent، indent، dedent، و nl هي متغيرات عامة، و .cond هو شرط محلي (معناها موضح أدناه). يمكن أن ينتج قالب الكود هذا الكود التالي:

if x {
    // do something
} else if y {
    // do something else
} else {
    // don't do anything
}

إليك قائمة بجميع قوالب الكود التي يدعمها re2v مع متغيراتها المحلية والشروط الخاصة بها. لاحظ أن تعريفًا معينًا قد يستخدم، ولكن لا يجب عليه، المتغيرات والشروط المحلية. يجب تعيين أي قوالب كود غير مستخدمة إلى <undefined>.

code:var_local
إعلان أو تعريف متغير محلي. المتغيرات المدعومة: type (نوع المتغير)، name (اسمه)، و init (القيمة الأولية، إن وجدت). الشروط: .init (صحيح إذا كان هناك مُهيئ).
code:var_global
نفس code:var_local، باستثناء أنه يستخدم على المستوى الأعلى.
code:const_local
تعريف ثابت محلي. المتغيرات المدعومة: type (نوع الثابت)، name (اسمه)، و init (القيمة الأولية).

معالجة نهاية الإدخال

إحدى المشاكل الرئيسية للمحلل المعجمي هي معرفة متى يجب التوقف. هناك بعض شروط الإنهاء:

  • قد يطابق المحلل المعجمي بعض القواعد (بما في ذلك القاعدة الافتراضية *) ويصل إلى حالة نهائية
  • قد يفشل المحلل المعجمي في مطابقة أي قاعدة ويصل إلى حالة افتراضية
  • قد يصل المحلل المعجمي إلى نهاية الإدخال

الشرطان الأولان ينهيان المحلل المعجمي بطريقة "طبيعية": يصل إلى حالة بدون انتقالات خارجية، ويتوقف المطابقة تلقائيًا. الشرط الثالث، نهاية الإدخال، مختلف: قد يحدث في أي حالة، ويجب أن يكون المحلل المعجمي قادرًا على التعامل معه. يقطع التحقق من نهاية الإدخال سير عمل المحلل المعجمي العادي ويضيف فروعًا شرطية إلى البرنامج المولّد، لذلك من الضروري تقليل عدد هذه الشيكات. يدعم re2v عددًا قليلاً من الطرق المختلفة لمعالجة نهاية الإدخال. يعتمد اختيار الطريقة على مدى تعقيد التعبيرات العادية، والحاجة إلى التخزين المؤقت، واعتبارات الأداء، وعوامل أخرى. فيما يلي قائمة بالطرق:

  • العلامة الدالة (Sentinel). تلغي هذه الطريقة الحاجة إلى شيكات نهاية الإدخال تمامًا. إنها بسيطة وفعالة، ولكنها تقتصر على الحالة التي توجد فيها "علامة دالة" طبيعية لا يمكن أن تظهر أبدًا في الإدخال الصالح. قد تظهر هذه العلامة في الإدخال غير الصالح، ولكن لا ينبغي السماح بها بواسطة التعبيرات العادية، إلا ربما كآخر حرف في القاعدة. تتم إضافة العلامة الدالة في نهاية الإدخال وتعمل كإشارة توقف: عندما يقرأ المحلل المعجمي هذه العلامة، فهي إما خطأ في بناء الجملة أو نهاية الإدخال. في كلتا الحالتين يجب على المحلل المعجمي التوقف. تُستخدم هذه الطريقة إذا تم تعطيل YYFILL باستخدام re2c:yyfill:enable = 0; وكان re2c:eof له القيمة الافتراضية -1.
  • العلامة الدالة مع شيكات الحدود. هذه الطريقة عامة: تسمح بمعالجة أي إدخال بدون قيود على التعبيرات العادية. الفكرة هي تقليل عدد شيكات نهاية الإدخال عن طريق إجرائها فقط على أحرف معينة. على غرار طريقة "العلامة الدالة"، يتم اختيار أحد الأحرف كـ "علامة دالة" ويتم إلحاقه بنهاية الإدخال. ومع ذلك، لا يوجد قيود على مكان ظهور العلامة الدالة (في الواقع، يمكن اختيار أي حرف كعلامة دالة). عندما يقرأ المحلل المعجمي هذا الحرف، يقوم بالإضافة إلى ذلك بإجراء شيك حدود. إذا كان الموضع الحالي ضمن الحدود، يستأنف المحلل المعجمي المطابقة ويتعامل مع العلامة الدالة كحرف عادي. وإلا فإنه يستدعي YYFILL (ما لم يتم تعطيله). إذا تم توفير المزيد من الإدخال، فسيقوم المحلل المعجمي بإعادة مطابقة الحرف الأخير والاستمرار كما لو لم تكن العلامة الدالة موجودة. وإلا فيجب أن تكون نهاية الإدخال الحقيقية، ويتوقف المحلل المعجمي. تُستخدم هذه الطريقة عندما يكون لـ re2c:eof قيمة غير سالبة (يجب تعيينها إلى القيمة الرقمية للعلامة الدالة). YYFILL اختياري.
  • شيكات الحدود مع الحشو. هذه الطريقة عامة، وقد تكون أسرع من طريقة "العلامة الدالة مع شيكات الحدود"، ولكنها أيضًا أكثر تعقيدًا. الفكرة هي تقسيم حالات DFA إلى مكونات متصلة بقوة (SCCs) وإنشاء شيك واحد لكل SCC لعدد كافٍ من الأحرف لتغطية أطول مسار غير حلقي في هذا SCC. يؤدي هذا إلى تقليل عدد الشيكات، ولكن هناك مشكلة مع الوحدات المعجمية القصيرة في نهاية الإدخال، حيث يتطلب الشيك أحرفًا كافية لتغطية أطول وحدة معجمية. يمكن إصلاح ذلك عن طريق حشو الإدخال ببضعة أحرف وهمية لا تشكل لاحقة وحدة معجمية صالحة (بحيث لا يمكن للمحلل المعجمي مطابقتها). يجب أن يكون طول الحشو YYMAXFILL، ويتم إنشاؤه باستخدام كتلة max. إذا لم يكن هناك إدخال كافٍ، فإن المحلل المعجمي يستدعي YYFILL الذي يجب أن يوفر على الأقل العدد المطلوب من الأحرف أو لا يعود. تُستخدم هذه الطريقة إذا تم تمكين YYFILL وكان re2c:eof هو -1 (هذا هو التكوين الافتراضي).
  • شيكات مخصصة. تتيح واجهة برمجة التطبيقات العامة (API) تجاوز العمليات الأساسية مثل قراءة حرف، مما يجعل من الممكن تضمين شيكات نهاية الإدخال كجزء منها. هذا النهج معرض للأخطاء ويجب استخدامه بحذر. لاستخدام طريقة مخصصة، قم بتمكين واجهة برمجة التطبيقات العامة (API) باستخدام --api custom أو re2c:api = custom; وعطّل شيكات الحدود الافتراضية باستخدام re2c:yyfill:enable = 0; أو re2c:yyfill:check = 0;.

تحتوي الأقسام الفرعية التالية على مثال لكل طريقة.

العلامة الدالة

يستخدم هذا المثال علامة دالة لمعالجة نهاية الإدخال. يحسب البرنامج الكلمات المفصولة بمسافات في سلسلة نصية منتهية بصفر. العلامة الدالة هي صفر: وهي الحرف الأخير في كل سلسلة إدخال، ولا يُسمح بها في منتصف وحدة معجمية بواسطة أي من القواعد (على وجه الخصوص، لم يتم تضمينها في نطاقات الأحرف حيث يسهل إغفالها). إذا ظهر صفر في منتصف سلسلة، فهذا خطأ في بناء الجملة وسيطابق المحلل المعجمي القاعدة الافتراضية *، ولكنه لن يقرأ ما وراء نهاية الإدخال أو يتعطل (استخدم تحذير -Wsentinel-in-midrule وتكوين re2c:sentinel للتحقق من ذلك). يقوم التكوين re2c:yyfill:enable = 0; بقمع إنشاء شيكات الحدود واستدعاءات YYFILL.

// re2v $INPUT -o $OUTPUT
// يتوقع سلسلة نصية منتهية بصفر.
fn lex(yyinput string) int {
    mut yycursor := 0
    mut count := 0
loop: /*!re2c
    re2c:yyfill:enable = 0;
    *      { return -1 }
    [\x00] { return count }
    [a-z]+ { count += 1; unsafe { goto loop } }
    [ ]+   {  unsafe { goto loop } }
    */
}
fn main() {
    assert lex("\0") == 0
    assert lex("one two three\0") == 3
    assert lex("f0ur\0") == -1
}

العلامة الدالة مع شيكات الحدود

يستخدم هذا المثال علامة دالة مع شيكات حدود لمعالجة نهاية الإدخال (تمت إضافة هذه الطريقة في الإصدار 1.2). يحسب البرنامج السلاسل النصية المفصولة بمسافات والمحاطة بعلامات اقتباس فردية. العلامة الدالة هي صفر، والتي يتم تحديدها باستخدام تكوين re2c:eof = 0;. كما هو الحال في طريقة العلامة الدالة، فإن الصفر هو الحرف الأخير في كل سلسلة إدخال، ولكن يُسمح به في منتصف القاعدة (على سبيل المثال، 'aaa\0aa'\0 هو إدخال صالح، ولكن 'aaa\0 خطأ في بناء الجملة). يتم إنشاء شيكات الحدود في كل حالة تطابق حرف إدخال، ولكنها مقصورة على الفرع الذي يعالج الصفر. شيكات الحدود تكون على شكل YYLIMIT <= YYCURSOR أو YYLESSTHAN(1) مع واجهة برمجة تطبيقات عامة. إذا كان شرط الشيك صحيحًا، فقد وصل المحلل المعجمي إلى نهاية الإدخال ويجب أن يتوقف (تم تعطيل YYFILL باستخدام re2c:yyfill:enable = 0; حيث يتناسب الإدخال مع مخزن مؤقت واحد، انظر قسم YYFILL مع العلامة الدالة للحصول على مثال يستخدم YYFILL). الوصول إلى نهاية الإدخال يفتح ثلاث احتمالات: إذا كان المحلل المعجمي في الحالة الأولية، فسيطابق قاعدة نهاية الإدخال $، وإلا فقد يعود إلى قاعدة مطابقة سابقة (بما في ذلك القاعدة الافتراضية *) أو ينتقل إلى حالة افتراضية، مما يتسبب في -Wundefined-control-flow.

// re2v $INPUT -o $OUTPUT
// يتوقع سلسلة نصية منتهية بصفر.
fn lex(yyinput string) int {
    mut yycursor, mut yymarker := 0, 0
    yylimit := yyinput.len - 1 // yylimit يشير إلى الصفر المنتهي
    mut count := 0
loop: /*!re2c
    re2c:eof = 0;
    re2c:yyfill:enable = 0;
    str = ['] ([^'\\] | [\\][^])* ['];
    *    { return -1 }
    $    { return count }
    str  { count += 1; unsafe { goto loop } }
    [ ]+ { unsafe { goto loop } }
    */
}
fn main() {
    assert lex("\0") == 0
    assert lex("'qu\0tes' 'are' 'fine: \\'' \0") == 3
    assert lex("'unterminated\\'\0") == -1
}

شيكات الحدود مع الحشو

يستخدم هذا المثال شيكات الحدود مع الحشو لمعالجة نهاية الإدخال (هذه الطريقة ممكّنة افتراضيًا). يحسب البرنامج السلاسل النصية المفصولة بمسافات والمحاطة بعلامات اقتباس فردية. يوجد حشو من أحرف صفر YYMAXFILL مضاف في نهاية الإدخال، حيث يتم إنشاء قيمة YYMAXFILL تلقائيًا باستخدام كتلة max. ليس من الضروري استخدام الصفر للحشو --- يمكن استخدام أي أحرف طالما أنها لا تشكل لاحقة وحدة معجمية صالحة (في هذا المثال، يجب ألا يحتوي الحشو على علامات اقتباس فردية، لأنها قد تُعتبر لاحقة لسلسلة محاطة بعلامات اقتباس فردية). توجد قاعدة "توقف" تطابق أول حرف حشو (صفر) وتنهي المحلل المعجمي (لاحظ أنها تتحقق مما إذا كان الصفر في بداية الحشو، وإلا فهو خطأ في بناء الجملة). يتم إنشاء شيكات الحدود فقط في بعض الحالات التي يحددها المكونات المتصلة بقوة للآلة الأساسية. الشيكات تكون على شكل (YYLIMIT - YYCURSOR) < n أو YYLESSTHAN(n) مع واجهة برمجة تطبيقات عامة

، حيث n هو الحد الأدنى لعدد الأحرف المطلوبة لمواصلة محلل المفردات (ويعني أيضًا أن الفحص التالي للحدود سيحدث في بحد أقصى n من الأحرف). إذا كان شرط الفحص صحيحًا، فقد وصل محلل المفردات إلى نهاية الإدخال وسيقوم باستدعاء YYFILL(n) الذي يجب أن يوفر على الأقل n من أحرف الإدخال أو لا يعود. في هذا المثال، تفشل YYFILL دائمًا وتنهي محلل المفردات بخطأ (وهو أمر جيد لأن الإدخال يناسب مخزنًا مؤقتًا واحدًا). انظر قسم YYFILL مع الحشو للحصول على مثال يعيد ملء مخزن الإدخال المؤقت باستخدام YYFILL.

// re2v $INPUT -o $OUTPUT
/*!max:re2c*/
// يتوقع سلسلة نصية محشوة بـ yymaxfill.
fn lex(str string) int {
    // قم بحشو السلسلة النصية بأصفار yymaxfill في النهاية.
    mut yyinput := []u8{len: str.len + yymaxfill}
    copy(mut &yyinput, str.bytes())
    mut yycursor := 0
    yylimit := yyinput.len
    mut count := 0
loop: /*!re2c
    re2c:YYFILL = "return -1";
    str = ['] ([^'\\] | [\\][^])* ['];
    [\x00] {
        // تحقق من أنه الحارس، وليس بعض الصفر غير المتوقع.
        if yycursor - 1 == str.len { return count } else { return -1 }
    }
    str  { count += 1; unsafe { goto loop } }
    [ ]+ { unsafe { goto loop } }
    *    { return -1 }
    */
}
fn main() {
    assert lex("") == 0
    assert lex("'qu\0tes' 'are' 'fine: \\'' ") == 3
    assert lex("'unterminated\\'") == -1
    assert lex("'unexpected \00 null\\'") == -1
}

فحوصات مخصصة

يستخدم هذا المثال طريقة مخصصة لمعالجة نهاية الإدخال بناءً على واجهة برمجة التطبيقات العامة. يقوم البرنامج بعد السلاسل النصية المنفردة المقتبسة والمفصولة بمسافات. إنه نفس مثال الحارس، باستثناء أن الإدخال ليس منتهيًا ب NULL. لتغطية غياب حرف الحارس في نهاية الإدخال، يعاد تعريف YYPEEK لإجراء فحص حدود قبل قراءة حرف الإدخال التالي. هذا غير فعال لأن الفحوصات تتم كثيرًا جدًا. إذا فشل شرط الفحص، تعيد YYPEEK الحرف الحقيقي، وإلا فإنها تعيد حرف حارس وهمي.

// re2v $INPUT -o $OUTPUT
// تعيد NULL "وهمي" منتهي إذا وصل المؤشر إلى الحد.
fn peek(str string, cur int) u8 {
    return if cur >= str.len { u8(0) } /* NULL وهمي */ else { return str[cur] }
}
// يتوقع سلسلة نصية بدون NULL منتهي.
fn lex(str string) int {
    mut cur := 0
    mut count := 0
loop: /*!re2c
    re2c:api = generic;
    re2c:yyfill:enable = 0;
    re2c:YYPEEK = "peek(str, cur)";
    re2c:YYSKIP = "cur += 1";
    *      { return -1 }
    [\x00] { return count }
    [a-z]+ { count += 1; unsafe { goto loop } }
    [ ]+   { unsafe { goto loop } }
    */
}
fn main() {
    assert lex("") == 0
    assert lex("one two three") == 3
    assert lex("f0ur") == -1
}

إعادة ملء المخزن المؤقت

تنشأ الحاجة إلى التخزين المؤقت عندما لا يمكن تعيين الإدخال في الذاكرة دفعة واحدة: إما أنه كبير جدًا، أو أنه يأتي بشكل تدفقي (مثل القراءة من مقبس). التقنية المعتادة في مثل هذه الحالات هي تخصيص مخزن مؤقت بسعة ثابتة ومعالجة الإدخال في أجزاء تناسب المخزن المؤقت. عند معالجة الجزء الحالي، يتم نقله للخارج ويتم نقل بيانات جديدة للداخل. عمليًا، الأمر أكثر تعقيدًا إلى حد ما، لأن حالة محلل المفردات لا تتكون من موضع إدخال واحد، بل مجموعة من المواضع المترابطة:

  • المؤشر: حرف الإدخال التالي المراد قراءته (YYCURSOR في واجهة برمجة تطبيقات مؤشر C أو YYSKIP/YYPEEK في الواجهة العامة API)
  • الحد: الموضع بعد آخر حرف إدخال متاح (YYLIMIT في واجهة برمجة تطبيقات مؤشر C، يتم التعامل معه ضمنيًا بواسطة YYLESSTHAN في الواجهة العامة API)
  • العلامة: موضع آخر تطابق تم العثور عليه، إن وجد (YYMARKER في الواجهة الافتراضية API أو YYBACKUP/YYRESTORE في الواجهة العامة API)
  • الرمز: بداية العبارة الحالية (ضمنية في واجهة re2v API، حيث إنها ليست مطلوبة لعمل محلل المفردات العادي ويمكن تعريفها وتحديثها بواسطة المستخدم)
  • علامة السياق: موضع السياق اللاحق (YYCTXMARKER في واجهة برمجة تطبيقات مؤشر C أو YYBACKUPCTX/YYRESTORECTX في الواجهة العامة API)
  • متغيرات العلامة: مواضع المطابقة الفرعية (معرفة باستخدام كتل stags و mtags وبدائيات الواجهة العامة API YYSTAGP/YYSTAGN/YYMTAGP/YYMTAGN)

ليست كل هذه تستخدم في كل حالة، ولكن إذا تم استخدامها، فيجب تحديثها بواسطة YYFILL. جميع المواضع النشطة موجودة في الجزء بين الرمز والمؤشر، لذلك يمكن تجاهل كل شيء بين بداية المخزن المؤقت والرمز، ويجب نقل الجزء من الرمز وحتى الحد إلى بداية المخزن المؤقت، ويجب ملء المساحة الحرة في نهاية المخزن المؤقت ببيانات جديدة. لتجنب استدعاءات YYFILL المتكررة، من الأفضل ملء أكبر عدد ممكن من أحرف الإدخال (على الرغم من أن عددًا أقل من الأحرف قد يكون كافيًا لاستئناف محلل المفردات). تختلف تفاصيل تنفيذ YYFILL قليلاً اعتمادًا على طريقة معالجة نهاية الملف المستخدمة: حالة قاعدة نهاية الملف أبسط إلى حد ما من حالة فحص الحدود مع الحشو. لاحظ أيضًا أنه إذا تم استخدام الخيار -f --storable-state، فإن YYFILL لها دلالات مختلفة قليلاً (موضحة في القسم الخاص بالحالة القابلة للتخزين).

YYFILL مع الحارس

إذا تم استخدام قاعدة نهاية الملف، فإن YYFILL عبارة عن بدائية تشبه الدالة لا تقبل أي وسيطات وتعيد قيمة يتم التحقق منها مقابل الصفر. يتم تشغيل استدعاء YYFILL بواسطة الشرط YYLIMIT <= YYCURSOR في واجهة برمجة تطبيقات مؤشر C و YYLESSTHAN() في الواجهة العامة API. يجب أن توفر استدعاء YYFILL ناجح حرفًا واحدًا على الأقل وتضبط مواضع الإدخال وفقًا لذلك. يجب دائمًا ضبط الحد ليكون واحدًا بعد موضع الإدخال الأخير في المخزن المؤقت، ويجب أن يكون الحرف عند موضع الحد هو رمز الحارس المحدد بواسطة تكوين re2c:eof. تعرض الصور أدناه المواقع النسبية لمواضع الإدخال في المخزن المؤقت قبل وبعد استدعاء YYFILL (يتم تمييز رمز الحارس بـ #، وتظهر الصورة الثانية الحالة التي لا يوجد فيها إدخال كافٍ لملء المخزن المؤقت بالكامل).

               <-- shift -->
             >-A------------B---------C-------------D#-----------E->
             buffer       token    marker         limit,
                                                  cursor
>-A------------B---------C-------------D------------E#->
             buffer,  marker        cursor        limit
             token
               <-- shift -->
             >-A------------B---------C-------------D#--E (EOF)
             buffer       token    marker         limit,
                                                  cursor
>-A------------B---------C-------------D---E#........
             buffer,  marker       cursor limit
             token

إليك مثال لبرنامج يقرأ ملف الإدخال input.txt في أجزاء بحجم 4096 بايت ويستخدم قاعدة نهاية الملف.

// re2v $INPUT -o $OUTPUT
import os
import strings
const bufsize = 4096
struct State {
    file     os.File
mut:
    yyinput  []u8
    yycursor int
    yymarker int
    yylimit  int
    token    int
    eof      bool
}
fn fill(mut st &State) int {
    if st.eof { return -1 } // نهاية ملف غير متوقعة
    // خطأ: العبارة طويلة جدًا. في الواقع يمكن إعادة تخصيص مخزن مؤقت أكبر.
    if st.token < 1 { return -2 }
    // قم بإزاحة محتويات المخزن المؤقت (تجاهل كل شيء حتى الرمز الحالي).
    copy(mut &st.yyinput, st.yyinput[st.token..st.yylimit])
    st.yycursor -= st.token
    st.yymarker -= st.token
    st.yylimit -= st.token
    st.token = 0
    // املأ المساحة الحرة في نهاية المخزن المؤقت ببيانات جديدة من الملف.
    pos := st.file.tell() or { 0 }
    if n := st.file.read_bytes_into(u64(pos), mut st.yyinput[st.yylimit..bufsize]) {
        st.yylimit += n
    }
    st.yyinput[st.yylimit] = 0 // أضف رمز الحارس
    // إذا تم القراءة أقل من المتوقع، فهذه نهاية الإدخال.
    st.eof = st.yylimit < bufsize
    return 0
}
fn lex(mut yyrecord &State) int {
    mut count := 0
loop:
    yyrecord.token = yyrecord.yycursor
    /*!re2c
        re2c:api = record;
        re2c:eof = 0;
        re2c:YYFILL = "fill(mut yyrecord) == 0";
        str = ['] ([^'\\] | [\\][^])* ['];
        *    { return -1 }
        $    { return count }
        str  { count += 1; unsafe { goto loop } }
        [ ]+ { unsafe { goto loop } }
    */
}
fn main() {
    fname := "input"
    content := "'qu\0tes' 'are' 'fine: \\'' "
    // قم بإعداد ملف الإدخال: عدة مرات حجم المخزن المؤقت، يحتوي على
    // سلاسل نصية مع أصفار واقتباسات محولة.
    mut fw := os.create(fname)!
    fw.write_string(strings.repeat_string(content, bufsize))!
    fw.close()
    count := 3 * bufsize // عدد السلاسل المقتبسة المكتوبة إلى الملف
    // قم بإعداد حالة محلل المفردات: جميع الإزاحات في نهاية المخزن المؤقت.
    mut fr := os.open(fname)!
    mut st := &State{
        file:     fr,
        // يتم تعيين الحارس عند إزاحة `yylimit` إلى صفر، مما يؤدي إلى تشغيل YYFILL.
        yyinput:  []u8{len: bufsize + 1},
        yycursor: bufsize,
        yymarker: bufsize,
        yylimit:  bufsize,
        token:    bufsize,
        eof:      false,
    }
    // قم بتشغيل محلل المفردات.
    n := lex(mut st)
    if n != count { panic("expected $count, got $n") }
    // التنظيف: قم بإزالة ملف الإدخال.
    fr.close()
    os.rm(fname)!
}

YYFILL مع الحشو

في الحالة الافتراضية (عندما لا يتم استخدام قاعدة نهاية الملف)، YYFILL عبارة عن بدائية تشبه الدالة تقبل وسيطة واحدة ولا تعيد أي قيمة. يتم تشغيل استدعاء YYFILL بواسطة الشرط (YYLIMIT - YYCURSOR) < n في واجهة برمجة تطبيقات مؤشر C و YYLESSTHAN(n) في الواجهة العامة API. الوسيطة التي تم تمريرها إلى YYFILL هي الحد الأدنى لعدد الأحرف التي يجب توفيرها. إذا فشلت في القيام بذلك، يجب ألا تعود YYFILL إلى محلل المفردات (لهذا السبب من الأفضل تنفيذها كـ ماكرو يعيد من الدالة المستدعية عند الفشل). في حالة استدعاء YYFILL ناجح، يجب تعيين موضع الحد إما إلى واحد بعد موضع الإدخال الأخير في المخزن المؤقت، أو إلى نهاية الحشو YYMAXFILL (في حال قامت YYFILL بقراءة ما لا يقل عن n حرف بنجاح، ولكن ليس كافيًا لملء المخزن المؤقت بالكامل). تعرض الصور أدناه المواقع النسبية لمواضع الإدخال في المخزن المؤقت قبل وبعد استدعاء YYFILL (يتم تمييز حشو YYMAXFILL في الصورة الثانية بـ # رموز).

               <-- shift -->                 <-- need -->
             >-A------------B---------C-----D-------E---F--------G->
             buffer       token    marker cursor
limit >-A------------B---------C-----D-------E---F--------G-> buffer, marker cursor limit token <-- shift --> <-- need --> >-A------------B---------C-----D-------E-F (EOF) buffer token marker cursor limit >-A------------B---------C-----D-------E-F############### buffer, marker cursor limit token <- YYMAXFILL ->

Here is an example of a program that reads input file input.txt in chunks of 4096 bytes and uses bounds-checking with padding.

// re2v $INPUT -o $OUTPUT
import os
import strings
/*!max:re2c*/
const bufsize = 4096
struct State {
    file     os.File
mut:
    yyinput  []u8
    yycursor int
    yylimit  int
    token    int
    eof      bool
}
fn fill(mut st &State, need int) int {
    if st.eof { return -1 } // unexpected EOF
    // Error: lexeme too long. In real life can reallocate a larger buffer.
    if st.token < need { return -2 }
    // Shift buffer contents (discard everything up to the current token).
    copy(mut &st.yyinput, st.yyinput[st.token..st.yylimit])
    st.yycursor -= st.token
    st.yylimit -= st.token
    st.token = 0
    // Fill free space at the end of buffer with new data from file.
    pos := st.file.tell() or { 0 }
    if n := st.file.read_bytes_into(u64(pos), mut st.yyinput[st.yylimit..bufsize]) {
        st.yylimit += n
    }
    // If read less than expected, this is the end of input.
    if st.yylimit < bufsize {
        st.eof = true
        for i := 0; i < yymaxfill; i += 1 { st.yyinput[st.yylimit + i] = 0 }
        st.yylimit += yymaxfill
    }
    return 0
}
fn lex(mut yyrecord &State) int {
    mut count := 0
loop:
    yyrecord.token = yyrecord.yycursor
    /*!re2c
        re2c:api = record;
        re2c:YYFILL = "r := fill(mut yyrecord, @@); if r != 0 { return r }";
        str = ['] ([^'\\] | [\\][^])* ['];
        [\x00] {
            // Check that it is the sentinel, not some unexpected null.
            return if yyrecord.token == (yyrecord.yylimit - yymaxfill) { count } else { -1 }
        }
        str  { count += 1; unsafe { goto loop } }
        [ ]+ { unsafe { goto loop } }
        *    { return -1 }
    */
}
fn main() {
    fname := "input"
    content := "'qu\0tes' 'are' 'fine: \\'' ";
    // Prepare input file: a few times the size of the buffer, containing
    // strings with zeroes and escaped quotes.
    mut fw := os.create(fname)!
    fw.write_string(strings.repeat_string(content, bufsize))!
    fw.close()
    count := 3 * bufsize // number of quoted strings written to file
    // Prepare lexer state: all offsets are at the end of buffer.
    // This immediately triggers YYFILL, as the YYLESSTHAN condition is true.
    mut fr := os.open(fname)!
    mut st := &State{
        file:     fr,
        yyinput:  []u8{len: bufsize + yymaxfill},
        yycursor: bufsize,
        yylimit:  bufsize,
        token:    bufsize,
        eof:      false,
    }
    // Run the lexer.
    n := lex(mut st)
    if n != count { panic("expected $count, got $n") }
    // Cleanup: remove input file.
    fr.close()
    os.rm(fname)!
}

FEATURES

Multiple blocks

Sometimes it is necessary to have multiple interrelated lexers (for example, if there is a high-level state machine that transitions between lexer modes). This can be implemented using multiple connected re2v blocks. Another option is to use start conditions.

The implementation of connections between blocks depends on the target language. In languages that have goto statement (such as C/C++ and Go) one can have all blocks in one function, each of them prefixed with a label. Transition from one block to another is a simple goto. In languages that do not have goto (such as Rust) it is necessary to use a loop with a switch on a state variable, similar to the yystate loop/switch generated by re2v, or else wrap each block in a function and use function calls.

The example below uses multiple blocks to parse binary, octal, decimal and hexadecimal numbers. Each base has its own block. The initial block determines base and dispatches to other blocks. Common configurations are defined in a separate block at the beginning of the program; they are inherited by the other blocks.

// re2v $INPUT -o $OUTPUT -i
const u32_lim = u64(1) << 32
fn parse_u32(yyinput string) ?u32 {
    mut yycursor, mut yymarker := 0, 0
    mut n := u64(0)
    mut yych := 0
    adddgt := fn (num u64, base u64, digit u8) u64 {
        n := num * base + u64(digit)
        return if n >= u32_lim { u32_lim } else { n }
    }
    /*!re2c
        re2c:yyfill:enable = 0;
        re2c:yych:emit = 0;
        end = "\x00";
        '0b' / [01]        { unsafe{ goto bin } }
        "0"                { unsafe{ goto oct } }
        ""   / [1-9]       { unsafe{ goto dec } }
        '0x' / [0-9a-fA-F] { unsafe{ goto hex } }
        *                  { return none }
    */
bin:
    /*!re2c
        end   { unsafe{ goto end } }
        [01]  { n = adddgt(n, 2, yyinput[yycursor-1] - 48); unsafe{ goto bin } }
        *     { return none }
    */
oct:
    /*!re2c
        end   { unsafe{ goto end } }
        [0-7] { n = adddgt(n, 8, yyinput[yycursor-1] - 48); unsafe{ goto oct } }
        *     { return none }
    */
dec:
    /*!re2c
        end   { unsafe{ goto end } }
        [0-9] { n = adddgt(n, 10, yyinput[yycursor-1] - 48); unsafe{ goto dec } }
        *     { return none }
    */
hex:
    /*!re2c
        end   { unsafe{ goto end } }
        [0-9] { n = adddgt(n, 16, yyinput[yycursor-1] - 48); unsafe{ goto hex } }
        [a-f] { n = adddgt(n, 16, yyinput[yycursor-1] - 87); unsafe{ goto hex } }
        [A-F] { n = adddgt(n, 16, yyinput[yycursor-1] - 55); unsafe{ goto hex } }
        *     { return none }
    */
end:
    if n < u32_lim {
        return u32(n)
    }
    return none
}
fn main() {
    test := fn (num ?u32, str string) {
        if n := parse_u32(str) {
            if m := num { if n != m { panic("wrong number") } }
        } else {
            if _ := num { panic("expected none") }
        }
    }
    test(1234567890, "1234567890\0")
    test(13, "0b1101\0")
    test(0x7fe, "0x007Fe\0")
    test(0o644, "0644\0")
    test(none, "9999999999\0")
    test(none, "123??\0")
}

Start conditions

Start conditions are enabled with --start-conditions option. They provide a way to encode multiple interrelated automata within the same re2v block.

Each condition corresponds to a single automaton and has a unique name specified by the user and a unique internal number defined by re2v. The numbers are used to switch between conditions: the generated code uses YYGETCOND and YYSETCOND primitives to get the current condition or set it to the given number. Use conditions block, --header option or re2c:header configuration to generate numeric condition identifiers. Configuration re2c:cond:enumprefix specifies the generated identifier prefix.

In condition mode every rule must be prefixed with a list of comma-separated condition names in angle brackets, or a wildcard <*> to denote all conditions. The rule syntax is extended as follows:

< condition-list > regular-expression code
A rule that is merged to every condition on the condition-list. It matches regular-expression and executes the associated code.
< condition-list > regular-expression => condition code
A rule that is merged to every condition on the condition-list. It matches regular-expression, sets the current condition to condition and executes the associated code.
< condition-list > regular-expression :=> condition
A rule that is merged to every condition on the condition-list. It matches regular-expression and immediately transitions to condition (there is no semantic action).
< condition-list > !action code
A rule that binds code to the place defined by action in every condition on the condition-list (see the actions section for various types of actions).
<! condition-list > code
A rule that prepends code to semantic actions of all rules for every condition on the condition-list. This syntax is deprecated and the !pre_rule action should be used instead (it does exactly the same).
< > code
A rule that creates a special entry condition with number zero and name "0" that executes code before jumping to other conditions. This syntax is deprecated, and the !entry action should be used instead (it provides a more fine-grained control, as the code can be specified on a per-condition basis, and one can jump directly to condition start without going through condition dispatch).
< > => condition code
Same as the previous rule, except that it sets the next condition.
< > :=> condition
Same as the previous rule, except that it has no associated code and immediately jumps to condition.

The code re2v generates for conditions depends on whether re2v uses goto/label approach or loop/switch approach to encode the automata.

In languages that have goto statement (such as C/C++ and Go) conditions are naturally implemented as blocks of code prefixed with labels of the form yyc_<cond>, where cond is a condition name (label prefix can be changed with re2c:cond:prefix). Transitions between conditions are implemented using goto and condition labels. Before all conditions re2v generates an initial switch on YYGETSTATE that jumps to the start state of the current condition. The shortcut rules :=> bypass the initial switch and jump directly to the specified condition (re2c:cond:goto can be used to change the default behavior). The rules with semantic actions do not automatically jump to the next condition; this should be done by the user-defined action code.

In languages that do not have goto (such as Rust) re2v reuses the yystate variable to store condition numbers. Each condition gets a numeric identifier equal to the number of its start state, and a switch between conditions is no different than a switch between DFA states of a single condition. (بما أن نفس النهج يُستخدم لتنفيذ الحالات القابلة للتخزين، فإن YYGETCOND/YYSETCOND تكون زائدة عن الحاجة إذا تم استخدام كل من الحالات القابلة للتخزين والشروط).

    */

حالة قابلة للتخزين

مع خيار --storable-state، يقوم re2v بإنشاء محلل يمكنه تخزين حالته الحالية، والعودة إلى المتصل، ثم استئناف العمليات بالضبط من حيث توقف. الوضع الافتراضي للتشغيل في re2v هو نموذج "السحب"، حيث "يسحب" المحلل المزيد من الإدخال كلما احتاج إليه. قد يكون هذا غير مقبول في الحالات التي يتوفر فيها الإدخال قطعة قطعة (على سبيل المثال، إذا تم استدعاء المحلل بواسطة المحلل، أو إذا كان برنامج المحلل يتواصل عبر بروتوكول مأخذ توصيل مع برنامج آخر يجب أن ينتظر ردًا من المحلل قبل إرسال الرسالة التالية). ميزة الحالة القابلة للتخزين مخصصة بالضبط لهذه الحالات: فهي تسمح بإنشاء محللات تعمل في نموذج "الدفع". عندما يحتاج المحلل إلى المزيد من الإدخال، فإنه يخزن حالته ويعود إلى المتصل. لاحقًا، عندما يتوفر المزيد من الإدخال، يستأنف المتصل المحلل بالضبط من حيث توقف. هناك بعض التغييرات اللازمة مقارنة بنموذج "السحب":

  • تعريف بدائيات YYSETSTATE() و YYGETSTATE(state).
  • تعريف المتغيرات yych و yyaccept (إذا تم استخدامها) و state كجزء من حالة المحلل الدائمة. يجب تهيئة المتغير state إلى -1.
  • يجب أن يعود YYFILL إلى البرنامج الخارجي بدلاً من محاولة توفير المزيد من الإدخال. يجب أن يشير رمز العودة إلى أن المحلل يحتاج إلى المزيد من الإدخال.
  • يجب على البرنامج الخارجي التعرف على المواقف التي يحتاج فيها المحلل إلى المزيد من الإدخال والاستجابة بشكل مناسب.
  • اختياريًا، استخدم كتلة getstate لإنشاء تبديل YYGETSTATE منفصل عن المحلل الرئيسي. يعمل هذا فقط مع اللغات التي تحتوي على goto (ليس في وضع --loop-switch).
  • استخدم re2c:eof وطريقة الجُملة الحدية مع فحوصات الحدود للتعامل مع نهاية الإدخال. قد لا تعمل طريقة الاعتماد على الحشو لأنها غير واضحة متى يتم إلحاق الحشو: قد لا تكون نهاية الإدخال الحالية هي النهاية النهائية للإدخال، وقد يؤدي إلحاق الحشو مبكرًا جدًا إلى قطع لغة طمعية مقروءة جزئيًا. علاوة على ذلك، نظرًا لمنطق البرنامج عالي المستوى، قد يعتمد الحصول على المزيد من الإدخال على معالجة اللغة في نهاية المخزن المؤقت (والتي تكون بالفعل محظورة بسبب شرط نهاية الإدخال).

هنا مثال على محلل بنموذج "الدفع" يحاكي قراءة حزم من مأخذ توصيل. يتكرر المحلل حتى يصادف نهاية الإدخال ويعود إلى الدالة المستدعية. يوفر المتصل المزيد من الإدخال عن طريق "إرسال" الحزمة التالية ويستأنف التحليل. تتوقف هذه العملية عندما يتم إرسال جميع الحزم، أو عند حدوث خطأ.

// re2v -f $INPUT -o $OUTPUT
import log
import os
// Use a small buffer to cover the case when a lexeme doesn't fit.
// In real world use a larger buffer.
const bufsize = 10
struct State {
mut:
    file     os.File
    yyinput  []u8
    yycursor int
    yymarker int
    yylimit  int
    token    int
    yystate  int
}
enum Status {
    lex_end
    lex_ready
    lex_waiting
    lex_bad_packet
    lex_big_packet
}
fn fill(mut st &State) Status {
    shift := st.token
    used := st.yylimit - st.token
    free := bufsize - used
    // Error: no space. In real life can reallocate a larger buffer.
    if free < 1 { return .lex_big_packet }
    // Shift buffer contents (discard already processed data).
    copy(mut &st.yyinput, st.yyinput[shift..shift+used])
    st.yycursor -= shift
    st.yymarker -= shift
    st.yylimit -= shift
    st.token -= shift
    // Fill free space at the end of buffer with new data.
    pos := st.file.tell() or { 0 }
    if n := st.file.read_bytes_into(u64(pos), mut st.yyinput[st.yylimit..bufsize]) {
        st.yylimit += n
    }
    st.yyinput[st.yylimit] = 0 // append sentinel symbol
    return .lex_ready
}
fn lex(mut yyrecord &State, mut recv &int) Status {
    mut yych := u8(0)
    /*!getstate:re2c*/
loop:
    yyrecord.token = yyrecord.yycursor
    /*!re2c
        re2c:api = record;
        re2c:eof = 0;
        re2c:YYFILL = "return .lex_waiting";
        packet = [a-z]+[;];
        *      { return .lex_bad_packet }
        $      { return .lex_end }
        packet { recv += 1; unsafe{ goto loop } }
    */
}
fn test(expect Status, packets []string) {
    // Create a pipe (open the same file for reading and writing).
    fname := "pipe"
    mut fw := os.create(fname) or { panic("cannot create file") }
    mut fr := os.open(fname) or { panic("cannot open file") }
    // Initialize lexer state: `state` value is -1, all offsets are at the end
    // of buffer.
    mut st := &State{
        file:     fr,
        // Sentinel at `yylimit` offset is set to zero, which triggers YYFILL.
        yyinput:  []u8{len: bufsize + 1},
        yycursor: bufsize,
        yymarker: bufsize,
        yylimit:  bufsize,
        token:    bufsize,
        yystate:  -1,
    }
    // Main loop. The buffer contains incomplete data which appears packet by
    // packet. When the lexer needs more input it saves its internal state and
    // returns to the caller which should provide more input and resume lexing.
    mut status := Status.lex_ready
    mut send := 0
    mut recv := 0
    for {
        status = lex(mut st, mut &recv)
        if status == .lex_end {
            break
        } else if status == .lex_waiting {
            if send < packets.len {
                log.debug("sending packet $send")
                fw.write_string(packets[send]) or { panic("cannot write to file") }
                fw.flush()
                send += 1
            }
            status = fill(mut st)
            log.debug("filled buffer $st.yyinput, status $status")
            if status != .lex_ready {
                break
            }
        } else if status == .lex_bad_packet {
            break
        }
    }
    // Check results.
    if status != expect || (status == .lex_end && recv != send) {
        panic("expected $expect with $send packet(s), got $status with $recv packet(s)")
    }
    // Cleanup: remove input file.
    fr.close()
    fw.close()
    os.rm(fname) or { panic("cannot remove file") }
}
fn main() {
    //log.set_level(.debug)
    test(.lex_end, [])
    test(.lex_end, ["zero;", "one;", "two;", "three;", "four;"])
    test(.lex_bad_packet, ["??;"])
    test(.lex_big_packet, ["looooooooooooong;"])
}

كتل قابلة لإعادة الاستخدام

يمكن إعادة استخدام الكتل القابلة لإعادة الاستخدام من النموذج /*!rules:re2c[:<name>] ... */ أو %{rules[:<name>] ... %} أي عدد من المرات ودمجها مع كتل re2v أخرى. <name> اختياري. يمكن استخدام كتلة قواعد في كتلة use أو توجيه. يتم إنشاء الكود لكتلة قواعد في كل نقطة استخدام.

يتم تعريف كتل الاستخدام باستخدام /*!use:re2c[:<name>] ... */ أو %{use[:<name>] ... %}. <name> اختياري: إذا لم يتم تحديده، فإن كتلة القواعد المرتبطة بها هي الأحدث (سواء كانت مسماة أو غير مسماة). يمكن لكتلة الاستخدام إضافة تعريفات وأعدادات وقواعد مسماة خاصة بها. حالة استخدام مهمة لكتل الاستخدام هي محلل يدعم ترميزات إدخال متعددة: يتم إعادة استخدام نفس كتلة القواعد عدة مرات مع إعدادات خاصة بالترميز (انظر المثال أدناه).

يمكن استخدام توجيه الاستخدام داخل الكتلة !use:<name>; من داخل كتلة re2v. يقوم بدمج الكتلة المشار إليها <name> في الكتلة الحالية. إذا تداخلت بعض القواعد والإعدادات المدمجة مع تلك المعرفة سابقًا، يتم حل التعارضات بالطريقة المعتادة: الأولوية للقاعدة الأولى، وتتجاوز الإعدادات الأخيرة ما سبقها. الاستثناء الوحيد هي القواعد الخاصة * و $ و (في وضع الشرط) <!>، والتي تتجاوز فيها التعريفات المحلية للكتلة أي تعريفات موروثة. يسمح توجيه الاستخدام بدمج كتل re2v مختلفة معًا في كتلة واحدة (انظر المثال أدناه).

تمت إضافة الكتل المسماة وتوجيه الاستخدام داخل الكتلة في re2v الإصدار 2.2. منذ ذلك الإصدار، يُسمح بالكتل القابلة لإعادة الاستخدام بشكل افتراضي (لا يلزم خيار خاص). قبل الإصدار 2.2، كان يمكن تمكين وضع إعادة الاستخدام باستخدام الخيار -r --reusable. قبل الإصدار 1.2، لم يكن يمكن خلط الكتل القابلة لإعادة الاستخدام مع الكتل العادية.

مثال على توجيه !use

// re2v $INPUT -o $OUTPUT
// This example shows how to combine reusable re2c blocks: two blocks
// ('colors' and 'fish') are merged into one. The 'salmon' rule occurs
// in both blocks; the 'fish' block takes priority because it is used
// earlier. Default

استخراج المباريات الفرعية

يحتوي re2v على خيارين لاستخراج المباريات الفرعية.

العلامات (Tags)
الخيار الأول هو استخدام علامات مستقلة بالشكل @stag أو #mtag، حيث stag و mtag أسماء معرفة من قبل المستخدم بشكل تعسفي. يتم تمكين العلامات باستخدام الخيار -T --tags أو إعداد re2c:tags = 1. من الناحية الدلالية، العلامات هي علامات موضعية: يمكن إدراجها في أي مكان في التعبير العادي، وترتبط بالموضع (أو المواضع المتعددة) المقابلة في سلسلة الإدخال. علامات S ترتبط بآخر موضع مطابق، و علامات M ترتبط بقائمة المواضع (يمكن استخدامها في تعبيرات تكرار فرعية، حيث يتوافق موضع واحد في التعبير العادي مع مواضع متعددة في سلسلة الإدخال). يجب أن يتم تعريف جميع العلامات من قبل المستخدم، إما يدويًا أو بمساعدة كتل svars و mvars. إذا كان هناك أكثر من طريقة لمطابقة العلامات مع الإدخال، يتم حل الغموض باستخدام استراتيجية فض الغموض الأكثر يسارية.
المجموعات الملتقطة (Captures)
الخيار الثاني هو استخدام مجموعات التقاط. يتم تمكينها باستخدام الخيار --captures أو إعداد re2c:captures = 1. هناك نكهتان لسياسات فض غموض مختلفة، --leftmost-captures (الافتراضي) لسياسة الفض الأكثر يسارية، و --posix-captures لسياسة أطول تطابق POSIX. في هذا الوضع، تعتبر جميع التعبيرات الفرعية الموضوعة بين قوسين مجموعات التقاط، ويمكن استخدام علامة التعجب لتمييز المجموعات غير الملتقطة: (! ... ). مع الخيار --invert-captures أو إعداد re2c:invert-captures = 1، يتم عكس معنى علامة التعجب. يتم تخزين عدد المجموعات لقاعدة المطابقة في متغير yynmatch (التعبير العادي بأكمله هو المجموعة رقم صفر)، ويتم تخزين نتائج المباريات الفرعية في مصفوفة yypmatch. يجب تعريف كل من yynmatch و yypmatch من قبل المستخدم، ويجب أن يكون حجم yypmatch على الأقل [yynmatch * 2]. استخدم كتلة maxnmatch لتحديد YYMAXNMATCH، وهو ثابت يساوي الحد الأقصى لقيمة yynmatch عبر جميع القواعد.
متغيرات الالتقاط (Captvars)
طريقة أخرى لاستخدام مجموعات الالتقاط هي الخيار --captvars أو إعداد re2c:captvars = 1. الاختلاف الوحيد مع --captures هو في الطريقة التي يولد بها الكود الناتج مخازن نتائج المباريات الفرعية: بدلاً من yynmatch و yypmatch، يولد re2v المتغيرات yytl<k> و yytr<k> لـ k-th مجموعة الالتقاط (يجب على المستخدم تعريف هذه باستخدام كتلة svars). تدعم الالتقاطات مع المتغيرات سياستي فض غموض: --leftmost-captvars أو re2c:leftmost-captvars = 1 لسياسة الفض الأكثر يسارية (الافتراضية) و --posix-captvars أو re2c:posix-captvars لسياسة أطول تطابق POSIX.

في جوهرها، تترجم كل هذه الخيارات إلى علامات و آلات حالات محدودة حتمية موسومة مع نظرة مستقبلية (Tagged Deterministic Finite Automata with Lookahead). الفكرة الأساسية لـ TDFA هي تقليل الحمل الزائد على استخراج المباريات الفرعية. في أقصى حد، إذا لم تكن هناك علامات أو مجموعات التقاط في تعبير عادي، فإن TDFA هو مجرد DFA عادي. إذا كان عدد العلامات معتدلاً، فإن الحمل الزائد بالكاد ملحوظ. تستخدم TDFA المولدة عددًا من متغيرات العلامات التي لا تتوافق مباشرة مع العلامات: قد يتم استخدام متغير واحد لعلامات مختلفة، وقد تتطلب علامة متغيرات متعددة لتخزين جميع قيمها الممكنة. في النهاية، يتم حل الغموض، ويبقى متغير نهائي واحد لكل علامة. يجب تعريف متغيرات العلامات باستخدام كتل stags أو mtags. إذا تم تخزين حالة المحلل اللغوي، فيجب أن تكون متغيرات العلامات جزءًا منها. يجب أيضًا تحديثها بواسطة YYFILL.

تدعم علامات S العمليات التالية:

  • حفظ موضع الإدخال في علامة S: t = YYCURSOR باستخدام واجهة مؤشر C أو عملية معرفة من قبل المستخدم YYSTAGP(t) باستخدام واجهة عامة
  • حفظ قيمة افتراضية في علامة S: t = NULL باستخدام واجهة مؤشر C أو عملية معرفة من قبل المستخدم YYSTAGN(t) باستخدام واجهة عامة
  • نسخ علامة S إلى أخرى: t1 = t2

تدعم علامات M العمليات التالية:

  • إلحاق موضع الإدخال بعلامة M: عملية معرفة من قبل المستخدم YYMTAGP(t) باستخدام كل من الواجهة الافتراضية والعامة
  • إلحاق قيمة افتراضية بعلامة M: عملية معرفة من قبل المستخدم YYMTAGN(t) باستخدام كل من الواجهة الافتراضية والعامة
  • نسخ علامة M إلى أخرى: t1 = t2

يمكن تنفيذ علامات S كقيم منفصلة (مؤشرات أو إزاحات). تتطلب علامات M تمثيلًا أكثر تعقيدًا، لأنها تحتاج إلى تخزين تسلسل قيم العلامات. أبسط وأقل تمثيل فعال لعلامة M هو قائمة (مصفوفة، متجه) من قيم العلامات؛ تمثيل أكثر كفاءة هو تخزين جميع علامات M في شجرة بادئة ممثلة بمصفوفة من العقد (v, p)، حيث v هي قيمة العلامة و p هو مؤشر إلى عقدة الأصل.

إليك مثال بسيط لاستخدام علامات S لتحليل إصدارات دلالية تتكون من ثلاثة مكونات رقمية: رئيسي، فرعي، تصحيح (الأخير اختياري). انظر أدناه لمثال أكثر تعقيدًا يستخدم YYFILL.

```c++ // re2v $INPUT -o $OUTPUT struct SemVer { major int minor int patch int } fn s2n(s string) int { // convert pre-parsed string to number mut n := 0 for c in s { n = n * 10 + int(c - 48) } return n } fn parse(yyinput string) ?SemVer { mut yycursor, mut yymarker := 0, 0 // Final tag variables available in semantic action. /*!svars:re2c format = 'mut @@ := 0\n'; */ // Intermediate tag variables used by the lexer (must be autogenerated). /*!stags:re2c format = 'mut @@ := -1\n'; */ /*!re2c re2c:yyfill:enable = 0; re2c:tags = 1; num = [0-9]+; @t1 num @t2 "." @t3 num @t4 ("." @t5 num)? إليك مثال أكثر تعقيدًا لاستخدام علامات S مع YYFILL لتحليل ملف يحتوي على إصدارات دلالية مفصولة بأسطر جديدة. متغيرات العلامات هي جزء من حالة المحلل اللغوي، ويتم تعديلها في YYFILL مثل مواضع الإدخال الأخرى. لاحظ أنه من الضروري لعلامات S لأن قيمها تصبح غير صالحة بعد إزاحة محتويات المخزن المؤقت. قد لا يكون هذا ضروريًا في تطبيق مخصص حيث تخزن متغيرات العلامات إزاحات بالنسبة لبداية سلسلة الإدخال بدلاً من المخزن المؤقت، وهو ما قد يكون الحال مع علامات M.
