Primitives

YYBACKUP
A generic API primitive that should save the current input position (to be restored with YYRESTORE later).
YYBACKUPCTX
A generic API primitive that should save the current input position as the position of the trailing context (to be restored with YYRESTORECTX later).
YYCONDTYPE
The type of the condition enum. It can be generated either with conditions block or --header option.
YYCOPYMTAG
A generic API primitive with two variables, lhs and rhs that should copy right-hand-side m-tag variable rhs to the left-hand-side m-tag variable lhs. For most languages this primitive has a default definition that assigns lhs to rhs.
YYCOPYSTAG
A generic API primitive with two variables, lhs and rhs that should copy right-hand-side s-tag variable rhs to the left-hand-side s-tag variable lhs. For most languages this primitive has a default definition that assigns lhs to rhs.
YYDEBUG
This primitive is generated only with -d, --debug-output option. Its purpose is to add logging to the generated code (typical YYDEBUG definition is a print statement). YYDEBUG statements are generated in every state and have two variables: state (either a DFA state index or -1) and symbol (the current input symbol).
YYFILL
A generic API primitive that returns the number of available input characters. If re2c:eof is not used, then YYFILL return value is ignored and it should not return on failure. The maximum value of len is YYMAXFILL.
YYFN
A primitive that defines function prototype in --recursive-functions code model. Its value should be an array of one or more strings, where each string contains two or three components separated by the string specified in re2c:fn:sep configuration (typically a semicolon). The first array element defines function name and return type (empty for a void function). Subsequent elements define function arguments: first, the expression for the argument used in function body (usually just a name); second, argument type; third, an optional formal parameter (it defaults to the first component - usually both the argument and the parameter are the same identifier).
YYGETACCEPT
A primitive with one variable var that stores numeric selector of the accepted rule. For most languages this primitive has a default definition that reads from var.
YYGETCOND
An r-value of type YYCONDTYPE that is equal to the current condition identifier.
YYGETSTATE
An r-value of integer type that is equal to the current lexer state. It should be initialized to -1.
YYINPUT
An r-value that stores the current input character sequence (string, buffer, etc.).
YYLESSTHAN
A generic API primitive with one variable len. It should be defined as an r-value of boolean type that equals true if and only if there are less than len input characters left.
YYMAXFILL
An integral constant equal to the maximum value of the argument to YYFILL. It can be generated with a max block.
YYMAXNMATCH
An integral constant equal to the maximal number of POSIX capturing groups in a rule. It is generated with a maxnmatch block.
YYMTAGN
A generic API primitive with one variable tag. YYMTAGN should append a value that represents non-existent input position position to the submatch history of tag (see the submatch extraction section for details.)
YYMTAGP
A generic API primitive with one variable tag. YYMTAGP should append the current position to the submatch history of tag (see the submatch extraction section for details.)
YYPEEK
A generic API primitive with no variables. It should be defined as an r-value of type YYCTYPE that is equal to the character at the current input position.
YYRESTORE
A generic API primitive that should restore the current input position to the value saved by YYBACKUP.
YYRESTORECTX
A generic API primitive that should restore the trailing context position saved with YYBACKUPCTX.
YYRESTORETAG
A generic API primitive with one variable tag that should restore the trailing context position to the value of tag.
YYSKIP
A generic API primitive that should advance the current input position by one code unit.
YYSHIFT
A generic API primitive with one variable shift that should shift the current input position by shift characters (the shift value may be negative).
YYSHIFTMTAG
A generic API primitive with two variables, tag and shift that should shift the latest value in the history of tag by shift code units (the shift value may be negative).
YYSHIFTSTAG
A generic API primitive with two variables, tag and shift that should shift tag by shift code units (the shift value may be negative).
YYSETACCEPT
A primitive with two variables: var (an l-value that stores numeric selector of the accepted rule), and val (the value of selector). For most languages this primitive has a default definition that assigns var to val.
YYSETCOND
A primitive with one variable cond that should set the current condition identifier to cond.
YYSETSTATE
A primitive with one variable state that should set the current lexer state to state.
YYSTAGN
A generic API primitive with one variable tag, where tag can be a pointer or an offset in YYINPUT (see submatch extraction section for details). YYSTAGN should to set tag to a value that represents non-existent input position.
YYSTAGP
A generic API primitive with one variable tag, where tag can be a pointer or an offset in YYINPUT (see submatch extraction section for details). YYSTAGP should set tag to the current input position.

-? --help -h
إظهار رسالة المساعدة.
--api <simple | record | generic>
تحديد الواجهة البرمجية (API) التي يستخدمها الرمز المولد للتفاعل مع الكود المعرف من قبل المستخدم. يجب استخدام الخيار simple في الحالات البسيطة عندما لا تكون هناك حاجة لإعادة تعبئة المخزن المؤقت وتخزين حالة المحلل اللغوي. يجب استخدام الخيار record عندما تحتاج حالة المحلل اللغوي إلى تخزينها في سجل (هيكل، فئة، إلخ). يجب استخدام الخيار generic في الحالات المعقدة عندما لا تكون الواجهات البرمجية الأخرى مرنة بما فيه الكفاية.
--bit-vectors -b
تحسين القفزات الشرطية باستخدام أقنعة البت. يشير هذا الخيار إلى --nested-ifs.
--captures, --leftmost-captures
تمكين استخراج المجموعات الفرعية مع مجموعات التقاط جشعة إلى أقصى اليسار. يتم جمع النتيجة في مصفوفة yybmatch بسعة 2 * YYMAXNMATCH، ويتم تعيين yynmatch إلى عدد المجموعات لقاعدة المطابقة.
--captvars, --leftmost-captvars
تمكين استخراج المجموعات الفرعية مع مجموعات التقاط جشعة إلى أقصى اليسار. يتم جمع النتيجة في المتغيرات yytl<k> و yytr<k> للمجموعة الـ k الملتقطة.
--case-insensitive
معاملة السلاسل النصية المحاطة بعلامات اقتباس مفردة ومزدوجة على أنها غير حساسة لحالة الأحرف.
--case-inverted
عكس معنى السلاسل النصية المحاطة بعلامات اقتباس مفردة ومزدوجة: معاملة السلاسل النصية المحاطة بعلامات اقتباس مفردة على أنها حساسة لحالة الأحرف والسلاسل النصية المحاطة بعلامات اقتباس مزدوجة على أنها غير حساسة لحالة الأحرف.
--case-ranges
دمج الحالات المتتالية في عبارات switch في نطاق بالشكل low ... high. هذه الصيغة هي امتداد للغة C/C++ مدعومة من قبل مترجمات مثل GCC و Clang و Tcc. الميزة الرئيسية مقارنة باستخدام حالات فردية هي تقليل حجم الكود المولد وتقليل وقت الإنشاء، على الرغم من أنها تؤدي أيضًا إلى تقليل حجم الملف الثنائي لبعض المترجمات مثل Tcc.
--computed-gotos -g
تحسين القفزات الشرطية باستخدام امتداد "computed goto" غير القياسي (والذي يجب أن يدعمه المترجم). يولد re2java جداول القفز فقط في الحالات المعقدة التي تحتوي على الكثير من التفرعات الشرطية. يمكن تكوين عتبة التعقيد باستخدام إعداد cgoto:threshold. يمكن تمكين الإزاحات النسبية باستخدام إعداد cgoto:relative. يشير هذا الخيار إلى --bit-vectors.
--computed-gotos-relative
مشابه لـ --computed-gotos ولكن يولد إزاحات نسبية لجداول القفز بدلاً من ذلك (والتي يجب أن يدعمها المترجم). يشير هذا الخيار إلى --computed-gotos.
--conditions --start-conditions -c
تمكين دعم "الشروط" المشابهة لـ Flex: محللات لغوية متعددة مترابطة داخل كتلة واحدة. هذا بديل لتحديد كتل re2java مختلفة يدويًا متصلة بـ goto أو استدعاءات الوظائف.
--depfile FILE
كتابة معلومات التبعية إلى FILE في شكل قاعدة Makefile <output-file> : <input-file> [include-file ...]. هذا يسمح بتتبع تبعيات البناء في وجود كتل/توجيهات include، بحيث يؤدي تحديث ملفات التضمين إلى إعادة إنشاء ملف الإخراج. يعتمد هذا الخيار على خيار --output.
--ebcdic --ecb -e
إنشاء محلل لغوي يقرأ الإدخال بتشفير EBCDIC. يفترض re2java أن نطاق الأحرف هو 0 -- 0xFF وحجم الأحرف هو بايت واحد.
--empty-class <match-empty | match-none | error>
تحديد الطريقة التي يتعامل بها re2java مع فئات الأحرف الفارغة. مع match-empty (الافتراضي) تتطابق الفئة الفارغة مع الإدخال الفارغ (وهو غير منطقي، ولكنه متوافق مع الإصدارات السابقة). مع match-none تفشل الفئة الفارغة دائمًا في المطابقة. مع error تثير الفئة الفارغة خطأ في الترجمة.
--encoding-policy <fail | substitute | ignore>
تحديد الطريقة التي يتعامل بها re2java مع بدائل Unicode. مع fail يتوقف re2java مع خطأ عند مواجهة بديل. مع substitute يستبدل re2java بصمت البدائل بنقطة رمز الخطأ 0xFFFD. مع ignore (الافتراضي) يتعامل re2java مع البدائل كنقاط رمز عادية. ينص معيار Unicode على أن البدائل المستقلة غير صالحة، ولكن المكتبات والبرامج في العالم الحقيقي تتصرف بطرق مختلفة.
--flex-syntax -F
دعم جزئي لصيغة Flex: في هذا الوضع، لا تحتاج التعريفات المسماة إلى علامة يساوي والفاصلة المنقوطة المنتهية، وعند استخدامها يجب أن تكون محاطة بأقواس معقوفة. يتم التعامل مع الأسماء بدون أقواس معقوفة كسلاسل نصية محاطة بعلامات اقتباس مزدوجة.
--goto-label
استخدم نموذج الكود "goto/label": قم بترميز DFA في شكل كتل تعليمات برمجية مسماة متصلة بانتقالات goto عبر الكتل. هذا مدعوم فقط للغات التي تحتوي على عبارة goto.
--header --type-header -t HEADER
إنشاء ملف HEADER. يمكن تحديد محتويات الملف باستخدام الكتل الخاصة header:on و header:off. إذا تم استخدام الشروط، فسيكون لدى رأس الملف المولد تعداد شرط تلقائيًا (ما لم يكن هناك كتلة conditions صريحة).

أضف PATH إلى قائمة المواقع التي تستخدم عند البحث عن ملفات التضمين. هذا الخيار مفيد بالاقتران مع كتلة أو توجيه include. يبحث re2java عن FILE في دليل الملف الأصل وفي مواقع التضمين المحددة بالخيار -I.

اسم مستعار مهمل لـ --api. الخيار default يتوافق مع simple (إنه بالفعل افتراضي لمعظم الواجهات الخلفية، ولكن ليس للجميع). الخيار custom يتوافق مع generic.

تحديد الطريقة التي يفسر بها re2java التعبيرات العادية. مع ascii (الافتراضي) يتعامل re2java مع الإدخال كترميز ASCII: أي تسلسل من وحدات الكود هو تسلسل من أحرف مستقلة من بايت واحد. مع utf8 يتعامل re2java مع الإدخال كترميز UTF8 ويدرك الأحرف متعددة البايتات.
--invert-captures
عكس معنى المجموعات الملتقطة وغير الملتقطة. افتراضيًا (...) ملتقطة و (! ...) غير ملتقطة. مع هذا الخيار (! ...) ملتقطة و (...) غير ملتقطة.

تحديد لغة الهدف. اللغات المدعومة هي C و D و Go و Haskell و Java و JS و OCaml و Python و Rust و Swift و V و Zig (يمكن إضافة المزيد من اللغات عبر ملفات بناء جملة معرفة من قبل المستخدم، انظر خيار --syntax). الخيار none يعطل تكوينات بناء الجملة الافتراضية، بحيث تكون لغة الهدف غير محددة.

تحديد تنسيق الموقع في الرسائل. مع gnu تتم طباعة المواقع كـ 'filename:line:column: ...'. مع msvc تتم طباعة المواقع كـ 'filename(line,column) ...'. الافتراضي هو gnu.
--loop-switch
استخدم نموذج الكود "loop/switch": قم بترميز DFA في شكل حلقة فوق عبارة switch، حيث تكون الحالات الفردية حالات switch. يتم تخزين الحالة في متغير yystate. التغييرات بين الحالات تحدث yystate إلى تسمية الحالة الوجهة وتستمر التنفيذ إلى رأس الحلقة.

منع إخراج الإصدار في الملف المولد.
--no-unsafe
لا تقم بإنشاء غلاف unsafe فوق YYPEEK (هذا الخيار خاص بـ Rust). لأسباب تتعلق بالأداء، يجب أن تتجنب YYPEEK التحقق من الحدود، حيث يقوم المحلل اللغوي بالفعل بإجراء فحوصات نهاية الإدخال بطريقة أكثر كفاءة. قد يختار المستخدم توفير تعريف YYPEEK آمن، أو تعريف غير آمن فقط في الإنشاءات الإصدارية، وفي هذه الحالة يساعد الخيار --no-unsafe على تجنب التحذيرات بشأن كتل unsafe الزائدة.
--output -o OUTPUT
تحديد ملف OUTPUT.
--posix-captures, -P
تمكين استخراج المجموعات الفرعية مع مجموعات التقاط بأسلوب POSIX. يتم جمع النتيجة في مصفوفة yybmatch بسعة 2 * YYMAXNMATCH، ويتم تعيين yynmatch إلى عدد المجموعات لقاعدة المطابقة.
--posix-captvars
تمكين استخراج المجموعات الفرعية مع مجموعات التقاط بأسلوب POSIX. يتم جمع النتيجة في المتغيرات yytl<k> و yytr<k> للمجموعة الـ k الملتقطة.
--recursive-functions
استخدم نموذج رمز يعتمد على الدوال المشتركة التكرارية، حيث تكون كل حالة من حالات DFA دالة منفصلة يمكنها استدعاء دوال الحالة الأخرى أو نفسها.
--reusable -r
تم إهماله منذ الإصدار 2.2 (تم السماح بالكتل القابلة لإعادة الاستخدام بشكل افتراضي الآن).
--skeleton -S
تجاهل رمز الواجهة المعرف من قبل المستخدم وإنشاء برنامج "هيكل عظمي" مكتفٍ ذاتيًا. بالإضافة إلى ذلك، قم بإنشاء ملفات إدخال بسلاسل مشتقة من القواعد النحوية المنتظمة ونتائج مطابقة مضغوطة تُستخدم للتحقق من سلوك "الهيكل العظمي" على جميع المدخلات. هذا الخيار مفيد للعثور على أخطاء في التحسينات وتوليد التعليمات البرمجية. هذا الخيار مدعوم فقط للغة C.
--storable-state -f
قم بإنشاء محلل لغوي يمكنه تخزين حالته الداخلية. هذا مفيد في محللات الدفع التي توقفها برنامج خارجي عندما لا يكون هناك مدخلات كافية، ثم تستأنف عندما تتوفر المزيد من المدخلات. في هذا الوضع، يجب على المستخدمين أيضًا تعريف البدائيات YYGETSTATE و YYSETSTATE، ويجب أن تكون المتغيرات yych و yyaccept و state جزءًا من حالة المحلل اللغوي المخزنة.
--syntax FILE
قم بتحميل التكوينات من FILE المحدد وتطبيقها فوق ملف البناء الافتراضي. لاحظ أن FILE يمكن أن تحدد عددًا قليلاً فقط من التكوينات (إذا تم استخدامها لتعديل ملف البناء الافتراضي)، أو يمكن أن تحدد واجهة خلفية لغة جديدة بالكامل (في الحالة الأخيرة، يوصى باستخدام الخيار --lang none).
--tags -T
قم بتمكين استخراج المطابقات الفرعية باستخدام العلامات.
--ucs2 --wide-chars -w
قم بإنشاء محلل لغوي يقرأ مدخلات مشفرة بـ UCS2. يفترض re2java أن نطاق الأحرف هو 0 -- 0xFFFF وحجم الحرف هو 2 بايت. هذا الخيار يتضمن --nested-ifs.
--utf8 --utf-8 -8
قم بإنشاء محلل لغوي يقرأ المدخلات بتشفير UTF-8. يفترض re2java أن نطاق الأحرف هو 0 -- 0x10FFFF وحجم الحرف هو 1 بايت.
--utf16 --utf-16 -x
قم بإنشاء محلل لغوي يقرأ مدخلات مشفرة بـ UTF16. يفترض re2java أن نطاق الأحرف هو 0 -- 0x10FFFF وحجم الحرف هو 2 بايت. هذا الخيار يتضمن --nested-ifs.
--utf32 --unicode -u
قم بإنشاء محلل لغوي يقرأ مدخلات مشفرة بـ UTF32. يفترض re2java أن نطاق الأحرف هو 0 -- 0x10FFFF وحجم الحرف هو 4 بايت. هذا الخيار يتضمن --nested-ifs.
--verbose
إخراج رسالة قصيرة في حالة النجاح.
--vernum -V
عرض معلومات الإصدار بتنسيق MMmmpp (رئيسي، ثانوي، فرعي).
--version -v
عرض معلومات الإصدار.
--single-pass -1
تم إهماله. لا يفعل شيئًا (المرور الأحادي هو الافتراضي الآن).
--debug-output -d
إصدار استدعاءات YYDEBUG في التعليمات البرمجية المولدة. هذا مفيد لتتبع تنفيذ المحلل اللغوي.
--dump-adfa
خيار التصحيح: إخراج DFA بعد التغليف (بتنسيق .dot).
--dump-cfg
خيار التصحيح: إخراج رسم بياني لتدفق التحكم للمتغيرات العلامية (بتنسيق .dot).
--dump-closure-stats
خيار التصحيح: إخراج إحصائيات حول عدد الحالات في الإغلاق.
--dump-dfa-det
خيار التصحيح: إخراج DFA مباشرة بعد التحديد (بتنسيق .dot).
--dump-dfa-min
خيار التصحيح: إخراج DFA بعد التصغير (بتنسيق .dot).
--dump-dfa-tagopt
خيار التصحيح: إخراج DFA بعد تحسينات العلامات (بتنسيق .dot).
--dump-dfa-tree
خيار التصحيح: إخراج DFA قيد الإنشاء مع تمثيل الحالات كأشجار تاريخ العلامات (بتنسيق .dot).
--dump-dfa-raw
خيار التصحيح: إخراج DFA قيد الإنشاء مع مجموعات حالات موسعة (بتنسيق .dot).
--dump-interf
خيار التصحيح: إخراج جدول التداخل الذي تم إنتاجه بواسطة تحليل الحيوية للمتغيرات العلامية.
--dump-nfa
خيار التصحيح: إخراج NFA (بتنسيق .dot).
--emit-dot -D
بدلاً من الإخراج العادي، قم بإنشاء رسم بياني للمحلل اللغوي بتنسيق .dot. يمكن تحويل الإخراج إلى صورة بمساعدة Graphviz (على سبيل المثال، شيء مثل dot -Tpng -odfa.png dfa.dot).
--dfa-minimization <moore | table>
خيار داخلي: خوارزمية تصغير DFA المستخدمة بواسطة re2java. الخيار moore هو خوارزمية مور (وهي الافتراضية). الخيار table هو خوارزمية "ملء الجدول". يجب أن تنتج كلتا الخوارزميتين نفس DFA حتى إعادة تسمية الحالات؛ ملء الجدول أبسط وأبطأ بكثير ويعمل كتطبيق مرجعي.
--eager-skip
خيار داخلي: اجعل المحلل اللغوي المولّد يتقدم بموضع الإدخال بشكل استباقي - مباشرة بعد قراءة رمز الإدخال. هذا يغير السلوك الافتراضي عندما يتم تقدم موضع الإدخال بشكل كسول - بعد الانتقال إلى الحالة التالية.
--no-lookahead
خيار داخلي، تم إهماله. كان يستخدم لتمكين خوارزمية TDFA(0). على عكس TDFA(1)، لا تستخدم خوارزمية TDFA(0) نظرة مستقبلية ذات رمز واحد. إنها تطبق عمليات السجل على الانتقالات الواردة بدلاً من الانتقالات الصادرة. أظهرت المقاييس أن خوارزمية TDFA(0) أقل كفاءة من TDFA(1).
--no-optimize-tags
خيار داخلي: منع تحسين المتغيرات العلامية (مفيد للتصحيح).
--posix-closure <gor1 | gtop>
خيار داخلي: تحديد خوارزمية أقصر مسار المستخدمة لإنشاء الإغلاق الإبسيلوني مع دلالات تمييز POSIX: gor1 (الافتراضي) يرمز إلى خوارزمية Goldberg-Radzik، و gtop يرمز إلى خوارزمية "الترتيب الطوبولوجي العام".
--posix-prectable <complex | naive>
خيار داخلي: تحديد الخوارزمية المستخدمة لحساب جدول أسبقية POSIX. خوارزمية complex تحسب جدول الأسبقية في اجتياز واحد لشجرة تاريخ العلامات ولها تعقيد تربيعي في عدد حالات TNFA؛ وهي الافتراضية. خوارزمية naive لها تعقيد مكعب في أسوأ الحالات لعدد حالات TNFA، ولكنها أبسط بكثير من complex وقد تكون أسرع قليلاً في الحالات غير المستعصية.
--stadfa
خيار داخلي، تم إهماله. كان يستخدم لتمكين خوارزمية staDFA، التي تختلف عن TDFA في أن عمليات السجل توضع في الحالات بدلاً من الانتقالات. أظهرت المقاييس أن خوارزمية staDFA أقل كفاءة من TDFA.
--fixed-tags <none | toplevel | all>
خيار داخلي: تحديد ما إذا كان يجب تطبيق تحسين العلامة الثابتة على جميع العلامات (all)، أو لا شيء منها (none)، أو فقط تلك الموجودة في الربط العلوي (toplevel). الافتراضي هو all. العلامات "الثابتة" هي تلك الموجودة على مسافة ثابتة من علامة أخرى (تسمى "الأساس"). في مثل هذه الحالات، يجب تتبع العلامة الأساسية فقط، ويمكن حساب قيمة العلامة الثابتة كقيمة العلامة الأساسية بالإضافة إلى إزاحة ثابتة. بالنسبة للعلامات الموجودة تحت البديل أو التكرار، من الضروري أيضًا التحقق مما إذا كانت العلامة الأساسية لديها قيمة عدم مطابقة (في هذه الحالة، يجب أيضًا تعيين العلامة الثابتة إلى عدم مطابقة، بغض النظر عن الإزاحة). بالنسبة للعلامات في الربط العلوي، لا يلزم إجراء الفحص، لأنها تتطابق دائمًا.

التعامل مع نهاية الإدخال

إحدى المشكلات الرئيسية للمحلل المعجمي هي معرفة متى يجب التوقف. هناك بضع حالات إنهاء:

  • قد يطابق المحلل المعجمي بعض القواعد (بما في ذلك القاعدة الافتراضية *) ويصل إلى حالة نهائية
  • قد يفشل المحلل المعجمي في مطابقة أي قاعدة ويصل إلى حالة افتراضية
  • قد يصل المحلل المعجمي إلى نهاية الإدخال

الحالتان الأوليان تنهيان المحلل المعجمي بطريقة "طبيعية": يصل إلى حالة بدون انتقالات صادرة، ويتوقف المطابقة تلقائيًا. الحالة الثالثة، نهاية الإدخال، مختلفة: قد تحدث في أي حالة، ويجب أن يكون المحلل المعجمي قادرًا على التعامل معها. التحقق من نهاية الإدخال يقاطع سير عمل المحلل المعجمي العادي ويضيف فروعًا شرطية إلى البرنامج الذي تم إنشاؤه، لذلك من الضروري تقليل عدد هذه عمليات التحقق. يدعم re2java بضع طرق مختلفة للتعامل مع نهاية الإدخال. يعتمد اختيار الطريقة التي يجب استخدامها على مدى تعقيد التعبيرات العادية، والحاجة إلى التخزين المؤقت، واعتبارات الأداء، وعوامل أخرى. فيما يلي قائمة بالطرق:

  • علامة مميزة. تلغي هذه الطريقة الحاجة إلى عمليات التحقق من نهاية الإدخال تمامًا. إنها بسيطة وفعالة، ولكنها تقتصر على الحالة التي توجد فيها "علامة مميزة" طبيعية لا يمكن أن تحدث أبدًا في الإدخال الصالح. قد تحدث هذه العلامة في الإدخال غير الصالح، ولكن لا ينبغي السماح بها بواسطة التعبيرات العادية، إلا ربما كآخر حرف في قاعدة. يتم إلحاق العلامة المميزة بنهاية الإدخال وتعمل كإشارة توقف: عندما يقرأ المحلل المعجمي هذه العلامة، فهي إما خطأ في الصيغة أو نهاية الإدخال. في كلتا الحالتين يجب أن يتوقف المحلل المعجمي. تُستخدم هذه الطريقة إذا تم تعطيل YYFILL باستخدام re2c:yyfill:enable = 0; و re2c:eof لها القيمة الافتراضية -1.
  • علامة مميزة مع فحوصات الحدود. هذه الطريقة عامة: تسمح للمرء بالتعامل مع أي إدخال دون قيود على التعبيرات العادية. الفكرة هي تقليل عدد عمليات التحقق من نهاية الإدخال عن طريق إجرائها فقط على أحرف معينة. على غرار طريقة "العلامة المميزة"، يتم اختيار أحد الأحرف كـ "علامة مميزة" وإلحاقها بنهاية الإدخال. ومع ذلك، لا يوجد قيد على مكان حدوث العلامة المميزة (في الواقع، يمكن اختيار أي حرف كعلامة مميزة). عندما يقرأ المحلل المعجمي هذه العلامة، فإنه يقوم أيضًا بفحص الحدود. إذا كان الموضع الحالي ضمن الحدود، يستأنف المحلل المعجمي المطابقة ويتعامل مع العلامة المميزة كحرف عادي. وإلا، فإنه يستدعي YYFILL (ما لم يتم تعطيله). إذا تم توفير المزيد من الإدخال، سيقوم المحلل المعجمي بإعادة مطابقة الحرف الأخير والاستمرار كما لو لم تكن العلامة المميزة موجودة. وإلا، فيجب أن تكون نهاية الإدخال الحقيقية، ويتوقف المحلل المعجمي. تُستخدم هذه الطريقة عندما يكون re2c:eof قيمة غير سالبة (يجب تعيينها إلى القيمة الرقمية للعلامة المميزة). YYFILL اختياري.
  • فحوصات الحدود مع الحشو. هذه الطريقة عامة، وقد تكون أسرع من طريقة "العلامة المميزة مع فحوصات الحدود"، ولكنها أيضًا أكثر تعقيدًا. الفكرة هي تقسيم حالات DFA إلى مكونات مرتبطة بقوة (SCCs) وإنشاء فحص واحد لكل SCC لعدد كافٍ من الأحرف لتغطية أطول مسار غير حلقي في هذا SCC. هذا يقلل من عدد الفحوصات، ولكن هناك مشكلة مع التعبيرات المعجمية القصيرة في نهاية الإدخال، حيث يتطلب الفحص عددًا كافيًا من الأحرف لتغطية أطول تعبير معجمي. يمكن إصلاح ذلك عن طريق حشو الإدخال ببضع أحرف وهمية لا تشكل لاحقة تعبير معجمي صالحة (بحيث لا يمكن للمحلل المعجمي مطابقتها). يجب أن يكون طول الحشو YYMAXFILL، الذي يتم إنشاؤه باستخدام كتلة max. إذا لم يكن هناك إدخال كافٍ، يستدعي المحلل المعجمي YYFILL الذي يجب أن يوفر على الأقل العدد المطلوب من الأحرف أو لا يعود. تُستخدم هذه الطريقة إذا تم تمكين YYFILL و re2c:eof هو -1 (هذا هو التكوين الافتراضي).
  • الفحوصات المخصصة. تتيح واجهة برمجة التطبيقات العامة تجاوز العمليات الأساسية مثل قراءة حرف، مما يجعل من الممكن تضمين فحوصات نهاية الإدخال كجزء منها. هذا النهج عرضة للأخطاء ويجب استخدامه بحذر. لاستخدام طريقة مخصصة، قم بتمكين واجهة برمجة التطبيقات العامة باستخدام --api custom أو re2c:api = custom; وتعطيل فحوصات الحدود الافتراضية باستخدام re2c:yyfill:enable = 0; أو re2c:yyfill:check = 0;.

BUFFER REFILLING

The need for buffering arises when the input cannot be mapped in memory all at once: either it is too large, or it comes in a streaming fashion (like reading from a socket). The usual technique in such cases is to allocate a fixed-sized memory buffer and process input in chunks that fit into the buffer. When the current chunk is processed, it is moved out and new data is moved in. In practice it is somewhat more complex, because lexer state consists not of a single input position, but a set of interrelated positions:

  • cursor: the next input character to be read (YYCURSOR in C pointer API or YYSKIP/YYPEEK in generic API)
  • limit: the position after the last available input character (YYLIMIT in C pointer API, implicitly handled by YYLESSTHAN in generic API)
  • marker: the position of the most recent match, if any (YYMARKER in default API or YYBACKUP/YYRESTORE in generic API)
  • token: the start of the current lexeme (implicit in re2java API, as it is not needed for the normal lexer operation and can be defined and updated by the user)
  • context marker: the position of the trailing context (YYCTXMARKER in C pointer API or YYBACKUPCTX/YYRESTORECTX in generic API)
  • tag variables: submatch positions (defined with stags and mtags blocks and generic API primitives YYSTAGP/YYSTAGN/YYMTAGP/YYMTAGN)

Not all these are used in every case, but if used, they must be updated by YYFILL. All active positions are contained in the segment between token and cursor, therefore everything between buffer start and token can be discarded, the segment from token and up to limit should be moved to the beginning of buffer, and the free space at the end of buffer should be filled with new data. In order to avoid frequent YYFILL calls it is best to fill in as many input characters as possible (even though fewer characters might suffice to resume the lexer). The details of YYFILL implementation are slightly different depending on which EOF handling method is used: the case of EOF rule is somewhat simpler than the case of bounds-checking with padding. Also note that if -f --storable-state option is used, YYFILL has slightly different semantics (described in the section about storable state).

YYFILL with sentinel

If EOF rule is used, YYFILL is a function-like primitive that accepts no arguments and returns a value which is checked against zero. YYFILL invocation is triggered by condition YYLIMIT <= YYCURSOR in C pointer API and YYLESSTHAN() in generic API. A non-zero return value means that YYFILL has failed. A successful YYFILL call must supply at least one character and adjust input positions accordingly. Limit must always be set to one after the last input position in buffer, and the character at the limit position must be the sentinel symbol specified by re2c:eof configuration. // re2java $INPUT -o $OUTPUT
import java.io.*;
import java.nio.file.*;
class Lexer {
    public static final int BUFSIZE = 4096;
    private BufferedInputStream stream;
    private byte[] yyinput;
    private int yycursor;
    private int yymarker;
    private int yylimit;
    private int token;
    private boolean eof;
    public Lexer(File file) throws FileNotFoundException {
        stream = new BufferedInputStream(new FileInputStream(file));
        // Sentinel at `yylimit` offset is set to zero, which triggers YYFILL.
        yyinput = new byte[BUFSIZE + 1];
        yycursor = yymarker = yylimit = token = BUFSIZE;
        eof = false;
    }
    private int fill() throws IOException {
        if (eof) { return -1; } // unexpected EOF
        // Error: lexeme too long. In real life can reallocate a larger buffer.
        if (token < 1) { return -2; }
        // Shift buffer contents (discard everything up to the current token).
        System.arraycopy(yyinput, token, yyinput, 0, yylimit - token);
        yycursor -= token;
        yymarker -= token;
        yylimit -= token;
        token = 0;
        // Read new data.
        int ret = stream.read(yyinput, yylimit, BUFSIZE - yylimit);
        if (ret == -1) {
            eof = true; // No more input.
            yyinput[BUFSIZE] = 0; // Set sentinel.
        } else {
            yylimit += ret;
        }
        // Set limit to one past the last byte.
        yylimit++;
        return ret;
    }
    public int lex() throws IOException {
        int count = 0;
        loop: while (true) {
            /*!re2c
                re2c:YYCTYPE = "byte";
                re2c:YYPEEK = "yyinput[yycursor]";
                re2c:YYFILL = "fill()";
                re2c:eof = 0;
                str = ['] ([^'\\] | [\\][^])* ['];
                *    { return -1; }
                [\x00] { return count; } // Sentinel hit.
                str  { count += 1; continue loop; }
                [ ]+ { continue loop; }
            */
        }
    }
    public static void main(String []args) throws IOException {
        File file = new File("input.txt");
        FileWriter writer = new FileWriter(file);
        writer.write("'qu\'tes' are fine: \\''\n"); // 3 strings
        writer.close();
        Lexer lexer = new Lexer(file);
        assert lexer.lex() == 3;
        file.delete();
    }
};

YYFILL with padding

In the default case (when EOF rule is not used) YYFILL is a function-like primitive that accepts a single argument and does not return any value. YYFILL invocation is triggered by condition (YYLIMIT - YYCURSOR) < n in C pointer API and YYLESSTHAN(n) in generic API. The argument passed to YYFILL is the minimal number of characters that must be supplied. If it fails to do so, YYFILL must not return to the lexer (for that reason it is best implemented as a macro that returns from the calling function on failure). In case of a successful YYFILL invocation the limit position must be set either to one after the last input position in buffer, or to the end of YYMAXFILL padding (in case YYFILL has successfully read at least n characters, but not enough to fill the entire buffer). The pictures below show the relative locations of input positions in buffer before and after YYFILL invocation (YYMAXFILL padding on the second picture is marked with # symbols).

import java.nio.file.*;
import java.util.Arrays;

    /*!max:re2c*/
    public static final int BUFSIZE = 4096;
    private BufferedInputStream stream;
    private byte[] yyinput;
    private int yycursor;
    private int yylimit;
    private int token;
    private boolean eof;

        stream = new BufferedInputStream(new FileInputStream(file));
        // Prepare lexer state: all offsets are at the end of buffer.
        // This immediately triggers YYFILL, as the YYLESSTHAN condition is true.
        yyinput = new byte[BUFSIZE + YYMAXFILL];
        yycursor = yylimit = token = BUFSIZE;
        eof = false;
    }
    private int fill(int need) throws IOException {
        if (eof) { return -1; } // unexpected EOF
        // Error: lexeme too long. In real life can reallocate a larger buffer.
        if (token < need) { return -2; }
        // Shift buffer contents (discard everything up to the current token).
        System.arraycopy(yyinput, token, yyinput, 0, yylimit - token);
        yycursor -= token;
        yylimit -= token;
        token = 0;
        // Fill free space at the end of buffer with new data from file.
        yylimit += stream.read(yyinput, yylimit, BUFSIZE - yylimit);
        yyinput[yylimit] = 0; // append sentinel symbol
        // If read less than expected, this is the end of input.
        if (yylimit < BUFSIZE) {
            eof = true;
            Arrays.fill(yyinput, yylimit, yylimit + YYMAXFILL, (byte)0);
            yylimit += YYMAXFILL;
        }
        return 0;
    }
    // Expects a null-terminated string.
    public int lex() throws IOException {
        int count = 0;
        loop: while (true) {
            token = yycursor;
            /*!re2c
                re2c:YYCTYPE = "byte";
                re2c:YYPEEK = "yyinput[yycursor]";
                re2c:YYFILL = "if (fill(@@) != 0) { return -2; }";
                str = ['\] ([^'\\] | [\\][^])* ['];
                [\x00] {
                    // Check that it is the sentinel, not some unexpected null.
                    return (token == yylimit - YYMAXFILL) ? count : -1;
                }
                str  { count += 1; continue loop; }
                [ ]+ { continue loop; }
                *    { return -1; }
            */
        }
    }
    public static void main(String []args) throws FileNotFoundException, IOException {
        String fname = "input";
        String content = "'qu\0tes' 'are' 'fine: \\'' ".repeat(Lexer.BUFSIZE);
        // Prepare input file: a few times the size of the buffer, containing
        // strings with zeroes and escaped quotes.
        Files.writeString(Paths.get(fname), content);
        int count = 3 * Lexer.BUFSIZE; // number of quoted strings written to file
        // Prepare lexer state: all offsets are at the end of buffer.
        File file = new File(".", fname);
        Lexer lexer = new Lexer(file);
        // Run the lexer.
        int n = lexer.lex();
        assert n == count;
        // Cleanup: remove input file.
        file.delete();
    }
};

FEATURES

Multiple blocks

Sometimes it is necessary to have multiple interrelated lexers (for example, if there is a high-level state machine that transitions between lexer modes). This can be implemented using multiple connected re2java blocks. Another option is to use start conditions.

The implementation of connections between blocks depends on the target language. In languages that have goto statement (such as C/C++ and Go) one can have all blocks in one function, each of them prefixed with a label. Transition from one block to another is a simple goto. In languages that do not have goto (such as Rust) it is necessary to use a loop with a switch on a state variable, similar to the yystate loop/switch generated by re2java, or else wrap each block in a function and use function calls.

The example below uses multiple blocks to parse binary, octal, decimal and hexadecimal numbers. Each base has its own block. The initial block determines base and dispatches to other blocks. Common configurations are defined in a separate block at the beginning of the program; they are inherited by the other blocks.

// re2java $INPUT -o $OUTPUT
class Parser {
    private String yyinput;
    private int yycursor;
    private int yymarker;
    private int number;
    private void add_digit(int base, int offset) throws ArithmeticException {
        number = Math.addExact(
            Math.multiplyExact(number, base),
            yyinput.charAt(yycursor - 1) - offset);
    }
    public int parse(String str) throws ArithmeticException, IllegalArgumentException {
        yyinput = str;
        yycursor = 0;
        number = 0;
        try {
            /*!re2c
                re2c:YYCTYPE = "char";
                re2c:YYPEEK = "yyinput.charAt(yycursor)";
                re2c:yyfill:enable = 0;
                end = "\x00";
                '0b' / [01]        { return parse_bin(); }
                "0"                { return parse_oct(); }
                ""   / [1-9]       { return parse_dec(); }
                '0x' / [0-9a-fA-F] { return parse_hex(); }
                *                  { throw new IllegalArgumentException("not a number"); }
            */
        } catch (Exception e) {
            return -1;
        }
    }
    private int parse_bin() throws ArithmeticException, IllegalArgumentException {
        /*!re2c
            end   { return number; }
            [01]  { add_digit(2, 48); return parse_bin(); }
            *     { throw new IllegalArgumentException("ill-formed binary number"); }
        */
    }
    private int parse_oct() throws ArithmeticException, IllegalArgumentException {
        /*!re2c
            end   { return number; }
            [0-7] { add_digit(8, 48); return parse_oct(); }
            *     { throw new IllegalArgumentException("ill-formed octal number"); }
        */
    }
    private int parse_dec() throws ArithmeticException, IllegalArgumentException {
        /*!re2c
            end   { return number; }
            [0-9] { add_digit(10, 48); return parse_dec(); }
            *     { throw new IllegalArgumentException("ill-formed decimal number"); }
        */
    }
    private int parse_hex() throws ArithmeticException, IllegalArgumentException {
        /*!re2c
            end   { return number; }
            [0-9] { add_digit(16, 48); return parse_hex(); }
            [a-f] { add_digit(16, 87); return parse_hex(); }
            [A-F] { add_digit(16, 55); return parse_hex(); }
            *     { throw new IllegalArgumentException("ill-formed hexadecimal number"); }
        */
    }
    public static void main(String []args) {
        Parser parser = new Parser();
        assert parser.parse("1234567890\0") == 1234567890;
        assert parser.parse("0b1101\0") == 0b1101;
        assert parser.parse("0x007Fe\0") == 0x7fe;
        assert parser.parse("0644\0") == 0644;
        assert parser.parse("9999999999\0") == -1;
        assert parser.parse("123??\0") == -1;
    }
};

شروط البدء

يتم تمكين شروط البدء باستخدام الخيار --start-conditions. وهي توفر طريقة لتشفير عدة آلات تلقائية مترابطة داخل نفس كتلة re2java.

يتوافق كل شرط مع آلة تلقائية واحدة وله اسم فريد يحدده المستخدم ورقم داخلي فريد يعرفه re2java. تُستخدم الأرقام للتبديل بين الشروط: يستخدم الكود الذي تم إنشاؤه بدائيات YYGETCOND و YYSETCOND للحصول على الشرط الحالي أو تعيينه إلى الرقم المحدد. استخدم كتلة conditions، أو الخيار --header، أو التكوين re2c:header لإنشاء معرفات شروط رقمية. يحدد التكوين re2c:cond:enumprefix بادئة المعرف الذي تم إنشاؤه.

في وضع الشرط، يجب أن تسبق كل قاعدة قائمة بفواصل من أسماء الشروط بين قوسين زاويين، أو رمز بدل <*> للإشارة إلى جميع الشروط. تم توسيع بناء جملة القاعدة على النحو التالي:

< condition-list > regular-expression code
قاعدة يتم دمجها مع كل شرط في condition-list. تتطابق مع regular-expression وتنفذ code المرتبط بها.
< condition-list > regular-expression => condition code
قاعدة يتم دمجها مع كل شرط في condition-list. تتطابق مع regular-expression، وتعين الشرط الحالي إلى condition، وتنفذ code المرتبط بها.
< condition-list > regular-expression :=> condition
قاعدة يتم دمجها مع كل شرط في condition-list. تتطابق مع regular-expression وتنتقل فورًا إلى condition (لا يوجد إجراء دلالي).
< condition-list > !action code
قاعدة تربط code بالمكان المحدد بواسطة action في كل شرط في condition-list (انظر قسم actions لأنواع مختلفة من الإجراءات).
<! condition-list > code
قاعدة تسبق code بالإجراءات الدلالية لجميع القواعد لكل شرط في condition-list. تم إيقاف استخدام بناء الجملة هذا، ويجب استخدام الإجراء !pre_rule بدلاً منه (يقوم بنفس الشيء بالضبط).
< > code
قاعدة تنشئ شرط بدء خاص بالرقم صفر والاسم "0" والذي ينفذ code قبل القفز إلى شروط أخرى. تم إيقاف استخدام بناء الجملة هذا، ويجب استخدام الإجراء !entry بدلاً منه (يوفر تحكمًا أكثر دقة، حيث يمكن تحديد الكود لكل شرط على حدة، ويمكن القفز مباشرة إلى بداية الشرط دون المرور عبر توزيع الشروط).
< > => condition code
نفس القاعدة السابقة، باستثناء أنها تعين condition التالية.
< > :=> condition
نفس القاعدة السابقة، باستثناء أنها لا تحتوي على كود مرتبط بها وتقفز فورًا إلى condition.

يعتمد الكود الذي ينشئه re2java للشروط على ما إذا كان re2java يستخدم نهج goto/label أو نهج loop/switch لتشفير الآلات التلقائية.

في اللغات التي تحتوي على جملة goto (مثل C/C++ و Go)، يتم تنفيذ الشروط بشكل طبيعي على شكل كتل من الكود مسبوقة بعناوين من النوع yyc_<cond>، حيث cond هو اسم شرط (يمكن تغيير بادئة العنوان باستخدام re2c:cond:prefix). يتم تنفيذ الانتقالات بين الشروط باستخدام goto وعناوين الشروط. قبل جميع الشروط، يقوم re2java بإنشاء مفتاح تبديل أولي على YYGETSTATE الذي يقفز إلى حالة البداية للشرط الحالي. تختصر القواعد المختصرة :=> مفتاح التبديل الأولي وتقفز مباشرة إلى الشرط المحدد (يمكن استخدام re2c:cond:goto لتغيير السلوك الافتراضي). القواعد ذات الإجراءات الدلالية لا تقفز تلقائيًا إلى الشرط التالي؛ يجب القيام بذلك بواسطة الكود الإجرائي المحدد من قبل المستخدم.

في اللغات التي لا تحتوي على goto (مثل Rust)، يعيد re2java استخدام المتغير yystate لتخزين أرقام الشروط. يحصل كل شرط على معرف رقمي يساوي عدد حالة بدايته، ولا يختلف التبديل بين الشروط عن التبديل بين حالات DFA لشرط واحد. لا توجد حاجة لمفتاح تبديل شرط أولي منفصل. (نظرًا لأنه يتم استخدام نفس النهج لتنفيذ الحالات القابلة للتخزين، فإن YYGETCOND/YYSETCOND غير ضروريين إذا تم استخدام كل من الحالات القابلة للتخزين والشروط).

يستخدم البرنامج أدناه شروط البدء لتحليل الأرقام الثنائية، الثمانية، العشرية، والسداسية عشرية. توجد كتلة واحدة حيث يكون لكل قاعدة شرط خاص بها، والشرط الأولي متصل بجميعها. يخزن المتغير المعرف من قبل المستخدم cond رقم الشرط الحالي؛ يتم تهيئته برقم الشرط الأولي الذي تم إنشاؤه بواسطة كتلة conditions.

الحالة القابلة للتخزين

مع الخيار --storable-state، يقوم re2java بإنشاء محلل يمكنه تخزين حالته الحالية، والعودة إلى المتصل، ولاحقًا استئناف العمليات بالضبط من حيث توقف. الوضع الافتراضي للتشغيل في re2java هو نموذج "السحب"، حيث "يسحب" المحلل المزيد من المدخلات كلما احتاج إليها. قد يكون هذا غير مقبول في الحالات التي تتوفر فيها المدخلات قطعة قطعة (على سبيل المثال، إذا تم استدعاء المحلل بواسطة المحلل، أو إذا كان برنامج المحلل يتواصل عبر بروتوكول مقبس مع برنامج آخر يجب أن ينتظر ردًا من المحلل قبل أن ينقل الرسالة التالية). ميزة الحالة القابلة للتخزين مخصصة لهذه الحالات بالضبط: فهي تسمح بإنشاء محللات تعمل بنموذج "الدفع". عندما يحتاج المحلل إلى المزيد من المدخلات، فإنه يخزن حالته ويعود إلى المتصل. لاحقًا، عندما تتوفر المزيد من المدخلات، يستأنف المتصل المحلل بالضبط من حيث توقف. هناك عدد قليل من التغييرات الضرورية مقارنة بنموذج "السحب":

  • تعريف بدائيات YYSETSTATE() و YYGETSTATE(state).
  • تعريف متغيرات yych، yyaccept (إذا تم استخدامها)، و state كجزء من حالة المحلل المستمرة. يجب تهيئة المتغير state بالقيمة -1.
  • يجب أن يعود YYFILL إلى البرنامج الخارجي بدلاً من محاولة توفير المزيد من المدخلات. يجب أن يشير رمز الإرجاع إلى أن المحلل يحتاج إلى المزيد من المدخلات.
  • يجب على البرنامج الخارجي التعرف على المواقف التي يحتاج فيها المحلل إلى المزيد من المدخلات والاستجابة بشكل مناسب.
  • اختياريًا، استخدم كتلة getstate لإنشاء مفتاح تبديل YYGETSTATE منفصلاً عن المحلل الرئيسي. هذا يعمل فقط مع اللغات التي تحتوي على goto (ليس في وضع --loop-switch).
  • استخدم re2c:eof وطريقة الرمز المميز مع فحوصات الحدود للتعامل مع نهاية المدخلات. قد لا تعمل الطريقة المعتمدة على الحشو لأنه من غير الواضح متى يتم إلحاق الحشو: قد لا تكون نهاية المدخلات الحالية نهاية المدخلات النهائية، وإلحاق الحشو مبكرًا جدًا قد يقطع جزءًا من مقطع مرموق متعطش. علاوة على ذلك، بسبب منطق البرنامج عالي المستوى، قد يعتمد الحصول على المزيد من المدخلات على معالجة المقطع عند نهاية المخزن المؤقت (الذي تم حظره بالفعل بسبب شرط نهاية المدخلات).

إليك مثال لمحلل بنموذج "الدفع" يحاكي قراءة حزم من مقبس. يتكرر المحلل حتى يواجه نهاية المدخلات ويعود إلى الدالة المستدعية. يوفر الدالة المستدعية المزيد من المدخلات عن طريق "إرسال" الحزمة التالية ويستأنف التحليل. تتوقف هذه العملية عندما يتم إرسال جميع الحزم، أو عند حدوث خطأ.

دعم الترميز


من الضروري فهم الفرق بين نقاط الترميز و وحدات الترميز. نقطة الترميز هي معرف رقمي للرمز. وحدة الترميز هي أصغر وحدة تخزين في النص المشفر. قد يتم تمثيل نقطة ترميز واحدة بأكثر من وحدة ترميز واحدة. في ترميز ثابت الطول ، يتم تمثيل جميع نقاط الترميز بنفس عدد وحدات الترميز. في ترميز متغير الطول ، قد يتم تمثيل نقاط الترميز بعدد مختلف من وحدات الترميز. لاحظ أن القاعدة "أي" [^] تطابق أي نقطة ترميز ، ولكن ليس بالضرورة أي وحدة ترميز (الطريقة الوحيدة لمطابقة أي وحدة ترميز بغض النظر عن الترميز هي القاعدة الافتراضية *). يعمل المحلل المعجمي الذي تم إنشاؤه مع تدفق وحدات الترميز: yych يخزن وحدة ترميز ، و YYCTYPE هو نوع وحدة الترميز. من ناحية أخرى ، يتم تحديد التعبيرات العادية من حيث نقاط الترميز. عندما يقوم re2java بتجميع التعبيرات العادية إلى آلات ، فإنه يترجم نقاط الترميز إلى وحدات ترميز. هذا بشكل عام ليس رسمًا بسيطًا: في الترميزات متغيرة الطول ، قد يتم ترجمة نطاق نقطة ترميز واحدة إلى رسم بياني معقد لوحدات الترميز. يتم دعم الترميزات التالية:




    
  
  • ASCII (ممكّن افتراضيًا). وهو ترميز ثابت الطول مع مساحة ترميز [0-255] ونقاط ترميز ووحدات ترميز بحجم بايت واحد.
    • 
  
  • EBCDIC (ممكّن باستخدام --ebcdic أو re2c:encoding:ebcdic). وهو ترميز ثابت الطول مع مساحة ترميز [0-255] ونقاط ترميز ووحدات ترميز بحجم بايت واحد.
    •

يتضمن ملف include/unicode_categories.re تعريفات re2java للفئات القياسية لـ Unicode.


يحدد الخيار --input-encoding ترميز ملف المصدر ، والذي يمكن استخدامه لتمكين حروف Unicode في التعبيرات العادية. على سبيل المثال ، يخبر --input-encoding utf8 re2java أن ملف المصدر بتنسيق UTF8 (يختلف عن --utf8 الذي يحدد ترميز نص الإدخال). يحدد الخيار --encoding-policy الطريقة التي يتعامل بها re2java مع أزواج Unicode البديلة (نقاط الترميز في النطاق [0xD800-0xDFFF]).


أدناه مثال على محلل معجمي لمعرفات Unicode المشفرة بتنسيق UTF8.






// re2java $INPUT -o $OUTPUT --utf8 -s
/*!include:re2c "unicode_categories.re" */
class Main {
    static boolean lex(String yyinput) {
        int yycursor = 0;
        int yymarker = 0;
        /*!re2c
            re2c:YYCTYPE = "char";
            re2c:YYPEEK = "yyinput.charAt(yycursor)";
            re2c:yyfill:enable = 0;
            // Simplified "Unicode Identifier and Pattern Syntax"
            // (see https://unicode.org/reports/tr31)
            id_start    = L | Nl | [$_];
            id_continue = id_start | Mn | Mc | Nd | Pc | [\u200D\u05F3];
            identifier  = id_start+;
            // It should be `id_start id_continue*`, but that causes `error: code too large`
            identifier { return true; }
            *          { return false; }
        */
    }
    public static void main(String []args) {
        assert lex("_\u042B\u0434\u0435\u043D\u0442\u0438\u0444\u0438\u043A\u0430\u0442\u043E\u0440\0");
    }
};










ملفات التضمين


يسمح re2java بتضمين ملفات أخرى باستخدام كتلة بالشكل /*!include:re2c FILE */ أو %{include FILE %}، أو توجيه داخل الكتلة !include FILE ;، حيث FILE هو مسار إلى الملف المراد تضمينه. يبحث re2java عن ملفات التضمين في دليل الملف المضمن وفي مواقع التضمين ، والتي يمكن تحديدها باستخدام الخيار -I. تعمل كتل / توجيهات التضمين في re2java بنفس الطريقة التي تعمل بها #include في C / C ++: يتم نسخ محتويات FILE حرفيًا في مكان الكتلة / التوجيه. قد تحتوي ملفات التضمين على تضمينات إضافية خاصة بها. استخدم الخيار --depfile لتتبع تبعيات البناء لملف الإخراج على ملفات التضمين. يوفر re2java بعض ملفات التضمين المعرفة مسبقًا والتي يمكن العثور عليها في الدليل الفرعي include/ للمشروع. تحتوي هذه الملفات على تعريفات قد تكون مفيدة للمشاريع الأخرى (مثل فئات Unicode) وتشكل شيئًا مثل مكتبة قياسية لـ re2java. فيما يلي مثال على استخدام ملفات التضمين.

ملفات الرأس


يسمح re2java بإنشاء ملف رأس من ملف .re الإدخال باستخدام الخيار --header أو التكوين re2c:header وأزواج الكتل بالشكل /*!header:re2c:on*/ و /*!header:re2c:off*/، أو %{header:on%} و %{header:off%}. تشير الكتلة الأولى إلى بداية ملف الرأس ، وتشير الثانية إلى نهايته. تتم معالجة كل شيء بين هاتين الكتلتين بواسطة re2java ، ويتم كتابة الكود الذي تم إنشاؤه إلى الملف المحدد باستخدام الخيار --header أو التكوين re2c:header (أو stdout إذا لم يتم استخدام أي خيار أو تكوين). قد يكون ملف الرأس الذي تم إنشاؤه تلقائيًا مطلوبًا في الحالات التي يتم فيها استخدام re2java لإنشاء تعريفات يجب أن تكون مرئية من وحدات ترجمة أخرى.


إليك مثال على إنشاء ملف رأس يحتوي على تعريف حالة المحلل المعجمي مع متغيرات العلامات (تعتمد متغيرات الأرقام على القواعد النحوية العادية وهي غير معروفة للمبرمج).






ملف الإدخال






// re2java $INPUT -o $OUTPUT --header lexer/state.java
package headers;
import headers.lexer.State;
/*!header:re2c:on*/
package headers.lexer;
public class State {
    public String yyinput;
    public int yycursor;
    /*!stags:re2c format = "public int @@;\n"; */
    public State(String str) {
        yyinput = str;
        yycursor = 0;
        /*!stags:re2c format = "@@ = 0;\n"; */
    }
};
/*!header:re2c:off*/
class Main {
    static int lex(String str) {
        State yyrecord = new State(str);
        int t;
        /*!re2c
            re2c:api = record;
            re2c:tags = 1;
            re2c:yyfill:enable = 0;
            re2c:YYCTYPE = "char";
            re2c:YYPEEK = "yyrecord.yyinput.charAt(yyrecord.yycursor)";
            re2c:header = "lexer/state.java";
            [a]* @t [b]* { return t; }
        */
    }
    public static void main(String []args) {
        assert lex("ab\0") == 1;
    }
};
