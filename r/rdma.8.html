rdma(8)

الحزمة: iproute2

التراخيص: GPL-2.0-or-later

RDMA(8) Linux RDMA(8)

الاسم

rdma - أداة RDMA

المُلَخَّص


rdma [ خيارات ] كائن { أمر | help }

rdma [ -force ] -batch اسم_ملف

كائن := { dev | link | resource | system | statistic | monitor }

خيارات := { -V[ersion] | -d[etails] | -j[son] | -o[neline] | -p[retty] }

الخيارات

-V, -Version
طباعة إصدار أداة rdma والخروج.
-b, -batch <اسم_ملف>
قراءة الأوامر من الملف المقدم أو المدخل القياسي وتنفيذها. أول فشل سيؤدي إلى إنهاء rdma.
-force
لا تنهِ rdma عند حدوث أخطاء في وضع الدُفعات. إذا كانت هناك أي أخطاء أثناء تنفيذ الأوامر، فسيكون رمز حالة الإرجاع الخاص بالتطبيق غير صفري.
-d, --details
إخراج معلومات مفصلة. إضافة -d ثانية تشمل تفاصيل خاصة بالبرنامج التشغيلي.
-r, --raw
يشمل الإخراج تفاصيل خاصة بالبرنامج التشغيلي بتنسيق خام.
-p, --pretty
عند دمجه مع -j، قم بإنشاء إخراج JSON جميل.
-j, --json
إنشاء إخراج JSON.
-o, -oneline
إخراج كل سجل في سطر واحد، مع استبدال أحرف الأسطر الجديدة بالحرف '\'.

الكائن

dev
- جهاز RDMA.
link
- متعلق بمنفذ RDMA.
resource
- تكوين موارد RDMA.
sys
- متعلق بنظام RDMA الفرعي.
statistic
- متعلق بإحصائيات عدادات RDMA.
monitor
- مراقب أحداث RDMA

يمكن كتابة أسماء جميع الكائنات بشكل كامل أو مختصر، على سبيل المثال يمكن اختصار stats بـ stat أو مجرد s.

الأمر

يحدد الإجراء المراد تنفيذه على الكائن. تعتمد مجموعة الإجراءات الممكنة على نوع الكائن. كقاعدة عامة، من الممكن عرض (أو سرد ) الكائنات، ولكن بعض الكائنات لا تسمح بجميع هذه العمليات أو لديها بعض الأوامر الإضافية. الأمر help متاح لجميع الكائنات. يقوم بطباعة قائمة بالأوامر المتاحة واتفاقيات بناء جملة الوسائط.

إذا لم يتم إعطاء أمر، يتم افتراض أمر افتراضي. عادة ما يكون list أو، إذا كانت الكائنات من هذه الفئة لا يمكن سردها، help.

حالة الخروج

حالة الخروج هي 0 إذا كان الأمر ناجحًا أو عددًا صحيحًا موجبًا عند الفشل.

أبلغ عن أي أخطاء إلى قائمة بريد Linux RDMA <linux-rdma@vger.kernel.org> حيث يتم إجراء التطوير والصيانة بشكل أساسي. لست بحاجة إلى الاشتراك في القائمة لإرسال رسالة إليها.
