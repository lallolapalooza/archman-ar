لأغراض التوافق عبر إصدارات المستودعات، يتم تجاهل جميع العناصر غير المعروفة بصمت. ومع ذلك، يحتفظ المستودع بجميع الأسماء الممكنة لنفسه لاستخدامها المستقبلي. إذا كنت ترغب في استخدام عناصر مخصصة، فإن مساحة الاسم `x-*` محجوزة لهذا الغرض، ويتعهد المستودع بعدم تخصيص أي أسماء مقابلة لها على الإطلاق.

يتبع وصف للعناصر وسماتها.

عنصر manifest

العنصر الجذر للملف.

عنصر notice

نص عشوائي يتم عرضه للمستخدمين عند انتهاء `repo sync`. يتم ببساطة تمرير المحتوى كما هو موجود في البيان.

عنصر remote

يمكن تحديد عنصر أو أكثر من عناصر المستودعات البعيدة. يحدد كل عنصر مستودع بعيد عنوان URL لمستودع Git مشترك بواسطة مشروع واحد أو أكثر و (اختياريًا) خادم مراجعة Gerrit الذي تقوم المشاريع بتحميل التغييرات من خلاله.

السمة `name`: اسم قصير فريد لهذا الملف البيان. يتم استخدام الاسم المحدد هنا كاسم بعيد في ملف `.git/config` لكل مشروع، وبالتالي فهو متاح تلقائيًا لأوامر مثل `git fetch` و `git remote` و `git pull` و `git push`.

السمة `alias`: الاسم المستعار، إذا تم تحديده، يستخدم لتجاوز `name` ليتم تعيينه كاسم بعيد في ملف `.git/config` لكل مشروع. يمكن تكرار قيمته بينما يجب أن يكون `name` فريدًا في ملف البيان. هذا يساعد كل مشروع على أن يكون له نفس الاسم البعيد الذي يشير فعليًا إلى عنوان URL بعيد مختلف.

السمة `fetch`: بادئة عنوان URL لمستودع Git لجميع المشاريع التي تستخدم هذا المستودع البعيد. يتم إلحاق اسم كل مشروع بهذه البادئة لتشكيل عنوان URL الفعلي المستخدم لاستنساخ المشروع.

السمة `pushurl`: بادئة عنوان URL "الدفع" لمستودع Git لجميع المشاريع التي تستخدم هذا المستودع البعيد. يتم إلحاق اسم كل مشروع بهذه البادئة لتشكيل عنوان URL الفعلي المستخدم لـ "git push" للمشروع. هذه السمة اختيارية؛ إذا لم يتم تحديدها، فسيستخدم "git push" نفس عنوان URL مثل السمة `fetch`.

السمة `review`: اسم مضيف خادم Gerrit حيث يتم تحميل المراجعات إليه بواسطة `repo upload`. هذه السمة اختيارية؛ إذا لم يتم تحديدها، فلن تعمل `repo upload`.

السمة `revision`: اسم فرع Git (على سبيل المثال، `main` أو `refs/heads/main`). ستقوم المستودعات البعيدة مع مراجعتها الخاصة بتجاوز المراجعة الافتراضية.

عنصر default

يمكن تحديد عنصر افتراضي واحد على الأكثر. يتم استخدام سماته البعيدة والمراجعة عندما لا يحدد عنصر المشروع سمته البعيدة أو المراجعة الخاصة به.

السمة `remote`: اسم لعنصر مستودع بعيد محدد مسبقًا. ستستخدم عناصر المشروع التي تفتقر إلى سمة المستودع البعيد الخاصة بها هذا المستودع البعيد.

السمة `revision`: اسم فرع Git (على سبيل المثال، `main` أو `refs/heads/main`). ستستخدم عناصر المشروع التي تفتقر إلى سمة المراجعة الخاصة بها هذه المراجعة.

السمة `dest-branch`: اسم فرع Git (على سبيل المثال، `main`). لن ترث عناصر المشروع التي لا تحدد `dest-branch` الخاصة بها هذه القيمة. إذا لم يتم تعيين هذه القيمة، فستستخدم المشاريع `revision` افتراضيًا بدلاً من ذلك.

السمة `upstream`: اسم مرجع Git حيث يمكن العثور على sha1. يستخدم عند مزامنة بيان مقيد بالمراجعة في وضع -c لتجنب الاضطرار إلى مزامنة مساحة المرجع بأكملها. ستتلقى عناصر المشروع التي لا تحدد `upstream` الخاصة بها هذه القيمة.

السمة `sync-j`: عدد المهام المتوازية لاستخدامها عند المزامنة.

السمة `sync-c`: يتم تعيينها إلى true لمزامنة فرع Git المحدد فقط (المحدد في السمة `revision`) بدلاً من مساحة المرجع بأكملها. ستستخدم عناصر المشروع التي تفتقر إلى عنصر sync-c الخاص بها هذه القيمة.

السمة `sync-s`: يتم تعيينها إلى true لمزامنة المشاريع الفرعية أيضًا.

السمة `sync-tags`: يتم تعيينها إلى false لمزامنة فرع Git المحدد فقط (المحدد في السمة `revision`) بدلاً من علامات المرجع الأخرى.

عنصر manifest-server

يمكن تحديد عنصر manifest-server واحد على الأكثر. يتم استخدام السمة url لتحديد عنوان URL لخادم البيان، وهو خدمة XML RPC.

راجع [وثائق المزامنة الذكية](./smart-sync.md) لمزيد من التفاصيل.

عنصر submanifest

يمكن تحديد عنصر أو أكثر من عناصر submanifest. يصف كل عنصر بيانًا واحدًا ليتم استخراجه كطفل.

السمة `name`: اسم فريد (ضمن البيان الفرعي الحالي) لهذا البيان الفرعي. يعمل كافتراضي لـ `revision` أدناه. يمكن استخدام نفس الاسم للبيانات الفرعية مع بيانات رئيسية (فرعية) مختلفة.

السمة `remote`: اسم لعنصر مستودع بعيد محدد مسبقًا. إذا لم يتم توفيره، يتم استخدام المستودع البعيد الذي يحدده العنصر الافتراضي.

السمة `project`: اسم مشروع البيان. يتم إلحاق اسم المشروع بعنوان URL للبحث الخاص بالمستودع البعيد لتكوين عنوان URL الفعلي لتهيئة المستودع البعيد. يتم تكوين عنوان URL على النحو التالي:

${remote_fetch}/${project_name}.git

حيث ${remote_fetch} هي سمة البحث الخاصة بالمستودع البعيد و ${project_name} هي سمة الاسم الخاصة بالمشروع. يتم دائمًا إلحاق اللاحقة ".git" حيث يفترض المستودع أن المصدر البعيد هو غابة من المستودعات البعيدة الفارغة. إذا كان للمشروع عنصر أب، فسيتم إضافة اسم الأصل إليه.

يجب أن يتطابق اسم المشروع مع الاسم الذي يعرفه Gerrit، إذا تم استخدام Gerrit لمراجعات التعليمات البرمجية.

يجب ألا يكون `project` فارغًا، ولا يمكن أن يكون مسارًا مطلقًا أو يستخدم مكونات المسار "." أو "..". يتم تفسيره دائمًا بالنسبة لإعدادات البحث الخاصة بالمستودع البعيد، لذا إذا كان مسار أساس مختلف مطلوبًا، فقم بتعريف مستودع بعيد مختلف بالإعدادات الجديدة المطلوبة.

إذا لم يتم توفيره، فسيتم استخدام المستودع البعيد والمشروع لهذا البيان: لا يمكن توفير `remote`.

تتم إضافة المشاريع من بيان فرعي وبياناتها الفرعية إلى مجموعة `submanifest::path:<path_prefix>`.

السمة `manifest-name`: اسم ملف البيان في مشروع البيان. إذا لم يتم توفيره، يتم استخدام `default.xml`.

السمة `revision`: اسم فرع Git (على سبيل المثال، "main" أو "refs/heads/main")، علامة (على سبيل المثال، "refs/tags/stable")، أو تجزئة تعهد. إذا لم يتم توفيره، يتم استخدام `name`.

السمة `path`: مسار اختياري نسبيًا إلى الدليل العلوي لعميل المستودع حيث يجب وضع الدليل العلوي لعميل مستودع البيان الفرعي. إذا لم يتم توفيره، يتم استخدام `revision`.

قد لا يكون `path` مسارًا مطلقًا أو يستخدم مكونات المسار "." أو "..".

السمة `groups`: قائمة بالمجموعات الإضافية التي تنتمي إليها جميع المشاريع في البيان الفرعي المضمن. هذا يضيف ويتكرر، مما يعني أن جميع المشاريع في البيانات الفرعية تحمل جميع مجموعات البيانات الفرعية الأصلية. نفس بناء الجملة مثل العنصر المقابل لـ `project`.

السمة `default-groups`: قائمة بمجموعات البيان التي تتم مزامنتها إذا لم يتم تحديد معلمة `--groups=` عند التهيئة. عندما تكون هذه القائمة فارغة، استخدم هذه القائمة بدلاً من "default" كقائمة للمجموعات التي تتم مزامنتها.

عنصر project

يمكن تحديد عنصر مشروع واحد أو أكثر. يصف كل عنصر مستودع Git واحد ليتم استنساخه في مساحة عمل عميل المستودع. يمكنك تحديد وحدات Git الفرعية عن طريق إنشاء مشروع متداخل. سيتم التعرف على وحدات Git الفرعية تلقائيًا وستكتسب سمات الأصل الخاصة بها، ولكن يمكن تجاوزها بواسطة عنصر مشروع محدد صراحةً.

السمة `name`: اسم فريد لهذا المشروع. يتم إلحاق اسم المشروع بعنوان URL للبحث الخاص بالمستودع البعيد لتكوين عنوان URL الفعلي لتهيئة المستودع البعيد. يتم تكوين عنوان URL على النحو التالي:

${remote_fetch}/${project_name}.git

حيث ${remote_fetch} هي سمة البحث الخاصة بالمستودع البعيد و ${project_name} هي سمة الاسم الخاصة بالمشروع. يتم دائمًا إلحاق اللاحقة ".git" حيث يفترض المستودع أن المصدر البعيد هو غابة من المستودعات البعيدة الفارغة. إذا كان للمشروع عنصر أب، فسيتم إضافة اسم الأصل إليه.

يجب أن يتطابق اسم المشروع مع الاسم الذي يعرفه Gerrit، إذا تم استخدام Gerrit لمراجعات التعليمات البرمجية.

يجب ألا يكون "name" فارغًا، ولا يمكن أن يكون مسارًا مطلقًا أو يستخدم مكونات المسار "." أو "..". يتم تفسيره دائمًا بالنسبة لإعدادات البحث الخاصة بالمستودع البعيد، لذا إذا كان مسار أساس مختلف مطلوبًا، فقم بتعريف مستودع بعيد مختلف بالإعدادات الجديدة المطلوبة. لا يتم فرض هذه القيود على [البيانات المحلية].

السمة `path`: مسار اختياري نسبيًا إلى الدليل العلوي لعميل المستودع حيث يجب وضع دليل العمل لمستودع Git لهذا المشروع. إذا لم يتم توفيره، يتم استخدام "name" الخاص بالمشروع. إذا كان للمشروع عنصر أب، فسيتم إضافة بادئة مسار الأصل إليه.

قد لا يكون "path" مسارًا مطلقًا أو يستخدم مكونات المسار "." أو "..". لا يتم فرض هذه القيود على [البيانات المحلية].

إذا كنت ترغب في وضع ملفات في جذر الفحص (على سبيل المثال، ملف README أو Makefile أو نص برمجي بناء آخر)، فاستخدم العناصر [copyfile] أو [linkfile] بدلاً من ذلك.

السمة `remote`: اسم لعنصر مستودع بعيد محدد مسبقًا. إذا لم يتم توفيره، يتم استخدام المستودع البعيد الذي يحدده العنصر الافتراضي.

السمة `revision`: اسم فرع Git الذي يريده البيان لتتبعه لهذا المشروع. يمكن أن تكون الأسماء نسبية إلى refs/heads (على سبيل المثال، فقط "main") أو مطلقة (على سبيل المثال، "refs/heads/main"). يجب أن تعمل العلامات و / أو SHA-1s الصريحة نظريًا، ولكن لم يتم اختبارها على نطاق واسع. إذا لم يتم توفيره، يتم استخدام المراجعة التي يوفرها عنصر المستودع البعيد إذا كان ذلك منطبقًا، وإلا يتم استخدام العنصر الافتراضي.

السمة `dest-branch`: اسم فرع Git (على سبيل المثال، `main`). عند استخدام `repo upload`، سيتم تقديم التغييرات للمراجعة على هذا الفرع. إذا لم يتم تحديدها هنا وفي العنصر الافتراضي، فسيتم استخدام `revision` بدلاً من ذلك.

السمة `groups`: قائمة بالمجموعات التي ينتمي إليها هذا المشروع، مفصولة بمسافات بيضاء أو فواصل. تنتمي جميع المشاريع إلى المجموعة "all"، وينتمي كل مشروع تلقائيًا إلى مجموعة باسمه: `name` ومساره: `path`. على سبيل المثال، بالنسبة لـ `<project name="monkeys" path="barrel-of"/>`، فإن تعريف المشروع هذا موجود ضمنيًا في مجموعات البيان التالية: default، name:monkeys، و path:barrel-of. إذا وضعت مشروعًا في المجموعة "notdefault"، فلن يتم تنزيله تلقائيًا بواسطة المستودع. إذا كان للمشروع عنصر أب، فإن `name` و `path` هنا هما الأصول المسبقة.

السمة `sync-c`: يتم تعيينها إلى true لمزامنة فرع Git المحدد فقط (المحدد في السمة `revision`) بدلاً من مساحة المرجع بأكملها.

السمة `sync-s`: يتم تعيينها إلى true لمزامنة المشاريع الفرعية أيضًا.

السمة `upstream`: اسم مرجع Git حيث يمكن العثور على sha1. يستخدم عند مزامنة بيان مقيد بالمراجعة في وضع -c لتجنب الاضطرار إلى مزامنة مساحة المرجع بأكملها.

>

الخاصية `clone-depth`: تحديد العمق الذي سيتم استخدامه عند جلب هذا المشروع. إذا تم تحديده، فإن هذه القيمة ستتجاوز أي قيمة تم إعطاؤها لـ `repo init` باستخدام الخيار --depth في سطر الأوامر.

الخاصية `force-path`: تعيين على `true` لإجبار هذا المشروع على إنشاء مستودع المرآة المحلي وفقًا لخاصية `path` الخاصة به (إذا تم توفيرها) بدلاً من خاصية `name`. تنطبق هذه الخاصية فقط على مزامنة المرايا المحلية، وسيتم تجاهلها عند مزامنة المشاريع في دليل عمل العميل.

العنصر extend-project

تعديل خصائص المشروع المسمى.

هذا العنصر مفيد في الغالب في ملف قائمة محلية، لتعديل خصائص مشروع موجود دون استبدال تعريف المشروع الحالي بالكامل. هذا يجعل القائمة المحلية أكثر متانة ضد التغييرات في القائمة الأصلية.

الخاصية `path`: إذا تم تحديدها، فقم بتحديد التغيير للمشاريع التي تم استنساؤها في المسار المحدد، بدلاً من جميع المشاريع التي تحمل نفس الاسم.

الخاصية `dest-path`: إذا تم تحديدها، فإنها تمثل مسارًا نسبيًا إلى الدليل العلوي لعميل `repo` حيث يجب وضع دليل عمل Git لهذا المشروع. يُستخدم هذا لنقل مشروع في الاستنساخ عن طريق تجاوز إعداد `path` الحالي.

الخاصية `groups`: قائمة بالمجموعات الإضافية التي ينتمي إليها هذا المشروع. نفس بناء الجملة مثل العنصر المقابل لـ `project`.

الخاصية `revision`: إذا تم تحديدها، فإنها تتجاوز مراجعة المشروع الأصلي. نفس بناء الجملة مثل العنصر المقابل لـ `project`.

الخاصية `remote`: إذا تم تحديدها، فإنها تتجاوز المستودع البعيد للمشروع الأصلي. نفس بناء الجملة مثل العنصر المقابل لـ `project`.

الخاصية `dest-branch`: إذا تم تحديدها، فإنها تتجاوز فرع الوجهة للمشروع الأصلي. نفس بناء الجملة مثل العنصر المقابل لـ `project`.

الخاصية `upstream`: إذا تم تحديدها، فإنها تتجاوز المصدر الأعلى للمشروع الأصلي. نفس بناء الجملة مثل العنصر المقابل لـ `project`.

الخاصية `base-rev`: إذا تم تحديدها، فإنها تضيف فحصًا مقابل المراجعة التي سيتم توسيعها. سيفشل تحليل القائمة وسيعطي قائمة بالمطابقات الممتدة إذا تغيرت المراجعات التي يتم توسيعها منذ تعيين `base-rev`. مخصص للاستخدام مع القوائم المطبقة باستخدام مراجعات التجزئة لمنع فروع التصحيح من إخفاء مراجعات أحدث للمصدر الأعلى. يقارن أيضًا المراجع المسماة مثل الفروع أو العلامات ولكنه مضلل إذا تم استخدام الفروع كـ `base-rev`. نفس بناء الجملة مثل العنصر المقابل لـ `project`.

العنصر annotation

يمكن تحديد صفر أو أكثر من عناصر التعليقات كعناصر فرعية لعنصر `project` أو `remote`. يصف كل عنصر زوج اسم-قيمة. بالنسبة للمشاريع، سيتم تصدير زوج الاسم-القيمة هذا إلى بيئة كل مشروع أثناء أمر `forall`، مع البادئة `REPO__`. بالإضافة إلى ذلك، هناك خاصية اختيارية "keep" تقبل القيم غير الحساسة لحالة الأحرف "true" (افتراضي) أو "false". تحدد هذه الخاصية ما إذا كان سيتم الاحتفاظ بالتعليق عند تصديره باستخدام الأمر الفرعي `manifest` أم لا.

العنصر copyfile

يمكن تحديد صفر أو أكثر من عناصر `copyfile` كعناصر فرعية لعنصر `project`. يصف كل عنصر زوج ملفات المصدر-الوجهة؛ سيتم نسخ ملف "src" إلى مكان "dest" أثناء أمر `repo sync`.

"src" نسبي للمشروع، "dest" نسبي إلى قمة الشجرة. لا يُسمح بالنسخ من مسارات خارج المشروع أو إلى مسارات خارج عميل `repo`.

يجب أن تكون "src" و "dest" ملفات. لا يُسمح بالدلائل أو الروابط الرمزية. يجب ألا تكون المسارات الوسيطة روابط رمزية أيضًا.

سيتم إنشاء الدلائل الأصلية لـ "dest" تلقائيًا إذا كانت مفقودة.

العنصر linkfile

إنه تمامًا مثل `copyfile` ويعمل في نفس وقت `copyfile` ولكن بدلاً من النسخ، فإنه ينشئ رابطًا رمزيًا.

يتم إنشاء الرابط الرمزي في "dest" (نسبي إلى قمة الشجرة) ويشير إلى المسار المحدد بواسطة "src" وهو مسار في المشروع.

سيتم إنشاء الدلائل الأصلية لـ "dest" تلقائيًا إذا كانت مفقودة.

قد يكون هدف الرابط الرمزي ملفًا أو دليلاً، ولكنه قد لا يشير إلى خارج عميل `repo`.

العنصر remove-project

يحذف مشروعًا من جدول القائمة الداخلي، مما يسمح ربما لعنصر مشروع لاحق في نفس ملف القائمة باستبدال المشروع بتعريف مختلف.

هذا العنصر مفيد في الغالب في ملف قائمة محلية، حيث يمكن للمستخدم إزالة مشروع، وربما استبداله بتعريفه الخاص.

يمكن استخدام `name` المشروع أو `path` المشروع لتحديد هدف الإزالة، مما يعني أن أحدهما مطلوب. إذا تم تحديد `name` فقط، يتم إزالة جميع المشاريع التي تحمل هذا الاسم.

إذا تم تحديد كل من `name` و `path`، يتم إزالة المشاريع التي تحمل نفس الاسم والمسار فقط، مما يعني أنه يتم الاحتفاظ بالمشاريع التي تحمل نفس الاسم ولكن في مواقع أخرى.

إذا تم تحديد `path` فقط، يتم إزالة مشروع مطابق بغض النظر عن اسمه. يتصرف المنطق بخلاف ذلك كما لو تم تحديد كليهما.

الخاصية `optional`: تعيين على `true` لتجاهل عناصر `remove-project` التي لا تتطابق مع عنصر `project`.

الخاصية `base-rev`: إذا تم تحديدها، فإنها تضيف فحصًا مقابل المراجعة التي سيتم إزالتها. سيفشل تحليل القائمة وسيعطي قائمة بالمطابقات المزالة إذا تغيرت المراجعات التي يتم إزالتها منذ تعيين `base-rev`. مخصص للاستخدام مع القوائم المطبقة باستخدام مراجعات التجزئة لمنع فروع التصحيح من إخفاء مراجعات أحدث للمصدر الأعلى. يقارن أيضًا المراجع المسماة مثل الفروع أو العلامات ولكنه مضلل إذا تم استخدام الفروع كـ `base-rev`. نفس بناء الجملة مثل العنصر المقابل لـ `project`.

العنصر repo-hooks

ملاحظة: انظر [التوثيق العملي](./repo-hooks.md) لاستخدام خطافات `repo`.

يمكن تحديد عنصر `repo-hooks` واحد فقط في كل مرة. سيؤدي محاولة إعادة تعريفه إلى فشل التحليل.

الخاصية `in-project`: المشروع الذي تم تعريف الخطافات فيه. يجب أن تتطابق القيمة مع الخاصية `name` (وليس الخاصية `path`) لعنصر `project` تم تعريفه مسبقًا.

الخاصية `enabled-list`: قائمة بالخطافات المراد استخدامها، مفصولة بمسافات أو بفواصل.

العنصر superproject

*** ملاحظة: هذا قيد التطوير حاليًا. ***

ملاحظة: انظر [توثيق git superprojects]( https://en.wikibooks.org/wiki/Git/Submodules_and_Superprojects) للمعلومات الأساسية.

يُستخدم هذا العنصر لتحديد عنوان URL للمشروع الأعلى. لديه خصائص "name" و "remote". "name" مطلوب فقط بينما يكون للآخرين قيم افتراضية مناسبة. يمكن تحديد مشروع أعلى واحد على الأكثر. سيؤدي محاولة إعادة تعريفه إلى فشل التحليل.

الخاصية `name`: اسم فريد للمشروع الأعلى. هذه الخاصية لها نفس معنى خاصية `name` للمشروع. انظر [العنصر project](#element-project) لمزيد من المعلومات.

الخاصية `remote`: اسم عنصر بعيد تم تعريفه مسبقًا. إذا لم يتم توفيره، يتم استخدام المستودع البعيد المحدد بواسطة العنصر الافتراضي.

الخاصية `revision`: اسم فرع Git (على سبيل المثال، `main` أو `refs/heads/main`) الذي تريد القائمة تتبعه لهذا المشروع الأعلى. إذا لم يتم توفيره، يتم استخدام المراجعة المحددة بواسطة العنصر البعيد إذا كان ذلك قابلاً للتطبيق، وإلا يتم استخدام العنصر الافتراضي.

العنصر contactinfo

*** ملاحظة: هذا قيد التطوير حاليًا. ***

يُستخدم هذا العنصر للسماح لمؤلفي القوائم بتسجيل معلومات الاتصال بأنفسهم. لديه خاصية "bugurl" مطلوبة. يمكن تكرار هذا العنصر، وستقوم أي إدخالات لاحقة بإلغاء الإدخالات السابقة. هذا سيسمح لمؤلفي القوائم الذين يوسعون القوائم بتحديد معلومات الاتصال الخاصة بهم.

الخاصية `bugurl`: عنوان URL لتقديم خطأ ضد مالك القائمة.

العنصر include

يوفر هذا العنصر إمكانية تضمين ملف قائمة آخر في القائمة الأصلية. تنطبق القواعد العادية على القائمة المستهدفة لتضمينها - يجب أن تكون قائمة قابلة للاستخدام بحد ذاتها.

الخاصية `name`: القائمة المراد تضمينها، محددة بشكل نسبي إلى جذر مستودع القائمة.

قد لا يكون "name" مسارًا مطلقًا أو يستخدم مكونات مسار "." أو "..". لا يتم فرض هذه القيود على [القوائم المحلية].

الخاصية `groups`: قائمة بالمجموعات الإضافية التي تنتمي إليها جميع المشاريع في القائمة المضمنة. هذه الإضافة متكررة، مما يعني أن جميع المشاريع في القوائم المضمنة تحمل جميع مجموعات التضمين الأصلية. نفس بناء الجملة مثل العنصر المقابل لـ `project`.

الخاصية `revision`: اسم فرع Git (على سبيل المثال، `main` أو `refs/heads/main`) الافتراضي الذي تنتمي إليه جميع المشاريع في القائمة المضمنة.

القوائم المحلية

يمكن إضافة مستودعات ومشاريع إضافية من خلال ملفات القوائم المحلية المخزنة في `$TOP_DIR/.repo/local_manifests/*.xml`.

على سبيل المثال:

$ ls .repo/local_manifests
local_manifest.xml another_local_manifest.xml
$ cat .repo/local_manifests/local_manifest.xml
<?xml version="1.0" encoding="UTF-8"?> <manifest>
<project path="manifest"
name="tools/manifest" />
<project path="platform-manifest"
name="platform/manifest" />
</manifest>

يمكن للمستخدمين إضافة مشاريع إلى القائمة (القوائم) المحلية قبل استدعاء `repo sync`، مما يوجه `repo` لتنزيل هذه المشاريع الإضافية وإدارتها تلقائيًا.

سيتم تحميل ملفات القوائم المخزنة في `$TOP_DIR/.repo/local_manifests/*.xml` بترتيب أبجدي.

تتم إضافة المشاريع من ملفات القوائم المحلية إلى مجموعة `local::<local manifest filename>`.

لم يعد المسار القديم `$TOP_DIR/.repo/local_manifest.xml` مدعومًا.
