الوصف

ملاحظة: هذه الصفحة غير مكتملة (لم يتم وصف وظائف المحلل المختلفة التي توفرها glibc) ومن المحتمل أن تكون قديمة.

الوظائف الموضحة أدناه تقوم بإجراء استعلامات لخوادم أسماء نطاقات الإنترنت وتفسير الاستجابات منها.

تتكون واجهة برمجة التطبيقات (API) من مجموعة من الوظائف الحديثة والقابلة لإعادة الدخول ومجموعة أقدم من الوظائف غير القابلة لإعادة الدخول التي تم استبدالها. الواجهات التقليدية للمحلل مثل res_init() و res_query() تستخدم بعض الحالة الثابتة (العالمية) المخزنة في البنية _res، مما يجعل هذه الوظائف غير آمنة للخيوط. قدم BIND 8.2 مجموعة من الواجهات الجديدة res_ninit() و res_nquery() وما إلى ذلك، والتي تأخذ res_state كوسيط أول لها، حتى تتمكن من استخدام حالة محلل لكل خيط.

تقوم وظائف res_ninit() و res_init() بقراءة ملفات التكوين (انظر resolv.conf(5)) للحصول على اسم النطاق الافتراضي وعنوان (عناوين) خادم الأسماء. إذا لم يتم تقديم خادم، يتم تجربة المضيف المحلي. إذا لم يتم تقديم نطاق، يتم استخدام النطاق المرتبط بالمضيف المحلي. يمكن تجاوزه باستخدام متغير البيئة LOCALDOMAIN. يتم تنفيذ res_ninit() أو res_init() عادةً بواسطة الاستدعاء الأول لإحدى الوظائف الأخرى. كل استدعاء لـ res_ninit() يتطلب استدعاءً مقابلًا لـ res_nclose() لتحرير الذاكرة التي خصصتها res_ninit() والاستدعاءات اللاحقة لـ res_nquery().

تقوم وظائف res_nquery() و res_query() بالاستعلام من خادم الأسماء لاسم النطاق المؤهل بالكامل name من النوع type والفئة class المحددين. يتم ترك الرد في المخزن المؤقت answer بطول anslen مقدم من المتصل.

تقوم وظائف res_nsearch() و res_search() بإجراء استعلام والانتظار للاستجابة مثل res_nquery() و res_query()، ولكن بالإضافة إلى ذلك، فهي تطبق قواعد الافتراضيات والبحث التي يتم التحكم فيها بواسطة RES_DEFNAMES و RES_DNSRCH (انظر وصف خيارات _res أدناه).

تقوم وظائف res_nquerydomain() و res_querydomain() بإجراء استعلام باستخدام res_nquery()/res_query() على دمج name و domain.

الوظائف التالية هي إجراءات منخفضة المستوى تستخدمها res_nquery()/res_query().

تقوم وظائف res_nmkquery() و res_mkquery() بإنشاء رسالة استعلام في buf بطول buflen لاسم النطاق dname. نوع الاستعلام op هو أحد الخيارات التالية (عادةً QUERY):

QUERY
استعلام قياسي.
IQUERY
استعلام عكسي. تم إزالة هذا الخيار في glibc 2.26، نظرًا لأنه لم يتم دعمه من قبل خوادم DNS لفترة طويلة جدًا.
NS_NOTIFY_OP
إشعار الثانوي بتغيير SOA (بدء السلطة).

newrr غير مستخدم حاليًا.

تقوم وظيفة res_nsend() و res_send() بإرسال استعلام مُعد مسبقًا معطى في msg بطول msglen وتعيد الإجابة في answer الذي يبلغ طوله anslen. سيتم استدعاء res_ninit()/res_init() إذا لم يتم استدعاؤها بالفعل.

تقوم وظيفة dn_comp() بضغط اسم النطاق exp_dn وتخزينه في المخزن المؤقت comp_dn بطول length. يستخدم الضغط مصفوفة من المؤشرات dnptrs للأسماء المضغوطة سابقًا في الرسالة الحالية. يشير المؤشر الأول إلى بداية الرسالة وتنتهي القائمة بـ NULL. يتم تحديد حد المصفوفة بواسطة lastdnptr. إذا كان dnptr هو NULL، فلا يتم ضغط أسماء النطاقات. إذا كان lastdnptr هو NULL، فلا يتم تحديث قائمة التسميات.

تقوم وظيفة dn_expand() بتوسيع اسم النطاق المضغوط comp_dn إلى اسم نطاق كامل، والذي يتم وضعه في المخزن المؤقت exp_dn بحجم length. اسم النطاق المضغوط موجود في رسالة استعلام أو رد، ويشير msg إلى بداية

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

تستخدم روتينات الدقة معلومات التكوين والحالة الواردة في بنية \__res_state (إما تم تمريرها كوسيط statep، أو في المتغير العام _res، في حالة الوظائف القديمة غير القابلة لإعادة الدخول). الحقل الوحيد لهذه البنية الذي يتم التعامل معه عادةً بواسطة المستخدم هو حقل options. يمكن أن يحتوي هذا الحقل على "OR" البتي من الخيارات التالية:

RES_INIT
صحيح إذا تم استدعاء res_ninit() أو res_init().
RES_DEBUG
طباعة رسائل التصحيح. هذا الخيار متاح فقط إذا تم بناء glibc مع تمكين التصحيح، وهو ليس الافتراضي.
RES_AAONLY (غير مطبق؛ مهمل في glibc 2.25)
قبول الإجابات الموثوقة فقط. يستمر res_send() حتى يجد إجابة موثوقة أو يعود بخطأ. كان هذا الخيار موجودًا ولكنه غير مطبق حتى glibc 2.24؛ منذ glibc 2.25، تم إهماله، ويؤدي استخدامه إلى تحذير.
RES_USEVC
استخدام اتصالات TCP للاستعلامات بدلاً من حزم UDP.
RES_PRIMARY (غير مطبق؛ مهمل في glibc 2.25)
الاستعلام عن خادم اسم المجال الأساسي فقط. كان هذا الخيار موجودًا ولكنه غير مطبق حتى glibc 2.24؛ منذ glibc 2.25، تم إهماله، ويؤدي استخدامه إلى تحذير.
RES_IGNTC
تجاهل أخطاء الاقتطاع. لا تعاود المحاولة باستخدام TCP.
RES_RECURSE
تعيين بت الرغبة في العودية في الاستعلامات. يتم تنفيذ العودية بواسطة خادم اسم المجال، وليس بواسطة res_send(). [ممكّن افتراضيًا].
RES_DEFNAMES
إذا تم تعيينه، سيقوم res_search() بإلحاق اسم المجال الافتراضي بالأسماء ذات المكون الواحد - أي تلك التي لا تحتوي على نقطة. [ممكّن افتراضيًا].
RES_STAYOPEN
يستخدم مع RES_USEVC للحفاظ على اتصال TCP مفتوحًا بين الاستعلامات.
RES_DNSRCH
إذا تم تعيينه، سيبحث res_search() عن أسماء المضيفين في المجال الحالي وفي النطاقات الأصلية. يستخدم هذا الخيار بواسطة gethostbyname(3). [ممكّن افتراضيًا].
RES_INSECURE1
قبول استجابة من خادم خاطئ. يمكن استخدام هذا للكشف عن المخاطر الأمنية المحتملة، ولكنك تحتاج إلى تجميع glibc مع تمكين التصحيح واستخدام الخيار RES_DEBUG (لغرض التصحيح فقط).
RES_INSECURE2
قبول استجابة تحتوي على استعلام خاطئ. يمكن استخدام هذا للكشف عن المخاطر الأمنية المحتملة، ولكنك تحتاج إلى تجميع glibc مع تمكين التصحيح واستخدام الخيار RES_DEBUG (لغرض التصحيح فقط).
RES_NOALIASES
تعطيل استخدام متغير البيئة HOSTALIASES.
RES_USE_INET6
محاولة استعلام AAAA قبل استعلام A داخل وظيفة gethostbyname(3)، وتعيين استجابات IPv4 في "شكل نفق" IPv6 إذا لم يتم العثور على سجلات AAAA ولكن توجد مجموعة سجلات A. منذ glibc 2.25، تم إهمال هذا الخيار، ويؤدي استخدامه إلى تحذير؛ يجب على التطبيقات استخدام getaddrinfo(3)، بدلاً من gethostbyname(3).
RES_ROTATE
يسبب اختيار خوادم الأسماء بنمط التدوير من بين تلك المدرجة. هذا له تأثير توزيع حمل الاستعلام على جميع الخوادم المدرجة، بدلاً من محاولة جميع العملاء للخادم الأول المدرج أولاً في كل مرة.
RES_NOCHECKNAME (غير مطبق؛ مهمل في glibc 2.25)
تعطيل فحص BIND الحديث لأسماء المضيفين المستلمة وأسماء البريد بحثًا عن أحرف غير صالحة مثل الشرطة السفلية (_)، أو غير ASCII، أو أحرف التحكم. كان هذا الخيار موجودًا حتى glibc 2.24؛ منذ glibc 2.25، تم إهماله، ويؤدي استخدامه إلى تحذير.
RES_KEEPTSIG (غير مطبق؛ مهمل في glibc 2.25)
لا تقم بإزالة سجلات TSIG. كان هذا الخيار موجودًا ولكنه غير مطبق حتى glibc 2.24؛ منذ glibc 2.25، تم إهماله، ويؤدي استخدامه إلى تحذير.
RES_BLAST (غير مطبق؛ مهمل في glibc 2.25)
إرسال كل استعلام بشكل متزامن وتكراري إلى جميع الخوادم. كان هذا الخيار موجودًا ولكنه غير مطبق حتى glibc 2.24؛ منذ glibc 2.25، تم إهماله، ويؤدي استخدامه إلى تحذير.
RES_USEBSTRING (glibc 2.3.4 إلى glibc 2.24)
إجراء عمليات بحث IPv6 عكسية باستخدام تنسيق التسمية الثنائية الموصوف في RFC 2673؛ إذا لم يتم تعيين هذا الخيار (وهو الافتراضي)، فسيتم استخدام تنسيق nibble. تمت إزالة هذا الخيار في glibc 2.25، لأنه كان يعتمد على امتداد DNS غير متوافق مع الإصدارات السابقة ولم يتم نشره أبدًا على الإنترنت.
RES_NOIP6DOTINT (glibc 2.24 والإصدارات الأقدم)
استخدم منطقة ip6.arpa في البحث العكسي IPv6 بدلاً من ip6.int، والذي تم إهماله منذ glibc 2.3.4. هذا الخيار موجود حتى ويشمل glibc 2.24، حيث يتم تمكينه افتراضيًا. في glibc 2.25، تمت إزالة هذا الخيار.
RES_USE_EDNS0 (منذ glibc 2.6)
تمكين دعم امتدادات DNS (EDNS0) الموصوفة في RFC 2671.
RES_SNGLKUP (منذ glibc 2.10)
افتراضيًا، تقوم glibc بإجراء عمليات بحث IPv4 و IPv6 بالتوازي منذ glibc 2.9. بعض خوادم DNS للأجهزة لا يمكنها التعامل مع هذه الاستعلامات بشكل صحيح وتجعل الطلبات تنتهي مهلتها. يعطل هذا الخيار السلوك ويجعل glibc تجري طلبات IPv6 و IPv4 بالتتابع (على حساب بعض التباطؤ في عملية الدقة).
RES_SNGLKUPREOP
عند تمكين الخيار RES_SNGLKUP، يفتح مقبسًا جديدًا لكل طلب.
RES_USE_DNSSEC
استخدم DNSSEC مع بت OK في سجل OPT. هذا الخيار يعني RES_USE_EDNS0.
RES_NOTLDQUERY
لا تبحث عن اسم غير مؤهل كـ (top-level domain (TLD)).
RES_DEFAULT
الخيار الافتراضي الذي يعني: RES_RECURSE، RES_DEFNAMES، RES_DNSRCH، و RES_NOIP6DOTINT.

قيمة الإرجاع

ترجع الوظائف res_ninit() و res_init() القيمة 0 عند النجاح، أو -1 إذا حدث خطأ.

ترجع الوظائف res_nquery() و res_query() و res_nsearch() و res_search() و res_nquerydomain() و res_querydomain() و res_nmkquery() و res_mkquery() و res_nsend() و res_send() طول الاستجابة، أو -1 إذا حدث خطأ.

ترجع الوظائف dn_comp() و dn_expand() طول الاسم المضغوط، أو -1 إذا حدث خطأ.

في حالة حدوث خطأ في الإرجاع من res_nquery() أو res_query() أو res_nsearch() أو res_search() أو res_nquerydomain() أو res_querydomain()، يمكن استشارة المتغير العام h_errno (انظر gethostbyname(3)) لتحديد الخطأ.

res_nquery(3) - Linux manual pages

NAME

res_nquery, res_nquery_nostat, res_nquery2, res_nquery3 - resolver functions for DNS queries

LIBRARY

DNS resolver library (libresolv, -lresolv)

SYNOPSIS

#include <resolv.h>

int res_nquery(res_state_t *statp, const char *name, int class, int type,
               unsigned char *buf, int buflen);
int res_nquery_nostat(res_state_t *statp, const char *name, int class, int type,
                      unsigned char *buf, int buflen);
int res_nquery2(res_state_t *statp, const char *name, int class, int type,
                unsigned char *buf, int buflen, int *rrstat);
int res_nquery3(res_state_t *statp, const char *name, int class, int type,
                unsigned char *buf, int buflen, int *rrstat, int *trunc,
                int *ttl);

DESCRIPTION

These functions are obsolete. Do not use them in new code. Use res_query(3) instead.

These functions perform a DNS query for the given name, class, and type. The results are placed in the buffer pointed to by buf, which has a maximum size of buflen bytes. The functions return the number of bytes placed in the buffer on success, or −1 on failure.

The statp argument is a pointer to a resolv.conf(5) state structure. This structure contains information about the DNS servers, search domains, and other options that affect DNS queries.

The name argument is the name to query. The class argument is the DNS class (e.g., C_IN for the Internet class). The type argument is the DNS type (e.g., T_A for an A record, T_MX for an MX record).

The buf argument is a pointer to a buffer where the DNS response will be stored. The buflen argument is the size of the buffer.

The res_nquery_nostat function is the same as res_nquery, but it does not update the statistics in the res_state_t structure.

The res_nquery2 function is the same as res_nquery, but it also returns the RCODE (response code) of the DNS response in the rrstat argument. This can be used to determine why a query failed.

The res_nquery3 function is the same as res_nquery2, but it also returns information about whether the response was truncated in the trunc argument, and the TTL (time to live) of the DNS records in the ttl argument.

RETURN VALUE

On success, these functions return the number of bytes placed in the buffer. On failure, they return −1 and set errno appropriately.

FILES

/etc/resolv.conf - resolver configuration file

ATTRIBUTES

For an explanation of the following attributes, see attributes(7).

+--------------------------------+------------------------------+
| Interface                      | Attribute                    |
+--------------------------------+------------------------------+
| res_nquery, res_nquery2,       | Deprecated                   |
| res_nquery3, res_nquery_nostat |                              |
+--------------------------------+------------------------------+

STANDARDS

These functions are specific to the GNU C Library and are not part of any standard. They are obsolete and should not be used.

HISTORY

The res_nquery functions first appeared in glibc 2.0.
