rigctlcom(1)

الحزمة: hamlib

التراخيص: GPL-2.0-or-later, LGPL-2.0-or-later

RIGCTLCOM(1) أدوات Hamlib RIGCTLCOM(1)

الاسم

rigctlcom - تمرير منفذ COM كجهاز TS-2000 إلى جهاز الإرسال الخاص بك

الملخص

rigctlcom [-hlLuV] [-m معرف] [-r الجهاز] [-R الجهاز] [-p الجهاز] [-d الجهاز] [-P النوع] [-D النوع] [-s سرعة البث] [-S سرعة البث] [-c معرف] [-C بارام=قيمة] [-B] [-v[-Z]]

الوصف

يسمح للبرامج التي يمكنها الاتصال بجهاز TS-2000 عبر منفذ COM باستخدام أجهزة Hamlib أو FLRig. يمكن لعدة برامج الاتصال بالجهاز عبر FLRig أو rigctld.

يجب إعداد منافذ COM/المنافذ التسلسلية الافتراضية أولاً باستخدام socat(1) أو ما شابه ذلك على أنظمة POSIX (BSD، Linux، OS/X). على Microsoft Windows، الأدوات المتاحة هي com0com، Free Virtual Serial Ports، أو VPSD.

يرجى الإبلاغ عن الأخطاء وتقديم الملاحظات على عنوان البريد الإلكتروني المذكور في قسم الأخطاء أدناه. التصحيحات وتحسينات التعليمات البرمجية المرسلة إلى نفس العنوان مرحب بها.

الخيارات

يتبع هذا البرنامج صيغة سطر الأوامر القياسية لـ GNU. قد تحتوي الخيارات القصيرة التي تأخذ وسيطة على القيمة متبوعة فورًا أو مفصولة بمسافة. تتطلب الخيارات الطويلة التي تبدأ بشرطتين (‘-’) علامة ‘=’ بين الخيار وأي وسيط.

إليك ملخص للخيارات المدعومة:

-m, --model=معرف
حدد رقم طراز جهاز الإرسال.
انظر قائمة الطرز (استخدم “rigctlcom -l”).
ملاحظة: سيستخدم rigctlcom (أو برامج الطرف الثالث التي تستخدم واجهة برمجة التطبيقات C) طراز جهاز الإرسال 2 لـ NET rigctl (الاتصال بـ rigctld).
-r, --rig-file=الجهاز
استخدم الجهاز كاسم ملف للمنفذ المتصل بجهاز الإرسال.
غالباً ما يكون منفذاً تسلسلياً، ولكنه قد يكون محولاً من USB إلى تسلسلي. عادةً /dev/ttyS0، /dev/ttyS1، /dev/ttyUSB0، وما إلى ذلك على Linux، COM1، COM2، وما إلى ذلك على MS Windows. نكهات BSD و Mac OS/X لها تعييناتها الخاصة. انظر وثائق نظامك.
يمكن إعطاء السلسلة الخاصة “uh-rig” لتمكين دعم أجهزة micro-ham.
-R, --rig-file2=الجهاز
استخدم الجهاز كاسم ملف لأحد منافذ COM الافتراضية -- سيتصل برنامجك بمنفذ COM الآخر من الزوج الافتراضي.
يمكن إنشاء منافذ تسلسلية افتراضية على أنظمة POSIX باستخدام socat(1):

$ socat -d -d pty,raw,echo=0 pty,raw,echo=0

انظر هذا الجواب في Stackoverflow لاستخدام socat.
على Microsoft Windows، الأدوات المتاحة هي com0com، Free Virtual Serial Ports، أو VPSD (انظر الوصف أعلاه للروابط WWW).
-p, --ptt-file=الجهاز
استخدم الجهاز كاسم ملف لجهاز الضغط للتحدث (Push-To-Talk) باستخدام ملف جهاز كما هو موضح أعلاه.
-d, --dcd-file=الجهاز
استخدم الجهاز كاسم ملف لجهاز كشف حامل البيانات (Data Carrier Detect) باستخدام ملف جهاز كما هو موضح أعلاه.
-P, --ptt-type=النوع
استخدم النوع من أجهزة الضغط للتحدث.
الأنواع المدعومة هي ‘RIG’ (أمر CAT)، ‘DTR’، ‘RTS’، ‘PARALLEL’، ‘NONE’، متجاوزًا نوع PTT المحدد في الواجهة الخلفية لجهاز الإرسال.
بعض الآثار الجانبية لهذا الأمر هي أنه عند تعيين النوع إلى DTR، تأتي حالة PTT المقروءة من الواجهة الأمامية لـ Hamlib، ولا تُقرأ من جهاز الإرسال. عند التعيين إلى NONE، لا يمكن قراءة أو تعيين حالة PTT حتى لو كانت الواجهة الخلفية لجهاز الإرسال تدعم قراءة/تعيين حالة PTT من جهاز الإرسال.
-D, --dcd-type=النوع
استخدم النوع من أجهزة كشف حامل البيانات.
الأنواع المدعومة هي ‘RIG’ (أمر CAT)، ‘DSR’، ‘CTS’، ‘CD’، ‘PARALLEL’، ‘NONE’.
-s, --serial-speed=سرعة البث
اضبط سرعة المنفذ التسلسلي على معدل سرعة البث.
يستخدم أقصى سرعة تسلسلية من قدرات الواجهة الخلفية لجهاز الإرسال (المحددة بواسطة -m أعلاه) كقيمة افتراضية.
-S, --serial-speed2=سرعة البث
اضبط سرعة المنفذ التسلسلي على معدل سرعة البث لمنفذ COM الافتراضي (انظر -R).
يستخدم أقصى سرعة تسلسلية من قدرات الواجهة الخلفية لجهاز الإرسال (المحددة بواسطة -m أعلاه) كقيمة افتراضية.
-c, --civaddr=معرف
استخدم معرف كعنوان CI-V للتواصل مع جهاز الإرسال.
مفيد فقط لأجهزة Icom وبعض أجهزة Ten-Tec.
ملاحظة: المعرف مكتوب بالنظام العشري، إلا إذا كان مسبوقًا بـ 0x، وفي هذه الحالة يكون بالنظام الست عشري.
-L, --show-conf
اعرض جميع معلمات التكوين لجهاز الإرسال المحدد بواسطة -m أعلاه.
-C, --set-conf=بارام=قيمة[،بارام=قيمة]
قم بتعيين معلمة (معلمات) تكوين جهاز الإرسال، على سبيل المثال stop_bits=2.
استخدم الخيار -L أعلاه للحصول على قائمة بمعلمات التكوين لطراز معين.
-u, --dump-caps
اعرض القدرات لجهاز الإرسال المحدد بواسطة -m أعلاه ثم اخرج.
-l, --list
اعرض جميع أرقام الطرز المحددة في Hamlib ثم اخرج.
القائمة مرتبة حسب رقم الطراز.
ملاحظة: في Linux، يمكن التمرير للخلف باستخدام Shift-PageUp/Shift-PageDown، أو باستخدام أشرطة التمرير في طرفية افتراضية في X أو نافذة cmd في Windows. يمكن توجيه الإخراج إلى more(1) أو less(1)، على سبيل المثال “rigctl -l | more”.
-n, --no-restore-ai
يقوم rigctl باستعادة حالة المعلومات التلقائية (AI) في جهاز الإرسال الذي يتم التحكم فيه.
إذا لم يكن هذا مطلوبًا، على سبيل المثال إذا كنت تستخدم rigctl لتشغيل أو إيقاف وضع AI، فمرر هذا الخيار.
-B, --mapa2b
يقوم بتعيين set_freq على VFOA إلى VFOB بدلاً من ذلك. هذا يسمح باستخدام CW skimmer مع جهاز الإرسال في وضع التقسيم والنقر على تردد في CW skimmer سيضبط VFOB على تردد الإرسال.
-v, --verbose
اضبط وضع الإسهاب، تراكمي (انظر التشخيص أدناه).
-Z, --debug-time-stamps
تمكين الطوابع الزمنية لرسائل التصحيح.
استخدم فقط بالاشتراك مع الخيار -v حيث أنه لا ينتج أي إخراج بمفرده.

التشخيص

يتم إرسال رسائل مفصلة إلى stderr. إذا كان الرمز 0 يعني نجاحاً، فإن أي قيمة أخرى تشير إلى خطأ.

يتم إرسال رسائل الخطأ إلى stderr.

رسائل الإسهاب:

-v
تُصدر رسائل معقولة.
-vv
تُصدر رسائل أكثر تفصيلاً.
-vvv
تُصدر رسائل تفصيلية للغاية، بما في ذلك جميع استدعاءات واجهة برمجة التطبيقات.

يمكن أن تكون الطوابع الزمنية مفيدة لتتبع أخطاء التوقيت.

أمثلة

لاستخدام جهاز IC-756PROII مع طراز Hamlib رقم 72، وسرعة 9600، ومنفذ COM1، لتشغيل برنامج يستدعي telnet://localhost:5555:


$ rigctlcom -m 72 -r COM1 -s 9600

ثم قم بتشغيل برنامجك مع telnet://localhost:5555.

لاستخدام جهاز FT-920 مع طراز Hamlib رقم 14، وسرعة 57600، ومنفذ تسلسلي /dev/ttyUSB0، لبرنامج يتصل بمنفذ COM افتراضي 3:


$ socat -d -d pty,raw,echo=0,link=/tmp/rigtty pty,raw,echo=0



$ rigctlcom -m 14 -r /dev/ttyUSB0 -R /tmp/rigtty -s 57600

ثم قم بتشغيل برنامجك مع /tmp/rigtty.

لاستخدام جهاز Yaesu FT-857D مع طراز Hamlib رقم 145، وعنوان CI-V 112 (0x70)، وسرعة 38400، ومنفذ تسلسلي /dev/ttyUSB0:


$ rigctlcom -m 145 -c 112 -r /dev/ttyUSB0 -s 38400

rigctlcom(1) - Hamlib documentation

NAME

rigctlcom - Rig control communication daemon

SYNOPSIS

rigctlcom [-h | --help] [-V | --version] [-v level] [-m model] [-r rig] [-s serial_port] [-d device] [-P protocol] [-l latency] [-t timeout] [-u] [-T tracefile] [-o] [-C parameter[=value]] [--set-conf parameter=value] [--show-conf]

DESCRIPTION

This program is a communication daemon that allows applications, that communicate with rigctld over a TCP/IP connection, to communicate with the Hamlib library directly, thus creating a virtual serial port. This is useful for applications that do not have built-in Hamlib support but do allow communication over a serial port, such as N1MM Logger+.

The daemon creates a pair of virtual serial ports. One port is used by the application to communicate with the daemon. The other port is used by the daemon to communicate with the Hamlib library, which in turn communicates with the radio.

The following diagram shows the communications flow that allows N1MM Logger+ to communicate with a radio connected to Flrig:


Flrig -><- rigctlcom -> COM9 <- virt_port_pipe -> COM10 <- N1MM

In this example, the N1MM Logger+ application connects to virtual serial port COM10. The rigctlcom daemon connects to the Hamlib library, model 4 (FLRig), on virtual serial port COM9. The operating system then pipes the communication between COM9 and COM10.

Other examples of applications that can be used with rigctlcom include the venerable DXtreme DX, DX Tunnel, and others that allow serial port communication but do not have direct Hamlib support.

The virtual serial ports can be created using any utility that supports the creation of virtual serial ports, such as:

  • socat(1) on Linux.
  • Virtual Serial Port Emulator on Windows.
  • Virtual Serial Port Driver on Windows.

A tutorial and additional information on setting up and using rigctlcom can be found on the Hamlib wiki.

OPTIONS

-h, --help
Show a summary of these options and exit.
-V, --version
Show version of rigctlcom and exit.

Note: Some options may not be implemented by a given backend and will return an error. This is most likely to occur with the --set-conf and --show-conf options.

DIAGNOSTICS

The -v, --verbose option allows different levels of diagnostics to be output to stderr and correspond to -v for BUG, -vv for ERR, -vvv for WARN, -vvvv for VERBOSE, or -vvvvv for TRACE.

A given verbose level is useful for providing needed debugging information to the email address below. For example, TRACE output shows all of the values sent to and received from the radio which is very useful for radio backend library development and may be requested by the developers.

EXIT STATUS

rigctlcom exits with:

0
if all operations completed normally;
1
if there was an invalid command line option or argument;
2
if an error was returned by Hamlib.

EXAMPLE

Start rigctlcom with FLRig as the Hamlib model and virtual com port pair COM9/COM10, e.g. N1MM Logger+ attaching to COM10 and using the TS-2000 emulator attached to COM9 (assumes virtual serial/COM ports pipe has been created with the proper utility as described above):


$ rigctlcom -m 4 -R COM9 -S 115200

The following diagram shows the communications flow that allows N1MM Logger+ to communicate with a radio connected to Flrig:


Flrig -><- rigctlcom -> COM9 <- virt_port_pipe -> COM10 <- N1MM
