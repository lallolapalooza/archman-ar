تم تقديم الخيارات الأكثر فائدة فقط أعلاه؛ انظر أدناه للحصول على قائمة أكثر اكتمالاً بالخيارات الخاصة بالمعالج الأولي. بالإضافة إلى ذلك، يقبل cpp معظم خيارات برنامج تشغيل gcc، والتي لم يتم إدراجها هنا. ارجع إلى وثائق GCC للحصول على التفاصيل.

وصف

معالج C الأولي، المعروف غالبًا باسم cpp، هو معالج ماكرو يستخدم تلقائيًا بواسطة مترجم C لتحويل برنامجك قبل الترجمة. يسمى معالج ماكرو لأنه يسمح لك بتعريف الماكرو، وهي اختصارات موجزة للإنشاءات الأطول.

معالج C الأولي مخصص للاستخدام فقط مع شفرة مصدر C و C ++ و Objective-C. في الماضي، تم إساءة استخدامه كمعالج نص عام. سيواجه مشاكل مع الإدخال الذي لا يتبع قواعد C المعجمية. على سبيل المثال، سيتم تفسير علامات الاقتباس المفردة كبداية لحروف ثابتة، مما يتسبب في أخطاء. أيضًا، لا يمكنك الاعتماد عليه في الحفاظ على خصائص الإدخال التي ليست مهمة للغات عائلة C. إذا تم معالجة ملف Makefile أوليًا، فسيتم إزالة جميع علامات الجدولة الصعبة، ولن يعمل ملف Makefile.

مع الأخذ في الاعتبار ذلك، يمكنك غالبًا الإفلات من استخدام cpp على أشياء ليست C. غالبًا ما تكون لغات البرمجة الأخرى المشابهة لـ Algol آمنة (Ada، إلخ) وكذلك التجميع، بحذر. يحافظ وضع -traditional-cpp على المزيد من المسافات البيضاء، وهو متسامح بشكل عام. يمكن تجنب العديد من المشاكل عن طريق كتابة تعليقات بأسلوب C أو C ++ بدلاً من تعليقات اللغة الأصلية، والحفاظ على الماكرو بسيطًا.

حيثما أمكن، يجب عليك استخدام معالج أولي موجه للغة التي تكتب بها. الإصدارات الحديثة من المجمع GNU لديها مرافق ماكرو. معظم لغات البرمجة عالية المستوى لديها آلية الترجمة الشرطية والتضمين الخاصة بها. إذا فشل كل شيء آخر، جرب معالج نصوص عام حقيقي، مثل GNU M4.

تختلف معالجات C الأولية في بعض التفاصيل. يناقش دليل المستخدم هذا معالج C الأولي GNU، والذي يوفر مجموعة فرعية صغيرة من ميزات معيار C ISO. في وضعه الافتراضي، لا يقوم معالج C الأولي GNU ببعض الأشياء التي يتطلبها المعيار. هذه ميزات نادرة الاستخدام، وقد تسبب تغييرات مفاجئة في معنى البرنامج الذي لا يتوقعها. للحصول على معيار C ISO صارم، يجب عليك استخدام خيارات -std=c90 أو -std=c99 أو -std=c11 أو -std=c17، اعتمادًا على إصدار المعيار الذي تريده. للحصول على جميع التشخيصات الإلزامية، يجب عليك أيضًا استخدام -pedantic.

يصف دليل المستخدم هذا سلوك المعالج الأولي ISO. لتقليل الاختلافات غير الضرورية، حيث لا يتعارض سلوك المعالج الأولي ISO مع الدلالات التقليدية، يجب أن يتصرف المعالج الأولي التقليدي بنفس الطريقة. التفاصيل المختلفة التي توجد مفصلة في قسم الوضع التقليدي.

للتوضيح، ما لم يُذكر خلاف ذلك، تشير الإشارات إلى CPP في دليل المستخدم هذا إلى GNU CPP.

خيارات

يتوقع أمر cpp اسمي ملفين كوسيطين، ملف_إدخال و ملف_إخراج. يقرأ المعالج الأولي ملف_إدخال مع أي ملفات أخرى يحددها مع #include. يتم كتابة كل المخرجات الناتجة عن ملفات الإدخال المدمجة في ملف_إخراج.

قد يكون أي من ملف_إدخال أو ملف_إخراج -، والذي يعني عند استخدامه كـ ملف_إدخال القراءة من الإدخال القياسي وعند استخدامه كـ ملف_إخراج الكتابة إلى الإخراج القياسي. إذا تم حذف أي من الملفين، فهذا يعني نفس الشيء كما لو تم تحديد - لهذا الملف. يمكنك أيضًا استخدام خيار -o ملف_إخراج لتحديد ملف الإخراج.

ما لم يُذكر خلاف ذلك، أو إذا انتهى الخيار بـ =، فإن جميع الخيارات التي تأخذ وسيطًا قد تحتوي على هذا الوسيط إما فورًا بعد الخيار، أو مع مسافة بين الخيار والوسيط: -Ifoo و -I foo لهما نفس التأثير.

العديد من الخيارات لها أسماء متعددة الأحرف؛ لذلك، لا يمكن تجميع خيارات متعددة ذات حرف واحد: -dM يختلف اختلافًا كبيرًا عن -d -M.

-D اسم
تحديد مسبق لـ اسم كـ ماكرو، مع تعريف 1.
-D اسم=تعريف
يتم معالجة محتويات تعريف كوحدات رمزية ومعالجتها كما لو أنها ظهرت أثناء مرحلة الترجمة الثالثة في توجيه #define. على وجه الخصوص، يتم اقتطاع التعريف بواسطة أحرف سطر جديد مضمنة.

إذا كنت تقوم بتشغيل المعالج الأولي من واجهة سطر أوامر أو برنامج يشبه واجهة سطر الأوامر، فقد تحتاج إلى استخدام صيغة الاقتباس الخاصة بواجهة سطر الأوامر لحماية الأحرف مثل المسافات التي لها معنى في صيغة واجهة سطر الأوامر.

إذا كنت ترغب في تعريف ماكرو يشبه الوظيفة على سطر الأوامر، فاكتب قائمة وسائطه مع أقواس محيطة قبل علامة يساوي (إذا وجدت). الأقواس ذات معنى لمعظم واجهات سطر الأوامر، لذلك يجب عليك اقتباس الخيار. مع sh و csh، تعمل -D'اسم(وسائط...)=تعريف'.

تتم معالجة خيارات -D و -U بالترتيب الذي تظهر به على سطر الأوامر. تتم معالجة جميع خيارات -imacros ملف و -include ملف بعد جميع خيارات -D و -U.

-U اسم
إلغاء أي تعريف سابق لـ اسم، سواء كان مضمنًا أو تم توفيره مع خيار -D.
-include ملف
معالجة ملف كما لو أن "#include "ملف"" ظهرت كسطر أول في ملف المصدر الأساسي. ومع ذلك، فإن الدليل الأول الذي يتم البحث فيه عن ملف هو دليل عمل المعالج الأولي بدلاً من الدليل الذي يحتوي على ملف المصدر الرئيسي. إذا لم يتم العثور عليه هناك، يتم البحث عنه في بقية سلسلة البحث الخاصة بـ "#include "..."" كالمعتاد.

إذا تم تقديم خيارات -include متعددة، فسيتم تضمين الملفات بالترتيب الذي تظهر به على سطر الأوامر.

-imacros ملف
تمامًا مثل -include، باستثناء أن أي مخرجات تنتج عن مسح ملف يتم التخلص منها. الماكرو التي يعرّفها تظل معرفة. هذا يسمح لك بالحصول على جميع الماكرو من ملف رأس دون معالجة إعلاناته أيضًا.

تتم معالجة جميع الملفات التي يحددها -imacros قبل جميع الملفات التي يحددها -include.

-undef
لا تقم بتعريف أي ماكرو خاصة بالنظام أو خاصة بـ GCC مسبقًا. تظل وحدات الماكرو المعرفة مسبقًا قياسيًا معرفة.
-pthread
تحديد ماكرو إضافية مطلوبة لاستخدام مكتبة خيوط POSIX. يجب عليك استخدام هذا الخيار باستمرار لكل من الترجمة والربط. هذا الخيار مدعوم على أهداف GNU/Linux، ومعظم مشتقات Unix الأخرى، وكذلك على أهداف x86 Cygwin و MinGW.
-M
بدلاً من إخراج نتيجة المعالجة الأولية، قم بإخراج قاعدة مناسبة لـ make تصف تبعيات ملف المصدر الرئيسي. يقوم المعالج الأولي بإخراج قاعدة make واحدة تحتوي على اسم ملف الكائن لهذا الملف المصدر، ونقطتين رأسيتين، وأسماء جميع الملفات المضمنة، بما في ذلك تلك الواردة من خيارات سطر الأوامر -include أو -imacros.

ما لم يتم تحديده صراحةً (باستخدام -MT أو -MQ)، يتكون اسم ملف الكائن من اسم ملف المصدر مع استبدال أي لاحقة بـ لاحقة ملف الكائن وإزالة أي أجزاء دليل بادئة. إذا كان هناك العديد من الملفات المضمنة، فسيتم تقسيم القاعدة إلى عدة أسطر باستخدام \-سطر جديد. القاعدة لا تحتوي على أوامر.

لا يؤدي هذا الخيار إلى قمع مخرجات تصحيح أخطاء المعالج الأولي، مثل -dM. لتجنب خلط مخرجات تصحيح الأخطاء هذه مع قواعد التبعية، يجب عليك تحديد ملف إخراج التبعية بشكل صريح باستخدام -MF، أو استخدام متغير بيئة مثل DEPENDENCIES_OUTPUT. لا تزال مخرجات تصحيح الأخطاء تُرسل إلى الإخراج المنتظم.

riscv64-elf-cpp

NAME

NAME

riscv64-elf-cpp - C preprocessor

SYNOPSIS

SYNOPSIS

cpp [OPTION...] [INPUT [OUTPUT]]

DESCRIPTION

DESCRIPTION

The C preprocessor, cpp, is a macro processor that is used as the first phase of a C, C++, and Objective-C compilation. It is typically invoked automatically by the compiler, but can be invoked directly by the user. It performs several transformations on the source code:

  • It expands macro invocations defined in header files and C source files.
  • It handles conditional compilation directives, such as #ifdef, #ifndef, #if, #else, #elif, and #endif.
  • It removes comments from the source code.
  • It includes the contents of other files specified by #include directives.

The output of cpp is a modified source file that is then passed to the compiler. This output is typically sent to standard output, which is then piped to the compiler. The compiler then performs the rest of the compilation process.

OPTIONS

OPTIONS

cpp supports a large number of options. Some of the most common ones include:

  • -Idir: Add directory dir to the list of directories to search for header files.
  • -Dmacro[=value]: Define macro with an optional value.
  • -Umacro: Undefine macro.
  • -o file: Write output to file instead of standard output.
  • -M: Print the list of prerequisites (header files) to standard output.
  • -MM: Like -M, but does not mention system header files.
  • -E: Stop after the preprocessing stage.
  • -std=c++XX: Use the C++ standard with name c++XX.
  • -v: Verbose output, show compiler invocations.

For a full list of options, please consult the documentation or run cpp --help.

ENVIRONMENT

ENVIRONMENT

The behavior of cpp can be influenced by environment variables, such as:

  • CPATH: A colon-separated list of directories to search for header files.
  • C_INCLUDE_PATH: A colon-separated list of directories to search for C header files.
  • CPLUS_INCLUDE_PATH: A colon-separated list of directories to search for C++ header files.
