RRDs(3pm)

الحزمة: rrdtool

التراخيص: GPL-2.0-or-later

RRDs(3) وثائق Perl المقدمة من المستخدم RRDs(3)

الاسم

RRDs - الوصول إلى RRDtool كوحدة مشتركة

الملخص

use RRDs;
RRDs::error
RRDs::last ...
RRDs::info ...
RRDs::create ...
RRDs::update ...
RRDs::updatev ...
RRDs::graph ...
RRDs::fetch ...
RRDs::tune ...
RRDs::times(start, end)
RRDs::dump ...
RRDs::restore ...
RRDs::flushcached ...
RRDs::register_fetch_cb ...
$RRDs::VERSION

الوصف

تسلسل الاستدعاء

تصل هذه الوحدة إلى وظائف RRDtool مباشرة من داخل Perl. يتم شرح الوسائط الخاصة بالوظائف المدرجة في الملخص في وثائق RRDtool العادية. استدعاء سطر الأوامر

rrdtool update mydemo.rrd --template in:out N:12:13

يتم تحويله إلى

RRDs::update ("mydemo.rrd", "--template", "in:out", "N:12:13");

لاحظ أن

--template=in:out

صالح أيضًا.

تأخذ الوظيفة RRDs::times معاملين: وقت "البداية" و "النهاية". يجب تحديد هذه الأوقات بتنسيق **تحديد الوقت بأسلوب AT** المستخدم بواسطة RRDtool. راجع وثائق **rrdfetch** للحصول على شرح مفصل لكيفية تحديد الوقت.

معالجة الأخطاء

لن تقوم وظائف RRD بإيقاف برنامجك حتى عندما لا تتمكن من فهم الوسائط التي قدمتها لها.

يجب استدعاء الوظيفة RRDs::error للحصول على حالة الخطأ بعد كل استدعاء وظيفة. إذا لم تُرجع RRDs::error شيئًا، فقد أكملت الوظيفة السابقة مهمتها بنجاح.

use RRDs;
RRDs::update ("mydemo.rrd","N:12:13");
my $ERR=RRDs::error;
die "ERROR while updating mydemo.rrd: $ERR\n" if $ERR;

قيم الإرجاع

تُرجع الوظائف RRDs::last، RRDs::graph، RRDs::info، RRDs::fetch، و RRDs::times نتائجها.

RRDs::last تُرجع عددًا صحيحًا واحدًا يمثل آخر وقت تحديث.

$lastupdate = RRDs::last ...

RRDs::graph تُرجع مصفوفة تحتوي على حجم x وحجم y للصورة المنشأة ومؤشر إلى مصفوفة تحتوي على نتائج وسائط PRINT.

($result_arr,$xsize,$ysize) = RRDs::graph ...
print "Imagesize: ${xsize}x${ysize}\n";
print "Averages: ", (join ", ", @$averages);

RRDs::info تُرجع مؤشرًا إلى تجزئة (hash). تمثل مفاتيح التجزئة أسماء خصائص RRD وقيم التجزئة هي قيم الخصائص.

$hash = RRDs::info "example.rrd";
foreach my $key (keys %$hash){
  print "$key = $$hash{$key}\n";
}

RRDs::graphv تأخذ نفس الوسائط مثل RRDs::graph ولكنها تُرجع مؤشرًا إلى تجزئة. تحتوي التجزئة المُرجعة على معلومات وصفية حول الرسم البياني. مثل حجمها وكذلك موضع منطقة الرسم البياني على الصورة. عند الاستدعاء باستخدام '-' كاسم ملف، يتم إرجاع محتويات الرسم البياني في التجزئة أيضًا (المفتاح 'image').

RRDs::updatev تُرجع أيضًا مؤشرًا إلى تجزئة. مفاتيح التجزئة هي سلاسل نصية مدمجة لوقت الطابع الزمني، وفهرس RRA، واسم مصدر البيانات لكل نقطة بيانات مجمعة (CDP) مكتوبة على القرص نتيجة لاستدعاء التحديث الحالي. قيم التجزئة هي قيم CDP.

RRDs::fetch هي الأكثر تعقيدًا من حيث قيم الإرجاع. هناك 4 قيم. عددان صحيحان عاديان، مؤشر إلى مصفوفة، ومؤشر إلى مصفوفة من المؤشرات.

my ($start,$step,$names,$data) = RRDs::fetch ... 
print "Start:       ", scalar localtime($start), " ($start)\n";
print "Step size:   $step seconds\n";
print "DS names:    ", join (", ", @$names)."\n";
print "Data points: ", $#$data + 1, "\n";
print "Data:\n";
for my $line (@$data) {
  print "  ", scalar localtime($start), " ($start) ";
  $start += $step;
  for my $val (@$line) {
    printf "%12.1f ", $val;
  }
  print "\n";
}

RRDs::xport يكشف عن وظيفة rrdxport ويُرجع البيانات بالبنية التالية:

my ($start,$end,$step,$cols,$names,$data) = RRDs::xport ...

# $start : طابع زمني
# $end   : طابع زمني
# $step  : ثواني
# $cols  : عدد الأعمدة المُرجعة
# $names : مؤشر مصفوفة بأسماء الأعمدة
# $data  : مؤشر مصفوفة لمؤشرات المصفوفات بالبيانات (الفهرس الأول هو الوقت، والثاني هو العمود)

RRDs::times تُرجع عددين صحيحين وهما عدد الثواني منذ عصر Unix (1970-01-01) للوسائط "البداية" و "النهاية" المقدمة، على التوالي.

راجع دليل الأمثلة لمزيد من الطرق لاستخدام هذا الامتداد.

وظيفة رد الاتصال لجلب البيانات

عادةً عند استخدام graph أو xport أو fetch، تأتي البيانات التي تراها من ملف rrd فعلي. لذلك، يقوم بعض الأشخاص الذين يحبون شكل رسوم RRD البيانية بتصدير بياناتهم من قاعدة بيانات ثم تحميلها إلى ملف rrd فقط ليكونوا قادرين على استدعاء rrdgraph عليها. باستخدام رد اتصال مخصص، يمكنك توفير التعليمات البرمجية الخاصة بك لمعالجة طلبات البيانات من graph و xport و fetch.

للقيام بذلك، يجب عليك أولاً كتابة وظيفة جلب بيانات في Perl، ثم تسجيل هذه الوظيفة باستخدام "RRDs::fetch_register_callback".

أخيرًا، يمكنك استخدام اسم المسار الزائف cb//[اسم الملف] لإخبار rrdtool باستخدام روتين رد الاتصال الخاص بك بدلاً من وظيفة جلب بيانات rrdtool العادية لتنظيم البيانات المطلوبة.

يجب أن تبدو وظيفة رد الاتصال كما يلي:

sub fetch_callback {
    my $args_hash = shift;
    # {
    #  filename => 'cb//somefilename',
    #  cd => 'AVERAGE',
    #  start => 1401295291,   
    #  end => 1401295591,
    #  step => 300 }
    # do some clever thing to get that data ready    
    return {
        start => $unix_timestamp,
        step => $step_width,
        data => {
            dsName1 => [ value1, value2, ... ],
            dsName2 => [ value1, value2, ... ],
            dsName3 => [ value1, value2, ... ],
        }
   };
}

ملاحظة

إذا كنت تتلاعب بالمتغير TZ، فيجب عليك أيضًا استدعاء وظيفة POSIX tzset(3) لتهيئة جميع الحالات الداخلية للمكتبة للعمل بشكل صحيح في المنطقة الزمنية التي تختارها.

use POSIX qw(tzset);
$ENV{TZ} = 'CET';   
POSIX::tzset();
