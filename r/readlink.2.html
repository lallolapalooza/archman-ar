readlink(2) دليل استدعاءات النظام readlink(2)

الاسم

readlink, readlinkat - قراءة قيمة رابط رمزي

المكتبة

مكتبة C القياسية (libc, -lc)

الملخص

#include <unistd.h>
ssize_t readlink(const char *restrict path, char buf[restrict bufsiz], size_t bufsiz);
#include <fcntl.h>            /* تعريف ثوابت AT_* */
#include <unistd.h>
ssize_t readlinkat(int dirfd, const char *restrict path, char buf[restrict bufsiz], size_t bufsiz);
متطلبات سمات اختبار الميزات لـ glibc (انظر feature_test_macros(7)):

readlink():

    _XOPEN_SOURCE >= 500 || _POSIX_C_SOURCE >= 200112L
        || /* glibc <= 2.19: */ _BSD_SOURCE

readlinkat():

الوصف

يقوم readlink() بوضع محتويات الرابط الرمزي path في المخزن المؤقت buf، والذي حجمه bufsiz. readlink() لا يلحق بايت نهاية صفري بـ buf. سيقوم (بصمت) بتقصير المحتويات (إلى طول bufsiz حرف)، في حالة كان المخزن المؤقت صغيرًا جدًا لاستيعاب كل المحتويات.

readlinkat()

استدعاء النظام readlinkat() يعمل تمامًا مثل readlink()، باستثناء الاختلافات الموضحة هنا.

إذا كان path نسبيًا، فسيتم تفسيره بالنسبة للدليل الذي يشير إليه واصف الملف dirfd (بدلاً من كونه نسبيًا لمجلد العمل الحالي للعملية المتصلة، كما يفعل readlink() لمسار نسبي).

إذا كان path نسبيًا و dirfd هي القيمة الخاصة AT_FDCWD، فسيتم تفسير path نسبيًا لمجلد العمل الحالي للعملية المتصلة (مثل readlink()).

إذا كان path مطلقًا، فسيتم تجاهل dirfd.

منذ Linux 2.6.39، يمكن أن يكون path سلسلة فارغة، وفي هذه الحالة يعمل الاستدعاء على الرابط الرمزي الذي يشير إليه dirfd (والذي يجب أن يكون قد تم الحصول عليه باستخدام open(2) مع العلامتين O_PATH و O_NOFOLLOW).

انظر openat(2) لشرح الحاجة إلى readlinkat().

قيمة الإرجاع

عند النجاح، تعيد هذه الاستدعاءات عدد البايتات التي تم وضعها في buf. (إذا كانت القيمة المعادة تساوي bufsiz، فقد يكون قد حدث اقتطاع.) عند حدوث خطأ، يتم إرجاع -1 ويتم تعيين errno للإشارة إلى الخطأ.

الأخطاء

EACCES
يُمنع إذن البحث عن مكون من بادئة المسار. (انظر أيضًا path_resolution(7).)
EBADF
(readlinkat()) path نسبي ولكن dirfd ليس AT_FDCWD ولا واصف ملف صالح.
EFAULT
يمتد buf خارج مساحة العنوان المخصصة للعملية.
EINVAL
bufsiz ليس موجبًا.
EINVAL
الملف المسمى (أي، المكون النهائي لاسم الملف لـ path) ليس رابطًا رمزيًا.
EIO
حدث خطأ في الإدخال/الإخراج أثناء القراءة من نظام الملفات.
ELOOP
تم العثور على عدد كبير جدًا من الروابط الرمزية أثناء ترجمة اسم المسار.
ENAMETOOLONG
كان اسم المسار، أو مكون من اسم المسار، طويلاً جدًا.
ENOENT
الملف المسمى غير موجود.
ENOMEM
لم تكن ذاكرة النواة الكافية متاحة.
ENOTDIR
مكون من بادئة المسار ليس دليلًا.
ENOTDIR
(readlinkat()) path نسبي و dirfd هو واصف ملف يشير إلى ملف بخلاف دليل.

المعايير

POSIX.1-2024.

التاريخ

readlink()
4.4BSD (ظهرت لأول مرة في 4.2BSD)، POSIX.1-2001، POSIX.1-2008.
readlinkat()
POSIX.1-2008. Linux 2.6.16، glibc 2.4.

حتى glibc 2.4 بما في ذلك، كان نوع الإرجاع لـ readlink() معرّفًا كـ int. حاليًا، نوع الإرجاع معرّف كـ ssize_t، كما هو مطلوب (حديثًا) في POSIX.1-2001.

glibc

على النوى القديمة التي لا يتوفر فيها readlinkat()، يعود استدعاء glibc إلى استخدام readlink(). عندما يكون path نسبيًا، يقوم glibc بإنشاء اسم مسار بناءً على الرابط الرمزي في /proc/self/fd الذي يتوافق مع الوسيط dirfd.

ملاحظات

قد لا يوفر استخدام مخزن مؤقت بحجم ثابت مساحة كافية لمحتويات الرابط الرمزي. يمكن الحصول على الحجم المطلوب للمخزن المؤقت من قيمة stat.st_size التي تعيدها استدعاء lstat(2) على الرابط. ومع ذلك، يجب التحقق من عدد البايتات التي كتبها readlink() و readlinkat() للتأكد من أن حجم الرابط الرمزي لم يزد بين الاستدعاءات. تخصيص المخزن المؤقت ديناميكيًا لـ readlink() و readlinkat() يعالج أيضًا مشكلة قابلية نقل شائعة عند استخدام PATH_MAX لحجم المخزن المؤقت، حيث لا يُضمن تعريف هذا الثابت حسب POSIX إذا لم يكن للنظام مثل هذا الحد.

readlink(2) — archlinux man pages

NAME

readlink, readlinkat — read the contents of a symbolic link

LIBRARY

Real-time library (libc, -lrt)

SYNOPSIS 

       #include <unistd.h>>

       ssize_t readlink(const char *restrict pathname,
                        char *restrict buf, size_t bufsiz);
       ssize_t readlinkat(int dirfd, const char *restrict pathname,
                          char *restrict buf, size_t bufsiz);

DESCRIPTION

The readlink() function reads the symbolic link specified by pathname. The first bufsiz bytes of the buffer pointed to by buf are used to store the contents of the symbolic link. The value stored in buf is the string that was used to create the symbolic link. No null terminator is appended to the buffer.

The readlinkat() function is equivalent to readlink() except that the symbolic link is interpreted relative to the directory referred to by the file descriptor dirfd (rather than always relative to the current working directory); the symbolic link is pathname. If pathname is an absolute path, then dirfd is ignored.

If pathname refers to a symbolic link, then readlink() and readlinkat() return the number of bytes in the symbolic link's value, and the value is placed in the buffer referred to by buf. The value is not null-terminated.

If pathname does not refer to a symbolic link, then readlink() and readlinkat() return -1 and set errno to EINVAL.

If the buffer referenced by buf is not large enough to hold the contents of the symbolic link, then readlink() and readlinkat() return bufsiz, and the contents of the buffer are unspecified.

If pathname refers to a symbolic link and the length of the symbolic link's contents is equal to bufsiz, it is indeterminate whether the contents were truncated. A calling application must reallocate the buffer and call readlink() or readlinkat() again if it requires the entire contents.

If dirfd is AT_FDCWD, then pathname must refer to a symbolic link relative to the current working directory.

The special constant AT_FDCWD is defined in <fcntl.h>.

RETURN VALUE

On success, readlink() and readlinkat() return the number of bytes copied into the buffer pointed to by buf. If the return value is greater than 0 and less than bufsiz, the buffer contains the complete contents of the symbolic link, and it is not null-terminated.

If the return value is equal to bufsiz, the contents of the buffer may have been truncated. The caller should reallocate the buffer and call readlink() or readlinkat() again to ensure that the entire contents were read.

On failure, they return -1 and set errno to indicate the error.

ERRORS

EACCES
Search permission denied for one of the components of the path prefix.
EBADF
dirfd is not a valid file descriptor.
EINVAL
pathname does not refer to a symbolic link, or bufsiz is zero and the symbolic link is empty.
EIO
An I/O error occurred while reading from the filesystem.
ELOOP
Too many symbolic links were encountered while resolving pathname.
ENAMETOOLONG
pathname is too long.
ENOENT
pathname does not exist or pathname is an empty string and dirfd refers to a directory that has been deleted.
ENOMEM
Insufficient kernel memory was available.
ENOTDIR
dirfd refers to a file that is not a directory, or one of the components of pathname (except the last) is not a directory.
EOVERFLOW
A component of pathname is too large to be represented. (This is rare, and only likely to happen in virtual file systems.)
EROFS
pathname refers to a file on a read-only filesystem, and the symbolic link target was potentially modified.
ETXTBSY
A binary file is being executed.

The readlinkat() function can also fail with the following errors:

EINVAL
dirfd is not AT_FDCWD and pathname is not an absolute path.
ENOTDIR
dirfd refers to a file that is not a directory.

STANDARDS

readlink(): POSIX.1-2001, POSIX.1-2008, XSI —companions. readlinkat(): POSIX.1-2008.

HISTORY

readlink() first appeared in AT&T System V.

readlinkat() was added in version 2.1 of glibc.

NOTES

The symbolic link itself is not followed. The contents of the symbolic link are returned.

If pathname refers to a symbolic link, and the length of the contents of the symbolic link is greater than or equal to bufsiz, then readlink() and readlinkat() return bufsiz, and the buffer buf contains bufsiz bytes of the link contents, but it is indeterminate whether the contents were truncated. In this case, a robust application should allocate a larger buffer and call readlink() or readlinkat() again.

If pathname refers to a symbolic link and the length of the symbolic link's contents is 0, readlink() and readlinkat() return 0, and the contents of the buffer remain unspecified.

For readlinkat(), if both pathname and dirfd are specified, the final path is the concatenation of the path specified by dirfd and the path specified by pathname.

The behavior of readlink() and readlinkat() when pathname refers to a file other than a symbolic link is described in lstat(2). However, readlink() and readlinkat() return an error if pathname does not refer to a symbolic link.

In the Linux kernel, readlink() is implemented as a call to readlinkat() with dirfd set to AT_FDCWD.

EXAMPLES

The following example program demonstrates the use of readlink():

#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <errno.h>
#include <string.h>

int
main(int argc, char *argv[])
{
    char *buf = NULL;
    char *ptr;
    size_t bufsiz = 0;
    ssize_t nbytes;

    if (argc != 2) {
        fprintf(stderr, "Usage: %s <file>\n", argv[0]);
        exit(EXIT_FAILURE);
    }

    /*
     * Allocate a buffer that grows as needed.
     */
    for (bufsiz = 128; ; bufsiz *= 2) {
        buf = malloc(bufsiz);
        if (buf == NULL) {
            perror("malloc");
            exit(EXIT_FAILURE);
        }

        nbytes = readlink(argv[1], buf, bufsiz);
        if (nbytes == -1) {
            perror("readlink");
            free(buf);
            exit(EXIT_FAILURE);
        }

        if (nbytes < bufsiz) {
            /*
             * The readlink() call succeeded and did not truncate the
             * contents.  We can break out of the loop.
             */
            break;
        }

        /*
         * The buffer was not large enough. free() the buffer and
         * loop again with a larger buffer.
         */
        free(buf);
        buf = NULL;
    }

    /*
     * The buffer contains the contents of the symbolic link.
     * Print the contents, but only up to nbytes, as readlink()
     * does not append a null terminator.
     */
    printf("'%s' points to '%.*s'\n", argv[1], (int) nbytes, buf);

    /*
     * If the return value was equal to the buffer size, then
     * the link target was larger than expected (perhaps because the
     * target was changed between the call to lstat() and the call to
     * readlink()).  Warn the user that the returned target may have
     * been truncated.  */
    if (nbytes == bufsiz)
        printf("(Returned buffer may have been truncated)\n");

    free(buf);
    exit(EXIT_SUCCESS);
}
