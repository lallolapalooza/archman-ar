RUBBER(1)General Commands ManualRUBBER(1)
\n
\n
\n

NAME

\n

rubber - a building system for LaTeX documents

\n
\n
\n

SYNOPSIS

\n

rubber [options] sources ...\n
\n rubber-pipe [options]

\n
\n
\n

DESCRIPTION

\n

Rubber is a wrapper for LaTeX and companion programs. Its purpose\n is, given a LaTeX source to process, to compile it enough times to resolve\n all references, possibly running satellite programs such as BibTeX,\n makeindex, Metapost, etc. to produce appropriate data files.

\n

The command rubber builds the specified documents\n completely. The source files may be either LaTeX sources (in which case the\n suffix .tex may be omitted) or documents in a format Rubber knows how to\n translate into LaTeX. If one compilation fails, the whole process stops,\n including the compilation of the next documents on the command line, and\n rubber returns a non-zero exit code.

\n

The command rubber-pipe does the same for one document but\n it reads the LaTeX source from standard input and dumps the compiled\n document on standard output.

\n

Some information cannot be extracted from the LaTeX sources. This\n is the case, for instance, with the search paths (which can be specified in\n environment variables like TEXINPUTS), or the style to be used with\n Makeindex. To address this problem, one can add information for Rubber in\n the comments of the LaTeX sources, see section DIRECTIVES.

\n
\n
\n

OPTIONS

\n

The options are used either to choose the action to be performed\n or to configure the building process. They are mostly the same in\n rubber and rubber-pipe. Options are parsed using GNU Getopt\n conventions.

\n
\n
-b, --bzip2
\n
Compress the final document (in bzip2 format). This is equivalent\n to saying -o bzip2 after all other options.
\n
--clean
\n
Remove all files produced by the compilation, instead of building the\n document. This option is present in rubber only. It applies to the\n compilation as it would be done with the other options of the command\n line, i.e. saying "rubber --clean foo" will not delete foo.ps,\n while saying "rubber --ps --clean foo" will.
\n
-c, --command <command>
\n
Execute the specified command (or directive) before parsing the\n input files. See section DIRECTIVES for details.
\n
-e, --epilogue <command>
\n
Execute the specified command (or directive) after parsing the\n input files. See section DIRECTIVES for details.
\n
-f, --force
\n
Force at least one compilation of the source. This may be useful, for\n instance, if some unusual dependency was modified (e.g. a package in a\n system directory). This option is irrelevant in rubber-pipe.
\n
-z, --gzip
\n
Compress the final document (in gzip format). This is equivalent to\n saying -o gz after all other options.
\n
-h, --help
\n
Display the list of all available options and exit nicely.
\n
--inplace
\n
Go to the directory of the source files before compiling, so that\n compilation results are in the same place as their sources.
\n
--into <directory>
\n
Go to the specified directory before compiling, so that all files are\n produced there and not in the current directory.
\n
--jobname <name>
\n
Specify a job name different from the base file name. This changes the\n name of output files and only applies to the first target.
\n
-k, --keep
\n
This option is used in rubber-pipe only. With this option, the\n temporary files will not be removed after compiling the document and\n dumping the results on standard output. The temporary document is named\n rubtmpX.tex, where X is a number such that no file of that name exists\n initially.
\n
-n, --maxerr <num>
\n
Set the maximum number of displayed errors. By default, up to 10 errors\n are reported, saying -n -1 displays all errors.
\n
-m, --module <module>[:<args>]
\n
Use the specified module in addition to the document's packages. Arguments\n can be passed to the package by adding them after a colon, they correspond\n to the package options in LaTeX. The module is loaded before\n parsing the document's sources.
\n
--only <sources>
\n
Compile the document partially, including only the specified sources. This\n works by inserting a call to \\includeonly on the command line. The\n argument is a comma-separated list of file names.
\n
-o, --post <module>[:<args>]
\n
Use the specified module as a post-processor. This is similar to the\n -m options except that the module is loaded after parsing\n the document.
\n
-d, --pdf
\n
Produce PDF output. When this option comes after --ps (for instance\n in the form -pd) it is a synonym for -o ps2pdf, otherwise it acts as -m pdftex, in order to use pdfLaTeX\n instead of LaTeX.
\n
-p, --ps
\n
Process the DVI produced by the process through dvips(1) to produce\n a PostScript document. This option is a synonym for\n -o dvips, it cannot come after --pdf.
\n
-q, --quiet
\n
Decrease the verbosity level. This is the reverse of -v.
\n
-r, --read <file>
\n
Read additional directives from the specified file (see also the directive\n "read").
\n
-S, --src-specials
\n
Enable generation of source specials if the compiler supports it. This is\n equivalent to setting the variable src-specials to yes.
\n
-s, --short
\n
Display LaTeX's error messages in a compact form (one error per\n line).
\n
-I, --texpath <directory>
\n
Add the specified directory to TeX's search path.
\n
--synctex
\n
Enable SyncTeX support in the LaTeX run.
\n
--unsafe
\n
Permit the document to invoke arbitrary external programs. This is\n potentially dangerous, only use this option for documents coming from a\n trusted source.
\n
-v, --verbose
\n
Increase the verbosity level. Levels between 0 and 4 exist, the default\n level is 1 for rubber and 0 for rubber-pipe. Beware, saying\n -vvv makes Rubber speak a lot.
\n
--version
\n
Print the version number and exit nicely.
\n
-W, --warn <type>
\n
Report information of the given type if there was no error during\n compilation. The available types are: boxes (overfull and underfull\n boxes), refs (undefined or multiply defined references),\n misc (other warnings) and all to report all warnings.
\n
\n
\n
\n

MODULES

\n

Rubber's action is influenced by modules. Modules take care of the\n particular features of packages and external programs.

\n
\n

Packages

\n

For every package that a document uses, Rubber looks for a module\n of the same name to perform the tasks that this package my require apart\n from the compilation by LaTeX. Modules

asymptote
يعالج ملفات .asy التي تم إنشاؤها بواسطة حزمة LaTeX، ثم يقوم بتشغيل إعادة ترجمة.
beamer
تتعامل هذه الوحدة مع ملفات Beamer الإضافية بنفس الطريقة التي تتعامل بها مع جداول المحتويات الأخرى.
bibtex, biblatex
تتولى معالجة قائمة المراجع في المستند باستخدام BibTeX عند الحاجة. يتم تحميل هذه الوحدة تلقائيًا إذا كان المستند يحتوي على الماكرو \bibliography (انظر أيضًا في التوجيهات للخيارات).
combine
تُستخدم حزمة combine لتجميع العديد من مستندات LaTeX في مستند واحد، وتتعامل هذه الوحدة مع التبعيات في هذه الحالة.
epsfig
تتعامل هذه الوحدة مع تضمين الرسوميات للمستندات التي تستخدم الماكرو \psfig القديم. إنها في الواقع واجهة لوحدة الرسوميات، انظر هذه الوحدة للحصول على التفاصيل.
glossaries
تشغل makeglossaries وتعيد الترجمة عند تغيير ملف .glo.
graphics, graphicx
تحدد هذه الوحدات الرسوميات المضمنة في المستند وتعتبرها تبعيات للترجمة. كما تستخدم قواعد قياسية لبناء هذه الملفات باستخدام برامج خارجية. انظر وثائق المعلومات للحصول على التفاصيل.
hyperref
تتعامل مع الملفات الإضافية التي تنتجها هذه الحزمة في بعض الحالات.
index, makeidx, nomencl
تعالج فهارس المستند وقوائم المصطلحات باستخدام makeindex(1) عند الحاجة (انظر القسم التوجيهات للخيارات).
ltxtable
تضيف تبعيات للملفات المدرجة عبر حزمة ltxtable في LaTeX.
minitoc, minitoc-hyper
عند التنظيف، قم بإزالة الملفات الإضافية التي تم إنشاؤها لإنشاء جداول محتويات جزئية.
moreverb, verbatim
تضيف الملفات المدرجة باستخدام \verbatiminput والماكرو المشابهة إلى قائمة التبعيات.
multibib
تتعامل مع قوائم المراجع الإضافية التي تنشئها هذه الحزمة، وتقوم بإزالة الملفات الإضافية عند التنظيف.
xr
تضيف ملفات .aux إضافية مستخدمة للمراجع الخارجية إلى قائمة التبعيات، بحيث تتم إعادة الترجمة تلقائيًا عند تغيير المستندات المشار إليها.

المعالجة المسبقة

الوحدات التالية متوفرة لاستخدام البرامج التي تنشئ مصدر LaTeX من تنسيق ملف مختلف:

cweb
الغرض من هذه الوحدة هو تشغيل cweave(1) إذا لزم الأمر قبل عملية الترجمة لإنتاج مصدر LaTeX. يتم تحميل هذه الوحدة تلقائيًا إذا كان الملف المحدد في سطر الأوامر له اللاحقة .w.
lhs2TeX
تستخدم هذه الوحدة المعالج المسبق lhs2TeX لإنشاء مصدر LaTeX من برنامج Haskell حرفي. يتم تشغيلها تلقائيًا إذا كان اسم ملف الإدخال ينتهي بـ .lhs.

المعالجة اللاحقة

الوحدات التالية متوفرة لدعم أنواع مختلفة من المعالجات اللاحقة. لاحظ أن الترتيب مهم عند استخدام هذه الوحدات: إذا كنت ترغب في استخدام سلسلة معالجة مثل

foo.tex -> foo.dvi -> foo.ps -> foo.pdf -> foo.pdf.gz
عليك تحميل الوحدات dvips و ps2pdf و gz بهذا الترتيب، على سبيل المثال باستخدام سطر الأوامر
rubber -p -o ps2pdf -z foo.tex
bzip2
ينتج نسخة مضغوطة من الملف النهائي باستخدام bzip2(1).
dvipdfm
يشغل dvipdfm(1) في نهاية الترجمة لإنتاج مستند PDF.
dvips
يشغل dvips(1) في نهاية الترجمة لإنتاج مستند PostScript. يتم تحميل هذه الوحدة أيضًا بواسطة خيار سطر الأوامر --ps.
expand
ينتج مصدر LaTeX موسع عن طريق استبدال ماكرو \input بالملفات المضمنة، وماكرو قائمة المراجع بقائمة المراجع التي تنتجها bibtex(1)، والفئات والحزم المحلية بمصادرها. إذا كان الملف الرئيسي هو foo.tex، فسيكون اسم الملف الموسع foo-final.tex. انظر وثائق المعلومات للحصول على التفاصيل.
gz
ينتج نسخة مضغوطة من الملف النهائي باستخدام gzip(1).
ps2pdf
بافتراض أن الترجمة تنتج مستند PostScript (على سبيل المثال، باستخدام الوحدة dvips)، قم بتحويل هذا المستند إلى PDF باستخدام ps2pdf(1).

اختيار المترجم

الوحدات التالية تستخدم لتغيير مترجم LaTeX:

aleph
استخدم مترجم Aleph بدلاً من TeX، أي ترجم المستند باستخدام lamed(1) بدلاً من latex.
omega
استخدم مترجم Omega بدلاً من TeX، أي ترجم المستند باستخدام lambda(1) بدلاً من latex. إذا تم استخدام الوحدة dvips أيضًا، فستستخدم odvips(1) لترجمة ملف DVI. لاحظ أنه يتم تشغيل هذه الوحدة تلقائيًا عند استخدام المستند للحزمة omega.
pdftex
يُعلم Rubber باستخدام pdflatex(1) بدلاً من latex(1) لترجمة المستند. افتراضيًا، ينتج هذا ملف PDF بدلاً من DVI، ولكن عند تحميل الوحدة بالخيار dvi (على سبيل المثال، بقول -m pdftex:dvi) يتم ترجمة المستند إلى DVI باستخدام pdflatex. يتم تحميل هذه الوحدة أيضًا بواسطة خيار سطر الأوامر --pdf.
vtex
يُعلم Rubber باستخدام مترجم VTeX. افتراضيًا، يستخدم هذا vlatex كمترجم لإنتاج مخرجات PDF. مع الخيار ps (على سبيل المثال، عند قول "rubber -m vtex:ps foo.tex") يكون المترجم المستخدم هو vlatexp والنتيجة هي ملف PostScript.
xelatex
يُعلم Rubber باستخدام xelatex(1) بدلاً من latex.

التوجيهات

يعتمد السلوك التلقائي لـ Rubber على البحث عن الماكرو في مصادر LaTeX. عندما لا يكون هذا كافيًا، يمكن إضافة توجيهات في تعليقات المصادر. التوجيه هو سطر مثل

% rubber: cmd args
يجب أن يبدأ السطر بـ "%"، ثم أي تسلسل من علامات "%" ومسافات، ثم النص "rubber:" متبوعًا بمسافات واسم أمر، ويمكن أن يتبعه مسافات وحجج.

التوجيهات العامة

alias <name1> <name2>
تظاهر بأن الماكرو name1 في LaTeX يعادل name2. يمكن أن يكون هذا مفيدًا عند تعريف أغلفة حول الماكرو المدعومة.
clean <file>
يشير إلى أنه يجب إزالة الملف المحدد عند التنظيف باستخدام --clean.
depend <file>
اعتبر الملف المحدد تبعية، بحيث سيتم التحقق من وقت تعديله.
make <file> [<options>]
يعلن أنه يجب إنشاء الملف المحدد. يمكن للخيارات تحديد الطريقة التي يجب إنتاجه بها، والخيارات المتاحة هي from <file> لتحديد المصدر و with <rule> لتحديد قاعدة التحويل. على سبيل المثال، القول "make foo.pdf from foo.eps" يشير إلى أنه يجب إنتاج foo.pdf من foo.eps، مع أي قاعدة تحويل يمكنها القيام بذلك. انظر وثائق المعلومات للحصول على تفاصيل حول تحويل الملفات.
module <module> [<options>]
تحميل الوحدة المحددة، مع الخيارات المحتملة. هذا يعادل خيار سطر الأوامر --module.
onchange <file> <command>
تنفيذ أمر shell المحدد بعد الترجمة إذا تغير محتويات الملف المحدد. ينتهي اسم الملف عند أول مسافة.
path <directory>
يضيف الدليل المحدد إلى مسار البحث لـ TeX (و Rubber). اسم الدليل هو كل ما يتبع المسافات بعد "path".
produce <file>
يعلن أن تشغيل LaTeX سيقوم بإنشاء أو تحديث الملف (الملفات) المحدد(ة).
read <file>
اقرأ ملف التوجيهات المحدد. يجب أن يحتوي الملف على توجيه واحد في كل سطر. يتم تجاهل الأسطر الفارغة والأسطر التي تبدأ بـ "%".
rules  ;
قراءة قواعد تحويل إضافية من الملف المحدد. تنسيق هذا الملف هو نفس تنسيق rules.ini، انظر توثيق المعلومات للتفاصيل.
set <name> <value>
تعيين قيمة متغير كسلسلة نصية. للتفاصيل حول المتغيرات الموجودة ومعانيها، انظر توثيق المعلومات.
setlist <name> <values>
تعيين قيمة متغير كقائمة سلاسل نصية (مفصولة بمسافات). للتفاصيل حول المتغيرات الموجودة ومعانيها، انظر توثيق المعلومات.
shell_escape
تمييز المستند على أنه يتطلب برامج خارجية (shell-escape أو write18). لا يقوم Rubber بتمكين هذا فعليًا إلا عند استدعائه مع الخيار --unsafe.
synctex
تمكين دعم SyncTeX في تشغيل LaTeX.
watch <file>
مراقبة الملف المحدد للتغييرات. إذا تغيرت محتويات هذا الملف بعد عملية تجميع، فسيتم تشغيل عملية تجميع أخرى. هذا مفيد في حالة قوائم المحتويات، على سبيل المثال.

توجيهات خاصة بالوحدات

إذا كان الأمر بالشكل foo.bar، فيعتبر أمرًا bar للوحدة foo. إذا لم يتم تسجيل هذه الوحدة عند العثور على التوجيه، فيتم تجاهل الأمر بصمت. بالنسبة للوحدات القياسية، فإن التوجيهات هي كما يلي:

biblatex.path <directory>
يضيف الدليل المحدد إلى مسار البحث لقواعد بيانات BibTeX (ملفات .bib).
bibtex.crossrefs <number>
يحدد الحد الأدنى لعدد crossref المطلوبة للإدراج التلقائي للمدخل المرجع في قائمة الاستشهادات. هذا يحدد الخيار -min-crossrefs عند استدعاء bibtex(1).
bibtex.path <directory>
يضيف الدليل المحدد إلى مسار البحث لقواعد بيانات BibTeX (ملفات .bib).
bibtex.stylepath <directory>
يضيف الدليل المحدد إلى مسار البحث لأنماط BibTeX (ملفات .bst).
bibtex.tool <command>
استخدام أداة ببليوغرافيا مختلفة بدلاً من BibTeX.
dvipdfm.options <options>
تمرير مفاتيح سطر الأوامر المحددة إلى dvipdfm.
dvips.options <options>
تمرير مفاتيح سطر الأوامر المحددة إلى dvips.
index.tool (index) <name>
يحدد الأداة التي سيتم استخدامها لمعالجة الفهرس. الأدوات المدعومة حاليًا هي makeindex(1) (الاختيار الافتراضي) و xindy(1). الوسيط index اختياري، ويمكن استخدامه لتحديد قائمة الفهارس التي ينطبق عليها الأمر. عند وجوده، يجب أن يكون محاطًا بأقواس؛ القائمة مفصولة بفواصل. عندما لا يكون الوسيط موجودًا، ينطبق الأمر على جميع الفهارس.
index.language (index) <language>
يحدد اللغة المستخدمة لفرز الفهرس. هذا ينطبق فقط عند استخدام xindy(1) كأداة فهرسة. الوسيط الاختياري له نفس الدلالات كما هو موضح أعلاه.
index.modules (index) <module>...
تحديد الوحدات التي سيتم استخدامها عند معالجة فهرس باستخدام xindy(1). الوسيط الاختياري له نفس الدلالات كما أعلاه.
index.order (index) <options>
يعدل خيارات الفرز للفهارس. الوسائط هي كلمات (مفصولة بمسافات) من بين standard، german و letter. هذا ينطبق فقط عند استخدام makeindex(1). الوسيط الاختياري له نفس الدلالات كما هو موضح أعلاه.
index.path (index) <directory>
يضيف الدليل المحدد إلى مسار البحث لأنماط الفهرس (ملفات .ist). الوسيط الاختياري له نفس الدلالات كما هو موضح أعلاه.
index.style (index) <style>
يحدد نمط الفهرس الذي سيتم استخدامه. الوسيط الاختياري له نفس الدلالات كما هو موضح أعلاه.
makeidx.language, .modules, .order, .path, .style, .tool
هذه التوجيهات هي نفسها كما في وحدة index، باستثناء أنها لا تقبل الوسيط الاختياري.
multibib.crossrefs, .path, .stylepath, .tool
هذه التوجيهات هي نفسها كما في وحدة bibtex ولكنها تنطبق على الببليوغرافيا التي تديرها حزمة multibib. تأخذ وسيطًا أول اختياريًا، بنفس اصطلاح التوجيهات الخاصة بوحدة index، والذي يمكن استخدامه لتحديد قائمة الببليوغرافيا التي ينطبق عليها الأمر.

يتم صيانة التوثيق الكامل لـ rubber كدليل Texinfo. إذا تم تثبيت برامج info و rubber بشكل صحيح في موقعك، فإن الأمر

info rubber

يجب أن يمنحك الوصول إلى الدليل الكامل.
