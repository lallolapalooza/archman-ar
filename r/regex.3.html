ERRORS

The functions regcomp(3), regexec(3), and regerror(3) can fail for the following reasons:

REG_ASSERT
An internal assertion failed in the regex routines. This indicates a bug in the implementation.
REG_BADBR
The number of characters in a regular expression's interval expression, `{n,m}`, is not a valid number or is out of range.
REG_BADPAT
The regular expression contained invalid syntax.
REG_BADRPT
A repeat operator (`?`, `*`, `+`, or `{n,m}`) is not preceded by a parenthesized group or a valid regular expression.
REG_BOTHF
Both REG_NOTBOL and REG_BOL were specified.
REG_ECOLLATE
The regular expression tried to use the collation character class `[=char=]` or `[.char.]` but the current locale does not support collation.
REG_ECTYPE
An invalid character class was specified (e.g., `[a-z1-9]`).
REG_EESCAPE
The backslash character `\` was used as the last character of the regular expression.
REG_EEND
A newline character was encountered in the regular expression, but REG_NEWLINE was not specified.
REG_EILSEQ
A sequence of characters in the regular expression was not a valid multibyte sequence according to the current locale.
REG_EMAKEMATCH
The pattern contained too many marked (parenthesized) subexpressions.
REG_ENOSUB
A regular expression contained too few subexpressions. This can happen when using regerror(3) with an error code related to subexpressions, but regcomp(3) was originally called with REG_NOSUB.
REG_ENOSPACE
Insufficient memory was available to store the compiled regular expression.
REG_ERANGE
The starting point of a range expression was greater than the ending point of the range operator; for example, the ending point of the range occurs prior to the starting point.
REG_ESIZE
Compiled regular expression requires a pattern buffer larger than 64 kB. This is not defined by POSIX.
REG_ESPACE
The regex routines ran out of memory.
REG_ESUBREG
Invalid back reference to a subexpression.

STANDARDS

POSIX.1-2008.

HISTORY

POSIX.1-2001.

Prior to POSIX.1-2008, regoff_t was required to be capable of storing the largest value that can be stored in either an off_t type or a ssize_t type.

CAVEATS

re_nsub is only required to be initialized if REG_NOSUB wasn't specified, but all known implementations initialize it regardless.

Both regex_t and regmatch_t may (and do) have more members, in any order. Always reference them by name.

EXAMPLES

#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <regex.h>
#define NITEMS(arr)  (sizeof((arr)) / sizeof((arr)[0]))
static const char *const str =
        "1) John Driverhacker;\n2) John Doe;\n3) John Foo;\n";
static const char *const re = "John.*o";
int main(void)
{
    static const char *s = str;
    regex_t     regex;
    regmatch_t  pmatch[1];
    regoff_t    off, len;
    if (regcomp(&regex, re, REG_NEWLINE))
        exit(EXIT_FAILURE);
    printf("String = \"%s\"\n", str);
    printf("Matches:\n");
    for (unsigned int i = 0; ; i++) {
        if (regexec(&regex, s, NITEMS(pmatch), pmatch, 0))
            break;
        off = pmatch[0].rm_so + (s - str);
        len = pmatch[0].rm_eo - pmatch[0].rm_so;
        printf("#%u:\n", i);
        printf("offset = %jd; length = %jd\n", (intmax_t) off,
                (intmax_t) len);
        printf("substring = \"%.*s\"\n", len, s + pmatch[0].rm_so);
        s += pmatch[0].rm_eo;
    }
    exit(EXIT_SUCCESS);
}
