reallocarray(3bsd)

الحزمة: libbsd

التراخيص: custom

reallocarray(3bsd) 3bsd reallocarray(3bsd)

الاسم

reallocarray، recallocarray، freezero — تخصيص وإلغاء تخصيص الذاكرة

المكتبة

المكتبة “libbsd”

الملخص

#include <stdlib.h> (انظر libbsd(7) لاستخدام التضمين.)
void *
reallocarray(void *ptr, size_t nmemb, size_t size);

void *
recallocarray(void *ptr, size_t oldnmemb, size_t nmemb, size_t size);

void
freezero(void *ptr, size_t size);

الوصف

مصممة للتخصيص الآمن للمصفوفات، فإن الدالة reallocarray() تشبه الدالة realloc() باستثناء أنها تعمل على nmemb عضو بحجم size وتتحقق من تجاوز الأعداد الصحيحة في حساب nmemb * size.

تستخدم لتخصيص الذاكرة التي تحمل بيانات حساسة، وتضمن الدالة recallocarray() أن الذاكرة التي أصبحت غير مخصصة يتم التخلص منها بشكل صريح، مما يعني أن الكائنات المجانية المخزنة مؤقتًا يتم مسحها باستخدام explicit_bzero(3).

الدالة recallocarray() تشبه الدالة reallocarray() باستثناء أنها تضمن مسح الذاكرة المخصصة حديثًا بشكل مشابه للدالة calloc(). إذا كان ptr هو NULL، يتم تجاهل oldnmemb وتكون المكالمة مكافئة للدالة calloc(). إذا لم يكن ptrNULL، فيجب أن يكون oldnmemboldnmemb * size هو حجم التخصيص السابق الذي أعاد ptr، وإلا فإن السلوك غير محدد. الدالة freezero() تشبه الدالة free() باستثناء أنها تضمن التخلص الصريح من الذاكرة. إذا كان ptr هو NULL، فلا يحدث أي إجراء. إذا لم يكن ptrNULL، يجب أن يكون الوسيط size مساويًا أو أصغر من حجم التخصيص السابق الذي أعاد ptr. تضمن freezero() أن نطاق الذاكرة بدءًا من ptrsize يتم التخلص منه أثناء إلغاء تخصيص الكائن بأكمله المخصص في الأصل.

قيم الإرجاع

تعيد الدالتان reallocarray() و recallocarray() مؤشرًا إلى المساحة المخصصة إذا نجحت؛ وإلا، يتم إرجاع مؤشر فارغ ويتم تعيين errno إلى ENOMEM.

إذا أدى ضرب nmemb و size إلى تجاوز الأعداد الصحيحة، فإن reallocarray() و recallocarray() ترجعان NULL وتعينان errno إلى ENOMEM.

إذا لم يكن ptrNULL وأدى ضرب oldnmemb و size إلى تجاوز الأعداد الصحيحة، فإن recallocarray() ترجع NULL وتعين errno إلى EINVAL.

اصطلاحات

ضع في اعتبارك calloc() أو الامتدادات reallocarray() و recallocarray() عندما يكون هناك ضرب في الوسيط size للدالة malloc() أو realloc(). على سبيل المثال، تجنب هذا الاصطلاح الشائع لأنه قد يؤدي إلى تجاوز الأعداد الصحيحة:

if ((p = malloc(num * size)) == NULL)
	err(1, NULL);

بديل مباشر هو reallocarray():

if ((p = reallocarray(NULL, num, size)) == NULL)
	err(1, NULL);

بدلاً من ذلك، يمكن استخدام calloc() بتكلفة عبء التهيئة.

عند استخدام realloc()، كن حذرًا لتجنب الاصطلاح التالي:

size += 50;
if ((p = realloc(p, size)) == NULL)
	return (NULL);

لا تقم بتعديل المتغير الذي يصف مقدار الذاكرة التي تم تخصيصها حتى ينجح التخصيص. هذا يمكن أن يسبب سلوكًا شاذًا للبرنامج إذا تم استخدام قيمة حجم غير صحيحة. في معظم الحالات، ستؤدي العينة أعلاه أيضًا إلى تسرب في الذاكرة. كما ذكرنا سابقًا، يشير إرجاع NULL إلى أن الكائن القديم لا يزال مخصصًا. الكود الأفضل يبدو كالتالي:

newsize = size + 50;
if ((newp = realloc(p, newsize)) == NULL) {
	free(p);
	p = NULL;
	size = 0;
	return (NULL);
}
p = newp;
size = newsize;

كما هو الحال مع malloc()، من المهم التأكد من أن قيمة الحجم الجديدة لن تتجاوز؛ أي تجنب التخصيصات مثل التالية:

if ((newp = realloc(p, num * size)) == NULL) {
	...

بدلاً من ذلك، استخدم reallocarray():

if ((newp = reallocarray(p, num, size)) == NULL) {
	...

استدعاء realloc() مع ptr بقيمة NULL يكافئ استدعاء malloc(). بدلاً من هذا الاصطلاح:

if (p == NULL)
	newp = malloc(newsize);
else
	newp = realloc(p, newsize);

استخدم ما يلي:

newp = realloc(p, newsize);

يجب استخدام الدالة recallocarray() لتغيير حجم الكائنات التي تحتوي على بيانات حساسة مثل المفاتيح. لتجنب تسرب المعلومات، تضمن مسح الذاكرة قبل وضعها في قائمة الكائنات الحرة الداخلية. يجب إلغاء تخصيص كائن كهذا عن طريق استدعاء freezero().
