ros-template - تحرير قالب لـ ros-init

الملخص

ros template أمر وسائط...

أوامر فرعية

init اسم-القالب
إنشاء قالب جديد في دليل المشروع المحلي.
deinit اسم-القالب
إزالة قالب من دليل المشروع المحلي.
list
عرض قائمة الملفات وحالات الملفات النوع الأذونات إعادة الكتابة في القوالب.
checkout [اسم-القالب]
عند استدعائها بدون اسم قالب، يعرض هذا الأمر المرشحين للقوالب الحالية للعمل عليها. إذا كان مع اسم القالب، يختار هذا الأمر الاسم كقالب حالي.
add [اسم-القالب] [ملفات ...]
إضافة ملفات إلى القالب الحالي. يمكن أن يكون المعامل الأول اسم قالب عندما يكون القالب الحالي هو الافتراضي.
cat [اسم-القالب] [ملفات ...]
عرض المحتويات في القالب الحالي.
edit [اسم-القالب] [ملفات ...]
تحرير محتوى الملفات في القالب باستخدام /usr/bin/editor.
path [اسم-القالب] [ملفات ...]
عرض المسار الأصلي للملفات في القالب.
rm [اسم-القالب] [ملفات ...]
إزالة ملف من القالب الحالي.
type [اسم-القالب] [نوع] [ملفات ...]
تغيير نوع الملف. الخيارات المتاحة لـ الأنواع هي djula أو copy. المتغيرات {{name}} {{author}} {{email}} {{universal_time}} متاحة في ملف القالب. بدون ملفات، يتم تغيير النوع الافتراضي.
chmod [اسم-القالب] [الوضع] [ملفات ...]
تغيير بتات وضع الملف للإنشاء. حدد الوضع بتنسيق ثماني.
rewrite [اسم-القالب] ملف قاعدة-إعادة-الكتابة
تغيير اسم الملف باستخدام قالب djula. المتغيرات {{name}} {{author}} {{email}} {{universal_time}} متاحة لـ قاعدة-إعادة-الكتابة.
export [اسم-القالب] [دليل]
تصدير الملفات في القالب الحالي إلى الدليل الحالي.
import [دليل]
استيراد قالب في الدليل الحالي
help
عرض المساعدة للأمر الفرعي.

الوصف

يدير الأمر ros-template(1) قوالب المشاريع.

إنشاء قالب

أولاً، يقوم الأمر الفرعي init بإنشاء قالب فارغ.

$ ros template init sample-template

تأخذ العديد من الأوامر الفرعية اسم قالب كمعامل أول. ولكن يمكنك حذفه باستخدام الأوامر الفرعية checkout. بعد التالي، يتم تطبيق هذه الأوامر الفرعية على sample-template.

$ ros template checkout sample-template

بعد ذلك، يضيف الأمر الفرعي add ملفات محلية إلى القالب. ثم، يعرض الأمر الفرعي list معلومات الملفات في القالب.

$ echo "Hello {{ author }}!!" > sample.txt
$ ros template add sample.txt
$ ros template list
      copy  sample.txt

كلمة copy تعني استراتيجية عند تطبيق القالب. هناك استراتيجيتان.

•
copy ينسخ الملف ببساطة كما هو.
•
djula يعالج محتوى الملف بواسطة محرك القوالب، Djula (http://mmontone.github.io/djula/).
•
سيتم شرح المتغيرات المتاحة لاحقًا.

يغير الأمر الفرعي type ذلك. بالإضافة إلى ذلك، يمكن تغيير الاستراتيجية الافتراضية (copy) لكل قالب بواسطة الأمر الفرعي type بدون أسماء ملفات (مثال. ros template type djula).

$ ros template type djula sample.txt
$ ros template list
      djula sample.txt

سيتم ببساطة إخراج sample.txt كـ sample.txt افتراضيًا. ولكن يمكنك تغييره بواسطة الأمر الفرعي rewrite. في المثال التالي، سيتم إخراجه كـ sample_<اسم المشروع>.txt.

$ ros template rewrite sample.txt "sample-{{ name }}.txt"
$ ros template list
      djula sample.txt -> "sample-{{ name }}.txt"

ملاحظة: يتم دائمًا معالجة قواعد إعادة الكتابة بواسطة Djula بغض النظر عن استراتيجية الملف.

تطبيق القالب

يمكن لـ ros-init(1) تحديد قالب.

$ mkdir temp ; cd temp
$ ros init sample-template some-project
$ ls
sample-some-project.txt
$ cat sample-some-project.txt # افترض أن "author" هو "alien"
Hello alien!!

يتم معالجة اسم الملف ومحتواه بواسطة Djula كما هو موضح أعلاه. يمكن استخدام المتغيرات التالية بشكل افتراضي.

•
{{name}}: اسم المشروع المحدد في ros-init(1)
•
{{author}}: اسم المؤلف المستخرج من إعدادات Git أو whoami
•
{{email}}: عنوان بريد إلكتروني مستخرج من إعدادات Git أو تم إنشاؤه باستخدام whoami واسم المضيف
•
{{universal_time}}: وقت عالمي تم إنشاؤه بواسطة وظيفة get-universal-time

بالإضافة إلى ذلك، يمكنك استخدام متغيرات أصلية كما يلي.

$ echo "Hello {{ area }}!!" > sample.txt
$ ros template add sample.txt # ملاحظة: سيتم الكتابة فوق الموجود
$ mkdir temp ; cd temp
$ ros init sample-template roswell --area 51
$ cat sample-roswell.txt
Hello 51!!

تصدير واستيراد القالب

بشكل أساسي، تم تصميم ros-template(1) لإدارة الملفات المضافة داخليًا.

ومع ذلك، إذا كنت ترغب، على سبيل المثال، في إدارته باستخدام Git في دليل محلي أو لتثبيت قوالب موزعة، يمكنك استخدام الأوامر الفرعية export و import.

أولاً، يقوم الأمر الفرعي export بتصدير الملفات المضافة وملف الإعداد roswell.init.<اسم القالب>.asd الذي تم إنشاؤه وتحريره داخليًا.

$ ros template export dir
$ ls dir
roswell.init.sample-template.asd  sample.txt
$ cat dir/sample.txt
Hello {{ area }}!!

ثانيًا، يقوم الأمر الفرعي import باستيرادها.

# افترض أن هذا جهاز آخر...
$ ros template list sample-template # لا يتم إخراج شيء
$ ls downloaded
roswell.init.sample-template.asd  sample.txt
$ ros template import downloaded
$ ros template list sample-template
      djula sample.txt -> "sample-{{ name }}.txt"

ملاحظة: إذا كان هناك قالب بنفس الاسم، فسيتم الكتابة فوقه.
