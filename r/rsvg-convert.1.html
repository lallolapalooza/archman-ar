rsvg-convert(1)

الحزمة: librsvg

التراخيص: LGPL-2.1-or-later

مرجع SVG

يتم عرض ملفات SVG إلى تنسيقات صور مختلفة بواسطة rsvg-convert .

تحديد حجم الصفحة

يتم تحديد حجم مستندات PDF و PS و EPS بواسطة سمات `width` و `height` الموجودة في عنصر `

إذا لم يتم تحديد `width` أو `height` في عنصر `

في هذا المثال، سيكون حجم الصورة الناتجة 2 بوصة × 3 بوصات (أو 192 × 288 بكسل عند DPI الافتراضي 96):

<svg xmlns="http://www.w3.org/2000/svg" width="2in" height="3in">
  <!-- graphical objects here -->
</svg>

تقوم الأوامر التالية بإنشاء ملفات PNG بأحجام مختلفة لملف SVG المثال أعلاه:

rsvg-convert two-by-three.svg > output.png #### ينشئ ملف PNG بدقة 192 * 288 بكسل

rsvg-convert --dpi-x=300 --dpi-y=300 two-by-three.svg > output.png #### ينشئ ملف PNG بدقة 600 * 900 بكسل

لاحظ أنه يتم تقريب أبعاد البكسل النهائية إلى أقرب بكسل، لتجنب قص الحواف اليمنى / السفلية. في المثال التالي، سيقوم rsvg-convert بإنشاء ملف PNG بحجم 300x300 بكسل:

rsvg-convert --width=299.5 --height=299.4 input.svg > output.png #### يخرج ملف PNG بدقة 300x300 بكسل مع صورة مقيّسة كسريًا

إذا حددت أبعادًا بالوحدات المادية، فسيتم ضربها في قيمة نقاط لكل بوصة (DPI) للحصول على أبعاد بالبكسل. على سبيل المثال، سينشئ هذا ملف PNG بدقة 96 × 96 بكسل، لأنه 1 × 1 بوصة عند DPI الافتراضي 96:

rsvg-convert --width=1in --height=1in input.svg > output.png #### يخرج ملف PNG بدقة 96x96 بكسل

وبالمثل، سينشئ هذا ملف PNG بدقة 300 × 300 بكسل، لأنه 1 × 1 بوصة عند 300 DPI:

rsvg-convert --width=1in --height=1in --dpi-x=300 --dpi-y=300 input.svg > output.png #### يخرج ملف PNG بدقة 300x300 بكسل

حجم الإخراج الافتراضي

إذا لم تحدد خيارات `--width` أو `--height` لحجم الإخراج، فسيقوم rsvg-convert بتحديد "حجم طبيعي" لـ SVG على النحو التالي:

  • SVG مع العرض والارتفاع بوحدات البكسل (px): <svg width="96px" height="192px"> لإخراج PNG، يتم استخدام نفس الأبعاد بالبكسل. بالنسبة لـ PDF/PS/EPS، يتم تحويل حجم البكسل هذا إلى وحدات مادية بناءً على قيمة DPI (انظر خيارات `--dpi-x` و `--dpi-y` )،
  • SVG مع العرض والارتفاع بالوحدات المادية: <svg width="1in" height="2in"> لإخراج PNG، يتم تحويل سمات `width` و `height` إلى بكسل، بناءً على قيمة DPI (انظر خيارات `--dpi-x` و `--dpi-y` ). بالنسبة لإخراج PDF/PS/EPS، يحدد العرض/الارتفاع بالوحدات المادية حجم الصفحة ما لم تحدد خيارات لحجم الصفحة؛ انظر تحديد حجم الصفحة أعلاه.
  • SVG مع viewBox فقط: <svg viewBox="0 0 20 30"> يتم استخدام حجم سمة `viewBox` لحجم البكسل للصورة كما في الحالة الأولى أعلاه.
  • SVG مع العرض والارتفاع بالنسب المئوية: <svg width="100%" height="100%" viewBox="0 0 20 30"> النسب المئوية لا معنى لها ما لم تحدد حجم منفذ عرض مع خيارات `--width` و `--height` . في غيابها، سيستخدم rsvg-convert ببساطة حجم `viewBox` لحجم البكسل، كما هو موضح أعلاه.
  • SVG بدون عرض أو ارتفاع أو viewBox: سيقوم rsvg-convert بقياس امتدادات جميع الكائنات الرسومية في مستند SVG وعرضها بمقياس 1:1 (1 بكسل لكل وحدة CSS px). يوصى بشدة بإعطاء مستندات SVG حجمًا صريحًا باستخدام سمات `width` أو `height` أو `viewBox` .

لون الخلفية

يمكنك استخدام الخيار `--background-color` ( `-b` اختصارًا) لتحديد لون الخلفية الذي سيظهر في أجزاء الصورة التي قد تكون شفافة بطريقة أخرى. يقبل هذا الخيار نفس بناء الجملة مثل خاصية CSS `color` ، لذا يمكنك استخدام بناء الجملة `#rrggbb` ، أو أسماء ألوان CSS مثل `white` ، أو `rgba()` .

rsvg-convert --background-color=white input.svg > output.png #### أبيض غير شفاف
rsvg-convert -b '#ff000080' input.svg > output.png #### أحمر شفاف - استخدم علامات اقتباس shell حتى لا يتم تفسير # كتعليق

اختيار لغة لـ SVG متعدد اللغات

يمكن لمستند SVG استخدام عنصر `` وعناصر فرعية بـ `systemLanguage` سمة لتوفير محتوى مختلف اعتمادًا على لغة المستخدم. على سبيل المثال:

<svg xmlns="http://www.w3.org/2000/svg" width="200" height="100">
  <rect width="200" height="100" fill="white"/>
  <g transform="translate(30, 30)" font-size="20">
    <switch allowReorder="yes">
      <text systemLanguage="es">Español</text>
      <text systemLanguage="de">Deutsch</text>
      <text systemLanguage="fr">Français</text>
      <text>English fallback</text>
    </switch>
  </g>
</svg>

يمكنك استخدام الخيار `--accept-language` لاختيار اللغة التي سيتم استخدامها عند التصيير. يقبل هذا الخيار سلاسل نصية بتنسيق مثل ترويسة HTTP Accept-Language ، وهي قائمة مفصولة بفواصل من علامات لغة BCP47: https://www.rfc-editor.org/info/bcp47

rsvg-convert --accept-language=es-MX input.svg > output.png #### يختار الإسبانية المكسيكية؛ يصيّر "Español".

ورقة أنماط المستخدم

يمكنك تضمين ورقة أنماط CSS إضافية لاستخدامها عند تصيير مستند SVG باستخدام الخيار `--stylesheet` . ستحتوي ورقة الأنماط على أصل المستخدم الخاص بـ CSS، بينما ستحتوي الأنماط المعلنة في مستند SVG على أصل المؤلف الخاص بـ CSS.

rsvg-convert --stylesheet=extra-styles.css input.svg > output.png

يرجى ملاحظة أنه وفقًا لقواعد CSS المتتالية، فإن ورقة أنماط المستخدم لا تتجاوز بالضرورة الأنماط المعرفة في مستند SVG. لتجاوزها بشكل موثوق، تحتاج إلى تعيين أنماطك الإضافية على !important.

وفقًا لمواصفات تعاقب CSS (https://www.w3.org/TR/css-cascade-4/#cascade-sort)، تتمتع إعلانات الأنماط بالأسبقية التالية. الإعلانات من الأصول اللاحقة في القائمة تفوز على الإعلانات من الأصول السابقة:

  • إعلانات وكيل المستخدم العادية (أنماط librsvg الخاصة).
  • إعلانات المستخدم العادية (من ورقة أنماط المستخدم الخاصة بك).
  • إعلانات المؤلف العادية (من مستند SVG).
  • إعلانات المؤلف !important (من مستند SVG).
  • إعلانات المستخدم !important (من ورقة أنماط المستخدم الخاصة بك).
  • إعلانات وكيل المستخدم !important (أنماط librsvg الخاصة).

بعد ذلك، تؤخذ خصوصية CSS وترتيب ظهور الإعلانات في الاعتبار.

ضع في اعتبارك input.svg التالي؛ لاحظ كيف أن المستطيل له `fill="red"` كسمة عرض، وفئة `recolorable`:

<svg xmlns="http://www.w3.org/2000/svg" width="100" height="100">
  <rect width="200" height="100" fill="white"/>
  <rect class="recolorable" x="10" y="10" width="50" height="50" fill="red"/>
  <text x="10" y="80" font-size="20" fill="red">Hello</text>
</svg>

وهذا هو extra-styles.css:

.recolorable { fill: blue !important; }
text { fill: green !important; }

ثم سيحتوي ملف PNG الذي تم إنشاؤه بواسطة الأمر أعلاه على هذه العناصر:

  • مربع أزرق بدلاً من مربع أحمر، بسبب المحدد لفئة `recolorable` . يتفوق إعلان `fill: blue !important;` على سمة العرض `fill="red"` .
  • نص باللون الأخضر، حيث تم تجاوز `fill="red"` الخاص به بـ fill: green !important .

خيارات

خيارات عامة

-f, --format format
تنسيق الإخراج للمستند المصيّر. القيم الممكنة هي png، pdf، pdf1.4، pdf1.5، pdf1.6، pdf1.7، ps، eps، svg. الافتراضي هو png. انظر قسم "إصدارات PDF" لمزيد من التفاصيل حول ما يسمح به كل منها.
-o, --output filename
تحديد اسم ملف الإخراج. إذا لم يتم تحديده، يتم الإخراج إلى المخرج القياسي.
-v, --version
عرض إصدار rsvg-convert الذي تستخدمه.
-?, --help
عرض ملخص للاستخدام والخيارات.

الحجم والموضع

فيما يلي، يجب تحديد قيم length باستخدام بناء جملة CSS <length>: https://developer.mozilla.org/en-US/docs/Web/CSS/length. على سبيل المثال، 640px أو 25cm.

--page-width length
عرض صفحة مستند الإخراج. الافتراضي هو استخدام عرض الصورة كمعدل

Name

rsvg-convert ‐ convert SVG files to other formats

Synopsis

rsvg-convert [OPTION...] [INPUT]

Description

The rsvg-convert utility converts the given SVG file INPUT to one of the following formats:

PNG
Portable Network Graphics
PDF
Portable Document Format
PS
PostScript
EPS
Encapsulated PostScript
SVG
Scalable Vector Graphics
TIFF
Tagged Image File Format

If INPUT is not specified, or if it is given as -, standard input is read. If no output file is specified with the --output option, the output is written to standard output.

The output format is determined by the filename extension of the output file, or by the --format option.

Options

The long and short options are separated by commas. Any whitespace in length or color arguments is ignored. SVG is one of the formats that can be specified for the --format option.

The following options are available:

-o, --output filename
Write output to filename instead of standard output.
-f, --format output-format
Write output in output-format format. Supported formats are png, pdf, ps, eps, svg, and tiff. If this option is omitted, the format is guessed from the filename extension of the --output option.
--page number
Render the given page number (starting from 1). If not specified, the first page is rendered. For formats that do not support multiple pages, this option is ignored.
--page-count number
Number of pages to render, starting from the page specified by --page. If not specified, only one page is rendered. For formats that do not support multiple pages, this option is ignored.
--page-height length
Page height of the output document. The default is to use the image's height as modified by the options below. Must be used together with --page-width.
--top length
Distance between top edge of the page and the rendered image. Default is 0.
--left length
Distance between left edge of the page and the rendered image. Default is 0.
-w, --width length
Width of the rendered image. If unspecified, the natural width of the image is used. See the section "SPECIFYING DIMENSIONS" above for details.
-h, --height length
Height of the rendered image. If unspecified, the natural height of the image is used. See the section "SPECIFYING DIMENSIONS" above for details.
-a, --keep-aspect-ratio
Specify that the aspect ratio is to be preserved. If not specified, aspect ratio will not be preserved. The image is scaled proportionally to fit in the --width and --height.
-d, --dpi-x number
Set the X resolution of the image in pixels per inch. Default is 96 DPI.
-p, --dpi-y number
Set the Y resolution of the image in pixels per inch. Default is 96 DPI.
-x, --x-zoom number
Horizontal scaling factor. Default is 1.0.
-y, --y-zoom number
Vertical factor factor. Default is 1.0.
-z, --zoom number
Horizontal and vertical scaling factor. Default is 1.0.

CONTROLLING THE RENDERED APPEARANCE

-b, --background-color color
Specify the background color. The color must be specified in CSS <color> syntax: https://developer.mozilla.org/en-US/docs/Web/CSS/color_value; for example, black, #ff0000, rgba(0.0, 1.0, 0.0, 1.0). The default is none; this will create transparent PNGs, or PDF/PS/EPS without a special background.
-s, --stylesheet filename.css
Filename of a custom CSS stylesheet.
-l, --accept-language language-tags
Specify which languages will be used for SVG documents with multiple languages. The value is formatted like an HTTP Accept-Language header, which is a comma-separated list of BCP47 language tags: https://www.rfc-editor.org/info/bcp47 e.g es-MX,fr,en. The default is to use the language specified by environment variables; see the section "ENVIRONMENT VARIABLES" below.

OPTIONS SPECIFIC TO PDF/PS/EPS OUTPUT

--keep-image-data
For SVG documents that reference PNG or JPEG images, include the original, compressed images in the final output, rather than uncompressed RGB data. This is the default behavior for PDF and (E)PS output.
--no-keep-image-data
Do not include the original, compressed images but instead embed uncompressed RGB data in PDF or (E)PS output. This will most likely result in larger documents that are slower to read.

MISCELLANEOUS

-i, --export-id object-id
Allows to specify an SVG object that should be exported based on its XML id attribute. If not specified, all objects will be exported.
-u, --unlimited
Turn off the XML parser's guards. The XML parser has some guards designed to mitigate large CPU or memory consumption in the face of malicious documents. It may also refuse to resolve data: URIs used to embed image data in SVG documents. If you are running into such issues when converting a SVG, this option allows to turn off these guards.
--testing
For developers only: render images for librsvg's test suite.
--completion shell-name
Generate a script for a shell's Tab completion. Possible values are bash, elvish, fish, powershell, zsh. Rsvg-convert will then write a suitable script to standard output.

ENVIRONMENT VARIABLES

SOURCE_DATE_EPOCH
If the selected output format is PDF, this variable can be used to control the CreationDate in the PDF file. This is useful for reproducible output. The environment variable must be set to a decimal number corresponding to a UNIX timestamp, defined as the number of seconds, excluding leap seconds, since 01 Jan 1970 00:00:00 UTC. The specification for this can be found at https://reproducible-builds.org/specs/source-date-epoch/
System language
Unless the --accept-language option is specified, the default is to use the system's environment to detect the user's preferred language. This consults the environment variables LANGUAGE, LC_ALL, LC_MESSAGES, and LANG.

PDF VERSIONS

The --format=pdf option makes rsvg-convert output the latest version of PDF that it supports. Normally this is the right thing to do, except when you have tools that consume the resulting PDFs but only support certain versions.

For example, LaTeX tools like pdflatex may issue a warning if you try to include a PDF image that uses a newer version than the surrounding document, similar to

PDF inclusion: found PDF version <1.7> but at most version <1.5> allowed

In this case, you may need to restrict the PDF version that rsvg-convert produces. Instead of --format=pdf, you can use the following:

--format=pdf1.4
Does not use PDF object streams; files may be bigger as they allow for less compression.
--format=pdf1.5
Allows creating PDFs where text can be selected and searched.
--format=pdf1.6
No special behavior.
--format=pdf1.7
Allows including UTF-8 filenames in link objects reliably.

If you are using LaTeX tooling, you may want to research options like \pdfminorversion=6.
