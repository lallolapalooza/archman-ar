الحزمة: jre8-openjdk-headless

rmid(1) أدوات استدعاء الأسلوب عن بعد (RMI) rmid(1)

الاسم

rmid - يبدأ خادم نظام التنشيط الذي يمكّن تسجيل الكائنات وتنشيطها في آلة جافا الافتراضية (JVM).

الملخص

rmid [خيارات]
خيارات
خيارات سطر الأوامر. انظر الخيارات.

الوصف

يقوم الأمر rmid ببدء خادم نظام التنشيط. يجب بدء خادم نظام التنشيط قبل أن يمكن تسجيل الكائنات القابلة للتنشيط في نظام التنشيط أو تنشيطها في JVM. للحصول على تفاصيل حول كيفية كتابة برامج تستخدم الكائنات القابلة للتنشيط، راجع البرنامج التعليمي استخدام التنشيط على http://docs.oracle.com/javase/8/docs/technotes/guides/rmi/activation/overview.html

ابدأ الخادم عن طريق تنفيذ الأمر rmid وتحديد ملف سياسة الأمان، على النحو التالي:

rmid -J-Djava.security.policy=rmid.policy

عند تشغيل تنفيذ Oracle للأمر rmid، يجب عليك افتراضيًا تحديد ملف سياسة أمان حتى يتمكن الأمر rmid من التحقق مما إذا كانت المعلومات في كل ActivationGroupDesc مسموحًا بها لبدء JVM لمجموعة تنشيط أم لا. على وجه التحديد، يجب الآن أن يكون الأمر والخيارات المحددة بواسطة CommandEnvironment وأي خصائص تم تمريرها إلى مُنشئ ActivationGroupDesc مسموح بها صراحةً في ملف سياسة الأمان للأمر rmid. تحدد قيمة الخاصية sun.rmi.activation.execPolicy السياسة التي يستخدمها الأمر rmid لتحديد ما إذا كان يمكن استخدام المعلومات في ActivationGroupDesc لبدء JVM لمجموعة تنشيط أم لا. لمزيد من المعلومات، راجع وصف الخيار -J-Dsun.rmi.activation.execPolicy=policy.

يقوم تنفيذ الأمر rmid ببدء المنشط (Activator) وسجل داخلي على المنفذ الافتراضي 1098 ويربط ActivationSystem بالاسم java.rmi.activation.ActivationSystem في هذا السجل الداخلي.

لتحديد منفذ بديل للسجل، يجب عليك تحديد الخيار -port عند تنفيذ الأمر rmid. على سبيل المثال، يبدأ الأمر التالي خادم نظام التنشيط وسجل على منفذ السجل الافتراضي، 1099.

rmid -J-Djava.security.policy=rmid.policy -port 1099

بدء RMID عند الطلب

بديل لبدء rmid من سطر الأوامر هو تكوين inetd (Oracle Solaris) أو xinetd (Linux) لبدء rmid عند الطلب.

عند بدء RMID، فإنه يحاول الحصول على قناة موروثة (موروثة من inetd/xinetd) عن طريق استدعاء طريقة System.inheritedChannel. إذا كانت القناة الموروثة فارغة أو لم تكن من نوع java.nio.channels.ServerSocketChannel، فإن RMID يفترض أنه لم يتم تشغيله بواسطة inetd/xinetd، ويبدأ كما هو موضح سابقًا.

إذا كانت القناة الموروثة من نوع ServerSocketChannel، فإن RMID يستخدم java.net.ServerSocket الذي تم الحصول عليه من ServerSocketChannel كمقبس خادم يقبل الطلبات للكائنات البعيدة التي يصدرها: السجل الذي يتم فيه ربط java.rmi.activation.ActivationSystem والكائن البعيد java.rmi.activation.Activator. في هذا الوضع، يتصرف RMID بنفس طريقة بدء التشغيل من سطر الأوامر، باستثناء الحالات التالية:

•
يتم إعادة توجيه المخرجات المطبوعة إلى System.err إلى ملف. يقع هذا الملف في الدليل المحدد بواسطة خاصية النظام java.io.tmpdir (عادةً /var/tmp أو /tmp) مع البادئة rmid-err واللاحقة tmp.
•
الخيار -port غير مسموح به. إذا تم تحديد هذا الخيار، يخرج RMID برسالة خطأ.
•
الخيار -log مطلوب. إذا لم يتم تحديد هذا الخيار، يخرج RMID برسالة خطأ

راجع صفحات الدليل لـ inetd (Oracle Solaris) أو xinetd (Linux) للحصول على تفاصيل حول كيفية تكوين الخدمات ليتم بدؤها عند الطلب.

الخيارات

-Cخيار

يحدد خيارًا يتم تمريره كوسيطة سطر أوامر لكل عملية فرعية (مجموعة تنشيط) من الأمر rmid عند إنشاء تلك العملية. على سبيل المثال، يمكنك تمرير خاصية إلى كل آلة افتراضية يتم إنشاؤها بواسطة خادم نظام التنشيط: 
rmid -C-Dsome.property=value

يمكن أن يكون هذا القدرة على تمرير وسائط سطر الأوامر إلى العمليات الفرعية مفيدة للتصحيح. على سبيل المثال، يسمح الأمر التالي بتسجيل مكالمات الخادم في جميع أجهزة JVM الفرعية.

rmid -C-Djava.rmi.server.logCalls=true
-Jخيار

يحدد خيارًا يتم تمريره إلى مترجم جافا الذي يشغل RMID. على سبيل المثال، لتحديد أن الأمر rmid يستخدم ملف سياسة باسم rmid.policy، يمكن استخدام الخيار -J لتعريف خاصية java.security.policy على سطر أوامر rmid، على سبيل المثال: 
rmid -J-Djava.security.policy-rmid.policy
-J-Dsun.rmi.activation.execPolicy=policy

يحدد السياسة التي يتبعها RMID للتحقق من الأوامر ووسائط سطر الأوامر المستخدمة لبدء JVM التي تعمل فيها مجموعة تنشيط. يرجى ملاحظة أن هذا الخيار موجود فقط في تنفيذ Oracle لخادم تنشيط Java RMI. إذا لم يتم تحديد هذه الخاصية على سطر الأوامر، فإن النتيجة هي نفسها كما لو تم تحديد -J-Dsun.rmi.activation.execPolicy=default. يمكن أن تكون القيم الممكنة لـ policy هي default، policyClassName، أو none.
•
default

تسمح سياسة execPolicy الافتراضية أو غير المحددة للأمر rmid بتنفيذ الأوامر ذات وسائط سطر الأوامر المحددة فقط عندما يُمنح الأمر rmid الإذن بتنفيذ تلك الأوامر والخيارات في ملف سياسة الأمان الذي يستخدمه الأمر rmid. يمكن استخدام تنفيذ مجموعة التنشيط الافتراضي فقط مع سياسة التنفيذ الافتراضية.

يبدأ الأمر rmid JVM لمجموعة تنشيط باستخدام المعلومات الموجودة في واصف مجموعة التنشيط المسجل للمجموعة، وهو ActivationGroupDesc. يحدد واصف المجموعة CommandEnvironment اختياري لـ ActivationGroupDesc والذي يتضمن الأمر المراد تنفيذه لبدء مجموعة التنشيط وأي وسائط سطر أوامر سيتم إضافتها إلى سطر الأوامر. افتراضيًا، يستخدم الأمر rmid الأمر java الموجود في java.home. يحتوي واصف المجموعة أيضًا على تجاوزات للخصائص التي يتم إضافتها إلى سطر الأوامر كوسائط محددة كـ: -D<property>=<value>. يمنح إذن com.sun.rmi.rmid.ExecPermission الأمر rmid الإذن بتنفيذ أمر محدد في CommandEnvironment للمجموعة لبدء مجموعة تنشيط. يمكّن إذن com.sun.rmi.rmid.ExecOptionPermission الأمر rmid من استخدام وسائط سطر الأوامر، المحددة كخصائص تجاوز في واصف المجموعة أو كوسائط في CommandEnvironment عند بدء مجموعة التنشيط. عند منح الأمر rmid الإذن بتنفيذ أوامر وخيارات مختلفة، يجب منح أذونات ExecPermission و ExecOptionPermission لجميع مصادر الكود.

ExecPermission

يمثل فئة ExecPermission الإذن للأمر rmid بتنفيذ أمر محدد لبدء مجموعة تنشيط.

الصيغة: اسم ExecPermission هو اسم المسار لأمر لمنح الأمر rmid الإذن بتنفيذه. يشير اسم المسار الذي ينتهي بشرطة مائلة (/) وعلامة نجمية (*) إلى أن جميع الملفات الموجودة في هذا الدليل

rmid(8) - Arch Linux

NAME

rmid - Java Remote Method Invocation activation system daemon

SYNOPSIS

rmid [ options ]

DESCRIPTION

The rmid command starts the rmid activation system daemon, which provides the Java Remote Method Invocation (RMI) activation system functionality. The activation system can be used to start persistent, (implicitly) garbage-collected remote objects.

The activation system daemon, rmid, is a program that manages activation groups and activation descriptors. An activation group is a virtual machine that is started and managed by the activation system. An activation descriptor contains information about a RMI object that can be activated, including the object's code location, restart information, and the java class name.

The rmid daemon must be started on demand, or as part of the system startup. The rmid daemon registers itself with the rmiregistry as the ActivationSystem.

The rmid daemon can be started with a security policy file that specifies which commands and command options the rmid daemon is allowed to execute. If no policy file is specified, then the rmid daemon does not perform any security checks on commands to be executed.

POLICY FILE SYNTAX

A policy file is a text file that contains a series of grant entries. Each grant entry specifies permissions to be granted to code sources that match the entry's code base and principal conditions.

The rmid command checks two types of permissions: ExecPermission and ExecOptionPermission.

ExecPermission

The ExecPermission class represents permission for the rmid command to execute a specific command. The name of an ExecPermission is the absolute path to the command.

A path name that ends in a slash (/) indicates all files and subdirectories contained in that directory. A path name that consists of the special token <<ALL FILES>> matches any file.

A path name that consists of an asterisk (*) indicates all the files in the current directory. A path name that consists of a minus sign (-) indicates all the files in the current directory and (recursively) all files and subdirectories contained in the current directory.

ExecOptionPermission

The ExecOptionPermission class represents permission for the rmid command to use a specific command-line option when starting an activation group. The name of an ExecOptionPermission is the value of a command-line option.

Syntax: Options support a limited wild card scheme. An asterisk signifies a wild card match, and it can appear as the option name itself (matches any option), or an asterisk (*) can appear at the end of the option name only when the asterisk (*) follows a dot (.) or an equals sign (=).

For example: * or -Dmydir.* or -Da.b.c=* is valid, but *mydir or -Da*b or ab* is not.

POLICY FILE FOR rmid

When you grant the rmid command permission to execute various commands and options, the permissions ExecPermission and ExecOptionPermission must be granted to all code sources (universally). It is safe to grant these permissions universally because only the rmid command checks these permissions.

An example policy file that grants various execute permissions to the rmid command is:

grant {
    permission com.sun.rmi.rmid.ExecPermission
        "/files/apps/java/jdk1.7.0/solaris/bin/java";
    permission com.sun.rmi.rmid.ExecPermission
        "/files/apps/rmidcmds/*";
    permission com.sun.rmi.rmid.ExecOptionPermission
        "-Djava.security.policy=/files/policies/group.policy";
    permission com.sun.rmi.rmid.ExecOptionPermission
        "-Djava.security.debug=*";
    permission com.sun.rmi.rmid.ExecOptionPermission
        "-Dsun.rmi.*";
};

The first permission granted allows the rmid tcommand o execute the 1.7.0 release of the java command, specified by its explicit path name. By default, the version of the java command found in java.home is used (the same one that the rmid command uses), and does not need to be specified in the policy file. The second permission allows the rmid command to execute any command in the directory /files/apps/rmidcmds.

The third permission granted, an ExecOptionPermission, allows the rmid command to start an activation group that defines the security policy file to be /files/policies/group.policy. The next permission allows the java.security.debug property to be used by an activation group. The last permission allows any property in the sun.rmi property name hierarchy to be used by activation groups.

To start the rmid command with a policy file, the java.security.policy property needs to be specified on the rmid command line, for example:

rmid -J-Djava.security.policy=rmid.policy.

START RMID ON DEMAND

•
<policyClassName>

If the default behavior is not flexible enough, then an administrator can provide, when starting the rmid command, the name of a class whose checkExecCommand method is executed to check commands to be executed by the rmid command.

The policyClassName specifies a public class with a public, no-argument constructor and an implementation of the following checkExecCommand method:

 public void checkExecCommand(ActivationGroupDesc desc, String[] command)
        throws SecurityException;

Before starting an activation group, the rmid command calls the policy's checkExecCommand method and passes to it the activation group descriptor and an array that contains the complete command to start the activation group. If the checkExecCommand throws a SecurityException, then the rmid command does not start the activation group and an ActivationException is thrown to the caller attempting to activate the object.

•
none

If the sun.rmi.activation.execPolicy property value is none, then the rmid command does not perform any validation of commands to start activation groups.

OPTIONS

-log dir

Specifies the name of the directory the activation system daemon uses to write its database and associated information. The log directory defaults to creating a log, in the directory in which the rmid command was executed.
-port port

Specifies the port the registry uses. The activation system daemon binds the ActivationSystem, with the name java.rmi.activation.ActivationSystem, in this registry. The ActivationSystem on the local machine can be obtained using the following Naming.lookup method call: 
import java.rmi.*; 
    import java.rmi.activation.*;
    ActivationSystem system; system = (ActivationSystem)
    Naming.lookup("//:port/java.rmi.activation.ActivationSystem");
-stop

Stops the current invocation of the rmid command for a port specified by the -port option. If no port is specified, then this option stops the rmid invocation running on port 1098.

ENVIRONMENT VARIABLES

CLASSPATH
Used to provide the system a path to user-defined classes. Directories are separated by colons, for example: .:/usr/local/java/classes.
