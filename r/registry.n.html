registry(n)

الحزمة: tcl

التراخيص: TCL

registry(n) حزم Tcl المجمعة registry(n)

الاسم

registry - التعامل مع سجل Windows

الملخص

package require registry 1.3

registry ?-mode? option keyName ?arg arg ...?

الوصف

توفر حزمة registry مجموعة عامة من العمليات للتعامل مع سجل Windows. تقوم الحزمة بتنفيذ الأمر Tcl registry. هذا الأمر مدعوم فقط على منصة Windows. تحذير: يجب استخدام هذا الأمر بحذر لأن السجل التالف يمكن أن يترك نظامك في حالة غير قابلة للاستخدام.

KeyName هو اسم مفتاح السجل. يجب أن تكون مفاتيح السجل واحدة من الأشكال التالية:

\\hostname\rootname\keypath

rootname\keypath

rootname

Hostname يحدد اسم أي مضيف Windows صالح يقوم بتصدير سجله. يجب أن يكون المكون rootname أحد القيم التالية: HKEY_LOCAL_MACHINE، HKEY_USERS، HKEY_CLASSES_ROOT، HKEY_CURRENT_USER، HKEY_CURRENT_CONFIG، HKEY_PERFORMANCE_DATA، أو HKEY_DYN_DATA. يمكن أن يكون keypath اسم مفتاح سجل واحد أو أكثر مفصولًا بأحرف الشرطة المائلة العكسية (\).

يشير الوسيط الاختياري -mode إلى السجل الذي سيتم العمل معه؛ عندما يكون -32bit، سيتم استخدام سجل 32 بت، وعندما يكون -64bit، سيتم استخدام سجل 64 بت. إذا تم حذف هذا الوسيط، فسيكون سجل النظام الافتراضي هو موضوع العملية المطلوبة.

Option يحدد ما يجب فعله مع اسم مفتاح السجل. يمكن قبول أي اختصار فريد لـ option. الخيارات الصالحة هي:

registry broadcast keyName ?-timeout milliseconds?
يرسل رسالة بث إلى النظام والبرامج قيد التشغيل لإعلامهم بالتحديثات معينة. هذا ضروري لنشر التغييرات على مفاتيح السجل الرئيسية مثل Environment. يحدد المهلة مقدار الوقت، بالمللي ثانية، للانتظار حتى تستجيب التطبيقات لرسالة البث. الافتراضي هو 3000. يوضح المثال التالي كيفية إضافة مسار إلى Environment العام وإعلام التطبيقات بالتغيير دون الحاجة إلى خطوة تسجيل الخروج/تسجيل الدخول (بافتراض امتيازات المسؤول):
set regPath [join {
    HKEY_LOCAL_MACHINE
    SYSTEM
    CurrentControlSet
    Control
    {Session Manager}
    Environment
} "\\"]
set curPath [registry get $regPath "Path"]
registry set $regPath "Path" "$curPath;$addPath"
registry broadcast "Environment"
registry delete keyName ?valueName?
إذا كان الوسيط الاختياري valueName موجودًا، فسيتم حذف القيمة المحددة ضمن keyName من السجل. إذا تم حذف الوسيط الاختياري valueName، فسيتم حذف المفتاح المحدد وأي مفاتيح فرعية أو قيم تحته في التسلسل الهرمي للسجل. إذا لم يكن من الممكن حذف المفتاح، فسيتم إنشاء خطأ. إذا لم يكن المفتاح موجودًا، فلن يكون للأمر أي تأثير.
registry get keyName valueName
يعيد البيانات المرتبطة بالقيمة valueName ضمن المفتاح keyName. إذا لم يكن المفتاح أو القيمة موجودين، فسيتم إنشاء خطأ. لمزيد من التفاصيل حول تنسيق البيانات المعادة، انظر أنواع مدعومة، أدناه.
registry keys keyName ?pattern?
إذا لم يتم تحديد pattern، فإنه يعيد قائمة بأسماء جميع المفاتيح الفرعية لـ keyName. إذا تم تحديد pattern، فسيتم إرجاع الأسماء التي تطابق pattern فقط. يتم تحديد المطابقة باستخدام نفس القواعد الخاصة بـ string match. إذا لم يكن keyName المحدد موجودًا، فسيتم إنشاء خطأ.
registry set keyName ?valueName data ?type??
إذا لم يتم تحديد valueName، فإنه ينشئ المفتاح keyName إذا لم يكن موجودًا بالفعل. إذا تم تحديد valueName، فإنه ينشئ المفتاح keyName والقيمة valueName إذا لزم الأمر. يتم تعيين محتويات valueName إلى data بالنوع المشار إليه بواسطة type. إذا لم يتم تحديد type، فسيتم افتراض النوع sz. لمزيد من التفاصيل حول وسيطات البيانات والنوع، انظر أنواع مدعومة أدناه.
registry type keyName valueName
يعيد نوع القيمة valueName في المفتاح keyName. لمزيد من المعلومات حول الأنواع المحتملة، انظر أنواع مدعومة، أدناه.
registry values keyName ?pattern?
إذا لم يتم تحديد pattern، فإنه يعيد قائمة بأسماء جميع قيم keyName. إذا تم تحديد pattern، فسيتم إرجاع الأسماء التي تطابق pattern فقط. يتم تحديد المطابقة باستخدام نفس القواعد الخاصة بـ string match.

أنواع مدعومة

تحتوي كل قيمة ضمن مفتاح في السجل على بعض البيانات من نوع معين بتمثيل خاص بالنوع. يقوم الأمر registry بالتحويل بين هذا التمثيل الداخلي وتمثيل يمكن أن تتعامل معه نصوص Tcl. في معظم الحالات، يتم إرجاع البيانات ببساطة كسلسلة Tcl. يشير النوع إلى الاستخدام المقصود للبيانات، ولكنه لا يغير التمثيل فعليًا. بالنسبة لبعض الأنواع، يعيد الأمر registry البيانات بتنسيق مختلف لتسهيل التعامل معها. الأنواع التالية معترف بها بواسطة الأمر registry:

binary
تحتوي قيمة السجل على بيانات ثنائية عشوائية. يتم تمثيل البيانات بالضبط في Tcl، بما في ذلك أي قيم صفرية مضمنة.
none
تحتوي قيمة السجل على بيانات ثنائية عشوائية بدون نوع محدد. يتم تمثيل البيانات بالضبط في Tcl، بما في ذلك أي قيم صفرية مضمنة.
sz
تحتوي قيمة السجل على سلسلة نصية تنتهي بصفر. يتم تمثيل البيانات في Tcl كسلسلة نصية.
expand_sz
تحتوي قيمة السجل على سلسلة نصية تنتهي بصفر تحتوي على مراجع غير موسعة لمتغيرات البيئة بالنمط القياسي لنظام Windows (على سبيل المثال، “%PATH%”). يتم تمثيل البيانات في Tcl كسلسلة نصية.
dword
تحتوي قيمة السجل على رقم 32 بت صغير النهاية (little-endian). يتم تمثيل البيانات في Tcl كسلسلة عشرية.
dword_big_endian
تحتوي قيمة السجل على رقم 32 بت كبير النهاية (big-endian). يتم تمثيل البيانات في Tcl كسلسلة عشرية.
link
تحتوي قيمة السجل على رابط رمزي. يتم تمثيل البيانات بالضبط في Tcl، بما في ذلك أي قيم صفرية مضمنة.
multi_sz
تحتوي قيمة السجل على مصفوفة من السلاسل النصية المنتهية بصفر. يتم تمثيل البيانات في Tcl كقائمة من السلاسل النصية.
resource_list
تحتوي قيمة السجل على قائمة موارد مشغل الجهاز. يتم تمثيل البيانات بالضبط في Tcl، بما في ذلك أي قيم صفرية مضمنة.

بالإضافة إلى الأنواع المسماة رمزيًا المذكورة أعلاه، يتم التعرف على الأنواع غير المعروفة باستخدام عدد صحيح 32 بت يتوافق مع رمز النوع الذي تعيده واجهات النظام. في هذه الحالة، يتم تمثيل البيانات بالضبط في Tcl، بما في ذلك أي قيم صفرية مضمنة.

قضايا قابلية النقل

أمر السجل متاح فقط على Windows.

مثال

طباعة كيفية استدعاء مترجم Tcl عند النقر المزدوج على ملف نصي Tcl:

package require registry
set ext .tcl
# قراءة اسم النوع
set type [registry get HKEY_CLASSES_ROOT\\$ext {}]

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.
