يمكننا أيضًا تخصيص لون المؤشر وعرضه، واختيار إخفائه عندما يكون مربع الإدخال فارغًا. يمكنك، على سبيل المثال، إنشاء مؤشر كتلة بلون قرمزي يظهر فقط عند إدخال نص، مثل هذا:

entry {
  cursor-color: rgb(220,20,60);
  cursor-width: 8px;
  hide-cursor-on-empty: true;
}

افتراضيًا، سيكون cursor-color هو نفس text-color. سيكون cursor-width دائمًا افتراضيًا 2 بكسل وسيتم تعيين hide-cursor-on-empty إلى false.

إذا كنت ترغب في رؤية السمة الكاملة، بما في ذلك التعديل الذي يمكنك إجراؤه، قم بتشغيل:

rofi -dump-theme

تحميل السمة الافتراضية

بشكل افتراضي، يقوم rofi بتحميل السمة الافتراضية. يتم تحميل هذه السمة دائمًا. يحتوي التكوين الافتراضي على:

@theme "default"

لإلغاء تحميل السمة الافتراضية، وتحميل سمة أخرى، أضف عبارة @theme إلى ملف config.rasi الخاص بك.

إذا كان لديك سمة محملة عبر @theme أو تستخدم السمة الافتراضية، يمكنك تعديلها عن طريق إضافة عناصر متجاوزة في نهاية ملف config.rasi الخاص بك.

للاطلاع على الفرق بين @import و @theme، راجع قسم التعامل مع ملفات متعددة في صفحة الدليل هذه.

لرؤية السمة الافتراضية، قم بتشغيل الأمر التالي:

rofi -no-config -dump-theme

الوصف

تم الدافع للحاجة إلى تنسيق سمة جديد حقيقة أن الطريقة التي تعامل بها rofi مع الأدوات (widgets) قد تغيرت. من رسم ثابت جدًا للخطوط والنصوص إلى شكل منظم لطيف لتعبئة الأدوات. هذا التغيير جعل من الممكن توفير إطار عمل سمة أكثر مرونة. تنسيق السمة القديم وملف التكوين ليسا مرنين بما يكفي للكشف عن هذه الخيارات بطريقة سهلة الاستخدام. لذلك، تم إنشاء تنسيق ملف جديد، ليحل محل القديم.

مواصفات التنسيق

الترميز

ترميز الملف هو UTF-8. يتم دعم تنسيقات نهايات الأسطر يونكس (\n) ويندوز (\r\n). ولكن يفضل يونكس.

التعليقات

يتم دعم تعليقات C و C++.

•
أي شيء بعد // وقبل سطر جديد يعتبر تعليقًا.
•
كل شيء بين /* و */ هو تعليق، يمكن أن يمتد هذا التعليق عبر عدة أسطر.

يمكن تداخل التعليقات ويمكن أن تكون تعليقات C مضمنة.

السطر التالي صحيح:

// تعليق سحري.
property: /* تعليق */ value;

لكن هذا ليس صحيحًا:

prop/*comment*/erty: value;

المسافات البيضاء

يتم تجاهل المسافات البيضاء وأسطر النهاية، مثل التعليقات، بواسطة المحلل.

هذا:

property: name;

متطابق مع:

     property             :
name
;

امتداد الملف

امتداد الملف المفضل لتنسيق السمة الجديد هو rasi. هذا اختصار لـ rofi advanced style information. إذا تم تقسيم ملف السمة على عدة ملفات، فيمكن أن يكون للملفات المضمنة الامتداد: rasinc.

البنية الأساسية

لكل عنصر قسم بخصائص محددة. يمكن تحديد الخصائص العامة في قسم * { }. تبدأ أسماء الأقسام الفرعية برمز هاش اختياري #.

يُنصح بتعريف قسم الخصائص العامة في أعلى الملف لجعل وراثة الخصائص أكثر وضوحًا.

/* قسم الخصائص العامة */
* {
    // قائمة الخصائص
}
/* قسم سمة العنصر. */
{element path} {
    // قائمة الخصائص
}
{elements... } {
    // قائمة الخصائص
}

إذا كان هناك أقسام متعددة بنفس الاسم، يتم دمجها. يتم تجاوز الخصائص المكررة والاحتفاظ بآخر إدخال تم تحليله.

قسم الخصائص العامة

يمكن أن تحتوي السمة على قسم واحد أو أكثر من أقسام الخصائص العامة. إذا كان هناك أكثر من قسم، فسيتم دمجها.

يشير قسم الخصائص العامة إلى القيم الافتراضية لكل عنصر. يمكن الإشارة إلى كل خاصية في هذا القسم باستخدام @{identifier} (انظر قسم الخصائص).

يتم الإشارة إلى قسم الخصائص العامة باستخدام * كمسار للعنصر.

قسم سمة العنصر

يمكن أن تحتوي السمة على أقسام سمات عناصر متعددة.

يمكن أن يتكون مسار العنصر من أسماء متعددة مفصولة بمسافات بيضاء أو نقاط. قد يحتوي كل عنصر على أي عدد من الأحرف والأرقام و -. يمكن أن يبدأ العنصر الأول في مسار العنصر اختياريًا بـ # (لأسباب تاريخية). يمكن تحديد عناصر متعددة بواسطة ,.

هذا اسم عنصر صحيح:

element normal.normal {
    background-color: blue;
}
button {
    background-color: blue;
}

وهو مطابق لـ:

element normal normal, button {
    background-color: blue;
}

كل قسم يرث الخصائص العامة. يمكن وراثة الخصائص صراحة من الأصل باستخدام الكلمة المفتاحية inherit. في المثال التالي:

window {
 a: 1;
 b: 2;
 children: [ mainbox ];
}
mainbox {
    a: inherit;
    b: 4;
    c: 8;
}

سيحتوي العنصر mainbox على مجموعة الخصائص التالية (إذا كان mainbox طفلاً لـ window):

a: 1;
b: 4;
c: 8;

إذا تم تحديد أقسام متعددة بنفس الاسم، فسيقوم المحلل بدمجها. إذا تم تعريف خصائص متعددة بنفس الاسم في قسم واحد، يتم استخدام الخاصية الأخيرة التي تم العثور عليها.

تنسيق الخصائص

تتكون الخصائص في قسم من:

{identifier}: {value};

كلا الحقلين إلزاميين للخاصية.

identifier يسمي الخاصية المحددة. يمكن أن تتكون المعرفات من أي مجموعة من الأرقام والأحرف و -. لا يجب أن تحتوي على أي مسافات بيضاء. يحدد هيكل value نوع الخاصية. لا يحدد المحلل الحالي أو يفرض نوعًا معينًا لمعرف identifier معين. عند الاستخدام، يتم تجاهل القيم ذات النوع الخاطئ التي لا يمكن تحويلها.

سلسلة نصية

•
التنسيق: (["'])[:print:]+\1

تكون السلاسل النصية دائمًا محاطة بعلامات اقتباس مزدوجة (") أو مفردة ('، فاصلة علوية). بين علامات الاقتباس يمكن أن يكون أي حرف قابل للطباعة.

على سبيل المثال:

font: "Awasome 12"
quot;;

يجب أن يكون النص صالحًا بتنسيق UTF-8، ويمكن تخطي الأحرف الخاصة:

text { content: "السطر الأول\n\tالسطر الثاني الذي تم إزاحته 'نص مقتبس'"; }
text { content: 'السطر الأول\n\tالسطر الثاني الذي تم إزاحته "نص مقتبس"'; }
text { content: "السطر الأول\n\tالسطر الثاني الذي تم إزاحته \"نص مقتبس\""; }

يمكن تخطي الأحرف الخاصة التالية: \b، \f، \n، \r، \t، \v، \، " و ' (لا تحتاج علامات الاقتباس المزدوجة داخل علامات الاقتباس المفردة أو العكس إلى تخطي).

عدد صحيح

•
التنسيق: [-+]?[:digit:]+

يمكن أن يحتوي العدد الصحيح على أي رقم.

أمثلة:

lines: 12;

عدد حقيقي

•
التنسيق: [-+]?[:digit:]+(\.[:digit:]+)?

العدد الحقيقي هو عدد صحيح مع جزء عشري اختياري.

مثال:

real: 3.4;

ما يلي غير صالح: .3، 3. أو الترميز العلمي: 3.4e-3.

قيمة منطقية

•
التنسيق: (true|false)

القيمة المنطقية هي إما true أو false. هذا حساس لحالة الأحرف.

مثال:

dynamic: false;

صورة

يدعم rofi مجموعة محدودة من تنسيقات الصور الخلفية.

•
التنسيق: url(“مسار الصورة”);
•
التنسيق: url(“مسار الصورة”, scale); حيث scale هي: none, both, width, height
•
التنسيق: linear-gradient(stop color,stop1, color, stop2 color, ...);
•
التنسيق: linear-gradient(to direction, stop color,stop1, color, stop2 color, ...); حيث direction هي: top,left,right,bottom.
•
التنسيق: linear-gradient(angle, stop color,stop1, color, stop2 color, ...); الزاوية بالدرجات، الراديان، التدرجات (كما تستخدم في اللون).

حيث path هو نص، و stop color هو من نوع color.

التنسيق: cmyk( {PERCENTAGE}, {PERCENTAGE}, {PERCENTAGE}, {PERCENTAGE} [, {PERCENTAGE} ])

يتم أيضًا دعم تنسيق المسافات البيضاء المقترح في CSS4.

القيم المختلفة هي:

•
{HEX} هو رقم سداسي عشري ( '0-9a-f' غير حساس لحالة الأحرف).

نمط النص

•
التنسيق: (bold|italic|underline|strikethrough|none)

يشير نمط النص إلى كيفية تمييز النص المميز. None يشير إلى عدم تطبيق أي تمييز.

•
bold: يجعل النص أكثر سمكًا من النص المحيط.
•
italic: يضع النص المميز بخط مائل (مائل).
•
underline: يضع خطًا تحت النص.
•
strikethrough: يضع خطًا عبر النص.

الخيارات التالية متاحة على Pango 1.50.0 والإصدارات الأحدث:

•
uppercase: يحول النص إلى أحرف كبيرة.
•
lowercase: يحول النص إلى أحرف صغيرة.

الخيار التالي معطل لأن Pango يتعطل معه إذا كان هناك تغيير في الحجم أو التفاف. سيتم إعادة تمكينه بمجرد إصلاحه:

•
capitalize: يحول الحرف الأول من كل كلمة إلى حرف كبير.

نمط الخط

•
التنسيق: (dash|solid)

يشير إلى كيفية رسم الخط. يدعم حاليًا:

•
dash: خط متقطع، حيث يكون الفراغ بنفس عرض الشرطة.
•
solid: خط متصل.

مسافة

•
التنسيق: {Integer}px
•
التنسيق: {Real}em
•
التنسيق: {Real}ch
•
التنسيق: {Real}%
•
التنسيق: {Real}mm

يمكن تحديد المسافة بثلاث وحدات مختلفة:

•
px: بكسل الشاشة.
•
em: نسبة إلى ارتفاع النص.
•
ch: نسبة إلى عرض رقم واحد.
•
mm: حجم فعلي بالمليمتر (بناءً على dpi).
•
%: نسبة من حجم الشاشة.

المسافات المستخدمة في الاتجاه الأفقي تستخدم عرض الشاشة. المسافات في الاتجاه الرأسي تستخدم ارتفاع الشاشة. مثال:

   padding: 10%;

على شاشة Full-HD (1920x1080)، تحدد هذه النسبة هامشًا قدره 192 بكسل على الجانبين الأيسر والأيمن و 108 بكسل في الأعلى والأسفل.

width: calc( 20% min 512 );

By default the element-icon and element-text child widgets are added to the element. This can be modified using the children property or the [no]-show-icons option.

A child added with another name is treated the same as the special widget described in the advanced layout section.

listview text highlight

The element-text widget in the listview is the one used to show the text. On this widget set the highlight property (only place this property is used) to change the style of highlighting. The highlight property consist of the text-style property and a color.

To disable highlighting:

  element-text {
    highlight: None;
  }

To set to red underlined:

  element-text {
    highlight: underline red;
  }

Layout

The new format allows the layout of the rofi window to be tweaked extensively. For each widget, the themer can specify padding, margin, border, font, and more. It even allows, as an advanced feature, to pack widgets in a custom structure.

Basic layout structure

The whole view is made out of boxes that pack other boxes or widgets. The box can be vertical or horizontal. This is loosely inspired by GTK.

الكلمات الرئيسية التالية محددة ويمكن استخدامها لتجميع مجموعة فرعية من الأدوات تلقائيًا. يتم استخدامها في السمة الافتراضية كما هو موضح في الشكل أعلاه.

•
mainbox يجمع: inputbar, message, listview, mode-switcher
•
inputbar يجمع: prompt,entry,case-indicator

أي اسم أداة يبدأ بـ textbox هو أداة مربع نص، والأخرى هي أدوات مربعات ويمكنها تجميع أدوات أخرى.

هناك العديد من الأدوات الخاصة التي يمكن استخدامها عن طريق إضافة بادئة إلى اسم الأداة:

أداة مربع النص

ox widget

This is a read-only textbox widget. The displayed string can be set with content.

Example:

textbox-custom {
  expand: false;
  content: "My Message";
}

Icon

This is an icon widget. The displayed icon can be set with filename and size with size. If the property action is set, it acts as a button. action can be set to a keybinding name and completes that action. (see rofi -show keys for a list).

If the squared property is set to false the widget height and width are not forced to be equal.

Example:

icon-paste {
    expand: false;
    filename: "gtk-paste";
    size: 24;
    vertical-align: 0.5;
    action: "kb-primary-paste";
}

button

This is a textbox widget that can have a `clickable' action. The action can be set to: keybinding: accepts a keybinding name and completes that action. (see rofi -show keys for a list).

button-paste {
    expand: false;
    content: "My Clickable Message";
    vertical-align: 0.5;
    action: "kb-primary-paste";
}

Children

To specify children, set the children property (this always happens on the box child, see example below):

inputbar {
  children: [prompt,entry,overlay,case-indicator];
}

The theme needs to be updated to match the hierarchy specified.

Below is an example of a theme emulating dmenu:

* {
    background-color:      Black;
    text-color:            White;
    border-color:          White;
    font:            "Times New Roman 12";
}
window {
    anchor:     north;
    location:   north;
    width:      100%;
    padding:    4px;
    children:   [ horibox ];
}
horibox {
    orientation: horizontal;
    children:   [ prompt, entry, listview ];
}
listview {
    layout:     horizontal;
    spacing:    5px;
    lines:      10;
}
entry {
    expand:     false;
    width:      10em;
}
element {
    padding: 0px 2px;
}
element selected {
    background-color: SteelBlue;
}

Padding and margin

Just like CSS, rofi uses the box model for each widget.

┌──────────────────────────────────────────────────────────────────┐
│ margin                                                           │
│  ┌────────────────────────────────────────────────────────────┐  │
│  │ border                                                     │  │
│  │ ┌────────────────────────────────────────────────────────┐ │  │
│  │ │ padding                                                │ │  │
│  │ │ ┌────────────────────────────────────────────────────┐ │ │  │
│  │ │ │ content                                            │ │ │  │
│  │ │ └────────────────────────────────────────────────────┘ │ │  │
│  │ └────────────────────────────────────────────────────────┘ │  │
│  └────────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────────┘

Explanation of the different parts:

•
Content - The content of the widget.
•
Padding - Clears an area around the widget. The padding shows the background color of the widget.
•
Border - A border that goes around the padding and content. The border use the border-color of the widget.
•
Margin - Clears an area outside the border. The margin is transparent.

The box model allows us to add a border around elements, and to define space between elements.

The size of each margin, border, and padding can be set. For the border, a linestyle and radius can be set.

Spacing

Widgets that can pack more then one child widget (currently box and listview) have the spacing property. This property sets the distance between the packed widgets (both horizontally and vertically).

┌───────────────────────────────────────┐
│ ┌────────┐ s ┌────────┐ s ┌────────┐  │
│ │ child  │ p │ child  │ p │ child  │  │
│ │        │ a │        │ a │        │  │
│ │        │ c │        │ c │        │  │
│ │        │ i │        │ i │        │  │
│ │        │ n │        │ n │        │  │
│ └────────┘ g └────────┘ g └────────┘  │
└───────────────────────────────────────┘

│  │ dummy         │  │ child  │  │ dummy         │  │
│  │ expand: true; │  │        │  │ expand: true; │  │
│  │               │  │        │  │               │  %
2502; │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ └───────────────┘ └────────┘ └───────────────┘ │ └────────────────────────────────────────────────────┘

إذا تم ضبط كلا الأداتين الوهميتين للتوسع، فسيتم توسيط child. اعتمادًا على علامة expand للطفل، سيتم تقسيم المساحة المتبقية بالتساوي بين كل من الأداة الوهمية والطفل (تمكين التوسع)، أو بين الأداتين الوهميتين (تعطيل التوسع).

التصحيح

للحصول على معلومات تصحيح الأخطاء من المحلل، قم بتشغيل rofi مثل:

G_MESSAGES_DEBUG=Parser rofi -show run

تظهر أخطاء بناء الجملة في نافذة منبثقة ويتم طباعتها إلى سطر الأوامر باستخدام الأمر أعلاه.

لرؤية العناصر التي تم الاستعلام عنها أثناء التشغيل، قم بتشغيل:

G_MESSAGES_DEBUG=Theme rofi -show run

لاختبار التغييرات الطفيفة، يمكن تمرير جزء من السمة عبر سطر الأوامر، على سبيل المثال لتعيينها على ملء الشاشة:

rofi -theme-str 'window { fullscreen:true;}' -show run

بناء جملة آخر لتعديل خصائص السمة هو:

rofi -theme+window+fullscreen true -show run

لطباعة السمة الحالية، قم بتشغيل:

rofi -dump-theme

دعم الوسائط

يمكن تحميل أجزاء من السمة بشكل مشروط، مثل خيار CSS @media.

@media ( min-width: 120 ) {
}

تدعم المفاتيح التالية كقيود:

•
min-width: تحميل عندما يكون العرض أكبر من أو يساوي القيمة.
•
max-width: تحميل عندما يكون العرض أصغر من القيمة.
•
min-height: تحميل عندما يكون الارتفاع أكبر من أو يساوي القيمة.
•
max-height: تحميل عندما يكون الارتفاع أصغر من القيمة.
•
min-aspect-ratio تحميل عندما تتجاوز نسبة العرض إلى الارتفاع القيمة.
•
max-aspect-ratio: تحميل عندما تكون نسبة العرض إلى الارتفاع أقل من القيمة.
•
monitor-id: معرف الشاشة، انظر rofi -help لمعرفات الشاشات.
•
enabled: خيار منطقي للتمكين. يدعم متغير البيئة أو DMENU للكشف عما إذا كان في وضع dmenu.

يأخذ @media رقمًا صحيحًا أو كسرًا، بالنسبة للرقم الصحيح يمكن إضافة px.

@media ( min-width: 120 px ) {
}

@media ( enabled: env(DO_LIGHT, false )) {
}

@media ( enabled: DMENU) {
}

قيود متضاربة

من الممكن تحديد قيود متضاربة في السمة. هذه التعارضات لا يتم الإبلاغ عنها بشكل صريح. المثال الأكثر شيوعًا هو فرض حجم نافذة محدد، على سبيل المثال عن طريق تمكين وضع ملء الشاشة، ووجود عدد من الأسطر محدد في listview، وجعل listview يتوسع ليشغل المساحة المتاحة. هناك تعارض واضح في هذه القيود الثلاثة. في هذه الحالة، لن يقتصر listview على عدد الأسطر، ولكنه سيحاول ملء المساحة المتاحة. الأمر متروك لمصمم السمة للتأكد من أن السمة تتعامل مع هذا بشكل صحيح.

تحليل الخطوط

يستخدم Rofi pango لعرض الخطوط. يجب تحديد الخط بتنسيق يفهمه Pango. عادةً ما يكون هذا هو اسم الخط متبوعًا بحجم الخط. على سبيل المثال:

mono 18

أو

FontAwesome 22

من صفحة دليل pango:

يجب أن يكون السلسلة النصية بالشكل

\[FAMILY-LIST] \[STYLE-OPTIONS] \[SIZE] \[VARIATIONS]

حيث FAMILY-LIST هي قائمة بأسماء العائلات مفصولة بفواصل وتنتهي اختياريًا بفاصلة، STYLE_OPTIONS هي قائمة كلمات مفصولة بمسافات حيث تصف كل كلمة نمطًا أو تنوعًا أو وزنًا أو تمددًا أو جاذبية، و SIZE هو رقم عشري (الحجم بالنقاط) أو اختياريًا متبوعًا بمعدل الوحدة “px” للحجم المطلق. VARIATIONS هي قائمة بمواصفات تنويع الخطوط مفصولة بفواصل بالشكل “axis=value” (العلامة = اختيارية).

الكلمات التالية مفهومة كأنماط: “Normal”، “Roman”، “Oblique”، “Italic”.

الكلمات التالية مفهومة كتنوعات: “Small-Caps”، “All-Small-Caps”، “Petite-Caps”، “All-Petite-Caps”، “Unicase”، “Title-Caps”.

الكلمات التالية مفهومة كأوزان: “Thin”، “Ultra-Light”، “Extra-Light”، “Light”، “Semi-Light”، “Demi-Light”، “Book”، “Regular”، “Medium”، “Semi-Bold”، “Demi-Bold”، “Bold”، “Ultra-Bold”، “Extra-Bold”، “Heavy”، “Black”، “Ultra-Black”، “Extra-Black”.

الكلمات التالية مفهومة كقيم تمدد: “Ultra-Condensed”، “Extra-Condensed”، “Condensed”، “Semi-Condensed”، “Semi-Expanded”، “Expanded”، “Extra-Expanded”، “Ultra-Expanded”.

الكلمات التالية مفهومة كقيم جاذبية: “Not-Rotated”، “South”، “Upside-Down”، “North”، “Rotated-Left”، “East”، “Rotated-Right”، “West”.

يمكن أن يكون أي واحد من الخيارات غائبًا. إذا كان FAMILY-LIST غائبًا، فسيتم تهيئة حقل اسم العائلة لوصف الخط الناتج إلى NULL. إذا كان STYLE-OPTIONS مفقودًا، فسيتم تعيين جميع خيارات النمط إلى القيم الافتراضية. إذا كان SIZE مفقودًا، فسيتم تعيين الحجم في وصف الخط الناتج إلى 0.

مثال نموذجي:

“Cantarell Italic Light 15 `wght`=200”

معالجة ملفات متعددة

يقدم تنسيق ملف rasi طريقتين لتضمين ملفات أخرى. يمكن استخدام هذا لتعديل السمات الموجودة، أو الحصول على اختلافات متعددة في السمة.

•
import: استيراد وتحليل ملف ثانٍ.
•
theme: تجاهل السمة، وتحميل الملف كسمة جديدة.

بناء الجملة:

@import "myfile"
@theme "mytheme"

الخيار في سطر الأوامر -theme يتم التعامل معه بشكل مشابه لـ @theme.

يمكن أن يكون الملف المحدد إما اسم، اسم ملف، مسار كامل.

إذا تم توفير اسم ملف، فسيحاول حله بالترتيب التالي:

•
إذا كان المسار مطلقًا والملف موجودًا، فسيقوم بفتح الملف. يتضمن هذا توسيع `~` أو `~user`
•
عند @import أو @theme، يبحث في دليل الملف الذي حاول تضمينه.
•
${XDG_CONFIG_HOME}/rofi/themes/
•
${XDG_CONFIG_HOME}/rofi/
•
${XDG_DATA_HOME}/rofi/themes/
•
${INSTALL PREFIX}/share/rofi/themes/

يتم حل الاسم (إذا لم يكن له امتداد صالح) كاسم ملف عن طريق إضافة امتداد .rasi و .rasinc. سيبحث أولاً عن ملفات بامتداد .rasi، ثم عن ملفات بامتداد .rasinc.

إذا كنت تريد إجراء استيراد اختياري، على سبيل المثال، عدم وجود خطأ عند عدم وجود الملف، يمكنك القيام بما يلي:

?import "myfile"

هذا لا يزال يلقي خطأ عند وجود خطأ في بناء الجملة، ولكنه لن يتوقف عن التحليل إذا لم يكن الملف موجودًا.
