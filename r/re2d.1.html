الاسم

re2d - توليد محللات معجمية سريعة للغة D

الملخص

re2d [ الخيارات ] [ التحذيرات ] المدخل

يمكن أن يكون المدخل ملفًا أو - للإدخال القياسي.

المقدمة

يعمل re2d كمعالج مسبق. يقرأ ملف المدخل (والذي عادةً ما يكون برنامجًا بلغة D، لكنه يمكن أن يكون أي شيء) ويبحث عن كتل من الشيفرة محاطة بعلامات بداية/نهاية ذات صيغة خاصة. يتم نسخ النص خارج هذه الكتل حرفيًا إلى ملف الخرج. تتم معالجة محتويات الكتل بواسطة re2d. حيث يترجمها إلى شيفرة بلغة D ويُخرج الشيفرة المولّدة مكان الكتلة.

إليك مثالًا لبرنامج صغير يتحقق مما إذا كانت سلسلة معينة تحتوي على رقم عشري:

// re2d $INPUT -o $OUTPUT -i
module main;
private bool lex(const(char)* yycursor) {
    /*!re2c
        re2c:YYCTYPE = char;
        re2c:yyfill:enable = 0;
        [1-9][0-9]* { return true; }
        *           { return false; }
    */
}
void main() {
    assert(lex("1234"));
}

في الخرج استبدل re2d الكتلة الموجودة في المنتصف بالشيفرة المولّدة:

/* Generated by re2d */
// re2d $INPUT -o $OUTPUT -i
module main;
private bool lex(const(char)* yycursor) {
{
    char yych;
    yych = *yycursor;
    switch (yych) {
        case '1': .. case '9': goto yy2;
        default: goto yy1;
    }
yy1:
    ++yycursor;
    { return false; }
yy2:
    yych = *++yycursor;
    switch (yych) {
        case '0': .. case '9': goto yy2;
        default: goto yy3;
    }
yy3:
    { return true; }
}
}
void main() {
    assert(lex("1234"));
}

الأساسيات

يتكون برنامج re2d من سلسلة من الكتل الممزوجة بشيفرة باللغة الهدف. قد تحتوي الكتلة على تعريفات وإعدادات وقواعد وإجراءات وتوجيهات بأي ترتيب:

الاسم = تعبير-نمطي ;
يربط التعريف الاسم بـالتعبير-النمطي. قد تحتوي الأسماء على أحرف أبجدية رقمية وشرطة سفلية. يعطي قسم التعابير النمطية نظرة عامة على صيغة re2d للتعبيرات النمطية. بمجرد تعريفه، يمكن استخدام الاسم في تعبيرات نمطية أخرى وفي القواعد. لا يُسمح بالاستدعاء الذاتي في التعريفات المسماة، ويجب تعريف كل اسم قبل استخدامه. ترث الكتلة التعريفات المسماة من النطاق العام. إعادة تعريف اسم موجود في النطاق الحالي يُعد خطأً.
الإعداد = القيمة ;
يسمح الإعداد بتغيير سلوك re2d وتخصيص الشيفرة المولّدة. للحصول على قائمة كاملة بالإعدادات المدعومة من re2d راجع قسم الإعدادات. اعتمادًا على إعداد معين، يمكن أن تكون القيمة كلمة مفتاحية أو عددًا صحيحًا غير سالب أو سلسلة من سطر واحد يجب أن تكون محاطة بعلامات اقتباس مزدوجة أو مفردة ما لم تكن مكونة من أحرف أبجدية رقمية. ترث الكتلة الإعدادات من النطاق العام وقد تعيد تعريفها أو تضيف إعدادات جديدة. تؤثر الإعدادات المعرفة داخل الكتلة على الكتلة بأكملها، حتى لو ظهرت في نهايتها.
تعبير-نمطي شيفرة
تربط القاعدة التعبير-النمطي بإجرائه الدلالي (كتلة شيفرة بين أقواس معقوفة، أو كتلة شيفرة تبدأ بـ:= وتنتهي عند سطر جديد يتبعه أي حرف غير مسافة بيضاء). إذا تطابق التعبير-النمطي، تُنفَّذ الشيفرة المرتبطة به. إذا تطابقت قواعد متعددة، تكون الأولوية للتطابق الأطول. إذا تطابقت قواعد متعددة مع نفس السلسلة، تكون الأولوية للأسبق. هناك قاعدتان خاصتان: القاعدة الافتراضية * وقاعدة نهاية المدخل $. يجب دائمًا تعريف القاعدة الافتراضية، ولها أدنى أولوية بغض النظر عن موقعها في الكتلة، وتطابق أي وحدة شيفرة (وليس بالضرورة حرفًا صالحًا، راجع قسم دعم الترميز). يجب تعريف قاعدة نهاية المدخل إذا تم استخدام الطريقة المقابلة لـمعالجة نهاية المدخل. مع شروط البدء تكون صيغة القواعد أكثر تعقيدًا.
!إجراء شيفرة
يربط الإجراء كتلة شيفرة يحددها المستخدم بموضع معين في آلة الحالات المحدودة المولّدة (بنفس الطريقة التي تربط بها الإجراءات الدلالية الشيفرة بالحالات النهائية). راجع قسم الإجراءات للحصول على قائمة كاملة بالإجراءات المعرفة مسبقًا.
!توجيه ;
التوجيه هو أحد العبارات المعرفة مسبقًا الخاصة. لكل توجيه غرض فريد. راجع قسم التوجيهات للتفاصيل.

الكتل

علامات بداية ونهاية الكتلة هي إما /*!re2c و*/، أو %{ و%} (كلا النمطين مدعوم). بدءًا من الإصدار 2.2 قد تحتوي الكتل على أسماء اختيارية تسمح بالإشارة إليها في كتل أخرى. هناك أنواع مختلفة من الكتل:

/*!re2c[:<name>] ... */ أو %{[:<name>] ... %}
تحتوي الكتلة العامة على تعريفات وإعدادات وقواعد وتوجيهات. يترجم re2d التعبيرات النمطية المرتبطة بكل قاعدة إلى آلة حالات محدودة حتمية، ويشفّرها في شكل قفزات شرطية باللغة الهدف ويستبدل الكتلة بالشيفرة المولّدة. تُضاف الأسماء والإعدادات المعرفة في كتلة عامة إلى النطاق العام وتصبح مرئية للكتل اللاحقة. في بداية البرنامج يُهيَّأ النطاق العام بـخيارات سطر الأوامر.
/*!local:re2c[:<name>] ... */ أو %{local[:<name>] ... %}
الكتلة المحلية مثل الكتلة العامة، لكن الأسماء والإعدادات فيها لها نطاق محلي (لا تؤثر على الكتل الأخرى).
/*!rules:re2c[:<name>] ... */ أو %{rules[:<name>] ... %}
كتلة القواعد مثل الكتلة المحلية، لكنها لا تولّد أي شيفرة بحد ذاتها، ولا تضيف أي تعريفات إلى النطاق العام -- بل هي مخصصة لإعادة الاستخدام في كتل أخرى. هذه طريقة لمشاركة الشيفرة (مزيد من التفاصيل في قسم الكتل القابلة لإعادة الاستخدام). قبل الإصدار 2.2 من re2d كانت كتل القواعد تتطلب خيار -r --reusable.
/*!use:re2c[:<name>] ... */ أو %{use[:<name>] ... %}
كتلة استخدام تشير إلى كتلة قواعد معرفة مسبقًا. إذا تم تحديد الاسم، يبحث re2d عن كتلة قواعد بهذا الاسم. وإلا تُستخدم أحدث كتلة قواعد (سواء كانت مسماة أو غير مسماة). يمكن لكتلة الاستخدام إضافة تعريفات وإعدادات وقواعد خاصة بها، تُضاف إلى تلك الموجودة في كتلة القواعد المشار إليها. قبل الإصدار 2.2 من re2d كانت كتل الاستخدام تتطلب خيار -r --reusable.
/*!max:re2c[:<name1>[:<name2>...]] ... */ أو %{max[:<name1>[:<name2>...]] ... %}
كتلة تولّد تعريف YYMAXFILL. تحدد قائمة اختيارية من أسماء الكتل أي الكتل يجب تضمينها عند حساب قيمة YYMAXFILL (إذا كانت القائمة فارغة، تُضمَّن جميع الكتل). افتراضيًا تكون الشيفرة المولّدة تعريفًا ماكرويًا للغة C (#define YYMAXFILL <n>)، أو متغيرًا عامًا للغة Go (var YYMAXFILL int = <n>). يمكن تخصيصها بإعداد اختياري format يحدد سلسلة قالب حيث يُستبدل @@{max} (أو @@ للاختصار) بالقيمة الرقمية لـYYMAXFILL.
/*!maxnmatch:re2c[:<name1>[:<name2>...]] ... */ أو %{maxnmatch[:<name1>[:<name2>...]] ... %}
كتلة تولّد تعريف YYMAXNMATCH (تتطلب خيار -P --posix-captures). تحدد قائمة اختيارية من أسماء الكتل أي الكتل يجب تضمينها عند حساب قيمة YYMAXNMATCH (إذا كانت القائمة فارغة، تُضمَّن جميع الكتل). افتراضيًا تكون الشيفرة المولّدة تعريفًا ماكرويًا للغة C (#define YYMAXNMATCH <n>)، أو متغيرًا عامًا للغة Go (var YYMAXNMATCH int = <n>). يمكن تخصيصها بإعداد اختياري format يحدد سلسلة قالب حيث يُستبدل @@{max} (أو @@ للاختصار) بالقيمة الرقمية لـYYMAXNMATCH.
/*!stags:re2c[:<name1>[:<name2>...]] ... */, /*!mtags:re2c[:<name1>[:<name2>...]] ... */ أو %{stags[:<name1>[:<name2>...]] ... %}, %{mtags[:<name1&>[:<name2>...]] ... %{
كتل تحدد قطعة قالب من الكود يتم توسيعها لكل متغير s-tag/m-tag يتم إنشاؤه بواسطة re2d. تحدد قائمة اختيارية من أسماء الكتل أي الكتل يجب تضمينها عند حساب مجموعة متغيرات الوسم (إذا كانت القائمة فارغة، يتم تضمين جميع الكتل). هناك إعدادان اختياريان: format وseparator. يحدد الإعداد format سلسلة قالب حيث يتم استبدال @@{tag} (أو @@ للاختصار) باسم كل متغير وسم. يحدد الإعداد separator قطعة من الكود تُستخدم لربط قطع format المُنشأة لمتغيرات الوسم المختلفة.
/*!svars:re2c[:<name1>[:<name2>...]] ... */, /*!mvars:re2c[:<name1>[:<name2>...]] ... */ أو %{svars[:<name1>[:<name2>...]] ... %}, %{mvars[:<name1>[:<name2>...]] ... %{
كتل تحدد قطعة قالب من الكود يتم توسيعها لكل s-tag/m-tag إما مذكور صراحةً بواسطة القواعد (باستخدام خيار --tags) أو يتم إنشاؤه ضمنيًا بواسطة re2d (باستخدام خيارات --captvars أو --posix-captvars). تحدد قائمة اختيارية من أسماء الكتل أي الكتل يجب تضمينها عند حساب مجموعة الوسوم (إذا كانت القائمة فارغة، يتم تضمين جميع الكتل). هناك إعدادان اختياريان: format وseparator. يحدد الإعداد format سلسلة قالب حيث يتم استبدال @@{tag} (أو @@ للاختصار) باسم كل وسم. يحدد الإعداد separator قطعة من الكود تُستخدم لربط قطع format المُنشأة للوسوم المختلفة.
/*!getstate:re2c[:<name1>[:<name2>...]] ... */ أو %{getstate[:<name1>[:<name2>...]] ... %}
كتلة تُنشئ إرسالًا شرطيًا بناءً على حالة المُحلِّل المعجمي (تتطلب خيار --storable-state). تحدد قائمة اختيارية من أسماء الكتل أي الكتل يجب تضمينها في إرسال الحالة. يذهب الانتقال الافتراضي إلى تسمية البداية للكتلة الأولى في القائمة. إذا كانت القائمة فارغة، يتم تضمين جميع الكتل، ويذهب الانتقال الافتراضي إلى الكتلة الأولى في الملف التي تحتوي على تسمية بداية. نوع الكتلة هذا غير متوافق مع خيار --loop-switch، لأنه يتطلب انتقالات عبر الكتل غير مدعومة بدون goto أو استدعاءات دوال.
/*!conditions:re2c[:<name1>[:<name2>...]] ... */, /*!types:re2c... */ أو %{conditions[:<name1>[:<name2>...]] ... %}, %{types... %}
كتلة تُنشئ تعداد الشروط (تتطلب خيار --conditions). تحدد قائمة اختيارية من أسماء الكتل أي الكتل يجب تضمينها عند حساب مجموعة الشروط (إذا كانت القائمة فارغة، يتم تضمين جميع الكتل). افتراضيًا، الكود المُنشأ هو تعداد YYCONDTYPE. يمكن تخصيصه باستخدام الإعدادات الاختيارية format وseparator. يحدد الإعداد format سلسلة قالب حيث يتم استبدال @@{cond} (أو @@ للاختصار) باسم كل شرط، ويتم استبدال @@{num} بفهرس رقمي لذلك الشرط. يحدد الإعداد separator قطعة من الكود تُستخدم لربط قطع format المُنشأة للشروط المختلفة.
/*!include:re2c <file> */ أو %{include <file> %}
تسمح هذه الكتلة بتضمين <file>، والذي يجب أن يكون مسار ملف بين علامتي اقتباس مزدوجتين. يتم استبدال محتويات الملف حرفيًا مكان الكتلة، بنفس الطريقة التي يعمل بها #include في C/C++. يمكن استخدام هذه الكتلة مع خيار --depfile لإنشاء تبعيات نظام البناء على الملفات المضمنة.
/*!header:re2c:on*/ أو %{header:on %}
تشير هذه الكتلة إلى بداية ملف الترويسة. تتم معالجة كل شيء بعدها وحتى كتلة header:off التالية بواسطة re2d ويُكتب إلى ملف الترويسة المحدد بخيار -t --type-header.
/*!header:re2c:off*/ أو %{header:off %}
تشير هذه الكتلة إلى نهاية ملف الترويسة الذي بدأ بكتلة header:on*/.
/*!ignore:re2c ... */ أو %{ignore ... %}
كتلة يتم تجاهل محتوياتها وإزالتها من ملف الإخراج.

الإعدادات

فيما يلي قائمة كاملة بالإعدادات المدعومة بواسطة re2d:

re2c:api, re2c:input
نفس خيار --api.
re2c:api:sigil
يحدد العلامة ("sigil") المستخدمة لعناصر نائبة للوسائط في أوليات API. القيمة الافتراضية هي @@. يبدأ العنصر النائب بالعلامة متبوعة باسم الوسيط بين أقواس معقوفة. على سبيل المثال، إذا تم تعيين العلامة إلى $، فستكون العناصر النائبة بالشكل ${name}. قد تستخدم واجهات API ذات الوسيط الواحد تدوينًا مختصرًا بدون الاسم بين الأقواس. يمكن تجاوز هذا الخيار بواسطة خيارات لأوليات API فردية، مثل re2c:YYFILL@len لـ YYFILL.
re2c:api:style
يحدد نمط API. القيم الممكنة هي functions (الافتراضي لـ C) وfree-form (الافتراضي لـ Go وRust). في نمط functions يتم إنشاء أوليات API بقائمة وسائط بين أقواس تتبع اسم الأولية. يتم توفير الوسائط فقط للمعاملات المُنشأة تلقائيًا (مثل عدد الأحرف الممررة إلى YYFILL)، ولكن ليس لسياق المُحلِّل المعجمي العام، لذا تتصرف الأوليات أشبه بماكرو في C/C++ أو إغلاقات في Go وRust. في النمط الحر لا يكون لأوليات API شكل ثابت: يجب تعريفها كسلاسل تحتوي على قطع كود حرة مع متغيرات مُدخلة بالشكل @@{var} أو @@ (تتوافق مع الوسائط في النمط الشبيه بالدوال). يمكن تجاوز هذا الإعداد لأوليات API فردية، انظر على سبيل المثال إعداد re2c:YYFILL:naked لـ YYFILL.
re2c:bit-vectors, re2c:flags:bit-vectors, re2c:flags:b
نفس خيار --bit-vectors، ولكن يمكن تكوينه على أساس كل كتلة.
re2c:captures, re2c:leftmost-captures
نفس خيار --leftmost-captures، ولكن يمكن تكوينه على أساس كل كتلة.
re2c:captvars, re2c:leftmost-captvars
نفس خيار --leftmost-captvars، ولكن يمكن تكوينه على أساس كل كتلة.
re2c:case-insensitive, re2c:flags:case-insensitive
نفس خيار --case-insensitive، ولكن يمكن تكوينه على أساس كل كتلة.
re2c:case-inverted, re2c:flags:case-inverted
نفس خيار --case-inverted، ولكن يمكن تكوينه على أساس كل كتلة.
re2c:case-ranges, re2c:flags:case-ranges
نفس خيار --case-ranges، ولكن يمكن تكوينه على أساس كل كتلة.
re2c:computed-gotos, re2c:flags:computed-gotos, re2c:flags:g
نفس خيار --computed-gotos، ولكن يمكن تكوينه على أساس كل كتلة.
re2c:computed-gotos:relative, re2c:cgoto:relative
نفس خيار --computed-gotos-relative، ولكن يمكن تكوينه على أساس كل كتلة.
re2c:computed-gotos:threshold, re2c:cgoto:threshold
إذا تم استخدام goto المحسوب، يحدد هذا الإعداد عتبة التعقيد التي تُفعّل إنشاء جداول القفز بدلاً من عبارات if المتداخلة والخرائط البتية. القيمة الافتراضية هي 9.
re2c:cond:abort
إذا تم تعيينه إلى قيمة صحيحة موجبة، فإن الحالة الافتراضية في إرسال الشروط المُنشأ تُنهي تنفيذ البرنامج.
re2c:cond:goto
يحدد قطعة من الكود تُستخدم لقواعد الاختصار المُنشأة تلقائيًا :=> في الشروط. القيمة الافتراضية هي goto @@;. يتم استبدال العنصر النائب @@ باسم الشرط (انظر الإعدادات re2c:api:sigil وre2c:cond:goto@cond).
re2c:cond:goto@cond
يحدد العلامة المستخدمة لاستبدال الوسائط في تعريف re2c:cond:goto. القيمة الافتراضية هي @@. يتجاوز الإعداد الأكثر عمومية re2c:api:sigil.
re2c:cond:divider
يحدد الفاصل لكتل الشروط. القيمة الافتراضية هي /* *********************************** */. يتم استبدال العناصر النائبة باسم الشرط (انظر re2c:api;sigil وre2c:cond:divider@cond).
re2c:cond:divider@cond
يحدد العلامة المستخدمة لاستبدال الوسائط في تعريف re2c:cond:divider. القيمة الافتراضية هي @@. يتجاوز الإعداد الأكثر عمومية re2c:api:sigil.
re2c:cond:prefix, re2c:condprefix
يحدد البادئة المستخدمة لتسميات الشروط. القيمة الافتراضية هي yyc_.
re2c:cond:enumprefix, re2c:condenumprefix
يحدد البادئة المستخدمة لمعرفات الشروط. القيمة الافتراضية هي yyc.

التعبيرات النمطية

يستخدم re2d الصياغة التالية للتعبيرات النمطية:

"foo"
قيمة نصية حرفية حساسة لحالة الأحرف.
'foo'
قيمة نصية حرفية غير حساسة لحالة الأحرف.
[a-xyz], [^a-xyz]
فئة أحرف (قد تكون منفية).
.
أي حرف باستثناء السطر الجديد.
R \ S
الفرق بين فئتي الأحرف R وS.
R*
صفر أو أكثر من تكرارات R.
R+
تكرار واحد أو أكثر من R.
R?
R اختياري.
R{n}
تكرار R بالضبط n مرة.
R{n,}
تكرار R على الأقل n مرة.
R{n,m}
تكرار R من n إلى m مرة.
(R)
فقط R؛ تُستخدم الأقواس لتجاوز الأولوية. إذا كان استخراج المطابقات الفرعية مفعّلًا، فإن (R) تكون مجموعة آسرة أو غير آسرة اعتمادًا على خيار --invert-captures.
(!R)
إذا كان استخراج المطابقات الفرعية مفعّلًا، فإن (!R) تكون مجموعة غير آسرة أو آسرة اعتمادًا على خيار --invert-captures.
R S
التسلسل: R متبوعًا بـS.
R | S
البديل: R أو S.
R / S
الاستباق: R متبوعًا بـS، لكن S لا يُستهلك.
name
تعبير نمطي معرّف باسم name (أو سلسلة حرفية "name" في وضع التوافق مع Flex).
{name}
تعبير نمطي معرّف باسم name في وضع التوافق مع Flex.
@stag
وسم s: يحفظ آخر موضع إدخال يطابقه @stag في متغير باسم stag.
#mtag
وسم m: يحفظ جميع مواضع الإدخال التي يطابقها #mtag في متغير باسم mtag.

قد تحتوي فئات الأحرف والسلاسل الحرفية على تسلسلات الهروب التالية: \a، \b، \f، \n، \r، \t، \v، \\، تسلسلات الهروب الثمانية \ooo وتسلسلات الهروب السداسية عشرية \xhh، \uhhhh و\Uhhhhhhhh.

الإجراءات

فيما يلي قائمة بالإجراءات المعرّفة مسبقًا التي يدعمها re2d:

!entry code
يربط إجراء الدخول كتلة code معرّفة من المستخدم بحالة البداية للآلة الحالة المنتهية الحالية. إذا استُخدمت شروط البداية، يمكن تعيين إجراء الدخول بشكل فردي لكل شرط. يمكن استخدام هذا الإجراء لإجراء التهيئة، مثل حفظ موضع بداية المعجم.
!pre_rule code
يضيف إجراء ما قبل القاعدة كتلة code معرّفة من المستخدم إلى بداية الإجراءات الدلالية لجميع القواعد في الكتلة الحالية (أو الشرط، إذا استُخدمت شروط البداية). يمكن استخدام هذا الإجراء لعزل الجزء المشترك من جميع الإجراءات الدلالية (مثل حفظ موضع نهاية المعجم).
!post_rule code
يضيف إجراء ما بعد القاعدة كتلة code معرّفة من المستخدم إلى نهاية الإجراءات الدلالية لجميع القواعد في الكتلة الحالية (أو الشرط، إذا استُخدمت شروط البداية). يمكن استخدام هذا الإجراء لإصدار عبارات فخ تحمي من تدفق التحكم غير المقصود.

التوجيهات

فيما يلي قائمة كاملة بالتوجيهات التي يدعمها re2d:

!use:name ;
توجيه استخدام داخل الكتلة يدمج كتلة قواعد معرّفة سابقًا بالاسم المحدد name في الكتلة الحالية. تُضاف التعريفات المسماة والتكوينات والقواعد الخاصة بالكتلة المرجعية إلى الكتلة الحالية. تُحل التعارضات بين القواعد والتكوينات المتداخلة بالطريقة المعتادة: القاعدة الأولى تأخذ الأولوية، وأحدث تكوين يتجاوز التكوينات السابقة. الاستثناء هو القواعد الخاصة * و$ و<!> التي تأخذ فيها التعريفات المحلية للكتلة الأولوية دائمًا. يمكن وضع توجيه الاستخدام في أي مكان داخل الكتلة، ويُسمح بتوجيهات استخدام متعددة.
!include file ;
هذا التوجيه مماثل لكتلة include: يُدرج محتويات file حرفيًا في مكان التوجيه.

واجهة البرنامج

تتفاعل الشيفرة المولّدة مع البرنامج الخارجي بمساعدة العناصر الأولية، المشار إليها مجتمعة باسم API. تعتمد العناصر الأولية التي يجب تعريفها لبرنامج معين على عوامل متعددة، بما في ذلك تعقيد التعبيرات النمطية وتمثيل الإدخال والتخزين المؤقت واستخدام ميزات متنوعة. يجب على المستخدم تعريف جميع العناصر الأولية اللازمة في شكل وحدات ماكرو أو دوال أو متغيرات أو أي شكل مناسب آخر يجعل الشيفرة المولّدة صحيحة نحويًا ودلاليًا. لا يتحقق re2d (ولا يمكنه) من التعريفات، لذا إذا كان أي شيء مفقودًا أو معرّفًا بشكل غير صحيح، فقد يحتوي البرنامج المولّد على أخطاء وقت الترجمة أو وقت التشغيل. يقدم هذا الدليل أمثلة على تعريفات API في الحالات الأكثر شيوعًا.

يمتلك re2d ثلاثة أنواع من API تحدد المجموعة الأساسية من العناصر الأولية التي يستخدمها البرنامج:

Simple API
هذا هو API الافتراضي لواجهة D الخلفية. يتكون من العناصر الأولية YYCURSOR وYYMARKER وYYCTXMARKER وYYLIMIT، والتي يجب تعريفها كمؤشرات من النوع YYCTYPE*.
Record API
يكون Record API مفيدًا في الحالات التي يجب فيها تخزين حالة المحلل المعجمي في بنية. يُفعّل بخيار --api record أو تكوين re2c:api = record. يتكون هذا API من متغير yyrecord (يمكن تجاوز الاسم بـre2c:yyrecord) والذي يجب تعريفه كبنية بحقول yycursor وyymarker وyyctxmarker وyylimit (يجب تعريف الحقول المستخدمة فقط بواسطة الشيفرة المولّدة، ويمكن تكوين أسمائها).
Generic API
هذا هو API الأكثر مرونة. يُفعّل بخيار --api generic أو تكوين re2c:api = generic. يحتوي على عناصر أولية للعمليات العامة: YYPEEK، YYSKIP، YYBACKUP، YYBACKUPCTX، YYSTAGP، YYSTAGN، YYMTAGP، YYMTAGN، YYRESTORE، YYRESTORECTX، YYRESTORETAG، YYSHIFT، YYSHIFTSTAG، YYSHIFTMTAG، YYLESSTHAN.

فيما يلي قائمة كاملة بعناصر API الأولية التي قد تستخدمها الشيفرة المولّدة للتفاعل مع البرنامج الخارجي.

YYCTYPE
نوع أحرف الإدخال (وحدات الشيفرة). بالنسبة لترميزات ASCII وEBCDIC وUTF-8 يجب أن يكون عددًا صحيحًا غير موقع بحجم 1 بايت. بالنسبة لـUTF-16 أو UCS-2 يجب أن يكون عددًا صحيحًا غير موقع بحجم 2 بايت. بالنسبة لـUTF-32 يجب أن يكون عددًا صحيحًا غير موقع بحجم 4 بايت.
YYCURSOR
قيمة l-value تخزن موضع الإدخال الحالي (مؤشر أو إزاحة عدد صحيح في YYINPUT). في البداية يجب أن يشير YYCURSOR إلى أول حرف إدخال، ثم تتقدمه الشيفرة المولّدة لاحقًا. عندما تطابق قاعدة ما، يكون موضع YYCURSOR هو الموضع الذي يلي آخر حرف مطابق.
YYLIMIT
قيمة r-value تخزن موضع نهاية الإدخال (مؤشر أو إزاحة عدد صحيح في YYINPUT). في البداية يجب أن يشير YYLIMIT إلى الموضع الذي يلي آخر حرف إدخال متاح. لا تغيّره الشيفرة المولّدة. يقارن المحلل المعجمي YYCURSOR بـYYLIMIT لتحديد ما إذا كانت هناك أحرف إدخال كافية متبقية.
YYMARKER
قيمة l-value تخزن موضع آخر قاعدة مطابقة (مؤشر أو إزاحة عدد صحيح في YYINPUT). تُستخدم لاستعادة موضع YYCURSOR إذا فشلت المطابقة الأطول واحتاج المحلل المعجمي إلى التراجع. لا حاجة للتهيئة.
YYCTXMARKER
قيمة l-value تخزن موضع السياق اللاحق (مؤشر أو إزاحة عدد صحيح في YYINPUT). لا حاجة للتهيئة. يكون YYCTXMARKER مطلوبًا فقط إذا استُخدم عامل الاستباق /.
YYFILL
عنصر أولي في API العام بمتغير واحد len. يجب أن يوفر YYFILL على الأقل len من أحرف الإدخال الإضافية أو يفشل. إذا استُخدم re2c:eof، فإن len يكون دائمًا 1 ويجب أن يعود YYFILL دائمًا إلى الدالة المستدعية؛ تشير قيمة الإرجاع صفر إلى النجاح. إذا لم يُستخدم re2c:eof، فإن قيمة إرجاع YYFILL تُتجاهل ويجب ألا يعود عند الفشل. القيمة القصوى لـlen هي YYMAXFILL.
YYFN
عنصر أولي يحدد نموذج الدالة الأولي في نموذج الشيفرة --recursive-functions. يجب أن تكون قيمته مصفوفة من سلسلة واحدة أو أكثر، حيث تحتوي كل سلسلة على مكونين أو ثلاثة مكونات مفصولة بالسلسلة المحددة في تكوين re2c:fn:sep (عادةً فاصلة منقوطة). يحدد عنصر المصفوفة الأول اسم الدالة ونوع الإرجاع (فارغ لدالة void). تحدد العناصر اللاحقة وسائط الدالة: أولًا، التعبير الخاص بالوسيط المستخدم في جسم الدالة (عادةً مجرد اسم)؛ ثانيًا، نوع الوسيط؛ ثالثًا، معامل شكلي اختياري (يُفترض افتراضيًا أنه المكون الأول - عادةً يكون كل من الوسيط والمعامل نفس المعرّف).
YYINPUT
قيمة r-value تخزن تسلسل أحرف الإدخال الحالي (سلسلة، مخزن مؤقت، إلخ).
YYMAXFILL
ثابت صحيح يساوي القيمة القصوى للوسيط الممرر إلى YYFILL. يمكن توليده باستخدام كتلة max.
YYLESSTHAN
عنصر أولي في API العام بمتغير واحد len. يجب تعريفه كقيمة r-value من النوع المنطقي تساوي true إذا وفقط إذا كان هناك أقل من len من أحرف الإدخال
YYPEEK
بدائية API عامة بدون متغيرات. يجب تعريفها كقيمة r من النوع YYCTYPE تساوي الحرف عند موضع الإدخال الحالي.
YYSKIP
بدائية API عامة يجب أن تقدّم موضع الإدخال الحالي بمقدار وحدة رمز واحدة.
YYBACKUP
بدائية API عامة يجب أن تحفظ موضع الإدخال الحالي (ليُستعاد لاحقًا باستخدام YYRESTORE).
YYRESTORE
بدائية API عامة يجب أن تستعيد موضع الإدخال الحالي إلى القيمة المحفوظة بواسطة YYBACKUP.
YYBACKUPCTX
بدائية API عامة يجب أن تحفظ موضع الإدخال الحالي كموضع للسياق التابع (ليُستعاد لاحقًا باستخدام YYRESTORECTX).
YYRESTORECTX
بدائية API عامة يجب أن تستعيد موضع السياق التابع المحفوظ بواسطة YYBACKUPCTX.
YYRESTORETAG
بدائية API عامة بمتغير واحد tag يجب أن تستعيد موضع السياق التابع إلى قيمة tag.
YYSTAGP
بدائية API عامة بمتغير واحد tag، حيث يمكن أن يكون tag مؤشرًا أو إزاحة في YYINPUT (انظر قسم استخراج المطابقات الفرعية للتفاصيل). يجب أن تضبط YYSTAGP قيمة tag على موضع الإدخال الحالي.
YYSTAGN
بدائية API عامة بمتغير واحد tag، حيث يمكن أن يكون tag مؤشرًا أو إزاحة في YYINPUT (انظر قسم استخراج المطابقات الفرعية للتفاصيل). يجب أن تضبط YYSTAGN قيمة tag على قيمة تمثل موضع إدخال غير موجود.
YYMTAGP
بدائية API عامة بمتغير واحد tag. يجب أن تُلحق YYMTAGP الموضع الحالي بسجل المطابقات الفرعية الخاص بـ tag (انظر قسم استخراج المطابقات الفرعية للتفاصيل.)
YYMTAGN
بدائية API عامة بمتغير واحد tag. يجب أن تُلحق YYMTAGN قيمة تمثل موضع إدخال غير موجود بسجل المطابقات الفرعية الخاص بـ tag (انظر قسم استخراج المطابقات الفرعية للتفاصيل.)
YYSHIFT
بدائية API عامة بمتغير واحد shift يجب أن تُزيح موضع الإدخال الحالي بمقدار shift حرفًا (قد تكون قيمة الإزاحة سالبة).
YYCOPYSTAG
بدائية API عامة بمتغيرين، lhs وrhs، يجب أن تنسخ متغير s-tag الأيمن rhs إلى متغير s-tag الأيسر lhs. لمعظم اللغات لهذه البدائية تعريف افتراضي يُسند lhs إلى rhs.
YYCOPYMTAG
بدائية API عامة بمتغيرين، lhs وrhs، يجب أن تنسخ متغير m-tag الأيمن rhs إلى متغير m-tag الأيسر lhs. لمعظم اللغات لهذه البدائية تعريف افتراضي يُسند lhs إلى rhs.
YYSHIFTSTAG
بدائية API عامة بمتغيرين، tag وshift، يجب أن تُزيح tag بمقدار shift وحدة رمز (قد تكون قيمة الإزاحة سالبة).
YYSHIFTMTAG
بدائية API عامة بمتغيرين، tag وshift، يجب أن تُزيح أحدث قيمة في سجل tag بمقدار shift وحدة رمز (قد تكون قيمة الإزاحة سالبة).
YYMAXNMATCH
ثابت صحيح يساوي الحد الأقصى لعدد مجموعات الالتقاط POSIX في قاعدة ما. يُولَّد باستخدام كتلة maxnmatch.
YYCONDTYPE
نوع تعداد الشرط. يمكن توليده إما باستخدام كتلة conditions أو خيار --header.
YYGETACCEPT
بدائية بمتغير واحد var تخزّن المحدد الرقمي للقاعدة المقبولة. لمعظم اللغات لهذه البدائية تعريف افتراضي يقرأ من var.
YYSETACCEPT
بدائية بمتغيرين: var (قيمة l تخزّن المحدد الرقمي للقاعدة المقبولة)، وval (قيمة المحدد). لمعظم اللغات لهذه البدائية تعريف افتراضي يُسند var إلى val.
YYGETCOND
قيمة r من النوع YYCONDTYPE تساوي معرّف الشرط الحالي.
YYSETCOND
بدائية بمتغير واحد cond يجب أن تضبط معرّف الشرط الحالي على cond.
YYGETSTATE
قيمة r من نوع صحيح تساوي حالة المحلل المعجمي الحالية. يجب تهيئتها إلى -1.
YYSETSTATE
بدائية بمتغير واحد state يجب أن تضبط حالة المحلل المعجمي الحالية على state.
YYDEBUG
تُولَّد هذه البدائية فقط مع خيار -d، --debug-output. الغرض منها إضافة تسجيل إلى الكود المولَّد (التعريف النموذجي لـ YYDEBUG هو عبارة طباعة). تُولَّد عبارات YYDEBUG في كل حالة ولها متغيران: state (إما فهرس حالة DFA أو -1) وsymbol (رمز الإدخال الحالي).
yyaccept
قيمة l من نوع صحيح غير موقّع تخزّن رقم أحدث قاعدة مطابقة. تعريف المستخدم ضروري فقط مع خيار --storable-state.
yybm
جدول يحتوي على خرائط بت مضغوطة لما يصل إلى 8 انتقالات (يُستخدم مع خيار --bitmaps). يحتوي الجدول على 256 عنصرًا ويُفهرَس بوحدات رمز بحجم بايت واحد. كل عنصر 8-بت يجمع قيمًا منطقية لما يصل إلى 8 انتقالات. البت k في العنصر n صحيح إذا وفقط إذا كانت وحدة الرمز n ضمن نطاق الانتقال k. فكرة هذه الخريطة هي استبدال العديد من فروع if أو حالات switch بفحص واحد لبت واحد في الجدول.
yych
قيمة l من النوع YYCTYPE تخزّن حرف الإدخال الحالي. تعريف المستخدم ضروري فقط مع خيار -f --storable-state.
yyctable
جدول قفز يُولَّد لإرسال الشرط الأولي (يُفعَّل بمزيج من خياري --conditions و--computed-gotos).
yyfill
قيمة l تخزّن نتيجة استدعاء YYFILL (قد يكون هذا ضروريًا للغات الوظيفية الصرفة، حيث YYFILL دالة أحادية ذات قيمة إرجاع معقدة).
yynmatch
قيمة l من نوع صحيح غير موقّع تخزّن عدد مجموعات الالتقاط POSIX في القاعدة المطابقة. تُستخدم فقط مع خيار -P --posix-captures.
yypmatch
مصفوفة من قيم l تُستخدم لحمل قيم الوسوم المقابلة للأقواس الملتقطة في القاعدة المطابقة. يجب أن يكون طول المصفوفة على الأقل yynmatch * 2 (عادةً YYMAXNMATCH * 2 خيار جيد). تُستخدم فقط مع خيار -P --posix-captures.
yystable
مهمَل.
yystate
قيمة l تُستخدم مع خيار --loop-switch لتخزين حالة DFA الحالية.
yytarget
جدول قفز يحتوي على أهداف القفز (عناوين التسميات) لجميع الانتقالات من حالة ما. هذا الجدول محلي لكل حالة. يُفعَّل توليد جداول yytarget مع خيار --computed-gotos.

الخيارات

بعض الخيارات لها تكوينات مقابلة، والبعض الآخر عام ولا يمكن تغييره بعد أن يبدأ re2c في قراءة ملف الإدخال. تتطلب خيارات التصحيح عمومًا بناء re2c في تكوين التصحيح. الخيارات الداخلية مفيدة للتجريب بالخوارزميات المستخدمة في re2c.

-? --help -h
عرض رسالة المساعدة.
--api <simple | record | generic>
تحديد واجهة API التي يستخدمها الكود المولَّد للتفاعل مع الكود المعرَّف من المستخدم. يجب استخدام الخيار simple في الحالات البسيطة عندما لا تكون هناك حاجة لإعادة ملء المخزن المؤقت وتخزين حالة المحلل المعجمي. يجب استخدام الخيار record عندما تحتاج حالة المحلل المعجمي إلى التخزين في سجل (struct، class، إلخ). يجب استخدام الخيار generic في الحالات المعقدة عندما لا تكون واجهتا API الأخريان مرنتين بما يكفي.
--bit-vectors -b
تحسين القفزات الشرطية باستخدام أقنعة البت. هذا الخيار يستلزم --nested-ifs.
--captures, --leftmost-captures
تفعيل استخراج المطابقات الفرعية بمجموعات التقاط جشعة أقصى اليسار. تُجمع النتيجة في مصفوفة yybmatch بسعة 2 * YYMAXNMATCH، وتُضبط yynmatch على عدد المجموعات للقاعدة المطابقة.
--captvars, --leftmost-captvars
تفعيل استخراج المطابقات الفرعية بمجموعات التقاط جشعة أقصى اليسار. تُجمَّع النتيجة
يتم جمعها في المتغيرات yytl<k>، yytr<k> لمجموعة الالتقاط رقم k.
--case-insensitive
التعامل مع السلاسل النصية المفردة والمزدوجة الاقتباس على أنها غير حساسة لحالة الأحرف.
--case-inverted
عكس معنى السلاسل النصية المفردة والمزدوجة الاقتباس: التعامل مع السلاسل المفردة الاقتباس على أنها حساسة لحالة الأحرف والسلاسل المزدوجة الاقتباس على أنها غير حساسة لحالة الأحرف.
--case-ranges

For tags in top-level concatenation the check is not needed, because they always match.

ملفات الصياغة

يعتمد دعم اللغات المختلفة في re2c على فكرة ملفات الصياغة. ملف الصياغة هو ملف تكوين يحدد صياغة اللغة الهدف -- ليس اللغة بأكملها، بل جزءًا صغيرًا منها يستخدمه الكود المولد. تجعل ملفات الصياغة re2c مرنًا للغاية، لكن لا ينبغي استخدامها كبديل لتكوينات re2c:: الغرض منها هو تحديد صياغة اللغة الهدف، وليس تخصيص محلل معجمي معين. جميع اللغات المدعومة لديها ملفات صياغة افتراضية تشكل جزءًا من التوزيع (انظر الدليل الفرعي include/syntax)؛ كما أنها مضمنة في ثنائي re2d. يمكن للمستخدمين تقديم ملف صياغة مخصص يتجاوز بعض التكوينات لإحدى اللغات المدعومة، أو يمكنهم اختيار إعادة تعريف جميع التكوينات (في هذه الحالة يجب استخدام خيار --lang none). تحتوي ملفات الصياغة على تكوينات من أربعة أنواع مختلفة: قوائم الميزات، وتكوينات اللغة، والتكوينات الموضعية، وقوالب الكود.

قوالب الكود

تحدد قوالب الكود صياغة اللغة الهدف. وهي مكتوبة بلغة بسيطة خاصة بالمجال بالقواعد الرسمية التالية: 
code-template ::
      name '=' code-exprs ';'
    | CODE_TEMPLATE ';'
    | '<undefined>' ';'
code-exprs ::
      <EMPTY>
    | code-exprs code-expr
code-expr ::
      STRING
    | VARIABLE
    | optional
    | list
optional ::
      '(' CONDITIONAL '?' code-exprs ')'
    | '(' CONDITIONAL '?' code-exprs ':' code-exprs ')'
list ::
      '[' VARIABLE ':' code-exprs ']'
    | '[' VARIABLE '{' NUMBER '}' ':' code-exprs ']'
    | '[' VARIABLE '{' NUMBER ',' NUMBER '}' ':' code-exprs ']'

قالب الكود هو تسلسل من حرفيات السلاسل والمتغيرات والعناصر الاختيارية والقوائم، أو إشارة إلى قالب كود آخر، أو قيمة خاصة <undefined>. المتغيرات هي عناصر نائبة يتم استبدالها أثناء مرحلة توليد الكود. متغيرات القوائم خاصة: عند توسيع قوالب القوائم، يكرر re2d التعبيرات على الجانب الأيمن من العمود عدة مرات، وفي كل مرة يستبدل تكرارات متغير القائمة بقيمة خاصة بهذا التكرار. للقوائم حدود اختيارية (يتم عد القيم السالبة من النهاية، على سبيل المثال -1 تعني العنصر الأخير). تبدأ أسماء الشروط بنقطة. قد تكون كل من الشروط والمتغيرات إما محلية (خاصة بقالب الكود المعطى) أو عامة (مسموح بها في جميع قوالب الكود). عندما يقرأ re2d ملف الصياغة، فإنه يتحقق من أن كل قالب كود يستخدم فقط المتغيرات والشروط المسموح بها فيه.

على سبيل المثال، قالب الكود التالي يحدد بنية if-then-else للغة شبيهة بلغة C:

code:if_then_else =
    [branch{0}: topindent "if " cond " {" nl
        indent [stmt: stmt] dedent]
    [branch{1:-1}: topindent "} else" (.cond ? " if " cond) " {" nl
        indent [stmt: stmt] dedent]
    topindent "}" nl;

هنا branch هو متغير قائمة: يتوسع branch{0} إلى الفرع الأول (وهو خاص، حيث لا يوجد جزء else)، ويتوسع branch{1:-1} إلى جميع الفروع المتبقية (إن وجدت). stmt هو أيضًا متغير قائمة: [stmt: stmt] هو قائمة متداخلة تتوسع إلى قائمة عبارات في جسم الفرع الحالي. topindent وindent وdedent وnl هي متغيرات عامة، و.cond هو شرط محلي (يتم وصف معناه أدناه). يمكن لقالب الكود هذا إنتاج الكود التالي:

if x {
    // do something
} else if y {
    // do something else
} else {
    // don't do anything
}

إليك قائمة بجميع قوالب الكود المدعومة من re2d مع متغيراتها وشروطها المحلية. لاحظ أن تعريفًا معينًا قد يستخدم، لكن ليس بالضرورة، المتغيرات والشروط المحلية. يجب تعيين أي قوالب كود غير مستخدمة إلى <undefined>.

التعامل مع نهاية الإدخال

إحدى المشكلات الرئيسية للمحلل المعجمي هي معرفة متى يتوقف. هناك بعض شروط الإنهاء:

  • قد يطابق المحلل المعجمي بعض القواعد (بما في ذلك القاعدة الافتراضية *) ويصل إلى حالة نهائية
  • قد يفشل المحلل المعجمي في مطابقة أي قاعدة ويصل إلى حالة افتراضية
  • قد يصل المحلل المعجمي إلى نهاية الإدخال

الشرطان الأولان ينهيان المحلل المعجمي بطريقة "طبيعية": يصل إلى حالة بلا انتقالات صادرة، وتتوقف المطابقة تلقائيًا. الشرط الثالث، نهاية الإدخال، مختلف: قد يحدث في أي حالة، ويجب أن يكون المحلل المعجمي قادرًا على التعامل معه. التحقق من نهاية الإدخال يقاطع سير العمل الطبيعي للمحلل المعجمي ويضيف فروعًا شرطية إلى البرنامج المولّد، لذلك من الضروري تقليل عدد هذه الفحوصات. يدعم re2d بعض الطرق المختلفة للتعامل مع نهاية الإدخال. أي واحدة تُستخدم تعتمد على تعقيد التعبيرات النمطية، والحاجة إلى التخزين المؤقت، واعتبارات الأداء وعوامل أخرى. فيما يلي قائمة بالطرق:

  • الحارس. هذه الطريقة تلغي الحاجة إلى فحوصات نهاية الإدخال تمامًا. إنها بسيطة وفعّالة، لكنها محدودة بالحالة التي يوجد فيها حرف "حارس" طبيعي لا يمكن أن يحدث أبدًا في إدخال صالح. قد يظهر هذا الحرف في إدخال غير صالح، لكن لا ينبغي أن تسمح به التعبيرات النمطية، إلا ربما كـ الحرف الأخير من قاعدة. يُلحق الحارس في نهاية الإدخال ويُستخدم كإشارة توقف: عندما يقرأ المحلل المعجمي هذا الحرف، فإنه إما خطأ نحوي أو نهاية الإدخال. في كلتا الحالتين يجب أن يتوقف المحلل المعجمي. تُستخدم هذه الطريقة إذا كان YYFILL معطّلًا بـ re2c:yyfill:enable = 0; وre2c:eof له القيمة الافتراضية -1.
  • الحارس مع فحوصات الحدود. هذه الطريقة عامة: تسمح بالتعامل مع أي إدخال دون قيود على التعبيرات النمطية. الفكرة هي تقليل عدد فحوصات نهاية الإدخال بإجرائها فقط على أحرف معينة. على غرار طريقة "الحارس"، يُختار أحد الأحرف كـ "حارس" ويُلحق في نهاية الإدخال. ومع ذلك، لا يوجد قيد على مكان ظهور الحارس (في الواقع، يمكن اختيار أي حرف كحارس). عندما يقرأ المحلل المعجمي هذا الحرف، فإنه يجري إضافةً إلى ذلك فحص حدود. إذا كان الموضع الحالي ضمن الحدود، يستأنف المحلل المعجمي المطابقة ويتعامل مع الحارس كحرف عادي. وإلا فإنه يستدعي YYFILL (ما لم يكن معطّلًا). إذا تم توفير المزيد من الإدخال، سيعيد المحلل المعجمي مطابقة الحرف الأخير ويستمر كما لو أن الحارس لم يكن موجودًا. وإلا فيجب أن تكون نهاية الإدخال الحقيقية، ويتوقف المحلل المعجمي. تُستخدم هذه الطريقة عندما يكون re2c:eof ذا قيمة غير سالبة (يجب ضبطه على القيمة الرقمية للحارس). YYFILL اختياري.
  • فحوصات الحدود مع الحشو. هذه الطريقة عامة، وقد تكون أسرع من طريقة "الحارس مع فحوصات الحدود"، لكنها أيضًا أكثر تعقيدًا. الفكرة هي تقسيم حالات DFA إلى مكونات متصلة بقوة (SCCs) وتوليد فحص واحد لكل SCC لعدد كافٍ من الأحرف لتغطية أطول مسار غير حلقي في هذا SCC. هذا يقلل عدد الفحوصات، لكن هناك مشكلة مع المعجمات القصيرة في نهاية الإدخال، حيث يتطلب الفحص أحرفًا كافية لتغطية أطول معجم. يمكن إصلاح ذلك بحشو الإدخال ببضعة أحرف وهمية لا تشكل لاحقة معجم صالحة (حتى لا يستطيع المحلل المعجمي مطابقتها). يجب أن يكون طول الحشو YYMAXFILL، المولّد بكتلة max. إذا لم يكن هناك إدخال كافٍ، يستدعي المحلل المعجمي YYFILL الذي يجب أن يوفر على الأقل العدد المطلوب من الأحرف أو لا يعود. تُستخدم هذه الطريقة إذا كان YYFILL مفعّلًا وre2c:eof هو -1 (هذا هو الإعداد الافتراضي).
  • فحوصات مخصصة. تسمح واجهة API العامة بتجاوز العمليات الأساسية مثل قراءة حرف، مما يجعل من الممكن تضمين فحوصات نهاية الإدخال كجزء منها. هذا النهج عرضة للأخطاء ويجب استخدامه بحذر. لاستخدام طريقة مخصصة، فعّل واجهة API العامة بـ --api custom أو re2c:api = custom; وعطّل فحوصات الحدود الافتراضية بـ re2c:yyfill:enable = 0; أو re2c:yyfill:check = 0;.

تحتوي الأقسام الفرعية التالية على مثال لكل طريقة.

الحارس

يستخدم هذا المثال حرف حارس للتعامل مع نهاية الإدخال. يحسب البرنامج الكلمات المفصولة بمسافات في سلسلة منتهية بالصفر. الحارس هو الصفر: إنه الحرف الأخير من كل سلسلة إدخال، وهو غير مسموح في منتصف معجم بأي من القواعد (على وجه الخصوص، غير مضمّن في نطاقات الأحرف حيث يسهل إغفاله). إذا ظهر صفر في منتصف سلسلة، فهو خطأ نحوي وسيطابق المحلل المعجمي القاعدة الافتراضية *، لكنه لن يقرأ بعد نهاية الإدخال أو ينهار (استخدم تحذير -Wsentinel-in-midrule وإعداد re2c:sentinel للتحقق من ذلك). الإعداد re2c:yyfill:enable = 0; يمنع توليد فحوصات الحدود واستدعاءات YYFILL.

// re2d $INPUT -o $OUTPUT
module main;
// Expect a null-terminated string.
private int lex(const(char)* yycursor) {
    uint count = 0;
    for (;;) {
    /*!re2c
        re2c:YYCTYPE = char;
        re2c:yyfill:enable = 0;
        *      { return -1; }
        [\x00] { return count; }
        [a-z]+ { ++count; continue; }
        [ ]+   { continue; }
    */
    }
    assert(0); // unreachable
}
void main() {
    assert(lex("") == 0);
    assert(lex("one two three") == 3);
    assert(lex("f0ur") == -1);
}

الحارس مع فحوصات الحدود

يستخدم هذا المثال الحارس مع فحوصات الحدود للتعامل مع نهاية الإدخال (أُضيفت هذه الطريقة في الإصدار 1.2). يحسب البرنامج السلاسل المفصولة بمسافات والمحاطة بعلامات اقتباس مفردة. حرف الحارس هو الصفر، المحدد بإعداد re2c:eof = 0;. كما في طريقة الحارس، الصفر هو الحرف الأخير من كل سلسلة إدخال، لكنه مسموح في منتصف قاعدة (على سبيل المثال، 'aaa\0aa'\0 هو إدخال صالح، لكن 'aaa\0 خطأ نحوي). تُولّد فحوصات الحدود في كل حالة تطابق حرف إدخال، لكنها محصورة في الفرع الذي يتعامل مع الصفر. فحوصات الحدود من الشكل YYLIMIT <= YYCURSOR أو YYLESSTHAN(1) مع واجهة API العامة. إذا كان شرط الفحص صحيحًا، فقد وصل المحلل المعجمي إلى نهاية الإدخال ويجب أن يتوقف (YYFILL معطّل بـ re2c:yyfill:enable = 0; حيث أن الإدخال يتسع في مخزن مؤقت واحد، انظر قسم YYFILL مع الحارس للحصول على مثال يستخدم YYFILL). الوصول إلى نهاية الإدخال يفتح ثلاث احتمالات: إذا كان المحلل المعجمي في الحالة الأولية فسيطابق قاعدة نهاية الإدخال $، وإلا فقد يرتد إلى قاعدة مطابقة سابقًا (بما في ذلك القاعدة الافتراضية *) أو يذهب إلى حالة افتراضية، مما يسبب -Wundefined-control-flow.

// re2d $INPUT -o $OUTPUT
module main;
// Expect a null-terminated string.
private int lex(immutable char[] s) {
    const(char)* yycursor = s.ptr, yylimit = s.ptr + s.length, yymarker;
    int count = 0;
    for (;;) {
    /*!re2c
        re2c:YYCTYPE = char;
        re2c:yyfill:enable = 0;
        re2c:eof = 0;
        str = ['] ([^'\\] | [\\][^])* ['];
        *    { return -1; }
        $    { return count; }
        str  { ++count; continue; }
        [ ]+ { continue; }
    */
    }
    assert(0); // unreachable
}
void main() {
    assert(lex("") == 0);
    assert(lex("'qu\0tes' 'are' 'fine: \\'' ") == 3);
    assert(lex("'unterminated\\'") == -1);
}

فحوصات الحدود مع الحشو

يستخدم هذا المثال فحوصات الحدود مع الحشو للتعامل مع نهاية الإدخال (هذه الطريقة مفعّلة افتراضيًا). يحسب البرنامج السلاسل المفصولة بمسافات والمحاطة بعلامات اقتباس مفردة. هناك حشو من YYMAXFILL حرف صفر ملحق في نهاية الإدخال، حيث قيمة YYMAXFILL مولّدة تلقائيًا بكتلة max. ليس من الضروري استخدام الصفر للحشو --- يمكن استخدام أي أحرف طالما أنها لا تشكل لاحقة معجم صالحة (في هذا المثال يجب ألا يحتوي الحشو على علامات اقتباس مفردة، لأنها قد تُخطئ على أنها لاحقة لسلسلة محاطة بعلامات اقتباس مفردة). هناك قاعدة "توقف" تطابق أول حرف حشو (الصفر) وتنهي المحلل المعجمي (لاحظ أنها تتحقق مما إذا كان الصفر في بداية الحشو، وإلا فهو خطأ نحوي). تُولّد فحوصات الحدود فقط في بعض الحالات التي تحددها المكونات المتصلة بقوة للأتمتة الأساسية. الفحوصات من الشكل (YYLIMIT - YYCURSOR) < n أو YYLESSTHAN(n) مععام API، حيث n هو الحد الأدنى لعدد الأحرف المطلوبة لكي يستمر المحلل المعجمي (وهذا يعني أيضًا أن فحص الحدود التالي سيحدث خلال n حرفًا على الأكثر). إذا كان شرط الفحص صحيحًا، فقد وصل المحلل المعجمي إلى نهاية الإدخال وسيستدعي YYFILL(n) الذي يجب أن يوفّر n حرفًا من الإدخال على الأقل أو ألا يعود. في هذا المثال يفشل YYFILL دائمًا وينهي المحلل المعجمي بخطأ (وهذا مقبول لأن الإدخال يتسع في مخزن مؤقت واحد). راجع قسم YYFILL مع الحشو للحصول على مثال يعيد ملء مخزن الإدخال المؤقت باستخدام YYFILL.

// re2d $INPUT -o $OUTPUT
module main;
import core.stdc.stdlib;
import core.stdc.string;
/*!max:re2c*/
private int lex(immutable char[] s) {
    // Make a copy of the string with YYMAXFILL zeroes at the end.
    char *buf = cast(char*) malloc(s.length + YYMaxFill);
    memcpy(buf, cast(const(void*)) s, s.length);
    memset(buf + s.length, 0, YYMaxFill);
    const(char)* yycursor = buf;
    const(char)* yylimit = buf + s.length + YYMaxFill;
    int count = 0;
loop:
    /*!re2c
        re2c:YYCTYPE = char;
        re2c:YYFILL = "goto fail;";
        str = ['] ([^'\\] | [\\][^])* ['];
        [\x00] {
            // Check that it is the sentinel, not some unexpected null.
            if (yycursor - 1 == buf + s.length) goto exit; else goto fail;
        }
        str  { ++count; goto loop; }
        [ ]+ { goto loop; }
        *    { goto fail; }
    */
fail:
    count = -1;
exit:
    free(buf);
    return count;
}
void main() {
    assert(lex("") == 0);
    assert(lex("'qu\0tes' 'are' 'fine: \\'' ") == 3);
    assert(lex("'unterminated\\'") == -1);
    assert(lex("'unexpected \0 null\\'") == -1);
}

فحوصات مخصصة

يستخدم هذا المثال طريقة مخصصة للتعامل مع نهاية الإدخال تعتمد على API العام. يعدّ البرنامج السلاسل النصية المفردة الاقتباس المفصولة بمسافات. وهو مماثل لمثال الحارس، باستثناء أن الإدخال غير منتهٍ بحرف null. للتعويض عن غياب حرف حارس في نهاية الإدخال، يُعاد تعريف YYPEEK ليقوم بفحص الحدود قبل أن يقرأ حرف الإدخال التالي. هذا غير فعّال لأن الفحوصات تُجرى كثيرًا جدًا. إذا فشل شرط الفحص، يعيد YYPEEK الحرف الحقيقي، وإلا فإنه يعيد حرف حارس وهمي.

// re2d $INPUT -o $OUTPUT
module main;
import core.stdc.stdlib;
import core.stdc.string;
private int lex(immutable char[] s) {
    // For the sake of example create a string without terminating null.
    char *buf = cast(char*) malloc(s.length);
    memcpy(buf, cast(const(void*)) s, s.length);
    const(char) *cur = buf, lim = buf + s.length;
    int count = 0;
    for (;;) {
    /*!re2c
        re2c:api = generic;
        re2c:yyfill:enable = 0;
        re2c:YYCTYPE = char;
        re2c:YYPEEK = "cur < lim ? *cur : 0";  // fake null
        re2c:YYSKIP = "++cur;";
        *      { count = -1; break; }
        [\x00] { break;{} }
        [a-z]+ { ++count; continue;{} }
        [ ]+   { continue; }
    */
    }
    free(buf);
    return count;
}
void main() {
    assert(lex("") == 0);
    assert(lex("one two three ") == 3);
    assert(lex("f0ur") == -1);
}

إعادة ملء المخزن المؤقت

تنشأ الحاجة إلى التخزين المؤقت عندما يتعذر تعيين الإدخال في الذاكرة دفعة واحدة: إما لأنه كبير جدًا، أو لأنه يأتي بأسلوب متدفق (مثل القراءة من مقبس). التقنية المعتادة في مثل هذه الحالات هي تخصيص مخزن مؤقت للذاكرة بحجم ثابت ومعالجة الإدخال في أجزاء تتسع في المخزن المؤقت. عند معالجة الجزء الحالي، يُنقل خارجًا وتُنقل بيانات جديدة إلى الداخل. عمليًا الأمر أكثر تعقيدًا إلى حد ما، لأن حالة المحلل المعجمي لا تتكون من موضع إدخال واحد، بل من مجموعة مواضع مترابطة:

  • المؤشر: حرف الإدخال التالي المراد قراءته (YYCURSOR في API مؤشر C أو YYSKIP/YYPEEK في API العام)
  • الحد: الموضع بعد آخر حرف إدخال متاح (YYLIMIT في API مؤشر C، ويُدار ضمنيًا بواسطة YYLESSTHAN في API العام)
  • العلامة: موضع أحدث تطابق، إن وُجد (YYMARKER في API الافتراضي أو YYBACKUP/YYRESTORE في API العام)
  • الرمز: بداية الوحدة المعجمية الحالية (ضمني في API الخاص بـ re2d، لأنه غير مطلوب لتشغيل المحلل المعجمي العادي ويمكن تعريفه وتحديثه بواسطة المستخدم)
  • علامة السياق: موضع السياق اللاحق (YYCTXMARKER في API مؤشر C أو YYBACKUPCTX/YYRESTORECTX في API العام)
  • متغيرات الوسم: مواضع المطابقة الفرعية (تُعرَّف بواسطة كتل stags و mtags وأساسيات API العام YYSTAGP/YYSTAGN/YYMTAGP/YYMTAGN)

لا تُستخدم كل هذه في كل حالة، لكن إذا استُخدمت، فيجب تحديثها بواسطة YYFILL. جميع المواضع النشطة محتواة في المقطع بين الرمز والمؤشر، لذلك يمكن التخلص من كل شيء بين بداية المخزن المؤقت و الرمز، ويجب نقل المقطع من الرمز وحتى الحد إلى بداية المخزن المؤقت، ويجب ملء المساحة الحرة في نهاية المخزن المؤقت ببيانات جديدة. لتجنب استدعاءات YYFILL المتكررة من الأفضل ملء أكبر عدد ممكن من أحرف الإدخال (حتى لو كانت أحرف أقل قد تكفي لاستئناف المحلل المعجمي). تفاصيل تنفيذ YYFILL تختلف قليلًا حسب طريقة التعامل مع EOF المستخدمة: حالة قاعدة EOF أبسط إلى حد ما من حالة فحص الحدود مع الحشو. لاحظ أيضًا أنه إذا استُخدم خيار -f --storable-state، فإن YYFILL له دلالات مختلفة قليلًا (موصوفة في القسم الخاص بالحالة القابلة للتخزين).

YYFILL مع الحارس

إذا استُخدمت قاعدة EOF، فإن YYFILL أساسي شبيه بالدالة لا يقبل وسائط ويعيد قيمة تُفحص مقابل الصفر. يُفعَّل استدعاء YYFILL بواسطة الشرط YYLIMIT <= YYCURSOR في API مؤشر C وYYLESSTHAN() في API العام. تعني القيمة المرجعة غير الصفرية أن YYFILL قد فشل. يجب أن يوفّر استدعاء YYFILL الناجح حرفًا واحدًا على الأقل ويضبط مواضع الإدخال وفقًا لذلك. يجب دائمًا ضبط الحد على واحد بعد آخر موضع إدخال في المخزن المؤقت، ويجب أن يكون الحرف عند موضع الحد هو رمز الحارس المحدد بواسطة إعداد re2c:eof. تُظهر الصور أدناه المواضع النسبية لمواضع الإدخال في المخزن المؤقت قبل وبعد استدعاء YYFILL (يُشار إلى رمز الحارس بـ #، وتُظهر الصورة الثانية الحالة التي لا يوجد فيها إدخال كافٍ لملء المخزن المؤقت بأكمله).

               <-- shift -->
             >-A------------B---------C-------------D#-----------E->
             buffer       token    marker         limit,
                                                  cursor
>-A------------B---------C-------------D------------E#->
             buffer,  marker        cursor        limit
             token
               <-- shift -->
             >-A------------B---------C-------------D#--E (EOF)
             buffer       token    marker         limit,
                                                  cursor
>-A------------B---------C-------------D---E#........
             buffer,  marker       cursor limit
             token

فيما يلي مثال لبرنامج يقرأ ملف الإدخال input.txt في أجزاء بحجم 4096 بايت ويستخدم قاعدة EOF.

// re2d $INPUT -o $OUTPUT
module main;
import core.stdc.string;
import core.stdc.stdio;
enum BUFSIZE = 4095;
struct Input {
    FILE* file;
    char[BUFSIZE + 1] buffer;// +1 for sentinel
    char* yylimit, yycursor, yymarker, token;
    bool eof;
};
private int fill(ref Input it) {
    if (it.eof) return 1;
    const size_t shift = it.token - it.buffer.ptr;
    const size_t used = it.yylimit - it.token;
    // Error: lexeme too long. In real life could reallocate a larger buffer.
    if (shift < 1) return 2;
    // Shift buffer contents (discard everything up to the current token).
    memmove(cast(void*)it.buffer.ptr, it.token, used);
    it.yylimit -= shift;
    it.yycursor -= shift;
    it.yymarker -= shift;
    it.token -= shift;
    // Fill free space at the end of buffer with new data from file.
    it.yylimit += fread(it.yylimit, 1, BUFSIZE - used, it.file);
    it.yylimit[0] = 0;
    it.eof = it.yylimit < (it.buffer.ptr + BUFSIZE);
    return 0;
}
private int lex(ref Input yyrecord) {
    int count = 0;
    for (;;) {
        yyrecord.token = yyrecord.yycursor;
    /*!re2c
        re2c:api = record;
        re2c:YYCTYPE = "char";
        re2c:YYFILL = "fill(yyrecord) == 0";
        re2c:eof = 0;
        str = ['] ([^'\\] | [\\][^])* ['];
        *    { return -1; }
        $    { return count; }
        str  { ++count; continue; }
        [ ]+ { continue; }
    */
    }
    assert(0);
}
void main() {
    const char[] fname = "input";
    const char[] content = "'qu\0tes' 'are' 'fine: \\'' ";
    // Prepare input file: a few times the size of the buffer, containing
    // strings with zeroes and escaped quotes.
    FILE* f = fopen(fname.ptr, "w");
    for (int i = 0; i < BUFSIZE; ++i) {
        fwrite(cast(const(void*)) content.ptr, 1, content.length - 1, f);
    }
    fclose(f);
    int count = 3 * BUFSIZE; // number of quoted strings written to file
    // Initialize lexer state: all pointers are at the end of buffer.
    Input it;
    it.file = fopen(fname.ptr, "r");
    it.yycursor = it.yymarker = it.token = it.yylimit = it.buffer.ptr + BUFSIZE;
    it.eof = 0;
    // Sentinel (at YYLIMIT pointer) is set to zero, which triggers YYFILL.
    it.yylimit[0] = 0;
    // Run the lexer.
    assert(lex(it) == count);
    // Cleanup: remove input file.
    fclose(it.file);
    remove(fname.ptr);
}

YYFILL مع الحشو

في الحالة الافتراضية (عندما لا تُستخدم قاعدة EOF) يكون YYFILL أساسيًا شبيهًا بالدالة يقبل وسيطًا واحدًا ولا يعيد أي قيمة. يُفعَّل استدعاء YYFILL بواسطة الشرط (YYLIMIT - YYCURSOR) < n في API مؤشر C وYYLESSTHAN(n) في API العام. الوسيط المُمرَّر إلى YYFILL هو الحد الأدنى لعدد الأحرف التي يجب توفيرها. إذا فشل في ذلك، فيجب ألا يعود YYFILL إلى المحلل المعجمي (ولهذا السبب من الأفضل تنفيذه كـ ماكرو يعود من الدالة المستدعية عند الفشل). في حالة استدعاء YYFILL الناجح يجب ضبط موضع الحد إما على واحد بعد آخر موضع إدخال في المخزن المؤقت، أو على نهاية حشو YYMAXFILL (في حالة أن YYFILL قد قرأ بنجاح n حرفًا على الأقل، لكن ليس بما يكفي لملء المخزن المؤقت بأكمله). تُظهر الصور أدناه المواضع النسبيةالمواقع النسبية لمواضع الإدخال في المخزن المؤقت قبل وبعد استدعاء YYFILL (حشو YYMAXFILL في الصورة الثانية مُعلَّم برموز #).

               <-- shift -->                 <-- need -->
             >-A------------B---------C-----D-------E---F--------G->
             buffer       token    marker cursor  limit
>-A------------B---------C-----D-------E---F--------G->
             buffer,  marker cursor               limit
             token
               <-- shift -->                 <-- need -->
             >-A------------B---------C-----D-------E-F        (EOF)
             buffer       token    marker cursor  limit
>-A------------B---------C-----D-------E-F###############
             buffer,  marker cursor                   limit
             token                        <- YYMAXFILL ->

فيما يلي مثال لبرنامج يقرأ ملف الإدخال input.txt على شكل أجزاء بحجم 4096 بايت ويستخدم التحقق من الحدود مع الحشو.

// re2d $INPUT -o $OUTPUT
module main;
import core.stdc.string;
import core.stdc.stdio;
/*!max:re2c*/
enum BufSize = (4096 - YYMaxFill);
struct Input {
    FILE* file;
    char[BufSize + YYMaxFill] buffer;
    char* yylimit, yycursor, token;
    bool eof;
};
private int fill(ref Input it, size_t need) {
    if (it.eof) return 1;
    const size_t shift = it.token - it.buffer.ptr;
    const size_t used = it.yylimit - it.token;
    // Error: lexeme too long. In real life could reallocate a larger buffer.
    if (shift < need) return 2;
    // Shift buffer contents (discard everything up to the current token).
    memmove(it.buffer.ptr, it.token, used);
    it.yylimit -= shift;
    it.yycursor -= shift;
    it.token -= shift;
    // Fill free space at the end of buffer with new data from file.
    it.yylimit += fread(it.yylimit, 1, BufSize - used, it.file);
    // If read less than expected, this is end of input => add zero padding
    // so that the lexer can access characters at the end of buffer.
    if (it.yylimit < it.buffer.ptr + BufSize) {
        it.eof = true;
        memset(it.yylimit, 0, YYMaxFill);
        it.yylimit += YYMaxFill;
    }
    return 0;
}
private int lex(ref Input yyrecord) {
    int count = 0;
    for (;;) {
        yyrecord.token = yyrecord.yycursor;
    /*!re2c
        re2c:api = record;
        re2c:YYCTYPE = "char";
        re2c:YYFILL = "if (fill(yyrecord, @@) != 0) return -1;";
        str = ['] ([^'\\] | [\\][^])* ['];
        [\x00] {
            // Check that it is the sentinel, not some unexpected null.
            return yyrecord.token == yyrecord.yylimit - YYMaxFill ? count : -1;
        }
        str  { ++count; continue; }
        [ ]+ { continue; }
        *    { return -1; }
    */
    }
    assert(0);
}
void main() {
    const char[] fname = "input";
    const char[] content = "'qu\0tes' 'are' 'fine: \\'' ";
    // Prepare input file: a few times the size of the buffer, containing
    // strings with zeroes and escaped quotes.
    FILE* f = fopen(fname.ptr, "w");
    for (int i = 0; i < BufSize; ++i) {
        fwrite(content.ptr, 1, content.length - 1, f);
    }
    fclose(f);
    int count = 3 * BufSize; // number of quoted strings written to file
    // Initialize lexer state: all pointers are at the end of buffer.
    // This immediately triggers YYFILL, as the check `it.yycursor < it.yylimit` fails.
    Input it;
    it.file = fopen(fname.ptr, "r");
    it.yycursor = it.token = it.yylimit = it.buffer.ptr + BufSize;
    it.eof = 0;
    // Run the lexer.
    assert(lex(it) == count);
    // Cleanup: remove input file.
    fclose(it.file);
    remove(fname.ptr);
}

كتل متعددة

أحيانًا يكون من الضروري وجود عدة مُحلِّلات معجمية مترابطة (على سبيل المثال، إذا كانت هناك آلة حالات عالية المستوى تنتقل بين أوضاع المُحلِّل المعجمي). يمكن تنفيذ ذلك باستخدام عدة كتل re2d متصلة. خيار آخر هو استخدام شروط البدء.

يعتمد تنفيذ الاتصالات بين الكتل على اللغة الهدف. في اللغات التي تحتوي على عبارة goto (مثل C/C++ وGo) يمكن أن تكون جميع الكتل في دالة واحدة، كل منها مسبوقة بتسمية. الانتقال من كتلة إلى أخرى هو مجرد goto بسيط. في اللغات التي لا تحتوي على goto (مثل Rust) من الضروري استخدام حلقة مع switch على متغير حالة، على غرار حلقة/switch yystate التي يولّدها re2d، أو تغليف كل كتلة في دالة واستخدام استدعاءات الدوال.

يستخدم المثال أدناه كتلًا متعددة لتحليل الأعداد الثنائية والثمانية والعشرية والست عشرية. لكل أساس كتلته الخاصة. تحدد الكتلة الأولية الأساس وتوزّع إلى الكتل الأخرى. يتم تعريف التكوينات المشتركة في كتلة منفصلة في بداية البرنامج؛ ويتم توريثها بواسطة الكتل الأخرى.

// re2d $INPUT -o $OUTPUT -i
module main;
enum ERROR = ulong.max;
private void add(ulong BASE)(ref ulong u, int d) {
    u = u * BASE + d;
    if (u > uint.max) { u = ERROR; }
}
private ulong parse_u32(const(char)* s) {
    const(char)* yycursor = s, yymarker;
    ulong u = 0;
    /*!re2c
        re2c:yyfill:enable = 0;
        re2c:YYCTYPE = char;
        end = "\x00";
        '0b' / [01]        { goto bin; }
        "0"                { goto oct; }
        "" / [1-9]         { goto dec; }
        '0x' / [0-9a-fA-F] { goto hex; }
        *                  { return ERROR; }
    */
bin:
    /*!re2c
        end   { return u; }
        [01]  { add!(2)(u, yycursor[-1] - '0'); goto bin; }
        *     { return ERROR; }
    */
oct:
    /*!re2c
        end   { return u; }
        [0-7] { add!(8)(u, yycursor[-1] - '0'); goto oct; }
        *     { return ERROR; }
    */
dec:
    /*!re2c
        end   { return u; }
        [0-9] { add!(10)(u, yycursor[-1] - '0'); goto dec; }
        *     { return ERROR; }
    */
hex:
    /*!re2c
        end   { return u; }
        [0-9] { add!(16)(u, yycursor[-1] - '0');      goto hex; }
        [a-f] { add!(16)(u, yycursor[-1] - 'a' + 10); goto hex; }
        [A-F] { add!(16)(u, yycursor[-1] - 'A' + 10); goto hex; }
        *     { return ERROR; }
    */
}
void main() {
    assert(parse_u32("") == ERROR);
    assert(parse_u32("1234567890") == 1234567890);
    assert(parse_u32("0b1101") == 13);
    assert(parse_u32("0x7Fe") == 2046);
    assert(parse_u32("0644") == 420);
    assert(parse_u32("9999999999") == ERROR);
}

شروط البدء

يتم تمكين شروط البدء باستخدام خيار --start-conditions. وهي توفر طريقة لتشفير عدة آلات ذاتية مترابطة داخل نفس كتلة re2d.

يتوافق كل شرط مع آلة ذاتية واحدة وله اسم فريد يحدده المستخدم ورقم داخلي فريد يحدده re2d. تُستخدم الأرقام للتبديل بين الشروط: يستخدم الكود المولَّد البدائيات YYGETCOND وYYSETCOND للحصول على الشرط الحالي أو تعيينه إلى الرقم المحدد. استخدم كتلة conditions أو خيار --header أو تكوين re2c:header لتوليد معرّفات الشروط الرقمية. يحدد التكوين re2c:cond:enumprefix بادئة المعرّف المولَّد.

في وضع الشروط يجب أن تكون كل قاعدة مسبوقة بقائمة من أسماء الشروط مفصولة بفواصل بين أقواس زاوية، أو بمحرف بدل <*> للدلالة على جميع الشروط. يتم توسيع صيغة القاعدة على النحو التالي:

< condition-list > regular-expression code
قاعدة يتم دمجها في كل شرط في condition-list. تطابق regular-expression وتنفذ code المرتبط بها.
< condition-list > regular-expression => condition code
قاعدة يتم دمجها في كل شرط في condition-list. تطابق regular-expression، وتضبط الشرط الحالي على condition وتنفذ code المرتبط بها.
< condition-list > regular-expression :=> condition
قاعدة يتم دمجها في كل شرط في condition-list. تطابق regular-expression وتنتقل فورًا إلى condition (لا يوجد إجراء دلالي).
< condition-list > !action code
قاعدة تربط code بالمكان المحدد بواسطة action في كل شرط في condition-list (انظر قسم الإجراءات لأنواع الإجراءات المختلفة).
<! condition-list > code
قاعدة تُضيف code في بداية الإجراءات الدلالية لجميع القواعد لكل شرط في condition-list. هذه الصيغة مهجورة ويجب استخدام إجراء !pre_rule بدلاً منها (فهو يفعل الشيء نفسه بالضبط).
< > code
قاعدة تنشئ شرط دخول خاصًا برقم صفر واسم "0" ينفذ code قبل الانتقال إلى الشروط الأخرى. هذه الصيغة مهجورة، ويجب استخدام إجراء !entry بدلاً منها (فهو يوفر تحكمًا أدق، حيث يمكن تحديد الكود على أساس كل شرط على حدة، ويمكن للمرء الانتقال مباشرة إلى بداية الشرط دون المرور عبر توزيع الشرط).
< > => condition code
مثل القاعدة السابقة، باستثناء أنها تضبط condition التالي.
< > :=> condition
مثل القاعدة السابقة، باستثناء أنها لا تحتوي على كود مرتبط وتنتقل فورًا إلى condition.

يعتمد الكود الذي يولّده re2d للشروط على ما إذا كان re2d يستخدم نهج goto/label أو نهج loop/switch لتشفير الآلات الذاتية.

في اللغات التي تحتوي على عبارة goto (مثل C/C++ وGo) يتم تنفيذ الشروط بشكل طبيعي ككتل من الكود مسبوقة بتسميات من الشكل yyc_<cond>، حيث cond هو اسم الشرط (يمكن تغيير بادئة التسمية باستخدام re2c:cond:prefix). يتم تنفيذ الانتقالات بين الشروط باستخدام goto وتسميات الشروط. قبل جميع الشروط يولّد re2d switch أوليًا على YYGETSTATE ينتقل إلى حالة البدء للشرط الحالي. تتجاوز قواعد الاختصار :=> الـ switch الأولي وتنتقل مباشرة إلى الشرط المحدد (يمكن استخدام re2c:cond:goto لتغيير السلوك الافتراضي). القواعد ذات الإجراءات الدلالية لا تنتقل تلقائيًا إلى الشرط التالي؛ يجب أن يتم ذلك بواسطة كود الإجراء المحدد من قبل المستخدم.

في اللغات التي لا تحتوي على goto (مثل Rust) يعيد re2d استخدام متغير yystate لتخزين أرقام الشروط. يحصل كل شرط على معرّف رقمي يساوي رقم حالة بدئه، والتبديل بين الشروط لا يختلف عن التبديل بين حالات DFA لـ siشرط ngle. ليست هناك حاجة لمفتاح شرط أولي منفصل. (نظرًا لأن النهج نفسه يُستخدم لتنفيذ الحالات القابلة للتخزين، فإن YYGETCOND/YYSETCOND زائدان عن الحاجة إذا تم استخدام كل من الحالات القابلة للتخزين والشروط).

يستخدم البرنامج أدناه شروط البدء لتحليل الأعداد الثنائية والثمانية والعشرية والسداسية عشرية. هناك كتلة واحدة حيث لكل أساس شرطه الخاص، والشرط الأولي متصل بجميعها. المتغير المعرّف من قبل المستخدم cond يخزّن رقم الشرط الحالي؛ تتم تهيئته إلى رقم الشرط الأولي المُولّد باستخدام كتلة conditions.

// re2d $INPUT -o $OUTPUT -ci
module main;
enum ERROR = ulong.max;
/*!conditions:re2c*/
private void add(ulong BASE)(ref ulong u, int d) {
    u = u * BASE + d;
    if (u > uint.max) { u = ERROR; }
}
private ulong parse_u32(const(char)* s) {
    const(char)* yycursor = s, yymarker;
    YYCond yycond = YYCond.yycinit;
    ulong u = 0;
    /*!re2c
        re2c:yyfill:enable = 0;
        re2c:YYCTYPE = char;
        <*> * { return ERROR; }
        <init> '0b' / [01]        :=> bin
        <init> "0"                :=> oct
        <init> "" / [1-9]         :=> dec
        <init> '0x' / [0-9a-fA-F] :=> hex
        <bin, oct, dec, hex> "\x00" { return u; }
        <bin> [01]  { add!(2)(u,  yycursor[-1] - '0');      goto yyc_bin; }
        <oct> [0-7] { add!(8)(u,  yycursor[-1] - '0');      goto yyc_oct; }
        <dec> [0-9] { add!(10)(u, yycursor[-1] - '0');      goto yyc_dec; }
        <hex> [0-9] { add!(16)(u, yycursor[-1] - '0');      goto yyc_hex; }
        <hex> [a-f] { add!(16)(u, yycursor[-1] - 'a' + 10); goto yyc_hex; }
        <hex> [A-F] { add!(16)(u, yycursor[-1] - 'A' + 10); goto yyc_hex; }
    */
}
void main() {
    assert(parse_u32("") == ERROR);
    assert(parse_u32("1234567890") == 1234567890);
    assert(parse_u32("0b1101") == 13);
    assert(parse_u32("0x7Fe") == 2046);
    assert(parse_u32("0644") == 420);
    assert(parse_u32("9999999999") == ERROR);
}

الحالة القابلة للتخزين

مع خيار --storable-state يولّد re2d مُحلّلًا معجميًا يمكنه تخزين حالته الحالية، والعودة إلى المستدعي، ثم استئناف العمليات لاحقًا من حيث توقف تمامًا. وضع التشغيل الافتراضي في re2d هو نموذج "السحب"، حيث "يسحب" المُحلّل المعجمي المزيد من المدخلات كلما احتاج إليها. قد يكون هذا غير مقبول في الحالات التي تصبح فيها المدخلات متاحة قطعة تلو الأخرى (على سبيل المثال، إذا استُدعي المُحلّل المعجمي من قبل المُحلّل النحوي، أو إذا كان برنامج المُحلّل المعجمي يتواصل عبر بروتوكول مقبس مع برنامج آخر يجب أن ينتظر ردًا من المُحلّل المعجمي قبل أن يرسل الرسالة التالية). ميزة الحالة القابلة للتخزين مخصصة بالضبط لمثل هذه الحالات: فهي تتيح توليد مُحلّلات معجمية تعمل في نموذج "الدفع". عندما يحتاج المُحلّل المعجمي إلى المزيد من المدخلات، فإنه يخزّن حالته ويعود إلى المستدعي. لاحقًا، عندما تصبح المزيد من المدخلات متاحة، يستأنف المستدعي المُحلّل المعجمي من حيث توقف تمامًا. هناك بعض التغييرات الضرورية مقارنة بنموذج "السحب":

  • عرّف البدائيات YYSETSTATE() وYYGETSTATE(state).
  • عرّف المتغيرات yych وyyaccept (إذا استُخدم) وstate كجزء من حالة المُحلّل المعجمي الدائمة. يجب تهيئة المتغير state إلى -1.
  • يجب أن تعود YYFILL إلى البرنامج الخارجي بدلًا من محاولة توفير المزيد من المدخلات. يجب أن يشير رمز الإرجاع إلى أن المُحلّل المعجمي يحتاج إلى المزيد من المدخلات.
  • يجب أن يتعرف البرنامج الخارجي على الحالات التي يحتاج فيها المُحلّل المعجمي إلى المزيد من المدخلات ويستجيب بشكل مناسب.
  • استخدم اختياريًا كتلة getstate لتوليد مفتاح YYGETSTATE منفصل عن المُحلّل المعجمي الرئيسي. هذا يعمل فقط للغات التي تحتوي على goto (وليس في وضع --loop-switch).
  • استخدم re2c:eof وطريقة الحارس مع فحوصات الحدود للتعامل مع نهاية المدخلات. قد لا تعمل الطريقة القائمة على الحشو لأنها غير واضحة متى يجب إلحاق الحشو: قد لا تكون نهاية المدخلات الحالية هي النهاية النهائية للمدخلات، وإلحاق الحشو مبكرًا جدًا قد يقطع معجمًا جشعًا مقروءًا جزئيًا. علاوة على ذلك، نظرًا لمنطق البرنامج عالي المستوى، قد يعتمد الحصول على المزيد من المدخلات على معالجة المعجم في نهاية المخزن المؤقت (والذي يكون محظورًا بالفعل بسبب حالة نهاية المدخلات).

إليك مثال على مُحلّل معجمي بنموذج "الدفع" يحاكي قراءة الحزم من مقبس. يتكرر المُحلّل المعجمي حتى يواجه نهاية المدخلات ويعود إلى الدالة المستدعية. توفر الدالة المستدعية المزيد من المدخلات عن طريق "إرسال" الحزمة التالية وتستأنف التحليل المعجمي. تتوقف هذه العملية عندما يتم إرسال جميع الحزم، أو عند حدوث خطأ.

// re2d $INPUT -o $OUTPUT -f
module main;
import core.stdc.stdio;
import core.stdc.string;
// Use a small buffer to cover the case when a lexeme doesn't fit.
// In real world use a larger buffer.
enum BUFSIZE = 10;
struct State {
    FILE* file;
    char[BUFSIZE + 1] buffer;
    char* yylimit, yycursor, yymarker, token;
    int yystate;
};
enum Status {END, READY, WAITING, BAD_PACKET, BIG_PACKET};
private Status fill(ref State st) {
    const size_t shift = st.token - cast(char*)st.buffer;
    const size_t used = st.yylimit - st.token;
    const size_t free = BUFSIZE - used;
    // Error: no space. In real life can reallocate a larger buffer.
    if (free < 1) return Status.BIG_PACKET;
    // Shift buffer contents (discard already processed data).
    memmove(cast(void*)st.buffer, st.token, used);
    st.yylimit -= shift;
    st.yycursor -= shift;
    st.yymarker -= shift;
    st.token -= shift;
    // Fill free space at the end of buffer with new data.
    const size_t read = fread(st.yylimit, 1, free, st.file);
    st.yylimit += read;
    st.yylimit[0] = 0; // append sentinel symbol
    return Status.READY;
}
private Status lex(ref State yyrecord, uint* recv) {
    char yych;
    /*!getstate:re2c*/
    for (;;) {
        yyrecord.token = yyrecord.yycursor;
    /*!re2c
        re2c:api = record;
        re2c:YYCTYPE = char;
        re2c:YYFILL = "return Status.WAITING;";
        re2c:eof = 0;
        packet = [a-z]+[;];
        *      { return Status.BAD_PACKET; }
        $      { return Status.END; }
        packet { *recv = *recv + 1; continue; }
    */
    }
    assert(0); // unreachable
}
private void test(string[] packets, Status expect) {
    // Create a pipe (open the same file for reading and writing).
    const(char*) fname = "pipe";
    FILE* fw = fopen(fname, "w");
    FILE* fr = fopen(fname, "r");
    setvbuf(fw, null, _IONBF, 0);
    setvbuf(fr, null, _IONBF, 0);
    // Initialize lexer state: `state` value is -1, all pointers are at the end
    // of buffer.
    State st;
    st.file = fr;
    st.yycursor = st.yymarker = st.token = st.yylimit = cast(char*)st.buffer + BUFSIZE;
    // Sentinel (at YYLIMIT pointer) is set to zero, which triggers YYFILL.
    st.yylimit[0] = 0;
    st.yystate = -1;
    // Main loop. The buffer contains incomplete data which appears packet by
    // packet. When the lexer needs more input it saves its internal state and
    // returns to the caller which should provide more input and resume lexing.
    Status status;
    uint send = 0, recv = 0;
    for (;;) {
        status = lex(st, &recv);
        if (status == Status.END) {
            debug{printf("done: got %u packets\n", recv);}
            break;
        } else if (status == Status.WAITING) {
            debug{printf("waiting...\n");}
            if (send < packets.length) {
                debug{printf("sent packet %u\n", send);}
                fprintf(fw, "%s", cast(char*)packets[send]);
                ++send;
            }
            status = fill(st);
            debug{printf("queue: '%s'\n", cast(char*)st.buffer);}
            if (status == Status.BIG_PACKET) {
                debug{printf("error: packet too big\n");}
                break;
            }
            assert(status == Status.READY);
        } else {
            assert(status == Status.BAD_PACKET);
            debug{printf("error: ill-formed packet\n");}
            break;
        }
    }
    // Check results.
    assert(status == expect);
    if (status == Status.END) assert(recv == send);
    // Cleanup: remove input file.
    fclose(fw);
    fclose(fr);
    remove(fname);
}
void main() {
    string[] packets1 = [];
    string[] packets2 = ["zero;", "one;", "two;", "three;", "four;"];
    string[] packets3 = ["zer0;"];
    string[] packets4 = ["looooooooooong;"];
    test(packets1, Status.END);
    test(packets2, Status.END);
    test(packets3, Status.BAD_PACKET);
    test(packets4, Status.BIG_PACKET);
}

الكتل القابلة لإعادة الاستخدام

الكتل القابلة لإعادة الاستخدام من الشكل /*!rules:re2c[:<name>] ... */ أو %{rules[:<name>] ... %} يمكن إعادة استخدامها أي عدد من المرات ودمجها مع كتل re2d الأخرى. <name> اختياري. يمكن استخدام كتلة قواعد في كتلة use أو توجيه. يتم توليد الكود الخاص بكتلة القواعد في كل نقطة استخدام.

تُعرّف كتل الاستخدام بـ /*!use:re2c[:<name>] ... */ أو %{use[:<name>] ... %}. <name> اختياري: إذا لم يُحدد، فإن كتلة القواعد المرتبطة هي الأحدث (سواء كانت مسماة أو غير مسماة). يمكن لكتلة الاستخدام إضافة تعريفات وإعدادات وقواعد خاصة بها. حالة استخدام مهمة لكتل الاستخدام هي المُحلّل المعجمي الذي يدعم ترميزات إدخال متعددة: تُعاد استخدام كتلة القواعد نفسها عدة مرات مع إعدادات خاصة بالترميز (انظر المثال أدناه).

يمكن استخدام توجيه الاستخدام داخل الكتلة !use:<name>; من داخل كتلة re2d. فهو يدمج الكتلة المشار إليها <name> في الكتلة الحالية. إذا تداخلت بعض القواعد والإعدادات المدمجة مع تلك المعرفة سابقًا، يتم حل التعارضات بالطريقة المعتادة: القاعدة الأسبق لها الأولوية، وأحدث إعداد يتجاوز الإعدادات السابقة. استثناء واحد هو القواعد الخاصة * و$ و(في وضع الشرط) <!>، حيث يتجاوز التعريف المحلي للكتلة أي تعريفات موروثة. يسمح توجيه الاستخدام بدمج كتل re2d المختلفة معًا في كتلة واحدة (انظر المثال أدناه).

أُضيفت الكتل المسماة وتوجيه الاستخدام داخل الكتلة في إصدار re2d 2.2. منذ ذلك الإصدار، تُسمح الكتل القابلة لإعادة الاستخدام افتراضيًا (لا حاجة لخيار خاص). قبل الإصدار 2.2 كان وضع إعادة الاستخدام ممكّنًا بخيار -r --reusable. قبل الإصدار 1.2 لم يكن من الممكن خلط الكتل القابلة لإعادة الاستخدام مع الكتل العادية.

مثال على توجيه !use

// re2d $INPUT -o $OUTPUT
module main;
// This example shows how to combine reusable re2c blocks: two blocks
// ('colors' and 'fish') are merged into one. The 'salmon' rule occurs
// in both blocks; the 'fish' block takes priority because it is used
// earlier. القاعدة الافتراضية * تظهر في الكتل الثلاث جميعها؛ التعريف المحلي (غير
// الموروث) له الأولوية.
enum What { COLOR, FISH, DUNNO };
/*!rules:re2c:colors
    *                            { assert(false); }
    "red" | "salmon" | "magenta" { return What.COLOR; }
*/
/*!rules:re2c:fish
    *                            { assert(false); }
    "haddock" | "salmon" | "eel" { return What.FISH; }
*/
private What lex(const(char)* s) {
    const(char)* yycursor = s, yymarker;
    /*!re2c
        re2c:YYCTYPE = "char";
        re2c:yyfill:enable = 0;
        !use:fish;
        !use:colors;
        * { return What.DUNNO; } // يتجاوز قواعد '*' الموروثة
    */
}
void main() {
    assert(lex("salmon") == What.FISH);
    assert(lex("what?") == What.DUNNO);
}

// re2d $INPUT -o $OUTPUT --input-encoding utf8
module main;
import std.stdint;
// يدعم هذا المثال ترميزات إدخال متعددة: UTF-8 وUTF-32.
// يتم توليد كلا المحللين المعجميين من كتلة القواعد نفسها، وكتل use
// تضيف فقط إعدادات خاصة بالترميز.
/*!rules:re2c
    re2c:yyfill:enable = 0;
    "∀x ∃y" { return 0; }
    *       { return 1; }
*/
private int lex_utf8(const(uint8_t)* s) {
    const(uint8_t)* yycursor = s, yymarker;
    /*!use:re2c
        re2c:YYCTYPE = uint8_t;
        re2c:encoding:utf8 = 1;
    */
}

    const(uint32_t)* yycursor = s, yymarker;
    /*!use:re2c
        re2c:YYCTYPE = uint32_t;

    */
}

    immutable uint8_t[] s8 = // UTF-8
        [ 0xe2, 0x88, 0x80, 0x78, 0x20, 0xe2, 0x88, 0x83, 0x79 ];

}

استخراج المطابقات الفرعية

لدى re2d خياران لاستخراج المطابقات الفرعية.

الوسوم
الخيار الأول هو استخدام وسوم مستقلة بالصيغة @stag أو #mtag، حيث stag وmtag أسماء عشوائية يحددها المستخدم. يتم تمكين الوسوم باستخدام خيار -T --tags أو إعداد re2c:tags = 1. دلالياً، الوسوم هي علامات موضع: يمكن إدراجها في أي مكان في تعبير نمطي، وهي ترتبط بالموضع المقابل (أو المواضع المتعددة) في سلسلة الإدخال. ترتبط وسوم s بآخر موضع مطابق، و ترتبط وسوم m بقائمة من المواضع (قد تُستخدم في تعبيرات فرعية متكررة، حيث يقابل موضع واحد في تعبير نمطي مواضع متعددة في سلسلة الإدخال). يجب أن تُعرَّف جميع الوسوم من قبل المستخدم، إما يدوياً أو بمساعدة كتلتي svars و mvars. إذا كانت هناك أكثر من طريقة واحدة يمكن بها مطابقة الوسوم مقابل الإدخال، يُحل الغموض باستخدام استراتيجية إزالة الغموض الجشعة من اليسار.
المجموعات الملتقطة
الخيار الثاني هو استخدام المجموعات الملتقطة. يتم تمكينها باستخدام خيار --captures أو إعداد re2c:captures = 1. هناك نوعان لسياسات إزالة الغموض المختلفة، --leftmost-captures (الافتراضي) لسياسة الجشع من اليسار، و--posix-captures لسياسة POSIX لأطول تطابق. في هذا الوضع تُعتبر جميع التعبيرات الفرعية المحاطة بأقواس مجموعات ملتقطة، و يمكن استخدام علامة التعجب لتمييز المجموعات غير الملتقطة: (! ... ). مع خيار --invert-captures أو إعداد re2c:invert-captures = 1 يُعكس معنى علامة التعجب. يُخزَّن عدد المجموعات للقاعدة المطابقة في متغير yynmatch (التعبير النمطي بأكمله هو المجموعة رقم صفر)، وتُخزَّن نتائج المطابقات الفرعية في مصفوفة yypmatch. يجب أن يُعرَّف كل من yynmatch وyypmatch من قبل المستخدم، ويجب أن يكون حجم yypmatch على الأقل [yynmatch * 2]. استخدم كتلة maxnmatch لتعريف YYMAXNMATCH، وهو ثابت يساوي القيمة العظمى لـ yynmatch بين جميع القواعد.
متغيرات الالتقاط
طريقة أخرى لاستخدام المجموعات الملتقطة هي خيار --captvars أو إعداد re2c:captvars = 1. الفرق الوحيد مع --captures هو في طريقة تخزين الكود المولَّد لنتائج المطابقات الفرعية: بدلاً من yynmatch وyypmatch يولِّد re2d المتغيرين yytl<k> وyytr<k> للمجموعة الملتقطة رقم k (يجب على المستخدم تعريف هذه باستخدام كتلة svars). تدعم عمليات الالتقاط بالمتغيرات سياستين لإزالة الغموض: --leftmost-captvars أو re2c:leftmost-captvars = 1 لسياسة الجشع من اليسار (الافتراضية) و--posix-captvars أو re2c:posix-captvars لسياسة POSIX لأطول تطابق.

تحت الغطاء، تترجم كل هذه الخيارات إلى وسوم وأتمتة محدودة حتمية موسومة مع نظرة استباقية (TDFA). الفكرة الأساسية لـ TDFA هي تقليل الحمل الزائد على استخراج المطابقات الفرعية. في الحالات القصوى، إذا لم تكن هناك وسوم أو مجموعات ملتقطة في تعبير نمطي، فإن TDFA هو مجرد DFA عادي. إذا كان عدد الوسوم معتدلاً، يكون الحمل الزائد بالكاد ملحوظاً. يستخدم TDFA المولَّد عدداً من متغيرات الوسوم التي لا تُقابل الوسوم مباشرة: قد يُستخدم متغير واحد لوسوم مختلفة، وقد يتطلب الوسم متغيرات متعددة لحمل جميع قيمه الممكنة. في النهاية يُحل الغموض، ولا يبقى سوى متغير نهائي واحد لكل وسم. يجب تعريف متغيرات الوسوم باستخدام كتلتي stags أو mtags. إذا كانت حالة المحلل المعجمي مخزَّنة، فيجب أن تكون متغيرات الوسوم جزءاً منها. كما تحتاج إلى التحديث بواسطة YYFILL.

تدعم وسوم s العمليات التالية:

  • حفظ موضع الإدخال في وسم s: t = YYCURSOR مع واجهة برمجة تطبيقات مؤشر C أو عملية يحددها المستخدم YYSTAGP(t) مع واجهة برمجة تطبيقات عامة
  • حفظ القيمة الافتراضية في وسم s: t = NULL مع واجهة برمجة تطبيقات مؤشر C أو عملية يحددها المستخدم YYSTAGN(t) مع واجهة برمجة تطبيقات عامة
  • نسخ وسم s إلى آخر: t1 = t2

تدعم وسوم m العمليات التالية:

  • إلحاق موضع الإدخال بوسم m: عملية يحددها المستخدم YYMTAGP(t) مع كل من واجهة برمجة التطبيقات الافتراضية والعامة
  • إلحاق القيمة الافتراضية بوسم m: عملية يحددها المستخدم YYMTAGN(t) مع كل من واجهة برمجة التطبيقات الافتراضية والعامة
  • نسخ وسم m إلى آخر: t1 = t2

يمكن تنفيذ وسوم s كقيم قياسية (مؤشرات أو إزاحات). تحتاج وسوم m إلى تمثيل أكثر تعقيداً، لأنها تحتاج إلى تخزين تسلسل من قيم الوسوم. التمثيل الأكثر سذاجة وغير كفؤ لوسم m هو قائمة (مصفوفة، متجه) من قيم الوسوم؛ التمثيل الأكثر كفاءة هو تخزين جميع وسوم m في شجرة بادئة ممثلة كمصفوفة من العقد (v, p)، حيث v هي قيمة الوسم وp مؤشر إلى العقدة الأصلية.

إليك مثالاً بسيطاً على استخدام وسوم s لتحليل الإصدارات الدلالية المكونة من ثلاثة مكونات رقمية: رئيسي، ثانوي، تصحيحي (الأخير اختياري). انظر أدناه للحصول على مثال أكثر تعقيداً يستخدم YYFILL.

// re2d $INPUT -o $OUTPUT
module main;
struct SemVer {
    int major;
    int minor;
    int patch;
};
private int s2n(const(char)* s, const(char)* e) { // سلسلة محللة مسبقاً إلى رقم
    int n = 0;
    for (; s < e; ++s) n = n * 10 + (*s - '0');
    return n;
}
private bool lex(const(char)* str, ref SemVer ver) {
    const(char)* yycursor = str, yymarker;
    // متغيرات الوسوم النهائية المتاحة في الإجراء الدلالي.
    /*!svars:re2c format = 'const(char)* @@;\n'; */
    // متغيرات الوسوم الوسيطة المستخدمة من قبل المحلل المعجمي (يجب أن تُولَّد تلقائياً).
    /*!stags:re2c format = 'const(char)* @@;\n'; */
    /*!re2c
        re2c:yyfill:enable = 0;
        re2c:tags = 1;
        re2c:YYCTYPE = "char";
        num = [0-9]+;
        @t1 num @t2 "." @t3 num @t4 ("." @t5 num)? [\x00] {
            ver.major = s2n(t1, t2);
            ver.minor = s2n(t3, t4);
            ver.patch = t5 != null ? s2n(t5, yycursor - 1) : 0;
            return true;
        }
        * { return false; }
    */
}
void main() {
    SemVer v;
    assert(lex("23.34", v) && v.major == 23 && v.minor == 34 && v.patch == 0);
    assert(lex("1.2.999", v) && v.major == 1 && v.minor == 2 && v.patch == 999);
    assert(!lex("1.a", v));
}

إليك مثالاً أكثر تعقيداً على استخدام وسوم s مع YYFILL لتحليل ملف يحتوي على إصدارات دلالية مفصولة بأسطر جديدة. متغيرات الوسوم جزء من حالة المحلل المعجمي، ويتم تعديلها في YYFILL مثل مواضع الإدخال الأخرى. لاحظ أن هذا ضروري لوسوم s لأن قيمها تصبح غير صالحة بعد إزاحة محتويات المخزن المؤقت. قد لا يكون ذلك ضرورياً في تنفيذ مخصص حيث تخزن متغيرات الوسوم إزاحات نسبية إلى بداية سلسلة الإدخال بدلاً من المخزن المؤقت، وهو ما قد يكون الحال مع وسوم m.

// re2d $INPUT -o $OUTPUT --tags
module main;
import core.stdc.string;
import core.stdc.stdio;
import std.stdio;
enum BUFSIZE = 4095;
struct Input {
    FILE* file;
    char[BUFSIZE + 1] buffer;// +1 للحارس
    char* yylimit, yycursor, yymarker, token;
    // يجب أن تكون متغيرات الوسوم الوسيطة جزءاً من حالة المحلل المعجمي المرر إلى YYFILL.
    // لا تُقابل الوسوم ويجب أن تُولَّد تلقائياً بواسطة re2c.
    /*!stags:re2c format = 'char* @@;'; */
    bool eof;
};
struct SemVer {
    int major;
    int minor;
    int patch;
};
private int s2n(const(char)* s, const(char)* e) { // سلسلة محللة مسبقاً إلى رقم
    int n = 0;
    for (; s < e; ++s) n = n * 10 + (*s - '0');
    return n;
}
private int fill(ref Input it) {
    if (it.eof) return 1;
    const size_t shift = it.token - it.buffer.ptr;
    const size_t used = it.yylimit - it.token;
    // خطأ: الوحدة المعجمية طويلة جداً. في الحياة الواقعية يمكن إعادة تخصيص مخزن مؤقت أكبر.
    if (shift < 1) return 2;
    // إزاحة محتويات المخزن المؤقت (تجاهل كل شيء حتى الوحدة المعجمية الحالية).
    memmove(cast(void*)it.buffer.ptr, it.token, used);
    it.yylimit -= shift;
    it.yycursor -= shift;
    it.yymarker -= shift;
    it.token -= shift;
    // يجب إزاحة متغيرات الوسوم مثل مواضع الإدخال الأخرى. التحقق
    // من عدم كونها null مطلوب فقط إذا كانت بعض الوسوم متداخلة داخل بديل
    // أو تكرار، بحيث يمكن أن تكون قيمتها null.
    /*!stags:re2c format = "if (it.@@) it.@@ -= shift;\n"; */
    // ملء المساحة الحرة في نهاية المخزن المؤقت ببيانات جديدة من الملف.
    it.yylimit += fread(it.yylimit, 1, BUFSIZE - used, it.file);
    it.yylimit[0] = 0;
    it.eof = it.yylimit < (it.buffer.ptr + BUFSIZE);
    return 0;
}
private bool lex(ref Input yyrecord, ref SemVer[] vers) {
    // المتغيرات النهائية المتاحة في الإجراءات الدلالية.
    /*!svars:re2c format = 'char* @@;'; */
    for (;;) {
        yyrecord.token = yyrecord.yycursor;
    /*!re2c
        re2c:api = record;
        re2c:YYCTYPE = "char";
        re2c:YYFILL = "fill(yyrecord) == 0";
        re2c:eof = 0;
        num = [0-9]+;
        num @t1 "." @t2 num @t3 ("." @t4 num)? [\n] {
            int major = s2n(yyrecord.token, t1);
            int minor = s2n(t2, t3);
            int patch = t4 != null ? s2n(t4, yyrecord.yycursor - 1) : 0;
            SemVer ver = SemVer(major, minor, patch);
            vers ~= ver;
            continue;
        }
        $ { return true; }
        * { return false; }
    */
    }
    assert(0);
}
void main() {
    const char[] fname = "input";
    const char[] content = "1.22.333\n' ";
    SemVer[BUFSIZE] expect = SemVer(1, 22, 333);
    SemVer[] actual;
    // Prepare input file: a few times the size of the buffer, containing
    // strings with zeroes and escaped quotes.
    FILE* f = fopen(fname.ptr, "w");
    for (int i = 0; i < BUFSIZE; ++i) {
        fwrite(cast(const(void*)) content.ptr, 1, content.length - 2, f); // skip null-terminator
    }
    fclose(f);
    // Initialize lexer state: all pointers are at the end of buffer.
    Input it;
    it.file = fopen(fname.ptr, "r");
    it.yycursor = it.yymarker = it.token = it.yylimit = it.buffer.ptr + BUFSIZE;
    it.eof = 0;
    // Sentinel (at YYLIMIT pointer) is set to zero, which triggers YYFILL.
    it.yylimit[0] = 0;
    // Run the lexer.
    assert(lex(it, actual) && actual == expect);
    // Cleanup: remove input file.
    fclose(it.file);
    remove(fname.ptr);
}

// re2d $INPUT -o $OUTPUT
module main;
struct SemVer { int major, minor, patch; };
private int s2n(const(char)* s, const(char)* e) { // pre-parsed string to number
    int n = 0;
    for (; s < e; ++s) n = n * 10 + (*s - '0');
    return n;
}

    const(char)* yycursor = str, yymarker;
    // Final tag variables available in semantic action.
    /*!svars:re2c format = 'const(char)* @@;\n'; */
    // Intermediate tag variables used by the lexer (must be autogenerated).
    /*!stags:re2c format = 'const(char)* @@;\n'; */
    /*!re2c
        re2c:yyfill:enable = 0;
        re2c:captvars = 1;
        re2c:YYCTYPE = "char";
        num = [0-9]+;

            ver.major = s2n(yytl1, yytr1);

فيما يلي مثال على استخدام وسوم m لتحليل إصدار بعدد متغير من المكونات. يتم تخزين متغيرات الوسم في شجرة ثلاثية (trie).

// re2d $INPUT -o $OUTPUT
module main;
enum MtagRoot = -1;
// An m-tag tree is a way to store histories with an O(1) copy operation.
// Histories naturally form a tree, as they have common start and fork at some
// point. The tree is stored as an array of pairs (tag value, link to parent).
// An m-tag is represented with a single link in the tree (array index).
struct Mtag {
    const(char)* elem; // tag value
    int pred; // index of the predecessor node or root
};
alias MtagTrie = Mtag[];
alias Ver = int[];
private int s2n(const(char)* s, const(char)* e) { // pre-parsed string to number
    int n = 0;
    for (; s < e; ++s) n = n * 10 + (*s - '0');
    return n;
}
// Append a single value to an m-tag history.
private void add_mtag(ref MtagTrie trie, ref int mtag, const(char)* value) {
    Mtag m = {value, mtag};
    mtag = cast(int)trie.length;
    trie ~= [m];
}
// Recursively unwind tag histories and collect version components.
private void unfold(const ref MtagTrie trie, int x, int y, ref Ver ver) {
    // Reached the root of the m-tag tree, stop recursion.
    if (x == MtagRoot && y == MtagRoot) return;
    // Unwind history further.
    unfold(trie, trie[x].pred, trie[y].pred, ver);
    // Get tag values. Tag histories must have equal length.
    assert(x != MtagRoot && y != MtagRoot);
    const(char)* ex = trie[x].elem, ey = trie[y].elem;
    if (ex != null && ey != null) {
        // Both tags are valid pointers, extract component.
        ver ~= [s2n(ex, ey)];
    } else {
        // Both tags are null (this corresponds to zero repetitions).
        assert(ex == null && ey == null);
    }
}
private bool parse(const(char)* str, ref Ver ver) {
    const(char)* yycursor = str, yymarker;
    MtagTrie mt;
    // Final tag variables available in semantic action.
    /*!svars:re2c format = "const(char)* @@;"; */
    /*!mvars:re2c format = "int @@;"; */
    // Intermediate tag variables used by the lexer (must be autogenerated).
    /*!stags:re2c format = "const(char)* @@ = null;"; */
    /*!mtags:re2c format = "int @@ = MtagRoot;"; */
    /*!re2c
        re2c:yyfill:enable = 0;
        re2c:tags = 1;
        re2c:YYCTYPE = "char";
        re2c:YYMTAGP = "add_mtag(mt, @@, yycursor);";
        re2c:YYMTAGN = "add_mtag(mt, @@, null);";
        num = [0-9]+;
        @t1 num @t2 ("." #t3 num #t4)* [\x00] {
            ver = [];
            ver ~= [s2n(t1, t2)];
            unfold(mt, t3, t4, ver);
            return true;
        }
        * { return false; }
    */
}
void main() {
    Ver v;
    assert(parse("1", v) && v == [1]);
    assert(parse("1.2.3.4.5.6.7", v) && v == [1, 2, 3, 4, 5, 6, 7]);
    assert(!parse("1.2.", v));
}

دعم الترميز

من الضروري فهم الفرق بين نقاط الترميز ووحدات الترميز. نقطة الترميز هي معرّف رقمي لرمز. وحدة الترميز هي أصغر وحدة تخزين في النص المُرمّز. قد يتم تمثيل نقطة ترميز واحدة بوحدة ترميز واحدة أو أكثر. في الترميز ثابت الطول يتم تمثيل جميع نقاط الترميز بنفس عدد وحدات الترميز. في الترميز متغير الطول قد يتم تمثيل نقاط الترميز بعدد مختلف من وحدات الترميز. لاحظ أن قاعدة "أي" [^] تطابق أي نقطة ترميز، ولكن ليس بالضرورة أي وحدة ترميز (الطريقة الوحيدة لمطابقة أي وحدة ترميز بغض النظر عن الترميز هي القاعدة الافتراضية *). يعمل المُحلّل المعجمي المُولّد مع تدفق من وحدات الترميز: yych يخزّن وحدة ترميز، وYYCTYPE هو نوع وحدة الترميز. من ناحية أخرى، يتم تحديد التعبيرات النمطية من حيث نقاط الترميز. عندما يقوم re2d بترجمة التعبيرات النمطية إلى أتمتة، فإنه يترجم نقاط الترميز إلى وحدات ترميز. هذا بشكل عام ليس تعيينًا بسيطًا: في الترميزات متغيرة الطول قد يتم ترجمة نطاق نقطة ترميز واحدة إلى رسم بياني معقد لوحدات الترميز. يتم دعم الترميزات التالية:

  • ASCII (مُمكّن افتراضيًا). إنه ترميز ثابت الطول بمساحة ترميز [0-255] ونقاط ترميز ووحدات ترميز بحجم 1 بايت.
  • EBCDIC (مُمكّن باستخدام --ebcdic أو re2c:encoding:ebcdic). إنه ترميز ثابت الطول بمساحة ترميز [0-255] ونقاط ترميز ووحدات ترميز بحجم 1 بايت.
  • UCS2 (مُمكّن باستخدام --ucs2 أو re2c:encoding:ucs2). إنه ترميز ثابت الطول بمساحة ترميز [0-0xFFFF] ونقاط ترميز ووحدات ترميز بحجم 2 بايت.
  • UTF8 (مُمكّن باستخدام --utf8 أو re2c:encoding:utf8). إنه ترميز يونيكود متغير الطول. حجم وحدة الترميز هو 1 بايت. يتم تمثيل نقاط الترميز بـ 1 -- 4 وحدات ترميز.
  • UTF16 (مُمكّن باستخدام --utf16 أو re2c:encoding:utf16). إنه ترميز يونيكود متغير الطول. حجم وحدة الترميز هو 2 بايت. يتم تمثيل نقاط الترميز بـ 1 -- 2 وحدات ترميز.
  • UTF32 (مُمكّن باستخدام --utf32 أو re2c:encoding:utf32). إنه ترميز يونيكود ثابت الطول بمساحة ترميز [0-0x10FFFF] ونقاط ترميز ووحدات ترميز بحجم 4 بايت.

ملف التضمين include/unicode_categories.re يوفر تعريفات re2d لفئات يونيكود القياسية.

الخيار --input-encoding يحدد ترميز الملف المصدر، والذي يمكن استخدامه لتمكين الحروف الحرفية ليونيكود في التعبيرات النمطية. على سبيل المثال --input-encoding utf8 يخبر re2d أن الملف المصدر بترميز UTF8 (يختلف عن --utf8 الذي يحدد ترميز النص المُدخل). الخيار --encoding-policy يحدد الطريقة التي يتعامل بها re2d مع بدائل يونيكود (نقاط الترميز في النطاق [0xD800-0xDFFF]).

فيما يلي مثال على مُحلّل معجمي لمعرّفات يونيكود المُرمّزة بـ UTF8.

// re2d $INPUT -o $OUTPUT -8 -i
module main;
/*!include:re2c "unicode_categories.re" */
private int lex(const(char)* s) {
    const(char)* yycursor = s, yymarker;
    /*!re2c
        re2c:YYCTYPE = "char";
        re2c:yyfill:enable = 0;
        // Simplified "Unicode Identifier and Pattern Syntax"
        // (see https://unicode.org/reports/tr31)
        id_start    = L | Nl | [$_];
        id_continue = id_start | Mn | Mc | Nd | Pc | [\u200D\u05F3];
        identifier  = id_start id_continue*;
        identifier { return 0; }
        *          { return 1; }
    */
}

    assert(lex("_Ыдентификатор") == 0);
    assert(lex("!!!")==1);
}

ملفات التضمين

يسمح re2d بتضمين ملفات أخرى باستخدام كتلة من الشكل /*!include:re2c FILE */ أو %{include FILE %}، أو توجيه داخل الكتلة !include FILE ;، حيث FILE هو مسار الملف المراد تضمينه. يبحث re2d عن ملفات التضمين في دليل الملف المُضمِّن وفي مواقع التضمين، والتي يمكن تحديدها باستخدام الخيار -I. تعمل كتل/توجيهات التضمين في re2d بنفس طريقة #include في C/C++: يتم لصق محتويات FILE حرفيًا في مكان الكتلة/التوجيه. قد تحتوي ملفات التضمين على تضمينات أخرى خاصة بها. استخدم الخيار --depfile لتتبع تبعيات البناء لملف الإخراج على ملفات التضمين. يوفر re2d بعض ملفات التضمين المحددة مسبقًا التي يمكن العثور عليها في الدليل الفرعي include/ الخاص بالمشروع. تحتوي هذه الملفات على تعريفات قد تكون مفيدة لمشاريع أخرى (مثل فئات يونيكود) وتشكل شيئًا مثل مكتبة قياسية لـ re2d. فيما يلي مثال على استخدام ملفات التضمين.

ملفات الرأس

يتيح re2d إنشاء ملف رأس من ملف الإدخال .re باستخدام خيار --header أو إعداد re2c:header وأزواج الكتل من الشكل /*!header:re2c:on*/ و /*!header:re2c:off*/، أو %{header:on%} و %{header:off%}. تحدد الكتلة الأولى بداية ملف الرأس، وتحدد الكتلة الثانية نهايته. تتم معالجة كل ما بين هذه الكتل بواسطة re2d، ويُكتب الكود المُنشأ إلى الملف المحدد بخيار --header أو إعداد re2c:header (أو stdout إذا لم يُستخدم أي منهما). قد يكون ملف الرأس المُنشأ تلقائيًا مطلوبًا في الحالات التي يُستخدم فيها re2d لإنشاء تعريفات يجب أن تكون مرئية من وحدات ترجمة أخرى.

فيما يلي مثال على إنشاء ملف رأس يحتوي على تعريف حالة المُحلِّل المعجمي مع متغيرات الوسوم (يعتمد عدد المتغيرات على القواعد النحوية المنتظمة وهو غير معروف للمبرمج).

ملف الإدخال

// re2d $INPUT -o $OUTPUT -i --header lexer/state.d
module main;
import core.stdc.stddef;
import lexer.state; // يتم إنشاء الوحدة بواسطة re2c
/*!header:re2c:on*/
module lexer.state;
struct LexerState {
    const(char)* str, yycursor;
    /*!stags:re2c format = "const(char)* @@;"; */
};
/*!header:re2c:off*/
private long lex(ref LexerState yyrecord) {
    const(char)* t;
    /*!re2c
        re2c:api = record;
        re2c:YYCTYPE = "char";
        re2c:tags = 1;
        re2c:yyfill:enable = 0;
        re2c:header = "lexer/state.d";
        [a]* @t [b]* { return t - yyrecord.str; }
    */
}
void main() {
    const(char)* s = "ab";
    LexerState st = {s, s /*!stags:re2c format = ", null"; */};
    assert(lex(st) == 1);
    const(char)* s2 = "aaabbbbbbbb";
    LexerState st2 = {s2, s2 /*!stags:re2c format = ", null"; */};
    assert(lex(st2) == 3);
}

برامج الهيكل العظمي

مع خيار -S, --skeleton، يتجاهل re2d كل الكود غير الخاص بـ re2d ويُنشئ برنامج C مكتفيًا بذاته يمكن تجميعه وتنفيذه لاحقًا. يتكون البرنامج من كود المُحلِّل المعجمي وبيانات الإدخال. لكل DFA مُنشأ (كتلة أو شرط) يُنشئ re2d مُحلِّلًا معجميًا مستقلًا و ملفين: ملف .input يحتوي على سلاسل مشتقة من DFA وملف .keys يحتوي على نتائج المطابقة المتوقعة. يشغّل البرنامج كل مُحلِّل معجمي على ملف .input المقابل ويقارن النتائج مع التوقعات. برامج الهيكل العظمي مفيدة جدًا لعدد من الأسباب:

  • يمكنها التحقق من صحة تحسينات re2d المختلفة (تُنشأ البيانات في وقت مبكر من العملية، قبل إجراء أي تحويلات على DFA).
  • قد يكون إنشاء مجموعة من بيانات الإدخال بتغطية جيدة مفيدًا لكل من الاختبار والقياس المرجعي.
  • يتيح إنشاء برامج قابلة للتنفيذ مكتفية بذاتها الحصول على حالات اختبار مُصغَّرة (قد يكون الكود الأصلي كبيرًا أو لديه الكثير من التبعيات).

تكمن الصعوبة في إنشاء بيانات الإدخال في أنه في جميع الحالات باستثناء أبسطها يكون عدد سلاسل الإدخال الممكنة كبيرًا جدًا (حتى إذا كان طول السلسلة محدودًا). يحل re2d هذه الصعوبة بإنشاء عدد كافٍ من السلاسل لتغطية جميع انتقالات DFA تقريبًا. ويستخدم الخوارزمية التالية. أولًا، يُنشئ هيكلًا عظميًا لـ DFA. بالنسبة للترميزات ذات حجم وحدة الكود 1 بايت (مثل ASCII وUTF-8 وEBCDIC) يكون الهيكل العظمي مجرد نسخة مطابقة من DFA الأصلي. بالنسبة للترميزات ذات وحدات الكود متعددة البايت يكون الهيكل العظمي نسخة من DFA مع حذف انتقالات معينة: أي أن re2d يأخذ على الأكثر 256 وحدة كود لكل نطاق متصل منفصل يتوافق مع انتقال DFA. القيم المختارة موزعة بالتساوي وتشمل حدود النطاق. بدلًا من محاولة تغطية جميع المسارات الممكنة في الهيكل العظمي (وهو أمر غير عملي) يُنشئ re2d عددًا كافيًا من المسارات لتغطية جميع انتقالات الهيكل العظمي، وبالتالي تفعيل القفزات الشرطية المقابلة في المُحلِّل المعجمي. تنفيذ الخوارزمية محدود بحوالي 1 جيجابايت من الانتقالات ويستهلك قدرًا ثابتًا من الذاكرة (يكتب re2d البيانات إلى الملف بمجرد إنشائها).

التصوير والتنقيح

مع خيار -D, --emit-dot، لا يُنشئ re2d كودًا. بدلًا من ذلك، يُفرِّغ DFA المُنشأ بصيغة DOT. يمكن للمرء تحويل هذا التفريغ إلى صورة لـ DFA باستخدام Graphviz أو مكتبة أخرى. لاحظ أن هذا الخيار يُظهر DFA النهائي بعد مروره بعدد من التحسينات والتحويلات. يمكن تفريغ المراحل السابقة باستخدام خيارات تنقيح متنوعة، مثل --dump-nfa و--dump-dfa-raw وغيرها (انظر القائمة الكاملة للخيارات).
