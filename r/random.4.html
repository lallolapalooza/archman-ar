NAME

random - entropy device

SYNOPSIS

/dev/random, /dev/urandom

DESCRIPTION

The /dev/random and /dev/urandom special files are character devices (major number 1, minor number 8 and 1, minor number 9, respectively) that serve as an interface to the kernel's random number generator.

The kernel maintains a pool of entropy gathered from various sources, such as mouse movements, keyboard input, disk I/O, and other hardware and software events. This entropy pool is used to generate cryptographically secure pseudo-random numbers.

Both files provide a stream of random bytes. The difference between them lies in how they handle situations where the entropy pool is low.

/dev/random will block if the entropy pool is considered insufficiently initialized. It will only return random bytes once it has enough entropy. This can be useful for applications that require a very high degree of randomness and are willing to wait for it, such as for generating long-term secret keys.

/dev/urandom, on the other hand, will not block. If the entropy pool is low, it will still generate pseudo-random bytes by using a pseudo-random number generator (PRNG) seeded from the entropy pool. This is generally suitable for most applications, including encryption and authentication, as the PRNG is designed to be cryptographically secure.

The number of bits of available entropy can be checked by reading the /proc/sys/kernel/random/entropy_avail file.

Other files under /proc/sys/kernel/random/ provide more information and control over the random number generator:

entropy_avail
This read-only file contains the number of bits of entropy currently available in the pool. When this value drops below a certain threshold, processes that do a select(2) or poll(2) for read access to /dev/random will be woken up.
read_wakeup_threshold
Contains the number of bits of entropy below which processes reading from /dev/random will block. These values can be changed by writing to the file.
write_wakeup_threshold
Contains the number of bits of entropy below which we wake up processes that do a select(2) or poll(2) for write access to /dev/random. These values can be changed by writing to the files.
uuid
boot_id
These read-only files contain random strings like 6fd5a44b-35f4-4ad4-a9b9-6b9be13e1fe9. The former is generated afresh for each read, the latter was generated once.

ioctl(2) interface

The following ioctl(2) requests are defined on file descriptors connected to either /dev/random or /dev/urandom. All requests performed will interact with the input entropy pool impacting both /dev/random and /dev/urandom. The CAP_SYS_ADMIN capability is required for all requests except RNDGETENTCNT.

RNDGETENTCNT
Retrieve the entropy count of the input pool, the contents will be the same as the entropy_avail file under proc. The result will be stored in the int pointed to by the argument.
RNDADDTOENTCNT
Increment or decrement the entropy count of the input pool by the value pointed to by the argument.
RNDGETPOOL
Removed in Linux 2.6.9.
RNDADDENTROPY
Add some additional entropy to the input pool, incrementing the entropy count. This differs from writing to /dev/random or /dev/urandom, which only adds some data but does not increment the entropy count. The following structure is used:

struct rand_pool_info {
    int    entropy_count;
    int    buf_size;
    __u32  buf[0];
};

Here entropy_count is the value added to (or subtracted from) the entropy count, and buf is the buffer of size buf_size which gets added to the entropy pool.
RNDZAPENTCNT
RNDCLEARPOOL
Zero the entropy count of all pools and add some system data (such as wall clock) to the pools.

FILES

/dev/random
/dev/urandom

NOTES

For an overview and comparison of the various interfaces that can be used to obtain randomness, see random(7).

BUGS

During early boot time, reads from /dev/urandom may return data prior to the entropy pool being initialized.
