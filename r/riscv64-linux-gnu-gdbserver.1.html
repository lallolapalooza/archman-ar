NAME

gdbserver ― a remote debugger stub for GDB

SYNOPSIS

gdbserver [--async] [--multi] [--debug-file=filename] [--debug-format=option1[,option2,...]] [--wrapper] [--once] [--version] [--help] [host:]port [program [args...]]
gdbserver --attach [--debug-file=filename] [--debug-format=option1[,option2,...]] [--wrapper] [--once] [--version] [--help] pid [program [args...]]

DESCRIPTION

gdbserver is a program that runs on the target machine, and allows you to debug a program running on that machine using GDB, which runs on the host machine. gdbserver listens for a TCP connection from GDB. When GDB connects, gdbserver can transfer control of the program being debugged to GDB.

The program to be debugged is specified by program. If program is specified, gdbserver starts it. If program is not specified, gdbserver attaches to the process specified by pid.

The host and port specify the network address gdbserver should listen on. If host is omitted, it defaults to listening on all interfaces. If port is omitted, it defaults to 2345.

The following options are supported:

OPTIONS

--async
Do not wait for GDB to connect before starting the program. This allows the program to run while GDB is starting up.
--multi
After a GDB session has finished, gdbserver will continue listening on the specified port, allowing subsequent GDB sessions to connect and debug the same program. This is useful for debugging multi-threaded applications, where GDB may detach and reattach multiple times.
--debug-file=filename
Send any debug output to the specified filename. This option is primarily intended for debugging gdbserver itself. Note that the default behavior for debug output is to send it to standard error. For programs launched by gdbserver, the debug output will be interleaved with the program's output. In contrast, if gdbserver is attached to an existing process, the debug output will be sent to standard error of the gdbserver process itself. The number of threads that can be reported in debug output is limited by the default value of "gdbserver". This could change in future releases of "gdbserver".

--debug-file=filename
Instruct "gdbserver" to send any debug output to the given filename. This option is intended for "gdbserver" development and for bug reports to the developers.
--debug-format=option1[,option2,...]
Instruct "gdbserver" to include extra information in each line of debugging output.
--wrapper
Specify a wrapper to launch programs for debugging. The option should be followed by the name of the wrapper, then any command-line arguments to pass to the wrapper, then "--" indicating the end of the wrapper arguments.
--once
By default, gdbserver keeps the listening TCP port open, so that additional connections are possible. However, if you start "gdbserver" with the --once option, it will stop listening for any further connection attempts after connecting to the first GDB session.

SEE ALSO

The full documentation for GDB is maintained as a Texinfo manual. If the "info" and "gdb" programs and GDB's Texinfo documentation are properly installed at your site, the command

info gdb

should give you access to the complete manual.
