الاسم

re2py - توليد محللات معجمية سريعة لـ Python

الملخص

re2py [ خيارات ] [ تحذيرات ] الإدخال

يمكن أن يكون الإدخال إما ملفًا أو - للإدخال القياسي.

مقدمة

يعمل re2py كمُعالج مسبق. يقرأ ملف الإدخال (وهو عادةً برنامج بلغة Python، ولكنه يمكن أن يكون أي شيء) ويبحث عن كتل من التعليمات البرمجية محاطة بعلامات بدء/إنهاء ذات تنسيق خاص. يتم نسخ النص خارج هذه الكتل كما هو إلى ملف الإخراج. تتم معالجة محتويات الكتل بواسطة re2py. يقوم بترجمتها إلى تعليمات برمجية بلغة Python ويخرج التعليمات البرمجية المُنشأة في مكان الكتلة.

هذا مثال لبرنامج صغير يتحقق مما إذا كانت سلسلة معينة تحتوي على رقم عشري:

# re2py $INPUT -o $OUTPUT
def lex(yyinput):
    yycursor = 0
%{
    re2c:yyfill:enable = 0;
    re2c:indent:top = 1;
    [1-9][0-9]* { return True }
    *           { return False }
%}
assert lex(b"1234\0")

في الإخراج، استبدل re2py الكتلة في المنتصف بالتعليمات البرمجية المُنشأة:

# تم الإنشاء بواسطة re2py
# re2py $INPUT -o $OUTPUT
def lex(yyinput):
    yycursor = 0
    yystate = 0
    while True:
        match yystate:
            case 0:
                yych = yyinput[yycursor]
                yycursor += 1
                if yych <= 0x30:
                    yystate = 1
                    continue
                if yych <= 0x39:
                    yystate = 2
                    continue
                yystate = 1
                continue
            case 1:
                return False
            case 2:
                yych = yyinput[yycursor]
                if yych <= 0x2F:
                    yystate = 3
                    continue
                if yych <= 0x39:
                    yycursor += 1
                    yystate = 2
                    continue
                yystate = 3
                continue
            case 3:
                return True
            case _:
                raise "خطأ داخلي في المحلل المعجمي"
assert lex(b"1234\0")

الأساسيات

يتكون برنامج re2py من تسلسل من الكتل المتداخلة مع التعليمات البرمجية في اللغة الهدف. قد تحتوي الكتلة على تعريفات، تكوينات، قواعد، إجراءات و توجيهات بأي ترتيب:

الاسم = تعبير-عادي ;
يقوم التعريف بربط الاسم بـ التعبير-العادي. قد تحتوي الأسماء على أحرف أبجدية رقمية وشرطة سفلية. يعطي قسم التعبيرات-العادية نظرة عامة على بناء جمل re2py للتعبيرات العادية. بمجرد تعريفه، يمكن استخدام الاسم في تعبيرات عادية أخرى وفي القواعد. لا يُسمح بالعودية في التعريفات المسماة، ويجب تعريف كل اسم قبل استخدامه. ترث الكتلة التعريفات المسماة من النطاق العام. إعادة تعريف اسم موجود في النطاق الحالي هو خطأ.
التكوين = قيمة ;
يسمح التكوين بتغيير سلوك re2py وتخصيص التعليمات البرمجية المُنشأة. للحصول على قائمة كاملة بالتكوينات التي يدعمها re2py، راجع قسم التكوينات. اعتمادًا على تكوين معين، يمكن أن تكون القيمة كلمة مفتاحية، أو رقم صحيح غير سالب، أو سلسلة نصية من سطر واحد يجب أن تكون محاطة بعلامات اقتباس مزدوجة أو مفردة ما لم تكن تتكون من أحرف أبجدية رقمية. ترث الكتلة التكوينات من النطاق العام وقد تعيد تعريفها أو تضيف تكوينات جديدة. تؤثر التكوينات المعرفة داخل الكتلة على الكتلة بأكملها، حتى لو ظهرت في نهايتها.
تعبير-عادي تعليمة برمجية
تقوم القاعدة بربط التعبير-العادي بإجراءها الدلالي (كتلة من التعليمات البرمجية بين قوسين معقوفين، أو كتلة من التعليمات البرمجية تبدأ بـ := وتنتهي بسطر جديد متبوع بأي حرف غير مسافة بيضاء). إذا تطابق التعبير-العادي، يتم تنفيذ التعليمة البرمجية المرتبطة به. إذا تطابقت عدة قواعد، فإن أطول تطابق له الأسبقية. إذا تطابقت عدة قواعد مع نفس السلسلة، فإن الأسبق له الأسبقية. هناك قاعدتان خاصتان: القاعدة الافتراضية * وقاعدة نهاية الإدخال $. يجب تعريف القاعدة الافتراضية دائمًا، ولها الأولوية الأقل بغض النظر عن مكانها في الكتلة، وتطابق أي وحدة رمز (ليس بالضرورة حرفًا صالحًا، انظر قسم دعم الترميز). يجب تعريف قاعدة نهاية الإدخال إذا تم استخدام الطريقة المقابلة لـ معالجة نهاية الإدخال. مع حالات البدء، تتمتع القواعد ببناء جمل أكثر تعقيدًا.
!تعليمة برمجية
تربط الإجراء كتلة تعليمة برمجية معرفة من قبل المستخدم بمكان معين في الآلة الحالة المحدودة المُنشأة (بنفس طريقة ربط الإجراءات الدلالية التعليمات البرمجية بالحالات النهائية). انظر قسم الإجراءات للحصول على قائمة كاملة بالإجراءات المعرفة مسبقًا.
!توجيه ;
التوجيه هو أحد العبارات الخاصة المعرفة مسبقًا. لكل توجيه غرض فريد. انظر قسم التوجيهات للحصول على التفاصيل.

الكتل

علامات بدء وإنهاء الكتلة هي إما /*!re2c و */، أو %{ و %} (كلا النمطين مدعومين). بدءًا من الإصدار 2.2، قد تحتوي الكتل على أسماء اختيارية تسمح بالإشارة إليها في كتل أخرى. هناك أنواع مختلفة من الكتل:

/*!re2c[:<name>] ... */ أو %{[:<name>] ... %}
تحتوي الكتلة العامة على تعريفات وتكوينات وقواعد وتوجيهات. يقوم re2py بتجميع التعبيرات العادية المرتبطة بكل قاعدة في آلة حالة محددة، ويقوم بتشفيرها على شكل قفزات شرطية في اللغة الهدف، ويستبدل الكتلة بالتعليمات البرمجية المُنشأة. تتم إضافة الأسماء والتكوينات المعرفة في كتلة عامة إلى النطاق العام وتصبح مرئية للكتل اللاحقة. في بداية البرنامج، تتم تهيئة النطاق العام بـ خيارات سطر الأوامر.
/*!local:re2c[:<name>] ... */ أو %{local[:<name>] ... %}
الكتلة المحلية تشبه الكتلة العامة، ولكن الأسماء والتكوينات فيها لها نطاق محلي (لا تؤثر على الكتل الأخرى).
/*!rules:re2c[:<name>] ... */ أو %{rules[:<name>] ... %}
كتلة القواعد تشبه الكتلة المحلية، ولكنها لا تنشئ أي تعليمات برمجية بنفسها، ولا تضيف أي تعريفات إلى النطاق العام - إنها مخصصة لإعادة استخدامها في كتل أخرى. هذه طريقة لمشاركة التعليمات البرمجية (مزيد من التفاصيل في قسم الكتل القابلة لإعادة الاستخدام). قبل الإصدار 2.2 من re2py، كانت كتل القواعد تتطلب خيار -r --reusable.
/*!use:re2c[:<name>] ... */ أو %{use[:<name>] ... %}
كتلة استخدام تشير إلى كتلة قواعد معرفة مسبقًا. إذا تم تحديد الاسم، يبحث re2py عن كتل قواعد بهذا الاسم. بخلاف ذلك، يتم استخدام أحدث كتلة قواعد (مسماة أو غير مسماة). يمكن لكتلة الاستخدام إضافة تعريفات وتكوينات وقواعد خاصة بها، والتي تضاف إلى تلك الموجودة في كتلة القواعد المشار إليها. قبل الإصدار 2.2 من re2py، كانت كتل الاستخدام تتطلب خيار -r --reusable.
/*!max:re2c[:<name1>[:<name2>...]] ... */ أو %{max[:<name1>[:<name2>...]] ... %}
كتلة تنشئ تعريف YYMAXFILL. تحدد قائمة اختيارية بأسماء الكتل أي الكتل يجب تضمينها عند حساب قيمة YYMAXFILL (إذا كانت القائمة فارغة، يتم تضمين جميع الكتل). افتراضيًا، التعليمات البرمجية المُنشأة هي تعريف ماكرو لـ C (#define YYMAXFILL <n>)، أو متغير عام لـ Go (var YYMAXFILL int = <n>). يمكن تخصيصها بتكوين اختياري format يحدد قالب سلسلة حيث يتم استبدال @@{max} (أو @@ باختصار) بالقيمة الرقمية لـ YYMAXFILL.
/*!maxnmatch:re2c[:<name1>[:<name2>...]] ... */ أو %{maxnmatch[:<name1>[:<name2>...]] ... %}
كتلة تنشئ تعريف YYMAXNMATCH (تتطلب خيار -P --posix-captures). تحدد قائمة اختيارية بأسماء الكتل أي الكتل يجب تضمينها عند حساب قيمة YYMAXNMATCH (إذا كانت القائمة فارغة، يتم تضمين جميع الكتل). افتراضيًا، التعليمات البرمجية المُنشأة هي تعريف ماكرو لـ C (#define YYMAXNMATCH <n>)، أو متغير عام لـ Go (var YYM
AXNMATCH int = <n>). يمكن تخصيصه باستخدام تكوين اختياري format الذي يحدد سلسلة قوالب يتم فيها استبدال @@{max} (أو @@ اختصارًا) بالقيمة الرقمية لـ YYMAXNMATCH.
/*!stags:re2c[:<name1>[:<name2>...]] ... */, /*!mtags:re2c[:<name1>[:<name2>...]] ... */ أو %{stags[:<name1>[:<name2>...]] ... %}, %{mtags[:<name1>[:<name2>...]] ... %{
كتل تحدد جزء قالب من التعليمات البرمجية يتم توسيعه لكل متغير s-tag/m-tag تم إنشاؤه بواسطة re2py. تحدد قائمة اختيارية بأسماء الكتل أي الكتل يجب تضمينها عند حساب مجموعة متغيرات العلامات (إذا كانت القائمة فارغة، يتم تضمين جميع الكتل). يوجد تكوينان اختياريان: format و separator. يحدد التكوين format سلسلة قوالب يتم فيها استبدال @@{tag} (أو @@ اختصارًا) باسم كل متغير علامة. يحدد التكوين separator جزءًا من التعليمات البرمجية يستخدم لربط قطع format التي تم إنشاؤها لمتغيرات العلامات المختلفة.
/*!svars:re2c[:<name1>[:<name2>...]] ... */, /*!mvars:re2c[:<name1>[:<name2>...]] ... */ أو %{svars[:<name1>[:<name2>...]] ... %}, %{mvars[:<name1>[:<name2>...]] ... %{
كتل تحدد جزء قالب من التعليمات البرمجية يتم توسيعه لكل s-tag/m-tag مذكور صراحةً بواسطة القواعد (مع الخيار --tags) أو تم إنشاؤه ضمنيًا بواسطة re2py (مع خيارات --captvars أو --posix-captvars). تحدد قائمة اختيارية بأسماء الكتل أي الكتل يجب تضمينها عند حساب مجموعة العلامات (إذا كانت القائمة فارغة، يتم تضمين جميع الكتل). يوجد تكوينان اختياريان: format و separator. يحدد التكوين format سلسلة قوالب يتم فيها استبدال @@{tag} (أو @@ اختصارًا) باسم كل علامة. يحدد التكوين separator جزءًا من التعليمات البرمجية يستخدم لربط قطع format التي تم إنشاؤها للعلامات المختلفة.
/*!getstate:re2c[:<name1>[:<name2>...]] ... */ أو %{getstate[:<name1>[:<name2>...]] ... %}
كتلة تنشئ تفريغًا شرطيًا لحالة المصنف (يتطلب الخيار --storable-state). تحدد قائمة اختيارية بأسماء الكتل أي الكتل يجب تضمينها في تفريغ الحالة. ينتقل الانتقال الافتراضي إلى تسمية البداية للكتلة الأولى في القائمة. إذا كانت القائمة فارغة، يتم تضمين جميع الكتل، وينتقل الانتقال الافتراضي إلى الكتلة الأولى في الملف التي لها تسمية بداية. هذه الكتلة غير متوافقة مع الخيار --loop-switch، لأنها تتطلب انتقالات عبر الكتل غير مدعومة بدون goto أو استدعاءات دالة.
/*!conditions:re2c[:<name1>[:<name2>...]] ... */, /*!types:re2c... */ أو %{conditions[:<name1>[:<name2>...]] ... %}, %{types... %}
كتلة تنشئ تعداد الشروط (تتطلب الخيار --conditions). تحدد قائمة اختيارية بأسماء الكتل أي الكتل يجب تضمينها عند حساب مجموعة الشروط (إذا كانت القائمة فارغة، يتم تضمين جميع الكتل). افتراضيًا، التعليمات البرمجية التي تم إنشاؤها هي تعداد YYCONDTYPE. يمكن تخصيصها بتكوينات اختيارية format و separator. يحدد التكوين format سلسلة قوالب يتم فيها استبدال @@{cond} (أو @@ اختصارًا) باسم كل شرط، ويتم استبدال @@{num} بالفهرس الرقمي لهذا الشرط. يحدد التكوين separator جزءًا من التعليمات البرمجية يستخدم لربط قطع format التي تم إنشاؤها للشروط المختلفة.
/*!include:re2c <file> */ أو %{include <file> %}
تسمح هذه الكتلة بتضمين <file>، والتي يجب أن تكون مسار ملف محاط بعلامتي اقتباس مزدوجة. يتم استبدال محتويات الملف حرفيًا في مكان الكتلة، بنفس الطريقة التي يعمل بها #include في C/C++. يمكن استخدام هذه الكتلة مع الخيار --depfile لإنشاء تبعيات نظام البناء على الملفات المضمنة.
/*!header:re2c:on*/ أو %{header:on %}
تحدد هذه الكتلة بداية ملف الرأس. كل شيء بعدها وحتى كتلة header:off التالية يتم معالجته بواسطة re2py ويتم كتابته إلى ملف الرأس المحدد بالخيار -t --type-header.
/*!header:re2c:off*/ أو %{header:off %}
تحدد هذه الكتلة نهاية ملف الرأس الذي بدأ بكتلة header:on*/.
/*!ignore:re2c ... */ أو %{ignore ... %}
كتلة يتم تجاهل محتوياتها وإزالتها من ملف الإخراج.

التكوينات

هذه قائمة كاملة بالتكوينات التي يدعمها re2py:

re2c:api, re2c:input
نفس الخيار --api.
re2c:api:sigil
تحديد العلامة ( "sigil") المستخدمة لمواضع الوسائط في بدائيات API. القيمة الافتراضية هي @@. يبدأ موضع الوسيط بالعلامة متبوعة باسم الوسيط في أقواس متعرجة. على سبيل المثال، إذا تم تعيين العلامة إلى $، فإن مواضع الوسائط ستكون بالشكل ${name}. قد تستخدم واجهات API ذات الوسيط الواحد صيغة مختصرة بدون الاسم في أقواس. يمكن تجاوز هذا الخيار بواسطة خيارات بدائيات API الفردية، مثل re2c:YYFILL@len لـ YYFILL.
re2c:api:style
تحديد نمط API. القيم الممكنة هي functions (الافتراضي لـ C) و free-form (الافتراضي لـ Go و Rust). في نمط functions، يتم إنشاء بدائيات API مع قائمة وسائط بين قوسين بعد اسم البدائي. يتم توفير الوسائط فقط للبارامترات المولدة تلقائيًا (مثل عدد الأحرف الممررة إلى YYFILL)، ولكن ليس لسياق المصنف العام، لذا تتصرف البدائيات بشكل أقرب إلى الماكرو في C/C++ أو الإغلاقات في Go و Rust. في نمط free-form، لا تحتوي بدائيات API على شكل ثابت: يجب تعريفها كسلاسل تحتوي على قطع تعليمات برمجية حرة الشكل مع متغيرات مستبدلة بالشكل @@{var} أو @@ (تتوافق مع الوسائط في النمط شبيه بالدالة). يمكن تجاوز هذا التكوين لبدائيات API الفردية، انظر على سبيل المثال تكوين re2c:YYFILL:naked لـ YYFILL.
re2c:bit-vectors, re2c:flags:bit-vectors, re2c:flags:b
نفس الخيار --bit-vectors، ولكن يمكن تكوينه على أساس كل كتلة.
re2c:captures, re2c:leftmost-captures
نفس الخيار --leftmost-captures، ولكن يمكن تكوينه على أساس كل كتلة.
re2c:captvars, re2c:leftmost-captvars
نفس الخيار --leftmost-captvars، ولكن يمكن تكوينه على أساس كل كتلة.
re2c:case-insensitive, re2c:flags:case-insensitive
نفس الخيار --case-insensitive، ولكن يمكن تكوينه على أساس كل كتلة.
re2c:case-inverted, re2c:flags:case-inverted
نفس الخيار --case-inverted، ولكن يمكن تكوينه على أساس كل كتلة.
re2c:case-ranges, re2c:flags:case-ranges
نفس الخيار --case-ranges، ولكن يمكن تكوينه على أساس كل كتلة.
re2c:computed-gotos, re2c:flags:computed-gotos, re2c:flags:g
نفس الخيار --computed-gotos، ولكن يمكن تكوينه على أساس كل كتلة.
re2c:computed-gotos:relative, re2c:cgoto:relative
نفس الخيار --computed-gotos-relative، ولكن يمكن تكوينه على أساس كل كتلة.
re2c:computed-gotos:threshold, re2c:cgoto:threshold
إذا تم استخدام goto المحسوب، يحدد هذا التكوين عتبة التعقيد التي تؤدي إلى إنشاء جداول قفز بدلاً من عبارات if متداخلة وخرائط بت. القيمة الافتراضية هي 9.
re2c:cond:abort
إذا تم تعيينها إلى قيمة عدد صحيح موجبة، فإن الحالة الافتراضية في تفريغ الشرط الذي تم إنشاؤه تنهي تنفيذ البرنامج.
re2c:cond:goto
يحدد جزءًا من التعليمات البرمجية المستخدم لل قواعد الاختصار المولدة تلقائيًا :=> في الشروط. الافتراضي هو goto @@;. يتم استبدال موضع الوسيط @@ باسم الشرط (انظر تكوينات re2c:api:sigil و re2c:cond:goto@cond).
re2c:cond:goto@cond
يحدد العلامة المستخدمة لاستبدال الوسائط في تعريف re2c:cond:goto. القيمة الافتراضية هي @@. تتجاوز التكوين العام re2c:api:sigil.
re2c:cond:divider
يحدد الفاصل للشروط. القيمة الافتراضية هي /* *********************************** */. يتم استبدال مواضع الوسائط باسم الشرط (انظر re2c:api;sigil و re2c:cond:divider@cond).
re2c:cond:divider@cond

التعبيرات العادية

Options

The options are used to configure the re2py generator.

--compressed
Generate a compressed lexer. This is useful for large lexers which otherwise might lead to stack overflow.
--cpp
Generate C++ code instead of C.
--header
Generate a header file with constants, structures and function prototypes. It also generates a mapping of condition names to numbers. Useful for C programs that use the generated lexer.
--help
Display a list of options and exit.
--hlines
Insert `#line` directives into the generated code. This helps to map the generated code back to the input specification.
--hooks
Enable the use of hooks. Hooks are functions that are called when certain events occur (e.g., when a rule is matched).
--input-encoding <encoding>
Set the input encoding. This is useful when the input file is not in UTF-8. Supported encodings are UTF-8, UTF-16, UTF-32, UCS-2, ISO-8859-1, CP1251.
--lang <lang>
Specify the target language. This is a string identifying the target language and its syntax. The default value is C. The following values are supported: C, C++, Python2, Python3, none.
--nfa
Generate NFA instead of DFA. NFA is generally slower but requires less memory.
--nested-ifs
Generate lexer using nested ifs. This is useful for large lexers which might otherwise lead to stack overflow.
--no-lines
Do not insert `#line` directives into the generated code.
--no-reduce
Do not perform rule reduction. This is useful for debugging.
--no-skip
Do not skip whitespace. This is useful for parsing code that contains whitespace.
--no-tags
Disable submatch extraction with tags.
--output FILE
Write output to FILE instead of stdout.
--resume
Enable lexer resumption. This mode is used when the lexer is interrupted by an outer program when there is not enough input, and then resumed when more input becomes available. In this mode users should additionally define YYGETSTATE and YYSETSTATE primitives, and variables yych, yyaccept and state should be part of the stored lexer state.
--syntax FILE
Load configurations from the specified FILE and apply them on top of the default syntax file. Note that FILE can define only a few configurations (if it's used to amend the default syntax file), or it can define a whole new language backend (in the latter case it is recommended to use --lang none option).
--tags -T
Enable submatch extraction with tags.
--ucs2 --wide-chars -w
Generate a lexer that reads UCS2-encoded input. re2py assumes that the character range is 0 -- 0xFFFF and character size is 2 bytes. This option implies --nested-ifs.
--utf8 --utf-8 -8
Generate a lexer that reads input in UTF-8 encoding. re2py assumes that the character range is 0 -- 0x10FFFF and character size is 1 byte.
--utf16 --utf-16 -x
Generate a lexer that reads UTF16-encoded input. re2py assumes that the character range is 0 -- 0x10FFFF and character size is 2 bytes. This option implies --nested-ifs.
--utf32 --unicode -u
Generate a lexer that reads UTF32-encoded input. re2py assumes that the character range is 0 -- 0x10FFFF and character size is 4 bytes. This option implies --nested-ifs.
--verbose
Output a short message in case of success.
--vernum -V
Show version information in MMmmpp format (major, minor, patch).
--version -v
Show version information.
--single-pass -1
Deprecated. Does nothing (single pass is the default now).
--debug-output -d
Emit YYDEBUG invocations in the generated code. This is useful to trace lexer execution.
--dump-adfa
Debug option: output DFA after tunneling (in .dot format).
--dump-cfg
Debug option: output control flow graph of tag variables (in .dot format).
--dump-closure-stats
Debug option: output statistics on the number of states in closure.
--dump-dfa-det
Debug option: output DFA immediately after determinization (in .dot format).
--dump-dfa-min
Debug option: output DFA after minimization (in .dot format).
--dump-dfa-tagopt
Debug option: output DFA after tag optimizations (in .dot format).
--dump-dfa-tree
Debug option: output DFA under construction with states represented as tag history trees (in .dot format).
--dump-dfa-raw
Debug option: output DFA under construction with expanded state-sets (in .dot format).
--dump-interf
Debug option: output interference table produced by liveness analysis of tag variables.
--dump-nfa
Debug option: output NFA (in .dot format).
--emit-dot -D
Instead of normal output generate lexer graph in .dot format. The output can be converted to an image with the help of Graphviz (e.g. something like dot -Tpng -odfa.png dfa.dot).
--dfa-minimization <moore | table>
Internal option: DFA minimization algorithm used by re2py. The moore option is the Moore algorithm (it is the default). The table option is the "table filling" algorithm. Both algorithms should produce the same DFA up to states relabeling; table filling is simpler and much slower and serves as a reference implementation.
--eager-skip
Internal option: make the generated lexer advance the input position eagerly -- immediately after reading the input symbol. This changes the default behavior when the input position is advanced lazily -- after transition to the next state.
--no-lookahead
Internal option, deprecated. It used to enable TDFA(0) algorithm. Unlike TDFA(1), TDFA(0) algorithm does not use one-symbol lookahead. It applies register operations to the incoming transitions rather than the outgoing ones. Benchmarks showed that TDFA(0) algorithm is less efficient than TDFA(1).
--no-optimize-tags
Internal option: suppress optimization of tag variables (useful for debugging).
--posix-closure <gor1 | gtop>
Internal option: specify shortest-path algorithm used for the construction of epsilon-closure with POSIX disambiguation semantics: gor1 (the default) stands for Goldberg-Radzik algorithm, and gtop stands for "global topological order" algorithm.
--posix-prectable <complex | naive>
Internal option: specify the algorithm used to compute POSIX precedence table. The complex algorithm computes precedence table in one traversal of tag history tree and has quadratic complexity in the number of TNFA states; it is the default. The naive algorithm has worst-case cubic complexity in the number of TNFA states, but it is much simpler than complex and may be slightly faster in non-pathological cases.
--stadfa
Internal option, deprecated. It used to enable staDFA algorithm, which differs from TDFA in that register operations are placed in states rather than on transitions. Benchmarks showed that staDFA algorithm is less efficient than TDFA.
--fixed-tags <none | toplevel | all>
Internal option: specify whether the fixed-tag optimization should be applied to all tags (all), none of them (none), or only those in toplevel concatenation (toplevel). The default is all. "Fixed" tags are those that are located within a fixed distance to some other tag (called "base"). In such cases only the base tag needs to be tracked, and the value of the fixed tag can be computed as the value of the base tag plus a static offset. For tags that are under alternative or repetition it is also necessary to check if the base tag has a no-match value (in that case fixed tag should also be set to no-match, disregarding the offset). For tags in top-level concatenation the check is not needed, because they always match.

Warnings

Warnings can be invividually enabled, disabled and turned into an error.

-W
Turn on all warnings.
-Werror
Turn warnings into errors. Note that this option alone doesn't turn on any warnings; it only affects those warnings that have been turned on so far or will be turned on later.
-W<warning>
Turn on warning.
-Wno-<warning>
Turn off warning.
-Werror-<warning>
Turn on warning and treat it as an error (this implies -W<warning>).
-Wno-error-<warning>
Don't treat this particular warning as an error. This doesn't turn off the warning itself.
-Wcondition-order
Warn if the generated program makes implicit assumptions about condition numbering. One should use either --header option or conditions block to generate a mapping of condition names to numbers and then use the autogenerated condition names.
-Wempty-character-class
Warn if a regular expression contains an empty character class. Trying to match an empty character class makes no sense: it should always fail. However, for backwards compatibility reasons re2py permits empty character classes and treats them as empty strings. Use the --empty-class option to change the default behavior.
-Wmatch-empty-string
Warn if a rule is nullable (matches an empty string). If the lexer runs in a loop and the empty match is unintentional, the lexer may unexpectedly hang in an infinite loop.
-Wswapped-range
Warn if the lower bound of a range is greater than its upper bound. The default behavior is to silently swap the range bounds.

code:yytarget_filter
الشرط المستخدم لتصفية قيم yych التي لا تغطيها جدول yytarget (يُستخدم مع خيار --computed-gotos). المتغير المدعوم: yych (يُعيّن إلى تكوين re2c:yych).

مخازن الإدخال المؤقتة

تتعامل re2c بشكل افتراضي مع مخازن الإدخال المؤقتة. عندما يصل المؤشر إلى نهاية المخزن المؤقت، يتم استدعاء دالة fill لإعادة ملء المخزن المؤقت. يتم استخدام هذه الدالة لإعادة تخصيص المخزن المؤقت، ونقل البيانات، وقراءة المزيد من الإدخال. يجب أن تعيد الدالة قيمة تشير إلى نجاح العملية أو فشلها.

يستخدم المثال التالي المخزن المؤقت مع ملء محدود (padding) لضمان أن جميع المطابقات تحدث داخل المخزن المؤقت.

# re2py $INPUT -o $OUTPUT
from enum import Enum
import os
BUFSIZE = 4096
# Maximum number of characters that can be part of a lexeme, but outside of the
# current input buffer. The value must be greater than zero.
YYMAXFILL = 5
class State:
    def __init__(self, fname):
        self.file = open(fname, "rb")
        self.yyinput = bytearray(BUFSIZE)
        # The maximum possible position of the cursor.
        self.yylimit = BUFSIZE - YYMAXFILL
        # The current position of the cursor.
        self.yycursor = self.yylimit
        # The position of the last matched lexeme.
        self.yymarker = self.yylimit
        # The position of the token.
        self.token = self.yylimit
        self.eof = False
    def __del__(self):
        self.file.close()
class Status(Enum):
    OK = 0
    EOF = 1
    LONG_LEXEME = 2
def fill(st, need):
    if st.eof:
        return Status.EOF
    # Error: lexeme too long. In real life could reallocate a larger buffer.
    if st.token < need:
        return Status.LONG_LEXEME
    # Shift buffer contents (discard everything up to the current token).
    st.yyinput = st.yyinput[st.token:st.yylimit]
    st.yycursor -= st.token;
    st.yymarker -= st.token;
    st.yylimit -= st.token;
    st.token = 0;
    # Fill free space at the end of buffer with new data from file.
    # We subtract 1 because YYMAXFILL characters are reserved for the sentinel.
    bytes = st.file.read(BUFSIZE - st.yylimit - 1) # -1 for sentinel
    if not bytes:
        st.eof = True # end of file
        # Add YYMAXFILL padding characters to the end of the buffer.
        st.yylimit += YYMAXFILL
        st.yyinput += b"\0" * YYMAXFILL
    else:
        st.yylimit += len(bytes);
        st.yyinput += bytes
    return Status.OK
def lex(yyrecord):
    count = 0
    while True:
        yyrecord.token = yyrecord.yycursor
    %{
        re2c:api = record;
        re2c:YYFILL = "if fill(yyrecord, @@) != Status.OK: return -1";
        re2c:indent:top = 2;
        # Match strings enclosed in single quotes. Allows escaped quotes and backslashes.
        str = [' ([^'\\] | [\\][^])* ']
        [\x00] {
            # Check that it is the sentinel, not some unexpected null.
            return count if yyrecord.token == yyrecord.yylimit - YYMAXFILL else -1
        }
        str {
            count += 1
            break
        }
        [ ]+ { break } # Match one or more spaces and break
        *    { return -1 } # Match any other character and return error
    %}
def main():
    fname = "input"
    # Prepare input file.
    f = open(fname, "w")
    for i in range(BUFSIZE):
        f.write("'qu\0tes' 'are' 'fine: \\'' ")
    f.close()
    # Run lexer on the prepared file.
    st = State(fname)
    # Expected result is 3 times the buffer size because each iteration writes
    # the same string 3 times.
    assert lex(st) == 3 * BUFSIZE
    # Cleanup.
    os.remove(fname)
if __name__ == '__main__':
    main()

الميزات

كتل متعددة

في بعض الأحيان يكون من الضروري وجود محركات مسح متعددة مترابطة (على سبيل المثال، إذا كانت هناك آلة حالة عالية المستوى تنتقل بين أوضاع المسح). يمكن تنفيذ ذلك باستخدام كتل re2py متعددة متصلة. خيار آخر هو استخدام الشروط الأولية.

يعتمد تنفيذ الاتصالات بين الكتل على اللغة المستهدفة. في اللغات التي تحتوي على عبارة goto (مثل C/C++ و Go) يمكن أن يكون لدى جميع الكتل وظيفة واحدة، كل منها مسبوقة بتسمية. الانتقال من كتلة إلى أخرى هو goto بسيط. في اللغات التي لا تحتوي على goto (مثل Rust) من الضروري استخدام حلقة مع مفتاح لمتغير حالة، مشابه لـ yystate حلقة/مفتاح تم إنشاؤه بواسطة re2py، أو تغليف كل كتلة في وظيفة واستخدام استدعاءات الوظائف.

يستخدم المثال أدناه كتلًا متعددة لتحليل الأرقام الثنائية والثمانية والعشرية والسداسية عشرية. كل قاعدة لها كتلتها الخاصة. تحدد الكتلة الأولية القاعدة وتوزع على الكتل الأخرى. يتم تعريف التكوينات المشتركة في كتلة منفصلة في بداية البرنامج؛ يتم وراثتها بواسطة الكتل الأخرى.

# re2py $INPUT -o $OUTPUT
class State:
    def __init__(self, str):
        self.yyinput = str
        self.yycursor = 0
        self.yymarker = 0
# Common re2c definitions shared between all functions.
%{
    re2c:api = record;
    re2c:yyrecord = st;
    re2c:yyfill:enable = 0;
    re2c:indent:top = 2;
%}
def parse_u32(str):
    st = State(str)
%{local
    re2c:indent:top = 1;
    '0b' / [01]        { return parse_bin(st) }
    "0"                { return parse_oct(st) }
    "" / [1-9]         { return parse_dec(st) }
    '0x' / [0-9a-fA-F] { return parse_hex(st) }
    *                  { return None }
%}
def parse_bin(st):
    n = 0
    while True: %{
        [01] {
            n = n * 2 + (st.yyinput[st.yycursor - 1] - 48)
            break
        }
        * { return n }
    %}
def parse_oct(st):
    n = 0
    while True: %{
        [0-7] {
            n = n * 8 + (st.yyinput[st.yycursor - 1] - 48)
            break
        }
        * { return n }
    %}
def parse_dec(st):
    n = 0
    while True: %{
        [0-9] {
            n = n * 10 + (st.yyinput[st.yycursor - 1] - 48)
            break
        }
        * { return n }
    %}
def parse_hex(st):
    n = 0
    while True: %{
        [0-9] {
            n = n * 16 + (st.yyinput[st.yycursor - 1] - 48)
            break
        }
        [a-f] {
            n = n * 16 + (st.yyinput[st.yycursor - 1] - 87)
            break
        }
        [A-F] {
            n = n * 16 + (st.yyinput[st.yycursor - 1] - 55)
            break
        }
        * { return n }

assert parse_u32(b"0x7Fe\0") == 2046
assert parse_u32(b"0644\0") == 420
assert parse_u32(b"9999999999\0") == 9999999999

الشروط الأولية

يتم تمكين الشروط الأولية باستخدام خيار --start-conditions. إنها توفر طريقة لترميز آلات متعددة مترابطة داخل نفس كتلة re2py.

يتوافق كل شرط مع آلة واحدة وله اسم فريد يحدده المستخدم ورقم داخلي فريد يحدده re2py. تستخدم الأرقام للتبديل بين الشروط: يستخدم الكود الذي تم إنشاؤه بدائيات YYGETCOND و YYSETCOND للحصول على الشرط الحالي أو تعيينه إلى رقم معين. استخدم كتلة conditions أو خيار --header أو تكوين re2c:header لإنشاء معرفات شروط رقمية. يحدد التكوين re2c:cond:enumprefix بادئة المعرف الذي تم إنشاؤه.

في وضع الشرط، يجب أن تكون كل قاعدة مسبوقة بقائمة بأسماء شروط مفصولة بفواصل في أقواس زاوية، أو حرف بدل <*> للدلالة على جميع الشروط. تمتد صيغة القاعدة على النحو التالي:

< condition-list > regular-expression code
قاعدة يتم دمجها مع كل شرط في condition-list. تطابق regular-expression وتنفذ code المرتبط.
< condition-list > regular-expression => condition code
قاعدة يتم دمجها مع كل شرط في condition-list. تطابق regular-expression، وتعيين الشرط الحالي إلى condition، وتنفذ code المرتبط.
< condition-list > regular-expression :=> condition
قاعدة يتم دمجها مع كل شرط في condition-list. تطابق regular-expression وتنتقل فورًا إلى condition (لا يوجد إجراء دلالي).
< condition-list > !action code
قاعدة تربط code بالمكان المحدد بواسطة action في كل شرط في condition-list (انظر قسم actions لأنواع مختلفة من الإجراءات).
< ! condition-list > code
قاعدة تضيف code إلى الإجراءات الدلالية لجميع القواعد لكل شرط في condition-list. تم إهمال هذه الصيغة، ويجب استخدام إجراء !pre_rule بدلاً منه (يقوم بنفس الشيء تمامًا).
< > code
قاعدة تنشئ شرط دخول خاص بالرقم صفر والاسم "0" الذي ينفذ code قبل القفز إلى شروط أخرى. تم إهمال هذه الصيغة، ويجب استخدام إجراء !entry بدلاً منه (يوفر تحكمًا أكثر دقة، حيث يمكن تحديد الكود لكل شرط على حدة، ويمكنك القفز مباشرة إلى بداية الشرط دون المرور عبر توزيع الشرط).
< > => condition code
نفس القاعدة السابقة، باستثناء أنها تعين condition التالي.
< > :=> condition
نفس القاعدة السابقة، باستثناء أنها لا تحتوي على كود مرتبط وتقفز فورًا إلى condition.

يعتمد الكود الذي يولده re2py للشروط على ما إذا كان re2py يستخدم نهج goto/label أو نهج loop/switch لتشفير الآلات.

في اللغات التي تحتوي على عبارة goto (مثل C/C++ و Go) يتم تنفيذ الشروط بشكل طبيعي ككتل من الكود مسبوقة بتسميات بالشكل yyc_<cond>، حيث cond هو اسم شرط (يمكن تغيير بادئة التسمية باستخدام re2c:cond:prefix). يتم تنفيذ الانتقالات بين الشروط باستخدام goto وتسميات الشروط. قبل جميع الشروط، يقوم re2py بإنشاء مفتاح أولي على YYGETSTATE الذي يقفز إلى حالة البداية للشرط الحالي. تتجاوز قواعد الاختصار :=> المفتاح الأولي وتقفز مباشرة إلى الشرط المحدد (يمكن استخدام re2c:cond:goto لتغيير السلوك الافتراضي). القواعد ذات الإجراءات الدلالية لا تقفز تلقائيًا إلى الشرط التالي؛ يجب القيام بذلك بواسطة الكود المحدد من قبل المستخدم.

في اللغات التي لا تحتوي على goto (مثل Rust) يعيد re2py استخدام المتغير yystate لتخزين أرقام الشروط. يحصل كل شرط على معرف رقمي يساوي عدد حالات البدء الخاصة به، ولا يختلف المفتاح بين الشروط عن المفتاح بين حالات DFA لشرط واحد. لا حاجة لمفتاح شرط أولي منفصل. (نظرًا لأنه يتم استخدام نفس النهج لتنفيذ حالات قابلة للتخزين، فإن YYGETCOND/YYSETCOND تكون زائدة عن الحاجة إذا تم استخدام كل من الحالات القابلة للتخزين والشروط).

يستخدم البرنامج أدناه شروطًا أولية لتحليل الأرقام الثنائية والثمانية والعشرية والسداسية عشرية. يوجد كتلة واحدة حيث لكل قاعدة شرطها الخاص، والشرط الأولي متصل بجميعها. تخزن المتغير المحدد من قبل المستخدم cond رقم الشرط الحالي؛ يتم تهيئته إلى رقم الشرط الأولي الذي تم إنشاؤه مع conditions

يحتوي re2py على خيارين لاستخراج المطابقة الفرعية.

علامات
الخيار الأول هو استخدام علامات قائمة بذاتها على شكل @stag أو #mtag، حيث stag و mtag هي أسماء عشوائية معرفة من قبل المستخدم. يتم تمكين العلامات باستخدام الخيار -T --tags أو التكوين re2c:tags = 1. دلالياً، العلامات هي علامات موضع: يمكن إدراجها في أي مكان في التعبير العادي، وهي تربط بالموضع المقابل (أو مواضع متعددة) في سلسلة الإدخال. علامات-S تربط بآخر موضع مطابق، و علامات-M تربط بقائمة من المواضع (يمكن استخدامها في تعبيرات الفرعية للتكرار، حيث يتوافق موضع واحد في التعبير العادي مع مواضع متعددة في سلسلة الإدخال). يجب تعريف جميع العلامات من قبل المستخدم، إما يدويًا أو بمساعدة كتل svars و mvars. إذا كان هناك أكثر من طريقة لمطابقة العلامات مع الإدخال، يتم حل الغموض باستخدام استراتيجية التمييز الطمعية اليسرى.
المجموعات الملتقطة
الخيار الثاني هو استخدام مجموعات الالتقاط. يتم تمكينها باستخدام الخيار --captures أو التكوين re2c:captures = 1. هناك نكهتان لسياسات تمييز مختلفة، --leftmost-captures (الافتراضي) لاستراتيجية الطمعية اليسرى، و --posix-captures لاستراتيجية أطول مطابقة POSIX. في هذا الوضع، تعتبر جميع التعبيرات الفرعية الموضوعة بين قوسين مجموعات التقاط، ويمكن استخدام علامة تعجب (!) لتمييز المجموعات غير الملتقطة: (! ... ). مع الخيار --invert-captures أو التكوين re2c:invert-captures = 1، يتم عكس معنى علامة التعجب. يتم تخزين عدد المجموعات لقاعدة المطابقة في المتغير yynmatch (التعبير العادي بأكمله هو المجموعة رقم صفر)، ويتم تخزين نتائج المطابقة الفرعية في المصفوفة yypmatch. يجب تعريف كل من yynmatch و yypmatch من قبل المستخدم، ويجب أن يكون حجم yypmatch على الأقل [yynmatch * 2]. استخدم كتلة maxnmatch لتعريف YYMAXNMATCH، وهو ثابت يساوي القيمة القصوى لـ yynmatch بين جميع القواعد.
متغيرات الالتقاط
طريقة أخرى لاستخدام مجموعات الالتقاط هي الخيار --captvars أو التكوين re2c:captvars = 1. الاختلاف الوحيد مع --captures هو في الطريقة التي يخزن بها re2py نتائج المطابقة الفرعية: بدلاً من yynmatch و yypmatch، يقوم re2py بإنشاء المتغيرات yytl<k> و yytr<k> للمجموعة الملتقطة رقم k (يجب على المستخدم الإعلان عن هذه باستخدام كتلة svars). تدعم عمليات الالتقاط بالمتغيرات سياستي تمييز: --leftmost-captvars أو re2c:leftmost-captvars = 1 لاستراتيجية الطمعية اليسرى (الافتراضي) و --posix-captvars أو re2c:posix-captvars لاستراتيجية أطول مطابقة POSIX.

من الداخل، تترجم كل هذه الخيارات إلى علامات و آلات حالة قطعية محددة بالعلامات مع التطلع (Tagged Deterministic Finite Automata with Lookahead - TDFA). الفكرة الأساسية لـ TDFA هي تقليل الحمل الزائد على استخراج المطابقة الفرعية. في الحالة القصوى، إذا لم تكن هناك علامات أو عمليات التقاط في تعبير عادي، فإن TDFA هو مجرد DFA عادي. إذا كان عدد العلامات معتدلاً، فإن الحمل الزائد لا يمكن ملاحظته تقريبًا. يستخدم TDFA الذي تم إنشاؤه عددًا من متغيرات العلامات التي لا تتطابق مباشرة مع العلامات: قد يتم استخدام متغير واحد لعلامات مختلفة، وقد تتطلب علامة واحدة متغيرات متعددة لتخزين جميع قيمها الممكنة. في النهاية، يتم حل الغموض، ويبقى متغير نهائي واحد لكل علامة. يجب تعريف متغيرات العلامات باستخدام كتل stags أو mtags. إذا تم تخزين حالة المحلل اللغوي (lexer)، فيجب أن تكون متغيرات العلامات جزءًا منها. كما تحتاج إلى تحديثها بواسطة YYFILL.

تدعم علامات-S العمليات التالية:

  • حفظ موضع الإدخال في علامة-S: t = YYCURSOR مع واجهة مؤشر C أو عملية معرفة من قبل المستخدم YYSTAGP(t) مع الواجهة العامة
  • حفظ قيمة افتراضية في علامة-S: t = NULL مع واجهة مؤشر C أو عملية معرفة من قبل المستخدم YYSTAGN(t) مع الواجهة العامة
  • نسخ علامة-S إلى أخرى: t1 = t2

تدعم علامات-M العمليات التالية:

  • إلحاق موضع الإدخال بعلامة-M: عملية معرفة من قبل المستخدم YYMTAGP(t) مع كل من الواجهة الافتراضية والعامة
  • إلحاق قيمة افتراضية بعلامة-M: عملية معرفة من قبل المستخدم YYMTAGN(t) مع كل من الواجهة الافتراضية والعامة
  • نسخ علامة-M إلى أخرى: t1 = t2

يمكن تنفيذ علامات-S كقيم مفردة (مؤشرات أو إزاحات). تحتاج علامات-M إلى تمثيل أكثر تعقيدًا، حيث تحتاج إلى تخزين تسلسل من قيم العلامات. التمثيل الأكثر بدائية وغير فعال لعلامة-M هو قائمة (مصفوفة، متجه) من قيم العلامات؛ تمثيل أكثر فعالية هو تخزين جميع علامات-M في شجرة بادئة ممثلة كمصفوفة من العقد (v, p)، حيث v هي قيمة العلامة و p هو مؤشر إلى العقدة الأم.

هذا مثال بسيط لاستخدام علامات-S لتحليل الإصدارات الدلالية التي تتكون من ثلاثة مكونات رقمية: رئيسي، فرعي، تصحيح (الأخير اختياري). انظر أدناه لمثال أكثر تعقيدًا يستخدم YYFILL.

# re2py $INPUT -o $OUTPUT
from collections import namedtuple
SemVer = namedtuple('SemVer', 'major minor patch')
NONE = -1
def parse(yyinput):
    yycursor = 0
    %{
    re2c:yyfill:enable = 0;
    re2c:tags = 1;
    re2c:indent:top = 1;
    num = [0-9]+;
    @t1 num @t2 "." @t3 num @t4 ("." @t5 num)? [\x00] {
        major = int(yyinput[t1:t2])
        minor = int(yyinput[t3:t4])
        patch = int(yyinput[t5:yycursor - 1]) if t5 != NONE else 0
        return SemVer(major, minor, patch)
    }
    * { return None }
%}
assert parse(b"23.34\0") == SemVer(23, 34, 0)
assert parse(b"1.2.99999\0") == SemVer(1, 2, 99999)
assert parse(b"1.a\0") == None

هذا مثال أكثر تعقيدًا لاستخدام علامات-S مع YYFILL لتحليل ملف يحتوي على إصدارات دلالية مفصولة بأسطر جديدة. متغيرات العلامات هي جزء من حالة المحلل اللغوي، ويتم تعديلها في YYFILL مثل مواضع الإدخال الأخرى. لاحظ أن هذا ضروري لعلامات-S لأن قيمها تصبح غير صالحة بعد إزاحة محتويات المخزن المؤقت. قد لا يكون هذا ضروريًا في تطبيق مخصص حيث تخزن متغيرات العلامات الإزاحات بالنسبة لبداية سلسلة الإدخال بدلاً من المخزن المؤقت، وهو ما قد يكون هو الحال مع علامات-M.

# re2py $INPUT -o $OUTPUT
from collections import namedtuple
from enum import Enum
import os
BUFSIZE = 4096
SemVer = namedtuple('SemVer', 'major minor patch')
class State:
    def __init__(self, fname):
        self.file = open(fname, "rb")
        self.yyinput = bytearray(BUFSIZE)
        self.yylimit = BUFSIZE - 1 # exclude terminating null
        self.yycursor = self.yylimit
        self.yymarker = self.yylimit
        self.token = self.yylimit
        self.eof = False
        %{stags format = "\n        self.@@ = -1"; %}
    def __del__(self):
        self.file.close()
class Status(Enum):
    OK = 0
    EOF = 1
    LONG_LEXEME = 2
def fill(st):
    if st.eof:
        return Status.EOF
    # Error: lexeme too long. In real life could reallocate a larger buffer.
    if st.token < 1:
        return Status.LONG_LEXEME
    # Shift buffer contents (discard everything up to the current token).
    st.yyinput = st.yyinput[st.token:st.yylimit]
    st.yycursor -= st.token;
    st.yymarker -= st.token;
    st.yylimit -= st.token;
    %{stags format = "\n    if st.@@ != -1: st.@@ -= st.token"; %}
    st.token = 0;
    # Fill free space at the end of buffer with new data from file.
    bytes = st.file.read(BUFSIZE - st.yylimit - 1) # -1 for sentinel
    if not bytes:
        st.eof = True # end of file
    else:
        st.yylimit += len(bytes);
        st.yyinput += bytes
    st.yyinput += b'\0' # append sentinel
    return Status.OK
def lex(st, count):
    vers = []
    while True:
        st.token = st.yycursor
    %{
        re2c:api = record;
        re2c:yyrecord = st;
        re2c:YYFILL = "fill(st) == Status.OK";
        re2c:eof = 0;
        re2c:indent:top = 2;
        re2c:tags = 1;
        num = [0-9]+;
        num @t1 "." @t2 num @t3 ("." @t4 num)? [\n] {
            major = int(st.yyinput[st.token:t1])
            minor = int(st.yyinput[t2:t3])
            patch = int(st.yyinput[t4:st.yycursor - 1]) if t4 != -1 else 0
            vers.append(SemVer(major, minor, patch))
            break
        }
        $ { return vers }
        * { return None }
    %}
def main():
    fname = "input"
    verstr = b"1.22.333\n"
    expect = [SemVer(1, 22, 333)] * BUFSIZE
    # Prepare input file.
    f = open(fname, "wb")
    for i in range(BUFSIZE):
        f.write(verstr)
    f.close()
    # Run lexer on the prepared file.
    st = State(fname)
    assert lex(st, 0) == expect
    # Cleanup.
    os.remove(fname)
if __name__ == '__main__':
    main()
