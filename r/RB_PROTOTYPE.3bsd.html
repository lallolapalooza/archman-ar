الوصف

تحدد هذه الماكرو هياكل بيانات لأنواع مختلفة من الأشجار: أشجار الانزلاق وأشجار الثنائية الحمراء والسوداء.

في تعريفات الماكرو، TYPE هو اسم العلامة لهيكل يحدده المستخدم ويجب أن يحتوي على حقل اسمه FIELD، من نوع SPLAY_ENTRY أو RB_ENTRY. المعامل HEADNAME هو اسم العلامة لهيكل يحدده المستخدم ويجب تعريفه باستخدام الماكرو SPLAY_HEAD() أو RB_HEAD(). المعامل NAME يجب أن يكون بادئة اسم فريدة لكل شجرة تم تعريفها.

يتم الإعلان عن نماذج الدوال باستخدام SPLAY_PROTOTYPE، RB_PROTOTYPE، أو RB_PROTOTYPE_STATIC. يتم إنشاء أجسام الدوال باستخدام SPLAY_GENERATE، RB_GENERATE، أو RB_GENERATE_STATIC. انظر الأمثلة أدناه لمزيد من التوضيح حول كيفية استخدام هذه الماكرو.

أشجار الانزلاق

شجرة الانزلاق هي هيكل بيانات ذاتي التنظيم. كل عملية على الشجرة تسبب حدوث انزلاق. الانزلاق ينقل العقدة المطلوبة إلى جذر الشجرة ويعيد توازنها جزئيًا.

هذا له فائدة أن المحلية في الطلب تسبب عمليات بحث أسرع حيث تنتقل العقد المطلوبة إلى أعلى الشجرة. من ناحية أخرى، كل عملية بحث تسبب كتابة للذاكرة.

يحدد نظرية التوازن إجمالي وقت الوصول لـ m عملية وإدخال n في شجرة فارغة مبدئيًا على أنه O((m + n)lg n). التكلفة المخففة لسلسلة من m وصول لشجرة انزلاق هي O(lg n).

تترأس شجرة الانزلاق هيكل يتم تعريفه بواسطة الماكرو SPLAY_HEAD(). يتم تعريف هيكل SPLAY_HEAD على النحو التالي:

SPLAY_HEAD(HEADNAME, TYPE) head;

حيث HEADNAME هو اسم الهيكل الذي سيتم تعريفه، والهيكل TYPE هو نوع العناصر التي سيتم إدراجها في الشجرة.

الماكرو SPLAY_ENTRY() يعرف هيكلًا يسمح بربط العناصر في الشجرة.

لأجل استخدام الدوال التي تعالج هيكل الشجرة، يجب الإعلان عن نماذجها باستخدام الماكرو SPLAY_PROTOTYPE()، حيث NAME هو معرف فريد لهذه الشجرة المعينة. المعامل TYPE هو نوع الهيكل الذي تتم إدارته بواسطة الشجرة. المعامل FIELD هو اسم العنصر المحدد بواسطة SPLAY_ENTRY().

يتم إنشاء أجسام الدوال باستخدام الماكرو SPLAY_GENERATE(). يأخذ نفس المعاملات مثل الماكرو SPLAY_PROTOTYPE()، ولكن يجب استخدامه مرة واحدة فقط.

أخيرًا، المعامل CMP هو اسم دالة تستخدم لمقارنة عقد الأشجار ببعضها البعض. تأخذ الدالة وسيطين من النوع struct TYPE *. إذا كان الوسيط الأول أصغر من الثاني، تعيد الدالة قيمة أصغر من الصفر. إذا كانا متساويين، تعيد الدالة صفرًا. بخلاف ذلك، يجب أن تعيد قيمة أكبر من الصفر. تحدد دالة المقارنة ترتيب عناصر الشجرة.

الماكرو SPLAY_INIT() يقوم بتهيئة الشجرة المشار إليها بواسطة head.

يمكن أيضًا تهيئة شجرة الانزلاق بشكل ثابت باستخدام الماكرو SPLAY_INITIALIZER() على النحو التالي:

SPLAY_HEAD(HEADNAME, TYPE) head = SPLAY_INITIALIZER(&head);

يقوم الماكرو SPLAY_INSERT() بإدراج العنصر الجديد elm في الشجرة. عند النجاح، يتم إعادة NULL. إذا كان هناك عنصر مطابق موجود بالفعل في الشجرة، يتم إحباط الإدراج، ويتم إعادة مؤشر إلى العنصر الموجود.

يقوم الماكرو SPLAY_REMOVE() بإزالة العنصر elm من الشجرة المشار إليها بواسطة head. عند النجاح، يتم إعادة مؤشر إلى العنصر المزال. يتم إعادة NULL إذا لم يكن elm موجودًا في الشجرة.

يمكن استخدام الماكرو SPLAY_FIND() للعثور على عنصر معين في الشجرة.

struct TYPE find, *res;
find.key = 30;
res = SPLAY_FIND(NAME, &head, &find);

يمكن استخدام الماكرو SPLAY_ROOT()، SPLAY_MIN()، SPLAY_MAX()، و SPLAY_NEXT() للتنقل في الشجرة:

for (np = SPLAY_MIN(NAME, &head); np != NULL; np = SPLAY_NEXT(NAME, &head, np))

أو، للتبسيط، يمكن استخدام الماكرو SPLAY_FOREACH():

SPLAY_FOREACH(np, NAME, &head)

يجب استخدام الماكرو SPLAY_EMPTY() للتحقق مما إذا كانت شجرة الانزلاق فارغة.

أشجار الثنائية الحمراء والسوداء

شجرة الثنائية الحمراء والسوداء هي شجرة بحث ثنائية مع لون العقدة كميزة إضافية. إنها تفي بمجموعة من الشروط:

  1. كل مسار بحث من الجذر إلى ورقة يتكون من نفس العدد من العقد السوداء،
  2. كل عقدة حمراء (باستثناء الجذر) لها أب أسود،
  3. كل عقدة ورقة سوداء.

كل عملية على شجرة الثنائية الحمراء والسوداء محدودة بـ O(lg n). الحد الأقصى لارتفاع شجرة الثنائية الحمراء والسوداء هو 2lg (n+1).

تترأس شجرة الثنائية الحمراء والسوداء هيكل يتم تعريفه بواسطة الماكرو RB_HEAD(). يتم تعريف هيكل RB_HEAD على النحو التالي:

RB_HEAD(HEADNAME, TYPE) head;

حيث HEADNAME هو اسم الهيكل الذي سيتم تعريفه، والهيكل TYPE هو نوع العناصر التي سيتم إدراجها في الشجرة.

الماكرو RB_ENTRY() يعرف هيكلًا يسمح بربط العناصر في الشجرة.

لأجل استخدام الدوال التي تعالج هيكل الشجرة، يجب الإعلان عن نماذجها باستخدام الماكرو RB_PROTOTYPE() أو RB_PROTOTYPE_STATIC()، حيث NAME هو معرف فريد لهذه الشجرة المعينة. المعامل TYPE هو نوع الهيكل الذي تتم إدارته بواسطة الشجرة. المعامل FIELD هو اسم العنصر المحدد بواسطة RB_ENTRY().

يتم إنشاء أجسام الدوال باستخدام الماكرو RB_GENERATE() أو RB_GENERATE_STATIC(). تأخذ هذه الماكرو نفس المعاملات مثل الماكرو RB_PROTOTYPE() و RB_PR

DESCRIPTION

The red-black tree macros provide an implementation of the red-black tree data structure. They are designed to be used for balanced binary search trees. The tree structure is embedded within the structure that holds the data. Red-black trees are fully balanced binary search trees and guarantee O(log n) performance for lookup, insertion and deletion.

The tree structure is implemented by the RB_ENTRY() macro, which should be defined within the structure that holds the data. For example:

struct mydata {
	RB_ENTRY(mydata) link;
	int value;
	/* ... other fields ... */
};

The RB_HEAD() macro defines the head of the tree. The first argument is the name for the tree head, and the second is the structure type that holds the data. For example:

RB_HEAD(my_tree_head, mydata) my_tree;

The RB_PROTOTYPE() macro is used to declare the functions that are generated by RB_GENERATE(). The first argument is the name of the tree head, the second is the name of the structure type that holds the data, the third argument is the name of the field defined by RB_ENTRY(), and the fourth argument is the name of the comparison function.

The RB_GENERATE() macro is used to generate the tree functions. It should be used only once in the entire program, typically in a source file that implements the tree operations. The arguments are the same as for RB_PROTOTYPE().

Finally, the CMP argument is the name of a function used to compare trees' nodes with each other. The function takes two arguments of type struct TYPE *. If the first argument is smaller than the second, the function returns a value smaller than zero. If they are equal, the function returns zero. Otherwise, it should return a value greater than zero. The compare function defines the order of the tree elements.

The RB_INIT() macro initializes the tree referenced by head.

The red-black tree can also be initialized statically by using the RB_INITIALIZER() macro like this:

RB_HEAD(HEADNAME, TYPE) head = RB_INITIALIZER(&head);

The RB_INSERT() macro inserts the new element elm into the tree. Upon success, NULL is returned. If a matching element already exists in the tree, the insertion is aborted, and a pointer to the existing element is returned.

The RB_REMOVE() macro removes the element elm from the tree pointed by head. RB_REMOVE() returns elm.

The RB_FIND() and RB_NFIND() macros can be used to find a particular element in the tree. RB_FIND() finds the node with the same key as elm. RB_NFIND() finds the first node greater than or equal to the search key.

struct TYPE find, *res;
find.key = 30;
res = RB_FIND(NAME, &head, &find);

The RB_ROOT(), RB_MIN(), RB_MAX(), RB_NEXT(), and RB_PREV() macros can be used to traverse the tree:

for (np = RB_MIN(NAME, &head); np != NULL; np = RB_NEXT(NAME, &head, np))

Or, for simplicity, one can use the RB_FOREACH() or RB_FOREACH_REVERSE() macros:

RB_FOREACH(np, NAME, &head)

The macros RB_FOREACH_SAFE() and RB_FOREACH_REVERSE_SAFE() traverse the tree referenced by head in a forward or reverse direction respectively, assigning each element in turn to np. However, unlike their unsafe counterparts, they permit both the removal of np as well as freeing it from within the loop safely without interfering with the traversal.

The RB_EMPTY() macro should be used to check whether a red-black tree is empty.

EXAMPLES

The following example demonstrates how to declare a red-black tree holding integers. Values are inserted into it and the contents of the tree are printed in order. Lastly, the internal structure of the tree is printed.

#include <sys/tree.h>
#include <err.h>
#include <stdio.h>
#include <stdlib.h>

struct node {
	RB_ENTRY(node) entry;
	int i;
};

int	intcmp(struct node *, struct node *);
void	print_tree(struct node *);

int
intcmp(struct node *e1, struct node *e2)
{
	return (e1->i < e2->i ? -1 : e1->i > e2->i);
}

RB_HEAD(inttree, node) head = RB_INITIALIZER(&head);
RB_PROTOTYPE(inttree, node, entry, intcmp)
RB_GENERATE(inttree, node, entry, intcmp)

int testdata[] = {
	20, 16, 17, 13, 3, 6, 1, 8, 2, 4, 10, 19, 5, 9, 12, 15, 18,
	7, 11, 14
};

void
print_tree(struct node *n)
{
	struct node *left, *right;

	if (n == NULL) {
		printf("nil");
		return;
	}
	left = RB_LEFT(n, entry);
	right = RB_RIGHT(n, entry);
	if (left == NULL && right == NULL)
		printf("%d", n->i);
	else {
		printf("%d(", n->i);
		print_tree(left);
		printf(",");
		print_tree(right);
		printf(")");
	}
}

int
main(void)
{
	int i;
	struct node *n;

	for (i = 0; i < sizeof(testdata) / sizeof(testdata[0]); i++) {
		if ((n = malloc(sizeof(struct node))) == NULL)
			err(1, NULL);
		n->i = testdata[i];
		RB_INSERT(inttree, &head, n);
	}

	RB_FOREACH(n, inttree, &head) {
		printf("%d\n", n->i);
	}
	print_tree(RB_ROOT(&head));
	printf("\n");
	return (0);
}

NOTES

Trying to free a tree in the following way is a common error:

SPLAY_FOREACH(var, NAME, &head) {
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
free(head);

Since var is free'd, the FOREACH() macro refers to a pointer that may have been reallocated already. Proper code needs a second variable.

for (var = SPLAY_MIN(NAME, &head); var != NULL; var = nxt) {
	nxt = SPLAY_NEXT(NAME, &head, var);
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
