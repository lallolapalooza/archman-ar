الاسم

cpp - المعالج المسبق للغة C

الملخص

cpp [-Dmacro[=defn]...] [-Umacro]
[-Idir...] [-iquotedir...]
[-M|-MM] [-MG] [-MF filename]
[-MP] [-MQ target...]
[-MT target...]
infile [[-o] outfile]

تم تقديم الخيارات الأكثر فائدة فقط أعلاه؛ راجع ما يلي للحصول على قائمة أكثر اكتمالاً بالخيارات الخاصة بالمعالج المسبق. بالإضافة إلى ذلك، يقبل cpp معظم خيارات برنامج تشغيل gcc، والتي لم يتم إدراجها هنا. ارجع إلى وثائق GCC للحصول على التفاصيل.

الوصف

المعالج المسبق للغة C، المعروف غالبًا باسم cpp، هو معالج وحدات ماكرو يتم استخدامه تلقائيًا بواسطة مترجم لغة C لتحويل برنامجك قبل الترجمة. يُطلق عليه معالج وحدات ماكرو لأنه يسمح لك بتعريف وحدات الماكرو، وهي اختصارات مختصرة للتراكيب الأطول.

المعالج المسبق للغة C مخصص للاستخدام فقط مع شفرة المصدر للغات C و C++ و Objective-C. في الماضي، تم إساءة استخدامه كمعالج نصوص عام. سيواجه صعوبة في المدخلات التي لا تتبع القواعد المعجمية للغة C. على سبيل المثال، سيتم تفسير علامات الاقتباس المفردة كبداية لثوابت الأحرف، وتسبب أخطاء. أيضًا، لا يمكنك الاعتماد عليه في الحفاظ على خصائص الإدخال التي ليست مهمة للغات عائلة C. إذا تم معالجة ملف Makefile مسبقًا، فسيتم إزالة جميع علامات الجدولة الصعبة، ولن يعمل ملف Makefile.

مع أخذ ذلك في الاعتبار، غالبًا ما يمكنك استخدام cpp على أشياء ليست بلغة C. لغات البرمجة الأخرى الشبيهة بـ Algol غالبًا ما تكون آمنة (Ada، إلخ.) كذلك التجميع، بحذر. وضع -traditional-cpp يحافظ على المزيد من المساحات البيضاء، وهو بشكل عام أكثر تساهلاً. يمكن تجنب العديد من المشاكل عن طريق كتابة تعليقات بأسلوب C أو C++ بدلاً من تعليقات اللغة الأصلية، والحفاظ على وحدات الماكرو بسيطة.

حيثما أمكن، يجب عليك استخدام معالج مسبق موجه للغة التي تكتب بها. تحتوي الإصدارات الحديثة من المجمع GNU على مرافق وحدات ماكرو. معظم لغات البرمجة عالية المستوى لديها آلية التجميع الشرطي والتضمين الخاصة بها. إذا فشل كل شيء، فحاول استخدام معالج نصوص عام حقيقي، مثل GNU M4.

تختلف معالجات C المسبقة في بعض التفاصيل. يناقش هذا الدليل معالج C المسبق GNU، الذي يوفر مجموعة فرعية صغيرة من ميزات معيار C القياسي ISO. في وضعه الافتراضي، لا يقوم معالج C المسبق GNU ببعض الأشياء المطلوبة من قبل المعيار. هذه ميزات نادرة الاستخدام، وقد تسبب تغييرات مفاجئة في معنى البرنامج الذي لا يتوقعها. للحصول على معيار C قياسي ISO صارم، يجب عليك استخدام الخيارات -std=c90 أو -std=c99 أو -std=c11 أو -std=c17، اعتمادًا على الإصدار الذي تريده من المعيار. للحصول على جميع التشخيصات الإلزامية، يجب عليك أيضًا استخدام -pedantic.

يصف هذا الدليل سلوك المعالج المسبق ISO. لتقليل الاختلافات غير الضرورية، حيث لا يتعارض سلوك المعالج المسبق ISO مع الدلالات التقليدية، يجب أن يتصرف المعالج المسبق التقليدي بنفس الطريقة. يتم تفصيل الاختلافات المختلفة التي توجد في القسم الوضع التقليدي.

للتوضيح، ما لم يُذكر خلاف ذلك، تشير الإشارات إلى CPP في هذا الدليل إلى CPP GNU.

الخيارات

يتوقع الأمر cpp اسمي ملفين كوسائط، infile و outfile. يقرأ المعالج المسبق infile جنبًا إلى جنب مع أي ملفات أخرى يحددها باستخدام #include. تتم كتابة جميع المخرجات الناتجة عن ملفات الإدخال المجمعة في outfile.

قد يكون أي من infile أو outfile هو -، والذي بالنسبة لـ infile يعني القراءة من الإدخال القياسي وبالنسبة لـ outfile يعني الكتابة إلى الإخراج القياسي. إذا تم حذف أي ملف، فإنه يعني نفس الشيء كما لو تم تحديد - لذلك الملف. يمكنك أيضًا استخدام خيار -o outfile لتحديد ملف الإخراج.

ما لم يُذكر خلاف ذلك، أو إذا انتهى الخيار بـ =، فإن جميع الخيارات التي تأخذ وسيطة يمكن أن تحتوي على تلك الوسيطة إما مباشرة بعد الخيار، أو مع وجود مسافة بين الخيار والوسيطة: -Ifoo و -I foo لهما نفس التأثير.

العديد من الخيارات لها أسماء متعددة الأحرف؛ لذلك، لا يمكن تجميع خيارات الأحرف المفردة المتعددة: -dM يختلف اختلافًا كبيرًا عن -d -M.

-D name
قم بتعريف name مسبقًا كوحدة ماكرو، مع التعريف 1.
-D name=definition
يتم ترميز محتويات definition ومعالجتها كما لو أنها ظهرت أثناء مرحلة الترجمة الثالثة في توجيه #define. على وجه الخصوص، يتم اقتطاع التعريف بواسطة أحرف السطر الجديد المضمنة.

إذا كنت تقوم بتشغيل المعالج المسبق من shell أو برنامج شبيه بالـ shell، فقد تحتاج إلى استخدام صيغة الاقتباس الخاصة بالـ shell لحماية الأحرف مثل المسافات التي لها معنى في صيغة الـ shell.

إذا كنت ترغب في تعريف وحدة ماكرو شبيهة بالدالة على سطر الأوامر، فاكتب قائمة الوسائط الخاصة بها مع أقواس محيطة قبل علامة المساواة (إن وجدت). الأقواس ذات معنى لمعظم الـ shells، لذلك يجب عليك اقتباس الخيار. مع sh و csh، يعمل -D'name(args...)=definition'.

تتم معالجة خيارات -D و -U بالترتيب الذي تظهر به على سطر الأوامر. تتم معالجة جميع خيارات -imacros file و -include file بعد جميع خيارات -D و -U.

-U name
إلغاء أي تعريف سابق لـ name، سواء كان مدمجًا أو تم توفيره باستخدام خيار -D.
-include file
قم بمعالجة file كما لو أن "#include "file"" ظهر كأول سطر في ملف المصدر الأساسي. ومع ذلك، فإن الدليل الأول الذي يتم البحث فيه عن file هو دليل العمل للمعالج المسبق بدلاً من الدليل الذي يحتوي على ملف المصدر الرئيسي. إذا لم يتم العثور عليه هناك، يتم البحث عنه في بقية سلسلة البحث الخاصة بـ "#include "..."" كالمعتاد.

إذا تم تقديم خيارات -include متعددة، يتم تضمين الملفات بالترتيب الذي تظهر به على سطر الأوامر.

-imacros file
تمامًا مثل -include، باستثناء أنه يتم تجاهل أي مخرجات ناتجة عن مسح file. تبقى وحدات الماكرو التي يعرّفها معرفة. هذا يسمح لك بالحصول على جميع وحدات الماكرو من ملف رأس دون معالجة تعريفاته أيضًا.

تتم معالجة جميع الملفات المحددة بواسطة -imacros قبل جميع الملفات المحددة بواسطة -include.

-undef
لا تقم بتعريف أي وحدات ماكرو خاصة بالنظام أو خاصة بـ GCC مسبقًا. تظل وحدات الماكرو المعرفة مسبقًا قياسيًا معرفة.
-pthread
قم بتعريف وحدات ماكرو إضافية مطلوبة لاستخدام مكتبة خيوط POSIX. يجب عليك استخدام هذا الخيار باستمرار لكل من الترجمة والربط. هذا الخيار مدعوم على أهداف GNU/Linux، ومعظم مشتقات Unix الأخرى، وكذلك على أهداف Cygwin و MinGW x86.
-M
بدلاً من إخراج نتيجة المعالجة المسبقة، قم بإخراج قاعدة مناسبة لـ make تصف تبعيات ملف المصدر الرئيسي. يقوم المعالج المسبق بإخراج قاعدة make واحدة تحتوي على اسم ملف الكائن لذلك الملف المصدر، ونقطتين رأسيتين، وأسماء جميع الملفات المضمنة، بما في ذلك تلك القادمة من خيارات سطر الأوامر -include أو -imacros.

ما لم يتم تحديده صراحةً (باستخدام -MT أو -MQ)، يتكون اسم ملف الكائن من اسم الملف المصدر مع استبدال أي لاحقة بلاحقة ملف الكائن وإزالة أي أجزاء دليل بادئة. إذا كانت هناك العديد من الملفات المضمنة، فسيتم تقسيم القاعدة إلى عدة أسطر باستخدام \-newline. القاعدة لا تحتوي على أوامر.

لا يؤدي هذا الخيار إلى قمع مخرجات تصحيح أخطاء المعالج المسبق، مثل -dM. لتجنب خلط مخرجات تصحيح الأخطاء هذه مع قواعد التبعية، يجب عليك تحديد ملف مخرجات التبعية صراحةً باستخدام -MF، أو استخدام متغير بيئة مثل DEPENDENCIES_OUTPUT. لا تزال مخرجات تصحيح الأخطاء تُرسل إلى الإخراج المنتظم.

-MM
مثل -M، ولكنه يتجاهل ملفات الرأس الخاصة بالنظام. هذا يعني أنه ينتج قاعدة make تقليدية، والتي تصف فقط ملفات الرأس التي تشير إليها مباشرةً.
-MG
مثل -M، ولكن يفترض أن الملفات التي تبدو كملفات رأس (مثل <header.h>) التي تم تضمينها هي ملفات يجب تضمينها وأنها لن تظهر أبدًا في شجرة التبعية. هذا هو السلوك القياسي في بعض الأحيان.
-MF filename
إذا تم استخدام -M أو -MM، فقم بتخزين قاعدة التبعية في filename بدلاً من stdout.
-MP
أضف قاعدة وهمية لكل ملف رأس تم تضمينه. هذا سيمنع make من الفشل إذا تم حذف ملف رأس. إذا تم استخدام -M أو -MM، فسيتم إضافة هذه القاعدة الوهمية تلقائيًا.
-MQ target
مثل -MT، ولكن مع اقتباس target بحيث يمكن استخدامه بأمان في صيغة make.
-MT target
غيّر الهدف في قاعدة التبعية التي تم إنشاؤها بواسطة -M أو -MM. الافتراضي هو اسم ملف الكائن. استخدام -MT له نفس تأثير استخدام -MQ.
-I dir
أضف الدليل dir إلى قائمة الدلائل التي يتم البحث فيها عن ملفات الرأس.

يتم البحث في الدلائل المحددة باستخدام -I بنفس ترتيب البحث عن الملفات المضمنة في التوجيهات "#include "..."" ، أي بعد الدليل الحالي.

يتم البحث في الدلائل المحددة باستخدام "#include<...>" بالترتيب المحدد.

إذا كان dir يبدأ بـ "/"، فإنه يعتبر مسارًا مطلقًا. وإلا، فإنه يعتبر مسارًا نسبيًا إلى الدليل الحالي. يتم تجاهل المسارات النسبية التي تتكون من "." أو "..".

إذا كان dir عبارة عن علامة تبويب، فسيتم تجاهلها.

يمكن تقديم خيارات -I متعددة. يتم البحث في الدلائل بالمسار المحدد.

-iquote dir
أضف الدليل dir إلى قائمة الدلائل التي يتم البحث فيها عن ملفات الرأس.

يتم البحث في الدلائل المحددة باستخدام -iquote بنفس ترتيب البحث عن الملفات المضمنة في التوجيهات "#include "..."" ، أي بعد الدليل الحالي.

تتم معالجة الدلائل المحددة باستخدام "#include "..."" بالترتيب المحدد.

إذا كان dir يبدأ بـ "/"، فإنه يعتبر مسارًا مطلقًا. وإلا، فإنه يعتبر مسارًا نسبيًا إلى الدليل الحالي. يتم تجاهل المسارات النسبية التي تتكون من "." أو "..".

إذا كان dir عبارة عن علامة تبويب، فسيتم تجاهلها.

يمكن تقديم خيارات -iquote متعددة. يتم البحث في الدلائل بالمسار المحدد.

-nostdinc
لا تبحث في الدلائل القياسية لملفات الرأس.
-nostdinc++
لا تبحث في الدلائل القياسية لملفات رأس C++.
-flto
قم بتمكين الترجمة المتوازية لـ Link Time Optimization. استخدم هذا الخيار لتمكين الترجمة المتوازية لـ Link Time Optimization.
-fno-lto
قم بتعطيل الترجمة المتوازية لـ Link Time Optimization. استخدم هذا الخيار لتعطيل الترجمة المتوازية لـ Link Time Optimization.
-traditional-cpp
قم بتشغيل المعالج المسبق التقليدي. هذا الخيار يخبر المعالج المسبق بتصرف كما يفعل معالج C المسبق التقليدي. يعني هذا أن الماكرو التقليدي يتم افتراضه. هذا الخيار له نفس تأثير الخيارات -traditional و -trigraphs.
-trigraphs
قم بتمكين دعم العلامات التركيبية الثلاثية. العلامات التركيبية الثلاثية هي تسلسلات من ثلاثة أحرف تستخدم لتمثيل أحرف غير موجودة في ASCII.
-gthird
قم بتمكين دعم العلامات التركيبية الثلاثية.
-dM
لا تقم بإخراج ملفات المصدر المعالجة. بدلاً من ذلك، قم بإخراج قائمة بالتعريفات التي تم تعيينها لوحدات الماكرو. يتم تمثيل كل تعريف كتعليق تعريفي. يتم تجاهل توجيهات `#include`.
-dm
لا تقم بإخراج ملفات المصدر المعالجة. بدلاً من ذلك، قم بإخراج قائمة بالتعريفات التي تم تعيينها لوحدات الماكرو. يتم تمثيل كل تعريف كتعليق تعريفي. يتم تجاهل توجيهات `#include`.
-dD
لا تقم بإخراج ملفات المصدر المعالجة. بدلاً من ذلك، قم بإخراج قائمة بالتعريفات التي تم تعيينها لوحدات الماكرو. يتم تمثيل كل تعريف كتعليق تعريفي. يتم تجاهل توجيهات `#include`.
-dN
لا تقم بإخراج ملفات المصدر المعالجة. بدلاً من ذلك، قم بإخراج قائمة بالتعريفات التي تم تعيينها لوحدات الماكرو. يتم تمثيل كل تعريف كتعليق تعريفي. يتم تجاهل توجيهات `#include`.
-dP
لا تقم بإخراج ملفات المصدر المعالجة. بدلاً من ذلك، قم بإخراج قائمة بالتعريفات التي تم تعيينها لوحدات الماكرو. يتم تمثيل كل تعريف كتعليق تعريفي. يتم تجاهل توجيهات `#include`.
-fpreprocessed
قم بمعالجة ملف الإدخال كما لو كان قد تمت معالجته مسبقًا. يعني هذا أن التوجيهات مثل `#include` و `#define` لا يتم معالجتها.
-fno-show-column
قم بتعطيل عرض معلومات العمود في رسائل الخطأ. رسائل الخطأ لا تعرض معلومات العمود.
-fshow-column
قم بتمكين عرض معلومات العمود في رسائل الخطأ. رسائل الخطأ تعرض معلومات العمود.
-traditional
قم بتشغيل المعالج المسبق التقليدي. هذا الخيار له نفس تأثير الخيارات -traditional-cpp و -trigraphs.
-H
قم بطباعة أسماء الملفات التي يتم تضمينها.
-P
لا تقم بإخراج توجيهات `#line` في ملف الإخراج. هذا الخيار مفيد عندما تريد استخدام المعالج المسبق لإنشاء ملف، ولكن لا تريد أن يتم تتبع الأخطاء في ملف الإخراج. يمنع هذا الخيار المعالج المسبق من إخراج توجيهات `#line`.
-C
لا تقم بإزالة تعليقات C. هذا الخيار يخبر المعالج المسبق بعدم إزالة تعليقات C. افتراضيًا، يقوم المعالج المسبق بإزالة جميع تعليقات C.
-CC
لا تقم بإزالة تعليقات C++. هذا الخيار يخبر المعالج المسبق بعدم إزالة تعليقات C++. افتراضيًا، يقوم المعالج المسبق بإزالة جميع تعليقات C++.
-quiet
قم بقمع معظم رسائل التحذير. هذا الخيار يخبر المعالج المسبق بقمع معظم رسائل التحذير. الرسائل التي سيتم قمعها هي تلك التي ليست خطيرة.
-v
قم بطباعة رقم إصدار المعالج المسبق. هذا الخيار يخبر المعالج المسبق بطباعة رقم إصداره. هذا مفيد عندما تريد معرفة إصدار المعالج المسبق الذي تستخدمه.
-o outfile
قم بتسمية ملف الإخراج outfile. هذا الخيار يخبر المعالج المسبق بتسمية ملف الإخراج outfile. إذا لم يتم تحديد هذا الخيار، فسيتم كتابة الإخراج إلى الإخراج القياسي.
-x language
قم بمعاملة الملفات التالية كما لو كانت من language. اللغة المدعومة الوحيدة هي c-header.
-std=standard

c17, iso9899:2017
c++98, iso14882:1998

c++14, iso14882:2014

c++20, iso14882:2020
c++23, iso14882:2023
gnuc
gnu++98, gnu++03
gnu++11
gnu++14
gnu++17

الخيار -std= standard يحدد المعيار المطلوب استخدامه. إذا تم تحديد هذا الخيار، فسيتم استخدام المعيار المحدد. إذا لم يتم تحديد هذا الخيار، فسيتم استخدام معيار GNU C افتراضيًا.

البيئة

قد تؤثر متغيرات البيئة التالية على تشغيل cpp:

C_INCLUDE_PATH
قائمة مفصولة بفواصل لأسماء الدلائل التي يجب البحث فيها عن ملفات الرأس. يتم تجاهل المسارات النسبية.
CPLUS_INCLUDE_PATH
قائمة مفصولة بفواصل لأسماء الدلائل التي يجب البحث فيها عن ملفات رأس C++.
DEPENDENCIES_OUTPUT
إذا تم تعيين هذا المتغير، فسيتم كتابة مخرجات التبعية إليها بدلاً من الإخراج القياسي. يستخدم هذا الخيار عند معالجة ملفات المصدر متعددة.
SOURCE_DATE_EPOCH
إذا تم تعيين هذا المتغير، فسيتم استخدامه كختم زمني لملفات المصدر. هذا يسمح بإمكانية تكرار بناء ملفات المصدر.
SYSTEM_HEADER_DEPS
إذا تم تعيين هذا المتغير، فسيتم استخدام نظام تتبع التبعيات الخاص بـ GCC. هذا يسمح بإنشاء ملفات تبعيات أكثر دقة.

يصدر المعالج المسبق رسائل خطأ على الإخراج القياسي للأخطاء. يتم كتابة مخرجات المعالج المسبق إلى الإخراج القياسي.

OPTIONS

-Idir
Add directory dir to the list of directories in which to look for header files, after the user-specified include directories. If you have both "..." and <...> style includes, the directory containing the current file is searched for the former (if specified with "...").
-I-
This option inhibits the use of the directory of the current file as the first search directory for "#include "file"". There is no way to override this effect of -I-.
-iquotedir
Add directory dir to the list of directories in which to look for header files, after the user-specified include directories and before the system headers. Only for C++ includes and only for quoted includes like "file".
-isystemdir
Add directory dir to the list of system include directories. These directories are searched after the user-specified include directories, and after the directory of the current file (for quoted includes). Also, these directories are searched for angle-bracket includes "#include <file>". If additional directories are specified with -I options after the -I-, those directories are searched for all #include directives.

In addition, -I- inhibits the use of the directory of the current file directory as the first search directory for "#include "file"". There is no way to override this effect of -I-.

-iprefix prefix
Specify prefix as the prefix for subsequent -iwithprefix options. If the prefix represents a directory, you should include the final /.
-iwithprefix dir
-iwithprefixbefore dir
Append dir to the prefix specified previously with -iprefix, and add the resulting directory to the include search path. -iwithprefixbefore puts it in the same place -I would; -iwithprefix puts it where -idirafter would.
-isysroot dir
This option is like the --sysroot option, but applies only to header files (except for Darwin targets, where it applies to both header files and libraries). See the --sysroot option for more information.
-imultilib dir
Use dir as a subdirectory of the directory containing target-specific C++ headers.
-nostdinc
Do not search the standard system directories for header files. Only the directories explicitly specified with -I, -iquote, -isystem, and/or -idirafter options (and the directory of the current file, if appropriate) are searched.
-nostdinc++
Do not search for header files in the C++-specific standard directories, but do still search the other standard directories. (This option is used when building the C++ library.)
--embed-dir=dir
Append dir directory to the list of searched directories for "#embed" preprocessing directive or "__has_embed" macro. There are no default directories for "#embed".

If dir begins with = or $SYSROOT, then the = or $SYSROOT is replaced by the sysroot prefix; see --sysroot and -isysroot.

-Wcomment
-Wcomments
Warn whenever a comment-start sequence /* appears in a /* comment, or whenever a backslash-newline appears in a // comment. This warning is enabled by -Wall.
-Wtrigraphs
Warn if any trigraphs are encountered that might change the meaning of the program. Trigraphs within comments are not warned about, except those that would form escaped newlines.

This option is implied by -Wall. If -Wall is not given, this option is still enabled unless trigraphs are enabled. To get trigraph conversion without warnings, but get the other -Wall warnings, use -trigraphs -Wall -Wno-trigraphs.

-Wundef
Warn if an undefined identifier is evaluated in an "#if" directive. Such identifiers are replaced with zero.
-Wexpansion-to-defined
Warn whenever defined is encountered in the expansion of a macro (including the case where the macro is expanded by an #if directive). Such usage is not portable. This warning is also enabled by -Wpedantic and -Wextra.
-Wunused-macros
Warn about macros defined in the main file that are unused. A macro is used if it is expanded or tested for existence at least once. The preprocessor also warns if the macro has not been used at the time it is redefined or undefined.

Built-in macros, macros defined on the command line, and macros defined in include files are not warned about.

Note: If a macro is actually used, but only used in skipped conditional blocks, then the preprocessor reports it as unused. To avoid the warning in such a case, you might improve the scope of the macro's definition by, for example, moving it into the first skipped block. Alternatively, you could provide a dummy use with something like:

#if defined the_macro_causing_the_warning
#endif
-Wno-endif-labels
Do not warn whenever an "#else" or an "#endif" are followed by text. This sometimes happens in older programs with code of the form 
#if FOO
...
#else FOO
...
#endif FOO

The second and third "FOO" should be in comments. This warning is on by default.

ENVIRONMENT

This section describes the environment variables that affect how CPP operates. You can use them to specify directories or prefixes to use when searching for include files, or to control dependency output.

Note that you can also specify places to search using options such as -I, and control dependency output with options like -M. These take precedence over environment variables, which in turn take precedence over the configuration of GCC.

CPATH
C_INCLUDE_PATH
CPLUS_INCLUDE_PATH
OBJC_INCLUDE_PATH
Each variable's value is a list of directories separated by a special character, much like PATH, in which to look for header files. The special character, "PATH_SEPARATOR", is target-dependent and determined at GCC build time. For Microsoft Windows-based targets it is a semicolon, and for almost all other targets it is a colon.

CPATH specifies a list of directories to be searched as if specified with -I, but after any paths given with -I options on the command line. This environment variable is used regardless of which language is being preprocessed.

The remaining environment variables apply only when preprocessing the particular language indicated. Each specifies a list of directories to be searched as if specified with -isystem, but after any paths given with -isystem options on the command line.

In all these variables, an empty element instructs the compiler to search its current working directory. Empty elements can appear at the beginning or end of a path. For instance, if the value of CPATH is ":/special/include", that has the same effect as -I. -I/special/include.

DEPENDENCIES_OUTPUT
If this variable is set, its value specifies how to output dependencies for Make based on the non-system header files processed by the compiler. System header files are ignored in the dependency output.

The value of DEPENDENCIES_OUTPUT can be just a file name, in which case the Make rules are written to that file, guessing the target name from the source file name. Or the value can have the form file target, in which case the rules are written to file file using target as the target name.

In other words, this environment variable is equivalent to combining the options -MM and -MF, with an optional -MT switch too.

SUNPRO_DEPENDENCIES
This variable is the same as DEPENDENCIES_OUTPUT (see above), except that system header files are not ignored, so it implies -M rather than -MM. However, the dependence on the main input file is omitted.
SOURCE_DATE_EPOCH
If this variable is set, its value specifies a UNIX timestamp to be used in replacement of the current date and time in the "__DATE__" and "__TIME__" macros, so that the embedded timestamps become reproducible.

The value of SOURCE_DATE_EPOCH must be a UNIX timestamp, defined as the number of seconds (excluding leap seconds) since 01 Jan 1970 00:00:00 represented in ASCII; identical to the output of "date +%s" on GNU/Linux and other systems that support the %s extension in the "date" command.

The value should be a known timestamp such as the last modification time of the source or package and it should be set by the build process.
