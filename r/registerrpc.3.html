SYNOPSIS AND DESCRIPTION


The RPC library routines are designed to allow users to generate RPC
    messages and services without knowing the details of the RPC protocol or
    the underlying transport mechanisms.


The RPC package provides a mechanism for remote procedure calls. It
    allows a program to call a procedure on a remote machine as if it were a
    local procedure. The RPC package supports both connectionless and
    connection-oriented transports.


The following routines are provided:


rpc_reg(char *nettype, char *procname, xdrproc_t proc, xdrproc_t xdr, xdrproc_t vdr, char *netconf, long authflg);



  

  
Registers an RPC procedure with the RPC package. This routine is used to
      register services for incoming RPC calls.




svc_reg(char *nettype, u_long procnr, xdrproc_t proc, xdrproc_t xdr, xdrproc_t vdr);



  

  
Registers an RPC service with the RPC package. This routine is used to
      register services for incoming RPC calls.




svc_unreg(u_long procnr);



  

  
Unregisters an RPC service from the RPC package.




svc_create(intsock, u_int recvsz, u_int sendsz);



  

  
Creates an RPC service transport handle.




bool_t xdr_accepted_reply(XDR *xdrs, struct rpc_msg *ar);



  

  
Used for describing RPC accepted reply messages. This routine is useful for
      users who wish to generate RPC-style messages without using the RPC
      package.




bool_t xdr_authunix_parms(XDR *xdrs, struct authunix_parms *aup);

Used for describing RPC reply messages. This routine is useful for users

void xprt_register(SVCXPRT *xprt);



  

  
After RPC service transport handles are created, they should register
      themselves with the RPC service package. This routine modifies the global
      variable svc_fds. Service implementors usually do not need this
      routine.




void xprt_unregister(SVCXPRT *xprt);



  

  
Before an RPC service transport handle is destroyed, it should unregister
      itself with the RPC service package. This routine modifies the global
      variable svc_fds. Service implementors usually do not need this
      routine.
