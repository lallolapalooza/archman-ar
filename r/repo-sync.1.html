الاسم

repo - repo sync - صفحة دليل لمزامنة repo

الملخص

repo sync [<project>...]

الوصف

ملخص

تحديث شجرة العمل إلى أحدث مراجعة

الخيارات

-h, --help
عرض رسالة المساعدة هذه والخروج
-j JOBS, --jobs=JOBS
عدد المهام التي سيتم تشغيلها بالتوازي (الافتراضي: يعتمد على عدد أنوية المعالج)
--jobs-network=JOBS
عدد مهام الشبكة التي سيتم تشغيلها بالتوازي (افتراضيًا --jobs أو 1). يتم تجاهله عند تعيين --interleaved
--jobs-checkout=JOBS
عدد مهام سحب الملفات المحلية التي سيتم تشغيلها بالتوازي (افتراضيًا --jobs أو 8). يتم تجاهله عند تعيين --interleaved
-f, --force-broken
خيار مهمل (سيتم حذفه في المستقبل)
--fail-fast
التوقف عن المزامنة بعد حدوث الخطأ الأول
--force-sync
الكتابة فوق دليل git موجود إذا كان يحتاج إلى الإشارة إلى دليل كائنات مختلف. تحذير: قد يؤدي ذلك إلى فقدان البيانات
--force-checkout
فرض سحب الملفات حتى لو نتج عنه التخلص من التعديلات غير الملتزم بها. تحذير: قد يؤدي ذلك إلى فقدان البيانات
--force-remove-dirty
فرض إزالة المشاريع ذات التعديلات غير الملتزم بها إذا لم تعد المشاريع موجودة في البيان. تحذير: قد يؤدي ذلك إلى فقدان البيانات
--rebase
إعادة تطبيق الالتزامات المحلية بغض النظر عما إذا كانت منشورة
-l, --local-only
تحديث شجرة العمل فقط، لا يتم جلب الملفات
--no-manifest-update, --nmu
استخدام سحب الملفات الحالي كما هو. (عدم التحديث إلى أحدث مراجعة)
--interleaved
جلب الملفات وسحبها بالتوازي (تجريبي)
-n, --network-only
جلب الملفات فقط، لا يتم تحديث شجرة العمل
-d, --detach
فصل المشاريع مرة أخرى إلى مراجعة البيان
-c, --current-branch
جلب الفرع الحالي فقط من الخادم
--no-current-branch
جلب جميع الفروع من الخادم
-m NAME.xml, --manifest-name=NAME.xml
بيان مؤقت لاستخدامه في هذه المزامنة
--clone-bundle
تمكين استخدام /clone.bundle على HTTP/HTTPS
--no-clone-bundle
تعطيل استخدام /clone.bundle على HTTP/HTTPS
-u MANIFEST_SERVER_USERNAME, --manifest-server-username=MANIFEST_SERVER_USERNAME
اسم المستخدم للمصادقة مع خادم البيان
-p MANIFEST_SERVER_PASSWORD, --manifest-server-password=MANIFEST_SERVER_PASSWORD
كلمة المرور للمصادقة مع خادم البيان
--fetch-submodules
جلب الوحدات الفرعية من الخادم
--use-superproject
استخدام مشروع البيان الرئيسي لمزامنة المشاريع؛ يتضمن -c
--no-use-superproject
تعطيل استخدام مشاريع البيان الرئيسية
--tags
جلب العلامات
--no-tags
لا تقم بجلب العلامات (الافتراضي)
--optimized-fetch
جلب المشاريع المثبتة إلى sha1 فقط إذا لم يكن المراجعة موجودًا محليًا
--retry-fetches=RETRY_FETCHES
عدد مرات إعادة محاولة جلب الملفات عند حدوث أخطاء عابرة
--prune
حذف المراجع التي لم تعد موجودة عن بعد (الافتراضي)
--no-prune
لا تقم بحذف المراجع التي لم تعد موجودة عن بعد
--auto-gc
تشغيل جمع القمامة على جميع المشاريع المتزامنة
--no-auto-gc
لا تقم بتشغيل جمع القمامة على أي مشاريع (الافتراضي)
-s, --smart-sync
مزامنة ذكية باستخدام البيان من آخر بناء جيد معروف
-t SMART_TAG, --smart-tag=SMART_TAG
مزامنة ذكية باستخدام البيان من علامة معروفة

خيارات التسجيل:

-v, --verbose
عرض كل المخرجات
-q, --quiet
عرض الأخطاء فقط

خيارات متعددة البيانات:

--outer-manifest
ابدأ التشغيل من البيان الخارجي
--no-outer-manifest
لا تقم بالتشغيل على البيانات الخارجية
--this-manifest-only
قم بالتشغيل على هذا البيان (الفرعي) فقط
--no-this-manifest-only, --all-manifests
قم بالتشغيل على هذا البيان وبياناته الفرعية

خيارات إصدار repo:

--no-repo-verify
لا تقم بالتحقق من كود مصدر repo

قم بتشغيل `repo help sync` لعرض الدليل التفصيلي.

التفاصيل

يقوم الأمر 'repo sync' بمزامنة مجلدات المشاريع المحلية مع المستودعات البعيدة المحددة في البيان. إذا لم يكن المشروع المحلي موجودًا بعد، فسيقوم بنسخ مجلد محلي جديد من المستودع البعيد وإعداد فروع التتبع كما هو محدد في البيان. إذا كان المشروع المحلي موجودًا بالفعل، فسيقوم 'repo sync' بتحديث الفروع البعيدة وإعادة تطبيق أي تغييرات محلية جديدة فوق تغييرات الخادم الجديدة.

سيقوم 'repo sync' بمزامنة جميع المشاريع المدرجة في سطر الأوامر. يمكن تحديد المشاريع إما بالاسم، أو بالمسار النسبي أو المطلق لمجلد المشروع المحلي. إذا لم يتم تحديد أي مشاريع، فسيقوم 'repo sync' بمزامنة جميع المشاريع المدرجة في البيان.

يمكن استخدام الخيار -d/--detach لتبديل المشاريع المحددة مرة أخرى إلى مراجعة البيان. هذا الخيار مفيد بشكل خاص إذا كان المشروع موجودًا حاليًا على فرع موضوع، ولكن مراجعة البيان مطلوبة مؤقتًا.

يمكن استخدام الخيار -s/--smart-sync للمزامنة مع بناء جيد معروف كما هو محدد بواسطة عنصر manifest-server في البيان الحالي. الخيار -t/--smart-tag مشابه ويسمح لك بتحديد علامة/تسمية مخصصة.

يمكن استخدام الخيارات -u/--manifest-server-username و -p/--manifest-server-password لتحديد اسم مستخدم وكلمة مرور للمصادقة مع خادم البيان عند استخدام الخيار -s أو -t.

إذا لم يتم تحديد -u و -p عند استخدام الخيار -s أو -t، فسيحاول 'repo sync' قراءة بيانات الاعتماد للمصادقة مع خادم البيان من ملف .netrc الخاص بالمستخدم.

لن يستخدم 'repo sync' بيانات اعتماد المصادقة من -u/-p أو .netrc i

repo-sync(1)

NAME

repo-sync — Synchronize repositories

SYNOPSIS

repo sync [−h|−−help] [−c|−−current-branch] [−−clone-bundle] [−−no-clone-bundle] [−−depth=DEPTH] [−−fail-fast] [−−force-checkout] [−−force-remove-dirty] [−−force-sync] [−−fetch-submodules] [−−fetch-tags] [−−jobs=N] [−−main-user=USER] [−−optimize-fetch] [−−prune] [−−quiet] [−−reference=REFERENCE] [−−sat-url=URL] [−−submodule-user=USER] [−−upload-dir=DIR] [−v|−−verbose] [−−with-dependencies] [−−no-tags] [−−all-branches] [−−current-branch] [−−all-files] [−−no-pseudo-selective-sync] [−−pseudo-selective-sync] [PROJECT...]

DESCRIPTION

Synchronize working tree files to the manifest version.

This command is used to download the specific version of the source code specified by the manifest file.

If the manifest file specifies a remote name other than "origin", repo will create a remote named after the manifest file name. The remote name will be "origin" if the manifest file does not specify one.

If the manifest file specifies a URL with embedded credentials, repo will use those credentials to access the repository. Otherwise, if the manifest server specified in the manifest file already includes credentials.

OPTIONS

All options can be specified on the command line.

The --jobs=N option can be used to specify how many projects to sync in parallel. Defaults to 4.00.

The --fail-fast option can be used to halt syncing as soon as possible when the first project fails to sync.

The --force-sync option can be used to overwrite existing git directories if they have previously been linked to a different object directory. WARNING: This may cause data to be lost since refs may be removed when overwriting.

The --force-checkout option can be used to force git to switch revs even if the index or the working tree differs from HEAD, and if there are untracked files. WARNING: This may cause data to be lost since uncommitted changes may be removed.

The --force-remove-dirty option can be used to remove previously used projects with uncommitted changes. WARNING: This may cause data to be lost since uncommitted changes may be removed with projects that no longer exist in the manifest.

The --no-clone-bundle option disables any attempt to use $URL/clone.bundle to bootstrap a new Git repository from a resumeable bundle file on a content delivery network. This may be necessary if there are problems with the local Python HTTP client or proxy configuration, but the Git binary works.

The --fetch-submodules option enables fetching Git submodules of a project from server.

The -c/--current-branch option can be used to only fetch objects that are on the branch specified by a project's revision.

The --optimized-fetch option can be used to only fetch projects that are fixed to a sha1 revision if the sha1 revision does not already exist locally.

The --prune option can be used to remove any refs that no longer exist on the remote.

The --auto-gc option can be used to trigger garbage collection on all projects. By default, repo does not run garbage collection.

DETAILS

SSH Connections

If at least one project remote URL uses an SSH connection (ssh://, git+ssh://, or user@host:path syntax) repo will automatically enable the SSH ControlMaster option when connecting to that host. This feature permits other projects in the same 'repo sync' session to reuse the same SSH tunnel, saving connection setup overheads.

To disable this behavior on UNIX platforms, set the GIT_SSH environment variable to 'ssh'. For example:

export GIT_SSH=ssh repo sync

Compatibility

This feature is automatically disabled on Windows, due to the lack of UNIX domain socket support.

This feature is not compatible with url.insteadof rewrites in the user's ~/.gitconfig. 'repo sync' is currently not able to perform the rewrite early enough to establish the ControlMaster tunnel.

If the remote SSH daemon is Gerrit Code Review, version 2.0.10 or later is required to fix a server side protocol bug.
