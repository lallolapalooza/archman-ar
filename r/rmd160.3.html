rmd160(3)

الحزمة: libmd

التراخيص: BSD

RMD160(3) Manual de Funciones de Biblioteca RMD160(3)

الاسم

RMD160Init، RMD160Update، RMD160Pad، RMD160Final، RMD160Transform، RMD160End، RMD160File، RMD160FileChunk، RMD160Data — حساب "RIPEMD-160" لمُلخص الرسالة

المكتبة

مكتبة دعم ملخصات الرسائل (MD4، MD5، إلخ) (libmd، -lmd)

ملخص

#include <sys/types.h>
#include <rmd160.h>

void
RMD160Init(RMD160_CTX *context);

void
RMD160Update(RMD160_CTX *context, const uint8_t *data, uint32_t nbytes);

void
RMD160Pad(RMD160_CTX *context);

void
RMD160Final(uint8_t digest[RMD160_DIGEST_LENGTH], RMD160_CTX *context);

void
RMD160Transform(uint32_t state[5], const uint8_t block[RMD160_BLOCK_LENGTH]);

char *
RMD160End(RMD160_CTX *context, char *buf);

char *
RMD160File(const char *filename, char *buf);

char *
RMD160FileChunk(const char *filename, char *buf, off_t offset, off_t length);

char *
RMD160Data(const uint8_t *data, size_t len, char *buf);

الوصف

تنفذ دوال RMD160 خوارزمية التجزئة لمُلخص الرسالة RIPE (RMD-160) بطول 160 بت. يتم استخدام RMD-160 لإنشاء تمثيل مكثف للرسالة يسمى ملخص الرسالة. تأخذ الخوارزمية رسالة أقل من 2^64 بت كمدخل وتنتج ملخصًا بطول 160 بت مناسب للاستخدام كتوقيع رقمي.

تعتبر دوال RMD160 أكثر أمانًا من دوال md4(3)، md5(3) و sha1(3). تشترك جميعها في واجهة متشابهة.

تقوم الدالة RMD160Init() بتهيئة RMD160_CTX context للاستخدام مع RMD160Update()، و RMD160Final(). تضيف الدالة RMD160Update() data بطول nbytes إلى RMD160_CTX المحدد بواسطة context. يتم استدعاء RMD160Final() عند إضافة جميع البيانات عبر RMD160Update() وتخزين ملخص الرسالة في المعلمة digest.

يمكن استخدام الدالة RMD160Pad() لتطبيق الحشو على ملخص الرسالة كما في RMD160Final()، ولكن لا يزال يمكن استخدام السياق الحالي مع RMD160Update().

تستخدم الدالة RMD160Transform() بواسطة RMD160Update() لتجزئة كتل 512 بت وتشكل جوهر الخوارزمية. يجب على معظم البرامج استخدام الواجهة التي توفرها RMD160Init()، RMD160Update() و RMD160Final() بدلاً من استدعاء RMD160Transform() مباشرة.

الدالة RMD160End() هي واجهة أمامية لـ RMD160Final() تقوم بتحويل الملخص إلى تمثيل ASCII للملخص ذي الـ 160 بت بالنظام الست عشري.

تقوم الدالة RMD160File() بحساب الملخص لملف وإرجاع النتيجة عبر RMD160End(). إذا لم تتمكن RMD160File() من فتح الملف، يتم إرجاع مؤشر NULL.

RMD160FileChunk() تعمل بشكل مشابه لـ RMD160File() ولكنها تحسب الملخص فقط لجزء الملف الذي يبدأ عند offset ويستمر لمدة length بايت أو حتى نهاية الملف، أيهما يأتي أولاً. يمكن تحديد length صفر للقراءة حتى نهاية الملف. سيتم تجاهل length أو offset السالبة.

تقوم الدالة RMD160Data() بحساب ملخص لسلسلة عشوائية وترجع النتيجة عبر RMD160End().

لكل من الدوال RMD160End()، RMD160File()، و RMD160Data()، يجب أن تكون المعلمة buf إما سلسلة نصية بحجم 41 حرفًا على الأقل أو مؤشر NULL. في الحالة الأخيرة، سيتم تخصيص مساحة ديناميكيًا عبر malloc(3) ويجب تحريرها باستخدام free(3) عند عدم الحاجة إليها.

أمثلة

سيقوم مقتطف الكود التالي بحساب ملخص للسلسلة النصية "abc" وهو "0x8eb208f7e05d987a9b044a8e98c6b087f15a0bfc".

RMD160_CTX rmd;
uint8_t results[RMD160_DIGEST_LENGTH];
char *buf;
int n;

buf = "abc";
n = strlen(buf);
RMD160Init(&rmd);
RMD160Update(&rmd, (uint8_t *)buf, n);
RMD160Final(results, &rmd);

/* Print the digest as one long hex value */
printf("0x");
for (n = 0; n < RMD160_DIGEST_LENGTH; n++)
	printf("%02x", results[n]);
putchar('\n');

بدلاً من ذلك، يمكن استخدام الدوال المساعدة بالطريقة التالية:

RMD160_CTX rmd;
uint8_t output[RMD160_DIGEST_STRING_LENGTH];
char *buf = "abc";

printf("0x%s\n", RMD160Data(buf, strlen(buf), output));

NAME

rmd160, rmd160init, rmd160update, rmd160final, RMD160End, RMD160File, RMD160FileChunk, RMD160Data ― RIPEMD-160 cryptographic hash function

LIBRARY

Message Digest (libmd, -lmd)

SYNOPSIS

#include <md5.h>

uint8_t *rmd160init( uint8_t *digest );
uint8_t *rmd160update( uint8_t *digest, const void *data, size_t len );
uint8_t *rmd160final( uint8_t *digest );

char *RMD160End( struct RMD160_CTX *ctx, char *buf );
char *RMD160File( const char *filename, char *buf );
char *RMD160FileChunk( const char *filename, char *buf, off_t offset, off_t length );
char *RMD160Data( const uint8_t *data, size_t len, char *buf );

DESCRIPTION

The RIPEMD-160 algorithm is a cryptographic hash function producing a 160-bit (20-byte) hash value. It is intended to provide better security than its predecessor, MD5, and the earlier RIPEMD. RIPEMD-160 is used in several public key infrastructure systems, notably in the generation of Bitcoin addresses.

The functions rmd160init, rmd160update, and rmd160final are the core functions for computing the hash. They operate on a context buffer, of type uint8_t, which must be at least 20 bytes in size.

The functions RMD160End, RMD160File, RMD160FileChunk, and RMD160Data provide a simpler, higher-level interface to compute the hash value.

The RMD160End function takes a pointer to a struct RMD160_CTX context, computes the hash, and stores the result as a 40-character hexadecimal string in the buffer pointed to by buf. The context buffer must be at least 40 bytes.

The RMD160File function computes the RIPEMD-160 hash of the file named by filename and returns the result as a 40-character hexadecimal string in buf. The buffer must be at least 40 bytes.

The RMD160FileChunk function is similar to RMD160File but computes the hash only for the specified chunk of the file, starting at offset and of size length.

The RMD160Data function computes the RIPEMD-160 hash of the data pointed to by data, of length len, and returns the result as a 40-character hexadecimal string in buf. The buffer must be at least 40 bytes.

EXAMPLES

Compute the RIPEMD-160 hash of a string:

    char digest[41];
    char *hash = RMD160Data("hello world", strlen("hello world"), digest);
    printf("RIPEMD-160(\"hello world\") = %s\n", hash);

HISTORY

The RMD-160 functions first appeared in OpenBSD 2.1.

A paper describing the RIPEMD-160 cryptographic hash function appeared in: H. Dobbertin, G. L. Peter, and Y. L. Wang, RIPEMD-160, a new 160 bit cryptographic hash function, Fast Software Encryption, LNCS 1039, pp. 329-341, Springer-Verlag, 1996. Another related paper by R. G. D. V. R. Preneel, The RIPEMD-160 cryptographic hash function, Dr. Dobb's Journal, Vol. 22, No. 1, pp. 24-28, January 1997.

AUTHORS

This implementation of RMD-160 was written by Markus Friedl.

The RMD160End(), RMD160File(), RMD160FileChunk(), and RMD160Data() helper functions are derived from code written by Poul-Henning Kamp.

CAVEATS

If a message digest is to be copied to a multi-byte type (ie: an array of five 32-bit integers) it will be necessary to perform byte swapping on little endian machines such as the i386, alpha, and vax.
