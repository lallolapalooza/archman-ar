DESCRIPTION

The routines described in this man page are part of the Sun Microsystems Remote Procedure Call (RPC) library. RPC allows a process on one machine to call a procedure in a process on another machine. This interface is designed to be machine-independent.

The RPC library consists of two main parts: the client side and the server side.

On the client side, routines are used to create a client handle, specify the authentication credentials, and make the remote procedure call. The routines like clnt_create, clnttcp_create, and clntudp_create create a client handle. The handle is then used with clnt_call to make the actual RPC. The routines clnt_destroy and clnt_freeres are used to free resources associated with the client handle.

The authentication routines authunix_create, authsys_create, and authnone_create create authentication credentials that can be associated with a client handle. The auth_destroy routine frees the authentication credentials.

The XDR (eXternal Data Representation) routines are used for data serialization and deserialization. Routines like xdr_callmsg and xdr_replymsg are used to serialize and deserialize RPC call and reply messages. xdr_free is used to free memory allocated by XDR.

On the server side, routines are used to register procedures with the RPC system, dispatch incoming calls, and send replies. Routines like svc_create, svcraw_create, svctcp_create, svcudp_create, and svcudp_bufcreate create server handles. These handles are used to receive and dispatch incoming RPC calls. svc_register and svc_unregister are used to register and unregister service routines with the RPC dispatcher. svc_run dispatches incoming calls. svc_sendreply sends a reply to the client. The svc_destroy routine frees server resources.

The svc_getreq and svc_getreqset routines are used by the server to process incoming requests. The routines svcerr_auth, svcerr_decode, svcerr_noproc, svcerr_noprog, svcerr_progvers, svcerr_systemerr, and svcerr_weakauth are used to send specific error replies to the client.

The XDR routines xdr_accepted_reply and xdr_rejected_reply are used to serialize and deserialize RPC accept and reject messages, respectively. xdr_authunix_parms and xdr_authsys_parms are used for serialization and deserialization of authentication parameters for AUTH_UNIX and AUTH_SYS authentication flavors. xdr_opaque_auth serializes and deserializes opaque authentication data. xdr_callhdr serializes and deserializes the header of an RPC call message.

\n
\n

Nettype

The RPC library supports different transport protocols and network types. The clnt_create routine uses the NETPATH environment variable or the /etc/netconfig file to determine the network type and transport protocol to use. If these are not specified, it defaults to UDP/IP.

The following network types are typically supported:

“udp”
UDP over IP.
“tcp”
TCP over IP.
“udp6”
UDP over IPv6.
“tcp6”
TCP over IPv6.

The clnt_create_vers routine allows specifying the version of the RPC service to connect to. If version 0 is specified, clnt_create_vers tries to find the highest version number supported by the server.

The clnt_control routine can be used to set or get various options for a client handle, such as the time-out value or the remote address.

The svc_create, svcraw_create, svctcp_create, svcudp_create, and svcudp_bufcreate routines create server handles for different transport protocols. svcudp_bufcreate allows specifying the send and receive buffer sizes.

The svc_register routine registers a program number and version number with the RPC binder service, making the service accessible to clients. svc_unregister removes the registration.

The svc_getreq and svc_getreqset routines are used by the server to process incoming requests. svc_run blocks indefinitely, processing requests for all registered services.

Data Structures

The RPC library uses several data structures to represent RPC messages, authentication information, and client/server handles.

The AUTH Structure
The AUTH structure contains information about the authentication credentials used for an RPC call. It typically includes the authentication flavor (e.g., AUTH_UNIX, AUTH_NONE) and the corresponding credentials. The exact members depend on the authentication flavor.
The CLIENT Structure
The CLIENT structure represents a client handle. It contains information about the connection to the RPC server, including the transport handle, the remote address, and the authentication credentials. This structure is opaque to the user and should only be manipulated through the provided RPC routines.
The SVCXPRT structure
The SVCXPRT structure represents a server handle. It contains information about the transport endpoint used by the RPC server, including the file descriptor, the transport type, and pointers to routines for sending and receiving messages. This structure is also opaque to the user.
The svc_reg structure
This structure is used internally by the RPC library to manage registered services. It is not typically accessed directly by applications.
The XDR structure
The XDR structure represents an XDR stream. It contains a pointer to the underlying buffer or device, and pointers to routines for performing XDR operations such as serialization, deserialization, and seeking.
