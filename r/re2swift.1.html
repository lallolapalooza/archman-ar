الاسم

re2swift - توليد محللات معجمية سريعة لـ Swift

الموجز

re2swift [ خيارات ] [ تحذيرات ] المدخل

يمكن أن يكون المدخل إما ملفًا أو - لـ stdin.

مقدمة

يعمل re2swift كمعالج أولي. يقرأ ملف المدخل (وهو عادةً برنامج بلغة Swift، ولكنه يمكن أن يكون أي شيء) ويبحث عن كتل التعليمات البرمجية المحاطة بعلامات بداية/نهاية ذات شكل خاص. يتم نسخ النص خارج هذه الكتل حرفياً إلى ملف المخرجات. تتم معالجة محتويات الكتل بواسطة re2swift. يقوم بترجمتها إلى تعليمات برمجية بلغة Swift ويخرج التعليمات البرمجية المولدة في مكان الكتلة.

إليك مثال لبرنامج صغير يتحقق مما إذا كانت سلسلة معينة تحتوي على رقم عشري:

// re2swift $INPUT -o $OUTPUT -i
func lex(_ yyinput: UnsafePointer<UInt8>) -> Bool {
  var yycursor = 0
  /*!re2c
    re2c:yyfill:enable = 0;
    [1-9][0-9]* { return true }
    *           { return false }
  */
}
assert(lex("1234"))

في المخرجات، استبدل re2swift الكتلة في المنتصف بالتعليمات البرمجية المولدة:

/* تم الإنشاء بواسطة re2swift */
// re2swift $INPUT -o $OUTPUT -i
func lex(_ yyinput: UnsafePointer<UInt8>) -> Bool {
  var yycursor = 0
  var yych: UInt8 = 0
  var yystate: UInt = 0
  yyl: while true {
    switch yystate {
      case 0:
        yych = yyinput[yycursor]
        yycursor += 1
        switch yych {
          case 0x31...0x39:
            yystate = 2
            continue yyl
          default:
            yystate = 1
            continue yyl
        }
      case 1: return false
      case 2:
        yych = yyinput[yycursor]
        switch yych {
          case 0x30...0x39:
            yycursor += 1
            yystate = 2
            continue yyl
          default:
            yystate = 3
            continue yyl
        }
      case 3: return true
      default: fatalError("خطأ في المحلل المعجمي الداخلي")
    }
  }
}
assert(lex("1234"))

الأساسيات

يتكون برنامج re2swift من تسلسل من الكتل المتناوبة مع التعليمات البرمجية باللغة المستهدفة. قد تحتوي الكتلة على تعريفات، إعدادات، قواعد، إجراءات و توجيهات بأي ترتيب:

الاسم = تعبير-نمطي ;
التعريف يربط الاسم بـ التعبير-النمطي. يمكن أن تحتوي الأسماء على أحرف أبجدية رقمية وشرطة سفلية. يعطي قسم التعبيرات النمطية نظرة عامة على بناء جمل re2swift للتعبيرات النمطية. بمجرد تعريفه، يمكن استخدام الاسم في تعبيرات نمطية أخرى وفي القواعد. لا يُسمح بالاستدعاء الذاتي في التعريفات المسماة، ويجب تعريف كل اسم قبل استخدامه. ترث الكتلة التعريفات المسماة من النطاق العام. إعادة تعريف اسم موجود في النطاق الحالي هو خطأ.
الإعداد = القيمة ;
الإعداد يسمح بتغيير سلوك re2swift وتخصيص التعليمات البرمجية المولدة. للحصول على قائمة كاملة بالإعدادات التي يدعمها re2swift، راجع قسم الإعدادات. اعتمادًا على إعداد معين، يمكن أن تكون القيمة كلمة رئيسية، أو رقم عدد صحيح غير سالب، أو سلسلة من سطر واحد يجب أن تكون محاطة بعلامات اقتباس مزدوجة أو مفردة ما لم تتكون من أحرف أبجدية رقمية. ترث الكتلة الإعدادات من النطاق العام وقد تعيد تعريفها أو تضيف إعدادات جديدة. تؤثر الإعدادات المعرفة داخل كتلة على الكتلة بأكملها، حتى لو ظهرت في نهايتها.
تعبير-نمطي تعليمات-برمجية
القاعدة تربط التعبير-النمطي بإجراء الدلالات المرتبط بها (كتلة من التعليمات البرمجية في أقواس متعرجة، أو كتلة من التعليمات البرمجية تبدأ بـ := وتنتهي بسطر جديد متبوع بأي حرف غير مسافة بيضاء). إذا تطابق التعبير-النمطي، يتم تنفيذ التعليمات-البرمجية المرتبطة به. إذا تطابقت قواعد متعددة، فإن أطول تطابق له الأسبقية. إذا تطابقت قواعد متعددة لنفس السلسلة، فإن القاعدة الأولى لها الأسبقية. هناك قاعدتان خاصتان: القاعدة الافتراضية * وقاعدة نهاية الإدخال $. يجب تعريف القاعدة الافتراضية، ولها أقل أولوية بغض النظر عن مكانها في الكتلة، وتتطابق مع أي وحدة رمز (ليس بالضرورة حرف صالح، انظر قسم دعم الترميز). يجب تعريف قاعدة نهاية الإدخال إذا تم استخدام طريقة التعامل مع نهاية الإدخال المقابلة. مع حالات البداية، تكون القواعد ذات بناء جمل أكثر تعقيدًا.
!إجراء تعليمات-برمجية
الإجراء يربط كتلة تعليمات-برمجية معرفة من قبل المستخدم بمكان معين في الآلة الحتمية المحدودة المولدة (بنفس طريقة ربط الإجراءات الدلالية بالدول النهائية). راجع قسم الإجراءات للحصول على قائمة كاملة بالإجراءات المعرفة مسبقًا.
!توجيه ;
التوجيه هو أحد العبارات الخاصة المعرفة مسبقًا. لكل توجيه غرض فريد. راجع قسم التوجيهات للحصول على التفاصيل.

الكتل

علامات بداية ونهاية الكتلة هي إما /*!re2c و */، أو %{ و %} (كلا الأسلوبين مدعومان). بدءًا من الإصدار 2.2، قد تحتوي الكتل على أسماء اختيارية تسمح بالإشارة إليها في كتل أخرى. هناك أنواع مختلفة من الكتل:

/*!re2c[:<name>] ... */ أو %{[:<name>] ... %}
الكتلة العامة تحتوي على تعريفات، إعدادات، قواعد وتوجيهات. يقوم re2swift بتجميع التعبيرات النمطية المرتبطة بكل قاعدة في آلة حتمية محدودة، ويقوم بتشفيرها في شكل قفزات شرطية بلغة الهدف ويستبدل الكتلة بالتعليمات البرمجية المولدة. تضاف الأسماء والإعدادات المعرفة في كتلة عامة إلى النطاق العام وتصبح مرئية للكتل اللاحقة. في بداية البرنامج، يتم تهيئة النطاق العام بـ خيارات سطر الأوامر.
/*!local:re2c[:<name>] ... */ أو %{local[:<name>] ... %}
الكتلة المحلية تشبه الكتلة العامة، ولكن الأسماء والإعدادات فيها لها نطاق محلي (لا تؤثر على الكتل الأخرى).
/*!rules:re2c[:<name>] ... */ أو %{rules[:<name>] ... %}
كتلة القواعد تشبه الكتلة المحلية، ولكنها لا تولد أي تعليمات برمجية بنفسها، ولا تضيف أي تعريفات إلى النطاق العام - فهي مخصصة لإعادة استخدامها في كتل أخرى. هذه طريقة لمشاركة التعليمات البرمجية (مزيد من التفاصيل في قسم الكتل القابلة لإعادة الاستخدام). قبل الإصدار 2.2 من re2swift، كانت كتل القواعد تتطلب الخيار -r --reusable.
/*!use:re2c[:<name>] ... */ أو %{use[:<name>] ... %}
كتلة استخدام تشير إلى كتلة قواعد معرفة مسبقًا. إذا تم تحديد الاسم، يبحث re2swift عن كتل قواعد بهذا الاسم. وإلا، يتم استخدام أحدث كتلة قواعد (سواء كانت مسماة أو غير مسماة). يمكن لكتلة الاستخدام إضافة تعريفات وإعدادات وقواعد خاصة بها، والتي تضاف إلى تلك الموجودة في كتلة القواعد المشار إليها. قبل الإصدار 2.2 من re2swift، كانت كتل الاستخدام تتطلب الخيار -r --reusable.
/*!max:re2c[:<name1>[:<name2>...]] ... */ أو %{max[:<name1>[:<name2>...]] ... %}
كتلة تولد تعريف YYMAXFILL. تحدد قائمة اختيارية بأسماء الكتل أي الكتل يجب تضمينها عند حساب قيمة YYMAXFILL (إذا كانت القائمة فارغة، يتم تضمين جميع الكتل). بشكل افتراضي، تكون التعليمات البرمجية المولدة تعريفًا ماكرو لـ C (#define YYMAXFILL <n>)، أو متغير عام لـ Go (var YYMAXFILL int = <n>). يمكن تخصيصها بإعداد اختياري format يحدد سلسلة قالب حيث يتم استبدال @@{max} (أو @@ اختصارًا) بالقيمة الرقمية لـ YYMAXFILL.
/*!maxnmatch:re2c[:<name1>[:<name2>...]] ... */ أو %{maxnmatch[:<name1>[:<name2>...]] ... %}

حالة قابلة للتخزين

مع الخيار --storable-state، تنشئ re2swift محللًا يمكنه تخزين حالته الحالية، والعودة إلى المستدعي، ثم استئناف العمليات بالضبط من حيث توقف. الوضع الافتراضي للتشغيل في re2swift هو نموذج "السحب" (pull)، حيث يقوم المحلل "بسحب" المزيد من المدخلات كلما احتاجها. قد يكون هذا غير مقبول في الحالات التي تكون فيها المدخلات متاحة جزءًا بجزء (على سبيل المثال، إذا تم استدعاء المحلل بواسطة المحلل اللغوي، أو إذا كان برنامج المحلل يتواصل عبر بروتوكول مقبس مع برنامج آخر يجب أن ينتظر ردًا من المحلل قبل أن يرسل الرسالة التالية). تم تصميم ميزة الحالة القابلة للتخزين خصيصًا لهذه الحالات: فهي تسمح بإنشاء محللات تعمل في نموذج "الدفع" (push). عندما يحتاج المحلل إلى المزيد من المدخلات، فإنه يخزن حالته ويعود إلى المستدعي. لاحقًا، عندما تتوفر المزيد من المدخلات، يستأنف المستدعي المحلل بالضبط من حيث توقف. هناك بعض التغييرات الضرورية مقارنة بنموذج "السحب":

  • تعريف البدائيات YYSETSTATE() و YYGETSTATE(state).
  • تعريف المتغيرات yych، yyaccept (إذا تم استخدامها) و state كجزء من حالة المحلل الدائمة. يجب تهيئة المتغير state إلى -1.
  • يجب أن يعود YYFILL إلى البرنامج الخارجي بدلاً من محاولة توفير المزيد من المدخلات. يجب أن يشير رمز الإرجاع إلى أن المحلل يحتاج إلى المزيد من المدخلات.
  • يجب على البرنامج الخارجي التعرف على المواقف التي يحتاج فيها المحلل إلى المزيد من المدخلات والاستجابة بشكل مناسب.
  • اختياريًا، استخدم كتلة getstate لإنشاء مفتاح YYGETSTATE منفصل عن المحلل الرئيسي. يعمل هذا فقط مع اللغات التي تحتوي على goto (وليس في وضع --loop-switch).
  • استخدم re2c:eof وطريقة الحارس مع فحوصات الحدود للتعامل مع نهاية المدخلات. قد لا تعمل طريقة الحشو (padding-based) لأن من غير الواضح متى يتم إضافة الحشو: قد لا تكون نهاية المدخلات الحالية هي النهاية المطلقة للمدخلات، وإضافة الحشو مبكرًا جدًا قد تقطع جزءًا من الكيان الجشع المقروء جزئيًا. علاوة على ذلك، بسبب منطق البرنامج عالي المستوى، قد يعتمد الحصول على المزيد من المدخلات على معالجة الكيان في نهاية المخزن المؤقت (والذي يتم حجبه بالفعل بسبب شرط نهاية المدخلات).

إليك مثال لمحلل نموذج "الدفع" يحاكي قراءة حزم من مقبس. يتكرر المحلل حتى يواجه نهاية المدخلات ويعود إلى الدالة المستدعية. يقوم المستدعي بتوفير المزيد من المدخلات عن طريق "إرسال" الحزمة التالية ويستأنف التحليل. تتوقف هذه العملية عند إرسال جميع الحزم، أو عند حدوث خطأ.

    // Error: No space. In the real world we can reallocate a larger buffer.
    if free < 1 {
      return .bigPacket
    }
    // Shift buffer contents, discarding everything up to the current lexeme.
    let shift = self.token
    self.yyinput.replaceSubrange(..<used, with: self.yyinput[shift..<self.yylimit])
    self.yylimit  -= shift
    self.yycursor -= shift
    self.yymarker -= shift
    self.token = 0
    // Fill free space at the end of buffer with new data.
    do {
      if let data = try self.file.read(upToCount: free) {
        self.yyinput.replaceSubrange(self.yylimit..<(self.yylimit + data.count), with: data)
        self.yylimit += data.count
      }
    } catch {
      fatalError("cannot read from file: \(error.localizedDescription)")
    }
    self.yyinput[self.yylimit] = 0  // append sentinel
    return .ready
  }
  enum Status {
    case end, ready, waiting, badPacket, bigPacket
  }
}

يتضمن ملف include/unicode_categories.re
    تعريفات re2swift للفئات القياسية لـ Unicode.


يحدد الخيار --input-encoding تشفير ملف المصدر، والذي يمكن استخدامه لتمكين الحروف الحرفية لـ Unicode في التعبيرات العادية. على سبيل المثال، يخبر --input-encoding utf8 re2swift أن ملف المصدر هو بتنسيق UTF8 (وهو يختلف عن --utf8 الذي يحدد تشفير نص الإدخال). يحدد الخيار --encoding-policy الطريقة التي يتعامل بها re2swift مع بدائل Unicode (نقاط الرموز في النطاق [0xD800-0xDFFF]).

ملفات التضمين


يسمح re2swift بتضمين ملفات أخرى باستخدام كتلة بالشكل /*!include:re2c FILE */ أو %{include FILE %}، أو توجيه داخل كتلة !include FILE ;، حيث FILE هو مسار الملف المراد تضمينه. يبحث re2swift عن ملفات التضمين في دليل الملف الذي يتضمنها وفي مواقع التضمين، والتي يمكن تحديدها باستخدام الخيار -I. تعمل كتل/توجيهات التضمين في re2swift بنفس طريقة عمل #include في C/C++: يتم نسخ محتويات FILE حرفياً في مكان الكتلة/التوجيه. قد تحتوي ملفات التضمين على تضمينات إضافية خاصة بها. استخدم الخيار --depfile لتتبع تبعيات البناء لملف الإخراج على ملفات التضمين. يوفر re2swift بعض ملفات التضمين المحددة مسبقاً والتي يمكن العثور عليها في الدليل الفرعي include/ للمشروع. تحتوي هذه الملفات على تعريفات قد تكون مفيدة للمشاريع الأخرى (مثل فئات Unicode) وتشكل شيئاً مثل مكتبة قياسية لـ re2swift. فيما يلي مثال على استخدام ملفات التضمين.

ملفات الرأس


يسمح re2swift بإنشاء ملف رأس من ملف .re المدخل باستخدام الخيار --header أو التكوين re2c:header وأزواج الكتل بالشكل /*!header:re2c:on*/ و /*!header:re2c:off*/، أو %{header:on%} و %{header:off%}. تحدد الكتلة الأولى بداية ملف الرأس، وتحدد الكتلة الثانية نهايته. تتم معالجة كل شيء بين هاتين الكتلتين بواسطة re2swift، ويتم كتابة الكود المُنشأ إلى الملف المحدد بالخيار --header أو التكوين re2c:header (أو stdout إذا لم يتم استخدام أي خيار أو تكوين). قد يكون ملف الرأس المُنشأ تلقائياً مطلوباً في الحالات التي يُستخدم فيها re2swift لإنشاء تعريفات يجب أن تكون مرئية من وحدات ترجمة أخرى.

برامج الهيكل العظمي


باستخدام الخيار -S, --skeleton، يتجاهل re2swift أي كود غير re2swift وينشئ برنامج C مكتفٍ ذاتيًا يمكن تجميعه وتنفيذه لاحقًا. يتكون البرنامج من كود المحلل اللغوي وبيانات الإدخال. لكل DFA مُنشأ (كتلة أو شرط)، ينشئ re2swift محللًا لغويًا مستقلًا وملفين: ملف .input يحتوي على سلاسل مشتقة من DFA وملف .keys يحتوي على النتائج المتوقعة للمطابقة. يقوم البرنامج بتشغيل كل محلل لغوي على ملف .input المقابل ويقارن النتائج بالتوقعات. برامج الهيكل العظمي مفيدة جدًا لعدة أسباب:




    
  
  • يمكنها التحقق من صحة تحسينات re2swift المختلفة (يتم إنشاء البيانات في مرحلة مبكرة من العملية، قبل حدوث أي تحويلات لـ DFA).
    • 
  
  • يمكن أن يكون إنشاء مجموعة من بيانات الإدخال مع تغطية جيدة مفيدًا لكل من الاختبار والقياس.
    • 
  
  • يتيح إنشاء برامج قابلة للتنفيذ مكتفية ذاتيًا الحصول على حالات اختبار مصغرة (قد يكون الكود الأصلي كبيرًا أو يحتوي على الكثير من التبعيات).
    • 





الصعوبة في إنشاء بيانات الإدخال هي أنه بالنسبة لجميع الحالات باستثناء الحالات البسيطة جدًا، فإن عدد سلاسل الإدخال الممكنة كبير جدًا (حتى لو كان طول السلسلة محدودًا). يحل re2swift هذه الصعوبة عن طريق إنشاء عدد كافٍ من السلاسل لتغطية جميع انتقالات DFA تقريبًا. يستخدم الخوارزمية التالية. أولاً، يبني هيكلًا عظميًا لـ DFA. بالنسبة للتشفيرات ذات حجم وحدة رمز بايت واحد (مثل ASCII، UTF-8، و EBCDIC)، فإن الهيكل العظمي هو مجرد نسخة طبق الأصل من DFA الأصلي. بالنسبة للتشفيرات ذات وحدات الرموز متعددة البايتات، فإن الهيكل العظمي هو نسخة من DFA مع إغفال انتقالات معينة: على وجه التحديد، يأخذ re2swift ما لا يزيد عن 256 وحدة رمز لكل نطاق متقطع مستمر يتوافق مع انتقال DFA. القيم المختارة موزعة بالتساوي وتشمل حدود النطاق. بدلاً من محاولة تغطية جميع المسارات الممكنة في الهيكل العظمي (وهو أمر غير عملي)، يقوم re2swift بإنشاء عدد كافٍ من المسارات لتغطية جميع انتقالات الهيكل العظمي، وبالتالي تشغيل القفزات الشرطية المقابلة في المحلل اللغوي. يقتصر تنفيذ الخوارزمية على حوالي 1 جيجابايت من الانتقالات ويستهلك كمية ثابتة من الذاكرة (يكتب re2swift البيانات إلى الملف بمجرد إنشائها).






التصور والتصحيح


باستخدام الخيار -D, --emit-dot، لا ينشئ re2swift كودًا. بدلاً من ذلك، يقوم بتفريغ DFA المُنشأ بتنسيق DOT. يمكن تحويل هذا التفريغ إلى صورة لـ DFA باستخدام Graphviz أو مكتبة أخرى. لاحظ أن هذا الخيار يعرض DFA النهائي بعد مروره بعدد من التحسينات والتحويلات. يمكن تفريغ المراحل المبكرة باستخدام خيارات تصحيح مختلفة، مثل --dump-nfa، --dump-dfa-raw، إلخ (راجع القائمة الكاملة للخيارات).
