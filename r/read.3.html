تحذير

هذا أمر متقدم وصعب. أنت لا تحتاج إليه إلا إذا كنت تعرف حقًا ما تفعله. معظم التطبيقات لن تحتاج إليه.

تاريخيًا، قدمت PhysicsFS الوصول إلى نظام الملفات الفعلي والأرشيفات داخل نظام الملفات هذا. ومع ذلك، في بعض الأحيان تحتاج إلى قوة أكبر من هذا. ربما تحتاج إلى توفير أرشيف موجود بالكامل في الذاكرة، أو تحتاج إلى ربط واجهة برمجة تطبيقات مدخلات/مخرجات ملف أخرى بـ PhysicsFS، أو تحتاج إلى ترجمة البتات (ربما لديك ملف .zip قياسي مشفر، وتحتاج إلى فك تشفيره أثناء التنقل لأرشيف zip غير المشتبه به).

PHYSFS_Io هي الواجهة التي تستخدمها الأرشيفات للحصول على بيانات الأرشيف. تاريخيًا، تم ربط هذا بمدخلات/مخرجات الملفات إلى نظام الملفات الفعلي، ولكن اعتبارًا من PhysicsFS 2.1، يمكن للتطبيقات توفير تطبيقات المدخلات/المخرجات الخاصة بها وقت التشغيل.

هذه الواجهة ليست بالضرورة ملاءمة عالمية للمدخلات/المخرجات. هناك عدد قليل من المتطلبات الجديرة بالملاحظة:

  • إنها تدعم فقط المدخلات/المخرجات المتزامنة (على الأقل، في الوقت الحالي).
  • يجب أن تكون قادرة على التكرار. إذا كان لديك مقبض ملف من fopen()، فيجب أن تكون قادرًا على إنشاء نسخة طبق الأصل فريدة منه (حتى يكون لدينا مقبضان لنفس الملف يمكن لكليهما البحث/القراءة/الخ. دون التدخل في بعضهما البعض).
  • يجب أن يعرفوا حجم مجموعة بياناتهم بالكامل.
  • يجب أن يكونوا قادرين على البحث والعودة إلى البداية عند الطلب.

... باختصار، ربما لن تقوم بإنشاء تنفيذ HTTP.

سلامة الخيوط: لا يُضمن أن تكون تطبيقات PHYSFS_Io آمنة للخيوط في حد ذاتها. تحت الغطاء حيث تستخدمها PhysicsFS، توفر المكتبة أقفالها الخاصة. إذا كنت تخطط لاستخدامها مباشرة من خيوط منفصلة، فيجب عليك إما استخدام المزامنات لحمايتها، أو عدم استخدام نفس PHYSFS_Io من خيطين في نفس الوقت.

توثيق الحقول

void(* PHYSFS_Io::destroy) (struct PHYSFS_Io *io)

تنظيف وإلغاء تخصيص مثيل المدخلات/المخرجات. تحرير الموارد المرتبطة، بما في ذلك (opaque) إذا كان ذلك منطبقًا.

يجب أن تنجح هذه الوظيفة دائمًا: على هذا النحو، فإنها تعيد void. قد يستدعي النظام وظيفة flush() الخاصة بك قبل ذلك. قد تبلغ عن فشل هناك إذا لزم الأمر. قد يتم استدعاء هذه الطريقة لاحقًا، في حالة فشل flush()، وفي هذه الحالة سيتعين عليك التخلي عن البيانات غير المفرغة والظروف الفاشلة الأخرى والتنظيف.

بمجرد استدعاء هذه الطريقة لمثيل معين، سيفترض النظام أنه غير آمن لمس هذا المثيل مرة أخرى وسيتخلص من أي مراجع له.

struct PHYSFS_Io *(* PHYSFS_Io::duplicate) (struct PHYSFS_Io *io)

تكرار مثيل المدخلات/المخرجات هذا. يجب أن ينتج عن هذا نسخة كاملة من PHYSFS_Io هذا، والتي يمكن أن تعيش بشكل مستقل تمامًا. يجب أن تكون النسخة قادرة على أداء جميع عملياتها دون التأثير على الأصل، بما في ذلك تدمير أي من الكائنين بشكل منفصل (لذلك، على سبيل المثال: لا يمكنهما مشاركة مقبض ملف؛ يحتاج كل منهما إلى مقبضه الخاص).

إذا لم تتمكن من تكرار مقبض، فمن القانوني إرجاع NULL، ولكنك ستحتاج بالتأكيد إلى هذه الوظيفة إذا كنت ترغب في استخدام هذا لـ PHYSFS_Io لدعم أرشيف.

int(* PHYSFS_Io::flush) (struct PHYSFS_Io *io)

إفراغ الموارد إلى الوسائط، أو إلى أي مكان آخر. هذه هي الفرصة للإبلاغ عن فشل الكتابات التي ادعت النجاح سابقًا، ولكن لا يزال لديها فرصة للفشل بالفعل. يمكن أن تكون هذه الطريقة NULL إذا لم يكن الإفراغ ضروريًا.

قد يتم استدعاء هذه الوظيفة قبل destroy()، حيث يمكنها الإبلاغ عن فشل ولا يمكن لـ destroy(). قد يتم استدعاؤها في أوقات أخرى أيضًا.

المعلمات

io مثيل المدخلات/المخرجات المراد إفراغه.

المرتجعات

صفر عند حدوث خطأ، غير صفر عند النجاح.

PHYSFS_sint64(* PHYSFS_Io::length) (struct PHYSFS_Io *io)

تحديد حجم مجموعة بيانات مثيل المدخلات/المخرجات. إرجاع عدد البايتات المتاحة في الملف، أو -1 إذا لم تتمكن من التحديد. سيكون الفشل قاتلاً تقريبًا للاستخدام المستمر لهذا الدفق، لذلك لا يمكنك ترك هذا غير منفذ.

المرتجعات

الحجم الكلي، بالبايت، لمجموعة البيانات.

void* PHYSFS_Io::opaque

بيانات النسخة لهذا الهيكل. كل نسخة لديها مؤشر مرتبط بها يمكن استخدامه لتخزين أي شيء تريده. هذا المؤشر خاص بكل نسخة من الدفق، لذلك يُفترض أنه سيتغير عند استدعاء duplicate(). يمكن إلغاء تخصيص هذا أثناء طريقة destroy().

PHYSFS_sint64(* PHYSFS_Io::read) (struct PHYSFS_Io *io, void *buf, PHYSFS_uint64 len)

قراءة المزيد من البيانات. قراءة (len) بايت من الواجهة، عند موضع المدخلات/المخرجات الحالي، وتخزينها في (buffer). يجب أن يتحرك موضع المدخلات/المخرجات الحالي للأمام بمقدار البايتات التي تمت قراءتها بنجاح.

ليس عليك تنفيذ هذا؛ قم بتعيينه إلى NULL إذا لم يتم تنفيذه. سيتم استخدام هذا فقط إذا تم فتح الملف للقراءة. إذا تم تعيينه إلى NULL، فسيتم استخدام تطبيق افتراضي يبلغ عن الفشل فورًا.

المعلمات

io مثيل المدخلات/المخرجات للقراءة منه.
buf المخزن المؤقت لتخزين البيانات فيه. يجب أن يكون بطول (len) بايت على الأقل ولا يمكن أن يكون NULL.
len عدد البايتات المراد قراءتها من الواجهة.

المرتجعات

عدد البايتات المقروءة من الملف، 0 عند نهاية الملف، -1 عند الفشل التام.

int(* PHYSFS_Io::seek) (struct PHYSFS_Io *io, PHYSFS_uint64 offset)

نقل موضع المدخلات/المخرجات إلى إزاحة بايت معينة من البداية. تنقل هذه الطريقة موضع المدخلات/المخرجات، لذا ستكون القراءة/الكتابة التالية للبايت الموجود عند الإزاحة (offset). عمليات البحث التي تتجاوز نهاية الملف يجب أن be treated as an error condition.

Parameters

io The i/o instance to seek.
offset The new byte offset for the i/o position.

Returns

non-zero on success, zero on error.

PHYSFS_sint64(* PHYSFS_Io::tell) (struct PHYSFS_Io *io)

Report current i/o position. Return bytes offset, or -1 if you aren't able to determine. A failure will almost certainly be fatal to further use of this stream, so you may not leave this unimplemented.

Parameters

io The i/o instance to query.

Returns

The current byte offset for the i/o position, -1 if unknown.

PHYSFS_uint32 PHYSFS_Io::version

Binary compatibility information. This must be set to zero at this time. Future versions of this struct will increment this field, so we know what a given implementation supports. We'll presumably keep supporting older versions as we offer new features, though.

PHYSFS_sint64(* PHYSFS_Io::write) (struct PHYSFS_Io *io, const void *buffer, PHYSFS_uint64 len)

Write more data. Write (len) bytes from (buffer) to the interface at the current i/o position. The current i/o position should move ahead by the number of bytes successfully written.

You don't have to implement this; set it to NULL if not implemented. This will only be used if the file is opened for writing. If set to NULL, a default implementation that immediately reports failure will be used.

You are allowed to buffer; a write can succeed here and then later fail when flushing. Note that PHYSFS_setBuffer() may be operating a level above your i/o, so you should usually not implement your own buffering routines.

Parameters

io The i/o instance to write to.
buffer The buffer to read data from. It must be at least (len) bytes long and can't be NULL.
len The number of bytes to read from (buffer).

Returns

number of bytes written to file, -1 if complete failure.
