MKUDFFS(8) دليل مدير النظام MKUDFFS(8)

الاسم

mkudffs — إنشاء نظام ملفات UDF

الملخص

mkudffs [ خيارات ] جهاز [ عدد-الكتل ]

الوصف

يُستخدم mkudffs لإنشاء نظام ملفات UDF على جهاز (عادةً قرص). جهاز هو الملف الخاص المقابل للجهاز (مثل /dev/hdX) أو صورة ملف. عدد-الكتل هو عدد الكتل على الجهاز. إذا تم حذفه، يقوم mkudffs تلقائيًا بتحديد حجم نظام الملفات. ترتيب الخيارات مهم. يجب أن يكون خيار التشفير هو الأول ويجب أن تكون الخيارات لتجاوز الإعدادات الافتراضية الضمنية بواسطة نوع الوسائط أو مراجعة UDF بعد الخيار الذي يتم تجاوزه.

الخيارات

-h,--help
عرض الاستخدام وقائمة الخيارات.
-l,--label= تسمية
تحديد تسمية UDF. تسمية UDF مرادفة لتحديد كلا الخيارين --lvid و --vid. إذا تم حذفه، تكون تسمية mkudffs هي LinuxUDF. (خيار متاح منذ mkudffs 1.1)
-u,--uuid= uuid
تحديد UUID الخاص بـ UDF. يجب أن يكون بالضبط 16 رقمًا سداسي عشريًا صغيرًا ويُستخدم لأول 16 حرفًا من الخيار --fullvsid. إذا تم حذفه، يتم إنشاء UUID الخاص بـ mkudffs من الوقت المحلي ورقم عشوائي. (خيار متاح منذ mkudffs 1.1)
-b,--blocksize= حجم-الكتلة
تحديد حجم الكتل بالبايت. حجم الكتلة الصالح لنظام ملفات UDF هو قوة للعدد 2 في النطاق من 512 إلى 32768 ويجب أن يتطابق مع حجم المنطق (القطاع) للجهاز. إذا تم حذفه، يتم تعيين حجم الكتلة لـ mkudffs إلى حجم المنطق (القطاع) للجهاز. إذا كان حجم المنطق (القطاع) للجهاز غير معروف (على سبيل المثال، عند إنشاء صورة قرص) فإنه يُستخدم حجم كتلة 512 لـ --media-type=hd و 2048 للأنواع الأخرى من الوسائط. (قبل mkudffs 1.1 كانت القيمة الافتراضية دائمًا 2048 بغض النظر عن --media-type)
-m,--media-type= نوع-الوسائط
تحديد نوع الوسائط. يجب تحديده قبل --udfrev. القيمة الافتراضية يتم اكتشافها تلقائيًا. عندما لا يعمل الاكتشاف التلقائي (على سبيل المثال، عند إنشاء صورة قرص) فإنه يُفترض قيمة hd. أنواع الوسائط الصالحة هي:
hd
HD (قرص صلب)
worm
WORM (الكتابة مرة واحدة القراءة المتعددة)
mo
MO (بصري مغناطيسي)
cd
CD-ROM (ذاكرة قراءة فقط للقرص المضغوط)
cdr
CD-R (قرص مضغوط قابل للتسجيل)
cdrw
CD-RW (قرص مضغوط قابل للقراءة والكتابة)
dvd
DVD-ROM (ذاكرة قراءة فقط لـ DVD)
dvdr
DVD-R (DVD قابل للتسجيل)
dvdrw
DVD-RW (DVD قابل للقراءة والكتابة)
dvdram
DVD-RAM (ذاكرة وصول عشوائي لـ DVD)
bdr
BD-R (قرص Blu-ray قابل للتسجيل)
(المتغير القصير للخيار -m والقيم cd، dvdr، bdr متاح منذ mkudffs 2.0 والاكتشاف التلقائي مدعوم منذ mkudffs 2.2)
-r,--udfrev= مراجعة-udf
تحديد مراجعة UDF المراد استخدامها، إما بتنسيق BCD سداسي عشري (مثل 0x0201) أو عشري (مثل 2.01). المراجعات الصالحة هي 1.01، 1.02، 1.50، 2.00، 2.01، 2.50 و 2.60. إذا تم حذفه، فإن مراجعة UDF لـ mkudffs هي 2.01، باستثناء أقراص Blu-ray التي تكون 2.50. المراجعات الأعلى من 2.01 تجريبية. يجب تحديد الخيار بعد --media-type. (القيم بالتنسيق العشري والمراجعات الأعلى من 2.01 مدعومة منذ mkudffs 2.0، المراجعة 1.01 مدعومة منذ mkudffs 2.1)
-n,--no-write
في الواقع لا، لا تكتب إلى الجهاز. قم فقط بالمحاكاة وعرض ما سيحدث لـ الجهاز. مفيد لتحديد الموقع المحسوب لكتل UDF المختلفة. (خيار متاح منذ mkudffs 2.0)
--new-file
إنشاء ملف صورة جديد محدد بواسطة الجهاز مع عدد-الكتل والفشل إذا كان الملف موجودًا بالفعل. إذا تم حذفه، يقوم mkudffs بإنشاء ملف صورة جديد فقط في حالة عدم وجوده بعد. (خيار متاح منذ mkudffs 2.0)
--lvid= معرف-حجم-منطقي
تحديد معرف الحجم المنطقي. إذا تم حذفه، فإن معرف الحجم المنطقي لـ mkudffs هو LinuxUDF. تستخدم معظم تطبيقات UDF هذا المعرف كتسمية للقرص.
--vid= معرف-الحجم
تحديد معرف الحجم. إذا تم حذفه، فإن معرف الحجم لـ mkudffs هو LinuxUDF.
--vsid= معرف-مجموعة-الأحجام
تحديد الحرف 17. إلى 127. من معرف مجموعة الأحجام. إذا تم حذفه، فإن معرف مجموعة الأحجام لـ mkudffs هو LinuxUDF.
--fsid= معرف-مجموعة-الملفات
تحديد معرف مجموعة الملفات. إذا تم حذفه، فإن معرف مجموعة الملفات لـ mkudffs هو LinuxUDF.
--fullvsid= معرف-مجموعة-الأحجام-كامل
تحديد معرف مجموعة الأحجام الكامل. يتجاوز الخيارات السابقة --uuid و --vsid. (خيار متاح منذ mkudffs 1.1)
--owner= اسم-المالك
تحديد اسم المالك، الشخص الذي قام بإنشاء الوسائط أو نظام الملفات. يتم تخزينه في معلومات الحجم المنطقي UDF 1، جزء من واصف الحجم لاستخدام التنفيذ UDF. (خيار متاح منذ mkudffs 2.3)
--organization= اسم-المؤسسة
تحديد اسم المؤسسة المسؤولة عن إنشاء الوسائط أو نظام الملفات. يتم تخزينه في معلومات الحجم المنطقي UDF 2، جزء من واصف الحجم لاستخدام التنفيذ UDF. (خيار متاح منذ mkudffs 2.3)
--contact= معلومات-الاتصال
تحديد معلومات الاتصال للوسائط أو نظام الملفات. يتم تخزينها في معلومات الحجم المنطقي UDF 3، جزء من واصف الحجم لاستخدام التنفيذ UDF. (خيار متاح منذ mkudffs 2.3)
--uid= uid
تحديد معرف المستخدم (uid) للدليل الجذر (/). إذا تم حذفه، فإن uid الخاص بـ mkudffs هو 0. القيمة الخاصة -1 تعني معرف مستخدم غير صالح أو غير محدد. (خيار متاح منذ mkudffs 1.1)
--gid= gid
تحديد معرف المجموعة (gid) للدليل الجذر (/). إذا تم حذفه، فإن gid الخاص بـ mkudffs هو 0. القيمة الخاصة -1 تعني معرف مجموعة غير صالح أو غير محدد. (خيار متاح منذ mkudffs 1.1)
--mode= وضع
تحديد الأذونات بتنسيق ثماني لوضع الدليل الجذر (/). إذا تم حذفه، فإن وضع mkudffs هو 0755. (خيار متاح منذ mkudffs 2.0)
--read-only
يحدد هذا الخيار أن القرص UDF بأكمله يجب أن يعامل على أنه للقراءة فقط. يقوم بتعيين علامة مجال SoftWriteProtect في واصف الحجم المنطقي وفي واصف مجموعة الملفات. بالإضافة إلى ذلك، بالنسبة لأنواع الوسائط القابلة للكتابة (hd، dvdram، dvdrw) يقوم بتعيين نوع وصول UDF إلى للقراءة فقط. (خيار متاح منذ mkudffs 2.2)
--bootarea= ملء
تحديد كيفية ملء منطقة إقلاع UDF والتي تبلغ 32 كيلوبايت الأولى من القرص ولا يستخدمها UDF نفسه. الخيار

NAME

mkudffs

make an UDF filesystem

SYNOPSIS

mkudffs [-v] [-o] [-b blocksize] [-l label] [-u] [-r revision] [-U] [-B boot] [-T table] [-a] [--] target [filesystem-size]

DESCRIPTION

The mkudffs utility is used to create a UDF (Universal Disk Format) filesystem on a device. UDF is a standard for optical media, but it can also be used on hard disks and other block devices.

The filesystem is created on the specified target device. The optional filesystem-size argument specifies the size of the filesystem in 512-byte sectors. If not specified, mkudffs uses the entire device size.

Options are:

-v, --verbose
Produce verbose output.
-o, --overwrite
Overwrite existing filesystem. Without this option, mkudffs will refuse to overwrite an existing filesystem.
-b blocksize, --blocksize=blocksize
Set the UDF block size. Default is 2048 bytes. UDF revision 2.50 and later require the block size to match the logical sector size of the device. See also BLOCK SIZE below.
-l label, --label=label
Set the volume label (Volume Identifier). Maximum length is 32 characters. If not specified, the label defaults to "UDF".
-u, --utf8
Encode the label in UTF-8. This is the default for non-ASCII labels.
-r revision, --revision=revision
Set the UDF revision. Supported revisions are 1.02, 1.50, 2.00, 2.01, 2.50, 2.60. The default is 1.02.
-U, --unicode
Encode the label in UCS-2BE. This is the default for ASCII labels.
-B boot, --boot=boot
Set the boot information. Possible values are:
none
No boot information (default).
bfs
Initial/El Torito boot information.
grub
GRUB boot information.
generic
Generic boot information.
-T table, --table=table
Set the partition table type. Possible values are:
none
No partition table (default).
mbr
MBR partition table.
gpt
GPT partition table.
-a, --all
Set all available partition types. This is equivalent to using --table=mbr and --table=gpt.
--
End of options. Any subsequent arguments are treated as the target.

BLOCK SIZE

In most cases, operating systems are unable to mount UDF filesystem if UDF block size differs from logical sector size of the device. Typically hard disks have sector size 512 bytes and optical media 2048 bytes. Therefore UDF block size must match the logical sector size of the device.

Linux kernel prior to version 2.6.30 used hardcoded UDF block size of 2048 bytes independently of logical sector size, therefore it was not able to automatically mount UDF filesystem if block size differed from 2048. Since 2.6.30 and prior to 4.11 Linux kernel used a logical sector size of the device as UDF block size, plus it tried fallback to 2048. Since 4.11 it uses logical sector size and fallbacks to any valid block size between logical sector size and 4096. Therefore since version 2.6.30 Linux kernel can automatically mount UDF filesystems correctly if UDF block size matches device logical sector size and since version 4.11 can automatically also mount devices which sector size does not match UDF block size. In any case and also for Linux kernel prior to version 2.6.30, different UDF block size (which is not autodetected) can be manually specified via bs=blocksize mount parameter.

WHOLE DISK VS PARTITION

UDF filesystem is supposed to be formatted on the whole media and not to the partitioned hard disk. Mac OS X systems enforce this rule and reject to automatically mount UDF filesystem unless it is formatted on the whole unpartitioned hard disk. Possible partition table (e.g. MBR or GPT) on disk with valid UDF filesystem is ignored. On the other hand, Microsoft Windows systems are unable to detect non-removable hard disks without MBR or GPT partition table. Removable disks do not have this restriction. A consequence is that non-removable hard disks formatted to UDF by Windows Vista+ are not recognized by Mac OS X systems and vice-versa. Note that manual mount of UDF partition on partitioned hard disk on Mac OS X system is possible and working (e.g. by running commands: mkdir /Volumes/DriveName && mount_udf /dev/disk1s1 /Volumes/DriveName). But there is no known way to mount an unpartitioned non-removable disk on Windows system.

Thanks to reserved and unused UDF boot area (first 32kB of UDF filesystem) it is possible to deal with this problem, by putting MBR on such non-removable hard disk just for compatibility reasons with Windows. Such MBR table would contain one partition which starts at sector 0 (includes MBR itself) and spans whole disk device. So the whole disk device and also the first partition on disk points to same sectors. Therefore UDF filesystem can be mounted either from whole disk device (needed for Mac OS X systems) or from first partition (needed for Microsoft Windows systems).

Linux kernel ignores MBR table if contains partition which starts at sector 0. Normally Linux kernel can detect and mount UDF filesystem either on a partition or on whole disk device. It does not have any restrictions.

mkudffs option --bootarea=mbr put such MBR table for compatibility with Microsoft Windows systems into disk when formatting.

LINUX LABEL BUGS

In most cases Logical Volume Identifier is used as UDF label. But Linux libblkid prior to version 2.26 used Volume Identifier. Therefore mkudffs --label for compatibility reasons set both Logical Volume Identifier and Volume Identifier.

Linux libblkid prior to version 2.30 incorrectly processed non-ASCII identifier strings encoded in 8-bit OSTA Compressed Unicode format. Therefore mkudffs since version 2.0 for compatibility reasons tries to encode a non-ASCII identifier strings in 16-bit OSTA Compressed Unicode format and then fallbacks to 8-bit format.

For more information about UDF Label and UUID see udflabel(8) section UDF LABEL AND UUID.

EXIT STATUS

mkudffs returns 0 if successful, non-zero if there are problems.

LIMITATIONS

mkudffs cannot create UDF 2.50 Metadata partition, therefore it does not support UDF revisions higher than 2.01 for non Write Once media yet. So there is no support for Blu-ray discs which needs UDF 2.50 (except for Blu-ray Disc Recordable which does not require Metadata partition).

mkudffs prior to version 2.2 was unable to process Unicode strings with code points above U+FFFF. When option --utf8 was specified then input strings were limited to 3-byte UTF-8 sequences and when option --u16 was specified then input strings were limited just to UCS-2BE strings (subset of UTF-16BE).

BUGS

mkudffs prior to version 1.1 was unable to process non-ASCII characters from identifier strings in --utf8 mode, --vsid option was completely broken and --blocksize must have been manually specified for hard disks as default value was hardcoded for optical disks. mkudffs prior to version 2.0 generated broken and unreadable cdr disc images.
