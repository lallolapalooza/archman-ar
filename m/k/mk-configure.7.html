اسم

mk-configure - بديل خفيف لـ GNU autotools

وصف

mk-configure هي مجموعة من ملفات التضمين لـ bmake (إصدار محمول من NetBSD make) وعدد من الملفات التنفيذية. وهي تهدف إلى تبسيط التطوير والبناء عبر المنصات.

هناك عدد قليل فقط من ملفات make الرئيسية: mkc.init.mk، mkc.mk، mkc.configure.mk، mkc.minitest.mk. كل شيء آخر (ملفات mkc_imp.*.mk) يتم تضمينه ضمنيًا. لا تستخدم ملفات mkc_imp.*.mk مباشرة! إذا فعلت ذلك، لا يمكنني ضمان التوافق العكسي. يتم تضمين mkc.configure.mk تلقائيًا بواسطة mkc.mk، ولكن يمكن تضمينها بشكل صريح. يوفر mkc.minitest.mk دعمًا بسيطًا لاختبارات التراجع ويجب تضمينه بشكل صريح. عادةً ما تتكون ملفات make الخاصة بـ mk-c من تعيينات للمتغيرات وتضمين mkc.mk في البداية والنهاية. يمكن أيضًا استخدام mkc.prog.mk، mkc.lib.mk، mkc.files.mk، mkc.subdir.mk و mkc.subprj.mk بدلاً من mkc.mk. هذا الأخير ينشط mkc.lib.mk إذا تم تعيين المتغير LIB، و mkc.prog.mk إذا تم تعيين المتغيرين PROG أو PROGS، و mkc.subprj.mk إذا تم تعيين المتغير SUBPRJ، و mkc.subdir.mk إذا تم تعيين المتغير SUBDIR، و mkc.files.mk بخلاف ذلك.

للحصول على معلمات تكوين على مستوى النظام، يقوم mkc.init.mk بتحميل ملف " ${MAKECONF} " إذا كان موجودًا. بدلاً من ذلك، يقوم بتحميل /etc/mkcmake.conf إذا كان موجودًا. إذا لم يكن ${MAKECONF} ولا /etc/mkcmake.conf موجودين، فإنه يحاول تحميل ملف /etc/mk.conf. إذا كان ملف " ${SRCTOP}/Makefile.common " موجودًا، فسيتم تضمينه أيضًا بواسطة جميع المشاريع الفرعية. ما لم يتم تعيين المتغير SRCTOP، يتم تضمين " ../Makefile.inc " أيضًا إذا كان موجودًا. قد تحدد هذه الملفات أيًا من المتغيرات الموضحة أدناه. يتم أيضًا تحميل الإعدادات الافتراضية الخاصة بالمترجم من " ~/.mkcmake " أو الدلائل النظامية. يتم تحديد هذه الإعدادات الافتراضية الخاصة بالمترجم في وقت البناء أو بمساعدة الأداة المساعدة mkc_compiler_settings.

أدناه بين أقواس مربعة هي القيمة الافتراضية للمتغيرات. بين أقواس مثلثة - طريقة الاستخدام النموذجية، حيث يعني I "تم تهيئته بواسطة mk-configure"، ويعني Iu "تم تهيئته بواسطة mk-configure ولكن قد يتجاوزه المستخدم"، ويعني Im "تم تهيئته بواسطة mk-configure ولكن قد يتم تعيينه في Makefile"، ويعني U "يتم تعيينه عادةً بواسطة المستخدم"، ويعني M "قد يتم تعيينه أو تغييره في Makefile الخاص بالمشروع"، ويعني Mu "قد يتم تعيينه في Makefile الخاص بالمشروع ولكن قد يتم تهيئته أو تجاوزه بواسطة المستخدم".

المتغير MKCMAKE هو دائمًا 1 في mkcmake.

الأهداف

يوفر mk-configure الأهداف التالية:

all
بناء كل شيء.
clean
تنظيف الملفات المؤقتة والأدلة بمساعدة الأوامر ${CLEANFILES_CMD} و ${CLEANDIRS_CMD}.
cleandir
إزالة جميع الملفات التي تم إزالتها بواسطة الهدف clean، بالإضافة إلى ملفات ذاكرة التخزين المؤقت التي تم إنشاؤها بواسطة mkc.configure.mk.
installdirs
إنشاء أدلة الهدف.
install
تثبيت البرامج والمكتبات والملفات وملفات التضمين وصفحات الدليل وما إلى ذلك في أدلة الهدف بمساعدة البرنامج ${INSTALL}.
uninstall
إزالة الملفات المثبتة بمساعدة الأمر ${UNINSTALL}.
configure
التحقق من المتغير MKC_ERR_MSG والفشل إذا تم تعيينه وطباعة رسالة خطأ.
depend
إنشاء ملف .depend_${.CURDIR:T} يحتوي على قائمة التبعيات (انظر mkdep(1)).
filelist
إخراج قائمة بملفات الوجهة للمشروع، سطر واحد لكل ملف، على سبيل المثال: 
  /usr/local/bin/hello
  /usr/local/man/man1/hello.1
obj
إذا كان MKOBJDIR هو "yes"، يتم إنشاء أدلة الكائنات (${.OBJDIR}) وفقًا للمتغيرين MAKEOBJDIR و MAKEOBJPREFIX. يتم استخدام umask الحالي لذلك.
mkgen
انظر mkc_imp.foreign_autotools.mk.
bin_tar, bin_targz, bin_tarbz2, bin_zip, bin_deb
بناء البرنامج، تثبيته في دليل مؤقت (باستخدام DESTDIR) وإنشاء أرشيف .tar/.tar.gz/.tar.bz2/.zip/.deb يحتوي على جميع الملفات المثبتة. يتوقع الهدف bin_deb ملفات تحكم debian في الدليل الفرعي DEBIAN، انظر examples/files للحصول على عينة.

ملاحظة: الأوامر المرتبطة بالأهداف all، install، clean، cleandir، depend، test، installdirs، uninstall، configure و filelist في Makefile تتجاوز السلوك القياسي.

ملاحظة: جميع الأهداف في هذه القائمة لها نظائر pre_*، do_* و post_*. انظر ALLTARGETS لمزيد من التفاصيل.

mkc.subprj.mk

The include file mkc.subprj.mk handles subprojects (subdirectories) organized as a dependency graph. It provides all targets provided by mkc.prog.mk. Variable SUBPRJ contains a list of pairs depdir:dir which mean that subproject dir depends on depdir. mkcmake all command will build all subprojects listed in SUBPRJ in a correct order (starting with subprojects having no dependencies and so on). There is also a target which allows the command bmake <subdir> where <subdir> is any directory listed in the variable SUBPRJ. The following targets are also provided: <target>-<subdir> where <target> is either of the following: all, clean, cleandir, depend, installdirs, install, uninstall and filelist. Also provided are: targets nodeps-<target>-<subdir> and subdir-<target>-<subdir>. Difference between <target>-<subdir> and nodeps-<target>-<subdir> is that mkcmake <target>-<subdir> runs the specified <target> for <subdir> and all its dependencies while mkcmake nodeps-<target>-<subdir> -- only for <subdir>. A target subdir-<target>-<subdir> is a synonym for nodeps-<target>-<subdir> See examples/hello_dictd subdirectory for the sample of use.

A list of targets for which pre_*, do_* and post_* counterparts exist, for example, pre_all, do_all and post_all. pre_* target runs before do_* target which in turn runs before post_*. mkc.configure.mk is an auxiliary include file for checking platform's features like headers, function or variable declarations, function implementation in a particular libraries, data types sizes etc. This include file is included by mkc.prog.mk and mkc.lib.mk automatically but in some cases it makes sense to include it explicitly. mkc.configure.mk itself includes mkc.init.mk, then mkc.conf.mk , and finally internal include file which updates CPPFLAGS, CFLAGS, LDADD and SRCS. mkc.configure.mk supports the following variables.

If "no", none of the checks are performed. It is set to "yes" unless target is "clean" and "cleandir".

Find traditional BSD mkdep(1) or recent NetBSD version of it respectively.

BUILTIN.endianness variable is set to either little, big or unknown depending on a hardware.

A list of C compiler options to check. If ${CC} -c support the specified option, variable HAVE_CC_OPT.<option:S/=/_/g> is set to 1 and 0 otherwise. Double underline in the option is considered as a single space character.

إذا تم تعيين MKC_PROG.id.<progname> إلى، على سبيل المثال، <prog_id>، فسيتم تعيين HAVE_PROG.<prog_id> و PROG.<prog_id>. يغير MKC_PROG.id.<progname> أيضًا أسماء ملفات ذاكرة التخزين المؤقت.

MKC_CHECK_PROTOTYPES
قائمة بالفحوصات (قائمة بالأسماء) لنماذج دوال C. MKC_PROTOTYPE_FUNC.<name> هو نموذج دالة C. MKC_PROTOTYPE_HEADERS.<name> هو قائمة بالرؤوس مفصولة بمسافة أو فاصلة. يتحقق mk-configure من أن النموذج المحدد صحيح، وإذا كان الأمر كذلك، يتم تعيين متغير bmake HAVE_PROTOTYPE.<name> إلى 1 ويتم إضافة -DHAVE_PROTOTYPE_<NAME>=1 إلى CPPFLAGS ما لم يتم تعيين MKC_NOAUTO إلى 1. بخلاف ذلك، يتم تعيين متغير HAVE_PROTOTYPE.<name> إلى 0. 
مثال.
  MKC_CHECK_PROTOTYPES = posix_iconv const_iconv
  MKC_PROTOTYPE_FUNC.posix_iconv =  
    size_t iconv(iconv_t,char**,size_t*,char**,size_t*)
  MKC_PROTOTYPE_FUNC.const_iconv =  
    size_t iconv(iconv_t,const char**,size_t*,char**,size_t*)
  MKC_PROTOTYPE_HEADERS.posix_iconv = iconv.h
  MKC_PROTOTYPE_HEADERS.const_iconv = iconv.h
Res.
 HAVE_PROTOTYPE.posix_iconv=0
 HAVE_PROTOTYPE.const_iconv=1
 CFLAGS += -DHAVE_PROTOTYPE_CONST_ICONV=1
MKC_CHECK_SIZEOF
قائمة <type>:<header> للتحقق. جزء <header> اختياري.

نتيجة للفحص، يتم تعيين متغير bmake SIZEOF.<type>.<header> (أو SIZEOF.<type>) إلى حجم نوع البيانات أو السلسلة "failed".
<type>: tr|*-|P_|g
<header>: tr|/.|__|g
أيضًا، تتم إضافة -DSIZEOF_<TYPE>_<HEADER>=<failed|1|2|...> (أو -DSIZEOF_<TYPE>=<failed|1|2|...>) إلى CPPFLAGS إذا نجح فحص sizeof() ما لم يتم تعيين MKC_NOAUTO إلى 1
<TYPE>: tr|a-z*-|A-ZP_|g
<HEADER>: tr|a-z/.|A-Z__|g

 مثال:  MKC_CHECK_SIZEOF += void*
      MKC_CHECK_SIZEOF += long-long off_t:sys/types.h
 Res: SIZEOF.voidP             = 4
      SIZEOF.long_long         = 4
      SIZEOF.off_t.sys_types_h = 8
      CFLAGS += -DSIZEOF_VOIDP=4 \
                -DSIZEOF_LONG_LONG=4 \
                -DSIZEOF_OFF_T_SYS_TYPES_H=8

<TYPE>: tr|a-z|A-Z|g
