mkfifo(3) دليل دوال المكتبة mkfifo(3)

الاسم

mkfifo, mkfifoat - إنشاء ملف FIFO خاص (أنبوب مسمى)

المكتبة

مكتبة C القياسية (libc، -lc)

الملخص

#include <sys/types.h>
#include <sys/stat.h>
int mkfifo(const char *path, mode_t mode);
#include <fcntl.h>           /* تعريف الثوابت AT_* */
#include <sys/stat.h>
int mkfifoat(int dirfd, const char *path, mode_t mode);
متطلبات ميزة الاختبار (Feature Test Macro Requirements) لـ glibc (انظر feature_test_macros(7)):

mkfifoat():

    منذ glibc 2.10:
        _POSIX_C_SOURCE >= 200809L
    قبل glibc 2.10:
        _ATFILE_SOURCE

الوصف

تقوم الدالة mkfifo() بإنشاء ملف FIFO خاص بالاسم path. يحدد mode أذونات الـ FIFO. يتم تعديلها بواسطة umask الخاصة بالعملية بالطريقة المعتادة: أذونات الملف المنشأ هي (mode & ~umask).

ملف FIFO الخاص مشابه للأنبوب (pipe)، باستثناء أنه يتم إنشاؤه بطريقة مختلفة. بدلاً من كونه قناة اتصال مجهولة، يتم إدخال ملف FIFO الخاص في نظام الملفات عن طريق استدعاء mkfifo().

بمجرد إنشاء ملف FIFO خاص بهذه الطريقة، يمكن لأي عملية فتحه للقراءة أو الكتابة، بنفس طريقة الملف العادي. ومع ذلك، يجب فتحه من كلا الطرفين في وقت واحد قبل أن تتمكن من متابعة إجراء عمليات الإدخال أو الإخراج عليه. فتح FIFO للقراءة يعلق عادةً حتى تفتح عملية أخرى نفس الـ FIFO للكتابة، والعكس صحيح. انظر fifo(7) لمعالجة ملفات FIFO الخاصة غير المعلقة.

mkfifoat()

تعمل الدالة mkfifoat() بنفس الطريقة تمامًا مثل mkfifo()، باستثناء الاختلافات الموضحة هنا.

إذا كان path نسبيًا، فسيتم تفسيره بالنسبة للدليل الذي يشير إليه واصف الملف dirfd (بدلاً من تفسيره بالنسبة لدليل العمل الحالي للعملية المستدعية، كما تفعل mkfifo() للمسار النسبي).

إذا كان path نسبيًا و dirfd هي القيمة الخاصة AT_FDCWD، فسيتم تفسير path بالنسبة لدليل العمل الحالي للعملية المستدعية (مثل mkfifo()).

إذا كان path مطلقًا، فسيتم تجاهل dirfd.

انظر openat(2) لشرح الحاجة إلى mkfifoat().

قيمة الإرجاع

عند النجاح، تُرجع mkfifo() و mkfifoat() القيمة 0. عند حدوث خطأ، تُرجع -1 ويتم تعيين errno للإشارة إلى الخطأ.

الأخطاء

EACCES
لم تسمح أحد الأدلة في path بإذن البحث (التنفيذ).
EBADF
(mkfifoat()) path نسبي ولكن dirfd ليست AT_FDCWD ولا واصف ملف صالح.
EDQUOT
تم استنفاد حصة المستخدم من كتل القرص أو الأجهزة (inodes) في نظام الملفات.
EEXIST
path موجود بالفعل. يتضمن هذا الحالة التي يكون فيها path رابطًا رمزيًا، سواء كان معلقًا أو لا.
ENAMETOOLONG
إما أن يكون الحجم الإجمالي لـ path أكبر من PATH_MAX، أو أن طول مكون اسم الملف الفردي أكبر من NAME_MAX. في نظام GNU، لا يوجد حد مفروض على طول اسم الملف الإجمالي، ولكن قد تفرض بعض أنظمة الملفات قيودًا على طول المكون.
ENOENT
مكون دليل في path غير موجود أو هو رابط رمزي معلق.
ENOSPC
لا يوجد مساحة في الدليل أو نظام الملفات للملف الجديد.
ENOTDIR
مكون يستخدم كدليل في path ليس، في الواقع، دليلاً.
ENOTDIR
(mkfifoat()) path نسبي و dirfd هو واصف ملف يشير إلى ملف آخر غير دليل.
EROFS
path يشير إلى نظام ملفات للقراءة فقط.
