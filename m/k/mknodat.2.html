mknod(2) دليل استدعاءات النظام mknod(2)

الاسم

mknod, mknodat - إنشاء ملف خاص أو عادي

المكتبة

مكتبة C القياسية (libc، -lc)

المُلَخَّص

#include <sys/stat.h>
int mknod(const char *path, mode_t mode, dev_t dev);
#include <fcntl.h>           /* تعريف ثوابت AT_* */
#include <sys/stat.h>
int mknodat(int dirfd, const char *path, mode_t mode, dev_t dev);
متطلبات ماكرو اختبار الميزات لـ glibc (انظر feature_test_macros(7)):

mknod():

    _XOPEN_SOURCE >= 500
        || /* منذ glibc 2.19: */ _DEFAULT_SOURCE
        || /* glibc <= 2.19: */ _BSD_SOURCE || _SVID_SOURCE

الوصف

يقوم استدعاء النظام mknod() بإنشاء عقدة نظام ملفات (ملف، ملف جهاز خاص، أو أنبوب مسمى) باسم path، مع السمات المحددة بواسطة mode و dev.

يحدد الوسيط mode كلاً من وضع الملف المراد استخدامه ونوع العقدة المراد إنشاؤها. يجب أن يكون مزيجًا (باستخدام OR ثنائي) من أحد أنواع الملفات المذكورة أدناه وصفر أو أكثر من بتات وضع الملف المدرجة في inode(7).

يتم تعديل وضع الملف بواسطة umask الخاص بالعملية بالطريقة المعتادة: في غياب ACL افتراضي، تكون أذونات العقدة التي تم إنشاؤها (mode & ~umask).

يجب أن يكون نوع الملف أحد S_IFREG، S_IFCHR، S_IFBLK، S_IFIFO، أو S_IFSOCK لتحديد ملف عادي (سيتم إنشاؤه فارغًا)، ملف جهاز حرفي، ملف جهاز كتلة، FIFO (أنبوب مسمى)، أو مقبس نطاق UNIX، على التوالي. (نوع الملف الصفري يعادل النوع S_IFREG.)

إذا كان نوع الملف S_IFCHR أو S_IFBLK، فإن dev يحدد أرقام الأجهزة الرئيسية والثانوية لملف الجهاز الخاص الذي تم إنشاؤه حديثًا (قد يكون makedev(3) مفيدًا لبناء القيمة لـ dev)؛ بخلاف ذلك يتم تجاهله.

إذا كان path موجودًا بالفعل، أو كان رابطًا رمزيًا، فسيفشل هذا الاستدعاء بخطأ EEXIST.

ستكون العقدة التي تم إنشاؤها مملوكة لمعرف المستخدم الفعال للعملية. إذا كان الدليل الذي يحتوي على العقدة يحتوي على بت set-group-ID مضبوطًا، أو إذا تم تحميل نظام الملفات باستخدام دلالات مجموعة BSD، فستستعير العقدة الجديدة ملكية المجموعة من دليلها الأصلي؛ بخلاف ذلك، ستكون مملوكة لمعرف المجموعة الفعال للعملية.

mknodat()

يعمل استدعاء النظام mknodat() بنفس طريقة عمل mknod()، باستثناء الاختلافات الموضحة هنا.

إذا كان path نسبيًا، فسيتم تفسيره بالنسبة إلى الدليل المشار إليه بواسطة واصف الملف dirfd (بدلاً من تفسيره بالنسبة إلى دليل العمل الحالي للعملية المتصلة، كما يفعل mknod() لمسار نسبي).

إذا كان path نسبيًا و dirfd هي القيمة الخاصة AT_FDCWD، فسيتم تفسير path بالنسبة إلى دليل العمل الحالي للعملية المتصلة (مثل mknod()).

إذا كان path مطلقًا، فسيتم تجاهل dirfd.

انظر openat(2) لشرح الحاجة إلى mknodat().

قيمة الإرجاع

mknod() و mknodat() ترجعان صفرًا عند النجاح. عند حدوث خطأ، يتم إرجاع -1 ويتم تعيين errno للإشارة إلى الخطأ.

الأخطاء

EACCES
لا يسمح الدليل الأصل بإذن الكتابة للعملية، أو أن أحد الأدلة في مسار path لم يسمح بإذن البحث. (انظر أيضًا path_resolution(7).)
EBADF
(mknodat()) path نسبي ولكن dirfd ليس AT_FDCWD ولا واصف ملف صالح.
EDQUOT
تم استنفاد حصة المستخدم من كتل القرص أو العقد على نظام الملفات.
EEXIST
path موجود بالفعل. يشمل ذلك الحالة التي يكون فيها path رابطًا رمزيًا، معلقًا أو لا.
EFAULT
path يشير إلى خارج مساحة العنوان التي يمكنك الوصول إليها.
EINVAL
mode طلب إنشاء شيء آخر غير ملف عادي، ملف جهاز خاص، FIFO، أو مقبس.
ELOOP
تم العثور على عدد كبير جدًا من الروابط الرمزية أثناء حل path.
ENAMETOOLONG
path كان طويلاً جدًا.
ENOENT
أحد مكونات الدليل في path غير موجود أو هو رابط رمزي معلق.
ENOMEM
لم تتوفر ذاكرة كافية في النواة.
ENOSPC
الجهاز الذي يحتوي على path ليس به مساحة للعقدة الجديدة.
ENOTDIR
أحد المكونات المستخدمة كدليل في path ليس في الواقع دليلًا.
ENOTDIR
(mknodat()) path نسبي و dirfd هو واصف ملف يشير إلى ملف آخر غير دليل.
EPERM
mode طلب إنشاء شيء آخر غير ملف عادي، FIFO (أنبوب مسمى)، أو مقبس نطاق UNIX، والمستدعي غير مميز (Linux: ليس لديه القدرة CAP_MKNOD)؛ يتم إرجاعها أيضًا إذا كان نظام الملفات الذي يحتوي على path لا يدعم نوع العقدة المطلوب.
EROFS
path يشير إلى ملف على نظام ملفات للقراءة فقط.

الإصدارات

تنص POSIX.1-2001: "الاستخدام الوحيد القابل للنقل لـ mknod() هو لإنشاء ملف FIFO خاص. إذا لم يكن mode هو S_IFIFO أو dev ليس 0، فإن سلوك mknod() غير محدد." ولكن في الوقت الحاضر، لا ينبغي استخدام mknod() لهذا الغرض أبدًا؛ يجب استخدام mkfifo(3)، وهي وظيفة محددة لهذا الغرض.

تحت Linux، لا يمكن استخدام mknod() لإنشاء أدلة. يجب إنشاء الأدلة باستخدام mkdir(2).

mknodat(2) — Linux man-pages (6.16)

NAME

mknodat - create a node relative to a directory file descriptor

LIBRARY

Realtime Library

SYNOPSIS

#include <sys/types.h>
#include <sys/stat.h>
#include <fcntl.h>

int mknodat(int dirfd, const char *pathname, mode_t mode, dev_t dev);

DESCRIPTION

The mknodat() function is equivalent to the mknod(2) function, except that the file to be created is relative to the directory referred to by the file descriptor dirfd. If pathname specifies an absolute path, then it is ignored, and dirfd is ignored as well.

If pathname is a relative path, then it is interpreted relative to the directory referred to by the file descriptor dirfd. If pathname begins with a slash (/), then it is interpreted relative to the root directory (and dirfd is ignored).

The dirfd argument must be an open file descriptor for a directory. The special value AT_FDCWD means the current working directory.

The mode argument specifies the file type and permissions of the new node. The file type must be one of S_IFREG, S_IFCHR, S_IFBLK, S_IFIFO, or S_IFSOCK.

The dev argument specifies the device numbers if the file is a character or block special file. It is ignored otherwise.

The least significant 9 bits of mode specify the file permission bits. These are:

    S_IRUSR (00400)  read permission for owner
    S_IWUSR (00200)  write permission for owner
    S_IXUSR (00100)  execute permission for owner
    S_IRGRP (00040)  read permission for group
    S_IWGRP (00020)  write permission for group
    S_IXGRP (00010)  execute permission for group
    S_IROTH (00004)  read permission for others
    S_IWOTH (00002)  write permission for others
    S_IXOTH (00001)  execute permission for others
The file permission bits are modified by the process's umask.

The behavior of mknodat() is undefined if mode specifies a regular file (S_IFREG) or a symbolic link (S_IFLNK).

RETURN VALUE

On success, mknodat() returns 0. On failure, it returns -1, and errno is set to indicate the error.

ERRORS

EACCES
Search permission denied for one of the components of pathname, or the directory referred to by dirfd.
EEXIST
pathname already exists.
EINVAL
mode is invalid, or does not specify a valid file type.
ENAMETOOLONG
A component of a pathname exceeded NAME_MAX characters, or the entire pathname exceeded PATH_MAX characters.
ENOENT
A component of pathname does not exist or is a dangling symbolic link (and AT_SYMLINK_NOFOLLOW was not specified), or dirfd refers to an invalid file descriptor.
ENOSPC
The directory or filesystem is full.
ENOTDIR
pathname was not a regular file and the user specified a regular file, or one of the components of pathname is not a directory, or dirfd refers to a file that is not a directory.
EROFS
pathname refers to a read-only filesystem.
EPERM
The operation not permitted. This can happen for several reasons, including trying to create a FIFO or socket in a directory where the user does not have write permissions.
ESPIPE
dirfd is associated with a pipe or FIFO.

VERSIONS

The mknodat() function was introduced in Linux kernel 3.1.17.

STANDARDS

This function is specific to Linux.

HISTORY

mknodat() appeared in Linux 3.1.17.

NOTES

The following flags can be included in mode when calling mknodat():

S_IFMT
0170000 — mask for file type
S_IFSOCK
0140000 — socket
S_IFLNK
0120000 — symbolic link
S_IFREG
0100000 — regular file
S_IFBLK
0060000 — block device
S_IFDIR
0040000 — directory
S_IFCHR
0020000 — character device
S_IFIFO
0010000 — FIFO

The dev argument is a combination of two values: the major number and the minor number. The macros major(dev) and minor(dev) can be used to extract these values. The macros makedev(maj, min) can be used to create a dev_t value from a major and minor number.
