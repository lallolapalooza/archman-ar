MKE2FS(8) دليل مدير النظام MKE2FS(8)

الاسم

mke2fs - إنشاء نظام ملفات ext2/ext3/ext4

الملخص

mke2fs [ -c | -l filename ] [ -b block-size ] [ -C cluster-size ] [ -d root-directory|tarball ] [ -D ] [ -g blocks-per-group ] [ -G number-of-groups ] [ -i bytes-per-inode ] [ -I inode-size ] [ -j ] [ -J journal-options ] [ -N number-of-inodes ] [ -n ] [ -m reserved-blocks-percentage ] [ -o creator-os ] [ -O [^]feature[,...] ] [ -q ] [ -E extended-options ] [ -v ] [ -F ] [ -L volume-label ] [ -M last-mounted-directory ] [ -S ] [ -t fs-type ] [ -T usage-type ] [ -U UUID ] [ -V ] [ -e errors-behavior ] [ -z undo_file ] device [ fs-size ]

mke2fs -O journal_dev [ -b block-size ] [ -L volume-label ] [ -n ] [ -q ] [ -v ] external-journal [ fs-size ]

الوصف

يستخدم mke2fs لإنشاء نظام ملفات ext2 أو ext3 أو ext4، عادةً في قسم قرص (أو ملف) يسمى بواسطة device.

يتم تحديد حجم نظام الملفات بواسطة fs-size. إذا لم يكن لـ fs-size لاحقة، فسيتم تفسيره على أنه كيلوبايت بقوة الرقم اثنين، ما لم يتم تحديد خيار -b blocksize، وفي هذه الحالة سيتم تفسير fs-size على أنه عدد كتل blocksize. إذا كانت حجم نظام الملفات لاحقة بـ 'k'، 'm'، 'g'، 't' (إما بحروف كبيرة أو صغيرة)، فسيتم تفسيرها في كيلوبايت بقوة الرقم اثنين، ميغابايت، جيجابايت، تيرابايت، إلخ. إذا تم حذف حجم نظام الملفات، فسيقوم mke2fs بإنشاء نظام الملفات بناءً على حجم الجهاز.

إذا تم تشغيل mke2fs كـ mkfs.XXX (أي mkfs.ext2، mkfs.ext3، أو mkfs.ext4) يتم ضمنيًا الخيار -t XXX؛ لذلك سيقوم mkfs.ext3 بإنشاء نظام ملفات للاستخدام مع ext3، وسيُنشئ mkfs.ext4 نظام ملفات للاستخدام مع ext4، وهكذا.

يتم التحكم في إعدادات المعلمات الافتراضية لنظام الملفات الذي تم إنشاؤه حديثًا، إذا لم يتم تجاوزها بواسطة الخيارات المدرجة أدناه، بواسطة ملف التكوين /etc/mke2fs.conf. انظر صفحة الدليل mke2fs.conf(5) لمزيد من التفاصيل.

الخيارات

-b block-size
حدد حجم الكتل بالبايت. القيم الصالحة لحجم الكتل هي قوى الرقم اثنين من 1024 إلى 65536 (مع ملاحظة أن النواة قادرة على تحميل أنظمة الملفات ذات حجم الكتل الأصغر من أو المساوية لحجم صفحة النظام - 4k على أنظمة x86، حتى 64k على ppc64 أو aarch64 اعتمادًا على تكوين النواة). إذا تم حذفها، يتم تحديد حجم الكتلة بشكل تقديري بناءً على حجم نظام الملفات والاستخدام المتوقع لنظام الملفات (انظر الخيار -T). في معظم الحالات الشائعة، يبلغ حجم الكتلة الافتراضي 4k. إذا كان block-size مسبوقًا بعلامة ناقص ('-')، فسيستخدم mke2fs طرقًا تقديرية لتحديد حجم الكتلة المناسب، مع شرط أن يكون حجم الكتلة على الأقل block-size بايت. هذا مفيد لأجهزة معينة تتطلب أن يكون حجم الكتلة مضاعفًا لـ 2k.
-c
تحقق من الجهاز بحثًا عن كتل تالفة قبل إنشاء نظام الملفات. إذا تم تحديد هذا الخيار مرتين، فسيتم استخدام اختبار قراءة-كتابة أبطأ بدلاً من اختبار قراءة فقط سريع.
-C cluster-size
حدد حجم الكتلة بالبايت لأنظمة الملفات التي تستخدم ميزة bigalloc. تتراوح قيم حجم الكتلة الصالحة من 2 إلى 32768 ضعف حجم كتلة نظام الملفات ويجب أن تكون قوة للرقم اثنين. لا يمكن تحديد حجم الكتلة إلا إذا تم تمكين ميزة bigalloc. (انظر صفحة الدليل ext4 (5) لمزيد من التفاصيل حول bigalloc.) يبلغ حجم الكتلة الافتراضي إذا تم تمكين bigalloc 16 ضعف حجم الكتلة.
-d root-directory|tarball
انسخ محتويات الدليل أو ملف tarball المحدد إلى الدليل الجذر لنظام الملفات. يتوفر إدخال ملف tarball فقط إذا تم تجميع mke2fs مع تمكين دعم libarchive وإذا كانت مكتبة libarchive المشتركة متاحة وقت التشغيل. القيمة الخاصة "-" ستقرأ ملف tarball من الإدخال القياسي.
-D
استخدم I/O مباشرًا عند الكتابة إلى القرص. هذا يتجنب قيام mke2fs بتلويث الكثير من ذاكرة التخزين المؤقت للمخزن المؤقت، مما قد يؤثر على التطبيقات الأخرى التي تعمل على خادم مزدحم. سيؤدي هذا الخيار إلى تشغيل mke2fs بشكل أبطأ بكثير، لذلك هناك مفاضلة في استخدام I/O مباشر.
-e error-behavior
تغيير سلوك كود النواة عند اكتشاف الأخطاء. في جميع الحالات، سيؤدي خطأ في نظام الملفات إلى قيام e2fsck(8) بفحص نظام الملفات عند التمهيد التالي. يمكن أن يكون error-behavior أحد الخيارين التاليين:
continue
متابعة التنفيذ العادي.
remount-ro
إعادة تحميل نظام الملفات للقراءة فقط.
panic
تسبب في تعطل النواة.
-E extended-options
تعيين خيارات موسعة لنظام الملفات. الخيارات الموسعة مفصولة بفواصل، وقد تأخذ وسيطة باستخدام علامة المساواة ('=') . كان الخيار -E هو -R في الإصدارات السابقة من mke2fs. لا يزال الخيار -R مقبولاً للتوافق مع الإصدارات السابقة، ولكنه مهمل. الخيارات الموسعة التالية مدعومة:
assume_storage_prezeroed[= <0 لتعطيل، 1 لتمكين>]
إذا تم تمكين هذا الخيار، فيفترض mke2fs أن جهاز التخزين قد تم إفراغه مسبقًا، ويتخطى إفراغ مجلة السجلات وجداول inode، ويضع علامة على علامات مجموعة الكتل للإشارة إلى أن جدول inode قد تم إفراغه.
discard
حاول تجاهل الكتل عند وقت إنشاء نظام الملفات (تجاهل الكتل مبدئيًا مفيد على أجهزة الحالة الصلبة والمخزن المؤقت/المخصص بشكل ضعيف). عندما يعلن الجهاز أن التجاهل يفرغ البيانات أيضًا (أي قراءة لاحقة بعد التجاهل وقبل الكتابة تعيد صفرًا)، فقم بتمييز جميع جداول inode غير الفارغة على أنها فارغة. هذا يسرع بشكل كبير تهيئة نظام الملفات. يتم تعيين هذا افتراضيًا.
encoding=encoding-name
قم بتمكين ميزة casefold في السجل الفائق وتعيين encoding-name كالترميز الذي سيتم استخدامه. إذا لم يتم تحديد encoding-name، يتم استخدام الترميز المحدد في mke2fs.conf(5).
encoding_flags=encoding-flags
حدد معلمات عمليات ترميز أسماء الملفات. إذا لم يتم تغيير علامة باستخدام هذه المعلمة، فسيتم استخدام قيمتها الافتراضية. يجب أن تكون encoding-flags قائمة مفصولة بفواصل من العلامات التي سيتم تمكينها. لتعطيل علامة، أضفها إلى القائمة بالبادئة "no".

العلامة الوحيدة التي يمكن تعيينها في الوقت الحالي هي strict، مما يعني أنه يجب رفض السلاسل غير الصالحة بواسطة نظام الملفات. في التكوين الافتراضي، تكون علامة strict معطلة.

lazy_itable_init[= <0 لتعطيل، 1 لتمكين>]
إذا تم تمكينها وتم تمكين ميزة uninit_bg، فلن يتم تهيئة جدول inode بالكامل بواسطة mke2fs. هذا يسرع تهيئة نظام الملفات بشكل ملحوظ، ولكنه يتطلب من النواة إكمال تهيئة نظام الملفات في الخلفية عند تحميل نظام الملفات لأول مرة. إذا تم حذف قيمة الخيار، فسيكون افتراضيًا 1 لتمكين إفراغ جدول inode المتأخر.
lazy_journal_init[= <0 لتعطيل، 1 لتمكين>]
إذا تم تمكين هذا الخيار، فلن يتم إفراغ عقدة مجلة السجلات بالكامل بواسطة mke2fs. هذا يسرع تهيئة نظام الملفات بشكل ملحوظ، ولكنه يحمل بعض المخاطر الصغيرة

MKE2FS.CONF(5)
mke2fs.conf configuration file for mke2fs The mke2fs.conf file is used to control the default behavior of the mke2fs(8) utility. It is used to define options which will be passed to the mkfs.ext4 or mkfs.ext3 or mkfs.ext2 commands. The configuration file is organized into sections, where each section starts with a name in square brackets, e.g. "[SECTION]". The first section is the global section, which is used for defaults. Subsequent sections are named after the filesystem type, e.g. "[ext3]", "[ext4]". Within each section, there are key-value pairs. The keys are mke2fs(8) options, and the values are the desired arguments for those options. Lines starting with '#' or ';' are commented out. The options supported in the configuration file are a subset of the options supported on the command line, and are used to set defaults for the options. Some options are boolean flags, and in the configuration file they are represented by specifying the option name followed by a value of "1" or "0". The configuration file can also be used to define named sets of options which can be selected by the user via the option on the command line. These named option sets are defined in sections named "" or "" etc. where the section name is specified by the mke2fs(8) command line options. Example [options] blocksize=1024 inode_size=256 lazy_itable_init=1 [mkfs.ext4] enable=has_journal,uninit_bg disable=large_file This configuration file will cause mke2fs(8) to use a block size of 1024 bytes and an inode size of 256 bytes. The inode table will be initialized lazily. For ext4 filesystems, the and features will be enabled by default, and the feature will be disabled by default. /etc/mke2fs.conf /usr/local/etc/mke2fs.conf ~/.mke2fs.conf mke2fs(8), mkfs.ext4(8), mkfs.ext3(8), mkfs.ext2(8) mkfs.ext4(8) - Linux manual page

ENVIRONMENT

MKE2FS_SYNC
إذا تم تعيينه إلى قيمة عدد صحيح غير صفرية، فسيتم استخدام قيمته لتحديد عدد المرات التي يتم فيها استدعاء sync(2) أثناء تهيئة جدول العقد.
MKE2FS_CONFIG
يحدد موقع ملف التكوين (انظر mke2fs.conf(5)).
MKE2FS_FIRST_META_BG
إذا تم تعيينه إلى قيمة عدد صحيح غير صفرية، فسيتم استخدام قيمته لتحديد مجموعة كتل البيانات الوصفية الأولى. هذا في الغالب لأغراض التصحيح.
MKE2FS_DEVICE_SECTSIZE
إذا تم تعيينه إلى قيمة عدد صحيح غير صفرية، فسيتم استخدام قيمته لتحديد حجم القطاع المنطقي لـ الجهاز.
MKE2FS_DEVICE_PHYS_SECTSIZE
إذا تم تعيينه إلى قيمة عدد صحيح غير صفرية، فسيتم استخدام قيمته لتحديد حجم القطاع الفعلي لـ الجهاز.
MKE2FS_SKIP_CHECK_MSG
إذا تم تعيينه، لا تعرض رسالة التحقق التلقائي لنظام الملفات الناتج عن عدد عمليات التحميل أو فاصل التحقق.
