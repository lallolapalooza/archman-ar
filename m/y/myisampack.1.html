الحزمة: mariadb

MYISAMPACK(1) نظام قواعد بيانات MariaDB MYISAMPACK(1)

الاسم

myisampack - إنشاء جداول MyISAM مضغوطة للقراءة فقط

الملخص

myisampack [خيارات] اسم_الملف ...

الوصف

تقوم أداة myisampack بضغط جداول MyISAM. تعمل myisampack عن طريق ضغط كل عمود في الجدول بشكل منفصل. عادةً، تقوم myisampack بضغط ملف البيانات بنسبة 40% إلى 70%.

عند استخدام الجدول لاحقًا، يقرأ الخادم المعلومات اللازمة لفك ضغط الأعمدة في الذاكرة. ينتج عن ذلك أداء أفضل بكثير عند الوصول إلى الصفوف الفردية، لأنه لا يلزم سوى فك ضغط صف واحد بالضبط.

يستخدم MariaDB وظيفة mmap() عند الإمكان لتنفيذ رسم الخرائط للذاكرة على الجداول المضغوطة. إذا لم تعمل mmap()، يعود MariaDB إلى عمليات الملفات العادية للقراءة/الكتابة.

يرجى ملاحظة ما يلي:

•إذا تم استدعاء خادم mariadbd بدون تمكين الأقفال الخارجية، فليس من الجيد استدعاء myisampack إذا كان من الممكن تحديث الجدول بواسطة الخادم أثناء عملية الضغط. الأكثر أمانًا هو ضغط الجداول مع إيقاف الخادم.

•بعد ضغط جدول، يصبح للقراءة فقط. هذا هو المقصود بشكل عام (مثل عند الوصول إلى الجداول المضغوطة على قرص CD).

قم باستدعاء myisampack بهذا الشكل:

shell> myisampack [خيارات] اسم_الملف ...

يجب أن يكون كل وسيط لاسم الملف هو اسم ملف فهرس (.MYI). إذا لم تكن في دليل قاعدة البيانات، فيجب عليك تحديد المسار إلى الملف. يجوز حذف الامتداد .MYI.

بعد ضغط جدول باستخدام myisampack، يجب عليك استخدام myisamchk -rq لإعادة بناء فهارسه. myisamchk(1).

تدعم myisampack الخيارات التالية. كما أنها تقرأ ملفات الخيارات وتدعم الخيارات المتعلقة بمعالجتها الموضحة في القسم 4.2.3.3.1، "خيارات سطر الأوامر التي تؤثر على معالجة ملفات الخيارات".

•--help, -?

عرض رسالة مساعدة والخروج.

•--backup, -b

إنشاء نسخة احتياطية من ملف بيانات كل جدول بالاسم اسم_الجدول.OLD.

•--character-sets-dir=مسار

الدليل الذي يتم فيه تثبيت مجموعات الأحرف. انظر القسم 9.5، "تكوين مجموعة الأحرف".

•--debug[=خيارات_التصحيح], -# [خيارات_التصحيح]

كتابة سجل تصحيح. سلسلة خيارات_التصحيح النموذجية هي 'd:t:o,اسم_الملف'. الافتراضي هو 'd:t:o'.

•--force, -f

إنتاج جدول مضغوط حتى لو أصبح أكبر من الجدول الأصلي أو إذا كان الملف الوسيط من استدعاء سابق لـ myisampack موجودًا. (تنشئ myisampack ملفًا وسيطًا يسمى اسم_الجدول.TMD في دليل قاعدة البيانات أثناء ضغط الجدول. إذا قمت بإنهاء myisampack، فقد لا يتم حذف ملف .TMD.) عادةً، تخرج myisampack بخطأ إذا وجدت أن اسم_الجدول.TMD موجود. مع --force، تقوم myisampack بضغط الجدول على أي حال.

•--join=اسم_جدول_كبير, -j اسم_جدول_كبير

دمج جميع الجداول المسماة في سطر الأوامر في جدول مضغوط واحد اسم_جدول_كبير. يجب أن تحتوي جميع الجداول التي سيتم دمجها على هيكل متطابق (نفس أسماء الأعمدة وأنواعها، ونفس الفهارس، وما إلى ذلك).

يجب ألا يكون اسم_جدول_كبير موجودًا قبل عملية الدمج. يجب أن تكون جميع الجداول المصدر المسماة في سطر الأوامر لدمجها في اسم_جدول_كبير موجودة. تتم قراءة الجداول المصدر لعملية الدمج ولكن لا يتم تعديلها. لا تنشئ عملية الدمج ملف .frm لـ اسم_جدول_كبير، لذلك بعد انتهاء عملية الدمج، انسخ ملف .frm من أحد الجداول المصدر وقم بتسميته اسم_جدول_كبير.frm.

•--silent, -s

الوضع الصامت. كتابة المخرجات فقط عند حدوث أخطاء.

•--test, -t

لا تقم بضغط الجدول فعليًا، فقط اختبر ضغطه.

•--tmpdir=مسار, -T مسار

استخدم الدليل المسمى كموقع تقوم فيه myisampack بإنشاء ملفات مؤقتة.

•--verbose, -v

الوضع المطول. كتابة معلومات حول تقدم عملية الضغط ونتيجتها.

•--version, -V

عرض معلومات الإصدار والخروج.

•--wait, -w

انتظر وأعد المحاولة إذا كان الجدول قيد الاستخدام. إذا تم استدعاء خادم mariadbd بدون تمكين الأقفال الخارجية، فليس من الجيد استدعاء myisampack إذا كان من الممكن تحديث الجدول بواسطة الخادم أثناء عملية الضغط.

NAME

myisampack

compress MyISAM table data

SYNOPSIS

myisampack [options] filename...

myisampack --unpack [options] filename...

DESCRIPTION

The myisampack utility compresses data files for MyISAM tables. It can make tables smaller and faster by removing redundant information. This process is lossless: the original table can be recovered from the compressed table. To unpack a packed table, use myisampack with the --unpack option.

When you run myisampack without any options, it performs a default compression that attempts to reduce the table size by eliminating trailing spaces, empty values, and constant values. The actual compression that is performed depends on the data contents of the table.

The myisampack utility uses Huffman compression and other techniques to reduce table size. The exact optimizations depend on the data type and content of each column.

After compressing a table, you should run myisamchk -rq to check the table integrity and update the index file. If you do not do this, the table may not be usable.

myisampack displays the following kinds of information:

•normal

The number of columns for which no extra packing is used.

•empty-space

The number of columns containing values that are only spaces. These occupy one bit.

•empty-zero

The number of columns containing values that are only binary zeros. These occupy one bit.

•empty-fill

The number of integer columns that do not occupy the full byte range of their type. These are changed to a smaller type. For example, a BIGINT column (eight bytes) can be stored as a TINYINT column (one byte) if all its values are in the range from -128 to 127.

•pre-space

The number of decimal columns that are stored with leading spaces. In this case, each value contains a count for the number of leading spaces.

•end-space

The number of columns that have a lot of trailing spaces. In this case, each value contains a count for the number of trailing spaces.

•table-lookup

The column had only a small number of different values, which were converted to an ENUM before Huffman compression.

•zero

The number of columns for which all values are zero.

•Original trees

The initial number of Huffman trees.

•After join

The number of distinct Huffman trees left after joining trees to save some header space.

After a table has been compressed, the Field lines displayed by myisamchk -dvv include additional information about each column:

•Type

The data type. The value may contain any of the following descriptors:

•constant

All rows have the same value.

•no endspace

Do not store endspace.

•no endspace, not_always

Do not store endspace and do not do endspace compression for all values.

•no endspace, no empty

Do not store endspace. Do not store empty values.

•table-lookup

The column was converted to an ENUM.

•zerofill(N)

The most significant N bytes in the value are always 0 and are not stored.

•no zeros

Do not store zeros.

•always zero

Zero values are stored using one bit.

•Huff tree

The number of the Huffman tree associated with the column.

•Bits

The number of bits used in the Huffman tree.

After you run myisampack, you must run myisamchk to re-create any indexes. At this time, you can also sort the index blocks and create statistics needed for the MariaDB optimizer to work more efficiently:

shell> myisamchk -rq --sort-index --analyze tbl_name.MYI

After you have installed the packed table into the MariaDB database directory, you should execute mariadb-admin flush-tables to force mariadbd to start using the new table.

To unpack a packed table, use the --unpack option to myisamchk.
