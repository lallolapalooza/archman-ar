EAGAIN
The MAP_NONBLOCK flag was specified, and the memory lock (specified by MAP_LOCKED) could not be acquired.
EBADF

EINVAL

ENOTSUP

الإصدارات

على بعض معماريات الأجهزة (مثل i386)، يعني PROT_WRITE ضمناً PROT_READ. يعتمد على المعمارية ما إذا كان PROT_READ يعني ضمنًا PROT_EXEC أم لا. يجب على البرامج المحمولة دائمًا تعيين PROT_EXEC إذا كانت تنوي تنفيذ التعليمات البرمجية في التعيين الجديد.

الطريقة المحمولة لإنشاء تعيين هي تحديد addr كـ 0 (NULL)، وحذف MAP_FIXED من flags. في هذه الحالة، يختار النظام العنوان للتعيين؛ يتم اختيار العنوان بحيث لا يتعارض مع أي تعيين موجود، ولن يكون 0. إذا تم تحديد العلم MAP_FIXED، و addr هو 0 (NULL)، فسيكون العنوان المعين 0 (NULL).

يتم تعريف ثوابت flags معينة فقط إذا تم تعريف وحدات الماكرو الاختبارية للميزات المناسبة (ربما افتراضيًا): _DEFAULT_SOURCE مع glibc 2.19 أو أحدث؛ أو _BSD_SOURCE أو _SVID_SOURCE في glibc 2.19 والأقدم. (استخدام _GNU_SOURCE كافٍ أيضًا، وكان من المنطقي أكثر أن يطلب هذا الماكرو تحديدًا، نظرًا لأن هذه العلامات خاصة بـ Linux.) العلامات ذات الصلة هي: MAP_32BIT، MAP_ANONYMOUS (والمرادف MAP_ANON)، MAP_DENYWRITE، MAP_EXECUTABLE، MAP_FILE، MAP_GROWSDOWN، MAP_HUGETLB، MAP_LOCKED، MAP_NONBLOCK، MAP_NORESERVE، MAP_POPULATE، و MAP_STACK.

اختلافات مكتبة C/النواة

تصف هذه الصفحة الواجهة التي توفرها دالة الغلاف mmap() الخاصة بـ glibc. في الأصل، استدعت هذه الدالة استدعاء نظام بنفس الاسم. منذ Linux 2.4، تم استبدال استدعاء النظام هذا بـ mmap2(2)، وفي الوقت الحاضر تستدعي دالة الغلاف mmap() الخاصة بـ glibc mmap2(2) بقيمة معدلة بشكل مناسب لـ offset.

المعايير

POSIX.1-2024.

التاريخ

POSIX.1-2001، SVr4، 4.4BSD.

على أنظمة POSIX التي تتوفر فيها mmap() و msync(2) و munmap()، يتم تعريف _POSIX_MAPPED_FILES في <unistd.h> بقيمة أكبر من 0. (انظر أيضًا sysconf(3)).

ملاحظات

يتم الحفاظ على الذاكرة المعينة بواسطة mmap() عبر fork(2)، بنفس السمات.

يتم تعيين الملف بمضاعفات حجم الصفحة. بالنسبة لملف ليس مضاعفًا لحجم الصفحة، يتم تصفير البايتات المتبقية في الصفحة الجزئية في نهاية التعيين عند تعيينها، ولا يتم كتابة التعديلات على تلك المنطقة إلى الملف. تأثير تغيير حجم الملف الأساسي لتعيين على الصفحات التي تتوافق مع المناطق المضافة أو المحذوفة من الملف غير محدد.

يمكن للتطبيق تحديد أي الصفحات في التعيين موجودة حاليًا في ذاكرة التخزين المؤقت للمخزن المؤقت/الصفحات باستخدام mincore(2).

استخدام MAP_FIXED بأمان

الاستخدام الآمن الوحيد لـ MAP_FIXED هو عندما تم حجز نطاق العنوان المحدد بواسطة addr و length مسبقًا باستخدام تعيين آخر؛ بخلاف ذلك، فإن استخدام MAP_FIXED خطير لأنه يزيل بشكل قسري التعيينات الموجودة مسبقًا، مما يسهل على العملية متعددة الخيوط إتلاف مساحة عنوانها الخاصة.

على سبيل المثال، لنفترض أن الخيط A يبحث في /proc/pid/maps لتحديد موقع نطاق عنوان غير مستخدم يمكنه تعيينه باستخدام MAP_FIXED، بينما يقوم الخيط B في نفس الوقت باكتساب جزء أو كل نفس نطاق العنوان. عندما يستخدم الخيط A لاحقًا mmap(MAP_FIXED)، فإنه سيقوم فعليًا بتغطية التعيين الذي أنشأه الخيط B. في هذا السيناريو، لا يحتاج الخيط B إلى إنشاء تعيين مباشرة؛ يكفي ببساطة استدعاء مكتبة تستخدم داخليًا dlopen(3) لتحميل مكتبة مشتركة أخرى. سيقوم استدعاء dlopen(3) بتعيين المكتبة في مساحة عنوان العملية. علاوة على ذلك، يمكن تنفيذ أي استدعاء مكتبة تقريبًا بطريقة تضيف تعيينات الذاكرة إلى مساحة العنوان، إما بهذه التقنية، أو ببساطة عن طريق تخصيص الذاكرة. تشمل الأمثلة brk(2) و malloc(3) و pthread_create(3) ومكتبات PAM http://www.linux-pam.org.

منذ Linux 4.17، يمكن لبرنامج متعدد الخيوط استخدام العلم MAP_FIXED_NOREPLACE لتجنب الخطر الموصوف أعلاه عند محاولة إنشاء تعيين في عنوان ثابت لم يتم حجزه بواسطة تعيين موجود مسبقًا.

تغييرات الطوابع الزمنية للتعيينات المدعومة بالملفات

بالنسبة للتعيينات المدعومة بالملفات، قد يتم تحديث الحقل st_atime للملف المعين في أي وقت بين mmap() وإلغاء التعيين المقابل؛ سيؤدي أول مرجع لصفحة معينة إلى تحديث الحقل إذا لم يتم ذلك بالفعل.

سيتم تحديث الحقلين st_ctime و st_mtime لملف معين باستخدام PROT_WRITE و MAP_SHARED بعد الكتابة في المنطقة المعينة، وقبل استدعاء msync(2) لاحقًا مع العلم MS_SYNC أو MS_ASYNC، إذا حدث أحدها.

تعيينات الصفحات الكبيرة (Huge TLB)

بالنسبة للتعيينات التي تستخدم الصفحات الكبيرة، تختلف متطلبات وسائط mmap() و munmap() بعض الشيء عن متطلبات التعيينات التي تستخدم حجم الصفحة النظامي الأصلي.

بالنسبة لـ mmap()، يجب أن يكون offset مضاعفًا لحجم الصفحة الكبيرة الأساسي. يقوم النظام تلقائيًا بمحاذاة length لتكون مضاعفًا لحجم الصفحة الكبيرة الأساسي.

بالنسبة لـ munmap()، يجب أن يكون كل من addr و length مضاعفًا لحجم الصفحة الكبيرة الأساسي.

محاذير

على عكس تطبيقات malloc(3) النموذجية، لا تمنع mmap() إنشاء كائنات أكبر من PTRDIFF_MAX. الكائنات التي تكون أكبر من PTRDIFF_MAX تعمل فقط بطرق محدودة في C (على وجه الخصوص، يؤدي طرح المؤشر إلى سلوك غير محدد إذا كانت النتيجة أكبر من PTRDIFF_MAX). بالإضافة إلى ذلك، يفترض GCC أيضًا أن لا يوجد كائن أكبر من PTRDIFF_MAX. عادةً ما يكون PTRDIFF_MAX نصف حجم مساحة العنوان؛ لذا بالنسبة لعمليات 32 بت، فهو عادةً 0x7fffffff (حوالي 2 جيجابايت).

أخطاء

في Linux، لا توجد ضمانات مثل تلك المقترحة أعلاه تحت MAP_NORESERVE. بشكل افتراضي، يمكن إنهاء أي عملية في أي لحظة عندما تنفد ذاكرة النظام.

قبل Linux 2.6.7، كان للعلم MAP_POPULATE تأثير فقط إذا تم تحديد prot كـ PROT_NONE.

يحدد SUSv3 أن mmap() يجب أن تفشل إذا كان length يساوي 0. ومع ذلك، قبل Linux 2.6.12، نجحت mmap() في هذه الحالة: لم يتم إنشاء أي تعيين وعادت الاستدعاء addr. منذ Linux 2.6.12، تفشل mmap() مع الخطأ EINVAL لهذه الحالة.

يحدد POSIX أن النظام يجب أن يقوم دائمًا بملء الصفحات الجزئية في نهاية الكائن بالصفر وأن النظام لن يكتب أبدًا أي تعديل للكائن بعد نهايته. في Linux، عند كتابة بيانات إلى مثل هذه الصفحة الجزئية بعد نهاية الكائن، تظل البيانات في ذاكرة التخزين المؤقت للصفحة حتى بعد إغلاق الملف وإلغاء تعيينه، وعلى الرغم من عدم كتابة البيانات إلى الملف نفسه، فقد ترى التعيينات اللاحقة المحتوى المعدل. في بعض الحالات، يمكن إصلاح ذلك عن طريق استدعاء msync(2) قبل إلغاء التعيين؛ ومع ذلك، هذا لا يعمل على tmpfs(5) (على سبيل المثال، عند استخدام واجهة الذاكرة المشتركة POSIX الموضحة في shm_overview(7)).

أمثلة

يطبع البرنامج التالي جزءًا من الملف المحدد في وسيطة سطر الأوامر الأولى الخاصة به إلى الإخراج القياسي. يتم تحديد نطاق البايتات المراد طباعتها عبر قيم الإزاحة والطول في وسيطات سطر الأوامر الثانية والثالثة. يقوم البرنامج بإنشاء تعيين للذاكرة للصفحات المطلوبة من الملف ثم يستخدم write(2) لإخراج البايتات المطلوبة.

مصدر البرنامج

#includ
e <err.h> #include <fcntl.h> #include <stdio.h> #include <stdlib.h> #include <sys/mman.h> #include <sys/stat.h> #include <sys/types.h> #include <unistd.h> int main(int argc, char *argv[]) { int fd; char *addr; off_t offset, pa_offset; size_t length; ssize_t s; struct stat sb; if (argc < 3 || argc > 4) { fprintf(stderr, "%s file offset [length]\n", argv[0]); exit(EXIT_FAILURE); } fd = open(argv[1], O_RDONLY); if (fd == -1) err(EXIT_FAILURE, "open"); if (fstat(fd, &sb) == -1) /* للحصول على حجم الملف */ err(EXIT_FAILURE, "fstat"); offset = atoi(argv[2]); pa_offset = offset & ~(sysconf(_SC_PAGE_SIZE) - 1); /* يجب أن يكون الإزاحة لـ mmap() متوافقة مع حجم الصفحة */ if (offset >= sb.st_size) { fprintf(stderr, "offset is past end of file\n"); exit(EXIT_FAILURE); } if (argc == 4) { length = atoi(argv[3]); if (offset + length > sb.st_size) length = sb.st_size - offset; /* لا يمكن عرض البايتات بعد نهاية الملف */ } else { /* لا يوجد وسيط طول ==> عرض حتى نهاية الملف */ length = sb.st_size - offset; } addr = mmap(NULL, length + offset - pa_offset, PROT_READ, MAP_PRIVATE, fd, pa_offset); if (addr == MAP_FAILED) err(EXIT_FAILURE, "mmap"); s = write(STDOUT_FILENO, addr + offset - pa_offset, length); if (s != length) { if (s == -1) err(EXIT_FAILURE, "write"); fprintf(stderr, "partial write"); exit(EXIT_FAILURE); } munmap(addr, length + offset - pa_offset); close(fd); exit(EXIT_SUCCESS); }
