DESCRIPTION

The libmaxminddb library provides functions for working MaxMind DB files. See https://maxmind.github.io/MaxMind-DB/ for the MaxMind DB format specification. The database and results are all represented by different data structures. Databases are opened by calling MMDB_open(). You can look up IP addresses as a string with MMDB_lookup_string() or as a pointer to a sockaddr structure with MMDB_lookup_sockaddr().

If the lookup finds the IP address in the database, it returns a MMDB_lookup_result_s structure. If that structure indicates that the database has data for the IP, there are a number of functions that can be used to fetch that data. These include MMDB_get_value() and MMDB_get_entry_data_list(). See the function documentation below for more details.

When you are done with the database handle you should call MMDB_close().

All publicly visible functions, structures, and macros begin with "MMDB_".

DATA STRUCTURES

All data structures exported by this library's maxminddb.h header are typedef'd in the form typedef struct foo_s { ... } foo_s so you can refer to them without the struct prefix.

This library provides the following data structures:

MMDB_s

This is the handle for a MaxMind DB file. We only document some of this structure's fields intended for public use. All other fields are subject to change and are intended only for internal use.

typedef struct MMDB_s {
    uint32_t flags;
    const char *filename;
    ...
    MMDB_metadata_s metadata;
} MMDB_s;
  • uint32_t flags - the flags this database was opened with. See the MMDB_open() documentation for more details.
  • const char *filename - the name of the file which was opened, as passed to MMDB_open().
  • MMDB_metadata_s metadata - the metadata for the database.

MMDB_metadata_s and MMDB_description_s

This structure can be retrieved from the MMDB_s structure. It contains the metadata read from the database file. Note that you may find it more convenient to access this metadata by calling MMDB_get_metadata_as_entry_data_list() instead.

typedef struct MMDB_metadata_s {
    uint32_t node_count;
    uint16_t record_size;
    uint16_t ip_version;
    const char *database_type;
    struct {
        size_t count;
        const char **names;
    } languages;
    uint16_t binary_format_major_version;
    uint16_t binary_format_minor_version;
    uint64_t build_epoch;
    struct {
        size_t count;
        MMDB_description_s **descriptions;
    } description;
} MMDB_metadata_s;
typedef struct MMDB_description_s {
    const char *language;
    const char *description;
} MMDB_description_s;

These structures should be mostly self-explanatory.

The ip_version member should always be 4 or 6. The binary_format_major_version should always be 2.

There is no requirement that the database metadata include languages or descriptions, so the count for these parts of the metadata can be zero. All of the other MMDB_metadata_s fields should be populated.

MMDB_lookup_result_s

This structure is returned as the result of looking up an IP address.

typedef struct MMDB_lookup_result_s {
    bool found_entry;
    MMDB_entry_s entry;
    uint16_t netmask;
} MMDB_lookup_result_s;

If the found_entry member is false then the other members of this structure do not contain meaningful values. Always check that found_entry is true first.

The entry member is used to look up the data associated with the IP address.

The netmask member tells you what subnet the IP address belongs to in this database. For example, if you look up the address 1.1.1.1 in an IPv4 database and the returned netmask is 16, then the address is part of the 1.1.0.0/16 subnet.

If the database is an IPv6 database, the returned netmask is always an IPv6 prefix length (from 0-128), even if that database also contains IPv4 networks. If you look up an IPv4 address and would like to turn the netmask into an IPv4 netmask value, you can simply subtract 96 from the value.

MMDB_result_s

You don't really need to dig around in this structure. You'll get this from a MMDB_lookup_result_s structure and pass it to various functions.

MMDB_entry_data_s

This structure is used to return a single data section entry for an IP. These entries can in turn point to other entries, as is the case for things like maps and arrays. Some members of this structure are not documented as they are only for internal use.

typedef struct MMDB_entry_data_s {
    bool has_data;
    union {
        uint32_t pointer;
        const char *utf8_string;
        double double_value;
        const uint8_t *bytes;
        uint16_t uint16;
        uint32_t uint32;
        int32_t int32;
        uint64_t uint64;
        {mmdb_uint128_t or uint8_t[16]} uint128;
        bool boolean;
        float float_value;
    };
    ...
    uint32_t data_size;
    uint32_t type;
} MMDB_entry_data_s;

The has_data member is true if data was found for a given lookup. See MMDB_get_value() for more details. If this member is false then none of the other values in the structure are meaningful.

الوصف

توفر مكتبة libmaxminddb وظائف للتعامل مع ملفات MaxMind DB. انظر https://maxmind.github.io/MaxMind-DB/ لمواصفات تنسيق MaxMind DB. يتم تمثيل قاعدة البيانات والنتائج جميعها بواسطة هياكل بيانات مختلفة. يتم فتح قواعد البيانات عن طريق استدعاء MMDB_open(). يمكنك البحث عن عناوين IP كسلسلة نصية باستخدام MMDB_lookup_string() أو كمؤشر إلى بنية sockaddr باستخدام MMDB_lookup_sockaddr().

إذا وجدت عملية البحث عنوان IP في قاعدة البيانات، فإنها تُرجع بنية MMDB_lookup_result_s. إذا أشارت هذه البنية إلى أن قاعدة البيانات تحتوي على بيانات لعنوان IP، فهناك عدد من الوظائف التي يمكن استخدامها لجلب هذه البيانات. وتشمل هذه MMDB_get_value() و MMDB_get_entry_data_list(). انظر توثيق الوظيفة أدناه لمزيد من التفاصيل.

عند الانتهاء من مقبض قاعدة البيانات، يجب عليك استدعاء MMDB_close().

تبدأ جميع الوظائف والهياكل والماكروات العامة بـ "MMDB_".

هياكل البيانات

جميع هياكل البيانات المصدرة بواسطة رأس maxminddb.h الخاص بهذه المكتبة يتم تعريفها بشكل مشروط بالشكل typedef struct foo_s { ... } foo_s حتى تتمكن من الإشارة إليها بدون البادئة struct.

توفر هذه المكتبة هياكل البيانات التالية:

MMDB_s

هذا هو المقبض لملف MaxMind DB. نوثق فقط بعض حقول هذا الهيكل المخصصة للاستخدام العام. تخضع جميع الحقول الأخرى للتغيير وهي مخصصة للاستخدام الداخلي فقط.

typedef struct MMDB_s {
    uint32_t flags;
    const char *filename;
    ...
    MMDB_metadata_s metadata;
} MMDB_s;
  • uint32_t flags - العلامات التي تم فتح قاعدة البيانات بها. انظر توثيق MMDB_open() لمزيد من التفاصيل.
  • const char *filename - اسم الملف الذي تم فتحه، كما تم تمريره إلى MMDB_open().
  • MMDB_metadata_s metadata - البيانات الوصفية لقاعدة البيانات.

MMDB_metadata_s و MMDB_description_s

يمكن استرداد هذا الهيكل من الهيكل MMDB_s. يحتوي على البيانات الوصفية المقروءة من ملف قاعدة البيانات. لاحظ أنه قد تجد أنه من الأنسب الوصول إلى هذه البيانات الوصفية عن طريق استدعاء MMDB_get_metadata_as_entry_data_list() بدلاً من ذلك.

typedef struct MMDB_metadata_s {
    uint32_t node_count;
    uint16_t record_size;
    uint16_t ip_version;
    const char *database_type;
    struct {
        size_t count;
        const char **names;
    } languages;
    uint16_t binary_format_major_version;
    uint16_t binary_format_minor_version;
    uint64_t build_epoch;
    struct {
        size_t count;
        MMDB_description_s **descriptions;
    } description;
} MMDB_metadata_s;
typedef struct MMDB_description_s {
    const char *language;
    const char *description;
} MMDB_description_s;

يجب أن تكون هذه الهياكل واضحة في الغالب.

يجب أن يكون عضو ip_version دائمًا 4 أو 6. يجب أن يكون binary_format_major_version دائمًا 2.

لا يوجد شرط بأن تتضمن البيانات الوصفية لقاعدة البيانات لغات أو أوصافًا، لذلك يمكن أن يكون count لهذه الأجزاء من البيانات الوصفية صفرًا. يجب ملء جميع حقول MMDB_metadata_s الأخرى.

MMDB_lookup_result_s

يتم إرجاع هذا الهيكل كنتيجة للبحث عن عنوان IP.

typedef struct MMDB_lookup_result_s {
    bool found_entry;
    MMDB_entry_s entry;
    uint16_t netmask;
} MMDB_lookup_result_s;

إذا كان عضو found_entry خاطئًا، فلن تحتوي الأعضاء الأخرى في هذا الهيكل على قيم ذات معنى. تحقق دائمًا من أن found_entry صحيح أولاً.

يُستخدم عضو entry للبحث عن البيانات المرتبطة بعنوان IP.

يخبرك عضو netmask عن الشبكة الفرعية التي ينتمي إليها عنوان IP في قاعدة البيانات هذه. على سبيل المثال، إذا بحثت عن العنوان 1.1.1.1 في قاعدة بيانات IPv4 وكان netmask المُرجع هو 16، فإن العنوان جزء من الشبكة الفرعية 1.1.0.0/16.

إذا كانت قاعدة البيانات قاعدة بيانات IPv6، فإن قناع الشبكة المُرجع هو دائمًا طول بادئة IPv6 (من 0-128)، حتى لو كانت قاعدة البيانات هذه تحتوي أيضًا على شبكات IPv4. إذا بحثت عن عنوان IPv4 وترغب في تحويل قناع الشبكة إلى قيمة قناع شبكة IPv4، يمكنك ببساطة طرح 96 من القيمة.

MMDB_result_s

لا تحتاج حقًا إلى التعمق في هذا الهيكل. ستحصل عليه من الهيكل MMDB_lookup_result_s وتمرره إلى وظائف مختلفة.

MMDB_entry_data_s

يُستخدم هذا الهيكل لإرجاع قسم بيانات واحد لإدخال لعنوان IP. يمكن أن تشير هذه الإدخالات بدورها إلى إدخالات أخرى، كما هو الحال في أشياء مثل الخرائط والمصفوفات. لم يتم توثيق بعض حقول هذا الهيكل لأنها للاستخدام الداخلي فقط.

typedef struct MMDB_entry_data_s {
    bool has_data;
    union {
        uint32_t pointer;
        const char *utf8_string;
        double double_value;
        const uint8_t *bytes;
        uint16_t uint16;
        uint32_t uint32;
        int32_t int32;
        uint64_t uint64;
        {mmdb_uint128_t or uint8_t[16]} uint128;
        bool boolean;
        float float_value;
    };
    ...
    uint32_t data_size;
    uint32_t type;
} MMDB_entry_data_s;

العضو has_data صحيح إذا تم العثور على بيانات لعملية بحث معينة. انظر MMDB_get_value() لمزيد من التفاصيل. إذا كان هذا العضو خاطئًا، فإن أيًا من القيم الأخرى في الهيكل ليست ذات معنى.

يحدد الاتحاد في بداية الهيكل البيانات الفعلية. لتحديد أي اتحاد

Mantén toda la estructura del archivo.

إذا كان هناك عضو مملوء، يجب عليك فحص العضو type. يجب ألا يكون العضو pointer في الاتحاد مملوءًا في أي بيانات تم إرجاعها بواسطة واجهة برمجة التطبيقات (API). يجب حل المؤشرات داخليًا.

العضو data_size ذو صلة فقط ببيانات من نوع utf8_string و bytes. utf8_string غير منتهٍ بـ NULL ويجب استخدام data_size لتحديد طوله.

يمكن مقارنة العضو type بأحد وحدات الماكرو MMDB_DATA_TYPE_*.

أعداد صحيحة 128 بت

يعتمد التعامل مع بيانات من نوع uint128 على كيفية دعم منصتك للأعداد الصحيحة ذات 128 بت، سواء كانت تدعمها أم لا. مع GCC 4.4 و 4.5 يمكننا كتابة unsigned int __attribute__ ((__mode__ (TI))). مع الإصدارات الأحدث من GCC (4.6+) و Clang (3.2+) يمكننا ببساطة كتابة "unsigned __int128".

للتحايل على هذه الاختلافات، تحدد هذه المكتبة نوعًا mmdb_uint128_t. يتم تعريف هذا النوع في ملف الرأس maxminddb.h حتى تتمكن من استخدامه في الكود الخاص بك.

مع المترجمات الأقدم، لا يمكننا استخدام عدد صحيح، لذلك نستخدم مصفوفة من 16 بايت من uint8_t. هذه هي البيانات المباشرة من قاعدة البيانات.

توفر هذه المكتبة ماكرو عامًا MMDB_UINT128_IS_BYTE_ARRAY. إذا كان هذا صحيحًا (1)، يتم إرجاع قيم uint128 كمصفوفة بايت، وإلا، كعدد صحيح mmdb_uint128_t.

قيم المؤشرات و MMDB_close()

الأعضاء utf8_string و bytes و (ربما) العضو uint128 في هذا الهيكل كلها مؤشرات مباشرة إلى قسم بيانات قاعدة البيانات. يمكن أن تكون هذه كتلة ذاكرة مخصصة بواسطة calloc أو mmap. في كلتا الحالتين، تصبح هذه المؤشرات غير صالحة بعد استدعاء MMDB_close().

إذا كنت بحاجة إلى الإشارة إلى هذه البيانات بعد ذلك الوقت، يجب عليك نسخ البيانات باستخدام دالة مناسبة (strdup، memcpy، إلخ).

MMDB_entry_data_list_s

يغلف هذا الهيكل قائمة مرتبطة من هياكل MMDB_entry_data_s.

typedef struct MMDB_entry_data_list_s {  
    MMDB_entry_data_s entry_data;  
    struct MMDB_entry_data_list_s *next;  
} MMDB_entry_data_list_s;

يسمح لك هذا الهيكل بفحص بيانات الخريطة أو المصفوفة عن طريق التكرار فوق القائمة المرتبطة.

MMDB_search_node_s

يغلف هذا الهيكل سجلين لعقدة بحث. هذا مفيد جدًا إذا كنت تريد كتابة كود يكرر شجرة البحث بأكملها بدلاً من البحث عن عنوان IP محدد.

typedef struct MMDB_search_node_s {  
    uint64_t left_record;  
    uint64_t right_record;  
    uint8_t left_record_type;  
    uint8_t right_record_type;  
    MMDB_entry_s left_record_entry;  
    MMDB_entry_s right_record_entry;  
} MMDB_search_node_s;

ستكون أنواع السجلات أحد القيم التالية:

  • MMDB_RECORD_TYPE_SEARCH_NODE - يشير السجل إلى عقدة البحث التالية.
  • MMDB_RECORD_TYPE_EMPTY - السجل هو عنصر نائب يشير إلى عدم وجود بيانات لعنوان IP. يجب أن تنتهي عملية البحث هنا.
  • MMDB_RECORD_TYPE_DATA - يحتوي السجل على بيانات في قسم بيانات قاعدة البيانات. استخدم السجل عند البحث عن بيانات السجل.
  • MMDB_RECORD_TYPE_INVALID - السجل غير صالح. قد يكون السبب هو البحث عن عقدة غير صالحة أو تلف قاعدة البيانات.

يكون MMDB_entry_s للسجل صالحًا فقط إذا كان النوع هو MMDB_RECORD_TYPE_DATA. يؤدي استخدام سجل من أنواع أخرى إلى حدوث خطأ أو بيانات غير صالحة.

رموز الحالة

ترجع هذه المكتبة (أو تملأ) رموز الحالة للعديد من الوظائف. رموز الحالة هذه هي:

  • MMDB_SUCCESS - كل شيء سار على ما يرام.
  • MMDB_FILE_OPEN_ERROR - حدث خطأ عند فتح ملف MaxMind DB.
  • MMDB_IO_ERROR - فشلت عملية إدخال / إخراج. تحقق من errno لمزيد من التفاصيل.
  • MMDB_CORRUPT_SEARCH_TREE_ERROR - عند البحث عن عنوان IP في شجرة البحث، تم الحصول على نتيجة مستحيلة. قاعدة البيانات تالفة أو تم إنشاؤها بشكل غير صحيح أو هناك خطأ في كود libmaxminddb.
  • MMDB_INVALID_METADATA_ERROR - هناك خطأ في بيانات قاعدة البيانات. يشمل ذلك مفاتيح بيانات التعريف المفقودة أو القيم المستحيلة (مثل ip_version = 7).
  • MMDB_UNKNOWN_DATABASE_FORMAT_ERROR - تشير بيانات التعريف الخاصة بقاعدة البيانات إلى أن الإصدار الرئيسي الخاص بها ليس 2. يمكن لهذه المكتبة فقط التعامل مع الإصدار الرئيسي 2.
  • MMDB_OUT_OF_MEMORY_ERROR - فشل استدعاء تخصيص الذاكرة (malloc، إلخ).
  • MMDB_INVALID_DATA_ERROR - يحتوي حقل بيانات على بيانات غير صالحة. على سبيل المثال، يدعي حقل uint16 أنه أكثر من 2 بايت. من المحتمل أن تكون قاعدة البيانات تالفة أو تم إنشاؤها بشكل غير صحيح.
  • MMDB_INVALID_LOOKUP_PATH_ERROR - يحتوي مسار البحث الذي تم تمريره إلى MMDB_get_value أو MMDB_vget_value أو MMDB_aget_value على إزاحة مصفوفة أكبر من LONG_MAX أو أصغر من LONG_MIN.
  • MMDB_LOOKUP_PATH_DOES_NOT_MATCH_DATA_ERROR - مسار البحث الذي تم تمريره إلى MMDB_get_value أو MMDB_vget_value أو MMDB_aget_value لا يتطابق مع بنية بيانات الإدخال. يمكن أن تحدث أسباب متعددة. قد يتضمن مسار البحث مفتاحًا غير موجود في خريطة. قد يتضمن مسار البحث فهرس مصفوفة أكبر من مصفوفة أو أصغر من الحد الأدنى للإزاحة من نهاية مصفوفة. قد يحدث أيضًا عندما يتوقع المسار العثور على خريطة أو مصفوفة حيث لا توجد.

يجب التعامل مع جميع رموز الحالة كقيم من النوع int.

MMDB_strerror()

const char *MMDB_strerror(int error_code)

تأخذ هذه الدالة رمز حالة وترجع سلسلة نصية باللغة الإنجليزية تشرح الحالة.

الوظائف

توفر هذه المكتبة الوظائف المصدرة التالية:

MMDB_open()

int MMDB_open(  
    const char *const filename,  
    uint32_t flags,  
    MMDB_s *const mmdb);

تفتح هذه الدالة مقبضًا لملف MaxMind DB. قيمة الإرجاع هي رمز حالة كما هو محدد أعلاه. يجب عليك التحقق من قيمة الإرجاع لهذا الاستدعاء.

MMDB_s mmdb;  
int status =  
    MMDB_open("/path/to/file.mmdb", MMDB_MODE_MMAP, &mmdb);  
if (MMDB_SUCCESS != status) { ... }  
...  
MMDB_close(&mmdb);

يجب ترميز filename بنظام UTF-8 على نظام Windows.

يمكن أن يكون الهيكل MMDB_s الذي تمرره على المكدس أو محجوزًا في ذاكرة الكومة. ومع ذلك، إذا كان الفتح ناجحًا، فسوف يحتوي على بيانات محجوزة في ذاكرة الكومة، لذلك يجب عليك إغلاقه باستخدام MMDB_close(). إذا لم يكن رمز الحالة MMDB_SUCCESS، فستضمن هذه المكتبة تحرير جميع الذاكرة المحجوزة قبل الإرجاع.

الأعلام الحالية هي:

•
MMDB_MODE_MMAP - يفتح الملف باستخدام mmap().

يمكنك تمرير 0 كقيمة لـ flags لفتح الملف بالأعلام الافتراضية. ومع ذلك، قد تتغير هذه القيم في الإصدارات المستقبلية. القيمة الافتراضية هي MMDB_MODE_MMAP.

MMDB_close()

void MMDB_close(MMDB_s *const mmdb);

تقوم هذه المكتبة بتحرير أي ذاكرة محجوزة أو mapped (mmap'd) مرتبطة بالهيكل MMDB_s. لا تحرر ذاكرة قاعدة البيانات.

y مخصص للهيكل نفسه! إذا قمت بتخصيص الهيكل من الكومة، فأنت مسؤول عن تحريره.

MMDB_lookup_string()

MMDB_lookup_result_s MMDB_lookup_string(
    MMDB_s *const mmdb,
    const char *const ipstr,
    int *const gai_error,
    int *const mmdb_error);

تبحث هذه الدالة عن عنوان IP يتم تمريره كسلسلة نصية منتهية بـ null. داخليًا، تقوم باستدعاء getaddrinfo() لحل العنوان إلى شكل ثنائي. ثم تستدعي MMDB_lookup_sockaddr() للبحث عن العنوان في قاعدة البيانات. إذا كنت قد قمت بالفعل بحل عنوان، يمكنك استدعاء MMDB_lookup_sockaddr() مباشرة، بدلاً من حل العنوان مرتين.

int gai_error, mmdb_error;
MMDB_lookup_result_s result =
    MMDB_lookup_string(&mmdb, "1.2.3.4", &gai_error, &mmdb_error);
if (0 != gai_error) { ... }
if (MMDB_SUCCESS != mmdb_error) { ... }
if (result.found_entry) { ... }

ترجع هذه الدالة دائمًا هيكل MMDB_lookup_result_s، ولكن يجب عليك أيضًا التحقق من المعلمات gai_error و mmdb_error. إذا أشارت أي من هذه إلى خطأ، فإن الهيكل المرجع يكون بلا معنى.

إذا لم يحدث خطأ، لا يزال يتعين عليك التأكد من أن عضو found_entry في النتيجة المرجعة صحيح. إذا لم يكن كذلك، فهذا يعني أن عنوان IP ليس له إدخال في قاعدة البيانات.

ستعمل هذه الدالة مع عناوين IPv4 حتى عندما تحتوي قاعدة البيانات على بيانات لكل من عناوين IPv4 و IPv6. سيتم البحث عن عنوان IPv4 كـ '::xxx.xxx.xxx.xxx' بدلاً من إعادة تعيينه إلى كتلة ::ffff:xxx.xxx.xxx.xxx المخصصة لعناوين IPv6 المضمنة لـ IPv4.

إذا قمت بتمرير عنوان IPv6 إلى قاعدة بيانات تحتوي فقط على بيانات IPv4، فسيكون عضو found_entry خاطئًا، ولكن حالة mmdb_error ستظل MMDB_SUCCESS.

MMDB_lookup_sockaddr()

MMDB_lookup_result_s MMDB_lookup_sockaddr(
    MMDB_s *const mmdb,
    const struct sockaddr *const sockaddr,
    int *const mmdb_error);

تبحث هذه الدالة عن عنوان IP تم حله بالفعل بواسطة getaddrinfo().

بخلاف عدم استدعاء getaddrinfo() بنفسها، هذه الدالة متطابقة مع الدالة MMDB_lookup_string().

int mmdb_error;
MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
if (MMDB_SUCCESS != mmdb_error) { ... }
if (result.found_entry) { ... }

وظائف البحث عن البيانات

هناك ثلاث دوال للبحث عن البيانات المرتبطة بعنوان IP.

int MMDB_get_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    ...);
int MMDB_vget_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    va_list va_path);
int MMDB_aget_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    const char *const *const path);

تسمح الدوال الثلاث بثلاثة أنماط استدعاء مختلفة قليلاً، لكنها جميعًا تفعل الشيء نفسه.

المعلمة الأولى هي قيمة MMDB_entry_s. في معظم الحالات، ستأتي هذه من قيمة MMDB_lookup_result_s التي تم إرجاعها بواسطة MMDB_lookup_string() أو MMDB_lookup_sockaddr().

المعلمة الثانية هي مرجع إلى هيكل MMDB_entry_data_s. سيتم ملء هذا بالبيانات التي يتم البحث عنها، إذا تم العثور على أي شيء. إذا لم يتم العثور على شيء، فسيكون العضو has_data في هذا الهيكل خاطئًا. إذا كان has_data صحيحًا، يمكنك النظر إلى العضو data_type.

المعلمة النهائية هي مسار بحث. يتكون المسار من مجموعة من السلاسل النصية التي تمثل إما مفاتيح الخريطة (مثل، "city") أو فهارس المصفوفة (مثل، "0"، "1"، "-1") لاستخدامها في البحث.

سيتم التعامل مع فهارس المصفوفة السالبة كإزاحة من نهاية المصفوفة. على سبيل المثال، يشير "-1" إلى العنصر الأخير في المصفوفة.

يسمح لك مسار البحث بالتنقل في هيكل بيانات معقد. على سبيل المثال، بالنظر إلى هذه البيانات:

{
    "names": {
        "en": "Germany",
        "de": "Deutschland"
    },
    "cities": [ "Berlin", "Frankfurt" ]
}

يمكننا البحث عن الاسم الإنجليزي باستخدام هذا الرمز:

MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
MMDB_entry_data_s entry_data;
int status =
    MMDB_get_value(&result.entry, &entry_data,
                   "names", "en", NULL);
if (MMDB_SUCCESS != status) { ... }
if (entry_data.has_data) { ... }

إذا أردنا العثور على المدينة الأولى، فسيكون مسار البحث "cities", "0". إذا لم تقم بتوفير مسار بحث على الإطلاق، فستحصل على الإدخال الذي يتوافق مع الخريطة ذات المستوى الأعلى. يجب أن ينتهي مسار البحث دائمًا بـ NULL، بغض النظر عن الدالة التي تستدعيها.

تأخذ الدالة MMDB_get_value عددًا متغيرًا من الوسائط. جميع الوسائط بعد مؤشر هيكل MMDB_entry_data_s * هي مسار البحث. يجب أن تكون الوسيطة الأخيرة NULL.

تقبل الدالة MMDB_vget_value قائمة va_list كمسار بحث. يجب أن تكون العنصر الأخير الذي تم استرداده بواسطة va_arg() هو NULL.

أخيرًا، تقبل الدالة MMDB_aget_value مصفوفة من السلاسل النصية كمسار بحث. يجب أن يكون العضو الأخير في هذه المصفوفة NULL.

إذا كنت ترغب في الحصول على جميع بيانات الإدخال مرة واحدة، يمكنك استدعاء MMDB_get_entry_data_list() بدلاً من ذلك.

لكل من الدوال الثلاث، القيمة المرجعة هي رمز حالة كما هو محدد أعلاه.

MMDB_get_entry_data_list()

int MMDB_get_entry_data_list(
    MMDB_entry_s *start,
    MMDB_entry_data_list_s **const entry_data_list);

تسمح لك هذه الدالة بالحصول على جميع البيانات لهيكل بيانات معقد دفعة واحدة، بدلاً من البحث عن كل قطعة باستخدام استدعاءات متكررة لـ MMDB_get_value().

MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
MMDB_entry_data_list_s *entry_data_list, *first;
int status =
    MMDB_get_entry_data_list(&result.entry, &entry_data_list);
if (MMDB_SUCCESS != status) { ... }
// حفظ هذا حتى نتمكن من تحرير هذه البيانات لاحقًا
first = entry_data_list;
while (1) {
    MMDB_entry_data_list_s *next = entry_data_list = entry_data_list->next;
    if (NULL == next) {
        break;
    }
    switch (next->entry_data.type) {
        case MMDB_DATA_TYPE_MAP: { ... }
        case MMDB_DATA_TYPE_UTF8_STRING: { ... }
        ...
    }
}
MMDB_free_entry_data_list(first);

يعود إليك تفسير هيكل بيانات entry_data_list. القائمة مرتبطة في اجتياز عمق أول. لنستخدم هذا الهيكل كمثال:

{
    "names": {
        "en": "Germany",
        "de": "Deutschland"
    },
    "cities": [ "Berlin", "Frankfurt" ]
}

ستتكون القائمة من العناصر التالية:

1.
MAP - خريطة المستوى الأعلى
2.
UTF8_STRING - مفتاح "names"
3.
MAP - خريطة لمفتاح "names"
4.
UTF8_STRING - مفتاح "en"
5.
UTF8_STRING - قيمة لمفتاح "en"
6.
UTF8_STRING - مفتاح "de"
7.
UTF8_STRING - قيمة لمفتاح "de"
8.
UTF8_STRING - مفتاح "cities"
9.
ARRAY - قيمة لمفتاح "cities"
10.
UTF8_STRING - array[0]
11.
UTF8_STRING - array[1]

القيمة المرجعة للدالة هي رمز حالة كما هو محدد أعلاه.

MMDB_free_entry_data_list()

void MMDB_free_entry_data_list(
    MMDB_entry_data_list_s *const entry_data_list);

ستقوم الدوال MMDB_get_entry_data_list() و MMDB_get_metadata_as_entry_data_list() بتخصيص هيكل القائمة المرتبطة من الكومة. استدعاء هذه الدالة لتحرير هيكل MMDB_entry_data_list_s.

MMDB_get_metadata_as_entry_data_list()

int MMDB_get_metadata_as_entry_data_list(
    MMDB_s *const mmdb,
    MMDB_entry_data_list_s **const entry_data_list);

تسمح لك هذه الدالة باسترداد بيانات التعريف الخاصة بقاعدة البيانات كقائمة مرتبطة من هياكل MMDB_entry_data_list_s. يمكن أن يكون هذا طريقة أكثر ملاءمة للتعامل مع بيانات التعريف من استخدام هيكل بيانات التعريف مباشرة.

    MMDB_entry_data_list_s *entry_data_list, *first;
    int status =
        MMDB_get_metadata_as_entry_data_list(&mmdb, &entry_data_list);
    if (MMDB_SUCCESS != status) { ... }
    first = entry_data_list;
    ... // افعل شيئًا بالبيانات
    MMDB_free_entry_data_list(first);

القيمة المرجعة للدالة هي رمز حالة كما هو محدد أعلاه.

MMDB_dump_entry_data_list()

int MMDB_dump_entry_data_list(
    FILE *const stream,
    MMDB_entry_data_list_s *const entry_data_list,
    int indent);

تأخذ هذه الدالة قائمة مرتبطة من هياكل MMDB_entry_data_list_s وتحولها إلى سلسلة نصية إلى stream المحدد. المعلمة indent هي مستوى المسافة البادئة الأولي للمخرجات المتولدة. يتم زيادتها لهياكل البيانات المتداخلة (الخرائط، المصفوفات، إلخ).

يجب أن يكون stream مقبض ملف (stdout، إلخ). إذا كانت منصتك توفر شيئًا مثل GNU open_memstream()، يمكنك استخدامه لالتقاط الإخراج كسلسلة نصية.

يتم تنسيق الإخراج بأسلوب يشبه JSON، ولكن يتم تمييز القيم بأنواع بياناتها (باستثناء الخرائط والمصفوفات التي تظهر مع ""{}"" و ""[]"" على التوالي).
