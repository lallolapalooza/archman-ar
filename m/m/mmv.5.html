MMV(5) دليل تنسيقات الملفات MMV(5)

اسم

mmv - قيم معينة في الذاكرة لتحسين الأداء

الملخص

$PCP_TMP_DIR/mmv/<file>

الوصف

الملفات الموجودة في $PCP_TMP_DIR/mmv يتم إنشاؤها إما بواسطة دالتي mmv_stats_init(3) و mmv_stats2_init(3) من مكتبة libpcp_mmv، أو بواسطة وحدة لغة أصلية مثل Parfait (Java) أو Speed (Golang) أو Hornet (Rust).

قد يكون هناك عدة ملفات في هذا الدليل، كل ملف يمثل مصدرًا واحدًا لمقاييس الأداء. يتم جلب المقاييس بواسطة pmdammv(1) الذي يقوم بتصديرها إلى بقية بنية Performance Co-Pilot.

تنسيق الملف

كل ملف يبدأ بالترويسة التالية:

الإزاحة الطول الاسم
0 4 الوسم == "MMV\0"
4 4 الإصدار (1 أو 2)
8 8 الجيل 1
16 8 الجيل 2
24 4 عدد إدخالات جدول المحتويات
28 4 الأعلام
32 4 معرف العملية (PID)
36 4 معرف المجموعة

يحدد رقم الإصدار تنسيق تخطيط التعيين المستخدم. هناك اثنان، كلاهما متشابه جدًا، كما هو موضح أدناه. الغرض الوحيد من تنسيق MMV الإصدار 2 هو السماح باستخدام أسماء مقاييس ومثيل أطول. إذا لم يتم استخدام أسماء أطول من MMV_NAMEMAX، فمن الأفضل استخدام تنسيق MMV الإصدار 1 حيث يسمح هذا للإصدارات الأقدم من PCP بمعالجة البيانات أيضًا. تمت إضافة دعم للتنسيق v2 في الإصدار pcp-3.11.4.

أرقام الأجيال هي طوابع زمنية وقت إنشاء الملف، ويجب أن تتطابق لكي يعتبر ملف MMV PMDA الملف.

يمكن للأعلام تحديد الطرق التي يفضل أن يتصرف بها MMV PMDA - على سبيل المثال، يحدد علم MMV_FLAG_PROCESS أنه يجب تصدير تلك القيم فقط إذا كانت العملية المحددة بواسطة PID قيد التشغيل حاليًا.

أخيرًا، إذا تم تعيين معرف المجموعة، فهو تلميح إلى MMV PMDA بشأن المجموعة التي يجب استخدامها مع هذا التطبيق عند تكوين معرفات المقاييس الفردية. معرف مقياس الأداء (انظر PMDA(3)) يتكون من رقم مجال PMDA، ورقم المجموعة، وأرقام العناصر الفردية الموضحة في قسم المقاييس.

تتبع الترويسة قسمين على الأقل من جدول المحتويات: قسم للمقاييس وقسم آخر للقيم. قسم جدول المحتويات له التنسيق التالي:

الإزاحة الطول القيمة
0 4 نوع القسم (انظر mmv_stats.h)
4 4 عدد الإدخالات في القسم
8 8 إزاحة القسم من بداية الملف

أنواع الأقسام هي:

1: إدخالات المجال (تعريفات مجال المثيلات)
2: المثيلات
3: المقاييس (تعريفات المقاييس)
4: القيم
5: سلسلة نصية
6: تسميات

الأقسام الإلزامية الوحيدة هي المقاييس والقيم. تظهر أقسام إدخالات المجال والمثيلات من أي إصدار فقط إذا كانت هناك مقاييس ذات مثيلات متعددة. تظهر أقسام السلاسل النصية فقط إذا كانت هناك مقاييس ذات قيم سلاسل نصية، عندما يتم تعريف المقاييس أو إدخالات المجال بنص مساعدة، أو في تنسيق MMV v2 حيث يتم تخزين أسماء المقاييس وأسماء المثيلات في أقسام السلاسل النصية (مما يوفر مساحة أكبر بكثير من تنسيق MMV v1 لهذه الأسماء). تظهر أقسام التسميات فقط إذا كانت هناك مقاييس مشروحة بتسميات (أزواج الاسم/القيمة). يتم دعم التسميات في تنسيق MMV v3.

تحتوي الإدخالات في أقسام إدخالات المجال على التنسيق التالي:

الإزاحة الطول القيمة
0 4 رقم تسلسلي فريد لهذا المجال
4 4 عدد الإدخالات في المجال
8 8 إزاحة المثيل الأول أو المثيل2
16 8 إزاحة نص المساعدة القصير
24 8 إزاحة نص المساعدة الطويل

تحتوي الإدخالات في قسم المثيلات (v1) على التنسيق التالي:

الإزاحة الطول القيمة
0 8 إزاحة داخل قسم إدخال المجال
8 4 حشو غير مستخدم (معبأ بالأصفار)
12 4 معرف المثيل الداخلي
16 64 معرف المثيل الخارجي

FILE FORMAT

The mmv tool's binary file format is described by the following structures. The byte order is little-endian.

The entries in the Indom section have the following format:

الإزاحة الطول القيمة
Offset Length Value
0 8 Offset into the indom section
8 4 Unused padding (zero filled)
12 4 Internal instance identifier
16 8 External instance identifier string offset

The entries in the Metrics (v1) section have the following format:

Offset Length Value
0 64 Metric Name
64 4 Metric Item (see PMDA(3))
68 4 Metric Type (see mmv_stats.h)
72 4 Semantics (see PMAPI(3))
76 4 Dimensions (see PMAPI(3))
80 4 Instance Domain ID
84 4 Unused padding (zero filled)
88 8 Short help text offset
96 8 Long help text offset

The entries in the Metrics (v2) section have the following format:

Offset Length Value
0 8 Metric Name string offset
8 4 Metric Item (see PMDA(3))
12 4 Metric Type (see mmv_stats.h)
16 4 Semantics (see PMAPI(3))
20 4 Dimensions (see PMAPI(3))
24 4 Instance Domain ID
28 4 Unused padding (zero filled)
32 8 Short help text offset
40 8 Long help text offset

The entries in the Values section have the following format:

Offset Length Value
0 8 pmAtomValue (see PMAPI(3))
8 8 Extra space for STRING and ELAPSED
16 8 Offset into the Metrics section
24 8 Offset into the Instances section

Each entry in the strings section is a 256 byte character array, containing a single NULL-terminated character string. So each string has a maximum length of 256 bytes, which includes the terminating NULL.

The entries in the Labels (v3) section have the following format:

Offset Length Value
0 4 Flags - PM_LABEL_ CLUSTER, ITEM, INDOM, INSTANCES and OPTIONAL
4 4 Identifier for given type (indom, cluster or item)
8 4 Internal Instance or PM_IN_NULL
12 244 Payload (Name and Value JSONB String)

Each entry in the payload is a 244 byte (maximum) character array, containing a single NULL-terminated name:value pair in JSON format. Insignificant whitespace must not be present. Label names consist only of alphanumeric characters or underscores, and must begin with an alphabetic. Upper and lower case characters are considered distinct.
