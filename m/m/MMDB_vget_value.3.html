MMDB_vget_value(3)

الحزمة: libmaxminddb

التراخيص: Apache-2.0

Mantén toda la estructura del archivo.

Si deseas llenar la estructura, debes ver la propiedad type. La propiedad pointer de la unión nunca debe ser poblada en cualquier datos devueltos por la API. Los punteros deben resolverse internamente.

La propiedad data_size es solo relevante para datos de tipo utf8_string y bytes. utf8_string no es terminada con null y data_size debe usarse para determinar su longitud.

La propiedad type puede compararse con una de las macros MMDB_DATA_TYPE_*.

128-bit Integers

El manejo de datos de tipo uint128 depende de cómo tu plataforma soporta los enteros de 128 bits, si lo hace o no. Con GCC 4.4 y 4.5 podemos escribir unsigned int __attribute__ ((__mode__ (TI))). Con versiones más recientes de GCC (4.6+) y clang (3.2+) podemos simplemente escribir "unsigned __int128".

Para trabajar alrededor de estas diferencias, esta biblioteca define un tipo mmdb_uint128_t. Este tipo está definido en el encabezado maxminddb.h, así puedes usarlo en tu código propio.

Con compiladores antiguos no podemos usar un entero, por lo que usamos un arreglo de 16 bytes de uint8_t. Esto es el datos directo de la base de datos.

Esta biblioteca proporciona una macro pública MMDB_UINT128_IS_BYTE_ARRAY. Si esta es verdadera (1), los valores uint128 se devuelven como un arreglo de bytes, si es falsa se devuelven como un entero mmdb_uint128_t.

Data Type Macros

Esta biblioteca proporciona una macro para cada tipo de datos definido por el esquema MaxMind DB.

  • MMDB_DATA_TYPE_UTF8_STRING
  • MMDB_DATA_TYPE_DOUBLE
  • MMDB_DATA_TYPE_BYTES
  • MMDB_DATA_TYPE_UINT16
  • MMDB_DATA_TYPE_UINT32
  • MMDB_DATA_TYPE_MAP
  • MMDB_DATA_TYPE_INT32
  • MMDB_DATA_TYPE_UINT64
  • MMDB_DATA_TYPE_UINT128
  • MMDB_DATA_TYPE_ARRAY
  • MMDB_DATA_TYPE_BOOLEAN
  • MMDB_DATA_TYPE_FLOAT

También hay algunos tipos que se usan solo internamente:

  • MMDB_DATA_TYPE_EXTENDED
  • MMDB_DATA_TYPE_POINTER
  • MMDB_DATA_TYPE_CONTAINER
  • MMDB_DATA_TYPE_END_MARKER

Si ves uno de estos en los datos devueltos, algo ha ido muy mal. La base de datos está dañada o fue generada incorrectamente o hay un error en el código de libmaxminddb.

Pointer Values and MMDB_close()

Los miembros utf8_string, bytes y (puede ser) el miembro uint128 de esta estructura son direcciones directas a la sección de datos de la base de datos. Esto puede ser un bloque calloc o un bloque mmap de memoria. En cualquiera de los casos, estos punteros se invalidarán después de que se llame a MMDB_close().

Si necesitas referirte a este dato después de ese tiempo, debes copiar los datos con una función adecuada (strdup, memcpy, etc.).

MMDB_entry_data_list_s

Esta estructura encapsula una lista enlazada de estructuras MMDB_entry_data_s.

typedef struct MMDB_entry_data_list_s {
    MMDB_entry_data_s entry_data;
    struct MMDB_entry_data_list_s *next;
} MMDB_entry_data_list_s;

Esta estructura te permite ver datos de mapa o arreglo completa iterando sobre la lista enlazada.

MMDB_search_node_s

Esta estructura encapsula los dos registros en un nodo de búsqueda. Esto es realmente útil solo si quieres escribir código que itera por el árbol de búsqueda completo en lugar de buscar un IP específico.

typedef struct MMDB_search_node_s {
    uint64_t left_record;
    uint64_t right_record;
    uint8_t left_record_type;
    uint8_t right_record_type;
    MMDB_entry_s left_record_entry;
    MMDB_entry_s right_record_entry;
} MMDB_search_node_s;

Los dos tipos de registro tomarán uno de los siguientes valores:

  • MMDB_RECORD_TYPE_SEARCH_NODE - El registro apunta al siguiente nodo de búsqueda.
  • MMDB_RECORD_TYPE_EMPTY - El registro es un placeholder que indica que no hay datos para el IP. El búsqueda debe terminar aquí.
  • MMDB_RECORD_TYPE_DATA - El registro es para datos en la sección de datos de la base de datos. Usa la entrada del registro al buscar los datos del registro.
  • MMDB_RECORD_TYPE_INVALID - El registro es inválido. Esto puede ocurrir por un nodo inválido buscado o por una base de datos corrupta.

El MMDB_entry_s del registro es válido solo si el tipo es MMDB_RECORD_TYPE_DATA. Los intentos de usar un registro para otros tipos de registro generarán un error o datos inválidos.

STATUS CODES

Esta biblioteca devuelve (o popula) códigos de estado para muchas funciones. Estos códigos de estado son:

  • MMDB_SUCCESS - todo funcionó
  • MMDB_FILE_OPEN_ERROR - hubo un error al abrir el archivo MaxMind DB.
  • MMDB_IO_ERROR - una operación de I/O falló. Verifica errno para más detalles.
  • MMDB_CORRUPT_SEARCH_TREE_ERROR - al buscar un IP en el árbol de búsqueda se obtuvo un resultado imposible. La base de datos está dañada o fue generada incorrectamente o hay un error en el código de libmaxminddb.
  • MMDB_INVALID_METADATA_ERROR - algo en la base de datos está mal. Esto incluye claves de metadatos ausentes o valores imposibles (como ip_version = 7).
  • MMDB_UNKNOWN_DATABASE_FORMAT_ERROR - la metadata de la base de datos indica que su versión major es 2. Esta biblioteca solo puede manejar versiones major 2.
  • MMDB_OUT_OF_MEMORY_ERROR - falló una llamada a un algoritmo de asignación de memoria (malloc, etc.).
  • MMDB_INVALID_DATA_ERROR - un campo de datos en la sección de datos contiene datos inválidos. Por ejemplo, una uint16 campo afirma ser más de 2 bytes. La base de datos es probablemente dañada o fue generada incorrectamente.
  • MMDB_INVALID_LOOKUP_PATH_ERROR - el camino de búsqueda pasado a MMDB_get_value, MMDB_vget_value, o MMDB_aget_value contiene un desplazamiento de array mayor que LONG_MAX o menor que LONG_MIN.
  • MMDB_LOOKUP_PATH_DOES_NOT_MATCH_DATA_ERROR - el camino de búsqueda pasado a MMDB_get_value, MMDB_vget_value, o MMDB_aget_value no coincide con la estructura de datos para el registro. Pueden ocurrir varias razones. El camino de búsqueda puede incluir un clave no en un mapa. El camino de búsqueda puede incluir un índice de array mayor que un array o menor que el desplazamiento mínimo desde el final de un array. Puede ocurrir cuando el camino espera encontrar un mapa o array donde ninguno exista.

Todos los códigos de estado deben tratarse como valores int.

MMDB_strerror()

const char *MMDB_strerror(int error_code)

Esta función toma un código de estado y devuelve una cadena en inglés explicando el estado.

FUNCTIONS

Esta biblioteca proporciona las siguientes funciones exportadas:

MMDB_open()

int MMDB_open(
    const char *const filename,
    uint32_t flags,
    MMDB_s *const mmdb);

Esta función abre un handle a un archivo MaxMind DB. El valor de retorno es un código de estado como definido anteriormente. Siempre verifica el valor de retorno de esta llamada.

MMDB_s mmdb;
int status =
    MMDB_open("/path/to/file.mmdb", MMDB_MODE_MMAP, &mmdb);
if (MMDB_SUCCESS != status) { ... }
...
MMDB_close(&mmdb);

El filename debe codificarse como UTF-8 en Windows.

La estructura MMDB_s que pasas puede estar en la pila o alojada en la memoria heap. Sin embargo, si la apertura es exitosa, contendrá datos alojados en la memoria heap, por lo que necesitas cerrarla con MMDB_close(). Si el estado devuelto no es MMDB_SUCCESS, esta biblioteca asegura que todo el espacio de memoria asignado se libere antes de devolverlo.

Los flags actualmente proporcionados son:

•
MMDB_MODE_MMAP - abre el archivo con mmap().

Pasar otros valores para flags puede producir resultados inesperados. En el futuro, podríamos agregar más flags que puedas unir con el modo, así como más modos.

También puedes pasar 0 como valor para flags, en el cual el archivo se abrirá con los flags por defecto. Sin embargo, estos valores por defecto pueden cambiar en futuras versiones. El valor por defecto actual es MMDB_MODE_MMAP.

MMDB_close()

void MMDB_close(MMDB_s *const mmdb);

Esta libera cualquier memoria asignada o mmap'd que se encuentre en la estructura MMDB_s. No libera la memoria del todo.

MMDB_lookup_string()

MMDB_lookup_result_s MMDB_lookup_string(
    MMDB_s *const mmdb,
    const char *const ipstr,
    int *const gai_error,
    int *const mmdb_error);

تبحث هذه الدالة في عنوان IP يتم تمريره كسلسلة نصية منتهية بـ NULL. داخليًا، تستدعي getaddrinfo() لحل العنوان إلى شكله الثنائي. ثم تستدعي MMDB_lookup_sockaddr() للبحث عن العنوان في قاعدة البيانات. إذا كنت قد قمت بالفعل بحل عنوان، فيمكنك استدعاء MMDB_lookup_sockaddr() مباشرة دون حلها مرتين.

int gai_error, mmdb_error;
MMDB_lookup_result_s result =
    MMDB_lookup_string(&mmdb, "1.2.3.4", &gai_error, &mmdb_error);
if (0 != gai_error) { ... }
if (MMDB_SUCCESS != mmdb_error) { ... }
if (result.found_entry) { ... }

تعيد هذه الدالة دائمًا هيكل MMDB_lookup_result_s، ولكن يجب عليك أيضًا التحقق من معاملي gai_error و mmdb_error. إذا أشار أي منهما إلى خطأ، فسيكون الهيكل المعاد غير مفيد.

إذا لم تكن هناك أخطاء، فلا يزال يتعين عليك التأكد من أن العضو found_entry في الهيكل المعاد هو صحيح. إذا لم يكن كذلك، فهذا يعني أن عنوان IP ليس له سجل في قاعدة البيانات.

تعمل هذه الدالة مع عناوين IPv4 حتى عندما تحتوي قاعدة البيانات على بيانات لكل من IPv4 و IPv6. سيتم البحث عن عنوان IPv4 كـ ::xxx.xxx.xxx.xxx، وليس كـ ::ffff:xxx.xxx.xxx.xxx.

إذا قمت بتمرير عنوان IPv6 إلى قاعدة بيانات تحتوي فقط على بيانات IPv4، فسيكون العضو found_entry خاطئًا، ولكن حالة mmdb_error ستظل MMDB_SUCCESS.

MMDB_lookup_sockaddr()

MMDB_lookup_result_s MMDB_lookup_sockaddr(
    MMDB_s *const mmdb,
    const struct sockaddr *const sockaddr,
    int *const mmdb_error);

تبحث هذه الدالة في عنوان IP تم حله بالفعل باستخدام getaddrinfo().

بخلاف استدعاء getaddrinfo() بنفسها، فإن هذه الدالة مطابقة للدالة MMDB_lookup_string().

int mmdb_error;
MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
if (MMDB_SUCCESS != mmdb_error) { ... }
if (result.found_entry) { ... }

وظائف البحث عن البيانات

هناك ثلاث دوال للبحث عن البيانات المرتبطة بعنوان IP.

int MMDB_get_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    ...);
int MMDB_vget_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    va_list va_path);
int MMDB_aget_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    const char *const *const path);

تسمح الدوال الثلاث بثلاثة أساليب استدعاء مختلفة قليلاً، لكنها جميعًا تقوم بنفس الشيء.

المعلمة الأولى هي قيمة MMDB_entry_s. في معظم الحالات، ستأتي هذه من هيكل MMDB_lookup_result_s الذي أعادته MMDB_lookup_string() أو MMDB_lookup_sockaddr().

المعلمة الثانية هي مرجع لهيكل MMDB_entry_data_s. سيتم ملء هذا بالبيانات التي يتم البحث عنها، إذا تم العثور على أي بيانات. إذا لم يتم العثور على بيانات، فسيكون العضو has_data لهذا الهيكل خاطئًا. إذا كان has_data صحيحًا، يمكنك التحقق من العضو data_type.

المعلمة الأخيرة هي مسار بحث. يتكون المسار من مجموعة من السلاسل التي تمثل مفاتيح الخريطة (على سبيل المثال، "city") أو فهارس المصفوفة (على سبيل المثال، "0"، "1"، "-1") لاستخدامها في البحث.

تُعتبر فهارس المصفوفة السالبة كإزاحة من نهاية المصفوفة. على سبيل المثال، "-1" يشير إلى العنصر الأخير في المصفوفة.

يسمح مسار البحث بالتنقل في هيكل معقد. على سبيل المثال، نظرًا لهذه البيانات:

{
    "names": {
        "en": "Germany",
        "de": "Deutschland"
    },
    "cities": [ "Berlin", "Frankfurt" ]
}

يمكننا البحث عن الاسم باللغة الإنجليزية باستخدام هذا الرمز:

MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
MMDB_entry_data_s entry_data;
int status =
    MMDB_get_value(&result.entry, &entry_data,
                   "names", "en", NULL);
if (MMDB_SUCCESS != status) { ... }
if (entry_data.has_data) { ... }

إذا أردنا العثور على المدينة الأولى، فسيكون مسار البحث هو "cities"، "0". إذا لم تقم بتوفير مسار بحث، فستحصل على السجل الذي يتوافق مع الخريطة ذات المستوى الأعلى. يجب أن ينتهي مسار البحث دائمًا بـ "NULL"، بغض النظر عن الدالة التي تستخدمها.

تقبل الدالة MMDB_get_value عددًا متغيرًا من المعاملات. جميع المعاملات بعد المؤشر إلى هيكل MMDB_entry_data_s هي مسار البحث. يجب أن يكون المعامل الأخير "NULL".

تقبل الدالة MMDB_vget_value قائمة `va_list` كمسار بحث. يجب أن يكون العنصر الأخير الذي تم استرداده بواسطة `va_arg()` هو "NULL".

أخيرًا، تقبل الدالة MMDB_aget_value مصفوفة من السلاسل النصية كمسار بحث. يجب أن يكون العنصر الأخير في هذه المصفوفة "NULL".

إذا كنت تريد الحصول على جميع بيانات الإدخال مرة واحدة، يمكنك استدعاء MMDB_get_entry_data_list().

لكل دالة من الدوال الثلاث، القيمة المعادة هي رمز حالة كما هو محدد أعلاه.

MMDB_get_entry_data_list()

int MMDB_get_entry_data_list(
    MMDB_entry_s *start,
    MMDB_entry_data_list_s **const entry_data_list);

تتيح لك هذه الدالة الحصول على جميع البيانات من هيكل معقد مرة واحدة، بدلاً من البحث عن كل جزء عبر استدعاءات متكررة لـ MMDB_get_value().

MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
MMDB_entry_data_list_s *entry_data_list, *first;
int status =
    MMDB_get_entry_data_list(&result.entry, &entry_data_list);
if (MMDB_SUCCESS != status) { ... }
// احتفظ بهذا الهيكل لتحريره لاحقًا
first = entry_data_list;
while (1) {
    MMDB_entry_data_list_s *next = entry_data_list = entry_data_list->next;
    if (NULL == next) {
        break;
    }
    switch (next->entry_data.type) {
        case MMDB_DATA_TYPE_MAP: { ... }
        case MMDB_DATA_TYPE_UTF8_STRING: { ... }
        ...
    }
}
MMDB_free_entry_data_list(first);

تقع على عاتقك مسؤولية تفسير هيكل entry_data_list. القائمة مرتبطة في مسح عميق. سنستخدم هذا الهيكل كمثال:

{
    "names": {
        "en": "Germany",
        "de": "Deutschland"
    },
    "cities": [ "Berlin", "Frankfurt" ]
}

ستحتوي القائمة على العناصر التالية:

1.
MAP - خريطة المستوى الأعلى
2.
UTF8_STRING - المفتاح "names"
3.
MAP - خريطة للمفتاح "names"
4.
UTF8_STRING - المفتاح "en"
5.
UTF8_STRING - القيمة للمفتاح "en"
6.
UTF8_STRING - المفتاح "de"
7.
UTF8_STRING - القيمة للمفتاح "de"
8.
UTF8_STRING - المفتاح "cities"
9.
ARRAY - القيمة للمفتاح "cities"
10.
UTF8_STRING - array[0]
11.
UTF8_STRING - array[1]

القيمة المعادة هي رمز حالة كما هو محدد أعلاه.

القيمة المعادة هي رمز حالة كما هو محدد أعلاه.

MMDB_dump_entry_data_list()

int MMDB_dump_entry_data_list(
    FILE *const stream,
    MMDB_entry_data_list_s *const entry_data_list,
    int indent);

تأخذ هذه الدالة قائمة مرتبطة من هياكل MMDB_entry_data_list_s وتُسلسلها إلى الملف stream. المعلمة indent هي مستوى الإزاحة الأولي للإخراج الذي تم إنشاؤه. يتم زيادتها للهياكل المتداخلة (الخرائط، المصفوفات، إلخ).

يجب أن يكون stream ملفًا (على سبيل المثال، stdout). إذا كانت منصتك توفر شيئًا مثل `open_memstream()` من GNU، فيمكنك استخدامه لالتقاط الإخراج كسلسلة.

الإخراج مُنسق بطريقة مشابهة لـ JSON، ولكن القيم مميزة بنوع بياناتها (باستثناء الخرائط والمصفوفات التي يتم عرضها كـ "{}" و "[]").

قد يتغير التنسيق المحدد للإخراج في الإصدارات المستقبلية.
