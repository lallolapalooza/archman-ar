MMDB_dump_entry_data_list(3)

الحزمة: libmaxminddb

التراخيص: Apache-2.0

type يتم استخدام العضو pointer الخاص بالاتحاد أبدًا في أي بيانات يتم إرجاعها بواسطة واجهة برمجة التطبيقات. يجب دائمًا حل المؤشرات داخليًا.

العضو data_size يكون ذا صلة فقط للبيانات من النوع utf8_string و bytes. لا يتم إنهاء utf8_string بسلسلة فارغة ويجب استخدام data_size لتحديد طوله.

يمكن مقارنة العضو type بأحد وحدات الماكرو MMDB_DATA_TYPE_*.

أعداد صحيحة 128 بت

تعتمد معالجة بيانات uint128 على كيفية دعم منصتك لأعداد صحيحة 128 بت، إن كانت تدعمها على الإطلاق. مع GCC 4.4 و 4.5 يمكننا كتابة unsigned int __attribute__ ((__mode__ (TI))). مع الإصدارات الأحدث من GCC (4.6+) و clang (3.2+) يمكننا ببساطة كتابة "unsigned __int128".

لتجاوز هذه الاختلافات، تحدد هذه المكتبة نوعًا يسمى mmdb_uint128_t. يتم تعريف هذا النوع في ملف الرأس maxminddb.h بحيث يمكنك استخدامه في الكود الخاص بك.

مع المترجمات الأقدم، لا يمكننا استخدام عدد صحيح، لذا نستخدم بدلاً من ذلك مصفوفة 16 بايت من قيم uint8_t. هذه هي البيانات الخام من قاعدة البيانات.

توفر هذه المكتبة ماكرو عامًا هو MMDB_UINT128_IS_BYTE_ARRAY. إذا كان هذا صحيحًا (1)، فسيتم إرجاع قيم uint128 كمصفوفة بايت، وإذا كان خاطئًا، فسيتم إرجاعها كعدد صحيح mmdb_uint128_t.

وحدات ماكرو لأنواع البيانات

توفر هذه المكتبة ماكرو لكل نوع بيانات تم تحديده بواسطة مواصفات MaxMind DB.

  • MMDB_DATA_TYPE_UTF8_STRING
  • MMDB_DATA_TYPE_DOUBLE
  • MMDB_DATA_TYPE_BYTES
  • MMDB_DATA_TYPE_UINT16
  • MMDB_DATA_TYPE_UINT32
  • MMDB_DATA_TYPE_MAP
  • MMDB_DATA_TYPE_INT32
  • MMDB_DATA_TYPE_UINT64
  • MMDB_DATA_TYPE_UINT128
  • MMDB_DATA_TYPE_ARRAY
  • MMDB_DATA_TYPE_BOOLEAN
  • MMDB_DATA_TYPE_FLOAT

هناك أيضًا بعض الأنواع المخصصة للاستخدام الداخلي فقط:

  • MMDB_DATA_TYPE_EXTENDED
  • MMDB_DATA_TYPE_POINTER
  • MMDB_DATA_TYPE_CONTAINER
  • MMDB_DATA_TYPE_END_MARKER

إذا رأيت أحد هذه الأنواع في البيانات المرجعة، فهذا يعني أن شيئًا ما قد حدث بشكل خاطئ. قاعدة البيانات تالفة أو تم إنشاؤها بشكل غير صحيح أو يوجد خطأ في كود libmaxminddb.

قيم المؤشرات و MMDB_close()

تعتبر الأعضاء utf8_string و bytes و (ربما) uint128 في هذا الهيكل مؤشرات مباشرة إلى قسم بيانات قاعدة البيانات. يمكن أن يكون هذا كتلة ذاكرة تم تخصيصها باستخدام calloc أو mmap. في كلتا الحالتين، ستصبح هذه المؤشرات غير صالحة بعد استدعاء MMDB_close().

إذا كنت بحاجة إلى الإشارة إلى هذه البيانات بعد ذلك الوقت، فيجب عليك نسخ البيانات باستخدام دالة مناسبة (strdup، memcpy، إلخ).

MMDB_entry_data_list_s

يغلف هذا الهيكل قائمة مرتبطة من هياكل MMDB_entry_data_s.

typedef struct MMDB_entry_data_list_s {
    MMDB_entry_data_s entry_data;
    struct MMDB_entry_data_list_s *next;
} MMDB_entry_data_list_s;

يتيح لك هذا الهيكل النظر إلى بيانات الخريطة أو المصفوفة بأكملها عن طريق التكرار فوق القائمة المرتبطة.

MMDB_search_node_s

يغلف هذا الهيكل السجلين في عقدة بحث. هذا مفيد حقًا فقط إذا كنت ترغب في كتابة كود يتكرر فوق شجرة البحث بأكملها بدلاً من البحث عن عنوان IP محدد.

typedef struct MMDB_search_node_s {
    uint64_t left_record;
    uint64_t right_record;
    uint8_t left_record_type;
    uint8_t right_record_type;
    MMDB_entry_s left_record_entry;
    MMDB_entry_s right_record_entry;
} MMDB_search_node_s;

ستأخذ أنواع السجلات هذه أحد القيم التالية:

  • MMDB_RECORD_TYPE_SEARCH_NODE - يشير السجل إلى عقدة البحث التالية.
  • MMDB_RECORD_TYPE_EMPTY - السجل هو عنصر نائب يشير إلى عدم وجود بيانات لعنوان IP. يجب أن ينتهي البحث هنا.
  • MMDB_RECORD_TYPE_DATA - السجل مخصص للبيانات في قسم البيانات من قاعدة البيانات. استخدم الإدخال للسجل عند البحث عن البيانات للسجل.
  • MMDB_RECORD_TYPE_INVALID - السجل غير صالح. إما تم البحث عن عقدة غير صالحة أو أن قاعدة البيانات تالفة.

يكون MMDB_entry_s للسجل صالحًا فقط إذا كان النوع هو MMDB_RECORD_TYPE_DATA. ستؤدي محاولات استخدام إدخال لأنواع سجلات أخرى إلى حدوث خطأ أو بيانات غير صالحة.

رموز الحالة

تُرجع هذه المكتبة (أو تملأ) رموز حالة للعديد من الدوال. رموز الحالة هذه هي:

  • MMDB_SUCCESS - نجاح كل شيء
  • MMDB_FILE_OPEN_ERROR - كان هناك خطأ أثناء محاولة فتح ملف MaxMind DB.
  • MMDB_IO_ERROR - فشلت عملية إدخال/إخراج. تحقق من errno لمزيد من التفاصيل.
  • MMDB_CORRUPT_SEARCH_TREE_ERROR - أعطانا البحث عن عنوان IP في شجرة البحث نتيجة مستحيلة. قاعدة البيانات تالفة أو تم إنشاؤها بشكل غير صحيح أو يوجد خطأ في كود libmaxminddb.
  • MMDB_INVALID_METADATA_ERROR - هناك خطأ في شيء ما في قاعدة البيانات. وهذا يشمل مفاتيح البيانات الوصفية المفقودة بالإضافة إلى القيم المستحيلة (مثل ip_version بقيمة 7).
  • MMDB_UNKNOWN_DATABASE_FORMAT_ERROR - تشير البيانات الوصفية لقاعدة البيانات إلى أن إصدارها الرئيسي ليس 2. يمكن لهذه المكتبة فقط التعامل مع الإصدار الرئيسي 2.
  • MMDB_OUT_OF_MEMORY_ERROR - فشل استدعاء تخصيص الذاكرة (malloc، إلخ).
  • MMDB_INVALID_DATA_ERROR - يحتوي إدخال في قسم البيانات على بيانات غير صالحة. على سبيل المثال، يدعي حقل uint16 أنه أطول من بايتين. قاعدة البيانات ربما تكون تالفة أو تم إنشاؤها بشكل غير صحيح.
  • MMDB_INVALID_LOOKUP_PATH_ERROR - يحتوي المسار البحثي المقدم إلى MMDB_get_value أو MMDB_vget_value أو MMDB_aget_value على إزاحة مصفوفة أكبر من LONGMAX أو أصغر من LONGMIN.
  • MMDB_LOOKUP_PATH_DOES_NOT_MATCH_DATA_ERROR - لا يتطابق المسار البحثي المقدم إلى MMDB_get_value أو MMDB_vget_value أو MMDB_aget_value مع بنية البيانات للإدخال. هناك عدد من الأسباب التي يمكن أن تحدث بها هذه المشكلة. يمكن أن يتضمن مسار البحث مفتاحًا غير موجود في الخريطة. يمكن أن يتضمن مسار البحث فهرس مصفوفة أكبر من مصفوفة أو أصغر من الحد الأدنى للإزاحة من نهاية المصفوفة. يمكن أن يحدث هذا أيضًا عندما يتوقع المسار العثور على خريطة أو مصفوفة حيث لا توجد.

يجب التعامل مع جميع رموز الحالة كقيم int.

MMDB_strerror()

const char *MMDB_strerror(int error_code)

تأخذ هذه الدالة رمز حالة وتعيد سلسلة نصية باللغة الإنجليزية توضح الحالة.

الدوال

توفر هذه المكتبة الدوال المصدرة التالية:

MMDB_open()

int MMDB_open(
    const char *const filename,
    uint32_t flags,
    MMDB_s *const mmdb);

تفتح هذه الدالة مقبضًا لملف MaxMind DB. قيمة الإرجاع هي رمز حالة كما هو محدد أعلاه. تحقق دائمًا من قيمة إرجاع هذا الاستدعاء.

MMDB_s mmdb;
int status =
    MMDB_open("/path/to/file.mmdb", MMDB_MODE_MMAP, &mmdb);
if (MMDB_SUCCESS != status) { ... }
...
MMDB_close(&mmdb);

يجب ترميز filename كـ UTF-8 على نظام Windows.

يمكن أن يكون الهيكل MMDB_s الذي تمرره على المكدس أو تم تخصيصه من الكومة. ومع ذلك، إذا كان الفتح ناجحًا، فسوف يحتوي على بيانات مخصصة من الكومة، لذا تحتاج إلى إغلاقه باستخدام MMDB_close(). إذا لم تكن الحالة المرجعة MMDB_SUCCESS، فإن هذه المكتبة تتأكد من تحرير جميع الذاكرة المخصصة قبل العودة.

العلامات المتوفرة حاليًا هي:

•
MMDB_MODE_MMAP - افتح قاعدة البيانات باستخدام mmap().

قد يؤدي تمرير قيم أخرى لـ flags إلى نتائج غير متوقعة. في المستقبل، قد نضيف علامات إضافية يمكنك دمجها مع الوضع باستخدام عملية OR الثنائية، بالإضافة إلى أوضاع إضافية.

يمكنك أيضًا تمرير 0 كقيمة لـ flags، وفي هذه الحالة سيتم فتح قاعدة البيانات بالعلامات الافتراضية. ومع ذلك، قد تتغير هذه الافتراضيات في الإصدارات المستقبلية. الافتراضي الحالي هو MMDB_MODE_MMAP.

MMDB_close()

void MMDB_close(MMDB_s *const mmdb);

يقوم هذا بتحرير أي ذاكرة مخصصة أو تم تعيينها بواسطة mmap يتم الاحتفاظ بها من الهيكل MMDB_s. * لا يحرر الذاكرة

y مخصصة للبنية نفسها! إذا خصصت البنية من الكومة، فأنت مسؤول عن تحريرها.

MMDB_lookup_string()

MMDB_lookup_result_s MMDB_lookup_string(
    MMDB_s *const mmdb,
    const char *const ipstr,
    int *const gai_error,
    int *const mmdb_error);

تقوم هذه الدالة بالبحث عن عنوان IP يتم تمريره كسلسلة نصية تنتهي بـ null. داخليًا، تستدعي getaddrinfo() لحل العنوان إلى شكل ثنائي. ثم تستدعي MMDB_lookup_sockaddr() للبحث عن العنوان في قاعدة البيانات. إذا قمت بالفعل بحل عنوان، يمكنك استدعاء MMDB_lookup_sockaddr() مباشرة، بدلاً من حل العنوان مرتين.

int gai_error, mmdb_error;
MMDB_lookup_result_s result =
    MMDB_lookup_string(&mmdb, "1.2.3.4", &gai_error, &mmdb_error);
if (0 != gai_error) { ... }
if (MMDB_SUCCESS != mmdb_error) { ... }
if (result.found_entry) { ... }

ترجع هذه الدالة دائمًا بنية MMDB_lookup_result_s، ولكن يجب عليك أيضًا التحقق من معاملي gai_error و mmdb_error. إذا أشار أي منهما إلى خطأ، فإن البنية المعادة تكون بلا معنى.

إذا لم يحدث خطأ، فلا يزال يتعين عليك التأكد من أن العضو found_entry في النتيجة المعادة هو صحيح (true). إذا لم يكن كذلك، فهذا يعني أن عنوان IP ليس له إدخال في قاعدة البيانات.

ستعمل هذه الدالة مع عناوين IPv4 حتى عندما تحتوي قاعدة البيانات على بيانات لكل من عناوين IPv4 و IPv6. سيتم البحث عن عنوان IPv4 كـ '::xxx.xxx.xxx.xxx' بدلاً من إعادة تعيينه إلى كتلة ::ffff:xxx.xxx.xxx.xxx المخصصة لعناوين IPv6 المعينة لـ IPv4.

إذا قمت بتمرير عنوان IPv6 إلى قاعدة بيانات تحتوي فقط على بيانات IPv4، فسيكون العضو found_entry خطأ (false)، ولكن سيظل حالة mmdb_error هي MMDB_SUCCESS.

MMDB_lookup_sockaddr()

MMDB_lookup_result_s MMDB_lookup_sockaddr(
    MMDB_s *const mmdb,
    const struct sockaddr *const sockaddr,
    int *const mmdb_error);

تبحث هذه الدالة عن عنوان IP تم حله بالفعل بواسطة getaddrinfo().

بخلاف عدم استدعاء getaddrinfo() بنفسها، هذه الدالة مطابقة لدالة MMDB_lookup_string().

int mmdb_error;
MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
if (MMDB_SUCCESS != mmdb_error) { ... }
if (result.found_entry) { ... }

وظائف البحث عن البيانات

هناك ثلاث وظائف للبحث عن البيانات المرتبطة بعنوان IP.

int MMDB_get_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    ...);
int MMDB_vget_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    va_list va_path);
int MMDB_aget_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    const char *const *const path);

تسمح الوظائف الثلاث بثلاثة أنماط استدعاء مختلفة قليلاً، لكنها جميعًا تفعل الشيء نفسه.

المعلمة الأولى هي قيمة MMDB_entry_s. في معظم الحالات، ستأتي من قيمة MMDB_lookup_result_s التي تم إرجاعها بواسطة MMDB_lookup_string() أو MMDB_lookup_sockaddr().

المعلمة الثانية هي مرجع لبنية MMDB_entry_data_s. سيتم ملؤها بالبيانات التي يتم البحث عنها، إذا تم العثور على أي شيء. إذا لم يتم العثور على شيء، فسيكون العضو has_data لهذه البنية خطأ (false). إذا كان has_data صحيحًا (true)، فيمكنك النظر إلى العضو data_type.

المعلمة الأخيرة هي مسار البحث. يتكون المسار من مجموعة من السلاسل النصية التي تمثل إما مفاتيح الخريطة (مثل، "city") أو فهارس المصفوفة (مثل، "0"، "1"، "-1") لاستخدامها في البحث.

سيتم التعامل مع فهارس المصفوفة السالبة كإزاحة من نهاية المصفوفة. على سبيل المثال، تشير "-1" إلى العنصر الأخير في المصفوفة.

يسمح لك مسار البحث بالتنقل في بنية بيانات معقدة. على سبيل المثال، بالنظر إلى هذه البيانات:

{
    "names": {
        "en": "Germany",
        "de": "Deutschland"
    },
    "cities": [ "Berlin", "Frankfurt" ]
}

يمكننا البحث عن الاسم الإنجليزي بهذا الكود:

MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
MMDB_entry_data_s entry_data;
int status =
    MMDB_get_value(&result.entry, &entry_data,
                   "names", "en", NULL);
if (MMDB_SUCCESS != status) { ... }
if (entry_data.has_data) { ... }

إذا أردنا العثور على المدينة الأولى، سيكون مسار البحث "cities", "0". إذا لم تقدم مسار بحث على الإطلاق، فستحصل على الإدخال الذي يتوافق مع الخريطة ذات المستوى الأعلى. يجب أن ينتهي مسار البحث دائمًا بـ NULL، بغض النظر عن الدالة التي تستدعيها.

تأخذ الدالة MMDB_get_value عددًا متغيرًا من المعلمات. جميع المعلمات بعد مؤشر بنية MMDB_entry_data_s * هي مسار البحث. يجب أن تكون المعلمة الأخيرة NULL.

تقبل الدالة MMDB_vget_value قائمة va_list كمسار بحث. يجب أن تكون العنصر الأخير المسترد بواسطة va_arg() هو NULL.

أخيرًا، تقبل الدالة MMDB_aget_value مصفوفة من السلاسل النصية كمسار بحث. يجب أن يكون العضو الأخير في هذه المصفوفة NULL.

إذا كنت ترغب في الحصول على جميع بيانات الإدخال مرة واحدة، يمكنك استدعاء MMDB_get_entry_data_list() بدلاً من ذلك.

لكل من الدوال الثلاث، القيمة المرجعة هي رمز حالة كما هو محدد أعلاه.

MMDB_get_entry_data_list()

int MMDB_get_entry_data_list(
    MMDB_entry_s *start,
    MMDB_entry_data_list_s **const entry_data_list);

تسمح لك هذه الدالة بالحصول على جميع البيانات لبنية بيانات معقدة مرة واحدة، بدلاً من البحث عن كل جزء باستخدام استدعاءات متكررة لـ MMDB_get_value().

MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
MMDB_entry_data_list_s *entry_data_list, *first;
int status =
    MMDB_get_entry_data_list(&result.entry, &entry_data_list);
if (MMDB_SUCCESS != status) { ... }
// حفظ هذا حتى نتمكن من تحرير هذه البيانات لاحقًا
first = entry_data_list;
while (1) {
    MMDB_entry_data_list_s *next = entry_data_list = entry_data_list->next;
    if (NULL == next) {
        break;
    }
    switch (next->entry_data.type) {
        case MMDB_DATA_TYPE_MAP: { ... }
        case MMDB_DATA_TYPE_UTF8_STRING: { ... }
        ...
    }
}
MMDB_free_entry_data_list(first);

يعود الأمر لك لتفسير بنية بيانات entry_data_list. يتم ربط القائمة في مسح عميق أولاً. دعنا نستخدم هذه البنية كمثال:

{
    "names": {
        "en": "Germany",
        "de": "Deutschland"
    },
    "cities": [ "Berlin", "Frankfurt" ]
}

ستتكون القائمة من العناصر التالية:

1.
MAP - الخريطة ذات المستوى الأعلى
2.
UTF8_STRING - المفتاح "names"
3.
MAP - الخريطة للمفتاح "names"
4.
UTF8_STRING - المفتاح "en"
5.
UTF8_STRING - القيمة للمفتاح "en"
6.
UTF8_STRING - المفتاح "de"
7.
UTF8_STRING - القيمة للمفتاح "de"
8.
UTF8_STRING - المفتاح "cities"
9.
ARRAY - القيمة للمفتاح "cities"
10.
UTF8_STRING - array[0]
11.
UTF8_STRING - array[1]

القيمة المرجعة للدالة هي رمز حالة كما هو محدد أعلاه.

MMDB_get_metadata_as_entry_data_list()

    MMDB_s *const mmdb,
    MMDB_entry_data_list_s **const entry_data_list);

تسمح لك هذه الدالة باسترداد بيانات التعريف الخاصة بقاعدة البيانات كقائمة مرتبطة من هياكل MMDB_entry_data_list_s. يمكن أن يكون هذا طريقة أكثر ملاءمة للتعامل مع بيانات التعريف بدلاً من استخدام بنية بيانات التعريف مباشرة.

    MMDB_entry_data_list_s *entry_data_list, *first;
    int status =
        MMDB_get_metadata_as_entry_data_list(&mmdb, &entry_data_list);
    if (MMDB_SUCCESS != status) { ... }
    first = entry_data_list;
    ... // افعل شيئًا بالبيانات
    MMDB_free_entry_data_list(first);

القيمة المرجعة للدالة هي رمز حالة كما هو محدد أعلاه.

MMDB_dump_entry_data_list()

int MMDB_dump_entry_data_list(
    FILE *const stream,
    MMDB_entry_data_list_s *const entry_data_list,
    int indent);

تأخذ هذه الدالة قائمة مرتبطة من هياكل MMDB_entry_data_list_s وتحولها إلى سلسلة نصية إلى stream المحدد. المعلمة indent هي مستوى المسافة البادئة الأولي للإخراج المولد. يتم زيادتها لهياكل البيانات المتداخلة (الخرائط، المصفوفات، إلخ).

يجب أن يكون stream مقبض ملف (stdout، إلخ). إذا كانت منصتك توفر شيئًا مثل GNU open_memstream()، فيمكنك استخدامه لالتقاط الإخراج كسلسلة نصية.

يتم تنسيق الإخراج بطريقة تشبه JSON، ولكن يتم تمييز القيم بأنواع بياناتها (باستثناء الخرائط والمصفوفات التي تظهر مع ""{}"" و ""[]"" على التوالي).
