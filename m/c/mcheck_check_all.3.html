mcheck(3) دليل دوال المكتبة mcheck(3)

الاسم

mcheck, mcheck_check_all, mcheck_pedantic, mprobe - فحص اتساق الكومة

المكتبة

مكتبة C القياسية (libc, -lc)

الملخص

#include <mcheck.h>
int mcheck(typeof(void (enum mcheck_status mstatus)) *f);
int mcheck_pedantic(
           typeof(void (enum mcheck_status mstatus)) *f);
void mcheck_check_all(void);
enum mcheck_status mprobe(void *ptr);

الوصف

تقوم الدالة mcheck() بتثبيت مجموعة من خطافات التصحيح لعائلة دوال تخصيص الذاكرة malloc(3). تتسبب هذه الخطافات في إجراء فحوصات اتساق معينة على حالة الكومة. يمكن لهذه الفحوصات اكتشاف أخطاء التطبيق مثل تحرير كتلة ذاكرة أكثر من مرة أو إتلاف هياكل بيانات مسك الدفاتر التي تسبق مباشرة كتلة الذاكرة المخصصة.

لتكون فعالة، يجب استدعاء الدالة mcheck() قبل أول استدعاء لـ malloc(3) أو دالة ذات صلة. في الحالات التي يصعب فيها ضمان ذلك، يؤدي ربط البرنامج بـ -lmcheck إلى إدراج استدعاء ضمني لـ mcheck() (مع وسيط NULL) قبل أول استدعاء لدالة تخصيص الذاكرة.

الدالة mcheck_pedantic() مشابهة لـ mcheck()، ولكنها تجري فحوصات على جميع الكتل المخصصة كلما تم استدعاء إحدى دوال تخصيص الذاكرة. يمكن أن يكون هذا بطيئًا جدًا!

تتسبب الدالة mcheck_check_all() في إجراء فحص فوري لجميع الكتل المخصصة. يكون هذا الاستدعاء فعالاً فقط إذا تم استدعاء mcheck() مسبقًا.

إذا اكتشف النظام عدم اتساق في الكومة، يتم استدعاء الدالة التي يوفرها المتصل والتي يشير إليها f بوسيط واحد، mstatus، والذي يشير إلى نوع عدم الاتساق الذي تم اكتشافه. إذا كان f هو NULL، فإن دالة افتراضية تطبع رسالة خطأ على stderr وتستدعي abort(3).

تقوم الدالة mprobe() بإجراء فحص اتساق لكتلة الذاكرة المخصصة المشار إليها بواسطة ptr. يجب استدعاء الدالة mcheck() مسبقًا (وإلا فإن mprobe() ترجع MCHECK_DISABLED).

يصف القائمة التالية القيم التي تم إرجاعها بواسطة mprobe() أو تمريرها كوسيط mstatus عند استدعاء f:

MCHECK_DISABLED (mprobe() فقط)
لم يتم استدعاء mcheck() قبل استدعاء أول دالة تخصيص ذاكرة. لا يمكن فحص الاتساق.
MCHECK_OK (mprobe() فقط)
لم يتم اكتشاف عدم اتساق.
MCHECK_HEAD
تم تخريب الذاكرة التي تسبق كتلة مخصصة.
MCHECK_TAIL
تم تخريب الذاكرة التي تتبع كتلة مخصصة.
MCHECK_FREE
تم تحرير كتلة ذاكرة مرتين.

قيمة الإرجاع

ترجع mcheck() و mcheck_pedantic() القيمة 0 عند النجاح، أو -1 عند حدوث خطأ.

السمات

ملاحظات

يؤدي ربط البرنامج بـ -lmcheck واستخدام متغير البيئة MALLOC_CHECK_ (الموصوف في mallopt(3)) إلى اكتشاف نفس أنواع الأخطاء. ولكن، استخدام MALLOC_CHECK_ لا يتطلب إعادة ربط التطبيق.

أمثلة

يقوم البرنامج أدناه باستدعاء mcheck() بوسيط NULL ثم يحرر نفس كتلة الذاكرة مرتين. توضح جلسة shell التالية ما يحدث عند تشغيل البرنامج:


$ ./a.out
About to free
About to free a second time
block freed twice
Aborted (core dumped)

مصدر البرنامج

#include <mcheck.h>
#include <stdio.h>
#include <stdlib.h>
int
main(void)
{
    char *p;
    if (mcheck(NULL) != 0) {
        fprintf(stderr, "mcheck() failed\n");
        exit(EXIT_FAILURE);
    }
    p = malloc(1000);
    fprintf(stderr, "About to free\n");
    free(p);
    fprintf(stderr, "\nAbout to free a second time\n");
    free(p);
    exit(EXIT_SUCCESS);
}
