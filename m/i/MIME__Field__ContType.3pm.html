MIME__Field__ContType(3pm)

الحزمة: perl-mime-tools

التراخيص: GPL, PerlArtistic

MIME::Field::ContType(3) توثيق Perl المساهم به من المستخدم MIME::Field::ContType(3)

الاسم

MIME::Field::ContType - حقل "Content-type"

الوصف

فئة فرعية من Mail::Field.

لا تستخدم هذه الفئة مباشرة... قد يتغير اسمها في المستقبل! بدلاً من ذلك، اطلب من Mail::Field إنشاء مثيلات جديدة بناءً على اسم الحقل!

الملخص

use Mail::Field;
use MIME::Head;
# إنشاء مثيل من بعض النصوص:
$field = Mail::Field->new('Content-type',
                          'text/HTML; charset="US-ASCII"');
# الحصول على نوع MIME، مثل 'text/plain' أو 'x-foobar'.
# يعيد 'text/plain' كافتراضي، حسب RFC 2045:
my ($type, $subtype) = split('/', $field->type);
# الحصول على معلومات عامة:
print $field->name;
# الحصول على معلومات متعلقة بنوع "message":
if ($type eq 'message') {
    print $field->id;
    print $field->number;
    print $field->total;
}
# الحصول على معلومات متعلقة بنوع "multipart":
if ($type eq 'multipart') {
    print $field->boundary;            # القيمة الأساسية، تم إصلاحها
    print $field->multipart_boundary;  # فارغ إذا لم تكن رسالة متعددة الأجزاء!
}
# الحصول على معلومات متعلقة بنوع "text":
if ($type eq 'text') {
    print $field->charset;      # يعيد 'us-ascii' كافتراضي

الواجهة العامة

boundary
يعيد حقل الفاصل. يتم إرجاع الفاصل بالضبط كما هو وارد في حقل "Content-type:"؛ أي أنه لا يتم إضافة الشرطتين المزدوجتين ("--") في البداية.

(حسناً، تقريباً بالضبط... من RFC 2046:

(إذا بدا أن فاصلًا ينتهي بمسافة بيضاء، فيجب افتراض أن المسافة البيضاء
قد تمت إضافتها بواسطة بوابة، ويجب حذفها.)

لذلك نلتزم ونزيل أي مسافات زائدة.)

يعيد سلسلة فارغة إذا لم يكن هناك فاصل، أو إذا كان الفاصل غير قانوني (على سبيل المثال، إذا كان فارغًا بعد إزالة جميع المسافات البيضاء الزائدة).

multipart_boundary
مثل boundary()، باستثناء أن هذا سيعيد أيضًا سلسلة فارغة إذا لم تكن الرسالة متعددة الأجزاء. بعبارة أخرى، هناك فحص تلقائي للتأكد من السلامة.
type
حاول جاهدًا تحديد نوع المحتوى (على سبيل المثال، "text/plain"، "image/gif"، "x-weird-type"، والذي يتم إرجاعه بأحرف صغيرة.

شيء رائع: الكود التالي سيعمل تمامًا كما تريد، حتى لو لم يكن هناك نوع فرعي (كما في "x-weird-type")... في مثل هذه الحالة، سيكون $subtype ببساطة سلسلة فارغة:

($type, $subtype) = split('/', $head->mime_type);

إذا كانت معلومات نوع المحتوى مفقودة، فإنها تفترض افتراضيًا "text/plain"، حسب RFC 2045:

رسائل RFC 2822 الافتراضية يتم تصنيفها بواسطة هذا البروتوكول كنص عادي في
مجموعة أحرف US-ASCII، والتي يمكن تحديدها صراحةً باسم
"Content-type: text/plain; charset=us-ascii". إذا لم يتم تحديد Content-Type،
يتم افتراض هذا الافتراضي.

ملاحظة: بموجب مبدأ "كن ليبراليًا فيما تقبله"، هذه الروتين لم يعد يتحقق من صحة بناء جملة نوع المحتوى. إذا لم يكن فارغًا، فقط قم بتحويله إلى أحرف صغيرة وإعادته.

ملاحظات

نظرًا لأن جميع المعلمات تقريبًا (إن لم تكن كلها) يجب أن تكون لها قيم غير فارغة لاعتبارها صالحة، فإننا نعيد ببساطة السلسلة الفارغة للإشارة إلى الحقول المفقودة. إذا كنت بحاجة إلى الحصول على القيمة الأساسية الحقيقية، فاستخدم طريقة param() الموروثة (التي تعيد undef إذا كان المعلم مفقودًا).
