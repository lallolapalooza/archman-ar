الحزمة: perl-mime-lite

التراخيص: GPL, PerlArtistic

MIME::Lite(3) توثيق الحزم المساهمة في Perl MIME::Lite(3)

الاسم

MIME::Lite - مولد رسائل MIME منخفض السعرات الحرارية

انتظر!

لا يوصي بها صاحبها الحالي. هناك بدائل متعددة، مثل Email::MIME أو MIME::Entity و Email::Sender، التي يجب استخدامها بدلاً منها. تستمر MIME::Lite في تلقي تقارير أخطاء غريبة ولا تخضع لعدد كبير من عمليات إعادة الهيكلة نظرًا لتوفر بدائل أفضل. فكر في استخدام خيار آخر.

الملخص

قم بإنشاء وإرسال رسالة باستخدام طريقة الإرسال الافتراضية لنظام التشغيل الخاص بك، رسالة ذات جزء واحد:

use MIME::Lite;
### إنشاء رسالة ذات جزء واحد جديدة، لإرسال ملف GIF:
$msg = MIME::Lite->new(
    From     => 'me@myhost.com',
    To       => 'you@yourhost.com',
    Cc       => 'some@other.com, some@more.com',
    Subject  => 'Helloooooo, nurse!',
    Type     => 'image/gif',
    Encoding => 'base64',
    Path     => 'hellonurse.gif'
);
$msg->send; # إرسال افتراضي

قم بإنشاء رسالة متعددة الأجزاء (أي، مع مرفقات) وأرسلها عبر SMTP:

### إنشاء رسالة متعددة الأجزاء جديدة:
$msg = MIME::Lite->new(
    From    => 'me@myhost.com',
    To      => 'you@yourhost.com',
    Cc      => 'some@other.com, some@more.com',
    Subject => 'A message with 2 parts...',
    Type    => 'multipart/mixed'
);
### إضافة أجزاء (كل "مرفق" له نفس وسائط "new"):
$msg->attach(
    Type     => 'TEXT',
    Data     => 'Here\'s the GIF file you wanted'
);
$msg->attach(
    Type     => 'image/gif',
    Path     => 'aaa000123.gif',
    Filename => 'logo.gif',
    Disposition => 'attachment'
);
### استخدام Net::SMTP للإرسال
$msg->send('smtp','some.host', Debug=>1 );

طباعة رسالة:

### التنسيق كسلسلة نصية:
$str = $msg->as_string;
### الطباعة في ملف إخراج (على سبيل المثال، تيار "sendmail"):
$msg->print(\*SENDMAIL);

إرسال رسالة:

### الإرسال بالطريقة "الأفضل" (الافتراضي هو استخدام "sendmail"):
$msg->send;
### الإرسال بطريقة محددة:
$msg->send('type',@args);

تحديد طريقة الإرسال الافتراضية:

MIME::Lite->send('smtp','some.host',Debug=>0);

مع المصادقة:

MIME::Lite->send('smtp','some.host', AuthUser=>$user, AuthPass=>$pass);

باستخدام SSL:

MIME::Lite->send('smtp','some.host', SSL => 1, Port => 465 );

الوصف

في السعي الأبدي لنكهة جيدة بسعرات حرارية أقل، نقدم: MIME::Lite.

MIME::Lite هو وحدة بسيطة ومستقلة لتوليد (وليس تحليل!) رسائل MIME... على وجه التحديد، تسمح للمستخدم الخاص بك بإنشاء رسالة بسيطة لائقة، ذات جزء واحد أو متعددة الأجزاء، تحتوي على نص أو ملفات ثنائية. لا تتطلب تثبيت مكتبات Mail:: أو MIME::، ولكنها ستعمل معها إذا كانت مثبتة لديك.

يمكنك تحديد كل جزء من الرسالة كبيانات حرفية (في مقياس أو مصفوفة)، أو كسلسلة يمكن تمريرها إلى open() للحصول على ملف إخراج للقراءة (على سبيل المثال، "<filename>" أو "somecommand|").

لا داعي للقلق بشأن ترميز رسالتك - ستفعل هذه الوحدة ذلك نيابة عنك. إنها تتعامل مع ترميزات MIME الخمس القياسية.

أمثلة

إنشاء رسالة بسيطة تحتوي على نص فقط

$msg = MIME::Lite->new(
    From     =>'me@myhost.com',
    To       =>'you@yourhost.com',
    Cc       =>'some@other.com, some@more.com',
    Subject  =>'Helloooooo, nurse!',
    Data     =>'How\'s it goin', eh?'
);

إنشاء رسالة بسيطة تحتوي على صورة فقط

$msg = MIME:: Lite->new(
    From     =>'me@myhost.com',
    To       =>'you@yourhost.com',
    Cc       =>'some@other.com, some@more.com',
    Subject  =>'Helloooooo, nurse!',
    Type     =>'image/gif',
    Encoding =>'base64',
    Path     =>'hellonurse.gif'
);

إنشاء رسالة متعددة الأجزاء

### إنشاء "حاوية" متعددة الأجزاء:
$msg = MIME:: Lite->new(
    From    =>'me@myhost.com',
    To      =>'you@yourhost.com',
    Cc      =>'some@other.com, some@more.com',
    Subject =>'A message with 2 parts...',
    Type    =>'multipart/mixed'
);
### إضافة الجزء النصي:
### (ملاحظة: "attach" لديه نفس وسائط "new"):
$msg->attach(
    Type     =>'TEXT',
    Data     =>'Here\'s the GIF file you wanted'
);
### إضافة الجزء الصوري:
$msg->attach(
    Type        =>'image/gif',
    Path        =>'aaa000123.gif',
    Filename    =>'logo.gif',
    Disposition => 'attachment'
);

إرفاق GIF برسالة نصية

سيقوم هذا بإنشاء رسالة متعددة الأجزاء تمامًا كما في الأعلى، ولكن باستخدام "حيلة المرفقات بجزء واحد":

### ابدأ برسالة نصية بسيطة:
$msg = MIME::Lite->new(
    From    =>'me@myhost.com',
    To      =>'you@yourhost.com',
    Cc      =>'some@other.com, some@more.com',
    Subject =>'A message with 2 parts...',
    Type    =>'TEXT',
    Data    =>'Here\'s the GIF file you wanted'
);
### إرفاق جزء... لجعل الرسالة متعددة الأجزاء تلقائيًا:
$msg->attach(
    Type     =>'image/gif',
    Path     =>'aaa000123.gif',
    Filename =>'logo.gif'
);

إرفاق جزء مُجهز مسبقًا برسالة

### إنشاء جزء مستقل:
$part = MIME::Lite->new(
    Top      => 0,
    Type     =>'text/html',
    Data     =>'<H1>Hello</H1>',
);
$part->attr('content-type.charset' => 'UTF-8');
$part->add('X-Comment' => 'A message for you');
### إرفاقه بأي رسالة:
$msg->attach($part);

طباعة رسالة إلى مقبض ملف

### الكتابة إلى ملف إخراج:
$msg->print(\*STDOUT);
### طباعة الرأس فقط:
$msg->print_header(\*STDOUT);
### طباعة الجسم المرمز فقط:
$msg->print_body(\*STDOUT);

طباعة رسالة إلى سلسلة نصية

### الحصول على الرسالة الكاملة كسلسلة نصية:
$str = $msg->as_string;
### الحصول على الرأس فقط:
$str = $msg->header_as_string;
### الحصول على الجسم المرمز فقط:
$str = $msg->body_as_string;

إرسال رسالة

### الإرسال بالطريقة "الأفضل" (الافتراضي هو استخدام "sendmail"):
$msg->send;

إرسال مستند HTML... مع صور مضمنة!

$msg = MIME:: Lite->new(
     To      =>'you@yourhost.com',
     Subject =>'HTML with in-line images!',
     Type    =>'multipart/related'
);
$msg->attach(
    Type => 'text/html',
    Data => qq{
        <body>
            Here's <i>my</i> image:
            <img src="cid:myimage.gif">
        </body>
    },
);
$msg->attach(
    Type => 'image/gif',
    Id   => 'myimage.gif',
    Path => '/path/to/somefile.gif',
);
$msg->send();

تغيير كيفية إرسال الرسائل

### القيام بشيء كهذا في "main" الخاص بك:
if ($I_DONT_HAVE_SENDMAIL) {
   MIME:: Lite->send('smtp', $host, Timeout=>60,
       AuthUser=>$user, AuthPass=>$pass);
}
### الآن ستقوم هذه بما هو صحيح:
$msg->send;         ### الآن ستستخدم Net::SMTP كما هو موضح أعلاه

ضبط/الحصول على الرؤوس والسمات

add TAG,VALUE
طريقة المثيل. تضيف الحقل TAG بالقيمة المعطاة إلى نهاية الرأس. سيتم تحويل TAG إلى أحرف صغيرة، وسيتم تحويل القيمة إلى "آمنة" (سترجع قيمة مع مسافة في النهاية).

تحذير: أي حقل MIME تضيفه سيتجاوز أي سمة MIME لديه عند إخراجها. عادةً، ستستخدم هذه الطريقة لإضافة حقول غير MIME:

$msg->add("Subject" => "Hi there!");

إعطاء قيمة كـ arrayref سيجعل كل تلك القيم تضاف. هذا مفيد فقط للحقول متعددة القيم مثل Received:

$msg->add("Received" => ["here", "there", "everywhere"]

إعطاء قيمة فارغة يضيف عنصرًا نائبًا غير مرئي إلى الرأس، والذي يمكن استخدامه لقمع إخراج حقول Content-* أو الحقل الخاص MIME-Version. عند قمع الحقول، يجب عليك استخدام replace() بدلاً من add():

$msg->replace("Content-disposition" => "");

ملاحظة: الاسم مأخوذ من Mail::Header.

attr ATTR,[VALUE]
طريقة المثيل. تضبط السمة MIME ATTR إلى القيمة STRING. سيتم تحويل ATTR إلى أحرف صغيرة. تستخدم هذه الطريقة عادة لضبط/الحصول على سمات MIME: 
$msg->attr("content-type"         => "text/html");
$msg->attr("content-type.charset" => "US-ASCII");
$msg->attr("content-type.name"    => "homepage.html");

سيؤدي هذا إلى إخراج نهائي يشبه:

Content-type: text/html; charset=US-ASCII; name="homepage.html"

يشير النطاق الفرعي الفارغ إلى الحقل المجهول الأول.

إعطاء قيمة مثل undef سيؤدي إلى إزالة محتوى النطاق الفرعي المقابل.

بدون وسيط، ترجع قيمة السمة:

$type = $msg->attr("content-type");        ### يرجع "text/html"
$name = $msg->attr("content-type.name");   ### يرجع "homepage.html"
delete TAG
طريقة المثيل. تحذف الحقل TAG بالقيمة المعطاة إلى نهاية الرأس. سيتم تحويل TAG إلى أحرف صغيرة. 
$msg->delete("Subject");

ملاحظة: الاسم مأخوذ من Mail::Header.

field_order FIELD,...FIELD
طريقة الفئة/المثيل. تغير الترتيب الذي يتم به إخراج حقول الرأس لهذا الكائن: 
$msg->field_order('from', 'to', 'content-type', 'subject');

عند استخدامها كطريقة للفئة، فإنها تغير الإعدادات الافتراضية لجميع الكائنات:

MIME::Lite->field_order('from', 'to', 'content-type', 'subject');

لا يهم حالة الأحرف: يتم تحويل جميع الأسماء إلى أحرف صغيرة. في كلتا الحالتين، يوفر مصفوفة فارغة لاستعادة الترتيب الافتراضي.

fields
طريقة المثيل. ترجع رأس الكائن بالكامل كمصفوفة من أزواج "[TAG, VALUE]"، حيث يكون كل TAG بأحرف صغيرة. لاحظ أن أي حقل تم تعيينه صراحة بواسطة المستخدم سيتجاوز حقول MIME التي سيتم إنشاؤها عادةً. لذلك، لا يجب عليك قول: 
$msg->set("Content-type" => "text/html; charset=US-ASCII");

إلا إذا كنت تريد أن تتجاوز القيمة السابقة حقل MIME Content-type الذي سيتم إنشاؤه عادةً.

ملاحظة: أسميت هذه الطريقة fields لأن طريقة header() الخاصة بـ Mail::Header ترجع شيئًا مختلفًا، لكنها مشابهة بما يكفي لإحداث الارتباك.

يمكنك تغيير ترتيب الحقول: انظر field_order. لا ينبغي أن تكون ضرورية، ولكن بعض الأشخاص يحتاجون إلى التعامل مع وحدات نمطية سيئة التنفيذ.

filename [FILENAME]
طريقة المثيل. تضبط اسم الملف الذي سيتم الإبلاغ عنه بهذه البيانات. هذا يضبط بالفعل كلا السمتين القياسيتين.

بدون وسيط، ترجع الاسم كما هو محدد بواسطة content-disposition.

get TAG,[INDEX]
طريقة المثيل. تحصل على محتوى الحقل TAG، والذي ربما تم تعيينه باستخدام set() أو replace(). ترجع نص الحقل. 
$ml->get('Subject', 0);

إذا تم إعطاء الفهرس الاختياري المستند إلى 0، فسوف ترجع OCCURS-0 للحقل TAG. بخلاف ذلك، انظر السياق: في سياق عددي، ترجع فقط OCURS-0؛ في سياق مصفوفة، ترجع جميع OCURS.

تحذير: يجب استخدامه فقط مع الحقول غير MIME. سلوك الحقول MIME لم يتم تحديده بعد، وسوف يرمي استثناء الآن.

get_length
طريقة المثيل. تعيد حساب طول جسم الرسالة إذا كانت العملية بسيطة، وتضبط السمة content-length كأثر جانبي: 
$msg->get_length;

ترجع الطول، أو undefined إذا لم يتم تعيينه.

ملاحظة: قد يكون طول المحتوى صعب الحساب، لأنه يتضمن بناء الجسم بالكامل بتشفيره وأخذ طوله (والذي، في حالة الرسائل المتعددة، يتضمن تجميد جميع المكونات الفرعية، وما إلى ذلك).

تضبط هذه الطريقة الطول إلى قيمة محددة فقط إذا كانت الرسالة مكونًا واحدًا بتشفير binary، ويكون الجسم متاحًا في الذاكرة أو كملف بسيط. بخلاف ذلك، يتم تعيين الطول على أنه undefined.

نظرًا لأن content-length ليس حقل MIME قياسيًا (لذلك فهو صحيح!)، يبدو من الإنصاف.

parts
طريقة المثيل. ترجع مكونات هذا الكيان، وهذا الكيان فقط. ترجع مصفوفة فارغة إذا لم يكن لهذا الكيان أي مكونات.

هذه الطريقة **ليست** تكرارية! يمكن أن تحتوي المكونات على مكونات فرعية؛ استخدم parts_DFS() للحصول على كل شيء.

parts_DFS
طريقة المثيل. ترجع قائمة بجميع كائنات MIME::Lite المتضمنة في هذا الكيان، بدءًا من الكيان نفسه، بترتيب البحث العميق أولاً. إذا لم يكن لهذا الكائن أي مكونات، فسيتم إرجاع الكائن نفسه فقط.
preamble [TEXT]
طريقة المثيل. تحصل على/تحدد سلسلة التمهيد، بافتراض أن هذا الكائن لديه مكونات فرعية. تحديده على أنه undef للسلسلة الافتراضية.
replace TAG,VALUE
طريقة المثيل. تحذف جميع تكرارات الحقول المسماة TAG، وتضيف حقلاً جديدًا بالقيمة المعطاة. سيتم تحويل TAG إلى أحرف صغيرة.

تحذير: حقول MIME (MIME-version, Content-*): إذا استبدلت حقلاً MIME، فإن نص الاستبدال سيتجاوز سمات MIME الفعلية عند إخراج هذا الحقل. لذلك، عادةً ما تستخدم attr() لتغيير حقول MIME و add()/replace() لتغيير الحقول غير MIME:

$msg->replace("Subject" => "Hi there!");

إعطاء قيمة كـ سلسلة فارغة سيؤدي فعليًا إلى إزالة هذا الحقل من الإخراج. هذه هي الطريقة الصحيحة لقمع حقول MIME الخاصة:

$msg->replace("Content-disposition" => "");

إعطاء قيمة كـ undefined سيزيل جميع القيم الصريحة لـ TAG دون إضافة قيم جديدة.

ملاحظة: اسم هذه الطريقة مأخوذ من Mail::Header.

scrub
طريقة المثيل. هذا كود ألفا. إذا كنت تستخدمه، فيرجى إخباري كيف كان أداؤه. يبحث بشكل تكراري في شجرة مكونات هذه الرسالة ويبحث عن سمات MIME التي يمكن إزالتها. مع وسيط مصفوفة، فإنه يزيل تلك السمات بالضبط؛ على سبيل المثال: 
$msg->scrub(['content-disposition', 'content-length']);

Setting/getting message data

binmode [OVERRIDE]
Instance method. With no argument, returns whether or not it thinks that the data (as given by the "Path" argument of `build()` ) should be read using binmode() (for example, when `read_now()` is invoked).

The default behavior is that any content type other than `"text/*"` or `"message/*"` is binmode'd; this should in general work fine.

With a defined argument, this method sets an explicit "override" value. An undefined argument unsets the override. The new current value is returned.

data [DATA]
Instance method. Get/set the literal DATA of the message. The DATA may be either a scalar, or a reference to an array of scalars (which will simply be joined).

Warning: setting the data causes the "content-length" attribute to be recomputed (possibly to nothing).

fh [FILEHANDLE]
Instance method. Get/set the FILEHANDLE which contains the message data.

Takes a filehandle as an input and stores it in the object. This routine is similar to path(); one important difference is that no attempt is made to set the content length.

path [PATH]
Instance method. Get/set the PATH to the message data.

Warning: setting the path recomputes any existing "content-length" field, and re-sets the "filename" (to the last element of the path if it looks like a simple path, and to nothing if not).

resetfh [FILEHANDLE]
Instance method. Set the current position of the filehandle back to the beginning. Only applies if you used "FH" in build() or attach() for this message.

Returns false if unable to reset the filehandle (since not all filehandles are seekable).

read_now
Instance method. Forces data from the path/filehandle (as specified by `build()` ) to be read into core immediately, just as though you had given it literally with the "Data" keyword.

Note that the in-core data will always be used if available.

Be aware that everything is slurped into a giant scalar: you may not want to use this if sending tar files! The benefit of not reading in the data is that very large files can be handled by this module if left on disk until the message is output via `print()` or `print_body()`.

sign PARAMHASH
Instance method. Sign the message. This forces the message to be read into core, after which the signature is appended to it.
Data
As in `build()`: the literal signature data. Can be either a scalar or a ref to an array of scalars.
Path
As in `build()`: the path to the file.

If no arguments are given, the default is:

Path => "$ENV{HOME}/.signature"

The content-length is recomputed.

verify_data
Instance method. Verify that all "paths" to attached data exist, recursively. It might be a good idea for you to do this before a `print()`, to prevent accidental partial output if a file might be missing. Raises exception if any path is not readable.

Output

print [OUTHANDLE]
Instance method. Print the message to the given output handle, or to the currently-selected filehandle if none was given.

All OUTHANDLE has to be is a filehandle (possibly a glob ref), or any object that responds to a `print()` message.

print_body [OUTHANDLE] [IS_SMTP]
Instance method. Print the body of a message to the given output handle, or to the currently-selected filehandle if none was given.

All OUTHANDLE has to be is a filehandle (possibly a glob ref), or any object that responds to a `print()` message.

Fatal exception raised if unable to open any of the input files, or if a part contains no data, or if an unsupported encoding is encountered.

IS_SMPT is a special option to handle SMTP mails a little more intelligently than other send mechanisms may require. Specifically this ensures that the last byte sent is NOT '\n' (octal \012) if the last two bytes are not '\r\n' (\015\012) as this will cause some SMTP servers to hang.

print_header [OUTHANDLE]
Instance method. Print the header of the message to the given output handle, or to the currently-selected filehandle if none was given.

All OUTHANDLE has to be is a filehandle (possibly a glob ref), or any object that responds to a `print()` message.

as_string
Instance method. Return the entire message as a string, with a header and an encoded body.
body_as_string
Instance method. Return the encoded body as a string. This is the portion after the header and the blank line.

Note: actually prepares the body by "printing" to a scalar. Proof that you can hand the `print*()` methods any blessed object that responds to a `print()` message.

header_as_string
Instance method. Return the header as a string.

Sending

send
send HOW, HOWARGS...
Class/instance method. This is the principal method for sending mail, and for configuring how mail will be sent.

As a class method with a HOW argument and optional HOWARGS, it sets the default sending mechanism that the no-argument instance method will use. The HOW is a facility name (see below), and the HOWARGS is interpreted by the facility. The class method returns the previous HOW and HOWARGS as an array.

MIME::Lite->send('sendmail', "d:\\programs\\sendmail.exe");
...
$msg = MIME::Lite->new(...);
$msg->send;

As an instance method with arguments (a HOW argument and optional HOWARGS), sends the message in the requested manner; e.g.:

$msg->send('sendmail', "d:\\programs\\sendmail.exe");

As an instance method with no arguments, sends the message by the default mechanism set up by the class method. Returns whatever the mail-handling routine returns: this should be true on success, false/exception on error:

$msg = MIME::Lite->new(From =>...);
$msg->send || die "you DON'T have mail!";

On Unix systems (or rather non-Win32 systems), the default setting is equivalent to:

MIME::Lite->send("sendmail", "/usr/lib/sendmail -t -oi -oem");

On Win32 systems the default setting is equivalent to:

MIME::Lite->send("smtp");

The assumption is that on Win32 your site/lib/Net/libnet.cfg file will be preconfigured to use the appropriate SMTP server. See below for configuring for authentication.

There are three facilities:

"sendmail", ARGS...
Send a message by piping it into the "sendmail" command. Uses the send_by_sendmail() method, giving it the ARGS. This usage implements (and deprecates) the `sendmail()` method.
"smtp", [HOSTNAME, [NAMEDPARMS] ]
Send a message by SMTP, using optional HOSTNAME as SMTP-sending host. Net::SMTP will be required. Uses the send_by_smtp() method. Any additional arguments passed in will also be passed through to send_by_smtp. This is useful for things like mail servers requiring authentication where you can say something like the following 
MIME::Lite->send('smtp', $host, AuthUser =>$user, AuthPass =>$pass);

which will configure things so future uses of

$msg->send();

do the right thing.

"sub", \&SUBREF, ARGS...
Sends a message MSG by invoking the subroutine SUBREF of your choosing, with MSG as the first argument, and ARGS following.

For example: let's say you're on an OS which lacks the usual Unix "sendmail" facility, but you've installed something a lot like it, and you need to configure your Perl script to use this "sendmail.exe" program. Do this following in your script's setup:

MIME::Lite->send('sendmail', "d:\\programs\\sendmail.exe");

Then, whenever you need to send a message $msg, just say:

$msg->send;

That's it. Now, if you ever move your script to a Unix box, all you need to do is change that line in the setup and you're done. All of your $msg->send invocations will work as expected.

After sending, the method last_send_successful() can be used to determine if the send was successful or not.

send_by_sendmail SENDMAILCMD
send_by_smtp HOST, [NAMEDPARMS]
send_by_sub SUBREF, ARGS...
last_send_successful
Instance method. Returns true or false depending on whether the last use of send() was successful.

ملاحظات

كيف أمنع عرض رؤوس المحتوى في قارئ البريد الخاص بي؟

من الواضح أن بعض المستخدمين يستخدمون قراء البريد التي تعرض رؤوس MIME مثل "Content-disposition"، ويريدون من MIME::Lite عدم إنشائها "لأنها تبدو قبيحة".

تنهد.

على الرغم من ذلك، ماذا؟ هنا، الرؤوس ليست فقط للجوانب الجمالية. فهي تساعد في ضمان فهم الرسائل بشكل صحيح من قبل قراء البريد. ولكن، ماذا تريد؟ هنا، يمكنك كبت رؤوس MIME القياسية. قبل إرسال الرسالة، قم بما يلي:

$msg->scrub;

يمكنك scrub() أي جزء من رسالة متعددة الأجزاء بشكل مستقل؛ فقط كن على علم بأنها تعمل بشكل متكرر. قبل أن تتفوه، لاحظ القواعد التي أطبقها:

Content-type
يمكنك كبت السمة "content-type" إذا، وفقط إذا، كان الجزء من نوع "text/plain" مع مجموعة الأحرف "us-ascii".
Content-transfer-encoding
يمكنك كبت السمة "content-transfer-encoding" إذا، وفقط إذا، كان الجزء يستخدم "7bit" أو "8bit" أو "binary" في الترميز. إذا كان خطك أقل من 1000 حرف، فمن الأفضل أن تفعل ذلك. بشكل عام، هذا يعني أنه يمكنك كبته للنص العادي، ولكن ليس للصور، إلخ.
Content-disposition
يمكنك كبت السمة "content-disposition" إذا كنت تثق بقارئ البريد في القيام بالمهمة الصحيحة عند تقريره لعرض مرفق مضمن أو كرابط. لاحظ أن كبت كل من "content-disposition" و "content-type" يعني أنه لن تكون هناك طريقة لتوصية اسم ملف للمرفق!

ملاحظة: هناك تقارير عن برامج بريد إلكتروني يائسة تتصرف بشكل سيء عند تزويدها بـ "content-disposition". إذا تم عرض المرفقات الخاصة بك بشكل مضمن أو العكس، حاول كبت هذه السمة.

Content~4

كيف أعطي اسماً توصياً مختلفاً للمرفق؟

باستخدام خيار Filename (مختلف عن Path!):

$msg->a

لا تعدل الإعدادات العامة

متغيرات التكوين العامة سيئة، ويجب التخلص منها. حتى ذلك الحين، يرجى اتباع الإرشادات الخاصة بكل تكوين حول كيفية عدم تغييرها.

مقدمة موجزة عن MIME

أنواع المحتوى

المعامل "Type" في build() هو نوع محتوى. هذا هو النوع الفعلي للبيانات التي ترسلها. وهو عادةً ما يكون سلسلة نصية بالشكل "majortype/minortype".

فيما يلي أنواع MIME الرئيسية. يمكن العثور على قائمة أكثر اكتمالاً في RFC-2046.

application
بيانات لا تتناسب مع أي من الفئات المتبقية، وخاصة البيانات التي تتم معالجتها بواسطة نوع من برامج التطبيقات. "application/octet-stream", "application/gzip", "application/postscript"...
audio
بيانات صوتية. "audio/basic"...
image
بيانات رسومية. "image/gif", "image/jpeg"...
message
رسالة، عادةً بريد إلكتروني آخر أو رسالة MIME. "message/rfc822"...
multipart
رسالة تحتوي على رسائل أخرى. "multipart/mixed", "multipart/alternative"...
text
بيانات نصية، مخصصة للقراءة البشرية. "text/plain", "text/html"...
video
بيانات فيديو أو بيانات فيديو + صوت. "video/mpeg"...

ترميزات نقل المحتوى

المعامل "Encoding" في build(). هذه هي الطريقة التي يتم بها إرسال جسم الرسالة للنقل بأمان.

فيما يلي ترميزات MIME الخمسة الرئيسية. يمكن العثور على قائمة أكثر اكتمالاً في RFC-2045.

7bit
في الأساس، لا يتم إجراء أي ترميز حقيقي. ومع ذلك، يضمن هذا التسمية عدم وجود أحرف 8 بت وأن الأسطر لا تتجاوز 1000 حرف طولًا.
8bit
في الأساس، لا يتم إجراء أي ترميز حقيقي. قد تحتوي الرسالة على أحرف 8 بت، ولكن هذا الترميز يضمن أن الأسطر لا تتجاوز 1000 حرف طولًا.
binary
لا يتم إجراء أي ترميز. قد تحتوي الرسالة على أحرف 8 بت، وقد تكون الأسطر أطول من 1000 حرف.
base64
مشابه لـ "uuencode"، ولكنه معرف جيدًا. هذه هي الطريقة التي يجب عليك بها إرسال معلومات ثنائية (ملفات tar، صور GIF، صور JPEG، إلخ).
quoted-printable
مفيد لترميز الرسائل النصية التي تحتوي على أحرف غير ASCII (على سبيل المثال، Latin-1، Latin-2، أو أي أبجدية أخرى 8 بت).

وحدات الدعم

تعمل MIME::Lite بشكل جيد مع الوحدات الأخرى إذا كانت موجودة. الوحدات التي يوصى بتثبيتها هي أحدث إصدار من MIME::Types، Mail::Address، MIME::Base64، MIME::QuotedPrint، و Net::SMTP. Email::Date::Format ضرورية تمامًا.

إذا لم تكن هذه الوحدات موجودة، فلن تعمل بعض الوظائف ولن تكون الميزات الأخرى فعالة أو محدثة كما يمكن أن تكون. ومع ذلك، فهي إضافات اختيارية.

ملحقات مجمعة

تأتي MIME::Lite مع العديد من الملفات الإضافية في حزمة التوزيع. وهذا يشمل أمثلة ووحدات مساعدة يمكنك استخدامها للبدء في استخدام الوحدة.

المجلد ./examples يحتوي على العديد من المقاطع الصغيرة المعدة، والتي تم توثيقها عمومًا، ولكن يجب أن تكون سهلة الفهم.

المجلد ./contrib يحتوي على وحدات مساعدة/ أدوات تأتي مع MIME::Lite، ولكنها لا تُثبت افتراضيًا. يرجى مراجعة ملفات POD المصاحبة لها.

الأخطاء

السبب وراء إصدار الإصدار 3.0 هو ضمان أن MIME::Lite محدثة وتم إصلاح أخطائها. إذا واجهت مشكلة، يرجى الإبلاغ عنها.

حسب علمي، لا توجد حاليًا أي أخطاء خطيرة في MIME::Lite، ولكن استخدامه غير كامل عمليًا.

على الرغم من ذلك، هناك العديد من المشكلات المفتوحة التي تقلقني، والتي سببها التقدم الذي أحرزه المجتمع منذ أن أصدر Eryq الإصدار الأخير. تعتمد الاختبارات على إطار عمل اختبار مثير للاهتمام ولكنه غير قياسي. أود أن أغيره إلى Test::More.

إذا فشلت الاختبارات، يرجى التحقق من المجلد ./testout، وفي أي تقرير خطأ، قم بتضمين مخرجات الملف ذي الصلة. هذه هي الميزة الوحيدة التي أراها تبرر عدم استخدام Test::More.

التصحيحات، الإصلاحات، والمساهمات مرحب بها، على الرغم من أنني على الأرجح لن أطبقها إذا لم يكن لديها اختبار مصاحب. هذا يعني أنه إذا لم يكن لدي وقت لكتابة الاختبار، فلن يتم تطبيق التصحيح، لذا يرجى تضمين اختبارات لأي تصحيح تقدمه.
