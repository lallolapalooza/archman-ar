mib2c.conf(5)

الحزمة: net-snmp

التراخيص: BSD

MIB2C.CONF(5) Net-SNMP MIB2C.CONF(5)

الاسم

mib2c.conf - كيفية كتابة ملفات mib2c.conf للقيام بأي شيء بناءً على مدخلات MIB.

الملخص

% cat > mib2c.test.conf << EOF @foreach $t table@
بداية الجدول $t
@foreach $c column@
echo $t يحتوي على عمود $c والذي له صيغة $c.syntax
@end@

@end@ EOF

% mib2c -c mib2c.test.conf internet

الوصف

لغة برمجة mib2c.conf هي لغة خاصة بـ MIB مصممة لمعالجة عقد MIB بطرق مرغوبة بسهولة. mib2c هو تسمية خاطئة (لأسباب تاريخية)، لأنه يمكنك إنتاج أي شيء (ليس فقط كود C). ابحث في دليل Net-SNMP "local" عن مجموعة من ملفات mib2c.*.conf النموذجية وشاهد القوة أمام عينيك.

الأوامر

يتم احتواء جميع الأوامر داخل ملفات mib2c.conf بعلامات @. كل شيء بعلامة @ في بداية ونهاية السطر يُفترض عمومًا أن يكون أمرًا خاصًا بـ mib2c. يتم تفصيل هذه هنا:

@open FILE@
يكتب المخرجات التي تم إنشاؤها إلى FILE. لاحظ أنه بالنسبة لمواصفات الملفات، فتح '-' سيطبع إلى stdout.
@append FILE@
يضيف FILE المحدد.
@close FILE@
يغلق FILE المحدد.
@push@
يحفظ المخرجات الحالية، ثم يمسح المخرجات. استخدمه مع @open@ و @pop@ للكتابة إلى ملف جديد دون التدخل في المخرجات الحالية.
@pop@
يدفع مكدس process() مستوى واحدًا لأعلى. استخدمه بعد @push@ للعودة إلى المجموعة السابقة من الملفات المفتوحة.
@foreach $VAR scalar@
كرر التكرار فوق الكود حتى @end@ مع ضبط $VAR على جميع القيم العددية المعروفة.
@foreach $VAR table@
كرر التكرار فوق الكود حتى @end@ مع ضبط $VAR على جميع الجداول المعروفة.
@foreach $VAR column@
كرر التكرار فوق الكود حتى @end@ مع ضبط $VAR على جميع الأعمدة المعروفة ضمن جدول معين. بالطبع، يجب استدعاء هذا داخل عبارة foreach-table.
@foreach $VAR nonindex@
كرر التكرار فوق الكود حتى @end@ مع ضبط $VAR على جميع الأعمدة غير الفهرسة المعروفة ضمن جدول معين. بالطبع، يجب استدعاء هذا داخل عبارة foreach-table.
@foreach $VAR internalindex@
كرر التكرار فوق الكود حتى @end@ مع ضبط $VAR على جميع الأعمدة الفهرسة الداخلية المعروفة ضمن جدول معين. بالطبع، يجب استدعاء هذا داخل عبارة foreach-table.
@foreach $VAR externalindex@
كرر التكرار فوق الكود حتى @end@ مع ضبط $VAR على جميع الأعمدة الفهرسة الخارجية المعروفة ضمن جدول معين. بالطبع، يجب استدعاء هذا داخل عبارة foreach-table.
@foreach $VAR index@
كرر التكرار فوق الكود حتى @end@ مع ضبط $VAR على جميع الفهارس المعروفة ضمن جدول معين. بالطبع، يجب استدعاء هذا داخل عبارة foreach-table.
@foreach $VAR notifications@
كرر التكرار فوق الكود حتى @end@ مع ضبط $VAR على جميع الإشعارات المعروفة.
@foreach $VAR varbinds@
كرر التكرار فوق الكود حتى @end@ مع ضبط $VAR على جميع varbinds المعروفة. بالطبع، يجب استدعاء هذا داخل عبارة foreach-notifications.
@foreach $LABEL, $VALUE enum@
كرر التكرار فوق الكود حتى @end@ مع ضبط $LABEL و $VALUE على الملصق والقيم من قائمة enum.
@foreach $RANGE_START, $RANGE_END range NODE@
كرر التكرار فوق الكود حتى @end@ مع ضبط $RANGE_START و $RANGE_END على مجموعة النطاقات القانونية المقبولة لعقدة MIB معينة.
@foreach $var stuff a b c d@
كرر التكرار فوق القيم a، b، c، d كما تم تعيينها بشكل عام (أي، يتم أخذ القيم مباشرة من القائمة دون توسيع MIB، إلخ).
@while expression@
كرر التكرار فوق الكود حتى يصبح التعبير خاطئًا.
@eval $VAR = expression@
يقوم بتقييم التعبير وتعيين النتائج إلى $VAR. هذا ليس تقييم perl كامل، ولكنه نوع من التقييم "المحاكي" المفيد للتعبيرات البسيطة مع الاحتفاظ بنفس مساحة أسماء المتغيرات. انظر أدناه للحصول على تفاصيل كاملة حول التصدير إلى perl.
@perleval STUFF@
يقوم بتقييم STUFF مباشرة في perl. لاحظ أن جميع متغيرات mib2c التي يتم تفسيرها داخل ملفات .conf موجودة في $vars{NAME} وسيتم طباعة تحذير إذا لم يُرجع STUFF القيمة 0. (إضافة 'return 0;' في نهاية STUFF هو حل بديل).
@startperl@
@endperl@
يعامل كل ما بين هذين الوسمين ككود perl، ويقوم بتقييمه.
@next@
إعادة تشغيل foreach؛ يجب استخدامه فقط داخل شرط. يتخطى الشرط الحالي، ثم يستمر في التخطي إلى النهاية لعبارة foreach الحالية.
@if expression@
يقوم بتقييم التعبير، وإذا كان التعبير صحيحًا، فإنه يعالج الجزء المحتوي حتى يتم الوصول إلى @end@ المناسب. إذا كان التعبير خاطئًا، فسيتم تقييم عبارة @elsif expression@ التالية (إذا كانت موجودة)، حتى يصبح تعبير صحيحًا. إذا لم يكن هناك تعبير كهذا وتم العثور على عبارة @else@، فسيتم تقييمها.
@ifconf file@
إذا كان يمكن العثور على الملف المحدد في مسار البحث عن ملفات التكوين، وإذا تم العثور عليه، فإنه يعالج الجزء المحتوي حتى يتم العثور على @end@ المناسب. كما هو الحال مع @if expression@ العادي، يمكن استخدام @elsif expression@ و @else@.
@ifdir dir@
إذا كان الدليل المحدد موجودًا، فقم بمعالجة الجزء المحتوي حتى يتم العثور على @end@ المناسب. كما هو الحال مع @if expression@ العادي، يمكن استخدام @elsif expression@ و @else@.
@define NAME@
@enddefine@
يحفظ "المحتوى" بين وسوم define و enddefine للاستدعاء لاحقًا باسم NAME عن طريق @calldefine NAME@.
@calldefine NAME@
ينفذ المحتوى الذي تم حفظه سابقًا باسم NAME.
@printf "expression" stuff1, stuff2, ...@
مثل كل دوال printf الأخرى التي تعرفها وتحبها.
@run FILE@
يستورد محتويات FILE كملف mib2c، ولكنه لا يؤثر على الملفات المفتوحة حاليًا.
@include FILE@
يستورد محتويات FILE كملف mib2c ويضيف مخرجاته إلى المخرجات الحالية.
@prompt $var QUESTION@
يعرض QUESTION للمستخدم، ويتوقع ردًا ويضعه في $var.
@print STUFF@
يطبع STUFF مباشرة إلى شاشة المستخدم (أي، ليس إلى حيث تذهب مخرجات mib2c العادية).
@quit@
يخرج (بصمت).
@exit@
يخرج!

المتغيرات

تبدو المتغيرات في لغة mib2c مشابهة جدًا لمتغيرات perl، من حيث أنها تبدأ بـ "$". يمكن استخدامها لأي شيء تريده، ولكن في أغلب الأحيان ستكون بمثابة عقد MIB التي تتم معالجتها بواسطة عبارات @foreach ...@.

لديها أيضًا خصائص خاصة عندما تكون عقدة MIB، بحيث يؤدي إضافة لواحق خاصة إليها إلى تفسيرها بطريقة ما. أسهل طريقة لفهم ذلك هي من خلال مثال. إذا كان المتغير 'x' يحتوي على الكلمة 'ifType'، فستحدث بعض الأشياء السحرية. في مخرجات mib2c، في أي وقت يتم رؤية $x، يتم استبدالها بـ "ifType". يمكن استخدام لواحق إضافية للحصول على جوانب أخرى من عقدة MIB تلك. إذا تم رؤية $x.objectID، فسيتم استبدالها بـ OID لـ ifType: ".1.3.6.1.2.1.2.2.1.3". اللواحق الأخرى التي يمكن أن تظهر بعد نقطة مدرجة أدناه.

شيء أخير: يمكنك استخدام أشياء مثل $vartext تنتهي فورًا بنص آخر، يمكنك استخدام {} للحصول على توسع صحيح لجزء فقط من مدخلات mib2c. مثال: $xtext سينتج "$xtext"، لكن ${x}text سينتج "ifTypetext" بدلاً من ذلك.

NAME

mib2c.conf, mib2c.snmpv3.conf, mib2c. MIB module configuration files

SYNOPSIS

mib2c.conf

mib2c.snmpv3.conf

mib2c. MIB module configuration files

DESCRIPTION

The mib2c utility uses a configuration file to control its behaviour when generating code from a MIB file. The default configuration file is mib2c.conf, but other files can be specified on the command line. Some modules may also have their own specific configuration files (e.g. mib2c.snmpv3.conf).

The configuration file uses a simple format: directives consist of a variable name, followed by an equals sign, followed by the value. Lines starting with a # or * are comments.

The configuration file can be divided into sections using the syntax:

sectionname "value" { ... }

This allows different parts of the configuration to be applied selectively, based on the MIB object or other criteria. The most common section is #mib2c-header, which is used for global settings.

The configuration file supports a number of variables that control the code generation process. These variables can be grouped into several categories:

COMMANDS

main.module

Specifies the main module to use for code generation (e.g. tree, table, script).

rootWriteString

Specifies whether to generate code for the root objectWriteString function. (Default: 0)

VARIABLES

$var.type
The SNMP data type of the variable.
$var.subtype
The specific subtype of the variable (e.g. integer, unsigned32).
$var.idx
1 if the variable is an index column, 0 if not.
$var.namelen
The length of the variable's name.
$var.name
The variable's name.
$var.access
The variable's access rights (e.g. read-only, read-write).
$var.status
The variable's status (e.g. current, obsolete).
$var.maxaccess
The variable's maximum access rights.
$var.isMandatory
1 if the variable is mandatory, 0 if not.
$var.isReadable
1 if the variable is readable, 0 if not.
$var.isWritable
1 if the variable is writable, 0 if not.
$var.isSetable
1 if the variable is settable (can be set via SNMP SET), 0 if not.
$var.isCreatable
1 if the variable is creatable (can be created via SNMP CREATE), 0 if not.
$var.isLastChange
1 if the variable is a LastChange object, 0 if not.
$var.isStorageType
1 if an object is a StorageType object, 0 if not

1 if an object is a RowStatus object, 0 if not 'settable', 'creatable', 'lastchange', 'storagetype' and 'rowstatus' can also be used with table variables to indicate whether it contains writable, creatable, LastChange, StorageType or RowStatus column objects
