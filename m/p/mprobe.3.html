mcheck(3) دليل الدوال المكتبية mcheck(3)

الاسم

mcheck, mcheck_check_all, mcheck_pedantic, mprobe - التحقق من اتساق الذاكرة المخصصة (heap)

المكتبة

مكتبة C القياسية (libc، -lc)

ملخص

#include <mcheck.h>
int mcheck(typeof(void (enum mcheck_status mstatus)) *f);
int mcheck_pedantic(
           typeof(void (enum mcheck_status mstatus)) *f);
void mcheck_check_all(void);
enum mcheck_status mprobe(void *ptr);

الوصف

تقوم الدالة mcheck() بتثبيت مجموعة من الخطافات (hooks) لأغراض تصحيح الأخطاء لوظائف تخصيص الذاكرة من عائلة malloc(3). هذه الخطافات تسبب إجراء بعض فحوصات الاتساق على حالة الذاكرة المخصصة (heap). يمكن للفحوصات اكتشاف أخطاء التطبيق مثل تحرير كتلة من الذاكرة أكثر من مرة أو إفساد هياكل البيانات الخاصة بحفظ المعلومات التي تسبق مباشرة كتلة ذاكرة مخصصة.

لكي تكون فعالة، يجب استدعاء الدالة mcheck() قبل أول استدعاء للدالة malloc(3) أو دالة ذات صلة. في الحالات التي يكون فيها ضمان ذلك صعبًا، يؤدي ربط البرنامج بـ -lmcheck إلى إدخال استدعاء ضمني للدالة mcheck() (مع وسيط NULL) قبل أول استدعاء لدالة تخصيص الذاكرة.

الدالة mcheck_pedantic() تشبه الدالة mcheck()، ولكنها تجري فحوصات على جميع الكتل المخصصة عندما يتم استدعاء إحدى دوال تخصيص الذاكرة. يمكن أن يكون هذا بطيئًا جدًا!

الدالة mcheck_check_all() تسبب فحصًا فوريًا لجميع الكتل المخصصة. هذا الاستدعاء يكون فعالاً فقط إذا تم استدعاء الدالة mcheck() مسبقًا.

إذا اكتشف النظام عدم اتساق في الذاكرة المخصصة، يتم استدعاء الدالة التي يوفرها المستخدم والتي يشير إليها f مع وسيط واحد، mstatus، والذي يشير إلى نوع عدم الاتساق الذي تم اكتشافه. إذا كان f هو NULL، تقوم دالة افتراضية بطباعة رسالة خطأ على stderr وتستدعي abort(3).

تقوم الدالة mprobe() بإجراء فحص اتساق على كتلة الذاكرة المخصصة المشار إليها بواسطة ptr. يجب استدعاء الدالة mcheck() مسبقًا (وإلا فإن mprobe() ترجع MCHECK_DISABLED).

يصف السرد التالي القيم التي ترجعها الدالة mprobe() أو التي يتم تمريرها كوسيط mstatus عند استدعاء f:

MCHECK_DISABLED (mprobe() فقط)
لم يتم استدعاء mcheck() قبل استدعاء أول دالة تخصيص ذاكرة. التحقق من الاتساق غير ممكن.
MCHECK_OK (mprobe() فقط)
لم يتم اكتشاف عدم اتساق.
MCHECK_HEAD
تم إفساد الذاكرة التي تسبق الكتلة المخصصة.
MCHECK_TAIL
تم إفساد الذاكرة التي تلي الكتلة المخصصة.
MCHECK_FREE
تم تحرير كتلة ذاكرة مرتين.

قيمة الإرجاع

ترجع الدالتان mcheck() و mcheck_pedantic() القيمة 0 عند النجاح، أو -1 عند الخطأ.

ملاحظات

يؤدي ربط برنامج بـ -lmcheck واستخدام متغير البيئة MALLOC_CHECK_ (الموصوف في mallopt(3)) إلى اكتشاف نفس أنواع الأخطاء. ولكن، استخدام MALLOC_CHECK_ لا يتطلب إعادة ربط التطبيق.

أمثلة

يقوم البرنامج أدناه باستدعاء mcheck() بوسيط NULL ثم يحرر نفس كتلة الذاكرة مرتين. توضح جلسة shell التالية ما يحدث عند تشغيل البرنامج:


$ ./a.out
About to free
About to free a second time
block freed twice
Aborted (core dumped)

مصدر البرنامج

#include <mcheck.h>
#include <stdio.h>
#include <stdlib.h>
int
main(void)
{
    char *p;
    if (mcheck(NULL) != 0) {
        fprintf(stderr, "mcheck() failed\n");
        exit(EXIT_FAILURE);
    }
    p = malloc(1000);
    fprintf(stderr, "About to free\n");
    free(p);
    fprintf(stderr, "\nAbout to free a second time\n");
    free(p);
    exit(EXIT_SUCCESS);
}
