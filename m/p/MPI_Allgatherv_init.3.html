MPI_Allgatherv_init(3)

الحزمة: openmpi

التراخيص: BSD-3-Clause AND LicenseRef-MPICH

MPI_Allgatherv_init(3) Open MPI MPI_Allgatherv_init(3)

MPI_Allgatherv, MPI_Iallgatherv, MPI_Allgatherv_init - يستقبل بيانات من جميع العمليات ويسلمها إلى الجميع. يمكن لكل عملية المساهمة بكمية مختلفة من البيانات.

الصيغة

#include <mpi.h>

     MPI_Datatype sendtype, void *recvbuf, const int recvcounts[],
     const int displs[], MPI_Datatype recvtype, MPI_Comm comm)
int MPI_Iallgatherv(const void *sendbuf, int sendcount,
     MPI_Datatype sendtype, void *recvbuf, const int recvcounts[],
     const int displs[], MPI_Datatype recvtype, MPI_Comm comm,
        MPI_Request *request)
int MPI_Allgatherv_init(const void *sendbuf, int sendcount,
     MPI_Datatype sendtype, void *recvbuf, const int recvcounts[],
     const int displs[], MPI_Datatype recvtype, MPI_Comm comm,
        MPI_Info info, MPI_Request *request)

معلمات الإدخال

  • sendbuf: عنوان المخزن المؤقت للإرسال (اختياري).
  • sendcount: عدد العناصر في المخزن المؤقت للإرسال (عدد صحيح).
  • sendtype: نوع العناصر في المخزن المؤقت للإرسال (مقبض).
  • recvcount: مصفوفة من الأعداد الصحيحة (بطول المجموعة) تحتوي على عدد العناصر المستلمة من كل عملية.
  • displs: مصفوفة من الأعداد الصحيحة (بطول المجموعة). يحدد العنصر i الإزاحة (نسبة إلى recvbuf) التي سيتم وضع البيانات الواردة من العملية i فيها.
  • recvtype: نوع العناصر في المخزن المؤقت الاستقبال (مقبض).
  • comm: المتصل (مقبض).
  • info: معلومات (مقبض، ثابت فقط).

معلمات الإخراج

  • recvbuf: عنوان المخزن المؤقت الاستقبال (اختياري).
  • request: طلب (مقبض، غير مانع فقط).
  • ierror: في Fortran فقط: رمز الخطأ (عدد صحيح).

الوصف

MPI_Allgatherv مشابه لـ MPI_Allgather من حيث أن جميع العمليات تستقبل بيانات من جميع العمليات الأخرى، باستثناء أن كل عملية يمكن أن ترسل كمية مختلفة من البيانات. يتم استلام كتلة البيانات المرسلة من العملية j بواسطة جميع العمليات ووضعها في الكتلة j من المخزن المؤقت recvbuf.

يجب أن يكون توقيع النوع المرتبط بـ sendcount و sendtype في العملية j هو نفسه توقيع النوع المرتبط بـ recvcounts[j] و recvtype في أي عملية أخرى.

النتيجة كما لو أن جميع العمليات قد نفذت استدعاءات إلى

MPI_Allgatherv(sendbuf, sendcount, sendtype, recvbuf, recvcount,
              displs,recvtype,root,comm);
// لـ root = 0, ..., n-1.

قواعد استخدام MPI_Allgatherv بشكل صحيح سهلة الاستخلاص من القواعد المقابلة لـ MPI_Gatherv.

استخدام خيار في المكان

عندما يكون المتصل متصلاً داخليًا، يمكنك إجراء عملية جمع في المكان (يتم استخدام المخزن المؤقت للإخراج كمخزن مؤقت للإدخال). استخدم المتغير MPI_IN_PLACE كقيمة لـ sendbuf. في هذه الحالة، يتم تجاهل sendcount و sendtype. يُفترض أن تكون بيانات الإدخال لكل عملية في المنطقة التي ستستلم فيها تلك العملية مساهمتها الخاصة في المخزن المؤقت الاستقبال. على وجه الخصوص، تكون نتيجة استدعاء لـ MPI_Allgatherv استخدمت خيار في المكان مساوية للحالة التي قامت فيها جميع العمليات بتنفيذ n استدعاءات لـ

MPI_Allgatherv ( MPI_IN_PLACE, 0, MPI_DATATYPE_NULL, recvbuf,
                 recvcounts, displs, recvtype, root, comm );
// لـ root =0, ... , n-1.

ملاحظة: MPI_IN_PLACE هي قيمة خاصة؛ لها نفس القيود في استخدامها مثل MPI_BOTTOM.

نظرًا لأن خيار في المكان يحول المخزن المؤقت الاستقبال إلى مخزن مؤقت للإرسال والاستقبال، فإن ربط Fortran الذي يتضمن INTENT يجب أن يضع علامة عليها كـ INOUT، وليس OUT.

عندما يكون المتصل متصلاً داخليًا

عندما يكون المتصل متصلاً داخليًا، تحدث عملية الجمع على مرحلتين. يتم جمع البيانات من جميع أعضاء المجموعة الأولى، وربطها، واستلامها بواسطة جميع أعضاء المجموعة الثانية. بعد ذلك، يتم جمع البيانات من جميع أعضاء المجموعة الثانية، وربطها، واستلامها بواسطة جميع أعضاء المجموعة الأولى. يجب أن تكون وسائط الإرسال في المجموعة الأولى متسقة مع وسائط الاستقبال في المجموعة الثانية، والعكس صحيح. يجب أن تظهر العملية سلوكًا متماثلًا وازدواجية كاملة.

الأخطاء

أكثر من 90٪ من إجراءات MPI تعيد قيمة خطأ؛ إجراءات C تعيد نتيجة الدالة، وإجراءات Fortran في آخر وسيط.

قبل إعادة قيمة الخطأ، يتم استدعاء معالج الخطأ المرتبط بكائن الاتصال (على سبيل المثال، المتصل، النافذة، الملف). إذا لم يكن هناك كائن اتصال مرتبط باستدعاء MPI، يعتبر الاستدعاء مرتبطًا بـ MPI_COMM_SELF ويتم استدعاء معالج الخطأ المقابل. عندما لا يتم تهيئة MPI_COMM_SELF (أي، قبل MPI_Init/MPI_Init_thread، بعد MPI_Finalize، أو عند استخدام نموذج الجلسات حصريًا)، يثير الخطأ معالج الخطأ الأولي. يمكن تغيير معالج الخطأ الأولي عن طريق استدعاء MPI_Comm_set_errhandler على MPI_COMM_SELF عند استخدام نموذج العالم، أو من خلال وسيط mpi_initial_errhandler لـ mpiexec أو مفتاح المعلومات لـ MPI_Comm_spawn/MPI_Comm_spawn_multiple. إذا لم يكن هناك معالج خطأ مناسب آخر، يتم استدعاء معالج الأخطاء MPI_ERRORS_RETURN لوظائف إدخال / إخراج MPI ومعالج الأخطاء MPI_ERRORS_ABORT لجميع أو

ERRORS

MPI standard error handlers are invoked for errors that occur during the execution of other MPI functions.

Open MPI includes three predefined error handlers that can be used:

  • MPI_ERRORS_ARE_FATAL Causes the program to abort all connected MPI processes.
  • MPI_ERRORS_ABORT An error handler that can be invoked on a communicator, window, file, or session. When called on a communicator, it acts as if MPI_Abort was called on that communicator. If called on a window or file, acts as if MPI_Abort was called on a communicator containing the group of processes in the corresponding window or file. If called on a session, aborts only the local process.
  • MPI_ERRORS_RETURN Returns an error code to the application.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.
