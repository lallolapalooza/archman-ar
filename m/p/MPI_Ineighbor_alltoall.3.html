INPUT PARAMETERS

sendbuf
Local buffer containing the data to be sent to all neighbors.
sendcount
Number of elements to send to each neighbor.
sendtype
Datatype of elements in the send buffer.
recvbuf
Local buffer where the data from all neighbors will be received.
recvcount
Number of elements to receive from each neighbor.
recvtype
Datatype of elements in the receive buffer.
comm
Communicator with a topology that includes neighbors.

OUTPUT PARAMETERS

request
MPI request handle that allows checking for completion.
IERROR
Fortran only: Error status.

DESCRIPTION

This function is the non-blocking version of MPI_Neighbor_alltoall. It allows a process to send data from its local buffer to all of its neighbors and receive data from all of its neighbors into its local buffer, without blocking.

The communicator must have a Cartesian topology or a graph topology associated with it, so that neighbors can be identified.

The send and receive counts and datatypes must be consistent across all processes in the communicator. Specifically, for all processes i in the communicator:

  • The number of elements sent by process i to neighbor j must be the same as the number of elements received by process j from neighbor i.
  • The send type used by process i must be compatible with the receive type used by neighbor j, and vice versa.

The data is sent from sendbuf to each neighbor and received into recvbuf from each neighbor. The request handle can be used with MPI_Wait or MPI_Test to determine when the communication is complete.

NEIGHBOR ORDERING

The order in which neighbors are specified is determined by the topology associated with the communicator. For Cartesian topologies, neighbors are ordered according to the dimension and direction (e.g., neighbors in dimension 0, direction -1, then dimension 0, direction +1, etc.). For graph topologies, neighbors are ordered according to their rank in the graph structure.

NOTES

The MPI_Count versions of the routine (MPI_Ineighbor_alltoall_c) are provided to allow the use of larger counts than can be represented by a standard 32-bit integer.

ERRORS

When an MPI function returns an error code, it is a value that indicates the general class of the error. If the error handler has been set to MPI_ERRORS_RETURN, then the function will return the error code to the application. Otherwise, the error handler that has been set for the communicator will be invoked. The error handler is associated with the communication object (e.g., communicator, window, file) that is associated with the communication call (e.g., communicator, window, file) is called. If no communication object is associated with the MPI call, then the call is considered attached to MPI_COMM_SELF and will call the associated MPI error handler. When MPI_COMM_SELF is not initialized (i.e., before MPI_Init/MPI_Init_thread, after MPI_Finalize, or when using the Sessions Model exclusively) the error raises the initial error handler. The initial error handler can be changed by calling MPI_Comm_set_errhandler on MPI_COMM_SELF when using the World model, or the mpi_initial_errhandler CLI argument to mpiexec or info key to MPI_Comm_spawn/MPI_Comm_spawn_multiple. If no other appropriate error handler has been set, then the MPI_ERRORS_RETURN error handler is called for MPI I/O functions and the MPI_ERRORS_ABORT error handler is called for all other MPI functions.

Open MPI includes three predefined error handlers that can be used:

  • MPI_ERRORS_ARE_FATAL Causes the program to abort all connected MPI processes.
  • MPI_ERRORS_ABORT An error handler that can be invoked on a communicator, window, file, or session. When called on a communicator, it acts as if MPI_Abort was called on that communicator. If called on a window or file, acts as if MPI_Abort was called on a communicator containing the group of processes in the corresponding window or file. If called on a session, aborts only the local process.
  • MPI_ERRORS_RETURN Returns an error code to the application.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.
