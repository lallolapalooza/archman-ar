MPI_Type_create_struct(3) Open MPI MPI_Type_create_struct(3)

MPI_Type_create_struct — إنشاء نوع بيانات مهيكل.

الصيغة

صيغة C

#include <mpi.h>
int MPI_Type_create_struct(int count, int array_of_blocklengths[],
     const MPI_Aint array_of_displacements[], const MPI_Datatype array_of_types[],
     MPI_Datatype *newtype)

صيغة Fortran

USE MPI
! أو الصيغة الأقدم: INCLUDE 'mpif.h'
MPI_TYPE_CREATE_STRUCT(COUNT, ARRAY_OF_BLOCKLENGTHS,
             ARRAY_OF_DISPLACEMENTS, ARRAY_OF_TYPES, NEWTYPE, IERROR)
     INTEGER COUNT, ARRAY_OF_BLOCKLENGTHS(*), ARRAY_OF_TYPES(*),
     INTEGER NEWTYPE, IERROR
     INTEGER(KIND=MPI_ADDRESS_KIND) ARRAY_OF_DISPLACEMENTS(*)

صيغة Fortran 2008

USE mpi_f08
MPI_Type_create_struct(count, array_of_blocklengths,
             array_of_displacements, array_of_types, newtype, ierror)
     INTEGER, INTENT(IN) :: count, array_of_blocklengths(count)
     INTEGER(KIND=MPI_ADDRESS_KIND), INTENT(IN) ::
     array_of_displacements(count)
     TYPE(MPI_Datatype), INTENT(IN) :: array_of_types(count)
     TYPE(MPI_Datatype), INTENT(OUT) :: newtype
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

معاملات الإدخال

  • count: عدد الكتل (عدد صحيح) — وهو أيضًا عدد المدخلات في المصفوفات array_of_types، array_of_displacements، و array_of_blocklengths.
  • array_of_blocklengths: عدد العناصر في كل كتلة (مصفوفة من الأعداد الصحيحة).
  • array_of_displacements: إزاحة البايت لكل كتلة (مصفوفة من الأعداد الصحيحة).
  • array_of_types: نوع العناصر في كل كتلة (مصفوفة من مقابض كائنات أنواع البيانات).

معاملات الإخراج

  • newtype: نوع بيانات جديد (مقبض).
  • ierror: Fortran فقط: حالة الخطأ (عدد صحيح).

الوصف

MPI_Type_create_struct ينشئ نوع بيانات مهيكل. تستبدل هذه الروتين MPI_Type_struct، الذي تم إهماله الآن.

MPI_Type_create_struct هو مُنشئ الأنواع الأكثر عمومية. إنه يعمم MPI_Type_create_hindexed بشكل أكبر من حيث أنه يسمح لكل كتلة بالتكون من تكرارات لأنواع بيانات مختلفة.

مثال 1: ليكن type1 من النوع

{(double, 0), (char, 8)}

مع مدى 16. ليكن B = (2, 1, 3)، D = (0, 16, 26)، و T = (MPI_FLOAT, type1, MPI_CHAR). إذن استدعاء لـ MPI_Type_create_struct(3, B, D, T, newtype) يعيد نوع بيانات مع خريطة النوع

{
 (float, 0), (float,4),             // 2 float
 (double, 16), (char, 24),          // 1 type1
 (char, 26), (char, 27), (char, 28) // 3 char
}

أي، نسختان من MPI_FLOAT تبدآن عند 0، متبوعتان بنسخة واحدة من type1 تبدأ عند 16، متبوعتان بثلاث نسخ من MPI_CHAR، تبدأ عند 26.

مثال 2:

مثال على هيكل مع بعض المكونات فقط كجزء من النوع

struct MyStruct {
    double x[2], y;
    char a;
    int n;
};
// إنشاء نوع جديد حيث نرسل فقط x، y و n
int B[] = {
    2, // 2 double
    1, // 1 double
    1, // 1 int
    1  // حشو المحاذاة
};
MPI_Aint D[] = {
    offsetof(struct MyStruct, x),
    offsetof(struct MyStruct, y),
    offsetof(struct MyStruct, n),
    sizeof(struct MyStruct)
};
MPI_Datatype T[] = {
    MPI_DOUBLE,
    MPI_DOUBLE,
    MPI_INT,
    MPI_UB
};
MPI_Datatype mpi_dt_mystruct;
MPI_Type_create_struct(4, B, D, T, &mpi_dt_mystruct);
MPI_Type_commit(&mpi_dt_mystruct);
// يمكننا الآن إرسال هيكل (باستثناء a)
struct MyStruct values[3];
if ( rank == 0 ) {
    // ... تهيئة values
    MPI_Send(values, 3, mpi_dt_mystruct, 1, 0, MPI_COMM_WORLD);
} else if ( rank == 1 ) {
    MPI_Recv(values, 3, mpi_dt_mystruct, 0, 0, MPI_COMM_WORLD, MPI_STATUS_IGNORE);
}

لمزيد من المعلومات، انظر القسم 5.1.2 من معيار MPI-4.0.

ملاحظات

إذا تم تعيين حد علوي صراحة باستخدام نوع بيانات MPI MPI_UB، فيجب أن يكون المؤشر المقابل موجبًا.

جعل معيار MPI-1 الأصلي تصريحات غامضة حول الحشو والمحاذاة؛ كان هذا مقصودًا للسماح بالتعريف البسيط للهياكل التي يمكن إرسالها مع عدد أكبر من واحد. على سبيل المثال،

struct {int a; char b;} foo;

قد يكون لها

sizeof(foo) = sizeof(int) + sizeof(char);

تعريف مدى نوع البيانات كشامل إبسيلون، والذي كان سيسمح للتنفيذ بجعل المدى لنوع بيانات MPI لهذا الهيكل مساويًا لـ 2*sizeof(int). ومع ذلك، نظرًا لأن الأنظمة المختلفة قد تحدد حشوًا مختلفًا، فقد تم تقديم توضيح للمعيار جعل الإبسيلون صفرًا. وبالتالي، إذا قمت بتعريف نوع بيانات هيكل وترغب في إرسال أو استقبال عناصر متعددة، يجب عليك بشكل صريح تضمين إدخال MPI_UB كآخر عضو في الهيكل. انظر المثال أعلاه.

الأخطاء

تقريبًا جميع روتينات MPI تعيد قيمة خطأ؛ روتينات C كنتيجة إرجاع للدالة وروتينات Fortran في الوسيط الأخير.

قبل إرجاع قيمة الخطأ، يتم استدعاء معالج الخطأ MPI الحالي المرتبط بكائن الاتصال (مثل، المخاطب، النافذة، الملف). إذا لم يكن هناك كائن اتصال مرتبط باستدعاء MPI، فيعتبر الاستدعاء مرتبطًا بـ MPI_COMM_SELF وسيتم استدعاء معالج الخطأ المرتبط به. عندما لا يتم تهيئة MPI_COMM_SELF (أي، قبل MPI_Init/MPI_Init_thread، بعد MPI_Finalize، أو عند استخدام نموذج الجلسات حصريًا) يثير الخطأ معالج الخطأ الأولي. يمكن تغيير معالج الخطأ الأولي عن طريق استدعاء MPI_Comm_set_errhandler على MPI_COMM_SELF عند استخدام نموذج العالم، أو الوسيط CLI mpi_initial_errhandler إلى mpiexec أو مفتاح معلومات إلى MPI_Comm_spawn/MPI_Comm_spawn_multiple. إذا لم يتم تعيين أي معالج خطأ مناسب آخر، فسيتم استدعاء معالج الخطأ MPI_ERRORS_RETURN لوظائف MPI I/O وسيتم استدعاء معالج الخطأ MPI_ERRORS_ABORT لجميع وظائف MPI الأخرى.

يتضمن Open MPI ثلاثة معالجات أخطاء محددة مسبقًا يمكن استخدامها:

  • MPI_ERRORS_ARE_FATAL يتسبب في إنهاء البرنامج لجميع عمليات MPI المتصلة.
  • MPI_ERRORS_ABORT معالج خطأ يمكن استدعاؤه على مخطب، نافذة، ملف، أو جلسة. عند استدعائه على مخطب، يعمل كما لو تم استدعاء MPI_Abort على هذا المخطب. إذا تم استدعاؤه على نافذة أو ملف، يعمل كما لو تم استدعاء MPI_Abort على مخطب يحتوي على مجموعة العمليات في النافذة أو الملف المقابل. إذا تم استدعاؤه على جلسة، فإنه ينهي العملية المحلية فقط.
  • MPI_ERRORS_RETURN يعيد رمز خطأ إلى التطبيق.

يمكن لتطبيقات MPI أيضًا تنفيذ معالجات الأخطاء الخاصة بها عن طريق استدعاء:

  • MPI_Comm_create_errhandler ثم MPI_Comm_set_errhandler
  • MPI_File_create_errhandler ثم MPI_File_set_errhandler
  • MPI_Session_create_errhandler ثم MPI_Session_set_errhandler أو عند MPI_Session_init
  • MPI_Win_create_errhandler ثم MPI_Win_set_errhandler

لاحظ أن MPI لا تضمن أن برنامج MPI يمكن أن يستمر بعد الخطأ.
