MPI_PROBE(3) Open MPI MPI_PROBE(3)

MPI_Probe — اختبار حظر للرسالة.

صيغة

صيغة C

#include <mpi.h>
int MPI_Probe(int source, int tag, MPI_Comm comm, MPI_Status *status)

صيغة Fortran

USE MPI
! أو الصيغة الأقدم: INCLUDE 'mpif.h'
MPI_PROBE(SOURCE, TAG, COMM, STATUS, IERROR)
     INTEGER SOURCE, TAG, COMM, STATUS(MPI_STATUS_SIZE), IERROR

صيغة Fortran 2008

USE mpi_f08
MPI_Probe(source, tag, comm, status, ierror)
     INTEGER, INTENT(IN) :: source, tag
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(MPI_Status) :: status
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

معاملات الإدخال

  • source: رتبة المصدر أو MPI_ANY_SOURCE (عدد صحيح).
  • tag: قيمة العلامة أو MPI_ANY_TAG (عدد صحيح).
  • comm: المراسِل (مقبض).

معاملات الإخراج

  • status: كائن الحالة (حالة).
  • ierror: Fortran فقط: حالة الخطأ (عدد صحيح).

الوصف

تسمح عمليتا MPI_Probe و MPI_Iprobe بفحص الرسائل الواردة، دون استلامها فعليًا. يمكن للمستخدم بعد ذلك تحديد كيفية استلامها، بناءً على المعلومات التي تم إرجاعها بواسطة الفحص في متغير الحالة. على سبيل المثال، قد يقوم المستخدم بتخصيص ذاكرة لمخزن الاستقبال المؤقت، وفقًا لطول الرسالة التي تم فحصها.

MPI_Probe تعمل مثل MPI_Iprobe باستثناء أنها مكالمة حظر تعود فقط بعد العثور على رسالة مطابقة.

إذا لم يكن تطبيقك بحاجة إلى فحص حقل status، فيمكنك توفير الموارد باستخدام الثابت المحدد مسبقًا MPI_STATUS_IGNORE كقيمة خاصة للمعامل status.

تضمن دلالات MPI_Probe و MPI_Iprobe التقدم: إذا تم إصدار استدعاء لـ MPI_Probe بواسطة عملية، وتم بدء إرسال يطابق الفحص بواسطة عملية ما، فسيعود استدعاء MPI_Probe، ما لم يتم استلام الرسالة بواسطة عملية استقبال متزامنة أخرى (يتم تنفيذها بواسطة خيط آخر في العملية الفاحصة). وبالمثل، إذا كانت عملية ما تنتظر بفحص ذاتي باستخدام MPI_Iprobe وتم إصدار رسالة مطابقة، فسيعود استدعاء MPI_Iprobe في النهاية flag = true ما لم يتم استلام الرسالة بواسطة عملية استقبال متزامنة أخرى.

المثال 1: استخدام فحص حظر للانتظار لرسالة واردة.

CALL MPI_COMM_RANK(comm, rank, ierr)
IF (rank == 0) THEN
   CALL MPI_SEND(i, 1, MPI_INTEGER, 2, 0, comm, ierr)
ELSE IF(rank == 1) THEN
   CALL MPI_SEND(x, 1, MPI_REAL, 2, 0, comm, ierr)
ELSE   ! rank == 2
   DO i=1, 2
      CALL MPI_PROBE(MPI_ANY_SOURCE, 0,
                     comm, status, ierr)
      IF (status(MPI_SOURCE) = 0) THEN
         CALL MPI_RECV(i, 1, MPI_INTEGER, 0, 0, status, ierr)
      ELSE
         CALL MPI_RECV(x, 1, MPI_REAL, 1, 0, status, ierr)
      END IF
   END DO
END IF

يتم استقبال كل رسالة بالنوع الصحيح.

المثال 2: برنامج مشابه للمثال السابق، ولكن مع مشكلة.

CALL MPI_COMM_RANK(comm, rank, ierr)
IF (rank == 0) THEN
   CALL MPI_SEND(i, 1, MPI_INTEGER, 2, 0, comm, ierr)
ELSE IF(rank == 1) THEN
   CALL MPI_SEND(x, 1, MPI_REAL, 2, 0, comm, ierr)
ELSE
   DO i=1, 2
      CALL MPI_PROBE(MPI_ANY_SOURCE, 0,
                     comm, status, ierr)
      IF (status(MPI_SOURCE) == 0) THEN
         CALL MPI_RECV(i, 1, MPI_INTEGER, MPI_ANY_SOURCE, &
                       0, status, ierr)
      ELSE
         CALL MPI_RECV(x, 1, MPI_REAL, MPI_ANY_SOURCE, &
                       0, status, ierr)
      END IF
   END DO
END IF

لقد عدلنا المثال 2 قليلاً، باستخدام MPI_ANY_SOURCE كمعامل المصدر في مكالمتي الاستقبال في الأسطر المسماة 100 و 200. البرنامج الآن غير صحيح: قد تقوم عملية الاستقبال باستقبال رسالة تختلف عن الرسالة التي تم فحصها بواسطة المكالمة السابقة لـ MPI_Probe.

الأخطاء

تقوم جميع روتينات MPI تقريبًا بإرجاع قيمة خطأ؛ روتينات C كنتيجة إرجاع للدالة وروتينات Fortran في المعامل الأخير.

قبل إرجاع قيمة الخطأ، يتم استدعاء معالج أخطاء MPI الحالي المرتبط بكائن الاتصال (على سبيل المثال، المراسل، النافذة، الملف). إذا لم يكن هناك كائن اتصال مرتبط بمكالمة MPI، فسيتم اعتبار المكالمة مرتبطة بـ MPI_COMM_SELF وسيتم استدعاء معالج أخطاء MPI المرتبط. عندما لا يتم تهيئة MPI_COMM_SELF (أي، قبل MPI_Init/MPI_Init_thread، بعد MPI_Finalize، أو عند استخدام نموذج الجلسات حصريًا) يثير الخطأ معالج الأخطاء الأولي. يمكن تغيير معالج الأخطاء الأولي عن طريق استدعاء MPI_Comm_set_errhandler على MPI_COMM_SELF عند استخدام نموذج العالم، أو وسيطة سطر الأوامر mpi_initial_errhandler إلى mpiexec أو مفتاح المعلومات إلى MPI_Comm_spawn/MPI_Comm_spawn_multiple. إذا لم يتم تعيين أي معالج أخطاء مناسب آخر، فسيتم استدعاء معالج أخطاء MPI_ERRORS_RETURN لوظائف MPI I/O وسيتم استدعاء معالج أخطاء MPI_ERRORS_ABORT لجميع وظائف MPI الأخرى.

يشمل Open MPI ثلاثة معالجات أخطاء محددة مسبقًا يمكن استخدامها:

  • MPI_ERRORS_ARE_FATAL يتسبب في إنهاء البرنامج لجميع عمليات MPI المتصلة.
  • MPI_ERRORS_ABORT معالج خطأ يمكن استدعاؤه على مراسل، نافذة، ملف، أو جلسة. عند استدعائه على مراسل، يعمل كما لو تم استدعاء MPI_Abort على هذا المراسل. عند استدعائه على نافذة أو ملف، يعمل كما لو تم استدعاء MPI_Abort على مجموعة من العمليات في النافذة أو الملف المقابل. عند استدعائه على جلسة، يقوم فقط بإنهاء العملية المحلية.
  • MPI_ERRORS_RETURN يعيد رمز خطأ إلى التطبيق.

يمكن لتطبيقات MPI أيضًا تنفيذ معالجات الأخطاء الخاصة بها عن طريق استدعاء:

  • MPI_Comm_create_errhandler ثم MPI_Comm_set_errhandler
  • MPI_File_create_errhandler ثم MPI_File_set_errhandler
  • MPI_Session_create_errhandler ثم MPI_Session_set_errhandler أو في MPI_Session_init
  • MPI_Win_create_errhandler ثم MPI_Win_set_errhandler

لاحظ أن MPI لا تضمن أن برنامج MPI يمكن أن يستمر بعد خطأ.

راجع صفحة دليل MPI للحصول على قائمة كاملة بـ رموز أخطاء MPI.

راجع قسم معالجة الأخطاء في معيار MPI-3.1 لمزيد من المعلومات.

لاحظ أنه وفقًا لقسم "حالة الإرجاع" في فصل "الاتصال من نقطة إلى نقطة" في معيار MPI، فإن أخطاء MPI على الرسائل التي يتم الاستعلام عنها بواسطة MPI_Probe لا تعيين حقل status.MPI_ERROR في status المُعاد. يتم دائمًا تمرير رمز الخطأ إلى معالج الخطأ الخلفي وقد يتم إعادته إلى المتصل من خلال قيمة الإرجاع لـ MPI_Probe إذا أعاده معالج الخطأ الخلفي. معالج الخطأ المحدد مسبقًا MPI MPI_ERRORS_RETURN يعرض هذا السلوك، على سبيل المثال.
