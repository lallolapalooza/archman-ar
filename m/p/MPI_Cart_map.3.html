MPI_Cart_map(3)

الحزمة: openmpi

التراخيص: BSD-3-Clause AND LicenseRef-MPICH

MPI_CART_MAP(3) Open MPI MPI_CART_MAP(3)

MPI_Cart_map — يقوم بربط العملية بمعلومات الهيكل الديكارتي.

الصيغة

صيغة C

#include <mpi.h>
int MPI_Cart_map(MPI_Comm comm, int ndims, const int dims[],
    const int periods[], int *newrank)

صيغة Fortran

USE MPI
! أو الصيغة القديمة: INCLUDE 'mpif.h'
MPI_CART_MAP(COMM, NDIMS, DIMS, PERIODS, NEWRANK, IERROR)
    INTEGER COMM, NDIMS, DIMS(*), NEWRANK, IERROR
    LOGICAL PERIODS(*)

صيغة Fortran 2008

USE mpi_f08
MPI_Cart_map(comm, ndims, dims, periods, newrank, ierror)
    TYPE(MPI_Comm), INTENT(IN) :: comm
    INTEGER, INTENT(IN) :: ndims, dims(ndims)
    LOGICAL, INTENT(IN) :: periods(ndims)
    INTEGER, INTENT(OUT) :: newrank
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror

معلمات الإدخال

  • comm : الاتصال المدخل (مقبض).
  • ndims : عدد أبعاد الهيكل الديكارتي (عدد صحيح).
dims
مصفوفة أعداد صحيحة بحجم ndims تحدد عدد العمليات في كل اتجاه إحداثي.
•
periods
مصفوفة منطقية بحجم ndims تحدد مواصفات الدورية في كل اتجاه إحداثي.

معلمات الإخراج

•
newrank
ترتيب معاد تصنيفه للعملية المستدعية؛ MPI_UNDEFINED إذا كانت العملية المستدعية لا تنتمي إلى الشبكة (عدد صحيح).
•
ierror : Fortran فقط: حالة الخطأ (عدد صحيح).

الوصف

يمكن استخدام MPI_Cart_map و MPI_Graph_map لتنفيذ جميع وظائف الهيكل الأخرى. بشكل عام، لن يتم استدعاؤهما مباشرة من قبل المستخدم، ما لم يكن هو أو هي يقوم بإنشاء إمكانات هيكل افتراضية إضافية بخلاف تلك التي توفرها MPI. MPI_Cart_map يحسب وضعًا "أمثل" للعملية المستدعية على الجهاز المادي. يمكن أن يتمثل أحد التطبيقات الممكنة لهذه الوظيفة في إعادة الترتيب دائمًا لترتيب العملية المستدعية، أي عدم إجراء أي إعادة ترتيب.

الأخطاء

تقوم جميع روتينات MPI تقريبًا بإرجاع قيمة خطأ؛ روتينات C كالنتيجة الإرجاعية للدالة، وروتينات Fortran في الوسيطة الأخيرة.

قبل إرجاع قيمة الخطأ، يتم استدعاء معالج أخطاء MPI الحالي المرتبط بكائن الاتصال (مثل، متصل، نافذة، ملف). إذا لم يكن هناك كائن اتصال مرتبط باستدعاء MPI، فسيتم اعتبار الاستدعاء مرتبطًا بـ MPI_COMM_SELF وسيستدعي معالج أخطاء MPI المرتبط. عندما لا تتم تهيئة MPI_COMM_SELF (أي، قبل MPI_Init/MPI_Init_thread، بعد MPI_Finalize، أو عند استخدام نموذج الجلسات حصريًا) يثير الخطأ معالج الأخطاء الأولي. يمكن تغيير معالج الأخطاء الأولي عن طريق استدعاء MPI_Comm_set_errhandler على MPI_COMM_SELF عند استخدام نموذج World، أو الوسيطة CLI mpi_initial_errhandler إلى mpiexec أو مفتاح المعلومات إلى MPI_Comm_spawn/MPI_Comm_spawn_multiple. إذا لم يتم تعيين معالج خطأ مناسب آخر، فسيتم استدعاء معالج الأخطاء MPI_ERRORS_RETURN لوظائف I/O لـ MPI، وسيتم استدعاء معالج الأخطاء MPI_ERRORS_ABORT لجميع وظائف MPI الأخرى.

يتضمن Open MPI ثلاثة معالجات أخطاء محددة مسبقًا يمكن استخدامها:

  • MPI_ERRORS_ARE_FATAL يتسبب في إنهاء البرنامج لجميع عمليات MPI المتصلة.
  • MPI_ERRORS_ABORT معالج خطأ يمكن استدعاؤه على متصل، نافذة، ملف، أو جلسة. عند استدعائه على متصل، فإنه يعمل كما لو تم استدعاء MPI_Abort على هذا المتصل. عند استدعائه على نافذة أو ملف، فإنه يعمل كما لو تم استدعاء MPI_Abort على متصل يحتوي على مجموعة العمليات في النافذة أو الملف المقابل. عند استدعائه على جلسة، فإنه ينهي العملية المحلية فقط.
  • MPI_ERRORS_RETURN يعيد رمز خطأ إلى التطبيق.

يمكن لتطبيقات MPI أيضًا تنفيذ معالجات الأخطاء الخاصة بها عن طريق الاستدعاء:

  • MPI_Comm_create_errhandler ثم MPI_Comm_set_errhandler
  • MPI_File_create_errhandler ثم MPI_File_set_errhandler
  • MPI_Session_create_errhandler ثم MPI_Session_set_errhandler أو عند MPI_Session_init
  • MPI_Win_create_errhandler ثم MPI_Win_set_errhandler

لاحظ أن MPI لا يضمن أن برنامج MPI يمكن أن يستمر بعد حدوث خطأ.
