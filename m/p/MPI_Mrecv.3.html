MPI_Mrecv(3)

الحزمة: openmpi

التراخيص: BSD-3-Clause AND LicenseRef-MPICH

MPI_MRECV(3) Open MPI MPI_MRECV(3)

MPI_Mrecv — استقبال مُحاصِر لرسالة مُطابقة

الصيغة

صيغة C

#include <mpi.h>
int MPI_Mrecv(void *buf, int count, MPI_Datatype type,
     MPI_Message *message, MPI_Status *status)

صيغة Fortran

USE MPI
! أو الشكل القديم: INCLUDE 'mpif.h'
MPI_MRECV(BUF, COUNT, DATATYPE, MESSAGE, STATUS, IERROR)
     <type>  BUF(*)
     INTEGER COUNT, DATATYPE, MESSAGE
     INTEGER STATUS(MPI_STATUS_SIZE), IERROR

صيغة Fortran 2008

USE mpi_f08
MPI_Mrecv(buf, count, datatype, message, status, ierror)
     TYPE(*), DIMENSION(..) :: buf
     INTEGER, INTENT(IN) :: count
     TYPE(MPI_Datatype), INTENT(IN) :: datatype
     TYPE(MPI_Message), INTENT(INOUT) :: message
     TYPE(MPI_Status) :: status
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

معلمات الإدخال

  • count: عدد العناصر المراد استقبالها (عدد صحيح غير سالب).
  • datatype: نوع بيانات كل عنصر في مخزن الإرسال (مقبض).
  • message: الرسالة (مقبض).

معلمات الإخراج

  • buf: العنوان الأولي لمخزن الاستقبال (اختياري).
  • status: كائن الحالة (حالة).
  • ierror: Fortran فقط: حالة الخطأ (عدد صحيح).

الوصف

تقوم الدوال MPI_Mrecv و MPI_Imrecv باستقبال الرسائل التي تم مطابقتها مسبقًا بواسطة استعلام مطابق.

إذا تم استدعاء MPI_Mrecv باستخدام MPI_MESSAGE_NULL كوسيط الرسالة، فإن الاستدعاء يعود فورًا مع تعيين كائن status إلى source = MPI_PROC_NULL، tag = MPI_ANY_TAG، و count = 0، كما لو تم إصدار استقبال من MPI_PROC_NULL.

إذا لم يكن تطبيقك بحاجة إلى فحص حقل status، يمكنك توفير الموارد باستخدام الثابت المُعرّف مسبقًا MPI_STATUS_IGNORE كقيمة خاصة لوسيط status.

الأخطاء

تقوم جميع روتينات MPI تقريبًا بإرجاع قيمة خطأ؛ روتينات C كنتيجة إرجاع للدالة وروتينات Fortran في الوسيط الأخير.

قبل إرجاع قيمة الخطأ، يتم استدعاء معالج خطأ MPI الحالي المرتبط بائنية الاتصال (مثل، التواصل، النافذة، الملف). إذا لم تكن هناك بائنية اتصال مرتبطة باستدعاء MPI، فسيتم اعتبار الاستدعاء مرتبطًا بـ MPI_COMM_SELF وسيتم استدعاء معالج خطأ MPI المرتبط. عندما لا يتم تهيئة MPI_COMM_SELF (أي، قبل MPI_Init/MPI_Init_thread، بعد MPI_Finalize، أو عند استخدام نموذج الجلسات حصريًا)، يثير الخطأ معالج الخطأ الأولي. يمكن تغيير معالج الخطأ الأولي عن طريق استدعاء MPI_Comm_set_errhandler على MPI_COMM_SELF عند استخدام نموذج World، أو وسيط سطر الأوامر mpi_initial_errhandler الخاص بـ mpiexec أو مفتاح info الخاص بـ MPI_Comm_spawn/MPI_Comm_spawn_multiple. إذا لم يتم تعيين معالج خطأ مناسب آخر، فسيتم استدعاء معالج الخطأ MPI_ERRORS_RETURN لوظائف MPI I/O وسيتم استدعاء معالج الخطأ MPI_ERRORS_ABORT لجميع وظائف MPI الأخرى.

تتضمن Open MPI ثلاثة معالجات خطأ مُعرّفة مسبقًا يمكن استخدامها:

  • MPI_ERRORS_ARE_FATAL يتسبب في إنهاء البرنامج لجميع عمليات MPI المتصلة.
  • MPI_ERRORS_ABORT معالج خطأ يمكن استدعاؤه على مصل، نافذة، ملف، أو جلسة. عند استدعائه على مصل، يتصرف كما لو تم استدعاء MPI_Abort على هذا المصل. عند استدعائه على نافذة أو ملف، يتصرف كما لو تم استدعاء MPI_Abort على مصل يحتوي على مجموعة العمليات في النافذة أو الملف المقابلة. عند استدعائه على جلسة، ينهي العملية المحلية فقط.
  • MPI_ERRORS_RETURN يعيد رمز خطأ إلى التطبيق.

يمكن لتطبيقات MPI أيضًا تنفيذ معالجات الخطأ الخاصة بها عن طريق استدعاء:

  • MPI_Comm_create_errhandler ثم MPI_Comm_set_errhandler
  • MPI_File_create_errhandler ثم MPI_File_set_errhandler
  • MPI_Session_create_errhandler ثم MPI_Session_set_errhandler أو عند MPI_Session_init
  • MPI_Win_create_errhandler ثم MPI_Win_set_errhandler

لاحظ أن MPI لا يضمن أن برنامج MPI يمكن أن يستمر بعد حدوث خطأ.

راجع صفحة دليل MPI للحصول على قائمة كاملة بـ أكواد خطأ MPI.

راجع قسم معالجة الأخطاء في معيار MPI-3.1 لمزيد من المعلومات.

لاحظ أنه وفقًا للقسم "حالة الإرجاع" في فصل "الاتصالات نقطة إلى نقطة" في معيار MPI، فإن أخطاء MPI على الرسائل المستلمة بواسطة MPI_Mrecv لا تقوم بتعيين الحقل status.MPI_ERROR في status المُعاد. يتم دائمًا تمرير رمز الخطأ إلى معالج الخطأ الخلفي وقد يتم تمريره مرة أخرى إلى المستدعي من خلال قيمة إرجاع MPI_Mrecv إذا قام معالج الخطأ الخلفي بإرجاعه. معالج الخطأ المُعرّف مسبقًا MPI MPI_ERRORS_RETURN يعرض هذا السلوك، على سبيل المثال.
