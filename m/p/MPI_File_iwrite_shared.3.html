MPI_File_iwrite_shared(3)

الحزمة: openmpi

التراخيص: BSD-3-Clause AND LicenseRef-MPICH

MPI_FILE_IWRITE_SHARED(3) Open MPI MPI_FILE_IWRITE_SHARED(3)

MPI_File_iwrite_shared — يكتب ملفًا باستخدام المؤشر المشترك للملف (غير متزامن، غير جماعي).

الصيغة

صيغة C

#include <mpi.h>
int MPI_File_iwrite_shared(MPI_File fh, const void *buf, int count, MPI_Datatype
     datatype, MPI_Request *request)

صيغة Fortran

USE MPI
! أو الصيغة القديمة: INCLUDE 'mpif.h'
MPI_FILE_IWRITE_SHARED(FH, BUF, COUNT, DATATYPE, REQUEST, IERROR)
     <type>  BUF(*)
     INTEGER FH, COUNT, DATATYPE, REQUEST, IERROR

صيغة Fortran 2008

USE mpi_f08
MPI_File_iwrite_shared(fh, buf, count, datatype, request, ierror)
     TYPE(MPI_File), INTENT(IN) :: fh
     TYPE(*), DIMENSION(..), INTENT(IN), ASYNCHRONOUS :: buf
     INTEGER, INTENT(IN) :: count
     TYPE(MPI_Datatype), INTENT(IN) :: datatype
     TYPE(MPI_Request), INTENT(OUT) :: request
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

معامل الإدخال/الإخراج

•
fh: مقبض الملف (handle).

معاملات الإدخال

  • count: عدد العناصر في المخزن المؤقت (عدد صحيح).
  • datatype: نوع بيانات كل عنصر في المخزن المؤقت (handle).

معاملات الإخراج

  • buf: العنوان الأولي للمخزن المؤقت (choice).
  • request: كائن الطلب (handle).
  • ierror: Fortran فقط: حالة الخطأ (عدد صحيح).

الوصف

MPI_File_iwrite_shared هي روتين غير متزامن تستخدم المؤشر المشترك للملف لكتابة الملفات. ترتيب التسلسل غير محدد لهذا الروتين غير الجماعي، لذا تحتاج إلى استخدام طرق أخرى للمزامنة لفرض ترتيب معين.

الأخطاء

تقوم جميع روتينات MPI تقريبًا بإرجاع قيمة خطأ؛ روتينات C كنتيجة إرجاع للدالة وروتينات Fortran في الوسيط الأخير.

قبل إرجاع قيمة الخطأ، يتم استدعاء معالج أخطاء MPI الحالي المرتبط بكائن الاتصال (مثل، المتصل، النافذة، الملف). إذا لم يكن هناك كائن اتصال مرتبط باستدعاء MPI، يعتبر الاستدعاء مرتبطًا بـ MPI_COMM_SELF وسيتم استدعاء معالج الأخطاء المرتبط.

عندما لا يتم تهيئة MPI_COMM_SELF (أي، قبل MPI_Init/MPI_Init_thread، بعد MPI_Finalize، أو عند استخدام نموذج الجلسات حصريًا)، يثير الخطأ معالج الأخطاء الأولي.

يمكن تغيير معالج الأخطاء الأولي عن طريق استدعاء MPI_Comm_set_errhandler على MPI_COMM_SELF عند استخدام نموذج العالم، أو الوسيط CLI mpi_initial_errhandler إلى mpiexec أو مفتاح المعلومات إلى MPI_Comm_spawn/MPI_Comm_spawn_multiple. إذا لم يتم تعيين أي معالج أخطاء مناسب آخر، فسيتم استدعاء معالج الأخطاء MPI_ERRORS_RETURN لوظائف MPI I/O وسيتم استدعاء معالج الأخطاء MPI_ERRORS_ABORT لجميع وظائف MPI الأخرى.

يتضمن Open MPI ثلاثة معالجات أخطاء محددة مسبقًا يمكن استخدامها:

  • MPI_ERRORS_ARE_FATAL يتسبب في إنهاء البرنامج لجميع عمليات MPI المتصلة.
  • MPI_ERRORS_ABORT معالج أخطاء يمكن استدعاؤه على متصل، نافذة، ملف، أو جلسة. عند استدعاؤه على متصل، يتصرف كما لو تم استدعاء MPI_Abort على هذا المتصل. عند استدعاؤه على نافذة أو ملف، يتصرف كما لو تم استدعاء MPI_Abort على متصل يحتوي على مجموعة العمليات في النافذة أو الملف المقابل. عند استدعاؤه على جلسة، ينهي العملية المحلية فقط.
  • MPI_ERRORS_RETURN يعيد رمز خطأ إلى التطبيق.

يمكن لتطبيقات MPI أيضًا تنفيذ معالجات الأخطاء الخاصة بها عن طريق استدعاء:

  • MPI_Comm_create_errhandler ثم MPI_Comm_set_errhandler
  • MPI_File_create_errhandler ثم MPI_File_set_errhandler
  • MPI_Session_create_errhandler ثم MPI_Session_set_errhandler أو عند MPI_Session_init
  • MPI_Win_create_errhandler ثم MPI_Win_set_errhandler

لاحظ أن MPI لا تضمن أن برنامج MPI يمكنه الاستمرار بعد حدوث خطأ.

انظر قسم معالجة الأخطاء من معيار MPI-3.1 لمزيد من المعلومات.
