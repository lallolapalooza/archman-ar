MPI_File_read_at_all_begin(3)

الحزمة: openmpi

التراخيص: BSD-3-Clause AND LicenseRef-MPICH

MPI_FILE_READ_AT_ALL_BEGIN(3) Open MPI MPI_FILE_READ_AT_ALL_BEGIN(3)

MPI_File_read_at_all_begin — يقرأ ملفًا في مواضع محددة بوضوح؛ الجزء الأول من روتين تجميعي مقسم (غير متزامن).

الصيغة (SYNTAX)

صيغة C (C Syntax)

#include <mpi.h>
int MPI_File_read_at_all_begin(MPI_File fh, MPI_Offset
     offset, void *buf, int count, MPI_Datatype
     datatype)

صيغة Fortran (Fortran Syntax)

USE MPI
! أو الشكل الأقدم: INCLUDE 'mpif.h'
MPI_FILE_READ_AT_ALL_BEGIN(FH, OFFSET, BUF,
     COUNT, DATATYPE, IERROR)
     <type>  BUF(*)
     INTEGER FH, COUNT, DATATYPE, IERROR
     INTEGER(KIND=MPI_OFFSET_KIND)   OFFSET

صيغة Fortran 2008 (Fortran 2008 Syntax)

USE mpi_f08
MPI_File_read_at_all_begin(fh, offset, buf, count, datatype, ierror)
     TYPE(MPI_File), INTENT(IN) :: fh
     INTEGER(KIND=MPI_OFFSET_KIND), INTENT(IN) :: offset
     TYPE(*), DIMENSION(..), ASYNCHRONOUS :: buf
     INTEGER, INTENT(IN) :: count
     TYPE(MPI_Datatype), INTENT(IN) :: datatype
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

معاملات الإدخال (INPUT PARAMETERS)

  • fh: مقبض الملف (File handle).
  • offset: موضع الملف (File offset) (عدد صحيح).
  • count: عدد العناصر في المخزن المؤقت (Number of elements in buffer) (عدد صحيح).
  • datatype: نوع بيانات كل عنصر من المخزن المؤقت.

معاملات الإخراج (OUTPUT PARAMETERS)

  • buf: العنوان الأولي للمخزن المؤقت (Initial address of buffer) (اختياري).
  • ierror: Fortran فقط: حالة الخطأ (Error status) (عدد صحيح).

الوصف (DESCRIPTION)

MPI_File_read_at_all_begin هو الجزء الأول من روتين تجميعي مقسم يحاول القراءة من الملف المرتبط بـ fh (في الموضع offset) لعدد إجمالي قدره count من عناصر البيانات من نوع datatype إلى المخزن المؤقت للمستخدم buf. الموضع offset بوحدات etype بالنسبة للعرض الحالي. أي، لا يتم احتساب الثقوب عند تحديد موضع. يتم استخلاص البيانات من الأجزاء التي يحددها العرض الحالي للملف.

ملاحظات (NOTES)

جميع روتينات الوصول للبيانات غير المتزامنة الجماعية "مقسمة" إلى روتينين، كل منهما بلاحقة _begin أو _end. تخضع هذه الروتينات الجماعية المقسمة للقواعد الدلالية الموضحة في القسم 9.4.5 من معيار MPI-2.

الأخطاء (ERRORS)

تقريبًا جميع روتينات MPI ترجع قيمة خطأ؛ روتينات C كالنتيجة المرجعة للدالة وروتينات Fortran في المعامل الأخير.

قبل إرجاع قيمة الخطأ، يتم استدعاء معالج الخطأ MPI الحالي المرتبط بكائن الاتصال (مثل، المراسل، النافذة، الملف). إذا لم يكن هناك كائن اتصال مرتبط باستدعاء MPI، فيعتبر الاستدعاء مرتبطًا بـ MPI_COMM_SELF وسيستدعي معالج الخطأ MPI المرتبط. عند عدم تهيئة MPI_COMM_SELF (أي، قبل MPI_Init/MPI_Init_thread، بعد MPI_Finalize، أو عند استخدام نموذج الجلسات حصريًا) يثير الخطأ معالج الخطأ الأولي. يمكن تغيير معالج الخطأ الأولي عن طريق استدعاء MPI_Comm_set_errhandler على MPI_COMM_SELF عند استخدام نموذج العالم، أو وسيطة سطر الأوامر mpi_initial_errhandler لـ mpiexec أو مفتاح المعلومات لـ MPI_Comm_spawn/MPI_Comm_spawn_multiple. إذا لم يتم تعيين أي معالج خطأ مناسب آخر، فسيتم استدعاء معالج الخطأ MPI_ERRORS_RETURN لوظائف MPI I/O وسيتم استدعاء معالج الخطأ MPI_ERRORS_ABORT لجميع وظائف MPI الأخرى.

تتضمن Open MPI ثلاثة معالجات خطأ معرفة مسبقًا يمكن استخدامها:

  • MPI_ERRORS_ARE_FATAL يؤدي إلى إنهاء البرنامج لجميع عمليات MPI المتصلة.
  • MPI_ERRORS_ABORT معالج خطأ يمكن استدعاؤه على مراسل، نافذة، ملف، أو جلسة. عند استدعائه على مراسل، يتصرف كما لو تم استدعاء MPI_Abort على هذا المراسل. عند استدعائه على نافذة أو ملف، يتصرف كما لو تم استدعاء MPI_Abort على مراسل يحتوي على مجموعة العمليات في النافذة أو الملف المقابل. عند استدعائه على جلسة، يقوم بإنهاء العملية المحلية فقط.
  • MPI_ERRORS_RETURN يرجع رمز خطأ إلى التطبيق.

يمكن لتطبيقات MPI أيضًا تنفيذ معالجات الخطأ الخاصة بها عن طريق استدعاء:

  • MPI_Comm_create_errhandler ثم MPI_Comm_set_errhandler
  • MPI_File_create_errhandler ثم MPI_File_set_errhandler
  • MPI_Session_create_errhandler ثم MPI_Session_set_errhandler أو عند MPI_Session_init
  • MPI_Win_create_errhandler ثم MPI_Win_set_errhandler

لاحظ أن MPI لا تضمن أن برنامج MPI يمكن أن يستمر بعد حدوث خطأ.
