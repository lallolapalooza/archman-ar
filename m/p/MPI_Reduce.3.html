MPI_Reduce(3) Open MPI MPI_Reduce(3)

MPI_Reduce، MPI_Ireduce، MPI_Reduce_init — تقليل القيم في جميع العمليات داخل مجموعة.

الصيغة

صيغة C

#include <mpi.h>
int MPI_Reduce(const void *sendbuf, void *recvbuf, int count,
               MPI_Datatype datatype, MPI_Op op, int root,
               MPI_Comm comm)
int MPI_Ireduce(const void *sendbuf, void *recvbuf, int count,
                MPI_Datatype datatype, MPI_Op op, int root,
                MPI_Comm comm, MPI_Request *request)
int MPI_Reduce_init(const void *sendbuf, void *recvbuf, int count,
                MPI_Datatype datatype, MPI_Op op, int root,
                MPI_Comm comm, MPI_Info info, MPI_Request *request)

معلمات الإدخال

  • sendbuf: عنوان مخزن الإرسال (اختياري).
  • count: عدد العناصر في مخزن الإرسال (عدد صحيح).
  • datatype: نوع بيانات عناصر مخزن الإرسال (مقبض).
  • op: عملية التقليل (مقبض).
  • root: العملية الفريدة للمجموعة (عدد صحيح).
  • comm: المتصل (مقبض).
  • info: المعلومات (مقبض، مستمر).

معلمات الإخراج

  • recvbuf: عنوان مخزن الاستقبال (اختياري، ذو مغزى فقط في العملية ذات الرتبة الجذرية).
  • request: الطلب (مقبض، غير مانع).
  • ierror: في Fortran فقط: حالة الخطأ (عدد صحيح).

الوصف

تقوم وظائف التقليل الشاملة (MPI_Reduce، MPI_Op_create، MPI_Op_free، MPI_Allreduce، MPI_Reduce_scatter، MPI_Scan) بإجراء عملية تقليل شاملة (مثل الجمع، الحد الأقصى، AND المنطقي، إلخ) بين جميع أعضاء المجموعة. يمكن أن تكون عملية التقليل واحدة من قائمة معرفة مسبقًا من العمليات أو عملية معرفة من قبل المستخدم. تأتي وظائف التقليل الشاملة في أنماط مختلفة: واحدة تعيد نتيجة التقليل في عقدة واحدة، وواحدة تعيد هذه النتيجة في جميع العقد، وعملية مسح (عملية بادئة متوازية). بالإضافة إلى ذلك، تجمع عملية تقليل-مسح بين وظائف التقليل والمسح.

تجمع MPI_Reduce العناصر المقدمة في مخزن الإدخال لكل عملية في المجموعة باستخدام العملية op وتعيد القيمة المجمعة في مخزن الإخراج للعملية ذات الرتبة الجذرية. يتم تعريف مخزن الإدخال بواسطة وسيطات sendbuf و count و datatype؛ يتم تعريف مخزن الإخراج بواسطة وسيطات recvbuf و count و datatype؛ كلاهما لهما نفس عدد العناصر، بنفس النوع. يتم استدعاء الروتين من قبل جميع أعضاء المجموعة باستخدام نفس الوسيطات لـ count و datatype و op و root و comm. لذلك، توفر جميع العمليات مخازن إدخال وإخراج بنفس الطول، بعناصر من نفس النوع. يمكن لكل عملية توفير عنصر واحد أو تسلسل من العناصر، والتي يتم عليها تطبيق عملية الدمج عنصرًا بعنصر على كل إدخال في التسلسل. على سبيل المثال، إذا كانت العملية هي MPI_MAX وكان مخزن الإرسال يحتوي على عنصرين عبارة عن أرقام عشرية (count = 2 و datatype = MPI_FLOAT)، فإن recvbuf(1) = الحد الأقصى الشامل (sendbuf(1)) و recvbuf(2) = الحد الأقصى الشامل (sendbuf(2)).

استخدام خيار الإدخال في المكان

عندما يكون المتصل متصلًا داخليًا، يمكنك إجراء عملية تقليل بدلاً من (يتم استخدام مخزن الاستقبال كمخزن للإرسال). استخدم القيمة MPI_IN_PLACE كقيمة لـ sendbuf للعملية ذات الرتبة الجذرية. في هذه الحالة، يتم أخذ بيانات الإدخال من مخزن الاستقبال في العملية ذات الرتبة الجذرية، حيث سيتم استبدالها ببيانات الإخراج.

ملاحظة: MPI_IN_PLACE هو نوع خاص؛ له نفس قيود الاستخدام مثل MPI_BOTTOM.

نظرًا لأن خيار الإدخال في المكان يحول مخزن الاستقبال إلى مخزن إرسال واستقبال، فإن ربط Fortran الذي يتضمن INTENT يجب أن يضع علامة عليه على أنه INOUT، وليس OUT.

عندما يكون المتصل متصلًا خارجيًا

عندما يكون المتصل متصلًا خارجيًا، تجمع العملية ذات الرتبة الجذرية للمجموعة الأولى بيانات من جميع العمليات في المجموعة الثانية ثم تقوم بتطبيق العملية op. تحدد المجموعة الأولى العملية ذات الرتبة الجذرية. تستخدم هذه العملية MPI_ROOT كقيمة لوسيطتها root. تستخدم العمليات المتبقية MPI_PROC_NULL كقيمة لوسيطتها root. تستخدم جميع عمليات المجموعة الثانية رتبة العملية ذات الرتبة الجذرية للمجموعة الأولى كقيمة لوسيطتها root. فقط وسيطات sendbuf في المجموعة الثانية ذات مغزى، وفقط وسيطات recvbuf في العملية ذات الرتبة الجذرية للمجموعة الأولى ذات مغزى.

عمليات التقليل المعرفة مسبقًا

يتم سرد قائمة العمليات المعرفة مسبقًا التي يوفرها MPI أدناه (عمليات التقليل المعرفة مسبقًا). يسرد هذا القسم أيضًا أنواع البيانات التي يمكن تطبيق كل عملية عليها. بالإضافة إلى ذلك، يمكن للمستخدمين تعريف عملياتهم الخاصة التي يمكن تجاوزها للعمل على أنواع بيانات متعددة، أساسية أو مشتقة. يتم شرح هذا بشكل أكبر في وصف العمليات المعرفة من قبل المستخدم (انظر صفحات الدليل لـ MPI_Op_create و MPI_Op_free).

يفترض دائمًا أن العملية op تجميعية. جميع العمليات المعرفة مسبقًا تعتبر أيضًا تجميعية. يمكن للمستخدمين تعريف عمليات تجميعية مفترضة، على الرغم من أنها ليست تبادلية. يتم تحديد ترتيب التقييم القانوني للتقليل حسب رتب العمليات في المجموعة. ومع ذلك، يمكن للتنفيذ الاستفادة من التجميعية أو التجميعية والتبادلية لتغيير ترتيب التقييم. هذا قد يغير نتيجة التقليل للعمليات غير التجميعية والتبادلية بشكل صارم، مثل إضافة الأرقام العشرية.

تعمل العمليات المعرفة مسبقًا فقط مع أنواع MPI المدرجة أدناه (عمليات التقليل المعرفة مسبقًا، وقسم MINLOC و MAXLOC، أدناه). يمكن أن تعمل العمليات المعرفة من قبل المستخدم على أنواع بيانات عامة ومشتقة. في هذه الحالة، كل وسيط تطبق عملية التقليل عليه هو عنصر موصوف بهذا النوع من البيانات، والذي يمكن أن يكون أحد عمليات التقليل. القيمة الناتجة هي نتيجة عملية التقليل المطبقة على كل عنصر.

MPI_Reduce October 30, 2025 MPI_Reduce(3) MPI
SYNTAX int MPI_Reduce(const void *sendbuf, void *recvbuf, int count, MPI_Datatype datatype, MPI_Op op, int root, MPI_Comm comm)
INPUT PARAMETERS sendbuf start of the send buffer (choice) count number of elements in buffer (non-negative integer) datatype datatype of elements in buffer (handle) op reduce operation (handle) root rank of root process (integer) comm communicator (handle)
OUTPUT PARAMETERS recvbuf start of the receive buffer (choice)
DESCRIPTION

MPI_Reduce performs a reduction operation on all data from all processes in a communicator and places the result on the root process.

All processes in the communicator comm participate in the operation. Each process provides a buffer sendbuf containing data to be sent to the root process. The root process receives data from all other processes. All processes must provide the same value of count, datatype, op, root, and comm.

The result is formed by applying the reduction operation op element by element to the data provided by all processes. For example, if op is MPI_SUM, then for each element i in the range [0, count-1], the root process will receive the sum of the i-th element from all processes.

The reduction operation is associative. If the operation is not commutative, the order of operations is determined by the ranks of the processes. Specifically, the data from process i is combined with the data from process j in an order determined by i and j.

The root process places the result in recvbuf. All other processes must provide a valid buffer for recvbuf if count is greater than 0. The contents of recvbuf on the non-root processes are undefined.

If root is the rank of the calling process, then recvbuf must be of the same type and length as sendbuf. The root process will receive the reduced values from all processes, including itself.

If sendbuf is specified as MPI_IN_PLACE on the root process, then the root process's send buffer is used for the receive buffer. The data is taken from the root process's sendbuf and the results are placed in the root process's recvbuf.

The op argument must be a predefined reduction operation or a reduction operation created with MPI_Op_create.

The datatype argument specifies the type of elements in the buffers. It must be a valid MPI datatype.

The comm argument specifies the communicator for the operation. It must be a valid MPI communicator.

USE OF IN-PLACE OPTION

When the root process provides MPI_IN_PLACE as the value for sendbuf, the data in the root process's buffer is used as both the send buffer and the receive buffer. The result of the reduction is placed back into the same buffer.

For example, if op is MPI_SUM, then recvbuf will contain the sum of the values in the original sendbuf from all processes.

The recvbuf must be of the same type and length as the sendbuf.

WHEN COMMUNICATOR IS AN INTER-COMMUNICATOR

When comm is an inter-communicator, the root process must be in the local group. The root parameter specifies the rank of the root process in the comm communicator. The reduction is performed only on the processes in the local group. The results are sent to the root process. The remote group is not involved in the reduction.

PREDEFINED REDUCE OPERATIONS

MPI provides the following predefined reduction operations:

  • MPI_SUM: sum of elements
  • MPI_PROD: product of elements
  • MPI_MAX: maximum element
  • MPI_MIN: minimum element
  • MPI_LAND: logical AND
  • MPI_BAND: bitwise AND
  • MPI_LOR: logical OR
  • MPI_BOR: bitwise OR
  • MPI_LXOR: logical XOR
  • MPI_BXOR: bitwise XOR
  • MPI_MAXLOC: maximum element and its location
  • MPI_MINLOC: minimum element and its location
MINLOC AND MAXLOC

When using MPI_MINLOC or MPI_MAXLOC, the datatype must be a contiguous tuple of (value, index), where the value is of the type specified by the user and the index is an MPI_Aint or MPI_Offset. The result is a pair (value, index) where value is the minimum or maximum value, and index is the location of that value. If there are multiple occurrences of the minimum or maximum value, the one with the smallest index is chosen.

NOTES ON COLLECTIVE OPERATIONS

All collective operations have a set of rules that must be followed. All processes participating in the collective call must call the same collective function with the same set of arguments (except for MPI_Comm which can be different communicators).

MPI_Reduce is a collective routine. All processes in the communicator must execute it.

ERRORS

When the communicator is a symmetric communicator, if the root process aborts, then all processes in the communicator are aborted. If a process other than the root process aborts, then the root process is aborted.

When the communicator is an inter-communicator, if the root process aborts, then all processes in the local group are aborted. If a process other than the root process aborts, then the root process is aborted, and all processes in the local group are aborted.

The initial error handler can be changed by calling MPI_Comm_set_errhandler on MPI_COMM_SELF when using the World model, or the mpi_initial_errhandler CLI argument to mpiexec or info key to MPI_Comm_spawn/MPI_Comm_spawn_multiple. If no other appropriate error handler has been set, then the MPI_ERRORS_RETURN error handler is called for MPI I/O functions and the MPI_ERRORS_ABORT error handler is called for all other MPI functions.

Open MPI includes three predefined error handlers that can be used:

  • MPI_ERRORS_ARE_FATAL Causes the program to abort all connected MPI processes.
  • MPI_ERRORS_ABORT An error handler that can be invoked on a communicator, window, file, or session. When called on a communicator, it acts as if MPI_Abort was called on that communicator. If called on a window or file, acts as if MPI_Abort was called on a communicator containing the group of processes in the corresponding window or file. If called on a session, aborts only the local process.
  • MPI_ERRORS_RETURN Returns an error code to the application.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.
