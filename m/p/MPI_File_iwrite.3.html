MPI_File_iwrite(3)

الحزمة: openmpi

التراخيص: BSD-3-Clause AND LicenseRef-MPICH

MPI_File_iwrite(3) Open MPI MPI_File_iwrite(3)

MPI_File_iwrite — يكتب ملفًا بدءًا من الموقع المحدد بمؤشر الملف الفردي (غير متزامن، غير جماعي).

الصيغة

صيغة C

#include <mpi.h>
int MPI_File_iwrite(MPI_File fh, const void *buf, int count,
     MPI_Datatype datatype, MPI_Request *request)

صيغة Fortran

USE MPI
! أو الشكل الأقدم: INCLUDE 'mpif.h'
MPI_FILE_IWRITE(FH, BUF, COUNT, DATATYPE, REQUEST, IERROR)
     <type>  BUF(*)
     INTEGER FH, COUNT, DATATYPE, REQUEST, IERROR

صيغة Fortran 2008

USE mpi_f08
MPI_File_iwrite(fh, buf, count, datatype, request, ierror)
     TYPE(MPI_File), INTENT(IN) :: fh
     TYPE(*), DIMENSION(..), INTENT(IN), ASYNCHRONOUS :: buf
     INTEGER, INTENT(IN) :: count
     TYPE(MPI_Datatype), INTENT(IN) :: datatype
     TYPE(MPI_Request), INTENT(OUT) :: request
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

معامل الإدخال/الإخراج

•
fh: مقبض الملف (handle).

معاملات الإدخال

  • buf: العنوان الأولي للمخزن المؤقت (choice).
  • count: عدد العناصر في المخزن المؤقت (integer).
  • datatype: نوع بيانات كل عنصر في المخزن المؤقت (handle).

معامل الإخراج

  • request: كائن الطلب (handle).
  • ierror: Fortran فقط: حالة الخطأ (integer).

الوصف

MPI_File_iwrite هو نسخة غير متزامنة من الواجهة MPI_File_write. تحاول الكتابة في الملف المرتبط بـ fh (في الموضع الحالي لمؤشر الملف الفردي الذي يحتفظ به النظام) عددًا إجماليًا قدره count من عناصر البيانات ذات النوع datatype من مخزن المستخدم المؤقت buf. يتم كتابة البيانات في الأجزاء المحددة من الملف من خلال العرض الحالي. تخزن MPI_File_iwrite عدد عناصر datatype التي تم كتابتها فعليًا في status. جميع الحقول الأخرى في status غير محددة.

يعد استدعاء هذه الوظيفة خطأً إذا تم تحديد وضع MPI_MODE_SEQUENTIAL عند فتح الملف.

الأخطاء

تقريبًا جميع روتينات MPI تعيد قيمة خطأ؛ روتينات C كنتيجة لإرجاع الوظيفة وروتينات Fortran في المعامل الأخير.

قبل إرجاع قيمة الخطأ، يتم استدعاء معالج أخطاء MPI الحالي المرتبط بكائن الاتصال (مثل، المتصل، النافذة، الملف). إذا لم يكن هناك كائن اتصال مرتبط باستدعاء MPI، فيعتبر الاستدعاء مرتبطًا بـ MPI_COMM_SELF وسيستدعي معالج الأخطاء الأولي. عندما لا يتم تهيئة MPI_COMM_SELF (أي، قبل MPI_Init/MPI_Init_thread، بعد MPI_Finalize، أو عند استخدام نموذج الجلسات حصريًا) فإن الخطأ يثير معالج الأخطاء الأولي. يمكن تغيير معالج الأخطاء الأولي عن طريق استدعاء MPI_Comm_set_errhandler على MPI_COMM_SELF عند استخدام نموذج العالم، أو الوسيطة CLI mpi_initial_errhandler لـ mpiexec أو مفتاح المعلومات لـ MPI_Comm_spawn/MPI_Comm_spawn_multiple. إذا لم يتم تعيين معالج أخطاء مناسب آخر، فيتم استدعاء معالج أخطاء MPI_ERRORS_RETURN لوظائف MPI I/O ويتم استدعاء معالج أخطاء MPI_ERRORS_ABORT لجميع وظائف MPI الأخرى.

يتضمن Open MPI ثلاثة معالجات أخطاء معرفة مسبقًا يمكن استخدامها:

  • MPI_ERRORS_ARE_FATAL يتسبب في إنهاء البرنامج لجميع عمليات MPI المتصلة.
  • MPI_ERRORS_ABORT معالج أخطاء يمكن استدعاؤه على متصل، نافذة، ملف، أو جلسة. عند استدعائه على متصل، فإنه يعمل كما لو تم استدعاء MPI_Abort على هذا المتصل. إذا تم استدعاؤه على نافذة أو ملف، فإنه يعمل كما لو تم استدعاء MPI_Abort على متصل يحتوي على مجموعة العمليات في النافذة أو الملف المقابل. إذا تم استدعاؤه على جلسة، فإنه يقوم بإنهاء العملية المحلية فقط.
  • MPI_ERRORS_RETURN يعيد رمز خطأ إلى التطبيق.

يمكن لتطبيقات MPI أيضًا تنفيذ معالجات الأخطاء الخاصة بها عن طريق استدعاء:

  • MPI_Comm_create_errhandler ثم MPI_Comm_set_errhandler
  • MPI_File_create_errhandler ثم MPI_File_set_errhandler
  • MPI_Session_create_errhandler ثم MPI_Session_set_errhandler أو عند MPI_Session_init
  • MPI_Win_create_errhandler ثم MPI_Win_set_errhandler

لاحظ أن MPI لا تضمن أن برنامج MPI يمكن أن يستمر بعد خطأ.
