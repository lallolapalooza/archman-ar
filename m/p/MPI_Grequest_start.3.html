MPI_Grequest_start(3) Open MPI MPI_Grequest_start(3)

MPI_Grequest_start — يبدأ طلبًا عامًا ويعيد مقبضًا له في request.

الصيغة

صيغة C

#include <mpi.h>
int MPI_Grequest_start(MPI_Grequest_query_function *query_fn,
    MPI_Grequest_free_function *free_fn,
    MPI_Grequest_cancel_function *cancel_fn, void *extra_state,
    MPI_Request *request)

صيغة Fortran

USE MPI
! أو الصيغة الأقدم: INCLUDE 'mpif.h'
MPI_GREQUEST_START(QUERY_FN, FREE_FN, CANCEL_FN, EXTRA_STATE,
    REQUEST, IERROR)
    INTEGER REQUEST, IERROR
    EXTERNAL QUERY_FN, FREE_FN, CANCEL_FN
      INTEGER(KIND=MPI_ADDRESS_KIND) EXTRA_STATE

صيغة Fortran 2008

USE mpi_f08
MPI_Grequest_start(query_fn, free_fn, cancel_fn, extra_state, request,
        ierror)
    PROCEDURE(MPI_Grequest_query_function) :: query_fn
    PROCEDURE(MPI_Grequest_free_function) :: free_fn
    PROCEDURE(MPI_Grequest_cancel_function) :: cancel_fn
    INTEGER(KIND=MPI_ADDRESS_KIND), INTENT(IN) :: extra_state
    TYPE(MPI_Request), INTENT(OUT) :: request
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror

معلمات الإدخال

•
query_fn
وظيفة رد اتصال يتم استدعاؤها عند الاستعلام عن حالة الطلب (وظيفة).
•
free_fn
وظيفة رد اتصال يتم استدعاؤها عند تحرير الطلب (وظيفة).
•
cancel_fn
وظيفة رد اتصال يتم استدعاؤها عند إلغاء الطلب (وظيفة).
•
extra_state : حالة إضافية.

معلمات الإخراج

  • request : طلب عام (مقبض).
  • ierror : Fortran فقط: حالة الخطأ (عدد صحيح).

الوصف

MPI_Grequest_start يبدأ request عامًا ويعيد مقبضًا له في request.

يتم سرد الصيغة والمعنى لوظائف رد الاتصال أدناه. يتم تمرير جميع وظائف رد الاتصال إلى الوسيط extra_state الذي تم ربطه بـ request بواسطة الاستدعاء المبدئي MPI_Grequest_start. يمكن استخدام هذا للحفاظ على حالة محددة من قبل المستخدم لـ request. في C، وظيفة الاستعلام هي

typedef int MPI_Grequest_query_function(void *extra_state,
    MPI_Status *status);

في Fortran، هي

SUBROUTINE GREQUEST_QUERY_FUNCTION(EXTRA_STATE, STATUS, IERROR)
    INTEGER STATUS(MPI_STATUS_SIZE), IERROR
    INTEGER(KIND=MPI_ADDRESS_KIND) EXTRA_STATE

وظيفة query_fn تحسب الحالة التي ينبغي إرجاعها للطلب العام. تتضمن الحالة أيضًا معلومات حول الإلغاء الناجح / غير الناجح للطلب (النتيجة التي سيتم إرجاعها بواسطة MPI_Test_cancelled).

يتم استدعاء وظيفة query_fn بواسطة استدعاء MPI_{Wait|Test}{any|some|all} الذي أكمل الطلب العام المرتبط بوظيفة رد الاتصال هذه. يتم استدعاء وظيفة رد الاتصال أيضًا بواسطة استدعاءات MPI_Request_get_status إذا كان الطلب مكتملًا عند حدوث الاستدعاء. في كلتا الحالتين، يتم تمرير وظيفة رد الاتصال بمرجع إلى متغير الحالة المقابل الذي مرره المستخدم إلى استدعاء MPI. إذا قدم المستخدم MPI_STATUS_IGNORE أو MPI_STATUSES_IGNORE إلى دالة MPI التي تسببت في استدعاء query_fn، فسوف تمرر MPI كائن حالة صالح إلى query_fn، وسيتم تجاهل هذه الحالة عند عودة وظيفة رد الاتصال. لاحظ أنه يتم استدعاء query_fn فقط بعد استدعاء MPI_Grequest_complete على الطلب؛ قد يتم استدعاؤها عدة مرات لنفس الطلب العام. لاحظ أيضًا أن استدعاء MPI_{Wait|Test}{some|all} قد يتسبب في استدعاءات متعددة لوظائف رد الاتصال query_fn، واحدة لكل طلب عام يتم إكماله بواسطة استدعاء MPI. ترتيب هذه الاستدعاءات غير محدد بواسطة MPI.

في C، وظيفة التحرير هي

typedef int MPI_Grequest_free_function(void *extra_state);

وفي Fortran، هي

SUBROUTINE GREQUEST_FREE_FUNCTION(EXTRA_STATE, IERROR)
    INTEGER IERROR
    INTEGER(KIND=MPI_ADDRESS_KIND) EXTRA_STATE

تقوم وظيفة رد الاتصال free_fn باستدعائها لتنظيف الموارد المخصصة من قبل المستخدم عند تحرير الطلب العام.

يتم استدعاء وظيفة رد الاتصال free_fn بواسطة استدعاء MPI_{Wait|Test}{any|some|all} الذي أكمل الطلب العام المرتبط بوظيفة رد الاتصال هذه. يتم استدعاء free_fn بعد استدعاء query_fn لنفس الطلب. ومع ذلك، إذا أكمل استدعاء MPI طلبات عامة متعددة، فإن ترتيب استدعاء وظائف رد الاتصال free_fn غير محدد بواسطة MPI.

يتم أيضًا استدعاء وظيفة رد الاتصال free_fn للطلبات العامة التي يتم تحريرها بواسطة استدعاء MPI_Request_free (لن يحدث استدعاء MPI_{Wait|Test}{any|some|all} لمثل هذا الطلب). في هذه الحالة، سيتم استدعاء وظيفة رد الاتصال إما في استدعاء MPI MPI_Request_free(request) أو في استدعاء MPI MPI_Grequest_complete(request)، أيهما يحدث أخيرًا. بمعنى آخر، في هذه الحالة، يتم تنفيذ رمز التحرير الفعلي بمجرد حدوث كلا الاستدعاءين ( MPI_Request_free و MPI_Grequest_complete). لا يتم إلغاء تخصيص request حتى بعد اكتمال free_fn. لاحظ أنه سيتم استدعاء free_fn مرة واحدة فقط لكل طلب بواسطة برنامج صحيح.

في C، وظيفة الإلغاء هي

typedef int MPI_Grequest_cancel_function(void *extra_state, int complete);

في Fortran، وظيفة الإلغاء هي

SUBROUTINE GREQUEST_CANCEL_FUNCTION(EXTRA_STATE, COMPLETE, IERROR)
     INTEGER IERROR
     INTEGER(KIND=MPI_ADDRESS_KIND) EXTRA_STATE
     LOGICAL COMPLETE

يتم استدعاء وظيفة cancel_fn لبدء إلغاء طلب عام. يتم استدعاؤه بواسطة MPI_Request_cancel(request). تمرر MPI إلى وظيفة رد الاتصال complete=true إذا تم استدعاء MPI_Grequest_complete بالفعل على الطلب، و complete=false بخلاف ذلك.

الأخطاء

تقوم جميع روتينات MPI تقريبًا بإرجاع قيمة خطأ؛ روتينات C كالنتيجة المرتجعة للدالة، وروتينات Fortran في الوسيط الأخير.

قبل إرجاع قيمة الخطأ، يتم استدعاء معالج أخطاء MPI الحالي المرتبط بكيان الاتصال (مثل، المرسل، النافذة، الملف). إذا لم يكن هناك كيان اتصال مرتبط باستدعاء MPI، فسيتم اعتبار الاستدعاء مرتبطًا بـ MPI_COMM_SELF وسيتم استدعاء معالج الأخطاء المرتبط به. عندما لا يتم تهيئة MPI_COMM_SELF (أي، قبل MPI_Init/MPI_Init_thread، بعد MPI_Finalize، أو عند استخدام نموذج الجلسات حصريًا) يثير الخطأ معالج الخطأ الأولي. يمكن تغيير معالج الخطأ الأولي عن طريق استدعاء MPI_Comm_set_errhandler على MPI_COMM_SELF عند استخدام نموذج العالم، أو الوسيط mpi_initial_errhandler لـ mpiexec أو مفتاح المعلومات لـ MPI_Comm_spawn/MPI_Comm_spawn_multiple. إذا لم يتم تعيين أي معالج خطأ مناسب آخر، فسيتم استدعاء معالج الخطأ MPI_ERRORS_RETURN لوظائف MPI I/O وسيتم استدعاء معالج الخطأ MPI_ERRORS_ABORT لجميع وظائف MPI الأخرى.

تتضمن Open MPI ثلاثة معالجات أخطاء محددة مسبقًا يمكن استخدامها:

  • MPI_ERRORS_ARE_FATAL يتسبب في إنهاء البرنامج لجميع العمليات المتصلة بـ MPI.
  • MPI_ERRORS_ABORT خطأ

MPI_Grequest_start(3)

NAME

MPI_Grequest_start - Starts a generalized MPI request

SYNTAX

C

```c
int MPI_Grequest_start(MPI_Grequest_query_function *query_fn,
MPI_Grequest_free_function *free_fn,
MPI_Grequest_cancel_function *cancel_fn,
void *extra_state,
MPI_Request *request);
```

Fortran

See the Fortran 2008 binding.

Fortran 2008

```fortran
SUBROUTINE MPI_Grequest_start(query_fn, free_fn, cancel_fn, extra_state, request, ierror)
INTEGER :: ierror
TYPE(MPI_Grequest_handle), INTENT(OUT) :: request
TYPE(*), INTENT(IN) :: query_fn, free_fn, cancel_fn, extra_state
END SUBROUTINE MPI_Grequest_start
```

INPUT PARAMETERS

query_fn
The function to call to query the status of the generalized request.
free_fn
The function to call to free any resources associated with the generalized request. This function will be called when the request is freed by MPI_Request_free or when the status of the request is queried and it is complete.
cancel_fn
The function to call to attempt to cancel the generalized request. This function will be called by MPI_Request_cancel.
extra_state
A pointer to user-defined state information that will be passed to the callback functions.

OUTPUT PARAMETERS

request
The handle of the generalized request.
ierror
Fortran only: The MPI error status.

DESCRIPTION

MPI_Grequest_start starts a generalized MPI request. A generalized request is an MPI request that is not directly associated with a specific MPI communication operation. Instead, it is associated with a set of callback functions that are invoked by MPI when certain events occur, such as the completion of the request or when the status of the request is queried.

The callback functions are:

query_fn
This function is called when the status of the generalized request is queried (e.g., by MPI_Test or MPI_Wait). It should return information about the status of the request, including whether it is complete and any error code associated with it.
free_fn
This function is called when the generalized request is freed (e.g., by MPI_Request_free) or when the request is completed and its status is queried. It should free any resources associated with the request.
cancel_fn
This function is called when an attempt is made to cancel the generalized request (e.g., by MPI_Request_cancel). It should attempt to cancel the underlying operation and return a value indicating whether the cancellation was successful.

The extra_state parameter is a pointer to user-defined state information that will be passed to the callback functions. This allows the callback functions to access any data they need to perform their tasks.

ERRORS

All MPI error handlers can be invoked on this call. The error codes returned are:

MPI_SUCCESS
No error.
MPI_ERR_PENDING
An operation is still pending.
MPI_ERR_IN_STATUS
An error occurred in one of the callback functions.

The default error handler is MPI_ERRORS_ARE_FATAL. This error handler can be invoked on a communicator, window, file, or session. When called on a communicator, it acts as if MPI_Abort was called on that communicator. If called on a window or file, acts as if MPI_Abort was called on a communicator containing the group of processes in the corresponding window or file. If called on a session, aborts only the local process.

MPI_ERRORS_RETURN Returns an error code to the application.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.

All callback functions return an error code. The code is passed back and dealt with as appropriate for the error code by the MPI function that invoked the callback function. For example, if error codes are returned, then the error code returned by the callback function will be returned by the MPI function that invoked the callback function. In the case of a MPI_{Wait|Test}any call that invokes both query_fn and free_fn, the MPI call will return the error code returned by the last callback, namely free_fn. If one or more of the request's in a call to `MPI_{Wait|Test}{some|all}` has failed, then the MPI call will return MPI_ERR_IN_STATUS. In such a case, if the MPI call was passed an array of statuses, then MPI will return in each of the statuses that correspond to a completed generalized request the error code returned by the corresponding invocation of its free_fn callback function. However, if the MPI function was passed MPI_STATUSES_IGNORE, then the individual error codes returned by each callback function will be lost.
