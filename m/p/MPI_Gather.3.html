MPI_Gather(3)

الحزمة: openmpi

التراخيص: BSD-3-Clause AND LicenseRef-MPICH

SYNOPSIS

The overall structure of the MPI_Gather subroutine is:

C++
    void MPI::Intracomm::Gather(const void* sendbuf, int sendcount,
        MPI::Datatype sendtype, void* recvbuf, int recvcount,
        MPI::Datatype recvtype, int root)

C
    MPI_GATHER(void* sendbuf, int sendcount, MPI_Datatype sendtype,
               void* recvbuf, int recvcount, MPI_Datatype recvtype,
               int root, MPI_Comm comm)

Fortran
    MPI_GATHER(SENDBUF, SENDCOUNT, SENDTYPE, RECVBUF, RECVCOUNT,
               RECVTYPE, ROOT, COMM)
    TYPE(*), DIMENSION(*) :: SENDBUF, RECVBUF
    INTEGER :: SENDCOUNT, SENDTYPE, RECVCOUNT, RECVTYPE, ROOT, COMM

The Fortran 2008 intrinsic subroutine mpi_gather is the generic, typed interface to this function.

INPUT PARAMETERS

•
SENDTYPE

MPI datatype of elements in send buffer (integer).

•
RECVTYPE

MPI datatype of elements in receive buffer (integer).

•
ROOT

Rank of the root process (integer).

•
COMM

Communicator (handle).

All processes in the communicator `comm` participate in the collective operation. The root process receives the data sent by all other processes, including itself.

The non-root processes send the contents of their send buffer to the root process. The root process receives these messages and concatenates them into its receive buffer. The send count on all processes must be consistent with the receive count on the root process.

The send count on each non-root process must be less than or equal to the receive count on the root process. The receive count on the root process must be equal to the sum of the send counts on all processes.

The send buffer argument must be consistent with the receive buffer argument. That is, the send buffer must be a pointer to the same memory location as the receive buffer.

The root process must specify a receive buffer of size recvcount * size of recvtype. The non-root processes must specify a send buffer of size sendcount * size of sendtype.

The root process must specify a receive count equal to the sum of the send counts on all processes. The non-root processes must specify a send count equal to the send count on the root process.

The send buffer argument of the processes in the first group must be consistent with the receive buffer argument of the root process in the second group.

OUTPUT PARAMETERS

•
RECVBUF

Contents of send buffers from all processes, concatenated in the receive buffer of the root process.

DESCRIPTION

MPI_Gather collects a contiguous block of data from all processes in a communicator and the root process arranges the data into a contiguous block.

More specifically, if `count` is the number of elements in the send buffer on each process, and `datatype` is the MPI datatype of those elements, then the root process will receive `size * count` elements of `datatype`, where `size` is the number of processes in the communicator. The data from process `i` is received after the data from process `i-1`.

The send buffer must be consistent across all processes. The receive buffer must be consistent on the root process.

The send count on each process must be the same. The receive count on the root process must be equal to the sum of the send counts on all processes.

The send buffer argument of the processes in the first group must be consistent with the receive buffer argument of the root process in the second group.

USE OF IN-PLACE OPTION

When the communicator is an intracommunicator, each process may specify the same buffer for both the send and receive arguments. In this case, the send buffer must contain the data that is to be received by the root process. The receive buffer will contain the concatenated data from all processes.

The root process must specify the same buffer for both the send and receive arguments. In this case, the send buffer must contain the data that is to be received by the root process. The receive buffer will contain the concatenated data from all processes.

WHEN COMMUNICATOR IS AN INTER-COMMUNICATOR

When the communicator is an inter-communicator, one group of processes (group A) is considered the "local" group, and the other group (group B) is considered the "remote" group. The root process is in the local group. The processes in the remote group send their data to the root process in the local group. The root process then concatenates the data from all processes in the remote group into its receive buffer.

The root process in the local group is identified by its rank in the local group. The processes in the remote group use the rank of the root process in the local group as the value of their root argument. The remaining processes in the local group use MPI_PROC_NULL as the value of their root argument.

The send buffer argument of the processes in the first group must be consistent with the receive buffer argument of the root process in the second group.

ERRORS

Almost all MPI routines return an error value; C routines as the return result of the function and Fortran routines in the last argument.

Before the error value is returned, the current MPI error handler associated with the communication object (e.g., communicator, window, file) is called. If no communication object is associated with the MPI call, then the call is considered attached to MPI_COMM_SELF and will call the associated MPI error handler. When MPI_COMM_SELF is not initialized (i.e., before MPI_Init/MPI_Init_thread, after MPI_Finalize, or when using the Sessions Model exclusively) the error raises the initial error handler. The initial error handler can be changed by calling MPI_Comm_set_errhandler on MPI_COMM_SELF when using the World model, or the mpi_initial_errhandler CLI argument to mpiexec or info key to MPI_Comm_spawn/MPI_Comm_spawn_multiple. If no other appropriate error handler has been set, then the MPI_ERRORS_RETURN error handler is called for MPI I/O functions and the MPI_ERRORS_ABORT error handler is called for all other MPI functions.

Open MPI includes three predefined error handlers that can be used:

  • MPI_ERRORS_ARE_FATAL Causes the program to abort all connected MPI processes.
  • MPI_ERRORS_ABORT An error handler that can be invoked on a communicator, window, file, or session. When called on a communicator, it acts as if MPI_Abort was called on that communicator. If called on a window or file, acts as if MPI_Abort was called on a communicator containing the group of processes in the corresponding window or file. If called on a session, aborts only the local process.
  • MPI_ERRORS_RETURN Returns an error code to the application.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.
