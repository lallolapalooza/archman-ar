MPI_File_write_all(3)

الحزمة: openmpi

التراخيص: BSD-3-Clause AND LicenseRef-MPICH

MPI_FILE_WRITE_ALL(3) Open MPI MPI_FILE_WRITE_ALL(3)

MPI_File_write_all — يكتب ملفًا يبدأ من المواقع المحددة بواسطة مؤشرات الملف الفردية (تجميعي، جماعي).

الصيغة

صيغة C

#include <mpi.h>
int MPI_File_write_all(MPI_File fh, const void *buf,
     int count, MPI_Datatype datatype, MPI_Status *status)

صيغة Fortran

USE MPI
! أو الشكل الأقدم: INCLUDE 'mpif.h'
MPI_FILE_WRITE_ALL(FH, BUF, COUNT,
     DATATYPE, STATUS, IERROR)
     <type>  BUF(*)
     INTEGER FH, COUNT, DATATYPE, STATUS(MPI_STATUS_SIZE), IERROR

صيغة Fortran 2008

USE mpi_f08
MPI_File_write_all(fh, buf, count, datatype, status, ierror)
     TYPE(MPI_File), INTENT(IN) :: fh
     TYPE(*), DIMENSION(..), INTENT(IN) :: buf
     INTEGER, INTENT(IN) :: count
     TYPE(MPI_Datatype), INTENT(IN) :: datatype
     TYPE(MPI_Status) :: status
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

معلمات الإدخال

  • fh: مقبض الملف (مقبض).
  • buf: عنوان بداية المخزن المؤقت (اختياري).
  • count: عدد العناصر في المخزن المؤقت (عدد صحيح).
  • datatype: نوع بيانات كل عنصر مخزن مؤقت (مقبض).

معلمات الإخراج

  • status: كائن الحالة (حالة).
  • ierror: Fortran فقط: حالة الخطأ (عدد صحيح).

الوصف

MPI_File_write_all هي روتينية جماعية تحاول الكتابة في الملف المرتبط بـ fh (عند الموضع الحالي لمؤشر الملف الفردي الذي تحتفظ به النظام) عدد إجمالي قدره count من عناصر البيانات التي لها نوع datatype من المخزن المؤقت للمستخدم buf. يتم كتابة البيانات في تلك الأجزاء من الملف المحددة بواسطة العرض الحالي. MPI_File_write_all يخزن عدد عناصر datatype التي تم كتابتها فعليًا في status. جميع الحقول الأخرى لـ status غير محددة.

من الخاطئ استدعاء هذه الدالة إذا تم تحديد وضع MPI_MODE_SEQUENTIAL عند فتح الملف.

الأخطاء

تعيد جميع روتينات MPI تقريبًا قيمة خطأ؛ روتينات C كنتيجة للإرجاع للدالة وروتينات Fortran في الوسيط الأخير.

قبل إعادة قيمة الخطأ، يتم استدعاء معالج أخطاء MPI الحالي المرتبط بجسم الاتصال (على سبيل المثال، المتصل، النافذة، الملف). إذا لم يكن هناك جسم اتصال مرتبط باستدعاء MPI، فيتم اعتبار الاستدعاء مرتبطًا بـ MPI_COMM_SELF وسيتم استدعاء معالج الأخطاء الأولي. عندما لا يتم تهيئة MPI_COMM_SELF (أي، قبل MPI_Init / MPI_Init_thread، بعد MPI_Finalize، أو عند استخدام نموذج الجلسات حصريًا) يثير الخطأ معالج الأخطاء الأولي. يمكن تغيير معالج الأخطاء الأولي عن طريق استدعاء MPI_Comm_set_errhandler على MPI_COMM_SELF عند استخدام نموذج العالم، أو وسيطة سطر الأوامر mpi_initial_errhandler لـ mpiexec أو مفتاح المعلومات لـ MPI_Comm_spawn / MPI_Comm_spawn_multiple. إذا لم يتم تعيين معالج أخطاء مناسب آخر، فسيتم استدعاء معالج أخطاء MPI_ERRORS_RETURN لوظائف إدخال / إخراج MPI وسيتم استدعاء معالج أخطاء MPI_ERRORS_ABORT لجميع وظائف MPI الأخرى.

يشمل Open MPI ثلاثة معالجات أخطاء معرفة مسبقًا يمكن استخدامها:

  • MPI_ERRORS_ARE_FATAL يتسبب في إنهاء البرنامج لجميع عمليات MPI المتصلة.
  • MPI_ERRORS_ABORT معالج خطأ يمكن استدعاؤه على متصل، نافذة، ملف، أو جلسة. عند استدعائه على متصل، فإنه يتصرف كما لو تم استدعاء MPI_Abort على هذا المتصل. إذا تم استدعاؤه على نافذة أو ملف، فإنه يتصرف كما لو تم استدعاء MPI_Abort على متصل يحتوي على مجموعة العمليات في النافذة أو الملف المقابل. إذا تم استدعاؤه على جلسة، فإنه ينهي العملية المحلية فقط.
  • MPI_ERRORS_RETURN يعيد رمز خطأ إلى التطبيق.

يمكن لتطبيقات MPI أيضًا تنفيذ معالجات الأخطاء الخاصة بها عن طريق استدعاء:

  • MPI_Comm_create_errhandler ثم MPI_Comm_set_errhandler
  • MPI_File_create_errhandler ثم MPI_File_set_errhandler
  • MPI_Session_create_errhandler ثم MPI_Session_set_errhandler أو في MPI_Session_init
  • MPI_Win_create_errhandler ثم MPI_Win_set_errhandler

لاحظ أن MPI لا يضمن أن برنامج MPI يمكن أن يستمر بعد خطأ.
