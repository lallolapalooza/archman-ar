MPI_Type_vector(3)

الحزمة: openmpi

التراخيص: BSD-3-Clause AND LicenseRef-MPICH

MPI_Type_vector(3) Open MPI MPI_Type_vector(3)

MPI_Type_vector — ينشئ نوع بيانات متجه (متدرج).

الصيغة

صيغة C

#include <mpi.h>
int MPI_Type_vector(int count, int blocklength, int stride,
     MPI_Datatype oldtype, MPI_Datatype *newtype)

صيغة Fortran

USE MPI
! أو الصيغة الأقدم: INCLUDE 'mpif.h'
MPI_TYPE_VECTOR(COUNT, BLOCKLENGTH, STRIDE, OLDTYPE, NEWTYPE,
             IERROR)
     INTEGER COUNT, BLOCKLENGTH, STRIDE, OLDTYPE
     INTEGER NEWTYPE, IERROR

صيغة Fortran 2008

USE mpi_f08
MPI_Type_vector(count, blocklength, stride, oldtype, newtype, ierror)
     INTEGER, INTENT(IN) :: count, blocklength, stride
     TYPE(MPI_Datatype), INTENT(IN) :: oldtype
     TYPE(MPI_Datatype), INTENT(OUT) :: newtype
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

معاملات الإدخال

  • count: عدد الكتل (عدد صحيح غير سالب).
  • blocklength: عدد العناصر في كل كتلة (عدد صحيح غير سالب).
  • stride: عدد العناصر بين بداية كل كتلة (عدد صحيح).
  • oldtype: نوع البيانات القديم (مقبض).

معاملات الإخراج

  • newtype: نوع البيانات الجديد (مقبض).
  • ierror: Fortran فقط: حالة الخطأ (عدد صحيح).

الوصف

الدالة MPI_Type_vector هي مُنشئ عام يسمح بتكرار نوع بيانات في مواقع تتكون من كتل متباعدة بالتساوي. يتم الحصول على كل كتلة عن طريق ربط نفس العدد من نسخ نوع البيانات القديم. المسافة بين الكتل هي مضاعف لمدى نوع البيانات القديم.

مثال 1: افترض مرة أخرى أن oldtype يحتوي على خريطة النوع {(double, 0), (char, 8)}، مع مدى 16. استدعاء لـ MPI_Type_vector(2, 3, 4, oldtype, newtype) سينشئ نوع البيانات بالخريطة التالية:

{(double, 0), (char, 8), (double, 16), (char, 24),
(double, 32), (char, 40),
(double, 64), (char, 72),
(double, 80), (char, 88), (double, 96), (char, 104)}

أي، كتلتان بثلاث نسخ من النوع القديم لكل منهما، مع خطوة بمقدار 4 عناصر (4 × 16 بايت) بين الكتل.

مثال 2: استدعاء لـ MPI_Type_vector(3, 1, -2, oldtype, newtype) سينشئ نوع البيانات

{(double, 0), (char, 8), (double, -32), (char, -24),
(double, -64), (char, -56)}

بشكل عام، افترض أن oldtype يحتوي على خريطة النوع

{(type(0), disp(0)), ..., (type(n-1), disp(n-1))},

مع مدى ex. لتكن bl طول الكتلة. نوع البيانات الذي تم إنشاؤه حديثًا يحتوي على عدد x bl x n من الإدخالات:

{(type(0), disp(0)), ..., (type(n-1), disp(n-1)),
(type(0), disp(0) + ex), ..., (type(n-1), disp(n-1) + ex), ...,
(type(0), disp(0) + (bl -1) * ex),...,
(type(n-1), disp(n-1) + (bl -1)* ex),
(type(0), disp(0) + stride * ex),..., (type(n-1),
disp(n-1) + stride * ex), ...,
(type(0), disp(0) + (stride + bl - 1) * ex), ...,
(type(n-1), disp(n-1) + (stride + bl -1) * ex), ...,
(type(0), disp(0) + stride * (count -1) * ex), ...,
(type(n-1), disp(n-1) + stride * (count -1) * ex), ...,
(type(0), disp(0) + (stride * (count -1) + bl -1) * ex), ...,
(type(n-1), disp(n-1) + (stride * (count -1) + bl -1) * ex)}

استدعاء لـ MPI_Type_contiguous(count, oldtype, newtype) يعادل استدعاء لـ MPI_Type_vector(count, 1, 1, oldtype, newtype)، أو استدعاء لـ MPI_Type_vector(1, count, n, oldtype, newtype)، n عشوائي.

الأخطاء

تقريبًا جميع روتينيات MPI ترجع قيمة خطأ؛ روتينيات C كنتيجة للإرجاع للدالة وروتينيات Fortran في المعامل الأخير.

قبل إرجاع قيمة الخطأ، يتم استدعاء معالج أخطاء MPI الحالي المرتبط بكيان الاتصال (مثل، المُتواصل، النافذة، الملف). إذا لم يكن هناك كيان اتصال مرتبط باستدعاء MPI، فسيتم اعتبار الاستدعاء متصلاً بـ MPI_COMM_SELF وسيتم استدعاء معالج الأخطاء المرتبط به. عندما لا يتم تهيئة MPI_COMM_SELF (أي، قبل MPI_Init/MPI_Init_thread، بعد MPI_Finalize، أو عند استخدام نموذج الجلسات حصريًا) يرفع الخطأ معالج الخطأ الأولي. يمكن تغيير معالج الخطأ الأولي عن طريق استدعاء MPI_Comm_set_errhandler على MPI_COMM_SELF عند استخدام نموذج العالم، أو وسيطة سطر الأوامر mpi_initial_errhandler إلى mpiexec أو مفتاح معلومات لـ MPI_Comm_spawn/MPI_Comm_spawn_multiple. إذا لم يتم تعيين أي معالج خطأ مناسب آخر، فسيتم استدعاء معالج الخطأ MPI_ERRORS_RETURN لوظائف إدخال/إخراج MPI وسيتم استدعاء معالج الخطأ MPI_ERRORS_ABORT لجميع وظائف MPI الأخرى.

يتضمن Open MPI ثلاثة معالجات أخطاء مُعرفة مسبقًا يمكن استخدامها:

  • MPI_ERRORS_ARE_FATAL يتسبب في إيقاف البرنامج لجميع عمليات MPI المتصلة.
  • MPI_ERRORS_ABORT معالج خطأ يمكن استدعاؤه على مُتواصل، نافذة، ملف، أو جلسة. عند استدعاؤه على مُتواصل، يتصرف كما لو تم استدعاء MPI_Abort على هذا المُتواصل. إذا تم استدعاؤه على نافذة أو ملف، يتصرف كما لو تم استدعاء MPI_Abort على مُتواصل يحتوي على مجموعة العمليات في النافذة أو الملف المقابل. إذا تم استدعاؤه على جلسة، يقوم فقط بإيقاف العملية المحلية.
  • MPI_ERRORS_RETURN يرجع رمز خطأ إلى التطبيق.

يمكن لتطبيقات MPI أيضًا تنفيذ معالجات الأخطاء الخاصة بها عن طريق الاستدعاء:

  • MPI_Comm_create_errhandler ثم MPI_Comm_set_errhandler
  • MPI_File_create_errhandler ثم MPI_File_set_errhandler
  • MPI_Session_create_errhandler ثم MPI_Session_set_errhandler أو عند MPI_Session_init
  • MPI_Win_create_errhandler ثم MPI_Win_set_errhandler

لاحظ أن MPI لا يضمن أن برنامج MPI يمكن أن يستمر بعد حدوث خطأ.

MPI_Type_vector(3)

MPI_Type_vector(3)

MPI_Type_vector — Creates a contiguous vector data type.

SYNOPSIS

int MPI_Type_vector(int count, int blocklength, int stride, MPI_Datatype oldtype, MPI_Datatype *newtype)

INPUT PARAMETERS

  • count

    Number of blocks.

  • blocklength

    Number of elements in each block.

  • stride

    Number of elements between the start of consecutive blocks.

  • oldtype

    Datatype of each element in the vector.

OUTPUT PARAMETERS

  • newtype

    New datatype (handle).

DESCRIPTION

MPI_Type_vector creates a new datatype representing a vector of elements. The vector consists of `count` blocks, each containing `blocklength` elements of type `oldtype`. The distance between the start of consecutive blocks, measured in elements of `oldtype`, is given by `stride`.

The created datatype is contiguous in memory if `stride` is equal to `blocklength`. Otherwise, it is non-contiguous.

NOTES

The values of `count`, `blocklength`, and `stride` must be non-negative.

If `count` is 0, the resulting datatype will be empty.

If `blocklength` is 0, the resulting datatype will be a committed empty datatype.

MPI_Type_contiguous(3), MPI_Type_indexed(3), MPI_Type_create_subarray(3)
