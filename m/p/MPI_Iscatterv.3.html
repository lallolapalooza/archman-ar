MPI_Iscatterv(3)

MPI_ISCATTERV(3) Open MPI MPI_ISCATTERV(3)

MPI_Scatterv, MPI_Iscatterv, MPI_Scatterv_init - تقوم بنثر (scatter) مخزن مؤقت أجزاءً إلى جميع المهام في مجموعة.

int MPI_Iscatterv(const void *sendbuf, const int sendcounts[], const int displs[],
     MPI_Datatype sendtype, void *recvbuf, int recvcount,
     MPI_Datatype recvtype, int root, MPI_Comm comm, MPI_Request *request)

     MPI_Datatype sendtype, void *recvbuf, int recvcount,
     MPI_Datatype recvtype, int root, MPI_Comm comm, MPI_Info info, MPI_Request *request)

معاملات الإدخال

  • sendbuf: عنوان مخزن الإرسال (اختياري، مهم فقط عند الجذر).
  • sendcounts: مصفوفة أعداد صحيحة (بطول حجم المجموعة) تحدد عدد العناصر المراد إرسالها لكل معالج.
  • displs: مصفوفة أعداد صحيحة (بطول حجم المجموعة). تحدد القيمة `i` في هذه المصفوفة الإزاحة (نسبة إلى `sendbuf`) التي يجب أخذ بيانات الإرسال منها إلى المعالج `i`.
  • sendtype: نوع عناصر مخزن الإرسال (معرّف).
  • recvcount: عدد العناصر في مخزن الاستقبال (عدد صحيح).
  • recvtype: نوع عناصر مخزن الاستقبال (معرّف).
  • root: رتبة عملية الإرسال (عدد صحيح).
  • comm: المتواصل (معرّف).
  • info: معلومات (معرّف، مستمر فقط).

معاملات الإخراج

  • recvbuf: عنوان مخزن الاستقبال (اختياري).
  • request: طلب (معرّف، غير متزامن فقط).
  • ierror: فورتران فقط: حالة الخطأ (عدد صحيح).

الوصف

MPI_Scatterv هي العملية العكسية لـ MPI_Gatherv.

MPI_Scatterv توسع وظائف MPI_Scatter من خلال السماح بعدد متغير من البيانات ليتم إرساله إلى كل عملية، نظرًا لأن sendcounts أصبحت الآن مصفوفة. كما أنها توفر مرونة أكبر فيما يتعلق بمكان أخذ البيانات من عند الجذر، من خلال توفير الوسيط الجديد، displs.

النتيجة كما لو أن الجذر قام بتنفيذ n عمليات إرسال،

MPI_Send(sendbuf + displs[i] * extent(sendtype),
         sendcounts[i], sendtype, i, ...);
// وكل عملية قامت بتنفيذ استقبال،
MPI_Recv(recvbuf, recvcount, recvtype, root, ...)

يتم تجاهل مخزن الإرسال لجميع العمليات غير الجذر.

يجب أن تكون البصمة النوعية الضمنية لـ sendcount[i]، sendtype عند الجذر مساوية للبصمة النوعية الضمنية لـ recvcount، recvtype عند العملية i (مع ذلك، قد تكون خرائط الأنواع مختلفة). هذا يعني أن كمية البيانات المرسلة يجب أن تكون مساوية لكمية البيانات المستلمة، بشكل زوجي بين كل عملية والجذر. لا تزال خرائط الأنواع المميزة بين المرسل والمستقبل مسموح بها.

جميع المعاملات للدالة مهمة على العملية root، بينما على العمليات الأخرى، تكون المعاملات recvbuf، recvcount، recvtype، root، comm فقط مهمة. يجب أن تكون المعاملات root و comm متطابقة في القيم على جميع العمليات.

يجب ألا يتسبب تحديد الأعداد، الأنواع، والإزاحات في قراءة أي موقع على الجذر أكثر من مرة.

مثال 1: عكس المثال 5 في صفحة دليل MPI_Gatherv. لدينا مسافة متغيرة بين الكتل في جانب الإرسال (الجذر)، وفي جانب الاستقبال نستقبل 100 - i عنصرًا في العمود i لمصفوفة C بحجم 100 × 150 في العملية i.

MPI_Comm comm;
int gsize,recvarray[100][150],*rptr;
int root, *sendbuf, myrank, bufsize, *stride;
MPI_Datatype rtype;
int i, *displs, *scounts, offset;
...
MPI_Comm_size( comm, &gsize);
MPI_Comm_rank( comm, &myrank );
stride = (int *)malloc(gsize*sizeof(int));
...
/* يتم تعيين stride[i] لـ i = 0 إلى gsize-1 بطريقة ما
 * يأتي sendbuf من مكان آخر
 */
...
displs = (int *)malloc(gsize*sizeof(int));
scounts = (int *)malloc(gsize*sizeof(int));
offset = 0;
for (i=0; i<gsize; ++i) {
    displs[i] = offset;
    offset += stride[i];
    scounts[i] = 100 - i;
}
/* إنشاء نوع للمجال الذي نستقبله
 */
MPI_Type_vector( 100-myrank, 1, 150, MPI_INT, &rtype);
MPI_Type_commit( &rtype );
rptr = &recvarray[0][myrank];
MPI_Scatterv(sendbuf, scounts, displs, MPI_INT,
             rptr, 1, rtype, root, comm);

مثال 2: عكس المثال 1 في صفحة دليل MPI_Gather. تقوم العملية الجذرية بنثر مجموعات من 100 عدد صحيح للعمليات الأخرى، ولكن مجموعات الـ 100 متباعدة بـ stride عدد صحيح في مخزن الإرسال. يتطلب استخدام MPI_Scatterv، حيث stride >= 100.

MPI_Comm comm;
int gsize,*sendbuf;
int root, rbuf[100], i, *displs, *scounts;
...
MPI_Comm_size(comm, &gsize);
sendbuf = (int *)malloc(gsize*stride*sizeof(int));
...
displs = (int *)malloc(gsize*sizeof(int));
scounts = (int *)malloc(gsize*sizeof(int));
for (i=0; i<gsize; ++i) {
   displs[i] = i*stride;
   scounts[i] = 100;
}
MPI_Scatterv(sendbuf, scounts, displs, MPI_INT,
             rbuf, 100, MPI_INT, root, comm);

استخدام خيار في المكان (IN-PLACE)

عندما يكون المتواصل متواصلاً داخليًا (intracommunicator)، يمكنك إجراء عملية النثر في المكان (يتم استخدام مخزن الإخراج كمخزن إدخال). استخدم المتغير MPI_IN_PLACE كقيمة لـ recvbuf الخاصة بعملية الجذر. في هذه الحالة، يتم تجاهل recvcount و recvtype، ولا ترسل عملية الجذر أي بيانات إلى نفسها.
