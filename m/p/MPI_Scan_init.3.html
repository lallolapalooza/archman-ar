معلمات الإدخال (INPUT PARAMETERS)

  • sendbuf: مخزن الإرسال (اختياري).
  • count: عدد العناصر في مخزن الإدخال (عدد صحيح).
  • datatype: نوع بيانات عناصر مخزن الإدخال (مقبض).
  • op: العملية (مقبض).
  • comm: المراسِل (مقبض).
  • info: معلومات (مقبض، دائم فقط).

معلمات الإخراج (OUTPUT PARAMETERS)

  • recvbuf: مخزن الاستقبال (اختياري).
  • request: الطلب (مقبض، غير متزامن فقط).
  • ierror: فورتران فقط: حالة الخطأ (عدد صحيح).

الوصف (DESCRIPTION)

يُستخدم MPI_Scan لإجراء اختزال لاحِق شامل على البيانات الموزعة عبر العمليات المتصلة. تُرجع العملية، في recvbuf للعملية ذات الرتبة i، الاختزال (محسوب وفقاً للدالة op) لقيم sendbufs للعمليات ذات الرتب 0، …، i (شامل). أنواع العمليات المدعومة، ودلالاتها، والقيود على مخازن الإرسال والاستقبال هي كما في MPI_Reduce.

مثال (EXAMPLE)

يستخدم هذا المثال عملية محددة من قبل المستخدم لإنتاج مسح مجزأ. يأخذ المسح المجزأ، كمدخل، مجموعة من القيم ومجموعة من القيم المنطقية، حيث تحدد القيم المنطقية الأجزاء المختلفة للمسح. على سبيل المثال،

values     v1      v2      v3      v4      v5      v6      v7      v8
logicals   0       0       1       1       1       0       0       1
result     v1    v1+v2     v3    v3+v4  v3+v4+v5   v6    v6+v7     v8

وبالتالي، تكون النتيجة للرتبة j هي مجموع v(i) + … + v(j)، حيث i هي أدنى رتبة بحيث لجميع الرتب n، i <= n <= j، منطقي(n) = منطقي(j). المعامل الذي ينتج هذا التأثير هو

      [ u ]     [ v ]     [ w ]
      [   ]  o  [   ]  =  [   ]
      [ i ]     [ j ]     [ j ]
حيث
    ( u + v إذا كان i = j w = ( ( v إذا كان i != j

لاحظ أن هذا معامل غير تبادلي. كود C الذي ينفذه معطى أدناه.

typedef struct {
        double val;
        int log;
} SegScanPair;
/*
 * الدالة المحددة من قبل المستخدم
 */
void segScan(SegScanPair *in, SegScanPair *inout, int *len,
        MPI_Datatype *dptr)
{
        int i;
        SegScanPair c;
        for (i = 0; i < *len; ++i) {
                if (in->log == inout->log)
                        c.val = in->val + inout->val;
                else
                        c.val = inout->val;
                c.log = inout->log;
                *inout = c;
                in++;
                inout++;
        }
}

لاحظ أن الوسيط inout للدالة المحددة من قبل المستخدم يقابل الوسيط الأيمن للمعامل. عند استخدام هذا المعامل، يجب أن نكون حذرين في تحديد أنه غير تبادلي، كما في ما يلي:

int                     i, base;
SeqScanPair     a, answer;
MPI_Op          myOp;
MPI_Datatype    type[2] = {MPI_DOUBLE, MPI_INT};
MPI_Aint                disp[2];
int                     blocklen[2] = {1, 1};
MPI_Datatype    sspair;
/*
 * شرح لـ MPI كيف تم تعريف النوع SegScanPair
 */
MPI_Get_address(a, disp);
MPI_Get_address(a.log, disp + 1);
base = disp[0];
for (i = 0; i < 2; ++i)
        disp[i] -= base;
MPI_Type_struct(2, blocklen, disp, type, &sspair);
MPI_Type_commit(&sspair);
/*
 * إنشاء عملية المسح المجزأ المحددة من قبل المستخدم
 * غير تبادلي - تعيين commute (الوسيط 2) إلى 0
 */
MPI_Op_create((MPI_User_function *)segScan, 0, &myOp);
...
MPI_Scan(a, answer, 1, sspair, myOp, comm);

استخدام خيار في المكان (USE OF IN-PLACE OPTION)

عندما يكون المراسل داخليًا، يمكنك إجراء عملية مسح في المكان (يُستخدم مخزن الإخراج كمخزن إدخال). استخدم المتغير MPI_IN_PLACE كقيمة للوسيط sendbuf. تُؤخذ بيانات الإدخال من مخزن الاستقبال وتُستبدل ببيانات الإخراج.

ملاحظات على العمليات الجماعية (NOTES ON COLLECTIVE OPERATIONS)

لا تُرجع دوال الاختزال من النوع MPI_Op قيمة خطأ. نتيجة لذلك، إذا اكتشفت الدوال خطأ، فإن كل ما يمكنها فعله هو إما استدعاء MPI_Abort أو تجاهل المشكلة بصمت. وبالتالي، إذا تم تغيير معالج الخطأ من MPI_ERRORS_ARE_FATAL إلى شيء آخر (مثل MPI_ERRORS_RETURN)، فقد لا يتم الإشارة إلى أي خطأ.

سبب ذلك هو مشاكل الأداء في ضمان أن جميع الروتينات الجماعية تُرجع نفس قيمة الخطأ.

الأخطاء (ERRORS)

تُرجع جميع روتينات MPI تقريبًا قيمة خطأ؛ روتينات C كنتيجة إرجاع للدالة، وروتينات فورتران في الوسيط الأخير.

قبل إرجاع قيمة الخطأ، يتم استدعاء معالج الخطأ MPI الحالي المرتبط بعنصر الاتصال (مثل، المراسل، النافذة، الملف). إذا لم يكن هناك عنصر اتصال مرتبط باستدعاء MPI، فسيتم اعتبار الاستدعاء مرتبطًا بـ MPI_COMM_SELF وسيتم استدعاء معالج الخطأ المرتبط به. عندما لا يتم تهيئة MPI_COMM_SELF (أي، قبل MPI_Init/MPI_Init_thread، بعد MPI_Finalize، أو عند استخدام نموذج الجلسات حصريًا) يثير الخطأ معالج الخطأ الأولي. يمكن تغيير معالج الخطأ الأولي عن طريق استدعاء MPI_Comm_set_errhandler على MPI_COMM_SELF عند استخدام نموذج العالم، أو mpi_init

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

الأخطاء

يمكن تحديد معالجات الأخطاء على مستوى ملف تعريف MPI العام باستخدام الوسيطة ial_errhandler لـ mpiexec أو كمفتاح معلومات لـ MPI_Comm_spawn/MPI_Comm_spawn_multiple. إذا لم يتم تعيين معالج أخطاء مناسب آخر، فسيتم استدعاء معالج الأخطاء MPI_ERRORS_RETURN لوظائف MPI I/O وسيتم استدعاء معالج الأخطاء MPI_ERRORS_ABORT لجميع وظائف MPI الأخرى.

يتضمن Open MPI ثلاثة معالجات أخطاء محددة مسبقًا يمكن استخدامها:

  • MPI_ERRORS_ARE_FATAL يتسبب في إنهاء البرنامج لجميع عمليات MPI المتصلة.
  • MPI_ERRORS_ABORT معالج أخطاء يمكن استدعاؤه على متصل، أو نافذة، أو ملف، أو جلسة. عند استدعائه على متصل، يتصرف كما لو تم استدعاء MPI_Abort على هذا المتصل. إذا تم استدعاؤه على نافذة أو ملف، يتصرف كما لو تم استدعاء MPI_Abort على متصل يحتوي على مجموعة العمليات في النافذة أو الملف المقابل. إذا تم استدعاؤه على جلسة، فإنه ينهي العملية المحلية فقط.
  • MPI_ERRORS_RETURN يعيد رمز خطأ إلى التطبيق.

يمكن لتطبيقات MPI أيضًا تنفيذ معالجات أخطاء خاصة بها عن طريق استدعاء:

  • MPI_Comm_create_errhandler ثم MPI_Comm_set_errhandler
  • MPI_File_create_errhandler ثم MPI_File_set_errhandler
  • MPI_Session_create_errhandler ثم MPI_Session_set_errhandler أو عند MPI_Session_init
  • MPI_Win_create_errhandler ثم MPI_Win_set_errhandler

لاحظ أن MPI لا يضمن أن برنامج MPI يمكن أن يستمر بعد حدوث خطأ.
