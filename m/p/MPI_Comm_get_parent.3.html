MPI_Comm_get_parent(3)

الحزمة: openmpi

التراخيص: BSD-3-Clause AND LicenseRef-MPICH

MPI_COMM_GET_PARENT(3) Open MPI MPI_COMM_GET_PARENT(3)

MPI_Comm_get_parent — إرجاع واجهة الاتصال الأصلية للعملية المنبثقة الحالية.

الصيغة

صيغة C

#include <mpi.h>
int MPI_Comm_get_parent(MPI_Comm *parent)

صيغة Fortran

USE MPI
! أو الشكل الأقدم: INCLUDE 'mpif.h'
MPI_COMM_GET_PARENT(PARENT, IERROR)
     INTEGER PARENT, IERROR

صيغة Fortran 2008

USE mpi_f08
MPI_Comm_get_parent(parent, ierror)
     TYPE(MPI_Comm), INTENT(OUT) :: parent
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

معلمات الإخراج

  • parent: واجهة الاتصال الأصلية (معرّف).
  • ierror: Fortran فقط: حالة الخطأ (عدد صحيح).

الوصف

إذا بدأت عملية ما باستخدام MPI_Comm_spawn أو MPI_Comm_spawn_multiple، فإن MPI_Comm_get_parent تُرجع واجهة الاتصال "الأصلية" للعملية الحالية. يتم إنشاء واجهة الاتصال الأصلية هذه ضمنياً داخل MPI_Init وهي نفس واجهة الاتصال التي تم إرجاعها بواسطة استدعاء الإنشاء الذي تم في العمليات الأصلية.

إذا لم يتم إنشاء العملية، فإن MPI_Comm_get_parent تُرجع MPI_COMM_NULL.

بعد تحرير أو قطع اتصال واجهة الاتصال الأصلية، تُرجع MPI_Comm_get_parent MPI_COMM_NULL.

ملاحظات

تُرجع MPI_Comm_get_parent معرّفاً لواجهة اتصال واحدة. سيؤدي استدعاء MPI_Comm_get_parent مرة ثانية إلى إرجاع معرّف لنفس واجهة الاتصال. سيؤدي تحرير المعرّف باستخدام MPI_Comm_disconnect أو MPI_Comm_free إلى جعل الإشارات الأخرى لواجهة الاتصال غير صالحة (معلقة). لاحظ أن استدعاء MPI_Comm_free على واجهة الاتصال الأصلية ليس مفيدًا.

الأخطاء

تقريباً جميع روتينات MPI تُرجع قيمة خطأ؛ روتينات C كناتج للدالة وروتينات Fortran في الوسيط الأخير.

قبل إرجاع قيمة الخطأ، يتم استدعاء معالج الخطأ MPI الحالي المرتبط بـ "كائن الاتصال" (مثل، واجهة الاتصال، النافذة، الملف). إذا لم يكن هناك "كائن اتصال" مرتبط باستدعاء MPI، فسيتم اعتبار الاستدعاء مرتبطًا بـ MPI_COMM_SELF وسيتم استدعاء معالج الخطأ MPI المرتبط. عندما لا تكون MPI_COMM_SELF مهيأة (أي، قبل MPI_Init/MPI_Init_thread، بعد MPI_Finalize، أو عند استخدام نموذج الجلسات حصريًا) يثير الخطأ معالج الخطأ الأولي. يمكن تغيير معالج الخطأ الأولي عن طريق استدعاء MPI_Comm_set_errhandler على MPI_COMM_SELF عند استخدام نموذج العالم، أو الوسيط المساعد `mpi_initial_errhandler` إلى mpiexec أو مفتاح المعلومات إلى MPI_Comm_spawn/MPI_Comm_spawn_multiple. إذا لم يتم تعيين أي معالج خطأ مناسب آخر، فسيتم استدعاء معالج الخطأ MPI_ERRORS_RETURN لوظائف MPI I/O وسيتم استدعاء معالج الخطأ MPI_ERRORS_ABORT لجميع وظائف MPI الأخرى.

تتضمن Open MPI ثلاثة معالجات أخطاء مسبقة يمكن استخدامها:

  • MPI_ERRORS_ARE_FATAL يتسبب في إنهاء البرنامج لجميع عمليات MPI المتصلة.
  • MPI_ERRORS_ABORT معالج خطأ يمكن استدعاؤه على واجهة اتصال، نافذة، ملف، أو جلسة. عند استدعائه على واجهة اتصال، يتصرف كما لو تم استدعاء MPI_Abort على تلك الواجهة. عند استدعائه على نافذة أو ملف، يتصرف كما لو تم استدعاء MPI_Abort على واجهة اتصال تحتوي على مجموعة العمليات في النافذة أو الملف المقابل. عند استدعائه على جلسة، يؤدي ذلك إلى إنهاء العملية المحلية فقط.
  • MPI_ERRORS_RETURN يرجع رمز خطأ إلى التطبيق.

يمكن لتطبيقات MPI أيضًا تنفيذ معالجات أخطاء خاصة بها عن طريق استدعاء:

  • MPI_Comm_create_errhandler ثم MPI_Comm_set_errhandler
  • MPI_File_create_errhandler ثم MPI_File_set_errhandler
  • MPI_Session_create_errhandler ثم MPI_Session_set_errhandler أو عند MPI_Session_init
  • MPI_Win_create_errhandler ثم MPI_Win_set_errhandler

لاحظ أن MPI لا تضمن أن برنامج MPI يمكن أن يستمر بعد خطأ.
