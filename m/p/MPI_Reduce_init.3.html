MPI_REDUCE_INIT(3) Open MPI MPI_REDUCE_INIT(3)

MPI_Reduce, MPI_Ireduce, MPI_Reduce_init - تقليل القيم على جميع العمليات ضمن مجموعة.

               MPI_Datatype datatype, MPI_Op op, int root,

int MPI_Ireduce(const void *sendbuf, void *recvbuf, int count,
                MPI_Datatype datatype, MPI_Op op, int root,
                MPI_Comm comm, MPI_Request *request)
int MPI_Reduce_init(const void *sendbuf, void *recvbuf, int count,
                MPI_Datatype datatype, MPI_Op op, int root,
                MPI_Comm comm, MPI_Info info, MPI_Request *request)

معاملات الإدخال

  • sendbuf: عنوان مخزن الإرسال (اختياري).
  • count: عدد العناصر في مخزن الإرسال (عدد صحيح).
  • datatype: نوع بيانات عناصر مخزن الإرسال (مقبض).
  • op: عملية التقليل (مقبض).
  • root: رتبة عملية الجذر (عدد صحيح).
  • comm: المتصل (مقبض).
  • info: معلومات (مقبض، دائم).

معاملات الإخراج

  • recvbuf: عنوان مخزن الاستقبال (اختياري، مهم فقط عند الجذر).
  • request: طلب (مقبض، فقط غير متزامن).
  • ierror: Fortran فقط: حالة الخطأ (عدد صحيح).

الوصف

تقوم دوال التقليل العامة (MPI_Reduce، MPI_Op_create، MPI_Op_free، MPI_Allreduce، MPI_Reduce_scatter، MPI_Scan) بإجراء عملية تقليل عامة (مثل المجموع، الحد الأقصى، AND المنطقية، إلخ) عبر جميع أعضاء المجموعة. يمكن أن تكون عملية التقليل إما واحدة من قائمة محددة مسبقًا من العمليات، أو عملية معرفة من قبل المستخدم. تأتي دوال التقليل العامة في عدة أشكال: تقليل يعيد نتيجة التقليل في عقدة واحدة، تقليل شامل يعيد هذه النتيجة في جميع العقد، وعملية مسح (بادئة متوازية). بالإضافة إلى ذلك، تجمع عملية التقليل والتشتيت بين وظائف عملية التقليل وعملية التشتيت.

MPI_Reduce تجمع العناصر المقدمة في مخزن الإدخال لكل عملية في المجموعة، باستخدام العملية op، وتعيد القيمة المجمعة في مخزن الإخراج للعملية ذات الرتبة root. يتم تعريف مخزن الإدخال بواسطة الوسائط sendbuf، count، و datatype؛ يتم تعريف مخزن الإخراج بواسطة الوسائط recvbuf، count، و datatype؛ كلاهما لهما نفس عدد العناصر، مع نفس النوع. يتم استدعاء الروتين من قبل جميع أعضاء المجموعة باستخدام نفس الوسائط لـ count، datatype، op، root، و comm. وبالتالي، توفر جميع العمليات مخازن إدخال ومخازن إخراج بنفس الطول، مع عناصر من نفس النوع. يمكن لكل عملية توفير عنصر واحد، أو سلسلة من العناصر، وفي هذه الحالة يتم تنفيذ عملية الدمج عنصرًا بعنصر على كل إدخال في السلسلة. على سبيل المثال، إذا كانت العملية هي MPI_MAX ومخزن الإرسال يحتوي على عنصرين من أرقام الفاصلة العائمة (count = 2 و datatype = MPI_FLOAT)، فإن recvbuf(1) = global max (sendbuf(1)) و recvbuf(2) = global max(sendbuf(2)).

استخدام خيار في المكان

عندما يكون المتصل عبارة عن متصل داخلي، يمكنك إجراء عملية تقليل في المكان (يتم استخدام مخزن الإخراج كمخزن إدخال). استخدم المتغير MPI_IN_PLACE كقيمة لـ sendbuf لعملية الجذر. في هذه الحالة، يتم أخذ بيانات الإدخال عند الجذر من مخزن الاستقبال، حيث سيتم استبدالها ببيانات الإخراج.

لاحظ أن MPI_IN_PLACE نوع خاص من القيم؛ له نفس القيود على استخدامه مثل MPI_BOTTOM.

نظرًا لأن خيار "في المكان" يحول مخزن الاستقبال إلى مخزن إرسال واستقبال، يجب على ربط Fortran الذي يتضمن INTENT وضع علامة عليها كـ INOUT، وليس OUT.

عندما يكون المتصل متصلاً بينيًا

عندما يكون المتصل عبارة عن متصل بيني، تجمع عملية الجذر في المجموعة الأولى البيانات من جميع العمليات في المجموعة الثانية ثم تجري عملية op. تحدد المجموعة الأولى عملية الجذر. تستخدم هذه العملية MPI_ROOT كقيمة لمعامل root الخاص بها. تستخدم العمليات المتبقية MPI_PROC_NULL كقيمة لمعامل root الخاص بها. تستخدم جميع العمليات في المجموعة الثانية رتبة عملية الجذر تلك في المجموعة الأولى كقيمة لمعامل root الخاص بها. تكون معاملات مخزن الإرسال فقط هي المهمة في المجموعة الثانية، وتكون معاملات مخزن الاستقبال فقط هي المهمة في عملية الجذر للمجموعة الأولى.

عمليات التقليل المعرفة مسبقًا

مجموعة العمليات المعرفة مسبقًا التي توفرها MPI مدرجة أدناه (عمليات التقليل المعرفة مسبقًا). يسرد هذا القسم أيضًا أنواع البيانات التي يمكن تطبيق العملية عليها. بالإضافة إلى ذلك، يمكن للمستخدمين تعريف عملياتهم الخاصة التي يمكن تحميلها بشكل زائد للعمل على أنواع بيانات متعددة، سواء كانت أساسية أو مشتقة. يتم شرح ذلك بشكل أكبر في وصف العمليات المعرفة من قبل المستخدم (انظر صفحات الدليل لـ MPI_Op_create و MPI_Op_free).

يفترض دائمًا أن العملية op تبادلية. يُفترض أيضًا أن جميع العمليات المعرفة مسبقًا تبادلية. يمكن للمستخدمين تعريف عمليات يفترض أنها تبادلية، ولكنها ليست تبادلية. يتم تحديد ترتيب التقييم "القياسي" للتقليل بواسطة رتب العمليات في المجموعة. ومع ذلك، يمكن للتنفيذ الاستفادة من التبادلية، أو التبادلية والتبادلية، لتغيير ترتيب التقييم. قد يؤدي هذا إلى تغيير نتيجة التقليل للعمليات التي ليست تبادلية وتبادلية تمامًا، مثل جمع الفاصلة العائمة.

تعمل المعاملات المعرفة مسبقًا فقط مع أنواع MPI المدرجة أدناه (عمليات التقليل المعرفة مسبقًا، وقسم MINLOC و MAXLOC، أدناه). قد تعمل المعاملات المعرفة من قبل المستخدم على أنواع بيانات عامة ومشتقة. في هذه الحالة، يكون كل معامل يتم تطبيق عملية التقليل عليه

MPI_Reduce_init(3) — Open MPI 5.0.9 Documentation

SYNTAX

      int MPI_Reduce_init(MPI_Comm comm, void *sendbuf, void *recvbuf,
                          int count, MPI_Datatype datatype, MPI_Op op,
                          int root, MPI_Info info, MPI_Request *request);

INPUT PARAMETERS

comm
Communicator (handle).
sendbuf
Address of send buffer (choice).
recvbuf
Address of receive buffer (choice).
count
Number of elements in buffer (non-negative integer).
datatype
Datatype of elements in buffer (handle).
op
Reduce operation (handle).
root
Rank of root process (integer).
info
Information hint (handle).
request
MPI request handle (handle).

OUTPUT PARAMETERS

request
MPI request handle (handle).

DESCRIPTION

This is a non-blocking version of MPI_Reduce. The MPI_Reduce_init function provides a mechanism to initiate a reduce operation and return immediately. The operation is specified by the arguments comm, sendbuf, recvbuf, count, datatype, op, and root. The info argument is currently unused and must be MPI_INFO_NULL.

The reduce operation is not performed immediately. Instead, a request handle is returned in request. The actual reduce operation will be performed when the request is completed by a call to MPI_Startall or MPI_Waitall.

The arguments to MPI_Reduce_init are identical to the arguments to MPI_Reduce.

The default binding for the comm communicator is the "world" communicator.

The MPI_Reduce_init function is the first in a family of three related functions: MPI_Reduce_init, MPI_Reduce_start, and MPI_Reduce_wait. This function is used to create a persistent reduce operation. The operation is not actually performed until MPI_Startall or MPI_Waitall is called. It is possible to start multiple reduce operations on the same communicator and the same request handle. It is also possible to call MPI_Reduce_init multiple times on the same communicator and the same request handle. In this case, the new arguments will be used for the next call to MPI_Startall or MPI_Waitall.

The MPI_Reduce_init function returns immediately. The actual reduce operation is performed when MPI_Startall or MPI_Waitall is called.

USE OF IN-PLACE OPTION

When a communicator is passed that has the same communicator as that in which the communicator is a subset of the original communicator, then the sendbuf and recvbuf arguments must be the same. In this case, the data is sent from the sendbuf and the result is placed back into the sendbuf. The sendbuf argument must be specified as MPI_IN_PLACE.

WHEN COMMUNICATOR IS AN INTER-COMMUNICATOR

When the communicator is an inter-communicator, then the root process must be specified as MPI_ROOT. The sendbuf and recvbuf arguments are only significant on the root process. On the non-root processes, the sendbuf argument must be specified as MPI_IN_PLACE.

PREDEFINED REDUCE OPERATIONS

The following reduce operations are predefined:

  • MPI_MAX
  • MPI_MIN
  • MPI_SUM
  • MPI_PROD
  • MPI_LAND
  • MPI_BAND
  • MPI_LOR
  • MPI_BOR
  • MPI_LXOR
  • MPI_BXOR
  • MPI_MAXLOC
  • MPI_MINLOC
  • MPI_REPLACE
  • MPI_NO_OP

MINLOC AND MAXLOC

The MPI_MAXLOC and MPI_MINLOC operations return both the maximum and minimum values, respectively, and the rank of the process that generated them. The datatype argument must be a struct containing two elements: the first element must be a numeric type, and the second element must be an integer type (typically MPI_INT).

NOTES ON COLLECTIVE OPERATIONS

Collective communication routines are not reentrant. That is, a process may not call a collective communication routine if it has a pending call to another collective communication routine.

The MPI_Reduce_init function is part of the MPI-3.0 standard.

ERRORS

When the value of comm is an invalid communicator or (when the Sessions Model is not used) when the value of info is invalid, the error is raised by the MPI library. All MPI routines return an error value of type int. The value is MPI_SUCCESS if the call was successful, or a negative value if an error occurred.

The MPI_ERR_ OTHER error code is the default error code that may be returned by functions that do not have a specific error code defined.

When using the Sessions Model exclusively, the error is raised by the initial error handler. The initial error handler can be changed by calling MPI_Comm_set_errhandler on MPI_COMM_SELF when using the World model, or the mpi_initial_errhandler CLI argument to mpiexec or info key to MPI_Comm_spawn/MPI_Comm_spawn_multiple. If no other appropriate error handler has been set, then the MPI_ERRORS_RETURN error handler is called for MPI I/O functions and the MPI_ERRORS_ABORT error handler is called for all other MPI functions.

Open MPI includes three predefined error handlers that can be used:

  • MPI_ERRORS_ARE_FATAL Causes the program to abort all connected MPI processes.
  • MPI_ERRORS_ABORT An error handler that can be invoked on a communicator, window, file, or session. When called on a communicator, it acts as if MPI_Abort was called on that communicator. If called on a window or file, acts as if MPI_Abort was called on a communicator containing the group of processes in the corresponding window or file. If called on a session, aborts only the local process.
  • MPI_ERRORS_RETURN Returns an error code to the application.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.
