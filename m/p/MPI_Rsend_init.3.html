MPI_Rsend_init(3)

الحزمة: openmpi

التراخيص: BSD-3-Clause AND LicenseRef-MPICH

MPI_RSEND_INIT(3) Open MPI MPI_RSEND_INIT(3)

MPI_Rsend_init — يبني مقبضًا للإرسال جاهز.

الصيغة

صيغة C

#include <mpi.h>
int MPI_Rsend_init(const void *buf, int count, MPI_Datatype datatype,
     int dest, int tag, MPI_Comm comm, MPI_Request *request)

صيغة Fortran

USE MPI
! أو الشكل الأقدم: INCLUDE 'mpif.h'
MPI_RSEND_INIT(BUF, COUNT, DATATYPE, DEST, TAG, COMM, REQUEST,
             IERROR)
     <type>  BUF(*)
     INTEGER COUNT, DATATYPE, DEST, TAG, COMM, REQUEST, IERROR

صيغة Fortran 2008

USE mpi_f08
MPI_Rsend_init(buf, count, datatype, dest, tag, comm, request, ierror)
     TYPE(*), DIMENSION(..), INTENT(IN), ASYNCHRONOUS :: buf
     INTEGER, INTENT(IN) :: count, dest, tag
     TYPE(MPI_Datatype), INTENT(IN) :: datatype
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(MPI_Request), INTENT(OUT) :: request
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

معلمات الإدخال

  • buf: العنوان الأولي لمخزن الإرسال (اختياري).
  • count: عدد العناصر المرسلة (عدد صحيح).
  • datatype: نوع كل عنصر (مقبض).
  • dest: رتبة الوجهة (عدد صحيح).
  • tag: علامة الرسالة (عدد صحيح).
  • comm: المتواصل (مقبض).

معلمات الإخراج

  • request: طلب الاتصال (مقبض).
  • ierror: Fortran فقط: حالة الخطأ (عدد صحيح).

الوصف

يقوم بإنشاء كائن اتصال مستمر لعملية إرسال في وضع الاستعداد، ويربط به جميع معاملات عملية الإرسال.

الاتصال (إرسال أو استقبال) الذي يستخدم طلبًا مستمرًا يتم بدءه بواسطة الدالة MPI_Start.

الأخطاء

تقوم جميع روتينات MPI تقريبًا بإرجاع قيمة خطأ؛ روتينات C كنتيجة إرجاع للدالة وروتينات Fortran في الوسيط الأخير.

قبل إرجاع قيمة الخطأ، يتم استدعاء معالج أخطاء MPI الحالي المرتبط بكائن الاتصال (مثل المتواصل، النافذة، الملف). إذا لم يكن هناك كائن اتصال مرتبط باستدعاء MPI، فإن الاستدعاء يعتبر ملحقًا بـ MPI_COMM_SELF وسيتم استدعاء معالج أخطاء MPI المرتبط به. عندما لا يتم تهيئة MPI_COMM_SELF (أي، قبل MPI_Init/MPI_Init_thread، بعد MPI_Finalize، أو عند استخدام نموذج الجلسات حصريًا) يثير الخطأ معالج الأخطاء الأولي. يمكن تغيير معالج الأخطاء الأولي عن طريق استدعاء MPI_Comm_set_errhandler على MPI_COMM_SELF عند استخدام نموذج العالم، أو وسيط سطر الأوامر mpi_initial_errhandler إلى mpiexec أو مفتاح معلومات إلى MPI_Comm_spawn/MPI_Comm_spawn_multiple. إذا لم يتم تعيين أي معالج أخطاء مناسب آخر، فسيتم استدعاء معالج الأخطاء MPI_ERRORS_RETURN لوظائف إدخال/إخراج MPI وسيتم استدعاء معالج الأخطاء MPI_ERRORS_ABORT لجميع وظائف MPI الأخرى.

تتضمن Open MPI ثلاثة معالجات أخطاء معرفة مسبقًا يمكن استخدامها:

  • MPI_ERRORS_ARE_FATAL يتسبب في إنهاء البرنامج لجميع عمليات MPI المتصلة.
  • MPI_ERRORS_ABORT معالج أخطاء يمكن استدعاؤه على متواصل، نافذة، ملف، أو جلسة. عند استدعائه على متواصل، يتصرف كما لو تم استدعاء MPI_Abort على ذلك المتواصل. عند استدعائه على نافذة أو ملف، يتصرف كما لو تم استدعاء MPI_Abort على متواصل يحتوي على مجموعة العمليات في النافذة أو الملف المقابل. عند استدعائه على جلسة، ينهي العملية المحلية فقط.
  • MPI_ERRORS_RETURN يرجع رمز خطأ إلى التطبيق.

يمكن لتطبيقات MPI أيضًا تنفيذ معالجات الأخطاء الخاصة بها عن طريق استدعاء:

  • MPI_Comm_create_errhandler ثم MPI_Comm_set_errhandler
  • MPI_File_create_errhandler ثم MPI_File_set_errhandler
  • MPI_Session_create_errhandler ثم MPI_Session_set_errhandler أو عند MPI_Session_init
  • MPI_Win_create_errhandler ثم MPI_Win_set_errhandler

لاحظ أن MPI لا يضمن أن برنامج MPI يمكن أن يستمر بعد خطأ.
