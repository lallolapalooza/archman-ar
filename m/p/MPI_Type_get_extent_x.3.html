MPI_Type_get_extent_x(3)

الحزمة: openmpi

التراخيص: BSD-3-Clause AND LicenseRef-MPICH

MPI_TYPE_GET_EXTENT_X(3) Open MPI MPI_TYPE_GET_EXTENT_X(3)

MPI_Type_get_extent, MPI_Type_get_extent_x - تُرجع الحد الأدنى والمدى لنوع بيانات.

الصيغة (SYNTAX)

صيغة C

#include <mpi.h>
int MPI_Type_get_extent(MPI_Datatype datatype, MPI_Aint *lb,
     MPI_Aint *extent)
int MPI_Type_get_extent_x(MPI_Datatype datatype, MPI_Count *lb,
     MPI_Count *extent)

صيغة فورتران

USE MPI
! أو الصيغة القديمة: INCLUDE 'mpif.h'
MPI_TYPE_GET_EXTENT(DATATYPE, LB, EXTENT, IERROR)
     INTEGER DATATYPE, IERROR
     INTEGER(KIND=MPI_ADDRESS_KIND) LB, EXTENT
MPI_TYPE_GET_EXTENT_X(DATATYPE, LB, EXTENT, IERROR)
     INTEGER DATATYPE, IERROR
     INTEGER(KIND=MPI_COUNT_KIND) LB, EXTENT

صيغة فورتران 2008

USE mpi_f08
MPI_Type_get_extent(datatype, lb, extent, ierror)
     TYPE(MPI_Datatype), INTENT(IN) :: datatype
     INTEGER(KIND=MPI_ADDRESS_KIND), INTENT(OUT) :: lb, extent
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror
MPI_Type_get_extent_x(datatype, lb, extent, ierror)
     TYPE(MPI_Datatype), INTENT(IN) :: datatype
     INTEGER(KIND = MPI_COUNT_KIND), INTENT(OUT) :: lb, extent
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

معامل الإدخال (INPUT PARAMETER)

•
datatype: نوع البيانات (مقبض).

معاملات الإخراج (OUTPUT PARAMETERS)

  • lb: الحد الأدنى لنوع البيانات (عدد صحيح).
  • extent: مدى نوع البيانات (عدد صحيح).
  • ierror: فورتران فقط: حالة الخطأ (عدد صحيح).

الوصف (DESCRIPTION)

تُرجع MPI_Type_get_extent الحد الأدنى والمدى لنوع البيانات datatype. لأي من الدالتين، إذا لم يتمكن المعامل lb أو extent من التعبير عن القيمة المراد إرجاعها (على سبيل المثال، إذا كان المعامل صغيرًا جدًا لاستيعاب قيمة الإخراج)، فسيتم تعيينه إلى MPI_UNDEFINED.

ملاحظة (NOTE)

يوصى بشدة باستخدام MPI_Type_get_extent بدلاً من وظائف MPI-1 القديمة MPI_Type_extent و MPI_Type_lb.

الأخطاء (ERRORS)

تقوم جميع روتينات MPI تقريبًا بإرجاع قيمة خطأ؛ روتينات C كنتيجة للدالة وروتينات فورتران في الوسيط الأخير.

قبل إرجاع قيمة الخطأ، يتم استدعاء معالج أخطاء MPI الحالي المرتبط بكيان الاتصال (مثل، المتصل، النافذة، الملف). إذا لم يكن هناك كيان اتصال مرتبط باستدعاء MPI، فيتم اعتبار الاستدعاء مرتبطًا بـ MPI_COMM_SELF وسيتم استدعاء معالج أخطاء MPI المرتبط. عندما لا يتم تهيئة MPI_COMM_SELF (أي، قبل MPI_Init/MPI_Init_thread، بعد MPI_Finalize، أو عند استخدام نموذج الجلسات حصريًا) يرفع الخطأ معالج الأخطاء الأولي. يمكن تغيير معالج الأخطاء الأولي عن طريق استدعاء MPI_Comm_set_errhandler على MPI_COMM_SELF عند استخدام نموذج العالم، أو الوسيط mpi_initial_errhandler إلى mpiexec أو مفتاح المعلومات إلى MPI_Comm_spawn/MPI_Comm_spawn_multiple. إذا لم يتم تعيين معالج أخطاء مناسب آخر، فسيتم استدعاء معالج الأخطاء MPI_ERRORS_RETURN لوظائف MPI I/O وسيتم استدعاء معالج الأخطاء MPI_ERRORS_ABORT لجميع وظائف MPI الأخرى.

يتضمن Open MPI ثلاثة معالجات أخطاء محددة مسبقًا يمكن استخدامها:

  • MPI_ERRORS_ARE_FATAL يتسبب في إنهاء البرنامج لجميع عمليات MPI المتصلة.
  • MPI_ERRORS_ABORT معالج أخطاء يمكن استدعاؤه على متصل، نافذة، ملف، أو جلسة. عند استدعائه على متصل، يتصرف كما لو تم استدعاء MPI_Abort على هذا المتصل. عند استدعائه على نافذة أو ملف، يتصرف كما لو تم استدعاء MPI_Abort على مجموعة من العمليات في النافذة أو الملف المقابل. عند استدعائه على جلسة، يقوم بإنهاء العملية المحلية فقط.
  • MPI_ERRORS_RETURN يُرجع رمز خطأ إلى التطبيق.

يمكن لتطبيقات MPI أيضًا تنفيذ معالجات أخطاء خاصة بها عن طريق استدعاء:

  • MPI_Comm_create_errhandler ثم MPI_Comm_set_errhandler
  • MPI_File_create_errhandler ثم MPI_File_set_errhandler
  • MPI_Session_create_errhandler ثم MPI_Session_set_errhandler أو عند MPI_Session_init
  • MPI_Win_create_errhandler ثم MPI_Win_set_errhandler

لاحظ أن MPI لا يضمن أن برنامج MPI يمكن أن يستمر بعد وقوع خطأ.
