MPI_Buffer_detach(3)

الحزمة: openmpi

التراخيص: BSD-3-Clause AND LicenseRef-MPICH

MPI_BUFFER_DETACH(3) Open MPI MPI_BUFFER_DETACH(3)

MPI_Buffer_detach — يزيل المخزن المؤقت الحالي (للاستخدام في MPI_Bsend، إلخ)

الصيغة (SYNTAX)

صيغة C (C Syntax)

#include <mpi.h>
int MPI_Buffer_detach(void *buf, int *size)

صيغة Fortran (Fortran Syntax)

USE MPI
! أو الشكل الأقدم: INCLUDE 'mpif.h'
MPI_BUFFER_DETACH(BUF, SIZE, IERROR)
    <type>  BUF(*)
    INTEGER SIZE, IERROR

صيغة Fortran 2008 (Fortran 2008 Syntax)

USE mpi_f08
MPI_Buffer_detach(buffer_addr, size, ierror)
    USE, INTRINSIC :: ISO_C_BINDING, ONLY
    TYPE(C_PTR), INTENT(OUT) :: buffer_addr
    INTEGER, INTENT(OUT) :: size
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror

معلمات الإخراج (OUTPUT PARAMETERS)

  • buf : عنوان المخزن المؤقت الأولي (اختياري).
  • size : حجم المخزن المؤقت، بالبايت (عدد صحيح).
  • ierror : Fortran فقط: حالة الخطأ (عدد صحيح).

الوصف (DESCRIPTION)

فصل المخزن المؤقت المرتبط حاليًا بـ MPI. تقوم الاستدعاءة بإرجاع عنوان وحجم المخزن المؤقت المفصول. ستتوقف هذه العملية حتى يتم إرسال جميع الرسائل الموجودة حاليًا في المخزن المؤقت. عند عودة هذه الدالة، قد يعيد المستخدم استخدام مساحة المخزن المؤقت أو يخصصها.

مثال: استدعاءات لربط وفصل المخازن المؤقتة.

#define BUFFSIZE 10000
int size char *buff;
MPI_Buffer_attach( malloc(BUFFSIZE), BUFFSIZE);
// يمكن الآن استخدام مخزن مؤقت بحجم 10000 بايت بواسطة MPI_Bsend
MPI_Buffer_detach( &buff, &size); // تم تقليص حجم المخزن المؤقت إلى صفر
MPI_Buffer_attach( buff, size); // المخزن المؤقت بحجم 10000 بايت متاح مرة أخرى

ملاحظات (NOTES)

السبب في أن MPI_Buffer_detach تُرجع عنوان وحجم المخزن المؤقت الذي يتم فصله هو السماح للمكتبات المتداخلة باستبدال المخزن المؤقت واستعادته. على سبيل المثال، تخيل

int size, mysize, idummy;
void *ptr, *myptr, *dummy;
MPI_Buffer_detach( &ptr, &size );
MPI_Buffer_attach( myptr, mysize );
/* ... كود المكتبة ... */
MPI_Buffer_detach( &dummy, &idummy );
MPI_Buffer_attach( ptr, size );

هذا يشبه إلى حد كبير إجراء روتين الإشارة في UNIX ولديه نفس نقاط القوة (إنه بسيط) ونقاط الضعف (إنه يعمل فقط للاستخدامات المتداخلة).

بالنسبة لـ Fortran: ربط Fortran لهذه الروتين مختلف. نظرًا لعدم وجود مؤشرات في Fortran، فمن المستحيل توفير طريقة لاستخدام مخرجات هذه الروتين لتبادل المخازن المؤقتة. في هذه الحالة، يتم تعيين حقل الحجم فقط.

بالنسبة لـ C: على الرغم من أن وسيطة buf معرّفة كـ void، إلا أنها في الواقع عنوان لمؤشر void. انظر التبرير (Rationale)، أدناه، لمزيد من التفاصيل.

حتى على الرغم من أن وظائف C MPI_Buffer_attach و MPI_Buffer_detach كلتاهما لديها وسيطة أولى من نوع void*، يتم استخدام هذه الوسائط بشكل مختلف: يتم تمرير مؤشر إلى المخزن المؤقت إلى MPI_Buffer_attach؛ يتم تمرير عنوان المؤشر إلى MPI_Buffer_detach، بحيث يمكن لهذا الاستدعاء إرجاع قيمة المؤشر.

الأخطاء (ERRORS)

تقريبًا جميع روتينات MPI تُرجع قيمة خطأ؛ وظائف C كالنتيجة المرتجعة للدالة ووظائف Fortran في الوسيطة الأخيرة.

قبل إرجاع قيمة الخطأ، يتم استدعاء معالج الخطأ MPI الحالي المرتبط بكيان الاتصال (على سبيل المثال، المتصل، النافذة، الملف). إذا لم يكن هناك كيان اتصال مرتبط باستدعاء MPI، فسيتم اعتبار الاستدعاء مرتبطًا بـ MPI_COMM_SELF وسيتم استدعاء معالج الخطأ المرتبط. عندما لا يتم تهيئة MPI_COMM_SELF (أي، قبل MPI_Init/MPI_Init_thread، بعد MPI_Finalize، أو عند استخدام نموذج الجلسات حصريًا)، يثير الخطأ معالج الخطأ الأولي. يمكن تغيير معالج الخطأ الأولي عن طريق استدعاء MPI_Comm_set_errhandler على MPI_COMM_SELF عند استخدام نموذج العالم، أو وسيطة سطر الأوامر mpi_initial_errhandler إلى mpiexec أو مفتاح المعلومات إلى MPI_Comm_spawn/MPI_Comm_spawn_multiple. إذا لم يتم تعيين أي معالج خطأ مناسب آخر، فسيتم استدعاء معالج الخطأ MPI_ERRORS_RETURN لوظائف MPI I/O وسيتم استدعاء معالج الخطأ MPI_ERRORS_ABORT لجميع وظائف MPI الأخرى.

تتضمن Open MPI ثلاثة معالجات أخطاء مُعرفة مسبقًا يمكن استخدامها:

  • MPI_ERRORS_ARE_FATAL يؤدي إلى إنهاء البرنامج لجميع عمليات MPI المتصلة.
  • MPI_ERRORS_ABORT معالج خطأ يمكن استدعاؤه على متصل، نافذة، ملف، أو جلسة. عند استدعائه على متصل، يتصرف كما لو تم استدعاء MPI_Abort على هذا المتصل. عند استدعائه على نافذة أو ملف، يتصرف كما لو تم استدعاء MPI_Abort على مجموعة من العمليات في النافذة أو الملف المقابل. عند استدعائه على جلسة، يقوم بإنهاء العملية المحلية فقط.
  • MPI_ERRORS_RETURN يُرجع رمز خطأ إلى التطبيق.

يمكن لتطبيقات MPI أيضًا تنفيذ معالجات الأخطاء الخاصة بها عن طريق الاستدعاء:

  • MPI_Comm_create_errhandler ثم MPI_Comm_set_errhandler
  • MPI_File_create_errhandler ثم MPI_File_set_errhandler
  • MPI_Session_create_errhandler ثم MPI_Session_set_errhandler أو في MPI_Session_init
  • MPI_Win_create_errhandler ثم MPI_Win_set_errhandler

لاحظ أن MPI لا يضمن أن برنامج MPI يمكن أن يستمر بعد الخطأ.
