MPI_Request_get_status(3)

الحزمة: openmpi

التراخيص: BSD-3-Clause AND LicenseRef-MPICH

MPI_Request_get_status(3) Open MPI MPI_Request_get_status(3)

MPI_Request_get_status — الوصول إلى المعلومات المرتبطة بطلب دون تحرير الطلب.

صيغة الاستدعاء (SYNTAX)

صيغة C (C Syntax)

#include <mpi.h>
int MPI_Request_get_status(MPI_Request request, int *flag, MPI_Status *status)

صيغة Fortran (Fortran Syntax)

USE MPI
! أو الصيغة القديمة: INCLUDE 'mpif.h'
MPI_REQUEST_GET_STATUS(REQUEST, FLAG, STATUS, IERROR)
     INTEGER REQUEST, STATUS(MPI_STATUS_SIZE), IERROR
     LOGICAL FLAG

صيغة Fortran 2008 (Fortran 2008 Syntax)

USE mpi_f08
MPI_Request_get_status(request, flag, status, ierror)
     TYPE(MPI_Request), INTENT(IN) :: request
     LOGICAL, INTENT(OUT) :: flag
     TYPE(MPI_Status) :: status
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

معلمة الإدخال (INPUT PARAMETER)

•
request: طلب الاتصال (مقبض).

معلمات الإخراج (OUTPUT PARAMETERS)

  • flag: علم منطقي، نفس الشيء كما في MPI_Test (منطقي).
  • status: كائن MPI_Status إذا كان العلم صحيحًا (الحالة).

الوصف (DESCRIPTION)

MPI_Request_get_status يضبط flag = true إذا كان العملية مكتملة أو يضبط flag = false إذا لم تكن مكتملة. إذا كانت العملية مكتملة، فإنه يعيد في status حالة الطلب. لا يقوم بتحرير أو تعطيل الطلب؛ يجب تنفيذ استدعاء لاحق لـ test أو wait أو free بهذا الطلب.

إذا كان تطبيقك لا يحتاج إلى فحص حقل status، فيمكنك توفير الموارد باستخدام الثابت المعرف مسبقًا MPI_STATUS_IGNORE كقيمة خاصة لمعلمة status.

الأخطاء (ERRORS)

تقريبًا جميع روتينات MPI تعيد قيمة خطأ؛ روتينات C كناتج إرجاع للدالة وروتينات Fortran في المعلمة الأخيرة.

قبل إرجاع قيمة الخطأ، يتم استدعاء معالج أخطاء MPI الحالي المرتبط بـ كائن الاتصال (مثل، المجمع، النافذة، الملف). إذا لم يكن هناك كائن اتصال مرتبط باستدعاء MPI، فيتم اعتبار الاستدعاء مرتبطًا بـ MPI_COMM_SELF وسيتم استدعاء معالج الأخطاء MPI المرتبط. عندما لا يكون MPI_COMM_SELF مهيئًا (أي، قبل MPI_Init/MPI_Init_thread، بعد MPI_Finalize، أو عند استخدام نموذج الجلسات حصريًا) يثير الخطأ معالج الأخطاء الأولي. يمكن تغيير معالج الأخطاء الأولي عن طريق استدعاء MPI_Comm_set_errhandler على MPI_COMM_SELF عند استخدام نموذج العالم، أو الوسيطة CLI mpi_initial_errhandler إلى mpiexec أو مفتاح معلومات لـ MPI_Comm_spawn/MPI_Comm_spawn_multiple. إذا لم يتم تعيين معالج خطأ مناسب آخر، فسيتم استدعاء معالج أخطاء MPI_ERRORS_RETURN لوظائف إدخال/إخراج MPI وسيتم استدعاء معالج أخطاء MPI_ERRORS_ABORT لجميع وظائف MPI الأخرى.

تتضمن Open MPI ثلاثة معالجات أخطاء معرفة مسبقًا يمكن استخدامها:

  • MPI_ERRORS_ARE_FATAL يتسبب في إنهاء البرنامج لجميع عمليات MPI المتصلة.
  • MPI_ERRORS_ABORT معالج خطأ يمكن استدعاؤه على مجمع، نافذة، ملف، أو جلسة. عند استدعائه على مجمع، يعمل كما لو تم استدعاء MPI_Abort على هذا المجمع. عند استدعائه على نافذة أو ملف، يعمل كما لو تم استدعاء MPI_Abort على مجمع يحتوي على مجموعة العمليات في النافذة أو الملف المقابل. عند استدعائه على جلسة، ينهي العملية المحلية فقط.
  • MPI_ERRORS_RETURN يعيد رمز خطأ إلى التطبيق.

يمكن لتطبيقات MPI أيضًا تنفيذ معالجات الأخطاء الخاصة بها عن طريق استدعاء:

  • MPI_Comm_create_errhandler ثم MPI_Comm_set_errhandler
  • MPI_File_create_errhandler ثم MPI_File_set_errhandler
  • MPI_Session_create_errhandler ثم MPI_Session_set_errhandler أو عند MPI_Session_init
  • MPI_Win_create_errhandler ثم MPI_Win_set_errhandler

لاحظ أن MPI لا تضمن أن برنامج MPI يمكن أن يستمر بعد خطأ.
