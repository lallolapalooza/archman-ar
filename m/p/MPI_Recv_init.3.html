MPI_Recv_init(3)

الحزمة: openmpi

التراخيص: BSD-3-Clause AND LicenseRef-MPICH

MPI_RECV_INIT(3) Open MPI MPI_RECV_INIT(3)

MPI_Recv_init — يبني مؤشرًا لعملية استلام.

الصياغة

صياغة C

#include <mpi.h>
int MPI_Recv_init(void *buf, int count, MPI_Datatype datatype,
     int source, int tag, MPI_Comm comm, MPI_Request *request)

صياغة Fortran

USE MPI
! أو الشكل الأقدم: INCLUDE 'mpif.h'
MPI_RECV_INIT(BUF, COUNT, DATATYPE, SOURCE, TAG, COMM, REQUEST,
             IERROR)
     <type>  BUF(*)
     INTEGER COUNT, DATATYPE, SOURCE, TAG, COMM, REQUEST, IERROR

صياغة Fortran 2008

USE mpi_f08
MPI_Recv_init(buf, count, datatype, source, tag, comm, request, ierror)
     TYPE(*), DIMENSION(..), ASYNCHRONOUS :: buf
     INTEGER, INTENT(IN) :: count, source, tag
     TYPE(MPI_Datatype), INTENT(IN) :: datatype
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(MPI_Request), INTENT(OUT) :: request
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

معاملات الإدخال

  • count: الحد الأقصى لعدد العناصر المراد استقبالها (عدد صحيح).
  • datatype: نوع كل عنصر (مؤشر).
  • source: رتبة المصدر (عدد صحيح).
  • tag: وسم الرسالة (عدد صحيح).
  • comm: المتواصل (مؤشر).

معامل الإدخال/الإخراج

•
buf: العنوان الأولي لمخزن الاستقبال المؤقت (اختياري).

معاملات الإخراج

  • request: طلب الاتصال (مؤشر).
  • ierror: Fortran فقط: حالة الخطأ (عدد صحيح).

الوصف

تنشئ طلب اتصال دائم لعملية استقبال. يتم تمييز المعامل buf بأنه OUT (خارج) لأن المستخدم يمنح الإذن بالكتابة على مخزن الاستقبال المؤقت عن طريق تمرير المعامل إلى MPI_Recv_init.

يكون طلب الاتصال الدائم غير نشط بعد إنشائه — لا يتم ربط أي اتصال نشط بالطلب.

يتم بدء الاتصال (إرسال أو استقبال) الذي يستخدم طلبًا دائمًا بواسطة الدالة MPI_Start أو MPI_Startall.

الأخطاء

تقريبًا جميع روتينات MPI تُرجع قيمة خطأ؛ روتينات C كنتيجة للإرجاع للدالة، وروتينات Fortran في المعامل الأخير.

قبل أن يتم إرجاع قيمة الخطأ، يتم استدعاء معالج أخطاء MPI الحالي المرتبط بكائن الاتصال (مثل المتواصل، النافذة، الملف). إذا لم يكن هناك كائن اتصال مرتبط باستدعاء MPI، فسيتم اعتبار الاستدعاء مرتبطًا بـ MPI_COMM_SELF وسيستدعي معالج الخطأ المرتبط. عندما لا يتم تهيئة MPI_COMM_SELF (أي، قبل MPI_Init/MPI_Init_thread، بعد MPI_Finalize، أو عند استخدام نموذج الجلسات حصريًا) يرفع الخطأ معالج الخطأ الأولي. يمكن تغيير معالج الخطأ الأولي عن طريق استدعاء MPI_Comm_set_errhandler على MPI_COMM_SELF عند استخدام نموذج العالم، أو وسيطة سطر الأوامر mpi_initial_errhandler إلى mpiexec أو مفتاح معلومات إلى MPI_Comm_spawn/MPI_Comm_spawn_multiple. إذا لم يتم تعيين معالج خطأ مناسب آخر، فسيتم استدعاء معالج الخطأ MPI_ERRORS_RETURN لوظائف إدخال/إخراج MPI، وسيتم استدعاء معالج الخطأ MPI_ERRORS_ABORT لجميع وظائف MPI الأخرى.

يتضمن Open MPI ثلاثة معالجات أخطاء معرفة مسبقًا يمكن استخدامها:

  • MPI_ERRORS_ARE_FATAL يؤدي إلى إنهاء البرنامج لجميع عمليات MPI المتصلة.
  • MPI_ERRORS_ABORT معالج خطأ يمكن استدعاؤه على متواصل، نافذة، ملف، أو جلسة. عند استدعائه على متواصل، يتصرف كما لو تم استدعاء MPI_Abort على هذا المتواصل. إذا تم استدعاؤه على نافذة أو ملف، يتصرف كما لو تم استدعاء MPI_Abort على متواصل يحتوي على مجموعة العمليات في النافذة أو الملف المقابل. إذا تم استدعاؤه على جلسة، فإنه ينهي العملية المحلية فقط.
  • MPI_ERRORS_RETURN يُرجع رمز خطأ إلى التطبيق.

يمكن لتطبيقات MPI أيضًا تنفيذ معالجات الأخطاء الخاصة بها عن طريق استدعاء:

  • MPI_Comm_create_errhandler ثم MPI_Comm_set_errhandler
  • MPI_File_create_errhandler ثم MPI_File_set_errhandler
  • MPI_Session_create_errhandler ثم MPI_Session_set_errhandler أو في MPI_Session_init
  • MPI_Win_create_errhandler ثم MPI_Win_set_errhandler

لاحظ أن MPI لا تضمن أن برنامج MPI يمكن أن يستمر بعد حدوث خطأ.
