MPI_Scatterv_init(3)

الحزمة: openmpi

التراخيص: BSD-3-Clause AND LicenseRef-MPICH

SYNTAX

The MPI routines described here allow a process to send data to itself.

MPI_Scatterv_init

  C Call:
    int MPI_Scatterv_init(MPI_Comm comm, const void *sendbuf, const int *sendcounts, const int *displs, MPI_Datatype sendtype, void *recvbuf, int recvcount, MPI_Datatype recvtype, int root, MPI_Info info, MPI_Request *request)

  Fortran Call:
    SUBROUTINE MPI_Scatterv_init(comm, sendbuf, sendcounts, displs, sendtype, recvbuf, recvcount, recvtype, root, info, request, ierror)
        INTEGER :: comm, sendcounts(*), displs(*), sendtype, recvcount, recvtype, root, ierror
        INTEGER, DIMENSION(..) :: sendbuf, recvbuf
        TYPE(MPI_Info) :: info
        INTEGER(KIND=MPI_ADDRESS_KIND) :: request

INPUT PARAMETERS

comm
Communicator with all participating processes (handle).
sendbuf
Address of the send buffer (choice).
sendcounts
Array of integers specifying the number of elements to send to each process (array of integers).
displs
Array of integers specifying the displacements (in number of elements) of the start of the data for each process (array of integers).
sendtype
Datatype of the elements in the send buffer (handle).
recvbuf
Address of the receive buffer (choice).
recvcount
Number of elements in the receive buffer (integer).
recvtype
Datatype of the elements in the receive buffer (handle).
root
Rank of the root process (integer).
info
Implementation advice (handle).

OUTPUT PARAMETERS

request
Communication request (handle).
ierror
Fortran only: Fortran return code. A value of MPI_SUCCESS indicates success.

DESCRIPTION

Initializes a non-blocking scatterv operation. This operation is similar to MPI_Scatterv, but it returns an MPI request handle that can be used to reference the operation.

The root process specifies the send buffer and the counts and displacements for each process. All processes specify a receive buffer and the count and datatype for receiving data.

The root process will send the data specified by sendcounts and displs arguments to each process in the communicator. The data sent to process j will be the elements starting at offset displs[j] and consisting of sendcounts[j] elements of type sendtype.

All processes receive data from the root process into the recvbuf argument. The number of elements received is recvcount and the datatype is recvtype.

The arguments sendbuf, sendtype, recvbuf, and recvtype are significant only at the root. The arguments recvbuf, recvcount, and recvtype are significant at all processes. The communicator comm and the root must be the same for all processes.

The info argument is used to provide hints to the MPI implementation about how to perform the operation. This can include information about buffering or communication patterns.

The operation is completed when MPI_Wait is called on the returned request handle.

USE OF IN-PLACE OPTION

When a communicator is used for this operation, all processes in the communicator must use the same value for the root argument. This value is the rank of the process in the communicator that is acting as the root. All processes must have the same value for the receive buffer argument of the receive-into calls. The receive buffer argument of the root process must be consistent with the send buffer argument of the root process.

If the recvbuf argument is the same as the sendbuf argument, the operation is called "in-place". This means that the data is received into the same buffer from which it was sent. This is only allowed if the sendbuf argument is the same for all processes. The sendbuf argument must be consistent with the recvbuf argument at the root.

Note that MPI_IN_PLACE is a special kind of value; it has the same restrictions on its use as MPI_BOTTOM.

Because the in-place option converts the receive buffer into a send-and-receive buffer, a Fortran binding that includes INTENT must mark these as INOUT, not OUT.

WHEN COMMUNICATOR IS AN INTER-COMMUNICATOR

When the communicator is an inter-communicator, the root process in the first group sends data to all processes in the second group. The first group defines the root process. That process uses MPI_ROOT as the value of its root argument. The remaining processes use MPI_PROC_NULL as the value of their root argument. All processes in the second group use the rank of that root process in the first group as the value of their root argument. The receive buffer argument of the root process in the first group must be consistent with the receive buffer argument of the processes in the second group.

ERRORS

Almost all MPI routines return an error value; C routines as the return result of the function and Fortran routines in the last argument.

Before the error value is returned, the current MPI error handler associated with the communication object (e.g., communicator, window, file) is called. If no communication object is associated with the MPI call, then the call is considered attached to MPI_COMM_SELF and will call the associated MPI error handler. When MPI_COMM_SELF is not initialized (i.e., before MPI_Init/MPI_Init_thread, after MPI_Finalize, or when using the Sessions Model exclusively) the error raises the initial error handler. The initial error handler can be changed by calling MPI_Comm_set_errhandler on MPI_COMM_SELF when using the World model, or the mpi_initial_errhandler CLI argument to mpiexec or info key to MPI_Comm_spawn/MPI_Comm_spawn_multiple. If no other appropriate error handler has been set, then the MPI_ERRORS_RETURN error handler is called for MPI I/O functions and the MPI_ERRORS_ABORT error handler is called for all other MPI functions.

Open MPI includes three predefined error handlers that can be used:

  • MPI_ERRORS_ARE_FATAL Causes the program to abort all connected MPI processes.
  • MPI_ERRORS_ABORT An error handler that can be invoked on a communicator, window, file, or session. When called on a communicator, it acts as if MPI_Abort was called on that communicator. If called on a window or file, acts as if MPI_Abort was called on a communicator containing the group of processes in the corresponding window or file. If called on a session, aborts only the local process.
  • MPI_ERRORS_RETURN Returns an error code to the application.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.
