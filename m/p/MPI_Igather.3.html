معلمات الإدخال

  • sendbuf : عنوان مخزن الإرسال (اختياري).
  • sendcount : عدد العناصر في مخزن الإرسال (عدد صحيح).
  • sendtype : نوع العناصر في مخزن الإرسال (مقبض).
  • recvcount : عدد العناصر لأي استقبال (عدد صحيح، له معنى فقط في العملية الجذر).
  • recvtype : نوع العناصر في مخزن الاستقبال (مقبض، له معنى فقط في العملية الجذر).
  • root : ترتيب عملية الاستقبال (عدد صحيح).
  • comm : الموصل (مقبض).
  • info : معلومات (مقبض، دائم).

الوصف

ترسل كل عملية (بما في ذلك العملية الجذر) محتويات مخزن الإرسال الخاص بها إلى عملية الجذر. تستقبل العملية الجذر الرسائل وتخزنها بترتيب ترتيبها. والنتيجة هي كما لو أن كل من العمليات n في المجموعة (بما في ذلك العملية الجذر) قد نفذت استدعاءً لـ

MPI_Send(sendbuf, sendcount, sendtype, root, ...)

وأن العملية الجذر قد نفذت n استدعاءات لـ

MPI_Recv(recfbuf + i * recvcount * extent(recvtype), recvcount,
         recvtype, i, ...)

حيث extent(recvtype) هو حجم النوع الذي تم الحصول عليه من استدعاء لـ MPI_Type_extent.

وصف بديل هو أن الرسائل n المرسلة من عمليات المجموعة يتم تسلسلها بترتيب الترتيب، ويتم استقبال الرسالة الناتجة بواسطة العملية الجذر كما لو تم استدعاء MPI_Recv(recvbuf, recvcount * n, recvtype, ...).

يتم تجاهل مخزن الاستقبال بواسطة جميع العمليات غير الجذر.

تسمح الأنواع المشتقة لكل من sendtype و recvtype. يجب أن يكون توقيع النوع لـ sendcount و sendtype في العملية i هو نفسه توقيع النوع لـ recvcount و recvtype في العملية الجذر. هذا يعني أن حجم البيانات المرسلة يجب أن يساوي حجم البيانات المستقبلة، زوجًا بين كل عملية والعملية الجذر. تسمح خرائط الأنواع المختلفة بين المرسل والمستقبل.

جميع الوسائط للدالة لها معنى في العملية الجذر، بينما في العمليات الأخرى، فقط الوسائط sendbuf و sendcount و sendtype و root و comm لها معنى. يجب أن تكون الوسائط root و comm لها نفس القيم في جميع العمليات.

يجب ألا يتسبب تحديد العدادات والأنواع في كتابة أي موقع في العملية الجذر أكثر من مرة. هذه الدعوة خاطئة. لاحظ أن الوسيط recvcount في العملية الجذر يشير إلى عدد العناصر التي يستقبلها من كل عملية، وليس العدد الإجمالي للعناصر التي يستقبلها.

المثال 1: جمع 100 عدد صحيح من كل عملية في المجموعة إلى الجذر.

MPI_Comm comm;
int gsize, sendarray[100];
int root, * rbuf;
...
MPI_Comm_size( comm, &gsize);
rbuf = (int*)malloc(gsize * 100 * sizeof(int));
MPI_Gather( sendarray, 100, MPI_INT, rbuf, 100, MPI_INT, root, comm);

المثال 2: المثال السابق المعدل — الجذر فقط يخصص ذاكرة لمخزن الاستقبال.

MPI_Comm comm;
int gsize, sendarray[100];
int root, myrank, * rbuf;
...
MPI_Comm_rank( comm, myrank);
if ( myrank == root) {
  MPI_Comm_size( comm, &gsize);
  rbuf = (int *)malloc(gsize * 100 * sizeof(int));
}
MPI_Gather( sendarray, 100, MPI_INT, rbuf, 100, MPI_INT, root, comm);

المثال 3: القيام بنفس الشيء كما في المثال السابق، ولكن استخدام نوع مشتق. لاحظ أن النوع لا يمكن أن يكون مجموعة كاملة من gsize * 100 الأعداد الصحيحة، لأن مطابقة النوع محددة زوجيًا بين الجذر وكل عملية في التجميع.

MPI_Comm comm;
int gsize, sendarray[100];
int root, * rbuf;
MPI_Datatype rtype;
...
MPI_Comm_size( comm, &gsize);
MPI_Type_contiguous( 100, MPI_INT, &rtype);
MPI_Type_commit( &rtype );
rbuf = (int*)malloc(gsize * 100 * sizeof(int));
MPI_Gather( sendarray, 100, MPI_INT, rbuf, 1, rtype, root, comm);

استخدام خيار في مكانه

عندما يكون الموصل داخليًا، يمكنك إجراء عملية جمع في مكانها (يتم استخدام مخزن الاستقبال كمخزن إرسال). استخدم المتغير MPI_IN_PLACE كقيمة لمخزن الإرسال للعملية الجذر. في هذه الحالة، يتم تجاهل sendcount و sendtype، ويُفترض أن مساهمة العملية الجذر في الجمع المتجه موجودة بالفعل في المكان الصحيح في مخزن الاستقبال. لاحظ أن MPI_IN_PLACE هو نوع خاص؛ له نفس القيود في استخدامه مثل MPI_BOTTOM. نظرًا لأن خيار في مكانه يحول مخزن الاستقبال إلى مخزن إرسال واستقبال، يجب على ربط Fortran الذي يتضمن INTENT تعيين هذه على أنها INOUT، وليس OUT.

عندما يكون الموصل هو واصل بيني

تتم عملية الجمع في مكانها (يتم استخدام مخزن الاستقبال كمخزن إرسال). استخدم المتغير MPI_IN_PLACE كقيمة لمخزن الإرسال للعملية الجذر. في هذه الحالة، يتم تجاهل sendcount و sendtype، ويُفترض أن مساهمة العملية الجذر في الجمع المتجه موجودة بالفعل في المكان الصحيح في مخزن الاستقبال. لاحظ أن MPI_IN_PLACE هو نوع خاص؛ له نفس القيود في استخدامه مثل MPI_BOTTOM. نظرًا لأن خيار في مكانه يحول مخزن الاستقبال إلى مخزن إرسال واستقبال، يجب على ربط Fortran الذي يتضمن INTENT تعيين هذه على أنها INOUT، وليس OUT.

أمثلة

Example 1: Gather 100 ints from every process in group to root.
MPI_Comm comm;
int gsize, sendarray[100];
int root, * rbuf;
...
MPI_Comm_size( comm, &gsize);
rbuf = (int*)malloc(gsize * 100 * sizeof(int));
MPI_Gather( sendarray, 100, MPI_INT, rbuf, 100, MPI_INT, root, comm);
Example 2: Previous example modified — only the root allocates memory for receive buffer.
MPI_Comm comm;
int gsize, sendarray[100];
int root, myrank, * rbuf;
...
MPI_Comm_rank( comm, myrank);
if ( myrank == root) {
  MPI_Comm_size( comm, &gsize);
  rbuf = (int *)malloc(gsize * 100 * sizeof(int));
}
MPI_Gather( sendarray, 100, MPI_INT, rbuf, 100, MPI_INT, root, comm);
Example 3: Do the same as previous example, but use a derived datatype. Note that the type cannot be the entire set of gsize * 100 ints since type matching is defined pairwise between the root and each process in the gather.
MPI_Comm comm;
int gsize, sendarray[100];
int root, * rbuf;
MPI_Datatype rtype;
...
MPI_Comm_size( comm, &gsize);
MPI_Type_contiguous( 100, MPI_INT, &rtype);
MPI_Type_commit( &rtype );
rbuf = (int*)malloc(gsize * 100 * sizeof(int));
MPI_Gather( sendarray, 100, MPI_INT, rbuf, 1, rtype, root, comm);

MPI_Igather

MPI_Igatherv, MPI_Igatherv — Asynchronous scatterv

SYNOPSIS

C++
    MPI_Igather(const void *sendbuf, int sendcount, MPI_Datatype sendtype,
        void *recvbuf, const int recvcounts[], const int displs[],
        MPI_Datatype recvtype, int root, MPI_Comm comm, MPI_Request *request)

Fortran
    MPI_IGATHER(SENDBUF, SENDCOUNT, SENDTYPE, RECVBUF, RECVCOUNTS, DISPLS,
        RECVTYPE, ROOT, COMM, REQUEST, IERROR)
                                                                                
                
        INTEGER SENDCOUNT, SENDTYPE, RECVCOUNTS(*)
        INTEGER DISPLS(*)
        INTEGER RECVTYPE, ROOT, COMM, REQUEST, IERROR

INPUT PARAMETERS

sendbuf: Non-root processes: pointer to the send buffer containing sendcount data elements to be sent.

sendcount: Non-root processes: number of elements in send buffer.

sendtype: Non-root processes: data type of elements in send buffer.

recvcounts: Root process: integer array (of length equal to the size of the communicator) specifying the number of elements that each process in the group sends to the root.

displs: Root process: integer array (of length equal to the size of the communicator) specifying the displacements (in elements) in the receive buffer where the data from each process is to be placed.

recvtype: Root process: data type of elements in the receive buffer.

root: Rank of the root process in the communicator.

comm: Communicator.

OUTPUT PARAMETERS

recvbuf: Root process: pointer to the receive buffer, which receives the data from all processes in the communicator.

request: Request. The handle of the communication.

IERROR (Fortran only): Fortran error return status.

DESCRIPTION

MPI_Igatherv is the non-blocking version of MPI_Gatherv. It gathers

Distributed arrays of data from all processes in a communicator to the root process. Each process sends data from its send buffer to the root. The root process receives the data from all the processes and concatenates them into its receive buffer.

The data is gathered in a scatter-like manner. Each process i sends its buffer of length sendcount elements of type sendtype to the root process. The root process receives these messages and places them into its receive buffer starting at offset displs[i] from the beginning of the receive buffer. The data from process i is placed into the receive buffer starting at offset displs[i] and is of length recvcounts[i] elements of type recvtype.

All arguments except request, recvbuf and IERROR are significant only on the root process. The send buffer and count arguments on non-root processes must be consistent with the receive buffer and count arguments on the root process.

The non-blocking communication is initiated and the function returns immediately. The completion of the communication can be checked by using MPI_Wait or MPI_Test.

The send buffer is the same for all processes. The receive buffer is defined only at the root process. On the root process, the receive buffer must be large enough to hold the data from all processes in the communicator. The size of the receive buffer on the root process is determined by the sum of all elements in the recvcounts array multiplied by the size of the recvtype elements.

The basic send and receive functions are involved. The arguments correspond to those in MPI_Gatherv.

USE OF IN-PLACE OPTION

When the communicator is an intracommunicator, all processes may pass the same address for the send and receive buffers (i.e. MPI_IN_PLACE). In this case, the send buffer is automatically replaced by the receive buffer. The data on the send buffer is sent to the root process, and the data on the root process is received into the receive buffer. On the root process, the send buffer argument is ignored and the receive buffer argument is used to store the data from all processes in the communicator.

WHEN COMMUNICATOR IS AN INTER-COMMUNICATOR

When the communicator is an inter-communicator, the root process in the first group gathers data from all the processes in the second group. The first group defines the root process. That process uses MPI_ROOT as the value of its root argument. The remaining processes use MPI_PROC_NULL as the value of their root argument. All processes in the second group use the rank of that root process in the first group as the value of their root argument. The send buffer argument of the processes in the first group must be consistent with the receive buffer argument of the root process in the second group.

ERRORS

Almost all MPI routines return an error value; C routines as the return result of the function and Fortran routines in the last argument.

Before the error value is returned, the current MPI error handler associated with the communication object (e.g., communicator, window, file) is called. If no communication object is associated with the MPI call, then the call is considered attached to MPI_COMM_SELF and will call the associated MPI error handler. When MPI_COMM_SELF is not initialized (i.e., before MPI_Init/MPI_Init_thread, after MPI_Finalize, or when using the Sessions Model exclusively) the error raises the initial error handler. The initial error handler can be changed by calling MPI_Comm_set_errhandler on MPI_COMM_SELF when using the World model, or the mpi_initial_errhandler CLI argument to mpiexec or info key to MPI_Comm_spawn/MPI_Comm_spawn_multiple. If no other appropriate error handler has been set, then the MPI_ERRORS_RETURN error handler is called for MPI I/O functions and the MPI_ERRORS_ABORT error handler is called for all other MPI functions.

Open MPI includes three predefined error handlers that can be used:

  • MPI_ERRORS_ARE_FATAL Causes the program to abort all connected MPI processes.
  • MPI_ERRORS_ABORT An error handler that can be invoked on a communicator, window, file, or session. When called on a communicator, it acts as if MPI_Abort was called on that communicator. If called on a window or file, acts as if MPI_Abort was called on a communicator containing the group of processes in the corresponding window or file. If called on a session, aborts only the local process.
  • MPI_ERRORS_RETURN Returns an error code to the application.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.
