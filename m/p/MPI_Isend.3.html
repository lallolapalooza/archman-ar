MPI_Isend(3)

الحزمة: openmpi

التراخيص: BSD-3-Clause AND LicenseRef-MPICH

MPI_Isend(3) Open MPI MPI_Isend(3)

MPI_Isend — يبدأ إرسالًا قياسيًا غير متزامن.

الصيغة

صيغة C

#include <mpi.h>
int MPI_Isend(const void *buf, int count, MPI_Datatype datatype, int dest,
     int tag, MPI_Comm comm, MPI_Request *request)

صيغة Fortran

USE MPI
! أو الصيغة الأقدم: INCLUDE 'mpif.h'
MPI_ISEND(BUF, COUNT, DATATYPE, DEST, TAG, COMM, REQUEST, IERROR)
     <type>  BUF(*)
     INTEGER COUNT, DATATYPE, DEST, TAG, COMM, REQUEST, IERROR

صيغة Fortran 2008

USE mpi_f08
MPI_Isend(buf, count, datatype, dest, tag, comm, request, ierror)
     TYPE(*), DIMENSION(..), INTENT(IN), ASYNCHRONOUS :: buf
     INTEGER, INTENT(IN) :: count, dest, tag
     TYPE(MPI_Datatype), INTENT(IN) :: datatype
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(MPI_Request), INTENT(OUT) :: request
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

معلمات الإدخال

  • buf: عنوان المخزن المؤقت للإرسال الأولي (اختياري).
  • count: عدد العناصر في المخزن المؤقت للإرسال (عدد صحيح).
  • datatype: نوع بيانات كل عنصر في المخزن المؤقت للإرسال (مقبض).
  • dest: رتبة الوجهة (عدد صحيح).
  • tag: وسم الرسالة (عدد صحيح).
  • comm: المتواصل (مقبض).

معلمات الإخراج

  • request: طلب الاتصال (مقبض).
  • ierror: Fortran فقط: حالة الخطأ (عدد صحيح).

الوصف

MPI_Isend يبدأ إرسالًا قياسيًا غير متزامن. تستدعي الاستدعاءات غير المتزامنة كائن طلب اتصال وتنشئه مع مقبض الطلب (الوسيط request). يمكن استخدام الطلب لاحقًا للاستعلام عن حالة الاتصال أو الانتظار حتى اكتماله.

يشير استدعاء إرسال غير متزامن إلى أن النظام قد يبدأ في نسخ البيانات خارج المخزن المؤقت للإرسال. يجب ألا يقوم المرسل بتعديل أي جزء من المخزن المؤقت للإرسال بعد استدعاء عملية إرسال غير متزامنة، حتى يكتمل الإرسال.

يمكن تحديد اكتمال طلب الإرسال عن طريق استدعاء MPI_Wait أو MPI_Waitany أو MPI_Test أو MPI_Testany باستخدام الطلب الذي تم إرجاعه بواسطة هذه الوظيفة.

الأخطاء

تقوم جميع روتينات MPI تقريبًا بإرجاع قيمة خطأ؛ وظائف C كنتيجة إرجاع للوظيفة ووظائف Fortran في الوسيط الأخير.

قبل إرجاع قيمة الخطأ، يتم استدعاء معالج خطأ MPI الحالي المرتبط بكائن الاتصال (مثل المتواصل، النافذة، الملف). إذا لم يكن هناك كائن اتصال مرتبط باستدعاء MPI، فسيتم اعتبار الاستدعاء ملحقًا بـ MPI_COMM_SELF وسيتم استدعاء معالج خطأ MPI المرتبط به. عندما لا يتم تهيئة MPI_COMM_SELF (أي، قبل MPI_Init / MPI_Init_thread، بعد MPI_Finalize، أو عند استخدام نموذج الجلسات حصريًا) يثير الخطأ معالج الخطأ الأولي. يمكن تغيير معالج الخطأ الأولي عن طريق استدعاء MPI_Comm_set_errhandler على MPI_COMM_SELF عند استخدام نموذج العالم، أو وسيط سطر الأوامر mpi_initial_errhandler إلى mpiexec أو مفتاح معلومات إلى MPI_Comm_spawn / MPI_Comm_spawn_multiple. إذا لم يتم تعيين معالج خطأ مناسب آخر، فسيتم استدعاء معالج الخطأ MPI_ERRORS_RETURN لوظائف إدخال/إخراج MPI وسيتم استدعاء معالج الخطأ MPI_ERRORS_ABORT لجميع وظائف MPI الأخرى.

يتضمن Open MPI ثلاثة معالجات أخطاء معرفة مسبقًا يمكن استخدامها:

  • MPI_ERRORS_ARE_FATAL يتسبب في إنهاء البرنامج لجميع عمليات MPI المتصلة.
  • MPI_ERRORS_ABORT معالج خطأ يمكن استدعاؤه على متواصل أو نافذة أو ملف أو جلسة. عند استدعائه على متواصل، فإنه يتصرف كما لو تم استدعاء MPI_Abort على هذا المتواصل. عند استدعائه على نافذة أو ملف، يتصرف كما لو تم استدعاء MPI_Abort على متواصل يحتوي على مجموعة العمليات في النافذة أو الملف المقابل. عند استدعائه على جلسة، يؤدي ذلك إلى إنهاء العملية المحلية فقط.
  • MPI_ERRORS_RETURN يرجع رمز خطأ إلى التطبيق.

يمكن لتطبيقات MPI أيضًا تنفيذ معالجات الأخطاء الخاصة بها عن طريق استدعاء:

  • MPI_Comm_create_errhandler ثم MPI_Comm_set_errhandler
  • MPI_File_create_errhandler ثم MPI_File_set_errhandler
  • MPI_Session_create_errhandler ثم MPI_Session_set_errhandler أو في MPI_Session_init
  • MPI_Win_create_errhandler ثم MPI_Win_set_errhandler

لاحظ أن MPI لا تضمن أن برنامج MPI يمكن أن يستمر بعد حدوث خطأ.
