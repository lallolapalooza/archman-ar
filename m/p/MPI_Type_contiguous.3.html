MPI_Type_contiguous(3)

الحزمة: openmpi

التراخيص: BSD-3-Clause AND LicenseRef-MPICH

MPI_TYPE_CONTIGUOUS(3) Open MPI MPI_TYPE_CONTIGUOUS(3)

MPI_Type_contiguous — ينشئ نوع بيانات متجاور.

الصيغة

صيغة C

#include <mpi.h>
int MPI_Type_contiguous(int count, MPI_Datatype oldtype,
     MPI_Datatype *newtype)

صيغة Fortran

USE MPI
! أو الشكل الأقدم: INCLUDE 'mpif.h'
MPI_TYPE_CONTIGUOUS(COUNT, OLDTYPE, NEWTYPE, IERROR)
     INTEGER COUNT, OLDTYPE, NEWTYPE, IERROR

صيغة Fortran 2008

USE mpi_f08
MPI_Type_contiguous(count, oldtype, newtype, ierror)
     INTEGER, INTENT(IN) :: count
     TYPE(MPI_Datatype), INTENT(IN) :: oldtype
     TYPE(MPI_Datatype), INTENT(OUT) :: newtype
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

معلمات الإدخال

  • count: عدد التكرار (عدد صحيح غير سالب).
  • oldtype: نوع البيانات القديم (مقبض).

معلمات الإخراج

  • newtype: نوع البيانات الجديد (مقبض).
  • ierror: Fortran فقط: حالة الخطأ (عدد صحيح).

الوصف

أبسط مُنشئ لنوع البيانات هو MPI_Type_contiguous، والذي يسمح بتكرار نوع بيانات في مواقع متجاورة.

newtype هو نوع البيانات الناتج عن ربط count نسخ من oldtype. يتم تعريف الربط باستخدام امتداد oldtype كحجم النسخ المربوطة.

مثال: لنفترض أن oldtype لديه خريطة نوع {(double, 0), (char, 8)}، بامتداد 16، ولنفترض count = 3. خريطة النوع لنوع البيانات الذي يتم إرجاعه بواسطة newtype هي

{(double, 0), (char, 8), (double, 16), (char, 24),
(double, 32), (char, 40)];

أي، عناصر double و char متناوبة، بإزاحات 0، 8، 16، 24، 32، 40.

بشكل عام، نفترض أن خريطة النوع لـ oldtype هي

{(type(0), disp(0)),...,(type(n-1), disp(n-1))},

مع امتداد ex. ثم لدى newtype خريطة نوع تحتوي على count * n مدخلات محددة بواسطة:

{(type(0), disp(0)), ...,(type(n-1), disp(n-1)),
(type(0), disp(0) + ex), ...,(type(n-1),
disp(n-1) + ex), ...,(type(0), disp(0) + ex * (count - 1)),
...,(type(n-1), disp(n-1) + ex * (count - 1))}.

لمزيد من المعلومات حول أنواع البيانات المشتقة، راجع فصل أنواع البيانات في معيار MPI.

الأخطاء

تقريبًا جميع إجراءات MPI تُرجع قيمة خطأ؛ إجراءات C كنتيجة إرجاع للدالة وإجراءات Fortran في الوسيط الأخير.

قبل إرجاع قيمة الخطأ، يتم استدعاء معالج أخطاء MPI الحالي المرتبط بكائن الاتصال (مثل، المرسل، النافذة، الملف). إذا لم يكن هناك كائن اتصال مرتبط باستدعاء MPI، يعتبر الاستدعاء مرتبطًا بـ MPI_COMM_SELF وسيتم استدعاء معالج الأخطاء الخاص به. عندما لا يتم تهيئة MPI_COMM_SELF (أي، قبل MPI_Init/MPI_Init_thread، بعد MPI_Finalize، أو عند استخدام نموذج الجلسات حصريًا) يثير الخطأ معالج الأخطاء الأولي. يمكن تغيير معالج الأخطاء الأولي عن طريق استدعاء MPI_Comm_set_errhandler على MPI_COMM_SELF عند استخدام نموذج العالم، أو الوسيط CLI mpi_initial_errhandler لـ mpiexec أو مفتاح المعلومات لـ MPI_Comm_spawn/MPI_Comm_spawn_multiple. إذا لم يتم تعيين أي معالج أخطاء مناسب آخر، فسيتم استدعاء معالج الأخطاء MPI_ERRORS_RETURN لوظائف MPI I/O وسيتم استدعاء معالج الأخطاء MPI_ERRORS_ABORT لجميع وظائف MPI الأخرى.

يتضمن Open MPI ثلاثة معالجات أخطاء معرفة مسبقًا يمكن استخدامها:

  • MPI_ERRORS_ARE_FATAL يتسبب في إنهاء البرنامج لجميع عمليات MPI المتصلة.
  • MPI_ERRORS_ABORT معالج أخطاء يمكن استدعاؤه على مرسل، نافذة، ملف، أو جلسة. عند استدعائه على مرسل، يعمل كما لو تم استدعاء MPI_Abort على ذلك المرسل. إذا تم استدعاؤه على نافذة أو ملف، يعمل كما لو تم استدعاء MPI_Abort على مرسل يحتوي على مجموعة العمليات في النافذة أو الملف المقابل. إذا تم استدعاؤه على جلسة، فإنه ينهي العملية المحلية فقط.
  • MPI_ERRORS_RETURN يُرجع رمز خطأ إلى التطبيق.

يمكن لتطبيقات MPI أيضًا تنفيذ معالجات أخطاء خاصة بها عن طريق استدعاء:

  • MPI_Comm_create_errhandler ثم MPI_Comm_set_errhandler
  • MPI_File_create_errhandler ثم MPI_File_set_errhandler
  • MPI_Session_create_errhandler ثم MPI_Session_set_errhandler أو عند MPI_Session_init
  • MPI_Win_create_errhandler ثم MPI_Win_set_errhandler

لاحظ أن MPI لا يضمن أن برنامج MPI يمكن أن يستمر بعد حدوث خطأ.
