MPI_Comm_call_errhandler(3)

الحزمة: openmpi

التراخيص: BSD-3-Clause AND LicenseRef-MPICH

MPI_COMM_CALL_ERRHANDLER(3) Open MPI MPI_COMM_CALL_ERRHANDLER(3)

MPI_Comm_call_errhandler — تمرير رمز الخطأ المقدم إلى معالج الخطأ المعين لاتصال

الصيغة

صيغة C

#include <mpi.h>
int MPI_Comm_call_errhandler(MPI_Comm comm, int errorcode)

صيغة Fortran

USE MPI
! أو الشكل القديم: INCLUDE 'mpif.h'
MPI_COMM_CALL_ERRHANDLER(COMM, ERRORCODE, IERROR)
    INTEGER COMM, ERRORCODE, IERROR

صيغة Fortran 2008

USE mpi_f08
MPI_Comm_call_errhandler(comm, errorcode, ierror)
    TYPE(MPI_Comm), INTENT(IN) :: comm
    INTEGER, INTENT(IN) :: errorcode
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror

معامل الإدخال

  • comm : اتصال مع معالج خطأ (مقبض).
  • errorcode : رمز الخطأ (عدد صحيح).

معاملات الإخراج

•
ierror : Fortran فقط: حالة الخطأ (عدد صحيح).

الوصف

تستدعي هذه الدالة معالج الخطأ المعين للاتصال comm برمز الخطأ errorcode المقدم. إذا تم استدعاء معالج الخطأ بنجاح، ولم يتم إنهاء العملية، وعاد معالج الخطأ، فإن هذه الدالة تعود بـ MPI_SUCCESS.

ملاحظات

يجب أن يلاحظ المستخدمون أن معالج الخطأ الافتراضي هو MPI_ERRORS_ARE_FATAL. بالتالي، سيؤدي استدعاء هذه الدالة إلى إنهاء العمليات في comm إذا لم يتم تغيير معالج الخطأ الافتراضي.

الأخطاء

تقريبًا جميع روتينات MPI تعود بقيمة خطأ؛ روتينات C كنتيجة إرجاع للدالة وروتينات Fortran في الوسيط الأخير.

قبل إعادة قيمة الخطأ، يتم استدعاء معالج الخطأ MPI الحالي المرتبط بكائن الاتصال (على سبيل المثال، الاتصال، النافذة، الملف). إذا لم يكن هناك كائن اتصال مرتبط باستدعاء MPI، فسيتم اعتبار الاستدعاء ملحقًا بـ MPI_COMM_SELF وسيتم استدعاء معالج الخطأ MPI المرتبط. عندما لا يتم تهيئة MPI_COMM_SELF (أي، قبل MPI_Init/MPI_Init_thread، بعد MPI_Finalize، أو عند استخدام نموذج الجلسات حصريًا)، يثير الخطأ معالج الخطأ الأولي. يمكن تغيير معالج الخطأ الأولي عن طريق استدعاء MPI_Comm_set_errhandler على MPI_COMM_SELF عند استخدام نموذج العالم، أو وسيط سطر الأوامر mpi_initial_errhandler لـ mpiexec أو مفتاح معلومات لـ MPI_Comm_spawn/MPI_Comm_spawn_multiple. إذا لم يتم تعيين معالج خطأ مناسب آخر، فسيتم استدعاء معالج الخطأ MPI_ERRORS_RETURN لوظائف MPI I/O وسيتم استدعاء معالج الخطأ MPI_ERRORS_ABORT لجميع وظائف MPI الأخرى.

تتضمن Open MPI ثلاثة معالجات أخطاء معرفة مسبقًا يمكن استخدامها:

  • MPI_ERRORS_ARE_FATAL يؤدي إلى إنهاء البرنامج لجميع عمليات MPI المتصلة.
  • MPI_ERRORS_ABORT معالج خطأ يمكن استدعاؤه على اتصال، نافذة، ملف، أو جلسة. عند استدعائه على اتصال، يتصرف كما لو تم استدعاء MPI_Abort على هذا الاتصال. إذا تم استدعاؤه على نافذة أو ملف، يتصرف كما لو تم استدعاء MPI_Abort على اتصال يحتوي على مجموعة العمليات في النافذة أو الملف المقابل. إذا تم استدعاؤه على جلسة، فإنه ينهي العملية المحلية فقط.
  • MPI_ERRORS_RETURN يعود برمز خطأ إلى التطبيق.

يمكن لتطبيقات MPI أيضًا تنفيذ معالجات الأخطاء الخاصة بها عن طريق الاستدعاء:

  • MPI_Comm_create_errhandler ثم MPI_Comm_set_errhandler
  • MPI_File_create_errhandler ثم MPI_File_set_errhandler
  • MPI_Session_create_errhandler ثم MPI_Session_set_errhandler أو عند MPI_Session_init
  • MPI_Win_create_errhandler ثم MPI_Win_set_errhandler

لاحظ أن MPI لا تضمن أن برنامج MPI يمكن أن يستمر بعد خطأ.
