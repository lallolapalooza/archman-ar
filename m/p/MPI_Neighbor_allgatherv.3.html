معلمات الإدخال

  • sendbuf: عنوان بداية مخزن الإرسال (اختياري).
  • sendcount: عدد العناصر في مخزن الإرسال (عدد صحيح).
  • sendtype: نوع العناصر في مخزن الإرسال (مقبض).
  • recvcount: مصفوفة أعداد صحيحة (بطول المجموعة) تحتوي على عدد العناصر التي سيتم استلامها من كل جار.
  • displs: مصفوفة أعداد صحيحة (بطول المجموعة). يحدد العنصر i الإزاحة (نسبة إلى recvbuf) حيث سيتم وضع بيانات الجار i.
  • recvtype: نوع العناصر في مخزن الاستقبال (مقبض).
  • comm: المتواصل (مقبض).
  • info Info (مقبض، ثابت فقط).:

معلمات الإخراج

  • recvbuf: عنوان مخزن الاستقبال (اختياري).
  • request: الطلب (مقبض، غير مانع).
  • ierror: في فورتران فقط: رمز الخطأ (عدد صحيح).

الوصف

MPI_Neighbor_allgatherv مشابه لـ MPI_Neighbor_allgather من حيث أن جميع العمليات تجمع البيانات من جميع الجيران، إلا أنه يمكن لكل عملية إرسال كمية مختلفة من البيانات. سيتم استلام كتلة البيانات المرسلة من الجار j بواسطة جميع الجيران وسيتم وضعها في الكتلة j من المخزن. يتم تحديد ترتيب الجيران والمخزن بواسطة طوبولوجيا comm. recvbuf.

يجب أن يكون توقيع النوع المرتبط بـ sendcount و sendtype في العملية j متساويًا لتوقيع النوع المرتبط بالعنصر المقابل في recvcounts في الجيران.

ترتيب الجيران

بالنسبة لطوبولوجيا الرسم البياني الموزعة التي تم إنشاؤها باستخدام MPI_Dist_graph_create، يتم تحديد تسلسل الجيران في مخازن الإرسال والاستقبال في كل عملية بالتسلسل الذي يتم إرجاعه بواسطة MPI_Dist_graph_neighbors للوجهات والمصادر على التوالي. بالنسبة لطوبولوجيا عامة تم إنشاؤها باستخدام MPI_Graph_create، يتم تحديد تسلسل الجيران في مخازن الإرسال والاستقبال بالتسلسل الذي يتم إرجاعه بواسطة MPI_Graph_neighbors. لاحظ أنه يجب استبدال الطوبولوجيات العامة بشكل عام بطوبولوجيات الرسم البياني الموزعة.

بالنسبة لطوبولوجيا ديكارتية تم إنشاؤها باستخدام MPI_Cart_create، يتم تحديد تسلسل الجيران في مخازن الإرسال والاستقبال في كل عملية وفقًا لترتيب الأبعاد، أولاً الجيران في الاتجاه السلبي ثم في الاتجاه الإيجابي بإزاحة 1. عدد المصادر والوجهات في روتينات الاتصال هو 2*ndims مع ndims المحدد في MPI_Cart_create. إذا لم يكن الجار موجودًا، أي على حافة طوبولوجيا ديكارتية غير دورية (أي periods[...]==false)، فإن هذا الجار يُعرّف على أنه MPI_PROC_NULL.

إذا كان الجار في أي من الوظائف هو MPI_PROC_NULL، فإن الاتصال الجماعي بالجيران يتصرف كـ اتصال من نقطة إلى نقطة مع MPI_PROC_NULL في هذا الاتجاه. أي، يظل المخزن جزءًا من تسلسل الجيران ولكنه لا يتم الاتصال به أو تحديثه.

ملاحظات

الخيار MPI_IN_PLACE لـ sendbuf ليس له أهمية لهذه العملية.

الأخطاء

تعيد معظم روتينات MPI قيمة خطأ؛ تعيد روتينات C نتيجة الدالة، وروتينات فورتران في الوسيط الأخير.

قبل إعادة قيمة الخطأ، يتم استدعاء معالج الخطأ المرتبط بكائن الاتصال (على سبيل المثال، المتواصل، النافذة، الملف) قيد الاستخدام. إذا لم يكن هناك كائن اتصال مرتبط باستدعاء MPI، فيعتبر الاستدعاء مرتبطًا بـ MPI_COMM_SELF وسيتم استدعاء معالج الخطأ المرتبط بـ MPI_COMM_SELF. عندما لا يتم تهيئة MPI_COMM_SELF (أي، قبل MPI_Init/MPI_Init_thread، بعد MPI_Finalize، أو عند استخدام نموذج الجلسة حصريًا)، يتم رفع الخطأ الأولي. يمكن تغيير معالج الخطأ الأولي عن طريق استدعاء MPI_Comm_set_errhandler على MPI_COMM_SELF عند استخدام نموذج العالم، أو من خلال وسيط mpiexec mpi_initial_errhandler أو معلمة معلومات MPI_Comm_spawn/MPI_Comm_spawn_multiple. إذا لم يكن هناك معالج خطأ مناسب آخر، يتم استدعاء معالج الخطأ MPI_ERRORS_RETURN لوظائف إدخال/إخراج MPI ومعالج الخطأ MPI_ERRORS_ABORT لجميع وظائف MPI الأخرى.

تتضمن Open MPI ثلاثة معالجات أخطاء مسبقة التكوين يمكن استخدامها:

  • MPI_ERRORS_ARE_FATAL يتسبب في إنهاء البرنامج لعملية MPI المتصلة.
  • MPI_ERRORS_ABORT معالج خطأ يمكن استدعاؤه على متواصل، نافذة، في

ERRORS

The default error handler is MPI_ERRORS_ARE_FATAL. When this error handler is invoked, all MPI processes are involved. MPI_Abort is called on all processes in the communicator. The input parameters to the error handler are the communicator, an error code, and the arguments to the MPI function that caused the error.

The error handler can be changed for any communicator using MPI_Comm_set_errhandler. The predefined error handlers are:

  • MPI_ERRORS_ARE_FATAL If this error handler is called on a communicator, it causes MPI_Abort to be called on all processes in the communicator.
  • MPI_ERRORS_RETURN If this error handler is called on a communicator, it returns the error code to the application. In this case, the application must check the return codes of all MPI functions. If an error occurs in a function that is called by multiple processes, the error code is returned to all processes. If the error handler is invoked on a communicator that is not a valid communicator, or if the error handler is invoked on a communicator that does not have an error handler associated with it, or if the error handler is invoked on a communicator that has been freed, then MPI_Abort is called on all processes in the communicator. If called on a communicator, it acts as if MPI_Abort was called on that communicator. If called on a window or file, acts as if MPI_Abort was called on a communicator containing the group of processes in the corresponding window or file. If called on a session, aborts only the local process.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.
