MPI_Mprobe(3)

الحزمة: openmpi

التراخيص: BSD-3-Clause AND LicenseRef-MPICH

MPI_MPROBE(3) Open MPI MPI_MPROBE(3)

MPI_Mprobe — فحص مطابق لحظر رسالة.

الصيغة

صيغة C

#include <mpi.h>
int MPI_Mprobe(int source, int tag, MPI_Comm comm,
     MPI_Message *message, MPI_Status *status)

صيغة فورتران

USE MPI
! أو الصيغة القديمة: INCLUDE 'mpif.h'
MPI_MPROBE(SOURCE, TAG, COMM, MESSAGE, STATUS, IERROR)
     INTEGER SOURCE, TAG, COMM, MESSAGE
     INTEGER STATUS(MPI_STATUS_SIZE), IERROR

صيغة فورتران 2008

USE mpi_f08
MPI_Mprobe(source, tag, comm, message, status, ierror)
     INTEGER, INTENT(IN) :: source, tag
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(MPI_Message), INTENT(OUT) :: message
     TYPE(MPI_Status) :: status
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

معاملات الإدخال

  • source: رتبة المصدر أو MPI_ANY_SOURCE (عدد صحيح).
  • tag: قيمة الوسم أو MPI_ANY_TAG (عدد صحيح).
  • comm: المتصل (مقبض).

معاملات الإخراج

  • message: الرسالة (مقبض).
  • status: كائن الحالة (حالة).
  • ierror: فورتران فقط: حالة الخطأ (عدد صحيح).

الوصف

مثل MPI_Probe و MPI_Iprobe، تسمح عمليتا MPI_Mprobe و MPI_Improbe بالاستعلام عن الرسائل الواردة دون استقبالها فعليًا، باستثناء أن MPI_Mprobe و MPI_Improbe توفران آلية لاستقبال الرسالة المحددة التي تمت مطابقتها بغض النظر عن عمليات الفحص أو الاستقبال الأخرى التي تم اعتراضها. هذا يمنح التطبيق فرصة لتحديد كيفية استقبال الرسالة، بناءً على المعلومات التي تم إرجاعها من الفحص. على وجه الخصوص، قد يقوم التطبيق بتخصيص الذاكرة لمخزن الاستقبال وفقًا لطول الرسالة التي تم فحصها.

يقوم الفحص المطابق مع MPI_PROC_NULL كـ source بإرجاع message = MPI_MESSAGE_NO_PROC، ويرجع كائن status المصدر = MPI_PROC_NULL، والوسم = MPI_ANY_TAG، والعدد = 0.

عندما تعود MPI_Mprobe (من source غير MPI_PROC_NULL)، يمكن استقبال الرسالة المطابقة بعد ذلك عن طريق تمرير مقبض message إلى الدالتين MPI_Mrecv أو MPI_Imrecv.

الأخطاء

تقريبًا جميع روتينيات MPI تعيد قيمة خطأ؛ روتينيات C كالنتيجة الراجعة للوظيفة، وروتينيات فورتران في المعامل الأخير.

قبل إعادة قيمة الخطأ، يتم استدعاء معالج الخطأ MPI الحالي المرتبط بجسم الاتصال (مثل المتصل، النافذة، الملف). إذا لم يكن هناك جسم اتصال مرتبط باستدعاء MPI، فيعتبر الاستدعاء مرتبطًا بـ MPI_COMM_SELF وسيتم استدعاء معالج الخطأ MPI المرتبط. عندما لا يتم تهيئة MPI_COMM_SELF (أي، قبل MPI_Init/MPI_Init_thread، بعد MPI_Finalize، أو عند استخدام نموذج الجلسات حصريًا) يثير الخطأ معالج الخطأ الأولي. يمكن تغيير معالج الخطأ الأولي عن طريق استدعاء MPI_Comm_set_errhandler على MPI_COMM_SELF عند استخدام نموذج العالم، أو الوسيط mpi_initial_errhandler الخاص بـ mpiexec أو مفتاح المعلومات الخاص بـ MPI_Comm_spawn/MPI_Comm_spawn_multiple. إذا لم يتم تعيين أي معالج خطأ مناسب آخر، فسيتم استدعاء معالج الخطأ MPI_ERRORS_RETURN لوظائف MPI I/O وسيتم استدعاء معالج الخطأ MPI_ERRORS_ABORT لجميع وظائف MPI الأخرى.

يتضمن Open MPI ثلاثة معالجات خطأ محددة مسبقًا يمكن استخدامها:

  • MPI_ERRORS_ARE_FATAL يتسبب في إنهاء البرنامج لجميع عمليات MPI المتصلة.
  • MPI_ERRORS_ABORT معالج خطأ يمكن استدعاؤه على متصل، نافذة، ملف، أو جلسة. عند استدعائه على متصل، يتصرف كما لو تم استدعاء MPI_Abort على هذا المتصل. إذا تم استدعاؤه على نافذة أو ملف، يتصرف كما لو تم استدعاء MPI_Abort على متصل يحتوي على مجموعة العمليات في النافذة أو الملف المقابل. إذا تم استدعاؤه على جلسة، فإنه ينهي العملية المحلية فقط.
  • MPI_ERRORS_RETURN يعيد رمز خطأ إلى التطبيق.

يمكن لتطبيقات MPI أيضًا تنفيذ معالجات الخطأ الخاصة بها عن طريق استدعاء:

  • MPI_Comm_create_errhandler ثم MPI_Comm_set_errhandler
  • MPI_File_create_errhandler ثم MPI_File_set_errhandler
  • MPI_Session_create_errhandler ثم MPI_Session_set_errhandler أو عند MPI_Session_init
  • MPI_Win_create_errhandler ثم MPI_Win_set_errhandler

لاحظ أن MPI لا تضمن أن برنامج MPI يمكن أن يستمر بعد حدوث خطأ.
