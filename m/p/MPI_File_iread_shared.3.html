MPI_File_iread_shared(3)

الحزمة: openmpi

التراخيص: BSD-3-Clause AND LicenseRef-MPICH

MPI_FILE_IREAD_SHARED(3) Open MPI MPI_FILE_IREAD_SHARED(3)

MPI_File_iread_shared — قراءة ملف باستخدام مؤشر الملف المشترك (غير متزامن، غير جماعي).

الصيغة

صيغة C

#include <mpi.h>
int MPI_File_iread_shared(MPI_File fh, void *buf, int count,
     MPI_Datatype datatype, MPI_Request *request)

صيغة Fortran

USE MPI
! أو الصيغة الأقدم: INCLUDE 'mpif.h'
MPI_FILE_IREAD_SHARED(FH, BUF, COUNT, DATATYPE, REQUEST, IERROR)
     <type>  BUF(*)
     INTEGER FH, COUNT, DATATYPE, REQUEST, IERROR

صيغة Fortran 2008

USE mpi_f08
MPI_File_iread_shared(fh, buf, count, datatype, request, ierror)
     TYPE(MPI_File), INTENT(IN) :: fh
     TYPE(*), DIMENSION(..), ASYNCHRONOUS :: buf
     INTEGER, INTENT(IN) :: count
     TYPE(MPI_Datatype), INTENT(IN) :: datatype
     TYPE(MPI_Request), INTENT(OUT) :: request
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

معامل الإدخال/الإخراج

•
fh: مقبض الملف (handle).

معاملات الإدخال

  • count: عدد العناصر في المخزن المؤقت (integer).
  • datatype: نوع بيانات كل عنصر في المخزن المؤقت (handle).

معاملات الإخراج

  • buf: العنوان الأولي للمخزن المؤقت (choice).
  • request: كائن الطلب (handle).
  • ierror: Fortran فقط: حالة الخطأ (integer).

الوصف

MPI_File_iread_shared هو إصدار غير متزامن لواجهة MPI_File_read_shared. يستخدم مؤشر الملف المشترك لقراءة الملفات. ترتيب التسلسل بين المعالجات ليس حتميًا لهذا الروتين غير الجماعي، لذا تحتاج إلى استخدام طرق مزامنة أخرى لفرض ترتيب معين بين المعالجات.

الأخطاء

تقريبًا جميع روتينات MPI ترجع قيمة خطأ؛ روتينات C كنتيجة إرجاع للدالة وروتينات Fortran في المعامل الأخير.

قبل إرجاع قيمة الخطأ، يتم استدعاء معالج خطأ MPI الحالي المرتبط بكائن الاتصال (مثل communicator، window، file). إذا لم يكن هناك كائن اتصال مرتبط باستدعاء MPI، فيتم اعتبار الاستدعاء مرتبطًا بـ MPI_COMM_SELF وسيستدعي معالج الخطأ المرتبط. عندما لا يتم تهيئة MPI_COMM_SELF (أي، قبل MPI_Init/MPI_Init_thread، بعد MPI_Finalize، أو عند استخدام نموذج الجلسات حصريًا) يثير الخطأ معالج الخطأ الأولي. يمكن تغيير معالج الخطأ الأولي عن طريق استدعاء MPI_Comm_set_errhandler على MPI_COMM_SELF عند استخدام نموذج العالم، أو الوسيط CLI mpi_initial_errhandler إلى mpiexec أو مفتاح معلومات لـ MPI_Comm_spawn/MPI_Comm_spawn_multiple. إذا لم يتم تعيين معالج خطأ مناسب آخر، فسيتم استدعاء معالج خطأ MPI_ERRORS_RETURN لوظائف الإدخال/الإخراج لـ MPI وسيتم استدعاء معالج خطأ MPI_ERRORS_ABORT لجميع وظائف MPI الأخرى.

تتضمن Open MPI ثلاثة معالجات خطأ محددة مسبقًا يمكن استخدامها:

  • MPI_ERRORS_ARE_FATAL يسبب إنهاء البرنامج لجميع عمليات MPI المتصلة.
  • MPI_ERRORS_ABORT معالج خطأ يمكن استدعاؤه على communicator، window، file، أو session. عند استدعائه على communicator، فإنه يتصرف كما لو تم استدعاء MPI_Abort على ذلك communicator. إذا تم استدعاؤه على window أو file، فإنه يتصرف كما لو تم استدعاء MPI_Abort على communicator يحتوي على مجموعة العمليات في window أو file المقابلة. إذا تم استدعاؤه على session، فإنه ينهي العملية المحلية فقط.
  • MPI_ERRORS_RETURN يرجع رمز خطأ إلى التطبيق.

يمكن لتطبيقات MPI أيضًا تنفيذ معالجات الخطأ الخاصة بها عن طريق الاستدعاء:

  • MPI_Comm_create_errhandler ثم MPI_Comm_set_errhandler
  • MPI_File_create_errhandler ثم MPI_File_set_errhandler
  • MPI_Session_create_errhandler ثم MPI_Session_set_errhandler أو في MPI_Session_init
  • MPI_Win_create_errhandler ثم MPI_Win_set_errhandler

لاحظ أن MPI لا تضمن أن برنامج MPI يمكن أن يستمر بعد خطأ.
