MPI_Rput(3)

الحزمة: openmpi

NAME

MPI_Rput

non-blocking put for one-sided communication

SYNTAX

C++:
int MPI::Win::Rput(const void* origin_addr, int origin_count, MPI_Datatype origin_datatype, int target_rank, MPI_Aint target_disp, int target_count, MPI_Datatype target_datatype, MPI_Win win)

C:
int MPI_Rput(const void *origin_addr, int origin_count, MPI_Datatype origin_datatype, int target_rank, MPI_Aint target_disp, int target_count, MPI_Datatype target_datatype, MPI_Win win, MPI_Request *request)

INPUT PARAMETERS

origin_addr
address of the buffer on the local process (choice)
origin_count
number of elements in the send buffer (integer)
origin_datatype
datatype of the elements in the send buffer (handle)
target_rank
rank of the target process (integer)
target_disp
displacement of the start of the target buffer relative to the start of the window
target_count
number of elements in the receive buffer (integer)
target_datatype
datatype of the elements in the receive buffer (handle)
win
window object on which to perform the operation
request
request object that can be used to specify and return the MPI status of the operation (handle)

OUTPUT PARAMETER

request
MPI_REQUEST_NULL on return if an error occurs, or a valid MPI request handle otherwise.

DESCRIPTION

The MPI routine MPI_Rput performs a non-blocking put operation. It transfers data from the origin buffer on the local process to the target buffer on the target process. The target buffer is specified by a rank and a base displacement within the target process's window.

The target buffer is defined by the base address of the window associated with the communication, plus the specified displacement and the datatype information.

The MPI_Rput call is initiated by the sender and does not require synchronization on the target side. The data is copied from the origin buffer to a system buffer. The operation completes when the data has been successfully transferred to the target buffer.

The request parameter is used to identify the non-blocking operation. It can be used later with MPI_Wait or MPI_Test to determine the status of the operation.

The C++ bindings provide overloaded versions of MPI_Rput that allow omitting the count or displacement arguments when they are zero. The version that omits the target count assumes the target count is the same as the origin count.

NOTES

The MPI_Rput function is part of the MPI One-Sided Communication interface.

The origin buffer must not be accessed until the MPI_Rput operation has completed. The target buffer may be accessed at any time.

The win argument must be a window created by MPI_Win_create, MPI_Win_allocate, or MPI_Win_allocate_shared.

The target_disp argument is an offset in units of the basic displacement, which is the size of the datatype.

The MPI_Request object is significant. It is created by the call and must be freed by the user using MPI_Request_free after the operation has been completed (e.g. via MPI_Wait or MPI_Test).

ERRORS

When an MPI function returns an error code, it is the value returned by the C/C++ function.

By default, this function returns the C/C++ error code in the following cases:

  • 1, if the C/C++ function is called with an invalid communicator:
    • MPI_COMM_WORLD
  • 2, if the C/C++ function is called with an invalid window:
    • MPI_WIN_NULL
  • 3, if the C/C++ function is called with an invalid request:
    • MPI_REQUEST_NULL
  • 4, if the C/C++ function is called with an invalid datatype:
    • MPI_DATATYPE_NULL
  • 5, if the C/C++ function is called with an invalid rank:
    • rank < 0 or rank >= size of communicator
  • 6, if the communication is not allowed:
    • No epoch is active on the window
  • 7, if the target process is not in the same communicator as the source process.

The error handler attached to the window is invoked if this function returns an error. The default error handler aborts the MPI job.

The error handler may be changed with MPI_Comm_set_errhandler for communicators, MPI_Win_set_errhandler for windows, MPI_File_set_errhandler for files, or MPI_Session_set_errhandler for sessions. However, MPI does not guarantee that an MPI program can continue to run past an error.

The following error handlers may be defined:

  • MPI_ERRORS_ARE_FATAL Stop all processes.
  • MPI_ERRORS_RETURN Returns an error code to the application.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.

الوصف

تقوم روتينية MPI MPI_Rput بتنفيذ عملية وضع غير متزامنة. تقوم بنقل البيانات من المخزن المؤقت المصدر في العملية المحلية إلى المخزن المؤقت الهدف في العملية الهدف. يتم تحديد المخزن المؤقت الهدف بواسطة ترتيب وإزاحة أساسية ضمن نافذة العملية الهدف.

يتم تعريف المخزن المؤقت الهدف بواسطة العنوان الأساسي للنافذة المرتبطة بالاتصال، بالإضافة إلى الإزاحة المحددة ومعلومات نوع البيانات.

يتم بدء استدعاء MPI_Rput بواسطة المرسل ولا يتطلب مزامنة على جانب الهدف. يتم نسخ البيانات من المخزن المؤقت المصدر إلى مخزن مؤقت للنظام. تكتمل العملية عندما يتم نقل البيانات بنجاح إلى المخزن المؤقت الهدف.

يتم استخدام معلمة request لتحديد العملية غير المتزامنة. يمكن استخدامها لاحقًا مع MPI_Wait أو MPI_Test لتحديد حالة العملية.

توفر روابط C++ إصدارات متراكبة من MPI_Rput تسمح بحذف وسيطات العدد أو الإزاحة عندما تكون صفرًا. يفترض الإصدار الذي يحذف عدد الهدف أن عدد الهدف هو نفس عدد المصدر.

ملاحظات

وظيفة MPI_Rput هي جزء من واجهة الاتصال أحادي الجانب لـ MPI.

يجب عدم الوصول إلى المخزن المؤقت المصدر حتى تكتمل عملية MPI_Rput. يمكن الوصول إلى المخزن المؤقت الهدف في أي وقت.

يجب أن تكون الوسيطة win نافذة تم إنشاؤها بواسطة MPI_Win_create أو MPI_Win_allocate أو MPI_Win_allocate_shared.

الوسيطة target_disp هي إزاحة بوحدات الإزاحة الأساسية، وهي حجم نوع البيانات.

كائن MPI_Request مهم. يتم إنشاؤه بواسطة الاستدعاء ويجب تحريره بواسطة المستخدم باستخدام MPI_Request_free بعد اكتمال العملية (على سبيل المثال، عبر MPI_Wait أو MPI_Test).

الأخطاء

عندما تعيد دالة MPI رمز خطأ، فهذه هي القيمة التي تعيدها دالة C/C++.

بشكل افتراضي، تعيد هذه الدالة رمز خطأ C/C++ في الحالات التالية:

  • 1، إذا تم استدعاء دالة C/C++ باستخدام مصفّف غير صالح:
    • MPI_COMM_WORLD
  • 2، إذا تم استدعاء دالة C/C++ باستخدام نافذة غير صالحة:
    • MPI_WIN_NULL
  • 3، إذا تم استدعاء دالة C/C++ باستخدام طلب غير صالح:
    • MPI_REQUEST_NULL
  • 4، إذا تم استدعاء دالة C/C++ باستخدام نوع بيانات غير صالح:
    • MPI_DATATYPE_NULL
  • 5، إذا تم استدعاء دالة C/C++ باستخدام ترتيب غير صالح:
    • rank < 0 أو rank >= حجم المصفّف
  • 6، إذا كان الاتصال غير مسموح به:
    • لا يوجد عصر نشط على النافذة
  • 7، إذا لم تكن العملية الهدف في نفس المصفّف مثل العملية المصدر.

يتم استدعاء معالج الأخطاء المرفق بالنافذة إذا أعادت هذه الدالة خطأ. يقوم معالج الأخطاء الافتراضي بإيقاف مهمة MPI.

يمكن تغيير معالج الأخطاء باستخدام MPI_Comm_set_errhandler للمصفّفات، و MPI_Win_set_errhandler للنوافذ، و MPI_File_set_errhandler للملفات، أو MPI_Session_set_errhandler للجلسات. ومع ذلك، لا تضمن MPI أن برنامج MPI يمكنه الاستمرار في العمل بعد حدوث خطأ.

قد يتم تعريف معالجات الأخطاء التالية:

  • MPI_ERRORS_ARE_FATAL إيقاف جميع العمليات.
  • MPI_ERRORS_RETURN يعيد رمز خطأ إلى التطبيق.

يمكن لتطبيقات MPI أيضًا تنفيذ معالجات أخطاء خاصة بها عن طريق استدعاء:

  • MPI_Comm_create_errhandler ثم MPI_Comm_set_errhandler
  • MPI_File_create_errhandler ثم MPI_File_set_errhandler
  • MPI_Session_create_errhandler ثم MPI_Session_set_errhandler أو عند MPI_Session_init
  • MPI_Win_create_errhandler ثم MPI_Win_set_errhandler

لاحظ أن MPI لا تضمن أن برنامج MPI يمكنه الاستمرار بعد حدوث خطأ.
