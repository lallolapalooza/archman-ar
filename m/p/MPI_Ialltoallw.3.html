معاملات الإدخال (INPUT PARAMETERS)

  • sendbuf: عنوان مخزن الإرسال.
  • sendcounts: مصفوفة أعداد صحيحة، حيث تحدد الإدخال i عدد العناصر المراد إرسالها إلى الرتبة i.
  • sdispls: مصفوفة أعداد صحيحة، حيث تحدد الإدخال i الإزاحة (بالبايت، الإزاحة من sendbuf) التي سيتم إرسال البيانات منها إلى الرتبة i.
  • sendtypes: مصفوفة أنواع بيانات، حيث تحدد الإدخال i نوع البيانات المراد استخدامه عند إرسال البيانات إلى الرتبة i.
  • recvcounts: مصفوفة أعداد صحيحة، حيث تحدد الإدخال j عدد العناصر المراد استقبالها من الرتبة j.
  • rdispls: مصفوفة أعداد صحيحة، حيث تحدد الإدخال j الإزاحة (بالبايت، الإزاحة من recvbuf) التي سيتم كتابة البيانات إليها من الرتبة j.
  • recvtypes: مصفوفة أنواع بيانات، حيث تحدد الإدخال j نوع البيانات المراد استخدامه عند استقبال البيانات من الرتبة j.
  • comm: المتواصل الذي سيتم تبادل البيانات فوقه.
  • info: معلومات (مقبض، دائم فقط)

معاملات الإخراج (OUTPUT PARAMETERS)

  • recvbuf: عنوان مخزن الاستقبال.
  • request: طلب (مقبض، غير متزامن فقط).
  • ierror: فورتران فقط: حالة الخطأ.

الوصف (DESCRIPTION)

MPI_Alltoallw هي عملية جماعية معممة تقوم فيها جميع العمليات بإرسال بيانات واستقبالها من جميع العمليات الأخرى. تضيف مرونة إلى MPI_Alltoallv من خلال السماح للمستخدم بتحديد نوع كتل البيانات الفردية (بالإضافة إلى الإزاحة وعدد العناصر). يمكن التفكير في عملها بالطريقة التالية، حيث تقوم كل عملية بإجراء 2n (n هو عدد العمليات في المتواصل comm) من اتصالات نقطة إلى نقطة مستقلة (بما في ذلك الاتصال بنفسها).

MPI_Comm_size(comm, &n);
for (i = 0, i < n; i++)
    MPI_Send(sendbuf + sdispls[i], sendcounts[i],
        sendtypes[i], i, ..., comm);
for (i = 0, i < n; i++)
    MPI_Recv(recvbuf + rdispls[i], recvcounts[i],
        recvtypes[i], i, ..., comm);

ترسل العملية j الكتلة k من sendbuf المحلية الخاصة بها إلى العملية k، والتي تضع البيانات في الكتلة j من recvbuf المحلية الخاصة بها.

عندما يتبادل زوج من العمليات البيانات، يجوز لكل منهما تمرير عدد عناصر ونوع بيانات مختلفين طالما أن المرسل يحدد نفس كمية البيانات المراد إرسالها (بالبايت) كما يتوقع المستلم استقبالها.

لاحظ أن العملية i قد ترسل كمية بيانات مختلفة إلى العملية j عما تستقبله من العملية j. أيضًا، قد ترسل العملية كميات وأنواع بيانات مختلفة تمامًا إلى عمليات مختلفة في المتواصل.

عندما يكون المتواصل متواصلاً بينيًا (INTER-COMMUNICATOR):

عندما يكون المتواصل متواصلاً بينيًا، تحدث عملية التجميع في مرحلتين. يتم تجميع البيانات من جميع أعضاء المجموعة الأولى واستقبالها بواسطة جميع أعضاء المجموعة الثانية. ثم يتم تجميع البيانات من جميع أعضاء المجموعة الثانية واستقبالها بواسطة جميع أعضاء المجموعة الأولى. تُظهر العملية سلوكًا متناظرًا مزدوج الاتجاه (full-duplex).

تحدد المجموعة الأولى العملية الجذر. تستخدم العملية الجذر MPI_ROOT كقيمة للمعامل root. تستخدم جميع العمليات الأخرى في المجموعة الأولى MPI_PROC_NULL كقيمة للمعامل root. تستخدم جميع العمليات في المجموعة الثانية رتبة العملية الجذر في المجموعة الأولى كقيمة للمعامل root.

عندما يكون المتواصل متواصلاً داخليًا (INTRA-COMMUNICATOR)، تكون هذه المجموعات متماثلة، وتحدث العملية في مرحلة واحدة.

استخدام خيار في المكان (USE OF IN-PLACE OPTION)

عندما يكون المتواصل متواصلاً داخليًا، يمكنك إجراء عملية جمع-كل-إلى-كل في المكان (يتم استخدام مخزن الإخراج كمخزن الإدخال). استخدم المتغير MPI_IN_PLACE كقيمة للمعامل sendbuf. في هذه الحالة، يتم تجاهل sendcounts و sdispls و sendtypes. يُفترض أن البيانات المدخلة لكل عملية موجودة في المساحة التي تستقبل فيها تلك العملية مساهمتها الخاصة في مخزن الاستقبال.

ملاحظات (NOTES)

يجب ألا تسبب مواصفات الأعداد والأنواع والإزاحات في كتابة أي موقع أكثر من مرة.

جميع المعاملات على جميع العمليات ذات مغزى. يجب أن يصف المعامل comm، على وجه الخصوص، نفس المتواصل على جميع العمليات.

INPUT PARAMETERS

NAME

sendbuf
Starting address of the send buffer (significant only if the rank of the process is in the set of senders).
sendcounts
Array of integers indicating the number of elements to send to each process.
displs
Array of integers indicating the displacement (in units of the corresponding datatype) from the start of the send buffer of the data for each process.
sendtypes
Array of MPI datatypes describing the data to send to each process.
recvbuf
Starting address of the receive buffer (significant only if the rank of the process is in the set of receivers).
recvcounts
Array of integers indicating the number of elements to receive from each process.
recvdispls
Array of integers indicating the displacement (in units of the corresponding datatype) from the start of the receive buffer of the data from each process.
recvtypes
Array of MPI datatypes describing the data to receive from each process.
comm
Communicator with a uniform distribution of processes.

OUTPUT PARAMETERS

NAME

request
MPI request handle (valid only if the rank of the process is in the set of senders or receivers).
IERROR
Fortran only: Error status (integer).

DESCRIPTION

MPI_Ialltoallw is the non-blocking version of MPI_Alltoallw. It is identical to MPI_Alltoallw except that it returns and leaves the communication described by request.

It performs a combination of a scatterv and gatherv operation. Specifically, all processes send recvcounts[i] elements of type recvtypes[i] starting at displacement recvdispls[i] to process i, and receive sendcounts[j] elements of type sendtypes[j] starting at displacement senddispls[j] from process j. All processes must provide the same counts, displacements, and datatypes in their calls.

All input arrays (sendcounts, displs, sendtypes, recvcounts, recvdispls, recvtypes) must be identical on all processes in the communicator.

The counts and displacements are in units of elements, not bytes. The send and receive counts, displacements, and types can be different for each process.

The send buffer must contain at least sendcounts[rank] elements of type sendtypes[rank]. The receive buffer must be large enough to hold at least recvcounts[rank] elements of type recvtypes[rank].

The displacements are relative to the start of the buffer. For send buffers, the displacement is relative to the start of the send buffer. For receive buffers, the displacement is relative to the start of the receive buffer.

The send and receive operations are non-overlapping. The send buffer can be the same as the receive buffer.

The MPI_Request_free and MPI_Wait routines can be used to complete the communication.

USE OF IN-PLACE OPTION

When the communicator is a Cartesian communicator, all reduced vector types operations allow the communicator to be the same as the argument for the receive buffer. This is the "in place" option. For the case of MPI_Ialltoallw, if the communicator is a Cartesian communicator, then the send buffer and the receive buffer arguments must be the same buffer.

In this case, the data sent by process i to process j must be placed in the send buffer in such a way that it can be received by process j from process i in the receive buffer. The send displacement must be interpreted as the displacement from the start of the buffer, and the receive displacement must be interpreted as the displacement from the start of the buffer.

The send and receive counts and datatypes must be the same for all processes. The send buffer must contain at least sendcounts[rank] elements of type sendtypes[rank]. The receive buffer must be large enough to hold at least recvcounts[rank] elements of type recvtypes[rank].

NOTES

The send and receive counts, displacements, and types are specified in units of the datatypes sendtypes and recvtypes, respectively.

ERRORS

Almost all MPI routines return an error value; C routines as the return result of the function and Fortran routines in the last argument.

Before the error value is returned, the current MPI error handler associated with the communication object (e.g., communicator, window, file) is called. If no communication object is associated with the MPI call, then the call is considered attached to MPI_COMM_SELF and will call the associated MPI error handler. When MPI_COMM_SELF is not initialized (i.e., before MPI_Init/ MPI_Init_thread, after MPI_Finalize, or when using the Sessions Model exclusively) the error raises the initial error handler. The initial error handler can be changed by calling MPI_Comm_set_errhandler on MPI_COMM_SELF when using the World model, or the mpi_initial_errhandler CLI argument to mpiexec or info key to MPI_Comm_spawn/MPI_Comm_spawn_multiple. If no other appropriate error handler has been set, then the MPI_ERRORS_RETURN error handler is called for MPI I/O functions and the MPI_ERRORS_ABORT error handler is called for all other MPI functions.

Open MPI includes three predefined error handlers that can be used:

  • MPI_ERRORS_ARE_FATAL Causes the program to abort all connected MPI processes.
  • MPI_ERRORS_ABORT An error handler that can be invoked on a communicator, window, file, or session. When called on a communicator, it acts as if MPI_Abort was called on that communicator. If called on a window or file, acts as if MPI_Abort was called on a communicator containing the group of processes in the corresponding window or file. If called on a session, aborts only the local process.
  • MPI_ERRORS_RETURN Returns an error code to the application.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.
