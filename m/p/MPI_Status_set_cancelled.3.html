MPI_Status_set_cancelled(3)

الحزمة: openmpi

التراخيص: BSD-3-Clause AND LicenseRef-MPICH

MPI_STATUS_SET_CANCELLED(3) Open MPI MPI_STATUS_SET_CANCELLED(3)

MPI_Status_set_cancelled — يضبط status للإشارة إلى إلغاء طلب.

الصيغة

صيغة C

#include <mpi.h>
int MPI_Status_set_cancelled(MPI_Status *status, int flag)

صيغة Fortran

USE MPI
! أو الصيغة الأقدم: INCLUDE 'mpif.h'
MPI_STATUS_SET_CANCELLED(STATUS, FLAG, IERROR)
     INTEGER STATUS(MPI_STATUS_SIZE), IERROR
     LOGICAL FLAG

صيغة Fortran 2008

USE mpi_f08
MPI_Status_set_cancelled(status, flag, ierror)
     TYPE(MPI_Status), INTENT(INOUT) :: status
     LOGICAL, INTENT(OUT) :: flag
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

معامل الإدخال/الإخراج

•
status: الحالة التي يتم ربط علم الإلغاء بها (status).

معامل الإدخال

•
flag: إذا تم ضبطه على صحيح (true)، فإنه يشير إلى إلغاء الطلب (logical).

معامل الإخراج

•
ierror: Fortran فقط: حالة الخطأ (integer).

الوصف

إذا تم ضبط flag على صحيح (true)، فإن استدعاء لاحق لـ MPI_Test_cancelled(status, flag*) سيعيد أيضًا flag = true؛ وإلا فإنه سيعيد false.

ملاحظات

يُنصح المستخدمون بعدم إعادة استخدام حقول الحالة لقيم أخرى غير تلك المخصصة لها. القيام بذلك قد يؤدي إلى نتائج غير متوقعة عند استخدام كائن الحالة. على سبيل المثال، قد يتسبب استدعاء MPI_Get_elements في حدوث خطأ إذا كانت القيمة خارج النطاق، أو قد يكون من المستحيل اكتشاف مثل هذا الخطأ. يمكن استخدام المعامل extra_state الذي يتم توفيره مع طلب عام لإرجاع معلومات لا تنتمي منطقياً إلى status. علاوة على ذلك، قد يؤدي تعديل القيم في حالة تم تعيينها داخليًا بواسطة MPI، مثل MPI_Recv، إلى نتائج غير قابلة للتنبؤ ويتم تثبيطها بشدة.

الأخطاء

تقريبًا جميع روتينات MPI تعيد قيمة خطأ؛ روتينات C كنتيجة إرجاع للدالة وروتينات Fortran في المعامل الأخير.

قبل إعادة قيمة الخطأ، يتم استدعاء معالج الخطأ MPI الحالي المرتبط بكائن الاتصال (مثل، المتصل، النافذة، الملف). إذا لم يكن هناك كائن اتصال مرتبط باستدعاء MPI، فسيتم اعتبار الاستدعاء مرتبطًا بـ MPI_COMM_SELF وسيستدعي معالج الخطأ MPI المرتبط. عندما لا يكون MPI_COMM_SELF مهيئًا (أي، قبل MPI_Init/MPI_Init_thread، بعد MPI_Finalize، أو عند استخدام نموذج الجلسات حصريًا) يثير الخطأ معالج الخطأ الأولي. يمكن تغيير معالج الخطأ الأولي عن طريق استدعاء MPI_Comm_set_errhandler على MPI_COMM_SELF عند استخدام نموذج العالم، أو الوسيطة CLI mpi_initial_errhandler لـ mpiexec أو مفتاح معلومات لـ MPI_Comm_spawn/MPI_Comm_spawn_multiple. إذا لم يتم تعيين معالج خطأ مناسب آخر، فسيتم استدعاء معالج الخطأ MPI_ERRORS_RETURN لوظائف MPI I/O وسيتم استدعاء معالج الخطأ MPI_ERRORS_ABORT لجميع وظائف MPI الأخرى.

يتضمن Open MPI ثلاثة معالجات أخطاء معرفة مسبقًا يمكن استخدامها:

  • MPI_ERRORS_ARE_FATAL يتسبب في إنهاء البرنامج لجميع عمليات MPI المتصلة.
  • MPI_ERRORS_ABORT معالج خطأ يمكن استدعاؤه على متصل، أو نافذة، أو ملف، أو جلسة. عند استدعائه على متصل، يتصرف كما لو تم استدعاء MPI_Abort على هذا المتصل. عند استدعائه على نافذة أو ملف، يتصرف كما لو تم استدعاء MPI_Abort على متصل يحتوي على مجموعة العمليات في النافذة أو الملف المقابل. عند استدعائه على جلسة، يقوم فقط بإنهاء العملية المحلية.
  • MPI_ERRORS_RETURN يعيد رمز خطأ إلى التطبيق.

يمكن لتطبيقات MPI أيضًا تنفيذ معالجات الأخطاء الخاصة بها عن طريق الاستدعاء:

  • MPI_Comm_create_errhandler ثم MPI_Comm_set_errhandler
  • MPI_File_create_errhandler ثم MPI_File_set_errhandler
  • MPI_Session_create_errhandler ثم MPI_Session_set_errhandler أو عند MPI_Session_init
  • MPI_Win_create_errhandler ثم MPI_Win_set_errhandler

لاحظ أن MPI لا تضمن إمكانية استمرار برنامج MPI بعد حدوث خطأ.
