MPI_Get_version(3)

الحزمة: openmpi

التراخيص: BSD-3-Clause AND LicenseRef-MPICH

MPI_GET_VERSION(3) Open MPI MPI_GET_VERSION(3)

MPI_Get_version — يعيد إصدار المعيار المقابل للتنفيذ الحالي.

الصيغة

صيغة C

#include <mpi.h>
int MPI_Get_version(int *version, int *subversion)

صيغة Fortran

USE MPI
! أو الشكل الأقدم: INCLUDE 'mpif.h'
MPI_GET_VERSION(VERSION, SUBVERSION, IERROR)
    INTEGER VERSION, SUBVERSION, IERROR

صيغة Fortran 2008

USE mpi_f08
MPI_Get_version(version, subversion, ierror)
    INTEGER, INTENT(OUT) :: version, subversion
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror

معلمات الإخراج

  • version : الرقم الرئيسي لإصدار المعيار المقابل (عدد صحيح).
  • subversion : الرقم الفرعي لإصدار المعيار المقابل (عدد صحيح).
  • ierror : Fortran فقط: حالة الخطأ (عدد صحيح).

الوصف

نظرًا لأن Open MPI v5.0.9 متوافق مع MPI-3.1 (انظر هذه الصفحة لمزيد من التفاصيل حول توافق معايير Open MPI) ستعيد هذه الوظيفة قيمة version 3 وقيمة subversion 1 لهذا الإصدار.

ملاحظة

MPI_Get_version هي واحدة من الوظائف القليلة التي يمكن استدعاؤها قبل MPI_Init وبعد MPI_Finalize.

الأخطاء

تقريبًا جميع إجراءات MPI تعيد قيمة خطأ؛ إجراءات C كنتيجة إرجاع للوظيفة وإجراءات Fortran في الوسيط الأخير.

قبل إعادة قيمة الخطأ، يتم استدعاء معالج أخطاء MPI الحالي المرتبط بكائن الاتصال (مثل، المخاطب، النافذة، الملف). إذا لم يكن هناك كائن اتصال مرتبط باستدعاء MPI، فإن الاستدعاء يعتبر مرتبطًا بـ MPI_COMM_SELF وسيستدعي معالج الخطأ MPI المرتبط. عندما لا يتم تهيئة MPI_COMM_SELF (أي، قبل MPI_Init/MPI_Init_thread، بعد MPI_Finalize، أو عند استخدام نموذج الجلسات حصريًا) يثير الخطأ معالج الخطأ الأولي. يمكن تغيير معالج الخطأ الأولي عن طريق استدعاء MPI_Comm_set_errhandler على MPI_COMM_SELF عند استخدام نموذج العالم، أو الوسيط CLI mpi_initial_errhandler لـ mpiexec أو مفتاح معلومات لـ MPI_Comm_spawn/MPI_Comm_spawn_multiple. إذا لم يتم تعيين أي معالج خطأ مناسب آخر، فسيتم استدعاء معالج الخطأ MPI_ERRORS_RETURN لوظائف إدخال/إخراج MPI وسيتم استدعاء معالج الخطأ MPI_ERRORS_ABORT لجميع وظائف MPI الأخرى.

تتضمن Open MPI ثلاثة معالجات أخطاء معرفة مسبقًا يمكن استخدامها:

  • MPI_ERRORS_ARE_FATAL يتسبب في إنهاء البرنامج لجميع عمليات MPI المتصلة.
  • MPI_ERRORS_ABORT معالج خطأ يمكن استدعاؤه على مخطب، نافذة، ملف، أو جلسة. عند استدعائه على مخطب، يتصرف كما لو تم استدعاء MPI_Abort على هذا المخطب. عند استدعائه على نافذة أو ملف، يتصرف كما لو تم استدعاء MPI_Abort على مخطب يحتوي على مجموعة العمليات في النافذة أو الملف المقابل. عند استدعائه على جلسة، يقوم فقط بإيقاف العملية المحلية.
  • MPI_ERRORS_RETURN يعيد رمز خطأ إلى التطبيق.

يمكن لتطبيقات MPI أيضًا تنفيذ معالجات أخطاء خاصة بها عن طريق استدعاء:

  • MPI_Comm_create_errhandler ثم MPI_Comm_set_errhandler
  • MPI_File_create_errhandler ثم MPI_File_set_errhandler
  • MPI_Session_create_errhandler ثم MPI_Session_set_errhandler أو في MPI_Session_init
  • MPI_Win_create_errhandler ثم MPI_Win_set_errhandler

لاحظ أن MPI لا يضمن أن برنامج MPI يمكن أن يستمر بعد الخطأ.
