MPI_Request_free(3) Open MPI MPI_Request_free(3)

MPI_Request_free — تحرير كائن طلب الاتصال.

الصيغة

صيغة C

#include <mpi.h>
int MPI_Request_free(MPI_Request *request)

صيغة Fortran

USE MPI
! أو الشكل القديم: INCLUDE 'mpif.h'
MPI_REQUEST_FREE(REQUEST, IERROR)
     INTEGER REQUEST, IERROR

صيغة Fortran 2008

USE mpi_f08
MPI_Request_free(request, ierror)
     TYPE(MPI_Request), INTENT(INOUT) :: request
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

معلمات الإدخال/الإخراج

|
request: كائن طلب الاتصال (مقبض).

الوصف

تسمح هذه العملية بتحرير كائن طلب الاتصال دون انتظار اكتمال الاتصال المرتبط به.

MPI_Request_free يحدد كائن طلب الاتصال للإفراج عنه ويضبط request إلى MPI_REQUEST_NULL. سيُسمح لأي اتصال قيد التقدم مرتبط بكائن الطلب بإكماله. سيتم تحرير كائن الطلب فقط بعد اكتمال إكماله.

ملاحظات

بمجرد تحرير كائن الطلب باستخدام MPI_Request_free، لا يمكن التحقق من اكتمال ناجح للاتصال المرتبط به باستخدام MPI_Wait أو MPI_Test. أيضًا، إذا حدث خطأ لاحقًا أثناء الاتصال، فلن تتمكن من إرجاع رمز خطأ للمستخدم؛ يجب التعامل مع هذا الخطأ على أنه خطأ فادح. قد تنشأ أسئلة حول متى يُعرف أن العمليات قد اكتملت عند استخدام MPI_Request_free. اعتمادًا على منطق البرنامج، قد تكون هناك طرق أخرى يعرف بها البرنامج أن عمليات معينة قد اكتملت، مما يجعل استخدام MPI_Request_free عمليًا. على سبيل المثال، يمكن تحرير طلب إرسال نشط عندما يكون منطق البرنامج بحيث يقوم المستلم بإرسال رد على الرسالة المرسلة - وصول الرد يبلغ المرسل بأن الإرسال قد اكتمل ويمكن إعادة استخدام مخزن الإرسال المؤقت. يجب عدم تحرير طلب استقبال نشط، حيث لن يتمكن المستلم من التحقق من اكتمال الاستقبال ويمكن إعادة استخدام مخزن الاستقبال المؤقت.

مثال:

CALL MPI_COMM_RANK(MPI_COMM_WORLD, rank)
IF(rank == 0) THEN
    DO i=1, n
      CALL MPI_ISEND(outval, 1, MPI_REAL, 1, 0, req, ierr)
      CALL MPI_REQUEST_FREE(req, ierr)
      CALL MPI_IRECV(inval, 1, MPI_REAL, 1, 0, req, ierr)
      CALL MPI_WAIT(req, status, ierr)
    END DO
ELSE IF (rank == 1) THEN
    CALL MPI_IRECV(inval, 1, MPI_REAL, 0, 0, req, ierr)
    CALL MPI_WAIT(req, status)
    DO I=1, n-1
       CALL MPI_ISEND(outval, 1, MPI_REAL, 0, 0, req, ierr)
       CALL MPI_REQUEST_FREE(req, ierr)
       CALL MPI_IRECV(inval, 1, MPI_REAL, 0, 0, req, ierr)
       CALL MPI_WAIT(req, status, ierr)
    END DO
    CALL MPI_ISEND(outval, 1, MPI_REAL, 0, 0, req, ierr)
    CALL MPI_WAIT(req, status)
END IF

عادةً ما تُستخدم هذه الروتينات لتحرير الطلبات المستمرة التي تم إنشاؤها باستخدام MPI_Recv_init أو MPI_Send_init والأدوات المساعدة الخاصة بها. ومع ذلك، يمكن استخدامها لتحرير طلب تم إنشاؤه باستخدام MPI_Irecv أو MPI_Isend والأدوات المساعدة الخاصة بها؛ في هذه الحالة، لا يمكن استخدام روتين الاختبار أو الانتظار على كائن الطلب. يُسمح بتحرير طلب نشط. ومع ذلك، بمجرد تحريره، لا يمكن استخدام كائن الطلب في روتين انتظار أو اختبار (على سبيل المثال، MPI_Wait).

الأخطاء

في الغالب، تُرجع روتينات MPI قيمة خطأ؛ تُرجع روتينات C قيمة نتيجة الدالة، وتُرجع روتينات Fortran في الوسيط الأخير.

قبل إعادة قيمة الخطأ، يتم استدعاء معالج الخطأ الحالي المرتبط بكائن الاتصال (على سبيل المثال، المتصل، النافذة، الملف). إذا لم يكن هناك كائن اتصال مرتبط بالاستدعاء MPI، فسيتم اعتبار الاستدعاء مرتبطًا بـ MPI_COMM_SELF وسيتم استدعاء معالج الخطأ المرتبط. عندما لا يتم تهيئة MPI_COMM_SELF (أي، قبل MPI_Init/MPI_Init_thread، بعد MPI_Finalize، أو عند استخدام نموذج الجلسة حصريًا)، يقوم الخطأ بتشغيل معالج الخطأ الأولي. يمكن تغيير معالج الخطأ الأولي عن طريق استدعاء MPI_Comm_set_errhandler في MPI_COMM_SELF عند استخدام نموذج العالم، أو الوسيط CLI mpi_initial_errhandler لـ mpiexec أو مفتاح المعلومات لـ MPI_Comm_spawn/MPI_Comm_spawn_multiple. إذا لم يكن هناك معالج خطأ مناسب آخر، فسيتم استدعاء معالج الخطأ MPI_ERRORS_RETURN لوظائف إدخال/إخراج MPI، وسيتم استدعاء معالج الخطأ MPI_ERRORS_ABORT لجميع وظائف MPI الأخرى.

تتضمن Open MPI ثلاثة معالجات أخطاء افتراضية يمكن استخدامها:

  • MPI_ERRORS_ARE_FATAL — التطبيق يقوم بإلغاء جميع عمليات MPI المتصلة.
  • MPI_ERRORS_ABORT — معالج خطأ يمكن استدعاؤه على متصل، نافذة، ملف، أو جلسة. عند استدعائه على متصل، فإنه يعمل كما لو تم استدعاء MPI_Abort على هذا المتصل. إذا تم استدعاؤه على نافذة أو ملف، فإنه يعمل كما لو تم استدعاء MPI_Abort على متصل يحتوي على مجموعة العمليات في النافذة أو الملف المقابل. إذا تم استدعاؤه على جلسة، فإنه يلغي العملية المحلية فقط.
  • MPI_ERRORS_RETURN — يرجع رمز خطأ إلى التطبيق.

يمكن لتطبيقات MPI أيضًا تنفيذ معالجات الأخطاء الخاصة بها عن طريق استدعاء:

  • MPI_Comm_create_errhandler ثم MPI_Comm_set_errhandler
  • MPI_File_create_errhandler ثم MPI_File_set_errhandler
  • MPI_Session_create_errhandler ثم MPI_Session_set_errhandler أو في MPI_Session_init
  • MPI_Win_create_errhandler ثم MPI_Win_set_errhandler

ملاحظة: لا يُضمن أن يتمكن تطبيق MPI من الاستمرار بعد حدوث خطأ.
