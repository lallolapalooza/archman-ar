MPI_Ibcast(3)

الحزمة: openmpi

التراخيص: BSD-3-Clause AND LicenseRef-MPICH

MPI_IBCAST(3) Open MPI MPI_IBCAST(3)

MPI_Bcast, MPI_Ibcast - يبث رسالة من العملية ذات الرتبة root إلى جميع العمليات الأخرى في المجموعة.

الصيغة

صيغة C

#include <mpi.h>
int MPI_Bcast(void *buffer, int count, MPI_Datatype datatype,
    int root, MPI_Comm comm)
int MPI_Ibcast(void *buffer, int count, MPI_Datatype datatype,
    int root, MPI_Comm comm, MPI_Request *request)

صيغة Fortran

USE MPI
! أو الصيغة الأقدم: INCLUDE 'mpif.h'
MPI_BCAST(BUFFER, COUNT, DATATYPE, ROOT, COMM, IERROR)
    <type>  BUFFER(*)
    INTEGER COUNT, DATATYPE, ROOT, COMM, IERROR
MPI_IBCAST(BUFFER, COUNT, DATATYPE, ROOT, COMM, REQUEST, IERROR)
    <type>  BUFFER(*)
    INTEGER COUNT, DATATYPE, ROOT, COMM, REQUEST, IERROR

صيغة Fortran 2008

USE mpi_f08
MPI_Bcast(buffer, count, datatype, root, comm, ierror)
    TYPE(*), DIMENSION(..) :: buffer
    INTEGER, INTENT(IN) :: count, root
    TYPE(MPI_Datatype), INTENT(IN) :: datatype
    TYPE(MPI_Comm), INTENT(IN) :: comm
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror
MPI_Ibcast(buffer, count, datatype, root, comm, request, ierror)
    TYPE(*), DIMENSION(..), ASYNCHRONOUS :: buffer
    INTEGER, INTENT(IN) :: count, root
    TYPE(MPI_Datatype), INTENT(IN) :: datatype
    TYPE(MPI_Comm), INTENT(IN) :: comm
    TYPE(MPI_Request), INTENT(OUT) :: request
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror

معاملات الإدخال/الإخراج

  • buffer: عنوان بداية المخزن المؤقت (اختياري).
  • count: عدد الإدخالات في المخزن المؤقت (عدد صحيح).
  • datatype: نوع بيانات المخزن المؤقت (مقبض).
  • root: رتبة عملية البث (عدد صحيح).
  • comm: المتواصل (مقبض).

معاملات الإخراج

  • request: طلب (مقبض، غير متزامن فقط).
  • ierror: Fortran فقط: حالة الخطأ (عدد صحيح).

الوصف

MPI_Bcast يبث رسالة من العملية ذات الرتبة root إلى جميع العمليات في المجموعة، بما في ذلك نفسها. يتم استدعاؤه بواسطة جميع أعضاء المجموعة باستخدام نفس المعاملات لـ comm و root. عند العودة، تم نسخ محتويات المخزن المؤقت للاتصال الخاص بـ root إلى جميع العمليات.

يُسمح بأنواع البيانات العامة المشتقة لـ datatype. يجب أن يتطابق توقيع النوع لـ count و datatype على أي عملية مع توقيع النوع لـ count و datatype عند root. هذا يعني أن كمية البيانات المرسلة يجب أن تكون مساوية لكمية البيانات المستلمة، بشكل ثنائي بين كل عملية و root. MPI_Bcast وجميع روتينات نقل البيانات الجماعية الأخرى تجعل هذا القيد. لا تزال خرائط الأنواع المتميزة بين المرسل والمستقبل مسموح بها.

مثال: بث 100 عدد صحيح من العملية 0 إلى كل عملية في المجموعة.

MPI_Comm comm;
int array[100];
int root=0;
//...
MPI_Bcast( array, 100, MPI_INT, root, comm);

كما هو الحال في العديد من أجزاء الكود النموذجية لدينا، نفترض أن بعض المتغيرات (مثل comm في المثال أعلاه) قد تم تعيين قيم مناسبة لها.

عندما يكون المتواصل متواصلاً بين المجموعات

عندما يكون المتواصل متواصلاً بين المجموعات، تقوم عملية root في المجموعة الأولى ببث البيانات إلى جميع العمليات في المجموعة الثانية. تحدد المجموعة الأولى عملية root. تستخدم تلك العملية MPI_ROOT كقيمة لمعامل root الخاص بها. تستخدم العمليات المتبقية MPI_PROC_NULL كقيمة لمعامل root الخاص بها. تستخدم جميع العمليات في المجموعة الثانية رتبة عملية root تلك في المجموعة الأولى كقيمة لمعامل root الخاص بها. يجب أن تكون معاملات المخزن المؤقت للاستقبال للعمليات في المجموعة الثانية متوافقة مع معامل المخزن المؤقت للإرسال لعملية root في المجموعة الأولى.

ملاحظات

هذه الوظيفة لا تدعم خيار "in-place" (في مكانه).

الأخطاء

تقريباً جميع روتينات MPI تعيد قيمة خطأ؛ روتينات C كنتيجة للإرجاع للدالة، وروتينات Fortran في المعامل الأخير.

قبل إرجاع قيمة الخطأ، يتم استدعاء معالج أخطاء MPI الحالي المرتبط بكيان الاتصال (مثل المتواصل، النافذة، الملف). إذا لم يتم ربط أي كيان اتصال باستدعاء MPI، فيعتبر الاستدعاء مرتبطًا بـ MPI_COMM_SELF ويستدعي معالج الأخطاء المقابل. عندما لا يتم تهيئة MPI_COMM_SELF (أي، قبل MPI_Init/MPI_Init_thread، بعد MPI_Finalize، أو عند استخدام نموذج الجلسات حصريًا) يثير الخطأ معالج الأخطاء الأولي. يمكن تغيير معالج الأخطاء الأولي عن طريق استدعاء MPI_Comm_set_errhandler على MPI_COMM_SELF عند استخدام نموذج العالم، أو وسيطة سطر الأوامر MPI_ERRORS_RETURN إلى mpiexec أو مفتاح معلومات إلى MPI_Comm_spawn/MPI_Comm_spawn_multiple. إذا لم يتم تعيين معالج أخطاء مناسب آخر، فسيتم استدعاء معالج أخطاء MPI_ERRORS_RETURN لوظائف MPI I/O وسيتم استدعاء معالج أخطاء MPI_ERRORS_ABORT لجميع وظائف MPI الأخرى.

يتضمن Open MPI ثلاثة معالجات أخطاء معرفة مسبقًا يمكن استخدامها:

  • MPI_ERRORS_ARE_FATAL يتسبب في إنهاء البرنامج لجميع عمليات MPI المتصلة.
  • MPI_ERRORS_ABORT معالج أخطاء يمكن استدعاؤه على متواصل، نافذة، ملف، أو جلسة. عند استدعائه على متواصل، يتصرف كما لو تم استدعاء MPI_Abort على هذا المتواصل. عند استدعائه على نافذة أو ملف، يتصرف كما لو تم استدعاء MPI_Abort على متواصل يحتوي على مجموعة العمليات في النافذة أو الملف المقابل. عند استدعائه على جلسة، ينهي العملية المحلية فقط.
  • MPI_ERRORS_RETURN يعيد رمز خطأ إلى التطبيق.

يمكن لتطبيقات MPI أيضًا تنفيذ معالجات الأخطاء الخاصة بها عن طريق الاستدعاء:

  • MPI_Comm_create_errhandler ثم MPI_Comm_set_errhandler
  • MPI_File_create_errhandler ثم MPI_File_set_errhandler
  • MPI_Session_create_errhandler ثم MPI_Session_set_errhandler أو عند MPI_Session_init
  • MPI_Win_create_errhandler ثم MPI_Win_set_errhandler

لاحظ أن MPI لا تضمن أن برنامج MPI يمكن أن يستمر بعد حدوث خطأ.
