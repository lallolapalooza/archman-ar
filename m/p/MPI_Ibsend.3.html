MPI_Ibsend(3)

الحزمة: openmpi

التراخيص: BSD-3-Clause AND LicenseRef-MPICH

MPI_IBSEND(3) Open MPI MPI_IBSEND(3)

MPI_Ibsend — تبدأ إرسال مخزن مؤقت غير متزامن.

الصيغة

صيغة C

#include <mpi.h>
int MPI_Ibsend(const void *buf, int count, MPI_Datatype datatype,
     int dest, int tag, MPI_Comm comm, MPI_Request *request)

صيغة Fortran

USE MPI
! أو الصيغة الأقدم: INCLUDE 'mpif.h'
MPI_IBSEND(BUF, COUNT, DATATYPE, DEST, TAG, COMM, REQUEST, IERROR)
     <type>  BUF(*)
     INTEGER COUNT, DATATYPE, DEST, TAG, COMM, REQUEST, IERROR

صيغة Fortran 2008

USE mpi_f08
MPI_Ibsend(buf, count, datatype, dest, tag, comm, request, ierror)
     TYPE(*), DIMENSION(..), INTENT(IN), ASYNCHRONOUS :: buf
     INTEGER, INTENT(IN) :: count, dest, tag
     TYPE(MPI_Datatype), INTENT(IN) :: datatype
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(MPI_Request), INTENT(OUT) :: request
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

معلمات الإدخال

  • buf: عنوان بداية المخزن المؤقت للإرسال (اختياري).
  • count: عدد العناصر في المخزن المؤقت للإرسال (عدد صحيح).
  • datatype: نوع بيانات كل عنصر في المخزن المؤقت للإرسال (معالج).
  • dest: رتبة الوجهة (عدد صحيح).
  • tag: علامة الرسالة (عدد صحيح).
  • comm: المتواصل (معالج).

معلمات الإخراج

  • request: طلب الاتصال (معالج).
  • ierror: Fortran فقط: حالة الخطأ (عدد صحيح).

الوصف

MPI_Ibsend تنشر إرسالًا غير متزامن في وضع التخزين المؤقت. تخصص استدعاءات عدم التزامن كائن طلب اتصال وتربطه بمعالج الطلب (المعلمة request). يمكن استخدام الطلب لاحقًا للاستعلام عن حالة الاتصال أو الانتظار لإكماله.

يشير استدعاء الإرسال غير المتزامن إلى أن النظام قد يبدأ في نسخ البيانات خارج المخزن المؤقت للإرسال. يجب على المرسل عدم تعديل أي جزء من المخزن المؤقت للإرسال بعد استدعاء عملية الإرسال غير المتزامنة، حتى يكتمل الإرسال.

الأخطاء

تقريبًا جميع روتينات MPI تُرجع قيمة خطأ؛ روتينات C كنتيجة للدالة وروتينات Fortran في المعلمة الأخيرة.

قبل إرجاع قيمة الخطأ، يتم استدعاء معالج الخطأ MPI الحالي المرتبط بـ كائن الاتصال (مثل المتواصل، النافذة، الملف). إذا لم يكن هناك كائن اتصال مرتبط باستدعاء MPI، فإن الاستدعاء يعتبر ملحقًا بـ MPI_COMM_SELF وسيقوم باستدعاء معالج الخطأ MPI المرتبط. عندما لا يتم تهيئة MPI_COMM_SELF (أي، قبل MPI_Init/MPI_Init_thread، بعد MPI_Finalize، أو عند استخدام نموذج الجلسات حصريًا) يثير الخطأ معالج الخطأ الأولي. يمكن تغيير معالج الخطأ الأولي عن طريق استدعاء MPI_Comm_set_errhandler على MPI_COMM_SELF عند استخدام نموذج World، أو وسيطة سطر الأوامر mpi_initial_errhandler لـ mpiexec أو مفتاح معلومات لـ MPI_Comm_spawn/MPI_Comm_spawn_multiple. إذا لم يتم تعيين أي معالج خطأ مناسب آخر، فسيتم استدعاء معالج الخطأ MPI_ERRORS_RETURN لوظائف MPI I/O وسيتم استدعاء معالج الخطأ MPI_ERRORS_ABORT لجميع وظائف MPI الأخرى.

يتضمن Open MPI ثلاثة معالجات خطأ محددة مسبقًا يمكن استخدامها:

  • MPI_ERRORS_ARE_FATAL يتسبب في إنهاء البرنامج لجميع عمليات MPI المتصلة.
  • MPI_ERRORS_ABORT معالج خطأ يمكن استدعاؤه على متواصل، نافذة، ملف، أو جلسة. عند استدعائه على متواصل، يتصرف كما لو تم استدعاء MPI_Abort على هذا المتواصل. عند استدعائه على نافذة أو ملف، يتصرف كما لو تم استدعاء MPI_Abort على متواصل يحتوي على مجموعة العمليات في النافذة أو الملف المقابل. عند استدعائه على جلسة، يقوم فقط بإنهاء العملية المحلية.
  • MPI_ERRORS_RETURN يعيد رمز خطأ إلى التطبيق.

يمكن لتطبيقات MPI أيضًا تنفيذ معالجات الخطأ الخاصة بها عن طريق استدعاء:

  • MPI_Comm_create_errhandler ثم MPI_Comm_set_errhandler
  • MPI_File_create_errhandler ثم MPI_File_set_errhandler
  • MPI_Session_create_errhandler ثم MPI_Session_set_errhandler أو عند MPI_Session_init
  • MPI_Win_create_errhandler ثم MPI_Win_set_errhandler

لاحظ أن MPI لا يضمن أن برنامج MPI يمكن أن يستمر بعد الخطأ.
