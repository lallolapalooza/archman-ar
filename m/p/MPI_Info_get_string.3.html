MPI_Info_get_string(3)

الحزمة: openmpi

التراخيص: BSD-3-Clause AND LicenseRef-MPICH

MPI_INFO_GET_STRING(3) Open MPI MPI_INFO_GET_STRING(3)

MPI_Info_get_string — يسترجع القيمة المرتبطة بمفتاح في كائن معلومات.

صيغة الاستدعاء

صيغة C

#include <mpi.h>
int MPI_Info_get_string(MPI_Info info, const char *key, int *buflen, char *value, int *flag)

صيغة Fortran

USE MPI
! أو الصيغة الأقدم: INCLUDE 'mpif.h'
MPI_INFO_GET_STRING(INFO, KEY, BUFLEN, VALUE, FLAG, IERROR)
     INTEGER INFO, BUFLEN, IERROR
     CHARACTER*(*) KEY, VALUE
     LOGICAL FLAG

صيغة Fortran 2008

USE mpi_f08
MPI_Info_get_string(info, key, buflen, value, flag, ierror)
     TYPE(MPI_Info), INTENT(IN) :: info
     CHARACTER(LEN=*), INTENT(IN) :: key
     INTEGER, INTENT(INOUT) :: buflen
     CHARACTER(LEN=valuelen), INTENT(OUT) :: value
     LOGICAL, INTENT(OUT) :: flag
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

معلمات الإدخال

  • info: كائن المعلومات (مقبض).
  • key: المفتاح (سلسلة نصية).

معلمات الإخراج

  • buflen عند الدخول، طول الوسيط value. عند العودة، يتم تعيينه إلى الحجم المطلوب لـ: احتواء السلسلة النصية للقيمة (عدد صحيح).
  • value: القيمة (سلسلة نصية).
  • flag: يتم تعيينه إلى true إذا كان المفتاح معرفًا، وإلى false إذا لم يكن كذلك (قيمة منطقية).
  • ierror: Fortran فقط: حالة الخطأ (عدد صحيح).

الوصف

MPI_Info_get_string تسترجع القيمة المرتبطة بـ key من info، إن وجدت. إذا كان هذا المفتاح موجودًا في info، فإنه يضبط flag على true ويعيد القيمة في value، وإلا فإنه يضبط flag على false ويترك value دون تغيير. buflen عند الإدخال هو حجم المخزن المؤقت المقدم، ولإخراج buflen هو حجم المخزن المؤقت المطلوب لتخزين سلسلة القيمة. إذا كان buflen الذي تم تمريره إلى الدالة أقل من الحجم الفعلي المطلوب لتخزين سلسلة القيمة (بما في ذلك المحدد الصفري في C)، فسيتم اقتطاع القيمة. عند العودة، سيتم تعيين قيمة buflen إلى حجم المخزن المؤقت المطلوب لتخزين سلسلة القيمة. إذا تم تعيين buflen إلى 0، فلن تتغير value. في C، buflen يتضمن المساحة المطلوبة للمحدد الصفري. في C، هذه الدالة تعيد سلسلة نصية محددة بـ null في جميع الحالات التي تكون فيها قيمة buflen المدخلة أكبر من 0.

إذا كان key أكبر من MPI_MAX_INFO_KEY، فإن الاستدعاء يعتبر خطأ.

الأخطاء

تقريبًا جميع إجراءات MPI تعيد قيمة خطأ؛ في C، تكون النتيجة هي قيمة الإرجاع للدالة، وفي Fortran تكون في الوسيط الأخير.

قبل إعادة قيمة الخطأ، يتم استدعاء معالج أخطاء MPI الحالي المرتبط بكائن الاتصال (على سبيل المثال، المتصل، النافذة، الملف). إذا لم يكن هناك كائن اتصال مرتبط باستدعاء MPI، فسيتم اعتبار الاستدعاء مرتبطًا بـ MPI_COMM_SELF وسيتم استدعاء معالج الأخطاء المرتبط به. عندما لا يكون MPI_COMM_SELF مهيأً (أي، قبل MPI_Init/MPI_Init_thread، بعد MPI_Finalize، أو عند استخدام نموذج الجلسات حصريًا)، يثير الخطأ معالج الأخطاء الأولي. يمكن تغيير معالج الأخطاء الأولي عن طريق استدعاء MPI_Comm_set_errhandler على MPI_COMM_SELF عند استخدام نموذج العالم، أو وسيط سطر الأوامر mpiexec mpi_initial_errhandler، أو مفتاح معلومات لـ MPI_Comm_spawn/MPI_Comm_spawn_multiple. إذا لم يتم تعيين أي معالج أخطاء مناسب آخر، فسيتم استدعاء معالج الأخطاء MPI_ERRORS_RETURN لوظائف MPI I/O، وسيتم استدعاء معالج الأخطاء MPI_ERRORS_ABORT لجميع وظائف MPI الأخرى.

تتضمن Open MPI ثلاثة معالجات أخطاء محددة مسبقًا يمكن استخدامها:

  • MPI_ERRORS_ARE_FATAL يسبب إنهاء البرنامج لجميع عمليات MPI المتصلة.
  • MPI_ERRORS_ABORT معالج أخطاء يمكن استدعاؤه على متصل، نافذة، ملف، أو جلسة. عند استدعائه على متصل، يتصرف كما لو تم استدعاء MPI_Abort على هذا المتصل. إذا تم استدعاؤه على نافذة أو ملف، يتصرف كما لو تم استدعاء MPI_Abort على متصل يحتوي على مجموعة العمليات في النافذة أو الملف المقابل. إذا تم استدعاؤه على جلسة، فإنه ينهي العملية المحلية فقط.
  • MPI_ERRORS_RETURN يعيد رمز خطأ إلى التطبيق.

يمكن لتطبيقات MPI أيضًا تنفيذ معالجات أخطاء خاصة بها عن طريق استدعاء:

  • MPI_Comm_create_errhandler ثم MPI_Comm_set_errhandler
  • MPI_File_create_errhandler ثم MPI_File_set_errhandler
  • MPI_Session_create_errhandler ثم MPI_Session_set_errhandler أو عند MPI_Session_init
  • MPI_Win_create_errhandler ثم MPI_Win_set_errhandler

لاحظ أن MPI لا يضمن أن برنامج MPI يمكن أن يستمر بعد حدوث خطأ.
