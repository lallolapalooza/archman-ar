الاسم

mfsmetadump - تفريغ معلومات بيانات MooseFS الوصفية بتنسيق قابل للقراءة.

الملخص

mfsmetadump [-d] [-s اسم_القسم] ملف_البيانات_الوصفية

الوصف

mfsmetadump يقوم بتفريغ معلومات بيانات MooseFS الوصفية بتنسيق قابل للقراءة. يتكون الإخراج من عدة أقسام بأنواع مختلفة من المعلومات. كل قسم يتكون من بيانات رأس - صفوف تبدأ بعلامة هاش (#) - وبيانات محتوى (قد تكون فارغة).

الخيارات

-d - استبدال جميع الأحرف غير القابلة للطباعة (الرموز < 32 و > 126) بـ '.' (كان هذا هو السلوك الافتراضي في الإصدار < 3.0.110).

-s - تفريغ القسم المحدد فقط من الملف. الأقسام الممكنة:

HEAD - معلومات الرأس
SESS - جلسات العملاء
LABS - تسميات (غير مستخدمة)
SCLA - فئات التخزين
PATT - تجاوزات الأنماط
NODE - عقد الشجرة (i-nodes)
EDGE - أسماء ملفات الشجرة (أسماء الملفات)
FREE - العقد الحرة (i-nodes المحذوفة)
QUOT - تعريفات الحصص
XATR - بيانات xattr
PACL - بيانات acl posix
OPEN - الملفات المفتوحة
FLCK - بيانات flock
PLCK - بيانات lockf, ioctl الخاصة بـ posix
CSDB - خوادم الأجزاء النشطة
CHNK - الأجزاء
ملف_البيانات_الوصفية
مسار ملف metadata.mfs

NAME

mfsmetadump — dump metadata from MooseFS master server

SYNOPSIS

mfsmetadump [-h] [-V] [-f

METADATA_FILE

] [-o

OUTPUT_FILE

]

DESCRIPTION

The mfsmetadump command dumps metadata information from a metadata backup file (created by mfsmasterbackup) or from a running master server. The metadata is dumped in a human-readable format. It can be used to inspect the metadata or to perform some sanity checks.

If no metadata file is specified using the -f option, mfsmetadump will try to connect to the master server specified in configuration file (mfsmaster.cfg(5)). If successful, it will dump the current metadata from the master server.

OPTIONS

-h
Show help message.
-V
Show program version.
-f METADATA_FILE
Path to the metadata file to be dumped. If not specified, connection to master server is attempted.
-o OUTPUT_FILE
Path to the output file. If not specified, output is written to standard output.

NOTES

The output format is based on a specific structure for metadata sections. Each section is introduced by a tag followed by a description or data. Here's a breakdown of the possible sections and their elements:

OPENFILE SECTION (OFLNK)

OPENFILE
line with open file description 
s	session id
i	inode number

FLOCK LOCK SECTION (FLCK)

FLOCK
line with flock-lock description 
i	inode number
s	session id
o	lock owner (FUSE lock owner)
t	lock type ('R' - shared lock, 'W' - exclusive lock)

POSIX LOCK SECTION (PLCK)

POSIXLOCK
line with posix-lock description 
i	inode number
s	session id
o	lock owner (FUSE lock owner)
p	local process id (owner pid)
r	lock range in format <START,END)
t	lock type ('R' - shared lock, 'W' - exclusive lock)

CHUNKSERVERS SECTION (CSDB)

chunk servers
number of chunkservers
CHUNCKSERVER
line with chunk server description 
i	server ip
p	server port
#	server id
m	maintenance mode
t	maintenance timeout timestamp

CHUNKS SECTION (CHNK)

nextchunkid
first available chunk number
CHUNK
line with chunk description 
i	chunk number
v	chunk version
t	timestamp, if in the future, means lock timestamp, if in the past, last modification timestamp
a	archive flag
(s,#)	list of entries, s is storage class id, # is number of files in this storage class containing this chunk
c	calculated storage class id (effectively used class id, if a chunk has more than one)

NOTICE! If a chunk's timestamp equals 0, it means the chunk was created by MooseFS version older than 4.45.0 and has not been locked or modified since.
