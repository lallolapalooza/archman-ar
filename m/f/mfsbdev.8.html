mfsbdev(8)

الحزمة: moosefs

التراخيص: GPL-2.0-only

mfsbdev(8) هذا جزء من MooseFS mfsbdev(8)

الاسم

mfsbdev - خادم/أداة إدارة جهاز كتلة MooseFS

الملخص

mfsbdev start [-H masterhost] [-P masterport] [-B masterbind] [-S masterpath] [-p masterpassword | -x passwordfile] [-l linksocket] [-i init_mappings_file] [-o options]

mfsbdev stop [-l linksocket]

mfsbdev map [-l linksocket] -f mfsfile [-d nbddevice] [-n linkname] [-s bdevsize] [-b blocksize | -5 | -1 | -2 | -4] [-r] [-i]

mfsbdev unmap [-l linksocket] ( -f mfsfile | -d nbddevice | -n linkname )

mfsbdev list [-l linksocket] [-t m|u|i]

mfsbdev resize [-l linksocket] ( -f mfsfile | -d nbddevice | -n linkname ) [-s bdevsize]

الوصف

تُستخدم هذه الأداة لإدارة أجهزة الكتلة. تعمل هذه الأداة في نظام Linux فقط. يجب تحميل وحدة النواة nbd لكي تعمل هذه الأداة بشكل صحيح.

الأوامر

start - يبدأ الخادم؛ يستمع الخادم فقط على مقبس في هذه النقطة؛ تستخدم جميع الأوامر الأخرى المقبس للتواصل مع الخادم؛ إذا لم يتم تحديد مقبس عبر الخيار -l، يتم استخدام الافتراضي: /dev/mfs/nbdsock

stop - يوقف الخادم

map - يعين ملفًا على mfs ليتم استخدامه كجهاز كتلة

unmap - يزيل تعيينًا

list - يسرد التعيينات الحالية

resize - يغير حجم جهاز الكتلة (يتطلب إصدار نواة 4.18 أو أعلى)

الخيارات

-H - المضيف الرئيسي؛ الافتراضي هو 'mfsmaster'

-P - منفذ المضيف الرئيسي؛ الافتراضي هو '9421'

-S - مسار المضيف الرئيسي (مجلد فرعي في MFS سيتم استخدامه كجذر لجميع تعيينات أجهزة الكتلة)؛ الافتراضي هو '/'

-p - كلمة مرور المضيف الرئيسي؛ متعارضة مع الخيار -x؛ إذا لم يتم توفير -p أو -x، تحاول الأداة الاتصال بدون كلمة مرور

-x - المسار إلى ملف يحتوي على كلمة مرور المضيف الرئيسي؛ متعارضة مع الخيار -p؛ إذا لم يتم توفير -p أو -x، تحاول الأداة الاتصال بدون كلمة مرور

-l - المسار إلى مقبس الاتصال؛ الافتراضي هو /dev/mfs/nbdsock

-f - المسار إلى ملف mfs المستخدم لتعيين جهاز الكتلة؛

-d - المسار إلى جهاز الكتلة الشبكي ('/dev/nbdX')؛ افتراضيًا (إذا لم يتم توفير هذا المعلمة) يتم استخدام أول جهاز متاح مع أمر map

-n - اسم الرابط الرمزي الذي تم إنشاؤه في '/dev/mfs'، والذي يشير إلى جهاز الكتلة الشبكي الذي تم إنشاؤه بواسطة أمر map؛ الافتراضي هو مزيج من اسم المضيف الرئيسي والمنفذ واسم ملف mfs

-s - حجم جهاز الكتلة، يمكن استخدام كل من لاحقات SI و IEC؛ الافتراضي هو حجم الملف الذي تم تعيين جهاز الكتلة إليه

-b - حجم الكتلة بالبايت

-5 - استخدام حجم كتلة 512 بايت (يعادل -b 512)

-1 - استخدام حجم كتلة 1024 بايت (يعادل -b 1024)

-2 - استخدام حجم كتلة 2048 بايت (يعادل -b 2048)

-4 - استخدام حجم كتلة 4096 بايت (يعادل -b 4096)

-r - يعين جهاز الكتلة للقراءة فقط (يسمح بتعيينات متعددة لنفس الملف)

-i (map) - تجاهل الأقفال؛ يمكن تعيين ملف واحد لأكثر من جهاز كتلة واحد، سيحاول كل عملية تعيين الحصول على القفل المناسب (مشترك للقراءة فقط، حصري للكتابة والقراءة) ولكنه سينجح حتى لو لم يتم الحصول على القفل

-t - يجبر أمر list على عرض المعلومات بتنسيق جاهز للاستخدام مع أمر map (المعلمة m) أو unmap (المعلمة u) أو مع تنسيق ملف MooseFS mfsbdev.cfg (المعلمة i)

-i (start) - استخدام ملف التكوين المقدم في المعلمة لبدء أجهزة الكتلة الأولية؛ للتنسيق انظر mfsbdev.cfg(5)

-o - معلمات إضافية، بتنسيق مشابه لـ mfsmount، يمكن تعريف العديد من المعلمات، مفصولة بفاصلة:

mfswritecachesize=N
تحديد حجم ذاكرة التخزين المؤقت للكتابة بالميغابايت (في النطاق: 16..2048 - الافتراضي: 128)
mfsreadaheadsize=N
تحديد حجم جميع مخازن القراءة المسبقة بالميغابايت (في النطاق: 16..2048 - الافتراضي: 128)
mfsreadaheadleng=N
تحديد كمية البايتات التي سيتم قراءتها إضافيًا (في النطاق: 128 كيلوبايت..2 ميغابايت - الافتراضي: 2097152 = 2 ميغابايت)
mfsreadaheadtrigger=N
تحديد كمية البايتات المقروءة بالتتابع التي تشغل القراءة المسبقة (الافتراضي: 20971520)
mfserroronlostchunk
عندما تكون جميع خوادم الأجزاء المعروفة متصلة بالرئيسي ويكون الجزء المطلوب مفقودًا، يتم إنهاء عملية الإدخال/الإخراج فورًا وإرجاع خطأ
mfserroronnospace
عندما تكون جميع خوادم الأجزاء المعروفة متصلة بالرئيسي ولا توجد مساحة خالية، يتم إنهاء عملية الإدخال/الإخراج فورًا وإرجاع خطأ
mfsioretries=N
تحديد عدد المحاولات قبل إرجاع خطأ في الإدخال/الإخراج (الافتراضي: 30)
mfstimeout=N
تحديد الحد الأقصى للوقت بالثواني قبل إرجاع خطأ في الإدخال/الإخراج (الافتراضي: 0 - مما يعني عدم وجود مهلة)
mfslogretry=N
تحديد الحد الأدنى لعدد مرات إعادة المحاولة الذي سيبدأ النظام عنده في تسجيل رسائل الإدخال/الإخراج (الافتراضي: 5)
mfsmaster=HOST
الاتصال برئيس MooseFS على HOST (الافتراضي هو mfsmaster) - يعادل -H
mfsport=PORT
الاتصال برئيس MooseFS على PORT (الافتراضي هو 9421) - يعادل -P
mfsbind=IP
العنوان المحلي المستخدم للاتصال بالرئيس بدلاً من الافتراضي - يعادل -B
mfssubfolder=PATH
تحميل دليل MooseFS المحدد (الافتراضي هو /، أي نظام الملفات بالكامل) - يعادل -S
mfspassword=PASSWORD
المصادقة مع رئيس MooseFS باستخدام PASSWORD
mfspreflabels=LABELEXPR
تحديد الملصقات المفضلة لاختيار خوادم الأجزاء أثناء عملية الإدخال/الإخراج
mfsnbdtimeout=N
تحديد الحد الأقصى للوقت بالثواني قبل أن تستسلم النواة (الافتراضي: 1800)

الملفات

mfsbdev.cfg
ملف تكوين خادم أجهزة الكتلة لـ MooseFS؛ ارجع إلى دليل mfsbdev.cfg(5) للحصول على التفاصيل

أمثلة

mfsbdev start - بدء خادم nbd بالخيارات الافتراضية (masterhost = mfsmaster، masterport = 9421، linksocket = /dev/mfs/nbdsock، المصادقة بدون كلمة مرور)

mfsbdev start -H mfsmaster.my.domain -P 9521 -x /etc/mfs/mastersecret - بدء خادم nbd الذي سيتصل بالرئيس mfsmaster.my.domain على المنفذ 9521 باستخدام كلمة مرور مقروءة من الملف /etc/mfs/mastersecret

mfsbdev stop -l /tmp/mynbdinstance - إيقاف خادم nbd الذي يستخدم مقبس Unix للاتصال /tmp/mynbdinstance

mfsbdev map -f devices/mybdev1.bin -s 2Ti -n mytestvm - إضافة تعيين إلى الخادم الذي يستخدم مقبس الاتصال الافتراضي (/dev/mfs/nbdsock). سيتم تخصيص الجهاز

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

ned تلقائيًا، سيتم تعيين الملف devices/mybdev1.bin لهذا الجهاز، وسيتم إنشاء رابط '/dev/mfs/mytestvm' لهذا الجهاز، وسيكون حجم الجهاز الكتلي 2TiB.

mfsbdev unmap -n mytestvm - إزالة التعيين الذي له الرابط المسمى mytestvm (يستخدم الرابط /dev/mfs/mytestvm).
