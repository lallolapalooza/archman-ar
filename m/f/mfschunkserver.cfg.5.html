خيارات بدء التشغيل

تتطلب التغييرات في هذا القسم إعادة تشغيل العملية.

WORKING_USER
المستخدم لتشغيل الخدمة باسمه
WORKING_GROUP
المجموعة لتشغيل الخدمة باسمها؛ قيمة اختيارية - إذا كانت فارغة، فسيتم استخدام المجموعة الافتراضية للمستخدم
SYSLOG_IDENT
اسم العملية لوضعه في رسائل syslog؛ الافتراضي هو mfschunkserver
LOCK_MEMORY
ما إذا كنت تريد إجراء mlockall() لتجنب تبديل عملية mfschunkserver؛ الافتراضي هو 0، أي لا
LIMIT_GLIBC_MALLOC_ARENAS
الحد من ساحات malloc إلى القيمة المعطاة - يمنع الخادم من استخدام كمية ضخمة من الذاكرة الافتراضية (Linux فقط، الافتراضي هو 4)
DISABLE_OOM_KILLER
تعطيل قاتل نفاد الذاكرة (Linux فقط، الافتراضي هو 1)
NICE_LEVEL
مستوى الأولوية الذي تعمل به الخدمة؛ الافتراضي هو -19؛ ملاحظة: يجب تشغيل العملية كـ root لزيادة الأولوية، إذا فشلت عملية تعيين الأولوية، تحتفظ العملية بمستوى الأولوية الذي بدأت به
FILE_UMASK
تعيين قناع الإعداد الافتراضي للمجموعة والآخرين (للمستخدم دائمًا 0)؛ الافتراضي هو 027 - حظر الكتابة للمجموعة وحظر الكل للآخرين
DATA_PATH
مكان تخزين ملف قفل الخدمة
ALLOW_STARTING_WITH_INVALID_DISKS
عند التعيين إلى واحد، لن تتوقف خدمة الأجزاء عن البدء حتى عند العثور على إدخالات غير صحيحة في ملف 'mfshdd.cfg'؛ الافتراضي هو 0 (لا تبدأ بإدخالات غير صالحة)
CAN_USE_MMAP
يمكن أن يؤدي استخدام mmap للتخصيص إلى تقليل استخدام الذاكرة قليلاً وإعطاء دفعة طفيفة في الأداء، ولكن على بعض البنى / النوى يمكن أن يؤدي إلى مشاكل - خاصة على البنى التي تحتوي على أكثر من وحدة معالجة مركزية مادية؛ الافتراضي هو 0

خيارات وقت التشغيل

تتطلب التغييرات في هذا القسم فقط إعادة تحميل العملية.

HDD_CONF_FILENAME
الموقع / الاسم البديل لملف mfshdd.cfg
HDD_TEST_SPEED
سرعة اختبارات الأجزاء في الخلفية بالميجابايت / ثانية لكل قرص (الإدخال المحدد رسميًا في mfshdd.cfg). يمكن إعطاء القيمة كرقم عشري؛ الافتراضي هو 1.0
HDD_MIN_TEST_INTERVAL
يمنع اختبار سلامة الأجزاء عندما تم إجراء آخر عملية إدخال / إخراج (بما في ذلك الاختبار) قبل أقل من HDD_MIN_TEST_INTERVAL؛ الافتراضي هو يوم واحد؛ لتنسيق القيمة انظر TIME
HDD_FADVISE_MIN_TIME
إذا أمكن، استخدم posix_fadvise(POSIX_DONTNEED) بعد كل اختبار جزء (ولكن فقط إذا تم إجراء آخر عملية إدخال / إخراج قبل أكثر من HDD_FADVISE_MIN_TIME). استخدام صفر سيؤدي دائمًا إلى إجراء posix_fadvise (مسح ذاكرة التخزين المؤقت) واستخدام قيمة سالبة لن يمسح ذاكرة التخزين المؤقت أبدًا بعد الاختبارات. هذا الإعداد صالح فقط للأنظمة التي تدعم posix_fadivise؛ الافتراضي هو يوم واحد؛ لتنسيق القيمة انظر TIME
HDD_LEAVE_SPACE_DEFAULT
مقدار المساحة التي يجب تركها غير مستخدمة على كل قرص صلب؛ تنسيق الرقم: [0-9]*([.][0-9]*)?([kMGTPE]|[KMGTPE]i)?B? ؛ الافتراضي هو 256MiB؛ أمثلة: 0.5GB، .5G، 2.56GiB، 1256M إلخ.
HDD_REBALANCE_UTILIZATION
نسبة مئوية من إجمالي وقت العمل التي يُسمح لخدمة الأجزاء بقضائها في إعادة توازن مساحة القرص الصلب؛ الافتراضي هو 20
HDD_HIGH_SPEED_REBALANCE_LIMIT
أقصى عدد من عمليات الكتابة المتزامنة لكل قرص في إعادة توازن القرص عالي السرعة (0 يعني استخدام إعادة التوازن القياسية؛ الافتراضي هو 0)
HDD_ERROR_TOLERANCE_COUNT, HDD_ERROR_TOLERANCE_PERIOD
عدد أخطاء الإدخال / الإخراج (COUNT) التي يمكن تحملها في مقدار معين من الثواني (PERIOD) على قرص صلب واحد؛ إذا تجاوز عدد الأخطاء هذا الإعداد، سيتم تمييز القرص الصلب المخالف على أنه تالف؛ القيم الافتراضية هي 2 و 600
HDD_FSYNC_BEFORE_CLOSE
تمكين / تعطيل fsync قبل إغلاق الجزء؛ الافتراضي هو 0 (إيقاف)
HDD_SPARSIFY_ON_WRITE
تمكين / تعطيل التشتت (تخطي الأصفار البادئة واللاحقة) أثناء كتابة كتلة جديدة؛ الافتراضي هو 1 (تشغيل)
HDD_RR_CHUNK_COUNT
عدد الأجزاء التي يجب إنشاؤها في دليل واحد قبل الانتقال إلى التالي؛ القيم الأعلى أفضل مع معظم خوارزميات ذاكرة التخزين المؤقت لنظام التشغيل، والقيم المنخفضة تؤدي إلى توزيع أجزاء أكثر توازنًا؛ الافتراضي هو 10000 والذي يعمل بشكل أفضل في معظم الحالات
HDD_KEEP_DUPLICATES_HOURS
عدد الساعات التي يجب الاحتفاظ بالأجزاء المكررة بها قبل حذفها (الافتراضي هو أسبوع واحد)؛ تغيير هذه القيمة وإعادة التحميل سيؤدي إلى إعادة تعيين العداد؛ لتنسيق القيمة انظر TIME
WORKERS_MAX, WORKERS_MAX_IDLE
الحد الأقصى لعدد العمال النشطين والحد الأقصى لعدد العمال الخاملين؛ القيم الافتراضية هي 250 و 40
SYSLOG_MIN_LEVEL
الحد الأدنى لمستوى الرسائل التي سيتم الإبلاغ عنها بواسطة خدمة الأجزاء؛ المستويات حسب الأهمية: ERROR، WARNING، NOTICE، INFO، DEBUG (الافتراضي هو INFO)
SYSLOG_ELEVATE_TO
الرسائل المبلغ عنها بمستوى أقل من المحدد بواسطة هذا الخيار سيتم ترقيتها إلى هذا المستوى (على سبيل المثال، إذا تم تعيين SYSLOG_MIN_LEVEL إلى DEBUG وتم تعيين SYSLOG_ELEVATE_TO إلى NOTICE، فسيتم إرسال جميع رسائل INFO و DEBUG إلى syslog كـ NOTICE ؛ الافتراضي هو NOTICE)

خيارات اتصال الماستر

تتطلب التغييرات في هذا القسم فقط إعادة تحميل العملية.

LABELS
سلسلة تسميات معرفة كمجموعة من الأحرف (غير حساسة لحالة الأحرف) مفصولة بفاصلة أو فاصلة منقوطة؛ الافتراضي فارغ - لا توجد تسميات
BIND_HOST
العنوان المحلي للاستخدام لاتصالات الماستر؛ الافتراضي هو *، أي العنوان المحلي الافتراضي
MASTER_HOST
مضيف MooseFS master، IP مسموح بها فقط في التركيبات ذات الماستر الواحد؛ الافتراضي هو mfsmaster
MASTER_PORT
منفذ أوامر MooseFS master؛ الافتراضي هو 9420
MASTER_CONTROL_PORT
(pro فقط) منفذ تحكم MooseFS master؛ الافتراضي هو 9419

مهلة بالثواني لاتصالات الماستر (إذا لم تكن 0)؛ إذا كانت هذه القيمة صفرًا، فتقوم خدمة الأجزاء بتعيينها مبدئيًا إلى 10 وتطلب من الماستر هذه القيمة

NAME

mfschunkserver.cfg

configuration file for MooseFS chunkserver

DESCRIPTION

The mfschunkserver.cfg file contains configuration parameters for the MooseFS chunkserver process (mfschunkserver(8)). This file is looked for in the following order:

  • Configuration file specified by the -c option.
  • The /etc/moosefs/mfschunkserver.cfg file.

The configuration file consists of a list of parameters, each on a separate line. Comments start with a hash character (#) and continue to the end of the line. Parameters are case-sensitive.

If a parameter is not found in the configuration file, a default value is used.

MASTER CONNECTION OPTIONS

These parameters control the connection of the chunkserver to the MooseFS master server.

MASTER_HOST
IP address or hostname of the master server.
MASTER_PORT
Port number of the master server (default is 9421).
MASTER_HEARTBEAT_INTERVAL
heartbeat interval in seconds (default is 10)
MASTER_RECONNECTION_DELAY
delay in seconds before trying to reconnect to master after disconnection (default is 5)
AUTH_CODE
authentication string (used only when master requires authorization)
CHUNKS_PER_REGISTER_PACKET
maximum number of chunks system will try to put in a single register message (default is 1000, limits 100-10000)

CLIENTS CONNECTION OPTIONS

Changes in this section require only process reload.

CSSERV_LISTEN_HOST
IP address to listen on for client (mount) connections (* means any)
CSSERV_LISTEN_PORT
port to listen on for client (mount) connections (default is 9422)

NOTES

TIME

For config variables that define time without requiring a single, specific unit, time can be defined as a number of seconds (integer) or a time period in one of two possible formats:

first format: #.#T where T is one of: s-seconds, m-minutes, h-hours, d-days or w-weeks; fractions of seconds will be rounded to full seconds

second format: #w#d#h#m#s, any number of definitions can be omitted, but the remaining definitions must be in order (so #d#m is still a valid definition, but #m#d is not); ranges: s,m: 0 to 59, h: 0 to 23, d: 0 t o 6, w is unlimited and the first definition is also always unlimited (i.e. for #d#h#m d will be unlimited)

Notice! For variable HDD_KEEP_DUPLICATES_HOURS only h,d and w time units are accepted and a value without a time unit is treated as hours; fractions are rounded to full hours.

Examples:

1.5h is the same as 1h30m, is the same as 90m, is the same as 5400s, is the same as 5400

2.5d is the same as 2d12h, is the same as 60h; 1d36h is not a valid time period (h is not the first definition, so it is bound by range 0 to 23)

1.03m is the same as 62s (61.8 seconds will be rounded up to 62)
