Mail__SpamAssassin__Plugin__AskDNS(3pm)

الحزمة: spamassassin

التراخيص: APACHE

NAME

Mail::SpamAssassin::Plugin::AskDNS - Plugin to perform DNS checks

SYNOPSIS

  # Inside a rule:
  body MY_TEST eval
      { my $ip = shift;
        # check if the IP is in a specified IP address range,
        # or if the IP is an A record for the given hostname.
        # If the lookup succeeds, the rule matches.
        return ( ask_dns($ip, '127.0.0.1') ||
                 ask_dns($ip, '192.168.0.0/255.255.0.0') ||
                 ask_dns($ip, 'example.com') );
      }

DESCRIPTION

This plugin allows you to perform DNS lookups as part of SpamAssassin rules. It can check if a given IP address (or hostname) resolves to a specific IP address or a range of IP addresses, or if it is listed in a DNS zone.

The main function exposed is ask_dns.

    ask_dns(NAME, TARGET)

NAME is the name to look up (e.g., an IP address or a hostname). TARGET is the target name to check against (e.g., an IP address, an IP address range, or a hostname).

The function returns true if the lookup succeeds and false otherwise.

NAME
A hostname or an IP address string. If an IP address string is given, it must be in a standard format (IPv4 dotted-decimal or IPv6 colon-decimal notation).
TARGET
The TARGET can take several forms:

IP Address/Network: The TARGET can be an IP address or network specification. This is used to check if the NAME resolves to an IP address within the specified range. The IP address/network can be specified in several ways:

  • A single IP address: e.g. 127.0.0.1. This will check if NAME resolves to exactly this IP address.
  • An IP address range: e.g. 127.0.0.1-127.0.0.10. This checks if NAME resolves to any IP address within this range (inclusive).
  • A network address with a netmask: e.g. 192.168.1.0/255.255.255.0. This checks if NAME resolves to any IP address within this network.
  • A network address with a prefix length: e.g. 192.168.1.0/24. This also checks if NAME resolves to any IP address within this network.
  • A shorthand notation: A single IP address like 16 is equivalent to 0.0.0.16. A hex value like 0x10 is equivalent to 16.

When comparing an IP address r against a target specification n (which might include a netmask m), the match is performed using bitwise AND: (r & m) == (n & m).

A single quad-dotted value is equivalent to a n-n form, i.e. it must match the returned value exactly with all its bits.

Some typical examples of a numeric filtering parameter are: 127.0.1.2, 127.0.1.20-127.0.1.39, 127.0.1.0/255.255.255.0, 0.0.0.16/0.0.0.16, 0x10/0x10, 16, 0x10.

Hostname: The TARGET can be a hostname. In this case, ask_dns checks if the NAME resolves to any of the IP addresses associated with the TARGET hostname. This is typically used for DNSBL lookups.

DNS Status Codes (rcode): The TARGET can be a comma-separated list of DNS status codes (rcode), enclosed in square brackets. Rcodes can be represented either by their numeric decimal values (e.g., 0 for NOERROR, 3 for NXDOMAIN), or their names (e.g., NXDOMAIN, FORMERR, SERVFAIL). See https://www.iana.org/assignments/dns-parameters for the list of names. When testing for a rcode where rcode is nonzero, a RR type parameter is ignored as a filter, as there is typically no answer section in a DNS reply when rcode indicates an error. Example: [NXDOMAIN], or [FormErr,ServFail,4,5].

NOTES

DNS timeout can be set with "rbl_timeout" option. See the "Mail::SpamAssassin::Conf" POD for details on "rbl_timeout".
