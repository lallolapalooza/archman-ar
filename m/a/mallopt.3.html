mallopt(3)

mallopt(3) دليل دوال المكتبة mallopt(3)

الاسم

mallopt — تعيين معلمات تخصيص الذاكرة

المكتبة

مكتبة C القياسية (libc،  -lc)

الملخص

#include <malloc.h>
int mallopt(int param, int value);

الوصف

تقوم الدالة mallopt() بتعديل المعلمات التي تتحكم في سلوك دوال تخصيص الذاكرة (انظر malloc(3)). يحدد الوسيط param المعلمة المراد تعديلها، ويحدد الوسيط value القيمة الجديدة لهذه المعلمة.

يمكن تحديد القيم التالية لـ param:

M_ARENA_MAX
إذا كانت قيمة هذه المعلمة غير صفرية، فإنها تحدد حدًا أقصى لعدد "الساحات" (arenas) التي يمكن إنشاؤها. الساحة هي مجموعة من الذاكرة يمكن استخدامها بواسطة استدعاءات malloc(3) (وما شابهها) لمعالجة طلبات التخصيص. الساحات آمنة للخيوط (thread-safe) وبالتالي قد تحتوي على طلبات ذاكرة متزامنة متعددة. المقايضة هي بين عدد الخيوط وعدد الساحات. كلما زاد عدد الساحات، قل تضارب الخيوط (contention) لكل خيط، ولكن زاد استخدام الذاكرة.
القيمة الافتراضية لهذه المعلمة هي 0، مما يعني أن الحد الأقصى لعدد الساحات يتم تحديده وفقًا لإعداد M_ARENA_TEST.
هذه المعلمة متاحة منذ glibc 2.10 عبر --enable-experimental-malloc، ومنذ glibc 2.15 افتراضيًا. في بعض إصدارات مخصص الذاكرة لم يكن هناك حد لعدد الساحات التي تم إنشاؤها (مثل CentOS 5، RHEL 5).
عند استخدام إصدارات glibc أحدث، قد تظهر التطبيقات في بعض الحالات تضاربًا عاليًا عند الوصول إلى الساحات. في هذه الحالات، قد يكون من المفيد زيادة M_ARENA_MAX لتتناسب مع عدد الخيوط. هذا مشابه في السلوك لاستراتيجيات tcmalloc و jemalloc (مثل مجموعات التخصيص لكل خيط).
M_ARENA_TEST
تحدد هذه المعلمة قيمة، بعدد الساحات التي تم إنشاؤها، والتي عندها سيتم فحص تكوين النظام لتحديد حد أقصى لعدد الساحات التي تم إنشاؤها. (انظر M_ARENA_MAX لتعريف الساحة).
حساب الحد الأقصى للساحة يعتمد على التنفيذ وعادة ما يتم حسابه كمضاعف لعدد وحدات المعالجة المركزية المتاحة. بمجرد حساب الحد الأقصى، تكون النتيجة نهائية وتقيد العدد الإجمالي للساحات.
القيمة الافتراضية للمعلمة M_ARENA_TEST هي 2 على الأنظمة التي يكون فيها sizeof(long) يساوي 4؛ وإلا فإن القيمة الافتراضية هي 8.
هذه المعلمة متاحة منذ glibc 2.10 عبر --enable-experimental-malloc، ومنذ glibc 2.15 افتراضيًا.
لا يتم استخدام قيمة M_ARENA_TEST عندما تكون M_ARENA_MAX قيمة غير صفرية.
M_CHECK_ACTION
يتحكم تعيين هذه المعلمة في كيفية استجابة glibc عند اكتشاف أنواع مختلفة من أخطاء البرمجة (مثل تحرير نفس المؤشر مرتين). تحدد أقل 3 بتات (2، 1، و 0) للقيمة المعينة لهذه المعلمة سلوك glibc، كما يلي:
البت 0
إذا تم تعيين هذا البت، فسيتم طباعة رسالة سطر واحد على stderr توفر تفاصيل حول الخطأ. تبدأ الرسالة بالسلسلة النصية "*** glibc detected ***"، تليها اسم البرنامج، اسم دالة تخصيص الذاكرة التي تم اكتشاف الخطأ فيها، وصف موجز للخطأ، وعنوان الذاكرة الذي تم اكتشاف الخطأ فيه.
البت 1
إذا تم تعيين هذا البت، فبعد طباعة أي رسالة خطأ محددة بواسطة البت 0، يتم إنهاء البرنامج عن طريق استدعاء abort(3). منذ glibc 2.4، إذا تم تعيين البت 0 أيضًا، فبين طباعة رسالة الخطأ والإجهاض، يطبع البرنامج أيضًا تتبعًا للمكدس (stack trace) على غرار backtrace(3)، ويطبع تخطيط الذاكرة للعملية بأسلوب /proc/pid/maps (انظر proc(5)).
البت 2 (منذ glibc 2.4)
هذا البت له تأثير فقط إذا تم تعيين البت 0 أيضًا. إذا تم تعيين هذا البت، فإن الرسالة المكونة من سطر واحد التي تصف الخطأ يتم تبسيطها لتشمل فقط اسم الدالة التي حدث فيها الخطأ ووصف موجز للخطأ.
يتم تجاهل البتات المتبقية في value.
الجمع بين التفاصيل المذكورة أعلاه، القيم العددية التالية ذات معنى لـ M_CHECK_ACTION:
0
تجاهل حالات الخطأ؛ استمر في التنفيذ (بنتائج غير محددة).
1
اطبع رسالة خطأ مفصلة واستمر في التنفيذ.
2
أوقف البرنامج.
3
اطبع رسالة خطأ مفصلة، تتبع المكدس، وتخطيطات الذاكرة، وأوقف البرنامج.
5
اطبع رسالة خطأ بسيطة واستمر في التنفيذ.
7
اطبع رسالة خطأ بسيطة، تتبع المكدس، وتخطيطات الذاكرة، وأوقف البرنامج.
منذ glibc 2.3.4، القيمة الافتراضية للمعلمة M_CHECK_ACTION هي 3. في glibc 2.3.3 وما قبلها، القيمة الافتراضية هي 1.
يمكن أن يكون استخدام قيمة M_CHECK_ACTION غير صفرية مفيدًا لأنه بخلاف ذلك قد يحدث انهيار بعد فترة طويلة، ويصبح سبب المشكلة الحقيقي صعب التتبع.
M_MMAP_MAX
تحدد هذه المعلمة الحد الأقصى لعدد طلبات التخصيص التي يمكن معالجتها بشكل متزامن باستخدام mmap(2). هذه المعلمة موجودة لأن بعض الأنظمة لديها عدد محدود من الجداول الداخلية للاستخدام بواسطة mmap(2)، واستخدام أكثر من عدد قليل منها قد يؤدي إلى تدهور الأداء.
القيمة الافتراضية هي 65,536، وهي قيمة ليس لها أهمية خاصة وتعمل فقط كحماية. تعيين هذه المعلمة إلى 0 يعطل استخدام mmap(2) لمعالجة طلبات التخصيص الكبيرة.
M_MMAP_THRESHOLD
بالنسبة للتخصيصات الأكبر من أو المساوية للحد المحدد (بالبايت) بواسطة M_MMAP_THRESHOLD والتي لا يمكن تلبيتها من قائمة العناصر الحرة، تستخدم دوال تخصيص الذاكرة mmap(2) بدلاً من زيادة نطاق البرنامج باستخدام sbrk(2).
تخصيص الذاكرة باستخدام mmap(2) له ميزة مهمة تتمثل في إمكانية تحرير كتل الذاكرة المخصصة بشكل مستقل إلى النظام. (على النقيض من ذلك، لا يمكن تقليص كومة الذاكرة إلا إذا تم تحرير الذاكرة في نهايتها العليا.) من ناحية أخرى، هناك بعض العيوب لاستخدام mmap(2): لا يتم وضع المساحة المحررة في القائمة الحرة لإعادة استخدامها بواسطة التخصيصات اللاحقة؛ قد يتم إهدار الذاكرة لأن تخصيصات mmap(2) يجب أن تكون محاذاة للصفحات (page-aligned)؛ ويجب على النواة (kernel) القيام بمهمة مكلفة لصفرة الذاكرة المخصصة عبر mmap(2). يؤدي الموازنة بين هذه العوامل إلى تعيين افتراضي قدره 128*1024 للمعلمة M_MMAP_THRESHOLD.
الحد الأدنى لهذه المعلمة هو 0. الحد الأقصى هو DEFAULT_MMAP_THRESHOLD_MAX: 512*1024 على الأنظمة 32 بت أو 4*1024*1024*sizeof(long) على الأنظمة 64 بت.
ملاحظة: في الوقت الحاضر، تستخدم glibc حد mmap ديناميكي افتراضيًا. القيمة الأولية للحد هي 128*1024، ولكن عندما يتم تحرير كتل أكبر من الحد الحالي وأصغر من أو تساوي DEFAULT_MMAP_THRESHOLD_MAX، يتم تعديل الحد للأعلى إلى حجم الكتلة المحررة. عندما يكون حد mmap الديناميكي قيد التشغيل، يتم أيضًا تعديل الحد لتقليص كومة الذاكرة ديناميكيًا إلى b

mallopt— memory allocator options

2025-09-21 GNU manpages 6.16 mallopt(3)

LIBRARY

libc, -lc

SYNOPSIS

#include <malloc.h>
int mallopt(int param, int value);

DESCRIPTION

The mallopt() function manipulates the behavior of the memory allocator.

The param argument specifies the option to be modified, and value specifies the new setting for that option. The available options for param are:

MALLOC_TRIM_THRESHOLD_: If value is non-zero, then malloc will attempt to shrink the heap by calling malloc_trim(3). Shrinking happens when the amount of free memory (since the last call to malloc_trim(3)) exceeds the specified value in bytes. If value is zero, then malloc_trim(3) is never called automatically. A value of 2 megabytes (2 * 1024 * 1024) is the default.

MALLOC_MMAP_THRESHOLD_: If the size of a request is greater than or equal to the specified value in bytes, the request is satisfied by memory obtained from mmap(2). Otherwise, the memory is obtained from the heap (see sbrk(2)). The default value is 128*1024 bytes.

MALLOC_MAX_ORDER_: This is a debugging option. If value is greater than zero, then the allocator will refuse requests for blocks larger than (1 << value) bytes. This can be useful for detecting bugs where a program requests a huge amount of memory by mistake. A value of zero disables this check.

MALLOC_CHECK_ACTION: This is a debugging option that controls the action taken when memory corruption is detected. The possible values for value are:

0
Continue execution (default).
1
Print a warning message to stderr.
2
Call abort(3).
3
Call abort() after printing a warning message.

The initial state of MALLOC_CHECK_ACTION is 0 unless the environment variable MALLOC_CHECK_ is set. If MALLOC_CHECK_ is set, its value is used as the initial value of MALLOC_CHECK_ACTION. If the value is invalid, it is ignored.

RETURN VALUE

On success, mallopt() returns 1. On failure, it returns 0.

ERRORS

Failure can occur if param is an unknown value.

VERSIONS

mallopt() is available since version 2.2 of glibc.

STANDARDS

This function is specific to GNU libc and should not be used in portable code.

HISTORY

The mallopt() function first appeared in glibc 2.2.

BUGS

The MALLOC_MAX_ORDER_ option is poorly documented. Its exact behavior is unclear. It is a debugging option, and its behavior might change in future versions of glibc.

The description of MALLOC_CHECK_ACTION states that invalid values are ignored. However, if MALLOC_CHECK_ is set to an invalid value, the default behavior (no checks) is used, which might not be what the user expects.

EXAMPLES

The following example demonstrates how to use mallopt() to set the MALLOC_CHECK_ACTION parameter to print a warning message when memory corruption is detected.

$ ./a.out 1
main(): returned from first free() call
main(): returned from second free() call

The next run shows how to set the same parameter using the MALLOC_CHECK_ environment variable:


$ MALLOC_CHECK_=1 ./a.out;
main(): returned from first free() call
*** glibc detected *** ./a.out: free(): invalid pointer: 0x092c2008 ***
main(): returned from second free() call

Program source

#include <malloc.h>
#include <stdio.h>
#include <stdlib.h>
int
main(int argc, char *argv[])
{
    char *p;
    if (argc > 1) {
        if (mallopt(M_CHECK_ACTION, atoi(argv[1])) != 1) {
            fprintf(stderr, "mallopt() failed");
            exit(EXIT_FAILURE);
        }
    }
    p = malloc(1000);
    if (p == NULL) {
        fprintf(stderr, "malloc() failed");
        exit(EXIT_FAILURE);
    }
    free(p);
    printf("%s(): returned from first free() call\n", __func__);
    free(p);
    printf("%s(): returned from second free() call\n", __func__);
    exit(EXIT_SUCCESS);
}
