Sentence Spacing

Each sentence should terminate at the end of an input line. By doing this, a formatter will be able to apply the proper amount of spacing after the end of sentence (unescaped) period, exclamation mark, or question mark followed by zero or more non-sentence closing delimiters (‘)’, ‘]’, ‘'’, ‘"’).

The proper spacing is also intelligently preserved if a sentence ends at the boundary of a macro line.

If an input line happens to end with a period, exclamation or question mark that isn't the end of a sentence, append a zero-width space (‘\&’).

Examples:

Do not end sentences mid-line like this.  Instead,
end a sentence like this.
A macro would end like this:
.Xr mandoc 1 .
An abbreviation at the end of an input line needs escaping, e.g.\&
like this.

REQUEST SYNTAX

A request or macro line consists of:

  1. the control character ‘.’ or ‘'’ at the beginning of the line,
  2. optionally an arbitrary amount of whitespace,
  3. the name of the request or the macro, which is one word of arbitrary length, terminated by whitespace,
  4. and zero or more arguments delimited by whitespace.

Thus, the following request lines are all equivalent:

.ig end
.ig    end
.   ig end

MACRO SYNTAX

Macros are provided by the mdoc(7) and man(7) languages and can be defined by the de request. When called, they follow the same syntax as requests, except that macro arguments may optionally be quoted by enclosing them in double quote characters (‘"’). Quoted text, even if it contains whitespace or would cause a macro invocation when unquoted, is always considered literal text. Inside quoted text, pairs of double quote characters (‘""’) resolve to single double quote characters.

To be recognised as the beginning of a quoted argument, the opening quote character must be preceded by a space character. A quoted argument extends to the next double quote character that is not part of a pair, or to the end of the input line, whichever comes earlier. Leaving out the terminating double quote character at the end of the line is discouraged. For clarity, if more arguments follow on the same input line, it is recommended to follow the terminating double quote character by a space character; in case the next character after the terminating double quote character is anything else, it is regarded as the beginning of the next, unquoted argument.

Both in quoted and unquoted arguments, pairs of backslashes (‘\\’) resolve to single backslashes. In unquoted arguments, space characters can alternatively be included by preceding them with a backslash (‘\ ’), but quoting is usually better for clarity.

Examples:

.Fn strlen "const char *s"
Group arguments "const char *s" into one function argument. If unspecified, "const", "char", and "*s" would be considered separate arguments.
.Op "Fl a"
Consider "Fl a" as literal text instead of a flag macro.

Define a user-defined string. The stringname and string arguments are space-separated. If the string begins with a double-quote character, that character will not be part of the string. The string can be interpolated into subsequent text by using \*[stringname] for a stringname of arbitrary length, or \*(NN or \*N if the length of stringname is two or one characters, respectively. الـ شرط هو تعبير منطقي. حاليًا، mandoc(1) يدعم مجموعة جزئية من شروط roff التالية:

  • إذا تمت إضافة '!' قبل الشرط، فسيتم عكسه منطقيًا.
  • إذا كان الحرف الأول من الشرط هو 'n' (وضع nroff) أو 'o' (صفحة فردية)، فسيتم تقييمه على أنه صحيح، ويبدأ الجسم بالحرف التالي.
  • إذا كان الحرف الأول من الشرط هو 'e' (صفحة زوجية)، 't' (وضع troff)، أو 'v' (وضع vroff)، فسيتم تقييمه على أنه خطأ، ويبدأ الجسم بالحرف التالي.
  • إذا كان الحرف الأول من الشرط هو 'c' (الحرف متاح)، فسيتم تقييمه على أنه صحيح إذا كان الحرف التالي حرفًا ASCII أو تسلسل هروب حرف صالحًا، أو خطأ بخلاف ذلك. يبدأ الجسم بالحرف الذي يلي هذا الحرف التالي.
  • إذا كان الحرف الأول من الشرط هو 'd'، فسيتم تقييمه على أنه صحيح إذا كان باقي الشرط هو اسم ماكرو معرف من قبل المستخدم أو سلسلة موجودة؛ وإلا، فسيتم تقييمه على أنه خطأ.
  • إذا كان الحرف الأول من الشرط هو 'r'، فسيتم تقييمه على أنه صحيح إذا كان باقي الشرط هو اسم سجل رقمي موجود؛ وإلا، فسيتم تقييمه على أنه خطأ.
  • إذا بدأ الشرطتعبيرات الأرقام المشروحة أدناه. سيتم تقييمه على أنه صحيح إذا كانت النتيجة موجبة، أو خطأ إذا كانت النتيجة صفرًا أو سالبة.
  • بخلاف ذلك، يُعتبر الحرف الأول من الشرط محددًا ويتم تقييمه على أنه صحيح إذا كانت السلسلة الممتدة من ظهوره الأول إلى ظهوره الثاني تساوي السلسلة الممتدة من ظهوره الثاني إلى ظهوره الثالث.
  • إذا لم يكن بالإمكان تحليل الشرط، فسيتم تقييمه على أنه خطأ.

إذا كان الشرط خاطئًا، فلن تتم معالجة أبنائه، ولكن سيتم تفسيرهم نحويًا للحفاظ على سلامة مستند الإدخال. وبالتالي،

.if t .ig

سيتم تجاهل '.ig'، مما قد يؤدي إلى نتائج مثيرة للاهتمام، ولكن

.if t .if t \{\

سيستمر في تفسير التركيب النحوي إلى نهاية الكتلة للشرط النهائي. ترث الشروط الفرعية، في هذه الحالة، بوضوح قيمة الحقيقة للأصل.

إذا بدأ قسم الجسم بقوس ملتف مهرب '\{'، يستمر النطاق حتى نهاية سطر الإدخال الذي يحتوي على تسلسل الهروب المقابل للقوس الملتف المغلق '\}'. إذا لم يكن الجسم محاطًا بأقواس، يستمر النطاق حتى نهاية السطر. إذا كان الشرط متبوعًا بـ جسم في نفس السطر، سواء بعد قوس أم لا، فإن الطلبات والوحدات النمطية يجب أن تبدأ بحرف تحكم. من الأكثر بديهية عمومًا، في هذه الحالة، كتابة

.if شرط \{\
.طلب
.\}

بدلاً من متابعة الطلب أو الوحدة النمطية كـ

.if شرط \{.طلب

يتم تحليل نطاق الشرط دائمًا، ولكن يتم تنفيذه فقط إذا تم تقييم الشرط على أنه صحيح.

لاحظ أن '\}' يتم تحويله إلى تسلسل هروب بعرض صفر إذا لم يتم تمريره كوحدة نمطية مستقلة '.\}'. على سبيل المثال،

.Fl a \} b

سيؤدي إلى اعتبار '\}' وسيطًا للوحدة النمطية 'Fl'.

NAME

roff - macro package formatting language

DESCRIPTION

roff is a macro package formatting language. It is intended to be used with the troff processor. The roff language provides a way to write documents with macros that can be expanded by troff. This allows for a structured approach to document formatting, where common formatting elements can be defined as macros and reused throughout a document.

The roff language has a rich set of features, including:

  • Macro definitions and expansion
  • Conditional processing
  • String definitions and manipulation
  • Number registers
  • Input/output control
  • Page formatting

roff is a powerful tool for creating complex documents, such as manuals, books, and technical papers. It is particularly well-suited for documents that require consistent formatting and structure.

LANGUAGE SYNTAX

The roff language uses a simple syntax based on commands, macro calls, and text. Commands are typically one or two characters long, followed by arguments. Macro calls are similar to commands but are defined by the user. Text is any content that is not a command or macro call.

Here are some basic syntax elements:

Commands:
Commands are two-character strings starting with a capital letter, followed by an optional argument. For example, .br (break) or .ce 5 (center 5 lines).
Macros:
Macros are user-defined commands. They start with a capital letter, followed by an optional argument. For example, .H1 for a level 1 heading.
Strings:
Strings are named sequences of characters. They are defined using the .ds command and can be expanded using the \\*n escape sequence.
Number Registers:
Number registers are named variables that can store numerical values. They are defined using the .nr command and can be manipulated using various commands and escape sequences.
Escape Sequences:
Escape sequences start with a backslash (\) followed by a character. They are used for special characters, commands, and control sequences. For example, \n[name] retrieves the value of the number register name.

REQUEST SYNTAX

Requests are commands that control the formatting process. They are typically written in the form .xxx [arguments], where .xxx is the request name and [arguments] are optional arguments. Examples include:

.br
Insert a line break.
.sp N
Insert N vertical spaces.
.nf
Start no-fill mode.
.fi
End no-fill mode (start fill mode).
.ce N
Center the next N lines.
.ti N
Temporarily indent the next line by N ems.

MACRO SYNTAX

Macros are user-defined commands that encapsulate formatting logic. They are defined using the .de request and invoked like requests. A macro definition looks like:

.de MacroName Arguments
	... macro body ...
..

Macro arguments are accessed using \1, \2, etc.

Example:

.de H1
.B \\$1
.sp 1
..

This defines a macro H1 that takes one argument (\\$1), makes it bold (.B), and adds a space after it.

REQUEST REFERENCE

This section provides a reference for common roff requests. (Note: A full reference would list all requests with their syntax and behavior.)

  • .ad: Adjust line spacing.
  • .bp N: Break page after N pages.
  • .br: Break line.
  • .ce N: Center text.
  • .ds S string: Define string S.
  • .ex: End processing.
  • .fi: Fill mode.
  • .fp N: First page number.
  • .fs: Start fine spacing.
  • .ft R: Select font R.
  • .i N: Indent.
  • .in N: Set indentation.
  • .it N: If no input, start loop.
  • .lc C: Set locale.
  • .ls N: Set line spacing.
  • .m N: Margin.
  • .na: No adjust.
  • .ne N: Not enough vertical space.
  • .nf: No fill mode.
  • .nh: No hyphenation.
  • .nm [N] [S] [E]: Number margin.
  • .nn N: No number.
  • .nr R N [V]: Number register.
  • .oh S: Define odd-page header.
  • .op: Page offset.
  • .os: Output stacked.
  • .p N: Page length.
  • .pc C: Page character.
  • .pd N: Page depth.
  • .pl N: Page length.
  • .pm N: Page margin.
  • .pr N: Print string.
  • .ps N: Point size.
  • .r N: Resume numbering.
  • .rP N: Relative point size.
  • .rS N: Relative spacing.
  • .rT N: Relative tab.
  • .re S: Resume environment.
  • .rh S: Define right-hand header.
  • .rm S: Remove string S.
  • .rn R1 R2: Rename register.
  • .rr R: Reset register.
  • .rs: Resume spacing.
  • .rt N: Return to tab.
  • .rts N: Return to tab stop.
  • .s N: Set spacing.
  • .sP N: Set point size.
  • .sS N: Set spacing.
  • .sT N: Set tab.
  • .sc: Set current page.
  • .sh N: Set hyphenation threshold.
  • .so F: Read input from file F.
  • .sp N: Space.
  • .tab N: Set tab.
  • .tc C: Set tab character.
  • .th N: Set hyphenation.
  • .ti N: Temporary indent.
  • .tl L: Title.
  • .tr S: Transliterate characters.
  • .ul N: Underline.
  • .un N: Underline.
  • .v [N]: Vertical spacing.
  • .vs N: Vertical spacing.
  • .wh N [S]: Define white space.

ESCAPE SEQUENCE REFERENCE

Escape sequences provide a way to insert special characters or perform actions within the text. They start with a backslash (\).

  • \b: Bold.
  • \c: Continue line.
  • \d: Down one-half em.
  • \fR: Set font to R.
  • \h N: Horizontal motion.
  • \L'string': Draw a line.
  • \n[name]: Get value of number register.
  • \o C: Overstrike character.
  • \r: Return from temporary indent.
  • \s N: Set point size.
  • \S N: Set start of line.
  • \t: Tab.
  • \u: Up one-half em.
  • \v N: Vertical motion.
  • \`: Beginning of input line.
  • \': End of input line.
  • \": Comment.
  • \\: Literal backslash.
  • \1, \2, ... : Macro arguments.

COMPATIBILITY

The roff language has evolved over time. The syntax and features described here are generally compatible with traditional roff implementations, but specific behavior may vary between different versions and processors.

The original roff was written in PDP-11 assembly for Version 1 AT&T UNIX. Joseph F. Ossanna improved roff and renamed it nroff for Version 2 AT&T UNIX. He then ported nroff to C as troff, which Brian W. Kernighan released with Version 7 AT&T UNIX. In 1989, James Clark re-implemented troff in C++, naming it groff.
