MANDOC(1) دليل الأوامر العامة MANDOC(1)

الاسم

mandoc — تنسيق صفحات الدليل

الملخص

mandoc [-ac] [-I os=اسم] [-K ترميز] [-mdoc | -man] [-O خيارات] [-T مخرج] [-W مستوى] [ملف ...]

الوصف

الأداة mandoc تقوم بتنسيق صفحات الدليل للعرض.

افتراضيًا، تقرأ mandoc نص mdoc(7) أو man(7) من المدخل القياسي وتنتج مخرج -T locale.

الخيارات هي كما يلي:

-a
إذا كان المخرج القياسي جهاز طرفي ولم يتم تحديد -c، استخدم less(1) لترقيم المخرج، تمامًا كما تفعل man(1).
-c
نسخ صفحات الدليل المنسقة إلى المخرج القياسي دون استخدام less(1) لترقيمها. هذا هو الافتراضي. يمكن تحديده لتجاوز -a.
-I os=اسم
تجاوز اسم نظام التشغيل الافتراضي اسم لـ mdoc(7) Os ولـ man(7) TH macro.
-K ترميز
تحديد ترميز الإدخال. الوسائط المدعومة لـ ترميز هي us-ascii، iso-8859-1، و utf-8. إذا لم يتم تحديده، فإن الكشف التلقائي يستخدم أول تطابق في القائمة التالية:
  1. إذا كانت البايتات الثلاثة الأولى من ملف الإدخال هي علامة ترتيب بايتات UTF-8 (BOM, 0xefbbbf)، يتم تفسير الإدخال كـ utf-8.
  2. إذا كان السطر الأول أو الثاني من ملف الإدخال يطابق تنسيق سطر وضع emacs
    .\" -*- [...؛] coding: ترميز؛ -*-

    ثم يتم تفسير الإدخال وفقًا لـ ترميز.

  3. إذا كان البايت غير ASCII الأول في الملف يقدم تسلسل UTF-8 صالحًا، يتم تفسير الإدخال كـ utf-8.
  4. بخلاف ذلك، يتم تفسير الإدخال كـ iso-8859-1.
-mdoc | -man
مع -mdoc، يتم تفسير جميع ملفات الإدخال كـ mdoc(7). مع -man، يتم تفسير جميع ملفات الإدخال كـ man(7). افتراضيًا، يتم الكشف تلقائيًا عن لغة الإدخال لكل ملف: إذا كان الماكرو الأول هو Dd أو Dt، يتم استخدام محلل mdoc(7)؛ بخلاف ذلك، يتم استخدام محلل man(7). مع الوسائط الأخرى، يتم تجاهل -m بصمت.
-O خيارات
خيارات مخرج مفصولة بفواصل. انظر أوصاف تنسيقات المخرج الفردية للـ خيارات المدعومة.
-T مخرج
تحديد تنسيق المخرج. القيم المدعومة لوسيط مخرج هي ascii، html، الافتراضي locale، man، markdown، pdf، ps، tree، و utf8.

الوضع الخاص -T lint يقوم فقط بتحليل الإدخال ولا ينتج أي مخرج. يتضمن -W all ويعيد توجيه رسائل المحلل، التي تظهر عادةً على المخرج القياسي للأخطاء، إلى المخرج القياسي.

-W مستوى
تحديد الحد الأدنى لـ مستوى الرسائل التي يتم الإبلاغ عنها في المخرج القياسي للأخطاء والتي تؤثر على حالة الخروج. يمكن أن يكون مستوى base، style، warning، error، أو unsupp. المستوى base يستخلص تلقائيًا نظام التشغيل من محتويات الماكرو Os، من خيار سطر الأوامر -Ios، أو من قيمة إرجاع uname(3). المستويات openbsd و netbsd هي أشكال من base تتجاوز الكشف التلقائي وتطلب التحقق من اصطلاحات النظام الأساسي لنظام تشغيل معين. المستوى all هو اسم بديل لـ base. افتراضيًا، mandoc صامت. انظر حالة الخروج و التشخيصات للحصول على التفاصيل.

الخيار الخاص -W stop يخبر mandoc بالخروج بعد تحليل ملف يتسبب في تحذيرات أو أخطاء على الأقل بالمستوى المطلوب. لن يتم إنتاج أي مخرج منسق من هذا الملف. إذا تم طلب كل من مستوى و stop، فيمكن ربطهما بفاصلة، على سبيل المثال -W error,stop.

ملف
اقرأ من ملف الإدخال المحدد. إذا تم تحديد ملفات متعددة، فسيتم معالجتها بالترتيب المحدد. إذا لم يتم تحديده، فتقرأ mandoc من المدخل القياسي.

الخيارات -fhklw مدعومة أيضًا وهي موثقة في man(1). في وضع -f و -k، تدعم mandoc أيضًا الخيارات -CMmOSs الموصوفة في دليل apropos(1). الخيارات -fkl متبادلة وتتجاوز بعضها البعض.

مخرج ASCII

استخدم -T ascii لفرض مخرج نصي بترميز أحرف ASCII ذي 7 بت الموثق في صفحة دليل ascii(7)، مع تجاهل locale(1) المحدد في البيئة.

يتم تطبيق أنماط الخطوط باستخدام ترميز التراجع الخلفي بحيث يتم تقديم حرف "c" تحته خط كـ '‘_\[bs]c'، حيث '\[bs]' هو حرف المسافة الخلفية رقم 8. يتم تقديم الأحرف الغامقة كـ 'c\[bs]c'. عادةً ما يتم تحويل هذه الترميزات إلى تسلسلات طرفية مناسبة بواسطة برنامج التقليب أو ul(1). لإزالة الترميز، قم بتوجيه المخرج إلى col(1) -b بدلاً من ذلك.

يتم تقديم الأحرف الخاصة الموثقة في mandoc_char(7) بأفضل شكل ممكن في مكافئ ASCII. على وجه الخصوص، يتم تمثيل علامات الاقتباس المفردة المفتوحة والمغلقة كأحرف رقم 0x60 و 0x27 على التوالي، وهو ما يتوافق مع جميع معايير ASCII من عام 1965 إلى أحدث مراجعة (2012) ويتوافق مع الطريقة التقليدية التي

The following -O arguments are accepted:

indent=indent
The left margin for normal text is set to indent blank characters instead of the default of five for mdoc(7) and seven for man(7). Increasing this is not recommended; it may result in degraded formatting, for example overfull lines or ugly line breaks. When output is to a pager on a terminal that is less than 66 columns wide, the default is reduced to three columns.
mdoc
Format man(7) input files in mdoc(7) output style. This prints the operating system name rather than the page title on the right side of the footer line, and it implies -O indent=5. One useful application is for checking that -T man output formats in the same way as the mdoc(7) source it was generated from.
tag[=term]
If the formatted manual page is opened in a pager, go to the definition of the term rather than showing the manual page from the beginning. If no term is specified, reuse the first command line argument that is not a section number. If that argument is in apropos(1) key=val format, only the val is used rather than the argument as a whole. This is useful for commands like ‘man -akO tag Ic=ulimit’ to search for a keyword and jump right to its definition in the matching manual pages.
width=width
The output width is set to width instead of the default of 78. When output is to a pager on a terminal that is less than 79 columns wide, the default is reduced to one less than the terminal width. In any case, lines that are output in literal mode are never wrapped and may exceed the output width.

HTML Output

Output produced by -T html conforms to HTML5 using optional self-closing tags. Default styles use only CSS1. Equations rendered from eqn(7) blocks use MathML.

The file /usr/share/misc/mandoc.css documents style-sheet classes available for customising output. If a style-sheet is not specified with -O style, -T html defaults to simple output (via an embedded style-sheet) readable in any graphical or text-based web browser.

Non-ASCII characters are rendered as hexadecimal Unicode character references.

The following -O arguments are accepted:

fragment
Omit the <!DOCTYPE> declaration and the <html>, <head>, and <body> elements and only emit the subtree below the <body> element. The style argument will be ignored. This is useful when embedding manual content within existing documents.
includes=fmt
The string fmt, for example, ../src/%I.html, is used as a template for linked header files (usually via the In macro). Instances of ‘%I’ are replaced with the include filename. The default is not to present a hyperlink.
man=fmt[;fmt]
The string fmt, for example, ../html%S/%N.%S.html, is used as a template for linked manuals (usually via the Xr macro). Instances of ‘%N’ and ‘%S’ are replaced with the linked manual's name and section, respectively. If no section is included, section 1 is assumed. The default is not to present a hyperlink. If two formats are given and a file %N.%S exists in the current directory, the first format is used; otherwise, the second format is used.
style=style.css
The file style.css is used for an external style-sheet. This must be a valid absolute or relative URI.
tag[=term]
Same syntax and semantics as for ASCII Output. This is implemented by passing a file:// URI ending in a fragment identifier to the pager rather than passing merely a file name. When using this argument, use a pager supporting such URIs, for example 
MANPAGER='lynx -force_html' man -T html -O tag=MANPAGER man
MANPAGER='w3m -T text/html' man -T html -O tag=toc mandoc

Consequently, for HTML output, this argument does not work with more(1) or less(1). For example, ‘MANPAGER=less man -T html -O tag=toc mandoc’ does not work because less(1) does not support file:// URIs.

toc
If an input file contains at least two non-standard sections, print a table of contents near the beginning of the output.

Locale Output

By default, mandoc automatically selects UTF-8 or ASCII output according to the current locale(1). If any of the environment variables LC_ALL, LC_CTYPE, or LANG are set and the first one that is set selects the UTF-8 character encoding, it produces UTF-8 Output; otherwise, it falls back to ASCII Output. This output mode can also be selected explicitly with -T locale.

Man Output

Use -T man to translate mdoc(7) input into man(7) output format. This is useful for distributing manual sources to legacy systems lacking mdoc(7) formatters. Embedded eqn(7) and tbl(7) code is not supported.

If the input format of a file is man(7), the input is copied to the output. The parser is also run, and as usual, the -W level controls which DIAGNOSTICS are displayed before copying the input to the output.

Markdown Output

Use -T markdown to translate mdoc(7) input to the markdown format conforming to John Gruber's 2004 specification. The output also almost conforms to the CommonMark specification.

The character set used for the markdown output is ASCII. Non-ASCII characters are encoded as HTML entities. Since that is not possible in literal font contexts, because these are rendered as code spans and code blocks in the markdown output, non-ASCII characters are transliterated to ASCII approximations in these contexts.

Markdown is a very weak markup language, so all semantic markup is lost, and even part of the presentational markup may be lost. Do not use this as an intermediate step in converting to HTML; instead, use -T html directly.

The man(7), tbl(7), and eqn(7) input languages are not supported by -T markdown output mode.

PDF Output

PDF-1.1 output may be generated by -T pdf. See PostScript Output for -O arguments and defaults.

PostScript Output

PostScript "Adobe-3.0" Level-2 pages may be generated by -T ps. Output pages default to letter sized and are rendered in the Times font family, 11-point. Margins are calculated as 1/9 the page length and width. Line-height is 1.4m.

Special characters are rendered as in ASCII Output.

The following -O arguments are accepted:

paper=name
The paper size name may be one of a3, a4, a5, legal, or letter. You may also manu mandoc - mdoc to man converter

FORMATTING OUTPUT

The mandoc utility accepts the following output formatting options.

ASCII Output

The default output format is plain ASCII text. This is always available. The output is formatted to be readable on terminals. No font styles, colors, or other advanced features are used.

Some characters are not available in ASCII. They are rendered as a question mark (?) and may trigger a warning. The following mapping from Unicode to ASCII is used:

ascii
No mapping is applied. All non-ASCII characters trigger a warning and are rendered as ?.
ascii7
The output is restricted to 7-bit ASCII. Characters outside this range are rendered as ?.
ascii8
The output is restricted to 8-bit ASCII, which means that all characters are printable. However, there are issues regarding portability across different systems.

The -O argument indent may be used to adjust the indentation of the output. The indent argument must be an integer number of characters. The default value is 8.

If the ascii8 encoding is not supported by the terminal, the output might not be rendered correctly. In such cases, consider using UTF-8 output instead.

HTML Output

Use -T html to produce HTML output. This is useful for displaying manuals on the web. The output is compliant with the HTML5 standard.

The -O arguments listed below are accepted for HTML output:

anchor
Generate anchor tags for the given macro names. For example, anchor=h1,h2,h3 will generate anchor tags for all h1, h2, and h3 macros.
fragment
Generate a fragment identifier for each heading. This is equivalent to using the anchor option with all heading macros. For example, fragment is equivalent to anchor=h1,h2,h3,h4,h5,h6.
style=path
Use the specified CSS file for styling the HTML output. The path can be absolute or relative. If not specified, a default stylesheet is used.
indent=n
Indent the HTML output by n spaces. The default is 2. A value of 0 disables indentation.
nopnop
Do not generate paragraph tags for the nop macro. This is useful for creating documents with a different structure.
nolnop
Do not generate list tags for the nol macro. This is useful for creating documents with a different structure.

Locale Output

Use -T locale to produce output based on the user's current locale settings. This means that the output encoding will be determined by the LC_CTYPE environment variable. If the locale is set to UTF-8, the output will be in UTF-8. Otherwise, it will be in ASCII.

See also UTF-8 Output.

PostScript Output

Use -T ps to produce PostScript output. This is useful for printing manuals.

The following -O arguments are accepted:

paper=size
Specify the paper size. Supported sizes include letter, legal, a0 through a10, b0 through b10, c0 through c10, executive, folio, note, quarto, statement, and tabloid. The default is letter.
scale=n
Scale the output by a factor of n. The default is 1.0.
noexpand
Do not expand tabs. By default, tabs are expanded to 8 spaces.
nocols
Do not use multiple columns. By default, mandoc tries to fit the output into the specified paper size using multiple columns if necessary.
width=NN
Set the width of the text to NN millimeters. If unknown, it will be set automatically.
height=NN
Set the height of the text to NN millimeters. If unknown, it will be set automatically.

The -O argument dims can be used to specify dimensions as NNxNN, width by height in millimeters. If an unknown value is encountered, letter is used.

UTF-8 Output

Use -T utf8 to force text output in UTF-8 multi-byte character encoding, ignoring the locale(1) settings in the environment. See ASCII Output regarding font styles and -O arguments.

On operating systems lacking locale or wide character support, and on those where the internal character representation is not UCS-4, mandoc always falls back to ASCII Output.

Syntax tree output

Use -T tree to show a human readable representation of the syntax tree. It is useful for debugging the source code of manual pages. The exact format is subject to change, so don't write parsers for it.

The first paragraph shows meta data found in the mdoc(7) prologue, on the man(7) TH line, or the fallbacks used.

In the tree dump, each output line shows one syntax tree node. Child nodes are indented with respect to their parent node. The columns are:

  1. For macro nodes, the macro name; for text and tbl(7) nodes, the content. There is a special format for eqn(7) nodes.
  2. Node type (text, elem, block, head, body, body-end, tail, tbl, eqn).
  3. Flags:
    • An opening parenthesis if the node is an opening delimiter.
    • An asterisk if the node starts a new input line.
    • The input line number (starting at one).
    • A colon.
    • The input column number (starting at one).
    • A closing parenthesis if the node is a closing delimiter.
    • A full stop if the node ends a sentence.
    • BROKEN if the node is a block broken by another block.
    • NOSRC if the node is not in the input file, but automatically generated from macros.
    • NOPRT if the node is not supposed to generate output for any output format.

The following -O argument is accepted:

noval
Skip validation and show the unvalidated syntax tree. This can help to find out whether a given behaviour is caused by the parser or by the validator. Meta data is not available in this case.

ENVIRONMENT

LC_CTYPE
The character encoding locale(1). When Locale Output is selected, it decides whether to use ASCII or UTF-8 output format. It never affects the interpretation of input files.
MANPAGER
Any non-empty value of the environment variable MANPAGER is used instead of the standard pagination program, less(1); see man(1) for details. Only used if -a or -l is specified.
PAGER
Specifies the pagination program to use when MANPAGER is not defined. If neither PAGER nor MANPAGER is defined, less(1) is used. Only used if -a or -l is specified.

EXIT STATUS

The mandoc utility exits with one of the following values, controlled by the message level associated with the -W option:

0
No base system convention violations, style suggestions, warnings, or errors occurred, or those that did were ignored because they were lower than the requested level.
1
At least one base system convention violation or style suggestion occurred, but no warning or error, and -W base or -W style was specified.
2
At least one warning occurred, but no error, and -W warning or a lower level was requested.
3
At least one parsing error occurred, but no unsupported feature was encountered, and -W error or a lower level was requested.
4
At least one unsupported feature was encountered, and -W unsupp or a lower level was requested.
5
Invalid command line arguments were specified. No input files have been read.
6
An operating system error occurred, for example exhaustion of memory, file descriptors, or process table entries. Such errors may cause mandoc to exit at once, possibly in the middle of parsing or formatting a file.

Note that selecting -T lint output mode implies -W all.

EXAMPLES

To page manuals to the terminal:

$ mandoc -l mandoc.1 man.1 apropos.1 makewhatis.8

To produce HTML manuals with /usr/share/misc/mandoc.css as the style-sheet:

$ mandoc -T html -O style=/usr/share/misc/mandoc.css mdoc.7 > mdoc.7.html

To check over a large set of manuals:

$ mandoc -T lint `find /usr/src -name \*\.[1-9]`

To produce a series of PostScript manuals for A4 paper:

$ mandoc -T ps -O paper=a4 mdoc.7 man.7 > manuals.ps

Convert a modern mdoc(7) manual to the older man(7) format, for use on systems lacking an mdoc(7) parser:

$ mandoc -T man foo.mdoc > foo.man

DIAGNOSTICS

Messages displayed by mandoc follow this format:

mandoc: file:line:column: level: message: macro arguments (os)

The first three fields identify the file name, line number, and column number of the input file where the message was triggered. The line and column numbers start at 1. Both are omitted for messages referring to an input file as a whole. All level and message strings are explained below. The name of the macro triggering the message and its arguments are omitted where meaningless. The os operating system specifier is omitted for messages that are relevant for all operating systems. Fatal messages about invalid command line arguments or operating system errors, for example when memory is exhausted, may also omit the file and level fields.

Message levels have the following meanings:

syserr
An operating system error occurred. There isn't necessarily anything wrong with the input files. Output may all the same be missing or incomplete.
badarg
Invalid command line arguments were specified. No input files have been read and no output is produced.
unsupp
An input file uses unsupported low-level roff(7) features. The output may be incomplete and/or misformatted, so using GNU troff instead of mandoc to process the file may be preferable.
error
Indicates a risk of information loss or severe misformatting, in most cases caused by serious syntax errors.
warning
Indicates a risk that the information shown or its formatting may mismatch the author's intent in minor ways. Additionally, syntax errors are classified at least as warnings, even if they do not usually cause misformatting.
style
An input file uses dubious or discouraged style. This is not a complaint about the syntax, and probably neither formatting nor portability are in danger. While great care is taken to avoid false positives on the higher message levels, the style level tries to reduce the probability that issues go unnoticed, so it may occasionally issue bogus suggestions. Please use your good judgement to decide whether any particular style suggestion really justifies a change to the input file.
base
A convention used in the base system of a specific operating system is not adhered to. These are not markup mistakes, and neither the quality of formatting nor portability are in danger. Messages of the base level are printed with the more intuitive style level, so that they can be used to check compliance with base system conventions.
level
tag.

Messages of the base, style, warning, error, and unsupp levels are hidden unless their level, or a lower level, is requested using a -W option or -T lint output mode.

As indicated below, all base and some style checks are only performed if a specific operating system name occurs in the arguments of the -W command line option, of the Os macro, of the -Ios command line option, or, if neither are present, in the return value of the uname(3) function.

(roff) يمكن إحاطة وسائط الماكرو بأحرف اقتباس مزدوجة بحيث لا يلزم إلغاء الأحرف المسافة وأسماء الماكرو الموجودة في الوسيط المقتبس. يمكن حذف علامة الاقتباس الختامية للوسيط الأخير للماكرو. ومع ذلك، لا يُنصح بحذفها لأنها تجعل الكود أصعب في القراءة.
ماكرو غير مفيد
(mdoc) تم العثور على ماكرو Bt أو Tn أو Ud. قم بحذفه ببساطة: فهو لا يخدم أي غرض مفيد.
فكر في استخدام ماكرو OS
(mdoc) تم العثور على سلسلة نصية في نص عادي أو في ماكرو Bx يمكن تمثيلها باستخدام Ox أو Nx أو Fx أو Dx.
أرقام الأخطاء خارج الترتيب
(mdoc, NetBSD) عناصر Er في قائمة Bl ليست بترتيب أبجدي.
رقم خطأ مكرر
(mdoc, NetBSD) تحتوي قائمة Bl على مدخلين متتاليين It يصفان نفس رقم Er.
دليل مُشار إليه غير موجود
(mdoc) يشير ماكرو Xr إلى صفحة دليل لم يتم العثور عليها. عند التشغيل باستخدام -W base، يقتصر البحث على النظام الأساسي، افتراضيًا على /usr/share/man:/usr/X11R6/man. يمكن تكوين هذا المسار وقت الترجمة باستخدام الماكرو المسبق للمعالج MANPATH_BASE. عند التشغيل باستخدام -W style، يتم البحث على طول مسار البحث الكامل كما هو موضح في صفحة دليل man(1)، مع مراعاة خيارات سطر الأوامر -m و -M، ومتغير البيئة MANPATH، وملف man.conf(5)، والرجوع افتراضيًا إلى /usr/share/man:/usr/X11R6/man:/usr/local/man، والذي يمكن تكوينه أيضًا وقت الترجمة باستخدام الماكرو المسبق للمعالج MANPATH_DEFAULT.
فاصلة نهائية
(mdoc) ينتهي الوسيط الأخير للماكرو Ex أو Fo أو Nd أو Nm أو Os أو Sh أو Ss أو St أو Sx بفاصلة نهائية. هذا عادة ما يكون أسلوبًا سيئًا وغالبًا ما يشير إلى أخطاء مطبعية. على الأرجح، يمكن إزالة الفاصلة.
لا توجد مسافة قبل الفاصلة النهائية
(mdoc) الوسيط الأخير للماكرو الذي يدعم وسائط الفواصل النهائية أطول من بايت واحد وينتهي بفاصلة نهائية. فكر في إدخال مسافة بحيث تصبح الفاصلة وسيطًا منفصلاً، وبالتالي نقلها خارج نطاق الماكرو.
وضع الملء ممكّن بالفعل، تخطي
(man) يحدث طلب fi على الرغم من أن المستند لا يزال في وضع الملء، أو عاد بالفعل إلى وضع الملء. ليس له تأثير.
وضع الملء معطل بالفعل، تخطي
(man) يحدث طلب nf على الرغم من أن المستند قد تم تبديله بالفعل إلى وضع عدم الملء ولم يعد إلى وضع الملء بعد. ليس له تأثير.
سطر نص الإدخال أطول من 80 بايت
فكر في تقسيم سطر نص الإدخال عند إحدى المسافات قبل العمود 80.
نص حرفي "--"، فكر ربما في استخدام \(em
(mdoc) على الرغم من أن جهاز الإخراج ASCII يعرض شرطة "-" كـ "--"، إلا أن هذه ليست طريقة جيدة لكتابتها في ملف الإدخال لأنها تعرض بشكل سيئ على جميع أجهزة الإخراج الأخرى.
اسم دالة بدون علامات
(mdoc) توجد كلمة متبوعة بزوج فارغ من الأقواس على سطر نصي. فكر في استخدام ماكرو Fn أو Xr.
مسافات بيضاء في نهاية سطر الإدخال
(mdoc, man, roff) المسافات البيضاء في نهاية أسطر الإدخال لا تكون ذات دلالة دلالية تقريبًا أبدًا - ولكن في الحالة النادرة حيث قد تكون كذلك، فإنها مربكة للغاية عند مراجعة المستندات وصيانتها.
أسلوب تعليق سيئ
(roff) تبدأ أسطر التعليقات بنقطة، وشرطة مائلة عكسية، وحرف اقتباس مزدوج. يعامل mandoc السطر كسطر تعليق حتى بدون الشرطة المائلة العكسية، ولكن ترك الشرطة المائلة العكسية قد لا يكون محمولاً.

تحذيرات متعلقة ببداية المستند

عنوان دليل مفقود، استخدام UNTITLED
(mdoc) لا يحتوي الماكرو Dt على وسائط، أو لا يوجد ماكرو Dt قبل أول ماكرو غير تمهيدي.
عنوان دليل مفقود، استخدام ""
(man) لا يوجد ماكرو TH، أو لا يحتوي على وسائط.
قسم دليل مفقود، استخدام ""
(mdoc, man) يحتوي ماكرو Dt أو TH على وسيط واحد فقط، والذي عادة ما يكون عنوان الدليل.

تحذيرات متعلقة بالوحدات

قوس في اسم الوظيفة
(mdoc) الوسيط الأول لوحدة Fc أو Fn يحتوي على قوس فتح أو إغلاق؛ هذا خطأ على الأرجح، الأقواس تتم إضافتها تلقائيًا.
اسم مكتبة غير معروف
(mdoc, ليس على OpenBSD) وحدة Lb لديها وسيط اسم غير معروف وسيتم عرضه على أنه "مكتبة “اسم”".
محتوى غير صالح في كتلة Rs
(mdoc) تحتوي كتلة Rs على نص عادي أو وحدات غير %. يتم ترك المحتوى الخاطئ في شجرة بناء الجملة. قد يكون التنسيق ضعيفًا.
وسيط قيمة منطقية غير صالح
(mdoc) وحدة Sm لديها وسيط بخلاف on أو off. يتم نقل الوسيط غير الصالح خارج الوحدة، مما يترك الوحدة فارغة، مما يتسبب في تبديل وضع التباعد.
الوسيط يحتوي على تسلسلي خط هروب مزدوجين للخط
(roff) الوسيط الثاني لطلب char يحتوي على أكثر من تسلسل هروب واحد للخط. قد يظل خط غير صحيح نشطًا بعد استخدام الحرف.
خط غير معروف، تخطي الطلب
(man, tbl) طلب roff(7) ft أو معدل تخطيط f في tbl(7) لديه وسيط خط غير معروف.
عدد فردي من الأحرف في الطلب
(roff) يحتوي طلب tr على عدد فردي من الأحرف. يتم تعيين الحرف الأخير إلى حرف فارغ.

تحذيرات متعلقة بالنص العادي

سطر فارغ في وضع الملء، استخدام .sp
(mdoc) معنى الأسطر الفارغة في الإدخال محدد جيدًا فقط في الوضع غير الملء: في وضع الملء، لا يُفترض أن تكون فواصل الأسطر في أسطر النص المدخل مهمة. ومع ذلك، للتوافق مع groff، يتم تنسيق الأسطر الفارغة في وضع الملء مثل طلبات sp. لطلب فاصل فقرة، استخدم Pp بدلاً من سطر فارغ.
علامة جدولة في نص مملوء
(mdoc, man) معنى أحرف الجدولة محدد جيدًا فقط في الوضع غير الملء: في وضع الملء، لا يُفترض أن تكون المسافات البيضاء مهمة في أسطر النص المدخل. كخيار يعتمد على التنفيذ، يتم تمرير أحرف الجدولة في أسطر النص إلى المنسقات في أي حال. بالنظر إلى أن النص قبل حرف الجدولة سيتم ملؤه، فمن الصعب التنبؤ بموضع نقطة الجدولة التي ستنتقل إليها علامة الجدولة.
جملة جديدة، سطر جديد
(mdoc) تبدأ جملة جديدة في منتصف سطر نص. ابدأها في سطر إدخال جديد لمساعدة المنسقات على إنتاج تباعد صحيح.
تسلسل هروب غير صالح
(roff) يحتوي تسلسل الهروب على محدد وسيط فتح غير صالح، يفتقر إلى محدد الوسيط الإغلاقي، الوسيط ذو شكل غير صالح، أو أنه تسلسل هروب حرف باسم غير صالح. إذا كان الوسيط غير مكتمل، فإن \* و \n يتوسعان إلى سلسلة فارغة، \B إلى الرقم ‘0’، و \w إلى طول الوسيط غير المكتمل. يتم تجاهل جميع تسلسلات الهروب غير الصالحة الأخرى.
هروب غير معرف، طباعة حرفيًا
(roff) في تسلسل الهروب، الحرف الأول مباشرة بعد الشرطة المائلة العكسية غير صالح. يتم طباعة هذا الحرف حرفيًا، وهو ما يعادل تجاهل الشرطة المائلة العكسية.
سلسلة غير معرفة، استخدام ""
(roff) إذا تم استخدام سلسلة دون تعريفها مسبقًا، فسيتم تعيين قيمتها ضمنيًا إلى السلسلة الفارغة. ومع ذلك، فإن تعريف السلاسل صراحة قبل الاستخدام يحافظ على الكود أكثر قابلية للقراءة.

سطر tbl يبدأ بامتداد
(tbl) الخلية الأولى في سطر تخطيط الجدول هي امتداد أفقي (‘s’). يتم تجاهل البيانات المقدمة لهذه الخلية، ولا تتم طباعة أي شيء في الخلية.

(tbl) السطر الأول لمواصفات تخطيط الجدول يطلب امتدادًا رأسيًا (‘^’). يتم تجاهل البيانات المقدمة لهذه الخلية، ولا تتم طباعة أي شيء في الخلية.

(tbl) تحتوي مواصفات تخطيط الجدول على أكثر من شريطين عموديين متتاليين. تتم طباعة شريط مزدوج، ويتم تجاهل جميع الأشرطة الإضافية.

أخطاء متعلقة بالجداول

حرف غير أبجدي في خيارات tbl
(tbl) يحتوي سطر خيارات الجدول على حرف غير حرف أو مسافة أو فاصلة حيث يُتوقع بدء اسم خيار. يتم تجاهل الحرف.

(tbl) يحتوي سطر خيارات الجدول على سلسلة من الأحرف لا تتطابق مع أي اسم خيار معروف. يتم تجاهل الكلمة.

(tbl) خيار جدول يتطلب وسيطًا لا يتبعه قوس فتح، أو أن قوس الفتح يتبعه مباشرة قوس إغلاق. يتم تجاهل الخيار.

(tbl) مواصفات تخطيط الجدول فارغة تمامًا، تحدد صفر أسطر وصفر أعمدة. كحل بديل، يتم استخدام عمود واحد محاذي لليسار.

(tbl) تحتوي مواصفات تخطيط الجدول على حرف لا يمكن تفسيره كحرف تخطيط رئيسي ولا كمعدل تخطيط، أو أن المعدل يسبق المفتاح الأول. يتم تجاهل الحرف غير الصالح.

(tbl) معدل التباعد في تخطيط الجدول كبير بشكل غير معقول. بدلاً من ذلك، يتم استخدام التباعد الافتراضي 3n.
tbl بدون أي خلايا بيانات
(tbl) لا يحتوي الجدول على أي خلايا بيانات. من المحتمل ألا ينتج عنه أي مخرجات.
تجاهل البيانات في خلية tbl ممتدة
(tbl) تم تمييز خلية في الجدول كـ امتداد أفقي (‘s’) أو امتداد رأسي (‘^’) في تخطيط الجدول، ولكنه يحتوي على بيانات. يتم تجاهل البيانات.
تجاهل خلايا بيانات tbl إضافية
(tbl) يحتوي سطر البيانات على خلايا أكثر من سطر التخطيط المقابل. يتم تجاهل البيانات في الخلايا الإضافية.
كتلة بيانات مفتوحة في نهاية tbl
(tbl) يتم فتح كتلة بيانات باستخدام T{، ولكن لا يتم إغلاقها أبدًا باستخدام T} مطابق. يتم وضع أسطر البيانات المتبقية من الجدول كلها في خلية واحدة، وتبقى أي خلايا متبقية فارغة.

وحدة مقدمة مكررة
(mdoc) تحدث إحدى وحدات المقدمة أكثر من مرة. النسخة الأخيرة تلغي جميع النسخ السابقة.

(mdoc) تظهر الوحدة Dt بعد الوحدة الأولى غير التمهيدية. لا تستطيع المنسقات التقليدية التعامل مع هذا لأنها تكتب رأس الصفحة قبل تحليل جسم المستند. على الرغم من أن هذا القيد التقني لا ينطبق على mandoc، إلا أن الدلالات التقليدية محفوظة. يتم تجاهل الوحدة المتأخرة بما في ذلك وسائطها.

(mdoc, man, roff) يحتوي ملف الإدخال على بايت ليس حرفًا قابلاً للطباعة من ascii(7).
mandoc(1) - Arch Linux man pages

NAME

mandoc - format and compile mdoc(7) and man(7) pages

SYNOPSIS

mandoc [-A arch] [-D macro=val] [-I path] [-K locale] [-M path] [-O option] [-T output] [-W category] [-a] [-c] [-f] [-h] [-k] [-l] [-s] [-w] [file ...]

DESCRIPTION

The mandoc utility is a command-line interface to the mandoc front-end for the mdocml documentation system. It compiles the input man or mdoc files into the specified output format. If no -T option is given, it defaults to -Tascii.

The mandoc utility accepts multiple input file arguments, processes them in the specified order, and writes the results to standard output. If no input files are specified, standard input is read.

It implements a subset of the troff(1) interface, focusing on mdoc and man language support. It also validates the input for correctness and warns about common errors.

The following options are available:

-A arch
Specify the target architecture for which the manual page is intended. For example, mandoc -A amd64 -Thtml .
-D macro=val
Define a preprocessor macro named macro to be expanded to val. This is primarily for the mdoc language.
-I path
Add path to the list of directories where mandoc searches for included files and manual pages. This option may appear multiple times. If path is empty, the default search path is used.
-K locale
Use the specified locale to determine character encoding. If this option is not given, the current locale is used.
-M path
Add path to the list of directories where mandoc searches for manual pages. This option may appear multiple times. If path is empty, the default search path is used.
-O option
Specify output options. Recognized options include indent, width, tag, noend, noroff, nounix, and fragment. See mandoc.conf(5) for details.
-T output
Specify the output format. The supported formats are ascii, character, html, irclog, json, latin1, man, markdown, ps, rgb, xhtml, and xml. The default is ascii.
-W category
Control warning messages. category can be all, error, fatal, none, warning, or a specific warning name. See mandoc(1) for details.
-a
Produce output with automatic line breaks.
-c
Check syntax only, do not produce output.
-f
Use fixed-width font for output.
-h
Produce HTML output with syntax highlighting.
-k
Search for manual pages matching a keyword.
-l
Produce output compatible with traditional troff.
-s
Produce output in a style similar to man.
-w
Produce output with syntax highlighting.

ENVIRONMENT

mandoc uses the following environment variables:

HOME
Used to find the user's .mandoc.conf file.
MANDOC_CONF
User-specific configuration file. Defaults to ~/.mandoc.conf.
MANDOC_TMPDIR
Temporary directory for intermediate files. Defaults to /tmp.
MANPATH
A colon-separated list of directories in which to search for manual pages. If unset, a default path is used.

EXIT STATUS

The mandoc utility exits with 0 on success, and with a non-zero value if an error occurred.

EXAMPLES

To convert a manual page to HTML:

mandoc -Thtml myprog.1.mdoc

To check for errors in a manual page without producing output:

mandoc -Werror myprog.1.mdoc

To search for manual pages related to "apropos":

mandoc -k apropos

DIAGNOSTICS

The mandoc utility issues various diagnostic messages for errors and warnings. These messages indicate problems with the input files, command-line arguments, or unsupported features.

Too many arguments

Fo, MT, PD, RS, UR, ft, or sp with more than one argument
(mdoc) The macros Fo, MT, PD, RS, UR, ft, or sp were invoked with more than one argument. The excess arguments are ignored.
An with another argument after -split or -nosplit
(mdoc) The An macro was invoked with an additional argument after -split or -nosplit. This argument is ignored.
RE with more than one argument or with a non-integer argument
(mdoc) The RE macro was invoked with more than one argument or with a non-integer argument. The arguments are ignored.
OP or a request of the de family with more than two arguments
(mdoc) The OP macro or a request of the de family was invoked with more than two arguments. The excess arguments are ignored.
Dt with more than three arguments
(mdoc) The Dt macro was invoked with more than three arguments. The excess arguments are ignored.
TH with more than five arguments
(man) The TH macro was invoked with more than five arguments. The excess arguments are ignored.
Bd, Bk, or Bl with invalid arguments
(mdoc) The macros Bd, Bk, or Bl were invoked with invalid arguments. The excess arguments are ignored.

Unsupported features

input too large
(mdoc, man) Currently, mandoc cannot handle input files larger than its arbitrary size limit of 2^31 bytes (2 Gigabytes). Since useful manuals are always small, this is not a problem in practice. Parsing is aborted as soon as the condition is detected.
unsupported control character
(roff) An ASCII control character supported by other roff(7) implementations but not by mandoc was found in an input file. It is replaced by a question mark.
unsupported escape sequence
(roff) An input file contains an escape sequence supported by GNU troff or Heirloom troff but not by mandoc, and it is likely that this will cause information loss or considerable misformatting.
unsupported roff request
(roff) An input file contains a roff(7) request supported by GNU troff or Heirloom troff but not by mandoc, and it is likely that this will cause information loss or considerable misformatting.
eqn delim option in tbl
(eqn, tbl) The options line of a table defines equation delimiters. Any equation source code contained in the table will be printed unformatted.
unsupported table layout modifier
(tbl) A table layout specification contains an '‘m’' modifier. The modifier is discarded.
ignoring macro in table
(tbl, mdoc, man) A table contains an invocation of an mdoc(7) or man(7) macro or of an undefined macro. The macro is ignored, and its arguments are handled as if they were a text line.
skipping tbl in -Tman mode
(mdoc, tbl) An input file contains the TS macro. This message is only generated in -T man output mode, where tbl(7) input is not supported.
skipping eqn in -Tman mode
(mdoc, eqn) An input file contains the EQ macro. This message is only generated in -T man output mode, where eqn(7) input is not supported.

Bad command line arguments

bad command line argument
The argument following one of the -IKMmOTW command line options is invalid, or a file given as a command line argument cannot be opened.
duplicate command line argument
The -I command line option was specified twice.
option has a superfluous value
An argument to the -O option has a value but does not accept one.
missing option value
An argument to the -O option has no argument but requires one.
bad option value
An argument to the -O indent or width option has an invalid value.
duplicate option value
The same -O option is specified more than once.
no such tag

(man) The -T markdown option was specified but an input file uses the man(7) language. No output is produced for that input file.

HISTORY

The mandoc utility first appeared in OpenBSD 4.8. The option -I appeared in OpenBSD 5.2, and -aCcfhKklMSsw in OpenBSD 5.7.
