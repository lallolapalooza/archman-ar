MARKDOWN(7) معلومات متنوعة يدوية MARKDOWN(7)

الاسم

Markdown — صيغة تنسيق نصوص Markdown

الوصف

الفلسفة

Markdown مقصود بأن يكون سهل القراءة والكتابة قدر الإمكان.

ومع ذلك، فإن سهولة القراءة لها الأولوية فوق كل شيء. يجب أن تكون الوثيقة المنسقة بـ Markdown قابلة للنشر كما هي، كنص عادي، دون أن تبدو وكأنها موسومة بعلامات أو تعليمات تنسيق. في حين تأثرت صيغة Markdown بالعديد من مرشحات النص إلى HTML الموجودة - بما في ذلك Setext، atx، Textile، reStructuredText، Grutatext، و EtText - فإن أكبر مصدر إلهام لصيغة Markdown هو تنسيق البريد الإلكتروني النصي العادي.

ولهذا الغرض، تتكون صيغة Markdown بالكامل من علامات ترقيم، تم اختيار علامات الترقيم هذه بعناية لتبدو كما تعني. على سبيل المثال، العلامات النجمية حول الكلمة تبدو بالفعل *تأكيدًا*. قوائم Markdown تبدو، حسنًا، قوائم. حتى اقتباسات الكتل تبدو كمقاطع نصية مقتبسة، بافتراض أنك استخدمت البريد الإلكتروني من قبل.

HTML المضمن

Markdown مقصود لغرض واحد: استخدامه كصيغة *للكتابة* على الويب.

Markdown ليس بديلاً عن HTML، ولا حتى قريبًا منه. صيغته صغيرة جدًا، تتوافق فقط مع مجموعة فرعية صغيرة جدًا من علامات HTML. الفكرة *ليست* إنشاء صيغة تجعل إدراج علامات HTML أسهل. في رأيي، علامات HTML سهلة الإدراج بالفعل. الفكرة من Markdown هي جعل القراءة والكتابة والتحرير سهلاً. HTML هو صيغة *نشر*؛ Markdown هي صيغة *كتابة*. وبالتالي، فإن صيغة تنسيق Markdown تعالج فقط القضايا التي يمكن نقلها في نص عادي.

لأي تنسيق غير مغطى بصيغة Markdown، استخدم ببساطة HTML نفسه. لا داعي لتصديره مسبقًا أو تحديده للإشارة إلى أنك تنتقل من Markdown إلى HTML؛ استخدم العلامات فقط.

القيود الوحيدة هي أن عناصر HTML على مستوى الكتلة - مثل <div>، <table>، <pre>، <p>، إلخ. - يجب فصلها عن المحتوى المحيط بخطوط فارغة، ويجب ألا يتم تضليل علامات البداية والنهاية للكتلة بعلامات جدولة أو مسافات. Markdown ذكي بما يكفي لعدم إضافة علامات <p> إضافية (غير مرغوب فيها) حول علامات HTML على مستوى الكتلة.

على سبيل المثال، لإضافة جدول HTML إلى مقال Markdown:

هذه فقرة عادية.

<table>
    <tr>
        <td>Foo</td>
    </tr>
</table>

هذه فقرة عادية أخرى.

لاحظ أن صيغة تنسيق Markdown لا تتم معالجتها داخل علامات HTML على مستوى الكتلة. على سبيل المثال، لا يمكنك استخدام *التأكيد* بأسلوب Markdown داخل كتلة HTML.

يمكن استخدام علامات HTML على مستوى الامتداد - مثل <span>، <cite>، أو <del> - في أي مكان في فقرة Markdown، أو عنصر قائمة، أو عنوان. إذا أردت، يمكنك حتى استخدام علامات HTML بدلاً من تنسيق Markdown؛ على سبيل المثال، إذا كنت تفضل استخدام علامات HTML <a> أو <img> بدلاً من صيغة الارتباط أو الصورة الخاصة بـ Markdown، فافعل ذلك.

على عكس علامات HTML على مستوى الكتلة، تتم معالجة صيغة Markdown *داخل* علامات المستوى الامتداد.

هروب تلقائي للأحرف الخاصة

في HTML، هناك حرفان يتطلبان معالجة خاصة: `<` و `&`. تستخدم أقواس الزاوية اليسرى لبدء العلامات؛ وتستخدم علامات الأمبير للإشارة إلى كيانات HTML. إذا كنت تريد استخدامها كأحرف حرفية، يجب عليك الهروب منها ككيانات، مثل `<` و `&`.

علامات الأمبير على وجه الخصوص مزعجة لكتاب الويب. إذا كنت تريد الكتابة عن 'AT&T'، يجب عليك كتابة '`AT&T`'. تحتاج حتى إلى الهروب من علامات الأمبير داخل عناوين URL. وبالتالي، إذا كنت تريد الارتباط بـ:

http://images.google.com/images?num=30&q=larry+bird

تحتاج إلى ترميز عنوان URL كـ:

http://images.google.com/images?num=30&amp;q=larry+bird

في سمة `href` لعلامة الربط الخاصة بك. وغني عن القول، هذا من السهل نسيانه، وربما يكون المصدر الأكثر شيوعًا لأخطاء التحقق من صحة HTML في مواقع الويب المنسقة بشكل جيد.

Markdown يسمح لك باستخدام هذه الأحرف بشكل طبيعي، مع الاهتمام بجميع الهروب اللازم لك. إذا استخدمت علامة أمبير كجزء من كيان HTML، فإنها تظل دون تغيير؛ بخلاف ذلك، سيتم ترجمتها إلى `&amp;`.

لذلك، إذا كنت تريد تضمين رمز حقوق النشر في مقالك، يمكنك كتابة:

&copy;

وسيقوم Markdown بتركه وشأنه. ولكن إذا كتبت:

AT&T

Markdown سيترجمها إلى:

AT&amp;T

بالمثل، لأن Markdown يدعم HTML المضمن، إذا استخدمت أقواس الزاوية كفواصل لعلامات HTML، فسيعاملها Markdown على هذا النحو. ولكن إذا كتبت:

4 < 5

Markdown سيترجمها إلى:

4 &lt; 5

ومع ذلك، داخل نطاقات التعليمات البرمجية وكتل التعليمات البرمجية الخاصة بـ Markdown، يتم دائمًا ترميز أقواس الزاوية وعلامات الأمبير تلقائيًا. هذا يجعل من السهل استخدام Markdown للكتابة عن تعليمات HTML البرمجية. (على عكس HTML الخام، وهي صيغة رهيبة للكتابة عن بناء جملة HTML، لأن كل `<` و `&` في مثال التعليمات البرمجية الخاص بك يحتاج إلى الهروب.)

عناصر الكتل

الفقرات وفواصل الأسطر

الفقرة هي ببساطة سطر واحد أو أكثر من النص المتتالي، مفصول بسطر فارغ واحد أو أكثر. (السطر الفارغ هو أي سطر يبدو كس سطر فارغ - السطر الذي يحتوي على مسافات أو علامات جدولة فقط يعتبر فارغًا). لا ينبغي تضليل الفقرات العادية بمسافات أو علامات جدولة.

تضمن قاعدة "سطر واحد أو أكثر من النص المتتالي" أن Markdown يدعم فقرات Dtext "الملفوفة بشدة". يختلف هذا بشكل كبير عن معظم منسقي النص إلى HTML الآخرين (بما في ذلك خيار "تحويل فواصل الأسطر" في Movable Type) الذين يترجمون كل حرف فاصل سطر في فقرة إلى علامة `
`.

عندما *تريد* إدراج فاصل `
` باستخدام Markdown، قم بإنهاء السطر بمسافتين أو أكثر، ثم اضغط على Enter.

نعم، هذا يتطلب جهدًا إضافيًا لإنشاء `
`، ولكن قاعدة "كل فاصل سطر هو `
`" المبسطة لن تعمل مع Markdown. اقتباسات الكتل بأسلوب البريد الإلكتروني في Markdown وعناصر القوائم متعددة الفقرات تعمل بشكل أفضل - وتبدو أفضل - عند تنسيقها بفواصل صلبة.

العناوين

Markdown يدعم نمطين للعناوين: Setext و atx.

العناوين بأسلوب Setext يتم "تسليط الضوء عليها" باستخدام علامات يساوي (للعناوين من المستوى الأول) وشرطات (للعناوين من المستوى الثاني). على سبيل المثال:

هذا عنوان H1
=============

هذا عنوان H2
-------------

أي عدد من علامات `=` أو `-` السفلية سيعمل.

تستخدم العناوين بأسلوب Atx 1-6 علامات هاش في بداية السطر، تتوافق مع مستويات العناوين 1-6. على سبيل المثال:

# هذا عنوان H1

## هذا عنوان H2

###### هذا عنوان H6
