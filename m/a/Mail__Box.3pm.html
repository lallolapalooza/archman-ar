Mail__Box(3pm)

الحزمة: perl-mail-box

التراخيص: Artistic-1.0-Perl, GPL-1.0-or-later

Mail::Box::New

Create a new folder object.

access => STRING
The access mode for the folder. This can be "r" (read-only), "w" (write-only), "a" (append-only), or "rw" (read-write). The default is "r". Note that not all folder types support all access modes.
charset => STRING
The default character set to use when reading or writing messages. If not specified, the folder will try to determine the character set from the Content-Type header. If that fails, it falls back to Mail::Box::charset().
create => BOOLEAN
Automatically create the folder when it does not exist yet. This will only work when access is granted for writing or appending to the folder.

Be careful: you may create a different folder type than you expect unless you explicitly specify Mail::Box::Manager::open(type).

extract => INTEGER | CODE | METHOD | 'LAZY'| 'ALWAYS'
Defines when to parse (process) the content of the message. When the header of a message is read, you may want to postpone the reading of the body: header information is more often needed than the body data, so why parse it always together? The cost of delaying is not too high, and with some luck you may never need parsing the body.

If you supply an INTEGER to this option, bodies of those messages with a total size less than that number will be extracted from the folder only when necessary. Messages where the size (in the "Content-Length" field) is not included in the header, like often the case for multiparts and nested messages, will not be extracted by default.

If you supply a CODE reference, that subroutine is called every time that the extraction mechanism wants to determine whether to parse the body or not. The subroutine is called with the following arguments:

CODE->(FOLDER, HEAD)

where FOLDER is a reference to the folder we are reading. HEAD refers to the Mail::Message::Head::Complete head of the message at hand. The routine must return a "true" value (extract now) or a "false" value (be lazy, do not parse yet). Think about using the Mail::Message::Head::guessBodySize() and Mail::Message::guessTimestamp() on the header to determine your choice.

The third possibility is to specify the NAME of a method. In that case, for each message is called:

FOLDER->NAME(HEAD)

Where each component has the same meaning as described above.

The fourth way to use this option involves constants: with "LAZY" all messages will be delayed. With "ALWAYS" you enforce unconditional parsing, no delaying will take place. The latter is usuful when you are sure you always need all the messages in the folder.

$folder->new(extract => 'LAZY');  # Very lazy
$folder->new(extract => 10000);   # Less than 10kB
# same, but implemented yourself
$folder->new(extract => &large);
sub large($) {
   my ($f, $head) = @_;
   my $size = $head->guessBodySize;
   defined $size ? $size < 10000 : 1
};
# method call by name, useful for Mail::Box
# extensions. The example selects all messages
# sent by you to be loaded without delay.
# Other messages will be delayed.
$folder->new(extract => 'sent_by_me');
sub Mail::Box::send_by_me($) {
    my ($self, $header) = @_;
    $header->get('from') =~ m/\bmy\@example.com\b/i;
}
field_type => CLASS
The type of the fields to be used in a header. Must extend Mail::Message::Field.
fix_headers => BOOLEAN
Broken MIME headers usually stop the parser: all lines not parsed are added to the body of the message. With this flag set, the erroneous line is added to the previous header field and parsing is continued. See Mail::Box::Parser::Perl::new(fix_header_errors).
folder => FOLDERNAME
Which folder to open (for reading or writing). When used for reading (the "access" option set to "r" or "a") the mailbox should already exist and must be readable. The file or directory of the mailbox need not exist if it is opened for reading and writing ("rw"). Write-permission is checked when opening an existing mailbox.

The folder name can be preceded by a "=", to indicate that it is named relative to the directory specified in new(folderdir). Otherwise, it is taken as relative or absolute path.

folderdir => $directory
Where are folders to be found by default? A folder-name may be preceded by a equals-sign ("=", a "mutt" convension) to explicitly state that the folder is located below the default directory. For example: in case "folderdir => '/tmp'" and "folder => '=abc'", the name of the folder-file is '/tmp/abc'. Each folder type has already some default set.
head_delayed_type => CLASS
The headers which are delayed: which will be read from file when it is needed, but not before.
head_type => CLASS
The type of header which contains all header information. Must extend Mail::Message::Head::Complete.
keep_dups => BOOLEAN
Indicates whether or not duplicate messages within the folder should be retained. A message is considered to be a duplicate if its message-id is the same as a previously parsed message within the same folder. If this option is "false" (the default) such messages are automatically deleted, because it is considered useless to store the same message twice.
lock_file => $file
The name of the $file which is used to lock. This must be specified when locking is to be used.
lock_timeout => $seconds
When the lock file is older than the specified number of $seconds, it is considered a mistake. The original lock is released, and accepted for this folder.
lock_type => CLASS|STRING|ARRAY
The type of the locker object. This may be the full name of a CLASS which extends Mail::Box::Locker, or one of the known locker types "DotLock", "Flock", "FcntlLock", "Mutt", "NFS", "POSIX", or "NONE". If an ARRAY is specified, then a Multi locker is built which uses the specified list.
lock_wait => $seconds
How many $seconds to wait before failing on opening this folder.
locker => OBJECT
An OBJECT which extends Mail::Box::Locker, and will handle folder locking replacing the default lock behavior.
log => LEVEL
manager => $manager
A reference to the object which manages this folder -- typically an Mail::Box::Manager instance.
message_type => CLASS
What kind of message objects are stored in this type of folder. The default is constructed from the folder class followed by "::Message". For instance, the message type for "Mail::Box::POP3" is "Mail::Box::POP3::Message"
multipart_type => CLASS
The default type of objects which are to be created for multipart message bodies.
remove_when_empty => BOOLEAN
Determines whether to remove the folder file or directory automatically when the write would result in a folder without messages nor sub-folders.
save_on_exit => BOOLEAN
Sets the policy for saving the folder when it is closed. A folder can be closed manually (see close()) or in a number of implicit ways, including on the moment the program is terminated.
trace => LEVEL
trusted => BOOLEAN
Flags whether to trust the data in the folder or not. Folders which reside in your "folderdir" will be trusted by default (even when the names if not specified staring with "="). Folders which are outside the folderdir or read from STDIN (Mail::Message::Construct::read()) are not trused by default, and require some extra checking.

If you do not check encodings of received messages, you may print binary data to the screen, which is a security risk.

الرسائل

$obj->current( [$number|$message|$message_id] )
تحتفظ بعض قارئات البريد بالرسالة الحالية، التي تمثل أحدث رسالة تم استخدامها. تُرجع هذه الدالة [بعد تحديد] الرسالة الحالية. يمكنك تحديد $number، لتحديد أن هذا الرقم من الرسائل سيتم اختياره كرسالة حالية، أو $message/$message_id (ما لم يكن الرأس قد تم تحميله بالفعل، وفي هذه الحالة لن يتم التعرف عليه).
$obj->find($message_id)
على غرار messageId()، تبحث هذه الدالة عن رسالة ذات $message_id، وتُرجع كائن الرسالة المقابل. ومع ذلك، فإن "find" ستتسبب في معالجة رسالة غير معالجة في المجلد حتى يتم العثور على معرف الرسالة. سيتم فحص المجلد من الخلف إلى الأمام.
$obj->findFirstLabeled( $label, [BOOLEAN, [$msgs]] )
تبحث عن أول رسالة تحمل هذه $label مع التكوين الصحيح. تحدد "BOOLEAN" ما إذا كنت تبحث عن أي قيمة "true" أو أي قيمة "false" في مصفوفة $msgs. بشكل افتراضي، يتم البحث عن قيمة "true". عندما لا تحتوي الرسالة على العلامة المطلوبة، تعتبر "false".
$obj->message( $index, [$message] )
تحصل على أو تحدد رسالة ذات فهرس معين. يتم احتساب الرسائل المحددة للحذف. تبدأ الفهارس السالبة من نهاية المجلد.
$obj->messageId( $message_id, [$message] )
بوسيط واحد، تُرجع الرسالة الموجودة في المجلد ذات $message_id. إذا تم تمرير كائن رسالة كوسيط ثانٍ (اختياري)، يتم تخزين الرسالة أولاً في المجلد، لتحل محل أي رسالة بنفس $message_id. (لا يلزم أن يتطابق $message_id الخاص بالرسالة $message مع $message_id).

!!تحذير!!: عند معالجة رؤوس الرسائل بشكل متأخر، قد تكون الرسالة موجودة في المجلد ولكن لم تتم معالجتها بعد في الذاكرة. في هذه الحالة، يُنصح باستخدام find() بدلاً من messageId() إذا كنت بحاجة إلى بحث كامل. هذا مهم بشكل خاص للمجلدات المنظمة بدون فهرس خاص، مثل Mail::Box::MH.

قد لا يزال $message_id داخل أقواس، والتي سيتم إزالتها. في هذه الحالة، يتم أيضًا إزالة المسافات (التي تأتي من سطر الرأس المزدوج). سيتم أيضًا إزالة البيانات الأخرى حول الأقواس.

!!مثال!!:

my $msg = $folder->messageId('<complex-message.id>');
$folder->messageId("<complex-message\n.id>", $msg);
my $msg = $folder->messageId('complex-message.id');
my $msg = $folder->messageId('garbage <complex-message.id> trash');
...

بالنسبة لبعض أنواع المجلدات (مثل MH)، قد تتسبب هذه الدالة في قراءة جميع ملفات الرسائل. راجع وثائقها المقابلة.

!!مثال!!:

foreach my $id ($folder->messageIds) {

$obj->messages( <'ALL'|$range|'ACTIVE'|'DELETED'|$label| !$label|$filter> )
تُرجع رسائل متعددة من المجلد. القيمة الافتراضية هي "ALL"، والتي ستُرجع (كما هو متوقع) جميع رسائل المجلد. تشير "ACTIVE" إلى الرسائل غير المحددة للحذف. هذا هو عكس "DELETED"، والتي تُرجع جميع رسائل المجلد التي سيتم حذفها عند إغلاق المجلد.

يمكنك أيضًا تحديد $range: رقمين يحددان فهرس البداية والنهاية في مصفوفة الرسائل. الفهارس السالبة تُعد من نهاية المجلد. عندما يكون الفهرس خارج النطاق، ستكون القائمة المُرجعة أقصر بدون تعليقات.

يعتبر كل شيء آخر غير الاسم الافتراضي بمثابة علامة. سيتم إرجاع الرسائل التي تحمل هذه العلامة. عندما تبدأ العلامة بعلامة تعجب (!)، يتم عكس نتيجة البحث.

لعمليات بحث أكثر تعقيدًا، يمكنك تحديد $filter، وهو ببساطة مرجع لدالة. يتم تمرير الرسالة كوسيط وحيد.

!!مثال!!:

foreach my $message ($folder->messages) {...}
foreach my $message (@$folder) {...}
# نفس الشيء مرتين
my @messages   = $folder->messages;
my @messages   = $folder->messages('ALL');
# الاختيار بناءً على النطاق (البداية، النهاية)
my $subset     = $folder->messages(10,-8);
# نفس الشيء مرتين:
my @not_deleted= grep {not $_->isDeleted}
                    $folder->messages;
my @not_deleted= $folder->messages('ACTIVE');
# السياق العددي لعدد الرسائل
my $nr_of_msgs = $folder->messages;
# الرسالة الثالثة، عن طريق التحميل الزائد
$folder->[2];
# الاختيار بناءً على العلامات
$mgr->moveMessages($spam, $inbox->message('spam'));
$mgr->moveMessages($archive, $inbox->message('seen'));
...
$obj->nrMessages(%options)
تستدعي ببساطة messages() في سياق عددي لإرجاع عدد بدلاً من الرسائل نفسها. يبدو أن بعض الأشخاص يفهمون هذا بشكل أفضل. لاحظ أن nrMessages() تُرجع افتراضيًا عددًا لـ "ALL" رسائل في المجلد، بما في ذلك كل من "ACTIVE" و "DELETED".

يتم تمرير %options إلى (وشرحها في) messages().

...
$obj->scanForMessages($message, $message_ids, $timespan, $window)
تبدأ برسالة $message، وتبحث عن سلسلة من الرسائل المتعلقة بها. على سبيل المثال، الرسائل التي تظهر في حقول رؤوس 'In-Reply-To' و 'Reference' لتلك الرسالة. تُعرف هذه الرسائل بواسطة $message_ids الخاصة بها وتريد العثور عليها في المجلد.

عندما تكون جميع معرفات الرسائل معروفة، يكون البحث بسيطًا: يتم العثور عليها في جدول عادي باستخدام messageId(). لكن Mail::Box بطيء حيث يمكنه، لذلك قد لا تكون العديد من الرسائل قد تمت قراءتها بعد من الملف وهذا هو الوضع المفضل، لأنه يوفر الوقت والذاكرة.

ليس من الذكاء البحث عن الرسائل من الأمام إلى الخلف في المجلد: هناك احتمال أكبر بأن تكون الرسالة ذات الصلة قريبة. لذلك، تبدأ هذه الدالة بفحص المجلد من الرسالة $message المحددة، نحو مقدمة المجلد.

يمكن استخدام $timespan لإنهاء البحث بناءً على الوقت في الرسالة. عند استخدام الثابت "EVER" كـ $timespan، لا يقتصر البحث على ذلك. عند تحديد عدد صحيح، سيتم استخدامه كوقت مطلق في تكات الوقت وفقًا لدالة "time" لنظامك. في حالات أخرى، يتم تمريره إلى timespan2seconds() لتحديد عتبة الوقت بالنسبة لوقت الرسالة.

يتم استخدام $window لتقييد عدد الرسائل التي سيتم فحصها كرقم صحيح أو سلسلة ثابتة "ALL".

تُرجع معرفات الرسائل التي لم يتم العثور عليها أثناء البحث. يتم التحذير من أن معرف الرسالة قد يكون معروفًا بالفعل وبالتالي لم يتم العثور عليه: تحقق أولاً.

!!مثال!!:

my $refs   = $msg->get('References') or return;
my @msgids = $ref =~ m/\<([^>]+\>/g;
my @failed = $folder->scanForMessages($msg, \@msgids, '3 days', 50);
...

مجلدات فرعية

$any->listSubFolders(%options)
يسرد أسماء جميع المجلدات الفرعية لهذا المجلد، دون التكرار بعمق. استخدم هذه الأسماء كوسائط لـ openSubFolder() للوصول إلى هذا المجلد.

بالنسبة لمجلدات MBOX، يتم محاكاة المجلدات الفرعية.

-Option    --Default
 check       <C<false>>
 folder      <from calling object>
 folderdir   <from folder>
 skip_empty  <C<false>>
...
check => BOOLEAN
هل يجب التحقق مما إذا كانت جميع الأسماء المُرجعة من النوع الصحيح؟ قد يحتاج كل مجلد فرعي إلى الفتح للتحقق من ذلك، بتكلفة عقوبة تعتمد على نوع المجلد (في بعض الحالات مكلف للغاية).
folder => FOLDERNAME
المجلد الذي يجب سرد مجلداته الفرعية.
folderdir => DIRECTORY
...
skip_empty =>
...
BOOL
هل يجب تضمين المجلدات الفارغة (المجلدات التي لا تحتوي حاليًا على رسائل)؟ المجلدات الفارغة ليست مفيدة للفتح، ولكن يمكن أن تكون مفيدة للحفظ.

my $folder = $mgr->open('=in/new');

my $sub = Mail::Box::Mbox->nameOfSubfolder('xyz', 'abc');

يعيد الحرف أو الأحرف المستخدمة لفصل الأسطر في ملف المجلد، اختياريًا بعد تعيينها إلى "STRING" أو أحد الثوابت. السطر الأول من المجلد يحدد القيمة الافتراضية.

my $folder = Mail::Box::Mbox->new(folder => 'Inbox'); # نفس الشيء
$obj->readMessages(%options)
يتم استدعاؤه بواسطة read() لقراءة الرسائل من نوع مجلد معين. ينظم read() الأنشطة العامة. الخيارات % هي "trusted"، "head_type"، "field_type"، "message_type"، "body_delayed_type"، و "head_delayed_type" اعتمادًا على نوع المجلد. القيم الافتراضية هي القيم الافتراضية للمنشئ (انظر new()).
$obj->storeMessage($message)
يخزن الرسالة في المجلد دون التحقق كما يفعل addMessage().
$obj->toBeThreaded($messages)
الرسالة المحددة جاهزة للإزالة من سلسلة. يتم تمريرها إلى مدير البريد، الذي يحتفظ بملخص لكائنات اكتشاف السلسلة قيد التداول.
$obj->toBeUnthreaded($messages)
الرسالة المحددة جاهزة للإدراج في سلسلة. يتم تمريرها إلى مدير البريد، الذي يحتفظ بملخص لكائنات اكتشاف السلسلة قيد التداول.
$obj->updateMessages(%options)
يتم استدعاؤه بواسطة update() لقراءة الرسائل التي وصلت إلى المجلد بعد فتحه. في بعض الأحيان، قد تقوم التطبيقات الخارجية بتنزيل رسائل في مجلد دون قفل (أو باستخدام قفل مختلف عما يستخدمه تطبيقك).

على الرغم من أن هذا خطير للغاية، إلا أنه يفشل فقط عند التحديث (إعادة ترتيب أو حذف الرسائل) في نفس الوقت تمامًا الذي تصل فيه رسائل جديدة. هذه الاصطدامات نادرة.

الخيارات هي نفسها كما في readMessages().

$obj->write(%options)
يكتب البيانات إلى القرص. النتيجة هي قيمة "true" (انظر "true") إذا نجحت. تتحول الرسائل المحذوفة إلى رسائل مدمرة: يتم تحرير ذاكرتها.

تنبيه: تأكد من كتابة (أو إغلاق close()) المجلد الوجهة قبل كتابة (أو إغلاق) المجلد المصدر، في حالة انقطاع النظام أو حدوث مشاكل في البرامج.

لكتابة مجلد إلى ملف مختلف، قم أولاً بإنشاء مجلد جديد، ثم انقل جميع الرسائل، ثم اكتب أو أغلق close() المجلد الجديد.

-Option      --Default
 force         false
 save_deleted  false
force => BOOLEAN
تجاوز حماية الكتابة باستخدام new(access) عند فتح المجلد (إذا أمكن، قد يكون لا يزال مقفلاً بواسطة نظام التشغيل).
save_deleted => BOOLEAN
سيقوم أيضًا بتخزين الرسائل التي تم تمييزها للحذف في مجلدها. يتم الاحتفاظ بعلامة الحذف (عند الإمكان)، مما يعني أن إعادة فتح المجلد قد يؤدي فعليًا إلى حذف الرسائل. انظر close(save_deleted).
$obj->writeMessages(%options)
يتم استدعاؤه بواسطة write() لكتابة الرسائل من نوع مجلد معين. ينظم "write" الأنشطة العامة. يتم تمرير جميع خيارات write() إلى writeMessages() كجزء منها. بالإضافة إلى ذلك، تتم إضافة بعض الخيارات الإضافية بواسطة "write" نفسها.
-Option  --Default
 messages  <required>
messages => ARRAY
الرسائل المراد كتابتها، وهي مجموعة فرعية من جميع الرسائل في المجلد الحالي.

التفاصيل

أنواع مختلفة من المجلدات

بشكل عام، هناك ثلاث فئات من المجلدات: تلك التي تجمع الرسائل حسب الملف، وتلك التي تجمع الرسائل في دليل، وتلك التي لا توفر وصولاً مباشرًا إلى بيانات الرسالة. هذه الأنواع من المجلدات تعتمد كل منها على فئة أساسية مختلفة.

  • المجلدات المستندة إلى الملفات Mail::Box::File

    تحتفظ المجلدات المستندة إلى الملفات بمجلد (مجموعة من الرسائل) في ملف واحد. الميزة هي أن مجلدك لديه ملف واحد فقط للوصول إليه، مما يسرع الأمور عندما يجب الوصول إلى جميع الرسائل مرة واحدة.

    أحد العيوب الرئيسية مقارنة بالمجلدات المستندة إلى الدليل هو أنه يجب عليك بناء بعض الوسائل لفصل جميع الرسائل. على سبيل المثال، يضيف MBOX سطر فاصل للرسائل بين الرسائل في الملف، وهذا السطر يمكن أن يسبب الارتباك مع محتويات الرسالة.

    بينما يكون الوصول إلى جميع الرسائل دفعة واحدة أسرع في المجلدات المستندة إلى الملفات، فإن الوصول إلى رسالة واحدة أبطأ (بكثير) لأنه يجب قراءة المجلد بأكمله. ومع ذلك، في المجلدات المستندة إلى الدليل، يجب عليك معرفة الرسالة التي تحتاجها، وهذا قد يكون مشكلة أيضًا.

    تشمل أمثلة المجلدات المستندة إلى الملفات MBOX و DBX و NetScape.

  • المجلدات المستندة إلى الدليل Mail::Box::Dir

    بدلاً من تجميع رسائل متعددة في ملف واحد، يمكنك أيضًا وضع كل رسالة في ملف منفصل وجمع هذه الملفات في دليل لتمثيل مجلد.

    العيوب الرئيسية لهذه المجلدات هي الكم الهائل من الملفات الصغيرة التي تحصل عليها عادةً في نظام الملفات الخاص بك. البحث في مجلدك بأكمله بطيء للغاية، لأنه يجب فتح العديد من الملفات للقيام بذلك.

    أفضل ميزة لهذا التنظيم هي أن كل رسالة يتم الاحتفاظ بها بالضبط كما تم استلامها، ويمكن معالجتها بواسطة نصوص برمجية خارجية أيضًا: لا تحتاج إلى أي وكيل مستخدم بريد (MUA).

    تشمل أمثلة المجلدات المنظمة حسب الدليل MH و Maildir و EMH و XMH.

  • مجلدات الشبكة (الخارجية) Mail::Box::Net

    بينما توفر الأنواع الموضحة سابقًا وصولًا مباشرًا إلى بيانات الرسالة، تحتفظ هذه الأنواع من المجلدات ببيانات الرسالة لك: يجب عليك طلب الرسائل أو أجزاء منها. لا تحتوي هذه المجلدات على اسم ملف أو امتيازات نظام ملفات أو قفل نظام للقلق بشأنه، ولكنها تتطلب عادةً اسم مضيف ومجلد ومعرفات رسائل وتفويض.

    تشمل أمثلة هذه الأنواع من المجلدات POP و IMAP الشهيرة، وتخزين الرسائل الموجه نحو قواعد البيانات.

أنواع المجلدات المتاحة

  • Mail::Box::Dbx (للقراءة فقط)

    يتم إنشاء ملفات Dbx بواسطة Outlook Express. باستخدام الوحدة النمطية الخارجية (اختيارية) Mail::Transport::Dbx، يمكنك قراءة هذه المجلدات، حتى عند تشغيل MailBox على منصة UNIX/Linux.

    لا تدعم المكتبة الكتابة وحذف الرسائل، وبالتالي لا يدعمها MailBox. الوصول للقراءة كافٍ لإجراء تحويلات المجلدات، على سبيل المثال.

  • Mail::Box::IMAP4 (جزئيًا)

    بروتوكول IMAP معقد للغاية. تم تنفيذ بعض الأجزاء لإنشاء عملاء IMAP (غير مثاليين ولكن قابلين للاستخدام). بالإضافة إلى ذلك، هناك أيضًا بعض الأجزاء لخوادم IMAP. الميزة الأكثر أهمية المفقودة هي دعم الاتصالات المشفرة.

  • Mail::Box::Maildir

    تحتوي مجلدات Maildir على دليل لكل مجلد. يحتوي دليل المجلد على أدلة فرعية "tmp" و "new" و "cur"، يحتوي كل منها على رسائل ذات غرض مختلف. يتم إنشاء ملفات برسائل جديدة في "tmp"، ثم يتم نقلها إلى "new" (جاهزة للقبول). لاحقًا، يتم نقلها إلى دليل "cur" (تم القبول). كل رسالة هي ملف واحد باسم يبدأ بطابع زمني. الاسم يحتوي أيضًا على علامات حول حالة الرسالة.

    لا يمكن استخدام مجلدات Maildir على Windows بسبب قيود أسماء الملفات على تلك المنصة.

  • Mail::Box::Mbox

    نوع مجلد يتم فيه تخزين جميع الرسائل ذات الصلة في ملف واحد. هذا نوع مجلد شائع جدًا لنظام UNIX.

  • Mail::Box::MH

    ينشئ هذا المجلد دليلًا لكل مجلد، وتكون الرسالة ملفًا واحدًا داخل هذا الدليل. يتم ترقيم ملفات الرسائل بشكل تسلسلي حسب ترتيب وصولها. ملف خاص ".mh_sequences" يحتفظ بعلامات حول الرسائل.

  • Mail::Box::POP3 (للقراءة/الحذف فقط)

    POP3 هو بروتوكول يمكن استخدامه لاسترداد الرسائل من نظام بعيد. بعد إنشاء الاتصال بخادم POP، يمكن النظر إلى الرسائل وإزالتها كما لو كانت على النظام المحلي.

  • Mail::Box::Netzwert

    نوع مجلد Netzwert محسّن لمعالجة صناديق البريد على مجموعة من الأنظمة مع تخزين NFS مشترك. الكود غير مدرج تحت GPL (حتى الآن)

أنواع المجلدات الأخرى مدرجة في قائمة الرغبات (الطويلة) لتنفيذها. الرجاء المساعدة في تنفيذ المزيد منها.

تنفيذ فئة المجلد

هيكل فئة المجلدات قريب جدًا من هيكل الرسائل. على سبيل المثال، يرتبط Mail::Box::File::Message بمجلد Mail::Box::File. أنواع المجلدات هي:

                   Mail::Box::Netzwert
Mail::Box::Mbox    | Mail::Box::Maildir  Mail::Box::POP3
|  Mail::Box::Dbx  | | Mail::Box::MH     |  Mail::Box::IMAP4
|  |               | | |                 |  |
|  |               | | |                 |  |
Mail::Box::File   Mail::Box::Dir       Mail::Box::Net
      |                  |                   |
      `--------------.   |   .---------------'
                     |   |   |
                     Mail::Box
                         |
                         |
            Mail::Reporter (فئة أساسية عامة)

تُنفذ الغالبية العظمى من ميزات المجلدات في Mail::Box، وبالتالي فهي متاحة لجميع أنواع المجلدات. في بعض الأحيان، يتم محاكاة الميزات التي تظهر في بعض أنواع المجلدات فقط للمجلدات التي تفتقر إليها، مثل دعم المجلدات الفرعية لـ MBOX.

التشخيصات

تحذير: لم يتم كتابة التغييرات في المجلد للقراءة فقط $self.
لقد فتحت المجلد للقراءة فقط - وهو الإعداد الافتراضي الذي تم تعيينه بواسطة new(access) -، وأجريت تعديلات، وتريد الآن إغلاقه. قم بتعيين close(force) إذا كنت تريد تجاوز وضع الوصول، أو أغلق المجلد مع تعيين close(write) إلى "NEVER". تم إلقاؤه بواسطة close()
خطأ: فشل النسخ لرسالة واحدة.
لسبب ما، على سبيل المثال امتلاء القرص، أو الحذف بواسطة عملية خارجية، أو الحماية من القراءة، من المستحيل نسخ إحدى الرسائل. سيستمر النسخ للرسائل الأخرى. تم إلقاؤه بواسطة copyTo()
خطأ: المجلد الوجهة $name غير قابل للكتابة.
المجلد الذي يتم نسخ الرسائل إليه لم يتم فتحه بوصول الكتابة (انظر new(access)). لا علاقة لهذا بإذن الكتابة للمجلد الذي يتحكم فيه نظام التشغيل الخاص بك. تم إلقاؤه بواسطة copyTo()
تحذير: رسائل مختلفة بمعرف $msgid
تم اكتشاف معرف الرسالة أكثر من مرة داخل نفس المجلد، ولكن محتوى الرسالة يبدو مختلفًا. هذا لا ينبغي أن يكون ممكنًا: يجب أن تكون كل رسالة فريدة. تم إلقاؤه بواسطة messageId()
خطأ: المجلد $name مفتوح للقراءة فقط
لا يمكنك الكتابة إلى هذا المجلد إلا إذا كنت قد فتحته للكتابة أو الإلحاق باستخدام new(access)، أو تم تعيين خيار "force" على "true". تم إلقاؤه بواسطة write()
خطأ: المجلد $name لم يتم حذفه: غير قابل للكتابة.
يجب فتح المجلد بوصول الكتابة عبر new(access)، وإلا فسيتم رفض حذفه. لذا، قد يكون لديك حق الوصول للكتابة وفقًا لنظام التشغيل، ولكن هذا لن يعني تلقائيًا أن طريقة "delete" هذه تسمح لك بذلك. العكس صحيح أيضًا. تم إلقاؤه بواسطة delete()
خطأ: تم تحديد فترة زمنية غير صالحة '$timespan'.
النص لا يتبع القواعد الصارمة لصيغة الفترة الزمنية المسموح بها كمعامل. تم إلقاؤه بواسطة timespan2seconds()
تحذير: معرف الرسالة '$msgid' لا يحتوي على نطاق.
وفقًا لمعايير RFC، تحتاج معرفات الرسائل إلى جزء عشوائي فريد، ثم "@"، ثم اسم نطاق. هذا لمنع إنشاء رسالتين لهما

DIAGNOSTICS

Error: Folder $name not found.
The folder that you try to open does not exist on the filesystem. Check the name, maybe you made a typo. You can create the folder with the new() method. Cast by messageId(). The warning emerges when the "@" is missing from the string. Cast by messageId()
Error: No folder name specified.
You did not specify the name of a folder to be opened. Use the new(folder) option or set the "MAIL" environment variable. Cast by new()
Error: Package $package does not implement $method.
Fatal error: the specific package (or one of its superclasses) does not implement this method where it should. This message means that some other related classes do implement this method however the class at hand does not. Probably you should investigate this and probably inform the author of the package. Cast by notImplemented()
Error: Unable to create subfolder $name of $folder.
The copy includes the subfolders, but for some reason it was not possible to copy one of these. Copying will proceed for all other sub-folders. Cast by copyTo()
Error: Writing folder $name failed
For some reason (you probably got more error messages about this problem) it is impossible to write the folder, although you should because there were changes made. Cast by write()

خطأ: المجلد $name غير موجود.
