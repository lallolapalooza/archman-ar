MARIADB-CHECK(1) نظام قاعدة بيانات MariaDB MARIADB-CHECK(1)

اسم

mariadb-check - برنامج صيانة الجداول (mariadb-check هو الآن رابط رمزي لـ mariadb-check)

ملخص

mariadb-check [خيارات] [اسم_قاعدة_البيانات [اسم_الجدول ...]]

وصف

يقوم عميل mariadb-check بصيانة الجداول: يقوم بفحص، إصلاح، تحسين، أو تحليل الجداول.

يتم قفل كل جدول وبالتالي يصبح غير متاح للجلسات الأخرى أثناء معالجته، على الرغم من أن عمليات الفحص تقفل الجدول بقفل للقراءة فقط. قد تستغرق عمليات صيانة الجداول وقتًا طويلاً، خاصة للجداول الكبيرة. إذا استخدمت خيار --databases أو --all-databases لمعالجة جميع الجداول في قاعدة بيانات واحدة أو أكثر، فقد يستغرق استدعاء mariadb-check وقتًا طويلاً. (هذا ينطبق أيضًا على mariadb-upgrade لأن هذا البرنامج يستدعي mariadb-check لفحص جميع الجداول وإصلاحها عند الضرورة.)

mariadb-check مشابه في وظيفته لـ myisamchk، ولكنه يعمل بشكل مختلف. الفرق التشغيلي الرئيسي هو أنه يجب استخدام mariadb-check عندما يكون خادم mariadbd قيد التشغيل، بينما يجب استخدام myisamchk عندما لا يكون كذلك. فائدة استخدام mariadb-check هي أنك لا تحتاج إلى إيقاف الخادم لإجراء صيانة الجداول.

يستخدم mariadb-check عبارات SQL CHECK TABLE، REPAIR TABLE، ANALYZE TABLE، و OPTIMIZE TABLE بطريقة ملائمة للمستخدم. يحدد العبارات التي يجب استخدامها للعملية التي تريد تنفيذها، ثم يرسل العبارات إلى الخادم ليتم تنفيذها.

محرك تخزين MyISAM يدعم جميع عمليات الصيانة الأربعة، لذا يمكن استخدام mariadb-check لتنفيذ أي منها على جداول MyISAM. قد لا تدعم محركات التخزين الأخرى جميع العمليات بالضرورة. في مثل هذه الحالات، يتم عرض رسالة خطأ. على سبيل المثال، إذا كان test.t جدول MEMORY، فإن محاولة فحصه ينتج عنها النتيجة التالية:

shell> mariadb-check test t
test.t
note     : محرك التخزين للجدول لا يدعم الفحص

إذا كان mariadb-check غير قادر على إصلاح جدول، راجع قاعدة معارف MariaDB لاستراتيجيات إصلاح الجداول اليدوية. سيكون هذا هو الحال، على سبيل المثال، بالنسبة لجداول InnoDB، والتي يمكن فحصها باستخدام CHECK TABLE، ولكن لا يمكن إصلاحها باستخدام REPAIR TABLE.

لا يدعم استخدام mariadb-check مع الجداول المقسمة.


تحذير

من الأفضل عمل نسخة احتياطية من الجدول قبل إجراء عملية إصلاح جدول؛ قد تتسبب العملية في فقدان البيانات في ظروف معينة. تشمل الأسباب المحتملة، على سبيل المثال لا الحصر، أخطاء نظام الملفات.

هناك ثلاث طرق عامة لاستدعاء mariadb-check:

shell> mariadb-check [خيارات] اسم_قاعدة_البيانات [اسم_الجدول ...]
shell> mariadb-check [خيارات] --databases اسم_قاعدة_البيانات ...
shell> mariadb-check [خيارات] --all-databases

إذا لم تسمي أي جداول بعد اسم_قاعدة_البيانات أو إذا استخدمت خيار --databases أو --all-databases، فسيتم فحص قواعد البيانات بأكملها.

يمتلك mariadb-check ميزة خاصة مقارنة ببرامج العميل الأخرى. يمكن تغيير السلوك الافتراضي لفحص الجداول (--check) عن طريق إعادة تسمية الثنائي. إذا كنت ترغب في الحصول على أداة تقوم بإصلاح الجداول افتراضيًا، يجب عليك فقط عمل نسخة من mariadb-check باسم mariadb-repair، أو عمل رابط رمزي لـ mariadb-check باسم mariadb-repair. إذا استدعيت mariadb-repair، فإنها تصلح الجداول.

يمكن استخدام الأسماء التالية لتغيير السلوك الافتراضي لـ mariadb-check.

mariadb-repair الخيار الافتراضي هو --repair
mysqlanalyze الخيار الافتراضي هو --analyze
mysqloptimize الخيار الافتراضي هو --optimize

يدعم mariadb-check الخيارات التالية، والتي يمكن تحديدها في سطر الأوامر أو في مجموعات خيارات ملف [mariadb-check] و [client]. الخيارات -c، -r، -a و -o حصرية لبعضها البعض.

•--help, -?

عرض رسالة مساعدة والخروج.

•--all-databases, -A

فحص جميع الجداول في جميع قواعد البيانات. هذا يعادل استخدام خيار --databases وتسمية جميع قواعد البيانات في سطر الأوامر.

•--all-in-1, -1

بدلاً من إصدار عبارة لكل جدول، قم بتنفيذ عبارة واحدة لكل قاعدة بيانات تسمي جميع الجداول من تلك القاعدة لمعالجتها.

•--analyze, -a

تحليل الجداول.

•--auto-repair

إذا كان الجدول المفحوص تالفًا، قم بإصلاحه تلقائيًا. يتم إجراء أي إصلاحات ضرورية بعد فحص جميع الجداول.

•--character-sets-dir=مسار

الدليل الذي تم تثبيت مجموعات الأحرف فيه.

•--check, -c

فحص الجداول بحثًا عن الأخطاء. هذه هي العملية الافتراضية.

•--check-only-changed, -C

فحص الجداول التي تغيرت فقط منذ آخر فحص أو التي لم يتم إغلاقها بشكل صحيح.

•--check-upgrade, -g

استدعاء CHECK TABLE مع خيار FOR UPGRADE لفحص الجداول بحثًا عن عدم التوافق مع الإصدار الحالي للخادم. يقوم هذا الخيار بتمكين خياري --fix-db-names و --fix-table-names تلقائيًا.

•--compress

ضغط جميع المعلومات المرسلة بين العميل والخادم إذا كان كلاهما يدعم الضغط.

•--databases, -B

معالجة جميع الجداول في قواعد البيانات المسماة. عادة، يتعامل mariadb-check مع الاسم الأول المقدم في سطر الأوامر كاسم قاعدة بيانات والأسماء التالية كجداول. مع هذا الخيار، فإنه يتعامل مع جميع وسائط الأسماء كقواعد بيانات.

•--debug[=خيارات_التصحيح], -# [خيارات_التصحيح]

كتابة سجل تصحيح. سلسلة خيارات_التصحيح نموذجية هي 'd:t:o,اسم_الملف'. الافتراضي هو 'd:t:o'.

•--debug-check

طباعة بعض معلومات التصحيح عند خروج البرنامج.

•--debug-info

طباعة معلومات التصحيح وإحصائيات استخدام الذاكرة ووحدة المعالجة المركزية عند خروج البرنامج.

•--default-auth=اسم

المصادقة الافتراضية لمكون العميل المستخدم.

•--default-character-set=اسم_مجموعة_الأحرف

استخدام اسم_مجموعة_الأحرف كمجموعة الأحرف الافتراضية.

•--defaults-extra-file=اسم_الملف

تعيين اسم_الملف كملف لقراءة الخيارات الافتراضية منه بعد قراءة ملفات الخيارات الافتراضية العامة. يجب تقديمه كأول خيار.

•--defaults-file=اسم_الملف

تعيين اسم_الملف كملف لقراءة الخيارات الافتراضية منه، مع تجاوز ملفات الخيارات الافتراضية العامة. يجب تقديمه كأول خيار.

•--extended, -e

إذا كنت تستخدم هذا الخيار لفحص الجداول، فإنه يضمن أنها متسقة بنسبة 100٪ ولكنه يستغرق وقتًا طويلاً.

إذا كنت تستخدم هذا الخيار لإصلاح الجداول، فإنه سيجبر على استخدام طريقة الإصلاح القديمة البطيئة باستخدام keycache، بدلاً من الإصلاح الأسرع بكثير عن طريق الفرز.

•--fast, -F

فحص الجداول التي لم يتم إغلاقها بشكل صحيح فقط.

•--fix-db-names

تحويل أسماء قواعد البيانات إلى التنسيق المستخدم منذ MySQL 5.1. تتأثر أسماء قواعد البيانات التي تحتوي على أحرف خاصة فقط.

•--fix-table-names

تحويل أسماء الجداول (بما في ذلك طرق العرض) إلى التنسيق المستخدم منذ MySQL 5.1. تتأثر أسماء الجداول التي تحتوي على أحرف خاصة فقط.

•--flush,

مسح كل جدول بعد

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

NAME

mariadb-check

check, repair, analyze and optimize MariaDB tables

SYNOPSIS

mariadb-check [options] [database ...] [table ...]

mariadb-check [options] {--all-databases | db_name ...}

mariadb-check [options] --databases db_name ...

mariadb-check [options] --tables db_name.table_name ...

DESCRIPTION

The mariadb-check utility is a client that checks, repairs, analyzes, and optimizes MariaDB tables. It can be used on the command line or as an SQL statement within the MariaDB client.

The utility operates on tables within one or more databases. By default, it operates on all tables in all databases that the connected user has access to. You can specify which databases or tables to operate on using the options described below.

The available operations are:

CHECK
Checks tables for errors.
REPAIR
Repairs corrupted tables.
ANALYZE
Analyzes tables to improve query performance.
OPTIMIZE
Optimizes tables to reclaim unused space and improve performance.

By default, mariadb-check performs a CHECK operation. You can specify other operations using the corresponding options.

OPTIONS

The following options are available:

•--analyze, -a

Analyze the tables.

•--all-databases, -A

Check all tables in all databases. This is the default behavior if no database or table names are specified.

•--auto-repair

Automatically repair corrupt tables. This option is enabled by default.

•--backup

Create a backup of the table before checking or repairing it. This option is only relevant for MyISAM tables.

•--check, -c

Check the tables. This is the default operation.

•--databases, -B

Treat all name arguments as database names. This option overrides the --tables option.

•--extend-check, -e

Perform an extended check that is slower but more thorough than a standard check. This option checks for more types of errors than the default.

•--extended, -e

Perform an extended check that is slower but more thorough than a standard check. This option checks for more types of errors than the default. This option is equivalent to --extend-check.

•--flush

Flush the tables after checking them. This releases any locks held by the checked tables. This is useful if you don't want to have the checked tables take up space in the caches after the check.

•--force, -f

Continue even if an SQL error occurs.

•--host=host_name, -h host_name

Connect to the MariaDB server on the given host.

•--medium-check, -m

Do a check that is faster than an --extended operation. This finds only 99.99% of all errors, which should be good enough in most cases.

•--no-defaults

Do not read default options from any option file. This must be given as the first argument.

•--optimize, -o

Optimize the tables.

•--password[=password], -p[password]

The password to use when connecting to the server. If you use the short option form (-p), you cannot have a space between the option and the password. If you omit the password value following the --password or -p option on the command line, mariadb-check prompts for one.

Specifying a password on the command line should be considered insecure. You can use an option file to avoid giving the password on the command line.

•--persistent, -Z

Used with ANALYZE TABLE to append the option PERSISTENT FOR ALL.

•--pipe, -W

On Windows, connect to the server via a named pipe. This option applies only if the server supports named-pipe connections.

•--plugin-dir=name


Directory for client-side plugins.

•--port=port_num, -P port_num

The TCP/IP port number to use for the connection. Forces --protocol=tcp when specified on the command line without other connection properties.

•--print-defaults

Print the program argument list and exit. This must be given as the first argument.

•--process-tables

Perform the requested operation on tables. Defaults to on; use --skip-process-tables to disable.

•--process-views=val

Perform the requested operation (only CHECK VIEW or REPAIR VIEW). Possible values are NO, YES (correct the checksum, if necessary, add the mariadb-version field), UPGRADE_FROM_MYSQL (same as YES and toggle the algorithm MERGE<->TEMPTABLE.

•--protocol={TCP|SOCKET|PIPE|MEMORY}

The connection protocol to use for connecting to the server. It is useful when the other connection parameters normally would cause a protocol to be used other than the one you want.

•--quick, -q

If you are using this option to check tables, it prevents the check from scanning the rows to check for incorrect links. This is the fastest check method.

If you are using this option to repair tables, it tries to repair only the index tree. This is the fastest repair method.

•--repair, -r

Perform a repair that can fix almost anything except unique keys that are not unique.

•--silent, -s

Silent mode. Print only error messages.

•--skip-database=db_name

Don't process the database (case-sensitive) specified as argument.

•--socket=path, -S path

For connections to localhost, the Unix socket file to use, or, on Windows, the name of the named pipe to use. Forces --protocol=socket when specified on the command line without other connection properties; on Windows, forces --protocol=pipe.

•--ssl

Enable SSL for connection (automatically enabled with other flags). Disable with --skip-ssl.

•--ssl-ca=name

CA file in PEM format (check OpenSSL docs, implies --ssl).

•--ssl-capath=name

CA directory (check OpenSSL docs, implies --ssl).

•--ssl-cert=name

X509 cert in PEM format (check OpenSSL docs, implies --ssl).

•--ssl-cipher=name

SSL cipher to use (check OpenSSL docs, implies --ssl).

•--ssl-key=name

X509 key in PEM format (check OpenSSL docs, implies --ssl).

•--ssl-crl=name

Certificate revocation list (check OpenSSL docs, implies --ssl).

•--ssl-crlpath=name

Certificate revocation list path (check OpenSSL docs, implies --ssl).

•--ssl-verify-server-cert

Verify server's "Common Name" in its cert against hostname used when connecting. This option is disabled by default.

•--tables

Override the --databases or -B option. All name arguments following the option are regarded as table names.

•--use-frm

For repair operations on MyISAM tables, get the table structure from the .frm file so that the table can be repaired even if the .MYI header is corrupted.

•--user=user_name, -u user_name

The MariaDB user name to use when connecting to the server.

•--verbose, -v

Verbose mode. Print information about the various stages of program operation. Using one --verbose option will give you more information about what mariadb-check is doing.

Using two --verbose options will also give you connection information.

Using it 3 times will print out all CHECK, RENAME and ALTER TABLE during the check phase.

•--version, -V

Display version information and exit.

•--write-binlog

This option is enabled by default, so that ANALYZE TABLE, OPTIMIZE TABLE, and REPAIR TABLE statements generated by mariadb-check are written to the binary log. Use --skip-write-binlog to cause NO_WRITE_TO_BINLOG to be added to the statements so that they are not logged. Use the --skip-write-binlog when these statements should not be sent to replication slaves or run when using the binary logs for recovery from backup.
