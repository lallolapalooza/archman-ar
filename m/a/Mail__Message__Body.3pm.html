NAME

Mail::Message::Body - the data of a body in a message

INHERITANCE

Mail::Message::Body has extra code in
  Mail::Message::Body::Construct
  Mail::Message::Body::Encode
Mail::Message::Body
  is a Mail::Reporter
Mail::Message::Body is extended by
  Mail::Message::Body::File
  Mail::Message::Body::Lines
  Mail::Message::Body::Multipart
  Mail::Message::Body::Nested
  Mail::Message::Body::String
Mail::Message::Body is realized by
  Mail::Message::Body::Delayed

SYNOPSIS

my Mail::Message $msg = ...;
my $body  = $msg->body;
my @text  = $body->lines;
my $text  = $body->string;
my $file  = $body->file;  # IO::File
$body->print(\*FILE);
my $content_type = $body->type;
my $transfer_encoding = $body->transferEncoding;
my $encoded = $body->encode(mime_type => 'text/html',
   charset => 'us-ascii', transfer_encoding => 'none');\n";
my $decoded = $body->decoded;

DESCRIPTION

The encoding and decoding functionality of a Mail::Message::Body is implemented in the Mail::Message::Body::Encode package. That package is automatically loaded when encoding and decoding of messages needs to take place. Methods to simply build an process body objects are implemented in Mail::Message::Body::Construct.

The body of a message (a Mail::Message object) is stored in one of the many body types. The functionality of each body type is equivalent, but there are performance differences. Each body type has its own documentation with details about its implementation.

Extends "DESCRIPTION" in Mail::Reporter.

OVERLOADED

overload: "" stringification
Returns the body as string --which will trigger completion-- unless called to produce a string for "Carp". The latter to avoid deep recursions.

» example: stringification of body

print $msg->body;   # implicit by print
my $body = $msg->body;
my $x    = "$body"; # explicit by interpolation
overload: '==' numerical comparison
compares if two references point to the same message. This only produces correct results is both arguments are message references within the same folder.

» example: use of numeric comparison on a body

my $skip = $folder->message(3);
foreach my $msg (@$folder)
{   next if $msg == $skip;
    $msg->send;
}
overload: @{} addressed as array
When a body object is used as being an array reference, the lines of the body are returned. This is the same as using lines().

» example: using a body as array

print $body->lines->[1];  # second line
print $body->[1];         # same
my @lines = $body->lines;
my @lines = @$body;       # same
overload: bool true/false
Always returns a "true" value, which is needed to have overloaded objects to be used as in if($body). Otherwise, "if(defined $body)" would be needed to avoid a runtime error.

based_on => BODY
The information about encodings must be taken from the specified BODY, unless specified differently.
charset => CHARSET|'PERL'|<undef>
Defines the character-set which is used in the data. Only useful in combination with a "mime_type" which refers to "text" in any shape, which does not contain an explicit charset already. This field is case-insensitive.

When a known CHARSET is provided and the mime-type says "text", then the data is expected to be raw octets in that particular encoding (see Encode). When 'PERL' is given, then then the data is in Perl's internal encoding; either cp1252 or utf8. More details in "Character encoding PERL"

checked => BOOLEAN
Whether the added information has been check not to contain illegal octets with respect to the transfer encoding and mime type. If not checked, and then set as body for a message, it will be.
content_id => STRING
In "multipart/related" MIME content, the "content_id" is required to allow access to the related content via a "cid:<...>" descriptor of an inline disposition.

A "Content-ID" is supposed to be globally unique. As such, it is common to append "@computer.domain" to the end of some unique string. As other content in the "multipart/related" container also needs to know what this "Content-ID" is, this should be left to the imagination of the person making the content (for now).

As a MIME header field, the "Content-ID" string is expected to be inside angle brackets

data => ARRAY-OF-LINES | STRING
The content of the body. The only way to set the content of a body is during the creation of the body. So if you want to modify the content of a message, you need to create a new body with the new content and add that to the body. The reason behind this, is that correct encodings and body information must be guaranteed. It avoids your hassle in calculating the number of lines in the body, and checking whether bad characters are enclosed in text.

Specify a reference to an ARRAY of lines, each terminated by a newline. Or one STRING which may contain multiple lines, separated and terminated by a newline.

description => STRING|FIELD
Informal information about the body content. The data relates to the "Content-Description" field. Specify a STRING which will become the field content, or a real FIELD.
disposition => STRING|FIELD
How this message can be decomposed. The data relates to the "Content-Disposition"

field. Specify a STRING which will become the field content, or a real FIELD. It is common to use this to specify that the content is inline or attachment.

eol => STRING
The end-of-line character(s) used in the body. This will be set correctly when the body is created from lines. Default is '\n'.
file => FILENAME
The body content is read from the specified FILE. Useful for large bodies.
filename => FILENAME
The filename of the body content. This is used as the "filename" parameter of the "Content-Disposition" header, if that header is present and the parameter is not yet set.
language => LANGUAGE
The language of the body content. This relates to the "Content-Language" header field.
mime_type => MIMETYPE|FIELD
The MIME type of the body content. This relates to the "Content-Type" header field. Default is "text/plain". You can specify a full MIME type like "text/html; charset=us-ascii" or just the type like "text/plain". The latter will have its parameters managed automatically.
transfer_encoding => ENCODING
The transfer encoding for the body. Default is "none". Known values are "7bit", "8bit", "quoted-printable", "base64", and "none".

In addition to the options above, the standard options for "Constructors" in Mail::Reporter are available.

EXAMPLE

The example in the SYNOPSIS shows the basic usage of the body object.

A more complete example:

use Mail::Message;
use Mail::Address;

my $from = Mail::Address->new('From','peter.is.me@home.dom');
my $to   = Mail::Address->new('To','someone.else@else.dom');

my $msg = Mail::Message->new;
$msg->from($from);
$msg->to($to);
$msg->subject('A message with an HTML part');

my $html = Mail::Message::Body::String->new(
    data => "<html><body><h1>Hello</h1></body></html>",
    mime_type => 'text/html; charset=us-ascii',
);
$msg->attach($html);

my $plain = Mail::Message::Body::String->new(
    data => 'This is the plain text version.',
    mime_type => 'text/plain; charset=us-ascii',
);
$msg->attach($plain);

# print $msg->as_string; # To see the output

NAME

Mail::Message::Body::String - text body with a defined string

SYNOPSIS

  # Construct a plain text message body
  my $body = Mail::Message::Body::String->new(
      data => "This is the message body.\nIt has multiple lines.\n",
  );

  # Construct a text message body with specific charset
  my $body = Mail::Message::Body::String->new(
      data    => $string,
      charset => 'ISO-8859-1',
  );

  # Construct a body for an existing message
  my $message = Mail::Message->new;
  my $body = Mail::Message::Body::String->new(
      message => $message,
      data    => $string,
  );
  $message->body($body);

  # Get the content
  my $string = $body->string;

  # Set disposition and filename
  $body->disposition('inline');
  $body->filename('hello.txt');

DESCRIPTION

A Mail::Message::Body::String object holds a text message body. The content of the body is a single STRING. For parts that are not text, use a specific subclass like Mail::Message::Body::File or Mail::Message::Body::Message.

This class is the base for all string-based body objects. You usually don't create instances of this class directly, but one of its subclasses like Mail::Message::Body::Lines, Mail::Message::Body::Plain, or Mail::Message::Body::HTML.

The constructor accepts the following arguments:

charset => STRING
The character set of the content. Default is "US-ASCII". Note that this is not a Perl internal encoding but the encoding used for the "Content-Type" header.
content_id => STRING|FIELD
The value for the "Content-ID" header. RFC2111.
data => STRING
The string that will be the content of the message body.

This option is only allowed for constructing a Mail::Message::Body::String object directly.

disposition => STRING|FIELD
The value for the "Content-Disposition" field. Specify a STRING which will become the field content, or a real FIELD.

The content of this field is specified in RFC 1806. The body of the field can be "inline", to indicate that the body is intended to be displayed automatically upon display of the message. Use "attachment" to indicate that they are separate from the main body of the mail message, and that their display should not be automatic, but contingent upon some further action of the user.

The "filename" attribute specifies a name to which is suggested to the reader of the message when it is extracted.

[3.017] RFC9078 adds type "reaction". This part content is restricted to a single line of emoji's. For this kind, you need to pass the FIELD here, as well as mime-type "text/plain".

eol => 'CR'|'LF'|'CRLF'|'NATIVE'
Convert the message into having the specified string as line terminator for all lines in the body. "NATIVE" is used to represent the "\n" on the current platform and will be translated in the applicable one.

BE WARNED that folders with a non-native encoding may appear on your platform, for instance in Windows folders handled from a UNIX system. The eol encoding has effect on the size of the body!

file => FILENAME|FILEHANDLE|IOHANDLE
Read the data from the specified file, file handle, or object of type "IO::Handle".
filename => FILENAME
[3.001] Overrule/set filename for content-disposition
language => STRING|ARRAY|LIST|FIELD
[3.017] RFC3282 "Content-Language" field, containing a comma separated list of language codes.
log => LEVEL
message => MESSAGE
The message where this body belongs to.
mime_type => STRING|FIELD|MIME
The type of data which is added. You may specify a content of a header line as STRING, or a FIELD object. You may also specify a MIME::Type object. In any case, it will be kept internally as a real field (a Mail::Message::Field object). This relates to the "Content-Type" header field.

A mime-type specification consists of two parts: a general class ("text", "image", "application", etc) and a specific sub-class. Examples for specific classes with "text" are "plain", "html", and "xml". This field is case-insensitive but case preserving. The default mime-type is "text/plain",

modified => BOOLEAN
Whether the body is flagged modified, directly from its creation.
trace => LEVEL
transfer_encoding => STRING|FIELD
The encoding that the data has. If the data is to be encoded, than you will have to call encode() after the body is created. That will return a new encoded body. This field is case-insensitive and relates to the "Content-Transfer-Encoding" field in the header.

» example:

my $body = Mail::Message::Body::String->new(file => \*IN,
   mime_type => 'text/html; charset="ISO-8859-1"');
my $body = Mail::Message::Body::Lines->new(data => ["first\n", $second],
   charset => 'ISO-10646', transfer_encoding => 'none');
my $body = Mail::Message::Body::Lines->new(data => \@lines,
   transfer_encoding => 'base64');
my $body = Mail::Message::Body::Lines->new(file => 'picture.gif',
   mime_type => 'image/gif', content_id => '<12345@example.com>',
   disposition => 'inline');

على وجه الخصوص، يجب عليك تغيير معرف الرسالة عند تغيير نص الرسالة: لا يجب أن يكون لرسالتين نفس المعرف.

بدون قيمة، يتم إرجاع الحالة الحالية، على الرغم من أنه من الأفضل استخدام isModified().

$obj->moveLocation( [$distance] )
ينقل تسجيل الرسالة إلى موقع جديد عبر $distance. يتم استدعاء هذا عند كتابة الرسالة إلى إصدار جديد من نفس ملف المجلد.
$obj->read( $parser, $head, $bodytype, [$chars, [$lines]] )
يقرأ نص الرسالة باستخدام $parser من ملف. يختلف تنفيذ هذا التابع بين أنواع النصوص. $bodytype هو اسم فئة أو مرجع لروتين يمكن أن ينتج اسم فئة، ويستخدم في النصوص المتعددة لتحديد نوع نص الرسالة لكل جزء.

الوسيط $chars هو العدد المقدر للبايتات في نص الرسالة، أو "undef" إذا لم يكن معروفًا. يمكن اشتقاق هذه المعلومات من الرأس ($Content-Length) أو حجم الملف.

الوسيط الثاني هو العدد المقدر لأسطر نص الرسالة. وهو أقل فائدة من $chars ولكنه قد يكون مفيدًا لتحديد ما إذا كان فاصل الرسائل موثوقًا. يمكن العثور على هذه القيمة في حقل "Lines" من الرأس.

التفاصيل

الوصول إلى الجسم

يمكن أن يحتوي الجسم على رسالة، ولكنه يمكن أن يوجد أيضًا بدون رسالة. في كلتا الحالتين، يتم تخزين البيانات، ويمكن طرح نفس الأسئلة: ما هو نوع البيانات، كم عدد البايت والأسطر، ما هو الترميز المستخدم. يمكن ترميز أي جسم وفك ترميزه، وإرجاع كائن جسم جديد. ومع ذلك، فإن الأجسام التي تشكل جزءًا من رسالة ستكون دائمًا بتنسيق يمكن كتابته في ملف أو إرساله إلى مكان ما: سيتم ترميزها إذا لزم الأمر.

» مثال

my $body    = Mail::Message::Body::String->new(mime_type => 'image/gif');
$body->print(\*OUT);    # هذه هي بيانات الصورة الثنائية...
my $encoded = $message->body($body);
$encoded->print(\*OUT); # بيانات بنص عادي، صورة مرمزة

الآن يشير encoded إلى جسم الرسالة $message، وهو محتوى $body بتنسيق يمكن نقله. عادةً ما يتم استخدام الترميز "base64".

تنفيذ فئة الجسم

يمكن تخزين جسم الرسالة بعدة طرق. باختصار، يمكن تقسيم التنفيذ إلى مجموعتين: مجمعات البيانات والأجسام المعقدة. تتضمن المجموعة الأولى طرقًا متعددة للوصول إلى البيانات، وهي متوافقة: تختلف فقط في الأداء وحجم الذاكرة اعتمادًا على الظروف. يتم إنشاء الأخيرة للتعامل مع أجزاء معقدة متعددة والاستخراج البطيء.

أجسام مجمعات البيانات

  • Mail::Message::Body::String

    يتم تخزين جسم الرسالة بالكامل في متغير وحيد. يمكن تخزين الرسائل الصغيرة بهذه الطريقة دون عقوبات أداء.

  • Mail::Message::Body::Lines

    يتم تخزين كل سطر من جسم الرسالة كمتغير وحيد. هذا مفيد لرؤية مفصلة لجسم الرسالة، والذي يتم تنظيمه عادة في أسطر.

  • Mail::Message::Body::File

    يتم تخزين جسم الرسالة في ملف مؤقت خارجي. هذا النوع من التخزين مفيد بشكل خاص عندما يكون الجسم كبيرًا، أو تكون الحقيبة الإجمالية كبيرة، أو يكون حجم الذاكرة محدودًا.

  • "Mail::Message::Body::InFolder"

    لم يتم تنفيذه بعد. يتم الاحتفاظ بالرسالة في الحقيبة، ويتم استخراجها فقط عند تغيير المحتوى.

  • "Mail::Message::Body::External"

    لم يتم تنفيذه بعد. يتم الاحتفاظ بالرسالة في ملف منفصل، عادةً لأن الجسم كبير. الفرق مع كائن "::External" هو أن هذا التخزين الخارجي يتم الاحتفاظ به بين إغلاق وفتح الحقيبة. يستخدم الكائن "::External" ملفًا فقط عندما تكون الحقيبة مفتوحة.

الأجسام المعقدة

  • Mail::Message::Body::Delayed

    لم يتم قراءة جسم الرسالة بعد، ولكن تم معرفة موقعه بالضبط، لذا يمكن قراءة الرسالة عند الحاجة. هذا جزء من آلية الاستخراج البطيء. بمجرد استخراجه، يمكن تحويل الكائن إلى أي جسم بسيط أو معقد.

  • Mail::Message::Body::Multipart

    يحتوي جسم الرسالة على سلسلة من الرسائل الفرعية (والتي يمكن أن تحتوي على أجسامها المتعددة الأجزاء). كل رسالة فرعية هي نسخة من Mail::Message::Part، وهي امتداد لـ Mail::Message.

  • Mail::Message::Body::Nested

    رسائل متداخلة، مثل "message/rfc822": تحتوي على رسالة في الجسم. بالنسبة لمعظم الأكواد، تعمل ببساطة كأجزاء متعددة.

ترميز الأحرف PERL

يمكن أن يكون كائن الجسم جزءًا من رسالة أو مستقلاً. في حالة كونه جزءًا من رسالة، يجب أن يكون "ترميز النقل" والمحتوى بتنسيق يمكن للبيانات نقله عبر SMTP.

ومع ذلك، إذا كنت تريد معالجة بيانات الجسم في Perl عادي (أو إذا قمت ببناء بيانات الجسم من سلاسل Perl عادية)، فيجب أن تكون على دراية بالتمثيل الداخلي للسلاسل في Perl. يمكن أن يكون هذا cp1252 (امتداد لـ latin1) أو utf8 (ليس UTF-8 حقيقيًا، ولكن شيئًا مشابهًا، انظر صفحة man perlunicode).

قبل استخدام بيانات رسالة واردة، قم بما يلي:

my $body  = $msg->decoded;
my @lines = $body->lines;

الآن، يكون للجسم مجموعة أحرف 'PERL' (عندما يكون نصًا).

عند إنشاء جسم جديد يحتوي على نص (افتراضيًا)، سيتم إنشاؤه باستخدام مجموعة أحرف 'PERL'، ما لم تحدد مجموعة أحرف.

my $body = Mail::Box::Body::Lines->new(data => \@lines);
# الآن mime=text/plain, charset=PERL
my $msg  = Mail::Message->buildFromBody($body);
$msg->body($body);
$msg->attach($body);   # إلخ
# كل هذه ستحول charset=PERL إلى UTF-8، cp1252، أو us-ascii، اعتمادًا على الأحرف الموجودة.

الكشف التلقائي عن مجموعة الأحرف

يمثل كائن الجسم هذا البيانات كجزء من رسالة موجودة، أو كجزء ليصبح جزءًا من رسالة. يمكن أن يكون الجسم في حالتين:

1.
جاهز للمعالجة كنص، باستخدام عمليات السلسلة في Perl
2.
بيانات ثنائية مقروءة أو للكتابة

في الحالة الأولى، لا يحتوي محتوى الجسم على ترميز نقل ('none')، ومجموعة الأحرف هي 'PERL'. في الحالة الثانية، يمكن أن يحتوي الجسم على ترميز نقل وله مجموعة أحرف (مدرجة في IANA) (افتراضيًا 'us-ascii')

باستخدام encode() (ربما عبر decoded())، يمكنك تحويل الجسم من حالة إلى أخرى. في خطوة واحدة، يمكنك تغيير ترميز النقل، أو مجموعة الأحرف، أو ما إذا كان بتنسيق سلسلة Perl أو بتنسيق خام (بالبايت).

[3.013] يتم إنشاء مشكلة خطيرة عندما يكون التحويل مطلوبًا، بينما لا تكون مجموعة الأحرف المدخلة أو المخرجة معروفة بشكل صريح. وفقًا لـ RFCs البريدية، الافتراضي هو 'us-ascii'. ومع ذلك، في العالم الحقيقي يمكن أن تكون أي شيء. لذلك، في مثل هذه المواقف، يتم تشغيل الكشف التلقائي.

1.
عند قراءة جسم (باستخدام Mail::Message::read() والأصدقاء)، قد تكون مجموعة الأحرف غير محددة حتى يتم تطبيق فك ترميز النقل. في ذلك الوقت، يتم تطبيق (الكشف التلقائي القابل للتكوين)؛
2.
عند إنشاء جسم داخل البرنامج بدون مجموعة أحرف محددة، سيتم استخدام 'PERL'؛
3.
عند كتابة جسم، لا يتم تحديد مجموعة الأحرف المطلوبة، ومجموعة الأحرف الحالية هي 'PERL'، لذلك يتم استخدام الكشف التلقائي. قد ينتج عن ذلك 'us-ascii'، 'cp1252'، أو 'utf-8'؛
4.
في الحالات الأخرى، تكون مجموعة الأحرف معروفة، لذا تعتبر 'بسيطة'.

التشخيص

تحذير: مجموعة الأحرف $name غير محددة
يواجه ترميز أو فك ترميز جسم رسالة مجموعة أحرف لا يفهمها وحدة Perl Encode. يتم تمريرها باستخدام encode()
تحذير: يتطلب محتوى النقل $encoding مجموعة أحرف صريحة، الافتراضي هو utf-8
يتم تمريرها باستخدام encode()
تحذير: لا يوجد مفكك ترميز معرف لمحتوى النقل $name.
تم ترميز البيانات (جسم الرسالة) بطريقة غير مفهومة حاليًا، لذلك لا يمكن فك ترميزها (أو إعادة ترميزها). يتم تمريرها باستخدام encode()
تحذير: لا يوجد مرمّز معرف لمحتوى النقل $name.
تم فك ترميز البيانات (جسم الرسالة)، ولكن مجموعة الأحرف المطلوبة غير معروفة. يتم إرجاع البيانات المفكوكة. يتم تمريرها باستخدام encode()
خطأ: الحزمة $package لا تنفذ $method.
Error_FATAL: الحزمة المحددة (أو إحدى فئاتها العليا) لا تنفذ هذه الطريقة حيث يجب أن تفعل ذلك. يعني هذا الرسالة أن بعض الفئات ذات الصلة تنفذ هذه الطريقة، ولكن الفئة المعنية لا تفعل ذلك. يجب عليك على الأرجح التحقيق في هذا وربما إبلاغ مؤلف الحزمة. يتم تمريرها باستخدام notImplemented()
تحذير: تم تجاهل فاصل السطر $eol
يتم تمريرها باستخدام eol()
