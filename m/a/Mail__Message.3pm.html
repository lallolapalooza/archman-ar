$obj->container()
إذا كانت الرسالة جزءًا من رسالة أخرى، ترجع "container" مرجعًا إلى الجسم المحتوي.

» مثال:

my Mail::Message $msg = ...
unless $msg->body->isMultipart or return;
my $part   = $msg->body->part(2);
$part->body->isMultipart or return;
my $nested = $part->body->part(3);
$nested->container;  # ترجع $msg->body
$nested->toplevel;   # ترجع $msg
$msg->container;     # ترجع undef
$msg->toplevel;      # ترجع $msg
$msg->isPart;        # ترجع false
$part->isPart;       # ترجع true
$obj->endsOnNewline()
[3.018] ترجع "true" عندما تحتوي الرسالة المطبوعة على حرف سطر جديد لاحق. في حالات نادرة، قد لا يكون هذا هو الحال. على سبيل المثال، عندما يتم قراءة الجسم من ملف تم إنشاؤه بدون سطر جديد لاحق.
$obj->isDummy()
تُستخدم الرسائل الوهمية لملء الفجوات في القوائم المرتبطة وما شابه ذلك، حيث يكون معرف الرسالة فقط معروفًا، ولكن ليس مكان رؤوس البيانات أو أجسامها.

هذه الطريقة متاحة أيضًا لكائنات Mail::Message::Dummy، حيث ستعيد "true". في أي امتداد لـ "Mail::Message"، ستعيد "false".

$obj->isPart()
تعيد "true" إذا كانت الرسالة جزءًا من رسالة أخرى. هذا هو الحال مع امتدادات Mail::Message::Part لـ "Mail::Message".
$obj->messageId()
استرداد معرف الرسالة. كل رسالة لها معرف رسالة فريد. يستخدم هذا المعرف بشكل أساسي للتعرف على خيوط المناقشة.
$obj->partNumber()
يعيد سلسلة نصية تمثل موقع هذا الجزء. في حال كانت الرسالة العليا رسالة واحدة، يتم إرجاع '"undef"'. عندما تكون رسالة متعددة الأجزاء، يتم إرجاع '1' حتى عدد الأجزاء المتعددة. قد يعيد جزء متداخل متعدد المستويات على سبيل المثال '2.5.1'.

عادةً ما تكون هذه السلسلة النصية قصيرة جدًا. يتبع الترقيم تصميم IMAP4، انظر RFC2060 القسم 6.4.5.

$obj->print( [$fh] )
اطبع الرسالة إلى مقبض الملف، والذي افتراضيًا هو المقبض المحدد، بدون التغليف المطلوب أحيانًا بواسطة مجلد
$message->print(\*STDERR); # إلى مخرج الخطأ
$message->print; # إلى الملف المحدد 
my $out = IO::File->new('out', 'w');
$message->print($out);      # بدون تغليف: لا يوجد مجلد
$message->write($out);      # مع تغليف: يوجد مجلد.
$obj->send( [$mailer], %options )
إرسال الرسالة إلى أي شيء خارج برنامج Perl هذا. تعيد "false" عند فشل الإرسال حتى بعد محاولات إعادة.

الـ $mailer الاختياري هو كائن Mail::Transport::Send. إذا لم يتم تحديد $mailer، فسيتم إنشاء واحد وسيتم الاحتفاظ به كافتراضي للرسائل التالية أيضًا.

الـ %options خاصة بالمرسل، وهي مزيج مما هو مفيد لإنشاء كائن المرسل والإرسال نفسه. لذلك، انظر الخيارات الممكنة لـ Mail::Transport::Send::new() و Mail::Transport::Send::send(). يوفر هذا الكائن أيضًا طريقة trySend() التي تمنح تحكمًا أكثر على مستوى منخفض.

» مثال:

$message->send;

هو اختصار (ولكن أقل مرونة) لـ

my $mailer = Mail::Transport::SMTP->new(@smtpopts);
$mailer->send($message, @sendopts);

انظر examples/send.pl في توزيع Mail::Box.

» مثال:

$message->send(via => 'sendmail')
$obj->size()
يعيد حجمًا تقديريًا للرسالة بأكملها بالبايت. في العديد من الحالات، الوظائف التي تعالج الرسالة بشكل أكبر، على سبيل المثال send() أو print()، ستحتاج إلى إضافة/تغيير أسطر رؤوس أو إضافة أحرف CR، لذا فإن الحجم هو تقدير فقط بهامش خطأ بضعة بالمائة من النتيجة الحقيقية.

يفترض الحساب أن كل نهاية سطر ممثلة بحرف واحد (مثل UNIX، MacOS، وأحيانًا Cygwin)، وليس حرفين (مثل Windows وأحيانًا Cygwin). إذا قمت بكتابة الرسالة إلى ملف على نظام يستخدم CR و LF لإنهاء سطر واحد (جميع إصدارات Windows)، فستكون النتيجة في هذا الملف أكبر بـ nrLines() على الأقل مما تعيده هذه الطريقة.

$obj->write( [$fh] )
اكتب الرسالة إلى مقبض الملف، والذي افتراضيًا هو $fh المحدد، مع جميع المعلومات المحيطة اللازمة لوضعها بشكل صحيح في ملف مجلد.

في معظم الحالات، ستكون نتيجة "write" هي نفسها نتيجة print(). الاستثناء الرئيسي هو رسائل مجلد Mbox، والتي سيتم طباعتها مع سطر 'From ' الرائد الخاص بها وسطر فارغ لاحق. سيتم إضافة '>' في مقدمة كل سطر من جسمها يبدأ بـ 'From '.

SYNOPSIS

  use Mail::Message;

  my $message = Mail::Message->new(...);
  my $label   = $message->label('seen');
  $message->label('seen' => 1);

  my @names = $message->labels;
  my $all   = $message->labels;

  $message->labelsToStatus;
  $message->statusToLabels;
  $message->modified(1);

DESCRIPTION

This class represents a single message. It is the base class for all message types, like "Mail::Box::Mbox::Message" and "Mail::Box::Maildir::Message".

The message is a container for the header and the body. The header is further structured into header fields. The body can be a simple text, or a MIME-compatible structure of parts.

Methods are provided to access and manipulate the content of the message.

Access to the message content

$obj->label( [$label|$name => $value, ...] )
Get and set message labels. Labels are small pieces of information that are stored with the message, like flags in a traditional mail client.

When called with no arguments, it returns the value of the $label, optionally after setting some values. In case of setting values, you specify key-value "PAIRS".

Labels are used to store knowledge about handling of the message within the folder. Flags about whether a message was read, replied to, or scheduled for deletion.

Some labels are taken from the header's "Status" and "X-Status" lines. Folder types like MH define a separate label file, and Maildir adds letters to the message filename. But the MailBox labels are always the same.

» example:

print $message->label('seen');
if($message->label('seen')) {...};
$message->label(seen => 1);
$message->label(deleted => 1);  # same as $message->delete
$obj->labels()
Returns all known labels. In SCALAR context, it returns the knowledge as reference to a hash. This is a reference to the original data, but you shall *not* change that data directly: call "label" for changes!

In LIST context, you get a list of names which are defined. Be warned that they will not all evaluate to "true", although most of them will.

$obj->labelsToStatus()
When the labels were changed, that may effect the "Status" and/or "X-Status" header lines of mbox messages. Read about the relation between these fields and the labels in the DETAILS chapter.

The method will carefully only affect the result of modified() when there is a real change of flags, so not for each call to label().

$obj->modified( [BOOLEAN] )
Returns (optionally after setting) whether this message is flagged as being modified. See isModified().
$obj->statusToLabels()
Update the labels according the status lines in the header. See the description in the DETAILS chapter.

Internals

$obj->clonedFrom()
Returns the message which is the original of this message, when this was created by a clone() operation.
$class->coerce($message, %options)
Coerce a $message into a Mail::Message. In some occasions, for instance where you add a message to a folder, this coercion is automatically called to ensure that the correct message type is stored.

The coerced message is returned on success, otherwise "undef". The coerced message may be a reblessed version of the original message or a new object. In case the message has to be specialized, for instance from a general Mail::Message into a Mail::Box::Mbox::Message, no copy is needed. However, to coerce a Mail::Internet object into a Mail::Message, a lot of copying and converting will take place.

Valid MESSAGEs which can be coerced into Mail::Message objects are of type

  • Any type of Mail::Box::Message
  • MIME::Entity objects, using Mail::Message::Convert::MimeEntity
  • Mail::Internet objects, using Mail::Message::Convert::MailInternet
  • Email::Simple objects, using Mail::Message::Convert::EmailSimple
  • Email::Abstract objects

Mail::Message::Part's, which are extensions of "Mail::Message"'s, can also be coerced directly from a Mail::Message::Body.

» example:

my $folder  = Mail::Box::Mbox->new;
my $message = Mail::Message->build(...);
my $coerced = Mail::Box::Mbox::Message->coerce($message);
$folder->addMessage($coerced);

Simpler replacement for the previous two lines:

my $coerced = $folder->addMessage($message);
$obj->isDelayed()
Check whether the message is delayed (not yet read from file). Returns "true" or "false", dependent on the body type.
$obj->readBody( $parser, $head, [$bodytype] )
Read a body of a message. The $parser is the access to the folder's file, and the $head is already read. Information from the $head is used to create expectations about the message's length, but also to determine the mime-type and encodings of the body data.

The $bodytype determines which kind of body will be made and defaults to the value specified by new(body_type). $bodytype may be the name of a body class, or a reference to a routine which returns the body's class when passed the $head as only argument.

$obj->readFromParser( $parser, [$bodytype] )
Read one message from file. The $parser is opened on the file. First readHead() is called, and the head is stored in the message. Then readBody() is called, to produce a body. Also the body is added to the message without decodings being done.

The optional $bodytype may be a body class or a reference to a code which returns a body-class based on the header.

$obj->readHead( $parser, [$class] )
Read a head into an object of the specified $class. The $class defaults to new(head_type). The $parser is the access to the folder's file.
$obj->recursiveRebuildPart($part, %options)
Inherited, see "Internals" in Mail::Message::Construct::Rebuild
$obj->storeBody($body)
Where the body() method can be used to set and get a body, with all the necessary checks, this method is bluntly adding the specified body to the message. No conversions, no checking.
$obj->takeMessageId( [STRING] )
Take the message-id from the "STRING", or create one when the "undef" is specified. If not "STRING" nor "undef" is given, the current header of the message is requested for the value of the 'Message-ID' field.

Angles (if present) are removed from the id.

$obj->destruct()
Remove the information contained in the message object. This will be ignored when more than one reference to the same message object exists, because the method has the same effect as assigning "undef" to the variable which contains the reference. Normal garbage collection will call DESTROY() when possible.

This method is only provided to hide differences with messages which are located in folders: their Mail::Box::Message::destruct() works quite differently.

» example: of Mail::Message destruct

my $msg = Mail::Message->read;
$msg->destruct;
$msg = undef;    # same
