MSGOP(2) دليل استدعاءات النظام MSGOP(2)

الاسم

msgrcv, msgsnd - عمليات قائمة رسائل System V

المكتبة

مكتبة C القياسية (libc، -lc)

التركيب

#include <sys/msg.h>
ssize_t msgrcv(size_t msgsz;
               int msqid, void msgp[msgsz], size_t msgsz, long msgtyp,
               int msgflg);
int msgsnd(size_t msgsz;
               int msqid, const void msgp[msgsz], size_t msgsz,
               int msgflg);

الوصف

تُستخدم استدعاءات النظام msgsnd() وmsgrcv() لإرسال الرسائل إلى قائمة رسائل System V واستقبال الرسائل منها. يجب أن يمتلك العملية المستدعية إذن الكتابة على قائمة الرسائل من أجل إرسال رسالة، وإذن القراءة لاستقبال رسالة.

الوسيط msgp هو مؤشر إلى بنية يحددها المستدعي بالشكل العام التالي:


struct msgbuf {
    long mtype;       /* نوع الرسالة، يجب أن يكون > 0 */
    char mtext[1];    /* بيانات الرسالة */
};

حقل mtext هو مصفوفة (أو بنية أخرى) يُحدد حجمها بواسطة msgsz، وهي قيمة عددية صحيحة غير سالبة. يُسمح بالرسائل ذات الطول الصفري (أي بدون حقل mtext). يجب أن يكون لحقل mtype قيمة عددية صحيحة موجبة تمامًا. يمكن استخدام هذه القيمة من قبل العملية المستقبلة لاختيار الرسالة (انظر وصف msgrcv() أدناه).

msgsnd()

يُضيف استدعاء النظام msgsnd() نسخة من الرسالة التي يشير إليها msgp إلى قائمة الرسائل التي يُحدد معرفها بواسطة msqid.

إذا كانت هناك مساحة كافية متاحة في القائمة، فإن msgsnd() ينجح فورًا. تُحكم سعة القائمة بواسطة حقل msg_qbytes في البنية البيانات المرتبطة بقائمة الرسائل. أثناء إنشاء القائمة، تتم تهيئة هذا الحقل إلى MSGMNB بايت، ولكن يمكن تعديل هذا الحد باستخدام msgctl(2). تُعتبر قائمة الرسائل ممتلئة إذا تحقق أي من الشرطين التاليين:

•
إضافة رسالة جديدة إلى القائمة ستؤدي إلى تجاوز إجمالي عدد البايتات في القائمة الحد الأقصى لحجم القائمة (حقل msg_qbytes).
•
إضافة رسالة أخرى إلى القائمة ستؤدي إلى تجاوز إجمالي عدد الرسائل في القائمة الحد الأقصى لحجم القائمة (حقل msg_qbytes). هذا الفحص ضروري لمنع وضع عدد غير محدود من الرسائل ذات الطول الصفري في القائمة. على الرغم من أن هذه الرسائل لا تحتوي على بيانات، إلا أنها مع ذلك تستهلك ذاكرة النواة (المقفلة).

إذا لم تكن هناك مساحة كافية متاحة في القائمة، فإن السلوك الافتراضي لـ msgsnd() هو الحجب حتى تصبح المساحة متاحة. إذا تم تحديد IPC_NOWAIT في msgflg، فإن الاستدعاء يفشل بدلاً من ذلك بالخطأ EAGAIN.

قد يفشل استدعاء msgsnd() المحجوب أيضًا إذا:

•
تمت إزالة القائمة، وفي هذه الحالة يفشل استدعاء النظام مع تعيين errno إلى EIDRM؛ أو
•
تم التقاط إشارة، وفي هذه الحالة يفشل استدعاء النظام مع تعيين errno إلى EINTR؛ انظر signal(7). (msgsnd() لا يُعاد تشغيله تلقائيًا أبدًا بعد مقاطعته بواسطة معالج إشارة، بغض النظر عن إعداد علم SA_RESTART عند إنشاء معالج إشارة.)

عند الإكمال الناجح، يتم تحديث بنية بيانات قائمة الرسائل كما يلي:

•
يُعيَّن msg_lspid إلى معرف العملية للعملية المستدعية.
•
يُزاد msg_qnum بمقدار 1.
•
يُعيَّن msg_stime إلى الوقت الحالي.

msgrcv()

يزيل استدعاء النظام msgrcv() رسالة من القائمة المحددة بواسطة msqid ويضعها في المخزن المؤقت الذي يشير إليه msgp.

يُحدد الوسيط msgsz الحد الأقصى للحجم بالبايت للعضو mtext في البنية التي يشير إليها الوسيط msgp. إذا كان طول نص الرسالة أكبر من msgsz، فإن السلوك يعتمد على ما إذا كان MSG_NOERROR محددًا في msgflg. إذا تم تحديد MSG_NOERROR، فسيتم اقتطاع نص الرسالة (وسيُفقد الجزء المقتطع)؛ إذا لم يتم تحديد MSG_NOERROR، فلن تُزال الرسالة من القائمة ويفشل استدعاء النظام بإرجاع -1 مع تعيين errno إلى E2BIG.

ما لم يتم تحديد MSG_COPY في msgflg (انظر أدناه)، يُحدد الوسيط msgtyp نوع الرسالة المطلوبة، كما يلي:

•
إذا كان msgtyp يساوي 0، فستُقرأ أول رسالة في القائمة.
•
إذا كان msgtyp أكبر من 0، فستُقرأ أول رسالة في القائمة من النوع msgtyp، ما لم يتم تحديد MSG_EXCEPT في msgflg، وفي هذه الحالة ستُقرأ أول رسالة في القائمة من نوع لا يساوي msgtyp.
•
إذا كان msgtyp أقل من 0، فستُقرأ أول رسالة في القائمة بأدنى نوع أقل من أو يساوي القيمة المطلقة لـ msgtyp.

الوسيط msgflg هو قناع بتات يُبنى بعملية OR لصفر أو أكثر من الأعلام التالية:

IPC_NOWAIT
العودة فورًا إذا لم تكن هناك رسالة من النوع المطلوب في القائمة. يفشل استدعاء النظام مع تعيين errno إلى ENOMSG.
MSG_COPY (منذ لينكس 3.8)
جلب نسخة من الرسالة بشكل غير إتلافي عند الموضع الترتيبي في القائمة المحدد بواسطة msgtyp (تُعتبر الرسائل مرقمة بدءًا من 0).
يجب تحديد هذا العلم بالاقتران مع IPC_NOWAIT، مما يؤدي إلى أنه إذا لم تكن هناك رسالة متاحة في الموضع المحدد، يفشل الاستدعاء فورًا بالخطأ ENOMSG. نظرًا لأنهما يغيران معنى msgtyp بطرق متعامدة، فلا يجوز تحديد كل من MSG_COPY وMSG_EXCEPT معًا في msgflg.
أُضيف علم MSG_COPY لتنفيذ مرفق نقطة تفتيش واستعادة النواة وهو متاح فقط إذا تم بناء النواة مع خيار CONFIG_CHECKPOINT_RESTORE.
MSG_EXCEPT
يُستخدم مع msgtyp أكبر من 0 لقراءة أول رسالة في القائمة بنوع رسالة يختلف عن msgtyp.
MSG_NOERROR
لاقتطاع نص الرسالة إذا كان أطول من msgsz بايت.

إذا لم تكن هناك رسالة من النوع المطلوب متاحة ولم يتم تحديد IPC_NOWAIT في msgflg، فسيتم حجب العملية المستدعية حتى يحدث أحد الشروط التالية:

•
تُوضع رسالة من النوع المطلوب في القائمة.
•
تُزال قائمة الرسائل من النظام. في هذه الحالة، يفشل استدعاء النظام مع تعيين errno إلى EIDRM.
•
تلتقط العملية المستدعية إشارة. في هذه الحالة، يفشل استدعاء النظام مع تعيين errno إلى EINTR. (msgrcv() لا يُعاد تشغيله تلقائيًا أبدًا بعد مقاطعته بواسطة معالج إشارة، بغض النظر عن إعداد علم SA_RESTART عند إنشاء معالج إشارة.)

عند الإكمال الناجح، يتم تحديث بنية بيانات قائمة الرسائل كما يلي:

يُعيَّن msg_lrpid إلى معرف العملية للعملية المستدعية.
يُنقص msg_qnum بمقدار 1.
يُعيَّن msg_rtime إلى الوقت الحالي.

القيمة المُرجعة

عند النجاح، يُرجع msgsnd() القيمة 0 ويُرجع msgrcv() القيمة

عدد البايتات المنسوخة فعليًا إلى مصفوفة mtext. عند الفشل، تُرجع كلتا الدالتين -1، وتضبطان errno للإشارة إلى الخطأ.

الأخطاء

يمكن أن تفشل msgsnd() بالأخطاء التالية:

EACCES
لا تمتلك العملية المستدعية إذن الكتابة على طابور الرسائل، ولا تمتلك قدرة CAP_IPC_OWNER في فضاء المستخدم الذي يحكم فضاء IPC الخاص بها.
EAGAIN
لا يمكن إرسال الرسالة بسبب حد msg_qbytes للطابور وتم تحديد IPC_NOWAIT في msgflg.
EFAULT
العنوان الذي تشير إليه msgp غير قابل للوصول.
EIDRM
تمت إزالة طابور الرسائل.
EINTR
أثناء النوم على حالة طابور رسائل ممتلئ، التقطت العملية إشارة.
EINVAL
قيمة msqid غير صالحة، أو قيمة mtype غير موجبة، أو قيمة msgsz غير صالحة (أقل من 0 أو أكبر من قيمة النظام MSGMAX).
ENOMEM
لا يمتلك النظام ذاكرة كافية لعمل نسخة من الرسالة التي تشير إليها msgp.

يمكن أن تفشل msgrcv() بالأخطاء التالية:

E2BIG
طول نص الرسالة أكبر من msgsz ولم يتم تحديد MSG_NOERROR في msgflg.
EACCES
لا تمتلك العملية المستدعية إذن القراءة على طابور الرسائل، ولا تمتلك قدرة CAP_IPC_OWNER في فضاء المستخدم الذي يحكم فضاء IPC الخاص بها.
EFAULT
العنوان الذي تشير إليه msgp غير قابل للوصول.
EIDRM
بينما كانت العملية نائمة لتلقي رسالة، تمت إزالة طابور الرسائل.
EINTR
بينما كانت العملية نائمة لتلقي رسالة، التقطت العملية إشارة؛ انظر signal(7).
EINVAL
كانت msqid غير صالحة، أو كانت msgsz أقل من 0.
EINVAL (منذ Linux 3.14)
حددت msgflg MSG_COPY، ولكن ليس IPC_NOWAIT.
EINVAL (منذ Linux 3.14)
حددت msgflg كلاً من MSG_COPY وMSG_EXCEPT.
ENOMSG
تم تحديد IPC_NOWAIT في msgflg ولم توجد رسالة من النوع المطلوب على طابور الرسائل.
ENOMSG
تم تحديد IPC_NOWAIT وMSG_COPY في msgflg و يحتوي الطابور على أقل من msgtyp رسالة.
ENOSYS (منذ Linux 3.8)
تم تحديد كلاً من MSG_COPY وIPC_NOWAIT في msgflg، وتم تكوين هذه النواة بدون CONFIG_CHECKPOINT_RESTORE.

المعايير

POSIX.1-2024.

رايتا MSG_EXCEPT وMSG_COPY خاصتان بـ Linux؛ يمكن الحصول على تعريفاتهما بتعريف ماكرو اختبار الميزة _GNU_SOURCE.

التاريخ

POSIX.1-2001، SVr4.

تم الإعلان عن الوسيطة msgp كـ struct msgbuf * في glibc 2.0 و2.1. تم الإعلان عنها كـ void * في glibc 2.2 وما بعدها، كما هو مطلوب بواسطة SUSv2 و SUSv3.

ملاحظات

تؤثر الحدود التالية على موارد طابور الرسائل في استدعاء msgsnd():

MSGMAX
الحد الأقصى لحجم نص الرسالة، بالبايت (القيمة الافتراضية: 8192 بايت). على Linux، يمكن قراءة هذا الحد وتعديله عبر /proc/sys/kernel/msgmax.
MSGMNB
الحد الأقصى لعدد البايتات التي يمكن احتواؤها في طابور رسائل (القيمة الافتراضية: 16384 بايت). على Linux، يمكن قراءة هذا الحد وتعديله عبر /proc/sys/kernel/msgmnb. يمكن لعملية مميزة (Linux: عملية تمتلك قدرة CAP_SYS_RESOURCE) زيادة حجم طابور رسائل بما يتجاوز MSGMNB باستخدام عملية msgctl(2) IPC_SET.

لا يمتلك التنفيذ حدودًا جوهرية على مستوى النظام لعدد رؤوس الرسائل (MSGTQL) وعدد البايتات في مجمع الرسائل (MSGPOOL).

الأخطاء البرمجية

في Linux 3.13 وما قبله، إذا تم استدعاء msgrcv() مع راية MSG_COPY، ولكن بدون IPC_NOWAIT، وكان طابور الرسائل يحتوي على أقل من msgtyp رسالة، فإن الاستدعاء كان سيحجب حتى كتابة الرسالة التالية إلى الطابور. عند تلك النقطة، كان الاستدعاء يُرجع نسخة من الرسالة، بغض النظر عما إذا كانت تلك الرسالة في الموضع الترتيبي msgtyp. تم إصلاح هذا الخطأ في Linux 3.14.

تحديد كلاً من MSG_COPY وMSC_EXCEPT في msgflg هو خطأ منطقي (لأن هذه الرايات تفرض تفسيرات مختلفة على msgtyp). في Linux 3.13 وما قبله، لم يتم تشخيص هذا الخطأ بواسطة msgrcv(). تم إصلاح هذا الخطأ في Linux 3.14.

أمثلة

يوضح البرنامج أدناه استخدام msgsnd() و msgrcv().

يتم تشغيل البرنامج المثال أولاً مع الخيار -s لإرسال رسالة ثم تشغيله مرة أخرى مع الخيار -r لتلقي رسالة.

تُظهر جلسة الصدفة التالية تشغيلاً نموذجيًا للبرنامج:


$ ./a.out -s
sent: a message at Wed Mar  4 16:25:45 2015
$ ./a.out -r
message received: a message at Wed Mar  4 16:25:45 2015

مصدر البرنامج

#include <errno.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/ipc.h>
#include <sys/msg.h>
#include <time.h>
#include <unistd.h>
struct msgbuf {
    long mtype;
    char mtext[80];
};
static void
usage(char *prog_name, char *msg)
{
    if (msg != NULL)
        fputs(msg, stderr);
    fprintf(stderr, "Usage: %s [options]\n", prog_name);
    fprintf(stderr, "Options are:\n");
    fprintf(stderr, "-s        send message using msgsnd()\n");
    fprintf(stderr, "-r        read message using msgrcv()\n");
    fprintf(stderr, "-t        message type (default is 1)\n");
    fprintf(stderr, "-k        message queue key (default is 1234)\n");
    exit(EXIT_FAILURE);
}
static void
send_msg(int qid, int msgtype)
{
    time_t         t;
    struct msgbuf  msg;
    msg.mtype = msgtype;
    time(&t);
    snprintf(msg.mtext, sizeof(msg.mtext), "a message at %s",
             ctime(&t));
    if (msgsnd(qid, &msg, sizeof(msg.mtext),
               IPC_NOWAIT) == -1)
    {
        perror("msgsnd error");
        exit(EXIT_FAILURE);
    }
    printf("sent: %s\n", msg.mtext);
}
static void
get_msg(int qid, int msgtype)
{
    struct msgbuf msg;
    if (msgrcv(qid, &msg, sizeof(msg.mtext), msgtype,
               MSG_NOERROR | IPC_NOWAIT) == -1) {
        if (errno != ENOMSG) {
            perror("msgrcv");
            exit(EXIT_FAILURE);
        }
        printf("No message available for msgrcv()\n");
    } else {
        printf("message received: %s\n", msg.mtext);
    }
}
int
main(int argc, char *argv[])
{
    int  qid, opt;
    int  mode = 0;               /* 1 = send, 2 = receive */
    int  msgtype = 1;
    int  msgkey = 1234;
    while ((opt = getopt(argc, argv, "srt:k:")) != -1) {
        switch (opt) {
        case 's':
            mode = 1;
            break;
        case 'r':
            mode = 2;
            break;
        case 't':
            msgtype = atoi(optarg);
            if (msgtype <= 0)
                usage(argv[0], "-t option must be greater than 0\n");
            break;
        case 'k':
            msgkey = atoi(optarg);
            break;
        default:
            usage(argv[0], "Unrecognized option\n");
        }
    }
    if (mode == 0)
        usage(argv[0], "must use either -s or -r option\n");
    qid = msgget(msgkey, IPC_CREAT | 0666);
    if (qid == -1) {
        perror("msgget");
        exit(EXIT_FAILURE);
    }
    if (mode == 2)
        get_msg(qid, msgtype);
    else
        send_msg(qid, msgtype);
    exit(EXIT_SUCCESS);
}
