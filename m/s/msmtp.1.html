الاستخدام

A suggestion for a suitable configuration file can be generated using the --configure option. Normally, a system wide configuration file and/or a user configuration file contain information about which SMTP server to use and how to use it, but all settings can also be configured on the command line.
The information about SMTP servers is organized in accounts. Each account describes one SMTP server: host name, authentication settings, TLS settings, and so on. Each configuration file can define multiple accounts.

The user can choose which account to use in one of three ways:

--account=id
Use the given account. Command line settings override configuration file settings.
--host=hostname
Use only the settings from the command line; do not use any configuration file data.
--from=address or --read-envelope-from
Choose the first account from the system or user configuration file that has a matching envelope-from address as specified by a from command. This works only when neither --account nor --host is used.
Subadresses are supported. For example, the envelope from address user+detail@example.com will match the account for user@example.com.
Furthermore, the envelope-from address of the account may be a wildcard pattern. See the from command.

If none of the above options is used (or if no account has a matching from command), then the account "default" is used.

Msmtp transmits mails unaltered to the SMTP server, with the following exceptions:
- The Bcc header(s) will be removed. This behavior can be changed with the remove_bcc_headers command and --remove-bcc-headers option.
- A From header will be added if the mail does not have one. This can be changed with the set_from_header command and --set-from-header option. The header will use the envelope from address and optionally a full name set with the -F option or from_full_name command.
- A Date header will be added if the mail does not have one. This can be changed with the set_date_header command and --set-date-header option.
- A Message-ID header will be added if the mail does not have one. This can be changed with the set_msgid_header command and --set-msgid-header option.
- When set_to_header is set, the original To, Cc, and Bcc headers are replaced with a new To header.

ملفات التكوين

If it exists and is readable, a system wide configuration file SYSCONFDIR/msmtprc will be loaded, where SYSCONFDIR depends on your platform. Use --version to find out which directory is used.
If it exists and is readable, a user configuration file will be loaded (~/.msmtprc will be tried first followed by $XDG_CONFIG_HOME/msmtp/config by default, but see --version). Accounts defined in the user configuration file override accounts from the system configuration file.
Configuration data from either file can be changed by command line options.

A configuration file is a simple text file. Empty lines and comment lines (whose first non-blank character is `#') are ignored.
Every other line must contain a command and may contain an argument to that command.
The argument may be enclosed in double quotes ("), for example if its first or last character is a blank.
If a file name starts with the tilde (~), this tilde will be replaced by $HOME. If a command accepts the argument on, it also accepts an empty argument and treats that as if it was on.
Commands are organized in accounts. Each account starts with the account command and defines the settings for one SMTP account.

Skip to the EXAMPLES section for a quick start.

Commands are as follows:

defaults
Set defaults. The following configuration commands will set default values for all following account definitions in the current configuration file.
account name [:account[,...]]
Start a new account definition with the given name. The current default values are filled in.
If a colon and a list of previously defined accounts is given after the account name, the new account, with the filled in default values, will inherit all settings from the accounts in the list.
eval cmd
Replace the current configuration file line with the first line of the output (stdout) of the command cmd. This can be used to decrypt settings or to create them via scripts. For example, eval echo host localhost replaces the current line with host localhost.
Note that every eval line will be evaluated when the configuration file is read.
The cmd command must not mess with standard input; if in doubt, append < /dev/null.
Note that for passwords you can also use the passwordeval command instead of eval password cmd. This has the advantage that the command is only evaluated if needed.
host hostname
The SMTP server to send the mail to. The argument may be a host name or a network address. Every account definition must contain this command.
port number
The port that the SMTP server listens on. The default is 25 ("smtp"), unless TLS without STARTTLS is used, in which case it is 465 ("smtps").
source_ip [IP]
Set a source IP address to bind the outgoing connection to. Useful only in special cases on multi-home systems. An empty argument disables this.
proxy_host [IP|hostname]
Use a SOCKS proxy. All network traffic will go through this proxy host, including DNS queries, except for a DNS query that might be necessary to resolve the proxy host name itself (this can be avoided by using an IP address as proxy host name). An empty hostname argument disables proxy usage. The supported SOCKS protocol version is 5. If you want to use this with Tor, see also "Using msmtp with Tor" below.
proxy_port [number]
Set the port number for the proxy host. An empty number argument resets this to the default port.
socket [type]
Use a socket instead of a TCP connection. Valid types are pipe, shm and inet.
pipe: Use a Unix domain socket with the name derived from the account name. This is only supported on Linux and BSD systems.
shm: Use a Unix domain socket in shared memory. This is only supported on Linux.
inet: Use an IPv4 or IPv6 socket. This is the default.
An empty type argument resets this to the default.
server_info [hostname]
Set the hostname that is reported to the mail server. This is only relevant if the server requires this information and will be used if the value is not empty. An empty argument disables this.
tls [on|off|proto]
Enable or disable TLS/SSL encryption. The default is off.
If proto is given, it must be one of starttls (default), legacy or only.
starttls: Use STARTTLS (this is the default). The connection is encrypted with STARTTLS.
legacy: Use legacy SMTP over TLS (SMTPS). The connection is encrypted from the beginning. Note that this is not compatible with STARTTLS.
only: Use TLS/SSL for encryption, but don't use STARTTLS. This is only useful if you want to connect to a server that does not support STARTTLS but still wants to use TLS/SSL encryption (e.g. some servers listen on port 465 for legacy SMTPS connections).
An empty argument enables TLS/SSL encryption with STARTTLS.
See also the tls_trust_file and tls_cert_file commands.
tls_trust_file [file]
Set the trust file for TLS/SSL certificates. If file is not given, the default trust file is used. See the TLS_TRUST_FILE section in msmtp.conf(5). An empty argument disables certificate verification.
tls_cert_file [file]
Set the certificate file for client certificate authentication. If file is not given, no client certificate will be used.
tls_key_file [file]
Set the private key file for client certificate authentication. If file is not given, the certificate file is used.
tls_key_cmd [command]
Set a command to retrieve the private key for client certificate authentication. The command is executed with no arguments. Its standard output is used as the private key.
For example: tls_key_cmd openssl s/mine.key.enc -d -a -pbkdf2
tls_dh_params_file [file]
Set the file containing Diffie-Hellman parameters. If not set, msmtp uses built-in parameters. Note that this option is only used when STARTTLS is enabled.
tls_ecdh_curve [curve]
Set the elliptic curve for ECDH. If not set, msmtp uses the default curve. Note that this option is only used when STARTTLS is enabled.
tls_ciphers [ciphers]
Set the list of allowed TLS ciphers. If not set, msmtp uses the default list. A colon-separated list of cipher names.
tls_prefer_server_ciphers [on|off]
Prefer server's cipher list. If not set, msmtp uses its own cipher list.
auth [on|off|method]
Enable or disable SMTP authentication. The default is on.
If method is given, it must be one of login, plain, cram-md5, digest-md5, gssapi, ntlm, spnego, kerberos_v5 or external.
An empty argument enables authentication with the default method (usually login).
See also the user and password commands.
user name
The user name for SMTP authentication. If not given, the user name is taken from the envelope sender address.
password password
The password for SMTP authentication. If not given, no password is used.
passwordeval cmd
Use the output of command cmd as password for SMTP authentication. This is safer than the password command, as the command is only executed if authentication is needed.
ntlm_auth [type]
Set NTLM authentication type. Valid types are ntlmv1, ntlmv2, ntlmv1-ntlmv2 (default).
Note that this option is only effective if auth is set to ntlm or spnego.
smtputf8 [on|off]
Enable or disable the SMTPUTF8 extension (RFC 6531). Default is on. This extension allows sending emails with non-ASCII characters in the recipient addresses and the envelope sender address.
mail_charset [charset]
Set the charset used for the Mail command. Default is "us-ascii". If the command line argument is empty, the default is used.
envelope_from [address]
Set the envelope sender address. If not given, the envelope sender address is taken from the From header.
See also the from command.
from [address]
Set the envelope sender address. This is the address that will be used by the mail server. If not given, the envelope sender address is taken from the From header.
Subadresses are supported. For example, the envelope from address user+detail@example.com will match the account for user@example.com.
Furthermore, the envelope from address of the account may be a wildcard pattern. For example, *@example.com matches all addresses at example.com.
See also the envelope_from command.
allow_from_override [on|off]
Allow overriding the envelope sender address. If set to on, the envelope sender address can be specified on the command line using the --from option. If set to off, this is not allowed and msmtp will use the envelope sender address from the configuration file. The default is on.
This option is ignored if the from command is used in the configuration file.
dsn_notify [conditions]
Set the conditions for DSN notifications. See RFC 3461, section 4.1.1. Possible conditions are always, success, failure, and never.
Example: dsn_notify success,failure
dsn_return [ret]
Set the DSN return path. See RFC 3461, section 4.1.1. Possible values are hdrs (headers only), full (full message) and truncated (truncated message).
Example: dsn_return hdrs
set_from_header [state]
Set handling of the From header. The default is auto.
on: Always add a From header.
off: Never add a From header.
auto: Add a From header only if the mail has no From header.
set_date_header [state]
Set handling of the Date header. The default is auto.
on: Always add a Date header.
off: Never add a Date header.
auto: Add a Date header only if the mail has no Date header.
set_msgid_header [state]
Set handling of the Message-ID header. The default is auto.
on: Always add a Message-ID header.
off: Never add a Message-ID header.
auto: Add a Message-ID header only if the mail has no Message-ID header.
set_to_header [state]
Set handling of the To header. The default is off.
on: Add a To header with the recipients.
off: Do not add a To header.
undisclosed_recipients: Add a To header with the value "undisclosed-recipients". This is useful when sending emails to mailing lists where you don't want to reveal the list members.
remove_bcc_headers [state]
Enable or disable the removal of Bcc headers. The default is on.
on: Remove Bcc headers.
off: Keep Bcc headers.
logfile [file]
Set or unset the log file. If file is not given, the log file is closed. An empty argument resets this to the default log file (usually ~/.msmtp.log).
logfile_time_format [fmt]
Set the time format for log file entries. If fmt is not given, the default format is used.
See strftime(3) for a description of the format string.
syslog [state|facility]
Enable or disable syslog logging. The default is off.
on: Enable syslog logging with the default facility (mail).
off: Disable syslog logging.
facility: Enable syslog logging with the specified facility. Possible facilities are kern, user, mail, daemon, auth, syslog, lpr, news, uucp, cron, authpriv, ftp, ntp, audit, alert, clock, local0 through local7.
aliases [file]
Set or unset an aliases file. If file is not given, the default aliases file is used. An empty argument disables aliases.
from_full_name [name]
Set a full name to be used in a From header if msmtp adds one. If name is not given, no full name is used. An empty argument disables this.
auto_from [state]
Obsolete. Use set_from_header instead.
maildomain [domain]
Obsolete. Use from instead.
timeout [seconds]
Set the connection timeout in seconds. Default is 30. An empty argument resets this to the default value.
connection_timeout [seconds]
Set the connection timeout in seconds. Default is 30. An empty argument resets this to the default value.
tls_timeout [seconds]
Set the TLS handshake timeout in seconds. Default is 60. An empty argument resets this to the default value.
eof_timeout [seconds]
Set the timeout for the EOF marker in seconds. Default is 10. An empty argument resets this to the default value.
keep_alive_timeout [seconds]
Set the keep-alive timeout in seconds. Default is 300. An empty argument resets this to the default value. Setting this to 0 disables keep-alive messages.
trust_xforward_for [on|off]
Trust the X-Forwarded-For header. Default is off. If enabled, msmtp will use the first IP address found in the X-Forwarded-For header as the client IP address. This can be useful when msmtp is used behind a proxy.
xforward_for_accept_invalid_ip [on|off]
Accept invalid IP addresses in the X-Forwarded-For header. Default is off. If enabled, msmtp will ignore invalid IP addresses and try to find a valid one.
xforward_for_accept_invalid_subnet [on|off]
Accept invalid subnets in the X-Forwarded-For header. Default is off. If enabled, msmtp will ignore invalid subnets and try to find a valid one.
