msgget(2) دليل استدعاءات النظام msgget(2)

الاسم

msgget - الحصول على معرف طابور رسائل System V

المكتبة

مكتبة C القياسية (libc، -lc)

الملخص

#include <sys/msg.h>
int msgget(key_t key, int msgflg);

الوصف

يقوم استدعاء النظام msgget() بإرجاع معرف طابور رسائل System V المرتبط بقيمة الوسيط key. يمكن استخدامه إما للحصول على معرف طابور رسائل تم إنشاؤه مسبقًا (عندما تكون msgflg صفرًا ولا تحمل key القيمة IPC_PRIVATE)، أو لإنشاء مجموعة جديدة.

يتم إنشاء طابور رسائل جديد إذا كانت key تحمل القيمة IPC_PRIVATE أو إذا لم تكن key تساوي IPC_PRIVATE، ولم يكن هناك طابور رسائل بالمفتاح key المحدد، وتم تحديد IPC_CREAT في msgflg.

إذا حددت msgflg كلًا من IPC_CREAT و IPC_EXCL، وكان هناك طابور رسائل موجود بالفعل للمفتاح key، فستفشل msgget() مع تعيين errno إلى EEXIST. (هذا مماثل لتأثير تركيبة O_CREAT | O_EXCL لـ open(2).)

عند الإنشاء، تحدد البتات الأقل أهمية للوسيط msgflg أذونات طابور الرسائل. تحتوي هذه بتات الأذونات على نفس التنسيق والدلالات مثل الأذونات المحددة لوسيط mode الخاص بـ open(2). (لا تُستخدم أذونات التنفيذ.)

إذا تم إنشاء طابور رسائل جديد، فسيتم تهيئة بنية البيانات المرتبطة به msqid_ds (انظر msgctl(2)) على النحو التالي:

•
يتم تعيين msg_perm.cuid و msg_perm.uid إلى معرف المستخدم الفعال للعملية المستدعية.
•
يتم تعيين msg_perm.cgid و msg_perm.gid إلى معرف المجموعة الفعال للعملية المستدعية.
•
يتم تعيين البتات الـ 9 الأقل أهمية في msg_perm.mode إلى البتات الـ 9 الأقل أهمية في msgflg.
•
يتم تعيين msg_qnum، msg_lspid، msg_lrpid، msg_stime، و msg_rtime إلى 0.
•
يتم تعيين msg_ctime إلى الوقت الحالي.
•
يتم تعيين msg_qbytes إلى حد النظام MSGMNB.

إذا كان طابور الرسائل موجودًا بالفعل، يتم التحقق من الأذونات، ويتم إجراء فحص لمعرفة ما إذا كان معلمًا للتدمير.

قيمة الإرجاع

عند النجاح، تعيد msgget() معرف طابور الرسائل (عدد صحيح غير سالب). عند الفشل، يتم إرجاع -1، ويتم تعيين errno للإشارة إلى الخطأ.

الأخطاء

EACCES
يوجد طابور رسائل للمفتاح key، ولكن العملية المستدعية ليس لديها إذن للوصول إلى الطابور، ولا تمتلك القدرة CAP_IPC_OWNER في نطاق المستخدم الذي يحكم نطاق IPC الخاص بها.
EEXIST
تم تحديد IPC_CREAT و IPC_EXCL في msgflg، ولكن طابور رسائل موجود بالفعل للمفتاح key.
ENOENT
لا يوجد طابور رسائل للمفتاح key ولم تحدد msgflg IPC_CREAT.
ENOMEM
يجب إنشاء طابور رسائل ولكن النظام لا يمتلك ذاكرة كافية للبنية البيانات الجديدة.
ENOSPC
يجب إنشاء طابور رسائل ولكن حد النظام للعدد الأقصى لطوابير الرسائل (MSGMNI) سيتم تجاوزه.

المعايير

POSIX.1-2024.

التاريخ

POSIX.1-2001، SVr4.

لينكس

حتى Linux 2.3.20، كانت Linux تعيد EIDRM لاستدعاء msgget() على طابور رسائل جدولة للحذف.

ملاحظات

IPC_PRIVATE ليس حقل علم بل نوع key_t. إذا تم استخدام هذه القيمة الخاصة للمفتاح key، فإن استدعاء النظام يتجاهل كل شيء ما عدا البِتات التسعة الأقل أهمية من msgflg وينشئ طابور رسائل جديدًا (عند النجاح).

الحد التالي هو حد النظام لموارد طوابير الرسائل التي تؤثر على استدعاء msgget():

MSGMNI
الحد على مستوى النظام لعدد طوابير الرسائل. قبل Linux 3.19، كانت القيمة الافتراضية لهذا الحد تُحسب باستخدام صيغة تعتمد على ذاكرة النظام المتاحة. منذ Linux 3.19، القيمة الافتراضية هي 32,000. على Linux، يمكن قراءة هذا الحد وتعديله عبر /proc/sys/kernel/msgmni.

أخطاء

ربما كان اختيار الاسم IPC_PRIVATE غير موفق، IPC_NEW كان سيظهر وظيفته بشكل أوضح.

msgget(2) - Arch Linux

msgget(2)

‎2023-10-26

الاسم

msgget - الحصول على معرف قائمة رسائل

الصيغة

cc ...
int msgget(key_t key, int msgflg);

الوصف

msgget هي عملية نظام لإنشاء قائمة رسائل جديدة أو فتح قائمة رسائل موجودة. `key` هو مفتاح فريد يستخدم لتحديد قائمة الرسائل. `msgflg` هي مجموعة من الأعلام التي تحدد سلوك العملية.

تستخدم الأعلام التالية:

  • IPC_CREAT: إنشاء قائمة الرسائل إذا لم تكن موجودة.
  • IPC_EXCL: فشل إذا كانت قائمة الرسائل موجودة بالفعل.
  • IPC_NOWAIT: (غير مستخدم بواسطة msgget)

يتم دمج `msgflg` مع إذن الوصول باستخدام عملية OR المنطقية.

القيمة المعادة

عند النجاح، تعيد msgget معرّف قائمة الرسائل. عند الفشل، تعيد -1 ويتم تعيين errno للإشارة إلى الخطأ.

الأخطاء

  • EACCES: لم يتم منح الإذن بالوصول إلى قائمة الرسائل.
  • EEXIST: قائمة الرسائل موجودة بالفعل ولم يتم تحديد IPC_CREAT.
  • ENOENT: قائمة الرسائل غير موجودة ولم يتم تحديد IPC_CREAT.
  • ENOSPC: تم الوصول إلى الحد الأقصى لعدد قوائم الرسائل.
  • ENOMEM: لا توجد ذاكرة كافية متاحة.
