Module::Build(3pm) وثائق مساهمات المستخدم لـ Perl Module::Build(3pm)

الاسم

Module::Build - بناء وتثبيت وحدات Perl

الملخص

العملية القياسية لبناء وتثبيت الوحدات:

perl Build.PL
./Build
./Build test
./Build install

أو، إذا كنت على نظام (مثل DOS أو Windows) لا يتطلب ترميز "./"، يمكنك القيام بما يلي:

perl Build.PL
Build
Build test
Build install

الوصف

"Module::Build" هو نظام لبناء واختبار وتثبيت وحدات Perl. إنه يهدف إلى أن يكون بديلاً لـ "ExtUtils::MakeMaker". يجوز للمطورين تغيير سلوك الوحدة من خلال التوريث الفرعي. كما أنه لا يتطلب "make" على نظامك - معظم كود "Module::Build" هو Perl نقي مكتوب بطريقة متوافقة مع الأنظمة المختلفة.

انظر "COMPARISON" لمزيد من المقارنات بين "Module::Build" وأدوات التثبيت الأخرى.

لتثبيت "Module::Build"، وأي وحدة أخرى تستخدم "Module::Build" لعملية التثبيت الخاصة بها، قم بما يلي:

perl Build.PL       # يقوم البرنامج النصي 'Build.PL' بإنشاء البرنامج النصي 'Build'
./Build             # نحتاج ./ للتأكد من أننا نستخدم هذا البرنامج النصي "Build"
./Build test        # وعدم استخدام برنامج نصي آخر قد يكون موجودًا في المسار
./Build install

يوضح هذا التكوين الأولي وتشغيل ثلاثة 'إجراءات'. في هذه الحالة، الإجراءات التي يتم تشغيلها هي 'build' (الإجراء الافتراضي)، 'test'، و 'install'. تشمل الإجراءات الأخرى المعرفة حتى الآن:

build                          manifest
clean                          manifest_skip
code                           manpages
config_data                    pardist
diff                           ppd
dist                           ppmdist
distcheck                      prereq_data
distclean                      prereq_report
distdir                        pure_install
distinstall                    realclean
distmeta                       retest
distsign                       skipcheck
disttest                       test
docs                           testall
fakeinstall                    testcover
help                           testdb
html                           testpod
install                        testpodcoverage
installdeps                    versioninstall

يمكنك تشغيل إجراء 'help' للحصول على قائمة كاملة بالإجراءات.

دليل الوثائق

وثائق "Module::Build" مقسمة إلى أقسام:

الاستخدام العام (Module::Build)
هذه هي الوثيقة التي تقرأها حاليًا. تصف الاستخدام الأساسي والمعلومات الخلفية. الغرض الرئيسي منها هو مساعدة المستخدم الذي يرغب في تعلم كيفية استدعاء والتحكم في نصوص "Module::Build" البرمجية من سطر الأوامر.
مرجع التأليف (Module::Build::Authoring)
تصف هذه الوثيقة بنية وتنظيم "Module::Build"، والمفاهيم ذات الصلة المطلوبة من قبل المؤلفين الذين يكتبون نصوص Build.PL لتوزيع أو التحكم في عمليات "Module::Build" برمجياً.
مرجع واجهة برمجة التطبيقات (Module::Build::API)
هذا مرجع لواجهة برمجة التطبيقات الخاصة بـ "Module::Build".
دليل الوصفات (Module::Build::Cookbook)
يوضح هذا المستند كيفية إنجاز العديد من المهام الشائعة. يغطي الاستخدام العام لسطر الأوامر وتأليف نصوص Build.PL البرمجية. يتضمن أمثلة عملية.

الإجراءات

هناك بعض المبادئ العامة قيد العمل هنا. أولاً، تسمى كل مهمة عند بناء وحدة 'إجراء'. هذه الإجراءات مدرجة أعلاه؛ فهي تتوافق مع مهام البناء والاختبار والتثبيت والتعبئة وما إلى ذلك.

ثانياً، يتم معالجة الوسائط بطريقة منهجية للغاية. الوسائط دائمًا أزواج مفتاح=قيمة. يمكن تحديدها في وقت "perl Build.PL" (أي "perl Build.PL destdir=/my/secret/place")، وفي هذه الحالة تدوم قيمها طوال مدة البرنامج النصي "Build". يمكن أيضًا تحديدها عند تنفيذ إجراء معين (أي "Build test verbose=1")، وفي هذه الحالة تدوم قيمها فقط طوال مدة هذا الأمر. المعلمات الإضافية لكل إجراء على سطر الأوامر لها الأسبقية على المعلمات المحددة في وقت "perl Build.PL".

تعتمد عملية البناء أيضًا بشكل كبير على الوحدة "Config.pm". إذا رغب المستخدم في تجاوز أي من القيم في "Config.pm"، فيمكنه تحديدها على النحو التالي:

perl Build.PL --config cc=gcc --config ld=gcc

توفر الإجراءات التالية افتراضيًا.

هذا مشابه لهدف make all في "MakeMaker".

[الإصدار 0.01]

[الإصدار 0.20]

يقوم هذا الإجراء ببناء قاعدة الكود الخاصة بك.

افتراضيًا، يقوم فقط بإنشاء دليل "blib/" وينسخ أي ملفات ".pm" و ".pod" من دليل "lib/" الخاص بك إلى الدليل "blib/". كما يقوم بتجميع أي ملفات ".xs" من "lib/" ووضعها في "blib/". بالطبع، تحتاج إلى مترجم C يعمل (ربما نفس المترجم الذي بنى perl نفسه) لكي تعمل عملية التجميع بشكل صحيح.

يقوم إجراء "code" أيضًا بتشغيل أي ملفات ".PL" في دليل lib/ الخاص بك. عادةً ما تنشئ هذه الملفات ملفات أخرى، مسماة بنفس الاسم ولكن بدون اللاحقة ".PL". على سبيل المثال، يمكن لملف lib/Foo/Bar.pm.PL إنشاء الملف lib/Foo/Bar.pm. يتم معالجة ملفات ".PL" أولاً، بحيث يتم نسخ أي ملفات ".pm" (أو أنواع أخرى نتعامل معها) بشكل صحيح.

NAME

Module::Build - Build and install Perl modules

SYNOPSIS

    use Module::Build;
    my $builder = Module::Build->new(
        module_name        => 'My-Module',
        dist_version       => '0.01',
        dist_author        => 'Your Name <you@example.com>',
        dist_abstract      => 'A short description of my module',
        requires_perl      => '5.006',
        # other options...
    );
    $builder->create_build_script;

DESCRIPTION

"Module::Build" is a system for building, testing, and installing Perl modules. It replaces the older "ExtUtils::MakeMaker" system, offering a more flexible and Perl-idiomatic approach.

Instead of generating a traditional Makefile, "Module::Build" generates a Perl script (named "Build") that performs all the build, test, and install actions. This allows for more complex build logic and platform-specific actions without needing to write C code or complex shell scripts.

This manual page provides an overview of "Module::Build", its features, and how to use it. For detailed information, refer to the other manual pages listed in the "SEE ALSO" section.

ACTIONS

"Module::Build" supports a variety of actions that can be invoked via the "Build" script. Some common actions include:

build
Compiles and builds the module. This is usually the default action if no action is specified.
test
Runs the module's test suite.
install
Installs the module into the Perl library.
clean
Removes generated files (e.g., compiled objects, Build script).
dist
Creates a distribution tarball.
upload
Uploads the distribution to a CPAN-like repository.

These actions can be invoked like so:

    perl Build.PL
    ./Build build
    ./Build test
    ./Build install
    ./Build clean
    ./Build dist
    ./Build upload

OPTIONS

The "Build.PL" script accepts various command-line options to customize the build process. These options are passed to the "Module::Build->new()" method.

Some common options include:

module_name
The name of the module (e.g., "My-Module").
dist_version
The distribution version (e.g., "0.01").
dist_author
The author of the distribution.
dist_abstract
A short abstract for the distribution.
requires_perl
The minimum required Perl version.
build_requires
A hash of modules required for building the distribution.
configure_requires
A hash of modules required for configuring the distribution.
recursive_install
If true, installs dependencies recursively.
auto_configure_requires
If true, automatically adds build and configure prerequisites.

Example:

    perl Build.PL --module_name My-Module --dist_version 1.0 --opt_flag --another_flag=value

INSTALL PATHS

Compatibility with ExtUtils::MakeMaker's PREFIX
Provided for compatibility with "ExtUtils::MakeMaker"'s PREFIX argument. "prefix" should be used when you want Module::Build to install your modules, documentation, and scripts in the same place as "ExtUtils::MakeMaker"'s PREFIX mechanism.

The following are equivalent.

perl Build.PL --prefix /tmp/foo
perl Makefile.PL PREFIX=/tmp/foo

Because of the complex nature of the prefixification logic, the behavior of PREFIX in "MakeMaker" has changed subtly over time. Module::Build's --prefix logic is equivalent to the PREFIX logic found in "ExtUtils::MakeMaker" 6.30.

The maintainers of "MakeMaker" do understand the troubles with the PREFIX mechanism, and added INSTALL_BASE support in version 6.31 of "MakeMaker", which was released in 2006.

If you don't need to retain compatibility with old versions (pre-6.31) of "ExtUtils::MakeMaker" or are starting a fresh Perl installation we recommend you use "install_base" instead (and "INSTALL_BASE" in "ExtUtils::MakeMaker"). See "Installing in the same location as ExtUtils::MakeMaker" in Module::Build::Cookbook for further information.

COMPARISON

A comparison between "Module::Build" and other CPAN distribution installers.

  • ExtUtils::MakeMaker requires "make" and use of a Makefile. "Module::Build" does not, nor do other pure-perl installers following the Build.PL spec such as Module::Build::Tiny. In practice, this is usually not an issue for the end user, as "make" is already required to install most CPAN modules, even on Windows.
  • ExtUtils::MakeMaker has been a core module in every version of Perl 5, and must maintain compatibility to install the majority of CPAN modules. "Module::Build" was added to core in Perl 5.10 and removed from core in Perl 5.20, and (like ExtUtils::MakeMaker) is only updated to fix critical issues and maintain compatibility. "Module::Build" and other non-core installers like Module::Build::Tiny are installed from CPAN by declaring themselves as a "configure" phase prerequisite, and in this way any installer can be used in place of ExtUtils::MakeMaker.
  • Customizing the build process with ExtUtils::MakeMaker involves overriding certain methods that form the Makefile by defining the subs in the "MY::" namespace, requiring in-depth knowledge of Makefile, but allowing targeted customization of the entire build. Customizing "Module::Build" involves subclassing "Module::Build" itself, adding or overriding pure-perl methods that represent build actions, which are invoked as arguments passed to the generated "./Build" script. This is a simpler concept but requires redefining the standard build actions to invoke your customizations. Module::Build::Tiny does not allow for customization.
  • "Module::Build" provides more features and a better experience for distribution authors than ExtUtils::MakeMaker. However, tools designed specifically for authoring, such as Dist::Zilla and its spinoffs Dist::Milla and Minilla, provide these features and more, and generate a configure script (Makefile.PL/Build.PL) that will use any of the various installers separately on the end user side. App::ModuleBuildTiny is an alternative standalone authoring tool for distributions using Module::Build::Tiny, which requires only a simple two-line Build.PL.
