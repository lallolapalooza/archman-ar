صيغة ملف تثبيت JAR

عندما يتم تشغيل ملف JAR بواسطة خادم، أو بواسطة modutil، أو بواسطة أي برنامج لا يفسر JavaScript، يجب تضمين ملف معلومات خاص لتثبيت المكتبات. هناك عدة أمور يجب مراعاتها بخصوص هذا الملف:

•يجب الإعلان عنه في ملف manifest الخاص بأرشيف JAR.
•يمكن أن يكون لاسم البرنامج النصي أي اسم.
•العلامة التعريفية لهذا هي Pkcs11_install_script. للإعلان عن معلومات تعريفية في ملف manifest، ضعها في ملف يتم تمريره إلى signtool.

مثال على البرنامج النصي

على سبيل المثال، يمكن أن يكون البرنامج النصي لمثبت PKCS #11 في الملف pk11install. إذا كان الأمر كذلك، فإن ملف المعلومات التعريفية لـ signtool يتضمن سطرًا مثل هذا:

+ Pkcs11_install_script: pk11install

يجب أن يحدد البرنامج النصي المنصة ورقم الإصدار، واسم الوحدة وملفها، وأي معلومات اختيارية مثل الأكواد المدعومة وآليات العمل. يمكن تعريف منصات متعددة في ملف تثبيت واحد.

ForwardCompatible { IRIX:6.2:mips SUNOS:5.5.1:sparc }
Platforms {
   WINNT::x86 {
      ModuleName { "مثال الوحدة" }
      ModuleFile { win32/fort32.dll }
      DefaultMechanismFlags{0x0001}
      DefaultCipherFlags{0x0001}
      Files {
         win32/setup.exe {
            Executable
            RelativePath { %temp%/setup.exe }
         }
         win32/setup.hlp {
            RelativePath { %temp%/setup.hlp }
         }
         win32/setup.cab {
            RelativePath { %temp%/setup.cab }
         }
      }
   }
   SUNOS:5.5.1:sparc {
      ModuleName { "مثال وحدة يونكس" }
      ModuleFile { unix/fort.so }
      DefaultMechanismFlags{0x0001}
      CipherEnableFlags{0x0001}
      Files {
         unix/fort.so {
            RelativePath{%root%/lib/fort.so}
            AbsolutePath{/usr/local/netscape/lib/fort.so}
            FilePermissions{555}
         }
         xplat/instr.html {
            RelativePath{%root%/docs/inst.html}
            AbsolutePath{/usr/local/netscape/docs/inst.html}
            FilePermissions{555}
         }
      }
   }
   IRIX:6.2:mips {
      EquivalentPlatform { SUNOS:5.5.1:sparc }
   }
}

قواعد البرنامج النصي

البرنامج النصي هو Java أساسي، يسمح بالقوائم، والأزواج من المفتاح والقيمة، والسلاسل النصية، والتركيبات من كل هذه. 

--> valuelist
valuelist --> value valuelist
               <null>
value ---> key_value_pair
            string
key_value_pair --> key { valuelist }
key --> string
string --> simple_string
            "complex_string"
simple_string --> [^ \t\n\""{""}"]+ 
complex_string --> ([^\"\\\r\n]|(\\\")|(\\\\))+

يجب الهروب من علامات الاقتباس والشرطات المائلة للخلف باستخدام شرطة مائلة للخلف. يجب ألا يحتوي السلسلة المعقدة على أسطر جديدة أو عودات عربة. خارج السلاسل المعقدة، يتم اعتبار جميع المسافات البيضاء (على سبيل المثال، المسافات، وعلامات الجدولة، وعودات العربة) متساوية وتستخدم فقط لتحديد الرموز.

المفاتيح

يستخدم ملف تثبيت Java المفاتيح لتحديد معلومات المنصة والوحدة.

ForwardCompatible يمنح قائمة بالمنصات المتوافقة مع المستقبل. إذا لم يتم العثور على المنصة الحالية في قائمة المنصات المدعومة، يتم فحص قائمة ForwardCompatible بحثًا عن أي منصات لها نفس نظام التشغيل والبنية في إصدار أقدم. إذا تم العثور على واحدة، فسيتم استخدام سماتها للمنصة الحالية.

Platforms (مطلوب) يمنح قائمة بالمنصات. كل إدخال في القائمة هو نفسه زوج من المفتاح والقيمة: المفتاح هو اسم المنصة وقائمة القيم تحتوي على سمات مختلفة للمنصة. السلسلة النصية للمنصة هي بتنسيق اسم النظام:إصدار نظام التشغيل:البنية. يحصل المثبت على هذه القيم من NSPR. إصدار نظام التشغيل هو سلسلة فارغة على أنظمة التشغيل غير Unix. يدعم NSPR هذه المنصات:

•AIX (rs6000)
•BSDI (x86)
•FREEBSD (x86)
•HPUX (hppa1.1)
•IRIX (mips)
•LINUX (ppc, alpha, x86)
•MacOS (PowerPC)
•NCR (x86)
•NEC (mips)
•OS2 (x86)
•OSF (alpha)
•ReliantUNIX (mips)
•SCO (x86)
•SOLARIS (sparc)
•SONY (mips)
•SUNOS (sparc)
•UnixWare (x86)
•WIN16 (x86)
•WIN95 (x86)
•WINNT (x86)

على سبيل المثال:

IRIX:6.2:mips
SUNOS:5.5.1:sparc
Linux:2.0.32:x86
WIN95::x86

يتم تعريف معلومات الوحدة بشكل مستقل لكل منصة في سمات ModuleName و ModuleFile و Files. يجب توفير هذه السمات ما لم يتم تحديد سمة EquivalentPlatform.

المفاتيح الخاصة بالمنصة

المفاتيح الخاصة بالمنصة لها معنى فقط ضمن قائمة القيم لإدخال في قائمة Platforms.

ModuleName (مطلوب) يمنح الاسم الشائع للوحدة. يستخدم هذا الاسم للإشارة إلى الوحدة بواسطة الخوادم وأداة modutil.

ModuleFile (مطلوب) يسمي ملف وحدة PKCS #11 لهذه المنصة. يتم تقديم الاسم كمسار نسبي للملف داخل أرشيف JAR.

Files (مطلوب) يسرد الملفات التي تحتاج إلى تثبيتها لهذه الوحدة. كل إدخال في قائمة الملفات هو زوج من المفتاح والقيمة. المفتاح هو مسار الملف في أرشيف JAR، وقائمة القيم تحتوي على سمات الملف. يجب تحديد RelativePath أو AbsolutePath على الأقل لكل ملف.

DefaultMechanismFlags يحدد الآليات التي تعد هذه الوحدة مقدمًا افتراضيًا لها؛ هذا يعادل الخيار -mechanism مع الأمر -add. هذا الزوج من المفتاح والقيمة هو سلسلة بتات محددة بتنسيق سداسي عشري (0x). يتم بناؤه كـ OR بت. إذا تم حذف إدخال DefaultMechanismFlags، فإن القيمة الافتراضية تكون 0x0.

RSA:                   0x00000001
DSA:                   0x00000002
RC2:                   0x00000004
RC4:                   0x00000008
DES:                   0x00000010
DH:                    0x00000020
FORTEZZA:              0x00000040
RC5:                   0x00000080
SHA1:                  0x00000100
MD5:                   0x00000200
MD2:                   0x00000400
RANDOM:                0x08000000
FRIENDLY:              0x10000000
OWN_PW_DEFAULTS:       0x20000000
DISABLE:               0x40000000

CipherEnableFlags يحدد الأكواد التي توفرها هذه الوحدة والتي لا يوفرها NSS (بحيث تمكن الوحدة تلك الأكواد لـ NSS). هذا يعادل الوسيطة -cipher مع الأمر -add. هذا المفتاح هو سلسلة بتات محددة بتنسيق سداسي عشري (0x). يتم بنائه كـ OR بت. إذا تم حذف إدخال CipherEnableFlags، فإن القيمة الافتراضية تكون 0x0.

EquivalentPlatform يحدد أنه يجب أيضًا استخدام سمات المنصة المسماة للمنصة الحالية. هذا يجعل الأمور أسهل عندما تستخدم أكثر من منصة نفس الإعدادات.

المفاتيح الخاصة بالملف

بعض المفاتيح لها معنى فقط ضمن قائمة القيم لإدخال في قائمة Files.

كل ملف يتطلب مفتاح مسار يحدد مكان الملف. يجب تحديد إما RelativePath أو AbsolutePath. إذا تم تحديد كليهما، يتم تجربة المسار النسبي أولاً، ويتم استخدام المسار المطلق فقط إذا لم يتم توفير دليل جذر نسبي بواسطة برنامج المثبت.

RelativePath يحدد الدليل الوجهة للملف، نسبيًا إلى دليل ما يتم تحديده وقت التثبيت. يمكن استخدام متغيرين في المسار النسبي: %root% و %temp%. يتم استبدال %root% في وقت التشغيل بالدليل الذي يجب تثبيت الملفات فيه نسبيًا إليه؛ على سبيل المثال، قد يكون هذا هو دليل جذر الخادم. يتم إنشاء دليل %temp% في بداية التثبيت ويتم تدميره في النهاية. الغرض من %temp% هو الاحتفاظ بالملفات القابلة للتنفيذ (مثل برامج الإعداد) أو الملفات التي تستخدمها هذه البرامج. يتم ضمان وجود الملفات الموجهة إلى الدليل المؤقت قبل تشغيل أي ملف قابل للتنفيذ؛ لا يتم حذفها حتى تنتهي جميع الملفات القابلة للتنفيذ.

AbsolutePath يحدد دليل الوجهة للملف كمسار مطلق.

Executable يحدد أن الملف سيتم تنفيذه أثناء عملية التثبيت. عادةً، يستخدم هذا السلسلة لبرنامج إعداد مقدم من بائع الوحدة، مثل ملف تنفيذي للإعداد ذاتي الاستخراج. يمكن تحديد أكثر من ملف واحد كقابل للتنفيذ، وفي هذه الحالة يتم تشغيل الملفات بالترتيب الذي يتم بها تحديدها في ملف البرنامج النصي.

FilePermissions يضبط الأذونات على أي ملفات مشار إليها في سلسلة من الأرقام الثمانية، وفقًا لتنسيق Unix القياسي. هذه السلسلة هي OR بت.

user read:                0400
user write:               0200
user execute:             0100
group read:               0040
group write:              0020
group execute:            0010
other read:               0004
other write:              0002
other execute:            0001

قد لا تفهم بعض المنصات هذه الأذونات. يتم تطبيقها فقط بالقدر الذي تكون فيه ذات معنى للمنصة الحالية. إذا تم حذف هذه السمة، فسيتم افتراض القيمة الافتراضية 777.

أنواع قواعد بيانات NSS

استخدمت NSS في الأصل قواعد بيانات BerkeleyDB لتخزين المعلومات الأمنية. الإصدارات الأخيرة من قواعد البيانات القديمة هذه هي:

•cert8.db للشهادات
•key3.db للمفاتيح
•secmod.db لمعلومات وحدة PKCS #11

ومع ذلك، فإن BerkeleyDB لديها قيود على الأداء، مما يمنع استخدامها بسهولة بواسطة تطبيقات متعددة في وقت واحد. تتمتع NSS ببعض المرونة التي تسمح للتطبيقات باستخدام محرك قاعدة بياناتها الخاص والمستقل مع الاحتفاظ بقاعدة بيانات مشتركة والتغلب على مشاكل الوصول. ومع ذلك، تتطلب NSS المزيد من المرونة لتوفير قاعدة بيانات أمنية مشتركة حقًا.

في عام 2009، قدمت NSS مجموعة جديدة من قواعد البيانات التي هي قواعد بيانات SQLite بدلاً من BerkleyDB. توفر قواعد البيانات الجديدة هذه المزيد من إمكانية الوصول والأداء:

•cert9.db للشهادات
•key4.db للمفاتيح
•pkcs11.txt، وهو عبارة عن قائمة بجميع وحدات PKCS #11 الموجودة في دليل فرعي جديد في دليل قواعد بيانات الأمان

نظرًا لأن قواعد بيانات SQLite مصممة للمشاركة، فهذه هي المشتركة نوع قاعدة البيانات. يُفضل نوع قاعدة البيانات المشتركة؛ يتم تضمين التنسيق القديم للتوافق مع الإصدارات السابقة.

بشكل افتراضي، تفترض الأدوات (certutil و pk12util و modutil) أن قواعد بيانات الأمان المقدمة تستخدم نوع SQLite. يجب تحديد قواعد البيانات القديمة يدويًا باستخدام البادئة dbm: مع دليل الأمان المقدم. على سبيل المثال:

modutil -create -dbdir dbm:/home/my/sharednssdb

لتعيين نوع قاعدة البيانات القديم كنوع افتراضي للأدوات، قم بتعيين متغير البيئة NSS_DEFAULT_DB_TYPE إلى dbm:

export NSS_DEFAULT_DB_TYPE="dbm"

يمكن إضافة هذا السطر إلى ملف ~/.bashrc لجعل التغيير دائمًا للمستخدم.

•https://wiki.mozilla.org/NSS_Shared_DB_Howto

للاطلاع على مسودة هندسية للتغييرات في قواعد بيانات NSS المشتركة، راجع wiki لمشروع NSS:

•https://wiki.mozilla.org/NSS_Shared_DB
