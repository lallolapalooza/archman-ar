الوصف

systemd-dissect هي أداة لفحص والتفاعل مع صور أقراص نظام التشغيل، وتحديداً صور الأقراص القابلة للاكتشاف (DDIs). تدعم أربعة عمليات مختلفة:

1. عرض معلومات عامة حول صورة نظام التشغيل، بما في ذلك بيانات os-release(5) الخاصة بالصورة، معرف الجهاز، معلومات الأقسام، والمزيد.
2. تحميل صورة نظام التشغيل إلى دليل محلي. في هذا الوضع، ستقوم بتشريح صورة نظام التشغيل وتحميل الأقسام المضمنة وفقًا لتعييناتها إلى دليل وربما أدلة فرعية.
3. إلغاء تحميل صورة نظام التشغيل من دليل محلي. في هذا الوضع، ستقوم بإلغاء تحميل الأقسام المحملة بشكل متكرر وإزالة جهاز الحلقة الأساسي، بما في ذلك جميع أجهزة الأقسام الفرعية.
4. نسخ الملفات والأدلة من وإلى صورة نظام التشغيل.

قد تعمل الأداة على ثلاثة أنواع من صور أنظمة التشغيل:

1. صور أقراص نظام التشغيل التي تحتوي على غلاف جدول أقسام GPT، مع وضع علامات على الأقسام وفقًا لـ مواصفات الأقسام القابلة للاكتشاف[1].
2. صور أقراص نظام التشغيل التي تحتوي على نظام ملفات عادي فقط بدون جدول أقسام مغلف. (يُفترض أن نظام الملفات هذا هو نظام الملفات الجذر لنظام التشغيل.)
3. صور أقراص نظام التشغيل التي تحتوي على جدول أقسام GPT أو MBR، مع قسم واحد فقط. (يُفترض أن هذا القسم يحتوي على نظام الملفات الجذر لنظام التشغيل.)

قد تستخدم صور أنظمة التشغيل أي نوع من أنظمة الملفات المدعومة في لينكس. بالإضافة إلى ذلك، قد تستفيد من تشفير قرص LUKS، وتحتوي على معلومات تكامل Verity. لاحظ أن صور أنظمة التشغيل المؤهلة قد يتم تشغيلها باستخدام الخيار --image= الخاص بـ systemd-nspawn(1)، ويمكن استخدامها كنظام ملفات جذر لخدمة النظام باستخدام إعداد ملف الوحدة RootImage=، راجع systemd.exec(5).

لاحظ أن جدول الأقسام المعروض عند استدعائه بدون مفتاح أمر (كما هو مدرج أدناه) لا يعرض بالضرورة جميع الأقسام المضمنة في الصورة، بل فقط الأقسام التي يتم فهمها واعتبارها جزءًا من صورة قرص نظام التشغيل. على وجه التحديد، يتم تجاهل الأقسام من أنواع غير معروفة، وكذلك الأقسام المكررة (أي أكثر من واحد لكل نوع قسم)، وكذلك أقسام الجذر و/usr/ التي لا تتوافق بنيتها مع النظام المحلي. بعبارة أخرى: ستعرض هذه الأداة ما تتعامل معه عند تحميل الصورة. لعرض القائمة الكاملة للأقسام، استخدم أداة مثل fdisk(8).

قد يتم استدعاء الأمر systemd-dissect باسم mount.ddi وفي هذه الحالة ينفذ واجهة "المساعد الخارجي" الخاصة بـ mount(8). هذا يضمن أنه يمكن تحميل صور الأقراص المتوافقة مع systemd-dissect مباشرة بواسطة mount و fstab(5). للتفاصيل، انظر أدناه.

بدلاً من مسار الصورة، يمكن تحديد دليل بصيغة ".v/" المتسلسلة، راجع systemd.v(7) للتفاصيل.

الأوامر

إذا لم يتم تمرير أي من مفاتيح الأوامر المدرجة أدناه، فسيتم فتح صورة القرص المحددة وعرض معلومات عامة حول الصورة والأقسام الموجودة واستخداماتها.

--mount, -m

تحميل صورة نظام التشغيل المحددة إلى الدليل المحدد. سيقوم هذا بتشريح الصورة، وتحديد نظام الملفات الجذر لنظام التشغيل — وكذلك ربما أقسام أخرى — وتحميلها إلى الدليل المحدد. إذا كانت صورة نظام التشغيل تحتوي على أقسام متعددة تحمل علامة مواصفات الأقسام القابلة للاكتشاف[1]، فسيتم إنشاء عمليات تحميل متداخلة متعددة. يتوقع هذا الأمر وسيطتين: مسار إلى ملف صورة، ومسار إلى دليل حيث سيتم تحميل الصورة.

لإلغاء تحميل صورة نظام تشغيل تم تحميلها بهذه الطريقة، استخدم عملية --umount.

عندما تحتوي صورة نظام التشغيل على أنظمة ملفات مشفرة بـ LUKS أو محمية بالتكامل Verity، يتم إعداد وحدات تخزين مناسبة ووضع علامات عليها للتفكيك التلقائي عند إلغاء تحميل الصورة.

قد يتم تحديد صورة نظام التشغيل إما كمسار إلى صورة نظام تشغيل مخزنة في ملف عادي أو قد تشير إلى عقدة جهاز كتلة (في الحالة الأخيرة، يجب أن يكون جهاز الكتلة هو الجهاز "الكامل"، أي ليس جهاز قسم). (الأوامر الأخرى المدعومة الموصوفة هنا تدعم هذا أيضًا.)

يتم التحقق من جميع أنظمة الملفات المحملة باستخدام تطبيق fsck(8) المناسب في وضع الإصلاح التلقائي، ما لم يتم إيقافه صراحةً (--fsck=no) أو تم طلب تشغيل للقراءة فقط (--read-only).

لاحظ أن هذه الوظيفة متاحة أيضًا في mount(8) عبر أمر مثل mount -t ddi myimage.raw targetdir/، وكذلك في fstab(5). للتفاصيل، انظر أدناه.

سيتم إلغاء تحميل جميع الأقسام المحملة بشكل متكرر، وسيتم إزالة جهاز الحلقة الأساسي، مع جميع أجهزة الأقسام الفرعية الخاصة به.

--attach

ربط صورة القرص المحددة بجهاز كتلة حلقة مخصص تلقائيًا، وطباعة المسار إلى جهاز كتلة الحلقة إلى المخرج القياسي. هذا مشابه لاستدعاء losetup --find --show --partscan، ولكنه سيتحقق من الصورة كـ DDI قبل الربط، ويستنتج حجم القطاع الصحيح لاستخدامه تلقائيًا. علاوة على ذلك، يضمن إنشاء أجهزة الكتل لكل قسم قبل العودة ويحاول تمكين وضع الإدخال/الإخراج المباشر، إن أمكن. يأخذ مسارًا إلى ملف صورة قرص.

systemd-dissect(1) — systemd manual

NAME

systemd-dissect - inspect and mount file system images

SYNOPSIS

systemd-dissect [-h] [--image=IMAGE] [--mount] [--mount-root=DIR] [--loop-ref=NAME] [--loop-ref-auto] [--read-only] [--discard=MODE] [--wipe-space] [--write-sparse] [--make-archive] [--with] [--mtree] [--mtree-hash=no] [--discover] [--system] [--user] [--all] [--quiet] [-q] [--image-policy=POLICY] [--image-filter=FILTER] [--no-pager] [--no-legend] [--json=MODE] [-- ARG...

DESCRIPTION

systemd-dissect can be used to inspect and mount various kinds of disk image formats, including flat disk images, partitioned disk images, and tarballs, archives or directories that are treated as OS images (see systemd.exec(5) for details). It aims to provide a unified interface for accessing the file systems contained within such images.

It is particularly useful for inspecting and mounting read-only container or OS images, for instance for debugging purposes or for extracting specific files or directories.

The command may be invoked in several ways:

  • As a standalone tool to inspect and mount images.

  • Via the mount(8) helper interface if symlinked to /sbin/mount.ddi. See section INVOCATION AS /SBIN/MOUNT.DDI below.

The tool understands several image formats. The most common ones are:

  • Flat disk images (e.g. .raw, .img). These may contain a partition table or be unpartitioned.

  • Tarballs (e.g. .tar, .tar.gz, .tar.xz). These are treated as OS images and may contain file system images or raw file systems.

  • Directory trees. These are treated as OS images.

The tool determines the image format automatically based on the file extension or by inspecting the file content.

If the image contains multiple file systems (e.g. due to a partition table), systemd-dissect will attempt to mount all of them. By default, it tries to mount them read-only.

COMMANDS

--mount
Mount the discovered file systems from the image. By default, the file systems are mounted under a temporary directory, which is then printed to standard output. This directory is automatically cleaned up when the process exits. Use --mount-root= to specify a different mount point base directory. If --mount-root= is used, the file systems will be mounted under DIR/IMAGE/... where IMAGE is the base name of the image file.

When mounting, the file systems are automatically assigned a suffix based on their partition GUID or partition number, e.g. /tmp/systemd-dissect.XXXXXX/foo.raw/PARTUUID=.../. If the image has no partition table or it is flat, the file system is mounted directly under DIR/IMAGE/.

This command is implied by /sbin/mount.ddi invocation.

--with
Execute the command specified in the remaining arguments (e.g. tar cz .) within the mounted file system(s) of the image. All file systems discovered within the image are mounted as described under --mount. The command is then executed, and after it finishes, all mounted file systems are unmounted and cleaned up.
--make-archive
Create a tar archive of the file system(s) within the image. The archive is written to the path specified in the next argument. If no argument is given, the archive is written to standard output. This is equivalent to using --with tar cz -.
--discover
List the file systems contained within the image, without mounting them. This is the default action if no other command is specified. The output format is similar to lsblk(8).

OPTIONS

The following options are understood:

--image-policy=POLICY
Takes an image policy string as argument, as per systemd.image-policy(7). The policy is enforced when operating on the disk image specified via --image=, see above. If not specified, defaults to the "*" policy, i.e. all recognized file systems in the image are used.
--image-filter=FILTER
Takes an image filter string as argument, as per systemd.image-filter(7). The filter is taken into consideration when operating on the disk image specified via --image=, see above. If not specified no filtering is applied.
--mount-root=DIR
Specifies the base directory under which to mount the file systems when --mount or --with is used. If not specified, a temporary directory is created.
--read-only
Mount the file systems read-only. This is the default unless specific options request write access (e.g. --discard=none).
--discard=MODE
Controls discard behavior for the underlying storage device. Expects one of "none", "auto", "discard", or "disabled".

If set to "none" (the default), no discard operations are performed.

If set to "auto", discard operations are performed only if the underlying block device supports them and they are not explicitly disabled.

If set to "disabled", discard operations are explicitly disabled.

If set to "discard", discard operations are explicitly enabled. This may be useful when dealing with SSDs or other thin-provisioned storage.

Added in version 254.

--wipe-space
When creating a new image file (e.g. with --make-archive and writing to stdout), this option ensures that unused space within the image is discarded, potentially reducing the size of the output file. This is similar to the --discard=discard option for mounts, but applied during image creation.
--write-sparse
When creating a new image file, this option ensures that the output file is created sparsely, meaning that blocks containing only zeros are not written to the disk. This is the default behavior for images created by this tool unless --wipe-space is used.
--mtree
When used with --discover, generates an mtree(5) compatible listing of the file system contents. This includes file types, permissions, and timestamps. File hashes may be included depending on the --mtree-hash= option.
--loop-ref=NAME
Sets the kernel loopback device's .lo_file_name field to the specified arbitrary string NAME. This string is used for identifying the loop device via the /dev/disk/by-loop-ref/ symlink directory.

The kernel accepts arbitrary free-form strings for this field, this is not enforced to be a path or filename referencing the backing file. Accepts arbitrary strings up to a length of 63 characters. This sets the kernel's .lo_file_name field for the block device. Note this is distinct from the /sys/class/block/loopX/loop/backing_file attribute file that always reports a path referring to the actual backing file. The latter is subject to mount namespace translation, the former is not.

This setting is particularly useful in combination with the --attach command, as it allows later referencing the allocated loop device via /dev/disk/by-loop-ref/... symlinks. Example: first, set up the loopback device via systemd-dissect attach --loop-ref=quux foo.raw, and then reference it in a command via the specified filename: cfdisk /dev/disk/by-loop-ref/quux.

Added in version 254.

--loop-ref-auto
Similar to --loop-ref=, but automatically derive the reference string from the specified backing filename, truncating it if necessary.

Added in version 258.

--mtree-hash=no
If combined with --mtree, turns off inclusion of file hashes in the mtree output. This makes the --mtree faster when operating on large images.

Added in version 254.

--system, --user
When used together with --discover controls whether to search for images installed system-wide or in the user's directories in $HOME. If neither switch is specified, will search within both scopes.

Added in version 258.

--all
If combined with --discover, also shows images that start with a dot, i.e. hidden images.

Added in version 258.

--quiet, -q
If combined with --attach, suppresses output of the used loopback block device path.

Added in version 258.

--no-pager
Do not pipe output into a pager.
--no-legend
Do not print the legend, i.e. column headers and the footer with hints.
--json=MODE
Shows output formatted as JSON. Expects one of "short" (for the shortest possible output without any redundant whitespace or line breaks), "pretty" (for a pretty version of the same, with indentation and line breaks) or "off" (to turn off JSON output, the default).

.

EXIT STATUS

On success, 0 is returned, a non-zero failure code otherwise. If the --with command is used the exit status of the invoked command is propagated.

INVOCATION AS /SBIN/MOUNT.DDI

systemd-dissect may be symlinked to /sbin/mount.ddi. If invoked through that it implements mount(8)'s "external helper" interface for the (pseudo) file system type "ddi". This means conformant disk images may be mounted directly via

# mount -t ddi myimage.raw targetdir/

in a fashion mostly equivalent to:

# systemd-dissect --mount myimage.raw targetdir/

Note that since a single DDI may contain multiple file systems it should later be unmounted with umount -R targetdir/, for recursive operation.

This functionality is particularly useful to mount DDIs automatically at boot via simple /etc/fstab entries. For example:

/path/to/myimage.raw /images/myimage/ ddi defaults 0 0

When invoked this way the mount options "ro", "rw", "discard", "nodiscard" map to the corresponding options listed above (i.e. --read-only, --discard=auto, --discard=disabled). Mount options are not generically passed on to the file systems inside the images.

EXAMPLES

Example 1. Generate a tarball from an OS disk image (--with)

# systemd-dissect --with foo.raw tar cz . >foo.tar.gz

or alternatively just:

Example 2. Generate a tarball from an OS disk image (--make-archive)

# systemd-dissect --make-archive foo.raw foo.tar.gz
