NAME

Moo - modern, simple, fast, and correct object construction

SYNOPSIS

    package MyClass;
    use Moo;

    has 'foo' => (
        is => 'rw',
        isa => 'Int',
        required => 1,
    );

    has 'bar' => (
        is => 'ro',
        default => sub { [] },
    );

    sub BUILD {
        my $self = shift;
        # ... initialization logic ...
    }

    sub method {
        my $self = shift;
        # ...
    }

    package main;
    my $instance = MyClass->new( foo => 42 );
    $instance->foo( 100 ); # ok, because is => 'rw'
    # $instance->bar( 100 ); # NO - error: bar is read-only!

DESCRIPTION

Moo is a toolkit for building Perl objects. It aims to be simpler than Moose, while still providing a large subset of its functionality.

Moo provides an object system that is based on roles and attributes. It does not provide a metaroom, and it does not try to provide a full implementation of the Perl object system. Instead, it provides a minimal, but complete, object system that is easy to use and understand.

WHY MOO EXISTS

Moose is a powerful and flexible object system, but it is also complex. Moo was created to provide a simpler alternative for those who do not need the full power of Moose. Moo is designed to be easy to learn and use, and it is also very fast.

MOO AND MOOSE

Moo is a subset of Moose. If you know Moose, you will find Moo very familiar. Many Moose features are available in Moo, but some are not. Moo does not have a metaroom, and it does not have the same level of introspection as Moose. However, Moo is much faster than Moose, and it is also much simpler.

You can use Moo and Moose together in the same project. Moo objects can inherit from Moose objects, and vice versa. This allows you to gradually migrate your Moose code to Moo, or to use Moo for new projects while still maintaining compatibility with existing Moose code.

MOO AND CLASS::XSACCESSOR

Moo is a modern alternative to Class::Accessor and its various extensions. Moo provides a more powerful and flexible way to define attributes, and it also provides a number of features that are not available in Class::Accessor, such as support for roles and immutability.

Moo is also generally faster than Class::Accessor, especially for classes with a large number of attributes.

MOO VERSUS ANY::MOOSE

Any::Moose is a compatibility layer that allows you to use Moose or Moo depending on what is available. Moo is a direct implementation of a subset of Moose, and it is generally faster and simpler than Any::Moose.

If you are starting a new project, it is generally recommended to use Moo directly. If you need to maintain compatibility with older code that uses Any::Moose, then you can continue to use it.

PUBLIC METHODS

new
Creates a new instance of the class. Takes a hash of attribute values as arguments.
meta
Returns the meta object for the class. This is used for introspection and other advanced features.

LIFECYCLE METHODS

BUILDARGS
A subroutine that is called before the constructor. It can be used to modify the arguments passed to the constructor.
BUILD
A subroutine that is called after the object has been created and initialized. It can be used to perform additional initialization tasks.
DEMOLISH
A subroutine that is called before the object is destroyed. It can be used to clean up resources.

IMPORTED SUBROUTINES

When you use Moo;, the following subroutines are imported into your package's namespace:

has
Declares an attribute.
with
Applies roles to the class.
extends
Specifies a parent class.
does
Specifies a role that the class implements.

SUB QUOTE AWARE

Moo is designed to be quote-aware. This means that you can use anonymous subroutines (closures) as attribute defaults or validation callbacks without worrying about them being executed at compile time.

    has 'counter' => (
        is => 'rw',
        default => sub { 0 },
    );

This is in contrast to older object systems that would execute anonymous subroutines at compile time, leading to unexpected behavior.

CLEANING UP IMPORTS

If you want to avoid importing all of Moo's subroutines into your package's namespace, you can use the :all tag:

    use Moo ();
    use Moo::Role; # For roles

    package MyClass;
    use Moo;
    use Moo::Role; # For roles

    has 'foo';

    package main;
    MyClass->new; # ok

    # has_attribute('foo'); # Not exported by default

Alternatively, you can import only the subroutines you need:

    package MyClass;
    use Moo 'has';
    use Moo::Role 'Role'; # For roles

    has 'foo';
    # Role; # Available if imported from Moo::Role

    package main;
    MyClass->new; # ok

If you're using MooseX::AttributeShortcuts, you can use it with Moo:

The nearest Moose invocation would be:


package MyClass;
use Moose;
use warnings FATAL => "all";
use MooseX::AttributeShortcuts;


or, if you're inheriting from a non-Moose class,


package MyClass;
use Moose;
use MooseX::NonMoose;
use warnings FATAL => "all";
use MooseX::AttributeShortcuts;

META OBJECT

There is no meta object. If you need this level of complexity you need Moose - Moo is small because it explicitly does not provide a metaprotocol. However, if you load Moose, then

Class::MOP::class_of($moo_class_or_role)

will return an appropriate metaclass pre-populated by Moo.

IMMUTABILITY

Finally, Moose requires you to call

__PACKAGE__->meta->make_immutable;

at the end of your class to get an inlined (i.e. not horribly slow) constructor. Moo does it automatically the first time ->new is called on your class. ("make_immutable" is a no-op in Moo to ease migration.)

An extension MooX::late exists to ease translating Moose packages to Moo by providing a more Moose-like interface.

COMPATIBILITY WITH OLDER PERL VERSIONS

Moo is compatible with perl versions back to 5.6. When running on older versions, additional prerequisites will be required. If you are packaging a script with its dependencies, such as with App::FatPacker, you will need to be certain that the extra prerequisites are included.

MRO::Compat
Required on perl versions prior to 5.10.0.
Devel::GlobalDestruction
Required on perl versions prior to 5.14.0.
