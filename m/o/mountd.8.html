الاسم

rpc.mountd - خادم تركيب NFS

الملخص

/usr/sbin/rpc.mountd [خيارات]

الوصف

ينفذ الخادم rpc.mountd جانب الخادم من بروتوكول NFS MOUNT، وهو بروتوكول جانبي لـ NFS الإصدار 2 [RFC1094] والإصدار 3 [RFC1813]. كما أنه يستجيب لطلبات نواة Linux لمصادقة العملاء ويوفر تفاصيل حول أذونات الوصول.

يحتفظ خادم NFS (nfsd) بذاكرة تخزين مؤقت لمعلومات المصادقة والتفويض المستخدمة لتحديد مصدر كل طلب، ثم ما هي أذونات الوصول التي يمتلكها هذا المصدر لأي نظام ملفات محلي. عندما لا توجد المعلومات المطلوبة في الذاكرة المؤقتة، يرسل الخادم طلبًا إلى mountd لملء المعلومات المفقودة. يستخدم Mountd جدول معلومات مخزن في /var/lib/nfs/etab ويتم صيانته بواسطة exportfs(8)، ربما بناءً على محتويات exports(5)، للاستجابة لكل طلب.

تركيب أنظمة ملفات NFS المصدرة

يحتوي بروتوكول NFS MOUNT على عدة إجراءات. أهم هذه الإجراءات هي MNT (تركيب تصدير) و UMNT (فك تركيب تصدير).

يحتوي طلب MNT على وسيطتين: وسيطة صريحة تحتوي على مسار الدليل الجذر للتصدير المراد تركيبه، ووسيطة ضمنية هي عنوان IP للمرسل.

عند تلقي طلب MNT من عميل NFS، يتحقق rpc.mountd من كل من المسار وعنوان IP للمرسل مقابل جدول التصدير الخاص به. إذا كان مسموحًا للمرسل بالوصول إلى التصدير المطلوب، يعيد rpc.mountd مقبض ملف NFS لدليل الجذر الخاص بالتصدير إلى العميل. يمكن للعميل بعد ذلك استخدام مقبض الجذر وملفات طلبات NFS LOOKUP للتنقل في بنية دليل التصدير.

ملف rmtab

يقوم الخادم rpc.mountd بتسجيل كل طلب MNT ناجح عن طريق إضافة إدخال إلى ملف /var/lib/nfs/rmtab. عند تلقي طلب UMNT من عميل NFS، يقوم rpc.mountd ببساطة بإزالة الإدخال المطابق من /var/lib/nfs/rmtab، طالما أن قائمة التحكم في الوصول لهذا التصدير تسمح للمرسل بالوصول إلى التصدير.

يمكن للعملاء اكتشاف قائمة أنظمة الملفات التي يقوم خادم NFS بتصديرها حاليًا، أو قائمة العملاء الآخرين الذين قاموا بتركيب تصديراته، باستخدام الأمر showmount(8). يستخدم showmount(8) إجراءات أخرى في بروتوكول NFS MOUNT للإبلاغ عن معلومات حول أنظمة ملفات الخادم المصدرة.

لاحظ، مع ذلك، أنه لا يوجد ضمان كبير لصحة محتويات /var/lib/nfs/rmtab. قد يستمر العميل في الوصول إلى تصدير حتى بعد استدعاء UMNT. إذا أعيد تشغيل العميل دون إرسال طلب UMNT، تظل هناك إدخالات قديمة لهذا العميل في /var/lib/nfs/rmtab.

تركيب أنظمة الملفات مع NFSv4

لا يستخدم الإصدار 4 (والإصدارات الأحدث) من NFS بروتوكول NFS MOUNT منفصلاً. بدلاً من ذلك، يتم التركيب باستخدام طلبات NFS العادية التي يتعامل معها خادم NFS في نواة Linux (nfsd). نتيجة لذلك، لا يتم تحديث /var/lib/nfs/rmtab ليعكس أي نشاط NFSv4.

الخيارات

-d kind or --debug kind
تشغيل التصحيح. الأنواع الصالحة هي: all، auth، call، general، و parse.
-l or --log-auth
تمكين تسجيل الردود على طلبات المصادقة والوصول من nfsd. يتم تخزين كل رد مؤقتًا بواسطة النواة لمدة 30 دقيقة (أو كما تم تعيينه بواسطة --ttl أدناه)، وسيتم تحديثه بعد 15 دقيقة (نصف وقت ttl) إذا ظل العميل المعني نشطًا. لاحظ أن -l يعادل -d auth ويمكن تمكينه في /etc/nfs.conf مع "debug = auth" في قسم [mountd].
سيقوم rpc.mountd دائمًا بتسجيل ردود المصادقة على طلبات MOUNT عند استخدام NFSv3، ولكن للحصول على سجلات مماثلة لـ NFSv4، يلزم هذا الخيار.
-i or --cache-use-ipaddr
عادةً ما تتم مطابقة كل عنوان IP للعميل مع كل معرف مضيف (اسم، حرف بدل، netgroup، إلخ) موجود في /etc/exports ويتم تكوين هوية مجمعة من جميع المعرفات المتطابقة. غالبًا ما يتم ربط العديد من العملاء بنفس الهوية المجمعة، لذا فإن إجراء هذه المطابقة يقلل من عدد تفاصيل الوصول المميزة التي تحتاج النواة إلى تخزينها. يؤدي تحديد الخيار -i إلى منع هذه المطابقة، بحيث يتم طلب الوصول إلى كل نظام ملفات وتخزينه مؤقتًا بشكل منفصل لكل عنوان IP للعميل. يمكن أن يؤدي القيام بذلك إلى زيادة العبء على تحديث الذاكرة المؤقتة قليلاً، ولكنه قد يجعل رسائل السجل الناتجة عن الخيار -l أسهل في القراءة.
-T or --ttl
توفير وقت للبقاء (TTL) للمعلومات المخزنة مؤقتًا المقدمة إلى النواة. تطلب النواة عادةً تحديثًا إذا كانت المعلومات مطلوبة بعد انتهاء نصف هذا الوقت. يؤدي زيادة الرقم المقدم، بالثواني، إلى تقليل معدل طلبات تحديث الذاكرة المؤقتة، وهذا ملحوظ بشكل خاص عند تسجيل هذه الطلبات باستخدام -l. ومع ذلك، فإن الزيادة تعني أيضًا أن التغييرات في تعيينات اسم المضيف إلى عناوين قد تستغرق وقتًا أطول لملاحظتها. TTL الافتراضي هو 1800 (30 دقيقة).
-F or --foreground
التشغيل في المقدمة (لا تقم بتشغيل كخادم).
-h or --help
عرض رسالة الاستخدام.
-o num or --descriptors num
تعيين الحد الأقصى لعدد واصفات الملفات المفتوحة إلى num. الافتراضي هو ترك الحد دون تغيير.
-N mountd-version or --no-nfs-version mountd-version
يمكن استخدام هذا الخيار لطلب عدم عرض rpc.mountd لإصدارات معينة من NFS. يمكن للإصدار الحالي من rpc.mountd دعم كل من NFS الإصدار 2 و 3 و 4. إذا كان يجب عدم عرض أي من هذه الإصدارات، فيجب استدعاء rpc.mountd بالخيار --no-nfs-version <vers>.
-n or --no-tcp
لا تعلن عن TCP للتركيب.
-p num or -P num or --port num
يحدد رقم المنفذ المستخدم لمقابسلات مستمع RPC. إذا لم يتم تحديد هذا الخيار، فسيحاول rpc.mountd استشارة /etc/services، وإذا نجح الحصول على المنفذ، فسيقوم بتعيين نفس المنفذ لجميع مقابسلات المستمع، وإلا فإنه يختار منفذًا عشوائيًا لكل مقبس مستمع.
يمكن استخدام هذا الخيار لإصلاح قيمة المنفذ لمستمعات rpc.mountd عندما يجب أن تمر طلبات NFS MOUNT عبر جدار حماية بين العملاء والخوادم.
-H prog or --ha-callout prog
تحديد برنامج استدعاء عالي التوفر. يتلقى هذا البرنامج استدعاءات لجميع طلبات MOUNT و UNMOUNT. هذا يسمح باستخدام rpc.mountd في بيئة NFS عالية التوفر (HA-NFS).
يتم تشغيل برنامج الاستدعاء مع 4 وسائط. الأول هو mount أو unmount اعتمادًا على سبب الاستدعاء. الثاني سيكون اسم العميل الذي يقوم بالتركيب. الثالث سيكون المسار الذي يقوم العميل بتركيبه. الأخير هو عدد التركيبات المتزامنة التي نعتقد أن العميل لديه لهذا المسار.
هذا الاستدعاء غير مطلوب مع النوى 2.6 والإصدارات الأحدث. بدلاً من ذلك، قم بتركيب نظام ملفات nfsd على /proc/fs/nfsd.
-s, --state-directory-path directory
تحديد دليل لوضع معلومات الحالة (etab و rmtab). إذا لم يتم تحديد هذا الخيار، فسيتم استخدام الافتراضي /var/lib/nfs.
-r, --reverse-lookup

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

mountd(8) - Arch Linux

NAME

mountd - NFS mount daemon

SYNOPSIS

rpc.mountd [ -d | --debug ] [ -h | --no-nfs-version ] [ -i | --manage-gids ] [ -l | --reverse-lookup ] [ -p port | --port port ] [ -n | --no-notify ] [ -s state-dir-path | --state-directory-path state-dir-path ] [ -t N | --num-threads N ] [ -u | --no-udp ] [ -V version | --nfs-version version ] [ -v | --version ] [ -g | --manage-gids ]

DESCRIPTION

The rpc.mountd daemon is part of the NFS server infrastructure. It is an RPC server that handles mount requests from NFS clients. When an NFS client wants to mount a filesystem from an NFS server, it sends an RPC request to rpc.mountd. rpc.mountd then checks the client's host name and IP address against the list of allowed clients specified in /etc/exports. If the client is allowed to mount the requested filesystem, rpc.mountd responds with the file handle of the exported filesystem.

The rpc.mountd daemon needs to be run in conjunction with rpc.nfsd, which handles the actual file operations (read, write, etc.) after the filesystem has been mounted.

OPTIONS

-d or --debug
Enable debugging messages. This is usually not needed unless you are debugging rpc.mountd itself.
-h or --no-nfs-version
Do not advertise NFS protocol versions other than the highest version supported by the kernel.
-i or --manage-gids
This option allows rpc.mountd to manage group IDs. When this option is enabled, rpc.mountd will accept requests from the kernel to map user IDs into lists of group IDs. This is useful for access control when the client might not be able to provide a complete list of group IDs due to NFS protocol limitations (maximum of 16 group IDs). This feature requires a Linux kernel version of at least 2.6.21.
-l or --reverse-lookup

rpc.mountd tracks IP addresses in the rmtab file. When a DUMP request is made (by someone running showmount -a, for instance), it returns IP addresses instead of hostnames by default. This option causes rpc.mountd to perform a reverse lookup on each IP address and return that hostname instead. Enabling this can have a substantial negative effect on performance in some situations.

-p port or --port port

Specifies the port on which rpc.mountd should listen for incoming RPC requests. If not specified, rpc.mountd will use the port assigned by the portmapper.

-n or --no-notify

Do not notify rpc.statd (the status monitor daemon) when rpc.mountd is started or stopped. This is typically used in highly available NFS configurations where rpc.statd is not used.

-s state-dir-path or --state-directory-path state-dir-path

Specifies the directory where rpc.mountd stores its state information, such as the list of currently mounted filesystems. The default is /var/lib/nfs.

-t N or --num-threads=N or --num-threads N

This option specifies the number of worker threads that rpc.mountd spawns. The default is 1 thread, which is probably enough. More threads are usually only needed for NFS servers which need to handle mount storms of hundreds of NFS mounts in a few seconds, or when your DNS server is slow or unreliable.

-u or --no-udp

Don't advertise UDP for mounting

-V version or --nfs-version version

This option can be used to request that rpc.mountd offer certain versions of NFS. The current version of rpc.mountd can support both NFS version 2 and the newer version 3.

-v or --version

Print the version of rpc.mountd and exit.

-g or --manage-gids

Accept requests from the kernel to map user id numbers into lists of group id numbers for use in access control. An NFS request will normally (except when using Kerberos or other cryptographic authentication) contains a user-id and a list of group-ids. Due to a limitation in the NFS protocol, at most 16 groups ids can be listed. If you use the -g flag, then the list of group ids received from the client will be replaced by a list of group ids determined by an appropriate lookup on the server. Note that the 'primary' group id is not affected so a newgroup command on the client will still be effective. This function requires a Linux Kernel with version at least 2.6.21.

CONFIGURATION FILE

Many of the options that can be set on the command line can also be controlled through values set in the [mountd] or, in some cases, the [nfsd] sections of the /etc/nfs.conf configuration file. Values recognized in the [mountd] section include manage-gids, cache-use-ipaddr, descriptors, port, threads, ttl, reverse-lookup, and state-directory-path, ha-callout which each have the same effect as the option with the same name.

The values recognized in the [nfsd] section include TCP, UDP, vers3, and vers4 which each have the same meaning as given by rpc.nfsd(8).

TCP_WRAPPERS SUPPORT

You can protect your rpc.mountd listeners using the tcp_wrapper library or iptables(8).

Note that the tcp_wrapper library supports only IPv4 networking.

Add the hostnames of NFS peers that are allowed to access rpc.mountd to /etc/hosts.allow. Use the daemon name mountd even if the rpc.mountd binary has a different name.

Hostnames used in either access file will be ignored when they can not be resolved into IP addresses. For further information see the tcpd(8) and hosts_access(5) man pages.

IPv6 and TI-RPC support

TI-RPC is a pre-requisite for supporting NFS on IPv6. If TI-RPC support is built into rpc.mountd, it attempts to start listeners on network transports marked 'visible' in /etc/netconfig. As long as at least one network transport listener starts successfully, rpc.mountd will operate.

FILES

/etc/exports
input file for exportfs, listing exports, export options, and access control lists
/var/lib/nfs/rmtab
table of clients accessing server's exports
