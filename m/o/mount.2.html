mount(2) System Calls Manual mount(2)

NAME

mount - mount filesystem

LIBRARY

Standard C library (libc, -lc)

SYNOPSIS

#include <sys/mount.h>
int mount(const char *source, const char *target,
          const char *filesystemtype, unsigned long mountflags,
          const void *_Nullable data);

DESCRIPTION

mount() attaches the filesystem specified by source (which is often a pathname referring to a device, but can also be the pathname of a directory or file, or a dummy string) to the location (a directory or file) specified by the pathname in target.

Appropriate privilege (Linux: the CAP_SYS_ADMIN capability) is required to mount filesystems.

Values for the filesystemtype argument supported by the kernel are listed in /proc/filesystems (e.g., "btrfs", "ext4", "jfs", "xfs", "vfat", "fuse", "tmpfs", "cgroup", "proc", "mqueue", "nfs", "cifs", "iso9660"). Further types may become available when the appropriate modules are loaded.

The data argument is interpreted by the different filesystems. Typically it is a string of comma-separated options understood by this filesystem. See mount(8) for details of the options available for each filesystem type. This argument may be specified as NULL, if there are no options.

A call to mount() performs one of a number of general types of operation, depending on the bits specified in mountflags. The choice of which operation to perform is determined by testing the bits set in mountflags, with the tests being conducted in the order listed here:

•
Remount an existing mount: mountflags includes MS_REMOUNT.
•
Create a bind mount: mountflags includes MS_BIND.
•
Change the propagation type of an existing mount: mountflags includes one of MS_SHARED, MS_PRIVATE, MS_SLAVE, or MS_UNBINDABLE.
•
Move an existing mount to a new location: mountflags includes MS_MOVE.
•
Create a new mount: mountflags includes none of the above flags.

Each of these operations is detailed later in this page. Further flags may be specified in mountflags to modify the behavior of mount(), as described below.

Additional mount flags

The list below describes the additional flags that can be specified in mountflags. Note that some operation types ignore some or all of these flags, as described later in this page.

MS_DIRSYNC (since Linux 2.5.19)
Make directory changes on this filesystem synchronous. (This property can be obtained for individual directories or subtrees using chattr(1).)
MS_LAZYTIME (since Linux 4.0)
Reduce on-disk updates of inode timestamps (atime, mtime, ctime) by maintaining these changes only in memory. The on-disk timestamps are updated only when:
•
the inode needs to be updated for some change unrelated to file timestamps;
•
the application employs fsync(2), syncfs(2), or sync(2);
•
an undeleted inode is evicted from memory; or
•
more than 24 hours have passed since the inode was written to disk.
This mount option significantly reduces writes needed to update the inode's timestamps, especially mtime and atime. However, in the event of a system crash, the atime and mtime fields on disk might be out of date by up to 24 hours.
Examples of workloads where this option could be of significant benefit include frequent random writes to preallocated files, as well as cases where the MS_STRICTATIME mount option is also enabled. (The advantage of combining MS_STRICTATIME and MS_LAZYTIME is that stat(2) will return the correctly updated atime, but the atime updates will be flushed to disk only in the cases listed above.)
MS_MANDLOCK
Permit mandatory locking on files in this filesystem. (Mandatory locking must still be enabled on a per-file basis, as described in fcntl(2).) Since Linux 4.5, this mount option requires the CAP_SYS_ADMIN capability and a kernel configured with the CONFIG_MANDATORY_FILE_LOCKING option. Mandatory locking has been fully deprecated in Linux 5.15, so this flag should be considered deprecated.
MS_NOATIME
Do not update access times for (all types of) files on this filesystem.
MS_NODEV
Do not allow access to devices (special files) on this filesystem.
MS_NODIRATIME
Do not update access times for directories on this filesystem. This flag provides a subset of the functionality provided by MS_NOATIME; that is, MS_NOATIME implies MS_NODIRATIME.
MS_NOEXEC
Do not allow programs to be executed from this filesystem.
MS_NOSUID
Do not honor set-user-ID and set-group-ID bits or file capabilities when executing programs from this filesystem. In addition, SELinux domain transitions require the permission nosuid_transition, which in turn needs also the policy capability nnp_nosuid_transition.
MS_RDONLY
Mount filesystem read-only.
MS_REC (since Linux 2.4.11)
Used in conjunction with MS_BIND to create a recursive bind mount, and in conjunction with the propagation type flags to recursively change the propagation type of all of the mounts in a subtree. See below for further details.
MS_RELATIME (since Linux 2.6.20)
When a file on this filesystem is accessed, update the file's last access time (atime) only if the current value of atime is less than or equal to the file's last modification time (mtime) or last status change time (ctime). This option is useful for programs, such as mutt(1), that need to know when a file has been read since it was last modified. Since Linux 2.6.30, the kernel defaults to the behavior provided by this flag (unless MS_NOATIME was specified), and the MS_STRICTATIME flag is required to obtain traditional semantics. In addition, since Linux 2.6.30, the file's last access time is always updated if it is more than 1 day old.
MS_SILENT (since Linux 2.6.17)

" - heading: Creating a bind mount content: "

If mountflags includes MS_BIND (available since Linux 2.4), then perform a bind mount. A bind mount makes a file or a directory subtree visible at another point within the single directory hierarchy. Bind mounts may cross filesystem boundaries and span chroot(2) jails.

\n

The filesystemtype and data arguments are ignored.

\n

The remaining bits (other than MS_REC, described below) in the mountflags argument are also ignored. (The bind mount has the same mount options as the underlying mount.) However, see the discussion of remounting above, for a method of making an existing bind mount read-only.

\n

By default, when a directory is bind mounted, only that directory is mounted; if there are any submounts under the directory tree, they are not bind mounted. If the MS_REC flag is also specified, then a recursive bind mount operation is performed: all submounts under the source subtree (other than unbindable mounts) are also bind mounted at the corresponding location in the target subtree.

" - heading: Changing the propagation type of an existing mount content: "

\n

The only other flags that can be specified while changing the propagation type are MS_REC (described below) and MS_SILENT (which is ignored).

\n

The source, filesystemtype, and data arguments are ignored.

MS_SLAVE

If this is a shared mount that is a member of a peer group that contains no other members, convert it to a private mount. Otherwise, the propagation type of the mount is left unchanged.
\n

" - heading: Moving a mount content: "

If mountflags contains the flag MS_MOVE (available since Linux 2.4.18), then move a subtree: source specifies an existing mount and target specifies the new location to which that mount is to be relocated. The move is atomic: at no point is the subtree unmounted.

\n

The remaining bits in the mountflags argument are ignored, as are the filesystemtype and data arguments.

" - heading: Creating a new mount content: "

If none of MS_REMOUNT, MS_BIND, MS_MOVE, MS_SHARED, MS_PRIVATE, MS_SLAVE, or MS_UNBINDABLE is specified in mountflags, then mount() performs its default action: creating a new mount. source specifies the source for the new mount, and target specifies the directory at which to create the mount point.

\n

The filesystemtype and data arguments are employed, and further bits may be specified in mountflags to modify the behavior of the call.

" - heading: RETURN VALUE content: "

On success, zero is returned. On error, -1 is returned, and errno is set to indicate the error.

تمت إضافة تعريفات MS_DIRSYNC، MS_MOVE، MS_PRIVATE، MS_REC، MS_RELATIME، MS_SHARED، MS_SLAVE، MS_STRICTATIME، و MS_UNBINDABLE إلى رؤوس glibc في glibc 2.12.

منذ Linux 2.4 يمكن تحميل نظام ملفات واحد في نقاط تحميل متعددة، ويمكن تكديس تحميلات متعددة على نفس نقطة التحميل.

قد يحتوي الوسيط mountflags على الرقم السحري 0xC0ED (MS_MGC_VAL) في أعلى 16 بت. (جميع الأعلام الأخرى التي تمت مناقشتها في الوصف تشغل الـ 16 بت المنخفضة من mountflags.) كان تحديد MS_MGC_VAL مطلوبًا قبل Linux 2.4، ولكن منذ Linux 2.4 لم يعد مطلوبًا ويتم تجاهله إذا تم تحديده.

تمت إعادة تسمية العلم الأصلي MS_SYNC إلى MS_SYNCHRONOUS في 1.1.69 عندما تمت إضافة MS_SYNC مختلفة إلى <mman.h>.

قبل Linux 2.4، فشلت محاولة تنفيذ برنامج له هوية مستخدم أو هوية مجموعة تم تعيينها على نظام ملفات تم تحميله بالعلم MS_NOSUID مع الخطأ EPERM. منذ Linux 2.4، تم تجاهل بتات هوية المستخدم وهويته مجموعة بصمت في هذه الحالة.

ملاحظات

مساحات أسماء التحميل

بدءًا من Linux 2.4.19، توفر Linux مساحات أسماء التحميل. مساحة اسم التحميل هي مجموعة التحميلات لنظام الملفات التي يمكن رؤيتها بواسطة عملية. يمكن (وعادة ما تكون) مساحات أسماء التحميل مشتركة بين عمليات متعددة، والتغييرات على مساحة الاسم (أي، التحميلات وإلغاء التحميلات) بواسطة عملية واحدة تكون مرئية لجميع العمليات الأخرى التي تشترك في نفس مساحة الاسم. (يمكن اعتبار وضع Linux قبل 2.4.19 على أنه مساحة اسم واحدة مشتركة بين كل عملية على النظام.)

تشترك العملية الفرعية التي تم إنشاؤها بواسطة fork(2) في مساحة اسم التحميل الخاصة بوالدتها؛ يتم الحفاظ على مساحة اسم التحميل عبر execve(2).

يمكن للعملية الحصول على مساحة اسم تحميل خاصة بها إذا: تم إنشاؤها باستخدام علم clone(2) CLONE_NEWNS، وفي هذه الحالة يتم تهيئة مساحة الاسم الجديدة الخاصة بها لتكون *نسخة* من مساحة اسم العملية التي استدعت clone(2)؛ أو تستدعي unshare(2) مع العلم CLONE_NEWNS، مما يتسبب في أن تحصل مساحة اسم التحميل الخاصة بالمستدعي على نسخة خاصة من مساحة الاسم التي كانت تشاركها سابقًا مع عمليات أخرى، بحيث تكون التحميلات وإلغاء التحميلات المستقبلية من قبل المستدعي غير مرئية للعمليات الأخرى (باستثناء العمليات الفرعية التي ينشئها المستدعي لاحقًا) والعكس صحيح.

لمزيد من التفاصيل حول مساحات أسماء التحميل، انظر mount_namespaces(7).

العلاقة الأبوية بين التحميلات

كل تحميل له تحميل أب. تحدد العلاقة الأبوية الشاملة لجميع التحميلات التسلسل الهرمي للدليل الواحد الذي تراه العمليات داخل مساحة اسم التحميل.

يتم تحديد أب التحميل الجديد عند إنشاء التحميل. في الحالة العادية، يكون أب التحميل الجديد هو تحميل نظام الملفات الذي يحتوي على الدليل أو الملف الذي يتم إرفاق التحميل الجديد به. في حالة تكديس تحميل جديد فوق تحميل موجود، يكون أب التحميل الجديد هو التحميل السابق الذي تم تكديسه في هذا الموقع.

/proc/pid/mounts و /proc/pid/mountinfo

يعرض الملف /proc/pid/mounts الخاص بنظام Linux قائمة التحميلات في مساحة اسم التحميل للعملية ذات المعرف المحدد. يعرض الملف /proc/pid/mountinfo معلومات أكثر عن التحميلات، بما في ذلك نوع الانتشار ومعلومات معرف التحميل التي تجعل من الممكن اكتشاف العلاقة الأبوية بين التحميلات. انظر proc(5) و mount_namespaces(7) للحصول على تفاصيل هذا الملف.

LIBRARY

System calls, Standard C library

SYNOPSIS

#include <sys/mount.h>

int mount(const char *source, const char *target, const char *filesystemtype, unsigned long mountflags, void *data);

int umount(const char *target);

int umount2(const char *target, int flags);

DESCRIPTION

The mount() system call is the modern way to establish a new file hierarchy mounted on the pathname target. The source argument specifies the object to be mounted, while target specifies the location in the filesystem hierarchy where the object will be mounted. The filesystemtype argument specifies the name of the filesystem type, e.g. "ext2", "nfs", "cifs", etc. The mountflags argument is a bit mask of the following flags:

MS_BIND
Create a bind mount. A bind mount makes a file or directory subtree available at another location. The contents of the source file or directory are visible at the target. The source and target must be directories. This flag is a super set of MS_REC.
MS_DIRSYNC
Synchronous directory updates on this filesystem.
MS_NODEV
Do not allow devices to be interpreted on this filesystem.
MS_NOEXEC
Do not allow program execution on this filesystem.
MS_NOSUID
Do not honor set-user-ID and set-group-ID bits on files on this filesystem.
MS_RDONLY
Mount filesystem read-only.
MS_REC
Recursively mount all of the filesystems specified by source and its subdirectories. This flag is a super set of MS_BIND.
MS_SILENT
Suppress any messages that the filesystem may want to print.
MS_SHARED
Mark the filesystem as shared.
MS_PRIVATE
Mark the filesystem as private.
MS_SLAVE
Mark the filesystem as slave.
MS_UNBINDABLE
Mark the filesystem as unbindable.

The data argument is filesystem-specific information, typically a string containing options. For example, for an NFS mount, data could be "addr=192.168.1.1,port=2049,protocol=udp".

The umount() and umount2() system calls detach the filesystem mounted on the pathname target from the file hierarchy. The flags argument to umount2() can be used to specify how the filesystem should be unmounted:

MNT_DETACH
Perform a lazy unmount. The filesystem is detached now; any subsequent references will fail with ENOENT until all references are released.
MNT_FORCE
Force unmount of a busy filesystem. This can lead to data loss.
MNT_EXPIRE
Mark the filesystem as expired.

If no flags are specified in umount2(), then the unmount will only succeed if the filesystem is not busy.

RETURN VALUE

On success, zero is returned. On failure, mount() and umount() return -1 and set errno to indicate the error.

ERRORS

EACCES
A loop device is needed for filesystem, but all loop devices are used.
EALREADY
A file system is already mounted on target.
EBUSY
target is busy. This is a possible error for umount().
EINVAL
source is not a block special file or source is an invalid block special file.
EINVAL
An invalid value was specified in mountflags.
ENAMETOOLONG
source or target too long.
ENODEV
filesystemtype not configured in the kernel.
ENOENT
A directory component in target does not exist, or target is an empty string.
ENOTBLK
source is not a block special file.
ENOTDIR
A component of target is not a directory.
ENXIO
The block device specified by source does not exist, or has been automaticallyЕ detac.
EPERM
We are not allowed to mount the filesystem.
EROFS
The filesystem is mounted read-only.
ENOMEM
Kernel memory allocation failed.
ENOSPC
The filesystem does not contain enough space to hold the new filesystem.
MS_BIND
EINVAL. A bind mount requires both source and target to be directories.
MS_BIND
ENOTDIR. source or target is not a directory.
MS_BIND
ENOENT. source or target does not exist.
MS_BIND
EPERM. Cannot bind mount an existing mount point.
MS_REC
EINVAL. A recursive bind mount requires both source and target to be directories.
MS_REC
ENOTDIR. source or target is not a directory.
MS_REC
ENOENT. source or target does not exist.
MS_REC
EPERM. Cannot recursively bind mount an existing mount point.

STANDARDS

These system calls are specific to Linux and were not present in older Unix systems. They are part of the POSIX standard.

HISTORY

The mount() and umount() system calls appeared in Linux 1.0. The umount2() system call was introduced in Linux 2.3.30.

NOTES

Only the superuser can mount filesystems. Users can be allowed to mount specific filesystems by the administrator by editing the /etc/fstab file. Bind mounts (MS_BIND) can be performed by unprivileged users if the filesystem is mounted with the MS_USER flag.

The source argument must be a valid path to a block device, network share, or other filesystem object. The target must be an existing directory.

The filesystemtype argument can be a string specifying the type of filesystem to be mounted. If it is NULL, the kernel will attempt to guess the filesystem type based on the contents of the source object.

The mountflags argument is a bitmask of options that control the behavior of the mount. See the Linux kernel documentation for a complete list of available flags.

The data argument is a pointer to a string containing filesystem-specific options. The format of this string depends on the type of filesystem being mounted.

The umount() system call is a legacy interface that is functionally equivalent to calling umount2() with no flags. It is recommended to use umount2() instead, as it provides more flexibility.

Unmounting a filesystem that is currently in use by one or more processes will generally fail with EBUSY, unless the MNT_FORCE flag is used with umount2(). Use of MNT_FORCE can lead to data loss and should be avoided if possible.

The MS_BIND flag allows a subtree to be mounted on another location. This is useful for situations where you want to make a directory or file available in a different part of the filesystem hierarchy without actually moving it.

The MS_REC flag allows for recursive mounting of bind mounts. This means that if you bind mount a directory, all of its contents (including subdirectories and their contents) will also be bind mounted.

Mount namespace operations (MS_SHARED, MS_PRIVATE, MS_SLAVE, MS_UNBINDABLE) allow for fine-grained control over how mounts propagate between namespaces. See mount_namespaces(7) for more details.
