mono-shlib-cop(1)

الحزمة: mono

التراخيص: GPL, LGPL2.1, MPL

mono-shlib-cop(1) دليل الأوامر العامة mono-shlib-cop(1)

الاسم

mono-shlib-cop - مدقق استخدام المكتبات المشتركة

ملخص

mono-shlib-cop [خيارات]* [اسم-ملف-التجميع]*

الخيارات

-p, --prefixes=بادئة
بادئات تثبيت Mono. هذا للعثور على $prefix/etc/mono/config. الافتراضي يعتمد على موقع mscorlib.dll، وعادة ما يكون صحيحًا.

الوصف

mono-shlib-cop هي أداة تفحص تجميعًا مدارًا تبحث عن استخدام خاطئ أو مشبوه للمكتبات المشتركة.

تأخذ الأداة اسم ملف تجميع واحد أو أكثر، وتقوم بفحص كل تجميع محدد.

الأخطاء التي يتم التحقق منها تشمل:

*
هل المكتبة المشتركة موجودة؟
*
هل الرمز المطلوب موجود داخل المكتبة المشتركة؟

التحذيرات التي يتم التحقق منها تشمل:

*
هل المكتبة المشتركة المستهدفة مكتبة مسماة؟ (ذات صلة فقط على أنظمة Unix، وليس Mac OS X أو Windows.)

بشكل عام، توجد فقط المكتبات المسماة مثل libc.so.6 على جهاز المستخدم، وستؤدي محاولات تحميل libc.so إلى System.DllNotFoundException. هناك ثلاثة حلول لهذا:

1.
تطلب من المستخدم تثبيت أي حزم -devel التي توفر المكتبة غير المسماة. هذا عادة ما يتطلب من المستخدم تثبيت عدد كبير من الحزم الإضافية، مما يعقد عملية التثبيت.
2.
استخدم اسمًا مسماة بالكامل في عبارات DllImport الخاصة بك. يتطلب هذا تعديل الكود المصدري الخاص بك وإعادة تجميعه كلما احتجت إلى استهداف إصدار مختلف من المكتبة المشتركة.
3.
توفير ملف assembly.config يحتوي على عناصر <dllmap/> لإعادة تعيين اسم المكتبة المشتركة المستخدمة بواسطة تجميعك إلى المكتبة المشتركة المسماة الفعلية الموجودة على نظام المستخدم. يوفر Mono عددًا من إدخالات <dllmap/> الموجودة مسبقًا، بما في ذلك تلك الخاصة بـ libc.so و libX11.so.

مثال

يحتوي الكود التالي على أمثلة للأخطاء والتحذيرات المذكورة أعلاه:

using System.Runtime.InteropServices; // for DllImport
class Demo {
	[DllImport ("bad-library-name")]
	private static extern void BadLibraryName ();
	[DllImport ("libc.so")]
	private static extern void BadSymbolName ();
	[DllImport ("libcap.so")]
	private static extern int cap_clear (IntPtr cap_p);
}
اسم مكتبة خاطئ
بافتراض أن المكتبة bad-library-name غير موجودة على جهازك، سيؤدي Demo.BadLibraryName إلى خطأ، لأنه يتطلب مكتبة مشتركة لا يمكن تحميلها. قد يكون هذا قابلاً للتجاهل؛ راجع BUGS
اسم رمز خاطئ
سيؤدي Demo.BadSymbolName إلى خطأ، لأن libc.so (المعاد تسميتها إلى libc.so.6 بواسطة ملف $prefix/etc/mono/config الخاص بـ mono) لا تحتوي على الدالة BadSymbolName
اعتماد مكتبة غير مسماة
بافتراض أن لديك الملف libcap.so، سيؤدي Demo.cap_clear إلى تحذير لأنه، على الرغم من أنه يمكن تحميل libcap.so، فقد لا تكون libcap.so موجودة على جهاز المستخدم (على FC2، /lib/libcap.so يتم توفيره بواسطة libcap-devel، ولا يمكنك افتراض أن المستخدمين النهائيين سيكون لديهم أي حزم -devel مثبتة).

إصلاح الكود

يعتمد الإصلاح على التحذير أو الخطأ:

أسماء مكتبات خاطئة
استخدم اسم مكتبة صالحًا في السمة DllImport، أو وفر إدخال <dllmap/> لإعادة تعيين اسم مكتبتك الموجودة إلى اسم مكتبة صالح.
أسماء رموز خاطئة
أشر إلى رمز موجود فعليًا في المكتبة المستهدفة.
اعتماد مكتبة غير مسماة
وفر إدخال <dllmap/> للإشارة إلى مكتبة مسماة بشكل صحيح، أو تجاهل التحذير (انظر BUGS).

إدخالات DLLMAP

يبحث Mono عن معلومات إعادة تعيين اسم-التجميع. على سبيل المثال، مع mcs.exe، سيقرأ Mono mcs.exe.config، ومع Mono.Posix.dll، سيقرأ Mono Mono.Posix.dll.config

الملف .config هو مستند XML يحتوي على قسم <configuration/> على المستوى الأعلى مع إدخالات <dllmap/> متداخلة، والتي تحتوي على سمات dll و target. يجب أن تحتوي سمة dll على نفس السلسلة المستخدمة في قيمة السمة DllImport، وتحدد سمة target المكتبة المشتركة التي يجب على mono تحميلها فعليًا في وقت التشغيل.

ملف .config نموذجي هو:

<configuration>
	<dllmap dll="gtkembedmoz" target="libgtkembedmoz.so" />
</configuration>

الأخطاء

*
يتم فحص إدخالات DllImport فقط؛ يتم تجاهل IL المحيط. نتيجة لذلك، إذا تم إجراء فحص في وقت التشغيل لاختيار المكتبة المشتركة التي سيتم استدعاؤها، فسيتم الإبلاغ عن خطأ على الرغم من أن المكتبة المحددة لا تستخدم أبدًا. ضع في اعتبارك هذا الكود: 
using System.Runtime.InteropServices; // for DllImport
class Beep {
	[DllImport ("kernel32.dll")]
	private static extern int Beep (int dwFreq, int dwDuration);
	[DllImport ("libcurses.so")]
	private static extern int beep ();
	public static void Beep ()
	{
		if (System.IO.Path.DirectorySeparatorChar == '\\') {
			Beep (750, 300);
		}
		else {
			beep ();
		}
	}
}
إذا تم تشغيل mono-shlib-cop على هذا التجميع، فسيتم الإبلاغ عن خطأ لاستخدام kernel32.dll، على الرغم من أن kernel32.dll لن تستخدم أبدًا على منصات Unix.
*
يقوم mono-shlib-cop حاليًا بفحص امتداد ملف المكتبة المشتركة فقط لتحديد ما إذا كان يجب إنشاء تحذير. سيؤدي امتداد .so دائمًا إلى إنشاء تحذير، حتى لو لم يكن .so رابطًا رمزيًا، ولم يتم توفيره في حزمة -devel، ولم تكن هناك مكتبة مشتركة مسماة (أمثلة محتملة تشمل /usr/lib/libtcl8.4.so, /usr/lib/libubsec.so, إلخ).

وبالتالي، فإن التحذيرات لأي مكتبات من هذا النوع غير مفيدة، وغير صحيحة.

لن تقوم Windows و Mac OS X بإنشاء تحذيرات أبدًا، حيث تستخدم هذه الأنظمة امتدادات مكتبات مشتركة مختلفة.
