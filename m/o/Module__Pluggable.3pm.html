Module__Pluggable(3pm)

الحزمة: perl-module-pluggable

التراخيص: PerlArtistic, GPL

Module::Pluggable(3) وثائق Perl المساهمة من المستخدم Module::Pluggable(3)

الاسم

Module::Pluggable - منح وحدتك تلقائيًا القدرة على امتلاك إضافات

الملخص

استخدام بسيط لـ Module::Pluggable -

package MyClass;
use Module::Pluggable;

ثم لاحقًا ...

use MyClass;
my $mc = MyClass->new();
# يعيد أسماء جميع الإضافات المثبتة تحت MyClass::Plugin::*
my @plugins = $mc->plugins();

مثال

لماذا قد ترغب في القيام بذلك؟ لنفترض أن لديك شيئًا يريد تمرير كائن إلى عدد من الإضافات المختلفة بالدور. على سبيل المثال، قد ترغب في استخراج البيانات الوصفية من كل بريد إلكتروني ترسله وتفعل شيئًا بها. الإضافات منطقية هنا لأنه يمكنك الاستمرار في إضافة محللات بيانات وصفية جديدة وستكون كل منطق ووصف لكل منها مكتفية ذاتيًا، ومن السهل إضافة معالجات جديدة دون تغيير الكود الأساسي. لهذا، قد تفعل شيئًا مثل ...

package Email::Examiner;
use strict;
use Email::Simple;
use Module::Pluggable require => 1;
sub handle_email {
    my $self  = shift;
    my $email = shift;
    foreach my $plugin ($self->plugins) {
        $plugin->examine($email);
    }
    return 1;
}

.. وستحصل جميع الإضافات على فرصة بالدور للنظر إليها.

يمكن توسيع هذا بسهولة بحيث يمكن للإضافات حفظ البريد الإلكتروني في مكان ما، وبعد ذلك لا ينبغي لأي إضافة أخرى محاولة القيام بذلك. فقط اجعل الأمر بحيث تعيد الطريقة "examine" القيمة 1 إذا كانت قد حفظت البريد الإلكتروني في مكان ما. قد ترغب أيضًا في أن تكون حذرًا وتتحقق مما إذا كانت الإضافة تحتوي على طريقة "examine".

foreach my $plugin ($self->plugins) {
    next unless $plugin->can('examine');
    last if     $plugin->examine($email);
}

وهكذا. السماء هي الحد الأقصى.

الوصف

يوفر طريقة بسيطة ولكن، نأمل، قابلة للتوسيع لوجود 'إضافات' لوحدتك. من الواضح أن هذا لن يكون الحل النهائي، ولكنه يعمل بالنسبة لي.

في الأساس، كل ما يفعله هو تصدير طريقة إلى مساحة اسمك تبحث في مسار بحث لملفات .pm وتحولها إلى أسماء فئات.

اختياريًا، يقوم بإنشاء هذه الفئات لك.

استخدام متقدم

بدلاً من ذلك، إذا كنت لا ترغب في استخدام 'plugins' كطريقة ...

package MyClass;
use Module::Pluggable sub_name => 'foo';

ثم لاحقًا ...

my @plugins = $mc->foo();

أو إذا كنت ترغب في البحث في مساحة اسم أخرى

package MyClass;
use Module::Pluggable search_path => ['Acme::MyClass::Plugin', 'MyClass::Extend'];

أو الدليل

use Module::Pluggable search_dirs => ['mylibs/Foo'];

أو إذا كنت ترغب في إنشاء كل إضافة بدلاً من مجرد إعادة الاسم

package MyClass;
use Module::Pluggable instantiate => 'new';

ثم

# سيتم تمرير كل ما تم تمريره إلى 'plugins'
# إلى 'new' لكل إضافة
my @plugins = $mc->plugins(@options);

بدلاً من ذلك، يمكنك فقط طلب الوحدة النمطية دون إنشائها

package MyClass;
use Module::Pluggable require => 1;

نظرًا لأن الطلب يبحث تلقائيًا عن الحزم الداخلية، وهو ما قد لا يكون مرغوبًا فيه، يمكنك إيقاف تشغيله

package MyClass;
use Module::Pluggable require => 1, inner => 0;

يمكنك الحد من الإضافات المحملة باستخدام الخيار except، سواء كسلسلة نصية، مرجع مصفوفة، أو تعبير عادي.

package MyClass;
use Module::Pluggable except => 'MyClass::Plugin::Foo';

أو

package MyClass;
use Module::Pluggable except => ['MyClass::Plugin::Foo', 'MyClass::Plugin::Bar'];

أو

package MyClass;
use Module::Pluggable except => qr/^MyClass::Plugin::(Foo|Bar)$/;

وبالمثل بالنسبة لـ only، والذي سيقوم فقط بتحميل الإضافات التي تتطابق.

تذكر أنه يمكنك استخدام الوحدة النمطية أكثر من مرة

package MyClass;
use Module::Pluggable search_path => 'MyClass::Filters', sub_name => 'filters';
use Module::Pluggable search_path => 'MyClass::Plugins', sub_name => 'plugins';

ثم لاحقًا ...

my @filters = $self->filters;
my @plugins = $self->plugins;

البحث عن الإضافات

في كل مرة تستدعي فيها 'plugins'، يتم اجتياز مسار البحث بأكمله مرة أخرى. هذا يسمح بالتحميل الديناميكي للإضافات حتى في وقت التشغيل. ومع ذلك، يمكن أن يكون هذا مكلفًا، لذا إذا كنت لا تتوقع أن ترغب في إضافة إضافات جديدة في وقت التشغيل، يمكنك القيام بما يلي

package Foo;
use strict;
use Module::Pluggable sub_name => '_plugins';
our @PLUGINS;
sub plugins { @PLUGINS ||= shift->_plugins }
1;

الحزم الداخلية

إذا كان لديك، على سبيل المثال، ملف lib/Something/Plugin/Foo.pm يحتوي على تعريفات حزم لكل من "Something::Plugin::Foo" و "Something::Plugin::Bar"، فما عليك سوى امتلاك خيار require أو instantiate معين، وسنجد أيضًا "Something::Plugin::Bar". رائع!

خيارات

يمكنك تمرير تجزئة من الخيارات عند استيراد هذه الوحدة النمطية.

يمكن أن تكون الخيارات ...

sub_name

اسم الإجراء الفرعي المراد إنشاؤه في مساحة اسمك.

افتراضيًا، هذا هو 'plugins'

search_path

مرجع مصفوفة لمساحات الأسماء للبحث فيها.

search_dirs

مرجع مصفوفة للدلائل للبحث فيها قبل @INC.

instantiate

استدعاء هذه الطريقة على الفئة. بشكل عام، من المحتمل أن يكون هذا 'new' ولكن يمكن أن يكون أي شيء تريده. سيتم تمرير أي وسيطات يتم تمريرها إلى 'plugins' إلى الطريقة.

الافتراضي هو 'undef'، أي إعادة اسم الفئة فقط.

require

فقط طلب الفئة، لا تقم بإنشائها (يتجاوز 'instantiate')؛

inner

إذا تم تعيينه على 0، فلن يبحث في الحزم الداخلية. إذا تم تعيينه على 1، فسيتجاوز "require".

only

يأخذ سلسلة نصية، مرجع مصفوفة، أو تعبير عادي يصف أسماء الإضافات الوحيدة التي سيتم إرجاعها. في حين أن هذا قد يبدو غريبًا ... حسنًا، إنه كذلك. ولكنه منطقي أيضًا. ثق بي.

except

على غرار "only"، يأخذ وصفًا للإضافات لاستبعادها من الإرجاع. هذا أقل غرابة.

package

هذا للاستخدام من قبل وحدات التوسعة التي تبني على "Module::Pluggable": تمرير خيار "package" يسمح لك بوضع طريقة الإضافة في حزمة مختلفة غير حزمتك الخاصة.

file_regex

افتراضيًا، يبحث "Module::Pluggable" فقط عن ملفات .pm.

من خلال توفير "file_regex" جديد، يمكنك تغيير هذا السلوك، على سبيل المثال:

file_regex => qr/\.plugin$/

include_editor_junk

افتراضيًا، يتجاهل "Module::Pluggable" الملفات التي تبدو وكأنها تركتها المحررات. حاليًا، هذا يعني الملفات التي تنتهي بـ ~ (~)، الامتدادات .swp أو .swo، أو الملفات التي تبدأ بـ .#.

ضبط "include_

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.
