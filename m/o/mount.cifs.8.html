mount.cifs(8)

الحزمة: cifs-utils

التراخيص: GPL-3.0-or-later

MOUNT.CIFS, MOUNT.SMB3(8) دليل مدير النظام MOUNT.CIFS, MOUNT.SMB3(8)

الاسم

mount.cifs, mount.smb3 - تحميل باستخدام نظام الملفات المشترك للإنترنت (CIFS)

الخلاصة

mount.cifs {service} {mount-point} [-o options]

هذه الأداة هي جزء من مجموعة cifs-utils.

mount.cifs يقوم بتحميل نظام ملفات CIFS أو SMB3 من لينكس. عادةً ما يتم استدعاؤه بشكل غير مباشر بواسطة أمر mount(8) عند استخدام الخيار "-t cifs". هذا الأمر يعمل فقط في لينكس، ويجب أن تدعم النواة نظام الملفات cifs. بروتوكول SMB3 هو خليفة بروتوكول CIFS (SMB) ويتم دعمه بواسطة معظم خوادم ويندوز، Azure (التخزين السحابي)، أجهزة Mac والعديد من الخوادم التجارية وأجهزة التخزين المتصلة بالشبكة (NAS) بالإضافة إلى Samba مفتوح المصدر الشهير.

mount.smb3 يقوم بتحميل نظام ملفات SMB3 فقط. عادةً ما يتم استدعاؤه بشكل غير مباشر بواسطة أمر mount(8) عند استخدام الخيار "-t smb3". تمت إضافة نوع نظام الملفات smb3 في النواة 4.18 وما فوق. يعمل بطريقة مشابهة لـ mount.cifs باستثناء أنه يمرر نوع نظام الملفات كـ smb3.

تقوم الأداة mount.cifs بربط اسم UNC (المورد الشبكي المصدر) المحدد كـ service (باستخدام صيغة //server/share، حيث "server" هو اسم الخادم أو عنوان IP و "share" هو اسم المشاركة) بالدليل المحلي mount-point.

يتم تحديد الخيارات لـ mount.cifs كقائمة مفصولة بفواصل من أزواج key=value. من الممكن إرسال خيارات أخرى غير المذكورة هنا، بافتراض أن وحدة نواة نظام الملفات cifs (cifs.ko) تدعمها. سيتم تسجيل خيارات تحميل cifs غير المعروفة التي يتم تمريرها إلى كود نواة cifs vfs في سجل النواة.

mount.cifs يتسبب في قيام cifsvfs بتشغيل خيط يسمى cifsd. بعد التحميل، يظل قيد التشغيل حتى يتم إلغاء تحميل المورد المحمل (عادةً عبر الأداة umount).

الأمر mount.cifs -V يعرض إصدار مساعد تحميل cifs.

الأمر modinfo cifs يعرض إصدار وحدة cifs.

الخيارات

username=arg|user=arg
يحدد اسم المستخدم للاتصال به. إذا لم يتم إعطاء هذا، يتم استخدام متغير البيئة USER.

الإصدارات السابقة من mount.cifs سمحت أيضًا بتحديد اسم المستخدم بصيغة user%password أو workgroup/user أو workgroup/user%password للسماح بتحديد كلمة المرور ومجموعة العمل كجزء من اسم المستخدم. دعم هذه الصيغ البديلة لأسماء المستخدمين تم إهماله الآن ويجب عدم استخدامه. يجب على المستخدمين استخدام password= و domain= المنفصلتين لتحديد هذه القيم. بينما تقبل بعض إصدارات وحدة نواة cifs user= كاختصار لهذا الخيار، فإن استخدامه قد يربك برنامج mount القياسي ليعتقد أن هذا تحميل غير خارق. لذلك يوصى باستخدام اسم الخيار الكامل username=.

password=arg|pass=arg
يحدد كلمة مرور CIFS. إذا لم يتم تحديد هذا الخيار، يتم استخدام متغير البيئة PASSWD. إذا لم يتم تحديد كلمة المرور مباشرة أو بشكل غير مباشر عبر وسيط لـ mount، فسيطلب mount.cifs كلمة مرور، ما لم يتم تحديد خيار guest.

لاحظ أن كلمة مرور تحتوي على حرف الفاصل (أي فاصلة ",") ستفشل في التحليل بشكل صحيح على سطر الأوامر. ومع ذلك، سيتم قراءة نفس كلمة المرور المعرفة في متغير البيئة PASSWD أو عبر ملف بيانات الاعتماد أو التي تم إدخالها عند طلب كلمة المرور بشكل صحيح.

password2=arg|pass2=arg
يحدد كلمة مرور بديلة للمساعدة في تدوير كلمات المرور. إذا لم يتم إعطاء هذا الخيار، يتم استخدام متغير البيئة PASSWD2. إذا لم يتم تحديد password2 مباشرة أو بشكل غير مباشر عبر وسيط لـ mount، فلن يطلب mount.cifs password2.

لاحظ أن password2 التي تحتوي على حرف الفاصل (أي فاصلة ",") ستفشل في التحليل بشكل صحيح على سطر الأوامر. ومع ذلك، سيتم قراءة نفس password2 المعرفة في متغير البيئة PASSWD2 أو عبر ملف بيانات الاعتماد (انظر أدناه) بشكل صحيح.

credentials=filename|cred=filename
يحدد ملفًا يحتوي على اسم مستخدم و/أو كلمة مرور وكلمة مرور بديلة اختيارية و/أو اسم مجموعة العمل. صيغة الملف هي:
username=value
password=value
password2=value
domain=value

هذا مفضل على وجود كلمات مرور كنص عادي في ملف مشترك، مثل /etc/fstab. تأكد من حماية أي ملف بيانات اعتماد بشكل صحيح.

uid=arg
يضبط معرف المستخدم (uid) الذي سيمتلك جميع الملفات أو الأدلة في نظام الملفات المحمل عندما لا يوفر الخادم معلومات الملكية. يمكن تحديده كاسم مستخدم أو معرف مستخدم رقمي. عندما لا يتم تحديده، يكون الافتراضي هو uid 0. يجب أن تكون الأداة mount.cifs بإصدار 1.10 أو أعلى لدعم تحديد uid بصيغة غير رقمية. انظر قسم ملكية وأذونات الملفات والأدلة أدناه لمزيد من المعلومات.
forceuid
يصدر تعليمات للعميل لتجاهل أي uid يقدمه الخادم للملفات والأدلة ودائمًا تعيين المالك إلى قيمة خيار uid=. انظر قسم ملكية وأذونات الملفات والأدلة أدناه لمزيد من المعلومات.
cruid=arg
يضبط معرف المستخدم (uid) لمالك ذاكرة التخزين المؤقت لبيانات الاعتماد. هذا مفيد بشكل أساسي مع sec=krb5. الافتراضي هو uid الحقيقي للعملية التي تنفذ التحميل. يوجه تحديد هذه المعلمة النداء الصاعد (upcall) للبحث عن ذاكرة تخزين مؤقت لبيانات الاعتماد مملوكة لذلك المستخدم.
gid=arg
يضبط معرف المجموعة (gid) الذي سيمتلك جميع الملفات أو الأدلة في نظام الملفات المحمل عندما لا يوفر الخادم معلومات الملكية. يمكن تحديده كاسم مجموعة أو معرف مجموعة رقمي. عندما لا يتم تحديده، يكون الافتراضي هو gid 0. يجب أن تكون الأداة mount.cifs بإصدار 1.10 أو أعلى لدعم تحديد gid بصيغة غير رقمية. انظر قسم ملكية وأذونات الملفات والأدلة أدناه لمزيد من المعلومات.
forcegid
يصدر تعليمات للعميل لتجاهل أي gid يقدمه الخادم للملفات والأدلة ودائمًا تعيين المالك إلى قيمة خيار gid=. انظر قسم ملكية وأذونات الملفات والأدلة أدناه لمزيد من المعلومات.
idsfromsid
استخراج uid/gid من SID خاص بدلاً من تعيينه. انظر قسم ملكية وأذونات الملفات والأدلة أدناه لمزيد من المعلومات.
port=arg
يضبط رقم المنفذ الذي سيحاول العميل الاتصال بخادم CIFS عليه. إذا تم تحديد هذه القيمة، فابحث عن اتصال موجود بهذا المنفذ، واستخدمه إذا كان موجودًا. إذا لم يكن موجودًا، حاول إنشاء اتصال جديد على هذا المنفذ. إذا فشل هذا الاتصال، فارجع خطأ. إذا لم يتم تحديد هذه القيمة، فابحث عن اتصال موجود على المنفذ 445 أو 139. إذا لم يكن هناك مثل هذا الاتصال، فحاول الاتصال على المنفذ 445 أولاً ثم المنفذ 139 إذا فشل ذلك. أرجع خطأ إذا فشل كلاهما.
netbiosname=arg
عند التحميل إلى خوادم عبر المنفذ 139، يحدد اسم مصدر RFC1001 لاستخدامه لتمثيل جهاز netbios الخاص بالعميل أثناء تهيئة جلسة netbios.
servern=arg
مشابه لـ netbiosname باستثناء أنه يحدد اسم netbios الخاص بالخادم بدلاً من العميل. على الرغم من أنه نادرًا ما يكون مطلوبًا للتحميل إلى خوادم أحدث، فإن هذا الخيار مطلوب للتحميل إلى بعض الخوادم القديمة (مثل OS/2 أو Windows 98 و Windows ME) نظرًا لأنها، عند الاتصال عبر المنفذ 139، لا تدعم اسم خادم افتراضي، على عكس معظم الخوادم الأحدث. يمكن أن يصل اسم الخادم إلى 15 حرفًا وعادة ما يكون بأحرف كبيرة.
file_mode=arg
إذا كان الخادم لا يدعم

وضعيات التخزين المؤقت

يمكن أن يؤدي التخزين المؤقت للبيانات محليًا إلى تحسينات كبيرة في الأداء، ولكنه يطرح أيضًا مشكلات تتعلق بتناسق البيانات. يمكن أن يتم التخزين المؤقت للبيانات بواسطة العميل دون علم الخادم، أو العكس. تتمثل إحدى طرق التعامل مع مثل هذه المشكلة في فرض أن جميع عمليات الوصول إلى الملفات تتم مباشرة إلى الخادم. ومع ذلك، فإن هذا مقيِّد للأداء، لذا فإن معظم البروتوكولات لديها آلية للسماح للعميل بتخزين البيانات مؤقتًا محليًا.

يفرض بروتوكول CIFS (بشكل فعال) على العميل عدم تخزين بيانات الملفات مؤقتًا ما لم يكن يمتلك قفلًا انتهازيًا (يعرف أيضًا باسم oplock) أو إيجارًا. يسمح كل من هذين الكيانين للعميل بضمان أنواع معينة من الوصول الحصري إلى ملف بحيث يمكنه الوصول إلى محتوياته دون الحاجة إلى التفاعل المستمر مع الخادم. يستدعي الخادم العميل عند الحاجة إلى إلغاء أي منهما والسماح للعميل بمقدار معين من الوقت لمسح أي بيانات مخزنة مؤقتًا.

يستخدم عميل CIFS ذاكرة التخزين المؤقت للصفحات (pagecache) في النواة لتخزين بيانات الملفات مؤقتًا. تكون أي عمليات إدخال/إخراج تتم عبر ذاكرة التخزين المؤقت للصفحات متسقة مع حدود الصفحات (page-aligned) بشكل عام. يمكن أن يكون هذا إشكاليًا عند دمجه مع أقفال النطاق بالبايت (byte-range locks) حيث أن آلية القفل في Windows إلزامية ويمكن أن تمنع عمليات القراءة والكتابة من الحدوث.

cache=none يعني أن العميل لا يستخدم ذاكرة التخزين المؤقت أبدًا للقراءات والكتابات العادية. يصل دائمًا إلى الخادم مباشرة لتلبية طلب قراءة أو كتابة.

cache=strict يعني أن العميل سيحاول اتباع بروتوكول CIFS/SMB2 بدقة. أي أن ذاكرة التخزين المؤقت تكون موثوقة فقط عندما يمتلك العميل قفلًا انتهازيًا (oplock). عندما لا يمتلك العميل قفلًا انتهازيًا، يتجاوز العميل ذاكرة التخزين المؤقت ويصل إلى الخادم مباشرة لتلبية طلب قراءة أو كتابة. بالقيام بذلك، يتجنب العميل مشاكل أقفال النطاق بالبايت. بالإضافة إلى ذلك، يتم تخزين أقفال النطاق بالبايت مؤقتًا على العميل عندما يمتلك قفلًا انتهازيًا ويتم "دفعها" إلى الخادم عند استدعاء هذا القفل.

cache=loose يسمح للعميل باستخدام دلالات بروتوكول أوسع يمكن أن توفر أداءً أفضل في بعض الأحيان على حساب تناسق ذاكرة التخزين المؤقت. ينطوي الوصول إلى الملفات دائمًا على ذاكرة التخزين المؤقت للصفحات. عندما لا يتم الاحتفاظ بقفل انتهازي أو إيجار، سيحاول العميل مسح ذاكرة التخزين المؤقت بعد فترة وجيزة من الكتابة إلى ملف. لاحظ أن هذا المسح لا يحدث بالضرورة قبل إرجاع استدعاء نظام الكتابة.

في حالة القراءة دون الاحتفاظ بقفل انتهازي، سيحاول العميل التحقق دوريًا من سمات الملف لتحديد ما إذا كان قد تغير وأن ذاكرة التخزين المؤقت قد لا تكون صالحة بعد الآن. تشبه هذه الآلية تلك التي تستخدمها NFSv2/3 لتناسق ذاكرة التخزين المؤقت، ولكنها إشكالية بشكل خاص مع CIFS. Windows "كسول" جدًا فيما يتعلق بتحديث حقل LastWriteTime الذي يستخدمه العميل للتحقق من ذلك. التأثير هو أن cache=loose يمكن أن يسبب تلف البيانات عند عمل عدة قراء وكتاب على نفس الملفات.

لهذا السبب، عند وصول عدة عملاء إلى نفس مجموعة الملفات، يوصى بـ cache=strict. يساعد ذلك في القضاء على مشاكل تناسق ذاكرة التخزين المؤقت باتباع بروتوكولات CIFS/SMB2 بشكل أكثر صرامة.

لاحظ أيضًا أنه بغض النظر عن نموذج التخزين المؤقت المستخدم، سيستخدم العميل دائمًا ذاكرة التخزين المؤقت للصفحات للتعامل مع الملفات المخرطة (mmap'ed files). لا يُضمن مسح الكتابات إلى الملفات المخرطة إلى الخادم إلا عند استدعاء msync()، أو عند الإغلاق (close()).

كان الإعداد الافتراضي في النوى قبل 3.7 هو loose. اعتبارًا من الإصدار 3.7، أصبح الإعداد الافتراضي هو strict.

CIFS/NTFS ACL، تعيين SID/UID/GID، واصفات الأمان

يُستخدم هذا الخيار للعمل مع كائنات الملفات التي تمتلك واصفات أمان (Security Descriptors) وقوائم التحكم في الوصول CIFS/NTFS بدلاً من نموذج المصادقة للمستخدم الذي يعتمد على UID، GID، بتات أذونات الملفات، و POSIX ACL. هذا هو نموذج المصادقة الأكثر شيوعًا لخوادم CIFS وهو النموذج الذي تستخدمه Windows.

يتطلب الدعم لهذا الأمر أن تكون وحدة نواة cifs مبنية بكل من خيارات CONFIG_CIFS_XATTR و CONFIG_CIFS_ACL ممكّنة. منذ Linux 5.3، لم يعد خيار CONFIG_CIFS_ACL موجودًا حيث يتم تضمين دعم CIFS/NTFS ACL دائمًا في وحدة نواة cifs.

معظم أنوية التوزيعات لديها بالفعل هذه الخيارات ممكّنة بشكل افتراضي، ولكن لا يزال بإمكانك التحقق مما إذا كانت ممكّنة باستخدام:

cat /lib/modules/$(uname -r)/build/.config

بدلاً من ذلك، إذا تم تكوين النواة مع CONFIG_IKCONFIG_PROC:

zcat /proc/config.gz

يتم تعيين CIFS/NTFS ACL إلى بتات أذونات الملفات باستخدام خوارزمية محددة في مستند Microsoft TechNet التالي:


http://technet.microsoft.com/en-us/library/bb463216.aspx

من أجل تعيين SIDs إلى/من UIDs و GIDs، يلزم ما يلي:

  • استدعاء نواة إلى الأداة المساعدة cifs.idmap تم إعدادها عبر request-key.conf(5)
  • دعم winbind أو sssd تم تكوينه عبر nsswitch.conf(5)

يرجى الرجوع إلى صفحات man الخاصة بـ cifs.idmap(8) و winbindd(8) و sssd(8) لمزيد من المعلومات.

يمكن استرداد واصفات الأمان لكائن الملف وتعيينها مباشرة باستخدام سمة ممتدة تسمى system.cifs_acl. واصفات الأمان المقدمة عبر هذه الواجهة هي "كتل" بيانات "خام" وتحتاج إلى أداة في مساحة المستخدم لتحليلها وتنسيقها أو لتجميعها مثل getcifsacl(1) و setcifsacl(1) على التوالي.

بعض الأشياء التي يجب مراعاتها أثناء استخدام خيار التركيب هذا:

  • قد يكون هناك زيادة في زمن الاستجابة عند التعامل مع البيانات الوصفية بسبب طلبات إضافية للحصول على واصفات الأمان وتعيينها.
  • التعيين بين CIFS/NTFS ACL و POSIX file permission bits غير كامل وقد يتم فقدان بعض معلومات ACL في الترجمة.
  • إذا لم يتم إعداد استدعاء cifs.idmap بشكل صحيح أو لم يتم تكوين winbind أو sssd وتشغيلهما، سيفشل تعيين المعرف (ID mapping). في هذه الحالة، سيتم تعيين uid و gid افتراضيًا إلى قيم المشاركة أو إلى قيم خيارات التركيب uid و/أو gid إذا تم تحديدها.

الوصول إلى الملفات بنية النسخ الاحتياطي

بالنسبة لمستخدم على الخادم، يتم تحديد الوصول المرغوب فيه إلى ملف بواسطة الأذونات والحقوق المرتبطة بهذا الملف. يتم تحقيق ذلك عادةً باستخدام الملكية وقائمة التحكم في الوصول (ACL). بالنسبة لمستخدم ليس لديه حقوق وصول إلى ملف، لا يزال من الممكن الوصول إلى هذا الملف لغرض معين أو مستهدف عن طريق منحه حقوقًا خاصة. أحد الأغراض المحددة هو الوصول إلى ملف بنية النسخ الاحتياطي أو الاستعادة، أي بنية النسخ الاحتياطي. يمكن عادةً منح الحق في الوصول إلى ملف بنية النسخ الاحتياطي عن طريق جعل هذا المستخدم جزءًا من المجموعة المدمجة Backup Operators. وبالتالي، عندما يحاول هذا المستخدم فتح ملف بنية النسخ الاحتياطي، يتم إرسال طلب الفتح عن طريق تعيين بت FILE_OPEN_FOR_BACKUP_INTENT كأحد CreateOptions.

على سبيل المثال، على خادم Windows، لا يمكن للمستخدم المسمى testuser فتح هذا الملف الذي يحتوي على واصف الأمان التالي:

REVISION:0x1
CONTROL:0x9404
OWNER:Administrator
GROUP:Domain Users
ACL:Administrator:ALLOWED/0x0/FULL

لكن المستخدم testuser، إذا أصبح جزءًا من مجموعة Backup Operators، يمكنه فتح الملف بنية النسخ الاحتياطي.

يمكن لأي مستخدم على جانب العميل يمكنه المصادقة كمستخدم من هذا النوع على الخادم، الوصول إلى الملفات بنية النسخ الاحتياطي. ولكن من المرغوب والأفضل لأسباب أمنية من بين أمور أخرى، تقييد هذا الحق الخاص.

يُستخدم خيار التركيب backupuid لتقييد هذا الحق الخاص لمستخدم يتم تحديده إما باسم أو بمعرف. يُستخدم خيار التركيب backupgid لتقييد هذا الحق الخاص للمستخدمين في مجموعة يتم تحديدها إما باسم أو بمعرف. يجب على المستخدمين الذين يطابقون backupuid أو backupgid فقط محاولة الوصول إلى الملفات بنية النسخ الاحتياطي. يمكن استخدام هذين الخيارين للتركيب معًا.

ملكية وأذونات الملفات والمجلدات

لا يوفر بروتوكول CIFS الأساسي معلومات ملكية Unix أو وضعًا للملفات والمجلدات. بسبب هذا، ستظهر الملفات والمجلدات بشكل عام مملوكة للقيم التي تم تعيين خيارات uid= أو gid= لها، وستكون لها أذونات تم تعيينها إلى file_mode و dir_mode الافتراضيين للتركيب. محاولة تغيير هذه القيم عبر chmod/chown ستعيد النجاح ولكن لن يكون لها أي تأثير.

عندما يتفاوض العميل والخادم على امتدادات Unix، سيتم تعيين uid و gid و mode المقدمة من الخادم للملفات والمجلدات. نظرًا لأن تركيبات CIFS عادةً ما تكون فردية، ويتم استخدام نفس بيانات الاعتماد بغض النظر عن المستخدم الذي يصل إلى التركيب، فسيتم عمومًا منح الملفات والمجلدات المنشأة حديثًا ملكية تتوافق مع بيانات الاعتماد التي تم استخدامها لتركيب المشاركة.

إذا كانت معرفات المستخدم (uid's) ومعرفات المجموعة (gid's) المستخدمة لا تتطابق على العميل والخادم، فقد تكون خيارات forceuid و forcegid مفيدة. لاحظ مع ذلك، أنه لا يوجد خيار مقابل لتجاوز الوضع (mode). قد لا تعكس الأذونات المعينة لملف عند تمكين forceuid أو forcegid الأذونات الحقيقية.

عندما لا يتم التفاوض على امتدادات Unix، من الممكن أيضًا محاكاتها محليًا على الخادم باستخدام خيار التركيب dynperm. عند تمكين خيار التركيب هذا، ستحصل الملفات والمجلدات المنشأة حديثًا على ما يبدو أنها أذونات صحيحة. ومع ذلك، لا يتم تخزين هذه الأذونات على الخادم ويمكن أن تختفي في أي وقت في المستقبل (رهنًا بتغييرات ذاكرة التخزين المؤقت لوحدات inode للنواة). بشكل عام، لا يُنصح بخيار التركيب هذا.

من الممكن أيضًا تجاوز فحص الأذونات على العميل تمامًا عبر خيار noperm. لا يمكن تجاوز فحوصات الأذونات من جانب الخادم. ستتوافق فحوصات الأذونات التي يجريها الخادم دائمًا مع بيانات الاعتماد المستخدمة لتركيب المشاركة، وليس بالضرورة مع المستخدم الذي يصل إلى المشاركة.

NOTES

This command may be used only by root, unless installed setuid, in which case the noexec and nosuid mount flags are enabled. When installed as a setuid program, the program follows the conventions set forth by the mount program for user mounts, with the added restriction that users must be able to chdir() into the mountpoint prior to the mount in order to be able to mount onto it.

Some samba client tools like smbclient(8) honour client-side configuration parameters present in smb.conf. Unlike those client tools, mount.cifs ignores smb.conf completely.

CONFIGURATION

The primary mechanism for making configuration changes and for reading debug information for the cifs vfs is via the Linux /proc filesystem. In the directory /proc/fs/cifs are various configuration files and pseudo files which can display debug information and performance statistics. There are additional startup options such as maximum buffer size and number of buffers which only may be set when the kernel cifs vfs (cifs.ko module) is loaded. These can be seen by running the modinfo utility against the file cifs.ko which will list the options that may be passed to cifs during module installation (device driver load). For more information see the kernel file fs/cifs/README. When configuring dynamic tracing (trace-cmd) note that the list of SMB3 events which can be enabled can be seen at: /sys/kernel/debug/tracing/events/cifs/.

SECURITY

The use of SMB2.1 or later (including the latest dialect SMB3.1.1) is recommended for improved security and SMB1 is no longer requested by default at mount time. Old dialects such as CIFS (SMB1, ie vers=1.0) have much weaker security. Use of CIFS (SMB1) can be disabled by modprobe cifs disable_legacy_dialects=y.

BUGS

Mounting using the CIFS URL specification is currently not supported.

The credentials file does not handle usernames or passwords with leading space.

Note that the typical response to a bug report is a suggestion to try the latest version first. So please try doing that first, and always include which versions you use of relevant software when reporting bugs (minimum: mount.cifs (try mount.cifs -V), kernel (see /proc/version) and server type you are trying to contact.
