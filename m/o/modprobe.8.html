MODPROBE(8) modprobe MODPROBE(8)

الاسم

modprobe - إضافة وإزالة الوحدات من نواة لينكس

الملخص

modprobe [-v] [-V] [-C ملف-الإعداد] [-n] [-i] [-q] [-b] [اسم-الوحدة]
[معلمات-الوحدة...]

modprobe [-r] [-v] [-n] [-i] [أسماء-الوحدات...]

modprobe [-c]

modprobe [--dump-modversions] [اسم-الملف]

الوصف

modprobe يضيف أو يزيل وحدة من نواة لينكس بذكاء: لاحظ أنه للراحة، لا يوجد فرق بين _ و - في أسماء الوحدات (يتم تحويل الشرطة السفلية تلقائيًا). modprobe يبحث في دليل الوحدات /usr/lib/`uname -r` عن جميع الوحدات والملفات الأخرى، باستثناء ملفات الإعداد الاختيارية (انظر modprobe.d(5)). سيستخدم modprobe أيضًا خيارات الوحدة المحددة في سطر أوامر النواة بالشكل <module>.<option> وقوائم الحظر بالشكل modprobe.blacklist=<module>.

لاحظ أنه على عكس نواة لينكس من السلسلة 2.4 (التي لا يدعمها هذا الأداة)، فإن هذه النسخة من modprobe لا تفعل شيئًا للوحدة نفسها: يتم تنفيذ عمل حل الرموز وفهم المعلمات داخل النواة. لذلك قد يكون فشل الوحدة مصحوبًا برسالة من النواة: انظر dmesg(8).

modprobe يتوقع ملف modules.dep.bin محدثًا كما تم إنشاؤه بواسطة أداة depmod المقابلة التي تأتي مع modprobe (انظر depmod(8)). يسرد هذا الملف الوحدات الأخرى التي تحتاجها كل وحدة (إن وجدت)، ويستخدم modprobe هذا لإضافة أو إزالة هذه التبعيات تلقائيًا.

إذا تم تقديم أي وسائط بعد اسم-الوحدة، فسيتم تمريرها إلى النواة (بالإضافة إلى أي خيارات مدرجة في ملف الإعداد).

عند تحميل الوحدات، يمكن أن يكون اسم-الوحدة أيضًا مسارًا إلى الوحدة. إذا كان المسار نسبيًا، فيجب أن يبدأ بـ "./" صراحةً. لاحظ أن هذا قد يفشل عند استخدام مسار لوحدة ذات تبعيات لا تتطابق مع قاعدة بيانات depmod المثبتة.

الخيارات

-a, --all

أدخل جميع أسماء الوحدات الموجودة في سطر الأوامر.

-b, --use-blacklist

يتسبب هذا الخيار في تطبيق modprobe لأوامر blacklist في ملفات الإعداد (إن وجدت) على أسماء الوحدات أيضًا. عادة ما يستخدمه udev(7).

-C دليل, --config=دليل

يتجاوز هذا الخيار دليل الإعداد الافتراضي. انظر modprobe.d(5).

يتم تمرير هذا الخيار عبر أوامر install أو remove إلى أوامر modprobe أخرى في متغير البيئة MODPROBE_OPTIONS.

-c, --showconfig

عرض الإعداد الفعال من دليل الإعداد والخروج.

--dump-modversions

طباعة قائمة بمعلومات إصدارات الوحدات المطلوبة لوحدة معينة. غالبًا ما تستخدم التوزيعات هذا الخيار لتعبئة وحدة نواة لينكس باستخدام تبعيات إصدارات الوحدات.

-d, --dirname

الدليل الجذر للوحدات، / افتراضيًا.

--first-time

عادةً، ينجح modprobe (ولا يفعل شيئًا) إذا طُلب منه إدخال وحدة موجودة بالفعل أو إزالة وحدة غير موجودة. هذا مثالي للبرامج النصية البسيطة؛ ومع ذلك، غالبًا ما ترغب البرامج النصية الأكثر تعقيدًا في معرفة ما إذا كان modprobe قد فعل شيئًا بالفعل: هذا الخيار يجعل modprobe يفشل في الحالة التي لم يفعل فيها شيئًا بالفعل.

--force-vermagic

تحتوي كل وحدة على سلسلة صغيرة تحتوي على معلومات مهمة، مثل إصدارات النواة والمترجم. إذا فشلت وحدة في التحميل واشتكت النواة من أن "سحر الإصدار" لا يتطابق، يمكنك استخدام هذا الخيار لإزالته. بطبيعة الحال، هذا الفحص موجود لحمايتك، لذا فإن استخدام هذا الخيار خطير ما لم تكن تعرف ما تفعله.

ينطبق هذا على أي وحدات يتم إدخالها: كل من الوحدة (أو الاسم المستعار) الموجودة في سطر الأوامر وأي وحدات تعتمد عليها.

--force-modversion

عند تجميع الوحدات مع تعيين CONFIG_MODVERSIONS، يتم إنشاء قسم يوضح إصدارات كل واجهة تستخدمها الوحدة (أو توفرها). إذا فشلت وحدة في التحميل واشتكت النواة من أن الوحدة تتعارض مع إصدار واجهة ما، يمكنك استخدام --force-modversion لإزالة معلومات الإصدار تمامًا. بطبيعة الحال، هذا الفحص موجود لحمايتك، لذا فإن استخدام هذا الخيار خطير ما لم تكن تعرف ما تفعله.

ينطبق هذا على أي وحدات يتم إدخالها: كل من الوحدة (أو الاسم المستعار) الموجودة في سطر الأوامر وأي وحدات تعتمد عليها.

-f, --force

حاول إزالة أي معلومات إصدار من الوحدة قد تمنع تحميلها بخلاف ذلك: هذا هو نفس استخدام كل من --force-vermagic و --force-modversion. بطبيعة الحال، هذه الفحوصات موجودة لحمايتك، لذا فإن استخدام هذا الخيار خطير ما لم تكن تعرف ما تفعله.

ينطبق هذا على أي وحدات يتم إدخالها: كل من الوحدة (أو الاسم المستعار) الموجودة في سطر الأوامر وأي وحدات تعتمد عليها.

-i, --ignore-install, --ignore-remove

يتسبب هذا الخيار في تجاهل modprobe لأوامر install و remove في ملف الإعداد (إن وجدت) للوحدة المحددة في سطر الأوامر (لا تزال أي وحدات تابعة تخضع للأوامر المحددة لها في ملف الإعداد). سيتم تجاهل كل من أوامر install و remove حاليًا عند استخدام هذا الخيار بغض النظر عما إذا كان الطلب قد تم بشكل أكثر تحديدًا باستخدام أحد أو كليهما --ignore-install أو --ignore-remove. انظر modprobe.d(5).

-n, --dry-run, --show

يفعل هذا الخيار كل شيء ولكنه لا يقوم فعليًا بإدخال أو حذف الوحدات (أو تشغيل أوامر التثبيت أو الإزالة). عند دمجه مع -v، يكون مفيدًا لتصحيح المشكلات. لأسباب تاريخية، كل من --dry-run و --show يعنيان في الواقع نفس الشيء وهما قابلان للتبديل.

-q, --quiet

بهذا العلم، لن يطبع modprobe رسالة خطأ إذا حاولت إزالة أو إدخال وحدة لا يمكن العثور عليها (وليست اسمًا مستعارًا أو أمر install/remove). ومع ذلك، ستظل تعود بحالة خروج غير صفرية. تستخدم النواة هذا للاستعلام عن الوحدات التي قد تكون موجودة بشكل فرضي باستخدام request_module.

-R, --resolve-alias

طباعة جميع أسماء الوحدات المطابقة لاسم مستعار. قد يكون هذا مفيدًا لتصحيح مشاكل الأسماء المستعارة للوحدات.

-r, --remove

يتسبب هذا الخيار في قيام modprobe بإزالة وحدة بدلاً من إدخالها. إذا كانت الوحدات التي تعتمد عليها غير مستخدمة أيضًا، فسيحاول modprobe إزالتها أيضًا. على عكس الإدخال، يمكن تحديد أكثر من وحدة في سطر الأوامر (لا معنى لتحديد معلمات الوحدة عند إزالة الوحدات).

عادة لا يوجد سبب لإزالة الوحدات، ولكن بعض الوحدات الخاطئة تتطلب ذلك. قد لا تكون نواة التوزيع الخاصة بك مبنية لدعم إزالة الوحدات على الإطلاق.

-w المهلة_بالميلي ثانية, --wait=المهلة_بالميلي ثانية

يتسبب هذا الخيار في استمرار modprobe -r في محاولة إزالة وحدة إذا فشلت بسبب كون الوحدة مشغولة، أي أن عداد مرجعها ليس 0 في وقت إجراء المكالمة. يحاول modprobe إزالة الوحدة مع زيادة وقت الانتظار بين كل محاولة حتى يصل إلى الحد الأقصى لوقت الانتظار بالمللي ثانية المقدم في هذا الخيار.

-S الإصدار, --set-version=الإصدار

تعيين إصدار النواة، بدلاً من استخدام uname(2) لتحديد إصدار النواة (الذي يحدد مكان العثور على الوحدات).

--show-depends

سرد تبعيات الوحدة (أو الاسم المستعار)، بما في ذلك الوحدة نفسها. ينتج عن هذا مجموعة (قد تكون فارغة) من أسماء ملفات الوحدات،

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

NAME

modprobe - add or remove modules from the kernel

SYNOPSIS

modprobe [ -r ] [ -f ] [ -i ] [ -w ] [ -n ] [ -q ] [ -s ] [ -V ] [ -v ] [ -C file ] [ -d directory ] [ -b firmware_dir ] [ --install=command ] [ --remove=command ] [ --first-time ] [ --force-install ] [ --ignore-install ] [ --ignore-remove ] [ --syslog ] [ --version ] [ --verbose ] [ --config=file ] [ --kmod-root=directory ] [ --firmware-path=firmware_dir ] [ -a ] [ -c ] [ -e ] [ -l ] [ -u ] [ -o ] [ -s ] [ -V ] [ -v ] [ -k ] [module ...]

DESCRIPTION

The modprobe utility is a helper program that intelligently inserts into the Linux kernel or removes modules from it. It is typically used as a fallback or a simpler alternative to insmod and rmmod.

Configuration files in /etc/modprobe.d/, /etc/modprobe.conf, and /etc/depmod.d/ are read to help modprobe determine dependencies and configuration options for modules.

When inserting a module, modprobe will first check if the module is already loaded. If not, it will examine the module's dependencies and attempt to insert any required modules first. It will then attempt to insert the requested module.

When removing a module, modprobe will first check if the module is currently in use. If not, it will examine the module's dependents and attempt to remove them first. It will then attempt to remove the requested module.

It also supports module aliases and install/remove commands, which are used to configure how modules are loaded and unloaded.

OPTIONS

-a, --all

Try to insert or remove all modules on the command line.

-c, --show-depends

Print a list of dependencies for each module specified on the command line.

-C file, --config=file

Specify an alternative configuration file to read instead of the default ones.

-d directory, --kmod-root=directory

Specify an alternative root directory for modules and configuration files. This is typically used in chroot environments.

-e, --export-own-dependencies

This option is used by depmod when it detects module dependencies.

-f, --force

Force the installation or removal of a module, even if it is currently in use or has dependencies. Use with caution.

-i, --ignore-remove

Ignore the removal of modules. This is useful when you want to prevent certain modules from being unloaded.

-k, --kernel-load

This option is used by the kernel to load modules.

-l, --list-loaded

List all currently loaded modules.

-n, --dry-run

Print what would be done, but don't actually do it. This is useful for debugging and verifying configurations.

-o, --ignore-install

Ignore the installation of modules. This is useful when you want to prevent certain modules from being loaded automatically.

-q, --quiet

Suppress all informational messages. Only errors will be printed.

-r, --remove

Remove the specified module(s) from the kernel.

-s, --syslog

Send all error messages through the syslog mechanism instead of to standard error. This is also automatically enabled when stderr is unavailable.

-u, --unsupported-modules

This option is used to handle unsupported modules.

-V, --version

Show version of program and exit.

-v, --verbose

Print messages about what the program is doing. Usually modprobe only prints messages if something goes wrong.

-w, --wait

Wait for module operations to complete. This is useful when dealing with modules that take a long time to load or unload.

--first-time

Only install or remove modules if they are not already installed or removed, respectively.

--force-install

Force the installation of a module, even if it is already loaded.

--ignore-install

Do not run install commands for modules. Typically, install commands are used to specify alternative module names, one per line, each starting with "insmod" and is typically used by distributions to determine which modules to include when generating initrd/initramfs images. Install commands which apply are shown prefixed by "install". It does not run any of the install commands. Note that modinfo(8) can be used to extract dependencies of a module from the module itself, but knows nothing of aliases or install commands.

--install=command

Specify a command to run when the module is installed.

--remove=command

Specify a command to run when the module is removed.

--syslog

This option causes any error messages to go through the syslog mechanism (as LOG_DAEMON with level LOG_NOTICE) rather than to standard error. This is also automatically enabled when stderr is unavailable.

This option is passed through install or remove commands to other modprobe commands in the MODPROBE_OPTIONS environment variable.

--version

Show version of program and exit.

--verbose

Print messages about what the program is doing. Usually modprobe only prints messages if something goes wrong.

This option is passed through install or remove commands to other modprobe commands in the MODPROBE_OPTIONS environment variable.

ENVIRONMENT

The MODPROBE_OPTIONS environment variable can also be used to pass command line arguments to modprobe. The format is intentionally left undocumented, since the use by third-party tools and scripts is discouraged.

The environment variable originates with the implementation of the install rules.
