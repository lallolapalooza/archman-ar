MERGE(7)

الحزمة: postgresql

التراخيص: PostgreSQL

MERGE(7) وثائق PostgreSQL 18.1 MERGE(7)

الاسم

MERGE - إدراج أو تحديث أو حذف صفوف من جدول

الصيغة

[ WITH with_query [, ...] ]
MERGE INTO [ ONLY ] target_table_name [ * ] [ [ AS ] target_alias ]
    USING data_source ON join_condition
    when_clause [...]
    [ RETURNING [ WITH ( { OLD | NEW } AS output_alias [, ...] ) ]
                { * | output_expression [ [ AS ] output_name ] } [, ...] ]
where data_source is:
    { [ ONLY ] source_table_name [ * ] | ( source_query ) } [ [ AS ] source_alias ]
and when_clause is:
    { WHEN MATCHED [ AND condition ] THEN { merge_update | merge_delete | DO NOTHING } |
      WHEN NOT MATCHED BY SOURCE [ AND condition ] THEN { merge_update | merge_delete | DO NOTHING } |
      WHEN NOT MATCHED [ BY TARGET ] [ AND condition ] THEN { merge_insert | DO NOTHING } }
and merge_insert is:
    INSERT [( column_name [, ...] )]
        [ OVERRIDING { SYSTEM | USER } VALUE ]
        { VALUES ( { expression | DEFAULT } [, ...] ) | DEFAULT VALUES }
and merge_update is:
    UPDATE SET { column_name = { expression | DEFAULT } |
                 ( column_name [, ...] ) = [ ROW ] ( { expression | DEFAULT } [, ...] ) |
                 ( column_name [, ...] ) = ( sub-SELECT )
               } [, ...]
and merge_delete is:
    DELETE

الوصف

تقوم MERGE بتنفيذ إجراءات تعديل الصفوف في الجدول الهدف المحدد باسم target_table_name، باستخدام data_source. توفر MERGE عبارة SQL واحدة يمكنها شرطيًا إدراج أو تحديث أو حذف الصفوف، وهو ما كان يتطلب بخلاف ذلك عبارات إجرائية متعددة.

أولاً، يقوم أمر MERGE بإجراء ربط بين data_source والجدول الهدف، مما ينتج عنه 0 أو أكثر من صفوف التغيير المرشحة. لكل صف تغيير مرشح، يتم تعيين حالة MATCHED أو NOT MATCHED BY SOURCE أو NOT MATCHED [BY TARGET] مرة واحدة، وبعد ذلك يتم تقييم عبارات WHEN بالترتيب المحدد. لكل صف تغيير مرشح، يتم تنفيذ عبارة WHEN الأولى التي يتم تقييمها على أنها صحيحة. لا يتم تنفيذ أكثر من عبارة WHEN واحدة لكل صف تغيير مرشح.

لإجراءات MERGE نفس تأثير تعليمات UPDATE أو INSERT أو DELETE العادية بنفس الأسماء. تختلف صيغة هذه التعليمات، خاصة أنه لا توجد عبارة WHERE ولا يتم تحديد اسم جدول. تشير جميع الإجراءات إلى الجدول الهدف، على الرغم من إمكانية إجراء تعديلات على جداول أخرى باستخدام المشغلات (triggers).

عند تحديد DO NOTHING، يتم تخطي صف المصدر. نظرًا لأنه يتم تقييم الإجراءات بترتيبها المحدد، يمكن أن يكون DO NOTHING مفيدًا لتخطي الصفوف غير المهمة من المصدر قبل معالجتها بشكل أكثر تفصيلاً.

تسمح عبارة RETURNING لـ MERGE بحساب وإرجاع قيم بناءً على كل صف تم إدراجه أو تحديثه أو حذفه. يمكن حساب أي تعبير يستخدم أعمدة من جدول المصدر أو الجدول الهدف، أو الدالة merge_action(). افتراضيًا، عند إجراء INSERT أو UPDATE، يتم استخدام القيم الجديدة لأعمدة الجدول الهدف، وعند إجراء DELETE، يتم استخدام القيم القديمة لأعمدة الجدول الهدف، على الرغم من أنه يمكنك أيضًا طلب القيم القديمة والجديدة بشكل صريح. صيغة قائمة RETURNING مطابقة لقائمة مخرجات SELECT.

لا توجد امتيازات محددة لـ MERGE. إذا تم تحديد UPDATE، يجب أن يكون لديك امتياز UPDATE على أعمدة الجدول الهدف المشار إليها في عبارة SET. إذا تم تحديد INSERT، يجب أن يكون لديك امتياز INSERT على الجدول الهدف. إذا تم تحديد DELETE، يجب أن يكون لديك امتياز DELETE على الجدول الهدف. إذا تم تحديد إجراء DO NOTHING، يجب أن يكون لديك امتياز SELECT على عمود واحد على الأقل من الجدول الهدف. تحتاج أيضًا إلى امتياز SELECT على أي أعمدة من جدول المصدر والجدول الهدف مشار إليها في أي شرط (بما في ذلك join_condition أو التعبير). يتم تقييم الامتيازات مرة واحدة في بداية العبارة ويتم التحقق منها سواء تم تنفيذ عبارات WHEN معينة أم لا.

MERGE غير مدعوم إذا كان الجدول الهدف عبارة عن عرض مادي (materialized view) أو جدول خارجي (external table) أو إذا كان لديه أي قواعد محددة.

المعلمات

with_query

تسمح عبارة WITH بتحديد استعلامات فرعية واحدة أو أكثر يمكن الإشارة إليها بالاسم في استعلام MERGE. لمزيد من التفاصيل، راجع القسم 7.8 و SELECT(7). ملاحظة: دعم WITH RECURSIVE غير متوفر في MERGE.

target_table_name

اسم (اختياريًا مع مخطط) الجدول أو العرض الذي سيتم ربطه. إذا تم تحديده فقط قبل اسم جدول، يتم تحديث الصفوف المتطابقة أو حذفها في الجدول المسمى. إذا لم يتم تحديده فقط، يتم أيضًا تحديث الصفوف في أي جداول موروثة من الجدول المسمى أو حذفها. اختياريًا، يمكن تحديد * بعد الاسم للإشارة بوضوح إلى تضمين الجداول التابعة. الكلمة المفتاحية ONLY وخيار * لا يؤثران على إجراءات الإدراج، والتي تقوم دائمًا بالإدراج في الجدول المسمى.

إذا كان target_table_name عبارة عن عرض، فيجب أن يكون قابلاً للتحديث تلقائيًا بدون مشغلات INSTEAD OF، أو أن يحتوي على مشغلات INSTEAD OF لكل نوع إجراء (INSERT، UPDATE، DELETE) محدد في عبارات WHEN. العروض ذات القواعد غير مدعومة.

target_alias

اسم بديل للجدول الهدف. عند توفير اسم مستعار، يتم إخفاء الاسم الحقيقي للجدول بالكامل. على سبيل المثال، بالنظر إلى MERGE INTO foo AS f، يجب أن تشير بقية عبارة MERGE إلى هذا الجدول باسم f، وليس foo.

source_table_name

اسم (اختياريًا مع مخطط) الجدول أو العرض أو جدول الانتقال. إذا تم تحديده فقط قبل اسم جدول، يتم تضمين الصفوف المتطابقة في الجدول المسمى. إذا لم يتم تحديده فقط، يتم أيضًا تضمين الصفوف في أي جداول موروثة من الجدول المسمى. اختياريًا، يمكن تحديد * بعد الاسم للإشارة بوضوح إلى تضمين الجداول التابعة.

source_query

استعلام (عبارة SELECT أو عبارة VALUES) يوفر الصفوف للربط في الجدول الهدف. للحصول على وصف للصيغة، راجع عبارة SELECT(7) أو عبارة VALUES(7).

source_alias

اسم بديل لمصدر البيانات. عند توفير اسم مستعار، يتم إخفاء الاسم الحقيقي للجدول أو الاستعلام الذي تم إصداره بالكامل.

join_condition

join_condition هو تعبير ينتج عنه قيمة منطقية (على غرار عبارة WHERE) تحدد الصفوف من جدول المصدر التي تتطابق مع الصفوف في الجدول الهدف.

ملاحظة:
يجب أن تظهر فقط أعمدة الهدف التي تحاول مطابقتها مع صفوف من جدول المصدر في join_condition. التعبيرات الفرعية لـ join_condition التي تشير فقط إلى أعمدة الجدول الهدف قد تؤثر على الإجراء الذي سيتم اتخاذه، وغالبًا بشكل غير متوقع.

when_clause

مطلوبة عبارة WHEN واحدة على الأقل.

يمكن لعبارة WHEN تحديد WHEN MATCHED أو WHEN NOT MATCHED BY SOURCE أو WHEN NOT MATCHED [BY TARGET]. ملاحظة: المعيار SQL يحدد فقط WHEN MATCHED و WHEN NOT MATCHED (والتي تُعرّف على أنها عدم وجود صف هدف مطابق). عند تحديد WHEN NOT MATCHED BY SOURCE، فهذا يعتبر امتدادًا لمعيار SQL، وكذلك خيار إضافة BY TARGET إلى WHEN NOT MATCHED لجعله أكثر وضوحًا.

إذا حددت عبارة WHEN عبارة WHEN MATCHED وكان صف التغيير المرشح يتطابق مع صف في جدول المصدر وصف في الجدول الهدف، فسيتم تنفيذ عبارة WHEN إذا لم يتم العثور على condition أو تم تقييمه على أنه صحيح.

إذا حددت عبارة WHEN عبارة WHEN NOT MATCHED BY SOURCE وكان صف التغيير المرشح يمثل صفًا في الجدول الهدف لا يتطابق مع صف في جدول المصدر، فسيتم تنفيذ عبارة WHEN إذا لم يتم العثور على condition أو تم تقييمه على أنه صحيح.

إذا حددت عبارة WHEN عبارة WHEN NOT MATCHED [BY TARGET] وكان صف التغيير المرشح يمثل صفًا في جدول المصدر لا يتطابق مع صف في الجدول الهدف، فسيتم تنفيذ عبارة WHEN إذا لم يتم العثور على condition أو تم تقييمه على أنه صحيح.

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

DATA_SOURCE

مصدر بيانات data_source لا يتطابق مع صف في الجدول الوجهة، يتم تنفيذ كتلة WHEN إذا كان الشرط condition غائبًا أو يُقيّم إلى صحيح.

condition

تعبير يُرجع قيمة منطقية. إذا أعاد التعبير لكتلة WHEN قيمة صحيحة، يتم تنفيذ إجراء تلك الكتلة لهذا الصف.

يمكن للشرط في كتلة WHEN MATCHED الإشارة إلى أعمدة في كل من علاقتي المصدر والوجهة. يمكن للشرط في كتلة WHEN NOT MATCHED BY SOURCE الإشارة فقط إلى أعمدة في علاقة الوجهة، حيث لا يوجد صف مصدر مطابق بحكم التعريف. يمكن للشرط في كتلة WHEN NOT MATCHED [BY TARGET] الإشارة فقط إلى أعمدة في علاقة المصدر، حيث لا يوجد صف وجهة مطابق بحكم التعريف. لا يمكن الوصول إلا إلى سمات النظام الخاصة بالجدول الوجهة.

merge_insert

تحديد إجراء INSERT يقوم بإدراج صف في الجدول الوجهة. يمكن أن تظهر أسماء أعمدة الجدول الوجهة بأي ترتيب. إذا لم يتم تحديد قائمة بأسماء الأعمدة، فإن الافتراضي هو جميع أعمدة الجدول بترتيبها المعلن.

سيتم ملء كل عمود غير موجود في القائمة الصريحة أو الضمنية بقيمة افتراضية، إما القيمة الافتراضية المعلنة الخاصة به أو NULL إذا لم تكن هناك.

إذا كان الجدول الوجهة جدولاً مقسمًا، فسيتم توجيه كل صف إلى القسم المناسب وإدراجه فيه. إذا كان الجدول الوجهة قسمًا، فسيحدث خطأ إذا انتهك أي صف إدخال قيد القسم.

لا يمكن تحديد أسماء الأعمدة أكثر من مرة. لا يمكن أن تحتوي إجراءات INSERT على استعلامات فرعية.

يمكن تحديد عبارة VALUES واحدة فقط. يمكن لعبارة VALUES الإشارة فقط إلى أعمدة علاقة المصدر، حيث لا يوجد صف وجهة مطابق بحكم التعريف.

merge_update

تحديد إجراء UPDATE يقوم بتحديث الصف الحالي للجدول الوجهة. لا يمكن تحديد أسماء الأعمدة أكثر من مرة.

لا يُسمح باسم جدول ولا بعبارة WHERE.

merge_delete

يحدد إجراء DELETE يقوم بحذف الصف الحالي من الجدول الوجهة. لا تقم بتضمين اسم الجدول أو أي عبارة أخرى، حيث سيتم تنفيذها عادةً باستخدام عبارة DELETE(7).

column_name

اسم عمود في الجدول الوجهة. يمكن تأهيل اسم العمود باسم حقل فرعي أو فهرس فرعي، إذا لزم الأمر. (الإدراج في حقول معينة فقط لعمود مركب يترك الحقول الأخرى فارغة.) لا تقم بتضمين اسم الجدول في تحديد عمود الوجهة.

OVERRIDING SYSTEM VALUE

بدون هذه العبارة، يكون من الخطأ تحديد قيمة صريحة (بخلاف DEFAULT) لعمود تم تعريفه على أنه GENERATED ALWAYS. تتجاوز هذه العبارة هذا القيد.

OVERRIDING USER VALUE

إذا تم تحديد هذه العبارة، فسيتم تجاهل أي قيمة مقدمة للأعمدة المعرفة على أنها GENERATED BY DEFAULT وسيتم تطبيق القيم التي تم إنشاؤها بواسطة التسلسل الافتراضي.

DEFAULT VALUES

يتم ملء جميع الأعمدة بقيمها الافتراضية. (لا يُسمح باستخدام عبارة OVERRIDING في هذا التنسيق.)

expression

تعبير يتم تعيينه للعمود. إذا تم استخدامه في كتلة WHEN MATCHED، فيمكن للتعبير استخدام قيم من الصف الأصلي في الجدول الوجهة وقيم من صف data_source. إذا تم استخدامه في كتلة WHEN NOT MATCHED BY SOURCE، فيمكن للتعبير استخدام قيم فقط من الصف الأصلي في الجدول الوجهة. إذا تم استخدامه في كتلة WHEN NOT MATCHED [BY TARGET]، فيمكن للتعبير استخدام قيم فقط من صف data_source.

DEFAULT

يقوم بتعيين العمود إلى قيمته الافتراضية (والتي ستكون NULL إذا لم يتم تعيين تعبير قيمة افتراضية بشكل صريح).

sub-SELECT

استعلام فرعي SELECT يُنشئ عددًا من أعمدة الإخراج مساوٍ لعدد الأعمدة المشار إليها في قائمة الأعمدة السابقة. يجب أن يُنشئ الاستعلام الفرعي صفًا واحدًا كحد أقصى. إذا أنشأ صفًا واحدًا، فسيتم تعيين قيم أعمدته إلى أعمدة الوجهة؛ إذا لم يُنشئ أي صف، فسيتم تعيين قيم NULL لأعمدة الوجهة. إذا تم استخدامه في كتلة WHEN MATCHED، فيمكن للاستعلام الفرعي الإشارة إلى قيم من الصف الأصلي في الجدول الوجهة وقيم من صف data_source. إذا تم استخدامه في كتلة WHEN NOT MATCHED BY SOURCE، فيمكن للاستعلام الفرعي الإشارة فقط إلى قيم من الصف الأصلي في الجدول الوجهة.

output_alias

اسم اختياري يحل محل OLD أو NEW في قائمة RETURNING.

افتراضيًا، يمكن إرجاع القيم القديمة من الجدول الوجهة عن طريق كتابة OLD.column_name أو OLD.*، ويمكن إرجاع القيم الجديدة عن طريق كتابة NEW.column_name أو NEW.*. عند توفير اسم مستعار، يتم إخفاء هذه الأسماء ويجب الإشارة إلى السجلات القديمة أو الجديدة باستخدام الاسم المستعار. على سبيل المثال، RETURNING WITH (OLD AS o, NEW AS n) أو o.*, n.*.

output_expression

تعبير يتم حسابه وإرجاعه بواسطة عبارة MERGE بعد كل صف تم تغييره (سواء تم إدراجه أو تحديثه أو حذفه). يمكن للتعبير استخدام أي عمود من جدول المصدر أو الجدول الوجهة، أو الدالة merge_action() لإرجاع معلومات إضافية حول الإجراء الذي تم تنفيذه.

كتابة * تُرجع جميع أعمدة جدول المصدر، متبوعة بجميع أعمدة الجدول الوجهة. يؤدي هذا عادةً إلى تكرار كبير، حيث غالبًا ما تكون جداول المصدر والوجهة مشتركة في العديد من الأعمدة. يمكن تجنب ذلك عن طريق تحديد * مع اسم أو اسم مستعار لجدول المصدر أو الجدول الوجهة.

يمكن أيضًا تأهيل اسم عمود أو * بـ OLD أو NEW، أو بالاسم المستعار المقابل لـ OLD أو NEW، لإرجاع القيم القديمة أو الجديدة من الجدول الوجهة. اسم عمود غير مؤهل من الجدول الوجهة، أو عمود من الجدول الوجهة أو * مؤهل باسم أو اسم مستعار للجدول الوجهة، يُرجع قيمًا جديدة لإجراءات INSERT و UPDATE، وقيمًا قديمة لإجراءات DELETE.

output_name

اسم لعمود تم إرجاعه.

المخرجات

بعد اكتمال ناجح، تُرجع عبارة MERGE علامة أمر بالشكل

MERGE total_count

total_count هو العدد الإجمالي للصفوف التي تم تغييرها (سواء تم إدراجها أو تحديثها أو حذفها). إذا كان total_count هو 0، فلم يتم تغيير أي صف.

إذا احتوت عبارة MERGE على عبارة RETURNING، فستكون النتيجة مشابهة لعبارة SELECT تحتوي على الأعمدة والقيم المحددة في قائمة RETURNING، محسوبة على الصفوف المدرجة أو المحدثة أو المحذوفة بواسطة العبارة.

ملاحظات

تُنفذ الخطوات التالية أثناء تنفيذ MERGE.

1. تنفيذ أي مشغلات BEFORE STATEMENT لجميع الإجراءات المحددة، بغض النظر عما إذا كانت عبارات WHEN الخاصة بها تتطابق.
2. إجراء ربط لجدول المصدر بالجدول الوجهة. سيتم تحسين الاستعلام الناتج بشكل طبيعي وسيُنتج مجموعة من صفوف التغيير المرشحة. لكل صف تغيير مرشح،
1. تقييم ما إذا كان كل صف MATCHED، أو NOT MATCHED BY SOURCE، أو NOT MATCHED [BY TARGET].
2. اختبار كل عبارة WHEN بالترتيب المحدد حتى تُرجع إحداها قيمة صحيحة.
3. عندما تُرجع عبارة قيمة صحيحة، تُنفذ الإجراءات التالية:
1. تنفيذ أي مشغلات BEFORE ROW التي يتم تشغيلها لنوع حدث الإجراء.
2. تنفيذ الإجراء المحدد، واستدعاء أي قيود على الجدول الوجهة.
3. تنفيذ أي مشغلات AFTER ROW التي يتم تشغيلها لنوع حدث الإجراء.

إذا كانت العلاقة الوجهة عبارة عن عرض مع مشغلات INSTEAD OF ROW لنوع حدث الإجراء، فسيتم استخدام هذه المشغلات لتنفيذ الإجراء بدلاً من ذلك.

3. تنفيذ أي مشغلات AFTER STATEMENT للإجراءات المحددة، بغض النظر عما إذا كانت قد حدثت أم لا. هذا مشابه لسلوك عبارة UPDATE التي تعدل أي صفوف.

باختصار، يتم تشغيل المشغلات من نوع الحدث (مثل INSERT) في كل مرة يتم فيها تحديد إجراء من هذا النوع. في المقابل، يتم تشغيل المشغلات على مستوى الصف فقط لنوع الحدث المحدد الذي يتم تنفيذه. لذلك، يمكن لعبارة MERGE تشغيل مشغلات من نوع الحدث UPDATE و INSERT، على الرغم من أنه تم تشغيل مشغلات على مستوى الصف UPDATE فقط.

يجب عليك التأكد من أن الربط يُنتج صف تغيير مرشح واحد على الأكثر لكل صف وجهة. بعبارة أخرى، لا يجب أن يرتبط صف وجهة بأكثر من صف مصدر واحد. إذا حدث ذلك، فسيتم استخدام صف تغيير مرشح واحد فقط لتعديل صف الوجهة؛ المحاولات اللاحقة ستسبب خطأ. قد يحدث هذا أيضًا إذا قامت المشغلات على مستوى الصف بتعديل الجدول الوجهة وتم تعديل الصفوف المعدلة لاحقًا بواسطة MERGE. إذا كان الإجراء المتكرر هو INSERT، فسيؤدي ذلك إلى انتهاك التفرد، بينما سيؤدي إجراء UPDATE أو DELETE المتكرر إلى انتهاك تعددية؛ والثاني مطلوب وفقًا لمعيار SQL. يختلف هذا عن السلوك القديم للربط في عبارات UPDATE و DELETE في PostgreSQL، حيث تم تجاهل المحاولات اللاحقة.

إذا قامت عبارة WHEN بحذف عبارة فرعية AND، فإنها تصبح عبارة نهائية يمكن الوصول إليها من هذا النوع (MATCHED، NOT MATCHED BY SOURCE، أو NOT MATCHED [BY TARGET]). إذا تم تحديد عبارة WHEN من هذا النوع لاحقًا، فمن المحتمل أن تكون غير قابلة للوصول وسيتم رفع خطأ. إذا لم يتم تحديد عبارة نهائية يمكن الوصول إليها من أي من الأنواع، فقد لا يكون هناك إجراء لصف تغيير مرشح.

يتم تحديد ترتيب إنشاء الصفوف من المصدر بشكل غير محدد افتراضيًا. يمكن استخدام source_query لتحديد ترتيب متسق، إذا لزم الأمر، مما قد يساعد في تجنب قفل الكتل بين المعاملات المتزامنة.

عند تنفيذ MERGE بالتزامن مع أوامر أخرى تعدل الجدول الوجهة، تنطبق قواعد عزل المعاملات بشكل طبيعي؛ انظر القسم 13.2 للحصول على شرح للسلوك في كل مستوى عزل. يمكنك أيضًا التفكير في استخدام INSERT ... ON CONFLICT كبديل لعبارة توفر القدرة على تنفيذ UPDATE إذا حدث INSERT متزامن. هناك اختلافات وقيود بين العبارتين وليستا قابلتين للتبديل.
