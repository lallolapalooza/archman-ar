اسم

memfd_create - إنشاء ملف مجهول

المكتبة

مكتبة C القياسية (libc، -lc)

نظرة عامة

#define _GNU_SOURCE         /* انظر feature_test_macros(7) */
#include <sys/mman.h>
int memfd_create(const char *name, unsigned int flags);

الوصف

يقوم memfd_create() بإنشاء ملف مجهول ويعيد واصف ملف يشير إليه. يتصرف الملف مثل ملف عادي، ويمكن بالتالي تعديله، اقتطاعه، تعيينه في الذاكرة، وما إلى ذلك. ومع ذلك، بخلاف ملف عادي، فهو يعيش في ذاكرة الوصول العشوائي (RAM) وله تخزين دعم متطاير. بمجرد إسقاط جميع المراجع إلى الملف، يتم إصداره تلقائيًا. يتم استخدام الذاكرة المجهولة لجميع الصفحات الداعمة للملف. لذلك، فإن الملفات التي تم إنشاؤها بواسطة memfd_create() لها نفس الدلالات مثل تخصيصات الذاكرة المجهولة الأخرى مثل تلك المخصصة باستخدام mmap(2) مع العلامة MAP_ANONYMOUS.

يتم تعيين حجم الملف الأولي إلى 0. بعد الاستدعاء، يجب تعيين حجم الملف باستخدام ftruncate(2). (بدلاً من ذلك، يمكن ملء الملف باستدعاءات لـ write(2) أو ما شابه.)

يتم استخدام الاسم المقدم في name كاسم ملف وسيتم عرضه كهدف للرابط الرمزي المقابل في الدليل /proc/self/fd/. الاسم المعروض مسبوق دائمًا بـ memfd: وهو مخصص لأغراض التصحيح فقط. لا تؤثر الأسماء على سلوك واصف الملف، وبالتالي يمكن أن يكون للملفات المتعددة نفس الاسم دون أي آثار جانبية.

يمكن دمج القيم التالية بتنسيق OR الثنائي في flags لتغيير سلوك memfd_create():

MFD_CLOEXEC
تعيين علامة الإغلاق عند التنفيذ (FD_CLOEXEC) على واصف الملف الجديد. انظر وصف العلامة O_CLOEXEC في open(2) للأسباب التي تجعل هذا مفيدًا.
MFD_ALLOW_SEALING
السماح بعمليات ختم على هذا الملف. انظر مناقشة العمليات F_ADD_SEALS و F_GET_SEALS في fcntl(2)، وأيضًا الملاحظات، أدناه. مجموعة الأختام الأولية فارغة. إذا لم يتم تعيين هذه العلامة، فستكون مجموعة الأختام الأولية F_SEAL_SEAL، مما يعني أنه لا يمكن تعيين أختام أخرى على الملف.
MFD_HUGETLB (منذ Linux 4.14)
سيتم إنشاء الملف المجهول في نظام الملفات hugetlbfs باستخدام الصفحات الضخمة. انظر ملف مصدر نواة Linux Documentation/admin-guide/mm/hugetlbpage.rst لمزيد من المعلومات حول hugetlbfs. تم دعم تحديد كل من MFD_HUGETLB و MFD_ALLOW_SEALING في flags منذ Linux 4.16.
MFD_HUGE_2MB
MFD_HUGE_1GB
...
يستخدم بالاشتراك مع MFD_HUGETLB لتحديد أحجام صفحات hugetlb بديلة (على التوالي، 2 ميجابايت، 1 جيجابايت، ...) على الأنظمة التي تدعم أحجام صفحات hugetlb متعددة. التعريفات لأحجام الصفحات الضخمة المعروفة مدرجة في ملف الرأس <linux/memfd.h>.
للحصول على تفاصيل حول تشفير أحجام الصفحات الضخمة غير المدرجة في ملف الرأس، انظر مناقشة الثوابت ذات الأسماء المتشابهة في mmap(2).

يجب أن تكون البتات غير المستخدمة في flags 0.

كقيمة إرجاع، يعيد memfd_create() واصف ملف جديد يمكن استخدامه للإشارة إلى الملف. يتم فتح واصف الملف هذا للقراءة والكتابة (O_RDWR) ويتم تعيين O_LARGEFILE لواصف الملف.

فيما يتعلق بـ fork(2) و execve(2)، تنطبق الدلالات المعتادة لواصف الملف الذي تم إنشاؤه بواسطة memfd_create(). يتم توريث نسخة من واصف الملف بواسطة الابن الناتج عن fork(2) ويشير إلى نفس الملف. يتم الاحتفاظ بواصف الملف عبر execve(2)، ما لم يتم تعيين علامة الإغلاق عند التنفيذ.

قيمة الإرجاع

عند النجاح، يعيد memfd_create() واصف ملف جديد. عند حدوث خطأ، يتم إرجاع -1 ويتم تعيين errno للإشارة إلى الخطأ.

ملاحظات

يوفر استدعاء النظام memfd_create() بديلاً بسيطًا لتركيب نظام الملفات tmpfs(5) يدويًا وإنشاء وفتح ملف في ذلك النظام. الغرض الأساسي من memfd_create() هو إنشاء ملفات وواصفات ملفات مرتبطة تستخدم مع واجهات برمجة التطبيقات لختم الملفات التي توفرها fcntl(2).

لدى استدعاء النظام memfd_create() أيضًا استخدامات بدون ختم الملفات (وهذا هو سبب تعطيل ختم الملفات، ما لم يتم طلبه صراحةً باستخدام العلامة MFD_ALLOW_SEALING). على وجه الخصوص، يمكن استخدامه كبديل لإنشاء ملفات في tmp أو كبديل لاستخدام open(2) O_TMPFILE في الحالات التي لا يوجد فيها نية لربط الملف الناتج فعليًا بنظام الملفات.

NAME

memfd_create - create an anonymous file in memory

LIBRARY

Linux, kernel

SYNOPSIS

#include <sys/memfd.h>
int memfd_create(const char *name, unsigned int flags);

DESCRIPTION

The memfd_create() system call creates an anonymous file backed by memory. This file is in the tmpfs(5) filesystem and has a lifetime that is independent of any filesystems, mounts, or storage devices. The file is created with a reference count of one; it will be destroyed once all file descriptors referring to it are closed.

The name argument specifies a default name for the file to be used by userspace observers (e.g., in the path /proc/pid/fd/). The name is visible in system monitoring tools (e.g., proc(5)). The name is not a pathname, and it does not affect file operations. The kernel truncates the name to NAME_MAX (excluding the null terminator). If the name is not unique, the behavior is unspecified. If name is NULL, then the name is NULL.

The flags argument is a bitmask that modifies the behavior of memfd_create(). The following flags are defined:

MFD_CLOEXEC
Sets the close-on-exec flag for the file descriptor. If this flag is set, the file descriptor will be closed in all other processes that are created by this process using fork(2) and executed using execve(2).
MFD_ALLOW_SEALING
Enable file sealing operations on the created file. File sealing is a mechanism that allows a process to restrict future modifications to a file. See fcntl(2) for details on file sealing. If this flag is not set, then file sealing is not supported for the file.
MFD_HUGETLB
The file will use the huge page TLB (Translation Lookaside Buffer) mechanism. This flag is only supported if the kernel is configured with CONFIG_HUGETLBFS. If huge pages are not available or if the system administrator has disabled huge pages for the user, then memfd_create() will fail with the error ENOSPC. The size of the huge pages is architecture-dependent. The size specified when using ftruncate(2) must be a multiple of the huge page size. If the size is not a multiple, then ftruncate() will fail with the error EINVAL.
MFD_NODEFER
(Since Linux 5.15) Do not defer the creation of the file backing store. Normally, the backing store for a file created by memfd_create() is created on demand, typically when the file is first written to or mapped into memory. This flag forces the creation of the backing store at the time of the call to memfd_create(). This can be useful for testing or for ensuring that any required resource checks (e.g., for huge pages) are performed immediately.

The file created by memfd_create() is initially empty (size zero). The caller can use file operations like write(2), ftruncate(2), and mmap(2) on the returned file descriptor.

The file descriptor returned by memfd_create() can be transferred to other processes via a UNIX domain socket (see unix(7) and cmsg(3)). This allows for the creation of shared memory regions that are not visible in the filesystem namespace.

If the MFD_ALLOW_SEALING flag is set, then the file descriptor returned by memfd_create() supports file sealing operations using fcntl(2). The possible seals are: F_SEAL_GROW, F_SEAL_SHRINK, F_SEAL_WRITE, F_SEAL_FUTURE_WRITE, and F_SEAL_SEAL. Once a seal is applied to a file, it cannot be removed. Seals can only be added by the process that created the file or by a process that has the CAP_SYS_ADMIN capability. If a process attempts to apply a seal that is incompatible with an existing seal, then the operation will fail with the error EINVAL. For example, if F_SEAL_WRITE is applied, then subsequent attempts to apply F_SEAL_GROW or F_SEAL_SHRINK will fail.

The file created by memfd_create() is automatically removed from the system when all file descriptors referring to it are closed. However, if the file is mapped into memory using mmap(2), and all file descriptors referring to it are closed, then the memory mapping will remain until it is unmapped.

An example of the usage of the sealing mechanism is as follows:

(1)
The first process creates a tmpfs(5) file using memfd_create(). The call yields a file descriptor used in subsequent steps.
(2)
The first process sizes the file created in the previous step using ftruncate(2), maps it using mmap(2), and populates the shared memory with the desired data.
(3)
The first process uses the fcntl(2) F_ADD_SEALS operation to place one or more seals on the file, in order to restrict further modifications on the file. (If placing the seal F_SEAL_WRITE, then it will be necessary to first unmap the shared writable mapping created in the previous step. Otherwise, behavior similar to F_SEAL_WRITE can be achieved by using F_SEAL_FUTURE_WRITE, which will prevent future writes via mmap(2) and write(2) from succeeding while keeping existing shared writable mappings).
(4)
A second process obtains a file descriptor for the tmpfs(5) file and maps it. Among the possible ways in which this could happen are the following:
•
The process that called memfd_create() could transfer the resulting file descriptor to the second process via a UNIX domain socket (see unix(7) and cmsg(3)). The second process then maps the file using mmap(2).
•
The second process is created via fork(2) and thus automatically inherits the file descriptor and mapping. (Note that in this case and the next, there is a natural trust relationship between the two processes, since they are running under the same user ID. Therefore, file sealing would not normally be necessary.)
•
The second process opens the file /proc/pid/fd/fd, where <pid> is the PID of the first process (the one that called memfd_create()), and <fd> is the number of the file descriptor returned by the call to memfd_create() in that process. The second process then maps the file using mmap(2).
(5)
The second process uses the fcntl(2) F_GET_SEALS operation to retrieve the bit mask of seals that has been applied to the file. This bit mask can be inspected in order to determine what kinds of restrictions have been placed on file modifications. If desired, the second process can apply further seals to impose additional restrictions (so long as the F_SEAL_SEAL seal has not yet been applied).

RETURN VALUE

On success, memfd_create() returns the new file descriptor. On failure, it returns -1, and errno is set to indicate the error.

ERRORS

EACCES
The name argument is not a valid name (e.g., contains '/').
EINVAL
Invalid flags were specified. Or, MFD_HUGETLB was specified, and the size requested is not a multiple of the huge page size.
EMFILE
The process has reached its limit for open file descriptors.
ENFILE
The system has reached its limit for open files.
ENODEV
The filesystem does not support the requested operation (e.g., trying to use MFD_HUGETLB on a system without hugetlbfs support).
ENOENT
The filesystem does not support the requested operation (e.g., the directory does not exist).
ENOMEM
Out of memory.
ENOSPC
MFD_HUGETLB was specified, but huge pages are not available or have been disabled by the system administrator.
ENXIO
A non seekable device was specified (e.g. pipe) and the flag MFD_HUGETLB was specified.

STANDARDS

This system call is specific to Linux. It first appeared in Linux 3.17.

HISTORY

The flags MFD_HUGETLB and MFD_NODEFER were added in Linux 3.17 and Linux 5.15, respectively.

NOTES

The file created by memfd_create() is not affected by filesystem remounts or unmounts. It is also not backed by any persistent storage.

If the caller does not specify MFD_ALLOW_SEALING, then file sealing is not supported for the file.

The name specified in the name argument is visible in the path /proc/pid/fd/. This can be useful for debugging purposes.

The file created by memfd_create() can be used to implement shared memory regions that are not visible in the filesystem namespace. This is because the file descriptor can be transferred to other processes via UNIX domain sockets.

EXAMPLES

Below are shown two example programs that demonstrate the use of memfd_create() and the file sealing API.

The first program, t_memfd_create.c, creates a tmpfs(5) file using memfd_create(), sets a size for the file, maps it into memory, and optionally places some seals on the file. The program accepts up to three command-line arguments, of which the first two are required. The first argument is the name to associate with the file, the second argument is the size to be set for the file, and the optional third argument is a string of characters that specify seals to be set on the file.

The second program, t_get_seals.c, can be used to open an existing file that was created via memfd_create() and inspect the set of seals that have been applied to that file.

The following shell session demonstrates the use of these programs. First we create a tmpfs(5) file and set some seals on it:


$ ./t_memfd_create my_memfd_file 4096 sw &
[1] 11775
PID: 11775; fd: 3; /proc/11775/fd/3

At this point, the t_memfd_create program continues to run in the background. From another program, we can obtain a file descriptor for the file created by memfd_create() by opening the /proc/pid/fd file that corresponds to the file descriptor opened by memfd_create(). Using that pathname, we inspect the content of the /proc/pid/fd symbolic link, and use our t_get_seals program to view the seals that have been placed on the file:


$ readlink /proc/11775/fd/3;
/memfd:my_memfd_file (deleted)
$ ./t_get_seals /proc/11775/fd/3;
Existing seals: WRITE SHRINK

Program source: t_memfd_create.c

#define _GNU_SOURCE
#include <err.h>
#include <fcntl.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/mman.h>
#include <sys/types.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    int           fd;
    char          *name, *seals_arg;
    ssize_t       size;
    unsigned int  seals;
    if (argc < 3) {
        fprintf(stderr, "%s name size [seals]\n", argv[0]);
        fprintf(stderr, "\t'seals' can contain any of the "
                "following characters:\n");
        fprintf(stderr, "\t\tg - F_SEAL_GROW\n");
        fprintf(stderr, "\t\ts - F_SEAL_SHRINK\n");
        fprintf(stderr, "\t\tw - F_SEAL_WRITE\n");
        fprintf(stderr, "\t\tW - F_SEAL_FUTURE_WRITE\n");
        fprintf(stderr, "\t\tS - F_SEAL_SEAL\n");
        exit(EXIT_FAILURE);
    }
    name = argv[1];
    size = atoi(argv[2]);
    seals_arg = argv[3];
    /* Create an anonymous file in tmpfs; allow seals to be
       placed on the file.  */
    fd = memfd_create(name, MFD_ALLOW_SEALING);
    if (fd == -1)
        err(EXIT_FAILURE, "memfd_create");
    /* Size the file as specified on the command line.  */
    if (ftruncate(fd, size) == -1)
        err(EXIT_FAILURE, "truncate");
    printf("PID: %jd; fd: %d; /proc/%jd/fd/%d\n",
           (intmax_t) getpid(), fd, (intmax_t) getpid(), fd);
    /* Code to map the file and populate the mapping with data
       omitted.  */
    /* If a 'seals' command-line argument was supplied, set some
       seals on the file.  */
    if (seals_arg != NULL) {
        seals = 0;
        if (strchr(seals_arg, 'g') != NULL)
            seals |= F_SEAL_GROW;
        if (strchr(seals_arg, 's') != NULL)
            seals |= F_SEAL_SHRINK;
        if (strchr(seals_arg, 'w') != NULL)
            seals |= F_SEAL_WRITE;
        if (strchr(seals_arg, 'W') != NULL)
            seals |= F_SEAL_FUTURE_WRITE;
        if (strchr(seals_arg, 'S') != NULL)
            seals |= F_SEAL_SEAL;
        if (fcntl(fd, F_ADD_SEALS, seals) == -1)
            err(EXIT_FAILURE, "fcntl");
    }
    /* Keep running, so that the file created by memfd_create()
       continues to exist.  */
    pause();
    exit(EXIT_SUCCESS);
}

Program source: t_get_seals.c

#define _GNU_SOURCE
#include <err.h>
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
int
main(int argc, char *argv[])
{
    int           fd;
    unsigned int  seals;
    if (argc != 2) {
        fprintf(stderr, "%s /proc/PID/fd/FD\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    fd = open(argv[1], O_RDWR);
    if (fd == -1)
        err(EXIT_FAILURE, "open");
    seals = fcntl(fd, F_GET_SEALS);
    if (seals == -1)
        err(EXIT_FAILURE, "fcntl");
    printf("Existing seals:");
    if (seals & F_SEAL_SEAL)
        printf(" SEAL");
    if (seals & F_SEAL_GROW)
        printf(" GROW");
    if (seals & F_SEAL_WRITE)
        printf(" WRITE");
    if (seals & F_SEAL_FUTURE_WRITE)
        printf(" FUTURE_WRITE");
    if (seals & F_SEAL_SHRINK)
        printf(" SHRINK");
    printf("\n");
    /* Code to map the file and access the contents of the
       resulting mapping omitted.  */
    exit(EXIT_SUCCESS);
}
