memcache_table(5)

الحزمة: postfix

التراخيص: EPL-2.0 OR IPL-1.0, BSD-4-Clause-UC

MEMCACHE_TABLE(5) دليل تنسيقات الملفات MEMCACHE_TABLE(5)

الاسم

memcache_table - تهيئة عميل memcache الخاص بـ Postfix

الملخص

postmap -q "سلسلة" memcache:/etc/postfix/اسم_الملف
postmap -q - memcache:/etc/postfix/اسم_الملف <ملف_الإدخال

الوصف


يستخدم نظام بريد Postfix جداول اختيارية لإعادة كتابة العناوين أو توجيه البريد. عادة ما تكون هذه الجداول بتنسيق dbm أو db.

بدلاً من ذلك، يمكن تحديد جداول البحث كأمثلة memcache. لاستخدام عمليات بحث memcache، عرّف مصدر memcache كجدول بحث في main.cf، على سبيل المثال:

    virtual_alias_maps = memcache:/etc/postfix/memcache-aliases.cf

الملف /etc/postfix/memcache-aliases.cf له نفس تنسيق ملف Postfix main.cf، ويحدد المعلمات الموضحة أدناه.

يدعم عميل memcache الخاص بـ Postfix عمليات البحث، التحديث، الحذف، والتسلسل (الأول/التالي). تتطلب عملية التسلسل قاعدة بيانات احتياطية تدعم العملية.

معلمات MEMCACHE الرئيسية

memcache (الافتراضي: inet:localhost:11211)
خادم memcache (ملاحظة: مفرد) الذي سيحاول Postfix الاتصال به. لخادم TCP حدد "inet:" متبوعًا باسم مضيف أو عنوان، ":"، واسم منفذ أو رقم. حدد عنوان IPv6 داخل "[]". لخادم UNIX-domain حدد "unix:" متبوعًا بمسار المقبس. أمثلة: 
    memcache = inet:memcache.example.com:11211
    memcache = inet:127.0.0.1:11211
    memcache = inet:[fc00:8d00:189::3]:11211
    memcache = unix:/path/to/socket

ملاحظة: للوصول إلى مقبس UNIX-domain باستخدام خادم proxymap(8)، يجب أن يكون الم संग्रहीत قابلاً للوصول بواسطة المستخدم غير المميز postfix.

backup (الافتراضي: غير محدد)
جدول Postfix اختياري يوفر نسخة احتياطية دائمة لقاعدة بيانات memcache. سيقوم عميل memcache الخاص بـ Postfix بتحديث قاعدة بيانات memcache كلما بحث أو غيّر معلومات في قاعدة البيانات الدائمة. حدد جدول "type:table" الخاص بـ Postfix. أمثلة: 
    # ذاكرة تخزين مؤقت غير مشتركة لـ postscreen.
    backup = btree:/var/lib/postfix/postscreen_cache_map
    # ذاكرة تخزين مؤقت مشتركة لـ postscreen للعمليات على نفس المضيف.
    backup = proxy:btree:/var/lib/postfix/postscreen_cache_map

الوصول إلى خوادم proxymap البعيدة قيد التطوير.

ملاحظة 1: عند مشاركة ذاكرة تخزين مؤقت دائمة لـ postscreen(8) أو verify(8)، قم بتعطيل التنظيف التلقائي للذاكرة المؤقتة (اضبط *_cache_cleanup_interval = 0) باستثناء مثيل Postfix واحد سيكون مسؤولاً عن تنظيف الذاكرة المؤقتة.

ملاحظة 2: عند مشاركة جداول متعددة لنفس قاعدة بيانات memcache، يجب على كل جدول استخدام ميزة key_format (انظر أدناه) لإضافة سلسلة فريدة خاصة به مسبقًا إلى مفتاح البحث. بخلاف ذلك، قد لا يعمل التنظيف التلقائي لذاكرة التخزين المؤقت لـ postscreen(8) أو verify(8).

ملاحظة 3: عند الوصول إلى قاعدة البيانات الاحتياطية باستخدام عمليات بحث "proxy:"، يجب تحديد اسم قاعدة البيانات الاحتياطية بالكامل (بما في ذلك البادئة "proxy:") في إعداد proxy_read_maps أو proxy_write_maps لخادم proxymap (اعتمادًا على ما إذا كان الوصول للقراءة فقط أو للقراءة والكتابة).

flags (الافتراضي: 0)
علامات اختيارية يجب تخزينها مع تحديث memcache. يتم تجاهل العلامات عند البحث عن معلومات.
ttl (الافتراضي: 3600)
وقت الانتهاء بالثواني لتحديثات memcache.

ملاحظة 1: عند استخدام جدول memcache كذاكرة تخزين مؤقت لـ postscreen(8) أو verify(8) بدون نسخة احتياطية دائمة، حدد قيمة *_cache_cleanup_interval = 0 مع جميع مثيلات Postfix التي تستخدم memcache، وحدد أكبر قيمة *_ttl لـ postscreen(8) أو قيمة *_expire_time لـ verify(8) كقيمة ttl لجدول memcache.

ملاحظة 2: وفقًا لوثائق بروتوكول memcache، تشير القيمة التي تزيد عن 30 يومًا (2592000 ثانية) إلى وقت UNIX مطلق. القيم الأصغر نسبية لوقت التحديث.

معلمات مفتاح MEMCACHE

key_format (الافتراضي: %s)
تنسيق مفاتيح البحث والتحديث التي يرسلها عميل memcache الخاص بـ Postfix إلى خادم memcache. افتراضيًا، تكون هذه هي نفسها مفاتيح البحث والتحديث التي يستقبلها عميل memcache من تطبيقات Postfix.

ملاحظة 1: لا يتم استخدام ميزة key_format لطلبات قاعدة البيانات backup.

ملاحظة 2: عند مشاركة جداول متعددة لنفس قاعدة بيانات memcache، يجب على كل جدول إضافة سلسلة فريدة خاصة به مسبقًا إلى مفتاح البحث. بخلاف ذلك، قد لا يعمل التنظيف التلقائي لذاكرة التخزين المؤقت لـ postscreen(8) أو verify(8).

أمثلة:

    key_format = aliases:%s
    key_format = verify:%s
    key_format = postscreen:%s

تدعم معلمة key_format توسيعات '%' التالية:

%%
يتم استبدال هذا بحرف '%' حرفي.
%s
يتم استبدال هذا بمفتاح إدخال عميل memcache.
%u
عندما يكون مفتاح الإدخال عنوانًا بالشكل user@domain، يتم استبدال %u بالجزء المحلي المقتبس SQL من العنوان. بخلاف ذلك، يتم استبدال %u بسلسلة البحث بأكملها. إذا كان الجزء المحلي فارغًا، يتم قمع البحث بصمت ولا يتم إرجاع أي نتائج (يتم تخطي التحديث مع تحذير).
%d
عندما يكون مفتاح الإدخال عنوانًا بالشكل user@domain، يتم استبدال %d بجزء النطاق من العنوان. بخلاف ذلك، يتم قمع البحث بصمت ولا يتم إرجاع أي نتائج (يتم تخطي التحديث مع تحذير).
%[SUD]
المكافئات العليا للأقسام المذكورة أعلاه تتصرف في معلمة key_format بشكل مطابق لنظائرها الدنيا.
%[1-9]
يتم استبدال الأنماط %1، %2، ... %9 بالمكون الأكثر أهمية المقابل لنطاق مفتاح الإدخال. إذا كان مفتاح الإدخال user@mail.example.com، فإن %1 هو com، و %2 هو example، و %3 هو mail. إذا كان مفتاح الإدخال غير مؤهل أو لا يحتوي على مكونات نطاق كافية لتلبية جميع الأنماط المحددة، يتم قمع البحث بصمت ولا يتم إرجاع أي نتائج (يتم تخطي التحديث مع تحذير).
domain (الافتراضي: لا توجد قائمة بالنطاقات)
يمكن لهذه الميزة تقليل حمل خادم قاعدة البيانات بشكل كبير. حدد قائمة بأسماء النطاقات، أو مسارات الملفات، أو قواعد بيانات "type:table". عند تحديدها، تكون مفاتيح البحث المؤهلة بالكامل مع جزء محلي *غير فارغ* ونطاق مطابق فقط هي المؤهلة للبحث أو التحديث: يتم تخطي عمليات البحث عن "user" العارية، وعمليات البحث عن النطاقات العارية، وعمليات البحث عن "@domain" بصمت (يتم تخطي التحديثات مع تحذير). مثال: 
    domain = example.com, hash:/etc/postfix/searchdomains

ضوابط أخطاء MEMCACHE

data_size_limit (الافتراضي: 10240)
الحد الأقصى لطول بيانات استجابة memcache بالبايت.
line_size_limit (الافتراضي: 1024)
الحد الأقصى لطول سطر استجابة memcache بالبايت.
max_try (الافتراضي: 2)
عدد مرات محاولة تنفيذ أمر memcache قبل الاستسلام. لا يعيد عميل memcache محاولة تنفيذ أمر عندما لا يقبل خادم memcache اتصالاً.
retry_pause (الافتراضي: 1)
الوقت بالثواني قبل إعادة محاولة أمر memcache فاشل.
