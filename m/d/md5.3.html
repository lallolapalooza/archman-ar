NAME

md5, MD5_Init, MD5_Update, MD5_Final, MD5_Transform, MD5End, MD5File, MD5FileChunk, MD5Data - MD5 cryptographic hash function

LIBRARY

Message Digest (libmd, -lmd)

SYNOPSIS

#include <sys/types.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <openssl/md5.h>

unsigned char *
MD5_Init(MD5_CTX *ctx);
unsigned char *
MD5_Update(MD5_CTX *ctx, const unsigned char *data, size_t len);
unsigned char *
MD5_Final(unsigned char *digest, MD5_CTX *ctx);
void
MD5_Transform(unsigned int state[4], const unsigned char block[64]);

char *
MD5End(struct MD5_CTX *ctx, char *buf);
char *
MD5File(const char *filename, char *buf);
char *
MD5FileChunk(const char *filename, char *buf, off_t offset, off_t length);
char *
MD5Data(const unsigned char *data, size_t len, char *buf);

DESCRIPTION

The MD5 algorithm is a widely used cryptographic hash function which produces a 128-bit hash value. The functions MD5_Init(), MD5_Update(), and MD5_Final() are the standard interface for using the MD5 algorithm. The MD5_CTX structure holds the intermediate state of the calculation.

First, MD5_Init() is called to initialize the context ctx. Then, MD5_Update() can be called one or more times with chunks of data to be hashed. Finally, MD5_Final() computes the hash value from the context ctx and stores it in the buffer digest, which must be at least MD5_DIGEST_LENGTH bytes long. The context ctx is left uninitialized and can be reused after MD5_Init() is called again.

The MD5_Transform() function is the core transformation of the MD5 algorithm. It takes a 512-bit block and updates the intermediate state state accordingly. This function is usually not called directly by applications.

The helper functions MD5End(), MD5File(), MD5FileChunk(), and MD5Data() are convenient wrappers for common tasks.

  • MD5End() finalizes a digest calculation and returns the digest as a null-terminated hexadecimal string in buf. If buf is NULL, space is allocated automatically.
  • MD5File() computes the MD5 hash of a file named filename and returns it as a null-terminated hexadecimal string in buf. If buf is NULL, space is allocated automatically.
  • MD5FileChunk() computes the MD5 hash of a portion of a file named filename. The portion starts at offset and has length length. It returns the digest as a null-terminated hexadecimal string in buf. If buf is NULL, space is allocated automatically.
  • MD5Data() computes the MD5 hash of a block of data of length len and returns it as a null-terminated hexadecimal string in buf. If buf is NULL, space is allocated automatically.

The digest is always MD5_DIGEST_LENGTH bytes long. The hexadecimal string representation is therefore 2 * MD5_DIGEST_LENGTH + 1 characters long.

HISTORY

These functions appeared in OpenBSD 2.0 and NetBSD 1.3.

AUTHORS

The original MD5 routines were developed by RSA Data Security, Inc., and published in the above references. This code is derived from a public domain implementation written by Colin Plumb.

The MD5End(), MD5File(), MD5FileChunk(), and MD5Data() helper functions are derived from code written by Poul-Henning Kamp.

BUGS

Collisions have been found for the full versions of both MD4 and MD5. The use of sha2(3) is recommended instead.
