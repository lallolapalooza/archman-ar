Some information about the typical lavrec output while recording

0.06.14:22 int: 00040 lst:0 ins:0 del:0 ae:0 td1=0.014 td2=0.029

The first part shows the time lavrec is recording. int: the interval between two frames. lst: the number of lost frames. ins and del: are the number of frames inserted and deleted for sync correction. ae: number of audio errors. td1 and td2 are the audio/video time-difference.

(int) frame interval should be around 33 (NTSC) or 40 (PAL/SECAM). If it is very different, you'll likely get a bad recording and/or many lost frames

(lst) lost frames are bad and mean that something is not working very well during recording (too slow HD, too high CPU usage, ...) Try recording with a greater decimation and possibly a lower quality.

(ins, del) inserted OR deleted frames of them are normal → sync. If you have many lost AND inserted frames, you're asking too much of your machine. Use less demanding options or try a different sound card.

(ae) audio errors are never good. Should be 0

(td1, td2) time differenceis always floating around 0, unless sync correction is disabled (--synchronization!=2, 2 is default).

Notes about ”interlace field order - what can go wrong and how to fix it”

Firstly, what does it mean for interlace field order to be wrong?

The mjpegtools image processing chain is frame-oriented. Since it is video material that is captured each frame comprised of a top field (the 0th, 2nd, 4th and so lines) and a bottom field (the 1st, 3rd, 5th and so on lines).

There are three bad things that can happen with fields

This is really only an issue for movies in PAL video where each film frame is sent as a pair of fields. These can be sent top or bottom field first and sadly it's not always the same, though bottom-first appears to be usual. If you capture with the wrong field order (you start capturing each frame with a bottom rather than a top or vice versa) the frames of the movie get split *between* frames in the stream. Played back on a TV where each field is displayed on its own this is harmless. The sequence of fields played back is exactly the same as the sequence of fields broadcast. Unfortunately, playing back on a Computer monitor where both fields of a frame appear at once it looks *terrible* because each frame is effectively mixing two moments 1/25sec apart in time.

The two fields can simply be swapped somehow so that top gets treat as bottom and bottom treat as top. Juddering and ”slicing” is the result. This occasionally seems to happen due to hardware glitches in the capture card.

Somewhere in capturing/processing the *order* in time of the two fields in each frame can get mislabeled somehow. This is not good as it means that when playback eventually takes place a field containing an image sampled earlier in time comes after an image sampled later. Weird ”juddering” effects are the results.

How can I recognize if I have one of these Problems ?

This can be hard to spot. If you have mysteriously flickery pictures during playback try encoding a snippet with the reverse field-order forced (see below). If things improve you know what the problem was and what the solution is!

Edit the video

تعديل باستخدام glav

Most tasks can be easily done by glav. Like deleting parts of the video, cut paste and copy parts of the videos.

glav button description

The modifications should be saved because glav does not destructively edit the video. This means that the original video is left untouched and the modifications are kept in an extra ”Edit List” file readable with a text editor. These files can be used as an input to the other lavtools programs such as lav2wav, lav2yuv, lavtrans.

If you want to cut off the beginning and the end of the stream mark the beginning and the and, and use the ”save select” button. The edit list file is than used as input for the lavtools. If you want to split a recorded video to some smaller parts simply select the parts and then save each part to a different listfile.

You can see all changes to the video and sound NOW and you do not need to recalculate anything.

If you want to get a "destructive" version of your edited video use:

Thanks to Philipp Zabel's lavpipe we can now make simple transitions between movies or combine multiple layers of movies.

Philipp wrote this HOWTO on how to make transitions:

Let's assume simple this scene: We have two input videos intro.avi and epilogue.mov and want to make intro.avi transition into epilogue.mov with a duration of one second (that is 25 frames for PAL or 30 frames for NTSC).

Intro.avi and epiloque.mov have to be of the same format (the same frame rate and resolution). In this example they are both 352x288 PAL files. intro.avi contains 250 frames and epilogue.mov is 1000 frames long.

Therefore our output file will contain:

إطارات intro.avi الأولى 225

the first 225 frames of intro.avi

انتقال 25 إطارًا يحتوي على آخر 25 إطارًا من intro.avi وأول 25 إطارًا من epilogue.mov

a 25 frame transition containing the last 25 frames of intro.avi and the first 25 frames of epilogue.mov

آخر 975 إطارًا من epilogue.mov

the last 975 frames of epilogue.mov

We could get the last 25 frames of intro.avi by calling:

>lav2yuv -o 225 -f 25 intro.avi

-o 255, the offset, tells lav2yuv to begin with frame # 225 and -f 25 makes it output 25 frames from there on.

Another possibility (because negative offsets are counted from the end)is:

> lav2yuv -o -25 intro.avi

And the first 25 frames of epilogue.mov:

> lav2yuv -f 25 epilogue.mov

-o defaults to an offset of zero

But we need to combine the two streams with lavpipe. So the call would be:

> lavpipe ”lav2yuv -o 255 -f 25 intro.avi” ”lav2yuv -f 25 epilogue.mov”

The output of this is a raw yuv stream that can be fed into transist.flt.

transist.flt needs to be informed about the duration of the transition and the opacity of the second stream at the beginning and at the end of the transition:

-o num
شفافية الإدخال الثاني في البداية [0-255]

opacity of second input at the beginning [0-255]

-O num
شفافية الإدخال الثاني في النهاية [0-255]

opacity of second input at the end [0-255]

-d num
مدة الانتقال بالإطارات

duration of transition in frames

An opacity of 0 means that the second stream is fully transparent (only stream one visible), at 255 stream two is fully opaque.

In our case the correct call (transition from stream 1 to stream 2) would be:

> transist.flt -o 0 -O 255 -d 25

The -s and -n parameters equate to the -o and -f parameters of lav2yuv and are only needed if anybody wants to render only a portion of the transition for whatever reason. Please note that this only affects the weighting calculations - none of the input is really skipped. If you use the skip parameter (-s 30, for example) you also need to skip the first 30 frames in lav2yuv (-o 30) in order to get the expected result. If you didn't understand this send an email to the authors or simply ignore -s and -n. The whole procedure will eventually be automated.

Now we want to compress the yuv stream with yuv2lav:

> yuv2lav -f a -q 80 -o transition.avi

Reads the yuv stream from stdin and outputs an avi file (-f a) with compressed jpeg frames of quality 80.

Now we have the whole command for creating a transition:

> ypipe ”lav2yuv -o 255 -f 25 intro.avi” ”lav2yuv -f 25 epilogue.mov” │ transist.flt -o 0 -O 255 -d 25 │ yuv2lav -f a -q 80 -o transition.avi

The resulting video can be written as a LAV Edit List (a plain text file) containing the following lines:

LAV Edit List
PAL
3
intro.avi
transition.avi
epilogue.mov
0 0 224
1 0 24
2 25 999

This file can be fed into glav or lavplay, or you can pipe it into mpeg2enc with lav2yuv or combine the whole stuff into one single mjpeg file with lavtrans or lav2yuv│yuv2lav.

إنشاء مقاطع فيديو MPEG-1

MPEG-1 هو تنسيق فيديو شائع ومناسب بشكل خاص لمقاطع الفيديو ذات الدقة المنخفضة. هو عبارة عن مجموعة فرعية من أفلام MPEG-1 هي أقراص الفيديو المضغوطة (VCD). يمكنك استخدام VBR (معدل البت المتغير) للفيديو (على الرغم من أن أقراص VCD تستخدم دائمًا تقريبًا فيديو CBR) ولكن يجب أن يكون الصوت CBR (معدل البت الثابت).

يُوصى باستخدام MPEG-1 لأحجام الصور التي تصل إلى 352x288 لـ PAL و 352x240 لـ NTSC. بالنسبة للأحجام الأكبر، يعد MPEG-2 الخيار الأفضل. لا يوجد دقة محددة يكون فيها MPEG-1 أفضل من MPEG-2. للتأكد، لا يستطيع MPEG-1 التعامل مع المصادر المتشابكة. إذا كان الفيديو الخاص بك متشابكًا، فأنت بحاجة إلى MPEG-2 لتشفيره بشكل صحيح.

مثال على إنشاء صوت MPEG-1

> lav2wav editlist.eli │ mp2enc -r 44100 -o sound.mp2

يمكنك توفير بعض البتات عن طريق إخبار mp2enc باستخدام معدل بت أقل (خيار -b) مثل 160 أو 192 كيلوبت/ثانية. يفرض الخيار -r 44100 على mp2enc إنشاء ملف صوتي بمعدل 44.1 كيلو هرتز.

> lav2wav editlist.eli │ mp2enc -b 128 -m -o sound.mp2

يقوم هذا بإنشاء خرج أحادي بمعدل بت قدره 128 كيلوبت/ثانية. المدخل هذه المرة هو ملف قائمة التحرير (يمكن أن يكون له أي اسم) تم إنشاؤه باستخدام glav، لذا يتم معالجة جميع التغييرات التي أجريتها في glav مباشرة وتسليمها إلى mp2enc. لا يتعين عليك إنشاء دفق محرر باستخدام lavtrans لتحويله بشكل صحيح.

مثال على إنشاء فيديو MPEG-1

> lav2yuv editlist.eli │ mpeg2enc -b 2000 -r 24 -q 6 -o video.m1v

ينشئ mpeg2enc فيديو بمعدل بت قدره 2000 كيلوبت/ثانية (أو 2048000 بت/ثانية) ولكن العلامة -q تنشط معدل البت المتغير وعامل جودة قدره 6. يستخدم نصف قطر بحث قدره 24.

شرح: عندما يتم استدعاء mpeg2enc بدون العلامة 'q'، فإنه ينشئ دفق MPEG "معدل البت الثابت". حيث (بشكل تقريبي) يتم تعديل قوة الضغط (وبالتالي جودة الصورة) لضمان أن كل إطار فيديو له بالضبط عدد البتات المحدد في المتوسط. هذه التدفقات ذات معدل البت الثابت مطلوبة للبث وللأجهزة منخفضة التكلفة مثل مشغلات DVD و VCD التي تستخدم أجهزة تشغيل ذات سرعة ثابتة وبطيئة.

من الواضح أن هذا غير فعال إلى حد ما لأنه يعني أن المشاهد غير النشطة تستخدم بتات كان يمكن "إنفاقها" بشكل أفضل على المشاهد سريعة التغيير. تشير العلامة 'q' إلى mpeg2enc لإنشاء دفق معدل البت المتغير. بالنسبة لهذه التدفقات، فإن معدل البت المحدد هو ببساطة الحد الأقصى المسموح به. تحدد المعلمة 'q' الحد الأدنى لدرجة الضغط التي سيتم تطبيقها عن طريق تحديد كيفية تسجيل معلومات الصورة بالضبط. عادةً ما يتم تعيين 'q' بحيث تستخدم المشاهد الهادئة أقل من الحد الأقصى المحدد (حوالي 6 أو 8) ولكن المشاهد سريعة الحركة ستظل محدودة بمعدل البت. لأغراض الأرشفة، يعد تعيين حد أقصى لمعدل البت مرتفعًا بما يكفي لعدم الوصول إليه أبدًا (على سبيل المثال، 10 ميجابت/ثانية) و q بقيمة 2 أو 3 خيارات معقولة.

مثال:

> lav2yuv stream.avi │ yuvscaler -I ACTIVE_352x240+0+24 │ mpeg2enc -b 1152 -r 16 -4 1 -2 1 -o video.m1v

عادةً ما يكون هناك في الأعلى والأسفل شريط أسود تقريبًا والكثير من عرض النطاق الترددي يُستخدم لشيء لا تحبه. يضبط الخيار yuvscaler -I ACTIVE كل ما هو خارج المنطقة المحددة إلى اللون الأسود ولكن حجم الصورة (352x288) لا يتغير. لذلك لديك شريط أسود حقيقي يستخدمه المشفر لبضع بتات فقط لتشفيره. لا يزال متوافقًا مع تنسيق أقراص VCD في هذا المثال. لتحديد النافذة النشطة، استخرج إطارًا واحدًا بتنسيق jpeg:

> lavtrans -f i -i 100 -o frame.jpg test.avi

ثم استخدم برنامج عرض الرسومات المفضل لديك لتحديد الحجم النشط. تحسن الخيارات -4 1 و -2 1 الجودة بنسبة 10٪ تقريبًا ولكن التحويل أبطأ.

عند حجم 352x288 (حجم PAL 1/2 الذي تم إنشاؤه عند استخدام الخيار -d 2 عند التسجيل) فإن معدل البت المطلوب / يجب أن يكون بين 1000-1500 كيلوبت/ثانية. بالنسبة لـ NTSC، يجب أن يكون تقريبًا نفس الشيء، لأن الصورة أصغر ولكن هناك المزيد من الإطارات في الثانية مقارنة بـ PAL.

على أي حال، فإن العامل الرئيسي هو جودة الأصل ودرجة الترشيح. المواد غير المفلترة ذات الجودة الرديئة تتطلب عادةً معدلًا أعلى لتجنب التشوهات المرئية. إذا كنت ترغب في تقليل معدل البت دون تشوهات مزعجة عند ضغط مواد البث، فيجب عليك تجربة أحد (أو أكثر) مرشحات الضوضاء.

مثال:

> lav2yuv stream.avi │ mpeg2enc -b 1500 -n s -g 6 -G 20 -P -o video.m1v

هنا سيتم تشفير stream.avi باستخدام:

-b 1500

معدل بت قدره 1500 كيلوبت/ثانية

-n s

يتم إجبار معيار الفيديو المدخل على SECAM

-P

يضمن هذا ظهور إطاري B بين إطارات I/P المتجاورة. لا تستطيع العديد من أجهزة فك تشفير MPEG-1 الشائعة التعامل مع التدفقات التي لا تحتوي على إطاري B بين إطارات I/P.

-g 6 -G 20

يمكن للمشفر تغيير حجم مجموعة الصور ديناميكيًا ليعكس تغييرات المشهد. يتم ذلك عن طريق تعيين حد أقصى لمجموعة الصور (العلامة -G) أكبر من الحد الأدنى (العلامة -g). بالنسبة لأقراص VCD، قد تكون القيم المعقولة 9 كحد أدنى و 15 كحد أقصى. بالنسبة لـ SVCD، ستكون 9 و 15 قيمًا جيدة. إذا كنت ترغب فقط في تشغيله على مشغل SW، يمكنك استخدام قيم حد أدنى/أقصى أخرى.

مثال:

> lav2yuv stream*.avi │ mpeg2enc -b 1500 -r 16 -4 1 -2 1 -S 630 -B 260 -o video_n1_1500_r16_41_21_S630_B240.m1v

يقوم lav2yuv بمعالجة جميع ملفات stream. ثم يتم إعطاء mpeg2enc بعض الخيارات التي تجعل الدفق المشفر يبدو أجمل. يعني استخدام -S 630 أن mpeg2enc يضع علامة على الدفق بحيث ينشئ mplex دفقًا جديدًا كل 630 ميجابايت. أحد الأشياء المهمة هو استخدام الخيار -B الذي يحدد معدل البت غير الفيديو (الصوت ومعلومات mplex). يجب أن تكون قيمة -B البالغة 260 مناسبة للصوت بمعدل 224 كيلوبت ومعلومات mplex. لمزيد من المعلومات، اطلع على نصوص التشفير في دليل النصوص.

مثال على تجميع MPEG-1

مثال:

>mplex sound.mp2 video.m1v -o my_video.mpg

يجمع sound.mp2 و video.m1v في my_video.mpg. يعمل الأمر بهذه السهولة فقط إذا كان لديك CBR (لم يتم استخدام الخيار -q مع mpeg2enc).

مثال:

mplex -V -r 1740 audio.mp2 video_vbr.m1v -o vbr_stream.mpg

هنا نقوم بتجميع دفق معدل بت متغير. mplex الآن مجمع أحادي المرور، لذلك لا يمكنه اكتشاف الحد الأقصى لمعدل البت، ويجب علينا تحديده. معدل بيانات الدفق الناتج هو: معدل بت الصوت + الحد الأقصى لمعدل بت الفيديو + 1-2٪ لمعلومات mplex. إذا كان الصوت (-b 224) يحتوي على 224 كيلوبت، والفيديو يحتوي على 1500 كيلوبت (تم تشفيره باستخدام -b 1500 -q 9)، فإن لدينا 1724 * 1.01 أو حوالي 1740 كيلوبت.

إنشاء مقاطع فيديو MPEG-2

يُوصى باستخدام MPEG-2 للمصادر ذات الصور التي تكون أكبر من 352x240 لـ NTSC و 352x288 لـ PAL. يمكن لـ MPEG-2 أيضًا التعامل مع المصادر المتشابكة مثل التسجيل من التلفزيون بدقة كاملة.

يسمح MPEG-2 باستخدام صوت MPEG Layer 3 (mp3). لذلك يمكنك استخدام مشفر mp3 المفضل لديك لإنشاء الصوت. ومع ذلك، فإن صوت MP3 غير صالح لأقراص DVD. من الأفضل استخدام صوت MP2 (Layer 2). يمكن أن يكون الصوت أيضًا تدفق VBR.

عادةً ما يكون MPEG-2 تدفق VBR. يتطلب إنشاء MPEG-2 مع التحسين الكثير من قوة المعالجة. فيلم بدقة مضاعفة ليس أكبر بـ 4 مرات من دفق MPEG-1. اعتمادًا على إعدادات الجودة الخاصة بك، سيكون أكبر بحوالي 1.5 إلى 3 مرات من دفق MPEG-1 بدقته المنخفضة. مثال على إنشاء صوت MPEG-2

> lav2wav editlist.eli │ mp2enc -o sound.mp2

يمكنك توفير بعض البتات عن طريق إخبار mp2enc باستخدام معدل بت أقل (خيار -b) مثل 160 أو 192 كيلوبت/ثانية. قد ترغب في إضافة -r 44100 بحيث يقوم mpeg2enc بإنشاء معدل عينة صوتي يبلغ 44.1 كيلو هرتز. آمل ألا أحتاج إلى شرح استخدام مشفر MP3. ولكن يجب ألا تستخدم جميع الخيارات المتقدمة المتاحة.

مثال على إنشاء فيديو MPEG-2

> lav2yuv editlist.eli │ mpeg2enc -f 3 -b 3000 -q 9 -o video.m2v

مثال بسيط جدًا لـ MPEG-2 Video. أهم خيار هو -f 3. هذا يخبر mpeg2enc أنه يجب عليه إنشاء دفق MPEG-2. نظرًا لأنه MPEG-2 عام، يجب عليك استخدام خيارات معدل البت -b. ويجب استخدام الخيار -q لأنك عادةً ما تريد دفق VBR يوفر المساحة. عند استخدام تدفقات VBR، يخبر الخيار -b mpeg2enc بالحد الأقصى لمعدل البت الذي يمكن استخدامه. يخبر الخيار -q mpeg2enc بالجودة التي يجب أن تتمتع بها التدفقات. يبلغ معدل البت حدًا أقصى لقيمة محددة بواسطة -b.

> lav2yuv editlist.eli │ mpeg2enc -f 3 -4 1 -2 1 -q7 -b 4500 -V 300 -P -g 6 -G 18 -I 1 -o video.m2v

سينشئ هذا دفق MPEG-2 بجودة أعلى لأن خيارات -4 1 و -2 1 تم استخدامها. مع -b 4500 -q 7، تخبر mpeg2enc بالحد الأقصى لمعدل البت وعامل الجودة. -V هو حجم مخزن الفيديو المستخدم لفك تشفير الدفق. للتشغيل SW، يمكن أن يكون أعلى بكثير من القيمة الافتراضية. يتم تعيين GOP الديناميكي باستخدام -g و -G. يمكن أن يساعد حجم GOP الأكبر في تقليل معدل البت المطلوب لجودة معينة، ولكن الأحجام الكبيرة جدًا يمكن أن تتسبب في تشوهات بسبب أخطاء التقريب المتراكمة في DCT/iDCT. يضمن الخيار -P أيضًا ظهور إطاري B بين إطارات I/P المتجاورة. يخبر الخيار -I 1 mpeg2enc أن المصدر مادة متشابكة مثل مقاطع الفيديو. يوجد منطق لتعويض الحركة المتشابكة (يستغرق وقتًا) في mpeg2enc. سيستخدم Mpeg2enc هذا المنطق إذا كان حجم الإطارات التي تقوم بتشفيرها أكبر من حجم VCD لمعيار التلفزيون الخاص بك.

إذا كنت تقوم بإلغاء تشابك الفيلم باستخدام yuvdeinterlace، فيجب عليك إخبار mpeg2enc بأنه لا يحتاج إلى إجراء تقدير للحركة للمواد المتشابكة. يجب عليك استخدام الخيار -I 0 لـ mpeg2enc للقول بأن الإطارات تم إلغاء تشابكها بالفعل. هذا سيوفر الكثير من الوقت عند التشفير. إذا لم تستخدم -I 0، فلن يتسبب ذلك في مشاكل، سيستغرق التشفير وقتًا أطول.

يمكنك أيضًا استخدام القياس والخيارات التي تعمل على تحسين (إزالة الضوضاء) الصور للحصول على دفقات أصغر. يتم شرح هذه الخيارات بالتفصيل في الأقسام التالية. ما هي القيم التي يجب استخدامها لتشفير VBR؟

يتحكم الخيار -q في الحد الأدنى من التكميم لدفق الإخراج. يتحكم التكميم في دقة ترميز معلومات الصورة. كلما انخفضت القيمة، كانت جودة الصورة أفضل. القيم الأقل من 4 هي قيم متطرفة ويجب استخدامها فقط إذا كنت تعرف ما تفعله.

عادةً ما يتعين عليك إعداد حد أقصى لمعدل البت باستخدام الخيار -b. المهمة الصعبة هي تعيين قيمة للخيار -q والخيار -b التي تنتج فيلمًا لطيفًا دون استخدام الكثير من عرض النطاق الترددي ولا تتسبب في الكثير من التشوهات.

يجب اختيار عامل جودة بحيث يختلف خرج mplex لمعدل البت الأقصى ومعدل البت المتوسط بنسبة 20-25٪ تقريبًا. إذا كان الفرق صغيرًا جدًا

إذا كانت لديك إعدادات VCD النموذجية، فإن بيانات CRC تحتاج إلى حوالي 0.27% من إجمالي البيانات. في أسوأ الحالات، حيث لديك دفق صوتي أحادي بمعدل بت 32 كيلو بت في الثانية، فإن بيانات CRC تحتاج إلى 1.92%. مثال إنشاء فيديو SVCD

> lav2yuv stream.avi │ yuvscaler -O SVCD │ mpeg2enc -f 4 -q 7 -I 1 -V 200 -o video.m2v

-f 4

يحدد خيارات mpeg2enc لـ SVCD

-q 7

يخبر mpeg2enc بإنشاء دفق بمعدل بت متغير

-I 1

يخبر mpeg2enc بافتراض أن الإشارة الأصلية هي فيديو متداخل الحقول حيث يتم أخذ عينات من الصفوف الفردية للبكسل بعد نصف إطار من الصفوف الزوجية في كل إطار. الخيار -I 0 (إخراج تقدمي (لا توجد صور حقول)) سيعمل أيضًا مع PAL

يمكنك استخدام معدلات بت أقل، ولكن معيار SVCD يحد معدل البت الإجمالي (الصوت والفيديو) إلى 2788800 بت في الثانية. لذا مع صوت 224 كيلوبت في الثانية والنفقات العامة، قد يكون 2550 ضيقًا للغاية. نظرًا لأن تنسيق SVCD يسمح بأي معدل صوت بين 32 و 384 كيلوبت في الثانية، يمكنك توفير بضعة بتات في الثانية باستخدام صوت 192 كيلوبت (أو للمواد غير الموسيقية 160 كيلوبت).

يدعم SVCD معدل البت المتغير (VBR)، لأن MPEG-2 عادة ما يكون VBR، ولكن مع الحد الأقصى لمعدل البت للفيديو البالغ 2500 كيلوبت في الثانية. مع العلامة -f 4، يقوم المشفر أيضًا بتعيين GOP ديناميكي بحد أدنى 6 وحد أقصى 18. هذا يوفر بضعة بتات في الثانية ويحسن جودة الصورة أثناء تغيير المشاهد. عند الترميز باستخدام -f 4، يتجاهل mpeg2enc خيارات معدل بت الفيديو (-b) ونصف قطر البحث (-r). إذا استخدمت -f 5، فعليك تحديد معدل البت والخيارات الأخرى لـ mpeg2enc.

إمكانية أخرى للأفلام بتنسيق PAL (الطراز الأوروبي 25 إطارًا/50 حقلاً في الثانية) هي:

> lav2yuv stream.avi │ yuvscaler -O SVCD │ mpeg2enc -f 4 -I 0 -V 300 -o video.m2v

يتم تصوير الأفلام على فيلم بمعدل 24 إطارًا في الثانية. بالنسبة للبث PAL، يتم عرض الفيلم ببساطة "أسرع قليلاً" بمعدل 25 إطارًا في الثانية (مما يزعج الأشخاص ذوي الحس الموسيقي المطلق). العلامة -I 0 تلغي الحسابات المعقدة المطلوبة للتعويض عن تداخل الحقول، مما يؤدي إلى ترميز أسرع بكثير.

للأسف، الأفلام التي يتم بثها بتنسيق NTSC (الطراز الأمريكي 30 إطارًا/60 حقلاً في الثانية) سيؤدي هذا إلى ضغط ضعيف جدًا. أخذ العينات "pulldown" المستخدم لإنتاج 60 حقلاً في الثانية من فيلم بمعدل 24 إطارًا في الثانية يعني أن نصف الإطارات في NTSC هي متداخلة الحقول.

لا تنس خيارات -S و -B المذكورة أعلاه. أنت تريد أن يتناسب الدفق مع قرص CD، أليس كذلك؟ مثال دمج SVCD

> mplex -f 4 -b 300 -r 2750 sound.mp2 video.m2v -o svcd_out.mpg

-f 4

يخبر mplex بدمج SVCD

-r 2750

هو معدل البت المحسوب للصوت + الفيديو + 1-2% معلومات الدمج

-b 300

هو المخزن المؤقت المتاح في جهاز التشغيل (نفس القيمة المستخدمة لترميز الفيديو (خيار -V الخاص بـ mpeg2enc)). إنشاء SVCD للقرص المضغوط

مثال:

> vcdimager -t svcd testvideo.mpg

ينشئ videocd.bin، وهو ملف البيانات، و videocd.cue الذي يستخدم كملف تحكم لـ cdrdao.

إنشاء أقراص DVD

كان هذا البيان صحيحًا قبل بضع سنوات: كل شيء في هذا القسم جديد. قد لا توجد القيود التي أذكرها هنا في الإصدار الحالي. حاليًا (ديسمبر 2007)، يعمل إنشاء أقراص DVD.

من الواضح أنك تحتاج إلى جهاز تسجيل DVD. كنت أمتلك جهاز Ricoh DVD+RW يعمل، وأعلم عن جهاز تسجيل DVD-RAM قادر على حرق DVD-R. تعمل هذه الأقراص أيضًا مع مشغل DVD. الآن معظم أجهزة تسجيل DVD قادرة على حرق كلا الوسيطين + و -، لذلك لا ينبغي أن تكون هذه مشكلة بعد الآن. تعتمد البرامج التي تستخدمها للحرق على محرك جهاز تسجيل DVD.

لإنشاء وكتابة ملفات VOB و IFO و BUP، نستخدم dvdauthor. متاح من Sourceforge (ربما كنت قد خمنت ذلك). مثال إنشاء صوت DVD

> lav2wav stream.eli │ mp2enc -o sound.mp2

يجب أن يكون معدل العينة 48 كيلو هرتز. ينشئ mp2enc افتراضيًا معدل عينة 48 كيلو هرتز. إذا لم يكن 48 كيلو هرتز، فسيعيد mp2enc أخذ عينات الصوت للحصول على معدل العينة. إذا تم تسجيل الصوت بمعدل 48 كيلو هرتز، فلا يلزم إعادة أخذ العينات ويمكن استخدام toolame للترميز (إنه أسرع من mp2enc). مثال إنشاء فيديو DVD

> lav2yuv stream.eli │ mpeg2enc -f 8 -o video.m2v

-f 8

يقوم هذا بتعيين الخيارات بشكل صحيح لفيديو MPEG-2 متوافق مع معيار DVD. يبلغ الحد الأقصى لمعدل البت 7500 كيلوبت في الثانية وحجم المخزن المؤقت للفيديو 230 كيلوبت. يتم تعيين عامل الجودة الافتراضي على 8. لا يقوم mpeg2enc حاليًا بتعيين طول تسلسل تلقائي كما يفعل مع VCD/SVCD.

يمكن أيضًا استخدام خيارات أخرى للحصول على دفق بمعدل بت منخفض وجودة عالية لتجاوز الإعدادات الافتراضية المذكورة أعلاه. يمكنك أيضًا استخدام yuvdenoise لزيادة جودة الصورة إذا كانت البيانات المدخلة مشوشة (من شريط VHS على سبيل المثال). سيبدو الأمر عادةً كالتالي:

إنشاء مقاطع فيديو DIVX

lav2avi.sh

طريقة أخرى لإنشاء DIVX هي برنامج mencoder وهو من مشروع mplayer. لمزيد من المعلومات حول mencoder، يرجى قراءة تعليمات ووثائق mencoder/mplayer. يمنح المرور الأول والمرور الثاني في النهاية تلميحات لمعدل البت يمكن استخدامها للترميز بحجم معين (650 ميجابايت، 700 ميجابايت، و 800 ميجابايت). يستخدم البرنامج النصي lav2avi.sh هذه المعلومات إذا تم توفيرها (للتيارات القصيرة يتم تجاهلها بواسطة mencoder). ابحث عن المعلمة preferedSize في البرنامج النصي. يمكنك أيضًا تحديد معلمات أخرى تستخدم للترميز باستخدام خيار encoderParam في البرنامج النصي. لوصف المعلمات القابلة للاستخدام، انظر إلى دليل mplayer/mencoder.

اسم ملف الإخراج هو اسم ملف الإدخال الخاص بك (الخيار الأول) ولكن مع امتداد avi. إذا كان حجم الملف أقل من المحدد بواسطة preferedSize، فذلك لأن المصدر كان ذا جودة عالية جدًا (لا يوجد ضوضاء) وكان معدل البت المحدد أعلى من المطلوب. تحصل عادةً على 700 ميجابايت لفيلم مدته 1.5 ساعة بحجم صورة نصف بالحجم بمعدل بت حوالي 900، وهذا يعني جودة جيدة لـ divx (بافتراض مواد المصدر ذات الجودة الجيدة بالطبع).

يقوم البرنامج النصي بإجراء ترميز من 3 خطوات:

الخطوة 1 - ترميز الصوت

الخطوة 2 - المرور الأول للفيديو

الخطوة 3 - المرور الثاني للفيديو

تعتبر وثائق mplayer/mencoder طريقة الترميز من 3 تمريرات (يمكن أن تسبب مشاكل مزامنة الصوت/الفيديو) وتوصي باستخدام طريقة المرور 2. وثائق mencoder/mplayer واسعة النطاق وتحتوي على العديد من التلميحات المفيدة (وحاسبة معدل البت في دليل الأدوات/directory).

للترميز، استخدم برنامج الترميز السريع ffmpeg (lavc). يعطي نتائج جيدة مع أداء عالٍ. لترميز الصوت، يتم استخدام mp3. لترميز جميع الأجزاء، يستخدم أنابيب Unix. هذا يعني أنك لا تحتاج إلى مساحة إضافية على محرك الأقراص الثابتة الخاص بك حيث ستتم جميع المعالجات الرئيسية.

تحسين الدفق

تساعد المرشحات على زيادة جودة الصورة لدفقات الفيديو ذات معدل البت الثابت (CBR). مع معدل البت المتغير (VBR) للفيديو، يتم تقليل حجم الملف.

مثال:

> lav2yuv stream.avi │ yuvmedianfilter │ mpeg2enc -o video.m1v

هنا يتم استخدام برنامج yuvmedianfilter لتحسين الصورة. يزيل هذا بعض الضوضاء منخفضة التردد في الصور. كما أنه ينعم الصورة قليلاً. يأخذ مؤشرًا مركزيًا ويحسب متوسط ​​البكسلات المحيطة به التي تقع ضمن الحد المحدد. ثم يستبدل البكسل المركزي بهذه القيمة الجديدة. يمكنك أيضًا استخدام خيار -r (نصف القطر) لـ othe

تعديل نسبة العرض إلى الارتفاع للعينة. إذا كان لديك فيديو متشابك، فيجب أن يكون الارتفاع وارتفاع الإزاحة مضاعفًا للرقم 4 إذا كان الفيديو متشابكًا. وإلا، يجب أن تكون القيم (العرض، الارتفاع، عرض الإزاحة، ارتفاع الإزاحة) مضاعفًا للرقم 2.

مشكلة لا يمكن حلها بسهولة عن طريق القياس هي عندما لا تكون الصورة في المنتصف أفقيًا. على جانب واحد لا توجد لديك وحدات بكسل سوداء وعلى الجانب الآخر لديك 30 على سبيل المثال. القياس هنا هو الحل الخاطئ. y4mshift هو الحل الأمثل لأنه يمكنه إزاحة الصورة إلى اليسار أو اليمين.

lav2yuv test.eli │ y4mshift -n 20 │ mpeg2enc -f 3 -b 4000 -q 10 -o video.m2v

سيؤدي ذلك إلى إزاحة الصورة 20 بكسل إلى اليمين. إذا استخدمت رقمًا سالبًا، فسيتم إزاحة الصورة إلى اليسار. يجب عليك استخدام رقم زوجي. يتم تعيين وحدات البكسل المدرجة باللون الأسود.

قد يتساءل البعض لماذا الصورة ليست في المنتصف وهناك حدود سوداء حول الصورة عند عرض ما قمت بتسجيله. السبب في الحدود السوداء يكمن في تاريخ تقنية تلفزيون الأنبوب الكاثودي (CRT). تاريخ معايير التلفزيون هو قصة مثيرة للاهتمام للغاية ولكن هذا الموضوع موصوف في كتب أخرى (كبيرة).

لا يعرض التلفزيون الصورة الكاملة. لا يتم عرض جزء من الصورة بسبب المسح الزائد للتلفزيونات (أحيانًا يصل إلى 10٪ ولكن الأكثر شيوعًا اليوم هو 5٪). ولكن عند التقاط الفيديو ببطاقة، ترى الصورة بأكملها بما في ذلك الحدود التي تفقدها أجهزة التلفزيون بسبب المسح الزائد. عادةً ما لا يكون الإزاحة الأفقية مشكلة لبطاقة الالتقاط. إنها مشكلة عند بث الفيلم وليس مزامنتها بشكل صحيح مع الصورة. هذا يعني أن مسح المصدر غير متزامن تمامًا مع الإشارة الحاملة، ولن تلاحظ ذلك على التلفزيون.

تحويل معدل الإطارات

هل احتجت يومًا إلى تحويل معدل الإطارات من PAL إلى NTSC أو العكس؟ أو شيء أبسط بكثير مثل تحويل معدل الإطارات من 24 إطارًا في الثانية إلى 24000:1001 للتحويل من معدل إطارات فيلم إلى معدل إطارات NTSC صالح.

إذًا yuvfps هو برنامجك. يمكنه خفض معدل الإطارات عن طريق إسقاط الإطارات أو إنشاء معدل إطارات أعلى عن طريق تكرار الإطارات. إذا كان لديك معدل إطارات خاطئ في الرأس، يمكنك فقط تغيير رأس تيار YUV وليس تعديل التيار.

نظرًا لأنه يتم تكرار الإطارات فقط (نسخها)، يجب عليك إزالة الضوضاء أولاً ثم تغيير معدل الإطارات والقياس في الخطوة الأخيرة. إذا كان لديك مصدر متشابك، فيجب عليك أيضًا إزالة التشابك قبل تغيير معدل الإطارات. إذا قمت بإنشاء معدل إطارات أعلى، فمن المحتمل جدًا أن تواجه وميضًا غريبًا عند تشغيله. إذا قمت بتحويل PAL إلى NTSC (30000:1001 إطارًا في الثانية حوالي 29.97 إطارًا في الثانية)، فسيكون معدل الإطارات أقل بحوالي عامل 480/576 (خطوط NTSC / خطوط PAL). إذا قمت بخفض معدل الإطارات من PAL إلى NTSC (عند 24000:1001) أو NTSC FILM (24 إطارًا في الثانية)، فستكون معدل البت حوالي (480 خطًا * 24 إطارًا في الثانية) / (576 خطًا * 25 إطارًا في الثانية). إذا قمت بتغيير معدل الإطارات قبل إزالة الضوضاء، فسوف يواجه yuvdenoise مشكلات في العثور على الضوضاء عبر الإطارات وستزداد النطاق الترددي المطلوب قليلاً.

مثال

> lav2yuv video.eli │ yuvfps -r 30000:1001 │ yuvscaler -O SVCD │ mpeg2enc -f 4 -o video_ntsc_svcd.m2v

هذا مثال لتحويل الفيديو المصدر إلى فيديو NTSC يعمل بسرعة 30000:1001 إطارًا في الثانية (أو حوالي 29.97 إطارًا في الثانية) بحجم SVCD.

مثال

> lav2yuv video.eli │ yuvdenoise │ yuvfps -r 24000:1001 │ yuvscaler -O SIZE_720x480 │ mpeg2enc -f 3 -b 4000 -q 7 -o video_ntsc.m2v

يوضح هذا المثال كيفية استخدام الأدوات. إزالة الضوضاء أولاً ثم تغيير معدل الإطارات وفي الخطوة الأخيرة تغيير حجم الصورة.

قد يحدث أن yuvscaler أو mpeg2enc لا يكتشفان معيار التلفزيون بشكل صحيح. إذا حدث ذلك، فسيتعين عليك إضافة خيار المعيار -n n/p/s إلى البرنامج الذي يختار المعيار الخاطئ.

إذا كنت تعلم أن الرأس يخبر بمعدل الإطارات الخاطئ، يمكنك ببساطة تغيير معدل الإطارات لرأس YUV بهذه الطريقة:

> lav2yuv video.eli │ yuvfps -r 25:1 -c │ mpeg2enc -f 3 -b 4000 -q 7 -o video_pal.m2v

تحتاج إلى خيار -c. لإخبار yuvfps بأنه يجب عليه فقط تغيير رأس التيار. مع -r 25:1 أنت تخبر yuvfps بمعدل الإطارات الذي يجب أن يكتبه في الرأس. في مثالك، معدل إطارات PAL البالغ 25 إطارًا في الثانية. يجب عليك دائمًا استخدام الشكل الكسري.

إذا كنت تعلم أن الرأس خاطئ، وتحتاج إلى معدل بت إخراج مختلف، يمكنك القيام بذلك في خطوة واحدة:

> lav2yuv video.eli │ yuvfps -s 24:1 -r 25:1 │ mpeg2enc -o video.m1vإعادة ترميز MPEG-2 موجود

لإعادة ترميز تيارات MPEG-2 الموجودة من بطاقات التلفزيون الرقمي أو أقراص DVD، فإن معدل بيانات أقل من البث سيعطي نتائج جيدة. يعمل VCD القياسي 1152 كيلوبت في الثانية عادةً بشكل جيد لـ MPEG-1. الفرق هو في نسبة الإشارة إلى الضوضاء الأصلية. الضوضاء في المواد التناظرية تجعل الضغط أكثر صعوبة بكثير.

ستحتاج أيضًا إلى تعديل إزاحة تأخير الصوت يدويًا بالنسبة للفيديو عند التجميع. في كثير من الأحيان يبدو أن تأخيرًا قدره 150 مللي ثانية يقوم بالخدعة.

عليك تنزيل حزم ac3dec و mpeg2dec. يمكنك العثور عليها على صفحتهم الرئيسية: mpeg2dec ( ) و ac3dec. لفك تشفير تدفقات الصوت، يمكن أن يكون mpg123 و mplayer مفيدًا جدًا. تحتاج أيضًا إلى sox و toolame.

في دليل البرامج النصية، يوجد برنامج نصي mpegtranscode يقوم بمعظم العمل.

لذلك تبدو إعادة الترميز كالتالي:

> mjpegtranscode -V -o vcd_stream mpeg2src.mpg

-V

يحدد الخيارات بحيث يتم إنشاء تيار متوافق مع VCD

-o vcd_stream

يتم إنشاء vcd_stream.m1v (فيديو) و vcd_stream.mp2 (صوت)

mpeg2src.mpg

يحدد التيار المصدر

يقوم البرنامج النصي أيضًا بطباعة شيء مثل هذا:

> SYNC 234 mSec

ستحتاج إلى ضبط تأخيرات بدء الصوت/الفيديو عند التجميع لضمان مزامنة الصوت والفيديو. يتم طباعة التأخير الدقيق (بالمللي ثانية) الذي تحتاج إلى تمريره إلى mplex لمزامنة الصوت والفيديو باستخدام "-v" بواسطة أداة extract_a52 المسماة "SYNC" عند تشغيلها مع علامة "s". هذه هي القيمة التي يطبعها البرنامج النصي mjpegtranscode بعد كلمة SYNC.

ثم تحتاج إلى تجميعها كالتالي:

> mplex -f 1 -O 234 vcd_stream.mp2 vcd_stream.m1v -o lowrate.mpg

-f 1

تم تعيين تنسيق الدمج على VCD

-O 234

إزاحة الطابع الزمني للفيديو بالمللي ثانية، يتم إنشاؤها بواسطة البرنامج النصي mjpegtranscoding، حيث يُسمح بالقيم السالبة

vcd_stream.mp2 & vcd_stream.m1v

الملفات التي تم إنشاؤها بواسطة البرنامج النصي

lowrate.mpg

تيار الإخراج المتوافق مع VCD

هنا لدينا مثال SVCD (فيديو MPEG-2):

> mjpegtranscode -S -o svcd_stream mpeg2src.mpg

عليك دمجه مع:

> mplex -f 4 -O 234 svcd_stream.mp2 svcd_stream.m2v -o lowrate.mpg

مشكلة: هناك مشكلة في بعض الأحيان مع NTSC وتشغيل VCD لأن الأفلام قد يتم إعادة ترميزها باستخدام 3:2 pulldown NTSC مع 60 مجالًا في الثانية. تم تصميم mpeg2dec للتشغيل على أجهزة الكمبيوتر وينشئ معدل الإطارات الأصلي 24 إطارًا في الثانية. إذا قمت بترميز الفيديو الآن، يتم إنشاء فيديو 30 إطارًا في الثانية. هذا الفيديو الآن قصير جدًا بالنسبة للصوت المشفر.

يمكن أن تعمل إعادة الترميز ولكن يجب أن تتم يدويًا:

> mpeg2dec -s -o pgmpipe mpeg2src.mpg │ pgmtoy4m -a 59:54 -r 25:1 -i t │ mpeg2enc -I 0 -f 4 -q 9 -V 230 -p -P -o svcd_stream.m2v

يخبر العلامة -p mpeg2enc بإنشاء علامات رأس لـ 3:2 pulldown لفيلم 24 إطارًا في الثانية. قد تعمل أيضًا إذا لم تقم بإضافة العلامة -p. لست بحاجة إلى العلامة -p عند إعادة الترميز إلى تنسيق VCD لأنها غير مدعومة في mpeg1.

إذا كنت ترغب في القيام بكل خطوة بنفسك، فسيبدو الأمر شيئًا كهذا

استخراج الصوت:

> cat test2.mpg │ extract_a52 - -s │ ac3dec -o wav -p sound.wav 2>/dev/null

أحد الأسطر الأولى التي تظهر يحتوي على العلامة "SYNC" التي يجب عليك استخدامها لاحقًا عند التجميع. يقوم 2>/dev/null بإعادة توجيه إخراج ac3dec إلى /dev/null. في الخطوة التالية، تقوم بإنشاء ملف صوت MPEG:

> cat sound.wav │ mp2enc -V -v 2 -o audio.mp2

-V

يجبر تنسيق VCD، يتم تحويل معدل العينة إلى 44.1 كيلو هرتز من 48 كيلو هرتز

-v 2

غير ضروري ولكنه إذا استخدمته، يخبرك mp2enc بكم ثانية من الملف الصوتي تم ترميزها بالفعل.

-o

يحدد ملف الإخراج.

cat test2.mpg │ extract_a52 - -s │ ac3dec -o wav │ sox -t wav /dev/stdin -t wav -r 44100 /dev/stdout │ toolame -p 2 -b 224 /dev/stdin audio.mp2

أحد الأسطر الأولى مرة أخرى، يحتوي الإخراج على العلامة "SYNC". يجب عليك استخدام هذا الوقت (المشار إليه بـ "SYNC_value" أدناه) عند القيام بالتجميع.

لإنشاء VCD استخدم:

> mpeg2dec -s -o pgmpipe test2.mpg │ pgmtoy4m -a 59:54 -r 25:1 -i t │ mpeg2enc -s -o video_vcd.m1v

mpeg2dec:

-s

يخبر mpeg2dec باستخدام ديمالتكسر تدفق البرنامج

-o pgmpipe

تنسيق إخراج الصور، مناسب لـ pgmtoy4m
