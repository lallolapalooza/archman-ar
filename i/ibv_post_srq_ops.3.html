IBV_POST_SRQ_OPS(3) دليل مبرمج Libibverbs IBV_POST_SRQ_OPS(3)

الاسم

ibv_post_srq_ops - إجراء عمليات على قائمة انتظار الاستلام المشتركة (SRQ) الخاصة ذات الإعدادات الخاصة

الملخص

#include <infiniband/verbs.h>

int ibv_post_srq_ops(struct ibv_srq *srq, struct ibv_ops_wr *wr,
                     struct ibv_ops_wr **bad_wr);

الوصف

تقوم الدالة ibv_post_srq_ops() بتنفيذ سلسلة من عمليات التعديل على إعدادات خاصة من نوع SRQ srq. حالياً، تُستخدم لتكوين SRQ لمطابقة العلامات. سلسلة عمليات الإعداد معرفة بقوائم مرتبطة من عناصر struct ibv_ops_wr بدءًا من wr.

struct ibv_ops_wr {
uint64_t                wr_id;   /* معرف WR معرف من قبل المستخدم */
/* مؤشر إلى WR التالي في القائمة، NULL إذا كان WR الأخير */
struct ibv_ops_wr      *next;
enum ibv_ops_wr_opcode  opcode;  /* من enum ibv_ops_wr_opcode */
int                     flags;   /* من enum ibv_ops_flags */
struct {
/* عدد الرسائل غير المتوقعة
 * التي تتعامل معها البرامج */
uint32_t unexpected_cnt;
/* معامل الإدخال لعملية DEL
 * ومعامل الإخراج لعملية ADD */
uint32_t handle;
struct {
uint64_t                recv_wr_id;   /* معرف WR معرف من قبل المستخدم لـ TM_RECV */
struct ibv_sge         *sg_list; /* مؤشر إلى مصفوفة s/g */
int                     num_sge; /* حجم مصفوفة s/g */
uint64_t                tag;
uint64_t                mask;    /* تعتبر الرسالة الواردة مطابقة إذا كان
                                    TMH.tag & entry.mask == entry.tag */
} add;
} tm;
};

يحتفظ الجزء الأول من struct ibv_ops_wr بفكرة ibv_send_wr. يحدد Opcode العملية المراد تنفيذها. حالياً، المدعومة هي قيم IBV_WR_TAG_ADD و IBV_WR_TAG_DEL و IBV_WR_TAG_SYNC. انظر أدناه لوصف مفصل.

للسماح بتسليم البيانات الموثوق به، تحتفظ TM SRQ بآلية تزامن خاصة على مستوى منخفض - مزامنة الطور. يشمل التعامل مع رسائل جانب الاستلام نشاطين متزامنين - نشر المخازن المؤقتة المعنونة بواسطة البرامج واستقبال الرسائل الواردة بواسطة الأجهزة. تعتبر هذه العملية متماسكة فقط إذا تم معالجة جميع الرسائل غير المتوقعة التي استقبلتها الأجهزة بالكامل في البرامج. لتمرير عدد الرسائل غير المتوقعة التي تمت معالجتها إلى الأجهزة، يجب استخدام الحقل unexpected_cnt ويجب تعيين علامة IBV_OPS_TM_SYNC.

لطلب WC لعمليات قائمة العلامات، يجب تمرير علامة IBV_OPS_SIGNALED. في هذه الحالة، سيتم إنشاء WC في CQ الخاص بـ TM SRQ، مع تحديد wr_id لـ WC.

تُستخدم العملية IBV_WR_TAG_ADD لإضافة إدخال علامة إلى قائمة مطابقة العلامات. يتكون إدخال العلامة من قائمة SGE، والعلامة & القناع (معاملات المطابقة)، ومعرف WR مبهم محدد من قبل المستخدم (يتم تمريره عبر حقل recv_wr_id) ويتم تحديده بشكل فريد بواسطة handle (تم إرجاعه بواسطة برنامج التشغيل). حجم قائمة مطابقة العلامات محدود بـ max_num_tags. حجم قائمة SGE محدود بـ max_sge.

تقوم العملية IBV_WR_TAG_DEL بإزالة إدخال علامة تمت إضافته سابقًا. يجب تعيين الحقل handle إلى القيمة التي تم إرجاعها بواسطة عملية IBV_WR_TAG_ADD التي تم إجراؤها سابقًا. قد تفشل العملية بسبب استهلاك العلامة المتزامن - في هذه الحالة، سيتم إرجاع الحالة IBV_WC_TM_ERR في WC.

قد تُستخدم العملية IBV_WR_TAG_SYNC إذا لم تكن هناك حاجة إلى تغييرات في قائمة المطابقة، فقط لتحديث عداد الرسائل غير المتوقعة.

تشير علامة IBV_WC_TM_SYNC_REQ التي تم إرجاعها في WC لعملية القائمة إلى أن مزامنة العداد مطلوبة. قد يتم أيضًا إرجاع هذه العلامة بواسطة WC الاستلام غير المتوقع، مما يطلب عملية IBV_WR_TAG_SYNC للحفاظ على اتساق TM.

قيمة الإرجاع

تُرجع الدالة ibv_post_srq_ops() القيمة 0 عند النجاح، أو قيمة errno عند الفشل (والتي تشير إلى سبب الفشل).
