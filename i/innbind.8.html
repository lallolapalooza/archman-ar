innbind(8)

الحزمة: inn

التراخيص: custom:INN

NAME

innbind

bind to and listen on network ports

SYNOPSIS

innbind [-f file descriptor] [-p port] [-a address]

DESCRIPTION

innbind is a small utility program used by innd and other programs that need to bind to and listen on network ports. It is designed to be run as a setuid root program to allow programs that are not running as root to bind to privileged ports (ports below 1024).

It is never run directly by the user. Instead, it is invoked by another program (such as innd) via a pipe or a socket, and given the file descriptor to bind to, the port number, and optionally the address to listen on.

The arguments are passed on the command line as a comma-separated list. The format is:

file descriptor,port,address,protocol

The protocol is optional and defaults to AF_INET (IPv4) if omitted.

The address is optional and defaults to binding to all available addresses on the host if omitted.

OPTIONS

-f file descriptor
This option is not used by innbind itself but is used by programs that invoke it to specify the file descriptor that was previously opened for the socket.
-p port
This option is not used by innbind itself but is used by programs that invoke it to specify the port number.
-a address
This option is not used by innbind itself but is used by programs that invoke it to specify the address to bind to.

SECURITY

Since innbind is typically run as setuid root, it is important that it is not vulnerable to any kind of abuse. It performs several checks before binding to a port:

  • It checks that the effective user ID is the news user (or whatever user was specified at configure time) and that the real user ID is also the news user.
  • It checks that the port number is not zero.
  • It checks that the protocol family is either AF_INET or AF_INET6.

DIAGNOSTICS

address family not specified
(Fatal) The protocol family was not specified on the command line.
bad port number %s
(Fatal) The port number specified on the command line is not a valid non-negative integer.
bind failed: %s
(Fatal) The call to bind(2) failed. The error message from the kernel is given.
can't bind to port %s
(Fatal) The call to bind(2) failed. The error message is given.
connect failed: %s
(Fatal) The call to connect(2) failed. The error message from the kernel is given.
file descriptor %d is not valid
(Fatal) The file descriptor specified on the command line is not a valid non-negative integer.
family %d is not non-negative
(Fatal) The protocol family specified on the command line is not a non-negative integer. It should be equal to either AF_INET or AF_INET6 on the system where innbind is run.
must be run by user %s (%lu), not %lu
(Fatal) When setuid root, innbind may only be run by the news user as specified at configure time ("news" by default), for security reasons.
no addresses specified
(Fatal) No arguments were given on the command line (except maybe -p).
port may not be zero in %s
(Fatal) The port number portion of the given command-line argument was zero.
unknown protocol family %s in %s
(Fatal) The protocol number portion of the given command-line argument is neither AF_INET nor AF_INET6.

EXAMPLES

As mentioned above, innbind is never run directly, only by innd and other programs that need to bind to and listen to network ports. Sample invocations by innd would be:

innbind 3,10,::,119

to bind the IPv6 socket on file descriptor 3 to port 119, all addresses, or:

innbind 6,2,10.0.0.3,433

to bind the IPv4 socket on file descriptor 6 to port 433 in the address 10.0.0.3.
