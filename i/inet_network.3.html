NAME

inet_network, inet_addr, inet_ntoa, inet_lnaof, inet_netof - local network address manipulation

LIBRARY

Sockets API (libresolv, libc)

SYNOPSIS

#include <arpa/inet.h>
in_addr_t inet_network(const char *cp);
in_addr_t inet_addr(const char *cp);
char *inet_ntoa(struct in_addr in);
in_addr_t inet_lnaof(struct in_addr in);
in_addr_t inet_netof(struct in_addr in);

DESCRIPTION

These functions are used to manipulate network addresses. The network address structure is defined in <netinet/in.h> as:

struct in_addr {
    in_addr_t s_addr;  /* address in network byte order */
};

The in_addr_t type is an unsigned 32-bit integer. Network addresses are typically stored in this 32-bit field in network byte order (most significant byte first).

The function inet_network converts a character string representation of an IPv4 network number into a 32-bit number in network byte order. The string format is a number of dotted decimal components. The function interprets the number in base 10. If a component is preceded by `0x” or `0X”, it is interpreted in base 16. If a component is preceded by `0”, it is interpreted in base 8. The function supports the internet standard "dotted decimal" notation. A common usage is to convert a network name (from the networks(5) file) into its network number.

The function inet_addr converts the IPv4 address supplied in the character string cp into a 32-bit unsigned integer (in network byte order). The string must be in the standard IPv4 dotted decimal format.

The function inet_ntoa converts the IPv4 address supplied in network byte order in the in.s_addr field of the structure pointed to by in into a character string in network standard dotted decimal format. **Note:** This function returns a pointer to a statically allocated buffer. Use this pointer immediately. The buffer is overwritten by every call to inet_ntoa.

The function inet_lnaof returns the local network address part of an IPv4 address in. The function inet_netof returns the network number part of an IPv4 address in.

The functions inet_addr and inet_network return the value INADDR_NONE (typically -1, i.e., 255.255.255.255) if the input string is not a valid address or network number.

The functions inet_lnaof and inet_netof return an in_addr_t value. The interpretation depends on the address class.

For Class A addresses, the first byte is the network number and the remaining three bytes are the local network address. inet_netof returns the first byte, and inet_lnaof returns the remaining three bytes.

For Class B addresses, the first two bytes are the network number and the last two bytes are the local network address. inet_netof returns the first two bytes, and inet_lnaof returns the last two bytes.

For Class C addresses, the first three bytes are the network number and the last byte is the local network address. inet_netof returns the first three bytes, and inet_lnaof returns the last byte.

Addresses starting with 127. are loopback addresses.

The functions inet_aton and inet_ntop are newer alternatives. inet_ntop is a more capable replacement for inet_ntoa, and inet_pton is a more capable replacement for inet_addr and inet_network. They are not vulnerable to buffer overflows and support both IPv4 and IPv6 addresses.

The functions inet_addr and inet_network are obsolete. Use inet_pton instead.

The function inet_ntoa is obsolete. Use inet_ntop instead.

STANDARDS

The functions inet_addr, inet_network, and inet_ntoa conform to POSIX.1-2001 and POSIX.1-2008. The functions inet_lnaof and inet_netof are not specified by POSIX.

NOTES

The functions inet_addr and inet_network have been deprecated by POSIX.1-2008. The function inet_ntoa has been deprecated by POSIX.1-2001.

The return value of inet_addr for the IP address 0.0.0.0 is the same as the return value for an invalid input string, INADDR_NONE. Since 0.0.0.0 is a valid IP address, this is a design flaw.

The inet_lnaof and inet_netof functions are not part of the standard API and may not be available on all systems.

The character string representation of addresses handled by these functions is restricted to IPv4 dotted-decimal format. For support of IPv6 addresses and a more robust API, use inet_ntop(3) and inet_pton(3).

EXAMPLES

Convert a dotted-decimal string to network byte order:

#include <arpa/inet.h>
#include <stdio.h>
#include <stdlib.h>
int
main(void)
{
    struct in_addr ip_addr;
    const char *ip_str = "192.168.1.1";
    // Convert string to network byte order
    if (inet_aton(ip_str, &ip_addr) == 0) {
        fprintf(stderr, "Invalid IP address format\n");
        exit(EXIT_FAILURE);
    }
    printf("Dotted-decimal: %s\n", ip_str);
    printf("Network byte order: 0x%lx\n", (unsigned long)ip_addr.s_addr);
    // Convert network byte order back to dotted-decimal string
    printf("Converted back: %s\n", inet_ntoa(ip_addr));
    exit(EXIT_SUCCESS);
}

Convert the IP address 127.0.0.1 in hex:

#include <arpa/inet.h>
#include <stdio.h>
#include <stdlib.h>
int
main(int argc, char *argv[])
{
    struct in_addr addr;
    if (argc != 2) {
        fprintf(stderr, "%s <dotted-address>\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    if (inet_aton(argv[1], &addr) == 0) {
        fprintf(stderr, "Invalid address\n");
        exit(EXIT_FAILURE);
    }
    printf("%s\n", inet_ntoa(addr));
    exit(EXIT_SUCCESS);
}
