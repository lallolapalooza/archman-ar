الاسم

io_uring_prep_linkat - إعداد طلب linkat

مُلخص

#include <fcntl.h>
#include <unistd.h>
#include <liburing.h>
void io_uring_prep_linkat(struct io_uring_sqe *sqe,
                          int olddirfd,
                          const char *oldpath,
                          int newdirfd,
                          const char *newpath,
                          int flags);
void io_uring_prep_link(struct io_uring_sqe *sqe,
                        const char *oldpath,
                        const char *newpath,
                        int flags);

الوصف

تقوم الدالة io_uring_prep_linkat(3) بإعداد طلب linkat. يتم إعداد مدخل قائمة الانتظار للإدخال sqe لاستخدام واصف الملف للمجلد القديم المشار إليه بواسطة olddirfd والمسار القديم المشار إليه بواسطة oldpath مع واصف الملف للمجلد الجديد المشار إليه بواسطة newdirfd والمسار الجديد المشار إليه بواسطة newpath وباستخدام العلامات المحددة في flags.

تقوم الدالة io_uring_prep_link(3) بإعداد طلب link. يتم إعداد مدخل قائمة الانتظار للإدخال sqe لاستخدام المسار القديم المشار إليه بواسطة oldpath والمسار الجديد المشار إليه بواسطة newpath، كلاهما نسبي للمجلد الحالي وباستخدام العلامات المحددة في flags.

تُعد هذه الدوال طلب linkat(2) أو link(2) غير متزامن. راجع صفحات الدليل المتعلقة بالتفاصيل.

قيمة الإرجاع

لا شيء

الأخطاء

سيحتوي حقل res الخاص بـ CQE على نتيجة العملية. انظر صفحة الدليل ذات الصلة للتفاصيل حول القيم الممكنة. لاحظ أنه بينما تقوم استدعاءات النظام المتزامنة بإرجاع -1 عند الفشل وتعيين errno إلى قيمة الخطأ الفعلية، لا تستخدم io_uring errno أبدًا. بدلاً من ذلك، فإنها ترجع errno المنفي مباشرة في حقل res الخاص بـ CQE.

ملاحظات

كما هو الحال مع أي طلب يمرر البيانات في هيكل، يجب أن تظل هذه البيانات صالحة حتى يتم تقديم الطلب بنجاح. ليست هناك حاجة لأن تظل صالحة حتى الانتهاء. بمجرد تقديم طلب، تكون الحالة داخل النواة مستقرة. تتطلب النواة المبكرة جدًا (5.4 والإصدارات الأقدم) أن تظل الحالة مستقرة حتى يحدث الاكتمال. يمكن للتطبيقات اختبار هذا السلوك عن طريق فحص علامة IORING_FEAT_SUBMIT_STABLE التي تم إرجاعها من io_uring_queue_init_params(3).
