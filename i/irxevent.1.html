irxevent(1)

الحزمة: lirc

التراخيص: GPL

IRXEVENT(1) أوامر المستخدم IRXEVENT(1)

الاسم

irxevent - مرسل أحداث X بالأشعة تحت الحمراء

الملخص

irxevent [خيار]... [ملف الإعداد]

الوصف

Irxevent هو برنامج لإرسال نقرات الأزرار وضغطات المفاتيح إلى تطبيقات X يتم تشغيلها بواسطة جهاز تحكم عن بعد يعمل بتقنية LIRC. يمكنك التحكم في مشغل الأقراص المدمجة/MP3 المفضل لديك، أو برنامج موالف التلفزيون الخاص بك، أو أي تطبيق X آخر يستجيب لإدخال لوحة المفاتيح أو الماوس. إذا كنت ترغب في ذلك، يمكنك إرسال emacs ^X^S من كرسيك.

Irxevent هو مكمل لـ irexec(1) و irpty(1).

الخيارات

-d --daemon
تشغيل العملية في الخلفية
-h --help
عرض ملخص الاستخدام
-V --version
عرض الإصدار

الملفات

يعمل Irxevent بنفس ملف الإعداد الخاص بـ irexec و irpty (~/.config/lircrc). للحصول على عينة lircrc كاملة، انظر examples/lircrc.

يمكن أن يبدو جزء من .lircrc الخاص بك كالتالي:

begin
        prog = irxevent
        button = VIDEO_UP
        config = Key SHIFT-KP_Add CurrentWindow
end
begin
        prog = irxevent
        button = VIDEO_DOWN
        config = Key SHIFT-KP_Subtract CurrentWindow
end
begin
        prog = irxevent
        button = STOP
        config = Key ctrl-c CurrentWindow
end
begin
        prog = irxevent
        button = 0
        config = Key f xawtv
        config = Key f xawtv
end
begin
        prog = irxevent
        button = POWER
        config = Key q xawtv
end
begin
        prog = irxevent
        button = CH_DOWN
        config = Button 1 329 92 kscd
end
begin
        prog = irxevent
        button = UP
        config = Button 1 110 80 GQmpeg
end
begin
        prog = irxevent
        button = DOWN
        config = Button 1 130 80 GQmpeg
end

ببساطة، يمكن أن تبدو سطور config كالتالي:

config = Key [shift-][ctrl-][alt-]<key> [Focus] <windowname>
        | WindowID <id> | CurrentWindow | RootWindow
config = Button <button> <x> <y> [Focus] <windowname> | WindowID <id>
        | CurrentWindow | RootWindow
config = xy_Key <x> <y> [shift-][ctrl-][alt-]<key> [Focus]
        <windowname> | WindowID id | CurrentWindow | RootWindow

بعض الأمثلة الإضافية:

config = Key Up xawtv
config = Key Down xawtv
config = Button 1 50 110 xclickme
config = Key q xawtv
config = Key ctrl-c mpg123
config = Key shift-Page_Up rxvt

في BNF، يبدو هذا كالتالي:

LINE    = "config =" <KEY|BUTTON|XYKEY> <TARGET> |
          "config =" <KEY|BUTTON|XYKEY> "Focus" <TARGET>
XYKEY   = "xy_Key" <x_position> <y_position> <MOD><KEYSPEC>
KEY     = "Key" <MOD><KEYSPEC>
MOD     = ["shift-"]["numlock-"]["ctrl-"]["alt-"]["meta-"]
          ["numlock-"]["mod3-"]["mod4-"]["mod5-"]["altgr-"]["scrlock-"]
KEYSPEC = Keyname | "KeySym:"KeySym | "KeyCode:"KeyCode
BUTTON  = "Button" <1..5> <x_position> <y_position>
TARGET  = Windowname | "WindowID" id | "CurrentWindow" | "RootWindow"

Keyname:

هو الرمز المفتاحي المعلن في نوافذ X. على سبيل المثال، يشير "Up" إلى سهم المؤشر المتجه للأعلى. "KP_Add" هو علامة الزائد في لوحة الأرقام. فقط ألقِ نظرة على irxevent.keys (في دليل التوثيق) إذا لم تكن متأكدًا من اسم الرمز.
KeySym:
الرقم الذي تم إرجاعه بواسطة XStringToKeysym(3x).
KeyCode:
الرقم الذي تم إرجاعه بواسطة XKeysymToKeycode(3x).
Windowname:
يمكن أن يكون الأحرف الأولى من اسم النافذة المعروض بواسطة مدير النوافذ أو الاسم المعروض أسفل الأيقونة. تستخدم بعض البرامج اسم النافذة المعروض بواسطة مدير النوافذ لعرض الكثير من معلومات الحالة ولكنها لا تغير اسم الأيقونة (مثل xawtv). يضيف البعض الآخر معلومات إلى اسم النافذة ("GQmpeg - kill_windooz.mp3"). إذا لم يتطابق اسم النافذة أو اسم الأيقونة مع معلومات Windowname المعطاة، فسيتم فحص XClassHint(3x).
CurrentWindow:
يشير إلى النافذة النشطة كما تم إرجاعها بواسطة XGetInputFocus(3x). في معظم الأحيان، تكون هذه هي النافذة التي يوجد بها مؤشر الماوس الخاص بك.
RootWindow:
يشير إلى النافذة الرئيسية كما تم إرجاعها بواسطة RootWindow(3x). قد تحتاج إلى هذا لإرسال أحداث إلى مدير النوافذ.
WindowID id:
يشير إلى النافذة ذات معرف النافذة id. يجب أن يكون id رقمًا عشريًا. إنه مفيد عندما لا يتمكن irxevent من العثور على النافذة المطلوبة بوسائل أخرى.
Focus:
سيتم إرسال الحدث المحدد إلى النافذة المعطاة فقط إذا كان لديها التركيز الحالي للإدخال. هذا بالطبع لا معنى له عند دمجه مع CurrentWindow.

استكشاف الأخطاء وإصلاحها

إذا واجهت مشاكل في العثور على الإحداثيات لنقرة زر، يمكنك تجربة xev -id <window_id>. يمكن العثور على window_id باستخدام xwininfo.

هناك برامج لا تقبل أي أحداث اصطناعية افتراضيًا لأنها قد تسبب مشاكل أمنية. حاليًا، من المعروف أن xterm و xemacs يتجاهلان الأحداث التي يحاكيها irxevent.

ومع ذلك، يمكنك جعل xterm يقبل الأحداث الخارجية عن طريق تمكين "Allow SendEvents" في "Main Options" (اضغط باستمرار على زر Ctrl واضغط على زر الماوس الأيسر داخل نافذة xterm). يمكنك أيضًا وضع هذا السطر في ملف .Xresources الخاص بك لتغيير هذا بشكل دائم:

XTerm.vt100.allowSendEvents: true

هناك طريقة أخرى وهي بدء تشغيل xterm بهذا الشكل:

xterm -xrm "XTerm.vt100.allowSendEvents: true"

سيقبل xemacs الأحداث إذا قمت بتعيين متغير داخلي. ما يلي تم أخذه من المساعدة عبر الإنترنت:

`x-allow-sendevents' هو متغير منطقي مدمج.

القيمة: t

التوثيق:

*Non-nil يعني السماح بالأحداث الاصطناعية. Nil يعني أنها تم تجاهلها.

تحذير: السماح لـ emacs بمعالجة SendEvents يفتح ثغرة أمنية كبيرة.

للسماح بالأحداث، يجب عليك تقييم كود lisp هذا (اضغط Meta-x وأدخل التعبير التالي):


(setq x-allow-sendevents t)

وضع هذا السطر في ملف .xemacs-options الخاص بك يجب أن يؤدي إلى نفس النتيجة.

إذا واجهت مشاكل في إرسال الأحداث، يرجى إرسال بريد إلكتروني إلي.
