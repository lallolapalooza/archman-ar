الاسم

io_uring_prep_socket - إعداد طلب إنشاء مقبس

الملخص

#include <sys/socket.h>
#include <liburing.h>
void io_uring_prep_socket(struct io_uring_sqe *sqe,
                          int domain,
                          int type,
                          int protocol,
                          unsigned int flags);
void io_uring_prep_socket_direct(struct io_uring_sqe *sqe,
                                 int domain,
                                 int type,
                                 int protocol,
                                 unsigned int file_index,
                                 unsigned int flags);
void io_uring_prep_socket_direct_alloc(struct io_uring_sqe *sqe,
                                 int domain,
                                 int type,
                                 int protocol,
                                 unsigned int flags);

الوصف

تقوم الدالة io_uring_prep_socket(3) بإعداد طلب إنشاء مقبس. يتم إعداد مدخل صف الإرسال sqe لاستخدام نطاق الاتصال المحدد بواسطة domain واستخدام نوع الاتصال المحدد بواسطة type والبروتوكول المحدد بواسطة protocol. الوسيط flags غير مستخدم حاليًا.

تعمل الأداة المساعدة io_uring_prep_socket_direct(3) تمامًا مثل io_uring_prep_socket(3)، باستثناء أنها تقوم بربط المقبس بوصف مباشر بدلاً من إرجاع واصف ملف عادي. يجب تعيين الوسيط file_index إلى الفتحة التي يجب استخدامها لهذا المقبس.

تعمل الأداة المساعدة io_uring_prep_socket_direct_alloc(3) تمامًا مثل io_uring_prep_socket_direct(3)، باستثناء أنها تقوم بتخصيص واصف مباشر جديد بدلاً من تمرير فتحة مجانية. وهي تعادل استخدام io_uring_prep_socket_direct(3) مع IORING_FILE_INDEX_ALLOC كالوسيط file_index. عند الانتهاء، سيقوم الحقل res في CQE بإرجاع الفتحة المباشرة التي تم تخصيصها للمقبس.

إذا تم استخدام البدائل المباشرة، فيجب على التطبيق أولاً تسجيل جدول ملفات باستخدام io_uring_register_files(3) بالحجم المناسب. بمجرد التسجيل، يمكن لطلب مقبس مباشر استخدام أي إدخال في هذا الجدول، طالما أنه ضمن حجم الجدول المسجل. إذا كان الإدخال المحدد يحتوي بالفعل على ملف، فسيتم إزالة الملف أولاً من الجدول وإغلاقه. وهو متسق مع سلوك تحديث ملف موجود باستخدام io_uring_register_files_update(3).

بالنسبة لطلب مقبس واصف مباشر، يمكن تعيين الوسيط file_index إلى IORING_FILE_INDEX_ALLOC. في هذه الحالة، سيتم استخدام فتحة مجانية في جدول ملفات io_uring تلقائيًا وسيتم إرجاع فهرس الملف كـ CQE res. سيتم إرجاع -ENFILE بخلاف ذلك إذا لم تكن هناك فتحات مجانية في جدول ملفات io_uring.

تقوم هذه الدوال بإعداد طلب socket(2) غير متزامن. راجع صف الدليل الخاص به للحصول على التفاصيل.

قيمة الإرجاع

لا شيء

الأخطاء

سيحتوي الحقل res في CQE على نتيجة العملية. راجع صف الدليل ذي الصلة للحصول على تفاصيل حول القيم المحتملة. لاحظ أنه حيث ستعيد استدعاءات النظام المتزامنة -1 عند الفشل وتعيين errno إلى قيمة الخطأ الفعلية، فإن io_uring لا تستخدم errno أبدًا. بدلاً من ذلك، تعيد errno المنفية مباشرة في حقل res الخاص بـ CQE.
