ip-vrf(8)

الحزمة: iproute2

التراخيص: GPL-2.0-or-later

IP-VRF(8) لينكس IP-VRF(8)

الاسم

ip-vrf - تشغيل أمر ضد VRF

المُلَخَّص


ip vrf { COMMAND | help }

ip vrf show [ NAME ]

ip vrf identify [ PID ]

ip vrf pids NAME

ip vrf exec [ NAME ] command...

الوصف

يوفر VRF عزلاً للحركة المرورية على الطبقة 3 للتوجيه، بشكل مشابه لكيفية استخدام VLAN لعزل حركة المرور على الطبقة 2. في الأساس، VRF هو جدول توجيه منفصل. ترتبط أجهزة الشبكة بـ VRF عن طريق إخضاع الجهاز لـ VRF. في تلك النقطة، تكون عناوين الشبكة المعينة للجهاز محلية لـ VRF مع نقل المسارات المضيفة والموصلة إلى الجدول المرتبط بـ VRF.

يمكن للعملية تحديد VRF باستخدام واجهات برمجة تطبيقات متعددة -- ربط المقبس بجهاز VRF باستخدام SO_BINDTODEVICE، أو تعيين ارتباط VRF باستخدام IP_UNICAST_IF أو IPV6_UNICAST_IF، أو تحديد VRF لرسالة معينة باستخدام IP_PKTINFO أو IPV6_PKTINFO.

افتراضيًا، لا ترتبط عملية بأي VRF. يمكن تعيين الارتباط صراحةً عن طريق جعل البرنامج يستخدم إحدى واجهات برمجة التطبيقات المذكورة أعلاه أو بشكل غير مباشر باستخدام مساعد لتعيين SO_BINDTODEVICE لجميع مقابس IPv4 و IPv6 (AF_INET و AF_INET6) عند إنشاء المقبس. هذا الأمر ip-vrf هو مساعد لتشغيل أمر ضد VRF معين مع توريث ارتباط VRF من الوالد إلى الابن.

ip vrf show [ NAME ] - عرض جميع VRF المكونة

يسرد هذا الأمر جميع VRF ومعرفات جداول التوجيه المقابلة لها. إذا تم تقديم NAME، فسيتم عرض VRF ومعرف الجدول هذا فقط. الأمر الأخير مفيد للبرمجة النصية حيث يكون معرف الجدول لـ VRF مطلوبًا.

ip vrf exec [ NAME ] cmd ... - تشغيل أمر cmd ضد VRF المسمى

يسمح هذا الأمر للتطبيقات غير الواعية بـ VRF بالتشغيل ضد VRF غير VRF الافتراضي (الجدول الرئيسي). يمكن تشغيل أمر ضد VRF الافتراضي عن طريق تمرير "default" كاسم VRF. هذا مفيد إذا كان shell الحالي مرتبطًا بـ VRF آخر (مثل VRF الإدارة).

يتطلب هذا الأمر تشغيل النظام مع cgroup v2 (مثل مع systemd، أضف systemd.unified_cgroup_hierarchy=1 إلى سطر أوامر النواة).

يتطلب هذا الأمر أيضًا تشغيله كـ root. بدلاً من ذلك، يمكن تشغيله بواسطة مستخدم غير مميز إذا تم توفير capabilities(7) التالية:

CAP_BPF
لتحميل برنامج BPF.
CAP_NET_ADMIN
لوضع المقبس في cgroup.
CAP_DAC_OVERRIDE
لإنشاء دليل فرعي لـ cgroup في /sys.
إذا تمت إضافة هذه الصلاحيات، وإذا تم بناء ip(8) بـ libcap(3)، فسيتم إسقاط هذه الصلاحيات قبل تنفيذ cmd بواسطة ip vrf exec. بالنسبة لكل استدعاء آخر غير مميز لـ ip(8)، سيتم إسقاط جميع الصلاحيات.

ملاحظة: لن يتم إسقاط الصلاحيات إذا تم تعيين CAP_NET_ADMIN إلى INHERITABLE لتجنب كسر البرامج ذات الصلاحيات المحيطة التي تستدعي ip.

ip vrf identify [PID] - الإبلاغ عن ارتباط VRF للعملية

يعرض هذا الأمر ارتباط VRF للعملية المحددة. إذا لم يتم تحديد PID، فستُستخدم معرف العملية الحالية.

ip vrf pids NAME - الإبلاغ عن العمليات المرتبطة بـ VRF المسمى

يعرض هذا الأمر معرفات جميع العمليات المرتبطة بـ VRF المحدد.

تحذيرات

يتطلب هذا الأمر نواة تم تجميعها مع تمكين CGROUPS و CGROUP_BPF.

مساعد VRF يؤثر *فقط* على مقابس طبقة الشبكة.

أمثلة

ip vrf exec red ssh 10.100.1.254

تشغيل ssh إلى 10.100.1.254 ضد جدول VRF red.
