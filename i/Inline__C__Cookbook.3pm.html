Inline__C__Cookbook(3pm)

Inline::C::Cookbook(3) وثائق Perl المساهمة من قبل المستخدم Inline::C::Cookbook(3)

الاسم

Inline::C::Cookbook - مجموعة غنية من وصفات Inline C

الوصف

من الأسهل لمعظمنا طهي وجبة من وصفة، بدلاً من مجرد رمي الأشياء في وعاء حتى يتكون شيء صالح للأكل. وكذلك هو الحال مع البرمجة. "Inline.pm" تجعل برمجة C لـ Perl سهلة قدر الإمكان. وجود مجموعة من العينات سهلة الفهم يجعلها أبسط.

يهدف هذا الدليل إلى أن يكون مستودعًا متناميًا باستمرار لأمثلة الترميز الصغيرة والكاملة؛ كل منها يوضح كيفية إنجاز مهمة معينة باستخدام Inline. كل مثال يتبعه نقاش قصير، يشرح بالتفصيل الميزات الخاصة التي يتم توضيحها.

تم تكييف العديد من هذه الوصفات من مناقشات البريد الإلكتروني التي أجريتها مع مستخدمي Inline حول العالم. لقد كانت تجربتي حتى الآن أن Inline توفر حلاً أنيقًا لجميع المشاكل تقريبًا المتعلقة بـ Perl و C.

بالهناء والشفاء!

المشكلة

الحل
perl -e 'use Inline C=>q{void greet(){printf("Hello, world\n");}};greet'

اللحم والبطاطس

أنواع البيانات

المشكلة
كيف أمرر أنواعًا مختلفة من البيانات إلى وظائف Inline C ومنها؛ مثل السلاسل النصية والأرقام والأعداد الصحيحة؟
الحل
# vowels.pl
use Inline 'C';
$filename = $ARGV[0];
die "Usage: perl vowels.pl filename\n" unless -f $filename;
$text = join '', <>;           # قراءة ملف الإدخال بالكامل
$vp = vowel_scan($text);       # استدعاء دالتنا
$vp = sprintf("%03.1f", $vp * 100);  # تنسيق للطباعة
print "The letters in $filename are $vp% vowels.\n";
__END__
__C__
/* Find percentage of vowels to letters */
double vowel_scan(char* str) {
  int letters = 0;
  int vowels = 0;
  int i = 0;
  char c;
  char normalize = 'a' ^ 'A';
  /* normalize forces lower case in ASCII; upper in EBCDIC */
  char A = normalize | 'a';
  char E = normalize | 'e';
  char I = normalize | 'i';
  char O = normalize | 'o';
  char U = normalize | 'u';
  char Z = normalize | 'z';
  while(c = str[i++]) {
    c |= normalize;
    if (c >= A && c <= Z) {
       letters++;
       if (c == A || c == E || c == I || c == O || c == U)
         vowels++;
    }
  }
  return letters ? ((double) vowels / letters) : 0.0;
}
نقاش
يأخذ هذا البرنامج اسم ملف من سطر الأوامر ويطبع نسبة الأحرف المتحركة إلى الأحرف في هذا الملف. "vowels.pl" يستخدم دالة Inline C تسمى "vowel_scan"، تأخذ وسيط سلسلة نصية، وتعيد نسبة الأحرف المتحركة كرقم عشري بين 0 و 1. وهي تتعامل مع الأحرف الكبيرة والصغيرة، وتعمل مع ASCII و EBCDIC. وهي سريعة جدًا أيضًا.

تشغيل هذا البرنامج ينتج:

> perl vowels.pl /usr/dict/words
The letters in /usr/dict/words are 37.5% vowels.

من المهم جدًا ملاحظة أن الأمثلة في هذا الدليل تستخدم "char *" لتعني سلسلة نصية. داخليًا، تمتلك Perl آليات مختلفة للتعامل مع السلاسل النصية التي تحتوي على نقاط رمزية أعلى من 255، باستخدام Unicode. هذا يعني أن معالجة السلاسل النصية بشكل سطحي كـ "char *"، وهي مصفوفة من أحرف 8 بت، يمكن أن تؤدي إلى مشاكل. تحتاج إلى أن تكون على دراية بهذا والنظر في استخدام مكتبة UTF-8 للتعامل مع السلاسل النصية.

قوائم الوسائط المتغيرة

المشكلة

كيف أمرر قائمة وسائط ذات حجم متغير إلى دالة Inline C؟

الحل
greet(qw(Sarathy Jan Sparky Murray Mike));
use Inline C => <<'END_OF_C_CODE';
void greet(SV* name1, ...) {
  Inline_Stack_Vars;
  int i;
  for (i = 0; i < Inline_Stack_Items; i++)
    printf("Hello %s!\n", SvPV(Inline_Stack_Item(i), PL_na));
  Inline_Stack_Void;
}
END_OF_C_CODE
نقاش
يقوم هذا البرنامج الصغير بتحية مجموعة من الأشخاص، مثل زملائي في العمل. نستخدم صيغة الحذف (ellipsis) الخاصة بـ "C": ""...""، حيث يمكن أن تكون القائمة بأي حجم.

نظرًا لعدم وجود أنواع أو أسماء مرتبطة بكل وسيط، لا يمكننا توقع أن يتعامل XS مع التحويلات نيابة عنا. سنحتاج إلى سحبها من المكدس (Stack) بأنفسنا. لحسن الحظ، هناك دالتان (ماكرو) تجعل هذه المهمة سهلة للغاية.

أولاً، نحتاج إلى بدء دالتنا بـ ""Inline_Stack_Vars"" . هذا يعرّف بعض المتغيرات الداخلية التي نحتاجها للوصول إلى المكدس (Stack). الآن يمكننا استخدام ""Inline_Stack_Items""، والتي تعيد عددًا صحيحًا يحتوي على عدد الوسائط التي تم تمريرها إلينا من Perl.

ملاحظة: من المهم استخدام وحدات الماكرو ""Inline_Stack_"" فقط عند وجود حذف ("...") في قائمة الوسائط، *أو* أن نوع الإرجاع للدالة هو void.

ثانيًا، نستخدم الدالة Inline_Stack_Item(x) للوصول إلى كل وسيط حيث "0 <= x < items".

ملاحظة: عندما تقوم

قوائم الوسائط متغيرة الطول

المشكلة
كيف يمكنني استدعاء دالة C التي تتوقع قائمة وسائط متغيرة الطول؟
الحل
use Inline C => <<'END_OF_C_CODE';
#include <stdarg.h>
void print_numbers(int count, ...) {
    va_list ap;
    int i;
    va_start(ap, count);
    for (i=0; i<count; i++) {
        printf("%d ", va_arg(ap, int));
    }
    printf("\n");
    va_end(ap);
}
END_OF_C_CODE

print_numbers(5, 1, 2, 3, 4, 5);
print_numbers(3, 10, 20, 30);
مناقشة
عند تعريف دالة C التي تستخدم قوائم الوسائط متغيرة الطول، يجب عليك استخدام بنية "va_list" و "va_start" و "va_arg" و "va_end" .

يجب تمرير الوسيط الأول ( "count" في هذا المثال) قبل علامة القطع الناقص ( "..." ). عندما يقوم مترجم XS بالتحقق من الوسائط، سيصدر خطأ إذا مررت عددًا أقل من العدد المحدد من الوسائط. لذلك، لا توجد حاليًا طريقة لتمرير قائمة فارغة عندما تكون قائمة متغيرة الطول متوقعة.

قيم إرجاع متعددة

المشكلة
كيف يمكنني إرجاع قائمة من القيم من دالة C؟
الحل
print map {"$_\n"} get_localtime(time);
use Inline C => <<'END_OF_C_CODE';
#include <time.h>
void get_localtime(SV * utc) {
  const time_t utc_ = (time_t)SvIV(utc);
  struct tm *ltime = localtime(&utc_);
  Inline_Stack_Vars;
  Inline_Stack_Reset;
  Inline_Stack_Push(sv_2mortal(newSViv(ltime->tm_year)));
  Inline_Stack_Push(sv_2mortal(newSViv(ltime->tm_mon)));
  Inline_Stack_Push(sv_2mortal(newSViv(ltime->tm_mday)));
  Inline_Stack_Push(sv_2mortal(newSViv(ltime->tm_hour)));
  Inline_Stack_Push(sv_2mortal(newSViv(ltime->tm_min)));
  Inline_Stack_Push(sv_2mortal(newSViv(ltime->tm_sec)));
  Inline_Stack_Push(sv_2mortal(newSViv(ltime->tm_isdst)));
  Inline_Stack_Done;
}
END_OF_C_CODE
مناقشة
Perl هي لغة حيث من الشائع إرجاع قائمة من القيم من استدعاء روتين فرعي بدلاً من قيمة واحدة فقط. C ليست كذلك. لكي نتمكن من تحقيق ذلك في C، نحتاج إلى معالجة مكدس استدعاء Perl يدويًا. لحسن الحظ، توفر Inline وحدات ماكرو لتسهيل ذلك.

يستدعي هذا المثال دالة "localtime" النظامية، ويعيد كل جزء من هيكل الوقت؛ تمامًا مثل الدالة المدمجة في Perl localtime(). عند كل دفعة مكدس، نقوم بإنشاء عدد صحيح جديد من Perl (SVIV) وجعله فانيًا. يضمن استدعاء sv_2mortal() أن عدد المراجع مضبوط بشكل صحيح. بدونها، سيتسرب الذاكرة من البرنامج.

ملاحظة: لا يلزم وجود عبارة "#include" بشكل فعلي، لأن Inline
يتضمن تلقائيًا رؤوس Perl التي تتضمن جميع استدعاءات النظام القياسية تقريبًا.

قيم إرجاع متعددة (طريقة أخرى)

المشكلة
كيف يمكنني إرجاع أكثر من قيمة واحدة دون استخدام مكدس Perl؟
الحل
use Inline::Files;
use Inline 'C';
my ($foo, $bar);
change($foo, $bar);
print "\$foo = $foo\n";
print "\$bar = $bar\n";
__C__
int change(SV* var1, SV* var2) {
  sv_setpvn(var1, "Perl Rocks!", 11);
  sv_setpvn(var2, "Inline Rules!", 13);
  return 1;
}
مناقشة
معظم واجهات دالة Perl ترجع قيمًا كقائمة من قيمة واحدة أو أكثر. عدد قليل جدًا مثل "chomp" ، سيقوم بتعديل قيمة مدخلة في مكانها. من ناحية أخرى، في C، تفعل ذلك كثيرًا. يتم تمرير القيم بالمرجع وتعديلها في مكانها بواسطة الدالة المستدعاة.

تبين أنه يمكننا القيام بذلك مع Inline أيضًا. السر هو استخدام نوع من '"SV*"' لكل وسيط سيتم تعديله. هذا يضمن التمرير بالمرجع، لأنه لا حاجة لتعيين الأنواع.

يمكن للدالة بعد ذلك استخدام واجهة برمجة تطبيقات Perl5 للعمل على هذا الوسيط. عندما تعود السيطرة إلى Perl، سيحتفظ الوسيط بالقيمة التي حددتتها دالة C. في هذا المثال، مررنا قيمتين فارغتين وقمت بتعيين قيم لهما مباشرة.

أخذ مرجع مصفوفة كوسيط

المشكلة
كيف يمكنني أخذ مرجع مصفوفة Perl كوسيط في دالة C الخاصة بي؟
الحل
SV *sum(SV *array) {
    int total = 0;
    int numelts, i;
    if ((!SvROK(array))
        || (SvTYPE(SvRV(array)) != SVt_PVAV)
        || ((numelts = av_len((AV *)SvRV(array))) < 0)
    ) {
        return &PL_sv_undef;
    }
    for (i = 0; i <= numelts; i++) {
        total += SvIV(*av_fetch((AV *)SvRV(array), i, 0));
    }
    return newSViv(total);
}
مناقشة
يعيد هذا المثال "undef" إذا تم إعطاؤه غير مرجع، أو غير مرجع مصفوفة، أو مرجع لمصفوفة فارغة. يمكنك رؤية كيف يمكنك توسيع هذا لأخذ أكثر من مرجع مصفوفة واحد.

استخدام الذاكرة

المشكلة
كيف يجب أن أقوم بتخصيص مخازن مؤقتة في كود Inline C الخاص بي؟
الحل
print greeting('Ingy');
use Inline C => <<'END_OF_C_CODE';
SV* greeting(SV* sv_name) {
  return (newSVpvf("Hello %s!\n", SvPV(sv_name, PL_na)));
}
END_OF_C_CODE
مناقشة
في هذا المثال، سنعيد التحية إلى المتصل، بدلاً من طباعتها. قد يبدو هذا سهلاً للغاية، باستثناء حقيقة أننا بحاجة إلى تخصيص مخزن مؤقت صغير لإنشاء التحية.

أحثك على الابتعاد عن "malloc" لمخزن مؤقت خاص بك. فقط استخدم إدارة الذاكرة المدمجة في Perl. بعبارة أخرى، قم بإنشاء قيمة عددية جديدة من Perl. تقوم الدالة "newSVpv" بذلك بالضبط. و "newSVpvf" تتضمن وظائف "sprintf".

المشكلة الأخرى هي التخلص من هذه القيمة العددية الجديدة. كيف سيتم تقليل عدد المراجع بعد تمرير القيمة العددية مرة أخرى؟ توفر Perl أيضًا دالة تسمى "sv_2mortal". المتغيرات الفانية تموت عندما يخرج السياق عن النطاق. بعبارة أخرى، ستنتظر Perl حتى يتم تمرير القيمة العددية الجديدة مرة أخرى ثم تقلل عدد المراجع من أجلك، مما يجعلها مؤهلة لجمع القمامة. راجع "perldoc perlguts".

في هذا المثال، يتم استدعاء "sv_2mortal" بشكل خفي بواسطة XS، لأننا حددنا نوع الإرجاع ليكون "SV*".

لعرض كود XS الذي تم إنشاؤه، قم بتشغيل الأمر ""perl -MInline=INFO,FORCE,NOCLEAN example004.pl"". سيؤدي هذا إلى ترك دليل البناء سليمًا وسيخبرك بمكان العثور عليه.

الوصول المباشر إلى متغيرات Perl

المشكلة
هل يمكنني كتابة دالة Inline C يمكنها الوصول إلى متغير Perl مباشرة دون الحاجة إلى تمريره كوسيط؟
الحل
use strict;
use warnings;
use Inline C => "DATA";
our $mesh_data = "MESH-POINTS 0.0 0.0 0.5 0.25 1.0 0.5 1.5 0.75";
CalcSurfaceHeights();
__DATA__
__C__
#define N_MP 4
void CalcSurfaceHeights() {
   double x[N_MP], y[N_MP], z;
   int    ix;
   char   *mesh_data = SvPV_nolen(get_sv("main::mesh_data", 0));
   sscanf(mesh_data, "MESH-POINTS %lf%lf%lf%lf%lf%lf%lf%lf",
                     x, y, x+1, y+1, x+2, y+2, x+3, y+3);
   for (ix=0; ix < N_MP; ix++) {
      z = 0.5*( sin(x[ix]) + sin(y[ix]) );
      printf("Surface-Height: %6.3f Mesh-Point: %6.2f, %6.2f\n",
             z, x[ix], y[ix]);
   }
}
مناقشة
هناك نقطتان فقط تحتاجان إلى شرح لفهم سبب عمل الكود أعلاه. في قسم Perl، ستلاحظ الإعلان 
our $mesh_data = "...";

لكي تكون متغيرات Perl قابلة للوصول مباشرة من دوال Inline::C، يجب تعريفها كمتغيرات حزمة. المتغيرات المعجمية، تلك المعرفة بـ my ، لا يمكن الوصول إليها بهذه الطريقة.

في قسم كود C في المثال، السطر التالي هو ما يجعل الوصول المباشر إلى متغير Perl يعمل؛

char *mesh_data = SvPV_nolen(get_sv("main::mesh_data", 0))

هنا، SvPV_nolen() ترجع مؤشرًا إلى سلسلة C الموجودة في المتغير العددي. الاختلاف "_nolen" يتجاهل طول سلسلة C. وبالتالي، تأخذ الدالة وسيطًا واحدًا فقط، وهو SV* لمتغير العددي.

كان بإمكاننا استخدام الشكل المعتاد ذي الوسيطين لـ SvPV() ، وبما أننا لا نهتم بطول السلسلة، نحدد PL_na للوسيط الثاني. ثم سيتغير استدعاء الدالة إلى،

SvPV(get_sv("main::mesh_data", 0), PL_na)

الدالة get_sv() ترجع SV* لمتغير حزمة عددي مسمى. تأخذ سلسلة C، تحتوي على الاسم المؤهل بالكامل للمتغير، كوسيط أول
