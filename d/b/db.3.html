dbopen(3) دليل وظائف المكتبة dbopen(3)

الاسم

dbopen - طرق الوصول إلى قاعدة البيانات

المكتبة

مكتبة C القياسية (libc، -lc)

الملخص

#include <sys/types.h>
#include <limits.h>
#include <db.h>
#include <fcntl.h>
DB *dbopen(const char *path, int flags, int mode, DBTYPE type,
           const void *openinfo);

الوصف

ملاحظة هامة: هذه الصفحة توثق الواجهات التي تم توفيرها حتى glibc 2.1. منذ glibc 2.2، لم تعد glibc توفر هذه الواجهات. على الأرجح، أنت تبحث عن واجهات برمجة التطبيقات (APIs) التي توفرها مكتبة libdb بدلاً من ذلك.

dbopen() هي واجهة المكتبة لملفات قواعد البيانات. تشمل تنسيقات الملفات المدعومة btree، hashed، وملفات موجهة لنظام UNIX. تنسيق btree هو تمثيل لهيكل شجرة متوازنة ومرتبة. تنسيق hashed هو مخطط تجزئة ديناميكي قابل للتوسيع. تنسيق الملف المسطح هو ملف تيار بايت بسجلات ذات طول ثابت أو متغير. تم وصف التنسيقات والمعلومات الخاصة بتنسيق الملف بالتفصيل في صفحات دليلها المقابلة btree(3)، hash(3)، و recno(3).

dbopen() تفتح path للقراءة و/أو الكتابة. قد يتم إنشاء ملفات لم يُقصد بها الحفاظ عليها على القرص عن طريق تعيين وسيطة path إلى NULL.

الوسيطان flags و mode كما هو محدد في روتين open(2)، ومع ذلك، فقط العلامات O_CREAT، O_EXCL، O_EXLOCK، O_NONBLOCK، O_RDONLY، O_RDWR، O_SHLOCK، و O_TRUNC ذات معنى. (ملاحظة، لا يمكن فتح ملف قاعدة بيانات بـ O_WRONLY.)

وسيطة type هي من نوع DBTYPE (كما هو محدد في ملف التضمين <db.h>) ويمكن تعيينها إلى DB_BTREE، DB_HASH، أو DB_RECNO.

وسيطة openinfo هي مؤشر إلى هيكل خاص بطريقة الوصول موصوف في صفحة دليل طريقة الوصول. إذا كان openinfo هو NULL، فستستخدم كل طريقة وصول القيم الافتراضية المناسبة للنظام وطريقة الوصول.

dbopen() ترجع مؤشرًا إلى هيكل DB عند النجاح و NULL عند حدوث خطأ. يتم تعريف هيكل DB في ملف التضمين <db.h>، ويحتوي على الحقول التالية على الأقل:


typedef struct {
    DBTYPE type;
    int (*close)(const DB *db);
    int (*del)(const DB *db, const DBT *key, unsigned int flags);
    int (*fd)(const DB *db);
    int (*get)(const DB *db, DBT *key, DBT *data,
               unsigned int flags);
    int (*put)(const DB *db, DBT *key, const DBT *data,
               unsigned int flags);
    int (*sync)(const DB *db, unsigned int flags);
    int (*seq)(const DB *db, DBT *key, DBT *data,
               unsigned int flags);
} DB;

تصف هذه العناصر نوع قاعدة البيانات ومجموعة من الوظائف التي تقوم بإجراءات مختلفة. تأخذ هذه الوظائف مؤشرًا إلى هيكل تم إرجاعه بواسطة dbopen()، وأحيانًا مؤشرًا واحدًا أو أكثر لهياكل المفتاح/البيانات وقيمة علم (flag).

type
نوع طريقة الوصول الأساسية (وتنسيق الملف).
close
مؤشر إلى روتين لمسح أي معلومات مخبأة مؤقتًا على القرص، وتحرير أي موارد مخصصة، وإغلاق الملفات الأساسية. نظرًا لأنه يمكن تخزين أزواج المفاتيح/البيانات مؤقتًا في الذاكرة، فإن الفشل في مزامنة الملف باستخدام وظيفة close أو sync قد يؤدي إلى معلومات غير متناسقة أو مفقودة. تُرجع روتينات close -1 عند حدوث خطأ (مع تعيين errno) و 0 عند النجاح.
del
مؤشر إلى روتين لإزالة أزواج المفاتيح/البيانات من قاعدة البيانات.
قد يتم تعيين العلم flag إلى القيمة التالية:
R_CURSOR
حذف السجل الذي تشير إليه المؤشر. يجب أن يكون المؤشر قد تم تهيئته مسبقًا.
تُرجع روتينات delete -1 عند حدوث خطأ (مع تعيين errno)، 0 عند النجاح، و 1 إذا لم يكن key المحدد موجودًا في الملف.
fd
مؤشر إلى روتين يرجع واصف ملف تمثيلي لقاعدة البيانات الأساسية. سيتم إرجاع واصف ملف يشير إلى نفس الملف لجميع العمليات التي تستدعي dbopen() بنفس اسم path. يمكن استخدام واصف الملف هذا بأمان كوسيطة لوظائف القفل fcntl(2) و flock(2). لا يرتبط واصف الملف بالضرورة بأي من الملفات الأساسية التي تستخدمها طريقة الوصول. لا يتوفر واصف ملف لقواعد البيانات الموجودة في الذاكرة. تُرجع روتينات fd -1 عند حدوث خطأ (مع تعيين errno)، وواصف الملف عند النجاح.
get
مؤشر إلى روتين يمثل الواجهة لاسترداد البيانات المفهرسة من قاعدة البيانات. يتم إرجاع عنوان وطول البيانات المرتبطة بـ key المحدد في الهيكل الذي يشير إليه data. تُرجع روتينات get -1 عند حدوث خطأ (مع تعيين errno)، 0 عند النجاح، و 1 إذا لم يكن key موجودًا في الملف.
put
مؤشر إلى روتين لتخزين أزواج المفاتيح/البيانات في قاعدة البيانات.
يمكن تعيين العلم flag إلى إحدى القيم التالية:
R_CURSOR
استبدال زوج المفتاح/البيانات المشار إليه بواسطة المؤشر. يجب أن يكون المؤشر قد تم تهيئته مسبقًا.
R_IAFTER
إلحاق البيانات فورًا بعد البيانات التي يشير إليها key، مع إنشاء زوج مفتاح/بيانات جديد. يتم إرجاع رقم السجل لزوج المفتاح/البيانات الملحق في هيكل key. (ينطبق فقط على طريقة الوصول DB_RECNO.)
R_IBEFORE
إدراج البيانات فورًا قبل البيانات التي يشير إليها key، مع إنشاء زوج مفتاح/بيانات جديد. يتم إرجاع رقم السجل لزوج المفتاح/البيانات المدرج في هيكل key. (ينطبق فقط على طريقة الوصول DB_RECNO.)
R_NOOVERWRITE
إدخال زوج المفتاح/البيانات الجديد فقط إذا كان المفتاح غير موجود مسبقًا.
R_SETCURSOR
تخزين زوج المفتاح/البيانات، مع تعيين أو تهيئة موضع المؤشر للإشارة إليه. (ينطبق فقط على طريقتي الوصول DB_BTREE و DB_RECNO.)
R_SETCURSOR متاح فقط لطريقتي الوصول DB_BTREE و DB_RECNO لأنه يعني أن المفاتيح لها ترتيب جوهري لا يتغير.
R_IAFTER و R_IBEFORE متاحان فقط لطريقة الوصول DB_RECNO لأنهما يعنيان أن طريقة الوصول قادرة على إنشاء مفاتيح جديدة. هذا صحيح فقط إذا كانت المفاتيح مرتبة ومستقلة، مثل أرقام السجلات.
السلوك الافتراضي لروتينات put هو إدخال زوج المفتاح/البيانات الجديد، واستبدال أي مفتاح موجود سابقًا.
تُرجع روتينات put -1 عند حدوث خطأ (مع تعيين errno)، 0 عند النجاح، و 1 إذا تم تعيين العلم R_NOOVERWRITE وكان المفتاح موجودًا بالفعل في الملف.
seq
مؤشر إلى روتين يمثل الواجهة للاسترداد المتسلسل من قاعدة البيانات. يتم إرجاع عنوان وطول المفتاح في الهيكل الذي يشير إليه key، ويتم إرجاع عنوان وطول البيانات في الهيكل الذي يشير إليه data.
قد يبدأ استرداد أزواج المفاتيح/البيانات المتسلسلة في أي وقت، ولا يتأثر موضع "المؤشر" باستدعاءات روتينات del، get، put، أو sync. سيتم عكس التعديلات على قاعدة البيانات أثناء المسح المتسلسل في المسح، أي أن السجلات المدرجة خلف المؤشر لن يتم إرجاعها بينما السجلات المدرجة ...
