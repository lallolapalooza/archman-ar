NAME

dbm_clearerr, dbm_error, dbm_fetch, dbm_firstkey, dbm_nextkey, dbm_open, dbm_store, dbm_close - database subroutines

SYNOPSIS

#include <ndbm.h>

void dbm_clearerr(DBM *db);
int dbm_error(DBM *db);
datum dbm_fetch(DBM *db, datum key);
datum dbm_firstkey(DBM *db);
datum dbm_nextkey(DBM *db);
DBM *dbm_open(const char *name, int flags, mode_t mode);
int dbm_store(DBM *db, datum key, datum content, int replace);
void dbm_close(DBM *db);

DESCRIPTION

These functions provide a simple database maintenance facility. The database is maintained in two files. The first file contains a directory of keys and the second contains all the data. For a database named name, the files are named name.dir and name.pag.

The datum structure is used to pass data to and from these functions. It is defined as:

typedef struct {
    char    *dptr;  /* Pointer to the data */
    int      dsize; /* Size of the data */
} datum;

dbm_open() opens the database specified by name. The flags are formed by ORing the following constants:

DBM_RDONLY
Open for reading only.
DBM_WRCREAT
Open for reading and writing. Create the database if it does not exist.
DBM_INSERT
Open for reading and writing. Do not create the database if it does not exist.
DBM_FREEBLKSIZ
Open for reading and writing. Insert/replace as specified by dbm_store(). Create the database if it does not exist.
DBM_REPLACE
Open for reading and writing. Insert/replace as specified by dbm_store(). Do not create the database if it does not exist.

The mode argument is the mode for the database files if they are created.

dbm_close() closes the database file, writing any buffered information. It should be called before exiting.

dbm_store() stores the content datum associated with the key datum. If replace is non-zero, it replaces any existing entry for that key. If replace is zero, it does not modify the database if the key already exists. If the store is successful, it returns 0; otherwise, it returns -1. Note that the data is copied into the database, so the caller may free the memory pointed to by dptr, if desired.

dbm_fetch() retrieves the datum associated with the key datum. If the key is not found, it returns a datum with dptr set to NULL.

dbm_delete() deletes the entry for the given key. It returns 0 on success, and -1 on failure.

dbm_firstkey() returns the first key in the database. If the database is empty, it returns a datum with dptr set to NULL.

dbm_nextkey() returns the next key in the database. If there are no more keys, it returns a datum with dptr set to NULL.

dbm_error() returns non-zero if an error has occurred, and zero otherwise.

dbm_clearerr() clears the error flag for the database.

RETURN VALUE

dbm_open() returns a pointer to a structure which will be used to access the database, or NULL if an error occurred.

dbm_store() and dbm_delete() return 0 on success, and -1 on failure.

dbm_fetch(), dbm_firstkey(), and dbm_nextkey() return a datum structure. If the key is not found or the database is empty, the dptr field of the returned datum will be NULL.

dbm_error() returns non-zero if an error has occurred, and zero otherwise.

dbm_clearerr() returns nothing.

ERRORS

The specific errors are implementation-dependent. However, errors can occur due to:

  • Insufficient disk space.
  • File access permissions.
  • Corrupt database files.
  • The name argument is a prefix of an unrelated file.

EXAMPLES

To store and retrieve information:

    DBM     *db;
    datum   key, content, retrieved;

    db = dbm_open("mydata", DBM_WRCREAT, 0600);
    if (db == NULL) {
        perror("dbm_open");
        exit(1);
    }

    key.dptr = "name";
    key.dsize = strlen(key.dptr);
    content.dptr = "Alice";
    content.dsize = strlen(content.dptr);

    if (dbm_store(db, key, content, DBM_REPLACE) == -1) {
        perror("dbm_store");
        dbm_close(db);
        exit(1);
    }

    retrieved = dbm_fetch(db, key);
    if (retrieved.dptr != NULL) {
        printf("Found: %s\n", retrieved.dptr);
    } else {
        printf("Not found.\n");
    }

    dbm_close(db);

To iterate through the database:

    DBM     *db;
    datum   key, content;

    db = dbm_open("mydata", DBM_RDONLY, 0);
    if (db == NULL) {
        perror("dbm_open");
        exit(1);
    }

    for (key = dbm_firstkey(db); key.dptr != NULL; key = dbm_nextkey(db)) {
        content = dbm_fetch(db, key);
        printf("Key: %s, Content: %s\n", key.dptr, content.dptr);
    }

    dbm_close(db);

APPLICATION USAGE

The dbm_store() function requires that the caller pass pointers to data that remain valid until the next call to dbm_store() or dbm_close(). If the caller wishes to reuse or free the memory associated with a key or content datum after a call to dbm_store(), they must first copy the data.

The dbm_error() and dbm_clearerr() functions are provided for error checking. It is recommended that applications use these functions to check for errors after each call that can fail.

Because of the possibility of hash collisions, the dbm_store() function may be slow. Systems implementing these functions may use hashing techniques to organize the data. If two keys hash to the same value, the system must perform extra work to store and retrieve the data. In the worst case, all keys hash to the same value, and the database becomes a linked list. Creating and updating databases by use of these functions is relatively slow because of data copies that occur upon hash collisions. These functions are useful for applications requiring fast lookup of relatively static information that is to be indexed by a single key.

Note that a strictly conforming application is extremely limited by these functions: since there is no way to determine that the keys in use do not all hash to the same value (although that would be rare), a strictly conforming application cannot be guaranteed that it can store more than one block's worth of data in the database. As long as a key collision does not occur, additional data may be stored, but because there is no way to determine whether an error is due to a key collision or some other error condition (dbm_error() being effectively a Boolean), once an error is detected, the application is effectively limited to guessing what the error might be if it wishes to continue using these functions.

The dbm_delete() function need not physically reclaim file space, although it does make it available for reuse by the database.

After calling dbm_store() or dbm_delete() during a pass through the keys by dbm_firstkey() and dbm_nextkey(), the application should reset the database by calling dbm_firstkey() before again calling dbm_nextkey(). The contents of these files are unspecified and may not be portable.

Applications should take care that database pathname arguments specified to dbm_open() are not prefixes of unrelated files. This might be done, for example, by placing databases in a separate directory.

Since some implementations use three characters for a suffix and others use four characters for a suffix, applications should ensure that the maximum portable pathname length passed to dbm_open() is no greater than {PATH_MAX}-4 bytes, with the last component of the pathname no greater than {NAME_MAX}-4 bytes.

RATIONALE

Previously the standard required the database to be stored in two files, one file being a directory containing a bitmap of keys and having .dir as its suffix. The second file containing all data and having .pag as its suffix. This has been changed not to specify the use of the files and to allow newer implementations of the Berkeley DB interface using a single file that have evolved while remaining compatible with the application programming interface. The standard developers considered removing the specific suffixes altogether but decided to retain them so as not to pollute the application file name space more than necessary and to allow for portable backups of the database.
