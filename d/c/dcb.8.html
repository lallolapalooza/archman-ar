dcb(8)

الحزمة: iproute2

التراخيص: GPL-2.0-or-later

DCB(8) Linux DCB(8)

الاسم

dcb - عرض / معالجة إعدادات DCB (Data Center Bridging)

النبذة


dcb [ خيارات ] { app | buffer | ets | maxrate | pfc } { أمر | مساعدة }

dcb [ -force ] -batch ملف

dcb [ خيارات ] مساعدة

خيارات

-n, --netns <NETNS>
يُبدّل dcb إلى مساحة اسم الشبكة المحددة NETNS.
-V, --Version
طباعة إصدار أداة dcb والخروج.
-b, --batch <FILENAME>
قراءة الأوامر من الملف المقدم أو المدخل القياسي وتفعيلها. أول فشل سيؤدي إلى إنهاء dcb.
-f, --force
لا تُنهِ dcb عند الأخطاء في وضع الدُفعات. إذا كانت هناك أي أخطاء أثناء تنفيذ الأوامر، فسيكون رمز إرجاع التطبيق غير صفري.
-i, --iec
عند عرض المعدلات، استخدم البادئات المستندة إلى 1024 (Ki, Mi, Bi) بدلاً من تلك المستندة إلى 1000 (K, M, B).
-j, --json
إنشاء إخراج JSON.
-N, --Numeric
إذا كانت الأداة الفرعية المعنية تترجم الأرقام إلى أسماء رمزية بأي شكل من الأشكال، فقم بقمع هذا الترجمة.
-p, --pretty
عند دمجه مع -j، قم بإنشاء إخراج JSON جميل.
-s, --statistics
إذا كان الكائن المعني يحتوي على أي عدادات إحصائية، قم بعرضها كجزء من إخراج "show".

الكائنات

app
- تكوين جدول أولوية التطبيق
buffer
- تكوين مخازن المنفذ
ets
- تكوين ETS (Enhanced Transmission Selection)
maxrate
- تكوين معدل الإرسال الأقصى لكل TC
pfc
- تكوين PFC (Priority-based Flow Control)

الأوامر

يحدد الأمر الإجراء المراد تنفيذه على الكائن. تعتمد مجموعة الإجراءات الممكنة على نوع الكائن. كقاعدة، من الممكن عرض الكائنات واستدعاء مساعدة موضوعية، والتي تطبع قائمة بالأوامر المتاحة واتفاقيات بناء الجملة الوسيطة.

معلمات المصفوفة

مثل الأوامر، فإن تحديد المعلمات هو في نطاق الكائنات الفردية (وأوامرها). ومع ذلك، فإن جزءًا كبيرًا من واجهة DCB يدور حول مصفوفات ذات حجم ثابت تحدد قيمة واحدة لكل مفتاح معين، مثل لكل فئة حركة مرور أو لكل أولوية. لذلك هناك بناء جملة واحد لضبط عناصر هذه المصفوفات. يتكون من سلسلة من أزواج KEY:VALUE، حيث يعتمد معنى المفاتيح والقيم الفردية على المعلمة.

يتم تقييم العناصر بالترتيب من اليسار إلى اليمين، وتتجاوز العناصر اللاحقة العناصر السابقة. يتم الاستعلام عن العناصر غير المحددة في سطر الأوامر من النواة ويتم الاحتفاظ بقيمتها الحالية.

كمثال، خذ معلمة وهمية tc-juju، والتي يمكن تعيينها لتشفير حركة المرور في TC معين إما بحظ سعيد أو حظ سيء. لذلك، يمكن أن يكون KEY 0..7 (كما هو معتاد لأرقام TC في DCB)، و VALUE إما none أو good أو bad. مثال على تغيير قيمة juju لـ TCs 0 و 7، مع ترك كل شيء آخر سليماً، سيكون حينئذ:

# dcb foo set dev eth0 tc-juju 0:good 7:bad

تم التعرف على مفتاح خاص، all، يقوم بتعيين نفس القيمة لجميع عناصر المصفوفة. يمكن دمج هذا مع بناء الجملة القياسي لعنصر واحد. على سبيل المثال، في ما يلي، يتم تعيين juju لجميع المفاتيح إلى none، باستثناء 0 و 7، والتي لها قيم أخرى:

# dcb foo set dev eth0 tc-juju all:none 0:good 7:bad

حالة الخروج

حالة الخروج هي 0 إذا كان الأمر ناجحًا أو عددًا صحيحًا موجبًا عند الفشل.
