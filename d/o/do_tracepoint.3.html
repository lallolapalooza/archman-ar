الحزمة: lttng-ust

التراخيص: LGPL2.1, GPL2, MIT

اسم ملف رابط التصحيح.

اكتشاف ما إذا كان LTTng-UST محملًا

لاكتشاف ما إذا كانت liblttng-ust محملة من تطبيق:

1.عرّف الرمز الضعيف lttng_ust_loaded عالميًا: 
int lttng_ust_loaded __attribute__((weak));

يتم تعيين هذا الرمز الضعيف بواسطة مُنشئ liblttng-ust.

2.اختبر lttng_ust_loaded عند الحاجة: 
/* ... */
if (lttng_ust_loaded) {
    /* LTTng-UST is loaded */
} else {
    /* LTTng-UST is NOT loaded */
}
/* ... */

ملاحظة

تتوفر بعض الأمثلة في دليل doc/examples https://github.com/lttng/lttng-ust/tree/stable-2.14/doc/examples لشجرة مصدر LTTng-UST.

يوضح هذا المثال جميع الميزات الموثقة في الأقسام السابقة. يتم اختيار طريقة الربط الثابت هنا لربط التطبيق بموفر نقاط التتبع.

يمكنك تجميع ملفات المصدر وربطها معًا بشكل ثابت على النحو التالي:

$ cc -c -I. tp.c
$ cc -c app.c
$ cc -o app tp.o app.o -llttng-ust -ldl

باستخدام أداة lttng(1)، قم بإنشاء جلسة تتبع LTTng، وتمكين جميع الأحداث الخاصة بموفر نقاط التتبع هذا، وبدء التتبع:

$ lttng create my-session
$ lttng enable-event --userspace 'my_provider:*'
$ lttng start

يمكنك أيضًا تمكين أحداث محددة:

$ lttng enable-event --userspace my_provider:big_event
$ lttng enable-event --userspace my_provider:event_instance2

قم بتشغيل التطبيق:

$ ./app some arguments

قم بإيقاف جلسة التتبع الحالية وفحص الأحداث المسجلة:

$ lttng stop
$ lttng view

ملف مصدر التطبيق

app.c:

#include <stdlib.h>
#include <stdio.h>
#include "tp.h"
#include "app.h"
static int array_of_ints[] = {
    100, -35, 1, 23, 14, -6, 28, 1001, -3000,
};
int main(int argc, char* argv[])
{
    FILE *stream;
    struct app_struct app_struct;
    lttng_ust_tracepoint(my_provider, simple_event, argc, argv[0]);
    stream = fopen("/tmp/app.txt", "w");
    if (!stream) {
        fprintf(stderr,
                "Error: Cannot open /tmp/app.txt for writing\n");
        return EXIT_FAILURE;
    }
    if (fprintf(stream, "0123456789") != 10) {
        fclose(stream);
        fprintf(stderr, "Error: Cannot write to /tmp/app.txt\n");
        return EXIT_FAILURE;
    }
    lttng_ust_tracepoint(my_provider, big_event, 35,
                         "hello tracepoint", stream, -3.14,
                         array_of_ints);
    fclose(stream);
    app_struct.b = argc;
    app_struct.c = "[the string]";
    lttng_ust_tracepoint(my_provider, event_instance1, 23,
                         &app_struct);
    app_struct.b = argc * 5;
    app_struct.c = "[other string]";
    lttng_ust_tracepoint(my_provider, event_instance2, 17,
                         &app_struct);
    app_struct.b = 23;
    app_struct.c = "nothing";
    lttng_ust_tracepoint(my_provider, event_instance3, -52,
                         &app_struct);
    return EXIT_SUCCESS;
}

متغيرات البيئة

LTTNG_HOME

دليل منزل المستخدم البديل. هذا المتغير مفيد عندما يكون لدى المستخدم الذي يشغل التطبيق المُقاس دليل منزل غير قابل للكتابة. هذا المسار هو المكان الذي توجد فيه مقابس Unix للتواصل مع خادم الجلسات الخاص بالمستخدم.

LTTNG_UST_ABORT_ON_CRITICAL

إذا تم تعيينه، قم بإنهاء التطبيق المُقاس عند رسالة خطأ حرجة.

LTTNG_UST_ALLOW_BLOCKING

إذا تم تعيينه، اسمح للتطبيق بإعادة محاولة تتبع الأحداث عندما لا يكون هناك مساحة كافية لسجل الحدث في المخزن المؤقت الفرعي، وبالتالي منع التطبيق فعليًا حتى يتم توفير مساحة أو الوصول إلى المهلة المحددة.

للسماح للتطبيق بالتعليق أثناء التتبع، تحتاج أيضًا إلى تحديد مهلة تعليق عند إنشاء قناة باستخدام الخيار --blocking-timeout من الأمر lttng-enable-channel(1).

قد يكون هذا الخيار مفيدًا في أعباء العمل التي تولد معدل نقل بيانات تتبع كبيرة جدًا، حيث يكون تعليق التطبيق مقايضة مقبولة لمنع تجاهل سجلات الأحداث.


تحذير
قد يؤثر تعيين متغير البيئة هذا بشكل كبير على توقيت التطبيق.

LTTNG_UST_APP_PATH

مسار الدليل الذي يُتوقع من خادم جلسات LTTng وضع الملفات التالية فيه لتلقي طلبات اتصال التطبيق المُقاس:
•؛ مقبس تسجيل التطبيق.
•؛ ملفات الذاكرة المشتركة "الانتظار" لإيقاظ التطبيقات المُقاسة التي تنتظر بدء خادم جلسة.
•؛ ملف منفذ الوكيل.

يحتوي هذا الملف على منفذ TCP الذي يجب على الوكلاء الاتصال به لتمكين تتبع LTTng.

يجب أن يكون هذا الدليل موجودًا عند بدء التطبيق لتمكين تتبع LTTng.

عند تعيين LTTNG_UST_APP_PATH، فإن liblttng-ust:

•؛ يأخذ هذا المسار فقط للاتصال بخادم الجلسة.
•؛ لن يتصل بخوادم الجلسات الجذر والمستخدم/والمستخدم كما هو معتاد.

راجع متغير البيئة المقابل LTTNG_UST_CTL_PATH في lttng-sessiond(8).

LTTNG_UST_CLOCK_PLUGIN

مسار الكائن المشترك الذي يعمل كملحق تجاوز الساعة. يمكن العثور على مثال لهذا الملحق في وثائق LTTng-UST ضمن examples/clock-override https://github.com/lttng/lttng-ust/tree/stable-2.14/doc/examples/clock-override.

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.
