الحزمة: docker

DOCKER(1) أدلة مستخدم دوكر DOCKER(1)

الاسم

docker-volume-create - إنشاء وحدة تخزين

الخلاصة

docker volume create [خيارات] [وحدة التخزين]

الوصف

ينشئ وحدة تخزين جديدة يمكن للحاويات استهلاكها وتخزين البيانات فيها. إذا لم يتم تحديد اسم، فإن Docker يقوم بإنشاء اسم عشوائي. يمكنك إنشاء وحدة تخزين ثم تكوين الحاوية لاستخدامها، على سبيل المثال:

$ docker volume create hello
hello
$ docker run -d -v hello:/world busybox ls /world

يتم إنشاء نقطة التحميل داخل دليل /src الخاص بالحاوية. لا يدعم Docker المسارات النسبية لنقاط التحميل داخل الحاوية.

يمكن لعدة حاويات استخدام نفس وحدة التخزين في نفس الوقت. هذا مفيد إذا كانت حاويتان بحاجة إلى الوصول إلى بيانات مشتركة. على سبيل المثال، إذا كانت إحدى الحاويات تكتب البيانات والأخرى تقرأها.

خيارات خاصة بمشغل وحدة التخزين

قد تأخذ بعض مشغلات وحدات التخزين خيارات لتخصيص إنشاء وحدة التخزين. استخدم علامات -o أو --opt لتمرير خيارات المشغل:

$ docker volume create --driver fake --opt tardis=blue --opt timey=wimey

يتم تمرير هذه الخيارات مباشرة إلى مشغل وحدة التخزين. قد تكون خيارات مشغلات وحدات التخزين المختلفة مختلفة (أو لا تفعل شيئًا على الإطلاق).

مشغل local المدمج على Windows لا يدعم أي خيارات.

مشغل local المدمج على Linux يقبل خيارات مشابهة لأمر mount الخاص بنظام Linux:

$ docker volume create --driver local --opt type=tmpfs --opt device=tmpfs --opt o=size=100m,uid=1000

مثال آخر:

$ docker volume create --driver local --opt type=btrfs --opt device=/dev/sda2

الخيارات

--availability="active" توفر وحدة التخزين في الكتلة ("active", "pause", "drain")

-d, --driver="local" تحديد اسم مشغل وحدة التخزين

--group="" مجموعة وحدة التخزين في الكتلة (وحدات تخزين الكتلة)

--label= تعيين بيانات وصفية لوحدة تخزين

--limit-bytes=0 الحد الأدنى لحجم وحدة التخزين في الكتلة بالبايت

-o, --opt=map[] تعيين خيارات خاصة بالمشغل

--required-bytes=0 الحد الأقصى لحجم وحدة التخزين في الكتلة بالبايت

--scope="single" نطاق وصول وحدة التخزين في الكتلة ("single", "multi")

--secret=map[] أسرار وحدة التخزين في الكتلة

--sharing="none" مشاركة وصول وحدة التخزين في الكتلة ("none", "readonly", "onewriter", "all")

--topology-preferred= طوبولوجيا مفضلة لوحدة التخزين في الكتلة

--topology-required= طوبولوجيا يجب أن تكون وحدة التخزين في الكتلة قابلة للوصول منها

--type="block" نوع وصول وحدة التخزين في الكتلة ("mount", "block")
