dup(2) دليل استدعاءات النظام dup(2)

الاسم

dup, dup2, dup3 - تكرار واصف ملف

المكتبة

مكتبة C القياسية (libc, -lc)

الملخص

#include <unistd.h>
int dup(int oldfd);
int dup2(int oldfd, int newfd);
#define _GNU_SOURCE             /* انظر feature_test_macros(7) */
#include <fcntl.h>              /* تعريف الثوابت O_* */
#include <unistd.h>
int dup3(int oldfd, int newfd, int flags);

الوصف

يقوم استدعاء النظام dup() بتخصيص واصف ملف جديد يشير إلى نفس وصف الملف المفتوح الذي يشير إليه الواصف oldfd. (لشرح أوصاف الملفات المفتوحة، انظر open(2).) يضمن رقم واصف الملف الجديد أن يكون واصف الملف المستخدم بأقل رقم والذي لم يتم استخدامه بعد في العملية المستدعية.

بعد عودة ناجحة، يمكن استخدام واصفات الملف القديمة والجديدة بشكل متبادل. نظرًا لأن واصفات الملفين تشير إلى نفس وصف الملف المفتوح، فإنهما يتشاركان في موضع الملف وحالة علامات الملف؛ على سبيل المثال، إذا تم تعديل موضع الملف باستخدام lseek(2) على أحد واصفات الملف، فإن الموضع يتم تغييره أيضًا للواصف الآخر.

واصفا الملف لا يتشاركان في علامات واصف الملف (علامة الإغلاق عند التنفيذ). علامة الإغلاق عند التنفيذ (FD_CLOEXEC؛ انظر fcntl(2)) للمُكرر تكون مغلقة (off).

dup2()

يقوم استدعاء النظام dup2() بنفس مهمة dup()، ولكن بدلاً من استخدام واصف الملف الأقل رقمًا الذي لم يتم استخدامه، فإنه يستخدم رقم واصف الملف المحدد في newfd. بعبارة أخرى، يتم تعديل واصف الملف newfd بحيث يشير الآن إلى نفس وصف الملف المفتوح الذي يشير إليه oldfd.

إذا كان واصف الملف newfd مفتوحًا من قبل، فسيتم إغلاقه قبل إعادة استخدامه؛ يتم الإغلاق بصمت (أي، لا يتم الإبلاغ عن أي أخطاء أثناء الإغلاق بواسطة dup2()).

يتم تنفيذ خطوات إغلاق وإعادة استخدام واصف الملف newfd بشكل متزامن. هذا مهم، لأن محاولة تنفيذ وظيفة مكافئة باستخدام close(2) و dup() ستكون عرضة لمشاكل التنافس، حيث قد يتم إعادة استخدام newfd بين الخطوتين. يمكن أن يحدث إعادة الاستخدام هذه لأن البرنامج الرئيسي مقاطع بواسطة معالج إشارات يقوم بتخصيص واصف ملف، أو لأن خيطًا متوازيًا يقوم بتخصيص واصف ملف.

لاحظ النقاط التالية:

•
إذا لم يكن oldfd واصف ملف صالحًا، فسيفشل الاستدعاء، ولن يتم إغلاق newfd.
•
إذا كان oldfd واصف ملف صالحًا، وكان newfd له نفس القيمة مثل oldfd، فلن يفعل dup2() شيئًا، وسيعيد newfd.

dup3()

dup3() هو نفس dup2()، باستثناء ما يلي:

•
يمكن للمستدعي فرض تعيين علامة الإغلاق عند التنفيذ (close-on-exec) لواصف الملف الجديد بتحديد O_CLOEXEC في flags. انظر وصف نفس العلامة في open(2) لأسباب قد يكون هذا مفيدًا.
•
إذا كان oldfd يساوي newfd، فسيفشل dup3() مع الخطأ EINVAL.

قيمة الإرجاع

عند النجاح، تعيد استدعاءات النظام هذه واصف الملف الجديد. عند حدوث خطأ، يتم إرجاع -1، ويتم تعيين errno للإشارة إلى الخطأ.

الأخطاء

EBADF
oldfd ليس واصف ملف مفتوح.
EBADF
newfd خارج النطاق المسموح به لواصفات الملف (انظر مناقشة RLIMIT_NOFILE في getrlimit(2)).
EBUSY
(Linux فقط) قد يتم إرجاع هذا بواسطة dup2() أو dup3() أثناء حالة تنافس مع open(2) و dup().
EINTR
تم مقاطعة استدعاء dup2() أو dup3() بواسطة إشارة؛ انظر signal(7).
EINVAL
(dup3()) يحتوي flags على قيمة غير صالحة.
EINVAL
(dup3()) كان oldfd مساويًا لـ newfd.
EMFILE
تم الوصول إلى حد العملية لكل عملية لعدد واصفات الملفات المفتوحة (انظر مناقشة RLIMIT_NOFILE في getrlimit(2)).
ENOMEM
كانت ذاكرة النواة غير كافية.

ملاحظات

الخطأ الذي تعيده dup2() يختلف عن الخطأ الذي تعيده fcntl(..., F_DUPFD, ...) عندما يكون newfd خارج النطاق. في بعض الأنظمة، تعيد dup2() أحيانًا EINVAL مثل F_DUPFD.

إذا كان newfd مفتوحًا، فإن أي أخطاء كان يمكن الإبلاغ عنها عند وقت close(2) يتم فقدانها. إذا كان هذا يمثل قلقًا، فعندئذٍ - ما لم يكن البرنامج أحادي الخيط ولا يقوم بتخصيص واصفات ملفات في معالجات الإشارات - فإن النهج الصحيح هو عدم إغلاق newfd قبل استدعاء dup2()، بسبب مشكلة التنافس الموصوفة أعلاه. بدلاً من ذلك، يمكن استخدام الكود المشابه لما يلي:


/* الحصول على نسخة مكررة من 'newfd' يمكن استخدامها لاحقًا
   للتحقق من أخطاء close()؛ خطأ EBADF يعني أن 'newfd' لم يكن مفتوحًا. */
tmpfd = dup(newfd);
if (tmpfd == -1 && errno != EBADF) {
    /* التعامل مع خطأ dup() غير متوقع. */
}
/* تكرار 'oldfd' على 'newfd' بشكل متزامن. */
if (dup2(oldfd, newfd) == -1) {
    /* التعامل مع خطأ dup2(). */
}
/* الآن تحقق من أخطاء close() على الملف المشار إليه أصلاً
   بواسطة 'newfd'. */
if (tmpfd != -1) {
    if (close(tmpfd) == -1) {
        /* التعامل مع الأخطاء من close. */
    }
}
