DESCRIPTION

The Internet Systems Consortium DHCP Distribution consists of three programs: dhcpd(8), the Internet DHCP server; dhclient(8), the Internet DHCP client daemon; and dhcrelay(8), an Ethernet DHCP relay agent.

dhcpd is a DHCP server. It is recommended that you consult the dhcpd.conf(5) manual page for a detailed description of the configuration file syntax.

dhclient is a DHCP client. It is recommended that you consult the dhclient.conf(5) manual page for a detailed description of the configuration file syntax.

dhcrelay is a DHCP relay agent. It is recommended that you consult the dhcrelay.conf(5) manual page for a detailed description of the configuration file syntax.

OPERATION

When dhcpd starts, it reads its configuration file, then it comprises a list of network interfaces from which to receive and to which to send DHCP messages. For each interface, it constructs a list of IP addresses which are available for lease.

When dhclient starts, it constructs a list of network interfaces from which to receive and to which to send DHCP messages. It then attempts to obtain a lease on an IP address for each interface.

When dhcrelay starts, it reads its configuration file, then it comprises a list of network interfaces from which to receive and to which to send DHCP messages. For each interface, it accepts DHCP messages and forwards them to a DHCP server which is specified in the configuration file.

COMMAND LINE

The command line arguments for each program are described below.

COMMAND LINE OPTIONS

The following options are available for dhcpd(8), dhclient(8), and dhcrelay(8):

-d
Run the daemon in the foreground. This is useful for debugging.
-f
Run the daemon in the foreground. Same as -d.
-t
Test the configuration file for syntax errors. The server will not start.
-T
Test the configuration file for syntax errors and print the values of specified variables. The server will not start.
-q
Print fewer status messages. This option is not supported by dhclient.
-1
Print fewer status messages. This option is not supported by dhclient.
-s
Print status messages to stderr. This option is not supported by dhclient.
-v
Print version information and exit.
-syslog
Log messages to syslog instead of stderr. This is the default for dhcpd and dhcrelay.
-nofork
Do not fork the daemon into the background. This is the default for dhclient.
-init-file filename
Read initialization information from filename. This option is not supported by dhclient.
-cf filename
Use filename as the configuration file.
-lf filename
Use filename as the lease file.
-pf filename
Use filename as the PID file.
interface...
A list of network interfaces on which the daemon should operate. If no interfaces are specified, the daemon will attempt to operate on all network interfaces.

The following options are available only for dhclient(8):

-i
Print the contents of the options in the DHCP packets.
-nw
Run dhclient on a non-networked machine. This is useful for testing.
-e variable=value
Set the environment variable variable to value. This can be used to override default values for certain options.
-p port
Use port as the DHCP port. The default is 67.
-s server
Use server as the DHCP server.

The following options are available only for dhcrelay(8):

-i
Do not release leases on startup. This is the default.
-c filename
Use filename as the DHCP server list file.
-p port
Use port as the DHCP port. The default is 67.
-s server
Use server as the DHCP server.

PORTS

The DHCP server listens on UDP port 67. The DHCP client listens on UDP port 68.

CONFIGURATION

The behavior of the DHCP server, client, and relay agent is controlled by configuration files. The default locations for these files are:

dhcpd:

/etc/dhcpd.conf (configuration file)

/var/lib/dhcp/dhcpd.leases (lease file)

/var/run/dhcpd.pid (PID file)

dhclient:

/etc/dhclient.conf (configuration file)

/var/lib/dhcp/dhclient.leases (lease file)

/var/run/dhclient.pid (PID file)

dhcrelay:

/etc/dhcrelay.conf (configuration file)

/var/run/dhcrelay.pid (PID file)

For a detailed description of the configuration file syntax, consult the manual pages for dhcpd.conf(5), dhclient.conf(5), and dhcrelay.conf(5).

Subnets

The DHCP server maintains a list of subnets for which it is configured to provide service. For each subnet, it keeps track of available IP addresses, lease lengths, and other parameters.

Lease Lengths

The DHCP server can be configured to provide leases for various lengths of time. The default lease length is typically one hour for normal clients and two hours for clients that are rebooting.

BOOTP Support

The DHCP server also supports BOOTP clients. BOOTP requests are handled similarly to DHCP requests, but BOOTP clients do not support options.

Options

The DHCP server supports a wide range of DHCP options, including router, domain name server, domain name, and others. These options can be specified in the configuration file.

OMAPI

The DHCP server provides an API (OMAPI) for remote administration. This API allows administrators to manage leases, hosts, and other configuration parameters without modifying the configuration file and restarting the server.

THE LEASE OBJECT

The lease object represents a lease assigned by the DHCP server to a client. It contains information such as the client's IP address, MAC address, lease start and end times, and other parameters.

THE HOST OBJECT

The host object represents a specific host on the network. It can be used to assign a static IP address to a host based on its MAC address, or to provide specific configuration options to a host.

THE GROUP OBJECT

The group object represents a group of hosts. It can be used to apply common configuration parameters to multiple hosts.

THE CONTROL OBJECT

The control object allows the DHCP server to be controlled remotely. It can be used to restart the server, display status information, and perform other administrative tasks.

THE FAILOVER-STATE OBJECT

The failover-state object represents the state of the failover relationship between two DHCP servers. It contains information such as the current state of the failover, the time of the last message received from the failover partner, and the time of the last update received from the failover partner.

peer-name string

The name of the failover partner.

local-state integer

The current state of the failover.

The following states are possible:

  • 0: unknown
  • 1: startup
  • 2: normal
  • 3: interrupted
  • 4: potential-conflict
  • 5: recovering
  • 6: stopped

remote-state integer

The current state of the failover partner.

See the description of local-state for possible values.

next-state integer

The next state the server will transition to.

See the description of local-state for possible values.

timer integer

The time in seconds until the next state transition.

mcf integer

The maximum client (or server) communications failures.

max-unacked-updates integer

The maximum number of update messages that can be unacknowledged.

load integer

The current load on the failover partner.

load-penalty integer

The penalty for the current load.

max-load-penalty integer

The maximum penalty for the load.

time-to-unreachable integer

The time in seconds until the failover partner is considered unreachable.

next- reconnect integer

The time in seconds until the next reconnection attempt.

backoff integer

The backoff time for retrying a connection.

max- backoff integer

The maximum backoff time for retrying a connection.

hba integer

The time in seconds since the last heartbeat message received from the failover partner.

max-hba integer

The maximum time in seconds since the last heartbeat message received from the failover partner before it is considered unreachable.

received- updates integer

The number of update messages received from the failover partner.

accepted- updates integer

The number of update messages accepted from the failover partner.

requested- updates integer

The number of update messages requested from the failover partner.

sent-updates integer

The number of update messages sent to the failover partner.

out-of-sync integer

Indicates whether the failover state is out of sync.

need- backup integer

Indicates whether a backup server is needed.

script- filename string

The name of the script to be run when the failover state changes.

script- elapsed integer

The time in seconds since the script was last run.

script- terminal integer

Indicates whether the script terminated successfully.

state- changed integer

The time in seconds since the failover state last changed.

peer-transaction-id integer

The transaction ID of the last message received from the failover partner.

our-transaction-id integer

The transaction ID of the last message sent to the failover partner.

our-last-xact integer

The time in seconds since the last transaction with the failover partner.

peer-last-xact integer

The time in seconds since the last transaction with the failover partner.

last-sent integer

The time in seconds since the last message sent to the failover partner.

last- received integer

The time in seconds since the last message received from the failover partner.

skew integer

Indicates the skew between the failover partner's clock and this DHCP server's clock.

max-response-delay integer

Indicates the time in seconds after which, if no message is received from the failover partner, the partner is assumed to be out of communication.

cur-unacked-updates integer

Indicates the number of update messages that have been received from the failover partner but not yet processed.
