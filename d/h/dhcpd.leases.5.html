dhcpd.leases(5)

الحزمة: dhcp

التراخيص: custom:isc-dhcp

الاسم

dhcpd.leases - صيغة ملف تأجير DHCP.

الوصف

يحتفظ خادم DHCP بسجل لمخزون العناوين التي قام بتعيينها للعملاء في ملف تأجير. يقوم هذا الملف بتخزين التأكيدات الحالية، بالإضافة إلى التأكيدات التي تم منحها في الماضي. يتم استخدام معلومات التأجير للمساعدة في استعادة الحالة في حالة تعطل الخادم، ولتتبع مخزون العناوين.

يتم تخزين معلومات التأجير في ملف التأجير بالتنسيق الذي تم إنشاؤه تلقائيًا بواسطة dhcpd(8) عند الحاجة. على الرغم من أنه يجب معالجة هذا الملف بواسطة dhcpd، إلا أنه يمكن أيضًا قراءته بواسطة مسؤول النظام للحصول على معلومات حول حالة شبكة TCP/IP.

تتكون ملفات تأجير DHCP من قائمة بتصريحات التأجير. كل تصريح يصف تأجيرًا معينًا.

تاريخ آخر تحديث للمعاملة الخاصة بالعميل

يتم تسجيل الوقت الذي تلقى فيه العميل آخر استجابة من الخادم باستخدام البيان cltt. هذه قيمة مهمة في بروتوكول التأجير، حيث تساعد في الحفاظ على تناسق حالة التأجير بين خوادم DHCP المتعددة.

التنسيق

تبدأ كل فقرة في ملف التأجير بوصف لعنوان IP الذي تم تأجيره. يتبع هذا وصفًا للتأجير نفسه.

lease {
  starts datetime ;
  ends datetime ;
  tstp datetime ;
  tsfp datetime ;
  atsfp datetime ;
  cltt datetime ;
  binding state state ;
  next binding state state ;
  rewind binding state state ;
  hardware hardware-type mac-address ;
  uid uid ;
  client-hostname hostname ;
  option option-name value ;
  ...
}

بالإضافة إلى ذلك، قد يتم تضمين البيانات المتعلقة بالبروتوكولات الخاصة مثل:

ia_na {
  binding state state ;
  preferred-life lifetime ;
  max-life lifetime ;
  ends datetime ;
  iaaddr ipv6-address { }
  iaprefix ipv6-prefix { }
  ...
}

يجب أن تكون كل البيانات الأخرى متوافقة مع بنية ملف التأجير.

بيانات مشتركة لتصريحات التأجير

starts date;
ends date;
tstp date;
tsfp date;
atsfp date;
cltt date;

يتم تسجيل وقت بدء وانتهاء التأجير باستخدام البيانات starts و ends. البيان tstp موجود إذا كان بروتوكول التبديل قيد الاستخدام، ويشير إلى الوقت الذي تم إخبار الند به بانتهاء صلاحية التأجير. البيان tsfp موجود أيضًا إذا كان بروتوكول التبديل قيد الاستخدام، ويشير إلى وقت انتهاء صلاحية التأجير الذي أقره الند. البيان atsfp هو الوقت الفعلي المرسل من شريك التبديل. البيان cltt هو وقت آخر معاملة للعميل.

انظر وصف التواريخ في القسم الخاص بالهياكل الشائعة.

hardware hardware-type mac-address;

يسجل بيان الأجهزة عنوان MAC لواجهة الشبكة التي سيتم استخدام التأجير عليها. يتم تحديده كسلسلة من البايتات السداسية العشرية، مفصولة بنقطتين فوق بعضهما البعض.

uid client-identifier;

يسجل البيان uid معرف العميل الذي يستخدمه العميل للحصول على التأجير. لا يُطلب من العملاء إرسال معرفات العملاء، وهذا البيان يظهر فقط إذا أرسل العميل واحدًا بالفعل. معرفات العملاء عادة ما تكون نوع ARP (1 للإيثرنت) متبوعًا بعنوان MAC، تمامًا مثل البيان hardware، ولكن هذا ليس مطلوبًا.

يتم تسجيل معرف العميل كقائمة سداسية عشرية مفصولة بنقطتين أو كسلسلة مقتبسة. إذا تم تسجيله كسلسلة مقتبسة ويحتوي على حرف واحد أو أكثر غير قابل للطباعة، فسيتم تمثيل تلك الأحرف كهروبات ثمانية - حرف مائل متبوع بثلاثة أرقام ثمانية. يتم تحديد التنسيق المستخدم بواسطة معلمة lease-id-format، والتي تعود افتراضيًا إلى الثماني.

client-hostname hostname ;

يرسل معظم عملاء DHCP اسم مضيفهم في الخيار host-name. إذا أرسل العميل اسم مضيفه بهذه الطريقة، يتم تسجيل اسم المضيف في التأجير ببيان client-hostname. هذا ليس مطلوبًا بموجب البروتوكول، ومع ذلك، فإن العديد من عملاء DHCP المتخصصين لا يرسلون خيار اسم مضيف.

binding state state;
next binding state state;

يعلن البيان binding state عن حالة ربط التأجير. عندما لا يكون خادم DHCP مهيأ لاستخدام بروتوكول التبديل، قد تكون حالة ربط التأجير active أو free أو abandoned. يضيف بروتوكول التبديل بعض الحالات الانتقالية الإضافية، بالإضافة إلى حالة backup، التي تشير إلى أن التأجير متاح للتخصيص بواسطة ثانوي التبديل. يرجى الرجوع إلى صفحة الدليل dhcpd.conf(5) لمزيد من المعلومات حول التأجيرات المهجورة.

يشير البيان next binding state إلى الحالة التي سينتقل إليها التأجير عند انتهاء صلاحية الحالة الحالية. يتم تحديد وقت انتهاء صلاحية الحالة الحالية في البيان ends.

rewind binding state state;

هذا البيان جزء من تحسين للاستخدام مع التبديل. هذا يساعد الخادم على إعادة توجيه التأجير إلى الحالة التي تم إرسالها مؤخرًا إلى نظيره.

option agent.circuit-id string;
option agent.remote-id string;

تستخدم هذه البيانات لتسجيل معرفات الدائرة ومعرفات الند المرسلة بواسطة وكيل الترحيل، إذا كان وكيل الترحيل يستخدم خيار معلومات وكيل الترحيل. هذا يسمح باستخدام هذه الخيارات باستمرار في التقييمات المشروطة حتى عندما يتصل العميل بالخادم مباشرة بدلاً من خلال وكيل الترحيل الخاص به.

متغير vendor-class-identifier

يحتفظ الخادم بمعرف فئة البائع الذي يوفره العميل لأغراض إعلامية، ولعرضها في استجابات DHCPLEASEQUERY.

bootp;
reserved;

إذا كانت موجودة، فإنها تشير إلى أنه يجب تعيين علامات تبديل BOOTP و RESERVED (على التوالي). يتم التعامل مع تأجيرات BOOTP و RESERVED الديناميكية بشكل مختلف عن التأجيرات الديناميكية العادية، حيث لا يمكن استخدامها إلا بواسطة العميل الذي تم تخصيصها له حاليًا.

أخرى قد يتم تضمين خيارات أخرى أو بيانات قابلة للتنفيذ، انظر وصفها في القسم الخاص بالهياكل الشائعة.

تأجير DHCPv6 (IA) التصريح

ia_ta  IAID_DUID { statements... }
ia_na  IAID_DUID { statements... }
ia_pd  IAID_DUID { statements... }

يبدأ كل تصريح تأجير بعلامة تشير إلى نوع التأجير. ia_ta للعناوين المؤقتة، ia_na للعناوين غير المؤقتة، و ia_pd لتفويض البادئة. يتبع هذه العلامة IAID و DUID المدمجان من العميل لهذا التأجير.

يتم تسجيل قيمة IAID_DUID كقائمة سداسية عشرية مفصولة بنقطتين أو كسلسلة مقتبسة. إذا تم تسجيلها كسلسلة مقتبسة وتحتوي على حرف واحد أو أكثر غير قابل للطباعة، فسيتم تمثيل تلك الأحرف كهروبات ثمانية - حرف مائل متبوع بثلاثة أرقام ثمانية. يتم التحكم في التنسيق المستخدم بواسطة معلمة lease-id-format، والتي تعود افتراضيًا إلى الثماني.

cltt date;

البيان cltt هو وقت آخر معاملة للعميل.

انظر وصف التواريخ في القسم الخاص بالهياكل الشائعة.

iaaddr ipv6-address { statements... }
iaprefix ipv6-address/prefix-length { statements... }
داخل كل تأجير يمكن أن يكون هناك عدة بيانات iaaddr و iaprefix. سيحتوي كل منها
    إما على عنوان IPv6 أو بادئة IPv6 (عنوان وطول بادئة يشير إلى كتلة عناوين بأسلوب
    CIDR). يمكن أن تحدث البيانات التالية داخل كل iaaddr أو iaprefix.
binding state state;
يعلن البيان binding state عن حالة ربط التأجير. في DHCPv6، سترى عادةً
    هذه الحالة كـ active أو expired.
preferred-life lifetime;
عمر التفضيل الخاص بعنوان IPv6 المرتبط بهذا العنوان، بالثواني.
max-life lifetime;
عمر الصلاحية المرتبط بهذا العنوان، بالثواني.
ends date;
وقت انتهاء التأجير. انظر وصف التواريخ في القسم الخاص بالهياكل الشائعة.
قد يتم تضمين خيارات إضافية أو بيانات قابلة للتنفيذ. انظر وصفها في القسم الخاص
    بالهياكل الشائعة.

تصريح حالة ند التبديل

يتم أيضًا تسجيل حالة أي ترتيبات تبديل للتبديل في ملف التأجير، باستخدام البيان failover peer:

failover peer name state {
my state state at date;
peer state state at date;
}

يتم تسجيل حالة الند المسمى name. يتم تسجيل كل من حالة الخادم قيد التشغيل (my state) وشريك التبديل الآخر (peer state). الحالات التالية ممكنة: unknown-state، partner-down، normal، communications-interrupted، resolution-interrupted، potential-conflict، recover، recover-done، shutdown، paused، و startup.
