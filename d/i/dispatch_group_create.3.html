dispatch_group_create(3)

الحزمة: libdispatch

التراخيص: Apache-2.0

dispatch_group_create(3) دليل وظائف المكتبة dispatch_group_create(3)

الاسم

dispatch_group_create، dispatch_group_async، dispatch_group_wait، dispatch_group_notify — مجموعات الكتل المقدمة إلى قوائم الانتظار

المُلَخَّص

#include <dispatch/dispatch.h>

dispatch_group_t
dispatch_group_create(void);

void
dispatch_group_enter(dispatch_group_t group);

void
dispatch_group_leave(dispatch_group_t group);

long
dispatch_group_wait(dispatch_group_t group, dispatch_time_t timeout);

void
dispatch_group_notify(dispatch_group_t group, dispatch_queue_t queue, void (^block)(void));

void
dispatch_group_notify_f(dispatch_group_t group, dispatch_queue_t queue, void *context, void (*function)(void *));

void
dispatch_group_async(dispatch_group_t group, dispatch_queue_t queue, void (^block)(void));

void
dispatch_group_async_f(dispatch_group_t group, dispatch_queue_t queue, void *context, void (*function)(void *));

الوصف

مجموعة الإرسال هي ارتباط لكتلة واحدة أو أكثر مقدمة إلى قوائم انتظار الإرسال للاستدعاء غير المتزامن. يمكن للتطبيقات استخدام مجموعات الإرسال للانتظار حتى اكتمال الكتل المرتبطة بالمجموعة.

تقوم الدالة dispatch_group_create() بإرجاع مجموعة إرسال جديدة وفارغة.

تقوم الدالتان dispatch_group_enter() و dispatch_group_leave() بتحديث عدد الكتل قيد التشغيل داخل مجموعة.

تنتظر الدالة dispatch_group_wait() حتى تكتمل جميع الكتل المرتبطة بـ group، أو حتى تنتهي المهلة المحددة timeout. إذا أصبحت group فارغة خلال الفترة الزمنية المحددة، فسترجع الدالة صفرًا للإشارة إلى النجاح. بخلاف ذلك، سيتم إرجاع رمز غير صفري. عند تمرير DISPATCH_TIME_FOREVER كـ timeout، ستنتظر استدعاءات هذه الدالة لوقت غير محدود حتى تصبح المجموعة فارغة، وستكون قيمة الإرجاع دائمًا صفرًا.

توفر الدالة dispatch_group_notify() إشعارًا غير متزامن باكتمال الكتل المرتبطة بـ group عن طريق تقديم block إلى queue المحددة بمجرد اكتمال جميع الكتل المرتبطة بـ group. يحتفظ النظام بمرجع لمجموعة الإرسال أثناء تعليق إشعار غير متزامن، لذلك من الصالح تحرير group بعد تعيين كتلة إشعار. ستكون المجموعة فارغة في وقت تقديم كتلة الإشعار إلى قائمة الانتظار المستهدفة. يمكن تحرير المجموعة باستخدام dispatch_release() أو إعادة استخدامها لعمليات إضافية.

تعمل الدالة المساعدة dispatch_group_async() على النحو التالي:

void
dispatch_group_async(dispatch_group_t group, dispatch_queue_t queue, dispatch_block_t block)
{
	dispatch_retain(group);
	dispatch_group_enter(group);
	dispatch_async(queue, ^{
		block();
		dispatch_group_leave(group);
		dispatch_release(group);
	});
}

قيمة الإرجاع

ترجع الدالة dispatch_group_create() القيمة NULL عند الفشل والقيمة غير NULL عند النجاح.

ترجع الدالة dispatch_group_wait() صفرًا عند النجاح وغير صفر بعد انتهاء المهلة. إذا كانت المهلة هي DISPATCH_TIME_FOREVER، فإن dispatch_group_wait() تنتظر إلى الأبد وترجع دائمًا صفرًا.

نموذج الذاكرة

يتم الاحتفاظ بمجموعات الإرسال وتحريرها عبر استدعاءات dispatch_retain() و dispatch_release().

الأساسيات

تعتبر الدالتان dispatch_group_async() و dispatch_group_notify() عبارة عن غلافين للدالتين dispatch_group_async_f() و dispatch_group_notify_f() على التوالي.

تحذيرات

لضمان سلوك محدد، يوصى باستدعاء dispatch_group_wait() فقط بعد تقديم جميع الكتل إلى المجموعة. إذا تقرر لاحقًا أنه يجب تشغيل كتل جديدة، يوصى بعدم إعادة استخدام مجموعة قيد التشغيل بالفعل، ولكن إنشاء مجموعة جديدة.

dispatch_group_wait() ترجع بمجرد أن يكون هناك بالضبط صفر كتل مُدرجة أو قيد التشغيل مرتبطة بمجموعة (بشكل أكثر تحديدًا، بمجرد موازنة كل استدعاء dispatch_group_enter() باستدعاء dispatch_group_leave()). إذا كان خيط واحد ينتظر مجموعة بينما يقوم خيط آخر بتقديم كتل جديدة إلى المجموعة، فقد تصل قيمة عدد الكتل المرتبطة مؤقتًا إلى الصفر قبل تقديم جميع الكتل. إذا حدث هذا، فسترجع dispatch_group_wait() مبكرًا: بعض الكتل المرتبطة بالمجموعة قد انتهت، ولكن بعضها لم يتم تقديمه أو تشغيله بعد.

ومع ذلك، كحالة خاصة، يمكن لكتلة مرتبطة بمجموعة أن تقدم كتلًا جديدة مرتبطة بنفس مجموعتها. في هذه الحالة، السلوك محدد: لن يستيقظ خيط منتظر حتى يتم الانتهاء من الكتل المقدمة حديثًا أيضًا.

كل ما سبق ينطبق أيضًا على dispath_group_notify()، مع استبدال "كتلة سيتم تقديمها" بـ "خيط منتظر".
