DROP_FUNCTION(7)

الحزمة: postgresql

التراخيص: PostgreSQL

DROP FUNCTION(7) وثائق PostgreSQL 18.1 DROP FUNCTION(7)

الاسم

DROP FUNCTION - إزالة دالة

الملخص

DROP FUNCTION [ IF EXISTS ] name [ ( [ [ argmode ] [ argname ] argtype [, ...] ] ) ] [, ...]
    [ CASCADE | RESTRICT ]

الوصف

DROP FUNCTION تزيل تعريف دالة موجودة. لتنفيذ هذا الأمر، يجب أن يكون المستخدم هو مالك الدالة. يجب تحديد أنواع وسائط الدالة، حيث يمكن أن توجد دوال مختلفة متعددة بنفس الاسم وقوائم وسائط مختلفة.

المعلمات

IF EXISTS

لا ترمي خطأ إذا كانت الدالة غير موجودة. يتم إصدار إشعار في هذه الحالة.

name

الاسم (يمكن التأهل بالمخطط اختياريًا) لدالة موجودة. إذا لم يتم تحديد قائمة الوسائط، يجب أن يكون الاسم فريدًا في مخططه.

argmode

وضع الوسيط: IN، OUT، INOUT، أو VARIADIC. إذا تم حذفه، فإن الافتراضي هو IN. لاحظ أن DROP FUNCTION لا تهتم فعليًا بوسائط OUT، حيث أن وسائط الإدخال فقط مطلوبة لتحديد هوية الدالة. لذلك يكفي سرد وسائط IN و INOUT و VARIADIC.

argname

اسم الوسيط. لاحظ أن DROP FUNCTION لا تهتم فعليًا بأسماء الوسائط، حيث أن أنواع بيانات الوسائط فقط مطلوبة لتحديد هوية الدالة.

argtype

نوع (أنواع) بيانات وسائط الدالة (يمكن التأهل بالمخطط اختياريًا)، إن وجدت.

CASCADE

أسقط تلقائيًا الكائنات التي تعتمد على الدالة (مثل المشغلات أو الأوامر)، وبدورها جميع الكائنات التي تعتمد على تلك الكائنات (انظر القسم 5.15).

RESTRICT

ارفض إسقاط الدالة إذا كانت هناك كائنات تعتمد عليها. هذا هو الافتراضي.

أمثلة

يزيل هذا الأمر دالة الجذر التربيعي:

DROP FUNCTION sqrt(integer);

أسقط دوال متعددة في أمر واحد:

DROP FUNCTION sqrt(integer), sqrt(bigint);

إذا كان اسم الدالة فريدًا في مخططه، فيمكن الإشارة إليه بدون قائمة وسائط:

DROP FUNCTION update_employee_salaries;

لاحظ أن هذا يختلف عن

DROP FUNCTION update_employee_salaries();

الذي يشير إلى دالة بدون وسائط، بينما يمكن للمتغير الأول الإشارة إلى دالة بأي عدد من الوسائط، بما في ذلك الصفر، طالما أن الاسم فريد.

التوافق

يتوافق هذا الأمر مع معيار SQL، مع هذه الإضافات الخاصة بـ PostgreSQL:

•يسمح المعيار فقط بإسقاط دالة واحدة لكل أمر.
•خيار IF EXISTS
•القدرة على تحديد أوضاع و أسماء الوسائط
