الوصف

winedbg هو مصحح أخطاء لـ Wine. يسمح بـ:

- تصحيح أخطاء تطبيقات Win32 الأصلية
- تصحيح أخطاء تطبيقات Winelib
- أن يكون بديلاً مباشرًا لـ Dr Watson

أوضاع التشغيل

يمكن استخدام winedbg في خمسة أوضاع. يحدد الوسيط الأول للبرنامج الوضع الذي سيعمل فيه winedbg.

الوضع الافتراضي
بدون أي وضع صريح، هذا هو وضع التشغيل القياسي لـ winedbg. سيعمل winedbg كواجهة أمامية للمستخدم.
--gdb
سيتم استخدام winedbg كوكيل لـ gdb. سيكون gdb هو الواجهة الأمامية لمعالجة الأوامر، وسيقوم winedbg بتوكيل جميع طلبات تصحيح الأخطاء من gdb إلى واجهات برمجة تطبيقات Win32.
--auto
يستخدم هذا الوضع عندما يتم إعداد winedbg في إدخال السجل AeDebug كمصحح أخطاء افتراضي. سيعرض winedbg بعد ذلك معلومات أساسية حول التعطل. هذا مفيد للمستخدمين الذين لا يرغبون في تصحيح الأخطاء، بل جمع المعلومات ذات الصلة بالتعطل لإرسالها إلى المطورين.
--minidump
يشبه هذا الوضع وضع --auto، باستثناء أنه بدلاً من طباعة المعلومات على الشاشة (كما يفعل --auto)، يتم حفظها في ملف تصريف مصغر. يتم تمرير اسم الملف إما على سطر الأوامر، أو يتم إنشاؤه بواسطة WineDbg عندما لا يتم توفير أي اسم. يمكن إعادة تحميل هذا الملف لاحقًا في winedbg لمزيد من الفحص.
ملف.mdmp
في هذا الوضع، يعيد winedbg تحميل حالة عملية مصححة تم حفظها في ملف تصريف مصغر. انظر الأمر minidump أدناه، أو وضع --minidump.

الخيارات

عند التشغيل في الوضع الافتراضي، تتوفر الخيارات التالية:

--command سلسلة نصية
سيقوم winedbg بتنفيذ الأمر سلسلة نصية كما لو تم إدخاله في سطر أوامر winedbg، ثم سيخرج. يمكن أن يكون هذا مفيدًا للحصول على معرف العملية للعمليات قيد التشغيل (winedbg --command "info proc").
--exec اسم_ملف
يحدد اسم الملف التنفيذي، دون بدء تشغيل الملف التنفيذي.
--file اسم_ملف
سيقوم winedbg بتنفيذ قائمة الأوامر الموجودة في ملف اسم_ملف كما لو تم إدخالها في سطر أوامر winedbg، ثم سيخرج.

عند التشغيل في وضع وكيل gdb، تتوفر الخيارات التالية:

--no-start
لا تقم بتشغيل gdb مباشرة؛ بدلاً من ذلك، اطبع أمر target remote الخاص بـ GDB الذي يجب تنفيذه والاستماع للاتصال من أي مصحح أخطاء متوافق مع GDB. في العادة، سيقوم --gdb بتشغيل كل من خادم تصحيح الوكيل ونسخة من gdb للواجهة الأمامية. هذا الخيار يوجه winedbg لتخطي تشغيل gdb، وبدلاً من ذلك يطبع أمر GDB الذي يمكن استخدامه للاتصال يدويًا بالخادم. هذا الأمر يكون بالشكل
target remote localhost:<منفذ>

حيث <منفذ> هو منفذ TCP الذي يرتبط به خادم تصحيح الوكيل لـ winedbg.

يسمح هذا الخيار للمستخدم باستبدال gdb ببعض الواجهات الأمامية الأخرى لمصحح الأخطاء، مثل ddd أو kgdb أو gdbgui أو Qt Creator. بغض النظر عما إذا تم تحديد --no-start أم لا، سيتم إغلاق winedbg بعد قطع الاتصال الأول (مثل فصل gdb عن العملية المصححة).
--port منفذ
ابدأ خادم تصحيح الوكيل الخاص بـ GDB على المنفذ المحدد. إذا لم يتم تحديد هذا الخيار، فسيسمح winedbg لنظام التشغيل باختيار أي منفذ متاح. يمكن استخدام هذا الخيار بالاقتران مع --no-start لتحديد المنفذ الذي سيرتبط به الخادم.
--with-xterm
سيؤدي هذا إلى تشغيل الواجهة الأمامية لـ gdb في نافذة xterm(1) جديدة بدلاً من استخدام طرفية Unix الحالية لواجهته. يتم تجاهل هذا الخيار إذا تم تحديد --no-start.

في جميع الأوضاع، يستخدم باقي سطر الأوامر، عند تمريره، لتحديد البرنامج، إن وجد، الذي سيتم تصحيح أخطائه:

اسم_البرنامج
هذا هو اسم ملف تنفيذي سيتم تشغيله لجلسة تصحيح الأخطاء. سيقوم winedbg بإنشاء عملية بهذا الملف التنفيذي فعليًا. إذا تم توفير وسائط_البرنامج أيضًا، فسيتم استخدامها كوسائط لإنشاء العملية التي سيتم تصحيحها.
معرف_العملية_wine
سيتصل winedbg بالعملية التي يكون معرف عملية Windows الخاص بها هو معرف_العملية_wine. استخدم الأمر info proc داخل winedbg لسرد العمليات قيد التشغيل ومعرفات عمليات Windows الخاصة بها.
الوضع الافتراضي
إذا لم يتم تحديد شيء، ستدخل المصحح بدون أي عملية قيد التشغيل أو مرفقة. سيتعين عليك القيام بالمهمة بنفسك.

الأوامر

الوضع الافتراضي، وأثناء إعادة تحميل ملف تصريف مصغر:

معظم الأوامر المستخدمة في winedbg تشبه أوامر gdb. يرجى الرجوع إلى وثائق gdb لمزيد من التفاصيل. انظر قسم اختلافات gdb لاحقًا للحصول على قائمة بالاختلافات عن أوامر gdb.

معالجة العمليات

attach N
اتصل بعملية Wine (N هو معرف Windows الخاص بها، رقمي أو سداسي عشري). يمكن الحصول على المعرفات باستخدام الأمر info process. لاحظ أن الأمر info process يعيد قيمًا سداسية عشرية.
attach ملف.mdmp
أعد تحميل حالة عملية مصححة من ملف التصريف المصغر ملف.mdmp. انظر الأمر minidump لحفظ مثل هذا الملف.
detach
افصل عملية Wine الحالية. لم تعد عملية Wine مصححة بواسطة WineDbg، ولكنها لا تزال قيد التشغيل (لهدف مباشر).
kill
يقوم بقتل عملية Wine الحالية. لم تعد عملية Wine مصححة بواسطة WineDbg، ويتم إنهاؤها أيضًا (لهدف مباشر).
minidump ملف.mdmp
يحفظ سياق تصحيح أخطاء العملية المصححة في ملف تصريف مصغر يسمى ملف.mdmp.
run
أعد تشغيل نفس العملية بنفس الوسائط. ملاحظة: جميع نقاط التوقف للعملية السابقة لم تعد متاحة.
run arg1 arg2...
أعد تشغيل نفس العملية بالوسائط arg1 arg2.... ملاحظة: جميع نقاط التوقف للعملية السابقة لم تعد متاحة.
thread N

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

>
قم بتغيير المسار الحالي إلى N (معرف المسار الخاص به في Windows، رقمي أو ست عشري).

الاسم

winedbg - Wine Debugger

نبذة

winedbg [-p pid] [-a] [-m] [--gdb] [command]

الوصف

winedbg هو مصحح أخطاء لبرنامج Wine.

يمكن استدعاؤه في عدة أوضاع:

الوضع التفاعلي:

في هذا الوضع، يبدأ winedbg بنفسه ويدخل في حلقة أوامر. يمكن استدعاء هذا الوضع بدون أي خيارات.

يمكنك إرفاق winedbg بعملية قيد التشغيل باستخدام الخيار -p pid.

يمكنك استدعاء winedbg في وضع تصحيح أخطاء وضع الكارثة باستخدام الخيار -a.

يمكنك استدعاء winedbg في وضع تصحيح أخطاء الحد الأدنى من التفريغ باستخدام الخيار -m.

يمكنك استدعاء winedbg في وضع GDB باستخدام الخيار --gdb.

يمكنك تنفيذ أمر واحد ثم الخروج باستخدام command.

أنواع البيانات

i
integer
c
character (only printable 0x20-0x7f are actually printed)
b
8-bit unsigned hexadecimal integer
g
Win32 GUID

Expressions

Expressions in Wine Debugger are mostly written in a C form. However, there are a few discrepancies:

Identifiers can take a '!' in their names. This allows mainly to specify a module where to look the ID from, e.g. USER32!CreateWindowExA.

In a cast operation, when specifying a structure or a union, you must use the struct or union keyword (even if your program uses a typedef).

When specifying an identifier, if several symbols with this name exist, the debugger will prompt for the symbol you want to use. Pick up the one you want from its number.

Information on Wine internals

Lists all Windows classes registered in Wine
info class id
Prints information on Windows class id
info share
Lists all the dynamic libraries loaded in the debugged program (including .so files, NE and PE DLLs)
info share N
Prints information on module at address N
info regs
Prints the value of the CPU registers
info all-regs
Prints the value of the CPU and Floating Point registers
info segment
Lists all allocated segments (i386 only)
info segment N
Prints information on segment N (i386 only)
info stack
Prints the values on top of the stack
info map
Lists all virtual mappings used by the debugged program
info map N
Lists all virtual mappings used by the program of Windows pid N
info wnd
Displays the window hierarchy starting from the desktop window
info wnd N
Prints information of Window of handle N
info process
Lists all w-processes in Wine session
info thread
Lists all w-threads in Wine session
info frame
Lists the exception frames (starting from current stack frame). You can also pass, as optional argument, a thread id (instead of current thread) to examine its exception frames.

Debug messages can be turned on and off as you are debugging using the set command, but only for channels initialized with the WINEDEBUG environment variable.

set warn + win
Turns on warn on win channel
set + win
Turns on warn/fixme/err/trace on win channel
set - win
Turns off warn/fixme/err/trace on win channel
set fixme - all
Turns off fixme class on all channels

وضع Gdb:

See the gdb documentation for all the gdb commands.

However, a few Wine extensions are available, through the monitor command:

monitor wnd
Lists all windows in the Wine session
monitor proc
Lists all processes in the Wine session
monitor mem
Displays memory mapping of debugged process

وضع Auto و minidump:

Since no user input is possible, no commands are available.

البيئة

WINE_GDB
When used in gdb proxy mode, WINE_GDB specifies the name (and the path) of the executable to be used for gdb. "gdb" is used by default.
