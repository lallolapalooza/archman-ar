الاسم

wireshark-filter - صيغة مرشح Wireshark ومرجعها

الموجز

wireshark [خيارات أخرى] [ -Y "تعبير مرشح العرض" | --display-filter "تعبير مرشح العرض" ]

tshark [خيارات أخرى] [ -Y "تعبير مرشح العرض" | --display-filter "تعبير مرشح العرض" ]

الوصف

Wireshark و TShark تشتركان في محرك ترشيح قوي يساعد على إزالة الضوضاء من تتبع الحزم ويسمح لك برؤية الحزم التي تهمك فقط. إذا استوفت حزمة المتطلبات المعبر عنها في المرشح الخاص بك، فسيتم عرضها في قائمة الحزم. تسمح مرشحات العرض بمقارنة الحقول داخل بروتوكول بقيمة معينة، ومقارنة الحقول بالحقول، والتحقق من وجود حقول أو بروتوكولات محددة.

تُستخدم المرشحات أيضًا في ميزات أخرى مثل إنشاء الإحصائيات وتلوين قائمة الحزم (الأخير متاح فقط لـ Wireshark). تصف صفحة الدليل هذه صيغتها. يمكن العثور على مرجع شامل لحقول المرشح داخل Wireshark وفي مرجع مرشحات العرض على https://www.wireshark.org/docs/dfref/.

صيغة المرشح

التحقق مما إذا كان حقل أو بروتوكول موجودًا

يسمح لك أبسط مرشح بالتحقق من وجود بروتوكول أو حقل. إذا كنت تريد رؤية جميع الحزم التي تحتوي على بروتوكول IP، فسيكون المرشح "ip" (بدون علامتي الاقتباس). لرؤية جميع الحزم التي تحتوي على حقل Token-Ring RIF، استخدم "tr.rif".

عندما يظهر بروتوكول أو حقل كوسيطة لوظيفة في مرشح، يظهر معامل وجود لهذا البروتوكول أو الحقل بشكل ضمني.

القيم والمعاملات

كل حقل له قيمة، ويمكن استخدام هذه القيمة في عمليات مع قيم قابلة للمقارنة (والتي قد تكون قيمًا حرفية، أو حقولًا أخرى، أو نتائج دوال). قيمة الحقل ليست بالضرورة ما يظهر في عرض Wireshark أو مخرجات TShark. على سبيل المثال، يتكافئ البروتوكول دلاليًا مع سلسلة البايتات التي يشغلها، وليس النص المعروض في شجرة البروتوكول.

معاملات المقارنة

يمكن التعبير عن معاملات المقارنة إما من خلال اختصارات تشبه اللغة الإنجليزية أو من خلال رموز تشبه لغة C:

eq, ==    يساوي
ne, !=    لا يساوي
gt, >     أكبر من
lt,      أصغر من
ge, =    أكبر من أو يساوي
le, <=    أصغر من أو يساوي

يعتمد الترتيب على نوع القيمة بالطريقة المعتادة (على سبيل المثال، أبجدي للمسلسلات وحسابي للأعداد الصحيحة). قد يظهر الحقل أكثر من مرة في إطار معين. في هذه الحالة، يمكن أن تكون المساواة صارمة (يجب أن تتطابق جميع الحقول مع الشرط) أو لا (يجب أن يتطابق أي حقل مع الشرط). عدم المساواة هو النفي المنطقي للمساواة. تحتوي الطاولة التالية على جميع معاملات المساواة، وأسماءها المستعارة ومعانيها:

eq, any_eq, ==    يجب أن يكون أي حقل مساويًا
ne, all_ne, !=    يجب ألا يكون جميع الحقول متساوية
    all_eq, ===   يجب أن تكون جميع الحقول متساوية
    any_ne, !==   يجب ألا يكون أي حقول متساوية

يمكن استخدام المعاملات "any" أو "all" مع أي معامل مقارنة لجعل الاختبار يطابق أي حقل أو كل الحقول:

all tcp.port > 1024
any ip.addr != 1.1.1.1

تتمتع المعدلات "any" و "all" بالأسبقية على معاملات المقارنة مثل "===" و "any_eq".

معاملات البحث والمطابقة

توجد معاملات إضافية معبر عنها باللغة الإنجليزية فقط، وليس بصيغة تشبه لغة C:

contains     هل يحتوي البروتوكول أو الحقل أو الشريحة على قيمة
matches, ~   هل تطابق السلسلة التعبير النمطي المتوافق مع Perl (حالة غير حساسة)

يسمح معامل "contains" للمرشح بالبحث عن تسلسل من الأحرف، معبراً عنه كسلسلة، أو بايتات، معبراً عنها كمصفوفة بايتات. يجب أن يكون نوع الجانب الأيسر من معامل "contains" قابلاً للمقارنة مع نوع الجانب الأيمن بعد أي تحويلات ضمنية أو صريحة.

على سبيل المثال، للبحث عن عنوان URL محدد لـ HTTP في التقاط، يمكن استخدام المرشح التالي:

http contains "https://www.wireshark.org"

لا يمكن استخدام معامل "contains" على حقول ذرية، مثل الأرقام أو عناوين IP.

يسمح معامل "matches" أو "~" للمرشح بالتطبيق على تعبير نمطي متوافق مع Perl (PCRE2) محدد. يجب أن يكون التعبير النمطي سلسلة مزدوجة الاقتباس. يجب أن يكون الجانب الأيسر من معامل "matches" سلسلة، والتي يمكن أن تكون حقلاً غير شبيه بالسلسلة يتم تحويله ضمنيًا أو صريحًا إلى سلسلة. المطابقات غير حساسة لحالة الأحرف بشكل افتراضي. على سبيل المثال، للبحث عن وكيل مستخدم WSP لـ WAP معين، يمكنك كتابة:

wsp.header.user_agent matches "cldc"

سيؤدي هذا إلى مطابقة "cldc" أو "CLDC" أو "cLdC" أو أي تركيبة أخرى من الأحرف الكبيرة والصغيرة.

يمكنك فرض حساسية حالة الأحرف باستخدام

wsp.header.user_agent matches "(?-i)cldc"

هذا مثال على بنية خيار (?-i) في PCRE2. يقوم (?-i) بإجراء تطابق نمطي حساس لحالة الأحرف ولكن يمكن تحديد خيارات أخرى أيضًا. يمكن العثور على مزيد من المعلومات في صفحة الدليل pcre2pattern(3)|https://www.pcre.org/current/doc/html/pcre2pattern.html.

الدوال

تحتوي لغة المرشحات على الدوال التالية:

upper(string-field) - تحويل حقل سلسلة إلى أحرف كبيرة
lower(string-field) - تحويل حقل سلسلة إلى أحرف صغيرة
len(field)          - إرجاع طول البايت لحقل سلسلة أو بايتات
count(field)        - إرجاع عدد مرات ظهور الحقل في إطار
string(field)       - تحويل حقل غير سلسلة إلى سلسلة
vals(field)         - تحويل قيمة الحقل إلى سلسلة قيمته
dec(field)          - تحويل عدد صحيح غير موقع إلى سلسلة عشرية
hex(field)          - تحويل عدد صحيح غير موقع إلى سلسلة سداسية عشرية
float(field)        - تحويل حقل إلى فاصلة عائمة أحادية الدقة
double(field)       - تحويل حقل إلى فاصلة عائمة مزدوجة الدقة
max(f1,...,fn)      - إرجاع القيمة القصوى
min(f1,...,fn)      - إرجاع القيمة الدنيا
abs(field)          - إرجاع القيمة المطلقة للحقول الرقمية

تُستخدم upper() و lower() لإجراء مقارنات سلاسل غير حساسة لحالة الأحرف. على سبيل المثال:

upper(ncp.nds_stream_name) contains "MACRO"
lower(mount.dump.hostname) == "angel"

يقوم string() بتحويل قيمة الحقل إلى سلسلة، مناسبة للاستخدام مع معاملات مثل "matches" أو "contains". يتم تحويل الحقول الصحيحة إلى تمثيلها العشري. يمكن استخدامه مع عناوين IP/Ethernet (بالإضافة إلى غيرها)، ولكن ليس مع حقول السلسلة أو البايتات. على سبيل المثال:

string(frame.number) matches "[13579]$"

يعطيك جميع الحزم الفردية. لاحظ أن معامل "matches" يحول ضمنيًا أنواع تمثيل سلسلة القيمة الخاصة بها؛ لمطابقة التمثيل العشري لحقل صحيح استخدم string().

يقوم vals() بتحويل قيمة حقل صحيح أو منطقي إلى سلسلة باستخدام سلسلة قيمة الحقل المرتبطة به، إذا كانت موجودة. ينتج هذا سلاسل مشابهة لتلك التي تظهر في الأعمدة المخصصة. يمكن أيضًا استخدام السلسلة الناتجة مع معاملات أخرى. مثال:

vals(pfcp.msg_type) contains "Request"

سيطابق هذا جميع الحزم التي تحتوي على طلب PFCP، حتى لو لم تتم مطابقة هذا الطلب مع استجابة.

يقوم dec() و hex() بتحويل حقول الأعداد الصحيحة غير الموقعة إلى تمثيل عشري أو سداسي عشري. حاليًا، يعطي dec() و string() نفس النتيجة لعدد صحيح غير موقع، ولكنه من الممكن

Functions

A number of functions are available for filtering. These functions take one or more arguments and return a value. The arguments must all have the same type, and the return type depends on the function. These functions can be used in both display and capture filters.

A number of functions exist to convert values from one type to another. These are useful for comparing fields of different types, or when you need to extract a specific type from a field.

string(field)      - Returns the string representation of the field.
bytes(field)       - Returns the byte representation of the field.
hexadecimal(field) - Returns the hexadecimal representation of the field.
decimal(field)     - Returns the decimal representation of the field.
octal(field)       - Returns the octal representation of the field.
binary(field)      - Returns the binary representation of the field.

The behaviour of string() on integer fields may change in the future, so it is recommended that you use hexadecimal(), decimal(), octal(), or binary() when you need to convert an integer field to its string representation.

It is possible to use the string() function on fields which are not strings. For example, you can use it on integer fields, to convert them to strings. It is also possible to use it on byte fields, to convert them to strings. It is also possible to use it on floating point fields, to convert them to strings. It is also possible to use it on IP address fields, to convert them to strings. It is also possible to use it on MAC address fields, to convert them to strings. It is also possible to use it on date and time fields, to convert them to strings. It is also possible to use it on boolean fields, to convert them to strings. It is also possible to use it on enum fields, to convert them to strings. It is also possible to use it on array fields, to convert them to strings. It is also possible to use it on struct fields, to convert them to strings.

The string() function will convert the field to its string representation. For example, if you have an integer field named frame.len, you can convert it to a string using string(frame.len). This will return the string "1234" if the frame length is 1234.

The string() function will be able to convert any field to its string representation. The behavior of string() on certain fields may change in the future. The developers are considering changing the behavior of string() for integer fields in the future. It is possible that in the future string() will use the native base of the field.

max() and min() take any number of arguments and returns one value, respectively the largest/smallest. The arguments must all have the same type.

There is also a set of functions to test IP addresses:

ip_special_name(ip)       - Returns the IP special-purpose block name as a string
ip_special_mask(ip)       - Returns the IP special-purpose block flags as a mask. The bits are:
                                4 3 2 1 0
                                ---------
                                S D F G R
                            S = Source, D = Destination, F = Forwardable, G = Globally-reachable, R = Reserved-by-protocol
ip_linklocal(ip)          - true if the IPv4 or IPv6 address is link-local
ip_multicast(ip)          - true if the IPv4 or IPv6 address is multicast
ip_rfc1918(ipv4)          - true if the IPv4 address is private-use (from the allocation in RFC 1918)
ip_ula(ipv6)              - true if the IPv6 address is unique-local (ULA) as in RFC 4193

Macros

It is possible to define display filter macros. Macro are names that are replaced with the associated expression, possibly performing argument substitution. Macro expansions are purely textual replacements and performed recursively before compilation. They allow replacing long and often used expressions with easy to use names.

Macros are defined using the GUI or directly in the "dmacros" configuration file. For example the definition

"addplusone" {$1 + $2 + 1}

creates a macro called addplusone that takes two arguments and expands to the given expression. Arguments in the replacement expression are given using the dollar sign.

Macros are invoked like function but preceded with a dollar sign (sometimes also called a sigil):

$addplusone(udp.src_port,udp.dst_port)

results in the expression

{udp.src_port + udp.dst_port + 1}

after argument substitution. There is an older alternative notation to invoke macros:

${addplusone:udp.src_port;udp.dst_port}

or

${addplusone;udp.src_port;udp.dst_port}

Both forms are equivalent and can be used interchangibly as a matter of preference.

Protocol field types

Each protocol field is typed. The types are:

ASN.1 object identifier, plain or relative
AX.25 address
Boolean
Byte sequence
Character string
Character, 1 byte
Date and time
Ethernet or other MAC address
EUI64 address
Fibre Channel WWN
Floating point, single or double precision
Frame number
Globally Unique Identifier
IEEE-11073 floating point, 16 or 32 bits
IPv4 address
IPv6 address
IPX network number
Label
OSI System-ID
Protocol
Signed integer, 1, 2, 3, 4, or 8 bytes
Time offset
Unsigned integer, 1, 2, 3, 4, or 8 bytes
VINES address

An integer may be expressed in decimal, octal, hexadecimal or binary notation, or as a C-style character constant. The following seven display filters are equivalent:

frame.len > 10
frame.len > 012
frame.len > 0xa
frame.len > 0b1010
frame.len > '\n'
frame.len > '\x0a'
frame.len > '\012'

Boolean values are either true or false. In a display filter expression testing the value of a Boolean field, true is expressed as the word true (case-insensitive) or any non-zero number. False is expressed as false (case-insensitive) or the number zero. For example, a token-ring packet’s source route field is Boolean. To find any source-routed packets, a display filter would be any of the following:

tr.sr == 1
tr.sr == true
tr.sr == TRUE

Non source-routed packets can be found with:

tr.sr == 0
tr.sr == false
tr.sr == FALSE

Ethernet addresses and byte arrays are represented by hex digits. The hex digits may be separated by colons, periods, or hyphens:

eth.dst eq ff:ff:ff:ff:ff:ff
aim.data == 0.1.0.d
fddi.src == aa-aa-aa-aa-aa-aa
echo.data == 7a

IPv4 addresses can be represented in either dotted decimal notation or by using the hostname:

ip.src == 192.168.1.1
ip.dst eq www.mit.edu

IPv4 addresses can be compared with the same logical relations as numbers: eq, ne, gt, ge, lt, and le. The IPv4 address is stored in host order, so you do not have to worry about the endianness of an IPv4 address when using it in a display filter.

Classless Inter-Domain Routing (CIDR) notation can be used to test if an IPv4 address is in a certain subnet. For example, this display filter will find all packets in the 129.111 network:

ip.addr == 129.111.0.0/16

Remember, the number after the slash represents the number of bits used to represent the network. CIDR notation can also be used with hostnames, as in this example of finding IP addresses on the same network as 'sneezy' (requires that 'sneezy' resolve to an IP address for filter to be valid):

ip.addr eq sneezy/24

The CIDR notation can only be used on IP addresses or hostnames, not in variable names. So, a display filter like "ip.src/24 == ip.dst/24" is not valid (yet).

Transaction and other IDs are often represented by unsigned 16 or 32 bit integers and formatted as a hexadecimal string with "0x" prefix:

(dhcp.id == 0xfe089c15) || (ip.id == 0x0373)

Strings are enclosed in double quotes:

http.request.method == "POST"

Inside double quotes, you may use a backslash to embed a double quote or an arbitrary byte represented in either octal or hexadecimal.

browser.comment == "An embedded \" double-quote"

Use of hexadecimal to look for "HEAD":

http.request.method == "\x48EAD"

Use of octal to look for "HEAD":

http.request.method == "\110EAD"

This means that you must escape backslashes with backslashes inside double quotes.

smb.path contains "\\\\SERVER\\SHARE"

looks for \\SERVER\SHARE in "smb.path". This may be more conveniently written as

smb.path contains r"\\SERVER\SHARE"

String literals prefixed with 'r' are called "raw strings". Such strings treat backslash as a literal character. Double quotes may still be escaped with backslash but note that backslashes are always preserved in the result.

The following table lists all escape sequences supported with strings and character constants:

\'          single quote
\"          double quote
\\          backslash
\a          audible bell
\b          backspace
\f          form feed
\n          line feed
\r          carriage return
\t          horizontal tab
\v          vertical tab
\NNN        arbitrary octal value
\xNN        arbitrary hexadecimal value
\uNNNN      Unicode codepoint U+NNNN
\UNNNNNNNN  Unicode codepoint U+NNNNNNNN

Date and time values can be given in ISO 8601 format or using a legacy month-year-time format:

"2020-07-04T12:34:56"
"Sep 26, 2004 23:18:04.954975"

The 'T' separator in ISO 8601 can be omitted. The timezone can be given as "Z" or an offset from UTC.

When not using ISO 8601 the timezone can be given as the strings "UTC", "GMT" or "UT" for UTC or also given as an offset from UTC, plus some North American and Nautical/Military designations (see the specification for %z in strptime(3) https://man.netbsd.org/strptime.3). Note that arbitrary timezone names are not supported however.

If the timezone is omitted then date and time values are interpreted as local time.

The slice operator

You can take a slice of a field if the field base type is a text string or a byte array (the base type of most network address fields is bytes). For example, you can filter on the vendor portion of an ethernet address (the first three bytes) like this:

eth.src[0:3] == 00:00:83

Another example is:

http.content_type[0:4] == "text"

You can use the slice operator on a protocol name, too. The "frame" protocol can be useful, encompassing all the data captured by Wireshark or TShark.

token[0:5] ne 0.0.0.1.1
llc[0] eq aa
frame[100-199] contains "wireshark"

The following syntax governs slices:

[i:j]    i = start_offset, j = length
[i-j]    i = start_offset, j = end_offset, inclusive.
[i]      i = start_offset, length = 1
[:j]     start_offset = 0, length = j
[i:]     start_offset = i, end_offset = end_of_field

Slice indexes are zero-based. Offsets can be negative, in which case they indicate the offset from the end of the field. The last byte of the field is at offset -1, the last but one byte is at offset -2, and so on. Here’s how to check the last four bytes of a frame:

frame[-4:4] == 0.1.2.3

or

frame[-4:] == 0.1.2.3

As mentioned above the slice operator can be used on string and byte fields and will respectively produce string or byte slices. String slices are indexed on UTF-8 codepoint boundaries (i.e: internationalized characters), so the following comparison is true:

"touché"[5] == "é"

The example above generates an error because the compiler rejects constant expressions but is otherwise syntactically correct and exemplifies the behaviour of string slices.

To obtain a byte slice of the same string the raw (@) operator can be used:

@"touché"[5-6] == c3:a9

A slice can always be compared against either a string or a byte sequence.
