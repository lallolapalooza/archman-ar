الاسم

wm - التواصل مع مدير النوافذ

الملخص

wm خيار نافذة ?وسائط?

الوصف

يُستخدم الأمر wm للتفاعل مع مديري النوافذ من أجل التحكم في أشياء مثل عنوان النافذة، هندستها، أو الزيادات التي يمكن تغيير حجمها بها. يمكن أن يأخذ الأمر wm أيًا من عدة أشكال مختلفة، اعتمادًا على الوسيط خيار. تتوقع جميع الأشكال وسيطًا إضافيًا واحدًا على الأقل، وهو نافذة، والذي يجب أن يكون اسم المسار لنافذة علوية.

الأشكال القانونية للأمر wm هي:

wm aspect نافذة ?الحد الأدنى للبسط الحد الأدنى للمقام الحد الأقصى للبسط الحد الأقصى للمقام?
إذا تم تحديد الحد الأدنى للبسط و الحد الأدنى للمقام و الحد الأقصى للبسط و الحد الأقصى للمقام، فسيتم تمريرها إلى مدير النوافذ ويجب على مدير النوافذ استخدامها لفرض نطاق من نسب العرض إلى الارتفاع المقبولة لـ النافذة. سيتم تقييد نسبة العرض إلى الارتفاع لـ النافذة (العرض/الطول) لتكون بين الحد الأدنى للبسط/الحد الأدنى للمقام و الحد الأقصى للبسط/الحد الأقصى للمقام. إذا تم تحديد الحد الأدنى للبسط وما إلى ذلك كسلاسل فارغة، فسيتم إزالة أي قيود حالية على نسبة العرض إلى الارتفاع. إذا تم تحديد الحد الأدنى للبسط وما إلى ذلك، فسيُرجع الأمر سلسلة فارغة. بخلاف ذلك، فإنه يُرجع قائمة Tcl تحتوي على أربعة عناصر، وهي القيم الحالية لـ الحد الأدنى للبسط و الحد الأدنى للمقام و الحد الأقصى للبسط و الحد الأقصى للمقام (إذا لم تكن هناك قيود على نسبة العرض إلى الارتفاع سارية المفعول، فسيتم إرجاع سلسلة فارغة).

يقوم هذا الأمر الفرعي بإرجاع أو تعيين سمات خاصة بالمنصة مرتبطة بنافذة. يُرجع الشكل الأول قائمة بالسمات الخاصة بالمنصة وقيمها. يُرجع الشكل الثاني قيمة الخيار المحدد. يقوم الشكل الثالث بتعيين قيمة واحدة أو أكثر. القيم هي كما يلي:

جميع المنصات تدعم السمات التالية (على الرغم من أن مستخدمي X11 يجب أن يروا الملاحظات أدناه):

-alpha
يحدد مستوى شفافية ألفا للنافذة العلوية. يقبل قيمة من 0.0 (شفاف تمامًا) إلى 1.0 (غير شفاف). سيتم تقييد القيم خارج هذا النطاق. حيثما لم يتم دعمه، تظل قيمة -alpha عند 1.0.
-fullscreen
يضع النافذة في وضع يشغل الشاشة بأكملها، ولا يحتوي على حدود، ويغطي منطقة الاستخدام العامة (أي قائمة البدء وشريط المهام على Windows، والـ dock وشريط القوائم على macOS، وزخارف النافذة العامة على X11).
-topmost
يحدد ما إذا كانت هذه نافذة علوية (تظهر فوق جميع النوافذ الأخرى).

على Windows، يمكن تعيين السمات التالية.

-disabled
يحدد ما إذا كانت النافذة في حالة معطلة.

يحدد نمط نافذة أدوات (كما هو محدد في MSDN).

على macOS، يمكن تعيين السمات التالية.

-modified
يحدد حالة تعديل النافذة (يحدد ما إذا كانت أداة إغلاق النافذة تحتوي على مؤشر التعديل وما إذا كان رمز الوكيل قابلاً للسحب).

-titlepath

-transparent
يجعل منطقة محتوى النافذة شفافة ويلغي الظل الخاص بالنافذة. لكي تكون الشفافية فعالة، يجب تعيين خلفية النافذة العلوية إلى لون يحتوي على بعض الألفا، على سبيل المثال "systemTransparent".

wm client window ?name?
If name is specified, this command stores name (which should be the name of the host on which the application is executing) in window's WM_CLIENT_MACHINE property for use by the window manager or session manager. The command returns an empty string in this case. If name is not specified, the command returns the last name set in a wm client command for window. If name is specified as an empty string, the command deletes the WM_CLIENT_MACHINE property from window.
wm colormapwindows window ?windowList?
This command is used to manipulate the WM_COLORMAP_WINDOWS property, which provides information to the window managers about windows that have private colormaps.

If windowList is not specified, the command returns a list whose elements are the names of the windows in the WM_COLORMAP_WINDOWS property. If windowList is specified, it consists of a list of window path names; the command overwrites the WM_COLORMAP_WINDOWS property with the given windows and returns an empty string. The WM_COLORMAP_WINDOWS property should normally contain a list of the internal windows within window whose colormaps differ from their parents.

The order of the windows in the property indicates a priority order: the window manager will attempt to install as many colormaps as possible from the head of this list when window gets the colormap focus. If window is not included among the windows in windowList, Tk implicitly adds it at the end of the WM_COLORMAP_WINDOWS property, so that its colormap is lowest in priority. If wm colormapwindows is not invoked, Tk will automatically set the property for each top-level window to all the internal windows whose colormaps differ from their parents, followed by the top-level itself; the order of the internal windows is undefined. See the ICCCM documentation for more information on the WM_COLORMAP_WINDOWS property.

wm command window ?value?
If value is specified, this command stores value in window's WM_COMMAND property for use by the window manager or session manager and returns an empty string. Value must have proper list structure; the elements should contain the words of the command used to invoke the application. If value is not specified then the command returns the last value set in a wm command command for window. If value is specified as an empty string, the command deletes the WM_COMMAND property from window.
wm deiconify window
Arrange for window to be displayed in normal (non-iconified) form. This is done by mapping the window. If the window has never been mapped then this command will not map the window, but it will ensure that when the window is first mapped it will be displayed in de-iconified form. On Windows, a deiconified window will also be raised and be given the focus (made the active window). Returns an empty string.
wm focusmodel window ?active|passive?
If active or passive is supplied as an optional argument to the command, then it specifies the focus model for window. In this case the command returns an empty string. If no additional argument is supplied, then the command returns the current focus model for window.

An active focus model means that window will claim the input focus for itself or its descendants, even at times when the focus is currently in some other application. Passive means that window will never claim the focus for itself: the window manager should give the focus to window at appropriate times. However, once the focus has been given to window or one of its descendants, the application may re-assign the focus among window's descendants. The focus model defaults to passive, and Tk's focus command assumes a passive model of focusing.

wm forget window
The window will be unmapped from the screen and will no longer be managed by wm. Windows created with the toplevel command will be treated like frame windows once they are no longer managed by wm, however, the -menu configuration will be remembered and the menus will return once the widget is managed again.
wm frame window
If window has been reparented by the window manager into a decorative frame, the command returns the platform specific window identifier for the outermost frame that contains window (the window whose parent is the root or virtual root). If window has not been reparented by the window manager then the command returns the platform specific window identifier for window.
wm geometry window ?newGeometry?
If newGeometry is specified, then the geometry of window is changed and an empty string is returned. Otherwise the current geometry for window is returned (this is the most recent geometry specified either by manual resizing or in a wm geometry command). NewGeometry has the form =widthxheight±x±y, where any of =, widthxheight, or ±x±y may be omitted. Width and height are positive integers specifying the desired dimensions of window. If window is gridded (see GRIDDED GEOMETRY MANAGEMENT below) then the dimensions are specified in grid units; otherwise they are specified in pixel units.

X and y specify the desired location of window on the screen, in pixels. If x is preceded by +, it specifies the number of pixels between the left edge of the screen and the left edge of window's border; if preceded by - then x specifies the number of pixels between the right edge of the screen and the right edge of window's border. If y is preceded by + then it specifies the number of pixels between the top of the screen and the top of window's border; if y is preceded by - then it specifies the number of pixels between the bottom of window's border and the bottom of the screen.

If newGeometry is specified as an empty string then any existing user-specified geometry for window is cancelled, and the window will revert to the size requested internally by its widgets.

Note that this is related to winfo geometry, but not the same. That can only query the geometry, and always reflects Tk's current understanding of the actual size and location of window, whereas wm geometry allows both setting and querying of the window manager's understanding of the size and location of the window. This can vary significantly, for example to reflect the addition of decorative elements to window such as title bars, and window managers are not required to precisely follow the requests made through this command.

wm grid window ?baseWidth baseHeight widthInc heightInc?
This command indicates that window is to be managed as a gridded window. It also specifies the relationship between grid units and pixel units. BaseWidth and baseHeight specify the number of grid units corresponding to the pixel dimensions requested internally by window using Tk_GeometryRequest. WidthInc and heightInc specify the number of pixels in each horizontal and vertical grid unit. These four values determine a range of acceptable sizes for window, corresponding to grid-based widths and heights that are non-negative integers. Tk will pass this information to the window manager; during manual resizing, the window manager will restrict the window's size to one of these acceptable sizes.

Furthermore, during manual resizing the window manager will display the window's current size in terms of grid units rather than pixels. If baseWidth etc. are all specified as empty strings, then window will no longer be managed as a gridded window. If baseWidth etc. are specified then the return value is an empty string.

Otherwise the return value is a Tcl list containing four elements corresponding to the current baseWidth, baseHeight, widthInc, and heightInc; if window is not currently gridded, then an empty string is returned.

Note that this command should not be needed very often, since the Tk_SetGrid library procedure and the setGrid option provide easier access to the same functionality.

wm group window ?pathName?
If pathName is specified, it gives the path name for the leader of a group of related windows. The window manager may use this information, for example, to unmap all of the windows in a group when the group's leader is iconified. PathName may be specified as an empty string to remove window from any group association. If pathName is specified then the command returns an empty string; otherwise it returns the path name of window's current group leader, or an empty string if window is not part of any group.

التحكم بواسطة واحد يستجيب بشكل مختلف.

تعتمد قائمة بروتوكولات مدير النوافذ المتاحة على مدير النوافذ، ولكن جميع مديري النوافذ المدعومين من Tk يوفرون WM_DELETE_WINDOW. على منصة ويندوز، يتم إرسال رسالة WM_SAVE_YOURSELF عند تسجيل خروج المستخدم أو إعادة تشغيل النظام.

إذا تم تحديد كل من name و command، فإن command يصبح المعالج للبروتوكول المحدد بواسطة name. سيتم إضافة الذرة الخاصة بـ name إلى خاصية WM_PROTOCOLS الخاصة بـ window لإخبار مدير النوافذ بأن التطبيق لديه معالج للبروتوكول المحدد بواسطة name، وسيتم استدعاء command في المستقبل كلما أرسل مدير النوافذ رسالة بهذا البروتوكول إلى تطبيق Tk. في هذه الحالة، يعيد الأمر wm protocol سلسلة فارغة. إذا تم تحديد name ولكن command لم يتم تحديده، فسيتم إرجاع المعالج الحالي لـ name، أو سلسلة فارغة إذا لم يكن هناك معالج معرف لـ name (كحالة خاصة، لا يتم إرجاع المعالج الافتراضي لـ WM_DELETE_WINDOW). إذا تم تحديد command كسلسلة فارغة، فسيتم إزالة الذرة الخاصة بـ name من خاصية WM_PROTOCOLS الخاصة بـ window وسيتم تدمير المعالج؛ وسيتم إرجاع سلسلة فارغة. أخيرًا، إذا لم يتم تحديد name أو command، فإن الأمر wm protocol يعيد قائمة بجميع البروتوكولات التي تم تعريف معالجات لها حاليًا لـ window.

wm resizable window ?width height?
يتحكم هذا الأمر فيما إذا كان المستخدم يمكنه تغيير حجم النافذة العلوية بشكل تفاعلي أم لا. إذا تم تحديد width و height، فستكون هذه قيم منطقية تحدد ما إذا كان يمكن للمستخدم تعديل عرض وارتفاع window. في هذه الحالة، يعيد الأمر سلسلة فارغة. إذا تم حذف width و height، فإن الأمر يعيد قائمة بعنصرين 0/1 يشيران إلى ما إذا كان يمكن تغيير عرض وارتفاع window حاليًا. افتراضيًا، تكون النوافذ قابلة لتغيير الحجم في كلا البعدين. إذا تم تعطيل تغيير الحجم، فسيكون حجم النافذة هو الحجم من آخر تغيير حجم تفاعلي أو أمر wm geometry. إذا لم تكن هناك عملية من هذا القبيل، فسيتم استخدام الحجم الطبيعي للنافذة.
wm sizefrom window ?who?
إذا تم تحديد who، فيجب أن تكون إما program أو user، أو اختصارًا لأحدهما. يشير إلى ما إذا كان حجم window الحالي قد طلبه البرنامج أو المستخدم. تتجاهل بعض مديري النوافذ الأحجام التي يطلبها البرنامج وتطلب من المستخدم تغيير حجم النافذة يدويًا؛ إذا تم تحديد user، فيجب على مدير النوافذ إعطاء النافذة حجمها المحدد دون طلب المساعدة من المستخدم. إذا تم تحديد who كسلسلة فارغة، فسيتم إلغاء مصدر الحجم الحالي. إذا تم تحديد who، فإن الأمر يعيد سلسلة فارغة. بخلاف ذلك، يعيد user أو window للإشارة إلى مصدر الحجم الحالي للنافذة، أو سلسلة فارغة إذا لم يتم تحديد أي مصدر حتى الآن. يفسر معظم مديري النوافذ "لا مصدر" على أنه مكافئ لـ program.
wm stackorder window ?isabove|isbelow window?
يعيد الأمر stackorder قائمة بالنوافذ العلوية بترتيب التكديس، من الأدنى إلى الأعلى. عندما يتم تمرير نافذة علوية واحدة، تتضمن القائمة المعادة بشكل متكرر جميع عناصر النافذة الفرعية التي هي نوافذ علوية. يتم إرجاع النوافذ العلوية فقط التي تم تعيينها حاليًا على الشاشة. يمكن أيضًا استخدام الأمر stackorder لتحديد ما إذا كانت نافذة علوية واحدة موضوعة فوق أو أسفل نافذة علوية ثانية. عند تمرير وسيطتين للنافذة مفصولتين بـ isabove أو isbelow، يشير نتيجة منطقية إلى ما إذا كانت النافذة الأولى حاليًا فوق أو أسفل النافذة الثانية في ترتيب التكديس.
wm state window ?newstate?
إذا تم تحديد newstate، فسيتم تعيين النافذة إلى الحالة الجديدة، وإلا فإنها تعيد الحالة الحالية لـ window: إما normal، iconic، withdrawn، icon، أو (Windows و macOS فقط) zoomed. الفرق بين iconic و icon هو أن iconic يشير إلى نافذة تم تصغيرها (على سبيل المثال، باستخدام الأمر wm iconify) بينما icon يشير إلى نافذة غرضها الوحيد هو العمل كأيقونة لنافذة أخرى (عبر الأمر wm iconwindow). لا يمكن تعيين حالة icon.
wm title window ?string?
إذا تم تحديد string، فسيتم تمريرها إلى مدير النوافذ لاستخدامها كعنوان لـ window (يجب أن يعرض مدير النوافذ هذه السلسلة في شريط عنوان window). في هذه الحالة، يعيد الأمر سلسلة فارغة. إذا لم يتم تحديد string، فإن الأمر يعيد العنوان الحالي لـ window. يحدد عنوان النافذة افتراضيًا باسمها.

إذا تم تحديد container، فسيتم إبلاغ مدير النوافذ بأن window هي نافذة مؤقتة (على سبيل المثال، قائمة منسدلة) تعمل نيابة عن container (حيث container هو اسم المسار لنافذة علوية). إذا تم تحديد container كسلسلة فارغة، فسيتم تمييز window على أنها ليست نافذة مؤقتة بعد الآن. بخلاف ذلك، يعيد الأمر اسم المسار لـ container الحالي لـ window، أو سلسلة فارغة إذا لم تكن window حاليًا نافذة مؤقتة. سترى النافذة المؤقتة تغييرات الحالة في الحاوية وستكتسب حالة الحاوية عند تعيينها لأول مرة. يجب أن تكون الرسم البياني الموجه مع حافة من كل نافذة مؤقتة إلى حاويتها دوريًا. على وجه الخصوص، يعتبر من الخطأ محاولة جعل نافذة نافذة مؤقتة لنفسها. قد يقوم مدير النوافذ أيضًا بتزيين النافذة المؤقتة بشكل مختلف، وإزالة بعض الميزات الموجودة عادةً (على سبيل المثال، أزرار التصغير والتكبير)، على الرغم من أن هذا يرجع بالكامل إلى تقدير مدير النوافذ.
wm withdraw window
يرتب لإزالة window من الشاشة. يتسبب هذا في إلغاء تعيين النافذة ونسيانها بواسطة مدير النوافذ. إذا لم يتم تعيين النافذة مطلقًا، فإن هذا الأمر يتسبب في تعيين النافذة في الحالة المسحوبة. لا يبدو أن جميع مديري النوافذ يعرفون كيفية التعامل مع النوافذ التي تم تعيينها في الحالة المسحوبة. لاحظ أنه في بعض الأحيان يبدو أنه من الضروري سحب نافذة ثم إعادة تعيينها (على سبيل المثال، باستخدام wm deiconify) لجعل بعض مديري النوافذ ينتبهون للتغييرات في سمات النافذة مثل المجموعة.

إدارة الموضع

افتراضيًا، تظهر النافذة العلوية على الشاشة في حجمها الطبيعي، وهو الحجم الذي تحدده الأدوات ومديري المواضع داخليًا. إذا تغير الحجم الطبيعي للنافذة العلوية، فستتغير أبعاد النافذة لتتوافق. يمكن إعطاء النافذة العلوية حجمًا آخر غير حجمها الطبيعي بطريقتين. أولاً، يمكن للمستخدم تغيير حجم النافذة يدويًا باستخدام مرافق مدير النوافذ، مثل مقابض تغيير الحجم. ثانيًا، يمكن للتطبيق طلب حجم معين لنافذة علوية باستخدام الأمر wm geometry. يتم التعامل مع هاتين الحالتين بشكل متطابق بواسطة Tk؛ في كلتا الحالتين، يتجاوز الحجم المطلوب الحجم الطبيعي. يمكنك إعادة النافذة إلى حجمها الطبيعي عن طريق استدعاء wm geometry بسلسلة geometry فارغة.

عادةً ما يمكن أن يكون للنافذة العلوية أي حجم من بكسل واحد في كل بعد إلى حجم شاشتها. ومع ذلك، يمكنك استخدام الأوامر wm minsize و wm maxsize لتحديد نطاق الأحجام المسموح بها. ينطبق النطاق الذي تم تعيينه بواسطة wm minsize و wm maxsize على جميع أشكال تغيير الحجم، بما في ذلك الحجم الطبيعي للنافذة بالإضافة إلى تغييرات الحجم اليدوية وأمر wm geometry. يمكنك أيضًا استخدام الأمر wm resizable لتعطيل تغيير الحجم التفاعلي تمامًا في بعد واحد أو كليهما.

يمكن استخدام الأوامر wm manage و wm forget لإجراء فصل وربط النوافذ. بعد إدارة أداة باستخدام الأمر wm manage، يمكن استخدام جميع أوامر wm الأخرى مع الأداة. لا يمكن إلا للأدوات التي تم إنشاؤها باستخدام أمر toplevel أن يكون لها قائمة مرفقة عبر خيار التكوين -menu. يمكن استخدام أداة toplevel كإطار وإدارتها مع أي من مديري المواضع الآخرين بعد استخدام الأمر wm forget. سيتم إخفاء أي قائمة مرتبطة بأداة toplevel عند إدارتها بواسطة مديري مواضع آخرين. ستظهر القوائم مرة أخرى بمجرد إدارة النافذة بواسطة wm. يجب إعادة تعيين جميع bindtags المخصصة للأدوات في شجرة فرعية تم تغيير أداة toplevel الخاصة بها عبر أمر wm manage أو wm forget، لتعديل أي مسار لأداة toplevel في bindtags. لا يلزم إعادة تعيين bindtags التي لم يتم تخصيصها.

إدارة المواضع الشبكية

تحدث إدارة المواضع الشبكية عندما تدعم إحدى أدوات التطبيق نطاقًا من الأحجام المفيدة. يحدث هذا، على سبيل المثال، في محرر نصوص حيث تكون أشرطة التمرير والقوائم والزخارف الأخرى ثابتة الحجم ولكن يمكن لأداة التحرير دعم أي عدد من الأسطر النصية أو الأحرف لكل سطر. في هذه الحالة، من المرغوب فيه عادةً السماح للمستخدم بتحديد عدد الأسطر أو الأحرف لكل سطر، إما باستخدام الأمر wm geometry أو عن طريق تغيير حجم النافذة تفاعليًا. في حالة النص، وفي حالات أخرى مثيرة للاهتمام أيضًا، تكون الأحجام المنفصلة للنافذة فقط منطقية، مثل الأعداد الصحيحة من الأسطر والأحرف لكل سطر؛ الأحجام العشوائية بالبكسل ليست مفيدة.

توفر إدارة المواضع الشبكية الدعم لهذا النوع من التطبيقات. تفترض Tk (ومدير النوافذ) وجود شبكة من نوع ما داخل التطبيق وأن التطبيق يجب تغيير حجمه بوحدات شبكية بدلاً من وحدات البكسل. يتم استدعاء إدارة المواضع الشبكية عادةً عن طريق تشغيل خيار setGrid لأداة؛ يمكن استدعاؤها أيضًا باستخدام الأمر wm grid أو عن طريق استدعاء Tk_SetGrid. في كل من هذه الأساليب، تحدد الأداة المعينة (أو أحيانًا التعليمات البرمجية في التطبيق ككل) العلاقة بين أحجام الشبكة الصحيحة للنافذة وأحجام البكسل. للعودة إلى إدارة المواضع غير الشبكية، استدعاء wm grid بسلاسل وسيطات فارغة.
