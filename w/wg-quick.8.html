wg-quick(8)

الحزمة: wireguard-tools

التراخيص: GPL

WG-QUICK(8) WireGuard WG-QUICK(8)

الاسم

wg-quick - إعداد واجهة WireGuard ببساطة

الاستخدام

wg-quick [ up | down | save | strip ] [ CONFIG_FILE | INTERFACE ]

الوصف

هذه أداة نصية بسيطة للغاية لإعداد واجهة WireGuard بسهولة، ومناسبة لعدد قليل من حالات الاستخدام الشائعة.

استخدم up لإضافة واجهة وإعدادها، واستخدم down لإيقاف الواجهة وإزالتها. يؤدي تشغيل up إلى إضافة واجهة WireGuard، وتشغيل الواجهة بالعناوين IP المقدمة، وإعداد MTU والمسارات، وتشغيل نصوص برمجية اختيارية قبل وبعد التشغيل. يؤدي تشغيل down إلى حفظ التكوين الحالي اختياريًا، وإزالة واجهة WireGuard، وتشغيل نصوص برمجية اختيارية قبل وبعد الإيقاف. استخدم save لحفظ تكوين واجهة موجودة دون إيقاف الواجهة. استخدم strip لإخراج ملف تكوين مع إزالة جميع الخيارات الخاصة بـ wg-quick(8)، وهو مناسب للاستخدام مع wg(8).

CONFIG_FILE هو ملف تكوين، يكون اسم الملف فيه هو اسم الواجهة متبوعًا بـ `.conf'. بخلاف ذلك، INTERFACE هو اسم واجهة، ويتم البحث عن التكوين الموجود في `/etc/wireguard/INTERFACE.conf'، أولاً، متبوعًا بمسارات البحث الخاصة بالتوزيع.

بشكل عام، هذه الأداة هي مجرد نص برمجي بسيط يغلف استدعاءات لـ wg(8) و ip(8) لإعداد واجهة WireGuard. تم تصميمها للمستخدمين ذوي الاحتياجات البسيطة، ويتم تشجيع المستخدمين ذوي الاحتياجات الأكثر تقدمًا بشدة على استخدام أداة أكثر تحديدًا، أو مدير شبكة أكثر اكتمالاً، أو بخلاف ذلك استخدام wg(8) و ip(8)، كالمعتاد.

التكوين

يضيف ملف التكوين بعض قيم التكوين الإضافية إلى التنسيق الذي يفهمه wg(8) لتكوين سمات إضافية لواجهة. يتعامل مع القيم التي يفهمها، ثم يمرر الباقي مباشرة إلى wg(8) لمزيد من المعالجة.

يستنتج جميع المسارات من قائمة عناوين IP المسموح بها للأقران، ويضيفها تلقائيًا إلى جدول توجيه النظام. إذا كان أحد هذه المسارات هو المسار الافتراضي (0.0.0.0/0 أو ::/0)، فإنه يستخدم ip-rule(8) لمعالجة تجاوز البوابة الافتراضية.

سيتم تمرير ملف التكوين مباشرة إلى الأمر الفرعي `setconf` الخاص بـ wg(8)، باستثناء الإضافات التالية لقسم Interface، والتي يتم التعامل معها بواسطة هذه الأداة:

  • Address — قائمة مفصولة بفواصل من عناوين IP (v4 أو v6) (اختياريًا مع أقنعة CIDR) ليتم تعيينها للواجهة. يمكن تحديدها عدة مرات.
  • DNS — قائمة مفصولة بفواصل من عناوين IP (v4 أو v6) ليتم تعيينها كخوادم DNS للواجهة، أو أسماء مضيفين غير IP ليتم تعيينها كمجالات بحث DNS للواجهة. يمكن تحديدها عدة مرات. عند تشغيل الواجهة، يتم تشغيل `resolvconf -a tun.INTERFACE -m 0 -x` وعند إيقافها، يتم تشغيل `resolvconf -d tun.INTERFACE`. إذا كانت استدعاءات resolvconf(8) هذه غير مرغوبة، يمكن استخدام مفاتيح PostUp و PostDown أدناه بدلاً من ذلك.
  • MTU — إذا لم يتم تحديده، يتم تحديد MTU تلقائيًا من عناوين نقطة النهاية أو المسار الافتراضي للنظام، وهو عادةً خيار جيد. ومع ذلك، لتحديد MTU يدويًا لتجاوز هذا الاكتشاف التلقائي، يمكن تحديد هذه القيمة بشكل صريح.
  • Table — يتحكم في جدول التوجيه الذي تتم إضافة المسارات إليه. هناك قيمتان خاصتان: `off' يعطل إنشاء المسارات تمامًا، و `auto' (الافتراضي) يضيف المسارات إلى الجدول الافتراضي ويمكّن المعالجة الخاصة للمسارات الافتراضية.
  • PreUp, PostUp, PreDown, PostDown — مقتطفات نصية سيتم تنفيذها بواسطة bash(1) قبل/بعد إعداد/إيقاف الواجهة، وغالبًا ما تستخدم لتكوين خيارات DNS مخصصة أو قواعد جدار الحماية. يتم توسيع السلسلة الخاصة `%i' إلى INTERFACE. يمكن تحديد كل منها عدة مرات، وفي هذه الحالة يتم تنفيذ الأوامر بالترتيب.
  • SaveConfig — إذا تم تعيينها على `true'، فسيتم حفظ التكوين من الحالة الحالية للواجهة عند الإغلاق. لذلك، سيتم الكتابة فوق أي تغييرات تم إجراؤها على ملف التكوين قبل إزالة الواجهة.

أسماء INTERFACE الموصى بها تشمل `wg0' أو `wgvpn0' أو حتى `wgmgmtlan0'. ومع ذلك، فإن الرقم في النهاية اختياري في الواقع، وأي سلسلة نصية حرة [a-zA-Z0-9_=+.-]{1,15} ستعمل. لذلك، حتى أسماء الواجهات التي تتوافق مع المواقع الجغرافية ستكون كافية، مثل `cincinnati', `nyc', أو `paris'، إذا كان ذلك مرغوبًا فيه بطريقة ما.

أمثلة

تستمد هذه الأمثلة من نفس بناء الجملة الموجود في wg(8)، ويمكن العثور على وصف أكثر اكتمالاً هناك. الخطوط العريضة أدناه مخصصة للخيارات التي توسع wg(8).

قد يتم استخدام ما يلي للاتصال كعميل ببوابة VPN لتوجيه جميع حركة المرور:


[Interface]
Address = 10.200.100.8/24
DNS = 10.200.100.1
PrivateKey = oK56DE9Ue9zK76rAc8pBl6opph+1v36lm7cXXsQKrQM=


[Peer]
PublicKey = GtL7fZc/bLnqZldpVofMCD6hDjrK28SsdLxevJ+qtKU=
PresharedKey = /UwcSPg38hW/D9Y3tcS1FOV0K1wuURMbS0sesJEP5ak=
AllowedIPs = 0.0.0.0/0
Endpoint = demo.wireguard.com:51820

تمت إضافة حقل `Address` هنا لتعيين عنوان الواجهة. يشير حقل `DNS` إلى أنه يجب تكوين خادم DNS للواجهة عبر resolvconf(8). يشير إدخال عناوين IP المسموح بها للند إلى أنه يجب تكوين هذه الواجهة كبوابة افتراضية، وهو ما تفعله هذه الأداة.

بناءً على المثال الأخير، قد يحاول المرء ما يسمى بـ "مفتاح القتل" (kill-switch)، لمنع تدفق الحزم غير المشفرة عبر الواجهات غير WireGuard، عن طريق إضافة السطرين التاليين `PostUp` و `PreDown` إلى قسم `[Interface]`:


PostUp = iptables -I OUTPUT ! -o %i -m mark ! --mark $(wg show %i fwmark) -m addrtype ! --dst-type LOCAL -j REJECT
PreDown = iptables -D OUTPUT ! -o %i -m mark ! --mark $(wg show %i fwmark) -m addrtype ! --dst-type LOCAL -j REJECT

تمت إضافة حقلي `PostUp` و `PreDown` لتحديد أمر iptables(8) الذي، عند استخدامه مع الواجهات التي لديها ند يحدد 0.0.0.0/0 كجزء من `AllowedIPs`، يعمل مع استخدام `fwmark` الخاص بـ wg-quick لإسقاط جميع الحزم التي لا تخرج من النفق مشفرة أو لا تمر عبر النفق نفسه. (لاحظ أن هذا لا يزال يسمح بمعظم حركة مرور DHCP، حيث تستخدم معظم عملاء DHCP مقابس `PF_PACKET`، والتي تتجاوز Netfilter.) عند استخدام IPv6، يمكن إضافة سطور مماثلة إضافية باستخدام ip6tables(8).

أو، ربما يكون من المرغوب فيه تخزين المفاتيح الخاصة في شكل مشفر، مثل استخدام pass(1):


PreUp = wg set %i private-key <(pass WireGuard/private-keys/%i)

للاستخدام على خادم، المثال التالي أكثر تعقيدًا ويتضمن أقرانًا متعددين:


[Interface]
Address = 10.192.122.1/24
Address = 10.10.0.1/16
SaveConfig = true
PrivateKey = yAnz5TF+lXXJte14tji3zlMNq+hd2rYUIgJBgB3fBmk=
ListenPort = 51820


[Peer]
PublicKey = xTIBA5rboUvnH4htodjb6e697QjLERt1NAB4mZqp8Dg=
AllowedIPs = 10.192.122.3/32, 10.192.124.1/24


[Peer]
PublicKey = TrMvSoP4jYQlY6RIzBgbssQqY3vxI2Pi+y71lOWWXX0=
AllowedIPs = 10.192.122.4/32, 192.168.0.0/16


[Peer]
PublicKey = gN65BkIKy1eCE9pP1wdc8ROUtkHLF2PfAqYdyYBz6EA=
AllowedIPs = 10.10.10.230/32

لاحظ سطري `Address` في الأعلى، وأن `SaveConfig` تم تعيينه على `true`، مما يشير إلى أنه يجب حفظ ملف التكوين عند الإغلاق باستخدام الحالة الحالية للواجهة.

يمكن استخدام مزيج من حقول `Table` و `PostUp` و `PreDown` للتوجيه بالسياسات أيضًا. على سبيل المثال، يمكن استخدام ما يلي لإرسال حركة مرور SSH (المنفذ 22 TCP) عبر النفق:
