الاسم

WMShell — فئة أداة WMShell

الملخص

#include <Xm/Xm.h>
#include <X11/Shell.h>

الوصف

WMShell هي أداة من المستوى الأعلى تغلف التفاعل مع مدير النوافذ.

الفئات

WMShell ترث السلوك والموارد من فئات Core و Composite و Shell.

مؤشر الفئة هو wmShellWidgetClass.

اسم الفئة هو WMShell.

موارد جديدة

يحدد الجدول التالي مجموعة من موارد الأدوات التي يستخدمها المبرمج لتحديد البيانات. يمكن للمبرمج أيضًا تعيين قيم الموارد للفئات الموروثة لتعيين سمات لهذه الأداة. للإشارة إلى مورد بالاسم أو الفئة في ملف .Xdefaults، قم بإزالة البادئة XmN أو XmC واستخدم الأحرف المتبقية. لتحديد أحد القيم المعرفة لمورد في ملف .Xdefaults، قم بإزالة البادئة Xm واستخدم الأحرف المتبقية (إما بأحرف صغيرة أو كبيرة، ولكن قم بتضمين أي شرطات سفلية بين الكلمات). تشير الرموز في عمود الوصول إلى ما إذا كان يمكن تعيين المورد المحدد في وقت الإنشاء (C) أو تعيينه باستخدام XtSetValues (S) أو استرجاعه باستخدام XtGetValues (G) أو غير قابل للتطبيق (N/A).

إذا لم يتم تحديد قيمة أولية، يتم تعيين القيمة إلى نافذة أداة السلف المهيأة الأولى في التسلسل الهرمي للوالدين عند تهيئة الأداة. إذا تم تحديد قيمة XtUnspecifiedWindowGroup، فلن يتم تعيين أي مجموعة نوافذ.
XmNwinGravity
يحدد جاذبية النافذة لاستخدامها من قبل مدير النوافذ في وضع الأداة. إذا لم يتم تحديد قيمة أولية، يتم تعيين القيمة عند تهيئة الأداة. إذا كان XmNgeometry ليس NULL، يتم تعيين XmNwinGravity إلى جاذبية النافذة التي تم إرجاعها بواسطة XWMGeometry. بخلاف ذلك، يتم تعيين XmNwinGravity إلى NorthWestGravity.
XmNwmTimeout
يحدد المدة الزمنية التي ينتظرها Intrinsics حتى يستجيب مدير النوافذ لأفعال معينة قبل الافتراض بعدم وجود مدير نوافذ. القيمة بالمللي ثانية ويجب ألا تكون سالبة.

NAME

WMShell - WidgetShell widget

SYNOPSIS

#include <Xm/WMShell.h>

DESCRIPTION

WMShell is a subclass of Object. It is used to associate a widget with a top-level window. The widget acts as a shell for the rest of the widget hierarchy.

The WMShell widget is a subclass of the VendorShell widget. It provides support for managing the window manager's interaction with the application's top-level window.

The WMShell widget is typically created implicitly by the Motif toolkit when an application creates a top-level widget such as XmMainWindow or XmDialogShell.

CALLBACKS

The WMShell widget does not define any callbacks of its own. However, it inherits callbacks from its superclasses and may be involved in callback processing related to window manager interactions.

WIDGETS

The WMShell widget itself is not directly created by applications. Instead, application-specific shells like ApplicationShell, TopLevelShell, DialogShell, and MenuShell are subclasses of WMShell (or indirectly through VendorShell).

RESOURCES

WMShell inherits resources from Core, Composite, Shell, and VendorShell. It does not introduce any new resources.

EXAMPLE

This widget is usually created implicitly. For example: 

#include <Xm/Xm.h>

    Widget toplevel;
    Widget label;

    toplevel = XtInitialize(argv[0], "HelloWorld", NULL, 0, &argc, argv);

    /* This implicitly creates a WMShell or a subclass */
    toplevel = XtCreateApplicationShell("app", topLevelShellWidgetClass, toplevel, NULL, 0);

    label = XmCreateLabel(toplevel, "hello", NULL, 0);
    XtManageChild(label);

    XtRealizeWidget(toplevel);
    XtMainLoop();

VIRTUAL KEYBOARDS

See XmKeysym(3) for more information on virtual key translation.

Translations

There are no translations for WMShell.
