WWW::Mechanize(3) وثائق Perl مساهمة من المستخدم WWW::Mechanize(3)

الاسم

WWW::Mechanize - تصفح ويب مفيد في كائن Perl

الإصدار

الإصدار 2.20

الملخص

يدعم WWW::Mechanize إجراء سلسلة من جلب الصفحات بما في ذلك متابعة الروابط وتقديم النماذج. يتم تحليل كل صفحة تم جلبها واستخراج الروابط والنماذج الخاصة بها. يمكن تحديد رابط أو نموذج، ويمكن ملء حقول النموذج وجلب الصفحة التالية. يحتفظ Mech أيضًا بسجل لعناوين URL التي قمت بزيارتها، والتي يمكن الاستعلام عنها وإعادة زيارتها.

use WWW::Mechanize ();
my $mech = WWW::Mechanize->new();
$mech->get( $url );
$mech->follow_link( n => 3 );
$mech->follow_link( text_regex => qr/download this/i );
$mech->follow_link( url => 'http://host.com/index.html' );
$mech->submit_form(
    form_number => 3,
    fields      => {
        username    => 'mungo',
        password    => 'lost-and-alone',
    }
);
$mech->submit_form(
    form_name => 'search',
    fields    => { query  => 'pot of gold', },
    button    => 'Search Now'
);
# تمكين معالجة النماذج الصارمة للكشف عن الأخطاء الإملائية وحقول النماذج غير الموجودة.
my $strict_mech = WWW::Mechanize->new( strict_forms => 1);
$strict_mech->get( $url );
# ستؤدي استدعاء هذه الطريقة إلى الانهيار، مما يوفر لك الكثير من الوقت في البحث عن الخطأ.
$strict_mech->submit_form(
    form_number => 3,
    fields      => {
        usernaem     => 'mungo',           # خطأ إملائي في اسم الحقل
        password     => 'lost-and-alone',
        extra_field  => 123,               # الحقل غير موجود
    }
);

الوصف

"WWW::Mechanize"، أو Mech اختصارًا، هي وحدة Perl للتصفح الآلي للويب ذي الحالة، تُستخدم لأتمتة التفاعل مع مواقع الويب.

تشمل الميزات:

  • جميع طرق HTTP
  • دعم عالي المستوى للروابط التشعبية ونماذج HTML، دون الحاجة إلى تحليل HTML بنفسك
  • دعم SSL
  • ملفات تعريف الارتباط التلقائية
  • رؤوس HTTP المخصصة
  • معالجة تلقائية لإعادة التوجيه
  • الوكلاء
  • المصادقة HTTP

Mech مناسب تمامًا للاستخدام في اختبار تطبيقات الويب. إذا كنت تستخدم أحد وحدات Test::*، مثل Test::HTML::Lint، يمكنك التحقق من المحتوى الذي تم جلبه واستخدامه كمدخل لاستدعاء اختبار.

use Test::More;
like( $mech->content(), qr/$expected/, "Got expected content" );

كل جلب للصفحة يخزن عنوان URL الخاص به في مكدس سجل يمكنك التنقل فيه.

$mech->back();

إذا كنت ترغب في تحكم أدق في جلب صفحاتك، يمكنك استخدام هذه الطرق. follow_link() و submit_form() هي مجرد أغلفة عالية المستوى حولها.

$mech->find_link( n => $number );
$mech->form_number( $number );
$mech->form_name( $name );
$mech->field( $name, $value );
$mech->set_fields( %field_values );
$mech->set_visible( @criteria );
$mech->click( $button );

WWW::Mechanize هي فئة فرعية مناسبة لـ LWP::UserAgent، ويمكنك أيضًا استخدام أي من طرق LWP::UserAgent.

$mech->add_header($name => $value);

يرجى ملاحظة أن Mech لا تدعم JavaScript، وتحتاج إلى برامج إضافية لذلك. يرجى التحقق من "JavaScript" في WWW::Mechanize::FAQ لمزيد من المعلومات.

cpan install WWW::Mechanize
# أو
cpanm WWW::Mechanize

المُنشئ وبدء التشغيل

new()

ينشئ ويعيد كائن WWW::Mechanize جديدًا، يشار إليه فيما بعد باسم "الوكيل".

my $mech = WWW::Mechanize->new()

يتجاوز مُنشئ WWW::Mechanize معامِليْن من مُنشئ LWP::UserAgent:

agent => 'WWW-Mechanize/#.##'
cookie_jar => {}    # كائن HTTP::Cookies فارغ، يعمل بالذاكرة فقط

يمكنك تجاوز هذه التجاوزات عن طريق تمرير معامِلات إلى المُنشئ، كما في:

my $mech = WWW::Mechanize->new( agent => 'wonderbot 1.01' );

إذا كنت لا ترغب في أي عبء إضافي لملفات تعريف الارتباط، أو لا تريد أن يقبل الروبوت الخاص بك ملفات تعريف الارتباط، فيجب عليك تعطيله صراحةً، على النحو التالي:

my $mech = WWW::Mechanize->new( cookie_jar => undef );

إليك المعامِلات التي يتعرف عليها WWW::Mechanize. لا تتضمن هذه المعامِلات التي يتعرف عليها LWP::UserAgent.

  • "autocheck => [0|1]"

    يتحقق من كل طلب تم تقديمه لمعرفة ما إذا كان ناجحًا. هذا يوفر عليك عناء التحقق يدويًا. أي أخطاء يتم العثور عليها هي أخطاء، وليست تحذيرات.

    القيمة الافتراضية قيد التشغيل، ما لم يتم استخدام فئة فرعية، وفي هذه الحالة تكون قيد الإيقاف. هذا يعني أن مثيلات WWW::Mechanize المستقلة بها autocheck قيد التشغيل، وهو أمر وقائي لغالبية مستخدمي Mech الذين لا يكلفون أنفسهم عناء التحقق من القيمة المرجعة لـ get() و post() ولا يمكنهم فهم سبب فشل رمزهم. ومع ذلك، إذا تم استخدام فئة فرعية لـ WWW::Mechanize، مثل Test::WWW::Mechanize أو Test::WWW::Mechanize::Catalyst، فقد لا يكون هذا افتراضيًا مناسبًا، لذلك فهو متوقف.

  • "noproxy => [0|1]"

    إيقاف الاستدعاء التلقائي لوظيفة LWP::UserAgent "env_proxy".

    يجب إيقاف تشغيل هذا صراحةً إذا كنت تستخدم Crypt::SSLeay للوصول إلى موقع https عبر خادم وكيل. ملاحظة: لا يزال يتعين عليك تعيين متغير البيئة HTTPS_PROXY الخاص بك حسب الاقتضاء.

  • "onwarn => \&func"

    مرجع لدالة متوافقة مع "warn"، مثل "Carp::carp"، والتي يتم استدعاؤها عند الحاجة إلى عرض تحذير.

    إذا تم تعيين هذا على "undef"، فلن يتم عرض أي تحذيرات. ومع ذلك، من الأفضل ربما استخدام طريقة "quiet" للتحكم في هذا السلوك.

    إذا لم يتم تمرير هذه القيمة، يستخدم Mech "Carp::carp" إذا تم تثبيت Carp، أو "CORE::warn" إذا لم يكن كذلك.

  • "onerror => \&func"

    مرجع لدالة متوافقة مع "die"، مثل "Carp::croak"، والتي يتم استدعاؤها عند حدوث خطأ قاتل.

    إذا تم تعيين هذا على "undef"، فلن يتم عرض أي أخطاء.

    إذا لم يتم تمرير هذه القيمة، يستخدم Mech "Carp::croak" إذا تم تثبيت Carp، أو "CORE::die" إذا لم يكن كذلك.

  • "quiet => [0|1]"

    لا تشتكي عند التحذيرات. تعيين "quiet => 1" هو نفس استدعاء "$mech->quiet(1)". الافتراضي هو الإيقاف.

  • &qu
t;b>current_form()</b>'>$mech->current_form()

يعيد النموذج الحالي ككائن HTML::Form.

$mech->links()

عند استدعائه في سياق قائمة، يعيد قائمة بالروابط الموجودة في الصفحة التي تم جلبها مؤخرًا. في سياق قياسي، يعيد مرجعًا إلى مصفوفة تحتوي على تلك الروابط. كل رابط هو كائن WWW::Mechanize::Link.

$mech->is_html()

يعيد صحيح/خطأ حول ما إذا كان المحتوى لدينا هو HTML، وفقًا لرؤوس HTTP.

$mech->title()

يعيد محتويات علامة "<TITLE>"، كما تم تحليلها بواسطة HTML::HeadParser. يعيد "undef" إذا لم يكن المحتوى HTML.

$mech->redirects()

طريقة ملائمة للحصول على عمليات إعادة التوجيه من استجابة HTTP الأخيرة.

لاحظ أنه يمكنك أيضًا استخدام is_redirect لمعرفة ما إذا كانت الاستجابة الأخيرة عملية إعادة توجيه مثل هذه.

$mech->get($url);
do_stuff() if $mech->res->is_redirect;

طرق التعامل مع المحتوى

$mech->content(...)

يعيد المحتوى الذي يستخدمه الميكانيكي داخليًا للصفحة الأخيرة التي تم جلبها. عادةً ما يكون هذا هو نفسه "$mech->response()->decoded_content()"، ولكن قد يختلف هذا بالنسبة لمستندات HTML إذا تم تجاوز "update_html" (وفي هذه الحالة سيتم إرجاع القيمة التي تم تمريرها إلى تنفيذ الفئة الأساسية لنفسها)، و/أو تم تمرير وسائط مسماة إضافية إلى content():

$mech->content( format => 'text' )
يعيد نسخة نصية فقط من الصفحة، مع إزالة جميع علامات HTML. تتطلب هذه الميزة تثبيت HTML::TreeBuilder الإصدار 5 أو أعلى، وإلا سيتم إطلاق خطأ فادح. يعمل هذا فقط إذا كان المحتوى HTML.
$mech->content( base_href => [$base_href|undef] )
يعيد مستند HTML، معدلًا ليحتوي على علامة "<base href="$base_href">" في الرأس. $base_href هو "$mech->base()" إذا لم يتم تحديده. هذا مفيد لتمرير HTML إلى HTML::Display على سبيل المثال. يعمل هذا فقط إذا كان المحتوى HTML.
$mech->content( raw => 1 )
يعيد "$self->response()->content()"، أي المحتوى الخام من الاستجابة.
$mech->content( decoded_by_headers => 1 )
يعيد المحتوى بعد تطبيق جميع رؤوس "Content-Encoding" ولكن بدون أي معالجة إضافية.
$mech->content( charset => $charset )
يعيد "$self->response()->decoded_content(charset => $charset)" (راجع HTTP::Response للحصول على التفاصيل).

للحفاظ على التوافق الرجعي، سيتم تجاهل المعلمات الإضافية ما لم يتم تحديد أي من "raw | decoded_by_headers | charset" وكان النص HTML، وفي هذه الحالة سيتم إنشاء خطأ.

ستعيد مثيل WWW::Mechanize جديد "undef" عند استدعاء "$mech->content()"، لأنه لا يوجد محتوى قبل إجراء طلب.

$mech->text()

يعيد نص المحتوى HTML الحالي. إذا لم يكن المحتوى HTML، فسيموت $mech.

يتم استخراج النص عن طريق تحليل المحتوى، ثم يتم تخزين النص المستخرج في الذاكرة المؤقتة، لذا لا تقلق بشأن أداء استدعاء هذا بشكل متكرر.

طرق الروابط

$mech->links()

يسرد جميع الروابط في الصفحة الحالية. كل رابط هو كائن WWW::Mechanize::Link. في سياق قائمة، يعيد قائمة بجميع الروابط. في سياق قياسي، يعيد مرجع مصفوفة بجميع الروابط.

$mech->follow_link(...)

يتبع رابطًا محددًا في الصفحة. تحدد المطابقة التي سيتم العثور عليها باستخدام نفس المعلمات التي تستخدمها find_link().

إليك بعض الأمثلة:

  • الرابط الثالث المسمى "download" 
    $mech->follow_link( text => 'download', n => 3 );
  • الرابط الأول حيث يحتوي عنوان URL على "download" بغض النظر عن الحالة: 
    $mech->follow_link( url_regex => qr/download/i );

    أو

    $mech->follow_link( url_regex => qr/(?i:download)/ );
  • الرابط الثالث في الصفحة 
    $mech->follow_link( n => 3 );
  • الرابط الذي يحمل عنوان URL 
    $mech->follow_link( url => '/other/page' );

    أو

    $mech->follow_link( url => 'http://example.com/page' );

يعيد نتيجة طريقة "GET" (كائن HTTP::Response) إذا تم العثور على رابط.

إذا لم يكن للصفحة روابط، أو لم يتم العثور على الرابط المحدد، فإنه يعيد "undef". إذا تم تمكين "autocheck"، فسيتم إطلاق استثناء بدلاً من ذلك.

$mech->find_link( ... )

يبحث عن رابط في الصفحة التي تم جلبها حاليًا. يعيد كائن WWW::Mechanize::Link يصف الرابط. (من المحتمل أن تكون أكثر اهتمامًا بالخاصية url().) إذا فشل في العثور على رابط، فإنه يعيد "undef".

يمكنك أخذ جزء عنوان URL وتمريره إلى طريقة get(). إذا كانت هذه هي خطتك، يمكنك استخدام طريقة follow_link() مباشرة، لأنها تقوم بإجراء get() لك تلقائيًا.

لاحظ أنه يتم تحليل علامات "<FRAME SRC="...">" من HTML ومعاملتها كروابط، لذا تعمل هذه الطريقة معها.

يمكنك تحديد الرابط الذي سيتم العثور عليه عن طريق تمرير واحد أو أكثر من أزواج المفتاح/القيمة هذه:

  • "text => 'string'," و "text_regex => qr/regex/,"

    "text" تطابق نص الرابط مع string، والذي يجب أن يكون مطابقًا تمامًا. لتحديد رابط بنص هو بالضبط "download"، استخدم

    $mech->find_link( text => 'download' );

    "text_regex" تطابق نص الرابط مع regex. لتحديد رابط بنص يحتوي على "download" في أي مكان، بغض النظر عن الحالة، استخدم

    $mech->find_link( text_regex => qr/download/i );

    لاحظ أن النص المستخرج من روابط الصفحة يتم اقتطاعه. على سبيل المثال، "<a> foo </a>" يتم تخزينه كـ 'foo'، والبحث عن مسافات بادئة أو زائدة سيفشل.

  • "url => 'string'," و "url_regex => qr/regex/,"

    يطابق عنوان URL للرابط مع string أو regex، حسب الاقتضاء. يمكن أن يكون عنوان URL عنوان URL نسبيًا، مثل foo/bar.html، اعتمادًا على كيفية ترميزه في الصفحة.

  • "url_abs => string" و "url_abs_regex => regex"

    يطابق عنوان URL المطلق للرابط مع string أو regex، حسب الاقتضاء. سيكون عنوان URL عنوان URL مطلقًا، حتى لو كان نسبيًا في الصفحة.

  • "name => string" و "name_regex => regex"

    يطابق اسم الرابط مع string أو regex، حسب الاقتضاء.

  • "rel => string" و "rel_regex => regex"

    يطابق rel الخاص بالرابط مع string أو regex، حسب الاقتضاء. يمكن استخدام هذا للعثور على أوراق الأنماط، أو أيقونات المفضلة، أو الروابط التي لا يرغب مؤلف الصفحة في تتبعها بواسطة الروبوتات.

  • "id => string" و "id_regex => regex"

    يطابق السمة 'id' الخاصة بالرابط مع string أو regex، حسب الاقتضاء.

  • "class => string" و "class_regex => regex"

    يطابق السمة 'class' الخاصة بالرابط مع string أو regex، حسب الاقتضاء.

  • "tag => string" و "tag_regex => regex"

    يطابق العلامة التي جاء منها الرابط مع string أو regex، حسب الاقتضاء. من المحتمل أن تكون "tag_regex" هي الأكثر فائدة للتحقق من أكثر من علامة واحدة، كما في:

    $mech->find_link( tag_regex => qr/^(a|frame)$/ );

    يتم تعريف العلامات والسمات التي يتم النظر فيها أدناه.

إذا لم يتم تحديد "n"، فستكون قيمتها الافتراضية 1. لذلك، إذا لم تحدد أي معلمات، فإن هذه الطريقة ستكون افتراضية للعثور على الرابط الأول في الصفحة.

لاحظ أنه يمكنك تحديد معلمات نص أو عنوان URL متعددة، والتي سيتم دمجها باستخدام AND. على سبيل المثال، للعثور على الرابط الأول بالنص "News" ويحتوي على "cnn.com" gt;add_header( Referer => undef );

إذا كنت تريد حذف رأس، استخدم "delete_header".

تُرجع عدد أزواج الاسم/القيمة التي تمت إضافتها.

ملاحظة: كانت هذه الطريقة مختلفة جدًا في WWW::Mechanize قبل 1.00. في ذلك الوقت، كانت الرؤوس مخزنة في هاش الحزمة، وليس كعضو في مثيل الكائن. كان استدعاء add_header() سيؤدي إلى تعديل الرؤوس لكل مثيل WWW::Mechanize، حتى بعد زوال الكائن الخاص بك.

$mech->delete_header( name [, name ... ] )

يزيل رؤوس HTTP من قائمة الوكيل الخاصة بالرؤوس الخاصة. على سبيل المثال، قد تحتاج إلى القيام بشيء مثل:

# لا ترسل مرجع لهذا العنوان
$mech->add_header( Referer => undef );
# احصل على العنوان
$mech->get( $url );
# العودة إلى السلوك الافتراضي
$mech->delete_header( 'Referer' );

$mech->quiet(true/false)

يسمح لك بكتم التحذيرات إلى الشاشة.

$mech->quiet(0); # تشغيل التحذيرات (الافتراضي)
$mech->quiet(1); # إيقاف التحذيرات
$mech->quiet();  # إرجاع حالة الكتم الحالية

$mech->autocheck(true/false)

يسمح لك بتمكين وتعطيل الفحص التلقائي.

يقوم الفحص التلقائي بفحص كل طلب يتم إجراؤه لمعرفة ما إذا كان ناجحًا. هذا يوفر عليك عناء التحقق يدويًا. أي أخطاء يتم العثور عليها هي أخطاء، وليست تحذيرات. يرجى الرجوع إلى "new" لمزيد من التفاصيل.

$mech->autocheck(1); # تشغيل الفحص التلقائي للطلبات (الافتراضي)
$mech->autocheck(0); # إيقاف الفحص التلقائي للطلبات
$mech->autocheck();  # إرجاع حالة الفحص التلقائي الحالية

$mech->stack_depth( $max_depth )

الحصول على أو تعيين عمق مكدس الصفحات. استخدم هذا إذا كنت تقوم بالكثير من كشط الصفحات وتنفد الذاكرة.

قيمة 0 تعني "لا يوجد سجل على الإطلاق". بشكل افتراضي، يكون أقصى عمق للمكدس كبيرًا جدًا، مما يحتفظ بكل السجل تقريبًا.

$mech->save_content( $filename, %opts )

يفرغ محتويات "$mech->content" إلى $filename. سيتم الكتابة فوق $filename. يُنهي إذا كانت هناك أي أخطاء.

إذا كان نوع المحتوى لا يبدأ بـ "text/"، فسيتم حفظ المحتوى في وضع ثنائي (أي يتم تعيين binmode() على مقبض ملف الإخراج).

يمكن تمرير وسائط إضافية كأزواج مفتاح/قيمة:

$mech->save_content( $filename, binary => 1
يتم تعيين مقبض الملف باستخدام "binmode" إلى ":raw" ويتم أخذ المحتويات عن طريق استدعاء "$self->content(decoded_by_headers => 1)". نفس استدعاء: 
$mech->save_content( $filename, binmode => ':raw',
                     decoded_by_headers => 1 );

يجب أن تكون هذه هي الطريقة الأكثر أمانًا لحفظ المحتويات حرفيًا.

$mech->save_content( $filename, binmode => $binmode )
يتم تعيين مقبض الملف إلى وضع ثنائي. إذا بدأ $binmode بـ ':'، فسيتم تمريره كمعامل إلى "binmode": 
binmode $fh, $binmode;

وإلا يتم تعيين مقبض الملف إلى وضع ثنائي إذا كان $binmode صحيحًا:

binmode $fh;
جميع الوسائط الأخرى
يتم تمريرها كما هي إلى "$mech->content(%opts)". على وجه الخصوص، قد يكون "decoded_by_headers" مفيدًا إذا كنت ترغب في التراجع عن تأثير ضغط الأسطر الذي يقوم به خادم الويب ولكن دون مزيد من تفسير المحتويات (على سبيل المثال، فك تشفيرها وفقًا لمجموعة الأحرف).

$mech->dump_headers( [$fh] )

يطبع تفريغًا لرؤوس استجابة HTTP للاستجابة الأخيرة. إذا لم يتم تحديد $fh أو كان "undef"، فإنه يفرغ إلى STDOUT.

بخلاف بقية طرق "dump_*"، يمكن أن يكون $fh قيمة قياسية. سيتم استخدامه كاسم ملف.

$mech->dump_links( [[$fh], $absolute] )

يطبع تفريغًا للروابط الموجودة في الصفحة الحالية إلى $fh. إذا لم يتم تحديد $fh أو كان "undef"، فإنه يفرغ إلى STDOUT.

إذا كان $absolute صحيحًا، فإن الروابط المعروضة تكون مطلقة، وليست نسبية.

$mech->dump_images( [[$fh], $absolute] )

يطبع تفريغًا للصور الموجودة في الصفحة الحالية إلى $fh. إذا لم يتم تحديد $fh أو كان "undef"، فإنه يفرغ إلى STDOUT.

إذا كان $absolute صحيحًا، فإن الروابط المعروضة تكون مطلقة، وليست نسبية.

سيشمل الإخراج سطورًا فارغة للصور التي لا تحتوي على سمة "src" وبالتالي لا يوجد لها عنوان URL.

$mech->dump_forms( [$fh] )

يطبع تفريغًا للنماذج الموجودة في الصفحة الحالية إلى $fh. إذا لم يتم تحديد $fh أو كان "undef"، فإنه يفرغ إلى STDOUT. تشغيل ما يلي:

my $mech = WWW::Mechanize->new();
$mech->get("https://www.google.com/");
$mech->dump_forms;

GET https://www.google.com/search [f]

  hl=en                          (hidden readonly)
  source=hp                      (hidden readonly)
  biw=                           (hidden readonly)
  bih=                           (hidden readonly)
  q=                             (text)
  btnG=Google Search             (submit)
  btnI=I'm Feeling Lucky         (submit)
  gbv=1                          (hidden readonly)

$mech->dump_text( [$fh] )

يطبع تفريغًا للنص الموجود في الصفحة الحالية إلى $fh. إذا لم يتم تحديد $fh أو كان "undef"، فإنه يفرغ إلى STDOUT.

طرق LWP::UserAgent معدلة

$mech->clone()

نسخ كائن mech. ستستخدم النسخة نفس مخزن ملفات تعريف الارتباط مثل mech الأصلي.

$mech->redirect_ok()

نسخة overloaded من redirect_ok() في LWP::UserAgent. تُستخدم هذه الطريقة لتحديد ما إذا كان يجب متابعة إعادة التوجيه في الطلب.

لاحظ أن مُنشئ WWW::Mechanize يضيف POST إلى قائمة "requests_redirectable" للوكيل.

$mech->request( $request [, $arg [, $size]])

نسخة overloaded من request() في LWP::UserAgent. يقوم بإجراء الطلب الفعلي. عادةً، إذا كنت تستخدم WWW::Mechanize، فذلك لأنك لا تريد التعامل مع هذا المستوى من الأشياء على أي حال.

لاحظ أنه سيتم تعديل $request.

يُرجع كائن HTTP::Response.

$mech->update_html( $html )

يسمح لك باستبدال HTML الذي عثر عليه mech. يقوم بتحديث شجري التحليل للنماذج والروابط التي يستخدمها mech داخليًا.

لنفترض أن لديك صفحة تعرف أنها تحتوي على إخراج غير صحيح، وتريد تحديثها بحيث تظهر الروابط بشكل صحيح:

my $html = $mech->content;
$html =~ s[</option>.{0,3}</td>][</option></select></td>]isg;
$mech->update_html( $html );

يتم استخدام هذه الطريقة أيضًا داخليًا بواسطة mech نفسه لتحديث محتوى HTML الخاص به عند تحميل صفحة. هذا يعني أنه إذا كنت ترغب في إجراء استبدال HTML الذي تم إجراؤه أعلاه بشكل منهجي، فسوف تقوم بتجاوز "update_html" في فئة فرعية على النحو التالي:

package MyMech;
use parent 'WWW::Mechanize';
sub update_html {
    my ($self, $html) = @_;
    $html =~ s[</option>.{0,3}</td>][</option></select></td>]isg;
    $self->WWW::Mechanize::update_html( $html );
}

إذا قمت بذلك، فسيستخدم mech HTML المنظم بدلاً من الأصلي سواء عند تحليله لاحتياجاته الخاصة، أو لإعادته إليك عبر content().

يُعد تجاوز هذه الطريقة أيضًا الطريقة الموصى بها لتنفيذ خطوات تحقق إضافية (على سبيل المثال، مدققات الروابط) لكل صفحة HTML مستلمة. ستكون "warn" و "warn" مفيدة عندئذٍ للإشارة إلى أخطاء التحقق.

$mech->credentials( $username, $password )

قدم بيانات اعتماد لاستخدامها للمصادقة الأساسية HTTP لجميع المواقع والنطاقات حتى إشعار آخر.

لا يزال النموذج ذو الأربعة وسائط الموصوف في LWP::UserAgent مدعومًا.

$mech->get_basic_credentials( $realm, $uri, $isproxy )

يُرجع بيانات الاعتماد للنطاق و URI.

$mech->clear_credentials()

قم بإزالة أي بيانات اعتماد تم إعدادها باستخدام credentials().

طرق داخلية فقط

هذه الطرق تستخدم داخليًا فقط. لا تحتاج على الأرجح لمعرفة عنها.

$mech->_update_page($request, $response)

تقوم بتحديث جميع المتغيرات الداخلية في $mech كما لو تم إجراء $request للتو، وتعيد $response. لا يتم تعديل مكدس الصفحات بواسطة هذه الطريقة، ويعود الأمر للمستدعي (مثل "request") للقيام بذلك.

تعديل طلب HTTP::Request قبل إرسال الطلب، لكل من طلبات GET و POST.

نضيف ترويسة "Referer"، بالإضافة إلى ترويسة للإشارة إلى أننا يمكننا قبول محتوى مشفر gzip، إذا تم تثبيت Compress::Zlib.

$mech->_make_request()

طريقة مريحة لتسهيل اعتراض الطلب من قبل الفئات الفرعية مثل WWW::Mechanize::Cached.

$mech->_reset_page()

تعيد تعيين الحقول الداخلية التي تتعقب العناصر المحللة للصفحة.

$mech->_extract_links()

تستخرج الروابط من محتوى صفحة الويب، وتملأ الخاصية "{links}" بكائنات WWW::Mechanize::Link.

$mech->_push_page_stack()

يحتفظ الوكيل بمكدس من الصفحات التي تمت زيارتها، والتي يمكن أن يخرج منها عند الحاجة للعودة للخلف وما إلى ذلك.

تحتاج الصفحة الحالية إلى دفعها إلى المكدس قبل الحصول على صفحة جديدة، ويجب إخراج المكدس عند حدوث العودة للخلف.

لا يأخذ أي من هذه عمليات أي وسيطات، بل تعمل فقط على الكائن $mech.

تحذير( @messages )

طريقة تحذير مركزية، للتشخيص والمشاكل غير الخطيرة. افتراضيًا، تقوم بالاستدعاء "CORE::warn"، ولكن يمكن تجاوزها عن طريق تعيين "onwarn" في المنشئ.

موت( @messages )

طريقة خطأ مركزية. افتراضيًا، تقوم بالاستدعاء "CORE::die"، ولكن يمكن تجاوزها عن طريق تعيين "onerror" في المنشئ.

أفضل الممارسات

الإعدادات الافتراضية يمكن أن تجعلك تبدأ بسرعة، ولكن هناك إعدادات يمكنك تغييرها لجعل حياتك أسهل.

autocheck
"autocheck" يمكن أن يوفر عليك عبء التحقق من رموز الحالة للنجاح. قد تتجاوزها عندما تصبح احتياجاتك أكثر تطورًا، ولكنها خيار آمن للبدء به. 
my $agent = WWW::Mechanize->new( autocheck => 1 );
cookie_jar
يشجعك على تثبيت Mozilla::PublicSuffix واستخدام HTTP::CookieJar::LWP كـ cookie jar الخاص بك. يوفر HTTP::CookieJar::LWP نموذج أمان أفضل يطابق متصفحات الويب الحالية عند تثبيت Mozilla::PublicSuffix. 
use HTTP::CookieJar::LWP ();
my $jar = HTTP::CookieJar::LWP->new;
my $agent = WWW::Mechanize->new( cookie_jar => $jar );
protocols_allowed
تم وراثة هذا الخيار مباشرة من LWP::UserAgent. يمكن استخدامه للسماح ببروتوكولات عشوائية. 
my $agent = WWW::Mechanize->new(
    protocols_allowed => [ 'http', 'https' ]
);

سيمنع هذا من متابعة الروابط مثل "file:///etc/passwd" عن طريق الخطأ.

protocols_forbidden
هذا الخيار موروث أيضًا مباشرة من LWP::UserAgent. يمكن استخدامه لمنع بروتوكولات عشوائية. 
my $agent = WWW::Mechanize->new(
    protocols_forbidden => [ 'file', 'mailto', 'ssh', ]
);

سيمنع هذا من متابعة الروابط مثل "file:///etc/passwd" عن طريق الخطأ.

strict_forms
فكر في تشغيل الخيار "strict_forms" عند إنشاء Mech جديد. سيقوم هذا بإجراء فحص صحي مفيد لحقول النماذج في كل مرة تقوم فيها بإرسال نموذج، مما قد يوفر عليك الكثير من وقت التصحيح. 
my $agent = WWW::Mechanize->new( strict_forms => 1 );

إذا كنت لا تريد هذا الخيار بشكل عام، يمكنك تشغيله لنماذج فردية أيضًا.

$agent->submit_form( fields => { foo => 'bar' } , strict_forms => 1 );

NAME

WWW::Mechanize::Shell - A WWW::Mechanize interface for the command line.

VERSION

This document describes WWW::Mechanize::Shell version 0.59.

SYNOPSIS

The WWW::Mechanize::Shell is not intended to be used directly. It is designed to be run as a command-line application.

The WWW::Mechanize::Shell is part of the WWW::Mechanize distribution.

    $ perl -MWWW::Mechanize::Shell -e shell

DESCRIPTION

The WWW::Mechanize::Shell is a command-line interface to WWW::Mechanize. It allows you to interact with web pages from the command line, rather than writing a script. It's useful for quick checks, simple form submissions, and for exploring websites.

The shell provides a command history, tab completion (if available), and a simple command set that mirrors many of the methods in WWW::Mechanize.

It also supports loading and saving sessions, and running scripts from files.

IMPORTANT LINKS

  • WWW::Mechanize on CPAN
  • WWW::Mechanize distribution
  • Andy Lester's CPAN page

INSTALLATION

You can install WWW::Mechanize and its components using CPAN.pm:

    cpan WWW::Mechanize

Or by manually unpacking the distribution and running:

    perl Makefile.PL
    make
    make install

CONSTRUCTOR AND STARTUP

WWW::Mechanize::Shell doesn't have a constructor that you'd call directly. Instead, you run it from the command line:

    $ perl -MWWW::Mechanize::Shell -e shell

This will start an interactive shell session. You can also pass arguments to the shell, such as a URL to visit:

    $ perl -MWWW::Mechanize::Shell -e 'shell("http://www.example.com/")'

You can also run a script file:

    $ perl -MWWW::Mechanize::Shell -e 'shell("myscript.pl")'

forward
Go forward to the next page in the history.

Reload the current page.
links
List all the links on the current page.
images
List all the images on the current page.
forms

Set the current form to the form with the given name.

Set the current form to the form with the given ID.

BEST PRACTICES

When using the shell, remember:

  • Always check the return status of commands, especially form submissions.
  • Use save_session and load_session to preserve your work.
  • Use the script command to automate repetitive tasks.
  • If you find yourself writing complex logic, consider writing a full Perl script instead.
