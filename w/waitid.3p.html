WAITID(3P) دليل مبرمج POSIX WAITID(3P)

مقدمة

هذه الصفحة الدليلية جزء من دليل مبرمج POSIX. قد يختلف تطبيق هذا الواجهة في لينكس (راجع صفحة دليل لينكس المقابلة لتفاصيل سلوك لينكس)، أو قد لا تكون الواجهة مطبقة في لينكس.

الاسم

waitid — انتظار تغيير حالة عملية فرعية

ملخص

#include <sys/wait.h>
int waitid(idtype_t idtype, id_t id, siginfo_t *infop, int options);

الوصف

تقوم الدالة waitid() بالحصول على معلومات الحالة (انظر القسم 2.13، معلومات الحالة) المتعلقة بأحداث الإنهاء، التوقف، و/أو الاستئناف في إحدى العمليات الفرعية للمستدعي.

تتسبب الدالة waitid() في أن تصبح الخيط المستدعي محظورًا حتى يحدث خطأ أو تتوفر معلومات الحالة للخيط المستدعي التي تحقق جميع الخصائص التالية (``معلومات الحالة المطابقة''):

*
معلومات الحالة تأتي من إحدى العمليات الفرعية في مجموعة العمليات الفرعية المحددة بواسطة الوسيطين idtype و id.
*
تغيير الحالة في معلومات الحالة يتطابق مع أحد علامات تغيير الحالة المعينة في الوسيط options.

إذا كانت معلومات الحالة المطابقة متاحة قبل استدعاء waitid()، فسيكون الإرجاع فوريًا. إذا كانت معلومات الحالة المطابقة متاحة لعمليتين فرعيتين أو أكثر، فإن ترتيب الإبلاغ عن حالتهما غير محدد.

كما هو موضح في القسم 2.13، معلومات الحالة، تستهلك الدالة waitid() معلومات الحالة التي تحصل عليها ما لم يتم تعيين علامة WNOWAIT في الوسيط options.

يوصف السلوك عند حظر خيوط متعددة في wait()، waitid()، أو waitpid() في القسم 2.13، معلومات الحالة.

تقوم الدالة waitid() بتسجيل معلومات الحالة التي تم الحصول عليها في البنية التي يشير إليها infop. سيتم ملء حقول البنية التي يشير إليها infop كما هو موضح تحت "مؤشر إلى دالة" في القسم 2.4.3، إجراءات الإشارة.

يتم استخدام الوسيطين idtype و id لتحديد أي العمليات الفرعية تنتظرها waitid().

إذا كان idtype هو P_PID، فسوف تنتظر waitid() العملية الفرعية ذات معرف العملية (process ID) المساوية لـ (pid_t)id.

إذا كان idtype هو P_PGID، فسوف تنتظر waitid() أي عملية فرعية ذات معرف مجموعة العمليات (process group ID) المساوية لـ (pid_t)id.

إذا كان idtype هو P_ALL، فسوف تنتظر waitid() أي عمليات فرعية ويتم تجاهل id.

يتم استخدام الوسيط options لتحديد تغييرات الحالة التي ستنتظرها waitid(). يتم تكوينه عن طريق ORing معًا العلامات التالية:

WCONTINUED
يجب إرجاع الحالة لأي عملية فرعية مستمرة لم يتم الإبلاغ عن حالتها منذ استئنافها من توقف التحكم بالوظائف أو تم الإبلاغ عنها فقط بواسطة استدعاءات لـ waitid() مع تعيين علامة WNOWAIT.
WEXITED
انتظر العمليات التي خرجت.
WNOHANG
لا تتوقف إذا لم تتوفر حالة؛ ارجع فورًا.
WNOWAIT
احتفظ بالعملية التي تم إرجاع حالتها في infop في حالة قابلة للانتظار. هذا لن يؤثر على حالة العملية؛ يمكن انتظار العملية مرة أخرى بعد اكتمال هذا الاستدعاء.
WSTOPPED
يجب إرجاع الحالة لأي عملية فرعية توقفت عند تلقي إشارة، ولم يتم الإبلاغ عن حالتها منذ توقفها أو تم الإبلاغ عنها فقط بواسطة استدعاءات لـ waitid() مع تعيين علامة WNOWAIT.

يجب على التطبيقات تحديد علامة واحدة على الأقل من علامات WEXITED أو WSTOPPED أو WCONTINUED ليتم ORing بها في الوسيط options.

يجب على التطبيق التأكد من أن الوسيط infop يشير إلى بنية siginfo_t. إذا عادت waitid() بسبب العثور على عملية فرعية استوفت الشروط المحددة بواسطة الوسيطين idtype و options، فسيتم ملء البنية التي يشير إليها infop بواسطة النظام بحالة العملية؛ سيتم تعيين العضو si_signo إلى SIGCHLD. إذا عادت waitid() بسبب تحديد WNOHANG وعدم توفر حالة لأي عملية محددة بواسطة idtype و id، فسيتم تعيين العضوين si_signo و si_pid للبنية التي يشير إليها infop إلى الصفر، وتكون قيم الأعضاء الأخرى للبنية غير محددة.

قيمة الإرجاع

إذا تم تحديد WNOHANG ولم تكن الحالة متاحة لأي عملية محددة بواسطة idtype و id، فسيتم إرجاع 0. إذا عادت waitid() بسبب تغيير حالة إحدى العمليات الفرعية التابعة لها، فسيتم إرجاع 0. بخلاف ذلك، سيتم إرجاع -1 وسيتم تعيين errno للإشارة إلى الخطأ.

الأخطاء

ستفشل الدالة waitid() إذا:

ECHILD
ليس لدى العملية المستدعية أي عمليات فرعية غير منتظرة.
EINTR
تم مقاطعة الدالة waitid() بإشارة.
EINVAL
تم تحديد قيمة غير صالحة لـ options، أو أن idtype و id يحددان مجموعة غير صالحة من العمليات.

الأقسام التالية إعلامية.

أمثلة

لا شيء.

استخدام التطبيق

ستقوم استدعاءات waitid() مع idtype مساوٍ لـ P_ALL بجمع معلومات حول أي عملية فرعية. قد يؤدي هذا إلى تفاعلات مع واجهات أخرى قد تنتظر عملياتها الفرعية الخاصة (على سبيل المثال، باستخدام system()). لهذا السبب، يوصى بأن التطبيقات المحمولة لا تستخدم waitid() مع idtype مساوٍ لـ P_ALL. انظر أيضًا استخدام التطبيق لـ wait().

كما هو محدد في عواقب إنهاء العملية، إذا كانت العملية المستدعية لديها SA_NOCLDWAIT معينًا أو لديها SIGCHLD معينًا إلى SIG_IGN، فإن إنهاء عملية فرعية لن يؤدي إلى توفر معلومات الحالة لخيط محظور في wait()، waitid()، أو waitpid(). وبالتالي، سيظل الخيط المحظور في إحدى دوال الانتظار محظورًا ما لم تتسبب حالة أخرى في استئناف تنفيذ الخيط (مثل فشل [ECHILD] بسبب عدم وجود أطفال متبقين في مجموعة الأطفال المنتظرين).

waitid — wait for a child process to change state

SYNOPSIS

#include <sys/wait.h>

int waitid(idtype_t idtype, id_t id, siginfo_t *infop, int options);

DESCRIPTION

The waitid() function is a more general interface for examining and retrieving information about child processes. It is analogous to the POSIX functions wait() and waitpid(), but allows for finer control over which child process to wait for and what information to retrieve.

The idtype argument specifies the type of identifier used by the id argument:

P_ALL
Wait for any child process. The id argument is ignored.
P_PID
Wait for the child process with process ID specified by id.
P_PGID
Wait for any child process whose process group ID is specified by id.
P_SID
Wait for any child process whose session ID is specified by id.

The infop argument points to a siginfo_t structure where information about the child process is stored. This structure is populated with details about the child's termination status, signal that caused termination, process ID, user ID, and other relevant information.

The options argument is a bitmask that specifies which events to wait for and how to behave:

WEXITED
Wait for a child process that has terminated. This is the default if no other options are specified.
WSTOPPED
Wait for a child process that has stopped (e.g., due to receiving a signal it cannot handle).
WCONTINUED
Wait for a child process that has been stopped and then continued.
WNOHANG
Do not block. If no child process matches the criteria, waitid() returns immediately with a return value of 0.
WNOWAIT
Do not discard the child process status. The status information will be available for subsequent calls to waitid().

If options is 0, waitid() blocks until a child process terminates. If options includes WEXITED, WSTOPPED, or WCONTINUED, waitid() blocks until a child process matches the specified criteria.

If waitid() returns successfully, it returns the process ID of the child process that caused the return. If options includes WNOHANG and no child process has yet changed state, 0 is returned.

RETURN VALUE

On success, waitid() returns the process ID of the waited-for child process. If options includes WNOHANG and no child process has yet changed state, 0 is returned. On failure, waitid() returns -1 and sets errno to indicate the error.

ERRORS

ECHILD
The calling process has no existing waitable children.
EINTR
The call was interrupted by a signal, and options did not specify SA_RESTART.
EINVAL
idtype is not one of the recognized values, or options contains mutually exclusive flags.
ENOMSG
options includes WNOHANG and no child process has yet changed state.

EXAMPLES

Wait for any child process to terminate:

struct siginfo info;
pid_t pid;

pid = waitid(P_ALL, 0, &info, WEXITED);
if (pid == -1) {
    perror("waitid");
    exit(EXIT_FAILURE);
}

if (pid > 0) {
    printf("Child process %d terminated with status %d\\n", pid, info.si_status);
}

APPLICATION USAGE

The waitid() function provides a flexible way to manage child processes. Developers can use it to wait for specific children, monitor process groups, or retrieve status information without terminating the child process.

RATIONALE

The waitid() function was introduced to provide a more unified and powerful interface for process state management compared to the older wait() and waitpid() functions. It allows for specifying the type of identifier to wait on and retrieving detailed signal information.

FUTURE DIRECTIONS

Future enhancements may include more granular control over the types of events to wait for and additional information that can be retrieved in the siginfo_t structure.
