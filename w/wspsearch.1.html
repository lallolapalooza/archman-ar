NAME

wspsearch - Run Windows Search Protocol searches against a SMB server

SYNOPSIS

wspsearch {//server/share} [--limit=results] [--search=phrase] [--kind=KIND] [--query=QUERY] [-?|--help] [--usage] [-d|--debuglevel=DEBUGLEVEL] [--debug-stdout] [-s|--configfile=CONFIGFILE] [--option=name=value] [-l|--log-basename=LOGFILEBASE] [--leak-report] [--leak-report-full] [-R|--name-resolve=NAME-RESOLVE-ORDER] [-O|--socket-options=SOCKETOPTIONS] [-m|--max-protocol=MAXPROTOCOL] [-n|--netbiosname=NETBIOSNAME] [--netbios-scope=SCOPE] [-W|--workgroup=WORKGROUP] [--realm=REALM] [-U|--user=[DOMAIN/]USERNAME[%PASSWORD]] [-N|--no-pass] [--password=STRING] [--pw-nt-hash] [-A|--authentication-file=FILE] [-P|--machine-pass] [--simple-bind-dn=DN] [--use-kerberos=desired|required|off] [--use-krb5-ccache=CCACHE] [--use-winbind-ccache] [--client-protection=sign|encrypt|off]

DESCRIPTION

This tool is part of the samba(1) suite.

wspsearch is a simple utility to run Windows Search Protocol searches against a SMB server that has the WSP service enabled.

OPTIONS

server

The SMB server name or IP address to connect to.

sharename

The name of a share on the server.

--query

A query specified in simplified AQS-like (Advanced query syntax).

Basic (AQS) syntax is supported (See SEE ALSO). A query consists of a sequence of queries connected by AND, OR and NOT boolean operators. The query elements are essentially restrictions defined by a property. There are some limitations on the operators supported and some types of properties like enumerated ranges are not supported at all. Additionally syntactically range values are not delimited as specified by AQS (ranges are instead specified as value-value). Some special cases that you see in the windows search UI (for example sizes like 'tiny', 'small', 'large' etc.) are exceptions which are handled more or less as keywords. See EXAMPLES.

--search=phrase

A simple phrase that is searched across the index

--kind=KIND

kind one of;
•Calendar
•Communication
•Contact
•Document
•Email
•Feed
•Folder
•Game
•InstantMessage
•Journal
•Movie
•Music
•Link
•Note
•Picture
•Program
•RecordedTV
•SearchFolder
•Task
•Video
•WebHistory

--limit

A limit on the number of results returned, by default there is a limit of 500 results, a limit of 0 indicates no limit and all results will be returned.

-?|--help

Print a summary of command line options.

--usage

Display brief usage message.

-d|--debuglevel=level

level is an integer from 0 to 10. The default value if this parameter is not specified is 1 for client applications.

The higher this value, the more detail will be logged to the log files about the activities of the server. At level 0, only critical errors and serious warnings will be logged. Level 1 is a reasonable level for day-to-day running - it generates a small amount of information about operations carried out.

Levels above 1 will generate considerable amounts of log data, and should only be used when investigating a problem. Levels above 3 are designed for use only by developers and generate HUGE amounts of log data, most of which is extremely cryptic.

Note that specifying this parameter here will override the log level parameter in the /etc/samba/smb.conf file.

--debug-stdout

This will redirect debug output to STDOUT. By default all clients are logging to STDERR.

--configfile=<configuration file>

The file specified contains the configuration details required by the client. The information in this file can be general for client and server or only provide client specific like options such as client smb encrypt. See /etc/samba/smb.conf for more information. The default configuration file name is determined at compile time.

--option=<name>=<value>

Set the smb.conf(5) option "<name>" to value "<value>" from the command line. This overrides compiled-in defaults and options read from the configuration file. If a name or a value includes a space, wrap whole --option=name=value into quotes.

-l|--log-basename=logdirectory

Base directory name for log/debug files. The extension ".progname" will be appended (e.g. log.smbclient, log.smbd, etc...). The log file is never removed by the client.

--leak-report

Enable talloc leak reporting on exit.

--leak-report-full

Enable full talloc leak reporting on exit.

-V|--version

Prints the program version number.

-U|--user=[DOMAIN\]USERNAME[%PASSWORD]

Sets the SMB username or username and password.

If %PASSWORD is not specified, the user will be prompted. The client will first check the USER environment variable (which is also permitted to also contain the password separated by a %), then the LOGNAME variable (which is not permitted to contain a password) and if either exists, the value is used. If these environmental variables are not found, the username found in a Kerberos Credentials cache may be used.

A third option is to use a credentials file which contains the plaintext of the username and password. This option is mainly provided for scripts where the admin does not wish to pass the credentials on the command line or via environment variables. If this method is used, make certain that the permissions on the file restrict access from unwanted users. See the -A for more details.

Be cautious about including passwords in scripts or passing user-supplied values onto the command line. For security it is better to let the Samba client tool ask for the password if needed, or obtain the password once with kinit.

While Samba will attempt to scrub the password from the process title (as seen in ps), this is after startup and so is subject to a race.

-N|--no-pass

If specified, this parameter suppresses the normal password prompt from the client to the user. This is useful when accessing a service that does not require a password.

Unless a password is specified on the command line or this parameter is specified, the client will request a password.

If a password is specified on the command line and this option is also defined the password on the command line will be silently ignored and no password will be used.

--password

Specify the password on the commandline.

Be cautious about including passwords in scripts or passing user-supplied values onto the command line. For security it is better to let the Samba client tool ask for the password if needed, or obtain the password once with kinit.

If --password is not specified, the tool will check the PASSWD environment variable, followed by PASSWD_FD which is expected to contain an open file descriptor (FD) number.

Finally it will check PASSWD_FILE (containing a file path to be opened). The file should only contain the password. Make certain that the permissions on the file restrict access from unwanted users!

While Samba will attempt to scrub the password from the process title (as seen in ps), this is after startup and so is subject to a race.

--pw-nt-hash

EXAMPLES

This is a set of examples that show how wspsearch can be used.

Example 1. Search for documents containing the word "invoice"

wspsearch //server/share --query="invoice" --kind=Document

Example 2. Search for PDF documents modified in the last 30 days

wspsearch //server/share --query="ext:pdf AND date:last-30-days"

Example 3. Search for music by artist "The Beatles"

wspsearch //server/share --query="artist:"The Beatles"" --kind=Music

Example 4. Search for files with "report" in their name

wspsearch //server/share --query="filename:report"

Example 5. Search for emails from "john.doe@example.com"

wspsearch //server/share --query="from:john.doe@example.com" --kind=Email

Example 6. Search for files larger than 1MB

wspsearch //server/share --query="size:>1MB"

Example 7. Search for files smaller than 100KB

wspsearch //server/share --query="size:<100KB"

Example 8. Search for files between 500KB and 1MB

wspsearch //server/share --query="size:500KB-1MB"

Example 9. Search for documents with a title containing "budget" and authored by "jane doe"

wspsearch //server/share --query="title:budget AND author:"jane doe"" --kind=Document

Example 10. Search for pictures with dimensions 800x600

wspsearch //server/share --query="width:800 AND height:600" --kind=Picture

Example 11. Search for programs last run in the last 7 days

wspsearch //server/share --query="datelastrun:last-7-days" --kind=Program

Example 12. Search for contacts with a phone number

wspsearch //server/share --query="phonenumbers:*" --kind=Contact

Example 13. Search for calendar events happening today

wspsearch //server/share --query="Event.StartDate:today" --kind=Calendar

Example 14. Search for tasks assigned to "user"

wspsearch //server/share --query="AssignedTo:user" --kind=Task

Example 15. Search for emails sent or received in the last 24 hours

wspsearch //server/share --query="datereceived:last-24-hours OR datesent:last-24-hours" --kind=Email

Example 16. Search for files modified by "admin"

wspsearch //server/share --query="owner:admin"

Example 17. Search for documents containing the word "report" and exclude documents modified in the last 24 hours

wspsearch //server/share --query="report NOT date:<24-hours"

Example 18. Search for files with the tag "important"

wspsearch //server/share --query="System.Keywords:important"

Example 19. Search for files with a rating of 3 stars or more

wspsearch //server/share --query="Rating:>3"

Example 20. Search for videos with a duration between 5 and 10 minutes

wspsearch //server/share --query="Duration:5-10min" --kind=Video

Example 21. Search for link in bookmarks

wspsearch //server/share --query="IsFavorite:true" --kind=Link

Example 22. Search for messages that contains "urgent"

wspsearch //server/share --search="urgent"

Example 23. Connect with username and password

wspsearch //server/share -U DOMAIN/USER%PASSWORD --query="invoice"

Example 24. Connect with username and prompt for password

wspsearch //server/share -U DOMAIN/USER --query="invoice"

Example 25. Connect with username and password from file

wspsearch //server/share -A /path/to/creds --query="invoice"

Example 26. Connect without password prompt to a public share

wspsearch //server/share -N --query="invoice"

Example 27. Limit results to 50

wspsearch //server/share --limit=50 --query="invoice"

Example 28. Set log level to 3

wspsearch //server/share -d 3 --query="invoice"

Example 29. Redirect debug output to stdout

wspsearch //server/share --debug-stdout --query="invoice"

Example 30. Use a specific configuration file

wspsearch //server/share -s /etc/samba/client.conf --query="invoice"

Example 31. Set an SMB configuration option from the command line

wspsearch //server/share --option="client smb encrypt=true" --query="invoice"

Example 32. Specify log file base name

wspsearch //server/share -l /var/log/samba/wspsearch --query="invoice"

Example 33. Enable leak reporting

wspsearch //server/share --leak-report --query="invoice"

Example 34. Set name resolve order

wspsearch //server/share -R hosts --query="invoice"

Example 35. Set socket options

wspsearch //server/share -O TCP_NODELAY --query="invoice"

Example 36. Set maximum protocol version

wspsearch //server/share -m SMB2 --query="invoice"

Example 37. Set NetBIOS name

wspsearch //server/share -n MYCLIENT --query="invoice"

Example 38. Set NetBIOS scope

wspsearch //server/share --netbios-scope=TEST --query="invoice"

Example 39. Set workgroup

wspsearch //server/share -W MYGROUP --query="invoice"

Example 40. Set realm

wspsearch //server/share --realm=EXAMPLE.COM --query="invoice"

Example 41. Use Kerberos authentication

wspsearch //server/share --use-kerberos=required --query="invoice"

Example 42. Use Kerberos credentials cache

wspsearch //server/share --use-krb5-ccache=/path/to/ccache --query="invoice"

Example 43. Use winbind credentials cache

wspsearch //server/share --use-winbind-ccache --query="invoice"

Example 44. Set client protection level

wspsearch //server/share --client-protection=sign --query="invoice"

NAME

wspsearch - search Windows Search Index

SYNOPSIS

wspsearch [OPTIONS] [--phrase=PHRASE|--query=QUERY] SERVER/SHARE

DESCRIPTION

wspsearch is a command line tool that can be used to search the Windows Search Index on a remote Windows share.

OPTIONS

The following options are available:

-A|--authentication-file=filename

This option allows you to specify a file from which to read the username and password used in the connection. The format of the file is: 
username = <value>
password = <value>
domain   = <value>

Make certain that the permissions on the file restrict access from unwanted users!

-P|--machine-pass

Use stored machine account password.

--simple-bind-dn=DN

DN to use for a simple bind.

--use-kerberos=desired|required|off

This parameter determines whether Samba client tools will try to authenticate using Kerberos. For Kerberos authentication you should use DNS names instead of IP addresses when connecting to a service. By default Samba client tools will try to use the default Kerberos credential cache (ccache). In case the ccache does not exist or -U|--user option was specified, clients will ask to enter a password and will obtain a Kerberos ticket (kinit) for you. If you want to use an alternative Kerberos credentical cache, use the --use-krb5-ccache option.

Note that specifying this parameter here will override the client use kerberos parameter in the /etc/samba/smb.conf file.

--use-krb5-ccache=CCACHE

Specifies the credential cache location for Kerberos authentication.

This will enforce --use-kerberos=required.

--use-winbind-ccache

Try to use the credential cache by winbind.

--client-protection=sign|encrypt|off

Sets the connection protection the client tool should use.

Note that specifying this parameter here will override the client protection parameter in the /etc/samba/smb.conf file.

In case you need more fine grained control you can use: --option=clientsmbencrypt=OPTION, --option=clientipcsigning=OPTION, --option=clientsigning=OPTION.

EXAMPLES

Search using a basic phrase:

'wspsearch -Usomeuser%password //server/share --phrase="cats"'

Search using an AQS like query for a picture whose name starts with p403 or p404:

'wspsearch -Usomeuser%password //server/share --query="ALL:$<p403 OR ALL:$<p404 AND System.Kind:picture"'

Adanced Query Syntax https://learn.microsoft.com/en-gb/windows/win32/search/-search-3x-advancedquerysyntax

الاسم

wspsearch - البحث في فهرس بحث Windows

الملخص

wspsearch [خيارات] [--عبارة=عبارة|--استعلام=استعلام] خادم/مشاركة

الوصف

wspsearch هي أداة سطر أوامر يمكن استخدامها للبحث في فهرس بحث Windows على مشاركة Windows بعيدة.

الخيارات

الخيارات التالية متاحة:

-A|--authentication-file=filename

يسمح لك هذا الخيار بتحديد ملف لقراءة اسم المستخدم وكلمة المرور المستخدمين في الاتصال. تنسيق الملف هو: 
username = <value>
password = <value>
domain   = <value>

تأكد من أن أذونات الملف تقيد الوصول من المستخدمين غير المرغوب فيهم!

-P|--machine-pass

استخدام كلمة مرور حساب الجهاز المخزنة.

--simple-bind-dn=DN

DN لاستخدامه في ربط بسيط.

--use-kerberos=desired|required|off

يحدد هذا المعامل ما إذا كانت أدوات عميل Samba ستحاول المصادقة باستخدام Kerberos. للمصادقة عبر Kerberos، يجب عليك استخدام أسماء DNS بدلاً من عناوين IP عند الاتصال بخدمة. افتراضيًا، ستحاول أدوات عميل Samba استخدام ذاكرة التخزين المؤقت لبيانات اعتماد Kerberos الافتراضية (ccache). في حالة عدم وجود ccache أو تم تحديد الخيار -U|--user، سيطلب العملاء إدخال كلمة مرور وسيحصلون على تذكرة Kerberos (kinit) لك. إذا كنت تريد استخدام ذاكرة تخزين مؤقت بديلة لبيانات اعتماد Kerberos، فاستخدم الخيار --use-krb5-ccache.

لاحظ أن تحديد هذا المعامل هنا سيتجاوز المعامل client use kerberos في الملف /etc/samba/smb.conf.

--use-krb5-ccache=CCACHE

يحدد موقع ذاكرة التخزين المؤقت لبيانات الاعتماد للمصادقة عبر Kerberos.

سيفرض هذا --use-kerberos=required.

--use-winbind-ccache

محاولة استخدام ذاكرة التخزين المؤقت لبيانات الاعتماد بواسطة winbind.

--client-protection=sign|encrypt|off

يحدد حماية الاتصال التي يجب أن تستخدمها أداة العميل.

لاحظ أن تحديد هذا المعامل هنا سيتجاوز المعامل client protection في الملف /etc/samba/smb.conf.

في حال كنت بحاجة إلى تحكم أكثر دقة، يمكنك استخدام: --option=clientsmbencrypt=OPTION، --option=clientipcsigning=OPTION، --option=clientsigning=OPTION.

'wspsearch -Usomeuser%password //server/share --query="ALL:$<p403 OR ALL:$<p404 AND System.Kind:picture"'
