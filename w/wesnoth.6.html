wesnoth(6)

الحزمة: wesnoth

التراخيص: GPL

 fps
عدد الإطارات في الثانية التي يمكن للعبة عرضها، يجب أن تكون القيمة بين 1 و 1000، القيمة الافتراضية هي معدل تحديث الشاشة.
-m, --multiplayer
تشغيل لعبة متعددة اللاعبين. هناك خيارات إضافية يمكن استخدامها مع --multiplayer كما هو موضح أدناه.
--mp-test
تحميل سيناريوهات الاختبار متعددة اللاعبين.
--new-widgets
توجد مجموعة أدوات واجهة جديدة قيد التطوير (WIP)، هذا الخيار يقوم بتفعيلها. هذا تجريبي جدًا، ولا تقم بتقديم تقارير عن الأخطاء لأن معظمها معروف. أجزاء من المكتبة تعتبر مستقرة وستعمل بدون هذا المفتاح.
--nodelay
تشغيل اللعبة بدون أي تأخيرات للاختبارات الرسومية. يتم تفعيل هذا تلقائيًا بواسطة --nogui.
--noaddons
تعطيل تحميل الإضافات الخاصة بالمستخدم.
--nocache
تعطيل تخزين بيانات اللعبة مؤقتًا.
--nogui
تشغيل اللعبة بدون واجهة رسومية (GUI). متاح فقط بالاشتراك مع --multiplayer أو --screenshot أو --plugin.
--nobanner
كبت شاشة البداية.
--nomusic
تشغيل اللعبة بدون موسيقى.
--noreplaycheck
عدم محاولة التحقق من إعادة تشغيل اختبار الوحدة. ذو صلة فقط عند استخدامه مع -u.
--nosound
تشغيل اللعبة بدون أصوات وموسيقى.
--output file
الإخراج إلى الملف المحدد. ينطبق على عمليات المقارنة.
--password password
يستخدم password عند الاتصال بخادم، متجاهلاً تفضيلات أخرى. غير آمن.
--plugin script
(تجريبي) تحميل script يحدد إضافة لـ Wesnoth. مشابه لـ --script، ولكن يجب أن تعيد ملف Lua دالة يتم تشغيلها كـ coroutine ويتم إيقاظها بشكل دوري بالتحديثات.
-P,--patch base-file patch-file
تطبيق تصحيح DiffWML على ملف WML؛ لا يقوم بمعالجة أي من الملفين مسبقًا. يقوم بإخراج WML المصحح إلى الإخراج القياسي أو إلى الملف المحدد بواسطة --output.
-p, --preprocess source-file/folder target-directory
معالجة مسبقة لملف/مجلد محدد. لكل ملف (ملفات) سيتم كتابة ملف .cfg عادي وملف .cfg معالج مسبقًا في الدليل الهدف المحدد. إذا تم تحديد مجلد، فسيتم معالجته مسبقًا بشكل متكرر بناءً على قواعد المعالجة المسبقة المعروفة. سيتم معالجة وحدات الماكرو الشائعة من دليل "data/core/macros" مسبقًا قبل الموارد المحددة. مثال: -p ~/wesnoth/data/campaigns/tutorial ~/result. للحصول على تفاصيل حول المعالج المسبق، تفضل بزيارة: https://wiki.wesnoth.org/PreprocessorRef#Command-line_preprocessor.
--preprocess-defines=DEFINE1,DEFINE2,...
قائمة مفصولة بفواصل من التعريفات لاستخدامها بواسطة أمر --preprocess. إذا كان SKIP_CORE في قائمة التعريفات، فلن يتم معالجة دليل "data/core" مسبقًا.
--preprocess-input-macros source-file
يستخدم فقط بواسطة أمر --preprocess. يحدد ملفًا يحتوي على [preproc_define]s ليتم تضمينها قبل المعالجة المسبقة.
--preprocess-output-macros[=target-file]
يستخدم فقط بواسطة أمر --preprocess. سيقوم بإخراج جميع وحدات الماكرو المعالجة مسبقًا في الملف الهدف. إذا لم يتم تحديد الملف، فسيكون الإخراج هو الملف '_MACROS_.cfg' في الدليل الهدف لأمر المعالجة المسبقة. يمكن تمرير ملف الإخراج إلى --preprocess-input-macros. يجب كتابة هذا المفتاح قبل أمر --preprocess.
-r XxY, --resolution XxY
يحدد دقة الشاشة. مثال: -r 800x600.
--render-image image output
يأخذ "سلسلة مسار صورة" صالحة لـ Wesnoth مع وظائف مسار الصور، ويخرجها إلى ملف .png. وظائف مسار الصور موثقة في https://wiki.wesnoth.org/ImagePathFunctionWML.
-R, --report
يهيئ أدلة اللعبة، ويطبع معلومات البناء المناسبة لتقارير الأخطاء، ويخرج.
--rng-seed number
يقوم بتهيئة مولد الأرقام العشوائية بالرقم number. مثال: --rng-seed 0.
--screenshot map output
يحفظ لقطة شاشة للخريطة map إلى output بدون تهيئة الشاشة.
--script file
(تجريبي) file يحتوي على سكربت Lua للتحكم في العميل.
-s[host], --server[=host]
يتصل بالمضيف المحدد إذا كان موجودًا، وإلا يتصل بالخادم الأول في التفضيلات. مثال: --server server.wesnoth.org.
--showgui
يشغل اللعبة مع الواجهة الرسومية، متجاوزًا أي --nogui ضمني.
--strict-validation
تُعامل أخطاء التحقق على أنها أخطاء فادحة.
-t[scenario_id], --test[=scenario_id]
يشغل اللعبة في سيناريو اختبار صغير. يجب أن يكون السيناريو محددًا بعلامة WML [test]. الافتراضي هو test. يمكن بدء عرض توضيحي لميزة [micro_ai] باستخدام micro_ai_test.
--translations-over percent
يحدد المعيار لاعتبار الترجمة مكتملة بما يكفي لعرضها في قائمة اللغات داخل اللعبة بـ percent. القيم الصالحة هي من 0 إلى 100.
-u, --unit scenario-id
يشغل سيناريو الاختبار المحدد كاختبار وحدة. يتضمن ضمنيًا --nogui.
--unsafe-scripts
يجعل حزمة package متاحة لسكربتات Lua، بحيث يمكنها تحميل حزم عشوائية. لا تفعل هذا مع السكربتات غير الموثوقة! هذا الإجراء يمنح Lua نفس الأذونات التي يمتلكها الملف التنفيذي لـ Wesnoth.
-S,--use-schema path
يحدد مخطط WML للاستخدام مع -V,--validate.
--userconfig-dir name
يحدد دليل تكوين المستخدم إلى name تحت $HOME أو "My Documents\My Games" لنظام ويندوز. يمكنك أيضًا تحديد مسار مطلق لدليل التكوين خارج $HOME أو "My Documents\My Games". على نظام ويندوز، من الممكن أيضًا تحديد دليل نسبي لدليل العمل الحالي باستخدام مسار يبدأ بـ ".\\" أو "..\\". تحت X11، يكون الافتراضي هو $XDG_CONFIG_HOME أو $HOME/.config/wesnoth، على الأنظمة الأخرى إلى مسار بيانات المستخدم.
--userconfig-path
يطبع مسار دليل تكوين المستخدم ويخرج.
--userdata-dir name
يحدد دليل بيانات المستخدم إلى name تحت $HOME أو "My Documents\My Games" لنظام ويندوز. يمكنك أيضًا تحديد مسار مطلق لدليل بيانات المستخدم خارج $HOME أو "My Documents\My Games". على نظام ويندوز، من الممكن أيضًا تحديد دليل نسبي لدليل العمل الحالي باستخدام مسار يبدأ بـ ".\\" أو "..\\".
--userdata-path
يطبع مسار دليل بيانات المستخدم ويخرج.
--username username
يستخدم username عند الاتصال بخادم، متجاهلاً تفضيلات أخرى.
--validate path
يتحقق من صحة ملف مقابل مخطط WML.
--validate-addon addon_id
يتحقق من صحة WML للإضافة المحددة أثناء اللعب.
--validate-core
يتحقق من صحة WML الأساسي أثناء اللعب.
--validate-schema  path
يتحقق من صحة ملف كمخطط WML.
--validcache
يفترض أن ذاكرة التخزين المؤقت صالحة. (خطير)
-v, --version
يعرض رقم الإصدار ويخرج.
--simple-version
يعرض رقم الإصدار ولا شيء آخر، ثم يخرج.
-w, --windowed
يشغل اللعبة في وضع النافذة.
--with-replay
يعيد تشغيل اللعبة التي تم تحميلها باستخدام الخيار --load.
