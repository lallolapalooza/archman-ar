clock_gettime, clock_settime, clock_getres - timer operations

\n

\nclock_gettime(), clock_settime(), clock_getres() – timer operations\n

\n
\n

SYNOPSIS

\n

#include <time.h>

\n

int clock_gettime(clockid_t clock_id, struct timespec *tp);
\nint clock_settime(clockid_t clock_id, const struct timespec *tp);
\nint clock_getres(clockid_t clock_id, struct timespec *res);

\n
\n
\n

DESCRIPTION

\n

These functions provide a way to set or get the value of a specified clock or to get the resolution of a specified clock.

\n

A clock ID is specified by clock_id. The POSIX standard defines the following clock IDs:

\n
\n
CLOCK_REALTIME
\n
A system-wide clock that is not affected by the system time changes. It represents the time since the Epoch. It can be changed by the system administrator, and consequently it can go backward, jump forward, or be set to different values. This clock is used for time-of-day.
\n
CLOCK_MONOTONIC
\n
A clock that cannot be set back. It is not affected by system time changes. Its value is not defined relative to any particular point in time, but it is useful for measuring intervals.
\n
CLOCK_PROCESS_CPUTIME_ID
\n
The CPU time consumed by the calling process. This clock includes time spent in system mode and user mode.
\n
CLOCK_THREAD_CPUTIME_ID
\n
The CPU time consumed by the calling thread. This clock includes time spent in system mode and user mode.
\n
\n

Linux also defines the following clock IDs:

\n
\n
CLOCK_TAI
\n
A clock that is like CLOCK_REALTIME, but is not affected by leap seconds. It is generally not affected by system time changes. It represents International Atomic Time (TAI).
\n
CLOCK_BOOTTIME
\n
A clock that is like CLOCK_MONOTONIC, but it also includes time while the system is suspended (e.g. sleeping).
\n
CLOCK_MONOTONIC_RAW
\n
A raw monotonic clock, which is not subject to incremental adjustments at the user-space level. This clock is not affected by NTP adjustments or the wall clock time changes.
\n
CLOCK_REALTIME_RAW
\n
A raw clock that is like CLOCK_REALTIME, but not subject to incremental adjustments at the user-space level.
\n
CLOCK_UPTIME_RAW
\n
A raw uptime clock, which is like CLOCK_UPTIME, but not subject to NTP adjustments or wall clock time changes.
\n
\n

The clock_gettime() function returns the current value of the clock specified by clock_id in the struct timespec pointed to by tp. The struct timespec is defined as:

\n
\n
where tv_sec is the number of seconds
    since the Epoch, and tv_nsec is the nanosecond
    fractional part. Both fields are non-negative.
\n
clock_settime() sets the time of
    the clock specified by clock_id to the value
    specified by tp. Only privileged processes can set
    clocks that are not CLOCK_PROCESS_CPUTIME_ID or
    CLOCK_THREAD_CPUTIME_ID.
\n
clock_getres() returns the resolution
    of the specified clock clock_id in the
    struct timespec pointed to by res.
    The resolution is the smallest time increment that can be measured by the
    clock. If the value returned in res is zero, then
    the clock does not provide a measurable resolution.
\n
All these functions return 0 for success. On error, -1 is
    returned and errno is set to indicate the error.

VERSIONS

\n

POSIX.1 specifies the following:

\n
\n

Setting the value of the CLOCK_REALTIME clock via\n clock_settime() shall have no effect on threads that are blocked\n waiting for a relative time service based upon this clock, including the\n nanosleep() function; nor on the expiration of relative timers based\n upon this clock. Consequently, these time services shall expire when the\n requested relative interval elapses, independently of the new or old value\n of the clock.

\n
\n

According to POSIX.1-2001, a process with "appropriate\n privileges" may set the CLOCK_PROCESS_CPUTIME_ID and\n CLOCK_THREAD_CPUTIME_ID clocks using clock_settime(). On\n Linux, these clocks are not settable (i.e., no process has "appropriate\n privileges").

Historical note for SMP systems

\n

Before Linux added kernel support for\n CLOCK_PROCESS_CPUTIME_ID and CLOCK_THREAD_CPUTIME_ID, glibc\n implemented these clocks on many platforms using timer registers from the\n CPUs (TSC on i386, AR.ITC on Itanium). These registers may differ between\n CPUs and as a consequence these clocks may return bogus results if a\n process is migrated to another CPU.

\n

If the CPUs in an SMP system have different clock sources, then\n there is no way to maintain a correlation between the timer registers since\n each CPU will run at a slightly different frequency. If that is the case,\n then clock_getcpuclockid(0) will return ENOENT to signify this\n condition. The two clocks will then be useful only if it can be ensured\n that a process stays on a certain CPU.

\n

The processors in an SMP system do not start all at exactly the\n same time and therefore the timer registers are typically running at an\n offset. Some architectures include code that attempts to limit these offsets\n on bootup. However, the code cannot guarantee to accurately tune the\n offsets. glibc contains no provisions to deal with these offsets (unlike the\n Linux Kernel). Typically these offsets are small and therefore the effects\n may be negligible in most cases.

\n

Since glibc 2.4, the wrapper functions for the system calls\n described in this page avoid the abovementioned problems by employing the\n kernel implementation of CLOCK_PROCESS_CPUTIME_ID and\n CLOCK_THREAD_CPUTIME_ID, on systems that provide such an\n implementation (i.e., Linux 2.6.12 and later).

clock_gettime, clock_settime, clock_getres - عمليات المؤقت

\nclock_gettime()، clock_settime()، clock_getres() – عمليات المؤقت\n

الوصف

\n

توفر هذه الدوال طريقة لضبط أو الحصول على قيمة مؤقت محدد أو\n للحصول على دقة مؤقت محدد.

\n

يتم تحديد معرف المؤقت بواسطة clock_id.\n يحدد معيار POSIX معرفات المؤقتات التالية:

\n
\n
CLOCK_REALTIME
\n
مؤقت على مستوى النظام لا يتأثر بتغيرات وقت النظام. إنه يمثل الوقت\n منذ الحقبة. يمكن لمسؤول النظام تغييره، وبالتالي يمكن أن يعود للخلف،\n يقفز للأمام، أو يتم تعيينه إلى قيم مختلفة. يستخدم هذا المؤقت لوقت\n اليوم.
\n
CLOCK_MONOTONIC
\n
مؤقت لا يمكن إرجاعه للخلف. لا يتأثر بتغيرات وقت النظام. قيمته غير\n معرفة بالنسبة لنقطة زمنية معينة، ولكنه مفيد لقياس الفترات.
\n
CLOCK_PROCESS_CPUTIME_ID
\n
وقت وحدة المعالجة المركزية الذي يستهلكه العملية المتصلة. يتضمن هذا\n المؤقت الوقت الذي تقضيه العملية في وضع النظام ووضع المستخدم.
\n
CLOCK_THREAD_CPUTIME_ID
\n
وقت وحدة المعالجة المركزية الذي يستهلكه الخيط المتصل. يتضمن هذا\n المؤقت الوقت الذي يقضيه الخيط في وضع النظام ووضع المستخدم.
\n
\n

كما يحدد Linux معرفات المؤقتات التالية:

\n
\n
CLOCK_TAI
\n
مؤقت شبيه بـ CLOCK_REALTIME، ولكنه لا يتأثر بالثواني\n الكبيسة. بشكل عام، لا يتأثر بتغيرات وقت النظام. يمثل التوقيت الذري\n الدولي (TAI).
\n
CLOCK_BOOTTIME
\n
مؤقت شبيه بـ CLOCK_MONOTONIC، ولكنه يشمل أيضًا الوقت\n الذي يكون فيه النظام في وضع الإيقاف المؤقت (مثل النوم).
\n
CLOCK_MONOTONIC_RAW
\n
مؤقت أحادي الاتجاه خام، لا يخضع لتعديلات تزايدية على مستوى مساحة\n المستخدم. لا يتأثر هذا المؤقت بتعديلات NTP أو تغيرات وقت الساعة الحائطية.
\n
CLOCK_REALTIME_RAW
\n
مؤقت خام شبيه بـ CLOCK_REALTIME، ولكنه لا يخضع لتعديلات\n تزايدية على مستوى مساحة المستخدم.
\n
CLOCK_UPTIME_RAW
\n
مؤقت وقت تشغيل خام، شبيه بـ CLOCK_UPTIME، ولكنه لا\n يخضع لتعديلات NTP أو تغيرات وقت الساعة الحائطية.
\n
\n

تقوم الدالة clock_gettime() بإرجاع القيمة\n الحالية للمؤقت المحدد بواسطة clock_id في بنية\n struct timespec التي يشير إليها tp.\n البنية struct timespec معرفة كالتالي:

\n
\n
حيث tv_sec هو عدد الثواني منذ\n    الحقبة، و tv_nsec هو الجزء الكسري بالنانوثانية.\n    كلا الحقلين غير سالبين.
\n
تقوم الدالة clock_settime() بضبط وقت\n    المؤقت المحدد بواسطة clock_id إلى القيمة المحددة بواسطة\n    tp. لا يمكن للعمليات غير المميزة إلا ضبط المؤقتات التي\n    ليست CLOCK_PROCESS_CPUTIME_ID أو\n    CLOCK_THREAD_CPUTIME_ID.
\n
تقوم الدالة clock_getres() بإرجاع دقة\n    المؤقت المحدد clock_id في بنية\n    struct timespec التي يشير إليها res.\n    الدقة هي أصغر فترة زمنية يمكن قياسها بواسطة المؤقت. إذا كانت القيمة\n    المرجعة في res صفرًا، فهذا يعني أن المؤقت لا\n    يوفر دقة قابلة للقياس.
\n
جميع هذه الدوال ترجع 0 عند النجاح. عند حدوث خطأ، يتم إرجاع -1\n    ويتم تعيين errno للإشارة إلى الخطأ.

الإصدارات

\n

يحدد POSIX.1 ما يلي:

\n
\n

ضبط قيمة المؤقت CLOCK_REALTIME عبر\n clock_settime() لن يكون له أي تأثير على الخيوط التي تنتظر\n خدمة زمنية نسبية تعتمد على هذا المؤقت، بما في ذلك الدالة\n nanosleep()؛ ولا على انتهاء صلاحية المؤقتات النسبية المعتمدة على\n هذا المؤقت. ونتيجة لذلك، ستنتهي صلاحية هذه الخدمات الزمنية عند انقضاء\n الفترة النسبية المطلوبة، بشكل مستقل عن القيمة الجديدة أو القديمة للمؤقت.

ملاحظة تاريخية للأنظمة المتعددة المعالجات (SMP)

\n

قبل أن تضيف Linux دعم النواة لـ\n CLOCK_PROCESS_CPUTIME_ID و CLOCK_THREAD_CPUTIME_ID، قامت glibc\n بتنفيذ هذه المؤقتات على العديد من المنصات باستخدام سجلات المؤقت من وحدات\n المعالجة المركزية (TSC على i386، AR.ITC على Itanium). قد تختلف هذه السجلات\n بين وحدات المعالجة المركزية ونتيجة لذلك قد تعيد هذه المؤقتات نتائج غير\n صحيحة إذا تم ترحيل عملية إلى وحدة معالجة مركزية أخرى.

\n

إذا كانت وحدات المعالجة المركزية في نظام SMP لديها مصادر مؤقت مختلفة،\n فلا توجد طريقة للحفاظ على الارتباط بين سجلات المؤقت حيث أن كل وحدة معالجة\n مركزية ستعمل بتردد مختلف قليلاً. إذا كان الأمر كذلك، فسيعيد\n clock_getcpuclockid(0) قيمة ENOENT للإشارة إلى هذا\n الوضع. ستكون المؤقتات مفيدة فقط إذا كان يمكن ضمان بقاء العملية على وحدة\n معالجة مركزية معينة.

\n

لا تبدأ المعالجات في نظام SMP جميعها في نفس الوقت بالضبط، وبالتالي\n تعمل سجلات المؤقت عادةً بإزاحة. تتضمن بعض المعماريات رمزًا يحاول\n الحد من هذه الإزاحات عند الإقلاع. ومع ذلك، لا يمكن للرمز ضمان ضبط\n الإزاحات بدقة. لا تحتوي glibc على أي أحكام للتعامل مع هذه الإزاحات\n (على عكس نواة Linux). عادة ما تكون هذه الإزاحات صغيرة وبالتالي قد تكون\n التأثيرات ضئيلة في معظم الحالات.

\n

منذ glibc 2.4، تتجنب الدوال الواقية لاستدعاءات النظام الموضحة في\n هذه الصفحة المشاكل المذكورة أعلاه عن طريق استخدام تنفيذ النواة لـ\n CLOCK_PROCESS_CPUTIME_ID و CLOCK_THREAD_CPUTIME_ID، على\n الأنظمة التي توفر مثل هذا التنفيذ (أي Linux 2.6.12 وما بعده).
