CSV output format

\n

CSV (comma-separated value) files are often used by spreadsheets\n and report generators. For CSV output, cvtsudoers\n double quotes strings that contain commas. For each literal double quote\n character present inside the string, two double quotes are output. This\n method of quoting commas is compatible with most spreadsheet programs.\n

\n

There are three possible sections in\n cvtsudoers's CSV output, each separated by a blank\n line:\n

\n
\n
defaults
\n
This section includes any Defaults settings in\n sudoers. The defaults section begins\n with the following heading:\n
\n 
defaults_type,binding,name,operator,value
\n
\n

The fields are as follows:\n

\n
\n
defaults_type
\n
The type of Defaults setting; one of\n defaults, defaults_command,\n defaults_host, defaults_runas, or\n defaults_user.\n
\n
binding
\n
For defaults_command,\n defaults_host, defaults_runas, and\n defaults_user this is the value that must match for\n the setting to be applied.\n
\n
name
\n
The name of the Defaults setting.\n
\n
operator
\n
The operator determines how the value is applied to the setting. It\n may be either ‘=’ (assignment),\n ‘+=’ (append), or\n ‘-=’ (remove).\n
\n
value
\n
The setting's value, usually a string or, for settings used in a\n boolean context,\n true or\n false.\n
\n
\n
\n
aliases
\n
This section includes any Cmnd_Alias\n Host_Alias, Runas_Alias, or\n User_Alias, entries from sudoers. The\n aliases section begins with the following heading:\n
\n 
alias_type,alias_name,members
\n
\n

The fields are as follows:\n

\n
\n
alias_type
\n
The type of alias; one of Cmnd_Alias,\n Host_Alias, Runas_Alias, or\n User_Alias.\n
\n
alias_name
\n
The name of the alias; a string starting with an upper-case letter\n that consists of upper-case letters, digits, or underscores.\n
\n
members
\n
A comma-separated list of members belonging to the alias. Due to the\n use of commas,\n members is\n surrounded by double quotes if it contains more than one member.\n
\n
\n
\n
rules
\n
This section includes the sudoers rules that grant\n privileges. The\n rules section\n begins with the following heading:\n
\n 
rule,user,host,runusers,rungroups,options,command
\n
\n

The fields are as follows:\n

\n
\n
rule
\n
This field indicates a sudoers\n rule\n entry.\n
\n
user
\n
The user the rule applies to. This may also be a Unix group (preceded\n by a ‘%’ character), a non-Unix\n group (preceded by ‘%:’) or a\n netgroup (preceded by a ‘+’\n character) or a User_Alias. If set to the special\n value ALL, it will match any user.\n
\n
host
\n
The host the rule applies to. This may also be a netgroup (preceded by\n a ‘+’ character) or a\n Host_Alias. If set to the special value\n ALL, it will match any host.\n
\n
runusers
\n
An optional comma-separated list of users (or\n Runas_Aliases) the command\n may be run as. If it contains more than one member, the value is\n surrounded by double quotes. If set to the special value\n ALL, it will match any user. If empty, the root user\n is assumed.\n
\n
rungroups
\n
An optional comma-separated list of groups (or\n Runas_Aliases) the command\n may be run as. If it contains more than one member, the value is\n surrounded by double quotes. If set to the special value\n ALL, it will match any group. If empty, the\n runuser's\n group is used.\n
\n
options
\n
An optional list of Defaults settings to apply to\n the command. Any Tag_Spec entries in\n sudoers are converted to\n options.\n
\n
commands
\n
A list of commands, with optional arguments, that the user is allowed\n to run. If set to the special value ALL, it will\n match any command.\n
\n
\n

For example, the following sudoers\n entry:\n

\n

\n

EXAMPLES

\n

Convert /etc/sudoers to LDIF (LDAP Data\n Interchange Format) where the ldap.conf file uses a\n sudoers_base of my-domain,dc=com, storing the result in\n sudoers.ldif:\n

\n
\n
$ cvtsudoers -b ou=SUDOers,dc=my-domain,dc=com -o sudoers.ldif \\\n             /etc/sudoers
\n
\n

Convert /etc/sudoers to JSON format,\n storing the result in sudoers.json:\n

\n
\n
$ cvtsudoers -f json -o sudoers.json /etc/sudoers
\n
\n

\n Parse /etc/sudoers and\n display only rules that match user\n ambrose on host\n hastur:\n

\n
\n
$ cvtsudoers -f sudoers -m user=ambrose,host=hastur /etc/sudoers
\n
\n

Same as above, but expand aliases and prune out any non-matching\n users and hosts from the expanded entries.\n

\n
\n
$ cvtsudoers -ep -f sudoers -m user=ambrose,host=hastur /etc/sudoers
\n
\n

Convert sudoers.ldif from LDIF to\n traditional sudoers format:\n

\n
\n
$ cvtsudoers -i ldif -f sudoers -o sudoers.new sudoers.ldif
\n
\n

Merge a global sudoers file with two\n host-specific policy files from the hosts “xyzzy” and\n “plugh”:\n

\n
\n
$ cvtsudoers -f sudoers -o sudoers.merged sudoers \\\n    xyzzy:sudoers.xyzzy plugh:sudoers.plugh
\n
\n
\n
