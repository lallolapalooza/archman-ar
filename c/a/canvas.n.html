canvas(n)

الحزمة: tk

التراخيص: TCL

NAME

canvas - create and manipulate canvas items

SYNOPSIS

pathName canvas ?options?
pathName add itemType ?args?
pathName bind item ?sequence? ?script?
pathName canvasx screenx ?screeny?
pathName canvasy screeny ?screenx?
pathName config ?options?
pathName delete item ?item ...?
pathName dchars item ?first? ?last?
pathName dtag item ?tagOrId ...?
pathName focus ?item?
pathName getleadsto item ?first? ?last?
pathName icursor item ?index?
pathName index item ?index?
pathName insert item index string
pathName itemconfig item ?commonSubmenu ?value?
pathName itembind item ?sequence? ?script?
pathName move item x y
pathName postscript ?options?
pathName scan option ?arg?
pathName see item ?item ...?
pathName selection ?option? ?arg?
pathName xview ?args?
pathName yview ?args?

DESCRIPTION

The canvas widget displays graphical objects such as lines, rectangles, polygons, text, bitmaps, and images. It also supports embedding other windows within the canvas. The canvas widget is a high-level widget that manages a collection of graphical items. The canvas widget itself is a widget, and the items within it are managed by the widget, not as separate widgets.

The canvas supports several different types of items:

  • Lines
  • Rectangles
  • Ovals
  • Polygons
  • Text
  • Bitmaps
  • Images
  • Windows

Each item is identified by a unique integer ID, or by one or more arbitrary string tags associated with the item. Commands that operate on items can refer to them either by ID or by tag.

Items are created using the add command, followed by the item type and arguments specific to that type. Items can be modified using the itemconfig command, and deleted using the delete command. Other commands provide ways to move items (move), make them visible (see), change their display state (focus, state), and retrieve information about them.

The canvas widget can also be scrolled using the xview and yview commands, which are designed to be linked to scrollbar widgets.

The canvas supports item-specific bindings. The bind command can be used to bind events to the canvas as a whole, while the itembind command can be used to bind events to particular items (or groups of items identified by tags).

The postscript command can be used to write the contents of the canvas to a file in PostScript format.

Coordinates within the canvas are specified using a coordinate system that can be transformed. Initially, the origin (0,0) is at the top-left corner of the canvas, and positive x and y coordinates increase to the right and down, respectively. However, the coordinate system can be transformed using the canvas command itself (see the Tk_Canvas.3 manual page).

Canvas items may have common options that control their appearance and behavior, such as color, stippling, and state. In addition, most items have options that control how they behave when the mouse pointer is over them and they are in a special state (e.g., the mouse is down, or the item has the input focus). These special states are indicated by options like -activefill, -activestipple, etc. The exact set of active options depends on the item type.

The following standard options are supported by most canvas items:

-fill	-disabledfill
-outline	-disabledoutline
-stipple	-disabledstipple
-tags

Many items also support corresponding -active options (e.g., -activefill). The default value for these options typically results in no visual change when the item is in the active state.

Standard options for items include:

-state normal | disabled
Specifies whether the item is currently active. Disabled items typically do not respond to events or mouse actions. Defaults to normal.
-tags tagOrIdList
A list of tags associated with the item. Items may have zero or more tags. Tags are used to group items together for operations like deletion, configuration, or event binding.

Other standard options include -width, -dash, and -stipple, which control the appearance of outlines and fills.

The options specific to each item type are described below.

ITEM TYPES

BITMAP ITEMS

A bitmap item displays a monochrome bitmap on the screen. Bitmap items are created with widget commands of the following form:

pathName create bitmap x y ?option value ...?
pathName create bitmap coordList ?option value ...?
The arguments x and y or coordList (which must have two elements) specify the coordinates of the point where the bitmap is to be displayed. The exact position is determined by the -anchor option. After the coordinates there may be any number of option-value pairs, each of which sets one of the configuration options for the item. These same option-value pairs may be used in itemconfigure widget commands to change the item's configuration. A bitmap item becomes the current item when the mouse pointer is over any part of its bounding box.

The following standard options are supported by bitmap items:

-anchor	-background
-disabledbackground	-disabledforeground
-fill	-activefill
-disabledfill	-foreground
-activeforeground	-state
-tags

The following extra options are supported for bitmap items:

-bitmap bitmapName
Specifies the bitmap to be displayed. BitmapName can be the name of a predefined bitmap (like {@code error} or {@code gray75}) or the name of a bitmap created with the Bitmap command. If this option is omitted, the item will display nothing.
-data bitmapString
Specifies the bitmap data as a string in the standard X11 bitmap format. This option is an alternative to -bitmap.
-file fileName
Specifies the name of a file containing bitmap data. This option is an alternative to -bitmap.
-maskdata bitmapString
Specifies the mask data as a string in the standard X11 bitmap format. This option is an alternative to -bitmap and is used to create bitmaps with transparent areas.
-maskfile fileName
Specifies the name of a file containing mask data. This option is an alternative to -bitmap and is used to create bitmaps with transparent areas.

IMAGE ITEMS

An image item displays a Tk image on the screen. Image items are created with widget commands of the following form:

pathName create image x y ?option value ...?
pathName create image coordList ?option value ...?
The arguments x and y or coordList (which must have two elements) specify the coordinates of the point where the image is to be displayed. The exact position is determined by the -anchor option. After the coordinates there may be any number of option-value pairs, each of which sets one of the configuration options for the item. These same option-value pairs may be used in itemconfigure widget commands to change the item's configuration. An image item becomes the current item when the mouse pointer is over any part of its bounding box.

The following standard options are supported by image items:

-anchor	-state
-tags

The following extra options are supported for image items:

-image imageName
Specifies the Tk image to be displayed. ImageName must be the name of an image created using the image command. If this option is omitted, the item will display nothing.

LINE ITEMS

A line item displays a sequence of connected line segments. Lines are created with widget commands of the following form:

pathName create line coordList ?option value ...?
pathName create line x1 y1 x2 y2 ?x3 y3 ...? ?option value ...?
The arguments coordList (which must contain an even number of elements) or x1 y1 x2 y2 ... specify the coordinates of the points defining the line. After the coordinates there may be any number of option-value pairs, each of which sets one of the configuration options for the item. These same option-value pairs may be used in itemconfigure widget commands to change the item's configuration. A line item becomes the current item when the mouse pointer is over any part that is painted or (when fully transparent) that would be painted if the -fill option were non-empty.

The following standard options are supported by lines:

-arrow	-arrowshape
-close	-dash
-dashoffset	-disableddash
-disabledfill	-disabledoffset
-disabledoutlinewidth	-disabledstipple
-fill	-activearrow
-activearrowshape	-activedash
-activedashoffset	-activefill
-activeoutlinewidth	-activestipple
-offset	-outline
-outlinestipple	-outlinewidth
-spline	-state
-tags	-width
-activewidth	-disabledwidth

There are no line-specific options.

OVAL ITEMS

An oval item displays an oval or circle on the screen. Ovals are created with widget commands of the following form:

pathName create oval x1 y1 x2 y2 ?option value ...?
pathName create oval coordList ?option value ...?
The arguments x1, y1, x2, and y2 or coordList (which must have four elements) give the coordinates of two diagonally opposite corners of the bounding box of the oval. The oval will include its upper and left edges but not its lower or right edges. After the coordinates there may be any number of option-value pairs, each of which sets one of the configuration options for the item. These same option-value pairs may be used in itemconfigure widget commands to change the item's configuration. An oval item becomes the current item when the mouse pointer is over any part that is painted or (when fully transparent) that would be painted if both the -fill and -outline options were non-empty.

The following standard options are supported by ovals:

-dash	-activedash
-disableddash	-dashoffset
-fill	-activefill
-disabledfill	-offset
-outline	-activeoutline
-disabledoutline	-outlineoffset
-outlinestipple	-activeoutlinestipple
-disabledoutlinestipple	-stipple
-activestipple	-disabledstipple
-state	-tags
-width	-activewidth
-disabledwidth

There are no oval-specific options.

POLYGON ITEMS

A polygon item displays a closed shape with any number of vertices. Polygons are created with widget commands of the following form:

pathName create polygon coordList ?option value ...?
pathName create polygon x1 y1 x2 y2 ?x3 y3 ...? ?option value ...?
The arguments coordList (which must contain an even number of elements) or x1 y1 x2 y2 ... specify the coordinates of the points defining the polygon's vertices. The polygon is automatically closed by connecting the last point back to the first. After the coordinates there may be any number of option-value pairs, each of which sets one of the configuration options for the item. These same option-value pairs may be used in itemconfigure widget commands to change the item's configuration. A polygon item becomes the current item when the mouse pointer is over any part that is painted or (when fully transparent) that would be painted if both the -fill and -outline options were non-empty.

The following standard options are supported by polygons:

-close	-dash
-dashoffset	-disableddash
-disabledfill	-disabledoutlinewidth
-disabledstipple	-fill
-activefill	-activedash
-activedashoffset	-activeoutlinestipple
-activeoutline	-activestipple
-outline	-outlinestipple
-outlinewidth	-stipple
-state	-tags
-width	-activewidth
-disabledwidth

There are no polygon-specific options.

RECTANGLE ITEMS

A rectangle item displays a rectangle on the display. Each rectangle may have an outline, a fill, or both. Rectangles are created with widget commands of the following form:

pathName create rectangle x1 y1 x2 y2 ?option value ...?
pathName create rectangle coordList ?option value ...?
The arguments x1, y1, x2, and y2 or coordList (which must have four elements) give the coordinates of two diagonally opposite corners of the rectangle (the rectangle will include its upper and left edges but not its lower or right edges). After the coordinates there may be any number of option-value pairs, each of which sets one of the configuration options for the item. These same option-value pairs may be used in itemconfigure widget commands to change the item's configuration. A rectangle item becomes the current item when the mouse pointer is over any part that is painted or (when fully transparent) that would be painted if both the -fill and -outline options were non-empty.

The following standard options are supported by rectangles:

-dash	-activedash
-disableddash	-dashoffset
-fill	-activefill
-disabledfill	-offset
-outline	-activeoutline
-disabledoutline	-outlineoffset
-outlinestipple	-activeoutlinestipple
-disabledoutlinestipple	-stipple
-activestipple	-disabledstipple
-state	-tags
-width	-activewidth
-disabledwidth

There are no rectangle-specific options.

TEXT ITEMS

A text item displays a string of characters on the screen in one or more lines. Text items support indexing, editing and selection through the dchars widget command, the focus widget command, the icursor widget command, the index widget command, the insert widget command, and the select widget command. Text items are created with widget commands of the following form:

pathName create text x y ?option value ...?
pathName create text coordList ?option value ...?
The arguments x and y or coordList (which must have two elements) specify the coordinates of a point used to position the text on the display (see the options below for more information on how text is displayed). After the coordinates there may be any number of option-value pairs, each of which sets one of the configuration options for the item. These same option-value pairs may be used in itemconfigure widget commands to change the item's configuration. A text item becomes the current item when the mouse pointer is over any part of its bounding box.

The following standard options are supported by text items:

-anchor	-fill
-activefill	-disabledfill
-stipple	-activestipple
-disabledstipple	-state
-tags

The following extra options are supported for text items:

-angle rotationDegrees
RotationDegrees tells how many degrees to rotate the text anticlockwise about the positioning point for the text; it may have any floating-point value from 0.0 to 360.0. For example, if rotationDegrees is 90, then the text will be drawn vertically from bottom to top. This option defaults to 0.0.
-font fontName
Specifies the font to use for the text item. FontName may be any string acceptable to Tk_GetFont. If this option is not specified, it defaults to a system-dependent font.
-justify how
Specifies how to justify the text within its bounding region. How must be one of the values left, right, or center. This option will only matter if the text is displayed as multiple lines. If the option is omitted, it defaults to left.
-text string
String specifies the characters to be displayed in the text item. Newline characters cause line breaks. The characters in the item may also be changed with the insert and delete widget commands. This option defaults to an empty string.
-underline
Specifies the integer index of a character within the text to be underlined. 0 corresponds to the first character of the text displayed, 1 to the next character, and so on. -1 means that no underline should be drawn (if the whole text item is to be underlined, the appropriate font should be used instead).
-width lineLength
Specifies a maximum line length for the text, in any of the forms described in the COORDINATES section above. If this option is zero (the default) the text is broken into lines only at newline characters. However, if this option is non-zero then any line that would be longer than lineLength is broken just before a space character to make the line shorter than lineLength; the space character is treated as if it were a newline character.

WINDOW ITEMS

Items of type window cause a particular window to be displayed at a given position on the canvas. Window items are created with widget commands of the following form:

pathName create window x y ?option value ...?
pathName create window coordList ?option value ...?
The arguments x and y or coordList (which must have two elements) specify the coordinates of a point used to position the window on the display, as controlled by the -anchor option. After the coordinates there may be any number of option-value pairs, each of which sets one of the configuration options for the item. These same option-value pairs may be used in itemconfigure widget commands to change the item's configuration. Theoretically, a window item becomes the current item when the mouse pointer is over any part of its bounding box, but in practice this typically does not happen because the mouse pointer ceases to be over the canvas at that point.

The following standard options are supported by window items:

-anchor	-state
-tags

The following extra options are supported for window items:

-height pixels
Specifies the height to assign to the item's window. Pixels may have any of the forms described in the COORDINATES section above. If this option is not specified, or if it is specified as zero, then the window is given whatever height it requests internally.
-width pixels
Specifies the width to assign to the item's window. Pixels may have any of the forms described in the COORDINATES section above. If this option is not specified, or if it is specified as zero, then the window is given whatever width it requests internally.
-window pathName
Specifies the window to associate with this item. The window specified by pathName must either be a child of the canvas widget or a child of some ancestor of the canvas widget. PathName may not refer to a top-level window.

Note: due to restrictions in the ways that windows are managed, it is not possible to draw other graphical items (such as lines and images) on top of window items. A window item always obscures any graphics that overlap it, regardless of their order in the display list. Also note that window items, unlike other canvas items, are not clipped for display by their containing canvas's border, and are instead clipped by the parent widget of the window specified by the -window option; when the parent widget is the canvas, this means that the window item can overlap the canvas's border.

APPLICATION-DEFINED ITEM TYPES

It is possible for individual applications to define new item types for canvas widgets using C code. See the documentation for Tk_CreateItemType.

BINDINGS

In the current implementation, new canvases are not given any default behavior: you will have to execute explicit Tcl commands to give the canvas its behavior.

CREDITS

Tk's canvas widget is a blatant ripoff of ideas from Joel Bartlett's ezd program. Ezd provides structured graphics in a Scheme environment and preceded canvases by a year or two. Its simple mechanisms for placing and animating graphical objects inspired the functions of canvases.
