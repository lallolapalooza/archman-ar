الاسم

containerd

ملخص

containerd

[--address|-a]=[value]
[--config|-c]=[value]
[--log-level|-l]=[value]
[--root]=[value]
[--state]=[value]

الوصف

containerd هو محرك حاويات عالي الأداء يمكن بدء تشغيل خدمته باستخدام هذا الأمر. إذا لم يتم تحديد أي من الأوامر config أو publish أو oci-hook أو help، فإن الإجراء الافتراضي للأمر containerd هو بدء تشغيل خدمة containerd في المقدمة.

يتم استخدام تكوين افتراضي إذا لم يتم تحديد ملف تكوين TOML أو لم يتم العثور عليه في الموقع الافتراضي للملف. يمكن استخدام الأمر containerd config لإنشاء التكوين الافتراضي لـ containerd. يمكن استخدام ناتج هذا الأمر وتعديله حسب الحاجة كتكوين مخصص.

الاستخدام:

containerd [GLOBAL OPTIONS] command [COMMAND OPTIONS] [ARGUMENTS...]

خيارات عامة

--address, -a="": عنوان خادم GRPC الخاص بـ containerd

--config, -c="": المسار إلى ملف التكوين (الافتراضي: "/etc/containerd/config.toml")

--log-level, -l="": تعيين مستوى التسجيل [trace, debug, info, warn, error, fatal, panic]

--root="": دليل الجذر الخاص بـ containerd

--state="": دليل الحالة الخاص بـ containerd

الأوامر

config

معلومات حول تكوين containerd

افتراضي

انظر ناتج التكوين الافتراضي

تفريغ

انظر ناتج التكوين الرئيسي النهائي مع استيراد ملفات التكوين الفرعية

ترحيل

ترحيل ملف التكوين الحالي إلى أحدث إصدار (لا يرحل ملفات التكوين الفرعية)

نشر

برنامج ثنائي لنشر الأحداث إلى containerd

--namespace="": مساحة الاسم للنشر إليها

--topic="": موضوع الحدث

oci-hook

يوفر أساسًا لخطافات تشغيل OCI للسماح بحقن الوسائط.
