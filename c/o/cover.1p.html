cover(1p)

الحزمة: perl-devel-cover

التراخيص: PerlArtistic, GPL

COVER(1p) توثيق Perl مساهم به من المستخدم COVER(1p)

الاسم

cover - تقرير إحصائيات التغطية

الإصدار

الإصدار 1.51

ملخص

cover -test
cover -report html_basic

الوصف

تقرير إحصائيات التغطية بتنسيقات متنوعة.

يُنشئ خيار الملخص ملخصاً نصياً قصيراً. تتوفر تقارير أخرى باستخدام خيار التقرير.

التقارير التالية متاحة حاليًا:

html        - تقارير HTML مفصلة (الافتراضي)
html_basic  - تقارير HTML مفصلة مع تمييز الصيغة
text        - ملخص نصي مفصل
compilation - إخراج بتنسيق مشابه لأخطاء Perl
json        - إخراج بتنسيق JSON
vim         - عرض معلومات التغطية في عمود الإلحاق الخاص بـ vim

الخيارات

يتم دعم خيارات سطر الأوامر التالية:

-h -help              - عرض المساعدة
-i -info              - عرض التوثيق
-v -version           - عرض الإصدار
-silent               - عدم طباعة رسائل المعلومات (الافتراضي: معطل)
-summary              - تقديم تقرير ملخص (الافتراضي: مفعل)
-report report_format - تنسيق التقرير (الافتراضي: html)
-outputdir dir        - الدليل الخاص بالإخراج (الافتراضي: قاعدة البيانات المعطاة)
-launch               - تشغيل التقرير في عارض (إذا كان متاحًا) (الافتراضي: معطل)
-select filename      - التقرير عن الملف فقط (الافتراضي: الكل)
-ignore filename      - عدم التقرير عن الملف (الافتراضي: لا شيء)
-select_re RE         - إضافة إلى التعبيرات العادية لملفات التحديد (الافتراضي: لا شيء)
-ignore_re RE         - إضافة إلى التعبيرات العادية للملفات التي سيتم تجاهلها (الافتراضي: لا شيء)
-relative_only        - بالنسبة لـ XS، تجاهل المسارات المطلقة (الافتراضي: معطل)
-gcov_chdir           - بالنسبة لـ XS، تشغيل gcov في الدلائل الفرعية (الافتراضي: معطل)
-write [db]           - كتابة قاعدة البيانات المدمجة (الافتراضي: معطل)
-delete               - حذف قاعدة البيانات (قواعد البيانات) (الافتراضي: معطل)
-dump_db              - تفريغ قاعدة البيانات (قواعد البيانات) (للتصحيح) (الافتراضي: معطل)
-coverage criterion   - التقرير عن المعيار (الافتراضي: جميع المتاح)
-test                 - حذف قاعدة البيانات وتشغيل make test (الافتراضي: معطل)
-gcov                 - تشغيل gcov لتغطية رمز XS (الافتراضي: مفعل إذا كنت تستخدم gcc)
-make make_prog       - استخدام برنامج 'make' المعطى لـ 'make test'
-prefer_lib           - تفضيل الملفات في lib (الافتراضي: معطل)
-ignore_covered_err   - السماح بتغطية الكود غير القابل للتغطية (الافتراضي: معطل)
-add_uncoverable_point    string
-delete_uncoverable_point string
-clean_uncoverable_points
-uncoverable_file         file
خيارات أخرى خاصة بتنسيق التقرير
coverage_database [coverage_database ...]

يمكن تحديد خيارات "-report"، "-select"، "-ignore"، "-select_re"، "-ignore_re"، و "-coverage" عدة مرات.

تنسيقات التقرير

خيارات "-report" التالية متاحة في الوحدة الأساسية. قد تتوفر تقارير أخرى إذا تم تثبيتها من حزم خارجية.

html|html_minimal (الافتراضي)
تقرير HTML. يتم ترميز نسب مئوية العتبات بالألوان وهي قابلة للتكوين عبر -report_c0 <integer>، و -report_c1 <integer>، و -report_c2 <integer>.: 
0%      75%      90%      100%
|   ..   |   ..   |   ..   |
   <c0      <c1      <c2   c3
   أحمر     أصفر    برتقالي أخضر
html_basic
تقرير HTML مع تمييز الصيغة إذا تم اكتشاف وحدة PPI::HTML أو Perl::Tidy. مثل تقرير html|html_minimal، يتم ترميز نسب مئوية العتبات بالألوان وهي قابلة للتكوين.
text
تقرير نصي عادي.
compilation
تقرير نصي بتنسيق مشابه لما يُخرجه Perl نفسه، بحيث يمكن استخدام التقرير بواسطة المحرر الخاص بك أو أدوات التقارير الأخرى لإظهار أماكن نقص التغطية.
json
تقرير بتنسيق JSON.
vim
تقرير مناسب للاستخدام مع محرر vim لإظهار بيانات التغطية في عمود الإلحاق.

التفاصيل

يمكن تحديد أي عدد من قواعد بيانات التغطية في سطر الأوامر. سيتم دمج قواعد البيانات هذه وستستند التقارير إلى المعلومات المدمجة. إذا لم يتم تحديد قواعد بيانات، فسيتم استخدام قاعدة البيانات الافتراضية (cover_db).

سيقوم خيار "-write" بكتابة قاعدة البيانات المدمجة. إذا لم يتم إعطاء اسم لقاعدة البيانات الجديدة، فسيتم الكتابة فوق قاعدة البيانات الأولى التي تم قراءتها. عند استخدام هذا الخيار، لا يتم إنشاء أي تقارير افتراضيًا.

حدد خيارات "-select"، "-select_re"، "-ignore"، و "-ignore_re" للتقرير عن ملفات محددة. يتم تفسير "-select" و "-ignore" على أنها قوالب shell؛ ويتم تفسير "-select_re" و "-ignore_re" على أنها تعبيرات عادية.

حدد خيارات "-coverage" للتقرير عن معايير محددة. افتراضيًا، سيتم الإبلاغ عن جميع المعلومات المتاحة عن جميع المعايير في جميع الملفات. خيارات التغطية المتاحة هي: statement، branch، condition، subroutine، pod، و default (والتي تساوي جميع الخيارات المتاحة). ومع ذلك، إذا كنت تعرف أنك تريد فقط معلومات التغطية لمعايير معينة، فمن الأفضل جمع البيانات لتلك المعايير فقط في المقام الأول عن طريق تحديدها في ذلك الوقت. سيؤدي ذلك إلى تسريع عمليات جمع البيانات وإعداد التقارير وتقليل استهلاك الذاكرة. انظر التوثيق الخاص بـ Devel::Cover لمزيد من المعلومات.

إذا كنت تريد كل شيء *باستثناء* بعض المعايير، فيمكنك قول شيء مثل "-coverage default,-pod".

إذا قمت بتحديد خيارات "-report" متعددة، فتأكد من عدم تعارضها. على سبيل المثال، ستقوم تقارير HTML المختلفة بالكتابة فوق نتائج بعضها البعض.

سيقوم خيار "-test" بحذف قواعد البيانات وتشغيل اختباراتك لإنشاء بيانات تغطية جديدة قبل إعداد تقرير عنها. Devel::Cover يعرف كيفية العمل مع ملفات Make القياسية لـ Perl بالإضافة إلى التوزيعات المستندة إلى Module::Build. للحصول على تعليمات مفصلة، انظر التوثيق الخاص بـ ExtUtils::MakeMaker على https://metacpan.org/module/ExtUtils::MakeMaker أو لـ Module::Build على https://metacpan.org/module/Module::Build وكلاهما يأتي بشكل قياسي في توزيعات Perl الحديثة.

سيحاول خيار "-gcov" تشغيل gcov على أي رمز XS. هذا يتطلب أنك تستخدم gcc بالطبع. إذا كنت تستخدم خيار "-test"، فسيتم تشغيله افتراضيًا. إذا كان لديك رمز XS في دلائل فرعية، فستحتاج على الأرجح إلى إضافة خيار "-gcov_chdir" نظرًا لأن gcov يبدو أنه يعمل بشكل أفضل مع ذلك.

يخبر خيار "-prefer_lib" Devel::Cover بإعداد تقرير عن الملفات الموجودة في دليل lib حتى لو تم استخدامها من دليل blib.

لن يقوم خيار "-ignore_covered_err" بتمييز خطأ إذا تم تغطية الكود غير القابل للتغطية.

حالة الخروج

القيم التالية للخروج يتم إرجاعها:

0 تم إكمال جميع العمليات بنجاح.

>0 حدث خطأ.

مع خيار -test، يتم إرجاع حالة الخروج لتشغيل الاختبار الأساسي.
