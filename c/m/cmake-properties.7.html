sections: - title: LINK_LIBRARY_OVERRIDE_ content: | Associated with <LIBRARY> from LINK_LIBRARY <#genex:LINK_LIBRARY> generator expressions. This can be used to resolve incompatible library features that result from specifying different features for <LIBRARY> in different LINK_LIBRARY <#genex:LINK_LIBRARY> generator expressions.

When set on a target, this property holds a single library feature name, which will be applied to <LIBRARY> when linking that target.

      add_library(lib1 ...)
      add_library(lib2 ...)
      add_library(lib3 ...)
      target_link_libraries(lib1 PUBLIC "<LINK_LIBRARY:feature1,external>")
      target_link_libraries(lib2 PUBLIC "<LINK_LIBRARY:feature2,lib1>")
      target_link_libraries(lib3 PRIVATE lib1 lib2)
      # lib1 is associated with both feature2 and no feature. Without any override,
      # this would result in a fatal error at generation time for lib3.
      # Define an override to resolve the incompatible feature associations.
      set_property(TARGET lib3 PROPERTY LINK_LIBRARY_OVERRIDE_lib1 feature2)
      # lib1 will now be associated with feature2 instead when linking lib3

It is also possible to override any feature with the pre-defined DEFAULT library feature. This effectively discards any feature for that link item, for that target only (lib3 in this example):

      # When linking lib3, discard any library feature for lib1
      set_property(TARGET lib3 PROPERTY LINK_LIBRARY_OVERRIDE_lib1 DEFAULT)

See the LINK_LIBRARY_OVERRIDE <#prop_tgt:LINK_LIBRARY_OVERRIDE> target property for an alternative way of overriding library features for multiple libraries at once. If both properties are defined and specify an override for the same link item, LINK_LIBRARY_OVERRIDE_<LIBRARY> takes precedence over LINK_LIBRARY_OVERRIDE <#prop_tgt:LINK_LIBRARY_OVERRIDE>.

Contents of LINK_LIBRARY_OVERRIDE_<LIBRARY> may use generator expressions <#manual:cmake-generator-expressions(7)>.

For more information about library features, see the CMAKE_<LANG>_LINK_LIBRARY_USING_<FEATURE> <#variable:CMAKE_<LANG>_LINK_LIBRARY_USING_<FEATURE>> and CMAKE_LINK_LIBRARY_USING_<FEATURE> <#variable:CMAKE_LINK_LIBRARY_USING_<FEATURE>> variables.

- title: LINK_OPTIONS content: |

Added in version 3.13.

List of options to use for the link step of shared library, module and executable targets as well as the device link step. Targets that are static libraries need to use the STATIC_LIBRARY_OPTIONS <#prop_tgt:STATIC_LIBRARY_OPTIONS> target property.

These options are used for both normal linking and device linking (see policy CMP0105 <#policy:CMP0105>). To control link options for normal and device link steps, $<HOST_LINK> <#genex:HOST_LINK> and $<DEVICE_LINK> <#genex:DEVICE_LINK> generator expressions can be used.

This property holds a semicolon-separated list <#cmake-language-lists> of options specified so far for its target. Use the target_link_options() <#command:target_link_options> command to append more options.

This property is initialized by the LINK_OPTIONS <#prop_dir:LINK_OPTIONS> directory property when a target is created, and is used by the generators to set the options for the compiler.

Contents of LINK_OPTIONS may use "generator expressions" with the syntax $<...>. See the cmake-generator-expressions(7) <#manual:cmake-generator-expressions(7)> manual for available expressions. See the cmake-buildsystem(7) <#manual:cmake-buildsystem(7)> manual for more on defining buildsystem properties.

Note:

This property must be used in preference to LINK_FLAGS <#prop_tgt:LINK_FLAGS> property.
- title: Host And Device Specific Link Options content: |

Added in version 3.18: When a device link step is involved, which is controlled by CUDA_SEPARABLE_COMPILATION <#prop_tgt:CUDA_SEPARABLE_COMPILATION> and CUDA_RESOLVE_DEVICE_SYMBOLS <#prop_tgt:CUDA_RESOLVE_DEVICE_SYMBOLS> properties and policy CMP0105 <#policy:CMP0105>, the raw options will be delivered to the host and device link steps (wrapped in -Xcompiler or equivalent for device link). Options wrapped with $<DEVICE_LINK:...> <#genex:DEVICE_LINK> generator expression will be used only for the device link step. Options wrapped with $<HOST_LINK:...> <#genex:HOST_LINK> generator expression will be used only for the host link step.

- title: Option De-duplication content: |

The final set of options used for a target is constructed by accumulating options from the current target and the usage requirements of its dependencies. The set of options is de-duplicated to avoid repetition.

Added in version 3.12: While beneficial for individual options, the de-duplication step can break up option groups. For example, -option A -option B becomes -option A B. One may specify a group of options using shell-like quoting along with a SHELL: prefix. The SHELL: prefix is dropped, and the rest of the option string is parsed using the separate_arguments() <#command:separate_arguments> UNIX_COMMAND mode. For example, "SHELL:-option A" "SHELL:-option B" becomes -option A -option B.

- title: Handling Compiler Driver Differences content: |

To pass options to the linker tool, each compiler driver has its own syntax. The LINKER: prefix and , separator can be used to specify, in a portable way, options to pass to the linker tool. LINKER: is replaced by the appropriate driver option and , by the appropriate driver separator. The driver prefix and driver separator are given by the values of the CMAKE_<LANG>_LINKER_WRAPPER_FLAG <#variable:CMAKE_<LANG>_LINKER_WRAPPER_FLAG> and CMAKE_<LANG>_LINKER_WRAPPER_FLAG_SEP <#variable:CMAKE_<LANG>_LINKER_WRAPPER_FLAG_SEP> variables.

For example, "LINKER:-z,defs" becomes -Xlinker -z -Xlinker defs for Clang and -Wl,-z,defs for GNU GCC.

The LINKER: prefix can be specified as part of a SHELL: prefix expression.

The LINKER: prefix supports, as an alternative syntax, specification of arguments using the SHELL: prefix and space as separator. The previous example then becomes "LINKER:SHELL:-z defs".

Note:

Specifying the SHELL: prefix anywhere other than at the beginning of the LINKER: prefix is not supported.
- title: LINK_SEARCH_END_STATIC content: |

End a link line such that static system libraries are used.

Some linkers support switches such as -Bstatic and -Bdynamic to determine whether to use static or shared libraries for -lXXX options. CMake uses these options to set the link type for libraries whose full paths are not known or (in some cases) are in implicit link directories for the platform. By default CMake adds an option at the end of the library list (if necessary) to set the linker search type back to its starting type. This property switches the final linker search type to -Bstatic regardless of how it started.

This property is initialized by the value of the variable CMAKE_LINK_SEARCH_END_STATIC <#variable:CMAKE_LINK_SEARCH_END_STATIC> if it is set when a target is created.

See also LINK_SEARCH_START_STATIC <#prop_tgt:LINK_SEARCH_START_STATIC>.

- title: LINK_SEARCH_START_STATIC content: |

Assume the linker looks for static libraries by default.

Some linkers support switches such as -Bstatic and -Bdynamic to determine whether to use static or shared libraries for -lXXX options. CMake uses these options to set the link type for libraries whose full paths are not known or (in some cases) are in implicit link directories for the platform. By default the linker search type is assumed to be -Bdynamic at the beginning of the library list. This property switches the assumption to -Bstatic. It is intended for use when linking an executable statically (e.g. with the GNU -static option).

This property is initialized by the value of the variable
CMAKE_LINK_SEARCH_START_STATIC <#variable:CMAKE_LINK_SEARCH_START_STATIC> if it is set when a target is created.

See also LINK_SEARCH_END_STATIC <#prop_tgt:LINK_SEARCH_END_STATIC>.

- title: LINK_WARNING_AS_ERROR content: |

Added in version 4.0.

Specify whether to treat warnings on link as errors. If enabled, adds a flag to treat warnings on link as errors. If the cmake --link-no-warning-as-error <#cmdoption-cmake-link-no-warning-as-error> option is given on the cmake(1) <#manual:cmake(1)> command line, this property is ignored.

This property takes a semicolon-separated-list <#cmake-language-lists> of the following values:

  • LINKER: treat the linker warnings as errors.
  • DRIVER: treat the compiler warnings as errors when used to drive the link step. See the COMPILE_WARNING_AS_ERROR <#prop_tgt:COMPILE_WARNING_AS_ERROR> target property for more information.

Moreover, for consistency with the COMPILE_WARNING_AS_ERROR <#prop_tgt:COMPILE_WARNING_AS_ERROR> target property, a boolean value can be specified:

  • True value: this is equivalent to LINKER and DRIVER values.
  • False value: deactivate this feature for the target.

This property is not implemented for all linkers. It is silently ignored if there is no implementation for the linker being used. The currently implemented compiler linker IDs <#variable:CMAKE_<LANG> IMPORTED_LOCATION <#prop_tgt:IMPORTED_LOCATION>).

إذا تم تعيين هذه الخاصية ولم تكن هناك تكوينات مطابقة متاحة، فسيتم اعتبار الهدف المستورد غير موجود. يتم تجاهل هذه الخاصية للأهداف غير المستوردة.

تتم تهيئة هذه الخاصية بقيمة المتغير CMAKE_MAP_IMPORTED_CONFIG_<CONFIG> <#variable:CMAKE_MAP_IMPORTED_CONFIG_<CONFIG>> إذا تم تعيينه عند إنشاء هدف.

مثال

على سبيل المثال، إنشاء مكتبة C++ مستوردة foo:

add_library(foo STATIC IMPORTED)

استخدم المسار foo_debug لنوع البناء Debug:

set_property(
  TARGET foo APPEND PROPERTY IMPORTED_CONFIGURATIONS DEBUG
  )
set_target_properties(foo PROPERTIES
  IMPORTED_LINK_INTERFACE_LANGUAGES_DEBUG "CXX"
  IMPORTED_LOCATION_DEBUG "${foo_debug}"
  )

استخدم المسار foo_release لنوع البناء Release:

set_property(
  TARGET foo APPEND PROPERTY IMPORTED_CONFIGURATIONS RELEASE
  )
set_target_properties(foo PROPERTIES
  IMPORTED_LINK_INTERFACE_LANGUAGES_RELEASE "CXX"
  IMPORTED_LOCATION_RELEASE "${foo_release}"
  )

استخدم إصدار Release من المكتبة لأنواع البناء MinSizeRel و RelWithDebInfo:

set_target_properties(foo PROPERTIES
  MAP_IMPORTED_CONFIG_MINSIZEREL Release
  MAP_IMPORTED_CONFIG_RELWITHDEBINFO Release
  )

MSVC_DEBUG_INFORMATION_FORMAT

تمت الإضافة في الإصدار 3.25.

حدد تنسيق معلومات التصحيح عند استهداف MSVC ABI.

القيم المسموح بها هي:

Embedded
قم بالترجمة باستخدام -Z7 أو علامة (علامات) مكافئة لإنتاج ملفات كائن بمعلومات تصحيح كاملة.
ProgramDatabase
قم بالترجمة باستخدام -Zi أو علامة (علامات) مكافئة لإنتاج قاعدة بيانات برنامج تحتوي على جميع معلومات التصحيح الرمزية.
EditAndContinue
قم بالترجمة باستخدام -ZI أو علامة (علامات) مكافئة لإنتاج قاعدة بيانات برنامج تدعم ميزة Edit and Continue.

يتم تجاهل القيمة على المترجمات التي لا تستهدف MSVC ABI، ولكن سيتم رفض قيمة غير مدعومة كخطأ عند استخدام مترجم يستهدف MSVC ABI.

قد تكون القيمة أيضًا سلسلة فارغة ("")، وفي هذه الحالة لن تتم إضافة علامة تنسيق معلومات التصحيح صراحةً بواسطة CMake.

استخدم تعبيرات المولد <#manual:cmake-generator-expressions(7)> لدعم التحديد لكل تكوين. على سبيل المثال، الرمز:

add_executable(foo foo.c)
set_property(TARGET foo PROPERTY
  MSVC_DEBUG_INFORMATION_FORMAT "$<$<CONFIG:Debug,RelWithDebInfo>:ProgramDatabase>")

يحدد للهدف foo تنسيق معلومات تصحيح قاعدة بيانات البرنامج لتكوينات Debug و RelWithDebInfo.

يتم تهيئة هذه الخاصية من قيمة المتغير CMAKE_MSVC_DEBUG_INFORMATION_FORMAT <#variable:CMAKE_MSVC_DEBUG_INFORMATION_FORMAT>، إذا تم تعيينه. إذا لم يتم تعيين هذه الخاصية، يختار CMake تنسيق معلومات التصحيح باستخدام القيمة الافتراضية $<$<CONFIG:Debug,RelWithDebInfo>:ProgramDatabase>، إذا كان مدعومًا من قبل المترجم، وإلا $<$<CONFIG:Debug,RelWithDebInfo>:Embedded>.

ملاحظة:

هذه الخاصية لها تأثير فقط عندما تكون السياسة CMP0141 <#policy:CMP0141> مضبوطة على NEW قبل الأمر project() <#command:project> أو enable_language() <#command:enable_language> الأول الذي يتيح لغة باستخدام مترجم يستهدف MSVC ABI.

MSVC_RUNTIME_CHECKS

تمت الإضافة في الإصدار 4.0.

حدد قائمة فحوصات وقت التشغيل الممكّنة عند استهداف MSVC ABI.

القيم المسموح بها هي:

PossibleDataLoss
قم بالترجمة باستخدام -RTCc أو علامة (علامات) مكافئة لتمكين فحوصات فقدان البيانات المحتمل.
StackFrameErrorCheck
قم بالترجمة باستخدام -RTCs أو علامة (علامات) مكافئة لتمكين فحوصات أخطاء إطار المكدس.
UninitializedVariable
قم بالترجمة باستخدام -RTCu أو علامة (علامات) مكافئة لتمكين فحوصات المتغيرات غير المهيأة.

يتم تجاهل القيمة على المترجمات التي لا تستهدف MSVC ABI، ولكن سيتم رفض قيمة غير مدعومة كخطأ عند استخدام مترجم يستهدف MSVC ABI.

قد تكون القيمة أيضًا سلسلة فارغة ("")، وفي هذه الحالة لن تتم إضافة علامات فحص أخطاء وقت التشغيل صراحةً بواسطة CMake.

استخدم تعبيرات المولد <#manual:cmake-generator-expressions(7)> لدعم التحديد لكل تكوين. على سبيل المثال، الرمز:

add_executable(foo foo.c)
set_property(TARGET foo PROPERTY
  MSVC_RUNTIME_CHECKS "$<$<CONFIG:Debug,RelWithDebInfo>:PossibleDataLoss;UninitializedVariable>")

يمكّن للهدف foo فحوصات فقدان البيانات المحتمل والمتغيرات غير المهيأة لتكوينات Debug و RelWithDebInfo.

يتم تهيئة هذه الخاصية من قيمة المتغير CMAKE_MSVC_RUNTIME_CHECKS <#variable:CMAKE_MSVC_RUNTIME_CHECKS>، إذا تم تعيينه. إذا لم يتم تعيين هذه الخاصية، يختار CMake فحوصات وقت التشغيل باستخدام القيمة الافتراضية $<$<CONFIG:Debug>:StackFrameErrorCheck;UninitializedVariable>، إذا كان مدعومًا من قبل المترجم، أو قيمة فارغة بخلاف ذلك.

ملاحظة:

هذه الخاصية لها تأثير فقط عندما تكون السياسة CMP0184 <#policy:CMP0184> مضبوطة على NEW قبل الأمر project() <#command:project> أو enable_language() <#command:enable_language> الأول الذي يتيح لغة باستخدام مترجم يستهدف MSVC ABI.

MSVC_RUNTIME_LIBRARY

تمت الإضافة في الإصدار 3.15.

حدد مكتبة وقت تشغيل MSVC للاستخدام بواسطة المترجمات التي تستهدف MSVC ABI.

القيم المسموح بها هي:

MultiThreaded
قم بالترجمة باستخدام -MT أو علامة (علامات) مكافئة لاستخدام مكتبة وقت تشغيل مرتبطة بشكل ثابت ومتعددة الخيوط.
MultiThreadedDLL
قم بالترجمة باستخدام -MD أو علامة (علامات) مكافئة لاستخدام مكتبة وقت تشغيل مرتبطة ديناميكيًا ومتعددة الخيوط.
MultiThreadedDebug
قم بالترجمة باستخدام -MTd أو علامة (علامات) مكافئة لاستخدام مكتبة وقت تشغيل مرتبطة بشكل ثابت ومتعددة الخيوط.
MultiThreadedDebugDLL
قم بالترجمة باستخدام -MDd أو علامة (علامات) مكافئة لاستخدام مكتبة وقت تشغيل مرتبطة ديناميكيًا ومتعددة الخيوط.

يتم تجاهل القيمة على المترجمات التي لا تستهدف MSVC ABI، ولكن سيتم رفض قيمة غير مدعومة كخطأ عند استخدام مترجم يستهدف MSVC ABI.

قد تكون القيمة أيضًا سلسلة فارغة ("") وفي هذه الحالة لن تتم إضافة علامة اختيار مكتبة وقت التشغيل صراحةً بواسطة CMake. لاحظ أنه مع مولدات Visual Studio <#visual-studio-generators> قد يختار نظام البناء الأصلي إضافة علامة اختيار مكتبة وقت التشغيل الافتراضية الخاصة به.

استخدم تعبيرات المولد <#manual:cmake-generator-expressions(7)> لدعم التحديد لكل تكوين. على سبيل المثال، الرمز:

add_executable(foo foo.c)
set_property(TARGET foo PROPERTY
  MSVC_RUNTIME_LIBRARY "MultiThreaded$<$<CONFIG:Debug>:Debug>")

يحدد للهدف foo مكتبة وقت تشغيل مرتبطة بشكل ثابت ومتعددة الخيوط مع أو بدون معلومات تصحيح اعتمادًا على التكوين.

يتم تهيئة الخاصية من قيمة المتغير CMAKE_MSVC_RUNTIME_LIBRARY <#variable:CMAKE_MSVC_RUNTIME_LIBRARY>، إذا تم تعيينه. إذا لم يتم تعيين الخاصية، فإن CMake يستخدم القيمة الافتراضية MultiThreaded$<$<CONFIG:Debug>:Debug>DLL لاختيار مكتبة وقت تشغيل MSVC.

ملاحظة:

هذه الخاصية لها تأثير فقط عندما تكون السياسة CMP0091 <#policy:CMP0091> مضبوطة على NEW قبل الأمر project() <#command:project> أو enable_language() <#command:enable_language> الأول الذي يتيح لغة باستخدام مترجم يستهدف MSVC ABI.

NAME

اسم منطقي للهدف.

اسم منطقي للقراءة فقط للهدف كما يستخدمه CMake.

NO_SONAME

ما إذا كان سيتم تعيين soname عند ربط مكتبة مشتركة.

قم بتمكين هذه الخاصية المنطقية إذا كان ينبغي لمكتبة SHARED التي تم إنشاؤها ألا يتم تعيين soname لها. الافتراضي هو تعيين soname لجميع المكتبات المشتركة طالما أن المنصة تدعم ذلك. بشكل عام، استخدم هذه الخاصية فقط للمكتبات الخاصة الطرفية أو المكونات الإضافية. إذا كنت تستخدمها على المكتبات المشتركة العادية التي ترتبط بها أهداف أخرى، فقد يقوم الرابط على بعض الأنظمة بإدراج مسار كامل للمكتبة (كما هو محدد في وقت الربط) في القسم الديناميكي للثنائي التابع. لذلك، بمجرد التثبيت، قد يفشل المحمل الديناميكي في تحديد موقع المكتبة للثنائي.

NO_SYSTEM_FR

OM_IMPORTED

لا تعامل مجلدات التضمين من واجهات الأهداف المستوردة المستهلكة <#imported-targets> كمجلدات نظام.

عندما تكون خاصية SYSTEM <#prop_tgt:SYSTEM> للهدف المستهلك مضبوطة على صحيح، يتم التعامل مع محتويات خاصية الهدف INTERFACE_INCLUDE_DIRECTORIES <#prop_tgt:INTERFACE_INCLUDE_DIRECTORIES> على أنها تضمينات نظام، أو على منصات Apple، عندما يكون الهدف إطارًا، فسيتم التعامل معه على أنه نظام. افتراضيًا، SYSTEM <#prop_tgt:SYSTEM> صحيح للأهداف المستوردة وخاطئ لأنواع الأهداف الأخرى. إذا تم ضبط خاصية NO_SYSTEM_FROM_IMPORTED على صحيح على هدف مستهلك، فلن تعامل ترجمة المصادر في هذا الهدف المستهلك محتويات INTERFACE_INCLUDE_DIRECTORIES <#prop_tgt:INTERFACE_INCLUDE_DIRECTORIES> للأهداف المستوردة المستهلكة كتضمينات نظام، حتى لو كانت خاصية SYSTEM <#prop_tgt:SYSTEM> لهذا الهدف المستورد خاطئة.

لا تتأثر المجلدات المدرجة في خاصية INTERFACE_SYSTEM_INCLUDE_DIRECTORIES <#prop_tgt:INTERFACE_SYSTEM_INCLUDE_DIRECTORIES> للأهداف المستهلكة بـ NO_SYSTEM_FROM_IMPORTED. ستُعامل هذه المجلدات دائمًا كتضمينات نظام من قبل المستهلكين.

يتم تهيئة هذه الخاصية بقيمة المتغير CMAKE_NO_SYSTEM_FROM_IMPORTED <#variable:CMAKE_NO_SYSTEM_FROM_IMPORTED> إذا تم تعيينه عند إنشاء هدف.

انظر خاصية الهدف EXPORT_NO_SYSTEM <#prop_tgt:EXPORT_NO_SYSTEM> لتعيين هذا السلوك على الهدف الذي يوفر مجلدات التضمين بدلاً من الهدف الذي يستهلكها.

OBJC_EXTENSIONS

تمت الإضافة في الإصدار 3.16.

قيمة منطقية تحدد ما إذا كانت امتدادات لغة Objective-C محددة للمترجم مطلوبة.

تحدد هذه الخاصية ما إذا كان يجب استخدام امتدادات مترجم محددة. بالنسبة لبعض المترجمات، يؤدي هذا إلى إضافة علامة مثل -std=gnu11 بدلاً من -std=c11 إلى سطر الترجمة. هذه الخاصية مضبوطة على ON افتراضيًا. يتم التحكم في مستوى معيار OBJC الأساسي بواسطة خاصية الهدف OBJC_STANDARD <#prop_tgt:OBJC_STANDARD>.

إذا لم يتم تعيين الخاصية، وقام المشروع بتعيين C_EXTENSIONS <#prop_tgt:C_EXTENSIONS>، فسيتم تعيين قيمة C_EXTENSIONS <#prop_tgt:C_EXTENSIONS> لـ OBJC_EXTENSIONS.

انظر دليل cmake-compile-features(7) <#manual:cmake-compile-features(7)> للحصول على معلومات حول ميزات الترجمة وقائمة المترجمات المدعومة.

يتم تهيئة هذه الخاصية بقيمة المتغير CMAKE_OBJC_EXTENSIONS <#variable:CMAKE_OBJC_EXTENSIONS> إذا تم تعيينها عند إنشاء هدف، وبخلاف ذلك بقيمة CMAKE_OBJC_EXTENSIONS_DEFAULT <#variable:CMAKE_<LANG>_EXTENSIONS_DEFAULT> (انظر CMP0128 <#policy:CMP0128>).

POSITION_INDEPENDENT_CODE

خاصية هدف تحدد ما إذا كان سيتم إنشاء هدف تم تمكين رمز مستقل عن الموضع له.

خاصية الهدف POSITION_INDEPENDENT_CODE تحدد ما إذا كان سيتم إنشاء ملفات تنفيذية أو مكتبات مستقلة عن الموضع. هذه الخاصية هي True بشكل افتراضي لأهداف المكتبات المشتركة (SHARED) و الوحدات (MODULE). بالنسبة للأهداف الأخرى، يتم تهيئة هذه الخاصية بقيمة المتغير CMAKE_POSITION_INDEPENDENT_CODE <#variable:CMAKE_POSITION_INDEPENDENT_CODE> إذا تم تعيينها عند إنشاء الهدف، أو False بخلاف ذلك.

ملاحظة:

بالنسبة لأهداف الملفات التنفيذية، يتم التحكم في خطوة الربط بواسطة السياسة CMP0083 <#policy:CMP0083> ووحدة CheckPIESupported <#module:CheckPIESupported>.

يشير الرمز المستقل عن الموضع (PIC) إلى رمز الآلة الذي يتم تنفيذه بشكل صحيح بغض النظر عن عنوان الذاكرة المطلق الخاص به. هذا مهم بشكل خاص للمكتبات المشتركة، والتي غالبًا ما يتم تحميلها في عناوين ذاكرة مختلفة بواسطة برامج مختلفة. يضمن إنشاء الرمز المستقل عن الموضع أنه يمكن مشاركة هذه المكتبات بأمان وكفاءة بين عمليات متعددة دون التسبب في تعارضات في العناوين. على بعض المنصات (خاصة أنظمة UNIX)، يعد إنشاء PIC أيضًا مطلبًا لإنشاء مكتبات مشتركة.

يوصى باستخدام الرمز المستقل عن الموضع أو يتطلب في الحالات التالية:

  • عند بناء مكتبات مشتركة أو وحدات (مثل، باستخدام add_library(... SHARED)، أو add_library(... MODULE))، حيث يسمح PIC بإعادة التوطين الديناميكي في وقت التشغيل.
  • عند بناء ملفات تنفيذية كملفات تنفيذية مستقلة عن الموضع (PIE)، والتي يمكن أن تعزز الأمان من خلال تمكين عشوائية تخطيط مساحة العنوان (ASLR).
  • على المنصات أو سلاسل الأدوات التي تتطلب PIC لأنواع معينة من الربط أو البيئات المعزولة.

يمكن أن يؤدي تمكين PIC إلى رمز أكبر قليلاً أو أبطأ على بعض البنى، ولكن هذا غالبًا ما تفوقه فوائد المرونة والأمان.

أمثلة

تمكين PIC لهدف مكتبة ثابتة:

add_library(foo STATIC foo.c)
set_target_properties(foo PROPERTIES POSITION_INDEPENDENT_CODE TRUE)

تمكين PIC لهدف ملف تنفيذي:

add_executable(app app.c)
set_target_properties(app PROPERTIES POSITION_INDEPENDENT_CODE TRUE)
# بالإضافة إلى ذلك، قم بتمرير خيارات ربط وقت التشغيل المتعلقة بـ PIE إلى الملف التنفيذي (الملفات التنفيذية).
include(CheckPIESupported)
check_pie_supported()

RESOURCE

تحديد ملفات الموارد في FRAMEWORK <#prop_tgt:FRAMEWORK> أو BUNDLE <#prop_tgt:BUNDLE>.

الهدف المميز بخاصية FRAMEWORK <#prop_tgt:FRAMEWORK> أو BUNDLE <#prop_tgt:BUNDLE> ينشئ إطار عمل أو حزمة تطبيق (مدعوم بكل من macOS و iOS) أو مكتبات مشتركة عادية على المنصات الأخرى. يمكن تعيين هذه الخاصية لقائمة من الملفات ليتم وضعها في الدليل المقابل (على سبيل المثال، دليل Resources لنظام macOS) داخل الحزمة. على المنصات غير Apple، يمكن تثبيت هذه الملفات باستخدام خيار RESOURCE للأمر install(TARGETS) <#targets>.

مثال على حزمة التطبيق التالية:

add_executable(ExecutableTarget
  addDemo.c
  resourcefile.txt
  appresourcedir/appres.txt)
target_link_libraries(ExecutableTarget heymath mul)
set(RESOURCE_FILES
  resourcefile.txt
  appresourcedir/appres.txt)
set_target_properties(ExecutableTarget PROPERTIES
  MACOSX_BUNDLE TRUE
  MACOSX_FRAMEWORK_IDENTIFIER org.cmake.ExecutableTarget
  RESOURCE "${RESOURCE_FILES}")

  ExecutableTarget
  Info.plist
  resourcefile.txt

بالنسبة لأنظمة macOS، سينتج الهيكل التالي للدليل:

  Contents
