CURLOPT_HTTP_VERSION(3)

الحزمة: curl

التراخيص: MIT

CURLOPT_HTTP_VERSION(3) دليل وظائف المكتبة CURLOPT_HTTP_VERSION(3)

الاسم

CURLOPT_HTTP_VERSION - إصدار بروتوكول HTTP المراد استخدامه

الملخص

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_HTTP_VERSION, long version);

الوصف

مرر version كـ long، معينًا لأحد القيم الموضحة أدناه. تطلب هذه القيم من libcurl استخدام إصدارات HTTP المحددة.

لاحظ أن إصدار HTTP هو مجرد طلب. لا تزال libcurl تعطي الأولوية لإعادة استخدام الاتصالات الموجودة، لذلك قد تعيد استخدام اتصال يستخدم إصدار HTTP لم تطلبه.

CURL_HTTP_VERSION_NONE
لا نهتم بإصدار المكتبة المستخدم. تستخدم libcurl ما تراه مناسبًا.
CURL_HTTP_VERSION_1_0
فرض طلبات HTTP 1.0.
CURL_HTTP_VERSION_1_1
فرض طلبات HTTP 1.1.
CURL_HTTP_VERSION_2_0
محاولة طلبات HTTP 2. تتراجع libcurl إلى HTTP 1.1 إذا لم يكن بالإمكان التفاوض على HTTP/2 مع الخادم.

عندما تستخدم libcurl HTTP/2 عبر HTTPS، فإنها لا تصر بنفسها على TLS 1.2 أو أعلى على الرغم من أن ذلك مطلوب بموجب المواصفات. يمكن للمستخدم إضافة هذا المطلب للإصدار باستخدام CURLOPT_SSLVERSION(3).

تمت إضافة الاسم البديل CURL_HTTP_VERSION_2 ليعكس بشكل أفضل اسم البروتوكول الفعلي.

CURL_HTTP_VERSION_2TLS
محاولة HTTP/2 عبر TLS (HTTPS) فقط. تتراجع libcurl إلى HTTP 1.1 إذا لم يكن بالإمكان التفاوض على HTTP/2 مع خادم HTTPS. بالنسبة لخوادم HTTP النصية العادية، تستخدم libcurl 1.1.
CURL_HTTP_VERSION_2_PRIOR_KNOWLEDGE
إصدار طلبات HTTP غير TLS باستخدام HTTP/2 بدون ترقية HTTP/1.1. يتطلب معرفة مسبقة بأن الخادم يدعم HTTP/2 مباشرة. لا تزال طلبات HTTPS تتم بطريقة HTTP/2 القياسية مع إصدار البروتوكول المتفاوض عليه في مصافحة TLS.

منذ الإصدار 8.10.0، إذا تم تعيين هذا الخيار لطلب HTTPS، فإن إصدار بروتوكول طبقة التطبيق (ALPN) المعروض على الخادم هو HTTP/2 فقط. قبل ذلك، تم عرض كل من HTTP/1.1 و HTTP/2.

CURL_HTTP_VERSION_3
(تمت إضافته في 7.66.0) يطلب هذا الخيار من libcurl محاولة استخدام HTTP/3 إلى المضيف المحدد في عنوان URL، مع التراجع إلى إصدارات HTTP السابقة إذا لزم الأمر.
CURL_HTTP_VERSION_3ONLY
(تمت إضافته في 7.88.0) يؤدي تعيين هذا إلى جعل libcurl تحاول استخدام HTTP/3 مباشرة إلى الخادم المحدد في عنوان URL ولا تتراجع إلى إصدار HTTP سابق إذا لم يدعم الخادم HTTP/3.

الافتراضي

منذ curl 8.13.0: CURL_HTTP_VERSION_NONE

منذ curl 7.62.0: CURL_HTTP_VERSION_2TLS

قبل ذلك: CURL_HTTP_VERSION_1_1

البروتوكولات

تؤثر هذه الوظيفة على http فقط

مثال

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    CURLcode ret;
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com/");
    curl_easy_setopt(curl, CURLOPT_HTTP_VERSION, CURL_HTTP_VERSION_2TLS);
    ret = curl_easy_perform(curl);
    if(ret == CURLE_HTTP_RETURNED_ERROR) {
      /* an HTTP response error problem */
    }
  }
}

التاريخ

أصبحت تعدادات CURL_HTTP_VERSION_* من النوع long في الإصدار 8.13.0، قبل هذا الإصدار كان تحويل long ضروريًا عند تمريره إلى curl_easy_setopt(3).

التوفر

تمت الإضافة في curl 7.9.1

قيمة الإرجاع

curl_easy_setopt(3) تعيد CURLcode يشير إلى النجاح أو الخطأ.

CURLE_OK (0) يعني أن كل شيء كان على ما يرام، وأي قيمة غير صفرية تعني حدوث خطأ، انظر libcurl-errors(3).
