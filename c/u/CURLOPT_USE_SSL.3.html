CURLOPT_USE_SSL(3)

الحزمة: curl

التراخيص: MIT

CURLOPT_USE_SSL(3) دليل وظائف المكتبة CURLOPT_USE_SSL(3)

الاسم

CURLOPT_USE_SSL - طلب استخدام SSL / TLS للنقل

الملخص

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_USE_SSL, long level);

الوصف

مرر قيمة طويلة باستخدام إحدى القيم أدناه، لجعل مكتبة curl تستخدم مستوى SSL الذي تريده للنقل.

هذه لجميع البروتوكولات التي تبدأ كنص عادي ويتم "ترقيتها" إلى SSL باستخدام أمر STARTTLS.

هذا لتمكين SSL/TLS عند استخدام FTP، SMTP، POP3، IMAP إلخ.

CURLUSESSL_NONE
لا تحاول استخدام SSL.
CURLUSESSL_TRY
حاول استخدام SSL، واستمر كالمعتاد بخلاف ذلك. لاحظ أن الخادم قد يغلق الاتصال إذا لم تنجح المفاوضات.
CURLUSESSL_CONTROL
تطلب SSL لاتصال التحكم أو تفشل مع CURLE_USE_SSL_FAILED.
CURLUSESSL_ALL
تطلب SSL لجميع الاتصالات أو تفشل مع CURLE_USE_SSL_FAILED.

الافتراضي

CURLUSESSL_NONE

البروتوكولات

تؤثر هذه الوظيفة على ftp، imap، pop3 و smtp

مثال

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    curl_easy_setopt(curl, CURLOPT_URL, "ftp://example.com/dir/file.ext");
    /* تطلب استخدام SSL لهذا، أو تفشل */
    curl_easy_setopt(curl, CURLOPT_USE_SSL, CURLUSESSL_ALL);
    /* قم بتنفيذ الطلب */
    curl_easy_perform(curl);
  }
}

التاريخ

كان هذا الخيار يُعرف باسم CURLOPT_FTP_SSL حتى الإصدار 7.16.4. مدعوم من LDAP منذ الإصدار 7.81.0. مدعوم بالكامل من قبل واجهة LDAP الخلفية فقط.

أصبحت الثوابت CURLUSESSL_* أنواع long في الإصدار 8.13.0، قبل هذا الإصدار كان تحويل long ضروريًا عند تمريره إلى curl_easy_setopt(3).

التوفر

تمت الإضافة في curl 7.17.0

قيمة الإرجاع

curl_easy_setopt(3) ترجع CURLcode يشير إلى النجاح أو الخطأ.

CURLE_OK (0) يعني أن كل شيء كان على ما يرام، أي قيمة غير صفرية تعني حدوث خطأ، انظر libcurl-errors(3).

انظر أيضًا
