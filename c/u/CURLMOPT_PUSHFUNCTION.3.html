CURLMOPT_PUSHFUNCTION(3)

الحزمة: curl

التراخيص: MIT

CURLMOPT_PUSHFUNCTION(3) دليل وظائف المكتبة CURLMOPT_PUSHFUNCTION(3)

الاسم

CURLMOPT_PUSHFUNCTION - وظيفة استدعاء توافق أو ترفض عمليات الدفع من الخادم

الملخص

#include <curl/curl.h>
int curl_push_callback(CURL *parent,
                       CURL *easy,
                       size_t num_headers,
                       struct curl_pushheaders *headers,
                       void *clientp);
CURLMcode curl_multi_setopt(CURLM *handle, CURLMOPT_PUSHFUNCTION,
                            curl_push_callback func);

الوصف

يتم استدعاء وظيفة الاستدعاء هذه عند دفع مجرى HTTP/2 جديد بواسطة الخادم (باستخدام إطار PUSH_PROMISE). إذا لم يتم تعيين وظيفة استدعاء دفع، فسيتم رفض جميع عمليات الدفع المعروضة تلقائيًا.

وصف وظيفة الاستدعاء

تتلقى وظيفة الاستدعاء وسائطها بهذه الطريقة:

parent هو المقبض الخاص بالمجرى الذي يصل إليه هذا الدفع. تم نسخ المقبض الجديد من المقبض الأصل (parent)، مما يعني أنه ورث جميع خياراته. الأمر متروك للتطبيق لتعديل أي خيارات إذا رغب في ذلك.

easy هو مقبض تم إنشاؤه حديثًا ويمثل عملية النقل القادمة هذه.

num_headers هو عدد أزواج الاسم + القيمة التي تم تلقيها ويمكن الوصول إليها

headers هو مقبض يستخدم للوصول إلى رؤوس الدفع باستخدام وظائف الوصول الموصوفة أدناه. هذا يصل فقط إلى رؤوس PUSH_PROMISE ويوفرها، ويتم توفير رؤوس الاستجابة العادية في وظيفة استدعاء الرأس (header callback) كما هو معتاد.

clientp هو المؤشر الذي تم تعيينه باستخدام CURLMOPT_PUSHDATA(3)

إذا أعادت وظيفة الاستدعاء CURL_PUSH_OK، فسيتم إضافة المقبض السهل (easy handle) الجديد إلى المقبض المتعدد (multi handle)، ويجب ألا تقوم وظيفة الاستدعاء بذلك بنفسها.

يمكن لوظيفة الاستدعاء الوصول إلى رؤوس PUSH_PROMISE باستخدام وظيفتي وصول. لا يمكن استخدام هاتين الوظيفتين إلا من داخل وظيفة الاستدعاء هذه ولا يمكنهما الوصول إلا إلى رؤوس PUSH_PROMISE: curl_pushheader_byname(3) و curl_pushheader_bynum(3). يتم تمرير رؤوس الاستجابة العادية إلى وظيفة استدعاء الرأس (header callback) للمجاري المدفوعة تمامًا كما هو الحال للمجاري العادية.

يمكن أيضًا الوصول إلى حقول الرأس باستخدام curl_easy_header(3)، الذي تم تقديمه في إصدارات libcurl اللاحقة.

قيمة إرجاع وظيفة الاستدعاء

CURL_PUSH_OK (0)
قبل التطبيق المجرى ويمكنه الآن البدء في تلقي البيانات، وقد تولى التطبيق ملكية مقبض curl.
CURL_PUSH_DENY (1)
ترفض وظيفة الاستدعاء المجرى ولا تصل أي بيانات إلى التطبيق، ويتم تدمير المقبض السهل (easy handle) بواسطة libcurl.
CURL_PUSH_ERROROUT (2)
إرجاع هذا الرمز يرفض المجرى المدفوع ويعيد خطأ إلى المجرى الأصل مما يؤدي إلى إغلاقه بخطأ. (تمت إضافته في 7.72.0)
*
جميع رموز الإرجاع الأخرى محفوظة للاستخدام المستقبلي.

الافتراضي

NULL، لا توجد وظيفة استدعاء

البروتوكولات

تؤثر هذه الوظيفة على http فقط

مثال

#include <string.h>
/* السماح فقط بعمليات الدفع لأسماء الملفات التي تبدأ بـ "push-" */
int push_callback(CURL *parent,
                  CURL *easy,
                  size_t num_headers,
                  struct curl_pushheaders *headers,
                  void *clientp)
{
  char *headp;
  int *transfers = (int *)clientp;
  FILE *out;
  headp = curl_pushheader_byname(headers, ":path");
  if(headp && !strncmp(headp, "/push-", 6)) {
    fprintf(stderr, "المسار هو %s\n", headp);
    /* حفظ الدفع هنا */
    out = fopen("pushed-stream", "wb");
    /* الكتابة إلى هذا الملف */
    curl_easy_setopt(easy, CURLOPT_WRITEDATA, out);
    (*transfers)++; /* واحد آخر */
    return CURL_PUSH_OK;
  }
  return CURL_PUSH_DENY;
}
int main(void)
{
  int counter;
  CURLM *multi = curl_multi_init();
  curl_multi_setopt(multi, CURLMOPT_PUSHFUNCTION, push_callback);
  curl_multi_setopt(multi, CURLMOPT_PUSHDATA, &counter);
}

التوفر

تمت الإضافة في curl 7.44.0

قيمة الإرجاع

curl_multi_setopt(3) تعيد قيمة CURLMcode تشير إلى النجاح أو الخطأ.

CURLM_OK (0) تعني أن كل شيء كان على ما يرام، القيمة غير الصفرية تعني حدوث خطأ، انظر libcurl-errors(3).
