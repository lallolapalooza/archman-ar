CURLOPT_HEADERFUNCTION(3)

الحزمة: curl

التراخيص: MIT

CURLOPT_HEADERFUNCTION(3) دليل وظائف المكتبة CURLOPT_HEADERFUNCTION(3)

اسم

CURLOPT_HEADERFUNCTION - دالة رد اتصال تستقبل بيانات الرأس

الملخص

#include <curl/curl.h>
size_t header_callback(char *buffer,
                       size_t size,
                       size_t nitems,
                       void *userdata);
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_HEADERFUNCTION,
                          header_callback);

الوصف

مرر مؤشرًا إلى دالة رد الاتصال الخاصة بك، والتي يجب أن تتطابق مع النموذج الأولي المعروض أعلاه.

يتم استدعاء دالة رد الاتصال هذه بواسطة libcurl بمجرد استلامها لبيانات الرأس. يتم استدعاء رد اتصال الرأس مرة واحدة لكل رأس ويتم تمرير أسطر الرأس الكاملة فقط إلى دالة رد الاتصال. يمكن تحليل الرؤوس بسهولة باستخدام دالة رد الاتصال هذه. يشير buffer إلى البيانات المستلمة، وحجم هذه البيانات هو nitems؛ size هو دائمًا 1. سطر الرأس المقدم غير منتهٍ بـ null. لا تقم بتعديل المخزن المؤقت الذي تم تمريره.

المؤشر المسمى userdata هو الذي قمت بتعيينه باستخدام خيار CURLOPT_HEADERDATA(3).

يجب أن تعيد دالة رد الاتصال الخاصة بك عدد البايتات التي تم التعامل معها بالفعل. إذا اختلف هذا المقدار عن المقدار الذي تم تمريره إلى دالة رد الاتصال الخاصة بك، فإنه يشير إلى حالة خطأ للمكتبة. هذا يؤدي إلى إلغاء النقل وتعيد الدالة libcurl المستخدمة CURLE_WRITE_ERROR.

يمكنك أيضًا إلغاء النقل عن طريق إرجاع CURL_WRITEFUNC_ERROR. (7.87.0)

يمكن أن يصل رأس HTTP كامل يتم تمريره إلى هذه الدالة إلى CURL_MAX_HTTP_HEADER (100K) بايت ويتضمن محدد السطر النهائي.

إذا لم يتم تعيين هذا الخيار، أو إذا تم تعيينه على NULL، ولكن تم تعيين CURLOPT_HEADERDATA(3) على أي شيء بخلاف NULL، فسيتم استخدام الدالة المستخدمة لقبول بيانات الاستجابة بدلاً من ذلك. هذه هي الدالة المحددة باستخدام CURLOPT_WRITEFUNCTION(3)، أو إذا لم يتم تحديدها أو كانت NULL - الدالة الافتراضية لكتابة التدفق.

من المهم ملاحظة أنه يتم استدعاء دالة رد الاتصال لرؤوس جميع الاستجابات المستلمة بعد بدء طلب وليس فقط للاستجابة النهائية. هذا يشمل جميع الاستجابات التي تحدث أثناء التفاوض على المصادقة. إذا كنت بحاجة إلى العمل فقط مع رؤوس الاستجابة النهائية، فأنت بحاجة إلى جمع الرؤوس في دالة رد الاتصال بنفسك واستخدام أسطر حالة HTTP، على سبيل المثال، لتحديد حدود الاستجابة.

بالنسبة لنقل HTTP، يتم تضمين سطر الحالة والسطر الفارغ الذي يسبق جسم الاستجابة كرؤوس ويتم تمريرهما إلى هذه الدالة.

عندما يرسل الخادم نقلًا مشفرًا بالقطع، فقد يحتوي على ذيل. هذا الذيل مطابق لرأس HTTP وإذا تم استلام مثل هذا الذيل، فسيتم تمريره إلى التطبيق باستخدام دالة رد الاتصال هذه أيضًا. هناك عدة طرق للكشف عن أنه ذيل وليس رأسًا عاديًا: 1) يأتي بعد جسم الاستجابة. 2) يأتي بعد سطر الرأس النهائي (CR LF) 3) يشير رأس Trailer: ضمن رؤوس الاستجابة العادية إلى ما هو رأس (رؤوس) يجب توقعه في الذيل.

بالنسبة لبروتوكولات غير HTTP مثل FTP و POP3 و IMAP و SMTP، يتم استدعاء هذه الدالة مع استجابات الخادم للأوامر التي ترسلها libcurl.

قد تكون الطريقة الأكثر ملاءمة للحصول على رؤوس HTTP هي استخدام curl_easy_header(3).

القيود

لا تقوم libcurl بفك طي "رؤوس مطوية" HTTP (تم إهمالها منذ RFC 7230). الرأس المطوي هو رأس يستمر في سطر لاحق ويبدأ بمسافة بيضاء. يتم تمرير مثل هذه الطيات إلى دالة رد اتصال الرأس بشكل منفصل، على الرغم من أنها مجرد استمرارات للأسطر السابقة من الناحية الفنية.

الافتراضي

لا شيء.

البروتوكولات

تؤثر هذه الوظيفة على ftp، http، imap، pop3 و smtp

مثال

static size_t header_callback(char *buffer, size_t size,
                              size_t nitems, void *userdata)
{
  /* تم استلام الرأس 'nitems' بايت في 'buffer' غير منتهٍ بـ NULL */
  /* تم تعيين 'userdata' باستخدام CURLOPT_HEADERDATA */
  return nitems;
}
int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com");
    curl_easy_setopt(curl, CURLOPT_HEADERFUNCTION, header_callback);
    curl_easy_perform(curl);
  }
}
