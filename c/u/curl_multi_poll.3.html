curl_multi_poll(3)

الحزمة: curl

التراخيص: MIT

curl_multi_poll(3) دليل وظائف المكتبة curl_multi_poll(3)

الاسم

curl_multi_poll - الاستطلاع على جميع مقابض easy في مقبض multi

الملخص

#include <curl/curl.h>
CURLMcode curl_multi_poll(CURLM *multi_handle,
                          struct curl_waitfd extra_fds[],
                          unsigned int extra_nfds,
                          int timeout_ms,
                          int *numfds);

الوصف

curl_multi_poll(3) يستطلع جميع واصفات الملفات المستخدمة بواسطة مقابض curl easy الموجودة في مجموعة المقابض المتعددة المعطاة. يتوقف حتى يتم اكتشاف نشاط على واصف واحد على الأقل من المقابض أو مرور timeout_ms. بدلاً من ذلك، إذا كان المقبض المتعدد لديه مؤقت داخلي معلق له وقت انتهاء صلاحية أقصر من timeout_ms، فسيتم استخدام هذا الوقت الأقصر بدلاً من ذلك لضمان دقة المؤقت بشكل معقول.

قد يقوم التطبيق المتصل بتمرير هياكل curl_waitfd إضافية مشابهة لهيكل pollfd الخاص بـ poll(2) ليتم الانتظار عليها في نفس الاستدعاء.

عند الانتهاء، إذا كان numfds غير NULL، فسيتم ملؤه بالعدد الإجمالي لواصفات الملفات التي حدثت عليها أحداث مثيرة للاهتمام. يمكن أن يشمل هذا العدد واصفات libcurl الداخلية بالإضافة إلى الواصفات المقدمة في extra_fds.

يمكن استخدام وظيفة curl_multi_wakeup(3) من خيط آخر لإيقاظ هذه الوظيفة والعودة بشكل أسرع. هذه إحدى التفاصيل التي تجعل هذه الوظيفة مختلفة عن curl_multi_wait(3) التي لا يمكن إيقاظها بهذه الطريقة.

إذا لم يتم توفير واصفات ملفات إضافية ولم يكن لدى libcurl واصف ملف لتقديمه للانتظار عليه، فإن هذه الوظيفة تنتظر بدلاً من ذلك خلال timeout_ms مللي ثانية (أو أقل إذا أشار مؤقت داخلي إلى ذلك). هذه تفصيلة أخرى تجعل هذه الوظيفة مختلفة عن curl_multi_wait(3).

يُشجع على استخدام هذه الوظيفة بدلاً من select(3) عند استخدام الواجهة المتعددة للسماح للتطبيقات بتجاوز مشكلة الحد الأقصى لـ 1024 واصف ملف بسهولة.

curl_waitfd

struct curl_waitfd {
  curl_socket_t fd;
  short events;
  short revents;
};
CURL_WAIT_POLLIN
علم بت (bit flag) لـ curl_waitfd.events يشير إلى أن المقبس يجب أن يستطلع أحداث القراءة مثل البيانات الجديدة المستلمة.
CURL_WAIT_POLLPRI
علم بت (bit flag) لـ curl_waitfd.events يشير إلى أن المقبس يجب أن يستطلع أحداث القراءة ذات الأولوية العالية مثل البيانات خارج النطاق.
CURL_WAIT_POLLOUT
علم بت (bit flag) لـ curl_waitfd.events يشير إلى أن المقبس يجب أن يستطلع أحداث الكتابة مثل أن المقبس جاهز للكتابة دون حظر.

البروتوكولات

تؤثر هذه الوظيفة على جميع البروتوكولات المدعومة

مثال

extern void handle_fd(int);
int main(void)
{
  CURL *easy_handle;
  CURLM *multi_handle;
  int still_running = 0;
  int myfd = 2; /* هذا هو واصف الملف الخاص بنا */
  multi_handle = curl_multi_init();
  easy_handle = curl_easy_init();
  /* إضافة واصف easy الفردي */
  curl_multi_add_handle(multi_handle, easy_handle);
  do {
    CURLMcode mc;
    int numfds;
    mc = curl_multi_perform(multi_handle, &still_running);
    if(mc == CURLM_OK) {
      struct curl_waitfd myown;
      myown.fd = myfd;
      myown.events = CURL_WAIT_POLLIN; /* انتظار الإدخال */
      myown.revents = 0; /* مسحها */
      /* الانتظار على نشاط واصفات curl أو على واصفنا الخاص،
         أو انتهاء المهلة */
      mc = curl_multi_poll(multi_handle, &myown, 1, 1000, &numfds);
      if(myown.revents) {
        /* هل تلقى واصفنا حدثًا؟ */
        handle_fd(myfd);
      }
    }
    if(mc != CURLM_OK) {
      fprintf(stderr, "curl_multi failed, code %d.\n", mc);
      break;
    }
  } while(still_running);
  curl_multi_remove_handle(multi_handle, easy_handle);
}

التوفر

تمت الإضافة في curl 7.66.0

قيمة الإرجاع

ترجع هذه الوظيفة قيمة CURLMcode تشير إلى النجاح أو الخطأ.

CURLM_OK (0) يعني أن كل شيء كان على ما يرام، والقيمة غير الصفرية تشير إلى حدوث خطأ، انظر libcurl-errors(3).
