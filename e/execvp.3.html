NAME

execvp, execvpe — execute program

LIBRARY

Standard C library (libc, -lc)

SYNOPSIS

Link with -lutil for execvpe(3).

#include <unistd.h>
int execvp(const char *file, char *const argv[]);
int execvpe(const char *file, char *const argv[], char *const envp[]);

DESCRIPTION

The exec family of functions replaces the current process image with a new process image.

The new process image is created by loading a program into the current address space and then executing that program from the beginning. Control cannot be returned to the calling process. Because the calling process image is overwritten, any error handling or cleanup in the calling process (e.g., critical sections guarded by mutexes) is not performed.

The list of arguments is passed to the new process image. The argument list must be terminated by a NULL pointer. The first argument in the array, by convention, should point to the filename associated with the file being executed.

The execvp() function constructs a list of arguments and environment variables for the new process image. The file argument is a name relative to some set of directories. execvp() searches the path, which is the list of directories searched when a command is found in the shell. The directories are searched in the order that they appear in the PATH environment variable. If file contains a slash character (`/`), then file is assumed to be a path relative to the current working directory or an absolute path. The algorithm used is similar to that used by sh(1) for finding commands. Note that the file argument is the name of the file to be executed. The argv argument is a NULL-terminated array of strings, which will be the argument list available to the new program. The first element of argv is conventionally used to hold the filename associated with the file being executed.

execvpe() is like execvp(), but it also takes an environment list envp. If envp is NULL, then the environment of the calling process is inherited.

RETURN VALUE

If one of the exec* functions returns, an error has occurred. The return value is -1, and errno is set to indicate the error.

ERRORS

The exec* functions can fail for the following reasons:

EACCES
Search permission denied for one of the components of the path prefix of file, or read permission denied for the file itself.
EFAULT
file or argv points to an invalid address.
ELOOP
Too many symbolic links encountered while processing file.
ENAMETOOLONG
file is too long.
ENOENT
A component of file does not exist, or file is an empty string.
ENOTDIR
A component of the path prefix of file is not a directory.
ENOMEM
Insufficient kernel memory was available to execute the process.
ETXTBSY
The file is executable but has been opened in write-only mode.
ENOEXEC
The file is not a valid executable file, or is for a different architecture.

ATTRIBUTES

For an explanation of the terms used in this section, see attributes(7).

Multithreading
The exec* functions are not thread-safe.

BUGS

Before glibc 2.24, execl() and execle() employed realloc(3) internally and were consequently not async-signal-safe, in violation of the requirements of POSIX.1. This was fixed in glibc 2.24.

Architecture-specific details

On sparc and sparc64, execv() is provided as a system call by the kernel (with the prototype shown above) for compatibility with SunOS. This function is not employed by the execv() wrapper function on those architectures.
