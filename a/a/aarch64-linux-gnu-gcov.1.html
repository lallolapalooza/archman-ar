aarch64-linux-gnu-gcov(1)

الحزمة: aarch64-linux-gnu-gcc

التراخيص: GPL, LGPL, FDL

source output:

path 10 not covered:
BB  3:           8:  for (i = 0; i < 10; i++)
BB  3:           9:    total += i;
BB  4: (false)   8:  for (i = 0; i < 10; i++)
BB  5: (true)   11:  int v = total > 100 ? 1 : 2;
BB  6:          11:  int v = total > 100 ? 1 : 2;
BB  8: (false)  13:  if (total != 45 && v == 1)
BB 11:          16:    printf ("Success\n");
BB 12:          17:  return 0;

العمود الأول (BB) هو تسلسل الكتل الأساسية (انظر -w). العمود الأوسط (true/false) هو القرار لهذا السطر. العمود الثالث هو رقم السطر. العمود الرابع هو السطر نفسه. يجب تشغيل هذه الأسطر بهذا الترتيب لتغطية المسار 10.

-d
--display-progress
عرض التقدم على المخرج القياسي.
-f
--function-summaries
إخراج ملخصات لكل دالة بالإضافة إلى الملخص على مستوى الملف.
--include regex
تضمين الدوال التي تطابق regex. هذا الخيار يجعل gcov يقوم فقط بالإبلاغ عن الدوال التي تطابق التعبير العادي الموسع regex. يمكن دمج هذه العلامة مع --exclude. إذا تطابقت دالة مع كل من التضمينات والاستثناءات، فإن آخر تضمين/استثناء هو الذي ينطبق. بشكل افتراضي، يقوم gcov بالإبلاغ عن جميع الدوال، ولكن إذا تم استخدام --include، فسيتم الإبلاغ فقط عن الدوال التي تطابق التضمين.
--exclude regex
استثناء الدوال التي تطابق regex. هذا الخيار يجعل gcov لا يقوم بالإبلاغ عن الدوال التي تطابق التعبير العادي الموسع regex. يمكن دمج هذه العلامة مع --include. إذا تطابقت دالة مع كل من التضمينات والاستثناءات، فإن آخر تضمين/استثناء هو الذي ينطبق. بشكل افتراضي، يقوم gcov بالإبلاغ عن جميع الدوال، وإذا تم استخدام --exclude، فسيتم استبعاد الدوال التي تطابقها.
-h
--help
عرض المساعدة حول استخدام gcov (على المخرج القياسي)، والخروج دون أي معالجة إضافية.
-j
--json-format
إخراج ملف gcov بتنسيق وسيط JSON سهل التحليل لا يتطلب شفرة المصدر للإنشاء. يتم ضغط ملف JSON باستخدام خوارزمية ضغط gzip وللملفات امتداد .gcov.json.gz.

هيكل JSON هو كالتالي:

{
  "current_working_directory": "foo/bar",
  "data_file": "a.out",
  "format_version": "2",
  "gcc_version": "11.1.1 20210510"
  "files": ["$file"]
}

حقول العنصر الجذر لها الدلالات التالية:

  • current_working_directory: دليل العمل الذي تم فيه تجميع وحدة التجميع
  • data_file: اسم ملف البيانات (GCDA)
  • format_version: الإصدار الدلالي للتنسيق

    التغييرات في الإصدار 2:

*
calls: تمت إضافة معلومات حول استدعاءات الدوال
*
gcc_version: إصدار مترجم GCC

لكل file الشكل التالي:

{
  "file": "a.c",
  "functions": ["$function"],
  "lines": ["$line"]
}

حقول عنصر file لها الدلالات التالية:

*
file_name: اسم ملف المصدر

لكل function الشكل التالي:

{
  "blocks": 2,
  "blocks_executed": 2,
  "demangled_name": "foo",
  "end_column": 1,
  "end_line": 4,
  "execution_count": 1,
  "name": "foo",
  "start_column": 5,
  "start_line": 1
}

حقول عنصر function لها الدلالات التالية:

  • blocks: عدد الكتل الموجودة في الدالة
  • blocks_executed: عدد الكتل المنفذة للدالة
  • demangled_name: الاسم المفكك للدالة
  • end_column: العمود في ملف المصدر حيث تنتهي الدالة
  • end_line: السطر في ملف المصدر حيث تنتهي الدالة
  • execution_count: عدد مرات تنفيذ الدالة
  • name: اسم الدالة
  • start_column: العمود في ملف المصدر حيث تبدأ الدالة
  • start_line: السطر في ملف المصدر حيث تبدأ الدالة

لاحظ أن أرقام الأسطر وأرقام الأعمدة تبدأ من 1. في التنفيذ الحالي، start_line و start_column لا يشملان أي معاملات قالب و النوع المرتجع البادئ، ولكن من المرجح أن يتم إصلاح هذا في المستقبل.

لكل line الشكل التالي:

{
  "block_ids": ["$block_id"],
  "branches": ["$branch"],
  "calls": ["$call"],
  "count": 2,
  "conditions": ["$condition"],
  "line_number": 15,
  "unexecuted_block": false,
  "function_name": "foo",
}

توجد الفروع والاستدعاءات فقط مع الخيار -b. حقول عنصر line لها الدلالات التالية:

  • block_ids: معرفات الكتل الأساسية التي تنتمي إلى السطر
  • count: عدد مرات تنفيذ السطر
  • line_number: رقم السطر
  • unexecuted_block: علامة تشير إلى ما إذا كان السطر يحتوي على كتلة غير منفذة (ليست كل العبارات في السطر منفذة)
  • function_name: اسم الدالة التي ينتمي إليها هذا line (بالنسبة لسطر يحتوي على عبارات مضمنة قد لا يتم تعيينه)

لكل branch الشكل التالي:

{
  "count": 11,
  "destination_block_id": 17,
  "fallthrough": true,
  "source_block_id": 13,
  "throw": false
}

حقول عنصر branch لها الدلالات التالية:

  • count: عدد مرات تنفيذ الفرع
  • fallthrough: صحيح عندما يكون الفرع فرعًا عاديًا
  • throw: صحيح عندما يكون الفرع فرعًا استثنائيًا
  • isource_block_id: معرف الكتلة الأساسية حيث يحدث هذا الفرع
  • destination_block_id: معرف الكتلة الأساسية التي يقفز إليها هذا الفرع

لكل call الشكل التالي:

{
  "destination_block_id": 1,
  "returned": 11,
  "source_block_id": 13
}

حقول عنصر call لها الدلالات التالية:

  • returned: عدد المرات التي عادت فيها استدعاءات الدالة (عدد الاستدعاءات يساوي line::count)
  • isource_block_id: معرف الكتلة الأساسية حيث يحدث هذا الاستدعاء
  • destination_block_id: معرف الكتلة الأساسية التي يستمر فيها الاستدعاء بعد العودة

لكل condition الشكل التالي:

{
  "count": 4,
  "covered": 2,
  "not_covered_false": [],
  "not_covered_true": [0, 1],
}

حقول عنصر condition لها الدلالات التالية:

  • count: عدد نتائج الشرط في هذا التعبير
  • covered: عدد نتائج الشرط المغطاة في هذا التعبير
  • not_covered_true: المصطلحات، حسب الفهرس، التي لم تُشاهَد على أنها صحيحة في هذا التعبير
  • not_covered_false: المصطلحات، حسب الفهرس، التي لم تُشاهَد على أنها خاطئة في هذا التعبير
-H
--human-readable
كتابة الأعداد بتنسيق سهل القراءة (مثل 24.6k).
-k
--use-colors
استخدام الألوان لأسطر التعليمات البرمجية التي لديها تغطية صفرية. نستخدم اللون الأحمر للأسطر غير الاستثنائية واللون السماوي للأسطر الاستثنائية. تُستخدم نفس الألوان للكتل الأساسية مع الخيار -a.
-l
--long-file-names
إنشاء أسماء ملفات طويلة للملفات المصدر المضمنة. على سبيل المثال، إذا كان ملف الرأس x.h يحتوي على تعليمات برمجية، وتم تضمينه في الملف a.c، فإن تشغيل gcov على الملف a.c سينتج ملف إخراج يسمى a.c##x.h.gcov بدلاً من x.h.gcov. يمكن أن يكون هذا مفيدًا إذا تم تضمين x.h في ملفات مصدر متعددة وتريد رؤية المساهمات الفردية. إذا استخدمت الخيار -p، فستكون أسماء الملفات المضمنة والمضمنة أسماء مسارات كاملة.
-m
--demangled-names
عرض أسماء الدوال المفككة في الإخراج. الافتراضي هو عرض أسماء الدوال المشفرة.
-M
--filter-on-demangled
جعل --include و --exclude تتطابق مع الأسماء المفككة. هذا يؤثر فقط على المطابقة ولا يعني --demangled-names، ولكن يمكن دمجه بأمان معها.
-n
--no-output
عدم إنشاء ملف إخراج gcov.
-o directory|file
--object-directory directory
--object-file file
تحديد الدليل الذي يحتوي على ملفات بيانات gcov، أو اسم مسار الكائن. يتم البحث عن ملفات البيانات .gcno و .gcda باستخدام هذا الخيار. إذا تم تحديد دليل، فإن ملفات البيانات تكون في ذلك الدليل وتسمى باسم ملف الإدخال، بدون امتداده. إذا تم تحديد ملف هنا، فإن ملفات البيانات تسمى بهذا الملف، بدون امتداده.
-p

الموقع متاح بموجب شروط ترخيص GPL-3.0 ، باستثناء محتويات صفحات الدليل ، والتي لها ترخيصها الخاص المحدد في حزمة Arch Linux المقابلة.

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.
