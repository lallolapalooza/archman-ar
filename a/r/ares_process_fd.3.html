ares_process_fd(3)

الحزمة: c-ares

التراخيص: MIT

ARES_PROCESS(3) دليل وظائف المكتبة ARES_PROCESS(3)

الاسم

ares_process_fds, ares_process_fd, ares_process - معالجة أحداث تحليل الأسماء

المُلَخَّص

#include <ares.h>
/*! الأحداث المستخدمة بواسطة ares_fd_events_t */
typedef enum {
  ARES_FD_EVENT_NONE  = 0,      /*!< لا توجد أحداث */
  ARES_FD_EVENT_READ  = 1 << 0, /*!< حدث قراءة (بما في ذلك قطع الاتصال / الخطأ) */
  ARES_FD_EVENT_WRITE = 1 << 1  /*!< حدث كتابة */
} ares_fd_eventflag_t;
/*! نوع يحمل واصف ملف وقناع أحداث، يستخدم بواسطة
 *  ares_process_fds() */
typedef struct {
  ares_socket_t fd;     /*!< واصف ملف */
  unsigned int  events; /*!< قناع من ares_fd_event_t */
} ares_fd_events_t;
typedef enum {
  ARES_PROCESS_FLAG_NONE        = 0,
  ARES_PROCESS_FLAG_SKIP_NON_FD = 1 << 0
} ares_process_flag_t;
ares_status_t ares_process_fds(ares_channel_t         *channel,
                               const ares_fd_events_t *events,
                               size_t                  nevents,
                               unsigned int            flags)
void ares_process_fd(ares_channel_t *channel,
                     ares_socket_t read_fd,
                     ares_socket_t write_fd)
void ares_process(ares_channel_t *channel,
                  fd_set *read_fds,
                  fd_set *write_fds)

الوصف

يجب استخدام هذه الوظائف من قبل المدمجين الذين يختارون عدم استخدام EventThread المُمكَّن عبر ARES_OPT_EVENT_THREAD الذي تم تمريره إلى ares_init_options. يفترض هذا أن المدمجين لديهم بالفعل حلقة أحداث خاصة بهم تتعامل مع إشعارات الأحداث لواصفات الملفات المختلفة ويرغبون في القيام بنفس الشيء مع تكاملهم مع c-ares.

تتعامل وظيفة ares_process_fds(3) مع أحداث الإدخال/الإخراج على واصفات الملفات وأوقات الاستعداد المرتبطة بالاستعلامات المعلقة على القناة المحددة بواسطة channel. يتم تمرير واصفات الملفات التي يجب معالجتها في مصفوفة من هياكل بيانات ares_fd_events_t في عضو fd، والأحداث هي قناع بتي ares_fd_eventflag_t في عضو event. يمكن أيضًا استخدام هذه الوظيفة لمعالجة أوقات الاستعداد عن طريق تمرير NULL إلى عضو events بقيمة nevents تساوي 0. يمكن أيضًا تحديد الأعلام في حقل flags وهي معرفة في ares_process_flag_t.

يمكن تحديد ARES_PROCESS_FLAG_SKIP_NON_FD لتخطي أي معالجة غير مرتبطة بأحداث واصف الملف الممررة بشكل خاص، وتشمل الأمثلة معالجة أوقات الاستعداد ومعالجة التنظيف. هذا مفيد إذا كان المدمج يعرف أنه سيرسل طلبات ares_process_fds(3) متعددة ويريد تخطي تلك المعالجة الإضافية. ومع ذلك، يجب على المدمج إرسال الطلب النهائي بالعلم حتى تتم معالجة وقت الاستعداد والمعالجة الأخرى قبل أن تنتظر حلقة الأحداث الخاصة به أحداثًا إضافية.

يجوز استخدام ares_fd_events_t مع عضو events بقيمة ARES_FD_EVENT_NONE (0) إذا لم تكن هناك أحداث لواصف ملف معين إذا رغب المدمج في الاحتفاظ بمصفوفة بجميع واصفات الملفات الممكنة وتحديث الجاهزية عبر عضو event.

سترجع هذه الوظيفة ARES_ENOMEM في حالات نفاد الذاكرة، وإلا فسترجع ARES_SUCCESS.

يوصى بهذه الوظيفة على ares_process_fd(3) لأنها يمكنها التعامل مع معالجة واصفات ملفات متعددة في وقت واحد، وبالتالي تتخطى تكرار المنطق الإضافي مثل معالجة وقت الاستعداد الذي سيكون مطلوبًا إذا تم استدعاء ares_process_fd(3) لواصفات ملفات متعددة تم إشعارها في نفس الوقت.

تستخدم هذه الوظيفة عادةً مع الخيار ARES_OPT_SOCK_STATE_CB.

يجب استخدام ares_timeout(3) لاسترداد وقت الاستعداد المطلوب، وعند انتهاء وقت الاستعداد، يجب على المدمج استدعاء ares_process_fds(3) بمصفوفة events فارغة. (أو ares_process_fd(3) مع تعيين كلا المقبسين إلى ARES_SOCKET_BAD). لا حاجة للقيام بذلك إذا تم تسليم الأحداث أيضًا لأي من واصفات الملفات، حيث سيتم التعامل مع معالجة وقت الاستعداد تلقائيًا بواسطة أي استدعاء لـ ares_process_fds(3) أو ares_process_fd(3).

وظيفة ares_process_fd(3) هي نفسها وظيفة ares_process_fds(3) باستثناء أنها يمكنها فقط معالجة واصف ملف قراءة واحد وواصف ملف كتابة واحد في كل مرة. يجب على المدمجين الجدد استخدام ares_process_fds(3) إذا أمكن.

تعمل وظيفة ares_process(3) بنفس الطريقة، باستثناء أنها تعمل على fd_sets كما يستخدمها select(3) ويتم استردادها بواسطة ares_fds(3). هذا الأسلوب مهمل ولا يجب استخدامه في التطبيقات الحديثة بسبب القيود المعروفة لتنفيذ select(3).
