ares_process(3)

الحزمة: c-ares

التراخيص: MIT

ARES_PROCESS(3) دليل وظائف المكتبة ARES_PROCESS(3)

الاسم

ares_process_fds, ares_process_fd, ares_process - معالجة الأحداث لحل اسم المجال

المُلَخَّص

#include <ares.h>
/*! الأحداث المستخدمة بواسطة ares_fd_events_t */
typedef enum {
  ARES_FD_EVENT_NONE  = 0,      /*!< لا أحداث */
  ARES_FD_EVENT_READ  = 1 << 0, /*!< حدث قراءة (بما في ذلك الانقطاع/الخطأ) */
  ARES_FD_EVENT_WRITE = 1 << 1  /*!< حدث كتابة */
} ares_fd_eventflag_t;
/*! نوع يحمل واصف ملف وقناع للأحداث، يستخدم بواسطة
 *  ares_process_fds() */
typedef struct {
  ares_socket_t fd;     /*!< واصف الملف */
  unsigned int  events; /*!< قناع من ares_fd_event_t */
} ares_fd_events_t;
typedef enum {
  ARES_PROCESS_FLAG_NONE        = 0,
  ARES_PROCESS_FLAG_SKIP_NON_FD = 1 << 0
} ares_process_flag_t;
ares_status_t ares_process_fds(ares_channel_t         *channel,
                               const ares_fd_events_t *events,
                               size_t                  nevents,
                               unsigned int            flags)
void ares_process_fd(ares_channel_t *channel,
                     ares_socket_t read_fd,
                     ares_socket_t write_fd)
void ares_process(ares_channel_t *channel,
                  fd_set *read_fds,
                  fd_set *write_fds)

الوصف

يجب على المدمجين الذين يختارون عدم استخدام EventThread المُمكّن عبر ARES_OPT_EVENT_THREAD المُمرر إلى ares_init_options استخدام هذه الوظائف. هذا يفترض أن المدمجين لديهم بالفعل حلقة الأحداث الخاصة بهم التي تتعامل مع إشعارات الأحداث لواصفات الملفات المختلفة ويرغبون في فعل الشيء نفسه مع تكاملهم مع c-ares.

تقوم وظيفة ares_process_fds(3) بمعالجة أحداث الإدخال/الإخراج على واصفات الملفات والمؤقتات المرتبطة بالاستعلامات المعلقة على القناة المحددة بواسطة channel. يتم تمرير واصفات الملفات المراد معالجتها في مصفوفة من هياكل بيانات ares_fd_events_t في العضو fd، والأحداث هي قناع ثنائي لـ ares_fd_eventflag_t في العضو event. يمكن أيضًا استخدام هذه الوظيفة لمعالجة المؤقتات عن طريق تمرير NULL إلى العضو events مع قيمة nevents تساوي 0. يمكن أيضًا تحديد الأعلام في حقل flags وهي معرفة في ares_process_flag_t.

يمكن تحديد ARES_PROCESS_FLAG_SKIP_NON_FD لتخطي أي معالجة غير مرتبطة بأحداث واصف الملفات المُمررة بشكل خاص، وتشمل الأمثلة معالجة المؤقتات ومعالجة التنظيف. هذا مفيد إذا كان المدمج يعلم أنه سيرسل طلبات ares_process_fds(3) متعددة ويريد تخطي تلك المعالجة الإضافية. ومع ذلك، يجب على المدمج إرسال الطلب النهائي مع العلم المحدد حتى تتم معالجة المؤقت والمعالجات الأخرى قبل أن تنتظر حلقة الأحداث الخاصة بهم أحداثًا إضافية.

يُسمح باستخدام ares_fd_events_t مع العضو events بقيمة ARES_FD_EVENT_NONE (0) إذا لم تكن هناك أحداث لواصف ملف معين إذا كان المدمج يرغب ببساطة في الاحتفاظ بمصفوفة تحتوي على جميع واصفات الملفات الممكنة وتحديث الاستعداد عبر العضو event.

ستُعيد هذه الوظيفة ARES_ENOMEM في حالات نفاد الذاكرة، وإلا فسوف تُعيد ARES_SUCCESS.

يُوصى بهذه الوظيفة على ares_process_fd(3) نظرًا لأنها يمكنها معالجة واصفات ملفات متعددة دفعة واحدة، وبالتالي تتخطى تكرار المنطق الإضافي مثل معالجة المؤقتات التي ستكون مطلوبة إذا تم استدعاء ares_process_fd(3) لواصفات ملفات متعددة تم إخطارها في نفس الوقت.

تُستخدم هذه الوظيفة عادةً مع الخيار ARES_OPT_SOCK_STATE_CB.

يجب استخدام ares_timeout(3) لاسترداد المؤقت المطلوب، وعند انتهاء المؤقت، يجب على المدمج استدعاء ares_process_fds(3) بمصفوفة events فارغة (NULL). (أو ares_process_fd(3) مع تعيين كلا المقبسين إلى ARES_SOCKET_BAD). لا حاجة للقيام بذلك إذا تم تسليم أحداث لواصفات الملفات أيضًا حيث ستتم معالجة المؤقت تلقائيًا بواسطة أي استدعاء لـ ares_process_fds(3) أو ares_process_fd(3).

وظيفة ares_process_fd(3) هي نفس وظيفة ares_process_fds(3) باستثناء أنها يمكنها معالجة واصف قراءة واحد وواصف كتابة واحد في كل مرة. يجب على المدمجين الجدد استخدام ares_process_fds(3) إن أمكن.

وظيفة ares_process(3) تعمل بنفس الطريقة، باستثناء أنها تعمل على fd_sets كما هو مستخدم بواسطة select(3) ويتم استردادها بواسطة ares_fds(3). هذه الطريقة مهجورة ولا يجب استخدامها في التطبيقات الحديثة بسبب القيود المعروفة على تنفيذ select(3).
