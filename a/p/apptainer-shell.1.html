DESCRIPTION

The apptainer shell command invokes an interactive shell within the specified Apptainer IMAGE or INSTANCE. This allows you to execute commands and interact with the container's environment as if you were inside it.

By default, apptainer shell will start a shell using the default shell defined within the container (usually /bin/bash or /bin/sh). If you specify a COMMAND, it will be executed instead of an interactive shell.

If the container is a virtual machine image, apptainer shell will start a virtual machine and then invoke a shell within that virtual machine.

OPTIONS

In addition to the global options, apptainer shell recognizes the following options:

--writable, -w
Creates a writable overlay for the container image. This allows you to make changes to the container's filesystem that will persist across sessions. Note that this option requires root privileges.
--overlay overlay
Mounts an overlay filesystem on top of the container. This allows you to add or modify files within the container without altering the original image. The overlay argument specifies the path to the overlay file or directory.
--mount type=bind,src=host,dst=container[,options]
Mounts a host directory or file into the container. This is useful for providing access to data or tools located outside the container. The type can be bind. src is the path on the host, and dst is the path inside the container. options can include ro for read-only access.
--no-home
Do not mount the user's home directory into the container.
--no-mount type
Do not mount specified filesystem types (e.g., home, tmp).
--nv
Enables automatic provisioning of NVIDIA GPU drivers within the container. This is a shortcut for using appropriate --mount options to bind mount the necessary NVIDIA drivers and libraries.
--compat
Enables compatibility mode, which may alter Apptainer's behavior to better align with older versions or specific use cases.
--security context
Sets the security context for the container. This is typically used in SELinux-enabled environments to specify the desired security context for the container process.
--pid
Creates a new PID namespace for the container, isolating its process tree from the host.
--fssize size
Sets the size of the filesystem for the container. This is often used when creating containers or overlay filesystems.
--no-eval
Disables evaluation of Apptainer configuration files within the container.
--no-privs
Runs the container without any elevated privileges, even if the user running Apptainer has them.
--vm
Runs the container as a virtual machine.
--vm-ram size
Sets the amount of RAM allocated to the virtual machine.

--vm-initrd path
