apk-repositories(5)

الحزمة: apk-tools

التراخيص: GPL-2.0-or-later

apk-repositories(5) دليل تنسيقات الملفات apk-repositories(5)

الاسم

/etc/apk/repositories
/etc/apk/repositories.d/*.list
/lib/apk/repositories.d/*.list
قائمة مستودعات الحزم

الوصف

apk(8) يقوم بتحميل تعريفات المستودعات من الملفات المذكورة أعلاه.

يتم تحميل ملف repositories أولاً. ثم يتم معالجة مسارات repositories.d إذا لم يتم استخدام الخيار --repositories-file. يتم تعداد الدلائل بالترتيب المذكور أعلاه. بمجرد رؤية ملف .list بالاسم المحدد، يتم تجاهل أي ملف بنفس الاسم في الدلائل اللاحقة.

تنسيق الملف

كل سطر يتبع أحد الصيغ التالية:

# تعليق

سطر تعليق يتم تجاهله.

set [-default] key=value

قم بتعيين المتغير المسمى key إلى القيمة المعطاة value.

يقتصر key على الحروف والأرقام وحرف الشرطة السفلية (_)، ويجب أن يبدأ بحرف. أسماء المتغيرات التي تبدأ بـ APK_ محجوزة للمتغيرات المضمنة ولا يمكن للمستخدم تعريفها.

يتم إجراء توسيع للمتغير على value قبل التعيين.

إذا تم تحديد الخيار -default، فلن تتغير قيمة key إذا كانت موجودة بالفعل.

حالياً، المتغيرات التالية معرفة:

•
APK_ARCH، المعمارية الأساسية لقاعدة البيانات

ndx [@tag] url
[v2|v3] [@tag] url [component...]

إذا كان تعريف المستودع يفتقر إلى حقل النوع، فإنه افتراضيًا هو النوع المعرف في أحدث أمر default، أو إذا كان غائبًا، فإنه افتراضيًا هو v2 (أو ndx إذا انتهى url بـ .adb أو .tar.gz). إذا كان التنسيق v3 أو انتهى اسم ملف ndx بـ .adb، فإن ملف فهرس تنسيق v3 مطلوب.

يمكن أن يكون @tag الاختياري موجودًا للإشارة إلى أنه لا ينبغي استخدام المستودع افتراضيًا. ارجع إلى apk-world(5) حول كيفية تمكين تثبيت الحزم من المستودعات الموسومة.

يتم إجراء توسيع للمتغير على أقسام url و component بشكل فردي في وقت تحليل السطر.

يشير url إلى ملف فهرس أو مسار المستودع. المخططات المدعومة حاليًا هي:

  • http://
  • https://
  • file://
  • مسار نظام ملفات مطلق (يجب أن يبدأ بـ `/`)

تحدد قائمة component قائمة مكونات المستودع. إذا تم تحديدها، يتم توسيع السطر إلى عناوين URL متعددة: واحد لكل مكون، ويتم إلحاق component بـ url. تحديد component مع نوع ndx غير صالح.

أمثلة

لتحديد قائمة مستودعات مقدمة من التوزيع، يمكن للتوزيع شحن، على سبيل المثال، /lib/apk/repositories.d/distribution.list بالمحتوى:

set -default distro_mirror=https://example.com/distro
v3 ${distro_mirror} main community

في /etc/apk/repositories.d/00-vars.list، يمكن تجاوز المرآة بالتالي:

set distro_mirror=https://mirror.example.com/distro

تخطيط المستودع

إذا كان type هو ndx، فإن التخطيط وحل المسار يكونان كالتالي:

  • url هو عنوان URL لملف الفهرس
  • base_url هو url مع إزالة المكون الأخير
  • مسار الحزمة الافتراضي: $base_url/$name-$version.apk

بخلاف ذلك، فإن type هو أحد أنواع المستودعات، ويعمل حل المسار كالتالي:

  • url هو base_url للمستودع
  • الفهرس (v3) موجود على $base_url/$arch/Packages.adb
  • الفهرس (v2) موجود على $base_url/$arch/APKINDEX.tar.gz
  • مسار الحزمة الافتراضي: $base_url/$arch/$name-$version.apk

إذا كان ملف الفهرس يحتوي على pkgname-spec محدد، فإنه يستخدم لبناء مسار الحزمة. بخلاف ذلك، يتم استخدام مسار الحزمة الافتراضي بناءً على القواعد المذكورة أعلاه.

إنشاء الفهارس والمستودعات

راجع apk-mkndx(8) حول كيفية إنشاء ملفات الفهرس و apk-adbsign(8) حول تعديل التوقيعات.

لتنسيق الفهرس القديم، ارجع إلى apk-index(8) لملفات الفهرس، abuild-keygen(1) للحصول على معلومات حول إنشاء المفاتيح، abuild-sign(1) للحصول على معلومات حول استخدام هذه المفاتيح لتوقيع الملفات.

apk-verify(8) يمكنه التحقق من ملفات الفهرس والحزم الجديدة والقديمة.

تحديث فهرس العميل

apk(8) يقوم بجلب وتخزين الفهرس لكل مستودع في ذاكرة تخزين مؤقتة محلية في /etc/apk/cache أو /var/cache/apk. ارجع إلى apk-cache(5) لمزيد من التفاصيل.

ارجع إلى apk-keys(5) حول كيفية تكوين العميل للتحقق من توقيعات الفهرس.
