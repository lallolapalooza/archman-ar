auplugin(3)

الحزمة: audit

التراخيص: GPL-2.0-or-later, LGPL-2.0-or-later

AUPLUGIN(3) واجهة برمجة تطبيقات تدقيق لينكس AUPLUGIN(3)

الاسم

auplugin_init, auplugin_stop, auplugin_event_loop, auplugin_event_feed - مساعدات معالجة أحداث الإضافات

ملخص

#include <auplugin.h>

int auplugin_init(int inbound_fd, unsigned queue_size, int q_flags, const char *path);
void auplugin_stop(void);
void auplugin_event_loop(auplugin_callback_ptr callback);
int auplugin_event_feed(auparse_callback_ptr callback, unsigned timer_interval, auplugin_timer_callback_ptr timer_cb);

الوصف

تقوم auplugin_init بتهيئة إطار عمل الإضافات. تحدد المعلمة inbound_fd واصف الملف الذي سيوفر رسائل التدقيق، عادةً الإدخال القياسي. تتحكم المعلمة queue_size في الحد الأقصى لعدد الأحداث التي يمكن وضعها في قائمة انتظار للمعالجة. تحدد المعلمة q_flags التخزين في الذاكرة أو التخزين المدعوم بالملف باستخدام الثوابت AUPLUGIN_Q_* المعرفة في auplugin.h. إذا كانت q_flags تتضمن AUPLUGIN_Q_IN_FILE, تحدد path ملف النسخ الاحتياطي. يتم وضع أي أحداث موجودة بالفعل في الملف في قائمة انتظار عند بدء التشغيل حتى تستأنف الإضافات معالجة السجلات التي لم يتم التعامل معها سابقًا. تحتفظ المكتبة بحالة عامة لقائمة الانتظار والخيوط العاملة الخاصة بها. لا يُسمح إلا بنسخة إضافية واحدة، لذلك يجب على المتصلين عدم استدعاء auplugin_init() بشكل متزامن من خيوط متعددة. تعيد الدالة 0 عند النجاح أو -1 إذا فشلت التهيئة.

تشير auplugin_stop إلى الإطار لإنهاء العمل. يتم استدعاؤها عادةً من معالج SIGTERM أو منطق إيقاف التشغيل الآخر.

تبدأ auplugin_event_loop خيط عامل لتسليم الأحداث الموجودة في قائمة الانتظار إلى الدالة callback المقدمة، سجلًا تلو الآخر. تظل الدالة معلقة في المتصل حتى يتم استدعاء auplugin_stop.

تعمل auplugin_event_feed مثل auplugin_event_loop، باستثناء أنه يتم تغذية الأحداث الموجودة في قائمة الانتظار إلى libauparse. يجب أن تتطابق المعلمة callback المقدمة مع نوع auparse_callback_ptr. تحدد المعلمة timer_interval عدد الثواني التي سينتظرها الخيط العامل للحصول على سجلات جديدة. يؤدي تعيين قيمة 0 إلى تعطيل منطق المؤقت. عند انتهاء الفترة، يتم استدعاء auparse_feed_age_events لمسح الأحداث القديمة. إذا لم تكن timer_cb NULL, فسيتم استدعاؤها مع الفترة قبل المسح. يؤدي تمرير timer_cb بقيمة NULL إلى الاحتفاظ بالسلوك الافتراضي لاستدعاء auparse_feed_age_events فقط. تعيد الدالة 0 عند النجاح أو -1 إذا لم يكن من الممكن تهيئة libauparse.

يمكن للإضافات الاستعلام عن إحصائيات قائمة الانتظار باستخدام auplugin_queue_depth و auplugin_queue_max_depth و auplugin_queue_overflow. قم بتسجيل رد اتصال باستخدام auplugin_register_stats_callback، وقم باستدعائه باستخدام auplugin_report_stats.

معالجة الإشارات

يجب على الإضافات إنشاء معالجات إشارات باستخدام sigaction(2) قبل الدخول إلى حلقة الأحداث. يجب أن يستدعي معالج SIGTERM الدالة auplugin_stop() لإيقاف الخيط العامل. يجب على معالجات الإشارات الأخرى، مثل SIGHUP أو SIGUSR1، تعيين أعلام عامة تتم معالجتها في ردود اتصال الأحداث أو المؤقت.

مثال:

static volatile sig_atomic_t reload;
static void handler(int sig)
{
    if (sig == SIGTERM)
        auplugin_stop();
    else if (sig == SIGHUP)
        reload = 1;
}
