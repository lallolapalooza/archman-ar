ALTER_VIEW(7)

الحزمة: postgresql

التراخيص: PostgreSQL

ALTER VIEW(7) توثيق PostgreSQL 18.1 ALTER VIEW(7)

الاسم

ALTER_VIEW - تغيير تعريف عرض

الموجز

ALTER VIEW [ IF EXISTS ] name ALTER [ COLUMN ] column_name SET DEFAULT expression
ALTER VIEW [ IF EXISTS ] name ALTER [ COLUMN ] column_name DROP DEFAULT
ALTER VIEW [ IF EXISTS ] name OWNER TO { new_owner | CURRENT_ROLE | CURRENT_USER | SESSION_USER }
ALTER VIEW [ IF EXISTS ] name RENAME [ COLUMN ] column_name TO new_column_name
ALTER VIEW [ IF EXISTS ] name RENAME TO new_name
ALTER VIEW [ IF EXISTS ] name SET SCHEMA new_schema
ALTER VIEW [ IF EXISTS ] name SET ( view_option_name [= view_option_value] [, ... ] )
ALTER VIEW [ IF EXISTS ] name RESET ( view_option_name [, ... ] )

الوصف

ALTER VIEW يغير الخصائص الإضافية المختلفة للعرض. (إذا كنت تريد تعديل الاستعلام الذي يحدد العرض، استخدم CREATE OR REPLACE VIEW).

يجب أن تمتلك العرض لاستخدام ALTER VIEW. لتغيير مخطط العرض، يجب أن يكون لديك أيضًا امتياز CREATE في المخطط الجديد. لتغيير المالك، يجب أن تكون قادرًا على SET ROLE إلى دور المالك الجديد، وهذا الدور يجب أن يكون لديه امتياز CREATE في مخطط العرض. (تفرض هذه القيود أن تغيير المالك لا يقوم بأي شيء لا يمكنك القيام به عن طريق حذف وإعادة إنشاء العرض. ومع ذلك، يمكن لمستخدم خارق تغيير ملكية أي عرض على أي حال).

المعلمات

name

اسم (يمكن تحديد المخطط له اختياريًا) لعرض موجود.

column_name

اسم عمود موجود.

new_column_name

اسم جديد لعمود موجود.

IF EXISTS

لا ترمي خطأ إذا كان العرض غير موجود. يتم إصدار إشعار في هذه الحالة.

SET/DROP DEFAULT

تحدد هذه الأشكال أو تزيل القيمة الافتراضية لعمود. يتم استبدال القيمة الافتراضية لعمود العرض في أي أمر INSERT أو UPDATE يكون هدفها هو العرض، قبل تطبيق أي قواعد أو مشغلات للعرض. لذلك، ستكون أولوية القيمة الافتراضية للعرض على أي قيم افتراضية من العلاقات الأساسية.

new_owner

اسم المستخدم للمالك الجديد للعرض.

new_name

الاسم الجديد للعرض.

new_schema

المخطط الجديد للعرض.

SET ( view_option_name [= view_option_value] [, ... ] )
RESET ( view_option_name [, ... ] )

يحدد أو يعيد تعيين خيار عرض. الخيارات المدعومة حاليًا هي:

check_option (enum)

يغير خيار التحقق من صحة العرض. يجب أن تكون القيمة local أو cascaded.

security_barrier (boolean)

يغير خاصية security-barrier للعرض. يجب أن تكون القيمة قيمة منطقية، مثل true أو false.

security_invoker (boolean)

يغير خاصية security-invoker للعرض. يجب أن تكون القيمة قيمة منطقية، مثل true أو false.

ملاحظات

لأسباب تاريخية، يمكن استخدام ALTER TABLE مع العروض أيضًا؛ ولكن الأشكال الوحيدة لـ ALTER TABLE المسموح بها مع العروض هي تلك التي تعادل الأشكال الموضحة أعلاه.

أمثلة

لإعادة تسمية العرض foo إلى bar:

ALTER VIEW foo RENAME TO bar;

لإرفاق قيمة عمود افتراضية بعرض قابل للتحديث:

CREATE TABLE base_table (id int, ts timestamptz);
CREATE VIEW a_view AS SELECT * FROM base_table;
ALTER VIEW a_view ALTER COLUMN ts SET DEFAULT now();
INSERT INTO base_table(id) VALUES(1);  -- ts سيحصل على قيمة NULL
INSERT INTO a_view(id) VALUES(2);  -- ts سيحصل على الوقت الحالي

التوافق

ALTER VIEW هو امتداد PostgreSQL للمعيار SQL.

انظر أيضًا

CREATE VIEW (CREATE_VIEW(7)), DROP VIEW (DROP_VIEW(7))
