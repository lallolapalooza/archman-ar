o و/أو من id. الاتجاهات الممكنة هي src (مصدر)، dst (وجهة)، src or dst (مصدر أو وجهة) و src and dst (مصدر ووجهة). على سبيل المثال، `src foo'، `dst net 1.2.3'، `src or dst port ftp-data'. إذا لم يكن هناك محدد اتجاه، فسيتم افتراض src or dst. بالنسبة لطبقات الارتباط `null' (أي بروتوكولات نقطة إلى نقطة مثل slip)، يمكن استخدام المحددين inbound (داخل) و outbound (خارج) لتحديد الاتجاه المطلوب.
proto
المحددات مقيدة ببروتوكولات IP فقط. البروتوكولات الممكنة هي: tcp، udp و icmp. على سبيل المثال، `udp src foo' أو `tcp port 21'. إذا لم يكن هناك محدد بروتوكول، فسيتم افتراض جميع البروتوكولات المتوافقة مع النوع. على سبيل المثال، `src foo' تعني `ip and ((tcp or udp) src foo)'، `net bar' تعني `ip and (net bar)'، و `port 53' تعني `ip and ((tcp or udp) port 53)'.

بالإضافة إلى ما سبق، هناك بعض الكلمات الرئيسية `الجوهرية' الخاصة التي لا تتبع النمط: gateway (بوابة)، broadcast (بث)، less (أقل)، greater (أكبر) والتعبيرات الحسابية. كل هذه تم وصفها أدناه.

يتم بناء تعبيرات تصفية أكثر تعقيدًا باستخدام الكلمات and (و)، or (أو) و not (ليس) لدمج الجواهر. على سبيل المثال، `host blort and not port ftp and not port ftp-data'. لتوفير الكتابة، يمكن حذف قوائم المحددات المتطابقة. على سبيل المثال، `tcp dst port ftp or ftp-data or domain' هو بالضبط نفس `tcp dst port ftp or tcp dst port ftp-data or tcp dst port domain'.

الجواهر المسموح بها هي:

dst host host
صحيح إذا كان حقل وجهة IP للحزمة هو host، والذي قد يكون عنوانًا أو اسمًا.
src host host
صحيح إذا كان حقل مصدر IP للحزمة هو host.
host host
صحيح إذا كان مصدر IP أو وجهة IP للحزمة هو host. يمكن إضافة الكلمات الرئيسية، ip، arp، أو rarp قبل أي من تعبيرات المضيف أعلاه، كما في: 
ip host host

وهو ما يعادل:
ether dst ehost
صحيح إذا كان عنوان وجهة Ethernet هو ehost. قد يكون ehost اسمًا من /etc/ethers أو رقمًا (انظر ethers(3N) للتنسيق الرقمي).
ether src ehost
صحيح إذا كان عنوان مصدر Ethernet هو ehost.
ether host ehost
صحيح إذا كان عنوان مصدر Ethernet أو وجهته هو ehost.
gateway host
صحيح إذا استخدمت الحزمة host كبوابة. أي أن عنوان Ethernet المصدر أو الوجهة كان host ولكن لم يكن مصدر IP ولا وجهة IP هو host. يجب أن يكون host اسمًا ويجب العثور عليه في كل من /etc/hosts و /etc/ethers. (تعبير مكافئ هو 
ether host ehost and not host host

والذي يمكن استخدامه مع أسماء أو أرقام لـ host / ehost.)
dst net net
صحيح إذا كان عنوان وجهة IP للحزمة لديه رقم شبكة هو net. قد يكون net اسمًا من /etc/networks أو رقم شبكة (انظر networks(4) للحصول على التفاصيل).
src net net
صحيح إذا كان عنوان مصدر IP للحزمة لديه رقم شبكة هو net.
net net
صحيح إذا كان عنوان مصدر IP أو وجهة IP للحزمة لديه رقم شبكة هو net.
net net mask mask
صحيح إذا كان عنوان IP يتطابق مع net مع قناع شبكة محدد. يمكن تحديده باستخدام src أو dst.
net net/len
صحيح إذا كان عنوان IP يتطابق مع net مع قناع شبكة بعرض len بت. يمكن تحديده باستخدام src أو dst.
dst port port
صحيح إذا كانت الحزمة هي ip/tcp أو ip/udp ولديها قيمة منفذ وجهة هي port. يمكن أن يكون port رقمًا أو اسمًا مستخدمًا في /etc/services (انظر tcp(4P) و udp(4P)). إذا تم استخدام اسم، فسيتم فحص كل من رقم المنفذ والبروتوكول. إذا تم استخدام رقم أو اسم غامض، فسيتم فحص رقم المنفذ فقط (على سبيل المثال، dst port 513 سيطبع كلاً من حركة مرور tcp/login وحركة مرور udp/who، و port domain سيطبع كلاً من tcp/domain و udp/domain traffic).
src port port
صحيح إذا كانت الحزمة لديها قيمة منفذ مصدر هي port.
port port
صحيح إذا كان منفذ مصدر الحزمة أو وجهتها هو port. يمكن إضافة الكلمات الرئيسية، tcp أو udp، قبل أي من تعبيرات المنافذ أعلاه، كما في: 
tcp src port port

والذي يطابق فقط حزم tcp التي يكون منفذ مصدرها port.
less length
صحيح إذا كان طول الحزمة أقل من أو يساوي length. هذا يعادل: 
len <= length.

greater length
صحيح إذا كان طول الحزمة أكبر من أو يساوي length. هذا يعادل: 
len >= length.

ip proto protocol
صحيح إذا كانت الحزمة حزمة IP (انظر ip(4P)) من نوع البروتوكول protocol. يمكن أن يكون protocol رقمًا أو أحد الأسماء tcp، udp أو icmp. لاحظ أن المعرفات tcp و udp هي أيضًا كلمات رئيسية ويجب الهروب منها باستخدام الشرطة المائلة العكسية (\)، والتي هي \\ في shell c.
ip broadcast
صحيح إذا كانت الحزمة حزمة IP للبث. يتحقق من كلا اصطلاحين البث (الكل أصفار والكل واحدات)، ويبحث عن قناع الشبكة الفرعية المحلية.
ip multicast
صحيح إذا كانت الحزمة حزمة IP للبث المتعدد.
ip
اختصار لـ: 
ether proto ip
tcp، udp، icmp
اختصارات لـ: 
ip proto p

حيث p هو أحد البروتوكولات المذكورة أعلاه.
expr relop expr
صحيح إذا كانت العلاقة صحيحة، حيث relop هو واحد من >، <، >=، <=، =، !=، و expr هو تعبير حسابي يتكون من ثوابت عدد صحيح (معبر عنها بتنسيق C قياسي)، والمعاملات الثنائية العادية [+, -, *, /, &, |]، ومعامل طول، ومستخرجات بيانات حزمة خاصة. للوصول إلى البيانات داخل الحزمة، استخدم الصيغة التالية: 
proto [ expr : size ]

Proto هو واحد من ip, tcp, udp أو icmp، ويشير إلى طبقة البروتوكول لعملية الفهرسة. يتم توفير الإزاحة بالبايت، بالنسبة للطبقة البروتوكول المشار إليها، بواسطة expr. Size اختياري ويشير إلى عدد البايتات في الحقل المعني؛ يمكن أن يكون واحدًا أو اثنين أو أربعة، ويكون الافتراضي واحدًا. معامل الطول، المشار إليه بالكلمة الرئيسية len، يعطي طول الحزمة.

على سبيل المثال، `ether[0] & 1 != 0' يلتقط جميع حركة مرور البث المتعدد. التعبير `ip[0] & 0xf != 5' يلتقط جميع حزم IP مع خيارات. التعبير `ip[6:2] & 0x1fff = 0' يلتقط فقط datagrams غير المجزأة و frag zero لـ datagrams المجزأة. يتم تطبيق هذا التحقق ضمنيًا على عمليات فهرسة tcp و udp. على سبيل المثال، tcp[0] يعني دائمًا البايت الأول من رأس TCP، ولا يعني أبدًا البايت الأول من شظية فاصلة.

يمكن دمج الجواهر باستخدام:

مجموعة مقوسة من الجواهر والعوامل (الأقواس خاصة بالـ Shell ويجب الهروب منها).
النفي (`!' أو `not').
الربط (`&&' أو `and').
التناوب (`||' أو `or').

للنفي أعلى أسبقية. التناوب والربط لهما نفس الأسبقية ويرتبطان من اليسار إلى اليمين. لاحظ أن رموز and الصريحة، وليس التجاور، مطلوبة الآن للربط.

إذا تم تقديم معرف بدون كلمة رئيسية، فسيتم افتراض أحدث كلمة رئيسية. على سبيل المثال، 

not host vs and ace
هو اختصار لـ 
not host vs and host ace
والذي لا ينبغي الخلط بينه وبين 
not ( host vs or ace )

يمكن تمرير وسيطات التعبير إلى ngrep إما كوسيط واحد أو كوسيطات متعددة، أيهما أكثر ملاءمة. بشكل عام، إذا كان التعبير يحتوي على رموز خاصة بالـ Shell، فمن الأسهل تمريره كوسيط واحد، محاط بعلامات اقتباس. يتم ربط الوسيطات المتعددة بمسافات قبل تحليلها.

التشخيص

الأخطاء من ngrep و libpcap و GNU regex library يتم إخراجها جميعًا إلى stderr.

حالة الخروج

تخرج الأداة المساعدة ngrep بإحدى القيم التالية:


0 تم مطابقة إطار واحد أو أكثر.
1 لم يتم مطابقة أي إطارات.
2 حدث خطأ.
3+ الجحيم يتجمد، اذهب!

NAME

ngrep - network grep

SYNOPSIS

ngrep [ options ] [ expression ]

DESCRIPTION

ngrep is a pcre-aware tool that attempts to match a given regular expression against the data payload of network packets.

In many ways, ngrep is like grep. However, instead of reading from files or standard input, ngrep reads from network interfaces.

ngrep allows you to specify a regular expression that will be used to match against the packet payload. If the regular expression matches, then ngrep will display the contents of the packet on the screen.

ngrep can also be used to send packets to standard output, which can then be piped to another program.

ngrep supports the same regular expression syntax as Perl Compatible Regular Expressions (PCRE).

OPTIONS

The following options are available:

-A N
Display N packets that follow the matching packet.
-a
Dumps a comparison of a packet's data on standard output.
-B N
Display N packets that precede the matching packet.
-d dev
Listen on interface dev. If not specified, ngrep will search for the first available interface that is not the loopback interface.
-e
Tell ngrep to display packets that do NOT match.
-F filter
Reads filter from file filter. This is useful for complex filters.
-G
Don't filter packets based on their direction. By default, ngrep only shows packets that are coming towards you.
-i
Ignore case in the regular expression matching.
-I
Read packet data from standard input.
-j
Dump packet data in hexadecimal format.
-l
Do not print a newline after each match.
-m N
Stop reading packets after N matches.
-N
Do not display the matching packet.
-O file
Write raw packets to file.
-p
Do not put the interface into promiscuous mode. This is useful if you are only interested in traffic to or from your machine.
-q
Quiet mode. Do not print packet contents to standard output.
-Q
Don't filter packets based on their direction. By default, ngrep only shows packets that are coming towards you.
-r
Recursively search subdirectories.
-s
Do not terminate ngrep on control-C.
-S
Display the packet on standard output without modification.
-t
Display packet timestamps.
-v
Invert the sense of matching, to select non-matching packets.
-V
Print version information and exit.
-w
Wrap regular expression matches.
-W
Display packet data in hexadecimal format.
-x
Display packet data in hexadecimal format.
-X
Display packet data in hexadecimal format.

DIAGNOSTICS

ngrep emits diagnostic messages to standard error.

EXIT STATUS

The exit status is 0 if any matches were found, and 1 otherwise. An exit status of 2 indicates an error.

الاسم

ngrep - شبكة grep

الملخص

ngrep [ خيارات ] [ تعبير ]

الوصف

ngrep هي أداة مدركة لـ pcre تحاول مطابقة تعبير عادي معطى مع حمولة بيانات حزم الشبكة.

من نواحٍ عديدة، ngrep تشبه grep. ومع ذلك، بدلاً من القراءة من الملفات أو الإدخال القياسي، تقرأ ngrep من واجهات الشبكة.

تسمح لك ngrep بتحديد تعبير عادي سيتم استخدامه للمطابقة مع حمولة الحزمة. إذا تطابق التعبير العادي، فستعرض ngrep محتويات الحزمة على الشاشة.

يمكن أيضًا استخدام ngrep لإرسال الحزم إلى الإخراج القياسي، والتي يمكن بعد ذلك توجيهها إلى برنامج آخر.

تدعم ngrep نفس بناء جملة التعبير العادي مثل التعبيرات العادية المتوافقة مع Perl (PCRE).
