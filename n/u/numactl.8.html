NUMACTL(8) دليل مسؤولي لينكس NUMACTL(8)

الاسم

numactl - التحكم في سياسة NUMA للعمليات أو الذاكرة المشتركة

الملخص

numactl [ --all ] [ --balancing ] [ --interleave nodes ] [ --weighted-interleave nodes ] [ --preferred node ] [ --preferred-many nodes ] [ --membind nodes ] [ --cpunodebind nodes ] [ --physcpubind cpus ] [ --localalloc ] [--] command {arguments ...}
numactl --show
numactl --hardware [--cpu-compress]
numactl --version
numactl [ --huge ] [ --offset offset ] [ --shmmode shmmode ] [ --length length ] [ --strict ]
[ --shmid id ] --shm shmkeyfile | --file tmpfsfile
[ --touch ] [ --dump ] [ --dump-nodes ] memory policy

الوصف

يقوم numactl بتشغيل العمليات بسياسة جدولة NUMA أو سياسة توزيع ذاكرة محددة. يتم تعيين السياسة للأمر وتورثها جميع عملياته الفرعية. بالإضافة إلى ذلك، يمكنه تعيين سياسة مستمرة لشرائح الذاكرة المشتركة أو الملفات.

استخدم -- قبل الأمر إذا كنت تستخدم خيارات الأمر التي قد تلتبس مع خيارات numactl.

يمكن تحديد nodes كـ N,N,N أو N-N أو N,N-N أو N-N,N-N وهكذا. يمكن تحديد nodes النسبية كـ +N,N,N أو +N-N أو +N,N-N وهكذا. تشير + إلى أن أرقام العقد نسبية إلى مجموعة العقد المسموح بها للعملية في مجموعة وحداتها (cpuset) الحالية. يشير ترميز !N-N إلى عكس N-N، بمعنى جميع العقد باستثناء N-N. إذا تم استخدامه مع ترميز +، قم بتحديد !+N-N. عندما يتم تحديد same، يتم استخدام قناع العقد السابق المحدد في سطر الأوامر. يعني all جميع العقد في مجموعة وحدات المعالجة الحالية.

بدلاً من رقم، يمكن أن تكون العقدة أيضًا:

netdev:DEV العقدة المتصلة بجهاز الشبكة DEV.
file:PATH العقدة الخاصة بجهاز الكتلة لـ PATH.
ip:HOST عقدة جهاز الشبكة لـ HOST
block:PATH عقدة جهاز الكتلة PATH
pci:[seg:]bus:dev[:func] عقدة جهاز PCI.

إعدادات السياسة هي:
--all, -a
إلغاء تعيين وعي مجموعة وحدات المعالجة الافتراضي، حتى يتمكن المستخدم من استخدام جميع وحدات المعالجة / العقد الممكنة لإعدادات السياسة التالية.
--interleave=nodes, -i nodes
تعيين سياسة تداخل الذاكرة. سيتم تخصيص الذاكرة باستخدام التوزيع الدوري على nodes. عندما لا يمكن تخصيص الذاكرة على هدف التداخل الحالي، سيتم الرجوع إلى عقد أخرى. يمكن تحديد عقد متعددة في --interleave، --membind و --cpunodebind.
--weighted-interleave=nodes, -w nodes
تعيين سياسة تداخل الذاكرة الموزونة. سيتم تخصيص الذاكرة باستخدام النسبة الموزونة لكل عقدة، والتي يمكن قراءتها من /sys/kernel/mm/mempolicy/weighted_interleave/node*. عندما لا يمكن تخصيص الذاكرة على هدف التداخل الحالي، سيتم الرجوع إلى عقد أخرى.
--membind=nodes, -m nodes
تخصيص الذاكرة فقط من العقد. سيفشل التخصيص عندما لا تتوفر ذاكرة كافية في هذه العقد. يمكن تحديد nodes كما هو موضح أعلاه.
--cpunodebind=nodes, -N nodes
تشغيل command فقط على وحدات المعالجة الخاصة بـ nodes. لاحظ أن العقد يمكن أن تتكون من وحدات معالجة متعددة. يمكن تحديد nodes كما هو موضح أعلاه.
--physcpubind=cpus, -C cpus
تشغيل process فقط على cpus. يقبل هذا أرقام وحدات المعالجة كما تظهر في حقول processor في /proc/cpuinfo، أو وحدات معالجة نسبية كما في نسبي إلى مجموعة وحدات المعالجة الحالية. يمكنك تحديد "all"، مما يعني جميع وحدات المعالجة في مجموعة وحدات المعالجة الحالية. يمكن تحديد وحدات المعالجة cpus الفعلية كـ N,N,N أو N-N أو N,N-N أو N-N,N-N وهكذا. يمكن تحديد وحدات المعالجة cpus النسبية كـ +N,N,N أو +N-N أو +N,N-N وهكذا. تشير + إلى أن أرقام وحدات المعالجة نسبية إلى مجموعة وحدات المعالجة المسموح بها للعملية في مجموعة وحداتها الحالية. يشير ترميز !N-N إلى عكس N-N، بمعنى جميع وحدات المعالجة باستثناء N-N. إذا تم استخدامه مع ترميز +، قم بتحديد !+N-N.
--localalloc, -l
محاولة التخصيص على العقدة الحالية للعملية، ولكن إذا لم يكن من الممكن تخصيص الذاكرة هناك، فسيتم الرجوع إلى عقد أخرى.
--preferred=node, -p node
تفضيل تخصيص الذاكرة على node، ولكن إذا لم يكن من الممكن تخصيص الذاكرة هناك، فسيتم الرجوع إلى عقد أخرى. يأخذ هذا الخيار رقم عقدة واحدة فقط. يمكن استخدام الترميز النسبي.
--balancing, -b
تمكين توازن NUMA الخاص بنواة لينكس للعملية إذا كانت مدعومة من قبل النواة. يجب استخدام هذا فقط مع --membind, -m فقط، وإلا فسيتم تجاهله.
--preferred-many=nodes, -P nodes
تفضيل تخصيص الذاكرة على nodes، ولكن إذا لم يكن من الممكن تخصيص الذاكرة هناك، فسيتم الرجوع إلى عقد أخرى. يأخذ هذا الخيار قناعًا من العقد المفضلة حيث تعتبر العقدة الأقرب إلى المحلية الأكثر تفضيلاً. يمكن استخدام الترميز النسبي.
--show, -s
عرض إعدادات سياسة NUMA للعملية الحالية.
--hardware, -H
عرض مخزون العقد المتاحة في النظام. عند تعيين الخيار --cpu-compress، عرض نطاقات وحدة المعالجة المركزية. هذا ليس افتراضيًا ولا يكسر أي نصوص برمجية موجودة.
يمكن لـ Numactl إعداد سياسة لشريحة ذاكرة مشتركة SYSV أو ملف في shmfs/hugetlbfs.
--version
طباعة إصدار حزمة numactl والخروج.
إعدادات السياسة التالية مستمرة وسيتم استخدامها بواسطة
جميع عمليات التعيين من تلك الذاكرة المشتركة. ترتيب الخيارات مهم هنا. يجب أن يتضمن التحديد على الأقل أحد الخيارات --shm, --shmid, --file لتحديد شريحة الذاكرة المشتركة أو الملف وسياسة ذاكرة كما هو موضح أعلاه ( --interleave, --localalloc, --preferred, --preferred-many, --membind ).
--huge
عند إنشاء شريحة ذاكرة مشتركة SYSV، استخدم صفحات كبيرة. صالح فقط قبل --shmid أو --shm
--offset
تحديد الإزاحة داخل شريحة الذاكرة المشتركة. الافتراضي 0. الوحدات الصالحة هي m (لـ MB)، g (لـ GB)، k (لـ KB)، وإلا فإنها تحدد البايتات.
--strict
إعطاء خطأ عندما تكون صفحة في المنطقة المطبقة السياسة في شريحة الذاكرة المشتركة قد تم استدعاؤها بالفعل بسياسة متعارضة. الافتراضي هو تجاهل ذلك بصمت.
--shmmode shmmode
صالح فقط قبل --shmid أو --shm عند إنشاء شريحة ذاكرة مشتركة، قم بتعيينها إلى الوضع الرقمي shmmode.
--length length
تطبيق السياسة على نطاق length في شريحة الذاكرة المشتركة أو جعل طول الشريحة طويلاً. الافتراضي هو استخدام الطول المتبقي. مطلوب عند إنشاء شريحة ذاكرة مشتركة وتحديد طول الشريحة الجديدة عندها. الوحدات الصالحة هي m (لـ MB)، g (لـ GB)، k (لـ KB)، وإلا فإنها تحدد البايتات.
--shmid id
إنشاء أو استخدام شريحة ذاكرة مشتركة بالمعرف الرقمي id
--shm shmkeyfile
إنشاء أو استخدام شريحة ذاكرة مشتركة، مع إنشاء المعرف باستخدام ftok(3) من shmkeyfile
--file tmpfsfile
تعيين سياسة لملف في tmpfs أو hugetlbfs
