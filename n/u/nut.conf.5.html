NAME

nut.conf – configuration file for Network UPS Tools (NUT)

DESCRIPTION

The nut.conf file contains global settings for the Network UPS Tools suite. These settings control the overall behavior of NUT, including which components should be started and how they should interact.

IMPORTANT NOTES

The settings in this file are read by the NUT init scripts (e.g. /etc/init.d/nut) to determine which daemons (upsd, upsmon) and drivers to start. This file is not intended to be used by the daemons directly.

The following directives are supported:

DIRECTIVES

MODE
This directive specifies the operational mode of NUT. Possible values include:
none: Disable NUT entirely. No daemons or drivers will be started.
standalone: Run NUT in standalone mode, typically on a system with a directly connected UPS. This mode usually starts the relevant UPS driver and upsd.
netclient: Run NUT as a client to a remote NUT server. This mode typically starts upsmon to monitor the remote server.
netserv: Run NUT as a network server. This mode typically starts upsd and the relevant UPS driver(s).
auto: Attempt to automatically determine the appropriate mode based on the system configuration and presence of UPS devices. This is often the default if not specified.
RUN_AS_USER
Specifies the user account under which the NUT daemons should run. Defaults to the nut user if not specified.
UPSD_OPTIONS
Additional command-line options to pass to the upsd daemon when it is started.
UPSMON_OPTIONS
Additional command-line options to pass to the upsmon daemon when it is started.
POWEROFF_WAIT
If specified, this directive sets a delay (in minutes or hours, e.g. 15m, 1h) after which the system should be powered off if the UPS is critically low on battery. This is primarily used by upsmon.

It is important to configure NUT appropriately for your specific environment. Incorrect configuration can lead to NUT failing to start, or worse, to unexpected system shutdowns or inability to shut down.

For platforms that do not have robust OS service management frameworks (like systemd, upstart, etc.), NUT might provide its own basic service management capabilities. However, it is generally recommended to integrate NUT with the system's native service manager for reliable operation. This can prevent issues where NUT might not report loudly if they could NOT do so (e.g. running on a system without a framework, or misconfigured so they could not report and the OS could eventually restart the false-positively identified "unresponsive" service.

Currently such reports, done by default, help troubleshoot service start-up and highlight that NUT sources (or package build) did not take advantage of tighter OS service management framework integration (if one exists, so that developers could focus on adding that). Reasons to set this flag could include platforms without such a framework and not expecting one, although nagging your favourite OS or contributing development to make it better is also a way.

EXAMPLE

   # /etc/nut/nut.conf.  See nut.conf(5)
   MODE=none
   UPSD_OPTIONS=""
   UPSMON_OPTIONS=""
   # POWEROFF_WAIT=15m

INTEGRATION

An init script, such as /etc/init.d/nut, is expected to source this file in order to determine which components have to be started.
