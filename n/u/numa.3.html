The functions described here manage NUMA (Non-Uniform Memory Access) memory allocation and processor affinity. The library allows users to query NUMA topology, control memory placement, and set processor affinity for threads and processes. Several functions interact with the concept of CPUs associated with NUMA nodes, specifically functions like de_to_cpu_update(), numa_node_of_cpu(), numa_bind(), numa_run_on_node(), numa_run_on_node_mask(), numa_run_on_node_mask_all(), and numa_get_run_node_mask(). These functions deal with the CPUs associated with numa nodes. See the descriptions below for more information.

\n

Some of these functions accept or return a pointer to struct bitmask. A struct bitmask controls a bit map of arbitrary length containing a bit representation of nodes. The predefined variable numa_all_nodes_ptr points to a bit mask that has all available nodes set; numa_no_nodes_ptr points to the empty set.

\n

Before any other calls in this library can be used numa_available() must be called. If it returns -1, all other functions in this library are undefined.

\n

numa_max_possible_node() returns the number of the highest possible node in a system. In other words, the size of a kernel type nodemask_t (in bits) minus 1. This number can be gotten by calling numa_num_possible_nodes() and subtracting 1.

\n

numa_num_possible_nodes() returns the size of kernel's node mask (kernel type nodemask_t). In other words, large enough to represent the maximum number of nodes that the kernel can handle. This will match the kernel's MAX_NUMNODES value. This count is derived from /proc/self/status, field Mems_allowed.

\n

numa_max_node() returns the highest node number available on the current system. (See the node numbers in /sys/devices/system/node/ ). Also see numa_num_configured_nodes().

\n

numa_num_configured_nodes() returns the number of memory nodes in the system. This count includes any nodes that are currently disabled. This count is derived from the node numbers in /sys/devices/system/node. (Depends on the kernel being configured with /sys (CONFIG_SYSFS)).

\n

numa_get_mems_allowed() returns the mask of nodes from which the process is allowed to allocate memory in it's current cpuset context. Any nodes that are not included in the returned bitmask will be ignored in any of the following libnuma memory policy calls.

\n

numa_num_configured_cpus() returns the number of cpus in the system. This count includes any cpus that are currently disabled. This count is derived from the cpu numbers in /sys/devices/system/cpu. If the kernel is configured without /sys (CONFIG_SYSFS=n) then it falls back to using the number of online cpus.

\n

numa_all_nodes_ptr points to a bitmask that is allocated by the library with bits representing all nodes on which the calling task may allocate memory. This set may be up to all nodes on the system, or up to the nodes in the current cpuset. The bitmask is allocated by a call to numa_allocate_nodemask() using size numa_max_possible_node(). The set of nodes to record is derived from /proc/self/status, field \"Mems_allowed\". The user should not alter this bitmask.

\n

numa_no_nodes_ptr points to a bitmask that is allocated by the library and left all zeroes. The bitmask is allocated by a call to numa_allocate_nodemask() using size numa_max_possible_node(). The user should not alter this bitmask.

\n

numa_all_cpus_ptr points to a bitmask that is allocated by the library with bits representing all cpus on which the calling task may execute. This set may be up to all cpus on the system, or up to the cpus in the current cpuset. The bitmask is allocated by a call to numa_allocate_cpumask() using size numa_num_possible_cpus(). The set of cpus to record is derived from /proc/self/status, field \"Cpus_allowed\". The user should not alter this bitmask.

\n

numa_num_task_cpus() returns the number of cpus that the calling task is allowed to use. This count is derived from the map /proc/self/status, field \"Cpus_allowed\". Also see the bitmask numa_all_cpus_ptr.

\n

numa_num_task_nodes() returns the number of nodes on which the calling task is allowed to allocate memory. This count is derived from the map /proc/self/status, field \"Mems_allowed\". Also see the bitmask numa_all_nodes_ptr.

\n

numa_parse_bitmap() parses line , which is a character string such as found in /sys/devices/system/node/nodeN/cpumap into a bitmask structure. The string contains the hexadecimal representation of a bit map. The bitmask may be allocated with numa_allocate_cpumask(). Returns 0 on success. Returns -1 on failure. This function is probably of little use to a user application, but it is used by libnuma internally.

\n

numa_parse_nodestring() parses a character string list of nodes into a bit mask. The bit mask is allocated by numa_allocate_nodemask(). The string is a comma-separated list of node numbers or node ranges. A leading ! can be used to indicate \"not\" this list (in other words, all nodes except this list), and a leading + can be used to indicate that the node numbers in the list are relative to the task's cpuset. The string can be \"all\" to specify all ( numa_num_task_nodes() ) nodes. Node numbers are limited by the number in the system. See numa_max_node() and numa_num_configured_nodes().\n
\nExamples: 1-5,7,10 !4-5 +0-3\n
\nIf the string is of 0 length, bitmask numa_no_nodes_ptr is returned. Returns 0 if the string is invalid.

\n

numa_parse_nodestring_all() is similar to numa_parse_nodestring , but can parse all possible nodes, not only current nodeset.

\n

numa_parse_cpustring() parses a character string list of cpus into a bit mask. The bit mask is allocated by numa_allocate_cpumask(). The string is a comma-separated list of cpu numbers or cpu ranges. A leading ! can be used to indicate \"not\" this list (in other words, all cpus except this list), and a leading + can be used to indicate that the cpu numbers in the list are relative to the task's cpuset. The string can be \"all\" to specify all ( numa_num_task_cpus() ) cpus. Cpu numbers are limited by the number in the system. See numa_num_task_cpus() and numa_num_configured_cpus().\n
\nExamples: 1-5,7,10 !4-5 +0-3\n
\nReturns 0 if the string is invalid.

\n

numa_parse_cpustring_all() is similar to numa_parse_cpustring , but can parse all possible cpus, not only current cpuset.

\n

numa_node_size() returns the memory size of a node. If the argument freep is not NULL, it used to return the amount of free memory on the node. On error it returns -1.

\n

numa_node_size64() works the same as numa_node_size(). This is useful on 32-bit architectures with large nodes.

\n

numa_preferred() returns the preferred node of the current task. This is the node on which the kernel preferably allocates memory, unless some other policy overrides this.

\n

numa_has_preferred_many() Returns > 0 if the system supports multiple preferred nodes.

\n

numa_preferred_many() Returns the current set of preferred nodes. This implies the empty set when the policy isn't one used for preference (PREFERRED, PREFERRED_MANY, BIND). The caller is responsible for freeing the mask with numa_bitmask_free().

\n

numa_set_preferred() sets the preferred node for the current task to node. The system will attempt to allocate memory from the preferred node, but will fall back to other nodes if no memory is available on the the preferred node. Passing a node of -1 argument specifies local allocation and is equivalent to calling numa_set_localalloc().

\n

numa_set_preferred_many() sets the preferred set of nodes for the current task to nodemask. This is similar to numa_set_preferred() with the exception that it utilizes a different kernel interface to specify multiple preferred nodes. The caller is responsible for freeing the mask with numa_bitmask_free().

\n

numa_has_home_node() Returns 1 if the system supports setting home_node for mbind and preferred_many.

\n

numa_set_mempolicy_home_node() set the home node for a VMA policy present in the task's address range. A home node is the NUMA node closest to which page allocation will come from. Users should use it after setting up a mbind or perfered_many memory policy for the specified range.

\n

numa_get_interleave_mask() returns the current interleave mask if the task's memory allocation policy is page interleaved. Otherwise, this function returns an empty mask.

\n

numa_set_interleave_mask() sets the memory interleave mask for the current task to nodemask. All new memory allocations are page interleaved over all nodes in the interleave mask. Interleaving can be turned off again by passing an empty mask (numa_no_nodes). The page interleaving only occurs on the actual page fault that puts a new page into the current address space. It is also only a hint: the kernel will fall back to other nodes if no memory is available on the interleave target.

\n

numa_interleave_memory() interleaves size bytes of memory page by page from start on nodes specified in nodemask. The size argument will be rounded up to a multiple of the system page size. If nodemask contains nodes that are externally denied to this process, this call will fail. This is a lower level function to interleave allocated but not yet faulted in memory. Not yet faulted in means the memory is allocated using mmap(2) or shmat(2), but has not been accessed by the current process yet. The memory is page interleaved to all nodes specified in nodemask. Normally numa_alloc_interleaved() should be used for private memory instead, but this function is useful to handle shared memory areas. To be useful the memory area should be several megabytes at least (or tens of megabytes of hugetlbfs mappings) If the numa_set_strict() flag is true then the operation will cause a numa_error if there were already pages in the mapping that do not follow the policy.

\n

numa_bind() binds the current task and its children to the nodes specified in nodemask. They will only run on the CPUs of the specified nodes and only be able to allocate memory from them. This function is equivalent to calling numa_run_on_node_mask(nodemask) followed by numa_set_membind(nodemask). If tasks should be bound to individual CPUs inside nodes consider using numa_node_to_cpus and the sched_setaffinity(2) syscall.

\n

numa_set_localalloc() sets the memory allocation policy for the calling task to local allocation. In this mode, the preferred node for memory allocation is effectively the node where the task is executing at the time of a page allocation.

numa_alloc() يخصص size بايت من الذاكرة باستخدام سياسة NUMA الحالية. سيتم تقريب الوسيط size إلى مضاعف حجم صفحة النظام. هذه الوظيفة بطيئة نسبيًا مقارنة بعائلة وظائف malloc(3). يجب تحرير الذاكرة باستخدام numa_free(). في حالة حدوث أخطاء، يتم إرجاع NULL.

numa_realloc() يغير حجم منطقة الذاكرة المشار إليها بواسطة old_addr من old_size إلى new_size. يجب أن تكون منطقة الذاكرة المشار إليها بواسطة old_addr قد تم تخصيصها باستخدام إحدى وظائف numa_alloc*. سيتم تقريب new_size إلى مضاعف حجم صفحة النظام. ستظل محتويات منطقة الذاكرة دون تغيير بحد أدنى من الأحجام القديمة والجديدة؛ ستكون الذاكرة المخصصة حديثًا غير مهيأة. سيتم الحفاظ على سياسة الذاكرة (وروابط العقد) المرتبطة بمنطقة الذاكرة الأصلية في المنطقة المعاد حجمها. على سبيل المثال، إذا تم تخصيص المنطقة الأولية باستدعاء لـ numa_alloc_onnode()، فسيتم تخصيص الصفحات الجديدة (إذا تم توسيع المنطقة) على نفس العقدة. ومع ذلك، إذا لم يتم تعيين سياسة ذاكرة للمنطقة الأصلية، فلا يمكن لـ numa_realloc() ضمان تخصيص الصفحات الجديدة على نفس العقدة. عند النجاح، يتم إرجاع عنوان المنطقة المعاد حجمها (والذي قد يختلف عن عنوان المنطقة الأولية)، وإلا يتم إرجاع NULL ويتم تعيين errno للإشارة إلى الخطأ. المؤشر الذي تم إرجاعه بواسطة numa_realloc() مناسب للتمرير إلى numa_free().

numa_free() يحرر size بايت من الذاكرة بدءًا من start، والتي تم تخصيصها بواسطة وظائف numa_alloc_* المذكورة أعلاه. سيتم تقريب الوسيط size إلى مضاعف حجم صفحة النظام.

numa_run_on_node() تشغيل المهمة الحالية وأطفالها على عقدة محددة. لن يتم ترحيلها إلى وحدات معالجة مركزية أخرى حتى يتم إعادة تعيين تقييد العقدة باستدعاء جديد لـ numa_run_on_node_mask(). السماح بالمرور -1 يسمح للنواة بالجدولة على جميع العقد مرة أخرى. عند النجاح، يتم إرجاع 0؛ عند حدوث خطأ، يتم إرجاع -1، ويتم تعيين errno للإشارة إلى الخطأ.

numa_distance() الإبلاغ عن المسافة في طوبولوجيا الجهاز بين عقدتين. العوامل هي مضاعف 10. ترجع 0 عندما لا يمكن تحديد المسافة. العقدة لها مسافة 10 لنفسها. يتطلب الإبلاغ عن المسافة إصدار نواة Linux 2.6.10 أو أحدث.

numa_set_bind_policy() يحدد ما إذا كانت الاستدعاءات التي تربط الذاكرة بعقدة محددة يجب أن تستخدم السياسة المفضلة أو السياسة الصارمة. السياسة المفضلة تسمح للنواة بتخصيص الذاكرة على عقد أخرى عندما لا يكون هناك ما يكفي من المساحة الحرة على العقدة المستهدفة. ستفشل السياسة الصارمة في التخصيص في هذه الحالة. تعيين الوسيط إلى يشير إلى صارمة، 0 مفضلة. لاحظ أن تحديد أكثر من عقدة غير صارمة قد يستخدم العقدة الأولى فقط في بعض إصدارات النواة.

numa_set_strict() يحدد علامة تشير إلى ما إذا كانت الوظائف التي تقوم بالتخصيص على عقد محددة يجب أن تستخدم سياسة صارمة. تعني صارمة أن التخصيص سيفشل إذا لم يكن من الممكن تخصيص الذاكرة على العقدة المستهدفة. التشغيل الافتراضي هو العودة إلى عقد أخرى. هذا لا ينطبق على التداخل والافتراضي.

numa_get_interleave_node() يستخدمه libnuma داخليًا. ربما ليس مفيدًا لتطبيقات المستخدم. يستخدم علامة MPOL_F_NODE من استدعاء نظام get_mempolicy، والتي لم يتم تصميمها للاستخدام التطبيقي (قد يتغير تشغيلها أو تتم إزالته بالكامل في إصدارات النواة المستقبلية). انظر get_mempolicy(2).

numa_pagesize() يرجع عدد البايتات في الصفحة. هذه الوظيفة هي ببساطة بديل سريع للاستدعاءات المتكررة لاستدعاء نظام getpagesize. انظر getpagesize(2).

numa_sched_getaffinity() يسترد قناع بت لوحدات المعالجة المركزية التي يمكن للمهمة التشغيل عليها. المهمة محددة بواسطة pid. يرجع قيمة الإرجاع لاستدعاء نظام sched_getaffinity. انظر sched_getaffinity(2). يجب أن يكون قناع البت بحجم يكفي على الأقل لهيكل قناع النواة. استخدم numa_allocate_cpumask() لتخصيصه. اختبر البتات في القناع عن طريق استدعاء numa_bitmask_isbitset().

numa_sched_setaffinity() يحدد وحدات المعالجة المركزية المسموح بها لمهمة معينة لتلك الوحدات المحددة في mask. المهمة محددة بواسطة pid. يرجع قيمة الإرجاع لاستدعاء نظام sched_setaffinity. انظر sched_setaffinity(2). يمكنك تخصيص قناع البت باستخدام numa_allocate_cpumask(). أو قد يكون قناع البت أصغر من هيكل قناع النواة. على سبيل المثال، استدعاء numa_bitmask_alloc() باستخدام الحد الأقصى لعدد وحدات المعالجة المركزية من numa_num_configured_cpus(). قم بتعيين البتات في القناع عن طريق استدعاء numa_bitmask_setbit().

numa_node_to_cpus() يحول رقم عقدة إلى قناع بت لوحدات المعالجة المركزية. يجب على المستخدم تمرير هيكل قناع بت مع مخزن مؤقت للقناع طويل بما يكفي لتمثيل جميع وحدات المعالجة المركزية الممكنة. استخدم numa_allocate_cpumask() لإنشائه. إذا لم يكن قناع البت طويلاً بما يكفي، فسيتم تعيين errno على ERANGE وسيتم إرجاع -1. عند النجاح، يتم إرجاع 0.

numa_node_to_cpu_update() علامة قناع بت وحدات المعالجة المركزية لجميع العقد قديمة، ثم احصل على أحدث قناع بت عن طريق استدعاء numa_node_to_cpus() هذا يسمح بتحديث حالة libnuma بعد حدث CPU hotplug. التطبيق مسؤول عن اكتشاف أحداث CPU hotplug.

numa_node_of_cpu() يرجع العقدة التي تنتمي إليها وحدة معالجة مركزية. إذا قدم المستخدم وحدة معالجة مركزية غير صالحة، فسيتم تعيين errno على EINVAL وسيتم إرجاع -1.

numa_allocate_cpumask () يرجع قناع بت بحجم يساوي قناع النواة (نوع النواة cpumask_t). بعبارة أخرى، كبير بما يكفي لتمثيل NR_CPUS من وحدات المعالجة المركزية. يمكن الحصول على هذا العدد من وحدات المعالجة المركزية عن طريق استدعاء numa_num_possible_cpus(). قناع البت مملوء بالصفر.

numa_free_cpumask يحرر cpumask تم تخصيصه سابقًا بواسطة numa_allocate_cpumask.

numa_allocate_nodemask() يرجع قناع بت بحجم يساوي قناع النواة (نوع النواة nodemask_t). بعبارة أخرى، كبير بما يكفي لتمثيل MAX_NUMNODES من العقد. يمكن الحصول على هذا العدد من العقد عن طريق استدعاء numa_num_possible_nodes(). قناع البت مملوء بالصفر.

numa_free_nodemask() يحرر nodemask تم تخصيصه سابقًا بواسطة numa_allocate_nodemask().

numa_bitmask_alloc() يخصص هيكل قناع بت وقناع البت المرتبط به. تحتوي الذاكرة المخصصة لقناع البت على كلمات كافية (نوع unsigned long) لاحتواء n بت. قناع البت مملوء بالصفر. يشير هيكل قناع البت إلى قناع البت ويحتوي على قيمة n.

numa_bitmask_clearall() يضبط جميع البتات في قناع البت إلى 0. يشير هيكل قناع البت إلى قناع البت ويحتوي على حجمه (bmp->size). يتم دائمًا إرجاع قيمة bmp. لاحظ أن numa_bitmask_alloc() ينشئ قناع بت مملوءًا بالصفر.
