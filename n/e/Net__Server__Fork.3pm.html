Net__Server__Fork(3pm)

الحزمة: perl-net-server

التراخيص: PerlArtistic, GPL

Net::Server::Fork(3) وثائق Perl التي ساهم بها المستخدم Net::Server::Fork(3)

الاسم

Net::Server::Fork - شخصية Net::Server

الملخص

use base qw(Net::Server::Fork);
sub process_request {
    #...code...
}
__PACKAGE__->run();

الوصف

يرجى قراءة الـ pod الخاص بـ Net::Server أولاً. هذه الوحدة هي شخصية، أو امتداد، أو فئة فرعية لوحدة Net::Server.

ترتبط هذه الشخصية بمنفذ واحد أو أكثر ثم تنتظر اتصال العميل. عندما يتم تلقي اتصال، يقوم الخادم بعمل fork لطفل. يعالج الطفل الطلب ثم يغلق.

باستثناء الإشارات بين الوالد والطفل، ستعمل هذه الوحدة (بوظائف أساسية) على أنظمة Win32.

الوسائط

check_for_dead
عدد الثواني للانتظار قبل البحث عن الأطفال المتوفين. يحدث هذا فقط إذا تم الوصول إلى الحد الأقصى لعدد عمليات الأطفال (max_servers). القيمة الافتراضية هي 60 ثانية.
max_servers
الحد الأقصى لعدد الأطفال المراد عمل fork لهم. لن يقبل الخادم الاتصالات حتى تكون هناك أطفال مجانيون. القيمة الافتراضية هي 256 طفلاً.
max_dequeue
الحد الأقصى لعدد عمليات إلغاء الانتظار للبدء. إذا تم إعطاء قيمة صفر أو undef، فلن يتم بدء عمليات إلغاء الانتظار. سيتم التحقق من عدد عمليات إلغاء الانتظار قيد التشغيل بواسطة المتغير check_for_dead.
check_for_dequeue
عدد الثواني للانتظار قبل عمل fork لعملية إلغاء الانتظار. المقصود هو استخدام عملية إلغاء الانتظار للعناية بعناصر مثل قوائم البريد. إذا تم إعطاء قيمة undef، فلن يتم بدء عمليات إلغاء الانتظار.

ملف الإعداد

انظر Net::Server.

تدفق العملية

يتبع تدفق العملية Net::Server حتى مرحلة post_accept. في هذه النقطة، يتم عمل fork لطفل. يكون الوالد قادرًا على الفور على الانتظار لطلب آخر. يعالج الطفل الطلب ثم يخرج.

الخطافات

يحتوي خادم Fork على الخطافات التالية بالإضافة إلى الخطافات التي توفرها الفئة الأساسية Net::Server. انظر Net::Server

"$self->pre_accept_hook()"
يحدث هذا الخطاف قبل استدعاء accept مباشرة.
"$self->post_accept_hook()"
يحدث هذا الخطاف في الطفل بعد accept و fork.
"$self->run_dequeue()"
يتم استدعاء هذا الخطاف فقط بالتزامن مع إعداد check_for_dequeue.

النشر الساخن

منذ الإصدار 2.000، قبل خادم Fork إشارات TTIN و TTOU. عند تلقي TTIN، يتم زيادة max_servers بمقدار 1. إذا تم تلقي إشارة TTOU، يتم تقليل max_servers بمقدار 1. هذا يسمح بضبط عدد عمليات المعالجة دون الحاجة إلى إعادة تشغيل الخادم.
