الاسم

Net::SNMP - واجهة موجهة للكائنات لـ SNMP

ملخص

وحدة Net::SNMP تنفذ واجهة موجهة للكائنات لبروتوكول إدارة الشبكة البسيط (SNMP). يمكن لتطبيقات Perl استخدام الوحدة لاسترداد أو تحديث المعلومات على مضيف بعيد باستخدام بروتوكول SNMP. تدعم الوحدة SNMP الإصدار 1، و SNMP الإصدار 2c (SNMPv2 المستند إلى المجتمع)، و SNMP الإصدار 3. تفترض وحدة Net::SNMP أن لدى المستخدم فهمًا أساسيًا لبروتوكول إدارة الشبكة البسيط والمفاهيم ذات الصلة بإدارة الشبكة.

الوصف

تجرد وحدة Net::SNMP التفاصيل المعقدة لبروتوكول إدارة الشبكة البسيط عن طريق توفير واجهة برمجة عالية المستوى للبروتوكول. يوفر كل كائن Net::SNMP تعيينًا واحدًا لواحد بين كائن Perl وعميل أو مدير SNMP عن بعد. بمجرد إنشاء الكائن، يمكن استخدامه لأداء إجراءات تبادل البروتوكول الأساسية التي يحددها SNMP.

يمكن إنشاء كائن Net::SNMP بحيث يكون له خصائص "مانعة" أو "غير مانعة". افتراضيًا، لا تعود الأساليب المستخدمة لإرسال رسائل SNMP إلا بعد اكتمال تبادل البروتوكول بنجاح أو انتهاء فترة المهلة. يعطي هذا السلوك الكائن خاصية "مانعة" لأن تدفق التعليمات البرمجية يتوقف حتى تعود الدالة.

يمكن تمرير الوسيط الاختياري المسمى -nonblocking إلى مُنشئ الكائن بقيمة صحيحة لمنح الكائن سلوك "غير مانع". الدالة التي يتم استدعاؤها بواسطة كائن غير مانع تقوم بوضع رسالة SNMP في قائمة الانتظار وتعود فورًا، مما يسمح لتدفق التعليمات البرمجية بالاستمرار. لا يتم إرسال رسائل SNMP الموجودة في قائمة الانتظار حتى يتم الدخول إلى حلقة أحداث عن طريق استدعاء الدالة snmp_dispatcher(). عند إرسال رسائل SNMP، يؤدي أي رد على الرسائل إلى استدعاء الدالة الفرعية التي يحددها المستخدم عند وضع الرسالة في قائمة الانتظار في الأصل. تنتهي حلقة الأحداث عندما تتم إزالة جميع الرسائل من قائمة الانتظار إما عن طريق تلقي رد، أو عن طريق تجاوز عدد المحاولات على طبقة النقل.

الكائنات المانعة

السلوك الافتراضي للدوال المرتبطة بكائن Net::SNMP هو منع تدفق التعليمات البرمجية حتى تكتمل الدالة. بالنسبة للدوال التي تبدأ تبادل بروتوكول SNMP الذي يتطلب ردًا، يتم إرجاع مرجع إلى جدول hash يحتوي على نتائج الاستعلام. يتم إرجاع القيمة غير المحددة بواسطة جميع الدوال عند حدوث فشل. يمكن استخدام الدالة error() لتحديد سبب الفشل.

يشير مرجع جدول hash الذي تم إرجاعه بواسطة تبادل بروتوكول SNMP إلى جدول hash تم إنشاؤه من قائمة VarBindList الموجودة في رسالة استجابة SNMP. يتم إنشاء جدول hash باستخدام أزواج ObjectName و ObjectSyntax في VarBindList. تتكون مفاتيح جدول hash من معرفات الكائنات (OBJECT IDENTIFIERs) بالترميز النقطي المقابل لكل ObjectName في VarBindList. يتم تعيين قيمة كل إدخال في جدول hash لتساوي قيمة ObjectSyntax المقابل. يمكن أيضًا استرداد مرجع جدول hash هذا باستخدام الدالة var_bind_list().

الكائنات غير المانعة

عندما يتم إنشاء كائن Net::SNMP بسلوك غير مانع، فإن استدعاء دالة مرتبطة بالكائن يعود فورًا، مما يسمح لتدفق التعليمات البرمجية بالاستمرار. عند استدعاء دالة من شأنها بدء تبادل بروتوكول SNMP يتطلب ردًا، يتم إرجاع قيمة صحيحة (أي 0x1) فورًا أو يتم إرجاع القيمة غير المحددة إذا كان هناك فشل. يمكن استخدام الدالة error() لتحديد سبب الفشل.

يمكن استرداد محتويات VarBindList الموجودة في رسالة استجابة SNMP عن طريق استدعاء الدالة var_bind_list() باستخدام مرجع الكائن الذي تم تمريره كالمعلمة الأولى للدالة الفرعية. القيمة التي تعود بها الدالة var_bind_list() هي مرجع إلى جدول hash تم إنشاؤه باستخدام أزواج ObjectName و ObjectSyntax في VarBindList. تتكون مفاتيح جدول hash من معرفات الكائنات (OBJECT IDENTIFIERs) بالترميز النقطي المقابل لكل ObjectName في VarBindList. يتم تعيين قيمة كل إدخال في جدول hash لتساوي قيمة ObjectSyntax المقابل. يتم إرجاع القيمة غير المحددة إذا كان هناك فشل، ويمكن استخدام الدالة error() لتحديد السبب.

وسائط الكائنات غير المانعة
عند إنشاء كائن Net::SNMP بخاصية "غير مانعة"، تأخذ معظم الدوال التي تنشئ رسالة SNMP وسائط إضافية لدعم هذه الخاصية.
الدالة الفرعية
تحتوي معظم الدوال المرتبطة بكائن غير مانع على وسيط مسمى اختياري يسمى -callback. يتوقع الوسيط -callback مرجعًا لدالة فرعية أو إلى مصفوفة يجب أن يكون عنصرها الأول مرجعًا لدالة فرعية. يتم تنفيذ الدالة الفرعية المحددة بواسطة الخيار -callback عند استلام استجابة لرسالة SNMP، أو حدوث حالة خطأ، أو تجاوز عدد المحاولات للرسالة.

عندما يحتوي الوسيط -callback فقط على مرجع دالة فرعية، يتم تقييم الدالة الفرعية مع تمرير مرجع إلى كائن Net::SNMP الأصلي كمعلمة وحيدة. إذا تم تعريف الوسيط -callback كمرجع لمصفوفة، يتم تمرير جميع العناصر في المصفوفة إلى الدالة الفرعية بعد مرجع كائن Net::SNMP. تتم إزالة العنصر الأول، المطلوب أن يكون مرجعًا لدالة فرعية، قبل تمرير الوسائط المتبقية إلى تلك الدالة الفرعية.

بمجرد استدعاء دالة واحدة مع الوسيط -callback، يبقى هذا الوسيط مع الكائن ويستخدم بواسطة أي استدعاءات لاحقة للدوال التي تستخدم الخيار -callback إذا كان الوسيط مفقودًا. يمكن تمرير القيمة غير المحددة إلى الوسيط -callback لحذف الدالة الفرعية.

ملاحظة: يجب ألا تتسبب الدالة الفرعية التي يتم تمريرها مع الوسيط المسمى -callback في حدوث مانع بنفسها. سيؤدي ذلك إلى إيقاف جميع الإجراءات في حلقة الأحداث، مما يبطل الخاصية غير المانعة لوحدة Net::SNMP.

تأخير
يمكن أيضًا تمرير الوسيط الاختياري -delay إلى الكائنات غير المانعة. يوجه الوسيط -delay الكائن للانتظار عدد الثواني الممرر إلى الوسيط قبل تنفيذ تبادل بروتوكول SNMP. تبدأ فترة التأخير عند دخول حلقة الأحداث. يتم تطبيق المعلم -delay على جميع الدوال المرتبطة بالكائن بمجرد تحديده. يجب إعادة تعيين قيمة التأخير إلى 0 ثانية لتعطيل معلم التأخير.
وسائط SNMPv3
سياق SNMP هو مجموعة من معلومات الإدارة التي يمكن الوصول إليها بواسطة كيان SNMP. قد يوجد عنصر معلومات الإدارة في أكثر من سياق واحد، وقد يتمتع كيان SNMP بالوصول إلى العديد من السياقات. يحدد مزيج contextEngineID و contextName سياقًا بشكل لا لبس فيه ضمن نطاق إداري. في رسالة SNMPv3، يتم تضمين contextEngineID و contextName كجزء من scopedPDU. تأخذ جميع الدوال التي تنشئ رسالة SNMP اختياريًا وسيطي -contextengineid و -contextname لتكوين هذه الحقول.
معرف محرك السياق
يتوقع الوسيط -contextengineid سلسلة سداسية عشرية تمثل contextEngineID المطلوب. يجب أن يكون طول السلسلة من 10 إلى 64 حرفًا (5 إلى 32 بايت) ويمكن أن تبدأ بـ "0x" اختيارية. بمجرد تحديد -contextengineid، فإنه يبقى مع الكائن حتى يتم تغييره مرة أخرى أو إعادة تعيينه إلى الافتراضي عن طريق تمرير القيمة غير المحددة. افتراضيًا، يتم تعيين contextEngineID لمطابقة authoritativeEngineID لمحرك SNMP المسؤول.

وسيطات مجال النقل
تستخدم وحدة Net::SNMP مجال النقل UDP/IPv4 بشكل افتراضي لتبادل رسائل SNMP بين الأجهزة المحلية والبعيدة. كما أنها تدعم UDP/IPv6 و TCP/IPv4 و TCP/IPv6 كبدائل. يمكن استخدام الوسيطة -domain لتغيير مجال النقل عن طريق تعيين القيمة إلى أحد السلاسل النصية التالية: 'udp6'، 'udp/ipv6'؛ 'tcp'، 'tcp4'، 'tcp/ipv4'؛ 'tcp6'، أو 'tcp/ipv6'. تقبل الوسيطة -domain أيضًا السلاسل النصية 'udp'، 'udp4'، أو 'udp/ipv4' التي تتوافق مع مجال النقل الافتراضي UDP/IPv4.

يمكن تحديد عنوان النقل لجهاز SNMP الوجهة باستخدام الوسيطة -hostname. هذه الوسيطة اختيارية والقيمة الافتراضية هي 'localhost'. يمكن تحديد رقم منفذ الوجهة كجزء من عنوان النقل أو باستخدام الوسيطة -port. يمكن تحديد كل من رقم المنفذ الرقمي واسم الخدمة النصي. يمكن أن يتبع رقم المنفذ الرقمي بين قوسين اسم الخدمة اختياريًا. سيتم استخدام رقم المنفذ هذا إذا لم يتمكن اسم الخدمة من الحل. إذا لم يتم تحديد رقم منفذ الوجهة، يتم استخدام المنفذ المعروف 161.

بشكل افتراضي، يتم تعيين عناوين وأرقام منافذ النقل المصدر ديناميكيًا بواسطة الجهاز المحلي الذي يتم استخدامه في وحدة Net::SNMP. يمكن تجاوز هذا التعيين الديناميكي باستخدام الوسيطتين -localaddr و -localport. تقبل هاتان الوسيطتان نفس القيم التي تقبلها الوسيطتان -hostname و -port على التوالي. يجب أن يتوافق العنوان المحلول مع عنوان صالح لواجهة الجهاز المحلي.

عند استخدام مجال نقل IPv4، يمكن تحديد عنوان النقل كاسم مضيف لشبكة IP أو كعنوان IPv4 بالترميز النقطي القياسي. يمكن إلحاق معلومات المنفذ اختياريًا باسم المضيف أو العنوان مفصولين بنقطتين رأسيتين. تنسيقات عنوان النقل IPv4 المقبولة هي "address"، "address:port"، "hostname"، و "hostname:port".

عند استخدام مجال نقل IPv6، يمكن تحديد عنوان النقل كاسم مضيف IP (والذي سيتم البحث عنه كسجل quads-A) أو كعنوان IPv6 بتنسيق عرض. يمكن تضمين معلومات المنفذ اختياريًا بعد نقطتين رأسيتين بعد اسم المضيف أو العنوان. عند تضمين هذه المعلومات بعد عنوان IPv6، يجب أن يكون العنوان محاطًا بأقواس مربعة. يمكن تحديد فهرس المنطقة (الموصوف في RFC 4007) بعد العنوان كقيمة عشرية مفصولة بعلامة النسبة المئوية. تنسيقات عنوان النقل IPv6 المقبولة هي "address"، "address%zone"، "[address]:port"، "[address%zone]:port"، "hostname"، و "hostname:port".

وسيطات نموذج الأمان
تتحكم الوسيطة -version في الوسيطات الأخرى المطلوبة بواسطة الباني session(). تدعم وحدة Net::SNMP بروتوكول SNMPv1 و SNMPv2c و SNMPv3. تفترض الوحدة بروتوكول SNMPv1 بشكل افتراضي إذا لم يتم تحديد الوسيطة -version. تتوقع الوسيطة -version رقمًا (أي '1' أو '2' أو '3') أو سلسلة نصية تحدد الإصدار (على سبيل المثال، 'snmpv1'، 'snmpv2c'، أو 'snmpv3') لتحديد إصدار SNMP.

يعتمد نموذج الأمان المستخدم بواسطة كائن Net::SNMP على إصدار SNMP المرتبط بالكائن. إذا كان إصدار SNMP هو SNMPv1 أو SNMPv2c، فسيتم استخدام نموذج أمان قائم على المجتمع، بينما إذا كان الإصدار هو SNMPv3، فسيتم استخدام نموذج أمان قائم على المستخدم (USM).

وسيطة نموذج الأمان القائم على المجتمع
إذا كان نموذج الأمان قائمًا على المجتمع، فإن الوسيطة الوحيدة المتاحة هي -community. تتوقع هذه الوسيطة سلسلة نصية سيتم استخدامها كاسم مجتمع. بشكل افتراضي، يتم تعيين اسم المجتمع على 'public' إذا لم تكن الوسيطة موجودة.
وسيطات نموذج الأمان القائم على المستخدم
يتطلب نموذج الأمان القائم على المستخدم (USM) المستخدم بواسطة SNMPv3 تحديد اسم أمان باستخدام الوسيطة -username. سيفشل إنشاء كائن Net::SNMP بإصدار محدد إلى SNMPv3 إذا كانت الوسيطة -username مفقودة. تتوقع الوسيطة -username سلسلة نصية بطول يتراوح من 1 إلى 32 بايت.

تسمح مستويات الأمان المختلفة بواسطة نموذج الأمان القائم على المستخدم والتي تعالج مخاوف المصادقة والخصوصية. سيستنتج كائن Net::SNMP SNMPv3 مستوى الأمان (securityLevel) بناءً على أي من الوسيطات التالية تم تحديدها.

افتراضيًا، يُفترض مستوى أمان 'noAuthNoPriv'. إذا تم تحديد الوسيطتين -authkey أو -authpassword، فإن مستوى الأمان يتحول إلى 'authNoPriv'. تتوقع الوسيطة -authpassword سلسلة نصية بطول بايت واحد على الأقل. اختياريًا، يمكن استخدام الوسيطة -authkey لتجنب الحاجة إلى تحديد كلمة مرور نص عادي في نص برمجي. تتوقع الوسيطة -authkey سلسلة نصية سداسية عشرية تم إنشاؤها عن طريق إلحاق كلمة المرور بـ authoritativeEngineID لجهاز الوجهة المحدد. يمكن استخدام الأداة المساعدة "snmpkey" المتضمنة في التوزيع لإنشاء السلسلة السداسية عشرية (انظر snmpkey).

تم تعريف خوارزميتي تجزئة مختلفتين بواسطة SNMPv3 يمكن استخدامهما بواسطة نموذج الأمان للمصادقة. هاتان الخوارزميتان هما HMAC-MD5-96 "MD5" (RFC 1321) و HMAC-SHA-96 "SHA-1" (NIST FIPS PUB 180-1). الخوارزمية الافتراضية التي تستخدمها الوحدة هي HMAC-MD5-96. يمكن تغيير هذا السلوك باستخدام الوسيطة -authprotocol. تتوقع هذه الوسيطة إما السلسلة 'md5' أو 'sha' لتعديل خوارزمية التجزئة.

عند تحديد الوسيطتين -privkey أو -privpassword، يتحول مستوى الأمان المرتبط بالكائن إلى 'authPriv'. وفقًا لـ SNMPv3، تتطلب الخصوصية استخدام المصادقة. لذلك، إذا كان أي من هاتين الوسيطتين موجودًا وكانت الوسيطتان -authkey أو -authpassword مفقودتين، فسيفشل إنشاء الكائن. تتوقع الوسيطتان -privkey و -privpassword نفس نوع الإدخال الذي تتوقعه الوسيطتان -authkey و -authpassword على التوالي.

يحدد نموذج الأمان القائم على المستخدم الموصوف في RFC 3414 بروتوكول تشفير واحد للخصوصية. يستخدم هذا البروتوكول، CBC-DES "DES" (NIST FIPS PUB 46-1)، افتراضيًا أو إذا تم تمرير السلسلة 'des' إلى الوسيطة -privprotocol. تدعم الوحدة أيضًا RFC 3826 الذي يصف استخدام CFB128-AES-128 "AES" (NIST FIPS PUB 197) في USM. يمكن تحديد بروتوكول تشفير AES عن طريق تمرير 'aes' أو 'aes128' إلى الوسيطة -privprotocol. بالعمل مع Extended Security Options Consortium http://www.snmp.com/protocol/eso.shtml، تدعم الوحدة أيضًا CBC-3DES-EDE "Triple-DES" (NIST FIPS 46-3) في نموذج الأمان القائم على المستخدم. يوجد هذا التعريف في المسودة http://www.snmp.com/eso/draft-reeder-snmpv3-usm-3desede-00.txt. يمكن تحديد بروتوكول تشفير Triple-DES باستخدام الوسيطة -privprotocol مع السلسلة '3des' أو '3desede'.

close() - تنظيف مجال النقل المرتبط بالكائن

$session->close();

يقوم هذا الأسلوب بتنظيف مجال النقل وأي أخطاء مرتبطة بالكائن. بمجرد إغلاقه، لا يمكن استخدام كائن Net::SNMP لإرسال أو استقبال رسائل SNMP.

snmp_dispatcher() - الدخول إلى حلقة الأحداث غير المتزامنة للكائن

$session->snmp_dispatcher();

تأخذ هذه الدالة معرفي كائن (OBJECT IDENTIFIERs) في تدوين النقطة وترجع قيمة صحيحة (أي، 0x1) إذا كان معرف الكائن الثاني يساوي الأول أو كان ابنًا في شجرة MIB المحددة في قاعدة معلومات الإدارة SNMP (MIB). يمكن استخدام هذه الدالة جنبًا إلى جنب مع الطرق "get-next-request()" أو "get-bulk-request()" لتحديد متى لا يكون OID في PDU GetResponse ضمن شجرة MIB المطلوبة.

oid_lex_cmp() - مقارنة معرفي كائن (OBJECT IDENTIFIERs) أبجديًا

$cmp = oid_lex_cmp($oid1, $oid2);

تأخذ هذه الدالة معرفي كائن (OBJECT IDENTIFIERs) في تدوين النقطة وترجع 1 أو 0 أو -1 إذا كان $oid1 أكبر أو يساوي أو أصغر من $oid2 أبجديًا على التوالي.

oid_lex_sort() - ترتيب قائمة معرفات الكائنات (OBJECT IDENTIFIERs) أبجديًا

@sorted_oids = oid_lex_sort(@oids);

تأخذ هذه الدالة قائمة بمعرفات الكائنات (OBJECT IDENTIFIERs) في تدوين النقطة وترجع القائمة مرتبة أبجديًا.

snmp_type_ntop() - تحويل نوع ASN.1 إلى تنسيق عرض

$text = snmp_type_ntop($type);

تأخذ هذه الدالة قيمة ثمانية البايت (octet) لنوع ASN.1 وترجع سلسلة نصية مناسبة للعرض. ترتبط بعض أنواع تعريفات ASN.1 بقيم ثمانية البايت متساوية عند ترميزها. هذه المنهجية لا يمكنها التمييز بين هذه التعيينات المتعددة ويتم إرجاع اسم النوع الأساسي الأبسط.

ticks_to_time() - تحويل TimeTicks إلى تنسيق زمني

$time = ticks_to_time($timeticks);

تأخذ هذه الدالة قيمة TimeTicks وترجع سلسلة تمثل الوقت المحدد بالقيمة. القيمة المتوقعة لـ TimeTicks هي قيمة عدد صحيح غير سالب تمثل الوقت بالمللي ثانية منذ حقبة معينة. ستعرض السلسلة المرجعة الوقت بتنسيق الأيام والساعات والثواني بناءً على قيمة معلمة TimeTicks.

2. حظر طلب SNMPv3 set-request لـ sysContact

يقوم هذا المثال بتعيين معلومات sysContact على مضيف بعيد إلى "Help Desk x911". تُستخدم الوسائط المسماة التي تم تمريرها إلى الدالة session() فقط لمثال الصيغة. يجب تكوين هذه المعلمات وفقًا لمعلمات SNMPv3 للمضيف البعيد. يمكن استخدام الأداة المساعدة "snmpkey" المضمنة في التوزيع لإنشاء قيم المفاتيح.

#! /usr/local/bin/perl
use strict;

my $OID_sysContact = '1.3.6.1.2.1.1.4.0';
my ($session, $error) = Net::SNMP->session(

   -version      => 'snmpv3',
   -username     => 'myv3Username',
   -authprotocol => 'sha1',
   -authkey      => '0x6695febc9288e36282235fc7151f128497b38f3f',
   -privprotocol => 'des',
   -privkey      => '0x6695febc9288e36282235fc7151f1284',
);
if (!defined $session) {
   printf "خطأ: %s.\n", $error;

   -varbindlist => [ $OID_sysContact, OCTET_STRING, 'Help Desk x911' ],

3. طلب SNMPv2c غير حظري get-bulk-request لـ ifTable

يحصل هذا المثال على محتويات ifTable عن طريق إرسال طلبات get-bulk حتى لا تكون الاستجابات جزءًا من ifTable. يمكن أيضًا الحصول على ifTable باستخدام الدالة get_table(). الكائن ifPhysAddress في الجدول له تنسيق OCTET STRING. افتراضيًا، يكون الترجمة نشطة ويتم ترجمة سلاسل OCTET STRING غير القابلة للطباعة إلى تنسيق سداسي عشري. في بعض الأحيان، تحتوي سلاسل OCTET STRING على أحرف قابلة للطباعة فقط، مما يؤدي إلى نتيجة غير متوقعة عند عدم ترجمتها. يقوم المثال بتعطيل الترجمة لـ OCTET STRING ويشكل المخرجات المحددة لكائنات ifPhysAddress.

#! /usr/local/bin/perl
use strict;
use warnings;
use Net::SNMP qw(:snmp);
my $OID_ifTable = '1.3.6.1.2.1.2.2';
my $OID_ifPhysAddress = '1.3.6.1.2.1.2.2.1.6';
my ($session, $error) = Net::SNMP->session(
   -hostname    => shift || 'localhost',
   -community   => shift || 'public',
   -nonblocking => 1,
   -translate   => [-octetstring => 0],
   -version     => 'snmpv2c',
);
if (!defined $session) {
   printf "خطأ: %s.\n", $error;
   exit 1;
}
my %table; # Hash لتخزين النتائج
my $result = $session->get_bulk_request(
   -varbindlist    => [ $OID_ifTable ],
   -callback       => [ \&table_callback, \%table ],
   -maxrepetitions => 10,
);
if (!defined $result) {
   printf "خطأ: %s\n", $session->error();
   $session->close();
   exit 1;
}
# ابدأ الآن تبادل رسائل SNMP.
snmp_dispatcher();
$session->close();
# اطبع النتائج، خاصة لـ ifPhysAddress.
for my $oid (oid_lex_sort(keys %table)) {
   if (!oid_base_match($OID_ifPhysAddress, $oid)) {
      printf "%s = %s\n", $oid, $table{$oid};
   } else {
      printf "%s = %s\n", $oid, unpack 'H*', $table{$oid};
   }
}
exit 0;
sub table_callback
{
   my ($session, $table) = @_;
   my $list = $session->var_bind_list();
   if (!defined $list) {
      printf "خطأ: %s\n", $session->error();
      return;
   }
   # قم بالتكرار عبر كل OID في الاستجابة وتعيين أزواج المفتاح/القيمة إلى المرجع الذي تم تمريره مع رد الاتصال. تأكد من أنك لا تزال في الجدول قبل تعيين أزواج المفتاح/القيمة.
   my @names = $session->var_bind_names();
   my $next  = undef;
   while (@names) {
      $next = shift @names;
      if (!oid_base_match($OID_ifTable, $next)) {
         return; # انتهى الجدول.
      }
      $table->{$next} = $list->{$next};
   }
   # لم ينته الجدول، أرسل طلبًا آخر، بدءًا من آخر OID في الاستجابة. لا يلزم تضمين وسيطة رد الاتصال، وسيتم استخدام نفس رد الاتصال الذي تم تحديده للطلب الأصلي.
   my $result = $session->get_bulk_request(
      -varbindlist    => [ $next ],
      -maxrepetitions => 10,
   );
   if (!defined $result) {
      printf "خطأ: %s.\n", $session->error();
   }
   return;
}

4. طلبات SNMPv1 غير حظرية get-request و set-request على مضيفين متعددين

يقوم هذا المثال أولاً باستطلاع مضيفين متعددين بحثًا عن sysUpTime الخاص بهم. إذا نجح استطلاع المضيف، يتم تعيين معلومات sysContact و sysLocation على المضيف. معلومات sysContact مثبتة بأنها "Help Desk x911"، بينما يتم تمرير معلومات sysLocation كوسيطة إلى رد الاتصال.

#! /usr/local/bin/perl
use strict;
use warnings;
use Net::SNMP;
my $OID_sysUpTime = '1.3.6.1.2.1.1.3.0';
my $OID_sysContact = '1.3.6.1.2.1.1.4.0';
my $OID_sysLocation = '1.3.6.1.2.1.1.6.0';
# Hash للمضيفين وبيانات الموقع.
my %host_data = (
   '10.1.1.2'  => 'Building 1, Second Floor',
   '10.2.1.1'  => 'Building 2, First Floor',
   'localhost' => 'Right here!',
);
# إنشاء جلسة لكل مضيف ووضع طلب get لـ sysUpTime في قائمة الانتظار.
for my $host (keys %host_data) {
   my ($session, $error) = Net::SNMP->session(
      -hostname    => $host,
      -community   => 'private',
      -nonblocking => 1,
   );
   if (!defined $session) {
      printf "خطأ: فشل في إنشاء جلسة للمضيف '%s': %s.\n",
             $host, $error;
      next;
   }
   my $result = $session->get_request(
      -varbindlist => [ $OID_sysUpTime ],
      -callback    => [ \&get_callback, $host_data{$host} ],
   );
   if (!defined $result) {
      printf "خطأ: فشل في وضع طلب get في قائمة الانتظار للمضيف '%s': %s.\n",
             $session->hostname(), $session->error();
   }
}
# ابدأ الآن تبادل رسائل SNMP.
snmp_dispatcher();
exit 0;
sub get_callback
{
   my ($session, $location) = @_;
   my $result = $session->var_bind_list();
   if (!defined $result) {
      printf "خطأ: فشل في طلب get للمضيف '%s': %s.\n",
             $session->hostname(), $session->error();
      return;
   }
   printf "sysUpTime للمضيف '%s' هو %s.\n",
           $session->hostname(), $result->{$OID_sysUpTime};
   # الآن قم بتعيين sysContact و sysLocation للمضيف.
   $result = $session->set_request(
      -varbindlist =>
      [
         $OID_sysContact,  OCTET_STRING, 'Help Desk x911',
         $OID_sysLocation, OCTET_STRING, $location,
      ],
      -callback    => \&set_callback,
   );
   if (!defined $result) {
      printf "خطأ: فشل في وضع طلب set في قائمة الانتظار للمضيف '%s': %s.\n",
             $session->hostname(), $session->error();
   }
   return;
}
sub set_callback
{
   my ($session) = @_;
   my $result = $session->var_bind_list();
   if (defined $result) {
      printf "تم تعيين sysContact للمضيف '%s' إلى '%s'.\n",
             $session->hostname(), $result->{$OID_sysContact};
      printf "تم تعيين sysLocation للمضيف '%s' إلى '%s'.\n",
             $session->hostname(), $result->{$OID_sysLocation};
   } else {
      printf "خطأ: فشل في طلب set للمضيف '%s': %s.\n",
             $session->hostname(), $session->error();
   }
   return;
}
