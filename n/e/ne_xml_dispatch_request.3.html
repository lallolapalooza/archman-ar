ne_xml_dispatch_request(3)

الحزمة: neon

التراخيص: LGPL-2.0-or-later

NE_XML_PARSE_RESPONS(3) مرجع واجهة برمجة تطبيقات neon NE_XML_PARSE_RESPONS(3)

الاسم

ne_xml_parse_response, ne_xml_dispatch_request, ne_xml_dispatchif_request - دوال مساعدة لتحليل استجابات XML

الملخص

#include <ne_xmlreq.h>

int ne_xml_parse_response(ne_request *req, ne_xml_parser *parser);

int ne_xml_dispatch_request(ne_request *req, ne_xml_parser *parser);

int ne_xml_dispatchif_request(ne_request *req, ne_xml_parser *parser, ne_accept_response acceptor, void *userdata);

الوصف

تقوم الدالة ne_xml_parse_response بقراءة نص استجابة HTTP ومعالجته باستخدام محلل XML المحدد. يجب استدعاء الدالة بعد أن تعود ne_begin_request بنجاح للطلب، ثم تقوم باستدعاء ne_read_response_block حتى يتم قراءة نص الاستجابة بالكامل. عند العودة بنجاح، يجب استدعاء ne_end_request لإكمال معالجة الاستجابة.

تعتبر الدوال ne_xml_dispatch_request و ne_xml_dispatchif_request مكافئة لاستدعاء ne_request_dispatch لإرسال طلب HTTP ومعالجة الاستجابة، مع تحليل نص الاستجابة باستخدام محلل XML المحدد تحت شروط معينة:

•بالنسبة لـ ne_xml_dispatch_request، أي استجابة من الفئة 2xx بنوع محتوى XML.
•بالنسبة لـ ne_xml_dispatchif_request، إذا أعادت الدالة المرتدة acceptor قيمة غير صفرية، واستخدمت الاستجابة نوع محتوى XML.

في كلتا الحالتين، يتم اتباع القواعد في RFC 7303[1] لتحديد أنواع محتوى XML، وهي text/xml، application/xml، أو أي نوع محتوى آخر ينتهي باللاحقة +xml. يتم تمرير المعامل userdata إلى الدالة acceptor.

لجميع الدوال الثلاث:

•يتم استدعاء محلل XML بشكل متكرر حتى الوصول إلى نهاية المستند.
•إذا حدث خطأ أثناء تحليل XML، يتم تعيين سلسلة خطأ الجلسة لوصف خطأ التحليل، ويتم إنهاء الاتصال دون مواصلة معالجة الاستجابة.

قيمة الإرجاع

ترجع جميع الدوال الموثقة هنا صفرًا عند النجاح، أو رمز خطأ NE_* عند الفشل.
