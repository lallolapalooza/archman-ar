ne_get_status(3)

الحزمة: neon

التراخيص: LGPL-2.0-or-later

NE_GET_STATUS(3) مرجع واجهة برمجة تطبيقات neon NE_GET_STATUS(3)

الاسم

ne_get_status, ne_get_response_location, ne_get_response_retry_after - استرداد خصائص استجابة HTTP

الملخص

#include <ne_request.h>

const ne_status *ne_get_status(const ne_request *request);

ne_uri *ne_get_response_location(ne_request *request);

time_t ne_get_response_retry_after(ne_request *request);

الوصف

تقوم الدالة ne_get_status بإرجاع مؤشر إلى كائن حالة HTTP الذي يعطي نتيجة الطلب. يصبح الكائن الذي تم إرجاعه صالحًا فقط بمجرد إرسال الطلب بنجاح (كانت القيمة المرجعة من ne_request_dispatch أو ne_begin_request صفرًا).

إذا كانت الاستجابة تتضمن رأس Location، فإن الدالة ne_get_response_location تقوم بتحليل وتحديد مرجع URI نسبيًا لهدف الطلب. إذا كان هناك جزء تجزئة ("#fragment") يمكن تطبيقه على هدف الطلب، يمكن تمريره كوسيطة للسماح بالتحديد النسبي المناسب.

تقوم الدالة ne_get_response_retry_after بتحليل أي رأس Retry-After مضمن في الاستجابة. إذا كانت قيمة الرأس تستخدم وقتًا نسبيًا، فيتم تفسيرها نسبيًا للوقت الذي تم فيه استدعاء الدالة، بدلاً من وقت تلقي الاستجابة، لذلك يجب استخدام الدالة مباشرة بعد إرسال الطلب.

قيمة الإرجاع

ترجع ne_get_status مؤشرًا إلى كائن حالة HTTP الذي يعطي نتيجة الطلب. يكون هذا المؤشر صالحًا حتى يتم تدمير كائن الطلب المرتبط به.

ترجع ne_get_response_location كائن ne_uri مخصص بواسطة malloc، أو NULL إذا لم يكن من الممكن تحليل URI في رأس Location أو لم يكن رأس Location موجودًا.

ترجع ne_get_response_retry_after قيمة time_t، أو صفرًا إذا لم يتم تضمين رأس Retry-After أو لم يكن من الممكن تحليل قيمة الرأس.

أمثلة

عرض رمز حالة الاستجابة لطريقة HEAD المطبقة على مورد ما.

ne_request *req = ne_request_create(sess, "HEAD", "/foo/bar");
if (ne_request_dispatch(req))
   /* معالجة الأخطاء... */
else
   printf("Response status code was %d\n", ne_get_status(req)->code);
ne_request_destroy(req);

التاريخ

ne_get_response_location متاح في neon 0.34.0 وما بعده.
