الحزمة: perl-ldap

التراخيص: GPL

Net::LDAP(3) User Contributed Perl Documentation Net::LDAP(3)

الاسم

Net::LDAP - بروتوكول الوصول الخفيف إلى الدليل

الملخص

use Net::LDAP;
$ldap = Net::LDAP->new( 'ldap.example.com' )  or  die "$@";
$mesg = $ldap->bind;                         # ربط مجهول
$mesg->code  and  die $mesg->error;          # التحقق من الأخطاء
$srch = $ldap->search( base   => "c=US",     # إجراء بحث
                       filter => "(&(sn=Barr)(o=Texas Instruments))"
                     );
$srch->code  and  die $srch->error;          # التحقق من الأخطاء
foreach $entry ($srch->entries) { $entry->dump; }
$mesg = $ldap->unbind;                       # إنهاء الجلسة
$ldap = Net::LDAP->new( 'ldaps://ldap.example.com' )  or  die "$@";
# ربط بسيط باستخدام DN وكلمة المرور
$mesg = $ldap->bind( 'cn=root, o=University of Michigan, c=us',
                     password => 'secret'
                   );
$mesg->code  and  die $mesg->error;          # التحقق من الأخطاء
$result = $ldap->add( 'cn=Barbara Jensen, o=University of Michigan, c=US',
                      attrs => [
                        cn          => ['Barbara Jensen', 'Barbs Jensen'],
                        sn          => 'Jensen',
                        mail        => 'b.jensen@umich.edu',
                        objectclass => ['top', 'person',
                                        'organizationalPerson',
                                        'inetOrgPerson' ],
                      ]
                    );
$result->code  and  warn "failed to add entry: ", $result->error;
$mesg = $ldap->unbind;                       # إنهاء الجلسة

الوصف

Net::LDAP هي مجموعة من الوحدات التي تنفذ واجهة برمجة تطبيقات خدمات LDAP لبرامج Perl. يمكن استخدام الوحدة للبحث في الدلائل أو إجراء وظائف الصيانة مثل إضافة أو حذف أو تعديل الإدخالات.

يفترض هذا المستند أن القارئ لديه بعض المعرفة ببروتوكول LDAP.

الباني

new ( HOST, OPTIONS )
ينشئ كائن Net::LDAP جديد ويفتح اتصالاً بالضيف المحدد.

"HOST" يمكن أن يكون اسم مضيف أو عنوان IP. يمكن تحديد منفذ TCP بعد اسم المضيف متبوعًا بنقطتين (مثل localhost:10389). المنفذ الافتراضي لـ LDAP هو 389.

يمكنك أيضًا تحديد URI، مثل 'ldaps://127.0.0.1:666' أو 'ldapi://%2fvar%2flib%2fldap_sock'. لاحظ أن '%2f's في مسار مقبس LDAPI سيتم ترجمتها إلى '/'. هذا لدعم خيارات استعلام LDAP مثل base، search إلخ، على الرغم من أنه سيتم تجاهل جزء الاستعلام من URI في هذا السياق. إذا لم يتم تحديد المنفذ في URI، فالقيمة الافتراضية هي إما 389 أو 636 لمخططات 'LDAP' و 'LDAPS' على التوالي.

"HOST" يمكن أن يكون أيضًا مرجعًا لمصفوفة من المضيفين، أو أزواج مضيف-منفذ، أو URIs لمحاولة الاتصال بها. سيتم تجربة كل منها بالترتيب حتى يتم إنشاء اتصال. فقط عندما تفشل جميعها، سيتم إرجاع نتيجة "undef".

port => N
المنفذ للاتصال به على الخادم البعيد. قد يتم تجاوزه بواسطة "HOST".
scheme => 'ldap' | 'ldaps' | 'ldapi'
مخطط الاتصال المراد استخدامه عند عدم استخدام URI كـ "HOST". (الافتراضي: ldap)
keepalive => 1
إذا تم تقديمه، قم بتعيين خيار SO_KEEPALIVE للمقبس اعتمادًا على القيمة البوليانية للخيارة. (الافتراضي: استخدام افتراضي النظام)

يتم تجاهل الأخطاء في تغيير خيار SO_KEEPALIVE للمقبس.

timeout => N
المهلة الممررة إلى IO::Socket عند الاتصال بالخادم البعيد. (الافتراضي: 120)
multihomed => N
سيتم تمريرها إلى IO::Socket كـ "MultiHomed" parameter عند الاتصال بالخادم البعيد
localaddr => HOST
سيتم تمريرها إلى IO::Socket كـ "LocalAddr" parameter، والذي يحدد عنوان IP للعميل (مقابل عنوان IP للخادم).
debug => N
تعيين مستوى التصحيح. انظر طريقة debug للحصول على التفاصيل.
async => 1
تنفيذ جميع العمليات بشكل غير متزامن.
onerror => 'die' | 'warn' | 'undef' | sub { ... }
في الوضع المتزامن، قم بتغيير ما يحدث عند اكتشاف خطأ.
'die'
سيتوقف Net::LDAP عن العمل عند اكتشاف خطأ.
'warn'
سيحذر Net::LDAP عند اكتشاف خطأ.
'undef'
سيحذر Net::LDAP عند اكتشاف خطأ ويكون "-w" قيد التشغيل. ستعيد الطريقة التي تم استدعاؤها "undef".

لاحظ أن هذه القيمة هي السلسلة النصية 'undef'، وليس القيمة "undef".

sub { ... }
سيتم استدعاء الدالة الفرعية المعطاة في سياق قياسي مع وسيط واحد، وهو رسالة النتيجة. ستكون القيمة المعادة هي القيمة المعادة للطريقة التي تم استدعاؤها.
version => N
تعيين إصدار البروتوكول المستخدم (الافتراضي هو LDAPv3). هذا مفيد إذا كنت تريد التحدث إلى خادم قديم وبالتالي يتعين عليك استخدام LDAPv2.
raw => REGEX
استخدم REGEX لتحديد أسماء السمات التي يجب اعتبارها ثنائية في نتائج البحث.

عند تقديم هذا الخيار، يقوم Net::LDAP بتحويل جميع قيم السمات التي لا تطابق هذه REGEX إلى سلاسل UTF-8 في Perl حتى تتمكن عوامل تشغيل Perl العادية (مطابقة الأنماط، ...) من العمل كما تتوقع حتى على السلاسل ذات الأحرف الدولية.

إذا لم يتم تقديم هذا الخيار، يتم التعامل مع قيم السمات كسلاسل بايت.

مثال: raw => qr/(?i:^jpegPhoto|;binary)/

inet4 => N
inet6 => N
حاول الاتصال بالخادم باستخدام بروتوكول IP المحدد فقط، أي إما IPv4 أو IPv6. إذا لم يكن البروتوكول المحدد مدعومًا، فسيفشل الاتصال.

الافتراضي هو استخدام أي من البروتوكولين.

مثال

$ldap = Net::LDAP->new( 'remote.host', async => 1 );

تحتوي اتصالات LDAPS على بعض الخيارات الإضافية الصالحة، انظر طريقة start_tls للحصول على التفاصيل. لاحظ أن المنفذ الافتراضي لـ LDAPS هو 636، والقيمة الافتراضية لـ 'sslversion' هي القيمة المستخدمة افتراضيًا بواسطة IO::Socket::SSL.

بالنسبة لاتصالات LDAPI، فإن HOST هو في الواقع موقع مقبس نطاق UNIX للاتصال به. الموقع الافتراضي هو '/var/run/ldapi'.

الطرق

تأخذ كل من الطرق التالية كمعاملات عددًا من المعلمات الثابتة متبوعة بالخيارات، يتم تمرير هذه الخيارات بطريقة مسماة، على سبيل المثال

$mesg = $ldap->bind( "cn=me,o=example", password => "mypasswd");

القيمة المعادة من هذه الطرق هي كائن مشتق من فئة Net::LDAP::Message. تسمح لك طرق هذه الفئة بفحص حالة الطلب.

abandon ( ID, OPTIONS )
التخلي عن طلب تم إصداره سابقًا. "ID" يمكن أن يكون رقمًا أو كائنًا وهو فئة فرعية من Net::LDAP::Message، تم إرجاعه من استدعاء طريقة سابقة.
control => CONTROL
control => [ CONTROL, ... ]
انظر "CONTROLS" أدناه
callback => CALLBACK
انظر "CALLBACKS" أدناه
changes => [ OP => [ ATTR => VALUE ], ... ]
هذا بديل لـ add و delete و replace و increment، حيث يمكن تقديم العملية بأكملها في وسيط واحد. يجب أن يكون "OP" إما add أو delete أو replace أو increment. يجب أن يكون "VALUE" سلسلة نصية أو مرجعًا لمصفوفة من السلاسل النصية، كما هو الحال سابقًا.

استخدم هذا الشكل إذا كنت تريد التحكم في ترتيب تنفيذ العمليات.

$mesg = $ldap->modify( $dn,
  changes => [
    add => [
      description => 'A description',
      member      => $newMember,
    ],
    delete => [
      seeAlso => [],
    ],
    add => [
      anotherAttribute => $value,
    ],
  ]
);
control => CONTROL
control => [ CONTROL, ... ]
انظر "CONTROLS" أدناه.
callback => CALLBACK
انظر "CALLBACKS" أدناه.

مثال

$mesg = $ldap->modify( $dn, add => { sn => 'Barr' } );
$mesg = $ldap->modify( $dn, delete => [qw(faxNumber)] );
$mesg = $ldap->modify( $dn, delete => { 'telephoneNumber' => '911' } );
$mesg = $ldap->modify( $dn, replace => { 'mail' => 'gbarr@pobox.com' } );
$mesg = $ldap->modify( $dn,
                       changes => [
                           # إضافة sn=Barr
                         add     => [ sn => 'Barr' ],
                           # حذف جميع أرقام الفاكس
                         delete  => [ faxNumber => []],
                           # حذف رقم الهاتف 911
                         delete  => [ telephoneNumber => ['911']],
                           # تغيير عنوان البريد الإلكتروني
                         replace => [ mail => 'gbarr@pobox.com']
                       ]
                     );
search ( OPTIONS )
يبحث في الدليل باستخدام مرشح معين. يمكن استخدام هذا لقراءة سمات إدخال واحد، أو إدخالات مباشرة أسفل إدخال معين، أو جميع شجرة الإدخالات.

النتيجة هي كائن من فئة Net::LDAP::Search.

base => DN
DN الذي هو إدخال الكائن الأساسي الذي يتم إجراء البحث بناءً عليه.
scope => 'base' | 'one' | 'sub' | 'subtree' | 'children'
بشكل افتراضي، يتم إجراء البحث في الشجرة بأكملها أسفل كائن الأساس المحدد. يمكن تغيير ذلك عن طريق تحديد معلمة "scope" بإحدى القيم التالية:
base
يبحث فقط في إدخال الكائن الأساسي.
one
يبحث في الإدخالات مباشرة أسفل إدخال الكائن الأساسي.
sub
subtree
يبحث في شجرة الإدخالات بأكملها (بما في ذلك إدخال الكائن الأساسي نفسه). هذا هو الافتراضي.
children
يبحث في شجرة الإدخالات بأكملها أسفل إدخال الكائن الأساسي، باستثناء إدخال الكائن الأساسي نفسه.

ملاحظة: يتطلب نطاق children امتداد ميزات LDAPv3.

deref => 'never' | 'search' | 'find' | 'always'
بشكل افتراضي، يتم فك الإشارات للبحث عن إدخال الكائن الأساسي للبحث، ولكن ليس عند البحث في الإدخالات الفرعية لكائن الأساس. يمكن تغيير ذلك عن طريق تحديد معلمة "deref" بإحدى القيم التالية:
never
لا تفك الإشارات أثناء البحث أو عند تحديد إدخال الكائن الأساسي للبحث.
search
فك الإشارات في الإدخالات الفرعية لكائن الأساس أثناء البحث، ولكن ليس عند تحديد إدخال الكائن الأساسي للبحث.
find
فك الإشارات عند تحديد إدخال الكائن الأساسي للبحث، ولكن ليس عند البحث في الإدخالات الفرعية لكائن الأساس. هذا هو الافتراضي.
always
فك الإشارات في كل من البحث وتحديد إدخال الكائن الأساسي للبحث.
sizelimit => N
حد حجم يقيد الحد الأقصى لعدد الإدخالات التي سيتم إرجاعها كنتيجة للبحث. قيمة 0، والافتراضي، تعني أنه لم يتم طلب حد. قد تفرض الخوادم حدًا أقصى لعدد الإدخالات التي سيتم إرجاعها.
timelimit => N
حد زمني يقيد الحد الأقصى للوقت (بالثواني) المسموح به للبحث. قيمة 0 (افتراضي) تعني أنه لم يتم طلب حد زمني.
typesonly => 1
يتم إرجاع أنواع السمات فقط (بدون قيم). عادةً، يتم إرجاع كل من أنواع السمات وقيمها.
filter => FILTER
مرشح يحدد الشروط التي يجب أن يستوفيها إدخال الدليل ليتم إرجاعه بواسطة البحث. يمكن أن يكون هذا سلسلة نصية أو كائن Net::LDAP::Filter. قد تحتاج القيم الموجودة داخل المرشحات إلى إلغاء تهريبها لتجنب مشاكل الأمان؛ انظر Net::LDAP::Filter لتعريف تنسيق المرشح، بما في ذلك قواعد إلغاء التهريب.
attrs => [ ATTR, ... ]
قائمة بالسمات التي سيتم إرجاعها لكل إدخال يتطابق مع مرشح البحث.

إذا لم يتم تحديد ذلك، فسترجع الخوادم السمات التي يمكن الوصول إليها افتراضيًا بالنظر إلى بيانات اعتماد الربط الخاصة بك.

قد تكون بعض السمات الإضافية مثل "createTimestamp" وسمات تشغيلية أخرى متاحة أيضًا:

$mesg = $ldap->search( ... ,
                       attrs => ['createTimestamp']
                     );

لاسترداد السمات الافتراضية وسمات أخرى، استخدم '*'.

$mesg = $ldap->search( ... ,
                       attrs => ['*', 'createTimestamp']
                     );

لعدم استرداد أي سمات (تعيد الخوادم فقط DNs للإدخالات المتطابقة)، استخدم '1.1':

$mesg = $ldap->search( ... ,
                       attrs => ['1.1']
                     );
control => CONTROL
control => [ CONTROL, ... ]
انظر "CONTROLS" أدناه.
callback => CALLBACK
انظر "CALLBACKS" أدناه.
raw => REGEX
استخدم REGEX لتحديد أسماء السمات التي تعتبر ثنائية في نتائج البحث.

عند توفير هذا الخيار، يقوم Net::LDAP بتحويل جميع قيم السمات التي لا تتطابق مع هذا REGEX إلى سلاسل Perl UTF-8 بحيث يمكن لمشغلي Perl المنتظمين (نمط البحث، إلخ) العمل كما هو متوقع حتى على السلاسل التي تحتوي على أحرف دولية.

إذا لم يتم توفير هذا الخيار، يتم التعامل مع قيم السمات كسلاسل بايت.

القيمة المقدمة هنا تتجاوز القيمة الموروثة من المنشئ.

مثال: raw => qr/(?i:^jpegPhoto|;binary)/

مثال

$mesg = $ldap->search(
                       base   => $base_dn,
                       scope  => 'sub',
                       filter => '(|(objectclass=rfc822mailgroup)(sn=jones))'
                     );
Net::LDAP::LDIF->new( \*STDOUT,"w" )->write( $mesg->entries );
start_tls ( OPTIONS )
سيؤدي استدعاء هذه الطريقة إلى تحويل الاتصال الحالي إلى اتصال يستخدم Transport Layer Security (TLS)، والذي يوفر اتصالاً مشفرًا. هذا ممكن فقط إذا كان الاتصال يستخدم LDAPv3 ويتطلب أن تعلن الخادم عن دعم LDAP_EXTENSION_START_TLS. استخدم "supported_extension" في Net::LDAP::RootDSE للتحقق من ذلك.
verify => 'none' | 'optional' | 'require'
كيفية التحقق من شهادة الخادم:
none
قد يوفر الخادم شهادة ولكن لن يتم التحقق منها - قد يعني هذا أنك متصل بخادم غير صحيح.
optional
يتحقق فقط عندما يقدم الخادم شهادة.
require
يجب على الخادم تقديم شهادة ويجب أن تكون صالحة.

إذا قمت بتعيين verify إلى optional أو require، فيجب عليك أيضًا تعيين cafile أو capath. الخيار الأكثر أمانًا هو require.

sslversion => 'sslv2' | 'sslv3' | 'sslv23' | 'tlsv1' | 'tlsv1_1' | 'tlsv1_2'
يحدد إصدار بروتوكول SSL/TLS المراد استخدامه. الافتراضي هو القيمة التي يستخدمها IO::Socket::SSL افتراضيًا.

انظر "SSL_version" في IO::Socket::SSL لمزيد من التفاصيل.

sslserver => SSLHOST
يسمح بتغيير اسم الخادم لاستخدامه في التحقق من الشهادة، في حالة عدم تطابق اسم الهدف مع شهادة خادم LDAP. إذا لم يتم تحديده، فإن الافتراضي هو اسم مضيف (HOST) المتصل.

انظر "SSL_verifycn_name" في IO::Socket::SSL لمزيد من التفاصيل.

ciphers => CIPHERS
يحدد المجموعة الفرعية من مجموعات التشفير المسموح بها لهذا الاتصال.

CONTROLS

value => VALUE
If the control being requested requires a value then this element should hold the value for the server.

CALLBACKS

Most of the above commands accept a callback option. This option should be a reference to a subroutine. This subroutine will be called for each packet received from the server as a response to the request sent.

When the subroutine is called the first argument will be the Net::LDAP::Message object which was returned from the method.

If the request is a search then multiple packets can be received from the server. Each entry is received as a separate packet. For each of these the subroutine will be called with a Net::LDAP::Entry object as the second argument.

During a search the server may also send a list of references. When such a list is received then the subroutine will be called with a Net::LDAP::Reference object as the second argument.

LDAP ERROR CODES

Net::LDAP also exports constants for the error codes that can be received from the server, see Net::LDAP::Constant.
