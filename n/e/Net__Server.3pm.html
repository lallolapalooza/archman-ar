الحزمة: perl-net-server

التراخيص: PerlArtistic, GPL

Net::Server(3) وثائق Perl المساهم بها من قبل المستخدم Net::Server(3)

الاسم

Net::Server - محرك خادم Perl عام وقابل للتوسيع

الملخص

#!/usr/bin/perl -w -T
package MyPackage;
use base qw(Net::Server);
sub process_request {
    my $self = shift;
    while (<STDIN>) {
        s/[\r\n]+$//;
        print "لقد قلت '&$_'\015\012"; # صدى أساسي
        last if /quit/i;
    }
}
MyPackage->run(port => 160, ipv => '*');
# سطر واحد للانطلاق بسرعة
perl -e 'use base qw(Net::Server); main->run(port => 20208)'
ملاحظة: بدءًا من Net::Server 2.005، القيمة الافتراضية لـ
      ipv هي IPv* مما يعني أنه إذا لم يتم تمرير مضيف، أو
      تم تمرير اسم مضيف، سيتم ربط أي مقابس IPv4 و IPv6 متاحة.
      يمكنك فرض IPv4 فقط بإضافة ipv => 4
      تكوين بأي من الطرق النصف دزينة التي نسمح لك بها
      لتحديده.

الوصف

"Net::Server" هو محرك خادم Perl عام وقابل للتوسيع.

"Net::Server" يحاول أن يكون خادمًا عامًا مثل "Net::Daemon" و "NetServer::Generic". إنه يتضمن القدرة على العمل كعملية inetd ("Net::Server::INET")، خادم اتصال واحد ("Net::Server" أو "Net::Server::Single")، خادم متفرع ("Net::Server::Fork")، خادم يُحضر مسبقًا يحافظ على عدد ثابت من الأطفال المحضرين مسبقًا ("Net::Server::PreForkSimple")، أو كخادم مُدار للتحضير المسبق يقوم بالحفاظ على عدد الأطفال بناءً على حمل الخادم ("Net::Server::PreFork"). في جميع الأنواع باستثناء نوع inetd، يوفر الخادم القدرة على الاتصال بمنفذ خادم واحد أو أكثر.

يتم تمكين أنواع الخادم الإضافية عن طريق "الشخصيات" أو الفئات الفرعية من "Net::Server". عن طريق نقل أنواع الخوادم المتعددة خارج الفئة الرئيسية "Net::Server"، يتم توسيع مفهوم "Net::Server" بسهولة إلى أنواع أخرى (في المستقبل القريب، نود إضافة شخصية "Thread").

"Net::Server" يستعير العديد من المفاهيم من خادم Apache. "Net::Server" يستخدم "خطافات" للسماح للخوادم المخصصة مثل SMTP و HTTP و POP3 وما إلى ذلك بالتراكب فوق الفئة الأساسية "Net::Server". بالإضافة إلى ذلك، تستعير الفئة "Net::Server::PreFork" مفاهيم min_start_servers و max_servers و min_waiting servers. تستخدم "Net::Server::PreFork" أيضًا مفهوم قبول متسلسل باستخدام flock عند قبول الاتصالات على منافذ متعددة (يمكن لـ PreFork الاختيار بين flock و IPC::Semaphore و pipe للتحكم في التسلسل).

الشخصيات

"Net::Server" مبني حول فئة مشتركة (Net::Server) ويتم توسيعه باستخدام فئات فرعية، أو "شخصيات". كل شخصية ترث، تتجاوز، أو تعزز الأساليب الأساسية للفئة الأساسية.

مضمنة مع حزمة Net::Server عدة شخصيات أساسية، لكل منها استخدامها الخاص.

Fork
موجود في الوحدة Net/Server/Fork.pm (انظر Net::Server::Fork). يربط هذا الخادم بمنفذ واحد أو أكثر ثم ينتظر الاتصال. عند استلام طلب عميل، يقوم الأب بتفرع طفل، والذي يتعامل بعد ذلك مع العميل ويخرج. هذا جيد للخدمات التي يتم الوصول إليها بشكل معتدل.
INET
موجود في الوحدة Net/Server/INET.pm (انظر Net::Server::INET). تم تصميم هذا الخادم للاستخدام مع inetd. يتم تجاوز الأساليب "pre_bind" و "bind" و "accept" و "post_accept" لأن هذه الخدمات يتم الاهتمام بها بواسطة خادم INET.
MultiType
موجود في الوحدة Net/Server/MultiType.pm (انظر Net::Server::MultiType). ليس لهذا الخادم وظيفة خادم خاصة به. إنه مصمم للخوادم التي تحتاج إلى طريقة بسيطة للتبديل بسهولة بين الشخصيات المختلفة. يمكن إعطاء معلمات "server_type" متعددة وسوف تتنقل Net::Server::MultiType عبرها حتى تجد فئة يمكنها استخدامها.
Multiplex
موجود في الوحدة Net/Server/Multiplex.pm (انظر Net::Server::Multiplex). يربط هذا الخادم بمنفذ واحد أو أكثر. يستخدم IO::Multiplex لتعددية المهام بين انتظار الاتصالات الجديدة وانتظار الإدخال على الاتصالات القائمة حاليًا. تم تصميم هذه الشخصية للعمل كعملية واحدة دون تفرع. لا يتم استخدام الأسلوب "process_request" أبدًا ولكن يتم استخدام الخطاف "mux_input" بدلاً من ذلك (انظر أيضًا IO::Multiplex). انظر examples/samplechat.pl كمثال يستخدم معظم ميزات Net::Server::Multiplex.
PreForkSimple
موجود في الوحدة Net/Server/PreFork.pm (انظر Net::Server::PreFork). يربط هذا الخادم بمنفذ واحد أو أكثر ثم يقوم بتفرع "max_servers" عملية طفل. سيتأكد الخادم من وجود دائمًا "max_servers" متاحة في أي وقت لاستقبال طلب عميل. كل من هؤلاء الأطفال سيعالج ما يصل إلى "max_requests" اتصالات عميل. هذا النوع جيد للمواقع التي يتم الوصول إليها بكثافة والتي يمكنها تخصيص عمليات max_server بغض النظر عن الحمل. يجب أن يكون قابلاً للتوسع لمعظم التطبيقات. يتم تحقيق قبول منافذ متعددة باستخدام flock أو IPC::Semaphore أو pipe لتسلسل الأطفال. يمكن أيضًا تشغيل التسلسل لمنفذ واحد لتجاوز نظام تشغيل لا يسمح لأطفال متعددين بالقبول في نفس الوقت. لمزيد من المناقشة حول التسلسل، انظر Net::Server::PreFork.
PreFork
موجود في الوحدة Net/Server/PreFork.pm (انظر Net::Server::PreFork). يربط هذا الخادم بمنفذ واحد أو أكثر ثم يقوم بتفرع "min_servers" عملية طفل. سيتأكد الخادم من وجود ما لا يقل عن "min_spare_servers" ولكن ليس أكثر من "max_spare_servers" متاحة في أي وقت لاستقبال طلب عميل، بحد أقصى "max_servers". كل من هؤلاء الأطفال سيعالج ما يصل إلى "max_requests" اتصالات عميل. هذا النوع جيد للمواقع التي يتم الوصول إليها بكثافة، ويجب أن يكون قابلاً للتوسع لمعظم التطبيقات. يتم تحقيق قبول منافذ متعددة باستخدام flock أو IPC::Semaphore أو pipe لتسلسل الأطفال. يمكن أيضًا تشغيل التسلسل لمنفذ واحد لتجاوز نظام تشغيل لا يسمح لأطفال متعددين بالقبول في نفس الوقت. لمزيد من المناقشة حول التسلسل، انظر Net::Server::PreFork.
Single
جميع الأساليب تسقط إلى Net::Server. تم توفير هذه الشخصية فقط كبديل لـ Net::Server::MultiType.
HTTP
موجود في الوحدة Net/Server/HTTP.pm (انظر Net::Server::HTTP). هذا الخادم هو مثال على كيفية إنشاء شخصية مخصصة. هو خادم HTTP بسيط للغاية يقوم بتشغيل طلبات HTTP الأساسية. يوفر وظائف سجل Apache القياسية.

Net::Server Documentation

HOOK METHODS

"$self->child_init_hook()"
Called just after a child process has been forked, but before the child has begun processing requests. The parent process is unaware of this hook running.
"$self->child_prefork_hook()"
Called by the parent process just before the fork. This is called only once per child that is forked. There is no equivalent hook for the child.
"$self->register_child($pid, $type)"
Called by the parent process when a child has been forked. Type will be one of dequeue, fork, prefork, or preforksimple depending on where the child was created.
"$self->child_finish_hook()"
Similar to the child_init_hook, but ran when the forked process is about to finish up.

OTHER METHODS

"$self->default_values"
Allow for returning configuration values that will be used if no other value could be found.

Should return a hashref.

sub default_values {
    return {
        port => 20201,
    };
}
"$self->handle_syslog_error"
Called when log_file is set to 'Sys::Syslog' and an error occurs while writing to the syslog. It is passed two arguments, the value of $@, and an arrayref containing the arguments that were passed to the log method when the error occurred.
"$self->log"
Parameters are a log_level and a message.

If log_level is set to 'Sys::Syslog', the parameters may alternately be a log_level, a format string, and format string parameters. (The second parameter is assumed to be a format string if additional arguments are passed along). Passing arbitrary format strings to Sys::Syslog will allow the server to be vulnerable to exploit. The server maintainer should make sure that any string treated as a format string is controlled.

# assuming log_file = 'Sys::Syslog'
$self->log(1, "My Message with %s in it");
# sends "%s", "My Message with %s in it" to syslog
$self->log(1, "My Message with %s in it", "Foo");
# sends "My Message with %s in it", "Foo" to syslog

If log_file is set to a file (other than Sys::Syslog), the message will be appended to the log file by calling the write_to_log_hook.

If the log_file is Sys::Syslog and an error occurs during write, the handle_syslog_error method will be called and passed the error exception. The default option of handle_syslog_error is to die - but could easily be told to do nothing by using the following code in your subclassed server:

sub handle_syslog_error {}

It the log had been closed, you could attempt to reopen it in the error handler with the following code:

sub handle_syslog_error {
    my $self = shift;
    $self->open_syslog;
}
"$self->new"
As of Net::Server 0.91 there is finally a "new" method. This method takes a class name and an argument hashref as parameters. The argument hashref becomes the "server" property of the object. 
package MyPackage;
use base qw(Net::Server);
my $obj = MyPackage->new({port => 20201});
# same as
my $obj = bless {server => {port => 20201}}, 'MyPackage';
"$self->open_syslog"
Called during post_configure when the log_file option is set to 'Sys::Syslog'. By default it use the parsed configuration options listed in this document. If more custom behavior is desired, the method could be overridden and Sys::Syslog::openlog should be called with the custom parameters.
"$self->shutdown_sockets"
This method will close any remaining open sockets. This is called at the end of the server_close method.

RESTARTING

Each of the server personalities (except for INET), support restarting via a HUP signal (see "kill -l"). When a HUP is received, the server will close children (if any), make sure that sockets are left open, and re-exec using the same commandline parameters that initially started the server. (Note: for this reason it is important that @ARGV is not modified until "->run" is called).

The Net::Server will attempt to find out the commandline used for starting the program. The attempt is made before any configuration files or other arguments are processed. The outcome of this attempt is stored using the method "->commandline". The stored commandline may also be retrieved using the same method name. The stored contents will undoubtedly contain Tainted items that will cause the server to die during a restart when using the -T flag (Taint mode). As it is impossible to arbitrarily decide what is taint safe and what is not, the individual program must clean up the tainted items before doing a restart.

sub configure_hook{
    my $self = shift;
    ### see the contents
    my $ref  = $self->commandline;
    use Data::Dumper;
    print Dumper $ref;
    ### arbitrary untainting - VERY dangerous
    my @untainted = map {/(.+)/;$1} @$ref;
    $self->commandline(\@untainted)
}

SHUTDOWN

Each of the Fork and PreFork personalities support graceful shutdowns via the QUIT signal. When a QUIT is received, the parent will signal the children and then wait for them to exit.

All server personalities support the normal TERM and INT signal shutdowns.

HOT DEPLOY

Since version 2.000, the Fork and PreFork personalities have accepted the TTIN and TTOU signals. When a TTIN is received, the max_servers is increased by 1. If a TTOU signal is received the max_servers is decreased by 1. This allows for adjusting the number of handling processes without having to restart the server.

If the log_level is set to at 3, then the new value is displayed in the logs.

وسائط لـ Net::Server:

  • listen - عنوان IP والمنفذ للاستماع عليه
  • server - اسم الخادم
  • max_servers - الحد الأقصى لعدد الخوادم المراد تشغيلها
  • max_connections - الحد الأقصى لعدد الاتصالات لكل خادم
  • max_children - الحد الأقصى لعدد العمليات الفرعية المراد تشغيلها
  • max_restarts - الحد الأقصى لعدد عمليات إعادة التشغيل
  • timeout - مهلة الاتصالات
  • log - ملف السجل للكتابة فيه
  • log_level - مستوى السجل
  • log_format - تنسيق السجل
  • log_rotate - تدوير السجل
  • log_tz - المنطقة الزمنية
