NAME

\n

nethack - Exploring The Mazes of Menace

\n
\n
\n

SYNOPSIS

\n

nethack [ -d directory ] [ -n ] [ \n -p profession ] [ -r race ] [ -[DX] ] [ \n -u playername ] [ -dec ] [ -ibm ] [ \n --showpaths ] [ --version[:paste] ]

\n

nethack [ -d directory ] -s [ \n -v ] [ -p profession ] [ -r race ] [ \n playernames ]

\n
\n
\n

DESCRIPTION

\n

NetHack is a display oriented Dungeons & Dragons(tm) - \n like game. The standard tty display and command structure resemble\n rogue.

\n

Other, more graphical display options exist for most\n platforms.

\n

To get started you really only need to know two commands. The\n command ? will give you a list of the available commands (as well as\n other information) and the command / will identify the things you see\n on the screen.

\n

To win the game (as opposed to merely playing to beat other\n people's high scores) you must locate the Amulet of Yendor which is\n somewhere below the 20th level of the dungeon and get it out. Few people\n achieve this; most never do. Those who have go down in history as heroes\n among heroes - and then they find ways of making the game even harder. See\n the Guidebook section on Conduct if this game has gotten too easy for\n you.

\n

When the game ends, whether by your dying, quitting, or escaping\n from the caves, NetHack will give you (a fragment of) the list of top\n scorers. The scoring is based on many aspects of your behavior, but a rough\n estimate is obtained by taking the amount of gold you've found in the cave\n plus four times your (real) experience. Precious stones may be worth a lot\n of gold when brought to the exit. There is a 10% penalty for getting\n yourself killed.

\n

The environment variable NETHACKOPTIONS can be used to initialize\n many run-time options. The ? command provides a description of these options\n and syntax. (The -dec and -ibm command line options are\n equivalent to the decgraphics and ibmgraphics run-time options\n described there, and are provided purely for convenience on systems\n supporting multiple types of terminals.)

\n

Because the option list can be very long (particularly when\n specifying graphics characters), options may also be included in a\n configuration file. The default is located in your home directory and named\n .nethackrc on Unix systems. On other systems, the default may be different,\n usually NetHack.cnf. On DOS or Windows, the name is defaults.nh, while on\n the Macintosh or BeOS, it is NetHack Defaults. The configuration file's\n location may be specified by setting NETHACKOPTIONS to a string consisting\n of an @ character followed by the filename.

\n

The -u playername option supplies the answer to the\n question "Who are you?". It overrides any name from the options or\n configuration file, USER, LOGNAME, or getlogin(), which will otherwise be\n tried in order. If none of these provides a useful name, the player will be\n asked for one. Player names (in conjunction with uids) are used to identify\n save files, so you can have several saved games under different names.\n Conversely, you must use the appropriate player name to restore a saved\n game.

\n

A playername suffix can be used to specify the profession,\n race, alignment and/or gender of the character. The full syntax of the\n playername that includes a suffix is "name-ppp-rrr-aaa-ggg".\n "ppp" are at least the first three letters of the profession (this\n can also be specified using a separate -p profession option).\n "rrr" are at least the first three letters of the character's race\n (this can also be specified using a separate -r race option).\n "aaa" are at least the first three letters of the character's\n alignment, and "ggg" are at least the first three letters of the\n character's gender. Any of the parts of the suffix may be left out.

\n

-p profession can be used to determine the character\n profession, also known as the role. You can specify either the male or\n female name for the character role, or the first three characters of the\n role as an abbreviation. -p @ has been retained to explicitly request\n that a random role be chosen. It may need to be quoted with a backslash (\@)\n if @ is the "kill" character (see "stty") for the\n terminal, in order to prevent the current input line from being cleared.

\n

Likewise, -r race can be used to explicitly request\n that a race be chosen.

\n

Leaving out any of these characteristics will result in you being\n prompted during the game startup for the information.

\n

The -s option alone will print out the list of your scores\n on the current version. An immediately following -v reports on all\n versions present in the score file. The -s may also be followed by\n arguments -p and -r to print the scores of particular roles\n and races only. It may also be followed by one or more player names to print\n the scores of the players mentioned, by 'all' to print out all scores, or by\n a number to print that many top scores.

\n

The -n option suppresses printing of any news from the game\n administrator.

\n

The -D or -X option will start the game in a special\n non-scoring discovery mode. -D will, if the player is the game\n administrator, start in debugging (wizard) mode instead.

\n

The -d option, which must be the first argument if it\n appears, supplies a directory which is to serve as the playground. It\n overrides the value from NETHACKDIR, HACKDIR, or the directory specified by\n the game administrator during compilation (usually\n /usr/games/lib/nethackdir). This option is usually only useful to the game\n administrator. The playground must contain several auxiliary files such as\n help files, the list of top scorers, and a subdirectory save where\n games are saved.

\n

--showpaths can be used to cause NetHack to show where it\n is expecting to find various configuration files.

\n

--version can be used to cause NetHack to show the version\n information it was compiled with, then exit. That will include the\n git commit hash if the information was available when the game was\n compiled. On some platforms, such as windows and macosx, a variation\n --version:paste can be used to cause NetHack to show the version\n information, then exit, while also leaving a copy of the version information\n in the paste buffer or clipboard for potential insertion into things like\n bug reports.

\n
\n
\n

AUTHORS

\n

Jay Fenlason (+ Kenny Woodland, Mike Thome and Jon Payne) wrote\n the original hack, very much like rogue (but full of bugs).

\n

Andries Brouwer continuously deformed their sources into an\n entirely different game.

\n

Mike Stephenson has continued the perversion of sources, adding\n various warped character classes and sadistic traps with the help of many\n strange people who reside in that place between the worlds, the Usenet Zone.\n A number of these miscreants are immortalized in the historical roll of\n dishonor and various other places.

\n

The resulting mess is now called NetHack, to denote its\n development by the Usenet. Andries Brouwer has made this request for the\n distinction, as he may eventually release a new version of his own.

\n
\n
\n

FILES

\n

Run-time configuration options were discussed above and use a\n platform specific name for a file in a platform specific location. For Unix,\n the name is '.nethackrc' in the user's home directory.

\n

All other files are in the playground directory, normally\n /usr/games/lib/nethackdir. If DLB was defined during the compile, the data\n files and special levels will be inside a larger file, normally nhdat, \n instead of being separate files.

\n

nethack The program itself.\n
\n data, oracles, rumors Data files used by NetHack.\n
\n quest.dat, bogusmon More data files.\n
\n engrave, epitaph, tribute Still more data files.\n
\n symbols Data file holding sets of specifications\n
\n for how to display monsters, objects, and\n
\n map features.\n
\n options Data file containing a description of the \tbuild-time option settings.\n
\n help, hh Help data files.\n
\n cmdhelp, opthelp, wizhelp More help data files.\n
\n *.lev Predefined special levels.\n
\n dungeon Control file for special levels.\n
\n history A short history of NetHack.\n
\n license Rules governing redistribution.\n
\n record The list of top scorers.\n
