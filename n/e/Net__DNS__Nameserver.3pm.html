NAME

Net::DNS::Nameserver - A DNS nameserver class

SYNOPSIS

    use Net::DNS::Nameserver;
    sub reply_handler {
        my ($q, $nameserver) = @_;
        # ... process the query ...
        # return an array of Net::DNS::RR objects for the answer, authority, and
        # additional sections.
        #
        # The question ($q) is a Net::DNS::Question object.
        # The nameserver ($nameserver) is a Net::DNS::Nameserver object.
        #
        # $q->query() returns the name being queried.
        # $q->type() returns the query type.
        #
        # Example:
        my @ans;
        my $rr = undef;
        if ($q->query() eq "example.com.") {
            $rr = new Net::DNS::RR(
                Name     => "example.com.",
                Type     => "A",
                TTL      => 3600,
                Address  => "1.2.3.4",
            );
            push @ans, $rr;
        }
        return (@ans);
    }
    my $ns = Net::DNS::Nameserver->new(
        LocalPort    => 53,
        ReplyHandler => \&reply_handler,
        Verbose      => 1,
        ) or die "couldn't create nameserver object";
    $ns->start_server;
    # ... server runs until interrupted ...
    exit;

DESCRIPTION

Net::DNS::Nameserver provides a framework for writing a DNS nameserver in Perl. It handles the low-level details of listening for DNS queries, parsing them, and sending replies.

You create a subclass of Net::DNS::Nameserver, implement a reply_handler subroutine, and then start the server.

METHODS

Net::DNS::Nameserver->new(...) new() creates a new Net::DNS::Nameserver object. It takes the following arguments:

LocalPort
The port to listen on. Defaults to 53.
ListenAddress
The IP address(es) to listen on. Defaults to all available addresses.
ReplyHandler
A reference to a subroutine that will be called to handle incoming queries. This subroutine will receive two arguments: the query object (a Net::DNS::Question) and the nameserver object itself. It should return an array of Net::DNS::RR objects that will form the answer, authority, and additional sections of the reply.
Verbose
If set to 1 or higher, the nameserver will print debugging information.

start_server(...) start_server() starts the nameserver listening for queries. It takes an optional argument, timeout, which specifies how many seconds to run the server for before exiting. If no timeout is specified, the server will run indefinitely until interrupted.

stop_server() stop_server() stops the nameserver.

EXAMPLES

# A simple nameserver that always replies with 1.2.3.4 for example.com
# and an SOA record for .
sub reply_handler {
    my ($q, $ns) = @_;
    my @ans;
    my $rcode = $ns->rcode(); # Default is NOERROR
    my @auth;
    my @add;
    my $headermask = {
        qr_header => {},
        qr_question => $q,
    };
    if ($q->type() eq 'SOA') {
        push @ans, new Net::DNS::RR(
            Name => '.',
            Type => 'SOA',
            TTL => 3600,
            Primary => 'ns1.example.com.',
            Admin => 'admin.example.com.',
            Serial => 1,
            Refresh => 10800,
            Retry => 3600,
            Expire => 604800,
            Minimum => 86400,
        );
    } elsif ($q->query() eq 'example.com.' && $q->type() eq 'A') {
        push @ans, new Net::DNS::RR(
            Name => 'example.com.',
            Type => 'A',
            TTL => 3600,
            Address => '1.2.3.4',
        );
    } else {
        $rcode = $ns->rcode('NXDOMAIN'); # Not found
    }
    my $optionmask = {};
    return ( $rcode, \@ans, \@auth, \@add, $headermask, $optionmask );
}
my $ns = Net::DNS::Nameserver->new(
                LocalPort    => 15353,
                ReplyHandler => \&reply_handler,
                Verbose      => 1
                ) or die "couldn't create nameserver object";
$ns->start_server(60);
exit;   # leaving nameserver processes running for 60 seconds

BUGS

Limitations in perl make it impossible to guarantee that replies to UDP queries from Net::DNS::Nameserver are sent from the IP-address to which the query was directed, the source address being chosen by the operating system based upon its notion of "closest address". This limitation is mitigated to some extent by creating a separate socket and subprocess for each IP address.
