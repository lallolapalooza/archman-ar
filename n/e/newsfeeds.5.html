FLAGS

D
The body of the Distribution header field of the article, or "?" if there is no such header field in the article.
G
Where the article is stored. If the newsgroup is crossposted, this is generally the first of the groups to which it was posted that this site receives; however, control messages are filed in control or control.* (which is the difference between this item and "g").
H
All of the headers, followed by a blank line. The Xref header field will already be present, and a Bytes header field containing the article's size in bytes as in the "b" item will be added to the headers. If used, this should be the only item in the list.
N
The body of the Newsgroups header field.
P
The body of the Path header field.
O
Overview data for the article.
R
Information needed for replication (the Xref header field without the site name).

More than one letter can be given. If multiple items are specified, they will be written in the order specified separated by spaces. ("H" should be the only item if given, but if it's not a newline will be sent before the beginning of the headers.) The default is Wn.

The "H" and "O" items are intended for use by programs that create news overview databases or require similar information. WnteO is the flag to generate input needed by the overchan(8) program.

The asterisk ("*") has special meaning. Normally it expands to a space-separated list of all sites that received the current article. If, however, this site is a target of a funnel feed (in other words, if it is named by other sites which have the Tm flag), then the asterisk expands to the names of the funnel feeds that received the article. Similarly, if the site is a program feed, an asterisk in the parameter field will be expanded into the list of funnel feeds that received the article. A program feed cannot get the site list unless it is the target of other Tm feeds.

أنواع التغذية (FEED TYPES)

innd يوفر أربعة أنواع أساسية من التغذية: سجل (log)، ملف (file)، برنامج (program)، وقناة (channel). المفسر (exploder) هو نوع خاص من القناة. بالإضافة إلى ذلك، يمكن أن تغذي عدة إدخالات نفس التغذية؛ هذه هي تغذيات القمع (funnel feeds)، والتي تشير إلى إدخال هو أحد الأنواع الأخرى. تم وصف تغذيات القمع جزئيًا أعلاه مع وصف علامة W*. تحصل تغذية القمع على كل مقال سيتم إرساله إلى أي من التغذيات التي تصب فيه، وعادة ما تتضمن علامة W* في علاماتها حتى يعرف البرنامج الذي يعالج تلك التغذية المواقع التي تلقت المقالات. أشهر تغذية قمع هي innfeed(8).

لاحظ أن مصطلح "تغذية" (feed) هو تسمية خاطئة تقنيًا، نظرًا لأن الخادم لا ينقل المقالات بنفسه ويكتب البيانات فقط إلى ملف أو برنامج أو سجل لإخبار برنامج آخر بنقل المقالات.

أبسط تغذية هي تغذية السجل (Tl). بخلاف الإشارة في ملف سجل الأخبار، pathlog/news، لا تتم كتابة أي بيانات. هذا يعادل إدخال Tf يكتب إلى /dev/null، باستثناء أنه لا يتم فتح أي ملف على الإطلاق. مسح تغذية السجل لا يفعل شيئًا.

تغذية الملف (Tf) هي النوع التالي الأبسط من التغذية. عندما يتلقى الموقع مقالًا، تتم كتابة البيانات المحددة إلى الملف المسمى بواسطة حقل parameter. إذا لم يكن parameter مسارًا مطلقًا، فيُعتبر نسبيًا للمسار pathoutgoing في inn.conf. إذا لم يتم توفير parameter، فإنه افتراضيًا لـ pathoutgoing/sitename. يجب أن يكون اسم الملف فريدًا (لا ينبغي أن يشير تغذيتان للملفات أبدًا إلى نفس الملف).

تم تصميم تغذيات الملفات للاستخدام بواسطة برامج خارجية تعالج البيانات المكتوبة بشكل دوري. للتعاون مع innd بشكل صحيح، يجب على البرامج الخارجية أولاً إعادة تسمية ملف الدفعة ثم إرسال أمر flush لهذا الموقع إلى innd باستخدام ctlinnd(8). سيقوم innd بعد ذلك بكتابة أي بيانات مخزنة مؤقتًا، وإغلاق الملف، وإعادة فتحه (تحت الاسم الأصلي)، ويمكن للبرنامج معالجة البيانات في الملف المعاد تسميته حسب رغبته. غالبًا ما تُستخدم تغذيات الملفات بالاشتراك مع nntpsend(8).

تغذية البرنامج (Tp) تقوم بتشغيل برنامج معين لكل مقال يتلقاه الموقع. يجب أن يكون حقل parameter هو سطر الأوامر للتنفيذ، ويجب أن يحتوي على نسخة واحدة من %s، والتي سيتم استبدالها برمز واجهة برمجة تطبيقات التخزين للمقال (يمكن للبرنامج استرداد المقال الفعلي باستخدام sm(8)). لن يتلقى البرنامج شيئًا على المدخل القياسي (على عكس الإصدارات السابقة من INN، حيث يتم إرسال المقال إلى البرنامج على stdin)، وسيتم تعيين الإخراج القياسي والخطأ من البرنامج إلى سجل الخطأ (pathlog/errlog). سيحاول innd تجنب تشغيل shell إذا لم يحتوي الأمر على أي أحرف تعريفية لـ shell؛ يمكن هزيمة هذه الميزة إذا لزم الأمر لسبب ما عن طريق إضافة فاصلة منقوطة في نهاية الأمر. يجب تحديد المسار الكامل للبرنامج المراد تشغيله ما لم يتم تشغيل الأمر بواسطة shell (ويوصى بشدة بتحديد المسار الكامل دائمًا بغض النظر).

إذا كانت تغذية البرنامج هي هدف لتغذية قمع، وإذا ظهر W* في علامات الموقع، فقد توجد نجمة واحدة في parameter وسيتم استبدالها بقائمة مفصولة بمسافات بأسماء المواقع التي تغذي القمع والتي تلقت المقال المعني. إذا لم يكن الموقع هدفًا لتغذية قمع، أو إذا لم يتم استخدام علامة W*، فإن النجمة ليس لها معنى خاص.

مسح تغذية البرنامج لا يفعل شيئًا.

بالنسبة لتغذية القناة (Tc) أو المفسر (Tx)، يحدد حقل parameter مرة أخرى العملية المراد تشغيلها. كما هو الحال مع تغذيات البرامج، يجب تحديد المسار الكامل للبرنامج. ومع ذلك، بدلاً من تشغيل البرنامج لكل مقال، يتم تشغيله مرة واحدة ثم كلما تلقى الموقع مقالًا، تتم كتابة البيانات المحددة بواسطة علامات الموقع إلى المدخل القياسي للبرنامج المشغل. يتم تعيين الإخراج القياسي والأخطاء كما هو الحال مع تغذيات البرامج. إذا خرجت العملية، فسيتم إعادة تشغيلها تلقائيًا. إذا فشل تشغيل العملية، فسيقوم الخادم بتخزين الإدخال مؤقتًا في ملف يسمى pathoutgoing/sitename وسيتحاول بدء العملية مرة أخرى لاحقًا.

عند مسح تغذية قناة أو مفسر، يقوم الخادم بإغلاق طرفه من الأنبوب إلى المدخل القياسي للبرنامج. سيتم تخزين أي بيانات معلقة لم يتم كتابتها مؤقتًا؛ انظر وصف علامة S أعلاه. سيقوم الخادم بعد ذلك بتشغيل نسخة جديدة من البرنامج. لا يتم إرسال أي إشارة إلى البرنامج؛ يعود الأمر للبرنامج الذي يعالج تغذية قناة أو مفسر لملاحظة نهاية الملف على مدخله القياسي والخروج بشكل مناسب.

المفسرات هي نوع خاص من تغذيات القنوات. بالإضافة إلى سلوك تغذية القناة الموصوف أعلاه، يمكن أيضًا إرسال أسطر الأوامر إلى المفسرات. تبدأ هذه الأسطر بنقطة تعجب وتفسيرها متروك للمفسر. الأوامر التالية يتم إنشاؤها تلقائيًا بواسطة الخادم:

!newgroup group
!rmgroup group
!flush
!flush site

يتم إرسال هذه الأوامر كلما تم تلقي أمر ctlinnd(8) بنفس الاسم بواسطة الخادم. بالإضافة إلى ذلك، يمكن استخدام أمر ctlinnd(8) "send" لإرسال سطر أوامر عشوائي إلى مفسر. المفسر الأساسي هو buffchan(8).

أخيرًا، تغذيات Tm هي مدخلات لقمع. يجب أن يحدد حقل parameter للموقع اسم الموقع الذي يعالج المقالات لجميع مدخلات القمع.

أمثلة (EXAMPLES)

بنية ملف newsfeeds معقدة للغاية لأنك تستطيع تحديد مجموعة واسعة بشكل مذهل من التغذيات. INN قادر على التفاعل مع مجموعة واسعة من البرامج التي تفعل أشياء مختلفة مع مقالات الأخبار. ومع ذلك، فإن أشهر إدخالين في newsfeeds هما تغذيات الملفات لـ nntpsend(8) وتغذيات القمع لـ innfeed(8).

الأول يبدو هكذا:

feed.example.com:*,!control,!control.*,!junk:Tf,Wnm:

والذي ينشئ ملفًا يسمى pathoutgoing/feed.example.com يحتوي على سطر واحد لكل مقال يتكون من رمز واجهة برمجة تطبيقات التخزين، ومسافة، ومعرف الرسالة.

والثاني يبدو هكذا:

feed.example.com:*,!control,!control.*,!junk:Tm:innfeed!

شبه ذلك تمامًا، باستثناء أن هذه هي مدخلات لتغذية قمع تسمى "innfeed!". يمكن للمرء أيضًا كتابة هذا بالشكل:

example/feed.example.com:*,!control,!control.*,!junk:Ap,Tm:innfeed!

(لاحظ Ap بحيث لا تزال المقالات التي تحتوي على "example" فقط في جسم حقل المسار (Path) يتم إرسالها)، وهو مكافئ تمامًا باستثناء أنه سيتم تسجيل ذلك في pathlog/news على أنه يذهب إلى الموقع "example" بدلاً من "feed.example.com".

الإدخال النموذجي للتغذية لـ innfeed(8) هو مثال جيد لتغذية قناة هي هدف لتغذيات قمع مختلفة (تأكد من تعيين المسار إلى innfeed بشكل صحيح):

innfeed!:!*:Tc,Wnm*:<pathbin in inn.conf>/innfeed -y

لاحظ أن pattern لهذه التغذية هو ببساطة "!*" لذلك لن تتلقى أي مقالات مباشرة. يجب أن تتلقى التغذية فقط تلك المقالات التي ستذهب إلى إحدى تغذيات القمع التي تصب فيها. سيتلقى innfeed(8) سطرًا واحدًا لكل مقال على مدخله القياسي يحتوي على رمز واجهة برمجة تطبيقات التخزين، ومعرف الرسالة، وقائمة مفصولة بمسافات بالمواقع التي يجب أن تتلقى هذا المقال.

إليك مثال أكثر غرابة لتغذية قناة:

watcher!:*:Tc,Wbnm\
    :exec awk '$1 > 1000000 { print "BIG", $2, $3 }' \
     >> <pathlog>/bigart

هذا يتلقى حجم البايت لكل مقال مع رمز واجهة برمجة تطبيقات التخزين ومعرف الرسالة، ويضيف إلى ملف سجل bigart سطرًا لكل مقال يزيد حجمه عن مليون بايت. هذه في الواقع طريقة غريبة لكتابة هذا لأن

newsfeeds(5)

الحزمة: inn

التراخيص: custom:INN

NAME

newsfeeds — format of the INN newsfeeds file

IN A NUTSHELL

The newsfeeds file is the INN configuration file that defines how articles are distributed, both locally and remotely.

DESCRIPTION

The newsfeeds file is an ASCII file, readable by all users, that describes how articles should be distributed. Each line in the file defines a single distribution channel, and consists of three colon-separated fields:

distribution
This is a newsgroup pattern that determines which articles this entry applies to. It is a comma-separated list of distributions (like world, mit, usa, etc.) and newsgroup names (like comp.sources.unix). See active(5) for a description of distributions.
destination
This defines where the articles matching the distribution should be sent. It can be a site name (in which case INN will try to send the article to that site using NNTP), a shell command to be run, or one of the special internal destinations defined by INN (like local or all).
flags
This is a comma-separated list of flags that modify the behavior of this feed. The flags control what kind of articles are sent, what arguments are passed to commands, and other details.

A blank line or a line starting with the comment character # is ignored.

FLAG VALUES

The following flags are recognized:

A
Send article text only (no headers).
C
Use the controlchan(8) program to handle control messages. This flag implies T.
L
Send article text and headers, but do not strip any MIME headers. This is the default.
M
Send article text and headers, stripping any MIME headers that are not needed to reconstruct the article.
n
Only send articles to this feed if they are posted locally. This is used for feeding local postings to external sites.
N
Only send articles to this feed if they are received from external sites. This is used for feeding locally posted articles to external sites.
R
Send article text and headers, stripping MIME headers but leaving enough so that the article can be reconstructed. This is the default for !-style feeds.
s
Send article text and headers, but do not strip any MIME headers. This is the default for !-style feeds.
m
Send article text and headers, stripping MIME headers but leaving enough so that the article can be reconstructed. This is the default.
T
Add the inn.conf(5) variable pathbin/sm to the beginning of the command line. This is the default for command-line feeds.
t
Do not add the pathbin/sm program to the command line. This is the default for site-to-site feeds.
c
Do not add the pathbin/sm program to the command line. This is the default for site-to-site feeds.
W
Do not prepend pathbin/sm to the command. This is the default for site-to-site feeds.
w
Prepend pathbin/sm to the command. This is the default for command-line feeds.
p
Pass the article through the innfeed(8) program before sending it to the destination. This is used for filtering and modification of articles.
P
Pass the article through the innfeed(8) program before sending it to the destination. This is used for filtering and modification of articles.
X
When the destination is a shell command, the article is piped to the command. Otherwise, the command is executed with the article name as an argument.
x
When the destination is a shell command, the article is passed as an argument. Otherwise, the command is executed with the article name as an argument.
Y
Do not send the article to the destination if it is a duplicate.
y
Send the article to the destination even if it is a duplicate.
Tc
Send the article to the destination, piping it to the command specified. This is the default for command-line feeds.
Wbnm
Do not send the article to the destination if it is a duplicate. Use the innfeed(8) program to filter the article. Send the article text only, and do not strip MIME headers.
Tm
Send the article to the destination, piping it to the command specified. This is the default for command-line feeds. Strip MIME headers but leave enough so that the article can be reconstructed.
Tc,Wbnm
Send the article to the destination, piping it to the command specified. Do not send the article to the destination if it is a duplicate. Use the innfeed(8) program to filter the article. Send the article text only, and do not strip MIME headers.
Tm:
Send the article to the destination, piping it to the command specified. This is the default for command-line feeds. Strip MIME headers but leave enough so that the article can be reconstructed.
Tc,Tc
Send the article to the destination, piping it to the command specified. This is the default for command-line feeds.
AC,Tc
Send the article to the destination, piping it to the command specified. Use the controlchan(8) program to handle control messages. This flag implies T.
Tc,Wnsm
Send the article to the destination, piping it to the command specified. Do not send the article to the destination if it is a duplicate. Use the innfeed(8) program to filter the article. Send the article text only, and do not strip MIME headers.
W*
When the destination is a shell command, the article is piped to the command. Otherwise, the command is executed with the article name as an argument.

FEED TYPES

There are several types of feeds:

Site feeds
These feeds send articles to another NNTP server. They are identified by a site name as the destination.
Command feeds
These feeds execute a shell command to process the articles. They are identified by a command as the destination.
Funnel feeds
These feeds are used to group multiple feeds under a single name. They are identified by a name followed by an exclamation mark (!) as the destination.
Local feeds
These feeds send articles to local programs or files. They are identified by special keywords like local or all as the destination.

EXAMPLES

Here are a few examples of newsfeeds entries:

This entry sends all articles in the junk newsgroup to the site otherserver:

junk:otherserver:Tn

This entry sends all articles in the world distribution to the local feed, which means they are processed by local newsreaders.

world:local:T

This entry sends articles larger than 1MB to a file named bigart in the pathlog directory:

watcher!:*:Tc,>1000000,Wbnm\
    :exec awk '{ print "BIG", $2, $3}' >> <pathlog>/bigart

Here's a cute, really simple news to mail gateway that also serves as an example of a fairly fancy program feed:

mailer!:!*:W*,Tp\
    :sm %s | innmail -s "News article" *

Remember that %s is replaced by the storage API token, so this retrieves the article and pipes it into innmail (which is safer than programs like Mail(1) because it doesn't parse the body for tilde commands) with a given subject line. Note the use of "*" in the command line and W* in the flags; this entry is designed to be used as the target of funnel feeds such as:

peter@example.com:news.software.nntp:Tm:mailer!
sue@example.com:news.admin.misc:Tm:mailer!

Suppose that the server receives an article crossposted between news.admin.misc and news.software.nntp. The server will notice that the article should be sent to the site "peter@example.com" and the site "bob@example.com", both of which funnel into "mailer!", so it will look at the "mailer!" site and end up executing the command line:

sm @...@ | innmail -s "News article" \
    peter@example.com sue@example.com

which will mail the article to both Peter and Sue.

Finally, another very useful example of a channel feed: the standard entry for controlchan(8). Make sure its path is properly set.

controlchan!\
    :!*,control,control.*,!control.cancel\
    :AC,Tc,Wnsm:<pathbin in inn.conf>/controlchan

This program only wants information about articles posted to a control newsgroup other than control.cancel, which due to the sorting of control messages described in innd(8) will send it all control messages except for cancel messages. controlchan gets the storage API token, the name of the sending site (for processing old-style ihave and sendme control messages, be sure to read about logipaddr in controlchan(8)), and the message ID for each article.

For many other examples, including examples of the special "ME" site entry, see the example newsfeeds file distributed with INN. Also see the install documentation that comes with INN for information about setting up the standard newsfeeds entries used by most sites.
