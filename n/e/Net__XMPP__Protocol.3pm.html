SetCallBacks
SetCallBacks(message=>function,
               presence=>function,
               iq=>function,
               send=>function,
               receive=>function,
               update=>function)

يقوم بتعيين وظائف الاستدعاء الثانوية (callbacks) للعلامات الرئيسية المذكورة. العلامات المتاحة هي <message/>، <presence/>، و <iq/>. إذا تم استلام حزمة بمعرف موجود في قائمة المعرفات المسجلة (انظر RegisterID أدناه)، فلن يتم إرسالها إلى هذه الوظائف، بل سيتم إدراجها في قائمة ويمكن استعادتها بواسطة بعض الوظائف التي سنذكرها لاحقًا.

يتم استخدام send و receive لتسجيل ما يتم إرساله وما يتم استقباله. يتم استخدام update كوسيلة لتحديث برنامجك أثناء انتظار حزمة بمعرف ليتم إرجاعها (مفيد لتطبيقات الواجهة الرسومية).

التغيير الكبير الذي جاء مع الإصدار الأخير هو أن معرف الجلسة يتم تمريره كوسيط أول لوظائف الاستدعاء الثانوية. تم القيام بذلك لتسهيل وحدة الخادم.

الوسيط التالي يعتمد على الاستدعاء الثانوي الذي تتحدث عنه. message و presence و iq تستقبل كائنات Net::XMPP التي تتوافق مع تلك الأنواع. send و receive تستقبل سلاسل نصية. update لا تستقبل شيئًا، ولا حتى معرف الجلسة.

إذا قمت بتعيين الوظيفة إلى undef، فسيتم إزالة الاستدعاء الثانوي من القائمة.

SetPresenceCallBacks
SetPresenceCallBacks(type=>function etc...)

يقوم بتعيين وظائف الاستدعاء الثانوية لنوع الحضور المحدد. تأخذ الدالة أنواعًا كالمفتاح الرئيسي، وتسمح لك بتحديد وظيفة لكل نوع حزمة يمكنك استقباله.

"available"
"unavailable"
"subscribe"
"unsubscribe"
"subscribed"
"unsubscribed"
"probe"
"error"

عندما يستقبل حزمة <presence/>، يتحقق مما إذا كان type="=" لديه استدعاء ثانوي محدد. إذا كان هناك واحد، فإنه يستدعيه بوسيطين:

معرف الجلسة، وكائن Net::XMPP::Presence.

إذا قمت بتعيين الوظيفة إلى undef، فسيتم إزالة الاستدعاء الثانوي من القائمة.

ملاحظة: إذا استخدمت هذه الطريقة الأكثر نظافة، فلا يجب عليك تحديد استدعاء ثانوي للحضور في وظيفة SetCallBacks.

Net::XMPP يحدد بعض الاستدعاءات الثانوية الافتراضية لأنواع مختلفة:
"subscribe" - يستجيب بـ "subscribed"
"unsubscribe" - يستجيب بـ "unsubscribed"
"subscribed" - يستجيب بـ "subscribed"
"unsubscribed" - يستجيب بـ "unsubscribed"

Process
    Process(integer)
takes the timeout period as an argument.  If no
timeout is listed then the function blocks until
a packet is received.  Otherwise it waits that
number of seconds and then exits so your program
can continue doing useful things.  NOTE: This is
important for GUIs.  You need to leave time to
process GUI commands even if you are waiting for
packets.  The following are the possible return
values, and what they mean:
    1   - Status ok, data received.
    0   - Status ok, no data received.
  undef - Status not ok, stop processing.

هام: يجب عليك التحقق من مخرج كل Process. إذا حصلت على undef، فهذا يعني أن الاتصال قد تم إغلاقه ويجب عليك التصرف وفقًا لذلك.

وظائف المعرف

SendWithID
SendWithID(object)
SendWithID(string)

تستقبل إما كائن Net::XMPP::xxxxx أو سلسلة نصية كوسيط، تضيف رقم المعرف المتاح، وترسل تلك الحزمة إلى الخادم. تعيد رقم المعرف المعين.

SendAndReceiveWithID
SendAndReceiveWithID(object, timeout)
SendAndReceiveWithID(string, timeout)

تستخدم SendWithID و WaitForID لتوفير وضع كامل لإرسال واستقبال الحزم ذات المعرفات. يمكن أن تستقبل إما كائن Net::XMPP::xxxxx أو سلسلة نصية. تعيد كائن Net::XMPP::xxxxx المناسب وفقًا لنوع الحزمة المستلمة. يتم تمرير المهلة الزمنية إلى WaitForID، انظر تلك الدالة لمعرفة كيفية عمل المهلة الزمنية.

ReceivedID
ReceivedID(integer)

تعيد 1 إذا تم استلام حزمة بالمعرف المحدد، وإلا تعيد 0.

GetID
GetID(integer)

تعيد كائن Net::XMPP::xxxxx المناسب وفقًا لنوع الحزمة المستلمة بالمعرف المحدد. إذا تم استلام المعرف، فإن GetID تعيد 0.

WaitForID
WaitForID(integer, timeout)

تتوقف حتى يتم استلام حزمة بالمعرف المحدد. تعيد كائن Net::XMPP::xxxxx المناسب وفقًا لنوع الحزمة المستلمة. إذا تم الوصول إلى حد المهلة الزمنية، ولم تصل الحزمة، فسيتم تجاهلها.

ملاحظة: <iq/> فقط تدعم المعرفات رسميًا، لذلك فإن إرسال <message/> أو <presence/> بمعرف هو مخاطرة. سيتجاهل الخادم علامة المعرف ويمررها، لذلك يجب أن يدعم كلا العميلين علامة المعرف لكي تكون هذه الوظائف مفيدة.

NAME

Net::XMPP::Protocol — API for parsing and managing XMPP roster information

SYNOPSIS

EXAMPLE USAGE

use Net::XMPP;
use Net::XMPP::Protocol qw(:roster);

my $xml = <<'EOF';
<iq type="result" id="roster-get-1" from="user@example.com/res" to="user2@example.com/res">
    <query xmlns="jabber:iq:roster">
        <item jid="buddy@example.com" name="Buddy" subscription="both" ask="subscribe">
            <group>Friends</group>
            <group>Colleagues</group>
        </item>
        <item jid="another@example.com" name="Another" subscription="none">
            <group>Work</group>
        </item>
    </query>
</iq>
EOF

my $roster_data = RosterParse($xml);
# $roster_data is a hash reference with JID as keys

my $jid_obj = Net::XMPP::JID->new("buddy@example.com");
my $roster_entry = RosterDBQuery($jid_obj, 'name');
# $roster_entry is "Buddy"

my @all_jids = RosterDBGetAllJIDs();
my @non_group_jids = RosterDBNonGroupJIDs();

DESCRIPTION

This module provides functions for parsing and managing XMPP roster information. It allows you to store and retrieve roster data in a convenient way.

METHODS

RosterParse(xml)
Parses the given XML string containing an XMPP roster query result. Returns a hash reference where keys are JIDs (as strings) and values are hashes containing roster information for each JID. The inner hash can contain the following keys:
name
The nickname of the contact.
ask
The subscription state (e.g., 'subscribe', 'unsubscribe').
subscription
The subscription type (e.g., 'none', 'from', 'to', 'both').
groups
An array reference of group names the contact belongs to.
RosterDBAdd(jid, data)
Adds or updates a roster entry for the given JID. The `jid` can be a string or a Net::XMPP::JID object. The `data` is a hash reference in the same format as returned by RosterParse.
RosterDBClear()
Clears all roster data from the database.
RosterDBGetAllJIDs()
Returns a list of Net::XMPP::JID objects representing all JIDs currently in the roster database.
RosterDBGetGroups(jid)
Returns an array reference of group names for the specified JID. The JID can be a string or a Net::XMPP::JID object.
RosterDBNonGroupJIDs
Returns a list of Net::XMPP::JID objects that represents all of the JIDs not in a roster group.
RosterDBQuery
RosterDBQuery(jid)

Returns a hash containing the data from the roster DB for the specified JID. The JID is either a string, or a Net::XMPP::JID object. The hash format the same as in RosterParse above.

RosterDBQuery
RosterDBQuery(jid,key)

Returns the entry from the above hash for the given key. The available keys are:
name, ask, subsrcription and groups The JID is either a string, or a Net::XMPP::JID object.
