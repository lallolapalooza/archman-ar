next(n)

الحزمة: tcl

التراخيص: TCL

next(n) أوامر TclOO next(n)

الاسم

next, nextto - استدعاء تنفيذات طرق الفئة الأعلى

الملخص

package require TclOO
next ?arg ...?
nextto class ?arg ...?

الوصف

يُستخدم الأمر next لاستدعاء تنفيذات طريقة لفئة، أو فئة أعلى، أو مزيج، والتي تم تجاوزها بواسطة الطريقة الحالية. لا يمكن استخدامه إلا من داخل طريقة. كما أنه يُستخدم داخل المرشحات للإشارة إلى النقطة التي تستدعي فيها المرشحة التنفيذ الفعلي (قد تقرر المرشحة عدم المتابعة في السلسلة، وقد تعالج نتائج المتابعة في سلسلة الطرق كما تختاره). نتيجة الأمر next هي نتيجة الطريقة التالية في سلسلة الطرق؛ إذا لم تكن هناك طرق أخرى في سلسلة الطرق، فستكون نتيجة next خطأ. الوسائط، arg، إلى next هي الوسائط التي سيتم تمريرها إلى الطريقة التالية في السلسلة.

الأمر nextto هو نفسه الأمر next، باستثناء أنه يأخذ وسيطة class إضافية تحدد فئة يجب استخدام تنفيذها لسلسلة الطرق الحالية (انظر info object call)؛ يجب أن يشير تنفيذ الطريقة المحدد إلى استدعاء غير مرشح موجود يقع لاحقًا في السلسلة مقارنة بالتنفيذ الحالي.

سلسلة الطرق

عند استدعاء طريقة لكائن، تحدث الأمور في عدة مراحل:

[1]
يتم فحص بنية الكائن، وفئته، وفئاته الأعلى، والمرشحات، والمزيجات، لبناء سلسلة طرق، والتي تحتوي على قائمة بتنفيذات الطرق التي سيتم استدعاؤها.
[2]
يتم استدعاء تنفيذ الطريقة الأول في السلسلة.
[3]
إذا استدعى تنفيذ الطريقة هذا الأمر next، فسيتم استدعاء تنفيذ الطريقة التالي (مع اعتبار وسائطه هي تلك التي تم تمريرها إلى next).
[4]
نتيجة استدعاء الطريقة الإجمالي هي نتيجة تنفيذ الطريقة الخارجي؛ تعيد تنفيذات الطرق الداخلية نتائجها من خلال next.
[5]
يتم تخزين سلسلة الطرق مؤقتًا للاستخدام المستقبلي.

ترتيب البحث عن الطرق

عند بناء سلسلة الطرق، يتم البحث عن تنفيذات الطرق بالترتيب التالي:

[1]
في الفئات الممزوجة بالكائن، بترتيب اجتياز الفئات. يتم فحص قائمة المزيجات بالترتيب الطبيعي.
[2]
في الفئات الممزوجة بفئات الكائن، مع البحث عن مصادر المزج بترتيب اجتياز الفئات. داخل كل فئة، تتم معالجة قائمة المزيجات بالترتيب الطبيعي.
[3]
في الكائن نفسه.
[4]
في فئة الكائن.
[5]
في الفئات الأعلى للفئة، باتباع كل فئة أعلى بطريقة البحث العميق أولاً بالترتيب الطبيعي لقائمة الفئات الأعلى.

يأتي أي تنفيذ طريقة معين دائمًا في وقت متأخر قدر الإمكان في القائمة الناتجة للتنفيذات؛ هذا يعني أنه إذا كانت فئة ما، A، ممزوجة بفئة، B، وهي أيضًا فئة أعلى لـ B، فإن مثيلات B ستعامل A دائمًا كفئة أعلى من منظور الوراثة. هذا صحيح حتى عند معالجة الوراثة المتعددة بشكل غير مباشر.

المرشحات

عندما يكون لدى الكائن قائمة بأسماء مرشحات معين عليها، أو هو مثيل لفئة (أو لديه فئة ممزوجة) تحتوي على قائمة بأسماء مرشحات معين عليها، قبل كل استدعاء لأي طريقة، تتم معالجة المرشحات. توجد تنفيذات المرشحات بترتيب اجتياز الفئات، كما هي قوائم أسماء المرشحات (يتم اجتياز كل منها بترتيب القائمة الطبيعي). سيؤدي الاستدعاء الصريح لطريقة مستخدمة كمرشحة إلى استدعاء تلك الطريقة مرتين، مرة كمرشحة ومرة كطريقة عادية.

يجب على كل مرشحة أن تقرر بنفسها ما إذا كانت ستسمح بالتنفيذ بالتقدم إلى التنفيذ المناسب للطريقة (وهو ما تفعله عن طريق استدعاء الأمر next حيث يتم إدراج المرشحات في مقدمة سلسلة استدعاء الطرق) وهي مسؤولة عن إرجاع نتيجة next.

يتم استدعاء المرشحات عند معالجة استدعاء للطريقة unknown بسبب فشل في تحديد تنفيذ طريقة، ولكن ليس عند استدعاء أي من المنشئات أو المدمرات. (لاحظ مع ذلك أن الطريقة destroy هي طريقة تقليدية، ويتم استدعاء المرشحات بشكل طبيعي عند استدعائها.)

أمثلة

يوضح هذا المثال كيفية استخدام الأمر next لاستدعاء تنفيذ الطريقة (للفئة الأعلى). البرنامج النصي:

oo::class create theSuperclass {
    method example {args} {
        puts "in the superclass, args = $args"
    }
}
oo::class create theSubclass {
    superclass theSuperclass
    method example {args} {
        puts "before chaining from subclass, args = $args"
        next a {*}$args b
        next pureSynthesis
        puts "after chaining from subclass"
    }
}
theSubclass create obj
oo::objdefine obj method example args {
    puts "per-object method, args = $args"
    next x {*}$args y
    next
}
obj example 1 2 3

يطبع ما يلي:

per-object method, args = 1 2 3
before chaining from subclass, args = x 1 2 3 y
in the superclass, args = a x 1 2 3 y b
in the superclass, args = pureSynthesis
after chaining from subclass
before chaining from subclass, args =
in the superclass, args = a b
in the superclass, args = pureSynthesis
after chaining from subclass

يوضح هذا المثال كيفية بناء فئة ذاكرة تخزين مؤقت بسيطة تطبق التذكير على جميع استدعاءات الطرق للكائنات التي تم مزجها فيها، ويظهر كيف يمكن أن تحدث فرقًا في أوقات الحساب:

oo::class create cache {
    filter Memoize
    method Memoize args {
        # Do not filter the core method implementations
        if {[lindex [self target] 0] eq "::oo::object"} {
            return [next {*}$args]
        }
        # Check if the value is already in the cache
        my variable ValueCache
        set key [self target],$args
        if {[info exist ValueCache($key)]} {
            return $ValueCache($key)
        }
        # Compute value, insert into cache, and return it
        return [set ValueCache($key) [next {*}$args]]
    }
    method flushCache {} {
        my variable ValueCache
        unset ValueCache
        # Skip the caching
        return -level 2 ""
    }
}
oo::object create demo
oo::objdefine demo {
    mixin cache
    method compute {a b c} {
        after 3000 ;# Simulate deep thought
        return [expr {$a + $b * $c}]
    }
    method compute2 {a b c} {
        after 3000 ;# Simulate deep thought
        return [expr {$a * $b + $c}]
    }
}
puts [demo compute  1 2 3]      → prints "7" after delay
puts [demo compute2 4 5 6]      → prints "26" after delay
puts [demo compute  1 2 3]      → prints "7" instantly
puts [demo compute2 4 5 6]      → prints "26" instantly
puts [demo compute  4 5 6]      → prints "34" after delay
puts [demo compute  4 5 6]      → prints "34" instantly
puts [demo compute  1 2 3]      → prints "7" instantly
demo flushCache
puts [demo compute  1 2 3]      → prints "7" after delay
