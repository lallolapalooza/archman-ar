stat(2) دليل استدعاءات النظام stat(2)

الاسم

stat, fstat, lstat, fstatat - الحصول على حالة الملف

المكتبة

مكتبة C القياسية (libc، -lc)

الملخص

#include <sys/stat.h>
int stat(const char *restrict path,
         struct stat *restrict statbuf);
int fstat(int fd, struct stat *statbuf);
int lstat(const char *restrict path,
         struct stat *restrict statbuf);
#include <fcntl.h>           /* تعريف ثوابت AT_* */
#include <sys/stat.h>
int fstatat(int dirfd, const char *restrict path,
         struct stat *restrict statbuf, int flags);

الوصف

تقوم هذه الدوال بإرجاع معلومات حول ملف، في المخزن المؤقت المشار إليه بواسطة statbuf. لا يلزم الحصول على أذونات على الملف نفسه، ولكن - في حالة stat() و fstatat() و lstat() - يلزم الحصول على إذن التنفيذ (البحث) على جميع الدلائل في path التي تؤدي إلى الملف.

stat() و fstatat() تسترجعان معلومات حول الملف المشار إليه بواسطة path؛ توصف الاختلافات لـ fstatat() أدناه.

lstat() مطابقة لـ stat()، باستثناء أنه إذا كان path رابطًا رمزيًا، فإنها ترجع معلومات حول الرابط نفسه، وليس الملف الذي يشير إليه الرابط.

fstat() مطابقة لـ stat()، باستثناء أن الملف الذي يتم استرجاع المعلومات حوله يتم تحديده بواسطة واصف الملف fd.

بنية stat

جميع استدعاءات النظام هذه ترجع بنية stat (انظر stat(3type)).

ملاحظة: لأسباب تتعلق بالأداء والبساطة، قد تحتوي حقول مختلفة في بنية stat على معلومات حالة من لحظات مختلفة أثناء تنفيذ استدعاء النظام. على سبيل المثال، إذا تم تغيير st_mode أو st_uid بواسطة عملية أخرى عن طريق استدعاء chmod(2) أو chown(2)، فقد ترجع stat() قيمة st_mode القديمة مع st_uid الجديدة، أو st_uid القديمة مع st_mode الجديدة.

fstatat()

استدعاء النظام fstatat() هو واجهة أكثر عمومية للوصول إلى معلومات الملف والتي لا تزال قادرة على توفير سلوك دقيق لكل من stat() و lstat() و fstat().

إذا كان path نسبيًا، فسيتم تفسيره بالنسبة للدليل المشار إليه بواسطة واصف الملف dirfd (بدلاً من كونه نسبيًا لمسار العمل الحالي للعملية المتصلة، كما هو الحال مع stat() و lstat() لمسار نسبي).

إذا كان path نسبيًا و dirfd هي القيمة الخاصة AT_FDCWD، فسيتم تفسير path بالنسبة لمسار العمل الحالي للعملية المتصلة (مثل stat() و lstat()).

إذا كان path مطلقًا، فسيتم تجاهل dirfd.

يمكن أن يكون flags إما 0، أو يتضمن واحدًا أو أكثر من الثوابت التالية ORed:

AT_EMPTY_PATH (منذ Linux 2.6.39)
إذا كان path سلسلة فارغة (أو NULL، منذ Linux 6.11) قم بتشغيل الملف المشار إليه بواسطة dirfd (الذي ربما تم الحصول عليه باستخدام open(2) O_PATH flag). في هذه الحالة، يمكن أن يشير dirfd إلى أي نوع من الملفات، وليس فقط دليل، وسلوك fstatat() مشابه لسلوك fstat(). إذا كان dirfd هو AT_FDCWD، فإن الاستدعاء يعمل على مسار العمل الحالي. هذا العلم خاص بنظام Linux؛ عرف _GNU_SOURCE للحصول على تعريفه.
AT_NO_AUTOMOUNT (منذ Linux 2.6.38)
لا تقم بتثبيت تلقائي للمكون النهائي ("اسم الأساس") من path. منذ Linux 3.1 تم تجاهل هذا العلم. منذ Linux 4.11 تم تضمين هذا العلم ضمنيًا.
AT_SYMLINK_NOFOLLOW
إذا كان path رابطًا رمزيًا، فلا تفك مرجعيته: بدلاً من ذلك، قم بإرجاع معلومات حول الرابط نفسه، مثل lstat(). (افتراضيًا، fstatat() تفك مراجع الروابط الرمزية، مثل stat().)

انظر openat(2) لشرح الحاجة إلى fstatat().

قيمة الإرجاع

عند النجاح، يتم إرجاع صفر. عند حدوث خطأ، يتم إرجاع -1، ويتم تعيين errno للإشارة إلى الخطأ.

الأخطاء

EACCES
يُرفض إذن البحث لأحد الدلائل في بادئة المسار لـ path. (انظر أيضًا path_resolution(7).)
EBADF
fd ليس واصف ملف مفتوح صالح.
EBADF
(fstatat()) path نسبي ولكن dirfd ليس AT_FDCWD ولا واصف ملف صالح.
EFAULT
عنوان سيء.
EINVAL
(fstatat()) تم تحديد علامة غير صالحة في flags.
ELOOP
تم العثور على عدد كبير جدًا من الروابط الرمزية أثناء اجتياز المسار.
ENAMETOOLONG
path طويل جدًا.
ENOENT
أحد مكونات path غير موجود أو هو رابط رمزي معلق.
ENOENT
path سلسلة فارغة ولم يتم تحديد AT_EMPTY_PATH في flags.
ENOMEM
نفاد الذاكرة (أي ذاكرة النواة).
ENOTDIR
أحد مكونات بادئة المسار لـ path ليس دليلًا.
ENOTDIR
(fstatat()) path نسبي و dirfd هو واصف ملف يشير إلى ملف غير الدليل.
EOVERFLOW
path أو fd يشير إلى ملف لا يمكن تمثيل حجمه أو رقمه الرمزي أو عدد كتلته في، على التوالي، الأنواع off_t أو ino_t أو blkcnt_t. يمكن أن يحدث هذا الخطأ عندما، على سبيل المثال، يقوم تطبيق تم تجميعه على نظام 32 بت بدون -D_FILE_OFFSET_BITS=64 باستدعاء stat() على ملف يتجاوز حجمه (1 << 31) -1 بايت.

فروقات مكتبة C / النواة

بمرور الوقت، أدى زيادة حجم هيكل stat إلى ثلاث إصدارات متتالية من stat(): sys_stat() (الفتحة __NR_oldstat)، sys_newstat() (الفتحة __NR_stat)، و sys_stat64() (الفتحة __NR_stat64) على منصات 32 بت مثل i386. كان أول إصدارين موجودين بالفعل في Linux 1.0 (وإن كانا باسمين مختلفين)؛ تم إضافة الأخير في Linux 2.4. تنطبق ملاحظات مماثلة على fstat() و lstat().

الإصدارات الداخلية للنواة لهيكل stat التي يتم التعامل معها بواسطة الإصدارات المختلفة هي، على التوالي:

__old_kernel_stat
الهيكل الأصلي، مع حقول ضيقة نوعًا ما، ولا يوجد حشو.
stat
حقل st_ino أكبر وحشو مضاف إلى أجزاء مختلفة من الهيكل للسماح بالتوسع المستقبلي.
stat64
حقل st_ino أكبر، وحقل st_uid و st_gid أكبر لاستيعاب توسيع Linux-2.4 لمعرفات المستخدمين (UIDs) ومعرفات المجموعات (GIDs) إلى 32 بت، وحقول أخرى متنوعة مكبرة ومزيد من الحشو في الهيكل. (تم استهلاك بايتات الحشو المختلفة في النهاية في Linux 2.6، مع ظهور معرفات الأجهزة 32 بت ومكونات النانو ثانية لحقول الطابع الزمني.)

تقوم دالة الغلاف glibc stat() بإخفاء هذه التفاصيل عن التطبيقات، واستدعاء أحدث إصدار من استدعاء النظام الذي توفره النواة، وإعادة حزم المعلومات المرجعة إذا لزم الأمر للثنائيات القديمة.

على الأنظمة الحديثة 64 بت، الحياة أبسط: يوجد استدعاء نظام stat() واحد وتتعامل النواة مع هيكل stat يحتوي على حقول بحجم كافٍ.

استدعاء النظام الأساسي الذي تستخدمه دالة الغلاف glibc fstatat() يسمى فعليًا fstatat64() أو، على بعض البنيات، newfstatat().

أمثلة

يستدعي البرنامج التالي lstat() ويعرض الحقول المحددة في هيكل stat المرجع.

#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/stat.h>
#include <sys/sysmacros.h>
#include <time.h>
int
main(int argc, char *argv[])
{
    struct stat sb;
    if (argc != 2) {
        fprintf(stderr, "Usage: %s <path>\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    if (lstat(argv[1], &sb) == -1) {
        perror("lstat");
        exit(EXIT_FAILURE);
    }
    printf("ID of containing device:  [%x,%x]\n",
           major(sb.st_dev),
           minor(sb.st_dev));
    printf("File type:                ");
    switch (sb.st_mode & S_IFMT) {
    case S_IFBLK:  printf("block device\n");            break;
    case S_IFCHR:  printf("character device\n");        break;
    case S_IFDIR:  printf("directory\n");               break;
    case S_IFIFO:  printf("FIFO/pipe\n");               break;
    case S_IFLNK:  printf("symlink\n");                 break;
    case S_IFREG:  printf("regular file\n");            break;
    case S_IFSOCK: printf("socket\n");                  break;
    default:       printf("unknown?\n");                break;
    }
    printf("I-node number:            %ju\n", (uintmax_t) sb.st_ino);
    printf("Mode:                     %jo (octal)\n",
           (uintmax_t) sb.st_mode);
    printf("Link count:               %ju\n", (uintmax_t) sb.st_nlink);
    printf("Ownership:                UID=%ju   GID=%ju\n",
           (uintmax_t) sb.st_uid, (uintmax_t) sb.st_gid);
    printf("Preferred I/O block size: %jd bytes\n",
           (intmax_t) sb.st_blksize);
    printf("File size:                %jd bytes\n",
           (intmax_t) sb.st_size);
    printf("Blocks allocated:         %jd\n",
           (intmax_t) sb.st_blocks);
    printf("Last status change:       %s", ctime(&sb.st_ctime));
    printf("Last file access:         %s", ctime(&sb.st_atime));
    printf("Last file modification:   %s", ctime(&sb.st_mtime));
    exit(EXIT_SUCCESS);
}
