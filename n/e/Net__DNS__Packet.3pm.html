NAME

Net::DNS::Packet - DNS packet manipulation

SYNOPSIS

$packet = Net::DNS::Packet->new($version);
$packet = Net::DNS::Packet->new($version, $header);
$packet = Net::DNS::Packet->new($version, $header, $question);
$packet = Net::DNS::Packet->new($version, $header, $question, $answer);
$packet = Net::DNS::Packet->new($version, $header, $question, $answer, $authority);
$packet = Net::DNS::Packet->new($version, $header, $question, $answer, $authority, $additional);

$packet->header($header);
$packet->question($question);
$packet->answer($answer);
$packet->authority($authority);
$packet->additional($additional);

$header    = $packet->header;
$question  = $packet->question;
$answer    = $packet->answer;
$authority = $packet->authority;
$additional= $packet->additional;

DESCRIPTION

The Net::DNS::Packet class is used to represent a DNS packet. It is a container for a Net::DNS::Header object, a Net::DNS::Question object, and zero or more Net::DNS::RR (Resource Record) objects in the answer, authority, and additional sections.

The constructor can be called with a version argument which is either "5" or "1" to indicate whether the packet is for an IN class or not. The default is "5". If the version argument is omitted, the default is used.

The constructor can also be called with optional arguments for the header, question, answer, authority and additional sections. If these are omitted, Net::DNS::Packet->new() creates empty versions of them.

The header, question, answer, authority, and additional methods can be used to retrieve or replace the respective sections of the packet.

METHODS

new

my $packet = Net::DNS::Packet->new('5');
my $packet = Net::DNS::Packet->new($version, $header);
my $packet = Net::DNS::Packet->new($version, $header, $question);
my $packet = Net::DNS::Packet->new($version, $header, $question, $answer);
my $packet = Net::DNS::Packet->new($version, $header, $question, $answer, $authority);
my $packet = Net::DNS::Packet->new($version, $header, $question, $answer, $authority, $additional);

The constructor creates a new packet object. The first argument is the version, which can be "5" (default) or "1". The subsequent arguments can be header, question, answer, authority and additional objects. If omitted, the objects are created automatically.

header

$packet->header($header);
$header = $packet->header;

The header method returns the header object associated with the packet. It can also be used to replace the header object.

question

$packet->question($question);
$question = $packet->question;

The question method returns the question object associated with the packet. It can also be used to replace the question object.

answer

$packet->answer($answer);
$answer = $packet->answer;

The answer method returns the answer section associated with the packet. This is an array reference of Net::DNS::RR objects. It can also be used to replace the answer section.

authority

$packet->authority($authority);
$authority = $packet->authority;

The authority method returns the authority section associated with the packet. This is an array reference of Net::DNS::RR objects. It can also be used to replace the authority section.

additional

$packet->additional($additional);
$additional = $packet->additional;

The additional method returns the additional section associated with the packet. This is an array reference of Net::DNS::RR objects. It can also be used to replace the additional section.

push

$packet->push( answer => $rr );
$packet->push( authority => $rr );
$packet->push( additional => $rr );

The push method adds a resource record to the specified section of the packet.

sign_tsig

$response = $request->reply;
$response->sign_tsig( $request, @options );

The sign_tsig() method is used to sign a DNS packet using the TSIG (Transaction Signature) mechanism. It takes the original request packet and any options as arguments.

Multi-packet transactions are signed by chaining the sign_tsig() calls together as follows:

$opaque = $packet1->sign_tsig( 'Kexample.+165+13281.private' );
$opaque = $packet2->sign_tsig( $opaque );
$opaque = $packet3->sign_tsig( $opaque );

The opaque intermediate object references returned during multi-packet signing are not intended to be accessed by the end-user application. Any such access is expressly forbidden.

Note that a TSIG record is added to every packet; this implementation does not support the suppressed signature scheme described in RFC2845.

verify and verifyerr

$reply->verify($query) || die $reply->verifyerr;

Verify TSIG signature of a reply to the corresponding query.

$opaque  = $packet1->verify( $query ) || die $packet1->verifyerr;
$opaque  = $packet2->verify( $opaque );
$verifed = $packet3->verify( $opaque ) || die $packet3->verifyerr;

Verify TSIG signature of a multi-packet reply to the corresponding query.

The opaque intermediate object references returned by verify() at each stage will be undefined (Boolean false) if verification fails. Testing at every stage is not necessary, which produces a BADSIG error on the final packet in the absence of more specific information. Access to the objects themselves, if they exist, is expressly forbidden.

sign_sig0

SIG0 support is provided through the Net::DNS::RR::SIG class. The requisite cryptographic components are not integrated into Net::DNS but reside in the Net::DNS::SEC distribution available from CPAN.

$update = Net::DNS::Update->new('example.com');
$update->push( update => rr_add('foo.example.com A 10.1.2.3'));
$update->sign_sig0('Kexample.com+003+25317.private');

Execution will be terminated if Net::DNS::SEC is not available.

verify SIG0

$packet->verify( $keyrr )               || die $packet->verifyerr;
$packet->verify( [$keyrr, ...] )        || die $packet->verifyerr;

Verify SIG0 packet signature against one or more specified KEY RRs.

sigrr

$sigrr = $packet->sigrr() || die 'unsigned packet';

The sigrr method returns the signature RR from a signed packet or undefined if the signature is absent.

truncate

The truncate method takes a maximum length as argument and then tries to truncate the packet and set the TC bit according to the rules of RFC2181 Section 9.

The smallest length limit that is honoured is 512 octets.
