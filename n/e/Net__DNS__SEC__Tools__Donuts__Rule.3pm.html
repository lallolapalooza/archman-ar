الحزمة: dnssec-tools

التراخيص: BSD

NAME

donuts-rule, donuts-policy - Manual pages for donuts rules and policies

DESCRIPTION

This document describes the format for rules and policies that are used by the donuts(8) utility.

Rules are written in Perl and are evaluated against DNS data. They are primarily used to enforce policy or to perform checks on DNS data.

The following sections detail the format of the rule file.

RULE FILE FORMAT

A rule file is a text file consisting of a series of tags, each followed by its value. The tags are case-sensitive. Tags may span multiple lines if they are enclosed in parentheses or curly braces. Comments begin with a '#' and continue to the end of the line.

The following tags are recognized:

name: RULE_NAME
A short, descriptive name for the rule. This name is used when reporting errors or when enabling/disabling rules.
level: NUMBER
A numeric severity level for the rule. Higher numbers indicate higher severity. Common values range from 1 to 10.
type: TYPE
The type of data the rule applies to. Recognized types include:
  • record: The rule applies to individual DNS records.
  • name: The rule applies to a DNS name and all its associated records.
  • zone: The rule applies to an entire DNS zone.
condition: EXPRESSION
A Perl expression that must evaluate to true for the rule's test code to be executed. If omitted, the test code is always executed.
test: PERL_CODE
The Perl code that performs the actual test. This code is executed only if the rule's type matches the data being processed and the condition (if any) is met. The code is expected to return a string if the test fails (indicating an error), and an empty string or false value if the test passes.

Inside the test code, the following variables are available:

$rule
A hash reference containing information about the rule itself, including any configuration tokens defined using the help: tag.
$record
A hash reference containing information about the current DNS record being processed. Available when type: is record.
$name
The DNS name being processed. Available when type: is name or zone.
$records
A hash reference where keys are record types (e.g., 'A', 'MX') and values are arrays of record objects. Available when type: is name or zone.
$recordname
The name of the record being processed. Available when type: is name.

The $rule, $recordname, and $records variables are automatically populated for the test code to use.

Example rules:

# local rule to mandate that each record must have a
# TTL > 60 seconds
name: DNS_TTL_AT_LEAST_60
level: 8
type: record
<test>
  return "TTL for $record->{name} is too small" if ($record->ttl < 60);
</test>
# local policy rule to mandate that anything with an A record
# must have an HINFO record too
name: DNS_MX_MUST_HAVE_A
level: 8
type: name
<test>
  return "$recordname has an A record but does not have an HINFO record"
    if (exists($records->{'A'}) && !exists($records->{'HINFO'}));
</test>
feature: NAME
The feature tag prevents this rule from running unless the NAME keyword was specified using the --features flag.
desc: DESCRIPTION
A short description of what the rule tests that will be printed to the user in help output or in the error summary when donuts outputs the results.
requires: PERLMODULE1 PERLMODULE2 ...
This allows rules to depend on installed perl modules. They'll be required and imported as the rule starts executing. If they don't exist, an error will be logged using donuts_error() stating that the module is required for that rule to work.
help: TOKEN: TOKEN-HELP
If the rule is configurable via the user's .donuts.conf file, this describes the configuration tokens for the user when they request configuration help via the -H or --help-config flags. Tokens may be used within rules by accessing them using the $rule reference passed to the code (the second argument).

Examples:

1) In the rule file (this is an incomplete rule definition):
   name:           SOME_TEST
   myconfig:       40
   help: myconfig: A special number to configure this test
   <test>
    # ... use $rule->{'myconfig'}
   </test>
2) This allows the user to change the value of myconfig via their
   .donuts.conf file:
   # change SOME_TEST config...
   name:     SOME_TEST
   myconfig: 40
3) and running donuts -H will show the help line for myconfig.
noindent 1
nowrap 1
Normally donuts will line-wrap the error summary produced by a rule to enable automatic pretty-printing of error results. Sometimes, however, rules may wish to self-format their outputs. The nowrap option indicates to donuts that the output is pre-formatted but should still be indented to align with the output of the rest of the error text (currently about 15 spaces.) The noindent tag, however, indicates that neither wrapping nor indenting should be performed, but that the error should be printed as is.
