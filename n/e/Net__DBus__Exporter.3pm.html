NAME

Net::DBus::Exporter - DBus exporter functions

SYNOPSIS

        use Net::DBus::Exporter qw(
                dbus_method
                dbus_signal
                dbus_property
                dbus_no_strict_exports
        );
        
        dbus_method($name, $params, $returns, [\%attributes]);
        dbus_method($name, $params, $returns, $interface, [\%attributes]);
        
        dbus_signal($name, $params, [\%attributes]);
        dbus_signal($name, $params, $interface, [\%attributes]);
        
        dbus_property($name, $type, $access, [\%attributes]);
        dbus_property($name, $type, $access, $interface, [\%attributes]);
        
        dbus_no_strict_exports();

DESCRIPTION

This module provides functions for exporting methods, signals, and properties to DBus.

In order to export a method, signal or property, the object's class must inherit from Net::DBus::Object.

The functions dbus_method, dbus_signal, and dbus_property should be called within the class's new method, or within a BEGIN block, to ensure that the metadata is available when the object is first created.

SCALAR TYPES

Valid scalar types are:

string
String (UTF-8 encoded)
boolean
Boolean (0 or 1)
int8
8-bit signed integer
int16
16-bit signed integer
int32
32-bit signed integer
int64
64-bit signed integer
uint8
8-bit unsigned integer
uint16
16-bit unsigned integer
uint32
32-bit unsigned integer
uint64
64-bit unsigned integer
double
Double precision floating point
float
Single precision floating point
object
Object path
signature
Type signature
array
Fixed-length array. This is a magic type, see COMPOUND TYPES.
variant
Variant
dict
Dictionary. This is a magic type, see COMPOUND TYPES.
struct
Struct. This is a magic type, see COMPOUND TYPES.

COMPOUND TYPES

Compound types are used to specify the types of parameters or return values. They are represented as array references, where the first element is the compound type name, and subsequent elements define the types of the members.

array
An array of elements of a specific type. For example, an array of strings is represented as ["array", "string"].
dict
A dictionary with keys of one type and values of another. For example, a dictionary with string keys and int32 values is represented as ["dict", "string", "int32"].
struct
A struct is a fixed-size collection of fields of potentially different types. For example, a struct containing a string and an int32 is represented as ["struct", "string", "int32"].

MAGIC TYPES

The following types can be used with dbus_method to indicate that a method can accept or return a variable number of values.

array
If used as the sole element in the $params or $returns array, it indicates that the method can accept or return any number of arguments of any type.

ANNOTATIONS

The optional \%attributes argument can be used to provide annotations for the exported member. The following annotations are supported:

deprecated
If true, the method, signal, or property is deprecated.
no_return
If true, the method is considered to have no return value, even if one is specified in $returns. This is useful for methods that perform an action and don't need to return status information.
param_names
An array reference of strings, specifying the names of the parameters to the method or signal. This is useful for documentation and introspection.
property_access
For properties, this can be set to readwrite, read, or write to specify the access level. If not provided, the default is readwrite.

METHODS

dbus_method($name, $params, $returns, [\%attributes]);
dbus_method($name, $params, $returns, $interface, [\%attributes]);
Exports a method called $name, accepting parameters defined by $params, and returning values whose types are defined by $returns. If the $interface parameter is provided, then the method is associated with that interface, otherwise the default interface for the calling package is used. The value for the $params parameter should be an array reference with each element defining the data type of a parameter to the method. Likewise, the $returns parameter should be an array reference with each element defining the data type of a return value. If it not possible to export a method which accepts a variable number of parameters, or returns a variable number of values.
dbus_no_strict_exports();
If a object is using the Exporter to generate DBus introspection data, the default behaviour is to only allow invocation of methods which have been explicitly exported.

To allow clients to access methods which have not been explicitly exported, call "dbus_no_strict_exports". NB, doing this may be a security risk if you have methods considered to be "private" for internal use only. As such this method should not normally be used. It is here only to allow switching export behaviour to match earlier releases.

dbus_property($name, $type, $access, [\%attributes]);
dbus_property($name, $type, $access, $interface, [\%attributes]);
Exports a property called $name, whose data type is $type. If the $interface parameter is provided, then the property is associated with that interface, otherwise the default interface for the calling package is used.
dbus_signal($name, $params, [\%attributes]);
dbus_signal($name, $params, $interface, [\%attributes]);
Exports a signal called $name, having parameters whose types are defined by $params. If the $interface parameter is provided, then the signal is associated with that interface, otherwise the default interface for the calling package is used. The value for the $params parameter should be an array reference with each element defining the data type of a parameter to the signal. Signals do not have return values. It not possible to export a signal which has a variable number of parameters.

EXAMPLES

No parameters, no return values
A method which simply prints "Hello World" each time its called 
sub Hello {
    my $self = shift;
    print "Hello World\n";
}
dbus_method("Hello", [], []);
One string parameter, returning an boolean value
A method which accepts a process name, issues the killall command on it, and returns a boolean value to indicate whether it was successful. 
sub KillAll {
    my $self = shift;
    my $processname = shift;
    my $ret  = system("killall $processname");
    return $ret == 0 ? 1 : 0;
}
dbus_method("KillAll", ["string"], ["bool"]);
One list of strings parameter, returning a dictionary
A method which accepts a list of files names, stats them, and returns a dictionary containing the last modification times. 
sub LastModified {
   my $self = shift;
   my $files = shift;
   my %mods;
   foreach my $file (@{$files}) {
      $mods{$file} = (stat $file)[9];
   }
   return \%mods;
}
dbus_method("LastModified", ["array", "string"], ["dict", "string", "int32"]);
Annotating methods with metdata
A method which is targeted for removal, and also does not return any value 
sub PlayMP3 {
    my $self = shift;
    my $track = shift;
    system "mpg123 $track &";
}
dbus_method("PlayMP3", ["string"], [], { deprecated => 1, no_return => 1 });

Or giving names to input parameters:

sub PlayMP3 {
    my $self = shift;
    my $track = shift;
    system "mpg123 $track &";
}
dbus_method("PlayMP3", ["string"], [], { param_names => ["track"] });
