NEXT(3perl) دليل مرجع مبرمجي Perl NEXT(3perl)

الاسم

NEXT - توفير صنف زائف NEXT (وما شابه) يسمح بإعادة إرسال الطرق

الملخص

use NEXT;
package P;
sub P::method   { print "$_[0]: P method\n";   $_[0]->NEXT::method() }
sub P::DESTROY  { print "$_[0]: P dtor\n";     $_[0]->NEXT::DESTROY() }
package Q;
use base qw( P );
sub Q::AUTOLOAD { print "$_[0]: Q AUTOLOAD\n"; $_[0]->NEXT::AUTOLOAD() }
sub Q::DESTROY  { print "$_[0]: Q dtor\n";     $_[0]->NEXT::DESTROY() }
package R;
sub R::method   { print "$_[0]: R method\n";   $_[0]->NEXT::method() }
sub R::AUTOLOAD { print "$_[0]: R AUTOLOAD\n"; $_[0]->NEXT::AUTOLOAD() }
sub R::DESTROY  { print "$_[0]: R dtor\n";     $_[0]->NEXT::DESTROY() }
package S;
use base qw( Q R );
sub S::method   { print "$_[0]: S method\n";   $_[0]->NEXT::method() }
sub S::AUTOLOAD { print "$_[0]: S AUTOLOAD\n"; $_[0]->NEXT::AUTOLOAD() }
sub S::DESTROY  { print "$_[0]: S dtor\n";     $_[0]->NEXT::DESTROY() }
package main;
my $obj = bless {}, "S";
$obj->method();             # Calls S::method, P::method, R::method
$obj->missing_method(); # Calls S::AUTOLOAD, Q::AUTOLOAD, R::AUTOLOAD
# Clean-up calls S::DESTROY, Q::DESTROY, P::DESTROY, R::DESTROY

الوصف

تضيف وحدة "NEXT" صنفًا زائفًا باسم "NEXT" إلى أي برنامج يستخدمها. إذا استدعت طريقة "m" التعبير "$self->NEXT::m()"، فإن الاستدعاء إلى "m" يُعاد إرساله كما لو أن الطريقة المستدعية لم تكن موجودة في الأصل.

ملاحظة: قبل استخدام هذه الوحدة، ينبغي عليك الاطلاع على next::method https://metacpan.org/pod/mro#next::method في وحدة mro الأساسية. لقد كانت "mro" وحدة أساسية منذ Perl 5.9.5.

بعبارة أخرى، فإن استدعاء "$self->NEXT::m()" يستأنف البحث بالعمق أولًا ومن اليسار إلى اليمين في التسلسل الهرمي لصنف $self الذي أدى إلى الاستدعاء الأصلي لـ "m".

لاحظ أن هذا ليس الشيء نفسه الذي يفعله "$self->SUPER::m()"، الذي يبدأ إرسالًا جديدًا يقتصر على البحث في أسلاف الصنف الحالي. يمكن لـ "$self->NEXT::m()" أن يتراجع متجاوزًا الصنف الحالي -- للبحث عن طريقة مناسبة في أسلاف أخرى لـ $self -- بينما لا يمكن لـ "$self->SUPER::m()" فعل ذلك.

من الاستخدامات النموذجية لذلك في الدوال الهدامة (destructors) لتسلسل هرمي من الأصناف، كما هو موضح في الملخص أعلاه. لكل صنف في التسلسل الهرمي طريقة DESTROY تؤدي إجراءً خاصًا بالصنف ثم تعيد إرسال الاستدعاء صعودًا في التسلسل الهرمي. ونتيجة لذلك، عندما يتم تدمير كائن من الصنف S، تُستدعى الدوال الهدامة لـ جميع أصنافه الآباء (بترتيب العمق أولًا ومن اليسار إلى اليمين).

من الاستخدامات النموذجية الأخرى لإعادة الإرسال في الطرق التي تُستدعى عبر "AUTOLOAD". إذا قررت إحدى هذه الطرق أنها غير قادرة على معالجة استدعاء معين، فقد تختار إعادة إرسال ذلك الاستدعاء، على أمل أن يقوم "AUTOLOAD" آخر (فوقها أو على يسارها) بعمل أفضل.

بشكل افتراضي، إذا فشلت محاولة إعادة الإرسال في العثور على طريقة أخرى في مكان آخر من التسلسل الهرمي لأصناف الكائن، فإنها تستسلم بهدوء ولا تفعل شيئًا (لكن انظر "فرض إعادة الإرسال"). هذا القبول اللطيف يختلف أيضًا عن السلوك (المزعج عمومًا) لـ "SUPER"، الذي يطرح استثناءً إذا لم يتمكن من إعادة الإرسال.

لاحظ أن محاولة أي طريقة (بما في ذلك "AUTOLOAD") إعادة إرسال أي طريقة لا تحمل الاسم نفسه تُعد خطأً فادحًا. على سبيل المثال:

sub S::oops { print "oops!\n"; $_[0]->NEXT::other_method() }

فرض إعادة الإرسال

من الممكن جعل "NEXT" يعيد الإرسال بشكل أكثر إلحاحًا (أي كما يفعل "SUPER")، بحيث تطرح إعادة الإرسال استثناءً إذا لم تتمكن من العثور على طريقة "تالية" لاستدعائها.

للقيام بذلك، ما عليك سوى استدعاء إعادة الإرسال على النحو التالي:

$self->NEXT::ACTUAL::method();

بدلًا من:

$self->NEXT::method();

تخبر "ACTUAL" وحدة "NEXT" بأنه يجب أن تكون هناك بالفعل طريقة تالية لاستدعائها، وإلا فيجب أن تطرح استثناءً.

يُستخدم "NEXT::ACTUAL" غالبًا في طرق "AUTOLOAD"، كوسيلة لرفض طلب "AUTOLOAD" مع الحفاظ على دلالات الاستثناء عند الفشل المعتادة:

sub AUTOLOAD {
        if ($AUTOLOAD =~ /foo|bar/) {
                # handle here
        }
        else {  # try elsewhere
                shift()->NEXT::ACTUAL::AUTOLOAD(@_);
        }
}

باستخدام "NEXT::ACTUAL"، إذا لم تكن هناك طريقة "AUTOLOAD" أخرى لمعالجة استدعاء الطريقة، فسيتم طرح استثناء (كما يحدث عادةً في غياب "AUTOLOAD" مناسبة).

تجنب التكرارات

إذا تم استخدام إعادة الإرسال عبر "NEXT" في طرق تسلسل هرمي من الأصناف على شكل "معيّن":

#     A   B
#    / \ /
#   C   D
#    \ /
#     E
use NEXT;
package A;                 
sub foo { print "called A::foo\n"; shift->NEXT::foo() }
package B;                 
sub foo { print "called B::foo\n"; shift->NEXT::foo() }
package C; @ISA = qw( A );
sub foo { print "called C::foo\n"; shift->NEXT::foo() }
package D; @ISA = qw(A B);
sub foo { print "called D::foo\n"; shift->NEXT::foo() }
package E; @ISA = qw(C D);
sub foo { print "called E::foo\n"; shift->NEXT::foo() }
E->foo();

فإن الأصناف المشتقة قد ترث (أو تعيد وراثة) طرق الصنف الأساسي عبر مسارين أو أكثر متميزين (مثل الطريقة التي يرث بها "E" الطريقة "A::foo" مرتين -- عبر "C" و"D"). في مثل هذه الحالات، ستستدعي سلسلة من عمليات إعادة الإرسال عبر "NEXT" الطريقة الموروثة المتعددة بقدر عدد مرات وراثتها. على سبيل المثال، يطبع الكود أعلاه:

called E::foo
called C::foo
called A::foo
called D::foo
called A::foo
called B::foo

(أي أن "A::foo" تُستدعى مرتين).

في بعض الحالات قد يكون هذا هو التأثير المطلوب داخل تسلسل هرمي على شكل معيّن، لكن في حالات أخرى (مثل الدوال الهدامة) قد يكون من الأنسب استدعاء كل طريقة مرة واحدة فقط خلال سلسلة من عمليات إعادة الإرسال.

لتغطية مثل هذه الحالات، يمكنك إعادة إرسال الطرق عبر:

$self->NEXT::DISTINCT::method();

بدلًا من:

$self->NEXT::method();

يتسبب هذا في أن يزور معيد الإرسال كل طريقة "method" متميزة مرة واحدة فقط. أي أنه يتخطى أي أصناف في التسلسل الهرمي زارها بالفعل أثناء إعادة الإرسال. لذا، على سبيل المثال، إذا أُعيد كتابة المثال السابق:

package A;                 
sub foo { print "called A::foo\n"; shift->NEXT::DISTINCT::foo() }
package B;                 
sub foo { print "called B::foo\n"; shift->NEXT::DISTINCT::foo() }
package C; @ISA = qw( A );
sub foo { print "called C::foo\n"; shift->NEXT::DISTINCT::foo() }
package D; @ISA = qw(A B);
sub foo { print "called D::foo\n"; shift->NEXT::DISTINCT::foo() }
package E; @ISA = qw(C D);
sub foo { print "called E::foo\n"; shift->NEXT::DISTINCT::foo() }
E->foo();

فإنه سيطبع:

called E::foo
called C::foo
called A::foo
called D::foo
called B::foo

ويحذف الاستدعاء الثاني لـ "A::foo" (لأنه لن يكون متميزًا عن الاستدعاء الأول لـ "A::foo").

لاحظ أنه يمكنك أيضًا استخدام:

$self->NEXT::DISTINCT::ACTUAL::method();

أو:

$self->NEXT::ACTUAL::DISTINCT::method();

للحصول على كل من الاستدعاء الفريد و الاستثناء عند الفشل.

لاحظ أنه، للتوافق التاريخي، يمكنك أيضًا استخدام "NEXT::UNSEEN" بدلًا من "NEXT::DIST

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

استدعاء جميع إصدارات دالةٍ ما باستدعاءٍ واحد

هناك صنف زائف آخر يوفّره "NEXT" وهو "EVERY". سلوكه أبسط بكثير من سلوك عائلة "NEXT". فالاستدعاء:

$obj->EVERY::foo();

يستدعي كل دالةٍ باسم "foo" يرثها الكائن الموجود في $obj. أي:

use NEXT;
package A; @ISA = qw(B D X);
sub foo { print "A::foo " }
package B; @ISA = qw(D X);
sub foo { print "B::foo " }
package X; @ISA = qw(D);
sub foo { print "X::foo " }
package D;
sub foo { print "D::foo " }
package main;
my $obj = bless {}, 'A';
$obj->EVERY::foo();        # prints" A::foo B::foo X::foo D::foo

إن إضافة البادئة "EVERY::" إلى استدعاء دالةٍ ما تجعل كل دالةٍ في تسلسل الكائن الهرمي تحمل ذلك الاسم تُستدعى. وكما يوضّح المثال أعلاه، فإنها لا تُستدعى بترتيب Perl المعتاد "الأيسر-الأعمق-أولًا". بل تُستدعى "بالعرض-أولًا-حسب الاعتماد".

وهذا يعني أن شجرة وراثة الكائن تُجتاز بالعرض أولًا، ويُستخدم الترتيب الناتج للأصناف كتسلسلٍ تُستدعى به الدوال. غير أن ذلك التسلسل يُعدَّل بفرض قاعدةٍ تقضي بأن تُستدعى الدالة المناسبة للصنف المشتق قبل الدالة نفسها لأي صنفٍ سلف. ولهذا السبب، في المثال أعلاه، تُستدعى "X::foo" قبل "D::foo"، رغم أن "D" تأتي قبل "X" في @B::ISA.

بشكلٍ عام، لا حاجة للقلق بشأن ترتيب الاستدعاءات. فستكون من اليسار إلى اليمين، بالعرض أولًا، والأكثر اشتقاقًا أولًا. وهذا يعمل على نحوٍ مثالي مع معظم الدوال الموروثة (بما فيها الدوال المدمِّرة)، لكنه غير مناسب لبعض أنواع الدوال (مثل الدوال البانية، والناسخة، والمنقّحة، والمهيّئة) حيث يكون من الأنسب أن تُستدعى الدوال الأقل اشتقاقًا أولًا (لأن الدوال الأكثر اشتقاقًا قد تعتمد على سلوك "أسلافها"). في تلك الحالة، بدلًا من استخدام الصنف الزائف "EVERY":

$obj->EVERY::foo();        # prints" A::foo B::foo X::foo D::foo

يمكنك استخدام الصنف الزائف "EVERY::LAST":

$obj->EVERY::LAST::foo();  # prints" D::foo X::foo B::foo A::foo

والذي يعكس ترتيب استدعاء الدوال.

أيًّا كان الإصدار المستخدم، فإن الدوال الفعلية تُستدعى في السياق نفسه (قائمة، أو عددي، أو فراغي) الذي جرى فيه الاستدعاء الأصلي عبر "EVERY"، وتُعيد:

  • تجزئةً من مراجع المصفوفات في سياق القائمة. كل مدخلٍ في التجزئة مفتاحه اسم الدالة المؤهَّل بالكامل، وقيمته مرجعٌ إلى مصفوفةٍ تحتوي على قيم الإرجاع للدالة في سياق القائمة.
  • مرجعًا إلى تجزئةٍ من القيم العددية في السياق العددي. كل مدخلٍ في التجزئة مفتاحه اسم الدالة المؤهَّل بالكامل، وقيمته قيم الإرجاع للدالة في السياق العددي.
  • لا شيء في السياق الفراغي (بداهةً).

استخدام دوال "EVERY"

الطريقة النموذجية لاستخدام استدعاء "EVERY" هي تغليفه في دالة أساسٍ أخرى ترثها جميع الأصناف. فمثلًا، لضمان أن كل دالة مدمِّرة يرثها الكائن تُستدعى فعلًا (بدلًا من استدعاء الأيسر-الأعمق-أولًا فقط):

package Base;
sub DESTROY { $_[0]->EVERY::Destroy }
package Derived1; 
use base 'Base';
sub Destroy {...}
package Derived2; 
use base 'Base', 'Derived1';
sub Destroy {...}

وهكذا دواليك. كل صنفٍ مشتق يحتاج إلى سلوك تنظيفٍ خاص به يضيف ببساطة دالته الخاصة "Destroy" (وليست دالة "DESTROY")، والتي يلتقطها الاستدعاء إلى "EVERY::LAST::Destroy" في الدالة المدمِّرة الموروثة على نحوٍ صحيح.

وبالمثل، لإنشاء تسلسلٍ هرميٍّ للأصناف تُستدعى فيه كل دالة تهيئةٍ يرثها كائنٌ جديد:

package Base;
sub new {
        my ($class, %args) = @_;
        my $obj = bless {}, $class;
        $obj->EVERY::LAST::Init(\%args);
}
package Derived1; 
use base 'Base';
sub Init {
        my ($argsref) = @_;
        ...
}
package Derived2; 
use base 'Base', 'Derived1';
sub Init {
        my ($argsref) = @_;
        ...
}

وهكذا دواليك. كل صنفٍ مشتق يحتاج إلى بعض سلوك التهيئة الإضافي يضيف ببساطة دالته الخاصة "Init" (وليست دالة "new")، والتي يلتقطها الاستدعاء إلى "EVERY::LAST::Init" في الدالة البانية الموروثة على نحوٍ صحيح.
