NAME

Net::Server::Multiplex - Base class for multiplexing servers

SYNOPSIS

    package MyServer;
    use base qw(Net::Server::Multiplex);
    # ... your server methods ...
    MyServer->run();

DESCRIPTION

This is the base class for servers that wish to handle multiple clients concurrently using a multiplexing I/O library such as IO::Multiplex(3pm). It provides the basic framework for accepting connections and dispatching them to client handler methods.

This class is designed to be subclassed. The subclass is responsible for defining how clients are handled.

PROCESS FLOW

The main loop is handled by the run method. It consists of the following steps:

  1. Call the prefork hook.
  2. Call the accept_connections method to start accepting client connections.
  3. Call the run_server method which is the main loop.
  4. Call the postfork hook (if applicable, i.e. if fork_server is true).
  5. Call the shutdown hook.

accept_connections sets up the listening socket and adds it to the multiplexer.

run_server is the main event loop. It waits for events from the multiplexer. When a connection is ready for reading, it calls handle_connection. When a client times out, it calls handle_timeout.

CLIENT PROCESSING

When a client connection is ready for reading, the run_server method calls the handle_connection method. This method is expected to read data from the client, process it, and send a response. By default, handle_connection calls the process_client method.

The process_client method is where the actual client handling logic should reside. It receives the client socket as an argument. The default implementation does nothing.

Subclasses should override process_client to implement their specific server logic.

HOOKS

The following methods are provided as hooks that can be overridden by subclasses:

prefork
Called before the server starts accepting connections. This is a good place to initialize resources that will be needed by all server processes.
postfork
Called in the child process after forking. This is a good place to initialize resources that are specific to each server process, such as reopening log files.
accept_connections
Sets up the listening socket and adds it to the multiplexer.
run_server
The main server loop that waits for and dispatches events.
handle_connection
Called when a client connection is ready for reading.
handle_timeout
Called when a client connection times out.
shutdown
Called when the server is shutting down.

TIMEOUTS

The Net::Server::Multiplex class uses IO::Multiplex for handling timeouts. You can set client-specific timeouts using the set_timeout method and a global timeout for the multiplexer using the mux_timeout method.

The handle_timeout method is called when a client connection exceeds its timeout. The default implementation removes the client from the multiplexer.

CALLBACK INTERFACE

This class provides a compatibility interface for the run_dequeue method found in Net::Server::Fork(3pm). This method is intended to be called by a parent process to handle client connections in a child process. It uses the set_timeout and mux_timeout methods internally.

Note that the check_for_dequeue option is not supported by this interface.
