الحزمة: netcdf-openmpi

NETCDF(3) وظائف مكتبة UNIDATA NETCDF(3)

الاسم

netcdf - واجهة مكتبة Unidata Common Data Form (netCDF)

الملخص

#include "netcdf.h"

cc ... -lnetcdf -lhdf5_hl -lhdf5 -lz -lm

يمكن العثور على الوثائق الكاملة لمكتبات netCDF على موقع netCDF: https://www.unidata.ucar.edu/software/netcdf/.

إصدار المكتبة

توثق هذه الوثيقة الإصدارات 3 و 4 من واجهة الوصول إلى البيانات Unidata netCDF للغة البرمجة C.

const char* nc_inq_libvers()

تُرجع سلسلة نصية تحدد إصدار مكتبة netCDF، ووقت بنائها، مثل: "3.1a of Aug 22 1996 12:57:47 $".

سيجد الأمر RCS ident(1) سلسلة نصية مثل "$Id: @(#) netcdf library version 3.1a of Sep 6 1996 15:56:26 $" في المكتبة. سيجد الأمر SCCS what(1) سلسلة نصية مثل "netcdf library version 3.1a of Aug 23 1996 16:07:40 $".

قيم الإرجاع

جميع وظائف netCDF (باستثناء nc_inq_libvers() و nc_strerror()) تُرجع قيمة حالة عدد صحيح.

إذا كانت قيمة الحالة المرتجعة هذه لا تساوي NC_NOERR (صفر)، فهذا يشير إلى حدوث خطأ. يمكن تعريف قيم الحالة الممكنة في ملف التضمين النظامي <errno.h> وفي "netcdf.h".

const char* nc_strerror(int status)

تُرجع ترجمة نصية للسلسلة لقيمة status، مثل "Attribute or variable name contains illegal characters" أو "No such file or directory".

عمليات الملف

int nc_create(const char path[], int cmode, int* ncid)

ينشئ مجموعة بيانات netCDF جديدة في path، ويرجع معرف netCDF في ncid. قد يتضمن الوسيط cmode المنطق OR للبت للأعلام التالية: NC_NOCLOBBER لحماية مجموعات البيانات الموجودة (الافتراضي يمحوها بصمت)، NC_SHARE للتحديثات المتزامنة لمجموعة البيانات لملفات التنسيق الكلاسيكي (الافتراضي هو تخزين الوصول مؤقتًا)،

عند إنشاء مجموعة بيانات netCDF، يتم فتحها NC_WRITE. مجموعة بيانات netCDF الجديدة في وضع التعيين. NC_64BIT_OFFSET. لإنشاء ملف بتنسيق الإزاحة 64 بت (على عكس التنسيق الكلاسيكي، وهو الافتراضي). NC_TRUE لإنشاء ملف netCDF-4/HDF5، و NC_CLASSIC_MODEL لضمان أن ملفات netCDF-4/HDF5 تحافظ على التوافق مع نموذج بيانات netCDF الكلاسيكي.

int nc__create(const char path[], int cmode, size_t initialsize, size_t* chunksize, int* ncid)

مثل nc_create() ولكن لديها معلمات إضافية لتحسين الأداء.

يحدد الوسيط initialsize الحجم الأولي للملف عند الإنشاء.

راجع nc__open() أدناه للحصول على شرح لمعلمة chunksize.

int nc_open(const char path[], int mode, int* ncid)

(يقابل ncopen() في الإصدار 2)

يفتح مجموعة بيانات netCDF موجودة في path ويرجع معرف netCDF في ncid. يتم وصف نوع الوصول بواسطة الوسيط mode، والذي قد يتضمن المنطق OR للبت للأعلام التالية: NC_WRITE للوصول للقراءة والكتابة (الافتراضي للقراءة فقط)، NC_SHARE للتحديثات المتزامنة لمجموعة البيانات (الافتراضي هو تخزين الوصول مؤقتًا)، و NC_LOCK (لم يتم تنفيذه بعد).

int nc__open(const char path[], int mode, size_t* chunksize, int* ncid)

مثل nc_open() ولكن لديها معلمة إضافية لتحسين الأداء.

الوسيط المشار إليه بواسطة chunksize يتحكم في مفاضلة بين المساحة والوقت، والذاكرة المخصصة في مكتبة netcdf مقابل عدد استدعاءات النظام. نظرًا للمتطلبات الداخلية، قد لا يتم تعيين القيمة تمامًا إلى القيمة المطلوبة. يتم إرجاع القيمة الفعلية المحددة بالمرجع. استخدام القيمة NC_SIZEHINT_DEFAULT يجعل المكتبة تختار قيمة افتراضية. تعتمد كيفية اختيار النظام للقيمة الافتراضية على النظام. في العديد من الأنظمة، يكون "حجم كتلة الإدخال/الإخراج المفضل" متاحًا من استدعاء النظام stat()، العضو st_blksize في struct stat. إذا كان هذا متاحًا، يتم استخدامه. وبخلاف ذلك، يتم استخدام ضعف حجم صفحة النظام. وبخلاف استدعاء لاكتشاف حجم صفحة النظام، فإننا نضبط حجم الكتلة الافتراضي على 8192.

حجم الكتلة هو خاصية لمعرف netcdf مفتوح معين ncid، وليس خاصية دائمة لمجموعة بيانات netcdf.

int nc_redef(int ncid)

(يقابل ncredef() في الإصدار 2)

يضع مجموعة بيانات netCDF مفتوحة في وضع التعيين، بحيث يمكن إضافة أو إعادة تسمية الأبعاد والمتغيرات والسمات، ويمكن حذف السمات.

int nc_enddef(int ncid)

(يقابل ncendef() في الإصدار 2)

يخرج مجموعة بيانات netCDF مفتوحة من وضع التعيين. يتم فحص التغييرات التي تم إجراؤها على مجموعة بيانات netCDF أثناء وجودها في وضع التعيين، ويتم تثبيتها على القرص إذا لم تحدث مشاكل. قد يتم أيضًا كتابة بعض قيم البيانات، انظر "تعبئة المتغيرات المسبقة" أدناه. بعد استدعاء ناجح، يمكن قراءة بيانات المتغير أو كتابتها إلى مجموعة البيانات.

int nc__enddef(int ncid, size_t h_minfree, size_t v_align, size_t v_minfree, size_t r_align)

مثل nc_enddef() ولكن لديها معلمات إضافية لتحسين الأداء.

تحذير: تكشف هذه الوظيفة عن الأجزاء الداخلية لتنسيق ملف netcdf الإصدار 1. قد لا تكون متاحة في تطبيقات netcdf المستقبلية.

يحتوي تنسيق ملف netcdf الحالي على ثلاثة أقسام، قسم "الرأس"، قسم البيانات للمتغيرات ذات الحجم الثابت، وقسم البيانات للمتغيرات التي تحتوي على بُعد غير محدود (متغيرات السجلات). يبدأ الرأس في بداية الملف. يتم احتواء الفهرس (الإزاحة) لبداية القسمين الآخرين في الرأس. عادةً، لا توجد مسافة بين الأقسام. هذا يسبب زيادة في تكاليف النسخ إذا أراد المرء تغيير حجم الأقسام، كما قد يحدث عند تغيير أسماء الأشياء، أو قيم سمات النص، أو إضافة سمات، أو إضافة متغيرات. أيضًا، بالنسبة للإدخال/الإخراج المخزن مؤقتًا، قد تكون هناك مزايا لمحاذاة الأقسام بطرق معينة.

تسمح معلمات minfree بالتحكم في تكاليف الاستدعاءات المستقبلية لـ nc_redef() و nc_enddef() عن طريق طلب توفير minfree بايت في نهاية القسم. تحدد معلمة h_minfree المساحة في نهاية قسم "الرأس". تحدد معلمة v_minfree المساحة في نهاية قسم البيانات للمتغيرات ذات الحجم الثابت.

تسمح معلمات المحاذاة بتعيين محاذاة بداية الأقسام المقابلة. يتم تقريب بداية القسم لأعلى إلى فهرس يمثل مضاعفًا لمعلمة المحاذاة. القيمة العلم NC_ALIGN_CHUNK تخبر المكتبة باستخدام حجم الكتلة (انظر أعلاه) كمعلمة محاذاة. تتحكم معلمة v_align في محاذاة بداية قسم البيانات للمتغيرات ذات الحجم الثابت. تتحكم معلمة r_align في محاذاة بداية قسم البيانات للمتغيرات التي تحتوي على بُعد غير محدود (متغيرات السجلات).

يتطلب تنسيق الملف محاذاة بتردد 4، لذلك يتم تقريب معلمات المحاذاة بصمت إلى مضاعفات 4. الاستدعاء المعتاد، nc_enddef(ncid)، يعادل nc__enddef(ncid, 0, 4, 0, 4).

لا يحتوي تنسيق الملف على قيمة "حجم السجل"، فهذه القيمة محسوبة من أحجام متغيرات السجلات. هذه الحقيقة المؤسفة تمنعنا من توفير تحكم في الحد الأدنى للمساحة والمحاذاة لـ "السجلات" في ملف netcdf. إذا أضفت متغيرًا يحتوي على بُعد غير محدود، فسيتم نسخ القسم الثالث دائمًا مع إضافة المتغير الجديد.

int nc_sync(int ncid)

(يقابل ncsync() في الإصدار 2)

ما لم يتم تعيين بت NC_SHARE في nc_open() أو nc_create()، يتم تخزين الوصول إلى مجموعة بيانات netCDF الأساسية مؤقتًا بواسطة المكتبة. هذه الوظيفة تزامن حالة مجموعة البيانات الأساسية والمكتبة. يتم ذلك تلقائيًا بواسطة nc_close() و nc_enddef().

int nc_abort(int ncid)

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

(يتوافق مع ncabort() في الإصدار 2)

لا تحتاج إلى استدعاء هذه الدالة. يتم استدعاء هذه الدالة تلقائيًا بواسطة nc_close() إذا كان ملف netCDF في وضع التعريف (define mode) وحد حدث خطأ ما أثناء الالتزام (commit). إذا لم يكن مجموعة بيانات netCDF في وضع التعريف، فإن هذه الدالة تعادل nc_close(). إذا تم استدعاؤها بعد nc_redef() ولكن قبل nc_enddef()، فلن يتم الالتزام بالتعريفات الجديدة وسيتم إغلاق مجموعة البيانات. إذا تم استدعاؤها بعد nc_create() ولكن قبل nc_enddef()، فسيتم حذف مجموعة البيانات.

DESCRIPTIONS OF FUNCTIONS

int nc_copy_att(int ncid, int varid, const char name[], int res_ncid, int res_varid)

Copies an attribute from one netCDF dataset to another. The destination netCDF dataset must be in define mode. If the attribute specified by name does not exist, an error is returned. If the attribute already exists in the destination, it will be overwritten. The attribute defined by name is copied from the source netCDF dataset identified by ncid and varid to the destination netCDF dataset identified by res_ncid and res_varid.

int nc_rename_att(int ncid, int varid, const char name[], const char newname[])

Renames an attribute in a netCDF dataset. The netCDF must be in define mode. You cannot rename an attribute to have the same name as another attribute of the same variable. name is the original attribute name. newname is the new name to be assigned to the specified attribute. If the new name is longer than the old name, the netCDF dataset must be in define mode.

int nc_del_att(int ncid, int varid, const char name[])

Deletes an attribute from a netCDF dataset. The dataset must be in define mode.

DESCRIPTIONS OF COMMON ARGUMENTS

In this section we define some common arguments which are used in the "FUNCTION DESCRIPTIONS" section.

int ncid
is the netCDF ID returned from a previous, successful call to nc_open() or nc_create()
char name[]
is the name of a dimension, variable, or attribute. The names of dimensions, variables and attributes consist of arbitrary sequences of alphanumeric characters (as well as underscore '_', period '.' and hyphen '-'), beginning with a letter or underscore. (However names commencing with underscore are reserved for system use.) Case is significant in netCDF names. A zero-length name is not allowed. As an input argument, it shall be a pointer to a 0-terminated string; as an output argument, it shall be the address of a buffer in which to hold such a string. The maximum allowable number of characters (excluding the terminating 0) is NC_MAX_NAME.
nc_type xtype
specifies the external data type of a netCDF variable or attribute and is one of the following: NC_BYTE, NC_CHAR, NC_SHORT, NC_INT, NC_FLOAT, or NC_DOUBLE. These are used to specify 8-bit integers, characters, 16-bit integers, 32-bit integers, 32-bit IEEE floating point numbers, and 64-bit IEEE floating-point numbers, respectively. (NC_INT corresponds to NC_LONG in version 2, to specify a 32-bit integer).
int dimids[]
is a vector of dimension ID's and defines the shape of a netCDF variable. The size of the vector shall be greater than or equal to the rank (i.e. the number of dimensions) of the variable (ndims). The vector shall be ordered by the speed with which a dimension varies: dimids[ndims-1] shall be the dimension ID of the most rapidly varying dimension and dimids[0] shall be the dimension ID of the most slowly varying dimension. The maximum possible number of dimensions for a variable is given by the symbolic constant NC_MAX_VAR_DIMS.
int dimid
is the ID of a netCDF dimension. netCDF dimension ID's are allocated sequentially from the non-negative integers beginning with 0.
int ndims
is either the total number of dimensions in a netCDF dataset or the rank (i.e. the number of dimensions) of a netCDF variable. The value shall not be negative or greater than the symbolic constant NC_MAX_VAR_DIMS.
int varid
is the ID of a netCDF variable or (for the attribute-access functions) the symbolic constant NC_GLOBAL, which is used to reference global attributes. netCDF variable ID's are allocated sequentially from the non-negative integers beginning with 0.
int* natts
is the number of global attributes in a netCDF dataset for the nc_inquire() function or the number of attributes associated with a netCDF variable for the nc_varinq() function.
const size_t index[]
specifies the indicial coordinates of the netCDF data value to be accessed. The indices start at 0; thus, for example, the first data value of a two-dimensional variable is (0,0). The size of the vector shall be at least the rank of the associated netCDF variable and its elements shall correspond, in order, to the variable's dimensions.
const size_t start[]
specifies the starting point for accessing a netCDF variable's data values in terms of the indicial coordinates of the corner of the array section. The indices start at 0; thus, the first data value of a variable is (0, 0, ..., 0). The size of the vector shall be at least the rank of the associated netCDF variable and its elements shall correspond, in order, to the variable's dimensions.
const size_t count[]
specifies the number of indices selected along each dimension of the array section. Thus, to access a single value, for example, specify count as (1, 1, ..., 1). Note that, for strided I/O, this argument must be adjusted to be compatible with the stride and start arguments so that the interaction of the three does not attempt to access an invalid data co-ordinate. The elements of the count vector correspond, in order, to the variable's dimensions.
const size_t stride[]
specifies the sampling interval along each dimension of the netCDF variable. The elements of the stride vector correspond, in order, to the netCDF variable's dimensions (stride[0]) gives the sampling interval along the most slowly varying dimension of the netCDF variable). Sampling intervals are specified in type-independent units of elements (a value of 1 selects consecutive elements of the netCDF variable along the corresponding dimension, a value of 2 selects every other element, etc.). A NULL stride argument is treated as (1, 1, ... , 1).
imap
specifies the mapping between the dimensions of a netCDF variable and the in-memory structure of the internal data array. The elements of the index mapping vector correspond, in order, to the netCDF variable's dimensions (imap[0] gives the distance between elements of the internal array corresponding to the most slowly varying dimension of the netCDF variable). Distances between elements are specified in type-independent units of elements (the distance between internal elements that occupy adjacent memory locations is 1 and not the element's byte-length as in netCDF 2). A NULL pointer means the memory-resident values have the same structure as the associated netCDF variable.

VARIABLE PREFILLING

By default, the netCDF interface sets the values of all newly-defined variables of finite length (i.e. those that do not have an unlimited, dimension) to the type-dependent fill-value associated with each variable. This is done when nc_enddef() is called. The fill-value for a variable may be changed from the default value by defining the attribute `_FillValue' for the variable. This attribute must have the same type as the variable and be of length one.

Variables with an unlimited dimension are also prefilled, but on an `as needed' basis. For example, if the first write of such a variable is to position 5, then positions 0 through 4 (and no others) would be set to the fill-value at the same time.

This default prefilling of data values may be disabled by or'ing the NC_NOFILL flag into the mode parameter of nc_open() or nc_create(), or, by calling the function nc_set_fill() with the argument NC_NOFILL. For variables that do not use the unlimited dimension, this call must be made before nc_enddef(). For variables that use the unlimited dimension, this call may be made at any time.
