التراخيص: PerlArtistic, GPL

Net::Server::Proto(3) وثائق Perl التي ساهم بها المستخدم Net::Server::Proto(3)

الاسم

Net::Server::Proto - طبقة توافق بروتوكول Net::Server

الملخص

ملاحظة: ابتداءً من Net::Server 2.005، القيمة الافتراضية لـ
      ipv هي IPv* مما يعني أنه إذا لم يتم تمرير مضيف، أو
      تم تمرير اسم مضيف، فسيتم ربط جميع أنواع المقابس المتاحة.
      يمكنك فرض IPv4 فقط عن طريق إضافة ipv => 4
      تكوين بأي من الطرق الست التي نسمح لك بها
      لتحديدها.
ملاحظة: بالنسبة لـ IPv6، ستحاول Net::Server أولاً استخدام الوحدة
      المدرجة في إعداد الخادم ipv6_package، ثم
      $Net::Server::ipv6_package، ثم IO::Socket::IP، ثم
      IO::Socket::INET6 (الذي تم إهماله).
# Net::Server::Proto ووحداتها المرافقة ليست
# مخصصة للاستخدام خارج نطاق Net::Server.
# ومع ذلك، إليك كيفية استخدامها. هذا
# مخصص فقط لأي شخص يرغب في توسيع
# البروتوكولات لتشمل مجموعة أخرى (على سبيل المثال ربما
# بروتوكول اتصال قاعدة بيانات)
use Net::Server::Proto;
my @info = Net::Server::Proto->parse_info(
    $port,            # المنفذ للاتصال به
    $default_host,    # المضيف للاستخدام إذا لم يتم العثور على أي في المنفذ
    $default_proto,   # البروتوكول للاستخدام إذا لم يتم العثور على أي في المنفذ
    $default_ipv,     # افتراضي IPv6 أو IPv4 إذا لم يتم العثور على أي في المنفذ
    $server_obj,      # كائن Net::Server
);
my @raw_info = Net::Server::Proto->get_addr_info($host, $port, $proto);
# يعيد مصفوفة من عناوين IP المستندة، والمنافذ، وقيم ipv
my $sock = Net::Server::Proto->object({
    port  => $port,
    host  => $host,
    proto => $proto,
    ipv   => $ipv, # * (IPv*) إذا كان خطأ (خطأ افتراضي)
}, $server);
# ستحاول Net::Server::Proto التفاعل مع
# الوحدات الفرعية المسماة بشكل مشابه لـ Net::Server::Proto::TCP
# سيتم تحميل الوحدات الفرعية الفردية بواسطة
# Net::Server::Proto عند الحاجة إليها.
use Net::Server::Proto::TCP; # أو UDP أو UNIX إلخ
# يعيد كائنًا هو فئة فرعية من IO::Socket
# في هذه المرحلة الكائن غير متصل.
# يمكن للطريقة جمع أي معلومات أخرى تحتاجها
# من كائن الخادم.
my $sock = Net::Server::Proto::TCP->object({
    port  => $port,
    host  => $host,
    proto => $proto,
    ipv   => 6, # IPv6 - الافتراضي هو * - يمكن أن يكون أيضًا '4'
}, $server);
# تسجيل أنه سيحدث اتصال.
# استخدم مرافق كائن Net::Server الممرر.
$sock->log_connect( $server );
# ربط فعلي بالمنفذ أو المقبس. هذا
# يتم عادةً عن طريق استدعاء طريقة التكوين.
$sock->connect();
# السماح بإعادة الربط بمقبس ملف مفتوح بالفعل.
# عادةً ما يقوم فقط بفتح fdopen.
$sock->reconnect();
### إعادة سلسلة تعريف فريدة لهذا المقبس يمكن
# استخدامها عند إعادة الاتصال.
my $str = $sock->hup_string();
# إعادة البروتوكول المستخدم بواسطة هذه الوحدة.
my $proto = $sock->NS_proto();

الوصف

Net::Server::Proto هي وحدة وسيطة تعيد كائنات من نمط IO::Socket تم مباركتها ضمن مجموعتها الخاصة من الفئات (مثل Net::Server::Proto::TCP, Net::Server::Proto::UNIX).

يتم تجميع ثلاثة أو أربعة بروتوكولات فقط مع Net::Server. TCP، UDP، UNIX، UNIXDGRAM، و SSLEAY. TCP هو تطبيق لـ SOCK_STREAM عبر مقبس INET. UDP هو تطبيق لـ SOCK_DGRAM عبر مقبس INET. يستخدم UNIX ملف مقبس بأسلوب unix مع بروتوكول SOCK_STREAM. يستخدم UNIXGRAM ملف مقبس بأسلوب unix مع بروتوكول SOCK_DGRAM. SSLEAY هو في الواقع مجرد طبقة فوق TCP ولكنه يستخدم Net::SSLeay للقراءة والكتابة من التدفق.

يمكن أن يكون البروتوكول الذي تم تمريره إلى Net::Server اسم وحدة أخرى تحتوي على ربطات البروتوكول. إذا تم تمرير بروتوكول MyServer::MyTCP، فإن المقبس سيتم مباركته في تلك الفئة. إذا تم تمرير Net::Server::Proto::TCP، فإنه سيحصل على تلك الفئة. إذا تم تمرير كلمة عادية، مثل tcp، udp، unix، unixdgram أو ssleay، يتم تحويل الكلمة إلى أحرف كبيرة، ويتم إلحاقها بـ "Net::Server::Proto::" (أي tcp = Net::Server::Proto::TCP).

الطرق

يجب أن تكون أسماء البروتوكولات المستخدمة بواسطة Net::Server::Proto فئات فرعية من IO::Socket. يجب أن تحتوي هذه الفئات أيضًا، كحد أدنى، على الطرق التالية:

object
يعيد كائنًا هو فئة فرعية من IO::Socket. في هذه المرحلة الكائن غير متصل. يمكن للطريقة جمع أي معلومات أخرى تحتاجها من كائن الخادم. الوسائط هي default_host، port، وكائن خادم بنمط Net::Server.
log_connect
تسجيل أنه سيحدث اتصال. استخدم مرافق كائن Net::Server الممرر. يجب أن تكون هذه سلسلة معلوماتية تشرح الخصائص التي يتم استخدامها.
connect
ربط فعلي بالمنفذ أو ملف المقبس. يتم هذا عادةً داخليًا عن طريق استدعاء طريقة التكوين للفئة الفائقة IO::Socket.
reconnect
السماح بإعادة الربط بمقبس ملف مفتوح بالفعل. عادةً ما يقوم فقط بفتح fdopen باستخدام الفئة الفائقة IO::Socket.
hup_string
إعادة سلسلة تعريف فريدة لهذا المقبس يمكن استخدامها عند إعادة الاتصال. يتم ذلك للسماح بتمرير معلومات بما في ذلك واصف الملف للمقابس المفتوحة عبر %ENV أثناء التنفيذ. يجب أن تكون هذه السلسلة دائمًا هي نفسها بناءً على معلمات التكوين.
NS_port
بروتوكول Net::Server. يعيد المنفذ الذي تستخدمه هذه الوحدة. إذا كان النوع الأساسي هو UNIX، فسيكون المنفذ في الواقع هو المسار إلى ملف مقبس unix.
NS_host
بروتوكول Net::Server. يعيد البروتوكول الذي تستخدمه هذه الوحدة. لا يلزم أن يكون هذا بروتوكولًا مسجلاً أو معروفًا.
NS_proto
بروتوكول Net::Server. يعيد البروتوكول الذي تستخدمه هذه الوحدة. لا يلزم أن يكون هذا بروتوكولًا مسجلاً أو معروفًا.
show
مشابه لـ log_connect، ولكنه يعرض ببساطة قائمة بالخصائص التي تم العثور عليها. يمكن استخدامه في أي وقت.

المضيف

قد يكون اسم المضيف فارغًا، أو '*'، أو عنوان IPv4، أو عنوان IPv6، أو اسم مضيف عادي، أو اسم مضيف بمواصفات IPv*.

host => "127.0.0.1",  # عنوان IPv4
host => "::1",        # عنوان IPv6
host => 'localhost',  # عناوين يتم إرجاعها بواسطة localhost (افتراضي IPv* - IPv4 و/أو IPv6)
host => 'localhost/IPv*',  # نفس الشيء
ipv  => '*',
host => 'localhost',  # نفس الشيء
ipv  => 6,
host => 'localhost',  # عناوين يتم إرجاعها بواسطة localhost (IPv6)
ipv  => 'IPv4 IPv6',
host => 'localhost',  # عناوين يتم إرجاعها بواسطة localhost (يتطلب IPv6 و IPv4)
host => '*',          # أي واجهات محلية (افتراضي IPv*)
ipv  => '*',
host => '*',          # أي واجهات محلية (أي IPv6 أو IPv4)
host => '*/IPv*',     # نفس الشيء

IPV

بالإضافة إلى القدرة على تحديد IPV كمعلمة منفصلة، يمكن أيضًا تمرير ipv كجزء من المضيف، كجزء من المنفذ، كجزء من البروتوكول أو يمكن تحديده عبر $ENV{'IPV'}. ترتيب الأسبقية هو كالتالي:

1) عنوان IPv4 أو IPv6 صريح - يفوز
2) ipv محدد في المنفذ
3) ipv محدد في المضيف
4) ipv محدد في proto
5) ipv محدد في الإعدادات الافتراضية
6) ipv محدد في $ENV{'IPV'}
7) افتراضي إلى IPv*

المنفذ

المنفذ هو أهم وسيط يتم تمريره إلى الفئات الفرعية للوحدة وإلى Net::Server::Proto نفسه. بالنسبة لمنافذ نمط tcp، udp، و ssleay، يكون الشكل بشكل عام host:port/protocol، [host]:port/protocol، host|port|protocol، host/port، أو port. إذا كان host عنوان IPv6 رقميًا، فيجب وضعه بين قوسين لتجنب الغموض في تحليل رقم المنفذ، على سبيل المثال: "[::1]:80". الفصل باستخدام المسافات أو الفواصل أو الأنابيب مسموح به أيضًا، على سبيل المثال "::1, 80". لمقابس unix، يكون الشكل بشكل عام socket_file|unix أو socket_file.

للمساعدة في التغلب على غموض التحليل، من الممكن أيضًا تمرير port كمؤشر هاش (أو كمصفوفة من مؤشرات الهاش) للمعلومات مثل:

port => {
    host  => "localhost",
    ipv   => 6, # يمكن أيضًا تمرير IPv6 (* هو الافتراضي)
    port  => 20203,
    proto => 'tcp',
}

إذا لم يتضمن مؤشر الهاش المضيف أو ipv أو proto - فسوف يستخدم القيمة الافتراضية التي يوفرها التكوين العام.
