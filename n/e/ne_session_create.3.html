ne_session_create(3)

الحزمة: neon

التراخيص: LGPL-2.0-or-later

NE_SESSION_CREATE(3) مرجع واجهة برمجة تطبيقات neon NE_SESSION_CREATE(3)

الاسم

ne_session_create, ne_close_connection, ne_session_destroy - إعداد جلسات HTTP

الملخص

#include <ne_session.h>

ne_session *ne_session_create(const char *scheme, const char *host, unsigned int port);

void ne_close_connection(ne_session *session);

void ne_session_destroy(ne_session *session);

الوصف

يمثل الكائن ne_session جلسة HTTP - تجميع منطقي لسلسلة من طلبات HTTP المقدمة إلى خادم معين. يمكن لأي طلبات تتم باستخدام الجلسة استخدام اتصال مستمر، ومشاركة بيانات اعتماد مصادقة مخزنة مؤقتًا وأي سمات مشتركة أخرى.

يتم إنشاء جلسة HTTP جديدة باستخدام الدالة ne_session_create؛ تحدد المعلمتان host و port الخادم المصدر المراد استخدامه، بالإضافة إلى scheme (عادةً "http"). قبل الاستخدام الأول لـ ne_session_create في عملية، يجب استدعاء ne_sock_init لإجراء أي تهيئة عامة تحتاجها أي مكتبات تستخدمها neon.

لتمكين SSL/TLS للجلسة، قم بتمرير السلسلة النصية "https" كـ scheme، إما تسجيل دالة التحقق من الشهادة (انظر ne_ssl_set_verify) أو الوثوق بالشهادة المناسبة (انظر ne_ssl_trust_cert، ne_ssl_trust_default_ca).

يجب أن يتبع المعلمة host تعريف المضيف في RFC 3986[1]، والذي يمكن أن يكون عنوان IP حرفيًا أو اسم مضيف مسجل (DNS). أمثلة صالحة لكل منهما: "198.51.100.42" (عنوان IP حرفي IPv4)، "[2001:db8::42]" (حرفي IPv6، والذي يجب أن يكون محاطًا بأقواس مربعة)، أو "www.example.com" (اسم مضيف DNS). يُسمح أيضًا ببناء جملة RFC 6874[2] لعناوين IPv6 الحرفية المحلية للرابط، على سبيل المثال "[fe80::1%25eth0]".

تُستخدم المعلمة scheme لتحديد URI للموارد المحددة أثناء معالجة الطلبات. بخلاف المعالجة الخاصة للسلسلة النصية "https"، لا يتم إجراء أي تفسير أو تحقق آخر لـ scheme. على سبيل المثال، إذا تم تكوين وكيل HTTP إلى FTP، يمكن استخدام scheme "ftp" للوصول إلى الموارد.

لاستخدام خادم وكيل للجلسة، يجب تكوينه (انظر ne_session_proxy) قبل إنشاء أي طلبات من كائن الجلسة.

يمكن تغيير خيارات إضافية لكل جلسة باستخدام الواجهة ne_set_session_flag.

إذا كان معروفًا أنه لن يتم استخدام الجلسة لفترة طويلة، يمكن استدعاء ne_close_connection لإغلاق الاتصال، إذا كان لا يزال مفتوحًا. استخدام هذه الدالة اختياري تمامًا، ولكن يجب عدم استدعائها إذا كان هناك طلب نشط يستخدم الجلسة.

بمجرد اكتمال الجلسة، يجب استدعاء ne_session_destroy لتدمير الموارد المرتبطة بالجلسة. يؤدي أي استخدام لاحق لمؤشر الجلسة إلى سلوك غير محدد. يجب عدم تدمير كائن الجلسة حتى بعد تدمير جميع كائنات الطلب المرتبطة.

ملاحظات

إذا تم تمرير اسم مضيف إلى ne_session_create، فسيتم حله عند إرسال أول طلب يستخدم الجلسة؛ لا يمكن اكتشاف فشل حل DNS إلا في ذلك الوقت (باستخدام رمز الخطأ NE_LOOKUP)؛ انظر ne_request_dispatch للحصول على التفاصيل.

قيم الإرجاع

ستقوم ne_session_create بإرجاع مؤشر إلى كائن جلسة جديد (ولن يكون NULL أبدًا).

أمثلة

إنشاء وتدمير جلسة:

ne_session *sess;
sess = ne_session_create("http", "host.example.com", 80);
/* ... استخدم sess ... */
ne_session_destroy(sess);
