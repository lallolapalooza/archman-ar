NEWS.DAILY(8) InterNetNews Documentation NEWS.DAILY(8)

الاسم

news.daily - تنفيذ مهام صيانة Usenet اليومية

الاستخدام

news.daily [delayrm] [expctl=path] [expdir=path] [expireover] [expireoverflags=args] [flags=args] [lowmark] [mailto=address] [noexpire] [noexpireover] [noexplog] [nologs] [nomail] [noprocbatch] [norenumber] [norm] [norotate] [nostat] [notdaily] [postexec=program] [procbatchdir=path] [tmpdir=path] [/path/to/a/program]

الوصف

يقوم news.daily بتنفيذ عدد من وظائف إدارة Usenet الهامة. يشمل ذلك:

  • إنتاج تقرير حالة باستخدام innstat؛
  • إزالة مقالات الأخبار القديمة (باستخدام expirerm إذا تم تحديد الكلمة المفتاحية delayrm)؛
  • مسح قاعدة بيانات النظرة العامة باستخدام expireover (إذا تم تحديد الكلمة المفتاحية المقابلة أو إذا كانت enableoverview مضبوطة على true في inn.conf)؛
  • معالجة ملفات السجل وتدوير ملفات السجل المؤرشفة باستخدام scanlogs؛
  • معالجة ملفات innfeed المتساقطة باستخدام procbatch؛
  • معالجة الرسائل المكدسة باستخدام rnews المستدعاة بالعلامة -U؛
  • إعادة ترقيم ملف active باستخدام ctlinnd؛
  • إعادة بناء ملف history باستخدام expire؛
  • إزالة أي ملفات مقبس قديمة موجودة في دليل pathrun؛
  • تجميع كل المخرجات وإرسالها عبر البريد.

يرجى ملاحظة أنه يجب تشغيل هذا البرنامج تحت حساب مسؤول الأخبار (عادةً "news")، وليس كـ root. افتراضيًا، يقوم news.daily بتنفيذ جميع وظائفه ويرسل المخرجات عبر البريد إلى مسؤول الأخبار، وهو المستخدم المحدد بواسطة --with-news-master وقت التكوين (وهو "usenet" افتراضيًا). يمكنك أيضًا تغيير هذا السلوك باستخدام الكلمة المفتاحية mailto.

من خلال تحديد الكلمات المفتاحية في سطر الأوامر، من الممكن تعديل الوظائف التي يتم تنفيذها، بالإضافة إلى تغيير الوسائط المعطاة لـ expire(8) و expireover(8). يجب تشغيل news.daily مرة واحدة في اليوم، عادةً من خلال cron(8). نظرًا لأنه سيؤدي إلى إبطاء الخادم أثناء تشغيله، يجب تشغيله خلال فترات استخدام الخادم المنخفض، مثل منتصف الليل. لتشغيله في الساعة 3 صباحًا، على سبيل المثال، أضف الإدخال التالي إلى ملف crontab الخاص بمستخدم الأخبار:

0 3 * * * <pathbin in inn.conf>/news.daily expireover lowmark

إذا كنت تستخدم أي طرق تخزين غير CNFS، أضف الكلمة المفتاحية delayrm إلى قائمة الخيارات أعلاه لـ news.daily.

يمكن تشغيله بشكل متكرر، ولكن مثل هذه الاستدعاءات يجب أن تستخدم على الأقل الكلمة المفتاحية norotate (أو ربما الكلمة المفتاحية notdaily) لمنع معالجة ملفات السجل وتدويرها بسرعة كبيرة. يتم استخدام البرنامج shlock(8) لمنع التنفيذ المتزامن.

يتم تنفيذ البرنامج المحدد بالمسار /path/to/a/program قبل إجراء أي انتهاء صلاحية. الاستخدام النموذجي هو تحديد برنامج انتهاء صلاحية بديل واستخدام الكلمة المفتاحية noexpire. يمكن تحديد برامج متعددة؛ سيتم استدعاؤها بالترتيب.

الكلمات المفتاحية

يمكن استخدام الكلمات المفتاحية التالية:

delayrm
يستخدم العلامة -z عند استدعاء expire و expireover. تتم كتابة أسماء المقالات المراد إزالتها إلى ملف مؤقت، ثم يتم إعادة تسميته بعد الانتهاء عن طريق استدعاء expirerm الذي بدوره يستدعي fastrm.
expctl=path
تحديد الملف لاستخدامه كـ expire.ctl لـ expire.
expdir=path
افتراضيًا، يقوم expire بإنشاء ملف history وقاعدة البيانات الجديدين في نفس الدليل الذي توجد فيه الملفات الحالية. استخدام هذه الكلمة المفتاحية يحدد موقعًا مختلفًا لإنشاء الملفات الجديدة (عن طريق تمرير العلامة -d إلى expire)، والتي سيتم نقلها بعد ذلك إلى الموقع الصحيح عند الانتهاء.
expireover
يتم استدعاء البرنامج expireover بعد الانتهاء لمسح قاعدة بيانات النظرة العامة. إذا لم يتم إنشاء بيانات نظرة عامة، فلا حاجة للكلمة المفتاحية expireover. هذا هو الحال عندما يعمل الخادم للموزعين فقط (بدون قارئ). افتراضيًا، لا يتم استدعاء expireover بواسطة news.daily إلا إذا تم تعيين enableoverview إلى true في inn.conf.
expireoverflags=args
إذا تم استخدام الكلمة المفتاحية expireover، يمكن استخدام هذه الكلمة المفتاحية لتحديد العلامات التي سيتم تمريرها إلى expireover. إذا تم استخدام الكلمة المفتاحية delayrm، فإن القيمة الافتراضية هي -z وقائمة الملفات المحذوفة؛ بخلاف ذلك، القيمة الافتراضية هي -s.
flags=args
افتراضيًا، يتم استدعاء expire بالوسيط -v1. استخدام هذه الكلمة المفتاحية يغير الوسائط إلى تلك المحددة. كن حذرًا لاستخدام علامات الاقتباس إذا كانت هناك حاجة إلى وسائط متعددة. ليس لهذه الكلمة المفتاحية أي تأثير إذا تم استخدام الكلمة المفتاحية noexpire.
lowmark
إذا تم استخدام الكلمة المفتاحية lowmark، يتم استخدام "ctlinnd lowmark" لإعادة ترقيم active. عملية "ctlinnd renumber" العادية ستستغرق وقتًا طويلاً. مع الكلمة المفتاحية lowmark، سيستغرق هذا وقتًا أقل. إذا تم استخدام الكلمة المفتاحية lowmark، فإن الكلمة المفتاحية norenumber غير ضرورية لأن news.daily تحددها ضمنيًا.

إذا تم تمرير الكلمة المفتاحية lowmark إلى news.daily، فيجب أيضًا تمرير الكلمة المفتاحية expireover؛ بخلاف ذلك، لن يتم أخذ هذا النوع من إعادة الترقيم في الاعتبار.

mailto=address
افتراضيًا، يرسل news.daily التقرير عبر البريد إلى عنوان newsmaster المحدد بواسطة --with-news-master وقت التكوين. يمكن للكلمة المفتاحية mailto تحديد عنوان مختلف لإرسال التقرير إليه. لاحظ أن استخدام هذه الكلمة المفتاحية ليس له تأثير إذا تم تحديد الكلمة المفتاحية nomail أيضًا.
noexpire
افتراضيًا، يتم استدعاء expire لإزالة مقالات الأخبار القديمة. استخدام هذه الكلمة المفتاحية يعطل هذه الوظيفة.
noexpireover
افتراضيًا، يتم استدعاء expireover لإزالة قاعدة بيانات النظرة العامة القديمة إذا تم تعيين enableoverview في inn.conf. استخدام هذه الكلمة المفتاحية يعطل هذه الوظيفة.
noexplog
يقوم expire عادةً بإلحاق المعلومات بـ pathlog/expire.log (انظر newslog(5)). استخدام هذه الكلمة المفتاحية يتسبب في معالجة مخرجات expire كجزء من مخرجات news.daily. ليس لها تأثير إذا تم استخدام الكلمة المفتاحية noexpire.
nologs
بعد الانتهاء، يتم استدعاء scanlogs لمعالجة ملفات السجل. استخدام هذه الكلمة المفتاحية يعطل جميع وظائف معالجة السجل.
nomail
عادةً ما يرسل news.daily رسالة بريد إلكتروني تحتوي على النتائج إلى المسؤول. استخدام هذه الكلمة المفتاحية يتسبب في إرسال هذه الرسالة إلى stdout و stderr بدلاً من ذلك. عادةً، يتم إعادة توجيه كل الأدوات المساعدة التي يستدعيها النص البرمجي إلى ملف. إذا كان الملف فارغًا، فلن يتم إرسال أي رسالة.
noprocbatch
تعطل هذه الكلمة المفتاحية تشغيل procbatch على ملفات innfeed المتساقطة التي تم إنشاؤها في دليل التخزين المؤقت الخاص به. تحتوي هذه الملفات على قائمة بالمقالات التي لم يتم إرسالها بشكل صحيح إلى الأقران. افتراضيًا، سيتم معالجتها وإزالتها لاحقًا.
norenumber
تعطل هذه الكلمة المفتاحية عملية "ctlinnd renumber". عادةً، يتم إعادة تعيين علامات الحد الأدنى لجميع مجموعات الأخبار في ملف active.
norm

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

news.daily(8) - Arch Linux

NAME

news.daily - performs daily maintenance for InterNetNews

SYNOPSIS

news.daily [keyword ...]

DESCRIPTION

news.daily performs daily maintenance tasks for InterNetNews (INN). These tasks include running expire(8), innstat(8), newslog(5), procbatch(8), and scanlogs(8). The exact tasks performed depend on the contents of the expire.ctl(5) file and the keywords specified on the command line.

KEYWORDS

compress
By default, log files are compressed using compress. Using this keyword disables this function.
ctlinndir
By default, any ctlinnd socket that has not been modified for two days will be removed. Using this keyword disables this function.
norotate
By default, log processing includes rotating and cleaning out log files. Using this keyword disables the rotating and cleaning aspect of the log processing: the logs files are only scanned for information and no contents are altered. This keyword has no effect if the nologs keyword is used. The norotate keyword is passed on to scanlogs if it is invoked.
nostat
This keyword disables the status report generated by innstat. Without this keyword, the status report is the first function performed, just prior to obtaining the news.daily lock.
notdaily
By default, news.daily expects to be run only once a day, and it does various things (like rotating logs) that normally should only be done on daily basis. Use this keyword any extra times news.daily is run in the day and the normal log files processing (and rotation) will not be done. This keyword implies nologs.
postexec=program
The program specified by the given path program is executed just after all expiration is done. Multiple programs may be specified; they will be invoked in order.
procbatchdir=path
news.daily tries to find the backlog directory of innfeed in innfeed.conf and innfeed-delayed.conf. In case several instances of innfeed are running or when its configuration file is not the default one, the procbatchdir keyword can be used to specify the path of the backlog directory. This keyword can be used more than once in the command-line, permitting specifying several backlog directories.
tmpdir=path
Overrides the pathtmp setting in inn.conf by setting the environment variable $TMPDIR to the specified path. Various parts of the expire process, such as sort, will then use this path as the directory for temporary files.
