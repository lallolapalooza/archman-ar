NAME

new_PcaPathConf, PcaPathConf, pca_set_check_fn, CplCheckFn, pca_scan_path, pca_last_error, del_PathCache — Path cache configuration

SYNOPSIS

#include <tecla/pathcache.h>

PathCache *
new_PathCache(void);

PathCache *
new_PcaPathConf(int flags);

void
pca_set_check_fn(PathCache *pc, CplCheckFn *check_fn,
                 void *data);

int (
    *pca_scan_path(PathCache *pc, const char *path))(void *data,
                                                      const char *pathname);

const char *
pca_last_error(PathCache *pc);

PathCache *
del_PathCache(PathCache *pc);

DESCRIPTION

This module provides facilities for maintaining a cache of files that may be found in a given list of directories. The cache is intended to be used to speed up the process of filename completion, and in particular, the process of looking up commands in the directories listed in the user's PATH environment variable.

The cache is populated by calling the pca_scan_path() function. This function takes a pointer to a PathCache object, and a string containing a list of directories to scan. The list of directories may be colon separated, as in the shell's PATH variable, or it may be just a single directory. If the string is NULL, then the directories listed in the PATH environment variable will be scanned.

The pca_scan_path() function may be called repeatedly to add new directories to the cache. The cache is cleared before each call to pca_scan_path() by default, but this behaviour may be modified by setting the PCA_ADDONLY flag when calling new_PcaPathConf().

PathCache objects are created using new_PathCache() or new_PcaPathConf(), and destroyed using del_PathCache(). These functions allocate and deallocate memory respectively, and may return NULL or have other error return values if memory allocation fails.

When pca_scan_path() is called, it scans the specified directories, and for each file it finds, it may call a user-supplied callback function to determine whether the file is of interest. If the callback function indicates that the file is of interest, then the file's pathname is added to the cache.

Files may be looked up in the cache by calling cpl_complete_word() or related functions. These functions may take a pointer to a PathCache object to constrain the search to files that have been cached.

AN EXAMPLE

  PathCache *pc;
  const char *path_dirs;

  pc = new_PathCache();
  path_dirs = getenv("PATH");
  pca_scan_path(pc, path_dirs);
  /* Now look for completions in the cache */
  cpl_complete_word(pc, "ls", 1);
  /* ... */
  del_PathCache(pc);

FUNCTION DESCRIPTIONS

The following functions are provided:

new_PathCache()
Creates and returns a new, empty PathCache object. The cache will be populated with files found in the directories specified in the PATH environment variable by default. No filtering is performed on the files found.
new_PcaPathConf(3)
Creates and returns a new, empty PathCache object, initialized with the given flags. The flags may be used to modify the behaviour of the cache, for example, to disable the default scanning of the PATH environment variable, or to cause subsequent calls to pca_scan_path() to add to the cache rather than replacing it. The only flag currently defined is PCA_ADDONLY, which causes the cache to be appended to rather than cleared before scanning.
pca_set_check_fn()
Sets the callback function that is to be used to filter files found during the scanning of directories. See the section on “BEING SELECTIVE” for more details.
pca_scan_path()
Scans the directories specified by the path argument and adds any files that are accepted by the filter function (see pca_set_check_fn) to the cache. If path is NULL, the contents of the PATH environment variable are used. If the PCA_ADDONLY flag was set using new_PcaPathConf(), the cache is not cleared before scanning. Returns a pointer to the filter function that was used, or NULL if an error occurred.
pca_last_error()
Returns a string describing the last error that occurred during a call to pca_scan_path(). This may be called if pca_scan_path() returns NULL.
del_PathCache()
Destroys the given PathCache object, freeing all associated memory.

POPULATING THE CACHE

The cache is populated by calling pca_scan_path(). This function takes a pointer to a PathCache object, and a string containing a list of directories to scan. The list of directories may be colon separated, as in the shell's PATH variable, or it may be just a single directory. If the string is NULL, then the directories listed in the PATH environment variable will be scanned.

The pca_scan_path() function may be called repeatedly to add new directories to the cache. The cache is cleared before each call to pca_scan_path() by default, but this behaviour may be modified by setting the PCA_ADDONLY flag when calling new_PcaPathConf().

LOOKING UP FILES

Files may be looked up in the cache by calling cpl_complete_word() or related functions. These functions may take a pointer to a PathCache object to constrain the search to files that have been cached.

FILENAME COMPLETION

The libtecla library provides a number of functions for performing filename completion. The most basic of these is cpl_complete_word(), which takes a string to complete, and returns a list of possible completions. The functions in this module are intended to be used in conjunction with these completion functions.

When a filename completion is requested, the completion functions will first check the cache to see if any matching filenames have already been found. If they have, then the cached list of completions is returned. If not, then the directories specified in the PATH environment variable are scanned, and any matching files are added to the cache and returned as completions.

BEING SELECTIVE

By default, pca_scan_path() will add all files found in the specified directories to the cache. However, it is possible to specify a callback function that will be called for each file found. This callback function will be called with the full pathname of the file, plus any application-specific data that you provide, and if the callback returns 1 the filename will be reported as a match, and if it returns 0, it will be ignored. Suitable callback functions and their prototypes should be declared with the following macro. The CplCheckFn typedef is also provided in case you wish to declare pointers to such functions.

  #define CPL_CHECK_FN(fn) int (fn)(void *data, \
                                    const char *pathname)
  typedef CPL_CHECK_FN(CplCheckFn);

Registering one of these functions involves calling the pca_set_check_fn() function. In addition to the callback function, passed via the check_fn argument, you can pass a pointer to anything via the data argument. This pointer will be passed on to your callback function, via its own data argument, whenever it is called, so this provides a way to pass appplication specific data to your callback.

  void pca_set_check_fn(PathCache *pc, CplCheckFn *check_fn,
                        void *data);

Note that these callbacks are passed the full pathname of each matching file, so the decision about whether a file is of interest can be based on any property of the file, not just its filename. As an example, the provided cpl_check_exe() callback function looks at the executable permissions of the file and the permissions of its parent directories, and only returns 1 if the user has execute permission to the file. This callback function can thus be used to lookup or complete command names found in the directories listed in the user's PATH environment variable. The example program given earlier in this man page provides a demonstration of this.

Beware that if somebody tries to complete an empty string, your callback will get called once for every file in the cache, which could number in the thousands. If your callback does anything time consuming, this could result in an unacceptable delay for the user, so callbacks should be kept short.

To improve performance, whenever one of these callbacks is called, the choice that it makes is cached, and the next time the corresponding file is looked up, instead of calling the callback again, the cached record of whether it was accepted or rejected is used. Thus if somebody tries to complete an empty string, and hits tab a second time when nothing appears to happen, there will only be one long delay, since the second pass will operate entirely from the cached dispositions of the files. These cached dipositions are discarded whenever pca_scan_path() is called, and whenever pca_set_check_fn() is called with changed callback function or data arguments.

ERROR HANDLING

If pca_scan_path() reports that an error occurred by returning 1, you can obtain a terse description of the error by calling pca_last_error(pc). This returns an internal string containing an error message.

  const char *pca_last_error(PathCache *pc);

CLEANING UP

Once you have finished using a PathCache object, you can reclaim its resources by passing it to the del_PathCache() destructor function. This takes a pointer to one of these objects, and always returns NULL.

  PathCache *del_PathCache(PathCache *pc);

THREAD SAFETY

In multi-threaded programs, you should use the libtecla_r.a version of the library. This uses POSIX reentrant functions where available (hence the _r suffix), and disables features that rely on non-reentrant system functions. In the case of this module, the only disabled feature is username completion in ~username/ expressions, in cpl_path_completions().

Using the libtecla_r.a version of the library, it is safe to use the facilities of this module in multiple threads, provided that each thread uses a separately allocated PathCache object. In other words, if two threads want to do path searching, they should each call new_PathCache() to allocate their own caches.
