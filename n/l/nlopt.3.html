nlopt(3)

الحزمة: nlopt

التراخيص: LGPL-2.1-or-later

NLOPT(3) دليل برمجة NLopt NLOPT(3)

الاسم

nlopt - مكتبة التحسين غير الخطى

الملخص

#include <nlopt.h>

nlopt_opt opt = nlopt_create(algorithm, n);
nlopt_set_min_objective(opt, f, f_data);
nlopt_set_ftol_rel(opt, tol);
...
nlopt_optimize(opt, x , &opt_f);
nlopt_destroy(opt);

تشير "..." إلى أي عدد من استدعاءات وظائف NLopt، أدناه، لتعيين معلمات التحسين، والقيود، ومعايير التوقف. هنا، nlopt_set_ftol_rel هي مجرد مثال لمعيار توقف محتمل. يجب عليك ربط البرنامج الناتج بأعلام الرابط -lnlopt -lm على يونكس.

الوصف

NLopt هي مكتبة للتحسين غير الخطي. تحاول تصغير (أو تكبير) دالة هدف غير خطية معينة f لـ n متغيرات تصميم، باستخدام algorithm المحدد، ربما تخضع لقيود خطية أو غير خطية. يتم إرجاع قيمة الدالة المثلى الموجودة في opt_f (من نوع double) مع قيم متغيرات التصميم المقابلة التي تم إرجاعها في المصفوفة x (من نوع double) بطول n. يجب أن تكون القيم المدخلة في x تخمينًا أوليًا للمثل.

يتم التحكم في معلمات التحسين عبر الكائن opt من النوع nlopt_opt، والذي يتم إنشاؤه بواسطة الدالة nlopt_create ويتم التخلص منه بواسطة nlopt_destroy. من خلال استدعاء وظائف مختلفة في مكتبة NLopt، يمكن للمرء تحديد معايير التوقف (على سبيل المثال، يتم تحديد نسبة تسامح نسبية لقيمة دالة الهدف بواسطة nlopt_set_ftol_rel)، وحدود عليا و/أو سفلية على متغيرات التصميم x، وحتى قيود غير خطية تعسفية غير متساوية ومتساوية.

من خلال تغيير المعلمة algorithm بين ثوابت محددة مسبقًا موصوفة أدناه، يمكن للمرء التبديل بسهولة بين مجموعة متنوعة من خوارزميات التصغير. تتطلب بعض هذه الخوارزميات تدرج (مشتقات) الدالة ليتم توفيرها عبر f، ولا تحتاج الخوارزميات الأخرى إلى مشتقات. تحاول بعض الخوارزميات إيجاد الأمثل العالمي ضمن الحدود المعطاة، ويجد البعض الآخر الأمثل المحلي فقط. تتعامل معظم الخوارزميات فقط مع الحالة التي لا توجد فيها قيود غير خطية. مكتبة NLopt هي غلاف حول العديد من حزم التحسين المجانية/مفتوحة المصدر، بالإضافة إلى بعض التطبيقات الجديدة للخوارزميات المنشورة. يمكنك بالطبع تجميع واستدعاء هذه الحزم بشكل منفصل، وفي بعض الحالات سيوفر هذا مرونة أكبر مما هو متاح عبر NLopt. ومع ذلك، اعتمادًا على الدالة المحددة التي يتم تحسينها، ستختلف الخوارزميات المختلفة في فعاليتها. الهدف من NLopt هو السماح لك بالتبديل بسرعة بين الخوارزميات لتجربتها لمشكلتك، من خلال توفير واجهة موحدة بسيطة لهذه الإجراءات الفرعية.

دالة الهدف

يتم تحديد دالة الهدف عن طريق استدعاء أحد:

nlopt_result nlopt_set_min_objective(nlopt_opt opt,
nlopt_func f,
void* f_data);
nlopt_result nlopt_set_max_objective(nlopt_opt opt,
nlopt_func f,
void* f_data);

اعتمادًا على ما إذا كان المرء يرغب في تصغير أو تكبير دالة الهدف f، على التوالي. يجب أن تكون الدالة f بالشكل:

double f(unsigned n,
const double* x,
double* grad,
void* f_data);

يجب أن تكون القيمة المرتجعة هي قيمة الدالة عند النقطة x، حيث تشير x إلى مصفوفة بطول n من متغيرات التصميم. البعد n مطابق للبعد الذي تم تمريره إلى nlopt_create.

بالإضافة إلى ذلك، إذا كان الوسيط grad ليس NULL، فإن grad يشير إلى مصفوفة بطول n يجب (عند العودة) تعيينها إلى تدرج الدالة فيما يتعلق بمتغيرات التصميم عند x. أي، يجب أن تحتوي grad[i] عند العودة على المشتق الجزئي df/dx[i]، لـ 0 <= i < n، إذا كان grad غير NULL. لا تستخدم جميع خوارزميات التحسين (أدناه) معلومات التدرج: بالنسبة للخوارزميات المدرجة على أنها "خالية من المشتقات"، سيكون الوسيط grad دائمًا NULL ولن يحتاج إلى حسابه أبدًا. (بالنسبة للخوارزميات التي تستخدم معلومات التدرج، قد يظل grad NULL لبعض الاستدعاءات.)

الوسيط f_data هو نفس الوسيط الذي تم تمريره إلى nlopt_set_min_objective أو nlopt_set_max_objective، ويمكن استخدامه لتمرير أي بيانات إضافية إلى الدالة. (أي، يمكن أن يكون مؤشرًا إلى بنية بيانات / نوع معرفة من قبل المستخدم يحتوي على المعلومات التي تحتاجها دالتك، والتي تقوم بتحويلها من void* عن طريق تأكيد النوع.)

قيود الحدود

تم تصميم معظم الخوارزميات في NLopt لتصغير الدوال ذات القيود الحدودية البسيطة على المدخلات. أي، يتم تقييد متجهات الإدخال x[i] لتكون في مستطيل فائق lb[i] <= x[i] <= ub[i] لـ 0 <= i < n. يتم تحديد هذه الحدود عن طريق تمرير المصفوفات lb و ub بطول n إلى دالة واحدة أو كليهما:

nlopt_result nlopt_set_lower_bounds(nlopt_opt opt,
const double* lb);
nlopt_result nlopt_set_upper_bounds(nlopt_opt opt,
const double* ub);

إذا لم يتم تعيين حد أدنى / علوي، فإن الافتراضي هو عدم وجود حد (غير مقيد، أي حد بقيمة لا نهائية)؛ من الممكن وجود حدود سفلية ولكن ليس حدود عليا أو العكس. بدلاً من ذلك، يمكن للمستخدم استدعاء إحدى الوظائف المذكورة أعلاه وتمرير حد سفلي بقيمة -HUGE_VAL و/أو حد علوي بقيمة +HUGE_VAL لبعض متغيرات التصميم لجعلها بلا حدود سفلية/عليا، على التوالي. (HUGE_VAL هو ثابت C القياسي لقيمة لا نهائية في النقطة العائمة، موجود في ملف الرأس math.h.)

لاحظ، مع ذلك، أن بعض الخوارزميات في NLopt، ولا سيما معظم خوارزميات التحسين العالمي، لا تدعم التحسين غير المقيد وستعيد خطأ إذا لم تقم بتوفير حدود عليا وسفلية محدودة.

للراحة، يتم توفير الدالتين التاليتين لتعيين الحدود السفلية/العليا لجميع متغيرات التصميم إلى ثابت واحد (بحيث لا تحتاج إلى ملء مصفوفة بقيمة ثابتة):

nlopt_result nlopt_set_lower_bounds1(nlopt_opt opt,
double lb);
nlopt_result nlopt_set_upper_bounds1(nlopt_opt opt,
double ub);

قيود غير خطية

تدعم العديد من الخوارزميات في NLopt (MMA و ORIG_DIRECT) أيضًا قيود عدم مساواة غير خطية تعسفية، ويسمح البعض أيضًا بقيود مساواة غير خطية (COBYLA، SLSQP، ISRES، و AUGLAG). بالنسبة لهذه الخوارزميات، يمكنك تحديد أي عدد تريده من القيود غير الخطية عن طريق استدعاء الوظائف التالية عدة مرات.

على وجه الخصوص، يمكن تحديد قيد عدم مساواة غير خطي بالشكل fc(x) <= 0، حيث تكون الدالة fc بنفس شكل دالة الهدف الموضحة أعلاه، عن طريق استدعاء:

nlopt_result nlopt_add_inequality_constraint(nlopt_opt opt,
nlopt_func fc,
void* fc_data,
double tol);

تمامًا كما هو الحال بالنسبة لدالة الهدف، fc_data هو مؤشر إلى بيانات مستخدم تعسفية سيتم تمريرها إلى الدالة fc كلما تم استدعاؤها. المعلمة tol هي نسبة تسامح تستخدم لأغراض معايير التوقف فقط: تعتبر النقطة x مقبولة للحكم على ما إذا كان يجب إيقاف التحسين إذا كان fc(x) <= tol. تعني نسبة التسامح صفر أن NLopt سيحاول عدم اعتبار أي x متقاربة إلا إذا كان fc سالبًا تمامًا؛ بشكل عام، يُنصح بنسبة تسامح صغيرة موجبة لتقليل الحساسية لأخطاء التقريب.

يمكن تحديد قيد مساواة غير خطي بالشكل h(x) = 0، حيث تكون الدالة h بنفس شكل دالة الهدف الموضحة أعلاه، عن طريق استدعاء:

nlopt_result nlopt_add_equality_constraint(nl

opt_opt opt,
nlopt_func h,
void* h_data,
double tol);

تمامًا كما هو الحال بالنسبة لدالة الهدف، h_data هو مؤشر لبيانات مستخدم عشوائية سيتم تمريرها إلى الدالة h كلما تم استدعاؤها. المعلمة tol هي تسامح يستخدم لغرض معايير التوقف فقط: تعتبر النقطة x صالحة للحكم على ما إذا كان يجب إيقاف التحسين إذا كانت |h(x)| <= tol. بالنسبة لقيود المساواة، يُنصح بشدة باستخدام تسامح إيجابي صغير للسماح لـ NLopt بالتقارب حتى لو كان قيد المساواة غير صفري قليلاً.

(لأي خوارزمية مدرجة على أنها "خالية من المشتقات" أدناه، ستكون الوسيطة grad لدالة fc أو h دائمًا NULL ولن تحتاج أبدًا إلى حسابها.)

لإزالة جميع قيود عدم المساواة و/أو قيود المساواة من مشكلة معينة opt، يمكنك استدعاء الدوال التالية:

nlopt_result nlopt_remove_inequality_constraints(nlopt_opt opt);
nlopt_result nlopt_remove_equality_constraints(nlopt_opt opt);

الخوارزميات

تحدد المعلمة algorithm خوارزمية التحسين (لمزيد من التفاصيل حول هذه، انظر ملفات README في الدلائل الفرعية لشفرة المصدر)، ويمكن أن تأخذ أيًا من القيم الثابتة التالية.

تشير الثوابت التي تحتوي على _G{N,D}_ في أسمائها إلى طرق التحسين العالمية (global optimization)، بينما تشير _L{N,D}_ إلى طرق التحسين المحلية (local optimization) (التي تحاول إيجاد حد أمثل محلي بدءًا من التخمين الأولي x). تشير الثوابت التي تحتوي على _{G,L}N_ إلى خوارزميات غير معتمدة على المشتقات (derivative-free) لا تتطلب من دالة الهدف تقديم مشتقة، بينما تشير _{G,L}D_ إلى خوارزميات معتمدة على المشتقات تتطلب من دالة الهدف تقديم مشتقة. (خاصة بالنسبة للتحسين المحلي، الخوارزميات المعتمدة على المشتقات متفوقة عمومًا على الخوارزميات الخالية من المشتقات: المشتقة مفيدة *إذا* كان يمكنك حسابها بتكلفة زهيدة، مثل باستخدام طريقة مساعدة.)

يتم إرجاع الخوارزمية المحددة لمشكلة معينة opt بواسطة الدالة:

nlopt_algorithm nlopt_get_algorithm(nlopt_opt opt);

الخوارزميات المتاحة هي:

NLOPT_GN_DIRECT_L
إجراء تحسين عالمي (G) خالي من المشتقات (N) باستخدام خوارزمية البحث DIRECT-L بواسطة Jones et al. كما عدلها Gablonsky et al. لتكون أكثر تركيزًا على البحث المحلي. لا تدعم التحسين غير المقيد. هناك أيضًا العديد من المتغيرات الأخرى لخوارزمية DIRECT التي يتم دعمها: NLOPT_GN_DIRECT، وهي خوارزمية DIRECT الأصلية؛ NLOPT_GN_DIRECT_L_RAND، نسخة عشوائية قليلاً من DIRECT-L قد تكون أفضل في مساحات البحث عالية الأبعاد؛ NLOPT_GN_DIRECT_NOSCAL، NLOPT_GN_DIRECT_L_NOSCAL، و NLOPT_GN_DIRECT_L_RAND_NOSCAL، وهي نسخ من DIRECT حيث لا يتم إعادة قياس الأبعاد إلى مكعب فائق موحد (مما يعني أن الأبعاد ذات الحدود الأكبر تحصل على وزن أكبر).
NLOPT_GN_ORIG_DIRECT_L
تحسين عالمي (G) خالي من المشتقات (N) باستخدام خوارزمية DIRECT-L كما هو مذكور أعلاه، بالإضافة إلى NLOPT_GN_ORIG_DIRECT وهي خوارزمية DIRECT الأصلية. على عكس NLOPT_GN_DIRECT_L أعلاه، تشير هاتان الخوارزميتان إلى شفرة تعتمد على الشفرة الأصلية بلغة Fortran بواسطة Gablonsky et al.، والتي تحتوي على بعض القيود المبرمجة مسبقًا على عدد التقسيمات وما إلى ذلك ولا تدعم جميع معايير التوقف الخاصة بـ NLopt، ولكن من ناحية أخرى تدعم قيود عدم المساواة غير الخطية التعسفية.
NLOPT_GD_STOGO
تحسين عالمي (G) باستخدام خوارزمية StoGO بواسطة Madsen et al. تستغل StoGO معلومات المشتقات (D) (التي يجب توفيرها بواسطة الدالة الهدف) لعمليات البحث المحلية الخاصة بها، وتجري البحث العالمي بتقنية التفرع والحد. لا يتم دعم إلا التحسين المقيد بالحدود. هناك أيضًا متغير آخر لهذه الخوارزمية، NLOPT_GD_STOGO_RAND، وهي نسخة عشوائية من مخطط بحث StoGO. خوارزميات StoGO متاحة فقط إذا تم تجميع NLopt مع تمكين شفرة C++، ويجب ربطها عبر -lnlopt_cxx بدلاً من -lnlopt (عبر مترجم C++، من أجل ربط مكتبات C++ القياسية).
NLOPT_LN_NELDERMEAD
إجراء تحسين محلي (L) خالي من المشتقات (N)، بدءًا من x، باستخدام خوارزمية Simplex لـ Nelder-Mead، معدلة لدعم قيود الحدود. Nelder-Mead، على الرغم من شعبيتها، معروفة بفشلها أحيانًا في التقارب لبعض دوال الهدف، لذلك يجب استخدامها بحذر. الأدلة المتناقلة، من ناحية أخرى، تشير إلى أنها تعمل بشكل جيد إلى حد ما في بعض الحالات التي يصعب التعامل معها بطرق أخرى، مثل الأهداف التي تحتوي على ضوضاء/غير متصلة. انظر أيضًا NLOPT_LN_SBPLX أدناه.
NLOPT_LN_SBPLX
إجراء تحسين محلي (L) خالي من المشتقات (N)، بدءًا من x، باستخدام خوارزمية تعتمد على خوارزمية Subplex بواسطة Rowan et al.، وهي نسخة محسنة من Nelder-Mead (أعلاه). تطبيقنا لا يستخدم الشفرة الأصلية لـ Rowan، ويحتوي على بعض التعديلات الطفيفة مثل الدعم الصريح لقيود الحدود. (مثل Nelder-Mead، غالبًا ما تعمل Subplex بشكل جيد عمليًا، حتى بالنسبة للأهداف التي تحتوي على ضوضاء/غير متصلة، ولكن لا يوجد ضمان صارم بأنها ستتقارب.)
NLOPT_LN_PRAXIS
تحسين محلي (L) خالي من المشتقات (N) باستخدام طريقة المحور الرئيسي (principal-axis method)، بناءً على شفرة Richard Brent. مصممة للتحسين غير المقيد، على الرغم من دعم قيود الحدود أيضًا (عن طريق الطريقة غير الفعالة لإرجاع +Inf عند انتهاك القيود).
NLOPT_LD_LBFGS
تحسين محلي (L) يعتمد على المشتقات (D) باستخدام خوارزمية BFGS محدودة الذاكرة (L-BFGS). (يجب أن توفر الدالة الهدف المشتقة.) يتم دعم التحسين غير المقيد بالإضافة إلى قيود الحدود البسيطة (انظر أعلاه). بناءً على تطبيق بواسطة Luksan et al.
NLOPT_LD_VAR2
تحسين محلي (L) يعتمد على المشتقات (D) باستخدام طريقة متغيرة محدودة الذاكرة مع إزاحة، بناءً على شفرة Luksan et al.، تدعم التحسين غير المقيد والمقيد بالحدود. NLOPT_LD_VAR2 تستخدم طريقة ذات رتبة 2، بينما .B NLOPT_LD_VAR1 هو متغير آخر يستخدم طريقة ذات رتبة 1.
NLOPT_LD_TNEWTON_PRECOND_RESTART
تحسين محلي (L) يعتمد على المشتقات (D) باستخدام طريقة نيوتن المقطوعة (truncated Newton method) المدعومة بـ LBFGS مع إعادة تشغيل الهبوط الأكثر انحدارًا، بناءً على شفرة Luksan et al.، تدعم التحسين غير المقيد والمقيد بالحدود. هناك العديد من المتغيرات الأخرى لهذه الخوارزمية: NLOPT_LD_TNEWTON_PRECOND (نفس الشيء بدون إعادة تشغيل)، NLOPT_LD_TNEWTON_RESTART (نفس الشيء بدون الدعم المسبق)، و NLOPT_LD_TNEWTON (نفس الشيء بدون إعادة تشغيل أو دعم مسبق).
NLOPT_GN_CRS2_LM
تحسين عالمي (G) خالي من المشتقات (N) باستخدام خوارزمية البحث العشوائي المتحكم فيه (CRS2) بواسطة Price، مع تعديل "التطفير المحلي" (LM) المقترح بواسطة Kaelo و Ali.
NLOPT_GN_ISRES
تحسين عالمي (G) خالي من المشتقات (N) باستخدام خوارزمية جينية (تطفير وتطور تفاضلي)، باستخدام ترتيب عشوائي للتعامل مع قيود عدم المساواة والمساواة غير الخطية كما اقترحها Runarsson و Yao.
NLOPT_G_MLSL_LDS, NLOPT_G_MLSL
تحسين عالمي (G) باستخدام خوارزمية الربط الفردي متعدد المستويات (MLSL) مع تسلسل ذي تباين منخفض (LDS) أو أرقام شبه عشوائية، على التوالي. تقوم هذه الخوارزمية بتنفيذ تسلسل ذي تباين منخفض أو شبه عشوائي لعمليات البحث المحلية، مع منهجية تجميع لتجنب عمليات البحث المحلية المتعددة لنفس الحد الأمثل المحلي. يجب تحديد خوارزمية البحث المحلي، جنبًا إلى جنب مع معايير الإنهاء/التسامحات لعمليات البحث المحلية، بواسطة nlopt_set_local_optimizer. (يمكن أن تكون هذه الخوارزمية الفرعية مع أو بدون مشتقات، وتحدد ما إذا كانت دالة الهدف تحتاج إلى مشتقات.)
NLOPT_LD_MMA, NLOPT_LD_CCSAQ
تحسين محلي (L) يعتمد على المشتقات (D) باستخدام طريقة المتجاوزات المتحركة (MMA)، أو بالأحرى نسخة محسنة من الخوارزمية كما نشرها Svanberg (2002). (يستخدم NLopt تطبيقًا مستقلاً مفتوح المصدر للشفرة لخوارزمية Svanberg.) CCSAQ هي خوارزمية ذات صلة من ورقة Svanberg تستخدم تقريبًا تربيعيًا محليًا بدلاً من نموذج MMA الأكثر تعقيدًا؛ عادة ما يكون لهاتين الخوارزميتين معدلات تقارب متشابهة. تدعم خوارزمية NLOPT_LD_MMA كلاً من التحسين المقيد بالحدود وغير المقيد، وتدعم أيضًا عددًا تعسفيًا (m) من قيود عدم المساواة غير الخطية (وليس المساواة) كما هو موضح أعلاه.
NLOPT_LD_SLSQP
تحسين محلي (L) يعتمد على المشتقات (D) باستخدام البرمجة التربيعية المتتابعة وتحديثات BFGS، تدعم قيود عدم المساواة والمساواة غير الخطية التعسفية، بناءً على شفرة Dieter Kraft (1988) المكيّفة للاستخدام من قبل مشروع SciPy. لاحظ أن هذه الخوارزمية تستخدم طرق المصفوفات الكثيفة التي تتطلب تخزينًا بمقدار O(n^2) ووقتًا بمقدار O(n^3)، مما يجعلها أقل عملية للمشاكل التي تتضمن أكثر من بضعة آلاف من المعلمات.
NLOPT_LN_COBYLA
تحسين محلي (L) خالي من المشتقات (N) باستخدام خوارزمية COBYLA بواسطة Powell (Constrained Optimization BY Linear Approximations). تدعم خوارزمية NLOPT_LN_COBYLA كلاً من التحسين المقيد بالحدود وغير المقيد، وتدعم أيضًا عددًا تعسفيًا (m) من قيود عدم المساواة/المساواة غير الخطية كما هو موضح أعلاه.
NLOPT_LN_NEWUOA
تحسين محلي (L) خالي من المشتقات (N) باستخدام متغير من خوارزمية NEWUOA بواسطة Powell، بناءً على تقريبات تربيعية متعاقبة لدالة الهدف. لقد عدلنا الخوارزمية لدعم قيود الحدود. الأصل

DESCRIPTION

The NLopt library is a collection of nonlinear optimization algorithms, and a common interface to them. NLopt is designed to handle problems where the objective function and/or constraints are nonlinear, and may not be differentiable.

NLopt is a C library, but it can be used from many other languages.

OBJECTIVE FUNCTION

To perform optimization, you must first define an objective function. This function should take the dimension n of the problem, the current point x, and a pointer grad where the gradient should be stored (if available), and return the value of the objective function at x. If the gradient is not required or available, you can pass NULL for grad.

The objective function is declared as:

typedef double (*nlopt_func)(unsigned n, const double *x, double *grad, void *f_data);

You set the objective function using either nlopt_set_min_objective (for minimization) or nlopt_set_max_objective (for maximization).

The f_data argument is a pointer to arbitrary user data that is passed to your objective function.

BOUND CONSTRAINTS

You can set lower and/or upper bounds on the variables using nlopt_set_lower_bounds, nlopt_set_upper_bounds, or nlopt_set_bounds. These functions take a pointer to an array of doubles of length n (the dimension of the problem).

If you wish to indicate that a variable has no bound in one direction, you should use the special values NLOPT_NEG_INFINITY or NLOPT_POS_INFINITY. For example, to set only lower bounds, you can pass NULL for the upper bounds array.

NONLINEAR CONSTRAINTS

NLopt supports both equality and inequality constraints. Constraints are defined using the same nlopt_func type as the objective function.

An equality constraint is of the form f(x) = 0, and an inequality constraint is of the form f(x) >= 0.

You add constraints using nlopt_add_equality_constraint and nlopt_add_inequality_constraint. The tol parameter specifies the tolerance for the constraint.

The tolerance for all equality constraints can be set globally using nlopt_set_equality_tolerance, and similarly for inequality constraints using nlopt_set_inequality_tolerance.

NLopt also supports preconditioner constraints via nlopt_add_precondКонstraint and nlopt_set_precondКонstraint_tol. These are used in conjunction with certain iterative algorithms to accelerate convergence.

ALGORITHMS

NLopt provides a variety of optimization algorithms. These are specified by the nlopt_algorithm enumeration type when creating an optimizer object with nlopt_create.

Common algorithms include:

NLOPT_LNSEARCH
Line-search algorithms (e.g., Conjugate Gradient, BFGS).
NLOPT_NLSEARCH
Non-linear search algorithms (e.g., Nelder-Mead).
NLOPT_DIRECT
DIRECT (DIviding RECTangles).
NLOPT_DNS
DIRECT-similar algorithm with deterministic bounds.
NLOPT_ORIG_DIRECT
Original DIRECT algorithm.
NLOPT_MLSL
Multi-Level Single-Linkage algorithm (global optimization).
NLOPT_SLSQP
Sequential Least Squares Programming.
NLOPT_COBYLA
Constrained Optimization BY Linear Approximation.
NLOPT_SCHWEFEL
Schwefel function based.
NLOPT_NEWUOA
New Unconstrained Optimization algorithm.
NLOPT_ISRES
Improved Stochastic Ranking Evolution Strategy.
NLOPT_AUGLAG
Augmented Lagrangian algorithm.
NLOPT_ST൫
Stochastic Distributed Evolution Strategy.

STOPPING CRITERIA

Optimization stops when one of the stopping criteria is met. You can set these criteria using:

nlopt_set_stop_tol(opt, NLOPT_STOP_VALUE, tol)
Stop when the objective function value is within tol of the optimal value.
nlopt_set_stop_tol(opt, NLOPT_STOP_FTOL_REL, tol)
Stop when the relative change in the objective function value is less than tol.
nlopt_set_stop_tol(opt, NLOPT_STOP_FTOL_ABS, tol)
Stop when the absolute change in the objective function value is less than tol.
nlopt_set_stop_tol(opt, NLOPT_STOP_XTOL_REL, tol)
Stop when the relative change in the parameter vector x is less than tol.
nlopt_set_stop_tol(opt, NLOPT_STOP_XTOL_ABS, tol)
Stop when the absolute change in the parameter vector x is less than tol.
nlopt_set_stop_tol(opt, NLOPT_STOP_MAXEVAL, tol)
Stop after at most tol function evaluations.
nlopt_set_stop_value(opt, val)
Stop when the objective function value reaches val.

RETURN VALUE

The functions return an nlopt_result code indicating success or failure. Possible return values include:

NLOPT_SUCCESS
Optimization completed successfully.
NLOPT_FAILURE
Generic failure.
NLOPT_INVALID_ARGS
Invalid arguments were provided.
NLOPT_OUT_OF_MEMORY
Out of memory.
NLOPT_ROUNDOFF
Roundoff error was detected.
NLOPT_FORCED_STOP
The optimization was stopped by the user (e.g., via a user-defined stop criterion).
NLOPT_BAD_FUNCALC
The objective function or constraint function returned an invalid value (e.g., NaN or infinity).
NLOPT_MAXTIME_EXCEEDED
The maximum time limit was exceeded.

The nlopt_minimize and nlopt_optimize functions return the final value of the objective function in the minf argument.

LOCAL OPTIMIZER

Some algorithms, particularly global optimization algorithms like MLSL, use a local optimizer internally. You can specify the local optimizer to be used via the nlopt_set_local_optimizer function.

nlopt_opt nlopt_set_local_optimizer(nlopt_opt opt,
nlopt_opt local_opt);

INITIAL STEP SIZE

For some algorithms, the initial step size (or search radius) is important. You can set this using:

nlopt_result nlopt_set_initial_step(nlopt_opt opt,
const double *dx);

Here, dx is an array of length n (the dimension of the problem) containing the initial step sizes for each dimension. If you pass NULL, a default value is used.

For some algorithms, you can also set a fixed radius for the initial search using:

nlopt_result nlopt_fixed_radius(nlopt_opt opt,
double radius);

STOCHASTIC POPULATION

Several of the stochastic search algorithms (e.g., CRS, MLSL, and ISRES) start by generating some initial "population" of random points x. By default, this initial population size is chosen heuristically in some algorithm-specific way, but the initial population can by changed by calling:

nlopt_result nlopt_set_population(nlopt_opt opt,
unsigned pop);

(A pop of zero implies that the heuristic default will be used.)

PSEUDORANDOM NUMBERS

For stochastic optimization algorithms, we use pseudorandom numbers generated by the Mersenne Twister algorithm, based on code from Makoto Matsumoto. By default, the seed for the random numbers is generated from the system time, so that they will be different each time you run the program. If you want to use deterministic random numbers, you can set the seed by calling:

void nlopt_srand(unsigned long seed);

Some of the algorithms also support using low-discrepancy sequences (LDS), sometimes known as quasi-random numbers. NLopt uses the Sobol LDS, which is implemented for up to 1111 dimensions.
