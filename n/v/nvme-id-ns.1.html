nvme-id-ns(1)

الحزمة: nvme-cli

التراخيص: GPL-2.0-or-later

NVME-ID-NS(1) دليل NVMe NVME-ID-NS(1)

اسم

nvme-id-ns - إرسال NVMe Identify Namespace، إرجاع النتيجة والهيكل

الملخص

nvme id-ns <device> [--vendor-specific | -v] [--raw-binary | -b]
                        [--namespace-id=<nsid> | -n <nsid>] [--force]
                        [--human-readable | -H]
                        [--output-format=<fmt> | -o <fmt>] [--verbose | -v]

الوصف

بالنسبة لجهاز NVMe المحدد، يرسل أمر تحديد مساحة الاسم ويوفر النتيجة والهيكل المُرجع.

المعلمة <device> إلزامية وقد تكون إما جهاز حرف NVMe (مثال: /dev/nvme0)، أو جهاز كتلة مساحة اسم (مثال: /dev/nvme0n1). إذا تم توفير جهاز الحرف، فإن خيار '--namespace-id' إلزامي، وإلا فإنه سيستخدم معرف مساحة الاسم (ns-id) لمساحة الاسم لجهاز الكتلة الذي فتحته. بالنسبة لأجهزة الكتلة، يمكن تجاوز معرف مساحة الاسم المستخدم بنفس الخيار.

عند النجاح، قد يتم إرجاع الهيكل بإحدى الطرق العديدة اعتمادًا على أعلام الخيارات؛ قد يتم تحليل الهيكل بواسطة البرنامج أو قد تتم طباعة المخزن المؤقت الخام إلى الإخراج القياسي.

الخيارات

-n <nsid>, --namespace-id=<nsid>

استرداد هيكل تحديد مساحة الاسم لمعرف مساحة الاسم المحدد. هذا مطلوب لأجهزة الأحرف، أو يتجاوز معرف مساحة الاسم الخاص بجهاز الكتلة إذا تم توفيره. إذا كان المتحكم يدعم قدرة إدارة مساحة الاسم وتم توفير 0xFFFFFFFF، فإن المتحكم يُرجع هيكل تحديد مساحة الاسم الذي يحدد القدرات المشتركة عبر مساحات الأسماء للمتحكم.

--force

طلب من المتحكم إرجاع هيكل تحديد مساحة الاسم حتى لو لم تكن مساحة الاسم مرفقة بالمتحكم. هذا صالح فقط للمتحكمات في الإصدار 1.2 أو أحدث. قد تفسر المتحكمات ذات الإصدار الأقل من هذا الأمر بشكل غير صحيح.

-b, --raw-binary

طباعة المخزن المؤقت الخام إلى الإخراج القياسي. لا يتم تحليل الهيكل بواسطة البرنامج. هذا يتجاوز الخيارات الخاصة بالبائع والقابلة للقراءة البشرية.

-V, --vendor-specific

بالإضافة إلى تحليل الحقول المعروفة، سيقوم هذا الخيار بتفريغ المنطقة الخاصة بالبائع من الهيكل في شكل سداسي عشري مع تفسير ASCII.

-H, --human-readable

سيقوم هذا الخيار بتحليل وتنسيق العديد من حقول البتات إلى تنسيقات قابلة للقراءة البشرية.

-o <fmt>, --output-format=<fmt>

تعيين تنسيق الإبلاغ إلى normal، json أو binary. يمكن استخدام تنسيق إخراج واحد فقط في كل مرة.

-v, --verbose

زيادة تفاصيل المعلومات في الإخراج.

أمثلة

•جعل البرنامج يفسر المخزن المؤقت المُرجع ويعرض الحقول المعروفة بتنسيق قابل للقراءة البشرية: 
# nvme id-ns /dev/nvme0n1
•إذا كنت تستخدم جهاز الحرف أو تجاوز معرف مساحة الاسم: 
# nvme id-ns /dev/nvme0 -n 1
# nvme id-ns /dev/nvme0n1 -n 1
# nvme id-ns /dev/nvme0 --namespace-id=1
•بالإضافة إلى عرض الحقول المعروفة، اجعل البرنامج يعرض الحقل الفريد للبائع: 
# nvme id-ns /dev/nvme0n1 --vendor-specific
# nvme id-ns /dev/nvme0n1 -V

سيقوم ما سبق بتفريغ المخزن المؤقت 'vs' بالنظام السداسي العشري لأنه لا يعرف كيفية تفسيره.

•اجعل البرنامج يُرجع الهيكل الخام بالنظام الثنائي: 
# nvme id-ns /dev/nvme0n1 --raw-binary > id_ns.raw
# nvme id-ns /dev/nvme0n1 -b > id_ns.raw

من المحتمل أن يكون من السيء عدم إعادة توجيه الإخراج القياسي عند استخدام هذا الوضع.

•بدلاً من ذلك، قد ترغب في إرسال البيانات إلى برنامج آخر يمكنه تحليل المخزن المؤقت الخام. 
# nvme id-ns /dev/nvme0n1 --raw-binary | nvme_parse_id_ns

يمكن أن يكون برنامج التحليل في المثال أعلاه برنامجًا يعرض الهيكل بالطريقة التي تفضلها. البرنامج التالي هو مثال على ذلك يمكنه تحليله ويمكنه قبول الإخراج عبر أنبوب (|) كما هو موضح في المثال أعلاه، أو يمكنك 'cat' مخزن إخراج محفوظ إليه.

/* File: nvme_parse_id_ns.c */
#include <linux/nvme.h>
#include <stdio.h>
#include <unistd.h>
int main(int argc, char **argv)
{
        unsigned char buf[sizeof(struct nvme_id_ns)];
        struct nvme_id_ns *ns = (struct nvme_id_ns *)buf;
        if (read(STDIN_FILENO, buf, sizeof(buf)))
                return 1;
        printf("nsze : %#llx\n", ns->nsze);
        printf("ncap : %#llx\n", ns->ncap);
        return 0;
}
