cmd

التحقق من GitHub

source = "github"

تحقق من GitHub https://github.com/
للتحديثات. الإصدار المُعاد هو بتنسيق التاريخ %Y%m%d.%H%M%S، على سبيل المثال 20130701.012212، ما لم يتم استخدام use_latest_release أو use_max_tag أو use_max_release. انظر أدناه.

github
مستودع GitHub، مع المؤلف، على سبيل المثال lilydjwg/nvchecker.
branch
أي فرع يجب تتبعه؟ الافتراضي: افتراضي المستودع.
path
سيتم إرجاع الالتزامات التي تحتوي على مسار الملف هذا فقط.
host
اسم المضيف لمثيل GitHub المستضاف ذاتيًا.
use_latest_release
اضبط هذا على true للتحقق من أحدث إصدار على GitHub.

إصدارات GitHub ليست مثل علامات git. سترى أسماء إصدارات كبيرة ووصفًا في صفحة الإصدارات لمثل هذه الإصدارات، على سبيل المثال zfsonlinux/zfs's https://github.com/zfsonlinux/zfs/releases ، وتلك الصغيرة مثل nvchecker's https://github.com/lilydjwg/nvchecker/releases

هي مجرد علامات git يجب استخدام use_max_tag أدناه.

ستعيد اسم علامة الإصدار بدلاً من التاريخ. (لأسباب تاريخية لا يعيد اسم الإصدار. انظر أدناه للتغيير.)

use_max_release
اضبط هذا على true للتحقق من أقصى إصدار على GitHub. هذا الخيار يعيد الأكبر مرتبًا حسب خيار sort_version_key. سيعيد اسم العلامة بدلاً من التاريخ.
use_release_name
عندما يكون use_latest_release أو use_max_release هو true، فإن ضبط هذا على true سيجعل nvchecker يعيد اسم الإصدار بدلاً من اسم العلامة.
include_prereleases
عندما يكون use_latest_release أو use_max_release هو true، اضبط هذا على true لأخذ الإصدارات الأولية في الاعتبار.

هذا يعيد أسماء الإصدارات (وليس أسماء العلامات).

يتطلب هذا رمزًا لأنه يستخدم واجهة برمجة تطبيقات GraphQL v4.

use_latest_tag
اضبط هذا على true للتحقق من أحدث علامة على GitHub.

يتطلب هذا رمزًا لأنه يستخدم واجهة برمجة تطبيقات GraphQL v4.

query
عندما يكون use_latest_tag هو true، يضبط هذا استعلامًا للعلامة. لا توثق GitHub طريقة المطابقة الدقيقة.
use_max_tag
اضبط هذا على true للتحقق من أقصى علامة على GitHub. على عكس use_max_release، يتضمن هذا الخيار العلامات المشروحة والخفيفة، ويعيد الأكبر مرتبًا حسب خيار sort_version_key. سيعيد اسم العلامة بدلاً من التاريخ.
token
رمز ترخيص شخصي يستخدم لاستدعاء واجهة برمجة التطبيقات.

قد تكون هناك حاجة إلى رمز ترخيص لاستخدام use_latest_tag أو include_prereleases أو لطلب التحديثات بشكل متكرر أكثر من المسموح به للمستخدمين المجهولين.

لتعيين رمز ترخيص، يمكنك تعيين:

  • الخيار token
  • إدخال في ملف المفاتيح للمضيف (على سبيل المثال، github.com)
  • إدخال في ملف netrc الخاص بك للمضيف

يدعم هذا المصدر خيارات القائمة عندما يتم تعيين use_max_tag أو use_max_release.

Sources

Here is a list of all supported sources:

When you are using a source that requires an API token, you can configure it by setting the token option, or an entry in the keyfile for the host (e.g. gitlab.com), or an entry in your netrc file for the host. In most cases, you don't need to specify an API token when using an authorization token. However, it might be useful if you want to make many queries to the API, to avoid hitting the API rate limit. In such cases, an API token is required.

Check GitLab

source = "gitlab"

Check GitLab https://gitlab.com/ for updates. The version returned is in date format %Y%m%d, e.g. 20130701, unless use_max_tag is used. See below.

gitlab
The gitlab repository, with author, e.g. Deepin/deepin-music.
branch
Which branch to track?
use_max_tag
Set this to true to check for the max tag on GitLab. Will return the biggest one sorted by old pkg_resources.parse_version. Will return the tag name instead of date.
host
Hostname for self-hosted GitLab instance.
token
GitLab authorization token used to call the API.

To set an authorization token, you can set:

  • the token option
  • an entry in the keyfile for the host (e.g. gitlab.com)
  • an entry in your netrc file for the host

This source supports List Options when use_max_tag is set.
