nvidia-settings(1)

قد يسبقها اختياريًا اسم شاشة X أو وحدة معالجة الرسومات (GPU) للصفحة، متبوعًا بفاصلة. مثال:


--page="GPU 0 - (Quadro 6000), PowerMizer"

سيتم استخدام أول صفحة يتطابق اسمها مع الوسيط PAGE. افتراضيًا، يتم عرض صفحة "System Information".

-L, --list-targets-only
عند إجراء استعلام عن سمة (من خيار سطر الأوامر '--query') أو تعيين سمة (من خيار سطر الأوامر '--assign' أو عند تحميل ملف ~/.nvidia-settings-rc)، يقوم nvidia-settings بتحديد هدف واحد أو أكثر لتحديد/تعيين السمة عليه.

سيؤدي الخيار '--list-targets-only' إلى قيام nvidia-settings بسرد الأهداف التي كان سيتم تنفيذ عملية الاستعلام/التعيين عليها، دون تنفيذ العملية (العمليات) فعليًا، ثم الخروج.

-w, --write-config, --no-write-config
احفظ ملف التكوين عند الخروج (ممكّن افتراضيًا).
-i, --use-gtk2
فرض استخدام nvidia-settings لمكتبة GTK+ 2 لواجهة المستخدم الرسومية إذا كانت واجهة المستخدم مطلوبة. هذا الخيار متاح فقط على الأنظمة التي تدعم فيها nvidia-settings واجهات المستخدم GTK+ 2 و GTK+ 3.
-I GTK-LIBRARY, --gtk-library=GTK-LIBRARY
حدد مكتبة واجهة المستخدم الرسومية المراد استخدامها إذا كانت هناك حاجة لواجهة مستخدم nvidia-settings. قد تكون هذه القيمة هي الموقع الدقيق للمكتبة أو قد تكون الدليل الذي يحتوي على المكتبة المسماة بشكل مناسب. إذا كان هذا هو الموقع الدقيق، فسيتم تجاهل خيار 'use-gtk2'.

1. تخطيط واجهة المستخدم الرسومية لـ nvidia-settings

تم تنظيم واجهة المستخدم الرسومية لـ nvidia-settings بقائمة من الفئات المختلفة على الجانب الأيسر. لا يمكن تحديد سوى إدخال واحد في القائمة في كل مرة، وتتحكم الفئة المحددة في "الصفحة" التي يتم عرضها على الجانب الأيمن من واجهة المستخدم الرسومية لـ nvidia-settings.

تم تنظيم قائمة الفئات في شجرة: تحتوي كل شاشة X على الفئات الفرعية ذات الصلة أسفلها. وبالمثل، تحتوي فئة "Display Devices" الخاصة بالشاشة على جميع أجهزة العرض الممكّنة أسفلها. بجانب كل شاشة X، الفئة الرئيسية الأخرى هي "nvidia-settings Configuration"، والتي تقوم بتكوين سلوك تطبيق nvidia-settings نفسه.

على طول الجزء السفلي من واجهة المستخدم الرسومية لـ nvidia-settings، من اليسار إلى اليمين، يوجد:

1)
شريط حالة يشير إلى آخر خيار تم تعديله؛
2)
زر "Help" الذي يقوم بتبديل عرض نافذة مساعدة توفر شرحًا مفصلاً للخيارات المتاحة في الصفحة الحالية؛ و
3)
زر "Quit" للخروج من nvidia-settings.

يتم تطبيق معظم الخيارات في جميع أنحاء nvidia-settings على الفور. الاستثناءات البارزة هي خيارات OpenGL التي يتم قراءتها فقط بواسطة OpenGL عند بدء تشغيل تطبيق OpenGL.

التفاصيل حول الخيارات في كل صفحة من nvidia-settings متاحة في نافذة المساعدة.

2. كيف يتفاعل OpenGL مع nvidia-settings

عند بدء تشغيل تطبيق OpenGL، يقوم بتنزيل القيم الحالية من مشغل X، ثم يقرأ البيئة (انظر APPENDIX E: OPENGL ENVIRONMENT VARIABLE SETTINGS في README). تتجاوز الإعدادات من خادم X القيم الافتراضية لـ OpenGL، وتتجاوز الإعدادات من البيئة القيم من خادم X.

على سبيل المثال، افتراضيًا يستخدم OpenGL إعداد FSAA الذي طلبه التطبيق (عادةً، لا تطلب التطبيقات أي FSAA). سيؤدي إعداد FSAA المحدد في nvidia-settings إلى تجاوز طلب تطبيق OpenGL. وبالمثل، فإن متغير البيئة __GL_FSAA_MODE سيتجاوز إعداد FSAA للتطبيق، وكذلك أي إعداد FSAA محدد في nvidia-settings.

لاحظ أن تطبيق OpenGL يسترد الإعدادات من خادم X فقط عند بدء تشغيله، لذلك إذا قمت بإجراء تغيير على قيمة OpenGL في nvidia-settings، فسيتم تطبيقه فقط على تطبيقات OpenGL التي يتم تشغيلها بعد تلك النقطة الزمنية.

3. تحميل الإعدادات تلقائيًا

لا يحتفظ مشغل NVIDIA X بالقيم التي تم تعيينها باستخدام nvidia-settings بين تشغيل خادم X (أو حتى بين تسجيل الدخول والخروج من X، مع xdm(1)، gdm، أو kdm). هذا متعمد، لأن المستخدمين المختلفين قد يكون لديهم تفضيلات مختلفة، وبالتالي يتم تخزين هذه الإعدادات على أساس كل مستخدم في ملف تكوين مخزن في الدليل الرئيسي للمستخدم.

اسم ملف التكوين هو ~/.nvidia-settings-rc. يمكنك تحديد اسم ملف تكوين مختلف باستخدام خيار سطر الأوامر --config.

بعد تشغيل nvidia-settings مرة واحدة وإنشاء ملف تكوين، يمكنك بعد ذلك تشغيل:

nvidia-settings --load-config-only

في أي وقت في المستقبل لتحميل هذه الإعدادات إلى خادم X مرة أخرى. على سبيل المثال، يمكنك وضع الأمر أعلاه في ملف ~/.xinitrc الخاص بك بحيث يتم تطبيق إعداداتك تلقائيًا عند تسجيل الدخول إلى X.

قد يبدو ملف .xinitrc الخاص بك، والذي يتحكم في تطبيقات X التي يجب بدء تشغيلها عند تسجيل الدخول إلى X (أو بدء تشغيل startx)، شيئًا كهذا: 

     nvidia-settings --load-config-only &
     xterm &
     evilwm
أو: 
     nvidia-settings --load-config-only &
     gnome-session
إذا لم يكن لديك ملف ~/.xinitrc بالفعل، فمن المحتمل أن يستخدم xinit(1) ملف xinitrc على مستوى النظام. هذا الملف على مستوى النظام موجود عادةً هنا: 
     /etc/X11/xinit/xinitrc
لاستخدامه، ولكن أيضًا لجعل nvidia-settings يقوم بتحميل إعداداتك، يمكنك إنشاء ملف ~/.xinitrc بالمحتويات التالية: 
     nvidia-settings --load-config-only &
     . /etc/X11/xinit/xinitrc
قد يختار مسؤولو النظام وضع أمر تحميل nvidia-settings مباشرة في البرنامج السكريحري xinitrc الخاص بالنظام.

يرجى الرجوع إلى صفحة الدليل لـ xinit(1) لمزيد من التفاصيل حول تكوين ملف ~/.xinitrc الخاص بك.

4. واجهة سطر الأوامر

تمتلك nvidia-settings واجهة سطر أوامر غنية: يمكن الاستعلام عن جميع السمات التي يمكن معالجتها باستخدام واجهة المستخدم الرسومية وتعيينها من سطر الأوامر. تتطابق صيغة سطر الأوامر للاستعلام عن السمات وتعيينها مع صيغة ملف التكوين .nvidia-settings-rc.

يمكن استخدام الخيار --query للاستعلام عن القيمة الحالية للسمات. سيبلغ هذا أيضًا عن القيم الصالحة للسمة. يمكنك تشغيل nvidia-settings --query all للحصول على قائمة كاملة بالسمات المتاحة، وما هي القيمة الحالية، وما هي القيم الصالحة للسمة، وعبر أي أنواع أهداف (مثل شاشات X، وحدات معالجة الرسومات) يمكن معالجة السمات. بالإضافة إلى ذلك، يمكن تحديد سمات فردية بهذا الشكل: 

        nvidia-settings --query Overlay
يمكن إضافة اسم سمة مسبقًا باسم شاشة X وشرطة مائلة للإشارة إلى شاشة X مختلفة؛ مثل: 
        nvidia-settings --query localhost:0.0/Overlay
يمكن أيضًا إضافة اسم سمة مسبقًا برقم الشاشة وشرطة مائلة: 
        nvidia-settings --query 0/Overlay
في هذه الحالة، سيتم استخدام شاشة X الافتراضية، ولكن يمكنك الإشارة إلى شاشة X التي يجب توجيه الاستعلام إليها (إذا كان خادم X الخاص بك يحتوي على شاشات X متعددة). إذا لم يتم تحديد شاشة X، فسيتم الاستعلام عن قيمة السمة لجميع الأهداف الصالحة للسمة (مثل وحدات معالجة الرسومات، شاشات العرض X، إلخ).

يمكن معالجة السمات عبر "أنواع الأهداف". يشير نوع الهدف إلى الكائن الذي يتم الاستعلام عنه عند الاستعلام عن سمة. نوع الهدف الافتراضي هو شاشة X، ولكن أنواع الأهداف الممكنة الأخرى هي وحدات معالجة الرسومات (GPUs)، وأجهزة Frame Lock، وأنظمة الحوسبة المرئية (Visual Computing Systems)، والمراوح، ومستشعرات الحرارة، وأجهزة الإرسال والاستقبال ثلاثية الأبعاد (3D Vision Pro Transceivers)، وأجهزة العرض.

تمنحك أنواع الأهداف مستويات مختلفة من الدقة لتنفيذ الاستعلامات والتعيينات. نظرًا لأن شاشات X يمكن أن تمتد عبر وحدات معالجة رسومات متعددة (في حالة Xinerama، أو SLI)، ويمكن أن توجد شاشات X متعددة على نفس وحدة معالجة الرسومات، فمن المفيد أحيانًا معالجة السمات حسب وحدة معالجة الرسومات بدلاً من شاشة X.

يتم احتواء مواصفات الهدف داخل أقواس وقد تتكون من اسم نوع الهدف، ونقطتين فوق بعضهما البعض، ومعرف الهدف. يمكن أن يكون اسم نوع الهدف أحد screen, gpu, framelock, fan, thermalsensor, svp, أو dpy; معرف الهدف هو الفهرس في قائمة الأهداف (لذلك النوع الهدف). يمكن استخدام مواصفات الهدف في أي مكان تستخدم فيه شاشة X في أوامر الاستعلام والتعيين؛ يمكن استخدام مواصفات الهدف إما بمفردها على الجانب الأيسر من الشرطة المائلة، أو كجزء من اسم شاشة X.

على سبيل المثال، تعالج الاستعلامات التالية شاشة X 0 على localhost: 

        nvidia-settings --query 0/VideoRam
        nvidia-settings --query localhost:0.0/VideoRam
        nvidia-settings --query [screen:0]/VideoRam
        nvidia-settings --query localhost:0[screen:0]/VideoRam
لمعالجة وحدة معالجة الرسومات 0 بدلاً من ذلك، يمكنك استخدام أي من: 
        nvidia-settings --query [gpu:0]/VideoRam
        nvidia-settings --query localhost:0[gpu:0]/VideoRam
لاحظ أنه إذا كانت مواصفات الهدف موجودة، فستتجاوز أي شاشة X محددة في اسم العرض كهدف للمعالجة. على سبيل المثال، سيقوم الاستعلام التالي بمعالجة وحدة معالجة الرسومات 0، وليس شاشة X 1: 
nvidia-settings --query localhost:0.1[gpu:0]/VideoRam

يمكن استخدام اسم هدف بدلاً من معرف الهدف، وفي هذه الحالة يتم معالجة جميع الأهداف ذات الأسماء المتطابقة.

على سبيل المثال، يمكن الاستعلام عن DigitalVibrance لجهاز العرض DVI-I-1 على النحو التالي: 

nvidia-settings --query [dpy:DVI-I-1]/DigitalVibrance

        nvidia-settings --query FSAA
              nvidia-settings --query 0/FSAA
              nvidia-settings --query alpha.example.org:0/FSAA
In the first two cases, the default X Display will be used, in the second case, the screen from the default X Display can be overridden, and in the third case, the entire default X Display can be overridden. The same possibilities are available in the ~/.nvidia-settings-rc configuration file. For example, in a computer lab environment, you might log into any of multiple workstations, and your home directory is NFS mounted to each workstation. In such a situation, you might want your ~/.nvidia-settings-rc file to be applicable to all the workstations. Therefore, you would not want your config file to qualify each attribute with an X Display Name. Leave the "Include X Display Names in the Config File" option unchecked on the nvidia-settings Configuration page (this is the default). There may be cases when you do want attributes in the config file to be qualified with the X Display name. If you know what you are doing and want config file attributes to be qualified with an X Display, check the "Include X Display Names in the Config File" option on the nvidia-settings Configuration page. These two X connections do not need to be to the same X server. For example, you might run nvidia-settings on the computer alpha.example.org, export the display to the computer beta.example.org, but be configuring the X server on the computer gamma.example.org: 
        nvidia-settings --display=beta.example.org:0 \
            --ctrl-display=gamma.example.org:0
If --ctrl-display is not specified, then the X Display to control is what --display indicates. If --display is also not specified, then the $DISPLAY environment variable is used. Note, however, that you will need to have X permissions configured such that you can establish an X connection from the computer on which you are running nvidia-settings (alpha.example.org) to the computer where you are displaying the GUI (beta.example.org) and the computer whose X Display you are configuring (gamma.example.org). The simplest, most common, and least secure mechanism to do this is to use 'xhost' to allow access from the computer on which you are running nvidia-settings. 
        (issued from beta.example.org)
              xhost +alpha.example.org
              (issued from gamma.example.org)
              xhost +alpha.example.org
This will allow all X clients run on alpha.example.org to connect and display on beta.example.org's X server and configure gamma.example.org's X server. Please see the xauth(1) and xhost(1) man pages, or refer to your system documentation on remote X applications and security.
