Chains are containers for rules. They exist in two kinds, base chains and regular chains. A base chain is an entry point for packets from the networking stack, a regular chain may be used as jump target and is used for better rule organization. Regular chains can be anonymous, see VERDICT STATEMENT examples for details.

add إضافة سلسلة جديدة في الجدول المحدد. عند تحديد خطاف وقيمة أولوية، يتم إنشاء السلسلة كسلسلة أساسية وربطها بمكدس الشبكات.
create على غرار أمر add، ولكن يعيد خطأ إذا كانت السلسلة موجودة بالفعل.
delete حذف السلسلة المحددة. يجب ألا تحتوي السلسلة على أي قواعد أو يتم استخدامها كهدف للقفز.
destroy حذف السلسلة المحددة، ولا تفشل إذا لم تكن موجودة. يجب ألا تحتوي السلسلة على أي قواعد أو يتم استخدامها كهدف للقفز.
rename إعادة تسمية السلسلة المحددة.
list سرد جميع قواعد السلسلة المحددة.
flush مسح جميع قواعد السلسلة المحددة.

بالنسبة للسلاسل الأساسية، تكون معلمات type و hook و priority إلزامية.

جدول 5. أنواع السلاسل المدعومة

النوع العائلات الخطافات الوصف
filter all all نوع سلسلة قياسي للاستخدام عند الشك.
nat ip, ip6, inet prerouting, input, output, postrouting تقوم سلاسل هذا النوع بترجمة العناوين الأصلية بناءً على إدخالات conntrack. الرزمة الأولى فقط للاتصال تمر عبر هذه السلسلة - عادةً ما تحدد قواعدها تفاصيل إدخال conntrack الذي تم إنشاؤه (بيانات NAT على سبيل المثال).
route ip, ip6, inet output إذا مرت رزمة عبر سلسلة من هذا النوع وكانت على وشك القبول، يتم إجراء بحث توجيه جديد إذا تم تغيير أجزاء ذات صلة من رأس IP. هذا يسمح بتنفيذ محددات توجيه السياسة في nftables على سبيل المثال.

بصرف النظر عن الحالات الخاصة الموضحة أعلاه (على سبيل المثال، نوع nat لا يدعم خطاف forward أو نوع route يدعم فقط خطاف output)، هناك ثلاث ملاحظات إضافية جديرة بالملاحظة:

•عائلة netdev تدعم مجموعتين فقط، وهما نوع filter مع خطاف ingress ونوع filter مع خطاف egress. تتطلب السلاسل الأساسية في هذه العائلة أيضًا أن يكون المعلمة device موجودة لأنها توجد لكل واجهة فقط.
•عائلة arp تدعم فقط خطافات input و output، وكلاهما في سلاسل من نوع filter.
•تدعم عائلة inet أيضًا خطاف ingress (منذ نواة Linux 5.10)، لتصفية حزم IPv4 و IPv6 في نفس موقع خطاف ingress الخاص بـ netdev. يسمح خطاف inet هذا بمشاركة المجموعات والخرائط بين خطافات prerouting و input و forward و output و postrouting القياسية وهذا الخطاف ingress.

تقبل المعلمة device اسم واجهة شبكة كسلسلة نصية، وهي مطلوبة عند إضافة سلسلة أساسية تقوم بتصفية حركة المرور على خطافات ingress أو egress. ستقوم أي سلاسل ingress أو egress بتصفية حركة المرور فقط من الواجهة المحددة في المعلمة device.

تقبل المعلمة priority قيمة عدد صحيح موقعة أو اسم أولوية قياسي يحدد الترتيب الذي يتم به اجتياز السلاسل التي لها نفس قيمة hook. الترتيب تصاعدي، أي أن قيم الأولوية الأقل لها الأسبقية على القيم الأعلى.

مع سلاسل نوع nat، يوجد حد أدنى للاستبعاد قدره -200 لقيم priority، لأن خطافات conntrack بهذه الأولوية وتتطلب NAT ذلك.

يمكن استبدال قيم الأولوية القياسية بأسماء سهلة التذكر. لا تكون جميع الأسماء منطقية في كل عائلة مع كل خطاف (انظر مصفوفات التوافق أدناه)، ولكن لا يزال يمكن استخدام قيمتها الرقمية لتحديد أولويات السلاسل.

تستند هذه الأسماء والقيم إلى أولويات xtables عند تسجيل سلاسلها الافتراضية.

تستخدم معظم العائلات نفس القيم، ولكن bridge يستخدم قيمًا مختلفة عن غيرها. انظر الجداول التالية التي تصف القيم والتوافق.

يمكن أيضًا تحقيق التعبيرات الحسابية الأساسية (الجمع والطرح) باستخدام هذه الأسماء القياسية لتسهيل تحديد الأولويات النسبية، على سبيل المثال، mangle - 5 تعني -155. ستتم طباعة القيم أيضًا بهذه الطريقة حتى تكون القيمة ليست أبعد من 10 عن القيمة القياسية.

تسمح السلاسل الأساسية أيضًا بتعيين policy السلسلة، أي ما يحدث للحزم التي لم يتم قبولها أو رفضها صراحةً في القواعد الموجودة. قيم السياسة المدعومة هي accept (وهو الافتراضي) أو drop.

القواعد

{add | insert} rule [family] table chain [handle handle | index index] statement ... [comment comment]
replace rule [family] table chain handle handle statement ... [comment comment]
{delete | reset} rule [family] table chain handle handle
destroy rule [family] table chain handle handle
reset rules [family] [table [chain]]

تتم إضافة القواعد إلى السلاسل في الجدول المحدد. إذا لم يتم تحديد العائلة، يتم استخدام عائلة ip. تتكون القواعد من نوعين من المكونات وفقًا لمجموعة من القواعد النحوية: التعابير والبيانات.

تدعم أوامر add و insert محدد موقع اختياري، وهو إما handle أو index (يبدأ من الصفر) لقاعدة موجودة. داخليًا، يتم دائمًا تحديد مواقع القواعد بواسطة handle ويتم إجراء الترجمة من index في مساحة المستخدم. هذا له آثار محتملة في حالة حدوث تغيير متزامن في مجموعة القواعد بعد انتهاء الترجمة: قد يتغير فهرس القاعدة الفعلي إذا تم إدراج قاعدة أو حذفها قبل القاعدة المشار إليها. إذا تم حذف القاعدة المشار إليها، يتم رفض الأمر بواسطة النواة كما لو تم تقديم handle غير صالح.

comment هو كلمة واحدة أو سلسلة متعددة الكلمات محاطة بعلامات اقتباس مزدوجة (") يمكن استخدامها لتدوين ملاحظات حول القاعدة الفعلية. **ملاحظة:** إذا كنت تستخدم bash لإضافة قواعد، فيجب عليك إلغاء علامات الاقتباس، على سبيل المثال، \"enable ssh for servers\".

add إضافة قاعدة جديدة موصوفة بقائمة البيانات. يتم إلحاق القاعدة بالسلسلة المحددة ما لم يتم تحديد موقع، وفي هذه الحالة يتم إدراج القاعدة بعد القاعدة المحددة.
insert نفس أمر add باستثناء أن القاعدة تُدرج في بداية السلسلة أو قبل القاعدة المحددة.
replace على غرار أمر add، ولكن القاعدة القديمة...
le يستبدل القاعدة المحددة. delete حذف القاعدة المحددة. destroy حذف القاعدة المحددة، لا يفشل إذا لم تكن موجودة. reset إعادة تعيين الحالة الموجودة في القاعدة، مثل قيم عدادات وبيانات الحصص.

إضافة قاعدة إلى سلسلة إخراج جدول ip.

nft add rule filter output ip daddr 192.168.0.0/24 accept # 'ip filter' مفترض
# نفس الأمر، مع تفصيل طفيف
nft add rule ip filter output ip daddr 192.168.0.0/24 accept

حذف قاعدة من جدول inet.

# nft -a list ruleset
table inet filter {
        chain input {
                type filter hook input priority filter; policy accept;
                ct state established,related accept # معالج 4
                ip saddr 10.1.1.1 tcp dport ssh accept # معالج 5
          ...
# حذف القاعدة ذات المعالج 5
nft delete rule inet filter input handle 5

المجموعات

تقدم nftables نوعين من مفاهيم المجموعات. المجموعات المجهولة هي مجموعات ليس لها اسم محدد. يتم إغلاق أعضاء المجموعة بين أقواس متعرجة، مع فواصل لفصل العناصر عند إنشاء القاعدة التي تستخدم المجموعة. بمجرد إزالة تلك القاعدة، تتم إزالة المجموعة أيضًا. لا يمكن تحديثها، أي بمجرد الإعلان عن مجموعة مجهولة، لا يمكن تغييرها بعد ذلك إلا عن طريق إزالة/تعديل القاعدة التي تستخدم المجموعة المجهولة.

استخدام مجموعات مجهولة لقبول شبكات فرعية ومنافذ معينة.

nft add rule filter input ip saddr { 10.0.0.0/8, 192.168.0.0/16 } tcp dport { 22, 443 } accept

المجموعات المسماة هي مجموعات تحتاج إلى تعريف أولاً قبل أن يمكن الإشارة إليها في القواعد. على عكس المجموعات المجهولة، يمكن إضافة عناصر إلى مجموعة مسماة أو إزالتها منها في أي وقت. تتم الإشارة إلى المجموعات من القواعد باستخدام علامة @ مسبوقة باسم المجموعة.

استخدام مجموعات مسماة لقبول عناوين ومنافذ.

nft add rule filter input ip saddr @allowed_hosts tcp dport @allowed_ports accept

تحتاج المجموعات allowed_hosts و allowed_ports إلى الإنشاء أولاً. يصف القسم التالي بناء جملة مجموعات nft بمزيد من التفصيل.

add set [family] table set { type type | typeof expression ; [flags flags ;] [timeout timeout ;] [gc-interval gc-interval ;] [elements = { element[, ...] } ;] [size size ;] [comment comment ;] [policy 'policy ;] [auto-merge ;] }
{delete | destroy | list | flush | reset } set [family] table set
list sets [family] [table]
delete set [family] table handle handle
{add | delete | destroy } element [family] table set { element[, ...] }

المجموعات هي حاويات عناصر من نوع بيانات معرف من قبل المستخدم، يتم تحديدها بشكل فريد باسم معرف من قبل المستخدم وإرفاقها بالجداول. يمكن تعديل سلوكها باستخدام الأعلام التي يمكن تحديدها في وقت إنشاء المجموعة.

راجع أعلام المجموعات والخرائط أدناه لمزيد من التفاصيل.

add إضافة مجموعة جديدة في الجدول المحدد. انظر جدول مواصفات المجموعة أدناه لمزيد من المعلومات حول كيفية تحديد خصائص المجموعة.
delete حذف المجموعة المحددة.
destroy حذف المجموعة المحددة، لا يفشل إذا لم تكن موجودة.
list عرض العناصر في المجموعة المحددة.
flush إزالة جميع العناصر من المجموعة المحددة.
reset إعادة تعيين الحالة في جميع العناصر المحتواة، مثل قيم عدادات وبيانات الحصص.

الجدول 8. مواصفات المجموعات

كلمة مفتاحية الوصف النوع
type نوع بيانات عناصر المجموعة سلسلة: ipv4_addr, ipv6_addr, ether_addr, inet_proto, inet_service, mark
typeof نوع بيانات عنصر المجموعة تعبير لاستنتاج نوع البيانات منه
flags أعلام المجموعة سلسلة: constant, dynamic, interval, timeout. تستخدم لوصف خصائص المجموعة.
timeout الوقت الذي يبقى فيه العنصر في المجموعة، إلزامي إذا تم إضافة المجموعة من مسار الحزمة (قواعد). سلسلة، رقم عشري متبوع بوحدة. الوحدات هي: d, h, m, s
gc-interval فترة جمع القمامة، متاحة فقط عندما تكون المهلة أو علامة المهلة نشطة. سلسلة، رقم عشري متبوع بوحدة. الوحدات هي: d, h, m, s
elements العناصر التي تحتوي عليها المجموعة نوع بيانات المجموعة
size الحد الأقصى لعدد العناصر في المجموعة، إلزامي إذا تم إضافة المجموعة من مسار الحزمة (قواعد). عدد صحيح غير سالب (64 بت)
policy سياسة المجموعة سلسلة: performance [افتراضي], memory
auto-merge دمج تلقائي للعناصر المتجاورة/المتداخلة في المجموعة (فقط لمجموعات الفترات)

gc-interval لا يؤثر على مهلة العنصر، ولكنه يؤثر على استعادة الذاكرة. يمكن لمجموعة كبيرة نادرًا ما تنتهي صلاحية عناصرها استخدام جمع قمامة أعلى (أقل تكرارًا) لتوفير وقت وحدة المعالجة المركزية، بينما تستفيد المجموعات التي تشهد العديد من التحديثات مع عناصر قصيرة العمر من فترة أقل. تضمن الفترات الأقل بقاء المجموعة أقل من حجمها الأقصى. داخليًا، يبقى الإدخال الذي انتهت صلاحيته حتى تتم إزالته بواسطة جامع القمامة، والذي يقلل أيضًا من عدد عناصر المجموعة. هذا يعني أيضًا أنه من الممكن أن يكون لديك مجموعة لا يمكنها استيعاب المزيد من العناصر، حتى لو انتهت صلاحية جميع العناصر، إذا تم تعيين gc-interval على قيمة كبيرة جدًا.

size يحدد الحد الأعلى لكمية العناصر التي يمكن للمجموعة دعمها. إلزامي للمجموعات التي تتم إضافتها من مجموعة القواعد باستخدام الكلمتين المفتاحيتين add و update. يوفر توفير الكلمة المفتاحية size للمجموعات التي تتم إضافتها فقط عبر nft add element استخدام تنفيذ مجموعة أكثر إحكامًا (يحافظ على الذاكرة)، ولكنه غير مطلوب.

يمكن استخدام الكلمة المفتاحية الاختيارية policy لطلب تنفيذ مجموعة أكثر حفاظًا على الذاكرة.

auto-merge يوجه واجهة nftables لدمج النطاقات المتجاورة والمتداخلة. مثال: عندما تحتوي المجموعة على النطاق 1.2.3.1-1.2.3.4، فإن إضافة العنصر 1.2.3.2 لا يكون لها أي تأثير. إضافة 1.2.3.5 يغير النطاق الحالي ليغطي 1.2.3.1-1.2.3.5. بدون هذا العلم، لا يمكن إضافة 1.2.3.2 ويتم إدراج 1.2.3.5 كإدخال جديد.

تعبيرات FIB

fib FIB_TUPLE FIB_RESULT
FIB_TUPLE := { saddr | daddr} [ . { iif | oif } . mark ]
FIB_RESULT  := { oif | oifname | check | type }

يعبر تعبير fib عن استعلام قاعدة معلومات التوجيه (fib) للحصول على معلومات مثل فهرس واجهة الإخراج.

الوسائط الأولى لتعبير fib هي المفاتيح المدخلة التي سيتم تمريرها إلى دالة بحث fib. يجب تحديد واحد من saddr أو daddr، وهما متعارضان.

الكلمات المفتاحية mark و iif و oif هي معدلات اختيارية للتأثير على نتيجة البحث، انظر جدول الكلمات المفتاحية FIB_TUPLE أدناه للحصول على وصف. الكلمات المفتاحية للجملة iif و oif متعارضة أيضًا.

الوسيط الأخير لتعبير fib هو نوع النتيجة المطلوب.

يطلب oif الحصول على فهرس الواجهة الذي سيتم استخدامه لإرسال الحزم إلى مصدر الحزمة (مفتاح saddr) أو وجهتها (مفتاح daddr). إذا لم يتم العثور على إدخال توجيه، فإن فهرس الواجهة المعادة هو 0.

oifname يشبه oif، ولكنه يملأ اسم الواجهة بدلاً من ذلك. هذا مفيد للتحقق من الواجهات الديناميكية مثل أجهزة ppp. إذا لم يتم العثور على إدخال، يتم إرجاع اسم واجهة فارغ.

type يعيد نوع العنوان مثل unicast أو multicast. يمكن عرض قائمة كاملة بأنواع العناوين المدعومة باستخدام nft describe fib_addrtype.

الجدول 31. الكلمات المفتاحية لـ FIB_TUPLE

كلمة مفتاحية الوصف النوع
type نوع بيانات عناصر الخريطة سلسلة: ipv4_addr, ipv6_addr, ether_addr, inet_proto, inet_service, mark, counter, quota. لا يمكن استخدام counter و quota كمفاتيح.
typeof نوع بيانات عنصر المجموعة تعبير لاستنتاج نوع البيانات
الكلمة المفتاحية الوصف
daddr إجراء بحث عادي في التوجيه: البحث في fib عن مسار إلى عنوان الوجهة للحزمة.
saddr إجراء بحث عكسي في التوجيه: البحث في fib عن مسار إلى عنوان المصدر للحزمة.
mark أخذ علامة الحزمة (nfmark) في الاعتبار عند الاستعلام عن fib.
iif إذا قدمت بحث fib مسارًا، فقم بالتحقق من أن واجهة الإخراج الخاصة به متطابقة مع واجهة الإدخال للحزمة.
oif إذا قدمت بحث fib مسارًا، فقم بالتحقق من أن واجهة الإخراج الخاصة به متطابقة مع واجهة الإخراج للحزمة. يمكن استخدام هذه العلامة فقط مع نتيجة type.

الجدول 32. الكلمات المفتاحية لـ FIB_RESULT

الكلمة المفتاحية الوصف نوع النتيجة
oif فهرس واجهة الإخراج iface_index
check التحقق من واجهة الإخراج boolean
oifname اسم واجهة الإخراج ifname
type نوع العنوان fib_addrtype (انظر nft describe fib_addrtype للحصول على قائمة)

نتيجة oif و oifname صالحة فقط في خطافات prerouting و input و forward. يمكن الاستعلام عن type من أي من خطافات prerouting و input و forward و output و postrouting.

بالنسبة لـ type، فإن وجود الكلمة المفتاحية iif في معدلات FIB_TUPLE يحد من الخطافات المتاحة لتلك التي ترتبط فيها الحزمة بواجهة إدخال، أي prerouting و input و forward. وبالمثل، فإن الكلمة المفتاحية oif في قائمة معدلات FIB_TUPLE سيحد من الخطافات المتاحة إلى forward و output و postrouting.

استخدام تعبيرات fib.

# إسقاط الحزم التي لا تحتوي على مسار عكسي
filter prerouting fib saddr . iif oif missing drop
في هذا المثال، يبحث 'saddr . iif' عن مسار إلى *عنوان المصدر* للحزمة ويقصر النتائج المطابقة على الواجهة التي وصلت منها الحزمة، ثم يخزن فهرس واجهة الإخراج من نتيجة fib التي تم الحصول عليها.
إذا لم يتم العثور على مسار لمزيج عنوان المصدر/واجهة الإدخال، فإن فهرس واجهة الإخراج هو صفر.
وبالتالي، ستسقط هذه القاعدة جميع الحزم التي لا تحتوي على مسار عكسي صارم (الحزمة الردية الافتراضية سترسل عبر الواجهة التي وصلت منها الحزمة المختبرة).
إذا تم استخدام 'saddr oif' فقط كمفتاح إدخال، فإن هذه القاعدة ستسقط فقط الحزم التي لا يمكن لـ fib العثور على مسار لها. في معظم الإعدادات، لن تسقط هذه القاعدة أي حزم لأن المسار الافتراضي هو الذي يتم إرجاعه.
# إسقاط الحزم إذا لم يكن عنوان IP الوجهة مهيئًا على الواجهة الواردة
filter prerouting fib daddr . iif type != { local, broadcast, multicast } drop
هذا يستعلم عن fib بناءً على عنوان الوجهة للحزمة الحالية وواجهة الإدخال.
إذا تم إرسال الحزمة إلى عنوان unicast مهيأ على واجهة مختلفة، فسيتم إسقاط الحزمة نظرًا لأن مثل هذا العنوان سيتم تصنيفه على أنه نوع 'unicast'.
بدون المعدل 'iif'، فإن أي عنوان مهيأ على الجهاز المحلي هو 'local'، وعناوين unicast غير المهيأة على أي واجهة ستعيد النوع 'unicast'.
# إجراء بحث في جدول "blackhole" محدد (0xdead، يحتاج إلى قاعدة ip مناسبة)
filter prerouting meta mark set 0xdead fib daddr . mark type vmap { blackhole : drop, prohibit : jump prohibited, unreachable : drop }

الجمل

تمثل الجمل إجراءات يتم اتخاذها. يمكنها تغيير تدفق التحكم (العودة، القفز إلى سلسلة مختلفة، قبول الحزمة أو إسقاطها) أو يمكنها تنفيذ إجراءات، مثل تسجيل الحزمة، أو رفضها، وما إلى ذلك.

توجد الجمل في نوعين. الجمل الطرفية تنهي تقييم القاعدة الحالية دون قيد أو شرط، والجمل غير الطرفية إما تنهي تقييم القاعدة الحالية بشكل مشروط أو لا تنهيها أبدًا، بعبارة أخرى، إنها سلبية من منظور تقييم مجموعة القواعد. يمكن أن يكون هناك عدد تعسفي من الجمل غير الطرفية في قاعدة، ولكن جملة طرفية واحدة فقط كعبارة نهائية.

جملة الحكم

تغير جملة الحكم تدفق التحكم في مجموعة القواعد وتصدر قرارات سياسة للحزم.

{accept | drop | queue | continue | return}
{jump | goto} CHAIN
CHAIN := chain_name | { statement ... }

accept و drop هي أحكام مطلقة - تنهي تقييم مجموعة القواعد فورًا.

accept إنهاء تقييم مجموعة القواعد وقبول الحزمة. لا تزال الحزمة قابلة للإسقاط لاحقًا بواسطة خطاف آخر، على سبيل المثال، القبول في خطاف forward لا يزال يسمح بإسقاط الحزمة لاحقًا في خطاف postrouting، أو سلسلة أساسية forward أخرى لها رقم أولوية أعلى ويتم تقييمها لاحقًا في مسار المعالجة.
drop إنهاء تقييم مجموعة القواعد وإسقاط الحزمة. يحدث الإسقاط فورًا، ولا يتم تقييم أي سلاسل أو خطافات أخرى. لا يمكن قبول الحزمة في سلسلة لاحقة مرة أخرى، حيث لم يتم تقييمها بعد للحزمة.
queue إنهاء تقييم مجموعة القواعد ووضع الحزمة في قائمة انتظار لمساحة المستخدم. يجب على مساحة المستخدم توفير حكم إسقاط أو قبول. في حالة القبول، تستأنف المعالجة مع خطاف السلسلة الأساسية التالية، وليس مع القاعدة التي تلي حكم قائمة الانتظار.
continue متابعة تقييم مجموعة القواعد مع القاعدة التالية. هذا هو السلوك الافتراضي في حالة عدم إصدار قاعدة لحكم.
return العودة من السلسلة الحالية ومتابعة التقييم في القاعدة التالية في السلسلة الأخيرة. إذا تم إصداره في سلسلة أساسية، فهو يعادل سياسة السلسلة الأساسية.
jump CHAIN متابعة التقييم في القاعدة الأولى في CHAIN. يتم دفع الموضع الحالي في مجموعة القواعد إلى مكدس استدعاء وسيستمر التقييم هناك عند تقييم السلسلة الجديدة بالكامل أو إصدار حكم return. في حالة إصدار حكم مطلق بواسطة قاعدة في السلسلة، تنتهي تقييم مجموعة القواعد فورًا ويتم اتخاذ الإجراء المحدد.
goto CHAIN على غرار jump، ولكن الموضع الحالي لا يتم دفعه إلى مكدس الاستدعاء، مما يعني أنه بعد تقييم السلسلة الجديدة، ستستمر المعالجة في السلسلة الأخيرة بدلاً من السلسلة التي تحتوي على عبارة goto.

بديل لتحديد اسم سلسلة عادية موجودة في CHAIN هو تحديد سلسلة مجهولة عند الحاجة. مثل المجموعات المجهولة، لا يمكن الرجوع إليها من قاعدة أخرى وسيتم إزالتها مع القاعدة التي تحتوي عليها.

استخدام جمل الأحكام.

# process packets from eth0 and the internal network in from_lan
# chain, drop all packets from eth0 with different source addresses.
filter input iif eth0 ip saddr 192.168.0.0/24 jump from_lan
filter input iif eth0 drop
# jump and goto statements support anonymous chain creation
filter input iif eth0 jump { ip saddr 192.168.0.0/24 drop ; udp dport domain drop; }

جملة الحمولة

payload_expression set value

تغير جملة الحمولة محتوى الحزمة. يمكن استخدامها على سبيل المثال لتعيين حقل رأس DSCP (diffserv) IP أو تسميات التدفق IPv6.

توجيه بعض الحزم بدلاً من الجسر.

# redirect tcp:http from 192.160.0.0/16 to local machine for routing instead of bridging
# assumes 00:11:22:33:44:55 is local MAC address.
bridge input meta iif eth0 ip saddr 192.168.0.0/16 tcp dport 80 meta pkttype set host ether daddr set 00:11:22:33:44:55

تعيين حقل رأس DSCP لـ IPv4.

ip forward ip dscp set 42

جملة رأس الامتداد

extension_header_expression set value

تغير جملة رأس الامتداد محتوى الحزمة في رؤوس متغيرة الحجم. يمكن استخدام هذا حاليًا لتغيير الحد الأقصى لحجم مقطع TCP للحزم، بشكل مشابه لهدف TCPMSS في iptables.

تغيير حجم TCP.

tcp flags syn tcp option maxseg size set 1360
# set a size based on route information:
tcp flags syn tcp option maxseg size set rt mtu

يمكنك أيضًا إزالة خيارات TCP عبر الكلمة المفتاحية reset.

إزالة خيار TCP.

tcp flags syn reset tcp option sack-perm

جملة التسجيل

log [prefix quoted_string] [level syslog-level] [flags log-flags]
log group nflog_group [prefix quoted_string] [queue-threshold value] [snaplen size]
log level audit

تمكّن جملة التسجيل من تسجيل الحزم المطابقة. عند استخدام هذه الجملة من قاعدة، سيقوم نواة Linux بطباعة بعض المعلومات حول جميع الحزم المطابقة، مثل حقول الرأس، عبر سجل النواة (حيث يمكن قراءتها باستخدام dmesg(1) أو قراءتها في syslog).

في الشكل الثاني للاستدعاء (إذا تم تحديد nflog_group)، سيمرر نواة Linux الحزمة إلى nfnetlink_log الذي سيرسل السجل عبر مقبس netlink إلى المجموعة المحددة. يمكن لعملية واحدة في مساحة المستخدم الاشتراك في المجموعة لتلقي السجلات، انظر man(8) ulogd للحصول على معلومات حول جهاز تسجيل Netfilter في مساحة المستخدم ووثائق libnetfilter_log في حالة رغبتك في تطوير برنامج مخصص لمعالجة سجلاتك.

في الشكل الثالث للاستدعاء (إذا تم تحديد level audit)، يكتب نواة Linux رسالة في مخزن التدقيق بتنسيق مناسب للقراءة مع auditd. لذلك لا يُسمح بخيارات تنسيق أخرى (مثل prefix أو flags) في هذا الوضع.

هذه جملة غير طرفية، لذا يستمر تقييم القاعدة بعد تسجيل الحزمة.

عبارة FWD

تُستخدم عبارة fwd لإعادة توجيه حزمة خام إلى واجهة أخرى. وهي متاحة فقط في الخطافات الداخلية والخارجية لشبكة netdev. إنها تشبه عبارة dup باستثناء عدم إنشاء نسخة.

يمكنك أيضًا تحديد عنوان النقطة التالية والجهاز الذي سيتم إعادة توجيه الحزمة إليه. يقوم هذا بتحديث عنوان MAC المصدر والوجهة للحزمة عن طريق إرسالها عبر الطبقة المجاورة. هذا أيضًا يقلل من حقل ttl لحزمة IP. يوفر هذا طريقة لتجاوز مسار إعادة التوجيه الكلاسيكي بشكل فعال، وبالتالي تخطي بحث fib (قاعدة معلومات إعادة التوجيه).

fwd to device
fwd [ip | ip6] to address device device

استخدام عبارة fwd.

# إعادة توجيه حزمة خام إلى الجهاز
netdev ingress fwd to "eth0"
# إعادة توجيه الحزمة إلى النقطة التالية 192.168.200.1 عبر الجهاز eth0
netdev ingress ether saddr set fwd ip to 192.168.200.1 device "eth0"

عبارة SET

تُستخدم عبارة set لإضافة أو تحديث العناصر ديناميكيًا في مجموعة (set) من مسار الحزمة. يجب أن تكون المجموعة setname موجودة بالفعل في الجدول المحدد وأن تكون قد تم إنشاؤها باستخدام إحدى العلامتين الديناميكية (dynamic) أو المهلة (timeout) أو كلتيهما. العلامة dynamic مطلوبة إذا كان تعبير عبارة set يتضمن كائنًا له حالة (stateful object). ضمنيًا، يتم استخدام العلامة timeout إذا تم إنشاء المجموعة بمهلة، وهي مطلوبة إذا قامت عبارة set بتحديث العناصر بدلاً من إضافتها. علاوة على ذلك، يجب أن تحدد هذه المجموعات حجمًا أقصى للمجموعة (لمنع استنفاد الذاكرة)، ويجب أن يكون لعناصرها مهلة (بحيث لا ينمو عددها بلا حدود) إما من تعريف المجموعة أو من العبارة التي تضيفها أو تحدثها. يمكن استخدام عبارة set، على سبيل المثال، لإنشاء قوائم حظر ديناميكية.

يتم أيضًا دعم التحديثات الديناميكية باستخدام الخرائط (maps). في هذه الحالة، يجب أن يوفر قاعدة add أو update كل من المفتاح وعنصر البيانات (القيمة)، مفصولين بواسطة :.

{add | update} @setname { expression [timeout timeout] [comment string] }

مثال لقائمة حظر بسيطة.

# تعريف مجموعة، مرتبطة بالجدول "filter"، في العائلة "ip".
# المهلة والحجم إلزاميين لأننا سنضيف عناصر من مسار الحزمة.
# ستنتهي صلاحية الإدخالات بعد دقيقة واحدة، وبعد ذلك قد تتم
# إضافتها مرة أخرى إذا استمر شرط الحد.
nft add set ip filter blackhole \
    "{ type ipv4_addr; flags dynamic; timeout 1m; size 65536; }"
# تعريف مجموعة لتخزين الحد الأقصى لكل عنوان مصدر.
# يجب فصل هذا عن blackhole لأن المهلة مختلفة
nft add set ip filter flood \
    "{ type ipv4_addr; flags dynamic; timeout 10s; size 128000; }"
# السماح بالمرور لواجهة داخلية.
nft add rule ip filter input meta iifname "internal" accept
# إسقاط الحزم الواردة من عناوين IP المحظورة.
nft add rule ip filter input ip saddr @blackhole counter drop
# إضافة عناوين IP المصدر إلى قائمة الحظر إذا حدثت أكثر من 10 اتصالات TCP
# طلبات في الثانية وعنوان IP.
nft add rule ip filter input tcp flags syn tcp dport ssh \
    add @flood { ip saddr limit rate over 10/second } \
    add @blackhole { ip saddr } \
    drop
# فحص حالة المجموعات.
nft list set ip filter flood
nft list set ip filter blackhole
# إضافة عنوانين يدويًا إلى قائمة الحظر.
nft add element filter blackhole { 10.2.3.4, 10.23.1.42 }

عبارة MAP

تُستخدم عبارة map للبحث عن بيانات بناءً على مفتاح إدخال محدد.

expression map { MAP_ELEMENTS }
MAP_ELEMENTS := MAP_ELEMENT [, MAP_ELEMENTS]
MAP_ELEMENT  := key : value

key هو قيمة يتم إرجاعها بواسطة expression.

استخدام عبارة map.

# تحديد هدف DNAT بناءً على منفذ TCP الوجهة:
# يتم إعادة توجيه الاتصالات إلى المنفذ 80 إلى 192.168.1.100،
# يتم إعادة توجيه الاتصالات إلى المنفذ 8888 إلى 192.168.1.101
nft add rule ip nat prerouting dnat tcp dport map { 80 : 192.168.1.100, 8888 : 192.168.1.101 }
# SNAT بناءً على عنوان المصدر:
# ستبدو الحزم من الشبكة 192.168.1.0/24 وكأنها صادرة من 10.0.0.1،
# ستبدو الحزم من الشبكة 192.168.2.0/24 وكأنها صادرة من 10.0.0.2
nft add rule ip nat postrouting snat to ip saddr map { 192.168.1.0/24 : 10.0.0.1, 192.168.2.0/24 : 10.0.0.2 }

عبارة VMAP

تعمل عبارة خريطة النتائج (vmap) بشكل مشابه لعبارة map، ولكنها تحتوي على نتائج (verdicts) كقيم.

expression vmap { VMAP_ELEMENTS }
VMAP_ELEMENTS := VMAP_ELEMENT [, VMAP_ELEMENTS]
VMAP_ELEMENT  := key : verdict

استخدام عبارة vmap.

# القفز إلى سلاسل مختلفة اعتمادًا على نوع بروتوكول الطبقة 4:
nft add rule ip filter input ip protocol vmap { tcp : jump tcp-chain, udp : jump udp-chain , icmp : jump icmp-chain }

عبارة XT

تمثل هذه عبارة xt من واجهة التوافق xtables. إنها حل بديل إذا كان الترجمة غير متاحة أو غير مكتملة.

xt TYPE NAME
TYPE := match | target | watcher

رؤية هذا يعني أن مجموعة القواعد (أو أجزاء منها) تم إنشاؤها بواسطة iptables-nft ويجب استخدام هذا لإدارتها.

تحذير: لن يقوم nftables باستعادة هذه العبارات.

أوامر إضافية

هذه بعض الأوامر الإضافية المضمنة في nft.

قائمة الخطافات (HOOKS)

يعرض هذا قائمة الوظائف التي تم تسجيلها لعائلة البروتوكول المحددة، بما في ذلك الوظائف التي تم تسجيلها ضمنيًا بواسطة وحدات النواة مثل nf_conntrack.

list hooks [family]
list hooks netdev [ device DEVICE_NAME ]

list hooks كافٍ لعرض كل ما هو نشط على النظام. ترتبط الخطافات في عائلة netdev بجهاز شبكة. إذا لم يتم توفير اسم جهاز، فسيقوم nft بالاستعلام عن جميع أجهزة الشبكة في مساحة اسم الشبكة الحالية. مثال على الاستخدام:

قائمة بجميع خطافات netfilter النشطة في مكدس ip أو ip6.

% nft list hooks inet
family ip {
        hook prerouting {
                -0000000400 ipv4_conntrack_defrag [nf_defrag_ipv4]
                -0000000200 ipv4_conntrack_in [nf_conntrack]
                -0000000100 nf_nat_ipv4_pre_routing [nf_nat]
        }
        hook input {
                 0000000000 chain inet filter input [nf_tables]
                +0000000100 nf_nat_ipv4_local_in [nf_nat]
[..]

يُظهر ما ورد أعلاه مضيفًا تم تمكين nat و conntrack وإلغاء تجزئة حزم ipv4. لكل موقع خطاف لعائلة البروتوكول المطلوبة، سيتم عرض قائمة بالخطافات النشطة باستخدام التنسيق

priority identifier [module_name]

سيتم عرضه.

تحدد قيمة priority الترتيب الذي يتم به استدعاء الخطافات. يتم فرز القائمة، ويتم تشغيل الرقم الأقل أولاً.

لا يمكن تغيير قيمة أولوية الخطافات المسجلة بواسطة النواة. بالنسبة للسلاسل الأساسية المسجلة بواسطة nftables، تقابل هذه القيمة قيمة priority المحددة في تعريف السلسلة الأساسية.

بعد القيمة الرقمية، يتم عرض معلومات حول الخطاف. بالنسبة للسلاسل الأساسية المعرفة في nftables، يتضمن ذلك عائلة الجدول واسم الجدول واسم السلاسل الأساسية. بالنسبة للخطافات الواردة من وحدات النواة، يتم استخدام اسم الدالة بدلاً من ذلك.

إذا تم توفير module name، فقد تم تسجيل الخطاف بواسطة وحدة النواة بهذا الاسم. يمكنك استخدام modinfo module name للحصول على مزيد من المعلومات حول الوحدة.

تتطلب هذه الوظيفة نواة تم بناؤها مع تمكين الخيار CONFIG_NETFILTER_NETLINK_HOOK، إما كوحدة أو مدمج. اسم الوحدة هو nfnetlink_hook.

المراقبة (MONITOR)

يسمح لك أمر monitor بالاستماع إلى أحداث Netlink التي تنتجها `nf_tables` subsystem. تتعلق هذه إما بإنشاء وحذف الكائنات أو بالحزم التي تم تمكين meta nftrace لها. عند حدوثها، سيقوم nft بطباعة الأحداث التي تتم مراقبتها إلى الإخراج القياسي بتنسيق JSON أو بتنسيق nft الأصلي.

monitor [new | destroy] MONITOR_OBJECT
monitor trace
MONITOR_OBJECT := tables | chains | sets | rules | elements | ruleset

لتصفية الأحداث المتعلقة بكائن ملموس، استخدم إحدى الكلمات المفتاحية في MONITOR_OBJECT.

لتصفية الأحداث المتعلقة بإجراء ملموس، استخدم الكلمة المفتاحية new أو destroy.

الشكل الثاني للاستدعاء لا يأخذ خيارات إضافية ويقوم فقط بطباعة الأحداث التي تم إنشاؤها للحزم التي تم تمكين nftrace لها.

اضغط ^C لإنهاء عملية المراقبة.

الاستماع إلى جميع الأحداث، والإبلاغ بتنسيق nft الأصلي.

% nft monitor

الاستماع إلى القواعد المحذوفة، والإبلاغ بتنسيق JSON.

% nft -j monitor destroy rules

الاستماع إلى كل من السلاسل الجديدة والمحذوفة، بتنسيق nft الأصلي.

% nft monitor chains

الاستماع إلى أحداث مجموعة القواعد مثل الجدول والسلسلة والقاعدة والمجموعة والعدادات والحصص، بتنسيق nft الأصلي.

% nft monitor ruleset

تتبع الحزم الواردة من المضيف 10.0.0.1.

% nft add rule filter input ip saddr 10.0.0.1 meta nftrace set 1
% nft monitor trace
