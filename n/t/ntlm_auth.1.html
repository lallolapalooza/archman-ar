NTLM_AUTH(1) أوامر المستخدم NTLM_AUTH(1)

الاسم

ntlm_auth - أداة للسماح بالوصول الخارجي إلى وظيفة مصادقة NTLM الخاصة بـ Winbind

الملخص

ntlm_auth

الوصف

هذه الأداة جزء من مجموعة samba(7).

ntlm_auth هي أداة مساعدة تقوم بمصادقة المستخدمين باستخدام مصادقة NT/LM. تُرجع 0 إذا تمت مصادقة المستخدم بنجاح و 1 إذا تم رفض الوصول. تستخدم ntlm_auth winbind للوصول إلى بيانات المستخدم والمصادقة الخاصة بنطاق. هذه الأداة مخصصة فقط للاستخدام من قبل برامج أخرى (حاليًا Squid و mod_ntlm_winbind).

متطلبات التشغيل

يجب أن يكون خادم winbindd(8) قيد التشغيل لكي تعمل العديد من هذه الأوامر.

تتطلب بعض هذه الأوامر أيضًا الوصول إلى الدليل winbindd_privileged في $LOCKDIR. يجب القيام بذلك إما عن طريق تشغيل هذا الأمر كـ root أو توفير وصول مجموعة إلى الدليل winbindd_privileged. لأسباب أمنية، يجب ألا يكون هذا الدليل متاحًا للجميع.

الخيارات

--helper-protocol=PROTO

العمل كبرنامج مساعد يعتمد على stdio. بروتوكولات المساعد الصالحة هي:

squid-2.4-basic

برنامج مساعد من جانب الخادم للاستخدام مع مصادقة Squid 2.4 الأساسية (نص عادي).

squid-2.5-basic

برنامج مساعد من جانب الخادم للاستخدام مع مصادقة Squid 2.5 الأساسية (نص عادي).

squid-2.5-ntlmssp

برنامج مساعد من جانب الخادم للاستخدام مع مصادقة Squid 2.5 NTLMSSP.

يتطلب الوصول إلى الدليل winbindd_privileged في $LOCKDIR. البروتوكول المستخدم موصوف هنا: http://devel.squid-cache.org/ntlm/squid_helper_protocol.html. تم توسيع هذا البروتوكول للسماح بتضمين حزمة NTLMSSP Negotiate كوسيط لأمر YR. (وبالتالي تجنب فقدان المعلومات في تبادل البروتوكول).

ntlmssp-client-1

برنامج مساعد من جانب العميل للاستخدام مع أي برامج خارجية قد ترغب في استخدام معرفة مصادقة Samba NTLMSSP.

هذا المساعد هو عميل، وبصفته كذلك قد يتم تشغيله بواسطة أي مستخدم. البروتوكول المستخدم هو فعليًا عكس البروتوكول السابق. يبدأ أمر YR (بدون أي وسيطات) تبادل المصادقة.

gss-spnego

برنامج مساعد من جانب الخادم ينفذ GSS-SPNEGO. يستخدم هذا بروتوكولًا مشابهًا جدًا لـ squid-2.5-ntlmssp، ولكنه يحتوي على بعض الاختلافات الدقيقة غير الموثقة خارج المصدر في هذه المرحلة.

يتطلب الوصول إلى الدليل winbindd_privileged في $LOCKDIR.

gss-spnego-client

برنامج مساعد من جانب العميل ينفذ GSS-SPNEGO. يستخدم هذا أيضًا بروتوكولًا مشابهًا للمساعدين أعلاه، ولكنه غير موثق حاليًا.

ntlm-server-1

بروتوكول مساعد من جانب الخادم، مخصص للاستخدام من قبل خادم RADIUS أو مكون إضافي 'winbind' لـ pppd، لتوفير مصادقة MSCHAP و MSCHAPv2.

يتكون هذا البروتوكول من أسطر بالشكل: Parameter: value و Parameter:: Base64-encode value. يشير وجود نقطة واحدة . إلى أن أحد الطرفين قد انتهى من تزويد البيانات للآخر. (مما قد يؤدي بدوره إلى مصادقة المساعد للمستخدم).

الوسيطات المطبقة حاليًا من البرنامج الخارجي إلى المساعد هي:

Username

اسم المستخدم، المتوقع أن يكون بترميز Samba unix charset.

أمثلة:

Username: bob

Username:: Ym9i

NT-Domain

نطاق المستخدم، المتوقع أن يكون بترميز Samba unix charset.

أمثلة:

NT-Domain: WORKGROUP

NT-Domain:: V09SS0dST1VQ

Full-Username

اسم المستخدم الكامل، المتوقع أن يكون بترميز Samba unix charset ومؤهل بـ winbind separator.

أمثلة:

Full-Username: WORKGROUP\bob

Full-Username:: V09SS0dST1VQYm9i

LANMAN-Challenge

قيمة LANMAN Challenge المكونة من 8 بايت، تم إنشاؤها عشوائيًا بواسطة الخادم، أو (في حالات مثل MSCHAPv2) تم إنشاؤها بطريقة ما بواسطة كل من الخادم والعميل.

أمثلة:

LANMAN-Challenge: 0102030405060708

LANMAN-Response

قيمة LANMAN Response المكونة من 24 بايت، محسوبة من كلمة مرور المستخدم و LANMAN Challenge المقدم. عادةً، يتم توفير هذا عبر الشبكة بواسطة عميل يرغب في المصادقة.

أمثلة:

LANMAN-Response: 0102030405060708090A0B0C0D0E0F101112131415161718

NT-Response

استجابة NT (>= 24 بايت) المحسوبة من كلمة مرور المستخدم و LANMAN Challenge المقدم. عادةً، يتم توفير هذا عبر الشبكة بواسطة عميل يرغب في المصادقة.

أمثلة:

NT-Response: 0102030405060708090A0B0C0D0E0F10111213141516171

Password

كلمة مرور المستخدم. سيتم توفير هذا بواسطة عميل شبكة، إذا كان المساعد يُستخدم في سياق قديم يكشف عن كلمات مرور نصية عادية بهذه الطريقة.

أمثلة:

Password: samba2

Password:: c2FtYmEy

Request-User-Session-Key

بعد المصادقة الناجحة، أرجع مفتاح جلسة المستخدم المرتبط بتسجيل الدخول.

أمثلة:

Request-User-Session-Key: Yes

Request-LanMan-Session-Key

بعد المصادقة الناجحة، أرجع مفتاح جلسة LANMAN المرتبط بتسجيل الدخول.

أمثلة:

Request-LanMan-Session-Key: Yes

تحذير
يجب على المطورين الحرص على ترميز البيانات (مثل أسماء المستخدمين/كلمات المرور) التي قد تحتوي على بيانات مستخدم ضارة، مثل حرف سطر جديد، بترميز base64. قد يحتاجون أيضًا إلى فك ترميز السلاسل من المساعد، والتي قد تكون هي نفسها مرمزة بـ base64.

--username=USERNAME

تحديد اسم المستخدم للمستخدم المراد مصادقته

--domain=DOMAIN

تحديد نطاق المستخدم المراد مصادقته

--workstation=WORKSTATION

تحديد محطة العمل التي قام المستخدم بالمصادقة منها

--challenge=STRING

تحدي NTLM (بالنظام السداسي عشري HEXADECIMAL)

--lm-response=RESPONSE

استجابة LM للتحدي (بالنظام السداسي عشري HEXADECIMAL)

--nt-response=RESPONSE

استجابة NT أو NTLMv2 للتحدي (بالنظام السداسي عشري HEXADECIMAL)

--password=PASSWORD

كلمة مرور المستخدم النصية العادية

إذا لم يتم تحديدها في سطر الأوامر، فسيتم طلبها عند الحاجة.

بالنسبة لأدوار الخادم المستندة إلى NTLMSSP، يحدد هذا الوسيط كلمة المرور المتوقعة، مما يسمح بالاختبار بدون تشغيل winbindd.

--request-lm-key

استرداد مفتاح جلسة LM

--request-nt-key

طلب مفتاح NT

--diagnostics

إجراء تشخيصات على سلسلة المصادقة. يستخدم كلمة المرور من --password أو يطلب واحدة.

--require-membership-of={SID|Name}

يتطلب أن يكون المستخدم عضوًا في مجموعة محددة (اسم أو SID) لنجاح المصادقة.

--pam-winbind-conf=FILENAME

تحديد المسار إلى ملف pam_winbind.conf.

--target-hostname=HOSTNAME

تحديد اسم المضيف المستهدف.

--target-service=SERVICE

تحديد الخدمة المستهدفة.

--use-cached-creds

ما إذا كان سيتم استخدام بيانات الاعتماد المخزنة مؤقتًا بواسطة winbindd.

--allow-mschapv2

السماح صراحةً بـ MSCHAPv2.

--offline-logon

السماح بتسجيل الدخول دون اتصال للمصادقة بالنص العادي.

-?|--help

طباعة ملخص لخيارات سطر الأوامر.

--usage

عرض رسالة استخدام موجزة.

-d|--debuglevel=level

level هو عدد صحيح من 0 إلى 10. القيمة الافتراضية إذا لم يتم تحديد هذا الوسيط هي 1 لتطبيقات العميل.

ntlm_auth(1) — Samba — Arch Linux

NAME

ntlm_auth

NTLM authentication helper for winbindd

SYNOPSIS

ntlm_auth --helper-protocol=protocol [options]

DESCRIPTION

The ntlm_auth program is an authentication helper that can be used by other programs like squid. It can perform NTLM and NTLMSSP authentication using winbindd(8) and the underlying Samba libraries.

It is designed to be used as a helper program for other daemons that require authentication services. The communication protocol between ntlm_auth and the calling daemon is line-based and simple.

This program is part of the Samba suite.

OPERATIONAL REQUIREMENTS

The ntlm_auth program requires access to the winbind daemon, and its socket file. The winbind daemon must be configured and running, and the ntlm_auth program must have appropriate permissions to access the socket file. The location of the socket file is specified by the winbindd socket directory parameter in smb.conf.

By default this directory is /var/run/samba/winbindd. This directory must be created and owned by the root user. The socket file, /var/run/samba/winbindd/winbindd_winbindd_unix_socket, must be readable and writable by the user that the calling daemon runs as.

The recommended setup is to create a group (e.g. winbind_access) and add the user that the calling daemon runs as to this group, and then set the permissions on the winbindd socket directory to 0750, and the group ownership to root:winbind_access.

In addition, you must enable the winbind use rpcwrapfslock parameter in smb.conf.

OPTIONS

--helper-protocol=protocol

This option specifies the protocol used by the helper program. Valid protocols include:

  • squid-2.4-basic
  • squid-2.4-ntlmssp
  • squid-2.5-basic
  • squid-2.5-ntlmssp
  • samba

--require-membership-of=group

This option restricts authentication to users who are members of the specified group. The group name should be specified in the format DOMAIN\groupname or GROUPNAME@DOMAIN.

--implementation=name

This option specifies the authentication implementation to use. Possible values are ntlm or ntlmv2-cisco.

--logging=level

This option specifies the level of debugging information to log. The higher the value, the more detail will be logged to the log files about the activities of the server. At level 0, only critical errors and serious warnings will be logged. Level 1 is a reasonable level for day-to-day running - it generates a small amount of information about operations carried out.

Levels above 1 will generate considerable amounts of log data, and should only be used when investigating a problem. Levels above 3 are designed for use only by developers and generate HUGE amounts of log data, most of which is extremely cryptic.

Note that specifying this parameter here will override the log level parameter in the /etc/samba/smb.conf file.

--debug-stdout

This will redirect debug output to STDOUT. By default all clients are logging to STDERR.

--configfile=<configuration file>

The file specified contains the configuration details required by the client. The information in this file can be general for client and server or only provide client specific like options such as client smb encrypt. See /etc/samba/smb.conf for more information. The default configuration file name is determined at compile time.

--option=<name>=<value>

Set the smb.conf(5) option "<name>" to value "<value>" from the command line. This overrides compiled-in defaults and options read from the configuration file. If a name or a value includes a space, wrap whole --option=name=value into quotes.

-V|--version

Prints the program version number.

EXAMPLE SETUP

To setup ntlm_auth for use by squid 2.5, with both basic and NTLMSSP authentication, the following should be placed in the squid.conf file.

auth_param ntlm program ntlm_auth --helper-protocol=squid-2.5-ntlmssp
auth_param basic program ntlm_auth --helper-protocol=squid-2.5-basic
auth_param basic children 5
auth_param basic realm Squid proxy-caching web server
auth_param basic credentialsttl 2 hours

Note

This example assumes that ntlm_auth has been installed into your path, and that the group permissions on winbindd_privileged are as described above.

To setup ntlm_auth for use by squid 2.5 with group limitation in addition to the above example, the following should be added to the squid.conf file.

auth_param ntlm program ntlm_auth --helper-protocol=squid-2.5-ntlmssp --require-membership-of='WORKGROUP\Domain Users'
auth_param basic program ntlm_auth --helper-protocol=squid-2.5-basic --require-membership-of='WORKGROUP\Domain Users'

TROUBLESHOOTING

If you're experiencing problems with authenticating Internet Explorer running under MS Windows 9X or Millennium Edition against ntlm_auth's NTLMSSP authentication helper (--helper-protocol=squid-2.5-ntlmssp), then please read the Microsoft Knowledge Base article #239869 and follow instructions described there.
