ntfs-3g(8)

الحزمة: ntfs-3g

التراخيص: GPL2

NAME

ntfs-3g - Read/write NTFS filesystem driver

SYNOPSIS

ntfs-3g [options] device mountpoint

mount -t ntfs-3g [options] device mountpoint

DESCRIPTION

ntfs-3g is an open source cross-platform `recoverability-enhanced' read/write driver for the Microsoft Windows 7/8/10/11 NTFS filesystem. It is based on the Linux-NTFS project, and it is the successor of the earlier released NTFS drivers.

ntfs-3g uses the FUSE (Filesystem in Userspace) framework to provide a stable, full featured, and reliable NTFS filesystem implementation.

The main goals of ntfs-3g are:

  • Provide a stable, reliable, and performant NTFS driver.
  • Support for all NTFS features, including, but not limited to, compressed files, encrypted files, sparse files, journaling, hard links, symbolic links, volume shadow copies, alternate data streams, extended attributes, and Access Control Lists (ACLs).
  • Safe read/write operation, with data integrity protection.
  • Easy to use, with sensible defaults.
  • Full disk encryption support (e.g. BitLocker To Go).
  • Wide platform support (Linux, macOS, FreeBSD, NetBSD, OpenSolaris, Solaris, Haiku, Minix 3, and Windows).

OPTIONS

The options are passed to the driver either directly to ntfs-3g or using the standard mount command options (e.g. `-o`).

Common mount options include:

ro
Mount the filesystem read-only.
rw
Mount the filesystem read-write. This is the default if not specified.
uid=uid
Set the user ID of the owner of all files. Defaults to the real UID of the process, or 0 if running as root.
gid=gid
Set the group ID of the owner of all files. Defaults to the real GID of the process, or 0 if running as root.
umask=mask
Set the file permissions for the files. The mask is given in octal.
fmask=mask
Set the file permissions for files only.
dmask=mask
Set the file permissions for directories only.
permissions
Enable POSIX POSIX ACLs support. This option is only useful if the filesystem is mounted read-write.
force
Force the mount even if the filesystem is marked for Windows recovery. Use with caution.
remove_hiberfile
Remove the Windows hibernation file if present. This allows Windows to hibernate again after the filesystem has been mounted read-write. Use with caution.
windows_names
Do not allow names that contain characters that are illegal in Windows (e.g., ':' and '*').
inherit
Enable inheritance of POSIX ACLs from parent directories. This option is only useful if the filesystem is mounted read-write.
no_wprotect
Disable the Windows write protection mechanism. This is not recommended unless you know what you are doing.
norecover
Do not perform a filesystem check. This option is useful for mounting an unclean filesystem.

For a complete list of options, see the ntfs-3g.conf(5) manual page.

USER MAPPING

NTFS does not support POSIX user and group ownership. However, ntfs-3g can simulate this by mapping UIDs and GIDs to NTFS security descriptors. This allows users to own files and directories on NTFS partitions. This feature is enabled by the permissions option.

The utility ntfsusermap may be used to create such a user mapping file.

EXAMPLES

Mount /dev/sda1 to /mnt/windows:

ntfs-3g /dev/sda1 /mnt/windows

or
mount -t ntfs-3g /dev/sda1 /mnt/windows
Mount the ntfs data partition /dev/sda3 to /mnt/data with standard Linux permissions applied :

ntfs-3g -o permissions /dev/sda3 /mnt/data

or
mount -t ntfs-3g -o permissions /dev/sda3 /mnt/data
Read-only mount /dev/sda5 to /home/user/mnt and make user with uid 1000 to be the owner of all files:

ntfs-3g /dev/sda5 /home/user/mnt -o ro,uid=1000

/etc/fstab entry for the above (the sixth and last field has to be zero to avoid a file system check at boot time) :

/dev/sda5 /home/user/mnt ntfs-3g ro,uid=1000 0 0

Unmount /mnt/windows:

umount /mnt/windows

EXIT CODES

To facilitate the use of the ntfs-3g driver in scripts, an exit code is returned to give an indication of the mountability status of a volume. Value 0 means success, and all other ones mean an error. The unique error codes are documented in the ntfs-3g.probe(8) manual page.

الاسم

ntfs-3g - برنامج تشغيل نظام ملفات NTFS للقراءة/الكتابة

الملخص

ntfs-3g [خيارات] جهاز نقطة_التحميل

mount -t ntfs-3g [خيارات] جهاز نقطة_التحميل

الوصف

ntfs-3g هو برنامج تشغيل مفتوح المصدر متعدد المنصات معزز بالاسترداد للقراءة/الكتابة لنظام ملفات Microsoft Windows 7/8/10/11 NTFS. وهو مبني على مشروع Linux-NTFS، وهو خليفة برامج تشغيل NTFS التي تم إصدارها سابقًا.

يستخدم ntfs-3g إطار عمل FUSE (نظام الملفات في مساحة المستخدم) لتوفير تطبيق مستقر وكامل الميزات وموثوق لنظام ملفات NTFS.

الأهداف الرئيسية لـ ntfs-3g هي:

  • توفير برنامج تشغيل NTFS مستقر وموثوق وعالي الأداء.
  • دعم جميع ميزات NTFS، بما في ذلك على سبيل المثال لا الحصر، الملفات المضغوطة، الملفات المشفرة، الملفات المتفرقة، التسجيل، الارتباطات الصلبة، الارتباطات الرمزية، نسخ الظل للحجم، جداول البيانات البديلة، السمات الموسعة، وقوائم التحكم في الوصول (ACLs).
  • عملية قراءة/كتابة آمنة، مع حماية سلامة البيانات.
  • سهل الاستخدام، مع إعدادات افتراضية منطقية.
  • دعم تشفير القرص الكامل (مثل BitLocker To Go).
  • دعم واسع للمنصات (Linux، macOS، FreeBSD، NetBSD، OpenSolaris، Solaris، Haiku، Minix 3، و Windows).

الخيارات

يتم تمرير الخيارات مباشرة إلى برنامج التشغيل إما إلى ntfs-3g أو باستخدام خيارات أمر mount القياسية (مثل `-o`).

تشمل خيارات التحميل الشائعة:

ro
تحميل نظام الملفات للقراءة فقط.
rw
تحميل نظام الملفات للقراءة/الكتابة. هذا هو الخيار الافتراضي إذا لم يتم تحديده.
uid=uid
تعيين معرف المستخدم (UID) لمالك جميع الملفات. القيمة الافتراضية هي UID الحقيقي للعملية، أو 0 إذا تم التشغيل كـ root.
gid=gid
تعيين معرف المجموعة (GID) لمالك جميع الملفات. القيمة الافتراضية هي GID الحقيقي للعملية، أو 0 إذا تم التشغيل كـ root.
umask=mask
تعيين أذونات الملفات. يتم إعطاء القناع في النظام الثماني.
fmask=mask
تعيين أذونات الملفات للملفات فقط.
dmask=mask
تعيين أذونات الملفات للمجلدات فقط.
permissions
تمكين دعم ACLs POSIX. هذا الخيار مفيد فقط إذا تم تحميل نظام الملفات للقراءة/الكتابة.
force
فرض التحميل حتى لو تم تمييز نظام الملفات لاسترداد Windows. استخدم بحذر.
remove_hiberfile
إزالة ملف الإسبات (hibernation file) الخاص بـ Windows إذا كان موجودًا. هذا يسمح لـ Windows بالدخول في وضع الإسبات مرة أخرى بعد تحميل نظام الملفات للقراءة/الكتابة. استخدم بحذر.
windows_names
عدم السماح بالأسماء التي تحتوي على أحرف غير قانونية في Windows (مثل ':' و '*').
inherit
تمكين وراثة ACLs POSIX من المجلدات الأصل. هذا الخيار مفيد فقط إذا تم تحميل نظام الملفات للقراءة/الكتابة.
no_wprotect
تعطيل آلية الحماية من الكتابة الخاصة بـ Windows. لا يوصى بذلك إلا إذا كنت تعرف ما تفعله.
norecover
عدم إجراء فحص لنظام الملفات. هذا الخيار مفيد لتحميل نظام ملفات غير نظيف.

للحصول على قائمة كاملة بالخيارات، راجع صفحة الدليل ntfs-3g.conf(5).

تعيين المستخدم

لا يدعم NTFS ملكية المستخدم والمجموعة POSIX. ومع ذلك، يمكن لـ ntfs-3g محاكاة ذلك عن طريق تعيين UIDs و GIDs إلى واصفات أمان NTFS. هذا يسمح للمستخدمين بامتلاك الملفات والمجلدات على أقسام NTFS. يتم تمكين هذه الميزة بواسطة الخيار permissions.

قد يتم استخدام الأداة المساعدة ntfsusermap لإنشاء ملف تعيين المستخدم هذا.

أمثلة

تحميل /dev/sda1 إلى /mnt/windows:

ntfs-3g /dev/sda1 /mnt/windows

أو
mount -t ntfs-3g /dev/sda1 /mnt/windows
تحميل قسم بيانات ntfs /dev/sda3 إلى /mnt/data مع تطبيق أذونات Linux القياسية:

ntfs-3g -o permissions /dev/sda3 /mnt/data

أو
mount -t ntfs-3g -o permissions /dev/sda3 /mnt/data
تحميل /dev/sda5 للقراءة فقط إلى /home/user/mnt وجعل المستخدم ذي المعرف uid 1000 هو مالك جميع الملفات:

ntfs-3g /dev/sda5 /home/user/mnt -o ro,uid=1000

إدخال /etc/fstab لما سبق (يجب أن يكون الحقل السادس والأخير صفرًا لتجنب فحص نظام الملفات عند بدء التشغيل):

/dev/sda5 /home/user/mnt ntfs-3g ro,uid=1000 0 0

إلغاء تحميل /mnt/windows:

umount /mnt/windows

رموز الخروج

لتسهيل استخدام برنامج التشغيل ntfs-3g في البرامج النصية، يتم إرجاع رمز خروج لإعطاء مؤشر على حالة إمكانية تحميل وحدة التخزين. القيمة 0 تعني النجاح، وجميع القيم الأخرى تعني حدوث خطأ. رموز الأخطاء الفريدة موثقة في صفحة الدليل ntfs-3g.probe(8).
