ntp-keygen - OpenNTPd key generation utility

version 1.0.0

December 2023

SYNOPSIS

ntp-keygen [-b | --imbits=modulus] [-c | --certificate=scheme] [-C | --cipher=cipher] [-d | --debug-level] [-D | --set-debug-level=level] [-e | --id-key] [-G | --gq-params] [-H | --host-key] [-I | --iffkey] [-i | --ident=group] [-l | --lifetime=days] [-m | --modulus=bits] [-M | --md5key] [-p | --password=passwd] [-P | --pvt-cert] [-q | --export-passwd=passwd] [-s | --subject-key=[host] [@@ group]] [-S | --sign-key=[RSA | DSA]] [-T | --trusted-cert] [-V | --mv-params=nkeys]

DESCRIPTION

The ntp-keygen utility is used to generate private and public keys and certificates for use by the OpenNTPd time synchronization daemon. This utility is used to support the various cryptographic authentication schemes available in OpenNTPd. The generation of these keys and certificates requires careful attention to detail and a thorough understanding of the cryptographic methods employed.

The following schemes are supported:

  • TC Time-Crypto authentication scheme. This is the original authentication scheme, which is now obsolete. It is included for backward compatibility only.
  • IFF Internet Finance Foundation authentication scheme, using the Schnorr identification scheme.
  • GQ Guillou-Quisquater authentication scheme.
  • MV Mu-Varadharajan authentication scheme.

Generating Keys and Certificates

Key and certificate generation is a complex process that depends on the chosen cryptographic scheme. The following subsections describe the process for each scheme.

TC scheme: Generate keys and certificates for all group hosts. For illustration assume trish is the TA, alice one of several trusted hosts and bob one of her clients. On TA trish run ntp-keygen -p password to generate the parameter file ntpkeys_TCpar_trish.filestamp and client key files ntpkeys_TCkeyd _ trish. filestamp where d is the key number (1 <= d <= 5). Copy the parameter file to alice and install a soft link from the generic ntpkey_tc_alice to this file. Copy one of the client key files to alice for later distribution to her clients. It does not matter which client key file goes to alice, since they all work the same way. Alice copies the client key file to all of her clients. On client bob install a soft link from generic ntpkey_tc_bob to the client key file. As the TC scheme updates the TC parameters file and certificate at the same time, keys and certificates can be regenerated as needed.

IFF scheme: Generate keys and certificates for all group hosts. On TA trish run ntp-keygen -I -p password to generate the parameter file ntpkeys_IFFpar_trish.filestamp and client key files ntpkeys_IFFkeyd _ trish. filestamp where d is the key number (1 <= d <= 5). Copy the parameter file to alice and install a soft link from the generic ntpkey_iff_alice to this file. Copy one of the client key files to alice for later distribution to her clients. It does not matter which client key file goes to alice, since they all work the same way. Alice copies the client key file to all of her clients. On client bob install a soft link from generic ntpkey_iff_bob to the client key file. As the IFF scheme updates the IFF parameters file and certificate at the same time, keys and certificates can be regenerated as needed.

GQ scheme: Generate keys and certificates for all group hosts. On TA trish run ntp-keygen -G -p password to generate the parameter file ntpkeys_GQpar_trish.filestamp and client key files ntpkeys_GQkeyd _ trish. filestamp where d is the key number (1 <= d <= 5). Copy the parameter file to alice and install a soft link from the generic ntpkey_gq_alice to this file. In addition, on each host bob install a soft link from generic ntpkey_gq_bob to this file. As the GQ scheme updates the GQ parameters file and certificate at the same time, keys and certificates can be regenerated as needed.

For the MV scheme, proceed as in the TC scheme to generate keys and certificates for all group hosts. For illustration assume trish is the TA, alice one of several trusted hosts and bob one of her clients. On TA trish run ntp-keygen -V n -p password, where n is the number of revokable keys (typically 5) to produce the parameter file ntpkeys_MVpar_trish.filestamp and client key files ntpkeys_MVkeyd _ trish. filestamp where d is the key number (0 < d < n). Copy the parameter file to alice and install a soft link from the generic ntpkey_mv_alice to this file. Copy one of the client key files to alice for later distribution to her clients. It does not matter which client key file goes to alice, since they all work the same way. Alice copies the client key file to all of her clients. On client bob install a soft link from generic ntpkey_mvkey_bob to the client key file. As the MV scheme is independent of keys and certificates, these files can be refreshed as needed.

Command Line Options

-b --imbits= modulus

Set the number of bits in the identity modulus for generating identity keys to modulus bits. The number of bits in the identity modulus defaults to 256, but can be set to values from 256 to 2048 (32 to 256 octets). Use the larger moduli with caution, as this can consume considerable computing resources and increases the size of authenticated packets.
-c --certificate= scheme

Select certificate signature encryption/message digest scheme. The scheme can be one of the following: RSA-MD2, RSA-MD5, RSA-MDC2, RSA-SHA, RSA-SHA1, RSA-RIPEMD160, DSA-SHA, or DSA-SHA1. Note that RSA schemes must be used with an RSA sign key and DSA schemes must be used with a DSA sign key. The default without this option is RSA-MD5. If compatibility with FIPS 140-2 is required, either the DSA-SHA or DSA-SHA1 scheme must be used.
-C --cipher= cipher

Select the OpenSSL cipher to encrypt the files containing private keys. The default without this option is three-key triple DES in CBC mode, des-ede3-cbc. The openssl -h command provided with OpenSSL displays available ciphers.
-d --debug-level

Increase debugging verbosity level. This option displays the cryptographic data produced in eye-friendly billboards.
-D --set-debug-level= level

Set the debugging verbosity to level. This option displays the cryptographic data produced in eye-friendly billboards.
-e --id-key

Write the IFF or GQ public parameters from the IFFkey or GQkey client keys file previously specified as unencrypted data to the standard output stream stdout. This is intended for automatic key distribution by email.
-G --gq-params

Generate a new encrypted GQ parameters and key file for the Guillou-Quisquater (GQ) identity scheme. This option is mutually exclusive with the -I and -V options.
-H --host-key

Generate a new encrypted RSA public/private host key file.
-I --iffkey

Generate a new encrypted IFF key file for the Schnorr (IFF) identity scheme. This option is mutually exclusive with the -G and Fl V options.
-i --ident= group

Set the optional Autokey group name to group. This is used in the identity scheme parameter file names of IFF, GQ, and MV client parameters files. In that role, the default is the host name if no group is provided. The group name, if specified using -i or -s following an ‘@@’ character, is also used in certificate subject and issuer names in the form host @@ group and should match the group specified via crypto ident or server ident in the ntpd configuration file.
-l --lifetime= days

Set the lifetime for certificate expiration to days. The default lifetime is one year (365 days).
-m --modulus= bits

Set the number of bits in the prime modulus for generating files to bits. The modulus defaults to 512, but can be set from 256 to 2048 (32 to 256 octets). Use the larger moduli with caution, as this can consume considerable computing resources and increases the size of authenticated packets.
-M --md5key

Generate a new symmetric keys file containing 10 MD5 keys, and if OpenSSL is available, 10 SHA keys. An MD5 key is a string of 20 random printable ASCII characters, while a SHA key is a string of 40 random hex digits. The file can be edited using a text editor to change the key type or key content. This option is mutually exclusive with all other options.
-p --password= passwd

Set the password for reading and writing encrypted files to passwd. These include the host, sign and identify key files. By default, the password is the string returned by the Unix hostname command.
-P --pvt-cert

Generate a new private certificate used by the PC identity scheme. By default, the program generates public certificates. Note: the PC identity scheme is not recommended for new installations.
-q --export-passwd= passwd

Set the password for writing encrypted IFF, GQ and MV identity files redirected to stdout to passwd. In effect, these files are decrypted with the -p password, then encrypted with the -q password. By default, the password is the string returned by the Unix hostname command.
-s --subject-key= [host] [@@ group]

Specify the Autokey host name, where host is the optional host name and group is the optional group name. The host name, and if provided, group name are used in host @@ group form as certificate subject and issuer. Specifying -s -@@ group is allowed, and results in leaving the host name unchanged, as with -i group. The group name, or if no group is provided, the host name are also used in the file names of IFF, GQ, and MV identity scheme client parameter files. If host is not specified, the default host name is the string returned by the Unix hostname command.
-S --sign-key= [RSA | DSA]

Generate a new encrypted public/private sign key file of the specified type. By default, the sign key is the host key and has the same type. If compatibility with FIPS 140-2 is required, the sign key type must be DSA.
-T --trusted-cert

Generate a trusted certificate. By default, the program generates a non-trusted certificate.
-V --mv-params nkeys

Generate nkeys encrypted server keys and parameters for the Mu-Varadharajan (MV) identity scheme. This option is mutually exclusive with the -I and -G options. Note: support for this option should be considered a work in progress.

Random Seed File

All cryptographically sound key generation schemes must have means to randomize the entropy seed used to initialize the internal pseudo-random number generator used by the library routines. The OpenSSL library uses a designated random seed file for this purpose. The file must be available when starting the NTP daemon and ntp-keygen program. If a site supports OpenSSL or its companion OpenSSH, it is very likely that means to do this are already available.

It is important to understand that entropy must be evolved for each generation, for otherwise the random number sequence would be predictable. Various means dependent on external events, such as keystroke intervals, can be used to do this and some systems have built-in entropy sources. Suitable means are described in the OpenSSL software documentation, but are outside the scope of this page.

The entropy seed used by the OpenSSL library is contained in a file, usually called .rnd, which must be available when starting the NTP daemon or the ntp-keygen program. The NTP daemon will first look for the file using the path specified by the randfile subcommand of the crypto configuration command. If not specified in this way, or when starting the ntp-keygen program, the OpenSSL library will look for the file using the path specified by the RANDFILE environment variable in the user home directory, whether root or some other user. If the RANDFILE environment variable is not present, the library will look for the .rnd file in the user home directory. Since both the ntp-keygen program and ntpd(1) daemon must run as root, the logical place to put this file is in /.rnd or /root/.rnd.<

ملفات البيانات التشفيرية

تبدأ جميع تنسيقات الملفات بسطرين غير مشفرين. يحتوي السطر الأول على اسم الملف، بما في ذلك اسم المضيف الذي تم إنشاؤه والطابع الزمني للملف، بالتنسيق ntpkey_key _ name. filestamp، حيث key هو نوع المفتاح أو المعلمة، name هو اسم المضيف أو المجموعة، و filestamp هو الطابع الزمني للملف (ثواني NTP) عند إنشاء الملف. حسب الاتفاق، تتضمن أسماء key في أسماء الملفات التي تم إنشاؤها أحرفًا كبيرة وصغيرة، بينما تتضمن أسماء key في أسماء الروابط التي تم إنشاؤها أحرفًا صغيرة فقط. لا يتم استخدام الطابع الزمني للملف في أسماء الروابط التي تم إنشاؤها. يحتوي السطر الثاني على الطابع الزمني بتنسيق Unix date التقليدي. تعتبر الأسطر التي تبدأ بـ ‘#’ تعليقات ويتجاهلها برنامج ntp-keygen والبرنامج الخفي ntpd(1).

يحتوي باقي الملف على بيانات تشفيرية، يتم ترميزها أولاً باستخدام قواعد ASN.1، ثم تشفيرها إذا لزم الأمر، وأخيرًا كتابتها بنص ASCII قابل للطباعة مشفر بتنسيق PEM، مسبوقًا بأسطر معرف محتوى MIME وملحوقًا بها.

الشكل 1. ملف مفاتيح متماثل نموذجي

يوضح الشكل 1 ملف مفاتيح متماثل نموذجي تستخدمه التنفيذ المرجعي. بعد الرأس، يتم إدخال المفاتيح واحدًا لكل سطر بالتنسيق
keyno type key
حيث keyno هو عدد صحيح موجب في النطاق 1-65535؛ type هو نوع المفتاح لخوارزمية تلخيص الرسائل، والتي في حالة عدم وجود مكتبة OpenSSL يجب أن تكون MD5 للإشارة إلى خوارزمية تلخيص الرسائل MD5؛ إذا تم تثبيت مكتبة OpenSSL، فيمكن أن يكون نوع المفتاح أي خوارزمية تلخيص رسائل تدعمها تلك المكتبة؛ ومع ذلك، إذا كانت التوافقية مع FIPS 140-2 مطلوبة، فيجب أن يكون نوع المفتاح إما SHA أو SHA1؛ key هو المفتاح نفسه، وهو سلسلة ASCII قابلة للطباعة بطول 20 حرفًا أو أقل: يتم اختيار كل حرف من الأحرف القابلة للطباعة البالغ عددها 93 في النطاق من 0x21 إلى 0x7e ( ‘’! إلى ‘~’ ) باستثناء المسافة والحرف ‘#’، وينتهي بمسافة بيضاء أو حرف ‘#’. يتكون مفتاح OpenSSL من سلسلة ASCII مشفرة بالنظام الست عشري مكونة من 40 حرفًا، والتي يتم اقتطاعها حسب الضرورة.

لاحظ أن المفاتيح المستخدمة بواسطة البرنامجين ntpq(1) و ntpdc(1) يتم فحصها مقابل كلمات المرور التي تطلبها البرامج ويتم إدخالها يدويًا، لذلك من المناسب عمومًا تحديد هذه المفاتيح بتنسيق ASCII يمكن قراءته بواسطة الإنسان.

ينشئ البرنامج ntp-keygen ملف مفاتيح متماثلة ntpkey_MD5key_hostname. filestamp. نظرًا لأن الملف يحتوي على مفاتيح مشتركة خاصة، يجب أن يكون مرئيًا للجذر فقط ويتم توزيعه بوسائل آمنة على مضيفات الشبكة الفرعية الأخرى. يقوم البرنامج الخفي NTP بتحميل الملف ntp.keys، لذا يقوم ntp-keygen بتثبيت رابط ناعم من هذا الاسم إلى الملف الذي تم إنشاؤه. بعد ذلك، يجب تثبيت روابط ناعمة مماثلة يدويًا أو تلقائيًا على مضيفات الشبكة الفرعية الأخرى. في حين أن هذا الملف لا يستخدم مع بروتوكول Autokey الإصدار 2، إلا أنه مطلوب للمصادقة على بعض أوامر التكوين عن بعد التي تستخدمها أدوات nt p q(1) و ntpdc(1).

خيارات

-b imbits, --imbits=imbits

بتات معامل الهوية. يأخذ هذا الخيار عددًا صحيحًا كوسيط له. يتم تقييد قيمة imbits لتكون: 
في النطاق 256 إلى 2048

عدد البتات في معامل الهوية. الافتراضي هو 512.

-c scheme, --certificate=scheme

مخطط الشهادة.

المخطط هو أحد هذه الخيارات: RSA-MD2, RSA-MD5, RSA-MDC2, RSA-SHA, RSA-SHA1, RSA-RIPEMD160, DSA-SHA, أو DSA-SHA1.

حدد مخطط تشفير/تلخيص الرسائل لتوقيع الشهادة. لاحظ أنه يجب استخدام مخططات RSA مع مفتاح توقيع RSA ويجب استخدام مخططات DSA مع مفتاح توقيع DSA. الافتراضي بدون هذا الخيار هو RSA-MD5.

-C cipher, --cipher=cipher

شفرة المفتاح الخاص.

حدد الشفرة المستخدمة لتشفير الملفات التي تحتوي على مفاتيح خاصة. الافتراضي هو ثلاثي DES ثلاثي المفاتيح في وضع CBC، وهو ما يعادل "-C des-ede3-cbc". تسرد أداة openssl الشفرات المتاحة في مخرجات "openssl -h".

-d, --debug-level

زيادة مستوى تفاصيل التصحيح. يمكن أن يظهر هذا الخيار عددًا غير محدود من المرات.
-D number, --set-debug-level=number

تعيين مستوى تفاصيل التصحيح. يمكن أن يظهر هذا الخيار عددًا غير محدود من المرات. يأخذ هذا الخيار عددًا صحيحًا كوسيط له.
-e, --id-key

كتابة مفاتيح هوية IFF أو GQ.

اكتب المعلمات العامة من مفاتيح العميل IFF أو GQ إلى الإخراج القياسي. هذا مخصص لتوزيع المفاتيح تلقائيًا عبر البريد الإلكتروني.

-G, --gq-params

إنشاء معلمات ومفاتيح GQ.

إنشاء معلمات ومفاتيح لمخطط تعريف GQ، مما يلغي أي معلمات قد تكون موجودة.

-H, --host-key

إنشاء مفتاح مضيف RSA.

إنشاء مفاتيح مضيف جديدة، مما يلغي أي مفاتيح قد تكون موجودة.

-I, --iffkey

إنشاء معلمات IFF.

إنشاء معلمات لمخطط تعريف IFF، مما يلغي أي معلمات قد تكون موجودة.

-i group, --ident=group

تعيين اسم مجموعة Autokey.

تعيين اسم مجموعة Autokey الاختياري إلى name. يستخدم هذا في اسم الملف لملفات معلمات العميل IFF أو GQ أو MV. في هذا الدور، الافتراضي هو اسم المضيف إذا لم يتم توفير هذا الخيار. اسم المجموعة، إذا تم تحديده باستخدام -i/--ident أو باستخدام -s/--subject-name بعد حرف '@@'، هو أيضًا جزء من موضوع شهادة المضيف الموقعة ذاتيًا وأسماء المُصدر بالشكل host@@group ويجب أن يتطابق مع ملف تكوين ntpd.

-l lifetime, --lifetime=lifetime

تعيين مدة صلاحية الشهادة. يأخذ هذا الخيار عددًا صحيحًا كوسيط له.

تعيين انتهاء صلاحية الشهادة إلى lifetime يومًا من الآن.

-m modulus, --modulus=modulus

معامل أولي. يأخذ هذا الخيار عددًا صحيحًا كوسيط له. يتم تقييد قيمة modulus لتكون: 
في النطاق 256 إلى 2048

عدد البتات في المعامل الأولي. الافتراضي هو 512.

-M, --md5key

إنشاء مفاتيح متماثلة.

إنشاء مفاتيح متماثلة، مما يلغي أي مفاتيح قد تكون موجودة.

-P, --pvt-cert

إنشاء شهادة خاصة PC.

إنشاء شهادة خاصة. افتراضيًا، ينشئ البرنامج شهادات عامة.

-p passwd, --password=passwd

كلمة مرور خاصة محلية.

يتم تشفير الملفات المحلية التي تحتوي على بيانات خاصة باستخدام خوارزمية DES-CBC وكلمة المرور المحددة. يجب تحديد نفس كلمة المرور للبرنامج المحلي ntpd عبر أمر التكوين "crypto pw password". كلمة المرور الافتراضية هي اسم المضيف المحلي.

-q passwd, --export-passwd=passwd

تصدير مفاتيح مجموعة IFF أو GQ بكلمة مرور.

تصدير مفاتيح مجموعة هوية IFF أو GQ إلى الإخراج القياسي، مشفرة بخوارزمية DES-CBC وكلمة المرور المحددة. يجب تحديد نفس كلمة المرور للبرنامج البعيد ntpd عبر أمر التكوين "crypto pw password". انظر أيضًا الخيار --id-key (-e) للتصديرات غير المشفرة.

-s host@group, --subject-name=host@group

تعيين اسم المضيف ومجموعة الاختيارية.

تعيين اسم المضيف Autokey، واسم المجموعة الاختياري الذي يتبع حرف '@@'. يستخدم اسم المضيف في اسم الملف لشهادات المضيف وشهادات التوقيع التي تم إنشاؤها، بدون اسم المجموعة. يستخدم اسم المضيف، واسم المجموعة إذا تم توفيره، بالشكل host@@group لـ

-S sign, --sign-key=sign


إنشاء مفتاح توقيع (RSA أو DSA).

قم بإنشاء مفتاح توقيع جديد من النوع المحدد، مما يلغي أي مفتاح قد يكون موجودًا. افتراضيًا، يستخدم البرنامج مفتاح المضيف كمفتاح توقيع.

-T, --trusted-cert

شهادة موثوق بها (مخطط TC).

قم بإنشاء شهادة موثوق بها. افتراضيًا، يقوم البرنامج بإنشاء شهادة غير موثوق بها.

-V num, --mv-params=num

إنشاء عدد num من معلمات MV. يأخذ هذا الخيار عددًا صحيحًا كوسيط له.

قم بإنشاء المعلمات والمفاتيح لمخطط التعريف Mu-Varadharajan (MV).

-v num, --mv-keys=num

تحديث عدد num من مفاتيح MV. يأخذ هذا الخيار عددًا صحيحًا كوسيط له.

لم يتم توثيق هذا الخيار بشكل كامل.

-?, --help

عرض معلومات الاستخدام والخروج.
-!, --more-help

تمرير معلومات الاستخدام الموسعة عبر عارض.
-> [cfgfile], --save-opts [=cfgfile]

حفظ حالة الخيارات في cfgfile. الافتراضي هو آخر ملف تهيئة مدرج في قسم إعدادات الخيارات، أدناه. سيخرج الأمر بعد تحديث ملف التهيئة.
-< cfgfile, --load-opts=cfgfile, --no-load-opts

تحميل الخيارات من cfgfile. سيقوم النموذج no-load-opts بتعطيل تحميل ملفات التهيئة / RC / INI السابقة. تتم معالجة --no-load-opts في وقت مبكر، خارج الترتيب.
--version [{v|c|n}]

إخراج إصدار البرنامج والخروج. الوضع الافتراضي هو "v"، وهو إصدار بسيط. سيقوم الوضع "c" بطباعة معلومات حقوق النشر وسيتم طباعة إشعار حقوق النشر الكامل بواسطة "n".

إعدادات الخيارات

يمكن تعيين أي خيار غير محدد كـ غير قابل للتعيين مسبقًا عن طريق تحميل القيم من ملفات التهيئة ("RC" أو ".INI") والمتغيرات البيئية التي تحمل الأسماء:

  NTP_KEYGEN_<option-name> أو NTP_KEYGEN

تأخذ الإعدادات البيئية الأسبقية (تتم معالجتها لاحقًا) لملفات التهيئة. ملفات homerc هي "$HOME" و ".". إذا كان أي من هذه الأدلة عبارة عن أدلة، فسيتم البحث عن ملف .ntprc داخل تلك الأدلة.

حالة الخروج

سيتم إرجاع أحد قيم الخروج التالية:

0 (EXIT_SUCCESS)

نجاح تنفيذ البرنامج.
1 (EXIT_FAILURE)

فشلت العملية أو لم يكن تركيب الأمر صالحًا.
66 (EX_NOINPUT)

لم يمكن تحميل ملف تهيئة محدد.
70 (EX_SOFTWARE)

واجهت libopts خطأ تشغيلي داخلي. يرجى الإبلاغ عنه إلى autogen-users@lists.sourceforge.net. شكرًا لك.
