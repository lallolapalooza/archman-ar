ntpd.conf(5)

الحزمة: openntpd

التراخيص: BSD

NTPD.CONF(5) دليل تنسيقات الملفات NTPD.CONF(5)

الاسم

ntpd.conf — ملف تكوين خادم بروتوكول الوقت الشبكي

الوصف

تصف صفحة الدليل هذه تنسيق ملف التكوين لـ ntpd(8).

ntpd.conf له التنسيق التالي:

يتم تجاهل الأسطر الفارغة والأسطر التي تبدأ بالحرف ‘#’.

يمكن تحديد الكلمات المفتاحية عدة مرات داخل ملف التكوين. خيارات التكوين الأساسية هي كما يلي:

listen on العنوان [rtable معرف الجدول]
ntpd(8) لديه القدرة على مزامنة الساعة المحلية مع خوادم NTP عن بعد، وإذا تم تحديد هذا التوجيه، يمكن أن يعمل كخادم NTP نفسه، مع إعادة توزيع الساعة المحلية.

حدد عنوان IP محلي أو اسم مضيف يجب أن يستمع إليه خادم ntpd(8) لتمكين مزامنة العملاء عن بعد. إذا ظهر عدة مرات، سيستمع ntpd(8) على كل عنوان محدد. إذا تم إعطاء ‘*’ كعنوان، سيستمع ntpd(8) على جميع العناوين المحلية باستخدام جدول التوجيه المحدد. ntpd(8) لا يستمع على أي عنوان بشكل افتراضي. الكلمة المفتاحية الاختيارية rtable ستحدد جدول التوجيه الذي سيتم الاستماع عليه، إذا كان نظام التشغيل يدعم نطاقات التوجيه. بشكل افتراضي، سيستمع ntpd(8) باستخدام جدول التوجيه الحالي. على سبيل المثال:

listen on *

أو

listen on 127.0.0.1
listen on ::1
listen on 127.0.0.1 rtable 4
query from عنوان المصدر
حدد عنوان IP محلي يجب أن يستخدمه خادم ntpd(8) للاستعلامات الصادرة إلى الخوادم المحددة لاحقًا، وهو مفيد على الأجهزة ذات الواجهات المتعددة. على سبيل المثال: 
query from 192.0.2.1
query from 2001:db8::1
sensor الجهاز [correction ميكروثانية] [refid معرف السلسلة] [stratum قيمة الطبقة] [trusted] [weight قيمة الوزن]
حدد جهاز قياس فرق الوقت ntpd(8) الذي يجب استخدامه، إذا كان نظام التشغيل يدعم أجهزة القياس. يمكن تحديد جهاز القياس عدة مرات: ntpd(8) سيستخدم كل جهاز قياس محدد موجود بالفعل. يتم تجاهل أجهزة القياس غير الموجودة. إذا تم إعطاء ‘*’ كاسم جهاز، سيستخدم ntpd(8) جميع أجهزة قياس فرق الوقت التي يجدها. ntpd(8) لا يستخدم أي جهاز قياس فرق الوقت بشكل افتراضي. على سبيل المثال: 
sensor *
sensor nmea0

يمكن إعطاء correction بالميكروثانية للتعويض عن إزاحة جهاز القياس. الحد الأقصى للتصحيح هو 127 ثانية. على سبيل المثال، إذا كان مستقبل DCF77 متأخرًا بمقدار 70 مللي ثانية عن الوقت الفعلي:

sensor udcf0 correction 70000

يمكن إعطاء refid معرف السلسلة يصل إلى 4 أحرف ASCII لنشر نوع جهاز القياس للعملاء. يقترح RFC 2030 بعض معرفات المراجع الشائعة، ولكن يمكن "اختراع معرفات جديدة حسب الاقتضاء". إذا لم يتم إعطاء معرف السلسلة، سيستخدم ntpd(8) معرف مرجع عام. على سبيل المثال:

sensor nmea0 refid GPS

يمكن استخدام الكلمة المفتاحية stratum لتغيير قيمة الطبقة من القيمة الافتراضية 1.

الكلمة المفتاحية trusted تشير إلى أن الوقت المتعلم آمن وموثوق به وغير معرض لهجمات الوسيط، لذلك يتم تخطي التحقق من constraints. هذا مفيد لتصحيح وقت التشغيل في البيئات التي لا يمكن فيها استخدام constraints.

الكلمة المفتاحية weight تسمح بتحكم أدق في الأهمية النسبية لمصادر الوقت (خوادم أو أجهزة قياس). يتم تحديد الأوزان في النطاق من 1 إلى 10؛ إذا لم يتم إعطاء وزن، فالقيمة الافتراضية هي 1. خادم بوزن 5، على سبيل المثال، سيكون له تأثير أكبر بخمس مرات على حساب انحراف الوقت مقارنة بخادم بوزن 1.

server العنوان [trusted] [weight قيمة الوزن]
حدد عنوان IP أو اسم المضيف لخادم NTP للمزامنة معه. إذا ظهر عدة مرات، سيحاول ntpd(8) المزامنة مع جميع الخوادم المحددة. إذا كان اسم المضيف يحل إلى عناوين IPv4 و/أو IPv6 متعددة، يستخدم ntpd(8) العنوان الأول. إذا لم يحصل على رد، يعيد ntpd(8) المحاولة مع العنوان التالي ويستمر في ذلك حتى يتم العثور على عنوان يعمل. على سبيل المثال: 
server 10.0.0.2 weight 5
server ntp.example.org weight 1

لتوفير التكرار، من الممارسات الجيدة تكوين خوادم متعددة. بشكل عام، يتم الحصول على أفضل دقة باستخدام الخوادم ذات زمن الاستجابة الشبكي المنخفض.

servers العنوان [trusted] [weight قيمة الوزن]
كما هو الحال مع server، حدد عنوان IP أو اسم المضيف لخادم NTP للمزامنة معه. إذا ظهر عدة مرات، سيحاول ntpd(8) المزامنة مع جميع الخوادم المحددة. في حال حل اسم المضيف إلى عناوين IP متعددة، سيحاول ntpd(8) المزامنة معها جميعًا. على سبيل المثال: 
servers pool.ntp.org
servers pool.ntp.org weight 5

القيود

ntpd(8) يمكن تكوينه للاستعلام عن 'التاريخ' من خوادم HTTPS موثوق بها عبر TLS. لا تستخدم هذه المعلومات الزمنية للدقة ولكنها تعمل كقيود مصادق عليها، مما يقلل من تأثير هجمات الوسيط غير المصادق عليها لـ NTP. سيتم تجاهل حزم NTP المستلمة بمعلومات الوقت التي تقع خارج نطاق قريب من القيد، وسيتم تمييز خوادم NTP هذه على أنها غير صالحة.

الدعم للقيود متاح فقط إذا تم ربط ntpd(8) مع libtls من LibreSSL. تكوين قيد بدون libtls يتسبب في أن يقوم ntpd(8) بتسجيل رسالة تحذير عند بدء التشغيل.

constraint from url [ip...]
حدد عنوان URL أو عنوان IP أو اسم المضيف لخادم HTTPS لتوفير قيد. إذا تبع عنوان URL عنوان أو أكثر، فسيتم تجربة عنوان URL والعناوين حتى يتم العثور على عنوان يعمل. يؤخذ مسار عنوان URL واسم الشهادة المتوقع دائمًا من عنوان URL المحدد. إذا تم استخدام constraint from أكثر من مرة، فسيقوم ntpd(8) بحساب قيد وسيط من جميع الخوادم المحددة. 
server ntp.example.org
constraint from www.example.com
constraint from "https://9.9.9.9" "2620:fe::9"
constraints from url
كما هو الحال مع constraint from، حدد عنوان URL أو عنوان IP أو اسم المضيف لـ HT

ntpd.conf(5) — OpenBSD manual pages

DESCRIPTION

ntpd.conf is the configuration file for the ntpd(8) daemon.

The file is located in /etc/ntpd.conf. It contains configuration directives, one per line. Lines starting with a # character are comments. The configuration file is parsed by ntpd(8) at startup.

The following directives are supported:

servers ...
This directive specifies the NTP servers that the daemon will synchronize to. The arguments are space-separated host names or IP addresses of NTP servers. If the ntpd.conf file contains no servers directive, ntpd(8) will try to contact the NTP servers listed in /etc/openntpd/ntp.conf, if it exists.
constraints ...
This directive specifies NTP servers that will be used as constraints. Constraints are NTP servers that are assumed to be correct. This directive can be used to override the default behavior of ntpd(8), which is to not trust any NTP server unless it has been verified.

If a hostname resolves to multiple IP addresses, ntpd(8) will calculate a median constraint from all of them. For example:

servers pool.ntp.org
constraints from "https://www.google.com/"
