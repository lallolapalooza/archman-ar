Data Types

The netCDF data model supports the following basic types:

byte
An 8-bit unsigned value. The zero byte has no special significance.
char
An 8-bit unsigned value. The technical interpretation is that it is an unsigned 8-bit value. The encoding of the 256 possible values is unspecified by default. A variable of char type may be marked with an "_Encoding" attribute to indicate the character set to be used: US-ASCII, ISO-8859-1, etc. Note that specifying the encoding of UTF-8 is equivalent to specifying US-ASCII This is because multi-byte UTF-8 characters cannot be stored in an 8-bit character. The only legal single byte UTF-8 values are by definition the 7-bit US-ASCII encoding with the top bit set to zero.
short
A 16-bit signed value.
int
A 32-bit signed value.
long
A synonym for int in CDL declarations, but is deprecated since there are now platforms with 64-bit representations for C longs.
float
A 32-bit IEEE normalized single-precision floating point number.
double
A 64-bit IEEE standard normalized double-precision floating point number.
int64
A 64-bit signed value.
ubyte
An 8-bit unsigned value.
ushort
A 16-bit unsigned value.
uint
A 32-bit unsigned value.
ulong
A synonym for uint in CDL declarations, but is deprecated since there are now platforms with 64-bit representations for C ulongs.
uint64
A 64-bit unsigned value.
string
A sequence of characters.

Variable names may be specified in either upper or lower case.

Bytes are intended to hold a full eight bits of data, and the zero byte has no special significance, as it mays for character data. ncgen converts byte declarations to char declarations in the output C code and to the nonstandard BYTE declaration in output Fortran code.

Shorts can hold values between -32768 and 32767. ncgen converts short declarations to short declarations in the output C code and to the nonstandard INTEGER*2 declaration in output Fortran code.

Ints can hold values between -2147483648 and 2147483647. ncgen converts int declarations to int declarations in the output C code and to INTEGER declarations in output Fortran code. long is accepted as a synonym for int in CDL declarations, but is deprecated since there are now platforms with 64-bit representations for C longs.

Int64 can hold values between -9223372036854775808 and 9223372036854775807. ncgen converts int64 declarations to longlong declarations in the output C code.

Floats can hold values between about -3.4+38 and 3.4+38. Their external representation is as 32-bit IEEE normalized single-precision floating point numbers. ncgen converts float declarations to float declarations in the output C code and to REAL declarations in output Fortran code. real is accepted as a synonym for float in CDL declarations.

Doubles can hold values between about -1.7+308 and 1.7+308. Their external representation is as 64-bit IEEE standard normalized double-precision floating point numbers. ncgen converts double declarations to double declarations in the output C code and to DOUBLE PRECISION declarations in output Fortran code.

The unsigned counterparts of the above integer types are mapped to the corresponding unsigned C types. Their ranges are suitably modified to start at zero.

The technical interpretation of the char type is that it is an unsigned 8-bit value. The encoding of the 256 possible values is unspecified by default. A variable of char type may be marked with an "_Encoding" attribute to indicate the character set to be used: US-ASCII, ISO-8859-1, etc. Note that specifying the encoding of UTF-8 is equivalent to specifying US-ASCII This is because multi-byte UTF-8 characters cannot be stored in an 8-bit character. The only legal single byte UTF-8 values are by definition the 7-bit US-ASCII encoding with the top bit set to zero.

Strings are assumed by default to be encoded using UTF-8. Note that this means that multi-byte UTF-8 encodings may be present in the string, so it is possible that the number of distinct UTF-8 characters in a string is smaller than the number of 8-bit bytes used to store the string.

ثوابت CDL

يمكن تعيين ثوابت للسمات أو المتغيرات من أي من أنواع netCDF الأساسية. تشبه صيغة الثوابت صيغة C، باستثناء أنه يجب إلحاق لاحقات النوع بالقيم القصيرة والعائمة للتمييز بينها وبين القيم الطويلة والمزدوجة.

يتم تمثيل ثابت byte كثابت عددي مع إضافة `b' (أو `B'). في واجهة برمجة التطبيقات القديمة لـ netCDF-2، كان يمكن أيضًا تمثيل ثوابت البايت باستخدام أحرف فردية أو تسلسلات هروب أحرف C القياسية مثل `a' أو `0. ولا يزال هذا مدعومًا للتوافق مع الإصدارات السابقة، ولكنه مهمل لجعله التمييز واضحًا بين نوع البايت الرقمي ونوع الحرف النصي. تشمل أمثلة ثوابت البايت:

 0b             // بايت صفري
 -1b            // -1 كبايت 8 بت
 255b           // أيضًا -1 كبايت 8 بت موقع

تهدف ثوابت الأعداد الصحيحة short إلى تمثيل الكميات الموقعة ذات 16 بت. شكل ثابت short هو ثابت عددي مع إضافة `s' أو `S'. إذا بدأ ثابت short بـ `0'، فسيتم تفسيره على أنه رقم ثماني، إلا إذا بدأ بـ `0x'، فسيتم تفسيره كثابت سداسي عشري. على سبيل المثال:

-2s	// قيمة قصيرة -2
0123s	// ثماني
0x7ffs  // سداسي عشري

تهدف ثوابت الأعداد الصحيحة int إلى تمثيل الكميات الموقعة ذات 32 بت. شكل ثابت int هو ثابت عددي عادي، على الرغم من أنه من المقبول اختياريًا إضافة `l' أو `L' فردية (مرة أخرى، تم إهمالها). كن حذرًا، ومع ذلك، يتم تفسير اللاحقة L كرقم صحيح 32 بت، ولا تفسر أبدًا كرقم صحيح 64 بت. يمكن أن يكون هذا مربكًا نظرًا لأن نوع C long يمكن أن يكون بشكل غامض 32 بت أو 64 بت.

إذا بدأ ثابت int بـ `0'، فسيتم تفسيره على أنه رقم ثماني، إلا إذا بدأ بـ `0x'، فسيتم تفسيره كثابت سداسي عشري (ولكن انظر الثوابت المبهمة أدناه). تشمل الأمثلة على ثوابت int الصالحة:

-2
1234567890L
0123		// ثماني
0x7ff		// سداسي عشري

تهدف ثوابت الأعداد الصحيحة int64 إلى تمثيل الكميات الموقعة ذات 64 بت. شكل ثابت int64 هو ثابت عددي مع إضافة `ll' أو `LL'. إذا بدأ ثابت int64 بـ `0'، فسيتم تفسيره على أنه رقم ثماني، إلا إذا بدأ بـ `0x'، فسيتم تفسيره كثابت سداسي عشري. على سبيل المثال:

-2ll	// قيمة غير موقعة -2
0123LL	// ثماني
0x7ffLL  // سداسي عشري

الثوابت ذات النقطة العائمة من نوع float مناسبة لتمثيل بيانات النقطة العائمة بحوالي سبعة أرقام ذات دقة مهمة. شكل ثابت float هو نفس شكل ثابت C ذي النقطة العائمة مع إضافة `f' أو `F'. على سبيل المثال، الثوابت التالية كلها ثوابت float مقبولة:

-2.0f
3.14159265358979f	// سيتم اقتطاعها لدقة أقل
1.f

الثوابت ذات النقطة العائمة من نوع double مناسبة لتمثيل بيانات النقطة العائمة بحوالي ستة عشر رقمًا ذا دقة مهمة. شكل ثابت double هو نفس شكل ثابت C ذي النقطة العائمة. يمكن إضافة `d' أو `D' اختياريًا. على سبيل المثال، الثوابت التالية كلها ثوابت double مقبولة:

-2.0
3.141592653589793
1.0e-20
1.d

يمكن إنشاء ثوابت الأعداد الصحيحة غير الموقعة عن طريق إضافة الحرف 'U' أو 'u' بين الثابت وأي لاحقة حجم لاحقة، أو مباشرة في نهاية لاحقة الحجم. لذلك يمكن للمرء أن يقول 10U، 100su، 100000ul، أو 1000000llu، على سبيل المثال.

يمكن إحاطة ثوابت الأحرف الفردية بعلامات اقتباس مفردة. إذا تم إحاطة تسلسل من حرف واحد أو أكثر بعلامات اقتباس مزدوجة، فيجب استنتاج تفسيرها من السياق. إذا تم إنشاء مجموعة البيانات باستخدام نموذج netCDF الكلاسيكي، فسيتم تفسير جميع هذه الثوابت كمصفوفة أحرف، لذلك يتم تفسير كل حرف في الثابت كما لو كان حرفًا فرديًا. إذا كانت مجموعة البيانات هي netCDF الموسعة، فيمكن تفسير الثابت كما هو الحال بالنسبة للنموذج الكلاسيكي أو كسلسلة نصية حقيقية (انظر أدناه) اعتمادًا على نوع السمة أو المتغير الذي يتم تضمين السلسلة فيه.

تفسير ثوابت الأحرف هو أن تلك التي تقع في نطاق ASCII القابل للطباعة (' '..'~') يُفترض أنها مشفرة كجزء من UTF-8 ذي بايت واحد، وهو ما يعادل US-ASCII. في جميع الحالات، يتم احترام اتفاقيات هروب سلاسل C المعتادة للقيم من 0 إلى 127. يُسمح بالقيم الأكبر من 127، ولكن ترميزها غير محدد. بالنسبة لـ netCDF الموسعة، يتم إهمال استخدام نوع الحرف لصالح نوع السلسلة.

بعض أمثلة ثوابت الأحرف هي كالتالي:

 'a'		// ASCII `a'
 "a"		// مكافئ لـ 'a'
 "Two\nlines\n"	// سلسلة من 10 أحرف مع سطرين مضمنين
 "a bell:\007"	// سلسلة تحتوي على جرس ASCII
لاحظ أن مصفوفة الأحرف netCDF "a" ستناسب متغيرًا بعنصر واحد، نظرًا لأنه لا يفترض وجود حرف NULL منهٍ. ومع ذلك، يتم تفسير البايت الصفري في مصفوفة الأحرف كنهاية للأحرف الهامة بواسطة برنامج ncdump، باتباع اصطلاح C. لذلك، لا ينبغي تضمين بايت NULL في سلسلة أحرف ما لم يكن في النهاية: استخدم نوع البيانات byte بدلاً من ذلك لمصفوفات البايت التي تحتوي على البايت الصفري.

يتم تمثيل ثوابت String، مثل ثوابت الأحرف، باستخدام علامات اقتباس مزدوجة. يمثل هذا غموضًا محتملاً حيث قد تشير سلسلة متعددة الأحرف أيضًا إلى قيمة أحرف ذات أبعاد. عادةً ما يحدث إزالة الغموض عن طريق السياق، ولكن يجب توخي الحذر لتحديد نوع string لضمان الاختيار الصحيح. يُفترض أن ثوابت السلسلة دائمًا مشفرة بـ UTF-8. هذا يعني على وجه التحديد أن ثابت السلسلة قد يحتوي بالفعل على أحرف UTF-8 متعددة البايتات. يمكن استخدام الثابت الخاص `NIL' لتمثيل سلسلة فارغة، وهي ليست نفس سلسلة صفرية الطول.

يتم تمثيل ثوابت Opaque كتسلسلات من الأرقام السداسية عشرية مسبوقة بـ 0X أو 0x: 0xaa34ffff، على سبيل المثال. لا تزال هذه الثوابت يمكن استخدامها كثوابت عددية وسيتم اقتطاعها أو تمديدها حسب الضرورة.

تعبيرات الثوابت المركبة

من أجل تعيين قيم للمتغيرات (أو السمات) التي يكون نوعها نوعًا محددًا من قبل المستخدم، تم توسيع صيغة الثوابت لتشمل تسلسلات من الثوابت المغلقة بين أقواس معقوفة (مثل ""{"..."}"). يسمى هذا الثابت ثابتًا مركبًا، ويمكن تداخل الثوابت المركبة.

بالنظر إلى النوع "T(*) vlen_t"، حيث T هو نوع أساسي آخر عشوائي، يجب تحديد الثوابت لهذا على النحو التالي.

    vlen_t var[2] = {t11,t12,...t1N}, {t21,t22,...t2m};
يُفترض أن تكون قيم tij هي ثوابت من النوع T.

بالنظر إلى النوع "compound cmpd_t {T1 f1; T2 f2...Tn fn}"، حيث Ti هي أنواع أساسية عشوائية أخرى، يجب تحديد الثوابت لهذا على النحو التالي.

    cmpd_t var[2] = {t11,t12,...t1N}, {t21,t22,...t2n};
يُفترض أن تكون قيم tij ثوابت من النوع Ti. إذا كانت الحقول مفقودة، فسيتم تعيينها باستخدام أي قيمة تعبئة محددة أو افتراضية لنوع الأساس للحقل.

يتم تعريف المجموعة العامة من القواعد الخاصة باستخدام الأقواس المعقوفة في القسم تحديد قوائم البيانات أدناه.

قواعد النطاق

مع إضافة المجموعات، لم يعد مساحة الأسماء للكائنات المعرفة مسطحة. يمكن إضافة بادئة للمراجع (الأسماء) من أي نوع أو بُعد أو متغير بالمسار المطلق الذي يحدد إعلانًا معينًا. وبالتالي قد يقول المرء

    variables:
        /g1/g2/t1 v1;

النوع الذي تتم الإشارة إليه (t1) هو النوع الموجود داخل المجموعة g2، والتي بدورها متداخلة في المجموعة g1. التشابه بين هذه الصيغة ومسارات ملفات Unix متعمد، ويمكن اعتبار المجموعات شكلاً من أشكال الدليل.

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.
