RETURN VALUE

Unless otherwise noted, functions that return an integer return OK on success and ERR on failure. Functions that return pointers return NULL on failure. Typically, ncurses treats a null pointer passed as a function parameter as a failure. ENVIRONMENT

The following symbols from the process environment customize the runtime behavior of ncurses applications. The library may be configured to disregard the variables TERMINFO, TERMINFO_DIRS, TERMPATH, and HOME, if the user is the superuser (root), or the application uses setuid(2) or setgid(2).

BAUDRATE

The debugging library checks this variable when the application has redirected output to a file. Its integral value is used for the baud rate. If that value is absent or invalid, ncurses uses 9600. This feature allows testers to construct repeatable test cases that take into account optimization decisions that depend on baud rate.

CC (command character)

When set, the command_character (cmdch) capability value of loaded terminfo entries changes to the value of this variable. Very few terminfo entries provide this feature.

Because this name is also used in development environments to represent the C compiler's name, ncurses ignores its value if it is not one character in length.

COLUMNS

This variable specifies the width of the screen in characters. Applications running in a windowing environment usually are able to obtain the width of the window in which they are executing. If COLUMNS is not defined and the terminal's screen size is not available from the terminal driver, ncurses uses the size specified by the columns (cols) capability of the terminal type's entry in the terminfo database, if any.

It is important that your application use the correct screen size. Automatic detection thereof is not always possible because an application may be running on a host that does not honor NAWS (Negotiations About Window Size) or as a different user ID than the owner of the terminal device file. Setting COLUMNS and/or LINES overrides the library's use of the screen size obtained from the operating system.

The COLUMNS and LINES variables may be specified independently. This property is useful to circumvent misfeatures of legacy terminal type descriptions; xterm(1) descriptions specifying 65 lines were once notorious. For best results, avoid specifying cols and lines capability codes in terminfo descriptions of terminal emulators.

ESCDELAY

لكي تتمكن curses من التمييز بين حرف ESC الناتج عن ضغطة المستخدم على مفتاح "Escape" في جهاز الإدخال وبين حرف يبدأ "تسلسل هروب" (كما ينتجه عادة مفاتيح الوظائف)، فإنها تنتظر بعد استلام حرف الهروب لمعرفة ما إذا كانت هناك أحرف إضافية متاحة في مجرى الإدخال خلال فترة زمنية قصيرة. المتغير العام ESCDELAY يخزن هذه الفترة بالمللي ثانية. القيمة الافتراضية 1000 (ثانية واحدة) كافية لمعظم الاستخدامات. متغير البيئة هذا يلغيها.

الحالة الأكثر شيوعًا التي قد ترغب فيها بتغيير هذه القيمة هي العمل مع مضيف بعيد عبر قناة اتصال بطيئة. إذا لم يتلق المضيف الذي يشغل تطبيق curses أحرف تسلسل الهروب في الوقت المناسب، فقد تفسر المكتبة هذه الأحرف كأحداث ضغطات مفاتيح متعددة.

أحداث الماوس في xterm(1) هي شكل من أشكال تسلسلات الهروب؛ لذلك، إذا كان تطبيقك يستخدم النقر المتعدد بشكل مكثف، فقد ترغب في زيادة القيمة الافتراضية لأن التأخير ينطبق على حدث النقر المتعدد المركب وكذلك على النقرات الفردية.

لا ينبغي للتطبيقات المحمولة الاعتماد على وجود ESCDELAY بأي من الشكلين، ولكن تعيين متغير البيئة بدلاً من المتغير العام لا يخلق مشاكل عند تجميع التطبيق.

إذا تم تعطيل keypad(3X) لنافذة curses التي تستقبل الإدخال، فيجب على البرنامج تمييز تسلسلات الهروب بنفسه.

هذا المكافئ لـ COLUMNS يحدد ارتفاع الشاشة بالأحرف. قدرة terminfo المقابلة ورمزها هو lines. انظر وصف المتغير COLUMNS أعلاه.

(منفذ OS/2 EMX فقط) يقوم OS/2 بترقيم فأرة بثلاثة أزرار بشكل غير متسق مع المنصات الأخرى، بحيث يكون 1 هو الزر الأيسر، و 2 هو الزر الأيمن، و 3 هو الزر الأوسط. يقوم هذا المتغير بتخصيص ترقيم أزرار الماوس. يجب أن تكون قيمته ثلاثة أرقام من 1 إلى 3 بأي ترتيب. افتراضيًا، تفترض ncurses ترقيمًا "132".

NCURSES_ASSUMED_COLORS

إذا تم تعيينه، يلغي هذا المتغير الافتراض المدمج في مكتبة ncurses بأن الألوان الافتراضية للطرفية هي الأبيض على الأسود؛ انظر default_colors(3X). قم بتعيين قيم الألوان الأمامية والخلفية باستخدام متغير البيئة هذا عن طريق تعيين قيمتين رقميتين مفصولتين بفاصلة، تشيران إلى أرقام الألوان الأمامية والخلفية على التوالي.

على سبيل المثال، لإخبار ncurses بعدم افتراض أي شيء عن الألوان، استخدم قيمة "-1,-1". لجعل مخطط الألوان الافتراضي أخضر على أسود، استخدم "2,0". تقبل ncurses القيم الصحيحة من -1 حتى قيمة قدرة terminfo max_colors (colors).

NCURSES_CONSOLE2

(منفذ MinGW فقط) برنامج Console2 يتعامل بشكل معيب مع استدعاء واجهة برمجة تطبيقات Microsoft Console CreateConsoleScreenBuffer. التطبيقات التي تستخدمه تتجمد. ومع ذلك، من الممكن محاكاة عمل هذا الاستدعاء عن طريق تعيين الإحداثيات، وحفظ محتويات الشاشة الأصلية واستعادتها بشكل صريح. تعيين متغير البيئة NCGDB له نفس التأثير.

NCURSES_GPM_TERMS

(Linux فقط) عندما يتم تكوين ncurses لاستخدام واجهة GPM، قد يسرد هذا المتغير اسم طرفية واحدة أو أكثر تتم مطابقة متغير TERM (انظر أدناه) معها. القيمة الفارغة تعطّل واجهة GPM، باستخدام دعم ncurses المدمج لبروتوكولات الماوس الخاصة بـ xterm(1) بدلاً من ذلك. إذا كان المتغير غائبًا، تحاول ncurses فتح GPM إذا كان TERM يحتوي على "linux".

NCURSES_NO_HARD_TABS

قد تستخدم ncurses أحرف علامة الجدولة (tab) في تحسين حركة المؤشر. في بعض الحالات، قد لا يتعامل برنامج تشغيل الطرفية الخاص بك معها بشكل صحيح. قم بتعيين متغير البيئة هذا إلى أي قيمة لتعطيل هذه الميزة. يمكنك أيضًا ضبط إعدادات stty(1) لتجنب المشكلة.

NCURSES_NO_MAGIC_COOKIE

تخزن العديد من الطرفيات سمات الفيديو كخاصية لخلية حرف، كما تفعل curses. تاريخيًا، سجل البعض تغييرات في سمات الفيديو كبيانات تشغل منطقيًا خلايا الأحرف على الشاشة، وتبدل السمات أو توقفها، بشكل مشابه للعلامات في لغة ترميز؛ تسمى هذه "بسكويت سحري" (magic cookies)، ويجب إعادة الكتابة فوقها لاحقًا. إذا لم يكن إدخال terminfo لنوع الطرفية الخاص بك يصف معالجتها للبسكويت السحري بشكل كافٍ، فقم بتعيين هذا المتغير إلى أي قيمة لإبلاغ ncurses بتعطيل السمات تمامًا.

NCURSES_NO_PADDING

تصف معظم أوصاف أنواع الطرفيات في قاعدة بيانات terminfo الأجهزة المادية. يستخدم العديد من الأشخاص تطبيقات تعتمد على curses في برامج محاكاة الطرفيات التي تعمل في بيئة نوافذ. يمكن لهذه البرامج تكرار جميع الميزات المهمة لطرفية مادية، ولكنها غالبًا ما تفتقر إلى قيودها. أبرز هذه العيوب الغائبة هي مشكلة إدارة تدفق البيانات؛ أي، الحد من سرعة الاتصال بما يمكن للأجهزة التعامل معه. ما لم يتم توصيل طرفية مادية بمركز طرفيات (الذي يقوم بالتحكم في التدفق)، يجب على التطبيق إدارة التحكم في التدفق بنفسه لمنع تجاوزات وفقدان البيانات.

أحد الحلول التي لا تتطلب أي تكلفة مادية هو أن يقوم التطبيق بالتوقف مؤقتًا بعد توجيه الطرفية لتنفيذ عملية تقوم بها ببطء، مثل مسح الشاشة. تدمج العديد من أوصاف أنواع الطرفيات، بما في ذلك VT100، مواصفات تأخير في القدرات. قد ترغب في استخدام أوصاف الطرفية هذه دون تحمل عقوبة الأداء. قم بتعيين NCURSES_NO_PADDING إلى أي قيمة لتعطيل جميع التأخيرات باستثناء التأخيرات الإلزامية. يتم استخدام التأخيرات الإلزامية من قبل قدرات الطرفية مثل flash_screen (flash).

NCURSES_NO_SETBUF

(مهمل) قبل التغييرات الداخلية التي تم تطويرها في ncurses 5.9 (رقع 20120825 إلى 20130126)، استخدمت المكتبة setbuf(3) لتمكين التخزين المؤقت الكامل للإخراج عند تهيئة الطرفية. تم القيام بذلك، كما في SVr4 curses، لزيادة الأداء. لأغراض الاختبار، لكل من ncurses وبعض التطبيقات، تم جعل هذه الميزة اختيارية. تعيين هذا المتغير عطّل التخزين المؤقت للإخراج، تاركًا مجرى الإخراج في الوضع الأصلي (عادةً ما يكون مخزنًا مؤقتًا للسطر).

في الوقت الحاضر، تقوم ncurses بالتخزين المؤقت الخاص بها ولا تتطلب هذا الحل البديل؛ لا تعدل تخزين مجرى الإخراج القياسي مؤقتًا. هذا النهج يجعل معالجة الإشارات، كما هو الحال مع المقاطعات، أكثر قوة. أحد العيوب هو أن بعض البرامج غير التقليدية خلطت استدعاءات stdio(3) مع استدعاءات ncurses (وعادةً ما حصلت على السلوك الذي توقعته). هذا لم يعد هو الحال؛ ncurses لا تكتب إلى واصف ملف الإخراج القياسي عبر مجرى مخزن مؤقت لـ stdio.

كحالة خاصة، لا تزال استدعاءات واجهة برمجة التطبيقات منخفضة المستوى مثل putp(3X) تستخدم مجرى الإخراج القياسي. استدعاءات curses عالية المستوى مثل printw(3X) لا تفعل ذلك.

NCURSES_NO_UTF8_ACS

عند التهيئة، تفحص ncurses متغير البيئة TERM لحالات خاصة حيث من المعروف أن أحرف رسم الخطوط من VT100 (وقدرات terminfo المقابلة لمجموعة الأحرف البديلة) غير مدعومة من قبل أنواع الطرفيات التي تدعي التوافق مع VT100. على وجه التحديد، عند التشغيل في بيئة لغة UTF-8، يتجاهلها جهاز وحدة التحكم الافتراضي Linux وبرنامج screen(1) الخاص بـ GNU. قم بتعيين هذا المتغير إلى قيمة غير صفرية لإبلاغ ncurses بأن دعم ACS معطل؛ ثم تقوم المكتبة بإخراج نقاط رمز Unicode التي تتوافق مع أحرف رسم الخطوط. قم بتعيينها إلى صفر (أو قيمة غير صحيحة) لتعطيل الفحص الخاص لأسماء أنواع الطرفيات التي تتطابق مع "linux" أو "screen"، مما يوجه ncurses للافتراض بأن ميزة ACS تعمل إذا وصف نوع الطرفية ذلك.

كبديل لاستخدام هذا المتغير، تبحث ncurses عن قدرة terminfo رقمية ممتدة U8 يمكن تجميعها باستخدام "tic -x". الأمثلة التالية.

# وحدة تحكم Linux، إذا تم ترقيعها لتوفير
# VT100 shift-in/shift-out، مع الخط المقابل.
linux-vt100|Linux console with VT100 line-graphics,
        U8#0, use=linux,
# uxterm مع تعيين خاصية vt100Graphics إلى false
xterm-utf8|xterm relying on UTF-8 line-graphics,
        U8#1, use=xterm,

تم اختيار الاسم المكون من حرفين "U8" للسماح باستخدامه عبر واجهة termcap الخاصة بـ ncurses.

NCURSES_TRACE

عند التهيئة، تتحقق ncurses (في تكوين التصحيح الخاص بها) من وجود هذا المتغير. إذا تم تعريفه بقيمة صحيحة، تستدعي المكتبة curses_trace(3X) مع تلك القيمة كوسيط.

TERM

يشير المتغير TERM إلى نوع الطرفية. كل نوع مميز، على الرغم من أن العديد منها متشابه. غالبًا ما يتم تعيينه بواسطة محاكيات الطرفيات لمساعدة التطبيقات في العثور على وصف طرفية قابل للعمل. يختار البعض تقريبًا شائعًا مثل "ansi" أو "vt100" أو "xterm" بدلاً من تطابق دقيق لقدراتها. في كثير من الأحيان، ستواجه التطبيقات مشاكل مع هذا النهج؛ على سبيل المثال، قد لا تعمل ضغطة مفتاح بشكل صحيح، أو قد تنتج تأثيرًا ولكن تظهر أحرفًا غير مفهومة على الشاشة.

تعيين TERM ليس له تأثير على التشغيل المادي؛ إنه يؤثر على الطريقة التي تتواصل بها التطبيقات مع الطرفية. وبالمثل، كقاعدة عامة (مع كون xterm(1) استثناءً نادرًا)، لا تغير محاكيات الطرفيات التي تسمح لك بتحديد TERM كمعامل أو قيمة تكوين سلوكها لمطابقة هذا الإعداد.

TERMCAP

إذا تم تكوين ncurses بدعم termcap، فإنها تبحث عن وصف نوع طرفية بتنسيق termcap إذا لم يكن هناك وصف بتنسيق terminfo متاحًا. تعيين هذا المتغير

riable directs ncurses لتجاهل موقع قاعدة بيانات termcap المعتاد، /etc/termcap؛ انظر TERMPATH أدناه. يجب أن يحتوي TERMCAP إما على وصف للطرفية (مع إزالة الأسطر الجديدة)، أو اسم ملف يشير إلى مكان تخزين المعلومات المطلوبة بواسطة متغير البيئة TERM.

TERMINFO

يمكن تهيئة ncurses لقراءة قواعد بيانات وصف أنواع الطرفيات في مواقع مختلفة باستخدام تنسيقات مختلفة. يتجاوز هذا المتغير الموقع الافتراضي.

  • يتم تخزين الأوصاف بتنسيق terminfo عادةً في شجرة دليل باستخدام أدلة فرعية مسماة بالأحرف الأولى الشائعة لأنواع الطرفيات المسماة فيها. هذا هو المخطط المستخدم في System V.
  • إذا تم تكوين ncurses لاستخدام قواعد بيانات مجزأة، فقد يسمي TERMINFO موقعها، مثل /usr/share/terminfo.db، بدلاً من /usr/share/terminfo/.

قاعدة البيانات المجزأة تستخدم مساحة أقل على القرص وهي أسرع قليلاً من شجرة الدلائل. ومع ذلك، تفترض بعض التطبيقات وجود شجرة الدلائل وتقرأها مباشرة بدلاً من استخدام واجهة برمجة تطبيقات terminfo.

  • إذا تم تكوين ncurses مع دعم termcap، فقد يحتوي هذا المتغير على موقع ملف termcap.
  • إذا كانت قيمة TERMINFO تبدأ بـ “hex:” أو “b64:”، فإن ncurses تستخدم ما تبقى من القيمة كوصف terminfo مجمّع. يمكنك إنتاج تنسيق base64 باستخدام infocmp(1M).
TERMINFO=$(infocmp -0 -Q2 -q)
export TERMINFO
يتم استخدام الوصف المجمّع فقط إذا كان يتوافق مع نوع الطرفية الذي يحدده TERM.

يعد تعيين TERMINFO هو أبسط طريقة، ولكنها ليست الوحيدة، لتوجيه ncurses إلى قاعدة بيانات الطرفية. مسار البحث هو كما يلي.

  • آخر قاعدة بيانات طرفية قامت بتطبيق ncurses قيد التشغيل بالكتابة إليها، إن وجدت
  • الموقع المحدد بواسطة متغير البيئة TERMINFO
  • $HOME/.terminfo
  • المواقع المدرجة في متغير البيئة TERMINFO_DIRS
  • الموقع (المواقع) التي تم تكوينها وتجميعها في ncurses
•
/usr/share/terminfo

TERMINFO_DIRS

يحدد هذا المتغير قائمة بالمواقع، تشبه PATH، التي يبحث فيها ncurses عن أوصاف أنواع الطرفيات الموضحة بواسطة TERMINFO أعلاه. يتم فصل عناصر القائمة بنقطتين فوق بعضهما (:) على Unix وفاصلة منقوطة (;) على OS/2 EMX. يفتقر terminfo الخاص بـ System V إلى ميزة مقابلة؛ TERMINFO_DIRS هو امتداد لـ ncurses.

TERMPATH

إذا لم يحتوي TERMCAP على وصف لنوع الطرفية أو اسم ملف، فإن ncurses تتحقق من محتويات TERMPATH، وهي قائمة بالمواقع، تشبه PATH، التي تبحث فيها عن أوصاف أنواع الطرفيات لـ termcap. يتم فصل عناصر القائمة بنقطتين فوق بعضهما (:) على Unix وفاصلة منقوطة (;) على OS/2 EMX.

إذا تم إلغاء تعيين كل من TERMCAP و TERMPATH أو كانا غير صالحين، فإن ncurses تبحث عن الملفات /etc/termcap، /usr/share/misc/termcap، و $HOME/.termcap، بهذا الترتيب.

تكوينات بديلة

من الممكن وجود العديد من تكوينات ncurses المختلفة، والتي يتم تحديدها بواسطة الخيارات المعطاة لبرنامج configure عند بناء المكتبة. قم بتشغيل البرنامج النصي مع الخيار --help لتصفحها جميعًا. هناك عدد قليل منها له أهمية خاصة لمطور التطبيقات الذي يستخدم ncurses.

--disable-overwrite
الاستدعاء القياسي لـ ncurses هو كما هو مذكور في SYNOPSIS:
#include <curses.h>

يتم استخدام هذا الخيار لتجنب تعارضات أسماء الملفات عندما لا تكون ncurses هي التنفيذ الرئيسي لـ curses للكمبيوتر. إذا تم تثبيت ncurses مع تعطيل الكتابة فوق الملفات، فإنها تضع ملفات الرأس الخاصة بها في دليل فرعي، على سبيل المثال:

#include <ncurses/curses.h>

كما أنها تحذف رابطًا رمزيًا يسمح لك باستخدام -lcurses لإنشاء ملفات تنفيذية.

--enable-widec
يقوم برنامج configure بإعادة تسمية المكتبة (وإذا تم استخدام الخيار --disable-overwrite) ويضع ملفات الرأس في دليل فرعي مختلف. جميع أسماء المكتبات لديها “w” مضافة إليها، أي بدلاً من
-lncurses

تقوم بالربط باستخدام

-lncursesw

يجب عليك أيضًا تمكين ميزات الأحرف العريضة في ملف الرأس عند تجميع مكتبة الأحرف العريضة لاستخدام الوظائف الممتدة (الأحرف العريضة). تغير الرمز الذي يمكّن هذه الميزات منذ X/Open Curses، الإصدار 4:

  • في الأصل، كانت ميزة الأحرف العريضة تتطلب الرمز _XOPEN_SOURCE_EXTENDED ولكن هذا كان صالحًا فقط لـ XPG4 (1996).
  • لاحقًا، اعتبر ذلك متعارضًا مع _XOPEN_SOURCE المعرّف بـ 500.
  • حتى منتصف عام 2018، لم تتطلب أي من الميزات في هذا التنفيذ _XOPEN_SOURCE أكثر من 600. ومع ذلك، توصي X/Open Curses، الإصدار 7 (2009) بتعريفه إلى 700.
  • بدلاً من ذلك، يمكنك تمكين الميزة عن طريق تعريف NCURSES_WIDECHAR مع التحذير من أن بعض ملفات الرأس الأخرى غير curses.h قد تتطلب قيمة محددة لـ _XOPEN_SOURCE (أو رمز خاص بالنظام).

تم تصميم ملف الرأس curses.h المثبت لمكتبة الأحرف العريضة ليكون متوافقًا مع رأس المكتبة غير العريضة. يختلف حجم بنية WINDOW فقط؛ عدد قليل من التطبيقات يتطلب أكثر من مؤشرات إلى WINDOWs.

إذا تم تثبيت ملفات الرأس مع السماح بالكتابة فوق الملفات، فيجب تثبيت رؤوس مكتبة الأحرف العريضة في النهاية، للسماح بإنشاء التطبيقات باستخدام أي من المكتبتين من نفس مجموعة ملفات الرأس.

--with-pthread
يقوم برنامج configure بإعادة تسمية المكتبة. جميع أسماء المكتبات لها “t” مضافة إليها (قبل أي “w” تم إضافتها بواسطة --enable-widec).
تم استبدال المتغيرات العامة مثل LINES بماكرو للسماح بالوصول للقراءة فقط. في نفس الوقت، يتم توفير وظائف تعيين لتعيين هذه القيم. قد تتطلب بعض التطبيقات (قليلة جدًا) تغييرات للعمل مع هذا الاتفاق.
--with-shared

--with-normal

--with-debug

--with-profile
تختلف أسماء المكتبات المشتركة والعادية (الثابتة) عن لاحقاتها، على سبيل المثال، libncurses.so و libncurses.a. تضيف مكتبات التصحيح والتنميط “_g” و “_p” إلى الأسماء الجذرية على التوالي، على سبيل المثال، libncurses_g.a و libncurses_p.a.
--with-termlib
يتم توفير الوظائف منخفضة المستوى التي لا تعتمد على ما إذا كانت المكتبة تدعم الأحرف العريضة في مكتبة tinfo.
من خلال القيام بذلك، يمكن مشاركة مكتبة tinfo بين التكوينات العريضة/العادية بالإضافة إلى تقليل حجم المكتبة عندما تكون هناك حاجة فقط للوظائف منخفضة المستوى.
هذه الوظائف موصوفة في هذه الصفحات:
  • curs_extend(3X) - امتدادات curses متنوعة
  • curs_inopts(3X) - خيارات إدخال curses
  • curs_kernel(3X) - روتينات curses منخفضة المستوى
  • curs_termattrs(3X) - روتينات الاستعلام عن بيئة curses
  • curs_termcap(3X) - محاكاة curses لـ termcap
  • curs_terminfo(3X) - واجهة curses لقاعدة بيانات terminfo
  • curs_util(3X) - روتينات مساعدة curses متنوعة
--with-trace
عادة ما توجد وظيفة trace في مكتبة التصحيح، ولكنها مفيدة أحيانًا لتكوينها في المكتبة المشتركة. يجب أن تتحقق نصوص التكوين من وجود الوظيفة بدلاً من افتراض أنها دائمًا في مكتبة التصحيح.

ملاحظات

تسمح X/Open Curses بأن تكون معظم الوظائف التي تحددها متاحة كـ macros أيضًا. تفعل ncurses ذلك

  • للوظائف التي ترجع قيمًا عبر معاملاتها،
  • لدعم الميزات القديمة،
  • لإعادة استخدام الوظائف (على سبيل المثال، تلك التي تنقل المؤشر قبل عملية أخرى)، و
  • عدد قليل من الحالات الخاصة.

إذا تمت إعادة توجيه واصف ملف الإخراج القياسي لبرنامج ncurses إلى شيء ليس جهاز طرفية، فإن المكتبة تكتب تحديثات الشاشة إلى واصف ملف الخطأ القياسي. كانت هذه ميزة غير موثقة لـ SVr3 curses.

راجع القسم الفرعي “ملفات الرأس” أدناه فيما يتعلق بالرموز التي يتم كشفها بواسطة تضمين curses.h.
