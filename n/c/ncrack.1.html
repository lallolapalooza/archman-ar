ncrack(1)

NCRACK(1) Ncrack Reference Guide NCRACK(1)

NAME

ncrack - Network authentication cracking tool

SYNOPSIS

ncrack [Options] {target specification}

DESCRIPTION

Ncrack is an open source tool for network authentication cracking. It was designed for high-speed parallel cracking using a dynamic engine that can adapt to different network situations. Ncrack can also be extensively fine-tuned for special cases, though the default parameters are generic enough to cover almost every situation. It is built on a modular architecture that allows for easy extension to support additional protocols. Ncrack is designed for companies and security professionals to audit large networks for default or weak passwords in a rapid and reliable way. It can also be used to conduct fairly sophisticated and intensive brute force attacks against individual services.


Warning

Ncrack is a project started in the Summer of 2009. While it is already useful for some purposes, it is still unfinished, beta quality software. You can help out by testing it and reporting any problems as described in the section called “BUGS”.

The output from Ncrack is a list of found credentials, if any, for each of the targets specified. Ncrack can also print an interactive status report of progress so far and possibly additional debugging information that can help track problems, if the user selected that option.

A typical Ncrack scan is shown in Example 1. The only Ncrack arguments used in this example are the two target IP addresses along with the the corresponding ports for each of them. The two example ports 21 and 22 are automatically resolved to the default services listening on them: ftp and ssh.

Example 1. A representative Ncrack scan

$ ncrack 10.0.0.130:21 192.168.1.2:22
Starting Ncrack 0.6 ( http://ncrack.org ) at 2016-01-03 22:10 EEST
Discovered credentials for ftp on 10.0.0.130 21/tcp:
10.0.0.130 21/tcp ftp: admin hello1
Discovered credentials for ssh on 192.168.1.2 22/tcp:
192.168.1.2 22/tcp ssh: guest 12345
192.168.1.2 22/tcp ssh: admin money$
Ncrack done: 2 services scanned in 156.03 seconds.
Ncrack finished.

The latest version of Ncrack can be obtained from http://nmap.org/ncrack. The latest version of this man page is available at http://nmap.org/ncrack/man.html .

TARGET SPECIFICATION

Everything on the Ncrack command-line that isn´t an option (or an option argument) is treated as a target host specification. The simplest case is to specify a target IP address or a hostname. Note, that you also need to specify a service to crack for the selected targets. Ncrack is very flexible in host/service specification. While hostnames and IP addresses can be defined with the flexibility that you are probably used to from Nmap, services along with service-specific options have a unique specification style that enables a combination of features to be taken advantage of.

Sometimes you wish to crack a whole network of adjacent hosts. For this, Ncrack supports CIDR-style addressing. You can append /numbits to an IPv4 address or hostname and Ncrack will try to crack every IP address for which the first numbits are the same as for the reference IP or hostname given. For example, 192.168.10.0/24 would send probes to the 256 hosts between 192.168.10.0 11000000 10101000 00001010 00000000) and 192.168.10.255 (binary: 11000000 10101000 00001010 11111111), inclusive. 192.168.10.40/24 would crack exactly the same targets. Given that the host scanme.nmap.org is at the IP address 64.13.134.52, the specification scanme.nmap.org/16 would send probes to the 65,536 IP addresses between 64.13.0.0 and 64.13.255.255. The smallest allowed value is /0, which targets the whole Internet. The largest value is /32, which targets just the named host or IP address because all address bits are fixed.

CIDR notation is short but not always flexible enough. For example, you might want to send probes to 192.168.0.0/16 but skip any IPs ending with .0 or .255 because they may be used as subnet network and broadcast addresses. Ncrack supports this through octet range addressing. Rather than specify a normal IP address, you can specify a comma-separated list of numbers or ranges for e

ach octet. على سبيل المثال، 192.168.0-255.1-254 سيؤدي إلى تخطي جميع العناوين في النطاق الذي ينتهي بـ .0 أو .255، و 192.168.3-5,7.1 سيستهدف العناوين الأربعة 192.168.3.1، 192.168.4.1، 192.168.5.1، و 192.168.7.1. يمكن حذف أي جانب من جوانب النطاق؛ القيم الافتراضية هي 0 على اليسار و 255 على اليمين. استخدام - بمفرده هو نفس الشيء مثل 0-255، ولكن تذكر استخدام 0- في الثماني الأول لذلك فإن محدد الهدف لا يبدو كخيار سطر الأوامر. لا تحتاج النطاقات إلى أن تكون مقتصرة على الثمانيات النهائية: المحدد سيرسل استعلامات إلى جميع عناوين IP على الإنترنت التي تنتهي بـ 13.37 هذا النوع من أخذ العينات الواسعة يمكن أن يكون مفيدًا للمسوح البحثية والبحث عبر الإنترنت. يقبل Ncrack مواصفات مضيف متعددة على سطر الأوامر، ولا تحتاج إلى أن تكون من نفس النوع. الأمر ncrack scanme.nmap.org 192.168.0.0/8 10.0.0,1,3-7.- -p22 يفعل ما تتوقعه. في حين أن الأهداف يتم تحديدها عادةً على أسطر الأوامر، فإن الخيارات التالية متاحة أيضًا للتحكم في تحديد الهدف: -iX اسم_ملف_الإدخال (الإدخال من تنسيق إخراج XML لـ Nmap) .
يقرأ مواصفات الهدف/الخدمة من ملف إخراج XML الخاص بـ Nmap. يتم إنشاء ملف XML الخاص بـ Nmap عن طريق مسح أي مضيفين وتحديد خيار -oX الخاص بـ Nmap. سيقوم Ncrack تلقائيًا بتحليل عناوين IP والمنافذ والخدمات المقابلة التي تكون مفتوحة وسيستخدم هذه الأهداف لتدقيق المصادقة. هذا خيار مفيد جدًا، حيث يتيح لك دمج هذين الأداتين -Nmap وNcrack - لكسر فقط الخدمات التي تكون مفتوحة بالتأكيد. بالإضافة إلى ذلك، إذا تم تمكين الكشف عن الإصدار في Nmap (خيار -sV)، فسيستخدم Ncrack هذه النتائج للتعرف على الخدمات المدعومة وكسرها ولكنها تستمع على منافذ غير افتراضية. على سبيل المثال، إذا كان المضيف لديه خادم يستمع على المنفذ 41414 وقام Nmap بتحديد أنه خدمة SSH، فسيستخدم Ncrack هذه المعلومات لكسرها باستخدام وحدة SSH. بالطبع، سيقوم Ncrack بتجاهل المنافذ/الخدمات المفتوحة التي لا تدعمها وحداته لكسر المصادقة.
-iN اسم_ملف_الإدخال (الإدخال من تنسيق الإخراج العادي لـ Nmap) .
يقرأ مواصفات الهدف/الخدمة من ملف الإخراج العادي لـ Nmap. يتم إنشاء الملف العادي لـ Nmap عن طريق مسح أي مضيفين وتحديد خيار -oN الخاص بـ Nmap. يعمل هذا تمامًا مثل خيار -iX الخاص بـ Ncrack، والفرق الوحيد هو تنسيق ملف الإدخال.
-iL اسم_ملف_الإدخال (الإدخال من قائمة) .
يقرأ مواصفات الهدف من اسم_ملف_الإدخال. تمرير قائمة كبيرة من المضيفين غالبًا ما يكون محرجًا على سطر الأوامر، ومع ذلك فهو رغبة شائعة. على سبيل المثال، قد ترغب في كسر قائمة من الخوادم المحددة جدًا التي تم تحديدها لاختبار الاختراق. ببساطة قم بإنشاء قائمة بالمضيفين لكسرهم ومرر اسم الملف هذا إلى Ncrack كوسيط للخيار -iL. يمكن أن تكون الإدخالات بأي من التنسيقات التي يقبلها Ncrack على سطر الأوامر (عنوان IP، اسم المضيف، CIDR، نطاقات الثماني، أو بناء جملة المضيف-الخدمة الخاص بـ Ncrack). يجب فصل كل إدخال بمسافة واحدة أو أكثر، علامات جدولة، أو أسطر جديدة. يمكنك تحديد شرطة (-) كاسم ملف إذا كنت تريد أن يقرأ Ncrack المضيفين من الإدخال القياسي بدلاً من ملف فعلي. لاحظ، مع ذلك، أنه إذا تم تحديد المضيفين بدون أي خدمة، فسيتعين عليك أيضًا توفير الخدمات/المنافذ للأهداف باستخدام الخيار -p.
--exclude مضيف1[, مضيف2[, ...]] (استبعاد المضيفين/الشبكات) .
يحدد قائمة مفصولة بفواصل الأهداف التي سيتم استبعادها من المسح حتى لو كانت جزءًا من نطاق الشبكة الإجمالي الذي تحدده. القائمة التي تمررها تستخدم بناء جملة Ncrack العادي، لذا يمكن أن تشمل أسماء المضيفين، شبكات CIDR، نطاقات الثماني، إلخ. يمكن أن يكون هذا مفيدًا عندما تتضمن الشبكة التي ترغب في مسحها خوادم حرجة للغاية لا يمكن المساس بها، وأنظمة معروف عنها أنها تتفاعل بشكل غير طبيعي مع الحمل الثقيل، أو الشبكات الفرعية التي يديرها أشخاص آخرون.
--excludefile ملف_الاستبعاد (قائمة الاستبعاد من الملف) .
يقدم هذا نفس وظائف الخيار --exclude، باستثناء أن الأهداف المستبعدة يتم توفيرها في ملف ملف_الاستبعاد مفصول بأسطر جديدة أو مسافات أو علامات جدولة بدلاً من سطر الأوامر.

تحديد الخدمة

لا يمكن إجراء أي جلسة كسر دون استهداف خدمة معينة للهجوم. تحديد الخدمة هو واحد من أكثر الأنظمة الفرعية مرونة في Ncrack ويتعاون مع تحديد الهدف بطريقة تسمح بتطبيق مجموعات مختلفة من الخيارات. لكي يبدأ Ncrack في العمل، سيتعين عليك تحديد مضيف هدف واحد على الأقل وخدمة مرتبطة به للهجوم. يوفر Ncrack طرقًا لتحديد خدمة بواسطة رقم منفذها الافتراضي، أو اسمها (كما تم استخراجه من ملف ncrack-services)، أو كليهما. عادةً، تحتاج إلى تحديد كل من الاسم ورقم المنفذ فقط في الحالة الخاصة عندما تعرف أن خدمة معينة تستمع على منفذ غير افتراضي.

يقدم Ncrack طريقتين متميزتين سيتم من خلالهما تطبيق الخدمات على أهدافك: تحديد خدمة لكل مضيف وتحديد عام.

تحديد خدمة لكل مضيف

الخدمات المحددة في هذا الوضع مكتوبة بجوار المضيف وتنطبق عليه فقط. ضع في اعتبارك، مع ذلك، أن تحديد الهدف يسمح بالرموز العامة/أقنعة الشبكة، مما يعني أساسًا أن تطبيق تنسيق تحديد خدمة لكل مضيف على هذا الهدف المحدد سيؤثر على جميع الأهداف الموسعة نتيجة لذلك. الصيغة العامة هي:

[اسم_الخدمة]://الهدف:[رقم_المنفذ]

حيث الهدف هو اسم مضيف أو عنوان IP بأي من التنسيقات الموضحة في قسم تحديد الهدف، [اسم_الخدمة] هو أحد أسماء الخدمات الشائعة كما هو محدد في ملف ncrack-services (مثل ssh، http) و [رقم_المنفذ] هو ما يعنيه بوضوح. يمكن لـ Ncrack تحديد أرقام المنافذ الافتراضية لكل خدمة يدعمها، بالإضافة إلى قدرته على استنتاج اسم الخدمة عند تحديد رقم منفذ افتراضي. تحديد كليهما له معنى فقط عندما يكون لدى المستخدم معرفة مسبقة بخدمة تستمع على رقم منفذ غير افتراضي. يمكن تحديد ذلك بسهولة عن طريق استخدام الكشف عن الإصدار مثل الذي يقدمه خيار -sV الخاص بـ Nmap.

مثال 2. مثال على تحديد خدمة لكل مضيف

$ ncrack scanme.nmap.org:22 ftp://10.0.0.10 ssh://192.168.1.*:5910

سيحاول الأمر أعلاه كسر المضيفين: scanme.nmap.org على خدمة SSH (المنفذ الافتراضي 22)، 10.0.0.10 على خدمة FTP (المنفذ الافتراضي 21)، و 192.168.1.0 - 192.168.1.255 (كل هذه الشبكة الفرعية C) على خدمة SSH على المنفذ غير الافتراضي 5910 الذي تم تحديده صراحةً. في الحالة الأخيرة، لن يتمكن Ncrack من تحديد أن مضيفي الشبكة الفرعية سيتم مسحهم مقابل خدمة SSH على هذا المنفذ المحدد بدون طلب المستخدم الصريح لذلك، لأنه لا يوجد أي تعيين لرقم المنفذ 5910 إلى خدمة SSH.

تحديد خدمة عام

الخدمات المحددة في هذا الوضع يتم تطبيقها على جميع المضيفين الذين لم يتم ربطهم بتنسيق تحديد الخدمة لكل مضيف. يتم ذلك باستخدام الخيار -p. في حين أن هذه الإمكانية قد تكون مشابهة لتلك الخاصة بـ Nmap، يجب أن تحاول عدم الخلط بينها، حيث أن الوظيفة ذات طبيعة مختلفة قليلاً. يمكن تحديد الخدمات باستخدام توجيهات مفصولة بفواصل للصيغة العامة:

-p [خدمة1]:[رقم_المنفذ1],[خدمة2]:[رقم_المنفذ2],...

كالعادة، لست بحاجة إلى تحديد كل من اسم الخدمة ورقم المنفذ لأن Ncrack يعرف تعيينات الخدمات الافتراضية إلى أرقام المنافذ الافتراضية. كن حذرًا مع ذلك لعدم تضمين أي مسافات بين كل اسم خدمة و/أو رقم منفذ، لأن Ncrack سيعتقد أن الوسيط بعد المسافة هو هدف وفقًا للقاعدة "كل ما ليس خيارًا هو تحديد هدف".

مثال 3. مثال على تحديد خدمة عام

$ ncrack scanme.nmap.org 10.0.0.120-122 192.168.2.0/24 -p 22,ftp:3210,telnet

سيحاول الأمر أعلاه كسر جميع المضيفين المحددين scanme.nmap.org، 10.0.0.120، 10.0.0.121، 192.168.2.0/24 مقابل الخدمات التالية: خدمة SSH (تم تعيينها من المنفذ الافتراضي 22)، خدمة FTP على المنفذ غير الافتراضي 3210، وخدمة TELNET على المنفذ الافتراضي 23.

بالطبع، يسمح لك Ncrack بدمج كلا وضعي تحديد الخدمة إذا كنت تعتقد أن ذلك ضروري. عادةً، ستحتاج فقط إلى تحديد عدد قليل من الخدمات ولكن كسر العديد من المضيفين مقابل العديد من الخدمات المختلفة قد يكون مشروعًا طويل الأجل للشبكات الكبيرة التي تحتاج إلى تدقيق مستمر بحثًا عن كلمات مرور ضعيفة. إذا كنت في شك، بشأن المضيفين والخدمات التي سيتم كسرها باستخدام الأمر الحالي، يمكنك استخدام الخيار -sL (انظر أدناه للشرح).

خيارات الخدمة

بخلاف تحديد الخدمة العام، يسمح لك Ncrack بتوفير مجموعة من الخيارات التي تنطبق على كل هدف أو مجموعة فرعية من أهدافك. تشمل الخيارات تحسينات التوقيت والأداء (والتي تم تحليلها بالتفصيل في قسم منفصل)، وتمكين/تعطيل SSL، ومعلمات أخرى خاصة بالوحدة النمطية مثل مسار URL النسبي لوحدة HTTP. يمكن تعريف الخيارات بطرق متنوعة تشمل: خيارات لكل مضيف، وخيارات لكل وحدة نمطية، وخيارات عامة. نظرًا لأنه يمكن استخدام مجموعة من هذه الخيارات، هناك تسلسل هرمي صارم للأسبقية سيتم مناقشته لاحقًا.

خيارات لكل مضيف

الخيارات في هذا الوضع تنطبق فقط على المضيف (المضيفين) التي تشير إليها وهي مكتوبة بجوارها وفقًا للصيغة التالية:

[اسم_الخدمة]://الهدف:[رقم_المنفذ],خيار1=قيمة_الخيار1,خيار2=قيمة_الخيار,...

الصيغة المتعلقة بتحديد الخدمة التي تأتي قبل الخيارات، تم شرحها في القسم السابق. خيارN يشير إلى أي من أسماء الخيارات المتاحة (ستتبع قائمة أدناه)، بينما تحدد قيمة_الخيارN قيمة هذا الخيار وتعتمد على طبيعتها. على سبيل المثال، تتوقع معظم الخيارات المتعلقة بالتوقيت استقبال أرقام كقيم، بينما يحتاج خيار path بوضوح إلى وسيط سلسلة.

خيارات لكل وحدة نمطية

الخيارات في هذا الوضع تنطبق على جميع المضيفين المرتبطين بالخدمة/الوحدة النمطية المعينة. يتم تحقيق ذلك باستخدام الخيار -m والذي يتم تعريفه بالصيغة:

-m خدمة-
