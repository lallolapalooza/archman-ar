connection.mptcp-flags

ما إذا كان سيتم تكوين نقاط نهاية MPTCP وعلامات العناوين. إذا تم تمكين MPTCP في NetworkManager، فسيقوم بتكوين عناوين الواجهة كنقاط نهاية MPTCP. لاحظ أن عناوين حلقة IPv4 (127.0.0.0/8)، وعناوين IPv4 المحلية للرابط (169.254.0.0/16)، وعنوان حلقة IPv6 (::1)، وعناوين IPv6 المحلية للرابط (fe80::/10)، وعناوين IPv6 المحلية الفريدة (ULA، fc00::/7) وعناوين امتداد خصوصية IPv6 (rfc3041، ipv6.ip6-privacy) سيتم استبعادها من التكوين كنقاط نهاية.

إذا كانت "معطلة" (0x1)، يتم تعطيل معالجة MPTCP للواجهة ولا يتم تسجيل أي نقاط نهاية.

العلامة "ممكّنة" (0x2) تعني تمكين معالجة MPTCP. يمكن أيضًا استنتاج هذه العلامة من وجود علامات أخرى.

حتى عند التمكين، ستظل معالجة MPTCP معطلة افتراضيًا ما لم يكن sysctl "/proc/sys/net/mptcp/enabled" قيد التشغيل. لا يغير NetworkManager sysctl وهذا متروك للمسؤول أو التوزيع. لتكوين نقاط النهاية حتى لو كان sysctl معطلاً، يمكن استخدام العلامة "أيضًا-بدون-sysctl" (0x4). في هذه الحالة، لا ينظر NetworkManager إلى sysctl ويقوم بتكوين نقاط النهاية بغض النظر.

حتى عند التمكين، سيقوم NetworkManager فقط بتكوين نقاط نهاية MPTCP لعائلة عناوين معينة إذا كان هناك مسار افتراضي أحادي الوجهة (0.0.0.0/0 أو ::/0) في جدول التوجيه الرئيسي. يمكن للعلا مة "أيضًا-بدون-المسار-الافتراضي" (0x8) تجاوز ذلك.

عند تمكين معالجة MPTCP، يتم تكوين نقاط النهاية باستخدام علامات العناوين المحددة "إشارة" (0x10)، "شبكة فرعية" (0x20)، "نسخ احتياطي" (0x40)، "شبكة كاملة" (0x80). انظر دليل ip-mptcp(8) للحصول على معلومات إضافية حول العلامات.

إذا كانت العلامات صفرًا (0x0)، يتم احترام الإعداد الافتراضي العام للاتصال من NetworkManager.conf. إذا ظل غير محدد، يكون البديل هو "ممكّن، شبكة فرعية". لاحظ أن هذا يعني أن MPTCP يتم التعامل معه افتراضيًا اعتمادًا على sysctl "/proc/sys/net/mptcp/enabled".

لا يغير NetworkManager حدود MPTCP ولا يمكّن MPTCP عبر "/proc/sys/net/mptcp/enabled". هذا تكوين مضيف يمكن للمسؤول تغييره عبر sysctl و ip-mptcp.

التصفية الصارمة للمسار العكسي (rp_filter) تكسر العديد من حالات استخدام MPTCP، لذلك عند تمكين معالجة MPTCP لعناوين IPv4 على الواجهة، سيقوم NetworkManager بتخفيف التصفية الصارمة للمسار العكسي (1) إلى الإعداد المخفف (2).

التنسيق: علامات (NMMptcpFlags)

القيم الصالحة: لا شيء/افتراضي (0x0)، معطل (0x1)، ممكّن (0x2)، أيضًا-بدون-sysctl (0x4)، أيضًا-بدون-المسار-الافتراضي (0x8)، إشارة (0x10)، شبكة فرعية (0x20)، نسخ احتياطي (0x40)، شبكة كاملة (0x80)

ipv6.dhcp-duid

سلسلة تحتوي على معرّف DHCPv6 الفريد (DUID) الذي يستخدمه عميل DHCP للتعريف عن نفسه لخوادم DHCPv6 (RFC 3315). يتم نقل DUID في خيار معرف العميل. إذا كانت السلسلة عبارة عن سلسلة سداسية عشرية ('aa:bb:cc')، فسيتم تفسيرها كسلسلة ثنائية وسيتم ملؤها كقيمة غامضة في خيار معرف العميل.

ستقوم القيم الخاصة "stable-llt"، "stable-ll"، و "stable-uuid" بإنشاء DUID من النوع المقابل، مشتق من معرف ثابت للاتصال ومفتاح فريد لكل مضيف. قد ترغب في تضمين محدد " ${DEVICE} " أو " ${MAC} " في المعرف الثابت، في حال تم تنشيط هذا الملف الشخصي على أجهزة متعددة. لذلك، سيكون عنوان طبقة الارتباط لـ "stable-ll" و "stable-llt" عنوانًا تم إنشاؤه مشتقًا من المعرف الثابت. سيتم اختيار قيمة وقت DUID-LLT في خيار "stable-llt" من بين فترة زمنية ثابتة مدتها ثلاث سنوات (الحد الأعلى للفترة هو نفس الطابع الزمني الثابت المستخدم في "llt").

الصفر يحدد قيمة افتراضية تم تكوينها عالميًا. إذا كانت هذه القيمة مفقودة أو صفرًا أيضًا، فإنها تكون افتراضيًا 50 للشبكات الافتراضية الخاصة (بما في ذلك WireGuard) و 100 للاتصالات الأخرى.

لاحظ أن الأولوية تستخدم لترتيب إعدادات DNS لعدة اتصالات نشطة. فهي لا تميز بين خوادم DNS المتعددة داخل نفس ملف تعريف الاتصال.

عندما يكون لدى أجهزة متعددة تكوينات بنفس الأولوية، يتم النظر في الشبكات الافتراضية أولاً، ثم الأجهزة ذات أفضل مسار افتراضي (أدنى مقياس) ثم جميع الأجهزة الأخرى.

عند استخدام dns=default، ستكون الخوادم ذات الأولوية الأعلى في الجزء العلوي من resolv.conf. لتحديد أولوية خادم معين على آخر ضمن نفس الاتصال، قم ببساطة بتحديده بالترتيب المطلوب. لاحظ أن المحلل عادةً ما يحاول أسماء الخوادم في /etc/resolv.conf بالترتيب المذكور، وينتقل إلى الخادم التالي في القائمة عند الفشل. انظر على سبيل المثال خيار "rotate" لإعداد dns-options. إذا كانت هناك أي أولويات DNS سالبة، فسيتم النظر فقط في أسماء الخوادم من الأجهزة ذات تلك الأولوية الأقل.

عند استخدام محلل DNS يدعم التوجيه الشرطي أو DNS المقسم (مع إعدادات dns=dnsmasq أو dns=systemd-resolved)، يتم استخدام كل اتصال للاستعلام عن المجالات في قائمة البحث الخاصة به. تحدد مجالات البحث الخوادم التي يجب الاستعلام منها، وتستخدم أولوية DNS لترتيب خوادم DNS بناءً على المجال. يتم توجيه الاستعلامات للمجالات غير الموجودة في أي قائمة بحث عبر الاتصالات التي تحتوي على المجال العام "~."، والذي يتم إضافته تلقائيًا إلى الاتصالات ذات المسار الافتراضي (أو يمكن إضافته يدويًا). عند تحديد اتصالات متعددة لنفس المجال، يفوز الاتصال ذو الأولوية الأفضل (القيمة الرقمية الأقل). إذا تم تكوين مجال فرعي على واجهة أخرى، فسيتم قبوله بغض النظر عن الأولوية، ما لم يكن المجال الأب على الواجهة الأخرى له أولوية سالبة، مما يتسبب في إخفاء المجال الفرعي. مع DNS المقسم، يمكنك تجنب تسريبات DNS غير المرغوب فيها عن طريق تكوين أولويات DNS ومجالات البحث بشكل صحيح، بحيث يتم تكوين أسماء الخوادم الواجهة المطلوبة فقط.

NAME

nm-settings-nmcli — description of properties used by nmcli

DESCRIPTION

nmcli can be used to set most of the NetworkManager settings. The following sections describe the properties that can be set using nmcli.

Note that not all properties are exposed via nmcli, and some properties may not be available depending on the NetworkManager version.

link setting

Link Settings.

Properties:

link.auto-configure

When set to true, the device will be automatically configured. When set to false, the device will not be automatically configured.

Format: boolean

link.mac-address

The MAC address to use for the device. When set to null, a MAC address is automatically chosen.

Format: mac address

link.mtu

The MTU of the device. When set to 0, the MTU is automatically determined.

Format: integer

Valid values: 0 - 65535

link.gso-max-segments

The maximum segments of a Generic Segment Offload packet the device should accept. The value must be between 0 and 4294967295. When set to -1, the existing value is preserved.

Format: integer

Valid values: -1 - 4294967295

Special values: default (-1)

link.gso-max-size

The maximum size of a Generic Segment Offload packet the device should accept. The value must be between 0 and 4294967295. When set to -1, the existing value is preserved.

Format: integer

Valid values: -1 - 4294967295

Special values: default (-1)

link.tx-queue-length

The size of the transmit queue for the device, in number of packets. The value must be between 0 and 4294967295. When set to -1, the existing value is preserved.

Format: integer

Valid values: -1 - 4294967295

Special values: default (-1)

loopback setting

Loopback Link Settings.

Properties:

loopback.mtu

Alias: mtu

If non-zero, only transmit packets of the specified size or smaller, breaking larger packets up into multiple Ethernet frames.

Format: integer

Special values: auto

prefix-delegation setting

IPv6 prefix delegation settings.

Properties:

prefix-delegation.subnet-id

The subnet ID to use on the interface from the prefix delegation received via an upstream interface. Set to a value between 0 and 0xffffffff (2^32 - 1) to indicate a specific subnet ID; or set to -1 to automatically choose an available subnet ID.

Format: integer

Valid values: -1 - 4294967295

veth setting

Veth Settings.

Properties:

veth.peer

Alias: peer

This property specifies the peer interface name of the veth. This property is mandatory.

Format: string

Secret flag types:

Each password or secret property in a setting has an associated flags property that describes how to handle that secret. The flags property is a bitfield that contains zero or more of the following values logically OR-ed together.

•0x0 (none) - the system is responsible for providing and storing this secret. This may be required so that secrets are already available before the user logs in. It also commonly means that the secret will be stored in plain text on disk, accessible to root only. For example via the keyfile settings plugin as described in the "PLUGINS" section in NetworkManager.conf(5).
•0x1 (agent-owned) - a user-session secret agent is responsible for providing and storing this secret; when it is required, agents will be asked to provide it.
•0x2 (not-saved) - this secret should not be saved but should be requested from the user each time it is required. This flag should be used for One-Time-Pad secrets, PIN codes from hardware tokens, or if the user simply does not want to save the secret.
•0x4 (not-required) - in some situations it cannot be automatically determined that a secret is required or not. This flag hints that the secret is not required and should not be requested from the user.
