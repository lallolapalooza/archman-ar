NAME

nmbd — Samba NetBIOS name server daemon

SYNOPSIS

nmbd [-D|-d|--daemonize] [-F|--foreground] [-S|--standalone] [-h|--help] [-l|--log-basename <log file basename>] [-p|--port <port number>] [-O|--log-opt <opt>=<value>] [-s|--configfile <configfile>] [-V|--version]

DESCRIPTION

nmbd is the Samba daemon that implements the NetBIOS name server (NBNS) protocol, which is used for NetBIOS name resolution. It allows clients on a network to find Samba servers by name, as well as allowing Samba servers to find other machines on the network that are running NetBIOS name service.

nmbd can be run in two modes: either as a standalone daemon (the default, specified using -S or --standalone), or as a daemon started by the super-server (like inetd, specified using -d or --daemonize).

It is recommended that nmbd be run as a standalone daemon, using the -S option.

If nmbd is run as a daemon, it will fork into the background and become a daemon process. If it is run in foreground mode (-F or --foreground), it will not fork, but will run in the foreground. This is useful for debugging.

The configuration file for nmbd is always smb.conf(5).

OPTIONS

-D, -d, --daemonize
If this option is specified, nmbd will fork into the background and become a daemon process. This is the default behaviour for nmbd when run from the command line. Note that this option is NOT compatible with the -F or --foreground option.
-F, --foreground
Causes nmbd to run in the foreground. This is useful for debugging. Note that this option is NOT compatible with the -D, -d or --daemonize option.
-S, --standalone
Run the server as a standalone daemon. This is the default behaviour. This option is NOT compatible with the -d option.
-h, --help
Prints a usage message and exits.
-l <log file basename>
Log files for nmbd will be written to the directory specified by the `log dir' parameter in the smb.conf file. If this parameter is not set, then the files will be written to /usr/local/samba/var/log.nmbd.
-p <port number>
The UDP port number that nmbd will listen on. The default is 137.
-O <opt>=<value>
Option override. This allows the user to specify configuration parameters on the command line, overriding any values specified in the configuration file. The parameter must be specified in the form param=value.
-s <configfile>
The name of the configuration file to use. By default this is /usr/local/samba/etc/smb.conf.
-V, --version
Prints the version number of nmbd and exits.

FILES

/usr/local/samba/etc/smb.conf

/usr/local/samba/var/locks/namelist.debug

/usr/local/samba/var/log.nmb

SIGNALS

To shut down an nmbd process it is recommended that SIGKILL (-9) NOT be used, except as a last resort, as this may leave the name database in an inconsistent state. The correct way to terminate nmbd is to send it a SIGTERM (-15) signal and wait for it to die on its own.

nmbd will accept SIGHUP, which will cause it to dump out its namelists into the file namelist.debug in the /usr/local/samba/var/locks directory (or the var/locks directory configured under wherever Samba was configured to install itself). This will also cause nmbd to dump out its server database in the log.nmb file. Additionally, the signal will cause reloading nmbd configuration.

Instead of sending a SIGHUP signal, a request to dump namelists into the file and reload a configuration file may be sent using smbcontrol(1) program.

The debug log level of nmbd may be raised or lowered using smbcontrol(1) (SIGUSR[1|2] signals are no longer used since Samba 2.2). This is to allow transient problems to be diagnosed, whilst still running at a normally low log level.
