ndctl-remove-passphrase(1)

الحزمة: ndctl

التراخيص: LGPL

NDCTL-REMOVE-PASSPHRASE(1) ndctl Manual NDCTL-REMOVE-PASSPHRASE(1)

الاسم

ndctl-remove-passphrase - إيقاف وحدة ذاكرة غير متطايرة (DIMM) عن القفل عند انقطاع التيار الكهربائي وتتطلب كلمة مرور للوصول إلى الوسائط

ملخص

ndctl remove-passphrase <nmem0> [<nmem1>..<nmemN>] [<options>]

الوصف

البحث في مخزن المفاتيح الخاص بالمستخدم عن كلمة مرور مشفرة لوحدة الذاكرة غير المتطايرة (NVDIMM) المعنية. إذا لم يتم العثور عليها، حاول تحميل كتلة كلمة المرور. بعد تعطيل كلمة المرور، قم بإزالة key-ID من مخزن المفاتيح وكذلك كتلة كلمة المرور من نظام الملفات.

خيارات

<dimm>

اسم جهاز nmemX، أو رقم معرف وحدة الذاكرة. تقييد العملية على وحدات الذاكرة المحددة. يمكن تحديد الكلمة المفتاحية all للإشارة إلى عدم وجود أي قيود، ومع ذلك، هذا هو نفس عدم توفير خيار --dimm على الإطلاق.

-b, --bus=

رقم معرف ناقل، أو سلسلة مزود (على سبيل المثال، "ACPI.NFIT"). تقييد العملية على النواقل المحددة. يمكن تحديد الكلمة المفتاحية all للإشارة إلى عدم وجود أي قيود، ومع ذلك، هذا هو نفس عدم توفير خيار --bus على الإطلاق.

-v, --verbose

إصدار رسائل التصحيح.

-m, --master-passphrase

يشير إلى أننا ندير كلمة المرور الرئيسية بدلاً من كلمة مرور المستخدم.

نظرية التشغيل

قدمت مواصفات طرق Intel الخاصة بالجهاز (DSM) v1.7 و v1.8 [1] عمليات إدارة الأمان التالية: تمكين كلمة المرور، تحديث كلمة المرور، فتح قفل وحدة الذاكرة، تعطيل الأمان، تجميد الأمان، محو آمن (التشفير)، الكتابة فوق، تمكين كلمة المرور الرئيسية، تحديث كلمة المرور الرئيسية، ومحو آمن لكلمة المرور الرئيسية.

تتكون إدارة الأمان لوحدات الذاكرة غير المتطايرة (NVDIMMs) من جزأين. يستخدم الواجهة الأمامية إطار عمل إدارة مفاتيح Linux (المفاتيح الموثوقة والمشفرة [2]) لتخزين كلمات المرور المشفرة في مخزن المفاتيح الذي تديره النواة. الواجهة لهذا هي الأداة keyutils التي تستخدم واجهات برمجة تطبيقات إدارة المفاتيح في نواة Linux. يأخذ الجزء الخلفي الحمولة المفككة (وهي كلمة مرور وحدة الذاكرة) ويمررها إلى وحدة الذاكرة.

على عكس DSMs الأخرى التي تتكون من libndctl وترسل إلى النواة عبر ioctl، تتم إدارة DSMs الأمان من خلال سمة security sysfs تحت جهاز dimm. يتم كتابة key-ID إلى سمة security وتقوم النواة بسحب مادة المفتاح المرتبطة من مخزن مفاتيح المستخدم الذي تحتفظ به النواة.

تبدأ عملية الأمان بإنشاء مفتاح رئيسي يستخدم لإغلاق (تشفير) كلمة مرور وحدة الذاكرة. يمكن أن يكون هناك مفتاح رئيسي مشترك واحد يستخدم لتشفير كلمة مرور كل وحدة ذاكرة، أو يمكن إنشاء مفتاح منفصل لكل وحدة ذاكرة. يشار أيضًا إلى المفتاح الرئيسي باسم مفتاح تشفير المفتاح (kek). يمكن أن يتم إنشاء kek بواسطة TPM (وحدة النظام المنصة الموثوقة) على النظام، أو بدلاً من ذلك، يمكن أيضًا استخدام System Master Key كـ kek.

لأغراض الاختبار، يمكن أيضًا استخدام مفتاح مستخدم مع حمولة عشوائية كـ kek. انظر [2] للحصول على التفاصيل. لتنفيذ أي عمليات أمان، من المتوقع أن يكون kek قد تم إضافته إلى مخزن مفاتيح المستخدم الخاص بالنواة كما هو موضح في المثال أدناه:

# keyctl show
Session Keyring
 736023423 --alswrv      0     0  keyring: _ses
 675104189 --alswrv      0 65534   \_ keyring: _uid.0
 680187394 --alswrv      0     0       \_ trusted: nvdimm-master

قبل تنفيذ أي من عمليات الأمان، يجب تعطيل جميع المناطق المرتبطة بوحدة الذاكرة المعنية. بالنسبة لعملية overwrite، بالإضافة إلى regions، يجب أيضًا تعطيل dimm.

[1] http://pmem.io/documents/NVDIMM_DSM_Interface-V1.8.pdf
[2] https://www.kernel.org/doc/Documentation/security/keys/trusted-encrypted.rst

تصف الأقسام الفرعية التالية تفاصيل كل ميزة أمان.

فتح القفل

يتم تنفيذ فتح القفل بواسطة النواة، ومع ذلك، يجب أن تحدث خطوة تحضيرية قبل أن تتمكن النواة من إصدار DSM لفتح القفل. من المتوقع أنه من initramfs، يتم تنفيذ أمر إعداد (ndctl load-keys) قبل تحميل وحدة libnvdimm بواسطة modprobe. سيقوم هذا الأمر بحقن kek وكلمات المرور المشفرة في مخزن مفاتيح المستخدم الخاص بالنواة. أثناء probe لبرنامج التشغيل libnvdimm، سيقوم بما يلي:

1.التحقق من حالة الأمان للجهاز ومعرفة ما إذا كانت وحدة الذاكرة مقفلة
2.طلب كلمة المرور المشفرة المرتبطة من مخزن مفاتيح المستخدم الخاص بالنواة
3.استخدام kek لفك تشفير كلمة المرور
4.إنشاء DSM لفتح القفل، ونسخ الحمولة المفكوكة إلى DSM
5.إصدار DSM لفتح قفل وحدة الذاكرة

إذا كانت وحدة الذاكرة مفتوحة بالفعل، ستحاول النواة إعادة التحقق من كلمة المرور. إذا فشلنا في إعادة التحقق من كلمة المرور، ستقوم النواة بتجميد الأمان ومنع أي تغييرات إضافية على تكوين الأمان. تتوفر معلمة وحدة نواة لتجاوز هذا السلوك.

إعداد كلمة مرور المستخدم

لإعداد كلمة مرور لوحدة الذاكرة، من المتوقع أن يكون kek المستخدم موجودًا في مخزن مفاتيح المستخدم الخاص بالنواة. يقوم kek بتشفير كلمة مرور وحدة الذاكرة باستخدام تنسيق مفتاح enc32. لا يتم توفير كلمة المرور العادية من قبل المستخدم ولا تكون مرئية له. بدلاً من ذلك، يتم إنشاؤها عشوائيًا بواسطة النواة ولا يمتلك المستخدمون حق الوصول إليها. عند التشفير، يتم كتابة كتلة ثنائية من كلمة المرور إلى دليل تخزين كتلة كلمة المرور (/etc/ndctl/keys). يتحمل المستخدم مسؤولية النسخ الاحتياطي لكتل كلمات المرور إلى موقع آمن.

تحديث كلمة مرور المستخدم

تستخدم عملية تحديث كلمة مرور المستخدم نفس أمر DSM مثل تمكين كلمة مرور المستخدم. يتم إجراء معظم العمل على جانب إدارة المفاتيح. لدى المستخدم خيار توفير kek جديد لكلمة المرور الجديدة، ولكن الاستمرار في استخدام kek الحالي مقبول أيضًا. يتم تنفيذ العمليات التالية لـ update-passphrase:

1.إزالة كلمة المرور المشفرة من مخزن مفاتيح المستخدم الخاص بالنواة.
2.إعادة تسمية كتلة كلمة المرور إلى old.
3.تحميل كتلة كلمة المرور القديمة هذه إلى مخزن المفاتيح باسم "old".
4.إنشاء كلمة المرور الجديدة وتشفيرها باستخدام kek.
5.إرسال DSM مع كلمات المرور القديمة والجديدة المفكوكة.
6.إزالة كلمة المرور القديمة وكتلة كلمة المرور من مخزن المفاتيح.

إزالة كلمة مرور المستخدم

يتم كتابة key-ID لكلمة المرور المراد إزالتها إلى sysfs. تقوم النواة بعد ذلك بإرسال DSM لتعطيل الأمان، ومن ثم تتم إزالة كلمة المرور من مخزن المفاتيح، ويتم حذف كتلة كلمة المرور المرتبطة.

المحو المشفر (الآمن)

هذه العملية مشابهة لـ remove-passphrase. تقوم النواة بإصدار تعليمات WBINVD قبل وبعد العملية لضمان عدم تلف البيانات من ذاكرة التخزين المؤقت لوحدة المعالجة المركزية القديمة. استخدم أمر sanitize-dimm الخاص بـ ndctl مع الخيار --crypto-erase لتنفيذ هذه العملية.

ndctl-remove-passphrase(1)

NAME

ndctl-remove-passphrase, ndctl-set-passphrase, ndctl-update-passphrase, ndctl-crypto-erase, ndctl-overwrite, ndctl-security-freeze - manage security features of Intel Optane™ persistent memory modules

SYNOPSIS

ndctl [-N] [-v] [Device] command [args]

Commands for security operations:

ndctl remove-passphrase [--force]
ndctl set-passphrase [--module=module] [--force] [passphrase]
ndctl update-passphrase [--module=module] [--force] [old_passphrase] [new_passphrase]
ndctl crypto-erase [--module=module] [--force] [passphrase]
ndctl overwrite [--module=module] [--force] [passphrase]
ndctl security-freeze [--module=module] [--force]

DESCRIPTION

The ndctl utility provides a mechanism to manage the security features of Intel Optane™ persistent memory (PMem) modules. This man page covers the commands related to passphrases, crypto-erase, overwrite, and security freeze operations.

These commands interact with the security sub-system of the PMem modules. The security sub-system allows for encryption of the PMem data at rest. This encryption is controlled by a passphrase.

The PMem module security sub-system is only accessible when the module is in a Security Frozen state or when the security sub-system is not locked. Initially, or after a system reboot, the security sub-system is unlocked.

The security sub-system supports the following states:

Unlocked
The security sub-system is not locked and can be accessed without a passphrase. Passphrase related operations can be performed.
Locked
The security sub-system is locked, requiring a valid passphrase to be provided before any security related operations can be performed. The PMem module data is encrypted.
Security Frozen
Any security command other than a status query is locked out until the next reboot. This state is intended to prevent tampering with the security settings.

The Device argument can be a specific PMem module (e.g., namespace0.0) or a comma-separated list of modules. If no device is specified, the command applies to all PMem modules managed by ndctl.

The --module option can be used to specify a specific PMem module for the command. The module identifier can be obtained from the output of ndctl list.

The --force option can be used to bypass confirmation prompts for destructive operations.

OPTIONS

-N, --dry-run
Print the command that would be sent to the PMem module, but do not send it.
-v, --verbose
Increase the verbosity of the output.

THEORY OF OPERATION

REMOVE PASSPHRASE

This command removes the current passphrase from the PMem module. After this operation, the security sub-system will be unlocked and the data on the PMem module will no longer be encrypted. This operation requires the current passphrase unless --force is used and the module is in a non-frozen state.

SET PASSPHRASE, UPDATE PASSPHRASE

set-passphrase: Sets a new passphrase for the PMem module. The module must be unlocked. If a passphrase is provided on the command line, it is used. Otherwise, the user will be prompted for a passphrase. The passphrase must be between 8 and 32 characters long.

update-passphrase: Updates the existing passphrase of the PMem module. This requires the old passphrase to be provided. The module must be locked (data encrypted) or unlocked. If the old passphrase is provided on the command line, it is used. Otherwise, the user will be prompted for the old passphrase. The new passphrase is then provided either on the command line or via prompt.

CRYPTO ERASE, OVERWRITE

crypto-erase: This command securely erases the data on the PMem module by leveraging the encryption engine. It effectively renders the data unrecoverable by cryptographic means. This command requires the module to be locked and the correct passphrase to be provided.

overwrite: This command securely erases the data on the PMem module by overwriting it with a specified pattern. This is a slower process than crypto-erase. This command requires the module to be unlocked. The kernel instruction WBINVD is issued by the kernel. If both --crypto-erase and --overwrite options are supplied, then crypto-erase is performed before overwrite.

SECURITY FREEZE

This operation does not require a passphrase. This will cause any security command other than a status query to be locked out until the next boot.

MASTER PASSPHRASE SETUP, UPDATE, and CRYPTO ERASE

These operations are similar to the user passphrase enable and update. The only difference is that a different passphrase is used. The master passphrase has no relation to the master key (kek) which is used for encryption of either passphrase.
