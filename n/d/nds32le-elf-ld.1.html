تنسيق الإدخال الافتراضي، التنسيق الأكثر شيوعًا على كل جهاز. input-format هو سلسلة نصية، اسم تنسيق معين تدعمه مكتبات BFD. (يمكنك عرض التنسيقات الثنائية المتاحة باستخدام objdump -i.)

قد ترغب في استخدام هذا الخيار إذا كنت تقوم بربط ملفات بتنسيق ثنائي غير عادي. يمكنك أيضًا استخدام -b للتبديل بين التنسيقات صراحةً (عند ربط ملفات الكائنات ذات التنسيقات المختلفة)، عن طريق تضمين -b input-format قبل كل مجموعة من ملفات الكائنات بتنسيق معين.

يتم أخذ التنسيق الافتراضي من متغير البيئة "GNUTARGET".

يمكنك أيضًا تحديد تنسيق الإدخال من نص برمجي، باستخدام الأمر "TARGET"؛

-c MRI-commandfile
--mri-script=MRI-commandfile
للتوافق مع الروابط التي أنتجتها MRI، يقبل ld ملفات النصوص البرمجية المكتوبة بلغة أوامر بديلة ومقيدة، موصوفة في قسم "ملفات النصوص البرمجية المتوافقة مع MRI" في توثيق GNU ld. قدم ملفات نصوص MRI البرمجية باستخدام الخيار -c؛ استخدم الخيار -T لتشغيل نصوص الروابط المكتوبة بلغة البرمجة ld للأغراض العامة. إذا لم يكن MRI-cmdfile موجودًا، فسيقوم ld بالبحث عنه في الأدلة المحددة بأي خيارات -L.
-d
-dc
-dp
هذه الخيارات الثلاثة متكافئة؛ يتم دعم أشكال متعددة للتوافق مع الروابط الأخرى. تقوم بتخصيص مساحة للرموز الشائعة حتى لو تم تحديد ملف إخراج قابل لإعادة التموضع (باستخدام -r). الأمر النصي "FORCE_COMMON_ALLOCATION" له نفس التأثير.
--depaudit AUDITLIB
-P AUDITLIB
يضيف AUDITLIB إلى الإدخال "DT_DEPAUDIT" في القسم الديناميكي. لا يتم التحقق من وجود AUDITLIB، ولا يستخدم DT_SONAME المحدد في المكتبة. إذا تم تحديده عدة مرات، فسيحتوي "DT_DEPAUDIT" على قائمة مفصولة بنقطتين رأسيتين لواجهات التدقيق المراد استخدامها. هذا الخيار له معنى فقط على منصات ELF التي تدعم واجهة rtld-audit. تم توفير الخيار -P للتوافق مع Solaris.
--enable-linker-version
يمكّن توجيه النص البرمجي للرابط "LINKER_VERSION"، الموصوف في بيانات قسم الإخراج. إذا تم استخدام هذا التوجيه في نص برمجي للرابط وتم تمكين هذا الخيار، فسيتم إدراج سلسلة تحتوي على إصدار الرابط في النقطة الحالية.

ملاحظة - موقع هذا الخيار في سطر أوامر الرابط مهم. سيؤثر فقط على النصوص البرمجية للروابط التي تأتي بعده في سطر الأوامر، أو التي تم بناؤها في الرابط.

--disable-linker-version
يعطّل توجيه النص البرمجي للرابط "LINKER_VERSION"، بحيث لا يقوم بإدراج سلسلة إصدار. هذا هو الإعداد الافتراضي.
--enable-non-contiguous-regions
يتجنب هذا الخيار توليد خطأ إذا كان قسم إدخال لا يناسب قسم إخراج مطابق. يحاول الرابط تخصيص قسم الإدخال لأقسام الإخراج المطابقة اللاحقة، ويولد خطأ فقط إذا لم يكن هناك قسم إخراج كبير بما فيه الكفاية. هذا مفيد عندما تتوفر عدة مناطق ذاكرة غير متجاورة ولا يتطلب قسم الإدخال واحدة معينة. لا يتغير ترتيب تقييم أقسام الإدخال، على سبيل المثال: 
MEMORY {
  MEM1 (rwx) : ORIGIN = 0x1000, LENGTH = 0x14
  MEM2 (rwx) : ORIGIN = 0x1000, LENGTH = 0x40
  MEM3 (rwx) : ORIGIN = 0x2000, LENGTH = 0x40
}
SECTIONS {
  mem1 : { *(.data.*); } > MEM1
  mem2 : { *(.data.*); } > MEM2
  mem3 : { *(.data.*); } > MEM3
}

مع أقسام الإدخال:
.data.1: size 8
.data.2: size 0x10
.data.3: size 4

ينتج عن ذلك تعيين .data.1 إلى mem1، وتعيين .data.2 و .data.3
إلى mem2، على الرغم من أن .data.3 سيتناسب مع mem3.

هذا الخيار غير متوافق مع عبارات INSERT لأنه يغير طريقة تعيين أقسام الإدخال إلى أقسام الإخراج.

--enable-non-contiguous-regions-warnings
يمكّن هذا الخيار التحذيرات عندما يسمح "--enable-non-contiguous-regions" بمطابقات غير متوقعة محتملة في تعيين الأقسام، مما قد يؤدي إلى تجاهل قسم بصمت بدلاً من الفشل لأنه لا يتناسب مع أي منطقة إخراج.
-e entry
--entry=entry
استخدم entry كرمز صريح لبدء تنفيذ برنامجك، بدلاً من نقطة الدخول الافتراضية. إذا لم يكن هناك رمز باسم entry، فسيحاول الرابط تحليل entry كرقم، واستخدامه كعنوان نقطة الدخول (سيتم تفسير الرقم بالأساس 10؛ يمكنك استخدام بادئة 0x للأساس 16، أو بادئة 0 للأساس 8).
--exclude-libs lib,lib,...
يحدد قائمة بمكتبات الأرشيف التي لا ينبغي تصدير الرموز منها تلقائيًا. يمكن فصل أسماء المكتبات بفاصلات أو نقطتين رأسيتين. تحديد "--exclude-libs ALL" يستبعد الرموز في جميع مكتبات الأرشيف من التصدير التلقائي. هذا الخيار متاح فقط لمنفذ i386 PE الموجه للرابط ومنافذ ELF الموجهة. بالنسبة لـ i386 PE، لا تزال الرموز المدرجة صراحةً في ملف .def مصدرة، بغض النظر عن هذا الخيار. بالنسبة لمنافذ ELF الموجهة، سيتم التعامل مع الرموز المتأثرة بهذا الخيار على أنها مخفية.
--exclude-modules-for-implib module,module,...
يحدد قائمة بملفات الكائنات أو أعضاء الأرشيف، التي لا ينبغي تصدير الرموز منها تلقائيًا، ولكن يجب نسخها بالكامل في مكتبة الاستيراد التي يتم إنشاؤها أثناء الربط. يمكن فصل أسماء الوحدات بفاصلات أو نقطتين رأسيتين، ويجب أن تتطابق تمامًا مع أسماء الملفات التي يستخدمها ld لفتح الملفات؛ بالنسبة لأعضاء الأرشيف، هذا هو مجرد اسم العضو، ولكن بالنسبة لملفات الكائنات، يجب أن يتضمن الاسم المدرج ويطابق تمامًا أي مسار مستخدم لتحديد ملف الإدخال في سطر أوامر الرابط. هذا الخيار متاح فقط لمنفذ i386 PE الموجه للرابط. الرموز المدرجة صراحةً في ملف .def لا تزال مصدرة، بغض النظر عن هذا الخيار.
-E
--export-dynamic
--no-export-dynamic
عند إنشاء ملف تنفيذي مرتبط ديناميكيًا، فإن استخدام الخيار -E أو الخيار --export-dynamic يتسبب في إضافة جميع الرموز إلى جدول الرموز الديناميكي. جدول الرموز الديناميكي هو مجموعة الرموز التي تكون مرئية من الكائنات الديناميكية في وقت التشغيل.

إذا لم تستخدم أيًا من هذين الخيارين (أو استخدمت الخيار --no-export-dynamic لاستعادة السلوك الافتراضي)، فسيحتوي جدول الرموز الديناميكي عادةً على الرموز فقط التي تمت الإشارة إليها بواسطة بعض الكائنات الديناميكية المذكورة في الرابط.

إذا استخدمت "dlopen" لتحميل كائن ديناميكي يحتاج إلى الإشارة مرة أخرى إلى الرموز المعرفة بواسطة البرنامج، بدلاً من كائن ديناميكي آخر، فستحتاج على الأرجح إلى استخدام هذا الخيار عند ربط البرنامج نفسه.

يمكنك أيضًا استخدام القائمة الديناميكية للتحكم في الرموز التي يجب إضافتها إلى جدول الرموز الديناميكي إذا كان تنسيق الإخراج يدعم ذلك. انظر وصف --dynamic-list.

لاحظ أن هذا الخيار خاص بمنافذ ELF الموجهة. تدعم أهداف PE وظيفة مماثلة لتصدير جميع الرموز من DLL أو EXE؛ انظر وصف --export-all-symbols أدناه.

--export-dynamic-symbol=glob
عند إنشاء ملف تنفيذي مرتبط ديناميكيًا، سيتم إضافة الرموز التي تطابق glob إلى جدول الرموز الديناميكي. عند إنشاء مكتبة مشتركة، لن يتم ربط المراجع إلى الرموز التي تطابق glob بتعريفاتها داخل المكتبة المشتركة. هذا الخيار لا يفعل شيئًا عند إنشاء مكتبة مشتركة ولم يتم تحديد -Bsymbolic أو --dynamic-list. هذا الخيار له معنى فقط على منصات ELF التي تدعم المكتبات المشتركة.
--export-dynamic-symbol-list=file
حدد --export-dynamic-symbol لكل نمط في الملف. تنسيق الملف هو نفس عقدة الإصدار بدون نطاق واسع واسم عقدة. انظر VERSION لمزيد من المعلومات.
-EB
ربط كائنات big-endian. يؤثر هذا على تنسيق الإخراج الافتراضي.
-EL
ربط كائنات little-endian. يؤثر هذا على تنسيق الإخراج الافتراضي.
-f name
--auxiliary=name
عند إنشاء كائن مشاركة ELF، قم بتعيين حقل DT_AUXILIARY الداخلي إلى الاسم المحدد. يخبر هذا الرابط الديناميكي أنه يجب استخدام جدول رموز كائن المشاركة كمرشح مساعد لجدول رموز كائن المشاركة name.

إذا قمت لاحقًا بربط برنامج بهذا الكائن المرشح، فعند تشغيل البرنامج، سيرى الرابط الديناميكي حقل DT_AUXILIARY. إذا كان هناك تعريف في كائن المشاركة name، فسيتم استخدامه بدلاً من التعريف في الكائن المرشح. لا يلزم وجود كائن المشاركة name. وبالتالي يمكن استخدام كائن المشاركة name لتوفير تنفيذ بديل لوظائف معينة، ربما لأغراض التصحيح أو لتحسين الأداء الخاص بالجهاز.

يمكن تحديد هذا الخيار أكثر من مرة. سيتم إنشاء إدخالات DT_AUXILIARY بالترتيب الذي تظهر به في سطر الأوامر.

-F name
scriptfile موجودًا في الدليل الحالي، فإن "ld" يبحث عنه في الدلائل المحددة بأي خيارات -L سابقة. تتراكم خيارات -T المتعددة.
-dT scriptfile
--default-script=scriptfile
استخدم scriptfile كملف نصي للرابط الافتراضي.

هذا الخيار مشابه للخيار --script باستثناء أن معالجة النص النصي يتم تأجيلها حتى بعد معالجة بقية سطر الأوامر. هذا يسمح للخيارات الموضوعة بعد الخيار --default-script على سطر الأوامر بالتأثير على سلوك نص الرابط، والذي يمكن أن يكون مهمًا عندما لا يمكن التحكم في سطر أوامر الرابط مباشرة بواسطة المستخدم. (على سبيل المثال، لأنه يتم بناء سطر الأوامر بواسطة أداة أخرى، مثل gcc).

-u symbol
--undefined=symbol
فرض إدخال symbol في ملف الإخراج كرمز غير محدد. قد يؤدي القيام بذلك، على سبيل المثال، إلى تشغيل ربط وحدات إضافية من المكتبات القياسية. يمكن تكرار -u مع حجج خيارات مختلفة لإدخال رموز غير محددة إضافية. هذا الخيار مكافئ لأمر نص الرابط "EXTERN".

إذا كان هذا الخيار قيد الاستخدام لفرض سحب وحدات إضافية إلى الرابط، وإذا كان الخطأ هو بقاء الرمز غير محدد، فيجب استخدام الخيار --require-defined بدلاً من ذلك.

--require-defined=symbol
يتطلب أن يكون symbol محددًا في ملف الإخراج. هذا الخيار هو نفس الخيار --undefined باستثناء أنه إذا لم يكن symbol محددًا في ملف الإخراج، فسيقوم الرابط بإصدار خطأ والخروج. يمكن تحقيق نفس التأثير في نص الرابط باستخدام "EXTERN" و "ASSERT" و "DEFINED" معًا. يمكن استخدام هذا الخيار عدة مرات للمطالبة برموز إضافية.
-Ur
بالنسبة للبرامج التي لا تستخدم مُنشئات أو مُدمّرات، أو لأنظمة ELF، فإن هذا الخيار يعادل -r: فهو ينشئ إخراجًا قابلاً للإصلاح - أي، ملف إخراج يمكن بدوره أن يكون مدخلاً لـ ld. بالنسبة للملفات التنفيذية الأخرى، ومع ذلك، فإن الخيار -Ur مشابه لـ -r ولكنه يحل أيضًا المراجع إلى المُنشئات والمُدمّرات.

بالنسبة لتلك الأنظمة التي يختلف فيها سلوك -r و -Ur، فإنه لا يعمل استخدام -Ur على الملفات التي تم ربطها بنفسها باستخدام -Ur؛ بمجرد بناء جدول المُنشئات، لا يمكن إضافته. استخدم -Ur فقط للرابط الجزئي الأخير، و -r للآخرين.

--orphan-handling=MODE
التحكم في كيفية معالجة الأقسام اليتيمة. القسم اليتيم هو قسم غير مذكور صراحة في نص الرابط.

يمكن أن يأخذ MODE أيًا من القيم التالية:

"place"
يتم وضع الأقسام اليتيمة في قسم إخراج مناسب باتباع الاستراتيجية الموضحة في الأقسام اليتيمة. يؤثر الخيار --unique أيضًا على كيفية وضع الأقسام.
"discard"
يتم تجاهل جميع الأقسام اليتيمة، عن طريق وضعها في قسم /DISCARD/.
"warn"
سيقوم الرابط بوضع القسم اليتيم كما هو الحال بالنسبة لـ "place" وإصدار تحذير أيضًا.
"error"
سيخرج الرابط بخطأ إذا تم العثور على أي قسم يتيم.

الافتراضي إذا لم يتم تقديم --orphan-handling هو "place".

--unique[=SECTION]
ينشئ قسم إخراج منفصل لكل قسم إدخال مطابق لـ SECTION، أو إذا كان وسيط القسم العام الاختياري مفقودًا، لكل قسم إدخال يتيم. القسم اليتيم هو قسم غير مذكور صراحة في نص الرابط. يمكنك استخدام هذا الخيار عدة مرات على سطر الأوامر؛ إنه يمنع الدمج العادي لأقسام الإدخال بنفس الاسم، ويتجاوز تعيينات أقسام الإخراج في نص الرابط.
-v
--version
-V
عرض رقم الإصدار لـ ld. يعرض الخيار -V أيضًا المحاكيات المدعومة. انظر أيضًا وصف --enable-linker-version في Options,,Command-line Options والذي يمكن استخدامه لإدراج سلسلة إصدار الرابط في ملف ثنائي.
-x
--discard-all
حذف جميع الرموز المحلية.
-X
--discard-locals
حذف جميع الرموز المحلية المؤقتة. (تبدأ هذه الرموز ببادئات تسمية محلية خاصة بالنظام، عادةً .L لأنظمة ELF أو L لأنظمة a.out التقليدية.)
-y symbol
--trace-symbol=symbol
طباعة اسم كل ملف مرتبط يظهر فيه symbol. يمكن تقديم هذا الخيار عددًا غير محدود من المرات. في العديد من الأنظمة، من الضروري إضافة شرطة سفلية في البداية.

-Y path
أضف path إلى مسار البحث عن المكتبة الافتراضي. هذا الخيار موجود للتوافق مع Solaris.
-z keyword
الكلمات الرئيسية المعترف بها هي:
call-nop=prefix-addr
call-nop=suffix-nop
call-nop=prefix-byte
call-nop=suffix-byte
حدد حشو 1-byte "NOP" عند تحويل المكالمة غير المباشرة إلى دالة معرفة محليًا، foo، عبر فتحة GOT الخاصة بها. call-nop=prefix-addr ينشئ "0x67 call foo". call-nop=suffix-nop ينشئ "call foo 0x90". call-nop=prefix-byte ينشئ "byte call foo". call-nop=suffix-byte ينشئ "call foo byte". مدعوم لـ i386 و x86_64.
cet-report=none
cet-report=warning
cet-report=error
حدد كيفية الإبلاغ عن خصائص GNU_PROPERTY_X86_FEATURE_1_IBT و GNU_PROPERTY_X86_FEATURE_1_SHSTK المفقودة في قسم .note.gnu.property للإدخال. cet-report=none، وهو الافتراضي، سيجعل الرابط لا يبلغ عن الخصائص المفقودة في ملفات الإدخال. cet-report=warning سيجعل الرابط يصدر تحذيرًا للخصائص المفقودة في ملفات الإدخال. cet-report=error سيجعل الرابط يصدر خطأ للخصائص المفقودة في ملفات الإدخال. لاحظ أن ibt سيوقف الإبلاغ عن خاصية GNU_PROPERTY_X86_FEATURE_1_IBT المفقودة و shstk سيوقف الإبلاغ عن خاصية GNU_PROPERTY_X86_FEATURE_1_SHSTK المفقودة. مدعوم لـ Linux/i386 و Linux/x86_64.
combreloc
nocombreloc

common
nocommon
إنشاء رموز مشتركة من نوع STT_COMMON أثناء رابط قابل للإصلاح. استخدم نوع STT_OBJECT إذا كان nocommon.
common-page-size=value
تعيين حجم الصفحة الأكثر استخدامًا إلى value. سيتم تحسين تخطيط صورة الذاكرة لتقليل صفحات الذاكرة إذا كان النظام يستخدم صفحات بهذا الحجم.

--warn-constructors

--warn-execstack
--warn-execstack-objects
--no-warn-execstack
على منصات ELF، قد يقوم الرابط بإنشاء رسائل تحذير إذا طُلب منه إنشاء ملف إخراج يحتوي على مكدس قابل للتنفيذ. هناك ثلاث حالات ممكنة:
1.
لا يتم إنشاء أي تحذيرات.
2.
يتم إنشاء التحذيرات دائمًا، حتى لو تم طلب مكدس قابل للتنفيذ عبر الخيار -z execstack في سطر الأوامر.
3.
يتم إنشاء تحذير فقط إذا طلب ملف كائن مكدسًا قابلاً للتنفيذ، ولكن ليس إذا تم استخدام الخيار -z execstack.

تعتمد الحالة الافتراضية على كيفية تكوين الرابط عند بنائه. يضع الخيار --no-warn-execstack الرابط دائمًا في وضع عدم وجود تحذيرات. يضع الخيار --warn-execstack الرابط في وضع التحذير دائمًا. يضع الخيار --warn-execstack-objects الرابط في وضع التحذير لملفات الكائنات فقط.

ملاحظة: يمكن لملفات الإدخال بتنسيق ELF تحديد أنها تحتاج إلى مكدس قابل للتنفيذ عن طريق وجود قسم .note.GNU-stack مع تعيين بت التنفيذ في علامات القسم الخاص به. يمكنها تحديد أنها لا تحتاج إلى مكدس قابل للتنفيذ عن طريق وجود نفس القسم، ولكن بدون تعيين بت علامة التنفيذ. إذا لم يكن لملف الإدخال قسم .note.GNU-stack، فإن السلوك الافتراضي يعتمد على الهدف. بالنسبة لبعض الأهداف، فإن عدم وجود مثل هذا القسم يعني أنه *مطلوب* مكدس قابل للتنفيذ. غالبًا ما يمثل هذا مشكلة لملفات التجميع المصنوعة يدويًا.

These options control whether section names longer than 8 characters are allowed in PE object files and executable images. By default, long section names are not allowed in object files, as fully-linked executable images do not carry the COFF string table required to support the longer names. As a GNU extension, it is possible to allow their use in executable images as well, or to (probably pointlessly!) disallow it in object files, by using these two options. Executable images generated with these long section names are slightly non-standard, carrying as they do a string table, and may generate confusing output when examined with non-GNU PE-aware tools, such as file viewers and dumpers. However, GDB relies on the use of PE long section names to find Dwarf-2 debug information sections in an executable image at runtime, and so if neither option is specified on the command-line, ld will enable long section names, overriding the default and technically correct behaviour, when it finds the presence of debug information while linking an executable image and not stripping symbols. For example, the undefined symbol "_foo" might be linked to the function "_foo@12", or the undefined symbol "_bar@16" might be linked to the function "_bar". If you specify --enable-stdcall-fixup, this feature is fully enabled and warnings are not printed. قم بالربط المتطور لـ "_symbol" بـ "__imp__symbol" لاستيرادات البيانات من وحدات DLL، مما يجعل من الممكن تجاوز آلية dllimport من جانب المستخدم والإشارة إلى أسماء رموز غير مشوشة. [هذا الخيار خاص بمنفذ الرابط المستهدف i386 PE]

الملاحظات التالية تتعلق بالتنفيذ الأصلي للخاصية وهي قديمة الآن لأهداف Cygwin و MinGW.

ملاحظة: استخدام امتداد 'auto-import' سيجعل قسم النص في ملف الصورة قابلاً للكتابة. وهذا لا يتوافق مع مواصفات تنسيق PE-COFF المنشورة بواسطة Microsoft.

ملاحظة - استخدام امتداد 'auto-import' سيؤدي أيضًا إلى وضع البيانات للقراءة فقط والتي ستوضع عادةً في قسم .rdata في قسم .data بدلاً من ذلك. هذا لتجاوز مشكلة مع الثوابت التي تم وصفها هنا: http://www.cygwin.com/ml/cygwin/2004-09/msg01101.html

استخدام 'auto-import' بشكل عام سيعمل 'ببساطة' - ولكن في بعض الأحيان قد ترى هذه الرسالة:

"لا يمكن استيراد المتغير '<var>' تلقائيًا. يرجى قراءة الوثائق الخاصة بـ ld "--enable-auto-import" لمعرفة التفاصيل."

تحدث هذه الرسالة عندما يصل بعض (الفرع) تعبير إلى عنوان يُعطى في النهاية عن طريق مجموع ثابتين (جداول استيراد Win32 تسمح بواحد فقط). الحالات التي قد يحدث فيها هذا تشمل الوصول إلى حقول الأعضاء من متغيرات الهياكل المستوردة من وحدة DLL، وكذلك استخدام فهرس ثابت لمتغير مصفوفة مستورد من وحدة DLL. قد يؤدي أي متغير متعدد الكلمات (مصفوفات، هياكل، long long، إلخ) إلى ظهور هذه الحالة الخطأ. ومع ذلك، بغض النظر عن نوع البيانات الدقيق للمتغير المصدر المصدر، سيقوم ld دائمًا بالكشف عنه وإصدار التحذير والخروج.

هناك عدة طرق لمعالجة هذه الصعوبة، بغض النظر عن نوع البيانات للمتغير المصدر:

إحدى الطرق هي استخدام مفتاح --enable-runtime-pseudo-reloc. هذا يترك مهمة ضبط الإشارات المرجعية في رمز العميل الخاص بك لبيئة وقت التشغيل، لذا تعمل هذه الطريقة فقط عندما تدعم بيئة وقت التشغيل هذه الميزة.

الحل الثاني هو إجبار أحد 'الثوابت' على أن يكون متغيرًا - أي، غير معروف وغير قابل للتحسين في وقت الترجمة. بالنسبة للمصفوفات، هناك احتمالان: أ) جعل الفهرس (عنوان المصفوفة) متغيرًا، أو ب) جعل الفهرس 'الثابت' متغيرًا. وبالتالي:

extern type extern_array[];
extern_array[1] -->
   { volatile type *t=extern_array; t[1] }

أو

extern type extern_array[];
extern_array[1] -->
   { volatile int t=1; extern_array[t] }

بالنسبة للهياكل (ومعظم أنواع البيانات الأخرى متعددة الكلمات)، فإن الخيار الوحيد هو جعل الهيكل نفسه (أو long long، أو ...) متغيرًا:

extern struct s extern_struct;
extern_struct.field -->
   { volatile struct s *t=&extern_struct; t->field }

أو

extern long long extern_ll;
extern_ll -->
  { volatile long long * local_ll=&extern_ll; *local_ll }

الطريقة الثالثة للتعامل مع هذه الصعوبة هي التخلي عن 'auto-import' للرمز المسبب للمشكلة ووضع علامة عليه بـ "__declspec(dllimport)". ومع ذلك، عملياً يتطلب ذلك استخدام تعريفات وقت الترجمة للإشارة إلى ما إذا كنت تقوم بإنشاء وحدة DLL، أو بناء رمز عميل سيرتبط بوحدة DLL، أو مجرد بناء / ربط بمكتبة ثابتة. عند الاختيار بين الطرق المختلفة لحل مشكلة 'العنوان المباشر مع إزاحة ثابتة'، يجب أن تأخذ في الاعتبار الاستخدام الفعلي في العالم الحقيقي:

الأصلي:

--foo.h
extern int arr[];
--foo.c
#include "foo.h"
void main(int argc, char **argv){
  printf("%d\n",arr[1]);
}

الحل 1:

--foo.h
extern int arr[];
--foo.c
#include "foo.h"
void main(int argc, char **argv){
  /* هذا الحل هو لـ win32 و cygwin؛ لا تقم بـ "التحسين" */
  volatile int *parr = arr;
  printf("%d\n",parr[1]);
}

الحل 2:

--foo.h
/* ملاحظة: يفترض التصدير التلقائي (لا يوجد __declspec(dllexport)) */
#if (defined(_WIN32) || defined(__CYGWIN__)) && \
  !(defined(FOO_BUILD_DLL) || defined(FOO_STATIC))
#define FOO_IMPORT __declspec(dllimport)
#else
#define FOO_IMPORT
#endif
extern FOO_IMPORT int arr[];
--foo.c
#include "foo.h"
void main(int argc, char **argv){
  printf("%d\n",arr[1]);
}

DESCRIPTION

The GNU linker ld is used to combine a number of object files and libraries, which are passed to it as a command line list, and create a single file, usually an executable file or a shared library.

The linker can be invoked with an option that specifies the kind of files to create. For example, ld(1) can create an executable file for use by Unix. It can also create a shared library.

The linker searches a list of directories for object files and libraries that have not been explicitly specified.

The linker supports a number of options for selecting the machine architecture, the type of executable file to create, the symbol table information to include, and for directing the linker's output.

ld can also be used to process linker scripts.

OPTIONS

The long options are supported if the linker was configured with --enable-long-long.

A summary of options is contained in the synopsis section above. The options that are available depend on the BFD library configuration.

Some options are available in multiple forms; for example, --static and -static. These are equivalent.

ENVIRONMENT

The linker checks for the following environment variables.

LD_BINFMT_FLAT If this environment variable is set, then ld(1) will default to not demangling symbols. This environment variable is used in a similar fashion by the "gcc" linker wrapper program. The default may be overridden by the --demangle and --no-demangle options.
