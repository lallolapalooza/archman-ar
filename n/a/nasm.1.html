NAME

\n

nasm â Netwide Assembler

\n

SYNOPSIS

\n

nasm [-f format] [-o outfile] [-l listfile] [-I path] [-D macro[=value]] [-U macro] [-X macro] [-i path] [-d macro[=value]] [-u macro] [-x macro] [--] infile...

\n
\n
\n

DESCRIPTION

\n

nasm is an assembler for the Intel 80x86 processor family. It is designed to provide a convenient and efficient way of writing assembly-language programs. It supports a number of output formats, including Linux/i386 object code, Linux a.out code, Microsoft 16-bit object code, dead.letter code, a flat binary format, and Java class files.

\n

This document describes the directives and preprocessor commands of nasm.

\n
\n
\n

OPTIONS

\n

The options are as follows:

\n
\n
-f format
\n
Specifies the output format for the assembly. If this is not given, nasm will guess based on the filename extension of the output file, or default to elf32 if no output file is specified.
\n
-o outfile
\n
Specifies the name of the output file. If this is not given, the output is written to stdout.
\n
-l listfile
\n
Causes a listing file to be produced. This file contains the source code, with line numbers and the generated machine code. If listfile is not given, the listing is written to stdout.
\n
-I path
\n
Adds a directory to the list of paths searched for included files. This option can be given multiple times.
\n
-D macro[=value]
\n
Defines a preprocessor macro. This is equivalent to using the %define directive in the source file.
\n
-U macro
\n
Undefines a preprocessor macro. This is equivalent to using the %undef directive in the source file.
\n
-X macro
\n
Causes the preprocessor to report an error if a macro is used but not defined. This is used in conjunction with -D and -U to ensure macros are always defined.
\n
-i path
\n
Adds a directory to the list of paths searched for included files. This is an alias for -I.
\n
-d macro[=value]
\n
Defines a preprocessor macro. This is an alias for -D.
\n
-u macro
\n
Undefines a preprocessor macro. This is an alias for -U.
\n
-x macro
\n
Causes the preprocessor to report an error if a macro is used but not defined. This is an alias for -X.
\n
--
\n
Signals the end of the options. Any remaining arguments are treated as input filenames.
\n
\n

SYNTAX

\n

The syntax of nasm is largely compatible with the Intel syntax used by MASM. However, it also supports a more concise alternative syntax. The assembler can be instructed to use either syntax using the INSTRUCTION directive, although the default is Intel syntax.

\n

Labels are defined by ending a line with a colon (:). For example: my_label:.

\n

Symbols can be defined using the EQU directive, e.g.: MY_CONST EQU 10.

\n

You can define a symbol that refers to the current assembly location using the dollar sign ($).

\n

The assembler supports standard mathematical operators (+, -, *, /, &, |, ^, ~, <<, >>) and parentheses for grouping.

\n

String literals can be enclosed in either single quotes (') or double quotes (").

\n

Comments are introduced by a semicolon (;) and extend to the end of the line.

\n

The ORG directive sets the current assembly address. For example: ORG 0x100.

\n

The EVEN directive advances the assembly point to the next even address.

\n

The ALIGN directive advances the assembly point to the next address divisible by the given value.

\n

The TIMES directive repeats the following instruction or data definition a specified number of times.

\n

The LOCAL directive defines a label that is local to the current macro invocation. This is useful for avoiding label collisions when using macros.

\n

A local label is constructed by appending a dollar sign ($) to a normal label name. For example, if you define a local label named loop inside a macro, it will be instantiated as my_macro.loop$, where my_macro is the name of the macro. The assembler automatically creates a symbol for the loop label: label.loop.

\n
\n
\n

DIRECTIVES

\n

SECTION name or SEGMENT name causes\nnasm to direct all following code to the named section. Section names\nvary with output file format, although most formats support the names\n.text, .data and .bss. (The exception is the obj\nformat, in which all segments are user-definable.)

\n

ABSOLUTE address causes nasm to position its\nnotional assembly point at an absolute address: so no code or data may be\ngenerated, but you can use RESB, RESW and RESD to move\nthe assembly point further on, and you can define labels. So this directive\nmay be used to define data structures. When you have finished doing absolute\nassembly, you must issue another SECTION directive to return to\nnormal assembly.

\n

BITS 16, BITS 32 or BITS\n64 switches the default processor mode for which nasm is\ngenerating code: it is equivalent to USE16 or USE32 in DOS\nassemblers.

\n

EXTERN symbol and GLOBAL symbol import\nand export symbol definitions, respectively, from and to other modules. Note\nthat the GLOBAL directive must appear before the definition of the\nsymbol it refers to.

\n

STRUC strucname and ENDSTRUC, when used to\nbracket a number of RESB, RESW or similar instructions, define\na data structure. In addition to defining the offsets of the structure\nmembers, the construct also defines a symbol for the size of the structure,\nwhich is simply the structure name with size tacked on to the\nend.

\n
\n
\n

FORMAT-SPECIFIC DIRECTIVES

\n

ORG address is used by the bin flat-form\nbinary output format, and specifies the address at which the output code\nwill eventually be loaded.

\n

GROUP grpname seg1 seg2... is used by\nthe obj (Microsoft 16-bit) output format, and defines segment groups. This\nformat also uses UPPERCASE, which directs that all segment, group and\nsymbol names output to the object file should be in uppercase. Note that the\nactual assembly is still case sensitive.

\n

LIBRARY libname is used by the rdf output\nformat, and causes a dependency record to be written to the output file\nwhich indicates that the program requires a certain library in order to\nrun.

\n
\n
\n

MACRO PREPROCESSOR

\n

Single-line macros are defined using the %define or\n%idefine commands, in a similar fashion to the C preprocessor. They\ncan be overloaded with respect to number of parameters, although defining a\nmacro with no parameters prevents the definition of any macro with the same\nname taking parameters, and vice versa. %define defines macros whose\nnames match case-sensitively, whereas %idefine defines\ncase-insensitive macros.

\n

Multi-line macros are defined using %macro and\n%imacro (the distinction is the same as that between %define\nand %idefine), whose syntax is as follows

\n
\n
%macro name minprm[-maxprm][+][.nolist] [defaults]\n        <some lines of macro expansion text>\n%endmacro
\n
\n

Again, these macros may be overloaded. The trailing plus sign\nindicates that any parameters after the last one get subsumed, with their\nseparating commas, into the last parameter. The defaults part can be\nused to specify defaults for unspecified macro parameters after\nminparam. %endm is a valid synonym for %endmacro.

\n

To refer to the macro parameters within a macro expansion, you use\n%1, %2 and so on. You can also enforce that a macro parameter\nshould contain a condition code by using %+1, and you can invert the\ncondition code by using %-1. You can also define a label specific to\na macro invocation by prefixing it with a double ‘%’ sign.

\n

Files can be included using the %include directive, which\nworks like C.

\n

The preprocessor has a ‘context stack’, which may be\nused by one macro to store information that a later one will retrieve. You\ncan push a context on the stack using %push, remove one using\n%pop, and change the name of the top context (without disturbing any\nassociated definitions) using %repl. Labels and %define macros\nspecific to the top context may be defined by prefixing their names with %$,\nand things specific to the next context down with %$$, and so on.

\n

Conditional assembly is done by means of %ifdef,\n%ifndef, %else and %endif as in C. (Except that\n%ifdef can accept several putative macro names, and will evaluate\nTRUE if any of them is defined.) In addition, the directives %ifctx\nand %ifnctx can be used to condition on the name of the top context\non the context stack. The obvious set of ‘else-if’ directives,\n%elifdef, %elifndef, %elifctx and %elifnctx are\nalso supported.

الملخص

\n

nasm [-f format] [-o outfile] [-l listfile] [-I path] [-D macro[=value]] [-U macro] [-X macro] [-i path] [-d macro[=value]] [-u macro] [-x macro] [--] infile...

\n

الوصف

\n

nasm هو مجمّع لعائلة معالجات Intel 80x86. تم تصميمه لتوفير طريقة مريحة وفعالة لكتابة برامج لغة التجميع. وهو يدعم عددًا من تنسيقات الإخراج، بما في ذلك كود كائن Linux/i386، وكود Linux a.out، وكود كائن Microsoft 16 بت، وكود dead.letter، وتنسيق ثنائي مسطح، وملفات فئة Java.

\n

توثق هذه المستند التوجيهات وأوامر المعالج المسبق لـ nasm.

\n
\n
\n

الخيارات

\n

الخيارات هي كما يلي:

\n
\n
-f format
\n
يحدد تنسيق الإخراج للتجميع. إذا لم يتم توفير هذا، فسيقوم nasm بالتخمين بناءً على امتداد اسم ملف الإخراج، أو الافتراضي إلى elf32 إذا لم يتم تحديد ملف إخراج.
\n
-o outfile
\n
يحدد اسم ملف الإخراج. إذا لم يتم توفير هذا، يتم كتابة الإخراج إلى stdout.
\n
-l listfile
\n
يؤدي إلى إنتاج ملف قائمة. يحتوي هذا الملف على الكود المصدري، مع أرقام الأسطر والتعليمات الآلية التي تم إنشاؤها. إذا لم يتم توفير listfile، تتم كتابة القائمة إلى stdout.
\n
-I path
\n
يضيف دليلًا إلى قائمة المسارات التي يتم البحث فيها عن الملفات المضمنة. يمكن تقديم هذا الخيار عدة مرات.
\n
-D macro[=value]
\n
يحدد ماكرو للمعالج المسبق. هذا يعادل استخدام التوجيه %define في الملف المصدري.
\n
-U macro
\n
يزيل تعريف ماكرو للمعالج المسبق. هذا يعادل استخدام التوجيه %undef في الملف المصدري.
\n
-X macro
\n
يجعل المعالج المسبق يبلغ عن خطأ إذا تم استخدام ماكرو ولكنه غير معرف. يستخدم هذا بالاقتران مع -D و -U لضمان تعريف الماكروات دائمًا.
\n
-i path
\n
يضيف دليلًا إلى قائمة المسارات التي يتم البحث فيها عن الملفات المضمنة. هذا اسم مستعار لـ -I.
\n
-d macro[=value]
\n
يحدد ماكرو للمعالج المسبق. هذا اسم مستعار لـ -D.
\n
-u macro
\n
يزيل تعريف ماكرو للمعالج المسبق. هذا اسم مستعار لـ -U.
\n
-x macro
\n
يجعل المعالج المسبق يبلغ عن خطأ إذا تم استخدام ماكرو ولكنه غير معرف. هذا اسم مستعار لـ -X.
\n
--
\n
يشير إلى نهاية الخيارات. يتم التعامل مع أي وسائط متبقية على أنها أسماء ملفات إدخال.

الصيغة

\n

صيغة nasm متوافقة إلى حد كبير مع صيغة Intel التي يستخدمها MASM. ومع ذلك، فإنه يدعم أيضًا صيغة بديلة أكثر إيجازًا. يمكن توجيه المجمّع لاستخدام أي من الصيغتين باستخدام التوجيه INSTRUCTION، على الرغم من أن الافتراضي هو صيغة Intel.

\n

يتم تعريف التسميات عن طريق إنهاء السطر بنقطتين رأسيتين (:). على سبيل المثال: my_label:.

\n

يمكن تعريف الرموز باستخدام التوجيه EQU، على سبيل المثال: MY_CONST EQU 10.

\n

يمكنك تعريف رمز يشير إلى موقع التجميع الحالي باستخدام علامة الدولار ($).

\n

يدعم المجمّع عوامل رياضية قياسية (+، -، *، /، &، |، ^، ~، <<، >>) والأقواس للتجميع.

\n

يمكن إحاطة ثوابت السلاسل النصية بعلامات اقتباس مفردة (') أو مزدوجة (").

\n

يتم تقديم التعليقات بواسطة فاصلة منقوطة (;) وتمتد حتى نهاية السطر.

\n

يقوم التوجيه ORG بتعيين عنوان التجميع الحالي. على سبيل المثال: ORG 0x100.

\n

يقوم التوجيه EVEN بتقديم نقطة التجميع إلى العنوان الزوجي التالي.

\n

يقوم التوجيه ALIGN بتقديم نقطة التجميع إلى العنوان التالي القابل للقسمة على القيمة المعطاة.

\n

يقوم التوجيه TIMES بتكرار التعليمات التالية أو تعريف البيانات عددًا محددًا من المرات.

\n

يقوم التوجيه LOCAL بتعريف تسمية محلية لاستدعاء الماكرو الحالي. هذا مفيد لتجنب تضارب التسميات عند استخدام الماكروات.

\n

يتم إنشاء تسمية محلية عن طريق إلحاق علامة الدولار ($) باسم تسمية عادي. على سبيل المثال، إذا قمت بتعريف تسمية محلية باسم loop داخل ماكرو، فسيتم إنشاؤها باسم my_macro.loop$، حيث my_macro هو اسم الماكرو. يقوم المجمّع تلقائيًا بإنشاء رمز للتسمية loop: label.loop.

\n

التوجيهات

\n

SECTION name أو SEGMENT name يتسبب\nفي توجيه nasm لكل التعليمات البرمجية اللاحقة إلى القسم المسمى. تختلف أسماء الأقسام حسب تنسيق ملف الإخراج، على الرغم من أن معظم التنسيقات تدعم الأسماء\n.text، .data و .bss. (الاستثناء هو تنسيق obj،\nحيث يمكن تعريف جميع المقاطع بواسطة المستخدم.)

\n

ABSOLUTE address يتسبب في أن يضع nasm نقطة\nالتجميع المفاهيمية الخاصة به في عنوان مطلق: لذلك لا يمكن إنشاء أي تعليمات\nبرمجية أو بيانات، ولكن يمكنك استخدام RESB و RESW و RESD\nلتحريك نقطة التجميع إلى الأمام، ويمكنك تعريف التسميات. لذلك يمكن استخدام هذا\nالتوجيه لتعريف هياكل البيانات. عند الانتهاء من التجميع المطلق، يجب عليك\nإصدار توجيه SECTION آخر للعودة إلى التجميع العادي.

\n

BITS 16، BITS 32 أو BITS\n64 يبدل وضع المعالج الافتراضي الذي يقوم nasm بإنشاء\nتعليمات برمجية له: إنه يعادل USE16 أو USE32 في مجمّعات DOS.

\n

EXTERN symbol و GLOBAL symbol\nيستوردان ويصدّران تعريفات الرموز، على التوالي، من وإلى وحدات أخرى. لاحظ أن\nالتوجيه GLOBAL يجب أن يظهر قبل تعريف الرمز الذي يشير إليه.

\n

STRUC strucname و ENDSTRUC، عند استخدامهما\nلتحديد عدد من التعليمات RESB و RESW أو ما شابهها، يحددان\nهيكل بيانات. بالإضافة إلى تحديد الإزاحات لأعضاء الهيكل، يقوم التركيب أيضًا\nبتعريف رمز لحجم الهيكل، وهو ببساطة اسم الهيكل مع إضافة size\nإلى النهاية.

\n
\n

التوجيهات الخاصة بالتنسيق

\n

ORG address يستخدم بواسطة تنسيق الإخراج الثنائي المسطح\nbin، ويحدد العنوان الذي سيتم تحميل التعليمات البرمجية للإخراج\nفيه في النهاية.

\n

GROUP grpname seg1 seg2... يستخدم بواسطة\nتنسيق الإخراج obj (Microsoft 16 بت)، ويحدد مجموعات المقاطع. يستخدم هذا\nالتنسيق أيضًا UPPERCASE، الذي يوجه إلى أن جميع أسماء المقاطع والمجموعات\nوالرموز التي يتم إخراجها إلى ملف الكائن يجب أن تكون بأحرف كبيرة. لاحظ أن\nالتجميع الفعلي لا يزال حساسًا لحالة الأحرف.

\n

LIBRARY libname يستخدم بواسطة تنسيق الإخراج rdf،\nويؤدي إلى كتابة سجل اعتماد في ملف الإخراج يشير إلى أن البرنامج يتطلب\nمكتبة معينة للتشغيل.

المعالج المسبق للماكرو

\n

يتم تعريف الماكروات ذات السطر الواحد باستخدام أوامر %define أو\n%idefine، بطريقة مشابهة للمعالج المسبق C. يمكن تحميلها بشكل زائد\nفيما يتعلق بعدد المعلمات، على الرغم من أن تعريف ماكرو بدون معلمات يمنع\nتعريف أي ماكرو بنفس الاسم يأخذ معلمات، والعكس صحيح. %define\nيعرف الماكروات التي تتطابق أسماؤها بحساسية حالة الأحرف، بينما %idefine\nيعرف الماكروات غير الحساسة لحالة الأحرف.

\n

يتم تعريف الماكروات متعددة الأسطر باستخدام %macro و\n%imacro (الفرق هو نفس الفرق بين %define و %idefine)،\nوتكون صيغتها كما يلي

\n
\n
%macro name minprm[-maxprm][+][.nolist] [defaults]\n        <some lines of macro expansion text>\n%endmacro
\n
\n

مرة أخرى، يمكن تحميل هذه الماكروات بشكل زائد. تشير علامة الزائد\nاللاحقة إلى أن أي معلمات بعد الأخيرة يتم استيعابها، مع فواصلها، في المعلمة\nالأخيرة. يمكن استخدام جزء defaults لتحديد القيم الافتراضية للمعلمات\nالماكرو غير المحددة بعد minparam. %endm هو اسم مرادف صالح\nلـ %endmacro.

\n

للإشارة إلى معلمات الماكرو داخل توسيع الماكرو، استخدم %1 و\n%2 وما إلى ذلك. يمكنك أيضًا فرض أن تحتوي معلمة الماكرو على رمز\nشرط باستخدام %+1، ويمكنك عكس رمز الشرط باستخدام %-1. يمكنك\nأيضًا تعريف تسمية خاصة باستدعاء الماكرو عن طريق وضع علامة النسبة المئوية\nالمزدوجة (%%) قبلها.

\n

يمكن تضمين الملفات باستخدام التوجيه %include، والذي\nيعمل مثل C.

\n

يحتوي المعالج المسبق على \"مكدس السياق\"، والذي يمكن استخدامه بواسطة\nماكرو واحد لتخزين المعلومات التي سيستردها لاحقًا ماكرو آخر. يمكنك دفع\nسياق على المكدس باستخدام %push، وإزالة واحد باستخدام %pop،\nوتغيير اسم السياق العلوي (دون إزعاج أي تعريفات مرتبطة) باستخدام %repl.\nيمكن تعريف التسميات والماكروات %define الخاصة بالسياق العلوي عن طريق\nوضع %$ قبل أسمائها، والأشياء الخاصة بالسياق التالي لأسفل بـ %$$، وهكذا.

\n

يتم إجراء التجميع الشرطي عن طريق %ifdef و %ifndef و\n%else و %endif كما في C. (باستثناء أن %ifdef\nيمكن أن تقبل العديد من أسماء الماكروات المفترضة، وستقوم بتقييم TRUE إذا تم\nتعريف أي منها.) بالإضافة إلى ذلك، يمكن استخدام التوجيهات %ifctx و\n%ifnctx للتحكم في اسم السياق العلوي في مكدس السياق. يتم أيضًا\nدعم مجموعة واضحة من توجيهات \"else-if\"، وهي %elifdef و %elifndef\nو %elifctx و %elifnctx.
