namespace__autoclean(3pm)

الحزمة: perl-namespace-autoclean

التراخيص: PerlArtistic, GPL

namespace::autoclean(3) وثائق Perl المساهم بها من قبل المستخدم namespace::autoclean(3)

الاسم

namespace::autoclean - الحفاظ على الاستيرادات خارج مساحتك الاسمية

الإصدار

الإصدار 0.31

الملخص

package Foo;
use namespace::autoclean;
use Some::Package qw/imported_function/;
sub bar { imported_function('stuff') }
# لاحقًا:
Foo->bar;               # يعمل
Foo->imported_function; # سيفشل. تم تنظيف imported_function بعد التجميع

الوصف

عندما تستورد دالة إلى حزمة Perl، فإنها ستكون متاحة بشكل طبيعي كطريقة.

السمة "namespace::autoclean" ستقوم بإزالة جميع الرموز المستوردة في نهاية دورة تجميع الحزمة الحالية. الدوال التي تم استدعاؤها في الحزمة نفسها ستظل مرتبطة باسمها، لكنها لن تظهر كطرق في فئتك أو مثيلاتك.

هذه الوحدة مشابهة جدًا لـ namespace::clean، باستثناء أنها ستنظف جميع الدوال المستوردة، بغض النظر عما إذا كنت قد استوردتها قبل أو بعد استخدام "use" للسمة. كما أنها لن تمس أي شيء يشبه طريقة.

إذا كنت تكتب مُصدِّرًا وترغب في تنظيف ما بعدك (ولأقرانك)، يمكنك استخدام المفتاح "-cleanee" لتحديد الحزمة التي سيتم تنظيفها:

package My::MooseX::namespace::autoclean;
use strict;
use namespace::autoclean (); # لا تنظيف، فقط تحميل
sub import {
    namespace::autoclean->import(
      -cleanee => scalar(caller),
    );
}

ماذا يتم تنظيفه وما لا يتم تنظيفه

"namespace::autoclean" ستترك أي شيء تعتبره طريقة. بالنسبة لفئات Moose، يعتمد هذا على الطريقة "get_method_list" من Class::MOP::Class. بالنسبة لفئات غير Moose، سيتم التعرف على أي شيء محدد داخل الحزمة كطريقة. يجب أن يتطابق هذا مع تعريف Moose للطريقة. بالإضافة إلى ذلك، لن يتم تنظيف الدوال السحرية المثبتة بواسطة overload.

المعلمات

-also => [ ITEM | REGEX | SUB, .. ]

-also => ITEM

-also => REGEX

-also => SUB

في بعض الأحيان قد لا ترغب في تنظيف الاستيرادات فقط، بل أيضًا الدوال المساعدة التي تستخدمها في طرقك. يمكن استخدام المفتاح "-also" للإعلان عن قائمة بالدوال التي يجب إزالتها بالإضافة إلى أي استيرادات:

use namespace::autoclean -also => ['some_function', 'another_function'];

إذا كانت هناك دالة واحدة فقط تحتاج إلى تنظيف إضافي، فإن المفتاح "-also" يقبل أيضًا سلسلة نصية عادية:

use namespace::autoclean -also => 'some_function';

في بعض الحالات، قد ترغب في حل تنظيف أكثر قوة.

يمكن للمفتاح "-also" أن يأخذ تعبيرًا عاديًا (Regex) أو مرجع رمز (CodeRef) لمطابقة أسماء الدوال المحلية التي سيتم تنظيفها.

use namespace::autoclean -also => qr/^_/
use namespace::autoclean -also => sub { $_ =~ m{^_} };
use namespace::autoclean -also => [qr/^_/ , qr/^hidden_/ ];
use namespace::autoclean -also => [sub { $_ =~ m/^_/ or $_ =~ m/^hidden/ }, sub { uc($_) == $_ } ];

-except => [ ITEM | REGEX | SUB, .. ]

-except => ITEM

-except => REGEX

-except => SUB

هذا يأخذ نفس الخيارات تمامًا مثل "-also" باستثناء أن أي شيء يتطابق معه لن يتم تنظيفه.

محاذير

عند الاستخدام مع فئات Moo، فإن الاستدلال المستخدم للتحقق من الطرق لن يعمل بشكل صحيح مع الطرق من الأدوار المستهلكة في وقت التجميع.

package My::Class;
use Moo;
use namespace::autoclean;
# سيئ، سيتم تنظيف أي طرق مستهلكة
BEGIN { with 'Some::Role' }
# جيد، سيتم الاحتفاظ بطرق الدور
with 'Some::Role';

بالإضافة إلى ذلك، قد لا يعمل اكتشاف الطرق بشكل صحيح في فئات Mouse في إصدارات Perl الأقدم من 5.10.

autoclean(3pm)

Autoclean is a module that provides an automatic cleanup mechanism for files and directories. It can be used to define rules for deleting temporary files, log files, or any other files that need to be periodically cleaned up.

SYNOPSIS

use autoclean;

# Define a rule to clean up files in a temporary directory
autoclean::add_rule(
    path    => '/tmp/my_app',
    pattern => qr/\.log$/,  # Clean up files ending with .log
    mtime   => 86400,        # Files older than 1 day
);

# Define a rule to clean up an empty directory
autoclean::add_rule(
    path    => '/var/cache/my_app',
    type    => 'dir',
    empty   => 1,
);

# Run the cleanup process
autoclean::run_cleanup();

DESCRIPTION

The autoclean module allows you to specify rules for cleaning up files and directories. Each rule consists of a path, an optional pattern, and optional time-based or type-based criteria.

The add_rule function takes a hash of options to define a cleanup rule:

  • path: The path to the file or directory to be cleaned up. This is a required argument.
  • pattern: A regular expression (Regexp object) that specifies which files to clean up within a directory. If not specified, all files in the directory will be considered.
  • mtime: A time in seconds. Files older than this duration (modification time) will be cleaned up.
  • type: The type of entry to clean. Can be 'file' or 'dir'. Defaults to 'file'.
  • empty: If set to 1, the rule will only apply to empty directories. This option is ignored if type is set to 'file'.

The run_cleanup function executes all defined rules and performs the cleanup. It iterates through the specified paths, checks the files or directories against the defined patterns and criteria, and deletes them if they match.

EXAMPLES

Cleaning up old log files in a web server's log directory: 

use autoclean;

autoclean::add_rule(
    path    => '/var/log/apache2',
    pattern => qr/access\.log\.\d{8}\.gz$/,
    mtime   => 604800, # 7 days
);

autoclean::run_cleanup();

Removing temporary cache files older than 24 hours: 

use autoclean;

autoclean::add_rule(
    path    => '/home/user/.cache/myapp',
    mtime   => 86400, # 24 hours
);

autoclean::run_cleanup();
