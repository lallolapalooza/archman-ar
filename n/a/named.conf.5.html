NAME

named.conf ‐ BIND 9 configuration file

SYNOPSIS

        option { ... };
        acl name { ... };
        logging channel ... { ... };
        logging category ... { ... };
        view name { ... };
        zone ... { ... };

DESCRIPTION

The named.conf file contains configuration information for the BIND 9 name server (named(8)). This information is used to determine how the name server should operate, which zones it is authoritative for, and how to handle DNS queries.

The configuration file is a text file that consists of a series of configuration statements. The syntax is C-like, with statements delimited by semicolons (;) and blocks of related statements enclosed in curly braces ({ ... }).

OPTIONS

        option {
                directory "path";
                pid-file "path";
                recursion yes | no;
                allow-query {  |  | none; ... };
                allow-recursion {  |  | none; ... };
                ...
        };
directory
Sets the working directory for the name server. This is often used to specify the location of zone files.
pid-file
Specifies the path to the process ID (PID) file for the name server.
recursion
Enables or disables recursive querying. If enabled, the server will attempt to resolve names not within its authoritative zones by querying other name servers.
allow-query
Specifies a list of clients (IP addresses or ACLs) that are allowed to send queries to the server.
allow-recursion
Specifies a list of clients that are allowed to make recursive queries.

ACCESS CONTROL LISTS (ACLs)

        acl name {
                <ip-address> | <network/prefix>;
                ...
        };

ACLs define groups of IP addresses that can be referenced in other configuration statements (e.g., allow-query, allow-recursion).

LOGGING

        logging channel name {
                file "path" [ versions numeric | size numeric k|m|g ];
                severity info | debug | notice | warning | error | critical;
                print-time yes | no;
                print-severity yes | no;
                print-category yes | no;
        };

        logging category name {
                channel name;
                ...
        };

The logging configuration allows fine-grained control over where and how BIND 9 logs messages. You can define logging channels (specifying file path, rotation, severity level) and then assign these channels to specific logging categories.

VIEWS

        view name [ class ] {
                match-clients {  | ; ... };
                match-destinations { ; ... };
                zone ... { ... };
                ...
        };

Views allow the server to provide different answers to DNS queries based on the source IP address of the client or the destination IP address of the query. This is useful for implementing split-horizon DNS.

match-clients
Specifies the clients for which this view is applicable.
match-destinations
Specifies the destination IP addresses for which this view is applicable.

ZONES

        zone "domain.name" [ class ] {
                type master | slave | forward | hint | delegation-only;
                file "filename";
                allow-transfer {  |  | * ) ] { (  |  [ port  ] |  [ port  ] ) [ key  ] [ tls  ]; ... };
                transfer-source (  | * );
                transfer-source-v6 (  | * );
                zone-statistics ( full | terse | none | <boolean> );
        };

Zone statements define the zones for which the name server is authoritative or handles queries. They specify the zone's name, type, the file containing the zone data, and access controls for zone transfers.

type
Specifies the type of zone:
  • master: The primary copy of the zone.
  • slave: A secondary copy of the zone, updated from a master.
  • forward: A zone whose queries are forwarded to other servers.
  • hint: Root hints for recursive servers.
  • delegation-only: A zone for which the server only provides NS records.
file
Specifies the filename containing the zone data.
allow-transfer
Controls which servers are allowed to request a zone transfer (AXFR/IXFR).
transfer-source
Specifies the source IP address for outgoing zone transfer requests.
transfer-source-v6
Specifies the source IPv6 address for outgoing zone transfer requests.
zone-statistics
Controls the level of statistics reported for the zone.
        zone <string> [ <class> ] {
                in-view <string>;
        };

This is a shorthand for defining a zone within a specific view.
