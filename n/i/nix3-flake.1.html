sourcehut: مشابه لـ github، وهي طريقة أكثر كفاءة لجلب مستودعات SourceHut. السمات التالية مطلوبة:
  • owner: مالك المستودع (بما في ذلك ~ البادئة).
  • repo: اسم المستودع.
مثل github، يتم تنزيل هذه كأرشيفات tarball.
بنية عنوان URL لـ sourcehut flakes هي:
sourcehut:<owner>/<repo>(/<rev-or-ref>)?(\?<params>)?
<rev-or-ref> يعمل بنفس طريقة github. يمكن تحديد اسم فرع أو علامة (tag) (ref)، أو تجزئة (hash) تنفيذ (commit) (rev).
بما أن SourceHut يسمح بالاستضافة الذاتية، يمكنك تحديد host كمعلمة (parameter)، للإشارة إلى أي مثيلات (instances) غير git.sr.ht.
حالياً، يعمل تحديد اسم ref فقط لمستودعات Git. يمكنك الإشارة إلى مستودعات Mercurial بمجرد تغيير host إلى hg.sr.ht (أو أي مثيل Mercurial آخر). مع التحذير أنه يجب عليك تحديد تجزئة تنفيذ (commit hash) (rev) بشكل صريح.
بعض الأمثلة:
  • sourcehut:~misterio/nix-colors
  • sourcehut:~misterio/nix-colors/main
  • sourcehut:~misterio/nix-colors?host=git.example.org
  • sourcehut:~misterio/nix-colors/182b4b8709b8ffe4e9774a4c5d6877bf6bb9a21c
  • sourcehut:~misterio/nix-colors/21c1a380a6915d890d408e9f22203436a35bb2de?host=hg.sr.ht

صيغة الـ Flake

كمثال، إليك flake.nix بسيط يعتمد على flake Nixpkgs ويوفر حزمة واحدة (أي، اشتقاق قابل للتثبيت):

{
  description = "A flake for building Hello World";
  inputs.nixpkgs.url = "github:NixOS/nixpkgs/nixos-20.03";
  outputs = { self, nixpkgs }: {
    packages.x86_64-linux.default =
      # Notice the reference to nixpkgs here.
      with import nixpkgs { system = "x86_64-linux"; };
      stdenv.mkDerivation {
        name = "hello";
        src = self;
        buildPhase = "gcc -o hello ./hello.c";
        installPhase = "mkdir -p $out/bin; install -t $out/bin hello";
      };
  };
}

السمات التالية مدعومة في flake.nix:

  • description: وصف موجز من سطر واحد للـ flake.
  • inputs: مجموعة سمات (attrset) تحدد تبعيات الـ flake (موضحة أدناه).
  • outputs: دالة، عند إعطائها مجموعة سمات تحتوي على مخرجات كل flake مدخل، مرقمة بمعرّفاتها، تنتج قيم Nix التي توفرها هذه الـ flake. وبالتالي، في المثال أعلاه، يحتوي inputs.nixpkgs على نتيجة استدعاء دالة outputs الخاصة بـ flake nixpkgs.
بالإضافة إلى مخرجات كل مدخل، يحتوي كل مدخل في inputs أيضًا على بعض البيانات الوصفية (metadata) حول المدخلات. وهي:
  • outPath: المسار في مخزن Nix (Nix store) لشجرة مصدر الـ flake. بهذه الطريقة، يمكن تمرير مجموعة السمات إلى import كما لو كانت مسارًا، كما في المثال أعلاه (import nixpkgs).
  • rev: تجزئة (hash) التنفيذ (commit) لمستودع الـ flake، إذا كان ذلك منطبقًا.
  • revCount: عدد الأسلاف للتنفيذ (revision) rev. هذا غير متاح لمستودعات github، حيث يتم جلبها كملفات tarball بدلاً من مستودعات Git.
  • lastModifiedDate: وقت تنفيذ (commit time) التنفيذ (revision) rev، بالتنسيق %Y%m%d%H%M%S (على سبيل المثال 20181231100934). على عكس revCount، هذا متاح لكل من مستودعات Git و GitHub، لذلك هو مفيد لإنشاء سلاسل إصدارات (version strings) متزايدة (نأمل) بشكل رتيب.
  • lastModified: وقت تنفيذ (commit time) التنفيذ (revision) rev كرقم صحيح يمثل عدد الثواني منذ عام 1970.
  • narHash: SHA-256 (بتنسيق SRI) لـ تمثيل أرشيف Nix (NAR) لشجرة مصدر الـ flake.
يجب أن تكون القيمة التي ترجعها دالة outputs مجموعة سمات (attribute set). يمكن أن تحتوي السمات على قيم اعتباطية؛ ومع ذلك، تتطلب أوامر nix الفرعية المختلفة سمات محددة لتكون ذات قيمة محددة (على سبيل المثال، يجب أن تكون packages.x86_64-linux مجموعة سمات للاشتتقاقات المبنية لمنصة x86_64-linux).
•
nixConfig: مجموعة من خيارات nix.conf التي سيتم تعيينها عند تقييم أي جزء من الـ flake. حرصًا على الأمان، يُسمح فقط بمجموعة صغيرة من الخيارات التي يمكن تعيينها دون تأكيد طالما أن accept-flake-config غير ممكّن في التكوين العام:
  • bash-prompt
  • bash-prompt-prefix
  • bash-prompt-suffix
  • flake-registry
  • commit-lock-file-summary

مدخلات الـ Flake

السمة inputs تحدد تبعيات الـ flake، كمجموعة سمات (attrset) تربط أسماء المدخلات بمراجع الـ flakes. على سبيل المثال، يحدد ما يلي تبعية على مستودعات nixpkgs و import-cargo:

# A GitHub repository.
inputs.import-cargo = {
  type = "github";
  owner = "edolstra";
  repo = "import-cargo";
};
# An indirection through the flake registry.
inputs.nixpkgs = {
  type = "indirect";
  id = "nixpkgs";
};

بدلاً من ذلك، يمكنك استخدام الصيغة الشبيهة بعنوان URL:

inputs.import-cargo.url = "github:edolstra/import-cargo";
inputs.nixpkgs.url = "nixpkgs";

يتم جلب كل مدخل وتقييمه وتمريره إلى دالة outputs كمجموعة سمات بنفس اسم المدخل المقابل. المدخل الخاص المسمى self يشير إلى مخرجات وشجرة مصدر الـ flake *الحالية*. وبالتالي، تبدو دالة outputs النموذجية كالتالي:

outputs = { self, nixpkgs, import-cargo }: {
  ... outputs ...
};

من الممكن أيضًا حذف مدخل بالكامل وإدراجه *فقط* كوسيطة دالة متوقعة لـ outputs. وبالتالي،

outputs = { self, nixpkgs }: ...;

بدون سمة inputs.nixpkgs، يعادل

inputs.nixpkgs = {
  type = "indirect";
  id = "nixpkgs";
};

يمكن أيضًا استخدام المستودعات التي لا تحتوي على flake.nix كمدخلات، عن طريق تعيين السمة flake للمدخل إلى false:

inputs.grcov = {
  type = "github";
  owner = "mozilla";
  repo = "grcov";
  flake = false;
};
outputs = { self, nixpkgs, grcov }: {
  packages.x86_64-linux.grcov = stdenv.mkDerivation {
    src = grcov;
    ...
  };
};

يمكن تجاوز المدخلات المتعدية (transitive inputs) من ملف flake.nix. على سبيل المثال، يقوم ما يلي بتجاوز مدخل nixpkgs الخاص بمدخل nixops:

inputs.nixops.inputs.nixpkgs = {
  type = "github";
  owner = "my-org";
  repo = "nixpkgs";
};

من الممكن أيضًا "وراثة" مدخل من مدخل آخر. هذا مفيد لتقليل تبعيات الـ flake. على سبيل المثال، يقوم ما يلي بتعيين مدخل nixpkgs الخاص بالـ flake العلوي ليكون مساويًا لمدخل nixpkgs الخاص بمدخل dwarffs الخاص بالـ flake العلوي:

inputs.nixpkgs.follows = "dwarffs/nixpkgs";
