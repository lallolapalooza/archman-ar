الاسم

nix.conf - ملف تكوين Nix

الوصف

يدعم Nix مجموعة متنوعة من إعدادات التكوين، والتي يتم قراءتها من ملفات التكوين أو أخذها كعلامات سطر أوامر.

ملف التكوين

بشكل افتراضي، يقرأ Nix الإعدادات من الأماكن التالية، بهذا الترتيب:

1.
ملف التكوين على مستوى النظام sysconfdir/nix/nix.conf (أي /etc/nix/nix.conf في معظم الأنظمة)، أو $NIX_CONF_DIR/nix.conf إذا تم تعيين NIX_CONF_DIR.
القيم التي تم تحميلها في هذا الملف لا يتم تمريرها إلى ديمون Nix. يفترض العميل أن الديمون قد قام بتحميلها بالفعل.
2.
إذا تم تعيين NIX_USER_CONF_FILES، فسيتم تحميل كل مسار مفصول بـ : بترتيب عكسي.
بخلاف ذلك، سيبحث عن ملفات nix/nix.conf في XDG_CONFIG_DIRS و XDG_CONFIG_HOME. إذا لم يتم تعيينها، فإن XDG_CONFIG_DIRS يكون افتراضياً /etc/xdg، و XDG_CONFIG_HOME يكون افتراضياً $HOME/.config وفقًا لـ مواصفات دليل الأساس XDG.
3.
إذا تم تعيين NIX_CONFIG، فسيتم التعامل مع محتوياته كمحتويات ملف تكوين.

تنسيق الملف

تتكون ملفات التكوين من أزواج الاسم = القيمة، واحد في كل سطر. تبدأ التعليقات بالحرف #.

مثال:

keep-outputs = true       # لطيف للمطورين
keep-derivations = true   # كذلك

يمكن تضمين ملفات أخرى بسطر مثل include <path>، حيث يتم تفسير <path> بالنسبة لملف التكوين الحالي. عدم وجود ملف يعتبر خطأ ما لم يتم استخدام !include بدلاً من ذلك.

عادةً ما يتجاوز إعداد التكوين أي قيمة سابقة. ومع ذلك، بالنسبة للإعدادات التي تأخذ قائمة من العناصر، يمكنك إضافة البادئة extra- إلى اسم الإعداد لـ *إلحاق* بالقيمة السابقة.

على سبيل المثال،

substituters = a b
extra-substituters = c d

يحدد إعداد substituters ليكون a b c d.

أسماء الخيارات غير المعروفة ليست خطأ، ويتم تجاهلها ببساطة مع تحذير.

علامات سطر الأوامر

يمكن تعيين خيارات التكوين في سطر الأوامر، متجاوزةً القيم المعينة في ملف التكوين:

•
كل إعداد تكوين له علامة سطر أوامر مقابلة (مثل --max-jobs 16). لا تحتاج الإعدادات المنطقية إلى وسيط، ويمكن تعطيلها صراحةً باستخدام البادئة no- (مثل --keep-failed و --no-keep-failed).
أسماء الخيارات غير المعروفة هي علامات غير صالحة (ما لم تكن هناك بالفعل علامة بهذا الاسم)، ويتم رفضها بخطأ.
•
العلامة --option <name> <value> يتم تفسيرها تمامًا مثل <name> = <value> في ملف إعدادات.
يتم تجاهل أسماء الخيارات غير المعروفة مع تحذير.

يتم دعم البادئة extra- للإعدادات التي تأخذ قائمة من العناصر (مثل --extra-trusted users alice أو --option extra-trusted-users alice).

الإعدادات الصحيحة

تدعم الإعدادات التي لها نوع صحيح البادئات K و M و G و T. هذه تسبب ضرب القيمة المحددة بـ 2^10 و 2^20 و 2^30 و 2^40 على التوالي. على سبيل المثال، --min-free 1M يعادل --min-free 1048576.

build-users-group
\n
\n
\n
\n
يحدد هذا الخيار مجموعة Unix التي تضم حسابات مستخدمي بناء Nix.\n في تثبيتات Nix متعددة المستخدمين، لا ينبغي إجراء عمليات البناء\n بواسطة حساب Nix حيث سيسمح ذلك للمستخدمين بتعديل مخزن Nix وقاعدة البيانات بشكل تعسفي\n عن طريق توفير أدوات بناء مصممة خصيصًا؛ ولا يمكن إجراؤها بواسطة المستخدم المتصل حيث سيسمح له بالتأثير على نتيجة البناء.\n
\n
\n
لذلك، إذا كان هذا الخيار غير فارغ ويحدد مجموعة صالحة، سيتم إجراء عمليات البناء\n تحت حسابات المستخدمين الذين هم أعضاء في المجموعة المحددة هنا (كما هو مدرج في /etc/group).\n لا ينبغي استخدام تلك الحسابات لأي غرض آخر!\n
\n
\n
لن يقوم Nix بتشغيل عمليتي بناء تحت نفس حساب المستخدم في نفس الوقت.\n هذا لمنع ثغرة أمنية واضحة: مستخدم خبيث يكتب تعبير Nix الذي يعدل نتيجة بناء تعبير Nix مشروع يتم بناؤه بواسطة مستخدم آخر.\n لذلك من الجيد أن يكون لديك أكبر عدد ممكن من حسابات مستخدمي بناء Nix التي يمكنك تخصيصها. (تذكر: معرفات المستخدمين غير مكلفة).\n
\n
\n
يجب أن يكون لدى مستخدمي البناء إذن لإنشاء ملفات في مخزن Nix، ولكن ليس حذفها.\n لذلك، يجب أن يكون /nix/store مملوكًا لحساب Nix، ويجب أن تكون مجموعته هي المجموعة المحددة هنا، ويجب أن يكون وضعه 1775.\n
\n
\n
إذا كانت مجموعة مستخدمي البناء فارغة، سيتم إجراء عمليات البناء تحت معرف المستخدم الخاص بعملية Nix (أي، معرف المتصل إذا كانت NIX_REMOTE فارغة، أو المعرف الذي يعمل تحته خادم Nix إذا كانت NIX_REMOTE هي daemon).\n من الواضح أنه لا ينبغي استخدام هذا مع خادم Nix يمكن الوصول إليه من قبل عملاء غير موثوق بهم.\n
\n
\n
الافتراضي هو nixbld عند التشغيل كـ root،\n فارغ بخلاف ذلك.\n

    NAME

    nix.conf — Nix configuration file

    DESCRIPTION

    The Nix configuration file is used to configure the behaviour of the Nix package manager. It is a shell script that is evaluated by Nix. Any shell commands can be used, as well as Nix's configuration primitives.

    The configuration file is looked for in the following locations, in order:

    1. The file specified by the NIX_CONF_FILE environment variable.

    2. /etc/nix/nix.conf

    3. ~/.config/nix/nix.conf

    If none of these files exist, the default configuration is used.

    AVAILABLE SETTINGS

    nix.conf

    The Nix configuration file is used to configure the behaviour of the Nix package manager. It is a shell script that is evaluated by Nix. Any shell commands can be used, as well as Nix's configuration primitives.

    The configuration file is looked for in the following locations, in order:

    1. The file specified by the NIX_CONF_FILE environment variable.

    2. /etc/nix/nix.conf

    3. ~/.config/nix/nix.conf

    If none of these files exist, the default configuration is used.

    nix.binaryCaches

    A list of binary caches (or "substituters") to use. Binary caches are URLs pointing to HTTP(S) servers that contain pre-built Nix derivations. Nix will attempt to download derivations from these caches before building them locally.

    Example:

    nix.binaryCaches = [ "https://cache.nixos.org/" ];
    nix.trustedUsers

    A list of users who are allowed to perform operations that require root privileges, such as adding new binary caches or building derivations that require root privileges. By default, only the root user is trusted.

    Example:

    nix.trustedUsers = [ "root" "alice" ];
    nix.trustedPublicKeys

    A list of public keys of trusted binary caches. Nix will only download packages from binary caches whose public keys are listed here. This is used to ensure that you are downloading packages from trusted sources.

    Example:

    nix.trustedPublicKeys = [ "cache.nixos.org-1:6NCHdD59X431o0gWyp2ABULGj+dvWw5+Gns+7xIfApg=" ];
    nix.plugin.check-owner.nix-build

    Specifies that the nix-build command should check if the user running it is the owner of the derivation being built. This is a security measure to prevent users from building derivations that they don't own.

    nix.max-silent-GC-interval

    The maximum time interval (in seconds) between garbage collections. Nix will automatically run the garbage collector if it hasn't been run for this amount of time.

    Default: 0 (always run GC)

    nix.netrc-file

    Path to a netrc file to be used for accessing authenticated HTTP(S) resources.

    nix.log-lines-on-error

    The number of log lines to display on error. By default, Nix will display all log lines.

    Default: -1 (display all lines)

    nix.narinfo-cache-negative-ttl

    Time-to-live (in seconds) for negative caching of narinfo entries. This is used to speed up subsequent requests for narinfo entries that are known to not exist.

    Default: 60

    nix.narinfo-cache-positive-ttl

    Time-to-live (in seconds) for positive caching of narinfo entries. This is used to speed up subsequent requests for narinfo entries that are known to exist.

    Default: 600

    nix.experimental-features

    A space-separated list of experimental features to enable. These features are not yet stable and may change or be removed in future versions of Nix.

    Example:

    nix.experimental-features = [ "nix-command" "flakes" ];
    nix.build-users-group

    The name of the group that Nix will use for building derivations. This is used to ensure that derivations are built in a clean environment and that they don't have access to the user's files.

    Default: nixbld

    nix.cache-db.path

    Path to the Nix cache database.

    nix.store-path
