nix3-env-shell(1)

الحزمة: nix

التراخيص: LGPL-2.1-only

nix3-env-shell(1) دليل الأوامر العامة nix3-env-shell(1)

تحذير
هذا البرنامج تجريبي وواجهته عرضة للتغيير.

الاسم

nix env shell - تشغيل shell حيث تتوفر الحزم المحددة

الملخص

nix env shell [خيار…] installables…

أمثلة

•
بدء shell يوفر youtube-dl من الشفرة السحرية nixpkgs:
# nix shell nixpkgs#youtube-dl
# youtube-dl --version
2020.11.01.1
•
بدء shell يوفر GNU Hello من NixOS 20.03:
# nix shell nixpkgs/nixos-20.03#hello
•
تشغيل GNU Hello:
# nix shell nixpkgs#hello --command hello --greeting 'Hi everybody!'
Hi everybody!
•
تشغيل أوامر متعددة في بيئة shell:
# nix shell nixpkgs#gnumake --command sh -c "cd src && make"
•
تشغيل GNU Hello في متجر chroot:
# nix shell --store ~/my-nix nixpkgs#hello --command hello
•
بدء shell يوفر GNU Hello في متجر chroot:
# nix shell --store ~/my-nix nixpkgs#hello nixpkgs#bashInteractive --command bash
لاحظ أنه من الضروري تحديد bash بشكل صريح لأن shell الافتراضي الخاص بك (على سبيل المثال /bin/bash) لن يكون موجودًا بشكل عام في chroot.

الوصف

nix shell يقوم بتشغيل أمر في بيئة يكون فيها المتغير $PATH يوفر installables المحددة. إذا لم يتم تحديد أمر، فإنه يبدأ shell الافتراضي لمستخدمك المحدد بواسطة $SHELL.

الاستخدام كـ #!-مفسر

يمكنك استخدام nix كمفسر للبرامج النصية للسماح للبرامج النصية المكتوبة بلغات اعتباطية بالحصول على تبعياتها الخاصة عبر Nix. يتم ذلك عن طريق بدء البرنامج النصي بالأسطر التالية:

#! /usr/bin/env nix
#! nix shell installables --command real-interpreter

حيث real-interpreter هو المفسر النصي "الحقيقي" الذي سيتم استدعاؤه بواسطة nix shell بعد حصوله على التبعيات وتهيئة البيئة، و installables هي أسماء السمات للتبعيات في Nixpkgs.

الأسطر التي تبدأ بـ #! nix تحدد خيارات (انظر أعلاه). لاحظ أنه لا يمكنك كتابة #! /usr/bin/env nix shell -i ... لأن العديد من أنظمة التشغيل تسمح فقط بوسيط واحد في أسطر #!.

على سبيل المثال، إليك برنامج نصي Python يعتمد على Python وحزمة prettytable:

#! /usr/bin/env nix
#! nix shell github:tomberek/-#python3With.prettytable --command python
import prettytable
# Print a simple table.
t = prettytable.PrettyTable(["N", "N^2"])
for n in range(1, 10): t.add_row([n, n * n])
print t

بالمثل، يلي هذا برنامج نصي Perl يحدد أنه يتطلب Perl وحزم HTML::TokeParser::Simple و LWP:

#! /usr/bin/env nix
#! nix shell github:tomberek/-#perlWith.HTMLTokeParserSimple.LWP --command perl -x
use HTML::TokeParser::Simple;
# Fetch nixos.org and print all hrefs.
my $p = HTML::TokeParser::Simple->new(url => 'http://nixos.org/');
while (my $token = $p->get_tag("a")) {
    my $href = $token->get_attr("href");
    print "$href\n" if $href;
}

في بعض الأحيان تحتاج إلى تمرير تعبير Nix بسيط لتخصيص حزمة مثل Terraform:

#! /usr/bin/env nix
#! nix shell --impure --expr ``
#! nix with (import (builtins.getFlake ''nixpkgs'') {});
#! nix terraform.withPlugins (plugins: [ plugins.openstack ])
#! nix ``
#! nix --command bash
terraform "$@"

ملاحظة

يجب عليك استخدام علامتي الاقتباس الخلفيتين (``) عند تمرير تعبير Nix بسيط في سطر shebang الخاص بـ nix shell.

أخيرًا، باستخدام دمج سطور shebang المتعددة لـ nix shell، يستخدم برنامج Haskell النصي التالي فرعًا محددًا من Nixpkgs/NixOS (فرع 21.11 المستقر):

#!/usr/bin/env nix
#!nix shell --override-input nixpkgs github:NixOS/nixpkgs/nixos-21.11
#!nix github:tomberek/-#haskellWith.download-curl.tagsoup --command runghc
import Network.Curl.Download
import Text.HTML.TagSoup
import Data.Either
import Data.ByteString.Char8 (unpack)
-- Fetch nixos.org and print all hrefs.
main = do
  resp <- openURI "https://nixos.org/"
  let tags = filter (isTagOpenName "a") $ parseTags $ unpack $ fromRight undefined resp
  let tags' = map (fromAttrib "href") tags
  mapM_ putStrLn $ filter (/= "") tags'

إذا كنت تريد أن تكون أكثر دقة، يمكنك تحديد مراجعة محددة لـ Nixpkgs:

#!nix shell --override-input nixpkgs github:NixOS/nixpkgs/eabc38219184cc3e04a974fe31857d8e0eac098d

يمكنك أيضًا استخدام تعبير Nix لبناء تبعياتك الخاصة. على سبيل المثال، كان يمكن كتابة مثال Python على النحو التالي:

#! /usr/bin/env nix
#! nix shell --impure --file deps.nix -i python

حيث يحتوي الملف deps.nix في نفس الدليل الذي يوجد به برنامج #! النصي على:

with import <nixpkgs> {};
python3.withPackages (ps: with ps; [ prettytable ])

خيارات

•
--command / -c command args
الأمر والوسائط المراد تنفيذها، الافتراضي هو $SHELL
•
--ignore-environment / -i
مسح البيئة بأكملها (باستثناء تلك المحددة بـ --keep).
•
--keep / -k name
الاحتفاظ بمتغير البيئة name.
•
--stdin
قراءة installables من الإدخال القياسي. لا يتم تطبيق installable افتراضي.
•
--unset / -u name
إلغاء تعيين متغير البيئة name.

خيارات التقييم الشائعة

•
--arg name expr
تمرير القيمة expr كوسيط name لوظائف Nix.
•
--arg-from-file name path
تمرير محتويات الملف path كوسيط name لوظائف Nix.
•
--arg-from-stdin name
تمرير محتويات stdin كوسيط name لوظائف Nix.
•
--argstr name string
تمرير السلسلة string كوسيط name لوظائف Nix.
...

Name

nix - Command-line interface for Nix

Synopsis

nix [options] subcommand [options] subcommand-arguments

nix [options] {--help | -h | --version}

Description

The Nix command-line tool provides a unified interface to the Nix package manager. It is intended to become the primary interface for Nix users, replacing older commands like nix-build, nix-shell, and nix-env.

The command-line interface is structured around subcommands, each serving a specific purpose. For example, nix build builds derivations, nix shell` launches shells, and nix search` searches for packages.

Most Nix commands operate on so-called *installables*. An installable is a reference to a derivation, package, or flake output. The syntax for installables is:

--installable installable

An installable can be one of the following:

  • A flake reference, such as nixpkgs/nixos or github:NixOS/nixpkgs/nixos-unstable.
  • A path to a Nix expression (e.g. ./default.nix) followed by an attribute path (e.g. :some.package.nested).
  • A path to a flake (e.g. ./my-flake) followed by an attribute path (e.g. #packages.x86_64-linux.my-package).

Options that are not specific to any subcommand are called global options. These are documented below.

Examples

  • Build the default package of the current flake:

    nix build

  • Build the hello package from nixpkgs:

    nix build --impure --expr 'builtins.import {}).hello'

    nix build --impure --expr 'import (fetchTarball "https://github.com/NixOS/nixpkgs/archive/nixos-21.05.tar.gz") {}'.hello

  • Search for the jq package in nixpkgs:

    nix search --impure --expr 'builtins.import {}' jq

  • Launch a development shell for the current flake:

    nix shell

  • Install the ripgrep package:

    nix build --impure --expr 'builtins.import {}'ripgrep

    nix build --installable 'nixpkgs#ripgrep'

Options

The following options are available for most Nix commands.

General options

•
--accept-flake-config
Allow flake configuration to contain arbitrary settings.
•
--allow-hot-reloading
Enable hot reloading for Nix daemon.
•
--allow-new-privileges
Allow running commands with new privileges. This option should generally be avoided, as it can lead to privilege escalation.
•
--allow-unfree
Allow fetching of, and building with, unfree packages.
•
--apply-check
If the configuration contains a nixos.apply-check option, then use it when building the system configuration. This will only install the system if the configuration is valid.
•
--arg name value
Pass the JSON string value to the Nix expression as the Nix variable name.
•
--argstr name value
Pass the string value to the Nix expression as the Nix variable name.
•
--bash-debug
If a Nix expression evaluation fails, drop into BASH. Useful for debugging.
•
--builders host-uri ...
Use the specified Nix build daemons. Overrides the builders configuration setting.
•
--commit
Commit the updated flake.lock file to Git.
•
--debugger
Start an interactive environment if evaluation fails.
•
--eval-store store-url
The URL of the Nix store to use for evaluation, i.e. to store derivations (.drv files) and inputs referenced by them.
•
--impure
Allow access to mutable paths and repositories.
•
--include / -I path
Add path to search path entries used to resolve lookup paths
This option may be given multiple times.
Paths added through -I take precedence over the nix-path configuration setting and the NIX_PATH environment variable.
•
--override-flake original-ref resolved-ref
Override the flake registries, redirecting original-ref to resolved-ref.

Common flake-related options

•
--commit-lock-file
Commit changes to the flake’s lock file.
•
--inputs-from flake-url
Use the inputs of the specified flake as registry entries.
•
--no-registries
Don’t allow lookups in the flake registries.
DEPRECATED
Use --no-use-registries instead.
•
--no-update-lock-file
Do not allow any updates to the flake’s lock file.
•
--no-write-lock-file
Do not write the flake’s newly generated lock file.
•
--output-lock-file flake-lock-path
Write the given lock file instead of flake.lock within the top-level flake.
•
--override-input input-path flake-url
Override a specific flake input (e.g. dwarffs/nixpkgs). This implies --no-write-lock-file.
•
--recreate-lock-file
Recreate the flake’s lock file from scratch.
DEPRECATED
Use nix flake update instead.
•
--reference-lock-file flake-lock-path
Read the given lock file instead of flake.lock within the top-level flake.
•
--update-input input-path
Update a specific flake input (ignoring its previous entry in the lock file).
DEPRECATED
Use nix flake update instead.

Logging-related options

•
--debug
Set the logging verbosity level to ‘debug’.
•
--log-format format
Set the format of log output; one of raw, internal-json, bar or bar-with-logs.
•
--print-build-logs / -L
Print full build logs on standard error.
•
--quiet
Decrease the logging verbosity level.
•
--verbose / -v
Increase the logging verbosity level.

Miscellaneous global options

•
--help
Show usage information.
•
--offline
Disable substituters and consider all previously downloaded files up-to-date.
•
--option name value
Set the Nix configuration setting name to value (overriding nix.conf).
•
--refresh
Consider all previously downloaded files out-of-date.
•
--repair
During evaluation, rewrite missing or corrupted files in the Nix store. During building, rebuild missing or corrupted store paths.
•
--version
Show version information.

Options that change the interpretation of installables

•
--expr expr
Interpret installables as attribute paths relative to the Nix expression expr.
•
--file / -f file
Interpret installables as attribute paths relative to the Nix expression stored in file. If file is the character -, then a Nix expression will be read from standard input. Implies --impure.

Note

See man nix.conf for overriding configuration settings with command line flags.
