nix-env-uninstall(1)

الحزمة: nix

التراخيص: LGPL-2.1-only

nix-env --uninstall(1) دليل الأوامر العامة nix-env --uninstall(1)

الاسم

nix-env --uninstall - إزالة الحزم من بيئة المستخدم

الملخص

nix-env {--uninstall | -e} أسماء_المشتقات…

الوصف

عملية إلغاء التثبيت تنشئ بيئة مستخدم جديدة، بناءً على الجيل الحالي من الملف الشخصي النشط، يتم منها إزالة مسارات المتجر المحددة بالأسماء الرمزية أسماء_المشتقات.

خيارات

يُسمح بالخيارات التالية لجميع عمليات nix-env، ولكن قد لا يكون لها تأثير دائمًا.

•
--file / -f مسار
يحدد تعبير Nix (المشار إليه أدناه باسم تعبير Nix النشط) الذي تستخدمه عمليات --install و --upgrade و --query --available للحصول على المشتقات. الافتراضي هو ~/.nix-defexpr.
إذا بدأ الوسيط بـ http:// أو https://، فسيتم تفسيره على أنه عنوان URL لحزمة مضغوطة سيتم تنزيلها وفك ضغطها في موقع مؤقت. يجب أن تتضمن الحزمة المضغوطة دليلاً واحداً في المستوى الأعلى يحتوي على ملف واحد على الأقل يسمى default.nix.
•
--profile / -p مسار
يحدد الملف الشخصي الذي سيتم استخدامه بواسطة العمليات التي تعمل على ملف شخصي (يشار إليه أدناه باسم الملف الشخصي النشط). الملف الشخصي هو تسلسل من بيئات المستخدم تسمى الأجيال، أحدها هو الجيل الحالي.
•
--dry-run
بالنسبة لعمليات --install و --upgrade و --uninstall و --switch-generation و --delete-generations و --rollback، ستؤدي هذه العلامة إلى قيام nix-env بطباعة ما سيتم فعله إذا لم تكن هذه العلامة محددة، دون القيام به فعليًا.
--dry-run تطبع أيضًا المسارات التي سيتم استبدالها (أي، تنزيلها) والمسارات التي سيتم بناؤها من المصدر (لأنه لا يوجد بديل متاح).
•
--system-filter نظام
بشكل افتراضي، تعرض العمليات مثل --query --available المشتقات المطابقة لأي منصة. تسمح لك هذه الخيار باستخدام المشتقات للنظام المحدد.

خيارات شائعة

تقبل معظم أوامر Nix خيارات سطر الأوامر التالية:

•
--help
يطبع ملخصًا لصيغة الأوامر ويخرج.
•
--version
يطبع رقم إصدار Nix على الإخراج القياسي ويخرج.
•
--verbose / -v
يزيد مستوى تفاصيل رسائل التشخيص المطبوعة على الخطأ القياسي. لكل عملية Nix، تكون المعلومات المطبوعة على الإخراج القياسي محددة جيدًا؛ يتم طباعة أي معلومات تشخيصية على الخطأ القياسي، وليس أبدًا على الإخراج القياسي.
يمكن تحديد هذا الخيار بشكل متكرر. حاليًا، مستويات التفاصيل التالية موجودة:
•
0 "الأخطاء فقط"
يطبع فقط الرسائل التي تشرح سبب فشل استدعاء Nix.
•
1 "إعلامي"
يطبع رسائل مفيدة حول ما تفعله Nix. هذا هو الافتراضي.
•
2 "ثرثار"
يطبع المزيد من الرسائل الإعلامية.
•
3 "ثرثرة"
يطبع المزيد من الرسائل الإعلامية.
•
4 "تصحيح الأخطاء"
يطبع معلومات تصحيح الأخطاء.
•
5 "تقيؤ"
يطبع كميات هائلة من معلومات تصحيح الأخطاء.
•
--quiet
يقلل مستوى تفاصيل رسائل التشخيص المطبوعة على الخطأ القياسي. هذا هو الخيار العكسي لـ -v / --verbose.
يمكن تحديد هذا الخيار بشكل متكرر. انظر قائمة مستويات التفاصيل السابقة.
•
--log-format تنسيق
يمكن استخدام هذا الخيار لتغيير تنسيق الإخراج، حيث يكون تنسيق أحد الخيارات التالية:
•
raw
هذا هو التنسيق الخام، كما يخرجه nix-build.
•
internal-json
يخرج السجلات بتنسيق منظم.
تحذير
على الرغم من أن المخطط نفسه مستقر نسبيًا، إلا أن تنسيق رسائل الخطأ (خاصة حقل msg) قد يتغير بين الإصدارات.
•
bar
يعرض شريط تقدم فقط أثناء عمليات البناء.
•
bar-with-logs
يعرض السجلات الخام، مع شريط التقدم في الأسفل.
•
--no-build-output / -Q
بشكل افتراضي، يتم عكس الإخراج الذي كتبه البناة إلى الإخراج القياسي والخطأ القياسي إلى الخطأ القياسي لأمر Nix. هذا الخيار يلغي هذا السلوك. لاحظ أن الإخراج القياسي والخطأ الخاص بالباني يتم كتابتهما دائمًا إلى ملف سجل في prefix/nix/var/log/nix.
•
--max-jobs / -j عدد
يضبط الحد الأقصى لعدد مهام البناء التي ستجريها Nix بالتوازي إلى العدد المحدد. حدد auto لاستخدام عدد وحدات المعالجة المركزية في النظام. الافتراضي هو المحدد بواسطة إعداد التكوين max-jobs، والذي افتراضيًا هو 1. القيمة الأعلى مفيدة على أنظمة SMP أو للاستفادة من تأخير الإدخال/الإخراج.
ضبطه على 0 يمنع البناء على الجهاز المحلي، وهو مفيد عندما تريد أن تحدث عمليات البناء فقط على بناة بعيدين.
•

OPTIONS

•
--cores
يحدد قيمة متغير البيئة NIX_BUILD_CORES في استدعاء البناة. يمكن للبناة استخدام هذا المتغير حسب تقديرهم للتحكم في الحد الأقصى للتوازي. على سبيل المثال، في Nixpkgs، إذا تم تعيين سمة البناء enableParallelBuilding إلى true، فإن الباني يمرر العلامة -jN إلى GNU Make. افتراضياً، يأخذ القيمة من إعداد التكوين cores، إذا تم تعيينه، أو 1 بخلاف ذلك. القيمة 0 تعني أن الباني يجب أن يستخدم جميع نوى وحدة المعالجة المركزية المتاحة في النظام.
•
--max-silent-time
يحدد الحد الأقصى لعدد الثواني التي يمكن للباني أن يمضيها دون إنتاج أي بيانات على الإخراج القياسي أو الخطأ القياسي. الافتراضي محدد بواسطة إعداد التكوين max-silent-time. القيمة 0 تعني عدم وجود مهلة.
•
--timeout
يحدد الحد الأقصى لعدد الثواني التي يمكن للباني أن يعمل فيها. الافتراضي محدد بواسطة إعداد التكوين timeout. القيمة 0 تعني عدم وجود مهلة.
•
--keep-going / -k
يواصل العمل قدر الإمكان في حالة فشل البناء. أي، إذا فشل بناء أحد مدخلات مشتقة معينة، سيقوم Nix ببناء المدخلات الأخرى، ولكن ليس المشتقة نفسها. بدون هذا الخيار، يتوقف Nix إذا فشل أي بناء (باستثناء عمليات بناء البدائل)، وقد يقتل عمليات البناء قيد التقدم (في حالة البناء المتوازي أو الموزع).
•
--keep-failed / -K
يحدد أنه في حالة فشل البناء، يجب عدم حذف الدليل المؤقت (عادةً في /tmp) الذي يتم فيه إجراء البناء. تتم طباعة مسار دليل البناء كرسالة إعلامية.
•
--fallback
كلما حاول Nix بناء مشتقة توجد بدائل معروفة لكل مسار إخراج، ولكن فشلت عملية تحقيق مسارات الإخراج عبر البدائل، يتم الرجوع إلى بناء المشتقة.
السيناريو الأكثر شيوعًا الذي يكون فيه هذا مفيدًا هو عندما نكون قد سجلنا بدائل لإجراء التوزيع الثنائي من، على سبيل المثال، مستودع شبكة. إذا كان المستودع معطلاً، فسيفشل تحقيق المشتقة. عندما يتم تحديد هذا الخيار، سيقوم Nix ببناء المشتقة بدلاً من ذلك. وبالتالي، يسقط التثبيت من الملفات الثنائية إلى التثبيت من المصدر. هذا الخيار ليس افتراضيًا لأنه ليس مرغوبًا فيه بشكل عام أن يؤدي فشل عابر في الحصول على البدائل إلى بناء كامل من المصدر (مع استهلاك الموارد المرتبط).
•
--readonly-mode
عند استخدام هذا الخيار، لا يتم بذل أي محاولة لفتح قاعدة بيانات Nix. معظم عمليات Nix تتطلب الوصول إلى قاعدة البيانات، لذلك ستفشل تلك العمليات.
•
--arg name value
يتم قبول هذا الخيار بواسطة nix-env و nix-instantiate و nix-shell و nix-build. عند تقييم تعبيرات Nix، سيحاول مُقيِّم التعبير تلقائيًا استدعاء الدوال التي يواجهها. يمكنه استدعاء الدوال تلقائيًا التي يكون لكل وسيطة فيها قيمة افتراضية (مثل، { argName ? defaultValue }: ...).
مع --arg، يمكنك أيضًا استدعاء الدوال التي تحتوي على وسائط بدون قيمة افتراضية (أو تجاوز قيمة افتراضية). أي، إذا واجه المُقيِّم دالة ذات وسيطة مسماة name، فسيستدعيها بالقيمة value.
على سبيل المثال، default.nix العلوي في Nixpkgs هو في الواقع دالة:
{ # The system (e.g., `i686-linux') for which to build the packages.
system ? builtins.currentSystem
...
}: ...
لذلك، إذا قمت باستدعاء هذا التعبير Nix (على سبيل المثال، عند تنفيذ nix-env --install --attr pkgname)، فسيتم استدعاء الدالة تلقائيًا باستخدام القيمة builtins.currentSystem للوسيطة system. يمكنك تجاوز ذلك باستخدام --arg، على سبيل المثال، nix-env --install --attr pkgname --arg system \"i686-freebsd\". (لاحظ أنه نظرًا لأن الوسيطة عبارة عن سلسلة نصية Nix حرفية، يجب عليك تهريب علامات الاقتباس.)
•
--argstr name value
هذا الخيار مثل --arg، فقط القيمة ليست تعبير Nix بل سلسلة نصية. لذا بدلاً من --arg system \"i686-linux\" (علامات الاقتباس الخارجية لإبقاء الصدفة سعيدة) يمكنك قول --argstr system i686-linux.
•
--attr / -A attrPath
حدد سمة من تعبير Nix العلوي الذي يتم تقييمه. (فقط nix-env و nix-instantiate و nix-build و nix-shell). المسار attribute attrPath هو تسلسل من أسماء السمات مفصولة بنقاط. على سبيل المثال، بالنظر إلى تعبير Nix العلوي e، فإن مسار السمة xorg.xorgserver سيؤدي إلى استخدام التعبير e.xorg.xorgserver. انظر nix-env --install لبعض الأمثلة الملموسة.
بالإضافة إلى أسماء السمات، يمكنك أيضًا تحديد فهارس المصفوفة. على سبيل المثال، مسار السمة foo.3.bar يحدد السمة bar للعنصر الرابع من المصفوفة في السمة foo للتعبير العلوي.
•
--expr / -E
فسر وسائط سطر الأوامر كتسلسل من تعبيرات Nix ليتم تحليلها وتقييمها، بدلاً من كونها قائمة بأسماء ملفات تعبيرات Nix. (فقط nix-instantiate و nix-build و nix-shell.)
بالنسبة إلى nix-shell، يُستخدم هذا الخيار بشكل شائع لمنحك بيئة shell يمكنك من خلالها بناء الحزم التي تم إرجاعها بواسطة التعبير. إذا كنت ترغب في الحصول على بيئة shell تحتوي على الحزم *المبنية* الجاهزة للاستخدام، فقم بتمرير تعبيرك إلى علامة nix-shell --packages المريحة بدلاً من ذلك.
•
-I / --include path
أضف إدخالاً إلى قائمة مسارات البحث المستخدمة لحل lookup paths. يمكن تقديم هذا الخيار عدة مرات.
المسارات المضافة عبر -I لها الأسبقية على إعداد التكوين nix-path و متغير البيئة NIX_PATH.
•
--option name value
عيّن خيار تكوين Nix name إلى value. هذا يتجاوز الإعدادات في ملف تكوين Nix (انظر nix.conf5).
•
--repair
إصلاح مسارات المتجر التالفة أو المفقودة عن طريق إعادة تنزيلها أو إعادة بنائها. لاحظ أن هذا بطيء لأنه يتطلب حساب تجزئة تشفير لمحتويات كل مسار في إغلاق البناء. لاحظ أيضًا التحذير تحت nix-store --repair-path.

Note

انظر man nix.conf لتجاوز إعدادات التكوين باستخدام علامات سطر الأوامر.

nix-env(1) — Nix manual

Name

nix-env - uninstall packages

Synopsis

nix-env [-q|-i|-u|-e] [-p path] [-f file] [-I path] [attribute...]

Description

The nix-env command installs, uninstalls, and upgrades packages in a user profile. It allows users to manage their own set of installed packages independently of the system-wide set of packages. This is achieved by creating a separate Nix store path (a profile) for each user, containing symlinks to the desired packages in the Nix store.

The primary operations are:

-i, --install
Installs the given packages (specified by attribute name or path to a Nix expression).
-u, --upgrade
Upgrades installed packages. If specific packages are named, only those will be upgraded. Otherwise, all installed packages will be upgraded to the latest available versions according to the current Nix channels.
-e, --uninstall
Uninstalls the given packages (specified by attribute name). If the attribute name is a regular expression, all installed packages whose attribute names match the regular expression will be uninstalled.
-q, --query
Queries the user profile. This is the default operation if no other operation is specified.

The following options are available:

-p, --profile path
Manages the profile located at path instead of the default user profile (~/.nix-profile).
-f, --file file
Specifies the Nix expression from which to install packages. This can be a path to a Nix file or a URL (e.g. https://nixos.org/channels/nixpkgs-unstable).
-I, --include path
Adds a directory to the Nix search path. This is useful for specifying paths to package definitions or other Nix expressions.
--dry-run
Perform a trial run with no changes made.
--rollback
Rolls back the profile to the previous generation. This is only possible if the profile has been modified at least once.
--list-generations
Lists all available profile generations.
--switch-generation generation
Switches the profile to the specified generation.
--delete-generations generation...
Deletes the specified profile generations. Generations can be specified by number or by a range (e.g., '1-5'). Use '--delete-generations old' to delete all generations except the current one.

Environment variables

•
NIX_PATH
A colon-separated list of search path entries used to resolve lookup paths.
This environment variable overrides the value of the nix-path configuration setting.
It can be extended using the -I option.
Example
$ export NIX_PATH=`/home/eelco/Dev:nixos-config=/etc/nixos
If NIX_PATH is set to an empty string, resolving search paths will always fail.
Example
$ NIX_PATH= nix-instantiate --eval '<nixpkgs>'
error: file 'nixpkgs' was not found in the Nix search path (add it using $NIX_PATH or -I)
•
NIX_IGNORE_SYMLINK_STORE
Normally, the Nix store directory (typically /nix/store) is not allowed to contain any symlink components. This is to prevent “impure” builds. Builders sometimes “canonicalise” paths by resolving all symlink components. Thus, builds on different machines (with /nix/store resolving to different locations) could yield different results. This is generally not a problem, except when builds are deployed to machines where /nix/store resolves differently. If you are sure that you’re not going to do that, you can set NIX_IGNORE_SYMLINK_STORE to 1.
Note that if you’re symlinking the Nix store so that you can put it on another file system than the root file system, on Linux you’re better off using bind mount points, e.g.,
$ mkdir /nix
$ mount -o bind /mnt/otherdisk/nix /nix
Consult the mount 8 manual page for details.
•
NIX_STORE_DIR
Overrides the location of the Nix store (default prefix/store).
•
NIX_DATA_DIR
Overrides the location of the Nix static data directory (default prefix/share).
•
NIX_LOG_DIR
Overrides the location of the Nix log directory (default prefix/var/log/nix).
•
NIX_STATE_DIR
Overrides the location of the Nix state directory (default prefix/var/nix).
•
NIX_CONF_DIR
Overrides the location of the system Nix configuration directory (default prefix/etc/nix).
•
NIX_CONFIG
Applies settings from Nix configuration from the environment. The content is treated as if it was read from a Nix configuration file. Settings are separated by the newline character.
•
NIX_USER_CONF_FILES
Overrides the location of the Nix user configuration files to load from.
The default are the locations according to the XDG Base Directory Specification. See the XDG Base Directories sub-section for details.
The variable is treated as a list separated by the : token.
•
TMPDIR
Use the specified directory to store temporary files. In particular, this includes temporary build directories; these can take up substantial amounts of disk space. The default is /tmp.
•
NIX_REMOTE
This variable should be set to daemon if you want to use the Nix daemon to execute Nix operations. This is necessary in multi-user Nix installations. If the Nix daemon’s Unix socket is at some non-standard path, this variable should be set to unix://path/to/socket. Otherwise, it should be left unset.
•
NIX_SHOW_STATS
If set to 1, Nix will print some evaluation statistics, such as the number of values allocated.
•
NIX_COUNT_CALLS
If set to 1, Nix will print how often functions were called during Nix expression evaluation. This is useful for profiling your Nix expressions.
•
GC_INITIAL_HEAP_SIZE
If Nix has been configured to use the Boehm garbage collector, this variable sets the initial size of the heap in bytes. It defaults to 384 MiB. Setting it to a low value reduces memory consumption, but will increase runtime due to the overhead of garbage collection.

XDG Base Directories

Nix follows the XDG Base Directory Specification.

For backwards compatibility, Nix commands will follow the standard only when use-xdg-base-directories is enabled. New Nix commands (experimental) conform to the standard by default.

The following environment variables are used to determine locations of various state and configuration files:

  • [XDG_CONFIG_HOME]{#env-XDGCONFIGHOME} (default ~/.config)
  • [XDG_STATE_HOME]{#env-XDGSTATEHOME} (default ~/.local/state)
  • [XDG_CACHE_HOME]{#env-XDGCACHEHOME} (default ~/.cache)

Examples

$ nix-env --uninstall gcc
$ nix-env --uninstall '.*' (remove everything)
