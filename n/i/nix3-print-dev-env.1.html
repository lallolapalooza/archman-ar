nix3-print-dev-env(1)

الحزمة: nix

التراخيص: LGPL-2.1-only

nix3-print-dev-env(1) دليل الأوامر العامة nix3-print-dev-env(1)

تحذير
هذا البرنامج تجريبي وواجهته عرضة للتغيير.

الاسم

nix print-dev-env - طباعة شيفرة شل يمكن استيرادها بواسطة bash لتكرار بيئة بناء لـ derivation

الملخص

nix print-dev-env [خيار••] installable

أمثلة

•
تطبيق بيئة البناء لـ GNU hello على الشل الحالي:
# . <(nix print-dev-env nixpkgs#hello)
•
الحصول على بيئة البناء بتنسيق JSON:
# nix print-dev-env nixpkgs#hello --json
سيبدو الإخراج كالتالي:
{
"bashFunctions": {
  "buildPhase": " \n    runHook preBuild;\n...",
  ...
},
"variables": {
  "src": {
    "type": "exported",
    "value": "/nix/store/3x7dwzq014bblazs7kq20p9hyzz0qh8g-hello-2.10.tar.gz"
  },
  "postUnpackHooks": {
    "type": "array",
    "value": ["_updateSourceDateEpochFromSourceRoot"]
  },
  ...
}
}

الوصف

يطبع هذا الأمر نص شل برمجي يمكن استيراده بواسطة bash ويقوم بتعيين المتغيرات ووظائف الشل التي تحددها عملية بناء installable. هذا يسمح لك بالحصول على بيئة بناء مشابهة في الشل الحالي الخاص بك بدلاً من شل فرعي (كما هو الحال مع nix develop).

مع --json، يكون الإخراج تسلسلاً بتنسيق JSON للمتغيرات والوظائف التي تحددها عملية البناء.

خيارات

•
--json
إنتاج الإخراج بتنسيق JSON، مناسب للاستهلاك بواسطة برنامج آخر.
•
--profile مسار
الملف الشخصي للعمل عليه.
•
--redirect installable outputs-dir
إعادة توجيه مسار مخزن إلى موقع قابل للتغيير.

خيارات التقييم الشائعة

•
--arg name expr
تمرير القيمة expr كـ name وسيطة لوظائف Nix.
•
--arg-from-file name path
تمرير محتويات الملف path كـ name وسيطة لوظائف Nix.
•
--arg-from-stdin name
تمرير محتويات stdin كـ name وسيطة لوظائف Nix.
•
--argstr name string
تمرير السلسلة النصية string كـ name وسيطة لوظائف Nix.
•
--debugger
بدء بيئة تفاعلية إذا فشل التقييم.
•
--eval-store store-url
عنوان URL لمخزن Nix للاستخدام في التقييم، أي لتخزين derivations (.drv files) والمدخلات المشار إليها بها.
•
--impure
السماح بالوصول إلى المسارات والمستودعات القابلة للتغيير.
•
--include / -I path
إضافة path إلى إدخالات المسار المستخدمة لحل مسارات البحث
يمكن إعطاء هذا الخيار عدة مرات.
المسارات المضافة عبر -I لها الأسبقية على إعداد التكوين nix-path و متغير البيئة NIX_PATH .
•
--override-flake original-ref resolved-ref
تجاوز سجلات flake، وإعادة توجيه original-ref إلى resolved-ref.

خيارات شائعة متعلقة بـ flake

•
--commit-lock-file
تثبيت التغييرات في ملف قفل flake.
•
--inputs-from flake-url
استخدام مدخلات flake المحدد كإدخالات سجل.
•
--no-registries
لا تسمح بعمليات البحث في سجلات flake.
تم إلغاء استخدامه
استخدم --no-use-registries بدلاً من ذلك.
•
--no-update-lock-file
لا تسمح بأي تحديثات لملف قفل flake.
•
--no-write-lock-file
لا تكتب ملف قفل flake الذي تم إنشاؤه حديثًا.
•
--output-lock-file flake-lock-path
اكتب ملف القفل المحدد بدلاً من flake.lock داخل flake المستوى الأعلى.
•
--override-input input-path flake-url
تجاوز مدخل flake معين (مثل dwarffs/nixpkgs). هذا يتضمن --no-write-lock-file.
•
--recreate-lock-file
إعادة إنشاء ملف قفل flake من البداية.
تم إلغاء استخدامه
استخدم nix flake update بدلاً من ذلك.
•
--reference-lock-file flake-lo

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.
