NICE(1P) دليل مبرمج POSIX NICE(1P)

المقدمة

صفحة الدليل هذه جزء من دليل مبرمج POSIX. قد يختلف تنفيذ Linux لهذا الواجهة (راجع صفحة دليل Linux المقابلة لتفاصيل سلوك Linux)، أو قد لا يتم تنفيذ الواجهة على Linux.

الاسم

nice — استدعاء أداة مساعدة بقيمة ترتيب معدلة

الملخص

nice [-n زيادة] أداة مساعدة [وسيط...]

الوصف

تقوم الأداة المساعدة nice باستدعاء أداة مساعدة، طالبةً تشغيلها بقيمة ترتيب (nice value) مختلفة (انظر المجلد الأساسي لتعريفات POSIX.1-2017، القسم 3.244، قيمة الترتيب). بدون خيارات، سيتم تشغيل الأداة المساعدة المنفذة بقيمة ترتيب أكبر من أو تساوي قيمة ترتيب العملية الحالية، حسب ما يحدده التنفيذ. إذا كان المستخدم يفتقر إلى الامتيازات المناسبة للتأثير على قيمة الترتيب بالطريقة المطلوبة، فإن الأداة المساعدة nice لن تؤثر على قيمة الترتيب؛ في هذه الحالة، قد يتم كتابة رسالة تحذير إلى الخطأ القياسي، ولكن هذا لن يمنع استدعاء الأداة المساعدة أو يؤثر على حالة الخروج.

الخيارات

تلتزم الأداة المساعدة nice بالمجلد الأساسي لتعريفات POSIX.1-2017، القسم 12.2، إرشادات بناء جملة الأداة المساعدة.

الخيار التالي مدعوم:

-n زيادة
عدد صحيح عشري موجب أو سالب سيكون له نفس تأثير تشغيل الأداة المساعدة كما لو أن الأداة المساعدة استدعت الدالة nice() مع القيمة الرقمية لمعامل الخيار زيادة.

المعاملات

سيتم دعم المعاملات التالية:

أداة مساعدة
اسم الأداة المساعدة التي سيتم استدعاؤها. إذا كان المعامل أداة مساعدة يشير إلى أي من الأدوات المساعدة المضمنة الخاصة في القسم 2.14، الأدوات المساعدة المضمنة الخاصة، فإن النتائج غير محددة.
وسيط
أي سلسلة نصية سيتم تقديمها كوسيط عند استدعاء الأداة المساعدة المسماة بواسطة المعامل أداة مساعدة.

الأداة المساعدة nice

على بعض الأنظمة، لا يكون لها تأثير ملحوظ على الأداة المساعدة المنفذة، وعلى بعض الأنظمة الأخرى تكون مكافئة تمامًا.

RATIONALE

The nice utility sets the scheduling priority of a command. A smaller scheduling priority number results in the process being scheduled less frequently, while a larger number results in it being scheduled more frequently. The default value is intended to be implementation-defined, but it is typically 10.

A negative increment value can be specified only by a privileged process. If a non-privileged process attempts to specify a negative increment, the behavior is undefined by POSIX.1-2008, but historical implementations differ. The System V behavior is to treat a negative increment as 0. The 4.3 BSD behavior is to write a "permission denied" message and not run the utility. POSIX.1-2017 specifies the System V behavior and also allows for an optional BSD-style message.

The C shell has a built-in version of nice that has a different interface from the one described in this volume of POSIX.1-2017. The POSIX.1-2017 standard specifies the behavior of the external utility.

The term "utility" is used, rather than "command", to highlight the fact that shell compound commands, pipelines, and so on, cannot be used. Special built-ins also cannot be used. However, "utility" includes user application programs and shell scripts, not just utilities defined in this volume of POSIX.1-2017.

Historical implementations of nice provide a nice value range of 40 or 41 discrete steps, with the default nice value being the midpoint of that range. By default, they raise the nice value of the executed utility by 10.

Some historical documentation states that the increment value must be within a fixed range. This is misleading; the valid increment values on any invocation are determined by the current process nice value, which is not always the default.

The definition of nice value is not intended to suggest that all processes in a system have priorities that are comparable. Scheduling policy extensions such as the realtime priorities in the System Interfaces volume of POSIX.1-2017 make the notion of a single underlying priority for all scheduling policies problematic. Some implementations may implement the nice-related features to affect all processes on the system, others to affect just the general time-sharing activities implied by this volume of POSIX.1-2017, and others may have no effect at all. Because of the use of "implementation-defined" in nice and renice, a wide range of implementation strategies are possible.

Earlier versions of this standard allowed a -increment option. This form is no longer specified by POSIX.1-2008 but may be present in some implementations.

If the user does not have appropriate privileges, attempting to decrease the nice value (by using a negative increment) results in a "permission denied" error. This is considered a bug.

When a user without appropriate privileges gives a negative increment, System V treats it like the command nice -0 utility, while 4.3 BSD writes a "permission denied" message and does not run the utility. The standard specifies the System V behavior together with an optional BSD-style "permission denied" message.

التعليل

تحدد الأداة nice أولوية الجدولة للأمر. يؤدي رقم أولوية جدولة أصغر إلى جدولة العملية بشكل أقل تكرارًا، بينما يؤدي رقم أكبر إلى جدولتها بشكل متكرر أكثر. القيمة الافتراضية مخصصة ليتم تعريفها من قبل التطبيق، ولكنها عادة ما تكون 10.

لا يمكن تحديد قيمة زيادة سالبة إلا بواسطة عملية ذات امتيازات. إذا حاولت عملية غير ذات امتيازات تحديد زيادة سالبة، فإن السلوك غير محدد بواسطة POSIX.1-2008، ولكن التطبيقات التاريخية تختلف. سلوك System V هو معاملة الزيادة السالبة على أنها 0. سلوك 4.3 BSD هو كتابة رسالة "تم رفض الإذن" وعدم تشغيل الأداة. تحدد POSIX.1-2017 سلوك System V وتسمح أيضًا برسالة اختيارية بأسلوب BSD "تم رفض الإذن".

يحتوي shell C على نسخة مدمجة من nice لها واجهة مختلفة عن تلك الموصوفة في هذا المجلد من POSIX.1-2017. يحدد معيار POSIX.1-2017 سلوك الأداة الخارجية.

يتم استخدام مصطلح "أداة" بدلاً من "أمر" لتسليط الضوء على حقيقة أنه لا يمكن استخدام أوامر shell المركبة، وخطوط الأنابيب، وما إلى ذلك. لا يمكن أيضًا استخدام الأدوات المدمجة الخاصة. ومع ذلك، تشمل "الأداة" برامج التطبيقات للمستخدم والنصوص البرمجية لـ shell، وليس فقط الأدوات المحددة في هذا المجلد من POSIX.1-2017.

التطبيقات التاريخية للأداة nice توفر نطاق قيمة لطيفة يتكون من 40 أو 41 خطوة منفصلة، مع كون القيمة اللطيفة الافتراضية هي نقطة المنتصف لهذا النطاق. افتراضيًا، ترفع القيمة اللطيفة للأداة المنفذة بمقدار 10.

تنص بعض الوثائق التاريخية على أن قيمة الزيادة يجب أن تكون ضمن نطاق ثابت. هذا مضلل؛ قيم الزيادة الصالحة في أي استدعاء يتم تحديدها بواسطة قيمة nice للعملية الحالية، والتي ليست دائمًا القيمة الافتراضية.

لا يُقصد بتعريف القيمة اللطيفة أن توحي بأن جميع العمليات في النظام لها أولويات قابلة للمقارنة. تجعل امتدادات سياسة الجدولة مثل أولويات الوقت الفعلي في مجلد واجهات النظام الخاص بـ POSIX.1-2017 فكرة الأولوية الأساسية الواحدة لجميع سياسات الجدولة إشكالية. قد تنفذ بعض التطبيقات ميزات nice-related للتأثير على جميع العمليات في النظام، والبعض الآخر للتأثير فقط على أنشطة المشاركة الزمنية العامة التي يشير إليها هذا المجلد من POSIX.1-2017، وقد لا يكون للبعض الآخر أي تأثير على الإطلاق. بسبب استخدام "يحدده التطبيق" في nice و renice، من الممكن وجود مجموعة واسعة من استراتيجيات التطبيق.
