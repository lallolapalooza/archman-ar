الاسم

nix-env - معالجة أو الاستعلام عن بيئات مستخدم Nix

الخلاصة

nix-env عملية [خيارات] [وسائط•••] [--option اسم قيمة] [--arg اسم قيمة] [--argstr اسم قيمة] [{--file | -f} مسار] [{--profile | -p} مسار] [--system-filter نظام] [--dry-run]

الوصف

nix-env يُستخدم لمعالجة بيئات مستخدم Nix. بيئات المستخدم هي مجموعات من البرامج المتاحة للمستخدم في وقت معين. بعبارة أخرى، إنها عرض مُصنّع للبرامج المتاحة في مخزن Nix. قد تكون هناك بيئات مستخدم متعددة: يمكن للمستخدمين المختلفين الحصول على بيئات مختلفة، ويمكن للمستخدمين الأفراد التبديل بين البيئات المختلفة.

nix-env يأخذ بالضبط علامة عملية واحدة تشير إلى الأمر الفرعي الذي سيتم تنفيذه. العمليات التالية متاحة:

  • --install
  • --upgrade
  • --uninstall
  • --set
  • --set-flag
  • --query
  • --switch-profile
  • --list-generations
  • --delete-generations
  • --switch-generation
  • --rollback

يمكن عرض هذه الصفحات دون اتصال:

•
man nix-env-<operation>.
مثال: man nix-env-install
•
nix-env --help --<operation>
مثال: nix-env --help --install

مصادر الحزم

nix-env يمكنه الحصول على الحزم من مصادر متعددة:

•
مجموعة سمات للتطويرات من:
  • تعبير Nix الافتراضي (بشكل افتراضي)
  • ملف Nix، محدد عبر --file
  • ملف تعريف، محدد عبر --from-profile
  • تعبير Nix هو دالة تأخذ تعبيرًا افتراضيًا كوسيط، محدد عبر --from-expression
•
مسار المتجر

المحددات

العديد من العمليات، مثل nix-env --query و nix-env --install، تأخذ قائمة من الوسائط التي تحدد الحزم التي سيتم تشغيلها.

يتم تحديد الحزم بناءً على جزء الاسم وجزء الإصدار من اسم التطوير الرمزي:

  • الاسم: كل شيء حتى الشرطة الأولى (-) التي *لا* يتبعها حرف.
  • الإصدار: الباقي، باستثناء الشرطة الفاصلة.

مثال

nix-env يحلل اسم التطوير الرمزي apache-httpd-2.0.48 إلى:

{
  "name": "apache-httpd",
  "version": "2.0.48"
}

مثال

nix-env يحلل اسم التطوير الرمزي firefox.* إلى:

{
  "name": "firefox.*",
  "version": ""
}

تُعامل أجزاء الاسم من وسائط nix-env كتعبيرات عادية موسعة ويتم مطابقتها مع أجزاء الاسم لأسماء التطويرات في مصدر الحزمة. المطابقة حساسة لحالة الأحرف. يمكن أن يتبع التعبير العادي اختياريًا شرطة (-) ورقم إصدار؛ إذا تم حذفه، فستتطابق أي نسخة من الحزمة. للحصول على تفاصيل حول التعبيرات العادية، انظر regex(7).

مثال

أنماط شائعة للعثور على أسماء الحزم باستخدام nix-env:

•
firefox
يطابق اسم الحزمة firefox وأي إصدار.
•
firefox-32.0
يطابق اسم الحزمة firefox والإصدار 32.0.
•
gtk\\+
يطابق اسم الحزمة gtk+. يجب أن يتم تهريب الحرف + باستخدام شرطة مائلة للخلف (\) لمنعه من تفسيره كمحدد كمي، ويجب تهريب الشرطة المائلة للخلف بدورها بشرطة مائلة للخلف أخرى لضمان أن الشل يمررها.
•
.\*
يطابق أي اسم حزمة. هذا هو الافتراضي لمعظم الأوامر.
•
'.*zip.*'
يطابق أي اسم حزمة يحتوي على السلسلة zip. لاحظ النقاط: '*zip*' لا يعمل، لأنه في تعبير عادي، يتم تفسير الحرف * كمحدد كمي.
•
'.*(firefox|chromium).*'
يطابق أي اسم حزمة يحتوي على السلاسل firefox أو chromium.

الملفات

nix-env يعمل على الملفات التالية.

تعبير Nix الافتراضي

المصدر لتعبيرات Nix الافتراضية المستخدمة بواسطة nix-env:

  • ~/.nix-defexpr
  • $XDG_STATE_HOME/nix/defexpr إذا كان use-xdg-base-directories مُعيّنًا إلى true.

يتم تحميله على النحو التالي:

  • إذا كان التعبير الافتراضي ملفًا، فسيتم تحميله كتعبير Nix.
  • إذا كان التعبير الافتراضي مجلدًا يحتوي على ملف default.nix، فسيتم تحميل هذا الملف default.nix كتعبير Nix.
  • إذا كان التعبير الافتراضي مجلدًا بدون default.nix، فسيتم تحميل هذا المجلد.

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

NAME

nix-collect-garbage

garbage collector for the Nix store

SYNOPSIS

nix-collect-garbage

[--delete-older-than days]

[--max-freed size]

[--force]

[--commit-lockfile]

[--defer-errors]

[--keep-since timestamp]

[--keep-derivations]

[--keep-outputs]

[--check]

[--help]

[--version]

[paths...]

DESCRIPTION

The Nix package manager maintains a collection of all the packages and other dependencies that have ever been built or installed. This collection is called the Nix store. Over time, the store can grow quite large. The command nix-collect-garbage removes unused elements from the store.

An element is considered unused if it is not reachable from any of the following:

  • The current user’s profile (see User profile link).
  • The root user’s profile.
  • Any channels subscribed to by the user (see nix-channel(1)).
  • Any channels subscribed to by the root user.
  • Any derivation that is currently being built.
  • Any derivation that is specified on the command line.

The garbage collector performs a reachability analysis. It starts with the set of all generations of all profiles and all channels, and all currently building derivations, and marks all elements reachable from these roots. All unmarked elements in the Nix store are then considered garbage and are removed.

The garbage collector may be invoked on the command line (e.g., nix-collect-garbage) or it may be run periodically by the Nix daemon (if it is configured to do so). Running the command line tool performs the garbage collection immediately. The daemon performs garbage collection on a schedule, usually once a week.

By default, nix-collect-garbage only collects garbage from the Nix store. You can specify paths on the command line to collect garbage only from those paths.

The command preserves the following:

  • All generations of all profiles and channels.
  • All currently building derivations.
  • All derivations specified on the command line (and their dependencies).

Elements that are not garbage collected are retained for their entire history. This means that if you have 5 profiles and 10 channels, you will always have at least 50 elements in the store (unless you explicitly delete profiles or channels).

Default expression

The Nix configuration file ~/.nix-defexpr/default.nix (or $XDG_CONFIG_HOME/nix/defexpr/default.nix if use-xdg-base-directories is set to true) is treated as the default Nix expression. If this file exists, it is evaluated and its result is added to the set of roots used by the garbage collector. The expression is evaluated as follows:

If the file ~/.nix-defexpr/default.nix exists, then its contents are loaded as Nix expressions. The expressions are combined into a single attribute set, each expression under an attribute with the same name as the original file or subdirectory. Subdirectories without a default.nix file are traversed recursively in search of more Nix expressions, but the names of these intermediate directories are not added to the attribute paths of the default Nix expression.

Then, the resulting expression is interpreted like this:

  • If the expression is an attribute set, it is used as the default Nix expression.
  • If the expression is a function, an empty set is passed as argument and the return value is used as the default Nix expression.

For example, if the default expression contains two files, foo.nix and bar.nix, then the default Nix expression will be equivalent to

{
  foo = import ~/.nix-defexpr/foo.nix;
  bar = import ~/.nix-defexpr/bar.nix;
}

The file manifest.nix is always ignored.

The command nix-channel places a symlink to the user’s current channels profile in this directory. This makes all subscribed channels available as attributes in the default expression.

User channel link

A symlink that ensures that nix-env can find your channels:

  • ~/.nix-defexpr/channels
  • $XDG_STATE_HOME/defexpr/channels if use-xdg-base-directories is set to true.

This symlink points to:

  • $XDG_STATE_HOME/profiles/channels for regular users
  • $NIX_STATE_DIR/profiles/per-user/root/channels for root

In a multi-user installation, you may also have ~/.nix-defexpr/channels_root, which links to the channels of the root user.nix-env: ../nix-env.md

Profiles

A directory that contains links to profiles managed by nix-env and nix profile:

  • $XDG_STATE_HOME/nix/profiles for regular users
  • $NIX_STATE_DIR/profiles/per-user/root if the user is root

A profile is a directory of symlinks to files in the Nix store.

Filesystem layout

Profiles are versioned as follows. When using a profile named path, path is a symlink to path-N-link, where N is the version of the profile. In turn, path-N-link is a symlink to a path in the Nix store. For example:

lrwxrwxrwx 1 alice users 51 Oct 29 13:20 /home/alice/.local/state/nix/profiles/profile-6-link -> /nix/store/6bvhpysd7vwz7k3b0pndn7ifi5xr32dg-profile

Each profile version contains a manifest file: - manifest.nix used by nix-env. - manifest.json used by nix profile (experimental).

User profile link

A symbolic link to the user’s current profile:

  • ~/.nix-profile
  • $XDG_STATE_HOME/nix/profile if use-xdg-base-directories is set to true.

By default, this symlink points to:

  • $XDG_STATE_HOME/nix/profiles/profile for regular users
  • $NIX_STATE_DIR/profiles/per-user/root/profile for root

The PATH environment variable should include /bin subdirectory of the profile link (e.g. ~/.nix-profile/bin) for the user environment to be visible to the user. The installer sets this up by default, unless you enable use-xdg-base-directories.

OPTIONS

--delete-older-than days
This option collects garbage and also deletes all garbage older than days days. This option is intended for cleaning up the Nix store and can be run periodically. It is safe to use because it preserves all current profiles and channels.
--max-freed size
The maximum number of bytes to free. If this is specified, the garbage collector will stop once it has freed up this much space. The size is specified as a number followed by an optional unit (k, m, g, t, p). For example, 100M.
--force
Don’t ask for confirmation before deleting files. This is intended for use in scripts.
--commit-lockfile
If nix-channel is run with --commit-lockfile, then nix-collect-garbage will preserve the generations of the channels.
--defer-errors
Don’t abort the garbage collection if errors occur (e.g. if the store path is still in use). It will simply report the error and continue collecting garbage.
--keep-since timestamp
Keep all garbage older than the specified timestamp. The timestamp should be in the format YYYY-MM-DDThh:mm:ssZ.
--keep-derivations
Do not collect garbage derivations (i.e., derivations that have not yet been evaluated). This is the default behaviour.
--keep-outputs
Do not collect garbage outputs (i.e., results of derivations that have not yet been built). This is the default behaviour.
--check
Perform a dry run of the garbage collection. It will print the list of all paths that would be removed, but won’t actually remove them.
--help
Display help message and exit.
--version
Display Nix version information and exit.

EXAMPLES

To remove all unused store paths:

$ nix-collect-garbage

To remove all unused store paths that are older than 7 days:

$ nix-collect-garbage -d 7

To perform a dry run:

$ nix-collect-garbage --check

To remove all unused store paths except for the current profile generations:

$ nix-collect-garbage --keep-derivations --keep-outputs
