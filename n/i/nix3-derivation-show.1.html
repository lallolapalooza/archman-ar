nix3-derivation-show(1)

الحزمة: nix

التراخيص: LGPL-2.1-only

nix3-derivation-show(1) دليل الأوامر العامة nix3-derivation-show(1)

تحذير
هذا البرنامج تجريبي وواجهته عرضة للتغيير.

الاسم

nix derivation show - عرض محتويات اشتقاق مخزن

الملخص

nix derivation show [خيار…] القابلة للتثبيت…

أمثلة

•
عرض الاشتقاق المخزن الذي ينتج عن تقييم حزمة Hello:
# nix derivation show nixpkgs#hello
{
"/nix/store/s6rn4jz1sin56rf4qj5b5v8jxjm32hlk-hello-2.10.drv": {
  …
}
}
•
عرض رسم بياني كامل للاشتقاق (إذا كان متاحًا) الذي أنتج نظام NixOS الخاص بك:
# nix derivation show -r /run/current-system
•
طباعة جميع الملفات التي تم جلبها باستخدام fetchurl بواسطة الرسم البياني لاعتماديات Firefox:
# nix derivation show -r nixpkgs#firefox \
| jq -r '.[] | select(.outputs.out.hash and .env.urls) | .env.urls' \
| uniq | sort
لاحظ أن .outputs.out.hash يحدد الاشتقاقات ذات المخرجات الثابتة (الاشتقاقات التي تنتج مخرجات لها تجزئة محتوى محددة)، بينما تحدد .env.urls الاشتقاقات التي لها سمة urls.

الوصف

يطبع هذا الأمر على المخرج القياسي تمثيلاً بصيغة JSON لـ اشتقاقات المخزن التي يتم تقييم القابلة للتثبيت إليها.

تُستخدم اشتقاقات المخزن داخليًا بواسطة Nix. وهي مسارات مخزن بالامتداد .drv التي تمثل الرسم البياني لاعتماديات وقت البناء الذي يتم تقييم تعبير Nix إليه.

بشكل افتراضي، يعرض هذا الأمر الاشتقاقات العلوية فقط، ولكن باستخدام --recursive، فإنه يعرض أيضًا اعتمادياتها.

يخرج nix derivation show خريطة JSON من مسارات المخزن إلى الاشتقاقات بالتنسيق التالي:

خيارات

•
--recursive / -r
تضمين اعتماديات الاشتقاقات المحددة.
•
--stdin
قراءة القابلة للتثبيت من المدخل القياسي. لا يتم تطبيق قابل للتثبيت افتراضي.

خيارات التقييم الشائعة

•
--arg name expr
تمرير القيمة expr كـ name الوسيط لوظائف Nix.
•
--arg-from-file name path
تمرير محتويات الملف path كـ name الوسيط لوظائف Nix.
•
--arg-from-stdin name
تمرير محتويات stdin كـ name الوسيط لوظائف Nix.
•
--argstr name string
تمرير السلسلة النصية string كـ name الوسيط لوظائف Nix.
•
--debugger
بدء بيئة تفاعلية إذا فشل التقييم.
•
--eval-store store-url
عنوان URL لمخزن Nix المستخدم للتقييم، أي لتخزين الاشتقاقات (.drv files) والمدخلات المشار إليها بواسطتها.
•
--impure
السماح بالوصول إلى المسارات والمستودعات القابلة للتغيير.
•
--include / -I path
إضافة path إلى مسارات البحث المستخدمة لحل مسارات البحث
يمكن إعطاء هذا الخيار عدة مرات.
المسارات المضافة عبر -I لها الأسبقية على إعداد تهيئة nix-path و متغير البيئة NIX_PATH.
•
--override-flake original-ref resolved-ref
تجاوز سجلات الشرر (flake registries)، وإعادة توجيه original-ref إلى resolved-ref.

خيارات شائعة متعلقة بالشرر (Flake-related)

•
--commit-lock-file
الالتزام بالتغييرات في ملف قفل الشرر.
•
--inputs-from flake-url
استخدام مدخلات الشرر المحدد كإدخالات في السجل.
•
--no-registries
عدم السماح بعمليات البحث في سجلات الشرر.
مهمل
استخدم --no-use-registries بدلاً من ذلك.
•
--no-update-lock-file
عدم السماح بأي تحديثات لملف قفل الشرر.
•
--no-write-lock-file
عدم كتابة ملف قفل الشرر الذي تم إنشاؤه حديثًا.
•
--output-lock-file flake-lock-path
كتابة ملف القفل المحدد بدلاً من flake.lock داخل الشرر العلوي.
•
--override-input input-path flake-url
تجاوز مدخل شرر محدد (على سبيل المثال، dwarffs/nixpkgs). هذا يعني --no-write-lock-file.
•
--recreate-lock-file
إعادة إنشاء ملف قفل الشرر من البداية.

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.
