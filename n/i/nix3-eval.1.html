nix3-eval(1)

الحزمة: nix

التراخيص: LGPL-2.1-only

nix3-eval(1) دليل الأوامر العامة nix3-eval(1)

تحذير
هذا البرنامج تجريبي وواجهته قابلة للتغيير.

الاسم

nix eval - تقييم تعبير Nix

الملخص

nix eval [خيار…] قابل-للتثبيت

أمثلة

•
تقييم تعبير Nix معطى في سطر الأوامر:
# nix eval --expr '1 + 2'
•
تقييم تعبير Nix إلى JSON:
# nix eval --json --expr '{ x = 1; }'
{"x":1}
•
تقييم تعبير Nix من ملف:
# nix eval --file ./my-nixpkgs hello.name
•
الحصول على الإصدار الحالي لـ nixpkgs flake:
# nix eval --raw nixpkgs#lib.version
•
طباعة مسار المتجر لحزمة Hello:
# nix eval --raw nixpkgs#hello
•
الحصول على قائمة بالفحوصات في nix flake:
# nix eval nix#checks.x86_64-linux --apply builtins.attrNames
•
إنشاء دليل بالمحتويات المحددة:
# nix eval --write-to ./out --expr '{ foo = "bar"; subdir.bla = "123"; }'
# cat ./out/foo
bar
# cat ./out/subdir/bla
123

الوصف

يقوم هذا الأمر بتقييم تعبير Nix المعطى ويطبع النتيجة على المخرج القياسي.

صيغة المخرج

nix eval يمكن أن ينتج مخرجات بعدة صيغ:

  • بشكل افتراضي، تتم طباعة نتيجة التقييم كتعبير Nix.
  • مع --json، تتم طباعة نتيجة التقييم بصيغة JSON. لاحظ أن هذا يفشل إذا كانت النتيجة تحتوي على قيم لا يمكن تمثيلها كـ JSON، مثل الدوال.
  • مع --raw، يجب أن تكون نتيجة التقييم سلسلة نصية، والتي تتم طباعتها حرفياً، دون أي اقتباس.
  • مع --write-to path، يجب أن تكون نتيجة التقييم سلسلة نصية أو مجموعة سمات متداخلة تكون قيم أوراقها سلاسل نصية. تتم كتابة هذه السلاسل النصية إلى ملفات مسماة path/attrpath. يجب ألا يكون path موجوداً بالفعل.

الخيارات

•
--apply expr
تطبيق الدالة expr على كل وسيط.
•
--json
إنتاج المخرج بصيغة JSON، مناسب للاستهلاك بواسطة برنامج آخر.
•
--raw
طباعة السلاسل النصية بدون علامات اقتباس أو تهريب.
•
--read-only
عدم تجسيد كل مشتق تم تقييمه. هذا يحسن الأداء، ولكنه قد يسبب أخطاء عند الوصول إلى مسارات المتجر للمشتقات أثناء التقييم.
•
--write-to path
كتابة سلسلة نصية أو مجموعة سمات من السلاسل النصية إلى path.

خيارات التقييم الشائعة

•
--arg name expr
تمرير القيمة expr كالوسيط name لدوال Nix.
•
--arg-from-file name path
تمرير محتويات الملف path كالوسيط name لدوال Nix.
•
--arg-from-stdin name
تمرير محتويات المدخل القياسي كالوسيط name لدوال Nix.
•
--argstr name string
تمرير السلسلة النصية string كالوسيط name لدوال Nix.
•
--debugger
بدء بيئة تفاعلية إذا فشل التقييم.
•
--eval-store store-url
عنوان URL لمتجر Nix لاستخدامه في التقييم، أي لتخزين المشتقات (ملفات .drv) والمدخلات المشار إليها بها.
•
--impure
السماح بالوصول إلى المسارات والمستودعات القابلة للتغيير.
•
--include / -I path
إضافة path إلى مسارات البحث المستخدمة لحل مسارات البحث
يمكن إعطاء هذا الخيار عدة مرات.
المسارات المضافة عبر -I لها الأسبقية على إعداد تهيئة nix-path و متغير البيئة NIX_PATH.
•
--override-flake original-ref resolved-ref
تجاوز سجلات الـ flake، وإعادة توجيه original-ref إلى resolved-ref.

خيارات متعلقة بالـ Flake الشائعة

•
--commit-lock-file
تثبيت التغييرات في ملف قفل الـ flake.
•
--inputs-from flake-url
استخدام مدخلات الـ flake المحدد كإدخالات في السجل.
•
--no-registries
عدم السماح بالبحث في سجلات الـ flake.
مهمل
استخدم --no-use-registries بدلاً من ذلك.
•
--no-update-lock-file
عدم السماح بأي تحديثات لملف قفل الـ flake.
•
--no-write-lock-file
عدم كتابة ملف قفل الـ flake الجديد الذي تم إنشاؤه.
•

Name

nix-eval - evaluate Nix expressions

Synopsis

nix-eval [options] --expr EXPR

nix-eval [options] --file FILE

nix-eval [options] INSTALLABLE...

Examples

Evaluate an expression:

$ nix-eval --expr '1 + 2'
3

Evaluate a Nix file:

$ nix-eval --file default.nix
{ ... }

Evaluate a flake:

$ nix-eval nixpkgs
{ ... }

Evaluate a specific attribute of a flake:

$ nix-eval nixpkgs#legacyPackages.x86_64.hello
{ ... }

Description

nix-eval evaluates Nix expressions and prints the result to standard output. It can take Nix expressions as strings, files, or flake references.

By default, nix-eval prints the resulting Nix value in a JSON-compatible format. This can be customized using the --output-format option.

If the evaluated expression results in a derivation, nix-eval will print the derivation's output path. If it results in a package, it will print the package's output path. Otherwise, it will print the JSON representation of the result.

Output format

The following output formats are supported:

json
Output the result as JSON. This is the default format. See also --json-pretty.
raw
Output the result as raw Nix store paths. This is equivalent to using nix store.

Options

Flake options

•
--commit-lockfile
Also commit the updated flake.lock file if it was changed.
•
--impure
Allow impure derivations to be built. This enables access to the Nix store, the Nix language, and the package collector from within the evaluated Nix expression. This is usually necessary when evaluating Nix expressions that depend on the Nixpkgs registry or other external resources.
•
--input-exclude path
Exclude the given flake input from evaluation.
•
--json-pretty
Output the result as JSON, but pretty-printed with indentation.
•
--lock-file flake-lock-path
Write the given lock file instead of flake.lock within the top-level flake.
•
--override-input input-path flake-url
Override a specific flake input (e.g. dwarffs/nixpkgs). This implies --no-write-lock-file.
•
--recreate-lock-file
Recreate the flake’s lock file from scratch.
DEPRECATED
Use nix flake update instead.
•
--reference-lock-file flake-lock-path
Read the given lock file instead of flake.lock within the top-level flake.
•
--update-input input-path
Update a specific flake input (ignoring its previous entry in the lock file).
DEPRECATED
Use nix flake update instead.

Logging-related options

•
--debug
Set the logging verbosity level to ‘debug’.
•
--log-format format
Set the format of log output; one of raw, internal-json, bar or bar-with-logs.
•
--print-build-logs / -L
Print full build logs on standard error.
•
--quiet
Decrease the logging verbosity level.
•
--verbose / -v
Increase the logging verbosity level.

Miscellaneous global options

•
--help
Show usage information.
•
--offline
Disable substituters and consider all previously downloaded files up-to-date.
•
--option name value
Set the Nix configuration setting name to value (overriding nix.conf).
•
--refresh
Consider all previously downloaded files out-of-date.
•
--repair
During evaluation, rewrite missing or corrupted files in the Nix store. During building, rebuild missing or corrupted store paths.
•
--version
Show version information.

Options that change the interpretation of installables

•
--expr expr
Interpret installables as attribute paths relative to the Nix expression expr.
•
--file / -f file
Interpret installables as attribute paths relative to the Nix expression stored in file. If file is the character -, then a Nix expression will be read from standard input. Implies --impure.

Note

See man nix.conf for overriding configuration settings with command line flags.
