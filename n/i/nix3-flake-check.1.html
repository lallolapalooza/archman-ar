nix3-flake-check(1) دليل الأوامر العامة nix3-flake-check(1)

تحذير
هذا البرنامج تجريبي وواجهته قابلة للتغيير.

الاسم

nix flake check - التحقق مما إذا كان الـ flake يتم تقييمه وتشغيل اختباراته

الملخص

nix flake check [خيار•] flake-url

أمثلة

•
تقييم الـ flake في الدليل الحالي، وبناء فحوصاته:
# nix flake check
•
التحقق من أن الـ flake patchelf يتم تقييمه، ولكن دون بناء فحوصاته:
# nix flake check --no-build github:NixOS/patchelf

الوصف

يتحقق هذا الأمر من أن الـ flake المحدد بواسطة مرجع الـ flake flake-url يمكن تقييمه بنجاح (كما هو مفصل أدناه)، وأن المشتقات المحددة بواسطة مخرجات الـ flake checks يمكن بناؤها بنجاح.

إذا تم تعيين الخيار keep-going إلى true، فسيستمر Nix في التقييم قدر الإمكان والإبلاغ عن الأخطاء عند اكتشافها. خلاف ذلك، سيتوقف عند الخطأ الأول.

فحوصات التقييم

يجب أن تكون سمات مخرجات الـ flake التالية مشتقات:

  • checks.system.name
  • defaultPackage.system
  • devShell.system
  • devShells.system.name
  • nixosConfigurations.name.config.system.build.toplevel
  • packages.system.name

يجب أن تكون سمات مخرجات الـ flake التالية تعريفات تطبيقات:

  • apps.system.name
  • defaultApp.system

يجب أن تكون سمات مخرجات الـ flake التالية تعريفات قوالب:

  • defaultTemplate
  • templates.name

يجب أن تكون سمات مخرجات الـ flake التالية تراكبات Nixpkgs:

  • overlay
  • overlays.name

يجب أن تكون سمات مخرجات الـ flake التالية وحدات NixOS:

  • nixosModule
  • nixosModules.name

يجب أن تكون سمات مخرجات الـ flake التالية حزم:

  • bundlers.name
  • defaultBundler

بالإضافة إلى ذلك، يتم تقييم مخرجات hydraJobs بنفس طريقة hydra-eval-jobs في Hydra (أي كمجموعة سمات متداخلة بعمق اعتباطيًا من المشتقات). وبالمثل، يتم تقييم مخرجات legacyPackages.system مثل nix-env --query --available.

NAME

nix3-flake-check — Checks that a flake is valid and works.

SYNOPSIS

nix flake check [option...] [flake-url]

EXAMPLES

Check the current flake:

$ nix flake check .

Check a remote flake:

$ nix flake check github:NixOS/nixpkgs

DESCRIPTION

The command runs all checks exposed by the flake.

A flake is a collection of outputs (e.g. packages, NixOS modules, dev shells) which are made available in a standardized way. The primary purpose of flakes is to provide reproducibility, enabling users to pin their dependencies.

The command requires the flake to expose at least one check output. Checks are defined in the checks attribute of the flake's outputs. For example, a flake could expose a checks.x86_64-linux.my-check attribute which would then be evaluated and run by this command.

The command ensures that the flake itself is valid and that all its dependencies are satisfied. This command also ensures that the flake's outputs are valid.

EVALUATION CHECKS

The command performs the following checks:

  1. flake validity: Checks that the flake's inputs are satisfied and that the flake can be evaluated without errors.

  2. dependency pinning: Checks that all inputs are pinned. This is to ensure reproducibility.

  3. type checking: Checks that the flake's outputs conform to the flake schema.

  4. check outputs: Runs all outputs exposed under the checks attribute.

OPTIONS

See Common options for the options that are available in most commands.
•
--commit-lockfile
If the lock file has been updated, commit the changes to the lock file. This is the default behaviour.
•
--no-commit-lockfile
Do not commit changes to the lock file. If the lock file has been updated, this will result in an error.
•
--eval-cache eval-cache-path
Use the given store path as an eval cache.
•
--exclude glob
Exclude results matching glob pattern.
•
--go-down
When checking a flake, recursively check all its dependencies.
•
--include glob
Include only results matching glob pattern.
•
--no-update-lock-file
Do not update the lock file. If the flake's dependencies have changed, this will result in an error.
•
--override-flake flake-url flake-url
Override an input flake reference. The first argument is the input flake to override, and the second argument is the new flake URL.
•
--output-lock-file flake-lock-path
Write the given lock file instead of flake.lock within the top-level flake.
•
--override-input input-path flake-url
Override a specific flake input (e.g. dwarffs/nixpkgs). This implies --no-write-lock-file.
•
--recreate-lock-file
Recreate the flake’s lock file from scratch.
DEPRECATED
Use nix flake update instead.
•
--reference-lock-file flake-lock-path
Read the given lock file instead of flake.lock within the top-level flake.
•
--update-input input-path
Update a specific flake input (ignoring its previous entry in the lock file).
DEPRECATED
Use nix flake update instead.
