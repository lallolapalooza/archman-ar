nix3-store-make-content-addressed(1)

الحزمة: nix

التراخيص: LGPL-2.1-only

nix3-store-make-content-addressed(1) دليل الأوامر العامة nix3-store-make-content-addressed(1)

تحذير
هذا البرنامج تجريبي وواجهته قابلة للتغيير.

الاسم

nix store make-content-addressed - إعادة كتابة مسار أو إغلاق إلى شكل معنون بالمحتوى

الملخص

nix store make-content-addressed [خيار•…] installables•…

أمثلة

•
إنشاء تمثيل معنون بالمحتوى للإغلاق الخاص بـ GNU Hello:
# nix store make-content-addressed nixpkgs#hello
…
rewrote '/nix/store/v5sv61sszx301i0x6xysaqzla09nksnd-hello-2.10' to '/nix/store/5skmmcb9svys5lj3kbsrjg7vf2irid63-hello-2.10'
نظرًا لأن المسارات الناتجة معنونة بالمحتوى، فهي دائمًا موثوقة ولا تحتاج إلى توقيعات لنسخها إلى مخزن آخر:
# nix copy --to /tmp/nix --trusted-public-keys '' /nix/store/5skmmcb9svys5lj3kbsrjg7vf2irid63-hello-2.10
على النقيض من ذلك، فإن الإغلاق الأصلي معنون بالمدخلات، لذا فإنه يحتاج إلى توقيعات لكي يكون موثوقًا به:
# nix copy --to /tmp/nix --trusted-public-keys '' nixpkgs#hello
cannot add path '/nix/store/zy9wbxwcygrwnh8n2w9qbbcr6zk87m26-libunistring-0.9.10' because it lacks a signature by a trusted key
•
إنشاء تمثيل معنون بالمحتوى للإغلاق الحالي لنظام NixOS :
# nix store make-content-addressed /run/current-system

الوصف

يقوم هذا الأمر بتحويل إغلاق مسارات المخزن المحددة بواسطة installables إلى صيغة معنونة بالمحتوى.

عادةً ما تكون مسارات مخزن Nix معنونة بالمدخلات، مما يعني أن جزء الهاش من مسار المخزن يتم حسابه من محتويات الاشتقاق (أي، الرسم البياني لتبعية وقت البناء). تحتاج المسارات المعنونة بالمدخلات إلى توقيعها بواسطة مفتاح موثوق به إذا كنت ترغب في استيرادها إلى مخزن، لأننا بحاجة إلى الثقة في أن محتويات المسار تم بناؤها بالفعل بواسطة الاشتقاق.

على النقيض من ذلك، في مسار معنون بالمحتوى، يتم حساب جزء الهاش من محتويات المسار. هذا يسمح بتحقق محتويات المسار دون أي معلومات إضافية مثل التوقيعات. هذا يعني أن أمرًا مثل

# nix store build /nix/store/5skmmcb9svys5lj3kbsrjg7vf2irid63-hello-2.10 \
    --substituters https://my-cache.example.org

سينجح حتى لو كان مخزن الثنائيات https://my-cache.example.org لا يقدم أي توقيعات.

الخيارات

•
--from store-uri
عنوان URL لمخزن Nix المصدر.
•
--json
إنتاج المخرجات بتنسيق JSON، مناسب للاستهلاك بواسطة برنامج آخر.
•
--stdin
قراءة elements من الإدخال القياسي. لا يتم تطبيق element افتراضي.
•
--to store-uri
عنوان URL لمخزن Nix الوجهة.

خيارات التقييم الشائعة

•
--arg name expr
تمرير القيمة expr كوسيط name لدوال Nix.
•
--arg-from-file name path
تمرير محتويات الملف path كوسيط name لدوال Nix.
•
--arg-from-stdin name
تمرير محتويات الإدخال القياسي كوسيط name لدوال Nix.
•
--argstr name string
تمرير السلسلة النصية string كوسيط name لدوال Nix.
•
--debugger
بدء بيئة تفاعلية إذا فشل التقييم.
•
--eval-store store-url
عنوان URL لمخزن Nix المستخدم للتقييم، أي لتخزين الاشتقاقات (.drv files) والمدخلات المشار إليها بها.
•
--impure
السماح بالوصول إلى المسارات والمستودعات القابلة للتغيير.
•
--include / -I path
إضافة path إلى إدخالات مسار البحث المستخدمة لحل مسارات البحث
يمكن إعطاء هذا الخيار عدة مرات.
المسارات المضافة عبر -I لها الأسبقية على إعداد التكوين nix-path و متغير البيئة NIX_PATH .
•
--override-flake original-ref resolved-ref
تجاوز سجلات الـ flake، وإعادة توجيه original-ref إلى resolved-ref.

خيارات شائعة متعلقة بالـ Flake

•
--commit-lock-file
تثبيت التغييرات في ملف القفل الخاص بالـ flake.
•
--inputs-from flake-url
استخدام مدخلات الـ flake المحدد كإدخالات سجل.
•
--no-registries
عدم السماح بالبحث في سجلات الـ flake.
تم إيقافه
استخدم --no-use-registries بدلاً من ذلك.
•
--no-update-lock-file
عدم السماح بأي تحديثات لملف القفل الخاص بالـ flake.
•
--no-write-lock-file
عدم كتابة ملف القفل الجديد الذي تم إنشاؤه بواسطة الـ flake.
•
--output-lock-file flake-lock-path
