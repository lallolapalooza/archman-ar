jdeprscan-openjdk25(1)

الحزمة: jdk-openjdk

التراخيص: LicenseRef-Java

JDEPRSCAN(1) أوامر JDK JDEPRSCAN(1)

الاسم

jdeprscan - أداة تحليل ثابتة تقوم بفحص ملف jar (أو تجميع آخر من ملفات الفئة) لاستخدام عناصر API المهملة

الملخص

jdeprscan [خيارات] {دليل|jar|فئة}

خيارات
راجع خيارات أمر jdeprscan
دليل|jar|فئة
jdeprscan تقوم الأداة بفحص كل وسيط للعناصر المهملة. يمكن أن تكون الوسائط:
•
دليل: دليل
•
jar: ملف JAR
•
فئة: اسم فئة أو ملف فئة

يجب أن يستخدم اسم الفئة النقطة ( .) كفاصل. على سبيل المثال:

java.lang.Thread

بالنسبة للفئات المتداخلة، يجب استخدام حرف الفاصل علامة الدولار ( $). على سبيل المثال:

java.lang.Thread$State

يمكن أيضًا تسمية ملف الفئة. على سبيل المثال:

build/classes/java/lang/Thread$State.class

الوصف

أداة jdeprscan هي أداة تحليل ثابتة توفرها JDK لفحص ملف JAR أو أي تجميع آخر من ملفات الفئة بحثًا عن استخدامات عناصر API المهملة. عناصر API المهملة التي تحددها أداة jdeprscan هي فقط تلك المعرفة بواسطة Java SE. عناصر API المهملة التي تعرفها مكتبات الطرف الثالث غير المبلغ عنها.

لفحص ملف JAR أو مجموعة من ملفات الفئة، يجب عليك أولاً التأكد من وجود جميع الفئات التي تعتمد عليها الفئات المفحوصة في مسار الفئة. قم بتعيين مسار الفئة باستخدام الخيار --class-path الموضح في خيارات أمر jdeprscan. عادةً، ستستخدم نفس مسار الفئة الذي تستخدمه عند استدعاء تطبيقك.

إذا لم تتمكن أداة jdeprscan من العثور على جميع الفئات التابعة، فستقوم بإنشاء رسالة خطأ لكل فئة مفقودة. عادةً ما تكون رسائل الخطأ هذه بالشكل:

error: cannot find class ...

إذا حدثت هذه الأخطاء، فيجب عليك تعديل مسار الفئة بحيث يتضمن جميع الفئات التابعة.

خيارات أمر jdeprscan

الخيارات التالية متاحة:

--class-path مسار
يوفر مسار بحث لحل الفئات التابعة.

مسار يمكن أن يكون مسار بحث يتكون من دليل واحد أو أكثر مفصولة بفاصل المسار الخاص بالنظام. على سبيل المثال:

•
Linux و macOS:

--class-path /some/directory:/another/different/dir

ملاحظة:

في Windows، استخدم فاصلة منقوطة ( ;) كفاصل بدلاً من نقطتين ( :).

•
Windows:

--class-path \some\directory;\another\different\dir

--for-removal
يحد الفحص أو القائمة بالعناصر المهملة للإزالة. لا يمكن استخدامه مع قيمة إصدار 6 أو 7 أو 8.
--full-version
يطبع سلسلة الإصدار الكامل للأداة.
--help أو -h
يطبع رسالة مساعدة كاملة.
--list أو -l
يطبع مجموعة عناصر API المهملة. لا يتم إجراء أي فحص، لذلك لا ينبغي تقديم أي وسائط دليل أو jar أو فئة.
--release 6|7|8|9
يحدد إصدار Java SE الذي يوفر مجموعة عناصر API المهملة للفحص.
--verbose أو -v
يمكّن إخراج رسالة إضافية أثناء المعالجة.
--version
يطبع سلسلة الإصدار المختصرة للأداة.

مثال على مخرجات jdeprscan

سيكون اسم ملف JAR لهذه المكتبة شيئًا مشابهًا لـ commons-math3-3.6.1.jar. لفحص ملف JAR هذا بحثًا عن استخدام عناصر API المهملة، قم بتشغيل الأمر التالي:

jdeprscan commons-math3-3.6.1.jar

ينتج هذا الأمر عدة أسطر من المخرجات. على سبيل المثال، قد يكون أحد أسطر المخرجات:

class org/apache/commons/math3/util/MathUtils uses deprecated method java/lang/Double::<init>(D)V

ملاحظة:

يتم تحديد اسم الفئة باستخدام الاسم الثنائي المفصول بشرطة مائلة كما هو موضح في JVMS 4.2.1. هذا هو الشكل المستخدم داخليًا في ملفات الفئة.

عنصر API المهمل الذي يستخدمه هو طريقة في الفئة java.lang.Double.

اسم الطريقة المهملة هو <init>، وهو اسم خاص يعني أن الطريقة هي في الواقع مُنشئ. اسم خاص آخر هو <clinit>، والذي يشير إلى مُهيئ ثابت للفئة.

تُدرج الطرق الأخرى ببساطة حسب اسم طريقتها. يتبع اسم الطريقة قائمة الوسائط ونوع الإرجاع:

(D)V

يشير هذا إلى أنه يأخذ قيمة double واحدة فقط (بدائية) ويعيد void. يمكن أن تصبح أنواع الوسائط وأنواع الإرجاع مشفرة. على سبيل المثال، قد يكون سطر آخر من المخرجات:

class org/apache/commons/math3/util/Precision uses deprecated method java/math/BigDecimal::setScale(II)Ljava/math/BigDecimal;

في سطر المخرجات هذا، توجد الطريقة المهملة في الفئة java.math.BigDecimal، والطريقة هي setScale(). في هذه الحالة، يعني (II) أنه يأخذ وسيطتين int. يشير Ljava/math/BigDecimal; بعد الأقواس إلى أنه يعيد مرجعًا إلى java.math.BigDecimal.

يمكن أن يكون تحليل jdeprscan محددًا للإصدار

يمكنك استخدام jdeprscan بالنسبة للإصدارات الثلاثة السابقة من JDK. على سبيل المثال، إذا كنت تستخدم JDK 9، فيمكنك التحقق مقابل JDK 8 أو 7 أو 6.

كمثال، انظر مقتطف الشفرة هذا:

public class Deprecations {
   SecurityManager sm = new RMISecurityManager();    // deprecated in 8
   Boolean b2 = new Boolean(true);          // deprecated in 9
}

الفئة الكاملة تتجمع بدون تحذيرات في JDK 7.

إذا قمت بتشغيل jdeprscan على نظام يستخدم JDK 9، فسترى:

$ jdeprscan --class-path classes --release 7 example.Deprecations
(no output)

قم بتشغيل jdeprscan بقيمة إصدار 8:

$ jdeprscan --class-path classes --release 8 example.Deprecations
class example/Deprecations uses type java/rmi/RMISecurityManager deprecated
class example/Deprecations uses method in type java/rmi/RMISecurityManager deprecated

قم بتشغيل jdeprscan على JDK 9:

$ jde

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.
