الخيارات التي تم إيقافها، وتم إهمالها، وتمت إزالتها:

•
خيارات Java المهملة: مقبولة ويتم التصرف بموجبها - يتم إصدار تحذير عند استخدامها.
•
خيارات Java التي تم إيقافها: مقبولة ولكن تم تجاهلها - يتم إصدار تحذير عند استخدامها.
•
خيارات Java التي تمت إزالتها: تمت إزالتها - استخدامها يؤدي إلى حدوث خطأ.

خيارات قياسية لـ Java

هذه هي الخيارات الأكثر شيوعًا التي تدعمها جميع تطبيقات JVM.

ملاحظة: لتحديد وسيط لوسيط طويل، يمكنك استخدام --name=value أو --name value.

-agentlib:libname[=options]
يقوم بتحميل مكتبة وكيل أصلية محددة. بعد اسم المكتبة، يمكن استخدام قائمة مفصولة بفواصل من الخيارات الخاصة بالمكتبة.
•
Linux و macOS: إذا تم تحديد الخيار -agentlib:foo، فإن JVM تحاول تحميل المكتبة المسماة libfoo.so في الموقع المحدد بواسطة متغير النظام LD_LIBRARY_PATH (على macOS هذا المتغير هو DYLD_LIBRARY_PATH).
•
Windows: إذا تم تحديد الخيار -agentlib:foo ، فإن JVM تحاول تحميل المكتبة المسماة foo.dll في الموقع المحدد بواسطة متغير النظام PATH.

يوضح المثال التالي كيفية تحميل مكتبة بروتوكول سلك تصحيح Java (JDWP) والاستماع لاتصال المقبس على المنفذ 8000، وتعليق JVM قبل تحميل الفئة الرئيسية:

-agentlib:jdwp=transport=dt_socket,server=y,address=8000

-agentpath:pathname[=options]
يقوم بتحميل مكتبة الوكيل الأصلية المحددة بالمسار المطلق. هذا الخيار يعادل -agentlib ولكنه يستخدم المسار الكامل واسم ملف المكتبة.
--class-path classpath, -classpath classpath, أو -cp classpath
قائمة مفصولة بفاصلة منقوطة ( ;) من الدلائل، وأرشيفات JAR، وأرشيفات ZIP للبحث عن ملفات الفئة.

تحديد classpath يلغي أي إعداد لمتغير البيئة CLASSPATH. إذا لم يتم استخدام خيار مسار الفئة ولم يتم تعيين classpath، فإن مسار فئة المستخدم يتكون من الدليل الحالي (.).

كميزة خاصة، يعتبر عنصر مسار الفئة الذي يحتوي على اسم أساسي للنجمة (*) مكافئًا لتحديد قائمة بجميع الملفات في الدليل بامتداد .jar أو .JAR. لا يمكن لبرنامج Java التمييز بين الاستدعاءين. على سبيل المثال، إذا كان الدليل mydir يحتوي على a.jar و b.JAR، فإن عنصر مسار الفئة mydir/* يتم توسيعه إلى A.jar:b.JAR، باستثناء أن ترتيب ملفات JAR غير محدد. يتم تضمين جميع ملفات .jar في الدليل المحدد، حتى المخفية، في القائمة. عنصر مسار الفئة الذي يتكون من نجمة (*) يتوسع إلى قائمة بجميع ملفات JAR في الدليل الحالي. متغير البيئة CLASSPATH، حيثما تم تعريفه، يتم توسيعه بشكل مشابه. أي توسيع لأحرف البدل في مسار الفئة يحدث قبل بدء تشغيل آلة Java الافتراضية. لا ترى برامج Java أبدًا أحرف البدل التي لم يتم توسيعها إلا عن طريق الاستعلام عن البيئة، مثل استدعاء System.getenv("CLASSPATH").

--disable-@files
يمكن استخدامه في أي مكان في سطر الأوامر، بما في ذلك في ملف وسيط، لمنع المزيد من توسيع @filename. يوقف هذا الخيار توسيع ملفات الوسائط @- بعد الخيار.
--enable-preview
يسمح للفئات بالاعتماد على **الميزات التجريبية** [https://docs.oracle.com/en/java/javase/12/language/index.html#JSLAN-GUID-5A82FE0E-0CA4-4F1F-B075-564874FE2823] للإصدار.
--module-path modulepath... أو -p modulepath
قائمة مفصولة بفاصلة منقوطة ( ;) من الدلائل حيث كل دليل هو دليل للوحدات.
--upgrade-module-path modulepath...
قائمة مفصولة بفاصلة منقوطة ( ;) من الدلائل حيث كل دليل هو دليل للوحدات التي تحل محل الوحدات القابلة للترقية في صورة التشغيل.
--add-modules module[,module...]
يحدد الوحدات الجذرية التي يجب حلها بالإضافة إلى الوحدة الأولية. module يمكن أن تكون أيضًا ALL-DEFAULT، ALL-SYSTEM، و ALL-MODULE-PATH.
--list-modules
يسرد الوحدات الملحوظة ويخرج.
-d module_name أو --describe-module module_name
يصف الوحدة المحددة ويخرج.
--dry-run
يقوم بإنشاء VM ولكنه لا ينفذ الطريقة الرئيسية. قد يكون هذا الخيار --dry-run مفيدًا للتحقق من صحة خيارات سطر الأوامر مثل تكوين نظام الوحدة.
--validate-modules
يتحقق من صحة جميع الوحدات ويخرج. هذا الخيار مفيد للعثور على التعارضات والأخطاء الأخرى مع الوحدات الموجودة في مسار الوحدة.
-Dproperty=value
يقوم بتعيين قيمة خاصية النظام. المتغير property هو سلسلة نصية بدون مسافات تمثل اسم الخاصية. المتغير value هو سلسلة نصية تمثل قيمة الخاصية. إذا كانت value سلسلة نصية تحتوي على مسافات، فقم بإحاطتها بعلامات اقتباس (على سبيل المثال -Dfoo="foo bar").
-disableassertions[:[packagename]...|:classname] أو -da[:[packagename]...|:classname]
يعطل التأكيدات. افتراضيًا، يتم تعطيل التأكيدات في جميع الحزم والفئات. بدون وسائط، -disableassertions (-da) يعطل التأكيدات في جميع الحزم والفئات. مع وسيط packagename الذي ينتهي بـ ...، فإن المفتاح يعطل التأكيدات في الحزمة المحددة وأي حزم فرعية. إذا كان الوسيط هو ببساطة ...، فإن المفتاح يعطل التأكيدات في الحزمة غير المسماة في دليل العمل الحالي. مع وسيط classname، يقوم المفتاح بتعطيل التأكيدات في الفئة المحددة.

ينطبق الخيار -disableassertions (-da) على جميع محملات الفئات وعلى فئات النظام (التي ليس لها محمل فئات). هناك استثناء واحد لهذه القاعدة: إذا تم توفير الخيار بدون وسائط، فإنه لا ينطبق على فئات النظام. هذا يجعل من السهل تعطيل التأكيدات في جميع الفئات باستثناء فئات النظام. الخيار -disablesystemassertions يمكّنك من تعطيل التأكيدات في جميع فئات النظام. لتمكين التأكيدات صراحةً في حزم أو فئات معينة، استخدم الخيار -enableassertions (-ea). يمكن استخدام كلا الخيارين في نفس الوقت. على سبيل المثال، لتشغيل تطبيق MyClass مع تمكين التأكيدات في الحزمة com.wombat.fruitbat (وأي حزم فرعية) ولكن تعطيلها في الفئة com.wombat.fruitbat.Brickbat، استخدم الأمر التالي:

java -ea:com.wombat.fruitbat... -da:com.wombat.fruitbat.Brickbat MyClass

-disablesystemassertions أو -dsa
يعطل التأكيدات في جميع فئات النظام.
-enableassertions[:[packagename]...|:classname] أو -ea[:[packagename]...|:classname]
يمكّن التأكيدات. افتراضيًا، يتم تعطيل التأكيدات في جميع الحزم والفئات. مع n
-XX:InitialRAMPercentage=percent
يحدد النسبة المئوية لمقدار الذاكرة الأولي الذي سيستخدمه وقت تشغيل Java (JVM) لمكدس Java قبل تطبيق الاستدلالات الإرغومية كنسبة مئوية من الحد الأقصى المحدد على النحو الموضح في -XX:MaxRAM option. القيمة الافتراضية هي 1.5625 بالمائة.

يوضح المثال التالي كيفية تعيين النسبة المئوية للكمية الأولية للذاكرة المستخدمة لمكدس Java:

-XX:InitialRAMPercentage=5

-XX:InitialSurvivorRatio=ratio
يحدد نسبة مساحة الناجين الأولية التي يستخدمها جامع القمامة للإنتاجية (الذي يتم تمكينه بواسطة -XX:+UseParallelGC option). يتم تمكين التحجيم التكيفي افتراضيًا مع جامع القمامة للإنتاجية باستخدام -XX:+UseParallelGC option، ويتم تغيير حجم مساحة الناجين وفقًا لسلوك التطبيق، بدءًا من القيمة الأولية. إذا تم تعطيل التحجيم التكيفي (باستخدام -XX:-UseAdaptiveSizePolicy option)، فيجب استخدام -XX:SurvivorRatio option لتحديد حجم مساحة الناجين طوال فترة تنفيذ التطبيق.

يمكن استخدام الصيغة التالية لحساب الحجم الأولي لمساحة الناجين (S) بناءً على حجم الجيل الشاب (Y)، ونسبة مساحة الناجين الأولية (R):

S=Y/(R+2)

يشير الرقم 2 في المعادلة إلى مساحتي ناجين. كلما زادت القيمة المحددة كنسبة مساحة الناجين الأولية، قل حجم مساحة الناجين الأولي.

افتراضيًا، يتم تعيين نسبة مساحة الناجين الأولية إلى 8. إذا تم استخدام القيمة الافتراضية لحجم مساحة الجيل الشاب (2 ميغابايت)، فإن الحجم الأولي لمساحة الناجين هو 0.2 ميغابايت.

يوضح المثال التالي كيفية تعيين نسبة مساحة الناجين الأولية إلى 4:

-XX:InitialSurvivorRatio=4

-XX:InitiatingHeapOccupancyPercent=percent
يحدد النسبة المئوية لاشغال الجيل القديم (من 0 إلى 100) التي تبدأ عندها دورات وضع العلامات المتزامنة الأولى لجامع القمامة G1.

افتراضيًا، يتم تعيين القيمة المبادرة إلى 45٪. تشير القيمة 0 إلى دورات GC متزامنة مستمرة من البداية حتى يقوم G1 بتعيين هذه القيمة بشكل تكيفي.

انظر أيضًا إلى الخيارات -XX:G1UseAdaptiveIHOP و -XX:G1AdaptiveIHOPNumInitialSamples.

يوضح المثال التالي كيفية تعيين اشغال المكدس المبادرة إلى 75٪:

-XX:InitiatingHeapOccupancyPercent=75

-XX:MaxGCPauseMillis=time
يحدد هدفًا لوقت توقف GC الأقصى (بالمللي ثانية). هذا هدف غير صارم، وسيبذل وقت تشغيل Java قصارى جهده لتحقيقه. القيمة المحددة لا تتكيف مع حجم المكدس الخاص بك. افتراضيًا، بالنسبة لـ G1، يكون هدف وقت التوقف الأقصى 200 مللي ثانية. جامعات الأجيال الأخرى لا تستخدم هدف وقت التوقف افتراضيًا.

يوضح المثال التالي كيفية تعيين هدف وقت التوقف الأقصى إلى 500 مللي ثانية:

-XX:MaxGCPauseMillis=500

-XX:MaxHeapSize=size
يحدد الحد الأقصى لحجم (بالبايت) مجمع تخصيص الذاكرة. يجب أن تكون هذه القيمة مضاعفًا لـ 1024 وأكبر من 2 ميغابايت. قم بإلحاق الحرف k أو K للإشارة إلى الكيلوبايت، m أو M للإشارة إلى الميجابايت، أو g أو G للإشارة إلى الجيجابايت. يتم اختيار القيمة الافتراضية في وقت التشغيل بناءً على تكوين النظام. بالنسبة لنشره الخادم، غالبًا ما يتم تعيين الخيارين -XX:InitialHeapSize و -XX:MaxHeapSize إلى نفس القيمة.

توضح الأمثلة التالية كيفية تعيين الحد الأقصى المسموح به لحجم الذاكرة المخصصة إلى 80 ميغابايت باستخدام وحدات مختلفة:


-XX:MaxHeapSize=83886080
-XX:MaxHeapSize=81920k
-XX:MaxHeapSize=80m

الخيار -XX:MaxHeapSize يعادل -Xmx.

-XX:MaxHeapFreeRatio=percent
يحدد النسبة المئوية القصوى المسموح بها لمساحة المكدس الخالية (من 0 إلى 100) بعد حدث GC. إذا توسعت المساحة الحرة للمكدس فوق هذه القيمة، يتم تقليص المكدس. افتراضيًا، يتم تعيين هذه القيمة إلى 70٪.

قلل حجم مكدس Java عن طريق خفض قيم المعاملين MaxHeapFreeRatio (القيمة الافتراضية هي 70٪) و MinHeapFreeRatio (القيمة الافتراضية هي 40٪) باستخدام خيارات سطر الأوامر -XX:MaxHeapFreeRatio و -XX:MinHeapFreeRatio. أدى خفض MaxHeapFreeRatio إلى 10٪ و MinHeapFreeRatio إلى 5٪ بنجاح إلى تقليل حجم المكدس دون الكثير من تدهور الأداء؛ ومع ذلك، قد تختلف النتائج بشكل كبير اعتمادًا على تطبيقك. جرب قيمًا مختلفة لهذه المعلمات حتى تصبح أقل ما يمكن مع الاستمرار في الحفاظ على الأداء المقبول.

-XX:MaxHeapFreeRatio=10 -XX:MinHeapFreeRatio=5

يجب على العملاء الذين يحاولون الاحتفاظ بالمكدس صغيرًا أيضًا إضافة الخيار -XX:-ShrinkHeapInSteps. انظر أمثلة ضبط الأداء لوصف استخدام هذا الخيار للاحتفاظ بمكدس Java صغيرًا عن طريق تقليل البصمة الديناميكية للتطبيقات المضمنة.

-XX:MaxMetaspaceSize=size
يحدد الحد الأقصى لمقدار الذاكرة الأصلية التي يمكن تخصيصها لبيانات التعريف الفئة. افتراضيًا، لا يتم تحديد حجم. يعتمد مقدار بيانات التعريف للتطبيق على التطبيق نفسه والتطبيقات الأخرى قيد التشغيل ومقدار الذاكرة المتاحة على النظام.

يوضح المثال التالي كيفية تعيين الحد الأقصى لحجم بيانات تعريف الفئة إلى 256 ميغابايت:

-XX:MaxMetaspaceSize=256m

-XX:MaxNewSize=size
يحدد الحد الأقصى لحجم (بالبايت) لمكدس الجيل الشاب (الحضانة). يتم تعيين القيمة الافتراضية بشكل إرغومي.
-XX:MaxRAM=size
يحدد الحد الأقصى لمقدار الذاكرة التي قد يستخدمها وقت تشغيل Java لمكدس Java قبل تطبيق الاستدلالات الإرغومية. القيمة الافتراضية هي الحد الأقصى لمقدار الذاكرة المتاحة لعملية JVM أو 128 جيجابايت، أيهما أقل.

الحد الأقصى لمقدار الذاكرة المتاحة لعملية JVM هو الحد الأدنى من الذاكرة الفعلية للجهاز وأي قيود يفرضها البيئة (على سبيل المثال، حاوية).

يؤدي تحديد هذا الخيار إلى تعطيل الاستخدام التلقائي لمؤشرات الأغراض المضغوطة (compressed oops) إذا كان المجموع الناتج عن هذا الخيار والخيارات الأخرى التي تؤثر على الحد الأقصى لمقدار الذاكرة أكبر من نطاق الذاكرة التي يمكن معالجتها بواسطة مؤشرات الأغراض المضغوطة. انظر -XX:UseCompressedOops لمزيد من المعلومات حول مؤشرات الأغراض المضغوطة.

يوضح المثال التالي كيفية تعيين الحد الأقصى لمقدار الذاكرة المتاحة لتحديد حجم مكدس Java إلى 2 جيجابايت:

-XX:MaxRAM=2G

-XX:MaxRAMPercentage=percent
يحدد الحد الأقصى لمقدار الذاكرة التي قد يستخدمها وقت تشغيل Java لمكدس Java قبل تطبيق الاستدلالات الإرغومية كنسبة مئوية من الحد الأقصى المحدد على النحو الموضح في -XX:MaxRAM option. القيمة الافتراضية هي 25 بالمائة.

يؤدي تحديد هذا الخيار إلى تعطيل الاستخدام التلقائي لمؤشرات الأغراض المضغوطة (compressed oops) إذا كان المجموع الناتج عن هذا الخيار والخيارات الأخرى التي تؤثر على الحد الأقصى لمقدار الذاكرة أكبر من نطاق الذاكرة التي يمكن معالجتها بواسطة مؤشرات الأغراض المضغوطة. انظر -XX:UseCompressedOops لمزيد من المعلومات حول مؤشرات الأغراض المضغوطة.

يوضح المثال التالي كيفية تعيين النسبة المئوية للحد الأقصى لمقدار الذاكرة المستخدمة لمكدس Java:

-XX:MaxRAMPercentage=75

-XX:MinRAMPercentage=percent
يحدد الحد الأقصى لمقدار الذاكرة التي قد يستخدمها وقت تشغيل Java لمكدس Java قبل تطبيق الاستدلالات الإرغومية كنسبة مئوية من الحد الأقصى المحدد على النحو الموضح في -XX:MaxRAM option للمكدسات الصغيرة. المكدس الصغير هو مكدس بحجم 125 ميغابايت تقريبًا. القيمة الافتراضية هي 50 بالمائة.

يوضح المثال التالي كيفية تعيين النسبة المئوية للحد الأقصى لمقدار الذاكرة المستخدمة لمكدس Java للمكدسات الصغيرة:

-XX:MinRAMPercentage=75

-XX:MaxTenuringThreshold=threshold
يحدد الحد الأقصى لعتبة الاستحواذ (tenuring threshold) للاستخدام في التحجيم التكيفي لـ GC. القيمة القصوى هي 15. القيمة الافتراضية هي 15 لجامع الإنتاجية (parallel collector).

java -XX:SharedArchiveFile=hello.jsa -cp hello.jar -Xlog:class+load test.Hello

يجب أن يحتوي ناتج هذا الأمر على النص التالي:

[info][class,load] test.Hello source: shared objects file

إنشاء ملف أرشيف CDS ديناميكي باستخدام -XX:SharedArchiveFile

تتمثل مزايا أرشيفات CDS الديناميكية في:

•
عادةً ما تستخدم مساحة أقل على القرص، حيث لا تحتاج إلى تخزين الفئات الموجودة بالفعل في الأرشيف الثابت.
•
يتم إنشاؤها بخطوة أقل من الأرشيف الثابت المقابل.

تنشئ الخطوات التالية ملف أرشيف CDS ديناميكي يحتوي على الفئات التي يستخدمها تطبيق test.Hello، باستثناء تلك الموجودة بالفعل في أرشيف CDS الافتراضي.

1.
قم بإنشاء أرشيف CDS ديناميكي، يسمى hello.jsa، يحتوي على جميع الفئات في hello.jar التي تم تحميلها بواسطة التطبيق test.Hello:

java -XX:ArchiveClassesAtExit=hello.jsa -cp hello.jar Hello

2.
قم بتشغيل التطبيق test.Hello باستخدام الأرشيف المشترك hello.jsa:

java -XX:SharedArchiveFile=hello.jsa -cp hello.jar test.Hello

3.
اختياري كرر الخطوة 4 من القسم السابق للتحقق من أن التطبيق test.Hello يستخدم الفئة الموجودة في الأرشيف المشترك hello.jsa.

من الممكن أيضًا إنشاء أرشيف CDS ديناميكي بأرشيف CDS ثابت غير افتراضي. على سبيل المثال،

java -XX:SharedArchiveFile=base.jsa -XX:ArchiveClassesAtExit=hello.jsa -cp hello.jar Hello

لتشغيل التطبيق باستخدام هذا الأرشيف CDS الديناميكي:

java -XX:SharedArchiveFile=base.jsa:hello.jsa -cp hello.jar Hello

(على نظام Windows، يجب استبدال المحدد : أعلاه بـ ;)

كما ذكرنا أعلاه، يمكن تخطي اسم الأرشيف الثابت:

java -XX:SharedArchiveFile=hello.jsa -cp hello.jar Hello

إنشاء ملفات أرشيف CDS باستخدام jcmd

يتطلب القسمان السابقان منك تعديل برنامج بدء تشغيل التطبيق لإنشاء أرشيف CDS. قد يكون هذا صعبًا في بعض الأحيان، على سبيل المثال، إذا تم إعداد مسار فئات التطبيق بواسطة روتينات معقدة.

يوفر الأمر jcmd VM.cds طريقة أقل تدخلاً لإنشاء أرشيف CDS عن طريق الاتصال بعملية JVM قيد التشغيل. يمكنك إنشاء إما أرشيف ثابت:

jcmd <pid> VM.cds static_dump my_static_archive.jsa

أو أرشيف ديناميكي:

jcmd <pid> VM.cds dynamic_dump my_dynamic_archive.jsa

لاستخدام ملف الأرشيف الناتج في تشغيل لاحق للتطبيق دون تعديل برنامج بدء تشغيل التطبيق، يمكنك استخدام التقنية التالية:

env JAVA_TOOL_OPTIONS=-XX:SharedArchiveFile=my_static_archive.jsa bash app_start.sh

ملاحظة: لاستخدام jcmd <pid> VM.cds dynamic_dump، يجب بدء تشغيل عملية JVM التي يحددها <pid> باستخدام -XX:+RecordDynamicDumpInfo، والتي يمكن تمريرها أيضًا إلى برنامج بدء تشغيل التطبيق باستخدام نفس التقنية:

env JAVA_TOOL_OPTIONS=-XX:+RecordDynamicDumpInfo bash app_start.sh

قيود على مسار الفئات ومسار الوحدات

•
لا يمكن لمسار الفئات (-classpath و -Xbootclasspath/a) ولا لمسار الوحدات (--module-path) أن يحتوي على أدلة غير فارغة.
•
فقط ملفات JAR الوحدات مدعومة في --module-path. الوحدات المفككة غير مدعومة.
•
يجب أن يكون مسار الفئات المستخدم في وقت إنشاء الأرشيف هو نفس مسار الفئات المستخدم في وقت التشغيل (أو بادئة له). (لا يوجد مثل هذا المتطلب لمسار الوحدات.)
•
لا يمكن تحميل أرشيف CDS إذا تم تعديل أي من ملفات JAR في مسار الفئات أو مسار الوحدات بعد إنشاء الأرشيف.
•
إذا تم تحديد أي من خيارات VM --upgrade-module-path، --patch-module أو --limit-modules، يتم تعطيل CDS. هذا يعني أن JVM ستنفذ دون تحميل أي أرشيفات CDS. بالإضافة إلى ذلك، إذا حاولت إنشاء أرشيف CDS مع تحديد أي من هذه الخيارات الثلاثة، فسوف تصدر JVM خطأ.

أمثلة على ضبط الأداء

يمكنك استخدام خيارات تشغيل Java المتقدمة لتحسين أداء تطبيقاتك.

الضبط لتحقيق إنتاجية أعلى

استخدم الأوامر والخيارات المتقدمة التالية لتحقيق أداء إنتاجية أعلى لتطبيقك:

java -server -XX:+UseParallelGC -XX:+UseLargePages -Xmn10g  -Xms26g -Xmx26g

الضبط لتحقيق وقت استجابة أقل

استخدم الأوامر والخيارات المتقدمة التالية لتحقيق أوقات استجابة أقل لتطبيقك:

java -XX:+UseG1GC -XX:MaxGCPauseMillis=100

الحفاظ على حجم كومة Java صغيرًا وتقليل البصمة الديناميكية لـ

التطبيقات المضمنة

استخدم خيارات التشغيل المتقدمة التالية للحفاظ على حجم كومة Java صغيرًا وتقليل البصمة الديناميكية للتطبيقات المضمنة:

-XX:MaxHeapFreeRatio=10 -XX:MinHeapFreeRatio=5

ملاحظة: القيم الافتراضية لهذين الخيارين هي 70% و 40% على التوالي. نظرًا لإمكانية حدوث تدهور في الأداء عند استخدام هذه الإعدادات الصغيرة، يجب عليك تحسين البصمة الصغيرة عن طريق تقليل هذه الإعدادات قدر الإمكان دون التسبب في تدهور غير مقبول في الأداء.

حالة الخروج

عادةً ما تُرجع القيم التالية بواسطة المشغل عند استدعائه بمعاملات غير صحيحة، أو أخطاء جسيمة، أو استثناءات أثارتها JVM. ومع ذلك، قد يختار تطبيق Java إرجاع أي قيمة باستخدام استدعاء API System.exit(exitValue). القيم هي:

•
0: اكتمال ناجح
•
>0: حدث خطأ
