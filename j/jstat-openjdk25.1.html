JSTAT(1) أوامر JDK JSTAT(1)

الاسم

jstat - مراقبة إحصائيات JVM

الملخص

ملاحظة: هذا الأمر تجريبي وغير مدعوم.

jstat generalOptions

jstat outputOptions [-t] [-h lines] vmid [interval [count]]

generalOptions
خيار واحد عام لسطر الأوامر. انظر General Options.
outputOptions
خيار تم الإبلاغ عنه بواسطة الخيار -options. خيار واحد أو أكثر من خيارات الإخراج تتكون من statOption واحد، بالإضافة إلى أي من الخيارات -t و -h و -J. انظر Output Options for the jstat Command.
-t
يعرض عمود طابع زمني كأول عمود في الإخراج. الطابع الزمني هو الوقت المنقضي منذ وقت بدء تشغيل JVM المستهدفة.
-h n
يعرض عنوان عمود كل n عينة (صفوف إخراج)، حيث n هو عدد صحيح موجب. القيمة الافتراضية هي 0، والتي تعرض عنوان العمود للصف الأول من البيانات.
vmid
معرف الآلة الافتراضية، وهو سلسلة نصية تشير إلى JVM المستهدفة. انظر Virtual Machine Identifier.
interval
فترة أخذ العينات بالوحدات المحددة، ثواني (s) أو ملي ثانية (ms). الوحدات الافتراضية هي ملي ثانية. يجب أن يكون عددًا صحيحًا موجبًا. عند تحديده، ينتج الأمر jstat إخراجه في كل فترة.
count
عدد العينات المراد عرضها. القيمة الافتراضية هي لا نهائي، مما يتسبب في أن يعرض الأمر jstat الإحصائيات حتى تنتهي JVM المستهدفة أو يتم إنهاء الأمر jstat. يجب أن تكون هذه القيمة عددًا صحيحًا موجبًا.

الوصف

يعرض الأمر jstat إحصائيات الأداء لـ Java HotSpot VM المزودة بأدوات. يتم تحديد JVM المستهدفة بواسطة معرف الآلة الافتراضية الخاص بها، أو خيار vmid.

يدعم الأمر jstat نوعين من الخيارات، الخيارات العامة والخيارات الإخراجية. تؤدي الخيارات العامة إلى أن يعرض الأمر jstat معلومات استخدام وإصدار بسيطة. تحدد خيارات الإخراج محتوى وتنسيق الإخراج الإحصائي.

جميع الخيارات ووظائفها تخضع للتغيير أو الإزالة في الإصدارات المستقبلية.

الخيارات العامة

إذا قمت بتحديد أحد الخيارات العامة، فلا يمكنك تحديد أي خيار أو معلمة أخرى.

-help
يعرض رسالة مساعدة.
-options
يعرض قائمة بالخيارات الثابتة. انظر Output Options for the jstat Command.

خيارات الإخراج لأمر jstat

إذا لم تحدد خيارًا عامًا، فيمكنك تحديد خيارات الإخراج. تحدد خيارات الإخراج محتوى وتنسيق إخراج الأمر jstat، وتتكون من statOption واحد، بالإضافة إلى أي من خيارات الإخراج الأخرى (-h و -t و -J). يجب أن يأتي statOption أولاً.

يتم تنسيق الإخراج كجدول، مع فصل الأعمدة بمسافات. صف عنوان مع عناوين يصف الأعمدة. استخدم الخيار -h لتعيين تردد عرض العنوان. أسماء رؤوس الأعمدة متسقة بين الخيارات المختلفة. بشكل عام، إذا قدم خياران عمودًا بنفس الاسم، فإن مصدر البيانات للعمودين هو نفسه.

استخدم الخيار -t لعرض عمود طابع زمني، يسمى Timestamp، كالعمود الأول في الإخراج. يحتوي عمود Timestamp على الوقت المنقضي، بالثواني، منذ بدء تشغيل JVM المستهدفة. يعتمد دقة الطابع الزمني على عوامل مختلفة وهو عرضة للتغيير بسبب تأخير جدولة الخيوط في الأنظمة ذات الحمل الثقيل.

استخدم معلمات الفاصل الزمني والعدد لتحديد عدد مرات عرض الأمر jstat، وعدد المرات التي يعرض فيها، على التوالي.

ملاحظة:

لا تكتب نصوصًا برمجية لتحليل إخراج الأمر jstat لأن التنسيق قد يتغير في الإصدارات المستقبلية. إذا قمت بكتابة نصوص برمجية تحلل إخراج الأمر jstat، فتوقع تعديلها للإصدارات المستقبلية لهذه الأداة.

-statOption
يحدد المعلومات الإحصائية التي يعرضها الأمر jstat. تسرد القائمة التالية الخيارات المتاحة. استخدم الخيار العام -options لعرض قائمة الخيارات لتثبيت النظام المحدد. انظر Stat Options and Output.

class: يعرض إحصائيات حول سلوك محمل الفئات.

compiler: يعرض إحصائيات حول سلوك مترجم Java HotSpot VM Just-in-Time.

gc: يعرض إحصائيات حول سلوك الكومة المجمعة للقمامة.

gccapacity: يعرض إحصائيات حول سعات الأجيال والمساحات المقابلة لها.

gccause: يعرض ملخصًا حول إحصائيات جمع القمامة (نفس -gcutil)، مع سبب أحداث جمع القمامة الأخيرة والحالية (عند الاقتضاء).

gcnew: يعرض إحصائيات حول سلوك الجيل الجديد.

gcnewcapacity: يعرض إحصائيات حول أحجام الأجيال الجديدة والمساحات المقابلة لها.

gcold: يعرض إحصائيات حول سلوك الجيل القديم وإحصائيات metaspace.

gcoldcapacity: يعرض إحصائيات حول أحجام الجيل القديم.

gcmetacapacity: يعرض إحصائيات حول أحجام metaspace.

gcutil: يعرض ملخصًا حول إحصائيات جمع القمامة.

printcompilation: يعرض إحصائيات طريقة تجميع Java HotSpot VM.

-JjavaOption
يمرر javaOption إلى مشغل تطبيق Java. على سبيل المثال، يضبط -J-Xms48m الذاكرة عند بدء التشغيل إلى 48 ميجابايت. للحصول على قائمة كاملة بالخيارات، انظر java.

خيارات الإحصائيات والإخراج

يلخصت المعلومات التالية الأعمدة التي يخرجها الأمر jstat لكل statOption.

-class option
إحصائيات محمل الفئات.

Loaded: عدد الفئات التي تم تحميلها.

Bytes: عدد الكيلوبايتات التي تم تحميلها.

Unloaded: عدد الفئات التي تم إلغاء تحميلها.

Bytes: عدد الكيلوبايتات التي تم إلغاء تحميلها.

Time: الوقت المستغرق في عمليات تحميل وإلغاء تحميل الفئات.

-compiler option
إحصائيات مترجم Java HotSpot VM Just-in-Time.

Compiled: عدد التجميعات

jstat(1) - Linux manual page

NAME

jstat — Provides a performance monitoring tool to observe the behavior of the Java Virtual Machine (JVM), and the Java application running on it.

SYNOPSIS

jstat [general options] [output options] [vmid[interval[count]]]

DESCRIPTION

The jstat command gathers and displays performance statistics from the Java Virtual Machine (JVM) running on a specified target system. This tool is useful for monitoring the behavior of a Java application and the JVM itself. The jstat command supports various monitoring options that provide insights into different aspects of the JVM's operation, such as garbage collection, compilation, and class loading.

The jstat command supports both local and remote JVM monitoring. For local monitoring, it attaches directly to the target JVM process. For remote monitoring, it uses the Remote Method Invocation (RMI) protocol to connect to a remote JVM.

The output of jstat is displayed in a tabular format, with columns representing different performance metrics. The specific columns displayed depend on the chosen output options.

GENERAL OPTIONS

-help
Displays help information for the jstat command.
-version
Displays version information for the jstat command.
-Joption
Passes the specified Java Virtual Machine (JVM) command-line option to the Java Virtual Machine, which is running the jstat command. For example, -J-Xmx256m sets the maximum heap size for the JVM running jstat to 256 megabytes.

OUTPUT OPTIONS FOR THE JSTAT COMMAND

The following options specify the type of statistics to be printed. The syntax for these options is consistent with the HotSpot -XX:+PrintCompilation option.

-class
Statistics related to class loading.
-compiler
Statistics related to the Java HotSpot VM Just-In-Time (JIT) compiler.
-gc
Garbage collection statistics.
-gccapacity
Garbage collection capacity statistics.
-gcdetails
Detailed garbage collection statistics.
-fullgc
Full garbage collection statistics.
-gcnew
Garbage collection statistics for the young generation.
-gcnewcapacity
Garbage collection new capacity statistics.
-gcold
Garbage collection statistics for the old generation.
-gcoldcapacity
Garbage collection old capacity statistics.
-gcutil
Garbage collection utility statistics.
-printcompilation
Displays Java HotSpot VM compilation information. This option is equivalent to the HotSpot -XX:+PrintCompilation option.

STAT OPTIONS AND OUTPUT

The jstat command prints statistics for the specified virtual machine. The jstat command supports the following options for statistics and output control:

-h[n]
This option prints the full header line after every n lines. The default value of n is 1.
-t
This option prints the timestamp of the beginning of the sample in the first column. The timestamp is the elapsed time in seconds since the start of the target JVM. The format for the timestamp field is consistent with the HotSpot -XX:+PrintCompilation option.
-Joption
Passes the specified Java Virtual Machine (JVM) command-line option to the Java Virtual Machine, which is running the jstat command. For example, -J-Xmx256m sets the maximum heap size for the JVM running jstat to 256 megabytes.
-option
Specifies the type of statistics to be printed. The option field is one of the options described in the OUTPUT OPTIONS FOR THE JSTAT COMMAND section. The option can also be a combination of these options. For example, -gc-t prints garbage collection statistics along with timestamps. The method name is the method within the specified class. The format for these two fields is consistent with the HotSpot -XX:+PrintCompilation option.

VIRTUAL MACHINE IDENTIFIER

The syntax of the vmid string corresponds to the syntax of a URI:

[protocol:][//]lvmid[@hostname[:port][/servername]

The syntax of the vmid string corresponds to the syntax of a URI. The vmid string can vary from a simple integer that represents a local JVM to a more complex construction that specifies a communications protocol, port number, and other implementation-specific values.

protocol
The communications protocol. If the protocol value is omitted and a host name isn't specified, then the default protocol is a platform-specific optimized local protocol. If the protocol value is omitted and a host name is specified, then the default protocol is rmi.
lvmid
The local virtual machine identifier for the target JVM. The lvmid is a platform-specific value that uniquely identifies a JVM on a system. The lvmid is the only required component of a virtual machine identifier. The lvmid is typically, but not necessarily, the operating system's process identifier for the target JVM process. You can use the jps command to determine the lvmid provided the JVM processes is not running in a separate docker instance. You can also determine the lvmid on Linux and macOS platforms with the ps command, and on Windows with the Windows Task Manager.
hostname
A host name or IP address that indicates the target host. If the hostname value is omitted, then the target host is the local host.
port
The default port for communicating with the remote server. If the hostname value is omitted or the protocol value specifies an optimized, local protocol, then the port value is ignored. Otherwise, treatment of the port parameter is implementation-specific. For the default rmi protocol, the port value indicates the port number for the rmiregistry on the remote host. If the port value is omitted and the protocol value indicates rmi, then the default rmiregistry port (1099) is used.
servername
The treatment of the servername parameter depends on implementation. For the optimized local protocol, this field is ignored. For the rmi protocol, it represents the name of the RMI remote object on the remote host.

EXAMPLES

This section presents some examples of monitoring a local JVM with an lvmid of 21891.

THE GCUTIL OPTION

This example attaches to lvmid 21891 and takes 7 samples at 250 millisecond intervals and displays the output as specified by the -gcutil option.

The output of this example shows that a young generation collection occurred between the third and fourth sample. The collection took 0.078 seconds and promoted objects from the eden space (E) to the old space (O), resulting in an increase of old space utilization from 66.80% to 68.19%. Before the collection, the survivor space was 97.02% utilized, but after this collection it's 91.03% utilized.

REPEAT THE COLUMN HEADER STRING

This example attaches to lvmid 21891 and takes samples at 250 millisecond intervals and displays the output as specified by -gcnew option. In addition, it uses the -h3 option to output the column header after every 3 lines of data.

In addition to showing the repeating header string, this example shows that between the second and third samples, a young GC occurred. Its duration was 0.001 seconds. The collection found enough active data that the survivor space 0 utilization (S0U) would have exceeded the desired survivor size (DSS). As a result, objects were promoted to the old generation (not visible in this output), and the tenuring threshold (TT) was lowered from 31 to 2.

Another collection occurs between the fifth and sixth samples. This collection found very few survivors and returned the tenuring threshold to 31.

INCLUDE A TIME STAMP FOR EACH SAMPLE

This example attaches to lvmid 21891 and takes 3 samples at 250 millisecond intervals. The -t option is used to generate a time stamp for each sample in the first column.

The Timestamp column reports the elapsed time in seconds since the start of the target JVM. In addition, the -gcoldcapacity output shows the old generation capacity (OGC) and the old space capacity (OC) increasing as the heap expands to meet allocation or promotion demands. The old generation capacity (OGC) has grown from 11,696 KB to 13,820 KB after the eighty-first full garbage collection (FGC). The maximum capacity of the generation (and space) is 60,544 KB (OGCMX), so it still has room to expand.

MONITOR INSTRUMENTATION FOR A REMOTE JVM

This example attaches to lvmid 40496 on the system named remote.domain using the -gcutil option, with samples taken every second indefinitely.

The lvmid is combined with the name of the remote host to construct a vmid of 40496@remote.domain. This vmid results in the use of the rmi protocol to communicate to the default jstatd server on the remote host. The jstatd server is located using the rmiregistry command on remote.domain that's bound to the default port of the rmiregistry command (port 1099).

jstat -gcutil 40496@remote.domain 1000

jstat(1)

jstat - Monitor Instrumentation for a Remote JVM

SYNOPSIS

jstat [ -J<option> ] [ -options ] [ vmid [ interval [ count ] ] ]

DESCRIPTION

The jstat utility collects and displays performance statistics from a running Java Virtual Machine (JVM) instrumented for monitoring.

OPTIONS

-J<option>
Passes the option to the Java HotSpot VM. For example, -J-Xms32m sets the initial heap size to 32 megabytes.
-options
One or more of the following options can be specified:
-class
Reports statistics about class loading.
-compiler
Reports statistics about the JIT compiler.
-gc
Reports statistics about garbage collection.
-gccapacity
Reports statistics about garbage collection capacities.
-gccause
Reports garbage collection statistics (including the cause of the last GC).
-gcnew
Reports statistics about garbage collection of the new generation.
-gcnewcapacity
Reports statistics about the capacities of the new generation.
-gcpermcapacity
Reports statistics about the permanent generation capacity.
-hist
Reports class histogram statistics.
-printcompilation
Reports Java HotSpot VM compilation statistics.
vmid
The virtual machine identifier of the target JVM. This can be a process ID (PID) or a specific identifier for remote JVMs.
interval
The sampling interval in seconds. If specified, statistics are printed at this interval.
count
The number of samples to take. If specified along with interval, this limits the total number of statistics collected.

EXAMPLES

# Display garbage collection statistics for the JVM with PID 12345 every 2 seconds
jstat -gc 12345 2
# Display class loading statistics for the JVM with PID 12345, once
jstat -class 12345
# Display garbage collection capacity statistics for the JVM with PID 12345, taking 5 samples at a 1-second interval
jstat -gccapacity 12345 1 5
