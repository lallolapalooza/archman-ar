jcmd - utility to diagnose applications and core JVM features

NAME

jcmd - utility to diagnose applications and core JVM features

SYNOPSIS

jcmd [ options ] <pid> [ jcmd options ]
jcmd [ options ] <pid> command [ command options ]

DESCRIPTION

The jcmd utility is a versatile tool that can be used to collect diagnostic information, perform various diagnostic actions, and control the JVM.

You can use jcmd to:

  • List all running JVM processes and their PIDs.

  • Print detailed information about a specific JVM process.

  • Perform various diagnostic actions on a specific JVM process.

jcmd can be run with or without arguments. If no arguments are provided, it will list all running JVM processes and their PIDs.

If a PID is provided, jcmd will attempt to connect to the JVM process with that PID and list the available commands for that JVM.

If a command is provided, jcmd will execute that command on the specified JVM process.

help
Lists all available commands for the target JVM.

Impact: Low

help.vm
Lists all available VM commands for the target JVM.

Impact: Low

help.diagnostic
Lists all available diagnostic commands for the target JVM.

Impact: Low

heap.dump [options]
Dumps the Java heap to a file.

Impact: Medium --- depends on the Java content.

Permission: java.lang.management.ManagementPermission(control)

options:

•
<filename>: (Optional) The name of the file to which the heap dump will be written (STRING, no default value)
jcmd.gc_heap_info
Dumps Java heap information.

Impact: Medium

jcmd.gc_run
Runs a full garbage collection.

Impact: Medium

jcmd.heap_usage
Dumps heap usage information.

Impact: Medium

jcmd.jstack [options]
Dumps thread information.

Impact: Medium --- depends on the Java content.

Permission: java.lang.management.ManagementPermission(monitor)

options:

•
<filename>: (Optional) The name of the file to which the thread dump will be written (STRING, no default value)
jcmd.memory_summary [options]
Requests runtime to report current memory summary.

Impact: Medium

Permission: java.lang.management.ManagementPermission(monitor)

options:

•
summary: (Optional) Requests runtime to report current memory summary, which includes total reserved and committed memory, along with memory usage summary by each subsystem. (BOOLEAN, false)
•
detail: (Optional) Requests runtime to report memory allocation >= 1K by each callsite. (BOOLEAN, false)
•
baseline: (Optional) Requests runtime to baseline current memory usage, so it can be compared against in later time. (BOOLEAN, false)
•
summary.diff: (Optional) Requests runtime to report memory summary comparison against previous baseline. (BOOLEAN, false)
•
detail.diff: (Optional) Requests runtime to report memory detail comparison against previous baseline, which shows the memory allocation activities at different callsites. (BOOLEAN, false)
•
shutdown: (Optional) Requests runtime to shutdown itself and free the memory used by runtime. (BOOLEAN, false)
•
statistics: (Optional) Prints tracker statistics for tuning purpose. (BOOLEAN, false)
•
scale: (Optional) Memory usage in which scale, KB, MB or GB (STRING, KB)
VM.print_touched_methods
Prints all methods that have ever been touched during the lifetime of this JVM.

Impact: Medium --- depends on Java content.

VM.set_flag [arguments]
Sets the VM flag option by using the provided value.

Impact: Low

arguments:

string value: (Optional) The value that you want to set (STRING, no default value)
