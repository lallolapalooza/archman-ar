JAVADOC(1) أوامر JDK JAVADOC(1)

الاسم

javadoc - إنشاء صفحات HTML لوثائق واجهة برمجة التطبيقات من ملفات مصدر Java

الخلاصة

javadoc [خيارات] [أسماء الحزم] [ملفات المصدر] [@ملفات]

الخيارات
يحدد خيارات سطر الأوامر، مفصولة بمسافات. انظر خيارات javadoc، الخيارات الموسعة، خيارات doclet القياسية، و خيارات إضافية مقدمة بواسطة doclet القياسي.
أسماء الحزم
يحدد أسماء الحزم التي ترغب في توثيقها، مفصولة بمسافات، على سبيل المثال java.lang java.lang.reflect java.awt. إذا كنت ترغب أيضًا في توثيق الحزم الفرعية، فاستخدم الخيار -subpackages لتحديد الحزم.

بشكل افتراضي، يبحث javadoc عن الحزم المحددة في الدليل الحالي والأدلة الفرعية. استخدم الخيار -sourcepath لتحديد قائمة الأدلة للبحث فيها عن الحزم.

ملفات المصدر
يحدد أسماء ملفات مصدر Java التي ترغب في توثيقها، مفصولة بمسافات، على سبيل المثال Class.java Object.java Button.java. بشكل افتراضي، يبحث javadoc عن الفئات المحددة في الدليل الحالي. ومع ذلك، يمكنك تحديد المسار الكامل لملف الفئة واستخدام أحرف البدل، على سبيل المثال /home/src/java/awt/Graphics*.java. يمكنك أيضًا تحديد المسار النسبي للدليل الحالي.
@ملفات
يحدد أسماء الملفات التي تحتوي على قائمة بخيارات أداة javadoc، وأسماء الحزم، وأسماء ملفات المصدر بأي ترتيب.

الوصف

تقوم أداة javadoc بتحليل التصريحات وتعليقات التوثيق في مجموعة من ملفات مصدر Java وإنتاج صفحات HTML المقابلة التي تصف (بشكل افتراضي) الفئات العامة والمحمية، والفئات المتداخلة (ولكن ليس الفئات الداخلية المجهولة)، والواجهات، والمنشئات، والطرق، والحقول. يمكنك استخدام أداة javadoc لإنشاء وثائق واجهة برمجة التطبيقات أو وثائق التنفيذ لمجموعة من ملفات المصدر.

يمكنك تشغيل أداة javadoc على حزم كاملة، أو ملفات مصدر فردية، أو كليهما. عند توثيق حزم كاملة، يمكنك استخدام الخيار -subpackages إما للتنقل المتكرر في دليل وأدلته الفرعية، أو لتمرير قائمة صريحة بأسماء الحزم. عند توثيق ملفات مصدر فردية، قم بتمرير قائمة بأسماء ملفات مصدر Java. انظر نظرة عامة على javadoc [https://www.oracle.com/pls/topic/lookup?ctx=en/java/javase/13/tools&id=JSJAV-GUID-7A344353-3BBF-45C4-8B28-15025DDCC643] في دليل Java Platform, Standard Edition Javadoc للحصول على معلومات حول استخدام أداة javadoc.

الامتثال

لا يتحقق doclet القياسي من محتوى تعليقات التوثيق من حيث الامتثال، ولا يحاول تصحيح أي أخطاء في تعليقات التوثيق. يُنصح أي شخص يقوم بتشغيل javadoc بالانتباه إلى المشكلات التي قد تنشأ عند إنشاء مخرجات غير متوافقة أو مخرجات تحتوي على محتوى قابل للتنفيذ، مثل JavaScript. يوفر doclet القياسي ميزة doclint لمساعدة المطورين على اكتشاف المشكلات الشائعة في تعليقات التوثيق؛ ولكن يوصى أيضًا بالتحقق من المخرجات التي تم إنشاؤها باستخدام أي أدوات امتثال وأدوات فحص مناسبة أخرى.

لمزيد من التفاصيل حول متطلبات الامتثال لمستندات HTML5، انظر متطلبات الامتثال [https://www.w3.org/TR/html5/infrastructure.html#conformance-requirements] في مواصفات HTML5. لمزيد من التفاصيل حول قضايا الأمان المتعلقة بصفحات الويب، انظر صفحة مشروع OWASP (Open Web Application Security Project) [https://www.owasp.org].

ملاحظة:

في الأدوات التي تدعم الخيارات من نمط --، يمكن للخيارات بأسلوب GNU استخدام علامة المساواة (=) بدلاً من المسافة لفصل اسم الخيار عن قيمته.

-breakiterator
يحسب الجملة الأولى باستخدام BreakIterator. يتم نسخ الجملة الأولى إلى ملخص الحزمة أو الفئة أو العضو وإلى الفهرس الأبجدي. يستخدم BreakIterator لتحديد نهاية الجملة لجميع اللغات باستثناء الإنجليزية.
•
خوارزمية تحديد نهاية الجملة الافتراضية للغة الإنجليزية - تتوقف عند نقطة تتبعها مسافة أو علامة كتلة HTML، مثل <P>.
•
خوارزمية تحديد نهاية الجملة لـ Breakiterator - تتوقف عند نقطة، علامة استفهام، أو علامة تعجب تتبعها مسافة عندما تبدأ الكلمة التالية بحرف كبير. يهدف هذا إلى التعامل مع معظم الاختصارات (مثل "الرقم التسلسلي. صالح" ، ولكن لن يتعامل مع "السيد. سميث"). الخيار -breakiterator لا يتوقف عند علامات HTML أو الجمل التي تبدأ بأرقام أو رموز. تتوقف الخوارزمية عند آخر نقطة في ../filename، حتى عند تضمينها في علامة HTML.
-doclet فئة
ينشئ المخرجات باستخدام doclet بديل. استخدم الاسم المؤهل بالكامل. تحدد هذه doclet المحتوى وتنسق المخرجات. إذا لم يتم استخدام الخيار -doclet، فإن أداة javadoc تستخدم doclet القياسي لإنشاء تنسيق HTML الافتراضي. يجب أن تحتوي هذه الفئة على الطريقة start(Root). يتم تحديد المسار لهذه الفئة البادئة بواسطة الخيار -docletpath.

OPTIONS DIVERSES

-verbose
Fournit des messages plus détaillés pendant l'exécution de l'outil javadoc. Sans l'option -verbose, des messages apparaissent pour le chargement des fichiers source, la génération de la documentation (un message par fichier source) et le tri. L'option -verbose provoque l'affichage de messages supplémentaires spécifiant le nombre de millisecondes nécessaires à l'analyse de chaque fichier source Java.
--version
Affiche les informations de version.
-Werror
Signale une erreur si des avertissements surviennent.

OPTIONS STANDARD DU DOCLET

Les options suivantes sont fournies par le doclet standard.

--add-stylesheet fichier
Ajoute un fichier de feuilles de style supplémentaire pour la documentation générée. Cette option peut être utilisée une ou plusieurs fois pour spécifier des feuilles de style supplémentaires incluses dans la documentation.

Exemple de ligne de commande :

javadoc --add-stylesheet new_stylesheet_1.css --add-stylesheet new_stylesheet_2.css pkg_foo

--allow-script-in-comments
Autorise les scripts JavaScript dans les options et les commentaires.
-author
Inclut le texte @author dans les documents générés.
-bottom code-html
Spécifie le texte à placer au bas de chaque fichier de sortie. Le texte est placé au bas de la page, sous la barre de navigation inférieure. Le texte peut contenir des balises HTML et des espaces blancs, mais dans ce cas, il doit être entre guillemets. Utilisez des caractères d'échappement pour les guillemets internes dans le texte.
-charset nom
Spécifie le jeu de caractères HTML pour ce document. Le nom doit être un nom MIME préféré tel que spécifié dans le Registre IANA des jeux de caractères [http://www.iana.org/assignments/character-sets].

Par exemple :

javadoc -charset "iso-8859-1" mypackage

Cette commande insère la ligne suivante dans l'en-tête de chaque page générée :

<META http-equiv="Content-Type" content="text/html; charset=ISO-8859-1">

La balise META est décrite dans la norme HTML (4197265 et 4137321), Représentation des documents HTML [http://www.w3.org/TR/REC-html40/charset.html#h-5.2.2].

-d répertoire
Spécifie le répertoire de destination où l'outil javadoc enregistre les fichiers HTML générés. Si vous omettez l'option -d, les fichiers sont enregistrés dans le répertoire courant. La valeur du répertoire peut être absolue ou relative au répertoire de travail courant. Le répertoire de destination est créé automatiquement lorsque l'outil javadoc s'exécute.
•
Linux et OS X : Par exemple, la commande suivante génère la documentation pour le package com.mypackage et enregistre les résultats dans le répertoire /user/doc/ :

javadoc -d /user/doc/ com.mypackage

•
Windows : Par exemple, la commande suivante génère la documentation pour le package com.mypackage et enregistre les résultats dans le répertoire \user\doc\ :

javadoc -d \user\doc\ com.mypackage

-docencoding nom
Spécifie l'encodage des fichiers HTML générés. Le nom doit être un nom MIME préféré tel que spécifié dans le Registre IANA des jeux de caractères [http://www.iana.org/assignments/character-sets].

Trois options sont disponibles pour être utilisées dans une commande d'encodage javadoc. L'option -encoding est utilisée pour encoder les fichiers lus par l'outil javadoc, tandis que les options -docencoding et -charset sont utilisées pour encoder les fichiers écrits par l'outil. Parmi les trois options disponibles, au plus, seule l'entrée et une option d'encodage de sortie sont utilisées dans une seule commande d'encodage. Si vous spécifiez les deux options d'encodage d'entrée et de sortie dans une commande, elles doivent avoir la même valeur. Si vous ne spécifiez aucune option de sortie, l'outil utilise l'encodage d'entrée par défaut.

Par exemple :

javadoc -docencoding "iso-8859-1" mypackage

-docfilessubdirs
Copie récursivement les sous-répertoires doc-files. Active la copie approfondie des répertoires de fichiers de documentation. Les sous-répertoires et leur contenu sont copiés récursivement dans la destination. Par exemple, le répertoire doc-files/example/images et tout son contenu sont copiés. Il existe également une option pour exclure les sous-répertoires.
-doctitle code-html
Spécifie le titre à placer près du haut du fichier de résumé général. Le texte spécifié dans la balise title est placé comme un en-tête centré de niveau un, directement sous la barre de navigation supérieure. La balise title peut contenir des balises HTML et des espaces blancs, mais dans ce cas, vous devez entourer le titre de guillemets. Les guillemets supplémentaires à l'intérieur de la balise title doivent être échappés. Par exemple, javadoc -doctitle "<b>Ma Bibliothèque</b><br>v1.0" com.mypackage.
-excludedocfilessubdir nom
Exclut tous les sous-répertoires de fichiers de documentation portant le nom donné. Voir -docfilessubdirs.
-footer code-html
Spécifie le texte du pied de page à placer au bas de chaque fichier de sortie. La valeur code-html est placée à droite de la barre de navigation inférieure. La valeur code-html peut contenir des balises HTML et des espaces blancs, mais dans ce cas, la valeur code-html doit être entourée de guillemets. Utilisez des caractères d'échappement pour les guillemets internes dans un pied de page.
-group nomp1:p2
Regroupe les packages spécifiés dans la page de présentation.
-header code-html
Spécifie le texte de l'en-tête à placer en haut de chaque fichier de sortie. L'en-tête est placé à droite de la barre de navigation supérieure. L'en-tête peut contenir des balises HTML et des espaces blancs, mais dans ce cas, l'en-tête doit être entouré de guillemets. Utilisez des caractères d'échappement pour les guillemets internes dans un en-tête. Par exemple, javadoc -header "<b>Ma Bibliothèque</b><br>v1.0" com.mypackage.
-helpfile nomfichier
Inclut le fichier qui crée un lien vers le lien AIDE dans les barres de navigation supérieure et inférieure. Sans cette option, l'outil javadoc crée un fichier d'aide help-doc.html codé en dur dans l'outil javadoc. Cette option vous permet de remplacer le défaut. Le nomfichier peut être n'importe quel nom et n'est pas limité à help-doc.html. Le
