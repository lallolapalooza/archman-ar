jarsigner - code signing and verification tool

SYNOPSIS

jarsigner [options] jar-file alias

jarsigner [options] -verify [-certs] jar-file [alias ...]

DESCRIPTION

The jarsigner utility is used to sign JAR files, or to verify the signatures of signed JAR files. This tool is part of the Java Development Kit (JDK).

When signing a JAR file, you need to provide a keystore containing the private key and certificate used for signing. The alias parameter specifies the alias of the key entry within the keystore.

When verifying a JAR file, jarsigner checks the integrity of the files within the JAR and the validity of the signatures. The -verify option is used for this purpose.

KEYSTORE ALIASES

Each entry in a keystore is identified by an alias, which is a string. When signing, you specify the alias of the private key and certificate you want to use.

KEYSTORE LOCATION

By default, jarsigner looks for the keystore in a file named .keystore in the user's home directory. You can specify a different keystore location using the -keystore option.

KEYSTORE IMPLEMENTATION

The keystore implementation used is determined by the Java security properties. The default implementation is the "JKS" (Java KeyStore) format.

SUPPORTED ALGORITHMS

The supported signature and digest algorithms depend on the Java cryptography providers configured in the security properties. Common algorithms include MD5withRSA, SHA1withRSA, SHA-256, and SHA-512.

THE SIGNED JAR FILE

A signed JAR file contains additional files that provide information about the signature. These files are typically located in the META-INF/ directory within the JAR.

The signature files include:
*.SF: The signature file, containing a hash of the manifest file.
*.DSA, *.RSA, or *.EC: The signature block file, containing the digital signature.
MANIFEST.MF: The manifest file, which lists all the files in the JAR and their corresponding hashes.

SIGNATURE FILE

The signature file (*.SF) contains a header indicating the manifest hash algorithm and the manifest hash itself. For example:

Manifest-Version: 1.0
Signature-Algorithm: SHA1withRSA
SHA1-Digest-Manifest-Main-Attributes: ...
...

SIGNATURE BLOCK FILE

The signature block file (*.DSA, *.RSA, or *.EC) contains the digital signature generated using the private key. It also includes the signer's certificate chain.

SIGNATURE TIME STAMP

Optionally, a signature can be timestamped by a trusted time stamping authority (TSA). This provides a way to verify the signature even after the signer's certificate has expired. The timestamp information is usually embedded in the signature block file.

JAR FILE VERIFICATION

When verifying a JAR file with the -verify option, jarsigner performs the following checks:

  1. It checks if the signature files and the manifest file exist and are properly formatted.
  2. It verifies the integrity of each file in the JAR by comparing its hash against the hash stored in the manifest file.
  3. It verifies the digital signature using the signer's public key (from the certificate).
  4. If a timestamp is present, it verifies the timestamp's validity and checks if the signature was created before the timestamp expired.

MULTIPLE SIGNATURES FOR A JAR FILE

A JAR file can be signed by multiple entities. Each signature is typically stored in a separate signature block file (e.g., META-INF/sigfile.DSA, META-INF/anothersig.RSA).

When verifying, you can specify one or more aliases to verify specific signatures, or run -verify without arguments to verify all available signatures.

OPTIONS FOR JARSIGNER

-keystore <url>
Specifies the location of the keystore.
-storepass <password>
Specifies the password for the keystore.
-storetype <type>
Specifies the keystore type (e.g., JKS, PKCS12).
-keypass <password>
Specifies the password for the private key.
-signedjar <jar-file>
Specifies the output file name for the signed JAR.
-verify
Verifies the signatures of the specified JAR file.
-certs
When used with -verify, displays the certificates associated with each signature.
-tsa <url>
Specifies the URL of the timestamping authority server.
-tsacert <cert-file>
Specifies the certificate of the timestamping authority.

DEPRECATED OPTIONS

Some options, such as those related to MD5 and SHA1 hashing algorithms, may be deprecated in newer versions due to security concerns. It is recommended to use stronger algorithms like SHA-256 or SHA-512.

ERRORS AND WARNINGS

jarsigner reports errors and warnings during the signing and verification process. These can indicate problems with the keystore, certificates, signatures, or the JAR file itself.

FAILURE

Indicates a critical error that prevents signing or verification from completing successfully. This could be due to an invalid keystore, incorrect passwords, or corrupted files.

SEVERE WARNINGS

Indicates potential security risks or significant issues that should be addressed. Examples include expired certificates or the use of weak cryptographic algorithms.

INFORMATIONAL WARNINGS

Provides non-critical information about the signing or verification process. This might include details about certificate chains or the use of default settings.

EXAMPLE OF SIGNING A JAR FILE

To sign a JAR file named myapp.jar with a key pair identified by the alias mykey in a keystore named mykeystore.jks:

jarsigner -keystore mykeystore.jks -signedjar myapp_signed.jar myapp.jar mykey

You will be prompted for the keystore password and the key password.

EXAMPLE OF VERIFYING A SIGNED JAR FILE

To verify the signatures of a signed JAR file:

jarsigner -verify myapp_signed.jar

This will output messages indicating whether the verification was successful or if there were any errors.

EXAMPLE OF VERIFICATION WITH CERTIFICATE INFORMATION

To verify the signatures and display the certificates:

jarsigner -verify -certs myapp_signed.jar

This will show detailed information about the signer's certificates, including their validity periods and distinguished names.
