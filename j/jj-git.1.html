jj-git(1) دليل الأوامر العامة jj-git(1)

الاسم

jj-git - أوامر للعمل مع المستودعات البعيدة لـ Git والمستودع الأساسي لـ Git

الملخص

jj git [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help] <الأوامر الفرعية>

الوصف

أوامر للعمل مع المستودعات البعيدة لـ Git والمستودع الأساسي لـ Git

انظر هذه [المقارنة]، بما في ذلك [جدول الأوامر].

[المقارنة]: https://docs.jj-vcs.dev/latest/git-comparison/.

[جدول الأوامر]: https://docs.jj-vcs.dev/latest/git-command-table

الخيارات

-h, --help
طباعة المساعدة (انظر الملخص مع '-h')

خيارات عامة

-R, --repository <المستودع>
مسار المستودع الذي سيتم العمل عليه

بشكل افتراضي، يبحث Jujutsu عن أقرب دليل .jj/ في دليل أب للمجلد الحالي.

--ignore-working-copy
عدم التقاط نسخة العمل، وعدم تحديثها

بشكل افتراضي، يلتقط Jujutsu نسخة العمل في بداية كل أمر. يتم أيضًا تحديث نسخة العمل في نهاية الأمر، إذا قام الأمر بتعديل التزام نسخة العمل (`@`). إذا كنت ترغب في تجنب التقاط نسخة العمل ورؤية التزام نسخة عمل قديم، يمكنك استخدام `--ignore-working-copy`. قد يكون هذا مفيدًا على سبيل المثال في موجه الأوامر، خاصة إذا كان لديك عملية أخرى تقوم بتثبيت نسخة العمل.

تحميل المستودع عند عملية معينة باستخدام `--at-operation` يعني ضمنيًا `--ignore-working-copy`.

--ignore-immutable
السماح بإعادة كتابة الالتزامات غير القابلة للتغيير

بشكل افتراضي، يمنع Jujutsu إعادة كتابة الالتزامات في مجموعة الالتزامات غير القابلة للتغيير التي تم تكوينها. هذا الخيار يعطل هذا الفحص ويسمح لك بإعادة كتابة أي التزام باستثناء الالتزام الجذري.

يؤثر هذا الخيار فقط على الفحص. لا يؤثر على تعبير `immutable_heads()` أو الكلمة الرئيسية للقالب `immutable`.

--at-operation <AT_OPERATION>
العملية التي سيتم تحميل المستودع عندها

العملية التي سيتم تحميل المستودع عندها. بشكل افتراضي، يقوم Jujutsu بتحميل المستودع عند آخر عملية، أو عند دمج العمليات المتباينة إذا وجدت.

يمكنك استخدام `--at-op=<معرف العملية>` لرؤية كيف كان يبدو المستودع عند عملية سابقة. على سبيل المثال، `jj --at-op=<معرف العملية> st` سيظهر لك ما كان سيظهر `jj st` عندما انتهت العملية المحددة للتو. `--at-op=@` هو تقريبًا نفس الإعداد الافتراضي باستثناء أن العمليات المتباينة لن يتم دمجها أبدًا.

استخدم `jj op log` للعثور على معرف العملية الذي تريده. أي بادئة غير واضحة لمعرف العملية كافية.

عند تحميل المستودع عند عملية سابقة، سيتم تجاهل نسخة العمل، كما لو تم تحديد `--ignore-working-copy`.

من الممكن تشغيل أوامر تعديل عند تحميل المستودع عند عملية سابقة. القيام بذلك يعادل تشغيل عمليات متزامنة تبدأ عند العملية السابقة. نادرًا ما يكون هناك سبب لذلك، ولكنه ممكن.

--debug
تمكين تسجيل التصحيح
--color <WHEN>
متى يتم تلوين الإخراج

[القيم الممكنة: always, never, debug, auto]

--quiet
إسكات الإخراج غير الأساسي للأمر

على سبيل المثال، `jj file list` سيظل يسرد الملفات، ولكنه لن يخبرك إذا تم التقاط نسخة العمل أو إذا تم إعادة بناء الأبناء.

سيتم طباعة التحذيرات والأخطاء.

--no-pager
تعطيل عارض الصفحات
--config <NAME=VALUE>
خيارات تكوين إضافية (يمكن تكرارها)

يجب تحديد الاسم كمفاتيح منقطة TOML. يجب تحديد القيمة كتعبير TOML. إذا لم تكن قيمة السلسلة محاطة بأي هياكل TOML (مثل صيغة المصفوفة)، يمكن حذف علامات الاقتباس.

--config-file <PATH>
ملفات تكوين إضافية (يمكن تكرارها)
