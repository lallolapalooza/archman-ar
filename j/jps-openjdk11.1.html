jps(1) أدوات المراقبة jps(1)

الاسم

jps - يسرد آلات Java الافتراضية (JVMs) المُراقبة على النظام المستهدف. هذا الأمر تجريبي وغير مدعوم.

ملخص

jps [ خيارات ] [ معرف_المضيف ]
خيارات
خيارات سطر الأوامر. انظر الخيارات.
معرف_المضيف
معرف النظام الذي يجب إنشاء تقرير العملية له. يمكن أن يتضمن معرف_المضيف مكونات اختيارية تشير إلى بروتوكول الاتصال ورقم المنفذ وبيانات أخرى خاصة بالتنفيذ. انظر معرف المضيف.

الوصف

يسرد الأمر jps آلات Java HotSpot الافتراضية المُراقبة على النظام المستهدف. يقتصر الأمر على الإبلاغ عن معلومات حول آلات Java الافتراضية التي يمتلك الإذن بالوصول إليها.

إذا تم تشغيل الأمر jps دون تحديد معرف_المضيف، فإنه يبحث عن آلات Java الافتراضية المُراقبة على المضيف المحلي. إذا تم تشغيله بمعرف معرف_المضيف، فإنه يبحث عن آلات Java الافتراضية على المضيف المحدد، باستخدام البروتوكول والمنفذ المحددين. يُفترض وجود عملية jstatd قيد التشغيل على المضيف المستهدف.

يبلغ الأمر jps عن معرف آلة Java الافتراضية المحلي، أو lvmid، لكل آلة Java افتراضية مُراقبة يتم العثور عليها على النظام المستهدف. عادةً ما يكون lvmid، ولكنه ليس بالضرورة، معرف عملية نظام التشغيل لعملية آلة Java الافتراضية. بدون خيارات، يعرض jps معرف lvmid الخاص بكل تطبيق Java متبوعًا بالشكل المختصر لاسم فئة التطبيق أو اسم ملف JAR. يتجاهل الشكل المختصر لاسم الفئة أو اسم ملف JAR معلومات الحزمة الخاصة بالفئة أو معلومات المسار الخاصة بملفات JAR.

يستخدم الأمر jps مشغل Java للعثور على اسم الفئة والوسائط التي تم تمريرها إلى طريقة main. إذا تم بدء تشغيل آلة Java الافتراضية باستخدام مشغل مخصص، فلن يكون اسم الفئة أو ملف JAR والوسائط الخاصة بطريقة main متاحة. في هذه الحالة، يُخرج الأمر jps السلسلة النصية Unknown لاسم الفئة أو اسم ملف JAR وللوسائط الخاصة بطريقة main.

يمكن تقييد قائمة آلات Java الافتراضية التي ينتجها الأمر jps بالأذونات الممنوحة للمستخدم الذي يقوم بتشغيل الأمر. يسرد الأمر فقط آلات Java الافتراضية التي يمتلك المستخدم حقوق الوصول إليها كما هو محدد بواسطة آليات التحكم في الوصول الخاصة بنظام التشغيل.

خيارات

يدعم الأمر jps عددًا من الخيارات التي تعدل مخرجات الأمر. تخضع هذه الخيارات للتغيير أو الإزالة في المستقبل.

-q

يقوم بقمع إخراج اسم الفئة واسم ملف JAR والوسائط التي تم تمريرها إلى طريقة main، وإنشاء قائمة بمعرفات آلات Java الافتراضية المحلية فقط.
-m

يعرض الوسائط التي تم تمريرها إلى طريقة main. قد تكون المخرجات null لآلات Java الافتراضية المضمنة.
-l

يعرض الاسم الكامل لحزمة الفئة الرئيسية للتطبيق أو المسار الكامل لملف JAR الخاص بالتطبيق.
-v

يعرض الوسائط التي تم تمريرها إلى آلة Java الافتراضية.
-V

يقوم بقمع إخراج اسم الفئة واسم ملف JAR والوسائط التي تم تمريرها إلى طريقة main، وإنشاء قائمة بمعرفات آلات Java الافتراضية المحلية فقط.
-Joption

يمرر option إلى آلة Java الافتراضية، حيث يكون option أحد الخيارات الموصوفة في صفحة المرجع لمشغل تطبيقات Java. على سبيل المثال، -J-Xms48m يضبط ذاكرة البدء على 48 ميجابايت. انظر java(1).

معرف المضيف

معرف المضيف، أو hostid، هو سلسلة تشير إلى النظام المستهدف. يتوافق بناء الجملة لسلسلة hostid مع بناء جملة URI:

[protocol:][[//]hostname][:port][/servername]
protocol
بروتوكول الاتصال. إذا تم حذف protocol ولم يتم تحديد hostname، فإن البروتوكول الافتراضي هو بروتوكول محلي محسّن خاص بالمنصة. إذا تم حذف البروتوكول وتم تحديد اسم مضيف، فإن البروتوكول الافتراضي هو rmi.
hostname
اسم مضيف أو عنوان IP يشير إلى المضيف المستهدف. إذا حذفت المعامل hostname، فإن المضيف المستهدف هو المضيف المحلي.
port
المنفذ الافتراضي للتواصل مع الخادم البعيد. إذا تم حذف المعامل hostname أو حدد المعامل protocol بروتوكولًا محليًا محسّنًا، فسيتم تجاهل المعامل port. بخلاف ذلك، فإن معالجة المعامل port خاصة بالتنفيذ. بالنسبة لبروتوكول rmi الافتراضي، يشير المعامل port إلى رقم المنفذ لـ rmiregistry على المضيف البعيد. إذا تم حذف المعامل port، وحدد المعامل protocol rmi، فسيتم استخدام منفذ rmiregistry الافتراضي (1099).
servername
تعتمد معالجة هذا المعامل على التنفيذ. بالنسبة للبروتوكول المحلي المحسّن، يتم تجاهل هذا الحقل. بالنسبة لبروتوكول rmi، هذا المعامل هو سلسلة نصية تمثل اسم كائن RMI البعيد على المضيف البعيد. انظر خيار -n في الأمر jstatd لمزيد من المعلومات.

تنسيق المخرجات

تتبع مخرجات الأمر jps النمط التالي:

lvmid [ [ classname | JARfilename | "Unknown"] [ arg* ] [ jvmarg* ] ]

يتم فصل جميع رموز الإخراج بمسافات بيضاء. يؤدي وجود قيمة arg تتضمن مسافات بيضاء مضمنة إلى إحداث غموض عند محاولة تعيين الوسائط إلى معلمات الموضع الفعلية الخاصة بها.

ملاحظة: يوصى بعدم كتابة نصوص برمجية لتحليل مخرجات jps لأن التنسيق قد يتغير في الإصدارات المستقبلية. إذا كنت تكتب نصوصًا برمجية تحلل مخرجات jps، فتوقع تعديلها للإصدارات المستقبلية من هذه الأداة.

أمثلة

يقدم هذا القسم أمثلة لأمر jps.

يسرد آلات Java الافتراضية المُراقبة على المضيف المحلي:

jps
18027 Java2Demo.JAR
18032 jps
18005 jstat

يسرد المثال التالي آلات Java الافتراضية المُراقبة على مضيف بعيد. يفترض هذا المثال أن خادم jstat وإما سجل RMI الداخلي الخاص به أو عملية rmiregistry خارجية منفصلة قيد التشغيل على المضيف البعيد على المنفذ الافتراضي (المنفذ 1099). كما يفترض أن المضيف المحلي لديه الأذونات المناسبة للوصول إلى المضيف البعيد. يتضمن هذا المثال أيضًا الخيار -l لإخراج الشكل الطويل لأسماء الفئات أو أسماء ملفات JAR.

jps -l remote.domain
3002 /opt/jdk1.7.0/demo/jfc/Java2D/Java2Demo.JAR
2857 sun.tools.jstatd.jstatd

يسرد المثال التالي آلات Java الافتراضية المُراقبة على مضيف بعيد بمنفذ غير افتراضي لسجل RMI. يفترض هذا المثال أن خادم jstatd، مع سجل RMI داخلي مرتبط بالمنفذ 2002، قيد التشغيل على المضيف البعيد. يستخدم هذا المثال أيضًا الخيار -m لتضمين الوسائط التي تم تمريرها إلى طريقة main لكل تطبيق Java مدرج.

jps -m remote.domain:2002
3002 /opt/jdk1.7.0/demo/jfc/Java2D/Java2Demo.JAR
3102 sun.tools.jstatd.jstatd -p 2002
