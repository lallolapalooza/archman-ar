الوصف

vmod_std تحتوي على وظائف أساسية تشكل جزءًا لا يتجزأ من Varnish، ولكنها لأسباب تتعلق بالهندسة المعمارية تناسب بشكل أفضل وحدة VMOD.

وظائف الأرقام

REAL random(REAL lo, REAL hi)

ترجع رقمًا حقيقيًا عشوائيًا بين lo و hi.

تستخدم هذه الوظيفة مولد الأرقام العشوائية "القابل للاختبار" في varnishd، مما يتيح إجراء اختبارات حتمية (انظر أمر CLI debug.srandom). لا ينبغي استخدام هذه الوظيفة للتطبيقات التشفيرية.

مثال:

set beresp.http.random-number = std.random(1, 100);

REAL round(REAL r)

تقريب الرقم الحقيقي r إلى أقرب عدد صحيح، ولكن تقريب الحالات النصفية بعيدًا عن الصفر (انظر round(3)).

وظائف السلاسل النصية

VOID collect(HEADER hdr, STRING sep=", ")

تدمج رؤوس hdr المتعددة في رأس واحد طويل. الفاصل الافتراضي sep هو الفاصل الافتراضي (فاصلة) للاستخدام عند دمج الرؤوس، مع مسافة إضافية للطباعة الجميلة.

يجب توخي الحذر عند دمج الرؤوس. على وجه الخصوص، دمج Set-Cookie سيؤدي إلى نتائج غير متوقعة من جانب المتصفح.

استخدام hdr من obj.http يؤدي إلى فشل VCL.

أمثلة:

std.collect(req.http.accept);
std.collect(req.http.cookie, "; ");

STRING querysort(STRING)

يقوم بفرز سلسلة الاستعلام لأغراض تطبيع ذاكرة التخزين المؤقت.

مثال:

set req.url = std.querysort(req.url);

STRING toupper(STRING s)

يحول السلسلة النصية s إلى أحرف كبيرة.

مثال:

set beresp.http.scream = std.toupper("yes!");

STRING tolower(STRING s)

يحول السلسلة النصية s إلى أحرف صغيرة.

مثال:

set beresp.http.nice = std.tolower("VerY");

STRING strstr(STRING s1, STRING s2)

ترجع سلسلة نصية تبدأ من أول ظهور للسلسلة النصية s2 في السلسلة النصية s1، أو سلسلة نصية فارغة إذا لم يتم العثور على s2.

لاحظ أن المقارنة حساسة لحالة الأحرف.

مثال:

if (std.strstr(req.url, req.http.restrict)) {
        ...
}

سيتحقق هذا مما إذا كان محتوى req.http.restrict يظهر في أي مكان في req.url.

BOOL fnmatch(STRING pattern, STRING subject, BOOL pathname, BOOL noescape, BOOL period)

BOOL fnmatch(
   STRING pattern,
   STRING subject,
   BOOL pathname=1,
   BOOL noescape=0,
   BOOL period=0
)

مطابقة الأنماط بأسلوب shell؛ ترجع true إذا كانت subject تطابق pattern، حيث قد يحتوي pattern على أحرف بديلة مثل * أو ?.

يتم تنفيذ المطابقة بواسطة تنفيذ fnmatch(3) على نظامك. تشمل قواعد مطابقة الأنماط في معظم الأنظمة ما يلي:

  • * يطابق أي تسلسل من الأحرف
  • ? يطابق حرفًا واحدًا
  • يتم تفسير تعبير قوس مثل [abc] أو [!0-9] كفئة أحرف وفقًا لقواعد التعبيرات العادية الأساسية (ليس تعبيرات pcre2(3) العادية)، باستثناء أنه يتم استخدام ! لعكس فئة الأحرف بدلاً من ^.

إذا كان pathname يساوي true، فإن حرف الشرطة المائلة للأمام / يتم مطابقته حرفيًا فقط، ولا يطابق أبدًا * أو ? أو تعبير قوس. بخلاف ذلك، قد يطابق / أحد هذه الأنماط. افتراضيًا، pathname يساوي true.

إذا كان noescape يساوي true، فإن حرف الشرطة المائلة للخلف \ تتم مطابقته كحرف عادي. بخلاف ذلك، \ هو حرف هروب، ويطابق الحرف الذي يتبعه في pattern. على سبيل المثال، \\ يطابق \ عندما يكون noescape يساوي true، و \\ عندما يكون false. افتراضيًا، noescape يساوي false.

إذا كان period يساوي true، فإن حرف النقطة الرائد . يطابق حرفيًا فقط، ولا يطابق أبدًا * أو ? أو تعبير قوس. تكون النقطة رائدة إذا كانت الحرف الأول في subject؛ إذا كان pathname يساوي true أيضًا، فإن النقطة التي تتبع مباشرة / تكون رائدة أيضًا (كما في /.). افتراضيًا، period يساوي false.

يستدعي std.fnmatch() فشل VCL ويرجع false إذا كان أي من pattern أو subject يساوي NULL - على سبيل المثال، إذا تم تحديد رأس غير مضبوط.

أمثلة:

# يطابق عناوين URL مثل /foo/bar و /foo/baz
if (std.fnmatch("/foo/*", req.url)) { ... }
# يطابق عناوين URL مثل /foo/bar/baz و /foo/baz/quux
if (std.fnmatch("/foo/*/ *", bereq.url)) { ... }
# يطابق /foo/bar/quux، ولكن ليس /foo/bar/baz/quux
if (std.fnmatch("/foo/*/quux", req.url)) { ... }
# يطابق /foo/bar/quux و /foo/bar/baz/quux
if (std.fnmatch("/foo/*/quux", req.url, pathname=false)) { ... }
# يطابق /foo/bar، /foo/car و /foo/far
if (std.fnmatch("/foo/?ar", req.url)) { ... }
# يطابق /foo/ متبوعًا بحرف غير رقمي
if (std.fnmatch("/foo/[!0-9]", req.url)) { ... }
