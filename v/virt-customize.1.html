    NAME

    virt-customize — Customize virtual machine disk images

    SYNOPSIS

    virt-customize [OPTION...] --in IMAGE --out IMAGE [COMMAND]...

    virt-customize [OPTION...] --inplace IMAGE [COMMAND]...

    virt-customize --help

    WARNING

    This is a low-level tool. It makes direct modifications to the disk image. If you make a mistake, you could break your virtual machine.

    It is strongly recommended that you back up your virtual machine disk image before using this command.

    DESCRIPTION

    virt-customize is a tool for making low-level modifications to virtual machine disk images. It can be used to perform a wide range of operations, such as installing or removing packages, modifying configuration files, or changing settings like the timezone.

    The tool works by running a sequence of commands against the specified disk image. These commands can be provided directly on the command line, or they can be read from a file.

    You can either create a new disk image with the modifications applied (--in and --out options) or modify the disk image in-place (--inplace option). Modifying in-place is faster but riskier.

    OPTIONS

    The following options are available:

    --copy-in FILE:DEST
    Upload local file "FILE" to destination "DEST" in the disk image. File owner and permissions from the original are preserved, so you should set them to what you want them to be in the disk image.

    "DEST" could be the final filename. This can be used to rename the file on upload.

    If "DEST" is a directory name (which must already exist in the guest) then the file is uploaded into that directory, and it keeps the same name as on the local filesystem.

    See also: --mkdir, --delete, --scrub.

    --copy-out FILE:DEST
    Copy file or directory "FILE" from the disk image to local destination "DEST".

    If "DEST" exists and is a directory, then "FILE" is copied into it.

    If "FILE" is a directory, then --recursive must be used.

    See also: --recursive.

    --delete FILE
    Delete "FILE" from the disk image. If "FILE" is a directory, then --recursive must be used.
    --firstboot FILE
    Install "FILE" as a firstboot script in the guest. This script will be executed once when the guest is first started.
    --firstboot-command COMMAND
    Add "COMMAND" to the list of commands that are executed once when the guest is first started. The commands are executed in the order they appear on the command line.
    --help
    Display help information and exit.
    --in IMAGE
    Read input from "IMAGE".
    --install PKG,PKG..
    Install the named packages (a comma-separated list). These are installed during the image build using the guest’s package manager (eg. apt, yum, etc.).
    --inplace IMAGE
    Modify the disk image "IMAGE" in-place. Use with caution!
    --mkdir DIR
    Create directory "DIR" in the disk image. Parent directories are created as needed.
    --mount-options OPTIONS
    Use "OPTIONS" when mounting the disk image. For example: "ro" to mount read-only.
    --out IMAGE
    Write output to "IMAGE".
    --partition N
    Select partition number "N" from the disk image. Partitions are numbered starting from 1.
    --probe-all
    Probe the disk image for all partitions and file systems, even if they are not standard.
    --quiet
    Suppress informational messages.
    --recursive
    Perform operations recursively on directories.
    --root-account PASSWORD
    Set the password for the root account to "PASSWORD".
    --run COMMAND
    Run "COMMAND" inside the guest. This command runs with elevated privileges (as root).

    See also: --run-user.

    --run-user USER COMMAND
    Run "COMMAND" inside the guest as "USER".
    --scrub FILE
    Remove "FILE" and overwrite its contents with random data. This is useful for securely deleting sensitive data.
    --size
    Print the size of the disk image in bytes and exit.
    --tar-in TARFILE:REMOTEDIR
    Copy local files or directories from a local tar file called "TARFILE" into the disk image, placing them in the directory "REMOTEDIR" (which must exist). Note that the tar file must be uncompressed (.tar.gz files will not work here)
    --timezone TIMEZONE
    Set the default timezone of the guest to "TIMEZONE". Use a location string like "Europe/London"
    --touch FILE
    This command performs a touch(1)-like operation on "FILE".
    --truncate FILE
    This command truncates "FILE" to a zero-length file. The file must exist already.
    --truncate-recursive PATH
    This command recursively truncates all files under "PATH" to zero-length.
    --uninstall PKG,PKG..
    Uninstall the named packages (a comma-separated list). These are removed during the image build using the guest’s package manager (eg. apt, yum, etc.). Dependent packages may also need to be uninstalled to satisfy the request.

    See also --install, --update.

    --update
    Do the equivalent of "yum update", "apt-get upgrade", or whatever command is required to update the packages already installed in the template to their latest versions.

    See also --install, --uninstall.

    --upload FILE:DEST
    Upload local file "FILE" to destination "DEST" in the disk image. File owner and permissions from the original are preserved, so you should set them to what you want them to be in the disk image.

    "DEST" could be the final filename. This can be used to rename the file on upload.

    If "DEST" is a directory name (which must already exist in the guest) then the file is uploaded into that directory, and it keeps the same name as on the local filesystem.

    See also: --mkdir, --delete, --scrub.

    --write FILE:CONTENT
    Write "CONTENT" to "FILE".

    SELINUX

    For guests which make use of SELinux, special handling for them might be needed when using operations which create new files or alter existing ones.

    For further details, see "SELINUX" in virt-builder(1).

    EXIT STATUS

    This program returns 0 on success, or 1 if there was an error.

    ENVIRONMENT VARIABLES

    "VIRT_TOOLS_DATA_DIR"
    This can point to the directory containing data files used for Windows firstboot installation.

    Normally you do not need to set this. If not set, a compiled-in default will be used (something like /usr/share/virt-tools).

    This directory may contain the following files:

    rhsrvany.exe
    This is the RHSrvAny Windows binary, used to install a "firstboot" script in Windows guests. It is required if you intend to use the --firstboot or --firstboot-command options with Windows guests.

    See also: "https://github.com/rwmjones/rhsrvany"

    pvvxsvc.exe
    This is a Windows binary shipped with SUSE VMDP, used to install a "firstboot" script in Windows guests. It is required if you intend to use the --firstboot or --firstboot-command options with Windows guests.

    For other environment variables, see "ENVIRONMENT VARIABLES" in guestfs(3).
