vacall(3)

VACALL(3) دليل وظائف المكتبة VACALL(3)

الاسم

vacall - وظائف C يتم استدعاؤها مع وسائط متغيرة

الملخص

#include <vacall.h>

extern void* vacall_function;

void function (va_alistalist)
{
  va_start_type(alist[, return_type]);
  arg = va_arg_type(alist[, arg_type]);
  va_return_type(alist[[, return_type], return_value]);
}

vacall_function = &function;

val = ((return_type (*) ()) vacall) (arg1,arg2,...);

الوصف

تسمح هذه المجموعة من الماكرو لوظيفة C function بالاستدعاء مع وسائط متغيرة وإرجاع قيم إرجاع متغيرة. هذا يشبه إلى حد كبير مرفق stdarg(3)، ولكنه يسمح أيضًا بتحديد قيمة الإرجاع في وقت التشغيل.

تختلف اصطلاحات استدعاء الوظائف بشكل كبير على الأجهزة المختلفة، وتحاول vacall توفير درجة من العزل عن هذه التبعيات الخاصة بالبنية.

الوظيفة التي يمكن استدعاؤها بأي عدد وأنواع من الوسائط والتي ستعيد أي نوع من قيم الإرجاع هي vacall. ستقوم ببعض العمليات السحرية واستدعاء الوظيفة المخزنة في المتغير vacall_function. إذا كنت ترغب في استخدام vacall أكثر من مرة، فاستخدم مرفق trampoline(3) لتخزين &function في vacall_function قبل استدعاء vacall مباشرة.

داخل function، يمكن استخدام الماكرو التالية للتنقل عبر قائمة الوسائط وتحديد قيمة إرجاع:

va_start_type(alist[, return_type]);
يبدأ المشي عبر قائمة الوسائط ويحدد نوع الإرجاع.
arg = va_arg_type(alist[, arg_type]);
يجلب الوسيط التالي من قائمة الوسائط.
va_return_type(alist[[, return_type], return_value]);
ينهي المشي عبر قائمة الوسائط ويحدد قيمة الإرجاع.

يجب أن يكون type في va_start_type و va_return_type أحد الخيارات: void، int، uint، long، ulong، longlong، ulonglong، double، struct، ptr أو (لالاصطلاحات استدعاء C ANSI فقط) char، schar، uchar، short، ushort، float، اعتمادًا على فئة return_type.

يجب أن تكون محددات return_type في va_start_type و va_return_type متطابقة. يجب أن تكون محددات return_type التي تم تمريرها إلى va_start_type و va_return_type متطابقة.

يجب أن يكون type في va_arg_type أحد الخيارات: int، uint، long، ulong، longlong، ulonglong، double، struct، ptr أو (لالاصطلاحات استدعاء C ANSI فقط) char، schar، uchar، short، ushort، float، اعتمادًا على فئة arg_type.

في va_start_struct(alist, return_type, splittable); يحدد العلم splittable ما إذا كان يمكن إرجاع الهيكل return_type في المسجلات بحيث يتناسب كل حقل هيكل بالكامل في مسجل واحد. يجب تحديد هذا للهياكل ذات الحجم 2 * sizeof(long). للهياكل ذات الحجم <= sizeof(long)، يتم تجاهل splittable وافتراض أنه 1. للهياكل ذات الحجم > 2 * sizeof(long)، يتم تجاهل splittable وافتراض أنه 0. هناك بعض الماكرو المفيدة لهذا:

va_word_splittable_1 (type1)
va_word_splittable_2 (type1, type2)
va_word_splittable_3 (type1, type2, type3)
va_word_splittable_4 (type1, type2, type3, type4)
لهيكل بثلاثة أماكن 
struct { type1 id1; type2 id2; type3 id3; }
يمكنك تحديد splittable كـ va_word_splittable_3 (type1, type2, type3).

ملاحظات

الوظائف التي ترغب في محاكاة وظائف نمط Kernighan & Ritchie (أي، في C ANSI، وظائف بدون قائمة وسائط محددة النوع) لا يمكنها استخدام قيم type char، schar، uchar، short، ushort، float. كما هو منصوص عليه في ترقيات تعبير K&R C الافتراضية، يجب عليهم استخدام int بدلاً من char، schar، uchar، short، ushort و double بدلاً من float.

تعمل الماكرو va_start_longlong()، va_start_ulonglong()، va_return_longlong()، va_return_ulonglong()، va_arg_longlong() و va_arg_ulonglong() فقط إذا كان مترجم C لديه نوع صحيح 64 بت long long يعمل.

يجب أن تحتوي أنواع الهياكل المستخدمة في va_start_struct() و va_struct() فقط على حقول int (موقعة أو غير موقعة)، long، long long أو مؤشرات. لا تدعم أنواع الهياكل التي تحتوي على char (موقعة أو غير موقعة)، short، float، double أو هياكل أخرى.

مثال

هذا المثال، وهو تنفيذ محتمل لـ execl(3) فوق execv(2) باستخدام stdarg(3)،

#include <stdarg.h>
#define MAXARGS 100
/* يتم استدعاء execl بواسطة execl(file, arg1, arg2, ..., (char *)0); */
int execl (...)
{
  va_list ap;
  char* file;
  char* args[MAXARGS];
  int argno = 0;
  va_start (ap);
  file = va_arg(ap, char*);
  while ((args[argno] = va_arg(ap, char*)) != (char *)0)
    argno++;
  va_end (ap);
  return execv(file, args);
}

يبدو هكذا باستخدام vacall(3):

#include <vacall.h>
#define MAXARGS 100
/* يتم استدعاء execl بواسطة vacall(file, arg1, arg2, ..., (char *)0); */
void execl (va_alist ap)
{
  char* file;
  char* args[MAXARGS];
  int argno = 0;
  int retval;
  va_start_int (ap);
  file = va_arg_ptr(ap, char*);
  while ((args[argno] = va_arg_ptr(ap, char*)) != (char *)0)
    argno++;
  retval = execv(file, args);
  va_return_int (ap, retval);
}
vacall_function = &execl;

انظر أيضا

stdarg(3)، trampoline(3)، callback(3).

أخطاء

تم اختبار التطبيقات الحالية على مجموعة من الحالات الشائعة ولكن من المحتمل أن تكون هناك العديد من الأخطاء.

عادة ما تكون هناك حدود مدمجة لحجم قائمة الوسائط، والتي قد تشمل أيضًا حجم أي وسائط هيكلية.

يأخذ القرار بشأن ما إذا كان الهيكل سيتم إرجاعه في المسجلات أو في الذاكرة في الاعتبار حجم الهيكل ومحاذاته فقط. هذا غير دقيق: على سبيل المثال، يقوم gcc على m68k-next بإرجاع struct { char a,b,c; } في المسجلات و struct { char a[3]; } في الذاكرة، على الرغم من أن كلا النوعين لهما نفس الحجم ونفس المحاذاة.

يمكن اجتياز قائمة الوسائط مرة واحدة فقط.

استخدام المتغير العام vacall_function ليس قابلاً لإعادة الدخول. تم إصلاح هذا في حزمة callback(3).
