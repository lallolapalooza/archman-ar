virt-xml(1)

الحزمة: virt-install

التراخيص: GPL-2.0-only

VIRT-XML(1) دعم المحاكاة الافتراضية VIRT-XML(1)

الاسم

virt-xml - تحرير XML الخاص بـ libvirt باستخدام خيارات سطر الأوامر.

الملخص

virt-xml النطاق إجراء-XML خيار-XML [خيار-الإخراج] [خيارات-متفرقة] ...

الوصف

virt-xml هو أداة سطر أوامر لتحرير XML الخاص بـ libvirt باستخدام خيارات سطر أوامر صريحة. راجع قسم الأمثلة في نهاية هذا المستند للبدء مباشرة.

كل استدعاء لـ virt-xml يتطلب 3 أشياء: اسم نطاق موجود لتعديله (أو XML يُمرَّر عبر stdin)، وإجراء على XML، وتغيير XML لتنفيذه. الإجراءات هي أحد ما يلي:

  • --add-device: إلحاق تعريف جهاز جديد بالـ XML
  • --remove-device: إزالة تعريف جهاز موجود
  • --edit: تحرير كتلة XML موجودة
  • --build-xml: فقط بناء كتلة XML المطلوبة وطباعتها. لا يُشترط وجود نطاق أو إدخال هنا، لكن يُوصى بتوفيرهما، حتى يتمكن virt-xml من ملء القيم الافتراضية المثلى.

تغيير XML هو نسخة واحدة من أي من خيارات XML التي يوفرها virt-xml، على سبيل المثال --disk أو --boot.

virt-xml يسمح فقط بزوج إجراء وXML واحد لكل استدعاء. إذا كنت بحاجة إلى إجراء تعديلات متعددة، فاستدعِ الأمر عدة مرات.

الخيارات

-c --connect URI
الاتصال بمراقب افتراضي غير افتراضي. راجع virt-install(1) للتفاصيل
domain
domain هو اسم أو UUID أو معرّف الجهاز الافتراضي الموجود. يمكن حذفه إذا كنت تستخدم --build-xml، أو إذا تم تمرير XML عبر stdin.

عند تحديد نطاق، يكون إجراء الإخراج الافتراضي هو --define، حتى لو كانت الآلة الافتراضية قيد التشغيل. لتحديث إعدادات الآلة الافتراضية قيد التشغيل، أضف خيار --update (لكن ليس كل الخيارات/الأجهزة تدعم تحديث إعدادات الآلة الافتراضية قيد التشغيل).

إذا تم تمرير XML عبر stdin، فإن الإخراج الافتراضي هو --print-xml.

إجراءات XML

--edit [خيارات-التحرير]
تحرير كتلة XML المحددة. تخبر خيارات-التحرير virt-xml أي كتلة يريد تحريرها. يتم تحديد نوع XML الذي نحرره بواسطة خيار XML الذي يُمرَّر إلى virt-xml . لذا إذا تم تمرير --disk، فإن خيارات-التحرير تحدد أي كتلة <disk> سيتم تحريرها.

بعض خيارات XML ترتبط دائمًا بكتلة XML واحدة فقط، مثل --cpu و--security و--boot و--clock وبعض الخيارات الأخرى. في تلك الحالات، لن يشتكي virt-xml إذا لم تكن كتلة XML المقابلة موجودة بالفعل، بل سينشئها لك.

معظم خيارات XML تدعم قيمة خاصة 'clearxml=yes'. عند دمجها مع --edit، فإنها ستفرغ كتلة XML التي يتم تحريرها بالكامل قبل تطبيق التغييرات المطلوبة. هذا يسمح بإعادة بناء كتلة XML بالكامل. راجع الأمثلة لبعض الاستخدامات.

أمثلة خيارات-التحرير:

•
--edit
--edit بدون أي خيارات يعني 'تحرير الكتلة الأولى'. لذا '--edit --disk خيارات-القرص' يعني 'تحرير أول <disk>'.

بالنسبة لخيارات كتلة XML الواحدة المذكورة أعلاه، فإن '--edit' المجرد بدون أي خيارات هو ما تريد استخدامه دائمًا.

•
--edit #
تحديد رقم كتلة XML المحددة. لذا '--edit 2 --disk خيارات-القرص' يعني 'تحرير ثاني <disk>'. هذا الخيار ينطبق حقًا فقط على XML الخاص بالأجهزة.
•
--edit all
تعديل كل كتلة XML من نوع خيار XML. لذا '--edit all --disk خيارات-القرص' يعني 'تحرير كل كتلة <disk>'. هذا الخيار ينطبق حقًا فقط على XML الخاص بالأجهزة.
•
--edit خيارات-الجهاز
تعديل كل كتلة XML تطابق خيارات الجهاز الممررة. تكون خيارات الجهاز بنفس التنسيق الذي سيُمرَّر إلى خيار XML.

لذا --edit path=/tmp/foo --disk خيارات-القرص يعني 'تحرير كل <disk> بمسار /tmp/foo'. هذا الخيار ينطبق حقًا فقط على XML الخاص بالأجهزة.

--add-device
إلحاق خيارات XML المحددة بقائمة <devices> في XML. مثال: '--add-device --disk خيارات-القرص' سينشئ كتلة <disk> جديدة ويضيفها إلى XML.

سيعطي هذا الخيار خطأ إذا تم تحديده مع خيار XML غير خاص بجهاز (راجع قسم --edit للحصول على قائمة جزئية).

--remove-device
إزالة الجهاز المحدد من XML. يتم اختيار الجهاز المراد إزالته بواسطة خيار XML، الذي يأخذ وسائط بنفس تنسيق --edit. أمثلة:
•
--remove-device --disk 2
إزالة جهاز القرص الثاني
•
--remove-device --network all
إزالة جميع أجهزة الشبكة
•
--remove-device --sound pcspk
إزالة جميع أجهزة الصوت ذات model='pcspk'

سيعطي هذا الخيار خطأ إذا تم تحديده مع خيار XML غير خاص بجهاز (راجع قسم --edit للحصول على قائمة جزئية).

--build-xml
فقط بناء XML المحدد، وطباعته إلى stdout. لا يُشترط وجود نطاق إدخال أو XML إدخال. مثال: '--build-xml --disk خيارات-القرص' سيطبع فقط جهاز <disk> الجديد.

ومع ذلك، إذا كان XML المُنشأ موجهًا لنطاق محدد، يُوصى بتمريره إلى virt-xml، حتى تتمكن الأداة من تعيين القيم الافتراضية المثلى.

سيعطي هذا الخيار خطأ إذا تم تحديده مع خيار XML لا يرتبط بشكل واضح بكتلة XML محددة، مثل --vcpus أو --memory.

خيارات الإخراج

تحدد هذه الخيارات الإجراء الذي يجب اتخاذه بعد تعديل XML. في الحالة الشائعة لا يلزم تحديدها، لأن 'إجراءات XML' ستستلزم إجراء إخراج افتراضيًا، موصوفًا بالتفصيل أعلاه. هذه مطلوبة فقط إذا كنت تريد تعديل الإخراج الافتراضي.

--update
إذا كان النطاق المحدد قيد التشغيل، فحاول تعديل إعدادات الآلة الافتراضية قيد التشغيل. إذا تم دمجه مع --edit، فهذه عملية تحديث. إذا تم دمجه مع --add-device، فهذا توصيل ساخن لجهاز. إذا تم دمجه مع --remove-device، فهذا فصل ساخن لجهاز.

ضع في اعتبارك أن معظم خصائص XML والأجهزة لا تدعم عمليات التحديث المباشر، لذا لا تتوقع أن تنجح في جميع الحالات.

افتراضيًا، هذا يستلزم أيضًا --define.

--define
تعريف تغيير XML المطلوب. هذا عادةً هو الافتراضي إذا لم يتم تحديد خيار إخراج، ولكن إذا تم تحديد خيار --print، فإن --define مطلوب لفرض التغيير.
--no-define
عدم تعريف XML صراحةً. على سبيل المثال إذا كنت تريد فقط تعديل حالة التشغيل لآلة افتراضية، فادمج هذا مع --update.
--start
بدء الآلة الافتراضية بعد تنفيذ التغييرات المطلوبة. إذا تم دمجه مع --no-define، فإن هذا سي
إنشاء إقلاع جهاز ظاهري مؤقت مع التغييرات المطلوبة.
--print-diff
طباعة تغيير XML المُنشأ بصيغة diff موحّدة. إذا تم تحديد خيار الإخراج هذا فقط، يتم تعطيل جميع خيارات الإخراج الأخرى ولا يتم إجراء أي تغيير دائم.
--print-xml
طباعة XML المُنشأ بالكامل. إذا تم تحديد خيار الإخراج هذا فقط، يتم تعطيل جميع خيارات الإخراج الأخرى ولا يتم إجراء أي تغيير دائم.
--confirm
قبل تعريف النطاق أو تحديثه، اعرض diff XML المُنشأ واطلب التأكيد تفاعليًا.

خيارات نظام تشغيل الضيف

--osinfo, --os-variant OS_VARIANT
تحسين إعدادات الضيف لنظام تشغيل محدد (مثل 'fedora29'، 'rhel7'، 'win10'). على الرغم من أنه ليس مطلوبًا، فإن تحديد هذا الخيار يُوصى به بشدة، لأنه يمكن أن يزيد الأداء بشكل كبير من خلال تحديد virtio ضمن تعديلات الضيف الأخرى.

إذا تم تثبيت الضيف باستخدام virt-manager الإصدار 2.0.0 أو أحدث، فلا ينبغي أن يكون تقديم هذه المعلومات ضروريًا، حيث سيتم تخزين متغير نظام التشغيل في إعدادات الضيف أثناء التثبيت وسيسترجعه virt-xml من هناك تلقائيًا.

استخدم الأمر virt-xml --osinfo list للحصول على قائمة متغيرات نظام التشغيل المقبولة. راجع osinfo-query os للحصول على مزيد من الإخراج.

راجع وثائق virt-install(1) للحصول على مزيد من التفاصيل حول --osinfo/--os-variant

خيارات التحويل

--convert-to-q35

الصيغة: --convert-to-q35 [OPTIONS]

تحويل إعدادات جهاز ظاهري موجود من نوع PC/i440FX إلى نوع Q35. يتكون هذا إلى حد كبير من:

  • تحويل طوبولوجيا الأجهزة من PCI إلى PCIe
  • تحويل أي تخزين IDE إلى SATA

قد تحتاج أيضًا إلى إجراء تغييرات في الإعدادات داخل الجهاز الظاهري للتعامل مع هذا. على سبيل المثال، قد لا يجد Windows 10 جهاز الإقلاع بعد التحويل من IDE إلى SATA. لكن الإقلاع في الوضع الآمن مرة واحدة قد يصلح ذلك.

الخيارات الفرعية هي:

num_pcie_root_ports=NUM
التحكم في عدد أجهزة وحدة التحكم pcie-root-port الافتراضية التي نضيفها إلى الجهاز الظاهري افتراضيًا.

--convert-to-vnc

الصيغة: --convert-to-vnc [OPTIONS]

تحويل جهاز ظاهري موجود لاستخدام جهاز رسومات VNC واحد حصريًا.

سيحاول إزالة جميع المراجع إلى أي إعدادات رسومات غير VNC، مثل Spice. على سبيل المثال:

  • سيتم استبدال أجهزة qxl
  • سيتم إزالة جميع أجهزة spicevmc وspiceport
  • سيتم تحويل spice GL إلى egl-headless

الخيارات الفرعية هي:

qemu-vdagent=on|off
إضافة جهاز qemu-vdagent إذا لم يكن أحدها مُهيأ بالفعل. يحل هذا محل بعض وظائف spice vdagent. القيمة الافتراضية هي off ولكن قد يتغير ذلك في المستقبل.

تُعدّل هذه الخيارات XML لفئة واحدة من عناصر XML. توجد وثائق أكثر اكتمالاً في virt-install(1).

بشكل عام، تُقابل هذه الخيارات XML الخاص بـ libvirt بشكل مباشر إلى حد كبير، والموثق على https://libvirt.org/formatdomain.html

سلاسل الخيارات تكون بالصيغة: --option opt=val,opt2=val2,... مثال: --disk path=/tmp/foo,shareable=on. يمكن استخدام الخصائص مع '--option opt=,'، لذا لمسح إعداد ذاكرة التخزين المؤقت لقرص يمكنك استخدام '--disk cache=,'

لأي خيار، استخدم --option=? لرؤية قائمة بجميع الخيارات الفرعية المتاحة، مثال: --disk=? أو --boot=?

كما يسرد إخراج --help بعض الأمثلة العامة. راجع قسم الأمثلة أدناه لبعض الأمثلة الشائعة.

يمتلك virt-xml تحديدًا بعض العمليات التي لا تنطبق حقًا على virt-install. أمثلة:

--boot refresh-machine-type=yes
تحديث قيمة XML <os><type machine=X></os> إلى أحدث قيمة يوفرها qemu. على سبيل المثال، إذا كان جهازك الظاهري يحتوي على قيمة نوع الجهاز pc-q35-4.0، فسيؤدي هذا إلى إعادة تعيين القيمة إلى q35، ويعمل بشكل مشابه مع أنواع الأجهزة الأخرى ذات الإصدارات. يكون هذا ضروريًا أحيانًا لتمكين إصلاحات أخطاء qemu، أو عندما يوقف qemu أنواع الأجهزة القديمة ويزيلها.

أمثلة

عرض قائمة بجميع الخيارات الفرعية التي يأخذها --disk و--network

# virt-xml --disk=? --network=?

تغيير <description> للنطاق 'EXAMPLE':

# virt-xml EXAMPLE --edit --metadata description="my new description"

# تمكين قائمة جهاز الإقلاع للنطاق 'EXAMPLE':

# virt-xml EXAMPLE --edit --boot menu=on

مسح تعريف <cpu> السابق للنطاق 'winxp'، وتغييره إلى 'host-model'، ولكن تأكيد diff تفاعليًا قبل الحفظ:

# virt-xml winxp --edit --cpu host-model,clearxml=yes --confirm

تغيير بطاقة الصوت الثانية إلى model=ich6 على 'fedora19'، ولكن إخراج diff فقط:

# virt-xml fedora19 --edit 2 --sound model=ich6 --print-diff

تحديث كلمة مرور كل جهاز رسومات إلى 'foo' للجهاز الظاهري قيد التشغيل 'rhel6':

# virt-xml rhel6 --edit all --graphics password=foo --update

إزالة مسار القرص من جهاز القرص hdc:

# virt-xml rhel6 --edit target=hdc --disk path=

تغيير جميع أجهزة القرص من النوع 'disk' لاستخدام cache=none، باستخدام XML من stdin، وطباعة XML الجديد إلى stdout.

# cat <xmlfile> | virt-xml --edit device=disk --disk cache=none

تغيير إدخال/إخراج القرص 'hda' إلى native واستخدام سياسة بدء التشغيل كـ 'optional'.

# virt-xml fedora20 --edit target=hda \
           --disk io=native,startup_policy=optional

تغيير جميع أجهزة المضيف لاستخدام driver_name=vfio للجهاز الظاهري 'fedora20' على الاتصال البعيد

# virt-xml --connect qemu+ssh://remotehost/system \
           fedora20 --edit all --hostdev driver_name=vfio

توصيل جهاز USB المضيف 001.003 أثناء التشغيل إلى النطاق قيد التشغيل 'fedora19':

# virt-xml fedora19 --update --add-device --hostdev 001.003

إضافة قناة spicevmc إلى النطاق 'winxp'، والتي ستكون متاحة بعد إيقاف تشغيل الجهاز الظاهري التالي.

# virt-xml winxp --add-device --channel spicevmc

إنشاء صورة قرص qcow2 بحجم 10G وإرفاقها بـ 'fedora18' لبدء تشغيل الجهاز الظاهري التالي:

# virt-xml fedora18 --add-device \
  --disk /var/lib/libvirt/images/newimage.qcow2,format=qcow2,size=10

نفس ما سبق، ولكن تأكد من إرفاق القرص بأنسب ناقل لنظام تشغيل الضيف من خلال تقديم معلومات عنه على سطر الأوامر:

# virt-xml fedora18 --osinfo fedora18 --add-device \
  --disk /var/lib/libvirt/images/newimage.qcow2,format=qcow2,size=10

فصل القرص vdb أثناء التشغيل من النطاق قيد التشغيل 'rhel7':

# virt-xml rhel7 --update --remove-device --disk target=vdb

إزالة جميع أجهزة الرسومات من الجهاز الظاهري 'rhel7' بعد إيقاف التشغيل التالي:

# virt-xml rhel7 --remove-device --graphics all

virt-xml(1) — Arch manual pages

NAME

virt-xml - manage virtual machine XML definitions

SYNOPSIS

virt-xml -c | --connect URI -d | --domain DOMAIN -e | --edit -l | --list -r | --remove -i | --info -p | --print -b | --build-xml -a | --add -N | --network -D | --disk -C | --graphics -m | --memory -f | --vcpus -w | --memorybacking -t | --tpm -T | --timestamp -u | --uuid -s | --serial -S | --sound -U | --usb -h | --hostdev -F | --filesystem -v | --video -k | --kernel -i | --initrd -c | --cmdline -r | --root -o | --os-variant -p | --cpu -c | --cache ... --qemu-commandline QEMU_COMMANDLINE -P | --patch -n | --no-patch --dry-run --confirm

DESCRIPTION

The virt-xml utility is designed to provide a simple interface for modifying virtual machine XML definitions, and for converting libvirt XML definitions to other formats.

This utility manipulates XML definitions using XPath expressions and patches, similar to how virsh operates.

OPTIONS

The following options are available for manipulating the XML definition:

  • -c, --connect URI: Connect to a non-default hypervisor. Default is QEMU/KVM.
  • -d, --domain DOMAIN: Specify the domain XML to operate on. If not specified, and not operating on a defined domain, a temporary domain is created.
  • -e, --edit: Edit the domain XML. This is the default mode if no other mode-specific option is provided.
  • -l, --list: List the domains that match the query.
  • -r, --remove: Remove the specified domain from the list.
  • -i, --info: Print information about the specified domain.
  • -p, --print: Print the resulting domain XML.
  • -b, --build-xml: Generate domain XML.
  • -a, --add: Add an XML fragment to the domain definition.
  • -N, --network: Modify the network configuration.
  • -D, --disk: Modify the disk configuration.
  • -C, --graphics: Modify the graphics configuration.
  • --memory -m: Modify memory configuration.
  • --memorybacking -w: Modify memory backing configuration.
  • --tpm -t: Modify TPM configuration.
  • --timestamp -T: Modify timestamp configuration.
  • --uuid -u: Modify UUID.
  • --serial -s: Modify serial port configuration.
  • --sound -S: Modify sound card configuration.
  • --usb -U: Modify USB host device configuration.
  • --hostdev -h: Modify host device configuration.
  • --filesystem -F: Modify filesystem configuration.
  • --video -v: Modify video configuration.
  • --kernel -k: Modify kernel boot configuration.
  • --initrd -i: Modify initrd boot configuration.
  • --cmdline -c: Modify kernel command line.
  • --root -r: Modify root device configuration.
  • --os-variant -o: Modify OS variant.
  • --cpu -p: Modify CPU configuration.
  • --cache -c: Modify cache settings.
  • --qemu-commandline QEMU_COMMANDLINE: Add a raw QEMU command line argument.
  • -P, --patch: Apply a patch to the XML definition. The patch should be in unified diff format.
  • -n, --no-patch: Do not apply any patches. This is useful when only a simple edit is needed.
  • --dry-run: Show what changes would be made, but do not apply them.
  • --confirm: Prompt for confirmation before applying changes.

XML ACTIONS

The following actions can be performed on the XML definition:

# virt-xml --build-xml --console pty,target_type=virtio

Add qemu command line passthrough:

# virt-xml f25 --edit --confirm --qemu-commandline="-device FOO"

Use boot device 'network' for a single transient boot:

# virt-xml myvm --no-define --start --edit --boot network

CAVEATS

Virtualization hosts supported by libvirt may not permit all changes that might seem possible. Some edits made to a VM's definition may be ignored. For instance, QEMU does not allow the removal of certain devices once they've been defined.
