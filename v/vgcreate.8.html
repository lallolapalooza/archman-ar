الاسم

vgcreate — إنشاء مجموعة وحدات

الملخص

vgcreate مُعاملات_الموضع
[ مُعاملات_الخيار ]

الوصف

يقوم vgcreate بإنشاء مجموعة وحدات (VG) جديدة على أجهزة الكتل. إذا لم يتم تهيئة الأجهزة مسبقًا كوحدات فعلية (PVs) باستخدام pvcreate(8)، فسيقوم vgcreate بتهيئتها، مما يجعلها وحدات فعلية (PVs). خيارات pvcreate لتهيئة الأجهزة متاحة أيضًا مع vgcreate.

عندما يستخدم vgcreate وحدة فعلية (PV) موجودة، يتم استخدام القيم الموجودة لوحدة PV الخاصة بحجم البيانات الوصفية، وبداية PE، وما إلى ذلك، حتى لو تم تحديد قيم مختلفة في أمر vgcreate. لتغيير هذه القيم، استخدم pvremove على الجهاز أولاً.

الخيارات

--addtag علامة
تضيف علامة إلى PV أو VG أو LV. يمكن تكرار هذا الخيار لإضافة علامات متعددة في وقت واحد. انظر lvm(8) للحصول على معلومات حول العلامات.
--alloc contiguous|cling|cling_by_tags|normal|anywhere|inherit
يحدد سياسة التخصيص عندما يحتاج الأمر إلى تخصيص أقسام فعلية (PEs) من VG. كل VG و LV لديها سياسة تخصيص يمكن تغييرها باستخدام vgchange/lvchange، أو تجاوزها في سطر الأوامر. normal يطبق قواعد المنطق السليم مثل عدم وضع أشرطة متوازية على نفس PV. inherit يطبق سياسة VG على LV. contiguous يتطلب وضع أقسام PEs الجديدة بجوار أقسام PEs الموجودة. cling يضع أقسام PEs الجديدة على نفس PV مثل أقسام PEs الموجودة في نفس شريط LV. إذا كانت هناك أقسام PEs كافية للتخصيص، ولكن normal لا يستخدمها، فإن anywhere سيستخدمها حتى لو قلل من الأداء، على سبيل المثال عن طريق وضع شريطين على نفس PV. يمكن أيضًا استخدام وسيطات PV الموضعية الاختيارية في سطر الأوامر لتقييد أقسام PVs التي سيستخدمها الأمر للتخصيص. انظر lvm(8) لمزيد من المعلومات حول التخصيص.
-A|--autobackup y|n
يحدد ما إذا كان يجب عمل نسخة احتياطية للبيانات الوصفية تلقائيًا بعد التغيير. يُنصح بشدة بتمكين هذا! انظر vgcfgbackup(8) لمزيد من المعلومات.
-c|--clustered y|n
كان هذا الخيار خاصًا بـ clvm وتم استبداله الآن بالخيار --shared مع lvmlockd(8).
--commandprofile سلسلة
ملف تعريف الأمر المراد استخدامه لتكوين الأمر. انظر lvm.conf(5) لمزيد من المعلومات حول ملفات التعريف.
--config سلسلة
إعدادات التكوين للأمر. هذه تتجاوز إعدادات lvm.conf(5). تستخدم الوسيطة السلسلة نفس تنسيق lvm.conf(5)، أو قد تستخدم بناء الجملة للقسم/الحقل. انظر lvm.conf(5) لمزيد من المعلومات حول التكوين.
--dataalignment الحجم[k|UNIT]
محاذاة بداية منطقة بيانات PV مع مضاعف لهذا الرقم. لمعرفة موقع أول قسم فعلي (PE) لوحدة PV موجودة، استخدم pvs -o +pe_start. بالإضافة إلى ذلك، قد يتم إزاحتها بمسافة إزاحة للمحاذاة، انظر --dataalignmentoffset. حدد أيضًا حجم PE مناسبًا عند إنشاء VG.
--dataalignmentoffset الحجم[k|UNIT]
إزاحة بداية منطقة بيانات PV بهذه المسافة الإضافية.
-d|--debug ...
ضبط مستوى التصحيح. كرر من 1 إلى 6 مرات لزيادة تفاصيل الرسائل المرسلة إلى ملف السجل و/أو syslog (إذا تم تكوينه).
--devices PV
يقيّد الأجهزة التي يمكن رؤيتها والوصول إليها بواسطة الأمر. الأجهزة غير المدرجة ستظهر على أنها مفقودة. يمكن تكرار هذا الخيار، أو يقبل قائمة مفصولة بفواصل للأجهزة. هذا يتجاوز ملف الأجهزة.
--devicesfile سلسلة
ملف يسرد الأجهزة التي يجب أن يستخدمها LVM. يجب أن يكون الملف موجودًا في /etc/lvm/devices/ ويتم إدارته بواسطة الأمر lvmdevices(8). هذا يتجاوز إعدادات lvm.conf(5) devices/devicesfile و devices/use_devicesfile.
--driverloaded y|n
إذا تم تعيينه على لا، فلن يحاول الأمر استخدام device-mapper. للاختبار والتصحيح.
-f|--force ...
تجاوز الفحوصات والتأكيدات والحمايات المختلفة. استخدم بحذر شديد.
-h|--help
عرض نص المساعدة.
--journal سلسلة
تسجيل المعلومات في سجل systemd. هذه المعلومات بالإضافة إلى المعلومات الممكّنة بواسطة إعداد السجل/اليومية في lvm.conf. command: تسجيل معلومات حول الأمر. output: تسجيل الإخراج الافتراضي للأمر. debug: تسجيل تفاصيل الأمر الكاملة.
--labelsector الرقم
افتراضيًا، يتم تسمية PV بمعرّف LVM2 في قطاعه الثاني (القطاع 1). هذا يسمح لك باستخدام قطاع مختلف بالقرب من بداية القرص (بين 0 و 3 شاملة - انظر LABEL_SCAN_SECTORS في المصدر). استخدمه بحذر.
--lockopt سلسلة
يستخدم لتمرير خيارات للحالات الخاصة إلى lvmlockd. انظر lvmlockd(8)<

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

OPTIONS

-a|--alloc AllocationPolicy
Determines which Physical Volumes the Logical Volume Manager selects when allocating space. See lvm.conf(5) for more information.
-A|--autobackup Set
Enable or disable the automatic backup of metadata. Default is to enable. Metadata is backed up to /etc/lvm/backup/. Setting this to 0 disables backups. Setting this to 1 enables backups. Metadata is backed up to /etc/lvm/archive/ on a LVM2 host. Setting this to 2 enables backups and also archives them. Setting this to 3 enables backups and archives them and also prevents LVM from automatically backing up metadata on this command. This is useful for preventing backup of metadata on LVM1 hosts. See lvm.conf(5) for more information.
-C|--chkhelp
Check for help information for command options.
-c|--devices Device
List of devices that LVM commands will use. For example: --devices /dev/sd[a-z] /dev/md/*
-d|--debug ...
Set debug level. Repeat from 1 to 4 times to increase the detail of messages sent to stdout and stderr.
-f|--force
Attempt to force the operation. Use with caution.
-g|--commit
Commit the metadata and update the VG on disk. This is the default behaviour. Use --commit 0 to disable. See lvm.conf(5) for more information.
-h|--help
Display help text.
-i|--interval Seconds
The interval at which to check for updates to the metadata. The default is 30 seconds. Setting to 0 disables the interval check.
-j|--jobs Number
Set the number of parallel jobs to run.
-k|--keepkeys
Do not assign a new UUID to the VG. Use the existing UUID.
-L|--logicalvolumessize Size[UNIT]
Sets the size of the logical volume. The size is specified as a number followed by an optional unit (see Size unit convention below).
-l|--logicalvolumes Number
Sets the maximum number of LVs allowed in a VG.
--locktype sanlock|dlm|none
Specify the VG lock type directly in place of using --shared. See lvmlockd(8) for more information.
--longhelp
Display long help text.
-l|--maxlogicalvolumes Number
Sets the maximum number of LVs allowed in a VG.
-p|--maxphysicalvolumes Number
Sets the maximum number of PVs that can belong to the VG. The value 0 removes any limitation. For large numbers of PVs, also see options --pvmetadatacopies, and --vgmetadatacopies for improving performance.
--metadataprofile String
The metadata profile to use for command configuration. See lvm.conf(5) for more information about profiles.
--metadatasize Size[m|UNIT]
The approximate amount of space used for each VG metadata area. The size may be rounded.
-M|--metadatatype lvm2
Specifies the type of on-disk metadata to use. lvm2 (or just 2) is the current, standard format. lvm1 (or just 1) is no longer used.
--nohints
Do not use the hints file to locate devices for PVs. A command may read more devices to find PVs when hints are not used. The command will still perform standard hint file invalidation where appropriate.
--nolocking
Disable locking. Use with caution, concurrent commands may produce incorrect results.
--persist String
Persistent Reservation operation. start: register local key and acquire reservation. stop: unregister local key, releasing reservation. remove: preempt and abort another key. clear: remove reservation and keys. check: check if started. autostart: start if the VG autostart flag is set. lvmlocal.conf pr_key or host_id must be configured to use PR. For local VGs, Write Exclusive (WE) is used, and for shared VGs Write Exclusive, all registrants (WEAR) is used. Use --setpersist to automate and/or require PR.
-s|--physicalextentsize Size[m|UNIT]
Sets the physical extent size of PVs in the VG. The value must be either a power of 2 of at least 1 sector (where the sector size is the largest sector size of the PVs currently used in the VG), or at least 128 KiB. Once this value has been set, it is difficult to change without recreating the VG, unless no extents need moving.
--profile String
An alias for --commandprofile or --metadataprofile, depending on the command.
--pvmetadatacopies 0|1|2
The number of metadata areas to set aside on a PV for storing VG metadata. When 2, one copy of the VG metadata is stored at the front of the PV and a second copy is stored at the end. When 1, one copy of the VG metadata is stored at the front of the PV. When 0, no copies of the VG metadata are stored on the given PV. This may be useful in VGs containing many PVs (this places limitations on the ability to use vgsplit later.)
-q|--quiet ...
Suppress output and log messages. Overrides --debug and --verbose. Repeat once to also suppress any prompts with answer 'no'.
--reportformat basic|json|json_std
Overrides current output format for reports which is defined globally by the report/output_format setting in lvm.conf(5). basic is the original format with columns and rows. If there is more than one report per command, each report is prefixed with the report name for identification. json produces report output in JSON format. json_std produces report output in JSON format which is more compliant with JSON standard. See lvmreport(7) for more information.
--setautoactivation y|n
Set the autoactivation property on a VG or LV. Display the property with vgs or lvs "-o autoactivation". When the autoactivation property is disabled, the VG or LV will not be activated by a command doing autoactivation (vgchange, lvchange, or pvscan using -aay.) If autoactivation is disabled on a VG, no LVs will be autoactivated in that VG, and the LV autoactivation property has no effect. If autoactivation is enabled on a VG, autoactivation can be disabled for individual LVs.
--setlockargs String
Add or remove lock_args settings for a shared VG. The lock_args determine lock manager behavior for the VG. These settings are only allowed for lock_type sanlock. persist: use persistent reservations for lock recovery. lvmlockd will preempt-abort the persistent reservation of a failed lock owner so that the lock can be acquired. notimeout: use locks that do not time out when the owner fails. In this case, a lock owned by a failed host can only be acquired using the persist feature. nopersist: do not use the persist feature. timeout: do not use the notimeout feature. The default behavior with no settings configured is: nopersist and timeout.
--setpersist String
Set flags to control persistent reservation behavior. y: set require and autostart flags. require: PR will be required to write or activate VG. autostart: PR will be automatically started. ptpl: use persist through power loss on devices. When autostart is enabled, autoactivation and auto-lockstart commands will first start PR. lvmlocal.conf pr_key or host_id must be configured to use PR. For local VGs, enabling system_id is also recommended.
--shared
Create a shared VG using lvmlockd if LVM is compiled with lockd support. lvmlockd will select lock type sanlock or dlm depending on which lock manager is running. This allows multiple hosts to share a VG on shared devices. lvmlockd and a lock manager must be configured and running. See lvmlockd(8) for more information about shared VGs.
--systemid String
Specifies the system ID that will be given to the new VG, overriding the system ID of the host running the command. A VG is normally created without this option, in which case the new VG is given the system ID of the host creating it. Using this option requires caution because the system ID of the new VG may not match the system ID of the host running the command, leaving the VG inaccessible to the host. See lvmsystemid(7) for more information.
-t|--test
Run in test mode. Commands will not update metadata. This is implemented by disabling all metadata writing but nevertheless returning success to the calling function. This may lead to unusual error messages in multi-stage operations if a tool relies on reading back metadata it believes has changed but hasn't.
-v|--verbose ...
Set verbose level. Repeat from 1 to 4 times to increase the detail of messages sent to stdout and stderr.
--version
Display version information.
--[vg]metadatacopies all|unmanaged|Number
Number of copies of the VG metadata that are kept. VG metadata is kept in VG metadata areas on PVs in the VG, i.e. reserved space at the start and/or end of the PVs. Keeping a copy of the VG metadata on every PV can reduce performance in VGs containing a large number of PVs. When this number is set to a non-zero value, LVM will automatically choose PVs on which to store metadata, using the metadataignore flags on PVs to achieve the specified number. The number can also be replaced with special string values: unmanaged causes LVM to not automatically manage the PV metadataignore flags. all causes LVM to first clear the metadataignore flags on all PVs, and then to become unmanaged.
-y|--yes
Do not prompt for confirmation interactively but always assume the answer yes. Use with extreme caution. (For automatic no, see -qq.)
-Z|--zero y|n
Controls if the first 4 sectors (2048 bytes) of the device are wiped. The default is to wipe these sectors unless either or both of --restorefile or --uuid are specified.

VARIABLES

VG
Volume Group name. See lvm(8) for valid names.
PV
Physical Volume name, a device path under /dev. For commands managing physical extents, a PV positional arg generally accepts a suffix indicating a range (or multiple ranges) of physical extents (PEs). When the first PE is omitted, it defaults to the start of the device, and when the last PE is omitted it defaults to end.
Start and end range (inclusive): PV[:PE-PE] ...
Start and length range (counting from 0): PV[:PE+PE] ...
String
See the option description for information about the string content.
Size[UNIT]
Size is an input number that accepts an optional unit. Input units are always treated as base two values, regardless of capitalization, e.g. 'k' and 'K' both refer to 1024. The default input unit is specified by letter, followed by |UNIT. UNIT represents other possible input units: b|B is bytes, s|S is sector

NAME

vgcreate

create a volume group

SYNOPSIS

vgcreate [-] [-a|--autobackup { y | n }] [-b|--backup { y | n }] [-c|--clustered { y | n }] [-d|--debug] [-f|--force] [-h|--help] [-l|--limits] [-M|--metadatatype { 0 | 1 }] [-m|--monitor { y | n }] [-p|-- يعني PhysicalExtents] [-S|--physicalextentsize PhysicalExtentSize] [-t|--test] [-u|--uuid] [-v|--verbose] [--] VolumeGroupName PhysicalVolume[PhysicalVolume...]

DESCRIPTION

Creates a new volume group VolumeGroupName from one or more physical volumes. A volume group is a pool of storage that can be accessed by Volume Manager. The VolumeGroupName must be unique in the system. The physical volumes specified by PhysicalVolume[PhysicalVolume...] are added to the new volume group.

If vgcreate(8) finds any LVM metadata on a physical volume, it will prompt the user to confirm that the volume should be reused. If the vgcreate(8) command is run with the -f (force) option, the user will not be prompted.

The VGDA (Volume Group Descriptor Area) is stored on each physical volume that is part of the volume group. The VGDA contains information about the volume group, the physical volumes that belong to it, and the logical volumes that are defined within it. A backup of the VGDA is kept in /etc/lvm/backup/VolumeGroupName and /etc/lvm/archive/VolumeGroupName.0.

USAGE

The physical extent size is the smallest amount of storage that can be allocated to a logical volume. The default physical extent size is 4 MiB. The size must be a power of 2. For example, 1024 is 1 KiB, 512 is 512 bytes.

You can specify the physical extent size with the -S option. If you do not specify a size, the default size is used.

You can also specify the number of physical extents per physical volume with the -p option. The default is to use all available space on the physical volume.

OPTIONS

-a, --autobackup y|n
Enables or disables the automatic backup of metadata. Default is yes.
-b, --backup y|n
Enables or disables the backup of metadata. Default is yes.
-c, --clustered y|n
If set to y, the volume group is created as a clustered volume group. This allows the volume group to be used by multiple hosts in a cluster. Default is no.
-d, --debug
Enables debug messages.
-f, --force
Forces the reuse of a physical volume that already contains LVM metadata.
-h, --help
Displays help information.
-l, --limits
Displays the limits of the volume group.
-M, --metadatatype 0|1
Sets the metadata type. Type 1 is the default and is recommended.
-m, --monitor y|n
If set to y, the volume group is created with monitoring enabled. This allows the volume group to be monitored for changes in the status of its physical volumes. Default is yes.
-p, -- يعني PhysicalExtents
Sets the number of physical extents per physical volume. Default is all available space.
-S, --physicalextentsize PhysicalExtentSize
Sets the physical extent size. The default is 4 MiB. The size can be specified in bytes, or in the following units:
b|B: 512 bytes
s|S: 512 bytes
k|K: KiB (1024 bytes)
m|M: MiB (1024 KiB)
g|G: GiB (1024 MiB)
t|T: TiB (1024 GiB)
p|P: PiB (1024 TiB)
e|E: EiB (1024 PiB)
(This should not be confused with the output control --units, where capital letters mean multiple of 1000.)
-t, --test
Perform a simulation of the command without making any changes.
-u, --uuid
Generates a new UUID for the volume group.
-v, --verbose
Enables verbose output.

ENVIRONMENT VARIABLES

See lvm(8) for information about environment variables used by lvm. For example, LVM_VG_NAME can generally be substituted for a required VG parameter.

EXAMPLES

Create a VG with two PVs, using the default physical extent size.
vgcreate myvg /dev/sdk1 /dev/sdl1
