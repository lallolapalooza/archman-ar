val_dane_match(3)

الحزمة: dnssec-tools

التراخيص: BSD

val_getdaneinfo(3) دليل المبرمج val_getdaneinfo(3)

الاسم

val_getdaneinfo(3) - إجراء تحقق متزامن لسجلات TLSA

val_dane_submit(3) - إجراء تحقق غير متزامن لسجلات TLSA

val_dane_match(3) - التحقق من معلومات TLSA مقابل البيانات المقدمة.

val_dane_check(3) - التحقق من معلومات TLSA لاتصال SSL (OpenSSL فقط)

val_free_dane(3) - تحرير الذاكرة المرتبطة بهيكل نتيجة DANE.

p_dane_error(3) - إرجاع سلسلة الخطأ لرمز خطأ DANE معين.

ملخص

#include <validator/validator.h>
#include <validator/val_dane.h>
int val_getdaneinfo(val_context_t *ctx,
                  const char *name,
                  struct val_daneparams *params,
                  struct val_danestatus **dres);
int val_dane_submit(val_context_t *ctx,
                  const char *name,
                  struct val_daneparams *params,
                  val_dane_callback callback,
                  void *callback_data,
                  val_async_status **status);
int val_dane_match(val_context_t *ctx,
                 struct val_danestatus *dane_cur,
                 const unsigned char *databytes,
                 int databyteslen);
#include <openssl/ssl.h>
int val_dane_check(val_context_t *ctx,
                 SSL *con,
                 struct val_danestatus *danestatus,
                 int *do_pathval);
void val_free_dane(struct val_danestatus *dres);
const char *p_dane_error(int rc);

الوصف

val_getdaneinfo() يقوم بإجراء بحث متزامن لسجل TLSA المرتبط بـ name معين ويعيد قائمة مرتبطة بجميع سجلات التي تم التحقق منها. val_dane_submit() يقوم بنفس البحث بطريقة غير متزامنة ويستدعي الدالة callback مع وسيطات callback_data عند اكتمال البحث. الدالة الاستدعاء الخلفي لها التعريف النوعي التالي:

typedef int (*val_dane_callback)(void *callback_data,
                               int retval,
                               struct val_danestatus **dres);

يوفر الوسيط status مقبضًا لطلب غير متزامن لتمكين العمليات المستقبلية (مثل إلغاء الطلب). لمزيد من المعلومات حول الكائن val_async_status انظر draft-hayatnagarkar-dnsext-validator-api.

اسم DNS الفعلي الذي يمتلك سجل TLSA في DNS له بادئة بالشكل _<port>._<proto>. val_getdaneinfo() سيقوم ببناء البادئة المذكورة أعلاه تلقائيًا؛ لذلك يجب ألا يحتوي الاسم name المقدم من المستخدم على هذه البادئة. الـ

يجب توفير المعلمات لبحث TLSA في الوسيط params، وهو مؤشر إلى الهيكل التالي:

struct val_daneparams {
  int port;
  int proto;
};

يتم استخدام حقلي port و proto في بناء البادئة لاسم TLSA الموضحة أعلاه.

يتم إرجاع نتائج بحث TLSA في الوسيط dres، وهو مؤشر إلى قائمة مرتبطة بالهياكل التالية:

struct val_danestatus {
  long ttl;
  int usage;
  int selector;
  int type;
  size_t datalen;
  unsigned char *data;
  struct val_danestatus *next;
};

الحقل ttl هو وقت البقاء المرتبط بسجل TLSA. لا يجب على التطبيق تخزين (واستخدام) سجل TLSA هذا بعد انتهاء مدة صلاحيته (TTL). الحقول usage و selector و type تتوافق مع الحقول الثلاثة الأولى من RDATA الخاص بـ TLSA كما هو موضح في rfc6698. يتم إرجاع بيانات ارتباط شهادة TLSA في الحقل data ويبلغ طولها datalen بايت. قد يكون هناك أكثر من سجل TLSA واحد مرتبط باسم معين، ويشير الحقل next إلى السجل التالي في هذه القائمة.

بالنظر إلى قائمة مرتبطة من هياكل TLSA في dres، يمكن استخدام val_dane_match() للتحقق مما إذا كانت بيانات ارتباط الشهادة لعنصر معين في هذه القائمة تتطابق مع البيانات المشفرة بنمط DER المقدمة في databytes بطول databyteslen.

تقوم الدالة val_dane_check() بتبسيط عملية المطابقة عندما يتم استخدام OpenSSL لتوفير دعم SSL/TLS داخل التطبيق. هذه الدالة تقوم تلقائيًا بالتكرار عبر جميع العناصر في dres وتقارن بيانات ارتباط الشهادة مع شهادات SSL/TLS المرتبطة باتصال SSL con. يسمح بروتوكول DANE بحالات استخدام معينة تسمح بتقديم أصول ثقة جديدة عبر DNSSEC. تشير قيمة do_pathval إلى ما إذا كان يجب على التطبيق المتابعة مع التحقق من مسار X509 لهذا الاتصال وفقًا للاستخدام الذي تم تشفيره في سجل TLSA.

تقوم الدالة val_free_dane() بتحرير الذاكرة المرتبطة بالقائمة المرتبطة المشار إليها بواسطة dres.

يحدد الوسيط ctx في جميع الدوال المذكورة أعلاه سياق التحقق، والذي يمكن تعيينه إلى NULL للقيم الافتراضية (انظر libval(3) و dnsval.conf لمزيد من التفاصيل حول سياقات التحقق وسياسة التحقق).

قيم الإرجاع

val_getdaneinfo() و val_dane_submit() ترجعان VAL_DANE_NOERROR عند النجاح، و VAL_DANE_MALFORMED_TLSA أو VAL_DANE_INTERNAL_ERROR لحالات الخطأ. يتم إرجاع القيمة VAL_DANE_NOTVALIDATED إذا لم يكن بالإمكان التحقق من سجل TLSA عبر DNSSEC. يتم إرجاع القيمة VAL_DANE_IGNORE_TLSA إذا كان سجل TLSA للاسم المحدد غائبًا بشكل مثبت.

يمكن أن تحتوي القيمة retval التي تم إرجاعها كوسيط للدالة val_dane_callback() على واحدة من VAL_DANE_NOERROR (للنجاح)، VAL_DANE_INTERNAL_ERROR (لحالات الخطأ) أو VAL_DANE_CANCELLED (عند إلغاء الطلب غير المتزامن).

val_dane_match() و val_dane_check() ترجعان VAL_DANE_NOERROR عند النجاح، VAL_DANE_INTERNAL_ERROR لحالات الخطأ العامة، و VAL_DANE_CHECK_FAILED إذا لم يكن بالإمكان مطابقة سجل TLSA بنجاح مقابل بيانات ارتباط الشهادة المقدمة.

يمكن استخدام الدالة p_dane_error() لتحويل رموز الخطأ المتعلقة بـ DANE إلى قيمة سلسلة خطأ.
