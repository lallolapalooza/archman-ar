The val_resolve_and_check is a library function that performs the necessary DNSSEC validation for a specific hostname. It takes the hostname and a pointer to a val_list_t structure as input and returns a status code indicating the result of the validation.

This function is part of the dnssec-tools library, which provides tools for DNSSEC operations.

DESCRIPTION

The val_resolve_and_check function attempts to resolve the DNS records for the given hostname and perform DNSSEC validation on the retrieved data. It utilizes the data structures and configurations provided in the val_list_t structure to guide the resolution and validation process.

The val_list_t structure is a fundamental component for managing the state and configuration of the validation process. It holds information such as:

“vl_rsapubkey”
A pointer to a list of RSA public keys, which are used for verifying signatures.
“vl_dskey”
A pointer to a list of DS (Delegation Signer) keys, used for establishing trust anchors.
“vl_context”
A context structure that may contain various settings and parameters for the validation process, such as DNS server addresses, port numbers, and timeout values.
“vl_flags”
Flags that control the behavior of the validation process, such as whether to perform NSEC or NSEC3 validation, or whether to trust pre-configured keys.

The function performs the following actions:

  • Resolves the DNS records (e.g., A, AAAA, MX) for the specified hostname.
  • Retrieves the corresponding DNSSEC records (e.g., RRSIG, DNSKEY, DS).
  • Validates the cryptographic signatures using the provided public keys and DS records.
  • Checks the chain of trust from the hostname up to a configured trust anchor.
  • Returns a status code indicating whether the validation was successful, failed, or if an error occurred.

DATA STRUCTURES

The primary data structure used by this function is:

val_list_t
This structure holds the validation context and keys required for performing DNSSEC validation. It typically includes:
typedef struct val_list {
    // RSA public keys for verification
    val_list_rsa_key_t *vl_rsapubkey;
    // DS keys for trust anchor establishment
    val_list_ds_key_t *vl_dskey;
    // Validation context (e.g., DNS server, port, flags)
    val_context_t *vl_context;
    // Flags to control validation behavior
    unsigned int vl_flags;
    // ... other members ...
} val_list_t;

The exact members and their types may vary depending on the version of the library. It is recommended to consult the library's documentation for the precise definition of val_list_t and related structures.

LOGGING

The validation library supports logging of various events and errors. The logging level can be controlled to obtain different levels of information.

VAL_LOG_NONE
No logging is performed.
VAL_LOG_ERR
Logs only error messages.
VAL_LOG_INFO
Logs informational messages, including validation results.
VAL_LOG_DEBUG
Logs detailed debug information for troubleshooting.
VAL_LOG_ALL
Logs all available information, including authentication chains.
Debug
This is likely a typo or an internal constant related to debug levels, possibly equivalent to VAL_LOG_DEBUG or a more verbose level.

RETURN VALUES

Return values for various functions are given below. These values can be displayed in ASCII format using the p_val_error() function.

VAL_NO_ERROR
No error was encountered.
VAL_NOT_IMPLEMENTED
Functionality not yet implemented.
VAL_RESOURCE_UNAVAILABLE
Some resource (crypto possibly) was unavailable. Currently not implemented.
VAL_BAD_ARGUMENT
Bad arguments passed as parameters.
VAL_INTERNAL_ERROR
Encountered some internal error.
VAL_NO_PERMISSION
No permission to perform operation. Currently not implemented.
VAL_CONF_PARSE_ERROR

VAL_CONF_NOT_FOUND
A configuration file was not available.
VAL_NO_POLICY
The policy identifier being referenced was invalid.

FILES

The validator library reads configuration information from two files, resolv.conf and dnsval.conf.

See dnsval.conf(5) for a description of the syntax for these files.
