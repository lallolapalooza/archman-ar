VI(1P) دليل مبرمج POSIX VI(1P)

مقدمة

صفحة الدليل هذه جزء من دليل مبرمج POSIX. قد يختلف تطبيق Linux لهذا الواجهة (استشر صفحة دليل Linux المقابلة لتفاصيل سلوك Linux)، أو قد لا تكون الواجهة مطبقة على Linux.

الاسم

vi — محرر شاشة مرئي

ملخص

vi [-rR] [-c أمر] [-t وسم_النص] [-w حجم] [ملف...]

الوصف

يجب توفير هذه الأداة على الأنظمة التي تدعم خيار أدوات منفعة المستخدم وقابليته للنقل وتحدد الرمز POSIX2_CHAR_TERM. على الأنظمة الأخرى، فإنها اختيارية.

الأداة vi (مرئي) هي محرر نصوص موجه بالشاشة. لا يتم وصف سوى الأوضاع المفتوحة والمرئية للمحرر في POSIX.1-2008؛ راجع محرر الأسطر ex للحصول على قدرات تحرير إضافية مستخدمة في vi. يمكن للمستخدم التبديل ذهابًا وإيابًا بين vi و ex وتنفيذ أوامر ex من داخل vi.

تستخدم صفحة المرجع هذه مصطلح مخزن التحرير المؤقت لوصف النص الحالي قيد العمل. لا يعني هذا المصطلح أي تطبيق محدد. يتم إجراء جميع تغييرات التحرير على المخزن المؤقت للتحرير، ولا تؤثر أي تغييرات عليه على أي ملف حتى يقوم أمر المحرر بكتابة الملف.

عند استخدام vi، تعمل شاشة الجهاز كنافذة على المخزن المؤقت للتحرير. يجب أن تنعكس التغييرات التي تم إجراؤها على المخزن المؤقت للتحرير في عرض الشاشة؛ يجب أن يشير موضع المؤشر على الشاشة إلى الموضع داخل المخزن المؤقت للتحرير.

بعض الأجهزة لا تمتلك جميع القدرات اللازمة لدعم التعريف الكامل لـ vi. عندما لا يمكن دعم هذه الأوامر على مثل هذه الأجهزة، لا يجب أن يؤدي هذا الشرط إلى رسالة خطأ مثل "ليس أمر تحرير" أو الإبلاغ عن خطأ في بناء الجملة. قد يقوم التطبيق إما بقبول الأوامر وإنتاج نتائج على الشاشة تكون نتيجة لمحاولة فاشلة لتلبية متطلبات هذا المجلد من POSIX.1-2017 أو الإبلاغ عن خطأ يصف النقص المتعلق بالجهاز.

Column Position Calculation

The display column for a character in the buffer is not necessarily the same as the column in the display. This occurs when a line in the buffer is wider than the current screen width and wraps onto additional display lines. In this case, however, the column position in the display shall be calculated for an infinite width display; for example, the column related to a character that is part of a line that has been folded onto additional screen lines will be offset from the display line column where the buffer line begins, not from the beginning of a particular display line.

The display cursor column in the display is based on the value of the current column, as follows, with each rule applied in turn:

1.
If the current column is after the last display line column used by the displayed line, the display cursor column shall be set to the last display line column occupied by the last non-<newline> in the current line; otherwise, the display cursor column shall be set to the current column.
2.
If the character of which some portion is displayed in the display line column specified by the display cursor column requires more than a single display line column:
a.
If in text input mode, the display cursor column shall be adjusted to the first display line column in which any portion of that character is displayed.
b.
Otherwise, the display cursor column shall be adjusted to the last display line column in which any portion of that character is displayed.

The current column shall not be changed by these adjustments to the display cursor column.

If an error occurs during the parsing or execution of a vi command:

*
The terminal shall be alerted. Execution of the vi command shall stop, and the cursor (for example, the current line and column) shall not be further modified.
*
Unless otherwise specified by the following command sections, it is unspecified whether an informational message shall be displayed.
*
Any partially entered vi command shall be discarded.
*
If the vi command resulted from a map expansion, all characters from that map expansion shall be discarded, except as otherwise specified by the map command (see ex).
*
If the vi command resulted from the execution of a buffer, no further commands caused by the execution of the buffer shall be executed.

Synopsis:

If in open mode, the <control>‐B command shall behave identically to the z command. Otherwise, if the current line is the first line of the edit buffer, it shall be an error.

otherwise, display a screen where the first line of the display shall be some portion of:

Scroll Forward

Synopsis:
[count] <control>-D

If the current line is the last line of the edit buffer, it shall be an error.

If no count is specified, count shall default to the count associated with the previous <control>‐D or <control>‐U command. If there was no previous <control>‐D or <control>‐U command, count shall default to the value of the scroll edit option.

If in open mode, write lines starting with the line after the current line, until count lines or the last line of the file have been written.

Current line: If the current line + count is past the last line of the edit buffer, set to the last line of the edit buffer; otherwise, set to the current line + count.

Current column: Set to non-<blank>.

Scroll Forward by Line

Synopsis:
[count] <control>-E

Display the line count lines after the last line currently displayed.

If the last line of the edit buffer is displayed, it shall be an error. If there is no line count lines after the last line currently displayed, the last line of the display shall display some portion of the last line of the edit buffer.

Current line: Unchanged if the previous current character is displayed; otherwise, set to the first line displayed.

Current column: Unchanged.

Yank

تاريخيًا، لم ينتقل الأمر yank إلى نهاية الحركة إذا كانت الحركة في الاتجاه الأمامي. لقد انتقل إلى نهاية الحركة إذا كانت الحركة في الاتجاه الخلفي، باستثناء الأمر _، أو لأوامر G و ' عندما كانت نهاية الحركة على السطر الحالي. تعقد هذا الأمر حقيقة أن عددًا من أوامر الحركة، أمر yank حرك المؤشر ولكنه لم يقم بتحديث الشاشة؛ على سبيل المثال، سينقل أمر لاحق المؤشر من نهاية الحركة، على الرغم من أن المؤشر على الشاشة لم يعكس حركة المؤشر لأمر yank. يتطلب POSIX.1-2008 أن تقوم جميع أوامر yank المرتبطة بالحركات الخلفية بنقل المؤشر إلى نهاية الحركة من أجل الاتساق، وبشكل خاص، لجعل أوامر ' كحركات متسقة مع أنماط البحث كحركات.

Redraw Window

تاريخيًا، كان الأمر z يقوم دائمًا بإعادة رسم الشاشة. هذا مسموح به ولكن ليس مطلوبًا بواسطة POSIX.1-2008، نظرًا للاستخدام المتكرر لأمر z في وحدات الماكرو مثل map n nz. لتحديد موضع الشاشة، بدلاً من استخدامه لتغيير حجم الشاشة. اعتقد مطورو المعيار أن توسيع أو تمرير الشاشة يوفر واجهة أفضل للمستخدمين. تم الحفاظ على القدرة على إعادة رسم الشاشة إذا تم تحديد حجم النافذة الجديد الاختياري، وفي أوامر L و R.

دلالات z^ مربكة في أحسن الأحوال. الممارسة التاريخية هي عرض الشاشة قبل الشاشة التي انتهت بالسطر المحدد. يتطلب POSIX.1-2008 الامتثال للممارسة التاريخية.

تاريخيًا، لم يعرض الأمر z سطرًا جزئيًا في أعلى أو أسفل الشاشة. إذا كان من المفترض عرض السطر الجزئي عادةً في أسفل الشاشة، فقد نجح الأمر، ولكن تم استبدال السطر الجزئي بأحرف '@'. إذا كان من المفترض عرض السطر الجزئي عادةً في أعلى الشاشة، فقد فشل الأمر. من أجل الاتساق وبساطة المواصفات، لا يسمح POSIX.1-2008 بهذا السلوك.

تاريخيًا، تجاهل الأمر z مع مواصفات سطر 1 الأمر. من أجل الاتساق وبساطة المواصفات، لا يسمح POSIX.1-2008 بهذا السلوك.

تاريخيًا، لم يقم الأمر z بتعيين عمود المؤشر إلى أول حرف غير فارغ للحرف إذا كان من المفترض عرض الشاشة الأولى، وكانت معروضة بالفعل. من أجل الاتساق وبساطة المواصفات، لا يسمح POSIX.1-2008 بهذا السلوك.

Input Mode Commands in vi

لم تسمح التطبيقات التاريخية لـ vi للمستخدم بمسح أكثر من سطر إدخال واحد، أو باستخدام أحرف المسح العادية مثل line erase و worderase و erase لمسح أحرف autoindent. نظرًا لوجود تطبيقات لـ vi لا تحتوي على هذه القيود، فإن كلا السلوكين مسموح بهما، ولكن الممارسة التاريخية فقط مطلوبة. في حالة هذه التوسعات، يُطلب من vi التوقف عند حدود autoindent والسطر السابق.

تاريخيًا، قامت التطبيقات بتحديث الجزء فقط من الشاشة حيث تم عرض حرف المؤشر الحالي. على سبيل المثال، ضع في اعتبارك ضغطات المفاتيح لـ vi:

iabcd<escape>0C<tab>

تاريخيًا، كان سيستبدل الأحرف "abcd" عند عرضها. تطبيقات أخرى تستبدل فقط الحرف 'a' بـ ، ثم تدفع بقية الأحرف إلى الأمام من المؤشر. كلتا التطبيقين لها مشاكل. التطبيق التاريخي ربما يكون أجمل بصريًا للمثال أعلاه؛ ومع ذلك، بالنسبة لضغطة المفاتيح:

iabcd<ESC>0R<tab><ESC>

نتج التطبيق التاريخي عن اختفاء السلسلة "bcd" ثم ظهورها مرة أخرى بشكل سحري عند إدخال الحرف . يتطلب POSIX.1-2008 السلوك السابق عند استبدال أعمدة المسح - أي، استبدال الأحرف التي لم تعد جزءًا منطقيًا من مخزن التحرير - والسلوك الأخير بخلاف ذلك.

تاريخيًا، قامت التطبيقات بتجاهل أحرف D و T عند إدخالها في أماكن لم يكن فيها وظيفة الأمر مناسبة. يتطلب POSIX.1-2008 أن تكون وظيفة T متاحة دائمًا، وأن يتم التعامل مع D كأي مفتاح آخر عند عدم العمل على أحرف autoindent.

NUL

حددت بعض التطبيقات التاريخية لـ vi عدد الأحرف المدخلة باستخدام حرف الإدخال NUL بـ 256 بايت. يسمح POSIX.1-2008 بهذا القيد؛ ومع ذلك، يتم تشجيع التطبيقات على إزالة هذا الحد.

<control>‐D

انظر أيضًا مبررات أمر وضع الإدخال . الافتراضات المخفية في أمر D (وفي مواصفات autoindent في vi بشكل عام) هي أن أحرف تشغل عمودًا واحدًا على الشاشة وأن أحرف تتكون من عدد صحيح من أحرف .

<newline>

يُسمح للتطبيقات بإعادة كتابة أحرف autoindent في السطر عند إدخال ، ، D، و T، أو عند استخدام أوامر shift، لأن التطبيقات التاريخية قد فعلت ذلك ووجدت أنه من الضروري القيام بذلك. على سبيل المثال، سيؤدي D عندما يسبق المؤشر واحد، مع تعيين tabstop إلى 8، و shiftwidth إلى 3، إلى استبدال بعدة أحرف .

<control>‐T

انظر أيضًا مبررات أمر وضع الإدخال . تاريخيًا، كان T يعمل فقط إذا لم يتم إدخال أي أحرف غير فارغة في سطر الإدخال الحالي. بالإضافة إلى ذلك، تم التعامل مع الأحرف المدرجة بواسطة T كأحرف autoindent، ولم يكن من الممكن مسحها باستخدام أحرف المسح العادية للمستخدم. نظرًا لوجود تطبيقات لا تحتوي على هذه القيود، وبما أن الانتقال إلى حدود العمود مفيد بشكل عام، فإن POSIX.1-2008 يتطلب إزالة كلا القيدين.

<control>‐V

تاريخيًا، استخدم vi ^V، بغض النظر عن قيمة حرف الـ literal-next للطرفية. يتطلب POSIX.1-2008 الامتثال للممارسة التاريخية.

يمكن تحقيق الاستخدامات الموصوفة لـ V أيضًا باستخدام Q، وهو مفيد في الطرفيات التي تستخدم V لوظيفة السهم لأسفل. ومع ذلك، تستخدم معظم التطبيقات التاريخية Q لحرف START في termios، لذلك لن يتلقى المحرر Q بشكل عام ما لم يتم تعيين وضع stty ixon على إيقاف. (بالإضافة إلى ذلك، قامت بعض التطبيقات التاريخية لـ vi بتعيين وضع ixon على تشغيل، لذلك كان من الصعب على المستخدم تعيينه على إيقاف.) يمكن جعل أي من أحرف الأوامر الموصوفة في POSIX.1-2008 غير فعالة عن طريق اختيارها كأحرف تحكم termios، باستخدام أداة stty أو طرق أخرى موصوفة في مجلد System Interfaces من POSIX.1-2017.

<ESC>

تاريخيًا، نبه SIGINT الطرفية عند استخدامها لإنهاء وضع الإدخال. هذا السلوك مسموح به، ولكنه ليس مطلوبًا، بواسطة POSIX.1-2008.

PROLOG

The PROLOG section is not a standard section of manual pages, but it is sometimes used to provide introductory information about the subject matter.

NAME

The NAME section should contain the name of the command or function, followed by a short, one-line description of its purpose.

SYNOPSIS

The SYNOPSIS section describes the syntax of the command or function. It uses a specific notation to indicate optional arguments, required arguments, and arguments that can be repeated.

DESCRIPTION

The DESCRIPTION section provides a detailed explanation of the command or function's behavior. It should be clear, concise, and comprehensive.

OPTIONS

The OPTIONS section describes the command-line options that can be used with the command. Each option should be described along with its purpose and any associated arguments.

OPERANDS

The OPERANDS section describes the arguments that are passed to the command or function. This section is typically used for commands that operate on files or other data.

STDIN

The STDIN section describes the standard input of the command or function. This is relevant for commands that read data from standard input.

INPUT FILES

The INPUT FILES section describes any files that the command or function reads as input.

ENVIRONMENT VARIABLES

The ENVIRONMENT VARIABLES section describes any environment variables that affect the behavior of the command or function.

ASYNCHRONOUS EVENTS

The ASYNCHRONOUS EVENTS section describes any asynchronous events (e.g., signals) that the command or function may handle or generate.

STDOUT

The STDOUT section describes the standard output of the command or function. This is relevant for commands that produce output to standard output.

STDERR

The STDERR section describes the standard error output of the command or function. This is relevant for commands that produce error messages or diagnostic information to standard error.

OUTPUT FILES

The OUTPUT FILES section describes any files that the command or function creates or modifies as output.

EXTENDED DESCRIPTION

The EXTENDED DESCRIPTION section can be used to provide more detailed information that does not fit into the other sections.

EXIT STATUS

The EXIT STATUS section describes the possible exit codes of the command or function and what they signify.

CONSEQUENCES OF ERRORS

The CONSEQUENCES OF ERRORS section describes what happens when the command or function encounters an error.

APPLICATION USAGE

The APPLICATION USAGE section provides guidance on how to use the command or function in specific applications or scenarios.

EXAMPLES

The EXAMPLES section provides practical examples of how to use the command or function.

RATIONALE

The RATIONALE section explains the reasoning behind certain design decisions or behaviors of the command or function.

FUTURE DIRECTIONS

The FUTURE DIRECTIONS section may discuss potential future developments or improvements related to the command or function.

SEE ALSO

The SEE ALSO section lists related manual pages, commands, or functions that the user might find useful.

COPYRIGHT

The COPYRIGHT section typically contains copyright notices and licensing information related to the manual page content.
