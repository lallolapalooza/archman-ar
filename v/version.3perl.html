version - Perl version objects

\n
\n\n\n
\n
use version;\n\nmy $v = version->parse('v1.2.3');\nmy $v2 = version->declare('v1.2.3');\nmy $v3 = version->from_tuple(1, 2, 3);\n\nmy $v4 = version->parse(1.002003);\nmy $v5 = version->parse('v1.2');\n\nif ($v > $v2) { ... }\nif ($v <= $v2) { ... }\nif ($v eq $v2) { ... }\nif ($v != $v2) { ... }\n\nprint $v;\nprint $v->normal;\nprint $v->stringify;\nprint $v->numify;\nprint $v->tuple;\n\nif ($v->is_alpha) { ... }\nif ($v->is_qv) { ... }\n
\n
\n\n\n

This module provides a way to handle version numbers in Perl.\nIt allows you to parse version strings into objects, compare them numerically,\nand perform other operations on them.

\n\n\n

There are several ways to create version objects:

\n
\n
version->parse(STRING)
\n
Parses a string representation of a version number. The string can be in\nvarious formats, including dotted decimals (e.g., '1.2.3'), versions with\nleading 'v' (e.g., 'v1.2.3'), and versions with alpha segments (e.g., '1.2_3').
\n
version->declare(STRING)
\n
Similar to parse, but specifically intended for declaring\nversion numbers within modules. It might have slightly different parsing rules\nor behavior in some edge cases.
\n
version->from_tuple(NUM, ...)
\n
Creates a version object from a list of numbers, which are treated as\ncomponents of the version. For example, version->from_tuple(1,\n2,\n3) creates the version object 'v1.2.3'.
\n
qv(STRING)
\n
This is an older function, similar to parse, but it's\ngenerally recommended to use version->parse instead.
\n
\n\n\n

The declare method is useful for setting the\nversion of a module.

\n
$VERSION = version->declare('v1.0.0');
\n

This sets the special $VERSION variable in your\nmodule to a version object.

\n\n\n

Version objects can be compared using the standard comparison\noperators:

\n
my $v1 = version->parse('v1.2.3');\nmy $v2 = version->parse('1.2.4');\n\nif ($v1 < $v2) { print \"v1 is older than v2\\n\"; }\nif ($v1 == version->parse('v1.2.3')) { print \"v1 equals v1.2.3\\n\"; }\n
\n

The module overloads the comparison operators, so you can use them\ndirectly on version objects. This is achieved by defining the necessary comparison\nmethods, allowing other comparison operators to work based on those two.

\n
if ( version->parse($v1) == version->parse($v2) ) {\n  # do stuff\n}
\n

If a version object is compared against a non-version object, the\nnon-object term will be converted to a version object using\nparse(). This may give surprising results:

\n
$v1 = version->parse(\"v0.95.0\");\n$bool = $v1 < 0.94; # TRUE since 0.94 is v0.940.0
\n

Always comparing to a version object will help avoid\nsurprises:

\n
$bool = $v1 < version->parse(\"v0.94.0\"); # FALSE
\n

Note that \"alpha\" version objects (where the version\nstring contains a trailing underscore segment) compare as less than the\nequivalent version without an underscore:

\n
$bool = version->parse(\"1.23_45\") < version->parse(\"1.2345\"); # TRUE
\n

See version::Internals for more details on \"alpha\"\nversions.

\n
\n\n\n
\n

is_alpha()

\n

True if and only if the version object was created with a\nunderscore, e.g.

\n
version->parse('1.002_03')->is_alpha;  # TRUE\nversion->declare('1.2.3_4')->is_alpha; # TRUE
\n
\n
\n

is_qv()

\n

True only if the version object is a dotted-decimal version,\ne.g.

\n
version->parse('v1.2.0')->is_qv;       # TRUE\nversion->declare('v1.2')->is_qv;       # TRUE\nqv('1.2')->is_qv;\                      # TRUE\nversion->parse('1.2')->is_qv;          # FALSE
\n
\n
\n

normal()

\n

Returns a string with a standard 'normalized' dotted-decimal form\nwith a leading-v and at least 3 components.

\n
version->declare('v1.2')->normal;  # v1.2.0\nversion->parse('1.2')->normal;     # v1.200.0
\n
\n
\n

numify()

\n

Returns a value representing the object in a pure decimal.

\n
version->declare('v1.2')->numify;  # 1.002000\nversion->parse('1.2')->numify;     # 1.200
\n
\n
\n

to_decimal

\n

This returns a new version object for the numified version, much\nlike "version->parse($v->numify)"\nwould.

\n
version->parse('v1.2')->to_decimal; # 1.002000
\n
\n
\n

to_dotted_decimal

\n

This returns a new version object for the normalized version, much\nlike "version->parse($v->normal)"\nwould.

\n
version->parse('1.002')->to_dotted_decimal; # v1.2.0
\n
\n
\n

tuple()

\n

This turns the components of the version into a list. E.g.

\n
version->parse('1.2.3')->tuple; # (1, 2, 3)
\n
\n
\n

from_tuple(...)

\n

This takes a list of components and creates a dotted decimal\nversion out of it. E.g.

\n
version->from_tuple(1, 2, 3) # v1.2.3
\n
\n
\n

stringify()

\n

Returns a string that is as close to the original representation\nas possible. If the original representation was a numeric literal, it will\nbe returned the way perl would normally represent it in a string. This\nmethod is used whenever a version object is interpolated into a string.

\n
version->declare('v1.2')->stringify;    # v1.2\nversion->parse('1.200')->stringify;     # 1.2\nversion->parse(1.02_30)->stringify;     # 1.023
\n
\n
\n

tuple

\n

Returns an array of non-negative integers that is used for\ncomparison purposes with other version objects.

\n
\n\n\n\n
\n

qv()

\n

This function is no longer recommended for use, but is maintained\nfor compatibility with existing code. If you do not want to have it exported\nto your namespace, use this form:

\n
use version 0.77 ();
\n
\n
\n

is_lax()

\n

(Not exported by default)

\n

This function takes a scalar argument and returns a boolean value\nindicating whether the argument meets the \"lax\" rules for a\nversion number. Leading and trailing spaces are not allowed.

\n
\n
\n

is_strict()

\n

(Not exported by default)

\n

This function takes a scalar argument and returns a boolean value\nindicating whether the argument meets the \"strict\" rules for a\nversion number. Leading and trailing spaces are not allowed.

\n
