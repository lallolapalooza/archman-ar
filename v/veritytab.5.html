NAME

veritytab — configuration file for device verity mapping

SYNOPSIS

/etc/veritytab

DESCRIPTION

The /etc/veritytab file specifies device verity mappings. It is a simple, plain-text file where each line defines a mapping. Blank lines and lines starting with # are ignored.

Each line defines one mapping and must be in the following format:

VERITY_DEVICE HASH_DEVICE DATA_DEVICE HASH_ALGORITHM ROOT_HASH FLAGS
VERITY_DEVICE
The block device node to create for the verity mapping. This may be a device node (e.g. /dev/dm-0), a file path (e.g. /dev/mapper/my-verity-device), or a PARTUUID (e.g. PARTUUID=...).
HASH_DEVICE
The block device node containing the hash tree. This may be a device node, a file path, or a PARTUUID.
DATA_DEVICE
The block device node containing the data. This may be a device node, a file path, or a PARTUUID.
HASH_ALGORITHM
The hash algorithm used for the hash tree. Supported algorithms include sha1, sha256, sha512, sm3.
ROOT_HASH
The hexadecimal string representing the root hash of the hash tree.
FLAGS
Optional flags. A space-separated list of keywords. Currently supported flags are:
auto
Set up the verity mapping automatically at boot or when systemd-veritysetup-generator is run. This is the default if no flags are specified.
noauto
Do not set up the verity mapping automatically. It can be set up manually using veritysetup(8).
deferred
Set up the verity mapping in deferred mode. This means the mapping will be created but the underlying data device will only be accessed when it is actually needed. This is useful for file systems that are not immediately mounted during early boot.

The deferred option is a special case. If the verity device is used for a file system that is mounted read-write in the initrd, this option should be used. With this option the device will still be detached but later after the root file system is unmounted.

All other verity protected block devices that contain file systems mounted in the initrd should use this option.

Added in version 248.

At early boot and when the system manager configuration is reloaded, this file is translated into native systemd units by systemd-veritysetup-generator(8).
