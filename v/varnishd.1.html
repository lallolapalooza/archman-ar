VARNISH(1)

varnishd

1.0

SYNOPSIS

varnishd [-a address [-a ...]] [-Ag handler [-Ag ...]] [-b backend [-b ...]] [-c cache_dir [-c ...]] [-D [-d]] [-F [-f file [-f ...]] [-g group [-h hash [-h ...]] [-i identity [-I clifile [-j jail [-j ...]] [-l vsl [-N NDELAYS [-n name [-P pidfile [-p parm [=value]] [-r parm [=value]] [-S secret-file [-s storage [-s ...]] [-T ip[:port] [-t TTL [-u user [-V]] [-w workspace [-X xclf]]

DESCRIPTION

The varnishd command starts the Varnish HTTP accelerator daemon.

The options are:

Main options

-a address
Listen for incoming HTTP requests on the specified address. This option can be specified multiple times for multiple addresses.

The address can be a hostname or IP address, optionally followed by a colon and a port number. If the port number is omitted, the default port 80 is used. If the address is omitted, the default address 0.0.0.0 is used.

See also the varnishd man page for more details on address formats.

-A handler
Use the specified administrator handler. The default is the telnet-like CLI on the management port. This option can be specified multiple times.
-b backend
Specify the default backend server to use. This is a shortcut for setting the default_backend parameter. The format is a hostname or IP address, optionally followed by a colon and a port number. If the port number is omitted, the default port 80 is used.
-c cache_dir
Specifies the directory for caching objects. This is a shortcut for setting the cache_dir parameter. The default is /var/cache/varnish.
-D
Daemonize: run the process in the background. This is the default.
-d
Do not daemonize: run the process in the foreground. This is useful for debugging. See also the -d option in the Advanced section.
-F
Run the Varnish Cache process in the foreground, without daemonizing. This is a shortcut for the -d option, but it also implies that the child process is not started explicitly, but instead is started implicitly by the parent process. This is useful for debugging. See also the -d option in the Advanced section.
-f file
Load VCL configuration from the specified file. This option can be used multiple times to load multiple VCL files. The files are loaded in the order specified, and later files can override earlier ones.
-g group
Set the group ID for the Varnish worker process. By default, the group ID of the user running varnishd is used.
-h <type[,options]>
Specifies the hash algorithm. See Hash Algorithm section for a list of supported algorithms.
-i identity
Specify the identity of the Varnish server. This can be accessed using server.identity from VCL.

The server identity is used for the received-by field of Via headers generated by Varnish. For this reason, it must be a valid token as defined by the HTTP grammar.

If not specified the output of gethostname(3) is used, in which case the syntax is assumed to be correct.

-I clifile
Execute the management commands in the file given as clifile before the worker process starts, see CLI Command File.
-j <jail[,jailoptions]>
Specify the jailing mechanism to use. See Jail section.
-l <vsl>
Specifies size of the space for the VSL records, shorthand for -p vsl_space=<vsl>. Scaling suffixes like 'K' and 'M' can be used up to (G)igabytes. See vsl_space for more information.
-N NDELAYS
Set the number of VSL record buffers. Defaults to 10000.
-n name
Specify a name for the Varnish instance. This is used to differentiate multiple Varnish instances running on the same host. The name is used in various places, including log files and shared memory segments.
-P pidfile
Write the PID of the process to the specified file.
-p <param=value>
Set the parameter specified by param to the specified value, see List of Parameters for details. This option can be used multiple times to specify multiple parameters.
-r <param[,param...]>
Make the listed parameters read only. This gives the system administrator a way to limit what the Varnish CLI can do. Consider making parameters such as cc_command, vcc_allow_inline_c and vmod_path read only as these can potentially be used to escalate privileges from the CLI.
-S secret-file
Path to a file containing a secret used for authorizing access to the management port. To disable authentication use none.

If this argument is not provided, a secret drawn from the system PRNG will be written to a file called _.secret in the working directory (see opt_n) with default ownership and permissions of the user having started varnish.

Thus, users wishing to delegate control over varnish will probably want to create a custom secret file with appropriate permissions (ie. readable by a unix group to delegate control to).

-s <[name=]type[,options]>
Use the specified storage backend. See Storage Backend section.

This option can be used multiple times to specify multiple storage files. Name is referenced in logs, VCL, statistics, etc. If name is not specified, "s0", "s1" and so forth is used.

-T ip[:port]
Listen for management connections on the specified IP address and port. The default is localhost:6082.
-t TTL
Specifies the default time to live (TTL) for cached objects. This is a shortcut for specifying the default_ttl run-time parameter.
-u user
Set the user ID for the Varnish worker process. By default, the user ID of the user running varnishd is used.
-V
Display the version number and exit. This must be the only option.
-w workspace
Specifies the size of the workspace for VSL records. Shorthand for -p vsl_workspace=<workspace>. Scaling suffixes like 'K' and 'M' can be used up to (G)igabytes.
-X xclf
Load VCL configuration from the compiled file given as xclf. This option can be used multiple times to load multiple VCL files.

Advanced, development and debugging options

-d
Enables debugging mode: The parent process runs in the foreground with a CLI connection on stdin/stdout, and the child process must be started explicitly with a CLI command. Terminating the parent process will also terminate the child.

Only one of -d or -F can be specified, and -d cannot be used together with -C.

-C
Print VCL code compiled to C language and exit. Specify the VCL file to compile with the -f option. Either -f or -b must be used with -C, and -C cannot be used with -F or -d.
-V
Display the version number and exit. This must be the only option.
-h <type[,options]>
Specifies the hash algorithm. See Hash Algorithm section for a list of supported algorithms.
-W waiter
Specifies the waiter type to use.

Hash Algorithm

The following hash algorithms are available:

-h critbit
self-scaling tree structure. The default hash algorithm in Varnish Cache 2.1 and onwards. In comparison to a more traditional B tree the critbit tree is almost completely lockless. Do not change this unless you are certain what you're doing.
-h simple_list
A simple doubly-linked list. Not recommended for production use.
-h <classic[,buckets]>
A standard hash table. The hash key is the CRC32 of the object's URL modulo the size of the hash table. Each table entry points to a list of elements which share the same hash key. The buckets parameter specifies the number of entries in the hash table. The default is 16383.

Storage Backend

Multiple storage backends (where the cached and in-flight objects are held) can be defined, and VCL can pilot which store is used by setting the beresp.storage variable (see man vcl-var for more information).

The argument format to define storage backends is:

-s <[name]=kind[,options]>
If name is omitted, Varnish will name storages sN, starting with s0 and incrementing N for every new storage.

For kind and options see details below.

Storages can be used in vcl as storage.name, so, for example if myStorage was defined by -s myStorage=malloc,5G, it could be used in VCL like so:

set beresp.storage = storage.myStorage;

A special name is Transient which is the default storage for uncacheable objects as resulting from a pass, hit-for-miss or hit-for-pass.

If no -s options are given, the default is:

-s default,100m

If no Transient storage is defined, the default is an unbound default storage as if defined as:

-s Transient=default

The following storage types and options are available:

-s <default[,size]>
The default storage type resolves to umem where available and malloc otherwise.
-s <malloc[,size]>
malloc is a memory based backend.
-s <umem[,size]>
umem is a storage backend which is more efficient than malloc on platforms where it is available.

See the section on umem in chapter Storage backends of The Varnish Users Guide for details.

-s <file,path[,size[,granularity[,advice]]]>
The file backend stores data in a file on disk. The file will be accessed using mmap. Note that this storage provide no cache persistence.

The path is mandatory. If path points to a directory, a temporary file will be created in that directory and immediately unlinked. If path points to a non-existing file, the file will be created.

If size is omitted, and path points to an existing file with a size greater than zero, the size of that file will be used. If not, an error is reported.

Granularity sets the allocation block size. Defaults to the system page size or the filesystem block size, whichever is larger.

Advice tells the kernel how varnishd expects to use this mapped region so that the kernel can choose the appropriate read-ahead and caching techniques. Possible values are normal, random and sequential, corresponding to MADV_NORMAL, MADV_RANDOM and MADV_SEQUENTIAL madvise() advice argument, respectively. Defaults to random.

-s <persistent,path,size>
Persistent storage. Varnish will store objects in a file in a manner that will secure the survival of most of the objects in the event of a planned or unplanned shutdown of Varnish. The persistent storage backend has multiple issues with it and will likely be removed from a future version of Varnish.

Jail

Varnish jails are a generalization over various platform specific methods to reduce the privileges of varnish processes. They may have specific options. Available jails are:

-j <solaris[,worker=`privspec`]>
Reduce privileges(5) for varnishd and sub-processes to the minimally required set. Only available on platforms which have the setppriv(2) call.

The optional worker argument can be used to pass a privilege-specification (see ppriv(1)) by which to extend the effective set of the varnish worker process. While extended privileges may be required by custom vmods, not using the worker option is always more secure.

  • الحد الأدنى: 0

إزالة المحتوى ذو الذيل الطويل من ذاكرة التخزين المؤقت للحفاظ على عدد الحظر أقل من هذه القيمة. القيمة 0 تعطل هذه الميزة.

عند تعيين هذه المعلمة إلى قيمة غير صفرية، يستمر المتسلل الحظر في العمل على قائمة الحظر كالمعتاد من الأعلى إلى الأسفل، ولكن عندما يصل إلى الحظر ذي الرقم ban_cutoff، فإنه يعامل جميع الكائنات كما لو كانت تتطابق مع حظر ويقوم بإزالتها من ذاكرة التخزين المؤقت. نظرًا لأنه يتم اختبار الكائنات المستخدمة بنشاط مقابل قائمة الحظر في وقت الطلب، ومن المرجح أن تكون مرتبطة بحظر بالقرب من أعلى قائمة الحظر، مع ban_cutoff، تتم إزالة الكائنات الأقل وصولاً ( "الذيل الطويل").

هذه المعلمة هي شبكة أمان لتجنب أوقات الاستجابة السيئة بسبب اختبار الحظر عند البحث. تعيين حد يتبادل وقت الاستجابة مع كفاءة ذاكرة التخزين المؤقت. القيمة الموصى بها تتناسب مع rate(bans_lurker_tests_tested) / n_objects أثناء عمل المتسلل الحظر، وهو عدد الحظر الذي يمكن للنظام تحمله. الكمون الإضافي بسبب اختبار الحظر في الطلب يكون في ترتيب ban_cutoff / rate(bans_lurker_tests_tested). على سبيل المثال، بالنسبة لـ rate(bans_lurker_tests_tested) = 2M/s ووقت كمون مقبول يبلغ 100 مللي ثانية، يمكن أن تكون القيمة الجيدة لـ ban_cutoff هي 200K.

cc_command

ملاحظة: القيمة الافتراضية الفعلية لهذه المعلمة تعتمد على بيئة بناء Varnish وخياراتها.

  • الافتراضي: exec $CC $CFLAGS %w -shared -o %o %s
  • علامات: must_reload

الأمر المستخدم لتجميع كود مصدر C في كائن تحميل عبر dlopen(3). يمكن استخدام التوسعات التالية:

  • %s: اسم ملف المصدر
  • %o: اسم ملف الإخراج
  • %w: معلمة cc_warnings
  • %d: الأمر الافتراضي الخام cc_command
  • %D: الأمر الافتراضي الموسع cc_command
  • %n: الدليل العامل (الخيار -n)
  • %%: علامة النسبة المئوية

يتم تجاهل تسلسلات التوسيع غير المعروفة للنسبة المئوية، ولتجنب عدم التوافق المستقبلي، يجب تهريب أحرف النسبة المئوية بتسلسل نسبة مئوية مزدوج.

تسمح توسعات %d و %D بتمرير القيمة الافتراضية للمعلمة إلى برنامج نصي غلاف لتنفيذ معالجة إضافية.

    NAME

    varnishd — The Varnish Cache HTTP accelerator

    SYNOPSIS

    varnishd [-a [address][:port] [-f configuration] [-F] [-j n_threads] [-L sharedlib] [-n name] [-P pidfile] [-r file] [-S masterkey] [-T admin_listen_address[:port]] [-V] [-v] [-w n_file,file_size[,max_MB]] [configuration ...]

    DESCRIPTION

    The varnishd daemon is the Varnish Cache HTTP accelerator. It listens for incoming HTTP requests on a specified network address and port, processes them according to its configuration, and forwards them to a backend server if necessary. Varnish caches the responses from the backend, and serves subsequent identical requests directly from the cache, thereby reducing the load on the backend and improving response times.

    The daemon can be controlled remotely using the varnishadm(1) command, which connects to the admin port specified with the -T option.

    The configuration is specified using Varnish Configuration Language (VCL), which is described in vcl(7). The VCL configuration can be loaded from a file using the -f option, or directly from the command line using the ... arguments.

    OPTIONS

    -a [address][:port]
    Specify the listening address and port for incoming HTTP requests. If no address is given, Varnish listens on all network interfaces. If no port is given, Varnish listens on port 80. Multiple -a options can be specified to listen on multiple addresses and ports.
    -f configuration
    Specify the VCL configuration file to load. If this option is given multiple times, the configurations are loaded in order, and the last one loaded takes precedence. If no -f option is given, Varnish looks for a file named default.vcl in its configuration directory.
    -F
    Foreground mode. Do not fork into the background. This is useful for debugging and for running Varnish under process supervisors.
    -j n_threads
    Specify the number of worker threads to use. The default is 4.
    -L sharedlib
    Load a shared library. This is used for loading VMODs (Varnish Modules).
    -n name
    Specify the instance name. This is used to separate Varnish instances running on the same machine. The name is used in cache directory names and log messages.
    -P pidfile
    Write the process ID to the specified file. This is useful for managing the Varnish process.
    -r file
    Raw mode. Instead of a cache, dump all requests and responses to the specified file. This is useful for debugging.
    -S masterkey
    Specify the secret key for the administrative interface. This is used by varnishadm(1) to connect to varnishd.
    -T admin_listen_address[:port]
    Specify the listening address and port for the administrative interface. If no address is given, Varnish listens on localhost. If no port is given, Varnish listens on port 6082. Multiple -T options can be specified.
    -V
    Print version information and exit.
    -v
    Verbose mode. Print VCL warnings and other informative messages to stderr.
    -w n_file,file_size[,max_MB]
    Specify the parameters for the shared memory log. n_file is the number of log files to use. file_size is the size of each log file in bytes. max_MB is the maximum amount of memory to use for the log (optional). The default is 4,17483648,0.
    configuration ...
    Specify VCL configuration directly on the command line. These are loaded after any configurations specified with -f.

    RUN TIME PARAMETERS

    Varnish supports a number of run-time parameters that can be changed while the daemon is running using the varnishadm(1) command. These parameters control various aspects of Varnish's behavior, such as cache size, worker threads, and logging.

    The available parameters can be listed using the varnishadm(1) command with the param.show command.

    EXIT CODES

    The varnishd daemon typically exits with a status code of 0 upon successful execution. Non-zero exit codes indicate an error condition, such as a failure to bind to a network socket, a VCL syntax error, or an inability to access cache storage.

    الاسم

    varnishd — مسرّع HTTP الخاص بـ Varnish Cache

    الملخص

    varnishd [-a [عنوان][:منفذ] [-f تهيئة] [-F] [-j عدد_الخيوط] [-L مكتبة_مشتركة] [-n الاسم] [-P ملف_معرف_العملية] [-r ملف] [-S مفتاح_رئيسي] [-T عنوان_الاستماع_للمسؤول[:منفذ]] [-V] [-v] [-w عدد_الملفات,حجم_الملف[,أقصى_ميغابايت]] [تهيئة ...]

    الوصف

    البرنامج الخفي varnishd هو مسرّع HTTP الخاص بـ Varnish Cache. يستمع لطلبات HTTP الواردة على عنوان وشبكة محددين، ويعالجها وفقًا لتهيئته، ويوجهها إلى خادم خلفي إذا لزم الأمر. يقوم Varnish بتخزين الاستجابات من الخادم الخلفي مؤقتًا، ويقدم الطلبات المتطابقة اللاحقة مباشرة من ذاكرة التخزين المؤقت، مما يقلل العبء على الخادم الخلفي ويحسن أوقات الاستجابة.

    يمكن التحكم في البرنامج الخفي عن بعد باستخدام الأمر varnishadm(1)، والذي يتصل بمنفذ المسؤول المحدد بالخيار -T.

    يتم تحديد التهيئة باستخدام لغة تهيئة Varnish (VCL)، والتي تم وصفها في vcl(7). يمكن تحميل تهيئة VCL من ملف باستخدام الخيار -f، أو مباشرة من سطر الأوامر باستخدام الوسائط ...

    الخيارات

    -a [عنوان][:منفذ]
    حدد عنوان الاستماع والمنفذ لطلبات HTTP الواردة. إذا لم يتم تقديم عنوان، يستمع Varnish على جميع واجهات الشبكة. إذا لم يتم تقديم منفذ، يستمع Varnish على المنفذ 80. يمكن تحديد خيارات -a متعددة للاستماع على عناوين ومنافذ متعددة.
    -f تهيئة
    حدد ملف تهيئة VCL المطلوب تحميله. إذا تم تقديم هذا الخيار عدة مرات، يتم تحميل التهيئة بالترتيب، ويكون الأخير هو السائد. إذا لم يتم تقديم خيار -f، يبحث Varnish عن ملف باسم default.vcl في دليل التهيئة الخاص به.
    -F
    وضع المقدمة (Foreground mode). لا تنفصل إلى الخلفية. هذا مفيد للتصحيح وتشغيل Varnish تحت مشرفي العمليات.
    -j عدد_الخيوط
    حدد عدد خيوط العمل المراد استخدامها. الافتراضي هو 4.
    -L مكتبة_مشتركة
    تحميل مكتبة مشتركة. يستخدم هذا لتحميل وحدات VMODs (وحدات Varnish).
    -n الاسم
    حدد اسم النسخة. يستخدم هذا لفصل نسخ Varnish التي تعمل على نفس الجهاز. يستخدم الاسم في أسماء دليل ذاكرة التخزين المؤقت ورسائل السجل.
    -P ملف_معرف_العملية
    اكتب معرف العملية إلى الملف المحدد. هذا مفيد لإدارة عملية Varnish.
    -r ملف
    وضع خام (Raw mode). بدلاً من ذاكرة التخزين المؤقت، قم بتفريغ جميع الطلبات والاستجابات إلى الملف المحدد. هذا مفيد للتصحيح.
    -S مفتاح_رئيسي
    حدد المفتاح السري لواجهة المسؤول. يستخدم هذا بواسطة الأمر varnishadm(1) للاتصال بـ varnishd.
    -T عنوان_الاستماع_للمسؤول[:منفذ]
    حدد عنوان الاستماع والمنفذ لواجهة المسؤول. إذا لم يتم تقديم عنوان، يستمع Varnish على localhost. إذا لم يتم تقديم منفذ، يستمع Varnish على المنفذ 6082. يمكن تحديد خيارات -T متعددة.
    -V
    اطبع معلومات الإصدار واخرج.
    -v
    وضع مفصل (Verbose mode). اطبع تحذيرات VCL ورسائل إعلامية أخرى إلى stderr.
    -w عدد_الملفات,حجم_الملف[,أقصى_ميغابايت]
    حدد معلمات سجل الذاكرة المشتركة. عدد_الملفات هو عدد ملفات السجل المراد استخدامها. حجم_الملف هو حجم كل ملف سجل بالبايت. أقصى_ميغابايت هو الحد الأقصى للمساحة الذاكرة المراد استخدامها للسجل (اختياري). الافتراضي هو 4,17483648,0.
    تهيئة ...
    حدد تهيئة VCL مباشرة على سطر الأوامر. يتم تحميل هذه بعد أي تهيئة محددة بـ -f.

    معاملات وقت التشغيل

    يدعم Varnish عددًا من معاملات وقت التشغيل التي يمكن تغييرها أثناء تشغيل البرنامج الخفي باستخدام الأمر varnishadm(1). تتحكم هذه المعاملات في جوانب مختلفة من سلوك Varnish، مثل حجم ذاكرة التخزين المؤقت، وخيوط العمل، والتسجيل.

    يمكن سرد المعاملات المتاحة باستخدام الأمر varnishadm(1) مع الأمر param.show.

    رموز الخروج

    عادةً ما يخرج البرنامج الخفي varnishd برمز حالة 0 عند التنفيذ الناجح. تشير رموز الخروج غير الصفرية إلى حالة خطأ، مثل الفشل في الربط بمقبس شبكة، أو خطأ في بناء جملة VCL، أو عدم القدرة على الوصول إلى مساحة ذاكرة التخزين المؤقت.
