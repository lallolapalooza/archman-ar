vgscan(8)

الحزمة: lvm2

التراخيص: GPL-2.0-only, LGPL-2.1-only

VGSCAN(8) دليل مدير النظام VGSCAN(8)

الاسم

vgscan — البحث عن جميع مجموعات الأقراص

الملخص

vgscan
[ خيارات_أخرى ]

الوصف

يقوم vgscan بفحص جميع أجهزة أقراص LVM المدعومة في النظام للبحث عن مجموعات الأقراص (VGs).

الاستخدام

vgscan

[ --ignorelockingfailure ]
[ --mknodes ]
[ --notifydbus ]
[ --refresh ]
[ --reportformat basic|json|json_std ]
[ خيارات_عامة ]

الخيارات

--commandprofile سلسلة
ملف تعريف الأوامر المراد استخدامه لتكوين الأوامر. انظر lvm.conf(5) لمزيد من المعلومات حول ملفات التعريف.
--config سلسلة
إعدادات التكوين للأمر. تتجاوز هذه الإعدادات إعدادات lvm.conf(5). تستخدم وسيطة السلسلة نفس تنسيق lvm.conf(5)، أو قد تستخدم صيغة القسم/الحقل. انظر lvm.conf(5) لمزيد من المعلومات حول التكوين.
-d|--debug ...
تعيين مستوى التصحيح. كرر من 1 إلى 6 مرات لزيادة تفاصيل الرسائل المرسلة إلى ملف السجل و/أو syslog (إذا تم تكوينه).
--devices PV
يقيد الأجهزة المرئية والمتاحة للأمر. ستبدو الأجهزة غير المدرجة وكأنها مفقودة. يمكن تكرار هذا الخيار، أو قبوله كقائمة مفصولة بفواصل من الأجهزة. هذا يتجاوز ملف الأجهزة.
--devicesfile سلسلة
ملف يسرد الأجهزة التي يجب أن يستخدمها LVM. يجب أن يكون الملف موجودًا في /etc/lvm/devices/ ويتم إدارته باستخدام أمر lvmdevices(8). يتجاوز هذا الإعدادات devices/devicesfile و devices/use_devicesfile في lvm.conf(5).
--driverloaded y|n
إذا تم تعيينه على لا، فلن يحاول الأمر استخدام device-mapper. للاختبار والتصحيح.
-h|--help
عرض نص المساعدة.
--ignorelockingfailure
يسمح للأمر بالاستمرار في عمليات البيانات الوصفية للقراءة فقط بعد فشل التأمين.
--journal سلسلة
تسجيل المعلومات في سجل systemd. هذه المعلومات بالإضافة إلى المعلومات الممكّنة بواسطة إعداد log/journal في lvm.conf. command: تسجيل معلومات حول الأمر. output: تسجيل الإخراج الافتراضي للأمر. debug: تسجيل تصحيح كامل للأمر.
--lockopt سلسلة
يستخدم لتمرير خيارات للحالات الخاصة إلى lvmlockd. انظر lvmlockd(8) لمزيد من المعلومات.
--longhelp
عرض نص المساعدة الطويل.
--mknodes
يتحقق أيضًا من ملفات LVM الخاصة في /dev المطلوبة لأقراص LVs النشطة وينشئ أي ملفات مفقودة ويزيل غير المستخدمة. انظر أيضًا الخيار الإضافي --refresh للاستخدام في بيئة udev.
--nohints
لا تستخدم ملف التلميحات لتحديد مواقع الأجهزة للأقراص PVs. قد يقرأ الأمر المزيد من الأجهزة للعثور على أقراص PVs عند عدم استخدام التلميحات. سيظل الأمر يقوم بإبطال صلاحية ملف التلميحات القياسي عند الاقتضاء.
--nolocking
تعطيل التأمين. استخدم بحذر، قد تنتج الأوامر المتزامنة نتائج غير صحيحة.
--notifydbus
إرسال إشعار إلى D-Bus. سينتهي الأمر بخطأ إذا لم يتم بناء LVM بدعم إشعارات D-Bus، أو إذا تم تعطيل إعداد التكوين notify_dbus.
--profile سلسلة
اسم مستعار لـ --commandprofile أو --metadataprofile، اعتمادًا على الأمر.
-q|--quiet ...
كتم الإخراج ورسائل السجل. يتجاوز --debug و --verbose. كرر مرة واحدة لكتم أي مطالبات مع إجابة "لا".
--refresh
إذا كان LV نشطًا، فأعد تحميل البيانات الوصفية الخاصة به. في بيئة يتم فيها استخدام udev لإدارة محتوى /dev، يوصى بشدة باستخدام هذا الخيار. وذلك لأن التحديث يعيد أيضًا إنشاء أحداث udev لـ LV بناءً على أي قواعد udev موجودة يتم تطبيقها لتعيين محتوى وأذونات /dev. بالإضافة إلى ذلك، قد تكون هذه العملية مفيدة إذا حدث خطأ ما، أو إذا كان يتم استخدام شكل من أشكال مشاركة LV يدوية.
--reportformat basic|json|json_std
يتجاوز تنسيق الإخراج الحالي للتقارير، والذي يتم تحديده عالميًا بواسطة إعداد report/output_format في lvm.conf(5). basic هو التنسيق الأصلي مع الأعمدة والصفوف. إذا كان هناك أكثر من تقرير واحد لكل أمر، يتم تمييز كل تقرير باسم التقرير للتعرف عليه. json ينتج إخراج التقرير بتنسيق JSON. json_std ينتج إخراج التقرير بتنسيق JSON الأكثر توافقًا مع معيار JSON. انظر lvmreport(7) لمزيد من المعلومات.
-t|--test
تشغيل في وضع الاختبار. لن تقوم الأوامر بتحديث البيانات الوصفية. يتم تنفيذ ذلك عن طريق تعطيل جميع كتابات البيانات الوصفية ولكن مع ذلك إرجاع النجاح للدالة المستدعاة. قد يؤدي هذا إلى رسائل خطأ غير عادية في العمليات متعددة المراحل إذا كانت الأداة تعتمد على قراءة البيانات الوصفية التي تعتقد أنها تغيرت ولكنها لم تتغير.
-v|--verbose ...
تعيين مستوى الإسهاب. كرر من 1 إلى 4 مرات لزيادة تفاصيل الرسائل المرسلة إلى stdout و stderr.
--version
عرض معلومات الإصدار.
-y|--yes
لا تطالب بتأكيد تفاعليًا ولكن افترض دائمًا الإجابة بنعم. استخدم بحذر شديد. (للحصول على لا تلقائي، راجع -qq).

vgscan(8) — Arch Linux

NAME

vgscan ― scan all disks, all devices, or a specified device for Volume Groups.

SYNOPSIS

vgscan [options]

vgscan -d [options]

vgscan -f[y]--force [options]

vgscan -h [options]

vgscan -H [options]

vgscan -v [options]

vgscan --monitor [options] [devices...]

vgscan --mknodes [options] [devices...]

vgscan --partitions [options]

vgscan --storageformat old|lvm1 [options]

vgscan --types type1[,type2,...] [options]

DESCRIPTION

This command scans for all block devices for Volume Groups (VGs) and updates the LVM cache file /etc/lvm/cache/.cache.

When no devices are specified, vgscan scans all registered devices for VGs.

The command is not normally needed because LVM commands always scan devices first when they need information on Volume Groups. However, it can be useful to run vgscan manually if you suspect the cache file is out of date.

Note that if a VG name is specified with -aay, and this volume group is not found, vgscan will exit with a non-zero status. This is the default behaviour.

USAGE

Scan all devices for Volume Groups and update the LVM cache file:

vgscan

Scan only the specified devices for Volume Groups:

vgscan /dev/sda* /dev/sdc*

Scan for Volume Groups and create LVM device nodes:

vgscan --mknodes

Scan for Volume Groups and update LVM device nodes.

vgscan --partitions

Scan for Volume Groups and then exit with a non-zero status if any VG is not found:

vgscan -aay

OPTIONS

devices...

A space-separated list of devices or patterns to scan. If no devices are specified, all devices are scanned.

-aay, --all

Scan all devices. If a VG is not found, exit with a non-zero status.

-d, --debug

Enable debugging output.

-f[y], --force

Force the scan. The default behavior is to use cached information if available. Using -fy will skip the cache and scan all devices directly.

-h, --help

Display help text and exit.

-H, --version

Display version information and exit.

--mknodes

Create LVM device nodes in /dev.

--monitor

Scan devices for Volume Groups and update the LVM cache file if Volume Groups are found. This option is typically used by the lvm-monitor daemon.

--partitions

Scan devices for partitions that may contain Volume Groups and create LVM device nodes for them.

--storageformat old|lvm1

Scan for Volume Groups using the old LVM1 metadata format. This option is for migrating LVM1 VGs to LVM2.

--types type1[,type2,...]

Scan only for specified Volume Group types. Possible types include lvm1, lvm2.

-v, --verbose

Enable verbose output.

ENVIRONMENT VARIABLES

See lvm(8) for information about environment variables used by lvm. For example, LVM_VG_NAME can generally be substituted for a required VG parameter.
