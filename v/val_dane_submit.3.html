val_dane_submit(3)

الحزمة: dnssec-tools

التراخيص: BSD

val_getdaneinfo(3) دليل المبرمج val_getdaneinfo(3)

الاسم

val_getdaneinfo(3) - إجراء تحقق متزامن لسجلات TLSA

val_dane_submit(3) - إجراء تحقق غير متزامن لسجلات TLSA

val_dane_match(3) - التحقق من معلومات TLSA مقابل البيانات المقدمة.

val_dane_check(3) - التحقق من معلومات TLSA لاتصال SSL (OpenSSL فقط)

val_free_dane(3) - تحرير الذاكرة المرتبطة ببنية نتيجة DANE.

p_dane_error(3) - إرجاع سلسلة الخطأ لرمز خطأ DANE معين.

ملخص

#include <validator/validator.h>
#include <validator/val_dane.h>
int val_getdaneinfo(val_context_t *ctx,
                  const char *name,
                  struct val_daneparams *params,
                  struct val_danestatus **dres);
int val_dane_submit(val_context_t *ctx,
                  const char *name,
                  struct val_daneparams *params,
                  val_dane_callback callback,
                  void *callback_data,
                  val_async_status **status);
int val_dane_match(val_context_t *ctx,
                 struct val_danestatus *dane_cur,
                 const unsigned char *databytes,
                 int databyteslen);
#include <openssl/ssl.h>
int val_dane_check(val_context_t *ctx,
                 SSL *con,
                 struct val_danestatus *danestatus,
                 int *do_pathval);
void val_free_dane(struct val_danestatus *dres);
const char *p_dane_error(int rc);

الوصف

val_getdaneinfo() تقوم بالبحث المتزامن عن سجل TLSA المرتبط بالاسم name المحدد وتعيد قائمة مرتبطة بجميع السجلات المتحقق منها. val_dane_submit() تقوم بنفس البحث بطريقة غير متزامنة وتستدعي الدالة callback مع وسيطات callback_data عند اكتمال البحث. تحتوي الدالة الراجعة على التعريف التالي:

typedef int (*val_dane_callback)(void *callback_data,
                               int retval,
                               struct val_danestatus **dres);

يوفر الوسيط status مقبضًا لطلب غير المتزامن لتمكين العمليات المستقبلية (مثل إلغاء الطلب). لمزيد من المعلومات حول الكائن val_async_status، راجع المسودة draft-hayatnagarkar-dnsext-validator-api.

اسم DNS الفعلي الذي يمتلك سجل TLSA في DNS له بادئة بالشكل _<port>._<proto>. val_getdaneinfo() ستبني البادئة المذكورة أعلاه تلقائيًا؛ لذلك، لا ينبغي أن يحتوي اسم name المقدم من المستخدم على هذه البادئة. الـ

يجب توفير معلمات بحث TLSA في الوسيط params، وهو مؤشر إلى البنية التالية:

struct val_daneparams {
  int port;
  int proto;
};

تستخدم حقلا port و proto في بناء بادئة اسم TLSA الموصوفة أعلاه.

يتم إرجاع نتائج بحث TLSA في الوسيط dres، وهو مؤشر إلى قائمة مرتبطة بالبنى التالية:

struct val_danestatus {
  long ttl;
  int usage;
  int selector;
  int type;
  size_t datalen;
  unsigned char *data;
  struct val_danestatus *next;
};

الحقل ttl هو وقت البقاء (time-to-live) المرتبط بسجل TLSA. يجب على التطبيق عدم تخزين (واستخدام) سجل TLSA هذا بما يتجاوز TTL الخاص به. تتوافق الحقول usage و selector و type مع الحقول الثلاثة الأولى من RDATA في TLSA كما هو موضح في rfc6698. يتم إرجاع بيانات ارتباط شهادة TLSA في الحقل data ويبلغ طولها datalen بايت. يمكن أن يكون هناك أكثر من سجل TLSA واحد مرتبط باسم معين، ويشير الحقل next إلى السجل التالي في هذه القائمة.

بالنظر إلى قائمة مرتبطة ببنى TLSA في dres، يمكن استخدام val_dane_match() للتحقق مما إذا كانت بيانات ارتباط الشهادة لعنصر معين في هذه القائمة تتطابق مع البيانات المشفرة DER المقدمة في databytes بطول databyteslen.

تبسط الدالة val_dane_check() عملية المطابقة عندما يستخدم OpenSSL لتوفير دعم SSL/TLS داخل التطبيق. هذه الدالة تتكرر تلقائيًا فوق جميع العناصر في dres وتقارن بيانات ارتباط الشهادة مع شهادات SSL/TLS المرتبطة باتصال SSL con. يتيح بروتوكول DANE حالات استخدام معينة تسمح بتقديم مراسِ ثقة جديدة عبر DNSSEC. القيمة do_pathval تشير إلى ما إذا كان يجب على التطبيق المضي قدمًا في التحقق من مسار X509 لهذا الاتصال وفقًا للاستخدام الذي تم ترميزه في سجل TLSA.

الدالة val_free_dane() تحرر الذاكرة المرتبطة بالقائمة المرتبطة التي يشير إليها dres.

يحدد الوسيط ctx في جميع الدوال المذكورة أعلاه سياق التحقق، والذي يمكن تعيينه إلى NULL للقيم الافتراضية (انظر libval(3) و dnsval.conf لمزيد من التفاصيل حول سياقات التحقق وسياسة التحقق).

قيم الإرجاع

val_getdaneinfo() و val_dane_submit() ترجعان VAL_DANE_NOERROR عند النجاح، و VAL_DANE_MALFORMED_TLSA أو VAL_DANE_INTERNAL_ERROR لحالات الخطأ. يتم إرجاع قيمة VAL_DANE_NOTVALIDATED إذا لم يكن من الممكن التحقق من سجل TLSA عبر DNSSEC. يتم إرجاع قيمة VAL_DANE_IGNORE_TLSA إذا كان سجل TLSA للاسم المحدد غائبًا بشكل قابل للإثبات.

قيمة retval التي يتم إرجاعها كوسيط للدالة val_dane_callback() يمكن أن تحتوي على أحد القيم: VAL_DANE_NOERROR (للنجاح)، VAL_DANE_INTERNAL_ERROR (لحالات الخطأ) أو VAL_DANE_CANCELLED (عند إلغاء الطلب غير المتزامن).

val_dane_match() و val_dane_check() ترجعان VAL_DANE_NOERROR عند النجاح، VAL_DANE_INTERNAL_ERROR لحالات الخطأ العامة، و VAL_DANE_CHECK_FAILED إذا لم يكن من الممكن مطابقة سجل TLSA بنجاح مع بيانات ارتباط الشهادة المقدمة.

يمكن استخدام الدالة p_dane_error() لتحويل رموز خطأ DANE المتعلقة إلى قيمة سلسلة خطأ.
