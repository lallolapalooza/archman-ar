NAME

vtc - Varnish Test Controller

OVERVIEW

The Varnish Test Controller vtc is a script that can be used to test Varnish, its VMODs and its configuration.

A test file is a sequence of commands, each command starting with a keyword, like:

varnish V1 -vcl {
    backend default { .host = "127.0.0.1"; }
} -start
varnish V1 -expect status 503
varnish V1 -stop

The commands are executed in the order they appear. A Varnish instance is referred to by a name, which is freely chosen by the user, but it must be a valid variable name. For example, V1, vcl1, or default are all valid names for Varnish instances.

The test script can also define Varnish Modules (VMODs) and use them in the test. For example:

vmod myvmod {
    sub vcl_init {
        new myobj = myvmod.myobject();
    }
    sub vcl_recv {
        myobj.method();
    }
}
varnish V1 -vcl {
    import myvmod;
    # ...
} -start

The name of the VMOD used in the vmod command is the name used to import it in the VCL code.

PARSING

The VTC parser is line-based and will interpret the following syntax:

STRING
A sequence of characters that is not empty and does not start with a special character.
"STRING"
A sequence of characters enclosed in double quotes.
"STRING"
A sequence of characters enclosed in single quotes.
{ ... }
A block of text. This is typically used for VCL code.
# ...
A comment. Everything after the # character until the end of the line is ignored.

Special characters are defined by the varnishd parser, and can be found in the varnishd(1) manual page.

MACROS

You can define macros using the macro keyword:

macro __V1_NAME __VCL_PORT
macro __V1_NAME __VCL_PORT
    ...

And use them later in the script using the $() syntax:

varnish ${__V1_NAME} -start

Each macro can have a default value, that will be used if no value is provided at the command line.

macro __MY_VAR "default_value"
echo "My variable is ${__MY_VAR}"

Macros are expanded in the order they are defined.

SYNTAX

The following commands are recognized by the test controller:

STRING
A string that describes the test case. This should be the first command in your test file.
block
Start a new block. Blocks can be nested.
endblock
End the current block.
echo STRING
Print STRING to standard output.
dump
Dump the Varnish Shared Memory (VSM) to a file.
exec CMD
Execute the command CMD. The test will fail if the command returns a non-zero exit code.
macro NAME [VALUE]
Define a macro NAME with an optional VALUE.
prog PROG
Identify the program PROG that is being tested. This is typically varnishd.
vcl VCL_CODE
Define a VCL configuration. VCL_CODE can be a string or a block.
vmod VMOD_CODE
Define a VMOD. VMOD_CODE can be a string or a block.
varnish NAME [OPTIONS]
Start a Varnish instance. NAME is the name of the instance. OPTIONS are optional flags that can modify the behavior of the varnish instance.

The following options can be used with the varnish command:

-vcl VCL_CODE
Use the given VCL code for this instance.
-vclfile FILE
Use the VCL code from the given FILE for this instance.
-vclsource VCL_SOURCE
Use the given VCL SOURCE for this instance.
-arg ARGUMENT
Pass the argument ARGUMENT to varnishd.
-close
Close the Varnish instance.
-connect
Connect to the Varnish instance.
-delete
Delete the Varnish instance.
-detach
Detach from the Varnish instance.
-expect STATUS
Wait until the Varnish instance reaches the given STATUS. STATUS can be running, stopped, or a specific exit code.
-expect_pid NUMBER
Expect the Varnish instance to have the given PID.
-expect_stderr PATTERN
Expect the stderr to match the given PATTERN.
-expect_stdout PATTERN
Expect the stdout to match the given PATTERN.
-log
Dump the Varnish log.
-nostart
Do not start the Varnish instance automatically.
-port PORT
Use the given PORT for the Varnish instance.
-run
Start the Varnish instance.
-start
Start the Varnish instance. This is a synonym for -run.
-stop
Stop the Varnish instance.
-stop-on-stderr PATTERN
Stop the Varnish instance if stderr matches PATTERN.
-stop-on-stdout PATTERN
Stop the Varnish instance if stdout matches PATTERN.
-timeout SECONDS
Set the timeout for the Varnish instance to SECONDS.
-tmpdir DIR
Use DIR as the temporary directory for the Varnish instance.
-wait
Wait for the Varnish instance to start.
-wait-stopped
Wait for the Varnish instance to stop.

The vcard command is used to send commands to the Varnish CLI. It takes the name of the Varnish instance and a string containing the command to send.

vcard V1 "status"

The vcard command can also be used to check the status of the CLI response.

vcard NAME COMMAND [EXPECTED_STATUS] [EXPECTED_RESPONSE]
Send COMMAND to the CLI of the Varnish instance NAME. If EXPECTED_STATUS is provided, it checks that the status code of the response matches. If EXPECTED_RESPONSE is provided, it checks that the response matches the given regular expression.

The vlog command is used to dump the Varnish log.

vlog V1

The vlog command can also be used to filter the log.

vlog NAME [FILTER]
Dump the log of the Varnish instance NAME. If FILTER is provided, it filters the log entries based on the filter expression.

The vsladm command is used to interact with the Varnish Shared Memory Log (VSL).

vsladm V1 -A -q "ReqStart - * HTTP/1.1" -t raw

The vsladm command has many options, refer to the vsladm(1) manual page for more details.

The varnishadm command is used to send commands to the Varnish CLI. It takes the name of the Varnish instance and a string containing the command to send.

varnishadm v1 -T localhost:6082 -S /path/to/secret.txt -cmd status

The varnishadm command can also be used to check the status of the CLI response.

varnishadm vNAME [-cli STRING] [-cliok STRING] [-clierr STATUS STRING] [-cliexpect REGEXP STRING] [-clijson STRING]
Send STRING to the CLI of the Varnish instance vNAME. The options -cliok, -clierr, and -cliexpect can be used to check the response. -clijson checks if the response is valid JSON.

The vsc command is used to dump Varnish Statistics Counters (VSC).

vsc v1 -n MAIN.client.req

The vsc command can also be used to check the value of counters.

vsc vNAME PATTERN
Dump VSC counters matching PATTERN for the Varnish instance vNAME.
-expect PATTERN OP NUMBER|-expect !PATTERN
Check if the VSC counter identified by PATTERN has the correct value. OP can be ==, >, >=, <, or <=. The ! negates the test. For example:
varnish v1 -expect SM?.s1.g_space > 1000000
varnish v1 -expect cache_hit >= cache_hit_grace
varnish v1 -expect ! unexpected_counter

The test takes up to 5 seconds before timing out.

The MAIN. namespace can be omitted from PATTERN.

The vsl_catchup command waits until the logging thread has idled to make sure that all the generated log is flushed.

vsl_catchup v1

The vsm command is used to interact with the Varnish Shared Memory (VSM).

vsm m1 -n v1 -expect-status "mgt-running,wrk-running"

The vsm command has the following options:

mNAME
Identify the VSM consumer, it must starts with 'm'.
-n STRING
Choose the working directory of the varnish instance. By default a VSM consumer connects to ${v1_name}.
-attach
Attach to a new varnish instance. Implicitly detach from the current varnish instance if applicable.
-detach
Detach from the current varnish instance.
-expect-status STRING
Check that the status of VSM matches the list of status flags from STRING. The expected status is represented as a comma-separated list of flags. The list of flags in STRING is not sensitive to the order of flags.

The available flags are:

  • mgt-running
  • mgt-changed
  • mgt-restarted
  • wrk-running
  • wrk-changed
  • wrk-restarted

Expecting a status automatically attaches to the varnish instance if that was not already the case.
