VGMKNODES(8) دليل مدير النظام VGMKNODES(8)

الاسم

vgmknodes — إنشاء الملفات الخاصة لأجهزة مجموعات وحدات التخزين في /dev

ملخص

vgmknodes
[ وسيطات_خيارات ]
[ وسيطات_مواقع ]

الوصف

يقوم vgmknodes بفحص عقد أجهزة LVM في /dev المطلوبة لوحدات التخزين النشطة (LVs) وإنشاء أي منها مفقود وإزالة تلك غير المستخدمة.

عادةً لا يلزم هذا الأمر إذا كانت جميع مكونات النظام تتفاعل بشكل صحيح.

راجع أيضًا الملاحظات في نهاية صفحة الدليل هذه لاستخدام vgmknodes مع udev.

الاستخدام

vgmknodes

[ --ignorelockingfailure ]
[ --refresh ]
[ --reportformat basic|json|json_std ]
[ COMMON_OPTIONS ]
[ VG|LV|Tag ... ]

خيارات

--commandprofile String
ملف تعريف الأمر لاستخدامه في تكوين الأوامر. انظر lvm.conf(5) لمزيد من المعلومات حول الملفات التعريفية.
--config String
إعدادات التكوين للأمر. هذه تتجاوز إعدادات lvm.conf(5). يستخدم وسيط السلسلة نفس تنسيق lvm.conf(5)، أو قد يستخدم صيغة القسم/الحقل. انظر lvm.conf(5) لمزيد من المعلومات حول التكوين.
-d|--debug ...
ضبط مستوى التصحيح. كرر من 1 إلى 6 مرات لزيادة تفاصيل الرسائل المرسلة إلى ملف السجل و/أو syslog (إذا تم تكوينه).
--devices PV
يقيد الأجهزة التي تكون مرئية ومتاحة للأمر. الأجهزة غير المدرجة ستبدو مفقودة. يمكن تكرار هذا الخيار، أو قبول قائمة أجهزة مفصولة بفواصل. هذا يتجاوز ملف الأجهزة.
--devicesfile String
ملف يسرد الأجهزة التي يجب أن يستخدمها LVM. يجب أن يكون الملف موجودًا في /etc/lvm/devices/ ويتم إدارته باستخدام الأمر lvmdevices(8). هذا يتجاوز إعدادات lvm.conf(5) devices/devicesfile و devices/use_devicesfile.
--driverloaded y|n
إذا تم تعيينه على no، فلن يحاول الأمر استخدام device-mapper. للاختبار والتصحيح.
-h|--help
عرض نص المساعدة.
--ignorelockingfailure
يسمح للأمر بالاستمرار في عمليات بيانات التعريف للقراءة فقط بعد فشل التأمين.
--journal String
تسجيل المعلومات في سجل systemd. هذه المعلومات بالإضافة إلى المعلومات التي تم تمكينها بواسطة إعداد log/journal في lvm.conf. command: تسجيل معلومات حول الأمر. output: تسجيل الإخراج الافتراضي للأمر. debug: تسجيل التصحيح الكامل للأمر.
--lockopt String
يستخدم لتمرير خيارات للحالات الخاصة إلى lvmlockd. انظر lvmlockd(8) لمزيد من المعلومات.
--longhelp
عرض نص المساعدة الطويل.
--nohints
لا تستخدم ملف التلميحات لتحديد مواقع الأجهزة لوحدات التخزين الفيزيائية (PVs). قد يقرأ الأمر المزيد من الأجهزة للعثور على وحدات التخزين الفيزيائية عند عدم استخدام التلميحات. سيظل الأمر يقوم بإبطال صحة ملف التلميحات القياسي حيثما كان ذلك مناسبًا.
--nolocking
تعطيل التأمين. استخدم بحذر، قد تؤدي الأوامر المتزامنة إلى نتائج غير صحيحة.
--profile String
اسم مستعار لـ --commandprofile أو --metadataprofile، اعتمادًا على الأمر.
-q|--quiet ...
كتم الإخراج ورسائل السجل. يتجاوز --debug و --verbose. كرر مرة واحدة لكتم أي مطالبات مع الإجابة "لا" أيضًا.
--refresh
إذا كانت وحدة التخزين النشطة (LV) نشطة، فقم بإعادة تحميل بيانات التعريف الخاصة بها. في بيئة يتم فيها استخدام udev لإدارة محتوى /dev، يوصى بشدة باستخدام هذا الخيار. هذا لأنه يقوم التحديث أيضًا بإعادة إنشاء أحداث udev لوحدة تخزين نشطة (LV) بناءً على أي قواعد udev موجودة يتم تطبيقها لتعيين محتوى /dev والأذونات. أيضًا، قد تكون هذه العملية مفيدة إذا حدث خطأ ما، أو إذا كان يتم استخدام شكل من أشكال مشاركة وحدة التخزين النشطة (LV) يدويًا.
--reportformat basic|json|json_std
يتجاوز تنسيق الإخراج الحالي للتقارير الذي يتم تحديده عالميًا بواسطة إعداد report/output_format في lvm.conf(5). basic هو التنسيق الأصلي مع الأعمدة والصفوف. إذا كان هناك أكثر من تقرير واحد لكل أمر، يتم تسمية كل تقرير مسبقًا باسم التقرير لتحديد الهوية. json ينتج إخراج التقرير بتنسيق JSON. json_std ينتج إخراج التقرير بتنسيق JSON وهو أكثر توافقًا مع معيار JSON. انظر lvmreport(7) لمزيد من المعلومات.
-t|--test
التشغيل في وضع الاختبار. لن تقوم الأوامر بتحديث بيانات التعريف. يتم تنفيذ هذا عن طريق تعطيل جميع عمليات كتابة بيانات التعريف ولكن مع ذلك إرجاع النجاح إلى الدالة المستدعية. قد يؤدي هذا إلى رسائل خطأ غير عادية في العمليات متعددة المراحل إذا اعتمدت أداة ما على قراءة بيانات التعريف التي تعتقد أنها تغيرت ولكنها لم تتغير.
-v|--verbose ...
ضبط مستوى الإسهاب. كرر من 1 إلى 4 مرات لزيادة تفاصيل الرسائل المرسلة إلى stdout و stderr.
--version
عرض معلومات الإصدار.
-y|--yes
لا تطالب بالتأكيد بشكل تفاعلي ولكن افترض دائمًا الإجابة بنعم. استخدم بحذر شديد. (للإجابة التلقائية بـ "لا"، راجع -qq.)

vgmknodes(8) — LVM TOOLS

NAME

vgmknodes — create device nodes for LVM volume groups

SYNOPSIS

vgmknodes [--list_all] [--volume_list VolumeGroupName ...]

DESCRIPTION

vgmknodes is a helper program to create device nodes for LVM volume groups. It is called by the system startup scripts when LVM is activated.

If no options are specified, it creates device nodes for all active LVM volume groups.

If --list_all is specified, it creates device nodes for all known LVM volume groups, whether active or not.

If --volume_list is specified, it creates device nodes for the listed volume groups only. This option can be used multiple times.

USAGE

Normally, vgmknodes is called automatically by the LVM activation scripts during system startup. It is not intended for direct use by the administrator.

OPTIONS

--list_all
Create device nodes for all LVM volume groups known to the system, whether they are active or not. LVM volume groups that are not active are created with permission 0600.

--volume_list VolumeGroupName
Create device nodes for the specified volume group(s). This option may be specified multiple times to create device nodes for multiple volume groups.

--help
Display the help message.

--version
Display the version information.

VARIABLES

The following environment variables are supported:

PATH
The system PATH is searched for commands. This should normally be set to allow access to mknod and lsattr.
LVM_SB_FILE
Specify the location of the LVM super-block file. This is used only when accessing a single volume group from an LVM configuration file. This variable is usually set by the LVM activation scripts.
LVM_VG_NAME
Specify a default volume group name. This allows commands to omit the VolumeGroupName parameter.

ENVIRONMENT VARIABLES

See lvm(8) for information about environment variables used by lvm. For example, LVM_VG_NAME can generally be substituted for a required VG parameter.

NOTES

When using udev(7) to manage the /dev content, it is also highly recommended to use the --refresh option. This way, the necessary udev events are generated too and associated udev rules are properly applied. If the --refresh option is not used in this case, then LVM recreates the /dev content directly and udev will not have proper records about affected symlinks and nodes. Also, any node permissions defined by udev rules are not applied. This, in turn, may cause problems for other system components that rely on reading the udev database to get the list of /dev symlinks and nodes and which rely on the permissions based on udev rules.
