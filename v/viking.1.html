NAME

\n

viking - program to manage GPS data

\n
\n
\n

SYNOPSIS

\n

viking [-d | --debug] [-V | \n --verbose]\n
\n [--latitude degrees] \n [--longitude degrees]\n
\n [-z | --zoom ZoomLevelOSM] [-m | \n --map MapId] [-x | --external]\n
\n [file...] | [-]

\n

viking [-h | --help]

\n

viking [-v | --version]

\n
\n
\n

DESCRIPTION

\n

Viking is a program to manage GPS data.

\n

You can import and plot tracks, routes and waypoints, show\n OpenStreetMap (OSM) and/or other maps, generate maps (using Mapnik), geotag\n images, add coordinate lines, make new tracks, routes and waypoints, hide\n different things, etc. It is written mainly in C with some C++ and uses the\n GTK+ 3 toolkit. It is available for Linux, other POSIX operating systems and\n Windows.

\n

Homepage: http://viking.sf.net

\n

Viking is licensed under the GNU GPL.

\n
\n
\n

OPTIONS

\n

file

\n
Specify file(s) to load at start.\n

If a filename is in the 'geo' URI sheme (RFC5870[1]) then\n the positional information will be used (and it will not attempt to load it\n as a file)

\n
\n

-

\n
Read input from standard in.
\n

-d, --debug

\n
Enable debug output.
\n

-V, --verbose

\n
Enable verbose output.
\n

-?, --help

\n
Show help options.
\n

-v, --version

\n
Show version.
\n

--latitude

\n
Set the initial position to the specified latitude in\n decimal degrees.
\n

--longitude

\n
Set the initial position to the specified longitude in\n decimal degrees.
\n

-z, --zoom

\n
Set the initial zoom level. The value is the OSM\n zoom level (0 - 22).
\n

-m, --map

\n
Add a map layer by specifying the map id. The value needs\n to match one of the internal ids or an id from the maps configuration\n extension (see below). Specifying a value of 0 will use the map layer default.\n
Internal Map Ids:
\n
OSM Mapnik = 13
\n
OSM Cycle = 17
\n
OSM Transport = 20
\n
OSM Humanitarian = 22
\n
\n

-e, --external

\n
Load all specified GPX files in 'external' mode.\n

This is in contrast to importing the data and storing it in the\n Viking file.

EXTENDING VIKING

\n

Currently, viking has some extension points based on configuration\n files. The file format is heavily inspired by the GtkBuilder file format: \n you specify the class of the GObject to build and set its properties.\n Technically, it is a XML file containing a "objects" root element.\n Inside this element, you set a collection of "object".

\n

Here is an example:

\n
\n
<objects>\n  <object class="ClassName">\n    <property name="property_name1">Property value</property>\n    <property name="property_name2">Property value</property>\n  </object>\n  ...\n</objects>
\n
\n

You can find more examples in the documentation part of the\n distribution.

\n

The User Configuration File Location directory is ~/.viking for\n versions up to v1.8. For new installs from v1.9 onwards it is\n ~/.config/viking If the legacy location exists then Viking will use that in\n preference to the new location.

\n

Map Source. It is possible to add new map sources. The file\n is maps.xml in User Configuration File Location directory. An example of the\n file in the distribution doc/examples/maps.xml. The VikSlippyMapSource\n allows declaration of any map source working like OpenStreetMap. It supports\n the following properties:

\n

id

\n
this is an integer and should be unique as it used to\n identify the map source
\n

name

\n
a string (should be unique) that is used for the OSM\n style cache directory name when the Map Cache directory is the default (up to\n v1.8 ~/.viking-maps or v1.9 onwards~/.cache/viking)
\n

label

\n
the text displayed in the map's source selection\n dialog
\n

hostname

\n
the server's hostname (eg.\n "tile.openstreetmap.org")
\n

url

\n
the parametrized address of the tile, in the spirit of C\n printf format, with 3 "%d" fields for Z, X and Y (in that order)\n (eg. "/%d/%d/%d.png")\n
\n
\nNote\n
\nThe full parametrized address can just be put in the URL field and the hostname\n field doesn't need specifying.\n

e.g. "https://tile.openstreetmap.org/%d/%d/%d.png"

\n
\n
\n

custom-http-headers (optional)

\n
Custom HTTP headers to be added to the download request.\n The default is none.\n

Multiple headers can be specified by separating each part with an\n '\\n'.

\n

The header allows of substition of values of the positional Z, X\n and Y (in that order) values, as per the url option above. Using\n multiple and/or different ordered values can be acheived via printf() \n positional argument specifiers. For example:

\n

DNT: 1\\nLine2: %d %d %d\\nReordered: %3$d %1$d %2$d

\n
\n

copyright (optional)

\n
The copyright of the map source.
\n

license (optional)

\n
The license of the map source.
\n

license-url (optional)

\n
The URL of the license of the map source.
\n

zoom-min (optional)

\n
The minimum zoom value supported by the tile server. The\n Default is 0 if not specified.
\n

zoom-max (optional)

\n
The maximum zoom value supported by the tile server. The\n Default is 18 if not specified.\n

See Zoom Levels[2]

\n
\n

lat-min (optional)

\n
The minimum latitude value in degrees supported by the\n tile server. The Default is -90 degrees if not specified.
\n

lat-max (optional)

\n
The maximum latitude value in degrees supported by the\n tile server. The Default is 90 degrees if not specified.
\n

lon-min (optional)

\n
The minimum longitude value in degrees supported by the\n tile server. The Default is -180 degrees if not specified.
\n

lon-max (optional)

\n
The maximum longitude value in degrees supported by the\n tile server. The Default is 180 degrees if not specified.
\n

file-extension (optional)

\n
The file extension of the files on disk. The default is\n .png\n

If the tile source URL ends in something other than .png, then\n this parameter will need to match it.

\n

This can also be useful in reading a tileset from other software\n which may name tiles in an alternative form, e.g. for Mobile Atlas creator\n it names them .png.tile

\n
\n
\nNote\n
\nThe file types actually usable are those supported by GDK Pixbuf Library, which\n includes at least PNG and JPEG.\n
\n
\n
\nNote\n
\nRemember to include the beginning '.' when specifying this parameter.\n
\n
\n

offset-x (optional)

\n
The offset of the map in the x plane (towards east) in\n metres. The default is 0.0 if not specified.\n

Use negative numbers to adjust in a westerly direction.

\n

Typical usage would be aligning differing maps, e.g. aerial\n imagery may be offset from cadastral maps.

\n

Currently this is a single value that applies to all zoom\n levels.

\n
\n

offset-y (optional)

\n
The offset of the map in the y plane (towards north) in\n metres. The default is 0.0 if not specified.\n

Use negative numbers to adjust in a southerly direction.

\n
\n

switch-xy (optional)

\n
Swap the X,Y values around in the URL parametrized\n ordering.\n

The default is false.

الوصف

\n

Viking هو برنامج لإدارة بيانات GPS.

\n

يمكنك استيراد ورسم المسارات (tracks)، الخطط (routes) ونقاط الاهتمام (waypoints)، عرض خرائط OpenStreetMap (OSM) و/أو خرائط أخرى، إنشاء خرائط (باستخدام Mapnik)، إضافة بيانات جغرافية للصور، إضافة خطوط إحداثيات، إنشاء مسارات وخطط ونقاط اهتمام جديدة، إخفاء أشياء مختلفة، إلخ. تم كتابته بشكل أساسي بلغة C مع بعض C++ ويستخدم واجهة GTK+ 3. وهو متاح لأنظمة Linux، وأنظمة POSIX الأخرى، و Windows.

\n

الصفحة الرئيسية: http://viking.sf.net

\n

Viking مرخص بموجب رخصة GNU GPL.

توسيع Viking

\n

حالياً، يمتلك viking بعض نقاط التوسع بناءً على ملفات التكوين. تنسيق الملف مستوحى بشكل كبير من تنسيق ملف GtkBuilder: تحدد فئة GObject التي سيتم بناؤها وتعيين خصائصها. من الناحية الفنية، هو ملف XML يحتوي على عنصر جذر \"objects\". داخل هذا العنصر، تحدد مجموعة من \"object\" (كائنات).

\n

هذا مثال:

\n
\n
<objects>\n  <object class="ClassName">\n    <property name="property_name1">Property value</property>\n    <property name="property_name2">Property value</property>\n  </object>\n  ...\n</objects>
\n
\n

يمكنك العثور على المزيد من الأمثلة في جزء التوثيق الخاص بالتوزيع.

\n

موقع ملف تكوين المستخدم هو ~/.viking للإصدارات حتى v1.8. للتثبيتات الجديدة من v1.9 فصاعدًا، يكون ~/.config/viking. إذا كان الموقع القديم موجودًا، فسيستخدم Viking هذا الموقع بتفضيل على الموقع الجديد.

\n

مصدر الخريطة. من الممكن إضافة مصادر خرائط جديدة. الملف هو maps.xml في دليل موقع تكوين المستخدم. مثال للملف موجود في توثيق التوزيع /examples/maps.xml. يتيح VikSlippyMapSource إعلان أي مصدر خريطة يعمل مثل OpenStreetMap. ويدعم الخصائص التالية:

\n

id

\n
هذا عدد صحيح ويجب أن يكون فريدًا لأنه يستخدم لتحديد مصدر الخريطة.
\n

name

\n
سلسلة نصية (يجب أن تكون فريدة) تُستخدم لاسم دليل ذاكرة التخزين المؤقت بأسلوب OSM عندما يكون دليل ذاكرة التخزين المؤقت للخريطة افتراضيًا (حتى v1.8 ~/.viking-maps أو v1.9 فصاعدًا ~/.cache/viking).
\n

label

\n
النص المعروض في مربع حوار اختيار مصدر الخريطة.
\n

hostname

\n
اسم مضيف الخادم (مثال:\n \"tile.openstreetmap.org\").
\n

url

\n
العنوان المُنسق للبلاطة، بروح تنسيق C printf، مع 3 حقول \"%d\" لـ Z و X و Y (بهذا الترتيب) (مثال: \"/%d/%d/%d.png\").\n
\n
\nملاحظة\n
\nيمكن وضع العنوان المُنسق بالكامل في حقل URL ولا يلزم تحديد حقل اسم المضيف.\n

مثال: \"https://tile.openstreetmap.org/%d/%d/%d.png\".

\n
\n

check-file-server-time (اختياري)

يرسل الطابع الزمني للبلاطة إلى الخادم، بحيث يمكن للخادم أن يقرر ما إذا كان يجب عليه إرسال بلاطة جديدة أم لا.

القيمة الافتراضية هي false.

use-etag (اختياري)

يستخدم ويقارن قيمة ETag[3] في تحديد ما إذا كان سيتم تنزيل بلاطة أحدث. القيمة الافتراضية هي false.

يتم تخزين قيمة ETag في ملف منفصل في نفس الدليل مثل البلاطة لتمكين التحقق من القيمة عبر عمليات تشغيل متعددة للبرنامج.

referer (اختياري)

عنوان URL ليكون بمثابة المرجع لطلب HTTP (على سبيل المثال، "http://hostname/")

follow-location (اختياري)

الحد الأقصى لعدد عمليات إعادة التوجيه المسموح بها. القيمة الافتراضية هي 0، أي لا توجد إعادة توجيه. استخدم -1 لعدد غير محدود من عمليات إعادة التوجيه.

tilesize-y (اختياري)

حجم البلاطة y. القيمة الافتراضية هي 256 بكسل إذا لم يتم تحديدها.

أدوات خارجية. من الممكن إضافة أدوات خارجية جديدة. الملف هو external_tools.xml في دليل موقع ملف تكوين المستخدم. مثال على الملف في التوزيع doc/examples/external_tools.xml. يسمح VikWebtoolCenter بتعريف أي Webtool باستخدام منطق يعتمد على إحداثيات المركز ومستوى التكبير. الخصائص ذات الصلة هي:

label

url

يسمح VikWebtoolBounds بتعريف أي Webtool باستخدام منطق يعتمد على إحداثيات الحدود. الخصائص ذات الصلة هي:

label

النص المعروض في إدخال القائمة

url

محرك التوجيه. من الممكن تعريف محركات توجيه جديدة. الملف هو routing.xml في دليل موقع ملف تكوين المستخدم. مثال على الملف في التوزيع doc/examples/routing.xml. يسمح VikRoutingWebEngine بتعريف محرك توجيه متاح عبر HTTP. الخصائص ذات الصلة هي:

id

سلسلة، يجب أن تكون فريدة حيث يتم استخدامها لتحديد محرك التوجيه

label

النص المعروض في إدخال القائمة

format

رمز تنسيق GPSBabel لتفسير استجابة الخدمة. افتراضيًا، يتم توقع استجابة GPX ومعالجتها داخليًا. ومع ذلك، إذا كانت الخدمة ترجع تنسيقًا مختلفًا، فسيتم استخدام GPSBabel لتحويل النص إلى شيء يمكن لـ Viking فهمه. يمكن استخدام التنسيقات التي يدعمها GPSBabel فقط: على سبيل المثال، 'gpx'، 'kml'، 'gtrnctr' (لملفات Garmin Training Center .tcx)، إلخ...

استخدم gpsbabel --help على سطر الأوامر لمعرفة أنواع الملفات المدعومة ورموزها لمعالجتها.

url-base

عنوان URL الأساسي لخدمة الويب (على سبيل المثال، "http://hostname/service?")

url-start-ll

الجزء من عنوان URL الذي يحدد موقع نقطة البداية، معلمات بروح تنسيق C printf، مع 2 "%s" للإحداثيات (على سبيل المثال، "&start=%s,%s")

url-stop-ll

الجزء من عنوان URL الذي يحدد موقع نقطة النهاية، معلمات بروح تنسيق C printf، مع 2 "%s" للإحداثيات (على سبيل المثال، "&stop=%s,%s")

url-via-ll (اختياري)

الجزء من عنوان URL الذي يحدد موقع نقطة المرور، معلمات بروح تنسيق C printf، مع 2 "%s" للإحداثيات (على سبيل المثال، "&via=%s,%s")

url-start-dir (اختياري)

الجزء من عنوان URL الذي يحدد موقع نقطة البداية للتوجيه المستند إلى الاتجاه، معلمات بروح تنسيق C printf، مع "%s" واحد للاتجاه (على سبيل المثال، "&start=%s")

url-stop-dir (اختياري)

الجزء من عنوان URL الذي يحدد موقع نقطة النهاية للتوجيه المستند إلى الاتجاه، معلمات بروح تنسيق C printf، مع "%s" واحد للاتجاه (على سبيل المثال، "&start=%s")

url-ll-lat-first (اختياري)

ترتيب مصطلحات خط العرض / خط الطول في إعدادات URL للبداية والتوقف والمرور. افتراضيًا، هذه القيمة TRUE.

على سبيل المثال، باستخدام خدمات Brouter، يستخدم عنوان URL زوجًا من القيم هما خط الطول ثم خط العرض. وبالتالي، فإن تعيين هذه القيمة إلى FALSE يضمن تنفيذ استبدال القيمة بالترتيب اللازم.

referer (اختياري)

عنوان URL ليكون بمثابة المرجع لطلب HTTP (على سبيل المثال، "http://hostname/")

follow-location (اختياري)

الحد الأقصى لعدد عمليات إعادة التوجيه المسموح بها. القيمة الافتراضية هي 0، أي لا توجد إعادة توجيه. استخدم -1 لعدد غير محدود من عمليات إعادة التوجيه.

مصادر بيانات الملفات عن بعد. من الممكن إضافة مراجع ويب يتوقع أن ترجع ملفًا يمكن فتحه مباشرة أو تحويله عبر GPSBabel. الملف هو datasources.xml في دليل موقع ملف تكوين المستخدم الخاص بك. مثال على الملف موجود في توزيع المصدر doc/examples/datasources.xml. يسمح VikWebtoolDatasource بتعريف أي عنوان URL باستخدام منطق يعتمد على الإحداثيات. الخصائص ذات الصلة هي:

label

النص المعروض في إدخال القائمة

url

عنوان URL المعلم بالمعلمات لفتحه بروح تنسيق C printf، مع ما يصل إلى 7 قيم "%s". على سبيل المثال، http://hostname/getfile?lat=%s&lon=%s

يعطى ترتيب هذه المعلمات ومعناها بواسطة url_format_code أدناه

url_format_code

سلسلة تصف معلمات استبدال عنوان URL المعلم بالمعلمات، يمثل كل حرف كيفية ترجمة كل مصطلح.

B = أسفل العرض الحالي أي الحد الأدنى لخط العرض

L = يسار العرض الحالي أي الحد الأدنى لخط الطول

T = أعلى العرض الحالي أي الحد الأقصى لخط العرض

R = يمين العرض الحالي أي الحد الأقصى لخط الطول

A = خط العرض المركزي للعرض الحالي

O = خط الطول المركزي للعرض الحالي

Z = قيمة تكبير OSM للعرض الحالي. انظر مستويات التكبير[2]

S = سلسلة إدخال حددها المستخدم تم طلبها من المستخدم عبر مربع حوار

وبالتالي، بالنسبة لمثال عنوان URL أعلاه، يجب أن يكون رمز التنسيق AO

file_type

يتم تمرير هذه القيمة للمعلمة -i في الواجهة مع GPSBabel.

إذا لم يتم تعريفها، فسيتم تفسير الملف المُرجع داخليًا كملف GPX.

يمكن استخدام قيم محتملة مثل 'kml'، 'mapsource' إلخ. انظر تنسيقات ملفات GPSBabel[6] للحصول على القائمة الكاملة.

babel_filter_args

يتم تمرير هذه القيمة لمعاملات فلتر الواجهة مع GPSBabel.

على سبيل المثال، يمكن استخدام ""-x nuketypes,routes"" لتصفية جميع المسارات من النتائج.

input_label

تُستخدم هذه القيمة عند طلب الإدخال من المستخدم.

إنها تسمية مربع إدخال النص.

الملفات

دليل موقع ملف تكوين المستخدم هو ~/.viking للإصدارات حتى v1.8. للتثبيتات الجديدة، يكون ~/.config/viking من v1.9 فصاعدًا. إذا كان الموقع القديم موجودًا، فسيستخدم Viking هذا الموقع بشكل مفضل على الموقع الجديد.

Configuration: maps.xml

ملف يحتوي على تعريف مصادر الخرائط.

انظر القسم السابق للتفاصيل.

Configuration: goto_tools.xml

ملف يحتوي على تعريف خدمات "اذهب إلى".

انظر القسم السابق للتفاصيل.

Configuration: external_tools.xml

ملف يحتوي على تعريف الأدوات الخارجية.

انظر القسم السابق للتفاصيل.

Configuration: datasources.xml

ملف يحتوي على تعريف مصادر بيانات الملفات عن بعد.

انظر القسم السابق للتفاصيل.

Configuration: routing.xml

ملف يحتوي على تعريف مصادر التوجيه.

انظر القسم السابق للتفاصيل.

Configuration: viking.prefs

تفضيلات برنامج Viking.

Configuration: viking_layer_defaults.ini

القيم الافتراضية للطبقات لبرنامج Viking.

Configuration: viking.ini

قيم Viking يتم حفظها تلقائيًا بين الجلسات.

لا يُقصد عمومًا تعديلها يدويًا.

ومع ذلك، يمكن تعيين بعض التحكم الدقيق في القيم الداخلية الافتراضية.

Configuration: keys.rc

ملف يحتوي على مسرعات مفاتيح الاختصار.

هذا بتنسيق خريطة مسرعات GTK القياسية.

حتى الإصدار v1.8 ~/.viking-maps/، من v1.9 فصاعدًا ~/.cache/viking/

الموقع الافتراضي لذاكرة التخزين المؤقت للخرائط للبلاطات التي تم تنزيلها أو إنشاؤها بواسطة Viking.

إذا كان الموقع القديم موجودًا، فسيستخدم Viking هذا الموقع بشكل مفضل.

يتم أيضًا البحث عن ملفات الامتداد (maps.xml، goto_tools.xml، datasources.xml، external_tools.xml، routing.xml) في الدلائل /etc/viking و /usr/share/viking (أو ما يعادلها على نظامك).

البيئة

XDG_DATA_HOME

دليل اختياري للبحث عن ملفات الامتداد (maps.xml، goto_tools.xml، datasources.xml، external_tools.xml، routing.xml).

XDG_DATA_DIRS

المسار المستخدم لتغيير الدلائل التي يتم مسحها بحثًا عن ملفات الامتداد (maps.xml، goto_tools.xml، datasources.xml، external_tools.xml، routing.xml).

VIKING_MAPS

المسار المستخدم للموقع الجذر الافتراضي للخرائط.
