الاسم

varnishtest - برنامج اختبار لـ Varnish

الملخص

varnishtest [-hikLlqv] [-b size] [-D name=val] [-j jobs] [-n iter] [-t duration] file [file ...]

الوصف

برنامج varnishtest هو برنامج يعتمد على النصوص البرمجية يستخدم لاختبار Varnish Cache.

يمكن لبرنامج varnishtest، عند بدء تشغيله وإعطائه ملف نص برمجي واحد أو أكثر، إنشاء عدد من الخيوط التي تمثل الخلفيات، وبعض الخيوط التي تمثل العملاء، وعملية varnishd. يتم بعد ذلك استخدام هذا لمحاكاة معاملة لاستدعاء سلوك محدد.

الخيارات التالية متاحة:

-b size
تعيين حجم المخزن المؤقت الداخلي (الافتراضي: 1M)

-D name=val تعريف ماكرو للاستخدام في النصوص البرمجية

-h
عرض المساعدة
-i
تعيين PATH و vmod_path للعثور على ملفات Varnish الثنائية في شجرة الإنشاء
-j jobs
تشغيل هذا العدد من الاختبارات بالتوازي
-k
الاستمرار عند فشل الاختبار
-L
ترك vtc.* المؤقت دائمًا
-l
ترك vtc.* المؤقت إذا فشل الاختبار
-n iterations
تشغيل الاختبارات هذا العدد من المرات

-p name=val تمرير المعلمات إلى جميع أسطر أوامر varnishd

-q
وضع هادئ: الإبلاغ عن حالات الفشل فقط
-t duration
انتهاء مهلة الاختبارات بعد هذه المدة (الافتراضي: 60 ثانية)
-v
وضع مطول: الإبلاغ دائمًا عن سجل الاختبار

file ملف لاستخدامه كنص برمجي

إذا تم تعيين TMPDIR في البيئة، يقوم varnishtest بإنشاء أدلة مؤقتة vtc.* لكل اختبار في $TMPDIR، أو في /tmp.

النصوص البرمجية

تم توثيق بناء جملة vtc بشكل مفصل في vtc(7). إذا كنت ترغب في المزيد من الأمثلة بخلاف المثال أدناه، يمكنك إلقاء نظرة على مستودع شفرة المصدر الخاص بـ Varnish، تحت bin/varnishtest/tests/، حيث يتم الاحتفاظ بجميع اختبارات الانحدار لـ Varnish.

مثال:

varnishtest "#1029"
server s1 {
        rxreq
        expect req.url == "/bar"
        txresp -gzipbody {[bar]}
        rxreq
        expect req.url == "/foo"
        txresp -body {<h1>FOO<esi:include src="/bar"/>BARF</h1>}
} -start
varnish v1 -vcl+backend {
        sub vcl_backend_response {
                set beresp.do_esi = true;
                if (bereq.url == "/foo") {
                        set beresp.ttl = 0s;
                } else {
                        set beresp.ttl = 10m;
                }
        }
} -start
client c1 {
        txreq -url "/bar" -hdr "Accept-Encoding: gzip"
        rxresp
        gunzip
        expect resp.bodylen == 5
        txreq -url "/foo" -hdr "Accept-Encoding: gzip"
        rxresp
        expect resp.bodylen == 21
} -run

عند تشغيله، سيقوم النص البرمجي أعلاه بمحاكاة خادم (s1) يتوقع طلبين مختلفين. سيقوم بتشغيل خادم Varnish (v1) وإضافة تعريف الواجهة الخلفية إلى VCL المحدد (-vcl+backend). أخيرًا، يقوم بتشغيل العميل c1، وهو عميل واحد يرسل طلبين.

اختبار شجرة الإنشاء

سواء كنت تقوم بإنشاء VMOD أو تستخدم واحدة قمت ببنائها للتو، يمكنك إخبار varnishtest بتمرير vmod_path إلى عمليات varnishd التي يتم تشغيلها باستخدام أمر varnish -start في حالة الاختبار الخاصة بك:

varnishtest -p vmod_path=... /path/to/*.vtc

بهذه الطريقة، يمكنك استخدام نفس حالات الاختبار على VMODs المثبتة والمبنية:

server s1 {...} -start
varnish v1 -vcl+backend {
    import wossname;
    ...
} -start
...

أنت لست مقيدًا بـ vmod_path ويمكنك تمرير أي معلمة، مما يسمح لك بتشغيل مصفوفة بناء دون تغيير مجموعة الاختبار. يمكنك تحقيق نفس الشيء باستخدام وحدات الماكرو، ولكن بعد ذلك تحتاج إلى تعريفها في كل مرة يتم تشغيلها.

يمكنك رؤية أوامر varnishd الفعلية في مخرجات الاختبار، وتبدو تقريبًا كما يلي:

exec varnishd [varnishtest -p params] [testing params] [vtc -arg params]

قد يتم تجاوز المعلمات التي تحددها باستخدام varnishtest -p بواسطة المعلمات التي يحتاجها varnishtest للعمل بشكل صحيح، وقد يتم تجاوزها بدورها بواسطة المعلمات المحددة في نصوص الاختبار البرمجية.

هناك أيضًا وضع خاص يقوم فيه varnishtest ببناء مسار PATH و vmod_path لنفسه للعثور على ملفات Varnish الثنائية (البرامج و VMODs) في شجرة الإنشاء المحيطة بـ varnishtest الثنائي. هذا مخصص لاختبار Varnish قيد التطوير وسيتجاهل vmod_path الخاص بك إذا قمت بتعيين واحد.

إذا كنت بحاجة إلى اختبار VMOD الخاص بك مقابل شجرة بناء Varnish، فيجب عليك تثبيته أولاً، في دليل مؤقت على سبيل المثال. باستخدام المعلومات المقدمة من pkg-config(1) الخاص بالتثبيت، يمكنك بناء PATH مناسب للوصول إلى برامج Varnish، و vmod_path للوصول إلى كل من VMOD الخاص بك و VMODs المدمجة:

export PKG_CONFIG_PATH=/path/to/install/lib/pkgconfig
BINDIR="$(pkg-config --variable=bindir varnishapi)"
SBINDIR="$(pkg-config --variable=sbindir varnishapi)"
PATH="SBINDIR:BINDIR:$PATH"
VMODDIR="$(pkg-config --variable=vmoddir varnishapi)"
VMOD_PATH="/path/to/your/vmod/build/dir:$VMODDIR"
varnishtest -p vmod_path="$VMOD_PATH" ...
