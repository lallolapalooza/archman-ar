glNamedBufferData(3G)

الحزمة: opengl-man-pages

التراخيص: SGI-B-2.0, OPL-1.0

NAME

glNamedBufferData — orphanage an immutable immutable buffer object

C SPECIFICATION

void glNamedBufferData(GLuint buffer, GLsizeiptr size, const void *data, GLenum usage);

PARAMETERS

buffer
The name of the buffer object.
size
The size of the buffer object's new data store in _bytes_.
data
A pointer to the data that will be copied into the new buffer object's data store. If data is NULL, then the contents of the data store are initially undefined.
usage
The intended usage pattern of the buffer object. The usage pattern is a hint to the OpenGL implementation that optimizes buffer object choices. It is not a strict enforcement. The value must be one of the symbols in the following list:

GL_STREAM_DRAW, GL_STREAM_READ, GL_STREAM_COPY, GL_STATIC_DRAW, GL_STATIC_READ, GL_STATIC_COPY, GL_DYNAMIC_DRAW, GL_DYNAMIC_READ, GL_DYNAMIC_COPY.

DESCRIPTION

glNamedBufferData establishes the data store of a buffer object. If buffer is zero, then the buffer object that would otherwise be modified is the currently bound buffer object of the type determined by the first three entries in the group of enablers. If buffer is not zero, then it must be the name of an existing buffer object.

glNamedBufferData is equivalent to calling glBindBuffer with buffer and then calling glBufferData.

The buffer parameter is the name of the buffer object to be modified. The size parameter is the length in basic memory units of the value of the buffer object to be created. The data parameter is a pointer to the location in memory where the initial values of the buffer object are to be found. If data is NULL, then the buffer object is created with an uninitialized data store. The usage parameter is a hint to the OpenGL implementation of how the buffer object will be used.

When glNamedBufferData is called, the existing data store for the buffer object is deleted and size bytes of new storage is allocated for the buffer object. Any previous value set for the buffer object by a call to glBufferData or glNamedBufferData is replaced by the new data store. If data is not NULL, then size bytes of data will be copied from the location pointed to by data into the buffer object.

The usage parameter is an optional hint to the OpenGL implementation. It can be one of GL_STREAM_DRAW, GL_STREAM_READ, GL_STREAM_COPY, GL_STATIC_DRAW, GL_STATIC_READ, GL_STATIC_COPY, GL_DYNAMIC_DRAW, GL_DYNAMIC_READ, GL_DYNAMIC_COPY.

The hint tells the GL how the buffer is likely to be used. The GL can use this information to perform optimizations. For example, if the buffer is intended to be used for rendering (GL_STATIC_DRAW), the GL might place the buffer data in memory that is optimal for the GPU. If the buffer is intended to be used for reading by the application (GL_STATIC_READ), the GL might place the data in memory that is optimal for the CPU. If the buffer is intended to be modified once and used many times (GL_DYNAMIC_DRAW), the GL might choose a memory region that allows for faster CPU writes.

The usage pattern is a hint, not a rule. The GL is free to ignore the hint. For instance, if a buffer is created with GL_STATIC_DRAW, the application can still make calls to update the buffer, such as glBufferSubData, or map it for CPU access. However, performance might not be optimal.

If data is not NULL, then the buffer is created with the specified initial data. This is equivalent to calling glBufferData with a non-null data pointer.

If data is NULL, then the buffer is created with an uninitialized data store. This is equivalent to calling glBufferData with a null data pointer.

NOTES

Buffer objects are created using glGenBuffers, which returns a list of buffer object names. These names are opaque values that can be used to identify buffer objects. A buffer object is an alias for the GL object, it does not contain the object. Buffer objects are created by binding a name to a buffer object using glBindBuffer. Once created, the buffer object is immutable. Its size cannot be changed, only its contents.

If the size specified is larger than the current buffer object size, the buffer object will be resized. If the size specified is smaller than the current buffer object size, the buffer object will be truncated.

The data pointer is only valid for the duration of the glNamedBufferData call. The data is copied from the pointer into the buffer object's data store.

ERRORS

GL_INVALID_OPERATION is generated if buffer was not generated by glGenBuffers.

GL_INVALID_VALUE is generated if size is negative.

GL_INVALID_OPERATION is generated if data is not NULL and size is zero.

GL_INVALID_ENUM is generated if usage is not one of the recognized symbols.
