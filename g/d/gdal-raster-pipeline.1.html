gdal-raster-pipeline(1)

الحزمة: gdal

التراخيص: custom

GDAL-RASTER-PIPELINE(1) GDAL GDAL-RASTER-PIPELINE(1)

الاسم

gdal-raster-pipeline - معالجة مجموعة بيانات نقطية بتطبيق عدة خطوات

تمت الإضافة في الإصدار 3.11.

الوصف

يمكن استخدام gdal raster pipeline لمعالجة مجموعة بيانات نقطية وتنفيذ خطوات معالجة مختلفة تقبل بيانات نقطية وتنتج بيانات نقطية.

بالنسبة لخطوط الأنابيب التي تمزج بين البيانات النقطية والمتجهة، استشر gdal pipeline.

تتقدم معظم الخطوات بتقييم اختياري لكتل البيانات النقطية، ما لم يُذكر خلاف ذلك في وثائقها، دون "تجسيد" مجموعة البيانات الناتجة عن عملية كل خطوة. قد يكون من المرغوب فيه أحيانًا لأغراض الأداء الانتقال إلى تجسيد مجموعة بيانات وسيطة على القرص باستخدام gdal raster materialize.

ملخص

الاستخدام: gdal raster pipeline [خيارات] <خط_الأنابيب>
معالجة مجموعة بيانات نقطية بتطبيق عدة خطوات.
الوسائط الموضعية:
خيارات شائعة:
  -h, --help              عرض رسالة المساعدة والخروج
  --json-usage            عرض الاستخدام كمستند JSON والخروج
  --config <مفتاح>=<قيمة>  خيار التكوين [يمكن تكراره]
  -q, --quiet             وضع هادئ (لا يوجد شريط تقدم)
<خط_الأنابيب> هو من الشكل: read|mosaic|stack [خيارات_القراءة] ( ! <اسم_الخطوة> [خيارات_الخطوة] )* ! info|compare|tile|write [خيارات_الكتابة]

يقوم خط الأنابيب بربط عدة خطوات، مفصولة بحرف ! (علامة تعجب). يجب أن تكون الخطوة الأولى read أو calc أو mosaic أو stack، والخطوة الأخيرة write أو info أو tile. كل خطوة لها وسائطها الخاصة الموضعية أو غير الموضعية. بخلاف read و calc و mosaic و stack و compare و info و tile و write، يمكن استخدام جميع الخطوات الأخرى عدة مرات في خط الأنابيب.

  --nodata <عدم_البيانات>                                        تعيين قيمة عدم بيانات محددة لنطاقات الإخراج ('none'، قيمة رقمية، 'nan'، 'inf'، '-inf')

GDALG OUTPUT (ON-THE-FLY / STREAMED DATASET)

It is possible to output a GDAL dataset in memory (on-the-fly, streamed). This can be useful for algorithms that have to read the input data multiple times, or for chaining multiple algorithms. It can be added but if so it must explicitly specify the stream output format and a non-significant output dataset name.

{
    "type": "gdal_streamed_alg",
    "command_line": "gdal raster pipeline ! read in.tif ! reproject --dst-crs=EPSG:32632 ! write --output-format=streamed streamed_dataset"
}

SUBSTITUTIONS

Added in version 3.12.

It is possible to use gdal pipeline to use a pipeline already serialized in a .gdal.json file, and customize its existing steps, typically changing an input filename, specifying an output filename, or adding/modifying arguments of steps.

See Substitutions.

NESTED PIPELINE

Added in version 3.12.

It is possible to create "nested pipelines", i.e. pipelines inside pipelines.

A nested pipeline is delimited by square brackets ([ and ]) surrounded by a space character.

There are 2 kinds of nested pipelines:

  • input nested pipelines: where the result dataset of the nested pipeline is used as the input dataset for an argument of the main pipeline.
  • output nested pipelines: where the output of a step of the main pipeline is used as the input of the nested pipeline in a following step. Output nested pipelines can only be used with the tee step.

See Nested pipeline.

EXAMPLES

Example 1: Reproject a GeoTIFF file to CRS EPSG:32632 ("WGS 84 / UTM zone 32N") and adding a metadata item

$ gdal raster pipeline ! read in.tif ! reproject --dst-crs=EPSG:32632 ! edit --metadata AUTHOR=EvenR ! write out.tif --overwrite

Example 2: Serialize the command of a reprojection of a GeoTIFF file in a GDALG file, and later read it

$ gdal raster pipeline ! read in.tif ! reproject --dst-crs=EPSG:32632 ! write in_epsg_32632.gdalg.json --overwrite
$ gdal raster info in_epsg_32632.gdalg.json

Example 3: Mosaic on-the-fly several input files and tile that mosaic.

gdal raster pipeline ! mosaic input*.tif ! tile output_folder
