How to change how the keys are verified

 

--crl-file file
This option specifies a file containing a certificate revocation list (CRL). Normally, gpgsm retrieves the CRL via the cdp extension of the certificate. This option is only useful for the offline usage of gpgsm. Note that CRLs are not signed by the issuer but by the CA.
--disable-crl-verification
Disable checking of certificate revocation lists. Note that by default, verification is enabled.
--load-crl-into-storage
Load CRLs into the GnuPG storage. This is useful for CRLs that are updated very often. CRLs may be given via --crl-file.
--check-ocsp-response
Check the OCSP response. With this option, gpgsm will check the signature of the OCSP response. This is important for a secure use of OCSP.
--ocsp-url url
This option may be used to specify the URL of the OCSP responder. If this option is not given, gpgsm will query the certificate for its default OCSP responder URL.
--timestamp
A timestamp is required to verify signatures made with a private key whose expiration date is in the past. The timestamp is taken from the certificate if available, otherwise it is taken from the local system time.
--check-signatures
Check all signatures on all keys. This is a slow operation and is only useful for debugging.
--check-untrusted-certificates
By default, gpgsm checks if the certificate is trusted. With this option, you can disable this check. This is mostly useful for debugging.
--validate
Check the validity of certificates. If a certificate is invalid, it is rejected. This option is implied by most commands which check certificates.
--trust-model model
Set the trust model to be used. Valid models are:
default
The default model, which is not very strict.
peertrust
Peer trust model, which is stricter than the default.
fulltrust
Full trust model, which is the strictest.
The default trust model is "default".
--remote-cert-keys
Fetch all certificates needed for verification from the remote party. This is useful when the certificates are not available locally.
--remote-crl
Fetch CRLs from the remote party. This is useful when CRLs are not available locally.
--remote-ocsp
Fetch OCSP responses from the remote party. This is useful when OCSP responses are not available locally.
--remote-only
Only use certificates and CRLs from the remote party. Do not use any local certificates or CRLs.
--remote-skip-fetch
Do not fetch any certificates or CRLs from the remote party. Use only local certificates and CRLs.
--remote-timeout seconds
Set the timeout for fetching certificates and CRLs from the remote party. The timeout is specified in seconds.
--remote-verify
Verify certificates from the remote party. This option is implied by most commands which check certificates.
--remote-verify-only
Only verify certificates from the remote party. Do not fetch any certificates or CRLs from the remote party.
--remote-verify-strict
Verify certificates from the remote party strictly. This means that all certificates and CRLs must be valid.
--remote-verify-verbose
Verify certificates from the remote party verbosely. This means that all steps of the verification process will be printed.
--remote-verify-quiet
Verify certificates from the remote party quietly. This means that only errors will be printed.
--remote-verify-timeout seconds
Set the timeout for verifying certificates from the remote party. The timeout is specified in seconds.
--remote-verify-retries n
Set the number of retries for verifying certificates from the remote party. The number of retries is specified by n.
