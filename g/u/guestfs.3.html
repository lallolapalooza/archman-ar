يمكنك استدعاء "guestfs_parse_environment" أو "guestfs_parse_environment_list" بعد ذلك لتحليل متغيرات البيئة. بدلاً من ذلك، لا تستدعي هذه الدوال إذا كنت تريد أن تظل المقبض بدون تأثير من متغيرات البيئة. انظر المثال أدناه.

الافتراضي (إذا لم يتم تحديد هذا العلم) هو استدعاء "guestfs_parse_environment" ضمنيًا.

"GUESTFS_CREATE_NO_CLOSE_ON_EXIT"
لا تحاول إغلاق المقبض في معالج atexit(3) إذا خرج البرنامج دون إغلاق المقبض صراحةً.

الافتراضي (إذا لم يتم تحديد هذا العلم) هو تثبيت معالج atexit.

استخدام "GUESTFS_CREATE_NO_ENVIRONMENT"

قد تستخدم "GUESTFS_CREATE_NO_ENVIRONMENT" واستدعاء صريح لـ "guestfs_parse_environment" على النحو التالي:

guestfs_h *g;
int r;

g = guestfs_create_flags (GUESTFS_CREATE_NO_ENVIRONMENT);
if (!g) {
  perror ("guestfs_create_flags");
  exit (EXIT_FAILURE);
}
r = guestfs_parse_environment (g);
if (r == -1)
  exit (EXIT_FAILURE);

أو لإنشاء مقبض غير متأثر بمتغيرات البيئة، قم بتجاهل استدعاء "guestfs_parse_environment" من الكود أعلاه.

يحتوي الكود أعلاه على ميزة أخرى وهي أن أي أخطاء ناتجة عن تحليل البيئة يتم تمريرها عبر معالج الأخطاء، بينما يقوم "guestfs_create" بطباعة الأخطاء على stderr ويتجاهلها.

guestfs_close

void guestfs_close (guestfs_h *g);

يغلق هذا مقبض الاتصال ويحرر جميع الموارد المستخدمة. إذا تم تعيين رد اتصال الإغلاق على المقبض، فسيتم استدعاؤه.

الطريقة الصحيحة لإغلاق المقبض هي:

if (guestfs_shutdown (g) == -1) {
  /* معالجة أخطاء الكتابة هنا */
}
guestfs_close (g);

"guestfs_shutdown" مطلوب فقط إذا كان **كل** ما يلي صحيحًا:

1.
تمت إضافة قرص واحد أو أكثر في وضع القراءة والكتابة، *و*
2.
تم استدعاء guestfs_launch، *و*
3.
قمت بإجراء بعض التغييرات، *و*
4.
لديك طريقة لمعالجة أخطاء الكتابة (على سبيل المثال، عن طريق الخروج برمز خطأ أو الإبلاغ عن شيء للمستخدم).

معالجة الأخطاء

يمكن للدوال API إرجاع أخطاء. على سبيل المثال، ستعيد جميع الدوال تقريبًا التي تُرجع "int" -1 للإشارة إلى خطأ.

تتوفر معلومات إضافية للأخطاء: سلسلة رسالة خطأ ورقم خطأ اختياري (errno) إذا كان الشيء الذي فشل هو استدعاء نظام.

يمكنك الحصول على معلومات إضافية حول آخر خطأ في المقبض عن طريق استدعاء "guestfs_last_error"، "guestfs_last_errno"، و/أو عن طريق إعداد معالج أخطاء باستخدام "guestfs_set_error_handler".

عند إنشاء المقبض، يتم تثبيت معالج أخطاء افتراضي يقوم بطباعة سلسلة رسالة الخطأ إلى "stderr". بالنسبة للبرامج الصغيرة التي تعمل لفترة قصيرة، يكفي القيام بما يلي:

if (guestfs_launch (g) == -1)
  exit (EXIT_FAILURE);

حيث أن معالج الأخطاء الافتراضي سيضمن طباعة رسالة خطأ على "stderr" قبل خروج البرنامج.

بالنسبة للبرامج الأخرى، سيرغب المتصل تقريبًا دائمًا في تثبيت معالج أخطاء بديل أو إجراء معالجة الأخطاء بشكل مضمن كما في المثال أدناه. تقوم جميع ربطات اللغات غير C بتثبيت معالجات أخطاء NULL وتحويل الأخطاء إلى استثناءات باستخدام كود مشابه لهذا:

const char *msg;
int errnum;

/* هذا يعطل السلوك الافتراضي لطباعة الأخطاء
   على stderr. */
guestfs_set_error_handler (g, NULL, NULL);

if (guestfs_launch (g) == -1) {
  /* افحص رسالة الخطأ واطبعها، ارمها،
     إلخ. */
  msg = guestfs_last_error (g);
  errnum = guestfs_last_errno (g);

  fprintf (stderr, "%s", msg);
  if (errnum != 0)
    fprintf (stderr, ": %s", strerror (errnum));
  fprintf (stderr, "\n");

  /* ... */
}

تُرجع "guestfs_create" "NULL" إذا تعذر إنشاء المقبض، ولأنه لا يوجد مقبض في حالة حدوث ذلك، فلا توجد طريقة للحصول على معلومات خطأ إضافية. منذ libguestfs >= 1.20، يمكنك استخدام "guestfs_create_flags" للتعامل بشكل صحيح مع الأخطاء أثناء إنشاء المقبض، على الرغم من أن الغالبية العظمى من البرامج يمكن أن تستمر في استخدام "guestfs_create" دون القلق بشأن هذا الموقف.

تتم معالجة أخطاء نفاد الذاكرة بشكل مختلف. الإجراء الافتراضي هو استدعاء abort(3). إذا كان هذا غير مرغوب فيه، يمكنك تعيين معالج باستخدام "guestfs_set_out_of_memory_handler".

guestfs_last_error

const char *guestfs_last_error (guestfs_h *g);

تُرجع هذه الدالة آخر رسالة خطأ حدثت على "g". إذا لم يحدث خطأ منذ إنشاء المقبض، فإنها تُرجع "NULL".

لاحظ أن السلسلة المرجعة لا تحتوي على حرف سطر جديد في النهاية. معظم رسائل الخطأ هي سطور فردية. بعضها مقسم على أسطر متعددة وتحتوي على أحرف "\n" داخل السلسلة ولكن ليس في النهاية.

عمر السلسلة المرجعة هو حتى يحدث خطأ تالٍ على نفس المقبض، أو يتم استدعاء "guestfs_close". إذا كنت بحاجة إلى الاحتفاظ بها لفترة أطول، فانسخها.

guestfs_last_errno

int guestfs_last_errno (guestfs_h *g);

تُرجع هذه الدالة آخر رقم خطأ (errno) حدث على "g".

إذا نجحت، يتم إرجاع عدد صحيح errno لا يساوي صفرًا.

في العديد من الحالات، يتم إرجاع errno الخاص "ENOTSUP" إذا حاولت استدعاء دالة أو استخدام ميزة غير مدعومة.

إذا لم يكن رقم خطأ متاحًا، تُرجع هذه الدالة 0. يمكن أن تُرجع هذه المكالمة 0 في ثلاث حالات:

1.
لم يكن هناك أي خطأ في المقبض.
2.
حدث خطأ ولكن errno كان غير ذي معنى. يتوافق هذا مع الحالة التي لم يأت فيها الخطأ من استدعاء نظام فاشل، ولكن لسبب آخر.
3.
حدث خطأ من استدعاء نظام فاشل، ولكن لسبب ما لم يتم التقاط errno وإرجاعه. يشير هذا عادةً إلى خطأ في libguestfs.

يحاول Libguestfs تحويل errno من داخل التطبيق إلى errno مقابل للمتصل (ليس بالأمر السهل تمامًا: قد يعمل التطبيق بنظام تشغيل مختلف تمامًا عن المكتبة وأرقام الأخطاء ليست موحدة عبر Un*xen). إذا تعذر القيام بذلك، فسيتم ترجمة الخطأ إلى "EINVAL". من الناحية العملية، يجب أن يحدث هذا فقط في ظروف نادرة جدًا.

guestfs_set_error_handler

typedef void (*guestfs_error_handler_cb) (guestfs_h *g,
                                          void *opaque,
                                          const char *msg);
void guestfs_set_error_handler (guestfs_h *g,
                                guestfs_error_handler_cb cb,
                                void *opaque);

سيتم استدعاء رد الاتصال "cb" إذا كان هناك خطأ. المعلمات التي تم تمريرها إلى رد الاتصال هي مؤشر بيانات غير شفاف وسلسلة رسالة الخطأ.

لم يتم تمرير "errno" إلى رد الاتصال. للحصول عليه، يجب على رد الاتصال استدعاء "guestfs_last_errno".

لاحظ أن سلسلة الرسالة "msg" يتم تحريرها بمجرد عودة دالة رد الاتصال، لذلك إذا كنت ترغب في تخزينها في مكان ما، يجب عليك إنشاء نسخة خاصة بك.

يقوم المعالج الافتراضي بطباعة الرسائل على "stderr".

إذا قمت بتعيين "cb" إلى "NULL"، فلن يتم استدعاء أي معالج.

guestfs_get_error_handler

guestfs_error_handler_cb guestfs_get_error_handler (guestfs_h *g,
                                                    void **opaque_rtn);

تُرجع معالج الأخطاء الحالي.

guestfs_push_error_handler

void guestfs_push_error_handler (guestfs_h *g,
                                 guestfs_error_handler_cb cb,
                                 void *opaque);

هذه الدالة مماثلة لـ "guestfs_set_error_handler"، باستثناء أنه يتم تخزين معالج الخطأ القديم في مكدس داخل المقبض. يمكنك استعادة معالج الخطأ السابق عن طريق استدعاء "guestfs_pop_error_handler".

استخدم الكود التالي لتعطيل الأخطاء مؤقتًا حول دالة:

guestfs_push_error_handler (g, NULL, NULL);
guestfs_mkdir (g, "/foo"); /* لا نهتم إذا فشل هذا. */
guestfs_pop_error_handler (g);

guestfs_pop_error_handler

void guestfs_pop_error_handler (guestfs_h *g);

استعادة معالج الخطأ السابق (انظر "guestfs_push_error_handler").

إذا قمت بإزالة المكدس عدة مرات، فسيتم استعادة معالج الخطأ الافتراضي.

guestfs_set_out_of_memory_handler

typedef void (*guestfs_abort_cb) (void);
void guestfs_set_out_of_memory_handler (guestfs_h *g,
                                        guestfs_abort_cb);

سيتم استدعاء رد الاتصال "cb" إذا كان هناك وضع نفاد الذاكرة. *لاحظ أن رد الاتصال هذا يجب ألا يعود*.

الافتراضي هو استدعاء abort(3).

لا يمكنك تعيين "cb" إلى "NULL". لا يمكنك تجاهل مواقف نفاد الذاكرة.

struct guestfs_stat *

Returns file information for the given "path".

This is the same as the stat(2) system call.

This function returns a "struct guestfs_stat *", or NULL if there was an error. The caller must call "guestfs_free_stat" after use.

guestfs_statvfs

struct guestfs_statvfs *
guestfs_statvfs (guestfs_h *g,
                 const char *path);

Returns file system statistics for any mounted file system. "path" should be a file or directory in the mounted file system (typically it is the mount point itself, but it doesn't need to be).

This is the same as the statvfs(2) system call.

This function returns a "struct guestfs_statvfs *", or NULL if there was an error. The caller must call "guestfs_free_statvfs" after use.

(Added in 1.9.2)

guestfs_strings

char **
guestfs_strings (guestfs_h *g,
                 const char *path);

This runs the strings(1) command on a file and returns the list of printable strings found.

The "strings" command has, in the past, had problems with parsing untrusted files. These are mitigated in the current version of libguestfs, but see "CVE-2014-8484".

This function returns a NULL-terminated array of strings (like environ(3)), or NULL if there was an error. The caller must free the strings and the array after use.

Because of the message protocol, there is a transfer limit of somewhere between 2MB and 4MB. See "PROTOCOL LIMITS".

(Added in 1.0.22)

guestfs_strings_e

char **
guestfs_strings_e (guestfs_h *g,
                   const char *encoding,
                   const char *path);

This is like the "guestfs_strings" command, but allows you to specify the encoding of strings that are looked for in the source file "path".

Allowed encodings are:

s
Single 7-bit-byte characters like ASCII and the ASCII-compatible parts of ISO-8859-X (this is what "guestfs_strings" uses).
S
Single 8-bit-byte characters.
b
16-bit big endian strings such as those encoded in UTF-16BE or UCS-2BE.
l (lower case letter L)
16-bit little endian such as UTF-16LE and UCS-2LE. This is useful for examining binaries in Windows guests.
B
32-bit big endian such as UCS-4BE.
L
32-bit little endian such as UCS-4LE.

The returned strings are transcoded to UTF-8.

The "strings" command has, in the past, had problems with parsing untrusted files. These are mitigated in the current version of libguestfs, but see "CVE-2014-8484".

This function returns a NULL-terminated array of strings (like environ(3)), or NULL if there was an error. The caller must free the strings and the array after use.

Because of the message protocol, there is a transfer limit of somewhere between 2MB and 4MB. See "PROTOCOL LIMITS".

(Added in 1.0.22)

guestfs_swapon_device

int
guestfs_swapon_device (guestfs_h *g,
                       const char *device);

This command enables the libguestfs appliance to use the swap device or partition named "device". The increased memory is made available for all commands, for example those run using "guestfs_command" or "guestfs_sh".

Note that you should not swap to existing guest swap partitions unless you know what you are doing. They may contain hibernation information, or other information that the guest doesn't want you to trash. You also risk leaking information about the host to the guest this way. Instead, attach a new host device to the guest and swap on that.

This function returns 0 on success or -1 on error.

(Added in 1.0.66)

guestfs_sync

int
guestfs_sync (guestfs_h *g);

This syncs the disk, so that any writes are flushed through to the underlying disk image.

You should always call this if you have modified a disk image, before closing the handle.

This function returns 0 on success or -1 on error.

(Added in 0.3)
