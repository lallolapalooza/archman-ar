-mfpu=name
This specifies what floating-point hardware (or hardware emulation) is available on the target. Permissible names are: auto, vfpv2, vfpv3, vfpv3-fp16, vfpv3-d16, vfpv3-d16-fp16, vfpv3xd, vfpv3xd-fp16, neon-vfpv3, neon-fp16, vfpv4, vfpv4-d16, fpv4-sp-d16, neon-vfpv4, fpv5-d16, fpv5-sp-d16, fp-armv8, neon-fp-armv8 and crypto-neon-fp-armv8. Note that neon is an alias for neon-vfpv3 and vfp is an alias for vfpv2.

The setting auto is the default and is special. It causes the compiler to select the floating-point and Advanced SIMD instructions based on the settings of -mcpu and -march.

If the selected floating-point hardware includes the NEON extension (e.g. -mfpu=neon), note that floating-point operations are not generated by GCC's auto-vectorization pass unless -funsafe-math-optimizations is also specified. This is because NEON hardware does not fully implement the IEEE 754 standard for floating-point arithmetic (in particular denormal values are treated as zero), so the use of NEON instructions may lead to a loss of precision.

You can also set the fpu name at function level by using the target("fpu=") function attributes or pragmas.

-mfp16-format=name
Specify the format of the "__fp16" half-precision floating-point type. Permissible names are none, ieee, and alternative; the default is none, in which case the "__fp16" type is not defined.
-mstructure-size-boundary=n
The sizes of all structures and unions are rounded up to a multiple of the number of bits set by this option. Permissible values are 8, 32 and 64. The default value varies for different toolchains. For the COFF targeted toolchain the default value is 8. A value of 64 is only allowed if the underlying ABI supports it.

Specifying a larger number can produce faster, more efficient code, but can also increase the size of the program. Different values are potentially incompatible. Code compiled with one value cannot necessarily expect to work with code or libraries compiled with another value, if they exchange information using structures or unions.

This option is deprecated.

-mabort-on-noreturn
Generate a call to the function "abort" at the end of a "noreturn" function. It is executed if the function tries to return.
-mlong-calls
-mno-long-calls
Tells the compiler to perform function calls by first loading the address of the function into a register and then performing a subroutine call on this register. This switch is needed if the target function lies outside of the 64-megabyte addressing range of the offset-based version of subroutine call instruction.

Even if this switch is enabled, not all function calls are turned into long calls. The heuristic is that static functions, functions that have the "short_call" attribute, functions that are inside the scope of a "#pragma no_long_calls" directive, and functions whose definitions have already been compiled within the current compilation unit are not turned into long calls. The exceptions to this rule are that weak function definitions, functions with the "long_call" attribute or the "section" attribute, and functions that are within the scope of a "#pragma long_calls" directive are always turned into long calls.

This feature is not enabled by default. Specifying -mno-long-calls restores the default behavior, as does placing the function calls within the scope of a "#pragma long_calls_off" directive. Note these switches have no effect on how the compiler generates code to handle function calls via function pointers.

-msingle-pic-base
Treat the register used for PIC addressing as read-only, rather than loading it in the prologue for each function. The runtime system is responsible for initializing this register with an appropriate value before execution begins.
-mpic-register=reg
Specify the register to be used for PIC addressing. For standard PIC base case, the default is any suitable register determined by compiler. For single PIC base case, the default is R9 if target is EABI based or stack-checking is enabled, otherwise the default is R10.
-mpic-data-is-text-relative
Assume that the displacement between the text and data segments is fixed at static link time. This permits using PC-relative addressing operations to access data known to be in the data segment. For non-VxWorks RTP targets, this option is enabled by default. When disabled on such targets, it will enable -msingle-pic-base by default.
-mpoke-function-name
Write the name of each function into the text section, directly preceding the function prologue. The generated code is similar to this: 
t0
    .ascii "arm_poke_function_name", 0
    .align
t1
    .word 0xff000000 + (t1 - t0)
arm_poke_function_name
    mov     ip, sp
    stmfd   sp!, {fp, ip, lr, pc}
    sub     fp, ip, #4

When performing a stack backtrace, code can inspect the value of "pc" stored at "fp + 0". If the trace function then looks at location "pc - 12" and the top 8 bits are set, then we know that there is a function name embedded immediately preceding this location and has length "((pc[-3]) & 0xff000000)".

-mthumb
-marm
Select between generating code that executes in ARM and Thumb states. The default for most configurations is to generate code that executes in ARM state, but the default can be changed by configuring GCC with the --with-mode=state configure option.

You can also override the ARM and Thumb mode for each function by using the target("thumb") and target("arm") function attributes or pragmas.

-mflip-thumb
Switch ARM/Thumb modes on alternating functions. This option is provided for regression testing of mixed Thumb/ARM code generation, and is not intended for ordinary use in compiling code.
-mtpcs-frame
Generate a stack frame that is compliant with the Thumb Procedure Call Standard for all non-leaf functions. (A leaf function is one that does not call any other functions.) The default is -mno-tpcs-frame.
-mtpcs-leaf-frame
Generate a stack frame that is compliant with the Thumb Procedure Call Standard for all leaf functions. (A leaf function is one that does not call any other functions.) The default is -mno-apcs-leaf-frame.
-mcallee-super-interworking
Gives all externally visible functions in the file being compiled an ARM instruction set header which switches to Thumb mode before executing the rest of the function. This allows these functions to be called from non-interworking code. This option is not valid in AAPCS configurations because interworking is enabled by default.
-mcaller-super-interworking
Allows calls via function pointers (including virtual functions) to execute correctly regardless of whether the target code has been compiled for interworking or not. There is a small overhead in the cost of executing a function pointer if this option is enabled. This option is not valid in AAPCS configurations because interworking is enabled by default.
-mtp=name
Specify the access model for the thread local storage pointer. The model soft generates calls to "__aeabi_read_tp". Other accepted models are tpidrurw, tpidruro and tpidrprw which fetch the thread pointer from the corresponding system register directly (supported from the arm6k architecture and later). These system registers are accessed through the CP15 co-processor interface and the argument cp15 is also accepted as a convenience alias of tpidruro. The argument auto uses the best available method for the selected processor. The default setting is auto.
-mtls-dialect=dialect
Specify the dialect to use for accessing thread local storage. Two dialects are supported---gnu and gnu2. The gnu dialect selects the original GNU scheme for supporting local and global dynamic TLS models. The gnu2 dialect selects the GNU descriptor scheme, which provides better performance for shared libraries. The GNU descriptor scheme is compatible with the original scheme, but does require new assembler, linker and library support. Initial and local exec TLS models are unaffected by this option and always use the original scheme.

بدون هذا الخيار، قد يتم استخدام سجل "X" بنفس طريقة "Y" أو "Z"، والتي يتم محاكاتها بعد ذلك بواسطة تعليمات إضافية. على سبيل المثال، تحميل قيمة باستخدام عنونة "X+const" مع "const" صغير غير سالب < 64 > إلى سجل Rn يتم تنفيذه كما يلي:

sbiw r26, const   ; X -= const

"EIND" والأجهزة ذات ذاكرة فلاش تزيد عن 128 كيلوبايت

المؤشرات في التنفيذ بعرض 16 بت. عنوان الدالة أو التسمية يمثل كعنوان كلمة بحيث يمكن للقفزات والاستدعاءات غير المباشرة استهداف أي عنوان رمز في نطاق 64 ألف كلمة.

لتسهيل القفز غير المباشر على الأجهزة ذات مساحة ذاكرة برامج تزيد عن 128 كيلوبايت، يوجد سجل دالة خاص يسمى "EIND" يعمل كأكثر جزء أهمية من العنوان المستهدف عندما يتم استخدام تعليمات "EICALL" أو "EIJMP".

يتم التعامل مع القفزات والاستدعاءات غير المباشرة على هذه الأجهزة على النحو التالي بواسطة المترجم وتخضع لبعض القيود:

  • لا يقوم المترجم بتعيين "EIND" أبدًا.
  • يستخدم المترجم "EIND" ضمنيًا في تعليمات "EICALL"/"EIJMP" أو قد يقرأ "EIND" مباشرة لمحاكاة استدعاء/قفز غير مباشر عن طريق تعليمات "RET".
  • يفترض المترجم أن "EIND" لا يتغير أبدًا أثناء رمز بدء التشغيل أو أثناء التطبيق. على وجه الخصوص، لا يتم حفظ/استعادة "EIND" في مقدمة/خاتمة الدالة أو روتين خدمة المقاطعة.
  • للاستدعاءات غير المباشرة للدوال و goto المحسوبة، يقوم الرابط بإنشاء short (short). short هي وسادات قفز تسمى أحيانًا trampolines. وبالتالي، يقفز الاستدعاء/القفز غير المباشر إلى مثل هذا short. يحتوي short على قفزة مباشرة إلى العنوان المطلوب.
  • يجب تشغيل استرخاء الرابط حتى يتمكن الرابط من إنشاء short بشكل صحيح في جميع المواقف. انظر خيار المترجم -mrelax وخيار الرابط --relax. هناك حالات ركنية حيث يُفترض أن يقوم الرابط بإنشاء short ولكنه يتعطل بدون استرخاء وبدون رسالة خطأ مفيدة.
  • تم ترتيب نص الرابط الافتراضي للشفرة مع "EIND = 0". إذا كان من المفترض أن تعمل الشفرة مع إعداد "EIND != 0"، فيجب استخدام نص رابط مخصص لوضع المقاطع التي يبدأ اسمها بـ ".trampolines" في المقطع حيث يشير "EIND" إليه.
  • لا يقوم رمز بدء التشغيل من libgcc بتعيين "EIND" أبدًا. لاحظ أن رمز بدء التشغيل هو مزيج من الشفرة من libgcc و AVR-LibC. بالنسبة لتأثير AVR-LibC على "EIND"، راجع دليل مستخدم AVR-LibC ("https://avrdudes.github.io/avr-libc/avr-libc-user-manual/").
  • من الشرعي لرمز بدء التشغيل الخاص بالمستخدم تعيين "EIND" مبكرًا، على سبيل المثال عن طريق رمز التهيئة الموجود في المقطع ".init3". تعمل هذه الشفرة قبل رمز بدء التشغيل العام الذي يقوم بتهيئة ذاكرة الوصول العشوائي واستدعاء المنشئات، ولكن بعد قطعة رمز بدء التشغيل من AVR-LibC التي تعين "EIND" إلى المقطع حيث توجد جدول المتجهات. 
    #include <avr/io.h>

static void
__attribute__((section(".init3"),naked,used,no_instrument_function))
init3_set_eind (void)
{
  __asm volatile ("ldi r24,pm_hh8(__trampolines_start)\n\t"
                  "out %i0,r24" :: "n" (&EIND) : "r24","memory");
}

    يتم تعريف الرمز "__trampolines_start" في نص الرابط.

  • يتم إنشاء short تلقائيًا بواسطة الرابط إذا تم استيفاء الشرطين التاليين:
-<عنوان تسمية يتم أخذه بوساطة المعدل "gs">
(اختصار لـ إنشاء short) كما يلي: 
LDI r24, lo8(gs(<func>))
LDI r25, hi8(gs(<func>))
-<الموقع النهائي لهذه التسمية في مقطع شفرة>
خارج المقطع الذي توجد فيه short.
*
يصدر المترجم معدلات "gs" هذه لتسميات الشفرة في المواقف التالية:
-<أخذ عنوان دالة أو تسمية شفرة.>
-<goto المحسوبة.>
-<إذا تم استخدام دالة حفظ المقدمة، انظر -mcall-prologues>
خيار سطر الأوامر.
-<جداول توزيع المفتاح/الحالة. إذا كنت لا تريد مثل هذا التوزيع>
يمكنك تحديد خيار سطر الأوامر -fno-jump-tables.
-<المنشئات/الهدمات C و C++ التي يتم استدعاؤها أثناء بدء التشغيل/الإغلاق.>
-<إذا وصلت الأدوات إلى معدل gs() الموضح أعلاه.>
*
القفز إلى عناوين غير رمزية كما يلي غير مدعوم: 
int main (void)
{
    /* Call function at word address 0x2 */
    return ((int(*)(void)) 0x2)();
}

بدلاً من ذلك، يجب إعداد short، أي يجب استدعاء الدالة عبر رمز ("func_4" في المثال):

int main (void)
{
    extern int func_4 (void);

    /* Call function at byte address 0x4 */
    return func_4();
}

ويجب ربط التطبيق بـ -Wl,--defsym,func_4=0x4. بدلاً من ذلك، يمكن تعريف "func_4" في نص الرابط.

التعامل مع سجلات الوظائف الخاصة "RAMPD"، "RAMPX"، "RAMPY"، و "RAMPZ"

تدعم بعض أجهزة AVR ذاكرة أكبر من نطاق 64 كيلوبايت الذي يمكن الوصول إليه بمؤشرات 16 بت. للوصول إلى مواقع الذاكرة خارج هذا النطاق 64 كيلوبايت، يتم استخدام محتوى سجل "RAMP" كجزء أعلى من العنوان: يتم دمج سجلات العنوان "X"، "Y"، "Z" مع سجل الوظائف الخاص "RAMPX"، "RAMPY"، "RAMPZ"، على التوالي، للحصول على عنوان واسع. وبالمثل، يتم استخدام "RAMPD" مع العنونة المباشرة.

  • يقوم رمز بدء التشغيل بتهيئة سجلات الوظائف الخاصة "RAMP" بالقيمة صفر.
  • إذا تم استخدام مساحة اسم عنوان AVR مسماة مساحة اسم أخرى غير عامة أو "__flash"، فسيتم تعيين "RAMPZ" حسب الحاجة قبل العملية.
  • إذا كان الجهاز يدعم ذاكرة وصول عشوائي أكبر من 64 كيلوبايت ويحتاج المترجم إلى تغيير "RAMPZ" لإنجاز عملية ما، فسيتم إعادة تعيين "RAMPZ" إلى الصفر بعد العملية.
  • إذا كان الجهاز يأتي مع سجل "RAMP" محدد، فإن مقدمة/خاتمة ISR تحفظ/تستعيد SFR هذا وتهيئه بالقيمة صفر في حالة أن شفرة ISR قد تستخدمه (ضمنياً).
  • ذاكرة الوصول العشوائي الأكبر من 64 كيلوبايت غير مدعومة بواسطة GCC لأهداف AVR. إذا كنت تستخدم مترجمًا مضمنًا للقراءة من مواقع خارج نطاق العنوان 16 بت وتغيير أحد سجلات "RAMP"، فيجب عليك إعادة تعيينه إلى الصفر بعد الوصول.

وحدات الماكرو المدمجة لـ AVR

يعرف GCC وحدات ماكرو مدمجة متعددة حتى يتمكن المستخدم من اختبار وجود الميزات أو عدم وجودها. يتم استنتاج أي من وحدات الماكرو المدمجة التالية تقريبًا من إمكانيات الجهاز وبالتالي يتم تشغيلها بواسطة خيار سطر الأوامر -mmcu=.

-EL
تحديد ترميز Big-endian أو Little-endian. الافتراضي هو Little-endian.
-mfloat-abi=name
يحدد ABI الذي سيتم استخدامه للفاصلة العائمة. القيم المسموح بها هي: soft، softfp، و hard.

يؤدي تحديد soft إلى قيام GCC بإنشاء إخراج يحتوي على استدعاءات مكتبية لعمليات الفاصلة العائمة. يسمح softfp بإنشاء تعليمات الفاصلة العائمة للأجهزة، ولكنه لا يزال يستخدم اصطلاحات استدعاء الفاصلة العائمة الناعمة. يسمح hard بإنشاء تعليمات الفاصلة العائمة واستخدام اصطلاحات استدعاء خاصة بـ FPU.

الافتراضي يعتمد على تكوين الهدف المحدد. لاحظ أن ABI للفاصلة العائمة الصلبة والناعمة غير متوافقة مع الربط؛ يجب عليك تجميع برنامجك بالكامل بنفس ABI، والربط بمجموعة مكتبات متوافقة.

-mhard-float
-msoft-float
تحديد تطبيقات الفاصلة العائمة للأجهزة أو البرامج. الافتراضي هو الفاصلة العائمة الناعمة.
-mdouble-float
-mno-double-float
عندما يكون -mhard-float ساري المفعول، تمكين إنشاء تعليمات الفاصلة العائمة مزدوجة الدقة. هذا هو الافتراضي باستثناء عند التجميع لـ CK803.
-mfdivdu
-mno-fdivdu
عندما يكون -mhard-float ساري المفعول، تمكين إنشاء تعليمات "frecipd" و "fsqrtd" و "fdivd". هذا هو الافتراضي باستثناء عند التجميع لـ CK803.
-mfpu=fpu
تحديد معالج الفاصلة العائمة. يمكن استخدام هذا الخيار فقط مع -mhard-float. القيم الممكنة لـ fpu هي fpv2_sf (مكافئ لـ -mno-double-float -mno-fdivdu) و fpv2 (-mdouble-float -mno-divdu) و fpv2_divd (-mdouble-float -mdivdu).
-melrw
-mno-elrw
تمكين التعليمات الموسعة "lrw". هذا الخيار افتراضيًا قيد التشغيل لـ CK801 وإلا فهو معطل.
-mistack
-mno-istack
تمكين تعليمات مكدس المقاطعة؛ الافتراضي هو التعطيل.

الخيار -mistack مطلوب لمعالجة سمات الدوال "interrupt" و "isr".

-mmp
تمكين تعليمات المعالجات المتعددة؛ الافتراضي هو التعطيل.
-mcp
تمكين تعليمات المعالج المساعد؛ الافتراضي هو التعطيل.
-mcache
تمكين تعليمات المعالج المساعد؛ الافتراضي هو التعطيل.
-msecurity
تمكين تعليمات الأمان C-SKY؛ الافتراضي هو التعطيل.
-mtrust
تمكين تعليمات الثقة C-SKY؛ الافتراضي هو التعطيل.
-mdsp
-medsp
-mvdsp
تمكين تعليمات C-SKY DSP أو Enhanced DSP أو Vector DSP، على التوالي. كل هذه الخيارات افتراضيًا معطلة.
-mdiv
-mno-div
إنشاء تعليمات القسمة. الافتراضي هو التعطيل.
-msmart
-mno-smart
إنشاء تعليمات لـ Smart Mode، باستخدام السجلات من 0 إلى 7 فقط للسماح باستخدام التعليمات ذات 16 بت. يتم تجاهل هذا الخيار لـ CK801 حيث يكون هذا هو السلوك المطلوب، وهو افتراضيًا قيد التشغيل لـ CK802. بالنسبة للأهداف الأخرى، الافتراضي هو التعطيل.

خيارات Cygwin و MinGW

هذه الخيارات الإضافية متاحة لأهداف Microsoft Windows:

-mconsole
يحدد هذا الخيار أن تطبيق وحدة تحكم هو المطلوب إنشاؤه، عن طريق توجيه الرابط لتعيين نوع رأس PE الفرعي المطلوب لتطبيقات وحدة التحكم. هذا الخيار متاح لأهداف Cygwin و MinGW وهو ممكّن افتراضيًا على تلك الأهداف.
-mcrtdll=library
قم بالمعالجة المسبقة أو التجميع أو الربط باستخدام DLL وقت تشغيل C المحدد library. يقوم هذا الخيار بضبط وحدات الماكرو المعرفة مسبقًا "__CRTDLL__" و "__MSVCRT__" و "_UCRT" و "__MSVCRT_VERSION__" لـ CRT المحدد library، واختر ملف البدء لـ CRT library، واربط مع CRT library. أسماء مكتبات CRT المعترف بها للمعالج المسبق هي: "crtdll*" و "msvcrt10*" و "msvcrt20*" و "msvcrt40*" و "msvcr40*" و "msvcrtd*" و "msvcrt-os*" و "msvcr70*" و "msvcr71*" و "msvcr80*" و "msvcr90*" و "msvcr100*" و "msvcr110*" و "msvcr120*" و "ucrt*". إذا لم يتم تحديد هذا الخيار، فسيتم استخدام مكتبة استيراد MinGW الافتراضية "msvcrt" للربط ولا يتم إجراء أي تعديل آخر للمعالج المسبق. مكتبة استيراد MinGW "msvcrt" هي مجرد رابط رمزي لـ (أو نسخة من) مكتبة استيراد MinGW CRT أخرى مختارة أثناء تجميع MinGW. مكتبة استيراد MinGW "msvcrt-os" مخصصة لمكتبة DLL نظام Windows CRT "msvcrt.dll" وفي معظم الحالات تكون مكتبة استيراد MinGW الافتراضية. بشكل عام، تغيير CRT DLL يتطلب إعادة تجميع MinGW CRT بالكامل. هذا الخيار مخصص للأغراض التجريبية والاختبار فقط. هذا الخيار متاح لأهداف MinGW.
-mdll
هذا الخيار متاح لأهداف Cygwin و MinGW. يحدد أنه سيتم إنشاء DLL --- مكتبة ربط ديناميكية --- مما يسمح باختيار كائن بدء التشغيل ووقت التشغيل المطلوبين ونقطة الدخول.
-mnop-fun-dllimport
هذا الخيار متاح لأهداف Cygwin و MinGW. يحدد أنه يجب تجاهل السمة "dllimport".
-mthreads
هذا الخيار متاح لأهداف MinGW. يحدد أن دعم الخيوط الخاص بـ MinGW
-mno-abicalls
توليد (عدم توليد) رمز مناسب للكائنات الديناميكية بنمط SVR4. -mabicalls هو الإعداد الافتراضي للأنظمة المستندة إلى SVR4.
-mshared
-mno-shared
توليد (عدم توليد) رمز مستقل تمامًا عن الموضع، وبالتالي يمكن ربطه في مكتبات مشتركة. يؤثر هذا الخيار فقط على -mabicalls.

كانت جميع رموز -mabicalls تقليديًا مستقلة عن الموضع، بغض النظر عن خيارات مثل -fPIC و -fpic. ومع ذلك، كتوسيع، تسمح سلسلة أدوات GNU للملفات التنفيذية باستخدام وصول مطلق للرموز المرتبطة محليًا. يمكنها أيضًا استخدام تسلسلات تهيئة GP أقصر وتوليد استدعاءات مباشرة للدوال المعرفة محليًا. يتم تحديد هذا الوضع بواسطة -mno-shared.

يعتمد -mno-shared على binutils 2.16 أو أعلى ويولد كائنات لا يمكن ربطها إلا بواسطة الرابط GNU. ومع ذلك، لا يؤثر الخيار على ABI للملف التنفيذي النهائي؛ إنه يؤثر فقط على ABI للكائنات القابلة للترحيل. يؤدي استخدام -mno-shared بشكل عام إلى جعل الملفات التنفيذية أصغر وأسرع.

-mshared هو الإعداد الافتراضي.

يمكنك جعل -mplt هو الإعداد الافتراضي عن طريق تكوين GCC باستخدام --with-mips-plt. الإعداد الافتراضي هو -mno-plt بخلاف ذلك.

-mxgot
-mno-xgot
إزالة (عدم إزالة) القيود المعتادة على حجم جدول الإزاحة العام.

يستخدم GCC عادةً تعليمة واحدة لتحميل القيم من GOT. في حين أن هذا فعال نسبيًا، إلا أنه يعمل فقط إذا كان GOT أصغر من حوالي 64 ألف. أي شيء أكبر يتسبب في قيام الرابط بالإبلاغ عن خطأ مثل:

relocation truncated to fit: R_MIPS_GOT16 foobar

إذا حدث هذا، يجب عليك إعادة تجميع الكود الخاص بك باستخدام -mxgot. يعمل هذا مع GOTs كبيرة جدًا، على الرغم من أن الكود أقل كفاءة أيضًا، حيث يتطلب ثلاث تعليمات لجلب قيمة رمز عام.

لاحظ أن بعض الروابط يمكنها إنشاء GOTs متعددة. إذا كان لديك رابط من هذا القبيل، فيجب عليك فقط استخدام -mxgot عندما يصل كائن ملف واحد إلى أكثر من 64 ألف من إدخالات GOT. قليل جدًا يفعلون.

لا يمكن استخدام هذا الخيار إلا إذا كانت البنية المستهدفة تدعم تعليمات الفرع المحتمل (branch-likely). -mfix-r10000 هو الافتراضي عند استخدام -march=r10000؛ -mno-fix-r10000 هو الافتراضي بخلاف ذلك.

-mfix-r5900
-mno-fix-r5900

-mfix-rm7000
-mno-fix-rm7000
الالتفاف حول أخطاء RM7000 "dmult"/"dmultu". يتم تنفيذ الالتفافات بواسطة المُجمّع بدلاً من GCC.
-mfix-vr4120
-mno-fix-vr4120
الالتفاف حول أخطاء VR4120 معينة:
  • "dmultu" لا تعطي دائمًا النتيجة الصحيحة.
  • "div" و "ddiv" لا تعطي دائمًا النتيجة الصحيحة إذا كان أحد المعاملين سالبًا.

تعتمد الالتفافات لأخطاء القسمة على دوال خاصة في libgcc.a. في الوقت الحالي، يتم توفير هذه الدوال فقط بواسطة تكوينات "mips64vr*-elf".

تتطلب أخطاء VR4120 الأخرى إدراج NOP بين أزواج معينة من التعليمات. يتم التعامل مع هذه الأخطاء بواسطة المُجمّع، وليس بواسطة GCC نفسه.

-mfix-vr4130
الالتفاف حول أخطاء VR4130 "mflo"/"mfhi". يتم تنفيذ الالتفافات بواسطة المُجمّع بدلاً من GCC، على الرغم من أن GCC يتجنب استخدام "mflo" و "mfhi" إذا كانت تعليمات VR4130 "macc" و "macchi" و "dmacc" و "dmacchi" متاحة بدلاً منها.
-mfix-sb1
-mno-fix-sb1
الالتفاف حول أخطاء نواة معالج SB-1 معينة. (يعمل هذا العلم حاليًا على الالتفاف حول أخطاء الفاصلة العائمة "F1" و "F2" في مراجعة SB-1 رقم 2.)
-mr10k-cache-barrier=setting
تحديد ما إذا كان يجب على GCC إدراج حواجز ذاكرة التخزين المؤقت لتجنب الآثار الجانبية للتنبؤ على معالجات R10K.

مثل العديد من المعالجات، يحاول R10K التنبؤ بنتيجة فرع مشروط وتنفيذ التعليمات بشكل تخميني من الفرع "المتبع". يقوم لاحقًا بإلغاء هذه التعليمات إذا كان التنبؤ خاطئًا. ومع ذلك، على R10K، يمكن أن يكون للتعليمات الملغاة حتى آثار جانبية.

تؤثر هذه المشكلة فقط على عمليات التخزين في النواة، وتبعًا للنظام، على عمليات التحميل في النواة. على سبيل المثال، قد يقوم تخزين تم تنفيذه بشكل تخميني بتحميل الذاكرة المستهدفة في ذاكرة التخزين المؤقت وتعيين خط ذاكرة التخزين المؤقت كـ "متسخ"، حتى لو تم إلغاء التخزين نفسه لاحقًا. إذا قامت عملية DMA بالكتابة إلى نفس منطقة الذاكرة قبل "تنظيف" الخط "المتسخ"، فإن البيانات المخزنة مؤقتًا تستبدل بيانات DMA. راجع دليل معالج R10K للحصول على وصف كامل، بما في ذلك المشاكل المحتملة الأخرى.

أحد الحلول هو إدراج تعليمات حاجز ذاكرة التخزين المؤقت قبل كل وصول إلى الذاكرة قد يتم تنفيذه بشكل تخميني وقد يكون له آثار جانبية حتى لو تم إلغاؤه. يتحكم -mr10k-cache-barrier=setting في تنفيذ GCC لهذا الحل. يفترض أن عمليات الوصول الملغاة لأي بايت في المناطق التالية ليس لها آثار جانبية:

1.
الذاكرة التي تشغلها إطار المكدس للدالة الحالية؛
2.
الذاكرة التي تشغلها وسيطة مكدس واردة؛
3.
الذاكرة التي تشغلها
-munroll-only-small-loops
يتحكم في إلغاء تكرار الحلقات الصغيرة المحافظ. يتم تمكينه افتراضيًا بواسطة O2، ويقوم بإلغاء تكرار الحلقات التي تحتوي على أقل من 4 تعليمات مرة واحدة. -f[no-]unroll-[all-]loops الصريحة ستعطّل هذا العلم لتجنب أي سلوك غير مقصود لإلغاء التكرار لا يريده المستخدم.

خيارات Xtensa

تدعم أهداف Xtensa هذه الخيارات:

-mconst16
-mno-const16
تمكين أو تعطيل استخدام تعليمات "CONST16" لتحميل القيم الثابتة. إن تعليمة "CONST16" ليست حاليًا خيارًا قياسيًا من Tensilica. عند تمكينها، يتم دائمًا استخدام تعليمات "CONST16" بدلاً من تعليمات "L32R" القياسية. يتم تمكين استخدام "CONST16" افتراضيًا فقط إذا كانت تعليمة "L32R" غير متوفرة.
-mfused-madd
-mno-fused-madd
تمكين أو تعطيل استخدام تعليمات الجمع/الطرح المدمجة في العمليات الحسابية للأرقام العشرية. ليس لهذا أي تأثير إذا لم يتم تمكين خيار الأرقام العشرية أيضًا. يؤدي تعطيل تعليمات الجمع/الطرح المدمجة إلى إجبار المترجم على استخدام تعليمات منفصلة لعمليات الضرب والجمع/الطرح. قد يكون هذا مرغوبًا فيه في بعض الحالات التي تتطلب نتائج متوافقة بشكل صارم مع IEEE 754: تعليمات الجمع/الطرح المدمجة لا تقوم بتقريب النتيجة الوسيطة، مما ينتج عنه نتائج بدقة *أكبر* من تلك المحددة في المعيار. يؤدي تعطيل تعليمات الجمع/الطرح المدمجة أيضًا إلى ضمان عدم حساسية مخرجات البرنامج لقدرة المترجم على دمج عمليات الضرب والجمع/الطرح.
-mserialize-volatile
-mno-serialize-volatile
عند تمكين هذا الخيار، يقوم GCC بإدراج تعليمات "MEMW" قبل مراجع الذاكرة "volatile" لضمان التناسق المتسلسل. الافتراضي هو -mserialize-volatile. استخدم -mno-serialize-volatile لتخطي تعليمات "MEMW".
-mforce-no-pic
بالنسبة للأهداف، مثل GNU/Linux، حيث يجب أن تكون جميع تعليمات كود المستخدم (user-mode) قابلة للإزاحة (position-independent code - PIC)، يعطل هذا الخيار PIC لترجمة كود النواة.
-mtext-section-literals
-mno-text-section-literals
تتحكم هذه الخيارات في معالجة مجمعات الحروف (literal pools). الافتراضي هو -mno-text-section-literals، الذي يضع الحروف في قسم منفصل في ملف الإخراج. هذا يسمح بوضع مجمع الحروف في ذاكرة وصول عشوائي/قراءة فقط للبيانات، كما يسمح للرابط بدمج مجمعات الحروف من ملفات الكائنات المنفصلة لإزالة الحروف المتكررة وتحسين حجم الكود. مع -mtext-section-literals، يتم إدراج الحروف في قسم النص للحفاظ عليها قريبة قدر الإمكان من مراجعها. قد يكون هذا ضروريًا لملفات التجميع الكبيرة. يتم وضع الحروف لكل دالة مباشرة قبل تلك الدالة.
-mauto-litpools
-mno-auto-litpools
تتحكم هذه الخيارات في معالجة مجمعات الحروف. الافتراضي هو -mno-auto-litpools، الذي يضع الحروف في قسم منفصل في ملف الإخراج ما لم يتم استخدام -mtext-section-literals. مع -mauto-litpools، يتم إدراج الحروف في قسم النص بواسطة المجمع. لا ينتج المترجم توجيهات ".literal" صريحة ويقوم بتحميل الحروف في السجلات باستخدام تعليمات "MOVI" بدلاً من "L32R" للسماح للمجمع بإجراء الاسترخاء ووضع الحروف حسب الضرورة. يتيح هذا الخيار للمجمع إنشاء عدة مجمعات للحروف لكل دالة وتجميع دوال كبيرة جدًا، والتي قد لا تكون ممكنة مع -mtext-section-literals.
-mtarget-align
-mno-target-align
عند تمكين هذا الخيار، يقوم GCC بتوجيه المجمع لمحاذاة التعليمات تلقائيًا لتقليل عقوبات التفرع على حساب بعض كثافة الكود. يحاول المجمع توسيع تعليمات الكثافة لمحاذاة أهداف التفرع والتعليمات التي تلي استدعاءات الدوال. إذا لم تكن هناك تعليمات كثافة آمنة كافية قبل الهدف لمحاذاته، فلا يتم إجراء أي توسيع. الافتراضي هو -mtarget-align. هذه الخيارات لا تؤثر على معالجة التعليمات ذات المحاذاة التلقائية مثل "LOOP"، والتي يحاذيها المجمع دائمًا، إما عن طريق توسيع تعليمات الكثافة أو عن طريق إدراج تعليمات NOP.
-mlongcalls
-mno-longcalls
عند تمكين هذا الخيار، يقوم GCC بتوجيه المجمع لترجمة الاستدعاءات المباشرة إلى استدعاءات غير مباشرة ما لم يتمكن من تحديد أن هدف الاستدعاء المباشر يقع ضمن النطاق المسموح به لتعليمة الاستدعاء. تحدث هذه الترجمة عادةً لاستدعاءات الدوال في ملفات المصدر الأخرى. على وجه التحديد، يقوم المجمع بترجمة تعليمة "CALL" المباشرة إلى "L32R" تليها تعليمة "CALLX". الافتراضي هو -mno-longcalls. يجب استخدام هذا الخيار في البرامج التي يمكن أن يكون فيها هدف الاستدعاء خارج النطاق. يتم تنفيذ هذا الخيار في المجمع، وليس في المترجم، لذا فإن كود التجميع الذي يولده GCC لا يزال يعرض تعليمات استدعاء مباشرة - انظر كود الكائنات المفكك لرؤية التعليمات الفعلية. لاحظ أن المجمع يستخدم استدعاءً غير مباشر لكل استدعاء عبر الملفات، وليس فقط تلك التي تكون خارج النطاق حقًا.
-mabi=name
إنشاء كود لـ ABI المحدد. القيم المسموح بها هي: call0، windowed. يتم اختيار ABI الافتراضي بواسطة تكوين نواة Xtensa.
-mabi=call0
عند تمكين هذا الخيار، يتم تمرير معاملات الدوال في السجلات "a2" إلى "a7"، ويتم حفظ السجلات "a12" إلى "a15" بواسطة المستدعي، وقد يتم استخدام السجل "a15" كمؤشر إطار. عند تمكين هذا الإصدار من ABI، يتم تعريف رمز المعالج المسبق لـ C "__XTENSA_CALL0_ABI__".
-mabi=windowed
عند تمكين هذا الخيار، يتم تمرير معاملات الدوال في السجلات "a10" إلى "a15"، وتقوم الدالة المستدعاة بتدوير نافذة السجل بمقدار 8 سجلات عند الدخول بحيث توجد وسائطها في السجلات "a2" إلى "a7". قد يتم استخدام السجل "a7" كمؤشر إطار. يتم تدوير نافذة السجل 8 سجلات للخلف عند العودة. عند تمكين هذا الإصدار من ABI، يتم تعريف رمز المعالج المسبق لـ C "__XTENSA_WINDOWED_ABI__".
-mextra-l32r-costs=n
تحديد تكلفة إضافية للوصول إلى ذاكرة التعليمات/قراءة فقط لتعليمات "L32R"، بوحدات الساعة. يؤثر هذا، عند التحسين للسرعة، على ما إذا كان تحميل ثابت من مجمع الحروف باستخدام "L32R" أو توليف الثابت من ثابت صغير باستخدام زوج من تعليمات الحساب. القيمة الافتراضية هي 0.
-mstrict-align
-mno-strict-align
تجنب أو السماح بإنشاء عمليات وصول إلى الذاكرة قد لا تكون محاذية لحدود الكائن الطبيعية كما هو موضح في مواصفات البنية. الافتراضي هو -mno-strict-align للنوى التي تدعم كل من عمليات التحميل والتخزين غير المحاذية في الأجهزة و -mstrict-align لجميع النوى الأخرى.
