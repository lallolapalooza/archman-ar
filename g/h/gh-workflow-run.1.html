gh-workflow-run(1)

الحزمة: github-cli

التراخيص: MIT

GH-WORKFLOW-RUN(1) دليل GitHub CLI GH-WORKFLOW-RUN(1)

الاسم

gh-workflow-run - تشغيل سير عمل عن طريق إنشاء حدث workflow_dispatch

الملخص

gh workflow run [<معرف-سير-العمل> | <اسم-سير-العمل>] [علامات]

الوصف

إنشاء حدث workflow_dispatch لسير عمل معين.

سيقوم هذا الأمر بتشغيل GitHub Actions لتشغيل ملف سير عمل معين. يجب أن يدعم ملف سير العمل المحدد مشغل on.workflow_dispatch ليتم تشغيله بهذه الطريقة.

إذا كان ملف سير العمل يدعم مدخلات، فيمكن تحديدها بعدة طرق:

  • بشكل تفاعلي
  • عبر العلامات -f/--raw-field أو -F/--field
  • بتنسيق JSON، عبر الإدخال القياسي

الخيارات

-F, --field <مفتاح=قيمة>
إضافة معامل نصي بتنسيق مفتاح=قيمة، مع احترام بناء @ (راجع "gh help api").
--json
قراءة مدخلات سير العمل بتنسيق JSON عبر STDIN
-f, --raw-field <مفتاح=قيمة>
إضافة معامل نصي بتنسيق مفتاح=قيمة
-r, --ref <نص>
اسم الفرع أو الوسم الذي يحتوي على إصدار ملف سير العمل الذي ترغب في تشغيله

الخيارات الموروثة من أوامر الأصل

-R, --repo <[المضيف/]المالك/المستودع>
تحديد مستودع آخر باستخدام تنسيق [المضيف/]المالك/المستودع

رموز الخروج

0: تنفيذ ناجح

1: خطأ

2: تم إلغاء الأمر

4: المصادقة مطلوبة

ملاحظة: قد يكون للأوامر المحددة رموز خروج إضافية. ارجع إلى مساعدة الأمر لمزيد من المعلومات.

مثال

# اجعل gh يطالبك بما ترغب في تشغيله من سير عمل وجمع المدخلات بشكل تفاعلي
$ gh workflow run
# تشغيل ملف سير العمل 'triage.yml' في الفرع الافتراضي للمستودع البعيد
$ gh workflow run triage.yml
# تشغيل ملف سير العمل 'triage.yml' في مرجع محدد
$ gh workflow run triage.yml --ref my-branch
# تشغيل ملف سير العمل 'triage.yml' مع مدخلات سطر الأوامر
$ gh workflow run triage.yml -f name=scully -f greeting=hello
# تشغيل ملف سير العمل 'triage.yml' مع JSON عبر الإدخال القياسي
$ echo '{"name":"scully", "greeting":"hello"}' | gh workflow run triage.yml --json
