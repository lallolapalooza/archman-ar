git-mv(1)

الحزمة: git

التراخيص: GPL-2.0-only

GIT-MV(1) دليل Git GIT-MV(1)

الاسم

git-mv - نقل أو إعادة تسمية ملف، مجلد، أو رابط رمزي

الملخص

git mv [-v] [-f] [-n] [-k] <مصدر> <وجهة>
git mv [-v] [-f] [-n] [-k] <مصدر>... <مجلد-الوجهة>

الوصف

نقل أو إعادة تسمية ملف، مجلد، أو رابط رمزي.

في الصيغة الأولى، تقوم بإعادة تسمية <مصدر>، والذي يجب أن يكون موجوداً وأن يكون ملفاً، رابطاً رمزياً، أو مجلداً، إلى <وجهة>. في الصيغة الثانية، يجب أن يكون <مجلد-الوجهة> مجلداً موجوداً؛ سيتم نقل المصادر المعطاة إلى هذا المجلد.

يتم تحديث الفهرس بعد اكتمال ناجح، ولكن يجب عمل commit للتغيير.

خيارات

-f, --force

فرض إعادة التسمية أو النقل لملف حتى لو كانت <وجهة> موجودة.

-k

تجاوز إجراءات النقل أو إعادة التسمية التي ستؤدي إلى حالة خطأ. يحدث الخطأ عندما لا يكون المصدر موجوداً أو غير متحكم به بواسطة Git، أو عندما يحاول استبدال ملف موجود ما لم يتم استخدام -f.

-n, --dry-run

لا تفعل شيئاً؛ فقط أظهر ما سيحدث.

-v, --verbose

الإبلاغ عن أسماء الملفات أثناء نقلها.

الوحدات الفرعية

نقل وحدة فرعية باستخدام ملف git (وهو ما يعني أنه تم استنساخها باستخدام إصدار Git 1.7.8 أو أحدث) سيقوم بتحديث ملف git وإعداد core.worktree لجعل الوحدة الفرعية تعمل في الموقع الجديد. كما سيحاول تحديث إعداد submodule.<name>.path في ملف gitmodules(5) ووضع هذا الملف في منطقة التتبع (ما لم يتم استخدام -n).

أخطاء

في كل مرة ينقل فيها تحديث مشروع رئيسي وحدة فرعية مملوءة (على سبيل المثال، عند التبديل بين الـ commits قبل وبعد النقل)، ستبقى نسخة فرعية قديمة في الموقع القديم وسيظهر مجلد فارغ في الموقع الجديد. لملء الوحدة الفرعية مرة أخرى في الموقع الجديد، سيتعين على المستخدم تشغيل "git submodule update" بعد ذلك. إزالة المجلد القديم آمن فقط عندما يستخدم ملف git، وإلا فسيتم حذف تاريخ الوحدة الفرعية أيضاً. سيتم إلغاء كلا الخطوتين عندما يتم تنفيذ التحديث المتكرر للوحدات الفرعية.
