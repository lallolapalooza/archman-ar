الاسم

git-annex-resolvemerge - حل تعارضات الدمج

الملخص

git annex resolvemerge

الوصف

يقوم بحل تعارض الدمج تلقائيًا. يتم ذلك تلقائيًا عند استخدام git annex sync أو git annex merge.

عندما يحتوي شجرتان يتم دمجهما على إصدارات متعارضة من ملف ملحق، سيتم حل تعارض الدمج عن طريق إضافة كلا الإصدارين إلى الشجرة، باستخدام صيغ مختلفة لاسم الملف.

عندما يقوم شجر بتعديل الملف، والشجر الآخر بحذف الملف، سيتم حل تعارض الدمج عن طريق إضافة الملف المعدل باستخدام صيغة مختلفة لاسم الملف، مع ترك اسم الملف الأصلي محذوفًا.

عندما يتضمن تعارض الدمج ملفًا ملحقًا في شجرة، ولكنه غير ملحق في الشجرة الأخرى، يتم حله عن طريق الاحتفاظ بالملف غير الملحق كما هو، وإضافة الإصدار الملحق باستخدام صيغة مختلفة لاسم الملف.

لاحظ أن تعارضات الدمج التي تتضمن ملفًا واحدًا أو أكثر ملحقًا فقط هي التي يتم حلها. تعارضات الدمج بين ملفين غير ملحقين لن يتم حلها تلقائيًا.

أمثلة

لنفترض أن أليس ارتكبت تغييرًا في الملف الملحق foo، وأن بوب ارتكب تغييرًا مختلفًا في نفس الملف foo.

سيؤدي الدمج بينهما إلى الفشل، وسيقوم git بتقديم تعارض الدمج كملف foo يشير إلى أحد إصدارات الرابط الرمزي لـ git-annex، مع الإشارة إلى أن foo لديه تعارض غير محلول في git status.

سيؤدي تشغيل git annex resolvemerge في هذا الموقف إلى حل تعارض الدمج، عن طريق استبدال الملف foo بملفات ذات أسماء مثل foo.variant-c696 و foo.variant-f16a. أحد الملفات له المحتوى الذي ارتكبته أليس، والآخر له المحتوى الذي ارتكبه بوب.

يمكن للمستخدم بعد ذلك فحص كلا الصيغتين للملف، وإما دمج التغييرين في ملف واحد، أو إعادة تسمية أحدهما إلى foo وحذف الآخر.

الآن لنفترض أن أليس ارتكبت تغييرًا في الملف الملحق bar، بينما ارتكب بوب حذفًا لنفس الملف bar. سيفشل الدمج. سيؤدي تشغيل git annex resolvemerge في هذا الموقف إلى حل تعارض الدمج عن طريق إنشاء ملف باسم مثل bar.variant-421f يحتوي على إصدار أليس. يظل الملف bar محذوفًا. يمكن للمستخدم لاحقًا فحص صيغة الملف وإما إعادة تسميتها إلى bar، أو اتخاذ قرار بحذفها أيضًا.

خيارات

يمكن استخدام git-annex-common-options(1).
