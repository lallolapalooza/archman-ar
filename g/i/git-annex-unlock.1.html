الاسم

git-annex-unlock - إلغاء قفل الملفات للتعديل

الملخص

git annex unlock [مسار ...]

الوصف

عادةً، يتم حماية محتوى الملفات المرفقة من التغيير. إلغاء قفل ملف مرفق يسمح بتعديله. عندما لا يتم تحديد أي ملفات، يتم إلغاء قفل جميع الملفات المرفقة في الدليل الحالي.

إلغاء قفل ملف يغير طريقة تخزينه في مستودع git (من رابط رمزي إلى ملف مؤشر)، لذلك سيقوم هذا الأمر بإجراء تغيير يمكنك تثبيته (commit).

محتوى الملف غير المقفل لا يزال مخزنًا في git-annex، وليس git، وعندما تقوم بتثبيت تعديلات على الملف، سيتم أيضًا تخزين التعديلات في git-annex، مع تخزين ملف المؤشر فقط في git.

إذا استخدمت git add لإضافة ملف إلى المرفق، فسيتم إضافته في شكل غير مقفل منذ البداية. هذا يسمح بسير عمل حيث يبدأ الملف غير مقفل، ويتم تعديله حسب الحاجة، ويتم قفله بمجرد وصوله إلى نسخته النهائية.

عادةً، يتطلب إلغاء قفل ملف إنشاء نسخة من محتواه، بحيث يتم الاحتفاظ بالمحتوى الأصلي، بينما يمكن تعديل النسخة. لاستخدام مساحة أقل، يمكن تعيين annex.thin على true؛ هذا يؤدي إلى إنشاء رابط صلب للمحتوى بدلاً من نسخة. (فقط عندما يدعم نظام الملفات ذلك.) بينما يمكن أن يوفر هذا مساحة كبيرة على القرص، فإن أي تعديل يتم إجراؤه على ملف سيؤدي إلى فقدان الإصدار القديم من الملف من المستودع المحلي. لذا، قم بتمكين annex.thin بحذر.

أمثلة


# git annex unlock disk-image
# git commit -m "تم إلغاء قفل القرص السماح للآلة الافتراضية بإجراء تغييرات أثناء تشغيلها"


# git annex unlock photo.jpg
# gimp photo.jpg
# git commit photo.jpg -m "إزالة العين الحمراء"
# gimp photo.jpg
# git commit photo.jpg -m "إصلاح التشبع المفرط" # git annex lock photo.jpg

خيارات

خيارات مطابقة الملف
يمكن استخدام git-annex-matching-options(1) لتحديد الملفات المراد إلغاء قفلها.
--json
تمكين إخراج JSON. هذا مخصص للبرامج التي تستخدم git-annex لتحليله. كل سطر من المخرجات هو كائن JSON.
--json-error-messages
الرسائل التي عادة ما يتم إخراجها إلى الخطأ القياسي يتم تضمينها في JSON بدلاً من ذلك.
يمكن أيضًا استخدام git-annex-common-options(1).
