الحزمة: git

NAME

git-am - Apply a series of patches from an mailbox

SYNOPSIS

git am [options] [mbox|file... ]
git am --continue|--abort|--skip

DESCRIPTION

This command is used to apply a series of patches extracted from an mbox(5) or a single patch file. Patches can be applied from mbox files or individual patch files.

When git am is run, it applies the patches found in the given mailboxes or files.

If the command fails, it will stop on the first patch that cannot be applied. The user can then resolve the conflict, and continue the patching process by running git am --continue. Alternatively, the user can skip the current patch by running git am --skip, or abort the entire process by running git am --abort.

The command refuses to process new mailboxes until the current operation is finished.

OPTIONS

--abort
Stop applying patches from the mailbox and reset to the state before git am began.
--skip
Discard the current patch and advance to the next one. This is useful after a failed patch that you don't want to apply.
--continue
Once conflicts are resolved or a failed patch is skipped, use this option to continue applying patches from where they left off.
--quit
Stop applying patches but leave the working directory and index file as they are.
-k, --keep-empty
Do not skip patches that are empty. An empty patch is one that does not change any files.
--fold[=foldcase]
This option is used when applying patches from mail messages. When a patch is applied, the patch is folded into the commit message. For example, if a patch has the subject "[PATCH 0/3] Foo", and this option is used, subsequent patches in the same series like "[PATCH 1/3] Bar" will be folded into the first patch's commit message. The optional foldcase argument determines how the case of the subject line is treated. If foldcase is not specified, or if it is fold, then the case of the subject line is ignored. If foldcase is case, then the case of the subject line is significant. Defaults to fold.
--inline
This option is used when applying patches from mail messages. It is the opposite of --fold. Each patch is applied as a separate commit. This is the default behavior.
--mailname=path
Specify the path to the mail spool file.
--thread[=frompath]
This option is used when applying patches from mail messages. When a patch is applied, its parent commit is determined by searching the commit history for a commit that matches the parent specified in the patch header. If no match is found, the parent is determined by the --thread option. If --thread is given without an argument, the parent is determined by the From: header. If --thread=frompath is given, the parent is determined by the From: header of the message found at frompath.
--3way
When applying a patch, fall back on 3-way merge if the patch does not apply cleanly. This requires that the patch records the identity of blobs it is supposed to apply to, and that we have those blobs available locally.
--show-current-patch[=diff|raw]
Show the message at which git am has stopped due to conflicts. If raw is specified, show the raw contents of the e-mail message; if diff, show the diff portion only. Defaults to raw.
--allow-empty
After a patch failure on an input e-mail message lacking a patch, create an empty commit with the contents of the e-mail message as its log message.

DISCUSSION

The commit author name is taken from the "From: " line of the message, and commit author date is taken from the "Date: " line of the message. The "Subject: " line is used as the title of the commit, after stripping common prefix "[PATCH <anything>]". The "Subject: " line is supposed to concisely describe what the commit is about in one line of text.

"From: ", "Date: ", and "Subject: " lines starting the body override the respective commit author name and title values taken from the headers.

The commit message is formed by the title taken from the "Subject: ", a blank line and the body of the message up to where the patch begins. Excess whitespace at the end of each line is automatically stripped.

The patch is expected to be inline, directly following the message. Any line that is of the form:

•three-dashes and end-of-line, or
•a line that begins with "diff -", or
•a line that begins with "Index: "

is taken as the beginning of a patch, and the commit log message is terminated before the first occurrence of such a line.

When initially invoking git am, you give it the names of the mailboxes to process. Upon seeing the first patch that does not apply, it aborts in the middle. You can recover from this in one of two ways:

1.skip the current patch by re-running the command with the --skip option.
2.hand resolve the conflict in the working directory, and update the index file to bring it into a state that the patch should have produced. Then run the command with the --continue option.

The command refuses to process new mailboxes until the current operation is finished, so if you decide to start over from scratch, run git am --abort before running the command with mailbox names.

Before any patches are applied, ORIG_HEAD is set to the tip of the current branch. This is useful if you have problems with multiple commits, like running git am on the wrong branch or an error in the commits that is more easily fixed by changing the mailbox (e.g. errors in the "From:" lines).

HOOKS

This command can run applypatch-msg, pre-applypatch, and post-applypatch hooks. See githooks(5) for more information.

CONFIGURATION

Everything below this line in this section is selectively included from the git-config(1) documentation. The content is the same as what’s found there:

am.keepcr

If true, git-am will call git-mailsplit for patches in mbox format with parameter --keep-cr. In this case git-mailsplit will not remove \r from lines ending with \r\n. Can be overridden by giving --no-keep-cr from the command line. See git-am(1), git-mailsplit(1).

am.threeWay

By default, git am will fail if the patch does not apply cleanly. When set to true, this setting tells git am to fall back on 3-way merge if the patch records the identity of blobs it is supposed to apply to and we have those blobs available locally (equivalent to giving the --3way option from the command line). Defaults to false. See git-am(1).
