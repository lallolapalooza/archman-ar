git-sh-setup(1)

الحزمة: git

التراخيص: GPL-2.0-only

GIT-SH-SETUP(1) دليل Git GIT-SH-SETUP(1)

الاسم

git-sh-setup — كود إعداد مشترك لسكربتات Git الطرفية

الملخص

. "$(git --exec-path)/git-sh-setup"

الوصف

هذا ليس أمرًا يرغب المستخدم النهائي في تشغيله. أبدًا. تهدف هذه الوثائق إلى الأشخاص الذين يدرسون سكربتات Porcelainish و/أو يكتبون سكربتات جديدة.

تم تصميم سكربت git sh-setup ليتم تضمينه (باستخدام .) بواسطة سكربتات طرفية أخرى لإعداد بعض المتغيرات التي تشير إلى أدلة Git العادية وبعض الدوال المساعدة للطرفية.

قبل تضمينه، يجب على السكربت الخاص بك إعداد بعض المتغيرات؛ USAGE (و LONG_USAGE، إن وجدت) تُستخدم لتعريف الرسالة التي تقدمها دالة الطرفية usage(). يمكن تعيين SUBDIRECTORY_OK إذا كان بإمكان السكربت العمل من دليل فرعي ضمن شجرة العمل (بعض الأوامر لا تفعل ذلك).

يقوم السكربت بتعيين متغيرات الطرفية GIT_DIR و GIT_OBJECT_DIRECTORY، ولكنه لا يقوم بتصديرها إلى البيئة.

الدوال

die

الخروج بعد إصدار رسالة الخطأ المقدمة إلى مجرى الخطأ القياسي.

usage

الخروج مع رسالة الاستخدام.

set_reflog_action

تعيين متغير البيئة GIT_REFLOG_ACTION إلى سلسلة معطاة (عادةً اسم البرنامج) ما لم يتم تعيينه بالفعل. في كل مرة يقوم فيها السكربت بتشغيل أمر git يقوم بتحديث المراجع (refs)، يتم إنشاء إدخال reflog باستخدام قيمة هذه السلسلة لتسجيل الأمر الذي قام بتحديث المرجع.

git_editor

تشغيل محرر من اختيار المستخدم (GIT_EDITOR، core.editor، VISUAL أو EDITOR) على ملف معين، ولكن الخروج بخطأ إذا لم يتم تحديد محرر وكانت الطرفية بسيطة (dumb).

is_bare_repository

إخراج true أو false إلى مجرى الإخراج القياسي للإشارة إلى ما إذا كان المستودع مستودعًا عاريًا (أي بدون شجرة عمل مرتبطة).

cd_to_toplevel

تشغيل أمر chdir للانتقال إلى أعلى شجرة العمل.

require_work_tree

التحقق مما إذا كان الدليل الحالي ضمن شجرة العمل للمستودع، وإلا فإنه يخرج.

require_work_tree_exists

التحقق مما إذا كانت شجرة العمل المرتبطة بالمستودع موجودة، وإلا فإنه يخرج. غالبًا ما يتم ذلك قبل استدعاء cd_to_toplevel، والذي يكون من المستحيل القيام به إذا لم تكن هناك شجرة عمل.

require_clean_work_tree <action> [<hint>]

التحقق من أن شجرة العمل والفهرس المرتبطين بالمستودع لا يحتويان على تغييرات غير ملتزم بها في الملفات المتتبعة. بخلاف ذلك، فإنه يصدر رسالة خطأ على الشكل Cannot <action>: <reason>. <hint>، ويخرج. مثال: 
require_clean_work_tree rebase "Please commit or stash them."

get_author_ident_from_commit

إخراج كود للاستخدام مع eval لتعيين متغيرات GIT_AUTHOR_NAME و GIT_AUTHOR_EMAIL و GIT_AUTHOR_DATE لالتزام معين.

create_virtual_base

تعديل الملف الأول بحيث لا تبقى سوى الأسطر المشتركة مع الملف الثاني. إذا كان هناك مواد مشتركة غير كافية، فيتم ترك الملف الأول فارغًا. تكون النتيجة مناسبة كمدخل أساسي افتراضي لدمج ثلاثي الاتجاهات.
