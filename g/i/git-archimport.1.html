git-archimport(1)

الحزمة: git

التراخيص: GPL-2.0-only

GIT-ARCHIMPORT(1) دليل Git GIT-ARCHIMPORT(1)

الاسم

git-archimport - استيراد مستودع GNU Arch إلى Git

الملخص

git archimport [-h] [-v] [-o] [-a] [-f] [-T] [-D <depth>] [-t <tempdir>]
               <archive>/<branch>[:<git-branch>]...

الوصف

يقوم باستيراد مشروع من مستودع واحد أو أكثر من مستودعات GNU Arch. سيقوم بتتبع الفروع والمستودعات ضمن مساحات الأسماء المحددة بواسطة معلمات <archive>/<branch> المقدمة. إذا لم يتمكن من العثور على الفرع البعيد الذي يأتي منه الدمج، فسيقوم باستيراده كالتزام عادي. إذا تمكن من العثور عليه، فسيتم تمييزه كدمج كلما أمكن ذلك (انظر المناقشة أدناه).

يتوقع النص البرمجي منك تزويد الجذور الرئيسية حيث يمكنه البدء في الاستيراد من التزام Arch من نوع استيراد أولي أو علامة. سيقوم بتتبع واستيراد فروع جديدة ضمن الجذور المقدمة.

يتوقع التعامل مع مشروع واحد فقط. إذا رأى فروعًا لها جذور مختلفة، فسيتم رفض تشغيله. في هذه الحالة، قم بتحرير معلمات <archive>/<branch> لتحديد نطاق الاستيراد بوضوح.

يستخدم git archimport **tla** بشكل مكثف في الخلفية للوصول إلى مستودع Arch. تأكد من توفر إصدار حديث من **tla** في المسار. يجب أن يعرف **tla** المستودعات التي تمررها إلى git archimport.

للاستيراد الأولي، يتوقع git archimport أن يجده في دليل فارغ. لتتبع تطوير مشروع يستخدم Arch، أعد تشغيل git archimport بنفس المعلمات كما في الاستيراد الأولي لأداء عمليات استيراد تزايدية.

بينما سيحاول git archimport إنشاء أسماء فروع منطقية للأرشيفات التي يستوردها، من الممكن أيضًا تحديد أسماء فروع Git يدويًا. للقيام بذلك، اكتب اسم فرع Git بعد كل معلمة <archive>/<branch>، مفصولة بنقطتين رأسيتين. بهذه الطريقة، يمكنك تقصير أسماء فروع Arch وتحويل المصطلحات العامية لـ Arch إلى مصطلحات Git، على سبيل المثال، تعيين فرع "PROJECT--devo--VERSION" إلى "master".

من الممكن ربط فروع Arch متعددة بفرع Git واحد؛ ستكون النتيجة ذات مغزى فقط إذا لم يتم إجراء أي التزامات على الفرع الأول، بعد إنشاء الفرع الثاني. ومع ذلك، هذا مفيد لتحويل مستودعات Arch التي تم تدويرها بشكل دوري.

عمليات الدمج

تُستخدم بيانات دمج التصحيحات من Arch لتمييز عمليات الدمج في Git أيضًا. Git لا يهتم كثيرًا بتتبع التصحيحات، ولا يأخذ في الاعتبار سوى الدمج عندما يدمج الفرع جميع الالتزامات منذ نقطة تفرعها. النتيجة النهائية هي أن Git سيكون لديه فكرة جيدة عن مدى تباعد الفروع. لذا فإن عملية الاستيراد تفقد بعض البيانات الوصفية لتداول التصحيحات.

لحسن الحظ، عند محاولة دمج الفروع المستوردة من Arch، سيجد Git قاعدة دمج جيدة، ولديه فرصة جيدة لتحديد التصحيحات التي تم تداولها بشكل غير متسلسل بين الفروع.

الخيارات

-h

عرض الاستخدام.

-v

إخراج مطول.

-T

العديد من العلامات. سيؤدي إلى إنشاء علامة لكل التزام، تعكس اسم الالتزام في مستودع Arch.

-f

استخدم استراتيجية استيراد مجموعة التصحيحات السريعة. يمكن أن يكون هذا أسرع بكثير للأشجار الكبيرة، ولكنه لا يمكنه التعامل مع إعادة تسمية الدليل أو تغييرات الأذونات. الاستراتيجية الافتراضية بطيئة وآمنة.

-o

استخدم هذا للتوافق مع أسماء الفروع القديمة التي تستخدمها الإصدارات السابقة من git archimport. كانت أسماء الفروع القديمة هي category--branch، بينما أسماء الفروع الجديدة هي archive,category--branch--version. في كلتا الحالتين، تتجاوز الأسماء المعطاة في سطر الأوامر تلك التي تم إنشاؤها تلقائيًا.

-D <depth>

تتبع سلالة الدمج وحاول استيراد الأشجار التي تم دمجها منها. حدد عمقًا أكبر من 1 إذا تم تقليم سجلات التصحيحات.

-a

حاول التسجيل التلقائي للأرشيفات على http://mirrors.sourcecontrol.net هذا مفيد بشكل خاص مع الخيار -D.

-t <tmpdir>

تجاوز دليل tempdir الافتراضي.

<archive>/<branch>

معرف <archive>/<branch> بالتنسيق الذي يفهمه **tla** **log**.
