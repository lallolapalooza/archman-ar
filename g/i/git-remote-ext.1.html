git-remote-ext(1)

الحزمة: git

التراخيص: GPL-2.0-only

GIT-REMOTE-EXT(1) دليل Git GIT-REMOTE-EXT(1)

الاسم

git-remote-ext - جسر النقل الذكي إلى أمر خارجي.

ملخص

git remote add <nick> "ext::<command>[ <arguments>...]"

الوصف

يستخدم مساعد النقل هذا <command> المحدد للاتصال بخادم Git بعيد.

يُفترض أن البيانات المكتوبة إلى الإدخال القياسي للأمر <command> المحدد يتم إرسالها إلى خادم git://، أو git-upload-pack، أو git-receive-pack، أو git-upload-archive (حسب الموقف)، ويُفترض أن البيانات المقروءة من الإخراج القياسي للأمر <command> يتم استلامها من نفس الخدمة.

يتم فصل الأمر والوسائط بمسافة غير مفصولة.

التسلسلات التالية لها معنى خاص:

'% '

مسافة حرفية في الأمر أو الوسيط.

%%

علامة النسبة المئوية الحرفية.

%s

يتم استبدالها باسم (receive-pack، upload-pack، أو upload-archive) للخدمة التي يريد Git استدعاؤها.

%S

يتم استبدالها بالاسم الطويل (git-receive-pack، git-upload-pack، أو git-upload-archive) للخدمة التي يريد Git استدعاؤها.

%G (يجب أن تكون الأحرف الأولى في وسيط)

لن يتم تمرير هذا الوسيط إلى <command>. بدلاً من ذلك، سيؤدي ذلك إلى بدء المساعد عن طريق إرسال طلبات خدمة git:// إلى الجانب البعيد مع تعيين حقل الخدمة إلى قيمة مناسبة وحقل المستودع إلى بقية الوسيط. الافتراضي هو عدم إرسال مثل هذا الطلب.

هذا مفيد إذا كان الجانب البعيد هو خادم git:// يتم الوصول إليه عبر نفق.

%V (يجب أن تكون الأحرف الأولى في وسيط)

لن يتم تمرير هذا الوسيط إلى <command>. بدلاً من ذلك، فإنه يحدد حقل vhost في طلب خدمة git:// (لبقية الوسيط). الافتراضي هو عدم إرسال vhost في مثل هذا الطلب (إذا تم إرساله).

متغيرات البيئة

GIT_TRANSLOOP_DEBUG

إذا تم تعيينه، فإنه يطبع معلومات تصحيح الأخطاء حول عمليات القراءة/الكتابة المختلفة.

متغيرات البيئة التي يتم تمريرها إلى الأمر

GIT_EXT_SERVICE

تم تعيينه إلى الاسم الطويل (git-upload-pack، إلخ...) للخدمة التي يحتاج المساعد إلى استدعائها.

GIT_EXT_SERVICE_NOPREFIX

تم تعيينه إلى الاسم الطويل (upload-pack، إلخ...) للخدمة التي يحتاج المساعد إلى استدعائها.

أمثلة

يتم استخدام مساعد النقل هذا بشفافية بواسطة Git عند استخدام أوامر مثل "git fetch <URL>"، "git clone <URL>"، "git push <URL>" أو "git remote add <nick> <URL>"، حيث يبدأ <URL> بـ ext::. أمثلة:

"ext::ssh -i /home/foo/.ssh/somekey user@host.example %S foo/repo"

مثل host.example:foo/repo، ولكن استخدم /home/foo/.ssh/somekey كمفتاح زوج و user كمستخدم على الجانب البعيد. هذا يتجنب الحاجة إلى تحرير .ssh/config.

"ext::socat -t3600 - ABSTRACT-CONNECT:/git-server %G/somerepo"

يمثل مستودعًا بمسار /somerepo يمكن الوصول إليه عبر بروتوكول git في عنوان مساحة الاسم المجرد /git-server.

"ext::git-server-alias foo %G/repo"

يمثل مستودعًا بمسار /repo يتم الوصول إليه باستخدام برنامج المساعد "git-server-alias foo". لا يتم تمرير مسار المستودع ونوع الطلب إلى سطر الأوامر ولكن كجزء من تدفق البروتوكول، كما هو الحال مع بروتوكول git://.

"ext::git-server-alias foo %G/repo %Vfoo"

يمثل مستودعًا بمسار /repo يتم الوصول إليه باستخدام برنامج المساعد "git-server-alias foo". سيكون اسم المضيف للخادم البعيد الذي تم تمريره في تدفق البروتوكول هو "foo" (هذا يسمح لعدة خوادم Git افتراضية بمشاركة عنوان مستوى الرابط).

"ext::git-server-alias foo %G/repo% with% spaces %Vfoo"

يمثل مستودعًا بمسار /repo with spaces يتم الوصول إليه باستخدام برنامج المساعد "git-server-alias foo". سيكون اسم المضيف للخادم البعيد الذي تم تمريره في تدفق البروتوكول هو "foo" (هذا يسمح لعدة خوادم Git افتراضية بمشاركة عنوان مستوى الرابط).

"ext::git-ssl foo.example /bar"

يمثل مستودعًا يتم الوصول إليه باستخدام برنامج المساعد "git-ssl foo.example /bar". يمكن تحديد نوع الطلب بواسطة المساعد باستخدام متغيرات البيئة (انظر أعلاه).
