git-annex-add(1)

الحزمة: git-annex

git-annex-add(1) دليل الأوامر العامة git-annex-add(1)

الاسم

git-annex-add - يضيف ملفات إلى ملحق git

الملخص

git annex add [مسار ...]

الوصف

يضيف الملفات المحددة إلى الملحق. إذا تم تحديد مجلد، فإنه يعمل على جميع الملفات داخل المجلد ومجلده الفرعي. إذا لم يتم تحديد مسار، فإنه يضيف الملفات من الدليل الحالي وما دونه.

سيتم تجاهل الملفات التي تم تسجيلها بالفعل في git ولم يتم تعديلها، أو التي تم تكوين git لتجاهلها، بصمت.

إذا تم تكوين annex.largefiles (في إعدادات git، gitattributes، أو إعدادات git-annex)، ولم يتطابق مع ملف، فسيتصرف git annex add بنفس طريقة git add ويضيف الملف غير الكبير مباشرة إلى مستودع git، بدلاً من الملحق. (بشكل افتراضي، يُفترض أن الملفات المخفية (dotfiles) ومحتويات المجلدات المخفية (dotdirs) ليست كبيرة، ويتم إضافتها مباشرة إلى git، ولكن يمكن تكوين annex.dotfiles لإلحاق تلك الملفات أيضًا.) راجع صفحة دليل git-annex للحصول على توثيق لهذه الإعدادات وغيرها من الإعدادات.

بشكل افتراضي، يتم إضافة الملفات الكبيرة إلى الملحق في شكل مقفل، مما يمنع المزيد من تعديل محتواها حتى يتم إلغاء قفلها بواسطة git-annex-unlock(1). (هذا ليس هو الحال مع ذلك عند وجود مستودع في نظام ملفات لا يدعم الروابط الرمزية.) يمكن استخدام إعداد git annex.addunlocked (وإعداد git-annex) لتغيير هذا السلوك.

يمكن أيضًا استخدام هذا الأمر لإضافة الروابط الرمزية، سواء كانت روابط رمزية لمحتوى ملحق، أو روابط رمزية أخرى.

أمثلة


# git annex add foo bar
add foo ok
add bar ok
# git commit -m added

خيارات

--no-check-gitignore
أضف الملفات التي تم تجاهلها بواسطة git.
--force-large
عامل جميع الملفات كملفات كبيرة، متجاهلاً إعدادات annex.largefiles و annex.dotfiles، وأضف إلى الملحق.
--force-small
عامل جميع الملفات كملفات صغيرة، متجاهلاً إعدادات annex.largefiles و annex.dotfiles و annex.addsmallfiles، وأضف إلى git.
--backend
يحدد الواجهة الخلفية الرئيسية للقيمة (key-value) التي سيتم استخدامها.
خيارات مطابقة الملفات
يمكن استخدام العديد من خيارات git-annex-matching-options(1) لتحديد الملفات المراد إضافتها.
على سبيل المثال: --largerthan=1GB
--jobs=N -JN
يضيف ملفات متعددة بالتوازي. قد يكون هذا أسرع. على سبيل المثال: -J4
سيؤدي تعيين هذا إلى "cpus" إلى تشغيل مهمة واحدة لكل نواة معالج.
--update -u
مثل git add --update، لا يضيف هذا ملفات جديدة، ولكن سيتم إضافة أي تحديثات للملفات المتعقبة إلى الفهرس.
--dry-run
يخرج ما سيتم فعله لكل ملف، ولكن يتجنب إجراء أي تغييرات.
--json
تمكين إخراج JSON. هذا مخصص للبرامج التي تستخدم git-annex لتحليله. كل سطر من الإخراج هو كائن JSON.
--json-progress
تضمين كائنات التقدم في إخراج JSON.
--json-error-messages
يتم تضمين الرسائل التي كانت ستخرج عادةً إلى الخطأ القياسي في JSON بدلاً من ذلك.
--batch
يتيح وضع الدفعة، حيث يتم قراءة ملف للإضافة في سطر واحد من الإدخال القياسي، وإضافة الملف، وتكرار العملية.
لاحظ أنه إذا تم تخطي ملف (بسبب عدم وجوده، أو تجاهله بواسطة git، أو وجوده بالفعل في git، أو عدم مطابقته لخيارات المطابقة)، فسيتم إخراج سطر فارغ بدلاً من الإخراج العادي الذي يتم إنتاجه عند إضافة ملف.
-z
يجعل مدخلات --batch مفصولة بحروف null بدلاً من الأسطر الجديدة المعتادة.
يمكن أيضًا استخدام git-annex-common-options(1).
