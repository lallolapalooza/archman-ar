git-p4(1)

الحزمة: git

التراخيص: GPL-2.0-only

CONFIGURATION VARIABLES

Submit variables

git-p4.detectRenames

اكتشاف عمليات إعادة التسمية. انظر git-diff(1). يمكن أن يكون هذا صحيحًا، خاطئًا، أو درجة كما هو متوقع بواسطة git diff -M.

git-p4.detectCopies

اكتشاف النسخ. انظر git-diff(1). يمكن أن يكون هذا صحيحًا، خاطئًا، أو درجة كما هو متوقع بواسطة git diff -C.

git-p4.detectCopiesHarder

اكتشاف النسخ بشكل أصعب. انظر git-diff(1). قيمة منطقية.

git-p4.preserveUser

عند الإرسال، إعادة تأليف التغييرات لتعكس مؤلف Git، بغض النظر عمن يقوم بتشغيل git p4 submit.

git-p4.allowMissingP4Users

عندما يكون preserveUser صحيحًا، يموت git p4 عادةً إذا لم يتمكن من العثور على مؤلف في خريطة مستخدمي p4. هذا الإعداد يرسل التغيير بغض النظر.

git-p4.skipSubmitEdit

تستدعي عملية الإرسال المحرر قبل إرسال كل تغيير p4. إذا كان هذا الإعداد صحيحًا، فسيتم تخطي خطوة التحرير.

git-p4.skipSubmitEditCheck

بعد تحرير رسالة تغيير p4، يتأكد git p4 من أن الوصف قد تم تغييره بالفعل من خلال النظر إلى وقت تعديل الملف. يعطل هذا الخيار هذا الاختبار.

git-p4.allowSubmit

بشكل افتراضي، يمكن استخدام أي فرع كمصدر لعملية git p4 submit. يسمح متغير التكوين هذا، إذا تم تعيينه، فقط بالفروع المسماة لاستخدامها كمصادر إرسال. يجب أن تكون أسماء الفروع هي الأسماء المختصرة (بدون "refs/heads/")، ويجب فصلها بفواصل ("،")، دون مسافات.

git-p4.skipUserNameCheck

إذا كان المستخدم الذي يقوم بتشغيل git p4 submit غير موجود في خريطة مستخدمي p4، فإن git p4 يخرج. يمكن استخدام هذا الخيار لفرض الإرسال بغض النظر.

git-p4.attemptRCSCleanup

إذا تم تمكينه، سيحاول git p4 submit تنظيف كلمات مفتاحية RCS ($Header$، إلخ). هذه ستؤدي بخلاف ذلك إلى تعارضات دمج وتمنع الإرسال. يجب اعتبار هذا الخيار تجريبيًا في الوقت الحالي.

git-p4.exportLabels

تصدير علامات Git إلى تسميات p4، كما في --export-labels.

git-p4.labelExportRegexp

سيتم تصدير تسميات p4 التي تطابق هذا التعبير العادي فقط. القيمة الافتراضية هي [a-zA-Z0-9_\-.]+$.

git-p4.conflict

تحديد سلوك الإرسال عند العثور على تعارض مع p4، كما في --conflict. السلوك الافتراضي هو ask.

git-p4.disableRebase

لا تقم بإعادة قاعدة الشجرة مقابل p4/master بعد الإرسال.

git-p4.disableP4Sync

لا تقم بمزامنة p4/master مع Perforce بعد الإرسال. يتضمن git-p4.disableRebase.

IMPLEMENTATION DETAILS

•يتم استيراد مجموعات التغييرات من p4 باستخدام Git fast-import.
•الاستنساخ أو المزامنة لا يتطلب عميل p4؛ يتم جمع محتويات الملفات باستخدام p4 print.
•يتطلب الإرسال عميل p4، والذي لا يكون في نفس موقع مستودع Git. يتم تطبيق الترقيعات، واحدًا تلو الآخر، على عميل p4 هذا وإرسالها من هناك.
•كل تثبيت يتم استيراده بواسطة git p4 يحتوي على سطر في نهاية رسالة السجل يشير إلى موقع مستودع p4 ورقم التغيير. يتم استخدام هذا السطر بواسطة عمليات git p4 sync اللاحقة لمعرفة تغييرات p4 الجديدة.
