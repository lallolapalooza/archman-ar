الحزمة: git

التراخيص: GPL-2.0-only

الملفات الأصلية (الإصدار 1) PACK-*.IDX لها التنسيق التالي:

•؛ يتكون الرأس من 256 عددًا صحيحًا بحجم 4 بايت بترتيب البايت الشبكي. يسجل الإدخال N لهذه الجدول عدد الكائنات في الحزمة المقابلة، أول بايت من اسم الكائن الخاص بها أقل من أو يساوي N. يُطلق على هذا جدول *التوسع من المستوى الأول*.
•؛ يتبع الرأس إدخالات مرتبة بحجم 24 بايت، إدخال واحد لكل كائن في الحزمة. كل إدخال هو: 
عدد صحيح بحجم 4 بايت بترتيب البايت الشبكي، يسجل مكان تخزين الكائن في ملف الحزمة كإزاحة من البداية.
اسم كائن واحد بالحجم المناسب.
•؛ ينتهي الملف بـ ذيل: 
نسخة من مجموع التحقق من ملف الحزمة في نهاية ملف الحزمة المقابل.
مجموع التحقق من الفهرس لجميع ما سبق.

ملف Pack Idx:

        --  +--------------------------------+
fanout      | fanout[0] = 2 (على سبيل المثال)    |-.
table       +--------------------------------+ |
            | fanout[1]                      | |
            +--------------------------------+ |
            | fanout[2]                      | |
            ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ |
            | fanout[255] = total objects    |---.
        --  +--------------------------------+ | |
main        | offset                         | | |
index       | object name 00XXXXXXXXXXXXXXXX | | |
table       +--------------------------------+ | |
            | offset                         | | |
            | object name 00XXXXXXXXXXXXXXXX | | |
            +--------------------------------+<+ |
          .-| offset                         |   |
          | | object name 01XXXXXXXXXXXXXXXX |   |
          | +--------------------------------+   |
          | | offset                         |   |
          | | object name 01XXXXXXXXXXXXXXXX |   |
          | ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~   |
          | | offset                         |   |
          | | object name FFXXXXXXXXXXXXXXXX |   |
        --| +--------------------------------+<--+
trailer   | | packfile checksum              |
          | +--------------------------------+
          | | idxfile checksum               |
          | +--------------------------------+
          .-------.
                  |
Pack file entry: <+
رأس إدخال ملف الحزمة:
   بت امتداد بحجم 1 بايت (MSB)
          النوع (3 بت تالية)
          size0 (4 بت سفلى)
   n-byte sizeN (طالما أن MSB مضبوط، كل 7 بت)
           size0..sizeN تشكل عددًا صحيحًا بحجم 4+7+7+..+7 بت، size0
           هو الجزء الأقل أهمية، و sizeN هو
           الجزء الأكثر أهمية.
بيانات الكائن المضغوط:
   إذا لم يكن DELTA، فبايتات مضغوطة (الحجم أعلاه
           هو حجم ما قبل الضغط).
   إذا كان REF_DELTA، فـ
     اسم الكائن الأساسي (الحجم أعلاه هو
           حجم بيانات الدلتا التي تلي ذلك).
     بيانات الدلتا، مضغوطة.
   إذا كان OFS_DELTA، فـ
     إزاحة n-byte (انظر أدناه) مفسرة كـ
           إزاحة سالبة من بايت النوع لرأس
           إدخال ofs-delta (الحجم أعلاه هو حجم
           بيانات الدلتا التي تلي ذلك).
     بيانات الدلتا، مضغوطة.
ترميز الإزاحة:
     n بايت مع تعيين MSB في جميعها باستثناء الأخير.
     الإزاحة هي بعد ذلك العدد المتكون من
     ربط الـ 7 بت السفلية لكل بايت، و
     لـ n >= 2 إضافة 2^7 + 2^14 + ... + 2^(7*(n-1))
     إلى النتيجة.

الملفات VERSION 2 PACK-*.IDX تدعم الحزم الأكبر من 4 جيجابايت، و

لديها بعض عمليات إعادة التنظيم الأخرى. لديها التنسيق:
•؛ رقم سحري بحجم 4 بايت * \377tOc* وهو قيمة غير معقولة لـ fanout[0].
•؛ رقم إصدار بحجم 4 بايت (= 2)
•؛ جدول توسع مكون من 256 إدخالًا تمامًا مثل v1.
•؛ جدول بأسماء الكائنات مرتبة. يتم تجميع هذه الأسماء معًا بدون قيم إزاحة لتقليل بصمة ذاكرة التخزين المؤقت للبحث الثنائي عن اسم كائن معين.
•؛ جدول بقيم CRC32 بحجم 4 بايت لبيانات الكائنات المضغوطة. هذا جديد في v2 حتى يمكن نسخ البيانات المضغوطة مباشرة من حزمة إلى حزمة أثناء إعادة التعبئة دون تلف غير مكتشف.
•؛ جدول قيم إزاحة بحجم 4 بايت (بترتيب البايت الشبكي). هذه عادةً ما تكون إزاحات ملف حزمة بحجم 31 بت، ولكن يتم ترميز الإزاحات الكبيرة كفهرس للجدول التالي مع تعيين البت ms.
•؛ جدول بإدخالات إزاحة بحجم 8 بايت (فارغ لملفات الحزم الأقل من 2 جيجابايت). يتم تنظيم ملفات الحزم مع الكائنات المستخدمة بكثافة نحو الأمام، لذلك لا تحتاج معظم مراجع الكائنات إلى الإشارة إلى هذا الجدول.
•؛ نفس الذيل لملف حزمة v1: 
نسخة من مجموع التحقق من ملف الحزمة في نهاية
ملف الحزمة المقابل.
مجموع التحقق من الفهرس لجميع ما سبق.

ملفات PACK-*.REV لها التنسيق:

•؛ رقم سحري بحجم 4 بايت * 0x52494458* (*RIDX*).
•؛ معرف إصدار بحجم 4 بايت (= 1).
•؛ معرف دالة تجزئة بحجم 4 بايت (= 1 لـ SHA-1، 2 لـ SHA-256).
•؛ جدول بمواضع الفهرس (واحد لكل كائن مضغوط، إجمالي num_objects، كل منها عدد صحيح غير موقع بحجم 4 بايت بترتيب الشبكة)، مرتبة حسب إزاحاتها المقابلة في ملف الحزمة.
•؛ ذيل، يحتوي على: 
مجموع التحقق من ملف الحزمة المقابل، و
مجموع تحقق لجميع ما سبق.

جميع الأرقام بحجم 4 بايت بترتيب الشبكة.

ملفات PACK-*.MTIMES لها التنسيق:

جميع الأرقام بحجم 4 بايت بترتيب البايت الشبكي.

•؛ رقم سحري بحجم 4 بايت * 0x4d544d45* (*MTME*).
•؛ معرف إصدار بحجم 4 بايت (= 1).
•؛ معرف دالة تجزئة بحجم 4 بايت (= 1 لـ SHA-1، 2 لـ SHA-256).
•؛ جدول بأعداد صحيحة غير موقعة بحجم 4 بايت. القيمة i هي وقت التعديل (mtime) للكائن i في الحزمة المقابلة بترتيب معجمي (فهرس). الـ mtimes تحسب ثواني الحقبة القياسية.
•؛ ذيل، يحتوي على مجموع تحقق لملف الحزمة المقابل، ومجموع تحقق لجميع ما سبق (كل منهما بطول وفقًا لدالة التجزئة المحددة).

ملفات MULTI-PACK-INDEX (MIDX) لها التنسيق التالي:

تشير ملفات multi-pack-index إلى ملفات حزم متعددة والكائنات السائبة.

للسماح بالامتدادات التي تضيف بيانات إضافية إلى MIDX، ننظم الجسم إلى "أجزاء" ونوفر جدول بحث في بداية الجسم. يشمل الرأس قيم طول معينة، مثل عدد الحزم، وعدد ملفات MIDX الأساسية، وأطوال وأنواع التجزئة.

جميع الأرقام بحجم 4 بايت بترتيب الشبكة.

الرأس:

توقيع بحجم 4 بايت:
    التوقيع هو: {'M', 'I', 'D', 'X'}
رقم إصدار بحجم 1 بايت:
    يكتب Git أو يتعرف فقط على الإصدار 1.
إصدار معرف الكائن بحجم 1 بايت
    نستنتج طول معرفات الكائن (OIDs) من هذه القيمة:
        1 => SHA-1
        2 => SHA-256
    إذا لم يتطابق نوع التجزئة مع خوارزمية التجزئة للمستودع،
    يجب تجاهل ملف multi-pack-index مع عرض تحذير
    للمستخدم.
عدد "الأجزاء" بحجم 1 بايت
عدد ملفات MIDX الأساسية بحجم 1 بايت:
    هذه القيمة صفر دائمًا حاليًا.
عدد ملفات الحزم بحجم 4 بايت

بحث الأجزاء:

(C + 1) * 12 بايت توفر إزاحات الأجزاء:
    أول 4 بايت تصف معرف الجزء. القيمة 0 هي علامة نهاية.
    8 بايت أخرى توفر الإزاحة في الملف الحالي لبدء الجزء.
    (يتم توفير الأجزاء بترتيب الملف، لذا يمكنك استنتاج الطول
    باستخدام موضع الجزء التالي إذا لزم الأمر.)
يتطابق بحث الأجزاء مع جدول المحتويات من
تنسيق الملف المستند إلى الأجزاء، انظر linkgit:gitformat-chunk[5].
يتم وصف البيانات المتبقية في الجسم جزءًا واحدًا في كل مرة، و
قد يتم تقديم هذه الأجزاء بأي ترتيب. الأجزاء مطلوبة ما لم
يتم تحديد خلاف ذلك.

بيانات الأجزاء:

أسماء ملفات الحزم (المعرف: {'P', 'N', 'A', 'M'})
    تخزين أسماء ملفات الحزم كسلسلة من السلاسل المنتهية بـ NUL. لا توجد
    حشوة إضافية بين أسماء الملفات،
    وهي مدرجة بترتيب معجمي. الجزء نفسه
    محشو في النهاية بما بين 0 و 3 بايت NUL لجعل
    حجم الجزء مضاعفًا لـ 4 بايت.
ملفات الحزم النقطية (المعرف: {'B', 'T', 'M', 'P'})
    تخزين جدول من عددين صحيحين غير موقعين بحجم 4 بايت بترتيب الشبكة.
    يقابل كل إدخال جدول حزمة واحدة (بالترتيب الذي
    تظهر به أعلاه في جزء `PNAM`). القيم لكل جدول
    إدخال هي كما يلي:
    - موضع البت الأول (بترتيب الحزمة الزائف، انظر أدناه) لـ
      احتواء كائن من تلك الحزمة.
    - عدد البتات التي تم اختيار الكائنات منها من تلك الحزمة.
توسع OID (المعرف: {'O', 'I', 'D', 'F'})
    يسجل الإدخال i، F[i]، عدد OIDs مع البايت
    الأول عند i أو أقل. وبالتالي F[255] يسجل العدد
    الإجمالي للكائنات.
بحث OID (المعرف: {'O', 'I', 'D', 'L'})
    يتم تخزين OIDs لجميع الكائنات في MIDX بترتيب معجمي
    في هذا الجزء.
إزاحات الكائنات (المعرف: {'O', 'O', 'F', 'F'})
    تخزين قيمتين بحجم 4 بايت لكل كائن.
    1: معرف الحزمة الصحيح للحزمة التي تخزن هذا الكائن.
    2: الإزاحة داخل الحزمة.
        إذا كانت جميع الإزاحات أقل من 2^32، فإن جزء الإزاحة الكبير
        لن يكون موجودًا ويتم تخزين الإزاحات كما في IDX v1.
        إذا كان هناك إزاحة واحدة على الأقل أكبر من 2^32-1،
        فيجب أن يكون جزء الإزاحة الكبير موجودًا، ويجب تخزين الإزاحات الأكبر من
        2^31-1 فيه بدلاً من ذلك. إذا كان جزء الإزاحة الكبير موجودًا وكان البت 31 قيد التشغيل، فإن إزالة هذا البت يكشف
        عن الصف في الإزاحات الكبيرة الذي يحتوي على الإزاحة ذات الـ 8 بايت لـ
        هذا الكائن.
[اختياري] إزاحات الكائنات الكبيرة (المعرف: {'L', 'O', 'F', 'F'})
    إزاحات بحجم 8 بايت في ملفات الحزم الكبيرة.
