gist(1)

الحزمة: gist

التراخيص: custom:MIT

GIST(1) دليل Gist GIST(1)

الاسم

gist - تحميل الكود إلى https://gist.github.com

ملخص

توفر جوهرة Ruby (gem) أمر gist الذي يمكنك استخدامه من طرف الأوامر الخاص بك لتحميل المحتوى إلى https://gist.github.com/.

التثبيت

○
إذا كان لديك Ruby مثبتًا:
gem install gist
○
إذا كنت تستخدم Bundler:
source :rubygems gem ´gist´
○
بالنسبة لنظام OS X، يتواجد gist في Homebrew
brew install gist
○
بالنسبة لنظام FreeBSD، يتواجد gist في ports
pkg install gist

الأمر

○
لتحميل محتويات a.rb ببساطة:
gist a.rb
○
تحميل ملفات متعددة:
gist a b c gist *.rb
○
افتراضيًا، يقرأ من STDIN، ويمكنك تعيين اسم ملف باستخدام -f.
gist -f test.rb <a.rb
○
بدلاً من ذلك، يمكنك ببساطة اللصق من الحافظة:
gist -P
○
استخدم -p لجعل الـ gist خاصًا:
gist -p a.rb
○
استخدم -d لإضافة وصف:
gist -d "عشوائي خطأ rbx" a.rb
○
يمكنك تحديث الـ gists الموجودة باستخدام -u:
gist -u GIST_ID FILE_NAME gist -u 42f2c239d2eb57299408 test.txt
○
إذا كنت ترغب في نسخ عنوان URL الناتج إلى الحافظة الخاصة بك، استخدم -c.
gist -c <a.rb
○
إذا كنت ترغب في نسخ عنوان URL القابل للتضمين الناتج إلى الحافظة الخاصة بك، استخدم -e.
gist -e <a.rb
○
ويمكنك ببساطة أن تطلب من gist فتح نافذة متصفح مباشرة باستخدام -o.
gist -o <a.rb
○
لسرد (gists عامة أو جميع gists للمستخدم المصادق عليه) gists للمستخدم
gist -l : جميع gists للمستخدم المصادق عليه gist -l defunkt : سرد gists العامة لـ defunkt

لقراءة gist وطباعته إلى STDOUT

gist -r GIST_ID
gist -r 374130
○
راجع gist --help لمزيد من التفاصيل.

تسجيل الدخول

قبل استخدام gist للمرة الأولى، ستحتاج إلى تسجيل الدخول. هناك تدفقان مدعومان لتسجيل الدخول:

1.
تدفق OAuth الخاص برمز الجهاز من Github. هذا هو الافتراضي للمصادقة مع github.com، ويمكن تمكينه لـ Github Enterprise عن طريق إنشاء تطبيق OAuth، وتصدير متغير البيئة GIST_CLIENT_ID مع معرف العميل لتطبيق OAuth.
2.
تدفق تبادل الرمز (المهجور) لاسم المستخدم وكلمة المرور. هذا هو الافتراضي لـ GitHub Enterprise، ويمكن استخدامه لتسجيل الدخول إلى github.com عن طريق تصدير متغير البيئة GIST_USE_USERNAME_AND_PASSWORD.

تدفق رمز الجهاز

يسمح لك هذا التدفق بالحصول على رمز عن طريق تسجيل الدخول إلى GitHub في المتصفح وكتابة رمز التحقق. هذه هي الآلية المفضلة.

gist --login
Requesting login parameters...
Please sign in at https://github.com/login/device
  and enter code: XXXX-XXXX
Success! https://github.com/settings/connections/applications/4f7ec0d4eab38e74384e

يتم تخزين الـ access_token المُرجع في ~/.gist ويتم استخدامه لجميع عمليات gisting المستقبلية. إذا كنت بحاجة إلى ذلك، يمكنك إلغاء الوصول من https://github.com/settings/connections/applications/4f7ec0d4eab38e74384e.

تدفق اسم المستخدم وكلمة المرور

يطلب هذا التدفق اسم مستخدم وكلمة مرور GitHub الخاصين بك (ورمز المصادقة الثنائية)، ويقوم بتبادلهما مقابل رمز لديه إذن "gist" (لا يتم تخزين اسم المستخدم وكلمة المرور الخاصين بك). تم إهمال هذه الآلية بواسطة GitHub، ولكنها قد لا تزال تعمل مع GitHub Enterprise.

gist --login
Obtaining OAuth2 access_token from GitHub.
GitHub username: ConradIrwin
GitHub password:
2-factor auth code:
Success! https://github.com/settings/tokens

يتم تخزين هذا الرمز في ~/.gist ويتم استخدامه لجميع عمليات gisting المستقبلية. إذا كنت بحاجة إلى ذلك، يمكنك إلغاؤه من https://github.com/settings/tokens، أو ببساطة حذف الملف.

إذا كانت لديك متطلبات مصادقة معقدة، يمكنك إنشاء ملف رمز يدويًا عن طريق لصق رمز GitHub بنطاق gist (وربما نطاق user:email لـ GitHub Enterprise) في ملف يسمى ~/.gist. يمكنك إنشاء واحد من https://github.com/settings/tokens

يجب أن يحتوي هذا الملف فقط على الرمز (حوالي 40 حرفًا سداسي عشري)، ولجعله أسهل في التعديل، يمكن اختياريًا أن يكون له سطر جديد نهائي (\n أو \r\n).

على سبيل المثال، إحدى الطرق لإنشاء هذا الملف هي تشغيل:

(umask 0077 && echo MY_SECRET_TOKEN > ~/.gist)

يضمن umask أن الملف يمكن الوصول إليه فقط من حساب المستخدم الخاص بك.

GitHub Enterprise

إذا كنت ترغب في أن يستخدم gist GitHub Enterprise المثبت محليًا لديك https://enterprise.github.com/، فأنت بحاجة إلى تصدير متغير البيئة GITHUB_URL (يتم ذلك عادةً في ~/.bashrc).

export GITHUB_URL=http://github.internal.example.com/

بمجرد القيام بذلك وإعادة تشغيل الطرفية (أو تشغيل source ~/.bashrc)، سيستخدم gist تلقائيًا GitHub Enterprise بدلاً من github.com العام

سيتم تخزين رمزك لـ GitHub Enterprise في .gist.<protocol>.<server.name>[.<port>] (على سبيل المثال، ~/.gist.http.github.internal.example.com لمثال GITHUB_URL أعلاه) بدلاً من ~/.gist.

إذا كان لديك خوادم متعددة أو تستخدم Enterprise و GitHub العام بشكل متكرر، يمكنك التغلب على ذلك عن طريق إنشاء نصوص برمجية تقوم بتعيين المتغير وتشغيل gist. ضع في اعتبارك أنه لاستخدام GitHub العام، يجب عليك إلغاء تعيين المتغير. مجرد تعيينه إلى عنوان URL العام لن ينجح. استخدم unset GITHUB_URL

تنسيق ملف الرمز

إذا لم تتمكن من استخدام كلمات المرور، كما تفعل معظم تثبيتات Enterprise، يمكنك إنشاء الرمز عبر واجهة الويب ثم ببساطة حفظ السلسلة في الملف الصحيح. تجنب فواصل الأسطر وإلا قد ترى: $ gist -l Error: Bad credentials

يمكنك أيضًا استخدام Gist كمكتبة من داخل كود Ruby الخاص بك:

إذا كنت بحاجة إلى ميزات أكثر تقدمًا، يمكنك أيضًا تمرير:

○
:access_token للمصادقة باستخدام OAuth2 (الافتراضي هو `File.read("~/.gist")).
○
:filename لتغيير تمييز بناء الجملة (الافتراضي هو a.rb).
○
:public إذا كنت تريد أن يكون لـ gist عنوان URL قابل للتخمين.
○
:description لإضافة وصف إلى gist الخاص بك.
○
:update لتحديث gist موجود (يمكن أن يكون عنوان URL أو معرف).
○
:copy لنسخ عنوان URL الناتج إلى الحافظة (الافتراضي هو false).
○
:open لفتح عنوان URL الناتج في متصفح (الافتراضي هو false).

ملاحظة: يجب أن يكون للـ access_token نطاق gist وقد يتطلب أيضًا نطاق user:email.

○
إذا

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.
