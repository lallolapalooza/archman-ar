الحزمة: git-lfs

التراخيص: MIT

GIT-LFS-CLONE(1)   GIT-LFS-CLONE(1)

الاسم

git-lfs-clone - استنساخ مستودع تم تمكينه بواسطة LFS بكفاءة

الملخص

git lfs clone [خيارات استنساخ git] <repository> [<directory>]

الوصف

استنساخ مستودع Git تم تمكينه بواسطة LFS بكفاءة أكبر عن طريق تعطيل LFS أثناء استنساخ git، ثم إجراء 'git lfs pull' مباشرة بعد ذلك.

'git lfs clone' يقوم أيضًا بتثبيت جميع الخطافات على مستوى المستودع (.git/hooks) التي يتطلبها LFS للعمل. إذا تم توفير --separate-git-dir، فسيتم تثبيت الخطافات هناك.

هذا أسرع من 'git clone' العادي لأن هذا الأخير سيقوم بتنزيل محتوى LFS باستخدام فلتر "smudge"، والذي يتم تنفيذه بشكل فردي لكل ملف في مساحة العمل. هذا غير فعال نسبيًا مقارنة بالوضع المجمع والتنزيلات المتوازية التي يقوم بها 'git lfs pull'.

الخيارات

جميع الخيارات التي يدعمها 'git clone'

-I <paths>, --include=<paths>

راجع تضمين واستبعاد.

-X <paths>, --exclude=<paths>

راجع تضمين واستبعاد.

--skip-repo

تجاوز تثبيت الخطافات على مستوى المستودع (.git/hooks) التي يتطلبها LFS. معطل افتراضيًا.

تضمين واستبعاد

يمكنك تكوين Git LFS لجلب الكائنات فقط لتلبية المراجع في مسارات معينة من المستودع، و/أو لاستبعاد مسارات معينة من المستودع، لتقليل الوقت الذي تقضيه في تنزيل أشياء لا تستخدمها.

في تكوين Git الخاص بك أو في ملف .lfsconfig، يمكنك تعيين إما lfs.fetchinclude أو lfs.fetchexclude أو كليهما إلى قوائم مسارات مفصولة بفواصل. إذا تم تعريف lfs.fetchinclude، فسيتم جلب كائنات Git LFS فقط إذا تطابق مسارها مع أحد المسارات في تلك القائمة، وإذا تم تعريف lfs.fetchexclude، فسيتم جلب كائنات Git LFS فقط إذا لم يتطابق مسارها مع أحد المسارات في تلك القائمة. تتم مطابقة المسارات باستخدام المطابقة الواسعة كما هو الحال في gitignore(5).

لاحظ أن استخدام خيارات سطر الأوامر -I و -X يتجاوز إعدادات التكوين المقابلة. يؤدي تعيين أي من الخيارين إلى سلسلة فارغة إلى مسح القيمة.

راجع أيضًا

git-clone(1)، git-lfs-pull(1)، gitignore(5).

جزء من مجموعة git-lfs(1).
