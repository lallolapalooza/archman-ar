git-rebase(1)

الحزمة: git

التراخيص: GPL-2.0-only

CONFIGURATION

In addition to the command line options, git rebase also respects the following configuration variables:

rebase.backend

الواجهة الخلفية الافتراضية المستخدمة لإعادة القاعدة. الخيارات الممكنة هي apply أو merge. في المستقبل، إذا اكتسبت الواجهة الخلفية للدمج جميع الإمكانيات المتبقية للواجهة الخلفية للتطبيق، فقد تصبح هذه الإعدادات غير مستخدمة.

rebase.stat

ما إذا كان سيتم عرض إحصائيات الفرق لما تغير في المنبع منذ آخر إعادة قاعدة. افتراضياً False.

rebase.autoSquash

إذا تم تعيينها على true، فقم بتمكين خيار --autosquash الخاص بـ git-rebase(1) افتراضيًا للوضع التفاعلي. يمكن تجاوز ذلك باستخدام الخيار --no-autosquash.

rebase.autoStash

عند تعيينها على true، قم بإنشاء إدخال تخزين مؤقت مؤقت تلقائيًا قبل بدء العملية، وقم بتطبيقه بعد انتهاء العملية. هذا يعني أنه يمكنك تشغيل إعادة القاعدة على مساحة عمل متسخة. ومع ذلك، استخدم بحذر: قد يؤدي تطبيق التخزين المؤقت النهائي بعد إعادة قاعدة ناجحة إلى تعارضات غير تافهة. يمكن تجاوز هذا الخيار باستخدام الخيارات --no-autostash و --autostash الخاصة بـ git-rebase(1). الافتراضي هو false.

rebase.updateRefs

إذا تم تعيينها على true، فقم بتمكين خيار --update-refs افتراضيًا.

rebase.missingCommitsCheck

إذا تم تعيينها على "warn"، فسيقوم git rebase -i بطباعة تحذير إذا تمت إزالة بعض الالتزامات (على سبيل المثال، تم حذف سطر)، ومع ذلك ستستمر إعادة القاعدة. إذا تم تعيينها على "error"، فستقوم بطباعة التحذير السابق وإيقاف إعادة القاعدة، ويمكن بعد ذلك استخدام git rebase --edit-todo لتصحيح الخطأ. إذا تم تعيينها على "ignore"، فلن يتم إجراء أي فحص. لإسقاط التزام دون تحذير أو خطأ، استخدم الأمر drop في قائمة المهام. الافتراضي هو "ignore".

rebase.instructionFormat

سلسلة تنسيق، كما هو محدد في git-log(1)، لاستخدامها في قائمة المهام أثناء إعادة القاعدة التفاعلية. سيتم تلقائيًا إضافة تجزئة الالتزام إلى بداية التنسيق.

rebase.abbreviateCommands

إذا تم تعيينها على true، فستستخدم git rebase أسماء أوامر مختصرة في قائمة المهام، مما ينتج عنه شيء مثل هذا: 
        p deadbee The oneline of the commit
        p fa1afe1 The oneline of the next commit
        ...

بدلاً من:

        pick deadbee The oneline of the commit
        pick fa1afe1 The oneline of the next commit
        ...

الافتراضي هو false.

rebase.rescheduleFailedExec

إعادة جدولة أوامر exec التي فشلت تلقائيًا. هذا له معنى فقط في الوضع التفاعلي (أو عند توفير خيار --exec). هذا هو نفس تحديد الخيار --reschedule-failed-exec.

rebase.forkPoint

إذا تم تعيينها على false، فقم بتعيين الخيار --no-fork-point افتراضيًا.

rebase.rebaseMerges

كيفية وما إذا كان سيتم تعيين الخيار --rebase-merges افتراضيًا. يمكن أن يكون rebase-cousins، أو no-rebase-cousins، أو قيمة منطقية. التعيين على true أو no-rebase-cousins يعادل --rebase-merges=no-rebase-cousins، والتعيين على rebase-cousins يعادل --rebase-merges=rebase-cousins، والتعيين على false يعادل --no-rebase-merges. تمرير --rebase-merges على سطر الأوامر، سواء مع وسيطة أو بدونها، يتجاوز أي تكوين rebase.rebaseMerges.

rebase.maxLabelLength

عند إنشاء أسماء تسميات من مواضيع الالتزام، قم باقتطاع الأسماء إلى هذا الطول. افتراضيًا، يتم اقتطاع الأسماء إلى أقل بقليل من NAME_MAX (للسماح، على سبيل المثال، بكتابة ملفات .lock للمراجع الفضفاضة المقابلة.

sequence.editor

محرر النصوص الذي تستخدمه git rebase -i لتحرير ملف تعليمات إعادة القاعدة. القيمة مخصصة للتفسير بواسطة shell عند استخدامها. يمكن تجاوزها بواسطة متغير البيئة GIT_SEQUENCE_EDITOR. عند عدم تكوينه، يتم استخدام محرر رسائل الالتزام الافتراضي بدلاً من ذلك.
