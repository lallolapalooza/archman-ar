gitformat-bundle(5)

الحزمة: git

التراخيص: GPL-2.0-only

GITFORMAT-BUNDLE(5) دليل Git GITFORMAT-BUNDLE(5)

الاسم

gitformat-bundle - تنسيق ملف الحزمة

الملخص

*.bundle
*.bdl

الوصف

تنسيق حزمة Git هو تنسيق يمثل كل من الإشارات (refs) وكائنات Git. الحزمة هي رأس بتنسيق مشابه لـ git-show-ref(1) متبوعًا بحزمة بتنسيق *.pack.

يتم إنشاء التنسيق وقراءته بواسطة الأمر git-bundle(1)، ويتم دعمه بواسطة، على سبيل المثال، git-fetch(1) و git-clone(1).

التنسيق

سنستخدم تدوين ABNF لتعريف تنسيق حزمة Git. راجع gitprotocol-common(5) للحصول على التفاصيل.

الحزمة من الإصدار 2 (v2) تبدو هكذا:

bundle    = signature *prerequisite *reference LF pack
signature = "# v2 git bundle" LF
prerequisite = "-" obj-id SP comment LF
comment      = *CHAR
reference    = obj-id SP refname LF
pack         = ... ; packfile

الحزمة من الإصدار 3 (v3) تبدو هكذا:

bundle    = signature *capability *prerequisite *reference LF pack
signature = "# v3 git bundle" LF
capability   = "@" key ["=" value] LF
prerequisite = "-" obj-id SP comment LF
comment      = *CHAR
reference    = obj-id SP refname LF
key          = 1*(ALPHA / DIGIT / "-")
value        = *(%01-09 / %0b-FF)
pack         = ... ; packfile

الدلالات

تتكون حزمة Git من عدة أجزاء.

•"الإمكانيات" (Capabilities)، وهي موجودة فقط في تنسيق v3، تشير إلى الوظائف التي تتطلبها الحزمة للقراءة بشكل صحيح.
•"المتطلبات المسبقة" (Prerequisites) تسرد الكائنات التي **لا** يتم تضمينها في الحزمة ويجب على قارئ الحزمة امتلاكها بالفعل، من أجل استخدام البيانات في الحزمة. الكائنات المخزنة في الحزمة قد تشير إلى كائنات متطلبات مسبقة وأي شيء يمكن الوصول إليه منها (على سبيل المثال، كائن شجرة في الحزمة يمكن أن يشير إلى كائن ملف (blob) يمكن الوصول إليه من متطلب مسبق) و/أو يتم التعبير عنه كفرق (delta) مقابل كائنات المتطلبات المسبقة.
•"الإشارات" (References) تسجل رؤوس الرسم البياني للتاريخ، أي، ما يمكن للقارئ "git fetch" منه.
•"الحزمة" (Pack) هي تدفق بيانات الحزمة الذي سيرسله "git fetch"، إذا قمت بعمل fetch من مستودع يحتوي على الإشارات المسجلة في "الإشارات" أعلاه إلى مستودع يحتوي على إشارات تشير إلى الكائنات المدرجة في "المتطلبات المسبقة" أعلاه.

في تنسيق الحزمة، يمكن أن يكون هناك تعليق يتبع معرف الكائن (obj-id) للمتطلب المسبق. هذا تعليق ولا معنى له محدد. يمكن لكاتب الحزمة وضع أي سلسلة هنا. يجب على قارئ الحزمة تجاهل التعليق.

ملاحظة حول الاستنساخ السطحي (shallow clones) وحزم Git

لاحظ أن المتطلبات المسبقة لا تمثل حدود الاستنساخ السطحي. دلالات المتطلبات المسبقة وحدود الاستنساخ السطحي مختلفة، وتنسيق حزمة Git v2 لا يمكنه تمثيل مستودع استنساخ سطحي.

الإمكانيات

نظرًا لعدم وجود فرصة للتفاوض، فإن الإمكانيات غير المعروفة تتسبب في إنهاء git bundle.

•object-format يحدد خوارزمية التجزئة (hash algorithm) المستخدمة، ويمكن أن تأخذ نفس قيم قيمة التكوين extensions.objectFormat.
•filter يحدد مرشح كائن (object filter) كما في الخيار --filter في git-rev-list(1). يجب تمييز ملف الحزمة الناتج كملف حزمة .promisor بعد فك حزمته.
