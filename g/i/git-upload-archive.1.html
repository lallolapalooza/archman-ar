git-upload-archive(1)

الحزمة: git

التراخيص: GPL-2.0-only

GIT-UPLOAD-ARCHIVE(1) دليل Git GIT-UPLOAD-ARCHIVE(1)

الاسم

git-upload-archive - إرسال أرشيف إلى git-archive

الملخص

git upload-archive <repository>

الوصف

يتم استدعاؤه بواسطة git archive --remote ويرسل أرشيفًا تم إنشاؤه إلى الطرف الآخر عبر بروتوكول Git.

عادةً لا يتم استدعاء هذا الأمر مباشرةً بواسطة المستخدم النهائي. الواجهة لهذا البروتوكول موجودة على جانب git archive، والمقصود من زوج البرامج استخدامه للحصول على أرشيف من مستودع بعيد.

الأمان

لحماية خصوصية الكائنات التي تمت إزالتها من السجل ولكن لم يتم تقليمها بعد، يتجنب git-upload-archive خدمة الأرشيفات للالتزامات والأشجار التي لا يمكن الوصول إليها من مراجع المستودع. ومع ذلك، نظرًا لأن حساب قابلية وصول الكائنات مكلف من الناحية الحسابية، يقوم git-upload-archive بتطبيق مجموعة قواعد أكثر صرامة ولكنها أسهل في التحقق:

1.يمكن للعملاء طلب التزام أو شجرة يشير إليها مرجع مباشرة. على سبيل المثال، git archive --remote=origin v1.0.
2.يمكن للعملاء طلب شجرة فرعية داخل التزام أو شجرة باستخدام بناء الجملة ref:path. على سبيل المثال، git archive --remote=origin v1.0:Documentation.
3.لا يمكن للعملاء استخدام تعبيرات sha1 أخرى، حتى لو كانت النتيجة النهائية قابلة للوصول. على سبيل المثال، لا يُسمح بالتزام نسبي مثل master^ ولا sha1 حرفي مثل abcd1234، حتى لو كانت النتيجة قابلة للوصول من المراجع.

لاحظ أن القاعدة 3 تحظر العديد من الحالات التي لا تثير أي آثار على الخصوصية. تخضع هذه القواعد للتغيير في الإصدارات المستقبلية من git، وقد يتبع الخادم الذي يصل إليه git archive --remote هذه القواعد بالضبط أو لا.

إذا كان خيار التكوين uploadArchive.allowUnreachable هو true، يتم تجاهل هذه القواعد، ويمكن للعملاء استخدام تعبيرات sha1 عشوائية. هذا مفيد إذا كنت لا تهتم بخصوصية الكائنات التي لا يمكن الوصول إليها، أو إذا كانت قاعدة بيانات الكائنات الخاصة بك متاحة بالفعل للوصول عبر http غير ذكي.
