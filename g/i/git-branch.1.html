git-branch(1)

الحزمة: git

التراخيص: GPL-2.0-only

مفاتيح العمل المدعومة هي نفسها تلك الموجودة في git-for-each-ref(1). ترتيب الفرز افتراضيًا هو القيمة المضبوطة لـ المتغير branch.sort إذا كان موجودًا، أو الفرز بناءً على اسم المرجع الكامل (بما في ذلك البادئة refs/...). يسرد هذا HEAD المنفصل (إذا كان موجودًا) أولاً، ثم الفروع المحلية وأخيرًا الفروع المتتبعة عن بعد. انظر git-config(1).

-r, --remotes

سرد أو حذف (إذا استخدم مع -d) الفروع المتتبعة عن بعد. امزجه مع --list لمطابقة الأنماط الاختيارية.

-a, --all

سرد كل من الفروع المتتبعة عن بعد والفروع المحلية. امزجه مع --list لمطابقة الأنماط الاختيارية.

-l, --list

سرد الفروع. مع <pattern>... الاختيارية، على سبيل المثال git branch --list 'maint-*'، قم بسرد الفروع التي تطابق الأنماط فقط.

--show-current

اطبع اسم الفرع الحالي. في حالة HEAD المنفصل، لا يتم طباعة شيء.

-v, -vv, --verbose

عندما تكون في وضع القائمة، اعرض sha1 وسطر موضوع الالتزام لكل رأس، جنبًا إلى جنب مع العلاقة مع الفرع الأعلى (إن وجد). إذا تم تقديمه مرتين، فقم بطباعة مسار شجرة العمل المرتبطة (إن وجدت) واسم الفرع الأعلى أيضًا (انظر أيضًا git remote show <remote>). لاحظ أن HEAD لشجرة العمل الحالية لن يتم طباعة مسارها (ستكون دائمًا دليلك الحالي).

-q, --quiet

كن أكثر هدوءًا عند إنشاء أو حذف فرع، مع قمع الرسائل غير الخطأ.

--abbrev=<n>

في القائمة المفصلة التي تعرض اسم كائن الالتزام، اعرض أقصر بادئة بطول <n> ستة عشرية على الأقل والتي تشير بشكل فريد إلى الكائن. القيمة الافتراضية هي 7 ويمكن تجاوزها بواسطة خيار التكوين core.abbrev.

--no-abbrev

اعرض sha1 الكامل في قائمة الإخراج بدلاً من اختصارها.

-t, --track[=(direct|inherit)]

عند إنشاء فرع جديد، قم بضبط إدخالات التكوين branch.<name>.remote و branch.<name>.merge لتعيين تكوين تتبع "المنبع" للفرع الجديد. سيخبر هذا التكوين git بعرض العلاقة بين الفرعين في git status و git branch -v. علاوة على ذلك، يوجه git pull بدون وسيطات لسحب من المنبع عند سحب الفرع الجديد.

يتم اختيار فرع المنبع الدقيق اعتمادًا على الوسيط الاختياري: -t، --track، أو --track=direct يعني استخدام فرع نقطة البداية نفسه كمنبع؛ --track=inherit يعني نسخ تكوين المنبع لفرع نقطة البداية.

يقوم متغير التكوين branch.autoSetupMerge بتحديد كيفية سلوك git switch، git checkout و git branch عندما لا يتم تحديد --track أو --no-track:

الخيار الافتراضي، true، يتصرف كما لو تم إعطاء --track=direct عندما تكون نقطة البداية فرعًا متتبعًا عن بعد. false يتصرف كما لو تم إعطاء --no-track. always يتصرف كما لو تم إعطاء --track=direct. inherit يتصرف كما لو تم إعطاء --track=inherit. simple يتصرف كما لو تم إعطاء --track=direct فقط عندما تكون <start-point> فرعًا متتبعًا عن بعد ويكون اسم الفرع الجديد هو نفس اسم الفرع البعيد.

راجع git-pull(1) و git-config(1) لمزيد من المناقشة حول كيفية استخدام خيارات branch.<name>.remote و branch.<name>.merge.

--no-track

لا تقم بضبط تكوين "المنبع"، حتى لو تم تعيين متغير التكوين branch.autoSetupMerge.

--recurse-submodules

هذا الخيار تجريبي! يتسبب في تكرار الأمر الحالي في الوحدات الفرعية إذا تم تمكين submodule.propagateBranches. انظر submodule.propagateBranches في git-config(1). حاليًا، يتم دعم إنشاء الفروع فقط.

عند استخدامه في إنشاء الفروع، سيتم إنشاء فرع جديد <branch-name> في المشروع الرئيسي وجميع الوحدات الفرعية في <start-point> للمشروع الرئيسي. في الوحدات الفرعية، سيشير الفرع إلى التزام الوحدة الفرعية في <start-point> للمشروع الرئيسي ولكن سيتم إعداد معلومات التتبع الخاصة بالفرع بناءً على فروع ووحدات الوحدة الفرعية e.g. git branch --recurse-submodules topic origin/main سيقوم بإنشاء فرع الوحدة الفرعية "topic" الذي يشير إلى التزام الوحدة الفرعية في "origin/main" للمشروع الرئيسي، ولكنه يتتبع "origin/main" للوحدة الفرعية.

--set-upstream

نظرًا لأن هذا الخيار كان له بناء جملة مربك، فهو لم يعد مدعومًا. يرجى استخدام --track أو --set-upstream-to بدلاً من ذلك.

-u <upstream>, --set-upstream-to=<upstream>

قم بإعداد معلومات تتبع <branch-name> بحيث يعتبر <upstream> فرع المنبع الخاص بـ <branch-name>. إذا لم يتم تحديد <branch-name>، فسيتم افتراض الفرع الحالي.

--unset-upstream

قم بإزالة معلومات المنبع الخاصة بـ <branch-name>. إذا لم يتم تحديد فرع، فسيتم افتراض الفرع الحالي.

--edit-description

افتح محررًا وقم بتحرير النص لشرح الغرض من الفرع، لاستخدامه بواسطة العديد من الأوامر الأخرى (مثل format-patch، request-pull، و merge (إذا تم تمكينه)). يمكن استخدام شروحات متعددة الأسطر.

--contains [<commit>]

قم بسرد الفروع التي تحتوي على <commit> فقط (HEAD إذا لم يتم تحديده). يعني ضمنيًا --list.

--no-contains [<commit>]

قم بسرد الفروع التي لا تحتوي على <commit> فقط (HEAD إذا لم يتم تحديده). يعني ضمنيًا --list.

--merged [<commit>]

قم بسرد الفروع التي يمكن الوصول إلى قممها من <commit> فقط (HEAD إذا لم يتم تحديده). يعني ضمنيًا --list.

--no-merged [<commit>]

قم بسرد الفروع التي لا يمكن الوصول إلى قممها من <commit> فقط (HEAD إذا لم يتم تحديده). يعني ضمنيًا --list.

--points-at <object>

قم بسرد فروع <object> فقط.

--format <format>

سلسلة تقوم بتضمين %(fieldname) من مرجع فرع يتم عرضه والكائن الذي يشير إليه. <format> هو نفس ما هو موجود في git-for-each-ref(1).

<branch-name>

اسم الفرع المراد إنشاؤه أو حذفه. يجب أن ينجح اسم الفرع الجديد في جميع الفحوصات التي تحددها git-check-ref-format(1). قد تقيد بعض هذه الفحوصات الأحرف المسموح بها في اسم الفرع.

<start-point>

سيشير رأس الفرع الجديد إلى هذا الالتزام. يمكن تقديمه كاسم فرع، أو معرف التزام، أو علامة. إذا تم حذف هذا الخيار، فسيتم استخدام HEAD الحالي بدلاً من ذلك.

<old-branch>

اسم فرع موجود. إذا تم حذف هذا الخيار، فسيتم استخدام اسم الفرع الحالي بدلاً من ذلك.

<new-branch>

الاسم الجديد لفرع موجود. تنطبق نفس القيود على <branch-name>.

التكوين

pager.branch يتم احترامه فقط عند سرد الفروع، أي عند استخدام --list أو ضمنيًا. الافتراضي هو استخدام باجر. انظر git-config(1).

كل ما هو فوق هذا السطر في هذا القسم غير مدرج من توثيق git-config(1). المحتوى الذي يلي هو نفس ما هو موجود هناك:

branch.autoSetupMerge

يخبر git branch، git switch و git checkout بضبط الفروع الجديدة بحيث يقوم git-pull(1) بدمجها بشكل مناسب من فرع نقطة البداية. لاحظ أنه حتى لو لم يتم تعيين هذا الخيار، يمكن اختيار هذا السلوك لكل فرع باستخدام الخيارين --track و --no-track. هذا الخيار افتراضيًا هو true. الإعدادات الصحيحة هي:

false

لا يتم إجراء أي إعداد تلقائي.

true

يتم إجراء الإعداد التلقائي عندما تكون نقطة البداية فرعًا متتبعًا عن بعد.

always

يتم إجراء الإعداد التلقائي عندما تكون نقطة البداية فرعًا محليًا أو فرعًا متتبعًا عن بعد.

inherit

إذا كان لنقطة البداية تكوين تتبع، فسيتم نسخه إلى الفرع الجديد.

simple

يتم إجراء الإعداد التلقائي فقط عندما تكون نقطة البداية فرعًا متتبعًا عن بعد ويكون اسم الفرع الجديد هو نفس اسم الفرع البعيد.

branch.autoSetupRebase

عند إنشاء فرع جديد باستخدام git branch، git switch أو git checkout الذي يتتبع فرعًا آخر، يخبر هذا المتغير Git بضبط السحب لإعادة التأسيس بدلاً من الدمج (انظر branch.<name>.rebase). الإعدادات الصحيحة هي:

never

لا يتم تعيين rebase تلقائيًا إلى true أبدًا.

local

يتم تعيين rebase إلى true للفروع المتتبعة للفروع المحلية الأخرى.

remote

يتم تعيين rebase إلى true للفروع المتتبعة للفروع المتتبعة عن بعد.

always

سيتم تعيين rebase إلى true لجميع الفروع المتتبعة.

انظر branch.autoSetupMerge للحصول على تفاصيل حول كيفية إعداد فرع لتتبع فرع آخر. هذا الخيار افتراضيًا هو never.
