الحزمة: git

التراخيص: GPL-2.0-only

GIT-REQUEST-PULL(1) Git Manual GIT-REQUEST-PULL(1)

الاسم

git-request-pull - يولد ملخصًا للتغييرات المعلقة

الملخص

git request-pull [-p] <start> <URL> [<end>]

الوصف

ينشئ طلبًا يطلب من مشروعك الخارجي سحب التغييرات إلى شجرتهم. يبدأ الطلب، المطبوع على المخرج القياسي، بوصف الفرع، ويلخص التغييرات، ويشير إلى مكان سحبها.

من المتوقع أن يمتلك المشروع الخارجي الالتزام المسمى بواسطة <start> ويطلب المخرج منه دمج التغييرات التي أجريتها منذ ذلك الالتزام، حتى الالتزام المسمى بواسطة <end>، عن طريق زيارة المستودع المسمى بواسطة <URL>.

الخيارات

-p

تضمين نص الرقعة في المخرج.

<start>

نقطة البداية للالتزام. هذا يسمي التزامًا موجودًا بالفعل في سجل المشروع الخارجي.

<URL>

عنوان URL للمستودع المراد السحب منه.

<end>

نقطة النهاية للالتزام (الافتراضي هو HEAD). هذا يسمي الالتزام في قمة السجل الذي تطلب سحبه.

عندما يمتلك المستودع المسمى بواسطة <URL> الالتزام في قمة مرجع مختلف عن المرجع المحلي لديك، يمكنك استخدام الصيغة <local>:<remote>، للحصول على اسمه المحلي، ثم نقطتين :، ثم اسمه البعيد.

أمثلة

تخيل أنك بنيت عملك على فرع master الخاص بك فوق إصدار v1.0، وتريد دمجه في المشروع. أولاً، تقوم بدفع هذا التغيير إلى مستودعك العام ليراه الآخرون:

git push https://git.ko.xz/project master

ثم، تقوم بتشغيل هذا الأمر:

git request-pull v1.0 https://git.ko.xz/project master

والذي سينتج عنه طلب إلى المشروع الخارجي، يلخص التغييرات بين إصدار v1.0 وفرع master الخاص بك، لسحبه من مستودعك العام.

إذا قمت بدفع تغييرك إلى فرع اسمه مختلف عن الفرع المحلي لديك، على سبيل المثال:

git push https://git.ko.xz/project master:for-linus

فيمكنك طلب سحبه باستخدام:

git request-pull v1.0 https://git.ko.xz/project master:for-linus
