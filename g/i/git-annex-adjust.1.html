الاسم

git-annex-adjust - الدخول إلى فرع معدل

الملخص

git annex adjust --unlock|--lock|--fix|--hide-missing [--unlock|--lock|--fix]|--unlock-present

الوصف

تدخل إلى شكل معدل من الفرع الحالي. سيتم التعامل مع الملفات الملحقة بشكل مختلف. على سبيل المثال، مع --unlock سيتم إلغاء قفل جميع الملفات الملحقة.

سيكون للفرع المعدل اسم مثل "adjusted/master(unlocked)". نظرًا لأنه فرع git عادي، يمكنك استخدام git checkout للعودة إلى الفرع الأصلي في أي وقت.

يسمح هذا بتغيير كيفية التعامل مع الملفات الملحقة، دون إجراء تغييرات على فرع عام بأوامر مثل git-annex unlock.

أثناء تواجدك في الفرع المعدل، يمكنك استخدام أوامر git-annex و git كالمعتاد. سيتم في البداية إجراء أي عمليات تثبيت تقوم بها على الفرع المعدل فقط.

لنشر الالتزامات من الفرع المعدل إلى الفرع الأصلي، وإلى المستودعات الأخرى، وكذلك لدمج التغييرات من المستودعات الأخرى، قم بتشغيل git annex sync. سيؤدي هذا إلى نشر التغييرات التي أجريتها مثل إضافة/حذف الملفات، ولكن لن يقوم بنشر التعديلات التي تم إجراؤها بواسطة هذا الأمر.

عند التواجد في فرع معدل، فإن استخدام git merge otherbranch ليس مثاليًا في كثير من الأحيان، لأن دمج فرع غير معدل قد يؤدي إلى تعارضات دمج غير ضرورية، أو إضافة ملفات بشكل غير معدل. ولا يمكن نشر مثل هذه عمليات الدمج من الفرع المعدل إلى الفرع الأصلي. لتجنب تلك المشاكل، استخدم git annex merge otherbranch.

إعادة تشغيل هذا الأمر بنفس الخيارات أثناء التواجد داخل الفرع المعدل سيقوم بتحديث الفرع المعدل حسب الضرورة (على سبيل المثال لـ --hide-missing و --unlock-present)، وسيؤدي أيضًا إلى نشر الالتزامات مرة أخرى إلى الفرع الأصلي.

الخيارات

--unlock
إلغاء قفل جميع الملفات الملحقة في الفرع المعدل. هذا يسمح بتعديل الملفات الملحقة.
عادةً، يتطلب إلغاء قفل ملف إنشاء نسخة من محتواه، بحيث يتم الاحتفاظ بالمحتوى الأصلي، بينما يمكن تعديل النسخة. لاستخدام مساحة أقل، يمكن تعيين annex.thin إلى true قبل تشغيل هذا الأمر؛ هذا يؤدي إلى إنشاء رابط صلب للمحتوى بدلاً من نسخة. (عندما يدعم نظام الملفات ذلك.) في حين أن هذا يمكن أن يوفر مساحة قرص كبيرة، فإن أي تعديل يتم إجراؤه على ملف سيؤدي إلى فقدان الإصدار القديم من الملف من المستودع المحلي. لذا، قم بتمكين annex.thin بحذر.
عند التواجد في فرع غير مقفل معدل، سيقوم git annex add بإضافة الملفات غير المقفلة بدلاً من السلوك الافتراضي لإضافتها مقفلة.
--lock
قفل جميع الملفات الملحقة في الفرع المعدل. قد يفضل هذا أولئك الذين يحبون رؤية روابط رمزية معطلة عندما لا يكون محتوى ملف ملحق موجودًا.
عند التواجد في فرع مقفل معدل، سيقوم git annex add بإضافة الملفات مقفلة، كما هو معتاد. ومع ذلك، لا يزال git add (و git commit -a وما إلى ذلك) يضيف الملفات غير المقفلة. هذا لأنه ليس من الممكن لتلك أوامر git إضافة الملفات مقفلة.
--fix
إصلاح الروابط الرمزية للملفات الملحقة لتشير إلى دليل كائن git annex المحلي. يمكن أن يكون هذا مفيدًا إذا تم سحب مستودع بطريقة غير عادية تمنع الروابط الرمزية المثبتة في git من الإشارة إلى كائنات annex.
--hide-missing
تضمين الملفات الملحقة فقط في الفرع المعدل عندما يكون محتواها موجودًا.
لا يتغير الفرع المعدل على الفور عندما تتغير إتاحة المحتوى، لذلك إذا قمت بـ git annex drop للملفات، فستصبح روابط معطلة بالطريقة المعتادة. وعندما يتم نسخ الملفات المفقودة إلى المستودع من مكان آخر، فلن تصبح مرئية على الفور في الفرع.
لتحديث الفرع المعدل ليعكس التغييرات في إتاحة المحتوى، قم بتشغيل git annex adjust --hide-missing مرة أخرى. أو، لأتمتة التحديثات، قم بتعيين إعداد annex.adjustedbranchrefresh.
على الرغم من إخفاء الملفات المفقودة، سيظل git annex sync --content يعمل عليها، ويمكن استخدامه لتنزيل الملفات المفقودة من المستودعات البعيدة. كما أنه يحدث الفرع المعدل بعد نقل المحتوى.
يمكن دمج هذا الخيار مع --unlock، --lock، أو --fix.
--unlock-present
إلغاء قفل الملفات التي يكون محتواها موجودًا، وقفل الملفات التي يكون محتواها مفقودًا. هذا يوفر فوائد العمل مع الملفات غير المقفلة، ولكنه يجعل من السهل رؤية متى يكون محتوى الملف غير مفقود، حيث سيكون رابطًا رمزيًا معطلاً.
لا يتغير الفرع المعدل على الفور عندما تتغير إتاحة المحتوى، لذلك عندما تقوم بـ git annex get للملفات، فستظل مقفلة. وعندما تقوم بـ git annex drop للملفات، فستظل مقفلة ولن تكون روابط رمزية معطلة.
لتحديث الفرع المعدل ليعكس التغييرات في إتاحة المحتوى، قم بتشغيل git annex adjust --unlock-present مرة أخرى. أو، لأتمتة التحديثات، قم بتعيين إعداد annex.adjustedbranchrefresh. أو استخدم git-annex sync --content، الذي يحدث الفرع بعد نقل المحتوى.
يمكن أيضًا استخدام git-annex-common-options(1).
