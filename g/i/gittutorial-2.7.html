gittutorial-2(7)

الحزمة: git

التراخيص: GPL-2.0-only

git diff --- a/file.txt +++ b/file.txt @@ -1 +1,2 @@ hello world! +hello world, again $ git add file.txt $ git diff

الفرق الأخير فارغ، ولكن لم يتم إجراء أي عمليات إلزام جديدة، ولا يزال الرأس لا يحتوي على السطر الجديد:

$ git diff HEAD
diff --git a/file.txt b/file.txt
index a042389..513feba 100644
--- a/file.txt
+++ b/file.txt
@@ -1 +1,2 @@
 hello world!
+hello world, again

إذن git diff يقارن بشيء آخر غير الرأس. الشيء الذي يقارن به هو بالفعل ملف الفهرس، والذي يتم تخزينه في .git/index بتنسيق ثنائي، ولكن يمكننا فحص محتوياته باستخدام ls-files:

$ git ls-files --stage
100644 513feba2e53ebbd2532419ded848ba19de88ba00 0       file.txt
$ git cat-file -t 513feba2
blob
$ git cat-file blob 513feba2
hello world!
hello world, again

إذن ما فعله git add لدينا هو تخزين كائن جديد ثم وضع مرجع له في ملف الفهرس. إذا قمنا بتعديل الملف مرة أخرى، سنرى أن التعديلات الجديدة تنعكس في مخرجات git diff:

$ echo 'again?' >>file.txt
$ git diff
index 513feba..ba3da7b 100644
--- a/file.txt
+++ b/file.txt
@@ -1,2 +1,3 @@
 hello world!
 hello world, again
+again?

مع الوسائط الصحيحة، يمكن لـ git diff أيضًا أن يوضح لنا الفرق بين دليل العمل وآخر عملية إلزام، أو بين الفهرس وآخر عملية إلزام:

$ git diff HEAD
diff --git a/file.txt b/file.txt
index a042389..ba3da7b 100644
--- a/file.txt
+++ b/file.txt
@@ -1 +1,3 @@
 hello world!
+hello world, again
+again?
$ git diff --cached
diff --git a/file.txt b/file.txt
index a042389..513feba 100644
--- a/file.txt
+++ b/file.txt
@@ -1 +1,2 @@
 hello world!
+hello world, again

في أي وقت، يمكننا إنشاء عملية إلزام جديدة باستخدام git commit (بدون الخيار "-a")، والتحقق من أن الحالة الملزمة تتضمن فقط التغييرات المخزنة في ملف الفهرس، وليس التغيير الإضافي الذي لا يزال في شجرة العمل لدينا فقط:

$ git commit -m "repeat"
$ git diff HEAD
diff --git a/file.txt b/file.txt
index 513feba..ba3da7b 100644
--- a/file.txt
+++ b/file.txt
@@ -1,2 +1,3 @@
 hello world!
 hello world, again
+again?

لذلك افتراضيًا، يستخدم git commit الفهرس لإنشاء عملية الإلزام، وليس شجرة العمل؛ الخيار "-a" لـ commit يخبره بتحديث الفهرس أولاً بجميع التغييرات في شجرة العمل.

أخيرًا، يجدر النظر في تأثير git add على ملف الفهرس:

$ echo "goodbye, world" >closing.txt
$ git add closing.txt

كان تأثير git add هو إضافة إدخال واحد إلى ملف الفهرس:

$ git ls-files --stage
100644 8b9743b20d4b15be3955fc8d5cd2b09cd2336138 0       closing.txt
100644 513feba2e53ebbd2532419ded848ba19de88ba00 0       file.txt

وكما يمكنك أن ترى باستخدام cat-file، هذا الإدخال الجديد يشير إلى المحتويات الحالية للملف:

$ git cat-file blob 8b9743b2
goodbye, world

الأمر "status" هو طريقة مفيدة للحصول على ملخص سريع للحالة:

$ git status
On branch master
Changes to be committed:
  (use "git restore --staged <file>..." to unstage)
        new file:   closing.txt
Changes not staged for commit:
  (use "git add <file>..." to update what will be committed)
  (use "git restore <file>..." to discard changes in working directory)
        modified:   file.txt

نظرًا لأن الحالة الحالية لـ closing.txt مخزنة مؤقتًا في ملف الفهرس، يتم سردها كـ "Changes to be committed". نظرًا لأن file.txt لديه تغييرات في دليل العمل التي لا تنعكس في الفهرس، يتم وضع علامة "changed but not updated". في هذه المرحلة، سيؤدي تشغيل "git commit" إلى إنشاء عملية إلزام أضافت closing.txt (بمحتوياتها الجديدة)، ولكن لم تعدل file.txt.

أيضًا، لاحظ أن git diff العادي يعرض التغييرات على file.txt، ولكن ليس إضافة closing.txt، لأن نسخة closing.txt في ملف الفهرس متطابقة مع تلك الموجودة في دليل العمل.

بالإضافة إلى كونها منطقة التجهيز لعمليات الإلزام الجديدة، يتم أيضًا ملء ملف الفهرس من قاعدة بيانات الكائنات عند استخراج فرع، ويتم استخدامه للاحتفاظ بالأشجار المشاركة في عملية دمج. انظر gitcore-tutorial(7) والصفحات الدليل ذات الصلة للحصول على التفاصيل.

ماذا بعد؟

في هذه المرحلة، يجب أن تعرف كل ما هو ضروري لقراءة صفحات الدليل لأي من أوامر git؛ مكان جيد للبدء به سيكون مع الأوامر المذكورة في giteveryday(7). يجب أن تكون قادرًا على العثور على أي مصطلحات غير معروفة في gitglossary(7).

دليل مستخدم Git[1] يوفر مقدمة أكثر شمولاً لـ Git.

gitcvs-migration(7) يشرح كيفية استيراد مستودع CVS إلى Git، ويوضح كيفية استخدام Git بطريقة تشبه CVS.

لبعض الأمثلة المثيرة للاهتمام لاستخدام Git، انظر howtos[2].

لمطوري Git، gitcore-tutorial(7) يتطرق بالتفصيل إلى الآليات الداخلية لـ Git المعنية، على سبيل المثال، إنشاء عملية إلزام جديدة.
