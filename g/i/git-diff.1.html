تنسيق الفرق المدمج

يمكن لأي أمر يولد فرقًا أن يأخذ الخيار -c أو --cc لإنتاج فرق مدمج عند عرض الدمج. هذا هو التنسيق الافتراضي عند عرض عمليات الدمج باستخدام git-diff(1) أو git-show(1). لاحظ أيضًا أنه يمكنك إعطاء خيار --diff-merges مناسب لأي من هذه الأوامر لفرض إنشاء فروقات بتنسيق معين.

يبدو تنسيق "الفرق المدمج" كالتالي:

1. يسبقها ترويسة "git diff"، والتي تبدو كالتالي (عند استخدام الخيار -c):

diff --combined file

أو كالتالي (عند استخدام الخيار --cc):

diff --cc file

2. يتبعها سطر واحد أو أكثر من رؤوس الرؤوس الموسعة (يوضح هذا المثال دمجًا مع والدين):

index <hash>,<hash>..<hash>
mode <mode>,<mode>..<mode>
new file mode <mode>
deleted file mode <mode>,<mode>

يظهر السطر mode <mode>,<mode>..<mode> فقط إذا كان أحد <mode> على الأقل مختلفًا عن الباقي. تم تصميم الرؤوس الموسعة التي تحتوي على معلومات حول نقل المحتوى المكتشف (إعادة التسمية واكتشاف النسخ) للعمل مع فرق بين <tree-ish> ولا يستخدمها تنسيق الفرق المدمج.

3. يتبعه ترويسة ملف من / ملف إلى سطرين:

--- a/file
+++ b/file

على غرار الترويسة ذات السطرين لتنسيق الفرق الموحد التقليدي، يتم استخدام /dev/null للإشارة إلى الملفات التي تم إنشاؤها أو حذفها.

ومع ذلك، إذا تم توفير الخيار --combined-all-paths، بدلاً من ملف من / ملف سطرين، تحصل على ترويسة ملف من / ملف N+1 سطر، حيث N هو عدد الآباء في التزام الدمج:

--- a/file
--- a/file
--- a/file
+++ b/file

يمكن أن يكون هذا التنسيق الموسع مفيدًا إذا كان اكتشاف إعادة التسمية أو النسخ نشطًا، للسماح لك برؤية الاسم الأصلي للملف في الآباء المختلفين.

4. تم تعديل تنسيق ترويسة الجزء لمنع الأشخاص من تغذيته عن طريق الخطأ إلى patch -p1. تم إنشاء تنسيق الفرق المدمج لمراجعة تغييرات التزام الدمج، ولم يكن المقصود تطبيقه. التغيير مشابه للتغيير في ترويسة index الموسعة:

@@@ <from-file-range> <from-file-range> <to-file-range> @@@

يوجد (عدد الآباء + 1) حرف @ في ترويسة الجزء لتنسيق الفرق المدمج.

على عكس تنسيق الفرق الموحد التقليدي، الذي يعرض ملفين A و B مع عمود واحد له بادئة - (ناقص - يظهر في A ولكنه محذوف في B) أو + (زائد - مفقود في A ولكنه مضاف إلى B) أو " " (مسافة - لم يتغير)، يقارن هذا التنسيق ملفين أو أكثر file1، file2،... بملف واحد X، ويعرض كيف يختلف X عن كل من fileN. يتم إضافة عمود واحد لكل من fileN إلى سطر الإخراج للإشارة إلى كيف يختلف X عن ذلك.

يعني حرف - في العمود N أن السطر يظهر في fileN ولكنه لا يظهر في النتيجة. يعني حرف + في العمود N أن السطر يظهر في النتيجة، ولا يحتوي fileN على هذا السطر (بمعنى آخر، تمت إضافة السطر، من وجهة نظر هذا الأصل).

في ناتج المثال أعلاه، تم تغيير توقيع الدالة من كلا الملفين (لذلك هناك عمليتا حذف - من كلا ملفي file1 و file2، بالإضافة إلى ++ ليعني سطرًا تمت إضافته لا يظهر في أي من file1 أو file2). أيضًا، ثمانية أسطر أخرى هي نفسها من file1 ولكنها لا تظهر في file2 (لذلك مسبوقة بـ +).

عند عرضه بواسطة git diff-tree -c، فإنه يقارن آباء التزام الدمج بنتيجة الدمج (أي file1..fileN هم الآباء). عند عرضه بواسطة git diff-files -c، فإنه يقارن الآباء غير المحلولين للدمج مع ملف شجرة العمل (أي file1 هو المرحلة 2 الملقبة "نسختنا"، file2 هو المرحلة 3 الملقبة "نسختهم").

تنسيقات فرق أخرى

يصف الخيار --summary الملفات المضافة حديثًا والمحذوفة والمعاد تسميتها ونسخها. يضيف الخيار --stat الرسم البياني diffstat(1) إلى الإخراج. يمكن دمج هذه الخيارات مع خيارات أخرى، مثل -p، وهي مخصصة للاستهلاك البشري.

عند عرض تغيير يتضمن إعادة تسمية أو نسخًا، تقوم صيغة إخراج --stat بتنسيق أسماء المسارات بشكل مضغوط عن طريق دمج البادئة واللاحقة المشتركة لأسماء المسارات. على سبيل المثال، سيتم عرض تغيير ينقل arch/i386/Makefile إلى arch/x86/Makefile مع تعديل 4 أسطر كالتالي:

arch/{i386 => x86}/Makefile    |   4 +--

يمنح الخيار --numstat معلومات diffstat(1) ولكنه مصمم لسهولة الاستهلاك الآلي. إدخال في إخراج --numstat يبدو كالتالي:

1       2       README
3       1       arch/{i386 => x86}/Makefile

أي، من اليسار إلى اليمين:

1. عدد الأسطر المضافة؛

2. علامة جدولة؛

3. عدد الأسطر المحذوفة؛

4. علامة جدولة؛

5. اسم المسار (ربما مع معلومات إعادة تسمية/نسخ)؛

6. سطر جديد.

عندما يكون خيار الإخراج -z فعالاً، يتم تنسيق الإخراج بهذه الطريقة:

1       2       README NUL
3       1       NUL arch/i386/Makefile NUL arch/x86/Makefile NUL

أي:

1. عدد الأسطر المضافة؛

2. علامة جدولة؛

3. عدد الأسطر المحذوفة؛

4. علامة جدولة؛

5. NUL (موجود فقط إذا تم إعادة تسميته/نسخه)؛

6. اسم المسار في الصورة الأولية؛

7. NUL (موجود فقط إذا تم إعادة تسميته/نسخه)؛

8. اسم المسار في الصورة اللاحقة (موجود فقط إذا تم إعادة تسميته/نسخه)؛

9. NUL.

الـ NUL الإضافي قبل مسار الصورة الأولية في حالة إعادة التسمية هو للسماح للنصوص البرمجية التي تقرأ الإخراج بتحديد ما إذا كان السجل الحالي الذي يتم قراءته هو سجل مسار واحد أو سجل إعادة تسمية/نسخ دون قراءة مسبقة. بعد قراءة الأسطر المضافة والمحذوفة، فإن القراءة حتى NUL ستعطي اسم المسار، ولكن إذا كان ذلك NUL، فإن السجل سيعرض مسارين.

أمثلة

طرق مختلفة للتحقق من شجرة عملك

$ git diff            (1)
$ git diff --cached   (2)
$ git diff HEAD       (3)
$ git diff AUTO_MERGE (4)
1. التغييرات في شجرة العمل التي لم يتم إعدادها بعد للالتزام التالي.
2. التغييرات بين الفهرس وآخر التزام لك؛ ما ستلتزم به إذا قمت بتشغيل git commit بدون خيار -a.
3. التغييرات في شجرة العمل منذ آخر التزام لك؛ ما ستلتزم به إذا قمت بتشغيل git commit -a
4. التغييرات في شجرة العمل التي أجريتها لحل تعارضات النصوص حتى الآن.

المقارنة مع التزامات عشوائية

$ git diff test            (1)
$ git diff HEAD -- ./test  (2)
$ git diff HEAD^ HEAD      (3)
1. بدلاً من استخدام قمة الفرع الحالي، قارن بقمة الفرع "test".
2. بدلاً من المقارنة بقمة الفرع "test"، قارن بقمة الفرع الحالي، ولكن قم بتحديد المقارنة بالملف "test".
3. قارن الإصدار قبل آخر التزام وآخر التزام.

مقارنة الفروع

$ git diff topic master    (1)
$ git diff topic..master   (2)
$ git diff topic...master  (3)
1. التغييرات بين قمم فرعي topic و master.
2. نفس الشيء كما في الأعلى.
3. التغييرات التي حدثت على فرع master منذ بدء فرع topic منه.

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.
