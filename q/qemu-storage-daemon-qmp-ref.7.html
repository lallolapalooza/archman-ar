مقدمة

يصف هذا الدليل الأوامر والأحداث التي يدعمها QEMU storage daemon QMP.

للعثور على عنصر معين، يرجى الرجوع إلى فهرس QSD <>.

يتم استخدام التدوين التالي في الأمثلة:

مثال:
-> ... نص أرسله العميل (أوامر) ...
<- ... نص أرسله الخادم (ردود الأوامر والأحداث) ...

يتم تنسيق نص المثال لسهولة القراءة. ومع ذلك، في الاستخدام الفعلي للبروتوكول، يتم إصداره عادةً كسطر واحد.

يرجى الرجوع إلى مواصفات بروتوكول آلة QEMU <> لمعرفة التنسيق العام للأوامر والاستجابات والأحداث.

الأمر job-finalize (منذ: 3.0)
يُصدر تعليمات لجميع المهام في معاملة (أو مهمة واحدة إذا لم تكن جزءًا من أي معاملة) لإنهاء أي تغييرات في الرسم البياني وإجراء أي تنظيف ضروري. يتطلب هذا الأمر أن تكون جميع المهام المعنية في حالة PENDING.

بالنسبة للمهام في معاملة، فإن إصدار تعليمات لمهمة واحدة بالإنهاء سيجبر جميع المهام في المعاملة على الإنهاء، لذلك يكفي إصدار تعليمات لمهمة واحدة فقط.

ينطبق الأمر فقط على المهام التي لديها خيار auto-finalize وعندما يتم تعيين هذا الخيار إلى false.

    بالنسبة لللقطات الخارجية، يحتوي القاموس على الجهاز، والملف المستخدم لإنشاء اللقطة الجديدة، والتنسيق. التنسيق الافتراضي، إذا لم يتم تحديده، هو qcow2.

    كل لقطة جديدة افتراضيًا يتم إنشاؤها بواسطة QEMU (مع مسح أي محتويات إذا كان الملف موجودًا بالفعل)، ولكن من الممكن أيضًا إعادة استخدام ملف تم إنشاؤه خارجيًا. في الحالة الأخيرة، يجب عليك التأكد من أن ملف الصورة الجديد له نفس محتويات الملف الحالي؛ لا يمكن لـ QEMU إجراء أي فحص مفيد. عادةً ما يتم تحقيق ذلك باستخدام ملف الصورة الحالي كملف داعم للصورة الجديدة.

    عند الفشل، سيتم استخدام الأقراص الأصلية قبل محاولة اللقطة.

    بالنسبة لللقطات الداخلية، يحتوي القاموس على الجهاز واسم اللقطة. إذا كانت هناك لقطة داخلية بنفس الاسم موجودة بالفعل، فسيتم رفض الطلب. بعض تنسيقات الصور فقط تدعمها، على سبيل المثال، qcow2، و rbd.

    عند الفشل، سيحاول QEMU حذف اللقطة الداخلية التي تم إنشاؤها حديثًا في المعاملة. عند حدوث خطأ في الإدخال/الإخراج أثناء الحذف، يحتاج المستخدم إلى إصلاحه لاحقًا باستخدام qemu-img أو أمر آخر.

    Arguments
    • path (string) --

      المسار داخل نموذج الكائن. هناك شكلان للمسارات المدعومة - المسارات المطلقة والمسارات الجزئية.

      المسارات المطلقة مشتقة من الكائن الجذر ويمكن أن تتبع خصائص child<> أو link<>. نظرًا لأنه يمكن أن تتبع خصائص link<>، يمكن أن تكون طويلة بشكل عشوائي. تبدو المسارات المطلقة مثل أسماء الملفات المطلقة ويتم تمييزها بشرطة مائلة بادئة.

      تبدو المسارات الجزئية مثل أسماء الملفات النسبية. لا تبدأ ببادئة. قواعد المطابقة للمسارات الجزئية دقيقة ولكنها مصممة لجعل تحديد الكائنات سهلاً. عند كل مستوى من شجرة التكوين، تتم مطابقة المسار الجزئي كمسار مطلق. لا يتم إرجاع المطابقة الأولى. يتم البحث عن مطابقتين على الأقل. يتم إرجاع نتيجة ناجحة فقط إذا تم العثور على مطابقة واحدة فقط. إذا تم العثور على أكثر من مطابقة واحدة، يتم إرجاع علامة للإشارة إلى أن المطابقة كانت غامضة.

    Return

      NAME

      object-del - Remove a QOM object

      INTRODUCTION

      This command is used to remove a QOM object.

      COMMON DATA TYPES

      No specific common data types are defined for this command.

      SOCKET DATA TYPES

      No specific socket data types are defined for this command.

      CRYPTOGRAPHY

      This command is not related to cryptography.

      BACKGROUND JOBS

      This command does not directly manage background jobs.

      BLOCK DEVICES

      This command can be used to remove block device objects.

      CHARACTER DEVICES

      This command can be used to remove character device objects.

      USER AUTHORIZATION

      User authorization is not directly handled by this command, but relies on the underlying QMP connection's authentication and authorization mechanisms.

      TRANSACTIONS

      This command can be part of a QMP transaction.

      QMP MONITOR CONTROL

      This command is part of the QMP Monitor Control interface.

      QMP INTROSPECTION

      Information about this command is available through QMP introspection.
