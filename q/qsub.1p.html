QSUB(1P) دليل مبرمج POSIX QSUB(1P)

مقدمة

هذه الصفحة الدليلية جزء من دليل مبرمج POSIX. قد يختلف تنفيذ لينكس لهذا الواجهة (راجع صفحة دليل لينكس المقابلة لتفاصيل سلوك لينكس)، أو قد لا تكون الواجهة مطبقة على لينكس.

الاسم

qsub — إرسال نص برمجي

الملخص

qsub [-a date_time] [-A account_string] [-c interval]
    [-C directive_prefix] [-e path_name] [-h] [-j join_list]
    [-k keep_list] [-m mail_options] [-M mail_list] [-N name]
    [-o path_name] [-p priority] [-q destination] [-r y|n]
    [-S path_name_list] [-u user_list] [-v variable_list] [-V]
    [-z] [script]

الوصف

لإرسال نص برمجي يعني إنشاء مهمة دفعة تقوم بتنفيذ النص البرمجي. يتم إرسال النص البرمجي بطلب إلى خادم دفعة. أداة qsub هي عميل دفعة متاح للمستخدم يرسل نصًا برمجيًا.

عند الانتهاء بنجاح، يجب أن تكون أداة qsub قد أنشأت مهمة دفعة ستقوم بتنفيذ النص البرمجي المرسل.

يجب أن ترسل أداة qsub نصًا برمجيًا عن طريق إرسال طلب مهمة دفعة إلى خادم دفعة.

يجب أن تضع أداة qsub قيمة متغيرات البيئة التالية في قائمة المتغيرات لمهمة الدفعة: HOME، LANG، LOGNAME، PATH، MAIL، SHELL، و TZ. سيكون اسم متغير البيئة هو الاسم الحالي مسبوقًا بالسلسلة PBS_O_.

ملاحظة:
إذا كانت القيمة الحالية للمتغير HOME في مساحة البيئة لأداة qsub هي /aa/bb/cc، فستضع qsub PBS_O_HOME=/aa/bb/cc في قائمة المتغيرات لمهمة الدفعة.

بالإضافة إلى المتغيرات الموضحة أعلاه، يجب أن تضيف أداة qsub المتغيرات التالية بالقيم المحددة إلى قائمة المتغيرات:

PBS_O_WORKDIR
المسار المطلق للدليل الحالي لعملية أداة qsub.
PBS_O_HOST
اسم المضيف الذي تعمل عليه أداة qsub.

خيارات

يجب أن تتوافق أداة qsub مع وحدة التعريفات الأساسية لـ POSIX.1-2017، القسم 12.2، إرشادات بناء جملة الأداة.

يجب أن تدعم الواجهة الخيارات التالية:

-a date_time
تحديد الوقت الذي تصبح فيه مهمة الدفعة مؤهلة للتنفيذ.

يجب أن تقبل أداة qsub وسيطة خيار تتوافق مع بناء جملة الوسيط time للأداة touch.


الجدول 4-19: قيم متغيرات البيئة (الأدوات)

اسم المتغير القيمة عند وقت qsub
PBS_O_HOME HOME
PBS_O_HOST اسم مضيف العميل
PBS_O_LANG LANG
PBS_O_LOGNAME LOGNAME
PBS_O_PATH PATH
PBS_O_MAIL MAIL
PBS_O_SHELL SHELL
PBS_O_TZ TZ
PBS_O_WORKDIR الدليل الحالي
ملاحظة:
سيضيف الخادم الذي يبدأ تنفيذ مهمة الدفعة متغيرات أخرى إلى بيئة مهمة الدفعة؛ راجع القسم 3.2.2.1، تنفيذ مهمة الدفعة.

يجب أن تحدد أداة qsub السمة Execution_Time لمهمة الدفعة إلى عدد الثواني منذ الحقبة الذي يعادل الوقت المحلي المعبر عنه بقيمة وسيطة الخيار date_time. يتم تعريف الحقبة في وحدة التعريفات الأساسية لـ POSIX.1-2017، القسم 3.150، الحقبة.

إذا لم يتم تقديم الخيار -a لأداة qsub، فستحدد الأداة السمة Execution_Time لمهمة الدفعة بوقت (عدد الثواني منذ الحقبة) يكون أسبق من وقت خروج الأداة.

-A account_string

تحديد الحساب الذي يجب أن تُحسب فيه استهلاك موارد مهمة الدفعة.

بناء جملة وسيطة الخيار account_string غير محدد.

يجب أن تحدد أداة qsub السمة Account_Name لمهمة الدفعة بقيمة وسيطة الخيار account_string.

إذا لم يتم تقديم الخيار -A لأداة qsub، فستقوم الأداة بحذف السمة Account_Name من سمات مهمة الدفعة.

-c interval
تحديد ما إذا كان يجب فحص مهمة الدفعة، وإذا كان الأمر كذلك، فكم مرة.

يجب أن تقبل أداة qsub قيمة لوسيط فترة الخيار تكون واحدة مما يلي:

n
لن يتم إجراء أي فحص لمهمة الدفعة (NO_CHECKPOINT).
s
سيتم إجراء الفحص فقط عند إيقاف تشغيل خادم الدفعة (CHECKPOINT_AT_SHUTDOWN).
c
سيتم إجراء الفحص الدوري التلقائي عند Minimum_Cpu_Interval لمثيل الدفعة، بوحدات دقائق وحدة المعالجة المركزية (CHECKPOINT_AT_MIN_CPU_INTERVAL).
c=minutes
سيتم إجراء الفحص الدوري التلقائي كل minutes من وقت وحدة المعالجة المركزية، أو كل Minimum_Cpu_Interval دقيقة، أيهما أكبر. يجب أن يتوافق الوسيط minutes مع بناء الجملة للأعداد الصحيحة غير الموقعة ويجب أن يكون أكبر من الصفر.

يجب أن تحدد أداة qsub السمة Checkpoint لمهمة الدفعة بقيمة وسيطة الخيار interval.

إذا لم يتم تقديم الخيار -c لأداة qsub، فستحدد الأداة السمة Checkpoint لمهمة الدفعة بالحرف المفرد 'u' (CHECKPOINT_UNSPECIFIED).

-C directive_prefix

تحديد البادئة التي تعلن عن توجيه لأداة qsub داخل النص البرمجي.

directive_prefix ليست سمة لمهمة دفعة؛ إنها تؤثر على سلوك أداة qsub.

إذا تم تقديم الخيار -C لأداة qsub، وكانت قيمة وسيطة الخيار directive_prefix هي السلسلة الفارغة، فلن تقوم الأداة بمسح ملف النص البرمجي بحثًا عن التوجيهات. إذا لم يتم تقديم الخيار -C لأداة qsub، فسيتم استخدام قيمة متغير البيئة PBS_DPREFIX. إذا لم يكن متغير البيئة معرفًا، فإن #PBS المشفرة في مجموعة الأحرف المحمولة هو الافتراضي.

-e path_name

PROLOG

This page is a manual page for the qsub utility. It is part of the POSIX.1-2017 standard. The qsub utility is used to submit a batch job to the batch subsystem.

NAME

qsub — submit a batch job to the batch subsystem

SYNOPSIS

qsub [option...] [utility [argument...]]
qsub -a [[hours]minutes]date [option...] [utility [argument...]]
qsub -u user [option...] [utility [argument...]]

DESCRIPTION

The qsub utility is used to submit a batch job to the batch subsystem. A batch job consists of a utility or script to be run, and possibly arguments to that utility or script.

The qsub utility shall create a batch job, place it in the appropriate queue, and then take the appropriate action based on the options specified.

The qsub utility differs from the at and batch utilities in that it is designed for use with a batch subsystem, rather than for immediate or deferred execution on the local host.

OPTIONS

-a [[hours]minutes]date
Specify the time when the batch job should be run. The format of the date is implementation-defined, but shall conform to the syntax.
-A account_string
Specify the account string to be used for accounting purposes.
-b
Indicate that the specified utility is a binary executable.
-c interval
Specify the checkpointing interval for the batch job.
-C center_info
Specify the center information for the batch job.
-e path_list
Specify the list of directories to be searched for executable files.
-f resource_list
Specify the list of resources required by the batch job.
-F file
Specify a file containing resource requirements.
-j job_identifier
Specify the job identifier for the batch job.
-J job_name
Specify a name for the batch job. This name is not used by the job execution management component of the batch subsystem; rather, it serves as a mnemonic handle for users. For example, the batch job name can help the user distinguish between multiple jobs listed by the qstat utility.
-o path
Redirect the standard output stream to the specified file. If the file exists, its contents shall be overwritten. If the file does not exist, it shall be created. If the file is specified as a directory, the behavior is implementation-defined.
-P priority
Designate the relative priority of a batch job for selection from a queue.
-q queue
Specify the initial queue for the batch job. If the user specifies a routing queue, the batch server routes the batch job to another queue for execution or further routing. If the user specifies a non-routing queue, the batch server of the queue eventually executes the batch job.
-r { y | n }
Control whether the submitted job will be rerun if the controlling batch node fails during execution of the batch job. The -r option likewise allows users to indicate whether or not the batch job is eligible to be rerun by the qrerun utility. Some jobs cannot be correctly rerun because of changes they make in the state of databases or other aspects of their environment. This volume of POSIX.1-2017 specifies that the default, if the -r option is not presented to the utility, will be that the batch job cannot be rerun, since the result of rerunning a non-rerunnable job might be catastrophic.
-S path
Specify the program (usually a shell) that will be invoked to process the script of the batch job. This option has been modified to allow a list of shell names and locations associated with different hosts.
-u user
Select from among the accounts the submitting user is authorized to use on a given host. The option-argument is a list of user-host pairs, so that the submitting user can provide different user identifiers for different nodes in the event the batch job is routed. The -u option provides a lot of flexibility to accommodate sites with complex account structures. Users that have the same user identifier on all the hosts they are authorized to use will not need to use the -u option.
-V
Export all current environment variables, as of the time the batch job is submitted, to the context of the processes of the batch job.
-v variable_list
Export specific environment variables from the current process to the processes of the batch job.
-z
Suppress the writing of the batch job identifier to standard output. The -z option is an existing NQS practice that has been standardized.

OPERANDS

The following operands are supported:

utility
A utility to be executed as a batch job.
argument
Arguments to be passed to the utility.

If no utility is specified, the standard input shall be executed as a shell script.

STDIN

The standard input shall be used to transmit the script to be executed, unless the - or option is used to specify a file containing the script. If the standard input is not used, it shall be unaffected.

INPUT FILES

None.

ENVIRONMENT VARIABLES

The following environment variables shall be used:

SHELL
Determines the default shell to use if the -S option is not specified.

The environment variables that are exported by the -V and -v options are described above.

ASYNCHRONOUS EVENTS

Default.

STDOUT

The standard output shall be used for any output generated by the submitted batch job, unless redirected by the -o option.

If the -z option is not specified, the standard output shall contain the job identifier of the submitted batch job.

STDERR

The standard error shall be used for any diagnostic messages generated by the qsub utility itself.

OUTPUT FILES

None.

EXTENDED DESCRIPTION

None.

EXIT STATUS

The exit status of qsub shall be one of the following values:

0
The batch job was successfully submitted to the batch subsystem.
>0
An error occurred during submission.

CONSEQUENCES OF ERRORS

The standard error shall be used for diagnostic messages.

APPLICATION USAGE

None.

EXAMPLES

None.

RATIONALE

The -J option allows users to specify a job name. This name is not used by the job execution management component of the batch job, but rather serves as a mnemonic handle for users. For example, the batch job name can help the user distinguish between multiple jobs listed by the qstat utility.

The -o option allows users to redirect the standard output stream. A user might, for example, wish to redirect to the null device the standard output stream of a job that produces copious yet superfluous output.

The -P option allows users to designate the relative priority of a batch job for selection from a queue.

The -q option allows users to specify an initial queue for the batch job. If the user specifies a routing queue, the batch server routes the batch job to another queue for execution or further routing. If the user specifies a non-routing queue, the batch server of the queue eventually executes the batch job.

The -r option allows users to control whether the submitted job will be rerun if the controlling batch node fails during execution of the batch job. The -r option likewise allows users to indicate whether or not the batch job is eligible to be rerun by the qrerun utility. Some jobs cannot be correctly rerun because of changes they make in the state of databases or other aspects of their environment. This volume of POSIX.1-2017 specifies that the default, if the -r option is not presented to the utility, will be that the batch job cannot be rerun, since the result of rerunning a non-rerunnable job might be catastrophic.

The -S option allows users to specify the program (usually a shell) that will be invoked to process the script of the batch job. This option has been modified to allow a list of shell names and locations associated with different hosts.

The -u option is useful when the submitting user is authorized to use more than one account on a given host, in which case the -u option allows the user to select from among those accounts. The option-argument is a list of user-host pairs, so that the submitting user can provide different user identifiers for different nodes in the event the batch job is routed. The -u option provides a lot of flexibility to accommodate sites with complex account structures. Users that have the same user identifier on all the hosts they are authorized to use will not need to use the -u option.

The -V option allows users to export all their current environment variables, as of the time the batch job is submitted, to the context of the processes of the batch job.

The -v option allows users to export specific environment variables from their current process to the processes of the batch job.

The -z option allows users to suppress the writing of the batch job identifier to standard output. The -z option is an existing NQS practice that has been standardized.

Historically, the qsub utility has served the batch job-submission function in the NQS system, the existing practice on which it is based. Some changes and additions have been made to the qsub utility in this volume of POSIX.1-2017, vis-a-vis NQS, as a result of the growing pool of experience with distributed batch systems.

The set of features of the qsub utility as defined in this volume of POSIX.1-2017 appears to incorporate all the common existing practice on potentially conforming platforms.

FUTURE DIRECTIONS

The qsub utility may be removed in a future version.
