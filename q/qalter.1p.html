NAME

qalter — alter batch job properties

SYNOPSIS

qalter [option...] job_identifier...

DESCRIPTION

The qalter utility shall submit a request to the batch system to alter one or more properties of a specified batch job or jobs. The properties that may be altered are listed below. Not all properties are necessarily supported by all implementations. Refer to the description of the qsub utility for a definition of the properties.

OPTIONS

The qalter utility shall support the options listed below. The options correspond to the job properties that can be altered.

-A
Allows users to change the account associated with a batch job.
-b
Allows users to alter the decision to join
(merge)
the standard error stream of the batch job with the standard output stream of the batch job.
-l
Allows users to change the resource limits imposed on a batch job.
-m
Allows users to modify the list of points in the life of a batch job at which the designated users will receive mail notification.
-M
Allows users to alter the list of users who will receive notification about events in the life of a batch job.
-N
Allows users to change the name of a batch job.
-o
Allows users to alter the name and path to which the standard output stream of the batch job will be written.
-P
Allows users to modify the priority of a batch job. Support for priority is optional for batch servers.
-r
Allows users to alter the rerunability status of a batch job.
-S
Allows users to change the name and location of the shell image that will be invoked to interpret the script of the batch job. This option has been modified to allow a list of shell name and locations associated with different hosts.
-u
Allows users to change the user identifier under which the batch job will execute.

OPERANDS

The following operand shall be supported:

job_identifier
Specifies the job or jobs to be altered. The syntax is provided so that the user can differentiate between the originating and destination (or executing) batch server. These may or may not be the same. The ‘.server_name’ portion identifies the originating batch server, while the ‘@server’ portion identifies the destination batch server.

STDIN

Not used.

INPUT FILES

None.

ENVIRONMENT VARIABLES

None.

ASYNCHRONOUS EVENTS

None.

STDOUT

If the altered job is successfully modified, the standard output shall be empty.

STDERR

The standard error stream shall be used to report errors.

OUTPUT FILES

None.

EXTENDED DESCRIPTION

None.

EXIT STATUS

On success, a value of 0 shall be returned.

On failure, a value greater than 0 shall be returned.

CONSEQUENCES OF ERRORS

No jobs shall be altered if an error occurs.

APPLICATION USAGE

None.

EXAMPLES

None.

RATIONALE

The -l option allows users to change the resource limits imposed on a batch job.

The -m option allows users to modify the list of points in the life of a batch job at which the designated users will receive mail notification.

The -M option allows users to alter the list of users who will receive notification about events in the life of a batch job.

The -N option allows users to change the name of a batch job.

The -o option allows users to alter the name and path to which the standard output stream of the batch job will be written.

The -P option allows users to modify the priority of a batch job. Support for priority is optional for batch servers.

The -r option allows users to alter the rerunability status of a batch job.

The -S option allows users to change the name and location of the shell image that will be invoked to interpret the script of the batch job. This option has been modified to allow a list of shell name and locations associated with different hosts.

The -u option allows users to change the user identifier under which the batch job will execute.

The job_identifier operand syntax is provided so that the user can differentiate between the originating and destination (or executing) batch server. These may or may not be the same. The .server_name portion identifies the originating batch server, while the @server portion identifies the destination batch server.

Historically, the qalter utility has been a component of the Network Queuing System (NQS), the existing practice from which this utility has been derived.

FUTURE DIRECTIONS

The qalter utility may be removed in a future version.
