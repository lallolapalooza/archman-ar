انظر الأوامر والخيارات لوصف هذه الأوامر مع خياراتها.

الوصف

الأمر keytool هو أداة لإدارة المفاتيح والشهادات. يمكّن المستخدمين من إدارة أزواج المفاتيح العامة/الخاصة الخاصة بهم والشهادات المرتبطة بها لاستخدامها في المصادقة الذاتية (حيث يقوم المستخدم بمصادقة نفسه للمستخدمين والخدمات الأخرى) أو خدمات سلامة البيانات والمصادقة، عن طريق استخدام التوقيعات الرقمية. كما يمكّن الأمر keytool المستخدمين من تخزين المفاتيح العامة (في شكل شهادات) للجهات المتصلة.

الشهادة هي بيان موقع رقمياً من كيان واحد (شخص، شركة، إلخ)، يقول أن المفتاح العام (وبعض المعلومات الأخرى) لكيان آخر له قيمة معينة. عندما يتم توقيع البيانات رقمياً، يمكن التحقق من التوقيع للتحقق من سلامة البيانات وأصالتها. السلامة تعني أن البيانات لم يتم تعديلها أو العبث بها، والأصالة تعني أن البيانات تأتي من الفرد الذي يدعي أنه أنشأها ووقعها.

يمكّن الأمر keytool المستخدمين أيضاً من إدارة المفاتيح السرية وكلمات المرور المستخدمة في التشفير وفك التشفير المتماثل (Data Encryption Standard). يمكنه أيضاً عرض معلومات أخرى متعلقة بالأمان.

يخزن الأمر keytool المفاتيح والشهادات في مخزن مفاتيح.

يستخدم الأمر keytool خاصيات الأمان jdk.certpath.disabledAlgorithms و jdk.security.legacyAlgorithms لتحديد الخوارزميات التي تعتبر خطراً أمنياً. يصدر تحذيرات عند استخدام خوارزميات معطلة أو قديمة. يتم تعريف خاصيات الأمان jdk.certpath.disabledAlgorithms و jdk.security.legacyAlgorithms في ملف java.security (الموجود في دليل $JAVA_HOME/conf/security الخاص بـ JDK).

ملاحظات الأوامر والخيارات

تنطبق الملاحظات التالية على الأوصاف الواردة في الأوامر والخيارات:

•
يسبق جميع أسماء الأوامر والخيارات رمز الشرطة (-).
•
يمكن تقديم أمر واحد فقط.
•
يمكن تقديم خيارات كل أمر بأي ترتيب.
•
هناك نوعان من الخيارات، أحدهما قيمته مفردة ويجب تقديمه مرة واحدة فقط. إذا تم تقديم خيار ذي قيمة مفردة عدة مرات، يتم استخدام قيمة الأخير. النوع الآخر هو متعدد القيم، والذي يمكن تقديمه عدة مرات ويتم استخدام جميع القيم. الخيار الوحيد متعدد القيم المدعوم حالياً هو الخيار -ext المستخدم لإنشاء امتدادات شهادات X.509v3.
•
يجب أن تظهر جميع العناصر غير المائلة أو الموجودة داخل أقواس متعرجة ({ }) أو مربعة ([ ]) كما هي.
•
الأقواس المتعرجة المحيطة بخيار تعني أنه يتم استخدام قيمة افتراضية عندما لا يتم تحديد الخيار في سطر الأوامر. تستخدم الأقواس المتعرجة أيضاً حول الخيارات -v، -rfc، و -J، والتي لها معنى فقط عندما تظهر في سطر الأوامر. ليس لها أي قيم افتراضية.
•
الأقواس المربعة المحيطة بخيار تعني أنه يتم مطالبة المستخدم بالقيم عندما لا يتم تحديد الخيار في سطر الأوامر. بالنسبة للخيار -keypass، إذا لم تحدد الخيار في سطر الأوامر، فإن الأمر keytool يحاول أولاً استخدام كلمة مرور مخزن المفاتيح لاستعادة المفتاح الخاص/السري. إذا فشلت هذه المحاولة، فسيطلب منك الأمر keytool كلمة مرور المفتاح الخاص/السري.
•
العناصر المائلة (قيم الخيارات) تمثل القيم الفعلية التي يجب تقديمها. على سبيل المثال، إليك تنسيق الأمر -printcert:

keytool -printcert {-file ملف_الشهادة} {-v}

عند تحديد أمر -printcert، استبدل ملف_الشهادة باسم الملف الفعلي، كالتالي: keytool -printcert -file VScert.cer

•
يجب إحاطة قيم الخيارات بعلامات اقتباس عندما تحتوي على مسافة.

When the -selfcert option is used, the public key is wrapped in an X.509 v3 self-signed certificate and stored as a single-element certificate chain. When the -signer option is specified, a new certificate is generated and signed by the designated signer and stored as a multiple-element certificate chain (containing the generated certificate itself, and the signer’s certificate chain). The certificate chain and private key are stored in a new keystore entry that is identified by its alias.

The -keyalg value specifies the algorithm to be used to generate the key pair, and the -keysize value specifies the size of each key to be generated. The -sigalg value specifies the algorithm that should be used to sign the certificate. This algorithm must be compatible with the -keyalg value.

The -groupname value specifies the named group (for example, the standard or predefined name of an Elliptic Curve) of the key to be generated. Only one of -groupname and -keysize can be specified.

The -signer value specifies the alias of a PrivateKeyEntry for the signer that already exists in the keystore. This option is used to sign the certificate with the signer’s private key. This is especially useful for key agreement algorithms (i.e. the -keyalg value is XDH, X25519, X448, or DH) as these keys cannot be used for digital signatures, and therefore a self-signed certificate cannot be created.

The -signerkeypass value specifies the password of the signer’s private key. It can be specified if the private key of the signer entry is protected by a password different from the store password.

The -dname value specifies the X.500 Distinguished Name to be associated with the value of -alias. If the -signer option is not specified, the issuer and subject fields of the self-signed certificate are populated with the specified distinguished name. If the -signer option is specified, the subject field of the certificate is populated with the specified distinguished name and the issuer field is populated with the subject field of the signer's certificate. If a distinguished name is not provided at the command line, then the user is prompted for one.

The value of -keypass is a password used to protect the private key of the generated key pair. If a password is not provided, then the user is prompted for it. If you press the Return key at the prompt, then the key password is set to the same password as the keystore password. The -keypass value must have at least six characters.

The value of -startdate specifies the issue time of the certificate, also known as the "Not Before" value of the X.509 certificate's Validity field.

The option value can be set in one of these two forms:

([+-]nnn[ymdHMS])+

[yyyy/mm/dd] [HH:MM:SS]

With the first form, the issue time is shifted by the specified value from the current time. The value is a concatenation of a sequence of subvalues. Inside each subvalue, the plus sign (+) means shift forward, and the minus sign (-) means shift backward. The time to be shifted is nnn units of years, months, days, hours, minutes, or seconds (denoted by a single character of y, m, d, H, M, or S respectively). The exact value of the issue time is calculated by using the java.util.GregorianCalendar.add(int field, int amount) method on each subvalue, from left to right. For example, the issue time can be specified by:


Calendar c = new GregorianCalendar();
c.add(Calendar.YEAR, -1);
c.add(Calendar.MONTH, 1);
c.add(Calendar.DATE, -1);
return c.getTime()

With the second form, the user sets the exact issue time in two parts, year/month/day and hour:minute:second (using the local time zone). The user can provide only one part, which means the other part is the same as the current date (or time). The user must provide the exact number of digits shown in the format definition (padding with 0 when shorter). When both date and time are provided, there is one (and only one) space character between the two parts. The hour should always be provided in 24-hour format.

When the option isn't provided, the start date is the current time. The option can only be provided one time.

The value of date specifies the number of days (starting at the date specified by -startdate, or the current date when -startdate isn't specified) for which the certificate should be considered valid.

Use the -genseckey command to generate a secret key and store it in a new KeyStore.SecretKeyEntry identified by alias.

The value of -keyalg specifies the algorithm to be used to generate the secret key, and the value of -keysize specifies the size of the key that is generated. ملاحظة:

هذا هو السطر الأول لجميع الخيارات:

-srckeystore مخزن_مفاتيح -destkeystore مخزن_مفاتيح

استخدم الأمر -importkeystore لاستيراد إدخال واحد أو جميع الإدخالات من مخزن مفاتيح مصدر إلى مخزن مفاتيح وجهة.

ملاحظة:

إذا لم تحدد -destkeystore عند استخدام الأمر keytool -importkeystore، فإن مخزن المفاتيح الافتراضي المستخدم هو $HOME/.keystore.

عند توفير الخيار -srcalias، يقوم الأمر باستيراد الإدخال الواحد المحدد بالاسم المستعار إلى مخزن المفاتيح الوجهة. إذا لم يتم توفير اسم مستعار للوجهة مع -destalias، فسيتم استخدام -srcalias كاسم مستعار للوجهة. إذا كان إدخال المصدر محميًا بكلمة مرور، فسيتم استخدام -srckeypass لاستعادة الإدخال. إذا لم يتم توفير -srckeypass، فسيحاول الأمر keytool استخدام -srcstorepass لاستعادة الإدخال. إذا لم يتم توفير -srcstorepass أو كان غير صحيح، فسيتم مطالبتك بكلمة مرور. يتم حماية إدخال الوجهة بواسطة -destkeypass. إذا لم يتم توفير -destkeypass، فسيتم حماية إدخال الوجهة بكلمة مرور إدخال المصدر. على سبيل المثال، تتطلب معظم الأدوات الخارجية storepass و keypass في مخزن مفاتيح PKCS #12 أن تكون متماثلة. لإنشاء مخزن مفاتيح PKCS#12 لهذه الأدوات، حدد دائمًا -destkeypass بنفس قيمة -deststorepass.

إذا لم يتم توفير الخيار -srcalias، فسيتم استيراد جميع الإدخالات في مخزن المفاتيح المصدر إلى مخزن المفاتيح الوجهة. يتم تخزين كل إدخال وجهة تحت الاسم المستعار من إدخال المصدر. إذا كان إدخال المصدر محميًا بكلمة مرور، فسيتم استخدام -srcstorepass لاستعادة الإدخال. إذا لم يتم توفير -srcstorepass أو كان غير صحيح، فسيتم مطالبتك بكلمة مرور. إذا كان نوع إدخال مخزن المفاتيح المصدر غير مدعوم في مخزن المفاتيح الوجهة، أو إذا حدث خطأ أثناء تخزين إدخال في مخزن المفاتيح الوجهة، فسيتم مطالبتك إما بتخطي الإدخال والمتابعة أو الإنهاء. يتم حماية إدخال الوجهة بكلمة مرور إدخال المصدر.

إذا كان الاسم المستعار للوجهة موجودًا بالفعل في مخزن المفاتيح الوجهة، فسيتم مطالبتك إما بالكتابة فوق الإدخال أو بإنشاء إدخال جديد تحت اسم مستعار مختلف.

إذا تم توفير الخيار -noprompt، فلن تتم مطالبتك باسم مستعار وجهة جديد. سيتم الكتابة فوق الإدخالات الموجودة بالاسم المستعار للوجهة. سيتم تخطي الإدخالات التي لا يمكن استيرادها وسيتم عرض تحذير.

الأوامر لإنشاء طلب شهادة

-certreq
الخيارات التالية متاحة للأمر -certreq:
•
{-alias اسم_مستعار}: اسم مستعار للإدخال المراد معالجته
•
{-sigalg خوارزمية}: خوارزمية التوقيع

إذا لم يتم تحديد le، فسيتم قراءة الشهادة أو سلسلة الشهادات من stdin.

يمكن للأمر keytool استيراد شهادات X.509 v1، v2، و v3، وسلاسل شهادات بتنسيق PKCS#7 تتكون من شهادات من هذا النوع. يجب توفير البيانات المراد استيرادها إما بتنسيق ترميز ثنائي أو بتنسيق ترميز قابل للطباعة (يُعرف أيضًا باسم ترميز Base64) كما هو محدد في معيار RFC 1421 الخاص بالإنترنت. في الحالة الأخيرة، يجب أن يحد الترميز في البداية بسلسلة تبدأ بـ -----BEGIN، ويحد في النهاية بسلسلة تبدأ بـ -----END.

تقوم باستيراد شهادة لسببين: لإضافتها إلى قائمة الشهادات الموثوق بها، ولاستيراد رد شهادة تم تلقيه من سلطة شهادات (CA) كنتيجة لتقديم طلب توقيع شهادة (CSR) إلى تلك السلطة. راجع الأمر -certreq في الأوامر لإنشاء طلب شهادة.

يتم تحديد نوع الاستيراد بواسطة قيمة الخيار -alias. إذا لم يشير الاسم المستعار إلى إدخال مفتاح، فيفترض الأمر keytool أنك تضيف شهادة موثوق بها. في هذه الحالة، يجب ألا يكون الاسم المستعار موجودًا بالفعل في مخزن المفاتيح. إذا كان الاسم المستعار موجودًا، فسيقوم الأمر keytool بإخراج خطأ لأن شهادة موثوق بها موجودة بالفعل لهذا الاسم المستعار، ولن يقوم باستيراد الشهادة. إذا كان -alias يشير إلى إدخال مفتاح، فيفترض الأمر keytool أنك تقوم باستيراد رد شهادة.

Use the -certreq command to generate a Certificate Signing Request (CSR) using the PKCS #10 format.

A CSR is intended to be sent to a CA. The CA authenticates the certificate requestor (usually offline) and returns a certificate or certificate chain to replace the existing certificate chain (initially a self-signed certificate) in the keystore.

The private key associated with alias is used to create the PKCS #10 certificate request. To access the private key, the correct password must be provided. If -keypass isn't provided at the command line and is different from the password used to protect the integrity of the keystore, then the user is prompted for it. If -dname is provided, then it is used as the subject in the CSR. Otherwise, the X.500 Distinguished Name associated with alias is used.

The -sigalg value specifies the algorithm that should be used to sign the CSR.

The CSR is stored in the -file file. If a file is not specified, then the CSR is output to -stdout.

Use the -importcert command to import the response from the CA.

إنشاء زوج المفاتيح

قم بإنشاء مخزن مفاتيح ثم قم بإنشاء زوج المفاتيح.

يمكنك إدخال الأمر كسطر واحد مثل التالي:

keytool -genkeypair -dname "cn=myname, ou=mygroup, o=mycompany, c=mycountry" -alias business -keyalg rsa -keypass password -keystore /working/mykeystore -storepass password -validity 180

يقوم الأمر بإنشاء مخزن مفاتيح يسمى mykeystore في الدليل الحالي (بشرط عدم وجوده بالفعل)، ويمنحه كلمة المرور المحددة بواسطة -keypass. يقوم بإنشاء زوج مفاتيح عام/خاص للكيان الذي يحمل الاسم المميز myname، mygroup، mycompany، ورمز بلد من حرفين mycountry. يستخدم خوارزمية إنشاء مفاتيح RSA لإنشاء المفاتيح؛ كلاهما بحجم 2048 بت

يستخدم الأمر خوارزمية التوقيع الافتراضية SHA256withRSA لإنشاء شهادة موقعة ذاتيًا تتضمن المفتاح العام ومعلومات الاسم المميز. الشهادة صالحة لمدة 180 يومًا، وترتبط بالمفتاح الخاص في إدخال مخزن مفاتيح يشار إليه بواسطة -alias business. يتم تعيين كلمة مرور للمفتاح الخاص المحددة بواسطة -keypass.

الأمر أقصر بشكل كبير عندما يتم قبول القيم الافتراضية. في هذه الحالة، يكون -keyalg مطلوبًا فقط، ويتم استخدام القيم الافتراضية للخيارات غير المحددة التي لديها قيم افتراضية. سيتم مطالبتك بأي قيم مطلوبة. يمكنك الحصول على التالي:

keytool -genkeypair -keyalg rsa

في هذه الحالة، يتم إنشاء إدخال مخزن مفاتيح بالاسم المستعار mykey، مع زوج مفاتيح تم إنشاؤه حديثًا وشهادة صالحة لمدة 90 يومًا. يتم وضع هذا الإدخال في دليل المنزل الخاص بك في مخزن مفاتيح يسمى .keystore . .keystore يتم إنشاؤه إذا لم يكن موجودًا بالفعل. سيتم مطالبتك بمعلومات الاسم المميز، مخزن المفاتيح.

كلمة المرور، وكلمة مرور المفتاح الخاص.

ملاحظة:

تفترض الأمثلة المتبقية أنك أجبت على المطالبات بقيم مساوية لتلك المحددة في أمر -genkeypair الأول. على سبيل المثال، اسم مميز cn=myname, ou=mygroup, o=mycompany, c=mycountry).

طلب شهادة موقعة من CA

ملاحظة:

أنشأ إنشاء زوج المفاتيح شهادة موقعة ذاتيًا؛ ومع ذلك، من المرجح أن يثق الآخرون بالشهادة عندما تكون موقعة من CA.

للحصول على توقيع CA، أكمل العملية التالية:

1.
إنشاء طلب توقيع شهادة (CSR):

keytool -certreq -file myname.csr

ينشئ هذا طلب توقيع شهادة (CSR) للكيان المحدد بالاسم المستعار الافتراضي mykey ويضع الطلب في الملف المسمى myname.csr.

2.
تقديم myname.csr إلى CA، مثل DigiCert.

يقوم CA بالمصادقة عليك، مقدم الطلب (عادةً غير متصل بالإنترنت)، ويعيد شهادة، موقعة من قبلهم، تصادق على مفتاحك العام. في بعض الحالات، يعيد CA سلسلة من الشهادات، كل منها يصادق على المفتاح العام لموقع الشهادة السابقة في السلسلة.

استيراد شهادة لـ CA

لاستيراد شهادة لـ CA، أكمل العملية التالية:

1.
قبل استيراد رد الشهادة من CA، تحتاج إلى شهادة واحدة أو أكثر موثوق بها إما في مخزن المفاتيح الخاص بك أو في ملف مخزن المفاتيح cacerts. انظر -importcert في الأوامر.
•
إذا كان رد الشهادة عبارة عن سلسلة شهادات، فستحتاج إلى الشهادة العليا في السلسلة. شهادة CA الجذر التي تصادق على المفتاح العام لـ CA.
•
إذا كان رد الشهادة عبارة عن شهادة واحدة، فستحتاج إلى شهادة لـ CA المصدر (الذي وقعها). إذا لم تكن هذه الشهادة موقعة ذاتيًا، فستحتاج إلى شهادة لموقعها، وهكذا، حتى شهادة CA جذر موقعة ذاتيًا.

يأتي مخزن المفاتيح cacerts مع مجموعة من شهادات الجذر الصادرة عن CAs في برنامج شهادات الجذر لـ Oracle Java [http://www.oracle.com/technetwork/java/javase/javasecarootcertsprogram-1876540.html]. إذا طلبت شهادة موقعة من CA، ولم تتم إضافة شهادة تصادق على المفتاح العام لهذا CA إلى cacerts، فيجب عليك استيراد شهادة من هذا CA كشهادة موثوق بها.

عادةً ما تكون الشهادة من CA موقعة ذاتيًا أو موقعة من قبل CA آخر. إذا كانت موقعة من قبل CA آخر، فستحتاج إلى شهادة تصادق على المفتاح العام لهذا CA.

على سبيل المثال، حصلت على ملف X.cer من شركة هي CA، ومن المفترض أن يكون الملف شهادة موقعة ذاتيًا تصادق على المفتاح العام لهذا CA. قبل استيرادها كشهادة موثوق بها، يجب عليك التأكد من صحة الشهادة عن طريق:

1.
عرضها باستخدام أمر keytool -printcert أو أمر keytool -importcert دون استخدام الخيار -noprompt. تأكد من أن بصمات الشهادة المعروضة تتطابق مع البصمات المتوقعة.
2.
الاتصال بالشخص الذي أرسل الشهادة، ومقارنة البصمات التي تراها مع تلك التي يعرضونها أو التي يعرضها مستودع مفاتيح عام آمن.

فقط عندما تكون البصمات متساوية، يمكن التأكد من أن الشهادة لم يتم استبدالها أثناء النقل بشهادة شخص آخر (مثل شهادة مهاجم). إذا حدث مثل هذا الهجوم، ولم تتحقق من الشهادة قبل استيرادها، فستثق بأي شيء وقعه المهاجم.

2.
استبدل الشهادة الموقعة ذاتيًا بسلسلة شهادات، حيث تصادق كل شهادة في السلسلة على المفتاح العام لموقع الشهادة السابقة في السلسلة، وصولًا إلى CA جذر.

إذا كنت تثق بصحة الشهادة، يمكنك إضافتها إلى مخزن المفاتيح الخاص بك عن طريق إدخال الأمر التالي:

keytool -importcert -alias alias -file *X*.cer`

ينشئ هذا الأمر إدخال شهادة موثوق بها في مخزن المفاتيح من البيانات الموجودة في ملف شهادة CA ويقوم بتعيين القيم المحددة بواسطة alias للإدخال.

استيراد رد الشهادة من CA

بعد استيراد شهادة تصادق على المفتاح العام لـ CA الذي قدمت إليه طلب توقيع شهادتك (أو توجد بالفعل شهادة كهذه في ملف cacerts)، يمكنك استيراد رد الشهادة واستبدال شهادتك الموقعة ذاتيًا بسلسلة شهادات.

سلسلة الشهادات هي واحدة مما يلي:

•
يتم إرجاعها بواسطة CA عندما يكون رد CA عبارة عن سلسلة.
•
يتم إنشاؤها عندما يكون رد CA عبارة عن شهادة واحدة. يتم إنشاء سلسلة الشهادات هذه باستخدام رد الشهادة والشهادات الموثوق بها المتاحة إما في مخزن المفاتيح حيث تقوم باستيراد الرد أو في ملف مخزن المفاتيح cacerts.

على سبيل المثال، إذا أرسلت طلب توقيع شهادتك إلى DigiCert، فيمكنك استيراد ردهم عن طريق إدخال الأمر التالي:

ملاحظة:

في هذا المثال، اسم الشهادة التي تم إرجاعها هو DCmyname.cer.

keytool -importcert -trustcacerts -file DCmyname.cer

تصدير شهادة تصادق على المفتاح العام

ملاحظة:

إذا استخدمت أمر jarsigner لتوقيع ملف أرشيف Java (JAR)، فسيرغب العملاء الذين يستخدمون الملف في المصادقة على توقيعك.

إحدى الطرق التي يمكن للعملاء من خلالها المصادقة عليك هي استيراد شهادة مفتاحك العام إلى مخزن المفاتيح الخاص بهم كإدخال موثوق به. يمكنك بعد ذلك تصدير الشهادة وتقديمها إلى عملائك.

على سبيل المثال:

1.
انسخ شهادتك إلى ملف يسمى myname.cer عن طريق إدخال الأمر التالي:

ملاحظة:

في هذا المثال، الاسم المستعار للإدخال هو mykey.

keytool -exportcert -alias mykey -file myname.cer

2.
باستخدام الشهادة وملف JAR الموقّع، يمكن للعميل استخدام أمر jarsigner للمصادقة على توقيعك.

استيراد مخزن المفاتيح

استخدم أمر importkeystore لاستيراد مخزن مفاتيح كامل إلى مخزن مفاتيح آخر. يستورد هذا جميع الإدخالات من مخزن المفاتيح المصدر، بما في ذلك المفاتيح والشهادات، إلى مخزن المفاتيح الوجهة بأمر واحد. يمكنك استخدام هذا الأمر لاستيراد الإدخالات من نوع مختلف من مخازن المفاتيح. أثناء الاستيراد، ستحصل جميع الإدخالات الجديدة في مخزن المفاتيح الوجهة على نفس أسماء الأسماء المستعارة وكلمات مرور الحماية (للمفاتيح السرية والمفاتيح الخاصة). إذا لم يتمكن أمر keytool من استعادة المفاتيح الخاصة أو المفاتيح السرية من مخزن المفاتيح المصدر، فسيطلب منك كلمة مرور. إذا اكتشف تكرارًا في الأسماء المستعارة، فسيسألك عن اسم مستعار جديد، ويمكنك تحديد اسم مستعار جديد أو ببساطة السماح لأمر keytool بالكتابة فوق الإدخال الموجود.

على سبيل المثال، استيراد إدخالات من مخزن مفاتيح من النوع JKS النموذجي key.jks إلى مخزن مفاتيح يعتمد على الأجهزة من النوع PKCS #11، عن طريق إدخال الأمر التالي:

keytool -importkeystore -srckeystore key.jks -destkeystore NONE -srcstoretype JKS -deststoretype PKCS11 -srcstorepass password -deststorepass password

يمكن أيضًا استخدام أمر importkeystore لاستيراد إدخال واحد من مخزن مفاتيح مصدر إلى مخزن مفاتيح وجهة. في هذه الحالة، بالإضافة إلى الخيارات التي استخدمتها في المثال السابق، تحتاج إلى تحديد الاسم المستعار الذي تريد استيراده. مع تحديد الخيار -srcalias، يمكنك أيضًا تحديد اسم الاسم المستعار للوجهة، وكلمة مرور الحماية لمفتاح سري أو خاص، وكلمة مرور الحماية للوجهة التي تريدها كما يلي:

keytool -importkeystore -srckeystore key.jks -destkeystore NONE -srcstoretype JKS -deststoretype PKCS11 -srcstorepass password -deststorepass password -srcalias myprivatekey -destalias myoldprivatekey -srckeypass password -destkeypass password -noprompt
