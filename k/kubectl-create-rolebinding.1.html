kubectl-create-rolebinding(1)

الحزمة: kubectl

التراخيص: Apache-2.0

KUBERNETES(1)(kubernetes) KUBERNETES(1)(kubernetes)
Eric Paris Jan 2015

الاسم

kubectl create rolebinding - إنشاء ربط دور لدور معين أو دور على مستوى الكتلة

السيناريو

kubectl create rolebinding [OPTIONS]

الوصف

إنشاء ربط دور لدور معين أو دور على مستوى الكتلة.

الخيارات

--allow-missing-template-keys=true إذا كان صحيحًا، تجاهل أي أخطاء في القوالب عندما يكون حقل أو مفتاح خريطة مفقودًا في القالب. ينطبق فقط على تنسيقات الإخراج golang وjsonpath.

--clusterrole="" دور الكتلة الذي يجب أن يشير إليه ربط الدور هذا.

--dry-run="none" يجب أن يكون "none"، "server"، أو "client". إذا كانت استراتيجية العميل، اطبع فقط الكائن الذي سيتم إرساله، دون إرساله. إذا كانت استراتيجية الخادم، قم بتقديم طلب من جانب الخادم دون حفظ المورد.

--field-manager="kubectl-create" اسم المدير المستخدم لتتبع ملكية الحقول.

--group=[] مجموعات للربط بالدور. يمكن تكرار العلم لإضافة مجموعات متعددة.

-o, --output="" تنسيق الإخراج. أحد الخيارات: (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--role="" الدور الذي يجب أن يشير إليه ربط الدور هذا.

--save-config=false إذا كان صحيحًا، سيتم حفظ تكوين الكائن الحالي في تعليقه. بخلاف ذلك، سيظل التعليق دون تغيير. هذا العلم مفيد عندما تريد إجراء kubectl apply على هذا الكائن في المستقبل.

--serviceaccount=[] حسابات الخدمة للربط بالدور، بالتنسيق :. يمكن تكرار العلم لإضافة حسابات خدمة متعددة.

--show-managed-fields=false إذا كان صحيحًا، احتفظ بالحقول المُدارة عند طباعة الكائنات بتنسيق JSON أو YAML.

--template="" سلسلة قالب أو مسار إلى ملف قالب لاستخدامه عند -o=go-template, -o=go-template-file. تنسيق القالب هو قوالب golang [http://golang.org/pkg/text/template/#pkg-overview].

--user=[] أسماء المستخدمين للربط بالدور. يمكن تكرار العلم لإضافة مستخدمين متعددين.

--validate="strict" يجب أن يكون أحد الخيارات: strict (أو true)، warn، ignore (أو false). سيستخدم "true" أو "strict" مخططًا للتحقق من صحة الإدخال ورفض الطلب إذا كان غير صالح. سيقوم بإجراء التحقق من صحة من جانب الخادم إذا تم تمكين ServerSideFieldValidation على api-server، ولكنه سيعود إلى تحقق أقل موثوقية من جانب العميل إذا لم يكن كذلك. ستحذر "warn" بشأن الحقول غير المعروفة أو المكررة دون منع الطلب إذا تم تمكين التحقق من صحة الحقول من جانب الخادم على API server، وسيتصرف كـ "ignore" بخلاف ذلك. "false" أو "ignore" لن تقوم بأي تحقق من صحة المخطط، مع إسقاط أي حقول غير معروفة أو مكررة بصمت.

خيارات موروثة من الأوامر الأصل

--as="" اسم المستخدم لانتحاله للعملية. يمكن أن يكون المستخدم مستخدمًا عاديًا أو حساب خدمة في مساحة اسم.

--as-group=[] المجموعة لانتحالها للعملية، يمكن تكرار هذا العلم لتحديد مجموعات متعددة.

--as-uid="" معرف المستخدم (UID) لانتحاله للعملية.

--cache-dir="/home/username/.kube/cache" دليل ذاكرة التخزين المؤقت الافتراضي

--certificate-authority="" مسار إلى ملف شهادة لسلطة الشهادات

--client-certificate="" مسار إلى ملف شهادة عميل لـ TLS

--client-key="" مسار إلى ملف مفتاح عميل لـ TLS

--cluster="" اسم كتلة kubeconfig للاستخدام

--context="" اسم سياق kubeconfig للاستخدام

--disable-compression=false إذا كان صحيحًا، تخطي ضغط الاستجابة لجميع الطلبات إلى الخادم

--insecure-skip-tls-verify=false إذا كان صحيحًا، فلن يتم التحقق من صلاحية شهادة الخادم. سيؤدي هذا إلى جعل اتصالات HTTPS الخاصة بك غير آمنة

--kubeconfig="" مسار إلى ملف kubeconfig للاستخدام في طلبات CLI.

--kuberc="" مسار إلى ملف kuberc للاستخدام للتفضيلات. يمكن تعطيل هذا عن طريق تصدير بوابة الميزات KUBECTL_KUBERC=false أو إيقاف تشغيل بوابة الميزات KUBERC=off.

--match-server-version=false طلب تطابق إصدار الخادم مع إصدار العميل

-n, --namespace="" إذا تم تقديمه، نطاق مساحة الاسم لهذا الطلب CLI

--password="" كلمة المرور للمصادقة الأساسية مع خادم API

--profile="none" اسم الملف الشخصي المراد التقاطه. أحد الخيارات: (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" اسم الملف المراد كتابة الملف الشخصي إليه

--request-timeout="0" الوقت قبل التخلي عن طلب خادم واحد. يجب أن تحتوي القيم غير الصفرية على وحدة زمنية مقابلة (مثل 1s، 2m، 3h). القيمة صفر تعني عدم انتهاء صلاحية الطلبات.

-s, --server="" عنوان ومنفذ خادم Kubernetes API

--tls-server-name="" اسم الخادم لاستخدامه للتحقق من صحة شهادة الخادم. إذا لم يتم توفيره، يتم استخدام اسم المضيف المستخدم للاتصال بالخادم

--token="" رمز مميز للمصادقة مع خادم API

--username="" اسم المستخدم للمصادقة الأساسية مع خادم API

--version=false يطبع --version، --version=raw معلومات الإصدار ويخرج؛ --version=vX.Y.Z... يضبط الإصدار المبلغ عنه

--warnings-as-errors=false عامل التحذيرات المستلمة من الخادم كأخطاء واخرج برمز خروج غير صفري

مثال

  # إنشاء ربط دور للمستخدم user1، user2، والمجموعة group1 باستخدام دور الكتلة admin
  kubectl create rolebinding admin --clusterrole=admin --user=user1 --user=user2 --group=group1
  # إنشاء ربط دور لحساب الخدمة monitoring:sa-dev باستخدام الدور admin
  kubectl create rolebinding admin-binding --role=admin --serviceaccount=monitoring:sa-dev
