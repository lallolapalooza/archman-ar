kubectl-create-secret-docker-registry(1)

الحزمة: kubectl

التراخيص: Apache-2.0

KUBERNETES(1)(kubernetes) KUBERNETES(1)(kubernetes)
Eric Paris Jan 2015

الاسم

kubectl create secret docker-registry - إنشاء سر لاستخدامه مع سجل Docker

الملخص

kubectl create secret docker-registry [خيارات]

الوصف

إنشاء سر جديد لاستخدامه مع سجلات Docker.

    تُستخدم أسرار Dockercfg للمصادقة مقابل سجلات Docker.
    عند استخدام سطر أوامر Docker لدفع الصور، يمكنك المصادقة مع سجل معين عن طريق تشغيل:
    '$ docker login DOCKER_REGISTRY_SERVER --username=DOCKER_USER --password=DOCKER_PASSWORD --email=DOCKER_EMAIL'.

ينتج عن ذلك ملف ~/.dockercfg يستخدمه أوامر 'docker push' و 'docker pull' اللاحقة للمصادقة مع السجل. عنوان البريد الإلكتروني اختياري.

    عند إنشاء تطبيقات، قد يكون لديك سجل Docker يتطلب المصادقة. لكي تتمكن العقد من سحب الصور نيابة عنك، يجب أن تكون لديها بيانات الاعتماد. يمكنك توفير هذه المعلومات عن طريق إنشاء سر dockercfg وإرفاقه بحساب الخدمة الخاص بك.

الخيارات

--allow-missing-template-keys=true إذا كان صحيحًا، تجاهل أي أخطاء في القوالب عند فقدان حقل أو مفتاح خريطة في القالب. ينطبق فقط على تنسيقات الإخراج golang و jsonpath.

--append-hash=false إلحاق تجزئة للسر باسمه.

--docker-email="" البريد الإلكتروني لسجل Docker

--docker-password="" كلمة المرور للمصادقة مع سجل Docker

--docker-server="https://index.docker.io/v1/" موقع الخادم لسجل Docker

--docker-username="" اسم المستخدم للمصادقة مع سجل Docker

--dry-run="none" يجب أن يكون "none"، "server"، أو "client". إذا كانت الاستراتيجية client، قم فقط بطباعة الكائن الذي سيتم إرساله، دون إرساله. إذا كانت الاستراتيجية server، قم بتقديم طلب من جانب الخادم دون تثبيت المورد.

--field-manager="kubectl-create" اسم المدير المستخدم لتتبع ملكية الحقول.

--from-file=[] يمكن تحديد مفاتيح الملفات باستخدام مسار الملف الخاص بها، وفي هذه الحالة سيتم إعطاؤها اسمًا افتراضيًا هو .dockerconfigjson، أو اختياريًا مع اسم ومسار ملف، وفي هذه الحالة سيتم استخدام الاسم المحدد. تحديد دليل سيؤدي إلى تكرار كل ملف مسمى في الدليل وهو مفتاح سر صالح. بالنسبة لهذا الأمر، يجب أن يكون المفتاح دائمًا .dockerconfigjson.

-o, --output="" تنسيق الإخراج. أحد: (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--save-config=false إذا كان صحيحًا، سيتم حفظ تكوين الكائن الحالي في تعليقه التوضيحي. وإلا، سيبقى التعليق التوضيحي دون تغيير. هذا الخيار مفيد عندما تريد إجراء kubectl apply على هذا الكائن في المستقبل.

--show-managed-fields=false إذا كان صحيحًا، احتفظ بـ managedFields عند طباعة الكائنات بتنسيق JSON أو YAML.

--template="" سلسلة القالب أو مسار ملف القالب للاستخدام عند -o=go-template، -o=go-template-file. تنسيق القالب هو قوالب golang [http://golang.org/pkg/text/template/#pkg-overview].

--validate="strict" يجب أن يكون أحد: strict (أو true)، warn، ignore (أو false). سيستخدم "true" أو "strict" مخططًا للتحقق من صحة الإدخال وفشل الطلب إذا كان غير صالح. سيقوم بإجراء التحقق من الصحة من جانب الخادم إذا تم تمكين ServerSideFieldValidation على api-server، ولكنه سيعود إلى التحقق من الصحة الأقل موثوقية من جانب العميل إذا لم يكن كذلك. ستحذر "warn" من الحقول غير المعروفة أو المكررة دون منع الطلب إذا تم تمكين التحقق من الصحة من جانب الخادم على خادم API، وسيتصرف كـ "ignore" بخلاف ذلك. لن يقوم "false" أو "ignore" بإجراء أي تحقق من المخطط، وسيتم إسقاط أي حقول غير معروفة أو مكررة بصمت.

الخيارات الموروثة من أوامر الأصل

--as="" اسم المستخدم للانتحال للعملية. يمكن أن يكون المستخدم مستخدمًا عاديًا أو حساب خدمة في مساحة اسم.

--as-group=[] المجموعة للانتحال للعملية، يمكن تكرار هذا الخيار لتحديد مجموعات متعددة.

--as-uid="" معرف المستخدم للانتحال للعملية.

--cache-dir="/home/username/.kube/cache" دليل ذاكرة التخزين المؤقت الافتراضي

--certificate-authority="" مسار لملف شهادة للسلطة المصدقة

--client-certificate="" مسار لملف شهادة العميل لـ TLS

--client-key="" مسار لملف مفتاح العميل لـ TLS

--cluster="" اسم كتلة kubeconfig للاستخدام

--context="" اسم سياق kubeconfig للاستخدام

--disable-compression=false إذا كان صحيحًا، تخطي ضغط الاستجابة لجميع الطلبات إلى الخادم

--insecure-skip-tls-verify=false إذا كان صحيحًا، لن يتم التحقق من صحة شهادة الخادم. سيؤدي هذا إلى جعل اتصالات HTTPS الخاصة بك غير آمنة

--kubeconfig="" مسار ملف kubeconfig للاستخدام في طلبات CLI.

--kuberc="" مسار ملف kuberc للاستخدام في التفضيلات. يمكن تعطيل هذا عن طريق تصدير بوابة الميزات KUBECTL_KUBERC=false أو إيقاف الميزة KUBERC=off.

--match-server-version=false تطلب مطابقة إصدار الخادم لإصدار العميل

-n, --namespace="" إذا كان موجودًا، نطاق مساحة الاسم لطلب CLI هذا

--password="" كلمة المرور للمصادقة الأساسية مع خادم API

--profile="none" اسم الملف الشخصي المراد التقاطه. أحد (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" اسم الملف الذي ستتم كتابة الملف الشخصي إليه

--request-timeout="0" الوقت المراد انتظاره قبل التخلي عن طلب خادم واحد. يجب أن تحتوي القيم غير الصفرية على وحدة زمنية مقابلة (مثل 1s، 2m، 3h). القيمة صفر تعني عدم انتهاء صلاحية الطلبات.

-s, --server="" عنوان ومنفذ خادم Kubernetes API

--tls-server-name="" اسم الخادم المراد استخدامه لـ التحقق من صحة شهادة الخادم. إذا لم يتم توفيره، فسيتم استخدام اسم المضيف المستخدم للاتصال بالخادم

--token="" رمز التوثيق (Bearer token) للمصادقة مع خادم API

--user="" اسم مستخدم kubeconfig للاستخدام

--username="" اسم المستخدم للمصادقة الأساسية مع خادم API

--version=false --version، --version=raw تطبع معلومات الإصدار وتخرج؛ --version=vX.Y.Z... يحدد الإصدار المبلغ عنه

--warnings-as-errors=false عامل التحذيرات المستلمة من الخادم كأخطاء والخروج برمز خروج غير صفري

مثال

  # إذا لم يكن لديك بالفعل ملف .dockercfg، فأنشئ سر dockercfg مباشرة
  kubectl create secret docker-registry my-secret --docker-server=DOCKER_REGISTRY_SERVER --docker-username=DOCKER_USER --docker-password=DOCKER_PASSWORD --docker-email=DOCKER_EMAIL
  # إنشاء سر جديد باسم my-secret من ~/.docker/config.json
  kubectl create secret docker-registry my-secret --from-file=path/to/.docker/config.json
