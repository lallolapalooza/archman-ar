kexec_load(2) دليل استدعاءات النظام kexec_load(2)

الاسم

kexec_load, kexec_file_load - تحميل نواة جديدة للتنفيذ لاحقاً

المكتبة

مكتبة C القياسية (libc, -lc)

الملخص

#include <linux/kexec.h>      /* تعريف ثوابت KEXEC_* */
#include <sys/syscall.h>      /* تعريف ثوابت SYS_* */
#include <unistd.h>
long syscall(SYS_kexec_load, unsigned long entry,
             unsigned long nr_segments,
             struct kexec_segment segments[nr_segments],
             unsigned long flags);
long syscall(SYS_kexec_file_load, int kernel_fd, int initrd_fd,
             unsigned long cmdline_len, const char cmdline[cmdline_len],
             unsigned long flags);

ملاحظة: لا توفر glibc أغلفة لاستدعاءات النظام هذه، مما يتطلب استخدام syscall(2).

الوصف

استدعاء النظام kexec_load() يقوم بتحميل نواة جديدة يمكن تنفيذها لاحقاً بواسطة reboot(2).

الوسيط flags هو قناع بت يتحكم في عملية الاستدعاء. يمكن تحديد القيم التالية في flags:

KEXEC_ON_CRASH (منذ Linux 2.6.13)
تنفيذ النواة الجديدة تلقائيًا عند تعطل النظام. يتم تحميل "نواة التعطل" هذه في منطقة ذاكرة محجوزة يتم تحديدها عند بدء التشغيل باستخدام المعلمة crashkernel لسطر أوامر النواة. يتم تصدير موقع هذه الذاكرة المحجوزة إلى مساحة المستخدم عبر الملف /proc/iomem، في إدخال بعنوان "Crash kernel". يمكن لتطبيق مساحة المستخدم تحليل هذا الملف وإعداد قائمة مقاطع (انظر أدناه) تحدد هذه الذاكرة المحجوزة كوجهة. إذا تم تحديد هذه العلامة، يتحقق النواة من أن المقاطع المستهدفة المحددة في segments تقع ضمن المنطقة المحجوزة.
KEXEC_PRESERVE_CONTEXT (منذ Linux 2.6.27)
الحفاظ على حالة الأجهزة والبرامج للنظام قبل تنفيذ النواة الجديدة. يمكن استخدام هذا لتعليق النظام. هذه العلامة متاحة فقط إذا تم تكوين النواة باستخدام CONFIG_KEXEC_JUMP، وتكون فعالة فقط إذا كانت nr_segments أكبر من 0.

تحتوي البتات ذات الترتيب العالي (المقابلة لقناع 0xffff0000) من flags على بنية النواة المراد تنفيذها. قم بتحديد (OR) الثابت KEXEC_ARCH_DEFAULT لاستخدام البنية الحالية، أو أحد ثوابت البنية التالية KEXEC_ARCH_386، KEXEC_ARCH_68K، KEXEC_ARCH_X86_64، KEXEC_ARCH_PPC، KEXEC_ARCH_PPC64، KEXEC_ARCH_IA_64، KEXEC_ARCH_ARM، KEXEC_ARCH_S390، KEXEC_ARCH_SH، KEXEC_ARCH_MIPS، و KEXEC_ARCH_MIPS_LE. يجب أن تكون البنية قابلة للتنفيذ على وحدة المعالجة المركزية للنظام.

الوسيط entry هو عنوان الدخول المادي في صورة النواة. الوسيط nr_segments هو عدد المقاطع التي يشير إليها المؤشر segments؛ تفرض النواة حداً (اعتباطياً) بـ 16 مقطعاً. الوسيط segments هو مصفوفة من هياكل kexec_segment التي تحدد تخطيط النواة:


struct kexec_segment {
    void   *buf;        /* المخزن المؤقت في مساحة المستخدم */
    size_t  bufsz;      /* طول المخزن المؤقت في مساحة المستخدم */
    void   *mem;        /* عنوان مادي للنواة */
    size_t  memsz;      /* طول العنوان المادي */
};

يتم نسخ صورة النواة المحددة بواسطة segments من العملية المتصلة إلى النواة إما في الذاكرة العادية أو في ذاكرة محجوزة (إذا تم تعيين KEXEC_ON_CRASH). تقوم النواة أولاً بإجراء فحوصات صحية مختلفة على المعلومات المقدمة في segments. إذا نجحت هذه الفحوصات، تقوم النواة بنسخ بيانات المقطع إلى ذاكرة النواة. يتم نسخ كل مقطع محدد في segments على النحو التالي:

•
buf و bufsz يحددان منطقة ذاكرة في مساحة العنوان الافتراضي للمتصل وهي مصدر النسخ. قد لا تتجاوز القيمة في bufsz القيمة في الحقل memsz.
•
mem و memsz يحددان نطاق عنوان مادي هو وجهة النسخ. يجب أن تكون القيم المحددة في كلا الحقلين مضاعفات لحجم صفحة النظام.
•
يتم نسخ bufsz بايت من المخزن المؤقت المصدر إلى المخزن المؤقت للنواة الوجهة. إذا كان bufsz أقل من memsz، فسيتم مسح البايتات الزائدة في المخزن المؤقت للنواة.

في حالة kexec عادي (أي، لم يتم تعيين علامة KEXEC_ON_CRASH)، يتم تحميل بيانات المقطع في أي ذاكرة متاحة ويتم نقلها إلى الوجهة النهائية عند إعادة تشغيل kexec (على سبيل المثال، عند تنفيذ أمر kexec(8) بالخيار -e).

في حالة kexec عند الانهيار (أي، تم تعيين علامة KEXEC_ON_CRASH)، يتم تحميل بيانات المقطع في الذاكرة المحجوزة في وقت الاستدعاء، وبعد الانهيار، تقوم آلية kexec ببساطة بتمرير التحكم إلى تلك النواة.

استدعاء النظام kexec_load() متاح فقط إذا تم تكوين النواة باستخدام CONFIG_KEXEC.

kexec_file_load()

استدعاء النظام kexec_file_load() مشابه لـ kexec_load()، ولكنه يأخذ مجموعة مختلفة من الوسائط. يقوم بقراءة النواة المراد تحميلها من الملف الذي يشير إليه واصف الملف kernel_fd، وقرص RAM الأولي (initrd) المراد تحميله من الملف الذي يشير إليه واصف الملف initrd_fd. الوسيط cmdline هو مؤشر إلى مخزن مؤقت يحتوي على سطر الأوامر للنواة الجديدة. الوسيط cmdline_len يحدد حجم المخزن المؤقت. يجب أن يكون البايت الأخير في المخزن المؤقت حرفًا صفريًا ('\0').

الوسيط flags هو قناع بت يعدل سلوك الاستدعاء. يمكن تحديد القيم التالية في flags:

KEXEC_FILE_UNLOAD
إلغاء تحميل النواة المحملة حاليًا.
KEXEC_FILE_ON_CRASH
تحميل النواة الجديدة في منطقة الذاكرة المحجوزة لنواة التعطل (كما هو الحال مع KEXEC_ON_CRASH). يتم تشغيل هذه النواة إذا تعطلت النواة قيد التشغيل حاليًا.
KEXEC_FILE_NO_INITRAMFS
تحميل initrd/initramfs اختياري. حدد هذه العلامة إذا لم يتم تحميل initramfs. إذا تم تعيين هذه العلامة، يتم تجاهل القيمة المقدمة في initrd_fd.

تمت إضافة استدعاء النظام kexec_file_load() لتوفير الدعم للأنظمة التي يجب فيها تقييد تحميل "kexec" على النواة الموقعة فقط. استدعاء النظام هذا متاح فقط إذا تم تكوين النواة باستخدام CONFIG_KEXEC_FILE.

قيمة الإرجاع

عند النجاح، تعيد استدعاءات النظام هذه 0. عند حدوث خطأ، يتم إرجاع -1 ويتم تعيين errno للإشارة إلى الخطأ.

EADDRNOTAVAIL
تم تحديد العلامة KEXEC_ON_CRASH، ولكن المنطقة المحددة بواسطة حقلي mem و memsz لأحد إدخالات segments تقع خارج نطاق الذاكرة المحجوزة لنواة التعطل.
EADDRNOTAVAIL

ERRORS

EACCES
The file referred to by kernel_fd or initrd_fd is not accessible.
EFAULT
An invalid user pointer was specified for an argument.
EINVAL
The value in nr_segments is less than or equal to 0.
EINVAL
The sum of the sizes in the segments array exceeds the value in the corresponding memsz field.
EINVAL
nr_segments exceeds KEXEC_SEGMENT_MAX (16).
EINVAL
Two or more of the kernel target buffers overlap.
EINVAL
The value in cmdline[cmdline_len-1] is not '\0'.
EINVAL
The file referred to by kernel_fd or initrd_fd is empty (length zero).
ENOEXEC
kernel_fd does not refer to an open file, or the kernel can't load this file. Currently, the file must be a bzImage and contain an x86 kernel that is loadable above 4 GiB in memory (see the kernel source file Documentation/x86/boot.txt).
ENOMEM
Could not allocate memory.
EPERM
The caller does not have the CAP_SYS_BOOT capability.
