الحزمة: kube-proxy

التراخيص: Apache-2.0

NAME

kube-proxy - kube-proxy is a network proxy that runs on each node in your cluster.

SYNOPSIS

kube-proxy [OPTIONS]

DESCRIPTION

The kube-proxy component is responsible for implementing the Kubernetes service abstraction. It watches for Service and EndpointSlice objects created through the Kubernetes API server and performs bookkeeping to implement what could be thought of as lightweight network load balancer. On Linux, it typically uses iptables rules to handle traffic redirection. On other operating systems, it may use other mechanisms.

The primary responsibility of kube-proxy is to forward traffic destined for a Service to the correct backend Pod. It supports several modes of operation, including `iptables`, `ipvs`, and `userspace` (deprecated).

When a Service is created, kube-proxy configures the network rules on the node to capture traffic destined for the Service's ClusterIP and port. It then selects a backend Pod associated with the Service (based on EndpointSlices) and forwards the traffic to that Pod's IP address and port.

This ensures that clients can reach Services using a stable ClusterIP, regardless of which Pods are running or where they are located.

OPTIONS

--bind-address="0.0.0.0" Bind the proxy to this IP address, default is 0.0.0.0
--bind-unmatched-headers=false If true, the header matching logic for unmatched requests will be disabled.
--config="" Configuration file or directory, where each file is a valid YAML, JSON or Properties file. See also --write-config-to.
--container-cidr="" If set, this kube-proxy will assume that all pods are in this CIDR. This is used for the userspace mode only.
--debug=false Enable debug logging.
--healthz-bind-address="127.0.0.1:10256" The address to listen on for the healthz server.
--kubeconfig="" --kubeconfig is the path to a kubeconfig file. Required in non-default paths.
--log-dir="" If set, all logs will be written to this directory, with maxsize, maxcount and rotation settings.
--log-file="" If set, all logs will be written to this file. Use the --log-dir option for log rotation.
--log-flush-frequency=5s Maximum number of seconds before log messages are forcibly flushed to disk.
--log-format=text The format of the logs. Valid values are text, json, and gofmt.
--master="" The address of the Kubernetes master for connection to the,'Kubernetes service' A master.Required to be in "http://" or "https://aa:bb" format.If empty, the default discovery will be used.
--masquerade-bit=14 bit manipulation is used for--masquerade traffic.
--metrics-bind-address="0.0.0.0:10249" The address to listen on for the metrics server.
--min-sync-period=0 Minimum duration the client will wait before syncing the list of objects. Applies to all clients of the API server.
--mode=iptables One of: "client", "proxy". Whether this proxy is "client" or "proxy".
--node-ip="" IP address of the node on which kube-proxy is running. If left empty, will be inferred. This parameter is experimental.
--pidfile="" File containing process ID (PID) of kube-proxy. If the file already exists, kube-proxy will not be started. May not be used together with --configure-cni.
--profiling-address="127.0.0.1:6060" The address to listen on for profiling. Use "0.0.0.0" to expose the profiler to the network.
--proxy-mode=iptables The mode which kube-proxy will use to handle traffic. Options: "userspace", "iptables", "ipvs".
--register-node=true Register the node into the cluster if it hasn't been registered yet.
--reporter= "docker-endpoint" Reporter batch dimensions. Options: "docker-endpoint", "container-managed-object", "k8s-pod".
--services-per-update=100 How many services can be updated simultaneously per DaemonSet or Deployment update.
--show-hidden-metrics=false If true, all hidden metrics will be shown.
--show-hidden-metrics-for-version="" The previous version for which you want to show hidden metrics. Only the previous minor version is meaningful, other values will not be allowed. The format is ., e.g.: '1.16'. The purpose of this format is make sure you have the opportunity to notice if the next release hides additional metrics, rather than being surprised when they are permanently removed in the release after that. This parameter is ignored if a config file is specified by --config.
--storage_driver_buffer_duration=1m0s Writes in the storage driver will be buffered for this duration, and committed to the non memory backends as a single transaction
--storage_driver_db="cadvisor" database name
--storage_driver_host="localhost:8086" database host:port
--storage_driver_password="root" database password
--storage_driver_secure=false use secure connection with database
--storage_driver_table="stats" table name
--storage_driver_user="root" database username
--update_machine_info_interval=5m0s Interval between machine info updates.
-v, --v=0 number for the log level verbosity
--version=false --version, --version=raw prints version information and quits; --version=vX.Y.Z... sets the reported version
--vmodule= comma-separated list of pattern=N settings for file-filtered logging (only works for text log format)
--write-config-to="" If set, write the default configuration values to this file and exit.
