kubectl-kustomize(1)

الحزمة: kubectl

التراخيص: Apache-2.0

KUBERNETES(1)(kubernetes) KUBERNETES(1)(kubernetes)
Eric Paris Jan 2015

الاسم

kubectl kustomize - بناء هدف kustomization من دليل أو عنوان URL

الملخص

kubectl kustomize [خيارات]

الوصف

بناء مجموعة من موارد KRM باستخدام ملف 'kustomization.yaml'. يجب أن يكون الوسيط DIR مسارًا إلى دليل يحتوي على 'kustomization.yaml'، أو عنوان URL لمستودع git مع لاحقة مسار تحدد نفس الشيء بالنسبة لجذر المستودع. إذا تم حذف DIR، فسيتم افتراض '.'.

الخيارات

--as-current-user=false - استخدام معرف المستخدم ومعرف المجموعة لمُنفذ الأمر لتشغيل الوظيفة في الحاوية

--enable-alpha-plugins=false - تمكين إضافات kustomize

--enable-helm=false - تمكين استخدام مولد استنفاد مخطط Helm.

--enable-managedby-label=false - تمكين إضافة app.kubernetes.io/managed-by

-e, --env=[] - قائمة بمتغيرات البيئة التي سيتم استخدامها بواسطة الوظائف

--helm-api-versions=[] - إصدارات واجهة برمجة تطبيقات Kubernetes التي يستخدمها Helm لـ Capabilities.APIVersions

--helm-command="helm" - أمر Helm (مسار الملف التنفيذي)

--helm-debug=false - تمكين إخراج التصحيح من مولد استنفاد مخطط Helm.

--helm-kube-version="" - إصدار Kubernetes الذي يستخدمه Helm لـ Capabilities.KubeVersion

--load-restrictor="LoadRestrictionsRootOnly" - إذا تم تعيينه على 'LoadRestrictionsNone'، يجوز لـ kustomizations المحلية تحميل ملفات من خارج جذرها. ومع ذلك، هذا يكسر قابلية نقل kustomization.

--mount=[] - قائمة بخيارات التخزين المقروءة من نظام الملفات

--network=false - تمكين الوصول إلى الشبكة للوظائف التي تعلن عن ذلك

--network-name="bridge" - شبكة docker لتشغيل الحاوية فيها

-o, --output="" - إذا تم تحديده، اكتب الإخراج إلى هذا المسار.

--reorder="legacy" - إعادة ترتيب الموارد قبل الإخراج مباشرة. استخدم 'legacy' لتطبيق إعادة ترتيب قديمة (مساحات الأسماء أولاً، Webhooks أخيرًا، إلخ). استخدم 'none' لقمع إعادة ترتيب نهائية.

خيارات موروثة من الأوامر الأصل

--as="" - اسم المستخدم للانتحال للعملية. يمكن أن يكون المستخدم مستخدمًا عاديًا أو حساب خدمة في مساحة أسماء.

--as-group=[] - المجموعة للانتحال للعملية، يمكن تكرار هذا العلم لتحديد مجموعات متعددة.

--as-uid="" - معرف المستخدم للانتحال للعملية.

--cache-dir="/home/username/.kube/cache" - دليل ذاكرة التخزين المؤقت الافتراضي

--certificate-authority="" - مسار ملف شهادة السلطة

--client-certificate="" - مسار ملف شهادة العميل لـ TLS

--client-key="" - مسار ملف مفتاح العميل لـ TLS

--cluster="" - اسم مجموعة kubeconfig المراد استخدامها

--context="" - اسم سياق kubeconfig المراد استخدامه

--disable-compression=false - إذا كان صحيحًا، فلا تستجب لضغط الاستجابة لجميع الطلبات إلى الخادم

--insecure-skip-tls-verify=false - إذا كان صحيحًا، فلن يتم التحقق من صحة شهادة الخادم. سيؤدي هذا إلى جعل اتصالات HTTPS الخاصة بك غير آمنة

--kubeconfig="" - مسار ملف kubeconfig المراد استخدامه لطلبات CLI.

--kuberc="" - مسار ملف kuberc المراد استخدامه للتفضيلات. يمكن تعطيل هذا عن طريق تصدير بوابة الميزات KUBECTL_KUBERC=false أو إيقاف الميزة KUBERC=off.

--match-server-version=false - يتطلب تطابق إصدار الخادم مع إصدار العميل

-n, --namespace="" - إذا كان موجودًا، نطاق مساحة الأسماء لطلب CLI هذا

--password="" - كلمة المرور للمصادقة الأساسية لخادم API

--profile="none" - اسم الملف الشخصي المراد التقاطه. أحد (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" - اسم الملف الذي سيتم كتابة الملف الشخصي إليه

--request-timeout="0" - المدة الزمنية للانتظار قبل الاستسلام لطلب خادم واحد. يجب أن تحتوي القيم غير الصفرية على وحدة زمنية مقابلة (مثل 1s، 2m، 3h). تعني القيمة صفر عدم انتهاء الطلبات.

-s, --server="" - عنوان ومنفذ خادم واجهة برمجة تطبيقات Kubernetes

--tls-server-name="" - اسم الخادم المراد استخدامه للتحقق من صحة شهادة الخادم. إذا لم يتم توفيره، يتم استخدام اسم المضيف المستخدم للاتصال بالخادم

--token="" - رمز Bearer للمصادقة لخادم API

--user="" - اسم مستخدم kubeconfig المراد استخدامه

--username="" - اسم المستخدم للمصادقة الأساسية لخادم API

--version=false - --version، --version=raw يطبع معلومات الإصدار ويخرج؛ --version=vX.Y.Z... يحدد الإصدار المبلغ عنه

--warnings-as-errors=false - تعامل مع التحذيرات المستلمة من الخادم كأخطاء واخرج برمز خروج غير صفر.

مثال

  # بناء الدليل الحالي
  kubectl kustomize
  # بناء دليل تكوين مشترك
  kubectl kustomize /home/config/production
  # البناء من github
  kubectl kustomize https://github.com/kubernetes-sigs/kustomize.git/examples/helloWorld?ref=v1.0.6
