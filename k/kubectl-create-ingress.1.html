kubectl-create-ingress(1)

الحزمة: kubectl

التراخيص: Apache-2.0

KUBERNETES(1)(kubernetes) KUBERNETES(1)(kubernetes)
Eric Paris Jan 2015

الاسم

kubectl create ingress - إنشاء مدخل بالاسم المحدد

الملخص

kubectl create ingress [خيارات]

الوصف

إنشاء مدخل بالاسم المحدد.

الخيارات

--allow-missing-template-keys=true إذا كان صحيحًا، تجاهل أي أخطاء في القوالب عندما يكون الحقل أو مفتاح الخريطة مفقودًا في القالب. ينطبق فقط على تنسيقات الإخراج golang و jsonpath.

--annotation=[] تعليق توضيحي لإدراجه في كائن المدخل، بالتنسيق annotation=value

--class="" فئة المدخل المراد استخدامها

--default-backend="" الخدمة الافتراضية للواجهة الخلفية، بالتنسيق svcname:port

--dry-run="none" يجب أن يكون "none" أو "server" أو "client". إذا كانت استراتيجية العميل، قم بطباعة الكائن الذي سيتم إرساله فقط، دون إرساله. إذا كانت استراتيجية الخادم، قم بإرسال طلب من جانب الخادم دون تثبيت المورد.

--field-manager="kubectl-create" اسم المدير المستخدم لتتبع ملكية الحقول.

-o, --output="" تنسيق الإخراج. واحد من: (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--rule=[] قاعدة بالتنسيق host/path=service:port[,tls=secretname]. تعتبر المسارات التي تحتوي على الحرف البادئ '*' بأنها pathType=Prefix. الوسيطة tls اختيارية.

--save-config=false إذا كان صحيحًا، سيتم حفظ تكوين الكائن الحالي في تعليقه التوضيحي. بخلاف ذلك، سيبقى التعليق التوضيحي دون تغيير. هذا العلم مفيد عندما تريد إجراء kubectl apply على هذا الكائن في المستقبل.

--show-managed-fields=false إذا كان صحيحًا، احتفظ بـ managedFields عند طباعة الكائنات بتنسيق JSON أو YAML.

--template="" سلسلة قالب أو مسار إلى ملف قالب لاستخدامه عند -o=go-template، -o=go-template-file. تنسيق القالب هو قوالب golang [http://golang.org/pkg/text/template/#pkg-overview].

--validate="strict" يجب أن يكون واحدًا من: strict (أو true)، warn، ignore (أو false). سيستخدم "true" أو "strict" مخططًا للتحقق من صحة الإدخال وفشل الطلب إذا كان غير صالح. سيقوم بإجراء التحقق من صحة جانب الخادم إذا تم تمكين ServerSideFieldValidation على api-server، ولكنه سيعود إلى التحقق الأقل موثوقية من جانب العميل إذا لم يتم تمكينه. سيحذر "warn" بشأن الحقول غير المعروفة أو المكررة دون منع الطلب إذا تم تمكين التحقق من صحة الحقول من جانب الخادم على خادم API، وسيتصرف مثل "ignore" بخلاف ذلك. لن يقوم "false" أو "ignore" بإجراء أي تحقق من صحة المخطط، وسيتم إسقاط أي حقول غير معروفة أو مكررة بصمت.

الخيارات الموروثة من الأوامر الأصل

--as="" اسم المستخدم للانتحال للعملية. يمكن أن يكون المستخدم مستخدمًا عاديًا أو حساب خدمة في نطاق.

--as-group=[] المجموعة للانتحال للعملية، يمكن تكرار هذا العلم لتحديد مجموعات متعددة.

--as-uid="" معرف المستخدم (UID) للانتحال للعملية.

--cache-dir="/home/username/.kube/cache" دليل الذاكرة المؤقتة الافتراضي

--certificate-authority="" مسار إلى ملف شهادة للسلطة المصدقة

--client-certificate="" مسار إلى ملف شهادة عميل لـ TLS

--client-key="" مسار إلى ملف مفتاح عميل لـ TLS

--cluster="" اسم الكتلة kubeconfig المراد استخدامها

--context="" اسم السياق kubeconfig المراد استخدامه

--disable-compression=false إذا كان صحيحًا، قم بالانسحاب من ضغط الاستجابة لجميع الطلبات إلى الخادم

--insecure-skip-tls-verify=false إذا كان صحيحًا، لن يتم التحقق من صحة شهادة الخادم. سيؤدي هذا إلى جعل اتصالات HTTPS الخاصة بك غير آمنة

--kubeconfig="" مسار إلى ملف kubeconfig المراد استخدامه لطلبات CLI.

--kuberc="" مسار إلى ملف kuberc المراد استخدامه للتفضيلات. يمكن تعطيل هذا عن طريق تصدير KUBECTL_KUBERC=false أو إيقاف تشغيل بوابة الميزة KUBERC=off.

--match-server-version=false طلب تطابق إصدار الخادم مع إصدار العميل

-n, --namespace="" إذا كان موجودًا، نطاق المساحة لطلب CLI هذا

--password="" كلمة المرور للمصادقة الأساسية على خادم API

--profile="none" اسم الملف الشخصي المراد التقاطه. واحد من (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" اسم الملف الذي سيتم كتابة الملف الشخصي إليه

--request-timeout="0" طول الوقت للانتظار قبل التخلي عن طلب خادم واحد. يجب أن تحتوي القيم غير الصفرية على وحدة زمنية مقابلة (مثل 1s، 2m، 3h). تعني القيمة صفر عدم انتهاء صلاحية الطلبات.

-s, --server="" عنوان ومنفذ خادم Kubernetes API

--tls-server-name="" اسم الخادم المراد استخدامه للتحقق من صحة شهادة الخادم. إذا لم يتم توفيره، يتم استخدام اسم المضيف المستخدم للاتصال بالخادم

--token="" رمز الدب (Bearer token) للمصادقة على خادم API

--user="" اسم مستخدم kubeconfig المراد استخدامه

--username="" اسم المستخدم للمصادقة الأساسية على خادم API

--version=false --version، --version=raw يطبع معلومات الإصدار ويخرج؛ --version=vX.Y.Z... يحدد الإصدار المبلغ عنه

--warnings-as-errors=false معاملة التحذيرات المستلمة من الخادم كأخطاء والخروج برمز خروج غير صفري

مثال

  # إنشاء مدخل واحد باسم 'simple' يوجه الطلبات إلى foo.com/bar إلى svc
  # svc1:8080 مع سر شهادة TLS "my-cert"
  kubectl create ingress simple --rule="foo.com/bar=svc1:8080,tls=my-cert"
  # إنشاء مدخل شامل للمسار "/path" يشير إلى الخدمة svc:port وفئة المدخل "otheringress"
  kubectl create ingress catch-all --class=otheringress --rule="/path=svc:port"
  # إنشاء مدخل مع تعليقين توضيحين: ingress.annotation1 و ingress.annotations2
  kubectl create ingress annotated --class=default --rule="foo.com/bar=svc:port" \
  --annotation ingress.annotation1=foo \
  --annotation ingress.annotation2=bla
  # إنشاء مدخل بنفس المضيف ومسارات متعددة
  kubectl create ingress multipath --class=default \
  --rule="foo.com/=svc:port" \
  --rule="foo.com/admin/=svcadmin:portadmin"
  # إنشاء مدخل بمضيفات متعددة ونوع المسار Prefix
  kubectl create ingress ingress1 --class=default \
  --rule="foo.com/path*=svc:8080" \
  --rule="bar.com/admin*=svc2:http"
  # إنشاء مدخل مع تمكين TLS باستخدام شهادة المدخل الافتراضية وأنواع مسارات مختلفة
  kubectl create ingress ingtls --class=default \
  --rule="foo.com/=svc:https,tls" \
  --rule="foo.com/path/subpath*=othersvc:8080"
  # إنشاء مدخل مع تمكين TLS باستخدام سر محدد ونوع المسار Prefix
  kubectl create ingress ingsecret --class=default \
  --rule="foo.com/*=svc:8080,tls=secret1"
  # إنشاء مدخل بواجهة خلفية افتراضية
  kubectl create ingress ingdefault --class=default \
  --default-backend=defaultsvc:http \
  --rule="foo.com/*=svc:8080,tls=secret1"
