kubectl-wait(1)

الحزمة: kubectl

التراخيص: Apache-2.0

KUBERNETES(1)(kubernetes) KUBERNETES(1)(kubernetes)
إريك باريس يناير 2015

الاسم

kubectl wait - تجريبي: انتظر شرطًا محددًا على مورد واحد أو أكثر

الملخص

kubectl wait [خيارات]

الوصف

تجريبي: انتظر شرطًا محددًا على مورد واحد أو أكثر.

يأخذ الأمر موارد متعددة وينتظر حتى يتم رؤية الشرط المحدد في حقل الحالة لكل مورد معين.

بدلاً من ذلك، يمكن للأمر الانتظار حتى يتم إنشاء أو حذف مجموعة الموارد المعطاة عن طريق توفير الكلمة المفتاحية "create" أو "delete" كقيمة للعلامة --for.

سيتم طباعة رسالة نجاح على المخرج القياسي تشير إلى وقت تلبية الشرط المحدد. يمكنك استخدام خيار -o لتغيير وجهة المخرج.

الخيارات

--all=false حدد جميع الموارد في مساحة الاسم لأنواع الموارد المحددة

-A, --all-namespaces=false إذا كانت موجودة، قم بإدراج الكائن (الكائنات) المطلوبة عبر جميع مساحات الأسماء. يتم تجاهل مساحة الاسم في السياق الحالي حتى لو تم تحديدها باستخدام --namespace.

--allow-missing-template-keys=true إذا كانت صحيحة، تجاهل أي أخطاء في القوالب عند وجود حقل أو مفتاح خريطة مفقود في القالب. ينطبق فقط على تنسيقات المخرج go-template و jsonpath.

--field-selector="" محدد (استعلام حقل) للتصفية، يدعم '=', '==', و '!='.(مثال: --field-selector key1=value1,key2=value2). يدعم الخادم عددًا محدودًا من استعلامات الحقول لكل نوع.

-f, --filename=[] تحديد المورد.

--for="" الشرط الذي سيتم الانتظار عليه: [create|delete|condition=condition-name[=condition-value]|jsonpath='{JSONPath expression}'=[JSONPath value]]. القيمة الشرطية الافتراضية هي true. تتم مقارنة قيم الشروط بعد طي الحالة البسيط لليونيكود، وهو شكل أكثر عمومية من عدم الحساسية لحالة الأحرف.

--local=false إذا كانت صحيحة، فلن يتصل التعليق التوضيحي بخادم api بل سيعمل محليًا.

-o, --output="" تنسيق المخرج. أحد الخيارات التالية: (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

-R, --recursive=true معالجة الدليل المستخدم في -f، --filename بشكل تكراري. مفيد عندما تريد إدارة المصادر ذات الصلة المنظمة داخل نفس الدليل.

-l, --selector="" محدد (استعلام تسمية) للتصفية، يدعم '=', '==', و '!='.(مثال: -l key1=value1,key2=value2)

--show-managed-fields=false إذا كانت صحيحة، احتفظ بحقول managedFields عند طباعة الكائنات بتنسيق JSON أو YAML.

--template="" سلسلة قالب أو مسار إلى ملف قالب لاستخدامه عند -o=go-template، -o=go-template-file. تنسيق القالب هو قوالب golang [http://golang.org/pkg/text/template/#pkg-overview].

--timeout=30s طول الوقت للانتظار قبل الاستسلام. صفر يعني التحقق مرة واحدة وعدم الانتظار، سالب يعني الانتظار لمدة أسبوع.

خيارات موروثة من أوامر أصلية

--as="" اسم مستخدم لانتحال الشخصية للعملية. يمكن أن يكون المستخدم مستخدمًا عاديًا أو حساب خدمة في مساحة أسماء.

--as-group=[] مجموعة لانتحال الشخصية للعملية، يمكن تكرار هذه العلامة لتحديد مجموعات متعددة.

--as-uid="" معرف مستخدم (UID) لانتحال الشخصية للعملية.

--cache-dir="/home/username/.kube/cache" دليل التخزين المؤقت الافتراضي

--certificate-authority="" مسار إلى ملف شهادة للسلطة المصدقة

--client-certificate="" مسار إلى ملف شهادة عميل لـ TLS

--client-key="" مسار إلى ملف مفتاح عميل لـ TLS

--cluster="" اسم مجموعة kubeconfig للاستخدام

--context="" اسم سياق kubeconfig للاستخدام

--disable-compression=false إذا كانت صحيحة، قم بالخروج من ضغط الاستجابة لجميع الطلبات إلى الخادم

--insecure-skip-tls-verify=false إذا كانت صحيحة، فلن يتم التحقق من صحة شهادة الخادم. سيؤدي هذا إلى جعل اتصالات HTTPS الخاصة بك غير آمنة

--kubeconfig="" مسار إلى ملف kubeconfig للاستخدام في طلبات CLI.

--kuberc="" مسار إلى ملف kuberc للاستخدام في التفضيلات. يمكن تعطيل هذا عن طريق تصدير KUBECTL_KUBERC=false بوابة الميزات أو إيقاف تشغيل الميزة KUBERC=off.

--match-server-version=false طلب تطابق إصدار الخادم مع إصدار العميل

-n, --namespace="" إذا كانت موجودة، نطاق مساحة الاسم لطلب CLI هذا

--password="" كلمة مرور للمصادقة الأساسية إلى خادم API

--profile="none" اسم الملف التعريفي المراد التقاطه. أحد الخيارات: (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" اسم الملف لكتابة الملف التعريفي إليه

--request-timeout="0" طول الوقت للانتظار قبل الاستسلام لطلب خادم واحد. يجب أن تحتوي القيم غير الصفرية على وحدة زمنية مقابلة (على سبيل المثال، 1s، 2m، 3h). تعني القيمة صفر عدم انتهاء مهلة الطلبات.

-s, --server="" عنوان ومنفذ خادم Kubernetes API

--tls-server-name="" اسم الخادم المستخدم لـ التحقق من صحة شهادة الخادم. إذا لم يتم توفيره، فسيتم استخدام اسم المضيف المستخدم للاتصال بالخادم

--token="" رمز مميز للمصادقة إلى خادم API

--user="" اسم مستخدم kubeconfig للاستخدام

--username="" اسم مستخدم للمصادقة الأساسية إلى خادم API

--version=false --version، --version=raw تطبع معلومات الإصدار وتخرج؛ --version=vX.Y.Z... تحدد الإصدار المبلغ عنه

--warnings-as-errors=false عامل التحذيرات المستلمة من الخادم كأخطاء واخرج برمز خروج غير صفري

مثال

  # انتظر حتى يحتوي البود "busybox1" على شرط الحالة من النوع "Ready"
  kubectl wait --for=condition=Ready pod/busybox1
  # القيمة الافتراضية لحالة الشرط هي true؛ يمكنك الانتظار لأهداف أخرى بعد فاصل يساوي (مقارنة بعد طي الحالة البسيط لليونيكود، وهو شكل أكثر عمومية من عدم الحساسية لحالة الأحرف)
  kubectl wait --for=condition=Ready=false pod/busybox1
  # انتظر حتى يحتوي البود "busybox1" على مرحلة الحالة "Running"
  kubectl wait --for=jsonpath='{.status.phase}'=Running pod/busybox1
  # انتظر حتى يكون البود "busybox1" جاهزًا
  kubectl wait --for='jsonpath={.status.conditions[?(@.type=="Ready")].status}=True' pod/busybox1
  # انتظر حتى يكون لدى الخدمة "loadbalancer" مدخل (ingress)
  kubectl wait --for=jsonpath='{.status.loadBalancer.ingress}' service/loadbalancer
  # انتظر حتى يتم إنشاء السر "busybox1"، مع مهلة 30 ثانية
  kubectl create secret generic busybox1
  kubectl wait --for=create secret/busybox1 --timeout=30s
  # انتظر حتى يتم حذف البود "busybox1"، مع مهلة 60 ثانية، بعد إصدار أمر "delete"
  kubectl delete pod/busybox1
  kubectl wait --for=delete pod/busybox1 --timeout=60s

الاسم

kubectl - أداة سطر أوامر للتواصل مع مجموعات Kubernetes.

الملخص

kubectl [command] [type] [resource] [flags]

الوصف

kubectl هو أداة سطر أوامر عالمية تسمح لك بتشغيل أوامر على مجموعات Kubernetes. إنها الأداة الأساسية لإدارة مجموعات Kubernetes.

باستخدام kubectl، يمكنك:

  • نشر التطبيقات
  • فحص وتعديل وإزالة الموارد الموجودة
  • عرض سجلات الموارد
  • إرسال أوامر إلى وحدات التحكم (Pods)
  • إدارة موارد Kubernetes مثل النشر (Deployments)، والخدمات (Services)، والحجرات (Pods)، إلخ.

يقوم kubectl بالاتصال بـ API Server الخاص بـ Kubernetes. يمكنك تكوين kubectl لاستخدام ملفات تكوين متعددة.

الخيارات

هذه بعض الخيارات الشائعة لـ kubectl:

--namespace <namespace> أو -n <namespace>
حدد مساحة الاسم التي يجب تنفيذ العملية فيها.
--context <context>
حدد السياق الذي يجب استخدامه لتوجيه الأوامر.
--kubeconfig <file>
حدد ملف kubeconfig بدلاً من استخدام الملف الافتراضي.
-o <format> أو --output <format>
حدد تنسيق الإخراج (مثل json، yaml، wide، custom-columns).
--help
عرض مساعدة شاملة للأمر.

خيارات موروثة من أوامر الآباء

kubectl يرث العديد من الخيارات من الأوامر الأصلية. يمكن استخدام هذه الخيارات مع معظم أوامر kubectl.

--v <level>
مستوى تسجيل مفصل. يستخدم للمساعدة في استكشاف الأخطاء وإصلاحها.

مثال

لعرض جميع الحجرات (Pods) في مساحة الاسم الافتراضية:

kubectl get pods

لإنشاء تطبيق من ملف YAML:

kubectl apply -f my-app.yaml

لعرض تفاصيل حجرة معينة:

kubectl describe pod my-pod
