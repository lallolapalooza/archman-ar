موقع مخزن المفاتيح.

إذا تم استخدام storetype JKS ولم يكن ملف مخزن المفاتيح موجودًا بعد، فيمكن أن تؤدي بعض أوامر keytool إلى إنشاء ملف مخزن مفاتيح جديد. على سبيل المثال، إذا تم استدعاء keytool -genkeypair ولم يتم تحديد الخيار -keystore، فسيتم إنشاء ملف مخزن المفاتيح الافتراضي المسمى .keystore في الدليل الرئيسي للمستخدم عند عدم وجوده بالفعل. وبالمثل، إذا تم تحديد الخيار -keystore ks_file ولكن لم يكن ks_file موجودًا، فسيتم إنشاؤه. لمزيد من المعلومات حول storetype JKS، راجع قسم KeyStore Implementation في KeyStore aliases.

لاحظ أن تيار الإدخال من الخيار -keystore يتم تمريره إلى طريقة KeyStore.load. إذا تم تحديد NONE كعنوان URL، فسيتم تمرير تيار فارغ إلى طريقة KeyStore.load. يجب تحديد NONE إذا لم يكن مخزن المفاتيح قائمًا على الملف. على سبيل المثال، عند تخزينه على جهاز رمز مميز مادي.

-storepass[:env| :file] argument

كلمة المرور المستخدمة لحماية سلامة مخزن المفاتيح.

إذا لم يتم تحديد المعدّل env أو file، فإن كلمة المرور تحتوي على الوسيط value، والذي يجب أن يكون طوله 6 أحرف على الأقل. بخلاف ذلك، يتم استرداد كلمة المرور على النحو التالي:

•
env: استرداد كلمة المرور من متغير البيئة المسمى argument.
•
file: استرداد كلمة المرور من الملف المسمى argument.

ملاحظة: تقبل جميع الخيارات الأخرى التي تتطلب كلمات مرور، مثل -keypass و -srckeypass و -destkeypass و -srcstorepass و -deststorepass، المعدّلات env و file. تذكر فصل خيار كلمة المرور والمعدّل بنقطتين رأسيتين (:).

يجب تقديم كلمة المرور لجميع الأوامر التي تصل إلى محتويات مخزن المفاتيح. بالنسبة لهذه الأوامر، عندما لا يتم توفير الخيار -storepass في سطر الأوامر، يتم سؤال المستخدم عنها.

عند استرداد المعلومات من مخزن المفاتيح، تكون كلمة المرور اختيارية. إذا لم يتم تحديد كلمة مرور، فلا يمكن التحقق من سلامة المعلومات المستردة وسيتم عرض تحذير.

-providerName provider_name

يستخدم لتحديد اسم موفر خدمة التشفير عند سرده في ملف خصائص الأمان.
-providerClass provider_class_name

يستخدم لتحديد اسم ملف الفئة الرئيسية لموفر خدمة التشفير عندما لا يكون موفر الخدمة مدرجًا في ملف خصائص الأمان.
-providerArg provider_arg

يستخدم مع الخيار -providerClass لتمثيل وسيط إدخال سلسلة اختياري للمنشئ لـ provider_class_name.
-protected

إما true أو false. يجب تحديد هذه القيمة على أنها true عندما يجب تحديد كلمة المرور من خلال مسار مصادقة محمي مثل قارئ PIN مخصص. نظرًا لوجود مخزني مفاتيح متضمنين في الأمر -importkeystore، يتم توفير الخيارين التاليين -srcprotected و -destprotected لمخزن المفاتيح المصدر ومخزن المفاتيح الوجهة على التوالي.
-ext {name{:critical} {=value}}

يشير إلى امتداد شهادة X.509. يمكن استخدام الخيار في -genkeypair و -gencert لتضمين الامتدادات في الشهادة التي تم إنشاؤها، أو في -certreq لإظهار الامتدادات المطلوبة في طلب الشهادة. يمكن أن يظهر الخيار عدة مرات. يمكن أن يكون الوسيط name اسم امتداد مدعوم (انظر Named Extensions) أو رقم OID عشوائي. الوسيط value، عند توفيره، يشير إلى الوسيط للامتداد. عند حذف value، فهذا يعني أن القيمة الافتراضية للامتداد أو أن الامتداد لا يتطلب وسيطًا. المعدّل :critical، عند توفيره، يعني أن السمة isCritical للامتداد هي true؛ وإلا، فهي false. يمكنك استخدام :c بدلاً من :critical.

NAMED EXTENSIONS

يدعم أمر keytool هذه الامتدادات المسماة. الأسماء غير حساسة لحالة الأحرف).

BC أو BasicContraints
القيم: الشكل الكامل هو: ca:{true|false}[,pathlen:<len>] أو <len>، وهو اختصار لـ ca:true,pathlen:<len>. عند حذف <len>، يكون لديك ca:true.
KU أو KeyUsage
القيم: usage(,usage)*، حيث يمكن أن يكون usage أحد الخيارات التالية: digitalSignature، nonRepudiation (contentCommitment)، keyEncipherment، dataEncipherment، keyAgreement، keyCertSign، cRLSign، encipherOnly، decipherOnly. يمكن اختصار الوسيط usage بالأحرف القليلة الأولى (dig لـ digitalSignature) أو بأسلوب camel-case (dS لـ digitalSignature أو cRLS لـ cRLSign)، طالما لم يتم العثور على لبس. قيم usage حساسة لحالة الأحرف.
EKU أو ExtendedKeyUsage
القيم: usage(,usage)*، حيث يمكن أن يكون usage أحد الخيارات التالية: anyExtendedKeyUsage، serverAuth، clientAuth، codeSigning، emailProtection، timeStamping، OCSPSigning، أو أي OID string. يمكن اختصار الوسيط usage بالأحرف القليلة الأولى أو بأسلوب camel-case، طالما لم يتم العثور على لبس. قيم usage حساسة لحالة الأحرف.
SAN أو SubjectAlternativeName
القيم: type:value(,type:value)*، حيث يمكن أن يكون type هو EMAIL، URI، DNS، IP، أو OID. الوسيط value هو قيمة التنسيق النصي لـ type.
IAN أو IssuerAlternativeName
القيم: نفس قيم SubjectAlternativeName.
SIA أو SubjectInfoAccess
القيم: method:location-type:location-value (,method:location-type:location-value)*، حيث يمكن أن يكون method هو timeStamping، caRepository أو أي OID. يمكن أن تكون وسائط location-type و location-value أي type:value مدعومة من امتداد SubjectAlternativeName.
AIA أو AuthorityInfoAccess
القيم: نفس قيم SubjectInfoAccess. يمكن أن يكون الوسيط method هو ocsp، caIssuers، أو أي OID.

عندما يكون name هو OID، تكون القيمة هي ترميز DER المشفر سداسي عشري لـ extnValue للامتداد باستثناء النوع والطول للأجزاء الثنائية. يتم تجاهل أي حرف إضافي بخلاف الأرقام السداسية العشرية القياسية (0-9، a-f، A-F) في السلسلة HEX. لذلك، يتم قبول كل من 01:02:03:04 و 01020304 كقيم متطابقة. عندما لا توجد قيمة، يكون للامتداد حقل قيمة فارغ.

اسم خاص honored، يستخدم في -gencert فقط، يشير إلى كيفية تلبية الامتدادات المتضمنة في طلب الشهادة. القيمة لهذا الاسم هي قائمة مفصولة بفواصل تتكون من all (يتم تلبية جميع الامتدادات المطلوبة)، name{:[critical|non-critical]} (يتم تلبية الامتداد المسمى، ولكن باستخدام سمة isCritical مختلفة) و -name (يستخدم مع all، يشير إلى استثناء). لا يتم تلبية الامتدادات المطلوبة افتراضيًا.

إذا تم توفير خيار -ext مسمى أو OID آخر، بالإضافة إلى الخيار -ext honored، فسيتم إضافة هذا الامتداد إلى الامتدادات التي تم تلبيتها بالفعل. ومع ذلك، إذا ظهر هذا الاسم (أو OID) أيضًا في القيمة المطلوبة، فإن قيمته وأهميته تتجاوزان تلك الموجودة في الطلب.

يتم دائمًا إنشاء امتداد subjectKeyIdentifier. بالنسبة للشهادات غير الموقعة ذاتيًا، يتم إنشاء authorityKeyIdentifier.

ملاحظة: يجب أن يكون المستخدمون على علم بأن بعض مجموعات الامتدادات (وحقول الشهادات الأخرى) قد لا تتوافق مع المعيار الإنترنت. انظر تحذير مطابقة الشهادة.

NAME

keytool

key and certificate management tool

SYNOPSIS

keytool [-command] [-options]

DESCRIPTION

The keytool utility is a key and certificate management tool that is used to manage a so-called keystore, which is a trusted database of keys and certificates. This tool enables users to:

  • Manage the private keys and associated public keys of the user.
  • Manage certificates of trusted Certificate Authorities (CAs), so that users and systems can be sure of a certificate's authenticity.

keytool is an all-in-one tool that supports managing keys and certificates. It generates and manages keys, and it imports and exports (in the form of certificates) the public keys of others.

Keytool is invoked with either a command or a command and associated options.

COMMAND AND OPTION NOTES

-alias alias name
Specifies the alias name of an entry in the keystore.
-keypass password
Specifies the password used to protect the private key.
-new password
Specifies the new password.
-dname "CN=name, OU=name, O=name, L=name, ST=name, C=country code"
Distinguished name to be used to generate a key pair.
-certpass password
Specifies the password for the certificate being replaced.
-validity n days
Number of days to specify the validity of the certificate.
-keyalg algorithm
Name of the public-key algorithm used for generating keys.
-keysize size
The size of the public key to create, in bits.
-storetype type
The type of keystore to be used.
-keystore filename
The name of the keystore file.
-storepass password
The password for the keystore contents.
-providername name
The name of the provider.
-providerpath pathname
The path to the provider's binary:
-v
Enable verbose output.
-protected
Prompt unprotected keystore for password.
-noprompt
Do not prompt the user for any passwords or confirmations.
-trustcacerts
Consider the additional certificates in the cacerts keystore when looking for trusted certificates.
-exportcert
Export user certificate.
-importcert
Import a certificate, certificate reply, or a certificate chain.
-gencert
Generate a certificate based on a certificate request.
-genkeypair
Generate a public/private key pair.
-list
List the contents of the keystore.
-printcert
Prints the certificate information.
-printcertreq
Prints the certificate request information.
-printentry
Prints the contents of a specific keystore entry.
-delete
Deletes the entry identified by alias.
-genkey
Generates a public/private key pair and self-signed certificate.
-verify
Verifies the specified certificate file.
-x509
Output the certificate in binary X.509 format.
-
Read the all content from standard input.

OPTION DEFAULTS

The default keystore type is jks.

The default key algorithm is DSA.

The default key size is 2048.

COMMON OPTIONS

The following options are common to most keytool commands:

-keystore filename
Specifies the name of the keystore file. If this option is not specified, then the default keystore file name is used.
-storepass password
Specifies the password needed to protect the keystore. If this option is not specified, keytool prompts for the password.
-storetype type

EXAMPLES

Generate a key pair and a self-signed certificate:
keytool -genkey -alias mykey -keyalg RSA -keysize 2048 -validity 365 -storepass changeit -keypass changeit
Export a certificate:
keytool -exportcert -alias mykey -file mykey.cer -storepass changeit
Import a certificate:
keytool -importcert -alias mykey -file mykey.cer -storepass changeit
List the contents of the keystore:
keytool -list -v -keystore mykeystore -storepass changeit
Delete an entry from the keystore:
keytool -delete -alias mykey -keystore mykeystore -storepass changeit

TERMS

Keystore: A repository for security-related objects, such as keys, certificates, and trusted certificates.

Alias: A unique name that identifies an entry in a keystore.

Certificate: A digitally signed document that binds a public key with an identity.

Public Key: The key in a public-key pair that can be freely distributed without harming security.

Private Key: The key in a public-key pair that is kept secret and used to decrypt data that has been encrypted with the corresponding public key.

Certificate Authority (CA): An entity that issues digital certificates.

Self-signed certificate: A certificate that is signed by itself, rather than by a trusted CA.

WARNINGS

Passwords should not be specified on a command line or in a script unless it is for testing, or you are on a secure system. When you do not specify a required password option on a command line, you are prompted for it.

CERTIFICATE CONFORMANCE WARNING

The Internet standard RFC 5280 has defined a profile on conforming X.509 certificates, which includes what values and value combinations are valid for certificate fields and extensions. See the standard at http://tools.ietf.org/rfc/rfc5280.txt

The keytool command does not enforce all of these rules so it can generate certificates that do not conform to the standard. Certificates that do not conform to the standard might be rejected by JRE or other applications. Users should ensure that they provide the correct options for -dname, -ext, and so on.

NOTES

IMPORT A NEW TRUSTED CERTIFICATE

Before you add the certificate to the keystore, the keytool command verifies it by attempting to construct a chain of trust from that certificate to a self-signed certificate (belonging to a root CA), using trusted certificates that are already available in the keystore.

If the -trustcacerts option was specified, then additional certificates are considered for the chain of trust, namely the certificates in a file named cacerts.

If the keytool command fails to establish a trust path from the certificate to be imported up to a self-signed certificate (either from the keystore or the cacerts file), then the certificate information is printed, and the user is prompted to verify it by comparing the displayed certificate fingerprints with the fingerprints obtained from some other (trusted) source of information, which might be the certificate owner. Be very careful to ensure the certificate is valid before importing it as a trusted certificate. See Importing Trusted Certificates Warning. The user then has the option of stopping the import operation. If the -noprompt option is specified, then there is no interaction with the user.

IMPORT A CERTIFICATE REPLY

When you import a certificate reply, the certificate reply is validated with trusted certificates from the keystore, and optionally, the certificates configured in the cacerts keystore file when the -trustcacerts option is specified. See The cacerts Certificates File.

The methods of determining whether the certificate reply is trusted are as follows:

•
If the reply is a single X.509 certificate, then the keytool command attempts to establish a trust chain, starting at the certificate reply and ending at a self-signed certificate (belonging to a root CA). The certificate reply and the hierarchy of certificates is used to authenticate the certificate reply from the new certificate chain of aliases. If a trust chain cannot be established, then the certificate reply is not imported. In this case, the keytool command does not print the certificate and prompt the user to verify it, because it is very difficult for a user to determine the authenticity of the certificate reply.
•
If the reply is a PKCS #7 formatted certificate chain or a sequence of X.509 certificates, then the chain is ordered with the user certificate first followed by zero or more CA certificates. If the chain ends with a self-signed root CA certificate and the-trustcacerts option was specified, the keytool command attempts to match it with any of the trusted certificates in the keystore or the cacerts keystore file. If the chain does not end with a self-signed root CA certificate and the -trustcacerts option was specified, the keytool command tries to find one from the trusted certificates in the keystore or the cacerts keystore file and add it to the end of the chain. If the certificate is not found and the -noprompt option is not specified, the information of the last certificate in the chain is printed, and the user is prompted to verify it.

If the public key in the certificate reply matches the user's public key already stored with alias, then the old certificate chain is replaced with the new certificate chain in the reply. The old chain can only be replaced with a valid keypass, and so the password used to protect the private key of the entry is supplied. If no password is provided, and the private key password is different from the keystore password, the user is prompted for it.

This command was named -import in earlier releases. This old name is still supported in this release. The new name, -importcert, is preferred going forward.
