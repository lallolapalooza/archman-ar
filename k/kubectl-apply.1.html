kubectl-apply(1)

الحزمة: kubectl

التراخيص: Apache-2.0

KUBERNETES(1)(kubernetes) KUBERNETES(1)(kubernetes)
Eric Paris Jan 2015

الاسم

kubectl apply - تطبيق تكوين على مورد بواسطة اسم الملف أو الإدخال القياسي

الملخص

kubectl apply [خيارات]

الوصف

تطبيق تكوين على مورد بواسطة اسم الملف أو الإدخال القياسي. يجب تحديد اسم المورد. سيتم إنشاء هذا المورد إذا لم يكن موجودًا بالفعل. لاستخدام 'apply'، قم دائمًا بإنشاء المورد مبدئيًا إما باستخدام 'apply' أو 'create --save-config'.

يتم قبول تنسيقات JSON و YAML.

إخلاء مسؤولية بيتا: وظيفة --prune ليست كاملة بعد. لا تستخدمها ما لم تكن على دراية بحالتها الحالية. انظر https://issues.k8s.io/34274.

الخيارات

--all=false تحديد جميع الموارد في مساحة اسم أنواع الموارد المحددة.

--allow-missing-template-keys=true إذا كانت صحيحة، تجاهل أي أخطاء في القوالب عند فقدان حقل أو مفتاح خريطة في القالب. ينطبق فقط على تنسيقات الإخراج golang و jsonpath.

--cascade="background" يجب أن يكون "background" أو "orphan" أو "foreground". يحدد استراتيجية التسلسل الهرمي للحذف للمعتمدين (على سبيل المثال، Pods التي تم إنشاؤها بواسطة ReplicationController). الافتراضي هو background.

--dry-run="none" يجب أن يكون "none" أو "server" أو "client". إذا كانت الاستراتيجية client، فقط اطبع الكائن الذي سيتم إرساله، دون إرساله. إذا كانت الاستراتيجية server، أرسل طلبًا من جانب الخادم دون الاحتفاظ بالمورد.

--field-manager="kubectl-client-side-apply" اسم المدير المستخدم لتتبع ملكية الحقول.

-f, --filename=[] الملفات التي تحتوي على التكوينات للتطبيق.

--force=false إذا كانت صحيحة، قم بإزالة الموارد فورًا من API وتجاوز الحذف الهادئ. لاحظ أن الحذف الفوري لبعض الموارد قد يؤدي إلى عدم اتساق أو فقدان بيانات ويتطلب تأكيدًا.

--force-conflicts=false إذا كانت صحيحة، سيقوم تطبيق جانب الخادم بفرض التغييرات مقابل التعارضات.

--grace-period=-1 فترة زمنية بالثواني تُمنح للمورد لإنهاء العمل بشكل هادئ. يتم تجاهله إذا كان سالبًا. اضبطه على 1 للإيقاف الفوري. يمكن تعيينه على 0 فقط عندما يكون --force صحيحًا (حذف قسري).

-k, --kustomize="" معالجة دليل kustomization. لا يمكن استخدام هذا الخيار مع -f أو -R.

--openapi-patch=true إذا كانت صحيحة، استخدم openapi لحساب الفرق عندما يكون openapi حاضرًا ويمكن العثور على المورد في مواصفات openapi. خلاف ذلك، ارجع إلى الأنواع المضمنة.

-o, --output="" تنسيق الإخراج. أحد الخيارات: (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--overwrite=true حل التعارضات تلقائيًا بين التكوين المعدل والتكوين الحالي باستخدام القيم من التكوين المعدل

--prune=false حذف كائنات الموارد تلقائيًا، التي لا تظهر في التكوينات وتم إنشاؤها بواسطة apply أو create --save-config. يجب استخدامها مع -l أو --all.

--prune-allowlist=[] الكتابة فوق القائمة المسموح بها الافتراضية لـ --prune

--record=false تسجيل أمر kubectl الحالي في تعليق المورد. إذا تم تعيينه على false، لا تسجل الأمر. إذا تم تعيينه على true، سجل الأمر. إذا لم يتم تعيينه، فسيتم افتراضيًا تحديث قيمة التعليق الموجودة فقط إذا كانت موجودة بالفعل.

-R, --recursive=false معالجة الدليل المستخدم في -f، --filename بشكل متكرر. مفيد عندما تريد إدارة البيانات التعريفية ذات الصلة المنظمة داخل نفس الدليل.

-l, --selector="" محدد (استعلام التسمية) للتصفية، يدعم '=', '==', '!=', 'in', 'notin'. (على سبيل المثال: -l key1=value1,key2=value2,key3 in (value3)). يجب أن تستوفي الكائنات المتطابقة جميع قيود التسمية المحددة.

--server-side=false إذا كانت صحيحة، يعمل apply في الخادم بدلاً من العميل.

--show-managed-fields=false إذا كانت صحيحة، احتفظ بـ managedFields عند طباعة الكائنات بتنسيق JSON أو YAML.

--subresource="" إذا تم تحديده، سيعمل apply على المورد الفرعي للكائن المطلوب. مسموح به فقط عند استخدام --server-side.

--template="" سلسلة قالب أو مسار إلى ملف قالب لاستخدامه عند -o=go-template، -o=go-template-file. تنسيق القالب هو قوالب golang (http://golang.org/pkg/text/template/#pkg-overview).

--timeout=0s طول الوقت للانتظار قبل الاستسلام لحذف، صفر يعني تحديد مهلة من حجم الكائن

--validate="strict" يجب أن يكون أحد الخيارات: strict (أو true)، warn، ignore (أو false). سيستخدم "true" أو "strict" مخططًا للتحقق من صحة الإدخال وفشل الطلب إذا كان غير صالح. سيقوم بإجراء تحقق من جانب الخادم إذا تم تمكين ServerSideFieldValidation على api-server، ولكنه سيعود إلى تحقق أقل موثوقية من جانب العميل إذا لم يكن كذلك. سيقوم "warn" بالتحذير بشأن الحقول غير المعروفة أو المكررة دون حظر الطلب إذا تم تمكين التحقق من جانب الخادم على خادم API، وسيتصرف كـ "ignore" بخلاف ذلك. لن يقوم "false" أو "ignore" بإجراء أي تحقق من المخطط، ويتجاهل بصمت أي حقول غير معروفة أو مكررة.

--wait=false إذا كانت صحيحة، انتظر حتى تختفي الموارد قبل العودة. هذا ينتظر finalizers.

الخيارات الموروثة من أوامر الأب

--as="" اسم المستخدم للانتحال في العملية. يمكن أن يكون المستخدم مستخدمًا عاديًا أو حساب خدمة في مساحة اسم.

--as-group=[] المجموعة للانتحال في العملية، يمكن تكرار هذا الخيار لتحديد مجموعات متعددة.

--as-uid="" المعرف الفريد (UID) للانتحال في العملية.

--cache-dir="/home/username/.kube/cache" دليل ذاكرة التخزين المؤقت الافتراضي

--certificate-authority="" مسار ملف شهادة سلطة الشهادات

--client-certificate="" مسار ملف شهادة العميل لـ TLS

--client-key="" مسار ملف مفتاح العميل لـ TLS

--cluster="" اسم مجموعة kubeconfig للاستخدام

--context="" اسم سياق kubeconfig للاستخدام

--disable-compression=false إذا كانت صحيحة، قم بإلغاء الاشتراك في ضغط الاستجابة لجميع الطلبات إلى الخادم

--insecure-skip-tls-verify=false إذا كانت صحيحة، لن يتم التحقق من صحة شهادة الخادم. سيجعل هذا اتصالات HTTPS الخاصة بك غير آمنة

--kubeconfig="" مسار ملف kubeconfig للاستخدام في طلبات CLI.

--kuberc="" مسار ملف kuberc للاستخدام للتفضيلات. يمكن تعطيل ذلك عن طريق تصدير KUBECTL_KUBERC=false أو إيقاف تشغيل بوابة الميزة KUBERC=off.

--match-server-version=false يتطلب تطابق إصدار الخادم مع إصدار العميل

-n, --namespace="" إذا كان موجودًا، نطاق مساحة الاسم لطلب CLI هذا

--password="" كلمة المرور للمصادقة الأساسية لخادم API

--profile="none" اسم الملف الشخصي المراد التقاطه. أحد الخيارات (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" اسم الملف لكتابة الملف الشخصي إليه

--request-timeout="0" طول الوقت للانتظار قبل الاستسلام لطلب خادم واحد. يجب أن تحتوي القيم غير الصفرية على وحدة زمنية مقابلة (على سبيل المثال: 1s، 2m، 3h). القيمة صفر تعني عدم انتهاء صلاحية الطلبات.

-s, --server="" عنوان ومنفذ خادم Kubernetes API

--tls-server-name="" اسم الخادم المستخدم للتحقق من صحة شهادة الخادم. إذا لم يتم توفيره، يتم استخدام اسم المضيف المستخدم للاتصال بالخادم

--token="" رمز الدب (Bearer token) للمصادقة لخادم API

--user="" اسم المستخدم في kubeconfig للاستخدام

--username="" اسم المستخدم للمصادقة الأساسية لخادم API

--version=false --version، --version=raw يطبع الإصدار

NAME

kubectl-apply - Apply a configuration to a resource by filename or stdin

SYNOPSIS

kubectl apply -f (<filename> | <url> | -) [--prune] [options]

DESCRIPTION

Apply a configuration to a resource by filename or stdin. To use kubectl apply, you must have the resource's LAST APPLIED CONFIGURATION annotation set. This annotation is used to track the last applied configuration and is used to determine what has changed. If you delete the annotation, kubectl apply will not be able to detect changes and will create a new resource.

This command is idempotent. This means that you can run it multiple times with the same configuration and it will have the same effect. This is useful for ensuring that your cluster is in a desired state.

To use this command, you must provide a file or a URL that contains the configuration for the resource. You can also pipe the configuration to stdin.

The --prune flag can be used to delete resources that are not present in the configuration file. This is a powerful flag and should be used with caution.

OPTIONS

--all
Select all resources, including those hidden from default list display.
--allow-missing-template-keys=true
If true, ignore any errors in templates when a field or map key is missing in the template. Other errors will still be raised. Default true.
--cascade=<background|foreground|orphan>
Must be one of: background, foreground, orphan. Whether the emission of deletions from the command should be cascaded. By default, an orphan deletion is the default, meaning that the parent resource is deleted, but the dependent resources are not.
--dry-run=<none|server|client>
Don't actually apply any changes. Print the changes that would be made instead. One of: none, server, client. Server dry run requires the server side dry run feature to be enabled. Default: none.
-f, --filename=[]
Filename, directory, or URL to files to use to create the resource(s).
--force-conflicts
If true, force the deletion of the conflicting resources. This is a dangerous option and should be used with caution.
--ignore-not-found=false
If true, ignore instructions that only operate on optional resources that are not installed. By default, instructions that are not supported are not ignored.
-k, --kustomize=""
Process the kustomization directory. This flag can't be used together with -f or -R.
-L, --label-columns=[]
Optional list of extra labels to include, separated by commas. Labels could be defined as an expression, such as 'value_expression=key' or 'key_expression=value'.
--no-headers=false
When using the default output format, don't print headers (default print headers).
--obj-owner=<owner>
The owner of the object. This is used to determine which resources to prune. By default, the owner is the namespace.
-o, --output=""
Output format. One of: al, custom-columns=..., custom-columns-file=..., go-template=..., go-template-file=..., json, jsonpath=..., jsonpath-file=..., short, template=..., templatefile=..., unstructured, wide
--prune=false
If true, delete resources that are not present in the configuration file. This is a dangerous option and should be used with caution.
--prune-allowlist=[]
Allow deletion of resources that match the specified resource types and namespaces. This is a safety mechanism to prevent accidental deletion of resources. Use with --prune.
--prune-empty=false
If true, delete resources that are empty. This is a dangerous option and should be used with caution.
--record=false
Record current kubectl command in the resource annotations. If set to true, the kubectl command that generated the current configuration will be stored in the object's annotations. Useful for debugging and auditing.
-R, --recursive=false
Process the directory used in -f, recursively.
--server-side=false
If true, use server-side apply. This is a more robust way to apply configurations and can be used to resolve conflicts. Default false.
--show-managed-fields=false
If true, keep and show all managed fields. Default false.
--template=<template>
Template string or path to template file to use when -o=go-template, -o=go-template-file, -o=template, or -o=templatefile is set for outputting.
--validate=true
If true, server-side validation is enabled. Default true.
--version=vX.Y.Z...
sets the reported version
--warnings-as-errors=false
Treat warnings received from the server as errors and exit with a non-zero exit code

EXAMPLE

  # Apply the configuration in pod.json to a pod
  kubectl apply -f ./pod.json
  # Apply resources from a directory containing kustomization.yaml - e.g. dir/kustomization.yaml
  kubectl apply -k dir/
  # Apply the JSON passed into stdin to a pod
  cat pod.json | kubectl apply -f -
  # Apply the configuration from all files that end with '.json'
  kubectl apply -f '*.json'
  # Note: --prune is still in Alpha
  # Apply the configuration in manifest.yaml that matches label app=nginx and delete all other resources that are not in the file and match label app=nginx
  kubectl apply --prune -f manifest.yaml -l app=nginx
  # Apply the configuration in manifest.yaml and delete all the other config maps that are not in the file
  kubectl apply --prune -f manifest.yaml --all --prune-allowlist=core/v1/ConfigMap
