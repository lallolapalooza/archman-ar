NAME

knockd – daemon for remotely opening and closing ports

SYNOPSIS

knockd [-d] [-f] [-q] [-c configfile] [-i interface] [-p pidfile]

DESCRIPTION

knockd is a daemon that listens to the network for a sequence of connection requests on specific ports. When the sequence is detected, it sends a command to the system. This is useful for remotely opening up a firewall port for a specific period of time, or for running other commands when a specific "knock" is detected.

The configuration file is typically located in /etc/knockd.conf.

COMMANDLINE OPTIONS

The options are used to override the default settings defined in the configuration file.

-d
Run in the foreground.
-f
Run in the foreground and print configuration errors to stdout.
-q
Quiet mode. Suppresses all output except for configuration errors.
-c configfile
Use the specified configuration file instead of the default /etc/knockd.conf.
-i interface
Listen on the specified network interface. If not specified, knockd will listen on all interfaces.
-p pidfile
Write the process ID to the specified file. The default is /run/knockd.pid.

CONFIGURATION

The configuration file consists of sections. Each section defines a "knock" sequence and the actions to take when it is detected.

A section starts with a name in square brackets, e.g., [openSSH]. This name is used to identify the knock sequence.

Within each section, you can define the following directives:

sequence: A comma-separated list of ports to knock on. The ports can be TCP or UDP, specified as <port> or <port>/<protocol>, where protocol is tcp or udp.

seq_timeout: The time in seconds to wait for the entire sequence to be completed. If the sequence is not completed within this time, it is reset.

command: The command to execute when the sequence is detected. The knocker's IP address is substituted for %IP%.

tcpflags: A comma-separated list of TCP flags that must be set for a packet to be considered part of the knock sequence. Valid flags are: syn, ack, urg, psh, fin, rst. If not specified, any packet is accepted.

interface: The network interface to listen on for this specific knock sequence. If not specified, the interface specified with the -i command-line option is used, or all interfaces if neither is specified.

target: The IP address to use when matching the sequence. This is useful if knockd is running on a router and you want to do something in response to a connection attempt to a routed host.

start_command: Alias for command.

cmd_timeout: The time in seconds to wait between executing start_command and stop_command. Only required if stop_command is used.

stop_command: The command to execute after cmd_timeout seconds have passed since start_command was executed. The knocker's IP address is substituted for %IP%.

start_command_6: The command to execute for IPv6 knocks.

stop_command_6: The command to execute for IPv6 knocks after cmd_timeout.

A special section [DEFAULT] can be used to define global defaults for all sections.

Example #1:

Open SSH access for 1 minute from the knocker's IP.

[openSSH]
        sequence    = 1111,2222,3333
        seq_timeout = 5
        command     = /sbin/iptables -I INPUT -s %IP% -p tcp --dport 22 -j ACCEPT
        tcpflags    = syn

Example #2:

Close SSH access after 5 minutes.

[closeSSH]
        sequence    = 4444,5555,6666
        seq_timeout = 5
        command     = /sbin/iptables -D INPUT -s %IP% -p tcp --dport 22 -j ACCEPT
        tcpflags    = syn

Example #3:

Open SSH access and close it after 600 seconds (10 minutes).

[ssh]
        sequence    = 1111,2222,3333
        seq_timeout = 5
        command     = /sbin/iptables -I INPUT -s %IP% -p tcp --dport 22 -j ACCEPT
        tcpflags    = syn
        cmd_timeout = 600
        stop_command = /sbin/iptables -D INPUT -s %IP% -p tcp --dport 22 -j ACCEPT

Example #4:

Open SSH access, but only if the packet has the SYN flag set.

[ssh]
        sequence    = 1111,2222,3333
        seq_timeout = 5
        command     = /sbin/iptables -I INPUT -s %IP% -p tcp --dport 22 -j ACCEPT
        tcpflags    = syn

CONFIGURATION: GLOBAL DIRECTIVES

These directives apply to all knock sequences unless overridden in a specific section.

Interface = <interface>
The network interface to listen on. Defaults to all interfaces.
pidfile = <pidfile>
The file to write the PID to. Defaults to /run/knockd.pid.
logfile = <logfile>
The file to log messages to. Defaults to syslog.

CONFIGURATION: KNOCK/EVENT DIRECTIVES

These directives define a specific knock sequence and its associated actions.

sequence = <port>[,<port>...]
A comma-separated list of ports to knock on. Ports can be specified as numbers (e.g. 1111) or with protocol (e.g. 1111/tcp). If protocol is omitted, the port will be checked for both TCP and UDP.
seq_timeout = <timeout>
The time in seconds to wait for the entire sequence to be completed. Defaults to 15 seconds.
command = <command>
The command to execute when the sequence is detected. The knocker's IP address is substituted for %IP%. This directive is an alias for Start_Command.
TCPFlags = <flags>
Comma-separated list of TCP flags that must be set for a packet to be considered part of the sequence. Valid flags are syn, ack, urg, psh, fin, rst. For example, to only accept SYN packets, use 
TCPFlags = syn
This is useful if you want to prevent spurious connections from triggering the knock sequence, or if you are testing over an SSH connection, as the SSH traffic will usually interfere with (and thus invalidate) the knock.

Separate multiple flags with commas (eg, TCPFlags = syn,ack,urg). Flags can be explicitly excluded by a "!" (eg, TCPFlags = syn,!ack).

Target = <ip-address>
Use the specified IP address instead of the address determined for the Interface when matching the Sequence. This is useful if knockd is running on a router and you want to do something in response to an actual connection attempt to a routed host - e.g., invoking etherwake to send the host a WOL packet.
Start_Command = <command>
Specify the command to be executed when a client makes the correct port-knock with IPv4. All instances of %IP% will be replaced with the knocker's IP address. The Command directive is an alias for Start_Command.
Start_Command_6 = <command>
Specify the command to be executed when a client makes the correct port-knock with IPv6. All instances of %IP% will be replaced with the knocker's IP address. The Command_6 directive is an alias for Start_Command_6. If not present it will automatically fallback onto the same IPV4 Start_Command value. You can use empty value to force doing nothing.
Cmd_Timeout = <timeout>
Time to wait (in seconds) between Start_Command and Stop_Command. This directive is optional, only required if Stop_Command is used.
Stop_Command = <command>
Specify the command to be executed when Cmd_Timeout seconds have passed since Start_Command has been executed. All instances of %IP% will be replaced with the knocker's IP address. This directive is optional.
Stop_Command_6 = <command>
Specify the command to be executed when Cmd_Timeout seconds have passed since Start_Command_6 has been executed. All instances of %IP% will be replaced with the knocker's IP address. This directive is optional. If not present it will automatically fallback onto the same IPV4 Stop_Command value. You can use empty value to force doing nothing.

SECURITY NOTES

Using the -l or --lookup commandline option to resolve DNS names for log entries may be a security risk! An attacker may find out the first port of a sequence if he can monitor the DNS traffic of the host running knockd. Also a host supposed to be stealth (eg, dropping packets to closed TCP ports instead of replying with an ACK+RST packet) may give itself away by resolving a DNS name if an attacker manages to hit the first (unknown) port of a sequence.

SEE ALSO

knock is the accompanying port-knock client, though telnet or netcat could be used for simple TCP knocks instead. For more advanced knocks, see hping, sendip or packit.

الاسم

knockd – خادم لفتح وإغلاق المنافذ عن بعد

الملخص

knockd [-d] [-f] [-q] [-c ملف_الإعدادات] [-i الواجهة] [-p ملف_pid]

الوصف

knockd هو خادم يستمع إلى الشبكة لسلسلة من طلبات الاتصال على منافذ محددة. عند اكتشاف السلسلة، فإنه يرسل أمرًا إلى النظام. هذا مفيد لفتح منفذ جدار الحماية عن بعد لفترة زمنية محددة، أو لتشغيل أوامر أخرى عند اكتشاف "ضربة" معينة.

عادة ما يكون ملف الإعدادات موجودًا في /etc/knockd.conf.

خيارات سطر الأوامر

تُستخدم الخيارات لتجاوز الإعدادات الافتراضية المحددة في ملف الإعدادات.

-d
تشغيل في الواجهة الأمامية.
-f
تشغيل في الواجهة الأمامية وطباعة أخطاء الإعدادات إلى المخرج القياسي.
-q
وضع الهدوء. يكتم جميع المخرجات باستثناء أخطاء الإعدادات.
-c ملف_الإعدادات
استخدام ملف الإعدادات المحدد بدلاً من الافتراضي /etc/knockd.conf.
-i الواجهة
الاستماع على الواجهة الشبكية المحددة. إذا لم يتم تحديدها، سيستمع knockd على جميع الواجهات.
-p ملف_pid
كتابة معرف العملية (PID) إلى الملف المحدد. الافتراضي هو /run/knockd.pid.

الإعدادات

يتكون ملف الإعدادات من أقسام. يحدد كل قسم "تسلسل ضربة" والإجراءات التي يجب اتخاذها عند اكتشافه.

يبدأ القسم باسم بين قوسين مربعين، على سبيل المثال [openSSH]. يستخدم هذا الاسم لتحديد تسلسل الضربات.

ضمن كل قسم، يمكنك تحديد التوجيهات التالية:

sequence: قائمة مفصولة بفواصل للمنافذ التي يجب الضرب عليها. يمكن أن تكون المنافذ TCP أو UDP، محددة كـ <port> أو <port>/<protocol>، حيث البروتوكول هو tcp أو udp.

seq_timeout: الوقت بالثواني للانتظار حتى اكتمال السلسلة بأكملها. إذا لم تكتمل السلسلة خلال هذا الوقت، يتم إعادة تعيينها.

command: الأمر الذي يجب تنفيذه عند اكتشاف السلسلة. يتم استبدال عنوان IP للمستدعي بـ %IP%.

tcpflags: قائمة مفصولة بفواصل بأعلام TCP التي يجب تعيينها لكي يعتبر الحزمة جزءًا من تسلسل الضربات. الأعلام الصالحة هي: syn, ack, urg, psh, fin, rst. إذا لم يتم تحديدها، يتم قبول أي حزمة.

interface: الواجهة الشبكية التي سيتم الاستماع عليها لتسلسل الضربات المحدد هذا. إذا لم يتم تحديده، يتم استخدام الواجهة المحددة في خيار سطر الأوامر -i، أو جميع الواجهات إذا لم يتم تحديد أي منهما.

target: عنوان IP الذي يجب استخدامه عند مطابقة السلسلة. هذا مفيد إذا كان knockd يعمل على جهاز توجيه وتريد القيام بشيء ما استجابةً لمحاولة اتصال بجهاز موجه - على سبيل المثال، استدعاء etherwake لإرسال حزمة WOL إلى الجهاز.

start_command: اسم بديل لـ command.

cmd_timeout: الوقت بالثواني للانتظار بين تنفيذ start_command و stop_command. مطلوب فقط إذا تم استخدام stop_command.

stop_command: الأمر الذي يجب تنفيذه بعد مرور cmd_timeout ثانية منذ تنفيذ start_command. يتم استبدال عنوان IP للمستدعي بـ %IP%.

start_command_6: الأمر الذي يجب تنفيذه لضربات IPv6.

stop_command_6: الأمر الذي يجب تنفيذه لضربات IPv6 بعد cmd_timeout.

يمكن استخدام قسم خاص [DEFAULT] لتحديد القيم الافتراضية العالمية لجميع الأقسام.

مثال #1:

فتح الوصول إلى SSH لمدة دقيقة واحدة من عنوان IP للمستدعي.

[openSSH]
        sequence    = 1111,2222,3333
        seq_timeout = 5
        command     = /sbin/iptables -I INPUT -s %IP% -p tcp --dport 22 -j ACCEPT
        tcpflags    = syn

مثال #2:

إغلاق الوصول إلى SSH بعد 5 دقائق.

[closeSSH]
        sequence    = 4444,5555,6666
        seq_timeout = 5
        command     = /sbin/iptables -D INPUT -s %IP% -p tcp --dport 22 -j ACCEPT
        tcpflags    = syn

مثال #3:

فتح الوصول إلى SSH وإغلاقه بعد 600 ثانية (10 دقائق).

[ssh]
        sequence    = 1111,2222,3333
        seq_timeout = 5
        command     = /sbin/iptables -I INPUT -s %IP% -p tcp --dport 22 -j ACCEPT
        tcpflags    = syn
        cmd_timeout = 600
        stop_command = /sbin/iptables -D INPUT -s %IP% -p tcp --dport 22 -j ACCEPT

مثال #4:

فتح الوصول إلى SSH، ولكن فقط إذا كان الحزمة تحمل علامة SYN.

[ssh]
        sequence    = 1111,2222,3333
        seq_timeout = 5
        command     = /sbin/iptables -I INPUT -s %IP% -p tcp --dport 22 -j ACCEPT
        tcpflags    = syn

الإعدادات: التوجيهات العامة

تنطبق هذه التوجيهات على جميع تسلسلات الضربات ما لم يتم تجاوزها في قسم محدد.

Interface = <الواجهة>
الواجهة الشبكية للاستماع عليها. الافتراضي هو جميع الواجهات.
pidfile = <ملف_pid>
الملف لكتابة معرف العملية (PID) إليه. الافتراضي هو /run/knockd.pid.
logfile = <ملف_السجل>
الملف لتسجيل الرسائل إليه. الافتراضي هو syslog.

الإعدادات: توجيهات الضرب/الحدث

تحدد هذه التوجيهات تسلسل ضربات محدد وإجراءاتها المرتبطة بها.

sequence = <port>[,<port>...]
قائمة مفصولة بفواصل للمنافذ التي يجب الضرب عليها. يمكن تحديد المنافذ كرقم (مثل 1111) أو مع البروتوكول (مثل 1111/tcp). إذا تم حذف البروتوكول، سيتم التحقق من المنفذ لكل من TCP و UDP.
seq_timeout = <timeout>
الوقت بالثواني للانتظار حتى اكتمال السلسلة بأكملها. الافتراضي هو 15 ثانية.
command = <command>
الأمر الذي يجب تنفيذه عند اكتشاف السلسلة. يتم استبدال عنوان IP للمستدعي بـ %IP%. هذا التوجيه هو اسم بديل لـ Start_Command.
TCPFlags = <flags>
قائمة مفصولة بفواصل لأعلام TCP التي يجب تعيينها لكي تعتبر الحزمة جزءًا من السلسلة. الأعلام الصالحة هي syn, ack, urg, psh, fin, rst. على سبيل المثال، لقبول حزم SYN فقط، استخدم 
TCPFlags = syn
هذا مفيد إذا كنت ترغب في منع الاتصالات العشوائية من تشغيل تسلسل الضربات، أو إذا كنت تختبر عبر اتصال SSH، حيث أن حركة مرور SSH عادةً ما تتداخل مع الضرب (وبالتالي تبطله).

افصل بين الأعلام المتعددة بفواصل (مثال: TCPFlags = syn,ack,urg). يمكن استبعاد الأعلام بشكل صريح عن طريق علامة "!" (مثال: TCPFlags = syn,!ack).

Target = <ip-address>
استخدم عنوان IP المحدد بدلاً من العنوان المحدد لـ Interface عند مطابقة Sequence. هذا مفيد إذا كان knockd يعمل على جهاز توجيه وتريد القيام بشيء ما استجابةً لمحاولة اتصال بجهاز موجه - على سبيل المثال، استدعاء etherwake لإرسال حزمة WOL إلى الجهاز.
Start_Command = <command>
حدد الأمر الذي سيتم تنفيذه عندما يقوم العميل بإجراء ضربة المنفذ الصحيحة مع IPv4. سيتم استبدال جميع تكرارات %IP% بعنوان IP للمستدعي. التوجيه Command هو اسم بديل لـ Start_Command.
Start_Command_6 = <command>
حدد الأمر الذي سيتم تنفيذه عندما يقوم العميل بإجراء ضربة المنفذ الصحيحة مع IPv6. سيتم استبدال جميع تكرارات %IP% بعنوان IP للمستدعي. التوجيه Command_6 هو اسم بديل لـ Start_Command_6. إذا لم يكن موجودًا، فسيعود تلقائيًا إلى نفس قيمة IPV4 Start_Command. يمكنك استخدام قيمة فارغة لفرض عدم القيام بأي شيء.
Cmd_Timeout = <timeout>
الوقت للانتظار (بالثواني) بين Start_Command و Stop_Command. هذا التوجيه اختياري، وهو مطلوب فقط إذا تم استخدام Stop_Command.
Stop_Command = <command>
حدد الأمر الذي سيتم تنفيذه عندما تمر Cmd_Timeout ثانية منذ تنفيذ Start_Command. سيتم استبدال جميع تكرارات %IP% بعنوان IP للمستدعي. هذا التوجيه اختياري.
Stop_Command_6 = <command>
حدد الأمر الذي سيتم تنفيذه عندما تمر Cmd_Timeout ثانية منذ تنفيذ Start_Command_6. سيتم استبدال جميع تكرارات %IP% بعنوان IP للمستدعي. هذا التوجيه اختياري. إذا لم يكن موجودًا، فسيعود تلقائيًا إلى نفس قيمة IPV4 Stop_Command. يمكنك استخدام قيمة فارغة لفرض عدم القيام بأي شيء.

ملاحظات أمنية

قد يمثل استخدام خيار سطر الأوامر -l أو --lookup لحل أسماء DNS لإدخالات السجل خطرًا أمنيًا! قد يكتشف المهاجم المنفذ الأول في التسلسل إذا كان بإمكانه مراقبة حركة مرور DNS للجهاز الذي يعمل عليه knockd. أيضًا، قد يكشف الجهاز المفترض أن يكون متخفيًا (مثل، إسقاط الحزم إلى منافذ TCP مغلقة بدلاً من الرد بحزمة ACK+RST) عن نفسه عن طريق حل اسم DNS إذا تمكن المهاجم من الوصول إلى المنفذ الأول (غير المعروف) في التسلسل.

انظر أيضًا

knock هو العميل المصاحب لضرب المنافذ، على الرغم من أن telnet أو netcat يمكن استخدامهما لضربات TCP البسيطة بدلاً من ذلك. لضربات أكثر تقدمًا، انظر hping، sendip أو packit.
