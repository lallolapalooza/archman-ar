OCSP_resp_find_status(3ssl)

الحزمة: openssl

التراخيص: Apache-2.0

NAME

OCSP_resp_find_status, OCSP_resp_get0_id, OCSP_resp_get1_id, OCSP_check_validity, OCSP_basic_verify - find certificate status in an OCSP response

SYNOPSIS

#include <openssl/ocsp.h>
int OCSP_resp_find_status(OCSP_RESPONSE *resp, OCSP_CERTID *id,
                          int *status, int *reason,
                          X509_GMOTIME **revtime, X509_GMOTIME **thisupd,
                          X509_GMOTIME **nextupd);
OCSP_CERTID *OCSP_resp_get0_id(const OCSP_BASIC_RESP *bs, int index);
OCSP_CERTID *OCSP_resp_get1_id(const OCSP_BASIC_RESP *bs, int index);
int OCSP_check_validity(X509_GMOTIME *thisupd, X509_GMOTIME *nextupd,
                        long sec, long maxsec);
int OCSP_basic_verify(OCSP_BASIC_RESP *resp, STACK_OF(X509) *certs,
                      X509_STORE *store, unsigned int flags);

DESCRIPTION

The OCSP (Online Certificate Status Protocol) protocol is used to obtain the status of a certificate.

OCSP_resp_find_status() searches the OCSP response object resp for an entry corresponding to the certificate ID id. If found, the status is returned in *status, the reason in *reason if the status is revocation, and the revocation time, thisUpdate time, and nextUpdate time are returned in *revtime, *thisupd, and *nextupd respectively. A value of OCSP_V_REASON_UNDEF is used if no specific reason is given.

OCSP_resp_get0_id() and OCSP_resp_get1_id() return the certificate ID at the given index from the basic response bs. OCSP_resp_get0_id() returns a pointer to the internal data, which MUST NOT be freed. OCSP_resp_get1_id() returns a newly duplicated copy, which MUST be freed by the caller.

OCSP_check_validity() checks if the current time is within the validity period specified by thisupd and nextupd. The sec parameter specifies the number of seconds allowed for the current time to be before thisupd. The maxsec parameter specifies the number of seconds allowed for the current time to be after nextupd. If maxsec is less than 0, then the nextupd check is not performed.

OCSP_basic_verify() verifies the OCSP response signature. The certs parameter is a stack of additional certificates to be used for verification. The store parameter is an X509_STORE to be used for finding the trust anchor. The flags parameter can be used to modify verification behaviour.

RETURN VALUES

OCSP_resp_find_status() returns 1 on success, 0 if no matching entry is found or if the response is invalid. The status codes are defined in RFC 2560. Possible values for *status are:

  • `V_OCSP_cert_ok` (0)
  • `V_OCSP_cert_revoked` (1)
  • `V_OCSP_cert_unknown` (2)

Possible values for *reason are:

  • `V_OCSP_REASON_UNDEF` (0)
  • `V_OCSP_REASON_KEY_COMPROMISE` (1)
  • `V_OCSP_REASON_CA_COMPROMISE` (2)
  • `V_OCSP_REASON_AFFILIATION_CHANGED` (3)
  • `V_OCSP_REASON_SUPERSEDED` (4)
  • `V_OCSP_REASON_CESSATION_OF_OPERATION` (5)
  • `V_OCSP_REASON_CERTIFICATE_HOLD` (6)
  • `V_OCSP_REASON_QUIT_WITHDRAWAL` (7)

OCSP_resp_get0_id() and OCSP_resp_get1_id() return a pointer to the certificate ID on success, or NULL on failure. Note that OCSP_resp_get1_id() returns 1 on success, 0 on failure.

OCSP_check_validity() returns 1 if thisupd and nextupd are valid time values and the current time + sec is not before thisupd and, if maxsec >= 0, the current time - maxsec is not past nextupd. Otherwise it returns 0 to indicate an error.

OCSP_basic_verify() returns 1 on success, 0 on verification not successful, or -1 on a fatal error such as malloc failure.

NOTES

Applications will typically call OCSP_resp_find_status() using the certificate ID of interest and then check its validity using OCSP_check_validity(). They can then take appropriate action based on the status of the certificate.

An OCSP response for a certificate contains thisUpdate and nextUpdate fields. Normally the current time should be between these two values. To account for clock skew the maxsec field can be set to nonzero in OCSP_check_validity(). Some responders do not set the nextUpdate field, this would otherwise mean an ancient response would be considered valid: the maxsec parameter to OCSP_check_validity() can be used to limit the permitted age of responses.

The values written to *revtime, *thisupd and *nextupd by OCSP_resp_find_status() and OCSP_single_get0_status() are internal pointers which MUST NOT be freed up by the calling application. Any or all of these parameters can be set to NULL if their value is not required.
