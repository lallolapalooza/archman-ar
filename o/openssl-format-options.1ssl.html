openssl-format-options(1ssl)

الحزمة: openssl

التراخيص: Apache-2.0

OPENSSL-FORMAT-OPTIONS(1ssl) OpenSSL OPENSSL-FORMAT-OPTIONS(1ssl)

الاسم

openssl-format-options - خيارات تنسيق إدخال وإخراج OpenSSL

الملخص

openssl command [ options ... ] [ parameters ... ]

الوصف

يمكن لعدة أوامر OpenSSL أخذ إدخال أو إنشاء إخراج في مجموعة متنوعة من التنسيقات.

منذ OpenSSL 3.0، يمكن قراءة المفاتيح والشهادات الفردية و CRLs من الملفات بأي من تنسيقات DER أو PEM أو P12. لم يعد تحديد تنسيق الإدخال الخاص بها مطلوبًا وستحاول أوامر openssl تلقائيًا جميع التنسيقات الممكنة. ومع ذلك، إذا تم تحديد تنسيق إدخال DER أو PEM، فإن ذلك سيكون إلزاميًا.

للوصول إلى مفتاح عبر محرك، يمكن استخدام تنسيق الإدخال ENGINE؛ بدلاً من ذلك، يمكن أن يسبق معرف المفتاح في وسيطة <uri> لخاصية المفتاح المقابلة بـ "org.openssl.engine:". انظر "Engine Options" في openssl(1) مثالاً لاستخدام الأخير.

الخيارات

خيارات التنسيق

الخيارات لتحديد التنسيق هي كما يلي. ارجع إلى صفحة الدليل الفردية لمعرفة الخيارات المقبولة.

-inform format, -outform format
تنسيق تدفقات الإدخال أو الإخراج.
-keyform format
تنسيق مصدر إدخال المفتاح الخاص.
-CRLform format
تنسيق مصدر إدخال CRL.

وسائط خيارات التنسيق

الوسائط المحتملة للتنسيق موصوفة أدناه. يتم قبول كل من الأحرف الكبيرة والصغيرة.

قائمة وسائط التنسيق المقبولة، والافتراضي، موصوفة في توثيق كل أمر.

DER
تنسيق ثنائي، مشفر أو محلل وفقًا لقواعد التشفير المميزة (DER) للغة بيانات ASN.1.
ENGINE
يستخدم لتحديد أن المادة المشفرة موجودة في محرك OpenSSL. يجب تكوين محرك أو تحديده باستخدام الخيار -engine. يمكن توفير كلمة مرور أو رقم PIN للمحرك باستخدام الخيار -passin.
P12
ملف مشفر بتنسيق DER يحتوي على كائن PKCS#12. قد يكون من الضروري توفير كلمة مرور فك تشفير لاسترداد المفتاح الخاص.
PEM
تنسيق نصي محدد في RFC 1421 و RFC 7468 من IETF. باختصار، هذه كتلة من التشفير base-64 (محددة في RFC 4648 من IETF)، مع خطوط محددة تستخدم لتحديد البداية والنهاية: 
يتم تجاهل النص قبل سطر BEGIN.
----- BEGIN object-type -----
OT43gQKBgQC/2OHZoko6iRlNOAQ/tMVFNq7fL81GivoQ9F1U0Qr+DH3ZfaH8eIkX
xT0ToMPJUzWAn8pZv0snA0um6SIgvkCuxO84OkANCVbttzXImIsL7pFzfcwV/ERK
UM6j0ZuSMFOCr/lGPAoOQU0fskidGEHi1/kW+suSr28TqsyYZpwBDQ==
----- END object-type -----
يتم تجاهل النص بعد سطر END أيضًا

يجب أن يتطابق object-type مع نوع الكائن المتوقع. على سبيل المثال، لن يتطابق "BEGIN X509 CERTIFICATE" إذا كان الأمر يحاول قراءة مفتاح خاص. تشمل الأنواع المدعومة:

ANY PRIVATE KEY
CERTIFICATE
CERTIFICATE REQUEST
CMS
DH PARAMETERS
DSA PARAMETERS
DSA PUBLIC KEY
EC PARAMETERS
EC PRIVATE KEY
ECDSA PUBLIC KEY
ENCRYPTED PRIVATE KEY
PARAMETERS
PKCS #7 SIGNED DATA
PKCS7
PRIVATE KEY
PUBLIC KEY
RSA PRIVATE KEY
SSL SESSION PARAMETERS
TRUSTED CERTIFICATE
X509 CRL
X9.42 DH PARAMETERS

تدعم أيضًا أنواع object-type القديمة التالية للتوافق مع الإصدارات السابقة:

DSA PRIVATE KEY
NEW CERTIFICATE REQUEST
RSA PUBLIC KEY
X509 CERTIFICATE
SMIME
كائن S/MIME كما هو موصوف في RFC 8551 من IETF. الإصدارات الأقدم كانت معروفة باسم CMS ومتوافقة. لاحظ أن التحليل بسيط وقد يفشل في تحليل بعض البيانات القانونية.
