\n

NAME

\n

oldstat, oldfstat, oldlstat - get file status (obsolete)

\n
\n
\n

LIBRARY

\n

Standard C library (libc, -lc)

\n
\n
\n

SYNOPSIS

\n

Convenience function:

\n
#include <sys/stat.h>\n\nint old_stat(const char *pathname, struct old_stat *statbuf);\nint old_fstat(int fd, struct old_stat *statbuf);\nint old_lstat(const char *pathname, struct old_stat *statbuf);\n\nint stat(const char *pathname, struct stat *statbuf);\nint fstat(int fd, struct stat *statbuf);\nint lstat(const char *pathname, struct stat *statbuf);\n
\n

Note: The old_* functions and structure are obsolete and\nshould not be used in new code.

\n
\n
\n

DESCRIPTION

\n

The stat(), fstat(), and lstat() functions\nreturn information about the file (or symbolic link in the case of\nlstat()) specified by pathname, or referenced by\nfile descriptor fd, and store it in the area pointed to by\nstatbuf.

\n

These functions differ from each other in the way they handle\nsymbolic links:

\n
    \n
  • stat() follows symbolic links: if pathname\npoints to a symbolic link, then the link itself is described, not the file\nthat it refers to.
    • \n
  • lstat() makes no distinction between symbolic links and other\nfile types; it returns information about the link itself.
    • \n
  • fstat() is like stat(), but its third argument is a file\ndescriptor, not a path name.
    • \n
\n

The statbuf argument is a pointer to a\nstruct stat structure, into which information about the file is\nstored. The structure has the following members:

\n
\n
st_dev
\n
ID of the device on which this file resides.
\n
st_ino
\n
This file's inode number.
\n
st_mode
\n
Protection bits.
\n
st_nlink
\n
Number of hard links to the file.
\n
st_uid
\n
User ID of the owner of the file.
\n
st_gid
\n
Group ID of the owner of the file.
\n
st_rdev
\n
Device ID (if this file is a device file).
\n
st_size
\n
Size of the file in bytes.
\n
st_atime
\n
Time of last access.
\n
st_atime_ns
\n
Nanoseconds part of time of last access.
\n
st_mtime
\n
Time of last modification.
\n
st_mtime_ns
\n
Nanoseconds part of time of last modification.
\n
st_ctime
\n
Time of last status change.
\n
st_ctime_ns
\n
Nanoseconds part of time of last status change.
\n
st_blksize
\n

Filesystem optimal I/O size.

\nThis field is set to the expected optimal block size for interacting with the\nphysical file system. (See also st_blocks.)
\n
st_blocks
\n

Number of 512B blocks allocated.

\nThis field is used to indicate the number of blocks allocated for this file,\nif supported by the underlying filesystem. The request for blocks is in units\nof st_blksize (see above). If possible, the value should be a multiple\nof st_blksize. However, this is not guaranteed. The value returned\nmay be 0 if the filesystem reports a block count of 0.
\n
\n

The fields st_atime, st_mtime, and st_ctime\nare time_t values. The fields st_atime_ns, st_mtime_ns,\nand st_ctime_ns are integers representing nanoseconds. The time fields\nare only guaranteed to be correct for files on local filesystems. Behaviour\nfor network filesystems (e.g. NFS) is implementation-dependent and may be\nunreliable.

\n

The macro st_size is the size of the file in bytes. For\nblock special files, `regular' files, or directories, this is the number of\nbytes in the file.

\n

The macro st_blocks is the number of blocks allocated to\nthe file for I/O purposes. The size of each block is given by st_blksize.\nThis value is typically a multiple of st_blksize. It may be less than\nst_size / st_blksize if the file has holes or if the filesystem\nallocates blocks inefficiently.

\n

The macro st_blksize is the optimal transfer block size\n(in bytes) for this file system. For example, on Linux, for an ext4 filesystem,\nthis value is typically 4096 bytes. It may be 0 if the filesystem does not\nsupport this value.

\n

The macro st_nlink is the number of hard links to the file.\nWhen st_nlink is zero after returning from these calls, the file is\neither no longer accessible, or it is an unlinked but still open file. The\nvalue st_nlink will be zero only if a \"stale\" file handle is encountered\nfor a file that has been removed.

\n

The macro st_mode is the file's type and mode. The low 16 bits\nare used for the file's permission bits. The high 16 bits define the file type.The macros S_ISBLK, S_ISCHR, S_ISDIR,\nS_ISFIFO, S_ISREG, S_ISLNK, S_ISSOCK\n(and S_ISREG etc) are defined in <sys/stat.h> and can be\nused to test the file type.

\n

The values in the st_mode field are composed from:

\n
\n
The file type mask
\n
S_IFMT (0170000)
\n
and one of
\n
S_IFREG (0100000) regular file
\n
S_IFDIR (0040000) directory
\n
S_IFCHR (0020000) character special file
\n
S_ISBLK (0060000) block special file
\n
S_ISFIFO (0010000) FIFO (named pipe)
\n
S_ISLNK (0120000) symbolic link
\n
S_ISSOCK (0140000) socket
\n
The permission bits:
\n
S_IRWXU (00700) owner has read, write, and execute permission
\n
S_IRUSR (00400) owner has read permission
\n
S_IWUSR (00200) owner has write permission
\n
S_IXUSR (00100) owner has execute permission
\n
S_IRWXG (00070) group has read, write, and execute permission
\n
S_IRGRP (00040) group has read permission
\n
S_IWGRP (00020) group has write permission
\n
S_IXGRP (00010) group has execute permission
\n
S_IRWXO (00007) others have read, write, and execute permission
\n
S_IROTH (00004) others have read permission
\n
S_IWOTH (00002) others have write permission
\n
S_IXOTH (00001) others have execute permission
\n
\n

The oldstat functions and struct old_stat structure\nwere present in older Linux systems and are provided for backward compatibility.\nNew code should use the stat, fstat, and lstat\nfunctions and the struct stat structure.

\n

POSIX.1-2001 requires that the mode bits in the st_mode field\nof the stat structure are valid, but POSIX.1-2008 tightens the\nspecification, requiring lstat() to return valid information in all\nfields except the mode bits in st_mode.

\n

Use of the st_blocks and st_blksize fields may be\nless portable. (They were introduced in BSD. The interpretation differs\nbetween systems, and possibly on a single system when NFS mounts are\ninvolved.)

\n
\n
\n

C library/kernel differences

\n

Over time, increases in the size of the stat structure have\nled to three successive versions of stat(): sys_stat() (slot\n__NR_oldstat), sys_newstat() (slot __NR_stat), and\nsys_stat64() (slot __NR_stat64) on 32-bit platforms such as\ni386. The first two versions were already present in Linux 1.0 (albeit with\ndifferent names); the last was added in Linux 2.4. Similar remarks apply for\nfstat() and lstat().

\n

The kernel-internal versions of the stat structure dealt\nwith by the different versions are, respectively:

\n
\n
__old_kernel_stat
\n
The original structure, with rather narrow fields, and no padding.
\n
stat
\n
Larger st_ino field and padding added to various parts of the\nstructure to allow for future expansion.
\n
stat64
\n
Even larger st_ino field, larger st_uid and st_gid\nfields to accommodate the Linux-2.4 expansion of UIDs and GIDs to 32 bits, and various other enlarged fields and further padding in the structure. (Various padding bytes were eventually consumed in Linux 2.6, with the\nadvent of 32-bit device IDs and nanosecond components for the timestamp\nfields.)
\n
\n

The glibc stat() wrapper function hides these details from\napplications, invoking the most recent version of the system call provided\nby the kernel, and repacking the returned information if required for old\nbinaries.

\n

On modern 64-bit systems, life is simpler: there is a single\nstat() system call and the kernel deals with a stat structure\nthat contains fields of a sufficient size.

\n

The underlying system call employed by the glibc fstatat()\nwrapper function is actually called fstatat64() or, on some\narchitectures, newfstatat().

\n

EXAMPLES

The following program calls lstat() and displays selected\nfields in the returned stat structure.

\n
#include <stdint.h>\n#include <stdio.h>\n#include <stdlib.h>\n#include <sys/stat.h>\n#include <sys/sysmacros.h>\n#include <time.h>\nint\nmain(int argc, char *argv[])\n{\n    struct stat sb;\n    if (argc != 2) {\n        fprintf(stderr, \"Usage: %s <path>\\n\", argv[0]);\n        exit(EXIT_FAILURE);\n    }\n    if (lstat(argv[1], &sb) == -1) {\n        perror(\"lstat\");\n        exit(EXIT_FAILURE);\n    }\n    printf(\"ID of containing device:  [%x,%x]\\n\",\n           major(sb.st_dev),\n           minor(sb.st_dev));\n    printf(\"File type:                \");\n    switch (sb.st_mode & S_IFMT) {\n    case S_IFBLK:  printf(\"block device\\n\");            break;\n    case S_IFCHR:  printf(\"character device\\n\");        break;\n    case S_IFDIR:  printf(\"directory\\n\");               break;\n    case S_IFIFO:  printf(\"FIFO/pipe\\n\");               break;\n    case S_IFLNK:  printf(\"symlink\\n\");                 break;\n    case S_IFREG:  printf(\"regular file\\n\");            break;\n    case S_IFSOCK: printf(\"socket\\n\");                  break;\n    default:       printf(\"unknown?\\n\");                break;\n    }\n    printf(\"I-node number:            %ju\\n\", (uintmax_t) sb.st_ino);\n    printf(\"Mode:                     %jo (octal)\\n\",\n           (uintmax_t) sb.st_mode);\n    printf(\"Link count:               %ju\\n\", (uintmax_t) sb.st_nlink);\n    printf(\"Ownership:                UID=%ju   GID=%ju\\n\",\n           (uintmax_t) sb.st_uid, (uintmax_t) sb.st_gid);\n    printf(\"Preferred I/O block size: %jd bytes\\n\",\n           (intmax_t) sb.st_blksize);\n    printf(\"File size:                %jd bytes\\n\",\n           (intmax_t) sb.st_size);\n    printf(\"Blocks allocated:         %jd\\n\",\n           (intmax_t) sb.st_blocks);\n    printf(\"Last status change:       %s\", ctime(&sb.st_ctime));\n    printf(\"Last file access:         %s\", ctime(&sb.st_atime));\n    printf(\"Last file modification:   %s\", ctime(&sb.st_mtime));\n    exit(EXIT_SUCCESS);\n}\n

الاسم

\n

oldstat, oldfstat, oldlstat - الحصول على حالة الملف (مهمل)

\n
\n
\n

المكتبة

\n

مكتبة C القياسية (libc, -lc)

\n
\n
\n

ملخص

\n

دالة مساعدة:

\n
#include <sys/stat.h>\n\nint old_stat(const char *pathname, struct old_stat *statbuf);\nint old_fstat(int fd, struct old_stat *statbuf);\nint old_lstat(const char *pathname, struct old_stat *statbuf);\n\nint stat(const char *pathname, struct stat *statbuf);\nint fstat(int fd, struct stat *statbuf);\nint lstat(const char *pathname, struct stat *statbuf);\n
\n

ملاحظة: الدوال old_* والبنية struct old_stat مهملة\nولا ينبغي استخدامها في الشفرة الجديدة.

\n
\n
\n

الوصف

\n

تقوم الدوال stat() و fstat() و lstat() بإرجاع\nمعلومات حول الملف (أو الرابط الرمزي في حالة lstat()) المحدد بواسطة\npathname، أو المشار إليه بواسطة واصف الملف fd، وتخزينها\nفي المنطقة التي يشير إليها statbuf.

\n

تختلف هذه الدوال عن بعضها البعض في طريقة تعاملها مع الروابط\nالرمزية:

\n
    \n
  • stat() يتبع الروابط الرمزية: إذا كان pathname\nيشير إلى رابط رمزي، فسيتم وصف الرابط نفسه، وليس الملف الذي يشير إليه.
    • \n
  • lstat() لا يميز بين الروابط الرمزية وأنواع الملفات الأخرى؛ فهي\nترجع معلومات حول الرابط نفسه.
    • \n
  • fstat() تشبه stat()، ولكن وسيطتها الثالثة هي واصف ملف،\nوليس اسم مسار.
    • \n
\n

الوسيط statbuf هو مؤشر إلى بنية struct stat،\nيتم تخزين المعلومات حول الملف فيها. تحتوي البنية على الأعضاء التالية:

\n
\n
st_dev
\n
معرف الجهاز الذي يوجد عليه هذا الملف.
\n
st_ino
\n
رقم الـ inode لهذا الملف.
\n
st_mode
\n
بتات الحماية.
\n
st_nlink
\n
عدد الروابط الصلبة للملف.
\n
st_uid
\n
معرف المستخدم لمالك الملف.
\n
st_gid
\n
معرف المجموعة لمالك الملف.
\n
st_rdev
\n
معرف الجهاز (إذا كان هذا الملف ملف جهاز).
\n
st_size
\n
حجم الملف بالبايت.
\n
st_atime
\n
وقت آخر وصول.
\n
st_atime_ns
\n
جزء النانو ثانية من وقت آخر وصول.
\n
st_mtime
\n
وقت آخر تعديل.
\n
st_mtime_ns
\n
جزء النانو ثانية من وقت آخر تعديل.
\n
st_ctime
\n
وقت آخر تغيير في الحالة.
\n
st_ctime_ns
\n
جزء النانو ثانية من وقت آخر تغيير في الحالة.
\n
st_blksize
\n

حجم الإدخال / الإخراج الأمثل لنظام الملفات.

\nيتم تعيين هذا الحقل إلى حجم الكتلة الأمثل المتوقع للتفاعل مع نظام الملفات\nالفعلي. (انظر أيضًا st_blocks).
\n
st_blocks
\n

عدد الكتل التي بحجم 512 بايت المخصصة.

\nيستخدم هذا الحقل للإشارة إلى عدد الكتل المخصصة لهذا الملف، إذا كان مدعومًا\nمن نظام الملفات الأساسي. الطلب على الكتل يكون بوحدات st_blksize (انظر\nأعلاه). إذا أمكن، يجب أن تكون القيمة مضاعفًا لـ st_blksize. ومع ذلك،\nهذا غير مضمون. قد تكون القيمة المرجعة 0 إذا كان نظام الملفات يبلغ عن عدد كتل\nيساوي 0.
\n
\n

الحقول st_atime و st_mtime و st_ctime\nهي قيم time_t. الحقول st_atime_ns و st_mtime_ns و\nst_ctime_ns هي أعداد صحيحة تمثل النانو ثانية. الحقول الزمنية مضمونة\nأن تكون صحيحة فقط للملفات الموجودة على أنظمة الملفات المحلية. سلوك أنظمة\nالملفات الشبكية (مثل NFS) يعتمد على التنفيذ وقد يكون غير موثوق به.

\n

الماكرو st_size هو حجم الملف بالبايت. بالنسبة لملفات الكتل\nالخاصة، والملفات \"العادية\"، أو الدلائل، يكون هذا هو عدد البايتات في الملف.

\n

الماكرو st_blocks هو عدد الكتل المخصصة للملف لأغراض الإدخال\n/ الإخراج. حجم كل كتلة معطى بواسطة st_blksize. هذه القيمة عادة ما تكون\nمضاعفًا لـ st_blksize. قد تكون أقل من st_size / st_blksize\nإذا كان للملف ثقوب أو إذا قام نظام الملفات بتخصيص كتل بشكل غير فعال.

\n

الماكرو st_blksize هو حجم الكتلة الأمثل للنقل (بالبايت) لنظام\nالملفات هذا. على سبيل المثال، في لينكس، لنظام ملفات ext4، عادة ما يكون حجم\nهذه القيمة 4096 بايت. قد تكون 0 إذا لم يكن نظام الملفات يدعم هذه القيمة.

\n

الماكرو st_nlink هو عدد الروابط الصلبة للملف. عندما يكون\nst_nlink صفرًا بعد العودة من هذه الاستدعاءات، فإن الملف لم يعد\nقابلاً للوصول إليه، أو أنه ملف مفتوح تم إلغاء ربطه. ستكون القيمة st_nlink\nصفرًا فقط إذا تم مواجهة مقبض ملف \"غير صالح\" لملف تم حذفه.

\n

الماكرو st_mode هو نوع الملف ووضعه. تستخدم الـ 16 بت السفلية\nلبتات إذن الملف. تحدد الـ 16 بت العلوية نوع الملف.الماكروات S_ISBLK و S_ISCHR و S_ISDIR و\nS_ISFIFO و S_ISREG و S_ISLNK و S_ISSOCK\n(و S_ISREG إلخ) معرفة في <sys/stat.h> ويمكن\nاستخدامها لاختبار نوع الملف.

\n

تتكون القيم في حقل st_mode مما يلي:

\n
\n
قناع نوع الملف
\n
S_IFMT (0170000)
\n
وواحد من
\n
S_IFREG (0100000) ملف عادي
\n
S_IFDIR (0040000) دليل
\n
S_IFCHR (0020000) ملف حرف خاص
\n
S_ISBLK (0060000) ملف كتلة خاص
\n
S_ISFIFO (0010000) FIFO (أنبوب مسمى)
\n
S_ISLNK (0120000) رابط رمزي
\n

\n
بتات الإذن:

S_IRWXU (00700) يمتلك المالك إذن القراءة والكتابة والتنفيذ
\n
S_IRUSR (00400) يمتلك المالك إذن القراءة
\n
S_IWUSR (00200) يمتلك المالك إذن الكتابة
\n
S_IXUSR (00100) يمتلك المالك إذن التنفيذ
\n
S_IRWXG (00070) تمتلك المجموعة إذن القراءة والكتابة والتنفيذ
\n
S_IRGRP (00040) تمتلك المجموعة إذن القراءة
\n
S_IWGRP (00020) تمتلك المجموعة إذن الكتابة
\n
S_IXGRP (00010) تمتلك المجموعة إذن التنفيذ
\n
S_IRWXO (00007) يمتلك الآخرون إذن القراءة والكتابة والتنفيذ
\n
S_IROTH (00004) يمتلك الآخرون إذن القراءة
\n
S_IWOTH (00002) يمتلك الآخرون إذن الكتابة
\n
S_IXOTH (00001) يمتلك الآخرون إذن التنفيذ
\n
\n

كانت الدوال oldstat والبنية struct old_stat موجودة\nفي أنظمة لينكس الأقدم ويتم توفيرها للتوافق الرجعي. يجب على الشفرة الجديدة\nاستخدام الدوال stat و fstat و lstat والبنية\nstruct stat.

\n

تُحكم POSIX.1-2001 على أن تكون بتات الوضع في حقل st_mode\nمن بنية stat صالحة، لكن POSIX.1-2008 تُشدد المواصفات، مطالبةً\nlstat() بإرجاع معلومات صالحة في جميع الحقول باستثناء بتات الوضع في\nst_mode.

\n

قد يكون استخدام حقلي st_blocks و st_blksize\nأقل قابلية للنقل. (تم تقديمها في BSD. يختلف التفسير بين الأنظمة، وربما على\nنظام واحد عند التعامل مع عمليات تحميل NFS.)

فروقات مكتبة C/النواة

\n

بمرور الوقت، أدت الزيادات في حجم بنية stat إلى ثلاث\nإصدارات متتالية من stat(): sys_stat() (الفتحة\n__NR_oldstat)، sys_newstat() (الفتحة __NR_stat)،\nو sys_stat64() (الفتحة __NR_stat64) على المنصات 32 بت مثل\ni386. كان الإصداران الأولان موجودين بالفعل في Linux 1.0 (وإن كانا\nبأسماء مختلفة)؛ تمت إضافة الأخير في Linux 2.4. تنطبق ملاحظات مماثلة\nلـ fstat() و lstat().

\n

إصدارات البنية الداخلية للنواة لبنية stat التي تتعامل\nمعها الإصدارات المختلفة هي، على التوالي:

\n
\n
__old_kernel_stat
\n
البنية الأصلية، بحقول ضيقة نسبيًا، ولا تحتوي على حشو.
\n
stat
\n
حقل st_ino أكبر وحشو مضاف إلى أجزاء مختلفة من البنية للسماح\nبالتوسع المستقبلي.
\n
stat64
\n
حقل st_ino أكبر، وحقول st_uid و st_gid أكبر\n لاستيعاب توسيع Linux-2.4 لمعرفات المستخدم (UIDs) ومعرفات المجموعة (GIDs) إلى 32 بت،\n وحقول أخرى متنوعة مكبرة ومزيد من الحشو في البنية. (تم استهلاك بايتات حشو\nمختلفة في النهاية في Linux 2.6، مع ظهور معرفات الأجهزة 32 بت ومكونات النانو ثانية\nللحقول الزمنية.)
\n
\n

تقوم دالة التغليف stat() في glibc بإخفاء هذه التفاصيل عن\nالتطبيقات، واستدعاء أحدث إصدار من استدعاء النظام الذي توفره النواة، وإعادة\nتجميع المعلومات المرجعة إذا لزم الأمر للملفات الثنائية القديمة.

\n

على الأنظمة الحديثة 64 بت، الحياة أبسط: يوجد استدعاء نظام واحد\nstat() وتتعامل النواة مع بنية stat تحتوي على حقول بحجم\nكافٍ.

\n

استدعاء النظام الأساسي الذي تستخدمه دالة التغليف fstatat()\nفي glibc يسمى فعليًا fstatat64() أو، على بعض البنى،\nnewfstatat().

\n
\n\n
\n

أمثلة

\n

يستدعي البرنامج التالي lstat() ويعرض الحقول المحددة في بنية\nstat المرجعة.

\n
#include <stdint.h>\n#include <stdio.h>\n#include <stdlib.h>\n#include <sys/stat.h>\n#include <sys/sysmacros.h>\n#include <time.h>\nint\nmain(int argc, char *argv[])\n{\n    struct stat sb;\n    if (argc != 2) {\n        fprintf(stderr, \"Usage: %s <path>\\n\", argv[0]);\n        exit(EXIT_FAILURE);\n    }\n    if (lstat(argv[1], &sb) == -1) {\n        perror(\"lstat\");\n        exit(EXIT_FAILURE);\n    }\n    printf(\"ID of containing device:  [%x,%x]\\n\",\n           major(sb.st_dev),\n           minor(sb.st_dev));\n    printf(\"File type:                \");\n    switch (sb.st_mode & S_IFMT) {\n    case S_IFBLK:  printf(\"block device\\n\");            break;\n    case S_IFCHR:  printf(\"character device\\n\");        break;\n    case S_IFDIR:  printf(\"directory\\n\");               break;\n    case S_IFIFO:  printf(\"FIFO/pipe\\n\");               break;\n    case S_IFLNK:  printf(\"symlink\\n\");                 break;\n    case S_IFREG:  printf(\"regular file\\n\");            break;\n    case S_IFSOCK: printf(\"socket\\n\");                  break;\n    default:       printf(\"unknown?\\n\");                break;\n    }\n    printf(\"I-node number:            %ju\\n\", (uintmax_t) sb.st_ino);\n    printf(\"Mode:                     %jo (octal)\\n\",\n           (uintmax_t) sb.st_mode);\n    printf(\"Link count:               %ju\\n\", (uintmax_t) sb.st_nlink);\n    printf(\"Ownership:                UID=%ju   GID=%ju\\n\",\n           (uintmax_t) sb.st_uid, (uintmax_t) sb.st_gid);\n    printf(\"Preferred I/O block size: %jd bytes\\n\",\n           (intmax_t) sb.st_blksize);\n    printf(\"File size:                %jd bytes\\n\",\n           (intmax_t) sb.st_size);\n    printf(\"Blocks allocated:         %jd\\n\",\n           (intmax_t) sb.st_blocks);\n    printf(\"Last status change:       %s\", ctime(&sb.st_ctime));\n    printf(\"Last file access:         %s\", ctime(&sb.st_atime));\n    printf(\"Last file modification:   %s\", ctime(&sb.st_mtime));\n    exit(EXIT_SUCCESS);\n}\n
