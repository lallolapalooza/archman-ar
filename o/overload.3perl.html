الآن يمكن الوصول إلى الكائن باستخدام كل من صيغة المصفوفة وصيغة الهاش:

my $bar = two_refs->new(3,4,5,6);
$bar->[2] = 11;
$bar->{two} == 11 or die 'bad hash fetch';

لاحظ العديد من الميزات الهامة في هذا المثال. أولاً وقبل كل شيء، فإن النوع الفعلي لـ $bar هو مرجع عددي (scalar reference)، ونحن لا نقوم بتحميل (overload) تفكيك المراجع العددية. بالتالي يمكننا الحصول على محتويات $bar الفعلية غير المحملة بمجرد استخدام $$bar (وهو ما نفعله في الدوال التي تحمل تفكيك المراجع). وبالمثل، الكائن الذي تم إرجاعه بواسطة الدالة TIEHASH() هو مرجع عددي.

ثانياً، نقوم بإنشاء هاش مرتبط (tied hash) جديد في كل مرة يتم فيها استخدام صيغة الهاش. هذا يسمح لنا بعدم القلق بشأن احتمال وجود حلقة مراجع، مما قد يؤدي إلى تسرب في الذاكرة.

يمكن علاج هاتين المشكلتين. على سبيل المثال، إذا أردنا تحميل تفكيك الهاش على مرجع لكائن تم تنفيذه كهاش بنفسه، فإن المشكلة الوحيدة التي يجب التغلب عليها هي كيفية الوصول إلى هذا الهاش الفعلي (على عكس الهاش الافتراضي الذي يتم عرضه بواسطة عامل تفكيك المراجع المحمل).

إليك أحد روتينات الجلب الممكنة:

sub access_hash {
    my ($self, $key) = (shift, shift);
    my $class = ref $self;
    bless $self, 'overload::dummy'; # Disable overloading of %{}
    my $out = $self->{$key};
    bless $self, $class;            # Restore overloading
    $out;
}

لإزالة إنشاء الهاش المرتبط عند كل وصول، قد تحتاج إلى مستوى إضافي من التحويل غير المباشر الذي يسمح ببنية مراجع غير دائرية:

package two_refs1;
use overload
    '%{}' => sub { ${shift()}->[1] },
    '@{}' => sub { ${shift()}->[0] };
sub new {
    my $p = shift;
    my $a = [@_];
    my %h;
    tie %h, $p, $a;
    bless \ [$a, \%h], $p;
}
sub gethash {
    my %h;
    my $self = shift;
    tie %h, ref $self, $self;
    \%h;
}
sub TIEHASH { my $p = shift; bless \ shift, $p }
my %fields;
my $i = 0;
$fields{$_} = $i++ foreach qw{zero one two three};
sub STORE {
    my $a = ${shift()};
    my $key = $fields{shift()};
    defined $key or die "Out of band access";
    $a->[$key] = shift;
}
sub FETCH {
    my $a = ${shift()};
    my $key = $fields{shift()};
    defined $key or die "Out of band access";
    $a->[$key];
}

الآن إذا تم تحميل $baz بهذه الطريقة، فإن $baz هو مرجع لمرجع للمصفوفة الوسيطة، والتي تحتفظ بمرجع للمصفوفة الفعلية، وهاش الوصول. الكائن الذي يتم ربطه (tieing object) لهاش الوصول هو مرجع لمرجع للمصفوفة الفعلية، لذلك:

  • لا توجد حلقات مراجع.
  • كلا "الكائنين" المباركين (blessed) في الفئة "two_refs1" هما مراجع لمراجع لمصفوفة، وبالتالي مراجع لـ عدد صحيح (scalar). لذلك، فإن تعبير الوصول "$$foo->[$ind]" لا يتضمن أي عمليات محملة.

حاسبة رمزية

ضع هذا في symbolic.pm في دليل وحدات Perl الخاص بك:

package symbolic;           # Primitive symbolic calculator
use overload nomethod => \&wrap;
sub new { shift; bless ['n', @_] }
sub wrap {
    my ($obj, $other, $inv, $meth) = @_;
    ($obj, $other) = ($other, $obj) if $inv;
    bless [$meth, $obj, $other];
}

هذه الوحدة غير عادية للغاية بالنسبة للوحدات المحملة: فهي لا توفر أي عوامل تشغيل محملة عادية، بدلاً من ذلك توفر تنفيذًا لـ "nomethod". في هذا المثال، تقوم الدالة "nomethod" بإرجاع كائن يغلف العمليات التي تتم على الكائنات: "symbolic->new(3)" تحتوي على "['n', 3]"، "2 + symbolic->new(3)" تحتوي على "['+', 2, ['n', 3]]".

إليك مثال على البرنامج النصي الذي "يحسب" جانب المثمن المحاط (circumscribed octagon) باستخدام الحزمة أعلاه:

require symbolic;
my $iter = 1;                   # 2**($iter+2) = 8
my $side = symbolic->new(1);
my $cnt = $iter;
while ($cnt--) {
    $side = (sqrt(1 + $side**2) - 1)/$side;
}
print "OK\n";

قيمة $side هي:

['/', ['-', ['sqrt', ['+', 1, ['**', ['n', 1], 2]],
                    undef], 1], ['n', 1]]

لاحظ أنه بينما حصلنا على هذه القيمة باستخدام برنامج نصي صغير لطيف، لا توجد طريقة سهلة لاستخدام هذه القيمة. في الواقع، يمكن فحص هذه القيمة في مصحح الأخطاء (debugger) (انظر perldebug)، ولكن فقط إذا تم تعيين خيار "bareStringify" O، وليس عبر الأمر "p".

إذا حاول شخص ما طباعة هذه القيمة، فسيتم استدعاء عامل التشغيل المحمل ""، والذي سيستدعي عامل التشغيل "nomethod". سيتم تحويل نتيجة هذا العامل إلى سلسلة مرة أخرى، ولكن هذه النتيجة هي مرة أخرى من النوع "symbolic"، مما سيؤدي إلى حلقة لا نهائية.

أضف دالة طباعة جميلة (pretty-printer) إلى الوحدة symbolic.pm:

sub pretty {
    my ($meth, $a, $b) = @{+shift};
    $a = 'u' unless defined $a;
    $b = 'u' unless defined $b;
    $a = $a->pretty if ref $a;
    $b = $b->pretty if ref $b;
    "[$meth $a $b]";
}

الآن يمكن إنهاء البرنامج النصي بـ:

print "side = ", $side->pretty, "\n";

الدالة "pretty" تقوم بتحويل من كائن إلى سلسلة (object-to-string conversion)، لذا من الطبيعي تحميل عامل التشغيل "" باستخدام هذه الدالة. ومع ذلك، داخل مثل هذه الدالة، ليس من الضروري طباعة مكونات $a و $b للكائن بطريقة جميلة. في الدالة أعلاه، "[$meth $a $b]" هو ربط (catenation) لبعض السلاسل النصية والمكونات $a و $b. إذا كانت هذه المكونات تستخدم التحميل (overloading)، فإن عامل تشغيل الربط سيبحث عن عامل التشغيل المحمل "."؛ إذا لم يكن موجودًا، فسيبحث عن عامل التشغيل المحمل "". لذلك يكفي استخدام:

use overload nomethod => \&wrap, '""' => \&str;
sub str {
    my ($meth, $a, $b) = @{+shift};
    $a = 'u' unless defined $a;
    $b = 'u' unless defined $b;
    "[$meth $a $b]";
}

الآن يمكن تغيير السطر الأخير من البرنامج النصي إلى:

print "side = $side\n";

والذي يخرج:

side = [/ [- [sqrt [+ 1 [** [n 1] 2]]] 1] [n 1]]

ويمكنك فحص القيمة في مصحح الأخطاء باستخدام جميع الطرق الممكنة.

لا يزال هناك خطأ ما: ضع في اعتبارك متغير الحلقة $cnt في البرنامج النصي. كان رقمًا، وليس كائنًا. لا يمكننا جعل قيمة $cnt من النوع "symbolic"، لأن الحلقة لن تنتهي.

في الواقع، لإنهاء الدورة، يجب أن يصبح $cnt خاطئًا (false). ومع ذلك، فإن عامل التشغيل "bool" للتحقق من الخطأ تم تحميله (هذه المرة عبر "" المحمل)، ويعيد سلسلة طويلة، وبالتالي فإن أي كائن من النوع "symbolic" يكون صحيحًا (true). للتغلب على هذا، نحتاج إلى طريقة لمقارنة كائن بالرقم 0. في الواقع، من الأسهل كتابة روتين تحويل رقمي.

هذا هو نص symbolic.pm مع إضافة مثل هذا الروتين (وتعديل طفيف لـ str()):

package symbolic;           # Primitive symbolic calculator
use overload
    nomethod => \&wrap, '""' => \&str, '0+' => \&num;
sub new { shift; bless ['n', @_] }
sub wrap {
    my ($obj, $other, $inv, $meth) = @_;
    ($obj, $other) = ($other, $obj) if $inv;
    bless [$meth, $obj, $other];
}
sub str {
    my ($meth, $a, $b) = @{+shift};
    $a = 'u' unless defined $a;
    if (defined $b) {
        "[$meth $a $b]";
    } else {
        "[$meth $a]";
    }
}
my %subr = (
    n => sub {$_[0]},
    sqrt => sub {sqrt $_[0]},
    '-' => sub {shift() - shift()},
    '+' => sub {shift() + shift()},
    '/' => sub {shift() / shift()},
    '*' => sub {shift() * shift()},
    '**' => sub {shift() ** shift()},
);
sub num {
    my ($meth, $a, $b) = @{+shift};
    my $subr = $subr{$meth}
    or die "Do not know how to ($meth) in symbolic";
    $a = $a->num if ref $a eq __PACKAGE__;
    $b = $b->num if ref $b eq __PACKAGE__;
    $subr->($a,$b);
}

كل العمل الخاص بالتحويل الرقمي يتم في %subr و num(). بالطبع، %subr ليست كاملة، فهي تحتوي فقط على العمليات المستخدمة في المثال أدناه. إليك سؤال إضافي: لماذا نحتاج إلى استدعاء تكراري صريح في num()؟ (الإجابة في نهاية هذا القسم.)

استخدم هذه الوحدة كالتالي:

require symbolic;
my $iter = symbolic->new(2);        # 16-gon
my $side = symbolic->new(1);
my $cnt = $iter;
while ($cnt) {
    $cnt = $cnt - 1;                # Mutator '--' not implemented
    $side = (sqrt(1 + $side**2) - 1)/$side;
}
printf "%s=%f\n", $side, $side;
printf "pi=%f\n", $side*(2**($iter+2));

                        [n 1]] 2]]] 1]

الوحدة أعلاه بدائية للغاية. لا تطبق دوال التعديل (mutator methods) ("++"، "-=" وما إلى ذلك)، ولا تقوم بالنسخ العميق (ليس مطلوبًا بدون دوال التعديل!)، وتطبق فقط تلك العمليات الحسابية المستخدمة في المثال.

لتطبيق معظم العمليات الحسابية أمر سهل؛ يجب فقط استخدام جداول العمليات، وتغيير الكود الذي يملأ %subr إلى:

my %subr = ( 'n' => sub {$_[0]} );
foreach my $op (split " ", $overload::ops{with_assign}) {
    $subr{$op} = $subr{"$op="} = eval "sub {shift() $op shift()}";
}
my @bins = qw(binary 3way_comparison num_comparison str_comparison);
foreach my $op (split " ", "@overload::ops{ @bins }") {
    $subr{$op} = eval "sub {shift() $op shift()}";
}
foreach my $op (split " ", "@overload::ops{qw(unary func)}") {
    print "defining '$op'\n";
    $subr{$op} = eval "sub {$op shift()}";
}

نظرًا لأن الدوال الفرعية التي تنفذ عوامل تشغيل التعيين ليست مطالبة بتعديل معاملاتهم (انظر "العمليات القابلة للتحميل" أعلاه)، فنحن لا نحتاج إلى أي شيء خاص ت

لـ

لجعل "&plusmn;" والأصدقاء يعملون، بالإضافة إلى إضافة هذه المعاملات إلى %subr وتحديد مُنشئ نسخ (مطلوب نظرًا لعدم وجود طريقة في Perl لمعرفة أن تنفيذ "+=" لا يغير الوسيط - انظر "مُنشئ النسخ").

لتنفيذ مُنشئ نسخ، أضف "'=' &=> \&cpy" إلى سطر "use overload"، وقم بترميز (يفترض هذا الترميز أن المُعدِّلات تغير الأشياء على مستوى واحد فقط، لذلك لا يلزم النسخ المتكرر):

sub cpy {
    my $self = shift;
    bless [@$self], ref $self;
}

لجعل "++" و "--" يعملان، نحتاج إلى تنفيذ مُعدِّلات فعلية، إما بشكل مباشر، أو في "nomethod". نواصل القيام بالأشياء داخل "nomethod"، وبالتالي نضيف

if ($meth eq '++' or $meth eq '--') {
    @$obj = ($meth, (bless [@$obj]), 1); # تجنب المرجع الدائري
    return $obj;
}

بعد السطر الأول من wrap(). هذه ليست أكثر تنفيذ فعالية، قد يفكر المرء في

sub inc { $_[0] = bless ['++', shift, 1]; }

بدلاً من ذلك.

كملاحظة أخيرة، لاحظ أنه يمكن ملء %subr بواسطة

my %subr = ( 'n' => sub {$_[0]} );
foreach my $op (split " ", $overload::ops{with_assign}) {
    $subr{$op} = $subr{"$op="} = eval "sub {shift() $op shift()}";
}
my @bins = qw(binary 3way_comparison num_comparison str_comparison);
foreach my $op (split " ", "@overload::ops{ @bins }") {
    $subr{$op} = eval "sub {shift() $op shift()}";
}
foreach my $op (split " ", "@overload::ops{qw(unary func)}") {
    $subr{$op} = eval "sub {$op shift()}";
}
$subr{'++'} = $subr{'+'};
$subr{'--'} = $subr{'-'};

هذا يكمل تنفيذ آلة حاسبة رمزية بدائية في 50 سطرًا من كود Perl. نظرًا لأن القيم الرقمية للتعبيرات الفرعية ليست مخزنة مؤقتًا، فإن الآلة الحاسبة بطيئة جدًا.

هذا هو الجواب على التمرين: في حالة str()، لا نحتاج إلى تكرار صريح لأن معامل "." المُحمّل بشكل زائد سيعود إلى معامل مُحمّل بشكل زائد موجود "". المعاملات الحسابية المُحمّلة بشكل زائد *لا* تعود إلى التحويل الرقمي إذا لم يتم طلب "fallback" بشكل صريح. وبالتالي، بدون تكرار صريح، ستقوم num() بتحويل "['+', $a, $b]" إلى "$a + $b"، والتي ستعيد بناء وسيط num().

إذا كنت تتساءل لماذا تختلف القيم الافتراضية للتحويل لـ str() و num()، لاحظ مدى سهولة كتابة الآلة الحاسبة الرمزية. هذه البساطة ترجع إلى اختيار مناسب للقيم الافتراضية. ملاحظة إضافية: نظرًا للتكرار الصريح، فإن num() أكثر هشاشة من sym(): نحتاج إلى التحقق صراحةً من نوع $a و $b. إذا كانت المكونات $a و $b من نوع ذي صلة، فقد يؤدي ذلك إلى مشاكل.

آلة حاسبة رمزية *حقًا*

قد يتساءل المرء لماذا نسمي الآلة الحاسبة أعلاه رمزية. السبب هو أن الحساب الفعلي لقيمة التعبير مؤجل حتى *يتم استخدام* القيمة.

لرؤيتها أثناء العمل، أضف طريقة

sub STORE {
    my $obj = shift;
    $#$obj = 1;
    @$obj->[0,1] = ('=', shift);
}

إلى الحزمة "symbolic". بعد هذا التغيير، يمكنك القيام

my $a = symbolic->new(3);
my $b = symbolic->new(4);
my $c = sqrt($a**2 + $b**2);

وتصبح القيمة الرقمية لـ $c هي 5. ومع ذلك، بعد استدعاء

$a->STORE(12);  $b->STORE(5);

تصبح القيمة الرقمية لـ $c هي 13. لا يوجد شك الآن في أن الوحدة symbolic توفر آلة حاسبة *رمزية* بالفعل.

لإخفاء الحواف الخشنة تحت الغطاء، قم بتوفير واجهة tie() للحزمة "symbolic". أضف طرق

sub TIESCALAR { my $pack = shift; $pack->new(@_) }
sub FETCH { shift }
sub nop {  }                # حول خطأ

(الخطأ، تم إصلاحه في Perl 5.14، موصوف في "BUGS"). يمكن للمرء استخدام هذه الواجهة الجديدة مثل

tie $a, 'symbolic', 3;
tie $b, 'symbolic', 4;
$a->nop;  $b->nop;          # حول خطأ
my $c = sqrt($a**2 + $b**2);

الآن القيمة الرقمية لـ $c هي 5. بعد "$a = 12; $b = 5"، تصبح القيمة الرقمية لـ $c هي 13. لعزل مستخدم الوحدة، أضف طريقة

sub vars { my $p = shift; tie($_, $p), $_->nop foreach @_; }

الآن

my ($a, $b);
symbolic->vars($a, $b);
my $c = sqrt($a**2 + $b**2);
$a = 3; $b = 4;
printf "c5  %s=%f\n", $c, $c;
$a = 12; $b = 5;
printf "c13  %s=%f\n", $c, $c;

يُظهر أن القيمة الرقمية لـ $c تتبع التغييرات في قيم $a و $b.

انظر أيضًا

يمكن استخدام الأمر "overloading" لتمكين أو تعطيل العمليات المُحمّلة بشكل زائد ضمن نطاق تشعب - انظر overloading.

التشخيصات

عند تشغيل Perl مع المفتاح -Do أو ما يعادله، تثير التحميل الزائد رسائل تشخيصية.

باستخدام الأمر "m" من مصحح Perl (انظر perldebug) يمكن استنتاج العمليات التي يتم تحميلها بشكل زائد (وأي سلف يؤدي إلى هذا التحميل الزائد). على سبيل المثال، إذا تم تحميل "eq" بشكل زائد، فإن الطريقة "(eq" يتم عرضها بواسطة المصحح. الطريقة "()" تقابل مفتاح "fallback" (في الواقع، وجود هذه الطريقة يظهر أن هذه الحزمة لديها تحميل زائد ممكّن، وهي ما تستخدمه الدالة "Overloaded" من الوحدة "overload").

قد تصدر الوحدة التحذيرات التالية:

عدد فردي من الوسائط لـ overload::constant
(W) احتوى استدعاء overload::constant على عدد فردي من الوسائط. يجب أن تأتي الوسائط في أزواج.
"%s" ليس نوعًا قابلاً للتحميل الزائد
(W) حاولت تحميل ثابت لا تعرفه حزمة التحميل الزائد.
"%s" ليس مرجع رمز
(W) الوسيط الثاني (الرابع، السادس، ...) لـ overload::constant يحتاج إلى أن يكون مرجع رمز. إما روتين مجهول، أو مرجع لروتين.
وسيط overload '%s' غير صالح
(W) تم تمرير وسيط لـ "use overload" لم تتعرف عليه. هل أخطأت في كتابة عامل؟

الأخطاء والمزالق

  • مأزق عند كون fallback TRUE وتعود Perl إلى التنفيذ المضمن لعامل هو أن بعض العوامل لها دلالات متعددة، على سبيل المثال "|": 
    use overload '0+' => sub { $_[0]->{n}; },
    fallback => 1;
my $x = bless { n => 4 }, "main";
my $y = bless { n => 8 }, "main";
print $x | $y, "\n";

    قد تتوقع أن يخرج هذا "12". في الواقع، يطبع "<": نتيجة ASCII لمعاملة "|" كعامل سلسلة ثنائي البت - أي، نتيجة معاملة المعاملات كسلاسل "4" و "8" بدلاً من الأرقام. حقيقة أن التحويل الرقمي ("0+") منفذ ولكن التحويل النصي ("") غير منفذ لا فرق له لأن الأخير تم إنشاؤه تلقائيًا من الأول.

    الطريقة الوحيدة لتغيير هذا هي توفير روتين خاص بك لـ '|'.

  • يزيد الإنشاء التلقائي للسحر من احتمالية إنشاء هياكل ذاتية الإشارة عن غير قصد. حاليًا، لن تحرر Perl الهياكل ذاتية الإشارة حتى يتم كسر الدورات بشكل صريح. على سبيل المثال، 
    use overload '+' => 'add';
sub add { bless [ \$_[0], \$_[1] ] };

    يطلب المشاكل، لأن

    $obj += $y;

    سيصبح فعليًا

    $obj = add($obj, $y, undef);

    مع نفس نتيجة

    $obj = [\$obj, \$foo];

    حتى لو لم تكن هناك متغيرات تعيين *صريحة* للعوامل في البرنامج النصي، فقد يتم إنشاؤها بواسطة المحسن. على سبيل المثال،

    "obj = $obj\n"

    قد يتم تحسينه إلى

    my $tmp = 'obj = ' . $obj;  $tmp .= "\n";
  • يتم ملء جدول الرموز بأسماء تبدو كضوضاء في سطر.
  • تم إصلاح هذا الخطأ في Perl 5.18، ولكن قد يظل يسبب لك مشاكل إذا كنت تستخدم إصدارات أقدم:

    لأغراض الوراثة، تتصرف كل حزمة مُحمّلة بشكل زائد كما لو كان "fallback" موجودًا (ربما غير معرّف). قد يؤدي هذا إلى تأثيرات مثيرة للاهتمام إذا لم تكن هناك حزمة مُحمّلة بشكل زائد، ولكنها ترث من حزمتين مُحمّلتين بشكل زائد.

  • قبل Perl 5.14، كانت العلاقة بين التحميل الزائد و tie() معطلة. كان يتم تشغيل التحميل الزائد أو عدمه بناءً على الفئة *السابقة* للمتغير tie().

    حدث هذا لأن وجود التحميل الزائد تم فحصه مبكرًا جدًا، قبل محاولة الوصول إلى tie(). إذا لم تتغير فئة القيمة التي تم جلبها FETCH() من المتغير المرتبط، فإن الحل البديل البسيط للكود الذي سيتم تشغيله على إصدارات Perl الأقدم هو الوصول إلى القيمة (عبر "() = $foo" أو ما شابه) فورًا بعد الربط، بحيث بعد هذا الاستدعاء، تتطابق الفئة *السابقة* مع الفئة الحالية.

  • الكلمات المجردة غير مغطاة بثوابت السلسلة المُحمّلة بشكل زائد.
  • لا يمكن تحميل معامل النطاق ".." بشكل زائد.
