الحزمة: containers-common

التراخيص: Apache-2.0

NAME

oci-hooks - OCI hooks configuration

SYNOPSIS

The OCI hooks are defined in JSON files located in /etc/containers/oci/hooks.d/.

DESCRIPTION

OCI hooks allow users to inject custom commands into the container runtime lifecycle. These commands can be executed at various stages of the container lifecycle, such as pre-start, post-start, pre-stop, post-stop, and post-cleanup.

The configuration files for OCI hooks are located in the /etc/containers/oci/hooks.d/ directory. Each file in this directory should be a valid JSON file describing a single hook.

A hook configuration file must contain the following keys:

hook
The path to the executable hook binary.
stages
An array of strings specifying the stages at which the hook should be executed. Possible values are prestart, poststart, prestop, poststop, and postcleanup.

Optional keys include:

arguments
An array of strings representing command-line arguments to be passed to the hook executable.
env
An array of strings representing environment variables to be set for the hook executable.
hasbindmounts
A boolean value indicating whether the hook requires access to bind mounted filesystems. If set to true, the hook will be executed in a context where bind mounts are available.
annotations
An array of strings representing regular expressions. The hook will only be executed if one of the container's annotations matches any of these regular expressions.

Directories

Hooks are read from the directory /etc/containers/oci/hooks.d/. The files are processed in lexicographical order. For more details, see the OCI Runtime Specification.

EXAMPLE

The following example configures a hook named oci-umount to be executed in the prestart stage. It also passes the --debug argument to the hook and indicates that the hook requires access to bind mounts.

$ cat /etc/containers/oci/hooks.d/oci-umount.json
{
  "hook": "/usr/libexec/oci/hooks.d/oci-umount",
  "arguments": ["--debug"],
  "hasbindmounts": true,
  "stages": ["prestart"]
}

The following example injects nvidia-container-runtime-hook prestart in the pre-start stage if the container is configured with an annotations entry whose value matches .*fluid-dynamics.*.

$ cat /etc/containers/oci/hooks.d/osystemd-hook.json
{
  "hook": "/usr/sbin/nvidia-container-runtime-hook",
  "arguments": ["prestart"],
  "annotations: [".*fluid-dynamics.*"],
  "stages": ["prestart"]
}
