إصدار واجهة سطر الأوامر CLI VERSION

يجب على جميع النصوص البرمجية والاستدعاءات البرمجية لـ opam استخدام `--cli' لضمان عملها بسلاسة مع الإصدارات المستقبلية من عميل opam. بالإضافة إلى ذلك، يمكن للمقالات الإخبارية أو الوثائق الأخرى الاستفادة، حيث إنها تمنع المعلومات من أن تصبح قديمة.

على الرغم من أن opam يدعم الجذور (~/.opam/) فقط للإصدار الحالي، إلا أنه يوفر توافقًا رجعيًا لواجهة سطر الأوامر الخاصة به.

نظرًا لأن دعم إصدار CLI تم إضافته فقط في opam 2.1، استخدم OPAMCLI لتحديد دعم 2.0 (حيث سيتجاهله opam 2.0 ببساطة)، و `--cli=2.1' للإصدارات 2.1 (أو أحدث)، حيث أن متغير البيئة الذي يتحكم في تحليل الصيغة يكون هشًا. لهذا الغرض، يعرض opam تحذيرًا إذا حددت OPAMCLI إصدارًا صالحًا بخلاف 2.0، وكذلك إذا تم تحديد `--cli=2.0'.

يتم تحديد إصدار سطر الأوامر عن طريق استخدام الخيار `--cli` أو متغير البيئة OPAMCLI. يمكن تحديد `--cli' أكثر من مرة، حيث يكون المثيل الأخير له الأسبقية. يتم فحص OPAMCLI فقط إذا لم يتم تقديم `--cli'.

حالة الخروج EXIT STATUS

باستثناء ما يلي، يعيد الأمر `exec` القيمة 127 إذا لم يتم العثور على الأمر أو تعذر تنفيذه، وقيمة خروج الأمر بخلاف ذلك.

0
نجاح، أو صحيح للاستعلامات المنطقية.
1
خطأ. يتم إرجاعه عندما تكون القيمة المنطقية متوقعة، على سبيل المثال عند التشغيل باستخدام --check، أو للاستعلامات مثل opam lint.
2
وسيطات سطر أوامر خاطئة، أو وسيطات سطر أوامر تشير إلى سياق غير صالح (على سبيل المثال، ملف لا يتبع التنسيق المتوقع).
5
غير موجود. طلبت شيئًا (حزمة، إصدار، مستودع، إلخ) لم يتم العثور عليه.
10
تم الإلغاء. تطلب العملية تأكيدًا لم يتم تقديمه.
15
تعذر الحصول على الأقفال المطلوبة للعملية.
20
لا يوجد حل لطلب المستخدم. قد يكون هذا ناتجًا عن

NAME

opam-admin-lint − Lint a repository.

SYNOPSIS

opam admin lint [OPTION]... [REPOSITORY]...

DESCRIPTION

This subcommand checks the provided repositories for various issues, like formatting errors, inconsistencies, or potential problems that may affect users.

If no repository is provided, the command checks all repositories configured in opam.

This command is intended for repository maintainers.

ARGUMENTS

REPOSITORY
The path to the repository to lint. Can be a local path or a URL.

OPTIONS

This subcommand supports the following options:

--fix
Attempts to automatically fix some of the detected issues.
--strict
In addition to standard checks, perform stricter checks that may fail more often.
--jobs=N, -j N
Use N parallel jobs to check the repositories. Defaults to the number of available cores.
--count-only
Only count the number of detected issues, do not display them.
--filter=STRING
Only report issues matching the given string.
--list-checks
List all available checks and exit.

COMMON OPTIONS

These options are common to most opam commands:

--help
Display a short help message and exit.
--help-all
Display help on all options and exit.
--debug
Activate debug mode. Equivalent to setting OPAMDEBUG=1.
--log-level=LEVEL

Set the logging level. Possible values are: fatal, error, warn, info, debug.

Default is info.

--log-file=FILE
Redirect logs to FILE instead of stderr.
--no-color
Disable coloured output.
--color
Enable coloured output (default).
--root=DIR
Use alternative opam root DIR.
--conf-file=FILE
Use alternative opam configuration file FILE.
--native-cache
Use native cache directory.
--no-native-cache
Disable native cache directory.

ENVIRONMENT

See opam(1) ENVIRONMENT for common environment variables.

The following environment variable is specific to this subcommand:

OPAMKEEPEMPTY
If set, opam-admin-lint will not complain about empty directories in the repository.

CLI VERSION

The opam-admin-lint command is part of the opam-admin binary. Its version is exposed via the opam --version command.

EXIT STATUS

0
Success. No issues were found, or all found issues were fixed.
1
An error occurred during the linting process (e.g., invalid repository path).
2
Issues were found and could not be fixed, or the --fix option was not used.
42
A user interrupt occurred (e.g., Ctrl-C).
128
A fatal error occurred.

The exit status can also be a bitmask, combining the following values:

2
There were linting errors.
4
Some linting errors were reported and not fixed.
8
There were linting warnings.
16
Some linting warnings were reported and not fixed.
32
There were linting notices.
64
Some linting notices were reported and not fixed.

For example, an exit status of 70 means that there were linting errors (2) and warnings (4) that were not fixed, and linting notices (64) that were reported.

The following exit codes are also possible:

20
Package metadata error. For example, wrong format in opam file, or referencing a non-existent dependency.
21
Dependency graph error. For example, cyclic dependencies, or asking to install two incompatible packages, for example.
30
Error in package definition, or other metadata files. Using --strict raises this error more often.
31
Package script error. Some package operations were unsuccessful. This may be an error in the packages or an incompatibility with your system. This can be a partial error.
40
Sync error. Could not fetch some remotes from the network. This can be a partial error.
50
Configuration error. Opam or system configuration doesn't allow operation, and needs fixing.
60
Solver failure. The solver failed to return a sound answer. It can be due to a broken external solver, or an error in solver configuration.
99
Internal error. Something went wrong, likely due to a bug in opam itself.
130
User interrupt. SIGINT was received, generally due to the user pressing Ctrl-C.
0
on success.
123
on indiscriminate errors reported on standard error.
124
on command line parsing errors.
125
on unexpected internal errors (bugs).
