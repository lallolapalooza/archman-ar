NAME

gdbserver — remote debugging tool

SYNOPSIS

gdbserver [options] [--multi] [--attach] {host}:{port} program [args...]
gdbserver [options] [--multi] [--attach] {host}:{port} --exec-file=file [args...]
gdbserver [options] [--multi] --attach {host}:{port} pid

DESCRIPTION

The "gdbserver" program is a simple program that supports debugging programs running on a remote machine. "gdbserver" needs to be run on the same machine as the program being debugged. You then connect to "gdbserver" from a host machine running a full GDB, using a serial line or TCP connection.

This is a basic description of how to use gdbserver. The full documentation for GDB is maintained as a Texinfo manual.

When invoked, "gdbserver" opens a listening socket on the specified TCP port, and waits for a connection from a GDB client. When GDB connects, "gdbserver" can load and run the specified program, or attach to an existing process.

The program is started with the given arguments. A GDB session can be attached to "gdbserver" using a TCP connection. "gdbserver" will then wait for commands from GDB.

The "--multi" option allows multiple GDB sessions to connect to gdbserver. This is useful for debugging multi-threaded applications where different threads might be debugged by different GDB instances. When "--multi" is used, gdbserver will not exit after the first GDB session disconnects. It will continue listening for new connections.

The "--attach" option allows gdbserver to attach to an existing process (specified by its PID) instead of starting a new program. This is useful for debugging long-running processes or services.

OPTIONS

--debug
Prints verbose debugging messages to stderr. This is intended for use by developers of "gdbserver". The output format and content may change in future releases of "gdbserver".
--debug-file=filename
Instruct "gdbserver" to send any debug output to the given filename. This option is intended for "gdbserver" development and for bug reports to the developers.
--debug-format=option1[,option2,...]
Instruct "gdbserver" to include extra information in each line of debugging output.
--wrapper
Specify a wrapper to launch programs for debugging. The option should be followed by the name of the wrapper, then any command-line arguments to pass to the wrapper, then "--" indicating the end of the wrapper arguments.
--once
By default, gdbserver keeps the listening TCP port open, so that additional connections are possible. However, if you start "gdbserver" with the --once option, it will stop listening for any further connection attempts after connecting to the first GDB session.

SEE ALSO

The full documentation for GDB is maintained as a Texinfo manual. If the "info" and "gdb" programs and GDB's Texinfo documentation are properly installed at your site, the command

info gdb

should give you access to the complete manual.
