oo_define(n)

الحزمة: tcl

التراخيص: TCL

define(n) أوامر TclOO define(n)

الاسم

oo::define, oo::objdefine, oo::Slot - تعريف وتكوين الفئات والكائنات

الملخص

package require TclOO
oo::define class defScript
oo::define class subcommand arg ?arg ...?
oo::objdefine object defScript
oo::objdefine object subcommand arg ?arg ...?
oo::Slot arg...

هيكل الفئة

oo::object
   → oo::Slot

الوصف

يُستخدم الأمر oo::define للتحكم في تكوين الفئات، والأمر oo::objdefine يُستخدم للتحكم في تكوين الكائنات (بما في ذلك الفئات ككائنات مثيل)، حيث يتم تطبيق التكوين على الكيان المسمى في الوسيط class أو object. يؤدي تكوين فئة ما أيضًا إلى تحديث تكوين جميع الفئات الفرعية لل فئة وجميع الكائنات التي هي مثيلات لتلك الفئة أو التي تمزجها (كما تم تعديلها بواسطة أي تكوين لكل مثيل). الطريقة التي يتم بها إجراء التكوين يتم التحكم فيها إما بواسطة الوسيط defScript أو بواسطة الوسيط subcommand وما يليه من وسائط arg؛ عندما يكون الأخير موجودًا، يكون الأمر كما لو أن جميع الوسائط من subcommand فصاعدًا تم تحويلها إلى قائمة وأن تلك القائمة تم استخدامها كوسيط defScript.

تكوين الفئات

الأوامر التالية مدعومة في defScript لـ oo::define، وكل منها يمكن استخدامه أيضًا في شكل subcommand:

constructor argList bodyScript
ينشئ أو يحدث المُنشئ لفئة. ستكون الوسائط الرسمية للمُنشئ (المعرفة بنفس تنسيق أمر Tcl proc) هي argList، وسيكون جسم المُنشئ هو bodyScript. عند تقييم جسم المُنشئ، سيكون مجال الأسماء الحالي للمُنشئ هو مجال أسماء فريد للكائن الذي يتم إنشاؤه. داخل المُنشئ، يجب استخدام الأمر next لاستدعاء مُنشئي الفئات العليا. إذا كان bodyScript هو سلسلة فارغة، فسيتم حذف المُنشئ.
deletemethod name ?name ...?
يحذف كل من الأساليب المسماة name من فئة. يجب أن تكون الأساليب موجودة مسبقًا في تلك الفئة. لا يؤثر على الفئات العليا للفئة، ولا يؤثر على الفئات الفرعية أو مثيلات الفئة (باستثناء عندما يكون لديهم سلسلة استدعاء عبر الفئة التي يتم تعديلها) أو كائن الفئة نفسه.
destructor bodyScript
ينشئ أو يحدث المُدمر لفئة. لا يأخذ المُدمرون أي وسائط، وسيكون جسم المُدمر هو bodyScript. يتم استدعاء المُدمر عند حذف كائنات الفئة، وعند استدعائه سيكون مجال الأسماء الفريد للكائن هو مجال الأسماء الحالي. يجب أن تستخدم المُدمرون الأمر next لاستدعاء مُدمر الفئات العليا. لاحظ أنه لا يتم استدعاء المُدمرون في جميع الحالات (على سبيل المثال، إذا تم تدمير المفسر). إذا كان bodyScript هو سلسلة فارغة، فسيتم حذف المُدمر.
لاحظ أن الأخطاء أثناء تقييم المُدمر *لا يتم إرجاعها* إلى الكود الذي يسبب تدمير كائن. بدلاً من ذلك، يتم تمريرها إلى معالج bgerror المحدد حاليًا.
export name ?name ...?
يرتب لتصدير كل من الأساليب المسماة، name (أي، يمكن استخدامها خارج مثيل عبر أمر مثيل الكائن) بواسطة الفئة التي يتم تعريفها. لاحظ أن الأساليب نفسها قد يتم تعريفها فعليًا بواسطة فئة عليا؛ تصديرات الفئات الفرعية تتجاوز رؤية الفئات العليا، وقد يتم تجاوزها بدورها بواسطة المثيلات.
filter ?-slotOperation? ?methodName ...?
يحدد هذا المنفذ (انظر SLOTTED DEFINITIONS أدناه) أو يحدث قائمة بأسماء الأساليب التي تُستخدم لحراسة ما إذا كان يمكن استدعاء استدعاءات الأساليب لمثيلات الفئة وما هي نتائج الأسلوب. كل methodName يسمي طريقة تصفية واحدة (قد تكون مرئية أو غير مرئية)؛ لا يعتبر تسمية أسلوب غير موجود خطأً لأنه قد يتم تعريفه بواسطة فئات فرعية. افتراضيًا، يعمل هذا المنفذ عن طريق الإلحاق.
forward name cmdName ?arg ...?
ينشئ أو يحدث أسلوبًا مُعاد توجيهه يسمى name. يتم تعريف الأسلوب ليتم توجيهه إلى الأمر المسمى cmdName، مع إضافة وسائط إضافية، arg وما إلى ذلك، قبل تلك الوسائط التي يحددها مستدعي الأسلوب. سيتم دائمًا حل cmdName باستخدام قواعد مجالات أسماء الكائنات المستدعية، أي، عندما لا يكون cmdName مؤهلاً بالكامل، سيتم البحث عن الأمر في مجال أسماء كل كائن، باستخدام مسار مجالات أسماء المثيلات، أو بالبحث في مجال الأسماء العام. سيتم تصدير الأسلوب إذا كان name يبدأ بحرف صغير، وغير مُصدر وإلا.
method name argList bodyScript
ينشئ أو يحدث أسلوبًا يتم تنفيذه كنص برمجي شبيه بالإجراء. اسم الأسلوب هو name، وستكون الوسائط الرسمية للأسلوب (المعرفة بنفس تنسيق أمر Tcl proc) هي argList، وسيكون جسم الأسلوب هو bodyScript. عند تقييم جسم الأسلوب، سيكون مجال الأسماء الحالي للأسلوب هو مجال أسماء فريد للكائن الحالي. سيتم تصدير الأسلوب إذا كان name يبدأ بحرف صغير، وغير مُصدر وإلا؛ يمكن تجاوز هذا السلوك عبر export و unexport.
mixin ?-slotOperation? ?className ...?
يحدد هذا المنفذ (انظر SLOTTED DEFINITIONS أدناه) أو يحدث قائمة بالفئات الإضافية التي سيتم مزجها في جميع مثيلات الفئة التي يتم تعريفها. كل وسيط className يسمي فئة واحدة سيتم مزجها. افتراضيًا، يعمل هذا المنفذ عن طريق الاستبدال.
renamemethod fromName toName
يعيد تسمية الأسلوب المسمى fromName في فئة إلى toName. يجب أن يكون الأسلوب قد وجد مسبقًا في الفئة، ويجب ألا يشير toName مسبقًا إلى أسلوب في تلك الفئة. لا يؤثر على الفئات العليا للفئة، ولا يؤثر على الفئات الفرعية أو مثيلات الفئة (باستثناء عندما يكون لديهم سلسلة استدعاء عبر الفئة التي يتم تعديلها)، أو كائن الفئة نفسه. لا يغير حالة تصدير الأسلوب؛ إذا تم تصديره من قبل، فسيتم تصديره بعد ذلك.
self subcommand arg ...
self script
هذا الأمر يعادل استدعاء oo::objdefine على الفئة التي يتم تعريفها (انظر CONFIGURING OBJECTS أدناه لوصف القيم المدعومة لـ subcommand). يتبع نفس النمط العام لمعالجة الوسائط مثل أوامر oo::define و oo::objdefine، و"oo::define cls self subcommand ..." يعمل بشكل متطابق مع "oo::objdefine cls subcommand ...".
superclass ?-slotOperation? ?className ...?
يسمح هذا المنفذ (انظر SLOTTED DEFINITIONS أدناه) بتغيير الفئات العليا للفئة التي يتم تعريفها. كل وسيط className يسمي فئة واحدة لتكون فئة عليا للفئة المعرفة. لاحظ أنه لا يجوز تغيير الكائنات من كونها فئات إلى كونها غير فئات أو العكس، وأن فئة أصل فارغة تعادل oo::object، ولا يمكن تعديل الفئات الأصلية لـ oo::object و oo::class. افتراضيًا، يعمل هذا المنفذ عن طريق الاستبدال.
unexport name ?name ...?
يرتب لعدم تصدير كل من الأساليب المسماة، name (أي، غير قابلة للاستخدام خارج المثيل عبر أمر مثيل الكائن).

تكوين الكائنات

الأوامر التالية مدعومة في defScript لـ oo::objdefine، وكل منها يمكن استخدامه أيضًا في شكل subcommand:

constructor argList bodyScript
ينشئ أو يحدث المُنشئ للكائن. هذا مشابه لـ oo::define constructor، باستثناء أنه يتم تطبيقه على كائن واحد بدلاً من فئة. إذا كان bodyScript فارغًا، يتم حذف المُنشئ.
delete
يحذف الكائن.
destructor bodyScript
ينشئ أو يحدث المُدمر للكائن. هذا مشابه لـ oo::define destructor، باستثناء أنه يتم تطبيقه على كائن واحد بدلاً من فئة. إذا كان bodyScript فارغًا، يتم حذف المُدمر.
export name ?name ...?
يُرتّب لتصدير كل من الأساليب المسماة، name، من الكائن. هذا مماثل لـ oo::define export، ولكن مع نطاق تطبيق على كائن واحد. يجب أن تكون هذه الأساليب قد تم تعريفها بالفعل بواسطة فئة الكائن أو فئاته العليا.
filter ?-slotOperation? ?methodName ...?
يحدد هذا المنفذ (انظر SLOTTED DEFINITIONS أدناه) أو يحدث قائمة بالأساليب التي سيتم استخدامها لتصفية استدعاءات الأساليب لهذا الكائن. هذا مماثل لـ oo::define filter، ولكن مع نطاق تطبيق على كائن واحد.
forward name cmdName ?arg ...?
ينشئ أو يحدث أسلوبًا مُعاد توجيهه للكائن. هذا مماثل لـ oo::define forward، ولكن مع نطاق تطبيق على كائن واحد.
method name argList bodyScript
ينشئ أو يحدث أسلوبًا للكائن. هذا مماثل لـ oo::define method، ولكن مع نطاق تطبيق على كائن واحد. يتم تصدير الأسلوب إذا بدأ اسمه بحرف صغير، وغير مُصدر وإلا؛ يمكن تجاوز هذا السلوك عبر export و unexport.
mixin ?-slotOperation? ?className ...?
يحدد هذا المنفذ (انظر SLOTTED DEFINITIONS أدناه) أو يحدث قائمة بالفئات التي سيتم مزجها لهذا الكائن. هذا مماثل لـ oo::define mixin، ولكن مع نطاق تطبيق على كائن واحد.
next ?arg ...?
عند استدعائه من داخل مُنشئ أو مُدمر تم استدعاؤه عبر oo::objdefine، فإنه يستدعي المُنشئ أو المُدمر للفئة الفائقة للكائن. إذا تم توفير وسائط، فسيتم تمريرها إلى المُنشئ أو المُدمر للفئة الفائقة.
renamemethod fromName toName
يعيد تسمية أسلوب للكائن. هذا مماثل لـ oo::define renamemethod، ولكن مع نطاق تطبيق على كائن واحد.
self subcommand arg ...
self script
هذا الأمر يعادل استدعاء oo::define على الكائن نفسه (انظر CONFIGURING CLASSES أعلاه لوصف القيم المدعومة لـ subcommand). يتبع نفس النمط العام لمعالجة الوسائط مثل أوامر oo::define و oo::objdefine، و"oo::objdefine obj self subcommand ..." يعمل بشكل متطابق مع "oo::define obj subcommand ...".
unexport name ?name ...?
يرتب لعدم تصدير كل من الأساليب المسماة، name، من الكائن. هذا مماثل لـ oo::define unexport، ولكن مع نطاق تطبيق على كائن واحد.

تعريفات المنافذ

بالإضافة إلى الأساليب، تسمح TclOO بتعريف "منافذ" (slots). المنافذ هي أماكن لتخزين البيانات التي يتم تكوينها إما عند تعريف الفئة أو عند تكوين كائن. إنها تختلف عن المتغيرات العادية من حيث أنها غالبًا ما تحتوي على آليات متكاملة للتحقق من الصحة أو التغيير أو التحديد. يتم تعريف المنافذ باستخدام الأوامر التالية:

filter ?script?
يتم استخدام هذا المنفذ لتحديد الأساليب التي سيتم استخدامها لتصفية استدعاءات الأساليب. إذا تم تقديم script، فسيتم استخدام النص البرمجي الناتج لتحديد قائمة أساليب التصفية. إذا لم يتم تقديم script، فإن الأمر يعيد قائمة أساليب التصفية المحددة حاليًا. الناتج الافتراضي هو قائمة فارغة.
mixin ?script?
يتم استخدام هذا المنفذ لتحديد الفئات الإضافية التي سيتم مزجها في الفئة أو الكائن. إذا تم تقديم script، فسيتم استخدام النص البرمجي الناتج لتحديد قائمة الفئات المراد مزجها. إذا لم يتم تقديم script، فإن الأمر يعيد قائمة الفئات المراد مزجها. الناتج الافتراضي هو قائمة فارغة.
superclass ?script?
يتم استخدام هذا المنفذ لتحديد الفئات العليا للفئة أو الكائن. إذا تم تقديم script، فسيتم استخدام النص البرمجي الناتج لتحديد قائمة الفئات العليا. إذا لم يتم تقديم script، فإن الأمر يعيد قائمة الفئات العليا المحددة حاليًا. الناتج الافتراضي هو قائمة تحتوي فقط على oo::object.

كل واحد من هذه الأوامر يأخذ وسيطًا اختياريًا، -slotOperation، والذي يمكن أن يكون أحد الكلمات الرئيسية التالية:

append
يضيف الوسائط الجديدة إلى نهاية القائمة الموجودة.
prepend
يضيف الوسائط الجديدة إلى بداية القائمة الموجودة.
replace
يستبدل القائمة الموجودة بالكامل بالوسائط الجديدة. هذه هي القيمة الافتراضية إذا لم يتم تحديد -slotOperation.

عند استخدام الأوامر oo::define أو oo::objdefine مع وسيط subcommand، فإن تحديد منفذ (مثل oo::define class superclass) يعادل استدعاء الأمر المناظر للمنفذ مع الوسيط script الذي تم إنشاؤه من باقي الوسائط.

مثال

package require TclOO
oo::class create person {
    method name {args} {
        setlist [lrange $args 0 end]
        if {[llength $list] == 0} {
            return "My name is $name."
        } else {
            set name [lindex $list 0]
        }
    }
    constructor {name} {
        set ::name $name
    }
}
oo::objdefine person {
    forward speak person::speak
}
set p [person new PersonName]
puts [$p name]
# Outputs: My name is PersonName.
puts [$p name First Middle Last]
# Outputs: My name is First Middle Last.
puts [$p name]
# Outputs: My name is First Middle Last.

NAME

oo::objdefine, oo::renamemethod, oo::mixin - define object-specific behaviour

SYNOPSIS

oo::objdefine objectName ?option value...?
oo::renamemethod objectName oldName newName
oo::mixin objectName className ?className...?

CLASS HIERARCHY

oo::object
  |- oo::objdefine

DESCRIPTION

The oo::objdefine command is used to specify additional behaviour for an existing object. It is a member of the oo::objdefine class, and as such, it takes a list of option value pairs to modify the specified object.

The options currently supported are:

‑method name ?body?
If body is specified, it defines a new method named name on the object. If body is not specified, it removes the method named name from the object. This can be used to override methods inherited from a class, or to add methods to objects that do not belong to a class.
‑replace name ?body?
Similar to ‑method, but removes any existing method by the same name before defining the new one. This is useful for overriding methods of a class that is later mixed in.
‑renamemethod oldName newName
Renames a method named oldName to newName on the object.
‑mixin className ?className...?
Mixes in the specified class (or classes) into the object. This adds all methods and inherited methods from the specified class(es) to the object. Mixins are searched in the order they are specified, and the first one containing a method will provide it.
‑unmixin className ?className...?
Removes the specified class (or classes) from the object's mixin path. Note that this does not remove methods defined directly on the object, only those inherited via mixins.

The oo::renamemethod command is a shorthand for oo::objdefine with the ‑renamemethod option.

The oo::mixin command is a shorthand for oo::objdefine with the ‑mixin option.

SLOTTED DEFINITIONS

The oo::objdefine command can also be used to define object-specific slots. Slots are essentially data members that can have associated methods for getting and setting their values.

oo::object create my_obj
oo::objdefine my_obj slot my_slot

This creates a slot named my_slot on the object my_obj. The initial value of the slot is empty. You can get and set the value of the slot using the my_slot method:

my_obj my_slot value          → returns ""
my_obj my_slot "new value"  → returns "new value"
my_obj my_slot                → returns "new value"

You can also specify initial values and constraints for slots:

oo::objdefine my_obj {
    slot name -default "unknown"
    slot count -default 0 -validate {int(value) > 0}
}

This creates two slots, name and count, with default values. The count slot has a validation script that ensures its value is a positive integer.

EXAMPLES

oo::object create hello
oo::objdefine hello method greet {
    puts "hello world"
}
hello greet           → prints "hello world"

oo::object create foo
oo::objdefine foo renamemethod bar baz
foo bar               → error "unknown method bar"
foo baz               → error "unknown method baz"

oo::object create lollipop
oo::objdefine lollipop method {
    puts "hello world"
}

This example shows how additional classes can be mixed into an object. It also shows how mixin is a slot that supports appending:

oo::object create inst
inst m1              → error "unknown method m1"
inst m2              → error "unknown method m2"
oo::class create A {
    method m1 {} {
        puts "red brick"
    }
}
oo::objdefine inst {
    mixin A
}
inst m1              → prints "red brick"
inst m2              → error "unknown method m2"
oo::class create B {
    method m2 {} {
        puts "blue brick"
    }
}
oo::objdefine inst {
    mixin -append B
}
inst m1              → prints "red brick"
inst m2              → prints "blue brick"
