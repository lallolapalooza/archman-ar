NAME

org.freedesktop.home1.5 — systemd home directory management

INTRODUCTION

This service manages user home directories, and may be used to activate, deactivate, and manage access to them. It is intended to be used by homectl(1) and display managers. See systemd-homed.service(8) for more information.

THE MANAGER OBJECT

Methods

ActivateHome() activates the home directory of user, potentially creating it if it does not exist. This is typically used by display managers to activate the home directory before the user logs in. The secret parameter should contain the user's login password or other authentication token. The acquire_uid parameter controls if the UID should be acquired for the home directory.

ActivateHomeIfReferenced() is similar to ActivateHome(), but only activates the home directory if it is already referenced by at least one other client. This is useful for activating home directories that might have been left inactive after a suspend, but are still referenced.

DeactivateHome() deactivates the home directory of user. This is used when the user logs out.

LockHome() locks the home directory of user. This prevents access until UnlockHome() is called.

UnlockHome() unlocks the home directory of user, requiring the secret to be provided.

ReleaseHome() releases any references held by the home directory manager to the home directory of user. This is typically called when the home directory is no longer needed, for example, after a successful logout.

Rebalance() synchronously rebalances free disk space between home directories. This operation is only performed if at least one home directory uses the LUKS2 backend and has rebalancing enabled. Otherwise, it is a no-op.

AdoptHome() adopts an existing directory as a home directory. The user_record contains the user's configuration in JSON format. blobs may contain arbitrary data associated with the user, keyed by name. This is typically used to import home directories from other systems.

CreateHomeEx() creates a new home directory for user with the given user_record, uid, and optional blobs. The flags parameter is currently unused and must be zero.

UpdateHomeEx() updates the home directory for user with new user_record and blobs. The flags parameter is currently unused and must be zero.

RenameHome() renames the home directory of old_user to new_user.

RemoveHome() removes the home directory of user. The secret parameter must be provided for authentication.

ChangeHomePassword() changes the password for the home directory of user, requiring the old password for verification.

AcquireHome() acquires a file descriptor that represents the home directory. This is typically used by clients that need direct access to the home directory, such as file managers. The please_suspend parameter indicates whether the system should suspend the home directory after the file descriptor is acquired.

RefHome() increments the reference count for the home directory of user. This is used to keep the home directory active even if no user is logged in. The please_suspend parameter indicates whether the home directory should be suspended after the reference is acquired.

RefHomeUnrestricted() is similar to RefHome(), but it does not impose any restrictions on acquiring the reference, allowing it to be acquired even if the home directory is locked or inactive.

ReleaseHome() decrements the reference count for the home directory of user. This is called when the client no longer needs access to the home directory.

LockAllHomes() locks all active home directories that only have references that opted into automatic suspending during system suspend. This is usually invoked automatically shortly before system suspend.

DeactivateAllHomes() deactivates all home areas that are currently active. This is usually invoked automatically shortly before system shutdown.

Rebalance() synchronously rebalances free disk space between home areas. This only executes an operation if at least one home area using the LUKS2 backend is active and has rebalancing enabled, and is otherwise a NOP.

ListSigningKeys() acquires a list of installed home area signing keys. Returns an array of key names with their PEM encoded public key data. Each entry also comes with a flags value which is currently unused and should be ignored by clients.

GetSigningKey() acquires the PEM encoded public part of the specified home area signing key of the specified name. Also returns a currently unused flags value that should be ignored. The flags parameter must be set to zero, currently.

AddSigningKey() adds a new key to the list of home area signing keys. Takes a name string (free-form, suitable as filename, with suffix ".public"), the PEM encoded public key data and a currently unused flags value that must be zero. The flags parameter must be set to zero, currently.

RemoveSigningKey() removes a key from the list of home area signing keys. Takes the name of the key to remove and a currently unused flags value that must be zero. The flags parameter must be set to zero, currently.

Properties

AutoLogin exposes an array of structures consisting of user name, seat name and object path of an home directory object. All locally managed users that have the "autoLogin" field set are listed here, with the seat name they are associated with. A display manager may watch this property and pre-fill the login screen with the users exposed this way.

Methods

Activate(), ActivateIfReferenced(), Deactivate(), Unregister(), Realize(), Remove(), Fixate(), Authenticate(), Update(), UpdateEx(), Resize(), ChangePassword(), Lock(), Unlock(), Acquire(), Ref(), RefUnrestricted(), Release(), operate like their matching counterparts on the org.freedesktop.home1.Manager interface (see above). The main difference is that they are methods of the home directory objects, and hence carry no additional user name parameter. Which of the two flavors of methods to call depends on the handles to the user known on the client side: if only the user name is known, it is preferable to use the methods on the manager object since they operate with user names only. Clients can also easily operate on their own home area by using the methods on the manager object with an empty string as the user name. If the client has the home's object path already acquired in some way, however, it is preferable to operate on the org.freedesktop.home1.Home objects instead.

Properties

UserName contains the user name of the user account/home directory.

UID contains the numeric UNIX UID of the user account.

UnixRecord contains a structure encapsulating the six fields a struct passwd typically contains (the password field is suppressed).

State exposes the current state home the home directory.

UserRecord contains the full JSON user record string of the user account.
