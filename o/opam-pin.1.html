opam-pin(1)

الحزمة: opam

التراخيص: LGPL-2.1-only

OPAM-PIN(1) دليل Opam OPAM-PIN(1)

الاسم

opam-pin - تثبيت حزمة معينة على إصدار أو مصدر محدد.

الملخص

opam pin [خيار]… [أمر] [معامل]…

الوصف

يسمح هذا الأمر بالتخصيص المحلي للحزم في مفتاح معين. يمكن أن يفرض التثبيت إصدارًا معينًا فقط، أو يوفر إصدارًا محليًا قابلاً للتعديل لتعريف الحزمة. من الممكن أيضًا إنشاء حزمة جديدة بمجرد تثبيت اسم حزمة غير موجود.

أي تخصيص متاح عبر الأمر الفرعي edit، ولكن الأمر الطرفي يوفر سهولة في تغيير عنوان URL لمصدر الحزمة، نظرًا لأنه الاستخدام الأكثر شيوعًا: opam pin add PKG URL يقوم بتعديل الحزمة PKG لجلب مصدرها من URL. إذا تم العثور على تعريف حزمة في شجرة مصدر الحزمة، فسيتم استخدامه محليًا.

إذا تم تحديد (أو -)، يتم تثبيت الحزمة بدون أرشيف مصدر. يمكن حذف اسم الحزمة إذا كان الهدف هو دليل يحتوي على وصف واحد أو أكثر للحزم الصالحة (هذا يسمح بعمل، على سبيل المثال، opam pin add . من دليل المصدر).

إذا كان PACKAGE يأخذ شكل name.version، فسيتم اعتبار الحزمة المثبتة على أنها الإصدار version بواسطة opam. كن حذرًا، فهذا لا يتعلق بالإصدار الفعلي للمصدر المستخدم للحزمة. انظر أيضًا خيار --with-version.

الأمر الفرعي الافتراضي هو list إذا لم تكن هناك معاملات إضافية، و add بخلاف ذلك إذا كان الأمر لا لبس فيه.

الأوامر

بدون معامل، الافتراضي هو list.

list
يسرد الحزم المثبتة. إذا كان المصدر مستودعًا بعيدًا، يعرض التجزئة التي تمثل حالته.
scan DIR
يسرد الحزم المتاحة للتثبيت في الدليل.
add PACKAGE TARGET
يثبت الحزمة PACKAGE على TARGET، والتي يمكن أن تكون إصدارًا، أو مسارًا، أو عنوان URL. يمكن حذف PACKAGE إذا كان TARGET يحتوي على وصف واحد أو أكثر للحزمة. يمكن استبدال TARGET بـ --dev-repo إذا كانت هناك حزمة بهذا الاسم معروفة بالفعل، أو --current إذا كانت الحزمة مثبتة بالفعل. إذا كان TARGET هو -، يتم تثبيت الحزمة كحزمة افتراضية، دون أي مصدر. سيستنتج opam نوع التثبيت من تنسيق (ومحتويات، إذا كانت محلية) TARGET. استخدم --kind أو عنوان URL صريحًا لتعطيل هذا السلوك. قد تستهدف التثبيتات لنظم التحكم في الإصدارات فرعًا أو تثبيتًا محددًا باستخدام #branch على سبيل المثال git://host/me/pkg#testing. إذا لم يكن PACKAGE اسم حزمة معروفًا، فسيتم إنشاء حزمة جديدة بهذا الاسم محليًا. بالنسبة لتثبيتات المصدر، يمكن تحديد إصدار الحزمة باستخدام تنسيق NAME.VERSION للحزمة، في ملف opam المصدر، أو باستخدام edit.
remove PACKAGES...|TARGET
يزيل تثبيت الحزم PACKAGES، ويعيد تعريفها من المستودع، إن وجدت. باستخدام TARGET، يزيل تثبيت كل ما هو مثبت حاليًا على هذا الهدف.
edit NAME
يفتح محررًا يمنحك فرصة لتغيير تعريف الحزمة الذي سيستخدمه opam محليًا للحزمة NAME، بما في ذلك إصدارها وعنوان URL لمصدرها. استخدام تنسيق NAME.VERSION سيقوم بتحديث الإصدار في ملف opam قبل التحرير، دون تغيير الهدف الفعلي. يتم تحديد المحرر المختار من متغيرات البيئة OPAMEDITOR، VISUAL أو EDITOR، بهذا الترتيب.

الخيارات

--all
عند إزالة التثبيت، يزيل جميع عمليات التثبيت في المفتاح المحدد.
--current
عند التثبيت، يستخدم الإصدار الحالي المثبت وبيانات الحزمة الوصفية: سيؤدي هذا إلى تجنب إعادة التثبيت بسبب التغييرات في البيانات الوصفية الأصلية، وقد يستخدم أيضًا للاحتفاظ بحزمة تم إزالتها من المصدر.
--dev-repo
تثبيت لمصدر الحزمة الأصلية لأحدث إصدار تطوير
-e, --edit
مع opam pin add، قم بتحرير ملف opam كما هو الحال مع `opam pin edit` بعد التثبيت.
-k KIND, --kind=KIND
يحدد نوع التثبيت. يجب أن يكون أحد هذه الأنواع: version، path، http، git، darcs، hg، none أو auto. إذا لم يتم تعيينه أو كان auto، يتم استنتاجه من تنسيق الهدف، مع الافتراضي إلى نظام التحكم المناسب في الإصدارات إذا تم اكتشاف واحد في الدليل المحدد، أو إلى path بخلاف ذلك. يمكن تعيين OPAMPINKINDAUTO إلى "0" لتعطيل الاكتشاف التلقائي لنظام التحكم في الإصدارات. استخدم none للتثبيت بدون هدف (للحزم الافتراضية).
-n, --no-action
يسجل فقط حالة التثبيت الجديدة، ولا يطالب بإعادة تثبيت الحزم المتأثرة أو إزالتها.
--normalise
يطبع قائمة الحزم المتاحة للتثبيت بالتنسيق `name.version^url`، وهو تنسيق يمكن لـ `opam pin add` فهمه. متاح فقط مع الأمر الفرعي scan. مثال على الاستخدام هو `opam pin scan . --normalise | grep foo | xargs opam pin add`
--recursive
يسمح بالبحث المتكرر عن ملفات *.opam. راجع --subpath أيضًا.
-s, --short
يطبع قوائم خام بالأسماء، اسم واحد في كل سطر، متجاوزًا أي تفاصيل.
--subpath=PATH
يتم استرداد ملفات *.opam من الدليل الفرعي المحدد بدلاً من الدليل الرئيسي. ثم يتم أخذ المصادر من الدليل الفرعي المستهدف، داخليًا يتم نسخ/جلب هذا الدليل الفرعي فقط. يمكن دمجه مع --recursive لإجراء بحث متكرر على المسار الفرعي.
--with-version=VERSION
يضبط إصدار التثبيت إلى VERSION للحزم المسماة PACKAGES أو الحزم المستردة من TARGET. له الأولوية على أي مواصفات إصدار أخرى (حقل الإصدار في ملف opam، وسيطة name.vers). عند التثبيت على إصدار، يتم استخدام مصدر الحزمة من هذا الإصدار، ولكن يتم الإعلان عنه كـ VERSION لـ opam. استخدام --with-version يعادل استخدام --edit وتعديل الإصدار في ملف تعريف الحزمة.

خيارات بناء الحزمة

--assume-depexts
تخطي خطوة تثبيت أي حزم نظام مفقودة، ومحاولة المتابعة بتجميع حزم opam على أي حال. إذا نجح التثبيت، فلن يطالب opam مرة أخرى بشأن حزم النظام هذه. ذو معنى فقط إذا تم تمكين التعامل مع التبعيات الخارجية.
-b, --keep-build-dir
احتفظ بدلائل البناء بعد تجميع الحزم. هذا يعادل تعيين $OPAMKEEPBUILDDIR إلى "true".
--build-doc
تمت إزالته في 2.1، استخدم --with-doc بدلاً من ذلك.
--build-test
تمت إزالته في 2.1، استخدم --with-test بدلاً من ذلك.
-d, --with-doc
تجميع وثائق الحزمة. هذا يؤثر فقط على الحزم المدرجة في سطر الأوامر. هذا يعادل تعيين $OPAMWITHDOC (أو $OPAMBUILDDOC الذي تم إيقافه) إلى "true".
--dry-run
محاكاة الأمر، ولكن دون تنفيذ أي تغييرات فعليًا. يمكن أيضًا تعيين هذا باستخدام متغير البيئة $OPAMDEBUG.
--fake
يسجل هذا الخيار الإجراءات في قاعدة بيانات opam، دون تنفيذها فعليًا. تحذير: هذا الخيار خطير ومن المحتمل أن يكسر بيئة opam الخاصة بك. ربما تريد --dry-run. لقد تم تحذيرك.
--ignore-constraints-on[=PACKAGES] (الافتراضي=)

--inplace-build

NAME

opam-pin

pin a package to a specific version

SYNOPSIS

opam pin [OPTION]... [PACKAGE[=VERSION]]

DESCRIPTION

This command pins a package to a specific version. If no version is specified, it defaults to the latest version available in the repositories. The pin will be recorded in the opam file of the current directory.

If the package is already installed, the command will try to update it to the pinned version.

If a version is specified, the package will be pinned to that version. If no version is specified, the latest version from the configured repositories will be used.

If the package is not installed, it will be installed to the specified version.

COMMANDS

opam pin

OPTIONS

See opam(1) for common options.

PACKAGE BUILD OPTIONS

--dev-repo
Pin the package to the development version from its repository.
--switch=SWITCH
Pin the package in the specified switch.
-y, --yes
Automatically answer yes to confirmation prompts.
--no-build
Do not build the package after pinning.
--unlock-flag
Remove the --locked flag on the package.
--keep-locked
Keep the --locked flag on the package.
--extra-repo=URL
Add an extra repository to use for the pinning.

COMMON OPTIONS

-h, --help
Show this help message and exit.
--verbose
Show more output.
--debug
Show debugging output.
--log-file=FILE
Log to a file.
--no-color
Disable colored output.

ENVIRONMENT

See opam(1) for environment variables.

CLI VERSION

Version 2.4.1
