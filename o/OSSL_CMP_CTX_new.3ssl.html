OSSL_CMP_CTX_get_option() يقرأ القيمة الحالية للخيار المعطى (على سبيل المثال، OSSL_CMP_OPT_IMPLICIT_CONFIRM) من بنية OSSL_CMP_CTX المعطاة.

OSSL_CMP_CTX_set_log_cb() تعين دالة رد الاتصال cb في ctx لمعالجة إدخالات قائمة الأخطاء ورسائل السجل. عندما تكون cb NULL، يتم طباعة الأخطاء إلى STDERR (إذا كانت متاحة، وإلا يتم تجاهلها) ويتم تجاهل جميع رسائل السجل. بدلاً من ذلك، يمكن استخدام OSSL_CMP_log_open(3) لتوجيه التسجيل إلى STDOUT.

OSSL_CMP_CTX_set_log_verbosity() هو ماكرو يعين خيار السياق OSSL_CMP_OPT_LOG_VERBOSITY إلى المستوى المعطى.

OSSL_CMP_CTX_print_errors() يخرج أي إدخالات في قائمة أخطاء OpenSSL. وهو مشابه لـ ERR_print_errors_cb(3) ولكنه يستخدم دالة رد الاتصال لتسجيل CMP إذا تم تعيينها في ctx للتوحيد مع تسجيل CMP إذا تم توفيرها. بخلاف ذلك، فإنه يستخدم ERR_print_errors(3) للطباعة إلى STDERR (ما لم يتم تعريف OPENSSL_NO_STDIO).

OSSL_CMP_CTX_set1_serverPath() تعين المسار HTTP لخادم CMP على المضيف، والمعروف أيضًا باسم "اسم مستعار لـ CMP". الافتراضي هو "/".

OSSL_CMP_CTX_set1_server() تعين عنوان الخادم address المعطى (والذي قد يكون اسم مضيف أو عنوان IP أو NULL) في ctx المعطى. إذا تم تعيين وسيط غير NULL بواسطة **OSSL_CMP_CTX_get_transfer_cb_arg()**، يتم استخدام معلومات عنوان الخادم هذه للإخراج التشخيصي فقط.

OSSL_CMP_CTX_set_serverPort() تعين منفذ خادم CMP للاتصال به. إذا لم يتم استخدامه أو كان الوسيط port هو 0، يتم تطبيق المنفذ الافتراضي، وهو 80 لـ HTTP و 443 لـ HTTPS. إذا تم تعيين وسيط غير NULL بواسطة **OSSL_CMP_CTX_get_transfer_cb_arg()**، يتم استخدام معلومات منفذ الخادم هذه للإخراج التشخيصي فقط.

OSSL_CMP_CTX_set1_proxy() تعين الوكيل HTTP المراد استخدامه للاتصال بخادم CMP المعطى ما لم يتم تجاوزه بواسطة أي إعدادات "no_proxy" (انظر أدناه). إذا لم يتم استخدام TLS، فسيتم تعيين هذا افتراضيًا على قيمة متغير البيئة "http_proxy" إذا تم تعيينها، وإلا "HTTP_PROXY". بخلاف ذلك، يتم تعيينه افتراضيًا على قيمة "https_proxy" إذا تم تعيينها، وإلا "HTTPS_PROXY". سلسلة وكيل فارغة تحدد عدم استخدام وكيل. بخلاف ذلك، يكون التنسيق "[http[s]://][userinfo@]host[:port][/path][?query][#fragment]"، حيث يتم تجاهل أي userinfo أو path أو query أو fragment معطاة. إذا كان سلسلة المضيف عنوان IPv6، فيجب أن تكون محاطة بـ "[" و "]". رقم المنفذ الافتراضي هو 80، أو 443 في حالة إعطاء "https:".

OSSL_CMP_CTX_set1_no_proxy() تعين قائمة أسماء مضيفات الخادم التي لا يتم استخدام وكيل HTTP لها. يمكن فصل الأسماء بفواصل و/أو مسافات. الافتراضي هو متغير البيئة "no_proxy" إذا تم تعيينه، وإلا "NO_PROXY".

OSSL_CMP_CTX_set_http_cb() تعين دالة رد الاتصال الاختيارية لـ BIO connect/disconnect، والتي لها النموذج الأولي

typedef BIO *(*HTTP_bio_cb_t) (BIO *bio, void *arg, int connect, int detail);

قد يقوم رد الاتصال بتعديل bio الذي توفره OSSL_CMP OSSL_HTTP_open(3) describe el callback que pueda hacer uso de un argumento personalizado arg, como se describe para el parámetro arg de OSSL_HTTP_open(3). El argumento se almacena en el OSSL_CMP_CTX mediante OSSL_CMP_CTX_set_http_cb_arg(). Véase también la opción OSSL_CMP_OPT_USE_TLS descrita anteriormente.

OSSL_CMP_CTX_set_http_cb_arg() establece el argumento, respectivamente un puntero a un estructura que contiene argumentos tales como una estructura SSL_CTX, opcionalmente usado por el callback de conexión/disconexión de HTTP. arg no se consume y debe por lo tanto ser liberado explícitamente cuando no lo necesita más. arg puede ser NULL para quitar la entrada. Si se establece un valor no NULL, no se puede usar OSSL_CMP_CTX_set1_proxy() o OSSL_CMP_CTX_set1_no_proxy() para establecer strings no NULL.

OSSL_CMP_CTX_get_http_cb_arg() obtiene el argumento, respectivamente el puntero a una estructura que contiene argumentos, previamente establecido por OSSL_CMP_CTX_set_http_cb_arg() o NULL si no está establecido.

OSSL_CMP_CTX_set_transfer_cb() establece la función de transferencia de mensajes, que tiene el tipo

typedef OSSL_CMP_MSG *(*OSSL_CMP_transfer_cb_t) (OSSL_CMP_CTX *ctx,
                                                 const OSSL_CMP_MSG *req);

El valor predeterminado es NULL, lo que implica el uso de OSSL_CMP_MSG_http_perform(3). La función de callback debe enviar el mensaje CMP de solicitud que obtiene a través del parámetro req y, en caso de éxito, devolver la respuesta, de lo contrario devolver NULL. La función de transferencia puede hacer uso de un argumento personalizado almacenado en el ctx mediante OSSL_CMP_CTX_set_transfer_cb_arg(), que puede ser recuperado mediante OSSL_CMP_CTX_get_transfer_cb_arg().

OSSL_CMP_CTX_set_transfer_cb_arg() establece un argumento, respectivamente un puntero a una estructura que contiene argumentos, opcionalmente usado por la función de transferencia. arg no se consume y debe por lo tanto ser liberado explícitamente cuando no lo necesita más. arg puede ser NULL para quitar la entrada.

OSSL_CMP_CTX_get_transfer_cb_arg() obtiene el argumento, respectivamente el puntero a una estructura que contiene argumentos, previamente establecido por OSSL_CMP_CTX_set_transfer_cb_arg() o NULL si no está establecido.

OSSL_CMP_CTX_set1_srvCert() establece la certificación esperada del servidor en ctx y confía directamente (incluso si está vencida) cuando verifica los mensajes de respuesta firmados. Esto fija el servidor aceptado y resulta en el ignorar cualquier configuración establecida con OSSL_CMP_CTX_set0_trusted(). Cualquier valor previamente establecido es liberado. El argumento cert puede ser NULL para quitar la entrada. Si se establece, el tema de la certificación también se usa como valor por defecto para el destinatario de las solicitudes CMP y como valor por defecto para el emisor de las respuestas CMP.

OSSL_CMP_CTX_set1_expected_sender() establece el nombre del Distinguished Name (DN) esperado en el campo emisor de las solicitudes CMP. El valor predeterminado es el tema de la certificación fijada en el servidor, si está presente. Esto puede usarse para asegurar que solo una entidad específica sea aceptada como firmante de mensajes CMP, y que los atacantes no puedan usar cálculos de certificados de una jerarquía de PKI confiada para falsificar como servidor CMP. Nota que este ofrece un poco más de libertad que OSSL_CMP_CTX_set1_srvCert(), que fija el servidor a la posesión de una certificación específica, mientras el nombre del emisor continuará a coincidir incluso después de actualizaciones de la certificación del servidor.

OSSL_CMP_CTX_set0_trusted() es un alias de la original OSSL_CMP_CTX_set0_trustedStore(). Establece en el contexto CMP ctx el almacenamiento de certificados de tipo X509_STORE que contiene certificados confiados, típicamente de cáracteres de raíz. Este es ignorado cuando se fija una certificación con OSSL_CMP_CTX_set1_srvCert(). El almacenamiento puede también incluir CRLs y una función de verificación de certificados usada para autenticación basada en firma. Cualquier entrada previamente establecida es liberada. Cuando se le pasa un parámetro NULL, la entrada se limpia.

OSSL_CMP_CTX_get0_trusted() es un alias de la original OSSL_CMP_CTX_get0_trustedStore(). Extrae del contexto CMP ctx el puntero al almacenamiento de certificados actualmente establecido que contiene anclajes de confianza, o un almacenamiento vacío si no está establecido.

OSSL_CMP_CTX_set1_untrusted() establece una lista de certificados no confiables de CAs intermedias que pueden ser útiles para la construcción de rutas en la propia certificación de CMP, para la propia certificación TLS (si es que existe), al verificar certificados de protección de CMP, y al verificar certificados recién enrollados. Los contadores de referencias de estos certificados procesados correctamente se incrementan. La lista de certificados no confiables en ctx se ampliará con extraCerts recibidos en los mensajes CMP, a menos que OSSL_CMP_OPT_NO_CACHE_EXTRACERTS esté configurado.

OSSL_CMP_CTX_get0_untrusted() devuelve un puntero a la lista de certificados no confiables en ctx, que puede estar vacía si no está establecida.

OSSL_CMP_CTX_set1_cert() establece la certificación del signer certificate, también llamada protection certificate, relacionada con la clave privada utilizada para la protección de mensajes CMP basados en firma. Por lo tanto, la clave pública de este cert debe corresponder a la clave privada establecida antes o después mediante OSSL_CMP_CTX_set1_pkey(). Cuando se usa la protección basada en firma de mensajes CMP, este certificado de firma será incluido primero en el campo extraCerts. Sirve como certificado de referencia de recurrimiento, ver OSSL_CMP_CTX_set1_oldCert(). El tema de este cert se usará como campo emisor de mensajes salientes, mientras que el tema de cualquier certificado establecido mediante OSSL_CMP_CTX_set1_oldCert(), el tema de cualquier certificado generado mediante OSSL_CMP_CTX_set1_p10CSR(), y cualquier valor establecido mediante OSSL_CMP_CTX_set1_subjectName() se usará como fallback.

El argumento cert puede ser NULL para quitar la entrada.

OSSL_CMP_CTX_build_cert_chain() construye una cadena de certificados para el certificado de firma del CMP establecido previamente en ctx. Agrega los candidates, una lista de certificados de CA intermedios que puedan ya constituir la cadena objetivo, a los certificados no confiables que ya existen en ctx. Luego, la función usa esta lista ampliada para la construcción de la cadena. Si own_trusted es NULL, construye la cadena lo más profundamente posible y ignora cualquier error de verificación. De lo contrario, el certificado de firma del servidor debe ser verificable donde la cadena alcanza un anclaje de confianza contenido en own_trusted. En caso de éxito, la función almacena la cadena resultado en ctx para ser incluida en el campo extraCerts de mensajes protegidos por firma. La llamada a esta función es opcional; por defecto, se realiza la construcción de la cadena de forma on demand equivalente a llamar esta función con los parámetros candidates y own_trusted siendo NULL.

OSSL_CMP_CTX_set1_pkey() establece la clave privada del cliente correspondiente a la certificación del servidor CMP establecida mediante OSSL_CMP_CTX_set1_cert(). Esta clave se usa para crear la protección basada en firma (protecciónAlg = MSG_SIG_ALG) de los mensajes salientes, a menos que se haya establecido una clave secreta mediante OSSL_CMP_CTX_set1_secretValue(). El argumento pkey puede ser NULL para quitar la entrada.

OSSL_CMP_CTX_set1_secretValue() establece en ctx el string de bytes sec de longitud len como clave compartida previa, o lo limpia si el argumento sec es NULL. Si está presente, esta clave se usa para crear autenticación y protección de integridad (más que aplicar protección basada en firma) de los mensajes salientes, y para verificar la autenticidad y la integridad de los mensajes entrantes con protección basada en firma (protecciónAlg = "MSG_MAC_ALG").

OSSL_CMP_CTX_set1_referenceValue() establece el valor dado ref con longitud len en el contexto ctx o lo limpia si el argumento ref es NULL. Según el RFC 4210 sección 5.1.1, si no se puede determinar el valor del campo emisor en los encabezados de mensaje CMP (es decir, no hay certificación del firmante y no se ha establecido la DN del sujeto mediante OSSL_CMP_CTX_set1_subjectName()), el campo emisor contendrá el DN NULL y el campo senderKID de la cabecera del mensaje CMP debe ser establecido. Cuando se usa protección basada en firma, el senderKID se establecerá en el subjectKeyIdentifier de la certificación del firmante del CMP. Si no está presente o cuando se use protección basada en MAC, el valor ref se usará como valor de fallback para senderKID.

OSSL_CMP_CTX_set1_recipient() establece el nombre del destinatario que se usará en el Encabezado PKI de las solicitudes CMP, es decir, el nombre X509 del servidor (CA).

El campo destinatario en el encabezado de un mensaje CMP es obligatorio. Si no se le especifica explícitamente, el destinatario se determina en el siguiente orden: el tema de la certificación del servidor establecida mediante OSSL_CMP_CTX_set1_srvCert(), el valor establecido mediante OSSL_CMP_CTX_set1_issuer(), el emisor de la certificación establecida mediante OSSL_CMP_CTX_set1_oldCert(), el emisor de la certificación del firmante del CMP, a menos que algún de estos esté presente, de lo contrario el DN NULL como último recurso.

OSSL_CMP_CTX_push0_geninfo_ITAV() agrega itav a la pila en el contexto ctx para ser añadido al campo generalInfo del encabezado PKIMessage de un mensaje CMP enviado con este contexto.

OSSL_CMP_CTX_reset_geninfo_ITAVs() limpia cualquier ITAVs añadidos mediante OSSL_CMP_CTX_push0_geninfo_ITAV().

OSSL_CMP_CTX_get0_geninfo_ITAVs() devuelve la lista de ITAVs establecidos en ctx para ser incluidos en el campo generalInfo del encabezado PKIMessage de las solicitudes o NULL si no está establecido.

OSSL_CMP_CTX_set1_extraCertsOut() establece el stack de extraCerts que se enviará a distancia.

OSSL_CMP_CTX_set0_newPkey() puede usarse explícitamente para establecer el estructura dada priv como la clave privada o pública a ser certificada en el contexto CMP. El parámetro priv debe ser 0 si y solo si la clave dada es una clave pública.

OSSL_CMP_CTX_get0_newPkey() devuelve la clave para el enrollamiento de certificado dependiendo de los campos del estructura de contexto CMP: el newPkey (que puede ser una clave privada o pública) si está presente, de lo contrario la clave pública en el p10CSR si está presente, de lo contrario la clave privada del cliente. Si el parámetro priv no es 0 y el seleccionado clave no tiene un componente privado, se devuelve NULL.

OSSL_CMP_CTX_set1_issuer() establece el nombre del intencional emisor que se establecerá en el CertTemplate, es decir, el nombre X509 del servidor (CA) que se utiliza.

OSSL_CMP_CTX_set1_serialNumber() establece el número de serie opcional usado para seleccionar la certificación a revocar en solicitudes de revocación (RR).

OSSL_CMP_CTX_set1_subjectName() establece la DN del sujeto que se usará en la estructura CertTemplate cuando se solicita una nueva certificación. Para solicitudes de actualización de claves (KUR), el valor predeterminado es el DN del sujeto de la certificación referente.

DESCRIPTION

This section describes the various functions for creating, manipulating, and freeing an OSSL_CMP_CTX structure, which holds the context for CMP operations.

OSSL_CMP_CTX_new() creates and initializes a new CMP context. If libctx is NULL, the default library context is used.

OSSL_CMP_CTX_free() frees the given CMP context.

OSSL_CMP_CTX_load_from_file() creates a CMP context by loading configuration from the specified file path. The password is used to decrypt any encrypted data in the file.

OSSL_CMP_CTX_new_from_pkcs12() creates a CMP context from a PKCS#12 file. The password is used to decrypt the file.

The OSSL_CMP_CTX_set* and OSSL_CMP_CTX_get0* functions are accessors for the various fields within the OSSL_CMP_CTX structure. These include:

Trusted Certificates:
Functions to set and get the stack of trusted CA certificates. `set0` versions take ownership of the passed stack, `set1` versions copy it.
Client Certificate and Private Key:
Functions to set and get the client's certificate and private key used for authentication.
Reference Value and Secret Value:
Functions to set and get the reference value and secret value, typically used for authentication.
Serial Number:
Functions to set and get the serial number, often used for certificate requests.
New Private Key:
Functions to set and get a new private key. The `set0` version takes ownership if the `copy` argument is 0.
Recipient Certificate:
Functions to set and get the recipient's certificate, used for encrypted messages.
Unprotected Request:
Functions to set and get an unprotected request message.
Fail Info Code:
Functions to set and get the fail info code, indicating an error in a CMP response.
Additional Chain:
Functions to set and get an additional certificate chain, used to build trust paths.
Confirmation Wait Time:
Functions to set and get the confirmation wait time.
Policy:
Functions to set and get the requested certificate policy.
Salts:
Functions to set and get key and key information salts.
Nonce:
Functions to set and get the recipient nonce.
MAC:
Functions to set and get the recipient MAC.
Operation:
Functions to set and get the CMP operation type.
Transfer Time:
Functions to set and get the transfer time.
URL and Proxy:
Functions to set and get the URL and proxy for HTTP communication.
HTTP Client:
Functions to set and get the HTTP request context.
Valid Certificates:
Functions to set and get a stack of valid certificates.
New Certificate:
Functions to set and get a new certificate.
New MAC:
Functions to set and get a new MAC.
Private Key:
Functions to set and get the private key associated with the new certificate.
General Info:
Functions to set and get general information structures. The `set0_free_general_info` controls whether the general info should be freed when the context is freed.
General Message ITAVs:
Functions to push an ITAV onto the general message, reset all ITAVs, and retrieve the current stack of ITAVs.
Library Context and Properties:
Functions to get the library context and property query string.
Validated Server Certificate:
Functions to get the validated server certificate from the last successful CMP operation.

OSSL_CMP_CTX_reinit() resets the CMP context for a new transaction. It clears most fields but preserves settings like trusted certificates, client certificate/key, and transport information.

NOTES

The `OSSL_CMP_CTX_set0_trusted` and `OSSL_CMP_CTX_set0_trustedStore` functions have been renamed to `OSSL_CMP_CTX_set0_trusted` for consistency. The old name is kept for backward compatibility via a macro.

The `OSSL_CMP_CTX_get0_trusted` and `OSSL_CMP_CTX_get0_trustedStore` functions have been renamed to `OSSL_CMP_CTX_get0_trusted` for consistency. The old name is kept for backward compatibility via a macro.

The `set0` variants of the setter functions take ownership of the provided object (e.g., `X509*`, `EVP_PKEY*`, `STACK_OF(X509)*`). The `set1` variants create a copy of the object. The `get0` variants return a pointer to the object owned by the context and should not be freed by the caller.

RETURN VALUES

The `OSSL_CMP_CTX_new*` functions return a pointer to the newly allocated OSSL_CMP_CTX structure, or NULL on failure. The `OSSL_CMP_CTX_free` function returns void.

The `OSSL_CMP_CTX_set*` functions return 1 on success and 0 on failure.

The `OSSL_CMP_CTX_get0*` functions return a pointer to the internal object or NULL if not set.

OSSL_CMP_CTX_reinit() returns 1 on success, 0 on failure.

EXAMPLES

Initialize CMP context and set up certificate request details:

OSSL_CMP_CTX *cmp_ctx = NULL;
X509_NAME *name = NULL;
EVP_PKEY *initialKey = NULL;
X509 *initialCert = NULL;
EVP_PKEY *currentKey = NULL;
X509 *currentCert = NULL;
EVP_PKEY *curentKey = NULL;
EVP_PKEY *updatedKey = NULL;

/* Assuming cmp_ctx, name, initialKey are initialized */

OSSL_CMP_CTX_set1_subjectName(cmp_ctx, name);
OSSL_CMP_CTX_set0_newPkey(cmp_ctx, 1, initialKey);

Perform an Initialization Request transaction:

initialCert = OSSL_CMP_exec_IR_ses(cmp_ctx);

Reset the transaction state of the CMP context and the credentials:

OSSL_CMP_CTX_reinit(cmp_ctx);
OSSL_CMP_CTX_set1_referenceValue(cmp_ctx, NULL, 0);
OSSL_CMP_CTX_set1_secretValue(cmp_ctx, NULL, 0);

Perform a Certification Request transaction, making use of the new credentials:

OSSL_CMP_CTX_set1_cert(cmp_ctx, initialCert);
OSSL_CMP_CTX_set1_pkey(cmp_ctx, initialKey);
OSSL_CMP_CTX_set0_newPkey(cmp_ctx, 1, curentKey);
currentCert = OSSL_CMP_exec_CR_ses(cmp_ctx);

Perform a Key Update Request, signed using the cert (and key) to be updated:

OSSL_CMP_CTX_reinit(cmp_ctx);
OSSL_CMP_CTX_set1_cert(cmp_ctx, currentCert);
OSSL_CMP_CTX_set1_pkey(cmp_ctx, currentKey);
OSSL_CMP_CTX_set0_newPkey(cmp_ctx, 1, updatedKey);
currentCert = OSSL_CMP_exec_KUR_ses(cmp_ctx);
currentKey = updatedKey;

Perform a General Message transaction including, as an example, the id-it-signKeyPairTypes OID and prints info on the General Response contents:

OSSL_CMP_CTX_reinit(cmp_ctx);
ASN1_OBJECT *type = OBJ_txt2obj("1.3.6.1.5.5.7.4.2", 1);
OSSL_CMP_ITAV *itav = OSSL_CMP_ITAV_create(type, NULL);
OSSL_CMP_CTX_push0_genm_ITAV(cmp_ctx, itav);
STACK_OF(OSSL_CMP_ITAV) *itavs;
itavs = OSSL_CMP_exec_GENM_ses(cmp_ctx);
print_itavs(itavs);
sk_OSSL_CMP_ITAV_pop_free(itavs, OSSL_CMP_ITAV_free);

HISTORY

The OpenSSL CMP functions were added in OpenSSL 3.0.

OSSL_CMP_CTX_get0_trustedStore() was renamed to OSSL_CMP_CTX_get0_trusted() and OSSL_CMP_CTX_set0_trustedStore() was renamed to OSSL_CMP_CTX_set0_trusted(), using macros, while keeping the old names for backward compatibility, in OpenSSL 3.2.

OSSL_CMP_CTX_reset_geninfo_ITAVs() was added in OpenSSL 3.0.8.

OSSL_CMP_CTX_set1_serialNumber(), OSSL_CMP_CTX_get0_libctx(), OSSL_CMP_CTX_get0_propq(), and OSSL_CMP_CTX_get0_validatedSrvCert() were added in OpenSSL 3.2.

OSSL_CMP_CTX_get0_geninfo_ITAVs() was added in OpenSSL 3.3.

Support for central key generation, requested via OSSL_CRMF_POPO_NONE, was added in OpenSSL 3.5.
