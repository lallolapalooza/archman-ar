OPENSSL_ia32cap(3ssl)

الحزمة: openssl

التراخيص: Apache-2.0

NAME

OPENSSL_ia32cap, OPENSSL_ia32cap_set_mode, OPENSSL_ia32cap_get_mode - processor capability control

SYNOPSIS

#include <openssl/ia32cap.h>

int OPENSSL_ia32cap_set_mode(const char *cap_str);

unsigned long OPENSSL_ia32cap_get_mode(void);

DESCRIPTION

The environment variable OPENSSL_ia32cap is a string that can be used to control the set of processor instruction set extensions that OpenSSL will attempt to use. It is primarily intended for diagnostic purposes, and to enable users to exert finer control over instruction set extension usage than would otherwise be possible.

The string is parsed into up to 5 logical vectors (LV0 to LV4), each representing a bitmask of processor capabilities. Each vector is represented as a sequence of colon-delimited values. For example, the string "LV0:LV1:LV2:LV3:LV4" represents the five logical vectors.

Each logical vector value can be represented as a decimal, octal, or hexadecimal number. For example, "0x20:10" means LV0 is 0x20 and LV1 is 10.

The logical vectors are used in the following manner:

  • LV0: Processor capabilities, primarily related to AVX-512 and newer.
  • LV1: Processor capabilities, primarily related to AVX2 and AVX.
  • LV2: Processor capabilities, primarily related to SSE2.
  • LV3: Processor capabilities, primarily related to SSE.
  • LV4: Processor capabilities, primarily related to x87 FPU.

The value of the environment variable is parsed by OPENSSL_ia32cap_set_mode(). If the call is successful, the current processor capabilities are updated according to the value provided. Subsequent calls to OPENSSL_ia32cap_get_mode() will return the value that was set. If the environment variable is not set, or if OPENSSL_ia32cap_set_mode() is not called, OpenSSL will determine the processor capabilities at runtime.

The environment variable OPENSSL_ia32cap can be set in several ways:

The default behaviour is to query the CPUID instruction at runtime and determine the capabilities from that. If the environment variable OPENSSL_ia32cap is set, then its value is used to determine the capabilities instead.

The value is a colon-separated list of logical vectors (LV). Each logical vector corresponds to a certain set of processor capabilities. The vectors are assigned as follows:

LV0
Capabilities related to AVX-512 and newer instruction sets.
LV1
Capabilities related to AVX2 and AVX instruction sets.
LV2
Capabilities related to SSE2 instruction set.
LV3
Capabilities related to SSE instruction set.
LV4
Capabilities related to x87 FPU instruction set.

Each logical vector value is a bitmask representing the enabled capabilities. These values can be specified as decimal, octal, or hexadecimal numbers. For example, "0x20:10" means LV0 is set to 0x20 and LV1 is set to 10.

When the environment variable is used in this form, each non-null logical vector will *overwrite* the entire corresponding capability vector pair with the provided value. To maintain compatibility with the behaviour of the original OPENSSL_ia32cap environment variable <env OPENSSL_ia32cap=LV0:LV1>, the subsequent capability vector pairs will be set to zero. For example:

"env OPENSSL_ia32cap=LV0:LV1:LV2:LV3:LV4"

Used in this form, each non-null logical vector will *overwrite* the entire corresponding capability vector pair with the provided value. To keep compatibility with the behaviour of the original OPENSSL_ia32cap environment variable <env OPENSSL_ia32cap=LV0:LV1>, the next capability vector pairs will be set to zero.

To illustrate, the following will zero all capability bits in logical vectors 1 and further (disable all post-AVX extensions):

"env OPENSSL_ia32cap=:0"

The following will zero all capability bits in logical vectors 2 and further:

"env OPENSSL_ia32cap=::0"

The following will zero all capability bits only in logical vector 1: "env OPENSSL_ia32cap=:0::::"

A more likely usage scenario would be to disable specific instruction set extensions. The '~' character is used to specify a bit mask of the extensions to be disabled for a particular logical vector.

To illustrate, the following will disable AVX2 code paths and further extensions:

"env OPENSSL_ia32cap=:~0x20000000000"

The following will disable AESNI (LV0 bit 57) and VAES (LV1 bit 41) extensions and therefore any code paths using those extensions but leave the rest of the logical vectors unchanged:

"env OPENSSL_ia32cap=~0x200000000000000:~0x20000000000:~0x0:~0x0:~0x0"

NOTES

Not all capability bits are copied from CPUID output verbatim. An example of this is the somewhat less intuitive clearing of LV0 bit #28, or ~0x10000000 in the "environment variable" terms. It has been adjusted to reflect whether or not the data cache is actually shared between logical cores. This in turn affects the decision on whether or not expensive countermeasures against cache-timing attacks are applied, most notably in AES assembler module.
