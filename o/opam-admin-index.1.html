opam-admin-index(1)

الحزمة: opam

التراخيص: LGPL-2.1-only

OPAM ADMIN-INDEX(1) دليل Opam admin OPAM ADMIN-INDEX(1)

الاسم

opam admin-index - إنشاء ملف فهرس شامل لتقديمه عبر HTTP.

الملخص

opam admin index [--full-urls-txt] [--minimal-urls-txt] [--no-urls-txt] [خيار]…

الوصف

يمكن تقديم مستودع opam عبر HTTP أو HTTPS باستخدام أي خادم ويب. لهذا الغرض، يجب إنشاء فهرس شامل أولاً: يقوم هذا الأمر بإنشاء الملفات التي سيتوقعها عميل opam عند جلب البيانات من مصدر HTTP، ويجب تشغيله بعد إجراء أي تغييرات على محتويات المستودع.

خيارات

--full-urls-txt
إنشاء ملف 'urls.txt' شامل، لمستودع سيتم استخدامه بواسطة إصدارات opam قبل 2.0.
--minimal-urls-txt
إنشاء ملف 'urls.txt' مصغر، والذي يتضمن فقط ملف 'repo'. هذا يسمح لإصدارات opam قبل 2.0 بقراءة هذا الملف، وإعادة توجيهها بشكل صحيح إلى مستودع مخصص لإصدارها، بافتراض تعريف حقل 'redirect:' مناسب، بدلاً من الفشل. هذا هو الافتراضي.
--no-urls-txt
لا تقم بإنشاء ملف 'urls.txt'. لم يعد ملف الفهرس هذا مطلوبًا من opam 2.0 فصاعدًا، ولكنه لا يزال يستخدمه الإصدارات الأقدم.

خيارات مشتركة

هذه الخيارات مشتركة لجميع الأوامر.

--best-effort
لا تفشل إذا لم يكن من الممكن تثبيت جميع الحزم المطلوبة: حاول تثبيت أكبر عدد ممكن. لاحظ أن ليس كل الحلول الخارجية قد تدعم هذا الخيار (الإصدارات الحديثة من aspcud أو mccs يجب أن تدعمه). هذا يعادل تعيين متغير البيئة $OPAMBESTEFFORT.
--cli=MAJOR.MINOR (افتراضي=2.4)
استخدم صيغة ودلالات الواجهة الطرفية MAJOR.MINOR. مخصص لأي استخدام دائم لـ opam (نصوص برمجية، تدوينات، إلخ)، أي إصدار من opam في نفس السلسلة MAJOR سيعمل كما هو الحال بالنسبة لإصدار MINOR المحدد. لم يكن العلم متاحًا في opam 2.0، لذا لاختيار واجهة 2.0 الطرفية، قم بتعيين متغير البيئة OPAMCLI إلى 2.0 بدلاً من استخدام هذا المعامل.
--color=متى
تلوين الإخراج. يجب أن تكون متى واحدة من دائما، أبدا أو تلقائي.
--confirm-level=مستوى
مستوى التأكيد، يجب أن يكون مستوى واحدًا من اسأل، لا، نعم أو نعم-غير-آمن. يمكن تحديده أكثر من مرة. إذا تم أيضًا إعطاء --yes أو --no، يتم أخذ قيمة آخر --confirm-level في الاعتبار. هذا يعادل تعيين $OPAMCONFIRMLEVEL.
--criteria=معايير
تحديد تفضيلات المستخدم لحل التبعيات لهذه التشغيلة. يتجاوز $OPAMCRITERIA، $OPAMFIXUPCRITERIA و $OPAMUPGRADECRITERIA. للحصول على تفاصيل حول اللغة المدعومة، والحلول الخارجية المتاحة، انظر http://opam.ocaml.org/doc/External_solvers.html. يمكن العثور على دليل عام لاستخدام تفضيلات الحلول في http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=اسم الملف
خيار التصحيح: احفظ طلبات CUDF المرسلة إلى الحل في اسم الملف-<n>.cudf حيث <n> هو الاستدعاء n-th للحل أثناء تشغيل opam.
--debug
طباعة رسالة التصحيح إلى stderr. هذا يعادل تعيين $OPAMDEBUG إلى "true".
--debug-level=مستوى
مثل --debug، ولكنه يسمح بتحديد مستوى التصحيح (--debug يضبطه إلى 1). يعادل تعيين $OPAMDEBUG إلى عدد صحيح موجب.
--git-version
طباعة إصدار git من opam، إذا تم تعيينه (أي، إذا كنت تستخدم إصدار تطوير)، ثم الخروج.
--help[=FMT] (افتراضي=auto)
عرض هذا المساعدة بتنسيق FMT. يجب أن يكون القيمة FMT واحدة من auto، pager، groff أو plain. مع auto، يكون التنسيق pager أو plain كلما كان متغير TERM هو dumb أو غير معرف.
--ignore-pin-depends
تجاهل الأقسام الإضافية المطلوبة بواسطة الحزم التي يتم تثبيتها، سواء يدويًا عبر opam pin أو عبر opam install DIR. هذا يعادل تعيين IGNOREPINDEPENDS=true.
--json=اسم الملف
حفظ نتائج تشغيل opam في ملف قابل للقراءة بواسطة الكمبيوتر. إذا كان اسم الملف يحتوي على الحرف `%'، فسيتم استبداله بفهرس لا يكتب فوق ملف موجود. مشابه لتعيين المتغير $OPAMJSON.
--no
الرد بلا على جميع أسئلة opam بنعم/لا دون طلب. انظر أيضًا --confirm-level. هذا يعادل تعيين $OPAMNO إلى "true".
--no-aspcud
تمت إزالته في 2.1.
--no-auto-upgrade
عند تكوين أو تحديث مستودع مكتوب لإصدار opam سابق (1.2)، يقوم opam بتحويله داخليًا إلى التنسيق الحالي. هذا يعطل هذا السلوك. لاحظ أنه يجب على المستودعات تحديد إصدار التنسيق الخاص بها في ملف 'repo' في جذرها، وإلا فسيتم افتراض أنها بالتنسيق الأقدم. في أي حال، من الأفضل ترقية المستودعات يدويًا باستخدام opam admin upgrade [--mirror URL] عندما يكون ذلك ممكنًا.
-q, --quiet
تعطيل --verbose.
--root=الجذر
استخدم الجذر كمسار الجذر الحالي. هذا يعادل تعيين $OPAMROOT إلى الجذر.
--safe, --readonly
تأكد من عدم تحديث أو إعادة كتابة أي شيء تلقائيًا. مفيد للاستدعاء من نصوص الإكمال، على سبيل المثال. سيفشل كلما كان مثل هذا التشغيل مطلوبًا؛ كما يتجنب انتظار الأقفال، ويتخطى الأسئلة التفاعلية ويتجاوز متغير $OPAMDEBUG. هذا يعادل تعيين متغير البيئة $OPAMSAFE.
--solver=CMD
تحديد الحل CUDF المراد استخدامه لحل مشاكل تثبيت الحزم. هذا إما حل مُعرَّف مسبقًا (يدعم هذا الإصدار من opam builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup)، أو أمر مخصص يجب أن يحتوي على المتغيرات %{input}%, %{output}%, %{criteria}%, ويمكن اختياريًا %{timeout}%. هذا يعادل تعيين $OPAMEXTERNALSOLVER.
--strict
فشل كلما تم العثور على خطأ في تعريف حزمة أو ملف تكوين. الافتراضي هو المتابعة بصمت إذا أمكن.
--switch=SWITCH
استخدم SWITCH كمحول مترجم حالي. هذا يعادل تعيين $OPAMSWITCH إلى SWITCH.
--use-internal-solver
تعطيل أي حل خارجي، واستخدام الحل المدمج (هذا يتطلب أن يكون opam قد تم تجميعه باستخدام حل مدمج). هذا يعادل تعيين $OPAMNOASPCUD أو $OPAMUSEINTERNALSOLVER.
-v, --verbose
كن أكثر تفصيلاً. يظهر -v واحد أوامر الحزم، وكرر لعرض الأوامر التي يتم استدعاؤها داخليًا أيضًا (مثل tar، curl، patch إلخ.) التكرار n مرة يعادل تعيين $OPAMVERBOSE إلى "n".
--version
عرض معلومات الإصدار.
-w, --working-dir
كلما تم تحديث الحزم المرتبطة بدليل محلي محكوم بالإصدار، قم بالتحديث إلى الحالة العاملة الحالية لمصدرها بدلاً من الحالة الملتزمة الأخيرة، أو المرجع الذي تشير إليه. نظرًا لأنه يتم نسخ دليل المصدر كما هو، فقد يؤدي عدم كونه نظيفًا إلى فشل بناء opam. هذا يؤثر فقط على الحزم المدرجة صراحة في سطر الأوامر. يمكن تعيينه أيضًا مع $OPAMWORKINGDIR.
-y, --yes
الرد بنعم على جميع أسئلة opam بنعم/لا دون طلب. انظر أيضًا --confirm-level. هذا يعادل تعيين $OPAMYES إلى "true".

OPAMKEEPBUILDDIR see install option `--keep-build-dir'.

OPAMKEEPLOGS tells opam to not remove some temporary command logs and some backups. This skips some finalisers and may also help to get more reliable backtraces.

OPAMLOCKED combination of `--locked' and `--lock-suffix' options.

OPAMLOGS logdir sets log directory, default is a temporary directory in /tmp

OPAMMAKECMD set the system make command to use.

OPAMMERGEOUT merge process outputs, stderr on stdout.

OPAMNO answer no to any question asked, see options `--no` and `--confirm-level`. OPAMNO is ignored if either OPAMCONFIRMLEVEL or OPAMYES is set.

OPAMNOAGGREGATE with `opam admin check', don't aggregate packages.

OPAMSOLVERALLOWSUBOPTIMAL (default `true') allows some solvers to still return a solution when they reach timeout; while the solution remains assured to be consistent, there is no guarantee in this case that it fits the expected optimisation criteria. If `true', opam willcontinue with a warning, if `false' a timeout is an error. Currently only the builtin-z3 backend handles this degraded case.

OPAMSOLVERTIMEOUT change the time allowance of the solver. Default is 60.0, set to 0 for unlimited. Note that all solvers may not support this option.

OPAMSOLVERTOLERANCE changes the tolerance towards the solver choosing an unoptimized solution (i.e. might pull outdated packages). Typical values range from 0.0 (best solution known to the solver) to 1.0 (unoptimized solution). Default is 0.0. This option is useful in case the solver can't find a solution in a reasonable time (see $OPAMSOLVERTIMEOUT). Note that all solvers may not support this option.

CLI VERSION

All scripts and programmatic invocations of opam should use `--cli' in order to ensure that they work seamlessly with future versions of the opam client. Additionally, blog posts or other documentation can benefit, as it prevents information from becoming stale.

Although opam only supports roots (~/.opam/) for the current version, it does provide backwards compatibility for its command-line interface.

Since CLI version support was only added in opam 2.1, use OPAMCLI to select 2.0 support (as opam 2.0 will just ignore it), and `--cli=2.1' for 2.1 (or later) versions, since an environment variable controlling the parsing of syntax is brittle. To this end, opam displays a warning if OPAMCLI specifies a valid version other than 2.0, and also if `--cli=2.0' is specified.

The command-line version is selected by using the `--cli' option or the OPAMCLI environment variable. `--cli' may be specified morethan once, where the last instance takes precedence. OPAMCLI is only inspected if `--cli' is not given.

EXIT STATUS

As an exception to the following, the `exec' command returns 127 if the command was not found or couldn't be executed, and the command's exit value otherwise.

0
Success, or true for boolean queries.
1
False. Returned when a boolean return value is expected, e.g. when running with --check, or for queries like opam lint.
2
Bad command-line arguments, or command-line arguments pointing to an invalid context (e.g. file not following the expected format).
5
Not found. You requested something (package, version, repository, etc.) that couldn't be found.
10
Aborted. The operation required confirmation, which wasn't given.
15
opam-admin(1)

EXIT STATUS

EXIT STATUS describes the exit codes of the opam-admin(1) command.

1
Could not acquire the locks required for the operation.
20
There is no solution to the user request. This can be caused by asking to install two incompatible packages, for example.
30
Error in package definition, or other metadata files. Using --strict raises this error more often.
31
Package script error. Some package operations were unsuccessful. This may be an error in the packages or an incompatibility with your system. This can be a partial error.
40
Sync error. Could not fetch some remotes from the network. This can be a partial error.
50
Configuration error. Opam or system configuration doesn't allow operation, and needs fixing.
60
Solver failure. The solver failed to return a sound answer. It can be due to a broken external solver, or an error in solver configuration.
99
Internal error. Something went wrong, likely due to a bug in opam itself.
130
User interrupt. SIGINT was received, generally due to the user pressing Ctrl-C.
0
on success.
123
on indiscriminate errors reported on standard error.
124
on command line parsing errors.
125
on unexpected internal errors (bugs).
