الوصف

تقوم الدالة open() بفتح ملف أو إنشاءه وتُرجع واصف ملف غير سالب يمثل الملف المفتوح. يجب أن تحدد علامة واحدة على الأقل من العلامات O_RDONLY، O_WRONLY، أو O_RDWR للوصول إلى الملف. يمكن دمج هذه العلامات مع علامات أخرى لتحديد سلوكيات الفتح.

O_DIRECTORY
إذا تم تعيين هذه العلامة، فيجب أن يشير المسار path إلى دليل. إذا لم يكن كذلك، فستفشل الدالة. إذا لم يتم تعيين O_DIRECTORY، وكانت علامة O_CREAT موجودة، وإذا كان الملف موجودًا بالفعل وكان ملفًا عاديًا، فستفشل الدالة.
O_EXCL
إذا تم تعيين هذه العلامة مع O_CREAT، فيجب أن تفشل الدالة إذا كان الملف موجودًا بالفعل. يتم استخدام هذه العلامة لضمان إنشاء ملف جديد فقط.
O_NOCTTY
إذا تم تعيين هذه العلامة، ولم يكن جهاز الطرفية مفتوحًا بالفعل في أي عملية، فلن يصبح الجهاز هو الطرفية المتحكمة للمنفذ. تستخدم هذه العلامة بشكل أساسي عند فتح طرفيات معينة.
O_NONBLOCK
إذا تم تعيين هذه العلامة، فإن عمليات القراءة والكتابة على واصف الملف المرتجع لن تحظر. إذا كان الجهاز عبارة عن أنبوب (FIFO)، وإذا تم فتح الواجهة الأمامية للكتابة، وفتحت الواجهة الخلفية للقراءة، ولم تكن هناك عملية تقرأ من الأنبوب، فإن فتح الأنبوب للقراءة باستخدام O_NONBLOCK سيعود فورًا بدون فشل. عند الفتح للكتابة، لا يؤثر O_NONBLOCK على سلوك الأنفاق.
O_SYNC
تؤدي هذه العلامة إلى أن تكون عمليات الكتابة متزامنة. يجب أن يتم تحديث بيانات الملف و OR metadata الخاصة به على الوسيط الفوري للتخزين.
O_TRUNC
إذا تم تعيين هذه العلامة وكان الملف موجودًا بالفعل، فسيتم تقصير طول الملف إلى صفر.
O_TTY_INIT
إذا كانت القيمة O_TTY_INIT تساوي صفرًا، فستقوم الدالة open() بتعيين أي معلمات غير قياسية لهيكل termios الطرفي إلى حالة توفر سلوكًا متوافقًا؛ انظر وحدة التعريفات الأساسية لوحدة POSIX.1−2017، القسم 11.2، المعلمات التي يمكن تعيينها. غير محدد ما إذا كانت O_TTY_INIT لها أي تأثير إذا كان الجهاز مفتوحًا بالفعل في أي عملية. إذا كان المسار path يشير إلى الجانب التابع لطرفية وهمية غير مفتوحة حاليًا في أي عملية، فستقوم الدالة open() بتعيين أي معلمات غير قياسية لهيكل termios الطرفي إلى حالة توفر سلوكًا متوافقًا، بغض النظر عما إذا كانت O_TTY_INIT مضبوطة. إذا كان المسار path لا يشير إلى جهاز طرفي، فسيتم تجاهل O_TTY_INIT.

إذا تم تعيين O_CREAT و O_DIRECTORY معًا، وكان وضع الوصول المطلوب ليس O_WRONLY أو O_RDWR، فالنتيجة غير محددة.

إذا تم تعيين O_CREAT ولم يكن الملف موجودًا سابقًا، عند اكتماله بنجاح، ستحدد الدالة open() طوابع الوصول الأخيرة لبيانات الملف، وتعديل البيانات الأخيرة، وتغيير حالة الملف الأخيرة، وطوابع تعديل البيانات الأخيرة وتغيير حالة الملف الأخيرة للدليل الأب للتحديث.

إذا تم تعيين O_TRUNC وكان الملف موجودًا سابقًا، عند اكتماله بنجاح، ستحدد الدالة open() طوابع تعديل البيانات الأخيرة وتغيير حالة الملف الأخيرة للملف للتحديث.

إذا تم تعيين كل من علامتي O_SYNC و O_DSYNC، فسيكون التأثير كما لو تم تعيين علامة O_SYNC فقط.

إذا كان المسار path يشير إلى ملف STREAMS، فيمكن بناء oflag من O_NONBLOCK OR'ed مع إما O_RDONLY أو O_WRONLY أو O_RDWR. علامات أخرى غير قابلة للتطبيق على أجهزة STREAMS ولن يكون لها أي تأثير عليها. تؤثر القيمة O_NONBLOCK على تشغيل برامج تشغيل STREAMS ووظائف معينة مطبقة على واصفات الملفات المرتبطة بملفات STREAMS. بالنسبة لبرامج تشغيل STREAMS، فإن تطبيق O_NONBLOCK يعتمد على الجهاز.

يجب على التطبيق التأكد من أنه يحدد علامة O_TTY_INIT عند الفتح الأول لجهاز طرفي منذ تمهيد النظام أو منذ إغلاق الجهاز بواسطة العملية التي كان لديه مفتوحًا آخر مرة. لا يحتاج التطبيق إلى تحديد علامة O_TTY_INIT عند فتح طرفيات وهمية. إذا كان المسار path يسمي الجانب الرئيسي لجهاز طرفي وهمي، فمن غير المحدد ما إذا كانت الدالة open() ستقفل الجانب التابع بحيث لا يمكن فتحه. يجب على التطبيقات المتوافقة استدعاء unlockpt() قبل فتح الجانب التابع.

سيتم تعيين أكبر قيمة يمكن تمثيلها بشكل صحيح في كائن من نوع off_t كحد أقصى للإزاحة في وصف ملف مفتوح.

ستكون الدالة openat() مكافئة للدالة open() باستثناء الحالة التي يحدد فيها المسار path مسارًا نسبيًا. في هذه الحالة، يتم تحديد الملف المراد فتحه بالنسبة للدليل المرتبط بواصف الملف fd بدلاً من الدليل الحالي. إذا كان وضع الوصول لوصف الملف المفتوح المرتبط بواصف الملف ليس O_SEARCH، فستقوم الدالة بالتحقق مما إذا كانت عمليات البحث في الدليل مسموح بها باستخدام الأذونات الحالية للدليل الأساسي لواصف الملف. إذا كان وضع الوصول هو O_SEARCH، فلن تجري الدالة الفحص.

تتوافق المعلمة oflag والمعلمة الاختيارية الرابعة تمامًا مع معلمات الدالة open().

إذا تم تمرير AT_FDCWD، وهي قيمة خاصة، إلى الدالة openat() في المعلمة fd، فسيتم استخدام الدليل الحالي وسيكون السلوك مطابقًا لاستدعاء الدالة open().

قيمة الإرجاع

عند اكتمالها بنجاح، ستفتح هذه الدوال الملف وتعيد عددًا صحيحًا غير سالب يمثل واصف الملف. بخلاف ذلك، ستعيد هذه الدوال -1 وتعيين errno للإشارة إلى الخطأ. إذا تم إرجاع -1، فلن يتم إنشاء أو تعديل أي ملفات.

الأخطاء

ستفشل هذه الدوال إذا:

EACCES
يتم رفض إذن البحث في مكون من بادئة المسار، أو الملف موجود وتم رفض الأذونات المحددة بواسطة oflag، أو الملف غير موجود وتم رفض إذن الكتابة للدليل الأصل للملف المراد إنشاؤه، أو تم تحديد O_TRUNC وتم رفض إذن الكتابة.
EEXIST
تم تعيين O_CREAT و O_EXCL، وكان الملف المسمى موجودًا.
EINTR
تم التقاط إشارة أثناء open().
EINVAL
التنفيذ لا يدعم عمليات الإدخال/الإخراج المتزامنة لهذا الملف.
EIO
يشير الوسيط path إلى ملف STREAMS وحدث تعليق أو خطأ أثناء open().
EISDIR
الملف المسمى هو دليل وتم تضمين oflag في O_WRONLY أو O_RDWR، أو تم تضمينه في O_CREAT بدون O_DIRECTORY.
ELOOP
توجد حلقة في الروابط الرمزية التي تم مواجهتها أثناء تحليل الوسيط path، أو تم تحديد O_NOFOLLOW وكان الوسيط path يسمي رابطًا رمزيًا.
EMFILE
جميع واصفات الملفات المتاحة للعملية مفتوحة حاليًا.
ENAMETOOLONG

طول مكون من المسار أطول من {NAME_MAX}.
ENFILE
العدد الأقصى المسموح به من الملفات مفتوح حاليًا في النظام.
ENOENT
لم يتم تعيين O_CREAT ولم يشر أحد مكونات path إلى ملف موجود، أو تم تعيين O_CREAT ولم يشر أحد مكونات بادئة المسار لـ path إلى ملف موجود، أو يشير path إلى سلسلة فارغة.
ENOENT أو ENOTDIR

تم تعيين O_CREAT، ويحتوي الوسيط path على حرف واحد على الأقل غير <slash> وينتهي بشرطات <slash> واحدة أو أكثر. إذا كان path بدون الشرطات <slash> الخلفية يشير إلى ملف موجود، فلن يحدث خطأ [ENOENT].
ENOSR
يشير الوسيط path إلى ملف قائم على STREAMS والنظام غير قادر على تخصيص STREAM.
ENOSPC
الدليل أو نظام الملفات الذي سيحتوي على الملف الجديد لا يمكن توسيعه، والملف غير موجود، وتم تحديد O_CREAT.
ENOTDIR
يشير أحد مكونات بادئة المسار إلى ملف موجود وهو ليس دليلًا أو رابطًا رمزيًا لدليل؛ أو لم يتم تحديد O_CREAT و O_EXCL، ويحتوي الوسيط path على حرف واحد على الأقل غير <slash> وينتهي بشرطات <slash> واحدة أو أكثر، ويشير آخر مكون مسار إلى ملف موجود ليس دليلًا أو رابطًا رمزيًا لدليل؛ أو تم تحديد O_DIRECTORY وكان الوسيط path يحل إلى ملف غير دليل.
ENXIO
تم تعيين O_NONBLOCK، والملف المسمى هو FIFO، وتم تعيين O_WRONLY، ولا توجد عملية لديها الملف مفتوح للقراءة.
ENXIO
الملف المسمى هو ملف خاص بالأحرف أو ملف خاص بالكتل، والجهاز المرتبط بهذا الملف الخاص غير موجود.
EOVERFLOW
الملف المسمى هو ملف عادي ولا يمكن تمثيل حجم الملف بشكل صحيح في كائن من نوع off_t.
EROFS
الملف المسمى موجود على نظام ملفات للقراءة فقط وكان O_WRONLY أو O_RDWR أو O_CREAT (إذا كان الملف غير موجود) أو O_TRUNC محددًا في الوسيط oflag.

ستفشل الدالة openat() إذا:

EACCES
وضع الوصول لوصف الملف المفتوح المرتبط بـ fd ليس O_SEARCH ولا تسمح أذونات الدليل الأساسي لـ fd بعمليات البحث في الدليل.
EBADF
الوسيط path لا يحدد مسارًا مطلقًا و fd ليس AT_FDCWD ولا واصف ملف صالح مفتوح للقراءة أو البحث.
ENOTDIR
الوسيط path ليس مسارًا مطلقًا و fd هو واصف ملف مرتبط بملف غير دليل.

قد تفشل هذه الدوال إذا:

EAGAIN
الوسيط path يسمي الجانب التابع لجهاز طرفي وهمي مقفل.
EINVAL
قيمة الوسيط oflag غير صالحة.
ELOOP
تم مواجهة أكثر من {SYMLOOP_MAX} رابط رمزي أثناء تحليل الوسيط path.
ENAMETOOLONG

طول المسار يتجاوز {PATH_MAX}، أو حل المسار لرابط رمزي أنتج نتيجة وسيطة بطول يتجاوز {PATH_MAX}.
ENOMEM
الوسيط path يسمي ملف STREAMS والنظام غير قادر على تخصيص الموارد.
EOPNOTSUPP
الوسيط path يسمي مقبسًا.
ETXTBSY
الملف هو ملف إجراء نقي (نص مشترك) يتم تنفيذه وكان oflag هو O_WRONLY أو O_RDWR.

الأقسام التالية إعلامية.

أمثلة

فتح ملف للكتابة بواسطة المالك

يفتح المثال التالي الملف /tmp/file، إما بإنشائه (إذا لم يكن موجودًا بالفعل)، أو بتقصيره

بتنسيق المحتوى بأكمله إلى اللغة العربية. احتفظ ببنية الملف بأكملها. ```arabic حجمه إلى 0 (إذا كان موجودًا بالفعل). في الحالة الأولى، إذا أنشأت المكالمة ملفًا جديدًا، فإن بتات إذن الوصول في وضع الملف الخاص بالملف يتم تعيينها للسماح بالقراءة والكتابة للمالك، والسماح بالقراءة فقط لأعضاء المجموعة والآخرين.

إذا نجحت المكالمة إلى open()، فسيتم فتح الملف للكتابة.

#include <fcntl.h>
...
int fd;
mode_t mode = S_IRUSR | S_IWUSR | S_IRGRP | S_IROTH;
char *pathname = "/tmp/file";
...
fd = open(pathname, O_WRONLY | O_CREAT | O_TRUNC, mode);
...

فتح ملف باستخدام فحص الوجود

يستخدم المثال التالي الدالة open() لمحاولة إنشاء ملف LOCKFILE وفتحه للكتابة. نظرًا لأن الدالة open() تحدد علامة O_EXCL، تفشل المكالمة إذا كان الملف موجودًا بالفعل. في هذه الحالة، يفترض البرنامج أن شخصًا آخر يقوم بتحديث ملف كلمة المرور ويخرج.

#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#define LOCKFILE "/etc/ptmp"
...
int pfd; /* Integer for file descriptor returned by open() call. */
...
if ((pfd = open(LOCKFILE, O_WRONLY | O_CREAT | O_EXCL,
    S_IRUSR | S_IWUSR | S_IRGRP | S_IROTH)) == -1)
{
    fprintf(stderr, "Cannot open /etc/ptmp. Try again later.\n");
    exit(1);
}
...

فتح ملف للكتابة

يفتح المثال التالي ملفًا للكتابة، وينشئ الملف إذا لم يكن موجودًا بالفعل. إذا كان الملف موجودًا، فإن النظام يقتطع الملف إلى صفر بايت.

#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#define LOCKFILE "/etc/ptmp"
...
int pfd;
char pathname[PATH_MAX+1];
...
if ((pfd = open(pathname, O_WRONLY | O_CREAT | O_TRUNC,
    S_IRUSR | S_IWUSR | S_IRGRP | S_IROTH)) == -1)
{
    perror("Cannot open output file\n"); exit(1);
}
...

استخدام التطبيق

لا يتطلب POSIX.1-2008 تعيين معلمات الجهاز الطرفي تلقائيًا إلى أي حالة عند الفتح الأول، ولا إعادة تعيينها بعد الإغلاق الأخير. من الممكن لتطبيق غير متوافق أن يترك جهاز طرفي في حالة يجد فيها العملية التالية التي تستخدم هذا الجهاز في حالة غير متوافقة، ولكن ليس لديها طريقة لتحديد ذلك. لضمان تعيين الجهاز إلى حالة أولية متوافقة، يجب على التطبيقات التي تقوم بفتح طرفي أول (بخلاف الطرفي الوهمي) القيام بذلك باستخدام علامة O_TTY_INIT لتعيين المعلمات المرتبطة بالطرفي إلى حالة متوافقة.

باستثناء ما هو محدد في هذا المجلد من POSIX.1-2017، فإن العلامات المسموح بها في oflag ليست متعارضة ولا يمكن استخدام أي عدد منها في وقت واحد. لا تجعل جميع مجموعات العلامات منطقية. على سبيل المثال، سيؤدي استخدام O_SEARCH | O_CREAT إلى فتح دليل موجود بنجاح للبحث، ولكن إذا لم يكن هناك ملف بهذا الاسم موجود، فمن غير المحدد ما إذا كان سيتم إنشاء ملف عادي. وبالمثل، إذا تم إرجاع واصف ملف غير دليلي بنجاح، فمن غير المحدد ما إذا كان واصف الملف سيحتوي على أذونات تنفيذ كما لو كان بواسطة O_EXEC (لاحظ أنه من غير المحدد ما إذا كان O_EXEC و O_SEARCH لهما نفس القيمة).

الأساس المنطقي

تسمح بعض التطبيقات بفتح FIFOs باستخدام O_RDWR. نظرًا لأنه يمكن تنفيذ FIFOs بطرق أخرى، ولأنه يمكن استخدام واصفي ملفين لنفس التأثير، فإن هذه الإمكانية تُركت غير محددة.

انظر getgroups() بشأن مجموعة الملف الذي تم إنشاؤه حديثًا.

يُفضل استخدام open() لإنشاء ملف عادي بدلاً من استخدام creat()، لأن الأخير زائد عن الحاجة ومضمن فقط لأسباب تاريخية.

يجب أن يكون استخدام علامة O_TRUNC على FIFOs والأدلة (لا يمكن فتح الأنابيب باستخدام open()) ممكنًا دون آثار جانبية غير متوقعة (على سبيل المثال، يجب ألا يؤدي creat() على FIFO إلى إزالة البيانات). نظرًا لأنه قد يتم تخزين بيانات من النوع المسبق في المخزن المؤقت لملفات الطرفيات الخاصة، فلا يجب أن تؤثر O_TRUNC على محتواها، خاصة إذا كان البرنامج الذي يفتح ملفًا عاديًا عادةً يفتح الطرفي المتحكم الحالي بدلاً من ذلك. تُترك أنواع الملفات الأخرى، وخاصة تلك المحددة من قبل التطبيق، محددة من قبل التطبيق.

يسمح POSIX.1-2008 بإرجاع [EACCES] لحالات غير تلك المدرجة صراحة.

تمت إضافة علامة O_NOCTTY للسماح للتطبيقات بتجنب الاستحواذ غير المقصود على طرفي تحكم كأثر جانبي لفتح ملف طرفي. لا يحدد هذا المجلد من POSIX.1-2017 كيفية الاستحواذ على طرفي تحكم، ولكنه يسمح للتطبيق بتوفير هذا عند open() إذا لم يتم تعيين علامة O_NOCTTY وتم استيفاء الشروط الأخرى المحددة في مجلد التعريفات الأساسية لـ POSIX.1-2017، الفصل 11، واجهة الطرفيات العامة.

في التطبيقات التاريخية، قيمة O_RDONLY هي صفر. بسبب ذلك، لا يمكن اكتشاف وجود O_RDONLY وخيار آخر. يجب على التطبيقات المستقبلية ترميز O_RDONLY و O_WRONLY كعلامات بت بحيث:

O_RDONLY | O_WRONLY == O_RDWR

تم تحديد O_EXEC و O_SEARCH كوضعَي وصول للملف. نظرًا لأن O_EXEC لا ينطبق على الأدلة، و O_SEARCH ينطبق فقط على الأدلة، فلا يلزم أن تكون قيمهما مميزة. نظرًا لأن O_RDONLY كان له تاريخيًا قيمة صفر، فإن التطبيقات غير قادرة على التمييز بين O_SEARCH و O_SEARCH | O_RDONLY، وبالمثل بالنسبة لـ O_EXEC.

بشكل عام، تتبع الدالة open() الرابط الرمزي إذا كان path يشير إلى رابط رمزي. ومع ذلك، فإن الدالة open()، عند استدعائها مع O_CREAT و O_EXCL، مطلوبة بالفشل مع [EEXIST] إذا كان path يشير إلى رابط رمزي موجود، حتى لو كان الرابط الرمزي يشير إلى ملف غير موجود. هذا السلوك مطلوب للسماح للتطبيقات ذات الامتيازات بإنشاء ملف جديد في موقع معروف دون إمكانية أن يتسبب رابط رمزي في إنشاء الملف في موقع مختلف.

على سبيل المثال، يمكن اختراق تطبيق ذي امتيازات يجب عليه إنشاء ملف باسم يمكن التنبؤ به في دليل يمكن للمستخدم الكتابة فيه، مثل دليل المستخدم الرئيسي، إذا أنشأ المستخدم رابطًا رمزيًا بهذا الاسم يشير إلى ملف غير موجود في دليل النظام. إذا كان بإمكان المستخدم التأثير على محتويات ملف، فيمكن للمستخدم اختراق النظام عن طريق إنشاء ملف تكوين نظام جديد أو ملف تخزين مؤقت سيتم تفسيره بعد ذلك بواسطة النظام. يجب أن يكون اختبار الرابط الرمزي الذي يشير إلى ملف غير موجود متزامنًا مع إنشاء ملف جديد.

بالإضافة إلى ذلك، ترفض الدالة open() فتح الأدلة إذا تم تعيين علامة O_DIRECTORY. هذا يتجنب حالات السباق حيث قد يقوم المستخدم باختراق النظام عن طريق استبدال رابط صلب بملف حساس (مثل جهاز أو FIFO) أثناء تشغيل تطبيق ذي امتيازات، حيث قد يكون لفتح ملف حتى للوصول للقراءة آثار جانبية غير مرغوب فيها.

بالإضافة إلى ذلك، لا تتبع الدالة open() الروابط الرمزية إذا تم تعيين علامة O_NOFOLLOW. هذا يتجنب حالات السباق حيث قد يقوم المستخدم باختراق النظام عن طريق استبدال رابط رمزي بملف حساس (مثل جهاز) أثناء تشغيل تطبيق ذي امتيازات، حيث قد يكون لفتح ملف حتى للوصول للقراءة آثار جانبية غير مرغوب فيها.

فرض معيار POSIX.1-1990 أن معرف المجموعة لملف تم إنشاؤه حديثًا يجب تعيينه إلى معرف المجموعة لدليله الأب أو إلى معرف المجموعة الفعال للعملية التي أنشأته. فرض FIPS 151-2 على التطبيقات توفير طريقة لجعل معرف المجموعة يعيّن إلى معرف المجموعة للدليل المحتوي، ولكنه لم يحظر التطبيقات التي تدعم أيضًا طريقة لتعيين معرف المجموعة إلى معرف المجموعة الفعال للعملية التي أنشأته. لا يجب أن تفترض التطبيقات المتوافقة أي معرف مجموعة سيتم استخدامه. إذا كان الأمر مهمًا، يمكن للتطبيق استخدام chown() لتعيين معرف المجموعة بعد إنشاء الملف، أو تحديد الظروف التي سيقوم فيها التطبيق بتعيين معرف المجموعة المطلوب.

الغرض من الدالة openat() هو تمكين فتح الملفات في أدلة أخرى غير الدليل العامل الحالي دون التعرض لمخاطر السباق. يمكن تغيير أي جزء من مسار الملف بالتوازي مع استدعاء open()، مما يؤدي إلى سلوك غير محدد. عن طريق فتح واصف ملف للدليل المستهدف واستخدام الدالة openat()، يمكن ضمان أن الملف المفتوح يقع نسبيًا إلى الدليل المطلوب. تستخدم بعض التطبيقات الدالة openat() لأغراض أخرى أيضًا. في بعض الحالات، إذا كان المعلمة oflag تحتوي على علامة O_XATTR، فإن واصف الملف المُرجع يوفر الوصول إلى السمات الموسعة. هذه الوظيفة غير موحدة هنا.

NAME

open - redirect I/O to or from a program, or open a filehandle

SYNOPSIS

 open FH, $command
 open FH, "|-", $command
 open FH, "<-", $command
 open FH, $mode, $filename
 open FH, $mode, $filename, @args
 open FH, $filename
 open FH, "<", $filename
 open FH, ">", $filename
 open FH, "$mode>", $filename
 open FH, "$mode>>", $filename
 open FH, "$mode<", $filename
 open FH, "$mode<<", $filename
 open FH, "$mode<<<", $filename
 open FH, $format, @args
 open FH, $fh, $mode, $filename
 open FH, $fh, $mode, $filename, @args
 open FH, $fh, $filename
 open FH, $fh, "<", $filename
 open FH, $fh, ">", $filename
 open FH, $fh, "$mode>", $filename
 open FH, $fh, "$mode>>", $filename
 open FH, $fh, "$mode<", $filename
 open FH, $fh, "$mode<<", $filename
 open FH, $fh, "$mode<<<", $filename

DESCRIPTION

The built-in function open is used to associate a filehandle with a file, an I/O device, or a program running as a separate process.

The general syntax is:

 open FILEHANDLE, PERL_EXPR

Where FILEHANDLE is a scalar variable containing the name of the filehandle to use, or a bareword filehandle. PERL_EXPR is a Perl expression that evaluates to a string containing the name of the file to open, or the command to run.

If the expression evaluates to a string that begins with a vertical bar (|), the rest of the string is taken as a command to which Perl supplies the standard input. If the expression starts with a vertical bar but the rest of the string is empty, then the command "sort" is executed.

If the expression evaluates to a string that begins with a vertical bar but is not just a vertical bar, the rest of the string is taken as a command to which Perl supplies the standard output.

Otherwise, the string is taken as the name of a file to be opened. The mode and type of access are determined by the value of the variable $& (if it exists), or by examining the string itself.

If the string starts with "<", the file is opened for reading. If the string starts with ">", the file is opened for writing (and truncated if it exists). If the string starts with ">>", the file is opened for writing (and appended to if it exists). If the string starts with "<<" or "<<<", the file is opened for reading and writing.

If none of these apply, the file is opened for reading. This is the default behavior.

The optional $mode argument specifies the mode in which to open the file. This is useful for controlling permissions, buffering, etc.

The optional @args argument is used when opening a filehandle for a command that takes arguments.

The function returns true on success and false on failure. If it fails, the special variable $! is set to the system error message.

RETURN VALUE

Returns true on success, false on failure.

ERRORS

See perlfunc(1) for a detailed description of possible errors and how they are reported.

EXAMPLES

Open a file for reading:

 open my $fh, "<", "file.txt" or die "Could not open file 'file.txt': $!";

Open a file for writing:

 open my $fh, ">", "output.txt" or die "Could not open file 'output.txt': $!";

Open a file for appending:

 open my $fh, ">>", "log.txt" or die "Could not open file 'log.txt': $!";

Open a pipe to a command for reading:

 open my $fh, "-|", "ls -l" or die "Could not open pipe: $!";

Open a pipe to a command for writing:

 open my $fh, "|-", "sort" or die "Could not open pipe: $!";

APPLICATION USAGE

This function is a core part of Perl's I/O handling and is used extensively in scripts for file and process management.

RATIONALE

The open function provides a flexible and powerful interface for interacting with files and external processes. Its ability to handle different modes and command execution makes it a cornerstone of Perl scripting.

FUTURE DIRECTIONS

The open function is a mature and stable feature of Perl. Future development will likely focus on minor enhancements and ensuring compatibility with new operating system features.
