ovs-vsctl(8)

الحزمة: openvswitch

التراخيص: Apache-2.0

ovs-vsctl(8) دليل Open vSwitch ovs-vsctl(8)

الاسم

ovs-vsctl - أداة للاستعلام عن ovs-vswitchd وتكوينه

الملخص

ovs-vsctl [خيارات] -- [خيارات] أمر [وسائط] [-- [خيارات] أمر [وسائط]]...

الوصف

يقوم البرنامج ovs-vsctl بتكوين ovs-vswitchd(8) من خلال توفير واجهة عالية المستوى لقاعدة بيانات التكوين الخاصة به. راجع ovs-vswitchd.conf.db(5) للحصول على وثائق شاملة لمخطط قاعدة البيانات.

يتصل ovs-vsctl بعملية ovsdb-server التي تحتفظ بقاعدة بيانات تكوين Open vSwitch. باستخدام هذا الاتصال، يقوم بالاستعلام وربما تطبيق تغييرات على قاعدة البيانات، اعتمادًا على الأوامر المقدمة. بعد ذلك، إذا قام بتطبيق أي تغييرات، فإنه ينتظر افتراضيًا حتى ينتهي ovs-vswitchd من إعادة تكوين نفسه قبل الخروج. (إذا استخدمت ovs-vsctl عندما لا يكون ovs-vswitchd قيد التشغيل، فاستخدم --no-wait.)

يمكن لـ ovs-vsctl تنفيذ أي عدد من الأوامر في تشغيل واحد، وتنفيذها كمعاملة ذرية واحدة مقابل قاعدة البيانات.

يبدأ سطر أوامر ovs-vsctl بخيارات عامة (راجع الخيارات أدناه للحصول على التفاصيل). تتبع الخيارات العامة أمرًا واحدًا أو أكثر. يجب أن يبدأ كل أمر بـ -- بحد ذاته كوسيط لسطر الأوامر، لفصله عن الأوامر اللاحقة. (الـ -- قبل الأمر الأول اختياري.) يبدأ الأمر نفسه بخيارات خاصة بالأمر، إن وجدت، متبوعة باسم الأمر وأي وسائط. راجع الأمثلة أدناه لأمثلة بناء الجملة.

التوافق مع تجسير VLAN لنظام Linux

يدعم البرنامج ovs-vsctl نموذج الجسر الذي تنفذه Open vSwitch، حيث يدعم جسر واحد منافذ على شبكات VLAN متعددة. في هذا النموذج، يكون كل منفذ على جسر إما منفذ ترحيل (trunk port) يمرر الحزم الموسومة برؤوس 802.1Q التي تحدد شبكات VLAN، أو يتم تعيينه على شبكة VLAN ضمنية واحدة لا يتم تمييزها أبدًا برأس 802.1Q.

للتوافق مع البرامج المصممة لجسر Linux، يدعم ovs-vsctl أيضًا نموذجًا يتم فيه فصل حركة المرور المرتبطة بشبكة VLAN 802.1Q معينة إلى جسر منفصل. يقوم شكل خاص من أمر add-br (انظر أدناه) بإنشاء "جسر وهمي" داخل جسر Open vSwitch لمحاكاة هذا السلوك. عندما يكون "الجسر الوهمي" نشطًا، يتعامل معه ovs-vsctl بشكل مشابه لجسر منفصل عن "جسر الوالد" الخاص به، ولكن التنفيذ الفعلي في Open vSwitch يستخدم جسرًا واحدًا فقط، مع تعيين المنافذ على الجسر الوهمي إلى شبكة VLAN الضمنية للجسر الوهمي الذي تنتمي إليه. (يتلقى جسر وهمي لشبكة VLAN 0 حزمًا لا تحتوي على علامة 802.1Q أو علامة بشبكة VLAN 0.)

الخيارات

تؤثر الخيارات التالية على سلوك ovs-vsctl ككل. تقبل بعض الأوامر الفردية أيضًا خياراتها الخاصة، والتي يتم تقديمها مباشرة قبل اسم الأمر. إذا كان الأمر الأول في سطر الأوامر يحتوي على خيارات، فيجب فصل هذه الخيارات عن الخيارات العامة بواسطة --.

--db=server
يحدد server كخادم قاعدة البيانات الذي يتصل به ovs-vsctl للاستعلام عن التكوين أو تعديله. قد يكون server طريقة اتصال نشطة أو سلبية لـ OVSDB، كما هو موضح في ovsdb(7). الافتراضي هو unix:/run/openvswitch/db.sock.
--no-wait
يمنع ovs-vsctl من الانتظار حتى يعيد ovs-vswitchd تكوين نفسه وفقًا لقاعدة البيانات المعدلة. يجب استخدام هذا الخيار إذا كان ovs-vswitchd غير قيد التشغيل؛ وإلا، لن يخرج ovs-vsctl حتى يبدأ ovs-vswitchd.
ليس لهذا الخيار أي تأثير إذا كانت الأوامر المحددة لا تغير قاعدة البيانات.
--no-syslog
افتراضيًا، يقوم ovs-vsctl بتسجيل وسائطه وتفاصيل أي تغييرات يقوم بها في سجل النظام. يعطل هذا الخيار هذا التسجيل.
هذا الخيار يعادل --verbose=vsctl:syslog:warn.
--oneline
يغير تنسيق الإخراج بحيث يتم طباعة ناتج كل أمر على سطر واحد. يتم طباعة أحرف السطر الجديد التي كانت ستفصل الأسطر كـ \n، ويتم مضاعفة أي تكرارات لـ \ التي قد تظهر في الناتج. يطبع سطرًا فارغًا لكل أمر ليس له ناتج. هذا الخيار لا يؤثر على تنسيق الناتج من الأوامر list أو find؛ راجع خيارات تنسيق الجدول أدناه.
--dry-run
يمنع ovs-vsctl من تعديل قاعدة البيانات فعليًا.
-t secs

--timeout=secs
افتراضيًا، أو مع قيمة secs تساوي 0، ينتظر ovs-vsctl إلى الأبد ردًا من قاعدة البيانات. يحد هذا الخيار من وقت التشغيل إلى ما يقرب من secs ثانية. إذا انتهت المهلة، سيخرج ovs-vsctl بإشارة SIGALRM. (عادةً ما تحدث المهلة فقط إذا لم يكن من الممكن الاتصال بقاعدة البيانات، أو إذا كان النظام مثقلًا.)
--retry
بدون هذا الخيار، إذا قام ovs-vsctl بالاتصال خارجيًا بخادم قاعدة البيانات (الافتراضي)، فسيحاول ovs-vsctl الاتصال مرة واحدة وسيخرج بخطأ إذا فشل الاتصال (مما يعني عادةً أن ovsdb-server غير قيد التشغيل).
مع هذا الخيار، أو إذا حدد --db أن ovs-vsctl يجب أن يستمع لاتصال وارد من خادم قاعدة البيانات، فسوف ينتظر ovs-vsctl الاتصال بقاعدة البيانات إلى الأبد.
بغض النظر عن هذا الإعداد، يحدد --timeout دائمًا المدة التي سينتظرها ovs-vsctl.

خيارات تنسيق الجدول

تتحكم هذه الخيارات في تنسيق الناتج من الأوامر list و find.

-f format

--format=format
يحدد نوع تنسيق الجدول. الأنواع التالية من format متاحة:
table
جداول نصية ثنائية الأبعاد بأعمدة محاذاة.
list (الافتراضي)
قائمة بعمود واحد لكل سطر وفواصل بين الصفوف بسطر فارغ.
html
جداول HTML.
csv
قيم مفصولة بفواصل كما هو محدد في RFC 4180.
json
تنسيق JSON كما هو محدد في RFC 4627. الناتج هو تسلسل من كائنات JSON، كل منها يقابل جدولًا واحدًا. كل كائن JSON له الأعضاء التالية بالقيم المحددة:
caption
عنوان الجدول. يتم حذف هذا العضو إذا لم يكن للجدول عنوان.
headings
مصفوفة بعنصر واحد لكل عمود في الجدول. كل عنصر في المصفوفة هو سلسلة نصية تعطي عنوان العمود المقابل.
data
مصفوفة بعنصر واحد لكل صف في الجدول. كل عنصر هو أيضًا مصفوفة بعنصر واحد لكل عمود في الجدول. عناصر هذه المصفوفة ذات المستوى الثاني هي الخلايا التي تشكل الجدول. يتم التعبير عن الخلايا التي تمثل بيانات أو أنواع بيانات OVSDB بالتنسيق الموضح في مواصفات OVSDB؛ يتم التعبير عن الخلايا الأخرى ببساطة كسلاسل نصية.
-d format

--data=format
يحدد التنسيق للخلايا داخل جداول الإخراج ما لم يتم تعيين تنسيق الجدول على json.

الأوامر

يصف هذا القسم أوامر ovs-vsctl.

إدارة الجسر

add-br bridge
ينشئ جسرًا جديدًا باسم bridge. إذا كان bridge عبارة عن سلسلة نصية تحتوي على أحرف نقطية، مثل "br0.100"، فيجب أن يكون هناك جسر اسمه "br0" موجودًا بالفعل. في هذه الحالة، سيقوم add-br بإنشاء جسر "وهمي" bridge. انظر Linux VLAN Bridging Compatibility أعلاه.
del-br bridge
يحذف bridge. يجب أن تكون جميع منافذ الجسر الأخرى قد تم حذفها أولاً.
list-brs
يطبع أسماء جميع الجسور.

إدارة المنافذ

add-port bridge port
يضيف port إلى bridge. الافتراضيات لـ port هي اسم الواجهة (مثل "eth0").
add-port bridge port -- [key[=value]...]
يضيف port إلى bridge. يتم تمرير key[=value]... إلى ovs-vswitchd لتكوين المنفذ. قد تكون هذه قيمًا مثل type=type، و options:key=value، و may-create.
del-port bridge port
يحذف port من bridge.
list-ports bridge
يطبع أسماء المنافذ على bridge.

إدارة الواجهات

type
يحدد نوع الواجهة.
options:key
يعين قيمة خيار الواجهة. يتم تعيين key إلى value.
ofport
يضبط معلمة OFPort للواجهة.

إدارة المتحكم

set-controller bridge target...

يعين متحكمات OpenFlow لـ bridge. يجب أن يكون كل target بتنسيق [ssl:]ip[:port]. لتكوين target، حدد ssl: قبل ip لتمكين SSL. إذا port غير محدد، فإنه يستخدم المنفذ الافتراضي (6633 لـ OpenFlow عبر SSL، 6653 بدون SSL).

لتحديد target بدون SSL، فإنه يستخدم عادةً المنافذ 6653 (OpenFlow) أو 6633 (OpenFlow عبر TLS).

إذا لم يتم توفير أي target، فلا يتم تعيين أي متحكمات.

get-controller bridge
يطبع متحكمات OpenFlow المعينة لـ bridge.
fair-queue bridge [num- queues]

تكوين fair-queue لـ bridge. إذا تم تحديد num-queues، فيجب أن يكون عددًا صحيحًا موجبًا يمثل عدد صفوف الأولوية المتاحة لـ bridge. إذا لم يتم تحديد num-queues، فستتم إزالة fair-queue من bridge.

تكوين بروتوكول اكتشاف الجوار

snooping-set-ip-version bridge version

يعين إصدار IP لـ snooping على bridge. version يجب أن يكون "ipv4" أو "ipv6". افتراضيًا، يتم تمكين كليهما.

snooping-get-ip-version bridge
يطبع إصدار IP لـ snooping على bridge.
snooping-set-dhcp-options bridge ip:mac...

يقوم بتكوين snooping لـ bridge لاستخدام ip:mac لتحديد مضيفي DHCP. ip يجب أن يكون عنوان IP (IPv4 أو IPv6)، و mac يجب أن يكون عنوان MAC المقابل. إذا لم يتم توفير أي ip:mac، فستتم إزالة تكوين DHCP من bridge.

snooping-get-dhcp-options bridge
يطبع خيارات DHCP لـ snooping على bridge.
snooping-set-vlan bridge vlans

يقوم بتكوين snooping لـ bridge لمراقبة vlans. vlans يجب أن يكون قائمة بأرقام شبكات VLAN (مثل "1,10,20-30"). إذا تم توفير قائمة فارغة، فستتم إزالة تكوين VLAN من bridge.

snooping-get-vlan bridge
يطبع شبكات VLAN لـ snooping على bridge.

تكوين QoS

qos-set-classifiers bridge qos tc ...

يقوم بتكوين مصنفات tc لـ qos على bridge. كل tc يجب أن يكون قائمة بمعايير (مثل "ip,tos"). إذا تم توفير قائمة فارغة، فسيتم إزالة جميع المصنفات.

qos-get-classifiers bridge qos
يطبع مصنفات qos لـ bridge.
qos-set-queue bridge qos tc queue

يقوم بتكوين queue لـ qos على bridge مع المصنف tc. queue يجب أن يكون عددًا صحيحًا غير سالب يمثل صفوف الأولوية المتاحة. إذا تم توفير "none" بدلاً من queue، فسيتم تعطيل الـ qos مع المصنف tc.

qos-get-queue bridge qos tc
يطبع صف الأولوية لـ qos مع المصنف tc على bridge.
qos-list-queues bridge qos
يطبع قائمة بجميع صفوف الأولوية المكونة لـ qos على bridge.

تكوين NetFlow

set-netflow bridge target...

يعين أهداف NetFlow لـ bridge. يجب أن يكون كل target بتنسيق ip[:port]. إذا لم يتم تحديد أي target، فلا يتم تعيين أي أهداف NetFlow.

get-netflow bridge
يطبع أهداف NetFlow المعينة لـ bridge.
set-collectors bridge ip:port...

يعين جامعي NetFlow لـ bridge. يجب أن يكون كل ip:port بتنسيق ip[:port]. إذا لم يتم تحديد أي ip:port، فلا يتم تعيين أي جامعين.

get-collectors bridge
يطبع جامعي NetFlow المعينين لـ bridge.

تكوين sFlow

set-sflow bridge targets...

يقوم بتكوين targets لـ sFlow على bridge. يجب أن يكون كل target بتنسيق ip:port[:sampling_rate[:polling_interval]]. إذا لم يتم توفير أي targets، فستتم إزالة تكوين sFlow.

get-sflow bridge
يطبع أهداف sFlow المكونة لـ bridge.

تكوين IPFIX

set-ipfix bridge targets...

يقوم بتكوين targets لـ IPFIX على bridge. يجب أن يكون كل target بتنسيق ip:port[:sampling_rate[:cache_active_timeout[:cache_size]]]. إذا لم يتم توفير أي targets، فستتم إزالة تكوين IPFIX.

get-ipfix bridge
يطبع أهداف IPFIX المكونة لـ bridge.

تكوين إخلاء التدفق

flow-expiration-flush-interval bridge secs

يضبط الفاصل الزمني لإخلاء التدفق لـ bridge إلى secs ثوانٍ. يتم تجاهل التدفقات التي تجاوزت وقت حياتها حتى تصبح المهلة صالحة بعد secs ثوانٍ.

إذا تم تعيين secs إلى "unlimited"، فلن يتم إخلاء التدفقات إلا عندما تتجاوز قاعدة البيانات حدود الذاكرة.

flow-expiration-flush-interval bridge
يطبع الفاصل الزمني لإخلاء التدفق لـ bridge.

تكوين جدول التدفق

table-statistics bridge [table]

يعرض إحصائيات جدول التدفق لـ bridge. إذا تم تحديد table، فيعرض الإحصائيات لجدول التدفق المحدد فقط. يمكن أن يكون table رقمًا أو اسمًا (مثل "table_1" أو "flow_table_1").

تكوين NAT

nat-add bridge type external_ip internal_ip logical_port

يقوم بتكوين NAT لـ bridge. type يجب أن يكون "source" أو "destination". external_ip هو عنوان IP الخارجي (المنفذ المنطقي)، و internal_ip هو عنوان IP الداخلي (المنفذ المنطقي). logical_port هو المنفذ المنطقي الذي سيتم استخدامه للتواصل بين الشبكات.

nat-del bridge type external_ip
يحذف تكوين NAT لـ bridge.
nat-list bridge
يطبع قائمة بتكوينات NAT لـ bridge.

تكوين نفق المنافذ

tunnel-add bridge tunnel_type tunnel_name options...

يقوم بإضافة نفق tunnel_name من النوع tunnel_type إلى bridge. options هي زوج من المفتاح/القيمة لتكوين النفق، مثل "local_ip=ip" و "remote_ip=ip".

tunnel-del bridge tunnel_name
يحذف النفق tunnel_name من bridge.
tunnel-list bridge
يطبع قائمة الأنفاق على bridge.

تكوين ربط المنافذ

bond-add-slave bridge bond_name slave_port
يضيف slave_port إلى الرباط bond_name على bridge.
bond-del-slave bridge bond_name slave_port
يحذف slave_port من الرباط bond_name على bridge.
bond-list-slaves bridge bond_name
يطبع قائمة منافذ الرقيق (slave ports) للرباط bond_name على bridge.

تكوين VLAN للمنافذ

port-vlan-set-id bridge port vlan_id

يضبط vlan_id للمنفذ port على bridge. إذا كانت vlan_id "none"، فلا يتم تعيين أي VLAN.

port-vlan-get-id bridge port
يطبع معرف VLAN للمنفذ port على bridge.
port-vlan-set-native-id bridge port vlan_id

يضبط vlan_id الافتراضي للمنفذ port على bridge. إذا كانت vlan_id "none"، فلا يتم تعيين أي VLAN افتراضي.

port-vlan-get-native-id bridge port
يطبع معرف VLAN الافتراضي للمنفذ port على bridge.
port-vlan-set-tag bridge port tag

يضبط tag (علامة VLAN) للمنفذ port على bridge. إذا كانت tag "none"، فلن يتم تمييز حزم المنفذ.

port-vlan-get-tag bridge port
يطبع علامة VLAN للمنفذ port على bridge.

إدارة قواعد التدفق

flow-get-cookie bridge
يطبع ملف تعريف الارتباط (cookie) لجدول التدفق على bridge.
flow-dump-tofile bridge file

يطبع جدول التدفق لـ bridge إلى file. إذا كان file هو "-"، فيعرض الناتج على القياسي.

flow-restore-fromfile bridge file [target]

يقوم باستعادة جدول التدفق لـ bridge من file. إذا كان file هو "-"، فيقرأ المدخلات من القياسي.

target اختياري ويحدد جدول التدفق الذي سيتم استعادة القواعد إليه. يمكن أن يكون target رقمًا أو اسمًا (مثل "table_1" أو "flow_table_1"). إذا لم يتم تحديد target، فستتم استعادة القواعد إلى الجدول الافتراضي.

إدارة قاعدة البيانات

show [bridge]

يعرض ملخصًا لقاعدة بيانات التكوين. إذا تم تحديد bridge، فيعرض ملخصًا لهذا الجسر فقط.

list table [column...]

يطبع محتويات table. إذا تم تحديد column، فيعرض فقط الأعمدة المحددة.

هذا الأمر مفيد للتحقق من قاعدة البيانات بدون تغييرها.

find table condition...

يبحث عن صفوف في table تطابق condition... و يطبع الأعمدة المحددة (أو الجميع إذا لم يتم تحديد أي أعمدة).

condition تتكون من اسم عمود و عامل تشغيل وقيمة. على سبيل المثال: name="br0" أو type!=internal.

يمكن ربط الشروط بـ "&&" (and) أو "||" (or).

get table column uuid [column...]

يطبع column (أو الأعمدة المحددة) لصف في table بالـ uuid المحدد.

set table column uuid value

يضبط column لصف في table بالـ uuid المحدد إلى value.

يمكن استخدام الرموز "+", "-", "*", "/" لتنفيذ عمليات حسابية على القيم الرقمية.

delete table uuid
يحذف الصف ذي الـ uuid المحدد من table.
insert table column value...

يقوم بإدراج صف جديد في table. يتم تحديد قيم الأعمدة بـ column=value.

monitor [table...]

يراقب التغييرات في table(s) ويطبع تحديثات في الوقت الحقيقي.

transact [table...]

ينفذ معاملة ذرية على قاعدة البيانات باستخدام الأوامر المقدمة في السطر التالي.

يجب أن تبدأ كل عملية داخل المعاملة بـ "--".

أوامر أخرى

version
يطبع إصدار Open vSwitch.
ping bridge [count]

يرسل count حزم ICMP echo request إلى bridge. افتراضيًا، يرسل 4 حزم.

fdb-list bridge
يطبع جدول بحث الأمام (forwarding database) لـ bridge.
dpctl bridge command...

ينفذ command على مقطع البيانات (datapath) الخاص بـ bridge.

راجع ovs-dpctl(8) لمزيد من التفاصيل.

أمثلة

إنشاء جسر جديد باسم br0:

ovs-vsctl add-br br0

إضافة الواجهة eth0 إلى الجسر br0:

ovs-vsctl add-port br0 eth0

تحديد متحكم OpenFlow لـ br0:

ovs-vsctl set-controller br0 tcp:192.168.1.100:6633

إزالة الجسر br0:

ovs-vsctl del-br br0

عرض تكوين الجسر br0:

ovs-vsctl show br0

تغيير قيمة حقل في جدول `Open_vSwitch`:

ovs-vsctl set Open_vSwitch . other_config:max-idle=40000

إضافة قاعدة تدفق:

ovs-vsctl --may-break-loops \
    flow-restore-fromfile br0 - <<EOF
,table=0,priority=60000,actions=NORMAL
EOF

تغيير قيمة حقل `bridge` في جدول `Interface`:

ovs-vsctl set Interface eth0 bridge=br1

إضافة أو تعديل مدخلات في جدولي `Bridge` و `Port`:

ovs-vsctl -- --id=@br create Bridge name=br1 \
    -- --id=@p create Port name=eth1 \
    -- set Bridge br1 ports=@p

تنفيذ عدة عمليات كمعاملة ذرية:

ovs-vsctl -- --id=@br create Bridge name=br1 \
    -- --id=@p create Port name=eth1 \
    -- set Bridge br1 ports=@p \
    -- set Port eth1 other_config:test=true

تحديد متحكمات OpenFlow مع SSL:

ovs-vsctl set-controller br0 ssl:192.168.1.100:6633

تعيين شبكات VLAN لمراقبة SNMP:

ovs-vsctl snooping-set-vlan br0 10,20-30

التشخيص

يمكن أن تفشل عمليات ovs-vsctl لعدة أسباب:

  • ovsdb-server غير قيد التشغيل.
  • لا يمكن الاتصال بـ ovsdb-server (على سبيل المثال، إذا كان --db يشير إلى خادم غير صحيح).
  • خطأ في بناء الجملة في سطر الأوامر.
  • خطأ في تكوين قاعدة البيانات (على سبيل المثال، محاولة إضافة منفذ موجود بالفعل).

في حالة فشل العملية، يقوم ovs-vsctl بطباعة رسالة خطأ إلى الخطأ القياسي والخروج برمز خروج غير صفري.

ovs-vsctl -- set Port eth0 qos=@newqos \

-- --id=@newqos create QoS type=linux-htb other-config:max-rate=1000000000 queues=0=@q0,1=@q1 \
-- --id=@q0 create Queue other-config:min-rate=100000000 other-config:max-rate=100000000 \
-- --id=@q1 create Queue other-config:min-rate=500000000

قم بإلغاء تكوين سجل جودة الخدمة أعلاه من eth1 فقط:

ovs-vsctl clear Port eth1 qos

لإلغاء تكوين سجل جودة الخدمة من كل من eth0 و eth1 ثم حذف سجل جودة الخدمة (الذي يجب القيام به صراحةً لأن سجلات جودة الخدمة غير المشار إليها لا يتم تدميرها تلقائيًا):

ovs-vsctl -- destroy QoS eth0 -- clear Port eth0 qos -- clear Port eth1 qos

(سيترك هذا الأمر سجلين لـ Queue غير مشار إليهما في قاعدة البيانات. لحذفهما، استخدم "ovs-vsctl list Queue" للعثور على معرفات UUID الخاصة بهما، ثم "ovs-vsctl destroy Queue uuid1 uuid2" لتدمير كل منهما أو استخدم "ovs-vsctl -- --all destroy Queue" لحذف جميع السجلات.)

ovs-vsctl clear Interface eth0 cfm_mpid

قم بتكوين الجسر br0 لإرسال سجلات NetFlow إلى منفذ UDP 5566 على المضيف 192.168.0.34، مع مهلة نشطة تبلغ 30 ثانية:

ovs-vsctl -- set Bridge br0 netflow=@nf \
-- --id=@nf create NetFlow targets=\"192.168.0.34:5566\" active-timeout=30

قم بتحديث تكوين NetFlow الذي تم إنشاؤه بواسطة الأمر السابق لاستخدام مهلة نشطة تبلغ 60 ثانية بدلاً من ذلك:

ovs-vsctl set NetFlow br0 active_timeout=60

قم بإلغاء تكوين إعدادات NetFlow من br0، والتي تدمر أيضًا سجل NetFlow (لأنه لم يعد مشار إليه):

ovs-vsctl clear Bridge br0 netflow

sFlow

قم بتكوين الجسر br0 لإرسال سجلات sFlow إلى مجمع على 10.0.0.1 في المنفذ 6343، باستخدام عنوان IP الخاص بـ eth1 كمصدر، مع معلمات أخذ عينات محددة:

ovs-vsctl -- --id=@s create sFlow agent=eth1 target=\"10.0.0.1:6343\" header=128 sampling=64 polling=10 \
-- set Bridge br0 sflow=@s

قم بإلغاء تكوين sFlow من br0، والذي يدمر أيضًا سجل sFlow (لأنه لم يعد مشار إليه):

ovs-vsctl -- clear Bridge br0 sflow

IPFIX

قم بتكوين الجسر br0 لإرسال سجل تدفق IPFIX واحد لكل عينة حزمة إلى منفذ UDP 4739 على المضيف 192.168.0.34، مع معرف مجال المراقبة 123 ومعرف نقطة المراقبة 456، ومهلة نشطة لذاكرة التخزين المؤقت للتدفق تبلغ دقيقة واحدة (60 ثانية)، وحجم ذاكرة تخزين مؤقت للتدفق بحد أقصى 13 تدفقًا، وتدفقات تم أخذ عينات منها عند منفذ الإخراج مع معلومات النفق (أخذ العينات عند منفذ الإدخال والإخراج ممكّن افتراضيًا إذا لم يتم تعطيله):

ovs-vsctl -- set Bridge br0 ipfix=@i \
-- --id=@i create IPFIX targets=\"192.168.0.34:4739\" obs_domain_id=123 obs_point_id=456 cache_active_timeout=60 cache_max_flows=13 \
other_config:enable-input-sampling=false other_config:enable-tunnel-sampling=true

قم بإلغاء تكوين إعدادات IPFIX من br0، والتي تدمر أيضًا سجل IPFIX (لأنه لم يعد مشار إليه):

ovs-vsctl clear Bridge br0 ipfix

بروتوكول شجرة الامتداد 802.1D (STP)

قم بتكوين الجسر br0 للمشاركة في شجرة امتداد 802.1D:

ovs-vsctl set Bridge br0 stp_enable=true

قم بتعيين أولوية الجسر لـ br0 إلى 0x7800:

ovs-vsctl set Bridge br0 other_config:stp-priority=0x7800

قم بتعيين تكلفة المسار للمنفذ eth0 إلى 10:

ovs-vsctl set Port eth0 other_config:stp-path-cost=10

قم بإلغاء تكوين STP من الأعلى:

ovs-vsctl set Bridge br0 stp_enable=false

تتبع البث المتعدد

قم بتكوين الجسر br0 لتمكين تتبع البث المتعدد:

ovs-vsctl set Bridge br0 mcast_snooping_enable=true

قم بتعيين وقت تقادم تتبع البث المتعدد لـ br0 إلى 300 ثانية:

ovs-vsctl set Bridge br0 other_config:mcast-snooping-aging-time=300

قم بتعيين حجم جدول تتبع البث المتعدد لـ br0 إلى 2048 إدخالًا:

ovs-vsctl set Bridge br0 other_config:mcast-snooping-table-size=2048

قم بتعطيل بث حزم البث المتعدد غير المسجلة إلى جميع المنافذ. عند تعيينها على true، سترسل المحول الحزم المتعددة غير المسجلة فقط إلى المنافذ المتصلة بموجهات البث المتعدد. عندما يتم تعيينها على false، سترسلها المحول إلى جميع المنافذ. يقوم هذا الأمر بتعطيل بث الحزم غير المسجلة على الجسر br0.

ovs-vsctl set Bridge br0 other_config:mcast-snooping-disable-flood-unregistered=true

قم بتمكين بث حزم البث المتعدد (باستثناء التقارير) على منفذ معين.

ovs-vsctl set Port eth1 other_config:mcast-snooping-flood=true

قم بتمكين بث التقارير على منفذ معين.

ovs-vsctl set Port eth1 other_config:mcast-snooping-flood-reports=true

قم بإلغاء تكوين تتبع البث المتعدد من الأعلى:

ovs-vsctl set Bridge br0 mcast_snooping_enable=false

بروتوكول شجرة الامتداد السريع 802.1D-2004 (RSTP)

قم بتكوين الجسر br0 للمشاركة في شجرة امتداد سريعة 802.1D-2004:

ovs-vsctl set Bridge br0 rstp_enable=true

قم بتعيين عنوان الجسر لـ br0 إلى 00:aa:aa:aa:aa:aa:

ovs-vsctl set Bridge br0 other_config:rstp-address=00:aa:aa:aa:aa:aa

قم بتعيين أولوية الجسر لـ br0 إلى 0x7000. يجب تحديد القيمة بتدوين عشري ويجب أن تكون مضاعفًا للرقم 4096 (إذا لم تكن كذلك، يتم تقريبها لأسفل إلى أقرب مضاعف للرقم 4096). قيمة الأولوية الافتراضية هي 0x800 (32768).

ovs-vsctl set Bridge br0 other_config:rstp-priority=28672

قم بتعيين وقت تقادم الجسر لـ br0 إلى 1000 ثانية. يجب أن تكون قيمة وقت التقادم بين 10 ثوانٍ و 1000000 ثانية. القيمة الافتراضية هي 300 ثانية.

ovs-vsctl set Bridge br0 other_config:rstp-ageing-time=1000

قم بتعيين إصدار بروتوكول القوة للجسر لـ br0 إلى 0. لإصدار بروتوكول القوة قيمتان مقبولتان: 0 (وضع توافق STP) و 2 (تشغيل عادي).

ovs-vsctl set Bridge br0 other_config:rstp-force-protocol-version=0

قم بتعيين أقصى عمر للجسر لـ br0 إلى 10 ثوانٍ. يجب أن تكون قيمة أقصى عمر بين 6 ثوانٍ و 40 ثانية. القيمة الافتراضية هي 20 ثانية.

ovs-vsctl set Bridge br0 other_config:rstp-max-age=10

قم بتعيين تأخير تقدم الجسر لـ br0 إلى 15 ثانية. يجب أن تكون هذه القيمة بين 4 ثوانٍ و 30 ثانية. القيمة الافتراضية هي 15 ثانية.

ovs-vsctl set Bridge br0 other_config:rstp-forward-delay=15

قم بتعيين عدد احتفاظ الإرسال للجسر لـ br0 إلى 7 ثوانٍ. يجب أن تكون هذه القيمة بين ثانية واحدة و 10 ثوانٍ. القيمة الافتراضية هي 6 ثوانٍ.

ovs-vsctl set Bridge br0 other_config:rstp-transmit-hold-count=7

قم بتمكين RSTP على المنفذ eth0:

ovs-vsctl set Port eth0 other_config:rstp-enable=true

قم بتعطيل RSTP على المنفذ eth0:

ovs-vsctl set Port eth0 other_config:rstp-enable=false

قم بتعيين أولوية المنفذ eth0 إلى 32. يجب تحديد القيمة بتدوين عشري ويجب أن تكون مضاعفًا للرقم 16 (إذا لم تكن كذلك، يتم تقريبها لأسفل إلى أقرب مضاعف للرقم 16). قيمة الأولوية الافتراضية هي 0x80 (128).

ovs-vsctl(8) — Open vSwitch

NAME

ovs-vsctl

configure Open vSwitch

SYNOPSIS

ovs-vsctl [options] command [command...]

DESCRIPTION

The ovs-vsctl utility is for administering Open vSwitch database entries from ovsdb-server(5). It can be used to configure the Open vSwitch configuration database and to query it.

The primary function of ovs-vsctl is to act as a frontend for the OVS database schema. It is not intended to be used to modify the Open vSwitch forwarding database, which is the job of ovs-vswitchd(8).

For a more detailed description of the schema and its fields, see ovs-vswitchd.conf.db(5).

OPTIONS

The long and short options are:

--all
-a
--db:column
Sets the value of the specified database column to the specified value. This is not supported for all columns.
--columns[=COLUMN...])
Print the specified COLUMNs to standard output. The default is to print all columns.
--data-type[=TYPE])
Print the data types of the specified COLUMNs to standard output. The default is to print all columns.
--delete
-d
--db:table
Deletes the specified row from the specified database table. This is not supported for all tables.
--destroy
-D
--db:table
Deletes the specified row from the specified database table and all columns that reference it. This is not supported for all tables.
--format[=FORMAT])
Prints the output in the specified FORMAT. The default is auto.
--help
-h
Prints a usage message and quits.
--id[=NAME])
Used to create a named row.
--if-exists
-i
--db:table
Does nothing if the specified row does not exist.
--limit[=N])
Limits the output to at most N rows.
--long-ids
-l
--db
Prints all columns for all rows.
--max-trigger-depth[=N])
Sets the maximum depth for recursive triggers.

EXAMPLES

The following commands configure the RSTP settings for port eth0 on bridge br0.
ovs-vsctl set Port eth0 other_config:rstp-port-priority=32

Set the port number of port eth0 to 3:

ovs-vsctl set Port eth0 other_config:rstp-port-num=3

Set the path cost of port eth0 to 150:

ovs-vsctl set Port eth0 other_config:rstp-path-cost=150

Set the admin edge value of port eth0:

ovs-vsctl set Port eth0 other_config:rstp-port-admin-edge=true

Set the auto edge value of port eth0:

ovs-vsctl set Port eth0 other_config:rstp-port-auto-edge=true

Set the admin point to point MAC value of port eth0. Acceptable values are 0 (not point-to-point), 1 (point-to-point, the default value) or 2 (automatic detection). The auto-detection mode is not currently implemented, and the value 2 has the same effect of 0 (not point-to-point).

ovs-vsctl set Port eth0 other_config:rstp-admin-p2p-mac=1

Set the admin port state value of port eth0. true is the default value.

ovs-vsctl set Port eth0 other_config:rstp-admin-port-state=false

Set the mcheck value of port eth0:

ovs-vsctl set Port eth0 other_config:rstp-port-mcheck=true

Deconfigure RSTP from above:

ovs-vsctl set Bridge br0 rstp_enable=false

OpenFlow Version

Configure bridge br0 to support OpenFlow versions 1.0, 1.2, and 1.3:

ovs-vsctl set bridge br0 protocols=OpenFlow10,OpenFlow12,OpenFlow13

Flow Table Configuration

Make flow table 0 on bridge br0 refuse to accept more than 100 flows:

ovs-vsctl -- --id=@ft create Flow_Table flow_limit=100 overflow_policy=refuse -- set Bridge br0 flow_tables=0=@ft

Make flow table 0 on bridge br0 evict flows, with fairness based on the matched ingress port, when there are more than 100:

ovs-vsctl -- --id=@ft create Flow_Table flow_limit=100 overflow_policy=evict groups='"NXM_OF_IN_PORT[]"' -- set Bridge br0 flow_tables:0=@ft
