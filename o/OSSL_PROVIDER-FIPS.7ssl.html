الحزمة: openssl

التراخيص: Apache-2.0

OSSL_PROVIDER-FIPS(7ssl) OpenSSL OSSL_PROVIDER-FIPS(7ssl)

الاسم

OSSL_PROVIDER-FIPS - مزود FIPS لـ OpenSSL

الوصف

مزود FIPS لـ OpenSSL هو مزود خاص يتوافق مع معايير معالجة المعلومات الفيدرالية (FIPS) المحددة في FIPS 140-3. هذه 'الوحدة' تحتوي على مجموعة معتمدة من خوارزميات التشفير التي تم التحقق منها من قبل مختبر اختبار معتمد.

خصائص

التطبيقات في هذا المزود لديها على وجه التحديد الخصائص التالية المعرفة للخوارزميات المعتمدة:

"provider=fips"
"fips=yes"

يمكن استخدامه في سلسلة استعلام الخصائص مع وظائف الاسترداد مثل EVP_MD_fetch(3) أو EVP_CIPHER_fetch(3)، بالإضافة إلى الوظائف الأخرى التي تأخذ سلسلة استعلام الخصائص، مثل EVP_PKEY_CTX_new_from_name(3).

لكي تكون متوافقة مع FIPS، من الضروري تضمين "fips=yes" كجزء من جميع استعلامات الخصائص. هذا يضمن استخدام التطبيقات المعتمدة من FIPS فقط للعمليات التشفيرية. قد يتضمن استعلام "fips=yes" أيضًا عمليات دعم أخرى غير تشفيرية غير موجودة في مزود FIPS، مثل مشفرات المفاتيح غير المتماثلة، انظر "إدارة المفاتيح غير المتماثلة" في OSSL_PROVIDER-default(7).

ليس من الضروري تضمين "provider=fips" كجزء من استعلام الخصائص الخاص بك. تضمين "provider=fips" في استعلام الخصائص الخاص بك يضمن استخدام مزود FIPS لـ OpenSSL للعمليات التشفيرية بدلاً من مزودات FIPS الأخرى القادرة.

الخوارزميات المعتمدة

الخوارزميات التي يتم استردادها باستخدام "fips=yes" قد لا تزال غير معتمدة إذا لم يتم استيفاء شروط معينة. انظر "مؤشرات FIPS" في fips_module(7) للحصول على معلومات إضافية.

معلمات المزود

انظر "معلمات المزود" في provider-base(7) للحصول على قائمة بالمعلمات الأساسية. يتعامل مزود FIPS لـ OpenSSL أيضًا مع المعلمات المتعلقة بمؤشرات FIPS كما هو محدد في "خيارات مؤشرات FIPS" في fips_config(5).

NAME

OSSL_PROVIDER-FIPS — OpenSSL FIPS provider

DESCRIPTION

The FIPS provider is a cryptographic provider that supports the FIPS standard (Federal Information Processing Standards). It implements a subset of the OpenSSL functionality that has been validated by an OpenSSL tester. The FIPS provider contains only algorithms and modes that are allowed by the FIPS standard.

The FIPS provider is typically loaded using the function OSSL_PROVIDER_load. It can be loaded into multiple library contexts.

The FIPS provider can be configured using configuration files. The default configuration file is located at <prefix>/ssl/openssl.cnf. You can specify a different configuration file using the function OSSL_PROVIDER_load_config.

The FIPS provider can be loaded in two modes: a normal operational mode and a self-test mode. The self-test mode is used to perform self-tests on the FIPS provider. The self-tests are performed automatically when the FIPS provider is loaded. If the self-tests fail, the FIPS provider will not be loaded.

SELF TESTING

The FIPS provider performs self-tests when it is loaded. These self-tests are performed automatically and cannot be disabled. The self-tests are performed on all the algorithms and modes that are supported by the FIPS provider.

The self-tests are performed in the following order:

  1. PRECLoad: This phase involves pre-loading necessary components and performing initial checks.
  2. CATEGORIES: Tests related to different categories of algorithms and operations.
  3. START: Indicates the beginning of a specific test or phase.
  4. CORRUPT: This phase is used to intentionally corrupt a component to test error handling.
  5. PASS: Indicates that a self-test has passed successfully.
  6. FAIL: Indicates that a self-test has failed.

The self-tests are performed using a callback function. The callback function is called with a set of parameters that describe the current phase and the test being performed. The callback function can return a value to indicate whether the test passed or failed.

EXAMPLES

A simple self test callback is shown below for illustrative purposes.

#include <openssl/self_test.h>
static OSSL_CALLBACK self_test_cb;
static int self_test_cb(const OSSL_PARAM params[], void *arg)
{
  int ret = 0;
  const OSSL_PARAM *p = NULL;
  const char *phase = NULL, *type = NULL, *desc = NULL;
  p = OSSL_PARAM_locate_const(params, OSSL_PROV_PARAM_SELF_TEST_PHASE);
  if (p == NULL || p->data_type != OSSL_PARAM_UTF8_STRING)
      goto err;
  phase = (const char *)p->data;
  p = OSSL_PARAM_locate_const(params, OSSL_PROV_PARAM_SELF_TEST_DESC);
  if (p == NULL || p->data_type != OSSL_PARAM_UTF8_STRING)
      goto err;
  desc = (const char *)p->data;
  p = OSSL_PARAM_locate_const(params, OSSL_PROV_PARAM_SELF_TEST_TYPE);
  if (p == NULL || p->data_type != OSSL_PARAM_UTF8_STRING)
      goto err;
  type = (const char *)p->data;
  /* Do some logging */
  if (strcmp(phase, OSSL_SELF_TEST_PHASE_START) == 0)
      BIO_printf(bio_out, "%s : (%s) : ", desc, type);
  if (strcmp(phase, OSSL_SELF_TEST_PHASE_PASS) == 0
          || strcmp(phase, OSSL_SELF_TEST_PHASE_FAIL) == 0)
      BIO_printf(bio_out, "%s\n", phase);
  /* Corrupt the SHA1 self test during the 'corrupt' phase by returning 0 */
  if (strcmp(phase, OSSL_SELF_TEST_PHASE_CORRUPT) == 0
          && strcmp(desc, OSSL_SELF_TEST_DESC_MD_SHA1) == 0) {
      BIO_printf(bio_out, "%s %s", phase, desc);
      return 0;
  }
  ret = 1;
err:
  return ret;
}

NOTES

Some released versions of OpenSSL do not include a validated FIPS provider. To determine which versions have undergone the validation process, please refer to the OpenSSL Downloads page https://www.openssl.org/source/. If you require FIPS-approved functionality, it is essential to build your FIPS provider using one of the validated versions listed there. Normally, it is possible to utilize a FIPS provider constructed from one of the validated versions alongside libcrypto and libssl compiled from any release within the same major release series. This flexibility enables you to address bug fixes and CVEs that fall outside the FIPS boundary.

You can load the FIPS provider into multiple library contexts as any other provider. However the following restriction applies. The FIPS provider cannot be used by multiple copies of OpenSSL libcrypto in a single process.

As the provider saves core callbacks to the libcrypto obtained in the OSSL_provider_init() call to global data it will fail if subsequent invocations of its OSSL_provider_init() function yield different addresses of these callbacks than in the initial call. This happens when different copies of libcrypto are present in the memory of the process and both try to load the same FIPS provider. A workaround is to have a different copy of the FIPS provider loaded for each of the libcrypto instances in the process.
