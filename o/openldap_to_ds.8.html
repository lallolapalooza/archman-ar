openldap_to_ds(8)

الحزمة: 389-ds-base

التراخيص: GPL-3.0-only

OPENLDAP_TO_DS(8) دليل Python المولد OPENLDAP_TO_DS(8)

الاسم

openldap_to_ds

الملخص

openldap_to_ds [-h] [-v] [--confirm] [--ignore-overlay [IGNORE_OVERLAY ...]] [--ignore-schema-oid [IGNORE_SCHEMA_OID ...]] [--ignore-attribute [IGNORE_ATTRIBUTE ...]] [-D BINDDN] [-w BINDPW] [-W] [-y PWDFILE] [-Z] instance slapd_config [slapd_ldif ...]

الوصف

الترحيل من OpenLDAP إلى 389 Directory Server.

يقوم هذا الأمر بأتمتة عملية تحويل خادم OpenLDAP إلى مثيل 389 Directory Server. هذا "جهد أفضل" لأن OpenLDAP و 389 Directory Server ليسا متطابقين، لذلك قد تتطلب بعض الميزات ترحيلاً يدوياً، أو لا يمكن ترحيلها على الإطلاق. تهدف هذه الأداة إلى ترحيل غالبية المحتوى الرئيسي مثل بيانات قاعدة البيانات، وتكوين الفهارس، والمخطط وبعض التراكبات (الإضافات).

المحتوى الذي يمكننا ترحيله:

* المخطط * محتوى قاعدة البيانات (من نسخة احتياطية ldif) * فهارس قاعدة البيانات * تراكب MemberOf (memberof) * تراكب التكامل المرجعي (refint) * تراكب سمة فريدة (unique)

بعض المحتوى الذي لا يمكن ترحيله يشمل بعض التراكبات (الإضافات)، ضوابط الوصول وتكوين النسخ المتماثل. أمثلة على الإضافات التي لا يمكن ترحيلها:

* تسجيل الوصول/التدقيق (مدمج في 389-ds افتراضياً) * الربط (يتطلب ترحيلاً يدوياً، قد لا يكون مكافئاً) * القيود (لا يوجد تراكب مكافئ) * خدمات الدليل الديناميكية (يتطلب ترحيلاً يدوياً إلى إضافة فئة الخدمة) * المجموعات/القوائم الديناميكية (يتطلب ترحيلاً يدوياً إلى إضافة الأدوار) * ذاكرة التخزين المؤقت للوكيل (لا يوجد تراكب مكافئ، يدعم 389-ds النسخ للقراءة فقط) * سياسة كلمة المرور (مدمجة في 389-ds، تتطلب ترحيلاً يدوياً) * إعادة الكتابة/إعادة التعيين (لا يوجد تراكب مكافئ) * موفر المزامنة (يتطلب ترحيلاً يدوياً إلى النسخ المتماثل أو إضافة مزامنة المحتوى) * فرز القيم (لا يوجد تراكب مكافئ)

يجب تشغيل هذا على الخادم الذي يشغل مثيل 389 Directory Instance لأنه يتطلب الوصول إلى نظام الملفات. يجب تشغيل هذه الأداة كـ root أو مستخدم dirsrv.

المتطلبات التالية من مثيل openldap الخاص بك:


* دليل تكوين slapd.d بتنسيق ldif/dynamic
* (اختياري) نسخة احتياطية من ملف ldif لقاعدة البيانات من slapcat

يمكن إنشاء هذه على مضيف OpenLDAP ونسخها إلى مضيف 389 Directory Server. لا يتم تطبيق أي إجراءات مدمرة على مثيل OpenLDAP.

إذا كنت تستخدم بالفعل تنسيق ldif/dynamic من /etc/openldap/slapd.d، يجب عليك أخذ نسخة من هذا لاستخدامها في الترحيل.


cp -a /etc/openldap/slapd.d /root/slapd.d

إذا كنت تستخدم ملف تكوين slapd.conf، يمكنك تحويله إلى التكوين الديناميكي دون التأثير على مثيلك قيد التشغيل باستخدام:


slaptest -f /etc/openldap/slapd.conf -F /root/slapd.d

للسماح اختياريًا بترحيل محتوى قاعدة بياناتك، يمكنك إنشاء نسخة احتياطية ldif للمحتوى الذي يمكن لـ 389 Directory Server استيراده. يجب تشغيل هذا لكل خلفية (suffix) للمثيل الخاص بك باستخدام الأمر:


# إذا كنت تستخدم تنسيق تكوين slapd.conf
slapcat -f /etc/openldap/slapd.conf -b SUFFIX -l /root/suffix.ldif
# إذا كنت تستخدم تنسيق تكوين slapd.d
slapcat -F /etc/openldap/slapd.d -b SUFFIX -l /root/suffix.ldif

يجب أن يكون لديك بالفعل 389 Directory Server تريد الاستيراد إليه. يمكنك إنشاؤه باستخدام أداة `dscreate`. سيتم تعديل البيانات والتكوين في هذا المثيل أو إزالته (أي إجراءات مدمرة محتملة).

ينصح بشدة باختبار هذه الأداة على نظام غير إنتاجي أولاً للتأكد من فهم العملية والتغييرات.

يجب تشغيل هذا فقط على المثيل الأول في طوبولوجيا 389 Directory Server. يجب تكوين جميع النسخ المتماثلة الأخرى من هذا المثيل بعد الترحيل.

instance
اسم مثيل 389-ds الذي سيتم ترحيل بيانات openldap إليه
slapd_config
المسار إلى تكوين openldap slapd.d الذي سيتم ترحيله
slapd_ldif
المسار إلى ملفات ldif قاعدة البيانات المصدرة ليتم استيرادها.

الخيارات

-v, --verbose
عرض تتبع مفصل للعمليات أثناء تنفيذ الأمر
--confirm
تأكيد أنك تريد تطبيق إجراءات الترحيل هذه على مثيل 389-ds. افتراضياً لا يتم اتخاذ أي إجراءات.
--ignore-overlay [IGNORE_OVERLAY ...]
تجاهل تراكبات openldap التالية من ترحيل تكوينها إلى إضافات 389-ds المكافئة. الخيارات الصالحة هي memberof, refint, unique.
--ignore-schema-oid [IGNORE_SCHEMA_OID ...]
تجاهل معرفات OIDS السمات أو الفئات لمخطط openldap التالية من الترحيل إلى 389-ds. هذا *قد* ينشئ مخططًا غير متناسق قد يتسبب في فشل الترحيل. استخدم بحذر.
--ignore-attribute [IGNORE_ATTRIBUTE ...]
تجاهل السمات التالية من الإدخالات التي يتم تحميلها من ldif. على سبيل المثال، قد لا ترغب في استيراد تجزئات userPassword.
-D BINDDN, --binddn BINDDN
حساب 389 Directory Server للربط به لتنفيذ عمليات الترحيل
-w BINDPW, --bindpw BINDPW
كلمة المرور لـ binddn
-W, --prompt
مطالبة بكلمة المرور لـ bind DN
-y PWDFILE, --pwdfile PWDFILE
يحدد ملفًا يحتوي على كلمة المرور لـ binddn
-Z, --starttls
الاتصال بـ 389 Directory Server باستخدام StartTLS
