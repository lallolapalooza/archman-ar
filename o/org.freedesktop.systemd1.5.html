الاسم

org.freedesktop.systemd1 - واجهة D-Bus لـ systemd

مقدمة

systemd(1) والشياطين المساعدة الخاصة به تعرض عددًا من واجهات برمجة التطبيقات عبر D-Bus. هذه الصفحة تصف فقط واجهات برمجة التطبيقات المختلفة التي تعرضها مدير النظام والخدمة نفسه. لا تغطي هذه الصفحة الشياطين المساعدة.

يعرض مدير الخدمة عددًا من الكائنات على الناقل: كائن مدير واحد كنقطة دخول مركزية للعملاء إلى جانب كائنات فردية لكل وحدة ولكل وظيفة في قائمة الانتظار. تطبق الكائنات الوحدات واجهة وحدة عامة بالإضافة إلى واجهة خاصة بالنوع. على سبيل المثال، تطبق وحدات الخدمة كل من org.freedesktop.systemd1.Unit و org.freedesktop.system1.Service. يمكن لكائن المدير سرد كائنات الوحدة أو الوظيفة أو تحويل اسم وحدة أو معرف وظيفة مباشرة إلى مسار الناقل لكائن D-Bus المقابل.

يتم عادةً ترميز الخصائص التي تعرض قيم الوقت بالميكروثانية (µs) على الناقل، حتى لو كانت الإعدادات المقابلة لها في ملفات الوحدات بالثواني.

يستخدم PID 1 polkit[1] للسماح بالوصول إلى العمليات المميزة للعمليات غير المميزة. تتوفر بعض العمليات (مثل الإغلاق/إعادة التشغيل/الإسبات) أيضًا عبر واجهة D-Bus الخاصة بـ logind، انظر org.freedesktop.login1(5).

SystemState يحتوي على الحالة الحالية لمدير النظام. القيم الممكنة هي:

"initializing"

النظام يقوم بالإقلاع، ولم يتم الوصول إلى basic.target بعد.

"starting"

النظام يقوم بالإقلاع، وتم الوصول إلى basic.target.

"running"

انتهى النظام من الإقلاع، ولكن بعض الوحدات في حالة فشل.

"maintenance"

انتهى النظام من الإقلاع، ولكن تم وضعه في وضع الإنقاذ أو الصيانة.

"stopping"

النظام يقوم بالإيقاف.

The PollLimitIntervalUSec and PollLimitBurst properties configure the polling limit for the socket unit. Expects a time in µs and unsigned integer, respectively. If either is set to zero the limiting feature is turned off.

Properties

Most of the properties map directly to the corresponding settings in socket unit files. As socket units can include ExecStartPre (and similar) fields which contain information about processes to execute. They also share most of the fields related to the execution context that Service objects expose (see above).

In addition to these properties there are the following:

NAccepted contains the accumulated number of connections ever accepted on this socket. This only applies to sockets with Accept set to "yes", i.e. those where systemd is responsible for accepted connections.

Similarly NConnections contains the number of currently open connections on this socket. It only applies only to socket units with Accept set to "yes".

Result encodes the reason why a socket unit failed if it is in the "failed" state (see ActiveState above). The values "success", "resources", "timeout", "exit-code", "signal" and "core-dump" have the same meaning as they have for the corresponding field of service units (see above). In addition to that, the value "service-failed-permanent" indicates that the service of this socket failed continuously.

FlushPending specifies whether to flush the socket just before entering the listening state. This setting only applies to sockets with Accept= set to "no".

NAME

systemd.directives — systemd directives

INTRODUCTION

This document lists all available systemd directives and the versions they were introduced in. It is split into several sections corresponding to the manager, unit, and job objects.

Directives are typically used in unit files, but some may also be used in systemd configuration files or passed on the command line.

This document does not include directives that are specific to individual unit types, but rather those that are generally applicable across multiple unit types or to the manager itself.

For a full description of each directive, please refer to the man page for the specific unit type (e.g., systemd.service(5), systemd.socket(5), etc.) or the manager configuration (systemd-system.conf(5)).
