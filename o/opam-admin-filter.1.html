opam-admin-filter(1)

الحزمة: opam

التراخيص: LGPL-2.1-only

OPAM ADMIN-FILTER(1) دليل Opam الإداري OPAM ADMIN-FILTER(1)

الاسم

opam admin filter - يقوم بتصفية المستودع للإبقاء فقط على الحزم المحددة

ملخص

opam admin filter [--dry-run] [--environment=VAR=VALUE[,VAR=VALUE]] [--remove] [OPTION]… [PATTERNS]…

الوصف

يقوم هذا الأمر بإزالة جميع تعريفات الحزم التي لا تطابق معايير البحث (المحددة بطريقة مشابهة لـ 'opam admin list') من مستودع.

محدِّدات حساسة للترتيب

-a, --available
يسرد فقط الحزم المتوفرة وفقًا لـ environment المحدد. بدون --environment، سيشمل أي حزم لا يمكن تحديد توفرها في هذه النقطة.
-A, --all
تضمين الكل، حتى الحزم غير المثبتة أو غير المتاحة
--installable
يسرد فقط الحزم القابلة للتثبيت وفقًا لـ environment المحدد (هذا يستدعي الحل وقد يكون مكلفًا؛ قد تكون الحزمة التي تعتمد على حزمة غير متاحة متاحة، ولكنها ليست قابلة للتثبيت أبدًا)
--latests-only
يسرد فقط أحدث إصدار لكل حزمة.

الوسائط

PATTERNS
أنماط الحزم مع الأحرف البديلة. المطابقة ضد NAME أو NAME.VERSION

خيارات

--dry-run
يسرد أوامر الإزالة، دون تنفيذها فعليًا
--environment=VAR=VALUE[,VAR=VALUE]
استخدم بيئة opam المعطاة، في شكل قائمة من ارتباطات 'var=value' مفصولة بفواصل، عند حل المتغيرات. يُستخدم هذا على سبيل المثال عند حساب الحزم المتاحة: إذا لم يتم تعريفها، سيتم افتراض توفر الحزم بمجرد عدم إمكانية حلها بشكل بحت من المتغيرات المعرفة عالميًا. لاحظ أنه، ما لم يتم تجاوزها، قد يتم أخذ متغيرات مثل 'root' أو 'opam-version' من تثبيت opam الحالي. ما هو معرف في ~/.opam/config يتم تجاهله دائمًا.
--remove
اعكس السلوك وقم بإزالة الحزم المطابقة، مع الاحتفاظ بتلك التي لا تتطابق.

خيارات اختيار الحزمة

--coinstallable-with=PACKAGES
يسرد فقط الحزم المتوافقة مع كل من PACKAGES.
--conflicts-with=PACKAGES
يسرد الحزم التي أعلنت عن تعارضات مع واحد على الأقل من القائمة المعطاة. يشمل هذا التعارضات المعرفة من الحزم في القائمة، أو من الحزمة الأخرى، أو بواسطة حقل conflict-class: مشترك.
--depends-on=PACKAGES
يسرد فقط الحزم التي تعتمد على واحدة من (مفصولة بفواصل) PACKAGES.
--depopts
تضمين التبعيات الاختيارية في طلبات التبعية.
--dev
تضمين حزم التطوير في التبعيات.
--field-match=FIELD:PATTERN
تصفية الحزم بمطابقة PATTERN على FIELD المعطاة.
--has-flag=FLAG
تضمين فقط الحزم التي تم تعيين العلامة المعطاة لها. علامات الحزمة هي واحدة مما يلي: light-uninstall verbose plugin compiler conf
--has-tag=TAG
تضمين فقط الحزم التي تم تعيين العلامة المعطاة لها.
--nobuild
استبعاد تبعيات البناء (يتم تضمينها افتراضيًا).
--or
بدلاً من اختيار الحزم التي تطابق كل المعايير، اختر الحزم التي تطابق أيًا منها.
--post
تضمين التبعيات المسماة كـ post.
--recursive
مع `--depends-on' و `--required-by'، عرض جميع التبعيات المتعدية بدلاً من التبعيات المباشرة فقط.
--required-by=PACKAGES
يسرد فقط تبعيات (مفصولة بفواصل) PACKAGES.
--resolve=PACKAGES
الاقتصار على حل لتثبيت (مفصولة بفواصل) PACKAGES، أي مجموعة متسقة من الحزم بما في ذلك تلك. هذا يختلف بشكل دقيق عن `--required-by --recursive`، وهو أكثر قابلية للتنبؤ ولا يمكن أن يفشل، ولكنه يسرد جميع التبعيات بشكل مستقل دون ضمان الاتساق. بدون `--installed`، تكون الإجابة مكتفية ذاتيًا ومستقلة عن التثبيت الحالي. مع `--installed`، يتم حسابها من مجموعة الحزم المثبتة حاليًا. `--no-switch` يجعل الحل مستقلاً بشكل أكبر عن الحزم المثبتة حاليًا، والبنية، وإصدار المترجم. لا يتم دعم الدمج مع `--depopts'.
-t, --with-test, --test
تضمين تبعيات الاختبار فقط.
--with-dev-setup
تضمين تبعيات الإعداد التطويري فقط.
--with-doc, --doc
تضمين تبعيات الوثائق فقط.

خيارات مشتركة

هذه الخيارات مشتركة لجميع الأوامر.

--best-effort
لا تفشل إذا لم يكن من الممكن تثبيت جميع الحزم المطلوبة: حاول تثبيت أكبر عدد ممكن. لاحظ أن ليس كل الحلول الخارجية قد تدعم هذا الخيار (الإصدارات الحديثة من aspcud أو mccs يجب أن تفعل). هذا يعادل تعيين متغير البيئة $OPAMBESTEFFORT.
--cli=MAJOR.MINOR (مفقود=2.4)
استخدم بناء جملة ودلالات الواجهة السطرية لـ MAJOR.MINOR. مخصص لأي استخدام دائم لـ opam (نصوص برمجية، مدونات، إلخ)، أي إصدار من opam في نفس سلسلة MAJOR سيتصرف كما هو الحال بالنسبة لإصدار MINOR المحدد. لم يكن الخيار متاحًا في opam 2.0، لذلك لاختيار الواجهة السطرية 2.0، قم بتعيين متغير البيئة OPAMCLI إلى 2.0 بدلاً من استخدام هذه المعلمة.
--color=WHEN
تلوين المخرجات. يجب أن يكون WHEN أحد الخيارات التالية: always، never أو auto.
--confirm-level=LEVEL
مستوى التأكيد، يجب أن يكون LEVEL أحد الخيارات التالية: ask، no، yes أو unsafe-yes. يمكن تحديده أكثر من مرة. إذا تم أيضًا تحديد --yes أو --no، فسيتم أخذ قيمة آخر --confirm-level في الاعتبار. هذا يعادل تعيين $OPAMCONFIRMLEVEL`.
--criteria=CRITERIA
حدد تفضيلات المستخدم لحل التبعيات لهذا التشغيل. يتجاوز $OPAMCRITERIA و $OPAMFIXUPCRITERIA و $OPAMUPGRADECRITERIA. للحصول على تفاصيل حول اللغة المدعومة، والحلول الخارجية المتاحة، راجع http://opam.ocaml.org/doc/External_solvers.html. يمكن العثور على دليل عام لاستخدام تفضيلات الحل في http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=FILENAME
خيار التصحيح: حفظ طلبات CUDF المرسلة إلى الحل في FILENAME-<n>.cudf حيث <n> هو الاستدعاء رقم n للحل أثناء تشغيل opam.
--debug
طباعة رسائل التصحيح إلى stderr. هذا يعادل تعيين $OPAMDEBUG إلى "true".
--debug-level=LEVEL
مثل --debug، ولكنه يسمح بتحديد مستوى التصحيح (--debug يضبطه على 1). يعادل تعيين $OPAMDEBUG إلى عدد صحيح موجب.
--git-version
طباعة إصدار git من opam، إذا تم تعيينه (أي، أنت تستخدم إصدار تطوير)، والخروج.
--help[=FMT] (افتراضي=auto)
عرض هذه المساعدة بتنسيق FMT. يجب أن يكون FMT أحد الخيارات: auto، pager، groff أو plain. مع auto، يكون التنسيق pager أو plain كلما كان متغير TERM هو dumb أو غير معرف.
--ignore-pin-depends
تجاهل تثبيتات إضافية مطلوبة بواسطة الحزم التي يتم تثبيتها، سواء يدويًا من خلال opam pin أو من خلال opam install DIR. هذا يعادل تعيين IGNOREPINDEPENDS=true.
--json=FILENAME
حفظ نتائج تشغيل opam في ملف قابل للقراءة آليًا. إذا كان اسم الملف يحتوي على الحرف `%`، فسيتم استبداله بفهرس لا يكتب فوق ملف موجود. مشابه لتعيين متغير $OPAMJSON.

opam-admin(1) - opam

NAME

opam admin - opam administration commands

SYNOPSIS

opam admin COMMAND [ OPTION... ] [ ARGUMENT... ]

DESCRIPTION

This manual page covers the administration commands of opam, including configuration, repository management, and debugging commands. See opam(1) for a list of all commands and manual pages.

ORDER SENSIBLE SELECTORS

When selecting package versions, opam considers the following properties in order:

1.
The exact package version specified on the command line (e.g. opam install foo.1.2.3).
2.
A user-defined selection preference, expressed using --criteria or the OPAMUPGRADECRITERIA environment variable.
3.
Dependencies of packages already installed or requested on the command line.
4.
The version specified in opam upgrade command (e.g. opam upgrade foo). This is only checked if no packages have been requested on the command line.
5.
A package manager selection preference, expressed using --select-mode or the OPAMSELECTMODE environment variable.
6.
The most recent version available, if none of the above apply.

ARGUMENTS

Most opam commands take package names as arguments. These can be qualified with a version number, e.g. foo.1.2.3.

Package names can also be specified as glob patterns (e.g. foo.*). These patterns are expanded in the context of the configured repositories.

When multiple packages are specified, they are processed in the order they appear on the command line. This order can be relevant for dependency resolution and for defining the root set of packages for which the lock file is generated.

OPTIONS

Most commands accept a number of common options. See COMMON OPTIONS for details.

PACKAGE SELECTION OPTIONS

--criteria=CRIT

User criteria for dependency resolution. The CRIT string is a list of package selectors, separated by commas. Each selector can be prefixed with + (positive) or ! (negative). A plain selector is treated as positive. The selectors are ordered by precedence. For example, --criteria='+foo.1.2,bar,!baz' means: prefer version 1.2 of package foo, then prefer any version of bar, and disallow baz.

This option overrides OPAMUPGRADECRITERIA when given on the command line.

--select-mode=MODE

Specifies how opam should select package versions when multiple versions are available and satisfy the given constraints. Valid modes are:

first
Select the first version found that satisfies the constraints.
last
Select the last version found that satisfies the constraints. This is the default.
shortest
Select the version with the shortest version string.
longest
Select the version with the longest version string.
preferred
Select the version marked as preferred by the user.

--with-test

Install or upgrade packages with their test suites. This option is passed to the opam install and opam upgrade commands.

--with-doc

Install or upgrade packages with their documentation. This option is passed to the opam install and opam upgrade commands.

--with-dev-setup

Install or upgrade packages with their development setup files (e.g. dune files). This option is passed to the opam install and opam upgrade commands.

--keep-source

Keep the source tarballs after installation. This option is passed to the opam install command.

--disable-tests

Do not build or install test suites, even if the package specifies them. This option is passed to the opam install and opam upgrade commands.

--disable-docs

Do not build or install documentation, even if the package specifies it. This option is passed to the opam install and opam upgrade commands.

--disable-dev-setup

Do not build or install development setup files, even if the package specifies them. This option is passed to the opam install and opam upgrade commands.

--unlock-base

When upgrading or installing, unlock any prerequisite packages that are currently locked, even if they are not explicitly requested on the command line. This option is passed to the opam install and opam upgrade commands.

COMMON OPTIONS

--yes, -y

Assume "yes" to all confirmation prompts. This option overrides OPAMYES and is ignored if OPAMCONFIRMLEVEL is set.

--no

Assume "no" to all confirmation prompts. This option overrides OPAMYES and is ignored if OPAMCONFIRMLEVEL is set.

--confirm-level=LEVEL

Set the confirmation level. Valid levels are low, medium, and high. This option overrides OPAMYES and OPAMNO.

--verbose, -v

Enable verbose output. This option overrides OPAMVERBOSE.

--quiet, -q

Enable quiet output. This option overrides OPAMVERBOSE.

--debug=FLAGS

Enable debug output. FLAGS is a comma-separated list of debug flags. See ENVIRONMENT for details on OPAMDEBUG.

--color=MODE

Set the color mode. Valid modes are auto, always, and never. This option overrides OPAMUTF8.

--switch=SWITCH

Select the opam switch to operate on. If not specified, the current switch is used. This option overrides OPAMSWITCH.

--working-dir=DIR

Set the working directory for the command. If not specified, the current directory is used. This option overrides OPAMWORKINGDIR.

--root=DIR

Set the opam root directory. If not specified, the default root (~/.opam) is used. This option overrides OPAMROOT.

--repositories=REPOS

Set the list of repositories to use. REPOS is a comma-separated list of repository names. This option overrides OPAMREPOSITORIES.

--config-path=PATH

Set the path to the opam configuration file. This option overrides OPAMCONFIGPATH.

--cli=VERSION

Specify the command-line interface version to use. See CLI VERSION for details.

--help, -h

Display a help message and exit.

--version

Display opam version and exit.

ENVIRONMENT

Environment variables can be used to configure opam's behavior. They are generally overridden by command-line options.

OPAM_USER_CONF_DIR

Specifies the directory where user-specific configuration files (like opam policies) are stored. Defaults to ~/.config/opam/.

OPAM_CONFIG_DIR

Specifies the directory where opam stores its configuration files. Defaults to $OPAM_USER_CONF_DIR.

OPAM_PACKAGE_DIR

Specifies the directory where opam stores package information (definitions, build results, etc.). Defaults to ~/.opam/.

OPAM_ROOT

Overrides OPAM_PACKAGE_DIR. Used to specify the opam root directory.

OPAMCLI

Sets the CLI version. See CLI VERSION.

OPAMCOLOR

Use colors in output. Supported values are true, false, auto. Defaults to auto.

OPAMCONFIRMLEVEL

Set the confirmation level for operations. Supported values are low, medium, high. Overrides OPAMYES and OPAMNO.

OPAMDEBUG

Enable debug output. The value is a comma-separated list of debug flags. Available flags include solver, repo, network, commands, install, remove, switch, jobs, check, fetch, build, test, uninstall, upgrade, pin, config, all.

OPAMDEVMODE see install option `--dev-mode'.

OPAMDEVMODEBASE see install option `--dev-mode-base'.

OPAMDOWNLOADER

Selects the downloader to use. Valid values are: curl, wget, fetch (macOS only), aria2, default (tries to use the best available).

OPAMFETCHCMD

Use the specified command for downloading source archives. Defaults to curl.

OPAMFILTER_PACKAGE see option `--filter'.

OPAMJOBS see option `--jobs'.

OPAMKEEPBUILDDIR see option `--keep-build-dir'.

OPAMKEEPCHECKOUTDIR see option `--keep-checkout-dir'.

OPAMKEEPSOURCE see install option `--keep-source'.

OPAMLOCKEDDEPS

When set to true, opam tries to generate a lock file for the current switch, pinning all installed packages to their current versions. This is the default behaviour for opam upgrade when no packages are specified.

OPAMLOCKFILE

Specifies the name of the lock file to use. Defaults to opam.lock.

OPAMNO see options `--yes' and `--confirm-level'.

OPAMNOTESTS see install option `--disable-tests'.

OPAMONLYRECIPE see option `--only-recipe'.

OPAMOUTPUTORDER

Specify the order in which opam outputs diagnostic information. Valid values are natural (follow the command execution order) or reverse (output diagnostics in reverse order of execution). Defaults to natural.

OPAMPIN_ROOT

If set to true, pins packages to the repository version instead of the opam file version. This is the default behavior for opam pin.

OPAMPIN_POLICY

Specifies the default policy for opam pin. Possible values are version, source, local, and dev.

OPAMPROBE_ROOT

If set to true, opam will probe the root directory for build artifacts before checking the switch's build directory. This can speed up rebuilds but may lead to incorrect results if the root directory is shared between different switches.

OPAMQUIET see option `--quiet'.

OPAMREPOSITORIES

A comma-separated list of repository names to use. If set, overrides the default list of repositories.

OPAMREPOLOCK

If set to true, opam will refuse to update repositories. This is useful for ensuring reproducible builds.

OPAMREPO_FILE

Use the specified file as the source for repository definitions. Defaults to ~/.opam/repositories.

OPAMRESOLVEFLAGS

Passes additional flags to the solver. Can be used for debugging the solver.

OPAMROOT see option `--root'.

OPAMSHELL

Use the specified shell for running package scripts. Defaults to sh.

OPAMSKIPHOOKS

If set to true, opam will skip all hooks (e.g. validation hooks).

OPAMSWITCH see option `--switch'. Automatically set by `opam env --switch=SWITCH --set-switch'.

OPAMUNLOCKBASE see install option `--unlock-base'.

OPAMUPGRADECRITERIA specifies user preferences for dependency solving when performing an upgrade. Overrides OPAMCRITERIA in upgrades if both are set. See also option --criteria.

OPAMUSEINTERNALSOLVER see option `--use-internal-solver'.

OPAMUSEOPENSSL Removed in 2.2.

OPAMUTF8 use UTF8 characters in output (one of one of always, never or auto). By default `auto', which is determined from the locale).

OPAMUTF8MSGS use extended UTF8 characters (camels) in opam messages. Implies OPAMUTF8. This is set by default on macOS only.

OPAMVALIDATIONHOOK if set, uses the `%{hook%}' command to validate an opam repository update.

OPAMVERBOSE see option `--verbose'.

OPAMVERBOSEON see option --verbose-on

OPAMVERSIONLAGPOWER do not use.

OPAMWITHDEVSETUP see install option `--with-dev-setup'.

OPAMWITHDOC see install option `--with-doc'.

OPAMWITHTEST see install option `--with-test.

OPAMWORKINGDIR see option `--working-dir'.

OPAMYES see options `--yes' and `--confirm-level`. OPAMYES has priority over OPAMNO and is ignored if OPAMCONFIRMLEVEL is set.

OPAMVAR_var overrides the contents of the variable var when substituting `%{var}%` strings in `opam` files.

OPAMVAR_package_var overrides the contents of the variable package:var when substituting `%{package:var}%` strings in `opam` files.

CLI VERSION

All scripts and programmatic invocations of opam should use `--cli' in order to ensure that they work seamlessly with future versions of the opam client. Additionally, blog posts or other documentation can benefit, as it prevents information from becoming stale.

Although opam only supports roots (~/.opam/) for the current version, it does provide backwards compatibility for its command-line interface.

Since CLI version support was only added in opam 2.1, use OPAMCLI to select 2.0 support (as opam 2.0 will just ignore it), and `--cli=2.1' for 2.1 (or later) versions, since an environment variable controlling the parsing of syntax is brittle. To this end, opam displays a warning if OPAMCLI specifies a valid version other than 2.0, and also if `--cli=2.0' is specified.

The command-line version is selected by using the `--cli' option or the OPAMCLI environment variable. `--cli' may be specified morethan once, where the last instance takes precedence. OPAMCLI is only inspected if `--cli' is not given.

EXIT STATUS

As an exception to the following, the `exec' command returns 127 if the command was not found or couldn't be executed, and the command's exit value otherwise.

0
Success, or true for boolean queries.
1
False. Returned when a boolean return value is expected, e.g. when running with --check, or for queries like opam lint.
2
Bad command-line arguments, or command-line arguments pointing to an invalid context (e.g. file not following the expected format).
5
Not found. You requested something (package, version, repository, etc.) that couldn't be found.
10
Aborted. The operation required confirmation, which wasn't given.
15
Could not acquire the locks required for the operation.
20
There is no solution to the user request. This can be caused by asking to install two incompatible packages, for example.
30
Error in package definition, or other metadata files. Using --strict raises this error more often.
31
Package script error. Some package operations were unsuccessful. This may be an error in the packages or an incompatibility with your system. This can be a partial error.
40
Sync error. Could not fetch some remotes from the network. This can be a partial error.
50
Configuration error. Opam or system configuration doesn't allow operation, and needs fixing.
60
Solver failure. The solver failed to return a sound answer. It can be due to a broken external solver, or an error in solver configuration.
99
Internal error. Something went wrong, likely due to a bug in opam itself.
130
User interrupt. SIGINT was received, generally due to the user pressing Ctrl-C.
0
on success.
123
on indiscriminate errors reported on standard error.
124
on command line parsing errors.
125
on unexpected internal errors (bugs).
