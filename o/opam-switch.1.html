opam-switch(1)

الحزمة: opam

التراخيص: LGPL-2.1-only

OPAM-SWITCH(1) دليل Opam OPAM-SWITCH(1)

الاسم

opam-switch - إدارة بادئات التثبيت المتعددة.

الملخص

opam switch [خيار]… [أمر] [وسيط]…

الوصف

يُستخدم هذا الأمر لإدارة "التحويلات"، وهي بادئات تثبيت مستقلة تحتوي على مترجمها الخاص ومجموعات من الحزم المثبتة والمثبتة. هذا مفيد بشكل عام للحصول على إصدارات مختلفة من المترجم متاحة في وقت واحد.

استخدم opam switch create لإنشاء تحويل جديد، و opam switch set لتعيين التحويل النشط حاليًا. بدون وسيط، يقوم بسرد التحويلات المثبتة، مع وسيط تحويل واحد، افتراضيًا إلى set.

تعاملات التحويل SWITCH يمكن أن تكون اسمًا عاديًا، للتحويلات التي سيتم الاحتفاظ بها داخل ~/.opam، أو اسم دليل، والذي في هذه الحالة هو الدليل حيث سيتم تثبيت بادئة التحويل، كـ _opam. سيختار Opam تلقائيًا تحويلًا بهذا الاسم موجودًا في الدليل الحالي أو الدلائل الأصلية له، ما لم يتم تعيين OPAMSWITCH أو تحديد --switch. عند إنشاء تحويل دليل، إذا تم العثور على تعريفات الحزم محليًا، فسيتم سؤال المستخدم تلقائيًا لتثبيتها بعد إنشاء التحويل ما لم يتم تحديد --no-install.

opam switch set يعين التحويل الافتراضي عالميًا. خطاف الصدفة، عند تمكينه، يقوم بمزامنة جلسة الصدفة الحالية مع هذا التحويل، ما لم يكن الدليل الحالي تحويلًا محليًا، وعندئذ يتم استخدام هذا التحويل المحلي. يمكنك دائمًا استخدام eval $(opam env --switch=SWITCH --set-switch) لتحديد التحويل بشكل صريح، والذي يتجاوز خطاف الصدفة.

الأوامر

بدون وسيط، افتراضيًا إلى list.

SWITCH
مع وسيط SWITCH، افتراضيًا إلى set SWITCH.
-
يعود إلى التحويل السابق غير المحلي (مشابه لـ git switch -). لتعيين التحويل الحالي إلى تحويل يسمى - استخدم --cli=2.1 أو أقل، أو استخدم opam switch set -
create SWITCH [COMPILER]
إنشاء تحويل جديد، وتثبيت المترجم المعطى هناك. SWITCH يمكن أن يكون اسمًا عاديًا، أو دليلًا، مطلقًا أو نسبيًا، وفي هذه الحالة يتم إنشاء تحويل محلي أسفل الدليل المعطى. COMPILER، إذا تم حذفه، افتراضيًا إلى SWITCH إذا كان اسمًا عاديًا، ما لم يتم تحديد --packages أو --formula أو --empty. عند إنشاء تحويل محلي، وعدم وجود أي من هذه الخيارات، يتم اختيار المترجم وفقًا للإعداد الافتراضي للتكوين (انظر opam-init(1)). إذا كان الدليل المختار يحتوي على تعريفات حزم، فسيتم البحث عن مترجم متوافق ضمن التحديد الافتراضي، وسيتم تثبيت الحزم تلقائيًا.
set SWITCH
تعيين التحويل النشط حاليًا، من بين التحويلات المثبتة.
remove SWITCH
إزالة التحويل المعطى من القرص.
export FILE
حفظ حالة التحويل الحالية إلى ملف. إذا تم تحديد --full، فإنه يتضمن بيانات تعريف جميع الحزم المثبتة، وإذا تم تحديد --freeze، فإنه يجمد جميع vcs إلى الالتزام الحالي الخاص بها.
import FILE
استيراد حالة تحويل محفوظة. إذا تم تحديد --switch ولا يشير إلى تحويل موجود، فسيتم إنشاء التحويل للاستيراد.
reinstall [SWITCH]
إعادة تثبيت تحويل المترجم المعطى وجميع حزمه.
list
يسرد التحويلات المثبتة.
list-available [PATTERN]
يسرد جميع الحزم المحتملة الموصى بتثبيتها عند إنشاء تحويل جديد، أي الحزم التي تم تعيين علامة compiler لها. إذا لم يتم توفير نمط، يتم عرض جميع الإصدارات. افتراضيًا، لن تظهر الحزم التي تم تمييزها بـ avoid-version أو deprecated ما لم يتم استخدام --all.
show
يطبع اسم التحويل الحالي.
invariant
يطبع الثابت النشط للتحويل.
set-invariant PACKAGES
يقوم بتحديث ثابت التحويل، أي الصيغة التي يجب أن يحافظ التحويل على التحقق منها طوال العمليات. يتم تجاوز الإعداد السابق. انظر أيضًا الخيارات --force و --no-action. بدون وسيط، يتم اختيار ثابت تلقائيًا.
set-description STRING
يعين وصفًا للتحويل المحدد.
link SWITCH [DIR]
يعين اسم مستعار محليًا لتحويل معين، بحيث يتم تحديد التحويل تلقائيًا عند التواجد في هذا الدليل أو دليل فرعي له.
install SWITCH
تمت إزالته في 2.1، استخدم create بدلاً من ذلك.
set-base PACKAGES
تمت إزالته في 2.1، استخدم set-invariant بدلاً من ذلك.

أمثلة

    opam switch create 4.08.0

إنشاء تحويل جديد يسمى "4.08.0" وتحديده، مع مترجم يتم اختياره تلقائيًا بالإصدار 4.08.0 (لاحظ أن هذا قد يفشل في حالة وجود أكثر من مترجم واحد يطابق هذا الإصدار).

    opam switch create ./ --deps-only

إعداد تحويل محلي لبناء الحزم المعرفة في ./. هذا يقوم بفحص الدليل الحالي بحثًا عن تعريفات الحزم، واختيار مترجم متوافق، وإنشاء تحويل محلي وتثبيت تبعيات الحزم المحلية.

    opam switch create trunk --repos default,beta=https://github.com/ocaml/ocaml-beta-repository.git ocaml-variants.4.10.0+trunk

إنشاء تحويل جديد يسمى "trunk"، مع ocaml-variants.4.10.0+trunk كمترجم، مع تحديد مستودع beta جديد مرتبط بعنوان URL المعطى بالإضافة إلى المستودع الافتراضي.

خيارات

-A COMP, --alias-of=COMP
تمت إزالته في 2.1.
--all
فقط لـ list-available: عرض جميع المترجمات المتاحة، بغض النظر عما إذا كانت مميزة بـ avoid-version أو deprecated.
--deps-only
عند إنشاء تحويل محلي في دليل مشروع (أي دليل يحتوي على تعريفات حزم opam)، قم بتثبيت تبعيات المشروع ولكن ليس المشروع نفسه. عند استيراد تحويل، لا تقم بتثبيت الحزم الجذر.
--description=STRING
إرفاق الوصف المعطى بتحويل عند إنشائه. استخدم الأمر الفرعي set-description لتعديل وصف تحويل موجود.
--empty
السماح بإنشاء تحويل فارغ، بدون ثابت.
--force
فقط لـ set-invariant: فرض تعيين الثابت، وتجاوز فحوصات الاتساق.
--formula=FORMULA
يسمح بتحديد "صيغة تبعية" كاملة، بما في ذلك حالات الاختيار، كثابت للتحويل. التنسيق هو نفسه كما هو مستخدم للتعبير عن التبعيات في ملفات تعريف الحزم، على سبيل المثال '"foo" {>= "1.1"}'
--freeze
عند التصدير، يقوم بتثبيت جميع عناوين URL لـ VCS إلى الالتزام الحالي الخاص بها، ويفشل إذا لم يكن بالإمكان استرداده. هذا يضمن أن الاستيراد سيستعيد الحالة الدقيقة. يعني ضمنيًا --full.
--full
عند التصدير، قم بتضمين بيانات تعريف جميع الحزم المثبتة، مما يسمح بإعادة الاستيراد حتى لو لم تكن موجودة في المستودعات (الافتراضي هو تضمين بيانات تعريف الحزم المثبتة فقط).
-n, --no-action
فقط لـ set-invariant: تعيين الثابت، ولكن لا تفرضه على الفور: انتظر الأمر التالي install أو upgrade أو ما شابه.
--no-autoinstall
تمت إزالته في 2.1.
--no-install
عند إنشاء تحويل محلي، لا تبحث عن أي Lo

ENVIRONMENT

The following environment variables can be used to configure opam behaviour:

OPAM_COLOR
Use colorized output. Can be true, false, or auto (default).
OPAM_CONFIG_DIR
Directory for opam configuration files (default is ~/.config/opam).
OPAM_KEEP_BUILD_DIR
If set, do not remove build directories after a package is built.
OPAM_NO_LOCKS
If set, opam will not create lockfiles.
OPAM_REPOSITORIES_DIR
Directory where repositories are cloned (default is ~/.opam/repositories).
OPAM_ROOT
Directory for opam state (switches, installed packages, etc.). Default is ~/.opam.
OPAM_PACKAGE_DIR
Directory where package source files are downloaded (default is ~/.opam/download).
OPAM_PATCH_DIR
Directory where package patches are downloaded (default is ~/.opam/patches).
OPAM_SWITCH_PREFIX
Directory prefix for switches (default is ~/.opam/).
OPAM_SWITCH_NAME
The name of the current switch. Defaults to default.
OPAM_GLOBAL_PROFILE
Global profile to use. Defaults to default.
OPAM_DEV_ROOT
See option --dev-root.
OPAM_PRETTY_PRINTS
Use pretty printing for output. Enabled by default.
OPAM_PRETTY_PRINTS_MAX_DEPTH
Maximum depth for pretty printing lists and strings (default: 3).
OPAM_PRETTY_PRINTS_MAX_ITEMS
Maximum number of items to display in pretty printed lists and strings (default: 10).
OPAMCLI
Selects the opam CLI version to use. See also the CLI VERSION section.
OPAMCONFIRMLEVEL
Overrides the default confirmation level. Can be 0 (no confirmation), 1 (ask for confirmation for non-interactive commands), or 2 (always ask for confirmation).
OPAMDEVMODE
If set, enables debug mode for package developers.
OPAMDRYRUN
If set, perform a dry run. Implies OPAMYES.
OPAMFIXEDDEPS
If set, opam will not try to change the installed versions of packages, unless explicitly requested. Useful for working with external tools that manage some packages.
OPAMKEEPWIN
Use a specific window to keep package build outputs, useful for debugging.
OPAMMIRRORS
A list of mirror URLs for downloading packages. The format is a space-separated list of URLs, e.g. "http://mirror1.example.com http://mirror2.example.com".
OPAMNOPIPE
Disable piping output from commands. Use this if your terminal does not handle pipes well.
OPAMNOUTF8
Disable extended UTF8 characters (like camels) in opam messages. Implies OPAMUTF8=false. This is set by default on non-macOS systems.
OPAMORDER
Controls the order in which operations are performed. Can be user (default) or deps.
OPAMUTF8
Enable extended UTF8 characters (like camels) in opam messages. Implies OPAMUTF8=true. This is set by default on macOS only.
OPAMVALIDATIONHOOK
If set, uses the `%{hook%}' command to validate an opam repository update.
OPAMVERBOSE
See option --verbose.
OPAMVERBOSEON
See option --verbose-on.
OPAMVERSIONLAGPOWER
do not use.
OPAMWITHDEVSETUP
See install option --with-dev-setup.
OPAMWITHDOC
See install option --with-doc.
OPAMWITHTEST
See install option --with-test.
OPAMWORKINGDIR
See option --working-dir.
OPAMYES
See options --yes and --confirm-level. OPAMYES has priority over OPAMNO and is ignored if OPAMCONFIRMLEVEL is set.
OPAMVAR_var
overrides the contents of the variable var when substituting `%{var}%` strings in `opam` files.
OPAMVAR_package_var
overrides the contents of the variable package:var when substituting `%{package:var}%` strings in `opam` files.

CLI VERSION

All scripts and programmatic invocations of opam should use `--cli' in order to ensure that they work seamlessly with future versions of the opam client. Additionally, blog posts or other documentation can benefit, as it prevents information from becoming stale.

Although opam only supports roots (~/.opam/) for the current version, it does provide backwards compatibility for its command-line interface.

Since CLI version support was only added in opam 2.1, use OPAMCLI to select 2.0 support (as opam 2.0 will just ignore it), and `--cli=2.1' for 2.1 (or later) versions, since an environment variable controlling the parsing of syntax is brittle. To this end, opam displays a warning if OPAMCLI specifies a valid version other than 2.0, and also if `--cli=2.0' is specified.

The command-line version is selected by using the `--cli' option or the OPAMCLI environment variable. `--cli' may be specified morethan once, where the last instance takes precedence. OPAMCLI is only inspected if `--cli' is not given.

EXIT STATUS

As an exception to the following, the `exec' command returns 127 if the command was not found or couldn't be executed, and the command's exit value otherwise.

0
Success, or true for boolean queries.
1
False. Returned when a boolean return value is expected, e.g. when running with --check, or for queries like opam lint.
2
Bad command-line arguments, or command-line arguments pointing to an invalid context (e.g. file not following the expected format).
5
Not found. You requested something (package, version, repository, etc.) that couldn't be found.
10
Aborted. The operation required confirmation, which wasn't given.
15
Could not acquire the locks required for the operation.
20
There is no solution to the user request. This can be caused by asking to install two incompatible packages, for example.
30
Error in package definition, or other metadata files. Using --strict raises this error more often.
31
Package script error. Some package operations were unsuccessful. This may be an error in the packages or an incompatibility with your system. This can be a partial error.
40
Sync error. Could not fetch some remotes from the network. This can be a partial error.
50
Configuration error. Opam or system configuration doesn't allow operation, and needs fixing.
60
Solver failure. The solver failed to return a sound answer. It can be due to a broken external solver, or an error in solver configuration.
99
Internal error. Something went wrong, likely due to a bug in opam itself.
130
User interrupt. SIGINT was received, generally due to the user pressing Ctrl-C.
0
on success.
123
on indiscriminate errors reported on standard error.
124
on command line parsing errors.
125
on unexpected internal errors (bugs).
