DESCRIPTION

The OpenSMTPD server provides a C API to allow external filters to hook into the SMTP transaction. Filters can inspect and modify the protocol flow, and can hook into various events.

The C filter API is designed to be simple and efficient. Filters are loaded as dynamic libraries by OpenSMTPD.

registering filters

Filters register their callbacks using the various osmtpd_register_filter_* functions. These functions should be called from the filter's entry point function. The entry point function must be named filter_init and must have the following signature:

void filter_init(void);

The following filter callback types are available:

Connect
Called when a new client connection is established. Allows filtering based on hostname and source/destination address.
HELO
Called when the client sends a HELO command.
EHLO
Called when the client sends an EHLO command.
STARTTLS
Called when the client initiates STARTTLS.
AUTH
Called when the client initiates authentication.
MAIL FROM
Called when the client sends the MAIL FROM command.
RCPT TO
Called when the client sends a RCPT TO command.
DATA
Called when the client sends the DATA command.
DATALINE
Called for each line of the DATA section.
RSET
Called when the client sends the RSET command.
QUIT
Called when the client sends the QUIT command.
NOOP
Called when the client sends the NOOP command.
HELP
Called when the client sends the HELP command.
WIZ
Called when the client sends the WIZ command (not a standard SMTP command).
COMMIT
Called when the transaction is committed.

In addition to filter callbacks, report callbacks can be registered. These callbacks are called when OpenSMTPD generates a report for an event. The incoming parameter determines whether the callback is for incoming (1) or outgoing (0) connections.

Connect
Called when a connection report is generated.
Disconnect
Called when a disconnect report is generated.
Identify
Called when an identify report is generated.
TLS
Called when a TLS report is generated.
AUTH
Called when an authentication report is generated.
Reset
Called when a reset report is generated.
Begin
Called when a begin report is generated.
Mail
Called when a mail report is generated.
Rcpt
Called when a recipient report is generated.
Envelope
Called when an envelope report is generated.
Data
Called when a data report is generated.
Commit
Called when a commit report is generated.
Rollback
Called when a rollback report is generated.
Client
Called when a client command report is generated.
Server
Called when a server response report is generated.
Response
Called when a general response report is generated.
Timeout
Called when a timeout report is generated.

The callback functions receive a pointer to an osmtpd_ctx structure, which provides access to the current session state and allows filters to interact with the server.

The return value of filter callbacks determines the server's action:

OSMTPD_FILTER_PROCEED
Continue processing the SMTP transaction.
OSMTPD_FILTER_REJECT
Reject the current SMTP command or transaction with an appropriate error message.
OSMTPD_FILTER_DISCONNECT
Disconnect the client.
OSMTPD_FILTER_REWRITE
Rewrite the current parameter (e.g., change the MAIL FROM or RCPT TO address).
OSMTPD_FILTER_DATALINE
If called from a filter_data callback, it indicates that the filter will handle reading the DATA section line by line. The filter must then call osmtpd_filter_dataline for each line.

The return value of report callbacks is ignored.

local data

Filters can maintain local data associated with each session and message. The osmtpd_local_session and osmtpd_local_message functions allow filters to register callbacks for creating and destroying session-specific and message-specific data, respectively.

The oncreate callbacks receive the osmtpd_ctx and should return a pointer to the newly allocated data. The ondelete callbacks receive the osmtpd_ctx and the pointer to the data to be freed.

needs

The osmtpd_need function can be used to specify requirements for the filter. For example, a filter might require access to the message body, in which case it would call osmtpd_need(OSMTPD_NEED_BODY).

session context

The osmtpd_ctx structure provides access to various pieces of information about the current SMTP session, including:

client_addr
The client's source address.
server_addr
The server's destination address.
hostname
The client's hostname (if resolved).
rdns
The client's reverse DNS hostname.
mailfrom
The current MAIL FROM address.
rcptto
A list of current RCPT TO addresses.
msgid
The ID of the current message.
data
A pointer to the session-specific local data.
msgdata
A pointer to the message-specific local data.

Filters can also use the following functions to interact with the server:

osmtpd_filter_proceed(ctx)
Continue the transaction.
osmtpd_filter_reject(ctx, code, msg)
Reject the current command or transaction.
osmtpd_filter_disconnect(ctx, code, msg)
Disconnect the client.
osmtpd_filter_rewrite(ctx, param, value)
Rewrite a parameter.
osmtpd_filter_dataline(ctx, line)
Provide a line of DATA to the server (used when filter_data returns OSMTPD_FILTER_DATALINE).
osmtpd_run(ctx)
Causes the server to run the filter, applying all registered callbacks. This function is typically called once at the end of filter_init.
osmtpd_warn(ctx, fmt, ...)
Log a warning message.
osmtpd_warnx(ctx, fmt, ...)
Log a warning message without a newline.
osmtpd_err(ctx, code, fmt, ...)
Log an error message and reject the command.
osmtpd_errx(ctx, code, fmt, ...)
Log an error message without a newline and reject the command.

exit codes

The filter callback functions should return one of the following values:

OSMTPD_FILTER_PROCEED
Continue processing the SMTP transaction.
OSMTPD_FILTER_REJECT
Reject the current SMTP command or transaction with an appropriate error message.
OSMTPD_FILTER_DISCONNECT
Disconnect the client.
OSMTPD_FILTER_REWRITE
Rewrite the current parameter (e.g., change the MAIL FROM or RCPT TO address).
OSMTPD_FILTER_DATALINE
If called from a filter_data callback, it indicates that the filter will handle reading the DATA section line by line. The filter must then call osmtpd_filter_dataline for each line.

الوصف

يوفر خادم OpenSMTPD واجهة برمجة تطبيقات C للسماح للمرشحات الخارجية بالربط في تدفق معاملة SMTP. يمكن للمرشحات فحص وتعديل تدفق البروتوكول، ويمكنها الربط في أحداث مختلفة.

تم تصميم واجهة برمجة تطبيقات مرشحات C لتكون بسيطة وفعالة. يتم تحميل المرشحات كمكتبات ديناميكية بواسطة OpenSMTPD.

تسجيل المرشحات

تقوم المرشحات بتسجيل دوال رد الاتصال الخاصة بها باستخدام دوال osmtpd_register_filter_* المختلفة. يجب استدعاء هذه الدوال من دالة نقطة الدخول للمرشح. يجب أن تكون دالة نقطة الدخول المسماة filter_init وأن تمتلك التوقيع التالي:

void filter_init(void);

أنواع ردود الاتصال المتاحة للمرشحات هي:

اتصال
يتم استدعاؤه عند إنشاء اتصال عميل جديد. يسمح بالترشيح بناءً على اسم المضيف وعنوان المصدر/الوجهة.
HELO
يتم استدعاؤه عندما يرسل العميل أمر HELO.
EHLO
يتم استدعاؤه عندما يرسل العميل أمر EHLO.
STARTTLS
يتم استدعاؤه عندما يبدأ العميل STARTTLS.
AUTH
يتم استدعاؤه عندما يبدأ العميل المصادقة.
MAIL FROM
يتم استدعاؤه عندما يرسل العميل أمر MAIL FROM.
RCPT TO
يتم استدعاؤه عندما يرسل العميل أمر RCPT TO.
DATA
يتم استدعاؤه عندما يرسل العميل أمر DATA.
DATALINE
يتم استدعاؤه لكل سطر في قسم DATA.
RSET
يتم استدعاؤه عندما يرسل العميل أمر RSET.
QUIT
يتم استدعاؤه عندما يرسل العميل أمر QUIT.
NOOP
يتم استدعاؤه عندما يرسل العميل أمر NOOP.
HELP
يتم استدعاؤه عندما يرسل العميل أمر HELP.
WIZ
يتم استدعاؤه عندما يرسل العميل أمر WIZ (ليس أمر SMTP قياسي).
COMMIT
يتم استدعاؤه عند تأكيد المعاملة.

تتلقى دوال رد الاتصال مؤشرًا إلى بنية osmtpd_ctx، والتي توفر الوصول إلى حالة الجلسة الحالية وتسمح للمرشحات بالتفاعل مع الخادم.

يحدد رمز الإرجاع لدوال رد الاتصال للمرشحات إجراء الخادم:

OSMTPD_FILTER_PROCEED
متابعة معالجة معاملة SMTP.
OSMTPD_FILTER_REJECT
رفض أمر SMTP الحالي أو المعاملة برسالة خطأ مناسبة.
OSMTPD_FILTER_DISCONNECT
قطع اتصال العميل.
OSMTPD_FILTER_REWRITE
إعادة كتابة المعلمة الحالية (على سبيل المثال، تغيير عنوان MAIL FROM أو RCPT TO).
OSMTPD_FILTER_DATALINE
إذا تم استدعاؤه من دالة رد اتصال filter_data، فإنه يشير إلى أن المرشح سيتعامل مع قراءة قسم DATA سطرًا بسطر. يجب على المرشح بعد ذلك استدعاء osmtpd_filter_dataline لكل سطر.

يتم تجاهل رمز الإرجاع لدوال رد الاتصال للتقارير.

بيانات محلية

يمكن للمرشحات الاحتفاظ ببيانات محلية مرتبطة بكل جلسة وكل رسالة. تسمح دوال osmtpd_local_session و osmtpd_local_message للمرشحات بتسجيل ردود الاتصال لإنشاء وتدمير البيانات الخاصة بالجلسة والرسالة على التوالي.

تتلقى ردود الاتصال oncreate بنية osmtpd_ctx ويجب أن تُرجع مؤشرًا إلى البيانات المخصصة حديثًا. تتلقى ردود الاتصال ondelete بنية osmtpd_ctx والمؤشر إلى البيانات التي يجب تحريرها.

الاحتياجات

يمكن استخدام الدالة osmtpd_need لتحديد المتطلبات للمرشح. على سبيل المثال، قد يحتاج المرشح إلى الوصول إلى نص الرسالة، وفي هذه الحالة سيستدعي osmtpd_need(OSMTPD_NEED_BODY).

وصف

واجهة برمجة تطبيقات osmtpd هي واجهة تعتمد على الأحداث لكتابة مرشحات smtpd(8). يتم تسجيل ردود المرشحات والتقارير عبر فئة osmtpd_register من الدوال، متبوعة بـ osmtpd_run. يجب أن يعيد رد الاتصال 0 في حالة النجاح، أو -1 في حالة حدوث خطأ يؤدي إلى قطع اتصال هذه الجلسة.

DESCRIPTION

The libopensmtpd library implements the OpenSMTPD filter API. The filters are small programs that can be loaded into OpenSMTPD to hook into the SMTP transaction and modify or reject it. The API is event-based, and filters are called back by OpenSMTPD when certain events occur during the SMTP transaction.

The main entry point for the filter library is osmtpd_run(), which takes an integer fd representing the listening socket to use. This function will block indefinitely, processing incoming SMTP connections.

Filters are registered using the osmtpd_register_filter* functions. Each filter has a name, a priority, a callback function, and an optional context pointer. The priority determines the order in which filters are called. Lower priority values are called first.

The callback function is called with a ctx pointer, which is the context passed during registration, and an event integer. The event can be one of the following:

OSMTPD_EVENT_CONNECT
A new client connection has been established.
OSMTPD_EVENT_HELO
The client has sent a HELO or EHLO command.
OSMTPD_EVENT_MAIL
The client has sent a MAIL FROM command.
OSMTPD_EVENT_RCPT
The client has sent a RCPT TO command.
OSMTPD_EVENT_DATA
The client has sent the DATA command, and the message content follows.
OSMTPD_EVENT_RCPT_MSG
A RCPT TO command has been processed and the message content is about to be sent.
OSMTPD_EVENT_PRE_DATALINE
A line of message data is about to be processed.
OSMTPD_EVENT_POST_DATALINE
A line of message data has been processed.
OSMTPD_EVENT_EOD
The end of the message data has been reached.
OSMTPD_EVENT_QUIT
The client has sent a QUIT command.
OSMTPD_EVENT_DISCONNECT
The client has disconnected.

After processing an event, the filter must call one of the following functions to indicate how to proceed:

osmtpd_filter_proceed
Continue the SMTP transaction normally.
osmtpd_filter_rewrite
Modify the message content. This function takes the modified data as an argument.
osmtpd_filter_reject
Reject the current transaction or message with a given reason.
osmtpd_filter_disconnect
Disconnect the client with a given reason.

The context pointer ctx passed to the filter callback can be used to store per-session or per-message data. The following functions can be used to retrieve filter-specific data:

char *hostname
The hostname of the client. osmtpd_need needs to be initialized with OSMTPD_NEED_HOSTNAME. If not available the attribute is set to NULL.
char *remote_addr
The IP address of the client. osmtpd_need needs to be initialized with OSMTPD_NEED_REMOTE_ADDR. If not available the attribute is set to 0.
char *msgid
The Message-ID of the message. osmtpd_need needs to be initialized with OSMTPD_NEED_MSGID. If not available the attribute is set to 0. Filters in need of filter specific data can use osmtpd_local_message and local_message.
char *username
The username with which the session was successfully authenticated. osmtpd_need needs to be initialized with If not available or authentication failed is set to NULL.
char *mailfrom
The envelope MAIL FROM address in the SMTP transaction. osmtpd_need needs to be initialized with OSMTPD_NEED_MAILFROM. If not available the attribute is set to NULL.
char **rcptto
The envelope RCPT TO address in the SMTP transaction. osmtpd_need needs to be initialized with OSMTPD_NEED_RCPTTO. This attribute is a NULL-terminated array of address strings. If not available the first element in the array is set to NULL.
uint64_t evpid
The envelope ID we're currently working on. osmtpd_need needs to be initialized with OSMTPD_NEED_EVPID. If not available the attribute is set to 0.
void *local_session
Any filter specific data that needs to be stored during the session. This is initialized on ctx creation by calling oncreate argument from osmtpd_local_session.
void *local_message
Any filter specific data that needs to be stored during the message transaction. This is initialized on ctx creation by calling oncreate argument from osmtpd_local_message.

The osmtpd_register_filter class of functions must call one of osmtpd_filter_proceed, osmtpd_filter_rewrite, osmtpd_filter_reject and osmtpd_filter_disconnect. This can be done either in the callback function itself, or at a later moment through another callback. Note that the session stalls until the osmtpd_filter has been called.

Exceptions to the above reply options are:

•
osmtpd_register_filter_connect's and osmtpd_register_filter functions' callbacks without argument can't use osmtpd_filter_rewrite.
•
osmtpd_register_filter_dataline's callback can only use osmtpd_filter_dataline.

osmtpd_warn, osmtpd_warnx, osmtpd_err and osmtpd_errx can be used as a standin for warn(3) , warnx(3) , err(3) and errx(3) without printing the program name to stderr. Additionally, osmtpd_warn and osmtpd_warnx prints the request ID on the logline when ctx is not NULL.
