الاسم

opensc.conf - ملف الإعدادات لـ OpenSC

الوصف

يحصل OpenSC على بيانات الإعدادات من المصادر التالية وبالترتيب التالي:

1. خيارات سطر الأوامر
2. متغيرات البيئة
3. مفتاح سجل Windows في HKEY_CURRENT_USER (إذا كان متاحاً)
4. مفتاح سجل Windows في HKEY_LOCAL_MACHINE (إذا كان متاحاً)
5. ملف الإعدادات على مستوى النظام (/etc/opensc.conf)

يتكون ملف الإعدادات، opensc.conf، من كتل (blocks)، والتي، بشكل عام، لها الصيغة التالية:

مفتاح [, اسم...] {
	محتويات_الكتلة
}

محتويات_الكتلة هي عنصر_كتلة واحد أو أكثر حيث يكون عنصر_كتلة واحداً مما يلي:

•# سلسلة تعليق
•مفتاح[, اسم...] = قيمة;
•كتلة

على المستوى الجذري، يجب أن يحتوي opensc.conf على كتلة إعدادات واحدة أو أكثر خاصة بالتطبيق:

app تطبيق {
	محتويات_الكتلة
}

تطبيق يحدد واحداً مما يلي:

•اسم_ملف: كتلة الإعدادات للتطبيق ذي مسار الملف المحدد.
•default: كتلة الإعدادات الاحتياطية لجميع التطبيقات
•opensc-pkcs11: كتلة الإعدادات لوحدة PKCS#11 (opensc-pkcs11.so)
•onepin-opensc-pkcs11: كتلة الإعدادات لوحدة PKCS#11 ذات PIN واحد (onepin-opensc-pkcs11.so)
•cardmod: كتلة الإعدادات لـ minidriver الخاص بـ Windows (opensc-minidriver.dll)
•tokend: كتلة الإعدادات لـ tokend الخاص بـ macOS (OpenSC.tokend)
•tool_ctapi, tool_cryptoflex, tool_dnie, tool_egk, tool_eidenv, tool_gids, tool_iasecc, tool_netkey, tool_npa, tool_openpgp, tool_opensc_asn1, tool_opensc_explorer, tool_opensc_notify, tool_opensc_tool, tool_piv, tool_pkcs11, tool_pkcs15_crypt, tool_pkcs15_init, tool_pkcs15_tool, tool_sc_hsm, tool_westcos: كتلة الإعدادات لأدوات OpenSC

خيارات الإعدادات

debug = رقم;

مقدار معلومات التصحيح المراد طباعتها (الافتراضي: 0). قيمة أكبر تعني مزيداً من معلومات التصحيح.

المتغير البيئي OPENSC_DEBUG يلغي هذا الإعداد.

debug_file = اسم_ملف;

الملف الذي ستُكتب إليه مخرجات التصحيح (الافتراضي: stderr). يتم التعرف على القيم الخاصة stdout و stderr.

profile_dir = اسم_ملف;

دليل قوالب تهيئة/تخصيص PKCS#15 لـ pkcs15-init(1) (الافتراضي: /usr/share/opensc).

إذا لم يتم العثور على قيمة الإعدادات هذه في Windows، يتم التحقق من مفتاح السجل Software\OpenSC Project\OpenSC\ProfileDir.

disable_colors = قيمة_منطقية;

تعطيل ألوان رسائل السجل (الافتراضي: false إذا كان متصلاً بوحدة تحكم، true بخلاف ذلك).

disable_popups = قيمة_منطقية;

تعطيل النوافذ المنبثقة لواجهة المستخدم الرسومية المضمنة (الافتراضي: false).

enable_default_driver = قيمة_منطقية;

تمكين برنامج تشغيل البطاقة الافتراضي (الافتراضي: false). يتم تمكين برنامج تشغيل البطاقة الافتراضي صراحةً لـ opensc-explorer(1) و opensc-tool(1).

card_drivers = اسم...;

قائمة بيضاء ببرامج تشغيل البطاقات التي سيتم تحميلها عند بدء التشغيل. القيمة الخاصة internal (الافتراضي) ستحمل جميع برامج التشغيل المترجمة بشكل ثابت.

إذا تم تقديم برنامج تشغيل غير معروف (أي ليس داخلياً أو قديماً)، فيجب كتابة كتلة إعدادات منفصلة لبرنامج التشغيل. القيمة الخاصة old ستحمل جميع برامج التشغيل المترجمة بشكل ثابت والتي قد يتم إزالتها في المستقبل.

يمكن استرداد قائمة أسماء برامج تشغيل البطاقات المدعومة من مخرجات opensc-tool --list-drivers.

المتغير البيئي OPENSC_DRIVER يلغي هذا الإعداد.

ignored_readers = اسم...;

قائمة القارئات التي سيتم تجاهلها (الافتراضي: فارغة). إذا تمت مطابقة أي من السلاسل المفصولة بفواصل في اسم قارئ (حساس لحالة الأحرف، المطابقة الجزئية ممكنة)، يتم تجاهل القارئ بواسطة OpenSC. استخدم opensc-tool --list-readers لرؤية جميع القارئات المتصلة حالياً.

reader_driver اسم { محتويات_الكتلة }

إعدادات برنامج تشغيل قارئ البطاقة الذكية حيث اسم هو أحد:
•ctapi: انظر القسم المسمى "إعدادات قارئات CT-API"
•pcsc: انظر القسم المسمى "إعدادات قارئات PC/SC"
•openct: انظر القسم المسمى "إعدادات قارئات OpenCT"
•cryptotokenkit: كتلة الإعدادات لقارئات CryptoTokenKit

انظر القسم المسمى "إعدادات قارئ البطاقة الذكية".

card_driver اسم { محتويات_الكتلة }

إعدادات برنامج تشغيل البطاقة حيث اسم هو أحد:
•npa: انظر القسم المسمى "خيارات الإعدادات لبطاقة الهوية الألمانية"
•dnie: انظر القسم المسمى "خيارات الإعدادات لبطاقة DNIe"
•edo: انظر القسم المسمى "خيارات الإعدادات لبطاقة الهوية البولندية الإلكترونية"
•eoi: انظر القسم المسمى "خيارات الإعدادات لبطاقة الهوية السلوفينية الإلكترونية"
•myeid: انظر القسم المسمى "خيارات الإعدادات لبطاقة MyEID"
•Any other value: كتلة الإعدادات لبرنامج تشغيل بطاقة تم تحميله خارجياً

card_atr سلسلة_سداسية_عشرية { محتويات_الكتلة }

بالإضافة إلى القائمة المدمجة للبطاقات المعروفة في برنامج تشغيل البطاقة، يمكنك تكوين بطاقة جديدة لبرنامج التشغيل باستخدام كتلة card_atr.

للتفاصيل، انظر القسم المسمى "الإعدادات بناءً على ATR".

disable_hw_pkcs1_padding = قيمة;

تعطيل حشو PKCS#1 v1.5 في العتاد عندما تدعم البطاقة إجراء عمليات RSA خام. المعلمات المعروفة:
•no: يتم تمكين حشو PKCS#1 v1.5 في العتاد عندما تدعمه البطاقة.
•sign: يتم تعطيل حشو PKCS#1 v1.5 للتوقيعات فقط (نوع PKCS#1 v1.5 1).
•decipher: يتم تعطيل حشو PKCS#1 v1.5 لفك التشفير فقط (نوع PKCS#1 v1.5 2).
•both: يتم تعطيل حشو PKCS#1 v1.5 لكل من التوقيعات وفك التشفير (نوع PKCS#1 v1.5 1 و 2).

(الافتراضي: decipher).

secure_messaging اسم { محتويات_الكتلة }

خيارات الإعدادات لملف تعريف المراسلة الآمنة اسم:

module_name = اسم_ملف;

اسم وحدة SM الخارجية (الافتراضي: libsmm-local.so).

module_path = اسم_ملف;

الدليل الذي يحتوي على وحدة SM الخارجية (الافتراضي: /usr/lib).

إذا لم يتم العثور على قيمة الإعدادات هذه في Windows، يتم التحقق من مفتاح السجل Software\OpenSC Project\OpenSC\SmDir.

module_data = قيمة;

بيانات محددة لضبط تهيئة الوحدة.

mode = قيمة;

وضع المراسلة الآمنة. المعلمات المعروفة:
•transmit: في هذا الوضع، يتم استدعاء إجراء تأمين APDU بواسطة إجراء إرسال APDU العام لـ OpenSC. في هذا الوضع، يتم تأمين جميع APDUs، باستثناء تلك التي تم تصفيتها بواسطة الإجراء الخاص بالبطاقة.
•acl: في هذا الوضع، يتم تأمين APDUs فقط إذا لزم الأمر بواسطة قوائم التحكم في الوصول (ACLs) للأمر المراد تنفيذه.

flags = قيمة;

علامات خاصة بنوع المراسلة الآمنة.

kmc = سلسلة_سداسية_عشرية;

KMC افتراضي لمدير بطاقة GP لبطاقات Java الخاصة بـ Oberthur.

ifd_serial =

هذا الموقع غير مرتبط بـ Arch Linux ولا تابع له بأي شكل من الأشكال. المحتوى هو ترجمة فقط لصفحات دليل Arch المنشورة على man.archlinux.org.

>سلسلة_ست_عشرية;

مجموعة_مفاتيح[_معرف_التطبيق]_رقم_تشفير = قيمة؛ مجموعة_مفاتيح[_معرف_التطبيق]_رقم_تجزئة = قيمة؛

قيم مجموعة المفاتيح من ملفات تعريف IAM لبطاقات Gemalto IAS/ECC مع معرف تطبيق اختياري

إطار_عمل اسم { محتويات_الكتلة }

خيارات التكوين الداخلية حيث اسم هو أحد:
•pkcs15: انظر القسم المسمى "تكوين إطار عمل PKCS#15"
•tokend: انظر القسم المسمى "تكوين Tokend"

pkcs11 { محتويات_الكتلة }

معلمات لوحدة PKCS11 الخاصة بـ OpenSC.

للتفاصيل انظر القسم المسمى "تكوين PKCS#11".

تكوين برنامج تشغيل قارئ البطاقة الذكية

خيارات تكوين لجميع برامج تشغيل القارئ

حجم_الإرسال_الأقصى = رقم؛ حجم_الاستقبال_الأقصى = رقم؛

تحديد حجم الأوامر والاستجابات (الافتراضي: حجم_الإرسال_الأقصى = 255، حجم_الاستقبال_الأقصى = 256). بعض القراء لا ينقلون قدرات الإرسال والاستقبال الخاصة بهم بشكل صحيح. يسمح حجم_الإرسال_الأقصى وحجم_الاستقبال_الأقصى بتعيين الحدود يدويًا، على سبيل المثال لتمكين قدرات الطول الممتد.

تمكين_الهروب قيمة_منطقية؛

اكتشاف قدرات القارئ باستخدام أوامر الهروب (APDU مغلفة مع CLA=0xFF كما هو محدد بواسطة PC/SC الجزء 3 و BSI TR-03119، على سبيل المثال للحصول على UID، وأوامر PIN المهربة، وإصدار البرنامج الثابت للقارئ، الافتراضي: خطأ)

تكوين قراء CT-API

وحدة_نمطية اسم_ملف { منافذ = أرقام؛ }

تحميل وحدة CT-API المحددة مع عدد المنافذ المحدد.

تكوين قراء PC/SC

الاتصال_الحصري = قيمة_منطقية؛

الاتصال بالقارئ في وضع حصري (الافتراضي: خطأ)؟ هذا الخيار ليس له تأثير في برنامج التشغيل المصغر لنظام Windows.

إجراء_قطع_الاتصال = إجراء؛

ماذا تفعل عند قطع الاتصال ببطاقة (SCardDisconnect). القيم الصالحة هي ترك، إعادة تعيين، إيقاف تشغيل (الافتراضي: ترك). هذا الخيار ليس له تأثير في برنامج التشغيل المصغر لنظام Windows.

إجراء_انتهاء_المعاملة = إجراء؛

ماذا تفعل في نهاية المعاملة (SCardEndTransaction). القيم الصالحة هي ترك، إعادة تعيين، إيقاف تشغيل (الافتراضي: ترك). هذا الخيار ليس له تأثير في برنامج التشغيل المصغر لنظام Windows.

إجراء_إعادة_الاتصال = إجراء؛

ماذا تفعل عند إعادة الاتصال ببطاقة (SCardReconnect). القيم الصالحة هي ترك، إعادة تعيين، إيقاف تشغيل (الافتراضي: ترك). هذا الخيار ليس له تأثير في برنامج التشغيل المصغر لنظام Windows.

تمكين_لوحة_الأرقام = قيمة_منطقية؛

تمكين لوحة الأرقام إذا تم اكتشافها (PC/SC v2.0.2 الجزء 10، الافتراضي: صحيح)

طول_الرقم_السري_الثابت = رقم؛

يمكن لبعض قراء لوحة الأرقام التعامل مع طول واحد فقط للرقم السري. يحدد طول_الرقم_السري_الثابت هذه القيمة بحيث يقوم OpenSC بتوسيع الحشو إلى هذا الطول (الافتراضي: 0، أي غير ثابت).

مكتبة_الموفر = اسم_ملف؛

استخدام موفر PC/SC محدد (الافتراضي: libpcsclite.so.1).

تكوين قراء OpenCT

قراء = رقم؛

القراء الافتراضيون للتخصيص (الافتراضي: 2).

خيارات التكوين لبطاقة MyEID

تعطيل_حشو_pkcs1_عتاد = قيمة_منطقية؛

يمكن لبطاقة MyEID تغليف البيانات (رمز التجزئة) داخليًا في بنية DigestInfo ASN.1 وفقًا لخوارزمية التجزئة المحددة (حاليًا لـ SHA1 فقط). يتم حشو DigestInfo إلى طول وحدة مفتاح RSA وفقًا لـ PKCS#1 v1.5، نوع الكتلة 01h. يجب ألا يتجاوز حجم DigestInfo 40% من طول وحدة مفتاح RSA. إذا كان هذا الحد غير مرضٍ (على سبيل المثال، يحتاج شخص ما إلى RSA 1024 مع SHA512)، يمكن للمستخدم تعطيل هذه الميزة. في هذه الحالة، سيقوم برنامج تشغيل البطاقة بكل ما هو ضروري قبل إرسال البيانات (رمز التجزئة) إلى البطاقة.

يمكن تعطيل حشو PKCS#1 v1.5 في العتاد بشكل عام باستخدام الخيار تعطيل_حشو_pkcs1_عتاد. عند استخدام الخيار العام لتعطيل الحشو، سيتم تعطيل الحشو حتى لو لم يقم الخيار الخاص بـ MyEID بتعطيله.

خيارات التكوين لبطاقة الهوية الألمانية

can = قيمة؛

تتطلب بطاقة الهوية الألمانية التحقق من CAN قبل رقم PIN لـ QES. ومع ذلك، هذا ليس جزءًا من ملف تعريف PKCS#15 للبطاقة. لذا للتحقق من رقم PIN الخاص بـ QES، نحتاج إلى كليهما. يمكن تقديم CAN هنا. إذا لم يتم تقديم CAN هنا، فسيتم طلبه في سطر الأوامر أو على القارئ (اعتمادًا على قدرات القارئ).

شهادة_st_dv = اسم_ملف؛ شهادة_st = اسم_ملف؛ مفتاح_st = اسم_ملف؛

التوقيع الإلكتروني المؤهل (QES) ممكن فقط مع قارئ مريح (CAT-K)، والذي يحتوي على مفتاح تشفير للمصادقة الذاتية كطرف توقيع (ST). عادةً ما نستخدم قدرة القارئ لتوقيع البيانات. ومع ذلك، أثناء التطوير، يمكنك تحديد شهادات ومفاتيح ناعمة لـ ST.

يمكن العثور على مثال PKI في بيانات المثال لـ **محاكي بطاقة الهوية الألمانية**[1]

خيارات التكوين لـ DNIe

الموافقة_المستخدم_ممكنة = قيمة_منطقية؛

تكوين رسالة التحذير عند إجراء عملية توقيع باستخدام DNIe. يستخدم فقط إذا تم تجميعه مع --enable-dnie-ui

تطبيق_الموافقة_المستخدم = اسم_ملف؛

تحديد تطبيق إدخال الرقم السري المراد استخدامه إذا تم تكوين عرض التحذير باستخدام إدخال الرقم السري (الافتراضي: /usr/bin/pinentry). يستخدم فقط إذا تم تجميعه مع --enable-dnie-ui

خيارات التكوين لبطاقة الهوية الإلكترونية البولندية

can = قيمة؛

رقم الوصول إلى البطاقة (CAN - رقم مكون من 6 أرقام مطبوع في الزاوية السفلية اليمنى من الجانب الأمامي للمستند) مطلوب لإنشاء اتصال بالبطاقة. قد يتم تجاوزه بواسطة متغير البيئة EDO_CAN. حاليًا، لا يمكن تعيينه بأي طريقة أخرى.

خيارات التكوين لبطاقة الهوية الإلكترونية السلوفينية

can = قيمة؛

رقم الوصول إلى البطاقة (CAN - رقم مكون من 6 أرقام مطبوع في الزاوية السفلية اليمنى من الجانب الأمامي للمستند) مطلوب لإنشاء اتصال بالبطاقة. قد يتم تجاوزه بواسطة متغير البيئة EOI_CAN. نظرًا لأن CAN مخزن أيضًا على البطاقة (بشكل مشفر) يمكن استخدامه لإنشاء اتصال آمن تلقائيًا، ولكن فقط إذا تم الوصول إلى البطاقة عبر الواجهة التلامسية.

خيارات التكوين لبطاقة PIV

التكوين بناءً على ATR

قناع_atr = سلسلة_ست_عشرية؛

يتم إجراء عملية AND منطقية للقناع مع ATR البطاقة قبل مقارنته بقيمة مرجع ATR أعلاه. يتيح استخدام هذا القناع تحديد وتكوين العديد من ATR كنفس نموذج البطاقة.

برنامج_التشغيل = اسم؛

عند التمكين، يتجاوز جميع الإعدادات الممكنة من قائمة تكوين البطاقة المدمجة في برامج تشغيل البطاقة.

اسم = اسم؛

تعيين اسم البطاقة لبرامج تشغيل البطاقة التي تسمح بذلك.

نوع = رقم؛

يسمح بتعيين النوع الدقيق للبطاقة المستخدم داخليًا بواسطة برنامج تشغيل البطاقة. يمكن العثور على القيم المسموح بها في الكود المصدري لـ cards.h.

علامات = قيمة...؛

علامات البطاقة كقيمة ست عشرية. يتم دمج قيم متعددة باستخدام OR. اعتمادًا على برنامج تشغيل البطاقة، يسمح هذا بالضبط بضبط قدرات برنامج تشغيل البطاقة لبطاقتك.

اختياريًا، يمكن تحديد بعض المعلمات المعروفة كسلاسل نصية:

•rng: مصدر أرقام عشوائية على اللوحة

NAME

opensc.conf — OpenSC configuration file

DESCRIPTION

The OpenSC PKCS#11 module can be configured by editing the opensc.conf file. The configuration can be done globally or per-user.

The file format is INI-style, with sections enclosed in square brackets.

Comments start with a hash character (#) and continue to the end of the line.

GLOBAL OPTIONS

These options can be specified in the global configuration file or in the user configuration file.

enable = bool;

Enable or disable the OpenSC PKCS#11 module (Default: true).

use_safe_user_creation = bool;

When this is enabled, OpenSC will not use an existing User PIN to initialize an application. Instead, it will try to create a new User PIN. This is generally useful for cards that are intended to be used by a single user. (Default: false).

debug = num;

Set the debug level. Higher values mean more debug output. (Default: 0).

See also the OPENSC_DEBUG environment variable.

card_drivers = name...;

A space-separated list of card driver names. OpenSC will only load the specified card drivers. If not specified, OpenSC will try to load all available card drivers.

See also the OPENSC_DRIVER environment variable.

use_default_pkcs11_context = bool;

Use the default PKCS#11 context. This is useful for debugging PKCS#11 applications. (Default: false).

pkcs11_context = path;

Path to the PKCS#11 context file.

disable_pin_caching = bool;

Disable PIN caching. If enabled, the PIN will not be cached in memory. This can improve security but may also lead to slower performance. (Default: false).

enable_pinpad = bool;

Enable or disable the PIN pad. If enabled, OpenSC will try to use a PIN pad to enter the PIN. This is useful for cards that require a PIN pad. (Default: true).

pinpad_pin_label = label;

The label of the PIN to be entered using the PIN pad.

lock_login = bool;

By default, the OpenSC PKCS#11 module will not lock your card once you authenticate to the card via C_Login (Default: false). Thus the other users or other applications is not prevented from connecting to the card and perform crypto operations (which may be possible because you have already authenticated with the card). This setting is not very secure.

Also, if your card is not locked, you can enconter problems due to limitation of the OpenSC framework, that still is not thoroughly tested in the multi threads environment.

Your settings will be more secure if you choose to lock your card. Nevertheless this behavior is a known violation of PKCS#11 specification. Now once one application has started using your card with C_Login, no other application can use it, until the first is done and calls C_Logout or C_Finalize. In the case of many PKCS#11 application this does not happen until you exit the application.

Thus it is impossible to use several smart card aware applications at the same time, e.g. you cannot run both Firefox and Thunderbird at the same time, if both are configured to use your smart card.

atomic = bool;

By default, interacting with the OpenSC PKCS#11 module may change the state of the token, e.g. whether a user is logged in or not (Default: false).

Thus other users or other applications may change or use the state of the token unknowingly. Other applications may create signatures abusing an existing login or they may logout unnoticed.

With this setting enabled the login state of the token is tracked and cached (including the PIN). Every transaction is preceded by restoring the login state. After every transaction a logout is performed. This setting by default also enables lock_login to disable access for other applications during the atomic transactions.

Please note that any PIN-pad should be disabled (see enable_pinpad), because the user would have to input his PIN for every transaction.

init_sloppy = bool;

With this setting disabled, the OpenSC PKCS#11 module will initialize the slots available when the application calls C_GetSlotList. With this setting enabled, the slots will also get initialized when C_GetSlotInfo is called (Default: true).

This setting is a workaround for Java which does not call C_GetSlotList when configured with a static slot instead of slotListIndex.

user_pin_unblock_style = mode;

User PIN unblock style mode is one of:
•none (Default): PIN unblock is not possible with PKCS#11 API
•set_pin_in_unlogged_session: C_SetPIN in unlogged session: PUK is passed as the OldPin argument of the C_SetPIN call.
•set_pin_in_specific_context: C_SetPIN in the CKU_SPECIFIC_CONTEXT logged session: PUK is passed as the OldPin argument of the C_SetPIN call.
•init_pin_in_so_session: C_InitPIN in CKU_SO logged session: User PIN 'UNBLOCK' is protected by SOPIN. (PUK == SOPIN).

create_puk_slot = bool;

Create slot for unblocking PIN with PUK (Default: false). This way PKCS#11 API can be used to login with PUK and change a PIN. May cause problems with some applications like Firefox and Thunderbird.

create_slots_for_pins = mode...;

Symbolic names of PINs for which slots are created where mode is a list of:
•all (Default): All non-SO-PIN, non-unblocking PINs
•user: The first global or first local PIN
•sign: The second PIN (first local, second global or second local)

Card can contain more then one PINs or more then one on-card application with its own PINs. Normally, to access all of them with the PKCS#11 API a slot has to be created for all of them. Many slots could be annoying for some of widely used application, like FireFox. This configuration parameter allows to select the PIN(s) for which PKCS#11 slot will be created.

Only PINs initialised, non-SO-PIN, non-unblocking are associated with symbolic name.

For the module to simulate the opensc-onepin module behavior the following option create_slots_for_pins = "user";
