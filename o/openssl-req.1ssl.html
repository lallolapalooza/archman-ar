NAME

openssl-req - PKCS#10 certificate request and certificate generating command

SYNOPSIS

openssl req [-help] [-cipher] [-inform DER|PEM] [-outform DER|PEM] [-in filename] [-passin arg] [-out filename] [-passout arg] [-text] [-pubkey] [-noout] [-verify] [-modulus] [-new] [-newkey arg] [-pkeyopt opt:value] [-noenc] [-nodes] [-key filename|uri] [-keyform DER|PEM|P12|ENGINE] [-keyout filename] [-keygen_engine id] [-digest] [-config filename] [-section name] [-x509] [-x509v1] [-CA filename|uri] [-CAkey filename|uri] [-not_before date] [-not_after date] [-days n] [-set_serial n] [-newhdr] [-copy_extensions arg] [-extensions section] [-reqexts section] [-addext ext] [-precert] [-utf8] [-reqopt] [-subject] [-subj arg] [-multivalue-rdn] [-sigopt nm:v] [-vfyopt nm:v] [-batch] [-verbose] [-quiet] [-nameopt option] [-rand files] [-writerand file] [-engine id] [-provider name] [-provider-path path] [-provparam [name:]key=value] [-propquery propq]

DESCRIPTION

This command primarily creates and processes certificate requests (CSRs) in PKCS#10 format. It can additionally create self-signed certificates for use as root CAs for example.

OPTIONS

-help
Print out a usage message.
-inform DER|PEM
The CSR input file format to use; by default PEM is tried first. See openssl-format-options(1) for details.
-outform DER|PEM
The output format; unspecified by default. See openssl-format-options(1) for details.

The data is a PKCS#10 object.

-cipher name
Specify the cipher to be used for encrypting the private key. If no cipher is specified, AES-256-CBC will be used by default. You can override this by providing any valid OpenSSL cipher name.
-in filename
This specifies the input filename to read a request from. This defaults to standard input unless -x509 or -CA is specified. A request is only read if the creation options (-new or -newkey or -precert) are not specified.
-sigopt nm:v
Pass options to the signature algorithm during sign operations. Names and values of these options are algorithm-specific.
-vfyopt nm:v
Pass options to the signature algorithm during verify operations. Names and values of these options are algorithm-specific.
-passin arg
The password source for private key and certificate input. For more information about the format of arg see openssl-passphrase-options(1).
-passout arg
The password source for the output file. For more information about the format of arg see openssl-passphrase-options(1).
-out filename
This specifies the output filename to write to or standard output by default.
-text
Prints out the certificate request in text form.
-subject
Prints out the certificate request subject (or certificate subject if -x509 is in use).
-pubkey
Prints out the public key.
-noout
This option prevents output of the encoded version of the certificate request.
-modulus
Prints out the value of the modulus of the public key contained in the request.
-verify
Verifies the self-signature on the request. If the verification fails, the program will immediately exit, i.e. further option processing (e.g. -text) is skipped.
-new
This option generates a new certificate request. It will prompt the user for the relevant field values. The actual fields prompted for and their maximum and minimum sizes are specified in the configuration file and any requested extensions.

If the -key option is not given it will generate a new private key using information specified in the configuration file or given with the -newkey and -pkeyopt options, else by default an RSA key with 2048 bits length.

-newkey arg
This option is used to generate a new private key unless -key is given. It is subsequently used as if it was given using the -key option.

This option implies the -new flag to create a new certificate request or a new certificate in case -x509 is used.

The argument takes one of several forms.

[rsa:]nbits generates an RSA key nbits in size. If nbits is omitted, i.e., -newkey rsa is specified, the default key size specified in the configuration file with the default_bits option is used if present, else 2048.

All other algorithms support the -newkey algname:file form, where file is an algorithm parameter file, created with "openssl genpkey -genparam" or an X.509 certificate for a key with appropriate algorithm.

param:file generates a key using the parameter file or certificate file, the algorithm is determined by the parameters.

algname[:file] generates a key using the given algorithm algname. If a parameter file file is given then the parameters specified there are used, where the algorithm parameters must match algname. If algorithm parameters are not given, any necessary parameters should be specified via the -pkeyopt option.

dsa:filename generates a DSA key using the parameters in the file filename. ec:filename generates EC key (usable both with ECDSA or ECDH algorithms), gost2001:filename generates GOST R 34.10-2001 key (requires gost engine configured in the configuration file). If just gost2001 is specified a parameter set should be specified by -pkeyopt paramset:X

-pkeyopt opt:value
Set the public key algorithm option opt to value. The precise set of options supported depends on the public key algorithm used and its implementation. See "KEY GENERATION OPTIONS" in openssl-genpkey(1) for more details.
-key filename|uri
This option provides the private key for signing a new certificate or certificate request. Unless -in is given, the corresponding public key is placed in the new certificate or certificate request, resulting in a self-signature.

تنسيق ملف الإعدادات

تُحدَّد خيارات الإعدادات في قسم req من ملف الإعدادات. يمكن تحديد اسم بديل باستخدام خيار -section. كما هو الحال مع جميع ملفات الإعدادات، إذا لم يتم تحديد قيمة في القسم المحدد، يتم البحث أيضًا في القسم الأولي غير المسمى أو قسم default.

الخيارات المتاحة موضحة بالتفصيل أدناه.

input_password, output_password
كلمات المرور لملف المفتاح الخاص المدخل (إذا كان موجودًا) وملف المفتاح الخاص المخرج (إذا تم إنشاء واحد). تتجاوز خيارات سطر الأوامر passin و passout قيم ملف الإعدادات.
default_bits
يحدد حجم المفتاح الافتراضي بالبت.

يُستخدم هذا الخيار بالاقتران مع خيار -new لإنشاء مفتاح جديد. يمكن تجاوزه بتحديد حجم مفتاح صريح في خيار -newkey. أصغر حجم مفتاح مقبول هو 512 بت. إذا لم يتم تحديد حجم مفتاح، فسيتم استخدام 2048 بت.

default_keyfile
هذا هو اسم الملف الافتراضي لكتابة المفتاح الخاص إليه. إذا لم يتم تحديده، يتم كتابة المفتاح إلى الإخراج القياسي. يمكن تجاوز هذا بواسطة خيار -keyout.
oid_file
يحدد هذا ملفًا يحتوي على معرفات الكائنات الإضافية. يجب أن يتكون كل سطر في الملف من الشكل الرقمي لمعرف الكائن متبوعًا بمسافة بيضاء ثم الاسم القصير متبوعًا بمسافة بيضاء وأخيرًا الاسم الطويل.
oid_section
يحدد هذا قسمًا في ملف الإعدادات يحتوي على معرفات كائنات إضافية. يجب أن يتكون كل سطر من الاسم القصير لمعرف الكائن متبوعًا بـ = والشكل الرقمي. الأسماء القصيرة والطويلة متماثلة عند استخدام هذا الخيار.
RANDFILE
عند بدء التشغيل، يتم تحميل الملف المحدد في مولد الأرقام العشوائية، وعند الخروج، سيتم كتابة 256 بايت إليه. يُستخدم لإنشاء المفاتيح الخاصة.
encrypt_key
إذا تم تعيين هذا على no، فعند إنشاء مفتاح خاص، فإنه لا يتم تشفيره. هذا يعادل خيار سطر الأوامر -noenc. للتوافق، يعد encrypt_rsa_key خيارًا مكافئًا.
default_md
يحدد هذا الخيار خوارزمية التجزئة المراد استخدامها. يمكن استخدام أي تجزئة مدعومة بواسطة أمر OpenSSL dgst. يمكن تجاوز هذا الخيار على سطر الأوامر. ستتجاهل بعض خوارزميات التوقيع (مثل Ed25519 و Ed448) أي تجزئة تم تعيينها.
string_mask
يقوم هذا الخيار بحظر استخدام أنواع معينة من السلاسل النصية في حقول معينة. لن يحتاج معظم المستخدمين إلى تغيير هذا الخيار. يمكن تعيينه على عدة قيم:
utf8only - يتم استخدام سلاسل UTF8 فقط (هذه هي القيمة الافتراضية)
pkix - أي نوع سلسلة باستثناء T61Strings
nombstr - أي نوع سلسلة باستثناء BMPStrings و UTF8Strings
default - أي نوع سلسلة

لاحظ أن utf8only هو توصية PKIX في RFC 5280، و string_mask الافتراضي؛ default ليس الخيار الافتراضي. القيمة nombstr هي حل بديل لبعض البرامج التي تواجه مشاكل مع BMPStrings و UTF8Strings ذات الحجم المتغير.

req_extensions
يحدد هذا قسم ملف الإعدادات الذي يحتوي على قائمة بالامتدادات المراد إضافتها إلى طلب الشهادة. يمكن تجاوزه بواسطة مفتاح سطر الأوامر -reqexts (أو -extensions). انظر صفحة الدليل x509v3_config(5) للحصول على تفاصيل تنسيق قسم الامتدادات.
x509_extensions
يحدد هذا قسم ملف الإعدادات الذي يحتوي على قائمة بالامتدادات المراد إضافتها إلى الشهادة التي تم إنشاؤها عند استخدام -x509. يمكن تجاوزه بواسطة مفتاح سطر الأوامر -extensions.
prompt
إذا تم تعيينه على القيمة no، فإنه يعطل المطالبة بحقول الشهادة ويأخذ القيم مباشرة من ملف الإعدادات. كما أنه يغير التنسيق المتوقع لقسمي distinguished_name و attributes.
utf8
إذا تم تعيينه على القيمة yes، فسيتم تفسير قيم الحقول كسلاسل UTF8، افتراضيًا يتم تفسيرها كـ ASCII. هذا يعني أن قيم الحقول، سواء تم مطالبتها من طرفية أو الحصول عليها من ملف إعدادات، يجب أن تكون سلاسل UTF8 صالحة.
attributes
يحدد هذا القسم الذي يحتوي على أي سمات للطلب: تنسيقه هو نفس تنسيق distinguished_name. عادةً ما قد تحتوي هذه على أنواع challengePassword أو unstructuredName. يتم تجاهلها حاليًا بواسطة أدوات توقيع الطلبات في OpenSSL ولكن قد ترغب فيها بعض السلطات المصدقة.
distinguished_name
يحدد هذا القسم الذي يحتوي على حقول الاسم المميز للمطالبة بها عند إنشاء شهادة أو طلب شهادة. يتم وصف التنسيق في القسم التالي.

تنسيق قسم الاسم المميز والسمات

هناك تنسيقان مختلفان لأقسام الاسم المميز والسمات. إذا تم تعيين خيار prompt على no، فإن هذه الأقسام تتكون فقط من أسماء الحقول والقيم: على سبيل المثال،

CN=My Name
OU=My Organization
emailAddress=someone@somewhere.org

يسمح هذا للبرامج الخارجية (مثل البرامج المستندة إلى واجهة المستخدم الرسومية) بإنشاء ملف قالب يحتوي على جميع أسماء الحقول والقيم وتمريره ببساطة إلى هذا الأمر. مثال على هذا النوع من ملفات الإعدادات موجود في قسم أمثلة.

بدلاً من ذلك، إذا كان خيار prompt غائبًا أو لم يتم تعيينه على no، فإن الملف يحتوي على معلومات المطالبة بالحقول. يتكون من أسطر بالشكل:

fieldName="prompt"
fieldName_default="default field value"
fieldName_min= 2
fieldName_max= 4

"fieldName" هو اسم الحقل المستخدم، على سبيل المثال commonName (أو CN). تُستخدم السلسلة "prompt" لمطالبة المستخدم بإدخال التفاصيل ذات الصلة. إذا لم يدخل المستخدم شيئًا، يتم استخدام القيمة الافتراضية؛ إذا لم تكن هناك قيمة افتراضية، يتم حذف الحقل. لا يزال من الممكن حذف الحقل إذا كانت هناك قيمة افتراضية إذا أدخل المستخدم ببساطة حرف ".".

يجب أن يكون عدد الأحرف المدخلة بين حدود fieldName_min و fieldName_max: قد تكون هناك قيود إضافية بناءً على الحقل المستخدم (على سبيل المثال، countryName يمكن أن يكون دائمًا بطول حرفين ويجب أن يتناسب مع PrintableString).

يمكن استخدام بعض الحقول (مثل organizationName) أكثر من مرة في DN. هذا يمثل مشكلة لأن ملفات الإعدادات لن تتعرف على نفس الاسم الذي يظهر مرتين. لتجنب هذه المشكلة، إذا كان fieldName يحتوي على بعض الأحرف متبوعة بنقطة، فسيتم تجاهلها. لذا على سبيل المثال، يمكن إدخال organizationName ثانٍ باستدعائه "1.organizationName".

أسماء الحقول المسموح بها فعليًا هي أي معرفات كائنات قصيرة أو طويلة. هذه مدمجة في OpenSSL وتشمل القيم المعتادة مثل commonName، countryName، localityName، organizationName، organizationalUnitName، stateOrProvinceName. بالإضافة إلى ذلك، يتم تضمين emailAddress، بالإضافة إلى name، surname، givenName، initials، و dnQualifier.

يمكن تعريف معرفات كائنات إضافية باستخدام خيارات oid_file أو oid_section في ملف الإعدادات. سيتم التعامل مع أي حقول إضافية كما لو كانت DirectoryString.

أمثلة

فحص والتحقق من طلب شهادة:

openssl req -in req.pem -text -verify -noout

تحديد خوارزمية التشفير المراد استخدامها لتشفير المفتاح الخاص:

openssl req -newkey rsa:2048 -keyout privatekey.pem -out request.csr -cipher aes-256-cbc

إنشاء مفتاح خاص ثم إنشاء طلب شهادة منه:

openssl genrsa -out key.pem 2048
openssl req -new -key key.pem -out req.pem

نفس الشيء ولكن باستخدام req فقط:

openssl req -newkey rsa:2048 -keyout key.pem -out req.pem

NAME

openssl-req – certificate signing request (CSR) generation, verification and display.

SYNOPSIS

openssl req [options] [-inform PEM|DER|NET] [-outform PEM|DER|NET] [-in filename] [-inany] [-out filename] [-text] [-verify] [-hash] [-modulus] [-pubkey] [-noout] [-schema] [-C] [-config filename] [-passin type:value] [-passout type:value] [-rand file(s)] [-new] [-newkey rsa:bits|dsa:bits|ec] [-nodes] [-key filename] [-keyform PEM|DER|NET] [-key_enc type] [-x509] [-set_serial string] [-set_issuer] [-set_subject] [-subject dn] [-copy_extensions in] [-x509toreq] [-asn1-kludge] [-asn1Dump] [-purpose purpose] [-sigopt <name>:<value>] [-vfyopt <name>:<value>] [-sm3] [-sm3_distid <distid>] [-vfyopt sm3_distid:<distid>] [-addext extnam=value] [-engine id]

DESCRIPTION

The req command is used to manage certificate requests (CSRs). It can be used to generate a new certificate request (and optionally a private key), and to process and display existing certificate requests.

A certificate request contains information about the entity requesting a certificate, and usually includes the entity's public key. The request is sent to a Certificate Authority (CA), which then typically signs the request with its own private key to produce a certificate.

The contents of a certificate request are defined by the PKCS#10 standard.

The req utility can be used in several ways:

  • To generate a new private key and a CSR.
  • To generate a new CSR from an existing private key.
  • To process an existing CSR (verify it, display its contents, etc).
  • To convert a CSR to a self-signed certificate (using the -x509 option).

The exact behaviour of req is controlled by a configuration file (usually named openssl.cnf). The configuration file can be overridden using the -config option. See config(5) for more details on the configuration file format.

A configuration file typically contains sections for default parameters, subject name fields, and certificate extensions.

OPTIONS

-help
Display a usage message and exit.
-in filename
The input filename to read the request from, or standard input if this option is not specified.
-inform PEM|DER|NET
The input format of the data read from the input filename. PEM is the default.
-out filename
The output filename to write the request to, or standard output if this option is not specified.
-outform PEM|DER|NET
The output format: PEM, DER, or NET (a binary format similar to DER). PEM is the default.
-text
Output the request in human-readable text format.
-verify
Verify the signature on the request. This option requires the public key that was used to sign the request.
-hash
Output the "subject key identifier" hash of the public key.
-modulus
Output the modulus of the public key.
-pubkey
Output the public key.
-noout
Do not output the encoded version of the request.
-schema
Output the request in an ASN1 schema format. This is generally not very useful unless you are debugging ASN1 encoding problems.
-C
Output the C code representing the DER-encoded request. This is generally not very useful unless you are debugging ASN1 encoding problems.
-config filename
The configuration file to use.
-passin type:value
The password source for decrypting an encrypted private key. See openssl(1) for details.
-passout type:value
The password source for encrypting an output private key. See openssl(1) for details.
-rand file(s)
A file or list of files containing random data. See openssl(1) for details.
-new
Generate a new certificate request. If this option is present, and -x509 is also present, then a self-signed certificate is generated instead of a certificate request.
-newkey rsa:bits | dsa:bits | ec
Generate a new private key at the same time as the certificate request. The type of key can be rsa, dsa, or ec (elliptic curve). If rsa or dsa is specified, bits is the desired key length (e.g. 2048 for RSA, 1024 or 2048 for DSA). If ec is specified, the elliptic curve can be chosen using the -named_curve option. If no key type is specified, rsa is assumed.
-nodes
If the private key is encrypted, do not encrypt it. This is equivalent to using -passout pass:.
-key filename
The filename containing the private key to use. If this option is omitted, and -newkey is not used, then a key is generated automatically. If the key is encrypted, you will be prompted for a password.
-keyform PEM|DER|NET
The input format of the private key. PEM is the default.
-key_enc type
Specify the encryption type to use when writing an encrypted private key. See openssl(1) for details.
-x509
Output a self-signed certificate instead of a certificate request. This option implies -new.
-set_serial string
Set the serial number for the certificate. The format of the string is a hexadecimal number. This option is only relevant when generating a self-signed certificate using -x509.
-set_issuer
Set the issuer name to be the same as the subject name. This option is only relevant when generating a self-signed certificate using -x509.
-set_subject
Set the subject name to the value specified on the command line using -subject. This option is only relevant when generating a self-signed certificate using -x509.
-subject dn
Set the subject name to the specified Distinguished Name (DN) string. This is used in conjunction with -set_subject and -x509.
-copy_extensions in
Copy extensions from the input certificate request to the output self-signed certificate. This option is only relevant when generating a self-signed certificate using -x509.
-x509toreq
Convert a self-signed certificate into a certificate request. The subject and public key from the certificate are used.
-asn1-kludge
This option implements a workaround for a bug in some older versions of OpenSSL where the attributes field in a certificate request was omitted if it was empty. Normally, an empty attributes field is encoded as 0xa000, but this option will cause it to be omitted entirely.
-asn1Dump
Dump the ASN1 structure of the request in a human-readable format. This is useful for debugging.
-purpose purpose
Set the certificate purpose. This is a comma-separated list of strings that specify the intended use of the certificate. It is often used in conjunction with the -x509 option to set the basicConstraints extension.
-addext extnam=value
Add a certificate extension to the request or certificate. The format is extension_name=value. See the x509v3_config(5) man page for a list of available extensions and their formats.
-engine id
Specify a cryptographic engine to use. See openssl(1) for details.
-sm3
Use the SM3 digest algorithm for SM2 signature generation and verification. This option is only applicable when using SM2 keys.
-sigopt name:value
Pass options to the signature algorithm. For SM2, this can be distid:<value> where value is the 16-byte string used for distinguishing the user. The default value is 1234567812345678.
-vfyopt name:value
Pass options to the signature verification algorithm. For SM2, this can be distid:<value> where value is the 16-byte string used for distinguishing the user. The default value is 1234567812345678.
-sm3_distid distid
Deprecated alias for -sigopt sm3_distid:<value>.
-vfyopt sm3_distid:<distid>
Deprecated alias for -vfyopt distid:<value>.

CONFIGURATION FILE FORMAT

The configuration file for req is an INI-style file. It contains various sections that control the behaviour of req. The most important sections are:

  • [ req ]: This section contains default parameters for the request generation.
  • [ req_distinguished_name ]: This section defines the fields that make up the Distinguished Name (DN) of the request.
  • [ req_attributes ]: This section defines any attributes to be included in the request.
  • [ v3_ca ]: This section defines certificate extensions for a CA certificate.

See the config(5) man page for more details on the configuration file format.

DISTINGUISHED NAME AND ATTRIBUTE SECTION FORMAT

The Distinguished Name and attribute sections have a specific format. Each entry consists of a name, a prompt string (which is displayed if the user is prompted for the value), and optional constraints.

For example:

countryName_default = AU
countryName_min = 2
countryName_max = 2

This defines the countryName field. It defaults to AU, and must be exactly 2 characters long.

Fields can be specified either by their full name (e.g., countryName) or by their short abbreviation (e.g., C). The short abbreviations are defined in the configuration file.

Attributes are similar, but do not form part of the Distinguished Name. An example is challengePassword.

EXAMPLES

Generate an RSA private key and a certificate request:

openssl req -new -newkey rsa:2048 -nodes -keyout key.pem -out req.pem

Generate a certificate request and prompt for all the necessary fields:

openssl req -new -keyout mykey.pem -out myreq.pem

Generate a self-signed certificate:

openssl req -x509 -newkey rsa:2048 -keyout key.pem -out cert.pem -days 365

Generate an SM2 private key and then generate a certificate request from it:

openssl ecparam -genkey -name SM2 -out sm2.key
openssl req -new -key sm2.key -out sm2.csr -sm3 -sigopt "distid:1234567812345678"

Examine and verify an SM2 certificate request:

openssl req -verify -in sm2.csr -sm3 -vfyopt "distid:1234567812345678"

Example of a file pointed to by the oid_file option:

1.2.3.4        shortName       A longer Name
1.2.3.6        otherName       Other longer Name

Example of giving the most common attributes (subject and extensions) on the command line:

openssl req -new -subj "/C=GB/CN=foo" \
                 -addext "subjectAltName = DNS:foo.co.uk" \
                 -addext "certificatePolicies = 1.2.3.4" \
                 -newkey rsa:2048 -keyout key.pem -out req.pem

NOTES

The certificate requests generated by Xenroll with MSIE have extensions added. It includes the keyUsage extension which determines the type of key (signature only or general purpose) and any additional OIDs entered by the script in an extendedKeyUsage extension.

DIAGNOSTICS

The following messages are frequently asked about:

Using configuration from /some/path/openssl.cnf
Unable to load config info

This is followed some time later by:

unable to find 'distinguished_name' in config
problems making Certificate Request

The first error message is the clue: it can't find the configuration file! Certain operations (like examining a certificate request) don't need a configuration file so its use isn't enforced. Generation of certificates or requests however does need a configuration file. This could be regarded as a bug.

Another puzzling message is this:

Attributes:
    a0:00

this is displayed when no attributes are present and the request includes the correct empty SET OF structure (the DER encoding of which is 0xa0 0x00). If you just see:

Attributes:

then the SET OF is missing and the encoding is technically invalid (but it is tolerated). See the description of the command line option -asn1-kludge for more information.

BUGS

OpenSSL's handling of T61Strings (aka TeletexStrings) is broken: it effectively treats them as ISO-8859-1 (Latin 1), Netscape and MSIE have similar behaviour. This can cause problems if you need characters that aren't available in PrintableStrings and you don't want to or can't use BMPStrings.

As a consequence of the T61String handling the only correct way to represent accented characters in OpenSSL is to use a BMPString: unfortunately Netscape currently chokes on these. If you have to use accented characters with Netscape and MSIE then you currently need to use the invalid T61String form.

The current prompting is not very friendly. It doesn't allow you to confirm what you've just entered. Other things like extensions in certificate requests are statically defined in the configuration file. Some of these: like an email address in subjectAltName should be input by the user.

HISTORY

The default encryption cipher was changed from 3DES to AES-256 in OpenSSL 3.5.

The -section option was added in OpenSSL 3.0.0.

The -multivalue-rdn option has become obsolete in OpenSSL 3.0.0 and has no effect.

The -engine option was deprecated in OpenSSL 3.0. The <-nodes> option was deprecated in OpenSSL 3.0, too; use -noenc instead.

The -reqexts option has been made an alias of -extensions in OpenSSL 3.2.

Since OpenSSL 3.2, generated certificates bear X.509 version 3 unless -x509v1 is given, and key identifier extensions are included by default.

Since OpenSSL 3.3, the -verify option will exit with 1 on failure.
