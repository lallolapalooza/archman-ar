الاسم

osm2pgsql-replication - محدث قاعدة بيانات osm2pgsql

الموجز

osm2pgsql-replication {-h | init | update | status} ...

الوصف

تحديث قاعدة بيانات osm2pgsql بالتغييرات من خادم نسخ OSM.

هذه الأداة تهيئ عملية التحديث بالبحث عن ملف الاستيراد
أو أحدث كائن في قاعدة البيانات. يتم بعد ذلك حفظ الحالة في جدول
في قاعدة البيانات. التكرارات اللاحقة تقوم بتنزيل البيانات المتاحة حديثًا وتطبيقها
على قاعدة البيانات.

راجع مساعدة الأمر 'init' و 'update' لمزيد من المعلومات حول
كيفية استخدام osm2pgsql-replication.

الخيارات

الأوامر الفرعية

osm2pgsql-replication init

تهيئة عملية النسخ.
osm2pgsql-replication update

تنزيل البيانات المتاحة حديثًا وتطبيقها على قاعدة البيانات.
osm2pgsql-replication status

طباعة معلومات حول حالة النسخ الحالية، اختياريًا بصيغة JSON.

الخيارات 'osm2pgsql-replication init'

الاستخدام: osm2pgsql-replication init [-h] [-q] [-v] [-d DB] [-U NAME]
[-H HOST] [-P PORT] [-p PREFIX]
[--middle-schema SCHEMA] [--schema SCHEMA]
[--osm-file FILE | --server URL]
[--start-at TIME]

تهيئة عملية النسخ.

تقوم هذه الوظيفة بتعيين خدمة النسخ لاستخدامها وتحديد
من أي تاريخ سيتم تطبيق التحديثات. يجب عليك استدعاء هذه الوظيفة مرة واحدة على الأقل
لإعداد عملية النسخ. يمكن استدعاؤها بأمان مرة أخرى لاحقًا
لتغيير خوادم النسخ أو للتراجع عن عملية التحديث و
إعادة تطبيق التحديثات.

هناك طرق مختلفة متاحة للتهيئة. عندما لا يتم
تقديم معلمات إضافية، يتم تهيئة البيانات من البيانات
في قاعدة البيانات. إذا تم استيراد البيانات من ملف بمعلومات نسخ
وكان جدول الخصائص متاحًا (لـ osm2pgsql >= 1.9)
فستُستخدم عملية النسخ من الملف. خلاف ذلك، تُستخدم خدمة التحديث الدقيقة (minutely)
من openstreetmap.org كخدمة النسخ الافتراضية. يتم أخذ تاريخ البدء إما من طابع زمني لقاعدة البيانات
(لـ osm2pgsql >= 1.9) أو يتم تحديده من أحدث طريقة (way) في قاعدة البيانات
عن طريق الاستعلام عن واجهة برمجة تطبيقات OSM (API) حول تاريخ إنشائها.

يمكن تغيير خدمة النسخ باستخدام المعلمة '--server'.
لاستخدام تاريخ بدء مختلف، أضف '--start-at' مع طابع زمني مطلق
(بتنسيق ISO، على سبيل المثال 2007-08-20T12:21:53Z). عندما تحدد الأداة تاريخ البدء
من الطابع الزمني لقاعدة البيانات أو تاريخ إنشاء الطريقة (way)، فإنها
تطرح 3 ساعات إضافية افتراضيًا لضمان توفر جميع التغييرات الجديدة. لتغيير فترة التراجع هذه، استخدم '--start-at' مع
عدد الدقائق للتراجع. يمكن أيضًا استخدام وضع التراجع هذا لـ
فرض التهيئة لاستخدام تاريخ قاعدة البيانات وتجاهل التاريخ
من معلومات النسخ الموجودة في الملف.

يمكن لعملية التهيئة أيضًا استخدام معلومات النسخ من
ملف OSM مباشرة وتجاهل جميع معلومات التواريخ الأخرى.
استخدم الأمر 'osm2pgsql-replication --osm-file <filename>' لهذا الغرض.

-q, --quiet
طباعة رسائل الخطأ فقط
-v, --verbose
زيادة تفصيل المخرجات
-d DB, --database DB
اسم قاعدة بيانات PostgreSQL للاتصال بها أو سلسلة conninfo
-U NAME, --username NAME
اسم مستخدم PostgreSQL
-H HOST, --host HOST
اسم مضيف خادم قاعدة البيانات أو موقع المقبس
-P PORT, --port PORT
منفذ خادم قاعدة البيانات
-p PREFIX, --prefix PREFIX
بادئة لأسماء الجداول (الافتراضي 'planet_osm')
--middle-schema SCHEMA
اسم المخطط (schema) لتخزين جدول حالة النسخ فيه
--schema SCHEMA
اسم المخطط (schema) لقاعدة البيانات
--osm-file FILE
الحصول على معلومات النسخ من الملف المحدد.
--server URL
استخدام خادم النسخ على عنوان URL المحدد
--start-at TIME
الوقت الذي ستبدأ عنده عملية النسخ. عندما يتم إعطاء طابع زمني مطلق (بتنسيق ISO)، سيتم استخدامه. إذا تم إعطاء رقم، فستبدأ عملية النسخ بعد عدد الدقائق المحدد من التاريخ المعروف لقاعدة البيانات.

الخيارات 'osm2pgsql-replication update'

الاستخدام: osm2pgsql-replication update update [options] [-- param [param ...]]

تنزيل البيانات المتاحة حديثًا وتطبيقها على قاعدة البيانات.

يتم تنزيل البيانات في أجزاء بحجم '--max-diff-size' ميجابايت. يتم حفظ كل جزء
في ملف مؤقت واستيراده باستخدام osm2pgsql من هناك. عادةً ما يتم حذف
الملف المؤقت بعد ذلك ما لم تحدد موقعًا صريحًا باستخدام '--diff-file'. بمجرد أن تكون قاعدة البيانات محدثة مع
مصدر النسخ، تخرج عملية التحديث برمز 0.

يجب تقديم أي حجج إضافية لـ osm2pgsql بعد '--'. يتم
تمرير معلمات قاعدة البيانات والبادئة إلى osm2pgsql. لا تحتاج
إلى تكرارها. سيتم دائمًا إضافة '--append' و '--slim' أيضًا.

استخدم المعلمة '--post-processing' لتنفيذ برنامج نصي بعد تشغيل osm2pgsql
بنجاح. إذا كانت التحديثات تتكون من عدة تشغيلات لأن حجم البيانات التي تم تنزيلها
تم الوصول إليه، فسيتم تنفيذ البرنامج النصي في كل مرة يعمل فيها osm2pgsql. إذا فشل المعالجة اللاحقة،
فستعتبر عملية التحديث بأكملها فاشلة ولن يتم تحديث معلومات النسخ. هذا يعني أنه عندما يتم تشغيل 'update' في المرة التالية،
فسوف تستأنف بتنزيل الاختلافات مرة أخرى وإعادة تطبيقها على
قاعدة البيانات. هذا آمن بشكل عام. يتلقى البرنامج النصي معلمتين:
معرف التسلسل والطابع الزمني لآخر تشغيل ناجح. قد يكون الطابع الزمني مفقودًا في الحالة النادرة التي يتوقف فيها
مصدر النسخ عن الاستجابة بعد تنزيل التحديثات.

param
معلمات إضافية لتمريرها إلى osm2pgsql.
--diff-file FILE
الملف لحفظ التغييرات قبل تطبيقها على osm2pgsql.
--max-diff-size MAX_DIFF_SIZE
الحد الأقصى للبيانات التي سيتم تحميلها بالميجابايت (الافتراضي: 500 ميجابايت)
--osm2pgsql-cmd OSM2PGSQL_CMD
المسار إلى أمر osm2pgsql
--once
تشغيل التحديثات مرة واحدة فقط، حتى عندما تتوفر المزيد من البيانات.
--post-processing SCRIPT
برنامج نصي للمعالجة اللاحقة لتشغيله بعد كل تنفيذ لـ osm2pgsql.
-q, --quiet
طباعة رسائل الخطأ فقط
-v, --verbose
زيادة تفصيل

NAME

osm2pgsql-replication - osm2pgsql replication utility

SYNOPSIS

osm2pgsql-replication init [options]
osm2pgsql-replication update [options]
osm2pgsql-replication status [options]

DESCRIPTION

The osm2pgsql-replication utility is used to update the PostgreSQL database with changes from the openstreetmap replication stream.

It supports three commands:

init
Initializes the replication state table and downloads the initial state file.

usage: osm2pgsql-replication init [-h] [-q] [-v] [-d DB] [-U NAME] [-H HOST]
[-P PORT] [-p PREFIX] [--middle-schema SCHEMA] [--schema SCHEMA]

Initializes the replication state in the database and downloads the initial state file.

update
Downloads the next state file from the replication stream and applies the changes to the database.

usage: osm2pgsql-replication update [-h] [-q] [-v] [-d DB] [-U NAME] [-H HOST]
[-P PORT] [-p PREFIX] [--middle-schema SCHEMA] [--schema SCHEMA]

Applies the next state file from the replication stream to the database.

status
Prints information about the current replication status.

usage: osm2pgsql-replication status [-h] [-q] [-v] [-d DB] [-U NAME] [-H HOST]
[-P PORT] [-p PREFIX] [--middle-schema SCHEMA] [--schema SCHEMA]
[--json]

Prints information about the current replication status, optionally as JSON.

OPTIONS

Common options for all commands:

-h, --help
Show help message and exit.
-q, --quiet
Print only error messages.
-v, --verbose
Increase verboseness of output.
-d DB, --database DB
Name of PostgreSQL database to connect to or conninfo string.
-U NAME, --username NAME
PostgreSQL user name.
-H HOST, --host HOST
Database server host name or socket location.
-P PORT, --port PORT
Database server port.
-p PREFIX, --prefix PREFIX
Prefix for table names (default 'planet_osm').
--middle-schema SCHEMA
Name of the schema to store the table for the replication state in.
--schema SCHEMA
Name of the schema for the database.

OPTIONS 'osm2pgsql-replication status'

usage: osm2pgsql-replication status [-h] [-q] [-v] [-d DB] [-U NAME] [-H HOST]
[-P PORT] [-p PREFIX]
[--middle-schema SCHEMA] [--schema SCHEMA]
[--json]

Print information about the current replication status, optionally as JSON.

Sample output:


2021-08-17 15:20:28 [INFO]: Using replication service 'https://planet.openstreetmap.org/replication/minute', which is at sequence 4675115 ( 2021-08-17T13:19:43Z )
2021-08-17 15:20:28 [INFO]: Replication server's most recent data is <1 minute old
2021-08-17 15:20:28 [INFO]: Local database is 8288 sequences behind the server, i.e. 5 day(s) 20 hour(s) 58 minute(s)
2021-08-17 15:20:28 [INFO]: Local database's most recent data is 5 day(s) 20 hour(s) 59 minute(s) old

With the ’--json’ option, the status is printed as a json object.


{
"server": {
"base_url": "https://planet.openstreetmap.org/replication/minute",
"sequence": 4675116,
"timestamp": "2021-08-17T13:20:43Z",
"age_sec": 27
},
"local": {
"sequence": 4666827,
"timestamp": "2021-08-11T16:21:09Z",
"age_sec": 507601
},
"status": 0
}

’status’ is 0 if there were no problems getting the status. 1 & 2 for
improperly set up replication. 3 for network issues. If status ≠ 0, then
the ’error’ key is an error message (as string). ’status’ is used as the
exit code.

’server’ is the replication server's current status. ’sequence’ is it's
sequence number, ’timestamp’ the time of that, and 'age_sec' the age of the
data in seconds.

’local’ is the status of your server.
