odbx_init(3)

الحزمة: opendbx

التراخيص: LGPL

odbx_init(3) OpenDBX odbx_init(3)

الاسم

odbx_init - تخصيص هياكل بيانات لكل اتصال

ملخص

#include <opendbx/api.h>


int odbx_init
(odbx_t** handle, const char* backend, const char* host, const char* port);

الوصف

يقوم odbx_init() بتخصيص وتهيئة كائن غير شفاف مطلوب لجميع العمليات اللاحقة داخل مكتبة OpenDBX، والذي يستخدم لتحديد الاتصال والحفاظ على معلومات لكل اتصال. اعتمادًا على الواجهة الخلفية، يمكنه فتح اتصال بخادم قاعدة البيانات، ولكن غالبًا ما يتم ذلك فقط عند إجراء المصادقة من خلال odbx_bind().

يتم تخزين مؤشر كائن الاتصال المخصص حديثًا في handle إذا اكتمل odbx_init() بنجاح. بخلاف ذلك، ستكون قيمة متغير handle غير محددة ويجب عدم استخدامها كمدخل لوظائف أخرى في المكتبة. يجب تحرير كائن الاتصال المُرجع بواسطة odbx_finish() لتجنب تسرب الذاكرة إذا لم يعد قيد الاستخدام من قبل التطبيق.

توفر مكتبة OpenDBX الوصول إلى العديد من تطبيقات قواعد البيانات المختلفة من خلال واجهة واحدة، وبالتالي يجب أن تعرف أي من وحدات الواجهة الخلفية المتاحة يجب استخدامها للعمليات. سيتم استخدام المعلمة backend للبحث عن الوحدة المطلوبة. يجب أن تكون سلسلة ASCII مختتمة بصفر وجميع الأحرف بأحرف صغيرة. حاليًا، تتوفر وحدات الواجهة الخلفية التالية:

•
firebird (Firebird/Interbase)
•
mssql (MS SQL Server عبر FreeTDS)
•
mysql (MySQL)
•
oracle (Oracle 8i/9i/10g)
•
pgsql (PostgreSQL)
•
sqlite (SQLite v2)
•
sqlite3 (SQLite v3)
•
sybase (Sybase ASE)

يتطلب الاتصال بخادم قاعدة البيانات على الأقل معرفًا لمعرفة موقع قاعدة البيانات. هناك عدة أنواع من المعرفات مثل أسماء المضيفين وعناوين IP وأنابيب التسمية وما إلى ذلك، والتي يمكن استخدامها. يمكن توفير أحدها عبر المعلمة host، ويعود الأمر إلى مكتبة قاعدة البيانات الأصلية فيما ستقبله. تقبل معظم المكتبات الأصلية على الأقل أسماء المضيفين وعناوين IP، وتستخدم أيضًا المنفذ المقدم في هذه الحالة. طرق المضيف المتاحة هي:

سلسلة اسم المضيف
مدعومة بواسطة واجهات Firebird/Interbase و MySQL و Oracle و PostgreSQL الخلفية
سلسلة عنوان IP
مدعومة بواسطة واجهات Firebird/Interbase و MySQL و Oracle و PostgreSQL الخلفية
المسار المطلق لمقبس نطاق Unix
مدعومة حاليًا بواسطة الواجهة الخلفية PostgreSQL فقط
مسار الدليل (نسبي) مع شرطة مائلة / خلفية
مطلوبة بواسطة واجهات SQLite و SQLite3 الخلفية
اسم القسم في ملف التكوين
مطلوبة بواسطة واجهات MS SQL Server و Sybase ASE الخلفية

اعتمادًا على مكتبة قاعدة البيانات الأصلية، من الممكن أيضًا استخدام قيم افتراضية خاصة بقاعدة البيانات للمعلمات host و port عن طريق توفير سلاسل فارغة مختتمة بصفر أو قيمة NULL.

قيمة الإرجاع

يعيد odbx_init() القيمة ODBX_ERR_SUCCESS، أو رمز خطأ قيمته أقل من الصفر إذا لم تكتمل إحدى العمليات بنجاح. يمكن سرد رموز الأخطاء الممكنة في قسم الأخطاء، ويمكن تغذيتها إلى odbx_error() و odbx_error_type() للحصول على مزيد من التفاصيل.

الأخطاء

-ODBX_ERR_BACKEND
أرجعت الوحدة الخلفية خطأ لأنها لم تتمكن من إعداد الهياكل اللازمة
-ODBX_ERR_PARAM
handle هو NULL ولا يمكن تخزين كائن الاتصال المخصص
-ODBX_ERR_NOMEM
فشل تخصيص ذاكرة جديدة لكائن الاتصال
-ODBX_ERR_SIZE
تجاوز طول سلسلة حجم المخزن المؤقت المتاح
-ODBX_ERR_NOTEXIST
لم يتم العثور على وحدة خلفية بهذا الاسم. إما أن الوحدة غير مثبتة، أو أن الاسم المقدم خاطئ أو ليس في حالة الأحرف الصحيحة
-ODBX_ERR_NOOP
الوحدة الخلفية لا توفر الدالة المطلوبة
