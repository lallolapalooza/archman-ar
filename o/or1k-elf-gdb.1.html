الحزمة: or1k-elf-gdb

التراخيص: GPL3

GDB(1) أدوات تطوير GNU GDB(1)

الاسم

gdb - مصحح GNU

ملخص

gdb [OPTIONS] [prog|prog procID|prog core]

الوصف

الغرض من المصحح مثل GDB هو السماح لك برؤية ما يحدث "داخل" برنامج آخر أثناء تنفيذه -- أو ما كان يفعله برنامج آخر في اللحظة التي تعطل فيها.

يمكن لـ GDB القيام بأربعة أنواع رئيسية من الأشياء (بالإضافة إلى أشياء أخرى لدعم هذه) لمساعدتك في اكتشاف الأخطاء أثناء حدوثها:

  • بدء برنامجك، وتحديد أي شيء قد يؤثر على سلوكه.
  • جعل برنامجك يتوقف عند شروط محددة.
  • فحص ما حدث، عندما يتوقف برنامجك.
  • تغيير الأشياء في برنامجك، حتى تتمكن من تجربة تصحيح آثار خطأ واحد والمضي قدمًا لمعرفة المزيد عن خطأ آخر.

يمكنك استخدام GDB لتصحيح الأخطاء في البرامج المكتوبة بلغات C و C++ و Fortran و Modula-2.

يتم استدعاء GDB بأمر shell "gdb". بمجرد البدء، يقرأ الأوامر من الطرفية حتى تخبره بالخروج باستخدام أمر GDB "quit" أو "exit". يمكنك الحصول على مساعدة عبر الإنترنت من GDB نفسه باستخدام الأمر "help".

يمكنك تشغيل "gdb" بدون وسائط أو خيارات؛ ولكن الطريقة الأكثر شيوعًا لبدء GDB هي باستخدام وسيط واحد أو وسيطين، وتحديد برنامج قابل للتنفيذ كوسيط:

gdb program

يمكنك أيضًا البدء بتحديد برنامج قابل للتنفيذ وملف أساسي:

gdb program core

يمكنك، بدلاً من ذلك، تحديد معرف عملية كوسيط ثانٍ أو استخدام الخيار "-p"، إذا كنت تريد تصحيح أخطاء عملية قيد التشغيل:

gdb program 1234
gdb -p 1234

سيؤدي ذلك إلى ربط GDB بالعملية 1234. مع الخيار -p، يمكنك حذف اسم ملف program.

فيما يلي بعض أوامر GDB الأكثر احتياجًا:

break [file:][function|line]
ضع نقطة توقف عند function أو line (في file).
run [arglist]
ابدأ برنامجك (مع arglist، إذا تم تحديده).
bt
تتبع الخلف: عرض مكدس البرنامج.
print expr
عرض قيمة تعبير.
c
استمر في تشغيل برنامجك (بعد التوقف، على سبيل المثال عند نقطة توقف).
next
نفذ السطر التالي من البرنامج (بعد التوقف)؛ تجاوز استدعاءات الدوال في السطر.
edit [file:]function
انظر إلى سطر البرنامج حيث يتوقف حاليًا.
list [file:]function
اكتب نص البرنامج بالقرب من المكان الذي يتوقف فيه حاليًا.
step
نفذ السطر التالي من البرنامج (بعد التوقف)؛ ادخل إلى استدعاءات الدوال في السطر.
help [name]
عرض معلومات حول أمر GDB name، أو معلومات عامة حول استخدام GDB.
quit
exit
الخروج من GDB.

للحصول على تفاصيل كاملة حول GDB، انظر Using GDB: A Guide to the GNU Source-Level Debugger، بواسطة Richard M. Stallman و Roland H. Pesch. نفس النص متاح عبر الإنترنت كإدخال "gdb" في برنامج "info".

الخيارات

أي وسائط بخلاف الخيارات تحدد ملفًا قابلاً للتنفيذ وملفًا أساسيًا (أو معرف عملية)؛ أي، الوسيط الأول الذي تم العثور عليه بدون علامة خيار مرتبطة به يعادل خيار --se، والوسيط الثاني، إن وجد، يعادل خيار -c إذا كان اسم ملف. العديد من الخيارات لها أشكال طويلة وقصيرة؛ كلاهما معروض هنا. الأشكال الطويلة يتم التعرف عليها أيضًا إذا قمت باختصارها، طالما أن ما يكفي من الخيار موجود ليكون غير مبهم.

تُظهر الأشكال المختصرة هنا مع - وتُظهر الأشكال الطويلة مع -- لتعكس كيف تظهر في --help. ومع ذلك، يتعرف GDB على جميع اتفاقيات البناء التالية لمعظم الخيارات:

"--option=value"
"--option value"
"-option=value"
"-option value"
"--o=value"
"--o value"
"-o=value"
"-o value"

يتم معالجة جميع الخيارات ووسائط سطر الأوامر التي تقدمها بترتيب تسلسلي. الترتيب مهم عند استخدام الخيار -x.

--help
-h
قائمة بجميع الخيارات، مع شروحات موجزة.
--symbols=file
-s file
قراءة جدول الرموز من file.
--write
تمكين الكتابة في الملفات القابلة للتنفيذ والملفات الأساسية.
--exec=file
-e file
استخدم file كملف قابل للتنفيذ لتشغيله عند الاقتضاء، ولفحص البيانات البحتة بالاقتران مع تفريغ أساسي.
--se=file
قراءة جدول الرموز من file واستخدامه كملف قابل للتنفيذ.
--core=file
-c file
استخدم file كتفريغ أساسي للفحص.
--command=file
-x file
تنفيذ أوامر GDB من file.
--eval-command=command
-ex command
تنفيذ أمر GDB المحدد command.
--init-eval-command=command
-iex
تنفيذ أمر GDB command قبل تحميل البرنامج الفرعي.
--directory=directory
-d directory
إضافة directory إلى المسار للبحث عن ملفات المصدر.
--nh
لا تقم بتنفيذ الأوامر من ~/.config/gdb/gdbinit، ~/.gdbinit، ~/.config/gdb/gdbearlyinit، أو ~/.gdbearlyinit
--nx
-n
لا تقم بتنفيذ الأوامر من أي ملفات تهيئة .gdbinit أو .gdbearlyinit.
--quiet
--silent
-q
"صامت". لا تطبع رسائل المقدمة وحقوق النشر. يتم أيضًا منع هذه الرسائل في وضع الدفعة.
--batch
تشغيل في وضع الدفعة. الخروج بحالة 0 بعد معالجة جميع ملفات الأوامر المحددة باستخدام -x (و .gdbinit، إذا لم يتم تثبيطه). الخروج بحالة غير صفرية إذا حدث خطأ في تنفيذ أوامر GDB في ملفات الأوامر.

NAME gdb - The GNU Project Debugger
SYNOPSIS gdb [] [] [] [] [] [pid] [] [] [] [] [] [] [directory] [directory] [] [] [ baudrate] [ timeout] [device] [] [] [] [] [] [pid] [] [] [] [] [] [] [directory] [directory] [] [device] [ [ ...]] [corefile] [ corefile] [symbolfile] [ symbolfile] [num] [ num] [executable] [symbolfile] [pid] [pid] [expr] []
DESCRIPTION GDB, the GNU Project Debugger, allows you to see what is going on inside another program while it executes or what another program was doing at the time it crashed. You can do things like: Start your program, specifying anything that might affect its behavior. Make your program stop on some kinds of errors, or on commands you, the programmer, specify. Examine what has happened, when your program has stopped: where it is, the values of its variables, and so forth. Change your program's variables, and in general, modify its environment, so you can experiment with correcting the effects of one bug and go on to detect the next one. As GDB runs, it processes commands you enter interactively. GDB also offers commands to control GDB itself, for example, to define what information is printed. GDB also has a sophisticated interface to Emacs which allows you to edit code, run GDB, and view GDB variables all in one place. This document details the command-line options for GDB. For more information on using GDB interactively, please consult the GDB manual.
OPTIONS The following options are available for invoking GDB. -help --help Print a summary of the command-line options, and exit. -nx --nx Do not read any initialization files. -batch --batch Run in batch mode. This is useful for invoking GDB from a script. GDB will not be interactive; it will exit when it has finished all of its commands. If the input is coming from a file (or via redirection), GDB will exit with the status reported by the exit code of the inferior. For example, if the program exits normally, GDB will exit with status 0. If the program terminated abnormally, GDB will exit with status 1. If the GDB script itself had errors, GDB will exit with status 2. This is not intended for running GDB on another computer; in order to make this more useful, the message Program exited normally. (which is ordinarily issued whenever a program running under GDB control terminates) is not issued when running in batch mode. --batch-silent Run in batch mode, just like , but totally silent. All GDB output is suppressed (stderr is unaffected). This is much quieter than and would be useless for an interactive session. This is particularly useful when using targets that give Loading section messages, for example. Note that targets that give their output via GDB, as opposed to writing directly to stdout, will also be made silent. --args prog [ arglist ] Change interpretation of command line so that arguments following this option are passed as arguments to the inferior. As an example, take the following command: gdb ./a.out -q It would start GDB with , not printing the introductory message. On the other hand, using: gdb --args ./a.out -q starts GDB with the introductory message, and passes the option to the inferior. --pid=pid Attach GDB to an already running program, with the PID pid. --tui Open the terminal user interface. --readnow Read all symbols from the given symfile on the first access. --readnever Do not read symbol files. --return-child-result GDB's exit code will be the same as the child's exit code. --configuration Print details about GDB configuration and then exit. --version Print version information and then exit. --cd=directory Run GDB using directory as its working directory, instead of the current directory. --data-directory=directory -D Run GDB using directory as its data directory. The data directory is where GDB searches for its auxiliary files. --fullname -f Emacs sets this option when it runs GDB as a subprocess. It tells GDB to output the full file name and line number in a standard, recognizable fashion each time a stack frame is displayed (which includes each time the program stops). This recognizable format looks like two \032 characters, followed by the file name, line number and character position separated by colons, and a newline. The Emacs-to-GDB interface program uses the two \032 characters as a signal to display the source code for the frame. -b baudrate Set the line speed (baud rate or bits per second) of any serial interface used by GDB for remote debugging. -l timeout Set timeout, in seconds, for remote debugging. --tty=device Run using device for your program's standard input and output.
