الوصف

برنامج ovsdb-client هو عميل سطر أوامر للتفاعل مع عملية ovsdb-server قيد التشغيل. يتصل كل أمر بـ OVSDB server المحدد، والذي قد يكون طريقة اتصال نشطة أو سلبية لـ OVSDB، كما هو موضح في ovsdb(7). الخادم الافتراضي هو unix:/run/openvswitch/db.sock و database الافتراضي هو Open_vSwitch.

يدعم ovsdb-client بناء الجملة method1,method2,...,methodN الموصوف في ovsdb(7) للاتصال بكتلة. عند استخدام هذا البناء، يحاول ovsdb-client أعضاء الكتلة بترتيب عشوائي حتى يجد قائد الكتلة. حدد الخيار --no-leader-only لقبول أي خادم متصل بالكتلة بدلاً من ذلك.

للاطلاع على مقدمة حول OVSDB وتنفيذه في Open vSwitch، راجع ovsdb(7).

الأقسام التالية تصف الأوامر التي يدعمها ovsdb-client.

أوامر مستوى الخادم

تعمل معظم أوامر ovsdb-client مع قاعدة بيانات فردية، ولكن هذه الأوامر تنطبق على خادم قاعدة بيانات بأكمله.

list-dbs [server]
يتصل بـ server، ويسترد قائمة قواعد البيانات المعروفة، ويطبعها سطرًا واحدًا لكل منها. هذه الأسماء لقاعدة البيانات هي التي قد تستخدمها الأوامر الأخرى لـ database.

أوامر مخطط قاعدة البيانات

تحصل هذه الأوامر على المخطط من قاعدة بيانات وتطبعه أو جزءًا منه.

get-schema [server] [database]
يتصل بـ server، ويسترد مخطط database، ويطبعه بتنسيق JSON.
list-tables [server] [database]
يتصل بـ server، ويسترد مخطط database، ويطبع جدولًا يسرد اسم كل جدول داخل قاعدة البيانات.
list-columns [server] [database] table
يتصل بـ server، ويسترد مخطط database، ويطبع جدولًا يسرد اسم ونوع كل عمود. إذا تم تحديد table، فسيتم سرد الأعمدة في هذا الجدول فقط؛ وإلا، فإن الجداول تشمل الأعمدة في جميع الجداول.

أوامر إدارة إصدار قاعدة البيانات

يمتلك مخطط OVSDB رقم إصدار مخطط، وتتضمن قاعدة بيانات OVSDB إصدارًا معينًا من مخطط OVSDB. تتخذ أرقام الإصدارات هذه شكل x.y.z، على سبيل المثال 1.2.3. لا يفرض تنفيذ OVSDB مخطط ترقيم إصدار معين، ولكن المخططات التي تتم إدارتها ضمن مشروع Open vSwitch تستخدم النهج التالي. كلما تم تغيير مخطط قاعدة البيانات بطريقة غير متوافقة مع الإصدارات السابقة (مثل حذف عمود أو جدول)، يتم زيادة x (ويتم إعادة تعيين y و z إلى 0). عندما يتم تغيير مخطط قاعدة البيانات بطريقة متوافقة مع الإصدارات السابقة (مثل إضافة عمود جديد)، يتم زيادة y (ويتم إعادة تعيين z إلى 0). عندما يتم تغيير مخطط قاعدة البيانات بشكل تجميلي (مثل إعادة تنسيق بناء الجملة الخاص به)، يتم زيادة z.

بعض قواعد بيانات OVSDB ومخططاتها، وخاصة القديمة جدًا، لا تحتوي على رقم إصدار.

أرقام إصدار المخطط وأرقام إصدار Open vSwitch مستقلة.

تعمل هذه الأوامر مع إصدارات مختلفة من مخططات وقواعد بيانات OVSDB.

convert [server] schema
يحول schema إلى شكل يتوافق مع ما يتوقعه server، ويطبع النتيجة بتنسيق JSON. يجب أن يكون schema إما اسم مخطط OVSDB (مثل Open_vSwitch) أو ملف JSON يصف مخطط OVSDB.

عند استدعائه بدون database، يتم افتراض schema بأنه يمثل قاعدة بيانات Open vSwitch.

needs-conversion [server] schema
يقارن schema مع المخطط المستخدم بواسطة server. إذا كان المخطط المقدم يختلف عن مخطط الخادم، يطبع ovsdb-client مخرجات JSON تصف التحويل المطلوب. وإلا، فإنها تنتج مخرجات فارغة.

عند استدعائه بدون database، يتم افتراض schema بأنه يمثل قاعدة بيانات Open vSwitch.

get-schema-version [server] [database]
يتصل بـ server، ويسترد مخطط database، ويطبع رقم إصدار المخطط الخاص به. إذا لم يكن لقاعدة البيانات رقم إصدار، فلن يتم طباعة أي شيء.

أوامر إدارة البيانات

تتفاعل هذه الأوامر مع البيانات الموجودة في جداول قاعدة بيانات OVSDB.

transact [server] transaction
ينفذ transaction على server.

transaction هو قائمة بعمليات OVSDB، مفصولة بفواصل. كل عملية لها صيغة JSON محددة. راجع ovsdb(7) للحصول على تفاصيل.

افتراضيًا، يطبع ovsdb-client نتيجة المعاملة بتنسيق JSON. ومع ذلك، إذا فشلت المعاملة، فإنها تنتج خطأ. لتجنب هذا، يمكنك استخدام query بدلاً من ذلك.

query [server] transaction
مثل transact، ولكنها لا تنتج خطأ عند فشل المعاملة. بدلاً من ذلك، تطبع مخرجات JSON تحتوي على وصف للخطأ.
dump [server] [database] [table [column...]]
يطبع جميع الصفوف في table أو جميع الصفوف والأعمدة المحددة في table. إذا لم يتم تحديد table، يتم طباعة جميع الجداول. إذا لم يتم تحديد database، يتم افتراض Open_vSwitch.
backup [server] [database] > snapshot
يكتب لقطة كاملة لقاعدة البيانات database إلى snapshot. snapshot هو ملف.

افتراضيًا، تكون لقطات النسخ الاحتياطي بتنسيق JSON.

restore [server] [database] < snapshot
يستعيد قاعدة البيانات database من snapshot.

إذا تم توفير --force، يتم استعادة قاعدة البيانات حتى لو كانت تحتوي على بيانات موجودة.

يجب أن يكون snapshot ملفًا تم إنشاؤه بواسطة backup.

monitor [server] [database] table [column[,column]...]...
ينشئ مراقبًا لـ table في database على server. تقوم ovsdb-client بطباعة إشعارات كلما تغيرت الصفوف التي تطابقها مواصفات المراقبة.

column[,column]... هي قائمة بالأعمدة المراد تتبعها. إذا تم حذفها، يتم تتبع جميع الأعمدة.

عندما تكون table هي ALL، يقوم monitor بتتبع جميع الجداول في قاعدة البيانات.

يقوم monitor بطباعة رسائل JSON لكل تحديث.

monitor-cond [server] [database] conditions table [column[,column]...]...
مثل monitor، ولكن يتم تطبيق conditions على الصفوف التي يتم مراقبتها.

conditions هو تعبير OVSDB Boolean. راجع ovsdb(7) للحصول على تفاصيل.

monitor-cond-since [server] [database] [last-id] conditions table [column[,column]...]...
مثل monitor-cond، ولكنها تبدأ المراقبة من last-id المحدد، والذي يتم استرداده عادةً من سجل monitor السابق. هذا يضمن عدم تفويت التحديثات.
wait [server] database state
ينتظر حتى تصل database على server إلى state المحدد. state هو سلسلة JSON تصف حالة قاعدة البيانات المطلوبة.

على سبيل المثال، للانتظار حتى تحتوي قاعدة البيانات Open_vSwitch على جدول Bridge يحتوي على صف واحد على الأقل، يمكنك استخدام: 

ovsdb-client wait \
    --format=json --data=bare \
    -- --id=@b bridge/name=br0 -- \
    --columns=name --format=json --data=bare \
    -- --id=@n \
    -- on_change=@n "SELECT 1 FROM bridge WHERE uuid = @b"
    $ovsdb-client wait unix:/var/run/openvswitch/db.sock \
        Open_vSwitch \
        '{"columns": {"Bridge": {"op": "==", "operand": ["br0"]}}}'

أوامر الاختبار

تسمح هذه الأوامر بالحصول على أقفال وإلغاء أقفال في قاعدة البيانات.

lock [server] lock
يحصل على lock المحدد على server. إذا كان القفل غير متوفر، فإن ovsdb-client ينتظر حتى يصبح متاحًا.
steal [server] lock
يحصل على lock المحدد على server، حتى لو كان مستخدمًا بالفعل. هذا يمكن أن يؤدي إلى فقدان البيانات إذا كان هناك عميل آخر يستخدم القفل.
unlock [server] lock
يحرر lock المحدد على server.

أوامر أخرى

help
يطبع رسالة مساعدة مفصلة.

خيارات الكتلة

--no-leader-only
عند الاتصال بكتلة OVSDB، لا تحاول الاتصال بقائد الكتلة. بدلاً من ذلك، اتصل بأي عضو في الكتلة.

خيارات تنسيق الإخراج

--format=format
يحدد تنسيق الإخراج. التنسيقات المدعومة هي json، csv، table (افتراضي)، و line.
--data=format
يحدد تنسيق بيانات الإخراج. التنسيقات المدعومة هي json، csv، table (افتراضي)، و line.
--no-headings
لا تطبع رؤوس الأعمدة.
--pretty
يطبع إخراج JSON بتنسيق سهل القراءة.
--bare
يطبع فقط البيانات، بدون أي معلومات تعريفية.
--timestamp
يطبع طابعًا زمنيًا قبل كل سطر إخراج.

خيارات الخادم

--pidfile[=pidfile]
ينشئ ملف PID في pidfile. إذا لم يتم تحديد pidfile، فسيتم استخدامه /run/openvswitch/ovsdb-server.pid.
--overwrite-pidfile
إذا كان ملف PID موجودًا بالفعل، فسيتم استبداله. قد يكون هذا مفيدًا إذا تم إنهاء عملية ovsdb-server بطريقة غير طبيعية.
--detach
يقوم بفصل الخادم عن وحدة التحكم بعد تشغيله.
--no-chdir
لا تقم بتغيير دليل العمل إلى الدليل الجذر.
--no-self-confinement
لا تقم بتقييد الخادم إلى دليل العمل.

خيارات التسجيل

-v[module[:destination[:level]]]
تنشيط التسجيل لمكون معين. يمكن تحديد module، destination (مثل syslog أو console)، و level (مثل dbg، info، warn، err). إذا تم حذف module، فسيتم تطبيق الإعداد على جميع المكونات. إذا تم حذف destination، فسيتم استخدامه syslog. إذا تم حذف level، فسيتم استخدام info.
--verbose[=module[:destination[:level]]]]
نفس -v.
--log-file[=file]
اكتب سجلات إلى file. إذا لم يتم تحديد file، فسيتم استخدامه /var/log/openvswitch/ovsdb-server.log.

خيارات البنية التحتية للمفاتيح العامة

--private-key=privkey.pem
حدد ملف المفتاح الخاص SSL/TLS.
--certificate=cert.pem
حدد ملف الشهادة SSL/TLS.
--ca-cert=cacert.pem
حدد ملف شهادة CA SSL/TLS.
--bootstrap-ca-cert=cacert.pem
حدد ملف شهادة CA SSL/TLS لـ bootstrap.

خيارات اتصال SSL/TLS

--ssl-protocols=protocols
حدد بروتوكولات SSL/TLS المسموح بها (مثل TLSv1.2,TLSv1.3).
--ssl-ciphers=ciphers
حدد خوارزميات التشفير SSL/TLS المسموح بها (مثل high).
--ssl-ciphersuites=ciphersuites
حدد مجموعات التشفير SSL/TLS المسموح بها (مثل e3d3c2e3-23d3-4e3d-3a3d-3e3d3a3d3e3d).

خيارات إعادة التشغيل

--record[=directory]
قم بتسجيل جميع الاتصالات التي يقوم بها ovsdb-client في directory. يستخدم هذا لتسجيل حركة مرور الشبكة للاختبار.
--replay[=directory]
قم بإعادة تشغيل جميع الاتصالات المسجلة من directory. يستخدم هذا لاختبار سلوك ovsdb-client دون الحاجة إلى خادم حقيقي.

خيارات شائعة

-h | --help
اطبع رسالة مساعدة موجزة ثم اخرج.
-V | --version
اطبع معلومات الإصدار ثم اخرج.
