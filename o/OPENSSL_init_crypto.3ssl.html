OPENSSL_init_crypto(3ssl)

الحزمة: openssl

التراخيص: Apache-2.0

OPENSSL_init_crypto
Initializes the OpenSSL library's crypto component. See DESCRIPTION for more information. This function may be called multiple times, but should only be called once per application initialization.
OPENSSL_init_ssl
Initializes the OpenSSL library's SSL component. See DESCRIPTION for more information. This function may be called multiple times, but should only be called once per application initialization.
OPENSSL_cleanup
Deinitializes the OpenSSL library's crypto and SSL components. See DESCRIPTION for more information.
OPENSSL_thread_stop
Deallocates resources associated with the current thread for the default OSSL_LIB_CTX. See DESCRIPTION for more information.
OPENSSL_thread_stop_ex
Deallocates resources associated with the current thread for the given OSSL_LIB_CTX. See DESCRIPTION for more information.
OPENSSL_atexit
Registers a function to be called during OPENSSL_cleanup. See DESCRIPTION for more information.
OPENSSL_INIT_new
Allocates an OPENSSL_INIT_SETTINGS object. See DESCRIPTION for more information.
OPENSSL_INIT_free
Frees an OPENSSL_INIT_SETTINGS object. See DESCRIPTION for more information.
OPENSSL_INIT_set_config_filename
Sets the configuration filename for the OPENSSL_INIT_SETTINGS object. See DESCRIPTION for more information.
OPENSSL_INIT_set_config_appname
Sets the application name for the OPENSSL_INIT_SETTINGS object. See DESCRIPTION for more information.
OPENSSL_INIT_set_file_flags
Sets the configuration file flags for the OPENSSL_INIT_SETTINGS object. See DESCRIPTION for more information.

قد يتم دمج خيارات متعددة معًا في استدعاء واحد لـ OPENSSL_init_crypto(). على سبيل المثال:

OPENSSL_init_crypto(OPENSSL_INIT_NO_ADD_ALL_CIPHERS
                    | OPENSSL_INIT_NO_ADD_ALL_DIGESTS, NULL);

تقوم الدالة OPENSSL_cleanup() بإلغاء تهيئة OpenSSL (لكل من libcrypto و libssl). يتم تحرير جميع الموارد التي خصصتها OpenSSL. عادةً لا تكون هناك حاجة لاستدعاء هذه الدالة مباشرة حيث يتم بدء تشغيلها تلقائيًا عند خروج التطبيق. يتم ذلك عبر الدالة القياسية لمكتبة C atexit(). في حالة إغلاق التطبيق بطريقة لا تستدعي معالجات atexit() المسجلة، فيجب على التطبيق استدعاء OPENSSL_cleanup() مباشرة. يُثبط للمطورين الذين يستخدمون مكتبات تعتمد على OpenSSL استدعاء هذه الدالة، وبدلاً من ذلك، يجب عليهم عادةً الاعتماد على إلغاء التهيئة التلقائي. هذا لتجنب حالات الخطأ حيث يستخدم كل من التطبيق والمكتبة التي يعتمد عليها OpenSSL، وتقوم المكتبة بإلغاء تهيئته قبل انتهاء التطبيق من استخدامه.

بمجرد استدعاء OPENSSL_cleanup()، لا يمكن إعادة تهيئة المكتبة. ستفشل محاولات استدعاء OPENSSL_init_crypto() وسيتم إضافة خطأ ERR_R_INIT_FAIL إلى مكدس الأخطاء. لاحظ أنه نظرًا لفشل التهيئة، لن تكون سلاسل أخطاء OpenSSL متاحة، فقط رمز خطأ. يمكن تمرير هذا الرمز إلى تطبيق سطر الأوامر openssl errstr لإنتاج خطأ قابل للقراءة (انظر openssl-errstr(1)).

تتيح الدالة OPENSSL_atexit() تسجيل دالة ليتم استدعاؤها أثناء OPENSSL_cleanup(). يتم استدعاء معالجات الإيقاف بعد إلغاء تهيئة الموارد الخاصة بالخيط، ولكن قبل تحرير الموارد الأخرى الخاصة بالعملية. في حالة تسجيل معالجات إيقاف متعددة، لا توجد ضمانات بشأن ترتيب التنفيذ.

تقوم الدالة OPENSSL_thread_stop_ex() بإلغاء تخصيص الموارد المرتبطة بالخيط الحالي لـ OSSL_LIB_CTX المحدد ctx. يمكن أن يكون المعامل ctx NULL، وفي هذه الحالة يتم استخدام OSSL_LIB_CTX الافتراضي.

عادةً، سيتم استدعاء هذه الدالة تلقائيًا بواسطة المكتبة عند انتهاء الخيط، طالما لم يتم تحرير OSSL_LIB_CTX قبل انتهاء الخيط. إذا تم استدعاء OSSL_LIB_CTX_free()، فسيتم استدعاء OPENSSL_thread_stop_ex تلقائيًا للخيط الحالي (ولكن ليس لأي خيوط أخرى ربما استخدمت OSSL_LIB_CTX هذا).

يجب استدعاء OPENSSL_thread_stop_ex على جميع الخيوط التي ستنتهي بعد تحرير OSSL_LIB_CTX. عادةً، لا يكون هذا ضروريًا لـ OSSL_LIB_CTX الافتراضي (لأن جميع الموارد يتم تنظيفها عند خروج المكتبة) إلا إذا كان يجب تحرير الموارد المحلية للخيط قبل خروج المكتبة، أو في الظروف الموضحة في قسم الملاحظات أدناه.

OPENSSL_thread_stop() هي نفس OPENSSL_thread_stop_ex() باستثناء أنه يتم دائمًا استخدام OSSL_LIB_CTX الافتراضي.

سيقوم العلم OPENSSL_INIT_LOAD_CONFIG بتحميل ملف تكوين، كما هو الحال مع CONF_modules_load_file(3) مع اسم ملف NULL واسم تطبيق NULL والأعلام CONF_MFLAGS_IGNORE_MISSING_FILE و CONF_MFLAGS_IGNORE_RETURN_CODES و CONF_MFLAGS_DEFAULT_SECTION. يمكن تخصيص اسم الملف واسم التطبيق والأعلام بتوفير كائن OPENSSL_INIT_SETTINGS غير فارغ. يمكن تخصيص الكائن عبر OPENSSL_INIT_new(). يمكن استخدام الدالة OPENSSL_INIT_set_config_filename() لتحديد اسم ملف غير افتراضي، والذي يتم نسخه ولا يحتاج إلى الإشارة إلى تخزين دائم. وبالمثل، يمكن استخدام OPENSSL_INIT_set_config_appname() لتحديد اسم تطبيق غير افتراضي. أخيرًا، يمكن استخدام OPENSSL_INIT_set_file_flags لتحديد أعلام غير افتراضية. إذا لم يتم تضمين العلم CONF_MFLAGS_IGNORE_RETURN_CODES، فإن أي أخطاء في ملف التكوين ستتسبب في خطأ إرجاع من OPENSSL_init_crypto أو بشكل غير مباشر من OPENSSL_init_ssl(3). يمكن تحرير الكائن باستخدام OPENSSL_INIT_free() عند الانتهاء. إذا كان الوسيط لـ OPENSSL_INIT_free() هو NULL، فلا يتم فعل شيء.

ملاحظات

يتم إلغاء تخصيص الموارد المحلية للخيط تلقائيًا عند انتهاء الخيط (على سبيل المثال، في بيئة pthreads، عند استدعاء pthread_exit()). في منصات Windows، يتم ذلك استجابةً لرسالة DLL_THREAD_DETACH مرسلة إلى نقطة دخول libcrypto32.dll. قد تتسبب بعض وظائف Windows في إنهاء الخيوط دون إرسال هذه الرسالة (على سبيل المثال ExitProcess()). إذا استخدم التطبيق مثل هذه الوظائف، فيجب على التطبيق تحرير موارد OpenSSL مباشرةً عبر استدعاء OPENSSL_thread_stop() على كل خيط. وبالمثل، لن يتم إرسال هذه الرسالة إذا تم ربط OpenSSL بشكل ثابت، وبالتالي يجب على التطبيقات التي تستخدم الربط الثابت أيضًا استدعاء OPENSSL_thread_stop() على كل خيط. بالإضافة إلى ذلك، إذا تم تحميل OpenSSL ديناميكيًا عبر LoadLibrary() ولم يتم تدمير الخيوط حتى بعد استدعاء FreeLibrary()، فيجب على كل خيط استدعاء OPENSSL_thread_stop() قبل استدعاء FreeLibrary().

على Linux/Unix حيث تم تحميل OpenSSL عبر dlopen() وكان التطبيق متعدد الخيوط وتم استدعاء dlclose() لاحقًا قبل تدمير الخيوط، فلن تتمكن OpenSSL من إلغاء تخصيص الموارد المرتبطة بتلك الخيوط. يجب على التطبيق إما استدعاء OPENSSL_thread_stop() على كل خيط قبل استدعاء dlclose()، أو بدلاً من ذلك، يجب أن يستخدم استدعاء dlopen() الأصلي العلم RTLD_NODELETE (حيثما كان متاحًا على المنصة).

قيم الإرجاع

تُرجع الدوال OPENSSL_init_crypto، OPENSSL_atexit()، و OPENSSL_INIT_set_config_appname() القيمة 1 عند النجاح أو 0 عند حدوث خطأ.
