stat(2) دليل استدعاءات النظام stat(2)

الاسم

stat, fstat, lstat, fstatat - الحصول على حالة الملف

المكتبة

مكتبة C القياسية (libc, -lc)

الملخص

#include <sys/stat.h>
int stat(const char *restrict path,
         struct stat *restrict statbuf);
int fstat(int fd, struct stat *statbuf);
int lstat(const char *restrict path,
         struct stat *restrict statbuf);
#include <fcntl.h>           /* تعريف ثوابت AT_* */
#include <sys/stat.h>
int fstatat(int dirfd, const char *restrict path,
         struct stat *restrict statbuf, int flags);

الوصف

تقوم هذه الاستدعاءات بإرجاع معلومات حول ملف، في المخزن المؤقت الذي يشير إليه statbuf. لا يلزم وجود أذونات على الملف نفسه، ولكن - في حالة stat() وfstatat() وlstat() - يلزم وجود إذن تنفيذ (بحث) على جميع الدلائل في path التي تؤدي إلى الملف.

stat() وfstatat() تسترجعان معلومات حول الملف الذي يشير إليه path؛ الاختلافات لـ fstatat() موضحة أدناه.

lstat() متطابقة مع stat()، باستثناء أنه إذا كان path عبارة عن رابط رمزي، فإنها ترجع معلومات حول الرابط نفسه، وليس الملف الذي يشير إليه الرابط.

fstat() متطابقة مع stat()، باستثناء أن الملف الذي يتم استرداد المعلومات حوله يتم تحديده بواسطة واصف الملف fd.

هيكل stat

تقوم جميع استدعاءات النظام هذه بإرجاع هيكل stat (انظر stat(3type)).

ملاحظة: لأسباب تتعلق بالأداء والبساطة، قد تحتوي الحقول المختلفة في هيكل stat على معلومات حالة من لحظات مختلفة أثناء تنفيذ استدعاء النظام. على سبيل المثال، إذا تم تغيير st_mode أو st_uid بواسطة عملية أخرى عن طريق استدعاء chmod(2) أو chown(2)، فقد ترجع stat() قيمة st_mode القديمة مع st_uid الجديدة، أو st_uid القديمة مع st_mode الجديدة.

fstatat()

استدعاء النظام fstatat() هو واجهة أكثر عمومية للوصول إلى معلومات الملف والتي لا تزال قادرة على توفير سلوك كل من stat() و lstat() وfstat().

إذا كان path نسبيًا، فسيتم تفسيره بالنسبة للدليل الذي يشير إليه واصف الملف dirfd (بدلاً من كونه نسبيًا لمجلد العمل الحالي للعملية المتصلة، كما هو الحال مع stat() وlstat() لمسار نسبي).

إذا كان path نسبيًا و dirfd هي القيمة الخاصة AT_FDCWD، فسيتم تفسير path نسبيًا لمجلد العمل الحالي للعملية المتصلة (مثل stat() وlstat()).

إذا كان path مطلقًا، فسيتم تجاهل dirfd.

يمكن أن تكون flags إما 0، أو تتضمن علامة واحدة أو أكثر مما يلي ORed:

AT_EMPTY_PATH (منذ Linux 2.6.39)
إذا كان path عبارة عن سلسلة فارغة (أو NULL، منذ Linux 6.11) فقم بالتشغيل على الملف الذي يشير إليه dirfd (والذي ربما تم الحصول عليه باستخدام open(2) مع علم O_PATH). في هذه الحالة، يمكن أن يشير dirfd إلى أي نوع من الملفات، وليس مجرد دليل، وسيكون سلوك fstatat() مشابهًا لسلوك fstat(). إذا كان dirfd هو AT_FDCWD، فإن الاستدعاء يعمل على مجلد العمل الحالي. هذا العلم خاص بنظام Linux؛ قم بتعريف _GNU_SOURCE للحصول على تعريفه.
AT_NO_AUTOMOUNT (منذ Linux 2.6.38)
لا تقم بتحميل تلقائي للمكون الأخير ("basename") من path. (منذ Linux 3.1 تم تجاهل هذا العلم. منذ Linux 4.11 تم تضمين هذا العلم ضمنياً.)
AT_SYMLINK_NOFOLLOW
إذا كان path رابطًا رمزيًا، فلا تقم بفك الإشارة إليه: بدلاً من ذلك، قم بإرجاع معلومات حول الرابط نفسه، مثل lstat(). (افتراضيًا، يقوم fstatat() بفك الإشارة إلى الروابط الرمزية، مثل stat().)

انظر openat(2) لشرح الحاجة إلى fstatat().

قيمة الإرجاع

عند النجاح، يتم إرجاع صفر. عند حدوث خطأ، يتم إرجاع -1، ويتم تعيين errno للإشارة إلى الخطأ.

الأخطاء

EACCES
يُحظر إذن البحث لأحد الأدلة في بادئة المسار path. (انظر أيضًا path_resolution(7).)
EBADF
fd ليس واصف ملف مفتوح صالح.
EBADF
(fstatat()) path نسبي ولكن dirfd ليس AT_FDCWD ولا واصف ملف صالح.
EFAULT
عنوان سيء.
EINVAL
(fstatat()) علم غير صالح محدد في flags.
ELOOP
تم العثور على عدد كبير جدًا من الروابط الرمزية أثناء اجتياز المسار.
ENAMETOOLONG
path طويل جدًا.
ENOENT
أحد مكونات path غير موجود أو رابط رمزي معلق.
ENOENT
path عبارة عن سلسلة فارغة ولم يتم تحديد AT_EMPTY_PATH في flags.
ENOMEM
نفاد الذاكرة (أي ذاكرة النواة).
ENOTDIR
أحد مكونات بادئة المسار path ليس دليلاً.
ENOTDIR
(fstatat()) path نسبي و dirfd هو واصف ملف يشير إلى ملف غير دليل.
EOVERFLOW
يشير path أو fd إلى ملف لا يمكن تمثيل حجمه أو رقمه الاستدلالي أو عدد كتلته في، على التوالي، الأنواع off_t أو ino_t أو blkcnt_t. يمكن أن يحدث هذا الخطأ عندما، على سبيل المثال، يقوم تطبيق تم تجميعه على منصة 32 بت بدون -D_FILE_OFFSET_BITS=64 باستدعاء stat() على ملف يتجاوز حجمه (1<<31)-1 بايت.
