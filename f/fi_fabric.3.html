NAME

fi_fabric - Fabric attributes

SYNOPSIS

A fabric attribute is a set of key/value pairs that describes fabric properties. The fabric attributes are returned by fi_getinfo(3) in the fi_info structure, and are used in the fi_info structure when calling fi_allocinfo.

ARGUMENTS

name
A fabric identifier.
prov_name - Provider Name
The name of the underlying fabric provider.
To request an utility provider layered over a specific core provider, both the provider names have to be specified using “;” as delimiter.
e.g. “ofi_rxm;verbs” or “verbs;ofi_rxm”
For debugging and administrative purposes, environment variables can be used to control which fabric providers will be registered with libfabric. Specifying “FI_PROVIDER=foo,bar” will allow any providers with the names “foo” or “bar” to be registered. Similarly, specifying “FI_PROVIDER=^foo,bar” will prevent any providers with the names “foo” or “bar” from being registered. Providers which are not registered will not appear in fi_getinfo results. Applications which need a specific set of providers should implement their own filtering of fi_getinfo’s results rather than relying on these environment variables in a production setting.
prov_version - Provider Version
Version information for the fabric provider, in a major.minor format. The use of the FI_MAJOR() and FI_MINOR() version macros may be used to extract the major and minor version data. See fi_version(3).
In case of an utility provider layered over a core provider, the version would always refer to that of the utility provider.
api_version
The interface version requested by the application. This value corresponds to the version parameter passed into fi_getinfo(3).

DESCRIPTION

Libfabric supports a set of attributes that describe the capabilities and properties of a fabric. These attributes are exposed through the fi_info structure, which is populated by the fi_getinfo call. The fabric attributes define the characteristics of a fabric and its underlying providers.

The primary fabric attributes are:

name

A string representing the name of the fabric. This is typically a general name for the underlying fabric technology, such as “verbs” for the InfiniBand Verbs interface, or “tcp” for TCP/IP.

prov_name

The name of the specific fabric provider implementing the fabric. Multiple providers can exist for a single fabric technology. For example, different hardware vendors might provide their own “verbs” provider.

When requesting an utility provider layered over a core provider, both provider names must be specified, separated by a “;” delimiter. For instance, “ofi_rxm;verbs” indicates a request for the OFI RXM utility provider layered over the “verbs” core provider. The order matters; “verbs;ofi_rxm” would imply the opposite layering.

Environment variables can be used to control provider registration for debugging and administrative purposes. `FI_PROVIDER=foo,bar` allows providers named “foo” or “bar” to be registered. Conversely, `FI_PROVIDER=^foo,bar` prevents providers named “foo” or “bar” from being registered. Providers not registered will not appear in the results of `fi_getinfo`. Applications requiring a specific set of providers should implement their own filtering of `fi_getinfo` results for production use, rather than relying on these environment variables.

prov_version

The version of the fabric provider, typically in a major.minor format. The macros FI_MAJOR() and FI_MINOR() can be used to extract these version components. Refer to fi_version(3) for details.

If an utility provider is layered over a core provider, this attribute reflects the version of the utility provider.

api_version

The version of the libfabric API that the application intends to use. This value corresponds to the version parameter provided to the fi_getinfo function.

NOTES

The fabric attributes are crucial for applications to understand and select appropriate communication fabrics and providers. The ability to specify provider layering and control provider registration through environment variables offers flexibility in development and testing.

It is important to note that the validity of attributes returned by fi_getinfo is dependent on the application's behavior. Specifically, attributes obtained via fi_getinfo should only be considered valid if the application does not close any fabric instances from another thread while fi_getinfo is being processed.

الاسم

fi_fabric - سمات النسيج

الملخص

السمة للنسيج هي مجموعة من أزواج المفتاح/القيمة التي تصف خصائص النسيج. يتم إرجاع سمات النسيج بواسطة fi_getinfo(3) في بنية fi_info، وتستخدم في بنية fi_info عند استدعاء fi_allocinfo.

المعاملات

name
معرف للنسيج.
prov_name - اسم المزود
اسم مزود النسيج الأساسي.
لطلب مزود أداة مساعدة (utility provider) مكدس فوق مزود أساسي محدد، يجب تحديد اسمي المزودين باستخدام “;” كمحدد.
مثال:  “ofi_rxm;verbs” أو “verbs;ofi_rxm”
لأغراض التصحيح والإدارة، يمكن استخدام متغيرات البيئة للتحكم في مزودات النسيج التي سيتم تسجيلها مع libfabric. تحديد “FI_PROVIDER=foo,bar” سيسمح بتسجيل أي مزودات بالاسمين “foo” أو “bar”. وبالمثل، تحديد “FI_PROVIDER=^foo,bar” سيمنع تسجيل أي مزودات بالاسمين “foo” أو “bar”. المزودات التي لم يتم تسجيلها لن تظهر في نتائج fi_getinfo. التطبيقات التي تحتاج إلى مجموعة محددة من المزودات يجب أن تنفذ تصفيتها الخاصة لنتائج fi_getinfo بدلاً من الاعتماد على متغيرات البيئة هذه في بيئة إنتاجية.
prov_version - إصدار المزود
معلومات الإصدار لمزود النسيج، بتنسيق رئيسي.فرعي (major.minor). يمكن استخدام الماكروهات FI_MAJOR() و FI_MINOR() لاستخراج بيانات الإصدار الرئيسي والفرعي. انظر fi_version(3).
في حالة وجود مزود أداة مساعدة مكدس فوق مزود أساسي، فإن الإصدار سيشير دائمًا إلى إصدار مزود الأداة المساعدة.
api_version
إصدار الواجهة الذي طلبه التطبيق. تتوافق هذه القيمة مع المعامل version الذي تم تمريره إلى fi_getinfo(3).

الوصف

يدعم Libfabric مجموعة من السمات التي تصف إمكانيات وخصائص النسيج. يتم عرض هذه السمات من خلال بنية fi_info، والتي يتم ملؤها بواسطة استدعاء fi_getinfo. تحدد سمات النسيج خصائص النسيج ومزوداته الأساسية.

سمات النسيج الرئيسية هي:

name

سلسلة نصية تمثل اسم النسيج. هذا عادة ما يكون اسمًا عامًا لتقنية النسيج الأساسية، مثل “verbs” لواجهة InfiniBand Verbs، أو “tcp” لـ TCP/IP.

prov_name

اسم مزود النسيج المحدد الذي ينفذ النسيج. يمكن أن توجد مزودات متعددة لتقنية نسيج واحدة. على سبيل المثال، قد يوفر مصنعو الأجهزة المختلفون مزود “verbs” الخاص بهم.

عند طلب مزود أداة مساعدة مكدس فوق مزود أساسي، يجب تحديد اسمي المزودين، مفصولين بمحدد “;”. على سبيل المثال، “ofi_rxm;verbs” تشير إلى طلب مزود الأداة المساعدة OFI RXM المكدس فوق مزود الأساس “verbs”. الترتيب مهم؛ “verbs;ofi_rxm” سيعني التكديس العكسي.

يمكن استخدام متغيرات البيئة للتحكم في تسجيل المزود لأغراض التصحيح والإدارة. `FI_PROVIDER=foo,bar` يسمح بتسجيل المزودات التي تسمى “foo” أو “bar”. على العكس، `FI_PROVIDER=^foo,bar` يمنع تسجيل المزودات التي تسمى “foo” أو “bar”. المزودات غير المسجلة لن تظهر في نتائج `fi_getinfo`. التطبيقات التي تحتاج إلى مجموعة محددة من المزودات يجب أن تنفذ تصفيتها الخاصة لنتائج `fi_getinfo` للاستخدام الإنتاجي، بدلاً من الاعتماد على متغيرات البيئة هذه.

prov_version

إصدار مزود النسيج، عادة بتنسيق رئيسي.فرعي. يمكن استخدام الماكروهات FI_MAJOR() و FI_MINOR() لاستخراج مكونات الإصدار هذه. ارجع إلى fi_version(3) للتفاصيل.

إذا تم تكديس مزود أداة مساعدة فوق مزود أساسي، فإن هذه السمة تعكس إصدار مزود الأداة المساعدة.

api_version

إصدار واجهة برمجة التطبيقات (API) الذي ينوي التطبيق استخدامه. تتوافق هذه القيمة مع المعامل version المقدم إلى الدالة fi_getinfo.

ملاحظات

سمات النسيج ضرورية للتطبيقات لفهم واختيار أقمشة ومزودات الاتصال المناسبة. القدرة على تحديد تكديس المزود والتحكم في تسجيل المزود من خلال متغيرات البيئة توفر المرونة في التطوير والاختبار.

من المهم ملاحظة أن صلاحية السمات التي تم إرجاعها بواسطة fi_getinfo تعتمد على سلوك التطبيق. على وجه التحديد، يجب اعتبار السمات التي تم الحصول عليها عبر fi_getinfo صالحة فقط إذا لم يغلق التطبيق أي مثيلات للنسيج من خيط آخر أثناء معالجة fi_getinfo.

قيمة الإرجاع

تُرجع FI_SUCCESS عند النجاح. عند حدوث خطأ، يتم إرجاع قيمة سالبة تتوافق مع خطأ النسيج (fabric errno). يتم تعريف قيم خطأ النسيج في rdma/fi_errno.h.
