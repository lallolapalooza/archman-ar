futimens(3p)

DESCRIPTION

The utimensat() function shall set the access and modification times of the file indicated by dirfd and pathname.

If pathname is not an absolute path, the file is interpreted relative to the directory referred to by the file descriptor dirfd. If pathname specifies a relative path and dirfd is AT_FDCWD, the path is interpreted relative to the current working directory.

If pathname is not an absolute path, and contains the slash (/) character, it is interpreted relative to the directory referred to by the file descriptor dirfd. If pathname is not an absolute path, and does not contain the slash character, it is interpreted relative to the directory referred to by the file descriptor dirfd, unless dirfd is AT_FDCWD, in which case it is interpreted relative to the current working directory.

The times argument points to an array of two timespec structures that specify the desired file access and modification times. The first structure, pointed to by times[0], specifies the file access time, and the second structure, pointed to by times[1], specifies the file modification time.

The flag argument is an implementation-defined bitmask. The POSIX.1‐2017 standard specifies the AT_SYMLINK_NOFOLLOW flag.

If the flag argument is zero, the utimensat() function behaves like utimes() on the specified file. If the last component of pathname refers to a symbolic link, the times of the symbolic link are changed.

If the AT_SYMLINK_NOFOLLOW flag is set in flag, and the last component of pathname refers to a symbolic link, then the times of the symbolic link are changed, not the file pointed to by the link.

If a component of pathname refers to a symbolic link and flag is zero, the symbolic link is followed and the times of the file pointed to by the link are changed. This implies that the times for the symbolic link itself are not changed.

If the times argument is a null pointer, the access and modification times of the file are set to the current time.

If times[0].tv_nsec is UTIME_NOW or times[1].tv_nsec is UTIME_NOW, the corresponding time is set to the current time. If times[0].tv_nsec is UTIME_OMIT or times[1].tv_nsec is UTIME_OMIT, the corresponding time is not changed.

The constants UTIME_NOW and UTIME_OMIT are defined in <sys/stat.h>.

The utimensat() function should be used in preference to utimes() as it provides the ability to specify the file relative to an open file descriptor, avoiding the race condition of resolving a path name in a directory that may be changed between the call to utimes() and the time the file is accessed.

The following describes the utimes() function.

The utimes() function shall set the access and modification times of the file specified by path. The times argument points to an array of two timespec structures that specify the desired file access and modification times. The first structure, pointed to by times[0], specifies the file access time, and the second structure, pointed to by times[1], specifies the file modification time. If times is a null pointer, the access and modification times of the file are set to the current time.

RETURN VALUE

Upon successful completion, the utimensat() and utimes() functions shall return 0.

Otherwise, they shall return -1 and set errno to indicate the error.

ERRORS

The utimensat() and utimes() functions may fail if:

EACCES
Search permission is denied for any component of a prefix of pathname, or write access or search permission is denied for the directory in which the file resides.
EBADF
The pathname argument does not specify an absolute path, and the dirfd argument is not a valid file descriptor.
EFAULT
The pathname or times argument points to an invalid address.
EINVAL
The value of times[0].tv_nsec or times[1].tv_nsec is invalid (neither UTIME_NOW, UTIME_OMIT, nor a value between 0 and 999,999,999 inclusive).
EINVAL
The value of the flag argument is not valid.
EIO
A physical I/O error has occurred.
EISDIR
The named file is a directory. (The times for a directory can be changed using futimens() with a file descriptor for the directory). The utimensat() function supports setting the times for directories when the last pathname component is . or .., or when the file descriptor refers to the directory itself.
ELOOP
More than {SYMLOOP_MAX} symbolic links were encountered during resolution of the pathname argument.
EMLINK
The named file is a regular file that has directories inside the file system. (This error code is specific to the behavior of utimes() on some legacy systems.)
ENAMETOOLONG

The length of a pathname exceeds {PATH_MAX}, or pathname resolution of a symbolic link produced an intermediate result with a length that exceeds {PATH_MAX}.
ENOENT
A component of pathname does not exist, or the pathname argument is an empty string.
ENOTDIR
A component of a prefix of pathname is not a directory, or pathname does not contain a slash character and dirfd is not AT_FDCWD and refers to a file that is not a directory.
ENXIO
The named file is a block special or character special file, and the device specified by the file does not exist.
EOVERFLOW
The named file is a regular file or symbolic link whose file size, number of links, or size of file's metadata cannot be represented on this implementation.
EROFS
The named file resides on a read-only file system.
ESRCH
The named file does not exist (this error code is specific to the behavior of utimes() on some legacy systems).
ETXTBSY
The file is a text file, and is being executed.

The utimensat() function may fail if:

EINVAL
The value of the flag argument is not valid.

EXAMPLES

None.

APPLICATION USAGE

None.

RATIONALE

The purpose of the utimensat() function is to set the access and modification time of files in directories other than the current working directory without exposure to race conditions. Any part of the path of a file could be changed in parallel to a call to utimes(), resulting in unspecified behavior. By opening a file descriptor for the target directory and using the utimensat() function it can be guaranteed that the changed file is located relative to the desired directory.

The standard developers considered including a special case for the permissions required by utimensat() when one tv_nsec field is UTIME_NOW and the other is UTIME_OMIT. One possibility would be to include this case in with the cases where times is a null pointer or both fields are UTIME_NOW, where the call is allowed if the process has write permission for the file. However, associating write permission with an update to just the last data access timestamp (which is normally updated by read()) did not seem appropriate. The other possibility would be to specify that this one case is allowed if the process has read permission, but this was felt to be too great a departure from the utime() and utimes() functions on which utimensat() is based. If an application needs to set the last data access timestamp to the current time for a file on which it has read permission but is not the owner, it can do so by opening the file, reading one or more bytes (or reading a directory entry, if the file is a directory), and then closing it.
