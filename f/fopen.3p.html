NAME

fopen, fdopen, fmemopen, freopen, open_memstream - open a stream

SYNOPSIS

    #include <stdio.h>

    FILE *fopen(const char *restrict pathname, const char *restrict mode);
    FILE *fdopen(int fd, const char *restrict mode);
    FILE *fmemopen(void *restrict buf, size_t size, const char *restrict mode);
    FILE *freopen(const char *restrict pathname, const char *restrict mode,
              FILE *restrict stream);
    FILE *open_memstream(char **restrict memptr, size_t *restrict size);

DESCRIPTION

The fopen() function shall open the file specified by pathname and associate it with a stream that is returned with the value (a pointer to a FILE structure). The argument pathname is a pointer to a character string specifying the name of the file to be opened. The argument mode is a pointer to a character string specifying the mode in which the file is to be opened. The valid modes for fopen() are described in Opening Modes .

The fdopen() function shall associate a stream with an existing file descriptor, obtained from a previous call to open(), creat(), fcntl(), mkstemp(), open_memstream(), or similar function that returns a file descriptor. The file descriptor remains associated with the stream after a successful call to fdopen(). Closing the stream with fclose() also closes the file descriptor. The argument mode is a pointer to a character string specifying the mode for the new stream. The valid modes for fdopen() are described in Opening Modes .

The fmemopen() function shall associate a stream with a fixed-size memory region buffer, buf, of the given size. The initial contents of the buffer are determined by the file content. The stream is initially positioned at the beginning of the buffer. If mode does not contain r, the buffer is initially empty. If mode contains r, the buffer is initialized with the contents of the file specified by pathname. Writing to a full buffer causes an error. The size argument is the size of the buffer in bytes. If size is zero, fmemopen() returns an error. The stream created by fmemopen() is read/write if mode contains r+ or w+, otherwise it is read-only. The buffer must remain valid until the stream is closed. The application can reposition the stream using fseek() or fsetpos() at any time. If the stream is created with w or w+, then seeking past the end of the buffer is permitted and expands the buffer to the new position. If seeking past the end of the buffer is permitted and the new position is beyond the end of the buffer, the buffer is filled with null bytes up to the new position.

The freopen() function shall close the stream that is currently associated with stream (if any) and then open the file specified by pathname and associate it with stream. The argument mode specifies the file's mode. The arguments pathname, mode, and stream are pointers to character strings and a FILE pointer, respectively.

The open_memstream() function shall create a set of stream functions that write to a dynamically allocated buffer. The buffer starts empty. The stream is positioned at the beginning of the buffer. The application can reposition the stream using fseek() or fsetpos() at any time. If seeking past the end of the buffer is permitted and the new position is beyond the end of the buffer, the buffer is filled with null bytes up to the new position. When the stream is closed, the buffer is automatically freed. The buffer and its size are passed back to the application via the memptr and size arguments.

Opening Modes

The mode argument is a string that begins with one of the following sequences of characters:

r
Open for reading. The file must exist.
w
Create a new file or truncate it to zero length if it exists.
a
Append; open for writing, and the file is created if it does not exist.
r+
Open for reading and writing. The file must exist.
w+
Create a new file or truncate it to zero length if it exists; open for reading and writing.
a+
Append; open for reading and writing, and the file is created if it does not exist. The stream is positioned at the end of the file. The input and output functions reposition the stream at the end of the file prior to each I/O operation.

The following characters may be appended to any of the above sequences:

b
Open in binary mode. If the b character is omitted, the mode is text mode. The standard interpretation is that the standard I/O environment is free to translate the <CR><LF> sequence to and from the underlying physical device representation and the representation in memory. Applications are expected to provide the appropriate translation if binary mode is intended.
e
Open in close-on-exec mode. The file descriptor associated with the stream will have the close-on-exec flag set. The application must ensure that the stream is not closed before the close-on-exec flag is set.

RETURN VALUE

Upon successful completion, fopen(), fdopen(), fmemopen(), freopen(), and open_memstream() shall return a pointer to a FILE structure. Otherwise, they shall return a null pointer and set errno to indicate the error.

ERRORS

The fopen(), fdopen(), fmemopen(), and freopen() functions may fail if:

EACCES
Access denied. The requested access to the file could not be granted because of the file permissions.
EBADF
Bad file descriptor. The fd argument is not a valid open file descriptor.
EINTR
Interrupted system call. A signal interrupted the operation before it completed.
EINVAL

Invalid argument. The value of the mode argument is not valid.
EISDIR
Is a directory. The named file is a directory, and the mode request specified writing or creation.
ELOOP
Too many symbolic links encountered. Too many symbolic links were encountered in resolving a component of the pathname.
EMFILE
Too many open files. The process has reached its limit on the number of open file descriptors.
ENAMETOOLONG
Filename too long. The length of a component of a pathname is longer than {NAME_MAX}.
ENFILE
File table overflow. The system limit on the total number of open files has been reached.
ENOENT
No such file or directory. The file specified by pathname does not exist and mode is not w or a or w+ or a+.
ENOMEM
Out of memory. Insufficient memory is available to create the stream.
ENOSPC
No space left on device. The file is on a device that is full, and the request to create or write to the file will fail.
ENOTDIR
Not a directory. A component of the path prefix names an existing file that is neither a directory nor a symbolic link to a directory, or the pathname argument contains at least one non-<slash> character and ends with one or more trailing <slash> characters and the last pathname component names an existing file that is neither a directory nor a symbolic link to a directory.
ENXIO
No such device or address. The named file is a character special or block special file, and the device associated with this special file does not exist.
EOVERFLOW
Value too large to be stored in data type. The named file is a regular file and the size of the file cannot be represented correctly in an object of type off_t.
EROFS
Read-only file system. The named file resides on a read-only file system and mode requires write access.

The fopen() function may fail if:

EINVAL
The value of the mode argument is not valid.
ELOOP
More than {SYMLOOP_MAX} symbolic links were encountered during resolution of the path argument.
EMFILE
{FOPEN_MAX} streams are currently open in the calling process.
ENAMETOOLONG

The length of a component of a pathname is longer than {NAME_MAX}.
ENOMEM
Insufficient storage space is available.
ETXTBSY
Text file busy. The file is a pure procedure (shared text) file that is being executed and mode requires write access.

EXAMPLES

Opening a File

The following example tries to open the file named file for reading. The fopen() function returns a file pointer that is used in subsequent fgets() and fclose() calls. If the program cannot open the file, it just ignores it.

#include <stdio.h>
...
FILE *fp;
...
void rgrep(const char *file)
{
...
    if ((fp = fopen(file, "r")) == NULL)
        return;
...
}
