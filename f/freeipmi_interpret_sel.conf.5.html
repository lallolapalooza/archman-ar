NAME

freeipmi_interpret_sel.conf

file format for FreeIPMI SEL interpretation configuration

DESCRIPTION

The freeipmi_interpret_sel.conf file is used to configure interpretations for SEL (System Event Log) records that are specific to an OEM (Original Equipment Manufacturer) or vendor. This allows FreeIPMI tools to provide more meaningful descriptions for certain SEL records that would otherwise be presented as generic or raw data.

The configuration file supports two main types of record interpretations:

IPMI_OEM_Timestamped_Record
This directive is used to define how to interpret a specific SEL record that has a timestamp associated with it. It allows you to map a combination of Manufacturer ID, Product ID, Record Type, and specific OEM data fields to a custom interpretation.
IPMI_OEM_Non_Timestamped_Record
This directive is used to define how to interpret a specific SEL record that does not have a timestamp associated with it. Similar to the timestamped record, it allows mapping specific identifiers and OEM data to a custom interpretation.

FORMAT

Each line in the configuration file represents a single interpretation rule. Lines starting with '#' are comments and are ignored. Blank lines are also ignored.

The general format for a configuration line is as follows:

Directive <Manufacturer-ID>:<Product-ID>,... <Record-Type> <OEMDATA1> ... <OEMDATAX> [<State>]

Where:

Directive
Must be either IPMI_OEM_Timestamped_Record or IPMI_OEM_Non_Timestamped_Record.
Manufacturer-ID:Product-ID,...
A comma-separated list of Manufacturer IDs and Product IDs that this rule applies to. Each Manufacturer ID can optionally be followed by a colon and a Product ID. If only a Manufacturer ID is provided, it applies to all products from that manufacturer. Wildcards are not supported here.
Record-Type
The type of the SEL record. This must be a valid hexadecimal value within the range specified for the directive (e.g., 0xC0-0xDF for IPMI_OEM_Timestamped_Record, 0xE0-0xFF for IPMI_OEM_Non_Timestamped_Record).
OEMDATA1...OEMDATAX
These represent the OEM-specific data bytes within the SEL record. Each field must be either a two-digit hexadecimal byte (e.g., 0xAF) or the keyword ANY, which acts as a wildcard and matches any byte value for that position. The number of OEMDATA fields depends on the directive used and the specific SEL record format being targeted.
State
This is an optional field, primarily used with IPMI_OEM_Non_Timestamped_Record. It specifies a state value associated with the record, which can be used for more granular interpretation or filtering.

EXAMPLES

Here are some examples illustrating the configuration syntax:

  • Timestamped Record Example:

    IPMI_OEM_Timestamped_Record 0x0002:0x0001 0xC1 ANY 0x05 ANY 0xFF 0x00 ANY ANY ANY ANY ANY
    This rule applies to records from Manufacturer ID 0x0002, Product ID 0x0001,
    with Record Type 0xC1. It matches if the 3rd OEM data byte is 0x05, the
    7th is 0xFF, and the 8th is 0x00. Other OEM data bytes can be anything.

  • Non-Timestamped Record Example:

    IPMI_OEM_Non_Timestamped_Record 0x010A:ANY 0xE0 0x01 0xFF ANY ANY ANY ANY ANY ANY ANY ANY ANY 0x01
    This rule applies to records from Manufacturer ID 0x010A (any product).
    The Record Type is 0xE0. It matches if the 1st OEM data byte is 0x01,
    the 3rd is 0xFF, and the final state field is 0x01. Other OEM data bytes
    can be anything.

  • Manufacturer-Wide Rule:

    IPMI_OEM_Timestamped_Record 0x0007: ANY 0xD0 0xAA ANY ANY ANY ANY ANY ANY ANY ANY ANY
    This rule applies to any product from Manufacturer ID 0x0007 for Record
    Type 0xD0, specifically matching if the first OEM data byte is 0xAA.

IPMI_OEM_Timestamped_Record

IPMI_OEM_Timestamped_Record can be used to configure an interpretation for a specific Manufacturer-ID, Product-ID, Record-Type, and OEM data combination. The Record-Type must be a legal record type for OEM Timestamped Records (currently 0xC0-0xDF). Each of the OEMDATA fields must specify a hex byte to match or the keyword ANY to match anything.
IPMI_OEM_Non_Timestamped_Record <Manufacturer-ID>:<Product-ID>,... Record-Type OEMDATA1 OEMDATA2 OEMDATA3 OEMDATA4 OEMDATA5 OEMDATA6 OEMDATA7 OEMDATA8 OEMDATA9 OEMDATA10 OEMDATA11 OEMDATA12 OEMDATA13 State
IPMI_OEM_Non_Timestamped_Record can be used to configure an interpretation for a specific Manufacturer-ID, Product-ID, Record-Type, and OEM data combination. The Record-Type must be a legal record type for OEM Non-Timestamped Records (currently 0xEO-0xFF). Each of the OEMDATA fields must specify a hex byte to match or the keyword ANY to match anything.
