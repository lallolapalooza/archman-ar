stat(2) دليل استدعاءات النظام stat(2)

الاسم

stat, fstat, lstat, fstatat - الحصول على حالة الملف

المكتبة

مكتبة C القياسية (libc, -lc)

الملخص

#include <sys/stat.h>
int stat(const char *restrict path,
         struct stat *restrict statbuf);
int fstat(int fd, struct stat *statbuf);
int lstat(const char *restrict path,
         struct stat *restrict statbuf);
#include <fcntl.h>           /* تعريف ثوابت AT_* */
#include <sys/stat.h>
int fstatat(int dirfd, const char *restrict path,
         struct stat *restrict statbuf, int flags);

الوصف

تقوم هذه الدوال بإرجاع معلومات حول ملف، في المخزن المؤقت الذي يشير إليه statbuf. لا يلزم وجود أذونات على الملف نفسه، ولكن - في حالة stat() و fstatat() و lstat() - يلزم وجود إذن التنفيذ (البحث) على جميع الدلائل الموجودة في path التي تؤدي إلى الملف.

stat() و fstatat() تسترجعان معلومات حول الملف الذي يشير إليه path؛ يتم وصف الاختلافات لـ fstatat() أدناه.

lstat() متطابقة مع stat()، إلا أنه إذا كان path رابطًا رمزيًا، فإنها ترجع معلومات حول الرابط نفسه، وليس الملف الذي يشير إليه الرابط.

fstat() متطابقة مع stat()، إلا أن الملف الذي سيتم استرداد المعلومات حوله يتم تحديده بواسطة واصف الملف fd.

بنية stat

جميع استدعاءات النظام هذه ترجع بنية stat (انظر stat(3type)).

ملاحظة: لأسباب تتعلق بالأداء والبساطة، قد تحتوي الحقول المختلفة في بنية stat على معلومات الحالة من لحظات مختلفة أثناء تنفيذ استدعاء النظام. على سبيل المثال، إذا تم تغيير st_mode أو st_uid بواسطة عملية أخرى عن طريق استدعاء chmod(2) أو chown(2)، فقد ترجع stat() قيمة st_mode القديمة مع st_uid الجديدة، أو قيمة st_uid القديمة مع st_mode الجديدة.

fstatat()

استدعاء النظام fstatat() هو واجهة أكثر عمومية للوصول إلى معلومات الملف التي يمكنها مع ذلك توفير سلوك مطابق لكل من stat() و lstat() و fstat().

إذا كان path نسبيًا، فيتم تفسيره بالنسبة للدليل الذي يشير إليه واصف الملف dirfd (بدلاً من كونه نسبيًا إلى دليل العمل الحالي للعملية المستدعية، كما تفعل stat() و lstat() لمسار نسبي).

إذا كان path نسبيًا وكان dirfd هي القيمة الخاصة AT_FDCWD، فيتم تفسير path نسبيًا إلى دليل العمل الحالي للعملية المستدعية (مثل stat() و lstat()).

إذا كان path مطلقًا، فيتم تجاهل dirfd.

يمكن أن يكون flags إما 0، أو يتضمن واحدًا أو أكثر من الأعلام التالية مع OR:

AT_EMPTY_PATH (منذ Linux 2.6.39)
إذا كان path سلسلة فارغة (أو NULL، منذ Linux 6.11) فقم بتشغيل الملف الذي يشير إليه dirfd (والذي ربما تم الحصول عليه باستخدام open(2) مع العلامة O_PATH). في هذه الحالة، يمكن أن يشير dirfd إلى أي نوع من الملفات، وليس فقط دليلًا، وسيكون سلوك fstatat() مشابهًا لسلوك fstat(). إذا كان dirfd هو AT_FDCWD، فإن الاستدعاء يعمل على دليل العمل الحالي. هذا العلم خاص بـ Linux؛ قم بتعريف _GNU_SOURCE للحصول على تعريفه.
AT_NO_AUTOMOUNT (منذ Linux 2.6.38)
لا تقم بتركيب المكون "basename" من path تلقائيًا. (منذ Linux 3.1 تم تجاهل هذا العلم. منذ Linux 4.11 تم تضمين هذا العلم ضمنيًا.)
AT_SYMLINK_NOFOLLOW
إذا كان path رابطًا رمزيًا، فلا تقم بفك مرجعيته: بدلاً من ذلك، أرجع معلومات حول الرابط نفسه، مثل lstat(). (افتراضيًا، تقوم fstatat() بفك مرجعية الروابط الرمزية، مثل stat().)

انظر openat(2) لشرح الحاجة إلى fstatat().

قيمة الإرجاع

عند النجاح، يتم إرجاع صفر. عند حدوث خطأ، يتم إرجاع -1، ويتم تعيين errno للإشارة إلى الخطأ.

الأخطاء

EACCES
يتم رفض إذن البحث لأحد الأدلة في بادئة المسار لـ path. (انظر أيضًا path_resolution(7).)
EBADF
fd ليس واصف ملف مفتوح صالح.
EBADF
(fstatat()) path نسبي ولكن dirfd ليس AT_FDCWD وليس واصف ملف صالح.
EFAULT
عنوان سيء.
EINVAL
(fstatat()) تم تحديد علم غير صالح في flags.
ELOOP
تم العثور على عدد كبير جدًا من الروابط الرمزية أثناء اجتياز المسار.
ENAMETOOLONG
path طويل جدًا.
ENOENT
أحد مكونات path غير موجود أو هو رابط رمزي معلق.
ENOENT
path عبارة عن سلسلة فارغة ولم يتم تحديد AT_EMPTY_PATH في flags.
ENOMEM
نفاد الذاكرة (أي ذاكرة النواة).
ENOTDIR
أحد مكونات بادئة المسار لـ path ليس دليلًا.
ENOTDIR
(fstatat()) path نسبي و dirfd هو واصف ملف يشير إلى ملف غير دليل.
EOVERFLOW
يشير path أو fd إلى ملف لا يمكن تمثيل حجمه، أو رقمه المرجعي (inode)، أو عدد الكتل الخاصة به في، على التوالي، الأنواع off_t، ino_t، أو blkcnt_t. قد يحدث هذا الخطأ عندما، على سبيل المثال، يقوم تطبيق تم تجميعه على منصة 32 بت بدون -D_FILE_OFFSET_BITS=64 باستدعاء stat() على ملف يتجاوز حجمه (1<<31)-1 بايت.
