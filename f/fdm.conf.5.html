fdm.conf(5)

الحزمة: fdm

التراخيص: BSD

الإجراءات

يُستخدم الأمر action لتعريف الإجراءات. يمكن تحديد هذه الإجراءات بالاسم في القواعد (انظر أدناه) لتنفيذ بعض الإجراءات على البريد. الصيغة هي:

action name [users] action
 
action name [users] { action ... }
 

الـ name هو سلسلة نصية تحدد اسمًا للإجراء. الوسيط users له نفس شكل تعريف الحساب. يمكن تجاوز إعداد المستخدم للإجراء في القاعدة المطابقة.

القيم الممكنة للـ action مدرجة أدناه. إذا تم تحديد إجراءات متعددة، يتم تنفيذها مرة واحدة بالترتيب المحدد، لكل مستخدم.

drop
تجاهل البريد.
keep
احتفظ بالبريد، لا تقم بإزالته من الحساب.
tag string [value value]
يقوم هذا الوسم بتصنيف البريد باستخدام string، واختياريًا value، والتي يمكن مطابقتها باستخدام شروط tagged أو string.
maildir path
حفظ البريد في مجلد البريد المحدد بواسطة path. إذا لم يكن مجلد البريد أو أي جزء من مساره موجودًا، فسيتم إنشاؤه، ما لم يتم تعيين خيار no-create.

يتم وسم البريد الذي تم تسليمه إلى مجلد بريد بوسم mail_file يحتوي على المسار الكامل لملف البريد.

mbox path [compress]
إلحاق البريد بملف mbox في path. إذا تم تحديد compress، فسيقوم fdm(1) بإضافة ‘.gz’ إلى path ومحاولة كتابة البريد باستخدام ضغط gzip(1). إذا لم يكن ملف mbox أو أي جزء من مساره موجودًا، فسيتم إنشاؤه، ما لم يتم تعيين خيار no-create.

يتم وسم البريد الذي تم تسليمه إلى ملف mbox بوسم mbox_file يحتوي على مسار ملف mbox.

exec command
تنفيذ الأمر command.
pipe command
توجيه البريد إلى الأمر command. يتم تشغيل أوامر exec و pipe كمستخدم الأمر.
write path
كتابة البريد إلى المسار path.
append path
إلحاق البريد بالمسار path.
smtp server host [port port] [from from] [to to]
الاتصال بخادم SMTP ومحاولة تسليم البريد إليه. إذا تم تحديد from أو to، فسيتم تمريرهما إلى الخادم في أوامر MAIL FROM أو RCPT TO. إذا لم يتم تحديدهما، يتم استخدام أسماء المستخدم والمضيف الحاليين.
lmtp server path | host [port port] [from from] [to to]
الاتصال بخادم LMTP ومحاولة تخزين البريد هناك. إذا كان سيتم استخدام مقبس UNIX، فيجب أن يكون path هو المسار المطلق.

port افتراضيًا هو 24. إذا تم تحديد from أو to، فسيتم تمريرهما إلى الخادم في أوامر MAIL FROM أو RCPT TO. إذا لم يتم تحديدهما، يتم استخدام أسماء المستخدم والمضيف الحاليين.

rewrite command
توجيه البريد بأكمله عبر الأمر command لإنشاء بريد جديد واستخدام هذا البريد لأي إجراءات أو قواعد لاحقة. مثال على إجراء rewrite هو: 
action "cat" pipe "cat"
action "rewrite" rewrite "sed 's/bob/fred/g'"
# rule will rewrite the message
match all action "rewrite" continue
# rule will cat the rewritten message
match all action "cat"
add-header name value value
إضافة رأس name بمحتوى value.
remove-header name
 
remove-headers { name ... }
إزالة جميع تكرارات الرؤوس التي تطابق نمط fnmatch(3) name.
stdout
كتابة البريد إلى stdout.
add-to-cache path key key
يقوم هذا الإجراء بإضافة السلسلة النصية key إلى ذاكرة التخزين المؤقت المحددة بواسطة path. إذا كانت key موجودة بالفعل في ذاكرة التخزين المؤقت، فسيتم استبدالها.
remove-from-cache path key key
إزالة السلسلة النصية key من ذاكرة التخزين المؤقت path، إذا كان هناك مفتاح مطابق.
action name
يقوم هذا باستدعاء إجراء مسمى آخر. يمكن استدعاء خمسة إجراءات كحد أقصى في تسلسل.

القواعد

يتم تحديد القواعد باستخدام الكلمة المفتاحية match. لها الشكل الأساسي التالي:

match condition [and | or condition ...] [users] actions [continue]
 

قد يكون الوسيط condition أحد الخيارات التالية:

all
يطابق كل البريد.
matched
يطابق البريد الذي طابق قاعدة سابقة وتم تمريره مع continue.
unmatched
عكس matched: يطابق فقط رسائل البريد التي لم تطابق أي قواعد سابقة.
account name | accounts { name ... }
يطابق فقط البريد الذي تم جلبه من الحساب المسمى أو الحسابات. قد تتضمن أسماء الحسابات أحرف بدل في shell لمطابقة حسابات متعددة، كما هو الحال مع خيارات سطر الأوامر -a و -x.
tagged string
يطابق رسائل البريد الموسومة بـ string.
[case] regexp [in headers | in body]
يحدد تعبيرًا عاديًا (regexp) يجب مطابقة كل رسالة بريد ضده. قد يتم تقييد المطابقات إلى رؤوس الرسالة أو جسمها بتحديد in headers أو in body. الكلمة المفتاحية case تجبر التعبير العادي على المطابقة الحساسة لحالة الأحرف: الافتراضي هو مطابقة غير حساسة لحالة الأحرف.
exec command [user user] returns (return code, stdout regexp)
 
pipe command [user user] returns (return code, [case] stdout regexp)
يقوم هذان الشرطان بتنفيذ أمر command واختبار قيمة العودة والناتج الخاص به. الوسيط return code هو رمز العودة الرقمي المتوقع و stdout regexp هو تعبير عادي ليتم اختباره مقابل ناتج الأمر إلى stdout. يمكن حذف أي من هذين الوسيطين: إذا تم تحديد كليهما، فيجب أن يتطابق كلاهما لكي يكون الشرط صحيحًا. سيقوم إصدار pipe بتوجيه البريد إلى stdin للأمر عند تنفيذه. إذا كان المستخدم i
