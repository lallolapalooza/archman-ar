fi_inject_writedata(3)

الحزمة: libfabric

التراخيص: BSD-2-Clause OR GPL-2.0-or-later

NAME

fi_inject_writedata - inject or write data with completion options

SYNOPSIS

fi_inject_writedata, fi_readmsg, fi_writemsg

#include <rdma/fabric.h>
ssize_t fi_inject_writedata(
    struct fi_info *info,
    void *buf,
    size_t len,
    void *desc
);
ssize_t fi_readmsg(
    struct fi_endpoint *endpoint,
    const struct fi_msg *msg,
    void *desc
);
ssize_t fi_writemsg(
    struct fi_endpoint *endpoint,
    const struct fi_msg *msg,
    void *desc
);

ARGUMENTS

info
Used with fi_inject_writedata. This is a pointer to a fi_info structure. This structure is used to specify fabric attributes and flags for the operation. The fi_info structure must be populated with valid information, including the desired fabric, transport, and endpoint type. The flags field of the fi_info structure can be used to specify operation-specific flags.
buf
Used with fi_inject_writedata. This is a pointer to the data buffer to be sent.
len
Used with fi_inject_writedata. This is the length of the data buffer to be sent.
desc
A user-defined data that is associated with the operation. This data is returned to the user in the completion queue entry for the operation. The type and usage of this parameter may vary depending on the operation and the underlying fabric provider.
endpoint
Used with fi_readmsg and fi_writemsg. This is a pointer to the endpoint object associated with the communication operation.
msg
Used with fi_readmsg and fi_writemsg. This is a pointer to a fi_msg structure, which contains details about the message to be sent or received. The fi_msg structure includes fields for the data buffer, message tags, and other operation-specific parameters.

DESCRIPTION

The fi_inject_writedata, fi_readmsg, and fi_writemsg functions are used to perform data transfer operations. fi_inject_writedata is a convenience function for injecting small messages, typically used for control messages or short data transfers. fi_readmsg and fi_writemsg are more general-purpose functions for reading and writing messages, respectively.

These functions allow the user to specify flags that can alter the default data transfer behavior. Flags specified with fi_readmsg or fi_writemsg override most flags previously configured with the endpoint, except where noted (see fi_endpoint.3). The following flags are usable with fi_readmsg and/or fi_writemsg.

FLAGS

FI_REMOTE_CQ_DATA
Applies to fi_writemsg. Indicates that remote CQ data is available and should be sent as part of the request. See fi_getinfo for additional details on FI_REMOTE_CQ_DATA. This flag is implicitly set for fi_writedata and fi_inject_writedata.
FI_COMPLETION
Indicates that a completion entry should be generated for the specified operation. The endpoint must be bound to a completion queue with FI_SELECTIVE_COMPLETION that corresponds to the specified operation, or this flag is ignored.
FI_MORE
Indicates that the user has additional requests that will immediately be posted after the current call returns. Use of this flag may improve performance by enabling the provider to optimize its access to the fabric hardware.
FI_INJECT
Applies to fi_writemsg. Indicates that the outbound data buffer should be returned to user immediately after the write call returns, even if the operation is handled asynchronously. This may require that the underlying provider implementation copy the data into a local buffer and transfer out of that buffer. This flag can only be used with messages smaller than inject_size.
FI_INJECT_COMPLETE
Applies to fi_writemsg. Indicates that a completion should be generated when the source buffer(s) may be reused.
FI_TRANSMIT_COMPLETE
Applies to fi_writemsg. Indicates that a completion should not be generated until the operation has been successfully transmitted and is no longer being tracked by the provider.
FI_DELIVERY_COMPLETE
Applies to fi_writemsg. Indicates that a completion should be generated when the operation has been processed by the destination.
FI_COMMIT_COMPLETE
Applies to fi_writemsg when targeting persistent memory regions. Indicates that a completion should be generated only after the result of the operation has been made durable.
FI_FENCE
Applies to transmits. Indicates that the requested operation, also known as the fenced operation, and any operation posted after the fenced operation will be deferred until all previous operations targeting the same peer endpoint have completed. Operations posted after the fencing will see and/or replace the results of any operations initiated prior to the fenced operation.

The ordering of operations starting at the posting of the fenced operation (inclusive) to the posting of a subsequent fenced operation (exclusive) is controlled by the endpoint’s ordering semantics.

RETURN VALUE

Returns 0 on success. On error, a negative value corresponding to fabric errno is returned. Fabric errno values are defined in rdma/fi_errno.h.

ERRORS

-FI_EAGAIN
See fi_msg(3) for a detailed description of handling FI_EAGAIN.

SEE ALSO

fi_getinfo(3), fi_endpoint(3), fi_domain(3), fi_cq(3)

fi_inject_writedata - حقن أو كتابة بيانات مع خيارات الإكمال

المعاملات

info
يستخدم مع fi_inject_writedata. هذا مؤشر إلى بنية fi_info. تستخدم هذه البنية لتحديد سمات النسيج (fabric) والعلامات (flags) لعملية النقل. يجب ملء بنية fi_info بمعلومات صالحة، بما في ذلك النسيج المطلوب، والنقل، ونوع نقطة النهاية (endpoint). يمكن استخدام حقل العلامات (flags) في بنية fi_info لتحديد علامات خاصة بالعملية.
buf
يستخدم مع fi_inject_writedata. هذا مؤشر إلى مخزن البيانات (buffer) المُراد إرساله.
len
يستخدم مع fi_inject_writedata. هذا هو طول مخزن البيانات المُراد إرساله.
desc
بيانات يحددها المستخدم ويتم ربطها بالعملية. يتم إرجاع هذه البيانات للمستخدم في إدخال طابور الإكمال (completion queue entry) للعملية. قد يختلف نوع هذا المعامل واستخدامه اعتمادًا على العملية وتنفيذ النسيج الأساسي.
endpoint
يستخدم مع fi_readmsg و fi_writemsg. هذا مؤشر إلى كائن نقطة النهاية (endpoint object) المرتبط بعملية الاتصال.
msg
يستخدم مع fi_readmsg و fi_writemsg. هذا مؤشر إلى بنية fi_msg، التي تحتوي على تفاصيل حول الرسالة المُراد إرسالها أو استقبالها. تتضمن بنية fi_msg حقولًا لمخزن البيانات، وعلامات الرسائل (message tags)، ومعلمات أخرى خاصة بالعملية.

الوصف

تُستخدم الدوال fi_inject_writedata و fi_readmsg و fi_writemsg لإجراء عمليات نقل البيانات. fi_inject_writedata هي دالة مساعدة لحقن الرسائل الصغيرة، تُستخدم عادةً لرسائل التحكم أو نقل البيانات القصيرة. fi_readmsg و fi_writemsg هما دالتان للأغراض العامة لقراءة وكتابة الرسائل على التوالي.

تسمح هذه الدوال للمستخدم بتحديد علامات (flags) يمكن أن تغير سلوك نقل البيانات الافتراضي. العلامات المحددة مع fi_readmsg أو fi_writemsg تتجاوز معظم العلامات التي تم تكوينها مسبقًا مع نقطة النهاية، إلا في الحالات المذكورة (انظر fi_endpoint.3). العلامات التالية قابلة للاستخدام مع fi_readmsg و/أو fi_writemsg.

علامات (FLAGS)

FI_REMOTE_CQ_DATA
تنطبق على fi_writemsg. تشير إلى أن بيانات طابور الإكمال البعيد (remote CQ data) متاحة ويجب إرسالها كجزء من الطلب. انظر fi_getinfo لمزيد من التفاصيل حول FI_REMOTE_CQ_DATA. يتم تعيين هذه العلامة ضمنيًا لـ fi_writedata و fi_inject_writedata.
FI_COMPLETION
تشير إلى أنه يجب إنشاء إدخال إكمال (completion entry) للعملية المحددة. يجب ربط نقطة النهاية بطابور إكمال (completion queue) مع FI_SELECTIVE_COMPLETION يتوافق مع العملية المحددة، وإلا سيتم تجاهل هذه العلامة.
FI_MORE
تشير إلى أن المستخدم لديه طلبات إضافية سيتم نشرها فورًا بعد عودة الاستدعاء الحالي. قد يؤدي استخدام هذه العلامة إلى تحسين الأداء من خلال تمكين الموفر (provider) من تحسين وصوله إلى أجهزة النسيج.
FI_INJECT
تنطبق على fi_writemsg. تشير إلى أنه يجب إرجاع مخزن البيانات الخارجي (outbound data buffer) للمستخدم فورًا بعد عودة استدعاء الكتابة، حتى لو تم التعامل مع العملية بشكل غير متزامن. قد يتطلب هذا أن تقوم بنية تنفيذ الموفر الأساسية بنسخ البيانات إلى مخزن مؤقت محلي ونقلها من هذا المخزن. يمكن استخدام هذه العلامة فقط مع الرسائل التي يقل حجمها عن inject_size.
FI_INJECT_COMPLETE
تنطبق على fi_writemsg. تشير إلى أنه يجب إنشاء إكمال عندما يمكن إعادة استخدام مخازن البيانات المصدر.
FI_TRANSMIT_COMPLETE
تنطبق على fi_writemsg. تشير إلى أنه لا يجب إنشاء إكمال حتى يتم إرسال العملية بنجاح ولا يتم تتبعها بواسطة الموفر بعد الآن.
FI_DELIVERY_COMPLETE
تنطبق على fi_writemsg. تشير إلى أنه يجب إنشاء إكمال عندما تتم معالجة العملية بواسطة الوجهة.
FI_COMMIT_COMPLETE
تنطبق على fi_writemsg عند استهداف مناطق الذاكرة الدائمة (persistent memory regions). تشير إلى أنه يجب إنشاء إكمال فقط بعد أن تصبح نتيجة العملية دائمة.
FI_FENCE
تنطبق على عمليات الإرسال (transmits). تشير إلى أن العملية المطلوبة، والمعروفة أيضًا بالعملية المحاطة بسياج (fenced operation)، وأي عملية يتم نشرها بعد العملية المحاطة بسياج سيتم تأجيلها حتى تكتمل جميع العمليات السابقة التي تستهدف نفس نقطة النهاية النظيرة. العمليات التي يتم نشرها بعد السياج ستشاهد و/أو تستبدل نتائج أي عمليات تم بدؤها قبل العملية المحاطة بسياج.

يتم التحكم في ترتيب العمليات بدءًا من نشر العملية المحاطة بسياج (شاملة) إلى نشر عملية لاحقة محاطة بسياج (غير شاملة) بواسطة دلالات الترتيب الخاصة بنقطة النهاية.

قيمة الإرجاع

ترجع 0 عند النجاح. عند حدوث خطأ، يتم إرجاع قيمة سالبة تتوافق مع خطأ النسيج (fabric errno). يتم تعريف قيم خطأ النسيج في rdma/fi_errno.h.
