fish-language(1)

اقتباس المتغيرات

يحدث توسيع المتغيرات أيضًا في السلاسل النصية المزدوجة الاقتباس. داخل علامات الاقتباس المزدوجة ("هذه")، سيتم دائمًا توسيع المتغيرات إلى وسيط واحد بالضبط. إذا كانت فارغة أو غير معرفة، فسيؤدي ذلك إلى سلسلة نصية فارغة. إذا كان لديها عنصر واحد، فسوف تتوسع إلى هذا العنصر. إذا كان لديها أكثر من ذلك، فسيتم ربط العناصر بمسافات، ما لم يكن المتغير متغير مسار - في هذه الحالة سيستخدم النقطتين (:) بدلاً من ذلك [3].

متغيرات Fish كلها قوائم، ويتم تقسيمها إلى عناصر عند تعيينها - وهذا يعني أنه من المهم تحديد ما إذا كان سيتم استخدام علامات الاقتباس أم لا مع set <>:

set foo 1 2 3 # متغير بثلاثة عناصر
rm $foo # تشغيل ما يعادل `rm 1 2 3` - محاولة حذف ثلاثة ملفات: 1، 2، و 3.
rm "$foo" # تشغيل `rm '1 2 3'` - محاولة حذف ملف واحد يسمى '1 2 3'
set foo # متغير فارغ
rm $foo # تشغيل `rm` بدون وسائط
rm "$foo" # تشغيل ما يعادل `rm ''`
set foo "1 2 3"
rm $foo # تشغيل ما يعادل `rm '1 2 3'` - محاولة حذف ملف واحد
rm "$foo" # نفس الشيء

هذا يختلف عن الأصداف الأخرى، التي تقوم بما يُعرف بـ "تقسيم الكلمات"، حيث تقسم المتغير عند استخدامه في توسيع. على سبيل المثال، في bash:

foo="1 2 3"
rm $foo # تشغيل ما يعادل `rm 1 2 3`
rm "$foo" # تشغيل ما يعادل `rm '1 2 3'`

هذا هو سبب المشاكل الشائعة جدًا مع أسماء الملفات التي تحتوي على مسافات في نصوص bash.

في Fish، سيتم توسيع المتغيرات غير المقتبسة إلى أكبر عدد من الوسائط التي تحتوي عليها من عناصر. هذا يعني أن قائمة فارغة ستتوسع إلى لا شيء، ومتغير بعنصر واحد سيتوسع إلى هذا العنصر، ومتغير بعناصر متعددة سيتوسع إلى كل من هذه العناصر بشكل منفصل.

إذا توسع متغير إلى لا شيء، فسيؤدي ذلك إلى إلغاء أي سلاسل نصية أخرى ملحقة به. انظر قسم دمج القوائم لمزيد من المعلومات.

في معظم الأحيان، عدم اقتباس المتغير هو الصحيح. الاستثناء هو عندما تحتاج إلى التأكد من تمرير المتغير كعنصر واحد، حتى لو كان غير معين أو يحتوي على عناصر متعددة. يحدث هذا غالبًا مع الاختبار <>:

set -l foo one two three
test -n $foo
# يطبع رسالة خطأ لأنه حصل على الكثير من الوسائط، لأنه تم تنفيذه مثل
test -n one two three
test -n "$foo"
# يعمل، لأنه تم تنفيذه مثل
test -n "one two three"
[3]
على عكس bash أو zsh، التي ستربط بأول حرف من $IFS (وهو عادةً مسافة).

الإشارة إلى المتغيرات

يمكن أيضًا استخدام الرمز $ عدة مرات، كنوع من عامل "الإشارة" (* في C أو C++)، كما في الكود التالي:

set foo a b c
set a 10; set b 20; set c 30
for i in (seq (count $$foo))
    echo $$foo[$i]
end
# الناتج هو:
# 10
# 20
# 30

$$foo[$i] هو "قيمة المتغير المسمى بواسطة $foo[$i]".

يمكن أيضًا استخدام هذا لإعطاء اسم متغير لدالة:

function print_var
    for arg in $argv
        echo Variable $arg is $$arg
    end
end
set -g foo 1 2 3
set -g bar a b c
print_var foo bar
# يطبع "Variable foo is 1 2 3" و "Variable bar is a b c"

بالطبع، سيتعين أن يكون المتغير متاحًا من الدالة، لذا يحتاج إلى أن يكون عامًا/عالميًا أو مصدّرًا. كما لا يمكنه التضارب مع اسم متغير مستخدم داخل الدالة. لذا إذا جعلنا $foo متغيرًا محليًا هناك، أو إذا أسميناه "arg" بدلاً من ذلك، فلن يعمل.

عند استخدام هذه الميزة مع الشرائح، سيتم استخدام الشرائح من الداخل إلى الخارج. $$foo[5] سيستخدم العنصر الخامس من $foo كاسم متغير، بدلاً من إعطاء العنصر الخامس لجميع المتغيرات التي يشير إليها $foo. سيتم التعبير عن ذلك بدلاً من ذلك بـ $$foo[1..-1][5] (خذ جميع عناصر $foo، واستخدمها كأسماء متغيرات، ثم أعط العنصر الخامس منها).

بعض الأمثلة الأخرى:

set listone 1 2 3
set listtwo 4 5 6
set var listone listtwo
echo $$var
# الناتج هو 1 2 3 4 5 6
echo $$var[1]
# الناتج هو 1 2 3
echo $$var[2][3]
# $var[2] هو listtwo، العنصر الثالث منه هو 6، الناتج هو 6
echo $$var[..][2]
# العنصر الثاني لكل متغير، لذا الناتج هو 2 5

المتغيرات كأوامر

مثل الأصداف الأخرى، يمكنك تشغيل قيمة متغير كأمر.

> set -g EDITOR emacs
> $EDITOR foo # يفتح emacs، ربما النسخة الرسومية

إذا كنت تريد إعطاء الأمر وسيطًا داخل المتغير، فيجب أن يكون عنصرًا منفصلاً:

> set EDITOR emacs -nw
> $EDITOR foo # يفتح emacs في الطرفية حتى لو كانت النسخة الرسومية مثبتة
> set EDITOR "emacs -nw"
> $EDITOR foo # يحاول العثور على أمر يسمى "emacs -nw"

أيضًا مثل الأصداف الأخرى، يعمل هذا فقط مع الأوامر والأوامر المدمجة والدوال - لن يعمل مع الكلمات المفتاحية لأن لها أهمية نحوية.

على سبيل المثال، set if $if لن يسمح لك بإنشاء كتلة if، و set cmd command لن يسمح لك باستخدام مزين الأمر <>، ولكنه يستخدم فقط مثل $cmd -q foo.

استبدال الأوامر

استبدال الأوامر هو توسيع يستخدم مخرجات أمر كوسائط لأمر آخر. على سبيل المثال:

echo $(pwd)

يقوم هذا بتنفيذ الأمر pwd <>، ويأخذ مخرجاته (بشكل أكثر تحديدًا ما كتبه إلى مجرى الإخراج القياسي "stdout") ويستخدمه كوسائط للأمر echo <>. لذا يتم تشغيل الأمر الداخلي (pwd) أولاً ويجب أن يكتمل قبل أن يبدأ الأمر الخارجي.

إذا طبع الأمر الداخلي أسطرًا متعددة، فسيستخدم Fish كل سطر منفصل كوسيط منفصل للأمر الخارجي. على عكس الأصداف الأخرى، لا يتم استخدام قيمة $IFS [4]، يقوم Fish بالتقسيم حسب أسطر جديدة.

يمكن أيضًا أن تكون استبدالات الأوامر ذات علامات اقتباس مزدوجة:

echo "$(pwd)"

عند استخدام علامات الاقتباس المزدوجة، لا يتم تقسيم مخرجات الأمر حسب الأسطر، ولكن يتم إزالة الأسطر الفارغة اللاحقة.

إذا تم توجيه المخرجات إلى string split أو string split0 <> كخطوة أخيرة، فسيتم استخدام هذه التقسيمات كما تظهر بدلاً من تقسيم الأسطر.

يسمح Fish أيضًا بكتابة استبدالات الأوامر بدون الدولار، مثل echo (pwd). هذا المتغير لن يتم توسيعه في علامات الاقتباس المزدوجة (echo "(pwd)" سيطبع (pwd)).

حالة خروج آخر استبدال أوامر تم تشغيله متاح في المتغير status إذا حدث الاستبدال في سياق أمر set <> (لذا if set -l (something) يتحقق مما إذا كان something قد أعاد true).

لاستخدام بعض الأسطر فقط من المخرجات، ارجع إلى الشرائح.

أمثلة:

# يطبع 'image.png'.
echo (basename image.jpg .jpg).png
# تحويل جميع ملفات JPEG في الدليل الحالي إلى
# صيغة PNG باستخدام برنامج 'convert'.
for i in *.jpg; convert $i (basename $i .jpg).png; end
# تعيين المتغير ``data`` لمحتويات 'data.txt'
# بدون تقسيمه إلى قائمة.
set data "$(cat data.txt)"
# تعيين ``$data`` لمحتويات البيانات، تقسيم حسب بايتات NUL.
set data (cat data | string split0)

أحيانًا تريد تمرير مخرجات أمر إلى أمر آخر يقبل الملفات فقط. إذا كان ملفًا واحدًا فقط، يمكنك عادةً تمريره عبر أنبوب، مثل:

grep fish myanimallist1 | wc -l

ولكن إذا كنت بحاجة إلى عدة ملفات أو إذا كان الأمر لا يقرأ من الإدخال القياسي، فإن "استبدال العملية" مفيد. تسمح الأصداف الأخرى بذلك عبر foo <(bar) <(baz)، ويستخدم Fish أمر psub <>:

# مقارنة الأسطر التي تحتوي على "fish" فقط في ملفين:
diff -u (grep fish myanimallist1 | psub) (grep fish myanimallist2 | psub)

ينشئ هذا ملفًا مؤقتًا، ويخزن مخرجات الأمر في هذا الملف ويطبع اسم الملف، لذا يتم تمريره إلى الأمر الخارجي.

لدى Fish حد افتراضي يبلغ 1 جيجابايت للبيانات التي سيقرأها في استبدال الأوامر. إذا تم الوصول إلى هذا الحد، يفشل الأمر (كله، وليس فقط استبدال الأوامر - لن يتم تنفيذ الأمر الخارجي على الإطلاق) ويتم تعيين $status إلى 122. هذا حتى لا تتسبب استبدالات الأوامر في نفاد ذاكرة النظام، لأنه عادةً ما يكون لدى نظام التشغيل لديك حد أقل بكثير، لذا فإن القراءة أكثر من ذلك ستكون عديمة الفائدة وضارة. يمكن تعديل هذا الحد باستخدام المتغير fish_read_limit (0 يعني بلا حدود). يؤثر هذا الحد أيضًا على الأمر read <>.

[4]
استثناء واحد: تعيين $IFS إلى فارغ سيعطل تقسيم الأسطر. هذا مهمل، استخدم string split <> بدلاً من ذلك.

توسيع الأقواس

يمكن استخدام الأقواس لكتابة قوائم مفصولة بفواصل. سيتم توسيعها مع كل عنصر يصبح معلمة جديدة، مع إرفاق السلسلة المحيطة. هذا مفيد لتوفير الكتابة، وفصل اسم متغير عن النص المحيط.

أمثلة:

> echo input.{c,h,txt}
input.c input.h input.txt
# نقل جميع الملفات ذات اللاحقة '.c' أو '.h' إلى الدليل الفرعي src.
> mv *.{c,h} src/
# عمل نسخة من `file` في `file.bak`.
> cp file{,.bak}
> set -l dogs hot cool cute "good "
> echo {$dogs}dog
hotdog cooldog cutedog good dog

إذا لم يكن هناك "" أو توسيع متغير بين الأقواس، فلن يتم توسيعها:

# هذا {} ليس خاصًا
> echo foo-{}
foo-{}
# هذا يمرر "HEAD@{2}" إلى git
> git reset --hard HEAD@{2}
> echo {{a,b}}
{a} {b} # لأن زوج الأقواس الداخلي تم توسيعه، ولكن الخارجي
