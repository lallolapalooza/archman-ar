NAME

fi_cq — completion queue

SYNOPSIS

#include <rdma/fabric.h>

int fi_cq_open(struct fid_fabric *fabric, struct fi_cq_attr *attr, struct fid_cq **cq);

int fi_cq_close(struct fid_cq *cq);

int fi_cq_bind(struct fid_cq *cq, struct fid_ ? * ? , void *impl_data);

int fi_cq_error(struct fid_cq *cq, uint32_t ms, void *cq_context);

int fi_cq_read(struct fid_cq *cq, void *buf, size_t len);

int fi_cq_sread(struct fid_cq *cq, void *buf, size_t len);

int fi_cq_tryread(struct fid_cq *cq, void *buf, size_t len);

int fi_cq_readerr(struct fid_cq *cq, void *buf, size_t len);

int fi_cq_sreaderr(struct fid_cq *cq, void *buf, size_t len);

int fi_cq_tryreaderr(struct fid_cq *cq, void *buf, size_t len);

int fi_cq_strerror(struct fid_cq *cq, int err, char *buf, size_t len);

int fi_cq_getopt(struct fid_cq *cq, int level, int option, void *optval);

int fi_cq_setopt(struct fid_cq *cq, int level, int option, void *optval);

ARGUMENTS

Pointer to fi_cq_attr structure containing attributes for the completion queue.

cq_context
Caller provided context that will be returned with the completion error.

Completion queue handle.
buf
Buffer to read completion entries into.
len
Size of the buffer.
cq
Completion queue handle.

Error code to get string representation of.

Buffer to write the error string into.

Size of the buffer.
cq
Completion queue handle.
level
The applicable level of the option. This can be the CQ level (FI_OPT_CQ) or the fabric level (FI_OPT_FABRIC).
option

The option name and value.

DESCRIPTION

The libfabric completion queue (CQ) is an object used to retrieve information about the completion of asynchronous operations. Completion queues are typically associated with endpoints, but can also be used independently for operations initiated by the fabric. A completion queue can be bound to multiple endpoints, counters, or event queues.

fi_cq_open creates and opens a new completion queue. The fabric handle is specified by the fabric parameter. The attr parameter is used to specify the attributes of the completion queue, such as the size and the completion queue format.

fi_cq_close closes and destroys the specified completion queue.

fi_cq_bind binds a completion queue to another libfabric object. The type of object that can be bound depends on the underlying fabric provider. Common objects that can be bound include endpoints, counters, and event queues.

fi_cq_error retrieves a specific error associated with a completion queue. The ms parameter specifies the maximum time to wait for an error to occur. The cq_context parameter is an optional caller-specified context that will be returned with the completion error.

fi_cq_read, fi_cq_sread, and fi_cq_tryread are used to read completion entries from the completion queue. fi_cq_read will block until a completion is available. fi_cq_sread will block until a completion is available or the buffer is full. fi_cq_tryread will return immediately if no completion is available.

fi_cq_readerr, fi_cq_sreaderr, and fi_cq_tryreaderr are used to read error completion entries from the completion queue. The behavior of these functions is similar to their non-error counterparts, but they specifically retrieve error completions.

fi_cq_strerror returns a human-readable string representation of a libfabric error code. The err parameter is the error code, and the buf and len parameters specify the buffer and its size for storing the error string.

fi_cq_getopt and fi_cq_setopt are used to get and set options on a completion queue, respectively. The level parameter specifies the level of the option (e.g., CQ level or fabric level), and the option and optval parameters specify the option name and value.

COMPLETION FIELDS

Completion entries are returned in a structure that includes the following fields:

op_err
Operation-specific error code.
flags
Completion flags indicating the type of completion.
user_data
User-defined data associated with the operation.
len
Bytes transferred or remaining.
tag
Message tag, if applicable.
addr
Source address, if applicable.
completion_id
Identifier for the completion.

COMPLETION FLAGS

The following flags can be set in the flags field of a completion entry:

FI_FLUSH
Indicates a flush completion.
FI_COMMIT_COMP
Indicates a commit completion.
FI_ABORT
Indicates an abort completion.
FI_RECV
Indicates a receive completion.
FI_SEND
Indicates a send completion.
FI_READ
Indicates a read completion.
FI_WRITE
Indicates a write completion.
FI_RMA_CMP
Indicates an RMA completion.
FI_COMPLETION
Indicates a general completion.
FI_ASYNC_COMP
Indicates an asynchronous completion.
FI_MULTI_COMP
Indicates multiple completions.
FI_MORE
Indicates more completions are available.
FI_END
Indicates the end of a sequence of completions.
FI_ERROR
Indicates an error completion.

COMPLETION EVENT SEMANTICS

Completion event semantics define how completion events are generated and reported. The available semantics depend on the underlying fabric provider and the capabilities of the hardware.

Common completion event semantics include:

FI_CQ_EVENT_COMPLETION
A completion event is generated for each operation that completes.
FI_CQ_EVENT_DATA_VALID
A completion event is generated when data is available for reading.
FI_CQ_EVENT_READ_COMP
A completion event is generated after a read operation has completed.

TARGET COMPLETION SEMANTICS

Target completion semantics define when a completion event is reported relative to the completion of an operation. This applies when binding a completion queue to an endpoint or other object.

Common target completion semantics include:

FI_CQ_TRANSMIT
Completion events are generated for transmit operations.
FI_CQ_RECEIVE
Completion events are generated for receive operations.
FI_CQ_FMR
Completion events are generated for FMR (Fast Memory Registration) operations.
FI_CQ_REJECT
Completion events are generated for rejected operations.

NOTES

The exact set of supported completion queue attributes, flags, and semantics may vary depending on the underlying fabric provider.

Error codes are defined in fi_errno(3).

RETURN VALUES

On success, the CQ functions return 0. On failure, they return a negative error code. The specific error code can be determined by consulting the return value and using fi_strerror(3) to retrieve a descriptive string. A specific error may be returned with a completion.

Fabric errno values are defined in rdma/fi_errno.h.
