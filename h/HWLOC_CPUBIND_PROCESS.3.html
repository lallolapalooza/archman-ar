الوصف التفصيلي

بعض أنظمة التشغيل تدعم فقط ربط الخيوط أو العمليات بوحدة معالجة مركزية (PU) واحدة. تدعم أنظمة أخرى الربط بمجموعات أكبر مثل الأنوية الكاملة أو الحزم أو حتى مجموعات عشوائية من وحدات المعالجة المركزية الفردية. في هذه الأنظمة ، يكون المجدول حرًا في تشغيل المهمة على أحد وحدات المعالجة المركزية هذه، ثم ترحيلها إلى وحدة معالجة مركزية أخرى، وما إلى ذلك. غالبًا ما يكون من المفيد استدعاء hwloc_bitmap_singlify() على مجموعة وحدة المعالجة المركزية الهدف قبل تمريرها إلى وظيفة الربط لتجنب هذه عمليات الترحيل المكلفة. انظر وثائق hwloc_bitmap_singlify() لمزيد من التفاصيل.

بعض أنظمة التشغيل لا توفر جميع الآليات التي تدعمها hwloc لربط العمليات والخيوط وما إلى ذلك. يمكن استخدام hwloc_topology_get_support() للاستعلام عن دعم ربط وحدة المعالجة المركزية الفعلي في نظام التشغيل المستخدم حالياً.

عندما لا تكون عملية الربط المطلوبة متاحة وتم تمرير العلامة HWLOC_CPUBIND_STRICT ، تعيد الوظيفة -1. يتم تعيين errno إلى ENOSYS عندما لا يكون من الممكن ربط نوع الكائن المطلوب (عمليات/خيوط). يتم تعيين errno إلى EXDEV عندما لا يمكن فرض مجموعة وحدة المعالجة المركزية المطلوبة (على سبيل المثال، تسمح بعض الأنظمة بوحدة معالجة مركزية واحدة فقط، وتسمح بعض الأنظمة الأخرى بعقدة NUMA واحدة فقط).

إذا لم يتم تمرير HWLOC_CPUBIND_STRICT ، فقد تفشل الوظيفة أيضًا، أو قد يستخدم نظام التشغيل عملية مختلفة قليلاً (مع آثار جانبية، مجموعة ربط أصغر، إلخ) عندما لا تكون العملية المطلوبة مدعومة بالضبط.

النسخة الأكثر قابلية للنقل والتي يجب تفضيلها على غيرها، كلما كان ذلك ممكنًا، هي النسخة التالية التي تربط ببساطة البرنامج الحالي، بافتراض أنه يعمل بخيط واحد:

hwloc_set_cpubind(topology, set, 0),

إذا كان البرنامج قد يعمل بخيوط متعددة، فيجب تفضيل النسخة التالية لربط الخيط الحالي فقط:

hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD),

انظر أيضًا

بعض أمثلة الأكواد متاحة تحت doc/examples/ في شجرة المصدر.

ملاحظة

لإلغاء الربط، ما عليك سوى استدعاء وظيفة الربط إما بمجموعة وحدة معالجة مركزية كاملة أو بمجموعة وحدة معالجة مركزية تساوي مجموعة وحدة المعالجة المركزية للنظام.

على بعض أنظمة التشغيل، قد يكون لربط وحدة المعالجة المركزية تأثيرات على ربط الذاكرة، انظر HWLOC_CPUBIND_NOMEMBIND

يمكن أن يكون تشغيل lstopo --top أو hwloc-ps أداة مفيدة جدًا للتحقق من كيفية حدوث الربط فعليًا.

وثائق نوع التعداد

enum hwloc_cpubind_flags_t

علامات ربط العمليات/الخيوط. يمكن استخدام علامات البت هذه لتحسين سياسة الربط.

الافتراضي (0) هو ربط العملية الحالية، بافتراض أنها تعمل بخيط واحد، بطريقة غير صارمة. هذه هي الطريقة الأكثر قابلية للنقل للربط حيث أن جميع أنظمة التشغيل توفرها عادةً.

ملاحظة

لا تدعم جميع الأنظمة جميع أنواع الربط. انظر قسم "الوصف التفصيلي" لـ ربط وحدة المعالجة المركزية لوصف الأخطاء التي قد تحدث.

عداد

HWLOC_CPUBIND_PROCESS
ربط جميع خيوط العملية الحالية (التي قد تكون متعددة الخيوط).
HWLOC_CPUBIND_THREAD
ربط الخيط الحالي للعملية الحالية.
HWLOC_CPUBIND_STRICT
طلب الربط الصارم من نظام التشغيل. افتراضيًا، عندما تكون وحدات المعالجة المركزية المحددة مشغولة بينما تكون وحدات المعالجة المركزية الأخرى خاملة، قد يقوم نظام التشغيل بتشغيل الخيط/العملية على تلك الوحدات المركزية الأخرى بدلاً من الوحدات المحددة، للسماح لها بالتقدم على أي حال. الربط الصارم يعني أن الخيط/العملية لن يتم تشغيله أبدًا على وحدات معالجة مركزية أخرى غير المحددة، حتى عندما تكون تلك مشغولة بمهام أخرى ووحدات معالجة مركزية أخرى خاملة.

ملاحظة

اعتمادًا على نظام التشغيل، قد لا يكون الربط الصارم ممكنًا (على سبيل المثال، نظام التشغيل لا ينفذه) أو غير مسموح به (على سبيل المثال، لأسباب إدارية)، وستفشل الوظيفة في هذه الحالة.

عند استرداد ربط عملية، تتحقق هذه العلامة مما إذا كانت جميع خيوطها لها نفس الربط بالفعل. إذا لم يتم إعطاء العلامة، فسيتم تجميع ربط كل خيط.

ملاحظة

هذه العلامة لا معنى لها عند استرداد ربط خيط.
HWLOC_CPUBIND_NOMEMBIND
تجنب أي تأثير على ربط الذاكرة. على بعض أنظمة التشغيل، ستقوم بعض وظائف ربط وحدة المعالجة المركزية أيضًا بربط الذاكرة بعقدة NUMA المقابلة. غالبًا ما لا يمثل هذا مشكلة للتطبيق، ولكن إذا كان كذلك، فإن تعيين هذه العلامة سيجعل hwloc يتجنب استخدام وظائف نظام التشغيل التي ستربط الذاكرة أيضًا. ومع ذلك، سيقلل هذا من دعم ربط وحدة المعالجة المركزية، أي أنه قد يعيد -1 مع تعيين errno إلى ENOSYS في بعض الحالات.

هذه العلامة ذات معنى فقط عند استخدامها مع وظائف تحدد ربط وحدة المعالجة المركزية. يتم تجاهلها عند استخدامها مع وظائف تسترد معلومات ربط وحدة المعالجة المركزية.

hwloc - hwloc_get_thread_cpubind(3)

NAME

hwloc_get_thread_cpubind, hwloc_set_thread_cpubind - للحصول على وربط وحدة المعالجة المركزية للخيط المحدد

SYNOPSIS

#include <hwloc.h>

int hwloc_get_thread_cpubind(hwloc_topology_t topology, hwloc_thread_t thread, hwloc_cpuset_t set, int flags);

int hwloc_set_thread_cpubind(hwloc_topology_t topology, hwloc_thread_t thread, hwloc_const_cpuset_t set, int flags);

DESCRIPTION

This function retrieves the current physical binding of thread thread. The CPU-set set (previously allocated by the caller) is filled with the list of PUs which the thread was last bound to.

The operating system may move some tasks from one processor to another at any time according to their binding, so this function may return something that is already outdated.

Returns

0 on success, -1 on error.

Note

hwloc_thread_t is pthread_t on Unix platforms, and HANDLE on native Windows platforms.

HWLOC_CPUBIND_PROCESS can not be used in flags.

int hwloc_get_cpubind (hwloc_topology_t topology, hwloc_cpuset_t set, int flags)

Get the current physical binding of the calling process or thread. The CPU-set set (previously allocated by the caller) is filled with the list of PUs which the calling process or thread was last bound to.

flags can include either HWLOC_CPUBIND_PROCESS or HWLOC_CPUBIND_THREAD to specify whether the query should be for the whole process (union of all CPUs on which all threads are running), or only the current thread. If the process is single-threaded, flags can be set to zero to let hwloc use whichever method is available on the underlying OS.

Returns

0 on success, -1 on error.

int hwloc_get_proc_cpubind (hwloc_topology_t topology, hwloc_pid_t pid, hwloc_cpuset_t set, int flags)

Get the current physical binding of process pid. The CPU-set set (previously allocated by the caller) is filled with the list of PUs which the process was last bound to.

Returns

0 on success, -1 on error.

Note

hwloc_pid_t is pid_t on Unix platforms, and HANDLE on native Windows platforms.

As a special case on Linux, if a tid (thread ID) is supplied instead of a pid (process ID) and HWLOC_CPUBIND_THREAD is passed in flags, the binding for that specific thread is returned.

On non-Linux systems, HWLOC_CPUBIND_THREAD can not be used in flags.

int hwloc_get_proc_last_cpu_location (hwloc_topology_t topology, hwloc_pid_t pid, hwloc_cpuset_t set, int flags)

Get the last physical CPU where a process ran. The CPU-set set (previously allocated by the caller) is filled with the list of PUs which the process last ran on.

The operating system may move some tasks from one processor to another at any time according to their binding, so this function may return something that is already outdated.

Returns

0 on success, -1 on error.

Note

hwloc_pid_t is pid_t on Unix platforms, and HANDLE on native Windows platforms.

As a special case on Linux, if a tid (thread ID) is supplied instead of a pid (process ID) and HWLOC_CPUBIND_THREAD is passed in flags, the last CPU location of that specific thread is returned.

On non-Linux systems, HWLOC_CPUBIND_THREAD can not be used in flags.
