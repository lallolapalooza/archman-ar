وصف تفصيلي

يمثل النوع hwloc_bitmap_t مجموعة من الأعداد الصحيحة (موجبة أو صفر). قد يكون البت المجمّع بحجم لا نهائي (كل البتات مُعيّنة بعد نقطة معينة). قد يكون البت المجمّع ممتلئًا إذا كانت كل البتات مُعيّنة.

تُستخدم البتات المجمّعة بواسطة hwloc لمجموعات معالجات النظام (التي قد تكون في الواقع خيوط معالجة)، مثل hwloc_cpuset_t (وهو نوع مُعرّف من hwloc_bitmap_t)، أو مجموعات عقد ذاكرة NUMA مثل hwloc_nodeset_t (وهو أيضًا نوع مُعرّف من hwloc_bitmap_t). تُستخدم هذه للمجالات cpuset و nodeset في البنية hwloc_obj، انظر مجموعات الكائنات (hwloc_cpuset_t و hwloc_nodeset_t).

كل من مجموعات المعالجات وعقد الذاكرة مُفهرسة دائمًا حسب رقم النظام الفعلي. ومع ذلك، يجب على المستخدمين عادةً عدم بناء مجموعات المعالجات وعقد الذاكرة يدويًا (على سبيل المثال، باستخدام hwloc_bitmap_set()). يجب بدلًا من ذلك استخدام مجموعات الكائنات الموجودة ودمجها مع hwloc_bitmap_or()، إلخ. على سبيل المثال، يمكن ربط الخيط الحالي بزوج من النوى باستخدام:

hwloc_obj_t core1 = ... , core2 = ... ;
hwloc_bitmap_t set = hwloc_bitmap_alloc();
hwloc_bitmap_or(set, core1->cpuset, core2->cpuset);
hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD);
hwloc_bitmap_free(set);

ملاحظة

تعيد معظم الوظائف أدناه 0 عند النجاح و -1 عند الخطأ. الحالة الشائعة للخطأ هي فشل داخلي في إعادة تخصيص/توسيع تخزين البت المجمّع (سيتم تعيين errno إلى ENOMEM). انظر أيضًا الإبلاغ عن الأخطاء في الواجهة البرمجية.

تتوفر العديد من الأمثلة لاستخدام واجهة برمجة تطبيقات البت المجمّع تحت دليل examples/ في شجرة المصادر. اختبارات التراجع مثل tests/hwloc/hwloc_bitmap*.c تستخدم هذه الواجهة بكثافة أيضًا.

توثيق تعريف المُعرّف (Macro Definition Documentation)

#define hwloc_bitmap_foreach_begin(id, bitmap)

معرّف حلقة يمر عبر البت المجمّع bitmap. يجب أن تبدأ الحلقة بـhwloc_bitmap_foreach_begin() وتنتهي بـhwloc_bitmap_foreach_end() متبوعة بفاصلة منقوطة.

id هو متغير الحلقة؛ يجب أن يكون عددًا صحيحًا غير مُشار إليه (unsigned int). ستقوم التكرارة الأولى بتعيين id إلى أدنى فهرس في البت المجمّع. ستمر التكرارات اللاحقة، بالترتيب، عبر جميع الفهارس المتبقية المعينة في البت المجمّع. لتوضيح: كل تكرارة ستعيد قيمة لـ id بحيث تكون hwloc_bitmap_isset(bitmap, id) صحيحة.

التأكيد يمنع الحلقة من أن تكون لا نهائية إذا كان البت المجمّع مُعيّنًا إلى ما لا نهاية.

#define hwloc_bitmap_foreach_end()

نهاية معرّف حلقة يمر عبر بت مجمّع. تحتاج إلى فاصلة منقوطة.

int hwloc_bitmap_singlify (hwloc_bitmap_t bitmap)

Keep a single index among those set in bitmap bitmap. May be useful before binding so that the process does not have a chance of migrating between multiple processors in the original mask. Instead of running the task on any PU inside the given CPU set, the operating system scheduler will be forced to run it on a single of these PUs. It avoids a migration overhead and cache-line ping-pongs between PUs.

Note

This function is NOT meant to distribute multiple processes within a single CPU set. It always return the same single bit when called multiple times on the same input set. hwloc_distrib() may be used for generating CPU sets to distribute multiple tasks below a single multi-PU object.

This function cannot be applied to an object set directly. It should be applied to a copy (which may be obtained with hwloc_bitmap_dup()).

Stringify a bitmap in the default hwloc format. Note that if the bitmap is a CPU or nodeset, it contains physical indexes.

Print the bits set inside a bitmap as a comma-separated list of hexadecimal 32-bit blocks. A bitmap containing bits 1, 33, 34, and all from 64 to 95 is printed as '0xffffffff,0x00000006,0x00000002'.

Up to buflen characters may be written in buffer buf.
