HWLOC_MEMBIND_PROCESS(3)

embind_policy_t

سياسة ربط الذاكرة. يمكن استخدام هذه الثوابت لاختيار سياسة الربط. يمكن استخدام سياسة واحدة فقط في كل مرة (أي لا يمكن دمج القيم معًا).

لا تدعم جميع الأنظمة جميع أنواع الربط. يمكن استخدام hwloc_topology_get_support() للاستعلام عن دعم سياسة ربط الذاكرة الفعلية في نظام التشغيل المستخدم حاليًا. راجع قسم "الوصف التفصيلي" الخاص بـ ربط الذاكرة لوصف الأخطاء التي يمكن أن تحدث.

المُعَرِّفات

HWLOC_MEMBIND_DEFAULT
إعادة تعيين سياسة تخصيص الذاكرة إلى افتراضي النظام. اعتمادًا على نظام التشغيل، قد يتوافق هذا مع HWLOC_MEMBIND_FIRSTTOUCH (Linux، FreeBSD)، أو HWLOC_MEMBIND_BIND (AIX، HP-UX، Solaris، Windows). لا يتم إرجاع هذه السياسة أبدًا بواسطة دوال الحصول على ربط الذاكرة. يتم تجاهل وسيطة مجموعة العقد (nodeset).
HWLOC_MEMBIND_FIRSTTOUCH
تخصيص كل صفحة ذاكرة بشكل فردي على عقدة NUMA المحلية للخيط الذي يلمسها. عادةً ما يجب أن تكون مجموعة العقد (nodeset) المعطاة hwloc_topology_get_topology_nodeset() بحيث يمكن للخيط الذي يلمس تشغيل وتخصيص الذاكرة على أي عقدة في النظام.

على AIX، إذا كانت مجموعة العقد (nodeset) أصغر، يتم تخصيص الصفحات محليًا (إذا كانت العقدة المحلية موجودة في مجموعة العقد) أو من عقدة عشوائية غير محلية (بخلاف ذلك).

HWLOC_MEMBIND_BIND
تخصيص الذاكرة على العقد المحددة. قد يختلف السلوك الفعلي قليلاً بين أنظمة التشغيل، خاصة عندما تكون العقد المطلوبة (بعضها أو كلها) ممتلئة. على Linux، افتراضيًا، يتم استخدام سياسة MPOL_PREFERRED_MANY (أو MPOL_PREFERRED). ومع ذلك، إذا تم أيضًا تقديم علامة hwloc الصارمة (strict flag)، فسيتم استخدام سياسة Linux MPOL_BIND بدلاً من ذلك.
HWLOC_MEMBIND_INTERLEAVE
تخصيص الذاكرة على العقد المحددة بطريقة متداخلة / دائرية. التخطيط الدقيق للذاكرة عبر عقد NUMA متعددة يعتمد على نظام التشغيل/النظام. يمكن أن يكون التداخل مفيدًا عندما ستصل الخيوط الموزعة عبر عقد NUMA المحددة إلى نطاق الذاكرة بالكامل بشكل متزامن، حيث سيؤدي التداخل بعد ذلك إلى موازنة مراجع الذاكرة.
HWLOC_MEMBIND_WEIGHTED_INTERLEAVE
تخصيص الذاكرة على العقد المحددة بطريقة متداخلة / مرجحة. التخطيط الدقيق للذاكرة عبر عقد NUMA متعددة يعتمد على نظام التشغيل/النظام. يمكن أن يكون التداخل المرجح مفيدًا عندما ستصل الخيوط الموزعة عبر عقد NUMA المحددة ذات قدرات النطاق الترددي المختلفة إلى نطاق الذاكرة بالكامل بشكل متزامن، حيث سيؤدي التداخل بعد ذلك إلى موازنة مراجع الذاكرة.
HWLOC_MEMBIND_NEXTTOUCH
لكل صفحة مرتبطة بهذه السياسة، في المرة التالية التي يتم لمسها فيها (وفي المرة التالية فقط)، يتم نقلها من موقعها الحالي إلى عقدة NUMA المحلية للخيط الذي حدث فيه مرجع الذاكرة (إذا كانت بحاجة إلى نقل على الإطلاق).
HWLOC_MEMBIND_MIXED
تم إرجاعها بواسطة دوال get_membind() عندما يكون لدى الخيوط المتعددة أو أجزاء من منطقة الذاكرة سياسات ربط ذاكرة مختلفة. تم إرجاعها أيضًا عندما يكون الربط غير معروف لأن خطافات الربط فارغة عندما يتم تحميل الطوبولوجيا من XML بدون HWLOC_THISSYSTEM=1، وما إلى ذلك.

توثيق الوظائف

void * hwloc_alloc (hwloc_topology_t topology, size_t len)

تخصيص بعض الذاكرة. هذا يعادل malloc()، باستثناء أنه يحاول تخصيص ذاكرة محاذية للصفحات من النظام.

الإرجاع

مؤشر إلى المنطقة المخصصة، أو NULL عند حدوث خطأ.

ملاحظة

يجب تحرير الذاكرة المخصصة باستخدام hwloc_free().

void * hwloc_alloc_membind (hwloc_topology_t topology, size_t len, hwloc_const_bitmap_t set, hwloc_membind_policy_t policy, int flags)

تخصيص بعض الذاكرة على عقد NUMA المحددة بواسطة set.

الإرجاع

مؤشر إلى المنطقة المخصصة.

NULL مع تعيين errno إلى ENOSYS إذا كان الإجراء غير مدعوم وتم تقديم HWLOC_MEMBIND_STRICT.

NULL مع تعيين errno إلى EXDEV إذا كان الربط لا يمكن إنفاذه وتم تقديم HWLOC_MEMBIND_STRICT.

NULL مع تعيين errno إلى ENOMEM إذا فشل تخصيص الذاكرة حتى قبل محاولة الربط.

إذا تم تحديد HWLOC_MEMBIND_BYNODESET، يتم اعتبار set كمجموعة عقد (nodeset). بخلاف ذلك، فهي مجموعة وحدات معالجة مركزية (cpuset).

ملاحظة

يجب تحرير الذاكرة المخصصة باستخدام hwloc_free().

void * hwloc_alloc_membind_policy (hwloc_topology_t topology, size_t len, hwloc_const_bitmap_t set, hwloc_membind_policy_t policy, int flags) [inline]

تخصيص بعض الذاكرة على عقد NUMA المحددة بواسطة set. أولاً، حاول التخصيص بشكل صحيح باستخدام hwloc_alloc_membind(). عند الفشل، يتم تغيير سياسة ربط الذاكرة الحالية للعملية أو الخيط باستخدام hwloc_set_membind() قبل تخصيص الذاكرة. وبالتالي تعمل هذه الوظيفة في المزيد من الحالات، مقابل تغيير الحالة الحالية (مما قد يؤثر على التخصيصات المستقبلية التي لن تحدد أي سياسة).

إذا تم تحديد HWLOC_MEMBIND_BYNODESET، يتم اعتبار set كمجموعة عقد (nodeset). بخلاف ذلك، فهي مجموعة وحدات معالجة مركزية (cpuset).

الإرجاع

مؤشر إلى المنطقة المخصصة، أو NULL عند حدوث خطأ.

int hwloc_free (hwloc_topology_t topology, void * addr, size_t len)

تحرير الذاكرة التي تم تخصيصها مسبقًا بواسطة hwloc_alloc() أو hwloc_alloc_membind().

الإرجاع

0 عند النجاح، -1 عند حدوث خطأ.

int hwloc_get_area_membind (hwloc_topology_t topology, const void * addr, size_t len, hwloc_bitmap_t set, hwloc_membind_policy_t * policy, int flags)

الاستعلام عن وحدات المعالجة المركزية (CPUs) القريبة من عقد NUMA المادية (physical NUMA node(s)) وسياسة الربط للذاكرة المحددة بواسطة (addr, len ). يتم ملء خريطة البت (bitmap) set (المخصصة مسبقًا بواسطة المتصل) بربط منطقة الذاكرة.

هذه الوظيفة لديها وسيطتان إخراج: set و policy. تعتمد القيم التي تم إرجاعها في هذه الوسيطات على كل من العلامات (flags) التي تم تمريرها وسياسات ربط الذاكرة ومجموعات العقد (nodesets) للصفحات في نطاق العنوان.

إذا تم تحديد HWLOC_MEMBIND_STRICT، يتم أولاً التحقق من الصفحات المستهدفة لمعرفة ما إذا كانت جميعها لها نفس سياسة ربط الذاكرة ومجموعة العقد (nodeset). إذا لم تكن كذلك، يتم إرجاع -1 ويتم تعيين errno إلى EXDEV. إذا كانت متطابقة عبر جميع الصفحات، يتم إرجاع set و policy في set و policy على التوالي.

إذا لم يتم تحديد HWLOC_MEMBIND_STRICT، يتم حساب اتحاد جميع عقد NUMA التي تحتوي على صفحات في نطاق العنوان. إذا كانت جميع الصفحات في الهدف لها نفس السياسة، يتم إرجاعها في policy. بخلاف ذلك، يتم تعيين policy إلى HWLOC_MEMBIND_MIXED.

إذا تم تحديد HWLOC_MEMBIND_BYNODESET، يتم اعتبار set كمجموعة عقد (nodeset). بخلاف ذلك، فهي مجموعة وحدات معالجة مركزية (cpuset).

إذا تم تحديد أي علامات أخرى، يتم إرجاع -1 ويتم تعيين errno إلى EINVAL.

الإرجاع

0 عند النجاح.

-1 مع تعيين errno إلى EINVAL إذا كان len يساوي 0.

int hwloc_get_area_memlocation (hwloc_topology_t topology, const void * addr, size_t len, hwloc_bitmap_t set, int flags)

الحصول على عقد NUMA التي يتم تخصيص الذاكرة المحددة بواسطة (addr, len ) فيها فعليًا. يتم ملء خريطة البت (bitmap) set (المخصصة مسبقًا بواسطة المتصل) وفقًا لعقد NUMA التي تم تخصيص صفحات منطقة الذاكرة فيها فعليًا. إذا لم يتم تخصيص أي صفحة فعليًا بعد، فقد تكون set فارغة.

إذا انتشرت الصفحات إلى عقد متعددة، فليس من المحدد ما إذا كانت تنتشر بالتساوي، أو ما إذا كانت معظمها على عقدة واحدة، وما إلى ذلك.

قد يقوم نظام التشغيل بنقل صفحات الذاكرة من معالج إلى آخر في أي وقت وفقًا لربطها، لذلك قد ترجع هذه الوظيفة شيئًا قديمًا بالفعل.
