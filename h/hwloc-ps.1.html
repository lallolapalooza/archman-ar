الحزمة: hwloc

NAME

hwloc-ps

display operating system's view of the process tree

SYNOPSIS

hwloc-ps [-N] [-L] [-e] [-p] [-i] [-d] [-c] [-s] [--whole] [--pid PID] [--process-domain DOMAIN]

OPTIONS

-N
Display PIDs and TIDs as ns32k names instead of OS specific ones. This is mostly useful for debugging the tool itself.
-L
Display PIDs and TIDs as OS specific names (e.g. thread IDs on Linux). This is the default.
-e
Display the actual OS specific PID/TID for each process/thread.
-p
Display the PIDs of the processes.
-i
Display the PIDs and TIDs of the threads.
-d
Display the domain ID of each process/thread.
-c
Display the Core ID of each process/thread.
-s
Display the OS specific name of each process/thread.
--whole
Do not truncate the process tree, display all processes.
--pid PID
Only display the process tree below the given PID. If PID is 0, display the whole tree.
--process-domain DOMAIN
Only display processes and threads belonging to the given DOMAIN.

DESCRIPTION

hwloc-ps is a utility to display operating system's view of the process tree. It lists processes, their threads, and their locations in the hardware topology.

This tool is mainly useful for debugging and understanding how processes and threads are distributed across the available hardware resources. It relies on the hwloc library's ability to query OS-level information about processes and their relationship with the underlying hardware.

The output format can be controlled using the various options to display PIDs, TIDs, domain IDs, core IDs, or OS-specific names.

By default, hwloc-ps displays a tree of processes and their threads. Each entry in the tree represents a process or a thread and shows its identifier, its domain ID, and the core it is running on. The tree structure helps visualize the parent-child relationships between processes.

The options -e, -p, -i, -d, -c, and -s can be combined to customize the output format. For example, using -p -d -c will display the PID, Domain ID, and Core ID for each process/thread.

The --pid option allows you to focus on a specific part of the process tree, starting from a given Process ID (PID). If --pid 0 is used, the entire process tree is displayed.

The --process-domain option filters the output to show only processes and threads belonging to a specified domain.

EXAMPLES

Example with lstopo integration

While hwloc-ps itself doesn't directly integrate with lstopo's graphical output, the information it provides can be correlated with the topology shown by lstopo. For instance, if lstopo shows that Core 3 is part of NUMA node 1, and hwloc-ps shows a process running on Core 3, you can infer that the process is running on NUMA node 1.

Examples with MPI processes

Consider an MPI job running across multiple processes. You can use hwloc-ps to see where each MPI process is placed.

Suppose you have an MPI program that prints its OMPI_COMM_WORLD_RANK environment variable. You can use a helper script like this:

#!/bin/sh
cat /proc/$1/environ 2>/dev/null | xargs --null --max-args=1 echo | grep
    OMPI_COMM_WORLD_RANK

And run it like this:

$ lstopo --of txt --pid $(pidof myprogram) --whole

This might produce output similar to:

PID TUID Domain Core OSName
29094 29094 0 0 myprogram
  \_ 29095 29095 1 1 myprogram
  \_ 29096 29096 3 3 myprogram

And running the script (let's call it get_mpi_rank.sh) on those PIDs:

$ ./get_mpi_rank.sh 29094
OMPI_COMM_WORLD_RANK=0
$ ./get_mpi_rank.sh 29095
OMPI_COMM_WORLD_RANK=1
$ ./get_mpi_rank.sh 29096
OMPI_COMM_WORLD_RANK=2

This shows that PID 29094 (running on Core 0) has MPI rank 0, PID 29095 (running on Core 1) has MPI rank 1, and PID 29096 (running on Core 3) has MPI rank 2. This helps in understanding how MPI ranks are mapped to physical cores.

Using the full command line for the script:

$ hwloc-ps -p -d -c -s

May produce output like:

PID TUID Domain Core OSName
29094 29094 0 0 myprogram
  29094 0 0 0
  \_ 29095 29095 1 1 myprogram
    29095 1 1 1
    \_ 29096 29096 3 3 myprogram
      29096 3 3 3

Where PID is the Process ID, TUID is the Thread ID (or PID if no threads), Domain is the NUMA domain, and Core is the core number. The OSName column shows the process/thread name.

If you run a script named myscript that uses the process ID as an argument:

#!/bin/sh
cat /proc/$1/environ 2>/dev/null | xargs --null --max-args=1 echo | grep
    OMPI_COMM_WORLD_RANK

Running it on the example PIDs would yield:

29094	PU:0	myprogram	OMPI_COMM_WORLD_RANK=0
  

   29095	PU:1	myprogram	OMPI_COMM_WORLD_RANK=1
  

   29096	PU:3	myprogram	OMPI_COMM_WORLD_RANK=2

where myscript is a shell script doing:

#!/bin/sh
cat /proc/$1/environ 2>/dev/null | xargs --null --max-args=1 echo | grep
    OMPI_COMM_WORLD_RANK

الاسم

hwloc-ps

عرض رؤية نظام التشغيل لشجرة العمليات

الملخص

hwloc-ps [-N] [-L] [-e] [-p] [-i] [-d] [-c] [-s] [--whole] [--pid PID] [--process-domain DOMAIN]

الخيارات

-N
عرض معرفات العمليات (PIDs) ومعرفات الخيوط (TIDs) كأسماء ns32k بدلاً من الأسماء الخاصة بنظام التشغيل. هذا مفيد بشكل أساسي لتصحيح أخطاء الأداة نفسها.
-L
عرض معرفات العمليات (PIDs) ومعرفات الخيوط (TIDs) كأسماء خاصة بنظام التشغيل (مثل معرفات الخيوط في لينكس). هذا هو الخيار الافتراضي.
-e
عرض معرف العملية/الخيط الفعلي الخاص بنظام التشغيل لكل عملية/خيط.
-p
عرض معرفات العمليات (PIDs).
-i
عرض معرفات العمليات (PIDs) ومعرفات الخيوط (TIDs).
-d
عرض معرف النطاق (domain ID) لكل عملية/خيط.
-c
عرض معرف النواة (Core ID) لكل عملية/خيط.
-s
عرض الاسم الخاص بنظام التشغيل لكل عملية/خيط.
--whole
عدم اقتطاع شجرة العمليات، عرض جميع العمليات.
--pid PID
عرض شجرة العمليات فقط أسفل معرف العملية (PID) المحدد. إذا كان PID هو 0، يتم عرض الشجرة بأكملها.
--process-domain DOMAIN
عرض العمليات والخيوط التي تنتمي إلى النطاق المحدد (DOMAIN) فقط.

الوصف

hwloc-ps هي أداة لعرض رؤية نظام التشغيل لشجرة العمليات. تسرد العمليات وخيوطها ومواقعها في الطوبولوجيا الخاصة بالأجهزة.

هذه الأداة مفيدة بشكل أساسي لتصحيح الأخطاء وفهم كيفية توزيع العمليات والخيوط عبر موارد الأجهزة المتاحة. تعتمد على قدرة مكتبة hwloc على الاستعلام عن معلومات مستوى نظام التشغيل حول العمليات وعلاقتها بالأجهزة الأساسية.

يمكن التحكم في تنسيق الإخراج باستخدام الخيارات المختلفة لعرض معرفات العمليات (PIDs)، ومعرفات الخيوط (TIDs)، ومعرفات النطاقات (domain IDs)، ومعرفات النوى (core IDs)، أو الأسماء الخاصة بنظام التشغيل.

بشكل افتراضي، تعرض hwloc-ps شجرة من العمليات وخيوطها. يمثل كل إدخال في الشجرة عملية أو خيطًا ويعرض معرفه، ومعرف نطاقه، والنواة التي يعمل عليها. يساعد هيكل الشجرة في تصور علاقات الوالدين والطفل بين العمليات.

يمكن دمج الخيارات -e، -p، -i، -d، -c، و -s لتخصيص تنسيق الإخراج. على سبيل المثال، استخدام -p -d -c سيعرض معرف العملية (PID)، ومعرف النطاق (Domain ID)، ومعرف النواة (Core ID) لكل عملية/خيط.

يسمح خيار --pid بالتركيز على جزء معين من شجرة العمليات، بدءًا من معرف العملية (PID) المحدد. إذا تم استخدام --pid 0، يتم عرض شجرة العمليات بأكملها.

يقوم خيار --process-domain بتصفية الإخراج لعرض العمليات والخيوط التي تنتمي إلى نطاق محدد فقط.

أمثلة

مثال مع تكامل lstopo

على الرغم من أن hwloc-ps نفسها لا تتكامل مباشرة مع الإخراج الرسومي لـ lstopo، إلا أن المعلومات التي توفرها يمكن ربطها بالطوبولوجيا التي يعرضها lstopo. على سبيل المثال، إذا أظهر lstopo أن النواة 3 جزء من عقدة NUMA 1، وأظهرت hwloc-ps عملية تعمل على النواة 3، يمكنك استنتاج أن العملية تعمل على عقدة NUMA 1.

أمثلة مع عمليات MPI

ضع في اعتبارك مهمة MPI تعمل عبر عمليات متعددة. يمكنك استخدام hwloc-ps لمعرفة مكان وضع كل عملية MPI.

لنفترض أن لديك برنامج MPI يطبع متغير البيئة الخاص به OMPI_COMM_WORLD_RANK. يمكنك استخدام برنامج نصي مساعد مثل هذا:

#!/bin/sh
cat /proc/$1/environ 2>/dev/null | xargs --null --max-args=1 echo | grep
    OMPI_COMM_WORLD_RANK

وتشغيله بهذا الشكل:

$ lstopo --of txt --pid $(pidof myprogram) --whole

قد ينتج عن ذلك إخراج مشابه لما يلي:

PID TUID Domain Core OSName
29094 29094 0 0 myprogram
  \_ 29095 29095 1 1 myprogram
  \_ 29096 29096 3 3 myprogram

وتشغيل البرنامج النصي (لنسميه get_mpi_rank.sh) على معرفات العمليات هذه:

$ ./get_mpi_rank.sh 29094
OMPI_COMM_WORLD_RANK=0
$ ./get_mpi_rank.sh 29095
OMPI_COMM_WORLD_RANK=1
$ ./get_mpi_rank.sh 29096
OMPI_COMM_WORLD_RANK=2

يوضح هذا أن العملية ذات المعرف 29094 (تعمل على النواة 0) لها رتبة MPI 0، والعملية ذات المعرف 29095 (تعمل على النواة 1) لها رتبة MPI 1، والعملية ذات المعرف 29096 (تعمل على النواة 3) لها رتبة MPI 2. يساعد هذا في فهم كيفية تعيين رتب MPI إلى النوى المادية.

باستخدام الأمر الكامل للبرنامج النصي:

$ hwloc-ps -p -d -c -s

قد ينتج عن ذلك إخراج مثل:

PID TUID Domain Core OSName
29094 29094 0 0 myprogram
  29094 0 0 0
  \_ 29095 29095 1 1 myprogram
    29095 1 1 1
    \_ 29096 29096 3 3 myprogram
      29096 3 3 3

حيث PID هو معرف العملية، TUID هو معرف الخيط (أو PID إذا لم تكن هناك خيوط)، Domain هو نطاق NUMA، و Core هو رقم النواة. يعرض عمود OSName اسم العملية/الخيط.

إذا قمت بتشغيل برنامج نصي يسمى myscript يستخدم معرف العملية كوسيط:

#!/bin/sh
cat /proc/$1/environ 2>/dev/null | xargs --null --max-args=1 echo | grep
    OMPI_COMM_WORLD_RANK

تشغيله على معرفات العمليات المثال سيؤدي إلى:

29094	PU:0	myprogram	OMPI_COMM_WORLD_RANK=0
  

   29095	PU:1	myprogram	OMPI_COMM_WORLD_RANK=1
  

   29096	PU:3	myprogram	OMPI_COMM_WORLD_RANK=2

حيث myscript هو برنامج نصي شل يقوم بما يلي:

#!/bin/sh
cat /proc/$1/environ 2>/dev/null | xargs --null --max-args=1 echo | grep
    OMPI_COMM_WORLD_RANK
